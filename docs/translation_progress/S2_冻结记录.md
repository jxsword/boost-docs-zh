## 2. 试点期间发现并修复的流水线缺陷（5 项）

1. **TM 键未含标记布局**：同文本不同标记布局的段共享键 → common_segments 串位。
   修复：`norm_key` = 规范化段串（含 ⦃n⦄/⟦⟧ 标记），与总纲 R3 一致。
2. **孤立块级结束标签不打标记**：`</p>` 无匹配开标签 → 相邻 text 项 → 任何译文无法通过布局校验。
   修复：`handle_endtag` 对孤立块级/内联结束标签插入占位。
3. **纯空白文本节点的空替换**：空译文片段替换空白节点 → 节点消失 → 段边界移位 → DOM 对等破坏。
   修复：空片段→空白 span 保留原字节；空片段→实体 span 写单空格保节点；非空片段照写（保证译文落点）。
4. **code 区间内的 title 属性被翻译**：破坏代码区完整性。
   修复：`filter_attrs_inside_code` 剔除与 code 区间相交的属性段（extract 与 reemit 两端生效）。
5. **账本序列号不续接**：重建批次覆盖旧文件但 seq 从 1 重来 → 部分段从未进批。
   修复：`build_batches` 按账本 per-lib 续接 seq；merge 对无批次文件的 queued 行安全跳过。

## 3. 门禁语义在试点中明确（冻结口径）

- **qa_dom_parity**：段数/逐段 token 签名/code 区字节三查；索引配对成立的前提是
  空白节点保序（缺陷 3 的修复即为此）。
- **qa_terms**：双检——(a) en 段中受保护标识符（BOOST_*/303 词表/CamelCase/全大写/
  含下划线或 ::）必须在 zh 段原样出现；(b) 限定名链（ns::name）整链保留。
  普通英语词形的库目录名（system/exception/config…）不触发硬门禁（防误报），
  其保护由翻译提示词 + 抽样回读承担。
- **qa_links**：三桶语义——hard（EN 有而 zh 缺的资产，致命）/ deferred（EN 有而 zh
  未镜像，渐进期预期，S6 全量验收时须为 0）/ upstream（EN 亦缺，上游缺陷如实镜像，
  非致命）。试点 hard=0。
- **qa_coverage**：words≥4 段按 CJK/词数比值 0.5 判漏译；words≤6 短段 CJK≥1 豁免；
  命令行/编译器报错形态（RE_CMDISH）豁免；按"整页全译页"口径判定（抽样页不判）。

## 4. 已知限制（随页交付，不隐瞒）

1. 译文文本落点以 span 顺序映射为准：当译语序与原文标记顺序差异极大时，
   文本出现在最近的可写 span——已通过"空片段→单空格保节点"规则保结构。
2. Antora 页内 JS（搜索/高亮）不汉化（总纲 C10 已记录）。
3. 上游缺陷如实镜像（如 hana 模板 `$relpath^` 占位符、msm favicon 缺失、
   asio 相对外链 n4656.pdf），qa_links upstream 桶计数可查。
4. 多索引文档的 `<title>` 属性段与正文段分开入 TM（键前缀 attr:），
   属性译法与正文可见文本可能出现措辞差异，抽样回读时一并检查。
