## 1. 数据口径与基线声明

- **库口径**：与 docs/02 §4 一致的 **158 库模块**（superproject submodule 口径）。伪模块 `headers` 无 meta 文件（2026-11-14 实测 404），不计入总表。
- **作者（Authors）** = 各库仓库 `meta/libraries.json` 的 `authors` 字段：库的设计与实现者，**含历史人物**（如 Beman Dawes 仍列于 Filesystem/Endian 作者名单）。
- **当前维护者（Maintainers）** = 同文件的 `maintainers` 字段：当前负责 bug 修复与发布的第一责任人，与官网库页面同源（官网即由该 meta 渲染；作者字段 158 库交叉比对全一致，仅 math 有 1 处空格差异）。
- **数据主源**：`https://raw.githubusercontent.com/boostorg/{仓库}/master/meta/libraries.json`（master 分支 = 发布态；2026-11-14 抓取 159 个仓库，158 命中）。原始文件存 `data/p2_cache/r9_meta/`（159 份），合并数据 `data/p2_cache/r9_consolidated.json`。
- **交叉源**：官网库列表缓存（`data/p2_cache/site_libraries.json`，author_names 158 条）；boost.org `/doc/libs/1_92_0/libs/{库名}/` 文档页抽样（7 条路径实测，含 numeric/* 特殊路径与重定向终点确认）。
- **伞形模块**：`functional`、`utility` 的模块级条目无维护者标注，表中聚合其分库条目（如 `utility/string_view` → Marshall Clow）维护者并在备注列注明。
- **人名规范**：一律保留官方拼写不译（含重音符号，如 Joaquín M López Muñoz、Ion Gaztañaga）；邮箱后缀已剥离（原始格式 `姓名 <email -at- domain>` 见 meta 原文件）。
- **局限声明**：① 维护者字段由各库维护者自行更新，非实时人事系统；② 官网新站人员页尚为占位数据（见 §2.5），无法作为第二独立人事源；③ 治理类"头衔"仅采信可抓取的公开来源。

## 2. 开发与维护组织简介

### 2.1 Boost 社区：治理权在社区本身

Boost 是纯志愿者社区：库经同行评审接纳，由各自作者与维护者持续维护。Glen Fernandes 2021-05-06 邮件列表公开表述（引用帖 2026-11-14 实测可达）："Software Freedom Conservancy 从未治理过 Boost，指导委员会没有，Boost Foundation 也没有——治理 Boost 的是 Boost 社区本身（库作者与维护者）"。因此本清单的"维护者"（§4）就是 Boost 实际的治理单元。

### 2.2 指导委员会（Steering Committee）与 Boost Foundation

- 指导委员会（SC）2011-05-27 由创始人 Beman Dawes 在邮件列表宣布成立（存档帖实测可达），长期作为社区治理机构。**官方 SC 站点已私有化**（boost.org 社区菜单指向的 sites.google.com/a/boost.org/steering/ 现跳登录页，2026-11-14 实测），**截至核实日无公开可访问的现任 SC 名单页**——本清单如实记录这一缺口，不猜测名单。
- **Boost Foundation**：501(c)(3) 非营利法人，支持 Boost 库、C++Now 会议及相关计划。**现任董事会（2026-11-14 实测基金会官方联系页）**：Robert Leahy（Board 主席）、Glen Fernandes（副主席/Director）、Jeff Garland（执行总监/标准化主席）、Inbal Levi（Summer of Code 主席/Director）、Darius Neațu（Director）、Bob Steagall（C++Now 会议主席/Director）、Zach Laine（安全与包容主席/Director）、David Sankel（财务主管/Director）、Matthew Guidry（Director）。2023-06 Wayback 快照显示其时董事会另含 Michael Caisse、Hartmut Kaiser、Peter Dimov（任期制，两年一换）。
- 2024 年前后社区就 C++ Alliance 与董事会关系发生过公开争论（邮件列表存档）；另有财务托管（Fiscal Sponsorship）委员会承担监督角色。治理结构处于重构期，引用时以基金会官方页与邮件列表为准。

### 2.3 Formal Review 流程与维护者的责任

- 候选库须经邮件列表公开评审：评审期通常 **10 天**，最终接受/拒绝由**评审经理（Review Manager）**依据社区意见决定；**Review Wizard** 负责评审排期调度；另有 Fast Track 快速通道（官网评审流程页原文，2026-11-14 实测，页面存于 boostorg/website 仓库）。
- 入库后库由维护者负责 bug 修复与随版本发布（评审流程页设有"Library Maintainer's Rights and Responsibilities"专节条目；该节正文本次未能完整抓取，如实注明）。
- 版本发布由**发布经理（Release Manager）**主持：Marshall Clow 为 1.93.0 现任发布经理（2026-10-19 邮件列表发帖实测）。

### 2.4 邮件列表、版主与社区渠道

- 邮件列表（lists.boost.org，Mailman3）是评审与治理的中枢：boost（开发者主列表）、boost-users、boost-announce 等（2026-11-14 实测可达）。
- **版主（Moderators）**：历史公示名单为 Dave Abrahams、Carl Daniel、Beman Dawes、Jeff Garland、Doug Gregor、John Maddock（旧版官网页存档于 boostorg/website 仓库，实测）；职责含执行讨论政策、审批新成员、管理站点仓库等。现状：新版列表站不再公示具名版主（实测）。
- 新站渠道：CPPLang Slack（官网标注 24,000+ 成员）、Reddit、GitHub。

### 2.5 boostorg GitHub 组织与基础设施

- **boostorg**（github.com/boostorg，实测）：superproject + submodule 模式，158 库模块各自独立成仓；每仓固定含 `meta/libraries.json`（本清单数据源）、`build.jam` 或 `build/`（构建）、`test/`、`doc/`。贡献流程 = fork + PR 至对应库仓库。
- **B2 构建系统**：仓库 `boostorg/build`（"B2 makes it easy to build C++ projects, everywhere"，BSL 1.0，2026-11-11 仍有推送）；1.92.0 附带 B2 5.5.3（docs/01）。superproject 顶层含 `CMakeLists.txt` 支持 CMake 消费。
- **官网两层架构**：`boostorg/website-v2`（Django 数据层）+ `boostorg/website2022`（v3 前端 SPA），2026-11-10/11 仍有推送。**R9 实测发现**：新站 `/people/` 页当前为占位数据（全员显示 Beman Dawes + fpo 占位图），人员名单功能未完工——故本清单人员事实以 meta 字段 + 邮件列表/GitHub 交叉核实为准。
- 历史项目备案：Boost Library Official Maintainer Program（BLOM，2015，招募企业认领无主库维护，唯一公示参与方 IceCube Collaboration 认领 Boost.Function）——无后续更新记录。

### 2.6 许可证与相关组织

- **Boost Software License 1.0（BSL）**：极宽松（允许商用闭源），是"志愿者作者 + 企业使用"生态的制度基础（LICENSE_1_0.txt 实测可达）。
- **C++ Alliance**：501(c)(3) 非营利，Boost 新站重建主导方；聘用多名维护者为全职工程师（Matt Borland、Joaquín M López Muñoz 等；Vinnie Falco 为其总裁暨执行总监；名录实测）。2024 年与 Boost 董事会有过公开分歧（见 §2.2）。
- **C++Now**：基金会支持的年度会议（Bob Steagall 任会议主席）；**GSoC**：Boost 多年参与，基金会董事会设 Summer of Code 主席（Inbal Levi）。
