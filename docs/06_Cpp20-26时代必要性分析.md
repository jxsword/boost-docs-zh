## 0. 核心结论（速读）

1. **Boost 仍然必要，但角色已经结构性改变**。C++11–23 三波吸收已把 Boost 的"通用工具层"（智能指针、optional/variant/any、filesystem、string_view、format 等）大量搬进标准库；Boost 从"准标准库前置仓库"转型为"标准覆盖之外的专业领域库集合"。
2. **截止 C++26（2026-11 cppreference 判定），仍有约 66 个 Boost 库/组件族无任何标准替代**，集中在六大领域：网络异步（Asio/Beast）、单元测试（Test）、数据格式与解析（JSON/URL/Spirit）、数值科学（Multiprecision/Math/Histogram/Odeint/Graph/Geometry）、进程间通信与序列化（Interprocess/Serialization）、应用框架件（Log/ProgramOptions/Locale/Signals2/Statechart/DLL 等）。
3. **C++26 新特性（反射 P2996、执行控制 P2300、std::linalg P1673、std::simd P1928 等）会进一步削减元编程与部分数值需求**，但截至 2026-11 编译器可用性有限，且完全不触及上述六大领域。
4. **一句话答案：C++20–26 时代用 Boost 不是"要不要"而是"用哪一层"——通用词汇类型（optional/span/format）一律用 `std::`，网络、测试、JSON、图、数值扩展、IPC 这六类必须 Boost。**

## 1. 第一部分：Boost 特性 → 标准对照表（逐标准"已合入"清单）

### 1.0 判定方法

- 基准源：cppreference 各标准特性页（C++11/14/17/20/23/26，URL 见第 6 节，全部实测可达，核实日期 2026-11-14）。
- cppreference C++11 页原文即有明确血统标注（实测摘录，2026-11-14）：
  - **From TR1**：`all of TR1 except Special Functions`（TR1 全部除特殊函数——TR1 的大量组件源自 Boost 或由 Boost 提供兼容实现 `boost::tr1`）
  - **From Boost**：`The thread library`、`exception_ptr`、`error_code and error_condition`、`iterator improvements (begin, end, next, prev)`
- C++14 页无 "From Boost" 类标注段（如实记录）。
- 本表统计口径：一行 = 一个 `std::` 组件族（如 shared_ptr/weak_ptr/make_shared 计 1 行）。

### 1.6 C++26 —— 截至 2026-11（cppreference 判定；12 行，★4 / ☆1 / ◦7）

| # | 已合入的 std 组件 | 与 Boost 的关系 | 血统 | 说明 |

### 1.7 血统小结：三波吸收曲线

| 标准 | 行数 | ★/☆/◦ | 特征 |
|---|---|---|---|
| C++11 | 25 | ★20 / ☆3 / ◦2 | 最大吸收（TR1 + Thread/System/Exception 直系） |
| C++14 | 0 | ◦3（间接） | 低谷：无直接血统组件 |
| C++17 | 17 | ★14 / ☆1 / ◦2 | TS 并入潮（filesystem/optional/variant/any/string_view/特殊函数） |
| C++20 | 13 | ★7 / ☆2 / ◦4 | Range-v3 血统 + 位操作/同步原语；format/span 为非 Boost 谱系 |
| C++23 | 12 | ★4 / ☆4 / ◦4 | expected/flat_map/stacktrace 直系；Compat 开始反向输出兼容实现 |
| C++26 | 12 | ★4 / ☆1 / ◦7 | 渐冷：新特性多为全新设计；Boost 侧以 Compat 向后移植、Cobalt 补生态应对 |

**结论**：Boost → std 的直接吸收在 C++23 达到第三峰后明显降温；C++26 的执行控制、反射、linalg、simd 均为非 Boost 直系的新设计。Boost 的价值重心已完全转移到第 2 部分的"标准永不覆盖区"。

## 2. 第二部分：截止 C++26 仍未入标准、必须用 Boost 的清单（定稿）

### 2.0 核实方法与特别核实项

- **核实基准**：cppreference C++11/14/17/20/23/26 六页特性清单逐页核对（核实日期 2026-11-14），六页无对应组件即判定"未入标准"；Boost 库存在性以 1.92.0 官方库清单实测为准。
- **特别核实项（写入/排除依据）**：
  1. 网络库：C++11–26 六页均无网络/socket 组件；联网 TS（Networking TS）从未并入任何标准 → Asio 类必用成立。
  2. `std::process` 未入 C++26（cppreference 2026-11 实测）→ boost::process 必用成立。
  3. scope guards 未入 C++26（实测）→ boost::scope（1.85.0 新增，"A collection of scope guard utilities and a unique_resource wrapper, from Andrey Semashev"）必用成立。
  4. `std::linalg`（P1673）与 `std::hive`（P0447）**已入 C++26**（实测）→ uBLAS 的 BLAS 用法将面临标准替代（过渡期结论），hive 与 Boost 无对应。
  5. Boost 1.92.0 清单实测无 concurrent_ptr / hazard_pointer / rcu / SIMD / Function2 库 → 相关任务候选不采信；std::simd 视为已移出的 Boost.SIMD 精神续作。
- **定稿口径**：A 类 = 核心必用（无标准替代、无平替争议）；B 类 = 过渡期必用（C++26 反射/linalg/execution 普及后可退役）；C 类 = 特殊场景必用（有部分标准替代但关键能力缺失）。

## 4. Boost 与标准库总对比（四件套）

### 4.1 简介

- **Boost（C++ 准标准库集合）**：约 150 个库、30 个分类（1.92.0 实测），宽松开源许可证（Boost Software License），每版四项校验发布。定位：标准的前置试验田 + 标准覆盖外的专业领域库。
- **标准库（`std::`）**：随编译器与平台分发，C++11→26 逐版吸收 Boost 血统组件与全新设计；覆盖"语言配套的通用层"，不覆盖网络、测试、专业数值等领域。

### 4.2 优缺点

| 维度 | Boost 优点 | Boost 缺点 | 标准库优点 | 标准库缺点 |
|---|---|---|---|---|
| 可用性 | 旧标准可用（最低 C++03/11 实测）；不受编译器版本拖累 | 需要额外获取/构建（部分需编译） | 随编译器即得、无第三方依赖 | 受限于工具链标准版本（企业常被锁在 C++14/17） |
| 覆盖面 | 网络/测试/JSON/图/数值等标准永不覆盖区 | 与 std 双轨并存易混用 | 词汇类型/容器/算法全面且 ABI 稳定 | 网络等领域缺位；平台实现质量不一 |
| 前瞻性 | 提案试验场（expected/flat_map/execution 的先例均出自社区） | API 随标准演进产生双轨（boost/std 同名组件） | 已合入组件稳定、文档权威 | 新特性滞后 Boost 实践 5–10 年 |
| 质量 | 回归测试矩阵 + 多编译器 CI | 各库质量/维护度不均 | 主流编译器保证 | — |
| 成本 | header-only 子集零构建成本 | 编译期长、二进制体积、版本升级风险 | 零引入成本 | — |

### 4.3 适用场景

- **Boost 优先**：网络异步服务；单测；JSON/URL/配置解析；图/几何/数值扩展；共享内存 IPC 与序列化；无锁/侵入式/多索引等高性能容器；插件与进程管理。
- **标准库优先**：新代码的智能指针/optional/variant/string_view/format/span/filesystem/chrono 日历/正则/线程与同步。
- **混合**：同一工程内——基础设施用 std 词汇类型，专业域引入对应 Boost 库；旧工具链项目用 Boost/Compat 桥接标准差。

### 4.4 选择策略矩阵

| 你的处境 | 建议 | 理由 |
|---|---|---|
| 新项目，C++23/26 工具链，纯业务逻辑 | std 为主，按需引入 Boost 专业域库 | 词汇类型已全覆盖；Boost 仅按第 3 节①类场景引入 |
| 新项目，C++20 工具链，含网络/测试/JSON | Boost 直接入列 | Asio/Beast/Test/JSON/URL 免拼装第三方，质量统一 |
| 维护 C++03–14 遗留系统 | Boost + Compat 桥接 | Compat 把 C++14–26 组件带回 C++11（官方实现，1.83.0 起） |
| 开发需跨多年编译器分发的库 | Boost 组件 + 特性测试宏分级 | Boost 版本谱系跨标准一致 |
| 追求最小构建体积/编译时间 | bcp/模块化提取 header-only 子集 | 避免整包引入 |
| 需要 Asio 网络栈 | 无论标准多新仍用 Boost | std 截止 C++26 无对应物 |

## 5. 总结论：C++20–26 时代 Boost 还有没有必要用

**有必要，且在六类领域不可替代。** 分三层回答：

1. **通用工具层——不必再用**。C++11（25 组件族）、C++17（17）、C++20（13）、C++23（12）已把智能指针、正则、无序容器、线程、optional/variant/any、filesystem、string_view、ranges、format、expected、flat_map、stacktrace 等约 79 个组件族中的大多数搬入标准（含 C++26 的 inplace_vector/function_ref 等）。新代码的"词汇类型与基础算法"应直接写 `std::`，保留 Boost 反而增加双轨负担。唯一例外是旧工具链：Boost 与 Compat 是把新标准带回旧编译器的唯一官方级通道。

2. **专业领域层——必须用**。截止 C++26（cppreference 2026-11 判定）下列领域标准库仍然空缺：网络异步（Asio/Beast/Redis）、单元测试（Test）、JSON/URL/配置（JSON/URL/PropertyTree）、图与几何（Graph/Geometry）、数值扩展（Multiprecision/Math/Histogram/Odeint/Units/QVM）、IPC 与序列化（Interprocess/Serialization）、解析器（Spirit）、状态机与信号槽（Statechart/MSM/Signals2）、日志与 CLI（Log/ProgramOptions）、本地化（Locale）、插件与进程（DLL/Process）、动态设施（Scope/Lockfree/Intrusive/MultiIndex/CircularBuffer/Histogram/Odeint/GIL/DLL/UUID/Wave/Iostreams/Nowide）。**定稿：A 类核心必用 33 项 + B 类过渡期必用 11 项 + C 类特殊场景必用 22 项，合计 66 项**；另有 19 项已被标准替代移出必用清单。

3. **未来层——C++26 会减一部分，但减不掉主体**。反射（P2996）落地后 Mp11/Hana/PFR/Describe 用法将大幅退役；`std::linalg`（P1673）与 `std::simd`（P1928）将挤压 uBLAS 与数值 SIMD 空间；`std::execution`（P2300）提供执行控制框架——但 socket、测试框架、JSON、图算法、任意精度、共享内存 IPC 等 C++26 一项都没给。**结论重申：C++20–26 时代 Boost 仍然必要——它已从"标准的前置仓库"变成"标准之外的必选专业库"；网络、测试、数据格式、数值科学、IPC 五大类是刚需区。**
