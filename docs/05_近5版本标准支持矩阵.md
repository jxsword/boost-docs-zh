## 0. 两种认定口径（本矩阵的核心方法）

Boost 官方**没有任何一页文档**声明"Boost X.Y 全库最低 C++ 标准"，因此本文件严格区分两种证据口径：

| 口径 | 含义 | 证据源 |
|---|---|---|
| **官方声明支持**（矩阵 A） | 各版发布说明（release notes）中的逐库标准要求、发布说明末尾的 "Compilers Tested"（主要测试编译器）清单、库文档中的 Requirements 页 | boost.org 各版发布页 / boostorg/website 存档 HTML / 1.92.0 库文档 |
| **CI 实测矩阵**（矩阵 B） | boostorg 各库仓库 `.github/workflows/ci.yml`（及 boostorg/boost-ci 可复用工作流）中实际列出的 CXXSTD 与编译器组合 | GitHub raw（经代理核实） |

两口径最重要的差异（本调研实测发现）：**1.88.0–1.92.0 五个版本的发布说明 "Compilers Tested" 一字未改**（模板自旧版沿用），最高只列到 **C++20**；而 CI 实测早已覆盖到 C++23/26（如 GCC 16、Clang 22）。即官方"声明口径"落后于"实测口径"。

图例：✔ 支持 ｜ ◐ 部分/有条件支持 ｜ ✖ 不支持/已弃用 ｜ **—** 官方未声明（不代表不可用）

| 版本 | 发布说明 "Compilers Tested" 声明的测试矩阵（五版完全相同，模板未更新） |
|---|---|
| 1.88.0–1.92.0（全部） | Linux：Clang（C++03: 3.4–3.9、12.0.0–15.0.0；C++11: 3.4/11/13/14/15；C++14: 3.5–5.0、12–15；C++17: 6.0.1–15；C++20: 11–15）；GCC（C++03: 4.6.3、11、12；C++11: 4.7.3、4.8.5、11、12；C++14: 5.4.0–9.1.0、11、12；C++17: 7.3.0–9.1.0、11、12；C++20: 8.0.1–12）。OS X：Apple Clang 11.0.3（C++03–C++20）。Windows：Visual C++ 10.0、11.0、12.0、14.0、14.1、14.2、14.3 |

### 3.2 逐库明细（抽查原文）

**Config**（`boostorg/config/.github/workflows/ci.yml`，develop 分支）
- Linux（ubuntu-24.04，`g++-13, g++-14`；ubuntu-22.04，`g++-11, g++-12, g++-13` 与 `clang++-15`）：`b2 ... cxxstd=03,11,14,17,20`
- macOS（macos-latest，em++）与 Windows（windows-2025）：MSVC `cxxstd=14,17,20,latest`；MSVC /clr `cxxstd=14,17,20`；clang-win `cxxstd=14,17,latest`；MinGW gcc `cxxstd=14,17,20`
- 另有兼容性 job：`toolset=gcc cxxstd=03,11,14,17` 与 `toolset=clang cxxstd=03,11,14,17`
- 解读：Config 作为全库兼容层仍实测 **C++03**；MSVC 上从 C++14 起测。

**Container**（`boostorg/container/.github/workflows/ci.yml`，develop 分支；~54KB 自定义矩阵）
- GCC：`gcc-4.8`（`cxxstd: "03,11"`，ubuntu:18.04 容器）→ `gcc-7`（`"03,11,14,17"`）→ `gcc-10`（`"03,11,14,17,20"`）→ `gcc-11/12`（`"03,11,14,17,20,23"`）→ `gcc-13`（`"03,11,14,17,20,2b"`）→ **`gcc-14/15/16`（`"03,11,14,17,20,23,26"`）**
- Clang：`clang-3.6–3.9`（`"03,11,14"`）→ `clang-6/7`（`"03,11,14,17"`）→ `clang-10–12`（`"03,11,14,17,20"`）→ 最新 clang 至 2c
- macOS：clang `cxxstd: "11,14,17,20,2b"` 与 `"11,14,17,20,23,2c"`（macos-15）
- Windows：`msvc-14.3` / `msvc-14.5`（`cxxstd: "14,17,20,latest"`，windows-2022/2025，32/64 位与 ARM）；clang-win（`"14,17,latest"`）；Windows gcc（`"03,11,14,17,2a"`）
- 解读：抽查库中唯一**仍实测 C++03** 的容器库，且 C++26 覆盖最完整（GCC 14/15/16 显式 "26"）。

**Test**（`boostorg/test/.github/workflows/ci.yml` → `boostorg/boost-ci/.github/workflows/reusable.yml@master` 默认矩阵 + 仓库排除项）
- 模板默认矩阵（节选原文）：`gcc-4.8 (cxxstd "11")`、`gcc-5 ("11,14,1z")`、`gcc-10 ("11,14,17,20")`、**`gcc-14 ("11,14,17,20,23")`、`gcc-15 ("11,14,17,20,23,2c")`、`gcc-16 ("11,14,17,20,23,26")`**；`clang-3.5 ("11")`、`clang-10–15 ("11,14,17,20")`、`clang-17 ("11,14,17,20,23")`、**`clang-20–22 ("11,14,17,20,23,2c")`**；`icpx-2025 ("11,14,17,20,23,2c")`
- Windows：`{"toolset": "msvc-14.3", "cxxstd": "14,17,20,latest", "os": "windows-2022"}`；`{"toolset": "msvc-14.5", "cxxstd": "14,17,20,latest", "os": "windows-2025-vs2026"}`（含 windows-11-arm）
- 仓库排除项（原文）：`compiler: 'gcc-4.8,gcc-4.9'  # Not C++11 compliant enough for Boost.Test`
- 解读：Test 的 CI 是全库覆盖最全的（C++11–26），且官方注释明言 C++11 合规底线；MSVC 工具集只测 14.3/14.5。

**URL**（`boostorg/url/.github/workflows/ci.yml`，develop 分支，`alandefreitas/cpp-actions/cpp-matrix@v1.9.5` 生成器）
- 生成器参数（原文）：`compilers: gcc >=8 / clang >=7 / msvc >=14.20 / apple-clang * / mingw *`；`standards: '>=11'`；最新编译器追加 `,latest`（b2 的 latest 占位可衰减至 2b/2c）
- 生成器内注释（原文）：GCC 5–7 与 Clang 3.8–6 因 runner 镜像（glibc）暂时无法承载，"The library still supports these compilers (C++11)"
- 解读：官方明示库支持 **C++11**；CI 当前下限 GCC 8 / Clang 7 / MSVC 14.20（VS2019），C++23/26 经 latest 占位覆盖。

**Asio**（`chriskohlhoff/asio/.github/workflows/linux.yml`，master 分支；boostorg/asio 为上游镜像，实测其 `.github` 目录无 workflows）
- Linux 标准（原文）：`cxx-std: ['c++11', 'c++14', 'c++17', 'c++2a', 'c++20', 'c++23', 'c++2c']`
- 编译器抽查：`g++-9/10/11/12/14/15`、`clang++-14/18/22`
- Windows（`windows.yml`）：`windows-2022/windows-2025/windows-11-arm` 的 msvc，另有 `CXXLATEST=1`、`SEPARATE_COMPILATION=1`、`clang-cl` 变体
- 解读：Asio CI 从 **C++11 一路测到 c++2c（C++26 草案）**；Windows 上由上游用当前 MSVC 直测（不展开多标准档）。

**JSON**（`boostorg/json`，develop 分支）
- `.github/workflows/` 仅含 `run_analyze-bloat.yml` 与 `run_fuzzer.yml`（实测 API 列举）——**无 GitHub Actions 测试矩阵**
- `.appveyor.yml`（Windows CI，B2_CXXSTD 原文节选）：VS2022 `14,17,20`；VS2019 `14,17,2a` 与 `11,14,17`；VS2017 `2a`、`14,17`、`11,14,1z`
- 库文档（1.92.0 JSON 文档页）："Requires only C++11"；文档所列已测编译器：clang 3.5–14、gcc 5–12、msvc 14.0–14.3
- 解读：文档口径 C++11 底线明确；CI 实测集中在 MSVC（11–20），Linux 矩阵不在 GitHub Actions。

**StlInterfaces**（`boostorg/stl_interfaces/.github/workflows/ci.yml`，develop 分支；旧版 boost-ci 模板）
- 抽查 job：`gcc-7/8/9`（ubuntu-20.04，`buildtype: "boost"`）等；模板按编译器默认标准集展开
- README 原文："This library requires at least C++14."
- 解读：文档明示 **C++14 底线**；CI 采用旧模板（GCC 7 起）。

### 3.3 回归测试看板（官方口径）

### 4.2 b2（构建工具）自身要求

Boost 1.73.0 发布说明（boostorg/website 存档，2026-11-14 经代理核实）原文：
> "WARNING: Since version 4.0.0 B2 requires a capable C++11 compiler to bootstrap."

即自 B2 4.0.0 起，**构建驱动 b2 自身的 bootstrap 需要 C++11 编译器**——这是近 5 版（1.88–1.92 内置 b2 5.3.2–5.5.3）构建 Boost 的硬前提之一。

### 4.3 考证："Boost 官方最低 C++11"从何而来（调研修正）

- **不存在**"某版本起官方全局最低 C++11"的单点声明。实测 boostorg/boost 1.92.0 超级项目 README、1.92.0 Config 文档首页均**无**最低标准/最低编译器版本声明。
- 真实演进路径（官方原文证据链）：
  1. **2020 年（1.73.0）起逐库弃用 C++03**：1.73 发布说明原文——Geometry "Support for C++03 has been deprecated and Geometry will require C++14 from Boost 1.75 onwards"；Math "C++03 support is now deprecated and will be removed from March 2021"；Multiprecision "Mark C++03 support as deprecated and due for removal in 2021"。
  2. 2021–2024 各库陆续落地 C++11 底线（Atomic 1.89、SmartPtr 1.90、MultiIndex 1.91 为近 5 版内的最后一批）。
  3. CI 层面：boost-ci 模板主线从 C++11 起测（`gcc-4.8 (11)`/`clang-3.5 (11)`），MSVC 从 14.3 起测（C++14 起步）。
- 结论：**"近 5 版的事实最低标准线 = C++11（构建 b2 亦需 C++11）"，但这是逐库声明 + CI 矩阵的事实收敛，而非官方全局声明**——个别库（如 Container）的 CI 仍保留 C++03 行。

## 5. 特殊情形与前瞻

1. **C++20 模块（C++20 modules）**：1.89.0 初始支持（Any/TypeIndex/PFR）→ 1.92.0 扩容至 Conversion/DLL/LexicalCast/PFR/Stacktrace/TypeIndex，并 "tested with and without `import std`"。C++26 列的"部分/前瞻"属性亦适用于模块化用法（需支持 modules 的 C++20/23 工具集）。
2. **Heap / Lockfree 弃 C++14（前瞻）**：1.92.0 官方宣布"本版是最后支持 C++14 的版本，未来版本将要求 C++17"——直接影响 1.93.0（2026-12-09 定档）。
3. **PFR 的 C++26 前瞻**：1.90.0 pack 解构实现（`BOOST_PFR_USE_CPP26`）、1.91.0 实验性 C++26 反射实现（`BOOST_PFR_USE_CPP26_REFLECTION`）——标准未定稿前的实验开关。
4. **C++26 兼容性修复**：1.89.0 Iterator 移除弃用的 `is_trivial`（C++26 中弃用）。
5. **新库标准底线速查**：OpenMethod（1.90.0）= C++17；Decimal（1.91.0）= C++14；StlInterfaces = C++14；Hash2/MQTT5（1.88.0）按其文档执行（未在本矩阵展开）。

## 6. 选择策略矩阵（按编译器现状选 Boost 版本）

| 用户处境（编译器/标准现状） | 推荐版本 | 理由 | 风险/注意事项 |
|---|---|---|---|
| 现代工具集：GCC ≥ 12 / Clang ≥ 15 / MSVC 14.3+，目标 C++17/20/23 | **1.92.0** | C++20 模块、Unordered ranges、URL 编译期解析、PFR C++26 实验等新能力均需新工具集；CI 对 C++23/26 的覆盖以 GCC 14+/Clang 20+ 为主 | C++23/26 官方声明口径"未声明"，属 CI 级覆盖；启用 C++20 modules 需确认工具集 modules 支持度 |
| 企业保守环境：C++14–17（GCC 7–11 / MSVC 14.1–14.2） | **1.92.0 仍可用**；长期冻结项目可锁 1.91.0-1 | C++11–17 是 boost-ci 主线（CI 全矩阵覆盖）；1.92.0 对 C++14/17 无破坏 | **1.93 起 Heap/Lockfree 将要求 C++17**（1.92.0 官方预告）；Math 要求 C++14（1.89 起）；MultiIndex 已弃 pre-C++11 |
| 老平台 C++11：GCC 4.8–4.9 / Clang 3.5–3.9 | **锁定历史版本**（约 1.72–1.81 区间，与 P4 主流区间衔接） | 近 5 版虽名义 C++11，但逐库地板持续抬高（Atomic/SmartPtr/MultiIndex 均在 1.89–1.91 收紧）；Test 官方 CI 注释明确 gcc-4.8/4.9 "C++11 合规度不足" | URL/JSON 等 C++11 库在老 GCC 上可用，但 Asio 新特性与 MSVC 侧支持差；无安全修复回灌 |
| MSVC ≤ 14.2（VS2015/2017 早期） | **锁定历史版本**（按库文档选择：JSON 文档仍列 msvc 14.0–14.3；URL 列 14.1–14.3） | 近 5 版 CI 实际只测 msvc-14.3/14.5，旧 MSVC 无回归保障 | 发布说明 "Compilers Tested" 的 MSVC 10.0–14.3 是陈旧模板，勿据此判断 |
| 场景驱动：网络/异步（Asio） | 1.92.0（上游 CI C++11–2c 全覆盖） | C++20 协程、C++17 外部链接 CPO 等渐进增强 | C++11 仍为底线；独立版 asio 与 Boost.Asio 版本对应关系另见 Asio 文档 |
| 场景驱动：JSON/URL/Beast 数据栈 | 1.92.0 | JSON "Requires only C++11"；URL 要求 C++11 | URL CI 下限 GCC 8/Clang 7/MSVC 14.20 |
| 场景驱动：单元测试（Test） | 任意近版（C++11+） | CI 矩阵最全（C++11–26、GCC/Clang/MSVC/Intel） | 老于 GCC 5 的环境需退回历史版本 |

**一句话结论**：近 5 版（1.88–1.92）的官方事实底线为 **C++11（b2 bootstrap 亦需 C++11）**，C++11/14/17/20 为全矩阵支持区，C++23 为 CI 级覆盖（官方未声明），C++26 为部分/前瞻（实验特性 + 实验性 CI 档）；编译器达标（GCC ≥ 12 / Clang ≥ 15 / MSVC 14.3+）时直接用 1.92.0，C++14 冻结项目注意 1.93 起 Heap/Lockfree 的 C++17 要求。
