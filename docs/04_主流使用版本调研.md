# Boost 主流使用版本调研（R4）

> 元数据
> 生成日期：2026-11-14 ｜ 版本基线：Boost 1.92.0（2026-11-14 冻结）
> 基线冻结声明：本文一切"当前/主流"判断以 2026-11-14 为准；上游最新稳定版为 Boost 1.92.0（2026-08-12 发布，GitHub `published_at` 实测）；1.91.0-1 为修补版本（修补重发布）；近 5 稳定版倒序为 1.92.0 → 1.91.0(-1) → 1.90.0 → 1.89.0 → 1.88.0；1.93.0-beta1（2026-11-11 发布）只预告、不纳入统计。
> 方法：9 类数据源逐个实测（每条 URL 记录核实日期与现象），多源加权得出"主流版本区间"结论，不单点化。
> 一句话结论：**截至 2026-11-14，各渠道 Boost 版本主要落在 1.80–1.92 区间，活跃主流核心为 1.83–1.90；滚动/包管理渠道已到 1.92.0，Conan 1.91.0，普通发行版 stable 多为 1.83–1.88，长期支持（LTS）与企业存量长尾在 1.66–1.79。**

## 1. 调研范围与方法

- **对象**：Boost（C++ 准标准库集合）在各发行版、包管理器与官方渠道中的"实际被使用的版本"分布。
- **数据源（9 类）**：Repology（发行版包版本聚合站）、Debian、Ubuntu、Fedora、Homebrew（macOS/Linux 包管理器）、vcpkg（微软系 C++ 包管理器）、Conan（去中心化 C/C++ 包管理器）、官方下载统计、其他旁证（MSYS2、Cygwin、Nixpkgs、Spack、xrepo、OpenWrt、企业级 EL 系、BSD 系、Chocolatey、Scoop、MacPorts 等）。
- **加权原则**：以"发行版/渠道分支"为统计单元（Repology 页面行数为包条目数，Alpine/Cygwin 等按库拆包会导致行数膨胀，需去重解读）；滚动渠道与快发行版反映"新项目可获得版本"，LTS/企业分支反映"存量系统锁定版本"；两类合并后给出区间而非单点。
- **网络环境**：本机直连失败或异常时统一走代理 `http://127.0.0.1:10808`；下表逐条记录。

### 4.2 发布节奏与渠道滞后规律

上游近 12 版发布日期均为 GitHub `published_at` 实测（见附录 A）：自 2022-12（1.81.0）起稳定维持"每年 4/8/12 月三发"节奏，每年净增 3 个 minor。据此把各渠道"落后上游的 minor 数"折算为滞后时长：

| 渠道类型 | 当前版本 | 落后 minor 数 | 滞后时长（约） | 滞后原因 |
|---|---|---|---|---|
| 滚动社区仓（Arch/Gentoo/Homebrew/MSYS2/FreeBSD/Tumbleweed/Scoop）与 vcpkg | 1.92.0 | 0 | 0–1 个月 | 随上游 tag 即时跟进 |
| Conan | 1.91.0 | 1 | 3–4 个月（一个发布周期） | 配方入库需 CI 验证 |
| Nixpkgs unstable / Debian sid / Debian 14 / Ubuntu 26.10 | 1.92.0 | 0 | 0–2 个月 | 开发分支随上游 |
| 快发行版 stable（Debian 13 = 1.88.0；Fedora 44 = 1.90.0；Ubuntu 26.04 = 1.90.0） | 1.88–1.90 | 2–4 | 6–19 个月 | 发布冻结后再不升版本 |
| 普通/次新发行版（Fedora 41–43 = 1.83.0；Alpine = 1.84.0；OpenWrt 24.10 = 1.86.0） | 1.83–1.86 | 6–9 | 1–3 年 | 同上 + 打包者保守策略 |
| 长期支持（LTS）（Ubuntu 24.04 = 1.83.0、22.04 = 1.74.0；Debian 12 = 1.81.0） | 1.74–1.83 | 9–18 | 3–6 年 | 只修不升（安全修补除外） |
| 企业级 EL 系（EL10 = 1.83.0、EL9 = 1.75.0、EL8 = 1.66.0） | 1.66–1.83 | 9–26 | 3–8 年 | ABI 稳定优先 |

**规律总结**：发行版打包滞后上游约 6 个月（滚动/开发分支）到 6 年（企业 LTS），典型 stable 发行版滞后约 2–4 个 minor（6–19 个月）；滞后来自发行版"发布冻结 + 仅安全修补"策略与重新打包/ABI 维护成本，而非上游不活跃。**发行版用户拿到的 Boost"先天"就是旧版**——这不是 Boost 特有，而是所有活跃上游库在发行版中的常态。

### 4.3 主流版本区间结论（多源加权，不单点）

> 综合第 3、4.1、4.2 节实测数据加权后的结论：

1. **主流版本区间：1.80 – 1.92**。绝大多数活跃渠道（滚动仓、包管理器、快发行版全部活跃分支）的当前版本都落在这个区间内。
2. **活跃主流核心：1.83 – 1.90**。这是"发行版 stable + 包管理器 + 下载量"三源交集：Conan 1.91.0、Fedora 41–43 与 EL10 与 Ubuntu 24.04 与 Alpine 共同锚定 1.83.0、Debian 13 与 Nixpkgs 25.11 锚定 1.88–1.89.0、Fedora 44/Ubuntu 26.04/Cygwin/Spack 锚定 1.90.0。
3. **最新前沿：1.92.0**。vcpkg/Homebrew/MSYS2/Arch/Gentoo/FreeBSD/Nix unstable/Debian sid 等已同步 1.92.0。
4. **企业存量长尾：1.66 – 1.79**（含 1.53/1.58 等更旧孤例）。EL8/9、Ubuntu 22.04/20.04、Debian 11、openSUSE Leap 15.x、Windows 上 Chocolatey 的 MSVC141 老工具集包等。这些版本仍在大量生产系统中运行，但已不属于"新项目可选"的主流。
5. **客观分布事实**：上游 1.92.0 很新（发布仅 3 个月），但**主流发行版多数仍打包 1.7x–1.8x**——"最新版"与"主流版"之间天然存在 1–3 年落差；统计上不存在单一"人人在用"的版本点，而是一个由渠道策略决定的区间分布。

## 5. 获取渠道比较（四件套）

### 5.1 各渠道简介

| 渠道 | 简介 |
|---|---|
| 系统发行版包（Debian/Ubuntu/Fedora/EL 系等，apt/dnf/zypper 安装） | 发行版维护者重新打包的 Boost，随系统分发；Debian 系以 `libboost1.8x-dev` 命名、Fedora 系单包 `boost` |
| 滚动社区仓（Arch/Gentoo/Homebrew/MSYS2/Nixpkgs/FreeBSD 等） | 随上游快速跟进的社区打包；Homebrew 另提供 boost@1.85 版本化公式兼容旧需求 |
| vcpkg | 微软系 C++ 包管理器：清单模式（manifest）+ 基线（baseline）锁定全部 162 个 `boost-*` 端口版本，与 MSVC/Visual Studio 生态深度集成 |
| Conan | 去中心化 C/C++ 包管理器：ConanCenter 仓库提供 boost 配方，lockfile 可精确锁定版本与选项 |
| 官方源码（GitHub Releases / archives.boost.io / git 子模块） | 上游单体发布包（含 b2（Boost 构建工具）驱动源码编译）或按库 clone boostorg 各仓；自编译最灵活 |
| Windows 独立渠道（Chocolatey/Scoop） | 预编译二进制按 MSVC 工具集拆包，安装即用但版本较旧 |

### 5.2 各渠道优缺点

| 渠道 | 优点 | 缺点 |
|---|---|---|
| 系统发行版包 | 与系统工具链/ABI 匹配；依赖自动解决；安全修补随系统推送；锁定天然成立 | 版本陈旧（stable 滞后 2–4 minor，LTS 滞后 3–6 年）；多版本并存困难（Debian 系靠包名后缀、Fedora 系基本单版本）；跨平台不可复用 |
| 滚动社区仓 | 版本新（0–1 minor）；安装简单 | 几乎无法锁旧版本（升级即变）；可复现构建差；部分仅单机环境适用 |
| vcpkg | 版本最新（1.92.0）；基线 + 清单锁定容易；Windows/MSVC 体验最好；跨平台 | 全库编译耗时；与系统包易混用冲突；基线随仓库 master 移动需自管 |
| Conan | 锁定最精确（lockfile）；版本区间宽（1.78–1.91 可选）；选项（header-only/静态/动态）可配 | 比上游滞后约 1 个 minor；配方/选项学习成本；需配置远程仓库 |
| 官方源码 | 版本任意可选；完全可控；仅头文件库直接解包即用 | 需编译的库要自行 b2/CMake 构建；无依赖管理与自动更新 |
| Windows 独立渠道 | 免编译，装完即用 | 版本旧（1.87.0 及更旧）；按工具集碎片化；工程集成能力弱 |

### 5.3 适用场景

| 渠道 | 适用场景 |
|---|---|
| 系统发行版包 | 服务器/桌面系统级软件、随发行版交付的程序、以系统包为依赖基线的开源项目 |
| 滚动社区仓 | 开发者本机快速试验、新特性尝鲜 |
| vcpkg | Windows/MSVC 项目、Visual Studio 工程、需要大量第三方 C++ 依赖的应用 |
| Conan | 多平台 C++ 工程、需要精确可复现构建的团队、CI/CD 依赖治理 |
| 官方源码 | 需要特定版本/补丁、嵌入式裁剪（bcp 子集复制）、仅头文件库快速集成 |
| Windows 独立渠道 | 无包管理器的传统 Windows 环境、老工具集兼容 |

### 5.4 选择策略矩阵

| 渠道 | 版本新旧（2026-11-14） | 更新频率 | 适用人群 | 锁定难度（锁定容易度） |
|---|---|---|---|---|
| 系统发行版包 | 旧（1.74–1.90，随套件冻结） | 随发行版（半年~数年一次，仅安全修补） | 运维/系统工程师、Linux 桌面用户 | **天然锁定**（升级需换发行版或自编译，反而"想升难"） |
| 滚动社区仓 | 最新（1.92.0） | 天级~周级 | 尝鲜者、本机开发 | 难（需 AUR 旧包/Nix 固定等旁门手段） |
| vcpkg | 最新（1.92.0） | 随上游（周级） | Windows/跨平台应用开发 | **容易**（baseline + manifest 一行锁定） |
| Conan | 较新（1.91.0，滞后 1 minor） | 随上游（周级，入库晚一个周期） | 工程化团队、多平台产品 | **最容易**（lockfile 精确到版本+选项） |
| 官方源码 | 任意（1.81–1.92 及历史全版本） | 随上游（季级三发） | 库作者、嵌入式、特殊版本需求 | 完全可控（自行管理目录/子模块） |
| Chocolatey/Scoop | 旧（1.58–1.92 分工具集） | 月级 | 传统 Windows 环境 | 中等（Scoop 可锁 manifest；Chocolatey pin） |

## 6. 按场景选择结论

- **企业存量系统**：不必也无法追新。跟随所在系统的发行版包（EL9 = 1.75.0、Ubuntu 24.04 LTS = 1.83.0、Debian 12 = 1.81.0 等），升级 Boost 以"换系统版本/大版本迭代"为节奏；对旧版本只需关注安全修补（发行版会做向后移植）。跨公司代码复用与库作者对接时，以"最低支持 1.6x–1.7x"为兼容基线沟通。
- **新项目**：优先走 C++ 包管理器拿最新稳定版——vcpkg 基线 1.92.0 或 Conan 1.91.0，并用清单/lockfile 从第一天锁定版本；不依赖发行版 Boost，避免"开发机新、部署机旧"漂移。
- **开源库作者（含面向 vcpkg/Conan 用户）**：版本声明采用区间而非单点——建议 CI 覆盖 1.78（Conan 仍收录的最旧）~1.92（上游最新）中的 3–5 个锚点（如 1.78/1.83/1.88/1.92），对仅头文件库尽量放宽下限；分发上确保出现在 vcpkg（已 1.92.0）与 Conan Center（1.91.0，留意入库晚一个周期的窗口期）两条主通路，不要假设用户能拿到 1.92。
- **Windows 开发**：MSVC 工具链走 vcpkg（1.92.0，与 Visual Studio 集成最好）；MinGW/clang 环境走 MSYS2（1.92.0-4）；传统无包管理环境可用 Chocolatey（1.87.0，较旧）或官方预编译/自编译。跨平台项目统一用 vcpkg/Conan 消解 Windows 与 Linux 发行版版本差异。
- **跨平台项目**：以 Conan lockfile 或 vcpkg baseline 把 Boost 版本写入仓库，做到"一处声明、三平台一致"；服务器部署端用容器镜像自持 Boost 版本，不信任宿主发行版包。

## 7. 分布事实的客观说明（避免误导）

- 上游 1.92.0 于 2026-08-12 发布，至今约 3 个月；**1.93.0-beta1 已于 2026-11-11 预告（不计入统计）**。
- 但发行版侧：Debian 13 stable = 1.88.0、Ubuntu 24.04 LTS = 1.83.0、Fedora 43 = 1.83.0、EL10 = 1.83.0、Alpine = 1.84.0——**主流发行版打包的多为 1.7x/1.8x**；只有滚动渠道与 C++ 包管理器拿到了 1.9x。引用本文数据讨论"Boost 现状"时，应区分"上游最新（1.92.0）""活跃主流（1.83–1.90）""存量长尾（1.66–1.79）"三层，不可混为一谈。
