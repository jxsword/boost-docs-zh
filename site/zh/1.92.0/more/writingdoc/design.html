引言

Boost 对库提交者 HTML 文档的设计没有任何要求. 如果你要提交的库已有 HTML 格式的文档, 或有易于转换为 HTML 格式的文档, 那么你无需阅读本文档. 但是, 如果你尚未编写文档, 或者预计需要翻译某种不易转换为 HTML 的格式的文档, 那么本文档可以为你提供大量关于如何用 HTML 编写文档的信息.

本文档有多处假定你编写的文档符合 文档结构文档中描述的结构. 并不要求你的文档内容遵循这些指南, 但它们提供了一种简洁而精确的方式, 可用于传达库的技术规范, 且为许多 Boost 用户所熟悉.

本文档还包含指向 HTML 模板文件的链接, 这些文件可用于快速开发库提交所需的文档. 这些模板遵循此处以及 文档结构文档中提出的指南.

HTML 文档包含的常见页面

大多数 HTML 文档项目都会包含一些常见页面. 下面给出这些常见页面的一般指南.

索引

索引页是用户浏览文档时看到的第一个页面. 通常该页面不应包含任何实际内容, 而是包含一个指向具体内容的链接列表. 该列表至少应包含指向文档中每个 HTML 页面的链接. 也可以选择为单个页面提供子列表, 链接到页面内的具体主题. 这些子列表应依据具体主题所用标题标签的层级构成"树"状层次. 为每个页面都提供这种子列表会使索引相当冗长, 而且由于每个页面都应包含自己的 页面索引, 避免这种子列表可能会使文档的导航更容易. 不过, 本指南有一个例外: 参考文档应包含指向库中每个头文件的链接, 以及一个子列表, 链接到头文件中发现的每个宏、值、类型、类、函数和对象 (参见 文档结构). 用户并不总是确定这些内容可能包含在哪个头文件中, 因此索引中的这种结构便于参考文档的导航.

索引列表通常应使用 HTML "定义列表" (<dl> 与 <dt> 标签) 构建. 定义列表没有项目符号或序号规范, 布局比无序列表 (<ul> 与 <li> 标签) 或有序列表 (<ol> 与 <li> 标签) 更整洁. 如果你选择使用公共的 Boost 样式表, 就应当向 <dl> 标签添加一个 class="index" 属性/值对.

提供了索引页模板供使用.

概述

概述页用于向读者介绍该库. 它应当对库的用途给出高层概述, 并向读者介绍他们可能不熟悉的任何概念. 这里也可以放置一些"轻量"的设计理由, 不过更完整的设计理由阐述最好放在 设计理由页中.

与大多数内容页一样, 概述页应包含一个 页面索引.

提供了概述页模板供使用.

定义

定义页用于提供用户可能不熟悉的术语的定义列表.

定义列表通常应使用 HTML "定义列表" (<dl> 与 <DT> 标签) 构建. 定义列表没有项目符号或序号规范, 布局比无序列表 (<UL> 与 <li> 标签) 或有序列表 (<ol> 与 <li> 标签) 更整洁. 如果你选择使用公共的 Boost 样式表, 就应当向 <dl> 标签添加一个 class="definition" 属性/值对.

由于本页内容应只包含定义列表, 因此不应包含 页面索引.

提供了定义页模板供使用.

设计理由

设计理由页用于详细阐述库设计背后的设计理由. 这些信息帮助用户理解库为何如此设计, 并可能减少一些常见问题的出现频率. 关于设计理由为何重要的更好说明, 请参阅一般提交指南中的 设计理由的设计理由.

与大多数内容页一样, 设计理由页应包含一个 页面索引.

提供了设计理由页模板供使用.

配置信息

配置信息页用于记载库使用的配置宏. 这类宏属于以下三组之一: 库实现者使用、定义在 <boost/config.hpp> 中的宏, 库用户用于检测平台配置信息的宏, 以及库用户为配置库行为而定义的宏.

与大多数内容页一样, 概述页应包含一个 页面索引.

提供了配置页模板供使用.

常见问题 (FAQ)

随着库逐渐成熟, 用户会提出关于库用法的各种问题. 用户往往会反复问同样的问题. 与其每次被问到时都要作答, 不如使用常见问题页 (通常称为 FAQ) 把问题和答案记录下来. 这部分文档不仅对用户而且对维护者都非常有价值, 因此应当从一开始就提供 FAQ 页. 如果没有明显会成为 FAQ 的问题, 初始页面可以只说明目前尚无 FAQ. 这个空占位符有助于向用户表明, 你计划在出现 FAQ 时予以解答.

FAQ 页的 页面索引应包含文档中所有问题的列表. 实际的问题条目应把问题放在标题标签中, 答案用标准段落格式, 从而呈现为易于阅读的整洁版式.

提供了常见问题页模板供使用.

参考文献

参考文献页用于记载文档中引用外部资源时相关的书目信息. 文档中使用括注引用, 链接到参考文献页中的条目. 书目条目提供外部资源的详细信息, 如果资源可在线获取, 还可包含指向该资源的超链接. 书目撰写有若干正式格式. 你可以使用任何想要的格式, 但可以考虑使用的较好格式之一可参见 此处.

由于参考文献页应只包含书目信息, 因此不需要 页面索引.

提供了参考文献页模板供使用.

致谢

致谢页用于对应当致谢的人致以谢意. 当有人对设计或实现提出意见, 或者你使用了他人工作时, 都应当致谢. 这是一种你也希望别人对你保持的礼节, 因此应当努力在自己的文档中感谢其他每个人的付出.

由于致谢页应只包含致谢列表, 因此不需要 页面索引.

提供了致谢页模板供使用.

头文件参考

头文件参考页是文档中最重要的页面. 它们记载所有库头文件, 包括其中定义的所有宏、值、类型、类、函数和对象. 为这些页面编写内容时, 遵循 文档结构中的指南通常会很有用.

与大多数内容页一样, 头文件参考页应包含一个 页面索引.

提供了头文件参考页模板供使用.

版式

有一些页面版式概念会在你的许多页面中频繁使用. 本节概述一些一般指南, 供你在为文档设计这些版式概念时遵循.

页面横幅

页面横幅位于页面最顶端, 提供关于页面内容的快速信息. 其中包括 Boost 标志 (向读者表明本页面是 Boost 网站的一部分)、文档标题 (通常是库名) 和页面标题. 在索引页上, Boost 标志应超链接到 Boost 主页; 在所有其他页面上则应链接到索引页. 这使用户能够轻松地在 Boost 网站和文档中导航. HTML 页面的 <title> 标签应由文档标题和页面标题组成, 中间用连字符分隔.

页面横幅应使用 <hr> 标签与页面其余部分分隔. 这有助于把实际内容与标题信息清楚分开, 产生更整洁的文本.

页面索引

页面索引用于快速导航到页面上文档的各个小节, 如果存在, 应位于页面横幅正下方.

索引列表通常应使用 HTML "定义列表" (<dl> 与 <DT> 标签) 构建. 定义列表没有项目符号或序号规范, 布局比无序列表 (<UL> 与 <li> 标签) 或有序列表 (<ol> 与 <li> 标签) 更整洁. 如果你选择使用 Boost 样式表, 就应当向 <dl> 标签添加一个 class="page-index" 属性/值对.

大多数页面都应包含页面索引.

文档内容

页面的实际文档内容将根据单个页面的具体需求进行排版, 如有页面索引则紧随其后放置, 否则紧随页面横幅放置. 文档内容通常表现为各节标题之下的段落文本.

脚注

脚注可用在页面的文档中. 在文档内容中, 脚注引用应采用带括号的脚注编号形式 (括号使读者更容易点击超链接), 超链接指向页面文档内容底部的实际脚注. 你可以用 <sup> 标签来格式化这些脚注编号, 或者 (更好) 使用 CSS 样式类, 以便把编号区分为脚注而不是正文的一部分. 如果你选择使用公共的 Boost 样式表, 其中已为此定义了一个 footnote 类.

修订信息

每页底部都应有修订信息, 标明该页面的最后修订时间. 此信息应通过 <hr> 标签与上方页面其余部分分隔. 以下 HTML 代码片段可用于跟踪修订信息 (此代码使用 Boost 网站上的一些服务器组件自动跟踪修订日期, 无需手工编辑日期文本):

<hr>
<p>Revised
  <!--webbot bot="Timestamp" S-Type="EDITED" S-Format="%d %B, %Y" startspan -->
  01 January, 2001
  <!--webbot bot="Timestamp" endspan i-checksum="39359" -->
</p>

版权信息

页面最底部应包含适用于该文档的所有版权信息.

格式

本节提供使用 HTML 排版文档的一般指南. 对各种"常见页面"的说明给出了文档特定小节的排版细节, 这些细节应优先于本指南.

代码

文档中的代码应放在 <code></code> 或 <pre></pre> 标签内. 与其他文本内联的代码使用 <code></code> 标签, 而 <pre></pre> 标签用于代码"块". 如果使用层叠样式表指定这些标签的格式, 应使用固定宽度的无衬线字体. 这可以确保代码易于与正文区分. 为 <pre></pre> 标签设置文本缩进样式也可能有益, 有助于把代码块与其他结构性 HTML 块分开. Boost 样式表为这些标签指定了格式.

注释: "代码"包括变量名、函数名等.

列表

在 HTML 中, 列表应构建为无序 (<UL> 与 <li> 标签)、有序 (<ol> 与 <li> 标签) 或定义 (<dl> 与 <DT> 标签) 列表. 当需要一组没有任何逻辑顺序的条目时, 使用无序列表, 例如库定义的、可用作模板实参的数据类型列表. 当条目集合必须按逻辑顺序组织时, 使用有序列表, 例如枚举某个操作按逻辑执行的步骤. 当列表不仅包含没有逻辑顺序的条目, 还包含这些条目的定义/描述等时, 使用定义列表. 一个很好的例子是 文档结构中描述的函数规范.

图形

应尽量少用图形, 最好完全不用. 图像会大大影响许多人的下载时间, 可能让用户不愿阅读文档. 如果需要用图像帮助说明文档中的内容, 可考虑在文档中只提供指向图像的链接, 而不是把图像直接嵌入文本. 如果确实要在文档正文中包含图像, 应在 <img> 标签中指定图像的尺寸, 以便用户的浏览器在图像加载之前优化文本排版.

不换行空格

HTML 文本中应避免使用不换行空格 (&nbsp;). 通常有更合适的文档排版方式, 例如使用列表结构, 或通过样式属性或在层叠样式表中指定缩进.

层叠样式表

层叠样式表让你可以对 HTML 文档应用一些高级格式样式. 更重要的是, 它们让你只需在一个文件中更改格式, 即可影响所有使用该样式表的页面. 与其在 HTML 中费力生成特定格式, 不如在样式表中指定格式, 通常这样更容易也更灵活.

Boost 样式表

使用层叠样式表来排版 HTML 是个好主意, 将其应用于整个 Boost 网站会大有好处. 当然我们不能强制要求 (如果 Boost 对提交提出这类琐细要求, 可能会让许多程序员不愿参与贡献). 不过, 还是提供了一个"标准" Boost 样式表 (http://www.boost.org/boost.css), 便于贡献者快速轻松地生成清晰一致、体现 Boost "品牌"的文档 (如果他们愿意). 如果日后决定更新 Boost "品牌", 只需修改这一个文件, 所有使用该样式表的文档都会自动更新.

Boost 提供的样式表不仅为许多标准标签指定了样式, 还指定了若干样式"类". 类是针对特定标签指定的, 而不是应用于某类标签的所有实例. 下面列出 Boost 样式表中指定的类及其使用时机:

index 编写索引列表时用于 <dl> 标签.
page-index 编写页面索引列表时用于 <dl> 标签.
Footnote 编写脚注编号时使用.
function-semantics 编写函数语义列表时用于 <dl> 标签.
