1 获取 Boost

获取 Boost 副本最可靠的方式是下载 boost_1_82_0.7z 或 boost_1_82_0.zip 并解压, 即可安装完整的 Boost 发行版.1

2 Boost 发行版

以下是最终目录结构的概貌:

boost_1_82_0\ .................The “boost root directory”
   index.htm .........A copy of www.boost.org starts here
   boost\ .........................All Boost Header files
   lib\ .....................precompiled library binaries
   libs\ ............Tests, .cpps, docs, etc., by library
     index.html ........Library documentation starts here
     algorithm\
     any\
     array\
                     …more libraries…
   status\ .........................Boost-wide test suite
   tools\ ...........Utilities, e.g. Boost.Build, quickbook, bcp
   more\ ..........................Policy documents, etc.
   doc\ ...............A subset of all Boost library docs

头文件的组织

Boost 库头文件的组织并不完全统一, 但大多数库遵循以下几种模式:

  • 一些较老的库和大多数非常小的库把所有公共头文件直接放在 boost\ 下.

  • 大多数库的公共头文件位于 boost\ 下以库命名的子目录中. 例如, Python 库的 def.hpp 头文件位于

    boost\python\def.hpp.

  • 一些库在 boost\ 中有一个“聚合头文件”, 它将 #include 该库的其他所有头文件. 例如, Boost.Python 的聚合头文件是

    boost\python.hpp.

  • 大多数库把私有头文件放在名为 detail\ 或 aux_\ 的子目录中. 不要指望在这些目录里找到任何你能使用的东西.

有几点需要特别注意:

  1. 通往 boost 根目录的路径 (通常是 C:\Program Files\boost\boost_1_82_0) 在文档和邮件列表中有时被称为 $BOOST_ROOT.

  2. 要编译 Boost 中的任何内容, 你需要有一个目录, 其中包含 boost\ 子目录, 并把它置于你的 #include 路径中. 在 Microsoft Visual Studio 中设置 #include 路径的具体步骤见本文档后面的内容; 如果你使用其他 IDE, 请查阅你的产品文档以获取说明.

  3. 由于 Boost 的所有头文件都以 .hpp 为扩展名, 且位于 boost 根目录的 boost\ 子目录下, 你的 Boost #include 指令将形如:

    #include <boost/whatever.hpp>

    或者

    #include "boost/whatever.hpp"

    具体取决于你对使用尖括号形式包含的偏好. 即使是 Windows 用户也可以 (而且出于可移植性的考虑, 或许也应该) 在 #include 指令中使用正斜杠; 你的编译器并不在意.

  4. 不要被 doc\ 子目录分散注意力; 它只包含 Boost 文档的一个子集. 如果你想要全部内容, 请从 libs\index.html 开始.

3 仅头文件库

许多人首先想知道的是: “我该如何构建 Boost?” 好消息是, 通常根本没什么需要构建的.

无需构建?

大多数 Boost 库都是 仅头文件 库: 它们完全由头文件构成, 其中包含模板和内联函数, 无需单独编译的库二进制文件, 链接时也无需特殊处理.

Boost 库中唯一必须单独构建的库是:

  • Boost.Chrono
  • Boost.Context
  • Boost.Filesystem
  • Boost.GraphParallel
  • Boost.IOStreams
  • Boost.Locale
  • Boost.Log (参见 构建文档)
  • Boost.MPI
  • Boost.ProgramOptions
  • Boost.Python (在构建和安装之前, 请参见 Boost.Python 构建文档)
  • Boost.Regex
  • Boost.Serialization
  • Boost.Thread
  • Boost.Timer
  • Boost.Wave

少数库有可选的单独编译二进制文件:

  • Boost.Graph 也有一个二进制组件, 仅当你打算 解析 GraphViz 文件 时才需要它.
  • Boost.Math 为 TR1 和 C99 的 cmath 函数提供了二进制组件.
  • Boost.Random 有一个二进制组件, 仅在使用 random_device 时才需要.
  • Boost.Test 可以“仅头文件”或“单独编译”模式使用, 不过严肃使用时建议单独编译.
  • Boost.Exception 为 32 位且 _MSC_VER==1310 和 _MSC_VER==1400 的情形提供了 exception_ptr 的非侵入式实现, 这需要单独编译的二进制文件. 通过 #define BOOST_ENABLE_NON_INTRUSIVE_EXCEPTION_PTR 启用.
  • Boost.System 自 Boost 1.69 起为仅头文件库. 出于兼容性考虑仍会构建一个存根库, 但已不再需要链接它.

4 使用 Boost 构建一个简单程序

为简单起见, 我们先从一个仅头文件库开始. 下面的程序从标准输入读取一组整数, 用 Boost.Lambda 把每个数乘以三, 再写到标准输出:

#include <boost/lambda/lambda.hpp>
#include <iostream>
#include <iterator>
#include <algorithm>

int main()
{
    using namespace boost::lambda;
    typedef std::istream_iterator<int> in;

    std::for_each(
        in(std::cin), in(), std::cout << (_1 * 3) << " " );
}

把这个程序的文本复制到一个名为 example.cpp 的文件中.

注释

要构建本指南中的示例, 你可以使用 Visual Studio 这样的集成开发环境 (IDE), 也可以从 命令提示符发出命令. 由于每个 IDE 和编译器的选项各不相同, 而 Microsoft 的编译器是 Windows 上占主导地位的编译器, 我们在此只给出 Visual Studio 2005 和 .NET 2003 IDE 及其对应命令提示符编译器的具体指引 (使用命令提示符要稍简单一些). 如果你使用的是其他编译器或 IDE, 把这些说明适配到你的环境应当相对容易.

然后按回车. 例如,

cd C:\Program Files\boost\boost_1_82_0

长命令可以通过在除最后一行外的每行末尾输入一个插入符 (^) 跨多行续写. 本页中的一些示例使用了这一技巧以节省水平空间.

5 准备使用 Boost 库二进制文件

如果你想使用任何需要单独编译的 Boost 库, 就需要获取库二进制文件.

5.1 从源码简化构建

如果你想使用 Visual C++ 从源码构建, 可以使用本节描述的简单构建步骤. 打开命令提示符, 把当前目录切换到 Boost 根目录, 然后输入以下命令:

bootstrap
.\b2

第一条命令会准备好 Boost.Build 系统以供使用. 第二条命令调用 Boost.Build 来构建需要单独编译的 Boost 库. 有关允许的选项列表, 请查阅 Boost.Build 文档.

5.2 或者, 从源码构建二进制文件

如果你使用的是早期版本的 Visual C++ 或其他厂商的编译器, 就需要使用 Boost.Build 来创建自己的二进制文件.

5.2.1 安装 Boost.Build

Boost.Build 是一个基于文本的软件开发、测试和安装系统. 首先, 你需要构建并安装它. 具体步骤如下:

  1. 进入 tools\build\ 目录.
  2. 运行 bootstrap.bat
  3. 运行 b2 install --prefix=PREFIX, 其中 PREFIX 是你希望安装 Boost.Build 的目录
  4. 把 PREFIX\bin 加入你的 PATH 环境变量.

5.2.2 确定你的工具集

首先, 在下表中找到与你的编译器对应的工具集 (最新列表始终可在 Boost.Build 文档中查看).

注释

如果你之前为 构建 b2 选择过工具集, 应当假定它不适用, 并改为从下表中重新选择.

5.2.3 选择构建目录

Boost.Build 会把构建时生成的所有中间文件放入 构建目录. 如果你的 Boost 根目录可写, 这一步并非严格必要: 默认情况下 Boost.Build 会在你当前的工作目录中为此创建一个 bin.v2/ 子目录.

5.2.4 调用 b2

把当前目录切换到 Boost 根目录, 然后按如下方式调用 b2:

b2 --build-dir=build-directory toolset=toolset-name --build-type=complete stage

有关这些及其他调用选项的完整说明, 请参见 Boost.Build 文档.

例如, 你的会话可能如下所示:3

C:\WINDOWS> cd C:\Program Files\boost\boost_1_82_0
C:\Program Files\boost\boost_1_82_0> b2 ^
More? --build-dir="C:\Documents and Settings\dave\build-boost" ^
More? --build-type=complete msvc stage

务必阅读这条说明, 了解该行中 ^、More? 以及引号 (") 出现的原因.

选项 “--build-type=complete” 会让 Boost.Build 构建库的所有受支持变体. 有关如何只构建特定变体的说明, 请在 Boost 用户邮件列表上询问.

构建特殊的 stage 构建目标会把 Boost 库二进制文件放入 Boost 树的 stage\lib\ 子目录中. 要使用其他目录, 请把 --stagedir=directory 选项传给 b2.

注释

b2 区分大小写; 上面以 粗体 显示的所有部分必须完全小写.

有关调用 b2 时可传入的其他选项的说明, 请输入:

b2 --help

特别是, 为了减少构建耗时, 你可能对以下内容感兴趣:

  • 查看库名列表, 使用 --show-libraries
  • 用 --with-库名 或 --without-库名 选项限制要构建哪些库
  • 通过在命令行中添加 release 或 debug 来选择特定的构建变体.

注释

Boost.Build 会产生大量输出, 这容易让你错过问题. 如果想确保一切顺利, 可以在命令行末尾附加 “>build.log 2>&1”, 把输出重定向到文件.

5.3 预期的构建输出

在构建 Boost 库的过程中, 你会看到一些打印到控制台的消息. 其中可能包括

  • 关于 Boost 库配置的提示——例如, Regex 库在不带 Unicode 支持构建时会输出一条关于 ICU 的消息; 如果没有安装 Python, Python 库可能被跳过 (不报错, 但会给出提示).

  • 来自构建工具的消息, 报告已构建或已跳过的构建目标数量. 如果这些数字对你来说毫无意义, 不必惊讶; 每个库都有很多构建目标.

  • 描述工具正在执行什么操作的构建动作消息, 形如:

    toolset-name.c++ long/path/to/file/being/built

  • 编译器警告.

5.4 出现构建错误时

构建 Boost 时看到的错误消息 (如果有的话) 应当只与 IOStreams 库对 zip 和 bzip2 格式的支持有关, 说明见 此处. 如果需要这些功能, 请安装 libz 和 libbz2 的相关开发包. 构建 Boost 库时出现的其他错误都值得警惕.

如果构建系统似乎找不到你的编译器和/或链接器, 考虑设置一个 user-config.jam 文件, 具体说明见 此处. 如果这不是你的问题所在, 或者 user-config.jam 文件对你无效, 请把有关为你的编译器配置 Boost 的问题提交到 Boost 用户邮件列表.

6 将程序链接到 Boost 库

为了演示与 Boost 二进制库的链接, 我们将使用下面这个从电子邮件中提取主题行的简单程序. 它使用 Boost.Regex 库, 该库有一个单独编译的二进制组件.

#include <boost/regex.hpp>
#include <iostream>
#include <string>

int main()
{
    std::string line;
    boost::regex pat( "^Subject: (Re: |Aw: )*(.*)" );

    while (std::cin)
    {
        std::getline(std::cin, line);
        boost::smatch matches;
        if (boost::regex_match(line, matches, pat))
            std::cout << matches[2] << std::endl;
    }
}

与链接相关的两个主要挑战是:

  1. 工具配置, 例如选择命令行选项或 IDE 构建设置.
  2. 在所有构建变体中, 找出其编译配置与项目其余部分兼容的那个库二进制文件.

自动链接

大多数 Windows 编译器和链接器都有所谓的“自动链接支持”, 它消除了第二个挑战. Boost 头文件中的特殊代码会检测你的编译器选项, 并利用该信息把正确库的名称编码进你的目标文件; 链接器则从你指定给它搜索的目录中选取具有该名称的库.

GCC 工具链 (Cygwin 和 MinGW) 是显著的例外; GCC 用户应参阅 Unix 变体操作系统的链接说明, 以获取应使用的命令行选项.

6.1 在 Visual Studio IDE 中链接

从我们先前创建的 仅头文件示例项目开始:

  1. 右键单击 example (位于 解决方案资源管理器窗格中), 然后从弹出的菜单中选择 属性
  2. 在 配置属性 > 链接器 > 附加库目录中, 输入 Boost 二进制文件的路径, 例如 C:\Program Files\boost\boost_1_82_0\lib\.
  3. 在 生成菜单中, 选择 生成解决方案.

6.3 库命名

注释

如果你的编译器像 Visual C++ 一样支持自动链接, 那么你或许可以 跳到下一步.

要为你的构建配置选择正确的二进制文件, 你需要了解 Boost 二进制文件的命名规则. 每个库文件名都由一组通用的元素序列组成, 用于描述它的构建方式. 例如, libboost_regex-vc71-mt-d-x86-1_34.lib 可以分解为以下元素:

lib
前缀: 除 Microsoft Windows 外, 每个 Boost 库名都以该字符串开头. 在 Windows 上, 只有普通静态库使用 lib 前缀; 导入库和 DLL 则不用.5
boost_regex
库名: 所有 boost 库文件名都以 boost_ 开头.
-vc71
工具集标记: 标识构建该二进制文件所用的 工具集 及其版本.
-mt
线程标记: 表示该库构建时启用了多线程支持. 未启用多线程支持构建的库可通过缺少 -mt 来识别.
-d

ABI 标记: 编码影响该库与其他已编译代码互操作性的细节. 对于每个这样的特性, 标记中会附加一个字母:

键 在以下情况使用此库: Boost.Build 选项
s 以静态方式链接 C++ 标准库与编译器运行时支持库. runtime-link=static
g 使用标准库和运行时支持库的调试版本. runtime-debugging=on
y 使用特制的 Python 调试版本. python-debugging=on
d 构建代码的调试版本.6 variant=debug
p 使用 STLPort 标准库, 而不是编译器自带的默认标准库. stdlib=stlport

例如, 如果你为配合静态运行库和 STLPort 标准库的调试版本而构建代码的调试版本, 标记将是: -sgdp. 如果以上情况都不适用, 则省略 ABI 标记.

-x86

架构与地址模型标记: 首字母按如下方式编码架构:

键 架构 Boost.Build 选项
x x86-32, x86-64 architecture=x86
a ARM architecture=arm
i IA-64 architecture=ia64
s Sparc architecture=sparc
m MIPS/SGI architecture=mips*
p RS/6000 & PowerPC architecture=power

字母后面的两位数字按如下方式编码地址模型:

键 地址模型 Boost.Build 选项
32 32 位 address-model=32
64 64 位 address-model=64
-1_34
版本标记: 完整的 Boost 发布版本号, 句点替换为下划线. 例如, 版本 1.31.1 的标记为 "-1_31_1".
.lib
扩展名: 按操作系统的通常约定确定. 在大多数 unix 风格的平台上, 静态库 (档案文件) 和共享库的扩展名分别为 .a 和 .so. 在 Windows 上, .dll 表示共享库, .lib 表示静态库或导入库. 在 unix 变体上若工具集支持, 还会附加完整的版本扩展名 (如 ".so.1.34"), 并创建一个指向库文件、名称不含尾部版本号的符号链接.
