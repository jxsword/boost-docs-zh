动机

表达式模板非常酷. 它们被用于许多库; 这里仅举三个最令人印象深刻的例子:

  • Boost.Spirit 允许你编写 EBNF 风格的文法, 并将其转换为 PEG 解析器.
  • Eigen 允许你使用非常自然且符合数学习惯的表达式语法进行线性代数运算, Eigen 利用这些表达式进行大量优化.
  • NT2 接受稍作修改的 MatLab 代码, 并将其解析为高度优化的 C++ 代码运行.

然而, 这可能代价高昂. 表达式模板的实现与维护成本很高. Eigen 与 Boost.Ublas 各自都拥有大量无法在别处复用的复杂表达式模板代码.

有了 C++14 与 C++17 标准提供的语言设施, 表达式模板库现在编写和使用都很直接, 编译时间也十分合理.

举个简单的例子, 假设我们正在做一些矩阵运算, 并写下这条语句:

D = A * B + C;

其中所有变量都是矩阵. 事实证明, 先为 A * B 创建临时对象, 再为乘积加 C 的结果创建另一个临时对象, 效率非常低下. 大多数矩阵运算库都会提供一次性完成的单个函数:

mul_add_assign(D, A, B, C);

如果你使用的矩阵库同时提供两种语法, 你必须留意何时应把使用运算符的代码替换为更高效的函数; 这既繁琐又容易出错. 如果库根本不提供运算符语法, 只提供更高效的函数调用, 那么使用该库的代码的可写性与可读性都会大打折扣.

使用 Boost.YAP, 你可以编写一些库代码, 使 D = A * B + C 这样的表达式自动转换为 mul_add_assign(D, A, B, C) 这样的表达式.

再看另一个例子. 我们中许多人用过 Unix 命令行工具来去除文件中的重复行:

sort file_with_duplicates | uniq > file_without_duplicates

当然, 我们可以用标准算法做非常类似的事情:

std::vector<int> v1 = {0, 2, 2, 7, 1, 3, 8};
std::sort(v1.begin(), v1.end());
auto it = std::unique(v1.begin(), v1.end());
std::vector<int> const v2(v1.begin(), it);
assert(v2 == std::vector<int>({0, 1, 2, 3, 7, 8}));

然而, 如果我们的代码能做到这一点, 但语法更简洁, 那就好得多:

std::vector<int> v1 = {0, 2, 2, 7, 1, 3, 8};
std::vector<int> const v2 = sort(v1) | unique;
assert(v2 == std::vector<int>({0, 1, 2, 3, 7, 8}));

这看起来与上面的 Unix 命令行相似得多. (让我们假装 Range-v3 还没有几乎完全做到这一点. )

Boost.YAP 可以用相当少的代码同时完成这两件事. 事实上, 如果你想看第二个例子如何实现, 可以直接跳到 可管道化算法 示例.

特性

  • 简单的 ExpressionTemplate 与 Expression 概念 (concept), 用户代码很容易建模. ExpressionTemplates 与 Expressions 上的成员与非成员函数可以用紧凑的宏添加, 并且存在一个建模 ExpressionTemplate 的参考模板用于原型设计或实验.
  • Boost.YAP 表达式的求值尽可能贴近内置 C++ 表达式的语义. 这使得表达式求值的语义更易于理解, 因为定义是相对于所涉类型的局部定义.
  • 表达式可以以用户自定义的方式显式变换. 这通过变换类中的重载调用运算符实现, 它们与整个表达式中的子表达式进行匹配. 虽然这些成员函数可以把子表达式变换为任何东西, 但常见的模式是只把某些子表达式变换为新的子表达式或适当的值, 而让其他子表达式保持不变. 这种 evaluate(transform(expr)) 惯用法预计将是使用 Yap 操纵与求值表达式最常见的方式之一.
  • 对表达式进行操作或创建表达式的函数. 本库提供 (并在 Boost.YAP 内部使用) 操纵表达式或其子表达式的函数. 例如, 这些函数简化了编写用户自定义变换的过程.
