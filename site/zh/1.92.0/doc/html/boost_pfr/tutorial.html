为什么元组不好而聚合类型更可取?

std::tuple 和 std::pair 适合泛型编程, 但它们有缺点. 首先, 使用它们的代码几乎难以阅读. 考虑两个定义:

元组

聚合类型

 
using auth_info_tuple = std::tuple<
    std::int64_t, // What does this integer represents?
    std::int64_t,
    std::time_t
>;

struct auth_info_aggregate {
    std::int64_t user_id;    // Oh, now I see!
    std::int64_t session_id;
    std::time_t  valid_till;
};

通过可聚合初始化的结构体来进行定义要清晰得多. 用法上也是如此: return std::get<1>(value); 对比 return value.session_id;.

聚合类型的另一个优点是更高效的拷贝、移动构造和赋值.

由于上述问题, 一些指南建议 使用聚合类型代替元组. 然而在函数式编程场景中聚合类型就无能为力了.

Boost.PFR 库 为可聚合初始化的结构体提供了类似元组的方法, 使聚合类型在以前只有元组才有用的场景中也能使用.

按索引访问结构体成员

以下示例展示如何使用 boost::pfr::get 按索引访问结构体字段.

让我们定义一个结构体:

#include <boost/pfr/core.hpp>

struct foo {            // defining structure
    int some_integer;
    char c;
};

我们可以按索引访问该结构体的字段:

foo f {777, '!'};
auto& r1 = boost::pfr::get<0>(f); // accessing field with index 0, returns reference to `foo::some_integer`
auto& r2 = boost::pfr::get<1>(f); // accessing field with index 1, returns reference to `foo::c`

自定义聚合类型的打印

以下示例展示如何编写自己的 io 操纵器用于打印:

#include <boost/pfr/ops.hpp>
#include <ostream>

namespace my_ns {

/// Usage:
///     struct foo {std::uint8_t a, b;};
///     ...
///     std::cout << my_ns::my_io(foo{42, 22});
///
/// Output: 42, 22
template <class T>
auto my_io(const T& value);

namespace detail {
    // Helpers to print individual values
    template <class T>
    void print_each(std::ostream& out, const T& v) { out << v; }
    void print_each(std::ostream& out, std::uint8_t v) { out << static_cast<unsigned>(v); }
    void print_each(std::ostream& out, std::int8_t v) { out << static_cast<int>(v); }

    // Structure to keep a reference to value, that will be ostreamed lower
    template <class T>
    struct io_reference {
        const T& value;
    };

    // Output each field of io_reference::value
    template <class T>
    std::ostream& operator<<(std::ostream& out, io_reference<T>&& x) {
        const char* sep = "";

        boost::pfr::for_each_field(x.value, [&](const auto& v) {
            out << std::exchange(sep, ", ");
            detail::print_each(out, v);
        });
        return out;
    }
}

// Definition:
template <class T>
auto my_io(const T& value) {
    return detail::io_reference<T>{value};
}

} // namespace my_ns

下面是更详细的描述:

1. eq, ne, gt, lt, le, ge, io 方式

如果你正在编写泛型算法, 并且仅当类型没有定义运算符时才需要使用来自 Boost.PFR 的运算符, 那么该方法很合适:

#include <boost/pfr/ops.hpp>

template <class T>
struct uniform_comparator_less {
    bool operator()(const T& lhs, const T& rhs) const noexcept {
        // If T has operator< or conversion operator then it is used.
        return boost::pfr::lt(lhs, rhs);
    }
};

该方法的效果仅限于函数内部. 它甚至对局部类型也有效, 例如在函数中定义的结构体.

2. BOOST_PFR_FUNCTIONS_FOR(T) 方式

如果你正在编写一个结构体并希望为该结构体定义运算符, 那么该方法很合适.

#include <boost/pfr/functions_for.hpp>

struct pair_like {
    int first;
    short second;
};

BOOST_PFR_FUNCTIONS_FOR(pair_like)   // Defines operators

// ...

assert(pair_like{1, 2} < pair_like{1, 3});

实参依赖查找工作良好. std::less 会为 struct pair_like 找到运算符. BOOST_PFR_FUNCTIONS_FOR(T) 不能用于局部类型. 它不会遵循 T 的转换运算符, 因此例如以下代码会输出不同的值:

#include <boost/pfr/functions_for.hpp>

struct empty {
    operator std::string() { return "empty{}"; }
};
// Uncomment to get different output:
// BOOST_PFR_FUNCTIONS_FOR(empty)

// ...
std::cout << empty{}; // Outputs `empty{}` if BOOST_PFR_FUNCTIONS_FOR(empty) is commented out, '{}' otherwise.

3. eq_fields, ne_fields, gt_fields, lt_fields, le_fields, ge_fields, io_fields 方式

如果你只想为你的类型提供部分运算符, 那么该方法很合适:

#include <boost/pfr/io_fields.hpp>

struct pair_like {
    int first;
    std::string second;
};

inline std::ostream& operator<<(std::ostream& os, const pair_like& x) {
    return os <<  bost::pfr::io_fields(x);
}

所有 *_fields 函数都会忽略用户定义的运算符, 只对类型的字段进行操作. 这使得它们非常适合用于定义你自己的运算符.

联合体的反射

如果类型包含联合体, 你可以使用类元组表示. 但请务必确保联合体的操作是手动定义的:

#include <boost/pfr/ops.hpp>

union test_union {
    int i;
    float f;
};

inline bool operator==(test_union l, test_union r) noexcept; // Compile time error without this operator

bool some_function(test_union f1, test_union f2) {
    return boost::pfr::eq(f1, f2); // OK
}

出于安全考虑, Boost.PFR 库禁用了联合体的反射. 遗憾的是, 没有办法找出联合体中 活跃 的成员, 而访问非活跃成员是一种未定义行为. 例如, 库可以总是返回第一个成员, 但将 u 以流方式输出到 union {char* c; long long ll; } u; u.ll= 1; 会因无效的指针解引用而使你的程序崩溃.

任何对联合体进行反射的尝试都会导致编译期错误. 在许多情况下会触发一个静态断言, 输出以下消息:

error: static_assert failed "====================> Boost.PFR: For safety reasons it is forbidden
        to reflect unions. See `Reflection of unions` section in the docs for more info."

字段名的反射

自 C++20 起, 可以使用 Boost.PFR 库按索引读取结构体字段的名称. 以下示例展示如何使用 boost::pfr::get_name 来做到这一点.

让我们定义一个结构体:

#include <boost/pfr/core_name.hpp>

struct foo {            // defining structure
    int some_integer;
    char c;
};

我们可以按索引访问该结构体的字段名:

constexpr std::string_view n1 = boost::pfr::get_name<0, foo>(); // returns "some_integer"
constexpr std::string_view n2 = boost::pfr::get_name<1, foo>(); // returns "c"
