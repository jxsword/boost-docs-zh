字段计数检测与获取成员引用

简要描述:

  1. 编译期: 使用聚合初始化来检测用户提供的结构体
    • BOOST_PFR_USE_CPP26_REFLECTION == 1:
      1. 编译期: 使用 C++26 反射来建立对字段的引用
    • BOOST_PFR_USE_CPP26_REFLECTION == 0 && BOOST_PFR_USE_CPP26 == 1:
      1. 编译期: 使用结构化绑定将类型 T 分解为已知可变数量的字段
    • BOOST_PFR_USE_CPP26_REFLECTION == 0 && BOOST_PFR_USE_CPP26 == 0 && BOOST_PFR_USE_CPP17 == 1:
      1. 编译期: 使用结构化绑定将类型 T 分解为已知数量的字段
    • BOOST_PFR_USE_CPP26_REFLECTION == 0 && BOOST_PFR_USE_CPP26 == 0 && BOOST_PFR_USE_CPP17 == 0 && BOOST_PFR_USE_LOOPHOLE == 1:
      1. 编译期: 使用聚合初始化来检测用户提供的结构体中的字段数量
      2. 编译期: 构造一个可转换为任何类型的结构体, 并记住它在用户提供的结构体聚合初始化期间被转换成的类型
      3. 编译期: 利用前几步得到的知识, 创建一个与用户提供的结构体具有完全相同布局的元组
      4. 编译期: 使用上一步得到的元组, 找出用户提供的结构体中每个字段的偏移量
      5. 运行期: 在已知结构体地址和每个字段偏移量的情况下, 获取指向每个字段的指针
      6. 运行期: 返回一个由字段引用组成的元组 => 结构体因此可以使用所有元组方法
    • BOOST_PFR_USE_CPP26 == 0 && BOOST_PFR_USE_CPP17 == 0 && BOOST_PFR_USE_LOOPHOLE == 0:
      1. 编译期: 设 I 为当前字段的索引, 它等于 0

      2. 运行期: 构造 T, 并使用一个可转换为任何类型的结构体的独立实例对字段 I 进行聚合初始化

        注释

        还需要额外注意确保编译器能够获得关于 T 的全部信息, 并确保对 T 的操作没有副作用, 这样编译器才能优化掉不必要的临时对象.

      3. 编译期: I += 1
      4. 编译期: 如果 I 不等于字段数量, 则从可转换为任何类型的结构体的转换运算符内部跳转到步骤 c.
      5. 编译期: 利用前几步得到的知识, 创建一个与用户提供的结构体具有完全相同布局的元组
      6. 编译期: 使用上一步得到的元组, 找出用户提供的结构体中每个字段的偏移量
      7. 运行期: 在已知结构体地址和每个字段偏移量的情况下, 获取指向每个字段的指针
    中的字段数量
  2. 运行期: 返回一个由字段引用组成的元组 => 结构体因此可以使用所有元组方法

一些基础内容的长篇描述: Antony Polukhin: Better C++14 reflections. 关于 C++14 在 BOOST_PFR_USE_LOOPHOLE == 0 下一些基础内容的长篇描述: Antony Polukhin: C++14 Reflections Without Macros, Markup nor External Tooling. 对 BOOST_PFR_USE_LOOPHOLE == 1 技术的描述, 由其发明者 Alexandr Poltavsky 撰写于 其博客.

字段名获取

如果 BOOST_PFR_USE_CPP26_REFLECTION == 1, 则使用 C++26 反射来获取名称. 否则:

  1. 编译期:
    • 获取类型为 T 的对象的成员引用, 使用 constexpr 函数
    • 把上一步得到的引用作为模板参数传给 constexpr 函数, 并附带 template <auto member_ptr>. 该函数返回 __PRETTY_FUNCTION__ 或其他厂商特定的宏, 这些宏会连同模板实参一起打印函数的完整名称.
    • 上一步返回的值包含成员名 (godbolt 示例). 对该值进行一些编译器特定的解析, 得到一个只包含成员名的 std::string_view.
  2. 运行期: 返回包含成员名的 std::string_view.
