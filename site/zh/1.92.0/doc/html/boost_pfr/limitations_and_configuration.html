限制与配置

注意

推荐使用 C++20 及以上标准. 对于不需要访问结构体成员名称的用户, C++17 已完全足够. 本库至少要求 C++14! 不支持 C++14 之前的编译器 (C++11、C++03...).

Boost.PFR 库可处理满足 SimpleAggregate 要求的类型: 不含基类、const 字段、引用或 C 数组的聚合类型:

struct simple_aggregate {  // SimpleAggregate
    std::string name;
    int age;
    boost::uuids::uuid uuid;
};

struct empty {             // SimpleAggregate
};

struct aggregate : empty { // not a SimpleAggregate
    std::string name;
    int age;
    boost::uuids::uuid uuid;
};

本库或许可以处理不满足 SimpleAggregate 要求的聚合类型, 但其行为往往是不可移植的.

Boost.PFR 的字段名提取仅适用于 SimpleAggregate 类型.

配置宏

默认情况下, Boost.PFR 会 自动检测你的编译器能力 并自动将配置宏定义为相应的值. 如果你希望覆盖该行为, 只需定义:

表 26.2. 宏

宏名

效果

BOOST_PFR_USE_CPP26_REFLECTION

如果你希望覆盖 Boost.PFR 的选择并使用 C++26 反射, 将其定义为 1. 如果你希望覆盖 Boost.PFR 的选择并禁用 C++26 反射, 将其定义为 0.

BOOST_PFR_USE_CPP26

如果你希望覆盖 Boost.PFR 的选择并在反射中使用 C++26 变参结构化绑定, 将其定义为 1. 如果你希望覆盖 Boost.PFR 的选择并禁用 C++26 变参结构化绑定, 将其定义为 0.

BOOST_PFR_USE_CPP17

如果你希望覆盖 Boost.PFR 的选择并在反射中使用 C++17 结构化绑定, 将其定义为 1. 如果你希望覆盖 Boost.PFR 的选择并禁用 C++17 结构化绑定, 将其定义为 0.

BOOST_PFR_USE_LOOPHOLE

将其定义为 1, 如果你希望覆盖 Boost.PFR 的选择并利用 CWG 2118 进行反射. 将其定义为 0, 如果你希望覆盖 Boost.PFR 的选择并禁用 CWG 2118.

BOOST_PFR_USE_STD_MAKE_INTEGRAL_SEQUENCE

将其定义为 0, 如果你因 std::make_integer_sequence 遇到模板实例化深度问题, 并希望使用 Boost.PFR 版本的该元函数. 将其定义为 1 可覆盖 Boost.PFR 的检测逻辑.

BOOST_PFR_HAS_GUARANTEED_COPY_ELISION

如果你的编译器没有正确实现 C++17 保证的拷贝消除, 并且无法反射含有不可移动字段的聚合类型, 将其定义为 0. 将其定义为 1 可覆盖 Boost.PFR 的检测逻辑.

BOOST_PFR_ENABLE_IMPLICIT_REFLECTION

如果你因隐式反射做出的许多低效选择而受到影响, 将其定义为 0. 将其定义为 1 可覆盖 Boost.PFR 的检测逻辑.

BOOST_PFR_CORE_NAME_ENABLED

在不支持字段名提取的平台上, 'boost/pfr/config.hpp' 头文件将 BOOST_PFR_CORE_NAME_ENABLED 宏定义为 0. 在包含该头文件之前将此宏定义为 0 会禁用获取字段名的能力.

BOOST_PFR_FUNCTION_SIGNATURE

对于已知的编译器, 该宏被定义为某个编译器特定的宏, 其输出包含非类型模板参数的完整函数签名.

BOOST_PFR_CORE_NAME_PARSING

描述如何从 BOOST_PFR_FUNCTION_SIGNATURE 宏中提取字段名. 详情见下文.

BOOST_PFR_ENABLED

在不支持 Boost.PFR 的平台上, boost/pfr/config.hpp 头文件将 BOOST_PFR_ENABLED 宏定义为 0. 在包含该头文件之前将此宏定义为 0 会禁用 Boost.PFR 库.

限制的详细说明

Boost.PFR 的反射存在一些取决于 C++ 标准和编译器能力的限制:

  • 静态变量会被忽略
  • T 必须是可聚合初始化的且无基类
  • 如果 T 包含 C 数组, 则反射的结果可能因 C++ 版本和库配置的不同而不同
  • 如果 BOOST_PFR_USE_CPP17 == 0, 还有以下限制:
    • 所有成员字段都不应拥有接受单个参数的模板构造函数.
    • 如果 BOOST_PFR_USE_LOOPHOLE == 0, 还有以下限制:
      • T 必须是可 constexpr 聚合初始化的, 且其所有字段必须可 constexpr 默认构造
      • boost::pfr::get、boost::pfr::structure_to_tuple、boost::pfr::structure_tie、boost::pfr::tuple_element 要求 T 是仅含内置类型的 POD 类型.

Boost.PFR 的字段名提取存在一些取决于 C++ 标准和编译器能力的限制:

  • T 应当可以像 extern T t; 一样使用, 即具有非内部链接.

调整 BOOST_PFR_CORE_NAME_PARSING

对于大多数流行编译器, BOOST_PFR_CORE_NAME_PARSING 已经设置妥当. 只有当库中的某个 static_assert 对 BOOST_PFR_CORE_NAME_PARSING 发出告警时, 你才需要调整它.

为此:

  1. 用你的编译器构建 test/core_name/print_name.cpp 并运行它
  2. 将 BOOST_PFR_CORE_NAME_PARSING 定义为 (skip_at_begin, skip_at_end, ""), 其中
    • skip_at_begin 等于输出中第一次出现 user_defined_field 之前的字符数
    • skip_at_end 等于输出中最后一次出现 user_defined_field 之后的字符数
  3. 检查 test/core_name/print_name.cpp 返回 "user_defined_field"
  4. 如果它未返回 user_defined_field, 则将 BOOST_PFR_CORE_NAME_PARSING 定义为 (skip_at_begin, skip_at_end, "T = "), 其中
    • skip_at_begin 在第 2 步中等于 skip_at_begin
    • skip_at_end 在第 2 步中等于 skip_at_end
    • "T = " 等于输出中紧邻 user_defined_field 之前的字符, 使用 backward("T = ") 从字符串右侧搜索该出现位置
  5. (可选, 但强烈推荐) 提交 工单 以请求将你的编译器加入受支持编译器列表. 请包含传给 BOOST_PFR_CORE_NAME_PARSING 宏的参数, 以及 test/core_name/print_name.cpp 的初始输出.
