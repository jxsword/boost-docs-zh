字体样式

['italic], [*bold], [_underline], [^teletype], [-strikethrough]

将生成:

斜体, 粗体, 下划线, teletype, 删除线

与所有非终结短语级元素一样, 这当然可以嵌套:

[*['bold-italic]]

将生成:

粗斜体

可替换文本

当你想要可能或必须由用户替换的内容时, 使用以下语法:

[~replacement]

这将生成:

replacement

引文

["A question that sometimes drives me hazy: am I or are the others crazy?]--Einstein

将生成:

“一个有时让我困惑的问题: 是我疯了, 还是别人疯了?”--爱因斯坦

注意正确的左右引号. 此外, 虽然你可以像 "quoted" 那样直接使用普通引号, 但我们上面的引文会生成正确的 DocBook 引文 (例如 <quote>quoted</quote>).

与所有短语元素一样, 引文可以嵌套. 示例:

["Here's the rule for bargains: ["Do other men, for they would do you.] That's
the true business precept.]

将生成:

“交易的规则是: ‘待人如待己.’ 这才是真正的经商信条.”

简单格式化

现在支持许多应用中常见的用于格式化文本的简单标记:

/italic/, *bold*, _underline_, =teletype=

将生成:

斜体, 粗体, 下划线, teletype

与 QuickBook 的标准格式化方案不同, 更简单的替代方案的规则要严格得多[32].

  • 简单标记不能嵌套. 你可以把简单标记与可嵌套标记组合使用.
  • 简单标记不能包含任何其他形式的 quickbook 标记.
  • 前导标记之后必须紧跟非空白字符
  • 尾随标记之前必须是非空白字符
  • 尾随标记之后必须是空格或标点
  • 如果在块内找不到匹配的标记, 则不会应用格式化. 这是为了确保未匹配的格式化标记 (这是常见错误) 不会破坏单个块之后的任何内容. 我们不希望仅仅因为忘记了一个尾随的 '*' 就让文档的其余部分渲染为粗体. 单个块由两个行尾或闭括号 ']' 终止.
  • 以星号开头的行将被解释为无序列表. 参见 无序列表.

如前所述, 简单标记不能跨越单个块. 以下段落中从 "have" 到 "full" 的文本将渲染为粗体:

Baa baa black sheep, *have you any wool?
Yes sir, yes sir, three bags full!*
One for the master, one for the dame,
And one for the little boy who lives down the lane.

Baa baa black sheep, have you any wool? Yes sir, yes sir, three bags full! One for the master, one for the dame, And one for the little boy who lives down the lane.

但在以下段落中, 未应用粗体:

Baa baa black sheep, *have you any wool?
Yes sir, yes sir, three bags full!
One for the master, one for the dame,
And one for the little boy who lives down the lane.

Baa baa black sheep, *你有羊毛吗? 有的先生, 有的先生, 整整三袋满! 一袋给主人, 一袋给夫人, 还有一袋给住在小巷里的小男孩.

角色 (Role)

这会生成一个带有 role 属性的 docbook 短语, 该属性可用于对短语分类. 这可用于为未在其他地方覆盖的用途标记文本. docbook role 会生成一个 html class, 可用于设置文本样式. 并且可以定制 xsl 样式表, 在生成 pdf 时对某些角色特殊处理.

boostbook 的 css 样式表和 xsl 样式表包含对可与 role 一起使用的有限颜色集的支持. 例如, 如果你写:

[role red Text content]

如果你使用 boostbook css (用于 html) 或用于生成 pdf 的 boostbook xsl, 你将得到红色文本.

可用颜色的完整列表为:

  • red
  • green
  • lime
  • blue
  • navy
  • yellow
  • magenta
  • indigo
  • cyan
  • purple
  • gold
  • silver
  • gray

行内代码

在编写 C++ 文档时, 在段落中内联代码相当常见. 我们为此提供了非常简单的标记. 例如, 这样:

This text has inlined code `int main() { return 0; }` in it.

将生成:

这段文字中有内联代码 int main() { return 0; } . 代码将进行语法高亮.

注释

我们只需用反引号把代码括起来: "`", 而不是单引号: "'" . 另外注意 `some code` 优于 [^some code].

代码块

预格式化代码直接以空格或制表符开头 (参见 代码) . 然而, 这种简单语法不能用作列表 (参见 有序列表 和 无序列表)、表格 (参见 表格) 等中的短语元素. 行内代码 (见上文) 则可以. 问题是, 行内代码不允许用换行、空格和制表符进行格式化. 这些都会丢失.

我们提供了一种介于两者之间的短语级标记. 通过使用双反引号或三反引号 (而非单反引号), 我们告诉 QuickBook 使用预格式化代码块. 示例:

``
    #include <iostream>

    int main()
    {
        std::cout << "Hello, World!" << std::endl;
        return 0;
    }
``

或者:

```
    #include <iostream>

    int main()
    {
        std::cout << "Hello, World!" << std::endl;
        return 0;
    }
```

将生成:

#include <iostream>

int main()
{
    std::cout << "Hello, World!" << std::endl;
    return 0;
}

源模式

如果文档包含多种类型的源代码, 则可以在处理文档时动态更改源模式. 所有 QuickBook 文档默认初始处于 C++ 模式, 不过可以在 文档 小节中设置替代的初始值.

要更改源模式, 使用 [source-mode] 标记, 其中 source-mode 是受支持的模式之一. 例如, 这样:

Python's [python] `import` is rather like C++'s [c++] `#include`. A
C++ comment `// looks like this` whereas a Python comment [python]
`# looks like this`.

将生成:

Python 的 import 类似于 C++ 的 #include . C++ 注释 // looks like this 而 Python 注释 #looks like this.

Quickbook 1.7 引入了 ! 元素, 可用于设置后续元素的源模式:

[teletype]
Example in C++: [!c++] `int main() {}`,
example with no highlighting: `int main() {}`.

将生成:

C++ 示例: int main() {}, 无高亮示例: int main() {}

要更改整个段落的源模式, 把 ! 元素放在段落之前的单独一行上:

[!c++]
`int main() {}` is highlighted as C++, as is `//example`.

[!c++] `int main() {}` is also highlighted as C++,
but `//example` isn't.

生成:

int main() {} 被高亮为 C++, //example 也是.

int main() {} 也被高亮为 C++, 但 //example 则不是.

! 元素还可用于为块和小节设置源模式. 例如:

[!python]
[section:python Section in which all code samples use python]

[/...]

[endsect:python]

[!c++]
[section:cpp Section in which all code samples use C++]

[/...]

[endsect:cpp]

或者为表格设置源模式:

[!teletype]
[table
    [[code][meaning]]
    [[`+`][addition]]
]

锚点

[#named_anchor]

命名锚点是一个钩子, 可被文档中其他位置的链接引用. 然后你可以用 [link named_anchor Some link text] 引用一个锚点. 参见 锚点链接、小节 和 标题.

这些锚点是全局的, 可以从 quickbook 文档的任何位置访问. 注意避免与其他小节中的锚点冲突.

链接

[@http://www.boost.org this is [*boost's] website....]

将生成:

这是 boost 的 网站....

链接文本就是链接本身的 URL 链接很常见. 示例:

see http://spirit.sourceforge.net/

因此, 当链接标记中没有文本时, 就假定使用 URL. 示例:

see [@http://spirit.sourceforge.net/]

将生成:

参见 http://spirit.sourceforge.net/

Boostbook 还支持一个自定义 url 方案, 用于链接到 boost 发行版内的文件:

[@boost:/libs/spirit/index.html the Boost.Spirit documentation]

将生成: Boost.Spirit 文档

注意, 这只有在使用 BoostBook 时才可用, 且仅用于链接 - 不能用于图像.

锚点链接

你可以在文档内使用如下方式链接:

[link document_id.section_id.normalized_header_text The link text]

更多信息参见 小节 和 标题 各节.

refentry 链接

此外, 你可以按如下方式在内部链接到 XML refentry:

[link xml.refentry The link text]

这会被转换为 <link linkend="xml.refentry">The link text</link>.

与 URL 一样, 链接文本是可选的. 如果不提供, 链接文本将自动为 refentry. 示例:

[link xml.refentry]

这会被转换为 <link linkend="xml.refentry">xml.refentry</link>.

代码链接

如果你想链接到参考小节中的函数、类、成员、枚举、概念、全局或头文件, 可以使用:

[funcref fully::qualified::function_name The link text]
[classref fully::qualified::class_name The link text]
[memberref fully::qualified::member_name The link text]
[enumref fully::qualified::enum_name The link text]
[macroref MACRO_NAME The link text]
[conceptref ConceptName The link text]
[headerref path/to/header.hpp The link text]
[globalref fully::qualified::global The link text]

同样, 链接文本是可选的. 如果不提供, 链接文本将自动为函数、类、成员、枚举、宏、概念、全局或头文件的名称. 示例:

[classref boost::bar::baz]

将以 "boost::bar::baz" 作为链接文本.

转义

当我们不想做任何处理时, 使用转义标记.

'''
escape (no processing/formatting)
'''

转义允许我们把 XML 标记传递给 BoostBook 或 DocBook . 例如:

'''
<emphasis role="bold">This is direct XML markup</emphasis>
'''

这是直接的 XML 标记

重要

使用转义时要小心. 文本必须符合 BoostBook/DocBook 语法.

单字符转义

反斜杠可用于转义单个标点字符. 紧跟反斜杠之后的标点将不加处理地传递. 当需要转义 QuickBook 标点 (如 [ 和 ]) 时, 这很有用. 例如, 如何转义三重引号? 很简单: \'\'\'

\n 有特殊含义. 它用于生成换行.

警告

\n 现已弃用, 请改用 [br] . 不过请节制使用, 因为它可能生成无效的 docbook

被转义的空格 \ 也有特殊含义. 被转义的空格会从输出中移除.

unicode 转义

你可以输入任何 16 位 unicode 字符, 方法是使用 \u 后跟其 4 位十六进制码; 或输入 32 位字符, 使用 \U 后跟 8 位十六进制码. 例如.

\u03B1 + \u03B2

将生成:

α + β

图像

[$image.jpg]

从 1.5 版起, 你还可以使用 DocBook imagedata 属性:

[$image.jpg [width 200in] [height 200in]]

脚注

从 1.3 版起, QuickBook 支持脚注. 只需把脚注文本放入 [footnote] 块中, 文本就会放在当前页面的底部. 例如, 这样:

[footnote A sample footnote]

将生成这个[33].

宏展开

__a_macro_identifier__

详情参见 宏.

模板展开

[a_template_identifier]

详情参见 模板.

条件生成

类似 C++ 的 #ifdef, 你可以根据宏的存在生成短语. 示例:

[? __to_be__ To be or not to be]

这里, 只有当宏符号 __to_be__ 之前已被定义时, 才会生成短语 "To be or not to be". 由于我们尚未定义 __to_be__, 上面的短语不会做任何事情. 现在, 定义该符号:

[def __to_be__]

[? __to_be__ To be or not to be]

结果为:

To be or not to be

在 quickbook 1.7 中, 可以在宏未定义时生成输出:

[?! __to_be__ Not to be]
