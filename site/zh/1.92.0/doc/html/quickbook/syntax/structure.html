文档信息

文档信息属性
嵌套 quickbook 文档

每个文档都必须以文档信息 (Document Info) 小节开头, 它看起来大致如下:

[article The Document Title
    [quickbook 1.7]
    [version 1.0]
    [id the_document_name]
    [copyright 2000 2002 2003 Joe Blow, Jane Doe]
    [authors [Blow, Joe] [Doe, Jane]]
    [license The document's license]
    [source-mode c++]
]

article 是文档类型. 有多种可能的文档类型, 其中大多数基于 docbook 文档元素. 这些在 DocBook: The Definitive Guide 中有完整描述:

  • book
  • article
  • chapter
  • part
  • appendix
  • preface
  • qandadiv
  • qandaset
  • reference
  • set

Boostbook 还添加了另一种文档类型 library, 用于软件库的文档编写.

因此 'foo' 库的文档可能这样开头:

[library Foo
    [quickbook 1.7]
    [id foo]
    [version 1.0]
]

文档信息属性

文档信息块有几种不同类型的属性. 它们都是可选的.

QuickBook 特有的元数据 
[quickbook 1.7]

quickbook 属性声明文档所针对的 quickbook 版本. 若缺失, 则假定版本 1.1. 建议使用 [quickbook 1.7], 即本文描述的版本.

注释

quickbook 版本也会对生成的标记做一些更改. 最显著的是, 为标题和小节自动生成的 id 在后续版本中有所不同. 为了尽量减少干扰, 你可以使用 compatibility-mode 属性来生成与旧版本类似的标记:

[article Article that was original
         written in quickbook 1.3
[quickbook 1.7]
[compatibility-mode 1.3]
]

此特性不应用于新文档, 只用于把旧文档移植到新版本.

quickbook 和 compatibility-mode 标签都可以用在文件开头 (文档信息块之前), 也可用于没有文档信息块的文件.

[source-mode teletype]

source-mode 属性设置初始 源模式 . 若省略, 将使用默认值 c++

Boostbook/Docbook 根元素属性 
[id foo]

id 指定文档元素的 id. 若未指定, id 将根据标题自动生成. 此 id 还用于生成嵌套的 id.

[lang en]

lang 指定文档语言. docbook 用它来本地化文档. 注意 Boostbook 没有任何本地化支持, 因此如果你用它生成参考文档, 无论怎样都会是英文.

它应该是取自 ISO 639 的语言代码 (也许还可以加上取自 ISO 3166 的国家代码, 如 en-US).

[dirname foo]

dirname 用于指定库在仓库中的目录名. 这是一个 boostbook 扩展, 因此只对 library 文档块有效. 它用于一些 boostbook 功能, 但对纯 quickbook 文档没有实际影响.

Docbook 元数据

version, copyright, authors, license, last-revision 和 bibliod 是可选信息.

Boostbook 元数据

purpose 和 category 是 boostbook 属性, 仅对 library 文档有效. 如果对其他文档类型使用它们, quickbook 会发出警告, 但仍会使用它们, 生成无效标记, 而样式表只会忽略这些标记.

转义的 Docbook

从 quickbook 1.7 起, 转义的 boostbook 或 docbook 可以包含在 docinfo 块中:

[article Some article
[quickbook 1.7]
'''<author>
    <firstname>John</firstname>
    <surname>Doe</surname>
    <email>john.doe@example.com</email>
</author>'''
]

转义的 docbook 总是放在 docinfo 块的末尾, 因此不应假定它会与 quickbook 生成的标记交错. 对同一信息混用 quickbook 和 docbook 属性效果不佳.

嵌套 quickbook 文档

Docinfo 块只能出现在 quickbook 文件的开头, 因此要创建更复杂的文档, 你需要使用多个 quickbook 文件, 并使用 include 标签 来嵌套它们. 例如, 假设你想创建一本带有引言和一章的书, 首先为这本书创建一个文件:

[book Simple example
[quickbook 1.7]
]

[include introduction.qbk]
[include chapter.qbk]
注释

像这样组织文档结构是 quickbook 1.6 引入的, 因此需要 [quickbook 1.6] 或更高版本的 docinfo 字段.

引言对应的文档类型是 preface, 因此 introduction.qbk 的内容应类似于:

[preface Introduction
[quickbook 1.7]
]

Write the introduction to the book here....

而 chapter.qbk:

[chapter A chapter
[quickbook 1.7]
]

Chapter contents....

小节

Quickbook 文档使用 '小节' 来组织结构. 它们用于生成目录, 并且在生成 html 时把文档拆分为多页. 这是可选的, 但除了最简单的文档外都是个好主意.

分节的文档可能如下:

[book Title
    [quickbook 1.5]
]

[section First Section]

[/...]

[endsect]

[section Second Section]

[/...]

[endsect]

小节以 section 标签开始, 以 [endsect] 标签结束. ([/...] 是注释, 后文所述)

小节可以指定可选 id:

[#quickbook.ref.id]
[section:id The Section Title]

id 将是所生成小节的文件名. 若未提供, "The Section Title" 将被规范化并成为 id. 有效字符为 a-Z, A-Z, 0-9 和 _ . 所有无效字符都转换为下划线, 所有大写转换为小写. 因此: "The Section Title" 将规范化为 "the_section_title".

小节的结束也可以有可选 id, 它只用于检查是否与小节的开头匹配.

[section:matching Section with an id]

[/...]

[endsect:matching]

它不会匹配生成的 id, 只匹配显式指定的 id, 因此下面会报错, 即使 quickbook 为该小节生成了 id generated:

[section Generated]

[/...]

[endsect:generated]

小节可以嵌套, 这会在目录中形成层次结构.
