xinclude

你可以用以下方式包含另一个 XML 文件:

[xinclude file.xml]

当 file.xml 由 Doxygen 生成且包含你的参考小节时, 这很有用.

xinclude 路径通常在生成的文档中原样使用, 如果你希望它们相对于当前 quickbook 文件, 这样就行不通了. Quickbook 可以向 boostbook 文档添加一个 xml:base 属性, 以指定应在哪里查找 xinclude 文件. 例如, 如果你希望它们相对于当前 quickbook 文件:

[article Article with xincludes
[quickbook 1.7]
[xmlbase .]
]

[xinclude file.xml]

现在, 若 file.xml 与 quickbook 文件在同一目录, xinclude 应该就能工作. 不过如果你分发生成的文件, 它可能无法工作 (因为它们的相对目录可能改变).

假设文章通过运行类似以下的命令生成在子目录中:

quickbook article.qbk --output-file=output/article.xml

这将生成一个 boostbook 根标签:

<article id="article_with_xincludes"
    last-revision="$Date: 2013/08/20 08:26:48 $"
    xml:base=".."
    xmlns:xi="http://www.w3.org/2001/XInclude">

因为 xml:base 被设为 .., xml 处理器会知道到父目录中查找 file.xml, 它在遇到 xi:include 标签时用到.

显式列表标签

有时 wiki 风格的列表标记可能难以使用, 尤其是当你希望在列表中加入更复杂的标记时. 因此 quickbook 1.6 引入了另一种标记列表的方式:

[ordered_list [item1][item2]]

等价于:

# item1
# item2

以及:

[itemized_list [item1][item2]]

等价于:

代码

预格式化代码以空格或制表符开头. 代码将根据当前 源模式 进行语法高亮:

#include <iostream>

int main()
{
    // Sample code
    std::cout << "Hello, World\n";
    return 0;
}

import cgi

def cookForHtml(text):
    '''"Cooks" the input text for HTML.'''

    return cgi.escape(text)

已定义的宏会在源代码中展开. 示例:

[def __array__ [@http://www.boost.org/doc/html/array/reference.html array]]
[def __boost__ [@http://www.boost.org/libs/libraries.htm boost]]

    using __boost__::__array__;

生成:

using boost::array;

在 quickbook 1.7 及更高版本中, 你可以在代码块中加入 标注 (callout), 如下所示:

[!c++]
    std::string foo_bar() /*< The /Mythical/ FooBar.
                          See [@http://en.wikipedia.org/wiki/Foobar Foobar for details] >*/
    {
        return "foo-bar"; /*< return 'em, foo-bar man! >*/
    }

这将生成:

std::string foo_bar() 
{
    return "foo-bar"; 
}

神秘 的 FooBar. 详情参见 Foobar 详情

return 'em, foo-bar man!

逃逸回 QuickBook

在代码、代码块和行内代码内部, QuickBook 不允许任何标记, 以避免与目标语法 (例如 C++) 冲突. 如果需要在代码内部切换回 QuickBook 标记, 可以使用特定语言的 逃逸回 (escape-back) 分隔符. 在 C++ 和 Python 中, 分隔符是双反引号: "``" 和 "``". 示例:

void foo()
{
}

将生成:

void foo()
{
}

从代码逃逸回 QuickBook 时, 只允许短语级标记. 不允许列表、表格等块级标记.

预格式化

有时, 你不希望某些预格式化文本被解析为源代码. 在这种情况下, 使用 [pre ... ] 标记块.

[pre

    Some *preformatted* text                    Some *preformatted* text

        Some *preformatted* text            Some *preformatted* text

            Some *preformatted* text    Some *preformatted* text

]

空格、制表符和换行按原样呈现. 与所有 quickbook 块级标记不同, pre (和 Code) 是唯一允许多个换行的标记. 上面的标记将生成:

Some preformatted text                    Some preformatted text

    Some preformatted text            Some preformatted text

        Some preformatted text    Some preformatted text

注意, 与 Code 不同, 在 pre 块内仍允许诸如字体样式之类的短语标记.

你可以为标题指定 id:

[h1:heading_id A heading to link to]

要链接到它, 你需要包含外层小节的 id:

[link document_id.section_id.heading_id The link text]

不过, 如果你希望使用与位置无关的链接, 可以在标题前加一个 锚点.

如果标题没有 id, 则会自动以规范化名字生成一个, 规范化使用 name="document_id.section_id.normalized_header_text" (即有效字符为 a-z, A-Z, 0-9 和 _ . 所有无效字符都转换为下划线, 所有大写都转换为小写. 例如: Section 2 小节中的 Heading 1 将规范化为 section_2.heading_1). 你可以使用:

[link document_id.section_id.normalized_header_text The link text]

来链接到它们. 更多信息参见 锚点链接 和 小节.

注释

指定标题 id 是 quickbook 1.6 的特性, 更早的版本不支持.

通用标题

在你不想关心标题级别 (1 到 6) 的情况下, 可以使用 通用标题:

[heading Heading]

通用标题假定其所在最内层小节的级别加一. 例如, 如果放在最外层小节中, 则它采用 h2.

标题常常用作小节的替代. 特别是在你不想开始新小节时使用. 不过在很多情况下, 特定小节中的标题只是平铺的. 示例:

[section A]
[h2 X]
[h2:link_id Y]
[h2 Z]
[endsect]

这里我们使用 h2, 假定小节 A 是最外层. 如果它位于内层, 你就得根据小节所在位置使用 h3、h4 等. 一般而言, 这是小节级别加一. 然而, 每次都要查看小节级别相当繁琐. 如果你按下文所示重写上面的示例, 这将自动完成:

[section A]
[heading X]
[heading Y]
[heading Z]
[endsect]

无论放在哪里它们都能很好地工作. 你可以随意重新安排小节, 无需任何额外工作即可确保正确的标题级别. 事实上, 有了 小节 和 标题, 你就拥有所需的一切. h1..h6 变得多余. h1..h6 在将来可能会被弃用.

宏

[def macro_identifier some text]

定义宏之后, 该标识符会替换文件中任何位置的文本, 包括段落、标记等. macro_identifier 是除 ']' 之外的非空白字符组成的字符串. 宏不能紧跟在字母字符或下划线之后. 替换文本可以是任何短语 (甚至是带标记的). 示例:

[def sf_logo [$http://sourceforge.net/sflogo.php?group_id=28447&amp;type=1]]
sf_logo

现在, sf_logo 放置在任何地方, 图片都会被内联.

提示

使用可区分的宏标识符是个好主意. 例如, 在本文档中, 宏标识符有两个前导和后随下划线 (例如 __spirit__ ). 这样做的原因是避免不想要的宏替换.

链接 (URL) 和图像是宏的绝佳候选. 1) 它们经常变化. 把所有链接和图像集中放在顶部附近的一个地方, 便于修改, 是个好主意. 2) 语法不美观. 例如, 读写 __spirit__ 比 [@http://spirit.sourceforge.net Spirit] 更容易.

更多示例:

[def :-)            [$theme/smiley.png]]
[def __spirit__     [@http://spirit.sourceforge.net Spirit]]

(参见 图像 和 链接)

调用这些宏:

Hi __spirit__  :-)

将生成:

Hi Spirit

模板

模板提供了一种更通用的文本替换机制. 当你需要创建可参数化的多行样板文本, 指定一次并多次展开时, 模板就派上用场. 模板接受一个或多个实参. 这些实参充当文本替换的占位符. 与仅限于短语级标记的简单宏不同, 模板可以包含块级标记 (例如段落、代码块和表格).

模板示例:

[template person[name age what]

Hi, my name is [name]. I am [age] years old. I am a [what].

]

模板标识符

模板标识符可以由以下构成:

  • 以一个字母字符或下划线开头, 后跟零个或多个字母数字字符或下划线. 这与典型的 C/C++ 标识符类似.
  • 单个标点字符 (非字母数字的可打印字符)

模板形参

模板形参是由一个字母字符或下划线开头、后跟零个或多个字母数字字符或下划线组成的标识符. 这与典型的 C/C++ 标识符类似.

模板形参会在 模板展开 处临时隐藏同名模板. 注意, 上面 person 模板的主体将 name, age 和 what 称为 [name] [age] 和 [what] . name age 和 what 实际上是模板调用期间存在的模板.

模板主体

模板主体几乎可以是任何 QuickBook 块或短语. 实际上有两种形式. 模板可以是短语级或块级. 短语模板的形式为:

[template sample[arg1 arg2...argN] replacement text... ]

块模板的形式为:

[template sample[arg1 arg2...argN]
replacement text...
]

基本规则如下: 如果换行紧跟在实参列表之后, 那么它是块模板; 否则它是短语模板. 短语模板通常作为短语的一部分展开. 与宏一样, 短语模板中不允许块级元素.

模板展开

你用如下方式展开模板:

[template_identifier arg1..arg2..arg3]

在模板展开时, 你提供实际实参. 模板将使用你提供的实参展开. 示例:

[person James Bond..39..Spy]
[person Santa Clause..87..Big Red Fatso]

它将展开为:

Hi, my name is James Bond. I am 39 years old. I am a Spy.

Hi, my name is Santa Clause. I am 87 years old. I am a Big Red Fatso.

注意

需要提醒的是: 模板是递归的. 模板可以调用另一个模板, 甚至直接或间接地调用自身. QuickBook 中 (尚) 没有控制结构, 因此这总意味着无限递归. QuickBook 能检测这种情况, 并在递归超过某个限制时报错.

每个实际实参可以是一个词、一段文本或几乎任何 QuickBook 短语 . 实参由双点 ".." 分隔, 并以闭括号结束.

注意, 模板和模板形参并非处处都能展开, 只有在文本被解释为短语的地方才行. 因此它们不能在表格标题和链接 url 等位置展开. 如果你想用模板基于模板形参生成链接, 就不能用普通链接, 而需要使用转义的 docbook. 示例:

[template boost_ticket[key] '''<ulink url="https://svn.boost.org/trac/boost/ticket/'''[key]'''">#'''[key]'''</ulink>''']

[boost_ticket 2035]

将展开为:

#2035

注意

由于 quickbook 不理解使用形参的上下文, 它会将其解释为 quickbook 标记, 因此在编写这样的模板时, 你需要转义任何有意义的标点.

无参模板

无参模板的外观和行为都像简单宏. 示例:

[template alpha[]&apos;&apos;&apos;&amp;#945;&apos;&apos;&apos;]
[template beta[]&apos;&apos;&apos;&amp;#946;&apos;&apos;&apos;]

展开:

Some squigles...[*[alpha][beta]]

我们得到:

一些弯弯曲曲的符号...αβ

与宏的区别在于

  • 显式的 模板展开语法 . 这是一个优点, 因为现在我们不必使用双下划线之类晦涩的命名约定 (例如 __alpha__) 来避免不想要的宏替换.
  • 模板在调用点展开. 宏在其声明点立即展开. 这很微妙, 可能导致行为上的细微差别, 尤其是当你在主体中引用其他宏和模板时.

模板标识符后的空括号 (alpha[]) 表示没有实参. 如果模板主体看起来不像模板实参列表, 我们可以省略空括号. 示例:

[template aristotle_quote Aristotle: [*['Education is the best provision
for the journey to old age.]]]

展开:

Here's a quote from [aristotle_quote].

我们得到:

以下是亚里士多德的一句话: 教育是为老年之旅所做的最好准备.

缺点是你无法避免模板标识符 aristotle_quote 与模板主体 "Aristotle..." 之间的空格. 该空格会成为模板主体的一部分. 如果不想要这个空格, 请使用空括号或空格转义: "\ ". 示例:

[template tag\ _tag]

然后展开:

`struct` x[tag];

我们得到:

struct x_tag;

你有几种方式可以做到这一点. 不过我个人更喜欢显式的空括号.

简单实参

如前所述, 实参由双点 ".." 分隔. 或者, 如果不使用双点而期望多个实参, QuickBook 会使用空白来分隔实参, 遵循以下逻辑:

  • 在找到的第一个空格处 ('', '\n', \t' or '\r') 把最后一个实参拆分为两个.
  • 重复, 直到实参数量足够或再也找不到空格 (此时报错).

例如:

[template simple[a b c d] [a][b][c][d]]
[simple w x y z]

将产生:

wxyz

"w x y z" 最初被视为单个实参, 因为我们没有提供任何 ".." 分隔符. 然而, 由于 simple 期望 4 个实参, "w x y z" 会被迭代拆分 (应用上述逻辑), 直到得到 "w"、"x"、"y" 和 "z".

QuickBook 只尝试获取所需的实参. 例如:

[simple w x y z trail]

将产生:

wxyz trail

实参为: "w"、"x"、"y" 和 "z trail".

注意

此处描述的行为适用于 QuickBook 1.5. 在更早的版本中, 同一模板调用中可以同时使用双点和空白作为分隔符. 如果你的文档标记为更早的版本, 它将使用旧行为, 其描述见 QuickBook 1.4 文档.

标点模板

关于模板, 我们的目标之一是让我们能够用 QuickBook 重写 QuickBook (作为 qbk 库). 为此, 我们需要支持在 QuickBook 中相当常见的单字符标点模板. 你可能已经注意到, 单字符标点可以用作 模板标识符 . 示例:

[template ![bar] <hey>[bar]</hey>]

现在, 展开它:

[!baz]

我们将得到:

<hey>baz</hey>

包含

你可以从一个 QuickBook 文件包含另一个. 语法很简单:

[include someother.qbk]

在 quickbook 1.6 及更高版本中, 如果被包含的文件有 docinfo 块, 则会创建一个嵌套文档. 它将作为独立文档处理, 不过来自外层文件的任何宏或模板仍会有效.

否则, 被包含的文件将像被剪切并粘贴到当前文档中一样处理, 但有以下例外:

  • __FILENAME__ 预定义宏将反映当前正在处理的文件的名称.
  • 被包含文件中定义的任何宏或模板的作用域限于该文件, 即它们不会被添加到外层文件.
注释

在 quickbook 1.5 及更早版本中, 模板在被包含文件中不限定作用域. 如果你想在 quickbook 1.6 中使用来自某文件的模板或宏, 请改用 导入.

[include] 指令允许你为被包含的文件指定要使用的文档 id. 你可以这样指定 id:

[include:someid someother.qbk]

所有自动生成的锚点都会使用该文档 id 作为唯一前缀. 例如, 如果 someother.qbk 中有一个名为 "Intro" 的顶层小节, 该小节的命名锚点将是 "someid.intro", 你可以用 [link someid.intro The Intro] 链接到它.

如果被包含的文件有 docinfo 块, 在 [include] 指令中指定的 id 将覆盖它.

你也可以包含 C、C++ 和 python 源文件. 这会包含文件中不在命名代码片段内的任何 quickbook 块. 语法细节参见 导入小节 . 例如, 假设你包含了以下文件:

/**
 * Hello world example
 */

// In this comment, the backtick indicates that this is a
// quickbook source block that will be included.

/*`
First include the appropriate header: [hello_includes]
Then write your main function: [hello_main]
*/

// This defines a code snippet, the syntax is
// described in the import section. It's available
// in the whole of this source file, not just after
// its definition.

//[hello_includes
#include <iostream>
//]

//[hello_main
int main() {
    std::cout << "Hello, trivial example" << std::endl;
}
//]

它将生成:

First include the appropriate header:

    #include <iostream>

Then write your main function:

    int main() {
        std::cout << "Hello, trivial example" << std::endl;
    }

导入

在 quickbook 1.6 及更高版本中, 如果你想使用来自某文件的模板、宏或代码片段, 需要导入它. 这不会包含该文件的任何内容, 但会把模板、宏和代码片段拉入当前文件的作用域.

对于 quickbook 文件, 这允许你创建模板和宏库. 对于 python (由 .py 扩展名指示)、C 或 C++ 文件, 这允许你从源文件中包含代码片段, 从而使你的代码示例保持最新并经过完整测试.

你可以毫不费力地把代码片段从源代码导入到你的 QuickBook 中. 下面说明这是如何做到的:

[bar]

代码片段标记

注意 stub.cpp 中的代码片段是如何被标记的. 我们使用如下形式的可区分注释:

//[id
some code here
//]

上面的第一行注释启动一个命名代码片段. 此前缀在 quickbook 中不可见. //[id 与 //] 之间的整个代码片段将作为模板插入 quickbook, 名为 id . 注释 //] 结束一个代码片段. 这在 quickbook 中同样不可见.

特殊注释

如下形式的特殊注释:

//` some [*quickbook] markup here

以及:

/*` some [*quickbook] markup here */

将由 QuickBook 解析. 它可以包含 quickbook 块 (例如小节、段落、表格等). 在第一种情况下, 开头的双斜杠、反引号和空白将被忽略. 在第二种情况下, 开头的斜杠-星号-反引号和结尾的星号-斜杠将被忽略.

如下形式的特殊注释:

/*<- this C++ comment will be ignored ->*/

或者

/*<-*/ "this c++ code  will be ignored" /*->*/

或者

//<-
private:
    int some_member;
//->

可用于阻止代码传递到 quickbook. 分隔符之间的所有文本都将被忽略.

如下形式的注释:

//=int main() {}

或者

/*=foo()*/

将显示为不在注释中的代码. 这允许你在片段中包含一些代码, 但在编译示例时实际不使用它.

标注 (Callout)

如下形式的特殊注释:

/*< some [*quickbook] markup here >*/

将被视为标注. 它们会被收集、编号, 并渲染为 "标注圆点" (带数字的小图标). 整个片段解析完后, 会生成标注列表. 详情参见 标注 . 示例:

std::string foo_bar() 
{
    return "foo-bar"; 
}

神秘 的 FooBar. 详情参见 Foobar 详情

return 'em, foo-bar man!

这是实际的代码:

//[ foo_bar
std::string foo_bar() /*< The /Mythical/ FooBar.
                      See [@http://en.wikipedia.org/wiki/Foobar Foobar for details] >*/
{
    return "foo-bar"; /*< return 'em, foo-bar man! >*/
}
//]

标注圆点被放在特殊标注注释所在的确切位置. 它可以位于代码中的任何地方. 不过这些圆点可能相当显眼, 会妨碍代码的清晰性. 还有另一种特殊的标注注释样式:

/*<< some [*quickbook] markup here >>*/

这是面向行的标注版本. 这样, "圆点"被放在代码块的最左侧, 远离实际代码. 由于放在最左侧, 代码的呈现不会被遮挡. 示例:

    {
    }

    ~x()
    {
    }

    int get() const
    {
        return n;
    }

    {
        n = n_;
    }
};

普通块

block 是一个普通块元素, 它不会把其内容包装在任何 docbook 或 boostbook 标签中. 这在使用转义的 docbook 块标签时很有用, 例如:

[template chapter[title]
[block'''<chapter><title>'''[title]'''</title>''']
]

[template chapterend
[block'''</chapter>''']
]

[chapter An example chapter]

Content

[chapterend]

如果没有 block 元素, chapter 和 chapterend 模板将被包装在段落标签中.

注释

在此示例中, 模板主体必须以换行开头, 这样模板才会以块模式解释.
