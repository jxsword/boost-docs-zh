升级到新版本

要将现有文档升级到新版 quickbook, 你需要更新 docinfo 块中的版本. 例如, 现有的 docinfo 块可能如下:

[library Boost.Example
    [quickbook 1.3]
    ...
]

把它改为:

[library Boost.Example
    [quickbook 1.7]
    [compatibility-mode 1.3]
    ...
]

compatibility-mode 标签确保它生成与旧版本类似的输出 - 最重要的是它会生成相同的 id, 确保指向生成 html 的链接不会失效.

然后尝试构建. 更高的版本有更严格的解析器, 因此可能出现错误. 你很可能需要修复一些游离的方括号. 它们可能需要转义. 例如, 要写出半开范围 [a,b), 请使用: \[a,b).

升级到 1.6 或更高版本时, 你可能需要重新考虑模板和宏的定义方式. 如果你之前 include 了某个文件以使用其模板, 现在需要改为 import 它, 因为模板现在由被包含文件限定作用域. 另外, 如果你在主 quickbook 文件中定义模板和宏, 你可能想把它们放到单独的文件中并 import 它, 这样主文档文件就可以专注于文档的结构和内容, 更易于阅读.

既然标题可以有 id, 为现有标题添加 id 是个好主意. 这意味着标题将拥有更可预测的 id, 不会随标题文本改变而变化. 为了保留链接, 你可以使用现有的生成 id 作为标题 id.

稳定版本

从 quickbook 1.3 起, 文档块中的 quickbook 属性选择要使用的语言版本. 并非 quickbook 的所有更改都通过版本开关实现, 主要是那些改变文档解释方式或会破坏现有文档的更改.

Quickbook 1.3 及更高版本

  • 引入 quickbook 语言版本化.
  • 在文档信息中, 允许在 license 和 purpose 属性中使用短语标记.
  • 完整限定的小节与标题. 小节名会拼接到 ID 上以避免冲突. 示例: doc_name.sect_name.sub_sect_name.sub_sub_sect_name.

Quickbook 1.5 及更高版本

  • 忽略方括号内的模板实参分隔符.
  • 如果使用了 .. 分隔符, 则不再拆分最后一个模板实参. 即绝不混用 .. 与空白分隔符.
  • 静态地而非动态地确定模板及其实参的作用域.
  • 为表格提供 id, 并允许你设置它们.
  • 在可拥有 id 的元素中, 允许 : 字符与 id 之间有空格.

带 docinfo 的包含

在 quickbook 1.5 中, 如果你包含一个以 docinfo 块开头的文件, 该块会被忽略, 文件原地展开. 在 quickbook 1.6 中, 它会被视为嵌套在当前位置的文档. 因此如果它有 'article' docinfo 块, 就会使用 boostbook 'article' 标签.

它大多也会生成与单独转换该文件时相同的标记 - 例如生成相同的 id, 文档使用 docinfo 块中指定的语言版本处理. 若未指定语言, 则使用默认版本 (1.1) 而不是包含它的文档的版本. 这可能令人意外, 但这是必需的, 这样 quickbook 转换它的方式才与单独转换时相同.

因此总的来说, 带 docinfo 的包含类似于 xinclude, 只有一些差异. 父文档中定义的模板和宏会在被包含文档中使用, 且 id 生成器会重写多个文档之间冲突的 id.

如果被包含文档没有 docinfo 块, 它就照旧被包含.

docinfo 块中的宏

现在可以在 docinfo 块的文本字段中展开宏. 在顶层 docinfo 块中只有预定义宏可用, 但在嵌套文档中, 父文档中定义的宏也可用.

这里有一个小缺陷 - 它会泄漏到旧版本的 license 和 purpose 字段, 但由于只有预定义宏可用, 不太可能破坏任何现有文档. 所以我宁可不再为此修复而把代码复杂化.

模板和宏的作用域

quickbook 长期存在一个缺陷: 宏按文件限定作用域, 而模板不是. 因此你可以在单独的文件中定义模板并包含它们, 但宏不行. 这一问题已修复, 一个文件中定义的模板不会再 '泄漏' 到另一个文件.

但这意味着无法在单独的文件中定义模板 - 这本来是个有用的特性. 为此, import 元素经过调整以同时支持 quickbook 文件. 如果导入 quickbook 文件, 其中定义的模板和宏会被添加到当前作用域, 但该文件包含的其他内容不会被使用. 这可用于创建模板和宏库文件. 这与导入代码片段的既有语义一致.

导入模板时, 它们会绑定到定义它们的文件的语言版本. 这意味着如果把它导入到版本不同的文件中, 不会改变它们的解释方式. 不过, 正如我们将在后文看到的, 生成的 boostbook 略有不同.

包含 C++ 和 python 文件

由于 import 现在支持 quickbook 文件, include 也支持源文件. 它会包含代码片段之外注释中的任何 quickbook 内容. 文件中的代码片段可在该文件内展开, 但作用域限于该文件. 方式与模板和宏在被包含的 quickbook 文件中限定作用域时完全相同.

id 生成

quickbook 1.5 中的 id 生成有些缺陷, 但没有版本开关就无法修复, 否则会破坏现有文档. 例如在 quickbook 1.5 中包含 quickbook 文件时, 它会停止使用文档信息中的显式 id, 而是根据文档标题生成一个新 id.

quickbook 1.6 的 id 生成器在其他方面也有所改进. 从小节标题、表格标题等生成 id 时, 它总是使用 quickbook 源码而非生成的 boostbook 来生成 id. 然后稍微清理 id, 去除前导和尾随下划线, 并把多个下划线替换为单个下划线. 之后, 如果新生成的 id 部分超过 32 个字符, 则将其截断.

虽然新的 id 生成器通常生成更好的 id, 但更容易产生重复, 因此 quickbook 需要更好地处理重复. 当存在多个相同 id 时, quickbook 根据优先级列表选择一个使用 - 优先选择锚点, 其次是显式文档和小节 id, 然后是其他显式 id, 最后是生成的 id. 随后, 文档中任何其他显式 id 会加上编号以避免重复 - 先按出现顺序处理显式 id, 再处理生成的 id. 偶然与显式 id 冲突的生成 id 绝不应改变显式 id.

更旧的语言版本仍生成与以往相同的 id, 但重复 id 例外, 它们使用新机制处理 - 这不是破坏性变更, 因为重复的 id 本来就无法链接.

兼容模式

如前所述, 更改 id 生成器会破坏使用旧语言版本编写的文档中的链接. 因此为方便过渡, 使用了 '兼容模式', 这只需要在 docinfo 中添加一个额外属性, 例如把 1.5 文档转换为 1.6 时:

[article Document
[quickbook 1.6]
[compatibility-mode 1.5]
]

这意味着文档将按 1.6 解析, 使用全部新特性, 但 id (以及可能其他标记) 将按 1.5 文档的方式生成.

当展开以与当前文档不同的语言版本编写的模板时, 也会隐式使用兼容模式. 因此模板按其编写时的版本解析, 但生成与当前文档兼容的 boostbook.

文档信息块之外的版本信息

现在可以在文件开头使用 quickbook 和 compatibility-mode 标签, 可以在文档信息块之前, 或在没有文档信息块时使用. 这对只包含模板的文件很有用, 它们其实不需要文档信息块.

如果不指定 compatibility-mode, 行为取决于是否有 docinfo 块. 如果有, 则使用文件的 quickbook 版本; 如果没有, 则继承父文档的兼容模式, 即使你指定了 quickbook 版本. 这是正确的做法 - 在文档内混用兼容模式是有问题的. 允许在 docinfo 块之外指定它们实际上可能是个错误.

这一更改也追溯适用于更旧的版本. 因此从旧版本包含时, 可以设置被包含文件的版本 (旧版本会忽略被包含文件中的文档信息).

显式标题 id

现在可以为标题指定显式 id:

[heading:id A heading with an explicit id]

标点更改

在 1.6 中, quickbook 对标点的解析更加一致. 现在在链接、锚点、表格标题、图像属性等中支持转义. 相应的代价是 quickbook 对未转义的括号更加严格. 括号仍可使用, 但必须配对, 否则报错.

由于 quickbook 现在会配对方括号, 它将修复一些错误解析. 例如 [*[bold]] 以前解析为 [bold] - 注意闭方括号不是粗体, 现在它解析为 [bold].

表格标题

表格标题现在按短语解析, 因此允许一些标记:

[table [*bold title]]

这是一个带粗体标题的空表格. 标题不再由换行结束, 而是由闭方括号或两个开方括号结束 - 后者出现在表格单元格开头, 所以现在这样可行:

[table Simple[[heading 1][heading 2]][[cell 1][cell 2]]]

XML 基

在转义的 boostbook 中使用 xi:include 标签的一个问题是, 你通常不知道 boostbook 文件会在哪个目录中, 因此无法使用相对链接. 通过向 document 标签添加 xml:base 属性可以解决. 为此, 在文档的 docinfo 块中使用新的 xmlbase 属性. 例如, 让转义的 xi:include 相对于文件所在目录:

[library Library documentation
[quickbook 1.6]
[xmlbase .]
]

xinclude 元素中的任何路径都会相应重写. 注意大多数文档不需要这个, 或许也不应该使用. 只有完全确定需要时才使用.

改进的模板解析器

模板声明与形参有了一个新解析器, 它能更好地理解转义和带括号的文本. 遗憾的是它不理解元素名, 因此在某些情况下可能出错. 例如:

[template doesnt_work[]
[ordered_list
    [`code phrase`]
]
]

在这种情况下, 它会认为 [\` 是模板调用并给出解析错误. 要绕过这个问题, 请在代码短语前放一个转义空格:

[template works[]
[ordered_list
    [\ `code phrase`]
]
]

新元素

quickbook 1.6 中新增的元素:

  • block
  • ordered_list 与 itemized_list
  • role

在错误上下文中使用元素的错误

以前如果在错误的上下文中使用元素, 它只会不被处理, 这令人意外. 人们常常没有意识到他们的元素未被处理. 所以现在这成为错误.

无效短语元素的错误

如果短语元素的主体无法解析, 它会直接原样使用. 现在改为硬错误.

单个实体的源模式

1.7 引入了一个新的 ! 元素类型, 用于设置单个实体的源模式而不改变其他部分的源模式. 这可用于代码块和其他元素. 例如:

[!c++]
    void foo() {};

[!python]```def foo():```

它还可用于为元素设置源模式:

[!teletype][table
    [[code][meaning]]
    [[`+`][addition]]
]

在小节之前使用时, 它为整个小节设置源模式.

如果它出现在段落开头, 只有当有换行时才用于整个段落, 例如.

[!c++]
A declaration `void foo();` and a definition `void foo() {}`.

代码块中的标注

目前标注只能用于代码片段. 1.7 增加了对普通代码块的支持. 使用与代码片段相同的语法, 标注描述紧跟在代码块之后.

docinfo 块中的转义 docbook

Quickbook 的 docinfo 属性可能永远不会像 docbook 属性那样丰富. 为了允许 quickbook 不支持的更灵活的标记, 可以在 docinfo 块中包含转义的 docbook:

[article Some article
[quickbook 1.7]
'''<author>
    <firstname>John</firstname>
    <surname>Doe</surname>
    <email>john.doe@example.com</email>
</author>'''
]

转义的 docbook 总是放在 docinfo 块的末尾, 因此不应假定它会与 quickbook 生成的标记交错. 对同一信息混用 quickbook 和 docbook 属性效果不佳.

列表中的段落

现在可以在列表中使用段落和块元素:

* Para 1

  Para 2
  * Nested Para 1

    Nested Para 2

        Code block
  Para 3

生成:

  • 段落 1

    段落 2

    • 嵌套段落 1

      嵌套段落 2

      Code block

    段落 3

某些属性中的模板

支持在链接值、锚点、角色和 include 中调用模板. 这有时是一种改变, 尤其是在当前允许空格的地方, 因此我可能需要在需要处使用略有不同的文法. 我认为还需要添加一些验证, 因为这个解析器允许的符号比某些旧解析器更多.

嵌套块中的列表标记

现在可以把列表标记放在嵌套块中, 例如表格、变长列表等. 遗憾的是缩进代码块更加棘手, 因为这些块的内容通常已经缩进. 与其尝试为边界情况制定合理的处理, 不如干脆在此上下文中不支持缩进代码块. 如果你想在此上下文中使用代码块, 仍应可以使用显式标记.

允许短语模板中的块元素

块元素现在可用于短语模板, 但不允许段落分隔, 因此以下是错误:

[template paras[] Something or other.

Second paragraph.]

如果短语模板只包含块元素, 那么它实际上与块模板无法区分. 因此以下两者输出相同:

[template foo[] [blurb Blah, blah, blah]]

与:

[template foo[]
[blurb Blah, blah, blah]
]

如果短语模板的短语内容与块元素混合, 它将像内联展开那样生成输出.

使用 glob 包含多个文件

现在可以对文件引用使用 glob 模式一次包含多个文件:

[include sub/*/*.qbk]
[include include/*.h]

所有匹配的文件和中间目录都会匹配并被包含. glob 模式可以是 "*" 匹配零个或多个字符, "?" 匹配单个字符, "[<c>-<c>]" 匹配字符类, "[^<char>-<char>]" 排除匹配字符类, "\\" 转义随后被匹配的 glob 特殊字符, 其他任何字符则与该字符匹配.

注释

由于文件引用中的转义, "\\" glob 转义是双 "\\"; 即转义的反斜杠.
