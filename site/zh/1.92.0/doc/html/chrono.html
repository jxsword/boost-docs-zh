动机

时间

我们每个人每天都要与时间打交道. 我们从出生起就凭直觉了解它. 因此我们都非常熟悉它, 并认为它是一件简单的事情. 在计算机程序中对时间建模本应同样简单. 遗憾的是, 这种表面上的简单只是肤浅的. 好在, 我们并不需要一个极其复杂的方案来满足大部分需求. 然而, 过于简单的方案可能是危险且低效的, 并且无法随计算机行业的发展而适应变化.

Boost.Chrono 实现了 C++11 中的新时间设施, 如 N2661 - A Foundation to Sleep On 提案所述. 该文档提供了关键设计决策的背景与动机, 也是本文档中大量信息的来源.

除了标准提案提供的时钟之外, Boost.Chrono 还提供特定的进程时钟和线程时钟.

挂钟时间与系统及用户时间

为了让 Boost.Chrono 的计时设施具有更广泛的用途, 本库提供了一些时钟, 它们是对操作系统进程时间 API 的薄封装, 从而可以提取进程的挂钟时间、用户 CPU 时间和系统 CPU 时间. 挂钟时间是 CPU 时间与系统 CPU 时间之和. (在类 POSIX 系统上, 这依赖于 times(). 在 Windows 上, 它依赖于 GetProcessTimes().)

说明

Boost.Chrono 库提供:

标准
  • 表示时间时长的手段: 由通用的 duration 类管理. 时间时长的例子包括天、minutes, seconds and nanoseconds,, 它们可以用每单位固定的时钟节拍数来表示. 所有这些时间时长单位都通过 duration 设施以通用接口统一起来.
  • 表示时间点的类型: time_point. time_point 表示一个纪元加上或减去一个 duration. The library leaves epochs unspecified. time_point 与一个 时钟 相关联.
  • 若干时钟, 其中某些可能在特定平台上不可用: system_clock, steady_clock 和 high_resolution_clock. 时钟是 time_point 和 duration, 和 a function which returns a time_point 的 now.
其他时钟

为了让计时设施具有更广泛的用途, Boost.Chrono 提供了一些时钟, 它们是对操作系统时间 API 的薄封装, 从而可以提取进程所耗的挂钟时间、用户 CPU 时间、系统 CPU 时间,

  • process_real_cpu_clock, 捕获当前进程所耗的挂钟 CPU 时间.
  • process_user_cpu_clock, 捕获当前进程所耗的用户 CPU 时间.
  • process_system_cpu_clock, 捕获当前进程所耗的系统 CPU 时间.
  • 一个类似元组的类 process_cpu_clock, 一起捕获进程的实耗 (real) 时间、用户 CPU 时间和系统 CPU 时间.
  • thread_clock, 一个线程稳定时钟, 给出当前线程所耗的时间 (在平台支持时).

最后, Boost.Chrono 包含 typeof 注册, 针对 duration 和 time_point, 以便在 C++03 编译器上使用模拟的 auto.

I/O

它为 duration 和 time_point 提供 I/O. 这种 I/O 使得这些类型的使用方便得多. 遵循 "只为你所用的部分付费" 的理念, 这一额外功能位于与 <boost/chrono/chrono.hpp> 分开的另一个头文件中, 即 <boost/chrono/chrono_io.hpp>.

It builds on <boost/ratio/ratio_io.hpp> 之上, 为 <boost/chrono.hpp> 中的类型提供可读且灵活的格式化与解析. 这种文本表示尽可能使用 SI 前缀. 这使得 boost::milliseconds 可以很容易地用文本 "milliseconds" 表示, 或者让一个假想的 meter 类打印出 "millimeter". duration 与 time_point 的 I/O 可以通过新的刻面进行定制: duration_units 和 time_point_units. 用户可以特化这些刻面, 使 chrono I/O 可以本地化. 不过 Boost.Chrono 并未提供完整的 locale 方案.

system_clock::time_point 的 I/O 以 UTC 时间点的方式提出, 并强烈地受到 ISO 9899:1999 (Programming languages - C)、ISO 9945:2003 (Information Technology - Portable Operating System Interface (POSIX)) 以及 ISO 8601:2004 (Data elements and interchange formats - Information interchange - Representation of dates and times) 的指引.

购者自慎 (Caveat Emptor)

操作系统提供的底层时钟受到许多看似任意的策略和实现不规则性的制约. 这是一种委婉的说法, 意思是它们往往不可靠, 而且每个操作系统甚至每个时钟都有自己独特而古怪的不可靠形式. 不要把全部赌注押在它们的精度上, 除非你已经非常熟悉特定操作系统到底保证了什么——而这通常少得可怜.
