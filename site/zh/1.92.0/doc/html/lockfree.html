Introduction & Motivation

引言与术语

术语 非阻塞 指那些不使用守卫等传统同步原语来确保线程安全的并发数据结构. Maurice Herlihy 和 Nir Shavit (参见 "The Art of Multiprocessor Programming") 区分了 3 类非阻塞数据结构, 各自具有不同的性质:

  • 若每个并发操作都保证在有限步内完成, 则称数据结构是 无等待 的. 因此可以为操作次数给出最坏情形保证.
  • 若某些并发操作保证在有限步内完成, 则称数据结构是 无锁 的. 虽然理论上可能出现某些操作永远得不到进展的情况, 但这在实际应用中发生的可能性极小.
  • 若一个并发操作保证在有限步内完成, 除非另一个并发操作干扰, 则称数据结构是 无阻碍 的.

某些数据结构只有在特定限制下使用时, 才能以无锁的方式实现. 对 boost.lockfree 的实现而言, 相关因素是生产者线程和消费者线程的数量. 单生产者 (sp) 或 多生产者 (mp) 表示只允许单个线程或多个并发线程向数据结构添加数据. 单消费者 (sc) 或 多消费者 (mc) 则表示从数据结构移除数据时的等价概念.

非阻塞数据结构的性质

非阻塞数据结构不依赖锁和互斥量来确保线程安全. 同步完全在用户态完成, 与操作系统没有任何直接交互 [7]. 这意味着它们不易出现优先级反转 (低优先级线程需要等待高优先级线程) 之类的问题.

非阻塞数据结构不依赖守卫, 而是需要 原子操作 (不中断执行的特定 CPU 指令). 这意味着任何线程要么看到操作之前的状态, 要么看到操作之后的状态, 不可能观察到中间状态. 并非所有硬件都支持同一组原子指令. 如果硬件不提供, 可以在软件中用守卫来模拟. 但这显然会失去无锁性质.

非阻塞数据结构的性能

讨论非阻塞数据结构的性能时, 必须区分 均摊 代价与 最坏情形 代价. 'lock-free' 与 'wait-free' 的定义只提到操作的上界. 因此, 无锁数据结构未必是每个用例的最佳选择. 若要最大化应用程序的吞吐量, 应当考虑高性能并发数据结构 [8].

为了优化系统的延迟或避免优先级反转, 无锁数据结构会是更好的选择, 这在实时应用中可能是必要的. 一般来说, 我们建议考虑无锁数据结构是否必要, 还是并发数据结构已经足够. 无论哪种情况, 我们都建议针对具体工作负载, 用不同的数据结构进行基准测试.

阻塞行为的来源

除了锁和互斥量 (反正 boost.lockfree 并不使用它们) 之外, 还有另外三个方面可能违反无锁性:

原子操作

某些体系结构没有在硬件中原生提供必要的原子操作. 若硬件不提供, 它们会在软件中用自旋锁模拟, 而自旋锁本身就是阻塞的.

内存分配

从操作系统分配内存不是无锁的. 这使得无法实现真正动态大小的非阻塞数据结构. boost.lockfree 的基于节点的数据结构使用内存池来分配内部节点. 若内存池耗尽, 就必须从操作系统为新节点分配内存. 不过, boost.lockfree 的所有数据结构都可以配置为避免内存分配 (此时特定的调用将失败). 这对需要无锁内存分配的实时系统尤其有用.

异常处理

C++ 异常处理不对其实时行为提供任何保证. 因此我们不鼓励在无锁代码中使用异常和异常处理.

数据结构

boost.lockfree 实现了六种无锁数据结构:

boost::lockfree::queue

一种无锁的多生产者/多消费者队列 (基于 Michael & Scott 算法)

boost::lockfree::bounded_ticket_queue

一种基于 Dyukov turnstile 的有界多生产者/多消费者队列 (Vyukov 有界 MPMC 算法). 可通过 single_producer<> 和 single_consumer<> 策略标签进行配置, 以获得无等待的 push 或 pop.

boost::lockfree::mpsc_weak_queue

一种多生产者/单消费者队列 (基于 Dmitry Vyukov 算法)

boost::lockfree::stack

一种无锁的多生产者/多消费者栈 (基于 Treiber 算法)

boost::lockfree::spsc_queue

一种无等待的单生产者/单消费者队列 (通常称为环形缓冲区)

boost::lockfree::spsc_value

一种无等待的单生产者/单消费者值 (通常称为三重缓冲)

数据结构配置

这些数据结构可以用 Boost.Parameter 风格的模板进行配置:

boost::lockfree::fixed_sized

把数据结构配置为 固定大小. 内部节点存储在数组内部, 通过数组下标寻址. 这把队列的可能大小限制为索引类型可寻址的元素数量 (通常为 2**16-2), 但在缺少双宽度比较交换指令的平台上, 这是实现无锁性的最佳方式.

boost::lockfree::capacity

在编译期设置数据结构的 容量. 这意味着该数据结构是固定大小的.

boost::lockfree::allocator

定义分配器.

boost::lockfree::allow_multiple_reads

把 boost::lockfree::spsc_value 配置为允许内容被多次读取.

boost::lockfree::single_producer

把数据结构配置为单生产者使用. 当设置为 true 时, push 不使用 CAS 且是无等待的. 仅对 boost::lockfree::bounded_ticket_queue 有效.

boost::lockfree::single_consumer

把数据结构配置为单消费者使用. 当设置为 true 时, pop 不使用 CAS 且是无等待的. 仅对 boost::lockfree::bounded_ticket_queue 有效.


[7] 自旋锁也不直接与操作系统交互. 但是, 持有自旋锁的线程可能被操作系统抢占, 这会违反无锁性质.

[8] Intel 的 Thread Building Blocks 库 提供了许多高效的并发数据结构, 它们未必是无锁的.
