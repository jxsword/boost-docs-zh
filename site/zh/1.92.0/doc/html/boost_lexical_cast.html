动机

有时一个值必须转换为字面文本形式, 例如 int 表示为 std::string; 或者反过来, 当 std::string 被解释为 int 时. 在程序的内部数据类型与程序外部的表示 (如窗口与配置文件) 之间转换时, 这类例子很常见.

标准的 C 与 C++ 库提供了许多执行此类转换的设施. 然而, 它们在易用性、可扩展性与安全性方面参差不齐.

例如, 以 atoi 为代表的标准 C 函数族存在许多局限:

  • 只支持一个方向的转换: 从文本到内部数据类型. 使用 C 库进行反方向转换, 要么需要使用 sprintf 函数这种不便且安全性受损的方式, 要么需要使用 itoa 等非标准函数而牺牲可移植性.
  • 支持的类型范围只是内置数值类型的一个子集, 即 int、long 与 double.
  • 类型范围无法以统一的方式扩展. 例如, 从字符串表示到复数或有理数的转换.

以 strtol 为代表的那些标准 C 函数具有相同的基本局限, 但对转换过程提供更细粒度的控制. 然而, 对于常见情形, 这种控制往往要么不需要, 要么不被使用. scanf 函数族提供了更大的控制力, 但同样缺乏安全性与易用性.

标准 C++ 库为这里讨论的这种核心内格式化提供了 stringstream. 它对经由文本进行的任意类型 I/O 的格式化与转换提供了大量控制. 然而, 对于简单转换, 直接使用 stringstream 要么笨拙 (引入额外的局部变量, 失去中缀表达式的便利), 要么晦涩 (在表达式中以临时对象创建 stringstream 对象). 刻面 (facet) 为控制文本表示提供了全面的概念与设施, 但其公认的高复杂性与高入门门槛使得简单转换也需要极深的介入, 将绝大多数程序员拒之门外.

lexical_cast 函数模板为任意类型以文本形式表示时常见的相互转换提供了方便且一致的形式. 它带来的简化是表达式层面的便利. 对于更复杂的转换, 例如精度或格式化需要比 lexical_cast 默认行为更严格的控制时, 建议采用传统的 std::stringstream 方法. 当转换为数值到数值时, boost::numeric_cast 可能提供比 lexical_cast 更合理的行为.

关于基于字符串的格式化所涉及的选择与问题的精彩讨论, 包括 stringstream、lexical_cast 等的比较, 参见 Herb Sutter 的文章 The String Formatters of Manor Farm. 另外, 请看一下 性能 一节.
