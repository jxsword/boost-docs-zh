定义自定义概念

(本节示例的源代码见 custom.cpp)

前面, 我们使用 BOOST_TYPE_ERASURE_MEMBER 为支持 push_back 的容器定义了一个概念. 但有时这个接口不够灵活. 本库还提供了一个更低层的接口, 可完全控制行为. 让我们看看定义 has_push_back. 需要些什么. 首先, 我们需要定义 has_push_back 模板本身. 我们给它两个模板参数, 一个用于容器, 一个用于元素类型. 该模板必须有一个名为 apply 的静态成员函数, 用于执行该操作.

template<class C, class T>
struct has_push_back
{
    static void apply(C& cont, const T& arg) { cont.push_back(arg); }
};

现在, 我们可以在 any 中使用它, 并用 call 来分派该操作.

std::vector<int> vec;
any<has_push_back<_self, int>, _self&> c(vec);
int i = 10;
call(has_push_back<_self, int>(), c, i);
// vec is [10].

我们的第二个任务是定制 any, 以便可以调用 c.push_back(10). 我们通过特化 concept_interface 来做到这一点. 第一个实参是 has_push_back, 因为我们想向每个 any (它使用 has_push_back 概念) 注入一个成员. 第二个实参 Base 被本库用来把 concept_interface 的多次使用串联起来, 我们必须公开继承它. Base 还用于访问完整的 any 类型. 第三个实参是代表该 any 的占位符. 如果有人使用 push_back<_c, _b>, 我们只想在容器中插入一个 push_back 成员, 而不是值类型. 因此, 第三个实参就是容器占位符.

当我们定义 push_back 时, 实参类型使用元函数 as_param. 这只是为了处理 T 是占位符的情形. 若 T 不是占位符, 则该元函数原样返回其实参 const T&.

namespace boost {
namespace type_erasure {
template<class C, class T, class Base>
struct concept_interface<has_push_back<C, T>, Base, C> : Base
{
    void push_back(typename as_param<Base, const T&>::type arg)
    { call(has_push_back<C, T>(), *this, arg); }
};
}
}

这样, 我们的示例变成

std::vector<int> vec;
any<has_push_back<_self, int>, _self&> c(vec);
c.push_back(10);

这正是我们想要的.

重载

(本节示例的源代码见 overload.cpp)

concept_interface 允许我们向 any 注入任意声明. 这非常灵活, 但有一些需要当心的陷阱. 有时我们想把同一个概念以不同参数使用多次. 以能正确处理重载的方式特化 concept_interface 有点棘手. 给定概念 foo, 我们希望下面的代码能工作:

any<
    mpl::vector<
        foo<_self, int>,
        foo<_self, double>,
        copy_constructible<>
    >
> x = ...;
x.foo(1);   // calls foo(int)
x.foo(1.0); // calls foo(double)

由于 concept_interface 创建的是线性继承链, 若不做一些额外工作, foo 的一个重载会遮蔽另一个.

以下是我发现可以可靠工作的技术.

对于成员函数, 我找不到避免使用两个特化的办法.

template<class T, class U>
struct foo
{
    static void apply(T& t, const U& u) { t.foo(u); }
};

namespace boost {
namespace type_erasure {

template<class T, class U, class Base, class Enable>
struct concept_interface< ::foo<T, U>, Base, T, Enable> : Base
{
    typedef void _fun_defined;
    void foo(typename as_param<Base, const U&>::type arg)
    {
        call(::foo<T, U>(), *this, arg);
    }
};

template<class T, class U, class Base>
struct concept_interface< ::foo<T, U>, Base, T, typename Base::_fun_defined> : Base
{
    using Base::foo;
    void foo(typename as_param<Base, const U&>::type arg)
    {
        call(::foo<T, U>(), *this, arg);
    }
};

}
}

这里使用 SFINAE 来检测是否需要 using 声明. 注意 concept_interface 的第四个实参是一个哑参数, 它总是 void, 专用于 SFINAE. 过去我用过的另一种解法是注入一个 fun 的哑声明, 并总是加入 using 声明. 由于几个原因, 这个解法较差: 它需要一个额外的接口来添加哑重载; 它还意味着 fun 总是被重载, 即使用户只要一个重载; 这使得获取 fun 的地址变得更难.

注意, 虽然使用 SFINAE 需要重复一些代码, 但必须重复的代码量相对较小, 因为 concept_interface 的实现通常只有一行. 这有点烦人, 但我认为在缺乏更好解法的情况下, 这是可以接受的代价.

对于自由函数, 你可以使用内联友元 (inline friend).

template<class T, class U>
struct bar_concept
{
    static void apply(T& t, const U& u) { bar(t, u); }
};

namespace boost {
namespace type_erasure {

template<class T, class U, class Base>
struct concept_interface< ::bar_concept<T, U>, Base, T> : Base
{
    friend void bar(typename derived<Base>::type& t, typename as_param<Base, const U&>::type u)
    {
        call(::bar_concept<T, U>(), t, u);
    }
};

template<class T, class U, class Base>
struct concept_interface< ::bar_concept<T, U>, Base, U, typename boost::disable_if<is_placeholder<T> >::type> : Base
{
    using Base::bar;
    friend void bar(T& t, const typename derived<Base>::type& u)
    {
        call(::bar_concept<T, U>(), t, u);
    }
};

}
}

基本上, 我们必须对每个实参各特化一次 concept_interface, 以确保重载被注入到第一个作为占位符的实参中. 你可能已经注意到, 实参类型有点棘手. 在第一个特化中, 第一个实参使用 derived 而不是 as_param. 原因在于, 如果使用 as_param, 就可能因定义两次同一个函数而违反单一定义规则 (ODR). 类似地, 我们在第二个特化中使用 SFINAE, 以确保当两个实参都是占位符时 bar 只被定义一次. 通过一点元编程可以把两个特化合并起来, 但除非实参很多, 否则可能不值得.

概念映射 (Concept Maps)

(本节示例的源代码见 concept_map.cpp)

有时, 以非侵入方式让一个类型适配某个概念会很有用. 例如, 假设我们想让 std::type_info 满足 less_than_comparable 概念. 为此, 只需特化该概念定义即可.

namespace boost {
namespace type_erasure {

template<>
struct less_than_comparable<std::type_info>
{
    static bool apply(const std::type_info& lhs, const std::type_info& rhs)
    { return lhs.before(rhs) != 0; }
};

}
}

注释

大部分 (但并非全部) 内建概念都可以被特化. 构造函数、析构函数和 RTTI 需要本库的特殊处理, 不能被特化. 只有原始概念 (primitive concept) 可以被特化, 因此迭代器概念也不行.

关联类型

(本节示例的源代码见 associated.cpp)

诸如 typename T::value_type 或 typename std::iterator_traits<T>::reference 之类的关联类型 (associated type) 在模板编程中相当常见. Boost.TypeErasure 使用 deduced 模板来处理它们. deduced 与普通的 placeholder 类似, 区别在于它所绑定的类型由调用一个元函数确定, 无需显式指定.

例如, 我们可以如下定义一个概念, 用于持有迭代器、裸指针或智能指针. 首先, 我们定义一个名为 pointee 的元函数来给出关联类型.

template<class T>
struct pointee
{
    typedef typename mpl::eval_if<is_placeholder<T>,
        mpl::identity<void>,
        boost::pointee<T>
    >::type type;
};

注意, 我们不能直接使用 boost::pointee, 因为这个元函数必须能安全地以占位符实例化. 只要它不报错, 返回什么并不重要. (本库从不尝试以占位符实例化它, 但实参依赖查找可能导致虚假的实例化.)

template<class T = _self>
struct pointer :
    mpl::vector<
        copy_constructible<T>,
        dereferenceable<deduced<pointee<T> >&, T>
    >
{
    // provide a typedef for convenience
    typedef deduced<pointee<T> > element_type;
};

现在, x 的概念使用两个占位符 _self 和 pointer<>::element_type. 当我们构造 x 并传入一个 int* 时, pointer<>::element_type 被推导为 pointee<int*>::type, 即 int. 这样, 解引用 x 会返回一个 any, 它包含一个 int.

int i = 10;
any<
    mpl::vector<
        pointer<>,
        typeid_<pointer<>::element_type>
    >
> x(&i);
int j = any_cast<int>(*x); // j == i

有时我们要求关联类型必须是特定类型. 这可以用 same_type 概念解决. 这里我们创建一个 any, 它可以持有元素类型为 int 的任意指针.

int i = 10;
any<
    mpl::vector<
        pointer<>,
        same_type<pointer<>::element_type, int>
    >
> x(&i);
std::cout << *x << std::endl; // prints 10

像这样使用 same_type, 实际上是让本库把 pointer<>::element_type 的所有使用替换为 int, 并验证它始终绑定到 int. 这样, 解引用 x 现在返回的是一个 int.

same_type 也可以用于两个占位符. 这让我们可以用一个简单的名字来代替反复写出某个关联类型.

int i = 10;
any<
    mpl::vector<
        pointer<>,
        same_type<pointer<>::element_type, _a>,
        typeid_<_a>,
        copy_constructible<_a>,
        addable<_a>,
        ostreamable<std::ostream, _a>
    >
> x(&i);
std::cout << (*x + *x) << std::endl; // prints 20
