设计理由

为什么必须显式指明析构函数的存在?

使用引用时不需要析构函数. 通过不隐式假定它, 我们允许以引用方式捕获带有 private 或 protected 析构函数的类型. 为保持一致, 按值捕获时也必须显式指明.

为什么是非成员函数?

any 的成员可以被定制. 通过使用自由函数, 我们保证不会干扰用户可能想要的任何东西.

为什么占位符叫 _a、_b 而不是 _1 _2

本库的早期版本使用名字 _1、_2 等, 而不是 _a、_b 等. 这造成了一定的混淆, 因为编号占位符已被其他若干库以略有不同的含义使用, 包括 Boost/Std Bind、Boost.Phoenix 和 Boost.MPL. 我最终决定, 由于这些占位符代表的是命名参数而不是位置参数, 字母比数字更合适.

为什么引用不用 boost::ref?

Boost.Function 允许你使用 boost::ref 来存储对函数对象的引用. 然而, 在一般情况下, 以相同方式对待引用和值会导致难以推断的不一致行为. 如果 Boost.TypeErasure 像这样处理引用, 那么当你复制一个 any 时, 你将无从得知新对象是真正的副本, 还是指向同一底层对象的新引用. Boost.Function 能侥幸这么做, 是因为它不暴露任何对所存函数对象的修改性操作.

另一种被提出的方法是只在第一次保存引用.

int i = 2;
any x = ref(i);
any y = x; // makes a copy

遗憾的是, 这无法处理所有用例, 因为没有可靠的办法从函数返回这样的引用. 此外, 无论是否需要它都会增加开销, 因为我们必须在 any 中加一个标志来跟踪它是否在存储引用. (把这一信息存进 vtable 中 "clone" 方法的替代做法, 鉴于 Boost.TypeErasure 所使用的解耦 vtable, 实现起来复杂得不可思议, 而且仍会增加开销.)
