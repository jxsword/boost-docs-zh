构造

(本节示例的源代码见 construction.cpp)

本库提供 constructible 概念, 允许 any 捕获构造函数. 其唯一的模板参数应当是一个函数签名. 返回类型必须是一个占位符 (placeholder), 指定要构造的类型. 参数即为构造函数的参数.

typedef mpl::vector<
    copy_constructible<_a>,
    copy_constructible<_b>,
    copy_constructible<_c>,
    constructible<_a(const _b&, const _c&)>
> construct;

typedef mpl::map<
    mpl::pair<_a, std::vector<double> >,
    mpl::pair<_b, std::size_t>,
    mpl::pair<_c, double>
> types;

any<construct, _b> size(std::size_t(10), make_binding<types>());
any<construct, _c> val(2.5, make_binding<types>());
any<construct, _a> v(size, val);
// v holds std::vector<double>(10, 2.5);

那么, 如果我们想要默认构造函数怎么办? 我们不能让 any 的默认构造函数去调用所含类型的默认构造函数, 因为它无从得知所含类型是什么. 因此, 我们需要显式传入占位符的绑定信息.

typedef mpl::vector<
    copy_constructible<>,
    constructible<_self()>
> construct;

any<construct> x(std::string("Test"));
any<construct> y(binding_of(x)); // y == ""

这一方法并不限于默认构造函数. 如果构造函数接受参数, 可以在绑定信息之后传入.

typedef mpl::vector<
    copy_constructible<>,
    constructible<_self(std::size_t, char)>
> construct;

any<construct> x(std::string("Test"));
any<construct> y(binding_of(x), 5, 'A');

转换

(本节示例的源代码见 convert.cpp)

只要该转换是一次"向上转换 (upcast)", 一个 any 就可以转换为另一个 any.

typedef any<
    mpl::vector<
        copy_constructible<>,
        typeid_<>,
        ostreamable<>
    >
> any_printable;
typedef any<
    mpl::vector<
        copy_constructible<>,
        typeid_<>
    >
> common_any;
any_printable x(10);
common_any y(x);

这一转换是合法的, 因为 common_any 的要求是 any_printable 要求的子集. 反方向的转换则是非法的.

common_any x(10);
any_printable y(x); // error

参考文献

(本节示例的源代码见 references.cpp)

要以引用方式捕获, 只需向 placeholder 添加一个引用即可.

int i;
any<typeid_<>, _self&> x(i);
any_cast<int&>(x) = 5; // now i is 5

注释

_self 是默认的 placeholder, 因此使用 _self& 最为简单. 我们也可以改用另一个 placeholder. any<typeid_<_a>, _a&> 的行为与之完全相同.

引用不能被重新绑定. 与 C++ 内建引用一样, 一旦初始化, 就不能再让它指向别的东西.

int i, j;
any<typeid_<>, _self&> x(i), y(j);
x = y; // error

注释

与其他操作一样, 针对引用的 x = y 作用于 i 与 j. 若 assignable<> 位于概念 (Concept) 之中, 这样的赋值是合法的, 但 x 仍将持有指向 i 的引用.

引用可以绑定到另一个 any.

typedef mpl::vector<
    copy_constructible<>,
    incrementable<>
> requirements;

any<requirements> x(10);
any<requirements, _self&> y(x);
++y; // x is now 11

若在底层对象离开作用域或被重置之后使用引用, 其行为是未定义的.

typedef mpl::vector<
    copy_constructible<>,
    incrementable<>,
    relaxed
> requirements;
any<requirements> x(10);
any<requirements, _self&> y(x);
x = 1.0;
++y; // undefined behavior.

这仅适用于引用从值构造的情形. 若引用从另一个引用构造, 新引用并不依赖于旧引用.

any<requirements> x(10);
boost::shared_ptr<any<requirements, _self&> > p(
    new any<requirements, _self&>(x));
any<requirements, _self&> y(*p); // equivalent to y(x);
p.reset();
++y; // okay

const 与非 const 引用都受支持.

int i = 0;
any<incrementable<>, _self&> x(i);
any<incrementable<>, const _self&> y(x);

非 const 引用可以转换为 const 引用, 但反之不行. 当然, 我们不能对 const 引用应用修改性的操作.

any<incrementable<>, _self&> z(y); // error
++y; // error

语法限制

在大多数情况下, 使用 any 的语法与使用底层对象的语法相同. 然而, 有少数情形无法实现这一点. any 引用是一个代理 (proxy), 不能用于需要真正引用的场合. 特别地, forward_iterator 并不构成一个合规的 ForwardIterator (除非 value_type 是固定的). 另一个区别是, 所有不接受至少一个 any 实参的操作都必须显式传入类型信息. 静态成员函数和构造函数可能属于这一类. 所有这些意味着, 将泛型算法应用于 any 实参时可能无法工作.
