本节描述如何在特定情况下使用本库.

非常规语法

有时, 标准的命令行语法并不够用. 例如, gcc 编译器有 "-frtti" 和 "-fno-rtti" 选项, 这种语法就没有被直接支持.

对这类情形, 本库允许用户提供一个 附加解析器 -- 一个会在每个命令行元素上被调用的函数, 调用发生在库进行任何处理之前. 如果附加解析器识别了该语法, 就返回选项名和选项值, 二者将被直接使用. 上面的示例可用以下代码处理:

pair<string, string> reg_foo(const string& s)
{
    if (s.find("-f") == 0) {
        if (s.substr(2, 3) == "no-")
            return make_pair(s.substr(5), string("false"));
        else
            return make_pair(s.substr(2), string("true"));
    } else {
        return make_pair(string(), string());
    }
}

下面是附加解析器的定义. 解析命令行时, 我们传入该附加解析器:

store(command_line_parser(ac, av).options(desc).extra_parser(reg_foo)
        .run(), vm);

完整示例见 "example/custom_syntax.cpp" 文件.

响应文件

某些操作系统对命令行长度的限制非常低. 绕过这些限制的常用方法是使用 响应文件. 响应文件就是一个配置文件, 其语法与命令行相同. 如果命令行中指定了要使用的响应文件的名称, 该文件就会在命令行之外被加载并解析. 本库不直接支持响应文件, 因此你需要额外编写一些代码.

首先, 你需要为响应文件定义一个选项:

("response-file", value<string>(),
     "can be specified with '@name', too")

其次, 你需要一个附加解析器来支持指定响应文件的标准语法 "@file":

pair<string, string> at_option_parser(string const&s)
{
    if ('@' == s[0])
        return std::make_pair(string("response-file"), s.substr(1));
    else
        return pair<string, string>();
}

最后, 当发现 "response-file" 选项时, 你必须加载该文件并将其传给命令行解析器. 这是最难的部分. 我们将使用 Boost.Tokenizer 库, 它可以用, 但有一些局限. 你也可以考虑 Boost.StringAlgo. 代码如下:

if (vm.count("response-file")) {
     // Load the file and tokenize it
     ifstream ifs(vm["response-file"].as<string>().c_str());
     if (!ifs) {
         cout << "Could not open the response file\n";
         return 1;
     }
     // Read the whole file into a string
     stringstream ss;
     ss << ifs.rdbuf();
     // Split the file content
     char_separator<char> sep(" \n\r");
     std::string ResponsefileContents( ss.str() );
     tokenizer<char_separator<char> > tok(ResponsefileContents, sep);
     vector<string> args;
     copy(tok.begin(), tok.end(), back_inserter(args));
     // Parse the file and store the options
     store(command_line_parser(args).options(desc).run(), vm);
}

完整示例见 "example/response_file.cpp" 文件.

Winmain 命令行

在 Windows 操作系统上, GUI 应用程序收到的命令行是一个单一字符串, 并未拆分成元素. 因此, 命令行解析器无法直接使用. 至少在某些编译器上可以取得拆分后的命令行, 但并不清楚是否所有编译器在操作系统的所有版本上都支持相同的机制. split_winmain 函数是本库提供的一种可移植机制.

下面是一个使用示例:

vector<string> args = split_winmain(lpCmdLine);
store(command_line_parser(args).options(desc).run(), vm);

split_winmain 函数针对 wchar_t 字符串进行了重载, 因此也可以用于 Unicode 应用.

选项组与隐藏选项

让一个 options_description 类实例包含程序的全部选项可能带来问题:

  • 某些选项只对特定来源才有意义, 例如配置文件.

  • 用户希望生成的帮助消息具有某种结构.

  • 某些选项根本不应出现在生成的帮助消息中.

为解决上述问题, 本库允许程序员创建多个 options_description 类实例, 并以不同的组合加以合并. 下面的示例将定义三组选项: 一组专用于命令行, 另两组面向特定的程序模块, 后两者中只有一组会显示在生成的帮助消息中.

每组选项都用标准语法定义. 不过, 你应当为每个 options_description 实例取合理的名称:

options_description general("General options");
general.add_options()
    ("help", "produce a help message")
    ("help-module", value<string>(),
        "produce a help for a given module")
    ("version", "output the version number")
    ;

options_description gui("GUI options");
gui.add_options()
    ("display", value<string>(), "display to use")
    ;

options_description backend("Backend options");
backend.add_options()
    ("num-threads", value<int>(), "the initial number of threads")
    ;

声明选项组之后, 我们将它们按两种组合合并. 第一种包含全部选项, 用于解析. 第二种用于 "--help" 选项.

// Declare an options description instance which will include
// all the options
options_description all("Allowed options");
all.add(general).add(gui).add(backend);

// Declare an options description instance which will be shown
// to the user
options_description visible("Allowed options");
visible.add(general).add(gui);

剩下的就是解析并处理这些选项:

variables_map vm;
store(parse_command_line(ac, av, all), vm);

if (vm.count("help"))
{
    cout << visible;
    return 0;
}
if (vm.count("help-module")) {
    const string& s = vm["help-module"].as<string>();
    if (s == "gui") {
        cout << gui;
    } else if (s == "backend") {
        cout << backend;
    } else {
        cout << "Unknown module '"
             << s << "' in the --help-module option\n";
        return 1;
    }
    return 0;
}
if (vm.count("num-threads")) {
    cout << "The 'num-threads' options was set to "
         << vm["num-threads"].as<int>() << "\n";
}

解析命令行时, 所有选项都是允许的. 但 "--help" 消息中不包含 "Backend options" 组 -- 该组中的选项是隐藏的. 用户可以通过传入 "--help-module backend" 选项来显式强制显示该选项组. 完整示例见 "example/option_groups.cpp" 文件.

自定义校验器

默认情况下, 选项值从字符串到 C++ 类型的转换是用 iostreams 完成的, 这有时并不方便. 本库允许用户针对特定的类定制该转换. 为此, 用户应提供 validate 函数的适当重载.

我们先定义一个简单的类:

struct magic_number {
public:
    magic_number(int n) : n(n) {}
    int n;
};

然后重载 validate 函数:

void validate(boost::any& v,
              const std::vector<std::string>& values,
              magic_number* target_type, int)
{
    static regex r("\\d\\d\\d-(\\d\\d\\d)");

    using namespace boost::program_options;

    // Make sure no previous assignment to 'a' was made.
    validators::check_first_occurrence(v);
    // Extract the first string from 'values'. If there is more than
    // one string, it's an error, and exception will be thrown.
    const string& s = validators::get_single_string(values);

    // Do regex match and convert the interesting part to
    // int.
    smatch match;
    if (regex_match(s, match, r)) {
        v = any(magic_number(lexical_cast<int>(match[1])));
    } else {
        throw validation_error(validation_error::invalid_option_value);
    }
}

该函数接受四个参数. 第一个是值的存储, 在本例中它要么为空, 要么包含一个 magic_number 类的实例. 第二个是该选项下一次出现时所找到的字符串列表. 其余两个参数则用于绕过某些编译器缺少偏特化和函数模板偏序支持的问题.

该函数首先检查不会对同一选项赋值两次. 然后检查传入的是否只有一个字符串. 接着借助 Boost.Regex 库校验该字符串. 若校验通过, 解析出的值便存入 v 变量.

完整示例见 "example/regex.cpp" 文件.

Unicode 支持

要把本库与 Unicode 一起使用, 你需要:

  • 对 Unicode 输入使用支持 Unicode 的解析器

  • 为需要 Unicode 支持的选项要求 Unicode 支持

多数解析器都有 Unicode 版本. 例如, parse_command_line 函数有一个接受 wchar_t 字符串 (而非普通 char 字符串) 的重载.

即便某些解析器支持 Unicode, 也并不意味着你需要修改所有选项的定义. 事实上, 对许多选项 (比如整数选项) 来说, 这样做毫无意义. 要利用 Unicode, 你需要 一些 支持 Unicode 的选项. 它们与普通选项的不同之处在于: 接受 wstring 输入, 并用宽字符流进行处理. 创建支持 Unicode 的选项很容易: 只需用 wvalue 函数代替普通的 value 即可.

当 ascii 解析器把数据传给 ascii 选项, 或 Unicode 解析器把数据传给 Unicode 选项时, 数据完全不会改变. 因此, ascii 选项看到的将是本地 8 位编码的字符串, 而 Unicode 选项看到的则是作为 Unicode 输入传入的那个字符串.

当 Unicode 数据被传给 ascii 选项, 或者相反时, 会发生什么? 本库会自动执行从 Unicode 到本地 8 位编码的转换. 例如, 若命令行是 ascii 编码, 而你使用 wstring 选项, 那么 ascii 输入将被转换为 Unicode.

为执行这一转换, 本库使用全局 locale 中的 codecvt<wchar_t, char> locale facet. 如果你想处理使用本地 8 位编码 (而非 7 位 ascii 子集) 的字符串, 应用程序应以如下代码开头:

locale::global(locale(""));

这会根据用户选择的 locale 来设置转换 facet.

不过, 明智的做法是检查你所用的实现中 C++ locale 支持的状况. 快速测试包含三个步骤:

  1. 进入 "test" 目录并构建 "test_convert" 可执行文件.

  2. 在环境中设置某个非 ascii 的 locale. 在 Linux 上, 例如可以运行:

    $ export LC_CTYPE=ru_RU.KOI8-R

  3. 以选定的编码中任意一个非 ascii 字符串作为参数运行 "test_convert" 可执行文件. 如果看到一列 Unicode 码点, 就说明一切正常. 否则, 你系统上的 locale 支持可能已损坏.

允许未知选项

通常, 遇到未知选项名时本库会抛出异常. 这一行为可以改变. 例如, 你的应用程序中只有一部分使用 Program_options, 而你希望把无法识别的选项传递给程序的其他部分, 甚至传递给另一个应用程序.

要允许命令行中出现未注册的选项, 你需要用 basic_command_line_parser 类来解析 (而不是 parse_command_line), 并调用该类的 allow_unregistered 方法:

parsed_options parsed =
    command_line_parser(argc, argv).options(desc).allow_unregistered().run();

对每个看起来像选项但名称未知的记号, 结果中都会加入一个 basic_option 实例. 该实例的 string_key 和 value 字段将包含对该记号进行句法解析的结果, unregistered 字段将被设为 true, 而 original_tokens 字段将包含该记号在命令行上的原始形式.

如果想把无法识别的选项继续传递下去, 可以使用 collect_unrecognized 函数. 该函数会为所有未识别的值收集原始记号, 并且可选地收集所有找到的位置选项. 比如说, 如果你的代码只处理少数几个选项, 而完全不处理位置选项, 就可以这样使用该函数:

vector<string> to_pass_further = collect_unrecognized(parsed.options, include_positional);

测试选项是否存在

到目前为止, 我们一直使用 count 方法来测试 variables_map 类上的某个选项是否已被设置; 由于要重复书写选项的 (字符串字面量) 名称, 这种方式容易出现拼写错误, 以及在一处重命名了选项而另一处未重命名所导致的错误:

po::options_description desc("Allowed options");
desc.add_options()
    ("compression", po::value<int>(), "set compression level")
;

po::variables_map vm;
po::store(po::parse_command_line(ac, av, desc), vm);
po::notify(vm);

if (vm.count("compression")) {
    cout << "Compression level was set to "
 << vm["compression"].as<int>() << ".\n";
} else {
    cout << "Compression level was not set.\n";
}

作为替代, 你可以使用 boost::optional 类型的变量; Program_options 为 Boost.Optional 提供了特殊支持, 使得当用户指定该选项时, boost::optional 变量会被初始化为相应的值:

po::options_description desc("Allowed options");
boost::optional<int> compression;
desc.add_options()
    ("compression", po::value(&compression), "set compression level")
;

po::variables_map vm;
po::store(po::parse_command_line(ac, av, desc), vm);
po::notify(vm);

if (compression) {
    cout << "Compression level was set to " << *compression << ".\n";
} else {
    cout << "Compression level was not set.\n";
}
