Getting Boost.Chrono

Boost.Chrono 位于最新 Boost 发布版的文件夹 /boost/chrono. 文档、测试与示例文件夹位于 boost/libs/chrono/.

你也可以从 Boost trunk 的 boost/chrono 和 libs/chrono 目录访问最新 (可能不稳定) 状态. 只需前往 here 并按那里的说明进行匿名 SVN 访问.

Where to install Boost.Chrono?

最简单的方式是把文件解压 (或从 SVN 检出) 到你的 BOOST_ROOT 目录.

Building Boost.Chrono

Boost.Chrono 可以通过定义 BOOST_CHRONO_HEADER_ONLY. 然而 Boost.Chrono 依赖非仅头文件的 Boost.System 库, 因此你需要链接 boost_system.

Boost.System 有一个未公开的特性 (使用宏 BOOST_ERROR_CODE_HEADER_ONLY) 可使其成为仅头文件.

If BOOST_CHRONO_HEADER_ONLY 未定义时, 使用前需要编译并构建该库, 例如:

bjam libs/chrono/build

Exception safety

只要底层实参提供相应保证, 库中的所有函数都是异常中性的, 并提供强异常安全保证.

Thread safety

除非明确指出, 库中的所有函数都不是线程安全的.

由于 Boost.Chrono 不使用可变全局变量, 线程安全分析仅限于对各实例变量的访问. 若一个函数会修改对某个用户变量的访问, 而另一个线程可能正在读取或写入它, 则使用该函数不是线程安全的.

duration 是本库的核心. 用户日常使用中看到的接口与 Jeff Garland 编写的 Boost.DateTime 时间 duration 库几乎完全相同, 语法与行为皆然. 这个 boost 库 7 年来一直非常流行, 该接口有着极好的历史记录.

本库由六个时间单位 duration 组成:

  • hours
  • minutes
  • seconds
  • milliseconds
  • microseconds
  • nanoseconds

选择这些单位作为 boost 库的子集, 是因为它们是睡眠、等待条件变量或等待获取互斥量锁时最常用的单位. 每个单位不过是对一个有符号整数计数的薄封装. 也就是说, 构造 minutes(3) 时, 所做的不过是把一个 3 存入 minutes. 当你构造 microseconds(3) 时, 所做的不过是把一个 3 存入 microseconds.

这些不同类型仅在相互转换时才有区别. 此时会使用单位特定的编译期转换常量把源单位转换为目标单位. (Boost 中) 只允许从粗单位到细单位的转换. 这一限制确保所有转换始终精确. 也就是说, microseconds 总能表示 minutes 的任何值.

在 Boost.DateTime 中, 这些单位通过继承联合在一起. Boost.Chrono 则通过类模板 duration. 也就是说, 在 Boost.Chrono 中, 上述六个单位不过是 duration. 与 Boost.DateTime 相比, 这一改变有着深远而积极的影响, 同时完全没有改变日常使用的语法.

最直接的好处是: 库可以立即生成所需的任何单位、任何精度. 在不同 duration 之间做比较或运算时 (假设希望比较与运算精确), 有时这是必要的.

另一个好处是: 通过公开类模板 duration 接口, 用户代码可以非常容易地创建 duration. 工具 ratio 用于指定精度, 只要精度能表示为相对于秒的有理常数, 该框架就能精确表示它 (三分之一秒没有问题, 三分之一个 femto 秒也没有问题). 所有这些实用性与灵活性, 只需使用零运行期开销的 ratio 设施即可免费获得.

在 Boost.DateTime 中, hours 与 nanoseconds 的表示不同. 前者通常用 long 表示, 而后者需要 long long. 原因很简单: 范围. 覆盖极大的时间范围并不需要很多小时. 但纳秒不是这样. 在可能时减小某些单位的 sizeof 开销, 可以带来显著的性能优势.

Boost.Chrono 延续并推广了这一理念. 不仅可以指定 duration 的精度, 还可以指定其表示. 它可以是任何整型, 甚至浮点类型; 也可以是模拟算术类型的用户自定义类型. 六个预定义单位都使用有符号整型作为其表示, 且其最小范围均为 ±292 年. nanoseconds 需要 64 位来覆盖该范围. hours 只需 23 位即可覆盖该范围.

那么, duration 到底是什么, 又该如何使用?

duration 具有一个表示和一个刻度周期 (精度).

template <class Rep, class Period = ratio<1> > class duration;

表示可以是任何算术类型或其模拟. 表示存储刻度 (tick) 计数. 这个计数是 duration 中唯一的数据成员. 若表示是浮点型, 它能以表示的精度存储刻度的小数部分. 刻度周期由 ratio 表示, 并被编码进 duration 的类型而非存储. 只有当试图在不同 duration 之间转换时, 刻度周期才会影响 duration 的行为. 而在同类 duration 之间做算术运算时, 刻度周期被完全忽略.

示例: 

typedef boost::chrono::duration<long, boost::ratio<60> > minutes;
minutes m1(3);                 // m1 stores 3
minutes m2(2);                 // m2 stores 2
minutes m3 = m1 + m2;          // m3 stores 5

typedef boost::chrono::duration<long long, boost::micro> microseconds;
microseconds us1(3);           // us1 stores 3
microseconds us2(2);           // us2 stores 2
microseconds us3 = us1 + us2;  // us3 stores 5

microseconds us4 = m3 + us3;   // us4 stores 300000005

在上面代码的最后一行, 有一个从 minutes 到 microseconds 的隐式转换, 结果得到一个相对较大的微秒数.

若需要访问 duration, 有一个成员 count(), 它只是返回存储的刻度计数.

long long tc = us4.count();    // tc is 300000005

这些 duration 的行为非常简单、非常可预测、非常可观察. 毕竟, 这其实就是 Jeff 的 boost 时间 duration 库久经考验的接口 (用模板而非继承统一实现).

如果我把 m3 + us3 to minutes 而不是 microseconds? 
minutes m4 = m3 + us3;

无法编译! 其理由是: 不应允许隐式截断误差发生. 若这样能编译, 那么 m4 将保存 5, 与 m3 相同的值. 与 us3 关联的值实际上被忽略了. 这类似于把 double 赋给 int 的问题: 小数部分被悄悄丢弃.

但如果截断行为正是我想要的呢?

有一个 duration_cast 设施可显式要求这种行为:

minutes m4 = boost::chrono::duration_cast<minutes>(m3 + us3);  // m4.count() == 5

一般来说, 可以随意进行 duration 运算. 若未使用 duration_cast 且代码能编译, 则运算是精确的. 若想覆盖这种精确运算行为, 可使用 duration_cast 来明确表达这一意愿. duration_cast 与隐式转换具有相同的效率, 并且只要可能就同样是精确的.

你可以使用 duration_cast<> 把 duration 转换成你想要的任何单位. 若无法精确转换, 该设施将向下舍入 (截断). 例如:

boost::chrono::nanoseconds start;
boost::chrono::nanoseconds end;
typedef boost::chrono::milliseconds ms;
ms d = boost::chrono::duration_cast<ms>(end - start);

// d now holds the number of milliseconds from start to end.

std::cout << d.count() << "ms\n";

我们可以先转换为 nanoseconds, 或某种基于整数的时长 (nanoseconds 总能精确转换到它), 那么 duration_cast<> 就不必要了:

typedef boost::chrono::nanoseconds ns;
ns d = end - start;
std::cout << ns.count() << "ns\n";

如果你需要带浮点表示的秒, 也可以省去 duration_cast<>:

typedef boost::chrono::duration<double> sec;  // seconds, stored with a double
sec d = end - start;
std::cout << sec.count() << "s\n";

如果不确定是否需要 duration_cast<>, 大可先不用试试. 若转换是精确的, 或目标具有浮点表示, 代码就能编译; 否则不能编译.

如果需要使用 duration_cast<>, 但想在转换不精确时向上而不是向下舍入, 下面是一个实现该功能的小巧实用的辅助函数. 编写它其实是理解 Boost.Chrono:

template <class ToDuration, class Rep, class Period>
ToDuration
round_up(boost::chrono::duration<Rep, Period> d)
{
    // first round down
    ToDuration result = boost::chrono::duration_cast<ToDuration>(d);
    if (result < d)  // comparisons are *always* exact
       ++result;     // increment by one tick period
    return result;
}

typedef boost::chrono::milliseconds ms;
ms d = round_up<ms>(end - start);
// d now holds the number of milliseconds from start to end, rounded up.
std::cout << d.count() << "ms\n";
Rounding functions

Boost.Chrono 为处理时长提供了几个简单的舍入工具函数.

// round down
template <class To, class Rep, class Period>
To
floor(const duration<Rep, Period>& d)
{
    return duration_cast<To>(d);
}

// round to nearest, to even on tie
template <class To, class Rep, class Period>
To
round(const duration<Rep, Period>& d)
{
    To t0 = duration_cast<To>(d);
    To t1 = t0;
    ++t1;
    BOOST_AUTO(diff0, d - t0);
    BOOST_AUTO(diff1, t1 - d);
    if (diff0 == diff1)
    {
        if (t0.count() & 1)
            return t1;
        return t0;
    }
    else if (diff0 < diff1)
        return t0;
    return t1;
}
// round up
template <class To, class Rep, class Period>
To
ceil(const duration<Rep, Period>& d)
{
    To t = duration_cast<To>(d);
    if (t < d)
        ++t;
    return t;
}

chrono 库的美妙之处在于这类转换既容易又精确. 例如, 要把 milliseconds (1/1000 秒) 转换为 1/30 秒, 必须把毫秒乘以 0.03. 众所周知, 计算机无法精确表示 0.03. 尽管如此, 发生平局时, round 仍能精确 (无舍入误差) 地检测出来并舍入到偶数. 差值 diff0 与 diff1 不是近似值, 而是精确的差值, 即使 d 的单位是毫秒而 To 是 1/30 秒也一样. diff0 与 diff1 是 1/3000 秒, 毫秒与 1/30 秒都能精确转换到它 (无截断误差).

类似地, 在 t < d 中进行比较 ceil 是精确的, 即使 t 与 d 与之没有精确转换. 舍入函数使用示例

#include <iostream>
#include <boost/chrono/chrono_io.hpp>
#include <boost/chrono/floor.hpp>
#include <boost/chrono/round.hpp>
#include <boost/chrono/ceil.hpp>

int main()
{
    using namespace boost::chrono;
    milliseconds ms(2500);
    std::cout << floor<seconds>(ms) << '\n';
    std::cout << round<seconds>(ms) << '\n';
    std::cout << ceil<seconds>(ms) << '\n';
    ms = milliseconds(2516);
    typedef duration<long, boost::ratio<1, 30> > frame_rate;
    std::cout << floor<frame_rate>(ms) << '\n';
    std::cout << round<frame_rate>(ms) << '\n';
    std::cout << ceil<frame_rate>(ms) << '\n';

    return 0;
}

2 seconds
2 seconds
3 seconds
75 [1/30]seconds
75 [1/30]seconds
76 [1/30]seconds
Trafficking in floating-point Durations

我不想到处写 duration_cast. 我对浮点表示的精度已经满意.

没问题. 当转换的目标具有浮点表示时, 所有转换都允许隐式发生.

typedef boost::chrono::duration<double, ratio<60> > dminutes;
dminutes dm4 = m3 + us3;  // dm4.count() == 5.000000083333333
这一切的代价有多大?

即使手写这些转换, 也不可能比它更高效. 使用 ratio 可确保所有转换常量在编译期尽可能化简. 这通常使转换因子的分子或分母化简为 1, 从而在转换刻度计数的运行期值时被忽略.

构建一个接受 duration 参数的函数有多复杂?

用户有以下几种选择:

  • 如果函数作者想接受任何 duration, 并愿意在浮点 duration 上工作, 他只需用任何浮点 duration 作为参数:
void f(boost::chrono::duration<double> d)  // accept floating-point seconds
{
    // d.count() == 3.e-6 when passed boost::chrono::microseconds(3)
}

f(boost::chrono::microseconds(3));
  • 如果函数作者只想使用整数 duration 为单位, 且满足于处理不低于纳秒的粒度 (仅举一例), 他可以简单地指定 nanoseconds 作为参数:
void f(boost::chrono::nanoseconds d)
{
    // d.count() == 3000 when passed boost::chrono::microseconds(3)
}

f(boost::chrono::microseconds(3));

在这种设计中, 若客户端想传入浮点 duration, or a duration, 那么客户端要自行负责在转换到纳秒时选择舍入模式.

boost::chrono::duration<double> s(1./3);  // 1/3 of a second
f(boost::chrono::duration_cast<boost::chrono::nanoseconds>(s));  // round towards zero in conversion to nanoseconds

在上面的例子中, f 的客户端选择了 "向零舍入" 作为转换到纳秒的期望舍入模式. 如果客户端的 duration 无法精确转换为纳秒, 又没有指定转换方式, 编译器将拒绝该调用:

f(s);  // does not compile
  • 如果函数作者想接受任何 duration, 但想使用整数表示并在内部控制舍入模式, 那么他可以把函数模板化:
template <class Rep, class Period>
void f(boost::chrono::duration<Rep, Period> d)
{
    // convert d to nanoseconds, rounding up if it is not an exact conversion
    boost::chrono::nanoseconds ns = boost::chrono::duration_cast<boost::chrono::nanoseconds>(d);
    if (ns < d)
        ++ns;
    // ns.count() == 333333334 when passed 1/3 of a floating-point second
}

  f(boost::chrono::duration<double>(1./3));
  • 如果示例中的作者不想接受基于浮点的 duration, 他可以这样强制该行为:
template <class Period>
void f(boost::chrono::duration<long long, Period> d)
{
    // convert d to nanoseconds, rounding up if it is not an exact conversion
    boost::chrono::nanoseconds ns = boost::chrono::duration_cast<nanoseconds>(d);
    if (ns < d)
        ++ns;
    // ns.count() == 333333334 when passed 333333333333 picoseconds
}
// About 1/3 of a second worth of picoseconds
f(boost::chrono::duration<long long, boost::pico>(333333333333));

持有浮点 duration 的客户端若想使用 f, 现在必须先自行转换成整数 duration, 再把结果传给 f.

总而言之, f 的作者在向客户端提供的接口方面有相当大的灵活性与控制力, 并有简单的办法在函数内部操纵 duration.

用户能否把 duration 传给一个单位不明确的函数?

不能. 无论上面 f 的作者选择哪种方案, 以下客户端代码都无法编译:f无法编译:

Can Durations Overflow?

这取决于表示. 默认 typedef 使用的表示不处理溢出. 用户可以定义自己的表示, 按应用程序的需要管理溢出.

Clocks

虽然 duration 只需关心精度和表示, 时钟与 time_point 却彼此密切相关、相互引用. 因为时钟更容易解释, 我们先讲时钟, 暂不完整解释 time_point. 介绍完时钟之后, 再回头说明 time_point 是什么会更容易.

时钟概念捆绑了三样东西:

  1. 一个具体的 duration 类型.
  2. 一个具体的 time_point 类型.
  3. 一个名为 now() 的函数, 返回具体的 time_point.

标准定义了三个与计算机时间关联的系统级时钟.

  • system_clock 表示系统级实时时钟, 可与外部时钟同步.
  • steady_clock 不能显式更改, 且自初始历元起的时间以平稳方式增加.
  • high_resolution_clock 打算使用平台提供的分辨率最高的系统级时钟.

Boost.Chrono 在底层平台支持时提供它们. 给定平台可能无法提供全部三种时钟.

本库还增加了一些进程或线程专用的时钟, 即每个进程或每个线程一个时钟.

用户还可以轻松创建更多时钟.

给定一个名为 Clock 的时钟, 它将具有:

class Clock {
public:
    typedef an arithmetic-like type        rep;
    typedef an instantiation of ratio      period;
    typedef boost::chrono::duration<rep, period> duration;
    typedef boost::chrono::time_point<Clock>     time_point;
    static constexpr bool is_steady =      true or false;

    static time_point now();
};

可以用如下方式从 Clock 获取当前时间:

Clock::time_point t1 = Clock::now();

而且可以用如下方式获取与 Clock 关联的两个 duration 之间的时长 time_point (均关联于 Clock) 之间的时长:

Clock::duration d = Clock::now() - t1;

而且可以用如下方式指定过去或未来的 time_point:

Clock::time_point t2 = Clock::now() + d;

注意, 即使某个具体时钟过时了, 接替它的下一个时钟也有相同的 API, 不需要新的学习曲线. 源代码的改动只是换一下时钟的类型. 随着新时钟的引入, 同一套 duration 与 time_point 框架继续工作. 同一个程序中也可以安全而轻松地处理多个时钟.

Time Point

那么, time_point 到底是什么, 又该如何使用?

A time_point 表示时间中的一个点, 与一段 duration 不同. 换一种说法: time_point 表示一个历元加/减一个 duration. 这样的例子包括:time_point

  • 计算机启动后 3 分钟.
  • 2038 年 1 月 19 日星期二 03:14:07 UTC
  • 我启动那个计时器后 20 毫秒.

在上面每个例子中, 都隐含着不同的历元. 有时一个历元数千年都有意义; 有时历元的含义过了一段时间就消失了 (例如计时器的启动时刻, 或计算机的启动时刻). 不过, 若已知两个 time_point 共享同一历元, 就可以对它们做减法, 得到有效的 duration, 即使历元的定义已不再有意义.

在 Boost.Chrono 中, 历元是一个纯抽象且未指明的概念. 没有任何类型表示历元. 它只是一个把 time_point (或不) 关联到某个时钟的概念; 若共享同一时钟, 则还把 time_points to one another. time_point 一般不可互操作, 除非已知各时钟所关联历元之间的关系.

那么, time_point 到底是什么, 又该如何使用?

A time_point 具有一个时钟和一个 duration.

template <class Clock, class Duration = typename Clock::duration> class time_point;

time_point 的时钟不会被存储. 它只是嵌入 time_point 的类型中, 并有两个用途:

  1. 因为源自不同时钟的 time_point 类型不同, 编译器可以被指示在不兼容的 time_point 以不当方式使用时报错.
  2. 给定一个 time_point, 常常需要把它与 "现在" 比较. 只要 time_point 知道自己是相对于哪个时钟定义的, 这就非常简单. time_point

A time_point's duration 被存储为 time_point. 因此 time_point 与其对应的 duration 具有完全相同的布局, 但含义迥异. 例如, 说 "我想睡 3 分钟" 是一回事; 说 "我要睡到那个计时器启动后 3 分钟的时刻" (除非你恰好现在启动了计时器) 则完全是另一回事. 在睡眠、等待条件变量和等待互斥量锁等常见用例中, 这两种含义 (以及睡眠选项) 都有很大的实用价值. Ada 等语言中也能找到这些相同的概念与工具.

一个计时器示例:

void f()
{
    boost::chrono::steady_clock::time_point start = boost::chrono::steady_clock::now();
    g();
    h();
    duration<double> sec = boost::chrono::steady_clock::now() - start;
    cout << "f() took " << sec.count() << " seconds\n";
}

注意, 若使用两个时钟 duration 之间的 time_point (其精度有影响) 时, 最好把时钟的 duration 转换为已知的 duration. 这可以使代码免受未来时钟精度变化的影响. 例如 duration. 这可以使代码免受时钟精度的未来变化影响. 例如 steady_clock

一个延迟循环示例:

// delay for at least 500 nanoseconds:
auto go = boost::chrono::steady_clock::now() + boost::chrono::nanoseconds(500);
while (boost::chrono::steady_clock::now() < go)
    ;

无论 steady_clock 的精度如何, 上述代码都会尽可能精确地延迟约半微秒. steady_clock 越精确, 对 500 纳秒的延迟就越准确.

#include <boost/chrono/chrono_io.hpp>
#include <sstream>
#include <cassert>

int main()
{

    istringstream in("5000 milliseconds 4000 ms 3001 ms");
    boost::chrono::seconds d(0);
    in >> d;
    assert(in.good());
    assert(d == seconds(5));
    in >> d;
    assert(in.good());
    assert(d == seconds(4));
    in >> d;
    assert(in.fail());
    assert(d == seconds(4));

    return 0;
}

在模板化代码中, 有时难以知道时长的单位是什么. 虽然一切都是确定的、可检查的, 但这样做可能很不方便, 尤其是只需要打印一条 "调试" 语句时. 例如:

// round to nearest, to even on tie
template <class To, class Rep, class Period>
To
round(const duration<Rep, Period>& d)
{
    To t0 = duration_cast<To>(d);
    To t1 = t0;
    ++t1;
    auto diff0 = d - t0;
    cout << "diff0 = " << diff0 << '\n';
    auto diff1 = t1 - d;
    cout << "diff1 = " << diff1 << '\n';
    if (diff0 == diff1)
    {
        if (t0.count() & 1)
            return t1;
        return t0;
    }
    else if (diff0 < diff1)
        return t0;
    return t1;
}

这正是时长 I/O 大显身手之处. 编译器知道 diff0 的类型, 依照本提案, 该类型 (带正确的单位) 会自动打印出来. 例如:

milliseconds ms = round<milliseconds>(nanoseconds(123));  // diff0 = 123 nanoseconds
                                                          // diff1 = 999877 nanoseconds
milliseconds ms = round<milliseconds>(Ticks(44));         // diff0 = 2 [1/3000]seconds
                                                          // diff1 = 1 [1/3000]second

这个简单的 I/O 将使时长对程序员友好得多.

system_clock::time_point

system_clock 很特别. 它是唯一一个在其 time_point 与 time_t 之间有转换的时钟. C 随后把 time_t 与 Gregorian calendar 关联起来, 途径是 ctime, gmtime, localtime、strftime. C 与 POSIX 都没有把 time_t 关联到任何其他历法. C 与 POSIX 都没有把 Gregorian calendar. ISO 8601 仅就格里高利历而言进行规定. Gregorian calendar.

Boost.Chrono 提供 system_clock::time_point I/O, 仅基于格里高利历. 不过由于 system_clock::time_point 仍可与 time_t 相互转换, 客户端可以创建其他能与 time_t 互操作, 进而与 system_clock::time_point.

此外, 所有主流宿主操作系统的既有实践都是以便于显示为 Coordinated Universal Time (UTC) 的格式存储系统时间. 因此 Boost.Chrono 规定 system_clock::time_point 的默认输出采用相对于 UTC 表示时间点的格式.

cout << system_clock::now() << '\n';

可能输出

2011-09-15 18:36:59.325132 +0000

此格式深受 ISO 8601 影响, 但在日期与时间之间放置 ' ' 而不是 'T'. 前者似乎更准确地反映既有实践. 选择全数字格式是为了让尽可能多的人能看懂; 选择 24 小时制也是出于同样的原因.

在被引用的标准中, 只有 ISO 8601 讨论了小数秒的输出. C 与 POSIX 都没有内置这项功能. 不过就本文撰写之时而言, system_clock::period 低于一秒似乎是普遍情况. 而且, 如果把 system_clock::time_point, 却能再流输入并得到相同的值, 应该是合理的. 因此小数秒的流输出 (至少默认情况下) 似乎是不可避免的.

最后, 末尾的 " +0000" 把按 UTC 格式化的 system_clock::time_point 与按计算机本地时区格式化的版本区分开来. 后者很容易做到:

cout << time_fmt(local) << system_clock::now() << '\n';

其结果可能为

2011-09-15 14:36:59.325132 -0400

注意, system_clock::time_point 本身既不是 UTC 也不是本地时间. 但在实践中, system_clock::time_point 是超出某个与 UTC 同步的历元的刻度计数. 因此, 当移动设备跨越时区时, 时区切换不会影响 system_clock::time_point 产生的 system_clock::now() 的值. 只有在为人类阅读而格式化时, 才可以选择 UTC 或本地时区. C 与 POSIX 对待 time_t 的方式与 Boost.Chrono 对待 system_clock::time_point:

tm* gmtime(const time_t* timer) -> UTC
tm* localtime(const time_t* timer) -> local time

本提案只是把 C/POSIX 的 time_t 功能扩展到 C++ 语法与 system_clock::time_point.

The time_fmt() 操纵器是 "粘性" 的. 它会一直生效, 直到流析构或被更改. 可以用以下方式把流重置为默认状态:

cout << time_fmt(utc);

还可以用时间格式序列进一步定制格式. 例如:

cout << time_fmt(local, "%A %B %e, %Y %r");
cout << system_clock::now() << '\n';  // Sunday April 24, 2011 02:36:59 PM

为宽流指定格式化操纵器时, 使用宽字符串.

同样可以在输入流上使用这些操纵器来指定解析序列.

遗憾的是, 目前没有表示小数秒的格式化/解析序列. Boost.Chrono 未提供此类序列. 目前, 要为 system_clock::time_point 格式化并解析小数秒, 可以使用默认格式, 或在 time_fmt().

流的当前 locale 可能影响提供给 system_clock::time_point 操纵器的解析/格式化序列 (例如星期几的名称、月份名称).

如何覆盖时长的默认构造函数

接下来演示如何覆盖 duration 的默认构造函数, 让它做你想做的任何事 (本例中设为零). 我们要做的只是更改表示:

namespace I_dont_like_the_default_duration_behavior {

template <class R>
class zero_default
{
public:
    typedef R rep;

private:
    rep rep_;
public:
    zero_default(rep i = 0) : rep_(i) {}
    operator rep() const {return rep_;}

    zero_default& operator+=(zero_default x) {rep_ += x.rep_; return *this;}
    zero_default& operator-=(zero_default x) {rep_ -= x.rep_; return *this;}
    zero_default& operator*=(zero_default x) {rep_ *= x.rep_; return *this;}
    zero_default& operator/=(zero_default x) {rep_ /= x.rep_; return *this;}

    zero_default  operator+ () const {return *this;}
    zero_default  operator- () const {return zero_default(-rep_);}
    zero_default& operator++()       {++rep_; return *this;}
    zero_default  operator++(int)    {return zero_default(rep_++);}
    zero_default& operator--()       {--rep_; return *this;}
    zero_default  operator--(int)    {return zero_default(rep_--);}

    friend zero_default operator+(zero_default x, zero_default y) {return x += y;}
    friend zero_default operator-(zero_default x, zero_default y) {return x -= y;}
    friend zero_default operator*(zero_default x, zero_default y) {return x *= y;}
    friend zero_default operator/(zero_default x, zero_default y) {return x /= y;}

    friend bool operator==(zero_default x, zero_default y) {return x.rep_ == y.rep_;}
    friend bool operator!=(zero_default x, zero_default y) {return !(x == y);}
    friend bool operator< (zero_default x, zero_default y) {return x.rep_ < y.rep_;}
    friend bool operator<=(zero_default x, zero_default y) {return !(y < x);}
    friend bool operator> (zero_default x, zero_default y) {return y < x;}
    friend bool operator>=(zero_default x, zero_default y) {return !(x < y);}
};

typedef boost::chrono::duration<zero_default<long long>, boost::nano        > nanoseconds;
typedef boost::chrono::duration<zero_default<long long>, boost::micro       > microseconds;
typedef boost::chrono::duration<zero_default<long long>, boost::milli       > milliseconds;
typedef boost::chrono::duration<zero_default<long long>                      > seconds;
typedef boost::chrono::duration<zero_default<long long>, boost::ratio<60>   > minutes;
typedef boost::chrono::duration<zero_default<long long>, boost::ratio<3600> > hours;
}

周期计数

用户可以轻松创建自己的时钟, 其时间点与时长都具有自选的表示和精度. 例如, 若有一个硬件计数器随 CPU 每个周期递增一次计数, 只需几十行代码就可以在其上轻松构建时钟、时间点和时长. 这样的系统可用于调用时间敏感的线程 API, 如 sleep、等待条件变量或等待互斥量锁. 本文提出的 API 不区分这是 300MHz 时钟 (刻度周期 3 1/3 纳秒) 还是 3GHz 时钟 (刻度周期 1/3 纳秒). 而且得到的代码与用户专门编写的周期计数器一样高效.

#include <boost/chrono.hpp>
#include <boost/type_traits.hpp>
#include <iostream>

template <long long speed>
struct cycle_count
{
    typedef typename boost::__ratio_multiply__<boost::ratio<speed>, boost::mega>::type
        frequency;  // Mhz
    typedef typename boost::__ratio_divide__<boost::ratio<1>, frequency>::type period;
    typedef long long rep;
    typedef boost::chrono::duration<rep, period> duration;
    typedef boost::chrono::time_point<cycle_count> time_point;

    static time_point now()
    {
        static long long tick = 0;
        // return exact cycle count
        return time_point(duration(++tick));  // fake access to clock cycle count
    }
};

template <long long speed>
struct approx_cycle_count
{
    static const long long frequency = speed * 1000000;  // MHz
    typedef nanoseconds duration;
    typedef duration::rep rep;
    typedef duration::period period;
    static const long long nanosec_per_sec = period::den;
    typedef boost::chrono::time_point<approx_cycle_count> time_point;

    static time_point now()
    {
        static long long tick = 0;
        // return cycle count as an approximate number of nanoseconds
        // compute as if nanoseconds is only duration in the std::lib
        return time_point(duration(++tick * nanosec_per_sec / frequency));
    }
};

class xtime {
private:
    long tv_sec;
    long tv_usec;

    void fixup() {
        if (tv_usec < 0) {
            tv_usec += 1000000;
            --tv_sec;
        }
    }

public:
    explicit xtime(long sec, long usec) {
        tv_sec = sec;
        tv_usec = usec;
        if (tv_usec < 0 || tv_usec >= 1000000) {
            tv_sec += tv_usec / 1000000;
            tv_usec %= 1000000;
            fixup();
        }
    }

    explicit xtime(long long usec) {
        tv_usec = static_cast<long>(usec % 1000000);
        tv_sec  = static_cast<long>(usec / 1000000);
        fixup();
    }

    // explicit
    operator long long() const {return static_cast<long long>(tv_sec) * 1000000 + tv_usec;}

    xtime& operator += (xtime rhs) {
        tv_sec += rhs.tv_sec;
        tv_usec += rhs.tv_usec;
        if (tv_usec >= 1000000) {
            tv_usec -= 1000000;
            ++tv_sec;
        }
        return *this;
    }

    xtime& operator -= (xtime rhs) {
        tv_sec -= rhs.tv_sec;
        tv_usec -= rhs.tv_usec;
        fixup();
        return *this;
    }

    xtime& operator %= (xtime rhs) {
        long long t = tv_sec * 1000000 + tv_usec;
        long long r = rhs.tv_sec * 1000000 + rhs.tv_usec;
        t %= r;
        tv_sec = static_cast<long>(t / 1000000);
        tv_usec = static_cast<long>(t % 1000000);
        fixup();
        return *this;
    }

    friend xtime operator+(xtime x, xtime y) {return x += y;}
    friend xtime operator-(xtime x, xtime y) {return x -= y;}
    friend xtime operator%(xtime x, xtime y) {return x %= y;}

    friend bool operator==(xtime x, xtime y)
        { return (x.tv_sec == y.tv_sec && x.tv_usec == y.tv_usec); }

    friend bool operator<(xtime x, xtime y) {
        if (x.tv_sec == y.tv_sec)
            return (x.tv_usec < y.tv_usec);
        return (x.tv_sec < y.tv_sec);
    }

    friend bool operator!=(xtime x, xtime y) { return !(x == y); }
    friend bool operator> (xtime x, xtime y) { return y < x; }
    friend bool operator<=(xtime x, xtime y) { return !(y < x); }
    friend bool operator>=(xtime x, xtime y) { return !(x < y); }

    friend std::ostream& operator<<(std::ostream& os, xtime x)
        {return os << '{' << x.tv_sec << ',' << x.tv_usec << '}';}
};

  • ss.cc 是 seconds 四舍五入到最接近的百分之一秒的

    2. include <ostream>
    3. include <iostream> 
// format duration as [-]d/hh::mm::ss.cc
template <class CharT, class Traits, class Rep, class Period>
std::basic_ostream<CharT, Traits>&
display(std::basic_ostream<CharT, Traits>& os,
        boost::chrono::duration<Rep, Period> d)
{
    using namespace std;
    using namespace boost;

    typedef boost::chrono::duration<long long, boost::ratio<86400> > days;
    typedef boost::chrono::duration<long long, boost:centi> centiseconds;

    // if negative, print negative sign and negate
    if (d < boost::chrono::duration<Rep, Period>(0))
    {
        d = -d;
        os << '-';
    }
    // round d to nearest centiseconds, to even on tie
    centiseconds cs = boost::chrono::duration_cast<centiseconds>(d);
    if (d - cs > boost::chrono::milliseconds(5)
        || (d - cs == boost::chrono::milliseconds(5) && cs.count() & 1))
        ++cs;
    // separate seconds from centiseconds
    boost::chrono::seconds s = boost::chrono::duration_cast<boost::chrono::seconds>(cs);
    cs -= s;
    // separate minutes from seconds
    boost::chrono::minutes m = boost::chrono::duration_cast<boost::chrono::minutes>(s);
    s -= m;
    // separate hours from minutes
    boost::chrono::hours h = boost::chrono::duration_cast<boost::chrono::hours>(m);
    m -= h;
    // separate days from hours
    days dy = boost::chrono::duration_cast<days>(h);
    h -= dy;
    // print d/hh:mm:ss.cc
    os << dy.count() << '/';
    if (h < boost::chrono::hours(10))
        os << '0';
    os << h.count() << ':';
    if (m < boost::chrono::minutes(10))
        os << '0';
    os << m.count() << ':';
    if (s < boost::chrono::seconds(10))
        os << '0';
    os << s.count() << '.';
    if (cs < boost::chrono::centiseconds(10))
        os << '0';
    os << cs.count();
    return os;
}
