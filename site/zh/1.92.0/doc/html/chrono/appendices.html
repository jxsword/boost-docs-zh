附录: 设计理由

参见 N2661 - A Foundation to Sleep On, 该文信息量很大, 并为关键设计决策提供了动机. 本节包含该文档的部分摘录.

时长为何需要 operator%

该运算符便于计算给定时位于某一时间框架中的位置. 一个典型例子是把时长转换为分解式 (broken-down) 时间时长, 如 hours::minutes::seconds:

class ClockTime
{
    typedef boost::chrono::hours hours;
    typedef boost::chrono::minutes minutes;
    typedef boost::chrono::seconds seconds;
public:
    hours hours_;
    minutes minutes_;
    seconds seconds_;

    template <class Rep, class Period>
      explicit ClockTime(const boost::chrono::duration<Rep, Period>& d)
        : hours_  (boost::chrono::duration_cast<hours>  (d)),
          minutes_(boost::chrono::duration_cast<minutes>(d % hours(1))),
          seconds_(boost::chrono::duration_cast<seconds>(d % minutes(1)))
          {}
};

附录: 常见问题 (FAQ)

为什么 process_cpu_clock 有时给出的 CPU 秒数多于实际秒数?

请询问您的操作系统供应商. 我们已用调试器检查过结果, 在 Windows 和 Linux 上, 操作系统有时报告的就是这种结果.

时长运算中的整数溢出会被检测并报告吗?

Boost.Ratio 避免一切可由算术运算产生并可化简的溢出. typedef 时长不检测溢出. 你需要能处理溢出的时长表示 (rep).

基准测试应使用哪些时钟?

每种时钟各有特点. 这取决于你要测量什么. 多数情况下, 线程时钟可能更合意; 若要测量受同步影响的代码, 进程时钟更好. 若应用是多进程的, 则可能需要全系统时钟.

监视应使用哪些时钟?

用于追踪 (trace) 目的, 最好使用全系统时钟.
