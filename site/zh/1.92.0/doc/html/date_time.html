动机

本库的动机来自在多个项目中使用并协助构建多个日期时间库的经历. 日期时间库为大多数开发项目提供基础基础设施. 然而, 大多数库在计算、格式化、转换或执行其他功能的能力方面都有局限. 例如, 大多数库不能正确处理闰秒, 不提供无穷 (infinity) 之类的概念, 也不提供使用高分辨率或网络时间源的能力. 这些库在日期和时间的表示上也往往过于僵化, 因此无法为项目或子项目定制策略.

使用日期和时间进行编程应当几乎像使用字符串和整数一样简单自然. 拥有一组健壮的运算符和计算能力, 可以从根本上简化包含大量时间逻辑的应用程序. 类应提供比较日期和时间、加上长度或时间长短、从时钟获取日期和时间, 以及自然地处理日期时间区间的能力.

开发本库的另一个动机是把现代 C++ 库设计技术应用到日期时间领域, 确切地说, 是构建一个用于构造时间类型的框架, 例如通过提供迭代器和特征 (traits) 类来控制库的基本性质. 据作者所知, 本库是把现代 C++ 实质性应用于日期时间库的唯一尝试.

领域概念

日期时间领域术语繁多, 问题复杂. 下面简要介绍一些你会在本库中看到其反映的概念.

本库支持 3 种基本的时间类型:

  • 时间点 (Time Point) -- 时间连续体中某个位置的指称.
  • 时间长短 (Time Duration) -- 不依附于时间连续体上任何点的一段时间长度.
  • 时间区间 (Time Interval) -- 依附于时间连续体上某个特定点的一段时间长短. 也称为时间段 (time period).

每种时间类型都有一个 分辨率 (Resolution), 由最小可表示的时间长短定义. 时间系统 (Time system) 提供所有这些类别的时间类型, 以及标记时间点和进行时间计算的规则. 历法系统 (Calendar Systems) 就是最大分辨率为一天的时间系统. 格里高利历 (Gregorian) 是当今使用最广泛的历法系统 (ISO 系统基本上是它的衍生). 当然还有许多其他历法系统. UTC (协调世界时) 是广泛使用的民用时间系统. UTC 通过闰秒在经度 0 处针对地球自转进行调整 (这是不可预测的, 只在必要时进行). 大多数 本地时间 系统基于 UTC, 但也会针对地球自转进行调整, 使得白昼时间在各地大致相似. 此外, 一些本地时间还包含 夏令时 (DST) 调整, 用于在夏季改变白昼时间.

时钟设备 (Clock Device) 是一种软件组件 (与某种硬件绑定), 它相对于某个时间系统提供当前日期或时间. 时钟可以按已知分辨率测量当前时间, 该分辨率可能高于或低于某个特定的时间表示.

本库提供对日期和时间计算的支持. 然而, 时间计算与整数计算并不完全相同. 如果你认真对待时间计算的准确性, 就需要阅读 稳定性、可预测性与近似.

设计概念

本库的产生在很大程度上源于这样一个观察: 很少有日期时间库以允许定制和扩展的方式构建. 一个典型例子是, 历法逻辑直接内置在日期类中, 或者时钟获取函数直接内置在时间类中. 这些设计决策通常使扩展或更改库行为变得不可能. 在更基本的层面上, 通常还存在关于时间表示分辨率或格里高利历的假设.

通常结果是, 由于对高分辨率时间表示的要求或其他与库实现不匹配的假设, 项目只能退而求其次, 接受一个不完善的库. 这是极其不幸的, 因为开发这类库绝非小事.

虽然设计远非完美, 但当前设计比作者所知的任何日期时间库都灵活得多. 预计在未来的版本中, 可扩展性的各个方面会得到更好的文档说明. 关于库设计目标的信息 在此概述.
