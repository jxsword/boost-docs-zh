字符串表示

顾名思义, 本库主要用于字符串. 不过, 在本库的语境中, 字符串不限于任何特定实现 (如 std::basic_string), 而是一个概念. 这使得本库中的算法可复用于任何满足给定要求的字符串类型.

定义: 字符串是按顺序有序方式访问的字符 范围. 字符是任何具有"廉价"复制与赋值的值类型.

字符串类型的第一项要求是必须可以通过 Boost.Range 访问. 该设施允许以统一的基于迭代器的方式访问字符串内部的元素. 这对本库而言已经足够

第二项要求定义了字符在字符串中的存储方式. 本库中的算法基于这样一个假设: 复制一个字符比分配额外存储来缓存结果更便宜. 对常见的字符类型而言这是自然的假设. 即使该要求不满足, 算法仍能工作, 但代价是性能下降.

此外, 某些算法对字符串类型有额外要求. 特别是, 要求算法能够创建给定类型的新字符串. 此时要求该类型满足序列 (Std §23.1.1) 要求.

在参考文档和代码中, 对字符串类型的要求以模板实参的名称来指代. RangeT 表示必须满足基本范围要求. SequenceT 表示扩展的序列要求.

序列特征

std::list 与 std::vector 的主要差别不在于它们提供的接口, 而在于类的内部细节及其执行各种操作的方式. 问题在于, 若没有某种特殊机制, 就无法从类的定义推断出这种差别. 然而, 了解特定容器的性质后, 某些算法可以显著加速运行.

序列特征 (sequence traits) 允许为序列容器指定附加性质 (见 Std.§32.2). 算法随后利用这些性质为某些操作选择优化处理方式. 序列特征声明在头文件 boost/algorithm/string/sequence_traits.hpp 中.

表 2.12. 序列特征

特征 说明
has_native_replace<C>::value 指定该序列具有类似 std::string 的 replace 方法
has_stable_iterators<C>::value 指定该序列具有稳定迭代器. 意思是 insert/erase/replace 之类的操作不会使迭代器失效.
has_const_time_insert<C>::value 指定该序列的 insert 方法具有常数时间复杂度.
has_const_time_erase<C>::value 指定该序列的 erase 方法具有常数时间复杂度

当前实现针对标准库的 std::list<T> 与 std::basic_string<T>, 以及 SGI 的 std::rope<T> 与 std::slist<T> 提供了特化.

查找算法

查找算法与 std::search() 算法功能相似, 但提供了一个更适合常见字符串操作的接口. 它们返回的不是一个匹配子序列的起始位置, 而是一个范围 - 当匹配子序列的长度事先未知时, 这是必需的. 该特性还允许把输入序列划分为三部分: 前缀、子串和后缀.

另一个差别是增加了 find_first 之外的多种搜索方法, 包括 find_regex.

在本库中, 查找算法以 Finder 为基础实现. 其他设施 (replace、split) 也使用 Finder. 为方便起见, 还为这些查找器提供了函数包装, 以简化查找操作.

目前本库只提供查找算法的朴素实现, 复杂度为 O(n * m), 其中 n 是输入序列的大小, m 是搜索序列的大小. 也存在复杂度为 O(n) 的算法, 但对较短的序列而言, 其常数开销相当大. 对于较小的 m << n (m 比 n 小一个数量级), 当前实现提供了可接受的效率. 甚至 C++ 标准也将搜索算法的必备复杂度定义为 O(n * m). 库的未来版本有可能把线性复杂度的算法作为可选项纳入

替换算法

替换算法的实现遵循库的分层结构. 底层实现输入序列中某个范围的泛型替换. 该层以一个 Finder 对象和一个 Formatter 对象作为输入. 这两个函数对象定义了替换什么以及用什么替换. 上层的函数只是对底层调用的包装. 查找器与 find 和 split 设施共享.

与往常一样, 底层的实现设计为可处理泛型序列, 同时在可能时利用特定特性 (通过使用 序列特征)

查找迭代器与拆分算法

查找迭代器是 find 设施 在逻辑上的延伸. 它不再只搜索一个匹配, 而是对整个输入进行迭代式搜索以找出多个匹配. 搜索结果随后用于划分输入. 哪些部分作为结果返回取决于算法: 可以是匹配的部分 (find_iterator), 也可以是介于其间的部分 (split_iterator).

此外, 诸如 find_all() 与 split() 这样的拆分算法可以简化常见操作. 它们使用查找迭代器搜索整个输入, 并把找到的匹配复制到提供的容器中.

异常安全性

本库要求, 用作模板或函数参数的类型上的所有操作都提供 基本异常安全保证. 反过来, 本库中的所有函数和算法, 除特别说明外, 都将提供 基本异常安全保证. 换言之: 面对异常时, 库会维持其不变式且不泄漏资源. 某些库操作提供更强的保证, 并逐个加以说明.

某些函数可以提供 强异常安全保证. 这意味着以下陈述成立:

  • 若抛出异常, 除该函数自身产生的效果外没有其他效果
  • 若异常并非由该函数抛出, 则没有任何效果

这一保证的提供条件是: 用作这些函数参数的类型上的操作要么提供强异常保证, 要么不改变全局状态.

在参考文档中, 术语 强异常安全保证 指的是上文定义的保证.
