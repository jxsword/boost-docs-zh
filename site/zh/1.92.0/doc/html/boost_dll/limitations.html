某些平台和编译器不能提供构建功能完整的 Boost.DLL 所需的全部功能. 本节列出了这些编译器, 并给出针对这些限制的可能的变通办法.

导出弱符号 (在 MinGW, Android 上失败)

Android 的某些版本以及 Windows 平台上的 MinGW 与 ld 无法混用 __dllexport__ 与 weak 属性. 这导致我们必须显式指明实例化 BOOST_DLL_ALIAS 的翻译单元, 使所有其他带该别名的 BOOST_DLL_ALIAS 声明成为 extern 变量.

必须持有 BOOST_DLL_ALIAS 实例的翻译单元, 在包含任何 Boost.DLL 库头文件之前必须定义 BOOST_DLL_FORCE_ALIAS_INSTANTIATION.

可以使用 BOOST_DLL_FORCE_NO_WEAK_EXPORTS 显式禁用弱符号导出. 这对绕过链接器问题, 或测试程序与不支持导出弱符号的链接器的兼容性会有帮助.

用户定义的节名 (在 SunOS + Oracle Solaris Studio 编译器上失败)

某些平台会忽略节属性, 因此使用 boost::dll::library_info 查询指定节中的符号可能一无所获.

线程安全的库加载 (在 FreeBSD, MacOS, iOS 及其他一些平台上失败)

在某些平台上, dlopen, dlclose 及其他一些函数假定不会被并发调用.

确定存在该问题的平台有 FreeBSD, MacOS, iOS.

确定不存在此类问题的平台有 Windows, Linux+glibc, Android, QNX.

其他平台尚存疑问. 如果你使用的平台不在列表中 (例如 Linux+busybox), 可以运行 shared_library_concurrent_load_test 测试来检测该问题:

cd boost_folder/libs/dll/test
../../../b2 -a shared_library_concurrent_load_test

嵌套函数定义

如果函数定义在类定义内部, 它可能被解释为总是内联 (always-inline), 从而导致该函数根本不被导出. 不过, 各编译器在这方面有所不同.
