常见问题 (F.A.Q.)

  • 问: Boost.DLL 是线程安全的吗?
    • 答: 某些平台允许并发调用 dlopen 一类的函数. 对这些平台而言, Boost.DLL 的安全性与其他所有 C++ 标准库容器一致: 即使所有实例加载的是同一个库, 不同线程使用 shared_library 的不同实例也是安全的. 在其他平台上, 并发调用 Boost.DLL 的任何函数都不安全 (即使一次 shared_library::location() 调用也会触发竞态条件). 参见 Limitations, Thread safe library loading.


  • 
          问: 在 Linux 上为什么一个插件的符号会在另一个插件中可见? 无法从正确的插件取得同名符号! 
    • 
                答: 你遇到了符号遮蔽 (symbol shadowing) 问题. 请用 "-fvisibility=hidden" 标志编译插件, 并阅读 Tutorial 一节.
    
        




  • 
          问: (Windows 的) Unicode 是如何处理的? 
    • 
                答: Boost.DLL 支持 Unicode, 因此可以向它提供 Unicode 路径.
    
        




  • 
          问: 可以打开可执行文件吗? 
    • 
                答: 可以. 符号需要使用 BOOST_SYMBOL_EXPORT 或 BOOST_DLL_ALIAS 在可执行文件中导出. 你可以调用 shared_library(program_location()) 来加载自身. 更多信息参见 Tutorial 一节. 你也可以查询可执行文件, 只需把可执行文件的路径提供给 library_info 类.
    
        




  • 
          问: 如果我在 shared_library::get<T> 或 import<T> 中指定了错误的类型会怎样? 
    • 
                答: 通常结果会是 Segmentation Fault. 不过, 让类型更严格是安全的, 例如把 const int 用于某个 int 不会有问题.
    
        




  • 
          问: 你们的库保证方法的 ABI 稳定性吗? 
    • 
                答: 库只保证用 BOOST_DLL_ALIAS 宏创建的别名名称不会随编译器或平台的改变而改变. 函数的 ABI 与 API 稳定性需要你自己负责.
    
        




  • 
          问: 对导出/导入的函数有任何函数签名限制吗? 
    • 
                答: 不能. 你可以导入/导出具有任意签名和任意返回参数的函数.
    
        




  • 
          问: 我有 2 个插件使用同一个共享库. 该共享库会被加载两次吗? 
    • 
                答: 不会. 插件将共享同一个共享库实例.
    
        




  • 
          问: 我有 2 个插件, 每个都必须使用自己版本的 libsome_library 共享库. 如何做到? 
    • 
                答: 通过把 libsome_library 静态链接进每个插件, 并用 load_mode::rtld_deepbind 加载插件来避免这种情况.
    
        




  • 
          问: 有 RTLD_NODELETE 模式吗? 有内置的办法跳过卸载或"泄漏"动态加载的库吗? 
    • 
                答: 不提供. Boost 力求支持最佳实践, 而泄漏资源不在其列. 如果你动态加载的第三方库无法卸载, 可以尝试: 
      std::vector<boost::dll::shared_library>& late_unload_registry() {
    static std::vector<boost::dll::shared_library> registry;
    return registry;
}

       并把该库推入那个注册表 late_unload_registry().emplace_back(third_party_shared_library). 这将强制该库在程序结束前不卸载.
    
        


如果上面的 late_unload_registry() 不起作用 - 请向该库的供应商寻求动态加载/卸载方面的支持.




  • 
          问: 如何从内存加载共享对象?? 
    • 
                答: 现有的操作系统都避免直接从用户空间内存加载共享库, 因此你找不到针对这种情况的系统调用. 目前 Boost.DLL 没有提供真正从内存加载共享对象的手段. 这需要为所有平台在用户空间重新实现动态链接器逻辑, 工作量巨大且极易出错. 不过, 可用的补丁是受欢迎的!
    
        


变通办法是把插件写入 RAM 中的临时文件, 再从该文件加载插件:


#include <boost/filesystem.hpp>
#include <boost/dll.hpp>
using namespace boost;

dll:shared_library load_from_memory(unsigned char* data, std::size_t size, const filesystem::path& tmp_plugin_path = filesystem::unique_path() / "libplugin.so") {
    const filesystem::path plugin_location = filesystem::temp_directory_path() / tmp_plugin_path;
    filesystem::create_directories(plugin_location.parent_path());
    filesystem::ofstream ofs(plugin_location, std::ios::out|std::ios::bin|std::ios::trunc);
    ofs.write(data, size);

    return dll::shared_library(plugin_location);
}




    


但无法保证 filesystem::temp_directory_path() 真的写入 RAM, 这非常依赖平台.
