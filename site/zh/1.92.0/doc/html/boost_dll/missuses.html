误用

警告

本节收录典型的错误与误用情形. 请仔细阅读, 这会节省大量调试时间!

  • 问题: 程序在 delete 或 free() 时崩溃.
  • 解决: 插件与程序必须使用相同的 C++ 标准库和 C 库, 且两者都必须动态链接. 对 Visual Studio, 请使用 /MD 或 /MDd 编译器开关.


    

  • 
          问题: 程序在 catch(...) 块中崩溃.
    • 

  • 
          示例:

    try {
    auto f = dll::import<int()>(path_to_pugin, "function");
    f();
    // `f` goes out of scope
} catch (const std::exception& e) {
    std::cerr << e.what();
}

    
        
    • 

  • 
          解决: 异常在插件内部生成, 因此它引用插件中的异常代码. 当 f 离开作用域时, 插件被卸载, 对异常代码的引用随之失效. 任何使用该异常变量的尝试都可能用到悬空引用, 导致段错误. 请修正代码: 
    auto f = dll::import<int()>(path_to_pugin, "function");
try {
    f();
    // `f` goes out of scope
} catch (const std::exception& e) {
    std::cerr << e.what();
}

    
        
    • 





    

  • 
          问题: 线程本地存储 (TLS) 似乎损坏了.
    • 

  • 
          解决: 某些平台对使用 TLS 的插件没有开箱即用的支持, 例如 Windows. 请使用平台特定的变通办法, 或干脆在插件中不使用 TLS.
    • 





    

  • 
          问题: 调用已加载的函数时崩溃, 或函数返回错误结果.
    • 

  • 
          解决: Boost.DLL 不保证 ABI 稳定性. 如果你用不同编译器或不同编译开关编译插件与程序, 函数的 ABI 可能发生变化, 最终得到错误的代码.
    • 





    

  • 
          问题: 插件卸载后程序崩溃.
    • 

  • 
          示例:

    void foo() {
    shared_ptr<int> p;
    try {
        auto f = dll::import<shared_ptr<int>()>(path_to_pugin, "function");
        p = f();
        // `f` goes out of scope
    } catch (const std::exception& e) {
        std::cerr << e.what();
    }
    std::cout << *p;
    // crashes here
}

    
        
    • 

  • 
          解决: 在那个具体的例子中, 问题出在 shared_ptr<int>. 它持有一个类型擦除的删除器, 该删除器的代码位于插件中. 当 p 析构时, shared_ptr<int> 试图调用该删除器, 但插件已被卸载, 删除器的代码已不可用.
    • 

  • 
          经验法则:: 如果插件方法返回任何 C++ 类变量, 请确保在该变量及其所有副本仍在作用域内时插件保持加载状态.
