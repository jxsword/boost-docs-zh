性能

理论上, 与手写循环相比, 使用 STL 算法和 lambda 仿函数的所有开销都可以像标准 STL 函数对象和 binder 的开销一样被优化掉. 取决于编译器, 这在实际中也可能成立. 我们在 1.5 GHz Intel Pentium 4 上用 GCC 3.0.4 编译器进行了两次测试. 使用了优化标志 -03.

在第一个测试中, 我们把 lambda 仿函数与显式编写的函数对象进行对比. 我们用这两种风格定义把实参反复自乘的一元函数. 从恒等函数开始, 一直到 x5. 这些表达式在 std::transform 循环内调用, 从一个 std::vector<int> 读取实参并把结果放入另一个. 向量长度为 100 个元素. 运行时间列于 表 17.3 "测试 1". 可以观察到两种方法没有显著差异.

在第二个测试中, 我们再次用 std::transform 对一个 100 元素向量的每个元素执行操作. 这次向量的元素类型是 double , 我们从非常简单的算术表达式开始, 逐渐过渡到更复杂的表达式. 运行时间列于 表 17.4 "测试 2". 这里我们还在测试中加入了经典 STL 风格的无名函数. 我们没有展示这些表达式, 因为它们相当复杂. 例如, 用经典 STL 工具编写的 表 17.4 "测试 2" 中最后一个表达式包含 7 次对 compose2的调用、8 次对 bind1st 的调用, 以及总共 14 次构造函数调用, 用于创建 multiplies、 minus 以及 plus 对象. 在这个测试中, BLL 表达式比相应的手写函数对象稍慢 (平均约 10%, 所有情形下低于 14%) . 经典 STL 表达式的性能损失更大, 最简单的表达式高达 27%.

这些测试表明, 与 STL 函数对象相比, BLL 没有引入性能损失. 使用合理的优化编译器, 可以预期其性能特性与使用经典 STL 相当. 而且, 对于简单表达式, 性能可以预期接近显式编写的函数对象. 但请注意, 对 lambda 仿函数的求值由一系列声明为 inline 的小函数调用组成. 如果编译器未能真正内联展开这些函数, 性能可能受损. 一旦发生这种情况, 运行时间可能翻倍以上. 虽然上面的测试没有包含这样的表达式, 但我们在一些看似简单的表达式上遇到过这种情况.

关于编译

BLL 相当大量地使用模板, 对同一模板执行大量递归实例化. 这 (至少) 有三点影响:

  • 虽然可以写出极其复杂的 lambda 表达式, 但这可能不是个好主意. 编译这类表达式可能最终在编译期需要大量内存, 并且编译缓慢.

  • 即使是最简单的 lambda 表达式产生的 lambda 仿函数类型也令人费解. 通常程序员根本不需要处理 lambda 仿函数类型, 但当 lambda 表达式出错时, 编译器通常会输出所涉 lambda 仿函数的类型. 这可能使错误信息非常长且难以解读, 尤其是当编译器输出完整的模板实例化链时.

  • C++ 标准建议 17 层的模板嵌套级别, 以帮助检测无限递归. 复杂的 lambda 模板很容易超过这一限制. 大多数编译器允许更多的嵌套模板, 但通常需要通过命令行参数显式提高限制.

可移植性

测试覆盖

BLL 可与以下编译器一起工作, 也就是说, 这些编译器能够编译 BLL 附带的测试用例:

  • GCC 3.0.4
  • KCC 4.0f with EDG 2.43.1
  • GCC 2.96 (有一个测试用例失败, exception_test.cpp 导致编译器内部错误. )

测试覆盖

下面的列表描述了所包含的测试文件以及每个文件覆盖的特性:

  • bind_tests_simple.cpp : 不同元数和不同目标函数类型 (函数指针、函数对象和成员函数) 的绑定表达式. 用绑定表达式进行函数组合.

  • bind_tests_simple_function_references.cpp : 重复 bind_tests_simple.cpp 中所有目标函数为函数指针的测试, 但改用函数引用.

  • bind_tests_advanced.cpp : 包含嵌套绑定表达式、 unlambda、 protect、 const_parameters 以及 break_const的测试. 包括把 lambda 仿函数作为实际实参传给其他 lambda 仿函数、柯里化 (currying) , 以及使用 sig 模板指定函数对象的返回类型.

  • operator_tests_simple.cpp : 测试 lambda 表达式支持的所有运算符, 即一元和二元算术、位、比较、逻辑、递增和递减、复合赋值、下标、取地址、解引用和逗号运算符. 测试了移位运算符的流特性, 以及用加减运算符进行的指针算术.

  • member_pointer_test.cpp : 成员指针运算符足够复杂, 值得单独一个测试文件.

  • control_structures.cpp : 循环与 if 结构的测试.

  • switch_construct.cpp : 包含 switch 语句所有受支持元数的测试, 带与不带 default 分支皆有.

  • exception_test.cpp : 包含抛出异常以及带不同数量 catch 块的 try/catch 结构的测试.

  • constructor_tests.cpp : 包含 constructor、 destructor、 new_ptr、 delete_ptr、 new_array 以及 delete_array的测试.

  • cast_test.cpp : 四种 cast 表达式的测试, 以及 typeid 和 sizeof的测试.

  • extending_return_type_traits.cpp : 针对用户自定义类型扩展返回类型推导系统的测试. 包含若干用户自定义运算符以及返回类型推导模板的相应特化.

  • is_instance_of_test.cpp : 包含对一个内部使用的特征模板的测试, 该模板能检测给定类型是否是某个模板的实例.

  • bll_and_function.cpp : 包含把 boost::function 与 lambda 仿函数一起使用的测试.
