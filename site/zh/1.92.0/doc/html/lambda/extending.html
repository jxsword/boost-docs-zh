扩展返回类型推导系统

本节解释如何扩展返回类型推导系统以覆盖用户自定义运算符. 在许多情况下这并无必要, 因为 BLL 为运算符定义了默认返回类型. 例如, 所有比较运算符的默认返回类型是 bool, 只要用户定义的比较运算符具有 bool 返回类型, 就无需为返回类型推导类编写新的特化. 不过有时这是无法避免的.

可重载的用户自定义运算符要么是一元的, 要么是二元的. 对于每个元数 (arity) , 都有两个特征模板定义不同运算符的返回类型. 因此, 可以通过为这些模板提供更多特化来扩展返回类型系统. 一元仿函数的模板是 plain_return_type_1<Action, A> 以及 return_type_1<Action, A> , 二元仿函数的则是 plain_return_type_2<Action, A, B> 以及 return_type_2<Action, A, B> .

这些模板的第一个参数 (Action) 是 动作 (action) 类, 用于指定运算符. 具有相似返回类型规则的运算符被归入 动作组 (action groups) , 只有动作类与动作组结合在一起才能无歧义地定义该运算符. 举例来说, 动作类型 arithmetic_action<plus_action> 代表 operator+. 不同动作类型的完整列表见 表 17.2 "动作类型".

其后的参数——一元情形下是 A , 二元情形下是 A 以及 B ——表示运算符调用的实参类型. 两组模板 plain_return_type_n 以及 return_type_n (其中n 为 1 或 2) 的区别在于参数类型呈现给它们的方式. 对于前者, 参数类型总是以非引用类型提供, 且不带 const 或 volatile 限定符. 这使得特化变得容易, 因为通常为每个用户自定义运算符 (或运算符组) 写一个特化就足够了. 另一方面, 如果某个运算符针对相同实参类型的不同 cv 限定进行了重载, 且这些重载版本的返回类型不同, 就需要更细粒度的控制. 因此, 对于后者, 参数类型保留 cv 限定符, 并且同样是非引用类型. 缺点是, 对于上述这类重载运算符集合, 最多可能需要 16 个 return_type_2 特化.

假设用户为某些用户自定义类型 X、 Y 以及 Z重载了以下运算符:

Z operator+(const X&, const Y&);
Z operator-(const X&, const Y&);

现在, 可以添加一个特化, 声明: 如果左操作数的类型为 X, 右操作数的类型为 Y, 那么所有这类二元算术运算符的返回类型都是 Z:

namespace boost { 
namespace lambda {
  
template<class Act> 
struct plain_return_type_2<arithmetic_action<Act>, X, Y> {
  typedef Z type;
};

}
}

定义了这个特化之后, BLL 就能正确推导上述两个运算符的返回类型. 注意, 特化必须与主模板位于同一个命名空间 ::boost::lambda中. 为简洁起见, 下文的示例不展示命名空间定义.

除了为一组运算符提供特化之外, 也可以在单个运算符的层面上进行特化. 假设我们为实参类型 X 以及 Y添加一个新的算术运算符:

X operator*(const X&, const Y&);

我们针对所有算术运算符的第一条规则规定此运算符的返回类型是 Z, 这显然不符合实际. 因此, 我们为乘法运算符提供一条新规则:

template<> 
struct plain_return_type_2<arithmetic_action<multiply_action>, X, Y> {
  typedef X type;
};

这些特化可以定义从实参类型到返回类型的任意映射. 假设我们有一个以元素类型为模板参数的数学向量类型:

template <class T> class my_vector;

假设加法运算符定义在任意两个 my_vector 实例化之间, 只要它们的元素类型之间定义了加法运算符. 此外, 结果 my_vector 的元素类型与元素类型相加的结果类型相同. 例如, my_vector<int> 与 my_vector<double> 相加得到 my_vector<double>. BLL 具有特征类, 可在整数、浮点和复数类之间执行隐式的内建和标准类型转换. 使用 BLL 工具, 上述加法运算符可以这样定义:

template<class A, class B> 
my_vector<typename return_type_2<arithmetic_action<plus_action>, A, B>::type>
operator+(const my_vector<A>& a, const my_vector<B>& b)
{
  typedef typename 
    return_type_2<arithmetic_action<plus_action>, A, B>::type res_type;
  return my_vector<res_type>();
}

为了让 BLL 正确推导 my_vector 加法的类型, 我们可以定义:

template<class A, class B> 
class plain_return_type_2<arithmetic_action<plus_action>, 
                           my_vector<A>, my_vector<B> > {
  typedef typename 
    return_type_2<arithmetic_action<plus_action>, A, B>::type res_type;
public:
  typedef my_vector<res_type> type;
};

注意, 我们复用了 BLL return_type_2 模板的现有特化, 这些特化要求实参类型为引用.
