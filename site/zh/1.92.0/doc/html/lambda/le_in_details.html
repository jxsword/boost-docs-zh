本节详细描述 lambda 表达式的不同类别. 我们为 lambda 表达式的每种可能形式单独设置一节.

占位符

BLL 定义了三种占位符类型: placeholder1_type、 placeholder2_type 以及 placeholder3_type. BLL 为每种占位符类型都预定义了一个占位符变量: _1、 _2 以及 _3. 不过, 并不强迫用户使用这些占位符. 用其他名字定义占位符很容易, 方法是定义占位符类型的新变量. 例如:

boost::lambda::placeholder1_type X;
boost::lambda::placeholder2_type Y;
boost::lambda::placeholder3_type Z;

定义了这些变量之后, X += Y * Z 等价于 _1 += _2 * _3.

lambda 表达式中占位符的使用决定了所得函数是零元的、一元的、二元的还是三元的 (3-ary) . 最高的占位符下标起决定作用. 例如:

_1 + 5              // unary
_1 * _1 + _1        // unary
_1 + _2             // binary
bind(f, _1, _2, _3) // 3-ary
_3 + 10             // 3-ary

注意, 最后一行创建的是一个三元函数, 它把 10 加到其 第三个 实参上. 前两个实参被丢弃. 此外, lambda 仿函数只有最小元数. 人们总是可以提供比实际需要更多的实参 (上限为受支持的占位符数量) . 多余的实参会被直接丢弃. 例如:

int i, j, k; 
_1(i, j, k)        // returns i, discards j and k
(_2 + _2)(i, j, k) // returns j+j, discards i and k

参见 "lambda 仿函数的元数"一节 以了解这一功能背后的设计理由.

除了这三种占位符类型之外, 还有第四种占位符类型 placeholderE_type. 该占位符的用法在描述 lambda 表达式中异常处理的 "异常"一节 中定义.

为占位符提供实际实参时, 参数传递方式始终是按引用传递. 这意味着对占位符的任何副作用都会反映到实际实参上. 例如:

int i = 1; 
(_1 += 2)(i);         // i is now 3
(++_1, cout << _1)(i) // i is now 4, outputs 4

基本规则是: 任何 C++ 运算符调用, 只要至少有一个实参是 lambda 表达式, 其本身就是 lambda 表达式. 几乎所有可重载的运算符都受支持. 例如, 下面是一个有效的 lambda 表达式:

cout << _1, _2[_3] = _1 && false

但是, 有一些限制源自 C++ 的运算符重载规则, 还有一些特殊情况.

不能被重载的运算符

有些运算符完全不能被重载 (::、 .、 .*) . 对某些运算符来说, 对返回类型的要求使其无法被重载以创建 lambda 仿函数. 这些运算符是 ->.、 ->、 new、 new[]、 delete、 delete[] 以及 ?: (条件运算符) .

赋值与下标运算符

这些运算符必须实现为类的成员. 因此, 左操作数必须是 lambda 表达式. 例如:

int i; 
_1 = i;      // ok
i = _1;      // not ok. i is not a lambda expression

针对这一限制有一个简单的解决办法, 在 "延迟常量与变量"一节中有描述. 简而言之, 可以用一个特殊的 var 函数把左手实参显式地转换为 lambda 仿函数:

var(i) = _1; // ok

逻辑运算符

逻辑运算符遵循短路求值规则. 例如, 在下面的代码中, i 永远不会被递增:

bool flag = true; int i = 0;
(_1 || ++_2)(flag, i);

逗号运算符

逗号运算符是 lambda 表达式中的 “语句分隔符” . 由于逗号也是函数调用中实参之间的分隔符, 有时需要额外的括号:

for_each(a.begin(), a.end(), (++_1, cout << _1));

如果 ++_1, cout << _1周围没有额外的括号, 这段代码会被解释为试图用四个实参调用 for_each .

由逗号运算符创建的 lambda 仿函数遵循 C++ 中总是先求值左操作数再求值右操作数的规则. 在上面的示例中, a 的每个元素先被递增, 然后写入流.

函数调用运算符

函数调用运算符的作用是对 lambda 仿函数求值. 实参过少的调用会导致编译期错误.

成员指针运算符

成员指针运算符 operator->* 可以自由重载. 因此, 对用户自定义类型而言, 成员指针运算符并非特殊情况. 然而其内建含义则稍微复杂一些. 当左手实参是指向某个类 A的对象的指针, 而右手实参是指向 A成员的指针、或指向 A 所派生类的成员的指针时, 会应用内建的成员指针运算符. 我们必须区分两种情况:

  • 右手实参是指向数据成员的指针. 在这种情况下, lambda 仿函数只是进行实参替换并调用内建的成员指针运算符, 该运算符返回指向成员的引用. 例如:

    struct A { int d; };
A* a = new A();
  ...
(a ->* &A::d);     // returns a reference to a->d 
(_1 ->* &A::d)(a); // likewise

  • 右手实参是指向成员函数的指针. 对于这样的内建调用, 其结果是一种延迟的成员函数调用. 这样的表达式后面必须跟一个函数实参列表, 延迟的成员函数调用将使用该列表执行. 例如:

    struct B { int foo(int); };
B* b = new B();
  ...
(b ->* &B::foo)         // returns a delayed call to b->foo
                        // a function argument list must follow
(b ->* &B::foo)(1)      // ok, calls b->foo(1)

(_1 ->* &B::foo)(b);    // returns a delayed call to b->foo, 
                        // no effect as such
(_1 ->* &B::foo)(b)(1); // calls b->foo(1)

绑定表达式

函数指针或引用作为目标
成员函数作为目标
成员变量作为目标
函数对象作为目标

绑定表达式可以有两种形式:

bind(target-function, bind-argument-list)
bind(target-member-function, object-argument, bind-argument-list)

绑定表达式延迟对一个函数的调用. 如果这个 目标函数 (target function) 是 n元的, 那么 bind-argument-list 也必须包含 n 个实参. 在 BLL 的当前版本中, 必须满足 0 <= n <= 9. 对于成员函数, 实参数量必须至多为 8, 因为对象实参占用一个实参位置. 基本上, bind-argument-list 必须是目标函数的有效实参列表, 只是任何实参都可以被占位符替换, 或更一般地, 被 lambda 表达式替换. 注意, 目标函数本身也可以是 lambda 表达式. 绑定表达式的结果是一个零元、一元、二元或三元 (3-ary) 函数对象, 取决于 bind-argument-list 中占位符的使用情况 (参见 "占位符"一节) .

绑定表达式创建的 lambda 仿函数的返回类型可以显式指定为模板参数, 如下例所示:

bind<RET>(target-function, bind-argument-list)

只有当目标函数的返回类型无法推导时才需要这样做.

以下各节描述不同类型的绑定表达式.

函数指针或引用作为目标

目标函数可以是指向函数的指针或引用, 既可以是绑定的, 也可以是非绑定的. 例如:

X foo(A, B, C); A a; B b; C c;
bind(foo, _1, _2, c)(a, b);
bind(&foo, _1, _2, c)(a, b);
bind(_1, a, b, c)(foo);

对于这种类型的绑定表达式, 返回类型推导总是能成功.

注意, 在 C++ 中, 只有当该地址被赋值给某个变量 (其类型可以消解歧义) 、或用作某个变量的初始化器、或使用了显式转换表达式时, 才可能取得重载函数的地址. 这意味着重载函数不能直接在绑定表达式中使用, 例如:

void foo(int);
void foo(float);
int i; 
  ...
bind(&foo, _1)(i);                            // error 
  ...
void (*pf1)(int) = &foo;
bind(pf1, _1)(i);                             // ok
bind(static_cast<void(*)(int)>(&foo), _1)(i); // ok

成员函数作为目标

在绑定表达式中使用成员函数指针的语法是:

bind(target-member-function, object-argument, bind-argument-list)

对象实参可以是对该对象的引用或指针, BLL 用统一的接口支持这两种情况:

bool A::foo(int) const; 
A a;
vector<int> ints; 
  ...
find_if(ints.begin(), ints.end(), bind(&A::foo, a, _1)); 
find_if(ints.begin(), ints.end(), bind(&A::foo, &a, _1));

类似地, 如果对象实参是非绑定的, 所得的 lambda 仿函数既可以通过指针调用, 也可以通过引用调用:

bool A::foo(int); 
list<A> refs; 
list<A*> pointers; 
  ...
find_if(refs.begin(), refs.end(), bind(&A::foo, _1, 1)); 
find_if(pointers.begin(), pointers.end(), bind(&A::foo, _1, 1));

尽管接口相同, 使用指针或引用作为对象实参在语义上有重要差异. 这些差异源于 bind函数接受参数的方式, 以及绑定参数在 lambda 仿函数内的存储方式. 对象实参的参数传递和存储机制与任何其他绑定实参槽位相同 (参见 "在 lambda 函数中存储绑定实参"一节) ; 它以 const 引用传入, 并以 const 副本的形式存储在 lambda 仿函数中. 这在 lambda 仿函数与原成员函数之间、以及看似相似的 lambda 仿函数之间造成了一些不对称. 例如:

class A {
  int i; mutable int j;
public:

  A(int ii, int jj) : i(ii), j(jj) {};
  void set_i(int x) { i = x; }; 
  void set_j(int x) const { j = x; }; 
};

使用指针时, 行为符合程序员的预期:

A a(0,0); int k = 1;
bind(&A::set_i, &a, _1)(k); // a.i == 1
bind(&A::set_j, &a, _1)(k); // a.j == 1

尽管存储了对象实参的 const 副本, 原对象 a 仍然被修改了. 这是因为对象实参是一个指针, 被复制的是指针本身, 而不是它所指的对象. 当我们使用引用时, 行为则不同:

A a(0,0); int k = 1;
bind(&A::set_i, a, _1)(k); // error; a const copy of a is stored. 
                           // Cannot call a non-const function set_i
bind(&A::set_j, a, _1)(k); // a.j == 0, as a copy of a is modified

要避免发生复制, 可以使用 ref 或者 cref 包装器 (var 以及 constant_ref 也可以) :

bind(&A::set_i, ref(a), _1)(k); // a.j == 1
bind(&A::set_j, cref(a), _1)(k); // a.j == 1

注意, 前述讨论只与绑定实参有关. 如果对象实参是非绑定的, 参数传递方式始终是按引用传递. 因此, 在下面两个 lambda 仿函数的调用中, a 不会被复制:

A a(0,0);
bind(&A::set_i, _1, 1)(a); // a.i == 1
bind(&A::set_j, _1, 1)(a); // a.j == 1

成员变量作为目标

指向成员变量的指针其实并不是函数, 但 bind 函数的第一个实参仍然可以是指向成员变量的指针. 调用这样的绑定表达式会返回对该数据成员的引用. 例如:

struct A { int data; };
A a;
bind(&A::data, _1)(a) = 1;     // a.data == 1

其成员被访问的对象的 cv 限定符会被遵守. 例如, 下面的代码试图写入一个 const 位置:

const A ca = a;
bind(&A::data, _1)(ca) = 1;     // error

函数对象作为目标

函数对象——即定义了函数调用运算符的类对象——可以用作目标函数. 一般来说, BLL 无法推导任意函数对象的返回类型. 不过, 有两种方法可以让 BLL 对某个函数对象类获得这一能力.

result_type typedef

BLL 支持标准库的约定: 在函数对象类中用名为 result_type 的成员 typedef 声明函数对象的返回类型. 下面是一个简单的示例:

struct A {
  typedef B result_type;
  B operator()(X, Y, Z); 
};

如果函数对象没有定义 result_type typedef, 则会尝试使用下文描述的方法 (sig 模板) 来解析该函数对象的返回类型. 如果函数对象同时定义了 result_type 和 sig, 则 result_type 优先.

sig 模板

让 BLL 知晓函数对象返回类型的另一种机制, 是定义成员模板 struct sig<Args> , 其中带有一个指定返回类型的 typedef type . 下面是一个简单的示例:

struct A {
  template <class Args> struct sig { typedef B type; }
  B operator()(X, Y, Z); 
};

模板实参 Args 是一个 tuple (更准确地说是一个 cons 列表) 类型 [tuple], 其中第一个元素是函数对象类型本身, 其余元素是调用该函数对象所用的实参类型. 与定义 result_type typedef 相比, 这似乎过于复杂. 然而, 仅用一个简单的 typedef 来表达返回类型有两个重要限制:

  1. 如果函数对象定义了多个函数调用运算符, 就无法为它们指定不同的结果类型.

  2. 如果函数调用运算符是模板, 结果类型可能依赖于模板参数. 因此, typedef 也应当是模板, 而 C++ 语言不支持这一点.

下面的代码展示了一个示例: 返回类型依赖于其中一个实参的类型, 以及如何用 sig 模板表达这种依赖关系:

struct A {

  // the return type equals the third argument type:
  template<class T1, class T2, class T3>
  T3 operator()(const T1& t1, const T2& t2, const T3& t3) const;

  template <class Args> 
  class sig {
    // get the third argument type (4th element)
    typedef typename 
      boost::tuples::element<3, Args>::type T3;
  public:
    typedef typename 
      boost::remove_cv<T3>::type type;
  };
};

Args 元组的元素始终是非引用类型. 此外, 元素类型可以带有 const 或 volatile 限定符 (合称为 cv 限定符 (cv-qualifiers) ) , 或两者兼有. 这是因为实参中的 cv 限定符可能影响返回类型. 把可能带 cv 限定的函数对象类型本身也放入 Args 元组的原因是: 函数对象类可以同时包含 const 和非 const (或 volatile, 甚至 const volatile) 的函数调用运算符, 而它们各自可以有不同的返回类型.

sig 模板可以看作一个 元函数 (meta-function) , 它把实参类型的元组映射为以该元组中类型为实参进行调用的结果类型. 正如上面的示例所示, 该模板最终可能相当复杂. 要执行的典型任务包括从元组中提取相关类型、移除 cv 限定符等. 有关能辅助这些任务的工具, 请参见 Boost type_traits [type_traits] 和 Tuple [type_traits] 库. sig 模板是对 FC++ 库 [fc++]中首次引入的类似机制的改进版本.

覆盖推导出的返回类型

零元 lambda 仿函数与 ret

返回类型推导系统可能无法推导某些用户自定义运算符或涉及类对象的绑定表达式的返回类型. 我们提供了一种特殊的 lambda 表达式类型, 用于显式声明返回类型并覆盖推导系统. 要声明由 lambda 表达式 e 定义的 lambda 仿函数的返回类型是 T, 可以这样写:

ret<T>(e);

其效果是: 对 lambda 表达式 e 完全不执行返回类型推导, 而是把 T 用作返回类型. 显然 T 不能是任意类型, lambda 仿函数的真实结果必须可隐式转换为 T. 例如:

A a; B b;
C operator+(A, B);
int operator*(A, B); 
  ...
ret<D>(_1 + _2)(a, b);     // error (C cannot be converted to D)
ret<C>(_1 + _2)(a, b);     // ok
ret<float>(_1 * _2)(a, b); // ok (int can be converted to float)
  ...
struct X {
  Y operator(int)();   
};
  ...
X x; int i;
bind(x, _1)(i);            // error, return type cannot be deduced
ret<Y>(bind(x, _1))(i);    // ok

对于绑定表达式, 有一种简写记法可以代替 ret. 最后一行也可以写成:

bind<Z>(x, _1)(i);

这一特性以 Boost Bind 库 [bind]为蓝本.

注意, 在嵌套的 lambda 表达式中, 凡是在推导会失败的地方, 每个子表达式都必须使用 ret . 例如:

A a; B b;
C operator+(A, B); D operator-(C);
  ...
ret<D>( - (_1 + _2))(a, b); // error 
ret<D>( - ret<C>(_1 + _2))(a, b); // ok

如果你发现自己在对相同的类型反复使用 ret , 那么扩展返回类型推导是值得的 (参见 "扩展返回类型推导系统"一节) .

零元 lambda 仿函数与 ret

如上所述, ret 的作用是阻止执行返回类型推导. 但有一个例外. 由于 C++ 模板实例化的工作方式, 编译器总是被迫为零实参 lambda 仿函数实例化返回类型推导模板. 这给 ret带来了一个小问题, 最好用示例来说明:

struct F { int operator()(int i) const; }; 
F f;
  ...
bind(f, _1);           // fails, cannot deduce the return type
ret<int>(bind(f, _1)); // ok
  ...
bind(f, 1);            // fails, cannot deduce the return type
ret<int>(bind(f, 1));  // fails as well!

BLL 无法推导上述 bind 调用的返回类型, 因为 F 没有定义 typedef result_type. 人们可能期望 ret 能解决这个问题, 但对于由绑定表达式产生的零元 lambda 仿函数 (上面的最后一行) , 这行不通. 返回类型推导模板仍会被实例化, 尽管并无必要, 结果就是编译错误.

解决办法是不要使用 ret 函数, 而是在 bind 调用中把返回类型定义为显式指定的模板参数:

bind<int>(f, 1);       // ok

用 ret<T>(bind(arg-list)) 和 bind<T>(arg-list) 创建的 lambda 仿函数具有完全相同的功能——只是对于某些零元 lambda 仿函数, 前者不工作而后者可以.

延迟常量与变量

一元函数 constant、 constant_ref 以及 var 把其实参转换为实现恒等映射的 lambda 仿函数. 前两个用于常量, 最后一个用于变量. 由于 lambda 表达式缺乏显式语法, 使用这些 延迟的 常量和变量有时是必要的. 例如:

for_each(a.begin(), a.end(), cout << _1 << ' ');
for_each(a.begin(), a.end(), cout << ' ' << _1);

第一行输出 a 的元素 (以空格分隔) , 而第二行输出一个空格后跟 a 的元素 (没有任何分隔符) . 原因在于 cout << ' ' 的两个操作数都不是 lambda 表达式, 因此 cout << ' ' 被立即求值. 要延迟 cout << ' '的求值, 必须把其中一个操作数显式标记为 lambda 表达式. 这可以通过 constant 函数实现:

for_each(a.begin(), a.end(), cout << constant(' ') << _1);

调用 constant(' ') 会创建一个零元 lambda 仿函数, 它存储字符常量 ' ' 并在被调用时返回对它的引用. 函数 constant_ref 与之类似, 区别在于它存储的是实参的常量引用. constant 和 consant_ref 仅在运算符调用有副作用时才需要, 如上例所示.

有时我们需要延迟变量的求值. 假设我们想以编号列表的形式输出容器的元素:

int index = 0; 
for_each(a.begin(), a.end(), cout << ++index << ':' << _1 << '\n');
for_each(a.begin(), a.end(), cout << ++var(index) << ':' << _1 << '\n');

第一次 for_each 调用不会如我们所愿; index 只被递增一次, 其值也只被写入输出流一次. 通过用 var 把 index 变成 lambda 表达式, 我们得到了想要的效果.

总而言之, var(x) 创建一个零元 lambda 仿函数, 它存储对变量 x的引用. 当该 lambda 仿函数被调用时, 返回对 x 的引用.

为延迟常量与变量命名

可以在 lambda 表达式之外预定义并命名一个延迟的变量或常量. 模板 var_type、 constant_type 以及 constant_ref_type 就是为此服务的. 它们的用法如下:

var_type<T>::type delayed_i(var(i));
constant_type<T>::type delayed_c(constant(c));

第一行定义变量 delayed_i , 它是类型为 i 的变量 T的延迟版本. 类似地, 第二行把常量 delayed_c 定义为常量 c的延迟版本. 例如:

int i = 0; int j;
for_each(a.begin(), a.end(), (var(j) = _1, _1 = var(i), var(i) = var(j)));

等价于:

int i = 0; int j;
var_type<int>::type vi(var(i)), vj(var(j));
for_each(a.begin(), a.end(), (vj = _1, _1 = vi, vi = vj));

下面是一个为延迟常量命名的示例:

constant_type<char>::type space(constant(' '));
for_each(a.begin(),a.end(), cout << space << _1);

关于赋值与下标运算符

如 "赋值与下标运算符"一节所述, 赋值和下标运算符总是定义为成员函数. 这意味着, 要使形如 x = y 或者 x[y] 的表达式被解释为 lambda 表达式, 左操作数 x 必须是 lambda 表达式. 因此, 有时为此需要使用 var . 我们重复 "赋值与下标运算符"一节中的示例:

int i; 
i = _1;       // error
var(i) = _1;  // ok

注意, 复合赋值运算符 +=、 -= 等可以定义为非成员函数, 因此即使只有右操作数是 lambda 表达式, 它们也会被解释为 lambda 表达式. 尽管如此, 显式延迟左操作数也完全没有问题. 例如, i += _1 等价于 var(i) += _1.

控制结构的 lambda 表达式

Switch 语句

BLL 定义了若干函数, 用于创建表示控制结构的 lambda 仿函数. 它们都以 lambda 仿函数作为参数并返回 void. 先看一个示例, 下面的代码输出某个容器 a的所有偶数元素:

for_each(a.begin(), a.end(), 
         if_then(_1 % 2 == 0, cout << _1));

BLL 为控制结构支持以下函数模板:

if_then(condition, then_part)
if_then_else(condition, then_part, else_part)
if_then_else_return(condition, then_part, else_part)
while_loop(condition, body)
while_loop(condition) // no body case
do_while_loop(condition, body)
do_while_loop(condition) // no body case 
for_loop(init, condition, increment, body)
for_loop(init, condition, increment) // no body case
switch_statement(...)

所有控制结构 lambda 仿函数的返回类型都是 void, 但 if_then_else_return除外——它包装的是对条件运算符的调用

condition ? then_part : else_part

该运算符的返回类型规则有些复杂. 基本上, 如果两个分支具有相同类型, 该类型就是返回类型. 如果分支的类型不同, 则其中一个分支 (比如类型为 A) 必须可转换为另一个分支 (比如类型为 B) . 在这种情况下, 结果类型是 B. 此外, 如果公共类型是左值, 返回类型也会是左值.

延迟变量在控制结构 lambda 表达式中往往很常见. 例如, 这里我们用 var 函数把 for_loop 的实参转换为 lambda 表达式. 这段代码的效果是给二维数组的每个元素加 1:

int a[5][10]; int i;
for_each(a, a+5, 
  for_loop(var(i)=0, var(i)<10, ++var(i), 
           _1[var(i)] += 1));

BLL 支持由 Joel de Guzmann 建议的控制表达式另一种语法. 通过重载 operator[] , 我们可以更接近内建控制结构的样子:

if_(condition)[then_part]
if_(condition)[then_part].else_[else_part]
while_(condition)[body]
do_[body].while_(condition)
for_(init, condition, increment)[body]

例如, 使用这种语法, 上面的 if_then 示例可以写成:

for_each(a.begin(), a.end(), 
         if_(_1 % 2 == 0)[ cout << _1 ])

随着经验的积累, 我们最终可能会弃用这两种语法中的一种.

Switch 语句

switch 控制结构的 lambda 表达式更为复杂, 因为 case 的数量可变. switch lambda 表达式的一般形式是:

switch_statement(condition, 
  case_statement<label>(lambda expression),
  case_statement<label>(lambda expression),
  ...
  default_statement(lambda expression)
)

condition 实参必须是一个 lambda 表达式, 它创建返回类型为整型的 lambda 仿函数. 不同的 case 用 case_statement 函数创建, 可选的 default 分支用 default_statement 函数创建. case 标签作为显式指定的模板实参提供给 case_statement 函数, 而 break 语句则隐式地成为每个 case 的一部分. 例如, case_statement<1>(a) (其中 a 是某个 lambda 仿函数) 会生成如下代码:

case 1: 
  evaluate lambda functor a; 
  break;

switch_statement 函数针对最多 9 个 case 语句进行了特化.

作为一个具体的例子, 下面的代码遍历某个容器 v , 对每个 输出“zero ” 0, 对每个 输出“one ” 1, 对其他任何值 输出“ nother: ” n. 注意, 在 switch_statement 之后串联了另一个 lambda 表达式, 以便在每个元素之后输出一个换行:

std::for_each(v.begin(), v.end(),
  ( 
    switch_statement(
      _1,
      case_statement<0>(std::cout << constant("zero")),
      case_statement<1>(std::cout << constant("one")),
      default_statement(cout << constant("other: ") << _1)
    ), 
    cout << constant("\n") 
  )
);

异常

BLL 提供抛出和捕获异常的 lambda 仿函数. 抛出异常的 lambda 仿函数用一元函数 throw_exception创建. 该函数的实参是要抛出的异常, 或是一个创建要抛出异常的 lambda 仿函数. 重抛 (rethrow) 异常的 lambda 仿函数用零元函数 rethrow 创建.

处理异常的 lambda 表达式则稍微复杂一些. try catch 块的 lambda 表达式的一般形式如下:

try_catch(
  lambda expression,
  catch_exception<type>(lambda expression),
  catch_exception<type>(lambda expression),
  ...
  catch_all(lambda expression)
)

第一个 lambda 表达式是 try 块. 每个 catch_exception 定义一个 catch 块, 其中显式指定的模板实参定义要捕获的异常类型. catch_exception 内的 lambda 表达式定义捕获到异常时要采取的动作. 注意, 所得的异常处理器以引用方式捕获异常, 即 catch_exception<T>(...) 会产生如下 catch 块:

catch(T& e) { ... }

最后一个 catch 块也可以改为调用 catch_exception<type> 或 catch_all, 后者是与 catch(...)等价的 lambda 表达式.

示例 17.1 "在 lambda 表达式中抛出和处理异常" 展示了 BLL 异常处理工具的用法. 第一个处理器捕获类型为 foo_exception的异常. 注意在处理器主体中 _1 占位符的用法.

第二个处理器展示如何抛出异常, 并演示了 异常占位符 (exception placeholder) _e的用法. 它是一个特殊的占位符, 在处理器主体内指代被捕获的异常对象. 这里我们处理类型为 std::exception的异常, 它携带一个说明异常原因的字符串. 可以用零实参成员函数 what查询该说明. 表达式 bind(&std::exception::what, _e) 创建用于进行该调用的 lambda 函数. 注意, _e 不能在异常处理器 lambda 表达式之外使用. 第二个处理器的最后一行构造一个新的异常对象并用 throw exception抛出它. 在 lambda 表达式中构造和析构对象在 "构造与析构"一节中解释

最后, 第三个处理器 (catch_all) 演示重抛异常.

示例 17.1 在 lambda 表达式中抛出和处理异常. 

for_each(
  a.begin(), a.end(),
  try_catch(
    bind(foo, _1),                 // foo may throw
    catch_exception<foo_exception>(
      cout << constant("Caught foo_exception: ") 
           << "foo was called with argument = " << _1
    ),
    catch_exception<std::exception>(
      cout << constant("Caught std::exception: ") 
           << bind(&std::exception::what, _e),
      throw_exception(bind(constructor<bar_exception>(), _1)))
    ),      
    catch_all(
      (cout << constant("Unknown"), rethrow())
    )
  )
);

构造与析构

运算符 new 以及 delete 可以重载, 但它们的返回类型是固定的. 特别是, 返回类型不能是 lambda 仿函数, 这使它们无法为 lambda 表达式而重载. 无法取得构造函数的地址, 因此构造函数不能用作绑定表达式中的目标函数. 析构函数也是如此. 作为绕过这些限制的办法, BLL 为 new 以及 delete 调用以及构造函数和析构函数定义了包装类. 这些类的实例是函数对象, 可以用作绑定表达式的目标函数. 例如:

int* a[10];
for_each(a, a+10, _1 = bind(new_ptr<int>())); 
for_each(a, a+10, bind(delete_ptr(), _1));

表达式 new_ptr<int>() 创建一个被调用时会执行 new int() 的函数对象, 把它包在 bind 里就使它成为 lambda 仿函数. 同样, 表达式 delete_ptr() 创建一个对其实参执行 delete 的函数对象. 注意, new_ptr<T>() 也可以接受实参. 它们被直接传递给构造函数调用, 因此允许调用带实参的构造函数.

作为 lambda 表达式中构造函数调用的示例, 下面的代码从两个容器 x 以及 y读取整数, 由它们构造 pair 并插入第三个容器:

vector<pair<int, int> > v;
transform(x.begin(), x.end(), y.begin(), back_inserter(v),
          bind(constructor<pair<int, int> >(), _1, _2));

表 17.1 "与构造和析构相关的函数对象" 列出了与创建和销毁对象相关的所有函数对象, 给出创建并调用该函数对象的表达式, 以及对该表达式求值的效果.

表 17.1 与构造和析构相关的函数对象

函数对象调用 被包装的表达式
constructor<T>()(arg_list) T(arg_list)
destructor()(a) a.~A(), 其中 a 的类型为 A
destructor()(pa) pa->~A(), 其中 pa 的类型为 A*

阻止实参替换

Unlambda
Protect

当 lambda 仿函数被调用时, 默认行为是把实际实参替换到所有子表达式中的占位符上. 本节描述阻止子表达式被替换和求值的工具, 并解释何时应使用这些工具.

绑定表达式的实参可以是任意 lambda 表达式, 例如其他绑定表达式. 例如:

int foo(int); int bar(int);
...
int i;
bind(foo, bind(bar, _1))(i);

最后一行进行调用 foo(bar(i)); 注意, 绑定表达式中的第一个实参——目标函数——也不例外, 因此也可以是绑定表达式. 最内层的 lambda 仿函数只需返回能用作目标函数的东西: 另一个 lambda 仿函数、函数指针、成员函数指针等. 例如, 在下面的代码中, 最内层的 lambda 仿函数在两个函数之间做出选择, 并返回指向其中一个的指针:

int add(int a, int b) { return a+b; }
int mul(int a, int b) { return a*b; }

int(*)(int, int)  add_or_mul(bool x) { 
  return x ? add : mul; 
}

bool condition; int i; int j;
...
bind(bind(&add_or_mul, _1), _2, _3)(condition, i, j);

Unlambda

如果目标函数是一个类型依赖于模板参数的变量, 嵌套的绑定表达式可能会无意间出现. 典型情况是目标函数可能是函数模板的形式参数. 在这种情况下, 程序员可能不知道目标函数是否是 lambda 仿函数.

考虑下面的函数模板:

template<class F>
int nested(const F& f) {
  int x;
  ...
  bind(f, _1)(x);
  ...
}

在函数内部的某处, 形式参数 f 在绑定表达式中被用作目标函数. 为使这个 bind 调用有效, f 必须是一元函数. 假设对 nested 进行如下两次调用:

int foo(int);
int bar(int, int);
nested(&foo);
nested(bind(bar, 1, _1));

两者都是具有合适实参和返回类型的一元函数或函数对象, 但后者无法编译. 在后一个调用中, nested 内的绑定表达式将变成:

bind(bind(bar, 1, _1), _1)

当用 x调用它时, 经过替换之后, 我们最终会尝试调用

bar(1, x)(x)

这是错误的. 对 bar 的调用返回 int, 而不是一元函数或函数对象.

在上面的示例中, nested 函数中绑定表达式的意图是把 f 当作普通函数对象处理, 而不是 lambda 仿函数. BLL 提供函数模板 unlambda 来表达这一点: 被包在 unlambda 里的 lambda 仿函数就不再是 lambda 仿函数, 也不参与实参替换过程. 注意, 对其他所有实参类型, unlambda 都是恒等操作, 只是会把非 const 对象变成 const.

使用 unlambda, nested 函数可以写成:

template<class F>
int nested(const F& f) {
  int x;
  ...
  bind(unlambda(f), _1)(x);
  ...
}

Protect

protect 函数与 unlambda 相关. 它同样用于阻止实参替换的发生, 但 unlambda 是永久地把 lambda 仿函数变成普通函数对象, 而 protect 只是暂时如此, 仅一轮求值. 例如:

int x = 1, y = 10;
(_1 + protect(_1 + 2))(x)(y);

第一次调用把 x 替换到最左边的 _1中, 得到另一个 lambda 仿函数 x + (_1 + 2), 它经 y 调用后变为 x + (y + 2), 最终得到 13.

把 protect 纳入库中的主要动机, 是允许嵌套的 STL 算法调用 ("嵌套 STL 算法调用"一节) .

右值作为 lambda 仿函数的实际实参

lambda 仿函数的实际实参不能是非 const 右值. 这是一个深思熟虑的设计决策: 要么有这个限制, 要么实际实参就不能有副作用. 有办法绕过这一限制. 我们重复 "lambda 仿函数的实际实参"一节 中的示例, 并列出各种不同的解决办法:

int i = 1; int j = 2; 
(_1 + _2)(i, j); // ok
(_1 + _2)(1, 2); // error (!)

  1. 如果右值是类类型, 创建该右值的函数的返回类型应定义为 const. 由于一个不幸的语言限制, 这对内建类型行不通, 因为内建右值不能加 const 限定.

  2. 如果 lambda 函数调用是可访问的, 可以用 make_const 函数把右值 变成 const (constify) . 例如:

    (_1 + _2)(make_const(1), make_const(2)); // ok

    通常 lambda 函数调用点位于标准算法函数模板内部, 使这一办法无法使用.

  3. 如果上述办法都不可行, 可以把 lambda 表达式包在 const_parameters 函数中. 它会创建另一种 lambda 仿函数, 以 const 引用接受其实参. 例如:

    const_parameters(_1 + _2)(1, 2); // ok

    注意, const_parameters 会把所有实参都变成 const. 因此, 如果其中一个实参是非 const 右值、而另一个实参需要以非 const 引用传递, 就不能使用这种方法.

  4. 如果上述办法都不可行, 仍有一种办法, 但遗憾的是它可能破坏 const 正确性. 该办法是又一个 lambda 仿函数包装器, 我们把它命名为 break_const 以提醒用户注意此函数的潜在危险. break_const 函数创建一个以 const 方式接受实参的 lambda 仿函数, 并在调用原被包装的 lambda 仿函数之前把 const 去除. 例如:

    int i; 
...
(_1 += _2)(i, 2);                 // error, 2 is a non-const rvalue
const_parameters(_1 += _2)(i, 2); // error, i becomes const
break_const(_1 += _2)(i, 2);      // ok, but dangerous

    注意, break_const 或者 const_parameters 的结果不是 lambda 仿函数, 因此不能用作 lambda 表达式的子表达式. 例如:

    break_const(_1 + _2) + _3; // fails.
const_parameters(_1 + _2) + _3; // fails.

    不过, 这类代码应当永远不需要, 因为对子 lambda 仿函数的调用是在 BLL 内部进行的, 不受非 const 右值问题的影响.

Cast 表达式

BLL 为四种 cast 表达式 static_cast、 dynamic_cast、 const_cast 以及 reinterpret_cast定义了对应物. 这些 cast 表达式的 BLL 版本带有前缀 ll_. 要转换到的类型以显式指定的模板实参给出, 唯一的实参是要进行转换的表达式. 如果实参是 lambda 仿函数, 则先对该 lambda 仿函数求值. 例如, 下面的代码用 ll_dynamic_cast 统计容器 derived 中 a实例的数量:

class base {};
class derived : public base {};

vector<base*> a;
...
int count = 0;
for_each(a.begin(), a.end(), 
         if_then(ll_dynamic_cast<derived*>(_1), ++var(count)));

Sizeof 与 typeid

这些表达式的 BLL 对应物名为 ll_sizeof 以及 ll_typeid. 两者都接受一个可以是 lambda 表达式的实参. 创建的 lambda 仿函数包装了 sizeof 或者 typeid 调用, 当 lambda 仿函数被调用时, 被包装的操作就会执行. 例如:

vector<base*> a; 
...
for_each(a.begin(), a.end(), 
         cout << bind(&type_info::name, ll_typeid(*_1)));

这里 ll_typeid 创建一个为每个元素调用 typeid 的 lambda 仿函数. typeid 调用的结果是 type_info 类的实例, 而绑定表达式创建一个调用该类 name 成员函数的 lambda 仿函数.

嵌套 STL 算法调用

BLL 把常见的 STL 算法定义为函数对象类, 其实例可以用作绑定表达式中的目标函数. 例如, 下面的代码遍历二维数组的元素并计算它们的和.

int a[100][200];
int sum = 0;

std::for_each(a, a + 100, 
	      bind(ll::for_each(), _1, _1 + 200, protect(sum += _1)));

STL 算法的 BLL 版本是类, 它们定义函数调用运算符 (或多个重载版本) 来调用 std 命名空间中对应的函数模板. 所有这些 struct 都放在子命名空间 boost::lambda:ll中.

注意, 没有简便的方法在 lambda 表达式中表达重载的成员函数调用. 这限制了嵌套 STL 算法的用途, 例如 begin 函数在容器模板中有不止一个重载定义. 一般而言, 无法写出与下面伪代码类似的东西:

std::for_each(a.begin(), a.end(), 
	      bind(ll::for_each(), _1.begin(), _1.end(), protect(sum += _1)));

不过, 可以为一些常见的特殊情况提供帮助. BLL 定义了两个辅助函数对象类 call_begin 以及 call_end, 它们包装对容器的 begin 和 (相应地) end 函数的调用, 并返回容器的 const_iterator 类型. 借助这些辅助模板, 上面的代码变成:

std::for_each(a.begin(), a.end(), 
	      bind(ll::for_each(), 
                   bind(call_begin(), _1), bind(call_end(), _1),
                        protect(sum += _1)));
