构建 Boost.Container
已测试的编译器

Boost.Container 库实现了多个知名容器, 包括 STL 容器. 该库旨在提供标准容器中没有的高级特性, 或为旧编译器提供最新的标准草案特性.

简而言之, Boost.Container 提供了什么?

  • 可以使用许多最新的 C++ 标准特性, 并且在更换编译器时可以轻松迁移代码.
  • 一个可移植的高性能实现, 在无异常支持的情况下编译也能工作, 并且当容器需要报告异常错误时提供可定制的错误处理.
  • 用户在所有平台上获得更一致的性能, 包括 SCARY 迭代器.
  • 实用的多态分配器和内存资源, 包括为 C++17 之前的编译器提供的实现和模拟
  • 新的高级特性 (例如递归容器) 以及 容器的可配置选项.
  • 容器支持带状态分配器, 并与 Boost.Interprocess 兼容 (可以安全地放置在共享内存中), 在使用 Boost.Interprocess 时相比标准容器具有更好的性能.
  • 你有许多非常实用的非标准容器, 例如 [stable/static/small]_vector, flat_[multi]set/map, devector 或 segtor.
  • 如果你在多个平台上工作, 将获得可移植的行为, 而无需依赖各平台标准库实现的一致性. 例如:
  • 基于用户反馈提供的超出标准的 扩展功能, 以提升代码性能.
  • 配置选项, 允许调整容器以适应用户需求.
  • 该库提供了一些新的实用容器:
    • flat_map、flat_set、flat_multimap 和 flat_multiset: 标准关联容器的直接替代品, 但更省内存且搜索更快.
    • stable_vector: std::list 与 std::vector 的混合容器: 具有类似 vector 的随机访问迭代器和类似 list 的插入与擦除迭代器稳定性.
    • static_vector: 一种类似 vector 的容器, 内部嵌入 (静态分配) 达到最大容量所需的全部内存. 最大容量不可增加, 在编译期指定.
    • small_vector: 一种类似 vector 的容器, 内部嵌入 (静态分配) 最少量的内存, 但在需要增加容量时动态分配元素. 此最小容量在编译期指定.
    • devector: 标准向量 (vector) 与双端队列 (deque) 容器的混合体. 它在前端和后端都提供廉价 (摊还常量时间) 的插入.
    • segtor: 一种具有分段 (基于块) 存储的序列容器, 类似 deque 但只在后端增长; 常量时间 push_back/pop_back, 随机访问.
    • slist: 经典的标准化之前的单向链表实现, 提供常量时间的 size(). 注意 C++11 的 forward_list 没有 size().

构建 Boost.Container

对于大多数功能, 无需编译 Boost.Container, 因为它是一个仅头文件库, 只需把 Boost 头文件目录加入编译器包含路径即可 但如果你使用以下功能则除外:

  • 扩展分配器
  • 一些 多态内存资源 (Polymorphic Memory Resources) 类.

这些例外被实现为一个需单独编译的库, 因此在这些情况下, 你必须把二进制文件安装到链接器可以找到的位置. 如果你按照 Boost 入门 说明操作, 这一步已经替你完成.

对于 CMake 构建系统, 该工程 (CMakeLists.txt) 包含 BOOST_CONTAINER_HEADER_ONLY 选项, 设为 ON 可将库构建为仅头文件库, 设为 OFF 则将其构建为需单独编译的库.

已测试的编译器

Boost.Container 需要良好的 C++03 兼容性. 一些已知可用的编译器有:

  • Visual C++ >= 10.0
  • GCC >= 4.8
