注释

前 3 章改编自 Howard E. Hinnant, Bjarne Stroustrup 和 Bronek Kozicki 的文章 A Brief Introduction to Rvalue References

复制可能很昂贵. 例如, 对向量而言 v2=v1 通常涉及一次函数调用, 一次内存分配和一个循环. 当我们确实需要一个向量的两份副本时这当然可以接受, 但在很多情况下并非如此: 我们常常把一个 vector 从一处复制到另一处, 只是为了随后覆盖旧的副本. 考虑:

template <class T> void swap(T& a, T& b)
{
   T tmp(a);   // now we have two copies of a
   a = b;      // now we have two copies of b
   b = tmp;    // now we have two copies of tmp (aka a)
}

但是, 我们并不想要 a 或 b 的任何副本, 只是想交换它们. 再试一次:

template <class T> void swap(T& a, T& b)
{
   T tmp(::boost::move(a));
   a = ::boost::move(b);
   b = ::boost::move(tmp);
}

这个 move() 把其实参的值给予目标, 但不必保留来源的值. 因此, 对于一个 vector, move() 可以合理地被期望将其参数留成一个容量为零的向量, 以避免不得不复制所有元素. 换句话说, 移动是一种潜在的破坏性复制.

在这个特定例子中, 本可以通过特化来优化 swap. 然而, 我们无法对每一个在删除或覆盖大对象之前复制它的函数都做特化. 那将是无法管理的.

在 C++0x 中, 移动语义通过引入右值引用而得以实现. 它们让我们能够实现 move() 而无需冗长代码或运行期开销. Boost.Move 是一个提供工具的库, 不仅可以在支持 rvalue references 的编译器上实现这些移动语义, 也可以在符合 C++03 的编译器上实现.
