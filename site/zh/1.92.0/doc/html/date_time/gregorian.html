格里高利历 (Gregorian Calendar)

格里高利历日期系统

引言 -- 用法示例

引言

格里高利历日期系统提供了一个基于格里高利历 (Gregorian Calendar) 的日期编程系统. 格里高利历最初于 1582 年推出, 用于修正儒略历 (Julian Calendar) 的误差. 然而, 许多地区直到很久之后才采纳这一变更. 因此历史日期存在潜在混淆.

实现的历法是"前置格里高利历" (proleptic Gregorian calendar) , 将日期回溯扩展到 1582 年格里高利历首次采用之前. 当前实现支持 1400-Jan-01 至 9999-Dec-31 范围内的日期. 许多资料会用儒略历表示 1582 年之前的日期, 因此如果需要对历史日期进行精确计算, 务必小心. 更多细节见 Reingold 与 Dershowitz 所著的 Calendrical Calculations. 《Calendrical Calculations》中的日期信息已被用于交叉测试格里高利历实现的正确性.

gregorian 系统的所有类型都位于 boost::gregorian 命名空间中. 库提供了便利头文件 boost/date_time/gregorian/gregorian_types.hpp, 它包含库的所有类而不依赖输入/输出. 另一个头文件 boost/date_time/gregorian/gregorian.hpp 则包含类型和输入/输出代码.

类 boost::gregorian::date 是用户使用的主要时间类型. 如果你有兴趣了解如何编写进行专门日期计算 (例如查找"四月第一个星期日") 的程序, 请参阅日期 生成器与算法页面.

Date

引言 -- 头文件 -- 构造 -- 从字符串构造 -- 从时钟构造 -- 访问器 -- 转换为字符串 -- 运算符 -- Struct tm 函数

引言

类 boost::gregorian::date 是日期编程的主要接口. 总体而言, date 类一旦构造即不可变, 不过它允许从另一个 date 赋值. 创建日期的技术包括读取来自时钟的当前日期、使用日期迭代器以及日期算法或生成器.

在内部, boost::gregorian::date 以 32 位整数类型存储. 该类特意设计为不包含虚函数. 这一设计使得在大量日期集合上进行高效计算和内存使用成为可能.

date 的构造会对所有输入进行验证, 因此不可能构造出"无效"的日期. 也就是说, 2001-Feb-29 无法构造为 date. 会抛出各种派生自 std::out_of_range 的异常, 以指明日期输入的哪一方面无效. 注意, 如果需要, 特殊值 not-a-date-time 可用作"无效"或"空"日期.

运算可逆性陷阱






向日期加上若干月再减去同样的月数, 自然的期望是恰好回到起点. date_time 库提供的结果通常正是如此, 但有一个重要的例外: months 时长类型实现的"贴合月末"行为. 当起始日是 31 天月份中的 28、29 或 30 日时, months 时长类型可能给出意外结果. month_iterator 不受此问题影响, 因此在示例中用它来说明一种可能的替代方案.







当起始日期在月中时, 加减任意月数都会得到月内同一日的结果 (例如: 从 15 日开始, 会落在 15 日) . 当日期是月末最后一天时, 加减任意月数的结果也是月末最后一天 (例如: 从 1 月 31 日开始, 会落在: 2 月 28 日、3 月 31 日等) .


    // using months duration type
    date d(2005, Nov, 30); // last day of November
    d + months(1); // result is last day of December "2005-Dec-31"
    d - months(1); // result is last day of October "2005-Oct-31"

    // using month_iterator
    month_iterator itr(d); // last day of November
    ++itr; // result is last day of December "2005-Dec-31"
    --itr; // back to original starting point "2005-Nov-30"
    --itr; // last day of October "2005-Oct-31"
  











如果起始日期是 31 天月份中的 28、29 或 30 日, 加减一个月的结果可能意外触发"贴合月末"行为. 这会导致最终结果与起始日期不同.


    // using months duration type
    date d(2005, Nov, 29);
    d += months(1); // "2005-Dec-29"
    d += months(1); // "2006-Jan-29"
    d += months(1); // "2006-Feb-28" --> snap-to-end-of-month behavior kicks in
    d += months(1); // "2006-Mar-31" --> unexpected result
    d -= months(4); // "2005-Nov-30" --> unexpected result, not where we started

    // using month_iterator
    month_iterator itr(date(2005, Dec, 30));
    ++itr; // "2006-Jan-30" --> ok
    ++itr; // "2006-Feb-28" --> snap-to DOES NOT kick in 
    ++itr; // "2006-Mar-30" --> ok
    --itr; // "2006-Feb-28" --> ok
    --itr; // "2006-Jan-30" --> ok
    --itr; // "2005-Dec-30" --> ok, back where we started
  











额外的时长类型 (months、years 和 weeks) 是为了方便而提供的, 可以轻松移除以确保该陷阱永不发生. 要移除这些类型, 只需取消定义 BOOST_DATE_TIME_OPTIONAL_GREGORIAN_TYPES.











日期时段

引言 -- 头文件 -- 构造 -- 修改器 -- 访问器 -- 转换为字符串 -- 运算符

引言


类 boost::gregorian::date_period 提供了两个日期之间范围的直接表示. 时段通过简化程序的条件逻辑, 能够简化某些类型的计算. 例如, 测试某个日期是否属于周末或节假日这类不规则日程, 可以用 date_period 的集合来完成. 这得益于若干方法, 它们可以判定某个 date_period 是否与另一个时段相交, 并生成相交产生的时段. 日期时段计算示例提供了一个这样的例子.


以相等的起点和终点创建的时段, 或以零时长创建的时段, 称为零长度时段. 零长度时段被视为无效 (构造无效时段是完全合法的) . 对于这些时段, last 点总是比 begin 点少一个单位.


日期时段与无穷值结合使用, 能够表达"直到另行通知"等复杂概念.

合并两个时段以及它们之间的间隔, 使 begin = min(p1.begin, p2.begin) 且 end = max(p1.end , p2.end)

                date(2002,Jan,5));

                date(2002,Jan,31));

向起点和终点都加上时长.

从起点减去时长, 并向终点加上时长.

                date(2002,Jan,10));
dp1.expand(days(2));
// 2002-Jan-02/2002-Jan-12

日期迭代器

引言 -- 头文件 -- 概述

引言


日期迭代器提供了在日期之间迭代的标准机制. 日期迭代器是 双向迭代器 (Bidirectional Iterator)  的一个模型, 可用于向集合填充日期以及执行其他日期生成任务. 例如, 打印月份 示例遍历一个月中的所有日期并打印它们.


这里的所有迭代器都派生自 boost::gregorian::date_iterator.



头文件



    


#include "boost/date_time/gregorian/gregorian.hpp" //include all types plus i/o
or
#include "boost/date_time/gregorian/gregorian_types.hpp" //no i/o just types



  



概述










语法
说明



示例






date_iterator

所有日级迭代器的公共 (抽象) 基类.







day_iterator(date start_date, int day_count=1)

每次迭代 day_count 天. 该迭代器不提供后缀递增/递减运算符, 只提供前缀运算符.



day_iterator day_itr(date(2005,Jan,1));
++d_itr; // 2005-Jan-02
day_iterator 2day_itr(date(2005,Feb,1),2);
++2d_itr; // 2005-Feb-03




week_iterator(...)
  Parameters:
    date start_date
    int week_offset (defaults to 1)

每次迭代 week_offset 周. 该迭代器不提供后缀递增/递减运算符, 只提供前缀运算符.



week_iterator wk_itr(date(2005,Jan,1));
++wk_itr; // 2005-Jan-08
week_iterator 2wk_itr(date(2005,Jan,1),2);
++2wk_itr; // 2005-Feb-15




month_iterator(...)
  Parameters:
    date start_date
    int month_offset (defaults to 1)

每次迭代 month_offset 个月. 月末有特殊处理规则: 如果起始日期是某月的最后一天, 则始终调整到该月的最后一天; 如果日期超出月末 (例如 Jan 31 + 1 month) , 则调回月末 (更多细节和示例见 运算可逆性陷阱. 注意:  month_iterator 不受该陷阱影响. ) 该迭代器不提供后缀递增/递减运算符, 只提供前缀运算符.



month_iterator m_itr(date(2005,Jan,1));
++m_itr; // 2005-Feb-01
month_iterator 2m_itr(date(2005,Feb,1),2);
++2m_itr; // 2005-Apr-01




year_iterator(...)
  Parameters:
    date start_date
    int year_offset (defaults to 1)

每次迭代 year_offset 年. year_iterator 总是落在与 date 参数相同的日上, 除非 date 是非闰年的 Feb 28. 此时该迭代器在闰年会返回 Feb 29 (例如: 2003-Feb-28、2004-Feb-29、2005-Feb-28) . 该迭代器不提供后缀递增/递减运算符, 只提供前缀运算符.



year_iterator y_itr(date(2005,Jan,1));
++y_itr; // 2006-Jan-01
year_iterator 2y_itr(date(2005,Feb,1),2);
++2y_itr; // 2007-Feb-01










日期生成器/算法



日期生成器/算法

引言 -- 头文件 -- 类概览 -- 函数概览

引言


日期算法或生成器是用于生成其他日期或日期日程的工具. 生成器函数以日期的某一部分 (如月和日) 为起点, 再提供另一部分来生成具体日期. 这使得程序员可以表达诸如"二月的第一个星期日"之类的概念, 然后在给定一个或多个年份时生成具体的日期集合. 注意: 自 boost 1_31_0 版起, 日期生成器名称已变更. 旧名称仍然可用, 但不再写入文档, 将来可能被弃用


另外还提供了用于生成日期或计算天数时长的独立函数. 这些函数接受一个 date 对象和一个 weekday 对象作为参数.


所有日期生成器类和函数都在 boost::gregorian 命名空间中.


 打印节假日 示例展示了详细的用法示例.
