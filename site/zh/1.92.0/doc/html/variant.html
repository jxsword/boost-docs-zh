摘要

variant 类模板是一个安全、泛型、基于栈的可辨识联合容器, 为以统一方式操纵来自异构类型集合的对象提供了简单的解决方案. 像 std::vector 这样的标准容器可以被视为“多值, 单类型”, 而 variant 则是“多类型, 单值”.

boost::variant 的显著特性包括:

  • 完整的值语义, 包括遵循转换操作的标准重载决议规则.
  • 通过 boost::apply_visitor 进行编译期类型安全的值访问.
  • 通过 boost::get 进行运行期检查的显式值提取.
  • 通过 boost::make_recursive_variant 与 boost::recursive_wrapper 两种方式支持递归 variant 类型.
  • 高效的实现——在可能时基于栈 (更多细节见“永不空”保证一节).

解决方案: 一个示例动机

问题

在 C++ 程序开发过程中, 程序员经常发现自己需要以统一的方式操纵多个不同的类型. 事实上, C++ 通过其 union 关键字为这类类型提供了直接的语言支持:

union { int i; double d; } u;
u.d = 3.14;
u.i = 3; // overwrites u.d (OK: u.d is a POD type)

然而, C++ 的 union 构造在面向对象环境中几乎无用. 该构造进入语言主要是为了保持与 C 的兼容性, 而 C 只支持 POD (Plain Old Data) 类型, 因此不接受表现出非平凡构造或析构的类型:

union {
  int i;
  std::string s; // illegal: std::string is not a POD type!
} u;

显然需要另一种方法. 典型的方案对对象进行动态分配, 随后通过一个公共基类型 (通常是虚基类 [Hen01], 或更危险地, 一个 void*) 操纵它们. 具体类型的对象随后可以通过多态向下转换构造 (例如 dynamic_cast、boost::any_cast 等) 取回.

然而, 这类方案极易出错, 原因如下:

  • 向下转换错误无法在编译期检测. 因此, 向下转换构造的错误用法只会导致仅在运行期才能发现的缺陷.
  • 新增具体类型可能被忽略. 如果向层次结构中添加新的具体类型, 现有的向下转换代码将照常工作, 完全忽略新类型. 因此, 程序员必须手动定位并修改大量位置的代码, 这常常导致难以发现的运行期错误.

此外, 即使实现正确, 这些方案也会因使用堆、虚函数调用与多态向下转换而产生相对显著的抽象惩罚.

解决方案: 一个示例动机

boost::variant 类模板以安全、直接且高效的方式解决了这些问题. 下面的示例演示了这个类的用法:

#include "boost/variant.hpp"
#include <iostream>

class my_visitor : public boost::static_visitor<int>
{
public:
    int operator()(int i) const
    {
        return i;
    }
    
    int operator()(const std::string & str) const
    {
        return str.length();
    }
};

int main()
{
    boost::variant< int, std::string > u("hello world");
    std::cout << u; // output: hello world

    int result = boost::apply_visitor( my_visitor(), u );
    std::cout << result; // output: 11 (i.e., length of "hello world")
}
