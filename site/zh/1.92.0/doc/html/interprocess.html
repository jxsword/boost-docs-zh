构建 Boost.Interprocess
已测试的编译器

Boost.Interprocess 简化了常用进程间通信与同步机制的使用, 并提供了多种此类机制:

  • 共享内存.
  • 内存映射文件.
  • 信号量、互斥体、条件变量以及可升级互斥体类型, 可将它们放置在共享内存和内存映射文件中.
  • 上述同步对象的命名版本, 类似于 UNIX/Windows 的 sem_open/CreateSemaphore API.
  • 文件锁.
  • 相对指针.
  • 消息队列.

Boost.Interprocess 还提供更高级的进程间机制, 用于动态分配共享内存或内存映射文件的一部分 (通常用于分配固定大小内存段的一部分). 利用这些机制, Boost.Interprocess 提供实用的工具在共享内存和内存映射文件中构造 C++ 对象, 包括类似 STL 的容器:

  • 在共享内存或内存映射文件中动态创建匿名对象和命名对象.
  • 与共享内存/内存映射文件兼容的类似 STL 的容器.
  • 适用于共享内存/内存映射文件的类 STL 分配器, 实现了多种内存分配模式 (如内存池).

构建 Boost.Interprocess

无需编译 Boost.Interprocess, 因为它是一个仅头文件库. 只需把 Boost 头文件目录加入编译器包含路径即可.

Boost.Interprocess 依赖于 Boost.DateTime, 后者需要单独编译. 然而, Boost.Interprocess 所使用的子集不需要任何单独编译, 因此用户可以定义 BOOST_DATE_TIME_NO_LIB 以避免 Boost 尝试自动链接 Boost.DateTime.

在 POSIX 系统中, Boost.Interprocess 使用 pthread 系统调用来实现互斥体、条件变量等类. 在某些操作系统中, 这些 POSIX 调用实现在单独的库中, 编译器不会自动链接它们. 例如, 在某些 Linux 系统中, POSIX pthread 函数实现在 librt.a 库中, 因此在链接使用 Boost.Interprocess 的可执行文件或共享库时, 可能需要添加该库. 如果遇到与这些 pthread 函数相关的链接错误, 请查阅系统文档以了解是哪个库实现了它们.

已测试的编译器

Boost.Interprocess 已在以下编译器/平台上测试:

  • Visual C++ >= 7.1.
  • GCC >= 4.1.
警告

GCC < 4.3 和 MSVC < 9.0 已被弃用, 将在下一个版本中移除.
