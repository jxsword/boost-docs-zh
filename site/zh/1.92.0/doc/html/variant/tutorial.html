Basic Usage

通过用所需类型实例化 boost::variant 类模板, 定义了某组类型上的可辨识联合容器. 这些类型称为 有界类型, 并须满足 BoundedType 概念的要求. 可以指定任意数量的有界类型, 直至某个由实现定义的上限 (见 BOOST_VARIANT_LIMIT_TYPES).

例如, 下面在 int 与 std::string 上声明一个可辨识联合容器:

boost::variant< int, std::string > v;

默认情况下, variant 会默认构造其第一个有界类型, 因此 v 初始时包含 int(0). 若这不是所想要的, 或第一个有界类型不可默认构造, 则可以从任何可转换为其某个有界类型的值直接构造 variant. 类似地, 可以把任何可转换为其某个有界类型的值赋给 variant, 如下所示:

v = "hello";

现在 v 包含一个 std::string, 其值等于 "hello". 我们可以通过 流式输出 v 到标准输出来证明这一点:

std::cout << v << std::endl;

不过通常, 我们希望对 variant 的内容做比流式输出更多的事. 因此, 我们需要某种访问所含值的方式. 有两种途径: apply_visitor, 它最安全且非常强大; 以及 get<T>, 它有时使用起来更方便.

例如, 假设我们想把字符串拼接到 v 所含的字符串之后. 通过 取值 (get), 这可以非常简单地完成, 如下所示:

std::string& str = boost::get<std::string>(v);
str += " world! ";

正如所愿, std::string (由 v 所含) 现在等于 "hello world! ". 同样, 我们可以通过把 v 流式输出到标准输出来证明这一点:

std::cout << v << std::endl;

虽然在这个简单示例中使用 get 完全可以接受, 但 get 通常有若干重大缺陷. 例如, 如果我们编写一个接受 variant<int, std::string> 的函数, 我们将不知道传入的 variant 包含的是 int 还是 std::string. 如果我们坚持继续使用 get, 就需要查询 variant 的所含类型. 下面的函数对给定的 variant 的内容"加倍", 演示了这一方法:

void times_two( boost::variant< int, std::string > & operand )
{
    if ( int* pi = boost::get<int>( &operand ) )
        *pi *= 2;
    else if ( std::string* pstr = boost::get<std::string>( &operand ) )
        *pstr += *pstr;
}

然而, 这样的代码相当脆弱, 若不仔细留意, 很可能引入只能在运行期发现的隐蔽逻辑错误. 例如, 考虑如果我们想扩展 times_two 以操作带有更多有界类型的 variant. 具体来说, 让我们把 std::complex<double> 加入集合. 显然, 我们至少需要更改函数声明:

void times_two( boost::variant< int, std::string, std::complex<double> > & operand )
{
    // as above...?
}

当然, 还需要其他更改, 因为目前若传入的 variant 实际上包含一个 std::complex 值, times_two 会静默返回——没有任何预期的副作用, 也没有任何错误. 在这个例子中, 修复方法显而易见. 但在更复杂的程序中, 首先识别和定位错误就可能耗费相当长的时间.

因此, variant 的现实使用通常要求比 get 更健壮的访问机制. 出于这一原因, variant 支持编译期检查式 访问 (visitation) (经由 apply_visitor). 访问要求程序员显式处理 (或忽略) 每个有界类型. 若未做到, 将导致编译期错误.

访问 variant 需要一个访问器对象. 下面演示了一个这样的访问器实现, 其行为与 times_two 完全相同:

class times_two_visitor
    : public boost::static_visitor<>
{
public:

    void operator()(int & i) const
    {
        i *= 2;
    }

    void operator()(std::string & str) const
    {
        str += str;
    }

};

实现了上述访问器之后, 我们就可以把它应用于 v, 如下所示:

boost::apply_visitor( times_two_visitor(), v );

如预期, v 的内容现在是一个 std::string, 等于 "hello world! hello world! ". (这次我们省略验证.)

除了增强的健壮性之外, 访问相对 get 还有另一个重要优势: 能够编写泛型访问器. 例如, 下面的访问器将把 任何 variant 的内容"加倍" (前提是其每个有界类型都支持 operator+=):

class times_two_generic
    : public boost::static_visitor<>
{
public:

    template <typename T>
    void operator()( T & operand ) const
    {
        operand += operand;
    }

};

同样, apply_visitor 启动整个流程:

boost::apply_visitor( times_two_generic(), v );

虽然访问的初始建立成本可能超过 get 所需的成本, 但其好处很快就会变得显著. 在结束本节之前, 我们还应探讨使用 apply_visitor 进行访问的最后一个好处: 延迟访问. 也就是说, apply_visitor 的一种特殊形式可用, 它不会立即把给定访问器应用到任何 variant, 而是返回一个函数对象, 该对象可作用于交给它的任何 variant. 这一行为在处理 variant 类型序列时特别有用, 如下所示:

std::vector< boost::variant<int, std::string> > vec;
vec.push_back( 21 );
vec.push_back( "hello " );

times_two_generic visitor;
std::for_each(
      vec.begin(), vec.end()
   , boost::apply_visitor(visitor)
   );

本节讨论 variant 的高级用法经常需要的若干库特性. 与上一节不同, 下面介绍的每个特性基本彼此独立. 因此, 本节不必按顺序或完整阅读.

预处理器宏

虽然 variant 类模板的可变参数列表大大简化了模板特定实例化的使用, 但它显著增加了泛型实例化使用的复杂性. 例如, 虽然如何编写接受特定 variant 实例化 (比如 variant<int, std::string>) 的函数一目了然, 但如何编写接受任意给定 variant 的函数就不那么清楚了.

由于 C++98 标准缺乏对真正的可变模板参数列表的支持, 需要使用预处理器. 虽然 Preprocessor 库提供了通用而强大的解决方案, 但必须重复 BOOST_VARIANT_LIMIT_TYPES 会不必要地使原本简单的代码变得杂乱. 因此, 对于常见用例, 本库提供了自己的宏 BOOST_VARIANT_ENUM_PARAMS.

如下面的示例所示, 该宏为用户简化了在函数模板或类模板的显式偏特化中声明 variant 类型的过程:

// general cases
template <typename T> void some_func(const T &);
template <typename T> class some_class;

// function template overload
template <BOOST_VARIANT_ENUM_PARAMS(typename T)>
void some_func(const boost::variant<BOOST_VARIANT_ENUM_PARAMS(T)> &);

// explicit partial specialization
template <BOOST_VARIANT_ENUM_PARAMS(typename T)>
class some_class< boost::variant<BOOST_VARIANT_ENUM_PARAMS(T)> >;

使用类型序列指定有界类型

虽然 variant 类模板的可变模板参数列表对典型用途很方便, 但它在两个重要方面存在限制. 首先, 由于 C++ 缺乏对真正的可变模板参数列表的支持, 参数数量必须限制在某个由实现定义的最大值 (即 BOOST_VARIANT_LIMIT_TYPES). 其次, 参数列表的一般性质使得对列表的编译期操作异常困难.

为解决这些问题, make_variant_over< Sequence > 暴露了一个 variant, 其有界类型是 Sequence 的元素 (其中 Sequence 是任何满足 MPL Sequence 概念要求的类型). 例如,

typedef mpl::vector< std::string > types_initial;
typedef mpl::push_front< types_initial, int >::type types;

boost::make_variant_over< types >::type v1;

行为等价于

boost::variant< int, std::string > v2;

递归 variant 类型

递归类型——借助 recursive_wrapper
递归类型——借助 make_recursive_variant

递归类型有助于用简单语法构造复杂语义. 例如, 几乎每个程序员都熟悉链表实现的经典定义, 其简单定义允许任意长度的序列:

template <typename T>
struct list_node
{
    T data;
    list_node * next;
};

variant 作为泛型类模板的性质, 遗憾地妨碍了递归 variant 类型的直接构造. 考虑下面为简单数学表达式构造结构的尝试:

struct add;
struct sub;
template <typename OpTag> struct binary_op;

typedef boost::variant<
      int
    , binary_op<add>
    , binary_op<sub>
    > expression;

template <typename OpTag>
struct binary_op
{
    expression left;  // variant instantiated here...
    expression right;

    binary_op( const expression & lhs, const expression & rhs )
        : left(lhs), right(rhs)
    {
    }

}; // ...but binary_op not complete until here!

虽然用心良好, 但上述方法无法编译, 因为 binary_op 在 variant 类型 expression 被实例化时仍是不完整的. 此外, 该方法还有一个更严重的逻辑缺陷: 即使 C++ 语法有所不同, 使上述示例能够"工作", expression 也需要具有无限大小, 这显然是不可能的.

为了克服这些困难, variant 为 boost::recursive_wrapper 类模板提供了特殊支持, 打破了这些问题核心处的循环依赖. 此外, boost::make_recursive_variant 为声明递归 variant 类型提供了更方便的语法. 这些设施的使用教程见 "借助 recursive_wrapper 的递归类型"一节 和 "借助 make_recursive_variant 的递归类型"一节.

借助 recursive_wrapper 的递归类型

下面的示例演示如何用 recursive_wrapper 解决 "递归 variant 类型"一节 中提出的问题:

typedef boost::variant<
      int
    , boost::recursive_wrapper< binary_op<add> >
    , boost::recursive_wrapper< binary_op<sub> >
    > expression;

由于 variant 为 recursive_wrapper 提供了特殊支持, 客户代码可以如同包装器不存在一样对待最终的 variant. 这在下面访问器的实现中可见, 它计算一个 expression 的值, 而完全没有引用 recursive_wrapper:

class calculator : public boost::static_visitor<int>
{
public:

    int operator()(int value) const
    {
        return value;
    }

    int operator()(const binary_op<add> & binary) const
    {
        return boost::apply_visitor( calculator(), binary.left )
             + boost::apply_visitor( calculator(), binary.right );
    }

    int operator()(const binary_op<sub> & binary) const
    {
        return boost::apply_visitor( calculator(), binary.left )
             - boost::apply_visitor( calculator(), binary.right );
    }

};

最后, 我们可以演示 expression 的实际运作:

void f()
{
    // result = ((7-3)+8) = 12
    expression result(
        binary_op<add>(
            binary_op<sub>(7,3)
          , 8
          )
      );

    assert( boost::apply_visitor(calculator(),result) == 12 );
}

性能: boost::recursive_wrapper 没有空状态, 这使其移动构造函数不太理想. 在兼容 C++11 的编译器上, 可考虑使用 std::unique_ptr 或其他安全指针以获得更好的性能.

借助 make_recursive_variant 的递归类型

对于递归 variant 类型的某些应用, 用户可能愿意牺牲将 recursive_wrapper 与 variant 一起使用所需的完全灵活性, 以换取以下便捷语法:

typedef boost::make_recursive_variant<
      int
    , std::vector< boost::recursive_variant_ >
    >::type int_tree_t;

所得 variant 类型的使用与预期一致:

std::vector< int_tree_t > subresult;
subresult.push_back(3);
subresult.push_back(5);

std::vector< int_tree_t > result;
result.push_back(1);
result.push_back(subresult);
result.push_back(7);

int_tree_t var(result);

需要说明的是, var 所得的内容可以表示为 ( 1 ( 3 5 ) 7 ).

最后, 注意递归 variant 的有界类型可以借助 boost::make_recursive_variant_over 通过类型序列来指定, 其语义与 make_variant_over 相同 (在 "使用类型序列指定有界类型"一节 中描述).

可移植性: 遗憾的是, 由于若干编译器的标准符合性问题, 并非所有编译器都支持 make_recursive_variant. 在这些编译器上, 本库通过定义预处理符号 BOOST_VARIANT_NO_FULL_RECURSIVE_VARIANT_SUPPORT 来表明缺乏支持. 因此, 除非使用高度符合标准的编译器, 否则改用 recursive_wrapper 将获得最大的可移植性, 如 "借助 recursive_wrapper 的递归类型"一节 所述.

二元访问

正如上面的教程所示, 访问是操作 variant 内容的强大机制. 二元访问通过允许同时访问两个不同 variant 对象的内容, 进一步扩展了访问的能力和灵活性.

值得注意的是, 该特性要求二元访问器与上面教程中讨论的访问器对象不兼容, 因为它们必须操作两个实参. 下面演示一个二元访问器的实现:

class are_strict_equals
    : public boost::static_visitor<bool>
{
public:

    template <typename T, typename U>
    bool operator()( const T &, const U & ) const
    {
        return false; // cannot compare different types
    }

    template <typename T>
    bool operator()( const T & lhs, const T & rhs ) const
    {
        return lhs == rhs;
    }

};

如预期, 访问器通过 variant 被应用于两个 apply_visitor 实参:

boost::variant< int, std::string > v1( "hello" );

boost::variant< double, std::string > v2( "hello" );
assert( boost::apply_visitor(are_strict_equals(), v1, v2) );

boost::variant< int, const char * > v3( "hello" );
assert( !boost::apply_visitor(are_strict_equals(), v1, v3) );

最后, 我们必须指出, 从 apply_visitor 的"延迟"形式返回的函数对象也支持二元访问, 如下所示:

typedef boost::variant<double, std::string> my_variant;

std::vector< my_variant > seq1;
seq1.push_back("pi is close to ");
seq1.push_back(3.14);

std::list< my_variant > seq2;
seq2.push_back("pi is close to ");
seq2.push_back(3.14);

are_strict_equals visitor;
assert( std::equal(
      seq1.begin(), seq1.end(), seq2.begin()
    , boost::apply_visitor( visitor )
    ) );

多重访问

多重访问通过允许同时访问三个及以上不同 variant 对象的内容, 扩展了访问的能力和灵活性. 注意, 多重访问器的头文件需要单独包含.

值得注意的是, 该特性要求多重访问器与上面教程中讨论的访问器对象不兼容, 因为它们必须操作与传给 apply_visitor 相同数量的实参. 下面演示一个用于三个参数的多重访问器的实现:

#include <boost/variant/multivisitors.hpp>

typedef boost::variant<int, double, bool> bool_like_t;
typedef boost::variant<int, double> arithmetics_t;

struct if_visitor: public boost::static_visitor<arithmetics_t> {
    template <class T1, class T2>
    arithmetics_t operator()(bool b, T1 v1, T2 v2) const {
        if (b) {
            return v1;
        } else {
            return v2;
        }
    }
};

如预期, 访问器通过 variant 被应用于三个 apply_visitor 实参:

bool_like_t v0(true), v1(1), v2(2.0);

assert(
    boost::apply_visitor(if_visitor(), v0, v1, v2)
    ==
    arithmetics_t(1)
);
