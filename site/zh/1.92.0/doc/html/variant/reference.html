BoundedType

有界类型 的要求如下:

  • CopyConstructible 或 MoveConstructible.
  • 析构函数必须满足不抛异常的异常安全保证.
  • 在 variant 模板实例化点必须是完整类型. (接受不完整类型的类型包装器见 boost::recursive_wrapper<T>, 它可用于实现递归 variant 类型.)

指定为 variant 模板实参的每个类型至少必须满足上述要求. 此外, 仅当其有界类型满足以下附加概念的要求时, variant 的某些特性才可用:

  • Assignable: 当且仅当其每个有界类型都满足该概念的要求时, variant 本身才是 Assignable. (注意, 顶层 const 限定类型和引用类型 不 满足这些要求.)
  • MoveAssignable: 当且仅当其每个有界类型都满足该概念的要求时, variant 本身才是 MoveAssignable. (注意, 顶层 const 限定类型和引用类型 不 满足这些要求.)
  • DefaultConstructible [20.1.4]: variant 本身是 DefaultConstructible, 当且仅当其第一个有界类型 (即 T1) 满足该概念的要求.
  • EqualityComparable: 当且仅当其每个有界类型都满足该概念的要求时, variant 本身才是 EqualityComparable.
  • LessThanComparable: 当且仅当其每个有界类型都满足该概念的要求时, variant 本身才是 LessThanComparable.
  • OutputStreamable: 当且仅当其每个有界类型都满足该概念的要求时, variant 本身才是 OutputStreamable.
  • Hashable: 当且仅当其每个有界类型都满足该概念的要求时, variant 本身才是 Hashable.

StaticVisitor

示例

静态访问器 (针对类型 T) 的要求如下:

  • 必须能通过重载 operator() 像函数一样调用, 并无歧义地接受任何 T 类型的值.
  • 必须暴露内部类型 result_type. 兼容 C++14 的编译器可以自动检测 result_type, 但若定义了 result_type 则沿用之. (把函数用作访问器的解决方案见 boost::visitor_ptr.)
  • 若 result_type 不是 void, 则函数对象的每个操作都必须返回可隐式转换为 result_type 的值.
示例

下面的类满足多个类型的静态访问器要求 (即显式地: int 与 std::string; 或者例如隐式地: short 与 const char *; 等等):

class my_visitor
    : public boost::static_visitor<int>
{
public:

    int operator()(int i)
    {
        return i * 2;
    }

    int operator()(const std::string& s)
    {
        return s.length();
    }

};

另一个例子是下面的类, 其函数调用运算符是成员模板, 使它能操作多种类型的值. 因此, 下面的类是任何支持流式输出的类型 (例如 int、double、std::string 等) 的访问器:

class printer
    : public boost::static_visitor<>
{
    template <typename T>
    void operator()(const T& t)
    {
        std::cout << t << std::endl;
    }
};

兼容 C++14 的编译器会自动检测 result_type:

    boost::variant<int, float> v;
    // ...

    boost::apply_visitor(
        [](auto val) { return std::to_string(val); },
        v
    );

OutputStreamable

输出流式 类型 T 的要求如下:

  • 对任何对象 t (其类型为 T), std::cout << t 必须是合法表达式.

Hashable

可哈希 类型 T 的要求如下:

  • 对任何对象 t (其类型为 T), boost::hash<T>()(t) 必须是合法表达式.

头文件 <boost/variant.hpp>

此头文件的存在只是为用户提供便利, 它包含了 boost/variant 目录中除 <boost/multivisiors.hpp> 之外的所有头文件.

头文件 <boost/variant/variant_fwd.hpp>

提供 boost::variant、boost::make_variant_over、boost::make_recursive_variant 与 boost::make_recursive_variant_over 类模板以及 boost::recursive_variant_ 标签类型的前置声明. 还定义了若干预处理符号, 如下所述.


BOOST_VARIANT_ENUM_PARAMS(param)
BOOST_VARIANT_ENUM_SHIFTED_PARAMS(param)
BOOST_VARIANT_DO_NOT_SPECIALIZE_STD_HASH
BOOST_VARIANT_NO_FULL_RECURSIVE_VARIANT_SUPPORT
