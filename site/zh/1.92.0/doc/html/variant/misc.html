Boost.Variant 与 Boost.Any 的比较

作为可辨识联合容器, Variant 库与 Any 库有许多相同的特性. 然而, 由于两个库都不能完全涵盖对方的功能, 无法笼统地推荐使用其中一个而不使用另一个.

话虽如此, Boost.Variant 相对 Boost.Any 有几个优势, 例如:

  • Boost.Variant 保证其内容的类型是有限的、用户指定的一组类型之一.
  • Boost.Variant 提供对其内容的 编译期 检查式访问 (visitation). (相比之下, 当前版本的 Boost.Any 完全不提供访问机制; 即使提供, 也需要在运行期检查.)
  • Boost.Variant 支持对其内容的泛型访问. (即使 Boost.Any 提供了访问机制, 它也只能对显式指定的类型进行访问.)
  • Boost.Variant 提供高效的、基于栈的存储方案 (避免了动态分配的开销).

当然, Boost.Any 相对 Boost.Variant 也有几个优势, 例如:

  • Boost.Any 正如其名, 几乎允许任何类型作为其内容, 提供极大的灵活性.
  • Boost.Any 为其 swap 操作提供不抛异常的异常安全保证.
  • Boost.Any 很少使用模板元编程技术 (避免了可能难以阅读的错误信息和显著的编译期处理器与内存需求).

可移植性

本库力求 100% 符合 ANSI/ISO C++. 然而, 由于 Type Traits 库的 type_with_alignment 设施本质上不可移植, 这一点严格来说是不可能完全做到的. 不过在实践中, 尚未发现有任何编译器或平台因这种对未定义行为的依赖而出现问题.

此外, 人们付出了大量努力, 以确保在各种编译器缺陷和其他符合性问题面前仍能正常工作. 迄今为止, 本库测试套件至少已在以下编译器上成功编译并通过基本和高级功能的测试:

故障排除

"模板实例化深度超过最大值"
"达到内部堆上限"

由于 variant 的实现大量使用模板, 编译时遇到与模板实例化深度、编译器内存等相关的问题并不罕见. 本节尝试为几种流行编译器上遇到的常见问题提供建议.

(本节仍在编写中, 欢迎提供更多建议/反馈. 若有任何有用的经验, 请发布到 Boost-Users 邮件列表.)

"模板实例化深度超过最大值"

GNU GCC
GNU GCC

编译器选项 -ftemplate-depth-NN 可以提高允许的最大实例化深度. (试试 -ftemplate-depth-50.)

"达到内部堆上限"

Microsoft Visual C++
Microsoft Visual C++

编译器选项 /ZmNNN 可以提高内存分配上限. NNN 是一个缩放百分比 (即 100 表示默认上限). (试试 /Zm200.)
