Boost.Intrusive 容器概览

Boost.Intrusive 提供了多种侵入式容器:

  • slist: 侵入式单链表. 对用户类的体积开销很小 (通常为一个指针的大小), 但许多操作具有线性时间复杂度, 因此如果用户想避免性能问题, 必须小心.
  • list: 类似 std::list 的侵入式链表. 对用户类的体积开销相当小 (通常为两个指针的大小). 许多操作具有常数时间复杂度.
  • set/multiset/rbtree: 类似 std::set/std::multiset 的基于红黑树的侵入式关联容器. 对用户类的体积开销适中 (通常为三个指针的大小). 许多操作具有对数时间复杂度.
  • avl_set/avl_multiset/avltree: 类似 std::set/std::multiset 的基于 AVL 树的侵入式关联容器. 对用户类的体积开销适中 (通常为三个指针的大小). 许多操作具有对数时间复杂度.
  • splay_set/splay_multiset/splaytree: 类似 std::set/std::multiset 的基于 splay 树的侵入式关联容器. splay 树没有常数时间操作, 但具有一些有趣的缓存特性. 对用户类的体积开销适中 (通常为三个指针的大小). 许多操作具有对数时间复杂度.
  • sg_set/sg_multiset/sgtree: 类似 std::set/std::multiset 的基于替罪羊树的侵入式关联容器. 替罪羊树可以用所需的平衡因子进行配置, 以达到所需的再平衡频率/搜索时间折衷. 对用户类的体积开销适中 (通常为三个指针的大小). 许多操作具有对数时间复杂度.

Boost.Intrusive 还提供了半侵入式容器:

  • unordered_set/unordered_multiset: 类似 std::tr1::unordered_set/std::tr1::unordered_multiset 的侵入式无序关联容器. 对用户类的体积开销适中 (平均每个元素两个指针). 许多操作具有均摊常数时间复杂度.

这些侵入式容器中的大多数都可以配置为常数时间 size 或线性时间 size:

  • 线性时间 size: 侵入式容器不保存随每次插入/擦除更新的 size 成员. 这意味着 size() 函数不具有常数时间复杂度. 另一方面, 容器更小, 而且某些操作 (例如链表中接受迭代器范围的 splice()) 具有常数时间复杂度而非线性复杂度.
  • 常数时间 size: 侵入式容器保存一个随每次插入/擦除更新的 size 成员. 这意味着 size() 函数具有常数时间复杂度. 另一方面, 这增大了容器的体积, 而且某些操作 (例如接受迭代器范围的 splice()) 在链表中具有线性时间复杂度.

为了使用户类与这些侵入式容器兼容, Boost.Intrusive 为每种容器类型提供了两种钩子:

  • 基类钩子: 钩子作为用户类的公有基类存储.
  • 成员钩子: 钩子作为用户类的公有成员存储.

除此之外, Boost.Intrusive 还提供了额外特性:

  • 安全模式钩子: 钩子构造函数将内部 node 初始化为一个已知的安全状态, 侵入式容器在使用该钩子向容器插入值之前会检查该状态. 当从容器中擦除元素时, 容器会将钩子的 node 重新置于安全状态. 这允许一种更安全的使用模式, 并可用于检测编程错误. 它在某些操作中意味着轻微的性能开销, 并可能将某些常数时间操作转换为线性时间操作.
  • 自动断链钩子: 钩子析构函数会自动从容器中移除对象, 用户可以在不引用容器的情况下安全地将对象从容器中断链.
  • 非裸指针: 如果用户想使用智能指针而非裸指针, Boost.Intrusive 钩子可以配置为使用任何类型的指针. 该配置信息也会传递到容器, 因此使用这些钩子配置的侵入式容器所用的所有内部指针都将是智能指针. 例如, Boost.Interprocess 定义了一种与共享内存兼容的智能指针, 称为 offset_ptr. Boost.Intrusive 可以配置为使用这种智能指针, 以支持共享内存侵入式容器.
