如何使用 Boost.Intrusive

如果计划将一个类插入侵入式容器, 你必须做出一些影响类定义本身的决定. 每个将用于侵入式容器的类都需要一些适当的数据成员来存储容器所需的信息. 在下面的示例中, 我们将以一个简单的侵入式容器——侵入式链表 (boost::intrusive::list) 为例, 但所有 Boost.Intrusive 容器都非常相似. 要使用 boost::intrusive::list 编译示例, 只需包含:

#include <boost/intrusive/list.hpp>

每个要插入侵入式容器的类都需要包含一个钩子, 该钩子将提供可插入容器所需的数据和资源. 使用 Boost.Intrusive, 你只需选择将钩子作为待插入类的公有基类或公有成员. Boost.Intrusive 还为高级用户提供了更灵活的钩子, 如 使用函数钩子 一章所述, 但通常基类钩子或成员钩子对大多数用户来说已经足够.

使用基类钩子

对于 list, 你可以公开派生自 list_base_hook.

template <class ...Options>
class list_base_hook;

该类可以接受多个选项. Boost.Intrusive 类以 option_name<option_value> 的形式接收参数. 你可以指定以下选项:

  • tag<class Tag>: 该参数用作标签 (tag), 因此可以从多个 list_base_hook 派生, 从而将一个对象同时放入多个侵入式链表. 不完整类型可以用作标签. 如果指定两个基类钩子, 你 必须 为每个钩子指定不同的标签. 示例: list_base_hook< tag<tag1> >. 如果未指定标签, 将使用默认标签 (稍后详细介绍默认标签).
  • link_mode<link_mode_type LinkMode>: 第二个模板参数控制链接策略. Boost.Intrusive 目前支持 3 种模式: normal_link, safe_link 和 auto_unlink. 默认使用 safe_link 模式. 更多信息参见 安全钩子 和 自动断链钩子 各节. 示例: list_base_hook< link_mode<auto_unlink> >
  • void_pointer<class VoidPointer>: 该选项是钩子内部使用的指针类型. 默认值为 void *, 即钩子中将使用裸指针. 更多信息参见题为 在 Boost.Intrusive 容器中使用智能指针 的一节. 示例: list_base_hook< void_pointer< my_smart_ptr<void> >

对于以下示例, 我们暂且忘掉这些选项, 使用默认值:

#include <boost/intrusive/list.hpp>

using namespace boost::intrusive;

class Foo
   //Base hook with default tag, raw pointers and safe_link mode
   :  public list_base_hook<>
{ /**/ };

之后, 我们可以定义侵入式链表:

template <class T, class ...Options>
class list;

list 接受要插入容器的类型 (T) 作为第一个参数, 用户还可以可选地指定选项. 我们有 3 种选项类型:

  • base_hook<class Hook> / member_hook<class T, class Hook, Hook T::* PtrToMember> / value_traits<class ValueTraits>: 所有这些选项指定要插入链表的类型 T 与钩子之间的关系 (因为同一个 T 类型中可以有多个钩子). member_hook 稍后解释, value_traits 将在 具有自定义 ValueTraits 的容器 一节中解释. 如果未指定任何选项, 容器将被配置为使用带默认标签的基类钩子. 为钩子配置的一些选项 (指针类型, 链接模式等) 将传播到容器.
  • constant_time_size<bool Enabled>: 指定容器是否要求常数时间 size() 函数. 这将指示侵入式容器存储一个额外成员以跟踪容器的当前大小. 默认激活常数时间 size.
  • size_type<class SizeType>: 指定一个能够容纳容器大小的无符号类型. 该类型将是 list.size() 返回的类型, 并且在请求 constant_time_size<true> 时是存储在侵入式容器中的类型. 用户通常不需要更改此类型, 但某些容器的 size_type 可能与 std::size_t 不同 (例如, STL 式容器使用由其分配器定义的 size_type). Boost.Intrusive 可以通过指定 size 的类型来实现这类容器. 默认类型为 std::size_t.

使用带默认标签的基类钩子, 存储将保存 Foo 对象的常数时间 size 侵入式链表的示例:

typedef list<Foo> FooList;

存储将保存 Foo 对象的非常数时间 size 侵入式链表的示例:

typedef list<Foo, constant_time_size<false> > FooList;

请记住, 如果基类钩子没有默认标签, 用户必须在容器声明中指定该基类钩子, 因为这通常意味着该类型有多个基类钩子, 而容器必须知道将使用哪个钩子:

#include <boost/intrusive/list.hpp>

using namespace boost::intrusive;

struct my_tag1;
struct my_tag2;

typedef list_base_hook< tag<my_tag1> > BaseHook;
typedef list_base_hook< tag<my_tag2> > BaseHook2;
class Foo   :  public BaseHook, public BaseHook2
{ /**/ };

typedef list< Foo, base_hook<BaseHook>  > FooList;
typedef list< Foo, base_hook<BaseHook2> > FooList2;

定义链表之后, 我们就可以使用它:

//An object to be inserted in the list
Foo foo_object;
FooList list;

list.push_back(object);

assert(&list.front() == &foo_object);

使用成员钩子

有时, 链表钩子与链表值类型之间的 'is-a' (是一个) 关系并不理想. 在这种情况下, 使用成员钩子作为数据成员而不是 '干扰' 继承层次可能是正确的方式: 你可以向类添加一个公有数据成员 list_member_hook<...>. 该类可以用与 list_base_hook 相同的选项进行配置, 但选项 tag 除外:

template <class ...Options>
class list_member_hook;

示例:

#include <boost/intrusive/list.hpp>

class Foo
{
   public:
   list_member_hook<> hook_;
   //...
};

使用成员钩子时, 使用 member_hook 选项来配置链表:

//This option will configure "list" to use the member hook
typedef member_hook<Foo, list_member_hook<>, &Foo::hook_> MemberHookOption;

//This list will use the member hook
typedef list<Foo, MemberHookOption> FooList;

现在我们可以使用容器:

//An object to be inserted in the list
Foo foo_object;
FooList list;

list.push_back(object);

assert(&list.front() == &foo_object);

不过, 成员钩子有一些实现上的限制: 如果父类与成员钩子之间存在虚继承关系, 那么父类与钩子之间的距离不是编译期固定值, 因此若不逆向工程编译器产生的 RTTI, 就无法从成员钩子获得父对象的地址. 除此之外, 对于具有复杂继承关系的类, 与 MSVC ABI 兼容的编译器采用的非标准成员指针实现不受成员钩子支持, 因为它同样依赖编译器产生的 RTTI 信息.

同时使用两种钩子

你可以使用每个容器一个钩子的方式, 将同一个对象同时插入多个侵入式容器. 下面是一个同时使用基类钩子和成员钩子的完整示例:

#include <boost/intrusive/list.hpp>
#include <vector>

using namespace boost::intrusive;

class MyClass : public list_base_hook<>
{
   int int_;

   public:
   list_member_hook<> member_hook_;

   MyClass(int i) :  int_(i)  {}
};

//Define a list that will store MyClass using the base hook
typedef list<MyClass> BaseList;

//Define a list that will store MyClass using the member hook
typedef member_hook
   < MyClass, list_member_hook<>, &MyClass::member_hook_> MemberOption;
typedef list<MyClass, MemberOption> MemberList;

int main()
{
   typedef std::vector<MyClass>::iterator VectIt;

   //Create several MyClass objects, each one with a different value
   std::vector<MyClass> values;
   for(int i = 0; i < 100; ++i)  values.push_back(MyClass(i));

   BaseList baselist;
   MemberList memberlist;

   //Now insert them in the reverse order in the base hook list
   for(VectIt it(values.begin()), itend(values.end())
      ; it != itend  ; ++it){
      baselist.push_front(*it);
   }

   //Now insert them in the same order as in vector in the member hook list
   for(VectIt it(values.begin()), itend(values.end()); it != itend; ++it)
      memberlist.push_back(*it);

   //Now test lists
   {
      BaseList::reverse_iterator rbit(baselist.rbegin());
      MemberList::iterator mit(memberlist.begin());
      VectIt  it(values.begin()), itend(values.end());

      //Test the objects inserted in the base hook list
      for(; it != itend; ++it, ++rbit)
         if(&*rbit != &*it)   return 1;

      //Test the objects inserted in the member hook list
      for(it = values.begin(); it != itend; ++it, ++mit)
         if(&*mit != &*it)    return 1;
   }

   return 0;
}

对象生命周期

尽管 list 的接口类似于 std::list, 但它的用法略有不同: 你必须始终记住, 你在侵入式容器中直接存储的是对象, 而不是副本. 被存储对象的生命周期不绑定到容器, 也不由容器管理:

  • 当容器在对象之前被销毁时, 对象不会被销毁, 因此必须小心避免资源泄漏.
  • 当对象在容器之前被销毁时, 程序很可能会崩溃, 因为容器中包含一个指向已不存在对象的指针.
