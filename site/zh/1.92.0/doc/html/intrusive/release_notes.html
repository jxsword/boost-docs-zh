Boost 1.91 发布

  • 如果 C++20 概念可用, 使用 normal_link 的钩子和容器现在使用 defaulted 析构函数. 如果内部使用的节点和比较对象是平凡可析构的, 这使得钩子和容器也可以平凡析构.
  • 如果 C++20 概念可用, 使用 normal_link 的钩子现在使用 defaulted 构造函数. 如果内部使用的节点是平凡可析构的, 这使得钩子可以平凡默认构造.
  • 更新了 list 和 slist 成员的 remove_xx 和 unique_xxx 方法, 使其返回被移除元素的数量, 以遵循 C++20 对 std::list 的修改.
  • 已修复的缺陷:
    • GitHub #92: 某些侵入式容器在可能时并非平凡可析构
    • GitHub #103: C++17: 当销毁函数带有 noexcept 说明符时出现编译错误
    • GitHub #105: 简化 ebo_function_holder

Boost 1.85 发布

  • 已修复的缺陷:
    • GitHub #81: unordered_set 的 rehash 会破坏 insert_commit_data
    • GitHub #83: [文档] 缺少索引
  • 潜在破坏性变更: 无序容器现在默认使用一个与 boost::hash 协议兼容的内部哈希仿函数.
    • 原因:
      • 自 Boost 1.84 起, Boost.ContainerHash 要求 C++11, 这破坏了 Boost.Intrusive 的 C++03 用户.
      • 为了避免对 Boost.ContainerHash 的头文件包含依赖, 该依赖还会间接引入其他库 (Boost.Describe, Boost.Mp11...).
    • 新的默认哈希函数:
      • 直接处理标量类型 (以防标量类型与 key_of_value 一起使用), 使用平凡哈希 (类似于 boost::hash).
      • 对于其他类型 (大多数 Boost.Intrusive 用户属于这种情况), 使用基于 ADL 的 hash_function 调用, 就像 boost::hash 一样.
      • 如果该 ADL 查找失败, 则前置声明 boost::hash 并通过该类型的对象进行调用. 如果用户在包含 Boost.Intrusive 之前或之后包含了 boost/container_hash/hash.hpp, boost::hash 将被正确调用.
    • 一些 Boost.Intrusive 用户可能在未包含所需的 boost/container_hash/hash.hpp 头文件的情况下使用了 Boost.ContainerHash 的函数/特性, 因为它是通过 Boost.Intrusive 间接包含的. 这些用户将需要显式包含 boost/container_hash/hash.hpp 以获得 Boost.ContainerHash 的特性.
  • Boost.Intrusive 不再依赖 Boost.StaticCast.

Boost 1.56 发布

  • 改进了 Doxygen 生成的参考手册, 并更新和修复了前置声明头文件.
  • 破坏 ABI: 修复了 Boost 1.55 版本引入的 ABI 回归, 主要在 MSVC 编译器上明显.
  • 破坏源代码兼容性: 移除了之前弃用的 xxx_dont_splay 函数 (来自 splay 容器), 以及 splay 容器的 splay_set_base_hook 和 splay_set_member_hook, 还有 bool splay = true 额外参数 (在 splaytree_algorithms 函数中).
  • 已修复的缺陷:
    • #8468: 在 Visual Studio 2010/2012 上使用带自定义分配器和对齐类型的 vector 时出现编译错误
    • #9332: "has_member_function_callable_with.hpp 在 msvc-12.0 上的编译错误".
    • #9650: "带状态值特征的侵入式链表".
    • #9746: 现代 Sun CC 编译器检测到侵入式库头文件中的错误
    • #9940: 使用 safe_link (或 auto_unlink) 钩子的侵入式链表中的严重缺陷
    • #9948: 移除侵入式容器中 const_cast 的使用
    • #9949: 在侵入式容器销毁时清除头节点钩子
    • #9961: 针对并非派生自 generic_hook 的钩子的测试
  • 优化了树的再平衡代码, 以避免冗余赋值.
  • 在 64 位平台上为 suggested_upper_bucket_count/suggested_lower_bucket_count 添加了 64 位素数值.
  • 删除了针对旧 SUN_CC 编译器的变通方案, 这些编译器现已不受支持, 因为现代 SunPro 编译器已足够符合标准.

Boost 1.55 发布

  • 破坏源代码兼容性: 弃用了 splay 容器的 xxx_dont_splay 函数. 弃用了 splay 容器的 splay_set_base_hook 和 splay_set_member_hook, 请改用 bs_set_base_hook 或 bs_set_member_hook. 两者将在 Boost 1.56 中移除.
  • 破坏 ABI: 哈希容器的尾迭代器之前的实现是指向桶数组末尾之后的位置 (参见 #8698), 当要插入的值被分配在桶数组旁边时会导致严重缺陷. 尾迭代器的实现已改为指向桶数组的开头.
  • 进行了大规模重构, 以减少模板和调试符号膨胀. 在 MSVC 编译器的 Debug 模式下, 测试目标文件已被削减一半. 没有 Identical COMDAT Folding (ICF) 的工具链应该会注意到体积的改善.
  • 实现了 SCARY 迭代器.
