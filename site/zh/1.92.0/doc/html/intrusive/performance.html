结论

与非侵入式容器相比, Boost.Intrusive 容器提供速度改进的主要原因在于:

  • 它们将内存分配/释放调用降到最少.
  • 它们获得更好的内存局部性.

本节将展示对比 boost::intrusive::list 与 std::list 上若干操作的性能测试:

  • 使用 push_back 的插入和容器销毁将展示与内存分配/释放相关的开销.
  • reverse 成员函数将展示侵入式容器所能实现的紧凑内存表示的优势.
  • sort 和 write access 测试将展示侵入式容器相比指针容器减少内存访问的优势.

给定一个 T 类型的对象, boost::intrusive::list<T> 可以替代 std::list<T> 以避免内存分配开销; 当用户想要多态值的容器或想在多个容器之间共享值时, 它也可以替代 std::list<T*>. 由于这种多功能性, 性能测试将对 6 种不同的链表类型执行:

  • 3 个侵入式链表保存名为 itest_class 的类, 每个链表使用不同的链接策略 (normal_link, safe_link, auto_unlink). itest_class 对象将紧密打包在一个 std::vector<itest_class> 对象中.
  • std::list<test_class>, 其中 test_class 与 itest_class 完全相同, 但没有侵入式钩子.
  • std::list<test_class*>. 该链表将包含指向 test_class 对象的指针, 这些对象紧密打包在一个 std::vector<test_class> 对象中. 我们将这种配置称为 紧凑指针链表
  • std::list<test_class*>. 该链表将包含指向 test_class 对象的指针, 这些对象由一个 std::list<test_class> 对象持有. 我们将这种配置称为 分散指针链表.

test_class 和 itest_class 都是模板类, 可以用一个布尔值进行配置以增大对象体积. 这样, 测试就可以用小对象和大对象来执行. 下面是测试代码的第一部分, 展示了 test_class 和 itest_class 类的定义以及一些其他实用工具:

//Iteration and element count defines
const int NumIter = 4;
const int NumElements   = 50000;

using namespace boost::intrusive;

template<bool BigSize>  struct filler        {  int dummy[10];   };
template <>             struct filler<false> {};

template<bool BigSize> //The object for non-intrusive containers
struct test_class :  private filler<BigSize>
{
   int i_;
   test_class()               {}
   test_class(int i) :  i_(i) {}
   friend bool operator <(const test_class &l, const test_class &r)  {  return l.i_ < r.i_;  }
   friend bool operator >(const test_class &l, const test_class &r)  {  return l.i_ > r.i_;  }
};

template <bool BigSize, link_mode_type LinkMode>
struct itest_class   //The object for intrusive containers
   :  public list_base_hook<link_mode<LinkMode> >,  public test_class<BigSize>
{
   itest_class()                                {}
   itest_class(int i) : test_class<BigSize>(i)  {}
};

template<class FuncObj> //Adapts functors taking values to functors taking pointers
struct func_ptr_adaptor  :  public FuncObj
{
   typedef typename FuncObj::first_argument_type*  first_argument_type;
   typedef typename FuncObj::second_argument_type* second_argument_type;
   typedef typename FuncObj::result_type           result_type;
   result_type operator()(first_argument_type a,  second_argument_type b) const
      {  return FuncObj::operator()(*a, *b); }
};

如我们所见, test_class 是一个非常简单的类, 持有一个 int. itest_class 只是一个具有基类钩子 (list_base_hook) 并且还派生自 test_class 的类.

func_ptr_adaptor 只是一个仿函数适配器, 用于将接受 test_list 对象的函数对象转换为接受指向这些对象的指针的函数对象.

完整测试代码可在 perf_list.cpp 源文件中找到.

后插入与销毁

第一个测试将衡量侵入式容器通过避免内存分配和释放所能带来的收益. 所有要插入侵入式容器的对象都在一次分配调用中分配, 而 std::list 则需要为每个对象分配内存, 并在每次擦除 (或容器销毁) 时释放它.

让我们比较不同插入测试中每种容器类型要执行的代码:

std::vector<typename ilist::value_type> objects(NumElements);
ilist l;
for(int i = 0; i < NumElements; ++i)
   l.push_back(objects[i]);
//Elements are unlinked in ilist's destructor
//Elements are destroyed in vector's destructor

对于侵入式容器, 所有值先在 vector 中创建, 然后插入侵入式链表.

stdlist l;
for(int i = 0; i < NumElements; ++i)
   l.push_back(typename stdlist::value_type(i));
//Elements unlinked and destroyed in stdlist's destructor

对于标准链表, 使用 push_back() 将元素压入末尾.

std::vector<typename stdlist::value_type> objects(NumElements);
stdptrlist l;
for(int i = 0; i < NumElements; ++i)
   l.push_back(&objects[i]);
//Pointers to elements unlinked and destroyed in stdptrlist's destructor
//Elements destroyed in vector's destructor

对于标准紧凑指针链表, 元素先在 vector 中创建, 然后使用 push_back() 压入指针链表的末尾.

stdlist objects;  stdptrlist l;
for(int i = 0; i < NumElements; ++i){
   objects.push_back(typename stdlist::value_type(i));
   l.push_back(&objects.back());
}
//Pointers to elements unlinked and destroyed in stdptrlist's destructor
//Elements unlinked and destroyed in stdlist's destructor

对于 分散指针链表, 元素先在一个链表中创建, 然后使用 push_back() 压入指针链表的末尾.

结果合乎逻辑: 侵入式链表只需要一次分配. normal_link 侵入式容器的销毁时间微不足道 (复杂度: O(1)), 而 safe_link 和 auto_unlink 侵入式容器需要将被擦除值的钩子置于默认状态 (复杂度: O(NumElements)). 这就是 normal_link 侵入式链表在此测试中表现出色的原因.

非侵入式容器需要进行多得多的分配, 这就是它们落后于人的原因. disperse pointer list 需要进行 NumElements*2 次分配, 所以这个结果并不令人意外.

Linux 测试表明, 对于大对象, 标准容器面对侵入式容器表现非常好. 在 MinGW 上几乎相同的 GCC 版本表现较差, 因此优秀的内存分配器可能是这些出色结果的原因.

对于小对象, 结果表明侵入式容器中值的紧凑存储改善了局部性, 反转比标准容器更快, 而标准容器的值可能分散在内存中, 因为每个值都是独立分配的. 注意, 分散指针链表 (指向另一个链表中分配的值的指针链表) 受到的影响更大, 因为指针链表的节点可能更加分散, 因为代码中来自两个链表的分配是交错进行的:

//Object list (holding `test_class`)
stdlist objects;

//Pointer list (holding `test_class` pointers)
stdptrlist l;

for(int i = 0; i < NumElements; ++i){
   //Allocation from the object list
   objects.push_back(stdlist::value_type(i));
   //Allocation from the pointer list
   l.push_back(&objects.back());
}

对于大对象, 紧凑指针链表获胜, 因为反转测试不需要访问存储在另一个容器中的值. 由于这个指针链表节点的所有分配可能彼此靠近 (因为在创建指针链表之前进程中没有其他分配), 其局部性优于侵入式容器. 与小值时一样, 分散指针链表的局部性较差.

排序

下一个测试衡量完成对成员函数 sort(Pred pred) 的调用所需的时间. 值 (test_class 和 itest_class) 和链表的创建方式如第一节所述. 每次迭代中将对值进行升序和降序排序. 例如, 如果 l 是一个链表:

for(int i = 0; i < NumIter; ++i){
   if(!(i % 2))
      l.sort(std::greater<stdlist::value_type>());
   else
      l.sort(std::less<stdlist::value_type>());
}

对于指针链表, 将使用 func_ptr_adaptor 对函数对象进行适配:

for(int i = 0; i < NumIter; ++i){
   if(!(i % 2))
      l.sort(func_ptr_adaptor<std::greater<stdlist::value_type> >());
   else
      l.sort(func_ptr_adaptor<std::less<stdlist::value_type> >());
}

请注意, 对于指针链表, sort 将接受一个 会访问 test_class 存储在另一个链表或 vector 中的值 的函数对象, 因此指针链表将承受一次额外的间接访问: 为了比较两个元素, 它们需要访问存储在另一个容器中的 test_class 值.

结论

侵入式容器可以提供等价非侵入式容器无法实现的性能优势. 当要插入的对象较小时, 内存局部性的改善很明显. 最小化内存分配/释放调用也是一个重要因素, 如果所有要插入侵入式容器的对象都使用 std::vector 或 std::deque 分配, 侵入式容器会让这一点变得简单.
