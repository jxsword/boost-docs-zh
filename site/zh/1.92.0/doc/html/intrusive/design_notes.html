设计说明

在设计 Boost.Intrusive 时, 考虑了以下指导原则:

性能敏感环境中的 Boost.Intrusive

Boost.Intrusive 在性能敏感环境中应当是一个有价值的工具, 遵循这一指导原则, Boost.Intrusive 被设计为提供众所周知的复杂度保证. 除此之外, 一些选项 (如可选的常数时间 size) 被设计为在某些函数中提供更快的复杂度保证, 例如 slist::splice.

关联容器的高级查找和插入函数接受任意键类型和谓词, 其设计旨在避免不必要的对象构造.

空间受限环境中的 Boost.Intrusive

Boost.Intrusive 在空间受限环境中应当是有用的, 遵循这一指导原则, Boost.Intrusive 将节点算法与侵入式容器分离, 以避免为每个用户类型实例化节点算法. 例如, 只需实例化一个红黑树算法类, 即可实现所有使用裸指针的 set 和 multiset 容器. 这样, Boost.Intrusive 力求避免与模板相关的任何代码体积开销.

除此之外, Boost.Intrusive 还实现了一些体积改进: 例如, 如果节点按两字节对齐, 红黑树会将颜色位嵌入父指针的低位. 放弃常数时间 size 操作的选项可以减小容器体积, 当容器为空或只包含少量值时, 这种额外的体积优化尤为明显.

作为基本构建块的 Boost.Intrusive

Boost.Intrusive 可以作为构建更复杂容器的基本构建块, 这一潜力促成了许多设计决策. 例如, 每个用户类型可以有多个钩子, 这为在 Boost.Intrusive 之上实现多索引容器提供了机会.

Boost.Intrusive 容器实现了以函数对象为参数的高级函数 (clone_from, erase_and_dispose, insert_check 等). 在侵入式容器之上实现非侵入式容器 (例如 STL 式容器) 时, 这些函数会派上用场.

扩展 Boost.Intrusive

Boost.Intrusive 提供了多种容器, 同时也允许复用 Boost.Intrusive 的元素来构建自定义容器. 程序员可能希望直接使用节点算法, 或构建利用应用程序环境的特殊钩子.

例如, 程序员可以定制 Boost.Intrusive 的部分组件, 以管理定义无法更改的旧数据结构.
