获得相同类型并缩短符号长度

Boost.Intrusive 用于钩子和容器的灵活选项指定机制有几个缺点:

  • 如果用户以不同的顺序指定相同的选项, 或者只指定部分选项而将其余保持默认, 创建的容器/钩子的类型就会不同. 有时这很令人恼火, 因为两位程序员指定相同的选项却可能得到不兼容的类型. 例如, 下面两个链表虽然使用相同的选项, 但类型并不相同:
#include <boost/intrusive/list.hpp>

using namespace boost::intrusive;

//Explicitly specify constant-time size and size type
typedef list<T, constant_time_size<true>, size_type<std::size_t> List1;

//Implicitly specify constant-time size and size type
typedef list<T> List2;
  • 选项指定符会导致类和函数的模板符号很长. 选项指定符本身就很冗长, 而且在没有变参模板的情况下, 会为未指定的选项分配多个默认模板参数. 如果产生很长的名称, 目标文件和调试信息文件可能增大, 编译时间也可能受到影响.

为了解决这些问题, Boost.Intrusive 提供了一些辅助元函数, 它们可以缩短符号长度, 并在使用相同选项 (无论是显式还是隐式) 时创建相同的类型. 这些元函数还能改善编译时间. 所有容器和钩子都有各自的 make_xxx 版本. 前面的示例可以这样重写以获得相同的链表类型:

#include <boost/intrusive/list.hpp>

 using namespace boost::intrusive;

 #include <boost/intrusive/list.hpp>

 using namespace boost::intrusive;

 //Explicitly specify constant-time size and size type
 typedef make_list<T, constant_time_size<true>, size_type<std::size_t>::type List1;

 //Implicitly specify constant-time size and size type
 typedef make_list<T>::type List2;

产生的符号长度和编译时间通常会更短, 目标/调试文件也会更小. 如果你关心文件大小和编译时间, 这个选项是你的最佳选择.
