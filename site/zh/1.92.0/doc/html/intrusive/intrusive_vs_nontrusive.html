侵入式容器与非侵入式容器的区别

侵入式容器与非侵入式容器的主要区别在于: 在 C++ 中, 非侵入式容器存储用户传入值的 副本. 容器使用 Allocator 模板参数来分配被存储的值:

#include <list>
#include <assert.h>

int main()
{
   std::list<MyClass> myclass_list;

   MyClass myclass(...);
   myclass_list.push_back(myclass);

   //The stored object is different from the original object
   assert(&myclass != &myclass_list.front());
   return 0;
}

为了存储 myclass 新分配的副本, 容器需要额外的数据: std::list 通常会分配一些节点, 节点中包含指向下一个节点和上一个节点的指针以及值本身. 大致类似于:

//A possible implementation of a std::list<MyClass> node
class list_node
{
   list_node *next;
   list_node *previous;
   MyClass    value;
};

另一方面, 侵入式容器不存储传入对象的副本, 而是存储对象本身. 将对象插入容器所需的额外数据必须由对象自身提供. 例如, 要将 MyClass 插入实现链表的侵入式容器, MyClass 必须包含所需的 next 和 previous 指针:

class MyClass
{
   MyClass *next;
   MyClass *previous;
   //Other members...
};

int main()
{
   acme_intrusive_list<MyClass> list;

   MyClass myclass;
   list.push_back(myclass);

   //"myclass" object is stored in the list
   assert(&myclass == &list.front());
   return 0;
}

如我们所见, 知道类应该包含哪些额外数据并非易事. Boost.Intrusive 提供了多种侵入式容器, 以及一种让用户类与这些容器兼容的简便方法.

Boost.Intrusive 容器的特性

从语义上讲, Boost.Intrusive 容器类似于一个持有对象指针的 STL 容器. 也就是说, 如果你有一个保存 T 类型对象的侵入式链表, 那么 std::list<T*> 可以让你执行几乎相同的操作 (维护和遍历类型 T 及其派生类型的一组对象).

非侵入式容器有一些局限:

  • 一个对象只能属于一个容器: 如果要在两个容器之间共享一个对象, 要么必须存储这些对象的多个副本, 要么需要使用指针容器: std::list<Object*>.
  • 使用动态分配来创建传入值的副本, 在某些应用中可能是性能和体积瓶颈. 通常, 动态分配会为每次分配强加额外的体积开销以存储簿记信息, 并需要同步以保护不同线程之间的并发分配.
  • 在 C++11 之前, 非侵入式容器只能存储对象的副本. 尽管如此, 仍然需要拷贝或移动构造函数以及拷贝或移动赋值运算符, 而且不可复制和不可移动的对象无法存入某些容器. 无论如何, new 对象必须在容器内通过构造函数创建, 同一个对象不能在两个容器之间共享.
  • 无法在 STL 容器中存储派生类对象同时保留其原始类型.

侵入式容器有一些重要优势:

  • 操作侵入式容器完全不会调用任何内存管理. 与动态内存相关的时间和体积开销可以降到最低.
  • 同一个对象可以同时插入多个容器, 对象体积的额外开销极小.
  • 遍历侵入式容器比语义等价的指针容器需要更少的内存访问: 迭代更快.
  • 侵入式容器提供比非侵入式容器更好的异常保证. 在某些情况下, 侵入式容器提供非侵入式容器无法实现的无抛出保证.
  • 从指向元素的指针或引用计算该元素的迭代器是一个常数时间操作 (计算 T* 在 std::list<T*> 中的位置具有线性复杂度).
  • 由于侵入式容器不做内存管理, 插入和擦除对象时具有可预测性. 内存管理通常不是可预测的操作, 因此非侵入式容器的复杂度保证比侵入式容器提供的保证更宽松.

侵入式容器也有缺点:

  • 存储在侵入式容器中的每种类型都需要额外的内存来存放容器所需的维护信息. 因此, 只要某个类型要存入侵入式容器, 就必须适当地修改该类型的定义. 尽管使用 Boost.Intrusive 时这项任务很容易, 但改动类型的定义有时是个关键问题.
  • 在侵入式容器中, 你存储的不是对象的副本, 而是将原始对象与容器中的其他对象链接起来. 对象存入侵入式容器不需要拷贝构造函数或赋值运算符. 但每当修改对象内容时, 你必须注意可能的副作用 (这对关联容器尤为重要).
  • 用户 必须独立于容器来管理被插入对象的生命周期.
  • 再次提醒, 你必须 小心: 与 STL 容器不同, 很容易在不直接触碰侵入式容器的情况下使迭代器失效, 因为对象可能在从容器中擦除之前就被销毁.
  • Boost.Intrusive 容器是 不可复制且不可赋值的. 由于侵入式容器没有分配能力, 这些操作毫无意义. 不过, 可以使用 swap 来实现移动能力. 为了简化存储 Boost.Intrusive 容器的类的拷贝构造函数和赋值运算符的实现, Boost.Intrusive 提供了特殊的克隆函数. 更多信息参见 克隆 Boost.Intrusive 容器 一节.
  • Boost.Intrusive 容器 不支持不完整类型. 一些 std 容器和大多数 Boost.Container 类型支持不完整类型.
  • 对于使用容器的程序, 使用侵入式容器时分析线程安全性更困难, 因为容器可能在没有显式调用容器成员的情况下被间接修改.
