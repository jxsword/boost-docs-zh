安全模式的特性

Boost.Intrusive 钩子可以配置为在安全链接 (safe-link) 模式下工作. 安全模式默认激活, 但也可以显式激活:

//Configuring the safe mode explicitly
class Foo : public list_base_hook< link_mode<safe_link> >
{};

借助安全模式, 用户无需任何外部引用即可检测对象是否实际插入了容器. 下面回顾安全模式的基本特性:

  • 钩子的构造函数将钩子置于一个已知良好的默认状态.
  • 钩子的析构函数检查钩子是否处于已知良好的默认状态. 如果不是, 将触发断言.
  • 每次将对象插入侵入式容器时, 容器都会检查钩子是否处于已知良好的默认状态. 如果不是, 将触发断言.
  • 每次从侵入式容器中擦除对象时, 容器都会将擦除的对象置于已知良好的默认状态.

借助这些特性, 用户无需任何外部引用, 通过调用 is_linked() 成员函数即可知道对象是否已插入容器. 如果对象实际上未插入容器, 钩子处于默认状态; 如果已插入容器, 钩子则不处于默认状态.

配置安全模式断言

默认情况下, Boost-Intrusive 钩子和容器引发的所有安全模式断言都使用 BOOST_ASSERT 实现, 用户可以对其进行配置. 更多信息请参见 http://www.boost.org/libs/utility/assert.html 中关于 BOOST_ASSERT 的说明.

BOOST_ASSERT 是全局配置的, 因此用户可能希望在不修改全局 BOOST_ASSERT 的情况下重新定义侵入式安全模式断言. 这可以通过重新定义以下宏来实现:

  • BOOST_INTRUSIVE_SAFE_HOOK_DEFAULT_ASSERT: 该断言将用于侵入式容器的插入函数, 以检查待插入值的钩子是否为默认构造.
  • BOOST_INTRUSIVE_SAFE_HOOK_DESTRUCTOR_ASSERT: 该断言将用于钩子的析构函数, 以检查钩子是否处于默认状态.

如果这些宏中的任何一个未被重新定义, 断言将默认为 BOOST_ASSERT. 如果定义了 BOOST_INTRUSIVE_SAFE_HOOK_DEFAULT_ASSERT 或 BOOST_INTRUSIVE_SAFE_HOOK_DESTRUCTOR_ASSERT, 并且程序员需要包含一个文件来配置该断言, 则可以用要包含的文件名定义 BOOST_INTRUSIVE_SAFE_HOOK_DESTRUCTOR_ASSERT_INCLUDE 或 BOOST_INTRUSIVE_SAFE_HOOK_DEFAULT_ASSERT_INCLUDE:

#define BOOST_INTRUSIVE_SAFE_HOOK_DESTRUCTOR_ASSERT          MYASSERT
#define BOOST_INTRUSIVE_SAFE_HOOK_DESTRUCTOR_ASSERT_INCLUDE <myassert.h>
