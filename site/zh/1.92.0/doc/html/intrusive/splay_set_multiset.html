基于 splay 树的侵入式关联容器: splay_set, splay_multiset 和 splay_tree

基于伸展树的容器的优缺点
splay_set、splay_multiset 与 splaytree 容器
示例

C++ 关联容器通常基于红黑树实现 (例如: STL, Boost.Intrusive 关联容器). 然而, 还有一些有趣的数据结构提供了一些优势 (也有一些劣势).

splay 树是一种自调整二叉搜索树, 通常用于缓存, 内存分配器和其他应用, 因为 splay 树具有 "缓存效应": 最近访问的元素的访问时间优于较少访问的元素. 有关 splay 树的更多信息, 请参见 相应的 Wikipedia 条目.

Boost.Intrusive 提供了 3 个基于 splay 树的容器: splay_set, splay_multiset 和 splaytree. 前两个类似于 set 或 multiset, 后者是一种泛化, 同时提供插入唯一键和多重键的函数.

使用 Boost.Intrusive 钩子时, 这些容器的内存开销通常为 3 个指针. 空的非常数时间 size splay 容器的大小也是 3 个指针.

基于 splay 树的容器的优缺点

基于 splay 树的侵入式容器在许多操作 (如查找, 插入, 擦除等) 中具有对数复杂度, 但如果某些元素比其他元素访问得更频繁, splay 树的查找速度会快于等价的平衡二叉树 (如红黑树).

splay 树提供的缓存效应是有代价的: 搜索元素时必须对树进行再平衡. 为了维护 const 正确性和线程安全保证, 当调用诸如 find(), lower_bound(), upper_bound(), equal_range(), count()... 等查找函数的 const 版本时, 该缓存效应不会更新. 这意味着将基于 splay 树的关联容器作为 set/ multiset 的直接替代品使用时, 特别是对于 const 查找函数, 可能无法带来预期的性能提升.

如果元素搜索是随机的, 树将不断再平衡而无法利用缓存效应, 因此对于某些搜索模式, splay 树的性能可能比其他平衡树更差.

Boost.Intrusive splay 关联容器不使用自己的钩子类型, 而是使用普通的二叉搜索树钩子. 有关这些钩子的更多信息, 请参见 二叉搜索树钩子: bs_set_base_hook 和 bs_set_member_hook 一节.

splay_set, splay_multiset 和 splaytree 容器 

template <class T, class ...Options>
class splay_set;

template <class T, class ...Options>
class splay_multiset;

template <class T, class ...Options>
class splaytree;

这些容器接受 如何使用 Boost.Intrusive 一节中说明的相同选项:

  • base_hook<class Hook> / member_hook<class T, class Hook, Hook T::* PtrToMember> / value_traits<class ValueTraits>: 指定用于配置容器的钩子类型或值特征. (要了解值特征, 请参见 具有自定义 ValueTraits 的容器 一节.)
  • constant_time_size<bool Enabled>: 激活常数时间 size() 操作. 默认: constant_time_size<true>
  • size_type<typename SizeType>: 指定用于存储容器 size 的类型. 默认: size_type<std::size_t>

它们还可以接受一个附加选项:

  • compare<class Compare>: 容器中待插入对象的比较函数. 比较仿函数必须产生严格弱序. 默认: compare< std::less<key_type> >
  • key_of_value<class KeyOfValueFunctionObject>: 一个函数对象, 定义待存储值类型的 key_type. 该类型将允许类似映射的接口. 详细信息参见 配合 set 和 multiset 的 map 与 multimap 式接口. 默认: key_type 等于 value_type (set 式接口).

示例

现在让我们看一个使用 splay_set/ splay_multiset 容器的小示例:

#include <boost/intrusive/splay_set.hpp>
#include <vector>
#include <functional>

using namespace boost::intrusive;

class mytag;

class MyClass
   : public bs_set_base_hook<>
{
   int int_;

   public:
   //This is a member hook
   bs_set_member_hook<> member_hook_;

   MyClass(int i)
      :  int_(i)
      {}
   friend bool operator< (const MyClass &a, const MyClass &b)
      {  return a.int_ < b.int_;  }
   friend bool operator> (const MyClass &a, const MyClass &b)
      {  return a.int_ > b.int_;  }
   friend bool operator== (const MyClass &a, const MyClass &b)
      {  return a.int_ == b.int_;  }
};

//Define a set using the base hook that will store values in reverse order
typedef splay_set< MyClass, compare<std::greater<MyClass> > >     BaseSplaySet;

//Define an multiset using the member hook
typedef member_hook<MyClass, bs_set_member_hook<>, &MyClass::member_hook_> MemberOption;
typedef splay_multiset< MyClass, MemberOption>   MemberSplayMultiset;

int main()
{
   typedef std::vector<MyClass>::iterator VectIt;

   //Create several MyClass objects, each one with a different value
   std::vector<MyClass> values;
   for(int i = 0; i < 100; ++i)  values.push_back(MyClass(i));

   BaseSplaySet   baseset;
   MemberSplayMultiset membermultiset;


   //Insert values in the container
   for(VectIt it(values.begin()), itend(values.end()); it != itend; ++it){
      baseset.insert(*it);
      membermultiset.insert(*it);
   }

   //Now test sets
   {
      BaseSplaySet::reverse_iterator rbit(baseset.rbegin());
      MemberSplayMultiset::iterator mit(membermultiset.begin());
      VectIt it(values.begin()), itend(values.end());

      //Test the objects inserted in the base hook set
      for(; it != itend; ++it, ++rbit){
         if(&*rbit != &*it)   return 1;
      }

      //Test the objects inserted in member and binary search hook sets
      for(it = values.begin(); it != itend; ++it, ++mit){
         if(&*mit != &*it)    return 1;
      }
   }
   return 0;
}
