量的构造与转换

量 (quantity) 定义为与特定单位相关联的任意值类型的值. 例如, 米是一个单位, 而 3.0 米是一个量. 量遵循两种独立的代数:其值类型的原生代数, 以及与所关联单位对应的量纲分析代数. 此外, 单位与量之间也定义了代数运算, 以简化量的定义; 这实际上等价于带单位值量的代数.

量由quantity 模板类实现, 该类定义于boost/units/quantity.hpp :

template<class Unit,class Y = double> class quantity;

该类同时以单位类型 (Unit) 和值类型 (Y) 为模板参数, 若未另行指定, 后者默认为双精度浮点类型. 值类型必须具有普通的复制构造函数和复制赋值运算符. 系统为标量与单位之间、标量与量之间、单位与量之间以及量与量之间的代数运算提供了 +、-、* 和 / 运算符. 此外, 可以使用pow<R> 和root<R> 函数计算整数幂、有理数次幂及方根. 最后, 还提供了标准的一组布尔比较运算符 (==, !=, <, <=, >, and >=) , 用于比较来自同一单位制的量. 在单位允许的前提下, 所有运算符都只是简单地委托给值类型对应的运算符.

BOOST_TYPEOF_REGISTER_TYPE(natural);
BOOST_TYPEOF_REGISTER_TYPE(integer);
BOOST_TYPEOF_REGISTER_TYPE(rational);

Conversions

转换只对量有意义, 因为它意味着至少存在一个乘法缩放系数, 还可能存在仿射线性偏移. 用于简化单位间转换定义的宏见boost/units/conversion.hpp 和boost/units/absolute.hpp (用于带偏移的仿射转换) .

宏BOOST_UNITS_DEFINE_CONVERSION_FACTOR 指定从第一种单位类型转换到第二种单位类型的缩放系数. 第一个参数必须是base_unit. 第二个参数可以是base_unit 或unit.

我们来声明一个简单的基本单位:

struct foot_base_unit : base_unit<foot_base_unit, length_dimension, 10> { };

现在, 我们希望能够把英尺转换为米, 反之亦然. 英尺被精确定义为 0.3048 米, 因此可以写出如下代码

BOOST_UNITS_DEFINE_CONVERSION_FACTOR(foot_base_unit, meter_base_unit, double, 0.3048);

或者, 也可以使用 SI 长度typedef:

BOOST_UNITS_DEFINE_CONVERSION_FACTOR(foot_base_unit, SI::length, double, 0.3048);

由于 SI 的长度单位是米, 这两种定义是等价的. 如果定义了这些转换, 那么这些单位的带缩放形式之间的转换也将自动有效.

宏BOOST_UNITS_DEFAULT_CONVERSION 指定一种在无法直接转换时应用于基本单位的转换. 利用它, 只需一个特化就可以让任意转换生效:

struct my_unit_tag : boost::units::base_unit<my_unit_tag, boost::units::force_type, 1> {};
// define the conversion factor
BOOST_UNITS_DEFINE_CONVERSION_FACTOR(my_unit_tag, SI::force, double, 3.14159265358979323846);
// make conversion to SI the default.
BOOST_UNITS_DEFAULT_CONVERSION(my_unit_tag, SI::force);

量的构造与转换

本库的设计理念是在对带量纲的量执行运算时, 安全性优先于便利性. 具体而言, 量的构造被要求完整指定值和单位. 禁止直接从标量值构造 (不过在确有需要时, 提供了静态成员函数from_value 来实现这一功能) . 此外, quantity_cast 到引用的转换允许直接访问quantity 变量的底层值. 库提供了一个显式构造函数, 用于在不同单位制之间进行量纲兼容的量之间的转换. 只有当约化单位完全相同时才允许单位制之间的隐式转换, 这既允许在不同系统中的等价单位之间进行平凡的转换 (例如 SI 秒与 CGS 秒) , 又能在编译期捕获无意的单位制不匹配, 并防止意外转换带来的潜在精度损失和性能开销. 赋值遵循同样的规则. 对于约化为无量纲的单位所对应的量有一个例外:在这种情况下, 允许通过类模板特化隐式转换到底层值类型. 不同值类型的量只有在值类型本身可隐式转换时才能隐式转换. quantity 类还定义了value() 成员, 用于直接访问底层值.

总结起来, 在以下条件下允许转换:

  • quantity<Unit,Y> 到quantity<Unit,Z> 的隐式转换是允许的, 条件是Y 与Z 可隐式转换.
  • 在quantity<Unit,Y> 与quantity<Unit,Z> 之间赋值是允许的, 条件是Y 与Z 可隐式转换.
  • 在quantity<Unit1,Y> 与quantity<Unit2,Z> 之间进行显式转换是允许的, 条件是Unit1 与Unit2 具有相同的量纲, 且Y 与Z 可隐式转换.
  • 在quantity<Unit1,Y> 与quantity<Unit2,Z> 之间进行隐式转换是允许的, 条件是Unit1 约化后与Unit2 的基本单位组合完全相同, 且Y 与Z 可转换.
  • 在与隐式转换相同的条件下, 允许在quantity<Unit1,Y> 与quantity<Unit2,Z> 之间赋值.
  • quantity<Unit,Y> 可以从Y 类型的值直接构造, 只需使用静态成员函数from_value. 当然, 这样做会绕过对新赋值的所有类型检查, 因此仅应在绝对必要时使用该方法.

当然, 只要允许隐式转换, 显式转换同样合法.

由于无量纲量没有关联的单位, 它们表现为普通标量, 允许与底层值类型 (或可与该值类型相互转换的类型) 之间进行隐式转换.
