警告

这些特性是实验性的, 未来版本中可能变更. 目前测试尚不充分, 因此你可能发现一些小缺陷 :(

注释

这些特性基于 P. Halpern、A. Robison、A. Laksberg、H. Sutter 等人的 C++1y 提案 n4088 - Task Region R3. 以下文字改编自该论文, 以展示差异.

与标准提案相比的主要差异是, 我们可以为多个任务区域使用同一个执行器.

注释

到目前为止, Boost.Thread 尚未实现 n4105 - Information technology – Programming languages, their environments and system software interfaces – Technical Specification for C++ Extensions for Parallelism 中定义的并行算法.

引言

本模块引入了 C++11/C++14 库函数模板 task_region 和库类 task_region_handle, 其成员函数 run 和 wait 共同使开发者能够编写表达力强且可移植的 fork-join 并行代码.

并行技术规范 (Parallelism TS) 工作草案 N4105 通过加入并行执行策略来扩展 STL 算法. 程序员可以以此为基础编写额外的高层算法, 这些算法可以基于所提供的并行算法实现. 然而, n4105 的范围并不包括表达任意 fork-join 并行性的更低层机制

本库提供的 task_region、run 与 wait 函数基于 task_group 概念, 该概念是 PPL 和 TBB 库共同子集的一部分.

Tutorial

考虑一个并行遍历树的例子: 用户提供的函数 compute 应用于树的每个节点, 返回结果之和:

template<typename Func>
int traverse(node *n, Func&& compute)
{
  int left = 0, right = 0;
  task_region([&](task_region_handle& tr) {
    if (n->left)
      tr.run([&] { left = traverse(n->left, compute); });
    if (n->right)
      tr.run([&] { right = traverse(n->right, compute); });
  });
  return compute(n) + left + right;
}

上面的例子演示了本文提出的两个函数的用法: task_region 与 task_region_handle::run. task_region 函数在程序代码中划定一个区域, 该区域可能包含任务调用, 任务由 run 成员函数派生, 而该成员函数属于 task_region_handle 类.

run 函数派生一个任务——一个允许相对于调用者并行执行的工作单元. run 在 task_region 中派生的所有并行任务, 都会在 task_region 结束时汇合回单个执行线程.

run 接受用户提供的函数对象 f 并异步启动它——即它可能在 f 执行完成之前返回. 实现的调度器可以选择立即运行 f, 或推迟运行 f, 直到计算资源可用.

一个 task_region_handle 只能由 task_region 构造, 因为它没有公开的构造函数. 因此, run 只能 (直接或间接) 从传递给 task_region 的用户提供的函数中调用:

void g();
void f(task_region_handle& tr)
{
  tr.run(g); // OK, invoked from within task_region in h
}
void h()
{
  task_region(f);
}

int main()
{
  task_region_handle tr; // Error: no public constructor
  tr.run(g); // No way to call run outside of a task_region
  return 0;
}

并行 Fibonacci

这无疑是 Fibonacci 函数最差的实现. 不过还是放在这里, 因为它简单并能清楚地展示 fork-join 结构. Fibonacci(n) = Fibonacci(n-1) + Fibonacci(n-2), 因此任务分解非常简单.

int fib_task_region(int n)
{
  using boost::experimental::parallel::task_region;
  using boost::experimental::parallel::task_region_handle;

  if (n == 0) return 0;
  if (n == 1) return 1;

  int n1;
  int n2;

  task_region([&](task_region_handle& trh)
      {
        trh.run([&]
            {
              n1 = fib_task_region(n - 1);
            });

        n2 = fib_task_region(n - 2);
      });

  return n1 + n2;
}

int main()
{
  for (int i = 0; i<10; ++i) {
    std::cout << fib_task_region(i) << " ";
  }
  std::cout << std::endl;
}
并行 Fibonacci - 特定执行器

上一个例子使用实现定义的方式来派生任务. 用户通常希望掌控任务必须如何派生. 有一个 task_region 的重载接受额外的 Executor 参数, 还有一个以 task_region_handle_gen<Executor> 为参数的函数. task_region_handle_gen<Executor> run 使用该执行器来派生任务.

template <class Ex>
int fib_task_region_gen( Ex& ex, int n)
{
  using boost::experimental::parallel::task_region;
  using boost::experimental::parallel::task_region_handle_gen;

  if (n == 0) return 0;
  if (n == 1) return 1;

  int n1;
  int n2;

  task_region(ex, [&](task_region_handle_gen<Ex>& trh) // (2)
      {
        trh.run([&]
            {
              n1 = fib_task_region(n - 1);
            });

        n2 = fib_task_region(n - 2);
      });

  return n1 + n2;
}

int main()
{
  boost::basic_thread_pool tp; // (1)
  for (int i = 0; i<10; ++i) {
    std::cout << fib_task_region_gen(tp,i) << " ";
  }
  std::cout << std::endl;
  return 0;
}

特定执行器在第 (1) 行声明, 并在第 (2) 行使用.
