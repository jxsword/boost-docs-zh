boost::thread 类负责启动和管理线程. 每个 boost::thread 对象表示单个执行线程, 或表示Not-a-Thread, 且至多一个 boost::thread 对象表示给定的执行线程: boost::thread 类型的对象不可复制.

boost::thread 类型的对象是可移动的, 因此可以存储在支持移动的容器中, 并从函数返回. 这允许把线程创建的细节封装到一个函数中.

boost::thread make_thread();

void f()
{
    boost::thread some_thread=make_thread();
    some_thread.join();
}
注释

在支持右值引用的编译器上, boost::thread 提供正确的移动构造函数和移动赋值运算符, 因此满足 C++0x 的MoveConstructible 和 MoveAssignable 概念. 在这样的编译器上, boost::thread 因此可以与支持这些概念的容器一起使用.

对于其他编译器, 通过移动模拟层提供移动支持, 因此容器必须显式检测该移动模拟层. 详见 <boost/thread/detail/move.hpp>.

启动线程

通过向构造函数传递一个可以无参调用的可调用类型对象来启动新线程. 该对象被复制到内部存储, 并在新创建的执行线程上调用. 如果该对象不得 (或不能) 被复制, 则可以使用 boost::ref 传入对函数对象的引用. 在这种情况下, 的用户必须确保被引用对象的存活期长于新创建的执行线程. 

struct callable
{
    void operator()();
};

boost::thread copies_are_safe()
{
    callable x;
    return boost::thread(x);
} // x is destroyed, but the newly-created thread has a copy, so this is OK

boost::thread oops()
{
    callable x;
    return boost::thread(boost::ref(x));
} // x is destroyed, but the newly-created thread still has a reference
  // this leads to undefined behaviour

如果你想用需要提供实参的函数或可调用对象构造 boost::thread 的实例, 可以通过向 boost::thread 构造函数传递附加实参来实现:

void find_the_question(int the_answer);

boost::thread deep_thought_2(find_the_question,42);

实参会被复制到内部线程结构中: 如果需要引用, 请使用 boost::ref——就像对可调用函数的引用一样.

可以传递的附加实参数量有一个未指定的上限.

线程属性

以这种方式启动的线程使用实现定义的线程属性创建, 如栈大小、调度、优先级等, 或任何平台特定属性. 如何提供一个允许用户设置平台特定属性的可移植接口并不明显. Boost.Thread 走中间路线, 通过 thread::attributes 类至少以可移植方式设置栈大小, 如下所示:

boost::thread::attributes attrs;
attrs.set_stack_size(4096*10);
boost::thread deep_thought_2(attrs, find_the_question, 42);

即使对于这个简单的属性也可能存在可移植性问题, 因为某些平台可能要求栈大小具有最小值和/或是指定页大小的倍数. 库会把请求的大小适配到平台约束, 因此用户不需要操心.

这是唯一以可移植方式提供的属性. 要在构造时设置任何其他线程属性, 用户需要使用不可移植的代码.

在 PThread 平台上, 用户需要获取线程属性句柄并将其用于任何属性.

下面说明用户在 PThread 平台上如何设置栈大小和调度策略.

boost::thread::attributes attrs;
// set portable attributes
// ...
attr.set_stack_size(4096*10);
#if defined(BOOST_THREAD_PLATFORM_WIN32)
    // ... window version
#elif defined(BOOST_THREAD_PLATFORM_PTHREAD)
    // ... pthread version
    pthread_attr_setschedpolicy(attr.native_handle(), SCHED_RR);
#else
#error "Boost threads unavailable on this platform"
#endif
boost::thread th(attrs, find_the_question, 42);

在 Windows 平台上就没那么简单了, 因为没有编译线程属性的类型. Windows 上线程的创建与通过 thread::attributes 类模拟的创建相关联. 这就是 LPSECURITY_ATTRIBUTES lpThreadAttributes. Boost.Thread 提供一个不可移植的 set_security 函数, 使用户可以在创建线程之前提供它, 如下所示

#if defined(BOOST_THREAD_PLATFORM_WIN32)
  boost::thread::attributes attrs;
  // set portable attributes
  attr.set_stack_size(4096*10);
  // set non portable attribute
  LPSECURITY_ATTRIBUTES sec;
  // init sec 
  attr.set_security(sec);
  boost::thread th(attrs, find_the_question, 42);
  // Set other thread attributes using the native_handle_type.
  //...
#else
#error "Platform not supported"
#endif

线程函数中的异常

如果传递给 boost::thread 构造函数的函数或可调用对象在被调用时传播的异常不是 boost::thread_interrupted 类型, 则会调用 std::terminate()

分离线程

可以通过显式调用 detach() 对象上的 boost::thread 成员函数来分离线程. 在这种情况下, boost::thread 对象不再代表现在已分离的线程, 而是代表Not-a-Thread.

int main()
{
  boost::thread t(my_func);
  t.detach();
}

join 线程

为了等待执行线程完成, 必须使用 join()、__join_for 或 __join_until (timed_join() 已弃用) 成员函数, 它们作用于 boost::thread 对象. join() 会阻塞调用线程, 直到 boost::thread 对象所表示的线程已完成.

int main()
{
  boost::thread t(my_func);
  t.join();
}

如果 boost::thread 对象所表示的执行线程已经完成, 或 boost::thread 对象表示Not-a-Thread, 则 join() 立即返回.

int main()
{
  boost::thread t;
  t.join(); // do nothing
}

基于时间的 join 类似, 不同之处在于: 如果被等待的线程在指定时间流逝或到达时仍未完成, 对 __join_for 或 __join_until 的调用也会返回.

int main()
{
  boost::thread t;
  if ( t.join_for(boost::chrono::milliseconds(500)) )
    // do something else
  t.join(); // join anyway
}

析构函数 V1-2

当代表执行线程的 boost::thread 对象被销毁时, 线程变为已分离状态. 线程一旦分离, 将继续执行, 直到构造时提供的函数或可调用对象的调用完成, 或程序终止. 也可以通过显式调用 detach() 对象上的 boost::thread 成员函数来分离线程. 在这种情况下, boost::thread 对象不再代表现在已分离的线程, 而是代表Not-a-Thread.

析构函数 V3-X

当代表执行线程的 boost::thread 对象被销毁时, 如果线程处于 __joinable__ 状态, 程序会终止.

int main()
{
  boost::thread t(my_func);
} // calls std::terminate()

你可以使用 thread_joiner 确保线程在线程析构函数处已被 join.

int main()
{
  boost::thread t(my_func);
  boost::thread_joiner g(t);
  // do something else
} // here the thread_joiner destructor will join the thread before it is destroyed.

中断

正在运行的线程可以被中断, 方法是调用相应 interrupt() 对象的 boost::thread 成员函数. 当中断的线程下一次执行指定的中断点之一时 (或它当前正在执行其中之一时处于阻塞状态) , 如果启用了中断, 则会在被中断的线程中抛出 boost::thread_interrupted 异常. 除非该异常在被中断线程的线程主函数内部被捕获, 否则栈展开过程 (与其他异常一样) 会执行具有自动存储期的析构函数. 与其他异常不同, 当 boost::thread_interrupted 从线程主函数传播出去时, 不会导致调用 std::terminate; 其效果如同线程主函数正常返回.

如果线程希望避免被中断, 它可以创建 boost::this_thread::disable_interruption 的实例. 此类的对象在构造时为其创建线程禁用中断, 并在析构时把中断状态恢复为之前的状态:

void f()
{
    // interruption enabled here
    {
        boost::this_thread::disable_interruption di;
        // interruption disabled
        {
            boost::this_thread::disable_interruption di2;
            // interruption still disabled
        } // di2 destroyed, interruption state restored
        // interruption still disabled
    } // di destroyed, interruption state restored
    // interruption now enabled
}

boost::this_thread::disable_interruption 实例的效果可以通过构造 boost::this_thread::restore_interruption 实例来暂时撤销, 传入相关的 boost::this_thread::disable_interruption 对象. 这会把中断状态恢复为 boost::this_thread::disable_interruption 对象构造时的状态, 并在 boost::this_thread::restore_interruption 对象销毁时再次禁用中断.

void g()
{
    // interruption enabled here
    {
        boost::this_thread::disable_interruption di;
        // interruption disabled
        {
            boost::this_thread::restore_interruption ri(di);
            // interruption now enabled
        } // ri destroyed, interruption disable again
    } // di destroyed, interruption state restored
    // interruption now enabled
}

在任何时刻, 当前线程的中断状态都可以通过调用 boost::this_thread::interruption_enabled() 查询.

线程 ID

boost::thread::id 类的对象可用于标识线程. 每个正在运行的执行线程都有唯一的 ID, 可通过调用相应 boost::thread 的 get_id() 成员函数获得, 或在县城内调用 boost::this_thread::get_id() 获得. boost::thread::id 类的对象可以复制, 并可用作关联容器中的键: 提供了全套比较运算符. 线程 ID 也可以用流插入运算符写入输出流, 但输出格式未指定.

boost::thread::id 的每个实例要么引用某个线程, 要么表示Not-a-Thread. 引用 Not-a-Thread 的实例相互比较相等, 但与任何引用真实执行线程的实例都不相等. boost::thread::id 上的比较运算符为每个不相等的线程 ID 提供全序.

在 Boost.Thread 资源中使用原生接口

boost::thread 类具有 native_handle_type 和 native_handle 成员, 提供对底层原生句柄的访问.

此原生句柄可用于更改 (例如) 调度策略.

一般来说, 把此句柄与可能与 Boost.Thread 提供的操作冲突的操作一起使用是不安全的. 一个错误用法的例子是直接 detach 线程, 因为这不会改变 boost::thread 实例的内部状态, 因此 joinable 函数会继续返回 true, 而原生线程已不可 join.

thread t(fct);
thread::native_handle_type hnd=t.native_handle();
pthread_detach(hnd);
assert(t.joinable());

在原生线程中使用 Boost.Thread 接口

使用原生接口创建的执行线程在本文档中称为原生线程.

原生执行线程的第一个例子是主线程.

用户可以使用 boost::this_thread、yield、sleep、sleep_for、sleep_until 函数访问与原生当前线程相关的一些同步函数.

int main() {
  // ... 
  boost::this_thread::sleep_for(boost::chrono::milliseconds(10));
  // ... 
}

当然, Boost.Thread 提供的所有同步设施在原生线程上也可用.

当从使用原生接口创建的线程调用时, boost::this_thread 的中断相关函数以降级模式运行, 即 boost::this_thread::interruption_enabled() 返回 false. 因此使用 boost::this_thread::disable_interruption 和 boost::this_thread::restore_interruption 不会有任何效果, 对 boost::this_thread::interruption_point() 的调用会被直接忽略.

由于中断线程的唯一途径是通过 boost::thread 实例, interruption_request() 对原生线程会返回 false.

pthread_exitPOSIX 限制

glibc/NPTL 中的 pthread_exit 会导致一种“强制栈展开”, 它几乎像 C++ 异常, 但不完全相同. 例如在 Mac OS X 上, pthread_exit 展开时不调用 C++ 析构函数.

这种行为与当前 Boost.Thread 设计不兼容, 因此在 POSIX 线程中使用此函数会导致任何 Boost.Thread 函数的行为未定义.

线程构造函数 

template<typename Callable>
thread(Callable func);

要求:

Callable 必须是 Copyable 的, 且 func() 必须是有效的表达式.

效果:

func 被复制到 thread 库内部管理的存储中, 并在新创建的执行线程上调用该副本. 如果此调用导致异常传播到 thread 库内部且异常不是 boost::thread_interrupted 类型, 则会调用 std::terminate(). 此调用的任何返回值都被忽略.

后置条件:

*this 指代新创建的执行线程, 而 this->get_id()!=thread::id()

抛出:

如果发生错误则为 boost::thread_resource_error.

错误条件:

resource_unavailable_try_again: 系统缺少创建另一个线程所需的资源, 或将超出系统对进程内线程数量的限制.

前置条件:

必须从构造 disabler 的同一线程调用.

效果:

把 boost::this_thread::interruption_enabled() 的当前状态为当前线程恢复到构造 disabler 之前的状态.

后置条件:

boost::this_thread::interruption_enabled() 对当前线程返回存储在 disabler 构造函数中的值.

抛出:

无.

析构函数 
~restore_interruption() noexcept;

前置条件:

必须从构造 *this 的同一线程调用.

效果:

为当前线程禁用中断.

后置条件:

boost::this_thread::interruption_enabled() 对当前线程返回 false.

抛出:

无.

非成员函数模板 at_thread_exit() 扩展 

#include <boost/thread/thread.hpp>

template<typename Callable>
void at_thread_exit(Callable func);

效果:

func 的副本被放入线程特定存储. 当当前线程退出时调用此副本 (即使线程已被中断) .

后置条件:

func 的副本已保存, 用于在线程退出时调用.

抛出:

std::bad_alloc 如果无法为函数的副本分配内存, boost::thread_resource_error 如果 thread 库内发生任何其他错误. 把 func 复制到内部存储时抛出的任何异常.

注释:

如果线程使用平台特定 API 被强制终止, 或线程由于调用 、 或 exit() 而终止, 则此函数abort()不会std::terminate()被调用. 特别是, 从 main() 返回等价于调用 exit(), 因此不会调用任何用 at_thread_exit() 注册的函数

thread_group 提供以某种方式相关联的线程集合. 可以使用 add_thread 和 create_thread 成员函数把新线程加入组. thread_group 不可复制或移动.

构造函数 

thread_group();

效果:

创建一个没有任何线程的新线程组.

析构函数 

~thread_group();

效果:

销毁 *this 并 delete 组中所有 boost::thread 对象.

成员函数 create_thread() 

template<typename F>
thread* create_thread(F threadfunc);

效果:

如同通过 boost::thread 创建一个新的 new thread(threadfunc) 对象, 并把它加入组.

后置条件:

this->size() 加一, 新线程正在运行.

返回:

指向新 boost::thread 对象的指针.

成员函数 add_thread() 

void add_thread(thread* thrd);

前置条件:

表达式 delete thrd 是格式良好的, 不会导致未定义行为, 且 is_thread_in(thrd) == false.

效果:

接管 boost::thread 所指向的 thrd 对象的所有权, 并把它加入组.

后置条件:

this->size() 加一.

成员函数 remove_thread() 

void remove_thread(thread* thrd);

效果:

如果 thrd 是组的成员, 则移除它而不调用 delete.

后置条件:

如果 thrd 曾是组的成员, 则 this->size() 减一.

成员函数 join_all() 

void join_all();

要求:

is_this_thread_in() == false.

效果:

对组中的每个 join() 对象调用 boost::thread

后置条件:

组中的每个线程都已终止.

注释:

由于 join() 是预定义中断点之一, join_all() 也是中断点.

成员函数 is_this_thread_in() 

bool is_this_thread_in();

返回:

如果组中存在线程 th 使得 th.get_id() == this_thread::get_id(), 则为 true.

成员函数 is_thread_in() 

bool is_thread_in(thread* thrd);

返回:

如果组中存在线程 th 使得 th.get_id() == thrd->get_id(), 则为 true.

成员函数 interrupt_all() 

void interrupt_all();

效果:

对组中的每个 interrupt() 对象调用 boost::thread

成员函数 size() 

int size();

返回:

组中的线程数量.

抛出:

无.
