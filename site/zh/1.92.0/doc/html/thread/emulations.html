=delete 模拟

C++11 允许使用 '= delete' 删除一些隐式生成的函数 (如构造函数和赋值运算符) , 如下所示

public:
  thread(thread const&) = delete;

在不支持该特性的编译器上, Boost.Thread 依赖部分模拟: 将该函数声明为 private 且不提供定义.

private:
  thread(thread &);

这种模拟只是部分的, 因为在某些编译器上 private 函数仍可用于重载决议, 并且会优先于其他需要转换的重载. 对移动语义模拟的影响见下文.

移动语义

已弃用的版本 2 接口
可移植接口

为了实现可移动类、移动参数和返回类型, Boost.Thread 在编译器支持时使用右值引用. 在不支持的编译器上, Boost.Thread 会根据 BOOST_THREAD_USES_MOVE 是否定义而使用 Boost.Move 提供的模拟或 Boost.Thread 之前版本提供的模拟. 当 BOOST_THREAD_VERSION 为 2 时, 该宏默认未定义. 自 BOOST_THREAD_VERSION 3 起, BOOST_THREAD_USES_MOVE 已被定义.

已弃用的版本 2 接口

辅助类与辅助函数
可移动模拟

在 1.50 版之前, Boost.Thread 使用自己的移动语义模拟, 其限制比 Boost.Move 提供的更多. 此外, 让 Boost.Thread 使用 Boost.Move 也符合整个 Boost 社区的利益, 这样 boost::thread 就可以存储在支持可移动语义的容器中.

为了至少在某些发布版中保持向后兼容, Boost.Thread 允许用户通过定义 BOOST_THREAD_DONT_USE_MOVE 来使用已弃用的移动语义模拟.

对于不支持右值引用的编译器, 移动语义的许多方面都可以模拟, Boost.Thread 的遗留实现为此提供了工具.

辅助类与辅助函数

下面是遗留移动语义辅助类与辅助函数的接口.

namespace boost
{
  namespace detail
  {
      template<typename T>
      struct thread_move_t
      {
        explicit thread_move_t(T& t_);
        T& operator*() const;
        T* operator->() const;
      private:
        void operator=(thread_move_t&);
      };
  }
  template<typename T>
  boost::detail::thread_move_t<T> move(boost::detail::thread_move_t<T> t);
}
可移动模拟

我们可以按如下方式编写一个 MovableOnly 类. 只需遵循以下简单步骤:

  • 添加转换至 detail::thread_move_t<classname>
  • 将复制构造函数设为 private.
  • 编写构造函数, 参数类型为 detail::thread_move_t<classname>
  • 编写赋值运算符, 参数类型为 detail::thread_move_t<classname>

例如, thread 类定义了以下内容:

class thread
{
  // ...
private:
    thread(thread&);
    thread& operator=(thread&);
public:
    detail::thread_move_t<thread> move()
    {
        detail::thread_move_t<thread> x(*this);
        return x;
    }
    operator detail::thread_move_t<thread>()
    {
        return move();
    }
    thread(detail::thread_move_t<thread> x)
    {
        thread_info=x->thread_info;
        x->thread_info.reset();
    }
    thread& operator=(detail::thread_move_t<thread> x)
    {
        thread new_thread(x);
        swap(new_thread);
        return *this;
    }
  // ...

};

可移植接口

BOOST_THREAD_NO_COPYABLE(CLASS)
BOOST_THREAD_MOVABLE(CLASS)
BOOST_THREAD_MOVABLE_ONLY(CLASS)
BOOST_THREAD_COPYABLE_AND_MOVABLE(CLASS)
BOOST_THREAD_RV_REF(TYPE)、BOOST_THREAD_RV_REF_BEG 与 BOOST_THREAD_RV_REF_END
BOOST_THREAD_RV(V)
BOOST_THREAD_MAKE_RV_REF(RVALUE)
BOOST_THREAD_DCL_MOVABLE、BOOST_THREAD_DCL_MOVABLE_BEG(T1) 与 BOOST_THREAD_DCL_MOVABLE_END

为了使库代码可移植, Boost.Thread 使用一些宏, 这些宏要么使用 Boost.Move 提供的设施, 要么使用 Boost.Thread 之前版本提供的已弃用移动语义.

关于如何声明新的可移动类及其限制的完整描述, 参见 Boost.Move 文档.

  • BOOST_THREAD_RV_REF(TYPE) 等价于 BOOST_RV_REF(TYPE)
  • BOOST_THREAD_RV_REF_BEG 等价于 BOOST_RV_REF_BEG(TYPE)
  • BOOST_THREAD_RV_REF_END 等价于 BOOST_RV_REF_END(TYPE)
  • BOOST_THREAD_FWD_REF(TYPE) 等价于 `BOOST_FWD_REF(TYPE)

此外, 要使代码可移植还需要以下宏:

  • BOOST_THREAD_RV(V) 宏, 用于从 BOOST_THREAD_RV_REF(TYPE) 访问右值,
  • BOOST_THREAD_MAKE_RV_REF(RVALUE) 生成一个右值.
  • BOOST_THREAD_DCL_MOVABLE(CLASS) 以避免与 Boost.Move 冲突
  • BOOST_THREAD_DCL_MOVABLE_BEG(T1) 与 BOOST_THREAD_DCL_MOVABLE_END 是 BOOST_THREAD_DCL_MOVABLE 在参数为模板实例化时的变体.

还提供了其他一些宏, 必须包含在 public 部分:

  • BOOST_THREAD_NO_COPYABLE 声明一个不可复制类: 要么删除复制构造函数与复制赋值, 要么把它们移到 private 部分.
  • BOOST_THREAD_MOVABLE(CLASS) 声明所有到右值引用的隐式转换.
  • BOOST_THREAD_MOVABLE_ONLY(CLASS) 等价于 BOOST_MOVABLE_BUT_NOT_COPYABLE(CLASS)
  • BOOST_THREAD_COPYABLE_AND_MOVABLE(CLASS) 等价于 BOOST_COPYABLE_AND_MOVABLE(CLASS)
BOOST_THREAD_NO_COPYABLE(CLASS)

该宏把类标记为不可复制, 禁用复制构造与赋值.

BOOST_THREAD_MOVABLE(CLASS)

该宏把类标记为可移动, 声明所有到右值引用的隐式转换.

BOOST_THREAD_MOVABLE_ONLY(CLASS)

该宏把类型标记为可移动但不可复制, 禁用复制构造与赋值. 用户需要编写移动构造/赋值函数, 才能完整实现一个可移动但不可复制的类.

BOOST_THREAD_COPYABLE_AND_MOVABLE(CLASS)

该宏把类型标记为可复制且可移动. 用户需要编写移动构造/赋值函数和复制赋值运算符, 才能完整实现一个可复制且可移动的类.

BOOST_THREAD_RV_REF(TYPE)、BOOST_THREAD_RV_REF_BEG 与 BOOST_THREAD_RV_REF_END

该宏用于为标记为 BOOST_THREAD_COPYABLE_AND_MOVABLE 或 BOOST_THREAD_MOVABLE_ONLY 的类实现移动构造函数和赋值中的可移植语法.

BOOST_THREAD_RV_REF_BEG 与 BOOST_THREAD_RV_REF_END 用于参数以 > 结尾的情形, 以避免编译器错误.

BOOST_THREAD_RV(V)

虽然 Boost.Move 模拟允许使用点运算符访问右值引用 BOOST_THREAD_RV_REF(TYPE), 但遗留实现定义了 operator->. 因此我们需要一个宏 BOOST_THREAD_RV 来屏蔽这种差异. 例如

thread(BOOST_THREAD_RV_REF(thread) x)
{
    thread_info=BOOST_THREAD_RV(x).thread_info;
    BOOST_THREAD_RV(x).thread_info.reset();
}

这些宏的使用显著缩减了 Boost.Thread 中与移动相关的代码量.

BOOST_THREAD_MAKE_RV_REF(RVALUE)

虽然 Boost.Move 是最好的 C++03 移动模拟, 但仍有一些限制会影响库的使用方式. 例如, 使用以下声明时

class thread {
  // ...
private:
  thread(thread &);
public:
  thread(rv<thread>&);
  // ...
};

即使 thread 可以转换为 rv<thread>, 这在某些编译器上也可能不工作, 因为编译器会优先选择 private 复制构造函数.

thread mkth()
{
  return thread(f);
}

在这些编译器上, 我们需要改用显式转换. 库提供了一个 move 成员函数来规避该问题.

thread mkth()
{
  return thread(f).move();
}

请注意, 此情形下不能使用 ::boost::move, 因为 thread 不能隐式转换为 thread&.

thread mkth()
{
  return ::boost::move(thread(f));
}

为了使 Boost.Thread 代码可移植, 用户需要使用宏 BOOST_THREAD_MAKE_RV_REF, 用法如下

thread mkth()
{
  return BOOST_THREAD_MAKE_RV_REF(thread(f));
}

请注意, Boost.Thread 遗留的移动模拟也存在同样的限制.

BOOST_THREAD_DCL_MOVABLE、BOOST_THREAD_DCL_MOVABLE_BEG(T1) 与 BOOST_THREAD_DCL_MOVABLE_END

由于 Boost.Move 也定义了 boost::move 函数, 我们需要特化 has_move_emulation_enabled_aux 元函数.

template <>
struct has_move_emulation_enabled_aux<thread>
  : BOOST_MOVE_BOOST_NS::integral_constant<bool, true>
{};

以禁用以下 Boost.Move 重载

template <class T>
inline typename BOOST_MOVE_BOOST_NS::disable_if<has_move_emulation_enabled_aux<T>, T&>::type move(T& x);

宏 BOOST_THREAD_DCL_MOVABLE(CLASS)、BOOST_THREAD_DCL_MOVABLE_BEG(T1) 与 BOOST_THREAD_DCL_MOVABLE_END 用于此目的. 例如

BOOST_THREAD_DCL_MOVABLE(thread)

以及

BOOST_THREAD_DCL_MOVABLE_BEG(T) promise<T> BOOST_THREAD_DCL_MOVABLE_END

显式 bool 转换

operator unspecified-bool-type() const
bool operator!() const

当编译器支持时, 锁提供显式 bool 转换运算符.

explicit operator bool() const;

库提供一个到未定义类型的隐式转换, 该类型可用作条件表达式.

#if defined(BOOST_NO_CXX11_EXPLICIT_CONVERSION_OPERATORS)
    operator unspecified-bool-type() const;
    bool operator!() const;
#else
    explicit operator bool() const;
#endif

当需要显式转换时, 用户应使用 lock.owns_lock().

返回:

owns_lock() 返回 true, 即在布尔上下文中求值为 true 的值; 否则返回在布尔上下文中求值为 false 的值.

抛出:

无.

bool operator!() const

返回:

! owns_lock().

抛出:

无.

作用域枚举

标准库中定义的部分枚举是作用域枚举.

在不支持它们的编译器上, 库使用一个类来包装底层类型. 不使用

enum class future_errc
{
    broken_promise,
    future_already_retrieved,
    promise_already_satisfied,
    no_state
};

而是把这些类型声明为

BOOST_SCOPED_ENUM_DECLARE_BEGIN(future_errc)
{
    broken_promise,
    future_already_retrieved,
    promise_already_satisfied,
    no_state
}
BOOST_SCOPED_ENUM_DECLARE_END(future_errc)

这些宏使得在几乎所有情形下都可以把 'future_errc' 用作作用域枚举.

但存在一些限制:

  • 该类型不是 C++ enum, 因此 'is_enum<future_errc>' 将是 false_type.
  • 模拟的作用域枚举不能用于 switch, 也不能用作模板实参. 在这些情形下, 用户需要使用一些宏.

不使用

    switch (ev)
    {
    case future_errc::broken_promise:
// ...

而使用

switch (boost::native_value(ev))
{
case future_errc::broken_promise:

并且不使用

#ifdef BOOST_NO_CXX11_SCOPED_ENUMS
template <>
struct BOOST_SYMBOL_VISIBLE is_error_code_enum<future_errc> : public true_type { };
#endif

而使用

#ifdef BOOST_NO_CXX11_SCOPED_ENUMS
template <>
struct BOOST_SYMBOL_VISIBLE is_error_code_enum<future_errc::enum_type> : public true_type { };
#endif
