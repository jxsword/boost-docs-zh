自 boost 1.35 以来的变更

Boost 1.36.0 发布版在 thread 库中包含若干新特性:

  • 新的泛型 lock() 与 try_lock() 函数, 用于一次锁定多个互斥量.
  • 在编译器支持的情况下为移动语义提供右值引用支持.
  • 修复了若干缺陷并补充了缺失的函数 (包括严重的 win32 条件变量缺陷) .
  • scoped_try_lock 类型现在与 Boost 1.34.0 及更早版本向后兼容.
  • 支持通过向 boost::thread 构造函数提供附加参数, 把函数实参传递给线程函数.
  • 为 timed_lock 与 timed_wait 函数添加了向后兼容的重载, 允许使用 xtime 表示超时.

2.0.0 版 - 自 boost 1.34 以来的变更

自 boost 1.34 发布以来, Boost.Thread 中几乎每一行代码都被修改过. 不过, 大多数接口变更都是扩展, 因此新代码在很大程度上与旧代码向后兼容. 新特性与破坏性变更如下所述.

新特性

  • boost::thread 的实例与各种锁类型现在都可移动.
  • 线程可以在 中断点 被中断.
  • 现在, 条件变量可以与任何实现 Lockable 概念 的类型一起使用——通过使用 boost::condition_variable_any (boost::condition 是 typedef 的别名, 指向 boost::condition_variable_any, 为向后兼容而提供) . boost::condition_variable 作为一种优化提供, 且只能与 boost::unique_lock<boost::mutex> (boost::mutex::scoped_lock) .
  • 线程 ID 与 boost::thread 分离, 因此线程可以获取自己的 ID (使用 boost::this_thread::get_id()) , 并且由于 ID 具有全套比较运算符, 可以用作关联容器中的键.
  • 超时现在使用 Boost DateTime 库实现: 通过 typedef boost::system_time 表示绝对超时, 并在许多情况下支持相对超时. boost::xtime 仅出于向后兼容而受支持.
  • 锁实现为公开可用的模板 boost::lock_guard、boost::unique_lock、boost::shared_lock 与 boost::upgrade_lock, 它们以互斥量类型为模板参数. Lockable 概念 已扩展为包含公开可用的 lock() 与 unlock() 成员函数, 锁类型会使用这些函数.

破坏性变更

下面的列表应当涵盖所有破坏向后兼容性的公开接口变更.

  • boost::try_mutex 已移除, 其功能被并入 boost::mutex. boost::try_mutex 保留为 typedef, 但不再是独立的类.
  • boost::recursive_try_mutex 已移除, 其功能被并入 boost::recursive_mutex. boost::recursive_try_mutex 保留为 typedef, 但不再是独立的类.
  • boost::detail::thread::lock_ops 已移除. 依赖 lock_ops 这一实现细节的代码将不再工作, 因为该细节已被移除——互斥量类型现在拥有公开的 lock() 与 unlock() 成员函数, 已无必要保留它.
  • scoped_lock 构造函数不再提供第二参数类型为 bool 的版本. 在之前的 boost 发布版中, 
    boost::mutex::scoped_lock some_lock(some_mutex,false);
    可用于创建与互斥量关联但在构造时不加锁的锁对象. 此设施现在已被以 boost::defer_lock_type 作为第二参数的构造函数取代: 
    boost::mutex::scoped_lock some_lock(some_mutex,boost::defer_lock);
  • locked() 成员函数 (位于 scoped_lock 类型中) 已重命名为 owns_lock().
  • 你不再能获得代表当前线程的 boost::thread 实例: 默认构造的 boost::thread 对象不与任何线程关联. 这种线程对象的唯一用途是支持比较运算符: 此功能已移至 boost::thread::id.
  • 有缺陷的 boost::read_write_mutex 已被 boost::shared_mutex 取代.
  • boost::mutex 现在永远不会递归. 对于 1.35 之前的 Boost 发布版, boost::mutex 在 Windows 上是递归的, 而在 POSIX 平台上不是.
  • 当将 boost::recursive_mutex 用于对 boost::condition_variable_any::wait() 的调用时, 互斥量只会解锁一层, 而不是完全解锁. 先前的行为并未得到保证, 也未在测试中体现.
