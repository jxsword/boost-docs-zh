线程本地存储

类 thread_specific_ptr

概要

线程本地存储允许多线程应用为每个线程拥有给定数据项的独立实例. 在单线程应用中会使用静态或全局数据的地方, 这在多线程应用中可能导致竞争、死锁或数据损坏. 一个例子是 C errno 变量, 用于存储与标准 C 库函数相关的错误码. 支持多线程应用的编译器为每个线程提供 errno 的独立实例是常见做法 (POSIX 也要求如此) , 以避免不同线程竞争读取或更新该值.

虽然编译器经常以声明语法扩展的形式提供此设施 (例如在 __declspec(thread) 或命名空间作用域变量声明上加 thread 或 static 注解) , 但这种支持不可移植, 且常常有某种限制, 例如只支持 POD 类型.

用 boost::thread_specific_ptr 实现可移植的线程本地存储

boost::thread_specific_ptr 提供一种可移植的线程本地存储机制, 可在 Boost.Thread 支持的所有编译器上工作. 每个 boost::thread_specific_ptr 实例表示一个指向对象的指针 (例如 errno) ——每个线程必须拥有不同的值. 当前线程的值可以用 get() 成员函数获取, 或使用 * 和 -> 指针解引用运算符获取. 初始时指针在每个线程中的值为 NULL, 但当前线程的值可以用 reset() 成员函数设置.

如果使用 reset() 更改当前线程的指针值, 则通过调用清理例程销毁前一个值. 或者, 可以把存储的值重置为 NULL, 并通过调用 release() 成员函数返回先前的值, 让应用重新承担销毁对象的责任.

线程退出时的清理

当线程退出时, 与每个 boost::thread_specific_ptr 实例关联的对象被销毁. 默认情况下, 指针 p 所指向的对象通过调用 delete p 销毁, 但可以通过向构造函数提供清理例程为 boost::thread_specific_ptr 的特定实例覆盖此行为. 在这种情况下, 对象通过调用 func(p) 销毁, 其中 func 是提供给构造函数的清理例程. 清理函数以未指定的顺序调用. 如果清理例程设置了一个已经被清理过的 boost::thread_specific_ptr 实例的关联值, 该值会被加入清理列表. 当不再有带值的 boost::thread_specific_ptr 实例时, 清理结束.

注: 在某些平台上, 对用平台原生 API 创建的线程不执行线程特定数据的清理. 在这些平台上, 只有以 boost::thread 启动的线程才执行此类清理, 除非在该线程中手动调用 boost::on_thread_exit().

关于键的性质的设计理由

Boost.Thread 使用 thread_specific_ptr 实例的地址作为线程特定指针的键. 这避免了创建/销毁需要锁保护的键以防止竞争条件. 这有一点点性能负担, 因为访问必须通过关联容器进行.

类 thread_specific_ptr

//  #include <boost/thread/tss.hpp>

namespace boost
{
  template <typename T>
  class thread_specific_ptr
  {
  public:
      thread_specific_ptr();
      explicit thread_specific_ptr(void (*cleanup_function)(T*));
      ~thread_specific_ptr();

      T* get() const;
      T* operator->() const;
      T& operator*() const;

      T* release();
      void reset(T* new_value=0);
  };
}

thread_specific_ptr();

要求:

delete this->get() 是格式良好的.

效果:

构造一个 thread_specific_ptr 对象, 用于存储指向每个线程特有的 T 类型对象的指针. 默认的基于 delete 的清理函数将用于在调用 reset() 或线程退出时销毁任何线程本地对象.

抛出:

如果发生错误则为 boost::thread_resource_error.

explicit thread_specific_ptr(void (*cleanup_function)(T*));

要求:

cleanup_function(this->get()) 不抛出任何异常.

效果:

构造一个 thread_specific_ptr 对象, 用于存储指向每个线程特有的 T 类型对象的指针. 所提供的 cleanup_function 将用于在调用 reset() 或线程退出时销毁任何线程本地对象.

抛出:

如果发生错误则为 boost::thread_resource_error.

~thread_specific_ptr();

要求:

与此 thread_specific_ptr 关联的所有线程特定实例 (可能与本线程关联的那个除外) 必须为空.

效果:

调用 this->reset() 清理当前线程的关联值, 并销毁 *this.

抛出:

无.

备注:

这一要求源于: 为了删除所有这些实例, 实现将被迫维护一个拥有关联特定指针的所有线程的列表, 这与线程特定数据的目标相悖.

注释

需要小心确保在 boost::thread_specific_ptr 实例被销毁后仍在运行的线程不对该实例调用任何成员函数.

T* get() const;

返回:

与当前线程关联的指针.

抛出:

无.

注释

boost::thread_specific_ptr 实例关联的初始值对每个线程都是 NULL.

T* operator->() const;

返回:

this->get()

抛出:

无.

T& operator*() const;

要求:

this->get 不是 NULL.

返回:

*(this->get())

抛出:

无.

void reset(T* new_value=0);

效果:

如果 this->get()!=new_value 且 this->get() 非NULL, 则酌情调用 delete this->get() 或 cleanup_function(this->get()). 把 new_value 存储为与当前线程关联的指针.

后置条件:

this->get()==new_value

抛出:

如果发生错误则为 boost::thread_resource_error.

T* release();

效果:

返回 this->get() 并把 NULL 存储为与当前线程关联的指针, 而不调用清理函数.

后置条件:

this->get()==0

抛出:

无.
