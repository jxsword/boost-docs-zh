动机

如今许多模板库都提供对象生成器, 利用 C++ 模板实参推导设施来简化对象创建. 考虑 std::pair. 为了实例化这个类模板并创建该实例化的一个临时对象, 必须提供模板实参以及构造函数参数:

std::pair<int, double>(5, 3.14159);

为避免这种重复, STL 提供了 std::make_pair 对象生成器. 使用它时, 模板参数的类型从提供的函数实参推导:

std::make_pair(5, 3.14159);

对临时对象来说这已经足够. 然而, 当需要分配一个具名对象时, 问题再次出现:

std::pair<int, double> p(5, 3.14159);

对象生成器不再有帮助:

std::pair<int, double> p = std::make_pair(5, 3.14159);

若能从初始化表达式 (右侧) 推导出对象 (左侧) 的类型就太好了, 但当前的 C++ 语法不允许这样做.

上面的例子展示了问题的本质, 但没有展示其规模. 许多库, 尤其是表达式模板库, 会创建类型极其复杂的对象, 并想方设法把这种复杂性隐藏在对象生成器后面. 考虑一个小小的 Boost.Lambda 函子:

_1 > 15 && _2 < 20

如果想为这样一个看似简单的函子分配一个具名副本, 就必须写出类似这样的东西:

lambda_functor<
    lambda_functor_base<
        logical_action<and_action>,
        tuple<
            lambda_functor<
                lambda_functor_base<
                    relational_action<greater_action>,
                    tuple<
                        lambda_functor<placeholder<1> >,
                        int const
                    >
                >
            >,
            lambda_functor<
                lambda_functor_base<
                    relational_action<less_action>,
                    tuple<
                        lambda_functor<placeholder<2> >,
                        int const
                    >
                >
            >
        >
    >
>
f = _1 > 15 && _2 < 20;

并不十分优雅. 为了解决这个问题 (以及其他一些问题), C++ 标准委员会正在考虑对标准语言的若干增补, 例如 typeof/decltype 与 auto (见 http://www.open-std.org/jtc1/sc22/wg21/docs/papers/2004/n1607.pdf).

typeof 运算符 (或 decltype, 它是 typeof 的一个稍有不同的变体) 允许在编译期确定表达式的类型. 使用 typeof, 上面的例子可以大幅简化:

typeof(_1 > 15 && _2 < 20) f = _1 > 15 && _2 < 20;

好多了, 但仍存在一些重复. auto 类型解决了剩下的问题:

auto f = _1 > 15 && _2 < 20;

Boost.Typeof 库的目的是提供一种基于库的解决方案, 在基于语言的设施加入标准并广泛可用之前, 可以使用该方案.
