常见问题(FAQ)

  • 问: 为什么 lexical_cast<int8_t>("127") 会抛出 bad_lexical_cast?
    • 答: 类型 int8_t 是一个 typedef, 对应于 char 或 signed char. 到这些类型的词汇转换只是从源中读取一个字节, 但由于源有多个字节, 因此抛出异常. 请使用其他整数类型, 例如 int 或 short int. 如果边界检查很重要, 还可以调用 boost::numeric_cast: numeric_cast<int8_t>(lexical_cast<int>("127")); 


  • 
          问: 为什么 lexical_cast<unsigned char>("127") 会抛出 bad_lexical_cast? 
    • 
                答: 到任何 char 类型的词汇转换只是从源中读取一个字节. 但由于源有多个字节, 因此抛出异常. 请使用其他整数类型, 例如 int 或 short int. 如果边界检查很重要, 还可以调用 boost::numeric_cast: numeric_cast<unsigned char>(lexical_cast<int>("127"));
              
    
        




  • 
          问: 为什么 lexical_cast<std::string> 在作用于 int8_t 或 uint8_t 时不符合我的预期? 
    • 
                答: 如上所述, 注意 int8_t 与 uint8_t 实际上是 char, 并且按此格式化. 为避免这一点, 请先转换为整数类型: lexical_cast<std::string>(static_cast<int>(n));
              
    
        




  • 
          问: 本实现总是会重置底层流对象的 ios_base::skipws 标志. 这破坏了我的 operator>>, 它只有在该标志存在时才能工作. 能否移除重置该标志的代码? 
    • 
                答: 也许在未来的版本中会如此. Lexical Conversion Library Proposal for TR2, N1973 (Kevlin Henney 与 Beman Dawes) 并不要求重置该标志, 但请记住 Lexical Conversion Library Proposal for TR2, N1973 尚未被委员会接受. 顺便说一句, 这是一个让你的 operator>> 更通用的大好机会. 读一本好的 C++ 书, 学习 std::sentry 和 ios_state_saver.
    
        




  • 
          问: 为什么 std::cout << boost::lexical_cast<unsigned int>("-1"); 不抛出异常, 而是输出 4294967295? 
    • 
                答: boost::lexical_cast 的行为与 std::stringstream 相同, 后者使用 num_get 函数 (来自 std::locale) 来转换数字. 如果查看 Programming languages — C++, 我们会看到 num_get 使用 scanf 的规则进行转换. 而在 C99 标准中, 对无符号输入值来说负号是可选的, 因此即使读入负数也不会产生错误, 结果将是对二的补码 (two's complement).
    
        




  • 
          问: 为什么 boost::lexical_cast<int>(L'A'); 输出 65, 而 boost::lexical_cast<wchar_t>(L"65"); 不抛出异常? 
    • 
                答: 如果使用旧版 Visual Studio 或以 /Zc:wchar_t- 标志编译代码, boost::lexical_cast 会把单个 wchar_t 字符视为 unsigned short. 这不是 boost::lexical_cast 的错误, 而是你所使用的编译器选项的限制.
    
        




  • 
          问: 为什么 boost::lexical_cast<double>("-1.#IND"); 会抛出 boost::bad_lexical_cast? 
    • 
                答: "-1.#IND" 是违反标准的编译器扩展. 要得到 NaN 与 Inf 值, 你应当输入 "-nan"、"nan"、"inf"、"-inf" (不区分大小写) 字符串. 当输入值为 NaN 或 Inf 时, boost::lexical_cast<string> 会输出 "-nan"、"nan"、"inf"、"-inf" 字符串.
    
        




  • 
          问: 使用 boost::lexical_cast 转换非零结尾字符串或子字符串的最快方式是什么? 
    • 
                答: 使用 boost::iterator_range 进行转换, 或使用带两个参数的 lexical_cast 重载. 例如, 若要将字符串中的两个字符转换为 int (字符串为 str), 你应当写 lexical_cast<int>(make_iterator_range(str.data(), str.data() + 2)); 或 lexical_cast<int>(str.data(),
                2);.
