概要

lexical_cast
bad_lexical_cast
try_lexical_convert

boost/lexical_cast.hpp 中定义的库特性:

namespace boost
{
    class bad_lexical_cast;

    template<typename Target, typename Source>
      Target lexical_cast(const Source& arg);

    template <typename Target>
      Target lexical_cast(const AnyCharacterType* chars, std::size_t count);

    namespace conversion
    {
        template<typename Target, typename Source>
            bool try_lexical_convert(const Source& arg, Target& result);

        template <typename AnyCharacterType, typename Target>
            bool try_lexical_convert(const AnyCharacterType* chars, std::size_t count, Target& result);

    } // namespace conversion
} // namespace boost

lexical_cast 

template<typename Target, typename Source>
  Target lexical_cast(const Source& arg);

将 arg 流式输出到基于标准库字符串的流中, 再将其作为 Target 对象流式读出并返回结果. 当 Target 为 std::string 或 std::wstring 时, 流提取会取走字符串的全部内容 (包括空格), 而不依赖默认的 operator>> 行为. 若转换不成功, 则抛出 bad_lexical_cast 异常.

template <typename Target>
  Target lexical_cast(const AnyCharacterType* chars, std::size_t count);

接受一个 count 字符数组作为输入参数, 并将其作为 Target 对象流式输出. 若转换不成功, 则抛出 bad_lexical_cast 异常. 此调用可用于处理非零结尾的字符数组, 或只处理字符数组的某一部分.

两个函数对参数类型和结果类型的要求如下:

  • Source 必须满足 OutputStreamable, 即定义了 operator<<, 其左侧为 std::ostream 或 std::wostream 对象, 右侧为参数类型的实例.
  • Target 必须满足 InputStreamable, 即定义了 operator>>, 其左侧为 std::istream 或 std::wistream 对象, 右侧为结果类型的实例.
  • Target 必须满足 CopyConstructible [20.1.3].
  • Target 必须满足 DefaultConstructible, 即可以对该类型的对象进行默认初始化 [8.5, 20.1.4].

底层流的字符类型被假定为 char, 除非 Source 或 Target 要求宽字符流, 此时底层流使用 wchar_t. 以下类型也可以使用 char16_t 或 char32_t 进行宽字符流操作:

  • 单个字符: char16_t, char32_t
  • 字符数组: char16_t *, char32_t *, const char16_t *, const char32_t *
  • 字符串: std::basic_string, boost::containers::basic_string
  • boost::iterator_range<WideCharPtr>, 其中 WideCharPtr 为指向宽字符的指针或指向 const 宽字符的指针
  • boost::array<CharT, N> 和 std::array<CharT, N>, boost::array<const CharT, N> 和 std::array<const CharT, N>
重要

许多编译器和运行时库在使用新的 Unicode 字符进行转换时会失败. 在使用这些新类型之前, 请确保以下代码能够编译并输出非零值:

std::cout
    << boost::lexical_cast<std::u32string>(1.0).size()
    << "  "
    << boost::lexical_cast<std::u16string>(1.0).size();

当需要对转换进行更高程度的控制时, std::stringstream 和 std::wstringstream 提供了更合适的途径. 当需要非基于流的转换时, lexical_cast 并不适合此类任务, 且不会为这类场景做特殊处理.

bad_lexical_cast 

class bad_lexical_cast : public std::bad_cast
{
public:
    ... // same member function interface as std::exception
};

用于指示 lexical_cast 运行期失败的异常.

try_lexical_convert

boost::lexical_cast 仍是词汇转换的主接口, 在大多数情况下应默认使用它. 不过, 有些开发者希望复用 boost::lexical_cast 的全部优化来构造自己的转换函数. 这正是 boost::conversion::try_lexical_convert 函数的用武之地.

try_lexical_convert 在转换成功时返回 true, 否则返回 false. 若转换失败且返回了 false, 则 result 输出变量的状态是未定义的.

实际上, boost::lexical_cast 是用 try_lexical_convert 实现的:

template <typename Target, typename Source>
inline Target lexical_cast(const Source &arg)
{
    Target result;

    if (!conversion::try_lexical_convert(arg, result))
        throw bad_lexical_cast();

    return result;
}

try_lexical_convert 放宽了 Target 类型对 CopyConstructible 与 DefaultConstructible 的要求. Target 与 Source 仍须满足以下要求:

  • Source 必须满足 OutputStreamable, 即定义了 operator<<, 其左侧为 std::ostream 或 std::wostream 对象, 右侧为参数类型的实例.
  • Target 必须满足 InputStreamable, 即定义了 operator>>, 其左侧为 std::istream 或 std::wistream 对象, 右侧为结果类型的实例.
