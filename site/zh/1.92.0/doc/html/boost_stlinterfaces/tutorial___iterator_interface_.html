教程: iterator_interface

注释

iterator_interface 提供的所有成员函数都位于你的迭代器的基类中 - 即 iterator_interface - 因此如果你在派生迭代器中定义了同名的成员函数, 它们会被隐藏. 如果你不喜欢 iterator_interface 提供的任何成员函数的语义, 尽管替换它.

iterator_interface 模板

虽然一个给定的迭代器可能关联大量操作, 但它需要定义的基础操作只有少数几个; 它支持的完整操作集都可以用这个小得多的基础来定义.

可以用用户自定义操作的一个子集来定义任何迭代器 Iter. 通过使 Iter 派生自 iterator_interface, 我们可以生成完整的操作集. iterator_interface 在 C++20 及更早版本中使用 CRTP, 在 C++23 及更高版本中使用推导的 this. 下面是 iterator_interface 的声明:

template<
    typename Derived,
    typename IteratorConcept,
    typename ValueType,
    typename Reference = ValueType &,
    typename Pointer = ValueType *,
    typename DifferenceType = std::ptrdiff_t>
struct iterator_interface;

或者, 对于 C++23 及更高版本:

template<
    typename IteratorConcept,
    typename ValueType,
    typename Reference = ValueType &,
    typename Pointer = ValueType *,
    typename DifferenceType = std::ptrdiff_t>
struct iterator_interface;

我们来逐项拆解.

Derived 是你派生 iterator_interface 时所用的类型.

重要

在 C++23 及更高版本中, 只要你没有定义 BOOST_STL_INTERFACES_DISABLE_DEDUCED_THIS, 就不必把派生类型传给 iterator_interface; 它没有 Derived 模板参数.

IteratorConcept 定义迭代器类别/概念. 它必须是 C++ 标准迭代器 tag 类型之一, 例如 std::forward_iterator_tag. 在 C++20 及更高版本中, std::contiguous_iterator_tag 也是可用的合法 tag.

ValueType 用于定义迭代器的 value_type typedef. 类似地, Reference 与 Pointer 分别用于定义迭代器的 reference 与 pointer typedef.

提示

Reference 不必是引用类型, Pointer 也不必是指针类型. 在编写代理迭代器时, 这一事实非常有用.

DifferenceType 用于定义迭代器的 difference_type. 别做怪人; 保持默认类型 std::ptrdiff_t 即可.

代理迭代器

有时你需要创建一个迭代器 I, 使得 I::reference_type 不是 (可能是 const 的) 对 I::value_type 的引用. 例如, 假设你想制作一个 zip 迭代器, 从两个独立的底层序列产生值对. 对序列 A 与 B, 其各自的 value_type 为 T 与 U, zip 迭代器的一种可能的 reference_type 是 std::pair<T &, U &> (这不同于对 pair 的引用, 例如 std::pair<T, U> &). 每个这样的 pair 都会包含一个对 A 中某个元素的引用, 以及一个对 B 中对应元素的引用.

再举一个例子, 如果你想要一个表示无穷序列 0, 1, 2, ... 的迭代器 I, 你将无法对其中大多数乃至所有值形成引用; 你会改为在需要每个值时生成一个临时对象. 这意味着 I::value_type 完全不涉及引用; 它可以是 int 或 double.

定义代理迭代器时, 可以使用一个为 iterator_interface 的参数提供合理默认值的模板别名:

template<
    typename Derived,
    typename IteratorConcept,
    typename ValueType,
    typename Reference = ValueType,
    typename DifferenceType = std::ptrdiff_t>
using proxy_iterator_interface = iterator_interface<
    Derived,
    IteratorConcept,
    ValueType,
    Reference,
    proxy_arrow_result<Reference>,
    DifferenceType>;

或者, 对于 C++23 及更高版本:

template<
    typename IteratorConcept,
    typename ValueType,
    typename Reference = ValueType,
    typename DifferenceType = std::ptrdiff_t>
using proxy_iterator_interface = iterator_interface<
    IteratorConcept,
    ValueType,
    Reference,
    proxy_arrow_result<Reference>,
    DifferenceType>;
注释

如上所示, proxy_iterator_interface 使用名为 proxy_arrow_result 的模板作为其指针类型. 该模板会复制通过 operator* 获得的任何值, 然后在其 operator-> 中返回指向该副本的指针. 若这是性能考量, 你可能想改用别的东西.

重要

如果你使用 C++23 或更高版本且未定义 BOOST_STL_INTERFACES_DISABLE_DEDUCED_THIS, 则上面的 Derived 模板参数将不存在.

注释

对于 random_access_iterator, 操作 i - i2 用于提供所有关系运算符, 包括 operator==() 与 operator!=(). 如果你在为不连续序列定义迭代器 (例如 std::deque), 这种 operator==() 实现可能不是最优的. 此时请提供你自己的 operator==(). operator!=() 将在 operator== 可用时提供.

重要说明: operator++() 与 operator--()

这种做法有一个小波折. 当你定义 operator++() 时 (位于你的迭代器类型 Derived 中), iterator_interface 会定义后置递增, 即 operator++(int). 但由于 Derived 有一个 operator++, 其基类 iterator_interface 也有, Derived 中的那个会 隐藏 iterator_interface 中的那个.

因此, 你需要添加一条 using 声明, 使基类中的 operator++ 在派生类中可见. 例如, 在 node_iterator 示例中有这些行:

    using base_type = boost::stl_interfaces::iterator_interface<
#if !BOOST_STL_INTERFACES_USE_DEDUCED_THIS
        node_iterator<T>,
#endif
        std::forward_iterator_tag, T>;
    using base_type::operator++;

重要

以上所述同样适用于 operator--. 因此, 对双向迭代器, 你还需要添加类似 using base_type::operator--; 的行.

注释

对随机访问迭代器而言这些 using 声明并不需要, 因为在这种情况下 Derived 没有 operator++().

融会贯通

好, 我们来实际定义一个简单的迭代器. 假设你需要与一些带有手写链表的遗留代码交互:

template<typename T>
struct node
{
    T value_;
    node * next_; // == nullptr in the tail node
};

我们无法把这段代码改为使用 std::list, 但若能把所有标准算法复用于该类型就好了. 定义一个迭代器就能达到这个目标.

template<typename T>
struct node_iterator
    : boost::stl_interfaces::iterator_interface<
#if !BOOST_STL_INTERFACES_USE_DEDUCED_THIS
          node_iterator<T>,
#endif
          std::forward_iterator_tag, T>

我们使 node_iterator 派生自 iterator_interface, 由于在 C++20 及更早版本中使用 CRTP, 我们必须首先传入 node_iterator 作为 Derived 模板参数 (若 BOOST_STL_INTERFACES_USE_DEDUCED_THIS 未定义), 这样 iterator_interface 才知道要转换成哪个派生类型才能访问用户自定义操作. 然后, 我们传入 std::forward_iterator_tag 作为 IteratorConcept, 因为这对单向链表是合适的. 最后, 我们传入 T, 让 iterator_interface 知道我们迭代器的 value_type 是什么.

其余模板参数保持默认: T & 用于 Reference, T * 用于 Pointer, 以及 std::ptrdiff_t 用于 DifferenceType. 对几乎所有迭代器你都会这么做. 最常见的例外通常是某种代理迭代器. 另一个例外是为了更好的代码生成, 你想对常量迭代器返回内建值而非引用. 后者的示例见引言中的 repeated_chars_iterator; 出于这个原因, 其 Reference 模板参数是 char.

constexpr node_iterator() noexcept : it_(nullptr) {}
constexpr node_iterator(node<T> * it) noexcept : it_(it) {}

接下来我们定义两个构造函数: 默认构造函数, 以及接受 node 指针的构造函数. forward_iterator 概念要求有默认构造函数, 但 iterator_interface 无法提供它, 因为构造函数在派生类型中若没有用户干预是不可见的.

重要

每个迭代器概念都要求有默认构造函数.

constexpr T & operator*() const noexcept { return it_->value_; }
constexpr node_iterator & operator++() noexcept
{
    it_ = it_->next_;
    return *this;
}
friend constexpr bool
operator==(node_iterator lhs, node_iterator rhs) noexcept
{
    return lhs.it_ == rhs.it_;
}

接下来, 我们定义 iterator_interface 完成其工作所需的用户自定义操作. 不出所料, 这三个必需的操作都非常直接.

注释

这里, 我把 operator==() 实现为隐藏友元函数. 如果改成实现为成员函数, 也同样可行, 像这样:

constexpr bool operator==(node_iterator rhs) const noexcept
{
    return it_ == rhs.it_;
}

这两种形式都可以, 因为 iterator_interface 是基于概念的 - 只要相应的表达式对 iterator_interface 模板完成其工作而言是良构的即可.

最后, 我们需要一条 using 声明, 使 iterator_interface::operator++(int) 可见:

    using base_type = boost::stl_interfaces::iterator_interface<
#if !BOOST_STL_INTERFACES_USE_DEDUCED_THIS
        node_iterator<T>,
#endif
        std::forward_iterator_tag, T>;
    using base_type::operator++;

下面是我们可能如何使用刚定义的前向迭代器:

node_iterator<int> const first(&nodes[0]);
node_iterator<int> const last;
for (auto it = first; it != last; it++) {
    std::cout << *it << " "; // Prints 0 1 2 3 4
}
std::cout << "\n";

适配现有迭代器怎么办?

问得好. 如果你想制作类似过滤迭代器, 或者说 UTF-8 到 UTF-32 转码迭代器的东西, 你是从一个现有迭代器出发进行适配的. 只要有这样一个基础迭代器 - 它已经具备语义正确的操作 - 就有办法免去编写全部用户自定义基础函数的工作.

例如, 考虑一个迭代器, 它包含指向 int 数组的指针, 以及类型为 Pred 的谓词. 它会滤掉不满足谓词的整数. 由于我们使用的是现有迭代器 (指向 int 的指针), 双向迭代器所需的操作 (以及更多) 我们已经全都有了, 只是 operator++ 作用于 int * 时不会像我们期望的那样跳过元素. 代码如下:

template<typename Pred>
struct filtered_int_iterator : boost::stl_interfaces::iterator_interface<
#if !BOOST_STL_INTERFACES_USE_DEDUCED_THIS
                                   filtered_int_iterator<Pred>,
#endif
                                   std::bidirectional_iterator_tag,
                                   int>
{
    filtered_int_iterator() : it_(nullptr) {}
    filtered_int_iterator(int * it, int * last, Pred pred) :
        it_(it),
        last_(last),
        pred_(std::move(pred))
    {
        // We need to do this in the constructor so that operator== works
        // properly on two filtered_int_iterators, when they bound a sequence
        // in which none of the ints meets the predicate.
        it_ = std::find_if(it_, last_, pred_);
    }

    // A bidirectional iterator based on iterator_interface usually required
    // four user-defined operations.  since we are adapting an existing
    // iterator (an int *), we only need to define this one.  The others are
    // implemented by iterator_interface, using the underlying int *.
    filtered_int_iterator & operator++()
    {
        it_ = std::find_if(std::next(it_), last_, pred_);
        return *this;
    }

    // It is really common for iterator adaptors to have a base() member
    // function that returns the adapted iterator.
    int * base() const { return it_; }

private:
    // Provide access to these private members.
    friend boost::stl_interfaces::access;

    // These functions are picked up by iterator_interface, and used to
    // implement any operations that you don't define above.  They're not
    // called base() so that they do not collide with the base() member above.
    //
    // Note that the const overload does not strictly speaking need to be a
    // reference, as demonstrated here.
    constexpr int *& base_reference() noexcept { return it_; }
    constexpr int * base_reference() const noexcept { return it_; }

    int * it_;
    int * last_;
    Pred pred_;
};

// A make-function makes it easier to deal with the Pred parameter.
template<typename Pred>
auto make_filtered_int_iterator(int * it, int * last, Pred pred)
{
    return filtered_int_iterator<Pred>(it, last, std::move(pred));
}

所以, 我们要做的只是让 iterator_interface 知道存在一个可供使用的基础迭代器 - 通过实现 base_reference() - 于是我们没有定义的操作由 iterator_interface 替我们定义好了.

下面是该迭代器的实际运行情况:

std::array<int, 8> ints = {{0, 1, 2, 3, 4, 5, 6, 7}};
int * const ints_first = ints.data();
int * const ints_last = ints.data() + ints.size();

auto even = [](int x) { return (x % 2) == 0; };
auto first = make_filtered_int_iterator(ints_first, ints_last, even);
auto last = make_filtered_int_iterator(ints_last, ints_last, even);

// This is an example only.  Obviously, we could have called
// std::copy_if() here.
std::vector<int> ints_copy;
std::copy(first, last, std::back_inserter(ints_copy));
assert(ints_copy == (std::vector<int>{0, 2, 4, 6}));

检查你的成果

Boost.STLInterfaces 能够检查你所写的部分代码与你要编写的迭代器的概念是否兼容. 它无法检查所有内容. 例如, Boost.STLInterfaces 不知道你的派生类型是否包含默认构造函数, 而这是所有迭代器都要求的. 特别是, iterator_interface 无法 static_assert Derived() 的良构性, 因为 Derived 在 iterator_interface 的函数体内部是不完整类型 - iterator_interface 是 Derived 的基类, 而不是相反.

既然你可以轻松地 static_assert 某个类型是否为给定概念的模型, 一个好的实践是在定义迭代器类型之后放置这样一条 static_assert.

例如, 在 node_iterator 之后你会发现这样的代码:

// static_assert(std::forward_iterator<node_iterator>, ""), or nothing in
// C++17 and earlier.
BOOST_STL_INTERFACES_STATIC_ASSERT_CONCEPT(
    node_iterator<int>, std::forward_iterator)

把这当作良好的代码卫生. 没有这个简单的检查, 你最终很可能要面对一条带有超长模板实例化栈的错误信息.

还有一个宏可以帮助你检查 std::iterator_traits 是否良构并提供正确的类型. 参见 BOOST_STL_INTERFACES_STATIC_ASSERT_ITERATOR_TRAITS.
