设计理由

存在最小派生类型约束

这是对 Derived 模板参数的约束, 适用于 iterator_interface, view_interface 与 sequence_container_interface:

std::enable_if_t<
    std::is_class<Derived>::value &&
    std::is_same<Derived, std::remove_cv_t<Derived>>::value>

这防止用 int, const 类型, 引用类型等实例化接口模板.

更进一步的约束是不可能的 (例如, 要求传给 view_interface 的 Derived 模板参数对应的类型同时具有 begin() 与 end()), 因为 Derived 在每个 *_interface 模板内部是不完整类型.

使用特殊的授权访问 struct

接口模板主要依赖其 Derived 模板参数提供的公有成员. 然而, iterator_interface 要求你提供 base_reference() 函数才能表现得像适配器. 由于至少非 const 重载会提供对你某个数据成员的非 const 左值引用, 把 base_reference() 留作公有成员会破坏许多类型的封装. 为了让用户能够把这些重载保持为私有, 才有了 access.

iterator_interface 可以表现得像适配器, 而其他接口模板不能

把这一功能加入 view_interface 并没有多大意义, 因为它毕竟只用到 begin() 与 end(), 即 Derived 类型的这两个成员.

对 sequence_container_interface 来说它同样没有太大意义. 想想你写过多少个容器适配器. 这种使用场景并不常见.

iterator_interface 接受大量模板参数, 而其他接口模板不接受

iterator_interface 实际上确实接受很多模板参数. 不过, 它通常只接受三个: Derived 类型, 迭代器类别, 以及迭代器的 value_type.

编写代理迭代器时, 通常使用 proxy_iterator_interface 别名, 同样只需要这三个模板参数. 尽管可以选择更多模板参数, 其余的很少有必要.

相比之下, view_interface 与 sequence_container_interface 模板的模板参数非常少. 对 view_interface 来说, 这是因为 view 概念中没有成员 typedef. 对 sequence_container_interface 而言, 一个以缩减代码量为目的的模板却要接受 14 个模板参数, 这被认为是荒谬的.

sequence_container_interface 不会推导嵌套类型, 例如 iterator

sequence_container_interface 可以推导标准序列容器所需的某些嵌套类型. 例如, iterator 可以推导为 decltype(*begin()). 但是, 类型 D (派生自 sequence_container_interface) 可能需要在其接口或实现中使用其中某些嵌套类型 - 例如 iterator. 若是如此, 这些嵌套类型在解析过程中出现得不够早, 无法用于 D - 如果它们来自 sequence_container_interface 中的推导. 这会让用户陷入尴尬境地: 不得不用另一个名称定义同一个嵌套类型, 以便能在 D 中使用. 把这些类型留给用户定义似乎更好.

sequence_container_interface 不支持关联容器或无序关联容器

确实如此. 关联容器的接口假定它们是基于节点的容器. 在现代硬件上, 基于节点的容器效率不高, 我不想鼓励人们写更多这类容器. 无序关联容器的接口排除了开放寻址, 我同样不想鼓励更多这种做法.

sequence_container_interface 不满足分配器感知容器要求

这一点或许不明显, 但 sequence_container_interface 确实无法帮助满足分配器感知要求. 分配器感知要求中除 3 项外全部是特殊成员与构造函数. 依据语言规则, CRTP 基类模板无法提供这些. 剩下的有 allocator_type typedef, 它必须由用户提供; 成员 swap(), 它本来就是容器要求 (分配器感知表中的条目只是规定成员 swap() 必须是常数时间); 以及 get_allocator(), 这同样是用户必须提供的.

处理分配器的大部分难点与其在容器内部使用的实现细节有关. sequence_container_interface 通过调用同一接口中用户提供的成员来补齐序列容器接口缺失的部分, 它无法帮助处理容器的实现.
