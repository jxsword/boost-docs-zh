Boost.Function 与函数指针的比较

与函数指针相比, Boost.Function 有若干优点, 即:

  • Boost.Function 允许任意兼容的函数对象作为目标 (而不要求精确的函数签名).

  • Boost.Function 可与参数绑定及其他函数对象构造库一起使用.

  • 调用空函数对象时, Boost.Function 具有可预测的行为.

当然, 函数指针相对 Boost.Function 也有若干优点:

  • 函数指针更小 (一个指针的大小, 而不是四个或更多)

  • 函数指针更快 (Boost.Function 可能需要两次经由函数指针的调用)

  • 函数指针与 C 库向后兼容.

  • 更易读的错误消息.

函数对象封装器的大小

函数对象封装器的大小相当于一个包含成员函数指针和两个数据指针的结构体. 实际大小可能因底层平台而有显著差异; 在使用 GCC 的 32 位 Mac OS X 上为 16 字节, 而在使用 Visual C++ 的 Windows 上为 32 字节. 此外, 如果函数对象目标无法放入 boost::function 对象中的小对象缓冲区, 它可能会被分配在堆上.

拷贝效率

拷贝函数对象封装器可能需要为函数对象目标的副本分配内存. 如果这种克隆的代价过高, 可以用更快的自定义分配器替换默认分配器, 或者选择让函数对象封装器只以引用方式存储函数对象目标 (使用 ref). 小型函数对象可以存储在 boost::function 对象自身内部, 从而提高拷贝效率.

调用效率

在使用能正确内联的编译器时, 调用一次函数对象需要一次经由函数指针的调用. 如果调用的是自由函数指针, 则还需要对该函数指针额外进行一次调用 (除非编译器具有非常强大的过程间分析能力).

应对虚函数 "膨胀"

使用虚函数往往会在许多编译器上造成 "代码膨胀". 当类包含虚函数时, 必须生成一个额外的函数来对对象的类型进行分类. 根据我们的经验, 当使用大量 boost::function 对象时, 这些辅助函数会显著增大可执行文件的体积.

在 Boost.Function 中, 采用了一种替代但等效的方法: 使用自由函数代替虚函数. Boost.Function 对象本质上是持有两个指针来完成一次有效的目标调用: 一个指向其所含函数对象的 void 指针, 以及一个指向 "调用器 (invoker)" 的 void 指针 -- 给定函数指针, 该调用器可以调用函数对象. 这个调用器函数执行 Boost.Function 所提供的参数与返回值转换. 第三个指针指向一个称为 "管理器 (manager)" 的自由函数, 它负责函数对象的克隆与销毁. 这一方案是类型安全的, 因为真正处理函数对象的函数 -- 调用器和管理器 -- 是以函数对象的类型实例化的, 因此它们可以安全地把传入的 void 指针 (函数对象指针) 转换为适当的类型.
