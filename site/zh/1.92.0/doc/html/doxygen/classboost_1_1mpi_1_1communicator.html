说明

类 communicator 抽象了 MPI 中一组相互通信的进程. 属于某个通信器的所有进程都可以确定该通信器的大小, 自己在该通信器中的秩, 并可与通信器中的任何其他进程通信.

communicator 公有成员函数

  1. communicator();

    为 MPI_COMM_WORLD 构建新的 Boost.MPI 通信器.

    构造一个附着到 MPI_COMM_WORLD 的 Boost.MPI 通信器. 这等价于以 (MPI_COMM_WORLD, comm_attach) 构造.

  2. communicator(const MPI_Comm & comm, comm_create_kind kind);

    基于 MPI 通信器 comm 构建新的 Boost.MPI 通信器.

    comm 可以是任何有效的 MPI 通信器. 如果 comm 是 MPI_COMM_NULL, 则会创建一个空通信器 (不能用于通信), 且 kind 参数被忽略. 否则, kind 参数决定 Boost.MPI 通信器与 comm: 的关联方式

    • 如果 kind 是 comm_duplicate, 则复制 (duplicate) comm 以创建新的通信器. 当 Boost.MPI 通信器 (及其所有副本) 被销毁时, 该新通信器将被释放. 仅当 comm 是有效的 MPI 内部通信器 (intracommunicator), 或底层 MPI 实现支持 MPI 2.0 (支持互联通信器的复制) 时才允许此选项.

    • 如果 kind 是 comm_take_ownership, 则取得 comm 的所有权. 当所有 Boost.MPI 通信器离开作用域时, 它将被自动释放. 当 comm 是 MPI_COMM_WORLD 时不得使用此选项.

    • 如果 kind 是 comm_attach, 则此 Boost.MPI 通信器将引用现有的 MPI 通信器 comm, 但当 Boost.MPI 通信器离开作用域时不会释放 comm. 仅当通信器由用户或 MPI 库管理时 (例如 MPI_COMM_WORLD) 才应使用此选项.

  3. communicator(const communicator & comm, const boost::mpi::group & subgroup);

    基于另一个 MPI 通信器的子群组构建新的 Boost.MPI 通信器.

    此例程将构造一个新的通信器, 其中包含通信器 comm 中列于群组 subgroup 内的所有进程. 等价于 MPI_Comm_create.

    参数:

    comm

    一个 MPI 通信器.

    subgroup

    MPI 通信器 comm 的一个子群组, 我们将为其构造一个新的通信器.

  7. template<typename T> void send(int dest, int tag, const T & value) const;
    向另一个进程发送数据.

    此例程执行一次可能阻塞的发送, 以标签 tag 发送到秩为 dest 的进程. 目标进程可以通过匹配的 recv 调用来接收它.

    给定的 value 必须适合通过 MPI 传输. 满足这些要求的类型有以下几类:

    • 可映射到 MPI 数据类型的类型: 如果 is_mpi_datatype<T> 可转换为 mpl::true_, 则 value 将使用 MPI 数据类型 get_mpi_datatype<T>() 传输. 所有具有 MPI 对应物的原始 C++ 数据类型, 例如 int, float, char, double 等, 都有到 MPI 数据类型的内建映射. 可以通过为你的类型特化 is_mpi_datatype, 将固定结构的 Serializable 类型转换为 MPI 数据类型.

    • Serializable 类型: 任何提供 Boost.Serialization 库所要求的 serialize() 功能的类型都可以被传输和接收.

    • 打包档案与骨架: 已打包到 mpi::packed_oarchive 中的数据, 以及已存入 mpi::packed_skeleton_oarchive 的数据骨架都可以传输, 但接收时将分别作为 mpi::packed_iarchive 和 mpi::packed_skeleton_iarchive 接收, 以便目标进程提取值 (或骨架).

    • 内容 (Content): 与先前传输的骨架相关联的内容可以通过 send 传输并由 recv 接收. 接收进程只能将内容接收到用匹配骨架构造的值的内容中.

    对于可映射到 MPI 数据类型的类型 (包括类型的内容), 调用此例程将产生一次 MPI_Send 调用. 对于可变长度的数据 (例如序列化类型和打包档案), 将通过 MPI_Send 发送两条消息: 一条包含数据的长度, 另一条包含数据本身.

    MPI 数据类型的 Std::vectors 被视为可变大小, 即其元素数量未知且必须传输 (尽管会跳过序列化过程). 如果发送方和接收方都知道向量大小, 则可以使用通信方法的数组特化版本.

    注意, 可变长度数据的传输模式是一个可能变化的实现细节.

    参数:

    dest

    数据将发送到的远程进程的秩.

    tag

    与此消息关联的标签. 标签可以是 0 与实现定义的上限之间的任何整数. 此上限可通过 environment::max_tag() 访问.

    value

    将传输给接收方的值. 此值的类型 T 必须满足前述传输要求.

  12. template<typename T> status recv(int source, int tag, T & value) const;
    从远程进程接收数据.

    此例程阻塞, 直到它从进程 source 收到具有给定 tag 的消息. 类型为 T 的 value 必须适合通过 MPI 传输, 包括可序列化类型, 可映射到 MPI 数据类型的类型 (包括大多数内建 C++ 类型), 打包的 MPI 档案, 骨架以及与骨架相关联的内容; 完整描述参见 send 的文档.

    参数:

    source

    将发送数据的进程. 它可以是通信器内的进程秩, 也可以是常量 any_source, 后者表示可以从任何进程接收消息.

    tag

    匹配源进程发送的特定种类消息的标签. 它可以是 send 允许的任何标签值. 或者, 该实参可以是常量 any_tag, 表示此接收匹配任何标签的消息.

    value

    成功接收后将包含消息的值. 此值的类型必须与发送方传输的值类型相匹配, 除非发送方传输的是打包档案或骨架: 在这些情况下, 发送方传输 packed_oarchive 或 packed_skeleton_oarchive, 而目标方分别接收 packed_iarchive 或 packed_skeleton_iarchive.

    返回:

    关于所接收消息的信息.

  19. template<typename T> request isend(int dest, int tag, const T & value) const;
    以非阻塞方式向远程进程发送消息.

    isend 方法在功能上与 send 方法完全相同, 并以相同方式传输数据, 区别在于 isend 在等待数据传输完成时不会阻塞. 相反, 它会立即返回一个 request 对象, 允许查询通信状态或等待其完成.

    参数:

    dest

    tag

    value

    将传输给接收方的值. 此值的类型 T 必须满足前述传输要求. 如果在传输之前修改了该值, 则修改可能传输也可能不传输.

    返回:

    描述此次通信的 request 对象.

    匹配源进程发送的特定种类消息的标签. 它可以是 send 允许的任何标签值. 或者, 该实参可以是常量 any_tag, 表示此接收匹配任何标签的消息.

    values

    成功接收后将包含消息中的值. 这些元素的类型必须与发送方传输的元素类型相匹配.

    n

    可存入 values 数组的值的数量. 它不得小于发送方传输的元素数量.

    返回:

    描述此次通信的 request 对象.

  28. status probe(int source = any_source, int tag = any_tag) const;
    等待消息可被接收.

    此操作等待与 (source, tag) 匹配的消息可接收. 然后返回关于该消息的信息. 其功能等价于 MPI_Probe. 要以非阻塞方式检查是否有消息可用, 请使用 iprobe.

    参数:

    source

    确定此秩是否有可用消息. 如果为 any_source, 则返回的消息可以来自任何源.

    tag

    确定给定标签是否有可用消息. 如果为 any_tag, 则返回的消息可以具有任何标签.

    返回:

    返回与给定条件匹配的第一条消息的信息.

    		 
  29. optional< status > iprobe(int source = any_source, int tag = any_tag) const;
    确定是否有消息可被接收.

    此操作确定是否有与 (source, tag) 匹配的消息可接收. 如果有, 则返回关于该消息的信息; 否则立即返回一个空的 optional. 其功能等价于 MPI_Iprobe. 要等待消息可用, 请使用 wait.

    参数:

    source

    确定此秩是否有可用消息. 如果为 any_source, 则返回的消息可以来自任何源.

    tag

    确定给定标签是否有可用消息. 如果为 any_tag, 则返回的消息可以具有任何标签.

    返回:

    如果有匹配的消息可用, 则返回关于该消息的信息. 否则返回空的 boost::optional.

  33. communicator split(int color, int key) const;

    将通信器拆分为多个互不相交的通信器, 每个通信器基于特定的颜色. 这是一个集合操作, 返回一个新的通信器, 它是 this 的子群组.

    参数:

    key

  40. void abort(int errcode) const;

    中止此通信器群组中的所有任务.

    尽最大努力中止此通信器群组中的所有任务. 取决于底层 MPI 实现, 这可能中止整个程序 (并可能向环境返回 errcode), 也可能只中止部分进程而允许其余进程继续. 请查阅你的 MPI 实现的文档. 这等价于调用 MPI_Abort

    参数:
