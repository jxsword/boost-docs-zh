说明

类型要求 T. T 必须是 SGIAssignable (SGI STL 定义的 Assignable 与 CopyConstructible 的组合). 此外, T 必须是 DefaultConstructible (当在调用 circular_buffer 的某些方法, 例如 insert(iterator pos, const value_type& item = value_type()) 时, 将其作为默认参数提供). 并且必须是 EqualityComparable 和/或 LessThanComparable (若该 circular_buffer 将与另一个容器比较).

类型要求 Alloc. Alloc 必须满足 STL 施加的分配器要求.

默认 Alloc. std::allocator<T>

circular_buffer 的详细文档请访问: http://www.boost.org/libs/circular_buffer/doc/circular_buffer.html

  21. array_range array_one();
    获取内部缓冲区的第一段连续数组.

    将存储的数据以数组形式传入旧式 C API 时, 本方法与 array_two() 结合使用会很有用. 假设有一个容量为 10 的 circular_buffer, 其中包含 7 个字符 'a', 'b', ..., 'g', 即 buff[0] == 'a', buff[1] == 'b', ... 和 buff[6] == 'g':

    circular_buffer<char> buff(10);

    内部表示通常不是线性的, 内部缓冲区的状态可能如下:

    |e|f|g| | | |a|b|c|d|
    end ___^
    begin _______^

    其中 |a|b|c|d| 表示 "array one", |e|f|g| 表示 "array two", 而 | | | | 是空闲空间.
    现在考虑一个将数据写入文件的典型 C 风格函数:

    int write(int file_desc, char* buff, int num_bytes);

    将 circular_buffer 的内容写入文件有两种方式. 一是依赖 array_one() 和 array_two() 方法并调用 write 函数两次:

    array_range ar = buff.array_one();
    write(file_desc, ar.first, ar.second);
    ar = buff.array_two();
    write(file_desc, ar.first, ar.second);

    二是依赖 linearize() 方法:

    write(file_desc, buff.linearize(), buff.size());

    由于 array_one() 和 array_two() 方法的复杂度为常数, 因此在调用 write 方法 "便宜" 时第一种方式更合适. 另一方面, 当调用 write 方法比调用复杂度为线性的 linearize() 方法更 "昂贵" 时, 第二种方式更合适.

    异常安全性. 不抛出异常.

    迭代器失效. 不会使任何迭代器失效.

    复杂度. 常数 (相对于 circular_buffer 的大小).

    警告

    一般而言, 调用任何会修改 circular_buffer 内部状态的方法都可能使内部缓冲区去线性化, 并使 array_one() 和 array_two() 返回的数组范围 (及其 const 版本) 失效.

    注释

    若内部缓冲区是线性的, 例如 |a|b|c|d|e|f|g| | | |, 则 "array one" 由 |a|b|c|d|e|f|g| 表示, 而 "array two" 不存在 (array_two() 方法返回大小为 0 的数组).

    参见: array_two(), linearize()

    返回:

    内部缓冲区第一段连续数组的数组范围. 若 circular_buffer 为空, 则返回数组的大小为 0.

    抛出:

    		 无.

  25. pointer linearize();
    将内部缓冲区线性化为一段连续数组.

    将存储的数据以数组形式传入旧式 C API 时, 本方法会很有用.

    异常安全性. 基本保证; 若 抛出 一节中的操作均不抛出异常, 则不抛出任何异常.

    迭代器失效. 使指向 circular_buffer 的所有迭代器失效 (等于 end() 的迭代器除外); 若在调用本方法之前后置条件 (效果) 已满足, 则不会使任何迭代器失效.

    复杂度. 线性 (相对于 circular_buffer 的大小); 若后置条件 (效果) 已满足, 则为常数.

    警告

    一般而言, 调用任何会修改 circular_buffer 内部状态的方法都可能使内部缓冲区去线性化, 并使返回的指针失效.

    参见: array_one() 和 array_two() 是将数据传入旧式 C API 的另一种方式; is_linearized(), rotate(const_iterator)

    后置条件:

    &(*this)[0] < &(*this)[1] < ... < &(*this)[size() - 1]

    返回:

  70. void rinsert(iterator pos, size_type n, param_value_type item);
    在指定位置之前插入 n 个 item 的副本.

    异常安全性. 基本保证; 若 抛出 一节中的操作均不抛出异常, 则不抛出任何异常.

    迭代器失效. 使指向插入点之前元素 (朝向开头, 不包括 pos) 的迭代器失效. 还会使指向被覆盖元素的迭代器失效.

    复杂度. 线性 (相对于 min[capacity(), std::distance(begin(), pos) + n]).

    示例. 考虑一个容量为 6、大小为 4 的 circular_buffer. 其内部缓冲区可能如下所示.

    |1|2|3|4| | |
    p ___^

    在位置 p 之前插入 5 个元素后:

    rinsert(p, (size_t)5, 0);

    实际上只插入了 4 个元素, 且元素 3 和 4 被覆盖. 这是因为 rinsert 操作会保留容量. 插入后内部缓冲区如下:

    |1|2|0|0|0|0|

    pos

    指定 item 插入位置的迭代器.

    n

    要插入的 item 的数量.

    item

    要插入其副本的元素.

    要求:

    pos 是指向 circular_buffer 或其末尾的有效迭代器.

    后置条件:

    将有 min[n, (end() - pos) + reserve()] 个元素被插入到位置 pos 之前.
    将有 min[end() - pos, max[0, n - reserve()]] 个元素在 circular_buffer 的末尾被覆盖.

    		 T::T(const T&) 抛出的任何异常. T::operator = (const T&) 抛出的任何异常. move_if_noexcept(T&) 的异常.
