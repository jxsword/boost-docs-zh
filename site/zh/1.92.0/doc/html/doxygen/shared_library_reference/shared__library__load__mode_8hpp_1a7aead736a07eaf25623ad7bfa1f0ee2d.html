类型 type

boost::dll::load_mode::type

概要

// In header: <boost/dll/shared_library_load_mode.hpp>


enum type { default_mode, dont_resolve_dll_references, 
            load_ignore_code_authz_level, load_with_altered_search_path, 
            rtld_lazy, rtld_now, rtld_global, rtld_local, rtld_deepbind, 
            append_decorations, search_system_folders };

说明

库加载模式.

每个系统家族都提供自己的模式. 特定平台不支持的标志将被静默忽略.

平台特定选项的详细说明参见: Windows 特定选项, POSIX 特定选项.

default_mode

默认打开模式. 默认启用的标志见下方 默认: 注释.

dont_resolve_dll_references

平台: Windows

默认: 禁用

使用该值且可执行模块是 DLL 时, 系统不为进程与线程的初始化和终止调用 DllMain. 同时, 系统也不加载指定模块引用的其他可执行模块.

注意 请勿使用该值; 它仅为向后兼容而提供. 若只打算访问 DLL 中的数据或资源, 请使用 LOAD_LIBRARY_AS_DATAFILE_EXCLUSIVE 或 LOAD_LIBRARY_AS_IMAGE_RESOURCE, 或两者并用.

load_ignore_code_authz_level

平台: Windows

默认: 禁用

使用该值时, 系统不为该 DLL 检查 AppLocker 规则, 也不应用软件限制策略.

load_with_altered_search_path

平台: Windows

默认: 禁用

使用该值且 lpFileName 指定绝对路径时, 系统使用备用文件搜索策略.

该值不能与任何 LOAD_LIBRARY_SEARCH 标志组合.

rtld_lazy

平台: POSIX

默认: 启用

重定位应在实现定义的时间执行, 范围从 dlopen() 调用之时到首次引用给定符号之时.

在支持动态符号绑定的实现上, 指定 RTLD_LAZY 应能提升性能, 因为进程可能不会引用给定对象中的所有函数. 而且, 对支持正常进程执行时动态符号解析的系统, 该行为模拟进程执行的正常处理方式.

rtld_now

平台: POSIX

默认: 禁用

对象首次加载时执行所有必要的重定位. 若对从不引用的函数执行重定位, 这可能浪费一些处理. 对于需要在对象一加载就得知执行期间引用的所有符号均可用这一点的插件, 该行为可能有用.

rtld_global

平台: POSIX

默认: 禁用

对象的符号应可供任何其他对象的重定位处理使用. 此外, 使用 dlopen(0, mode) 与相应的 dlsym() 进行符号查找, 可以搜索以该模式加载的对象.

rtld_local

平台: POSIX

默认: 启用

对象的符号不提供给任何其他对象的重定位处理使用.

这是 Windows 的默认行为, 无法更改.

rtld_deepbind

平台: POSIX (要求 glibc >= 2.3.4)

默认: 禁用

对象将优先使用自己的符号, 而不是已加载库中包含的同名全局符号. POSIX.1-2001 未规定该标志.

append_decorations

平台: Windows, POSIX

默认: 禁用

在尝试加载之前, 为共享库文件名追加平台特定的扩展名与前缀. 若加载尝试失败, 则按精确指定的名称尝试加载.

示例: 

// Opens `./my_plugins/plugin1.dll` on Windows, `./my_plugins/libplugin1.so` on Linux, `./my_plugins/libplugin1.dylib` on MacOS.
// If that fails, loads `./my_plugins/plugin1`
boost::dll::shared_library lib("./my_plugins/plugin1", load_mode::append_decorations);

search_system_folders

平台: Windows, POSIX

默认: 禁用

若库路径不含父路径, 则允许从系统文件夹加载.
