类 shared_library

boost::dll::shared_library — 该类可用于加载动态链接库 (DLL) 或共享库 (也称为动态共享对象 DSO), 并获取其导出符号 (函数与变量).

说明

shared_library 实例共享对实际加载的 DLL/DSO 的引用计数, 因此让多个 shared_library 实例引用同一个 DLL/DSO 是安全且节省内存的, 即使这些实例是通过不同路径 (相对 + 绝对) 加载且指向同一对象.

在 Linux/POSIX 上需与 "dl" 库链接. 在 Linux/POSIX 上还建议使用 "-fvisibility=hidden" 标志.

shared_library 公有静态函数

  1. static boost::dll::fs::path suffix();

    返回共享模块的后缀: 在调用 load() 或构造函数/加载时.

    返回:

    共享模块的后缀: ".dll" (Windows), ".so" (Unix/Linux/BSD), ".dylib" (MacOS/IOS)

    		 
  2. static boost::dll::fs::path decorate(const boost::dll::fs::path & sl);

    返回共享模块名的修饰路径, 即已加上所需前缀/后缀.

    建议: 使用 load 与 load_mode::append_decorations, 而不是通过 decorate() 构造修饰路径并据此加载.

    例如, 对于 "path/to/boost" 这样的路径, 它返回:

    • 在 POSIX 平台上为 path/to/libboost.so

    • 在 OSX 上为 path/to/libboost.dylib

    • 在 Windows 上为 path/to/boost.dll

    该方法同时处理相对路径与绝对路径.

    • Windows 注意事项: decorate() 不会在修饰路径前加 "lib". 出于 MinGW 兼容目的, 请将 load 与 load_mode::append_decorations 配合使用.

    • POSIX 注意事项: 若初始模块名已带 lib 前缀, 则只把 suffix() 追加到路径

    参数:

    sl

    要修饰的模块名与路径 - 例如: /usr/lib/boost

    返回:

    修饰后的不可移植路径, 它可能不存在于文件系统中, 或因平台特性而可能出错.
