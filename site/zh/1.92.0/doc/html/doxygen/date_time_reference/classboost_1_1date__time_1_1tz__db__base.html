类模板 tz_db_base

boost::date_time::tz_db_base — 从 csv 数据文件创建 time_zone 数据库.

概要

// In header: <boost/date_time/tz_db_base.hpp>

template<typename time_zone_type, typename rule_type> 
class tz_db_base {
public:
  // types
  typedef char                                                           char_type;             
  typedef time_zone_type::base_type                                      time_zone_base_type;   
  typedef time_zone_type::time_duration_type                             time_duration_type;    
  typedef time_zone_names_base< char_type >                              time_zone_names;       
  typedef boost::date_time::dst_adjustment_offsets< time_duration_type > dst_adjustment_offsets;
  typedef std::basic_string< char_type >                                 string_type;           

  // public member functions
  tz_db_base();
  void load_from_stream(std::istream &);
  void load_from_file(const std::string &);
  bool add_record(const string_type &, 
                  boost::shared_ptr< time_zone_base_type >);
  boost::shared_ptr< time_zone_base_type > 
  time_zone_from_region(const string_type &) const;
  std::vector< std::string > region_list() const;

  // private member functions
  rule_type * parse_rules(const string_type &, const string_type &) const;
  week_num get_week_num(int) const;
  void split_rule_spec(int &, int &, int &, string_type) const;
  bool parse_string(string_type &);
};

说明

包含 tz_db_base 所用 zone_specs 的 csv 文件预期由库使用者定制. 定制此文件 (或创建自己的文件) 时, 文件必须遵循特定格式.

第一行预期包含列标题, 因此 tz_db_base 不会处理它.

每条记录 (行) 必须有十一个字段. 其中一些字段可以为空. 每个字段 (即使是空字段) 必须用双引号括起来. 例如:

"America/Phoenix" <- string enclosed in quotes
""                <- empty field

一些字段表示一段时间的长度. 这些字段的格式必须是:

"{+|-}hh:mm[:ss]" <- length-of-time format

其中正负号是必需的, 秒是可选的.

由于某些时区不使用夏令时, zone_spec 中的每个字段并非都必须有值. 所有 zone_spec 必须至少有 ID 和 GMT offset. 使用夏令时的时区必须填满除以下字段外的所有字段: STD ABBR、STD NAME、DST NAME. 请注意, 对使用夏令时的时区而言 DST ABBR 是必需的 (更多细节见字段说明) .

******* 字段及其描述/细节 *********

ID: 包含 zone_spec 的标识字符串. 只要是唯一的, 任何字符串都可以. 不允许两个 ID 相同.

STD ABBR: STD NAME: DST ABBR: DST NAME: 这四个是所描述时区使用的全部名称和缩写. 这些字段可以填任何字符串, 但需谨慎填写. 这些字段保存的字符串将用于许多 local_time 类的输出. 例如:

time_zone nyc = tz_db.time_zone_from_region("America/New_York");
local_time ny_time(date(2004, Aug, 30), IS_DST, nyc);
cout << ny_time.to_long_string() << endl;
// 2004-Aug-30 00:00:00 Eastern Daylight Time
cout << ny_time.to_short_string() << endl;
// 2004-Aug-30 00:00:00 EDT

注意: 具体的格式/函数名可能有所不同 —— 更多细节见 local_time 文档.

GMT offset: 在进行任何夏令时调整之前, 为得到本地时间而加到 UTC 上的小时数. 例如: America/New_York 偏移 -5 小时, Africa/Cairo 偏移 +2 小时. 格式必须遵循上述时长格式.

DST adjustment: 夏令时生效时加到 gmt_offset 上的时间量. 格式必须遵循上述时长格式.

DST Start Date rule: 这是一个特殊格式的字符串, 描述转换发生的年内日期. 它自身包含三个字段, 以分号分隔. 第一个字段表示月内的 "第 n 个" 星期几. 可能的值为: 1 (第一个), 2 (第二个), 3 (第三个), 4 (第四个), 5 (第五个) 和 -1 (最后一个). 第二个字段表示星期几, 范围 0-6 (Sun=0). 第三个字段表示月份, 范围 1-12 (Jan=1).

示例: "-1;5;9"="Last Friday of September" (九月的最后一个星期五) , "2;1;3"="Second Monday of March" (三月的第二个星期一)

Start time: 起始时间是开始转换当日, 午夜过后发生转换的小时数. 简单地说, 就是进行转换的日内时刻 (24 小时制). 格式必须遵循上述时长格式, 但必须始终为正.

DST End date rule: 见 DST Start date rule. 区别在于这是夏令时结束的日期 (转换到 STD).

End time: 与 Start time 相同.

  1. tz_db_base();
    构造空数据库.

    处理 csv 数据文件, 可能抛出异常.

    可能抛出 data_not_accessible 或 bad_field_count 异常

  4. bool add_record(const string_type & region, 
                boost::shared_ptr< time_zone_base_type > tz);
    如果记录成功添加到映射则返回 true

    接受形如 "America/Phoenix" 的地区名, 以及该地区的 time_zone 对象. id 字符串必须是数据库中尚不存在的唯一名称.

  5. boost::shared_ptr< time_zone_base_type >

  6. std::vector< std::string > region_list() const;
    返回保存数据库中时区地区的字符串向量.
