说明

类模板 hashtable 是一种侵入式哈希表容器, 用于构造侵入式 unordered_set 和 unordered_multiset 容器. 仅当 VoidOrKeyEqual 对象和 Hasher 不抛出异常时, 不抛出保证才成立.

hashtable 是一种半侵入式容器: 要存储在容器中的每个对象都必须包含合适的钩子, 但容器还需要额外的辅助内存才能工作: hashtable 需要在构造函数中传入一个指向 bucket_type 类型数组的指针. 该桶数组必须具有与容器至少相同的生存期. 这使得 hashtable 的使用比纯侵入式容器更复杂. bucket_type 可默认构造、可复制且可赋值

模板参数 T 是容器要管理的类型. 用户可以指定附加选项; 若未提供选项, 则使用默认选项.

容器支持以下选项: base_hook<>/member_hook<>/value_traits<>、constant_time_size<>、size_type<>、hash<> 和 equal<> bucket_traits<>、power_2_buckets<>、cache_begin<> 以及 incremental<>.

hashtable 只提供前向迭代器, 但提供 4 种迭代器类型: 用于遍历整个容器的 iterator 和 const_iterator, 以及用于遍历存储在单个桶中的值的 local_iterator 和 const_local_iterator. 局部迭代器更快也更小.

不建议使用非常数时间大小的 hashtable, 因为若干关键函数 (如 "empty()") 会变成非常数时间函数. 非常数时间大小的 hashtable 主要用于支持 auto-unlink 钩子.

hashtable 不执行自动重哈希, 也不提供与负载因子相关的函数. 可以显式请求重哈希, 用户必须提供自那一刻起使用的新桶数组.

由于不执行自动重哈希, 插入或擦除元素时迭代器从不失效. 只有重哈希时迭代器才失效.

  1. explicit hashtable(const bucket_traits & b_traits, 
                   const hasher & hash_func = hasher(), 
                   const key_equal & equal_func = key_equal(), 
                   const value_traits & v_traits = value_traits());

    要求: buckets 不得正被任何其他资源使用.

    效果: 构造一个空的 unordered_set, 存储对桶数组的引用以及 key_hasher 与 equal_func 函子的副本.

    复杂度: 常数.

    抛出: 若 value_traits::node_traits::node 构造函数抛出异常 (预定义的 Boost.Intrusive 钩子不会发生这种情况), 或 hash_func 或 equal_func 的复制构造或调用抛出异常.

    注释: 桶数组只能在 *this 被释放之后释放.

  2. template<typename Iterator> 
  hashtable(bool unique, Iterator b, Iterator e, 
            const bucket_traits & b_traits,

            const key_equal & equal_func = key_equal(), 
            const value_traits & v_traits = value_traits());

    要求: buckets 不得正被任何其他资源使用, 且解引用迭代器必须产生 value_type 类型的左值.

    注释: 桶数组只能在 *this 被释放之后释放.

  void clone_from(const hashtable & src, Cloner cloner, Disposer disposer);

    要求: Disposer::operator()(pointer) 不应抛出异常. Cloner 应产生与原节点比较相等且哈希相同的节点.

    抛出: 若 cloner 或 hasher 抛出异常, 或哈希或相等性谓词的复制抛出异常. 基本保证.

  23. template<typename KeyType, typename KeyHasher, typename KeyEqual> 
  std::pair< iterator, bool > 
  insert_unique_check(const KeyType & key, KeyHasher hash_func, 
                      KeyEqual equal_func, insert_commit_data & commit_data);

    要求: "hash_func" 必须是诱导与所存 hasher 相同哈希值的哈希函数. 区别在于 "hash_func" 对给定的键而非 value_type 计算哈希.

    "equal_func" 必须是诱导与 key_equal 相同相等性的相等性函数. 区别在于 "equal_func" 把任意键与容器中的值进行比较.

    效果: 使用用户提供的键 (而非值本身) 检查一个值是否可以插入 unordered_set.

    返回: 若存在等价值, 返回包含指向已存在值的迭代器和 false 的对组. 若该值可以插入, 返回的对组布尔成员为 true, 并填充 "commit_data", 该数据应与 "insert_commit" 函数一起使用.

    复杂度: 平均情况 O(1), 最坏情况 O(this->size()).

    抛出: 若 hash_func 或 equal_func 抛出异常. 强保证.

    注释: 构造 value_type 代价高昂时可用此函数提升性能: 若存在等价值, 已构造的对象必须丢弃. 很多时候, 节点中用于施加哈希或相等性的部分比 value_type 的构造代价低得多, 此函数提供了用该部分检查插入是否会成功的机会.

    若检查成功, 用户可以构造 value_type 并使用 "insert_commit" 以常数时间插入对象.

    仅在 unordered_set 没有更多对象被插入或擦除的情况下, "commit_data" 对随后的 "insert_commit" 保持有效.

    成功的重哈希之后 insert_commit_data 保持有效.

  25. iterator insert_unique_commit(reference value,

    要求: new_bucket_traits 可以持有指向新桶数组的指针, 或指向同一旧桶数组但长度不同. new_size 是 new_buckets 所指数组的长度. 若 new_bucket_traits.bucket_begin() == this->bucket_pointer(), new_bucket_traits.bucket_count() 可以大于或小于 this->bucket_count(). 'new_bucket_traits' 的复制构造函数不应抛出异常.

  65. bool incremental_rehash(const bucket_traits & new_bucket_traits) noexcept;

    效果: 若 new_bucket_traits.bucket_count() 不是 this->bucket_count()/2 或 this->bucket_count()*2, 或 this->split_bucket() != new_bucket_traits.bucket_count(), 则返回 false 且不做任何事.

    否则, 把 new_bucket_traits 复制赋值给内部 bucket_traits, 并把所有对象从旧桶转移到新桶.

    复杂度: 与 size() 成线性.

    抛出: 无

    注释: 此方法仅在启用 incremental<true> 选项时可用.
