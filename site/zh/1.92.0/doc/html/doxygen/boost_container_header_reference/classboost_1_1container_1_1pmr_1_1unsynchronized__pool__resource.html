类 unsynchronized_pool_resource

boost::container::pmr::unsynchronized_pool_resource

说明

unsynchronized_pool_resource 是一种通用内存资源, 具有以下性质:

  • 每个资源拥有已分配的内存, 并在销毁时释放, 即使某些已分配块尚未调用 deallocate.

  • 池资源由一组池组成, 服务于不同块大小的请求. 每个单独的池管理一组块集 (chunk), 每个块集又被划分为大小一致的块, 通过调用 do_allocate 返回. 对 do_allocate(size, alignment) 的每次调用被分派到服务于能容纳至少 size 字节的最小块的池.

  • 当特定池耗尽时, 从该池分配块会导致从上游分配器 (构造时提供) 分配一个额外的内存块集 (chunk), 从而补充该池. 每次相继的补充中, 获得的块集大小按几何级数增长. [ Note: 通过按块集分配内存, 池化策略增加了连续分配在内存中彼此靠近的机会. - end note ]

  • 超过任何池最大块大小的分配请求直接由上游分配器满足.

  • pool_options 结构体可传递给池资源构造函数, 以调整最大块大小和最大块集大小.

unsynchronized_pool_resource 类不能被多个线程同时访问, 因此在单线程应用中完全避免了同步开销.

unsynchronized_pool_resource 公有成员函数

  1. unsynchronized_pool_resource(const pool_options & opts, 
                             memory_resource * upstream) noexcept;

    要求: upstream 是有效内存资源的地址.

    效果: 构造一个池资源对象, 只要池资源无法从其自身内部数据结构满足内存请求, 它就会从上游获取内存. 所得对象将持有 upstream 的副本, 但不拥有 upstream 所指向的资源. [ Note: 意图是在大多数情况下, 对 upstream->allocate() 的调用远少于对 this->allocate() 的调用. - end note 池化机制的行为根据 opts 实参的值进行调整.

    抛出: 除非 upstream->allocate() 抛出异常, 否则不抛出. 此构造函数是否以及在何种条件下调用 upstream->allocate() 是未指定的.

  2. unsynchronized_pool_resource() noexcept;

    效果: 与 unsynchronized_pool_resource(pool_options(), get_default_resource()) 相同.

  3. explicit unsynchronized_pool_resource(memory_resource * upstream) noexcept;

    效果: 与 unsynchronized_pool_resource(pool_options(), upstream) 相同.

  4. explicit unsynchronized_pool_resource(const pool_options & opts) noexcept;

    效果: 与 unsynchronized_pool_resource(opts, get_default_resource()) 相同.

  5. unsynchronized_pool_resource(const unsynchronized_pool_resource &) = delete;
  6. unsynchronized_pool_resource 
operator=(const unsynchronized_pool_resource &) = delete;
  7. ~unsynchronized_pool_resource();

    效果: 调用 this->release().

  8. void release();

    效果: 必要时调用 upstream_resource()->deallocate() 以释放所有已分配的内存. [ Note: 即使某些已分配块尚未调用 deallocate, 内存也会释放回 upstream_resource(). - end note ]

  9. memory_resource * upstream_resource() const;

    返回: 提供给本对象构造函数的 upstream 实参的值.

  10. pool_options options() const;

    返回: 控制此资源池化行为的选项. 返回结构体中的值可能不同于提供给池资源构造函数的值, 因为零值会被替换为实现定义的默认值, 且大小可能被舍入到未指定的粒度.

  11. std::size_t pool_count() const;

    返回: 池资源中将使用的池数量.

    注释: 非标准扩展.

  12. std::size_t pool_index(std::size_t bytes) const;

    返回: 将用于服务 bytes 分配的池的索引. 返回 pool_count(), 若 bytes 大于 options().largest_required_pool_block (不会使用任何池来服务此请求).

    注释: 非标准扩展.

  13. std::size_t pool_next_blocks_per_chunk(std::size_t pool_idx) const;

    要求: pool_idx < pool_index()

    返回: 将在由 pool_idx 指定的池的下一个块集中分配的块数.

    注释: 非标准扩展.

  14. std::size_t pool_block(std::size_t pool_idx) const;

    要求: pool_idx < pool_index()

    返回: 指定 pool_idx 池所管理的块的字节数.

    注释: 非标准扩展.

  15. std::size_t pool_cached_blocks(std::size_t pool_idx) const;

    要求: pool_idx < pool_index()

    返回: 指定 pool_idx 池已缓存且无需调用 upstream_allocator 即可服务的块数.

    注释: 非标准扩展.

unsynchronized_pool_resource 受保护成员函数

  1. virtual void * do_allocate(std::size_t bytes, std::size_t alignment);

    返回: 指向大小至少为 bytes 的已分配存储的指针. 所分配内存的大小和对齐应满足从 memory_resource 派生的类的要求.

    效果: 若为大小 bytes 的块选择的池无法从其自身内部数据结构满足内存请求, 它将调用 upstream_resource()->allocate() 以获取更多内存. 若 bytes 大于最大池能处理的量, 则将使用 upstream_resource()->allocate() 分配内存.

    抛出: 除非 upstream_resource()->allocate() 抛出异常, 否则不抛出.

  2. virtual void do_deallocate(void * p, std::size_t bytes, std::size_t alignment);

    效果: 把 p 处的内存返还给池. 此操作是否以及在何种情况下会导致对 upstream_resource()->deallocate() 的调用是未指定的.

    抛出: 无.

  3. virtual bool do_is_equal(const memory_resource & other) const noexcept;

    返回: this == dynamic_cast<const unsynchronized_pool_resource*>(&other).
