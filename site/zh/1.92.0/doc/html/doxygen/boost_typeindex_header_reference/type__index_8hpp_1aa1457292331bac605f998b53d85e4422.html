宏 BOOST_TYPE_INDEX_CTTI_USER_DEFINED_PARSING

BOOST_TYPE_INDEX_CTTI_USER_DEFINED_PARSING

概要

// In header: <boost/type_index.hpp>

BOOST_TYPE_INDEX_CTTI_USER_DEFINED_PARSING

说明

这是一个在 RTTI 关闭时生成正确 pretty_names() 的辅助宏.

BOOST_TYPE_INDEX_CTTI_USER_DEFINED_PARSING 宏可定义为 '(begin_skip, end_skip, runtime_skip, runtime_skip_until)' 并附带参数, 以便为 TypeIndex 库默认无法识别的编译器添加支持.

示例:

设想如下情况:

boost::typeindex::ctti_type_index::type_id<int>().pretty_name()

返回以下字符串:

"static const char *boost::detail::ctti<int>::n() [T = int]"

以及

boost::typeindex::ctti_type_index::type_id<short>().pretty_name()

返回以下内容:

"static const char *boost::detail::ctti<short>::n() [T = short]"

可以看到, 前 39 个字符是 "static const char *boost::detail::ctti<", 它们不依赖于类型 T. 前 39 个字符之后是人类可读的类型名称, 它在字符串末尾重复出现. 字符串总是以 ']' 结尾, 该字符占用 1 个字符.

现在, 如果把 BOOST_TYPE_INDEX_CTTI_USER_DEFINED_PARSING 定义为 (39, 1, false, ""), 我们将得到

"int>::n() [T = int"

对于 boost::typeindex::ctti_type_index::type_id<int>().pretty_name(), 而

"short>::n() [T = short"

对于 boost::typeindex::ctti_type_index::type_id<short>().pretty_name().

现在还需要额外处理类型最后一次出现之前的字符. 做法是告诉宏: 我们需要切除 "T = " 之前的所有内容, 包括 "T = " 本身:

(39, 1, true, "T = ")

对于 GCC 或 Clang 命令行, 编译所有源文件时需要添加以下命令行:

-DBOOST_TYPE_INDEX_CTTI_USER_DEFINED_PARSING='(39, 1, true, "T = ")'

更多信息请参见 RTTI emulation limitations.
