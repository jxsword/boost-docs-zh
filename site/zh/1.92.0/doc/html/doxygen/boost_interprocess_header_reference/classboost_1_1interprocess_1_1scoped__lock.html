类模板 scoped_lock

boost::interprocess::scoped_lock

概要

// In header: <boost/interprocess/sync/scoped_lock.hpp>

template<typename Mutex> 
class scoped_lock {
public:
  // types
  typedef Mutex mutex_type;

  // public member functions
  scoped_lock() noexcept;
  explicit scoped_lock(mutex_type &);
  scoped_lock(mutex_type &, defer_lock_type);
  scoped_lock(mutex_type &, accept_ownership_type);
  scoped_lock(mutex_type &, try_to_lock_type);
  template<typename TimePoint> scoped_lock(mutex_type &, const TimePoint &);
  scoped_lock(scoped_lock &&) noexcept;
  template<typename T> 
    explicit scoped_lock(upgradable_lock< T > &&, unspecified = 0);
  template<typename T> 
    scoped_lock(upgradable_lock< T > &&, try_to_lock_type, unspecified = 0);
  template<typename T, typename TimePoint> 
    scoped_lock(upgradable_lock< T > &&, const TimePoint &, unspecified = 0);
  template<typename T> 
    scoped_lock(sharable_lock< T > &&, try_to_lock_type, unspecified = 0);
  ~scoped_lock();
  scoped_lock & operator=(scoped_lock &&);
  void lock();
  bool try_lock();
  template<typename TimePoint> bool timed_lock(const TimePoint &);
  template<typename TimePoint> bool try_lock_until(const TimePoint &);
  template<typename Duration> bool try_lock_for(const Duration &);
  void unlock();
  bool owns() const noexcept;
  operator unspecified_bool_type() const noexcept;
  mutex_type * mutex() const noexcept;
  mutex_type * release() noexcept;
  void swap(scoped_lock< mutex_type > &) noexcept;
};

说明

scoped_lock 旨在为 Mutex 执行加锁、解锁、尝试加锁和限时加锁 (递归与否) 等任务. Mutex 无需提供所有这些功能. 若 scoped_lock<Mutex> 的使用者未使用 Mutex 不提供的功能, 不会有任何影响. 互斥量所有权可通过移动语义的语法进行转移, 所有权转移在构造和赋值时均被允许. scoped_lock 不支持复制语义: 尝试复制构造或复制赋值会导致编译期错误. 互斥量所有权也可以通过构造函数从 upgradable_lock 和 sharable_lock 移入. 在这种用法下, scoped_lock 与 write_lock 具有相同的功能.

scoped_lock 公有成员函数

  1. scoped_lock() noexcept;

    效果: 默认构造一个 scoped_lock. 后置条件: owns() == false 且 mutex() == 0.

  2. explicit scoped_lock(mutex_type & m);

    效果: m.lock(). 后置条件: owns() == true 且 mutex() == &m. 注释: 该构造函数将取得互斥量的所有权. 若另一线程已拥有该互斥量, 此线程将阻塞直到互斥量被释放. 此构造函数是否处理递归加锁取决于互斥量.

  3. scoped_lock(mutex_type & m, defer_lock_type);

    后置条件: owns() == false 且 mutex() == &m. 注释: 该构造函数不会取得互斥量的所有权. 对被引用的互斥量不产生任何影响.

  4. scoped_lock(mutex_type & m, accept_ownership_type);

    后置条件: owns() == true 且 mutex() == &m. 注释: 该构造函数假定互斥量已被锁定. 对被引用的互斥量不产生任何影响.

  5. scoped_lock(mutex_type & m, try_to_lock_type);

    效果: m.try_lock(). 后置条件: mutex() == &m, owns() == 构造函数内执行的 m.try_lock() 的返回值. 注释: 若无需等待即可取得互斥量的所有权, 该构造函数将取得所有权. 此构造函数是否处理递归加锁取决于互斥量. 若 mutex_type 不支持 try_lock, 实例化此构造函数将在编译期失败, 但除此之外没有影响.

  6. template<typename TimePoint> 
  scoped_lock(mutex_type & m, const TimePoint & abs_time);

    效果: m.timed_lock(abs_time). 后置条件: mutex() == &m, owns() == 构造函数内执行的 m.timed_lock(abs_time) 的返回值. 注释: 若能在到达 abs_time 之前取得互斥量的所有权, 该构造函数将取得所有权. 此构造函数是否处理递归加锁取决于互斥量. 若 mutex_type 不支持 try_lock, 实例化此构造函数将在编译期失败, 但除此之外没有影响.

  7. scoped_lock(scoped_lock && scop) noexcept;

    后置条件: mutex() == 构造函数执行前 scop.mutex() 的值, s1.mutex() == 0, owns() == 构造函数执行前 scop.owns() 的值. 注释: 若 scop scoped_lock 拥有该互斥量, 所有权将以无阻塞方式移交给此 scoped_lock; 若 scop scoped_lock 不拥有该互斥量, 此 scoped_lock 也不拥有. 只有移动构造的 scoped_lock 才匹配此签名. 未移动的 scoped_lock 可通过表达式 "boost::move(lock);" 移动. 此构造函数不改变互斥量的状态, 只可能改变其拥有者.

  8. template<typename T> 
  explicit scoped_lock(upgradable_lock< T > && upgr, unspecified = 0);

    效果: 若 upgr.owns() 为真, 则对被引用的互斥量调用 unlock_upgradable_and_lock(), 并调用 upgr.release(). 后置条件: mutex() == 构造前 upgr.mutex() 的值, upgr.mutex() == 0, owns() == 构造前 upgr.owns() 的值, 构造后 upgr.owns() == false. 注释: 若 upgr 已锁定, 此构造函数将在解锁 upgr 的同时锁定此 scoped_lock. 若 upgr 未锁定, 此 scoped_lock 也将处于未锁定状态. 只有移动构造的 upgradable_lock 才匹配此签名. 未移动的 upgradable_lock 可通过表达式 "boost::move(lock);" 移动. 若其他线程持有此互斥量的 sharable_lock (sharable_lock 可与 upgradable_lock 共享所有权), 此构造函数可能阻塞.

  9. template<typename T> 
  scoped_lock(upgradable_lock< T > && upgr, try_to_lock_type, unspecified = 0);

    效果: 若 upgr.owns() 为真, 则对被引用的互斥量调用 try_unlock_upgradable_and_lock(): a) 若 try_unlock_upgradable_and_lock() 返回 true, 则 mutex() 获得 upgr.release() 的值, owns() 被置为 true. b) 若 try_unlock_upgradable_and_lock() 返回 false, 则 upgr 不受影响, 此 scoped_lock 构造与默认构造具有相同的效果. c) 否则 upgr.owns() 为 false, mutex() 获得 upgr.release() 的值, owns() 被置为 false. 注释: 此构造不会阻塞. 它会立即尝试从 upgr 取得互斥量所有权, 同时把锁类型从 "读锁" 改为 "写锁". 若一开始就没有持有 "读锁", 互斥量只是把类型改为未锁定的 "写锁". 若持有 "读锁", 则只有能以非阻塞方式完成时才发生互斥量转移.

  10. template<typename T, typename TimePoint> 
  scoped_lock(upgradable_lock< T > && upgr, const TimePoint & abs_time, 
              unspecified = 0);

    效果: 若 upgr.owns() 为真, 则对被引用的互斥量调用 timed_unlock_upgradable_and_lock(abs_time): a) 若 timed_unlock_upgradable_and_lock(abs_time) 返回 true, 则 mutex() 获得 upgr.release() 的值, owns() 被置为 true. b) 若 timed_unlock_upgradable_and_lock(abs_time) 返回 false, 则 upgr 不受影响, 此 scoped_lock 构造与默认构造具有相同的效果. c) 否则 upgr.owns() 为 false, mutex() 获得 upgr.release() 的值, owns() 被置为 false. 注释: 此构造不会阻塞. 它会立即尝试从 upgr 取得互斥量所有权, 同时把锁类型从 "读锁" 改为 "写锁". 若一开始就没有持有 "读锁", 互斥量只是把类型改为未锁定的 "写锁". 若持有 "读锁", 则只有能以非阻塞方式完成时才发生互斥量转移.

  11. template<typename T> 
  scoped_lock(sharable_lock< T > && shar, try_to_lock_type, unspecified = 0);

    效果: 若 shar.owns() 为真, 则对被引用的互斥量调用 try_unlock_sharable_and_lock(). a) 若 try_unlock_sharable_and_lock() 返回 true, 则 mutex() 获得 shar.release() 的值, owns() 被置为 true. b) 若 try_unlock_sharable_and_lock() 返回 false, 则 shar 不受影响, 此 scoped_lock 构造与默认构造具有相同的效果. c) 否则 shar.owns() 为 false, mutex() 获得 shar.release() 的值, owns() 被置为 false. 注释: 此构造不会阻塞. 它会立即尝试从 shar 取得互斥量所有权, 同时把锁类型从 "读锁" 改为 "写锁". 若一开始就没有持有 "读锁", 互斥量只是把类型改为未锁定的 "写锁". 若持有 "读锁", 则只有能以非阻塞方式完成时才发生互斥量转移.

  12. ~scoped_lock();

    效果: 若 (owns()) 则 mp_mutex->unlock(). 注释: 析构行为确保互斥量锁不被泄漏. *<zwj></zwj>/

  13. scoped_lock & operator=(scoped_lock && scop);

    效果: 若调用前 owns() 为真, 则对 mutex() 调用 unlock(). *this 获得 scop 的状态, scop 被置为默认构造状态. 注释: 对于递归互斥量, 赋值前 this 与 scop 可能同时拥有同一互斥量. 此时赋值后 this 仍拥有该互斥量 (而 scop 不拥有), 但互斥量的锁定计数会减一.

  14. void lock();

    效果: 若 mutex() == 0 或已锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 lock(). 后置条件: owns() == true. 注释: scoped_lock 从不拥有互斥量的状态变为拥有互斥量的状态, 必要时阻塞.

  15. bool try_lock();

    效果: 若 mutex() == 0 或已锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 try_lock(). 后置条件: owns() == mutex()->try_lock() 的返回值. 注释: scoped_lock 从不拥有互斥量的状态变为拥有互斥量的状态, 但前提是不需要阻塞. 若 mutex_type 不支持 try_lock(), 实例化此函数将在编译期失败, 但除此之外没有影响. *<zwj></zwj>/

  16. template<typename TimePoint> bool timed_lock(const TimePoint & abs_time);

    效果: 若 mutex() == 0 或已锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 timed_lock(abs_time). 后置条件: owns() == mutex()-> timed_lock(abs_time) 的返回值. 注释: scoped_lock 从不拥有互斥量的状态变为拥有互斥量的状态, 但前提是能在指定时间内取得所有权. 若 mutex_type 不支持 timed_lock(), 实例化此函数将在编译期失败, 但除此之外没有影响. *<zwj></zwj>/

  17. template<typename TimePoint> bool try_lock_until(const TimePoint & abs_time);

    效果: 若 mutex() == 0 或已锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 try_lock_until(abs_time). 后置条件: owns() == mutex()-> timed_lock(abs_time) 的返回值. 注释: scoped_lock 从不拥有互斥量的状态变为拥有互斥量的状态, 但前提是能在指定时间内取得所有权. 若 mutex_type 不支持 timed_lock(), 实例化此函数将在编译期失败, 但除此之外没有影响. *<zwj></zwj>/

  18. template<typename Duration> bool try_lock_for(const Duration & dur);

    效果: 若 mutex() == 0 或已锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 try_lock_until(abs_time). 后置条件: owns() == mutex()-> timed_lock(abs_time) 的返回值. 注释: scoped_lock 从不拥有互斥量的状态变为拥有互斥量的状态, 但前提是能在指定时间内取得所有权. 若 mutex_type 不支持 timed_lock(), 实例化此函数将在编译期失败, 但除此之外没有影响. *<zwj></zwj>/

  19. void unlock();

    效果: 若 mutex() == 0 或未锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 unlock(). 后置条件: owns() == false. 注释: scoped_lock 从拥有互斥量的状态变为不拥有互斥量的状态. *<zwj></zwj>/

  20. bool owns() const noexcept;

    效果: 若此 scoped_lock 已获得被引用的互斥量, 则返回 true.

  21. operator unspecified_bool_type() const noexcept;

    转换为 bool. 返回 owns().

  22. mutex_type * mutex() const noexcept;

    效果: 返回指向被引用互斥量的指针, 若没有可引用的互斥量则返回 0.

  23. mutex_type * release() noexcept;

    效果: 返回指向被引用互斥量的指针, 若没有可引用的互斥量则返回 0. 后置条件: mutex() == 0 且 owns() == false.

  24. void swap(scoped_lock< mutex_type > & other) noexcept;

    效果: 与被移动的锁交换状态. 抛出: 无.
