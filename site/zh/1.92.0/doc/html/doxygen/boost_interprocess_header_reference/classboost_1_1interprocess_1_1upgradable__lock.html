类模板 upgradable_lock

boost::interprocess::upgradable_lock

概要

// In header: <boost/interprocess/sync/upgradable_lock.hpp>

template<typename UpgradableMutex> 
class upgradable_lock {
public:
  // types
  typedef UpgradableMutex mutex_type;

  // public member functions
  upgradable_lock() noexcept;
  explicit upgradable_lock(mutex_type &);
  upgradable_lock(mutex_type &, defer_lock_type);
  upgradable_lock(mutex_type &, accept_ownership_type);
  upgradable_lock(mutex_type &, try_to_lock_type);
  template<typename TimePoint> 
    upgradable_lock(mutex_type &, const TimePoint &);
  upgradable_lock(upgradable_lock< mutex_type > &&) noexcept;
  template<typename T> upgradable_lock(scoped_lock< T > &&, unspecified = 0);
  template<typename T> 
    upgradable_lock(sharable_lock< T > &&, try_to_lock_type, unspecified = 0);
  ~upgradable_lock();
  upgradable_lock & operator=(upgradable_lock &&);
  void lock();
  bool try_lock();
  template<typename TimePoint> bool timed_lock(const TimePoint &);
  void unlock();
  bool owns() const noexcept;
  operator unspecified_bool_type() const noexcept;
  mutex_type * mutex() const noexcept;
  mutex_type * release() noexcept;
  void swap(upgradable_lock< mutex_type > &) noexcept;
};

说明

upgradable_lock 旨在为 Mutex 执行读加锁、解锁、尝试读加锁和限时读加锁 (递归与否) 等任务. 此外 upgradable_lock 可以用 transfer_lock 语法把所有权转移给 scoped_lock. Mutex 无需提供所有这些功能. 若 upgradable_lock<Mutex> 的使用者未使用 Mutex 不提供的功能, 不会有任何影响. 互斥量所有权可在多个 read_lock 之间共享, 也可与单个 upgradable_lock 共享. upgradable_lock 不支持复制语义. 不过 upgradable_lock 支持通过 transfer_lock 语法从 upgradable_lock 或 scoped_lock 转移所有权.

upgradable_lock 公有成员函数

  1. upgradable_lock() noexcept;

    效果: 默认构造一个 upgradable_lock. 后置条件: owns() == false 且 mutex() == 0.

  2. explicit upgradable_lock(mutex_type & m);
  3. upgradable_lock(mutex_type & m, defer_lock_type);

    后置条件: owns() == false 且 mutex() == &m. 注释: 该构造函数不会取得互斥量的所有权. 对被引用的互斥量不产生任何影响.

  4. upgradable_lock(mutex_type & m, accept_ownership_type);

    后置条件: owns() == true 且 mutex() == &m. 注释: 该构造函数假定互斥量已被可升级锁定. 对被引用的互斥量不产生任何影响.

  5. upgradable_lock(mutex_type & m, try_to_lock_type);

    效果: m.try_lock_upgradable(). 后置条件: mutex() == &m, owns() == 构造函数内执行的 m.try_lock_upgradable() 的返回值. 注释: 若无需等待即可取得互斥量的可升级所有权, 该构造函数将取得所有权. 此构造函数是否处理递归加锁取决于互斥量. 若 mutex_type 不支持 try_lock_upgradable, 实例化此构造函数将在编译期失败, 但除此之外没有影响.

  6. template<typename TimePoint> 
  upgradable_lock(mutex_type & m, const TimePoint & abs_time);

    效果: m.timed_lock_upgradable(abs_time) 后置条件: mutex() == &m, owns() == 构造函数内执行的 m.timed_lock_upgradable() 的返回值. 注释: 若能在指定时间内取得互斥量的可升级所有权, 该构造函数将取得所有权. 此构造函数是否处理递归加锁取决于互斥量. 若 mutex_type 不支持 timed_lock_upgradable, 实例化此构造函数将在编译期失败, 但除此之外没有影响.

  7. upgradable_lock(upgradable_lock< mutex_type > && upgr) noexcept;

    效果: 对底层互斥量没有影响. 后置条件: mutex() == 构造前 upgr.mutex() 的值, upgr.mutex() == 0, owns() == 构造前 upgr.owns() 的值, upgr.owns() == false. 注释: 若 upgr 已锁定, 此构造函数将在解锁 upgr 的同时锁定此 upgradable_lock. 若 upgr 未锁定, 此 upgradable_lock 也将处于未锁定状态. 只有移动构造的 upgradable_lock 才匹配此签名. 未移动的 upgradable_lock 可通过表达式 "boost::move(lock);" 移动. 此构造函数不改变互斥量的状态, 只可能改变其拥有者.

  8. template<typename T> 
  upgradable_lock(scoped_lock< T > && scop, unspecified = 0);

    效果: 若 scop.owns() 为真, 则 m_.unlock_and_lock_upgradable(). 后置条件: mutex() == 构造前 scop.mutex() 的值, scop.mutex() == 0, owns() == 构造前 scop.owns() 的值, 构造后 scop.owns() == false. 注释: 若 scop 已锁定, 此构造函数将把独占所有权转移为此 upgradable_lock 的可升级所有权. 只有移动构造的 sharable_lock 才匹配此签名. 未移动的 sharable_lock 可通过表达式 "boost::move(lock);" 移动.

  9. template<typename T> 
  upgradable_lock(sharable_lock< T > && shar, try_to_lock_type, 
                  unspecified = 0);

    效果: 若 shar.owns() 为真, 则对被引用的互斥量调用 try_unlock_sharable_and_lock_upgradable(). a) 若 try_unlock_sharable_and_lock_upgradable() 返回 true, 则 mutex() 获得 shar.release() 的值, owns() 被置为 true. b) 若 try_unlock_sharable_and_lock_upgradable() 返回 false, 则 shar 不受影响, 此 upgradable_lock 构造与默认构造具有相同的效果. c) 否则 shar.owns() 为 false, mutex() 获得 shar.release() 的值, owns() 被置为 false. 注释: 此构造不会阻塞. 它会立即尝试从 shar 取得互斥量所有权, 同时把锁类型从 "读锁" 改为 "可升级锁". 若一开始就没有持有 "读锁", 互斥量只是把类型改为未锁定的 "可升级锁". 若持有 "读锁", 则只有能以非阻塞方式完成时才发生互斥量转移.

  10. ~upgradable_lock();

    效果: 若 (owns()) 则 m_->unlock_upgradable(). 注释: 析构行为确保互斥量锁不被泄漏.

  11. upgradable_lock & operator=(upgradable_lock && upgr);

    效果: 若 owns() 为真, 则对 mutex() 调用 unlock_upgradable(). *this 获得 upgr 的状态, upgr 被置为默认构造状态. 注释: 对于递归互斥量, 赋值前 this 与 upgr 可能同时拥有该互斥量. 此时赋值后 this 仍拥有该互斥量 (而 upgr 不拥有), 但互斥量的可升级锁定计数会减一.

  12. void lock();

    效果: 若 mutex() == 0 或已锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 lock_upgradable(). 后置条件: owns() == true. 注释: sharable_lock 从不拥有互斥量的状态变为拥有互斥量的状态, 必要时阻塞.

  13. bool try_lock();

    效果: 若 mutex() == 0 或已锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 try_lock_upgradable(). 后置条件: owns() == mutex()->try_lock_upgradable() 的返回值. 注释: upgradable_lock 从不拥有互斥量的状态变为拥有互斥量的状态, 但前提是不需要阻塞. 若 mutex_type 不支持 try_lock_upgradable(), 实例化此函数将在编译期失败, 但除此之外没有影响.

  14. template<typename TimePoint> bool timed_lock(const TimePoint & abs_time);

    效果: 若 mutex() == 0 或已锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 timed_lock_upgradable(abs_time). 后置条件: owns() == mutex()->timed_lock_upgradable(abs_time) 的返回值. 注释: upgradable_lock 从不拥有互斥量的状态变为拥有互斥量的状态, 但前提是能在指定时间内取得所有权. 若 mutex_type 不支持 timed_lock_upgradable(abs_time), 实例化此函数将在编译期失败, 但除此之外没有影响.

  15. void unlock();

    效果: 若 mutex() == 0 或未锁定, 则抛出 lock_exception() 异常. 对被引用的互斥量调用 unlock_upgradable(). 后置条件: owns() == false. 注释: upgradable_lock 从拥有互斥量的状态变为不拥有互斥量的状态.

  16. bool owns() const noexcept;

    效果: 若此 scoped_lock 已获得被引用的互斥量, 则返回 true.

  17. operator unspecified_bool_type() const noexcept;

    转换为 bool. 返回 owns().

  18. mutex_type * mutex() const noexcept;

    效果: 返回指向被引用互斥量的指针, 若没有可引用的互斥量则返回 0.

  19. mutex_type * release() noexcept;

    效果: 返回指向被引用互斥量的指针, 若没有可引用的互斥量则返回 0. 后置条件: mutex() == 0 且 owns() == false.

  20. void swap(upgradable_lock< mutex_type > & other) noexcept;

    效果: 与被移动的锁交换状态. 抛出: 无.
