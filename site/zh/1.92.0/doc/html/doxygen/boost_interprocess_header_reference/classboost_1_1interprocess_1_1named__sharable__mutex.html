类 named_sharable_mutex

boost::interprocess::named_sharable_mutex

概要

// In header: <boost/interprocess/sync/named_sharable_mutex.hpp>


class named_sharable_mutex {
public:

  // public member functions
  named_sharable_mutex(create_only_t, const char *, 
                       const permissions & = permissions());
  named_sharable_mutex(open_or_create_t, const char *, 
                       const permissions & = permissions());
  named_sharable_mutex(open_only_t, const char *);
  named_sharable_mutex(create_only_t, const wchar_t *, 
                       const permissions & = permissions());
  named_sharable_mutex(open_or_create_t, const wchar_t *, 
                       const permissions & = permissions());
  named_sharable_mutex(open_only_t, const wchar_t *);
  ~named_sharable_mutex();
  void lock();
  bool try_lock();
  template<typename TimePoint> bool timed_lock(const TimePoint &);
  template<typename TimePoint> bool try_lock_until(const TimePoint &);
  template<typename Duration> bool try_lock_for(const Duration &);
  void unlock();
  void lock_sharable();
  void lock_shared();
  bool try_lock_sharable();
  bool try_lock_shared();
  template<typename TimePoint> bool timed_lock_sharable(const TimePoint &);
  template<typename TimePoint> bool try_lock_shared_until(const TimePoint &);
  template<typename Duration> bool try_lock_shared_for(const Duration &);
  void unlock_sharable();
  void unlock_shared();

  // public static functions
  static bool remove(const char *);
  static bool remove(const wchar_t *);
};

说明

具有全局名称的共享互斥量, 因此可以从不同进程找到它. 此互斥量不能放置在共享内存中, 每个进程应拥有自己的命名共享互斥量.

named_sharable_mutex 公有成员函数

  1. named_sharable_mutex(create_only_t, const char * name, 
                     const permissions & perm = permissions());

    以名称创建一个全局共享互斥量. 若无法创建该共享互斥量, 抛出 interprocess_exception 

  2. named_sharable_mutex(open_or_create_t, const char * name, 
                     const permissions & perm = permissions());

    打开或创建具有名称的全局共享互斥量. 若创建该共享互斥量, 此调用等价于 named_sharable_mutex(create_only_t, ...); 若该共享互斥量已创建, 此调用等价于 named_sharable_mutex(open_only_t, ... ).

  3. named_sharable_mutex(open_only_t, const char * name);

    若该共享互斥量先前已创建, 则以名称打开全局共享互斥量. 若先前未创建, 此函数抛出 interprocess_exception.

  4. named_sharable_mutex(create_only_t, const wchar_t * name, 
                     const permissions & perm = permissions());

    以名称创建一个全局共享互斥量. 若无法创建该共享互斥量, 抛出 interprocess_exception

    注释: 该函数仅在提供原生 wchar_t API 的操作系统上可用 (例如 Windows).

  5. named_sharable_mutex(open_or_create_t, const wchar_t * name, 
                     const permissions & perm = permissions());

    打开或创建具有名称的全局共享互斥量. 若创建该共享互斥量, 此调用等价于 named_sharable_mutex(create_only_t, ...); 若该共享互斥量已创建, 此调用等价于 named_sharable_mutex(open_only_t, ... ).

    注释: 该函数仅在提供原生 wchar_t API 的操作系统上可用 (例如 Windows).

  6. named_sharable_mutex(open_only_t, const wchar_t * name);

    若该共享互斥量先前已创建, 则以名称打开全局共享互斥量. 若先前未创建, 此函数抛出 interprocess_exception.

    注释: 该函数仅在提供原生 wchar_t API 的操作系统上可用 (例如 Windows).

  7. ~named_sharable_mutex();

    销毁 *this 并指示调用进程已结束对该资源的使用. 析构函数将释放系统为该进程使用此资源而分配的所有系统资源. 之后仍可通过调用 open 构造函数重载再次打开该资源. 要从系统中擦除该资源, 请使用 remove().

  8. void lock();

    要求: 调用线程不拥有该互斥量.

    效果: 调用线程尝试获得该互斥量的独占所有权; 若另一线程已独占或共享地拥有该互斥量, 则等待直到能够获得所有权. 抛出: 出错时抛出 interprocess_exception.

    注释: 若已拥有所有权的线程调用此函数, 程序可能死锁. 若实现能检测到死锁, 则可能抛出异常.

  9. bool try_lock();

    要求: 调用线程不拥有该互斥量.

    效果: 调用线程尝试不等待地获取互斥量的独占所有权. 若没有其他线程独占或共享地拥有该互斥量, 则成功. 返回: 若能立即获得独占所有权则返回 true; 若必须等待则返回 false. 抛出: 出错时抛出 interprocess_exception.

    注释: 若已拥有所有权的线程调用此函数, 程序可能死锁. 若实现能检测到死锁, 则可能抛出异常.

  10. template<typename TimePoint> bool timed_lock(const TimePoint & abs_time);

    要求: 调用线程不拥有该互斥量.

    效果: 调用线程尝试获取互斥量的独占所有权, 必要时等待, 直到没有其他线程独占或共享地拥有该互斥量或到达 abs_time. 返回: 若获得独占所有权则返回 true, 否则返回 false. 抛出: 出错时抛出 interprocess_exception.

    注释: 若已拥有所有权的线程调用此函数, 程序可能死锁. 若实现能检测到死锁, 则可能抛出异常.

  11. template<typename TimePoint> bool try_lock_until(const TimePoint & abs_time);

    与 timed_lock 相同, 但此函数仿照标准库接口设计.

  12. template<typename Duration> bool try_lock_for(const Duration & dur);

    与 timed_lock 相同, 但此函数仿照标准库接口设计.

  13. void unlock();

    前置条件: 线程必须拥有该互斥量的独占所有权. 效果: 调用线程释放该互斥量的独占所有权. 抛出: 出错时抛出从 interprocess_exception 派生的异常.

  14. void lock_sharable();

    要求: 调用线程不拥有该互斥量.

    效果: 调用线程尝试获得该互斥量的共享所有权; 若另一线程独占拥有该互斥量, 则等待直到能够获得所有权. 抛出: 出错时抛出 interprocess_exception.

    注释: 若已拥有所有权的线程调用此函数, 程序可能死锁. 若实现能检测到死锁, 则可能抛出异常

  15. void lock_shared();

    与 lock_sharable 相同, 但采用与 std 兼容的接口

    效果: 调用线程尝试不等待地获取互斥量的共享所有权. 若没有其他线程独占拥有该互斥量, 则成功. 返回: 若能立即获得共享所有权则返回 true; 若必须等待则返回 false. 抛出: 出错时抛出 interprocess_exception.

  17. bool try_lock_shared();

    与 try_lock_sharable 相同, 但采用与 std 兼容的接口
