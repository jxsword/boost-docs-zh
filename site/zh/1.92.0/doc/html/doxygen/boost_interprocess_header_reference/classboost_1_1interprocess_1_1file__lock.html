类 file_lock

boost::interprocess::file_lock

概要

// In header: <boost/interprocess/sync/file_lock.hpp>


class file_lock {
public:

  // public member functions
  file_lock() noexcept;
  file_lock(const char *);
  file_lock(const wchar_t *);
  file_lock(file_lock &&) noexcept;
  file_lock & operator=(file_lock &&) noexcept;
  ~file_lock();
  void swap(file_lock &) noexcept;
  void lock();
  bool try_lock();
  template<typename TimePoint> bool timed_lock(const TimePoint &);
  template<typename TimePoint> bool try_lock_until(const TimePoint &);
  template<typename Duration> bool try_lock_for(const Duration &);
  void unlock();
  void lock_sharable();
  void lock_shared();
  bool try_lock_sharable();
  bool try_lock_shared();
  template<typename TimePoint> bool timed_lock_sharable(const TimePoint &);

  template<typename Duration> bool try_lock_shared_for(const Duration &);
  void unlock_sharable();
  void unlock_shared();
};

说明

文件锁是一种使用文件、类似于互斥量的互斥工具. 文件锁具有共享与独占两种加锁能力, 可与 scoped_lock 和 sharable_lock 类一起使用. 文件锁无法保证同一进程内线程之间的同步, 因此文件锁只应用于同步不同进程的线程.

file_lock 公有成员函数

  1. file_lock() noexcept;

    构造一个空文件映射. 不抛出异常

  2. file_lock(const char * name);

    打开文件锁. 若文件不存在或没有可用的操作系统资源, 抛出 interprocess_exception.

  3. file_lock(const wchar_t * name);

    打开文件锁. 若文件不存在或没有可用的操作系统资源, 抛出 interprocess_exception.

    注释: 该函数仅在提供原生 wchar_t API 的操作系统上可用 (例如 Windows).

  4. file_lock(file_lock && moved) noexcept;

    将 "moved" 的文件映射对象所有权移交给 *this. 调用后, "moved" 不再表示任何文件映射对象. 不抛出异常

  5. file_lock & operator=(file_lock && moved) noexcept;

    将 "moved" 的文件映射所有权移交给 *this. 调用后, "moved" 不再表示任何文件映射. 不抛出异常

  6. ~file_lock();
    关闭文件锁. 不抛出异常.
  7. void swap(file_lock & other) noexcept;

    交换两个 file_lock. 不抛出异常.

  8. void lock();

    要求: 调用线程不拥有该互斥量.

    效果: 调用线程尝试获得该互斥量的独占所有权; 若另一线程已独占或共享地拥有该互斥量, 则等待直到能够获得所有权. 抛出: 出错时抛出 interprocess_exception.

    注释: 若已拥有所有权的线程调用此函数, 程序可能死锁. 若实现能检测到死锁, 则可能抛出异常.

  9. bool try_lock();

    要求: 调用线程不拥有该互斥量.

    效果: 调用线程尝试不等待地获取互斥量的独占所有权. 若没有其他线程独占或共享地拥有该互斥量, 则成功. 返回: 若能立即获得独占所有权则返回 true; 若必须等待则返回 false. 抛出: 出错时抛出 interprocess_exception.

    注释: 若已拥有所有权的线程调用此函数, 程序可能死锁. 若实现能检测到死锁, 则可能抛出异常.

  10. template<typename TimePoint> bool timed_lock(const TimePoint & abs_time);

    要求: 调用线程不拥有该互斥量.

    效果: 调用线程尝试获取互斥量的独占所有权, 必要时等待, 直到没有其他线程独占或共享地拥有该互斥量或到达 abs_time. 返回: 若获得独占所有权则返回 true, 否则返回 false. 抛出: 出错时抛出 interprocess_exception.

    注释: 若已拥有所有权的线程调用此函数, 程序可能死锁. 若实现能检测到死锁, 则可能抛出异常.

  11. template<typename TimePoint> bool try_lock_until(const TimePoint & abs_time);

    与 timed_lock 相同, 但此函数仿照标准库接口设计.

  12. template<typename Duration> bool try_lock_for(const Duration & dur);

    与 timed_lock 相同, 但此函数仿照标准库接口设计.

  13. void unlock();

    前置条件: 线程必须拥有该互斥量的独占所有权. 效果: 调用线程释放该互斥量的独占所有权. 抛出: 出错时抛出从 interprocess_exception 派生的异常.

  14. void lock_sharable();

    要求: 调用线程不拥有该互斥量.

    效果: 调用线程尝试获得该互斥量的共享所有权; 若另一线程独占拥有该互斥量, 则等待直到能够获得所有权. 抛出: 出错时抛出 interprocess_exception.

    注释: 若拥有互斥量对象的线程调用此函数, 程序可能死锁. 若实现能检测到死锁, 则可能抛出异常.

  15. void lock_shared();

    与 lock_sharable 相同, 但采用与 std 兼容的接口

  16. bool try_lock_sharable();

    效果: 调用线程尝试不等待地获取互斥量的共享所有权. 若没有其他线程独占拥有该互斥量, 则成功. 返回: 若能立即获得共享所有权则返回 true; 若必须等待则返回 false. 抛出: 出错时抛出 interprocess_exception.

  17. bool try_lock_shared();

    与 try_lock_sharable 相同, 但采用与 std 兼容的接口

  18. template<typename TimePoint> 
  bool timed_lock_sharable(const TimePoint & abs_time);

    效果: 调用线程尝试获取互斥量的共享所有权, 必要时等待, 直到没有其他线程独占拥有该互斥量或到达 abs_time. 返回: 若获得共享所有权则返回 true, 否则返回 false. 抛出: 出错时抛出 interprocess_exception.

  19. template<typename TimePoint> 
  bool try_lock_shared_until(const TimePoint & abs_time);

    与 timed_lock_sharable 相同, 但此函数仿照标准库接口设计.

  20. template<typename Duration> bool try_lock_shared_for(const Duration & dur);

    与 timed_lock_sharable 相同, 但此函数仿照标准库接口设计.

  21. void unlock_sharable();

    前置条件: 线程必须拥有该互斥量的共享所有权. 效果: 调用线程释放该互斥量的共享所有权. 抛出: 出错时抛出从 interprocess_exception 派生的异常.
