boost::interprocess::segment_manager

说明

此对象被放置在内存段的开头, 实现段的 (命名或匿名) 部分分配. 此对象包含两个索引, 维护名称与段中一部分区域之间的关联.

第一个索引包含普通命名对象的映射, 使用模板参数中指定的 char 类型.

第二个索引包含唯一实例的关联. 键是待构造的唯一类型经 type_info.name() 函数返回的 const char *.

segment_manager<CharType, MemoryAlgorithm, IndexType> 公开继承自 segment_manager_base<MemoryAlgorithm>, 并从它继承了多个与匿名对象及原始内存分配相关的公有函数. 有关这些函数请参见 segment_manager_base 参考.

segment_manager 公有成员函数

  1. explicit segment_manager(size_type segment_size);

    段管理器的构造函数. "size" 是正在构造段管理器的内存段的大小. 可能抛出异常

  2. template<typename T> std::pair< T *, size_type > find(char_ptr_holder_t name);

    尝试查找先前的命名/唯一分配. 返回地址和对象计数. 失败时返回对组 (pair) 的第一个成员为 0.

  3. template<typename T> 
  std::pair< T *, size_type > find_no_lock(char_ptr_holder_t name);

    尝试查找先前的命名/唯一分配. 返回地址和对象计数. 失败时返回对组 (pair) 的第一个成员为 0. 此搜索没有互斥量保护! 只应在 atomic_func() 调用内部使用, 在那里内部互斥量保证处于锁定状态.

  4. template<typename T> 
  construct_proxy< T >::type construct(char_ptr_holder_t name);

    返回抛出异常的 "construct" 代理对象

  5. template<typename T> 
  construct_proxy< T >::type find_or_construct(char_ptr_holder_t name);

    返回抛出异常的 "search or construct" 代理对象

  6. template<typename T> 
  construct_proxy< T >::type 
  construct(char_ptr_holder_t name, const std::nothrow_t &);

    返回不抛出异常的 "construct" 代理对象

  7. template<typename T> 
  construct_proxy< T >::type 
  find_or_construct(char_ptr_holder_t name, const std::nothrow_t &);

    返回不抛出异常的 "search or construct" 代理对象

  8. template<typename T> 
  construct_iter_proxy< T >::type construct_it(char_ptr_holder_t name);
    返回抛出异常的 "construct from iterators" 代理对象.
  9. template<typename T> 
  construct_iter_proxy< T >::type find_or_construct_it(char_ptr_holder_t name);

    返回抛出异常的 "search or construct from iterators" 代理对象

  10. template<typename T> 
  construct_iter_proxy< T >::type 
  construct_it(char_ptr_holder_t name, const std::nothrow_t &);

    返回不抛出异常的 "construct from iterators" 代理对象

  11. template<typename T> 
  construct_iter_proxy< T >::type 
  find_or_construct_it(char_ptr_holder_t name, const std::nothrow_t &);

    返回不抛出异常的 "search or construct from iterators" 代理对象

  12. template<typename Func> void atomic_func(Func & f);

    调用对象函数时阻塞递归 interprocess_mutex, 并保证在执行对象函数调用期间任何进程都不会执行新的 named_alloc 或销毁操作

  13. template<typename Func> bool try_atomic_func(Func & f);

    尝试调用函子, 保证在执行对象函数调用期间任何进程都不会执行新的构造、搜索或销毁操作. 若因内部互斥量已被锁定而无法立即执行原子函数, 则返回 false. 若函子抛出异常, 此函数也随之抛出.

  14. template<typename T> bool destroy(char_ptr_holder_t name);

    销毁先前创建的命名/唯一实例. 若对象不存在则返回 false.

  15. template<typename T> void destroy_ptr(const T * p);

    使用地址销毁匿名、唯一或命名对象

  16. void reserve_named_objects(size_type num);

    预分配所需的索引资源, 以优化在托管内存段中创建 "num" 个命名对象的操作. 若内存不足, 可能抛出 boost::interprocess::bad_alloc.

  17. void reserve_unique_objects(size_type num);

    预分配所需的索引资源, 以优化在托管内存段中创建 "num" 个唯一对象的操作. 若内存不足, 可能抛出 boost::interprocess::bad_alloc.

  18. void shrink_to_fit_indexes();

    在命名对象索引和唯一对象索引上调用 shrink_to_fit, 尝试从这些索引中释放未使用的内存.

  19. size_type get_num_named_objects();

    返回段中存储的命名对象数量.

  20. size_type get_num_unique_objects();

    返回段中存储的唯一对象数量.

  21. const_named_iterator named_begin() const;

    返回一个常量迭代器, 指向此段管理器所执行的命名分配信息的开头

  22. const_named_iterator named_end() const;

    返回一个常量迭代器, 指向此段管理器所执行的命名分配信息的结尾

  23. const_unique_iterator unique_begin() const;

    返回一个常量迭代器, 指向此段管理器所执行的唯一分配信息的开头

  24. const_unique_iterator unique_end() const;

    返回一个常量迭代器, 指向此段管理器所执行的唯一分配信息的结尾

  25. template<typename T> allocator< T >::type get_allocator();

    返回类型 T 的默认分配器实例, 该实例从此段管理器分配内存.

  26. template<typename T> deleter< T >::type get_deleter();

    返回类型 T 的默认删除器实例, 该删除器将删除在此段管理器中构造的对象.

segment_manager 公有静态函数

  2. template<typename T> static size_type get_instance_length(const T * ptr);

  3. template<typename T> static instance_type get_instance_type(const T * ptr);

  4. static size_type get_min_size();

    获得段管理器所需的最小大小
