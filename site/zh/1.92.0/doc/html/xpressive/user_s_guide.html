引言

什么是 xpressive?

xpressive 是一个正则表达式模板库. 正则表达式 (regex) 既可以写成在运行期动态解析的字符串 (动态正则), 也可以写成在编译期解析的 表达式模板[30] (静态正则). 动态正则的优点是可以在运行期接受用户输入或从初始化文件读取. 静态正则有几个优点. 由于它们是 C++ 表达式而不是字符串, 因此可以在编译期进行语法检查. 此外, 它们可以自然地引用程序中其他地方的代码和数据, 使你能够在正则匹配过程中回调你的代码. 最后, 由于它们是静态绑定的, 编译器可以为静态正则生成更快的代码.

xpressive 的双重特性独特而强大. 静态 xpressive 有点像 Spirit Parser Framework. 与 Spirit 一样, 你可以用表达式模板和静态正则构建文法. (与 Spirit 不同, xpressive 会进行穷举回溯, 尝试一切可能来找到与你的模式匹配的结果.) 动态 xpressive 有点像 Boost.Regex. 事实上, 任何用过 Boost.Regex 的人都应该对 xpressive 的接口感到熟悉. xpressive 的创新之处在于允许你在同一个程序中混合搭配静态和动态正则, 甚至在同一个表达式中也是如此! 你可以把动态正则嵌入静态正则, 或者反之亦然, 被嵌入的正则将完整参与搜索, 并按需回溯以使匹配成功.

Hello, world!

理论讲得够多了. 我们来看 xpressive 风格的 Hello World:

#include <iostream>
#include <boost/xpressive/xpressive.hpp>

using namespace boost::xpressive;

int main()
{
    std::string hello( "hello world!" );

    sregex rex = sregex::compile( "(\\w+) (\\w+)!" );
    smatch what;

    if( regex_match( hello, what, rex ) )
    {
        std::cout << what[0] << '\n'; // whole match
        std::cout << what[1] << '\n'; // first capture
        std::cout << what[2] << '\n'; // second capture
    }

    return 0;
}

这个程序输出如下:

hello world!
hello
world

关于这段代码, 你首先会注意到的是 xpressive 中的所有类型都位于 boost::xpressive 命名空间中.

注释

本文其余大部分示例都将省略 using namespace boost::xpressive; 指令. 就当它在那里好了.

接着, 你会注意到正则对象的类型是 sregex. 如果你熟悉 Boost.Regex, 这与你所习惯的不同. "s" 中的 "sregex" 代表 "string", 表示这个正则可用于在 std::string 对象中查找模式. 我稍后会详细讨论这一差异及其影响.

注意正则对象是如何初始化的:

sregex rex = sregex::compile( "(\\w+) (\\w+)!" );

要从字符串创建正则表达式对象, 必须调用 basic_regex<>::compile() 这样的工厂方法. 这是 xpressive 与其他面向对象正则表达式库不同的又一个方面. 其他库鼓励你把正则表达式看作一种“增强版字符串”. 在 xpressive 中, 正则表达式不是字符串, 而是用领域特定语言写成的小程序. 字符串只是该语言的一种表示. 另一种表示是表达式模板. 例如, 上面那行代码等价于以下代码:

sregex rex = (s1= +_w) >> ' ' >> (s2= +_w) >> '!';

这描述的是同一个正则表达式, 只是它使用的是静态 xpressive 定义的领域特定嵌入式语言.

如你所见, 静态正则的语法与标准 Perl 语法明显不同. 这是因为我们受限于 C++ 的语法. 最大的差异是使用 >> 表示 "后随". 例如, 在 Perl 中你可以直接把子表达式并排放置:

abc

但在 C++ 中, 必须有一个运算符来分隔子表达式:

a >> b >> c

在 Perl 中, 括号 () 有特殊含义. 它们用于分组, 但副作用是也会创建诸如 $1 和 $2 这样的后向引用. 在 C++ 中, 无法重载括号来赋予它们副作用. 为了获得同样的效果, 我们使用特殊的 s1、s2 等 token. 向某个 token 赋值即可创建一个后向引用 (在 xpressive 中称为子匹配).

你还会注意到, 一到多次重复运算符 + 从后缀位置移到了前缀位置. 这是因为 C++ 没有后缀的 + 运算符. 因此:

"\\w+"

等价于:

+_w

我们将在后文介绍所有其他差异.

安装 xpressive

获取 xpressive

获取 xpressive 有两种方式. 第一种也是最简单的方式是下载最新版本的 Boost. 只需访问 http://sf.net/projects/boost 并点击 “下载” 链接.

第二种方式是直接访问 Boost Subversion 仓库. 只需访问 http://svn.boost.org/trac/boost/ 并按照那里的说明进行匿名 Subversion 访问. Boost Subversion 中的版本是不稳定的.

构建时使用 xpressive

Xpressive 是一个仅头文件模板库, 这意味着使用它无需修改构建脚本, 也无需链接任何单独的库文件. 你只需 #include <boost/xpressive/xpressive.hpp>. 如果只使用静态正则, 可以只包含 xpressive_static.hpp 来改善编译时间. 同样, 如果只打算使用动态正则, 可以包含 xpressive_dynamic.hpp.

如果你还想在静态正则中使用语义动作或自定义断言, 就需要额外包含 regex_actions.hpp.

要求

Xpressive 要求 Boost 1.34.1 或更高版本.

  • tru64cxx 71 及更高版本

basic_regex<>

包含一个已编译的正则表达式. basic_regex<> 是 xpressive 中最重要的类型. 你用 xpressive 所做的一切都从创建一个 basic_regex<> 类型的对象开始.

match_results<> 保存 regex_match() 或 regex_search() 操作的结果. 它表现得像一个 sub_match<> 对象的 vector. sub_match<> 对象包含一个标记子表达式 (在 Perl 中也称为后向引用). 它基本上只是一对迭代器, 表示标记子表达式的开始和结束.

regex_search()

在字符串中搜索与正则匹配的子串. regex_search() 会从字符串开头开始, 在每个位置尝试查找匹配, 直到找到匹配或字符串穷尽为止. 与 regex_match() 一样, 如果你给 regex_search() 传入一个 match_results<>, 它会把找到的所有标记子表达式写入其中.

regex_replace()

给定输入字符串、正则和替换字符串, regex_replace() 会把输入字符串中与正则匹配的部分替换为替换字符串, 从而构建一个新字符串. 替换字符串可以包含对标记子表达式的引用.

regex_iterator<>

一个 STL 兼容迭代器, 便于找出字符串中所有与正则匹配的位置. 解引用一个 regex_iterator<> 会返回一个 match_results<>. 递增一个 regex_iterator<> 会查找下一个匹配.

regex_token_iterator<>

与 regex_iterator<> 类似, 区别在于解引用一个 regex_token_iterator<> 返回一个字符串. 默认情况下, 它返回正则匹配到的整个子串, 但也可以配置为一次返回任意或全部标记子表达式, 甚至返回字符串中不与正则匹配的部分.

regex_compiler<>

basic_regex<> 对象的工厂. 它把字符串“编译”为正则表达式. 你通常不必直接与 regex_compiler<> 打交道, 因为 basic_regex<> 类有一个内部使用 regex_compiler<> 的工厂方法. 但如果你需要做一些特别的事情, 比如创建一个 basic_regex<> 对象并使用不同的 std::locale, 就需要显式使用 regex_compiler<>.

创建正则对象

动态正则

使用 xpressive 时, 你要做的第一件事是创建一个 basic_regex<> 对象. 本节详细介绍在 xpressive 支持的两种方言 (静态和动态) 中构建正则表达式的具体细节.

静态正则

概述

真正使 xpressive 与其他 C/C++ 正则表达式库区别开来的特性, 是能够用 C++ 表达式来编写正则表达式. xpressive 通过运算符重载实现这一点, 使用一种称为 表达式模板 的技术, 在 C++ 中嵌入一门专用于模式匹配的迷你语言. 这些“静态正则”相比基于字符串的正则有许多优势. 具体而言, 静态正则:

  • 在编译期进行语法检查; 它们绝不会在运行期因语法错误而失败.
  • 可以自然地引用其他 C++ 数据和代码, 包括其他正则, 从而可以简单地用正则表达式构建文法, 并绑定在正则的相应部分匹配时执行的用户自定义动作.
  • 静态绑定, 便于内联和优化. 静态正则不需要状态表、虚函数、字节码或无法在编译期解析的函数指针调用.
  • 不限于在字符串中搜索模式. 例如, 你可以声明一个在整数数组中查找模式的静态正则.

由于我们用 C++ 表达式来组合静态正则, 因此受制于合法 C++ 表达式的规则. 遗憾的是, 这意味着“经典”正则表达式语法并不总是能干净地映射到 C++ 中. 相反, 我们映射的是正则的构造, 为其挑选合法的 C++ 新语法.

构造与赋值

把一个静态正则赋值给一个 basic_regex<> 类型的对象即可创建它. 例如, 下面定义了一个可用于在 std::string 类型对象中查找模式的正则:

sregex re = '$' >> +_d >> '.' >> _d >> _d;

赋值的工作方式类似.

字符与字符串字面量

在静态正则中, 字符和字符串字面量匹配其自身. 例如, 在上面的正则中, '$' 和 '.' 分别匹配字符 '$' 和 '.'. 不要被 $ 和 . 在 Perl 中是元字符这一点搞糊涂. 在 xpressive 中, 字面量始终表示其自身.

在静态正则中使用字面量时, 必须注意至少有一个操作数不是字面量. 例如, 下面这些不是有效的正则:

sregex re1 = 'a' >> 'b';         // ERROR!
sregex re2 = +'a';               // ERROR!

二元 >> 运算符的两个操作数都是字面量, 一元 + 运算符的操作数也是字面量, 因此这两条语句将分别调用 C++ 原生的二元右移运算符和一元正号运算符. 这不是我们想要的. 要让运算符重载生效, 至少一个操作数必须是用户自定义类型. 我们可以用 xpressive 的 as_xpr() 辅助函数来给表达式“沾染”正则属性, 强制运算符重载找到正确的运算符. 上面的两个正则应写为:

sregex re1 = as_xpr('a') >> 'b'; // OK
sregex re2 = +as_xpr('a');       // OK

顺序与选择

你可能已经注意到, 静态正则中的子表达式必须用顺序运算符 >> 分隔. 这个运算符可以读作“后随”.

// Match an 'a' followed by a digit
sregex re = 'a' >> _d;

选择 (alternation) 与 Perl 中一样, 使用 | 运算符. 这个运算符可以读作“或”. 例如:

// match a digit character or a word character one or more times
sregex re = +( _d | _w );

分组与捕获

在 Perl 中, 括号 () 有特殊含义. 它们用于分组, 但副作用是也会创建诸如 $1 和 $2 这样的后向引用. 在 C++ 中, 括号只用于分组 -- 无法赋予它们副作用. 为了获得同样的效果, 我们使用特殊的 s1、s2 等 token. 向某个 token 赋值即可创建一个后向引用. 之后你可以在表达式的后面使用这个后向引用, 就像在 Perl 中使用 \1 和 \2 一样. 例如, 考虑下面这个查找匹配 HTML 标签的正则:

"<(\\w+)>.*?</\\1>"

在静态 xpressive 中, 则应写为:

'<' >> (s1= +_w) >> '>' >> -*_ >> "</" >> s1 >> '>'

注意如何通过向 s1 赋值来捕获后向引用, 然后在模式的后面使用 s1 来查找匹配的结束标签.

提示

分组而不捕获后向引用

在 xpressive 中, 如果你只想分组而不捕获后向引用, 可以只用 () 而不带 s1. 这等价于 Perl 的 (?:) 非捕获分组构造.

大小写不敏感与国际化

Perl 允许你使用 (?i:) 模式修饰符使正则表达式的一部分不区分大小写. xpressive 也有一个大小写不敏感的模式修饰符, 称为 icase. 你可以按如下方式使用它:

sregex re = "this" >> icase( "that" );

在这个正则表达式中, "this" 将精确匹配, 但 "that" 将不区分大小写地匹配.

大小写不敏感的正则表达式引出了国际化问题: 不区分大小写的字符比较应如何求值? 此外, 许多字符类是与 locale 相关的. 哪些字符由 digit 匹配, 哪些由 alpha 匹配? 答案取决于正则表达式对象所使用的 std::locale 对象. 默认情况下, 所有正则表达式对象都使用全局 locale. 你可以使用 imbue() 模式修饰符来覆盖默认行为, 如下:

std::locale my_locale = /* initialize a std::locale object */;
sregex re = imbue( my_locale )( +alpha >> +digit );

这个正则表达式将求值 alpha 和 digit, 所依据的是 my_locale. 有关如何定制正则行为的更多信息, 请参阅关于本地化与 Regex Traits 的章节.

动态正则

概述

静态正则固然好用, 但有时你需要更“动态”一点的东西. 设想你正在开发一个带正则搜索/替换功能的文本编辑器. 你需要在运行期从最终用户那里接受一个正则表达式作为输入. 应当有办法把字符串解析为正则表达式. 这正是 xpressive 动态正则的用武之地. 它们与静态版本由相同的核心组件构建, 但采用晚绑定, 因此你可以在运行期指定它们.

构造与赋值

创建动态正则有两种方式: 使用 basic_regex<>::compile() 函数或 regex_compiler<> 类模板. 若想使用默认 locale, 用 basic_regex<>::compile(). 若需要指定不同的 locale, 用 regex_compiler<>. 在关于regex 文法的章节中, 我们会看到 regex_compiler<> 的另一种用途.

下面是一个使用 basic_regex<>::compile() 的示例:

sregex re = sregex::compile( "this|that", regex_constants::icase );

下面是使用 regex_compiler<> 的同一示例:

sregex_compiler compiler;
sregex re = compiler.compile( "this|that", regex_constants::icase );

basic_regex<>::compile() 是以 regex_compiler<> 为基础实现的.

动态 xpressive 语法

由于动态语法不受合法 C++ 表达式规则的约束, 我们可以放心地为动态正则使用人们熟悉的语法. 出于这个原因, xpressive 用于动态正则的语法遵循 John Maddock 向标准库添加正则表达式的提案所确立的样式. 它本质上是 ECMAScript 标准化的语法, 为支持国际化做了少量修改.

由于该语法在其他地方已有详尽文档, 我只想让你参考现有的标准, 而不在此重复规范.

国际化

与静态正则一样, 动态正则也通过允许你指定不同的 std::locale 来支持国际化. 为此, 必须使用 regex_compiler<>. regex_compiler<> 类有一个 imbue() 函数. 在你已经对一个 regex_compiler<> 对象 imbue 了自定义 std::locale 之后, 该 regex_compiler<> 编译的所有正则对象都将使用那个 locale. 例如:

std::locale my_locale = /* initialize your locale object here */;
sregex_compiler compiler;
compiler.imbue( my_locale );
sregex re = compiler.compile( "\\w+|\\d+" );

这个正则表达式将使用 my_locale 来求值内部字符集 "\\w" 和 "\\d".

匹配与搜索

概述

创建正则对象之后, 你就可以使用 regex_match() 和 regex_search() 算法在字符串中查找模式. 本页介绍正则匹配和搜索的基础知识. 在所有情况下, 如果你熟悉 regex_match() 和 regex_search() 在 Boost.Regex 库中的工作方式, 那么 xpressive 的版本以同样的方式工作.

查看字符串是否与正则匹配

regex_match() 算法检查正则是否与给定输入匹配.

警告

regex_match() 算法只会在正则匹配整个输入 (从头到尾) 时才报告成功. 如果正则只匹配输入的一部分, regex_match() 将返回 false. 如果你想在字符串中搜索正则匹配的子串, 请使用 regex_search() 算法.

输入可以是一个双向范围 (如 std::string)、C 风格的以空字符结尾的字符串, 或一对迭代器. 在所有情况下, 用于遍历输入序列的迭代器类型必须与声明正则对象时使用的迭代器类型匹配. (你可以使用快速入门中的表格找到适合你的迭代器的正则类型.)

cregex cre = +_w;  // this regex can match C-style strings
sregex sre = +_w;  // this regex can match std::strings

if( regex_match( "hello", cre ) )              // OK
    { /*...*/ }

if( regex_match( std::string("hello"), sre ) ) // OK
    { /*...*/ }

if( regex_match( "hello", sre ) )              // ERROR! iterator mis-match!
    { /*...*/ }

regex_match() 算法还可以选择接受一个 match_results<> 结构作为输出参数. 如果给出, regex_match() 算法会把正则的哪些部分匹配了输入的哪些部分的信息填入该 match_results<> 结构.

cmatch what;
cregex cre = +(s1= _w);

// store the results of the regex_match in "what"
if( regex_match( "hello", what, cre ) )
{
    std::cout << what[1] << '\n'; // prints "o"
}

regex_match() 算法还可以选择接受一个 match_flag_type 位掩码. 通过 match_flag_type, 你可以控制匹配求值的某些方面. 完整的标志列表及其含义请参见 match_flag_type 参考.

std::string str("hello");
sregex sre = bol >> +_w;

// match_not_bol means that "bol" should not match at [begin,begin)
if( regex_match( str.begin(), str.end(), sre, regex_constants::match_not_bol ) )
{
    // should never get here!!!
}

搜索匹配的子串

当你想知道输入序列是否包含正则匹配的子序列时, 使用 regex_search(). regex_search() 会尝试在输入序列的开头匹配正则, 并在序列中向前扫描, 直到找到匹配或穷尽序列.

在其他方面, regex_search() 的行为与 regex_match() (见上文) 相同. 特别是, 它可以对双向范围 (如 std::string)、C 风格的以空字符结尾的字符串或迭代器范围进行操作. 同样必须注意确保正则的迭代器类型与输入序列的迭代器类型匹配. 与 regex_match() 一样, 你可以选择提供一个 match_results<> 结构来接收搜索结果, 以及一个 match_flag_type 位掩码来控制匹配的求值方式.

访问结果

概述

有时, 仅仅知道一个 regex_match() 或 regex_search() 是否成功并不够. 如果你把一个 match_results<> 类型的对象传给 regex_match() 或 regex_search(), 那么在算法成功完成之后, match_results<> 将包含关于正则的哪些部分匹配了序列的哪些部分的额外信息. 在 Perl 中, 这些子序列称为 后向引用, 它们保存在变量 $1、$2 等中. 在 xpressive 中, 它们是 sub_match<> 类型的对象, 保存在 match_results<> 结构中, 该结构表现得像一个 sub_match<> 对象的 vector.

你已经把一个 match_results<> 对象传给了正则算法, 并且算法成功了. 现在你想查看结果. 你对 match_results<> 对象所做的大部分操作是索引它以访问其内部保存的 sub_match<> 对象, 但除此之外还能对一个 match_results<> 对象做一些别的事情.

结果以指向输入序列的迭代器形式保存. 任何使输入序列失效的操作都会使匹配结果失效. 例如, 如果你匹配一个 std::string 对象, 结果只在下一次调用该 std::string 对象的非 const 成员函数之前有效. 之后, match_results<> 对象持有的结果就是无效的. 不要再使用它们!

字符串替换

正则表达式不仅擅长搜索文本, 还擅长操作文本. 最常见的文本操作任务之一就是查找并替换. xpressive 提供 regex_replace() 算法来进行搜索和替换.

regex_replace()

使用 regex_replace() 进行查找并替换很简单. 你只需要一个输入序列、一个正则对象和一个格式串或格式化器对象. regex_replace() 算法有多个版本. 有些版本接受输入序列为双向容器 (如 std::string), 并在一个相同类型的新容器中返回结果. 另一些版本接受输入为以空字符结尾的字符串, 并返回一个 std::string. 还有一些版本接受输入序列为一对迭代器, 并把结果写入输出迭代器. 替换内容可以指定为带格式序列的字符串, 也可以指定为格式化器对象. 下面是一些使用基于字符串的替换的简单示例.

std::string input("This is his face");
sregex re = as_xpr("his");                // find all occurrences of "his" ...
std::string format("her");                // ... and replace them with "her"

// use the version of regex_replace() that operates on strings
std::string output = regex_replace( input, re, format );
std::cout << output << '\n';

// use the version of regex_replace() that operates on iterators
std::ostream_iterator< char > out_iter( std::cout );
regex_replace( out_iter, input.begin(), input.end(), re, format );

上面的程序输出如下:

Ther is her face
Ther is her face

注意 所有 "his" 的出现都已被替换为 "her".

格式化器对象

格式串的表达能力并不总能满足你所有的文本替换需求. 考虑一个简单的例子: 想把输入字符串映射为输出字符串, 就像你可能对环境变量所做的那样. 为此你要用的不是格式字符串, 而是格式化器对象. 考虑以下代码, 它查找形如 "$(XYZ)" 的内嵌环境变量, 并通过在一个 map 中查找该环境变量来计算替换字符串.

#include <map>
#include <string>
#include <iostream>
#include <boost/xpressive/xpressive.hpp>
using namespace boost;
using namespace xpressive;

std::map<std::string, std::string> env;

std::string const &format_fun(smatch const &what)
{
    return env[what[1].str()];
}

int main()
{
    env["X"] = "this";
    env["Y"] = "that";

    std::string input("\"$(X)\" has the value \"$(Y)\"");

    // replace strings like "$(XYZ)" with the result of env["XYZ"]
    sregex envar = "$(" >> (s1 = +_w) >> ')';
    std::string output = regex_replace(input, envar, format_fun);
    std::cout << output << std::endl;
}

在这个例子中, 我们用一个函数 format_fun() 来即时计算替换字符串. 它接受一个包含当前匹配结果的 match_results<> 对象. format_fun() 把第一个子匹配用作全局 env map 的键. 上面的代码显示:

"this" has the value "that"

格式化器不必是普通函数, 也可以是类类型的对象. 而且它可以不返回字符串, 而是接受一个输出迭代器并把替换内容写入其中. 考虑下面的代码, 它在功能上与上面的代码等价.

#include <map>
#include <string>
#include <iostream>
#include <boost/xpressive/xpressive.hpp>
using namespace boost;
using namespace xpressive;

struct formatter
{
    typedef std::map<std::string, std::string> env_map;
    env_map env;

    template<typename Out>
    Out operator()(smatch const &what, Out out) const
    {
        env_map::const_iterator where = env.find(what[1]);
        if(where != env.end())
        {
            std::string const &sub = where->second;
            out = std::copy(sub.begin(), sub.end(), out);
        }
        return out;
    }

};

int main()
{
    formatter fmt;
    fmt.env["X"] = "this";
    fmt.env["Y"] = "that";

    std::string input("\"$(X)\" has the value \"$(Y)\"");

    sregex envar = "$(" >> (s1 = +_w) >> ')';
    std::string output = regex_replace(input, envar, fmt);
    std::cout << output << std::endl;
}

格式化器表达式

除格式字符串和格式化器对象之外, regex_replace() 还接受格式化器表达式. 格式化器表达式是生成字符串的 lambda 表达式. 它使用与语义动作相同的语法, 语义动作将在后面介绍. 上面的示例使用 regex_replace() 把字符串替换为环境变量, 这里用格式化器表达式再写一遍.

#include <map>
#include <string>
#include <iostream>
#include <boost/xpressive/xpressive.hpp>
#include <boost/xpressive/regex_actions.hpp>
using namespace boost::xpressive;

int main()
{
    std::map<std::string, std::string> env;
    env["X"] = "this";
    env["Y"] = "that";

    std::string input("\"$(X)\" has the value \"$(Y)\"");

    sregex envar = "$(" >> (s1 = +_w) >> ')';
    std::string output = regex_replace(input, envar, ref(env)[s1]);
    std::cout << output << std::endl;
}

在上面的代码中, 格式化器表达式是 ref(env)[s1]. 这意味着用第一个子匹配的值 s1 作为 env map 的键. 这里 xpressive::ref() 的作用是使对局部变量 env 的引用变得惰性, 从而把索引操作推迟到知道要用什么替换 s1 时才执行.

字符串拆分与分词

regex_token_iterator<> 是文本操作世界中的“Ginsu 多功能刀”. 它能切片! 也能切丁! 本节描述如何使用高度可配置的 regex_token_iterator<> 来切分输入序列.

概述

你用一个输入序列、一个正则和一些可选的配置参数来初始化 regex_token_iterator<>. regex_token_iterator<> 会使用 regex_search() 来查找序列中正则匹配的第一个位置. 解引用时, regex_token_iterator<> 返回一个 token, 其形式为 std::basic_string<>. 它返回哪个字符串取决于配置参数. 默认情况下它返回与完整匹配对应的字符串, 但也可以返回与某个特定标记子表达式对应的字符串, 甚至返回序列中未匹配的部分. 当你递增 regex_token_iterator<> 时, 它会移动到下一个 token. 下一个 token 是什么取决于配置参数. 它可能只是当前匹配中的另一个标记子表达式, 也可能是下一个匹配的一部分或全部, 还可能是未匹配的部分.

如你所见, regex_token_iterator<> 能做很多事. 这使得它难以描述, 但一些示例应该能把它讲清楚.

示例 1: 简单分词

这个示例使用 regex_token_iterator<> 把一个序列切分为由单词组成的 token 序列.

std::string input("This is his face");
sregex re = +_w;                      // find a word

// iterate over all the words in the input
sregex_token_iterator begin( input.begin(), input.end(), re ), end;

// write all the words to std::cout
std::ostream_iterator< std::string > out_iter( std::cout, "\n" );
std::copy( begin, end, out_iter );

该程序显示如下内容:

This
is
his
face

示例 2: 简单分词 (重装上阵)

这个示例同样使用 regex_token_iterator<> 把一个序列切分为由单词组成的 token 序列, 但它把正则用作分隔符. 当我们把 -1 作为最后一个参数传给 regex_token_iterator<> 构造函数时, 它指示 token 迭代器把输入中未匹配正则的部分当作 token.

std::string input("This is his face");
sregex re = +_s;                      // find white space

// iterate over all non-white space in the input. Note the -1 below:
sregex_token_iterator begin( input.begin(), input.end(), re, -1 ), end;

// write all the words to std::cout
std::ostream_iterator< std::string > out_iter( std::cout, "\n" );
std::copy( begin, end, out_iter );

该程序显示如下内容:

This
is
his
face

示例 3: 简单分词 (革命再起)

这个示例同样使用 regex_token_iterator<> 把一个包含一堆日期的序列切分为只由年份组成的 token 序列. 当我们把一个正整数 N 作为最后一个参数传给 regex_token_iterator<> 构造函数时, 它指示 token 迭代器只把每个匹配的第 N 个标记子表达式当作 token.

std::string input("01/02/2003 blahblah 04/23/1999 blahblah 11/13/1981");
sregex re = sregex::compile("(\\d{2})/(\\d{2})/(\\d{4})"); // find a date

// iterate over all the years in the input. Note the 3 below, corresponding to the 3rd sub-expression:
sregex_token_iterator begin( input.begin(), input.end(), re, 3 ), end;

// write all the words to std::cout
std::ostream_iterator< std::string > out_iter( std::cout, "\n" );
std::copy( begin, end, out_iter );

该程序显示如下内容:

2003
1999
1981

示例 4: 不那么简单的分词

这个示例与前一个类似, 但它不是只对年份分词, 而是把日、月和年都变成 token. 当我们把一个整数数组 {I,J,...} 作为最后一个参数传给 regex_token_iterator<> 构造函数时, 它指示 token 迭代器把每个匹配的第 I、J 等个标记子表达式当作 token.

std::string input("01/02/2003 blahblah 04/23/1999 blahblah 11/13/1981");
sregex re = sregex::compile("(\\d{2})/(\\d{2})/(\\d{4})"); // find a date

// iterate over the days, months and years in the input
int const sub_matches[] = { 2, 1, 3 }; // day, month, year
sregex_token_iterator begin( input.begin(), input.end(), re, sub_matches ), end;

// write all the words to std::cout
std::ostream_iterator< std::string > out_iter( std::cout, "\n" );
std::copy( begin, end, out_iter );

该程序显示如下内容:

02
01
2003
23
04
1999
13
11
1981

sub_matches 数组指示 regex_token_iterator<> 先取第 2 个子匹配的值, 再取第 1 个, 最后取第 3 个. 再次递增迭代器会指示它再次使用 regex_search() 来查找下一个匹配. 此时, 该过程重复进行 -- token 迭代器先取第 2 个子匹配的值, 再取第 1 个, 依此类推.

命名捕获

概述

对于复杂的正则表达式, 处理按编号的捕获可能很麻烦. 数左括号来弄清该引用哪个捕获可不是什么乐趣. 更无趣的是, 仅仅编辑一下正则表达式就可能使某个捕获获得新的编号, 使按旧编号引用它的代码失效.

其他正则表达式引擎用一种称为 命名捕获 的特性来解决这个问题. 该特性允许你给捕获指定一个名字, 并按名字而非编号回指该捕获. Xpressive 也支持命名捕获, 静态和动态正则中均支持.

动态命名捕获

对于动态正则表达式, xpressive 在命名捕获的语法上跟随其他流行正则引擎的做法. 你可以用 "(?P<xxx>...)" 创建命名捕获, 并用 "(?P=xxx)" 回指该捕获. 例如, 下面是一个创建命名捕获并回指它的正则表达式:

// Create a named capture called "char" that matches a single
// character and refer back to that capture by name.
sregex rx = sregex::compile("(?P<char>.)(?P=char)");

上面这个正则表达式的效果是找出第一个重复的字符.

一旦你使用带命名捕获的正则执行了匹配或搜索操作, 就可以通过 match_results<> 对象用捕获的名字访问该命名捕获.

std::string str("tweet");
sregex rx = sregex::compile("(?P<char>.)(?P=char)");
smatch what;
if(regex_search(str, what, rx))
{
    std::cout << "char = " << what["char"] << std::endl;
}

以上代码输出:

char = e

你也可以在替换字符串中回指命名捕获. 其语法是 "\\g<xxx>". 下面是一些演示在进行字符串替换时如何使用命名捕获的代码.

std::string str("tweet");
sregex rx = sregex::compile("(?P<char>.)(?P=char)");
str = regex_replace(str, rx, "**\\g<char>**", regex_constants::format_perl);
std::cout << str << std::endl;

注意, 使用命名捕获时必须指定 format_perl. 只有 perl 语法能识别 "\\g<xxx>" 语法. 上面的代码显示:

tw**e**t

静态命名捕获

如果你使用静态正则表达式, 创建和使用命名捕获就更容易了. 你可以用 mark_tag 类型创建一个变量, 使用方式与 s1、s2 等一样, 但名字更有意义. 下面是上面的示例使用静态正则时的样子:

mark_tag char_(1); // char_ is now a synonym for s1
sregex rx = (char_= _) >> char_;

匹配操作之后, 你可以用 mark_tag 来索引 match_results<> 以访问命名捕获:

std::string str("tweet");
mark_tag char_(1);
sregex rx = (char_= _) >> char_;
smatch what;
if(regex_search(str, what, rx))
{
    std::cout << what[char_] << std::endl;
}

以上代码输出:

char = e

在使用 regex_replace() 进行字符串替换时, 你可以用命名捕获来创建如下所示的 格式表达式:

std::string str("tweet");
mark_tag char_(1);
sregex rx = (char_= _) >> char_;
str = regex_replace(str, rx, "**" + char_ + "**");
std::cout << str << std::endl;

以上代码输出:

tw**e**t
注释

要使用格式表达式, 需要包含 <boost/xpressive/regex_actions.hpp>.

文法与嵌套匹配

概述

把正则表示为 C++ 表达式的一个关键好处, 是能够在正则内部轻松引用其他 C++ 代码和数据. 这使得其他正则表达式库无法实现的编程惯用法成为可能. 特别值得注意的是一个正则引用另一个正则的能力, 这让你可以用正则表达式构建文法. 本节描述如何按值和按引用把一个正则嵌入另一个正则, 正则对象在引用其他正则时的行为, 以及如何在成功解析后访问结果树.

按值嵌入正则

basic_regex<> 对象具有值语义. 当一个正则对象出现在另一个正则定义的右侧时, 就好像该正则被按值嵌入; 也就是说, 被嵌套正则的一个副本由外围正则保存. 内层正则在模式匹配过程中由外层正则调用. 内层正则完整参与匹配, 并按需回溯以使匹配成功.

考虑一个带全字选项的正则查找功能的文本编辑器. 你可以用 xpressive 这样实现:

find_dialog dlg;
if( dialog_ok == dlg.do_modal() )
{
    std::string pattern = dlg.get_text();          // the pattern the user entered
    bool whole_word = dlg.whole_word.is_checked(); // did the user select the whole-word option?

    sregex re = sregex::compile( pattern );        // try to compile the pattern

    if( whole_word )
    {
        // wrap the regex in begin-word / end-word assertions
        re = bow >> re >> eow;
    }

    // ... use re ...
}

仔细看这一行:

// wrap the regex in begin-word / end-word assertions
re = bow >> re >> eow;

这一行创建了一个按值嵌入旧正则的新正则. 然后, 新正则被赋回给原来的正则. 由于右侧复制了旧正则, 这就像你期望的那样工作: 新正则具有旧正则的行为, 外面包裹着词首词尾断言.

注释

注意, re = bow >> re >> eow 并不定义一个递归正则表达式, 因为正则对象默认按值嵌入. 下一节展示如何通过按引用嵌入正则来定义递归正则表达式.

按引用嵌入正则

如果你希望能够构建递归正则表达式和上下文无关文法, 按值嵌入正则是不够的. 你需要让你的正则表达式能够自引用. 大多数正则表达式引擎不给你这种能力, 但 xpressive 给.

提示

理论计算机科学家们会正确地指出, 自引用的正则表达式已经不是“正则的”, 因此严格来说, xpressive 其实根本不是一个正则表达式引擎. 但正如 Larry Wall 曾经所说: “[正则表达式]这个术语已随我们模式匹配引擎的能力而成长, 所以我不打算在这里与语言上的必然性作对.”

考虑下面的代码, 它使用 by_ref() 辅助设施定义了一个匹配配对嵌套括号的递归正则表达式:

sregex parentheses;
parentheses                          // A balanced set of parentheses ...
    = '('                            // is an opening parenthesis ...
        >>                           // followed by ...
         *(                          // zero or more ...
            keep( +~(set='(',')') )  // of a bunch of things that are not parentheses ...
          |                          // or ...
            by_ref(parentheses)      // a balanced set of parentheses
          )                          //   (ooh, recursion!) ...
        >>                           // followed by ...
      ')'                            // a closing parenthesis
    ;

匹配配对嵌套的标签是一项重要的文本处理任务, 也是“经典”正则表达式无法完成的任务之一. by_ref() 辅助设施使之成为可能. 它允许把一个正则对象按引用嵌入另一个正则对象. 由于右侧按引用持有 parentheses, 把右侧赋回给 parentheses 就会创建一个环, 该环将递归执行.

构建文法

一旦我们允许正则表达式自引用, 精灵就出瓶了, 各种有趣的东西都成为可能. 特别是, 我们现在可以用正则表达式构建文法. 我们来看教科书式的文法示例: 简单的计算器.

sregex group, factor, term, expression;

group       = '(' >> by_ref(expression) >> ')';
factor      = +_d | group;
term        = factor >> *(('*' >> factor) | ('/' >> factor));
expression  = term >> *(('+' >> term) | ('-' >> term));

上面定义的正则 expression 做了一件对正则表达式来说相当了不起的事: 它匹配数学表达式. 例如, 如果输入字符串是 "foo 9*(10+3) bar", 这个模式就会匹配 "9*(10+3)". 它只匹配合式的数学表达式, 即括号配对且每个中缀运算符都有两个操作数. 可别用随便哪个正则表达式引擎来尝试这个!

让我们更仔细地看看这个正则文法. 注意它是循环的: expression 以 term 为基础实现, 后者又以 factor 为基础实现, 后者又以 group 为基础实现, 后者又以 expression 为基础实现, 从而闭合了这个环. 一般来说, 定义循环文法的方法是前向声明这些正则对象, 并按引用嵌入那些尚未初始化的正则表达式. 在上面的文法中, 只有一处需要引用尚未初始化的正则对象: group 的定义. 在那个位置, 我们用 by_ref() 按引用嵌入 expression. 在所有其他位置, 按值嵌入其他正则对象就足够了, 因为它们已经初始化, 其值不会再改变.

提示

尽可能按值嵌入

一般来说, 优先按值而非按引用嵌入正则表达式. 这样少一层间接, 使你的模式匹配得稍快一些. 此外, 值语义更简单, 会让你的文法更容易推理. 不必担心“复制”正则的开销. 每个正则对象与其所有副本共享同一个实现.

动态正则文法

使用 regex_compiler<>, 你也可以用动态正则表达式构建文法. 做法是创建命名正则, 并按名字引用其他正则. 每个 regex_compiler<> 实例都保存一个从名字到用它创建的正则的映射.

你可以通过在正则前面加上 "(?$name=)" 来创建命名的动态正则, 其中 name 是正则的名字. 你可以用 "(?$name)" 从另一个正则引用命名正则. 命名正则在被另一个正则引用时还不必存在, 但在你使用该正则时必须已存在.

下面是一个使用动态正则文法实现上文计算器示例的代码片段.

using namespace boost::xpressive;
using namespace regex_constants;

sregex expr;

{
     sregex_compiler compiler;
     syntax_option_type x = ignore_white_space;

            compiler.compile("(? $group  = ) \\( (? $expr ) \\) ", x);
            compiler.compile("(? $factor = ) \\d+ | (? $group ) ", x);
            compiler.compile("(? $term   = ) (? $factor )"
                             " ( \\* (? $factor ) | / (? $factor ) )* ", x);
     expr = compiler.compile("(? $expr   = ) (? $term )"
                             "   ( \\+ (? $term ) | - (? $term )   )* ", x);
}

std::string str("foo 9*(10+3) bar");
smatch what;

if(regex_search(str, what, expr))
{
     // This prints "9*(10+3)":
     std::cout << what[0] << std::endl;
}

与静态正则文法一样, 嵌套的正则调用会创建嵌套的匹配结果 (见下文 嵌套结果). 其结果是为匹配的字符串生成一棵完整的解析树. 与静态正则不同, 动态正则总是按引用嵌入, 而不是按值嵌入.

循环模式、复制与内存管理, 哦天哪!

上面的计算器示例引出了许多非常复杂的内存管理问题. 四个正则对象相互引用, 有的直接、有的间接, 有的按值、有的按引用. 如果我们从函数中返回其中一个, 而让其他的离开作用域, 会怎样? 这些引用会怎么样? 答案是, 正则对象内部采用引用计数, 只要还需要被引用的正则对象, 它们就会使其保活. 因此按值传递正则对象永远不是问题, 即使它引用了已经离开作用域的其他正则对象.

处理过引用计数的人可能熟悉它的阿喀琉斯之踵: 循环引用. 如果正则对象采用引用计数, 那么像计算器示例中创建的那样的环会怎样? 会泄漏吗? 答案是: 不会泄漏. basic_regex<> 对象有一些巧妙的引用跟踪代码, 确保即使是循环的正则文法, 在最后一个外部引用消失时也会被清理. 所以不必担心. 尽管创建循环文法、随意传递和复制你的正则对象. 这样做快速高效, 并保证不会泄漏, 也不会产生悬空引用.

嵌套正则与子匹配作用域

嵌套正则表达式引出了子匹配作用域的问题. 如果内层和外层正则都读写同一个子匹配向量, 混乱将随之而来. 内层正则会践踏外层正则写入的子匹配. 例如, 下面这段代码会做什么?

sregex inner = sregex::compile( "(.)\\1" );
sregex outer = (s1= _) >> inner >> s1;

作者很可能并不打算让内层正则覆盖外层正则写入的子匹配. 当内层正则是从用户输入接受的时候, 问题尤其尖锐. 作者无从得知内层正则是否会践踏子匹配向量. 这显然不可接受.

实际上, 每次嵌套正则调用都会得到自己的作用域. 子匹配属于那个作用域. 也就是说, 每次嵌套正则调用都得到自己的子匹配向量副本来操作, 因此外层正则的子匹配不可能被内层正则践踏. 例如, 上面定义的正则 outer 会正确地匹配 "ABBA".

嵌套结果

如果嵌套正则有自己的子匹配, 那么在成功匹配之后应当有办法访问它们. 事实上是有的. 在 regex_match() 或 regex_search() 之后, match_results<> 结构表现得像嵌套结果树的头部. match_results<> 类提供一个 nested_results() 成员函数, 它返回由 match_results<> 结构组成的有序序列, 表示嵌套正则的结果. 嵌套结果的顺序与嵌套正则对象匹配的顺序相同.

以我们之前见过的匹配配对嵌套括号的正则为例:

sregex parentheses;
parentheses = '(' >> *( keep( +~(set='(',')') ) | by_ref(parentheses) ) >> ')';

smatch what;
std::string str( "blah blah( a(b)c (c(e)f (g)h )i (j)6 )blah" );

if( regex_search( str, what, parentheses ) )
{
    // display the whole match
    std::cout << what[0] << '\n';

    // display the nested results
    std::for_each(
        what.nested_results().begin(),
        what.nested_results().end(),
        output_nested_results() );
}

该程序显示如下内容:

( a(b)c (c(e)f (g)h )i (j)6 )
    (b)
    (c(e)f (g)h )
        (e)
        (g)
    (j)

这里你可以看到结果是如何嵌套的, 以及它们是按被发现的顺序存储的.

提示

output_nested_results 的定义见示例一节.

过滤嵌套结果

有时一个正则会有多个嵌套的正则对象, 而你想知道哪个结果对应哪个正则对象. 这正是 basic_regex<>::regex_id() 和 match_results<>::regex_id() 派上用场的地方. 在遍历嵌套结果时, 你可以把结果中的正则 id 与你感兴趣的正则对象的 id 进行比较.

为了稍微简化这一点, xpressive 提供了一个谓词, 使遍历对应某个特定嵌套正则的结果变得简单. 它名为 regex_id_filter_predicate, 旨在与 Boost.Iterator 一起使用. 你可以按如下方式使用它:

sregex name = +alpha;
sregex integer = +_d;
sregex re = *( *_s >> ( name | integer ) );

smatch what;
std::string str( "marsha 123 jan 456 cindy 789" );

if( regex_match( str, what, re ) )
{
    smatch::nested_results_type::const_iterator begin = what.nested_results().begin();
    smatch::nested_results_type::const_iterator end   = what.nested_results().end();

    // declare filter predicates to select just the names or the integers
    sregex_id_filter_predicate name_id( name.regex_id() );
    sregex_id_filter_predicate integer_id( integer.regex_id() );

    // iterate over only the results from the name regex
    std::for_each(
        boost::make_filter_iterator( name_id, begin, end ),
        boost::make_filter_iterator( name_id, end, end ),
        output_result
        );

    std::cout << '\n';

    // iterate over only the results from the integer regex
    std::for_each(
        boost::make_filter_iterator( integer_id, begin, end ),
        boost::make_filter_iterator( integer_id, end, end ),
        output_result
        );
}

其中 output_results 是一个简单的函数, 它接受一个 smatch 并显示完整匹配. 注意我们如何把 regex_id_filter_predicate 与 basic_regex<>::regex_id() 和 boost::make_filter_iterator() (来自 Boost.Iterator) 结合使用, 只选出对应某个特定嵌套正则的结果. 这个程序显示如下:

marsha
jan
cindy
123
456
789

语义动作与用户自定义断言

概述

设想你想解析一个输入字符串并用它构建一个 std::map<>. 对于这类任务, 仅匹配正则表达式是不够的. 你想在你的正则表达式的某些部分匹配时做点什么. Xpressive 允许你把语义动作附加到静态正则表达式的某些部分. 本节告诉你怎么做.

语义动作

考虑下面的代码, 它使用 xpressive 的语义动作解析一个单词/整数对字符串, 并把它们塞进一个 std::map<>. 下面是对它的说明.

#include <string>
#include <iostream>
#include <boost/xpressive/xpressive.hpp>
#include <boost/xpressive/regex_actions.hpp>
using namespace boost::xpressive;

int main()
{
    std::map<std::string, int> result;
    std::string str("aaa=>1 bbb=>23 ccc=>456");

    // Match a word and an integer, separated by =>,
    // and then stuff the result into a std::map<>
    sregex pair = ( (s1= +_w) >> "=>" >> (s2= +_d) )
        [ ref(result)[s1] = as<int>(s2) ];

    // Match one or more word/integer pairs, separated
    // by whitespace.
    sregex rx = pair >> *(+_s >> pair);

    if(regex_match(str, rx))
    {
        std::cout << result["aaa"] << '\n';
        std::cout << result["bbb"] << '\n';
        std::cout << result["ccc"] << '\n';
    }

    return 0;
}

这个程序打印如下:

1
23
456

正则表达式 pair 有两部分: 模式和动作. 模式要求匹配一个单词 (捕获到子匹配 1) 和一个整数 (捕获到子匹配 2), 二者以 "=>" 分隔. 动作是方括号中的部分: [ ref(result)[s1] = as<int>(s2) ]. 它说: 取子匹配 1, 用它索引 results map, 并把子匹配 2 转换为整数的结果赋给它.

注释

要在静态正则中使用语义动作, 必须 #include <boost/xpressive/regex_actions.hpp>

这是如何工作的? 与静态正则表达式的其余部分一样, 方括号之间的部分也是表达式模板. 它对动作进行编码并稍后执行. 表达式 ref(result) 创建对 result 对象的惰性引用. 更大的表达式 ref(result)[s1] 是一个惰性的 map 索引操作. 稍后当这个动作被执行时, s1 会被替换为第一个 sub_match<>. 同样, 当 as<int>(s2) 被执行时, s2 会被替换为第二个 sub_match<>. as<> 动作使用 Boost.Lexical_cast 把它的参数转换为所要求的类型. 整个动作的效果是向 map 中插入一个新的单词/整数对.

注释

函数 boost::ref() 在 <boost/ref.hpp> 中与 boost::xpressive::ref() 在 <boost/xpressive/regex_actions.hpp> 中有一个重要区别. 前者返回一个普通 reference_wrapper<>, 它在许多方面表现得像普通引用. 相比之下, boost::xpressive::ref() 返回一个惰性引用, 你可以在延迟执行的表达式中使用它. 这就是为什么我们可以写 ref(result)[s1], 即使 result 并没有一个 operator[] 能够接受 s1.

除了子匹配占位符 s1、s2 等之外, 你还可以在动作中使用占位符 _ 来回指与该动作所附加的子表达式匹配的字符串. 例如, 你可以用下面的正则来匹配一串数字, 把它们解释为整数并把结果赋给一个局部变量:

int i = 0;
// Here, _ refers back to all the
// characters matched by (+_d)
sregex rex = (+_d)[ ref(i) = as<int>(_) ];

惰性动作执行

把动作附加到正则表达式的一部分并执行匹配, 到底是什么意思? 动作何时执行? 如果动作是重复子表达式的一部分, 动作执行一次还是多次? 如果子表达式最初匹配, 但由于正则表达式的其余部分匹配失败而最终失败, 动作还会执行吗?

答案是, 默认情况下动作是惰性执行的. 当子表达式匹配一个字符串时, 它的动作被放入一个队列, 连同该动作所引用的任何子匹配的当前值. 如果匹配算法必须回溯, 动作会按需从队列中弹出. 只有在整个正则成功匹配之后, 动作才真正被执行. 它们一次性全部执行, 顺序为它们加入队列的顺序, 作为 regex_match() 返回前的最后一步.

例如, 考虑下面这个每当找到一个数字就递增计数器的正则.

int i = 0;
std::string str("1!2!3?");
// count the exciting digits, but not the
// questionable ones.
sregex rex = +( _d [ ++ref(i) ] >> '!' );
regex_search(str, rex);
assert( i == 2 );

动作 ++ref(i) 被入队三次: 每找到一个数字一次. 但它只被执行两次: 每个位于 '!' 字符之前的数字一次. 当遇到 '?' 字符时, 匹配算法回溯, 把最后一个动作从队列中移除.

立即执行动作

当你希望语义动作立即执行时, 可以把包含动作的子表达式包裹在一个 keep() 中. keep() 对其子表达式关闭回溯, 但它也使子表达式入队的任何动作在 keep() 结束时执行. 这就好比 keep() 中的子表达式被编译成一个独立的正则对象, 匹配 keep() 就像对 regex_search() 的一次单独调用. 它匹配字符并执行动作, 但从不回溯或回退. 例如, 设想上面的例子被写成如下形式:

int i = 0;
std::string str("1!2!3?");
// count all the digits.
sregex rex = +( keep( _d [ ++ref(i) ] ) >> '!' );
regex_search(str, rex);
assert( i == 3 );

我们把子表达式 _d [ ++ref(i) ] 包裹在 keep() 中. 现在, 每当这个正则匹配一个数字, 动作就会入队并立即执行, 然后才尝试匹配 '!' 字符. 在这个例子中, 动作执行了三次.

注释

与 keep() 类似, before() 和 after() 中的动作也会在其子表达式匹配后提前执行.

惰性函数

到目前为止, 我们已经看到了如何编写由变量和运算符组成的语义动作. 但如果你想在语义动作中调用函数怎么办? Xpressive 提供了实现这一点的机制.

第一步是定义一个函数对象类型. 例如, 下面是一个对其参数调用 push() 的函数对象类型:

struct push_impl
{
    // Result type, needed for tr1::result_of
    typedef void result_type;

    template<typename Sequence, typename Value>
    void operator()(Sequence &seq, Value const &val) const
    {
        seq.push(val);
    }
};

下一步是使用 xpressive 的 function<> 模板定义一个名为 push 的函数对象:

// Global "push" function object.
function<push_impl>::type const push = {{}};

这个初始化看起来有点奇怪, 但这是因为 push 被静态初始化. 这意味着它不需要在运行期构造. 我们可以在语义动作中按如下方式使用 push:

std::stack<int> ints;
// Match digits, cast them to an int
// and push it on the stack.
sregex rex = (+_d)[push(ref(ints), as<int>(_))];

你会注意到, 这样做会使成员函数的调用看起来像普通函数调用. 你也可以选择用另一种方式编写语义动作, 使它看起来更像成员函数调用:

sregex rex = (+_d)[ref(ints)->*push(as<int>(_))];

Xpressive 能识别 ->* 的用法, 并把这个表达式与上面的完全等同对待.

当你的函数对象必须返回一个依赖于其参数的类型时, 可以使用 result<> 成员模板来代替 result_type typedef. 例如, 下面是一个 first 函数对象, 它返回 first 成员, 其对象为 std::pair<> 或 sub_match<>:

// Function object that returns the
// first element of a pair.
struct first_impl
{
    template<typename Sig> struct result {};

    template<typename This, typename Pair>
    struct result<This(Pair)>
    {
        typedef typename remove_reference<Pair>
            ::type::first_type type;
    };

    template<typename Pair>
    typename Pair::first_type
    operator()(Pair const &p) const
    {
        return p.first;
    }
};

// OK, use as first(s1) to get the begin iterator
// of the sub-match referred to by s1.
function<first_impl>::type const first = {{}};

引用局部变量

正如上面的示例所示, 我们可以在动作中使用 xpressive::ref() 引用局部变量. 任何这样的变量都被正则表达式按引用持有, 应当小心避免让这些引用悬空. 例如, 在下面的代码中, 对 i 的引用在 bad_voodoo() 返回时会悬空:

sregex bad_voodoo()
{
    int i = 0;
    sregex rex = +( _d [ ++ref(i) ] >> '!' );
    // ERROR! rex refers by reference to a local
    // variable, which will dangle after bad_voodoo()
    // returns.
    return rex;
}

编写语义动作时, 确保所有引用不悬空是你的责任. 一种做法是把变量做成共享指针, 让正则按值持有它.

sregex good_voodoo(boost::shared_ptr<int> pi)
{
    // Use val() to hold the shared_ptr by value:
    sregex rex = +( _d [ ++*val(pi) ] >> '!' );
    // OK, rex holds a reference count to the integer.
    return rex;
}

在上面的代码中, 我们用 xpressive::val() 按值持有共享指针. 这通常没有必要, 因为出现在动作中的局部变量默认按值持有, 但在这个例子中是必要的. 如果我们把动作写成 ++*pi, 它将立即执行. 这是因为 ++*pi 不是表达式模板, 而 ++*val(pi) 是.

在语义动作中把所有变量都包在 ref() 和 val() 里可能很繁琐. Xpressive 提供 reference<> 和 value<> 模板来简化工作. 下表展示了等价关系:

local<int> i(0);
std::string str("1!2!3?");

// questionable ones.
sregex rex = +( _d [ ++i ] >> '!' );
regex_search(str, rex);
assert( i.get() == 2 );

注意我们用 local<>::get() 来访问局部变量的值. 另外要当心, local<> 同样可能造成悬空引用, 就像 reference<> 一样.

引用非局部变量

在本节开头, 我们使用带语义动作的正则来解析一个单词/整数对字符串, 并把它们塞进一个 std::map<>. 这要求 map 和正则一起定义, 并在二者离开作用域之前使用. 如果我们想只定义一次正则, 然后用它填充许多不同的 map, 该怎么办? 我们宁愿把 map 传给 regex_match() 算法, 而不是把对它的引用直接嵌入正则对象. 我们可以做的替代方案是定义一个占位符, 并在语义动作中使用该占位符而不是 map 本身. 之后, 当我们调用某个正则算法时, 再把引用绑定到一个实际的 map 对象. 下面的代码展示了如何做到这一点.

// Define a placeholder for a map object:
placeholder<std::map<std::string, int> > _map;

// Match a word and an integer, separated by =>,
// and then stuff the result into a std::map<>
sregex pair = ( (s1= +_w) >> "=>" >> (s2= +_d) )
    [ _map[s1] = as<int>(s2) ];

// Match one or more word/integer pairs, separated
// by whitespace.
sregex rx = pair >> *(+_s >> pair);

// The string to parse
std::string str("aaa=>1 bbb=>23 ccc=>456");

// Here is the actual map to fill in:
std::map<std::string, int> result;

// Bind the _map placeholder to the actual map
smatch what;
what.let( _map = result );

// Execute the match and fill in result map
if(regex_match(str, what, rx))
{
    std::cout << result["aaa"] << '\n';
    std::cout << result["bbb"] << '\n';
    std::cout << result["ccc"] << '\n';
}

这个程序显示:

1
23
456

我们在这里用 placeholder<> 定义 _map, 它代表一个 std::map<> 变量. 我们可以在语义动作中使用这个占位符, 就像它是一个 map 一样. 然后, 我们定义一个 match_results<> 结构, 并用 “what.let( _map = result );” 把一个实际的 map 绑定到占位符. regex_match() 调用的行为就像语义动作中的占位符已被替换为对 result 的引用一样.

注释

语义动作中的占位符在运行期并不会被替换为对变量的引用. 正则对象在任何正则算法期间都不会以任何方式被改变, 因此在多线程中使用它们是安全的.

如果你使用的是 regex_iterator<> 或 regex_token_iterator<>, 晚绑定动作参数的语法稍有不同. 正则迭代器接受一个额外的构造函数参数, 用于指定参数绑定. 有一个 let() 函数可用于把变量绑定到它们的占位符. 下面的代码演示了如何做到这一点.

// Define a placeholder for a map object:
placeholder<std::map<std::string, int> > _map;

// Match a word and an integer, separated by =>,
// and then stuff the result into a std::map<>
sregex pair = ( (s1= +_w) >> "=>" >> (s2= +_d) )
    [ _map[s1] = as<int>(s2) ];

// The string to parse
std::string str("aaa=>1 bbb=>23 ccc=>456");

// Here is the actual map to fill in:
std::map<std::string, int> result;

// Create a regex_iterator to find all the matches
sregex_iterator it(str.begin(), str.end(), pair, let(_map=result));
sregex_iterator end;

// step through all the matches, and fill in
// the result map
while(it != end)
    ++it;

std::cout << result["aaa"] << '\n';
std::cout << result["bbb"] << '\n';
std::cout << result["ccc"] << '\n';

这个程序显示:

1
23
456

用户自定义断言

你可能已经熟悉正则表达式断言. 在 Perl 中, 一些例子是 ^ 和 $ 断言, 你可以用它们分别匹配字符串的开头和结尾. Xpressive 允许你定义自己的断言. 自定义断言是一个条件, 在匹配过程中的某个点必须为真, 匹配才能成功. 你可以用 xpressive 的 check() 函数检查自定义断言.

定义自定义断言有几种方式. 最简单的是使用函数对象. 假设你想确保某个子表达式匹配的子串长度为 3 或 6 个字符. 下面的结构定义了这样一个谓词:

// A predicate that is true IFF a sub-match is
// either 3 or 6 characters long.
struct three_or_six
{
    bool operator()(ssub_match const &sub) const
    {
        return sub.length() == 3 || sub.length() == 6;
    }
};

你可以在正则表达式中按如下方式使用这个谓词:

// match words of 3 characters or 6 characters.
sregex rx = (bow >> +_w >> eow)[ check(three_or_six()) ] ;

上面的正则表达式会找出长度为 3 或 6 个字符的整词. three_or_six 谓词接受一个 sub_match<>, 它回指与自定义断言所附加的子表达式匹配的那部分字符串.

注释

自定义断言参与决定匹配成功与否. 与惰性执行的动作不同, 自定义断言在正则引擎搜索匹配时立即执行.

自定义断言也可以用与语义动作相同的语法内联定义. 下面是用内联方式编写的同一自定义断言:

// match words of 3 characters or 6 characters.
sregex rx = (bow >> +_w >> eow)[ check(length(_)==3 || length(_)==6) ] ;

在上面的代码中, length() 是一个惰性函数, 它调用其参数的 length() 成员函数; _ 是一个占位符, 接收 sub_match.

一旦你掌握了内联编写自定义断言的技巧, 它们可以非常强大. 例如, 你可以写一个只匹配有效日期的正则表达式 (对该术语采用某种足够宽松的定义, 即 “有效”).

int const days_per_month[] =
    {31, 29, 31, 30, 31, 30, 31, 31, 30, 31, 31, 31};

mark_tag month(1), day(2);
// find a valid date of the form month/day/year.
sregex date =
    (
        // Month must be between 1 and 12 inclusive
        (month= _d >> !_d)     [ check(as<int>(_) >= 1
                                    && as<int>(_) <= 12) ]
    >>  '/'
        // Day must be between 1 and 31 inclusive
    >>  (day=   _d >> !_d)     [ check(as<int>(_) >= 1
                                    && as<int>(_) <= 31) ]
    >>  '/'
        // Only consider years between 1970 and 2038
    >>  (_d >> _d >> _d >> _d) [ check(as<int>(_) >= 1970
                                    && as<int>(_) <= 2038) ]
    )
    // Ensure the month actually has that many days!
    [ check( ref(days_per_month)[as<int>(month)-1] >= as<int>(day) ) ]
;

smatch what;
std::string str("99/99/9999 2/30/2006 2/28/2006");

if(regex_search(str, what, date))
{
    std::cout << what[0] << std::endl;
}

上面的程序输出如下:

2/28/2006

注意内联自定义断言如何用于对月、日和年的值进行范围检查. 该正则表达式不匹配 "99/99/9999" 或 "2/30/2006", 因为它们不是有效日期. (没有第 99 个月, 而 2 月也没有 30 天.)

符号表与属性

概述

符号表只需用一个 std::map<> 就能内建到 xpressive 正则表达式中. map 的键是要匹配的字符串, map 的值是要返回给你的语义动作的数据. xpressive 属性名为 a1、a2 直到 a9, 保存与匹配键对应的值, 以便在语义动作中使用. 如果找不到符号, 可以为属性指定默认值.

符号表

xpressive 符号表只是一个 std::map<>, 其键是字符串类型, 值可以是任何东西. 例如, 下面的正则表达式匹配 map1 中的一个键, 并把对应的值赋给属性 a1. 然后, 在语义动作中, 它把存储在属性 a1 中的值赋给一个整数结果.

int result;
std::map<std::string, int> map1;
// ... (fill the map)
sregex rx = ( a1 = map1 ) [ ref(result) = a1 ];

考虑下面的示例代码, 它把数字名称转换为整数. 下面是对它的说明.

#include <string>
#include <iostream>
#include <boost/xpressive/xpressive.hpp>
#include <boost/xpressive/regex_actions.hpp>
using namespace boost::xpressive;

int main()
{
    std::map<std::string, int> number_map;
    number_map["one"] = 1;
    number_map["two"] = 2;
    number_map["three"] = 3;
    // Match a string from number_map
    // and store the integer value in 'result'
    // if not found, store -1 in 'result'
    int result = 0;
    cregex rx = ((a1 = number_map ) | *_)
        [ ref(result) = (a1 | -1)];

    regex_match("three", rx);
    std::cout << result << '\n';
    regex_match("two", rx);
    std::cout << result << '\n';
    regex_match("stuff", rx);
    std::cout << result << '\n';
    return 0;
}

这个程序打印如下:

3
2
-1

首先, 程序构建一个数字 map, 以数字名称作为字符串键, 对应的整数作为值. 然后, 它使用属性 a1 构建一个静态正则表达式, 该属性表示符号表查找的结果. 在语义动作中, 该属性被赋给整数变量 result. 如果找不到符号, 则把默认值 -1 赋给 result. 通配符 *_ 确保即使找不到符号, 正则也能匹配.

这个示例的更完整版本见 libs/xpressive/example/numbers.cpp[31]. 它转换最多到 "nine hundred ninety nine million nine hundred ninety nine thousand nine hundred ninety nine" 的数字名称, 以及一些特殊的数字名称如 "dozen".

默认情况下符号表匹配区分大小写, 但把表达式包裹在 icase() 中可以使其不区分大小写.

属性

一个正则表达式中最多可以使用 9 个属性. 它们命名为 a1、a2、...、a9, 位于 boost::xpressive 命名空间中. 属性类型与赋给它的 map 的第二个成分相同. 可以在语义动作中用语法 (a1 | default-value) 为属性指定默认值.

属性有正确的作用域, 所以你可以做些疯狂的事情, 比如: ( (a1=sym1) >> (a1=sym2)[ref(x)=a1] )[ref(y)=a1]. 内层语义动作看到的是内层 a1, 外层语义动作看到的是外层的. 它们甚至可以有不同的类型.

注释

Xpressive 会从 map 构建一个隐藏的三分搜索树, 以便快速搜索. 如果定义了 BOOST_DISABLE_THREADS, 隐藏的三分搜索树会“自适应”, 每次搜索之后它会根据先前搜索的频率重构自身, 以提高未来搜索的效率.

本地化与 Regex Traits

概述

用正则表达式匹配字符串通常需要与 locale 相关的信息. 例如, 不区分大小写的比较如何执行? 与 locale 相关的行为被封装在一个 traits 类中. xpressive 提供三个 traits 类模板: cpp_regex_traits<>、c_regex_traits<> 和 null_regex_traits<>. 第一个封装一个 std::locale, 第二个封装全局 C locale, 第三个是在搜索非字符数据时使用的桩 traits 类型. 所有 traits 模板都符合Regex Traits 概念.

设置默认的 Regex Trait

默认情况下, xpressive 对所有模式使用 cpp_regex_traits<>. 这使所有正则对象都使用全局 std::locale. 如果编译时定义了 BOOST_XPRESSIVE_USE_C_TRAITS, 那么 xpressive 默认将使用 c_regex_traits<>.

在动态正则中使用自定义 Traits

要创建使用自定义 traits 对象的动态正则, 必须使用 regex_compiler<>. 基本步骤如下面的示例所示:

// Declare a regex_compiler that uses the global C locale
regex_compiler<char const *, c_regex_traits<char> > crxcomp;
cregex crx = crxcomp.compile( "\\w+" );

// Declare a regex_compiler that uses a custom std::locale
std::locale loc = /* ... create a locale here ... */;
regex_compiler<char const *, cpp_regex_traits<char> > cpprxcomp(loc);
cregex cpprx = cpprxcomp.compile( "\\w+" );

regex_compiler 对象充当正则工厂. 一旦它们被 imbue 了一个 locale, 它们创建的每个正则对象都将使用那个 locale.

在静态正则中使用自定义 Traits

如果你想让某个特定的静态正则使用不同的 traits 集, 可以使用特殊的 imbue() 模式修饰符. 例如:

// Define a regex that uses the global C locale
c_regex_traits<char> ctraits;
sregex crx = imbue(ctraits)( +_w );

// Define a regex that uses a customized std::locale
std::locale loc = /* ... create a locale here ... */;
cpp_regex_traits<char> cpptraits(loc);
sregex cpprx1 = imbue(cpptraits)( +_w );

// A shorthand for above
sregex cpprx2 = imbue(loc)( +_w );

imbue() 模式修饰符必须包裹整个模式. 只对静态正则的一部分使用 imbue 是错误的. 例如:

// ERROR! Cannot imbue() only part of a regex
sregex error = _w >> imbue(loc)( _w );

搜索非字符数据: null_regex_traits

使用 xpressive 静态正则, 你不限于在字符序列中搜索模式. 你可以在原始字节、整数或任何符合Char 概念的东西中搜索模式. null_regex_traits<> 使这变得简单. 它是 Regex Traits 概念的桩实现. 它不识别任何字符类, 也不做任何区分大小写的映射.

例如, 使用 null_regex_traits<>, 你可以写一个静态正则来在整数序列中查找模式, 如下所示:

// some integral data to search
int const data[] = {0, 1, 2, 3, 4, 5, 6};

// create a null_regex_traits<> object for searching integers ...
null_regex_traits<int> nul;

// imbue a regex object with the null_regex_traits ...
basic_regex<int const *> rex = imbue(nul)(1 >> +((set= 2,3) | 4) >> 5);
match_results<int const *> what;

// search for the pattern in the array of integers ...
regex_search(data, data + 7, what, rex);

assert(what[0].matched);
assert(*what[0].first == 1);
assert(*what[0].second == 6);

技巧与窍门

使用这些技巧和窍门, 从 xpressive 中榨取最佳性能.

一次编译模式并反复使用

编译正则 (动态或静态) 的开销比执行匹配或搜索大得多. 如果可以选择, 宁愿把模式编译成一个 basic_regex<> 对象一次并反复使用, 也不要一遍又一遍地重新创建它.

由于 basic_regex<> 对象不会被任何正则算法改变, 一旦其初始化 (以及它所属的任何文法的初始化) 完成, 它们就是完全线程安全的. 复用模式的最简单方式是把你的 basic_regex<> 对象设为 "static const".

复用 match_results<> 对象

match_results<> 对象缓存动态分配的内存. 因此, 如果你必须执行多次正则搜索, 复用同一个 match_results<> 对象要好得多.

警告: match_results<> 对象不是线程安全的, 所以不要疯狂地跨线程复用它们.

优先使用接受 match_results<> 对象的算法

这是上一条技巧的推论. 如果你要做多次搜索, 应该优先选择接受 match_results<> 对象的正则算法, 而不是不接受的那种, 并且每次复用同一个 match_results<> 对象. 如果你不提供 match_results<> 对象, 将为你创建一个临时的对象, 并在算法返回时丢弃. 对象中缓存的任何内存都将被释放, 下次不得不重新分配.

优先使用接受迭代器范围的算法而非以空字符结尾的字符串

xpressive 为 regex_match() 和 regex_search() 算法提供了在 C 风格以空字符结尾的字符串上进行操作的重载. 你应该优先使用接受迭代器范围的重载. 当你把一个以空字符结尾的字符串传给正则算法时, 结束迭代器会通过调用 strlen 立即计算. 如果你已经知道字符串的长度, 可以通过用 [begin, end) 对来调用正则算法来避免这一开销.

使用静态正则

平均而言, 静态正则的执行速度比对应的动态正则快约 10 到 15%. 值得花时间熟悉静态正则方言.

理解 syntax_option_type::optimize

optimize 标志告诉正则编译器花额外的时间分析模式. 它可以使某些模式执行得更快, 但会增加编译模式的时间, 且通常会增加模式消耗的内存量. 如果你打算复用你的模式, optimize 通常是值得的. 如果模式只用一次, 就不要用 optimize.

常见陷阱

牢记以下提示, 避免踩进 xpressive 的坑.

在单线程中创建文法

使用静态正则, 你可以通过把正则相互嵌套来创建文法. 编译外层正则时, 外层和内层正则对象, 以及它们直接或间接引用的所有正则对象, 都会被修改. 因此, 让全局正则对象参与文法是危险的. 最好从单个线程构建正则文法. 构建完成后, 得到的正则文法可以在多个线程中无问题地执行.

当心嵌套的量词

这是许多正则表达式引擎共有的陷阱. 某些模式可能导致指数级的糟糕性能. 这些模式通常涉及一个被量词修饰的项嵌套在另一个量词中, 例如 "(a*)*", 尽管在许多情况下问题更难发现. 当心具有嵌套量词的模式.

检查字符串是否包含与正则匹配的子串

注意在这个示例中, 我们如何使用自定义的 mark_tag 来使模式更可读. 之后我们可以用 mark_tag 来索引 match_results<>.

#include <iostream>
#include <boost/xpressive/xpressive.hpp>

using namespace boost::xpressive;

int main()
{
    char const *str = "I was born on 5/30/1973 at 7am.";

    // define some custom mark_tags with names more meaningful than s1, s2, etc.
    mark_tag day(1), month(2), year(3), delim(4);

    // this regex finds a date
    cregex date = (month= repeat<1,2>(_d))           // find the month ...
               >> (delim= (set= '/','-'))            // followed by a delimiter ...
               >> (day=   repeat<1,2>(_d)) >> delim  // and a day followed by the same delimiter ...
               >> (year=  repeat<1,2>(_d >> _d));    // and the year.

    cmatch what;

    if( regex_search( str, what, date ) )
    {
        std::cout << what[0]     << '\n'; // whole match
        std::cout << what[day]   << '\n'; // the day
        std::cout << what[month] << '\n'; // the month
        std::cout << what[year]  << '\n'; // the year
        std::cout << what[delim] << '\n'; // the delimiter
    }

    return 0;
}

替换所有与正则匹配的子串

下面的程序在一个字符串中查找日期, 并用伪 HTML 对其进行标记.

#include <iostream>
#include <boost/xpressive/xpressive.hpp>

using namespace boost::xpressive;

int main()
{
    std::string str( "I was born on 5/30/1973 at 7am." );

    // essentially the same regex as in the previous example, but using a dynamic regex
    sregex date = sregex::compile( "(\\d{1,2})([/-])(\\d{1,2})\\2((?:\\d{2}){1,2})" );

    // As in Perl, $& is a reference to the sub-string that matched the regex
    std::string format( "<date>$&</date>" );

    str = regex_replace( str, date, format );
    std::cout << str << '\n';

    return 0;
}

把字符串拆分为各自与正则匹配的 token

#include <iostream>
#include <boost/xpressive/xpressive.hpp>

using namespace boost::xpressive;

int main()
{
    std::string str( "Eric: 4:40, Karl: 3:35, Francesca: 2:32" );

    // find a race time
    sregex time = sregex::compile( "(\\d):(\\d\\d)" );

    // the first marked sub-expression followed by the value of the second

    sregex_token_iterator end;

    for( ; cur != end; ++cur )

    return 0;

以正则作为分隔符拆分字符串

下面的程序取一些已用 HTML 标记的文本, 并剥除标记. 它使用一个匹配 HTML 标签的正则和一个 regex_token_iterator<>, 后者返回字符串中不与正则匹配的部分.

#include <iostream>
#include <boost/xpressive/xpressive.hpp>

using namespace boost::xpressive;

int main()
{
    std::string str( "Now <bold>is the time <i>for all good men</i> to come to the aid of their</bold> country." );

    // find a HTML tag
    sregex html = '<' >> optional('/') >> +_w >> '>';

    // the -1 below directs the token iterator to display the parts of
    // the string that did NOT match the regular expression.
    sregex_token_iterator cur( str.begin(), str.end(), html, -1 );
    sregex_token_iterator end;

    for( ; cur != end; ++cur )
    {
        std::cout << '{' << *cur << '}';
    }
    std::cout << '\n';

    return 0;
}

显示嵌套结果树

下面是一个辅助类, 演示你可以如何显示一棵嵌套结果树:

// Displays nested results to std::cout with indenting
struct output_nested_results
{
    int tabs_;

    output_nested_results( int tabs = 0 )
        : tabs_( tabs )
    {
    }

    template< typename BidiIterT >
    void operator ()( match_results< BidiIterT > const &what ) const
    {
        // first, do some indenting
        typedef typename std::iterator_traits< BidiIterT >::value_type char_type;
        char_type space_ch = char_type(' ');
        std::fill_n( std::ostream_iterator<char_type>( std::cout ), tabs_ * 4, space_ch );

        // output the match
        std::cout << what[0] << '\n';

        // output any nested matches
        std::for_each(
            what.nested_results().begin(),
            what.nested_results().end(),
            output_nested_results( tabs_ + 1 ) );
    }
};
