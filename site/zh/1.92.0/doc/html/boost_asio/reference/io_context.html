use_service

该 io_context 类为异步 I/O 对象的用户提供核心 I/O 功能, 包括:

  • ip::tcp::socket
  • ip::tcp::acceptor
  • ip::udp::socket
  • deadline_timer.

该 io_context 类还包含一些面向自定义异步服务开发者的设施.

线程安全

不同 对象: 安全.

共享 对象: 安全, 但 restart() 与 notify_fork() 函数. 调用 restart() 时, 不得调用此函数: 此时存在未完成的 run(), run_one(), run_for(), run_until(), poll() 或 poll_one() 调用会导致未定义行为. notify_fork() 函数不应在任何一个 io_context 函数, 或与 io_context 正在另一线程中被调用.

同步与异步操作

I/O 对象上的同步操作会为单个操作隐式地运行 io_context 对象, 而必须调用 io_context 的 run(), run_one(), run_for(), run_until(), poll() 或 poll_one() 等函数, 才能让 io_context 代表 C++ 程序执行异步操作. 异步操作完成的通知通过调用关联的处理器来传递. 处理器只会由当前正在调用 run(), run_one(), run_for(), run_until(), poll() 或 poll_one() 的 io_context.

处理器抛出的异常的影响

如果处理器抛出异常, 该异常允许沿抛出线程对 run(), run_one(), run_for(), run_until(), poll() 或 poll_one(). 调用这些函数的其他线程不受影响. 之后由应用负责捕获该异常.

异常被捕获之后, run(), run_one(), run_for(), run_until(), poll() 或 poll_one() 调用可以重新开始, 无需 先行调用 restart(). 这使得该线程可以重新加入 io_context 对象的线程池, 且不影响池中的任何其他线程.

例如:

boost::asio::io_context io_context;
...
for (;;)
{
  try
  {
    io_context.run();
    break; // run() exited normally
  }
  catch (my_exception& e)
  {
    // Deal with exception as appropriate.
  }
}
向 io_context 提交任意任务

要向 io_context, 请使用 dispatch, post 或 defer 自由函数.

例如:

void my_task()
{
  ...
}

...

boost::asio::io_context io_context;

// Submit a function to the io_context.
boost::asio::post(io_context, my_task);

// Submit a lambda object to the io_context.
boost::asio::post(io_context,
    []()
    {
      ...
    });

// Run the io_context until it runs out of work.
io_context.run();
防止 io_context 因无工作可做而停止

某些应用可能需要防止一个 io_context 对象的 run() 调用在无工作可做时返回. 例如, io_context 可能正在后台线程中运行, 该线程在应用的异步操作之前启动. run() 调用保持运行, 办法是用 make_work_guard 函数来创建一个 boost::asio::executor_work_guard<io_context::executor_type> 类型的对象:

boost::asio::io_context io_context;
boost::asio::executor_work_guard<boost::asio::io_context::executor_type>
  = boost::asio::make_work_guard(io_context);
...

要实现关闭, 应用随后需要调用 io_context 对象的 stop() 成员函数. 这将使 io_context run() 调用尽快返回, 放弃未完成的操作, 且不允许分派就绪的处理器.

或者, 如果应用要求允许所有操作和处理器正常完成, 可以显式重置 work 对象.

boost::asio::io_context io_context;
boost::asio::executor_work_guard<boost::asio::io_context::executor_type>
  = boost::asio::make_work_guard(io_context);
...
work.reset(); // Allow run() to exit.
