ip::basic_resolver::async_resolve (5 个重载中的第 4 个)

对查询执行异步正向解析, 得到条目列表.

template<
    typename ResolveToken = default_completion_token_t<executor_type>>
DEDUCED async_resolve(
    const protocol_type & protocol,
    string_view host,
    string_view service,
    resolver_base::flags resolve_flags,
    ResolveToken && token = default_completion_token_t< executor_type >());

此函数用于将主机名和服务名解析为端点条目列表. 它是 异步操作 的发起函数, 并且总是立即返回.

参数

protocol

协议对象, 通常表示互联网协议的 IPv4 或 IPv6 版本.

host

标识位置的字符串. 可以是描述性名称, 也可以是数字地址字符串. 若为空字符串且指定了 passive 标志, 解析得到的端点适用于本地服务绑定. 若为空字符串且未指定 passive, 解析得到的端点将使用回环地址.

service

标识所请求服务的字符串. 可以是描述性名称, 也可以是对应端口号的数字字符串. 可以为空字符串, 此时所有解析得到的端点的端口号都为 0.

resolve_flags

一组确定如何执行名称解析的标志. 默认标志适用于与远程主机的通信. 可用标志集合参见 ip::resolver_base 文档.

token

用于产生完成处理器的 完成标记, 该处理器会在解析完成时被调用. 可用的完成标记包括 use_future, use_awaitable, yield_context, 或具有正确完成签名的函数对象. 完成处理器的函数签名必须是:

void handler(
  const boost::system::error_code& error, // Result of operation.
  resolver::results_type results // Resolved endpoints as a range.
);

无论异步操作是否立即完成, 完成处理器都不会在此函数内部被调用. 若立即完成, 将以等同于使用 async_immediate 的方式调用处理器.

成功的解析操作保证会向处理器传递一个非空范围.

完成签名 
void(boost::system::error_code, results_type)
备注

在 POSIX 系统上, 主机名可在文件 /etc/hosts 中本地定义. 在 Windows 上, 主机名可在文件 c:\windows\system32\drivers\etc\hosts 中定义. 远程主机名的解析通过 DNS 执行. 操作系统在解析主机名时可能使用其他位置 (例如 Windows 上的 NETBIOS 名称).

在 POSIX 系统上, 服务名通常定义在文件 /etc/services 中. 在 Windows 上, 服务名可在文件 c:\windows\system32\drivers\etc\services 中找到. 操作系统在解析服务名时可能使用其他位置.
