defer (7 个重载中的第 5 个)

提交一个函数, 在指定的目标执行器上运行, 并把结果传递给完成处理器.

template<
    typename Function,
    typename Executor,
    typename CompletionToken = default_completion_token_t<Executor>>
auto defer(
    Function && function,
    const Executor & ex,
    CompletionToken && token = default_completion_token_t< Executor >(),
    constraint_t< !is_void< result_of_t< decay_t< Function >()> >::value >  = 0,
    constraint_t<(execution::is_executor< Executor >::value &&can_require< Executor, execution::blocking_t::never_t >::value)||is_executor< Executor >::value >  = 0);

此函数提交一个函数对象到指定的执行器上执行. 函数对象会排队等待执行, 并且在从 defer() 返回之前绝不会从当前线程调用. 在被提交的函数完成之后, 完成处理器会连同函数的结果一起被分派到其关联的执行器上运行.

使用 defer() 而不是 post, 表示调用者希望执行器延迟函数对象的排队. 当函数对象表示当前调用上下文的延续时, 这可以让执行器优化排队.

参数

function

要在目标执行器上执行的无参函数.

ex

目标执行器.

token

将用于产生完成处理器的 完成标记. 完成处理器的函数签名必须为:

void handler(decay_t<result_of_t<decay_t<Function>()>>);
返回值

此函数返回 async_initiate<CompletionToken, void()>(Init{ex}, token), 其中 Init 是一个定义如下的函数对象类型:

class Init
{
public:
  using executor_type = Executor;
  explicit Init(const Executor& ex) : ex_(ex) {}
  executor_type get_executor() const noexcept { return ex_; }
  template <typename CompletionHandler>
    void operator()(CompletionHandler&& completion_handler,
      Function&& function) const;
private:
  Executor ex_; // exposition only
};

函数调用运算符: Init:

  • 通过执行以下操作, 获取处理器关联的执行器对象 ex1 (类型为 Ex1):

    auto ex1 = get_associated_executor(completion_handler, ex);

  • 通过执行以下操作, 获取处理器关联的分配器对象 alloc:

    auto alloc = get_associated_allocator(completion_handler);

  • 如果 execution::is_executor<Ex1>::value 为 true, 则构造一个函数对象包装器 f, 它带有成员 executor_ (以 prefer(ex1, execution::outstanding_work.tracked) 初始化)、成员 function_ (是 function 的 decay 拷贝)、成员 handler_ (是 completion_handler 的 decay 拷贝), 以及一个执行以下操作的函数调用运算符:

    auto result = std::move(function_)(); auto a = get_associated_allocator(handler_); prefer(executor_, execution::allocator(a)).execute( std::bind(std::move(handler_), std::move(result)));

  • 如果 execution::is_executor<Ex1>::value 为 false, 则构造一个函数对象包装器 f, 它带有成员 work_ (以 make_work_guard(ex1) 初始化)、成员 function_ (是 function 的 decay 拷贝)、成员 handler_ (是 completion_handler 的 decay 拷贝), 以及一个执行以下操作的函数调用运算符:

    auto result = std::move(function_)(); auto a = get_associated_allocator(handler_); work_.get_executor().dispatch( std::bind(std::move(handler_), std::move(result)), a); work_.reset();

  • 如果 execution::is_executor<Executor>::value 为 true, 则执行

    prefer( require(ex, execution::blocking.never), execution::relationship.fork, execution::allocator(alloc) ).execute(std::move(f));

  • 如果 execution::is_executor<Executor>::value 为 false, 则执行

    ex.defer(std::move(f), alloc);

备注

如果函数对象抛出异常, 该异常允许传播到目标执行器. 这种情况下的行为取决于执行器. 例如, io_context 会允许异常传播到运行 io_context 的调用者, 而 thread_pool 则会调用 std::terminate.

示例

此 defer 重载可用于把长时间运行的工作提交到线程池, 完成后在关联的完成执行器 (例如协程的关联执行器) 上继续执行:

boost::asio::awaitable<void> my_coroutine()
{
   // ...

   int result = co_await boost::asio::defer(
       []{
         return perform_expensive_computation();
       },
       my_thread_pool);

   // handle result on the coroutine's associated executor
}
完成签名 
void(decay_t<result_of_t<decay_t<Function>()>>)
