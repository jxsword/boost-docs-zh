async_read_until (12 个重载中的第 4 个)

启动一个将数据读入动态缓冲区序列、直至某个函数对象指示匹配的异步操作.

template<
    typename AsyncReadStream,
    typename DynamicBuffer_v1,
    typename MatchCondition,
    typename ReadToken = default_completion_token_t<        typename AsyncReadStream::executor_type>>
DEDUCED async_read_until(
    AsyncReadStream & s,
    DynamicBuffer_v1 && buffers,
    MatchCondition match_condition,
    ReadToken && token = default_completion_token_t< typename AsyncReadStream::executor_type >(),
    constraint_t< is_match_condition< MatchCondition >::value >  = 0,
    constraint_t< is_dynamic_buffer_v1< decay_t< DynamicBuffer_v1 > >::value >  = 0,
    constraint_t< !is_dynamic_buffer_v2< decay_t< DynamicBuffer_v1 > >::value >  = 0);

此函数用于将数据异步读入指定的动态缓冲区序列, 直至用户定义的匹配条件函数对象作用于该动态缓冲区序列所含数据时指示成功匹配. 它是 异步操作 的发起函数, 并且总是立即返回. 异步操作将持续进行, 直至下列条件之一成立:

  • 匹配条件函数对象返回一个 std::pair, 其第二个元素的求值结果为 true.
  • 发生了错误.

此操作通过对流的 async_read_some 函数的零次或多次调用实现, 被称为组合操作. 若匹配条件函数对象已指示匹配, 此异步操作将立即完成. 程序必须确保在该操作完成之前, 流不执行任何其他读操作 (例如 async_read、async_read_until、流的 async_read_some 函数, 或任何其他执行读取的组合操作) .

参数

s

要从中读取数据的流. 其类型必须支持 AsyncReadStream 概念.

buffers

要读入数据的动态缓冲区序列. 尽管 buffers 对象可按需复制, 但底层内存块的所有权仍由调用者保留, 调用者必须保证这些内存块在完成处理器被调用前保持有效.

match_condition

将被调用以判定是否存在匹配的函数对象. 该函数对象的签名必须为:

pair<iterator, bool> match_condition(iterator begin, iterator end);

其中 iterator 表示类型:

buffers_iterator<typename DynamicBuffer_v1::const_buffers_type>

迭代器参数 begin 与 end 定义了要扫描以判定是否存在匹配的字节范围. 返回值的 first 成员是一个迭代器, 标记匹配函数已消费字节的末端之后的位置. 该迭代器用于为匹配条件的任何后续调用计算 begin 参数. 若已找到匹配, 返回值的 second 成员为 true, 否则为 false.

token

将用于产生完成处理器的 完成标记, 该处理器将在读取完成时被调用. 可能的完成标记包括 use_future、use_awaitable、yield_context, 或具有正确完成签名的函数对象. 完成处理器的函数签名必须为:

void handler(
  // Result of operation.
  const boost::system::error_code& error,

  // The number of bytes in the dynamic buffer sequence's
  // get area that have been fully consumed by the match
  // function. O if an error occurred.
  std::size_t bytes_transferred
);

无论异步操作是否立即完成, 完成处理器都不会在此函数内部被调用. 若立即完成, 将以等同于使用 async_immediate 的方式调用处理器.

备注

async_read_until 操作成功后, 动态缓冲区序列中可能在匹配函数对象的数据之后还包含额外数据. 应用程序通常会将这些数据留在动态缓冲区序列中, 供后续的 async_read_until 操作检查.

完成签名 
void(boost::system::error_code, std::size_t)
备注

is_match_condition 类型特征的默认实现对函数指针以及具有 result_type typedef 的函数对象求值为 true. 对其他用户定义函数对象必须对其特化.

示例

将数据异步读入 std::string 直至遇到空白字符:

typedef boost::asio::buffers_iterator<
    boost::asio::const_buffer> iterator;

std::pair<iterator, bool>
match_whitespace(iterator begin, iterator end)
{
  iterator i = begin;
  while (i != end)
    if (std::isspace(*i++))
      return std::make_pair(i, true);
  return std::make_pair(i, false);
}
...
void handler(const boost::system::error_code& e, std::size_t size);
...
std::string data;
boost::asio::async_read_until(s, data, match_whitespace, handler);

将数据异步读入 std::string 直至找到匹配字符:

class match_char
{
public:
  explicit match_char(char c) : c_(c) {}

  template <typename Iterator>
  std::pair<Iterator, bool> operator()(
      Iterator begin, Iterator end) const
  {
    Iterator i = begin;
    while (i != end)
      if (c_ == *i++)
        return std::make_pair(i, true);
    return std::make_pair(i, false);
  }

private:
  char c_;
};

namespace asio {
  template <> struct is_match_condition<match_char>
    : public boost::true_type {};
} // namespace asio
...
void handler(const boost::system::error_code& e, std::size_t size);
...
std::string data;
boost::asio::async_read_until(s, data, match_char('a'), handler);
逐操作取消

此异步操作支持对以下 cancellation_type 值进行取消:

  • cancellation_type::terminal
  • cancellation_type::partial

(前提是 AsyncReadStream 类型的 async_read_some 操作同样支持它们. )
