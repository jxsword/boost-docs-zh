async_read_until (12 个重载中的第 9 个)

启动一个将数据读入动态缓冲区序列、直至其包含指定分隔符的异步操作.

template<
    typename AsyncReadStream,
    typename DynamicBuffer_v2,
    typename ReadToken = default_completion_token_t<        typename AsyncReadStream::executor_type>>
DEDUCED async_read_until(
    AsyncReadStream & s,
    DynamicBuffer_v2 buffers,
    char delim,
    ReadToken && token = default_completion_token_t< typename AsyncReadStream::executor_type >(),
    constraint_t< is_dynamic_buffer_v2< DynamicBuffer_v2 >::value >  = 0);

此函数用于将数据异步读入指定的动态缓冲区序列, 直至该动态缓冲区序列的读取区 (get area) 包含指定分隔符. 它是 异步操作 的发起函数, 并且总是立即返回. 异步操作将持续进行, 直至下列条件之一成立:

  • 动态缓冲区序列的读取区包含指定分隔符.
  • 发生了错误.

此操作通过对流的 async_read_some 函数的零次或多次调用实现, 被称为组合操作. 若动态缓冲区序列的读取区已包含该分隔符, 此异步操作将立即完成. 程序必须确保在该操作完成之前, 流不执行任何其他读操作 (例如 async_read、async_read_until、流的 async_read_some 函数, 或任何其他执行读取的组合操作) .

参数

s

要从中读取数据的流. 其类型必须支持 AsyncReadStream 概念.

buffers

要读入数据的动态缓冲区序列. 尽管 buffers 对象可按需复制, 但底层内存块的所有权仍由调用者保留, 调用者必须保证这些内存块在完成处理器被调用前保持有效.

delim

分隔符字符.

token

将用于产生完成处理器的 完成标记, 该处理器将在读取完成时被调用. 可能的完成标记包括 use_future、use_awaitable、yield_context, 或具有正确完成签名的函数对象. 完成处理器的函数签名必须为:

void handler(
  // Result of operation.
  const boost::system::error_code& error,

  // The number of bytes in the dynamic buffer sequence's
  // get area up to and including the delimiter.
  // 0 if an error occurred.
  std::size_t bytes_transferred
);

无论异步操作是否立即完成, 完成处理器都不会在此函数内部被调用. 若立即完成, 将以等同于使用 async_immediate 的方式调用处理器.

完成签名 
void(boost::system::error_code, std::size_t)
备注

async_read_until 操作成功后, 动态缓冲区序列中可能在分隔符之后还包含额外数据. 应用程序通常会将这些数据留在动态缓冲区序列中, 供后续的 async_read_until 操作检查.

示例

将数据异步读入 std::string 直至遇到换行符:

std::string data;
...
void handler(const boost::system::error_code& e, std::size_t size)
{
  if (!e)
  {
    std::string line = data.substr(0, n);
    data.erase(0, n);
    ...
  }
}
...
boost::asio::async_read_until(s, data, '\n', handler);

async_read_until 操作成功完成后, 缓冲区 data 包含该分隔符:

{ 'a', 'b', ..., 'c', '\n', 'd', 'e', ... }

随后对 substr 的调用会提取包括分隔符在内的全部数据, 使字符串 line 包含:

{ 'a', 'b', ..., 'c', '\n' }

调用 erase 之后, 剩余数据如下保留在缓冲区 data 中:

{ 'd', 'e', ... }

这些数据可能是新行的开头, 将由后续的 async_read_until 操作提取.

逐操作取消

此异步操作支持对以下 cancellation_type 值进行取消:

  • cancellation_type::terminal
  • cancellation_type::partial

(前提是 AsyncReadStream 类型的 async_read_some 操作同样支持它们. )
