执行器要求

标准执行器

设 executor-of-impl 为仅用于阐释的概念

template<class E, class F>
  concept executor-of-impl =
    invocable<decay_t<F>&> &&
    constructible_from<decay_t<F>, F> &&
    move_constructible<decay_t<F>> &&
    copy_constructible<E> &&
    is_nothrow_copy_constructible_v<E> &&
    equality_comparable<E> /* nothrow */ &&
    requires(const E& e, F&& f) {
      e.execute((F&&)f);
    };

则 executor 与 executor_of 概念定义如下:

template<class E>
  concept executor =
    executor-of-impl<E, execution::invocable_archetype>;

template<class E, class F>
  concept executor_of =
    executor<E> &&
    executor-of-impl<E, F>;

执行器的相等比较与 swap 操作均不得通过异常退出.

执行器类型的拷贝构造函数、析构函数、相等比较、swap 函数、execute 函数或关联的 query 函数, 均不得因不同线程对这些函数的并发调用而引入数据竞争.

对于任意两个 (可能为 const 的) 值 x1 与 x2 (属于某执行器类型 X) , x1 == x2 应返回 true 仅当 boost::asio::query(x1,p) == boost::asio::query(x2,p) 对每个属性 p 成立, 且其中 boost::asio::query(x1,p) 与 boost::asio::query(x2,p) 均为良构且结果为满足 equality_comparable (C++Std [equalitycomparable]) 的非 void 类型. [注: 上述要求意味着: x1 == x2 返回 true 的前提是 x1 与 x2 可互换且效果相同. 执行器在概念上可能包含命名属性类型未暴露的附加属性, 这些属性可通过 boost::asio::query 观察; 此时, 这些属性是否影响相等性由具体的执行器实现决定. 返回 false 不一定意味着效果不同. —注结束]

执行器类型的析构函数不得为等待已提交函数对象完成而阻塞. [注: 等待已提交函数对象完成的能力可由关联的执行上下文提供. —注结束]

除上述要求外, 类型 E 与 F 仅在满足下表所列要求时才模型化 executor_of.

设:

  • e 表示类型为 E 的 (可能为 const 的) 执行器对象,
  • cf 表示函数对象 DECAY_COPY(std::forward<F>(f))
  • f 表示一个函数, 其类型为 F&&, 可按 cf() 调用, 且其中 decay_t<F> 模型化 move_constructible.

表达式 e.execute(f):

  • 在调用线程上求值 DECAY_COPY(std::forward<F>(f)), 以创建 cf, 该对象将由某个执行代理至多调用一次.
  • 在此次调用完成前可能阻塞. 与 f 的调用同步 ([intro.multithread]) .
  • 不得传播函数对象或提交给执行器的任何其他函数所抛出的异常.

[注: 对单向提交的函数所抛出异常的处理方式由实现定义. 关联执行代理的前向进展保证由实现定义. —注结束]

Networking TS 风格执行器

本库为 执行器 描述了一组标准要求. 满足 Executor 要求的类型体现了用于确定已提交函数对象如何执行的一组规则.

类型 X 满足 Executor 要求, 如果它满足 CopyConstructible (C++Std [copyconstructible]) 和 Destructible (C++Std [destructible]) 的要求, 以及下面列出的附加要求.

这些类型的构造函数、比较运算符、拷贝操作、移动操作、swap 操作以及成员函数 context、on_work_started 与 on_work_finished 均不得通过异常退出.

这些要求中定义的执行器拷贝构造函数、比较运算符与其他成员函数, 不得因不同线程对这些函数的并发调用而引入数据竞争.

设 ctx 为该执行器的 context() 成员函数返回的执行上下文. 执行器即变为无效, 当首次调用 ctx.shutdown() 返回后, 对无效执行器调用 on_work_started、on_work_finished、dispatch、post 或 defer 的效果未定义. [注: 拷贝构造函数、比较运算符与 context() 成员函数在 ctx 被销毁前持续保持有效. —注结束]

在下表中, x1 与 x2 表示类型为 X 的 (可能为 const 的) 值, mx1 表示类型为 X 的亡值 (xvalue) , f 表示可以零个实参调用的 MoveConstructible (C++Std [moveconstructible]) 函数对象, a 表示类型为 A 的 (可能为 const 的) 值, 该类型满足 Allocator 要求 (C++Std [allocator.requirements]) , u 表示一个标识符.

不得通过异常退出.

不得通过异常退出.

前置条件: 此前已调用 x2.on_work_started(), 其中 x1 == x2.

x1.dispatch(std::move(f),a)

效果: 创建对象 f1, 以 DECAY_COPY(forward<Func>(f)) (C++Std [thread.decaycopy]) 在当前执行线程中初始化. 调用 f1() 至多一次. 执行器可阻塞调用者的前向进展, 直至 f1() 执行完毕.

执行器实现应使用所提供的分配器分配存储函数对象所需的任何内存. 在调用函数对象之前, 执行器应释放所有已分配的内存. [注: 本技术规范中定义的执行器除非另有说明, 否则始终使用所提供的分配器. —注结束]

同步: dispatch 的调用与 f1 的调用同步 (C++Std [intro.multithread]) .

x1.post(std::move(f),a)
x1.defer(std::move(f),a)

效果: 创建对象 f1, 以 DECAY_COPY(forward<Func>(f)) 在当前执行线程中初始化. 调用 f1() 至多一次. 执行器不得为等待 f1() 完成而阻塞调用者的前向进展.

执行器实现应使用所提供的分配器分配存储函数对象所需的任何内存. 在调用函数对象之前, 执行器应释放所有已分配的内存. [注: 本技术规范中定义的执行器除非另有说明, 否则始终使用所提供的分配器. —注结束]

同步: post 或 defer 的调用与 f1 的调用同步 (C++Std [intro.multithread]) .

[注: 尽管对 defer 的要求与 post 相同, 但使用 post 表示调用者偏好: 不 阻塞 f1 进展的第一步, 而 defer 则表示调用者偏好: 要 阻塞 f1. defer 的一个用途是表明调用者的意图, 即 f1 是当前调用上下文的延续. 执行器可利用此信息来优化或以其他方式调整 f1 的调用方式. —注结束]
