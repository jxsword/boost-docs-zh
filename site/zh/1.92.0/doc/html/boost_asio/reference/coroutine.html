coroutine

提供对实现无栈协程的支持.

class coroutine
成员函数

名称

说明

coroutine [constructor]

以其初始状态构造协程.

is_child

如果协程是分叉的子协程, 则返回 true.

is_complete

如果协程已到达其终止状态, 则返回 true.

is_parent

如果协程是分叉的父协程, 则返回 true.

coroutine 类可用于实现无栈协程. 该类本身用于存储协程的当前状态.

协程可复制构造和赋值, 空间开销只有一个 int. 它们可以用作基类:

class session : coroutine
{
  ...
};

或用作数据成员:

class session
{
  ...
  coroutine coro_;
};

或者甚至可以使用 lambda 或 bind() 把它绑定为函数实参. 重要的一点是, 应用程序要在协程必须保持存活的整个期间维护该对象的一个副本.

伪关键字

协程与某些 "伪关键字" 配合使用, 这些伪关键字以宏的形式实现. 这些宏由一个头文件定义:

#include <boost/asio/yield.hpp>

反过来也可以按如下方式取消定义:

#include <boost/asio/unyield.hpp>

reenter

reenter 宏用于定义协程体. 它只接受一个实参: 指向协程对象的指针或引用. 例如, 如果基类是一个协程对象, 可以这样写:

reenter (this)
{
  ... coroutine body ...
}

而如果是数据成员或其他变量, 则可以这样写:

reenter (coro_)
{
  ... coroutine body ...
}

当 reenter 在运行期执行时, 控制会跳转到上一个 yield 或 fork 所在的位置.

协程体也可以是单条语句, 例如:

reenter (this) for (;;)
{
  ...
}

限制: reenter 宏使用 switch 实现. 这意味着在协程体内使用局部变量时必须小心. 局部变量不允许位于重新进入协程可能绕过变量定义的位置.

yield statement

这种形式的 yield 关键字常与异步操作配合使用:

yield socket_->async_read_some(buffer(*buffer_), *this);

这分为四个逻辑步骤:

  • yield 保存协程的当前状态.
  • 该语句发起异步操作.
  • 恢复点定义在该语句之后紧邻的位置.
  • 控制转移到协程体的末尾.

当异步操作完成时, 会调用该函数对象, 并且 reenter 使控制转移到恢复点. 重要的是要记住让协程状态随异步操作一起传递. 在上面的代码片段中, 当前类是一个函数对象, 它以协程对象作为基类或数据成员.

该语句也可以是复合语句, 这允许我们定义作用域受限的局部变量:

yield
{
  mutable_buffer b = buffer(*buffer_);
  socket_->async_read_some(b, *this);
}

yield return expression ;

这种形式的 yield 常用于生成器或基于协程的解析器. 例如, 函数对象:

struct interleave : coroutine
{
  istream& is1;
  istream& is2;
  char operator()(char c)
  {
    reenter (this) for (;;)
    {
      yield return is1.get();
      yield return is2.get();
    }
  }
};

定义了一个简单的协程, 交错读取两个输入流中的字符.

这种类型的 yield 分为三个逻辑步骤:

  • yield 保存协程的当前状态.
  • 恢复点定义在分号之后紧邻的位置.
  • 表达式的值从函数返回.

yield ;

这种形式的 yield 等价于以下步骤:

  • yield 保存协程的当前状态.
  • 恢复点定义在分号之后紧邻的位置.
  • 控制转移到协程体的末尾.

当协程用于协作式线程且调度被显式管理时, 可能会使用这种形式. 例如:

struct task : coroutine
{
  ...
  void operator()()
  {
    reenter (this)
    {
      while (... not finished ...)
      {
        ... do something ...
        yield;
        ... do some more ...
        yield;
      }
    }
  }
  ...
};
...
task t1, t2;
for (;;)
{
  t1();
  t2();
}

yield break ;

yield 的最后一种形式用于显式终止协程. 这种形式包含两个步骤:

  • yield 把协程状态设置为指示终止.
  • 控制转移到协程体的末尾.

一旦终止, 对 is_complete() 的调用将返回 true, 并且协程不能被重新进入.

注意, 如果协程体在没有 yield 的情况下退出 (例如通过 return、抛出异常或执行到协程体末尾), 协程也可能被隐式终止.

fork statement

当 "分叉" 协程时使用 fork 伪关键字, 即把它拆分为两个 (或更多) 副本. fork 的一个用例是在服务器中, 为每个客户端连接创建一个新的协程:

reenter (this)
{
  do
  {
    socket_.reset(new tcp::socket(my_context_));
    yield acceptor->async_accept(*socket_, *this);
    fork server(*this)();
  } while (is_parent());
  ... client-specific handling follows ...
}

fork 涉及的逻辑步骤为:

  • fork 保存协程的当前状态.
  • 该语句创建协程的一个副本, 然后立即执行它, 或将其调度为以后执行.
  • 恢复点定义在分号之后紧邻的位置.
  • 对于 "父" 协程, 控制立即从下一行继续.

函数 is_parent() 和 is_child() 可用于区分父协程和子协程. 可以用这些函数来改变后续的控制流.

注意, fork 本身并不执行实际的分叉. 创建协程的克隆并调用它是应用程序的职责. 克隆可以像上面那样立即调用, 也可以调度为延迟执行, 例如使用 post.

替代宏名

如果愿意, 应用程序可以使用遵循更常见命名约定的宏名, 而不是伪关键字. 这些宏名是:

  • BOOST_ASIO_CORO_REENTER 而不是 reenter
  • BOOST_ASIO_CORO_YIELD 而不是 yield
  • BOOST_ASIO_CORO_FORK 而不是 fork
