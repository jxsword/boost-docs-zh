execution_context 类与服务

类 execution_context 实现了一组可扩展、类型安全且多态的服务, 按服务类型索引.

服务用于管理在执行上下文内共享的资源. 例如, 定时器可以用单个定时器队列来实现, 而该队列就会保存在一个服务中.

对 execution_context 中的服务的访问通过三个函数模板进行: use_service(), add_service() 与 has_service().

在 use_service<Service>() 的调用中, 类型实参选择一个服务, 使所指名类型的所有成员可用. 若 Service 不存在于某个 execution_context, 就会创建一个 Service, 并将其添加到 execution_context. C++ 程序可以检查一个 execution_context 是否实现了某个特定服务, 可使用函数模板 has_service<Service>().

服务对象可以显式添加到一个 execution_context, 方法是使用函数模板 add_service<Service>(). 若 Service 已存在, 则抛出 service_already_exists 异常. 若服务的所有者与 execution_context 参数指定的对象不是同一个对象, 则抛出 invalid_service_owner 异常.

一旦从 execution_context 对象上通过调用 use_service() 获取该服务引用, 只要其所属的 execution_context 对象存在, 该引用就一直可用.

所有服务实现都以 execution_context::service 作为公有基类. 自定义服务可以通过派生该类来实现, 然后添加到一个 execution_context 中, 使用的正是上文所述的设施.

作为基类的 execution_context

类 execution_context 只能用作具体执行上下文类型的基类. io_context 就是这类派生类型的一个例子.

在销毁时, 派生自 execution_context 的类必须执行 execution_context::shutdown(), 然后执行 execution_context::destroy().

这一销毁序列使程序可以借助 shared_ptr<>. 当对象的生命期与某个连接 (或其他某个异步操作序列) 的生命期绑定在一起时, 一个 shared_ptr (指向该对象) 会被绑定到与其相关联的所有异步操作的处理器中. 其工作方式如下:

  • 当单个连接结束时, 所有相关联的异步操作都会完成. 相应的处理器对象被销毁, 并且所有指向这些对象的 shared_ptr 引用都被销毁.
  • 要关闭整个程序, io_context 函数 stop() 会被调用, 以尽快终止所有 run() 调用. io_context 析构函数会调用 shutdown() 与 destroy() 来销毁所有待处理的处理器, 使所有指向连接对象的 shared_ptr 引用全部被销毁.
