basic_socket_acceptor::async_accept (8 个重载中的第 5 个)

Start an asynchronous accept. 

template<
    typename ExecutionContext,
    typename MoveAcceptToken = default_completion_token_t<executor_type>>
DEDUCED async_accept(
    ExecutionContext & context,
    MoveAcceptToken && token = default_completion_token_t< executor_type >(),
    constraint_t< is_convertible< ExecutionContext &, execution_context & >::value >  = 0);

此函数用于异步接受一个新连接. 它是 异步操作 的发起函数, 并总是立即返回.

此重载要求 Protocol 模板参数满足 AcceptableProtocol 类型要求.

参数

context

要用于新接受的套接字的 I/O 执行上下文对象.

token

将用于产生完成处理器的 完成标记, 完成处理器将在接受完成时被调用. 可能的完成标记包括 use_future、use_awaitable、yield_context, 或具有正确完成签名的函数对象. 完成处理器的函数签名必须是:

void handler(
  // Result of operation.
  const boost::system::error_code& error,

  // On success, the newly accepted socket.
  typename Protocol::socket::template rebind_executor<
    typename ExecutionContext::executor_type>::other peer
);

无论异步操作是否立即完成, 完成处理器都不会在此函数内部被调用. 若立即完成, 将以等同于使用 async_immediate 的方式调用处理器.

完成签名 
void(boost::system::error_code,
  typename Protocol::socket::template rebind_executor<
    typename ExecutionContext::executor_type>::other))
示例 
void accept_handler(const boost::system::error_code& error,
    boost::asio::ip::tcp::socket peer)
{
  if (!error)
  {
    // Accept succeeded.
  }
}

逐操作取消

在 POSIX 或 Windows 操作系统上, 此异步操作支持对以下 cancellation_type 值进行取消:

  • cancellation_type::terminal
  • cancellation_type::partial
  • cancellation_type::total
