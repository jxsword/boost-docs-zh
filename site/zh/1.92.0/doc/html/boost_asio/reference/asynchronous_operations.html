对异步操作的要求

本节使用名称 Alloc1, Alloc2, alloc1, alloc2, Args, CompletionHandler, completion_handler, Executor1, Executor2, ex1, ex2, f, i, N, Signatures, token, initiation, Initiation, Ti, ti, work1 与 work2 作为占位符来指定下文的要求.

异步操作的一般概念

发起函数是可被调用以启动异步操作的函数. 完成处理器是将至多被调用一次、并接收异步操作结果的函数对象.

异步操作的生命周期由以下事件与阶段组成:

— 事件 1: 通过调用发起函数启动异步操作.

— 阶段 1: 异步操作此时处于未决状态.

— 事件 2: 异步操作对外可观察的副作用 (若有) 已完全确立. 完成处理器被提交给某个执行器.

— 阶段 2: 异步操作此时处于已完成状态.

— 事件 3: 完成处理器被调用并接收异步操作的结果.

在本库中, 所有带 async_ 前缀的函数都是发起函数.

完成标记与处理器

发起函数:

— 是带有模板参数 CompletionToken 的函数模板;

— 以 完成标记 对象 token (类型为 CompletionToken) 作为最后一个参数;

— 指定一个或多个完成签名 (下文称为可变参数包形式的调用签名, C++Std [func.def]) Signatures, 用于确定完成处理器可能的实参集合.

在本库中, 发起函数指定一个完成签名元素, 它定义调用签名 Signatures. 本库中的 完成签名元素可带有命名参数, 异步操作的结果可用这些名称来表述.

完成标记的行为通过特化 async_result 特征来确定. 这些特化必须具有如下形式:

template <class CompletionToken, class... Signatures>
struct async_result
{
  template<
      class Initiation,
      class RawCompletionToken,
      class... Args
    >
  static initiating-fn-return-type initiate(
      Initiation&& initiation,
      RawCompletionToken&& token,
      Args&&... args
    );
};

async_result 特化的 initiate() 静态成员函数的实现必须:

  • 将完成标记转换为对象 completion_handler (其类型为 CompletionHandler) . 类型 CompletionHandler 必须满足 Destructible (C++Std [destructible]) 与 MoveConstructible (C++Std [moveconstructible]) 的要求, 并且可以按指定的调用签名调用.

  • 使得函数对象 initiation 被调用, 如同通过以下调用:

    std::forward<Initiation>(initiation)(
    std::move(completion_handler),
    std::forward<Args>(args)...);

对 initiation 的此次调用可以是立即的, 也可以是延迟的 (例如以支持惰性求值) . 若 initiation 是延迟的, 则 initiation 与 args... 对象必须按需衰减拷贝并移动.

async_result 特征必须为 CompletionToken 的衰减后类型特化. 提供了辅助函数模板 async_initiate, 以简化对适当特化的 async_result<>::initiate 的正确调用:

template<
    class CompletionToken,
    completion_signature... Signatures,
    class Initiation,
    class... Args
  >
DEDUCED async_initiate(
    Initiation&& initiation,
    CompletionToken& token,
    Args&&... args
  );

[注: 对类型 CompletionToken 没有其他要求. —注结束]

发起函数返回类型的自动推导

发起函数返回 async_initiate<CompletionToken, Signatures...>(initiation, token, unspecified-args...), 其中 initiation 是一个未指定类型 Initiation 的函数对象, 其定义为:

class Initiation
{
public:
  using executor_type = Executor; // optional
  executor_type get_executor() const noexcept; // optional

  template <class CompletionHandler, unspecified-args...>
    void operator()(CompletionHandler&& completion_handler, unspecified-args...) const;
};

为了便于阐释, 本库有时会以返回类型 DEDUCED 标注函数. 对每个返回 DEDUCED 的函数声明, 其含义等同于一个自动推导的返回类型, 其类型为表达式 async_initiate<CompletionToken, Signatures...>(initiation, token, unspecified-args...) 的类型.

[示例: 给定一个具有单一 完成签名 void(R1 r1, R2 r2) 的异步操作, 满足这些要求的发起函数可按如下方式实现:

template<class CompletionToken>
auto async_xyz(T1 t1, T2 t2, CompletionToken&& token)
{
  return async_initiate<CompletionToken, void(R1, R2)>(
      [](auto completion_handler, T1 t1, T2 t2)
      {
        // initiate the operation and cause completion_handler to be invoked
        // with the result
      }, token, std::move(t1), std::move(t2));
}

概念 completion_token_for 与 completion_handler_for 也可用于改善编译期诊断:

template<completion_token_for<void(R1, R2)> CompletionToken>
auto async_xyz(T1 t1, T2 t2, CompletionToken&& token)
{
  return async_initiate<CompletionToken, void(R1, R2)>(
      [](completion_handler_for<void(R1, R2)> auto completion_handler, T1 t1, T2 t2)
      {
        // initiate the operation and cause completion_handler to be invoked
        // with the result
      }, token, std::move(t1), std::move(t2));
}

发起函数也可直接使用 async_result 特征来实现:

template<class CompletionToken>
auto async_xyz(T1 t1, T2 t2, CompletionToken&& token)
{
  return async_result<decay_t<CompletionToken>, void(R1, R2)>::initiate(
      [](auto completion_handler, T1 t1, T2 t2)
      {
        // initiate the operation and cause completion_handler to be invoked
        // with the result
      }, forward<CompletionToken>(token), std::move(t1), std::move(t2));
}

注意 decay_t 与 forward 应用于 CompletionToken 类型的用法. 不过首选第一种形式, 因为它保持与遗留完成标记要求的兼容性.

—示例结束]

发起函数实参的生命周期

除非另有说明, 发起函数实参的生命周期应按如下方式处理:

— 若形参具有指针类型, 或具有指向非常量的左值引用类型, 则实现可分别假定所指向对象或所引用对象在完成处理器被调用前保持有效. [注: 换言之, 程序必须保证实参在完成处理器被调用前有效. —注结束]

— 否则, 实现不得在发起函数完成后假定实参仍然有效. [注: 换言之, 程序无须保证实参在发起函数完成后仍然有效. —注结束] 实现可复制该实参, 且所有副本应在完成处理器被调用后立即销毁, 不得晚于此.

对发起函数的非阻塞要求

发起函数不得为等待未决操作完成而阻塞 (C++Std [defns.block]) 调用线程.

[注: 发起函数仍可能因其他原因阻塞调用线程. 例如, 发起函数可能锁定互斥量以同步对共享数据的访问. —注结束]

关联执行器

参与异步操作的某些对象具有关联执行器. 这些对象按下文各节的规定获取.

关联 I/O 执行器

异步操作具有一个满足 Executor 要求的关联执行器. 若异步操作未另行指定, 该关联执行器是类型为 inline_executor 的对象.

本库中的所有异步操作都有一个关联 I/O 执行器对象, 其确定方式如下:

— 若发起函数是成员函数, 则关联执行器是同一对象的 get_executor 成员函数所返回的执行器.

— 若发起函数不是成员函数, 则关联执行器是发起函数第一个实参的 get_executor 成员函数所返回的执行器.

操作的关联 I/O 执行器可通过 Initiation 函数对象的 executor_type 类型别名与 get_executor() 成员函数暴露.

设 Executor1 为关联执行器的类型. 设 ex1 为类型 Executor1 的一个值, 表示按上述方式获得的关联执行器对象.

关联完成处理器执行器

类型为 CompletionHandler 的完成处理器对象具有类型为 Executor2 的关联执行器, 其满足 Executor 要求. 类型 Executor2 为 associated_executor_t<CompletionHandler, Executor1>. 设 ex2 为类型 Executor2 的一个值, 通过执行 get_associated_executor(completion_handler, ex1) 获得.

关联立即完成执行器

类型为 CompletionHandler 的完成处理器对象具有类型为 Executor3 的关联立即执行器, 其满足 Executor 要求. 类型 Executor3 为 associated_immediate_executor_t<CompletionHandler, Executor1>. 设 ex3 为类型 Executor3 的一个值, 通过执行 get_associated_immediate_executor(completion_handler, ex1) 获得.

未决工作

若操作不会立即完成 (即操作未在调用发起函数的执行线程内、于发起函数返回之前完成) , 则在异步操作完成之前, 该异步操作应维持:

— 一个对象 work1 , 其类型为 executor_work_guard<Executor1> , 按 work1(ex1) 初始化, 且满足 work1.owns_work() == true; 以及

— 一个对象 work2 , 其类型为 executor_work_guard<Executor2> , 按 work2(ex2) 初始化, 且满足 work2.owns_work() == true.

中间存储的分配

异步操作可能分配内存. [注: 例如用于存储 completion_handler 对象副本及发起函数实参的数据结构. —注结束]

设 Alloc1 为一个类型, 其满足 ProtoAllocator 要求, 表示异步操作的默认分配策略. [注: 通常为 std::allocator<void>. —注结束] 设 alloc1 为类型 Alloc1 的一个值.

类型为 CompletionHandler 的完成处理器对象具有一个关联分配器对象 alloc2, 其类型为 Alloc2, 满足 ProtoAllocator 要求. 类型 Alloc2 为 associated_allocator_t<CompletionHandler, Alloc1>. 设 alloc2 为类型 Alloc2 的一个值, 通过执行 get_associated_allocator(completion_handler, alloc1) 获得.

本库中定义的异步操作:

— 若需要, 仅使用完成处理器的关联分配器分配内存.

— 在完成处理器执行之前, 释放所有使用完成处理器关联分配器分配的内存.

[注: 实现可能执行会分配内存、但不使用关联分配器的操作系统或底层 API 调用. 分配器函数的调用不得引入数据竞争 (参见 C++Std [res.on.data.races]) . —注结束]

异步操作完成时完成处理器的执行

设 Args... 为 Signatures... 中某个完成签名的实参类型; 并设 N 为 sizeof...(Args). 设 i 位于区间 [0, N) . 设 Ti 为 i 中的第 Args... 个类型; 并设 ti 为第 i 个与 Ti 关联的完成处理器实参.

设 f 为一个函数对象, 其:

— 可按 f() 调用, 且如此调用时调用 completion_handler, 如同通过 std::move(completion_handler)(forward<T0>(t0), ..., forward<TN-1>(tN-1));

— 具有关联执行器, 使得 get_associated_executor(f, ex1) 返回一个等于 ex2 的执行器; 以及

— 具有关联分配器, 使得 get_associated_allocator(f, alloc1) 返回一个等于 alloc2 的分配器.

[注: 对 f 的这些关联执行器与分配器要求, 通常通过为 f 特化关联器特征来实现, 使其转发到针对 completion_handler 的关联器特征. —注结束]

若异步操作立即完成 (即操作在调用发起函数的执行线程内、于发起函数返回之前完成) , 则完成处理器应如同通过执行 post(ex1, std::move(f)) 而被提交执行.

否则, 当操作完成时, 完成处理器应如同通过执行 dispatch(ex2, std::move(f)) 而被提交执行.

立即完成的优化

若异步操作立即完成, 则作为一种优化, 该操作可任选其一:

— 获取关联立即完成执行器 ex3, 方式是执行 get_associated_immediate_executor(completion_handler, ex1), 然后如同通过执行 dispatch(ex3, std::move(f)) 提交完成处理器; 或

— 若表达式 post(ex2, std::move(f)) 为良构, 则通过执行该表达式提交完成处理器.

[注: 若 completion_handler 未定制关联立即执行器, 则第一种优化的行为等同于 post(ex1, std::move(f)). —注结束]

完成处理器与异常

允许完成处理器抛出异常. 从完成处理器执行中传播出的任何异常, 其效果由正在执行该完成处理器的执行器决定.

默认完成标记

每个 I/O 执行器类型都有一个关联的默认完成标记类型. 它通过 default_completion_token 特征指定. 此特征可在异步操作声明中按如下方式使用:

template <
    typename IoObject,
    typename CompletionToken =
      typename default_completion_token<
        typename IoObject::executor_type
      >::type
  >
auto async_xyz(
    IoObject& io_object,
    CompletionToken&& token =
      typename default_completion_token<
        typename IoObject::executor_type
      >::type{}
  );

若未特化, 此特征类型为 void, 表示对给定的 I/O 执行器没有可用的默认完成标记类型.

[示例: default_completion_token 特针对 use_awaitable 完成标记做了特化, 使其可按如下示例使用:

auto socket = use_awaitable.as_default_on(tcp::socket(my_context));
// ...
co_await socket.async_connect(my_endpoint); // Defaults to use_awaitable.

在此示例中, socket 对象的类型从 tcp::socket 转换为具有默认完成标记被设为 use_awaitable 的 I/O 执行器.

或者, 套接字类型可以直接计算:

using tcp_socket = use_awaitable_t<>::as_default_on_t<tcp::socket>;
tcp_socket socket(my_context);
// ...
co_await socket.async_connect(my_endpoint); // Defaults to use_awaitable.

—示例结束]
