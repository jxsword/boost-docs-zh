basic_seq_packet_socket::async_receive (2 个重载中的第 2 个)

启动异步接收.

template<
    typename MutableBufferSequence,
    typename ReadToken = default_completion_token_t<executor_type>>
DEDUCED async_receive(
    const MutableBufferSequence & buffers,
    socket_base::message_flags in_flags,
    socket_base::message_flags & out_flags,
    ReadToken && token = default_completion_token_t< executor_type >());

此函数用于从顺序分组数据套接字异步接收数据. 它是 异步操作 的发起函数, 并总是立即返回.

参数

buffers

接收数据所用的一份或多份缓冲区. 尽管 buffers 对象可按需复制, 但底层内存块的所有权仍由调用者保留, 调用者必须保证这些内存块在完成处理器被调用前保持有效.

in_flags

指定如何进行接收调用的标志.

out_flags

异步操作完成后, 包含与接收数据关联的标志. 例如, 如果设置了 socket_base::message_end_of_record 位, 则接收的数据标记一条记录的结束. 调用者必须保证被引用的变量在完成处理器被调用之前保持有效.

token

将用于产生完成处理器的 完成标记, 该处理器将在接收完成时被调用. 可能的完成标记包括 use_future、use_awaitable、yield_context, 或具有正确完成签名的函数对象. 完成处理器的函数签名必须为:

void handler(
  const boost::system::error_code& error, // Result of operation.
  std::size_t bytes_transferred // Number of bytes received.
);

无论异步操作是否立即完成, 完成处理器都不会在此函数内部被调用. 若立即完成, 将以等同于使用 async_immediate 的方式调用处理器.

完成签名 
void(boost::system::error_code, std::size_t)
示例

要接收单个数据缓冲区, 请按如下方式使用 buffer 函数:

socket.async_receive(
    boost::asio::buffer(data, size),
    0, out_flags, handler);

有关一次性接收多个缓冲区, 以及如何将其用于数组、boost::array 或 std::vector 的信息, 参见 buffer 文档.

逐操作取消

在 POSIX 或 Windows 操作系统上, 此异步操作支持对以下 cancellation_type 值进行取消:

  • cancellation_type::terminal
  • cancellation_type::partial
  • cancellation_type::total
