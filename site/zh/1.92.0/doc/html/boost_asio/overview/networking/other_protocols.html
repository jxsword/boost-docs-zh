对其他协议的支持

对其他套接字协议 (例如 Bluetooth 或 IRCOMM 套接字) 的支持, 可以通过实现 protocol 类型要求 来添加. 不过, 在许多情况下, 这些协议也可以与 Boost.Asio 的泛型协议支持一起使用. 为此, Boost.Asio 提供以下四个类:

  • generic::datagram_protocol
  • generic::raw_protocol
  • generic::seq_packet_protocol
  • generic::stream_protocol

这些类实现了 protocol 类型要求, 但允许用户在运行期指定地址族 (例如 AF_INET) 和协议类型 (例如 IPPROTO_TCP) . 例如:

boost::asio::generic::stream_protocol::socket my_socket(my_io_context);
my_socket.open(boost::asio::generic::stream_protocol(AF_INET, IPPROTO_TCP));
...

还包含了一个端点类模板 boost::asio::generic::basic_endpoint 来支持这些协议类. 只要其原生表示能放进一个 sockaddr_storage 对象, 该端点就可以容纳任何其他端点类型. 这个类还能从实现了 endpoint 类型要求的其他类型进行转换:

boost::asio::ip::tcp::endpoint my_endpoint1 = ...;
boost::asio::generic::stream_protocol::endpoint my_endpoint2(my_endpoint1);

这种转换是隐式的, 以支持以下使用场景:

boost::asio::generic::stream_protocol::socket my_socket(my_io_context);
boost::asio::ip::tcp::endpoint my_endpoint = ...;
my_socket.connect(my_endpoint);
C++11 移动构造

使用 C++11 时, 可以从一个套接字 (或接受器) 对象进行移动构造, 转换为更泛型的协议的套接字 (或接受器) 类型. 如果协议转换是有效的:

Protocol1 p1 = ...;
Protocol2 p2(p1);

那么对应的套接字转换也是允许的:

Protocol1::socket my_socket1(my_io_context);
...
Protocol2::socket my_socket2(std::move(my_socket1));

例如, 一种可能的转换是从 TCP 套接字转换为泛型的面向流套接字:

boost::asio::ip::tcp::socket my_socket1(my_io_context);
...
boost::asio::generic::stream_protocol::socket my_socket2(std::move(my_socket1));

这些转换同样适用于移动赋值.

这些转换并不局限于上述泛型协议类. 用户定义的协议可以通过类似地确保从 Protocol1 到 Protocol2 的转换有效来利用这一特性.

接受泛型套接字

为方便起见, 套接字接受器的 accept() 和 async_accept() 函数可以直接接受到不同协议的套接字类型中, 只要对应的协议转换有效. 例如, 下面这种用法是受支持的, 因为协议 boost::asio::ip::tcp 可转换为 boost::asio::generic::stream_protocol:

boost::asio::ip::tcp::acceptor my_acceptor(my_io_context);
...
boost::asio::generic::stream_protocol::socket my_socket(my_io_context);
my_acceptor.accept(my_socket);
