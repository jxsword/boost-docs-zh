Boost.Asio 基本结构

Boost.Asio 可用于对套接字等 I/O 对象执行同步和异步操作. 在使用 Boost.Asio 之前, 先对 Boost.Asio 的各个组成部分、你的程序以及二者如何协同工作建立一个概念上的认识, 可能会很有帮助.

作为一个入门示例, 我们来考虑对套接字执行 connect 操作时会发生什么. 我们先从同步操作开始考察.

你的程序 至少拥有一个 I/O 执行上下文, 例如 boost::asio::io_context 对象、boost::asio::thread_pool 对象, 或者 boost::asio::system_context. 这个 I/O 执行上下文 表示 你的程序 与 操作系统 I/O 服务之间的联系.

boost::asio::io_context io_context;

要执行 I/O 操作, 你的程序 将需要一个 I/O 对象, 例如 TCP 套接字:

boost::asio::ip::tcp::socket socket(io_context);

当执行同步 connect 操作时, 会发生以下事件序列:

1. 你的程序 通过调用 I/O 对象 来发起 connect 操作:

socket.connect(server_endpoint);

2. I/O 对象 将该请求转发给 I/O 执行上下文.

3. I/O 执行上下文 调用 操作系统 来执行 connect 操作.

4. 操作系统 将操作结果返回给 I/O 执行上下文.

5. I/O 执行上下文 将操作产生的任何错误转换为一个类型为 boost::system::error_code 的对象. 一个 error_code 可以与特定值进行比较, 或作为布尔值来测试 (其中 false 结果表示未发生错误) . 然后, 结果被向上传回 I/O 对象.

6. I/O 对象 在操作失败时抛出类型为 boost::system::system_error 的异常. 如果发起操作的代码当初写成如下形式:

boost::system::error_code ec;
socket.connect(server_endpoint, ec);

那么 error_code 变量 ec 将被设置为操作的结果, 并且不会抛出异常.

使用异步操作时, 则会发生一个不同的事件序列.

1. 你的程序 通过调用 I/O 对象 来发起 connect 操作:

socket.async_connect(server_endpoint, your_completion_handler);

其中 your_completion_handler 是一个具有如下签名的函数或函数对象:

void your_completion_handler(const boost::system::error_code& ec);

所需的确切签名取决于所执行的异步操作. 参考文档为每个操作指明了相应的形式.

2. I/O 对象 将该请求转发给 I/O 执行上下文.

3. I/O 执行上下文 通知 操作系统 应当开始一次异步 connect.

时间流逝. (在同步情形下, 这一等待将完全包含在 connect 操作的持续时间内. )

4. 操作系统 通过把结果放入一个队列来表明 connect 操作已经完成, 等待 I/O 执行上下文 来取走.

5. 当使用 io_context 作为 I/O 执行上下文时, 你的程序 必须调用 io_context::run() (或类似的 io_context 成员函数之一) 才能取回结果. 对 io_context::run() 的调用在还有未完成的异步操作时会阻塞, 因此通常应在启动第一个异步操作之后立即调用它.

6. 在对 io_context::run() 的调用期间, I/O 执行上下文 将操作结果出队, 将其转换为一个 error_code, 然后将其传递给 你的完成处理器.

以上是 Boost.Asio 工作方式的简化图景. 如果你的需求更为高级, 例如扩展 Boost.Asio 以执行其他类型的异步操作, 那么你需要进一步深入文档.
