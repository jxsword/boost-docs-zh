设计理由

大多数程序都以某种方式与外部世界交互, 无论是通过文件、网络、串行线缆还是控制台. 有时 (例如在联网的情况下) , 单个 I/O 操作可能需要很长时间才能完成. 这给应用开发带来了特殊的挑战.

Boost.Asio 提供了管理这些长时间运行操作的工具, 而不要求程序使用基于线程和显式加锁的并发模型.

Boost.Asio 库面向使用 C++ 进行系统编程的程序员, 这类编程往往需要访问网络等操作系统功能. 特别地, Boost.Asio 致力于实现以下目标:

  • 可移植性. 库应当支持一系列常用操作系统, 并在这些操作系统上提供一致的行为.
  • 可扩展性. 库应当便于开发可扩展到数千个并发连接的网络应用. 库在各个操作系统上的实现应当采用最能实现这种可扩展性的机制.
  • 效率. 库应当支持分散-聚集 I/O 等技术, 并允许程序尽量减少数据拷贝.
  • 借鉴既有 API 的概念, 如 BSD 套接字. BSD 套接字 API 被广泛实现和理解, 并有大量文献介绍. 其他编程语言的网络 API 通常也使用类似的接口. 在合理的范围内, Boost.Asio 应当利用现有实践.
  • 易于使用. 库应当采取工具箱而非框架的思路, 为新用户降低入门门槛. 也就是说, 它应当尽量减少前期的学习投入, 只需学习一些基本规则和指南. 此后, 库使用者只需要理解正在使用的具体函数.
  • 为进一步抽象提供基础. 库应当允许开发提供更高层抽象的其他库, 例如 HTTP 等常用协议的实现.

虽然 Boost.Asio 最初主要聚焦于网络, 但其异步 I/O 概念已被扩展到其他操作系统资源, 例如串口、文件描述符等.
