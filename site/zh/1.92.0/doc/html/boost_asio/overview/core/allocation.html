自定义内存分配

许多异步操作都需要分配一个对象来存储与该操作相关的状态. 例如, Win32 实现需要 OVERLAPPED 派生类的对象, 以便传递给 Win32 API 函数.

此外, 程序通常包含容易辨识的异步操作链. 半双工协议实现 (例如 HTTP 服务器) 会为每个客户端准备一条操作链 (先接收后发送) ; 全双工协议实现则会有两条并行执行的操作链. 程序应当能够利用这一知识, 为一条链中的所有异步操作复用内存.

给定一个用户自定义 Handler 对象 h 的副本, 如果实现需要为该处理器分配内存, 它将使用 get_associated_allocator 函数获取一个分配器. 例如:

boost::asio::associated_allocator_t<Handler> a = boost::asio::get_associated_allocator(h);

关联分配器必须满足标准 Allocator 要求.

默认情况下, 处理器使用标准分配器 (它借助 ::operator new() 和 ::operator delete() 实现) . 可以针对特定的处理器类型定制分配器, 方法是指定嵌套类型 allocator_type 和成员函数 get_allocator():

class my_handler
{
public:
  // Custom implementation of Allocator type requirements.
  typedef my_allocator allocator_type;

  // Return a custom allocator implementation.
  allocator_type get_allocator() const noexcept
  {
    return my_allocator();
  }

  void operator()() { ... }
};

在更复杂的情况下, 可以直接对 associated_allocator 模板进行偏特化:

namespace boost { namespace asio {

  template <typename Allocator>
  struct associated_allocator<my_handler, Allocator>
  {
    // Custom implementation of Allocator type requirements.
    typedef my_allocator type;

    // Return a custom allocator implementation.
    static type get(const my_handler&,
        const Allocator& a = Allocator()) noexcept
    {
      return my_allocator();
    }
  };

} } // namespace boost::asio

实现保证内存释放会发生在关联处理器被调用之前, 这意味着这块内存已经可以供该处理器启动的任何新异步操作复用.

自定义内存分配函数可以从任何正在调用 Boost.Asio 库函数的用户创建线程中调用. 对于库所包含的异步操作, 实现保证: 在单个操作的上下文内, 实现不会针对该处理器的内存分配函数进行并发调用. 如果异步操作需要从不同线程调用分配函数, 实现会插入适当的内存屏障以确保正确的内存可见性. (注意: 如果同一个分配器被多个并发异步操作共享, 这可能导致对内存分配函数的并发调用. 使用 strand 并不能阻止这些并发调用, 因为操作可能需要在 strand 之外分配内存. 在这种情况下, 由共享分配器负责提供必要的线程安全保证. )
