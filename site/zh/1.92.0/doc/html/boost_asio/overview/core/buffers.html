缓冲区

从根本上说, I/O 涉及在与称为缓冲区的连续内存区域之间传输数据. 这些缓冲区可以简单地表示为一个由指针和字节大小组成的元组. 然而, 为了支持高效网络应用的开发, Boost.Asio 包含对 scatter-gather 操作的支持. 这类操作涉及一个或多个缓冲区:

  • scatter 读把数据接收到多个缓冲区中.
  • gather 写传输多个缓冲区.

因此, 我们需要一个抽象来表示缓冲区的集合. Boost.Asio 采用的方法是定义一个类型 (实际上是两个类型) 来表示单个缓冲区. 它们可以存储在容器中, 容器可以传递给 scatter-gather 操作.

除了以指针和字节大小来指定缓冲区之外, Boost.Asio 还区分可修改内存 (称为 mutable) 和不可修改内存 (后者由 const 限定变量的存储空间创建) . 因此这两个类型可以定义如下:

typedef std::pair<void*, std::size_t> mutable_buffer;
typedef std::pair<const void*, std::size_t> const_buffer;

这里, mutable_buffer 可以转换为 const_buffer, 但反方向的转换是无效的.

不过, Boost.Asio 并没有按原样使用上述定义, 而是定义了两个类: mutable_buffer 和 const_buffer. 其目标是提供连续内存的不透明表示, 其中:

  • 这些类型在转换中的行为与 std::pair 相同. 也就是说, mutable_buffer 可以转换为 const_buffer, 但反方向的转换是不允许的.
  • 对缓冲区越界提供保护. 给定一个缓冲区实例, 用户只能创建表示同一内存范围或其子范围的另一个缓冲区. 为了提供进一步的安全性, 库还包含一些机制, 可以从数组、由 POD 元素组成的 boost::array 或 std::vector, 或从 std::string 自动确定缓冲区的大小.
  • 底层内存可以通过 data() 成员函数显式访问. 一般而言, 应用程序永远不需要这样做, 但库实现需要用它把原始内存传递给底层的操作系统函数.

最后, 可以把多个缓冲区放入容器, 从而传递给 scatter-gather 操作 (例如 read() 或 write()) . MutableBufferSequence 和 ConstBufferSequence 这两个概念已被定义, 从而使得诸如 std::vector、std::list、std::array 或 boost::array 这样的容器可以使用.

Streambuf 用于与 Iostreams 集成

boost::asio::basic_streambuf 类派生自 std::basic_streambuf, 用于把输入序列和输出序列与一个或多个某种字符数组类型的对象关联起来, 这些对象的元素存储任意值. 这些字符数组对象位于 streambuf 对象内部, 但提供了对数组元素的直接访问, 以便它们可以与 I/O 操作 (例如套接字的 send 或 receive 操作) 配合使用:

  • streambuf 的输入序列可以通过 data() 成员函数访问. 该函数的返回类型满足 ConstBufferSequence 要求.
  • streambuf 的输出序列可以通过 prepare() 成员函数访问. 该函数的返回类型满足 MutableBufferSequence 要求.
  • 通过调用 commit() 成员函数, 数据从输出序列的前端转移到输入序列的后端.
  • 通过调用 consume() 成员函数, 数据从输入序列的前端移除.

streambuf 构造函数接受一个 size_t 实参, 指定输入序列与输出序列大小之和的最大值. 任何若成功便会把内部数据增长到超出此限制的操作, 都会抛出一个 std::length_error 异常.

缓冲区序列的逐字节遍历

buffers_iterator<> 类模板允许把缓冲区序列 (即满足 MutableBufferSequence 或 ConstBufferSequence 要求的类型) 当作连续字节序列来遍历. 此外还提供了名为 buffers_begin() 和 buffers_end() 的辅助函数, 此时 buffers_iterator<> 模板参数会被自动推导.

例如, 要从套接字读取一行并读入 std::string, 可以这样写:

boost::asio::streambuf sb;
...
std::size_t n = boost::asio::read_until(sock, sb, '\n');
boost::asio::streambuf::const_buffers_type bufs = sb.data();
std::string line(
    boost::asio::buffers_begin(bufs),
    boost::asio::buffers_begin(bufs) + n);
缓冲区字面量

_buf 字面量后缀定义于命名空间 boost::asio::buffer_literals 中, 可用于从字符串、二进制整数和十六进制整数字面量创建 const_buffer 对象. 这些缓冲区字面量可以是任意长度. 例如:

using namespace boost::asio::buffer_literals;

boost::asio::const_buffer b1 = "hello"_buf;
boost::asio::const_buffer b2 = 0xdeadbeef_buf;
boost::asio::const_buffer b3 = 0x01234567'89abcdef'01234567'89abcdef_buf;
boost::asio::const_buffer b4 = 0b1010101011001100_buf;

与缓冲区字面量关联的内存在程序的整个生存期内有效. 这意味着该缓冲区可以安全地用于异步操作:

async_write(my_socket, "hello"_buf, my_handler);
缓冲区调试

一些标准库实现 (例如 Microsoft Visual C++ 8.0 及更高版本自带的实现) 提供了一项称为迭代器调试 (iterator debugging) 的特性. 这意味着迭代器的有效性会在运行期进行检查. 如果程序试图使用一个已经失效的迭代器, 就会触发断言. 例如:

std::vector<int> v(1)
std::vector<int>::iterator i = v.begin();
v.clear(); // invalidates iterators
*i = 0; // assertion!

Boost.Asio 利用这一特性来增加缓冲区调试功能. 考虑以下代码:

void dont_do_this()
{
 std::string msg = "Hello, world!";
 boost::asio::async_write(sock, boost::asio::buffer(msg), my_handler);
}

调用异步读或写时, 你需要确保操作的缓冲区在完成处理器被调用之前保持有效. 在上面的例子中, 缓冲区是 std::string 变量 msg. 该变量位于栈上, 因此在异步操作完成之前它就会离开作用域. 如果幸运, 应用程序会崩溃; 但更可能出现的是随机故障.

启用缓冲区调试后, Boost.Asio 会把一个指向该字符串的迭代器保存到异步操作完成, 然后解引用它以检查其有效性. 在上面的例子中, 你会在 Boost.Asio 试图调用完成处理器之前观察到一次断言失败.

对于 Microsoft Visual Studio 8.0 或更高版本, 以及定义了 _GLIBCXX_DEBUG 的 GCC, 这一特性会自动可用. 这种检查有性能开销, 因此缓冲区调试只在调试构建中启用. 对于其他编译器, 可以通过定义 BOOST_ASIO_ENABLE_BUFFER_DEBUGGING 来启用它, 也可以通过定义 BOOST_ASIO_DISABLE_BUFFER_DEBUGGING 来显式禁用它.
