Strands: 无需显式加锁地使用线程

strand 被定义为事件处理器的严格串行调用 (即不并发调用) . 使用 strand 可以在多线程程序中执行代码, 而无需显式加锁 (例如使用互斥量) .

strand 可以是隐式的, 也可以是显式的, 如下列几种可选方式所示:

  • 只从一个线程调用 io_context::run() 意味着所有事件处理器都在一个隐式 strand 中执行, 这是由于 io_context 保证处理器只从 run() 内部调用.
  • 当与一个连接相关联的异步操作只有单一链条时 (例如在 HTTP 这类半双工协议实现中) , 处理器不可能并发执行. 这就是隐式 strand.
  • 显式 strand 是 strand<> 或 io_context::strand 的实例. 所有事件处理器函数对象都需要使用 boost::asio::bind_executor() 绑定到 strand, 或者以其他方式通过该 strand 对象进行投递/派发.

对于组合异步操作, 例如 async_read() 或 async_read_until(), 如果某个完成处理器经由 strand, 那么所有中间处理器也应经由同一个 strand. 这是为了确保对调用方与组合操作之间共享的任何对象的线程安全访问 (就 async_read() 而言, 该对象是套接字, 调用方可以对其 close() 来取消操作) .

为此, 所有异步操作都通过 get_associated_executor 函数获取处理器的关联执行器. 例如:

boost::asio::associated_executor_t<Handler> a = boost::asio::get_associated_executor(h);

关联执行器必须满足 Executor 要求. 异步操作将使用它来提交中间处理器和最终处理器以供执行.

可以通过指定嵌套类型 executor_type 和成员函数 get_executor(), 为特定的处理器类型定制执行器:

class my_handler
{
public:
  // Custom implementation of Executor type requirements.
  typedef my_executor executor_type;

  // Return a custom executor implementation.
  executor_type get_executor() const noexcept
  {
    return my_executor();
  }

  void operator()() { ... }
};

在更复杂的情况下, 可以直接对 associated_executor 模板进行偏特化:

struct my_handler
{
  void operator()() { ... }
};

namespace boost { namespace asio {

  template <class Executor>
  struct associated_executor<my_handler, Executor>
  {
    // Custom implementation of Executor type requirements.
    typedef my_executor type;

    // Return a custom executor implementation.
    static type get(const my_handler&,
        const Executor& = Executor()) noexcept
    {
      return my_executor();
    }
  };

} } // namespace boost::asio

boost::asio::bind_executor() 函数用于将特定的执行器对象 (例如 strand) 绑定到完成处理器. 这种绑定会如上所示自动关联执行器. 例如, 要将 strand 绑定到完成处理器, 只需这样写:

my_socket.async_read_some(my_buffer,
    boost::asio::bind_executor(my_strand,
      [](error_code ec, size_t length)
      {
        // ...
      }));
