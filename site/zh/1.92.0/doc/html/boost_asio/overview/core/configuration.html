运行时配置与并发提示

Boost.Asio 提供了若干运行时配置选项, 可用于微调 Boost.Asio 的行为, 例如启用或禁用特定的优化. 可用配置选项列于下表.

小节

键

类型

默认值

说明

scheduler

assume_continuation

bool

true 若 "scheduler" / "concurrency_hint" 为 1, 否则为 false otherwise

当为 true 时, 调度器假定所有投递的处理器都表示当前正在执行的处理器的延续, 无论它们是否被显式标记为延续. 随后, 投递的处理器会被加入一个快速的线程本地队列并暂存, 直到当前正在执行的处理器结束, 然后在不唤醒任何休眠线程的情况下批量刷新.

这可以改善短时处理器的性能, 但如果某个处理器是长时运行的, 却又投递了一个期望被其他线程急切接手的处理器, 那么这一假设是不安全的.

scheduler

concurrency_hint

int

0

这是对 io_context 实现的一个建议, 指出应使用多少活动线程来运行完成处理器.

当使用 Windows I/O 完成端口后端时, 该值会被传递给 CreateIoCompletionPort.

使用基于 Reactor 的后端时, 实现会把值 1 识别为 io_context 将从单线程运行的指示, 并基于这一假设应用若干优化. 例如, 当一个处理器在另一个处理器内部被投递时, 新处理器会被加入一个快速的线程本地队列 (其后果是新处理器会被暂存, 直到当前正在执行的处理器结束) .

无论这个配置选项指定什么值, io_context 或 thread_pool 仍然提供完整的线程安全性, 而且不同的 I/O 对象可以在任何线程中使用.

scheduler

locking

bool

true

使用基于 Reactor 的后端时, 该选项用于启用或禁用调度器中的锁. 当设为 false 时, 该选项有以下限制:

—— 必须注意确保对 io_context 及其任何关联 I/O 对象 (例如套接字和定时器) 的所有操作, 一次只发生在一个线程中.

—— 异步 resolve 操作会以 operation_not_supported 失败.

—— 如果一个 signal_set 与 io_context 一起使用, 那么 signal_set 对象不能与程序中的任何其他 io_context 一起使用.

scheduler

locking_spin_count

int

0

使用基于 Reactor 的后端时, 首次尝试以非阻塞方式获取调度器内部锁的次数.

scheduler

task_usec

int

-1

调度器等待其 reactor 任务完成的最长时间, 以微秒为单位. 值为 -1 表示该等待时间没有限制. 可以设为 0 以启用 CPU 绑定的自旋.

scheduler

wait_usec

int

-1

调度器在空闲线程 (即当前没有执行处理器、也没有在 reactor 上等待的线程) 中等待其唤醒事件的最长时间, 以微秒为单位. 值为 -1 表示该等待时间没有限制. 可以设为 0, 以在多线程运行的执行上下文中启用 CPU 绑定的自旋.

reactor

preallocated_io_objects

unsigned int

0

构造时要分配的内部 reactor I/O 对象状态的数量.

reactor 实现使用每个 I/O 对象的状态来跟踪诸如未完成操作队列等信息. 这些状态对象在 I/O 对象销毁后被回收, 但如果当前没有可用的未用状态对象, 就会分配新的.

如果构造时已知 I/O 对象数量的上限, 可以设置该配置选项以确保构造完成后不再发生任何分配.

reactor

registration_locking

bool

true

启用或禁用 reactor 中围绕 I/O 对象注册与注销的锁.

如果设为 false, 必须注意不要并发地打开或关闭 I/O 对象.

reactor

registration_locking_spin_count

int

0

执行 I/O 对象注册或注销时, 首次尝试以非阻塞方式获取 reactor 锁的次数.

reactor

io_locking

bool

true

启用或禁用 reactor 中针对每个 I/O 对象的锁

如果设为 false, 必须注意确保 上的 run 函数io_context (即 run、run_for、run_until、run_one、run_one_for、run_one_until、poll 和 poll_one) 以及该上下文关联 I/O 对象 (例如套接字和定时器) 上的所有操作, 一次只发生在一个线程中.

reactor

io_locking_spin_count

int

0

首次尝试以非阻塞方式获取 reactor 的每个 I/O 对象锁的次数.

reactor

io_uring_iowait

bool

true

仅适用于 Linux io_uring 后端.

当为 true (默认值) 时, 只要存在待处理的提交队列条目 (包括用于套接字和定时器等待的条目, 而非真正的 I/O) , 阻塞等待完成的线程就会被标记为处于 iowait 状态. 当为 false 时, 这种标记会通过 io_uring_set_iowait() 抑制, 这可以避免 CPU 使用率指标虚高, 并让 CPU 进入更深的空闲状态.

需要 liburing 2.12 或更高版本才能生效; 在更早的版本上会被忽略. 底层的内核支持需要 Linux 内核 6.15 或更高版本.

reactor

io_uring_submit_batch_size

int

128

仅适用于 Linux io_uring 后端.

提交队列条目达到该数量时会被立即提交, 而不是延迟并成批提交.

reactor

io_uring_ring_count

int

1

仅适用于 Linux io_uring 后端.

单个执行上下文 (io_uring 或 io_context) 内部维护的独立 thread_pool 实例 ("ring") 的数量. 每个提交操作的线程会被分配一个 ring (轮转分配, 在该线程的生存期内保持稳定) .

当执行上下文与多个线程一起使用时, 增大该值可能改善可伸缩性.

小于 1 的值会被视为 1.

reactor

io_uring_ring_size

unsigned int

16384

仅适用于 Linux io_uring 后端.

用于设定每个 io_uring 实例大小的条目数, 会传递给 io_uring_queue_init. 更大的值允许在必须刷新提交队列条目之前有更多操作在途, 代价是每个 ring 需要锁定更多内存. 减小该值可以降低每个 ring 的内存占用, 这在 RLIMIT_MEMLOCK 限制较低的环境中可能很重要.

值为 0 时选择默认值.

reactor

reset_edge_on_partial_read

bool

false

仅适用于 Linux epoll 后端.

当为 true 时, 面向流的套接字上的部分读被视为已消耗掉边沿触发的就绪通知, 需要新的就绪边沿才能执行进一步的读操作. 当为 false (默认值) 时, 套接字被视为一直可读, 直到读操作以 EAGAIN 失败.

reactor

use_eventfd

bool

true

仅适用于 Linux epoll 后端.

当为 true 时, reactor 使用 eventfd 描述符来唤醒阻塞的 epoll_wait 调用. 当为 false 时, 改用管道.

reactor

use_timerfd

bool

true

仅适用于 Linux epoll 后端.

当为 true 时, reactor 使用 timerfd 描述符来管理超时. 当为 false 时, 会计算距离下一次超时的时长, 并作为超时值传给 epoll_wait.

timer

heap_reserve

unsigned int

0

内部定时器队列堆中预留的条目数.

如果构造时已知定时器数量的上限, 可以设置该配置选项以确保构造完成后不再发生任何定时器分配.

resolver

threads

unsigned int

0

用于异步名字解析的内部线程数量.

如果非零, 则在构造第一个 resolver 对象时创建指定数量的线程. 否则, 最多在第一次调用 async_resolve 时创建一个线程.

这些配置选项与执行上下文 (例如 io_context 或 thread_pool) 相关联. 要使用非默认值, 必须在构造时把一个配置服务安装到执行上下文中. 下文的几个小节说明了实现这一点的多种方式.

从字符串配置

要从字符串读取配置选项, 请在构造执行上下文时传入一个 config_from_string 对象:

boost::asio::io_context my_io_context{
    boost::asio::config_from_string{
      "scheduler.concurrency_hint=10\n"
      "scheduler.locking=1"}};

每个变量必须单独占一行, 形式如下:

section.key=value

或者, 如果指定了可选的前缀:

prefix.section.key=value

空行以及以 # 开头的行会被忽略. 也允许在值后面附加以 # 开头的注释.

从环境变量配置

要从环境变量读取配置选项, 请在构造执行上下文时传入一个 config_from_env 对象:

boost::asio::io_context my_io_context{
    boost::asio::config_from_env{"my_app"}};

环境变量名的构造方式是: 把前缀、小节和键用下划线作为分隔符连接起来, 然后把得到的字符串转换为全大写. 例如, 给定前缀 "my_app" 以及 "scheduler" / "concurrency_hint" option, the value is read from an environment variable named , 环境变量名就是 `BOOST_ASIO_MY_APP_SCHEDULER_CONCURRENCY_HINT`.

从并发提示配置

为了向后兼容, io_context 构造函数 可以接受一个整数形式的并发提示. 该值用于按下表所述初始化配置选项.

concurrency_hint 值

效果

n, 其中 n < 0xFFFF

等价于设置:

—— "scheduler" / "concurrency_hint" 设为 n.

—— "scheduler" / "locking" 设为 true.

—— "reactor" / "registration_locking" 设为 true.

—— "reactor" / "io_locking" 设为 true.

BOOST_ASIO_CONCURRENCY_HINT_UNSAFE

—— "scheduler" / "concurrency_hint" 设为 1.

—— "scheduler" / "locking" 设为 false.

—— "reactor" / "registration_locking" 设为 false.

—— "reactor" / "io_locking" 设为 false.

BOOST_ASIO_CONCURRENCY_HINT_UNSAFE_IO

—— "scheduler" / "concurrency_hint" 设为 1.

—— "scheduler" / "locking" 设为 true.

—— "reactor" / "registration_locking" 设为 true.

—— "reactor" / "io_locking" 设为 false.

BOOST_ASIO_CONCURRENCY_HINT_SAFE

—— "scheduler" / "concurrency_hint" 设为 0.

—— "scheduler" / "locking" 设为 true.

—— "reactor" / "registration_locking" 设为 true.

—— "reactor" / "io_locking" 设为 true.

默认构造的 io_context 对象所使用的并发提示, 可以通过定义 BOOST_ASIO_CONCURRENCY_HINT_DEFAULT 宏在编译期覆盖. 例如, 指定

-DBOOST_ASIO_CONCURRENCY_HINT_DEFAULT=1

作为编译器命令行参数, 意味着程序中所有默认构造的 1 对象都使用 io_context 的并发提示. 类似地, 以 io_context 构造的 1 对象所使用的并发提示, 可以通过定义 BOOST_ASIO_CONCURRENCY_HINT_1 来覆盖. 例如, 传入

-DBOOST_ASIO_CONCURRENCY_HINT_1=BOOST_ASIO_CONCURRENCY_HINT_UNSAFE

作为编译器参数, 将为所有这些对象禁用线程安全.

自定义配置选项

应用程序和第三方库可以利用 config 类把自己的配置选项与执行上下文关联起来, 或者访问上面列出的配置选项. 配置参数的值通过向 get 成员函数传入小节、键和默认值来访问: 

boost::asio::config cfg{ctx};
bool enable_locking = cfg.get("scheduler", "locking", true);
