处理器跟踪

为帮助调试异步程序, Boost.Asio 提供了对处理器跟踪 (handler tracking) 的支持. 通过定义 BOOST_ASIO_ENABLE_HANDLER_TRACKING 启用后, Boost.Asio 会把调试输出写入标准错误流. 输出会记录异步操作及其处理器之间的关系.

当你在调试时需要了解异步操作是如何链接在一起的, 或者当前有哪些待处理的异步操作, 这一特性非常有用. 举个例子, 下面是运行 HTTP Server 示例、处理单个请求然后通过 Ctrl+C 关闭时的输出:

每一行的形式如下:

<tag>|<timestamp>|<action>|<description>

<tag> 总是 @asio, 用于从程序输出中识别并提取处理器跟踪消息.

<timestamp> 是自 1970 年 1 月 1 日 UTC 以来的秒数和微秒数.

<action> 取以下形式之一:

>n

程序进入编号为 n 的处理器. <description> 显示传给该处理器的实参.

<n

程序离开编号为 n 的处理器.

!n

程序因异常离开编号为 n 的处理器.

~n

编号为 n 的处理器未被调用即被销毁. 当 io_context 被销毁时, 所有未完成的异步操作通常都属于这种情况.

n^m

编号为 n 的处理器即将创建一个新的异步操作, 其完成处理器编号为 m. <description> 包含源代码位置信息, 帮助确定异步操作在程序中的启动位置.

n*m

编号为 n 的处理器创建了一个新的异步操作, 其完成处理器编号为 m. <description> 显示启动的是哪个异步操作.

n

编号为 n 的处理器执行了其他操作. <description> 显示被调用的函数. 目前只记录 close() 和 cancel() 操作, 因为它们可能影响待处理异步操作的状态.

.n

实现在异步操作的过程中执行了一次系统调用, 该操作以编号为 n 的处理器作为完成处理器. <description> 显示被调用的函数及其结果. 这些跟踪事件只在基于 Reactor 的实现中发出.

当 <description> 显示同步或异步操作时, 格式为 <object-type>@<pointer>.<operation>. 对于处理器进入 (handler entry) , 它显示实参及其值的逗号分隔列表.

如上所示, 每个处理器都会被分配一个数字标识符. 当处理器跟踪输出显示处理器编号为 0 时, 表示该动作是在任何处理器之外执行的.

添加位置信息

程序可以在源代码中使用宏 BOOST_ASIO_HANDLER_LOCATION 来扩充处理器跟踪输出的位置信息. 例如:

#define HANDLER_LOCATION \
  BOOST_ASIO_HANDLER_LOCATION((__FILE__, __LINE__, __func__))

// ...

void do_read()
{
  HANDLER_LOCATION;

  auto self(shared_from_this());
  socket_.async_read_some(boost::asio::buffer(data_, max_length),
      [this, self](boost::system::error_code ec, std::size_t length)
      {
        HANDLER_LOCATION;

        if (!ec)
        {
          do_write(length);
        }
      });
}

有了这些额外的位置信息之后, 处理器跟踪输出可能包含一个由源代码位置组成的调用栈:

@asio|1589423304.861944|>7|ec=system:0,bytes_transferred=5
@asio|1589423304.861952|7^8|in 'async_write' (./../../../boost/asio/impl/write.hpp:330)
@asio|1589423304.861952|7^8|called from 'do_write' (handler_tracking/async_tcp_echo_server.cpp:62)
@asio|1589423304.861952|7^8|called from 'operator()' (handler_tracking/async_tcp_echo_server.cpp:51)
@asio|1589423304.861952|7*8|socket@0x7ff61c008230.async_send
@asio|1589423304.861975|.8|non_blocking_send,ec=system:0,bytes_transferred=5
@asio|1589423304.861980|<7|

此外, 如果 std::source_location 或 std::experimental::source_location 可用, use_awaitable_t 标记 (在默认构造或用作默认完成标记时) 还会使处理器跟踪为每个新创建的异步操作输出源代码位置. use_awaitable_t 对象也可以用位置信息显式构造.

自定义跟踪

可以通过把 BOOST_ASIO_CUSTOM_HANDLER_TRACKING 宏定义为某个头文件的名字 (用 "" 或 <> 括起来) 来定制处理器跟踪. 这个头文件必须实现以下预处理器宏:

宏

说明

BOOST_ASIO_INHERIT_TRACKED_HANDLER

为实现异步操作的类指定一个基类. 使用时, 该宏紧跟在类名之后, 因此必须具有 : public my_class 的形式.

BOOST_ASIO_ALSO_INHERIT_TRACKED_HANDLER

为实现异步操作的类指定一个基类. 使用时, 该宏位于其他基类之后, 因此必须具有 , public my_class 的形式.

BOOST_ASIO_HANDLER_TRACKING_INIT(args)

用于初始化跟踪机制的表达式.

BOOST_ASIO_HANDLER_LOCATION(args)

用于定义源代码位置的变量声明. args 是一个带括号的函数实参列表, 包含文件名、行号和函数名.

BOOST_ASIO_HANDLER_CREATION(args)

在创建异步操作时调用的表达式. args 是一个带括号的函数实参列表, 包含属主的执行上下文、被跟踪的处理器、对象类型的名称、指向对象的指针、对象的原生句柄以及操作名称.

BOOST_ASIO_HANDLER_COMPLETION(args)

在异步操作完成时调用的表达式. args 是一个带括号的函数实参列表, 包含被跟踪的处理器.

BOOST_ASIO_HANDLER_INVOCATION_BEGIN(args)

在完成处理器被调用之前立即调用的表达式. args 是一个带括号的函数实参列表, 包含传给完成处理器的各个实参.

BOOST_ASIO_HANDLER_INVOCATION_END

在完成处理器被调用之后立即调用的表达式.

BOOST_ASIO_HANDLER_OPERATION(args)

当调用某个同步对象操作 (例如 close() 或 cancel()) 时调用的表达式. args 是一个带括号的函数实参列表, 包含属主的执行上下文、对象类型的名称、指向对象的指针、对象的原生句柄以及操作名称.

BOOST_ASIO_HANDLER_REACTOR_REGISTRATION(args)

当对象在 reactor 中注册时调用的表达式. args 是一个带括号的函数实参列表, 包含属主的执行上下文、对象的原生句柄以及一个唯一的注册键.

BOOST_ASIO_HANDLER_REACTOR_DEREGISTRATION(args)

当对象从 reactor 注销时调用的表达式. args 是一个带括号的函数实参列表, 包含属主的执行上下文、对象的原生句柄以及一个唯一的注册键.

BOOST_ASIO_HANDLER_REACTOR_READ_EVENT

用于标识 reactor 读就绪事件的位掩码常量.

BOOST_ASIO_HANDLER_REACTOR_WRITE_EVENT

用于标识 reactor 写就绪事件的位掩码常量.

BOOST_ASIO_HANDLER_REACTOR_ERROR_EVENT

用于标识 reactor 错误就绪事件的位掩码常量.

BOOST_ASIO_HANDLER_REACTOR_EVENTS(args)

当在 reactor 中注册的对象变为就绪时调用的表达式. args 是一个带括号的函数实参列表, 包含属主的执行上下文、唯一注册键以及就绪事件的位掩码.

BOOST_ASIO_HANDLER_REACTOR_OPERATION(args)

当实现作为基于 Reactor 的异步操作的一部分而执行系统调用时调用的表达式. args 是一个带括号的函数实参列表, 包含被跟踪的处理器、操作名称、操作产生的错误码, 以及 (可选的) 已传输字节数.
