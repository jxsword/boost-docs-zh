流、短读与短写

Boost.Asio 中的许多 I/O 对象都是面向流的. 这意味着:

  • 没有消息边界. 被传输的数据是连续的字节序列.
  • 读或写操作传输的字节数可能少于请求的数量. 这称为短读 (short read) 或短写 (short write) .

提供面向流 I/O 的对象实现以下一项或多项类型要求:

  • SyncReadStream, 其同步读操作通过名为 read_some() 的成员函数执行.
  • AsyncReadStream, 其异步读操作通过名为 async_read_some() 的成员函数执行.
  • SyncWriteStream, 其同步写操作通过名为 write_some() 的成员函数执行.
  • AsyncWriteStream, 其异步写操作通过名为 async_write_some() 的成员函数执行.

面向流的 I/O 对象的例子包括 ip::tcp::socket、ssl::stream<>、posix::stream_descriptor、windows::stream_handle 等.

程序通常希望传输确切数量的字节. 当发生短读或短写时, 程序必须重新启动该操作, 并持续这样做, 直到所需的字节数传输完毕. Boost.Asio 提供了自动完成这一工作的通用函数: read()、async_read()、write() 和 async_write().

为什么 EOF 是错误
  • 流的末端可能导致 read、async_read、read_until 或 async_read_until 函数违反其契约. 例如, 对 N 字节的读取可能因 EOF 而提前结束.
  • EOF 错误可用于区分流的末端与长度为 0 的成功读取.
