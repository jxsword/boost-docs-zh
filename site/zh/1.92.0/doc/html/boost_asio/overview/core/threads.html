线程与 Boost.Asio

线程安全

一般而言, 对不同对象的并发使用是安全的, 但对单个对象的并发使用则不安全. 不过, 诸如 io_context 这样的类型提供了更强的保证: 并发使用单个对象是安全的.

线程池

多个线程可以调用 io_context::run() 来建立一个线程池, 完成处理器可以从中被调用. 这种方法也可与 post() 一起使用, 作为在线程池中执行任意计算任务的一种手段.

注意, 所有已加入某个 io_context 线程池的线程都被视为等同的, io_context 可以以任意方式在这些线程之间分配工作.

内部线程

本库在特定平台上的实现可能会使用一个或多个内部线程来模拟异步性. 这些线程必须尽可能地让库的使用者感觉不到. 特别地, 这些线程:

  • 不得直接调用用户的代码; 并且
  • 必须阻塞所有信号.

这种方法由以下保证作为补充:

  • 异步完成处理器只会从当前正在调用 io_context::run() 的线程中被调用.

因此, 创建和管理所有接收通知的线程是库使用者的责任.

采用这种方法的原因包括:

  • 只从单个线程调用 io_context::run() 时, 用户的代码可以避免与同步相关的开发复杂度. 例如, 库使用者可以实现 (从用户的角度看) 单线程的可扩展服务器.
  • 库使用者可能需要在线程启动后不久、任何其他应用代码执行之前, 在该线程中执行初始化. 例如, Microsoft COM 的使用者必须先调用 CoInitializeEx, 然后才能从该线程调用任何其他 COM 操作.
  • 库接口与线程创建和管理的接口解耦, 从而允许在没有线程可用的平台上实现.
