关联特征与关联器

异步代理具有 关联特征, 它们规定当异步操作作为该代理的一部分进行组合时应如何表现, 例如:

  • 分配器, 它决定代理的异步操作如何获取内存资源.
  • 取消槽, 它决定代理的异步操作如何支持取消.
  • 执行器, 它决定代理的完成处理器如何排队和运行.

当异步操作在异步代理中运行时, 其实现可以查询这些关联特征, 并使用它们来满足其代表的要求或偏好. 异步操作通过将 关联器 特征应用于完成处理器来执行这些查询. 每个特征都有对应的关联器特征.

可以为具体的完成处理器类型特化关联器特征, 以便:

  • 接受异步操作提供的默认特征, 并原样返回该默认值
  • 返回该特征的一个无关实现, 或者
  • 对提供的默认值进行适配, 以引入完成处理器所需的额外行为.
关联器的规范

给定名为[2] associated_R 的关联器特征, 它具有:

  • 一个源值 s, 其类型为 S——在本例中即完成处理器及其类型,
  • 一组类型要求 (或一个 concept) R, 它们定义关联特征的语法和语义要求, 以及
  • 一个候选值 c, 其类型为 C, 满足类型要求 R——它代表关联特征的一个默认实现, 由异步操作提供

异步操作使用该关联器特征计算:

  • 类型 associated_R<S, C>::type, 以及
  • 值 associated_R<S, C>::get(s, c)

它们满足 R 中定义的要求. 为方便起见, 它们也可以分别通过类型别名 associated_R_t<S, C> 和自由函数 get_associated_R(s, c) 访问.

该特征的主模板被规定为:

  • 若 S::R_type 合式, 则定义嵌套类型别名 type 为 S::R_type, 并定义静态成员函数 get, 返回 s.get_R()
  • 否则, 若 associator<associated_R, S, C>::type 合式且表示一个类型, 则继承自 associator<associated_R, S, C>
  • 否则, 定义嵌套类型别名 type 为 C, 并定义静态成员函数 get, 返回 c.

[2] 关联器特征名为 associated_allocator、associated_executor 和 associated_cancellation_slot.
