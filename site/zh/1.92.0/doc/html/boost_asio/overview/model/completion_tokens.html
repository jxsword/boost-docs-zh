完成标记

Boost.Asio 异步模型的一个关键目标是支持多种组合机制. 这是通过 完成标记 实现的: 用户把完成标记传递给异步操作的发起函数, 以定制库的 API 表面. 按照约定, 完成标记是异步操作发起函数的最后一个参数.

例如, 如果用户传递一个 lambda (或其他函数对象) 作为完成标记, 异步操作的行为如前所述: 操作开始, 当操作完成时结果被传递给该 lambda.

socket.async_read_some(buffer,
    [](error_code e, size_t)
    {
      // ...
    }
  );

当用户传递 use_future 完成标记时, 操作表现得如同以 promise 和 future 对来实现. 发起函数不仅启动操作, 还返回一个可用于等待结果的 future.

future<size_t> f =
  socket.async_read_some(
      buffer, use_future
    );
// ...
size_t n = f.get();

类似地, 当用户传递 use_awaitable 完成标记时, 发起函数表现得如同一个基于 awaitable 的协程 [6]. 然而在这种情况下, 发起函数并不直接启动异步操作. 它只返回 awaitable, 后者在被 co_await 时才启动操作.

awaitable<void> foo()
{
  size_t n =
    co_await socket.async_read_some(
        buffer, use_awaitable
      );

  // ...
}

最后, yield_context 完成标记使发起函数在有栈协程的上下文中表现为同步操作. 它不仅启动异步操作, 还会阻塞该有栈协程直至操作完成. 从有栈协程的角度看, 它就是同步操作.

void foo(boost::asio::yield_context yield)
{
  size_t n = socket.async_read_some(buffer, yield);

  // ...
}

所有这些用法都由 async_read_some 发起函数的单一实现所支持.

为做到这一点, 异步操作必须先指定一个 完成签名 (或可能的多个签名) , 描述将传递给其完成处理器的参数.

然后, 操作的发起函数取得完成签名、完成标记及其内部实现, 并把它们传给 async_result 特征. async_result 特征是一个定制点, 它把这些内容组合起来, 先产生一个具体的完成处理器, 然后启动操作.

为了在实践中看到这一点, 让我们用一个分离的线程把同步操作适配成异步操作: [7] 

template <
    completion_token_for<void(error_code, size_t)> 
      CompletionToken>
auto async_read_some(
    tcp::socket& s,
    const mutable_buffer& b,
    CompletionToken&& token)
{
  auto init = []( 
      auto completion_handler,
      tcp::socket* s,
      const mutable_buffer& b)
  {
    std::thread( 
        [](
            auto completion_handler,
            tcp::socket* s,
            const mutable_buffer& b
          )
        {
          error_code ec;
          size_t n = s->read_some(b, ec);
          std::move(completion_handler)(ec, n); 
        },
        std::move(completion_handler),
        s,
        b
      ).detach();
  };

  return async_result< 
      decay_t<CompletionToken>,
      void(error_code, size_t)
    >::initiate(
        init, 
        std::forward<CompletionToken>(token), 
        &s, 
        b
      );
}

completion_token_for concept 检查用户提供的完成标记是否将满足指定的完成签名. 对于较旧版本的 C++, 这里只需改用 typename.

定义一个函数对象, 其中包含启动异步操作的代码. 它接收具体的完成处理器, 随后是通过 async_result 特征传入的任何附加参数.

函数对象的函数体派生一个新线程来执行该操作.

一旦操作完成, 完成处理器会收到结果.

async_result 特征被传入 (衰减后的) 完成标记类型, 以及异步操作的完成签名.

调用该特征的 initiate 成员函数, 首先传入启动操作的函数对象.

接下来是转发的完成标记. 特征实现会把它转换成具体的完成处理器.

最后, 传入函数对象的任何附加参数. 假定这些参数可能被特征实现衰减拷贝并移动.

在实践中, 我们应当调用 async_initiate 辅助函数, 而不是直接使用 async_result 特征. async_initiate 函数会自动完成对完成标记的必要衰减和转发, 同时提供对旧式完成标记实现的向后兼容.

template <
    completion_token_for<void(error_code, size_t)>
      CompletionToken>
auto async_read_some(
    tcp::socket& s,
    const mutable_buffer& b,
    CompletionToken&& token)
{
  auto init = /* ... as above ... */;

  return async_initiate<
      CompletionToken,
      void(error_code, size_t)
    >(init, token, &s, b);
}

我们可以把完成标记看作一种原型完成处理器. 当我们传递一个函数对象 (如 lambda) 作为完成标记时, 它已经满足完成处理器要求. async_result 主模板通过简单地透传参数来处理这种情况:

template <class CompletionToken, completion_signature... Signatures>
struct async_result
{
  template <
      class Initiation,
      completion_handler_for<Signatures...> CompletionHandler,
      class... Args>
  static void initiate(
      Initiation&& initiation,
      CompletionHandler&& completion_handler,
      Args&&... args)
  {
    std::forward<Initiation>(initiation)(
        std::forward<CompletionHandler>(completion_handler),
        std::forward<Args>(args)...);
  }
};

我们可以看到, 这个默认实现避免了所有参数的拷贝, 从而确保急切发起尽可能高效.

另一方面, 懒惰的完成标记 (例如上文中的 use_awaitable) 可以捕获这些参数, 以便延迟启动操作. 例如, 针对平凡的 deferred 标记 (它只是把操作打包以备后用) 的一个特化可能看起来像这样:

template <completion_signature... Signatures>
struct async_result<deferred_t, Signatures...>
{
  template <class Initiation, class... Args>
  static auto initiate(Initiation initiation, deferred_t, Args... args)
  {
    return [
        initiation = std::move(initiation),
        arg_pack = std::make_tuple(std::move(args)...)
      ](auto&& token) mutable
    {
      return std::apply(
          [&](auto&&... args)
          {
            return async_result<decay_t<decltype(token)>, Signatures...>::initiate(
                std::move(initiation),
                std::forward<decltype(token)>(token),
                std::forward<decltype(args)>(args)...
              );
          },
          std::move(arg_pack)
        );
    };
  }
};

[6] awaitable 类模板随 Boost.Asio 库一起提供, 作为 C++20 协程的返回类型. 这些协程可以轻易地以其他基于 awaitable 的协程来实现.

[7] 仅为说明之用. 不建议在真实场景中使用!
