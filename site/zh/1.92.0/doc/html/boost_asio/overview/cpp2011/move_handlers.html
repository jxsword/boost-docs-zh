可移动处理器

在 C++11 及更高版本中, 用户定义的完成处理器只要求可移动构造, 不要求可拷贝构造.

启用移动支持后, 文档形式如下的异步操作:

template <typename Handler>
void async_XYZ(..., Handler handler);

实际上声明为:

template <typename Handler>
void async_XYZ(..., Handler&& handler);

处理器参数被完美转发, 移动构造发生在 async_XYZ() 的函数体内. 这确保所有其他函数实参都在移动之前完成求值. 当 async_XYZ() 的其他实参是处理器的成员时, 这一点至关重要. 例如:

struct my_operation
{
  unique_ptr<tcp::socket> socket;
  unique_ptr<vector<char>> buffer;
  ...
  void operator(error_code ec, size_t length)
  {
    ...
    socket->async_read_some(boost::asio::buffer(*buffer), std::move(*this));
    ...
  }
};

移动支持会在 g++ 4.5 及更高版本中自动启用 (使用 -std=c++0x 或 -std=gnu++0x 编译器选项时) . 可以通过定义 BOOST_ASIO_DISABLE_MOVE 将其禁用, 或通过定义 BOOST_ASIO_HAS_MOVE 为其他编译器显式启用. 注意, 这些宏也影响 可移动 I/O 对象 的可用性.
