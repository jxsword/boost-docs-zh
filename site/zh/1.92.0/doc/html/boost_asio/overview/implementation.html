平台特定的实现说明

本节列出平台特定的实现细节, 例如默认的多路分用机制、内部创建的线程数量, 以及线程何时创建.

Linux Kernel 2.4

多路分用机制:

  • 使用 select 进行多路分用. 这意味着进程中文件描述符的数量不允许超过 FD_SETSIZE.

线程:

  • 使用 select 进行的多路分用, 在调用 io_context::run()、io_context::run_one()、io_context::poll() 或 io_context::poll_one() 的某个线程中执行.
  • 每个 io_context 使用一个或多个额外线程来模拟异步主机解析. 默认只创建一个线程, 但可以通过 "resolver" / "threads" 配置选项 改变这一行为.

分散-聚集:

  • 单次操作最多可传输 min(64,IOV_MAX) 个缓冲区.

Linux Kernel 5.10

多路分用机制:

  • 如果定义了 BOOST_ASIO_HAS_IO_URING, 则对与文件相关的异步操作使用 io_uring.
  • 使用 epoll 对其他事件源进行多路分用.
  • 可选择对所有异步操作使用 io_uring, 条件是在定义 BOOST_ASIO_HAS_IO_URING 之外, 还定义 BOOST_ASIO_DISABLE_EPOLL 以禁用 epoll.

线程:

  • 使用 epoll 和 io_uring 进行的多路分用, 在调用 io_context::run()、io_context::run_one()、io_context::poll() 或 io_context::poll_one() 的某个线程中执行.
  • 每个 io_context 使用一个或多个额外线程来模拟异步主机解析. 默认只创建一个线程, 但可以通过 "resolver" / "threads" 配置选项 改变这一行为.

分散-聚集:

  • 单次操作最多可传输 min(64,IOV_MAX) 个缓冲区.

Windows 95, 98 和 Me

多路分用机制:

  • 使用 select 进行多路分用.

Windows NT, 2000, XP, 2003, Vista, 7, 8, 10 和 11

多路分用机制:

  • 对所有异步套接字操作使用重叠 I/O 和 I/O 完成端口, 异步连接除外.
  • 使用 select 模拟异步连接.

线程:

  • 使用 I/O 完成端口进行的多路分用, 在调用 io_context::run()、io_context::run_one()、io_context::poll() 或 io_context::poll_one() 的所有线程中执行.
  • 每个 io_context 使用一个额外的线程来触发定时器. 该线程在构造第一个 basic_deadline_timer 或 basic_waitable_timer 对象时创建.
  • 每个 io_context 可能会使用一个额外的线程进行 select 多路分用. 该线程在第一次调用以下内容时创建:
    • 套接字 async_wait() 函数, 但在面向流的套接字上使用 wait_read 时除外. (对于面向流套接字上的 wait_read, 会使用重叠 I/O 操作 WSARecv, 不需要额外的线程. )
    • 套接字 async_connect() 操作, 当重叠 I/O 操作 ConnectEx 不可用时. (在近期版本的 Windows 上, 会使用 ConnectEx, 不需要额外的线程. )
  • 每个 io_context 使用一个或多个额外线程来模拟异步主机解析. 默认只创建一个线程, 但可以通过 "resolver" / "threads" 配置选项 改变这一行为.

分散-聚集:

  • 对于套接字, 单次操作最多可传输 64 个缓冲区.
  • 对于面向流的句柄, 单次操作只能传输一个缓冲区.
Windows Runtime

Boost.Asio 对 Windows Runtime 提供有限的支持. 它要求启用语言扩展. 由于 Windows Runtime API 暴露的设施受限, 该支持带有以下注意事项:

  • 诸如 io_context、strand、缓冲区、组合操作、定时器等核心设施都应能正常工作.
  • 对于套接字, 仅支持客户端 TCP.
  • 不支持客户端 TCP 套接字的显式绑定.
  • 套接字不支持 cancel() 函数. 异步操作只能通过关闭套接字来取消.
  • 不支持使用 null_buffers 的操作.
  • 仅支持 tcp::no_delay 与 socket_base::keep_alive 选项.
  • 解析器不支持服务名, 只支持编号. 也就是说, 必须使用"80"而不是"http".
  • 大多数解析器查询标志都不起作用.

多路分用机制:

  • 使用 Windows::Networking::Sockets::StreamSocket 类来实现异步 TCP 套接字操作.

线程:

  • 事件完成会被交付到 Windows 线程池, 并投递到 io_context 以便执行处理器.
  • 每个 io_context 使用一个额外的线程来触发定时器. 该线程在构造第一个定时器对象时创建.

分散-聚集:

  • 对于套接字, 单次操作最多可传输一个缓冲区.
