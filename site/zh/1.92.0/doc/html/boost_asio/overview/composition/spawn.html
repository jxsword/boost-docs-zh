有栈协程

spawn() 函数是运行有栈协程的高层封装. 它基于 Boost.Coroutine 库. spawn() 函数使程序能够以同步的方式实现异步逻辑, 如下例所示:

boost::asio::spawn(my_strand, do_echo, boost::asio::detached);

// ...

void do_echo(boost::asio::yield_context yield)
{
  try
  {
    char data[128];
    for (;;)
    {
      std::size_t length =
        my_socket.async_read_some(
          boost::asio::buffer(data), yield);

      boost::asio::async_write(my_socket,
          boost::asio::buffer(data, length), yield);
    }
  }
  catch (std::exception& e)
  {
    // ...
  }
}

传给 spawn() 的第一个实参可以是执行器或执行上下文. 这个实参决定协程被允许执行的上下文. 例如, 服务器的每个客户端对象可能由多个协程组成; 它们应当都运行在同一个 strand 上, 这样就无需显式同步.

第二个实参是一个具有如下签名的函数对象:

void coroutine(boost::asio::yield_context yield);

它指定作为协程一部分运行的代码. 参数 yield 可以代替完成处理器传给异步操作, 如下所示:

std::size_t length =
  my_socket.async_read_some(
    boost::asio::buffer(data), yield);

这会启动异步操作并挂起协程. 当异步操作完成时, 协程会被自动恢复.

当异步操作的处理器签名具有如下形式时:

void handler(boost::system::error_code ec, result_type result);

发起函数返回 result_type. 在上面的 async_read_some 示例中, 它就是 size_t. 如果异步操作失败, error_code 会被转换为一个 system_error 异常并抛出.

当处理器签名具有如下形式时:

void handler(boost::system::error_code ec);

发起函数返回 void. 如上所述, 错误会以 system_error 异常的形式传回协程.

要从操作中收集 error_code 而不是让它抛出异常, 可按如下方式把输出变量与 yield_context 关联:

boost::system::error_code ec;
std::size_t length =
  my_socket.async_read_some(
    boost::asio::buffer(data), yield[ec]);

注意: 如果 spawn() 与一个指定为 Executor 类型的执行器一起使用, 那么函数对象签名实际上是:

void coroutine(boost::asio::basic_yield_context<Executor> yield);
