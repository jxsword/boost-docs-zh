作为异步操作的组合

应用程序开发者可能希望将自己的组合封装为符合 异步操作 要求的形式, 纳入 异步模型 之中. 这样做有助于将这些操作与 Boost.Asio 已提供的操作无缝地组合起来.

虽然这些操作可以从零开始编写以满足 对异步操作的要求, 但 Boost.Asio 提供了 async_compose 函数来简化这一过程. async_compose 实现会自动提供一个中间完成处理器, 它正确地传播 关联特征, 并针对 I/O 执行器和完成执行器跟踪未完成的工作.

下面的示例展示了一个异步 echo 循环 (即先读、再写, 如此往复) , 以一个简单状态机的形式表达.

struct async_echo_implementation
{
  tcp::socket& socket_;
  boost::asio::mutable_buffer buffer_;
  enum { starting, reading, writing } state_;

  template <typename Self>
  void operator()(Self& self,
      boost::system::error_code error = {},
      std::size_t n = 0)
  {
    switch (state_)
    {
    case starting:
      state_ = reading;
      socket_.async_read_some(
          buffer_, std::move(self));
      break;
    case reading:
      if (error)
      {
        self.complete(error, 0);
      }
      else
      {
        state_ = writing;
        boost::asio::async_write(socket_, buffer_,
            boost::asio::transfer_exactly(n),
            std::move(self));
      }
      break;
    case writing:
      self.complete(error, n);
      break;
    }
  }
};

然后在一个发起函数中使用该实现, 该函数只是简单地对 async_compose 进行了包装:

template <typename CompletionToken>
auto async_echo(tcp::socket& socket,
    boost::asio::mutable_buffer buffer,
    CompletionToken&& token) ->
  typename boost::asio::async_result<
    typename std::decay<CompletionToken>::type,
      void(boost::system::error_code, std::size_t)>::return_type
{
  return boost::asio::async_compose<CompletionToken,
    void(boost::system::error_code, std::size_t)>(
      async_echo_implementation{socket, buffer,
        async_echo_implementation::starting},
      token, socket);
}

这里, async_compose 首先被传入一个函数对象, 该函数对象包含这个组合异步操作的实现. 传给该函数对象的第一个实参是对外层中间完成处理器的非 const 引用. 其余实参则是来自该实现所执行的任何异步操作的完成处理器的各个实参.

async_compose 函数还会被传入完成标记, 以及零个或多个需要为其维持未完成工作的 I/O 对象或 I/O 执行器.
