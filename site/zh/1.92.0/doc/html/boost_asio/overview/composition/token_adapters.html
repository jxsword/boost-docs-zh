完成标记适配器

完成标记适配器 (completion token adapter) 是一种可以泛型地应用于 完成标记 的工具, 用于产生一个行为经过修改的新完成标记. 完成标记适配器的常见用途包括:

  • 自动包装完成处理器, 以添加 关联特征.
  • 变换完成签名以及传递给完成处理器的各个参数.

Boost.Asio 包含若干完成标记适配器, 如下所述.

bind_executor、bind_allocator、bind_cancellation_slot 与 bind_immediate_executor

bind_executor 函数可对一个完成标记进行适配, 为完成处理器注入一个 关联执行器.

这个例子展示了将 bind_executor 适配器应用于一个 lambda, 以指定处理器应在指定的 strand 中执行. 传递给完成处理器的参数原样透传.

my_socket.async_read_some(my_buffer,
    boost::asio::bind_executor(my_strand,
      [](boost::system::error_code error, std::size_t bytes_transferred)
      {
        // ...
      }));

当应用于会使发起函数产生结果的完成标记 (例如 use_awaitable) 时, 结果将不加修改地返回.

boost::asio::awaitable<void> my_coroutine()
{
  // ...
  std::size_t bytes_transferred =
    co_await my_socket.async_read_some(my_buffer,
      boost::asio::bind_executor(my_strand, boost::asio::use_awaitable));
  // ...
}

bind_allocator、bind_cancellation_slot 和 bind_immediate_executor 这几个适配器的工作方式类似, 分别为完成处理器注入 关联分配器、关联取消槽 以及关联立即执行器.

redirect_error

redirect_error 函数可对一个完成标记进行适配, 把操作产生的 error_code 捕获到指定的变量中. 在此过程中, 它会修改完成签名, 移除最初的 error_code 参数.

这个例子展示了将 redirect_error 适配器应用于一个 lambda, 以指定错误应被捕获到 my_error 中. error_code 不再传递给完成处理器, 但其余参数原样透传.

boost::system::error_code my_error; // N.B. must be valid until operation completes
// ...
my_socket.async_read_some(my_buffer,
    boost::asio::redirect_error(
      [](std::size_t bytes_transferred)
      {
        // ...
      }, my_error));

当应用于会使发起函数产生结果的完成标记 (例如 use_awaitable) 时, 结果将不加修改地返回. 但是, 如果操作失败, co_await 表达式在恢复时将不再抛出异常.

boost::asio::awaitable<void> my_coroutine()
{
  // ...
  boost::system::error_code my_error;
  std::size_t bytes_transferred =
    co_await my_socket.async_read_some(my_buffer,
      boost::asio::redirect_error(boost::asio::use_awaitable, my_error));
  // ...
}
redirect_disposition

redirect_disposition 函数可对一个完成标记进行适配, 把操作产生的任何 处置 (disposition) 捕获到指定的变量中. 在此过程中, 它会修改完成签名, 移除最初的处置参数.

这个例子展示了将 redirect_disposition 适配器应用于一个 lambda, 以指定处置应被捕获到 my_exception 中. error_code (它是一个处置类型) 不再传递给完成处理器, 但其余参数原样透传.

std::exception_ptr my_exception; // N.B. must be valid until operation completes
// ...
my_socket.async_read_some(my_buffer,
    boost::asio::redirect_disposition(
      [](std::size_t bytes_transferred)
      {
        // ...
      }, my_exception));

当应用于会使发起函数产生结果的完成标记 (例如 use_awaitable) 时, 结果将不加修改地返回. 但是, 如果操作失败, co_await 表达式在恢复时将不再抛出异常.

boost::asio::awaitable<void> my_coroutine()
{
  // ...
  std::exception_ptr my_exception;
  std::size_t bytes_transferred =
    co_await my_socket.async_read_some(my_buffer,
      boost::asio::redirect_disposition(boost::asio::use_awaitable, my_exception));
  // ...
}
as_tuple

as_tuple 适配器可用于指定把完成处理器的各个参数合并成单个元组实参.

例如, as_tuple 适配器可以与 use_awaitable 和结构化绑定配合使用, 如下所示:

auto [e, n] =
  co_await my_socket.async_read_some(my_buffer,
    boost::asio::as_tuple(boost::asio::use_awaitable));

这个适配器还可以用作默认完成标记:

using default_token = boost::asio::as_tuple_t<boost::asio::use_awaitable_t<>>;
using tcp_socket = default_token::as_default_on_t<tcp::socket>;
// ...
boost::asio::awaitable<void> do_read(tcp_socket my_socket)
{
  // ...
  auto [e, n] = co_await my_socket.async_read_some(my_buffer);
  // ...
}
as_single
注释

这是一项实验性特性.

experimental::as_single 适配器可用于指定把完成处理器的各个参数合并成单个实参. 对于只有一个参数的完成签名, 该实参原样透传. 对于有两个或更多参数的签名, 各参数被合并成一个元组.

例如, 当应用于定时器 wait 操作时, 单个的 error_code 实参会直接传递给完成处理器:

my_timer.async_wait(
    boost::asio::experimental::as_single(
      [](boost::system::error_code error)
      {
        // ...
      }));

当应用于套接字读操作 (其完成签名指定两个参数) 时, 结果会以元组的形式传递给处理器:

my_socket.async_read_some(my_buffer,
    boost::asio::experimental::as_single,
      [](std::tuple<boost::system::error_code, std::size_t> result)
      {
        // ...
      }));
append

append 完成标记适配器可用于在完成签名的末尾附加额外的完成处理器参数.

例如:

timer.async_wait(
    boost::asio::append(
      [](boost::system::error_code ec, int i)
      {
        // ...
      },
      42
    )
  );

std::future<int> f = timer.async_wait(
    boost::asio::append(
      boost::asio::use_future,
      42
    )
  );
prepend

prepend 完成标记适配器可用于在既有完成处理器参数之前传递额外的完成处理器参数.

例如:

timer.async_wait(
    boost::asio::prepend(
      [](int i, boost::system::error_code ec)
      {
        // ...
      },
      42
    )
  );

std::future<std::tuple<int, boost::system::error_code>> f = timer.async_wait(
    boost::asio::prepend(
      boost::asio::use_future,
      42
    )
  );
consign

consign 完成标记适配器可用于把额外的值附加到完成处理器上. 这通常用于确保某个对象 (例如智能指针) 在完成处理器被调用之前始终至少保有一份副本.

例如:

auto timer1 = std::make_shared<boost::asio::steady_timer>(my_io_context);
timer1->expires_after(std::chrono::seconds(1));
timer1->async_wait(
    boost::asio::consign(
      [](boost::system::error_code ec)
      {
        // ...
      },
      timer1
    )
  );

auto timer2 = std::make_shared<boost::asio::steady_timer>(my_io_context);
timer2->expires_after(std::chrono::seconds(30));
std::future<void> f =
  timer2->async_wait(
    boost::asio::consign(
      boost::asio::use_future,
      timer2
    )
  );
参见
