C++20 协程支持

C++20 协程的支持通过 awaitable 类模板、use_awaitable 完成标记以及 co_spawn() 函数提供. 借助这些设施, 程序可以配合 co_await 关键字, 以同步的方式实现异步逻辑, 如下例所示:

boost::asio::co_spawn(executor, echo(std::move(socket)), boost::asio::detached);

// ...

boost::asio::awaitable<void> echo(tcp::socket socket)
{
  try
  {
    char data[1024];
    for (;;)
    {
      std::size_t n = co_await socket.async_read_some(boost::asio::buffer(data));
      co_await async_write(socket, boost::asio::buffer(data, n));
    }
  }
  catch (std::exception& e)
  {
    std::printf("echo Exception: %s\n", e.what());
  }
}

传给 co_spawn() 的第一个实参是一个 执行器, 它决定协程被允许执行的上下文. 例如, 服务器的每个客户端对象可能由多个协程组成; 它们应当都运行在同一个 strand 上, 这样就无需显式同步.

第二个实参是一个 awaitable<R>, 即协程入口点函数的结果; 在上面的例子中, 它就是调用 echo 的结果. (此外, 这个实参也可以是一个返回 awaitable<R> 的函数对象. ) 模板参数 R 是协程产生的返回值的类型. 在上面的例子中, 协程返回 void.

第三个实参是一个完成标记, co_spawn() 会用它生成一个具有签名 void(std::exception_ptr, R) 的完成处理器. 协程结束后, 将以协程的结果调用该完成处理器. 在上面的例子中, 我们传入完成标记类型 boost::asio::detached, 用于显式忽略异步操作的结果.

在这个例子中, 协程体在 echo 函数中实现. 当调用异步操作而未显式指定完成标记时, 将使用默认完成标记 deferred. 这使得操作的发起函数返回一个延迟异步操作对象, 该对象可与 co_await 关键字配合使用:

std::size_t n = co_await socket.async_read_some(boost::asio::buffer(data));

或者, 我们也可以显式指定 use_awaitable 完成标记:

std::size_t n = co_await socket.async_read_some(boost::asio::buffer(data), boost::asio::use_awaitable);

使用这两种完成标记中的任意一种时, 当异步操作的处理器签名具有如下形式:

void handler(boost::system::error_code ec, result_type result);

表达式的结果类型为 co_await. 在上面的 result_type 示例中, 它就是 async_read_some. 如果异步操作失败, size_t 会被转换为一个 error_code 异常并抛出system_error.

当处理器签名具有如下形式时:

void handler(boost::system::error_code ec);

co_await 表达式产生一个 void 结果. 如上所述, 错误会以 system_error 异常的形式传回协程.

错误处理

要执行显式的错误处理 (而非默认的抛异常行为) , 可以使用 as_tuple、redirect_disposition 或 redirect_error 完成标记适配器.

as_tuple 完成标记适配器会把完成处理器的各个参数打包成一个元组, 然后作为被等待操作的结果返回. 例如:

boost::asio::awaitable<void> echo(tcp::socket socket)
{
  char data[1024];
  for (;;)
  {
    std::tuple<boost::system::error_code, std::size_t> result =
      co_await socket.async_read_some(
        boost::asio::buffer(data), boost::asio::as_tuple);
    if (!std::get<0>(result))
    {
      // success
    }

    // ...
  }
}

或者在显式指定 use_awaitable 完成标记的情况下:

boost::asio::awaitable<void> echo(tcp::socket socket)
{
  char data[1024];
  for (;;)
  {
    std::tuple<boost::system::error_code, std::size_t> result =
      co_await socket.async_read_some(boost::asio::buffer(data),
        boost::asio::as_tuple(boost::asio::use_awaitable));
    if (!std::get<0>(result))
    {
      // success
    }

    // ...
  }
}

结果也可以直接捕获到结构化绑定中:

boost::asio::awaitable<void> echo(tcp::socket socket)
{
  char data[1024];
  for (;;)
  {
    auto [ec, n] = co_await socket.async_read_some(
        boost::asio::buffer(data), boost::asio::as_tuple);
    if (!ec)
    {
      // success
    }

    // ...
  }
}

或者, 可以使用 redirect_error 完成标记适配器把错误捕获到一个给定的 error_code 变量中:

boost::asio::awaitable<void> echo(tcp::socket socket)
{
  char data[1024];
  for (;;)
  {
    boost::system::error_code ec;
    std::size_t n = co_await socket.async_read_some(
        boost::asio::buffer(data), boost::asio::redirect_error(ec));
    if (!ec)
    {
      // success
    }

    // ...
  }
}
协程与按操作取消

由 co_spawn 创建的所有执行线程都拥有一个取消状态, 它记录针对该协程发出的任何取消请求的当前状态. 要访问这一状态, 可按如下方式使用 this_coro::cancellation_state:

boost::asio::awaitable<void> my_coroutine()
{
  boost::asio::cancellation_state cs
    = co_await boost::asio::this_coro::cancellation_state;

  // ...

  if (cs.cancelled() != boost::asio::cancellation_type::none)
    // ...
}

当最初由 co_spawn 创建时, 执行线程的取消状态仅支持 cancellation_type::terminal 值. 要更改取消状态, 请调用 this_coro::reset_cancellation_state.

默认情况下, 被取消的协程若继续执行, 后续任何对 co_await 对象的 awaitable<> 都会触发异常. 这一行为可以通过使用 this_coro::throw_if_cancelled 来改变.

协调并行的协程
注释

这是一项实验性特性.

逻辑运算符 || 和 && 已针对 awaitable<> 进行了重载, 以便多个协程能够以简单的方式并行等待.

当使用 && 等待时, co_await 表达式会等待直到两个操作都成功完成. 作为一种"短路"求值, 如果一个操作因异常而失败, 另一个操作会立即被取消. 例如:

std::tuple<std::size_t, std::size_t> results =
  co_await (
    async_read(socket, input_buffer, use_awaitable)
      && async_write(socket, output_buffer, use_awaitable)
  );

在 && 操作完成之后, 所有操作的结果会被串接成一个元组. 在上面的例子中, 第一个 size_t 表示 async_read 结果的非异常部分, 第二个 size_t 则是 async_write 的结果.

当使用 || 等待时, co_await 表达式会等待直到其中任一操作成功. 作为一种"短路"求值, 如果一个操作成功而未抛出异常, 另一个操作会立即被取消. 例如:

std::variant<std::size_t, std::monostate> results =
  co_await (
    async_read(socket, input_buffer, use_awaitable)
      || timer.async_wait(use_awaitable)
  );

在 || 操作完成之后, 第一个以非异常方式完成的操作的结果会被放入一个 std::variant 中. variant 的当前活动索引反映哪个操作最先完成. 在上面的例子中, 索引 0 对应于 async_read 操作.

这些运算符可以通过添加 #include 来启用:

#include <boost/asio/experimental/awaitable_operators.hpp>

然后将 experimental::awaitable_operators 命名空间的内容引入作用域:

using namespace boost::asio::experimental::awaitable_operators;

注意: 要使用这些运算符, 我们必须显式指定 use_awaitable 完成标记.

以轻量级协程实现异步操作

co_composed 模板支持使用 C++20 协程以轻量级方式实现用户自定义的异步操作. 下面的示例展示了一个以协程实现 echo 协议的简单异步操作:

template <typename CompletionToken>
auto async_echo(tcp::socket& socket,
    CompletionToken&& token)
{
  return boost::asio::async_initiate<
    CompletionToken, void(boost::system::error_code)>(
      boost::asio::co_composed<
        void(boost::system::error_code)>(
          [](auto state, tcp::socket& socket) -> void
          {
            try
            {
              state.throw_if_cancelled(true);
              state.reset_cancellation_state(
                boost::asio::enable_terminal_cancellation());

              for (;;)
              {
                char data[1024];
                std::size_t n =
                  co_await socket.async_read_some(
                    boost::asio::buffer(data));

                co_await boost::asio::async_write(socket,
                    boost::asio::buffer(data, n));
              }
            }
            catch (const boost::system::system_error& e)
            {
              co_return {e.code()};
            }
          }, socket),
      token, std::ref(socket));
}
