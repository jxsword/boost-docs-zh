使用、构建和配置 Boost.Asio

支持的平台

以下平台与编译器组合会被定期测试:

  • 使用 g++ 4.6 或更高版本的 Linux
  • 使用 clang 3.4 或更高版本的 Linux
  • 使用 g++ 9 或更高版本的 FreeBSD
  • 使用 Xcode 10 或更高版本的 macOS
  • 使用 Visual C++ 11.0 (Visual Studio 2012) 或更高版本的 Win32
  • 使用 Visual C++ 11.0 (Visual Studio 2012) 或更高版本的 Win64

以下平台也可能可用:

  • AIX
  • Android
  • HP-UX
  • iOS
  • NetBSD
  • OpenBSD
  • QNX Neutrino
  • Solaris
  • Tru64
  • 使用 MinGW 的 Win32.
  • 使用 Cygwin 的 Win32. (必须定义 __USE_W32_SOCKETS.)

Dependencies

链接使用 Boost.Asio 的程序必须具备以下库:

  • Boost.System, 用于 boost::system::error_code 和 boost::system::system_error 类.
  • Boost.Coroutine (可选), 如果你使用 spawn() 来启动协程.
  • Boost.Regex (可选), 如果你使用 read_until() 或 async_read_until() 中接受 boost::regex 参数的任何重载.
  • OpenSSL (可选), 如果你使用 Boost.Asio 的 SSL 支持.

此外, 部分示例还需要 Boost.Thread、Boost.Date_Time 或 Boost.Serialization 库.

注释

使用 MSVC 或 Borland C++ 时, 你可能需要在项目设置中添加 -DBOOST_DATE_TIME_NO_LIB 和 -DBOOST_REGEX_NO_LIB, 分别禁用 Boost.Date_Time 和 Boost.Regex 库的自动链接. 或者, 你也可以选择构建这些库并链接它们.

构建 Boost 库

你可以从 Boost 下载包的根目录运行以下命令, 构建使用 Boost.Asio 及其示例所需的 Boost 库子集:

  b2 --with-system --with-thread --with-date_time --with-regex --with-serialization stage

这里假定你已经构建了 b2. 更多细节请查阅 Boost.Build 文档.

可选的单独编译

默认情况下, Boost.Asio 是仅头文件库. 不过, 一些开发者可能更愿意使用单独编译的源代码来构建 Boost.Asio. 为此, 在程序的某一个源文件 (且仅一个) 中加入 #include <boost/asio/impl/src.hpp>, 然后在项目/编译器设置中定义 BOOST_ASIO_SEPARATE_COMPILATION 并构建程序. 或者, 也可以定义 BOOST_ASIO_DYN_LINK, 把单独编译的 Boost.Asio 构建为共享库的一部分.

如果使用 Boost.Asio 的 SSL 支持, 你还需要添加 #include <boost/asio/ssl/impl/src.hpp>.

调试器支持

一些可与 Asio 一起使用的调试器扩展位于 https://github.com/chriskohlhoff/asio-debugger-extensions.

Macros

下表列出的宏可用于控制 Boost.Asio 的接口、功能和行为.

宏

说明

BOOST_ASIO_NO_DEPRECATED

禁用 Boost.Asio 的已弃用接口和功能.

已弃用的旧接口及其替代品清单参见 Networking TS 兼容性.

BOOST_ASIO_NO_TS_EXECUTORS

禁用 Boost.Asio 对 Networking TS 执行器模型的支持.

默认情况下, Boost.Asio 同时支持 Networking TS 风格的执行器和遵循提议标准执行器模型的执行器. 此宏可用于把支持限制为仅提议标准执行器. 更多信息参见 提议的标准执行器.

BOOST_ASIO_USE_TS_EXECUTOR_AS_DEFAULT

指定 any_io_executor 指 Networking TS 风格的多态封装.

any_io_executor 类型别名是所有 I/O 对象的默认运行期多态执行器. 该类型别名指向 execution::any_executor<> 模板, 并指定了一组用于 I/O 的可支持属性.

这个新名称可能破坏直接使用旧 Networking TS 风格多态封装 executor 的现有代码. 如果需要向后兼容, BOOST_ASIO_USE_TS_EXECUTOR_AS_DEFAULT 会把 any_io_executor 类型别名改为指向 executor 多态封装.

更多信息参见 提议的标准执行器.

BOOST_ASIO_NO_DYNAMIC_BUFFER_V1

禁用对 DynamicBuffer_v1 类型要求的支持.

默认情况下, 动态缓冲区操作 (如 read、async_read、read_until、async_read_until、write 和 async_write ) 同时支持动态缓冲区的 DynamicBuffer_v1 和 DynamicBuffer_v2 类型要求.

定义 BOOST_ASIO_NO_DYNAMIC_BUFFER_V1 时, 对 DynamicBuffer_v1 类型与函数的所有支持都会被 #ifdef 排除. 同时也禁用把 basic_streambuf 与 read、async_read、read_until、async_read_until、write 和 async_write 函数一起使用的支持.

BOOST_ASIO_ENABLE_BUFFER_DEBUGGING

启用 Boost.Asio 的缓冲区调试支持, 它有助于识别读写操作中何时使用了无效缓冲区 (例如, 正在写入的 std::string 对象在写操作完成之前被销毁).

使用 Microsoft Visual C++ 11.0 或更高版本时, 如果启用了编译器的迭代器调试支持, 则自动定义此宏, 除非已定义 BOOST_ASIO_DISABLE_BUFFER_DEBUGGING.

使用 g++ 时, 如果启用了标准库调试 (定义了 _GLIBCXX_DEBUG), 则自动定义此宏, 除非已定义 BOOST_ASIO_DISABLE_BUFFER_DEBUGGING.

BOOST_ASIO_DISABLE_BUFFER_DEBUGGING

显式禁用 Boost.Asio 的缓冲区调试支持.

BOOST_ASIO_ENABLE_HANDLER_TRACKING

启用 Boost.Asio 的 处理器跟踪 调试设施.

BOOST_ASIO_DISABLE_DEV_POLL

显式禁用 Solaris 上的 /dev/poll 支持, 强制使用基于 select 的实现.

BOOST_ASIO_DISABLE_EPOLL

显式禁用 Linux 上的 epoll 支持, 强制使用基于 select 的实现.

BOOST_ASIO_DISABLE_EVENTFD

显式禁用 Linux 上的 eventfd 支持, 强制使用管道来中断阻塞的 epoll/select 系统调用.

BOOST_ASIO_DISABLE_KQUEUE

显式禁用 macOS 和 BSD 变体上的 kqueue 支持, 强制使用基于 select 的实现.

BOOST_ASIO_DISABLE_IOCP

显式禁用 Windows 上的 I/O 完成端口支持, 强制使用基于 select 的实现.

BOOST_ASIO_DISABLE_THREADS

显式禁用 Boost.Asio 的线程支持, 与 Boost 整体是否支持线程无关.

BOOST_ASIO_NO_WIN32_LEAN_AND_MEAN

默认情况下, 在 Windows 上编译时 Boost.Asio 会自动定义 WIN32_LEAN_AND_MEAN, 以尽量减少所包含的 Windows SDK 头文件和特性数量. BOOST_ASIO_NO_WIN32_LEAN_AND_MEAN 的存在会阻止 WIN32_LEAN_AND_MEAN 被定义.

BOOST_ASIO_NO_NOMINMAX

默认情况下, 在 Windows 上编译时 Boost.Asio 会自动定义 NOMINMAX, 以抑制 min() 和 max() 宏的定义. BOOST_ASIO_NO_NOMINMAX 的存在会阻止 NOMINMAX 被定义.

BOOST_ASIO_NO_DEFAULT_LINKED_LIBS

在 Windows 上使用 Microsoft Visual C++ 或 Borland C++ 编译时, Boost.Asio 会自动链接套接字支持所需的 Windows SDK 库 (即 ws2_32.lib 和 mswsock.lib, 或为 Windows CE 构建时的 ws2.lib). BOOST_ASIO_NO_DEFAULT_LINKED_LIBS 宏阻止链接这些库.

BOOST_ASIO_ENABLE_CANCELIO

允许在旧版 Windows 上使用 CancelIo 函数. 若未启用, 则在 Windows XP、Windows Server 2003 及更早版本的 Windows 上运行时, 对套接字对象调用 cancel() 将总是以 asio::error::operation_not_supported 失败. 在 Windows Vista、Windows Server 2008 及更高版本上运行时, 则始终使用 CancelIoEx 函数.

在启用 CancelIo 函数的使用之前, 有两个问题需要考虑:

  • 它只会取消在当前线程中发起的异步操作.

  • 它可能看似无误地完成, 但取消未完成操作的请求可能被操作系统静默忽略. 它是否生效似乎取决于所安装的驱动程序.

    要获得可移植的取消行为, 请考虑使用以下替代方案之一:

  • 通过定义 BOOST_ASIO_DISABLE_IOCP 禁用 asio 的 I/O 完成端口后端.
  • 使用套接字对象的 close() 函数同时取消未完成的操作并关闭套接字.

BOOST_ASIO_NO_TYPEID

禁止在 Boost.Asio 中使用 typeid 运算符. 若定义了 BOOST_NO_TYPEID, 则自动定义此宏.

BOOST_ASIO_HASH_MAP_BUCKETS

确定 Boost.Asio 内部 hash_map 对象的桶数量. 该值应为以逗号分隔、按升序排列的素数列表. hash_map 实现会在 map 中元素增多时自动增加桶数量.

一些示例:

  • 将 BOOST_ASIO_HASH_MAP_BUCKETS 定义为 1021 意味着 hash_map 对象将始终包含 1021 个桶, 与 map 中元素的数量无关.
  • 将 BOOST_ASIO_HASH_MAP_BUCKETS 定义为 53,389,1543 意味着 hash_map 对象初始时包含 53 个桶. 随着元素加入 map, 桶数量将依次增加到 389、1543.

BOOST_ASIO_USE_BOOST_DATE_TIME_FOR_SOCKET_IOSTREAM

使 basic_socket_streambuf 和 basic_socket_iostream 改用旧的 Boost.Date_Time 接口, 而不是 chrono.

BOOST_ASIO_SEPARATE_COMPILATION

使用单独编译的源代码作为 Boost.Asio 的实现.

更多信息参见 上文.

BOOST_ASIO_DYN_LINK

使用单独编译的源代码作为 Boost.Asio 的实现, 并导出符号以便作为共享库的一部分包含.

更多信息参见 上文.

BOOST_ASIO_DISABLE_VISIBILITY

禁用所有符号可见性 pragma.

注意: 如果符号被隐藏, 必须格外小心, 确保 Boost.Asio 类型不会跨越共享库 API 边界传递.

编译器/平台特性检测宏

Asio 会自动定义与特定编译器和目标平台上检测到的可用特性相对应的预处理器宏. 这些宏以前缀 BOOST_ASIO_HAS_ 命名, 并在下表中列出.

其中许多宏还有一个对应的 BOOST_ASIO_DISABLE_ 宏, 可用于显式禁用该特性.

一般而言, 用户不应显式定义 BOOST_ASIO_HAS_ 宏, 除非在最新版本的编译器或平台上确有必要作为变通方案. 对于某个特定 BOOST_ASIO_HAS_ 宏未被自动定义的较旧编译器/平台组合, 测试可能表明所声称的特性不足以兼容 Boost.Asio 的需求.
