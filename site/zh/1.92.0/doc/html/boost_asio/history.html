修订历史

Asio 1.38.2 / Boost 1.92 beta

  • 新增了 "scheduler" / "assume_continuation" 配置参数. 当 true 时, 调度器假定所有投递的处理器都是当前正在执行的处理器的延续, 从而允许将它们加入快速的线程本地队列. 这可以提升仅使用短时运行处理器的应用程序的性能.
  • 新增了 "reactor" / "io_uring_ring_count" 配置参数. 它设置单个执行上下文内部维护的独立 io_uring 实例 (环) 的数量. 将该参数从默认值 1 调大, 在执行上下文与多线程配合使用时可能提升可伸缩性.
  • 新增了 "reactor" / "io_uring_ring_size" 配置参数, 用于指定每个 io_uring 实例中的条目数量.
  • 新增了 "reactor" / "io_uring_submit_batch_size" 配置参数. 它设置待处理的 io_uring 提交队列条目数量达到多少时立即提交, 而不是延迟提交.
  • 新增了 "reactor" / "io_uring_iowait" 配置参数, 可用于确定在 io_uring 操作待处理期间是否将线程标记为处于 iowait 状态.
  • 新增了配置 ssl::stream<> 内部缓冲区大小的能力.
  • 新增了 boost/asio/fwd.hpp, 作为一种安全地对某些 Boost.Asio 类名进行前向声明的方式, 即使在定义了 BOOST_ASIO_ENABLE_VERSION_NAMESPACE 或 BOOST_ASIO_VERSION_NAMESPACE 时也是如此.
  • 新增了一个将 cancel_after 与协程结合使用的示例.
  • 将所有异常类改为使用内联实现, 以修复在某些平台上使用分离编译时出现的未定义符号错误.
  • 将常量与 CPO 改为在 C++17 及更高版本中使用外部链接.
  • 将"slim"互斥量改为在 Linux 上使用 futex.
  • 将 reactor 的发送/接收路径改为使用 MSG_DONTWAIT (如果受支持) , 而不是将套接字设为非阻塞.
  • 为 concurrency_hint == 1 补充了 io_context 类的 poll_one() 函数中缺失的一项优化.
  • 新增了对 co_composed 在 BOOST_ASIO_NO_EXCEPTIONS 下的支持.
  • 修复了 co_composed 在 MSVC 上使用多个完成签名时发生的崩溃.
  • 通过在其内部协程表示中确保 16 字节块对齐, 修复了 co_composed 在 MSVC 上的崩溃.
  • 修复了 cancel_after 某个重载的返回类型.
  • 修复了 basic_streambuf::commit/consume 在大小大于或等于 INT_MAX 时的整数截断问题.
  • 修复了移动 SSL 流时触发的缓冲区失效错误, 并在文档中澄清了缓冲区失效语义.
  • 修复了一些编译器 (如 nvc++) 上出现的编译错误, 该错误发生在将 post、dispatch 或 defer (或构建于其上的异步操作) 与完成处理器一起使用时.
  • 修复了 parallel_group 对非终结取消请求的处理.
  • 修复了由原子线程栅栏导致的 thread sanitizer 警告, 并为 io_uring 后端添加了 thread sanitizer 插桩.
  • 修复了 basic_resolver_results 中的有符号/无符号警告.
  • 修复了 experimental::channel 在旧版本 MSVC 下的编译.
  • 修复了 NetBSD 和 OpenBSD 上 multicast::enable_loopback 套接字选项的大小.
  • 在 SSL 实现中抑制了 case 贯穿警告.
  • 修复了使用 clang-cl 时的标准库协程检测.
  • 改进了文档中的交叉引用.

Asio 1.38.1 / Boost 1.91

  • 新增了使用内联命名空间的可选二进制版本控制. 如果定义了预处理器宏 BOOST_ASIO_ENABLE_VERSION_NAMESPACE, Asio 将把所有符号编译到包含版本号的内联命名空间之下. 此外, 用户也可以通过直接定义 BOOST_ASIO_VERSION_NAMESPACE 来指定自定义的内联命名空间名称. 这使得不同版本的 Asio 可以在同一进程中共存而不产生符号冲突. 内联命名空间默认禁用, 以免破坏对 Asio 名称进行前向声明的既有代码.
  • 将 Windows 默认互斥量实现从 CRITICAL_SECTION 改为 SRWLOCK.
  • 新增了基于 std::atomic 的"slim"互斥量实现. 在编译器和操作系统支持时, 这可以减小 strand、套接字及其他描述符所需状态的大小.
  • 新增了对在 Cygwin64 下编译的支持.
  • 新增了在不使用 __USE_W32_SOCKETS 的情况下使用 Cygwin 的支持, 允许以 POSIX 套接字 API 取代 Winsock API.
  • 新增了让用户在包含 Asio 头文件之前覆盖 BOOST_ASIO_DECL 的能力. 这可用于覆盖符号可见性属性, 或禁用 DLL 导入/导出修饰.
  • 修复了 MSG_NOSIGNAL 在 NetBSD 上的处理, 该平台无论 _POSIX_VERSION 如何都支持此标志.
  • 修复了与近期 Boost 版本的构建, 这些版本不再支持链接 boost_system.
  • 修复了在旧版本 Android 上与 musl libc 的兼容性.
  • 修复了在旧版 Apple 平台上对 std::aligned_alloc 的检测.
  • 修复了在用 MSVC 编译时 serial_port_base::character_size::store 中的一条警告.
  • 在文档中澄清了 ip::multicast::outbound_interface 的 IPv4 与 IPv6 语义.
  • 更新了 TLS v1.3 上下文初始化, 以正确检测 LibreSSL 支持 (自 LibreSSL 3.2.0 起可用) .
  • 修复了与近期围绕 X509 常量性的 OpenSSL API 变更的兼容性.

Asio 1.37.0

  • 新增了 execution::inline_exception_handling 属性. 该属性用于描述执行器对所提交函数抛出的异常的处理方式作出何种保证, 此时该函数在 execute 中内联执行.
  • 新增了 inline_executor, 这是一个始终内联执行函数对象的执行器. inline_executor 适合用作完成执行器, 但不能用作 I/O 执行器.
  • 将 associated_executor 的默认候选执行器从 system_executor 改为 inline_executor.
  • 新增了 inline_or_executor<> 与 inline_or() 辅助函数. inline_or_executor<> 模板是一个执行器适配器. 它会在允许时尝试内联执行所提交的函数对象, 否则将函数对象投递给被封装的执行器.

  • 新增了 dispatch、post 与 defer 的重载, 它们接受一个要在目标执行器上运行的函数对象, 并将结果递送给完成处理器:

    asio::post(
  []{
    // ... perform long running computation ...
    return result;
  },
  my_thread_pool,
  asio::bind_executor(my_io_context,
    [](int result)
    {
      // ...
    }));


    或者, 如果从使用默认 asio::deferred 完成标记的协程中调用:

    int result = co_await asio::post(
  []{
    // perform long running computation
    return result;
  }, my_thread_pool);

  • 新增了 redirect_disposition 完成标记适配器, 作为 redirect_error 的通用对应物. redirect_disposition 适配器用于把异步操作产生的处置结果 (如 error_code) 捕获到变量中:

    std::exception_ptr my_exception;
// ...
my_socket.async_read_some(my_buffer,
    boost::asio::redirect_disposition(
      [](std::size_t bytes_transferred)
      {
        // ...
      }, my_exception));
  • 为已弃用的条目标注了 [[deprecated]] 属性.
  • 新增了配置参数"reactor" / "reset_edge_on_partial_read". 当为 true 时, 面向流的套接字上的部分读取被视为已消费边沿触发的就绪通知, 需要新的就绪事件才能继续读取. (部分写入总是消费边沿. ) 这避免了不必要的推测性读取. 默认为 false.
  • 新增了配置参数"reactor" / "use_eventfd", 用于确定 epoll reactor 后端是否使用 eventfd. 默认为 true.
  • 新增了配置参数"reactor" / "use_timerfd", 用于确定 epoll reactor 后端是否使用 timerfd. 默认为 true.
  • 为标准库对 std::source_location 的支持实现了编译期特性检查, 作为对 std::experimental::source_location 的补充.
  • 停止使用已弃用的函数 boost::array::c_array().
  • 补上了针对 BOOST_ASIO_DISABLE_TIMERFD 缺失的预处理器检查.
  • 修复了 asio::awaitable 移动赋值中的资源泄漏.
  • 修复了 ssl 流移动赋值中的内存泄漏.
  • 修复了 kqueue reactor 中的一个 thread sanitizer 问题.
  • 修复了在 io_uring 后端中传入的 handler tracking 参数.
  • 修复了一条未使用参数警告 boost::asio::detail::null_thread.

Asio 1.33.0

  • 新增了将字节 span 及字节 span 序列用作缓冲区序列的支持. 这意味着它们可以直接传给 async_read 等 I/O 操作.
  • 新增了对处置结果 (disposition) 的支持, 处置结果是可用于测试异步操作是否无错完成的类型. 这包括 error_code 与 exception_ptr, 但可以通过对 disposition_traits 类模板的特化扩展到用户类型. 打算以处置结果进行工作的泛型代码不应直接使用 boost::asio::disposition_traits, 而应使用:
    • 通过与 boost::asio::no_error (类型为 boost::asio::no_error_t) 比较, 测试处置结果是否不含错误.
    • 使用 boost::asio::to_exception_ptr 将处置结果转换为 std::exception_ptr.
    • 使用 boost::asio::throw_exception 抛出与处置结果对应的异常, 但须先将该处置结果与 boost::asio::no_error 进行测试.
  • 为 boost::asio::use_future 完成标记、基于 boost::asio::awaitable<> 的协程、boost::asio::spawn() 以及 boost::asio::experimental::cancellation_condition 添加了处置结果支持.
  • 新增了 execution_context::service_maker 抽象基类. service_maker 是一个传递给执行上下文构造函数的对象, 允许在上下文构造时添加服务. io_context 与 thread_pool 还新增了接受 service_maker 的构造函数重载.

  • 新增了 boost::asio::config. config 类提供对与执行上下文相关联的配置参数的访问. 该类供 asio 内部使用, 或供构建于 asio 之上的库或用户提供的抽象使用. 这些配置参数通常用于微调行为, 例如启用或禁用某些优化. 在构造执行上下文 (如 io_context) 时, 调用者可以可选地传递一个 service_maker, 将具体的配置服务安装到上下文中. 例如:

    boost::asio::io_context ctx{boost::asio::config_from_env{}};

    配置参数的值通过 config 类访问, 传入节、键与默认值:

    boost::asio::config cfg{ctx};
bool enable_locking = cfg.get("scheduler", "locking", true);
  • 添加了 asio 的 io_context 与 thread_pool 实现所识别的初始配置参数集:
    • "scheduler" / "concurrency_hint" (int, 默认 0) - 向调度器建议在运行完成处理器时应使用的活动数量.
    • "scheduler" / "locking" (bool, 默认 true) - 可设为 false 以禁用调度器中的锁定, 此时必须注意不要对执行上下文或其 I/O 对象执行并发操作.
    • "scheduler" / "locking_spin_count" (int, 默认 0) - 首先尝试以不阻塞方式获取锁的次数.
    • "scheduler" / "task_usec" (long, 默认 -1) - 调度器等待其 reactor 任务完成的最长时间.
    • "scheduler" / "wait_usec" (long, 默认 -1) - 调度器在空闲线程中等待其唤醒事件的最长时间.
    • "reactor" / "preallocated_io_objects" (unsigned int, 默认 0) - 在构造时分配的内部 reactor I/O 对象状态的数量.
    • "reactor" / "registration_locking" (bool, 默认 true) - 可设为 false 以禁用 reactor 中围绕 I/O 对象注册的锁定, 此时必须注意不要并发地打开或关闭 I/O 对象.
    • "reactor" / "registration_locking_spin_count" (int, 默认 0) - 首先尝试以不阻塞方式获取锁的次数.
    • "reactor" / "io_locking" (bool, 默认 true) - 可设为 false 以禁用 reactor 中针对每个 I/O 对象的锁定, 此时执行上下文必须是单线程的, 并且必须注意不要并发调用 I/O 操作的发起函数.
    • "reactor" / "io_locking_spin_count" (int, 默认 0) - 首先尝试以不阻塞方式获取锁的次数.
  • 移除了先前已弃用的一些设施:
    • 移除了基于 Boost.Coroutine 的 spawn() 重载. spawn() 函数现在只能与 Boost.Context 中的纤程 (fiber) 支持配合使用.

Asio 1.4.6 / Boost 1.44

  • 确保处理器实参以 const 类型传递.

  • 确保 unsigned char 与 isdigit 在 getaddrinfo 模拟中一起使用 (#4201) .
  • 修复了对极小但非零超时的处理 (#4205) .
  • 修复了把空缓冲区序列传给组合读或写操作时发生的崩溃.
  • 补上了 operator+ 缺失的重载 (在 buffers_iterator 中) (#4382) .
  • 实现了 Windows 上 null_buffers 操作的取消.

Asio 1.4.5 / Boost 1.43

  • 减小了生成代码的大小.

  • 将 io_control() 成员函数改为在修改阻塞模式时始终对底层描述符调用 ioctl (#3307) .
  • 将解析器实现改为不再需要 typedef InternetProtocol::resolver_query 与 InternetProtocol::resolver_iterator, 因为这两个 typedef 都不属于已文档化的 InternetProtocol 要求. ip::tcp、ip::udp 与 ip::icmp 类中对应的 typedef 已被弃用.
  • 修复了不基于 select() 的 reactor 的带外处理.
  • 添加了新宏 BOOST_ASIO_DISABLE_THREADS, 允许独立禁用 Asio 的线程支持.
  • 次要文档改进.
