Signals2 API 的发展

从 Boost.Signals 移植到 Boost.Signals2

下面总结了 Boost.Signals2 API 相对于原始 Boost.Signals 库所做的更改. 我们还针对把既有 Boost.Signals 代码移植到 Boost.Signals2 时如何处理每项更改提供了一些说明.

  • 命名空间 boost::signals 已被 boost::signals2 取代, 以避免与原始的 Boost.Signals 实现以及 Qt 的 "signals" 宏发生冲突. 所有 Boost.Signals2 类都位于 boost::signals2 命名空间之内, 不像原始的 Boost.Signals, 后者在 boost 命名空间中还有部分类 (此外还有自己的 boost::signals 命名空间).

    Boost.Signals2 的头文件位于 boost/signals2/ 子目录中, 而不是原始 Boost.Signals 使用的 boost/signals 子目录. 此外, 除便利头文件 boost/signals2.hpp 之外的所有头文件都位于 boost/signals2/ 子目录内, 不像原始的 Boost.Signals, 后者在父目录 boost/ 中保留了几个头文件 (此外还有自己的 boost/signals/ 子目录).

    例如, signal 类现在位于 boost::signals2 命名空间而不是 boost 命名空间中, 其头文件现在位于 boost/signals2/signal.hpp 而不是 boost/signal.hpp.

    移植时, 处理这些更改应当只需对 #include 指令和命名空间限定做微不足道的修改. 此外, Boost.Signals2 新的命名空间和头文件位置使它能够在同一程序中与原始的 Boost.Signals 库共存, 移植可以分步进行.

  • 自动连接管理现在通过使用 shared_ptr/weak_ptr 和 signals2::slot::track() 来实现, 如教程中所述. 不过, 旧的 (线程不安全的) Boost.Signals 自动连接管理方案仍通过 boost::signals2::trackable 类得到支持.

    如果你不打算把程序做成多线程的, 最简单的移植路径是把对 boost::signals::trackable 作为基类的使用替换为 boost::signals2::trackable. Boost.Signals2 使用与原始 Boost.Signals 库相同的 boost::visit_each 机制来发现 trackable 对象.

  • 对于 shared_ptr 所管理的对象, 已通过 deconstruct 工厂函数增加了对后构造函数 (postconstructor, 以及前析构函数 predestructor) 的支持. 其动因是 shared_ptr 对新连接跟踪方案的重要性, 以及无法在对象的构造函数中获得指向它的 shared_ptr. deconstruct 的使用在教程中有描述.

    deconstruct 的使用并非必需, 提供它只是希望它可能有用. 如果你移植的代码中某个类在其构造函数中创建指向自身成员函数的连接, 同时你又想使用新的自动连接管理方案, 那么你可能会想使用它. 此时你可以把连接的创建从构造函数移到某个 adl_postconstruct 函数中, 在那里可以获得对拥有者 shared_ptr 的引用并传递给 signals2::slot::track. deconstruct 函数将用于创建该类的对象并运行其关联的 adl_postconstruct 函数. 你可以强制使用 deconstruct, 方法是把类的构造函数设为私有并声明 deconstruct_access 为友元.

  • signals2::slot 类接受一个新的 Signature 模板参数, 可用作函数对象, 并具有一些支持新 Boost.Signals2 自动连接管理方案的附加特性.

    槽类的更改一般不应造成任何移植困难, 尤其是如果你使用了前面提到的 boost::signals2::trackable 兼容类. 如果你把代码转换为使用新的自动连接管理方案, 则需要采用一些新的槽特性, 如教程中所述.

  • optional_last_value 类已取代 last_value 成为信号的默认合并器 (combiner).

    signals2::last_value 合并器仍然提供, 只是其行为略有变化: 当信号被调用时若没有连接任何槽, 它会抛出异常, 而不是始终要求至少连接一个槽 (其 void 特化除外, 该特化从不要求连接任何槽).

    如果你移植的信号在其签名中具有 void 返回类型且使用默认合并器, 则无须任何更改. 如果你把默认合并器用于非 void 返回类型, 并且关心信号调用返回的值, 那么你必须考虑到 optional_last_value 返回的是一个 boost::optional 而不是普通值. 处理这个问题的一个简单办法是使用 boost::optional::operator*() 来访问返回的 boost::optional 中包装的值.

    或者, 你也可以通过指定 Combiner 模板参数 (用于你的 signals2::signal) 为 signals2::last_value 来完成移植.

  • signals2::signal 类增加了一个新的 typedef signals2::signal::extended_slot_type 和新的 signals2::signal::connect_extended() 方法. 这些使得可以连接接受一个额外 signals2::connection 参数的槽, 在它们被调用时为其提供对其信号/槽连接的线程安全访问. 还有一个新的 ExtendedSlotFunction 模板参数, 用于为新扩展槽指定底层槽函数类型.

    这些新增内容应当对移植没有影响, 除非你同时还要把程序从单线程程序转换为多线程程序. 在那种情况下, 如果你的槽需要访问其到调用它们的信号的 signals2::connection (例如用于阻塞或断开自己的连接), 你可能希望用 signals2::signal::connect_extended() 来连接这些槽. 这还需要为槽增加一个额外的连接参数. 关于如何以及为何使用扩展槽的更多信息, 请参见教程.

  • signals2::signal 类有一个新的 Mutex 模板参数, 用于指定信号及其连接内部使用的互斥量类型.

    Mutex 模板参数可以保留其默认值 boost::signals2::mutex, 这应当对移植几乎没有影响. 不过, 如果你的程序是单线程的, 并且担心不必要的互斥量加锁带来性能开销, 你可能希望为信号使用不同的互斥量, 例如 dummy_mutex. 请参见教程 以了解 Mutex 参数的更多信息.

  • signal::combiner() 方法 (它以前返回对信号合并器的引用) 已被 signals2::signal::combiner (现在按值返回合并器) 和 signals2::signal::set_combiner 取代.

    移植时, 把旧的返回引用的 signal::combiner() 函数的使用替换为新的 "按值" signals2::signal::combiner 和 signals2::signal::set_combiner 函数应当是直接了当的. 不过, 你需要检查代码中对 combiner 方法的每次调用, 以确定你的程序逻辑是否被更改后的返回类型破坏.

  • 连接不再有 block() 和 unblock() 方法. 连接的阻塞现在通过创建 shared_connection_block 对象来完成, 这些对象提供 RAII 风格的阻塞.

    如果你有会阻塞连接的既有 Boost.Signals 代码, 例如:

      namespace bs = boost::signals;

  bs::connection my_connection;
  //...

  my_connection.block();
  do_something();
  my_connection.unblock();

    那么移植到 Boost.Signals2 之后的版本看起来像:

      namespace bs2 = boost::signals2;

  bs2::connection my_connection;
  //...

  {
    bs2::shared_connection_block blocker(my_connection);
    do_something();
  } // blocker goes out of scope here and releases its block on my_connection

Version 1.56

Version 1.56 修改了信号析构函数的行为: 它不再显式调用 disconnect_all_slots. 与信号析构函数并发运行的任何信号调用现在应当正常完成, 而不是跳过所有剩余的槽. 一旦所有并发的信号调用完成, 指向被删除信号的所有连接最终仍将断开. 这一变更使 Boost.Signals2 的行为更接近原始 Boost.Signals 库的行为.

Version 1.45

Version 1.45 增加了 slot::track_foreign(). 此方法允许跟踪由 shared_ptr 类而非 boost::shared_ptr 所拥有的对象, 例如 std::shared_ptr.

Version 1.40

Version 1.40 为 shared_connection_block 类增加了一些新特性, 使其更加灵活:

  • shared_connection_block 现在可默认构造.

  • 现在可以在构造 shared_connection_block 时不立即阻塞其连接.

  • 增加了 shared_connection_block::connection() 查询, 用于访问 shared_connection_block 关联的连接.

Version 1.40 还引入了 Signals2 的变参模板实现, 当 Boost 检测到编译器支持变参模板时会使用该实现 (变参模板是 C++11 的新特性). 这一变更对用户基本上是透明的, 不过它确实对接口引入了一些可见的微调, 如下所述.

以下库特性已被弃用, 仅当你的编译器没有使用变参模板时才可用 (即 Boost.Config 定义了 BOOST_NO_CXX11_VARIADIC_TEMPLATES).

  • "可移植语法" (portable syntax) 的 signal 和 slot 类, 即 signals2::signal0, signal1 等.

  • signals2::signal 和 signals2::slot 类中的 arg1_type, arg2_type 等成员 typedef. 它们被模板成员类 signals2::signal::arg 和 signals2::slot::arg 取代.

Version 1.39

Version 1.39 是首个包含 Signals2 库的 Boost 发布版本.
