如何阅读本教程

本教程并不要求按顺序通读. 其顶层结构大致区分了库中的不同概念(例如处理多个槽的调用、向槽传入及从槽传出值), 并且在每个概念中都先介绍基本思想, 稍后再描述库的更复杂用法. 每一节都标注了 初级、中级 或 高级, 以帮助引导读者. 初级 章节包含所有库用户都应当了解的信息; 仅读完 初级 章节, 就可以很好地使用 Signals2 库. 中级 章节在 初级 章节的基础上介绍稍复杂的库用法. 最后, 高级 章节详细讲述 Signals2 库的非常高级的用法, 这些用法通常需要对 初级 和 中级 主题有扎实的实际掌握; 大多数用户无需阅读 高级 章节.

Hello, World! (初级)

下面的示例使用信号与槽输出 "Hello, World!". 首先, 我们创建一个信号 sig, 它是一个不带参数、返回值为 void 的信号. 接着, 我们把 hello 函数对象用 connect 方法连接到该信号. 最后, 像调用函数一样使用信号 sig 来调用各个槽, 这会进而调用 HelloWorld::operator() 来输出 "Hello, World!".

struct HelloWorld
{
  void operator()() const
  {
    std::cout << "Hello, World!" << std::endl;
  }
};

  // Signal with no arguments and a void return value
  boost::signals2::signal<void ()> sig;

  // Connect a HelloWorld slot
  HelloWorld hello;
  sig.connect(hello);

  // Call all of the slots
  sig();

连接多个槽 (初级)

从信号调用单个槽没什么意思, 所以我们可以把输出 "Hello, World!" 的工作拆分到两个完全独立的槽中, 让 Hello, World 程序更有意思. 第一个槽将输出 "Hello", 它可能如下所示:

struct Hello
{
  void operator()() const
  {
    std::cout << "Hello";
  }
};

第二个槽将输出 ", World!" 和一个换行, 以完成该程序. 第二个槽可能如下所示:

struct World
{
  void operator()() const
  {
    std::cout << ", World!" << std::endl;
  }
};

与前面的示例一样, 我们可以创建一个信号 sig, 它不带参数并具有 void 返回值. 这次, 我们把 hello 和 world 两个槽都连接到同一个信号, 当我们调用该信号时, 两个槽都会被调用.

  boost::signals2::signal<void ()> sig;

  sig.connect(Hello());
  sig.connect(World());

  sig();

默认情况下, 槽被压入槽列表的末尾, 因此该程序的输出将符合预期:

Hello, World!

对槽调用组排序 (中级)

槽可以有副作用, 这意味着某些槽必须先于其他槽被调用, 即使它们的连接顺序并非如此. Boost.Signals2 库允许把槽放入以某种方式排序的组中. 对于我们的 Hello, World 程序, 我们希望 "Hello" 在 ", World!" 之前输出, 所以我们把 "Hello" 放入一个必须先于 ", World!" 所在组执行的组. 为此, 我们可以在 connect 调用的开头提供一个额外参数来指定组. 组值默认为 int 类型, 并按整数 < 关系排序. 下面是我们构造 Hello, World 的方式:

  boost::signals2::signal<void ()> sig;

  sig.connect(1, World());  // connect with group 1
  sig.connect(0, Hello());  // connect with group 0

调用该信号将正确输出 "Hello, World!", 因为 Hello 对象位于组 0 中, 该组先于 World 对象所在的组 1. 组参数实际上是可选的. 在第一个 Hello, World 示例中我们省略了它, 因为当所有槽相互独立时它是多余的. 那么, 如果我们把使用组参数的 connect 调用与不使用组参数的调用混在一起, 会发生什么? "未命名"的槽(即连接时未指定组名的槽)可以被放在槽列表的开头或结尾(分别把 boost::signals2::at_front 或 boost::signals2::at_back 作为传给 connect 的最后一个参数), 默认放在列表末尾. 当指定了组时, 最后的 at_front 或 at_back 参数描述该槽在组排序中的位置. 用 at_front 连接的未分组槽总是先于所有已分组槽. 用 at_back 连接的未分组槽总是排在所有已分组槽之后.

如果我们像这样向示例中添加一个新槽:

struct GoodMorning
{
  void operator()() const
  {
    std::cout << "... and good morning!" << std::endl;
  }
};

  // by default slots are connected at the end of the slot list
  sig.connect(GoodMorning());

  // slots are invoked this order:
  // 1) ungrouped slots connected with boost::signals2::at_front
  // 2) grouped slots according to ordering of their groups
  // 3) ungrouped slots connected with boost::signals2::at_back
  sig();

... 我们就会得到想要的结果:

Hello, World!
... and good morning!

向槽传入值与从槽传出值

槽参数 (初级)
信号返回值 (高级)

槽参数 (初级)

信号可以把参数传递给它调用的每个槽. 例如, 传播鼠标移动事件的信号可能希望传递新的鼠标坐标以及鼠标按钮是否被按下.

举个例子, 我们将创建一个向其槽传递两个 float 参数的信号. 然后我们将创建几个槽, 输出对这些值进行各种算术运算的结果.

void print_args(float x, float y)
{
  std::cout << "The arguments are " << x << " and " << y << std::endl;
}

void print_sum(float x, float y)
{
  std::cout << "The sum is " << x + y << std::endl;
}

void print_product(float x, float y)
{
  std::cout << "The product is " << x * y << std::endl;
}

void print_difference(float x, float y)
{
  std::cout << "The difference is " << x - y << std::endl;
}

void print_quotient(float x, float y)
{
  std::cout << "The quotient is " << x / y << std::endl;
}

  boost::signals2::signal<void (float, float)> sig;

  sig.connect(&print_args);
  sig.connect(&print_sum);
  sig.connect(&print_product);
  sig.connect(&print_difference);
  sig.connect(&print_quotient);

  sig(5., 3.);

该程序将输出以下内容:

The arguments are 5 and 3
The sum is 8
The product is 15
The difference is 2
The quotient is 1.66667

因此, 像调用函数一样调用 sig 时传给它的任何值都会被传递给每个槽. 在创建信号时, 我们必须预先声明这些值的类型. 类型 boost::signals2::signal<void (float, float)> 表示该信号具有 void 返回值并接受两个 float 值. 因此, 连接到 sig 的任何槽都必须能够接受两个 float 值.

信号返回值 (高级)

正如槽可以接收参数, 它们也可以返回值. 这些值随后可以通过一个 组合器 返回给信号的调用者. 组合器是一种可以把调用槽的结果(可能没有结果, 也可能有一百个; 在程序运行之前我们无从得知)合并为单一结果并返回给调用者的机制. 该单一结果通常是各槽调用结果的简单函数: 最后一次槽调用的结果、任何槽返回的最大值、或包含全部结果的容器, 都是可能的形式.

我们可以稍微修改之前的算术运算示例, 让各个槽都返回计算乘积、商、和或差的结果. 然后信号本身可以基于这些结果返回一个值并输出:

float product(float x, float y) { return x * y; }
float quotient(float x, float y) { return x / y; }
float sum(float x, float y) { return x + y; }
float difference(float x, float y) { return x - y; }

boost::signals2::signal<float (float, float)> sig;
  sig.connect(&product);
  sig.connect(&quotient);
  sig.connect(&sum);
  sig.connect(&difference);

  // The default combiner returns a boost::optional containing the return
  // value of the last slot in the slot list, in this case the
  // difference function.
  std::cout << *sig(5, 3) << std::endl;

这个示例程序将输出 2. 这是因为具有返回类型的信号(float, 即传给 boost::signals2::signal 类模板的第一个模板参数)的默认行为是调用所有槽, 然后返回一个包含最后被调用的槽所返回结果的 boost::optional. 对于本示例, 这一行为确实有些滑稽, 因为槽没有副作用, 而结果就是最后连接的那个槽.

更有意思的信号结果是任何槽所返回值中的最大值. 为此, 我们创建一个如下所示的自定义组合器:

// combiner which returns the maximum value returned by all slots
template<typename T>
struct maximum
{
  typedef T result_type;

  template<typename InputIterator>
  T operator()(InputIterator first, InputIterator last) const
  {
    // If there are no slots to call, just return the
    // default-constructed value
    if(first == last ) return T();
    T max_value = *first++;
    while (first != last) {
      if (max_value < *first)
        max_value = *first;
      ++first;
    }

    return max_value;
  }
};

maximum 类模板充当函数对象. 其结果类型由模板参数给出, 这也是它预期用于计算最大值的类型(例如, maximum<float> 将求 float 的最大值, 输入是一个 float 序列). 当 maximum 对象被调用时, 会得到一个输入迭代器序列 [first, last), 其中包含调用所有槽的结果. maximum 利用这个输入迭代器序列计算最大元素, 并返回该最大值.

我们实际上是通过把这个新的函数对象类型安装为信号的组合器来使用它. 组合器模板参数跟在信号的调用签名之后:

boost::signals2::signal<float (float x, float y),
              maximum<float> > sig;

现在我们可以连接执行算术运算的槽并使用该信号:

  sig.connect(&product);
  sig.connect(&quotient);
  sig.connect(&sum);
  sig.connect(&difference);

  // Outputs the maximum value returned by the connected slots, in this case
  // 15 from the product function.
  std::cout << "maximum: " << sig(5, 3) << std::endl;

该程序的输出将是 15, 因为无论槽以何种顺序连接, 5 和 3 的乘积都会大于商、和或差.

在其他情况下, 我们可能希望把槽计算出的所有值一起放入一个大型数据结构中返回. 用另一个组合器可以轻松做到这一点:

// aggregate_values is a combiner which places all the values returned
// from slots into a container
template<typename Container>
struct aggregate_values
{
  typedef Container result_type;

  template<typename InputIterator>
  Container operator()(InputIterator first, InputIterator last) const
  {
    Container values;

    while(first != last) {
      values.push_back(*first);
      ++first;
    }
    return values;
  }
};

同样, 我们可以用这个新组合器创建一个信号:

boost::signals2::signal<float (float, float),
    aggregate_values<std::vector<float> > > sig;
  sig.connect(&quotient);
  sig.connect(&product);
  sig.connect(&sum);
  sig.connect(&difference);

  std::vector<float> results = sig(5, 3);
  std::cout << "aggregate values: ";
  std::copy(results.begin(), results.end(),
    std::ostream_iterator<float>(std::cout, " "));
  std::cout << "\n";

该程序的输出将包含 15、8、1.6667 和 2. 这里有趣的是, signal 类的第一个模板参数 float 实际上并不是信号的返回类型. 相反, 它是被连接槽使用的返回类型, 同时也是传给组合器的输入迭代器的 value_type. 组合器本身是一个函数对象, 它的 result_type 成员类型成为信号的返回类型.

传给组合器的输入迭代器把解引用操作转换为槽调用. 因此, 组合器可以选择只调用部分槽, 直到满足某个特定条件为止. 例如, 在分布式计算系统中, 组合器可以询问每个远程系统是否处理该请求. 只需要一个远程系统处理特定请求, 所以在某个远程系统接受该工作之后, 我们不希望再让任何其他远程系统执行同样的任务. 这样的组合器只需检查解引用迭代器时返回的值, 并在值可接受时返回. 下面的组合器返回第一个指向 FulfilledRequest 数据结构的非空指针, 而不会让任何后续槽去完成该请求:

struct DistributeRequest {
  typedef FulfilledRequest* result_type;

  template<typename InputIterator>
  result_type operator()(InputIterator first, InputIterator last) const
  {
    while (first != last) {
      if (result_type fulfilled = *first)
        return fulfilled;
      ++first;
    }
    return 0;
  }
};

断开槽的连接 (初级)

槽并不预期在连接之后无限期地存在. 通常, 槽只用于接收少量事件, 随后即被断开连接, 而程序员需要能够控制何时不再连接某个槽.

显式管理连接的入口是 boost::signals2::connection 类. connection 类唯一地表示特定信号与特定槽之间的连接. connected() 方法检查信号与槽是否仍然连接, disconnect() 方法则在信号与槽在其被调用时仍处于连接状态的情况下断开它们. 对信号的 connect() 方法的每次调用都会返回一个连接对象, 该对象可用于确定连接是否仍然存在, 或断开信号与槽的连接.

  boost::signals2::connection c = sig.connect(HelloWorld());
  std::cout << "c is connected\n";
  sig(); // Prints "Hello, World!"

  c.disconnect(); // Disconnect the HelloWorld object
  std::cout << "c is disconnected\n";
  sig(); // Does nothing: there are no connected slots

阻塞槽 (初级)

槽可以被临时"阻塞", 意味着在信号被调用时它们将被忽略, 但并未被永久断开连接. 这通常用于防止无限递归: 若不加阻止, 运行某个槽会导致它所连接的信号再次被调用. 一个 boost::signals2::shared_connection_block 对象会临时阻塞一个槽. 解除连接阻塞的办法是: 对引用该连接的所有对象调用 unblock, 或者销毁所有引用该连接的 shared_connection_block 对象. 下面是阻塞/解除阻塞槽的示例:

  boost::signals2::connection c = sig.connect(HelloWorld());
  std::cout << "c is not blocked.\n";
  sig(); // Prints "Hello, World!"

  {
    boost::signals2::shared_connection_block block(c); // block the slot
    std::cout << "c is blocked.\n";
    sig(); // No output: the slot is blocked
  } // shared_connection_block going out of scope unblocks the slot
  std::cout << "c is not blocked.\n";
  sig(); // Prints "Hello, World!"}

scoped_connection (中级)

boost::signals2::scoped_connection 类引用一个信号/槽连接, 当 scoped_connection 对象离开作用域时该连接将被断开. 当连接只需临时存在时, 这一能力很有用, 例如:

  {
    boost::signals2::scoped_connection c(sig.connect(ShortLived()));
    sig(); // will call ShortLived function object
  } // scoped_connection goes out of scope and disconnects

  sig(); // ShortLived function object no longer connected to sig

注意, 由于 scoped_connection 不可复制, 尝试用赋值语法初始化 scoped_connection 会失败. 可以使用显式初始化语法, 或先默认构造再从 signals2::connection 赋值:

// doesn't compile due to compiler attempting to copy a temporary scoped_connection object
// boost::signals2::scoped_connection c0 = sig.connect(ShortLived());

// okay
boost::signals2::scoped_connection c1(sig.connect(ShortLived()));

// also okay
boost::signals2::scoped_connection c2;
c2 = sig.connect(ShortLived());

断开等价槽的连接 (中级)

可以使用 signal::disconnect 方法的某种形式来断开与给定函数对象等价的槽的连接, 只要该函数对象的类型具有可访问的 == 运算符. 例如:

void foo() { std::cout << "foo"; }
void bar() { std::cout << "bar\n"; }

boost::signals2::signal<void ()> sig;
  sig.connect(&foo);
  sig.connect(&bar);
  sig();

  // disconnects foo, but not bar
  sig.disconnect(&foo);
  sig();

自动连接管理 (中级)

Boost.Signals2 可以自动跟踪信号/槽连接所涉对象的生命期, 包括当参与槽调用的对象被销毁时自动断开槽的连接. 例如, 考虑一个简单的新闻投递服务: 客户端连接到一个新闻提供者, 当信息到达时, 新闻提供者随后把新闻发送给所有已连接的客户端. 这个新闻投递服务可以这样构造:

class NewsItem { /* ... */ };

typedef boost::signals2::signal<void (const NewsItem&)> signal_type;
signal_type deliverNews;

希望接收新闻更新的客户端只需把一个能够接收新闻条目的函数对象连接到 deliverNews 信号. 例如, 我们可以在应用程序中设置一个专门用于新闻的特别消息区, 例如:

struct NewsMessageArea : public MessageArea
{
public:
  // ...

  void displayNews(const NewsItem& news) const
  {
    messageText = news.text();
    update();
  }
};

// ...
NewsMessageArea *newsMessageArea = new NewsMessageArea(/* ... */);
// ...
deliverNews.connect(boost::bind(&NewsMessageArea::displayNews,
  newsMessageArea, _1));

但是, 如果用户关闭了新闻消息区, 销毁了 newsMessageArea 对象——deliverNews 知道该对象——会怎样? 很可能会发生段错误. 不过, 通过使用 slot::track, Boost.Signals2 可以跟踪任何由 shared_ptr 管理的对象. 当槽跟踪的任何一个对象失效时, 该槽会自动断开连接. 此外, Boost.Signals2 会确保在其所关联的槽执行到一半时, 没有任何被跟踪对象失效. 它的做法是在执行槽之前, 先创建该槽的被跟踪对象的临时 shared_ptr 副本. 要跟踪 NewsMessageArea, 我们用 shared_ptr 管理其生命期, 并在连接之前通过槽的 slot::track 方法把 shared_ptr 传给槽, 例如:

// ...
boost::shared_ptr<NewsMessageArea> newsMessageArea(new NewsMessageArea(/* ... */));
// ...
deliverNews.connect(signal_type::slot_type(&NewsMessageArea::displayNews,
  newsMessageArea.get(), _1).track(newsMessageArea));

注意, 上面的示例中不需要显式调用 bind(). 如果给 signals2::slot 构造函数传入多于一个参数, 它会自动把所有参数传给 bind 并使用返回的函数对象.

还要注意, 我们把一个普通指针作为第二个参数传给槽构造函数, 即使用 newsMessageArea.get() 而不是直接传 shared_ptr 本身. 如果我们传的是 newsMessageArea 本身, 就会把 shared_ptr 的一份副本绑定进槽函数, 从而阻止 shared_ptr 失效. 然而, 使用 slot::track 意味着我们希望允许被跟踪对象失效, 并在失效发生时自动断开连接.

shared_ptr 类中除 boost::shared_ptr 以外的其他类(例如 std::shared_ptr)也可以出于连接管理的目的被跟踪. 它们由 slot::track_foreign 方法提供支持.

后构造函数与前析构函数 (高级)

使用 shared_ptr 进行跟踪的一个局限是, 对象无法在其构造函数中设置对自身的跟踪. 但是, 可以在"后构造函数"中设置跟踪, 后构造函数在对象创建完成并被传给 shared_ptr 之后调用. Boost.Signals2 库通过 deconstruct() 工厂函数提供对后构造函数与前析构函数的支持.

对于大多数情况, 为一个类设置后构造函数的最简单、最可靠的方式是: 定义一个关联的 adl_postconstruct 函数供 deconstruct() 查找, 把该类的构造函数设为私有, 并授予 deconstruct 访问这些私有构造函数的权限, 办法是把 deconstruct_access 声明为友元. 这将确保该类的对象只能通过 deconstruct() 函数创建, 并且其关联的 adl_postconstruct() 函数总会被调用.

示例 一节包含若干定义带后构造函数与前析构函数的类, 以及使用 deconstruct() 创建这些类对象的示例

注意, Boost.Signals2 中的后构造函数/前析构函数支持对库的使用绝非必需. 使用 deconstruct 纯属可选. 一种替代做法是为你的类定义静态工厂函数. 工厂函数可以创建对象, 把对象的所有权交给 shared_ptr, 为对象设置跟踪, 然后返回 shared_ptr.

何时会发生断开? (中级)

当以下任一条件发生时, 就会发生信号/槽断开连接:

  • 连接通过连接的 disconnect 方法被直接显式断开, 或通过信号的 disconnect 方法、scoped_connection 的析构函数被间接断开.

  • 槽所跟踪的对象被销毁.

  • 信号被销毁.

这些事件可以在任何时间发生, 而不会打断信号的调用序列. 如果信号/槽连接在信号调用序列进行期间的任何时刻被断开, 调用序列仍会继续, 但不会调用已被断开连接的槽. 此外, 信号可以在处于调用序列中时被销毁, 此时它会完成其槽调用序列, 但之后不可再被直接访问.

信号可以被递归调用(例如, 信号 A 调用一个槽 B, 而 B 又调用信号 A...). 在递归情形下断开行为不变, 只是槽调用序列中包含了信号所有嵌套调用的槽调用.

注意, 即使连接已被断开, 与其关联的槽可能仍在执行过程中. 换句话说, 断开连接不会阻塞等待与该连接关联的槽完成执行. 这种情形可能发生在多线程环境中——断开连接与信号调用并发进行; 也可能发生在单线程环境中——某个槽自行断开连接.

传递槽 (中级)

Boost.Signals2 库中的槽由任意函数对象创建, 因而没有固定的类型. 然而, 常见的情况是要求槽通过不可模板化的接口传递. 槽可以通过每个特定信号类型的 slot_type 来传递, 任何与该信号签名兼容的函数对象都可以传给 slot_type 参数. 例如:

// a pretend GUI button
class Button
{
  typedef boost::signals2::signal<void (int x, int y)> OnClick;
public:
  typedef OnClick::slot_type OnClickSlotType;
  // forward slots through Button interface to its private signal
  boost::signals2::connection doOnClick(const OnClickSlotType & slot);

  // simulate user clicking on GUI button at coordinates 52, 38
  void simulateClick();
private:
  OnClick onClick;
};

boost::signals2::connection Button::doOnClick(const OnClickSlotType & slot)
{
  return onClick.connect(slot);
}

void Button::simulateClick()
{
  onClick(52, 38);
}

void printCoordinates(long x, long y)
{
  std::cout << "(" << x << ", " << y << ")\n";
}

  Button button;
  button.doOnClick(&printCoordinates);
  button.simulateClick();

doOnClick 方法现在在功能上等价于 connect 方法, 也就是 onClick 信号的方法, 但 doOnClick 方法的细节可以隐藏在实现细节文件中.

示例: Document-View

信号可以用来实现灵活的 Document-View 架构. 文档将包含一个信号, 每个视图都可以连接到它. 下面的 Document 类定义了一个支持多个视图的简单文本文档. 注意, 它存储一个单一信号, 所有视图都将连接到该信号.

class Document
{
public:
    typedef boost::signals2::signal<void ()>  signal_t;

public:
    Document()
    {}

    /* Connect a slot to the signal which will be emitted whenever
      text is appended to the document. */
    boost::signals2::connection connect(const signal_t::slot_type &subscriber)
    {
        return m_sig.connect(subscriber);
    }

    void append(const char* s)
    {
        m_text += s;
        m_sig();
    }

    const std::string& getText() const
    {
        return m_text;
    }

private:
    signal_t    m_sig;
    std::string m_text;
};

接下来, 我们可以开始定义视图. 下面的 TextView 类提供了文档文本的简单视图.

class TextView
{
public:
    TextView(Document& doc): m_document(doc)
    {
        m_connection = m_document.connect(boost::bind(&TextView::refresh, this));
    }

    ~TextView()
    {
        m_connection.disconnect();
    }

    void refresh() const
    {
        std::cout << "TextView: " << m_document.getText() << std::endl;
    }
private:
    Document&               m_document;
    boost::signals2::connection  m_connection;
};

另外, 我们还可以使用 HexView 视图提供以十六进制值表示的文档视图:

class HexView
{
public:
    HexView(Document& doc): m_document(doc)
    {
        m_connection = m_document.connect(boost::bind(&HexView::refresh, this));
    }

    ~HexView()
    {
        m_connection.disconnect();
    }

    void refresh() const
    {
        const std::string&  s = m_document.getText();

        std::cout << "HexView:";

        for (std::string::const_iterator it = s.begin(); it != s.end(); ++it)
            std::cout << ' ' << std::hex << static_cast<int>(*it);

        std::cout << std::endl;
    }
private:
    Document&               m_document;
    boost::signals2::connection  m_connection;
};

为了把示例串起来, 下面是一个简单的 main 函数, 它建立两个视图然后修改文档:

int main(int argc, char* argv[])
{
    Document    doc;
    TextView    v1(doc);
    HexView     v2(doc);

    doc.append(argc == 2 ? argv[1] : "Hello world!");
    return 0;
}

完整的示例源码由 Keith MacDonald 贡献, 可在 示例 一节中找到. 我们还提供了该程序的几个变体, 它们使用自动连接管理在视图销毁时断开其连接.

让槽访问其连接 (高级)

你可能会遇到希望从槽自身内部断开或阻塞该槽连接的情况. 例如, 假设你有一组异步任务, 每个任务完成时都会发出一个信号. 你希望把一个槽连接到所有任务, 以便在每个任务完成时获取其结果. 一旦某个任务完成并且槽被运行, 该槽就不再需要连接到已完成的任务. 因此, 你可能希望通过让槽在运行时断开其发起调用的连接来清理旧连接.

要让槽断开(或阻塞)其发起调用的连接, 它必须能够访问一个引用发起调用的信号槽连接的 signals2::connection 对象. 困难在于, connection 对象由 signal::connect 方法返回, 因此直到槽已经连接到信号之后才可用. 在多线程环境中这一点尤为麻烦, 因为在槽正在被连接时, 信号可能正被另一个线程并发调用.

因此, 信号类提供了 signal::connect_extended 方法, 允许把接受一个额外参数的槽连接到信号. 该额外参数是一个 signals2::connection 对象, 它引用当前调用该槽的信号槽连接. signal::connect_extended 使用由 signal::extended_slot_type typedef 给定类型的槽.

示例一节包含一个 extended_slot 程序, 演示 signal::connect_extended 的使用语法.

更改信号的 Mutex 类型 (高级).

在大多数情况下, boost::signals2::mutex 用作 signals2::signal 的 Mutex 模板类型参数时的默认类型应当够用. 如果你想使用别的互斥量类型, 它必须可默认构造, 并满足 Boost.Thread 库定义的 Lockable 概念. 也就是说, 它必须具有 lock() 和 unlock() 方法(Lockable 概念还包括一个 try_lock() 方法, 但本库不要求 try 加锁).

Boost.Signals2 库提供了一个可与 signal 配用的替代互斥量类: boost::signals2::dummy_mutex. 这是一个用于单线程程序的假互斥量——在单线程程序中锁定真实互斥量只会带来无用的开销. 可与 signal 配用的其他互斥量类型还有 boost::mutex, 以及 C++11 的 std::mutex.

更改信号的 Mutex 模板类型参数可能很繁琐, 因为它前面有大量模板参数. signal_type 元函数在这种情况下特别有用, 因为它为 signals2::signal 类启用了命名模板类型参数. 例如, 要声明一个接受 int 作为参数、并使用 boost::signals2::dummy_mutex 作为其 Mutex 类型的信号, 可以这样写:

namespace bs2 = boost::signals2;
using namespace bs2::keywords;
bs2::signal_type<void (int), mutex_type<bs2::dummy_mutex> >::type sig;
