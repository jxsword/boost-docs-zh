说明

xpressive 是一个面向 C++ 的高级、面向对象的正则表达式模板库. 正则表达式可以写成在运行期解析的字符串, 也可以写成在编译期解析的表达式模板. 正则表达式可以相互引用并递归地引用自身, 使你能够用它们构建任意复杂的文法.

动机

如果你需要在 C++ 中操纵文本, 通常只有两个互不相干的选择: 正则表达式引擎或解析器生成器. 正则表达式引擎 (如 Boost.Regex) 功能强大且灵活; 模式以字符串表示, 可以在运行时指定. 然而, 这也意味着语法错误同样要到运行时才会被发现. 此外, 正则表达式并不适合高级文本处理任务, 例如匹配配平的嵌套标签. 这类任务传统上由解析器生成器 (如 Spirit 解析器框架) 处理. 这些工具更强大但不够灵活. 它们通常不允许你在解析过程中随意修改文法规则. 另外, 它们没有正则表达式那种穷举回溯语义, 这使得编写某些类型的模式更具挑战性.

xpressive 把这两种方法无缝地结合在一起, 在 C++ 文本处理领域占据了一个独特的位置. 使用 xpressive, 你可以像使用 Boost.Regex 那样, 把正则表达式表示为字符串; 也可以像使用 Spirit 那样, 把正则表达式写成 C++ 表达式, 享受专用于文本操作的嵌入式语言带来的全部好处. 更重要的是, 你可以把两者混合使用, 兼得双方之利: 编写正则表达式文法, 其中一些正则表达式是静态绑定的——由编译器硬编码并进行语法检查——另一些则是动态绑定、在运行时指定的. 这些正则表达式可以递归地相互引用, 匹配普通正则表达式无法匹配的字符串模式.

影响与相关工作

xpressive 接口的设计深受 John Maddock 的 Boost.Regex 库以及他向标准库添加正则表达式的提案的影响. 我还从 Joel de Guzman 的 Spirit 解析器框架中获得了大量启发, 它是静态 xpressive 的原型. 其他启发来源包括 Perl 6 的重新设计与 GRETA. (你可以在这里阅读 Perl 6 将给正则表达式文化带来的变化摘要. )
