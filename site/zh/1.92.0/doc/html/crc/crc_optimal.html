优化的 CRC 计算器 

#include <boost/cstdint.hpp>  // for boost::uintmax_t
#include <cstddef>            // for std::size_t

namespace boost
{
    template < std::size_t Bits, uintmax_t TruncPoly, uintmax_t InitRem,
     uintmax_t FinalXor, bool ReflectIn, bool ReflectRem >
    class crc_optimal;
}

boost::crc_optimal 类模板充当一个可接受字节级输入的非增广式 CRC 处理器. 它把所有 Rocksoft™ Model CRC 算法参数都作为模板参数. 与 crc_basic 一样, WIDTH 仍是第一个参数, 并决定用于除法寄存器的内建无符号整数类型. 其余 Rocksoft™ Model CRC 算法参数移到模板参数位置, 其相对顺序与它们在 crc_basic 构造函数中的顺序相同. (有些参数有默认值.) 基于 crc_optimal 的对象既可以默认构造, 使其行为与具有等效设置的 crc_basic 对象相同, 也可以使用一个参数, 该参数会覆盖初始余数值[2], 但不会永久影响初始余数属性.

除模板参数和构造之外, crc_optimal 与 crc_basic 在接口上还有以下区别:

  • 增加了五个与新增模板参数对应的类静态不可变数据成员.

  • 移除了 process_bit 和 process_bits 成员函数.
  • 增加了 operator () 成员函数的两个版本. 单参数版本转发到 process_byte, 使其适用于接受 (并可能返回) 函数对象的 STL 算法[3]. 无参数版本转发到 checksum, 使其适用于期望生成器对象的 STL 算法[4].
  • 把两个 reset 成员函数合并为一个. (它使用单个参数, 该参数可以有默认实参.)

crc_basic 与 crc_optimal 之间的主要区别在于内部实现. crc_basic 的对象无论以何种单元作为输入, 其 CRC 算法都是逐位运行的. crc_optimal 的对象, 当 WIDTH 至少为 CHAR_BIT[5] 时, 使用以字节为索引的表驱动 CRC 算法, 它比逐位处理 快得多.

由于所有参数都在编译期指定, 你无法将单个计算器对象复用于参数不同的多次独立运行. 该类型使用自动定义的复制/移动/赋值与析构例程.


[2] 即在读取任何输入之前的中间余数.

[3] 类似于 std::for_each.

[4] 不过, 在仅把该对象用作生成器的代码中, 它不会改变其返回值.

[5] 也就是说, 如果 WIDTH 只需要用到单个字节的一部分, 优化将被挂起.
