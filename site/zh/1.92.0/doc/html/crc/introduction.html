CRCs
注释

部分入门材料基于 Ross N. Williams 的 A Painless Guide to CRC Error Detection Algorithms 一文, 刊于其 The CRC Pitstop 网站.

二进制数据在传输时 (通常以电子方式) 有可能损坏. 发现这种损坏的一种方法是: 由原始数据编码生成某个值, 将该值发送给接收方, 然后在目的地对收到的数据进行编码时, 确认其生成相同的值.

接收方检查之后有几种可能:

  • 校验值在两处都匹配, 数据完整地传输了过来.
  • 数据损坏了, 校验值不匹配.
  • 数据完好, 但校验值损坏了. 这种情况无法与前一种情况区分开, 但属于 (相对) 安全的误报.
  • 数据和/或校验值损坏了, 但损坏方式使得检查编码的结果仍然一致. 这是危险的漏报!

把漏报降到最低的方法, 是选择对每次输入都产生大量变化 (尤其是变化数量可变) 的编码算法.

这些校验值被称为 校验和 (checksum), 因为它们用于 检查 数据的一致性, 而且最初的编码算法是基于加法 (即 求和) 的.

循环冗余码 是一种一致性检查, 它把消息数据视为模 2 多项式除法的一个 (长) 被除数. 模 2 运算在合并数值时不使用进位/借位. 一个具体的 CRC 定义了每次处理的固定位数, 该位数同时也是用作除数的固定多项式 (系数为模 2) 的次数.

由于模运算不涉及大小顺序, 被除数当前高位部分与试探性部分积 (除数与试探的新商系数之积) 之间的比较, 是通过查看被除数的最高次系数是否为一来完成的. (除数的最高次系数按定义必须为一, 因为它是唯一非零的选择.) 除法完成后的余数被用作 CRC 校验和的基础.

CRC 实现

对于给定的模 2 多项式除数次数 x, 余数最多有 x 项 (从 x - 1 次到常数项). 系数是模 2 的, 这意味着它们可以用 0 和 1 表示. 因此, 余数可以用一个 (无符号) 整数来建模, 该整数至少有 x 位的 宽度.

除数的 x 次项必须为一, 这意味着它总是已知的, 可以隐含而不必显式包含在表示中. 其较低的 x 项必须指定, 因此除数可以按与余数相同的方式建模. 采用这种建模, 除数的表示可以说是被截断的, 因为最高次项的值是隐含的而未存储.

余数和 (截断的) 除数多项式 存储为基本的计算机整数. 与之相对, 被除数由输入的数据位流建模, 每个新到来的位都是被除数多项式的下一个较低次项. 长除法可以分块处理, 按需读取新的高位项. 这对应于每次一个字节 (或位) 地读取数据, 即时生成更新后的余数, 而无需一次性读取 (和/或存储 (!)) 整个数据消息.

长除法在把先前的项处理进 (中间) 余数之后, 会追加新的被除数项. 因此, 在每个除法步骤中只有余数需要改变; 新的输入字节 (或位) 与余数组合构成中间被除数, 然后与部分积 (基于除数和被除数的最高位) 组合再次成为余数.

消息增广

当除法期间所有输入数据都已被读取后, 最后的 x 个位仍滞留在中间余数中. 它们尚未被推过除法步骤; 为此, 必须向系统传入 x 个额外的零值位. 这确保消息的所有数据位都得到处理. 后处理后的余数就是校验和. 系统要求消息经过 增广, 即附加 x 个额外的位, 才能得到结果.

另一种做法是, 如果除法之后的增广位改为预期的校验和, 那么余数将把校验和与自身相减, 最终余数为零. 如果数据或校验和或两者中存在位错误, 余数最终将不为零. 这种做法要求校验和从最高位开始向下喂入 (即大端序).

利用除法执行方式的特性, 各步骤可以重新安排, 使后处理的零值位不再需要; 其效果被合并到过程的开始部分. 这类系统读取 非增广 消息, 之后直接从中间余数得到校验和. (当然, 你不能在这种系统上使用“用校验和增广消息并零检查”技术.)

其他 CRC 参数

由于长除法从最高次项向下进行, 最简单的做法是把到来的字节视为最高位的未处理项, 并读取该字节内的位: 最高位是最高的未处理项, 依次向下. 不过, 一些硬件实现从最低位开始向上读取每个字节反而更容易. 为了在软件中模拟这类系统, 程序需要标记为需要应用 输入反射. 反射一个内建整数会反转其位的顺序: 最低位与最高位交换状态, 次低位与次高位交换, 等等. 输入反射可以在每个字节到来时反射它来完成, 也可以保持字节不变而反射其他内部运作. 后者听起来更难, 但现实世界中通常这样做, 因为与逐字节反射不同, 它是一次性的开销.

类似地, 一些硬件以相反的顺序处理最终余数, 这意味着模拟这类系统的软件需要标记为 输出反射 生效.

一些 CRC 并不直接返回余数 (无论是否反射), 而是增加一个额外的步骤来取补输出位. 取补把 1 变成 0, 反之亦然. 这可以通过使用全 1 (与余数位长相同) 的异或位掩码来模拟. 有些系统为了多样性使用并非全 1 的 最终异或掩码. (该掩码在任何输出反射 之后 进行.)

在另一端, 当最初的一些字节被读取时, 内建整数寄存器通常从零开始. 一些 CRC 系统并非只是在前 x 步中单纯加载输入位, 而是使用非零的 初始余数 来增加额外的处理. 由于可能与零值增广位合并, 对于同一系统的增广与非增广版本, 该初始值必须不同.

紧凑的 CRC 参数规格

Rocksoft™ Model CRC 算法 (简称 RMCA) 由 Ross Williams 设计, 用于描述给定 CRC 系统的所有规格要点 (引文如下):

RMCA 参数

WIDTH

这是以位表示的算法宽度. 它比 Poly 的宽度小一.

POLY

此参数是多项式 (poly). 它是一个二进制值, 应以十六进制数指定. 多项式的最高位应省略. 例如, 如果多项式为 10110, 则应指定 06. 该参数的一个重要方面是它表示未反射的多项式; 无论所建模的算法是否反射, 在除法期间该参数的最低位始终是除数的 LSB.

INIT

此参数指定算法开始时寄存器的初始值. 这是在直接表算法中要赋给寄存器的值. 在表算法中, 我们可以认为寄存器总是从零值开始, 而该值在第 N 次位迭代之后被异或进寄存器. 此参数应以十六进制数指定.

REFIN

这是一个布尔参数. 如果它为 FALSE, 输入字节按位 7 为最高有效位 (MSB), 位 0 为最低有效位的方式处理. 如果此参数为 FALSE, 每个字节在处理前先被反射.

REFOUT

这是一个布尔参数. 如果它被设为 FALSE, 寄存器中的最终值直接送入 XOROUT 阶段; 否则, 如果此参数为 TRUE, 寄存器的最终值先被反射.

XOROUT

这是一个 W 位的值, 应以十六进制数指定. 在该值作为正式校验和返回之前, 它与寄存器的最终值 (在 REFOUT 阶段之后) 进行异或.

他的描述假定字节为八位大小. POLY 是 (截断的) 除数. INIT 是初始余数, 前提是使用非增广版的 CRC 处理. (如果你使用的是增广式 CRC, 则必须在初始化之前消除内建零增广的效果.)

本库中的两个函数模板和两个类模板提供了执行 CRC 计算的方法. 你把各个 Rocksoft™ Model CRC 算法参数作为模板参数和/或构造函数参数给出. 然后一次性 (对于函数) 或分块 (对于类对象) 提交所有消息数据字节.

注意, 一些错误检测技术把校验和结果合并到消息数据之内, 而 CRC 校验和要么位于末尾 (在增广, 无任何一种反射, 位宽为字节大小倍数且无异或掩码的情况下), 要么带外传输.
