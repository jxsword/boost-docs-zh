理论 CRC 计算器 

#include <cstddef>  // for std::size_t

namespace boost
{
    template < std::size_t Bits >
    class crc_basic;
}

boost::crc_basic 类模板充当一个可接受位级输入的非增广式 CRC 处理器. 它只接受一个 Rocksoft™ Model CRC 算法参数作为模板参数, 即 WIDTH, 该参数决定用于除法寄存器的内建无符号整数类型. 其余 Rocksoft™ Model CRC 算法参数可以通过构造函数传入. (大多数参数都有默认值.)

用于寄存器的整数类型以 value_type 公开, 而 Rocksoft™ Model CRC 算法属性可以通过以下方式获得:

由于大多数参数是在运行期指定的, 你可以将一个计算器对象复用于参数不同的多次独立运行. 该类型使用自动定义的复制/移动/赋值与析构例程.

下面是一个复用的示例:

std::pair<unsigned, unsigned> crc_16_and_xmodem( void const *b, std::size_t l )
{
    std::pair<unsigned, unsigned>  result;
    boost::crc_basic<16>           crc1( 0x8005u, 0u, 0u, true, true );

    crc1.process_bytes( b, l );
    result.first = crc1.checksum();
    crc1 = boost::crc_basic<16>( 0x8408u, crc1.get_initial_remainder(),
     crc1.get_final_xor_value(), crc1.get_reflect_input(),
     crc1.get_reflect_remainder() );
    crc1.process_bytes( b, l );
    result.second = crc1.checksum();

    return result;
}

目前, 大多数 Rocksoft™ Model CRC 算法参数只能通过对整个对象赋值来更改.

这些参数基于 boost::crc_16_type.

更改参数以匹配 boost::crc_xmodem_type.

本示例必然要演示输入和输出. 该类有一个输出成员函数 checksum, 它返回 CRC 步骤所得的余数, 再加上任何后处理反射和/或异或掩码. 提交输入数据进行处理有几种方式:

表 9.2. boost::crc_basic 中用于输入的成员函数

成员函数

输入类型/风格

process_bit

单个位.

process_bits

给定字节中指定位数的一些位. 读取从所需的最高位开始.

process_byte

整个字节. 字节内的位按与 get_reflect_input 一致的顺序读取.

process_block

范围内的所有字节. 该范围由指向第一个字节的指针和指向末端之后一个 (字节) 的另一个指针定义.

process_bytes

范围内的所有字节. 该范围由指向第一个字节的指针和要读取的字节数定义.

目前这些输入函数不返回任何内容.

对象可以持久存在, 这意味着数据不必位于单个块中:

unsigned  combined_crc_16( unsigned block_count, ... )
{
    using namespace std;

    boost::crc_basic<16>  crc1( 0x8005u, 0u, 0u, true, true );
    va_list               ap;

    va_start( ap, block_count );
    while ( block_count-- )
    {
        void const * const  bs = va_arg( ap, void const * );
        size_t const        bl = va_arg( ap, size_t );

        crc1.process_bytes( bs, bl );
    }
    va_end( ap );

    return crc1.checksum();
}

任何 CRC 操作都不会抛出异常, 因此在各变参宏调用之间不需要额外的保护.

C 风格的可变参数例程是宏或可能是宏.

这些参数基于 boost::crc_16_type.

va_arg 调用原本位于 process_bytes 调用之内, 但我想到函数实参之间的调用顺序没有保证, 因此我需要显式的对象声明来强制提取顺序.

计算器对象受输入影响的状态可以用 get_interim_remainder 成员函数读取. 对象可以用 reset 成员函数的单参数版本加载同种状态. 该状态是对所有已输入数据执行的 CRC 运算所得的余数, 不带任何输出后处理.

这两个函数可以配合使用, 把状态保存到持久介质并在以后恢复. 注意, 如果 Rocksoft™ Model CRC 算法参数在程序中并非固定不变, 则必须通过其他手段保存/恢复它们.

不带参数调用 reset 会把中间余数设置为对象构造时 INIT 所设定的值. 这使得同一个计算器对象可以在相同的 CRC 标准下, 用不同的数据消息进行相互独立的运行.
