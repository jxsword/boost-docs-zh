函数 deconstruct

boost::signals2::deconstruct — 创建一个 shared_ptr, 支持后构造函数和前析构函数.

概要

// In header: <boost/signals2/deconstruct.hpp>


template<typename T> postconstructor_invoker<T> deconstruct();
template<typename T, typename A1> 
  postconstructor_invoker<T> deconstruct(const A1 & arg1);
template<typename T, typename A1, typename A2> 
  postconstructor_invoker<T> deconstruct(const A1 & arg1, const A2 & arg2);
template<typename T, typename A1, typename A2, ..., typename AN> 
  postconstructor_invoker<T> 
  deconstruct(const A1 & arg1, const A2 & arg2, ..., const AN & argN);

说明

仅用一次分配就创建一个对象及其所属的 shared_ptr<T> (包装在 postconstructor_invoker 内) , 方式与 boost::make_shared() 类似. 此外, deconstruct 支持后构造函数和前析构函数. 返回的 shared_ptr 被包装在 postconstructor_invoker 内, 以便为用户提供向后构造函数传参的机会, 同时确保后构造函数在被包装的 shared_ptr 可访问之前运行.

要使用 deconstruct, 必须为你的类定义一个后构造函数. 更具体地说, 必须定义一个可通过参数依赖查找找到的 adl_postconstruct 函数. 通常, 这意味着在其关联类所在的命名空间中定义一个 adl_postconstruct 函数. 参见 postconstructor_invoker 的参考文档, 其中规定了传给 adl_postconstruct 调用的实参.

可选地, 你可以为你的类定义一个前析构函数. 做法是定义一个可通过参数依赖查找找到的 adl_predestruct 函数. shared_ptr (由 deconstruct 创建) 的删除器会以单个实参调用 adl_predestruct (非限定调用) : 一个指向即将被删除的对象的指针. 为方便起见, 该指针在被传给 adl_predestruct 之前总是会被转换为指向非 const 类型. 如果通过参数依赖查找找不到用户定义的 adl_predestruct 函数, 则使用默认函数 (什么都不做) . 在 adl_predestruct 被调用之后, 删除器会用 checked_delete 删除该对象.

传给 deconstruct() 调用的任何实参都会被转发到模板类型 T 的匹配构造函数. 也可以把实参传给该类关联的 adl_postconstruct 函数, 方法是使用 postconstructor_invoker::postconstruct() 方法.

注释:

如果你的编译器支持 C++11 的右值引用和变参模板特性, 则 deconstruct 将使用如下原型对实参进行到 T 构造函数的完美转发:

template< typename T, typename... Args > postconstructor_invoker< T > deconstruct( Args && ... args );

否则, 如概要所示, 实参转发通过 const 引用进行. 要把非 const 引用传给构造函数, 你需要用 boost::ref 把它们包装进引用包装器.

要让所有 deconstruct 重载访问你的类的私有和受保护构造函数, 可以把 deconstruct_access 声明为友元. 将私有构造函数与 deconstruct_access 结合使用会很有用, 可以确保你的对象只能由 deconstruct 创建, 从而其后构造函数或前析构函数总会被调用.

返回:

一个 postconstructor_invoker<T>, 拥有一个新分配的类型为 T 的对象.
