函数 relaxed_get

boost::relaxed_get — 从给定的 variant 中检索指定类型的值. 与 strict_get 不同, 它不会在编译期断言类型 U 是可存入 variant 的类型之一.

概要

// In header: <boost/variant/get.hpp>


template<typename U, typename T1, typename T2, ..., typename TN> 
  U * relaxed_get(variant<T1, T2, ..., TN> * operand);
template<typename U, typename T1, typename T2, ..., typename TN> 
  const U * relaxed_get(const variant<T1, T2, ..., TN> * operand);
template<typename U, typename T1, typename T2, ..., typename TN> 
  U & relaxed_get(variant<T1, T2, ..., TN> & operand);
template<typename U, typename T1, typename T2, ..., typename TN> 
  const U & relaxed_get(const variant<T1, T2, ..., TN> & operand);
template<typename U, typename T1, typename T2, ..., typename TN> 
  U && relaxed_get(variant<T1, T2, ..., TN> && operand);

说明

get 函数允许以运行期检查的类型安全方式检索给定 variant 的内容. 仅当内容为指定类型 U 时该函数才成功, 失败时按下文所述方式指示.

建议: 在新代码中使用 get 或 strict_get. strict_get 提供更多编译期检查, 其行为更接近 C++ 标准库中的 std::get.

警告: 当 operand 或其内容被销毁后 (例如, 当给定的 variant 被赋以不同类型的值时) , 返回的引用即失效. 因此, 在处理返回的引用时必须格外小心谨慎.

注释:

 作为其类型安全保证的一部分, get 强制实施 const 正确性. 因此, 指定的类型 U 必须带 const 限定, 只要 operand 或其内容也带 const 限定. 反之则无此要求: 也就是说, 指定的类型 U 可以带 const 限定, 即使 operand 及其内容不带.

返回:

 如果传入指针, get 在值内容为指定类型 U 时返回指向该值内容的指针; 否则返回空指针. 如果传入引用, get 在值内容为指定类型 U 时返回对该值内容的引用; 否则抛出异常 (见下文) .

抛出:

 接受 variant 指针的重载不会抛出异常; 接受 variant 引用的重载会抛出 bad_get, 如果内容不是指定类型 U.

设计理由:

 虽然通过 apply_visitor 进行访问因安全性更高而通常更受青睐, 但 get 因用法直接, 在某些情况下可能更为便利.
