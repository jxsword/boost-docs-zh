类 vector 容器的默认初始化

STL 和大多数其他容器在常见操作 (如 vector::resize(size_type n) 或 explicit vector::vector(size_type n)) 中对新元素进行值初始化.

在一些性能敏感的环境中, vector 被用作文件或网络操作的可变大小缓冲区的替代品, 此时 值初始化 的开销不可忽略, 因为新元素添加到容器后很快就会被外部来源覆盖.

Boost.Container 为 vector, static_vector 和 stable_vector: explicit container::container(size_type n, default_init_t) 和 container::resize(size_type n, default_init_t), 其中新元素使用 默认初始化 构造.

关联容器的有序范围插入 (ordered_unique_range, ordered_range)

填充关联容器时, 若用户保证要插入的输入范围已按谓词排序, 则可以获得巨大的性能提升. 这可能发生在从 set 插入值到 multiset 时, 或在不同关联容器家族之间 ([multi]set/map 与 flat_[multi]set/map).

Boost.Container 为构造函数和插入操作提供了一些重载, 它们接受 ordered_unique_range_t 或 ordered_range_t 标签参数作为第一个参数. 使用 ordered_unique_range_t 重载时, 用户通知容器输入范围已按容器谓词排序且无重复. 使用 ordered_range_t 重载时, 用户通知容器输入范围已按容器谓词排序但可能有重复. 有了这一信息, 容器可以避免多次谓词调用并缩短插入时间.

常量时间范围 splice, 适用于 (s)list

在第一个 C++ 标准中, list::size() 并不要求为常量时间, 这在 C++ 社区中引起了一些争议. 引用 Howard Hinnant 的论文 On List Size:

关于 std::list<T>::size() 应为 O(1) 还是 O(N) 存在相当多的争论. 通常的论点指出这是一种权衡:

splice(iterator position, list& x, iterator first, iterator last);

若 size() 为 O(1) 且 this != &x, 则此方法必须执行线性操作, 以便调整每个 list 中的 size 成员

C++11 明确要求 size() 为 O(1), 因此范围 splice 变成了 O(N). 不过, Howard Hinnant 的论文提出了一个新的 splice 重载, 使得即使是 O(1) 的 list:size() 实现, 在调用者知道范围大小时也能实现 O(1) 的范围 splice:

void splice(iterator position, list& x, iterator first, iterator last, size_type n);

效果: 将范围 [first, last) 中的元素插入到 position 之前, 并从 x 中移除这些元素.

要求: [first, last) 是 x 中的有效范围. 若 position 是范围 [first, last) 中的迭代器, 则结果未定义. 仅使指向被拼接元素的迭代器和引用失效. n == distance(first, last).

抛出: 无.

复杂度: 常量时间.

这个新的 splice 签名允许调用者传入输入范围的距离. 这一信息在调用点通常是已知的. 若传入该信息, 则即使 size 为 O(1), 操作也是常量时间.

Boost.Container 为 list 实现了此重载, 并为 slist 实现了其修改版本 (因为 slist::size() 也是 O(1)).
