Boost.Container 历史

Boost.Container 是一项长期开发工作的产物, 始于 2004 年的实验性 Shmem 库, 该库率先在共享内存中使用标准容器. Shmem 包含经过修改的 SGI STL 容器代码, 经调整以支持非原始的 allocator::pointer 类型和有状态分配器. 经过评审后, Shmem 被接受为 Boost.Interprocess, 该库随后持续改进和完善这些容器.

2007 年, 来自节点容器 (map, list, slist) 的容器代码被重写、重构并扩展, 用于构建侵入式容器库 Boost.Intrusive. Boost.Interprocess 的容器经重构以利用 Boost.Intrusive 容器, 并将代码重复降至最低. 多年来这两个库持续获得支持与缺陷修复. 它们引入了移动语义、就地构造插入以及当时尚未发布的 C++0x 标准的更多特性.

Boost.Interprocess 的容器始终符合标准, 这些容器以及诸如 stable_vector 和 flat_[multi]set/map 之类的新容器在 Boost.Interprocess 之外也得到了成功使用. 这些容器当时已经足够成熟, 足以拥有自己的库, 因此很自然地将它们汇集起来, 构建了 Boost.Container, 一个面向更广泛受众的库.

致谢、说明与链接

  • 最初的标准容器代码来自 SGI STL 库, 该库增强了最初的 HP STL 代码. 这些代码为 Boost.Interprocess 重写, 并迁移到 Boost.Intrusive. 非常感谢 Alexander Stepanov, Meng Lee, David Musser, Matt Austern... 以及所有 HP 和 SGI STL 开发者.
  • flat_[multi]_map/set 容器最初基于 Loki 的 AssocVector 类. 代码为 Boost.Interprocess 重写并扩展, 因此感谢 Andrei Alexandrescu.
  • stable_vector 由 Joaquín M. López Muñoz 发明并编写, 后经适配用于 Boost.Interprocess. 感谢如此出色的容器.
  • static_vector 基于 Andrew Hundt 和 Adam Wulkiewicz 的高性能 varray 类. vector 的许多性能改进也受到其实现的启发. 谢谢!
  • devector 的初始实现基于 Thaler Benedek 的高性能 devector 实现, 后经适配用于 Boost.Container. 同时也受到 Orson Peters 和 Lars Hagen 类似实现的启发. 感谢如此出色的代码和文档!
  • Howard Hinnant 的帮助和建议在实现移动语义、改进分配器支持以及实现小字符串优化时至关重要. 感谢 Howard 出色的标准库实现.
  • 最后, 感谢所有这些年来提供帮助的 Boosters, 他们改进、修复并评审了我所有的库.

Boost 1.92 发布

  • 新增了由 Joaquín M. López Muñoz 设计的 hub 容器. 更多信息参见 Hub Container 章节.
  • 已修复的缺陷/问题:
    • GitHub #334: "P2363R5 实现中的错误重载决议保护".
    • GitHub #336: "erase 与 small_vector<std::string> 的编译错误".
    • GitHub #338: "uses_allocator_construction.hpp: 缺少 #include .../config_end.hpp".
  • 添加 unchecked_emplace_back 和 unchecked_push_back 至 vector, static_vector 和 small_vector.
  • 实现了 C++23 P1518 变更, 修改了所有容器的分配器扩展构造函数, 使容器的推导指引不再过度受限.

Boost 1.91 发布

  • 实现了来自 C++23 (P2077) 和 C++26 (P2363) 的异构重载.
  • 在 C++20 编译器中, static_vector<T> 的析构函数在 T 为平凡时现在也是平凡的.
  • 使用分配器构造 (uses-allocator construction) 现在即使在 C++03 中也能处理前缀和后缀分配器约定.
  • 实现了 C++20 的 uninitialized_construct_using_allocator 和 make_obj_using_allocator.
  • 为若干分配器和 PMR 工具添加了 [[nodiscard]].
  • 为 new_allocator 和 pmr::new_delete_resource() 实现了超对齐分配支持:
    • 若可用, 则在 __cpp_aligned_new 特性下使用 C++17 的工具.
    • 否则使用替代的对齐分配函数 (posix_memalign, aligned_alloc, _aligned_malloc...).
  • 为 adaptive_pool 和 node_allocator 实现了超对齐分配支持
  • 将 erase/erase_if/unique 成员 (位于 list 和 slist 中) 的返回类型更改为 size_type, 以遵循 C++20 对 std::list 的变更.
  • 更新了 basic_string:
    • 添加了缺失的 string_view 成员, 并更新了 operator[] 使其能够返回结尾空字符.
    • 添加了 C++20 starts_with/ends_with 和 C++23 contains 重载.
    • 为 basic_string 中接受 const CharT* 参数的方法添加了空指针检查.
    • 从 std::nullptr_t 中删除了构造函数.
    • 添加 inline_chars, growth_factor 和 stored_size 选项至 basic_string.
    • 新增 segtor 容器: deque 的单端兄弟: 一种具有分段 (基于块) 存储的随机访问序列容器, 类似 deque 但只在尾部增长.
  • 已修复的缺陷/问题:
    • GitHub #323: "flat_tree::try_emplace 未定义行为".
    • GitHub #328: "boost::container::deque 存储了多余的分配器副本, 导致体积增大".
    • GitHub #332: "XCode 12 上 C++11/14 中 aligned_alloc 不可用".

Boost 1.90 发布

  • 重新实现了 boost::container::deque. 原实现基于 SGI 的原始数据结构 (与 libstdc++ 类似). 主要更改:
    • sizeof(deque) 原先占 10 个字 (word), 现在只占 4 个字. 可能是现有实现中最轻量的.
    • sizeof(deque::iterator) 原先占 4 个字, 现在只占 2 个字 (与 libc++ 和 MSVC 类似).
    • 重新实现了若干内部算法, 以加速 deque 的分段特性.
    • 默认值略有更改, 64 位平台现在默认使用 1024 字节块, 而非经典的 SGI 512 字节块.
    • 新实现为将来进一步的 deque 类变体和优化铺平了道路.

Boost 1.81 发布

  • devector 的插入逻辑已重新实现: 当在一端插入没有空闲容量而另一端有空闲容量时, 将元素移动到 devector 的中心. 当前实现在仅向一端插入并从另一端弹出时会不断重新分配内存, 导致内存占用非常高. 新策略基于文章 Double-ended vector - is it useful? (作者 Lars Greger Nordland Hagen).
