扩展功能: 扩展分配器 (Extended allocators)

许多 C++ 程序员都想过, 好用的老牌 realloc 在 C++ 中处于什么位置. 这是个好问题. 我们能否使用内存扩展机制来改善 vector 的性能, 避免过多复制? 但 vector 并不是唯一能从改进的分配器接口中受益的容器: 我们可以利用突发分配机制在 list 中插入多个元素, 该机制能摊销使用单节点分配策略时无法摊销的开销 (互斥锁、空闲内存查找...).

这些改进需要扩展 STL 分配器接口, 并使用一个新的通用分配器, 因为 new 和 delete 不提供扩展和突发能力.

  • Boost.Container 容器支持一种扩展分配器接口, 它基于提案 N1953: Upgrading the Interface of Allocators using API Versioning, N2045: Improving STL allocators 的演进以及文章 Applying classic memory allocation strategies to C++ containers. 该扩展分配器接口由 allocator, adaptive_pool 和 node_allocator 类实现.
  • 扩展分配器使用修改过的 Doug Lea Malloc (DLMalloc) 低层分配器, 并提供用于实现内存扩展和突发分配的 C API. DLmalloc 以极高的体积与速度效率著称, 许多 malloc 实现都以该分配器为基础, 包括构建在 DLmalloc 之上的多线程分配器 (参见 ptmalloc2, ptmalloc3 或 nedmalloc). 这个低层分配器实现为一个单独编译的库, 以下扩展分配器依赖该库:
  • allocator: 这个扩展分配器提供扩展、原地收缩和突发分配能力, 实现为修改版 DLMalloc 之上的薄封装. 它可以搭配所有容器使用, 当程序员想使用扩展分配器能力时, 它应是默认选择.
  • node_allocator: 这是一个 Simple Segregated Storage 分配器, 类似于 Boost.Pool, 它利用修改版 DLMalloc 的突发接口. 除非显式请求, 否则它不会将内存归还给 DLMalloc 分配器 (因而也不会归还给系统). 它的内存开销极小, 因此适合那些分配极小 value_type 的节点容器 ([boost::container::list list], [boost::container::slist slist] [boost::container::set set]...), 并且在单节点分配时, 其节点分配时间优于 allocator.
  • adaptive_pool: 这是一个可以把内存归还系统的低开销节点分配器. 其开销可以非常低 (小节点低于 5%), 且速度几乎与 node_allocator 一样快. 它也适合节点容器.

只需在喜欢的容器的相应模板实参中指定新分配器即可使用它们:

#include <boost/container/vector.hpp>
#include <boost/container/flat_set.hpp>
#include <boost/container/list.hpp>
#include <boost/container/set.hpp>

//"allocator" is a general purpose allocator that can reallocate
//memory, something useful for vector and flat associative containers
#include <boost/container/allocator.hpp>

//"adaptive_pool" is a node allocator, specially suited for
//node-based containers
#include <boost/container/adaptive_pool.hpp>

int main ()
{
   using namespace boost::container;

   //A vector that can reallocate memory to implement faster insertions
   vector<int, allocator<int> > extended_alloc_vector;

   //A flat set that can reallocate memory to implement faster insertions
   flat_set<int, std::less<int>, allocator<int> > extended_alloc_flat_set;

   //A list that can manages nodes to implement faster
   //range insertions and deletions
   list<int, adaptive_pool<int> > extended_alloc_list;

   //A set that can recycle nodes to implement faster
   //range insertions and deletions
   set<int, std::less<int>, adaptive_pool<int> > extended_alloc_set;

   //Now user them as always
   extended_alloc_vector.push_back(0);
   extended_alloc_flat_set.insert(0);
   extended_alloc_list.push_back(0);
   extended_alloc_set.insert(0);

   //...
   return 0;
}
