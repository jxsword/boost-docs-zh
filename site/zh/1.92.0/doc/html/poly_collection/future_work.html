评审者和 Boost.PolyCollection 用户所要求的一些特性, 正在考虑纳入本库的未来版本之中.

替代 RTTI 系统

Boost.PolyCollection 可以被扩展以在缺乏 RTTI 支持的场景中使用 Boost.TypeIndex. 进一步延伸这一思路, 某些环境 (例如游戏引擎) 提供自己的 RTTI 框架并不罕见: 那么, 对 Boost.PolyCollection 更具雄心的扩展, 就是通过某种特征类 (traits class) 指定 std::type_info 和 typeid 的替代物, 使其可配置为使用用户提供的 RTTI.

拷贝特征

boost::base_collection 要求所存储的对象既是 MoveConstructible 又是 MoveAssignable; 遗憾的是, OOP 层次结构中习惯上会限制拷贝以避免切片 (slicing), 这将迫使用户为使用 Boost.PolyCollection 而重新审视其类定义. 通过提供一个可配置的特征类可以缓解这一问题, 其中拷贝和赋值可在外部定义

template<typename T>
struct copy_traits
{
  void construct(void*,T&&);
  void assign(T&,T&&);
};

, 其默认实现则采用常规的 placement new 和 T::operator=.

并行算法

C++17 引入了 并行算法, 例如 std::for_each 的并行版本; 因此, 提供相应的 Boost.PolyCollection 专用算法 便是顺理成章之事. 多态集合的分段特性使其特别适合并行处理.

有序多态集合

用户已表示对以下多态集合感兴趣: 元素在其段内保持有序, 并可选地排除重复项, 就像 boost::flat_set/boost::flat_multiset 对其内部数据向量所做的那样. 悬而未决的问题是, 这些集合是否还应保证段之间的某种顺序 (现有的集合并不保证), 以便能够定义容器级的 operator< 及相关运算符.
