多态模型

动态多态的关键方面是: 类型为 T 的值能够在内部使用另一个可能不同类型的值 U 来实现某一给定接口. 基类/派生类多态是 C++ 中经典的动态多态模型, 但不是唯一可能的模型.

形式上, 一个 多态模型 由以下内容定义

  • 一个由允许的接口类型组成的族 Interface; 并且对每个 I ∈ Interface, 有一个由满足以下条件的类型组成的族 Implementation(I): I.
  • 对于给定的接口类型 I, 一个操作 subobject(x), 它将实现类型的每个值映射到其内部使用的、可能属于另一实现类型的值 y [21].

静态多态是 subobject(x) = x 对所有 x 都成立的平凡情形. 基类/派生类多态的特征由以下几点刻画:

  • Interface = { Base : std::is_polymorphic_v<Base> }.
  • Implementation(Base) = { Derived : std::is_base_of_v<Base,Derived> }.
  • subobject(x) = static_cast<Derived&>(x) 其中 typeid(x)==typeid(Derived).

一个多态模型被称为封闭的, 如果对任意 I ∈ Interface, suboject 的取值范围是 Implementation(I) 中类型的一个有限子集, 即子对象可以属于的类型只有有限多个. 非封闭的模型称为开放的.

多态容器

多态集合

多态容器 是一种存储某类型 T 对象的对象, 这些对象在隐式关联的多态模型下实现给定接口 I. 多态容器满足 Container 和 AllocatorAwareContainer 的要求, 但有以下修改:

  • 在出现之处, 将关于 T 须为 CopyInsertable、CopyAssignable、MoveInsertable、MoveAssignable 或 EqualityComparable 的要求, 替换为以下语义条款: 若容器中的某个子对象不是 CopyConstructible (分别为 CopyAssignable、MoveConstructible、MoveAssignable、EqualityComparable), 则可能抛出异常.
  • 将 [container.requirements.general]/3 替换为: allocator_type 必须具有如下性质: 对任何类型 U, 其实现 I, 且关联类型 A = std::allocator_traits<allocator_type>::rebind_alloc<U>: U 是 CopyInsertable (分别为 MoveInsertable), 这是相对于 A 而言的, 当且仅当 U 是 CopyConstructible (分别为 MoveConstructible); 存储在这些容器中的所有 U 类型的子对象, 都应当使用 std::allocator_traits<A>::construct 函数构造, 并使用 std::allocator_traits<A>::destroy 函数销毁; 这些函数 (或针对重绑定分配器的等价函数) 仅为所存储子对象的类型而调用, 而不为容器使用的任何其他类型 (内部或公开) 调用.

多态集合 将其 value_type 类型的对象存储在专属于所含子对象各类型的 段 之中. 仅允许其子对象为可接受类型的对象, 其中类型 U 被称为可接受的, 如果

  • 它实现与该容器关联的接口,
  • 它是 MoveConstructible,
  • 它是 MoveAssignable, 或者 std::is_nothrow_move_constructible<U>::value 是 true.

若其关联的多态模型是开放的 (相应地, 封闭的), 则称该集合为开放的 (相应地, 封闭的). 多态集合遵循 PolymorphicContainer 的要求, 并带有以下修改和额外保证:

  • empty() 和 size() 的复杂度与集合的段数呈线性关系.
  • 不提供 max_size().
  • a==b 求值为 true, 当且仅当对于 U 类型的子对象在 a 中的每个非空段, 都存在一个由 U 组成、位于 b 中的段, 其大小相同且元素按相同顺序相等, 反之亦然.
  • 不会抛出与某个子对象类型不是 CopyAssignable、MoveConstructible 或 MoveAssignable 相关联的异常.

类型 U 被称为已注册到集合中, 如果已为 U 创建了一个 (可能为空的) 段. 已注册类型在容器的整个存续期间保持注册状态, 除非容器被移动、被赋值或被交换. 对于封闭集合, 所有可接受类型在构造时自动注册.

每个段都有一个关联的容量, 指示其在无需重新分配的情况下可达到的最大大小. 当超出该限制时 (或通过 reserve 显式触发), 将分配具有更大容量的新存储空间, 并移动元素.

集合遍历依次经过第一个段的元素, 然后是第二个段, 依此类推. 对于开放集合, 段被访问的顺序是未指定的, 但在创建新段之前保持稳定. 对于封闭集合, 段顺序是固定的, 由集合类型的规范决定.

除 iterator 和 const_iterator 之外, 还有迭代器类型 local_base_iterator 和 local_iterator<U> (及其 const_ 对应类型), 其对象可用于遍历 U 的段 (以与全局遍历相同的顺序). 局部基迭代器指向 value_type, 而 (const_)local_iterator<U> 则指向 U. 所有局部迭代器都模拟 RandomAccessIterator. 局部基迭代器不可用于跨段遍历, 比较关联到不同段的局部基迭代器是未定义行为. 指向 U 的段的 (const) 局部基迭代器, 可显式转换为指向同一位置的 (const_)local_iterator<U>, 反之亦然.

插入和擦除不会使迭代器 (全局或局部) 失效, 但以下情形除外: 若未超出受影响段的容量, 则从插入/擦除点到该段末尾的迭代器会失效; 否则, 指向该段的所有迭代器/引用都会失效 [22].

为描述多态集合的其余要求, 我们使用以下记法:

  • C 是一个多态集合类型,
  • c 是类型 C 的对象, cc 是一个可能 const 的、类型为 C 的对象,
  • al 是 C::allocator_type 类型的一个值,
  • info 是 const C::index_type& 类型的一个值,
  • U 是一个可接受类型, Us... 是可接受类型的模板参数包,
  • n 是 size_type 的一个值,
  • x 是类型 T 的一个值, 该类型实现与集合关联的接口,
  • args... 是类型 Args&&... 的函数参数包,
  • it 是 c 的可能 const 全局迭代器,
  • it1 和 it2 是 C 集合 (非 c) 的 (同类型的) 可能 const 全局迭代器, 且 [it1, it2) 是有效范围.
  • lbit 是 c 的可能 const 局部基迭代器,
  • lbit1 和 lbit2 是 C 集合 (非 c) 的 (同类型的) 可能 const 局部基迭代器, 且 [lbit1, lbit2) 是有效范围.
  • lit 是一个 (const_)local_iterator<U> (属于 c),
  • lit1 和 lit2 是 (同类型的) (const_)local_iterator<U> (属于 C 集合, 非 c), 且 [lit1, lit2) 是有效范围,
  • i1 和 i2 是 c 之外指向 T 的迭代器, 且 [i1, i2) 是有效范围,
  • j1 和 j2 是 c 之外的迭代器, 且 [j1, j2) 是有效范围,
  • xit1 和 xit2 是 c 的 (同类型的) 可能 const 迭代器 (全局或局部), 且 [xit1, xit2) 是有效范围.
类型宏

C::type_index

可以是 std::type_info 或 std::size_t. 我们将 index<U> 定义如下:

  • 若 type_index 为 std::type_info: 则为 typeid(U),
  • 若 type_index 为 std::size_t: 则为索引号 i, 使得 U 是第 i 个元素 (位于 Us... 之中), 其中 Us... 是关联多态模型中所指定的可接受类型列表.

C::local_base_iterator

RandomAccessIterator, 其值类型、差值类型以及指针和引用类型与 C::iterator 相同, 可用于访问给定段的元素. 可隐式转换为 C::const_local_base_iterator; 若其所指向的段可显式转换为 C::local_iterator<U> (若其所指向的段实际上就是 U 的段).

C::const_local_base_iterator

RandomAccessIterator, 其值类型、差值类型以及指针和引用类型与 C::const_iterator 相同, 可用于访问给定段的元素. 可显式转换为 C::const_local_iterator<U> (若其所指向的段实际上就是 U 的段).

C::local_iterator<U>

RandomAccessIterator, 其值类型为 U, 引用类型为 U&, 指针类型为 U*, 差值类型与 C::iterator 相同, 可用于访问 U 的段的元素. 可隐式转换为 C::const_local_iterator<U>, 可显式转换为 C::local_base_iterator.

C::const_local_iterator<U>

RandomAccessIterator, 其值类型为 U, 引用类型为 const U&, 指针类型为 const U*, 差值类型与 C::iterator 相同, 可用于访问 U 的段的元素. 可显式转换为 C::const_local_base_iterator.

C::const_base_segment_info

CopyConstructible 和 CopyAssignable 类型, 携带关于集合某一给定段的信息. 若 ci 是一个可能 const 的、类型为 C::const_base_segment_info 的对象, 且关联到 c 的 U 段, 则

  • ci.begin()==c.cbegin(index<U>)
  • ci.cbegin()==c.cbegin(index<U>)
  • ci.begin<U>()==c.cbegin<U>()
  • ci.cbegin<U>()==c.cbegin<U>()
  • ci.end()==c.cend(index<U>)
  • ci.cend()==c.cend(index<U>)
  • ci.end<U>()==c.cend<U>()
  • ci.cend<U>()==c.cend<U>()
  • ci.type_info()==index<U>

C::base_segment_info

CopyConstructible 和 CopyAssignable 类型, 公开派生自 C::const_base_segment_info 并暴露其公开接口. 此外, 若 i 是类型为 C::base_segment_info 的对象, 且关联到 c 的 U 段, 则

  • i.begin()==c.begin(index<U>)
  • i.begin<U>()==c.begin<U>()
  • i.end()==c.end(index<U>)
  • i.end<U>()==c.end<U>()

C::const_segment_info<U>

CopyConstructible 和 CopyAssignable 类型, 携带关于 U 段的信息. 若 ci 是一个可能 const 的、类型为 C::const_segment_info<U> 的对象, 且关联到集合 c, 则

  • ci.begin()==c.cbegin<U>()
  • ci.cbegin()==c.cbegin<U>()
  • ci.end()==c.cend<U>()
  • ci.cend()==c.cend<U>()

C::segment_info<U>

CopyConstructible 和 CopyAssignable 类型, 公开派生自 C::const_segment_info<U> 并暴露其公开接口. 此外, 若 i 是类型为 C::segment_info<U> 的对象, 且关联到集合 c, 则

  • i.begin()==c.begin<U>()
  • i.end()==c.end<U>()

C::base_segment_info_iterator

InputIterator, 其值类型和引用类型为 C::base_segment_info.

C::const_base_segment_info_iterator

InputIterator, 其值类型和引用类型为 C::const_base_segment_info.

C::const_segment_traversal_info

CopyConstructible 和 CopyAssignable 类型, 带有 const 成员函数 begin/cbegin 和 end/cend, 返回 C::const_base_segment_info_iterator 对象, 这些对象跨越 C::const_base_segment_info 对象的一个范围.

C::segment_traversal_info

CopyConstructible 和 CopyAssignable 类型, 公开派生自 C::const_segment_traversal_info 并暴露其公开接口. 此外, 提供非 const 成员函数 begin 和 end, 返回 C::base_segment_info_iterator 对象, 这些对象跨越等价的 C::base_segment_info 对象范围.

所提供的算法模拟其在 <algorithm> 中同名算法的功能, 但利用 Boost.PolyCollection (全局) 迭代器的分段特性来提供更好的性能. 此外, 可以向这些算法传递具体类型以进行 类型恢复.

为描述这些算法, 我们使用以下记法:

  • alg 是 "boost/poly_collection/algorithm.hpp" 中任一算法的 (无限定) 名称, 但 for_each_n、copy_n 和 rotate_copy 除外.
  • first、middle 和 last 是 Boost.PolyCollection 某集合的 (同类型的) 可能 const 全局迭代器, 且 [first, middle) 和 [middle, last) 是有效范围.
  • args... 是类型 Args&&... 的函数参数包,
  • Ts... 是该集合的可接受类型的模板参数包, 封闭集合情形下还额外可选 all_types.
    • 开放集合: Us... 定义为 Ts....
    • 封闭集合: Us... 定义为集合中所有可接受类型的集合 (若 all_types 在 Ts... 中), 否则定义为 Ts....

(1) alg(first,last,args...)
(2) for_each_n(first,args...)
(3) copy_n(first,args...)
(4) rotate_copy(first,middle,last,args...)

要求: 表达式 expr 是合式的, 其中 expr 定义为:
(1) std::alg(first,last,args...),
(2) std::for_each_n(first,args...),
(3) std::copy_n(first,args...),
(4) std::rotate_copy(first,middle,last,args...).
效果: 等价于 expr.
返回: expr.
复杂度: 即 expr 的复杂度.

(1) alg<Ts...>(first,last,args...)
(2) for_each_n<Ts...>(first,args...)
(3) copy_n<Ts...>(first,args...)
(4) rotate_copy<Ts...>(first,middle,last,args...)

要求: 表达式 expr 是合式的, 其中 expr 定义为:
(1) std::alg(rfirst,rlast,args...),
(2) std::for_each_n(rfirst,args...),
(3) std::copy_n(rfirst,args...),
(4) std::rotate_copy(rfirst,rmiddle,rlast,args...),
且 rfirst、rmiddle 和 rlast 是行为类似于其 first、middle 和 last 对应物的类迭代器对象, 但其解引用得到相应的子对象 (const)U& (若指向 U 的段且 U 在 Us... 中 [26]).
效果: 等价于 expr.
返回: expr.
复杂度: 即 expr 的复杂度.
注释: 对于封闭集合, 若 Us... 非空且包含集合的所有可接受类型 (完全恢复, total restitution), 则 rfirst、rmiddle 和 rlast 向集合的 value_type 的解引用操作永远不会被实例化.
