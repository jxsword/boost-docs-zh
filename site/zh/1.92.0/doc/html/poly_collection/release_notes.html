Boost 1.92

  • 使 variant_collection_value_type_impl<Ts...> 的关系运算符仅在相应关系运算符对所有 Ts... 都可用时才可用, 以符合 WG21 论文 P2944R3.
  • 修复了与 libc++ v21 及更高版本的不兼容问题 (PR#34).

Boost 1.88

  • 新增 boost::variant_collection, 一个行为类似于 std::vector<std::variant<...>> 的封闭多态集合.

Boost 1.76

  • 规避了影响 GCC 9.3-10.2 版本的 GCC 缺陷 (issue #20).

Boost 1.74

  • 修复了 boost::type_erasure::any 和 boost::any 之间的内部二义性问题 (issue #17).
  • 维护性工作.

Boost 1.73

  • 消除了 boost::poly_collection::for_each 中一个潜在的冗余移动警告.
  • 修复了一个缺陷: 在具有不传播且不相等分配器的集合之间进行分配器扩展的移动构造和移动赋值时, 元素会被拷贝而非移动.
  • 对于 GCC 4.8 附带的旧版 libstdc++-v3 (Clang 也可使用), 分配器扩展的移动构造不再退化为分配器扩展的拷贝构造.

Boost 1.72

  • 维护性工作.

Boost 1.71

  • 维护性工作.

Boost 1.70

  • 在 Billy O'Neal 报告一个错误 (PR#9) 之后, 改进了对有状态分配器和分配器传播特征的处理.
  • 修复了内部缓存结构中一个潜在的严重缺陷.

Boost 1.69

  • 新增了算法 std::for_each_n 和 std::sample 的 Boost.PolyCollection 专用版本.

Boost 1.67

  • 维护性修复.

Boost 1.66

  • Boost.PolyCollection 已向后移植到 GCC 4.8 至 4.9 以及 Clang 3.3 至 3.6. GCC 4.8 附带的 libstdc++-v3 版本 (Clang 也可使用) 存在一些缺陷, 导致使用 Boost.PolyCollection 时有以下限制:
    • 未正确支持有状态分配器.
    • 分配器扩展的移动构造会退化为分配器扩展的拷贝构造.
    • 如果在元素拷贝过程中抛出异常, 拷贝构造会崩溃.
  • 维护性修复.

Boost 1.65

  • 初始发布.
