(测试程序位于 perf.cpp.)

我们运行了测试, 以衡量 Boost.PolyCollection 各容器在以下两种场景中的性能:

  • 元素的插入.
  • 使用 std::for_each 和 boost::poly_collection::for_each 进行线性遍历和处理 (分别采用和不采用 类型恢复).

作为比较基线, 我们使用了来自标准库和 Boost 的容器与设施 (细节见下文). 测试在一台配备 8GB 内存和 Intel Core i5-8265U CPU @1.60GHz (基准频率) 的 Windows 10 机器上, 针对以下环境进行:

  • Visual Studio 2022 x64: 64 位 (x64) 的 Visual Studio 2022, release 模式
  • GCC 13.2 x64: MinGW 下的 GCC 13.2.0, -O3 -DNDEBUG
  • Clang 13.0 x64: Visual Studio 下的 Clang 13.0.1 (clang-cl), 64 位 (x64), release 模式

boost::base_collection

  • 基线容器: ptr_vector = boost::ptr_vector<base>
  • 多态集合: base_collection = boost::base_collection<base>
  • 元素类型: T1 = derived1, T2 = derived2, T3 = derived3 
struct base
{
  virtual ~base()=default;
  virtual int operator()(int)const=0;
};

struct derived1 final:base
{
  derived1(int n):n{n}{}
  virtual int operator()(int)const{return n;}

  int n;
};

struct derived2 final:base
{
  derived2(int n):n{n}{}
  virtual int operator()(int x)const{return x*n;}

  int unused,n;
};

struct derived3 final:base
{
  derived3(int n):n{n}{}
  virtual int operator()(int x)const{return x*x*n;}

  int unused,n;
};

boost::function_collection

  • 基线容器: func_vector = std::vector<std::function<int(int)>>
  • 多态集合: function_collection = boost::function_collection<int(int)>
  • 元素类型: T1 = concrete1, T2 = concrete2, T3 = concrete3 
struct concrete1
{
  concrete1(int n):n{n}{}
  int operator()(int)const{return n;}

  int n;
};

struct concrete2
{
  concrete2(int n):n{n}{}
  int operator()(int x)const{return x*n;}

  int unused,n;
};

struct concrete3
{
  concrete3(int n):n{n}{}
  int operator()(int x)const{return x*x*n;}

  int unused,n;
};

boost::any_collection

  • 基线容器: any_vector = std::vector<boost::type_erasure::any<concept_>>
  • 多态集合: any_collection = boost::any_collection<concept_>
  • 元素类型: T1 = int, T2 = double, T3 = char 
using concept_=boost::mpl::vector<
  boost::type_erasure::copy_constructible<>,
  boost::type_erasure::relaxed,
  boost::type_erasure::typeid_<>,
  boost::type_erasure::incrementable<>
>;

boost::variant_collection

  • 基线容器: variant_vector = std::vector<std::variant<int,double,char>>
  • 多态集合: variant_collection = boost::variant_collection<boost::mp11::mp_list<int,double,char>>
  • 元素类型: T1 = int, T2 = double, T3 = char

处理测试

结果: boost::base_collection
结果: boost::function_collection
结果: boost::any_collection
结果: boost::variant_collection

测试衡量遍历一个大小为 n 的容器 (n 介于 102 与 107 之间) 并对其每个元素执行一个操作所耗费的时间. 对于 boost::base_collection 和 boost::function_collection (以及相应的基线容器), 该操作定义为

struct for_each_callable
{
  for_each_callable():res{0}{}

  template<typename T>
  void operator()(T& x){
    res+=x(2);
  }

  int res;
};

而对于 boost::any_collection, 我们使用

struct for_each_incrementable
{
  for_each_incrementable():res{0}{}

  template<typename T>
  void operator()(T& x){
    ++x;
    ++res;
  }

  int res;
};

而对于 boost::variant_collection, 我们有

struct for_each_alternative
{
  for_each_alternative():res{0}{}

  template<template<typename...> class V,typename... Ts>
  void operator()(V<Ts...>& x){
    visit(*this,x);
  }

  template<typename T>
  void operator()(T& x){
    ++x;
    ++res;
  }

  int res;
};

基线容器以三种不同设置进行测试:

  • 直接按 插入测试 一节所述流程初始化后的状态. 由于元素按其构造时间排序, 可以预期存在一定程度的内存连续性.
  • 插入后再增加一个额外阶段, 按元素的类型对其排序. 这以牺牲缓存友好性为代价提高了分支预测效率.
  • 再增加一个插入后阶段, 将容器中的所有元素随机洗牌. 无论在缓存还是分支预测方面, 这都是最坏的可能情形. 我们不对 variant_vector 采用这一设置, 因为它等价于直接情形 (std::variant 不分配动态内存).

至于多态集合, 则测量以下三种变体:

  • 采用 std::for_each (与基线容器相同).
  • 使用 boost::poly_collection::for_each.
  • 使用 boost::poly_collection::for_each 搭配 类型恢复 (涵盖 T1、T2 和 T3).
