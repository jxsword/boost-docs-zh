编写新的共享内存分配算法

如果默认算法不满足用户要求, 很容易提供不同的算法 (如位图或更高级的隔离链表) 来满足需求. 实现该算法的类必须与共享内存兼容, 因此它不应有任何虚函数或虚继承, 也不应有任何带虚函数或虚继承的间接基类.

需要实现的接口如下:

class my_algorithm
{
   public:

   //!The mutex type to be used by the rest of Interprocess framework
   typedef implementation_defined   mutex_family;

   //!The pointer type to be used by the rest of Interprocess framework
   typedef implementation_defined   void_pointer;

   //!Constructor. "size" is the total size of the managed memory segment,
   //!"extra_hdr_bytes" indicates the extra bytes after the sizeof(my_algorithm)
   //!that the allocator should not use at all.
   my_algorithm (std::size_t size, std::size_t extra_hdr_bytes);

   //!Obtains the minimum size needed by the algorithm
   static std::size_t get_min_size (std::size_t extra_hdr_bytes);

   //!Allocates bytes, returns 0 if there is not more memory
   void* allocate (std::size_t nbytes);

   //!Deallocates previously allocated bytes
   void  deallocate (void *adr);

   //!Returns the size of the memory segment
   std::size_t get_size()  const;

   //!Increases managed memory in extra_size bytes more
   void grow(std::size_t extra_size);
   /*...*/
};

来看需要定义的公共 typedef:

typedef /* . . . */ void_pointer;
typedef /* . . . */ mutex_family;

void_pointer typedef 指定使用该算法的 Boost.Interprocess 框架将要使用的指针类型. 例如, 如果我们定义

typedef void * void_pointer;

所有使用该算法的 Boost.Interprocess 框架都将使用原始指针作为成员. 但如果我们定义:

typedef offset_ptr<void> void_pointer;

那么所有 Boost.Interprocess 框架都将使用相对指针.

mutex_family 是一个结构, 包含 Boost.Interprocess 框架中要使用的各种 interprocess_mutex 类型的 typedef. 例如定义了

struct mutex_family
{
   typedef boost::interprocess::interprocess_mutex             mutex_type;
   typedef boost::interprocess::interprocess_recursive_mutex   recursive_mutex_type;
};

它使所有 interprocess_mutex 类型都使用 boost::interprocess 的 interprocess_mutex 类型. 用户可以指定所需的互斥量家族.

typedef mutex_family mutex_family;

新算法 (姑且称之为 my_algorithm) 必须实现 boost::interprocess::rbtree_best_fit 类提供的所有函数:

  • my_algorithm 的构造函数必须接受 2 个参数:
    • size 表示托管内存段的总大小, my_algorithm 对象将始终在内存段偏移 0 处构造.
    • extra_hdr_bytes 参数表示从偏移 sizeof(my_algorithm) 之后、my_algorithm 完全不能使用的字节数. 这些额外的字节将用于存储不应被覆盖的附加数据. 因此, my_algorithm 将放置在内存段的地址 XXX 处, 并管理段的 (XXX + sizeof(my_algorithm) + extra_hdr_bytes, XXX + size) 范围.
  • get_min_size() 函数应返回在传入 extra_hdr_bytes 参数的情况下, 算法保持有效所需的最小空间. 该函数将用于检查内存段是否足够大, 能否把算法放在那里.
  • allocate() 函数在没有更多可用内存时必须返回 0. my_algorithm 返回的内存必须按系统上最严格的内存对齐方式对齐. 该函数应使用 typename mutex_family::mutex_type interprocess_mutex 提供的同步能力执行. 这意味着, 如果我们定义 typedef mutex_family mutex_family; , 该函数就应提供与被 interprocess_mutex lock/unlock 包围时相同的同步. 通常这用 mutex_family::mutex_type 类型的成员实现, 但也可以用原子指令或无锁算法实现.
  • deallocate() 函数必须使返回的缓冲区可用于新的分配. 该函数应提供与 allocate() 相同的同步.
  • size() 函数将返回构造函数中传入的 size 参数. 因此, my_algorithm 应在内部存储该大小.
  • grow() 函数将让 my_algorithm 把托管内存扩展 extra_size 字节. 因此 size() 函数应返回更新后的大小, 新的托管内存范围将是 (若算法构造处的地址为 XXX): (XXX + sizeof(my_algorithm) + extra_hdr_bytes, XXX + old_size + extra_size) . 该函数应提供与 allocate() 相同的同步.

就是这样. 现在我们可以创建使用新算法的新托管共享内存:

//Managed memory segment to allocate named (c-string) objects
//using a user-defined memory allocation algorithm
basic_managed_shared_memory<char,
                         ,my_algorithm
                         ,flat_map_index>
   my_managed_shared_memory;

为 Boost.Interprocess 构建自定义 STL 兼容分配器

如果提供的类 STL 分配器不满足用户需要, 用户可以利用原始内存分配和命名对象构造函数实现另一个 STL 兼容分配器. 这样, 用户就可以在基本的共享内存分配方案之上实现更合适的分配方案, 就像更复杂的分配器构建在 new/delete 函数之上一样.

使用托管内存段时, get_segment_manager() 函数返回指向段管理器的指针. 通过该指针, 可以直接调用原始内存分配和命名对象构造函数:

//Create the managed shared memory and initialize resources
managed_shared_memory segment
   (create_only
   ,"/MySharedMemory"   //segment name
   ,65536);             //segment size in bytes

//Obtain the segment manager
managed_shared_memory::segment_manager *segment_mngr
   = segment.get_segment_manager();

//With the segment manager, now we have access to all allocation functions
segment_mngr->deallocate(segment_mngr->allocate(32));
segment_mngr->construct<int>("My_Int")[32](0);
segment_mngr->destroy<int>("My_Int");

//Initialize the custom, managed memory segment compatible
//allocator with the segment manager.
//
//MySTLAllocator uses segment_mngr->xxx functions to
//implement its allocation scheme
MySTLAllocator<int> stl_alloc(segment_mngr);

//Alias a new vector type that uses the custom STL compatible allocator
typedef std::vector<int, MySTLAllocator<int> > MyVect;

//Construct the vector in shared memory with the allocator as constructor parameter
segment.construct<MyVect>("MyVect_instance")(stl_alloc);

用户可以创建新的 STL 兼容分配器, 让它们使用段管理器来访问所有内存管理/对象构造函数. Boost.Interprocess 的所有 STL 兼容分配器都基于这种方法. 请记住 , 要与托管内存段兼容, 分配器应把其 pointer typedef 定义为与 segment_manager::void_pointer typedef 相同的指针家族. 也就是说, 如果 segment_manager::void_pointer 是 offset_ptr<void> , MySTLAllocator<int> 就应把 pointer 定义为 offset_ptr<int> . 原因在于分配器是容器的成员, 如果我们想把容器放入托管内存段, 分配器也必须为此做好准备.

构建自定义索引

托管内存段使用名称/对象索引来加速对象搜索和创建. 托管内存段的默认特化 (例如 managed_shared_memory ) 使用 boost::interprocess::flat_map 作为索引.

不过, 索引类型可以通过模板参数选择, 因此用户可以在需要时定义自己的索引类型. 要构建新的索引类型, 用户必须按照以下准则创建一个类:

  • 索引的接口必须遵循 std::map 和 std::tr1::unordered_map 的通用公共接口 (包括公共 typedef). 其 value_type typedef 的类型可以是:
std::pair<key_type, mapped_type>

或者

std::pair<const key_type, mapped_type>

这样有序数组或 deque 就可以用作索引类型. 一些遵循这一基本接口的已知类有 boost::unordered_map, boost::interprocess::flat_map 和 boost::interprocess::map .

  • 该类必须是一个类模板, 只接受这种类型的 traits 结构:
struct index_traits
{
   typedef /*...*/   key_type;
   typedef /*...*/   mapped_type;
   typedef /*...*/   segment_manager;
};

template <class IndexTraits>
class my_index_type;

key_type typedef 在传入的 index_traits 中时, 将是以下类的特化:

//!The key of the named allocation information index. Stores a to
//!a null string and the length of the string to speed up sorting
template<...>
struct index_key
{
   typedef /*...*/                              char_type;
   typedef /*...*/                              const_char_ptr_t;

   //Pointer to the object's name (null terminated)
   const_char_ptr_t                             mp_str;

   //Length of the name buffer (null NOT included)
   std::size_t                                  m_len;

   //!Constructor of the key
   index_key (const CharT *name, std::size_t length);

   //!Less than function for index ordering
   bool operator < (const index_key & right) const;

   //!Equal to function for index ordering
   bool operator == (const index_key & right) const;
};

mapped_type 不会被自定义索引直接修改, 但定义索引类型时需要它. segment_manager 将是管理该索引的段管理器的类型. segment_manager 会定义一些有用的内部类型, 如 void_pointer 或 mutex_family .

  • 自定义索引类型的构造函数必须接受指向 segment_manager 的指针作为构造函数参数:
constructor(segment_manager *segment_mngr);
  • 索引必须提供一个内存预留函数, 当用户知道将要插入索引的元素数量时, 可以用它优化索引:
void reserve(std::size_t n);

例如, 基于 flat_map_index 的索引类型 boost::interprocess::flat_map 就定义为:

namespace boost { namespace interprocess {

#ifndef BOOST_INTERPROCESS_DOXYGEN_INVOKED

//!Helper class to define typedefs from IndexTraits
template <class MapConfig>
struct flat_map_index_aux
{
   typedef typename MapConfig::key_type            key_type;
   typedef typename MapConfig::mapped_type         mapped_type;
   typedef typename MapConfig::
      segment_manager_base                   segment_manager_base;
   typedef std::less<key_type>                     key_less;
   typedef std::pair<key_type, mapped_type>        value_type;
   typedef allocator<value_type
                    ,segment_manager_base>   allocator_type;
   typedef boost::container::flat_map<key_type,  mapped_type,
                                      key_less, allocator_type>      index_t;
};

#endif   //#ifndef BOOST_INTERPROCESS_DOXYGEN_INVOKED

//!Index type based in flat_map. Just derives from flat_map and
//!defines the interface needed by managed memory segments.
template <class MapConfig>
class flat_map_index
   //Derive class from flat_map specialization
   : private flat_map_index_aux<MapConfig>::index_t
{
   #if !defined(BOOST_INTERPROCESS_DOXYGEN_INVOKED)
   typedef flat_map_index_aux<MapConfig>  index_aux;
   typedef typename index_aux::index_t    base_type;
   typedef typename index_aux::
      segment_manager_base                   segment_manager_base;
   typedef typename base_type::key_type      key_type;
   typedef typename base_type::mapped_type   mapped_type;
   #endif   //#ifndef BOOST_INTERPROCESS_DOXYGEN_INVOKED

   public:
   using base_type::begin;
   using base_type::end;
   using base_type::size;
   using base_type::erase;
   using base_type::shrink_to_fit;
   using base_type::reserve;
   typedef typename base_type::iterator         iterator;
   typedef typename base_type::const_iterator   const_iterator;
   typedef typename base_type::value_type       value_type;
   typedef typename MapConfig::compare_key_type compare_key_type;
   typedef iterator                             insert_commit_data;
   typedef iterator                             index_data_t;

   //!Constructor. Takes a pointer to the segment manager. Can throw
   flat_map_index(segment_manager_base *segment_mngr)
      : base_type(typename index_aux::key_less(),
                  typename index_aux::allocator_type(segment_mngr))
   {}

   std::pair<iterator, bool> insert_check
      (const compare_key_type& key, insert_commit_data&)
   {
      std::pair<iterator, bool> r;
      r.first = this->base_type::find(key_type(key.str(), key.len()));
      r.second = r.first == this->base_type::end();
      return r;
   }

   iterator insert_commit
      (const compare_key_type &k, void *context, index_data_t&, insert_commit_data& )
   {
      //Now commit the insertion using previous context data
      return this->base_type::insert(value_type(key_type(k.str(), k.len()), mapped_type(context))).first;
   }

   iterator find(const compare_key_type& k)
   {  return this->base_type::find(key_type(k.str(), k.len()));   }
};

}}   //namespace boost { namespace interprocess

如果用户定义基于节点容器的索引 (这种容器在插入或擦除其他元素时迭代器不会失效), Boost.Interprocess 可以优化通过指针销毁时的命名对象销毁. Boost.Interprocess 可以在对象旁边存储一个迭代器, 擦除索引条目时不使用对象名称, 而是使用该迭代器, 这是更快的操作. 因此, 如果你正在创建新的基于节点容器的索引 (例如树), 应当为 boost::interprocess::is_node_index<...> (定义于 <boost/interprocess/detail/utilities.hpp> ) 定义一个特化:

//!Trait classes to detect if an index is a node
//!index. This allows more efficient operations
//!when deallocating named objects.
template<class MapConfig>
struct is_node_index
   <my_index<MapConfig> >
{
   static const bool value = true;
};

Interprocess 还定义了其他索引类型:

  • boost::map_index 使用 boost::interprocess::map 作为索引类型.
  • boost::null_index : 使用一个虚拟索引类型, 适用于用户只需要匿名分配并希望节省一些空间和类实例化的情况.

定义一个使用新索引的新托管内存段很容易. 例如, 使用新索引的新托管共享内存:

//!Defines a managed shared memory with a c-strings as
//!a keys, the red-black tree best fit algorithm (with process-shared mutexes
//!and offset_ptr pointers) as raw shared memory management algorithm
//!and a custom index
typedef
   basic_managed_shared_memory <
                              char,
                              rbtree_best_fit<mutex_family>,
                              my_index_type
                             >
   my_managed_shared_memory;
