Interprocess 分配器引言

Boost.Interprocess 分配器的特性
交换 Boost.Interprocess 分配器
allocator: 用于托管内存段的通用分配器

如前所述, Boost.Interprocess 提供了使用托管内存段 (托管共享内存、托管映射文件等) 的原始内存分配和对象构造, 用户最早的请求之一就是在托管共享内存中使用容器. 为实现这一点, Boost.Interprocess 利用托管内存段的内存分配算法构建了多种内存分配方案, 包括通用分配器和节点分配器.

Boost.Interprocess 分配器可通过模板参数配置. 分配器定义其 pointer typedef 时, 依据的是作为模板实参传入的段管理器的 void_pointer typedef. 当该 segment_manager::void_pointer 是相对指针时 (例如 offset_ptr<void>), 用户可以将这些分配器放置在多个进程中以不同基址映射的内存里.

Boost.Interprocess 分配器的特性

容器分配器通常可默认构造, 因为它们是无状态的. std::allocator 和 Boost.Pool 的 boost::pool_allocator/boost::fast_pool_allocator 就是可默认构造分配器的例子.

另一方面, Boost.Interprocess 分配器需要从具体的内存段分配内存, 而不是从系统级的内存源 (如堆). Boost.Interprocess 分配器是 有状态的 , 这意味着必须对它们进行配置, 告诉它们共享内存或内存映射文件在哪里.

这一信息在编译期和运行期传递: 分配器通过模板参数接收段管理器的类型, 其构造函数则接收一个指针, 指向用户想要在其中分配值的托管内存段的段管理器.

Boost.Interprocess 分配器 没有默认构造函数 , 容器必须用一个配置好的分配器显式初始化:

//The allocators must be templatized with the segment manager type
typedef any_interprocess_allocator
   <int, managed_shared_memory::segment_manager, ...> Allocator;

//The allocator must be constructed with a pointer to the segment manager
Allocator alloc_instance (segment.get_segment_manager(), ...);

//Containers must be initialized with a configured allocator
typedef my_list<int, Allocator> MyIntList;
MyIntList mylist(alloc_inst);

//This would lead to a compilation error, because
//the allocator has no default constructor
//MyIntList mylist;

Boost.Interprocess 分配器还有一个 get_segment_manager() 函数, 返回它们在构造函数中收到的底层段管理器:

Allocator::segment_manager s = alloc_instance.get_segment_manager();
AnotherType *a = s->construct<AnotherType>(anonymous_instance)(/*Parameters*/);

交换 Boost.Interprocess 分配器

交换 STL 容器时, 关于如何处理分配器存在活跃的讨论. 一些 STL 实现, 例如 Visual .NET 2003 的 Dinkumware, 会在分配器不相等时通过一个临时对象对整个容器执行深交换. 关于容器交换的 提议决议 是, 分配器应当以不抛异常的方式交换.

遗憾的是, 这种方法不适用于共享内存. 使用堆分配器时, 如果节点分配器组 1 共享同一个隔离存储, 组 2 共享另一个隔离存储, 那么交换组 1 的一个分配器和组 2 的另一个分配器只需简单的指针交换. 但当用户想交换两个共享内存分配器, 且二者位于不同的共享内存段时, 这就无法做到. 由于共享内存通常在每个进程中映射到不同的地址, 一个段中的指针无法指向另一个共享内存段中的任何对象, 因为在每个进程中, 段之间的距离都不相同. 不过, 如果两个共享内存分配器位于同一个段中, 则可以进行不抛异常的交换, 就像堆分配器一样.

在最终决议达成之前, Boost.Interprocess 分配器实现了一个不抛异常的 swap 函数, 交换内部指针. 如果把位于一个共享内存段中的分配器与位于另一个共享内存段中的分配器交换, 结果是未定义的, 而且几乎肯定会崩溃.

allocator: 用于托管内存段的通用分配器

allocator 类定义了一个分配器类, 它使用托管内存段的算法来分配和释放内存. 这是通过托管内存段的 段管理器 实现的. 该分配器相当于托管内存段版本的标准 std::allocator . allocator 以被分配类型和段管理器为模板参数.

相等性:: 用同一个段管理器构造的两个 allocator 实例比较相等. 如果一个实例用复制构造函数创建, 该实例与原实例比较相等.

分配线程安全:: 分配与释放实现为对段管理器分配函数的调用, 因此分配器提供与段管理器相同的线程安全性.

要使用 allocator , 必须包含以下头文件:

#include <boost/interprocess/allocators/allocator.hpp>

allocator 的声明如下:

namespace boost {
namespace interprocess {

template<class T, class SegmentManager>
class allocator;

}  //namespace interprocess {
}  //namespace boost {

该分配器只提供所需的 typedef, 并把所有分配和释放请求转发给构造函数中传入的段管理器, 就像 std::allocator 把请求转发给 operator new[] 一样.

使用 allocator 很简单:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/interprocess/allocators/allocator.hpp>
#include <cassert>

using namespace boost::interprocess;

int main ()
{
   //Remove shared memory on construction and destruction
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   } remover;

   //Create shared memory
   managed_shared_memory segment(create_only,"MyName", 65536);

   //Create an allocator that allocates ints from the managed segment
   allocator<int, managed_shared_memory::segment_manager>
      allocator_instance(segment.get_segment_manager());

   //Copy constructed allocator is equal
   allocator<int, managed_shared_memory::segment_manager>
      allocator_instance2(allocator_instance);
   assert(allocator_instance2 == allocator_instance);

   //Allocate and deallocate memory for 100 ints
   allocator_instance2.deallocate(allocator_instance.allocate(100), 100);

   return 0;
}

隔离存储节点分配器

隔离存储节点分配器的附加参数与函数
node_allocator: 进程共享的隔离存储
private_node_allocator: 私有隔离存储
cached_node_allocator: 缓存节点以避免开销

变长内存算法会为每次分配的管理信息浪费一些空间. 有时 (通常对小对象而言) 这是不可接受的. 在某些分配和释放方案下, 内存算法还会使托管内存段碎片化, 降低其性能. 当分配大量同类型对象时, 简单的隔离存储会成为快速且节省空间的分配器, 如 Boost.Pool 库中所述.

隔离存储节点分配器从一个通用内存分配器分配大内存块, 并将该块划分为多个节点. 节点中不存储任何簿记信息, 从而实现最小的内存浪费: 空闲节点用节点内存中构造的指针链接起来.

Boost.Interprocess 基于这种隔离存储算法提供了 3 种分配器: node_allocator, private_node_allocator 和 cached_node_allocator.

要了解隔离存储池实现的细节, 请参阅 Boost.Interprocess 隔离存储池的实现 一节.

隔离存储节点分配器的附加参数与函数

node_allocator, private_node_allocator 和 cached_node_allocator 实现了标准分配器接口, 以及 Boost.Interprocess 分配器的特性 中说明的函数.

所有这些分配器都以 3 个参数模板化:

  • class T: 要分配的类型.
  • class SegmentManager: 将在构造函数中传入的段管理器的类型.
  • std::size_t NodesPerChunk: 每个内存块将包含的节点数. 该值决定了池的节点用尽时向段管理器请求的内存大小. 此参数有默认值.

这些分配器还提供 deallocate_free_chunks() 函数. 该函数会遍历池的所有内存块, 将空闲内存块归还给托管内存段. 如果不使用该函数, 空闲块要等到池被销毁时才会释放, 因此在销毁池之前把池分配的内存归还给段的唯一办法就是手动调用该函数. 该函数相当耗时, 因为其复杂度是二次的 (O(N^2)).

node_allocator: 进程共享的隔离存储

对于堆内存节点分配器 (如 Boost.Pool 的 boost::fast_pool_allocator ), 通常每个节点大小使用一个全局的、线程共享的单例池. 如果试图在进程之间共享节点分配器, 这是不可能的. 为实现这种共享, node_allocator 使用段管理器的唯一类型分配服务 (参见 唯一实例构造 一节).

初始化时, node_allocator 对象会在段中搜索这个唯一对象. 如果不存在, 就构建一个. 这样, 在一个内存段中构建的所有 node_allocator 对象共享一个唯一的内存池.

公共隔离存储不仅在同类型的 node_allocator 之间共享, 也在所有分配同大小对象的节点分配器之间共享, 例如 node_allocator<uint32> 和 node_allocator<float32> . 这节省了大量内存, 但也给每次节点分配带来了同步开销.

动态创建的公共隔离存储内置引用计数, 使 node_allocator 能知道是否还有其他 node_allocator 也连接到同一个公共隔离存储. 当最后一个连接到池的分配器被销毁时, 池即被销毁.

相等性:: 用同一个段管理器构造的两个 node_allocator 实例比较相等. 如果一个实例用复制构造函数创建, 该实例与原实例比较相等.

分配线程安全:: 分配与释放实现为对共享池的调用. 共享池提供与段管理器相同的同步保证.

要使用 node_allocator, 必须包含以下头文件:

#include <boost/interprocess/allocators/node_allocator.hpp>

node_allocator 的声明如下:

namespace boost {
namespace interprocess {

template<class T, class SegmentManager, std::size_t NodesPerChunk = ...>
class node_allocator;

}  //namespace interprocess {
}  //namespace boost {

一个使用 node_allocator 的示例:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/interprocess/allocators/node_allocator.hpp>
#include <cassert>

using namespace boost::interprocess;

int main ()
{
   //Remove shared memory on construction and destruction
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   } remover;

   //Create shared memory
   managed_shared_memory segment(create_only,
                                 "MyName",  //segment name
                                 65536);

   //Create a node_allocator that allocates ints from the managed segment
   //The number of chunks per segment is the default value
   typedef node_allocator<int, managed_shared_memory::segment_manager>
      node_allocator_t;
   node_allocator_t allocator_instance(segment.get_segment_manager());

   //Create another node_allocator. Since the segment manager address
   //is the same, this node_allocator will be
   //attached to the same pool so "allocator_instance2" can deallocate
   //nodes allocated by "allocator_instance"
   node_allocator_t allocator_instance2(segment.get_segment_manager());

   //Create another node_allocator using copy-constructor. This
   //node_allocator will also be attached to the same pool
   node_allocator_t allocator_instance3(allocator_instance2);

   //All allocators are equal
   assert(allocator_instance == allocator_instance2);
   assert(allocator_instance2 == allocator_instance3);

   //So memory allocated with one can be deallocated with another
   allocator_instance2.deallocate(allocator_instance.allocate(1), 1);
   allocator_instance3.deallocate(allocator_instance2.allocate(1), 1);

   //The common pool will be destroyed here, since no allocator is
   //attached to the pool
   return 0;
}

private_node_allocator: 私有隔离存储

如前所述, node_allocator 在分配同大小对象的节点分配器之间共享公共隔离存储, 这优化了内存使用. 但它需要唯一/命名对象构造特性才能实现这种共享, 并且由于共享, 每次节点分配都有同步开销. 有时唯一对象服务不可用 (例如, 在构建用于实现命名分配服务本身的索引类型时), 或同步开销不可接受. 很多时候, 程序员希望确保池在分配器销毁时一并销毁, 以尽快释放内存.

因此 private_node_allocator 使用与 node_allocator 相同的隔离存储, 但每个 private_node_allocator 都有自己的隔离存储池. 分配节点时不使用同步, 因此对于分配和释放节点通常只涉及几次指针操作的场景, 开销要小得多.

相等性:: 两个 private_node_allocator 实例 绝不 比较相等. 用一个分配器分配的内存 不能 用另一个分配器释放.

分配线程安全:: 分配与释放 不是 线程安全的.

要使用 private_node_allocator, 必须包含以下头文件:

#include <boost/interprocess/allocators/private_node_allocator.hpp>

private_node_allocator 的声明如下:

namespace boost {
namespace interprocess {

template<class T, class SegmentManager, std::size_t NodesPerChunk = ...>
class private_node_allocator;

}  //namespace interprocess {
}  //namespace boost {

一个使用 private_node_allocator 的示例:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/interprocess/allocators/private_node_allocator.hpp>
#include <cassert>

using namespace boost::interprocess;

int main ()
{
   //Remove shared memory on construction and destruction
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   }  remover;

   //Create shared memory
   managed_shared_memory segment(create_only,
                                 "MyName",  //segment name
                                 65536);

   //Create a private_node_allocator that allocates ints from the managed segment
   //The number of chunks per segment is the default value
   typedef private_node_allocator<int, managed_shared_memory::segment_manager>
      private_node_allocator_t;
   private_node_allocator_t allocator_instance(segment.get_segment_manager());

   //Create another private_node_allocator.
   private_node_allocator_t allocator_instance2(segment.get_segment_manager());

   //Although the segment manager address
   //is the same, this private_node_allocator will have its own pool so
   //"allocator_instance2" CAN'T deallocate nodes allocated by "allocator_instance".
   //"allocator_instance2" is NOT equal to "allocator_instance"
   assert(allocator_instance != allocator_instance2);

   //Create another node_allocator using copy-constructor.
   private_node_allocator_t allocator_instance3(allocator_instance2);

   //This allocator is also unequal to allocator_instance2
   assert(allocator_instance2 != allocator_instance3);

   //Pools are destroyed with the allocators
   return 0;
}

cached_node_allocator: 缓存节点以避免开销

node_allocator 的完全节点共享可能给某些应用带来很高的开销, 而 private_node_allocator 的最小同步开销又可能给另一些应用带来不可接受的内存浪费.

为解决这一问题, Boost.Interprocess 提供了一个分配器 cached_node_allocator , 它从公共池分配节点, 但私有地缓存其中一部分, 使后续分配没有同步开销. 当缓存满时, 分配器将一些缓存的节点归还给公共池, 这些节点即可供其他分配器使用.

相等性:: 用同一个段管理器构造的两个 cached_node_allocator 实例比较相等. 如果一个实例用复制构造函数创建, 该实例与原实例比较相等.

分配线程安全:: 分配与释放 不是 线程安全的.

要使用 cached_node_allocator, 必须包含以下头文件:

#include <boost/interprocess/allocators/cached_node_allocator.hpp>

cached_node_allocator 的声明如下:

namespace boost {
namespace interprocess {

template<class T, class SegmentManager, std::size_t NodesPerChunk = ...>
class cached_node_allocator;

}  //namespace interprocess {
}  //namespace boost {

一个 cached_node_allocator 实例与一个 node_allocator 实例, 如果二者接收相同的模板参数, 就共享同一个池. 这意味着其中一个归还给共享池的节点可以被另一个复用. 请注意, 这并不意味着两个分配器比较相等, 这只是给希望最大化池的使用的程序员提供的信息.

cached_node_allocator, 还提供了一些额外的函数来控制缓存 (缓存可以按实例控制):

  • void set_max_cached_nodes(std::size_t n): 设置最大缓存节点数限制. 如果缓存节点达到限制, 一部分将被归还给共享池.
  • std::size_t get_max_cached_nodes() const: 返回最大缓存节点数限制.
  • void deallocate_cache(): 将缓存的节点归还给共享池.

一个使用 cached_node_allocator 的示例:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/interprocess/allocators/cached_node_allocator.hpp>
#include <cassert>

using namespace boost::interprocess;

int main ()
{
   //Remove shared memory on construction and destruction
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   } remover;

   //Create shared memory
   managed_shared_memory segment(create_only, "MyName", 65536);

   //Create a cached_node_allocator that allocates ints from the managed segment
   //The number of chunks per segment is the default value
   typedef cached_node_allocator<int, managed_shared_memory::segment_manager>
      cached_node_allocator_t;
   cached_node_allocator_t allocator_instance(segment.get_segment_manager());

   //The max cached nodes are configurable per instance
   allocator_instance.set_max_cached_nodes(3);

   //Create another cached_node_allocator. Since the segment manager address
   //is the same, this cached_node_allocator will be
   //attached to the same pool so "allocator_instance2" can deallocate
   //nodes allocated by "allocator_instance"
   cached_node_allocator_t allocator_instance2(segment.get_segment_manager());

   //The max cached nodes are configurable per instance
   allocator_instance2.set_max_cached_nodes(5);

   //Create another cached_node_allocator using copy-constructor. This
   //cached_node_allocator will also be attached to the same pool
   cached_node_allocator_t allocator_instance3(allocator_instance2);

   //We can clear the cache
   allocator_instance3.deallocate_cache();

   //All allocators are equal
   assert(allocator_instance == allocator_instance2);
   assert(allocator_instance2 == allocator_instance3);

   //So memory allocated with one can be deallocated with another
   allocator_instance2.deallocate(allocator_instance.allocate(1), 1);
   allocator_instance3.deallocate(allocator_instance2.allocate(1), 1);

   //The common pool will be destroyed here, since no allocator is
   //attached to the pool
   return 0;
}

自适应池节点分配器

自适应池节点分配器的附加参数与函数
adaptive_pool: 进程共享的自适应池
private_adaptive_pool: 私有自适应池
cached_adaptive_pool: 避免同步开销

基于简单隔离存储算法的节点分配器既省空间又快速, 但它们有一个问题: 只能增长. 每个分配的节点都不带任何用于存储附加数据的负载, 这导致如下限制: 节点被释放时, 它被存入节点空闲链表, 但内存不会归还给段管理器, 因此被释放的节点只能被使用同一节点池的其他容器复用.

如果多个容器使用 boost::interprocess::node_allocator 临时分配大量对象, 但最终只存储其中一小部分, 这种行为可能有问题: 节点池将充满无法复用的节点, 浪费段中的内存.

基于自适应池的分配器用一些空间 (开销可低至 1%) 和性能 (对许多应用而言可以接受) 换取将节点的空闲块归还给内存段的能力, 使它们可以被任何其他容器或托管对象构造使用. 要了解"自适应池"实现的细节, 请参阅 Boost.Intrusive 自适应池的实现 一节.

与基于隔离存储的节点分配器一样, Boost.Interprocess 提供了 3 种新分配器: adaptive_pool, private_adaptive_pool, cached_adaptive_pool.

自适应池节点分配器的附加参数与函数

adaptive_pool, private_adaptive_pool 和 cached_adaptive_pool 实现了标准分配器接口, 以及 Boost.Interprocess 分配器的特性 中说明的函数.

所有这些分配器都以 4 个参数模板化:

  • class T: 要分配的类型.
  • class SegmentManager: 将在构造函数中传入的段管理器的类型.
  • std::size_t NodesPerChunk: 每个内存块将包含的节点数. 该值决定了池的节点用尽时向段管理器请求的内存大小. 此参数有默认值.
  • std::size_t MaxFreeChunks: 池将持有的最大空闲块数. 如果达到该限制, 池将把块归还给段管理器. 此参数有默认值.

这些分配器还提供 deallocate_free_chunks() 函数. 该函数会遍历池的所有内存块, 将空闲内存块归还给托管内存段. 该函数比隔离存储分配器的同名函数快得多, 因为自适应池算法对空闲块提供常数时间的访问.

adaptive_pool: 进程共享的自适应池

与 node_allocator 一样, 每个节点大小使用一个全局的、进程线程共享的池. 初始化时, adaptive_pool 在段中搜索该池. 如果不存在, 就构建一个. 自适应池用唯一名称创建. 自适应池也在所有分配同大小对象的节点分配器之间共享, 例如 adaptive_pool<uint32> 和 adaptive_pool<float32>.

当所有连接到池的分配器都被销毁时, 公共自适应池即被销毁.

相等性:: 用同一个段管理器构造的两个 adaptive_pool 实例比较相等. 如果一个实例用复制构造函数创建, 该实例与原实例比较相等.

分配线程安全:: 分配与释放实现为对共享池的调用. 共享池提供与段管理器相同的同步保证.

要使用 adaptive_pool, 必须包含以下头文件:

#include <boost/interprocess/allocators/adaptive_pool.hpp>

adaptive_pool 的声明如下:

namespace boost {
namespace interprocess {

template<class T, class SegmentManager, std::size_t NodesPerChunk = ..., std::size_t MaxFreeChunks = ...>
class adaptive_pool;

}  //namespace interprocess {
}  //namespace boost {

一个使用 adaptive_pool 的示例:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/interprocess/allocators/adaptive_pool.hpp>
#include <cassert>

using namespace boost::interprocess;

int main ()
{
   //Remove shared memory on construction and destruction
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   } remover;

   //Create shared memory
   managed_shared_memory segment(create_only,"MyName", 65536);

   //Create a adaptive_pool that allocates ints from the managed segment
   //The number of chunks per segment is the default value
   typedef adaptive_pool<int, managed_shared_memory::segment_manager>
      adaptive_pool_t;
   adaptive_pool_t allocator_instance(segment.get_segment_manager());

   //Create another adaptive_pool. Since the segment manager address
   //is the same, this adaptive_pool will be
   //attached to the same pool so "allocator_instance2" can deallocate
   //nodes allocated by "allocator_instance"
   adaptive_pool_t allocator_instance2(segment.get_segment_manager());

   //Create another adaptive_pool using copy-constructor. This
   //adaptive_pool will also be attached to the same pool
   adaptive_pool_t allocator_instance3(allocator_instance2);

   //All allocators are equal
   assert(allocator_instance == allocator_instance2);
   assert(allocator_instance2 == allocator_instance3);

   //So memory allocated with one can be deallocated with another
   allocator_instance2.deallocate(allocator_instance.allocate(1), 1);
   allocator_instance3.deallocate(allocator_instance2.allocate(1), 1);

   //The common pool will be destroyed here, since no allocator is
   //attached to the pool
   return 0;
}

private_adaptive_pool: 私有自适应池

正如 private_node_allocator 拥有私有的隔离存储池, private_adaptive_pool 拥有自己的自适应池. 如果用户想避免容器中过多的节点分配同步开销, private_adaptive_pool 是一个不错的选择.

相等性:: 两个 private_adaptive_pool 实例 绝不 比较相等. 用一个分配器分配的内存 不能 用另一个分配器释放.

分配线程安全:: 分配与释放 不是 线程安全的.

要使用 private_adaptive_pool, 必须包含以下头文件:

#include <boost/interprocess/allocators/private_adaptive_pool.hpp>

private_adaptive_pool 的声明如下:

namespace boost {
namespace interprocess {

template<class T, class SegmentManager, std::size_t NodesPerChunk = ..., std::size_t MaxFreeChunks = ...>
class private_adaptive_pool;

}  //namespace interprocess {
}  //namespace boost {

一个使用 private_adaptive_pool 的示例:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/interprocess/allocators/private_adaptive_pool.hpp>
#include <cassert>

using namespace boost::interprocess;

int main ()
{
   //Remove shared memory on construction and destruction
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   } remover;

   //Create shared memory
   managed_shared_memory segment(create_only,
                                 "MyName",  //segment name
                                 65536);

   //Create a private_adaptive_pool that allocates ints from the managed segment
   //The number of chunks per segment is the default value
   typedef private_adaptive_pool<int, managed_shared_memory::segment_manager>
         private_adaptive_pool_t;
   private_adaptive_pool_t allocator_instance(segment.get_segment_manager());

   //Create another private_adaptive_pool.
   private_adaptive_pool_t allocator_instance2(segment.get_segment_manager());

   //Although the segment manager address
   //is the same, this private_adaptive_pool will have its own pool so
   //"allocator_instance2" CAN'T deallocate nodes allocated by "allocator_instance".
   //"allocator_instance2" is NOT equal to "allocator_instance"
   assert(allocator_instance != allocator_instance2);

   //Create another adaptive_pool using copy-constructor.
   private_adaptive_pool_t allocator_instance3(allocator_instance2);

   //This allocator is also unequal to allocator_instance2
   assert(allocator_instance2 != allocator_instance3);

   //Pools are destroyed with the allocators
   return 0;
}

cached_adaptive_pool: 避免同步开销

自适应池也有缓存版本. 在这个分配器中, 分配器缓存一些节点, 以避免共享自适应池的同步与簿记开销. cached_adaptive_pool 从公共自适应池分配节点, 但私有地缓存其中一部分, 使后续分配没有同步开销. 当缓存满时, 分配器将一些缓存的节点归还给公共池, 这些节点即可供同一托管段的其他 cached_adaptive_pools 或 adaptive_pools 使用.

相等性:: 用同一个段管理器构造的两个 cached_adaptive_pool 实例比较相等. 如果一个实例用复制构造函数创建, 该实例与原实例比较相等.

分配线程安全:: 分配与释放 不是 线程安全的.

要使用 cached_adaptive_pool, 必须包含以下头文件:

#include <boost/interprocess/allocators/cached_adaptive_pool.hpp>

cached_adaptive_pool 的声明如下:

namespace boost {
namespace interprocess {

template<class T, class SegmentManager, std::size_t NodesPerChunk = ..., std::size_t MaxFreeNodes = ...>
class cached_adaptive_pool;

}  //namespace interprocess {
}  //namespace boost {

一个 cached_adaptive_pool 实例与一个 adaptive_pool 实例, 如果二者接收相同的模板参数, 就共享同一个池. 这意味着其中一个归还给共享池的节点可以被另一个复用. 请注意, 这并不意味着两个分配器比较相等, 这只是给希望最大化池的使用的程序员提供的信息.

cached_adaptive_pool, 还提供了一些额外的函数来控制缓存 (缓存可以按实例控制):

  • void set_max_cached_nodes(std::size_t n): 设置最大缓存节点数限制. 如果缓存节点达到限制, 一部分将被归还给共享池.
  • std::size_t get_max_cached_nodes() const: 返回最大缓存节点数限制.
  • void deallocate_cache(): 将缓存的节点归还给共享池.

一个使用 cached_adaptive_pool 的示例:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/interprocess/allocators/cached_adaptive_pool.hpp>
#include <cassert>

using namespace boost::interprocess;

int main ()
{
   //Remove shared memory on construction and destruction
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   } remover;

   //Create shared memory
   managed_shared_memory segment(create_only,"MyName", 65536);

   //Create a cached_adaptive_pool that allocates ints from the managed segment
   //The number of chunks per segment is the default value
   typedef cached_adaptive_pool<int, managed_shared_memory::segment_manager>
      cached_adaptive_pool_t;
   cached_adaptive_pool_t allocator_instance(segment.get_segment_manager());

   //The max cached nodes are configurable per instance
   allocator_instance.set_max_cached_nodes(3);

   //Create another cached_adaptive_pool. Since the segment manager address
   //is the same, this cached_adaptive_pool will be
   //attached to the same pool so "allocator_instance2" can deallocate
   //nodes allocated by "allocator_instance"
   cached_adaptive_pool_t allocator_instance2(segment.get_segment_manager());

   //The max cached nodes are configurable per instance
   allocator_instance2.set_max_cached_nodes(5);

   //Create another cached_adaptive_pool using copy-constructor. This
   //cached_adaptive_pool will also be attached to the same pool
   cached_adaptive_pool_t allocator_instance3(allocator_instance2);

   //We can clear the cache
   allocator_instance3.deallocate_cache();

   //All allocators are equal
   assert(allocator_instance == allocator_instance2);
   assert(allocator_instance2 == allocator_instance3);

   //So memory allocated with one can be deallocated with another
   allocator_instance2.deallocate(allocator_instance.allocate(1), 1);
   allocator_instance3.deallocate(allocator_instance2.allocate(1), 1);

   //The common pool will be destroyed here, since no allocator is
   //attached to the pool
   return 0;
}
