托管内存段类的声明

引言

如前所述, Boost.Interprocess 提供了一些基本类来创建共享内存对象和文件映射, 并把这些可映射类映射到进程的地址空间.

然而, 对非平凡任务而言, 管理这些内存段并不容易. 映射区域是固定长度的内存缓冲区, 动态创建和销毁任意类型的对象需要大量工作, 因为这需要编写内存管理算法来分配该段的部分内存. 很多时候, 我们还希望为共享内存中创建的对象关联名称, 让所有进程都能用名称找到对象.

Boost.Interprocess 提供了 4 个托管内存段类:

  • 管理共享内存映射区域 (basic_managed_shared_memory 类).
  • 管理内存映射文件 (basic_managed_mapped_file).
  • 管理堆分配 (operator new) 的内存缓冲区 (basic_managed_heap_memory 类).
  • 管理用户提供的固定大小缓冲区 (basic_managed_external_buffer 类).

前两个类管理可在进程之间共享的内存段. 第三个类适合创建复杂数据库, 通过消息队列等其他机制发送给其他进程. 第四个类可以管理任何固定大小的内存缓冲区. 前两个类将在接下来两节中讲解. basic_managed_heap_memory 和 basic_managed_external_buffer 稍后讲解.

托管内存段最重要的服务有:

  • 内存段部分内存的动态分配.
  • 在内存段中构造 C++ 对象. 这些对象可以是匿名的, 也可以为它们关联名称.
  • 命名对象的查找能力.
  • 众多特性的定制: 内存分配算法、索引类型或字符类型.
  • 原子构造与销毁: 如果段被两个进程共享, 就不可能创建两个与同一名称关联的对象, 从而简化同步.

托管内存段类的声明

所有 Boost.Interprocess 托管内存段类都是可由用户定制的模板类:

template
      <
         class CharType,
         class MemoryAlgorithm,
         template<class IndexConfig> class IndexType
      >
class basic_managed_shared_memory / basic_managed_mapped_file /
      basic_managed_heap_memory   / basic_external_buffer;

这些类可以用以下模板参数定制:

  • CharType 是用于标识所创建命名对象的字符类型 (例如 char 或 wchar_t)
  • MemoryAlgorithm 是用于分配段的部分内存的内存算法 (例如 rbtree_best_fit). 内存算法的内部 typedef 还定义:
    • 所有分配操作使用的同步类型 (MemoryAlgorithm::mutex_family). 这允许使用用户自定义的互斥量, 或避免内部加锁 (可能由用户在外部进行同步).
    • 内存分配算法或辅助结构 (如维护对象/名称关联的映射) 使用的 Pointer 类型 (MemoryAlgorithm::void_pointer). 与此托管内存段一起使用的所有 STL 兼容分配器和容器都将使用这种指针类型. 指针类型将决定托管内存段能否在多个进程之间映射. 例如, 如果 void_pointer 是 offset_ptr<void> , 我们就能在每个进程中以不同基址映射托管段. 如果 void_pointer 是 void* , 则只能使用固定地址映射.
    • 内存算法的更多细节参见 编写新的内存分配算法 .
  • IndexType 是用于存储名称-对象关联的索引类型 (例如 map、哈希 map 或有序 vector).

这样, 我们就可以用 char 或 wchar_t 字符串来标识内存段中创建的 C++ 对象, 可以插入新的共享内存分配算法, 并使用最适合需求的索引类型.

常用托管共享内存类

如前所述, basic_managed_shared_memory 提供了丰富的定制能力. 但对普通用户而言, 需要的是常见的、默认的共享内存命名对象创建. 因此, Boost.Interprocess 定义了最常用的托管共享内存特化:

//!Defines a managed shared memory with c-strings as keys for named objects,
//!the default memory algorithm (with process-shared mutexes,
//!and offset_ptr as internal pointers) as memory allocation algorithm
//!and the default index type as the index.
//!This class allows the shared memory to be mapped in different base
//!in different processes
typedef
   basic_managed_shared_memory<char
                              ,/*Default memory algorithm defining offset_ptr<void> as void_pointer*/
                              ,/*Default index type*/>
   managed_shared_memory;

//!Defines a managed shared memory with wide strings as keys for named objects,
//!the default memory algorithm (with process-shared mutexes,
//!and offset_ptr as internal pointers) as memory allocation algorithm
//!and the default index type as the index.
//!This class allows the shared memory to be mapped in different base
//!in different processes
typedef
   basic_managed_shared_memory<wchar_t
                              ,/*Default memory algorithm defining offset_ptr<void> as void_pointer*/
                              ,/*Default index type*/>
   wmanaged_shared_memory;

managed_shared_memory 在共享内存中分配与 c 字符串关联的对象, wmanaged_shared_memory 在共享内存中分配与 wchar_t 空结尾字符串关联的对象. 两者都把指针类型定义为 offset_ptr<void> , 因此可用于在不同进程中以不同基址映射共享内存.

如果用户希望在所有进程中把共享内存映射到相同地址, 并在内部使用原始指针而非偏移指针, Boost.Interprocess 定义了以下类型:

//!Defines a managed shared memory with c-strings as keys for named objects,
//!the default memory algorithm (with process-shared mutexes,
//!and offset_ptr as internal pointers) as memory allocation algorithm
//!and the default index type as the index.
//!This class allows the shared memory to be mapped in different base
//!in different processes*/
typedef basic_managed_shared_memory
   <char
   ,/*Default memory algorithm defining void * as void_pointer*/
   ,/*Default index type*/>
fixed_managed_shared_memory;

//!Defines a managed shared memory with wide strings as keys for named objects,
//!the default memory algorithm (with process-shared mutexes,
//!and offset_ptr as internal pointers) as memory allocation algorithm
//!and the default index type as the index.
//!This class allows the shared memory to be mapped in different base
//!in different processes
typedef basic_managed_shared_memory
   <wchar_t
   ,/*Default memory algorithm defining void * as void_pointer*/
   ,/*Default index type*/>
wfixed_managed_shared_memory;

构造托管共享内存

托管共享内存是一个高级类, 它组合了一个共享内存对象和一个覆盖整个共享内存对象的映射区域. 这意味着当我们 创建 一个新的托管共享内存时:

  • 创建一个新的共享内存对象.
  • 整个共享内存对象映射到进程的地址空间.
  • 在映射区域中构造一些辅助对象 (名称-对象索引、内部同步对象、内部变量...) 以实现托管内存段特性.

当我们 打开 一个托管共享内存时

  • 打开一个共享内存对象.
  • 整个共享内存对象映射到进程的地址空间.

要使用托管共享内存, 必须包含以下头文件:

#include <boost/interprocess/managed_shared_memory.hpp>

//1.  Creates a new shared memory object
//    called "MyName".
//2.  Maps the whole object to this
//    process' address space.
//3.  Constructs some objects in shared memory
//    to implement managed features.
//!!  If anything fails, throws interprocess_exception
//
managed_shared_memory segment      ( create_only
                                   , "MyName"    //Shared memory object name
                                   , 65536);     //Shared memory object size in bytes

//1.  Opens a shared memory object
//    called "MyName".
//2.  Maps the whole object to this
//    process' address space.
//3.  Obtains pointers to constructed internal objects
//    to implement managed features.
//!!  If anything fails, throws interprocess_exception
//
managed_shared_memory segment (open_only, "MyName"); //Shared memory object name

//1.  If the segment was previously created
//    equivalent to "open_only" (size is ignored).
//2.  Otherwise, equivalent to "create_only"
//!!  If anything fails, throws interprocess_exception
//
managed_shared_memory segment      ( open_or_create
                                   , "MyName"    //Shared memory object name
                                   , 65536);     //Shared memory object size in bytes

当 managed_shared_memory 对象被销毁时, 共享内存对象会自动解除映射, 所有资源被释放. 要从系统中移除共享内存对象, 必须使用 shared_memory_object::remove 函数. 如果仍有进程映射着该共享内存对象, 移除可能失败.

用户还可以把托管共享内存映射到固定地址. 使用 fixed_managed_shared_memory 时这个选项必不可少. 为此, 只需把映射地址作为额外参数加入:

fixed_managed_shared_memory segment      (open_only      ,"MyFixedAddressSharedMemory" //Shared memory object name
   ,(void*)0x30000000            //Mapping address

使用原生 Windows 共享内存

Windows 用户可能还想使用原生 Windows 共享内存而不是可移植的 shared_memory_object 托管内存. 这可以通过 basic_managed_windows_shared_memory 类实现. 使用它只需包含:

#include <boost/interprocess/managed_windows_shared_memory.hpp>

该类的接口与 basic_managed_shared_memory 相同, 但使用原生 Windows 共享内存. 注意这个托管类与 Windows 共享内存有相同的生存期问题: 当最后一个连接到该 Windows 共享内存的进程与之分离 (或结束/崩溃) 时, 内存即被销毁. 因此 Windows 共享内存不支持持久化.

要在系统服务与用户应用程序之间使用 managed_windows_shared_memory 通信, 请阅读 原生 Windows 共享内存 一章中的说明.

使用 XSI (System V) 共享内存

Unix 用户可能还想使用 XSI (System V) 而不是可移植的 shared_memory_object 托管内存. 这可以通过 basic_managed_xsi_shared_memory 类实现. 使用它只需包含:

#include <boost/interprocess/managed_xsi_shared_memory.hpp>

该类的接口与 basic_managed_shared_memory 几乎相同, 但后端使用 XSI 共享内存.

关于托管 XSI 共享内存能力的更多信息, 请参见 basic_managed_xsi_shared_memory 类参考.

常用托管映射文件

如前所述, basic_managed_mapped_file 提供了丰富的定制能力. 但对普通用户而言, 需要的是常见的、默认的共享内存命名对象创建. 因此, Boost.Interprocess 定义了最常用的托管映射文件特化:

//Named object creation managed memory segment
//All objects are constructed in the memory-mapped file
//   Names are c-strings,
//   Default memory management algorithm(rbtree_best_fit with no mutexes)
//   Name-object mappings are stored in the default index type (flat_map)
typedef basic_managed_mapped_file <
   char,
   rbtree_best_fit<mutex_family, offset_ptr<void> >,
   flat_map_index
   >  managed_mapped_file;

//Named object creation managed memory segment
//All objects are constructed in the memory-mapped file
//   Names are wide-strings,
//   Default memory management algorithm(rbtree_best_fit with no mutexes)
//   Name-object mappings are stored in the default index type (flat_map)
typedef basic_managed_mapped_file<
   wchar_t,
   rbtree_best_fit<mutex_family, offset_ptr<void> >,
   flat_map_index
   >  wmanaged_mapped_file;

managed_mapped_file 在内存映射文件中分配与 c 字符串关联的对象, wmanaged_mapped_file 在内存映射文件中分配与 wchar_t 空结尾字符串关联的对象. 两者都把指针类型定义为 offset_ptr<void> , 因此可用于在不同进程中以不同基址映射文件.

构造托管映射文件

托管映射文件是一个高级类, 它组合了一个文件和一个覆盖整个文件的映射区域. 这意味着当我们 创建 一个新的托管映射文件时:

  • 创建一个新文件.
  • 整个文件映射到进程的地址空间.
  • 在映射区域中构造一些辅助对象 (名称-对象索引、内部同步对象、内部变量...) 以实现托管内存段特性.

当我们 打开 一个托管映射文件时

  • 打开一个文件.
  • 整个文件映射到进程的地址空间.

要使用托管映射文件, 必须包含以下头文件:

#include <boost/interprocess/managed_mapped_file.hpp>

//1.  Creates a new file
//    called "MyMappedFile".
//2.  Maps the whole file to this
//    process' address space.
//3.  Constructs some objects in the memory mapped
//    file to implement managed features.
//!!  If anything fails, throws interprocess_exception
//
managed_mapped_file mfile      ( create_only
                               , "MyMappedFile" //Mapped file name
                               , 65536);        //Mapped file size

//1.  Opens a file
//    called "MyMappedFile".
//2.  Maps the whole file to this
//    process' address space.
//3.  Obtains pointers to constructed internal objects
//    to implement managed features.
//!!  If anything fails, throws interprocess_exception
//
managed_mapped_file mfile      ( open_only
                               , "MyMappedFile"); //Mapped file name

//1.  If the file was previously created
//    equivalent to "open_only".
//2.  Otherwise, equivalent to "open_only" (size is ignored)
//
//!!  If anything fails, throws interprocess_exception
//
managed_mapped_file mfile      (open_or_create
                               , "MyMappedFile" //Mapped file name
                               , 65536);        //Mapped file size

当 managed_mapped_file 对象被销毁时, 文件会自动解除映射, 所有资源被释放. 要从文件系统中删除文件, 可以使用标准 C 的 std::remove 或 Boost.Filesystem 的 remove() 函数, 但如果仍有进程把该文件映射在内存中, 或文件被任何进程打开, 删除可能失败.

要获得更可移植的行为, 请使用 file_mapping::remove(const char *) 操作, 即使文件正被映射也能删除. 不过, 在某些操作系统上, 如果文件已被打开 (例如被 C++ 文件流打开) 且未授予删除共享权限, 删除仍会失败. 但在大多数常见情况下 file_mapping::remove 已经足够可移植.

关于托管映射文件能力的更多信息, 请参见 basic_managed_mapped_file 类参考.
