与映射地址无关的指针: offset_ptr

当创建共享内存和内存映射文件来在两个进程之间通信时, 内存段在每个进程中可能映射到不同地址:

#include<boost/interprocess/shared_memory_object.hpp>

// ...

using namespace boost::interprocess;

//Open a shared memory segment
shared_memory_object shm_obj
   (open_only                    //open or create
   ,"shared_memory"              //name
   ,read_only   //read-only mode
   );

//Map the whole shared memory
mapped_region region
   ( shm                         //Memory-mappable object
   , read_write                  //Access mode
   );

//This address can be different in each process
void *addr = region.get_address();

这使在映射区域中创建复杂对象变得困难: 放在映射区域中的 C++ 类实例可能有指针指向同样放在映射区域中的另一个对象. 由于指针存储的是绝对地址, 该地址只对把对象放到那里的进程有效, 除非所有进程把映射区域映射到相同地址.

为了能在映射区域中模拟指针, 用户必须使用 偏移量 (对象之间的距离) 而非绝对地址. 映射区域中两个对象之间的偏移量对任何映射该区域的进程都相同, 即使该区域放在不同基址上. 为便于使用偏移量, Boost.Interprocess 提供了 offset_ptr.

offset_ptr 封装了提供类指针接口所需的全部底层操作. 该类的接口受 Boost 智能指针启发, 这个智能指针存储所指对象地址与其自身 this 指针之间的偏移 (以字节为单位的距离). 想象常见 32 位处理器上的一个结构:

struct structure
{
   int               integer1;   //The compiler places this at offset 0 in the structure
   offset_ptr<int>   ptr;        //The compiler places this at offset 4 in the structure
   int               integer2;   //The compiler places this at offset 8 in the structure
};

//...

structure s;

//Assign the address of "integer1" to "ptr".
//"ptr" will store internally "-4":
//    (char*)&s.integer1 - (char*)&s.ptr;
s.ptr = &s.integer1;

//Assign the address of "integer2" to "ptr".
//"ptr" will store internally "4":
//    (char*)&s.integer2 - (char*)&s.ptr;
s.ptr = &s.integer2;

的一个大问题 offset_ptr 是空指针的表示. 空指针无法安全地用偏移表示, 因为绝对地址 0 总是在映射区域之外. 由于段在每个进程中可能映射到不同基址, 地址 0 与 offset_ptr 之间的距离对每个进程都不同.

一些实现选择偏移 0 (即指向自身的 offset_ptr ) 作为空指针表示, 但这对许多用例无效, 因为像链表或 STL 容器节点这样的结构经常指向自身 (例如空容器的末端节点), 需要用到 0 偏移值. 另一种方案是在偏移之外再存储一个布尔值来指示指针是否为空. 然而, 这会增加指针大小并损害性能.

因此, offset_ptr 把偏移 1 定义为空指针, 这意味着该类 不能 指向其自身 this 指针之后的那个字节:

using namespace boost::interprocess;

offset_ptr<char> ptr;

//Pointing to the next byte of it's own address
//marks the smart pointer as null.
ptr = (char*)&ptr + 1;

//ptr is equal to null
assert(!ptr);

//This is the same as assigning the null value...
ptr = 0;

//ptr is also equal to null
assert(!ptr);

实践中这一限制并不重要, 因为用户几乎从不需要指向这个地址.

offset_ptr 提供所有类指针操作和 random_access_iterator typedef, 因此可以用在需要随机访问迭代器的 STL 算法中, 并可通过 traits 检测. 关于该类成员与操作的更多信息, 请参见 offset_ptr reference.
