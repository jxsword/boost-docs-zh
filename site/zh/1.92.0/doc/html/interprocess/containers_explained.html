Boost.Interprocess 分配器对容器的要求

Boost.Interprocess 的 STL 兼容分配器提供 STL 兼容的分配器接口, 如果它们把内部的 pointer typedef 定义为相对指针, 就可以用来把 STL 容器放入共享内存、内存映射文件或用户自定义的内存段中.

最初, 在 C++98 和 C++03 中, 这个 pointer typedef 毫无用处. 正如 Scott Meyers 在其 Effective STL 一书第 10 条中提到的, "注意分配器的约定与限制":

  • "标准明确允许库实现者假设每个分配器的 pointer typedef 都是 T* 的同义词"
  • "标准规定, STL 的实现可以假设同类型的所有分配器对象都是等价的, 且总是比较相等"

显然, 如果任何 STL 实现忽略 pointer typedef, 就没有任何智能指针能用作 allocator::pointer. 如果 STL 实现假设同类型的所有分配器对象比较相等, 它就会认为分别从不同内存池分配的两个分配器相等, 这完全是灾难.

我们要用 Boost.Interprocess 放入共享内存或内存映射文件的 STL 容器不能做任何这些假设, 因此:

  • STL 容器不得假设用一个分配器分配的内存可以用同类型的其他分配器释放. 只有当一个对象分配的内存可以用另一个对象释放时, 分配器对象才必须比较相等, 而这只能在运行期用 operator==() 检验.
  • 容器的内部指针应当是 allocator::pointer 类型, 且容器不得假设 allocator::pointer 是原始指针.

这在理论上已在 C++11 中修复: 引入了 std::pointer_traits 工具, 标准库容器也为它们添加了支持. 然而, 由于 ABI 顾虑和用户需求不多, 一些实现仍未完全支持 花哨指针 (fancy pointer) 类型, 例如 boost::interprocess:offset_ptr . 这些实现在某些容器中仍使用原始指针实现内部数据或迭代器.

这种不可移植的情况在 "P0773R0: Towards meaningful fancy pointers" 中有描述

"我们能否使用偏移花哨指针类型来实现内存区域的安全共享?"

"可以; 但对厂商的要求不明确, 而且程序员也面临一些陷阱."

"场景 (A), 即偏移指针, 只有一个站得住脚的解决方案, "继续给予部分支持""

托管内存段中的可移植容器

重要

由于 Boost.Container 于 2011 年从 Boost.Interprocess 中诞生, 本库一直维护着几个 <boost/interprocess/containers/.hpp> 头文件以保持向后兼容. 这些头文件现已弃用, 并将在未来的 Boost 版本中移除. 用户应直接使用 Boost.Container 头文件

由于标准库实现存在上述部分支持的情况, Boost.Interprocess 强烈建议使用 Boost.Container 容器, 它们保证可与 Boost.Interprocess 协同工作

以下 Boost.Container 容器与 Boost.Interprocess 兼容:

  • deque
  • devector
  • flat_map/multimap
  • flat_set/multiset
  • list
  • map/multimap
  • set/multiset
  • slist
  • small_vector
  • stable_vector
  • static_vector
  • string
  • vector

要把这些容器放入托管内存段, 我们必须用 Boost.Interprocess 分配器定义分配器模板参数, 使容器在托管内存段中分配值. 要把容器本身放入共享内存, 我们用 Boost.Interprocess 在托管内存段中构造它, 就像构造其他对象一样. 注意这些容器也支持 uses-allocator 协议, 得益于隐式分配器传递协议, 用法得以简化:

#include <boost/container/vector.hpp>
#include <boost/interprocess/allocators/allocator.hpp>
#include <boost/interprocess/managed_shared_memory.hpp>

int main ()
{
   using namespace boost::interprocess;
   //Remove shared memory on construction and destruction
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   } remover;

   //A managed shared memory where we can construct objects
   //associated with a c-string
   managed_shared_memory segment(create_only,"MyName", 65536);

   //Alias an STL-like allocator of ints that allocates ints from the segment
   typedef allocator<int, managed_shared_memory::segment_manager>
      ShmemAllocator;

   //Alias a vector that uses the previous STL-like allocator
   typedef boost::container::vector<int, ShmemAllocator> MyVector;

   int initVal[]        = {0, 1, 2, 3, 4, 5, 6 };
   const int *begVal    = initVal;
   const int *endVal    = initVal + sizeof(initVal)/sizeof(initVal[0]);

   //Initialize the STL-like allocator
   const ShmemAllocator alloc_inst (segment.get_segment_manager());

   //Construct the vector in the shared memory segment with the STL-like allocator
   //from a range of iterators
   MyVector *myvector =
      segment.construct<MyVector>
         ("MyVector")/*object name*/
         (begVal     /*first ctor parameter*/
         ,endVal     /*second ctor parameter*/
         ,alloc_inst /*third ctor parameter*/);

   //Use vector as your want
   std::sort(myvector->rbegin(), myvector->rend());
   // . . .
   //When done, destroy and delete vector from the segment
   segment.destroy<MyVector>("MyVector");

   //Note that you can take advantage of the uses-allocator protocol and avoid
   //explicitly passing the allocator parameter ("construct" will detect the container
   //is compatible with the protocol and initialize the allocator accordingly:
   myvector = segment.construct<MyVector>("MyVector") (begVal,endVal);

   //Alternative destroy function that takes the pointer instead of the name
   segment.destroy_ptr(myvector);

   return 0;
}

这些容器也展示了创建/修改现有容器使其能放入共享内存是多么容易.

这块内存在哪里分配?

Boost.Interprocess 容器是使用两种机制 同时 放入共享内存/内存映射文件等的:

  • Boost.Interprocess construct<>, find_or_construct<>... 函数. 这些函数把一个 C++ 对象放入共享内存/内存映射文件. 但这只放置对象本身, 而 不是 对象可能动态分配的内存.
  • 共享内存分配器. 它们允许分配共享内存/内存映射文件的部分区域, 使容器能够动态分配内存片段来存储新插入的元素.

这意味着, 要把任何 Boost.Interprocess 容器 (包括 Boost.Interprocess 字符串) 放入共享内存或内存映射文件, 容器 必须:

  • 把模板分配器参数定义为 Boost.Interprocess 分配器.
  • 每个容器构造函数都必须接受 Boost.Interprocess 分配器作为参数.
  • 必须使用 construct<>/find_or_construct<>... 函数把容器放入托管内存.

如果做到前两点但不使用 construct<> 或 find_or_construct<> , 你创建的容器将 只 存在于你的进程中, 但其包含类型的内存却从共享内存/内存映射文件分配.

看一个示例:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/container/vector.hpp>
#include <boost/container/string.hpp>
#include <boost/interprocess/allocators/allocator.hpp>

int main ()
{
   using namespace boost::interprocess;
   //Typedefs
   typedef allocator<char, managed_shared_memory::segment_manager>
      CharAllocator;
   typedef boost::container::basic_string<char, std::char_traits<char>, CharAllocator>
      MyShmString;
   typedef allocator<MyShmString, managed_shared_memory::segment_manager>
      StringAllocator;
   typedef boost::container::vector<MyShmString, StringAllocator>
      MyShmStringVector;

   //Open shared memory
   //Remove shared memory on construction and destruction
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   } remover;

   managed_shared_memory shm(create_only, "MyName", 10000);

   //Create allocators
   CharAllocator     charallocator  (shm.get_segment_manager());
   StringAllocator   stringallocator(shm.get_segment_manager());

   //This string is in only in this process (the pointer pointing to the
   //buffer that will hold the text is not in shared memory).
   //But the buffer that will hold "this is my text" is allocated from
   //shared memory
   MyShmString mystring(charallocator);
   mystring = "this is my text";

   //This vector is only in this process (the pointer pointing to the
   //buffer that will hold the MyShmString-s is not in shared memory).
   //But the buffer that will hold 10 MyShmString-s is allocated from
   //shared memory using StringAllocator. Since strings use a shared
   //memory allocator (CharAllocator) the 10 buffers that hold
   //"this is my text" text are also in shared memory.
   MyShmStringVector myvector(stringallocator);
   myvector.insert(myvector.begin(), 10, mystring);

   //This vector is fully constructed in shared memory. All pointers
   //buffers are constructed in the same shared memory segment
   //This vector can be safely accessed from other processes.
   MyShmStringVector *myshmvector =
      shm.construct<MyShmStringVector>("myshmvector")(stringallocator);
   myshmvector->insert(myshmvector->begin(), 10, mystring);

   //Destroy vector. This will free all strings that the vector contains
   shm.destroy_ptr(myshmvector);
   return 0;
}

容器的容器

创建容器的容器时, 每个容器都需要一个分配器. 为了避免使用多个类型定义复杂的分配器, 我们可以利用 void 分配器提供的类型擦除, 以及把 void 分配器隐式转换为分配其他类型的分配器的能力.

这里有一个在共享内存中构建 map 的示例. 键是字符串, 映射类型是一个存储多个容器的类:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/interprocess/allocators/allocator.hpp>
#include <boost/container/map.hpp>
#include <boost/container/vector.hpp>
#include <boost/container/string.hpp>

using namespace boost::interprocess;
namespace bc = boost::container;

//Typedefs of allocators and containers
typedef managed_shared_memory::segment_manager                    seg_mngr_t;
typedef allocator<void, seg_mngr_t>                               void_alloc_t;
typedef bc::vector<int, allocator<int, seg_mngr_t> >              int_vec_t;
typedef bc::vector<int_vec_t, allocator<int_vec_t, seg_mngr_t> >  int_vec_vec_t;
typedef bc::basic_string
   <char, std::char_traits<char>, allocator<char, seg_mngr_t> >   string_t;

class complex_data
{
   string_t      string_;
   int_vec_vec_t int_vec_vec_;

   public:

   complex_data(const char *name, const void_alloc_t &valloc) //void_alloc_t is convertible to allocator<T>
      : string_(name, valloc), int_vec_vec_(valloc)
   {}
};

//Definition of a shared memory map<string_t,complex_data...>
typedef std::pair<const string_t, complex_data>                map_value_type;
typedef allocator<map_value_type, seg_mngr_t>                  map_value_type_allocator;
typedef bc::map< string_t, complex_data, std::less<string_t>
               , map_value_type_allocator>                     complex_map_type;

int main ()
{
   managed_shared_memory segment(create_only,"MyName", 65536); //Create shared memory

   //An allocator convertible to any allocator<T, seg_mngr_t> type
   void_alloc_t alloc_inst (segment.get_segment_manager());

   //Construct the map calling map(key_compare, allocator_type), the allocator argument is explicit
   complex_map_type *mymap = segment.construct<complex_map_type>
         ("MyMap")(std::less<string_t>(), alloc_inst);

   //Both key(string) and value(complex_data) need an allocator in their constructors
   string_t  key_object(alloc_inst);
   complex_data mapped_object("default_name", alloc_inst);
   map_value_type value(key_object, mapped_object);
   //Modify values and insert them in the map
   mymap->insert(value);

   return 0;
}

如果用户设计一个与 uses-allocator 构造 兼容的类型, 该示例可以简化. 这简化了代码, 并允许更高效的操作, 例如使用透明函数进行查找和插入:

#include <boost/interprocess/managed_shared_memory.hpp>
#include <boost/interprocess/allocators/allocator.hpp>
#include <boost/container/map.hpp>
#include <boost/container/vector.hpp>
#include <boost/container/string.hpp>
#include <functional>

using namespace boost::interprocess;
namespace bc = boost::container;

//Typedefs of allocators and containers
typedef managed_shared_memory::segment_manager                   seg_mngr_t;
typedef allocator<void, seg_mngr_t>                              void_alloc_t;
typedef bc::vector<int, allocator<int, seg_mngr_t> >             int_vec_t;
typedef bc::vector<int_vec_t, allocator<int_vec_t, seg_mngr_t> > int_vec_vec_t;
typedef bc::basic_string
   <char, std::char_traits<char>, allocator<char, seg_mngr_t> >  string_t;

class complex_data
{
   string_t      string_;
   int_vec_vec_t int_vec_vec_;

   public:
   typedef void_alloc_t allocator_type; //Activates the uses-allocator protocol

   complex_data(const char *name, const void_alloc_t &valloc) //void_alloc_t is convertible to allocator<T>
      : string_(name, valloc), int_vec_vec_(valloc)
   {}
};

//Definition of a shared memory map<string_t, complex_data...> with transparent comparison
typedef std::pair<const string_t, complex_data>          map_value_type;
typedef allocator<map_value_type, seg_mngr_t>            map_value_type_allocator;
typedef bc::map< string_t, complex_data, std::less<>
               , map_value_type_allocator>               complex_map_type;

int main ()
{
   managed_shared_memory segment(create_only, "MyName", 65536); //Create shared memory

   //Construct the map calling map(key_compare, allocator_type), the allocator argument is implicit
   complex_map_type *mymap = segment.construct<complex_map_type>("MyMap")();

   //Efficient transparent insertion, string_t and complex_data are constructed in-place with implicit allocators
   mymap->try_emplace("key_str", "default_name");

   return 0;
}
