什么是共享内存?

共享内存是最快的进程间通信机制. 操作系统把一个内存段映射到多个进程的地址空间, 使多个进程无需调用操作系统函数即可读写该内存段. 不过, 读写共享内存的进程之间需要某种同步.

设想服务器进程想用网络机制向位于同一台机器上的客户端进程发送一个 HTML 文件时会发生什么:

  • 服务器必须把文件读入内存并传给网络函数, 网络函数再把这块内存复制到操作系统内部内存.
  • 客户端用网络函数把数据从操作系统内部内存复制到自己的内存.

如上所示, 共有两次复制: 一次从内存到网络, 一次从网络到内存. 而且这些复制通过通常开销不菲的操作系统调用完成. 共享内存可以避免这种开销, 但我们需要在两个进程之间同步:

  • 服务器把一块共享内存映射到自己的地址空间, 并获得对一个同步机制的访问权. 服务器用该同步机制获得对内存的独占访问, 然后把文件复制到内存.
  • 客户端把共享内存映射到自己的地址空间, 等待服务器释放独占访问权, 然后使用数据.

使用共享内存可以避免两次数据复制, 但必须同步对共享内存段的访问.

创建可在进程间共享的内存段

要使用共享内存, 必须执行两个基本步骤:

  • 向操作系统请求一个可在进程间共享的内存段. 用户可以用 共享内存对象 创建/销毁/打开这块内存: 一种表示可同时映射到多个进程地址空间的内存的对象.
  • 把该内存的一部分或全部与调用进程的地址空间关联. 操作系统在调用进程的地址空间中寻找一个足够大的地址范围, 并把该地址范围标记为特殊范围. 对该地址范围的更改会被其他同样映射了同一共享内存对象的进程自动看到.

两个步骤成功完成后, 进程就可以开始写读地址空间, 向其他进程发送和接收数据. 下面看看如何用 Boost.Interprocess 做到这一点:

头文件

管理共享内存只需包含以下头文件:

#include <boost/interprocess/shared_memory_object.hpp>

创建共享内存段

如前所述, 我们必须使用 shared_memory_object 类来创建、打开和销毁可被多个进程映射的共享内存段. 我们可以指定该共享内存对象的访问模式 (只读或读写), 就像对待文件一样:

  • 创建共享内存段. 如果已创建则抛出异常:
using namespace boost::interprocess;
shared_memory_object shm_obj
   (create_only                  //only create
   ,"shared_memory"              //name
   ,read_write                   //read-write mode
   );
  • 打开或创建共享内存段:
using namespace boost::interprocess;
shared_memory_object shm_obj
   (open_or_create               //open or create
   ,"shared_memory"              //name
   ,read_only                    //read-only mode
   );
  • 只打开共享内存段. 如果不存在则抛出异常:
using namespace boost::interprocess;
shared_memory_object shm_obj
   (open_only                    //only open
   ,"shared_memory"              //name
   ,read_write                   //read-write mode
   );

共享内存对象创建时大小为 0. 要设置共享内存的大小, 用户必须在以读写属性打开的共享内存上使用 truncate 函数调用:

shm_obj.truncate(10000);

由于共享内存具有内核或文件系统生存期, 用户必须显式销毁它. remove 操作在共享内存不存在、文件已打开或文件仍被其他进程内存映射时可能失败并返回 false:

using namespace boost::interprocess;
shared_memory_object::remove("shared_memory");

关于 shared_memory_object 的更多细节, 请参见 boost::interprocess::shared_memory_object 类参考.

映射共享内存段

创建或打开之后, 进程只需把共享内存对象映射到进程的地址空间. 用户可以映射整个共享内存, 也可以只映射其中一部分. 映射过程用 mapped_region 类完成. 该类表示已从共享内存或其他同样具备映射能力的设备 (例如文件) 映射来的内存区域. 可以从任何 mapped_region 对象创建 memory_mappable , 而且可以想象, shared_memory_object 就是一个 memory_mappable 对象:

using namespace boost::interprocess;
std::size_t ShmSize = ...

//Map the second half of the memory
mapped_region region
   ( shm                      //Memory-mappable object
   , read_write               //Access mode
   , ShmSize/2                //Offset from the beginning of shm
   , ShmSize-ShmSize/2        //Length of the region
   );

//Get the address of the region
region.get_address();

//Get the size of the region
region.get_size();

用户可以指定映射区域从可映射对象的哪个偏移开始以及映射区域的大小. 如果未指定偏移或大小, 则映射整个可映射对象 (此处为共享内存). 如果指定了偏移但未指定大小, 映射区域覆盖从偏移到可映射对象末尾的部分.

关于 mapped_region 的更多细节, 请参见 boost::interprocess::mapped_region 类参考.

简单示例

来看一个共享内存使用的简单示例. 服务器进程创建共享内存对象, 映射它并把所有字节初始化为某个值. 之后, 客户端进程打开共享内存, 映射它, 并检查数据是否已正确初始化:

#include <boost/interprocess/shared_memory_object.hpp>
#include <boost/interprocess/mapped_region.hpp>
#include <cstring>
#include <cstdlib>
#include <string>

int main(int argc, char *argv[])
{
   using namespace boost::interprocess;

   if(argc == 1){  //Parent process
      //Remove shared memory on construction and destruction
      struct shm_remove
      {
         shm_remove() { shared_memory_object::remove("MyName"); }
         ~shm_remove(){ shared_memory_object::remove("MyName"); }
      } remover;

      //Create a shared memory object.
      shared_memory_object shm (create_only, "MyName", read_write);

      //Set size
      shm.truncate(1000);

      //Map the whole shared memory in this process
      mapped_region region(shm, read_write);

      //Write all the memory to 1
      std::memset(region.get_address(), 1, region.get_size());

      //Launch child process
      std::string s(argv[0]); s += " child ";
      if(0 != std::system(s.c_str()))
         return 1;
   }
   else{
      //Open already created shared memory object.
      shared_memory_object shm (open_only, "MyName", read_only);

      //Map the whole shared memory in this process
      mapped_region region(shm, read_only);

      //Check that memory was initialized to 1
      char *mem = static_cast<char*>(region.get_address());
      for(std::size_t i = 0; i < region.get_size(); ++i)
         if(*mem++ != 1)
            return 1;   //Error checking memory
   }
   return 0;
}

无共享内存对象系统的模拟

Boost.Interprocess 以 POSIX 语义提供可移植的共享内存. 一些操作系统不支持 POSIX 定义的共享内存:

  • Windows 操作系统使用页面文件支撑的内存提供共享内存, 但生存期语义与 POSIX 定义的不同 (更多信息见 原生 Windows 共享内存 一节).
  • 一些 UNIX 系统完全不提供完整的 POSIX 共享内存对象支持.

在这些平台上, 共享内存用临时文件目录中创建的 "boost_interprocess" 文件夹里的映射文件来模拟. 在 Windows 平台上, 如果注册表中存在 "Common AppData" 键, "boost_interprocess" 文件夹就创建在该目录下 (XP 中通常为 "C:\Documents and Settings\All Users\Application Data", Vista 中为 "C:\ProgramData"). 对没有该注册键的 Windows 平台和 Unix 系统, 共享内存创建在系统临时文件目录 ("/tmp" 或类似) 中.

由于这种模拟, 在其中一些系统上共享内存具有文件系统生存期.

移除共享内存

shared_memory_object 提供静态 remove 函数来移除共享内存对象.

如果共享内存对象不存在或被另一个进程打开, 该函数 可能 失败. 注意该函数与标准 C 的 int remove(const char *path) 函数类似. 在 UNIX 系统中, shared_memory_object::remove 调用 shm_unlink:

  • 该函数将移除 name 所指字符串命名的共享内存对象的名称.
  • 如果在解除链接时存在一个或多个对共享内存对象的引用, 名称会在函数返回前被移除, 但内存对象内容的删除将推迟到对共享内存对象的所有打开和映射引用都被移除之后.
  • 即使对象在最后一次函数调用之后仍然存在, 随后重用该名称再创建 boost::interprocess::shared_memory_object 实例时, 行为就如同不存在同名共享内存对象一样 (即尝试用该名称打开对象会失败, 而同名对象可以再次创建).

在 Windows 操作系统中, 当前版本对 UNIX unlink 行为提供了一种通常可接受的模拟: 文件被改名为随机名称, 并标记为 在最后一个打开的句柄关闭时删除.

UNIX 系统的匿名共享内存

当涉及多个进程时, 创建共享内存段并映射它会有些繁琐. 在 UNIX 系统中, 如果进程之间通过 fork() 操作系统调用相关联, 可以用匿名共享内存这一更简单的方法.

这一特性在 UNIX 系统上通过映射 \dev\zero 设备实现, 或者在符合 POSIX 的 MAP_ANONYMOUS 系统调用中直接使用 mmap .

这一特性在 Boost.Interprocess 中通过 anonymous_shared_memory() 函数封装, 该函数返回一个 mapped_region 对象, 其中包含可由相关进程共享的匿名共享内存段.

下面是一个示例:

#include <boost/interprocess/anonymous_shared_memory.hpp>
#include <boost/interprocess/mapped_region.hpp>
#include <iostream>
#include <cstring>

int main ()
{
   using namespace boost::interprocess;
   try {
      //Create an anonymous shared memory segment with size 1000
      mapped_region region(anonymous_shared_memory(1000));

      //Write all the memory to 1
      std::memset(region.get_address(), 1, region.get_size());

      //The segment is unmapped when "region" goes out of scope
   }
   catch(interprocess_exception &ex){
      std::cout << ex.what() << std::endl;
      return 1;
   }
   return 0;
}

段创建后, 可以使用 fork() 调用, 让 region 在两个相关进程之间通信.

原生 Windows 共享内存

Windows 操作系统也提供共享内存, 但这种共享内存的生存期与内核或文件系统生存期大不相同. 共享内存由页面文件支撑, 当最后一个连接到共享内存的进程结束时, 它会被自动销毁.

因此, 用原生 Windows 共享内存无法有效模拟内核或文件系统持久化, Boost.Interprocess 用内存映射文件来模拟共享内存. 这保证了 POSIX 与 Windows 操作系统之间的可移植性.

不过, 访问原生 Windows 共享内存是 Boost.Interprocess 用户的常见需求, 因为他们想访问由不使用 Boost.Interprocess 的其他进程创建的共享内存. 为了管理原生 Windows 共享内存, Boost.Interprocess 提供了 windows_shared_memory 类.

Windows 共享内存的创建与可移植共享内存的创建略有不同: 段的大小必须在创建对象时指定, 不能像共享内存对象那样通过 truncate 指定. 请注意, 当最后一个连接到共享内存的进程结束时, 共享内存即被销毁 , 因此原生 Windows 共享内存 没有持久性.

在服务与用户应用程序之间共享内存也有所不同. 要在服务与用户应用程序之间共享内存, 共享内存的名称必须以全局命名空间前缀 "Global\\" 开头. 这个全局命名空间使多个客户端会话上的进程能够与服务应用程序通信. 服务组件可以在全局命名空间中创建共享内存, 然后客户端会话可以使用 "Global" 前缀打开这块内存.

从会话零以外的会话在全局命名空间中创建共享内存对象是需要特权的操作.

重复一下可移植共享内存对象给出的同一示例: 服务器进程创建共享内存对象, 映射它并把所有字节初始化为某个值. 之后, 客户端进程打开共享内存, 映射它, 并检查数据是否已正确初始化. 请注意, 如果服务器在客户端连接共享内存之前退出, 客户端的连接将失败 , 因为当没有进程连接到内存时, 共享内存段即被销毁.

这是服务器进程:

#include <boost/interprocess/windows_shared_memory.hpp>
#include <boost/interprocess/mapped_region.hpp>
#include <cstring>
#include <cstdlib>
#include <string>

int main(int argc, char *argv[])
{
   using namespace boost::interprocess;

   if(argc == 1){  //Parent process
      //Create a native windows shared memory object.
      windows_shared_memory shm (create_only, "MyName", read_write, 1000);

      //Map the whole shared memory in this process
      mapped_region region(shm, read_write);

      //Write all the memory to 1
      std::memset(region.get_address(), 1, region.get_size());

      //Launch child process
      std::string s(argv[0]); s += " child ";
      if(0 != std::system(s.c_str()))
         return 1;
      //windows_shared_memory is destroyed when the last attached process dies...
   }
   else{
      //Open already created shared memory object.
      windows_shared_memory shm (open_only, "MyName", read_only);

      //Map the whole shared memory in this process
      mapped_region region(shm, read_only);

      //Check that memory was initialized to 1
      char *mem = static_cast<char*>(region.get_address());
      for(std::size_t i = 0; i < region.get_size(); ++i)
         if(*mem++ != 1)
            return 1;   //Error checking memory
      return 0;
   }
   return 0;
}

如上所示, 原生 Windows 共享内存需要同步, 以确保共享内存不会在客户端启动之前被销毁.

XSI 共享内存

在许多 UNIX 系统上, 操作系统还提供另一种共享内存机制: XSI (X/Open 系统接口) 共享内存段, 也称 "System V" 共享内存. 这种共享内存机制相当流行且可移植, 它不基于文件映射语义, 而是使用特殊函数 (shmget, shmat, shmdt, shmctl...)

与 POSIX 共享内存段不同, XSI 共享内存段不由名称标识, 而由通常用 ftok 创建的 "键" 标识. XSI 共享内存段具有内核生存期, 必须显式移除. XSI 共享内存不支持写时复制和部分共享内存映射, 但支持匿名共享内存.

Boost.Interprocess 提供简单的 (xsi_shared_memory) 和托管的 (managed_xsi_shared_memory) 共享内存类来简化 XSI 共享内存的使用. 它还用简单的 xsi_key 类封装了键的创建.

重复一下可移植共享内存对象给出的同一示例: 服务器进程创建共享内存对象, 映射它并把所有字节初始化为某个值. 之后, 客户端进程打开共享内存, 映射它, 并检查数据是否已正确初始化.

这是服务器进程:

#include <boost/interprocess/xsi_shared_memory.hpp>
#include <boost/interprocess/mapped_region.hpp>
#include <cstring>
#include <cstdlib>
#include <string>

using namespace boost::interprocess;

void remove_old_shared_memory(const xsi_key &key)
{
   try {
      xsi_shared_memory xsi(open_only, key);
      xsi_shared_memory::remove(xsi.get_shmid());
   }
   catch(interprocess_exception &e){
      if(e.get_error_code() != not_found_error)
         throw;
   }
}

int main(int argc, char *argv[])
{
   if(argc == 1){  //Parent process
      //Build XSI key (ftok based)
      xsi_key key(argv[0], 1);

      remove_old_shared_memory(key);

      //Create a shared memory object.
      xsi_shared_memory shm (create_only, key, 1000);

      //Remove shared memory on destruction
      struct shm_remove
      {
         int shmid_;
         shm_remove(int shmid) : shmid_(shmid){}
         ~shm_remove(){ xsi_shared_memory::remove(shmid_); }
      } remover(shm.get_shmid());

      //Map the whole shared memory in this process
      mapped_region region(shm, read_write);

      //Write all the memory to 1
      std::memset(region.get_address(), 1, region.get_size());

      //Launch child process
      std::string s(argv[0]); s += " child ";
      if(0 != std::system(s.c_str()))
         return 1;
   }
   else{
      //Build XSI key (ftok based)
      xsi_key key(argv[0], 1);

      //Create a shared memory object.
      xsi_shared_memory shm (open_only, key);

      //Map the whole shared memory in this process
      mapped_region region(shm, read_only);

      //Check that memory was initialized to 1
      char *mem = static_cast<char*>(region.get_address());
      for(std::size_t i = 0; i < region.get_size(); ++i)
         if(*mem++ != 1)
            return 1;   //Error checking memory
   }
   return 0;
}

什么是内存映射文件?

文件映射是文件内容与进程地址空间某一部分的关联. 系统创建文件映射来关联文件与进程的地址空间. 映射区域是进程用来访问文件内容的地址空间部分. 单个文件映射可以有多个映射区域, 用户因此可以把文件的部分内容与进程地址空间关联, 而不必把整个文件映射进地址空间, 因为文件可能大于进程的整个地址空间 (常见 32 位系统上的 9GB DVD 镜像文件). 进程用指针读写文件, 就像使用动态内存一样. 文件映射有以下优点:

  • 统一的资源使用方式. 文件和内存可以用同一组函数处理.
  • 由操作系统自动进行文件数据同步与缓存.
  • 在文件中复用 C++ 工具 (STL 容器、算法).
  • 两个或多个应用程序之间的共享内存.
  • 无需把整个文件映射进内存即可高效处理大文件
  • 如果多个进程使用同一文件映射创建文件的映射区域, 每个进程的视图都包含磁盘上该文件的相同副本.

文件映射不仅用于进程间通信, 也可以用来简化文件的使用, 用户无需用文件管理函数来写文件. 用户只管把数据写进进程内存, 操作系统会把数据转储到文件.

当两个进程把同一文件映射进内存时, 一个进程写入的内存会被另一个进程看到, 因此内存映射文件可以用作进程间通信机制. 可以说, 内存映射文件提供与共享内存相同的进程间通信服务, 还附加了文件系统持久性. 不过, 由于操作系统必须同步文件内容与内存内容, 内存映射文件不如共享内存快.

使用映射文件

要使用内存映射文件, 必须执行两个基本步骤:

  • 创建一个代表文件系统中已有文件的可映射对象. 该对象将用于创建该文件的多个映射区域.
  • 把整个文件或文件的一部分与调用进程的地址空间关联. 操作系统在调用进程的地址空间中寻找一个足够大的地址范围, 并把该地址范围标记为特殊范围. 对该地址范围的更改会被其他同样映射了同一文件的进程自动看到, 而且这些更改也会自动传到磁盘.

两个步骤成功完成后, 进程就可以开始读写地址空间, 与其他进程收发数据, 并把文件内容与对映射区域所做的更改同步. 下面看看如何用 Boost.Interprocess 做到这一点:

头文件

管理映射文件只需包含以下头文件:

#include <boost/interprocess/file_mapping.hpp>

创建文件映射

首先, 我们必须把文件内容与进程地址空间关联. 为此, 必须创建一个代表该文件的可映射对象. 在 Boost.Interprocess 中, 这是通过创建 file_mapping 对象实现的:

using namespace boost::interprocess;
file_mapping m_file
   ("/usr/home/file"       //filename
   ,read_write             //read-write mode
   );

现在可以用新创建的对象创建映射区域. 关于此类的更多细节请参见 boost::interprocess::file_mapping 类参考.

把文件内容映射到内存

创建文件映射后, 进程只需把共享内存映射到进程的地址空间. 用户可以映射整个共享内存, 也可以只映射其中一部分. 映射过程用 mapped_region 类完成. 如前所述, 该类表示已从共享内存或其他同样具备映射能力的设备映射来的内存区域:

using namespace boost::interprocess;
std::size_t FileSize = ...

//Map the second half of the file
mapped_region region
   ( m_file                   //Memory-mappable object
   , read_write               //Access mode
   , FileSize/2               //Offset from the beginning of shm
   , FileSize-FileSize/2      //Length of the region
   );

//Get the address of the region
region.get_address();

//Get the size of the region
region.get_size();

用户可以指定映射区域从文件的哪个偏移开始以及映射区域的大小. 如果未指定偏移或大小, 则映射整个文件. 如果指定了偏移但未指定大小, 映射区域覆盖从偏移到文件末尾的部分.

如果多个进程映射同一文件, 而某进程修改了其他进程也映射的映射区域中的内存范围, 更改会立即对其他进程可见. 但磁盘上的文件内容不会立即更新, 因为那会损害性能 (写磁盘比写内存慢几倍). 如果用户想确保文件内容已更新, 可以把视图中的一段刷新到磁盘. 函数返回时, 刷新过程已经启动, 但不保证所有数据都已写入磁盘:

//Flush the whole region
region.flush();

//Flush from an offset until the end of the region
region.flush(offset);

//Flush a memory range starting on an offset
region.flush(offset, size);

记住, 这个偏移 不是文件中的偏移, 而是映射区域中的偏移. 如果一个区域覆盖文件的后半部分并刷新整个区域, 只能保证文件的一半已被刷新.

关于 mapped_region 的更多细节, 请参见 boost::interprocess::mapped_region 类参考.

简单示例

用内存映射文件重现共享内存一节描述的同一示例. 服务器进程创建共享内存段, 映射它并把所有字节初始化为某个值. 之后, 客户端进程打开共享内存, 映射它, 并检查数据是否已正确初始化:

#include <boost/interprocess/file_mapping.hpp>
#include <boost/interprocess/mapped_region.hpp>
#include <iostream>
#include <fstream>
#include <string>
#include <vector>
#include <cstring>
#include <cstddef>
#include <cstdlib>

int main(int argc, char *argv[])
{
   using namespace boost::interprocess;

   //Define file names
   const char *FileName  = "file.bin";
   const std::size_t FileSize = 10000;

   if(argc == 1){ //Parent process executes this
      {  //Create a file
         file_mapping::remove(FileName);
         std::filebuf fbuf;
         fbuf.open(FileName, std::ios_base::in | std::ios_base::out
                              | std::ios_base::trunc | std::ios_base::binary);
         //Set the size
         fbuf.pubseekoff(FileSize-1, std::ios_base::beg);
         fbuf.sputc(0);
      }

      //Remove on exit
      struct file_remove
      {
         file_remove(const char *FileName)
            : FileName_(FileName) {}
         ~file_remove(){ file_mapping::remove(FileName_); }
         const char *FileName_;
      } remover(FileName);

      //Create a file mapping
      file_mapping m_file(FileName, read_write);

      //Map the whole file with read-write permissions in this process
      mapped_region region(m_file, read_write);

      //Get the address of the mapped region
      void * addr       = region.get_address();
      std::size_t size  = region.get_size();

      //Write all the memory to 1
      std::memset(addr, 1, size);

      //Launch child process
      std::string s(argv[0]); s += " child ";
      if(0 != std::system(s.c_str()))
         return 1;
   }
   else{  //Child process executes this
      {  //Open the file mapping and map it as read-only
         file_mapping m_file(FileName, read_only);

         mapped_region region(m_file, read_only);

         //Get the address of the mapped region
         void * addr       = region.get_address();
         std::size_t size  = region.get_size();

         //Check that memory was initialized to 1
         const char *mem = static_cast<char*>(addr);
         for(std::size_t i = 0; i < size; ++i)
            if(*mem++ != 1)
               return 1;   //Error checking memory
      }
      {  //Now test it reading the file
         std::filebuf fbuf;
         fbuf.open(FileName, std::ios_base::in | std::ios_base::binary);

         //Read it to memory
         std::vector<char> vect(FileSize, 0);
         fbuf.sgetn(&vect[0], std::streamsize(vect.size()));

         //Check that memory was initialized to 1
         const char *mem = static_cast<char*>(&vect[0]);
         for(std::size_t i = 0; i < FileSize; ++i)
            if(*mem++ != 1)
               return 1;   //Error checking memory
      }
   }

   return 0;
}

映射区域详解

一个类统管一切
多个进程中的映射地址
固定地址映射
映射偏移与地址限制

一个类统管一切

如前所述, shared_memory_object 和 file_mapping 对象都可以用来创建 mapped_region 对象. 从共享内存对象或文件映射创建的映射区域是同一个类, 这带来许多好处.

例如, 可以在 STL 容器中混用来自共享内存和内存映射文件的映射区域. 只依赖映射区域的库无需重新编译即可用于共享内存或内存映射文件.

多个进程中的映射地址

在前面的示例中, 文件或共享内存内容映射到进程的地址空间, 但地址是由操作系统选择的.

如果多个进程映射同一文件/共享内存, 每个进程的映射地址几乎必然不同. 由于每个进程可能以不同方式使用其地址空间 (例如分配了或多或少的动态内存), 无法保证文件/共享内存会映射到相同的地址.

如果两个进程把同一对象映射到不同地址, 这会使该内存中的指针失效, 因为指针 (绝对地址) 只对写入它的进程有意义. 解决办法是使用对象之间的偏移 (距离) 而不是指针: 如果两个对象被一个进程放在同一共享内存段中, 那么在另一个进程中 每个对象的地址会不同 , 但 它们之间的距离 (以字节为单位) 是相同的.

因此, 映射共享内存和内存映射文件时的第一条建议是避免使用原始指针, 除非你清楚自己在做什么. 当放在映射区域中的对象想指向同一映射区域中的另一个对象时, 应使用数据之间的偏移或相对指针来获得指针功能. Boost.Interprocess 提供了一个名为 boost::interprocess::offset_ptr 的智能指针, 可以安全地放在共享内存中, 并用于指向放在同一共享内存/内存映射文件中的另一个对象.

固定地址映射

相对指针的使用效率低于原始指针, 因此如果用户能在两个进程中把同一文件或共享内存对象映射到相同地址, 使用原始指针可能是个好主意.

要把对象映射到固定地址, 用户可以在 mapped region 的构造函数中指定该地址:

mapped_region region ( shm                         //Map shared memory
                     , read_write                  //Map it as read-write
                     , 0                           //Map from offset 0
                     , 0                           //Map until the end
                     , (void*)0x3F000000           //Map it exactly there
                     );

不过, 即便地址未被占用, 用户也不能把区域映射到任意地址. 标记映射区域起点的偏移参数同样受到限制. 这些限制将在下一节说明.

映射偏移与地址限制

如前所述, 用户不能把可映射对象映射到任意地址, 也不能把相当于映射区域起点的可映射对象偏移指定为任意值. 大多数操作系统把映射地址和可映射对象的偏移限制为一个叫 页面大小 的值的倍数. 原因是 操作系统的映射操作以整页为单位进行.

如果使用固定映射地址, offset 和 address 参数应当是该值的倍数. 对 32 位操作系统, 该值通常为 4KB 或 8KB.

//These might fail because the offset is not a multiple of the page size
//and we are using fixed address mapping
mapped_region region1( shm                   //Map shared memory
                     , read_write            //Map it as read-write
                     , 1                     //Map from offset 1
                     , 1                     //Map 1 byte
                     , (void*)0x3F000000     //Aligned mapping address
                     );

//These might fail because the address is not a multiple of the page size
mapped_region region2( shm                   //Map shared memory
                     , read_write            //Map it as read-write
                     , 0                     //Map from offset 0
                     , 1                     //Map 1 byte
                     , (void*)0x3F000001     //Not aligned mapping address
                     );

由于操作系统的映射操作以整页为单位, 指定不是页面大小倍数的映射 size 或 offset 会浪费比必要更多的资源. 如果用户指定如下 1 字节映射:

//Map one byte of the shared memory object.
//A whole memory page will be used for this.
mapped_region region ( shm                    //Map shared memory
                     , read_write             //Map it as read-write
                     , 0                      //Map from offset 0
                     , 1                      //Map 1 byte
                     );

操作系统会保留一整页, 且不会被任何其他映射复用, 于是我们浪费了 (page size - 1) 字节. 要想高效使用操作系统资源, 应创建大小为 page size 字节倍数的区域. 如果用户为某文件指定如下两个映射区域, 该文件有 2*page_size 字节:

//Map the first quarter of the file
//This will use a whole page
mapped_region region1( shm                //Map shared memory
                     , read_write         //Map it as read-write
                     , 0                  //Map from offset 0
                     , page_size/2        //Map page_size/2 bytes
                     );

//Map the rest of the file
//This will use a 2 pages
mapped_region region2( shm                //Map shared memory
                     , read_write         //Map it as read-write
                     , page_size/2        //Map from offset 0
                     , 3*page_size/2      //Map the rest of the shared memory
                     );

在这个例子中, 第一半页浪费在第一个映射中, 另一半页浪费在第二个映射中, 因为偏移不是页面大小的倍数. 资源占用最小的映射是映射整页:

//Map the whole first half: uses 1 page
mapped_region region1( shm                //Map shared memory
                     , read_write         //Map it as read-write
                     , 0                  //Map from offset 0
                     , page_size          //Map a full page_size
                     );

//Map the second half: uses 1 page
mapped_region region2( shm                //Map shared memory
                     , read_write         //Map it as read-write
                     , page_size          //Map from offset 0
                     , page_size          //Map the rest
                     );

如何获得 page size ? mapped_region 类有一个返回该值的静态函数:

//Obtain the page size of the system
std::size_t page_size = mapped_region::get_page_size();

操作系统还可能限制每个进程或每个系统可映射的内存区域数量.

在映射区域中构造对象的限制

用偏移指针代替原始指针
禁止引用
禁止虚函数
小心静态类成员

当两个进程创建同一可映射对象的映射区域时, 两个进程可以通过读写这块内存通信. 一个进程可以在该内存中构造 C++ 对象供第二个进程使用. 然而, 被多个进程共享的映射区域并不能容纳任意 C++ 对象, 因为并非每个类都适合成为进程共享对象, 特别是当映射区域在每个进程中映射到不同地址时.

用偏移指针代替原始指针

把对象放入映射区域并在每个进程中把该区域映射到不同地址时, 原始指针会成为问题, 因为它们只对把对象放入其中的进程有效. 为解决此问题, Boost.Interprocess 提供了一种特殊的智能指针来代替原始指针. 因此, 含有原始指针 (或内部持有原始指针的 Boost 智能指针) 的用户类不能安全地放入进程共享的映射区域. 这些指针必须替换为偏移指针, 而且如果想让不同进程使用这些共享对象, 这些指针必须只指向放在同一映射区域中的对象.

当然, 放在进程间共享的映射区域中的指针只应指向该映射区域中的对象. 否则, 指针将指向只对一个进程有效的地址, 其他进程访问该地址时可能崩溃.

禁止引用

引用与指针有同样的问题 (主要因为引用就是用指针实现的). 然而, 目前 C++ 中无法创建完全可用的智能引用 (例如, operator .() 无法重载). 因此, 如果用户想把对象放入共享内存, 对象的成员中不能有任何 (智能或普通) 引用.

只有当映射区域在所有共享内存段的进程中都映射到相同基址时, 引用才能正常工作. 与指针一样, 放在映射区域中的引用只应指向该映射区域中的对象.

禁止虚函数

虚表指针和虚表位于构造对象的进程的地址空间中, 因此如果把带有虚函数或虚基类的类放入共享内存, 放在共享内存中的虚表指针对其他进程无效, 它们会崩溃.

这个问题很难解决, 因为每个进程需要不同的虚表指针, 而包含该指针的对象又被多个进程共享. 即使把映射区域在每个进程中映射到相同地址, 虚表也可能在每个进程中位于不同地址. 要为进程间共享的对象启用虚函数, 需要对编译器做深入修改, 而且虚函数会蒙受性能损失. 这就是 Boost.Interprocess 不计划支持进程间共享映射区域中的虚函数和虚继承的原因.

小心静态类成员

类的静态成员是被该类所有实例共享的全局对象. 因此, 静态成员在进程中实现为全局变量.

构造带有静态成员的类时, 每个进程都有自己的一份静态成员副本, 因此在一个进程中更新静态成员不会改变另一进程中该静态成员的值. 所以要小心这类类. 如果静态成员只是进程启动时初始化、之后完全不变的常量 (例如当作枚举使用), 且对所有进程取值相同, 那么它们并不危险.
