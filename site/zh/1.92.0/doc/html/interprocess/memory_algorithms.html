内存分配算法

simple_seq_fit: 简单的共享内存管理算法
rbtree_best_fit: 对数时间复杂度的最佳适配分配

simple_seq_fit: 简单的共享内存管理算法

该算法是顺序适配算法的变体, 使用空闲内存缓冲区的单向链表. 算法基于题为 "Taming Shared Memory" 的共享内存文章 . 算法如下:

共享内存被划分为若干空闲共享内存块, 每块带有一些控制数据和若干可立即使用的内存字节. 控制数据包含指向下一个空闲块的指针 (在我们的实现中是 offset_ptr) 和块的大小. 分配器由按地址排序的空闲块单向链表组成. 最后一块始终指向第一块:

simple_seq_fit memory layout:

    main      extra  allocated  free_block_1     allocated   free_block_2    allocated   free_block_3
    header    header  block       ctrl     usr     block      ctrl     usr     block      ctrl     usr
   _________  _____  _________  _______________  _________  _______________  _________  _______________
  |         ||     ||         ||         |     ||         ||         |     ||         ||         |     |
  |free|ctrl||extra||         ||next|size| mem ||         ||next|size| mem ||         ||next|size| mem |
  |_________||_____||_________||_________|_____||_________||_________|_____||_________||_________|_____|
      |                         | |                         |  |                       | |
      |_>_>_>_>_>_>_>_>_>_>_>_>_| |_>_>_>_>_>_>_>_>_>_>_>_>_|  |_>_>_>_>_>_>_>_>_>_>_>_| |
                                |                                                        |
                                |_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<_<__|

当用户请求 N 字节内存时, 分配器遍历空闲块链表, 寻找足够大的块. 如果块的 "mem" 部分与请求的内存大小相同, 我们把该块从链表中移除, 并返回指向其 "mem" 部分的指针. 如果 "mem" 部分大于所需, 我们把该块拆成两块: 一块为请求大小, 另一块为剩余大小. 然后取出大小恰好合适的块, 从链表中移除并交给用户.

当用户释放一个块时, 我们遍历链表 (记住链表是有序的), 根据块地址找到其位置. 找到后, 尽可能与相邻块合并.

为便于实现, 空闲内存块的大小以 "basic_size" 字节的倍数来度量. basic size 是对齐到机器最严格对齐值的控制块大小.

该算法是空间开销低的算法, 适合简单的分配方案. 只有当大小是主要考量时才应使用它, 因为内存碎片化时该算法的性能会下降. 该算法的分配和释放时间是线性的, 因此当分配数量很多时, 用户应使用对性能更友好的算法.

在大多数 32 位系统上, 按 8 字节对齐, "basic_size" 为 8 字节. 这意味着 1 字节的分配请求会产生 16 字节的块, 其中 8 字节可供用户使用. 分配 8 字节同样产生相同的 16 字节块.

rbtree_best_fit: 对数时间复杂度的最佳适配分配

该算法是高级算法, 使用红黑树按大小对内存段的空闲部分排序, 从而实现对数复杂度的分配. 除此之外, 它还维护一个由所有内存部分 (空闲与已分配) 组成的双向链表, 以便在合并操作时以常数时间访问前一块和后一块.

用于构建空闲节点红黑树的数据会被用户覆盖, 因为内存一旦分配, 这些数据就不再使用. 这把内存大小开销保持在双向链表开销的水平, 相当小 (两个指针). 基本方案如下:

rbtree_best_fit memory layout:

   main            allocated block   free block                        allocated block  free block
   header
  _______________  _______________  _________________________________  _______________  _________________________________
 |               ||         |     ||         |                 |     ||         |     ||         |                 |     |
 |  main header  ||next|prev| mem ||next|prev|left|right|parent| mem ||next|prev| mem ||next|prev|left|right|parent| mem |
 |_______________||_________|_____||_________|_________________|_____||_________|_____||_________|_________________|_____|

该分配算法相当快, 在大共享内存段和大数量分配的情况下扩展性良好. 形成一个块需要最小的内存量: 双向链表与红黑树控制数据之和. 块的大小以最严格对齐值的倍数度量.

在大多数按 8 字节对齐的 32 位系统上, 块的最小大小为 24 字节. 当块被分配时, 与红黑树相关的控制数据会被用户覆盖 (因为只有空闲块才需要它).

在这些系统上, 1 字节的分配请求意味着:

  • 用段中的 24 字节内存形成一个块.
  • 其中 16 字节可供用户使用.

对于极小的分配 (<= 8 字节), 该算法比简单顺序适配算法浪费更多内存 (多 8 字节). 对大于 8 字节的分配, 内存开销完全相同. 这是 Boost.Interprocess 托管内存段的默认分配算法.
