同步机制的类型

如前所述, 如果不能有效同步对内存的访问, 通过内存映射文件或共享内存对象在进程间共享内存的能力就没多大用处. 这与线程同步机制遇到的问题相同: 堆内存和全局变量在线程之间共享, 但对这些资源的访问通常需要通过互斥量和条件变量来同步. Boost.Threads 实现了同一进程内线程之间的这些同步工具. Boost.Interprocess 实现了类似的机制来同步不同进程的线程.

命名与匿名同步机制

Boost.Interprocess 提供两类同步对象:

  • 命名工具: 当两个进程想创建这种类型的对象时, 两个进程都必须用相同名称 创建 或 打开 对象. 这与创建或打开文件类似: 一个进程用 fstream 以名称 filename 创建文件, 另一个进程用另一个 fstream 以相同的 filename 参数打开该文件. 每个进程使用不同的对象来访问资源, 但两个进程使用的是同一个底层资源.
  • 匿名工具: 由于这类工具没有名称, 两个进程必须通过共享内存或内存映射文件共享 同一个对象. 这与传统线程同步对象类似: 两个进程共享同一个对象. 与线程同步不同 (后者的全局变量和堆内存在同一进程的线程之间共享), 不同进程的两个线程之间共享对象的唯一途径是通过映射同一可映射资源 (例如共享内存或内存映射文件) 的映射区域.

每种类型各有优缺点:

  • 对简单的同步任务, 命名工具更易处理, 因为两个进程不必创建共享内存区域并在其中构造同步机制.
  • 使用内存映射对象时, 匿名工具可以序列化到磁盘, 从而自动持久化同步工具. 可以在内存映射文件中构造一个同步工具, 重启系统, 再次映射文件, 然后毫无问题地继续使用该同步工具. 命名同步工具做不到这一点.

命名工具与匿名工具的主要接口区别在于构造函数. 匿名工具通常只有一个构造函数, 而命名工具有多个构造函数, 其第一个参数是一个特殊类型, 用于请求创建、打开或打开或创建底层资源:

using namespace boost::interprocess;

//Create the synchronization utility. If it previously
//exists, throws an error
NamedUtility(create_only, ...)

//Open the synchronization utility. If it does not previously
//exist, it's created.
NamedUtility(open_or_create, ...)

//Open the synchronization utility. If it does not previously
//exist, throws an error.
NamedUtility(open_only, ...)

另一方面, 匿名同步工具只能被创建, 进程必须用其他机制同步谁创建该工具:

using namespace boost::interprocess;

//Create the synchronization utility.
AnonymousUtility(...)

什么是互斥量?

Mutex (互斥量) 是 mutual exclusion 的缩写, 是进程间同步最基本的形式. 互斥量保证同一时刻只有一个线程能锁定给定的互斥量. 如果一段代码被互斥量的加锁和解锁包围, 就能保证同一时刻只有一个线程执行这段代码. 当该线程 解锁 互斥量后, 其他线程才能进入该代码区域:

//The mutex has been previously constructed

lock_the_mutex();

//This code will be executed only by one thread
//at a time.

unlock_the_mutex();

互斥量还可以是 递归的 或 非递归的:

  • 递归互斥量可以被同一线程多次锁定. 要完全解锁互斥量, 线程必须按加锁次数逐次解锁.
  • 非递归互斥量不能被同一线程多次锁定. 如果线程把互斥量锁定两次, 结果未定义: 可能抛出错误, 也可能线程永远被阻塞.

互斥量操作

来自 Boost.Interprocess 的所有互斥量类型都实现以下操作:

void lock()

效果:: 调用线程尝试获得互斥量的所有权; 如果另一线程拥有该互斥量, 则等待直到获得所有权. 线程取得互斥量所有权后, 必须由同一线程解锁. 如果互斥量支持递归锁定, 必须按加锁次数逐次解锁.

抛出:: 出错时抛出 interprocess_exception .

bool try_lock()

效果:: 调用线程尝试获得互斥量的所有权; 如果另一线程拥有该互斥量, 立即返回. 如果互斥量支持递归锁定, 必须按加锁次数逐次解锁.

返回:: 如果线程获得了互斥量所有权, 返回 true; 如果另一线程拥有该互斥量, 返回 false.

抛出:: 出错时抛出 interprocess_exception .

template<class TimePoint> bool timed_lock(const TimePoint &abs_time)

效果:: 调用线程将尝试获得互斥量的独占所有权, 直至到达指定时间. 如果互斥量支持递归锁定, 必须按加锁次数逐次解锁.

返回:: 如果线程获得了互斥量所有权, 返回 true; 如果超时, 返回 false.

抛出:: 出错时抛出 interprocess_exception .

void unlock()

前置条件:: 线程必须拥有该互斥量的独占所有权.

效果:: 调用线程释放互斥量的独占所有权. 如果互斥量支持递归锁定, 必须按加锁次数逐次解锁.

抛出:: 出错时抛出派生自 interprocess_exception 的异常.

重要

作用域锁

进程读写完数据后解锁互斥量非常重要. 在有异常的情况下这并不容易做到, 因此互斥量通常与作用域锁一起使用: 作用域锁是一个能保证互斥量总是被解锁的类, 即使发生异常也是如此. 要使用作用域锁只需包含:

#include <boost/interprocess/sync/scoped_lock.hpp>

基本上, 作用域锁在其析构函数中调用 unlock() , 因此即使发生异常互斥量也总会被解锁. 作用域锁有多个构造函数, 可以对互斥量加锁、尝试加锁、定时加锁或根本不加锁.

using namespace boost::interprocess;

//Let's create any mutex type:
MutexType mutex;

{
   //This will lock the mutex
   scoped_lock<MutexType> lock(mutex);

   //Some code

   //The mutex will be unlocked here
}

{
   //This will try_lock the mutex
   scoped_lock<MutexType> lock(mutex, try_to_lock);

   //Check if the mutex has been successfully locked
   if(lock){
      //Some code
   }

   //If the mutex was locked it will be unlocked
}

{
   boost::posix_time::ptime abs_time = ...

   //This will timed_lock the mutex
   scoped_lock<MutexType> lock(mutex, abs_time);

   //Check if the mutex has been successfully locked
   if(lock){
      //Some code
   }

   //If the mutex was locked it will be unlocked
}

更多信息请查阅 scoped_lock's reference .

匿名互斥量示例

设想两个进程需要向建在共享内存中的循环缓冲区写跟踪记录. 每个进程都需要获得对循环缓冲区的独占访问, 写入跟踪记录后继续.

为保护循环缓冲区, 我们可以在其中存储一个进程共享互斥量. 每个进程在写数据前锁定互斥量, 写完跟踪记录后写入一个标志 (doc_anonymous_mutex_shared_data.hpp 头文件):

#include <boost/interprocess/sync/interprocess_mutex.hpp>

struct shared_memory_log
{
   enum { NumItems = 100 };
   enum { LineSize = 100 };

   shared_memory_log()
      :  current_line(0)
      ,  end_a(false)
      ,  end_b(false)
   {}

   //Mutex to protect access to the queue
   boost::interprocess::interprocess_mutex mutex;

   //Items to fill
   char   items[NumItems][LineSize];
   int    current_line;
   bool   end_a;
   bool   end_b;
};

这是主进程. 它创建共享内存, 构造循环缓冲区并开始写跟踪记录:

#include <boost/interprocess/shared_memory_object.hpp>
#include <boost/interprocess/mapped_region.hpp>
#include <boost/interprocess/sync/scoped_lock.hpp>
#include "doc_anonymous_mutex_shared_data.hpp"
#include <iostream>
#include <cstdio>

using namespace boost::interprocess;

int main ()
{
   try {
      //Remove shared memory on construction and destruction
      struct shm_remove
      {
         shm_remove() { shared_memory_object::remove("MyName"); }
         ~shm_remove(){ shared_memory_object::remove("MyName"); }
      } remover;

      //Create a shared memory object.
      shared_memory_object shm
         (create_only                  //only create
         , "MyName" //name
         , read_write                  //read-write mode
         );

      //Set size
      shm.truncate(sizeof(shared_memory_log));

      //Map the whole shared memory in this process
      mapped_region region
         (shm                       //What to map
         ,read_write   //Map it as read-write
         );

      //Get the address of the mapped region
      void * addr       = region.get_address();

      //Construct the shared structure in memory
      shared_memory_log * data = new (addr) shared_memory_log;

      //Write some logs
      for(int i = 0; i < shared_memory_log::NumItems; ++i){
         //Lock the mutex
         scoped_lock<interprocess_mutex> lock(data->mutex);
         std::sprintf(data->items[(data->current_line++) % shared_memory_log::NumItems]
                  ,"%s_%d", "process_a", i);
         if(i == (shared_memory_log::NumItems-1))
            data->end_a = true;
         //Mutex is released here
      }

      //Wait until the other process ends
      while(1){
         scoped_lock<interprocess_mutex> lock(data->mutex);
         if(data->end_b)
            break;
      }
   }
   catch(interprocess_exception &ex){
      std::cout << ex.what() << std::endl;
      return 1;
   }
   return 0;
}

如上所示, 互斥量可用于保护数据, 却不能用来向另一个进程通知事件. 为此, 我们需要条件变量, 下一节将介绍.

命名互斥量示例

现在设想两个进程要向文件写跟踪记录. 它们先写自己的名称, 再写消息. 由于操作系统可能随时中断进程, 两个进程的消息片段可能交错, 因此需要一种把整条消息原子地写入文件的方法. 为此, 我们可以使用命名互斥量, 让每个进程在写入前锁定互斥量:

#include <boost/interprocess/sync/scoped_lock.hpp>
#include <boost/interprocess/sync/named_mutex.hpp>
#include <fstream>
#include <iostream>
#include <cstdio>


int main ()
{
   using namespace boost::interprocess;
   try {
      struct file_remove
      {
         file_remove() { std::remove("MyName"); }
         ~file_remove(){ std::remove("MyName"); }
      } file_remover;
      struct mutex_remove
      {
         mutex_remove() { named_mutex::remove("MyName"); }
         ~mutex_remove(){ named_mutex::remove("MyName"); }
      } remover;

      //Open or create the named mutex
      named_mutex mutex(open_or_create, "MyName");

      std::ofstream file("MyName");

      for(int i = 0; i < 10; ++i){

         //Do some operations...

         //Write to file atomically
         scoped_lock<named_mutex> lock(mutex);
         file << "Process name, ";
         file << "This is iteration #" << i;
         file << std::endl;
      }
   }
   catch(interprocess_exception &ex){
      std::cout << ex.what() << std::endl;
      return 1;
   }
   return 0;
}

什么是条件变量?

在前面的示例中, 互斥量用于 加锁 , 但我们不能用它高效地 等待 直到继续条件满足. 条件变量能做两件事:

  • wait (等待): 线程被阻塞, 直到其他线程通知它可以继续, 因为导致等待的条件已经消失.
  • notify (通知): 线程向一个或所有被阻塞的线程发出信号, 告诉它们导致其等待的条件已经消失.

在条件变量上等待总是与互斥量关联的. 在条件上等待之前必须先锁定互斥量. 等待条件变量时, 线程 原子地 解锁互斥量并等待.

当线程从等待函数返回时 (例如因为收到信号或超时), 互斥量对象再次处于锁定状态.

命名条件变量与匿名条件变量类似, 但它们与命名互斥量配合使用. 很多时候, 我们不希望把同步对象与被同步的数据存放在一起:

  • 我们想在保持数据不变的情况下更换同步方法 (从进程间换到进程内, 或完全不用同步). 如果把进程共享的匿名同步对象与被同步的数据存在一起, 就无法做到这一点.
  • 我们想通过网络或其他通信方式发送被同步的数据. 发送进程共享的同步对象毫无意义.

匿名条件变量示例

设想一个进程向简单的共享内存缓冲区写跟踪记录, 另一个进程逐条打印. 第一个进程写完跟踪记录后等待另一个进程打印数据. 为此, 我们可以使用两个条件变量: 第一个用于阻塞发送方, 直到第二个进程打印了消息; 第二个用于阻塞接收方, 直到缓冲区中有可打印的跟踪记录.

共享内存跟踪缓冲区 (doc_anonymous_condition_shared_data.hpp):

#include <boost/interprocess/sync/interprocess_mutex.hpp>
#include <boost/interprocess/sync/interprocess_condition.hpp>

struct trace_queue
{
   enum { LineSize = 100 };

   trace_queue()
      :  message_in(false)
   {}

   //Mutex to protect access to the queue
   boost::interprocess::interprocess_mutex      mutex;

   //Condition to wait when the queue is empty
   boost::interprocess::interprocess_condition  cond_empty;

   //Condition to wait when the queue is full
   boost::interprocess::interprocess_condition  cond_full;

   //Items to fill
   char   items[LineSize];

   //Is there any message
   bool message_in;
};

这是主进程. 它创建共享内存, 把缓冲区放入其中, 然后逐条写消息, 直到写出 "last message" 表示没有更多要打印的消息:

#include <boost/interprocess/shared_memory_object.hpp>
#include <boost/interprocess/mapped_region.hpp>
#include <boost/interprocess/sync/scoped_lock.hpp>
#include <iostream>
#include <cstdio>
#include "doc_anonymous_condition_shared_data.hpp"

using namespace boost::interprocess;

int main ()
{

   //Erase previous shared memory and schedule erasure on exit
   struct shm_remove
   {
      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }
   } remover;

   //Create a shared memory object.
   shared_memory_object shm
      (create_only                  //only create
      , "MyName" //name
      , read_write                  //read-write mode
      );
   try {
      //Set size
      shm.truncate(sizeof(trace_queue));

      //Map the whole shared memory in this process
      mapped_region region
         (shm                       //What to map
         ,read_write //Map it as read-write
         );

      //Get the address of the mapped region
      void * addr       = region.get_address();

      //Construct the shared structure in memory
      trace_queue * data = new (addr) trace_queue;

      const int NumMsg = 100;

      for(int i = 0; i < NumMsg; ++i){
         scoped_lock<interprocess_mutex> lock(data->mutex);
         if(data->message_in){
            data->cond_full.wait(lock);
         }
         if(i == (NumMsg-1))
            std::sprintf(data->items, "%s", "last message");
         else
            std::sprintf(data->items, "%s_%d", "my_trace", i);

         //Notify to the other process that there is a message
         data->cond_empty.notify_one();

         //Mark message buffer as full
         data->message_in = true;
      }
   }
   catch(interprocess_exception &ex){
      std::cout << ex.what() << std::endl;
      return 1;
   }


   return 0;
}

第二个进程打开共享内存, 逐条打印消息, 直到收到 "last message" 消息:

#include <boost/interprocess/shared_memory_object.hpp>
#include <boost/interprocess/mapped_region.hpp>
#include <boost/interprocess/sync/scoped_lock.hpp>
#include <iostream>
#include <cstring>
#include "doc_anonymous_condition_shared_data.hpp"

using namespace boost::interprocess;

int main ()
{
   //Create a shared memory object.
   shared_memory_object shm
      (open_only                    //only create
      , "MyName" //name
      ,read_write                   //read-write mode
      );

   try {
      //Map the whole shared memory in this process
      mapped_region region
         (shm                       //What to map
         ,read_write //Map it as read-write
         );

      //Get the address of the mapped region
      void * addr       = region.get_address();

      //Obtain a pointer to the shared structure
      trace_queue * data = static_cast<trace_queue*>(addr);

      //Print messages until the other process marks the end
      bool end_loop = false;
      do{
         scoped_lock<interprocess_mutex> lock(data->mutex);
         if(!data->message_in){
            data->cond_empty.wait(lock);
         }
         if(std::strcmp(data->items, "last message") == 0){
            end_loop = true;
         }
         else{
            //Print the message
            std::cout << data->items << std::endl;
            //Notify the other process that the buffer is empty
            data->message_in = false;
            data->cond_full.notify_one();
         }
      }
      while(!end_loop);
   }
   catch(interprocess_exception &ex){
      std::cout << ex.what() << std::endl;
      return 1;
   }

   return 0;
}

什么是信号量?

信号量是一种基于内部计数的进程间同步机制, 提供两个基本操作:

  • Wait (等待): 测试信号量计数的值, 若小于或等于 0 则等待; 否则将计数减一.
  • Post (发布): 将信号量计数加一. 如果有进程被阻塞, 则唤醒其中一个.

如果信号量的初始计数设为 1, 则 Wait 操作等价于互斥量加锁, Post 等价于互斥量解锁. 这种信号量称为 二元信号量 .

虽然信号量可以像互斥量那样使用, 但它有一个独特之处: 与互斥量不同, Post 操作不必由执行 Wait 操作的同一个线程/进程执行.

      shm_remove() { shared_memory_object::remove("MyName"); }
      ~shm_remove(){ shared_memory_object::remove("MyName"); }

      , "MyName" //name
      , read_write                  //read-write mode
      );

   //Set size
   shm.truncate(sizeof(shared_memory_buffer));

   //Map the whole shared memory in this process
   mapped_region region
      (shm                       //What to map
      ,read_write //Map it as read-write
      );

   //Get the address of the mapped region
   void * addr       = region.get_address();

   shared_memory_buffer * data = new (addr) shared_memory_buffer;

   //Insert data in the array
   for(int i = 0; i < NumMsg; ++i){
      data->nempty.wait();
      data->mutex.wait();
      data->items[i % shared_memory_buffer::NumItems] = i;
      data->mutex.post();
      data->nstored.post();
   }

   return 0;
}

什么是共享互斥量和可升级互斥量?

共享互斥量与可升级互斥量是特殊的互斥量类型, 提供比普通互斥量更多的锁定可能. 有时, 我们可以区分 读取 数据与 修改 数据. 如果只有部分线程需要修改数据, 而用普通互斥量保护数据免受并发访问, 并发能力会相当有限: 两个只读数据的线程会被串行化, 而不是并发执行.

如果我们允许只读数据的线程并发访问, 同时避免读线程与写线程之间、或写线程相互之间的并发访问, 就能提升性能. 在读取数据多于修改数据、且同步的数据读取代码需要一定执行时间的应用中尤其如此. 用共享互斥量可以获得 2 种锁:

  • 独占锁: 类似普通互斥量. 如果一个线程获得独占锁, 在独占锁释放之前, 其他线程不能获得任何锁 (独占或其他). 如果任何线程已持有非独占的锁, 试图获得独占锁的线程将阻塞. 这种锁由要修改数据的线程获取.
  • 共享锁: 如果一个线程获得共享锁, 其他线程不能获得独占锁. 如果任何线程已持有独占锁, 试图获得共享锁的线程将阻塞. 这种锁由只需读取数据的线程获取.

用可升级互斥量, 除了上述锁之外还可以获得一种新的可升级锁:

  • 可升级锁: 获得可升级锁类似于获得 特权共享锁. 如果一个线程获得可升级锁, 其他线程可以继续获得共享锁. 如果任何线程已持有独占锁或可升级锁, 试图获得可升级锁的线程将阻塞. 已获得可升级锁的线程保证能够在持有共享锁的其他线程释放后, 原子地获得独占锁. 适用于 可能 需要修改数据、但通常只需读取数据的线程. 该线程获得可升级锁, 其他线程可以继续获得共享锁. 若该可升级线程读完数据后需要修改, 它可以提升为独占锁: 当所有共享锁线程都释放共享锁后, 可升级锁原子地提升为独占锁. 新提升的线程可以修改数据, 并确信在转换期间没有其他线程修改过数据. 只有 1 个线程可以获得可升级 (特权读者) 锁.

与普通互斥量一样, 即使出现异常也要释放已获得的锁, 这一点很重要. Boost.Interprocess 互斥量最好与 scoped_lock 工具配合使用, 但该类只提供独占锁定.

由于可升级互斥量有共享锁定与可升级锁定, 我们又有了两个新工具: sharable_lock 和 upgradable_lock . 这两个类与 scoped_lock 类似, 只是 sharable_lock 在构造函数中获得共享锁, 而 upgradable_lock 在构造函数中获得可升级锁.

这两个工具可用于任何提供所需操作的同步对象. 例如, 没有可升级锁定特性的用户自定义互斥量类型, 只要同步对象提供 sharable_locklock_sharable() 和 unlock_sharable() 操作, 就可以使用

#include <boost/interprocess/sync/sharable_lock.hpp>

#include <boost/interprocess/sync/upgradable_lock.hpp>

sharable_lock 在析构函数中调用 unlock_sharable() , 而 upgradable_lock 在析构函数中调用 unlock_upgradable() , 因此即使发生异常, 可升级互斥量也总会被解锁.

using namespace boost::interprocess;

SharableOrUpgradableMutex sh_or_up_mutex;

作用域锁及类似工具提供了简单的资源管理能力, 但对于可升级互斥量这类高级互斥量类型, 存在这样一些操作: 原子地释放已获得的锁类型并获得另一种锁类型. 这由可升级互斥量操作实现, 例如 unlock_and_lock_sharable().

这些操作用 锁转移操作 可以更有效地管理. 锁转移操作显式地表明, 一个锁所拥有的互斥量被转移到另一个锁, 执行原子解锁加加锁操作.

简单锁转移

设想一个线程先修改一些数据, 之后需要长时间只读这些数据. 代码可以先获得独占锁, 修改数据, 然后原子地释放独占锁并获得共享锁. 通过这一序列, 我们保证没有其他线程能在转换期间修改数据, 而且更多读者可以获得共享锁, 提升并发能力. 若不用锁转移操作, 代码要这样写:

using namespace boost::interprocess;
interprocess_upgradable_mutex mutex;

//Acquire exclusive lock
mutex.lock();

//Modify data

//Atomically release exclusive lock and acquire sharable lock.
//More threads can acquire the sharable lock and read the data.
mutex.unlock_and_lock_sharable();

//Read data

//Explicit unlocking
mutex.unlock_sharable();

这看似简单, 但一旦出现异常, 就很难知道抛出异常时互斥量处于哪种锁状态, 以及应该调用哪个函数来解锁:

try{
   //Mutex operations
}
catch(...){
   //What should we call? "unlock()" or "unlock_sharable()"
   //Is the mutex locked?
}

我们可以用 锁转移 来简化这些管理:

using namespace boost::interprocess;
interprocess_upgradable_mutex mutex;

//Acquire exclusive lock
scoped_lock s_lock(mutex);

//Modify data

//Atomically release exclusive lock and acquire sharable lock.
//More threads can acquire the sharable lock and read the data.
sharable_lock(move(s_lock));

//Read data

//The lock is automatically unlocked calling the appropriate unlock
//function even in the presence of exceptions.
//If the mutex was not locked, no function is called.

如上所示, 即使任何时刻抛出异常, 互斥量也会通过自动调用适当的 unlock() 或 unlock_sharable() 方法被解锁.

在前面的示例中, 转移操作使用的互斥量此前已被锁定:

}

但也可以用未锁定的源执行转移, 例如因为显式解锁、try、timed 或 defer_lock 构造函数:

//These operations can leave the mutex unlocked!

{
   //Try might fail
   scoped_lock<Mutex>      e_lock(mut, try_to_lock);
   sharable_lock<Mutex>    s_lock(move(e_lock));
}
{
   //Timed operation might fail
   scoped_lock<Mutex>      e_lock(mut, time);
   sharable_lock<Mutex>    s_lock(move(e_lock));
}
{
   //Avoid mutex locking
   scoped_lock<Mutex>      e_lock(mut, defer_lock);
   sharable_lock<Mutex>    s_lock(move(e_lock));
}
{
   //Explicitly call unlock
   scoped_lock<Mutex>      e_lock(mut);
   e_lock.unlock();
   //Mutex was explicitly unlocked
   sharable_lock<Mutex>    s_lock(move(e_lock));
}

  • 目标锁不执行原子 unlock_xxx_and_lock_xxx 操作.
  • 目标锁也处于未锁定状态.
  • 源锁被 release(), 互斥量的所有权转移给目标.
{
   scoped_lock<Mutex>      e_lock(mut, defer_lock);
   sharable_lock<Mutex>    s_lock(move(e_lock));

   //Assertions
   assert(e_lock.mutex() == 0);
   assert(s_lock.mutex() != 0);
   assert(e_lock.owns()  == false);
}

转移失败

执行锁转移时, 操作可能失败:

  • 执行的原子互斥量解锁加加锁函数可能抛出异常.
  • 执行的原子函数可能是可能失败的 "try" 或 "timed" 函数.

第一种情况下, 互斥量所有权不转移, 源锁的析构函数将解锁互斥量:

{
   scoped_lock<Mutex>      e_lock(mut, defer_lock);

   //This operations throws because
   //"unlock_and_lock_sharable()" throws!!!
   sharable_lock<Mutex>    s_lock(move(e_lock));

   //Some code ...

   //e_lock's destructor will call "unlock()"
}

第二种情况下, 如果内部 "try" 或 "timed" 操作失败 (返回 "false"), 互斥量所有权 不会 转移, 源锁保持不变, 目标锁的状态与默认构造时相同:

{
   sharable_lock<Mutex>    s_lock(mut);

   //Internal "try_unlock_sharable_and_lock_upgradable()" returns false
   upgradable_lock<Mutex>  u_lock(move(s_lock, try_to_lock));

   assert(s_lock.mutex() == &mut);
   assert(s_lock.owns()  == true);
   assert(u_lock.mutex() == 0);
   assert(u_lock.owns()  == false);

   //u_lock's destructor does nothing
   //s_lock's destructor calls "unlock()"
}

什么是文件锁?

文件锁是一种进程间同步机制, 使用 内嵌 在文件中的互斥量来保护对文件的并发读写. 这个 内嵌互斥量 具有共享与独占锁定能力. 有了文件锁, 现有文件就可以当作互斥量使用, 无需创建额外的同步对象来控制并发的文件读写.

一般来说, 文件锁定能力分两种:

  • 建议锁 (advisory locking):: 操作系统内核维护已锁定文件的列表, 但即使某进程获得了共享锁, 内核也不阻止向这些文件写入; 即使某进程获得了独占锁, 也不阻止从文件读取. 任何进程都可以无视建议锁. 这意味着建议锁是为 合作的 进程准备的, 即相互信任的进程. 这类似于保护共享内存段中数据的互斥量: 连接到该内存的任何进程都可以覆写数据, 但 合作的 进程会先获取互斥量锁, 用互斥量保护数据.
  • 强制锁 (mandatory locking):: 操作系统内核检查每一次读写请求, 验证该操作是否可以按照已获得的锁执行. 读写在锁释放之前被阻塞.

Boost.Interprocess 使用各操作系统广泛使用的原生能力, 这意味着:

  • 在 Unix 系统上, 使用广泛可用且经过充分测试的基于 POSIX fcntl 的建议锁. 此外, 一些强制锁实现 (如 Linux) 并不可靠.
  • 在 Windows 系统上, 使用原生强制锁 (通过 FileLockEx).

在某些系统上, 文件锁定还可以进一步细化, 形成 记录锁 : 用户可以指定锁应用于文件内的某个 字节范围 . 这样, 多个进程在需要访问文件中不同字节范围时可以并发写入. Boost.Interprocess 目前 不 提供记录锁, 但将来可能会提供. 要使用文件锁只需包含:

#include <boost/interprocess/sync/file_lock.hpp>

文件锁是具有 进程生存期 的类. 也就是说, 如果持有文件锁的进程结束或崩溃, 操作系统会自动解锁. 在某些情况下, 这个特性非常有用: 可以保证即使进程崩溃也自动解锁, 避免在系统中留下被阻塞的资源. 文件锁用文件名作为参数构造:

#include <boost/interprocess/sync/file_lock.hpp>

int main()
{
   //This throws if the file does not exist or it can't
   //open it with read-write access!
   boost::interprocess::file_lock flock("my_file");
   return 0;
}

文件锁操作

文件锁具有普通互斥量的操作, 外加共享锁定能力. 这意味着可以让多个读者持有共享锁, 而写者持有独占锁等待读者完成工作.

不过, 文件锁 不 支持可升级锁定或提升/降级 (锁转移), 因此比可升级锁更受限. 操作如下:

void lock()

效果:: 调用线程尝试获得文件锁的独占所有权; 如果另一线程拥有该互斥量的独占或共享所有权, 则等待直到获得所有权.

抛出:: 出错时抛出 interprocess_exception .

bool try_lock()

效果:: 调用线程尝试在不等待的情况下获得文件锁的独占所有权. 如果没有其他线程拥有该文件锁的独占或共享所有权, 则成功.

返回:: 如果能立即获得独占所有权, 返回 true; 如果必须等待, 返回 false.

抛出:: 出错时抛出 interprocess_exception .

template <class TimePoint> bool timed_lock(const TimePoint &abs_time)

效果:: 调用线程尝试获得文件锁的独占所有权, 必要时等待, 直到没有其他线程拥有该文件锁的独占或共享所有权, 或到达 abs_time.

返回:: 如果获得独占所有权, 返回 true; 否则返回 false.

抛出:: 出错时抛出 interprocess_exception .

void unlock()

前置条件:: 线程必须拥有该文件锁的独占所有权.

效果:: 调用线程释放文件锁的独占所有权.

抛出:: 出错时抛出派生自 interprocess_exception 的异常.

void lock_sharable()

效果:: 调用线程尝试获得文件锁的共享所有权; 如果另一线程拥有该文件锁的独占所有权, 则等待直到获得所有权.

抛出:: 出错时抛出 interprocess_exception .

bool try_lock_sharable()

效果:: 调用线程尝试在不等待的情况下获得文件锁的共享所有权. 如果没有其他线程拥有该文件锁的独占所有权, 则成功.

返回:: 如果能立即获得共享所有权, 返回 true; 如果必须等待, 返回 false.

抛出:: 出错时抛出 interprocess_exception .

template <class TimePoint> bool timed_lock_sharable(const TimePoint &abs_time)

效果:: 调用线程尝试获得文件锁的共享所有权, 必要时等待, 直到没有其他线程拥有该文件锁的独占所有权, 或到达 abs_time.

返回:: 如果获得共享所有权, 返回 true; 否则返回 false.

抛出:: 出错时抛出 interprocess_exception .

void unlock_sharable()

前置条件:: 线程必须拥有该文件锁的共享所有权.

效果:: 调用线程释放文件锁的共享所有权.

抛出:: 出错时抛出派生自 interprocess_exception 的异常.

不过, 锁转移只允许在同类型的锁之间进行, 即从共享锁到另一个共享锁, 或从作用域锁到另一个作用域锁. 从作用域锁到共享锁的转移是不允许的, 因为 file_lock 没有像 unlock_and_lock_sharable() 那样的锁提升或降级函数. 这会产生编译错误:

//Compilation error, f_lock has no "unlock_and_lock_sharable()" member!
sharable_lock<file_lock> e_lock(move(f_lock));

注意: 同步限制

如果你打算像使用命名互斥量那样使用文件锁, 请务必小心, 因为可移植文件锁有同步限制, 主要因为不同实现 (POSIX, Windows) 提供的保证不同. Interprocess 文件锁有以下限制:

  • 未指定 file_lock 能否同步 同一进程的两个线程.
  • 未指定一个进程能否使用两个指向同一文件的 file_lock 对象.

第一个限制主要来自 POSIX: 文件句柄是进程级属性而非线程级属性. 这意味着, 如果一个线程用 file_lock 对象锁定了文件, 其他线程会看到文件已被锁定. 而 Windows 的文件锁定机制提供线程同步保证, 试图锁定已锁定文件的线程会被阻塞.

第二个限制来自这一事实: 在 Windows 中, 文件锁定同步状态与单个文件描述符绑定. 这意味着, 如果创建两个指向同一文件的 file_lock 对象, 则不保证同步. 在 POSIX 中, 当两个文件描述符用于锁定同一文件时, 若其中一个描述符被关闭, 调用进程设置的所有文件锁都会被清除.

总之, 如果你打算在进程中使用可移植文件锁, 请遵守以下限制:

  • 对每个文件, 每个进程只使用一个 file_lock 对象.
  • 用同一线程锁定和解锁文件.
  • 如果在使用文件锁的同时还用 std::fstream/原生文件句柄写该文件, 请在释放该文件的所有锁之前不要关闭文件.

如前所述, 文件锁可用于同步两个进程, 但在解锁文件锁之前, 务必 确保数据已写入文件. 请注意 iostream 类有某种缓冲, 因此如果想确保其他进程能看到你写入的数据, 有以下选择:

  • 用原生文件函数 (Unix 系统的 read()/write() 和 Windows 系统的 ReadFile/WriteFile) 代替 iostream.

什么是消息队列?

消息队列类似于消息列表. 线程可以把消息放入队列, 也可以从队列移除消息. 每条消息还可以有 优先级 , 优先级高的消息先于优先级低的消息被读取. 每条消息有以下属性:

  • 一个优先级.
  • 消息的长度.
  • 数据 (若长度大于 0).

线程可以用 3 种方法向消息队列发送消息或从消息队列接收消息:

  • 阻塞: 发送时若消息队列已满, 或接收时队列为空, 线程被阻塞, 直到有空间放新消息或有新消息到来.
  • 尝试: 发送时若消息队列已满, 或接收时队列为空, 线程立即返回并报错.
  • 定时: 发送时若消息队列已满, 或接收时队列为空, 线程重试该操作, 直到成功 (返回成功状态) 或超时 (返回失败).

消息队列 只在进程之间复制原始字节 , 不发送对象. 这意味着, 如果想用消息队列发送对象, 对象必须可以二进制序列化. 例如, 我们可以在进程间发送整数, 但 不能 发送 std::string . 应使用 Boost.Serialization 或 Boost.Interprocess 的高级机制在进程间发送复杂数据.

Boost.Interprocess 消息队列是命名的进程间通信: 消息队列用名称创建, 也用名称打开, 就像文件一样. 创建消息队列时, 用户必须指定消息的最大大小和消息队列可存储的最大消息数量. 这些参数将决定所需的资源 (例如, 如果使用共享内存实现消息队列, 则是所用共享内存的大小).

using namespace boost::interprocess;
//Create a message_queue. If the queue
//exists throws an exception
message_queue mq
   (create_only         //only create
   ,"message_queue"     //name
   ,100                 //max message number
   ,100                 //max message size
   );

using namespace boost::interprocess;
//Creates or opens a message_queue. If the queue
//does not exist creates it, otherwise opens it.
//Message number and size are ignored if the queue
//is opened
message_queue mq
   (open_or_create      //open or create
   ,"message_queue"     //name
   ,100                 //max message number
   ,100                 //max message size
   );

using namespace boost::interprocess;
//Opens a message_queue. If the queue
//does not exist throws an exception.
message_queue mq
   (open_only           //only open
   ,"message_queue"     //name
   );

消息队列通过调用静态 remove 函数显式移除:

using namespace boost::interprocess;
message_queue::remove("message_queue");

如果消息队列仍被任何进程使用, 该函数可能失败.

使用消息队列

要使用消息队列, 必须包含以下头文件:

#include <boost/interprocess/ipc/message_queue.hpp>

在下面的示例中, 第一个进程创建消息队列, 并向其写入一个整数数组. 另一个进程只是读取该数组并检查序号是否正确. 这是第一个进程:

#include <boost/interprocess/ipc/message_queue.hpp>
#include <iostream>
#include <vector>

using namespace boost::interprocess;

int main ()
{
   try {
      //Erase previous message queue
      message_queue::remove("message_queue");

      //Create a message_queue.
      message_queue mq
         (create_only               //only create
         ,"message_queue"           //name
         ,100                       //max message number
         ,sizeof(int)               //max message size
         );

      //Send 100 numbers
      for(int i = 0; i < 100; ++i){
         mq.send(&i, sizeof(i), 0);
      }
   }
   catch(interprocess_exception &ex){
      std::cout << ex.what() << std::endl;
      return 1;
   }

   return 0;
}

这是第二个进程:

#include <boost/interprocess/ipc/message_queue.hpp>
#include <iostream>
#include <vector>

using namespace boost::interprocess;

int main ()
{
   try {
      //Open a message queue.
      message_queue mq
         (open_only        //only open
         ,"message_queue"  //name
         );

      unsigned int priority;
      message_queue::size_type recvd_size;

      //Receive 100 numbers
      for(int i = 0; i < 100; ++i){
         int number;
         mq.receive(&number, sizeof(number), recvd_size, priority);
         if(number != i || recvd_size != sizeof(number))
            return 1;
      }
   }
   catch(interprocess_exception &ex){
      message_queue::remove("message_queue");
      std::cout << ex.what() << std::endl;
      return 1;
   }
   message_queue::remove("message_queue");
   return 0;
}
