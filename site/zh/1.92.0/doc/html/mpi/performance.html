性能评估

消息传递性能在高性能分布式计算中至关重要. 为了评估 Boost.MPI 的性能, 我们修改了标准的 NetPIPE 基准测试(版本 3.6.2)使其使用 Boost.MPI, 并将其性能与原生 MPI 进行了比较. 我们运行了 NetPIPE 基准测试的五种不同变体:

  1. MPI: 未修改的 NetPIPE 基准测试.
  2. Boost.MPI: 修改为使用 Boost.MPI 调用进行通信的 NetPIPE.
  3. MPI (Datatypes): 修改为使用派生数据类型(其自身只包含一个 MPI_BYTE)而非基本数据类型的 NetPIPE.
  4. Boost.MPI (Datatypes): 修改为使用用户自定义类型 Char 代替基本类型 char 的 NetPIPE. Char 类型只包含一个 char, 一个使其可序列化的 serialize() 方法, 并对 is_mpi_datatype 进行特化, 迫使 Boost.MPI 为其构建派生的 MPI 数据类型.
  5. Boost.MPI (Serialized): 修改为使用用户自定义类型 Char 代替基本类型 char 的 NetPIPE. 这个 Char 类型只包含一个 char 并且可序列化. 与 Datatypes 情形不同, is_mpi_datatype 没有 被特化, 从而迫使 Boost.MPI 执行非常非常多的序列化调用.

实际测试是在 Indiana University 计算机科学系 的 Odin 集群上进行的, 该集群包含 128 个通过 Infiniband 连接的节点. 每个节点配备 4GB 内存和两个 AMD Opteron 处理器. NetPIPE 基准测试使用 Intel C++ 编译器 9.0 版、Boost 1.35.0 (prerelease) 和 Open MPI 1.1 版编译. NetPIPE 结果如下:

关于这些 NetPIPE 结果可以得出一些观察结论. 首先, 前两幅图表明, 对于基本类型, Boost.MPI 的性能与 MPI 相当. 接下来两幅图表明, 对于派生数据类型, Boost.MPI 的性能同样与 MPI 相当, 尽管 Boost.MPI 提供的构建派生数据类型的方式比原生 MPI 抽象得多且完全透明. 派生数据类型的总体性能明显差于基本数据类型, 但瓶颈在于底层 MPI 实现本身. 最后, 当强制 Boost.MPI 逐个序列化字符时, 性能大幅下降. 这一特定情形是 Boost.MPI 最坏的情况, 因为我们要序列化数百万个独立的字符. 总体而言, Boost.MPI 提供的额外抽象并不会损害其性能.
