使用 Boost.MPI

开始使用 Boost.MPI 需要一个可用的 MPI 实现、较新版本的 Boost, 以及一些配置信息.

MPI 实现

要开始使用 Boost.MPI, 你首先需要一个可用的 MPI 实现. 有许多符合标准的 MPI 实现 可供选择. Boost.MPI 应当能与其中任何实现一起工作, 尽管它只在以下实现上得到过广泛测试:

  • Open MPI
  • MPICH2
  • Intel MPI

你可以使用下面的简单程序测试你的实现, 该程序把一条消息从一个处理器传递到另一个处理器. 每个处理器都会向标准输出打印一条消息.

#include <mpi.h>
#include <iostream>

int main(int argc, char* argv[])
{
  MPI_Init(&argc, &argv);

  int rank;
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  if (rank == 0) {
    int value = 17;
    int result = MPI_Send(&value, 1, MPI_INT, 1, 0, MPI_COMM_WORLD);
    if (result == MPI_SUCCESS)
      std::cout << "Rank 0 OK!" << std::endl;
  } else if (rank == 1) {
    int value;
    int result = MPI_Recv(&value, 1, MPI_INT, 0, 0, MPI_COMM_WORLD,
			  MPI_STATUS_IGNORE);
    if (result == MPI_SUCCESS && value == 17)
      std::cout << "Rank 1 OK!" << std::endl;
  }
  MPI_Finalize();
  return 0;
}

你应当在两个处理器上编译并运行该程序. 为此, 请查阅你的 MPI 实现的文档. 以 OpenMPI 为例, 你使用 mpiCC 或 mpic++ 编译器进行编译, 启动 LAM/MPI 守护进程, 然后通过 mpirun 运行你的程序. 例如, 如果你的程序名为 mpi-test.cpp, 则使用以下命令:

mpiCC -o mpi-test mpi-test.cpp
lamboot
mpirun -np 2 ./mpi-test
lamhalt

运行该程序时, 你会看到 Rank 0 OK! 和 Rank 1 OK! 都被打印到屏幕上. 不过, 它们可能以任意顺序打印, 甚至可能相互交叠. 对这个 MPI 程序而言, 下面的输出是完全合法的:

Rank Rank 1 OK!
0 OK!

如果你的输出与上面类似, 说明你的 MPI 实现似乎能与 C++ 编译器协同工作, 我们可以继续前进了.

安装

与 Boost 的其他部分一样, Boost.MPI 使用 Boost.Build 系统 2 版来配置和构建库二进制文件.

请参阅针对 Unix 变体(包括 Unix、Linux 和 MacOS)或 Windows 的 Boost 通用安装说明. 简化构建说明应当适用于大多数平台, 只需按下文所述做少量特定修改.

Bootstrap

如 boost 安装说明所述, 从 boost 根目录运行 bootstrap(unix 变体为 ./bootstrap.sh, Windows 为 bootstrap.bat)会生成一个 'project-config.jam` 文件. 你需要编辑该文件并添加以下一行:

using mpi ;

或者, 你也可以显式提供想要构建的 Boost 库列表. 请参阅 --help 选项, 它属于 bootstrap 脚本.

设置你的 MPI 实现

问题排查

首先, 你需要浏览 include/boost/mpi/config.hpp 文件, 检查是否有某些设置需要针对你的 MPI 实现或偏好进行修改.

特别是 BOOST_MPI_HOMOGENEOUS 宏, 如果你计划在一组异构机器上运行, 就需要把它注释掉. 参见下文的 优化 说明.

大多数 MPI 实现都要求特定的编译和链接选项. 为了向用户屏蔽这些细节, 大多数 MPI 实现都提供包装器, 它们会悄无声息地把这些选项传给编译器.

根据你的 MPI 实现, 可能需要做一些工作来告诉 Boost 使用哪个特定的 MPI 选项. 这通过 using mpi ; 指令在 project-config.jam 文件中完成, 其一般形式为(不要忘记在 : 周围以及 ; 之前留出空格):

using mpi
   : [<MPI compiler wrapper>]
   : [<compilation and link options>]
   : [<mpi runner>] ;

取决于你的安装和 MPI 发行版, 构建系统也许能够找到全部所需信息, 此时你只需指定:

using mpi ;
问题排查

大多数情况下, 尤其是在生产型 HPC 集群上, 需要做一些工作.

下面列出了最常见的问题以及相应的解决建议.

  • 你的包装器不在 PATH 中, 或者没有使用标准名称

你需要通过第一个参数告诉构建系统如何调用它:

using mpi : /opt/mpi/bullxmpi/1.2.8.3/bin/mpicc ;
警告

Boost.MPI 只使用 C 接口, 因此指定 C 包装器应当足够. 但某些实现会坚持导入 C++ 绑定.

  • 你的包装器非常另类, 或者根本不存在

对于某些实现, 或者某些特定的集成方式[9], 你需要通过第二个参数以 'jam' 指令的形式提供编译和链接选项. 下面这种类型的配置曾经是某个特定 Intel MPI 实现所要求的(在这种情况下, 包装器的名称可以留空):

using mpi : mpiicc :
      <library-path>/softs/intel/impi/5.0.1.035/intel64/lib
      <library-path>/softs/intel/impi/5.0.1.035/intel64/lib/release_mt
      <include>/softs/intel/impi/5.0.1.035/intel64/include
      <find-shared-library>mpifort
      <find-shared-library>mpi_mt
      <find-shared-library>mpigi
      <find-shared-library>dl
      <find-shared-library>rt ;

为了方便, MPI 包装器通常带有一个能提供所需信息的选项, 该选项通常以 --show 开头. 你可以利用它们来找出所需的 jam 指令:

$ mpiicc -show
icc -I/softs/.../include ... -L/softs/.../lib ... -Xlinker -rpath -Xlinker /softs/.../lib .... -lmpi -ldl -lrt -lpthread
$

$ mpicc --showme
icc -I/opt/.../include -pthread -L/opt/.../lib -lmpi -ldl -lm -lnuma -Wl,--export-dynamic -lrt -lnsl -lutil -lm -ldl
$ mpicc --showme:compile
-I/opt/mpi/bullxmpi/1.2.8.3/include -pthread
$ mpicc --showme:link
-pthread -L/opt/.../lib -lmpi -ldl -lm -lnuma -Wl,--export-dynamic -lrt -lnsl -lutil -lm -ldl
$

要查看 MPI 自动检测的结果, 请在 bjam 命令行传入 --debug-configuration.

  • 无法检测启动语法
注释

它只在 运行测试 时使用.

如果你需要用特殊命令来启动 MPI 程序, 就需要通过 using mpi 指令的第三个参数来指定它.

于是, 假定你用如下方式启动 all_gather_test 程序:

$mpiexec.hydra -np 4 all_gather_test

该指令将形如:

using mpi : mpiicc :
     [<compilation and link options>]
 : mpiexec.hydra -n  ;

构建

构建整个 Boost 发行版:

$cd <boost distribution>
$./b2

构建 Boost.MPI 库及其依赖:

$cd <boost distribution>/lib/mpi/build
$../../../b2

测试

你可以用以下命令运行回归测试:

$cd <boost distribution>/lib/mpi/test
$../../../b2

安装

安装整个 Boost 发行版:

$cd <boost distribution>
$./b2 install

使用 Boost.MPI

要构建基于 Boost.MPI 的应用程序, 请按照通常 MPI 程序的方式编译和链接, 但记住要链接 boost_mpi 和 boost_serialization 库, 例如,

mpic++ -I/path/to/boost/mpi my_application.cpp -Llibdir \
  -lboost_mpi -lboost_serialization

如果你计划在 C++ Boost.MPI 之外同时使用 Boost.MPI 的 Python 绑定, 还需要链接 boost_mpi_python 库, 例如在链接命令中加入 -lboost_mpi_python-gcc. 只有当你打算从 Python 中 注册 C++ 类型 或使用 骨架/内容机制 时, 才需要这一步.


[9] 某些 HPC 集群会坚持要求用户使用其内部的 MPI 系统接口.
