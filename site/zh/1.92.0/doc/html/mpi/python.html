Boost.MPI 从 Python 编程语言经由 boost.mpi 模块提供另一套 MPI 接口. Boost.MPI Python 绑定构建在 C++ Boost.MPI 之上, 使用了 Boost.Python 库, 在动态的、面向对象的语言中提供了 Boost.MPI 的几乎全部功能.

Boost.MPI Python 模块可以从 libs/mpi/build 目录构建和安装. 只需按照 C++ Boost.MPI 的 配置与 安装 说明操作即可. 安装 Python 模块之后, 请确保安装位置位于你的 PYTHONPATH 中.

快速上手

开始使用 Boost.MPI Python 模块就像导入 boost.mpi 一样简单. 我们的第一段 "Hello, World!" 程序只有两行:

import boost.mpi as mpi
print "I am process %d of %d." % (mpi.rank, mpi.size)

请继续用多个进程运行这个程序. 务必通过 python 解释器运行, 并从 mpirun 中调用, 例如,

mpirun -np 5 python hello_world.py

这将返回如下输出:

I am process 1 of 5.
I am process 3 of 5.
I am process 2 of 5.
I am process 4 of 5.
I am process 0 of 5.

Boost.MPI 的点对点操作在 Python 中的语法与在 C++ 中几乎相同. 我们可以编写一个简单的双进程 Python 程序, 通过传输 Python 字符串打印 "Hello, world!":

import boost.mpi as mpi

if mpi.world.rank == 0:
  mpi.world.send(1, 0, 'Hello')
  msg = mpi.world.recv(1, 1)
  print msg,'!'
else:
  msg = mpi.world.recv(0, 0)
  print (msg + ', '),
  mpi.world.send(0, 1, 'world')

这段 Python 代码与 C++ 教程中的示例 只有几处显著区别. 首先, 我们在 Python 中不需要编写任何初始化代码: 只需加载 boost.mpi 模块, 相应的 MPI_Init 和 MPI_Finalize 调用就会自动进行. 其次, 我们通过 MPI 在进程之间传递 Python 对象. 任何可以 pickle 的 Python 对象都可以传输; 下一节将更详细地描述 Boost.MPI Python 层如何传输对象. 最后, 当我们用 recv 接收对象时, 不需要指定类型, 因为 Python 对象的传输是多态的.

在 Python 中试用 Boost.MPI 时, 别忘了随时可以通过 pydoc 获取帮助: 只需在命令行传入模块或模块实体的名称(例如 pydoc boost.mpi.communicator), 即可获得完整的参考文档. 有疑问时, 试一下就知道了!

传输用户自定义数据

Boost.MPI 可以用多种不同方式传输用户自定义数据. 最重要的是, 它可以通过在发送端 pickle、在接收端 unpickle 来传输任意 Python 对象, 使任意复杂的 Python 数据结构都能与 MPI 互操作.

Boost.MPI 还通过其 C++ 接口支持对(已暴露给 Python 的)C++ 对象的高效序列化和传输. 任何提供满足 Boost.Serialization 库要求的(反)序列化例程的 C++ 类型都有资格享受这一优化, 但该类型必须事先注册. 要注册 C++ 类型, 请调用 C++ 函数 register_serialized. 如果你的 C++ 类型来自其他 Python 模块(很可能如此!), 那些模块将需要链接 boost_mpi 和 boost_mpi_python 库, 如 安装一节 所述. 注意, 你 不需要 链接 Boost.MPI Python 扩展模块.

最后, Boost.MPI 支持把对象的结构与其存储的数据分离开, 使这两部分可以分别传输. 这一"骨架/内容"机制将在后文中更详细地描述, 它是一种通信优化, 适用于数据结构固定而内部数据频繁变化的问题.

集合通信操作

对于任何能用点对点通信操作传输的数据类型, Boost.MPI 都支持全部 MPI 集合通信操作(scatter、reduce、scan、broadcast 等). 对于需要用户指定操作的 MPI 集合通信操作(例如 reduce 和 scan), 该操作可以是任意 Python 函数. 例如, 可以用 all_reduce 拼接字符串:

mpi.all_reduce(my_string, lambda x,y: x + y)

以下模块级函数实现 MPI 集合通信操作: all_gather 从所有进程汇聚值. all_reduce 合并所有进程的结果. all_to_all 每个进程向所有其他进程发送数据. broadcast 将数据从一个进程广播到所有其他进程. gather 把所有进程的值汇聚到根进程. reduce 把所有进程的结果合并到根进程. scan 对所有进程的值进行前缀归约. scatter 把根进程存放的值散发到所有进程.

骨架/内容机制

Boost.MPI 提供骨架/内容机制, 允许把大型数据结构的传输拆分为两个独立的阶段: 先发送数据结构的骨架(即"形状"), 之后(可能多次)再发送数据结构的内容(即"数据"), 只要自骨架传输之后结构未曾改变即可. 当数据结构很大且其形状固定时, 骨架/内容机制可以改善性能, 因为骨架需要序列化(其大小未知), 而内容传输是定长的, 无需额外拷贝即可完成.

要在 Python 中使用骨架/内容机制, 必须先 从 C++ 把你的数据结构类型注册到骨架/内容机制. 注册函数是 register_skeleton_and_content, 位于 <boost/mpi/python.hpp> 头文件中.

注册 C++ 数据结构之后, 就可以用 skeleton() 为该数据结构的实例提取骨架. 所得到的 skeleton_proxy 可以通过普通的 send 例程传输, 例如,

mpi.world.send(1, 0, skeleton(my_data_structure))

skeleton_proxy 对象可以在另一端通过 recv() 接收, 它会把一个新建的、与发送方具有相同"形状"的数据结构实例存入其 "object" 属性:

shape = mpi.world.recv(0, 0)
my_data_structure = shape.object

骨架传输完成后, 内容(通过 get_content 访问)可以用几乎相同的方式传输. 但注意, 接收方在其接收调用中也要指定 get_content(my_data_structure):

if mpi.rank == 0:
  mpi.world.send(1, 0, get_content(my_data_structure))
else:
  mpi.world.recv(0, 0, get_content(my_data_structure))

当然, 只要数据结构中的值(而非其形状)发生变化, 这种内容传输就可以反复进行.

骨架/内容机制是一种结构化的方式, 用于利用定制 MPI 数据类型与 MPI_BOTTOM 之间的交互, 从而消除额外的缓冲区拷贝.

C++/Python MPI 兼容性

Boost.MPI 是一个 C++ 库, 其设施已通过 Boost.Python 库暴露给 Python. 由于 Boost.MPI Python 绑定直接构建在 C++ 库之上, 且 C++ 库的几乎每个特性在 Python 中都可用, 使用 Boost.MPI 的 C++/Python 混合程序可以互相交互, 例如从 Python 发送一个值而在 C++ 中接收它(反之亦然). 不过, 这样做需要一些小心. 由于 Python 对象是动态类型的, Boost.MPI 会在传输对象序列化形式的同时传输类型信息, 使得即使不知道对象的类型也能接收它. 这一机制与 C++ 端的做法不同, 在 C++ 端, 被传输值的静态类型总是已知的.

在 Boost.MPI 的 C++ 视角与 Python 视角之间通信的唯一方式, 是完全以 Python 对象进行传输. 对 Python 而言, 这本来就是常态, 因此不会有什么改变. 对 C++ 而言, 这意味着发送和接收 boost::python::object 类型的值, 该类型来自 Boost.Python 库. 例如, 假设我们想从 Python 传输一个整数值:

comm.send(1, 0, 17)

在 C++ 中, 我们会把该值接收到一个 Python 对象中, 然后 extract 出一个整数值:

boost::python::object value;
comm.recv(0, 0, value);
int int_value = boost::python::extract<int>(value);

将来, Boost.MPI 会继续扩展, 以改善与 C++ Boost.MPI 以及 C MPI 绑定的互操作性.
