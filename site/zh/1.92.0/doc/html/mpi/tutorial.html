一个 Boost.MPI 程序由许多相互协作的进程(可能运行在不同计算机上)组成, 它们通过传递消息相互通信. Boost.MPI 是一个库(底层的 MPI 也是如此), 而不是一种语言, 因此 Boost.MPI 程序的第一步是创建一个 mpi::environment 对象, 由它初始化 MPI 环境并启用进程间的通信. mpi::environment 对象在主程序中用程序参数(它可能会修改这些参数)初始化. 该对象的创建会初始化 MPI, 其析构会终结 MPI. 在绝大多数 Boost.MPI 程序中, 一个 mpi::environment 实例会在程序最开始处声明于 main 中.

警告

在全局作用域声明 mpi::environment 是未定义行为. [10]

与 MPI 的通信总是在一个 通信器上进行, 通信器只需默认构造一个 mpi::communicator 类型的对象即可创建. 随后可以查询该通信器, 以确定有多少进程在运行(通信器的"大小"), 并给每个进程分配一个从零到通信器大小减一的唯一编号(即进程的"秩"):

#include <boost/mpi/environment.hpp>
#include <boost/mpi/communicator.hpp>
#include <iostream>
namespace mpi = boost::mpi;

int main()
{
  mpi::environment env;
  mpi::communicator world;
  std::cout << "I am process " << world.rank() << " of " << world.size()
            << "." << std::endl;
  return 0;
}

例如, 如果你用 7 个进程运行该程序, 将得到如下输出:

I am process 5 of 7.
I am process 0 of 7.
I am process 1 of 7.
I am process 6 of 7.
I am process 2 of 7.
I am process 4 of 7.
I am process 3 of 7.

当然, 各进程每次的执行顺序可能不同, 因此秩的输出未必严格递增. 更有趣的是, 文本可能完全乱掉, 因为一个进程可能早在另一个进程写完 "of 7." 之前就开始写 "I am a process".

如果你的 MPI 库仍然只支持 MPI 1.1, 则需要像本例那样把命令行参数传递给环境构造函数:

#include <boost/mpi/environment.hpp>
#include <boost/mpi/communicator.hpp>
#include <iostream>
namespace mpi = boost::mpi;

int main(int argc, char* argv[])
{
  mpi::environment env(argc, argv);
  mpi::communicator world;
  std::cout << "I am process " << world.rank() << " of " << world.size()
            << "." << std::endl;
  return 0;
}

阻塞通信

作为一个消息传递库, MPI 的首要用途是在进程之间例行地传递消息, 即点对点通信. MPI 包含发送消息、接收消息以及查询消息是否可用的例程. 每条消息都有源进程、目标进程、标签(tag)和包含任意数据的载荷. 源进程和目标进程分别是消息发送方和接收方的秩. 标签是整数, 让接收方能够区分来自同一发送方的不同消息.

下面的程序使用两个 MPI 进程向屏幕写入 "Hello, world!"(hello_world.cpp):

#include <boost/mpi.hpp>
#include <iostream>
#include <string>
#include <boost/serialization/string.hpp>
namespace mpi = boost::mpi;

int main()
{
  mpi::environment env;
  mpi::communicator world;

  if (world.rank() == 0) {
    world.send(1, 0, std::string("Hello"));
    std::string msg;
    world.recv(1, 1, msg);
    std::cout << msg << "!" << std::endl;
  } else {
    std::string msg;
    world.recv(0, 0, msg);
    std::cout << msg << ", ";
    std::cout.flush();
    world.send(0, 1, std::string("world"));
  }

  return 0;
}

第一个处理器(秩 0)使用标签 0 把消息 "Hello" 传给第二个处理器(秩 1). 第二个处理器打印它收到的字符串(外加一个逗号), 然后用不同的标签把消息 "world" 传回处理器 0. 第一个处理器随后写出带 "!" 的这条消息并退出. 所有发送都通过 communicator::send 方法完成, 所有接收都用相应的 communicator::recv 调用.

非阻塞通信

默认的 MPI 通信操作——send 和 recv——可能必须等到整个传输完成才能返回. 有时这种 阻塞 行为会对性能产生负面影响, 因为发送方在等待传输进行时本可以执行有用的计算. 然而更重要的是那些必须同时进行多个通信操作的情形, 例如一个进程要同时发送和接收.

让我们重新审视 前一小节中的 "Hello, world!" 程序. 该程序的核心部分传输两条消息:

if (world.rank() == 0) {
  world.send(1, 0, std::string("Hello"));
  std::string msg;
  world.recv(1, 1, msg);
  std::cout << msg << "!" << std::endl;
} else {
  std::string msg;
  world.recv(0, 0, msg);
  std::cout << msg << ", ";
  std::cout.flush();
  world.send(0, 1, std::string("world"));
}

第一个进程先把消息传给第二个进程, 然后准备接收消息. 第二个进程以相反的顺序进行发送和接收. 然而, 这一事件序列就只是个 序列——本质上没有任何并行性. 我们可以使用非阻塞通信来确保两条消息同时传输(hello_world_nonblocking.cpp):

#include <boost/mpi.hpp>
#include <iostream>
#include <string>
#include <boost/serialization/string.hpp>
namespace mpi = boost::mpi;

int main()
{
  mpi::environment env;
  mpi::communicator world;

  if (world.rank() == 0) {
    mpi::request reqs[2];
    std::string msg, out_msg = "Hello";
    reqs[0] = world.isend(1, 0, out_msg);
    reqs[1] = world.irecv(1, 1, msg);
    mpi::wait_all(reqs, reqs + 2);
    std::cout << msg << "!" << std::endl;
  } else {
    mpi::request reqs[2];
    std::string msg, out_msg = "world";
    reqs[0] = world.isend(0, 1, out_msg);
    reqs[1] = world.irecv(0, 0, msg);
    mpi::wait_all(reqs, reqs + 2);
    std::cout << msg << ", ";
  }

  return 0;
}

我们把对 communicator::send 和 communicator::recv 成员的调用替换为对其非阻塞对应物的类似调用, 即 communicator::isend 和 communicator::irecv. 前缀 i 表示这些操作会立即返回一个 mpi::request 对象, 它可以查询通信请求的状态(参见 test 方法)或等待其完成(参见 wait 方法). 多个请求可以用 wait_all 操作同时完成.

重要

关于通信的完成/推进: MPI 标准要求用户保留非阻塞通信的请求句柄, 并调用 "wait" 操作(或成功测试完成)来完成发送或接收. 大多数 C MPI 实现允许用户丢弃非阻塞发送的请求, 与之不同, Boost.MPI 要求用户调用 "wait" 或 "test", 因为请求对象可能包含必须保留到发送完成才可释放的临时缓冲区. 此外, MPI 标准并不保证接收在调用 "wait" 或 "test" 之前有任何进展, 尽管大多数 C MPI 实现确实允许接收在调用 "wait" 或 "test" 之前推进. 而 Boost.MPI 通常需要 "test" 或 "wait" 调用才能取得进展. 更具体地说, Boost.MPI 保证多次调用 "test" 最终会完成通信(这是因为序列化通信可能是一个多步骤操作).

如果你多次运行该程序, 可能会看到一些奇怪的结果: 某些运行会产生:

Hello, world!

而另一些运行会产生:

world!
Hello,

甚至是 "Hello" 和 "world" 中字母的某种乱序版本. 这说明程序存在一定的并行性, 因为在两条消息(同时)传输之后, 两个进程会并发执行各自的打印语句. 无论从性能还是正确性来看, 非阻塞通信操作对许多使用 MPI 的并行应用都至关重要.

点对点操作 是 Boost.MPI 中核心的消息传递原语. 然而, 许多消息传递应用还需要更高层的通信算法, 用于合并或汇总存储在许多不同进程上的数据. 这些算法支持许多常见任务, 例如"把这个值广播给所有进程"、"计算所有处理器上值的总和"或"找出全局最小值".

广播

broadcast 算法是迄今最简单的集合通信操作. 它把一个值从单个进程广播到 communicator 内的所有其他进程. 例如, 下面的程序把 "Hello, World!" 从进程 0 广播到所有其他进程.(hello_world_broadcast.cpp)

#include <boost/mpi.hpp>
#include <iostream>
#include <string>
#include <boost/serialization/string.hpp>
namespace mpi = boost::mpi;

int main()
{
  mpi::environment env;
  mpi::communicator world;

  std::string value;
  if (world.rank() == 0) {
    value = "Hello, World!";
  }

  broadcast(world, value, 0);

  std::cout << "Process #" << world.rank() << " says " << value
            << std::endl;
  return 0;
}

用 7 个进程运行该程序将产生如下结果:

Process #0 says Hello, World!
Process #2 says Hello, World!
Process #1 says Hello, World!
Process #4 says Hello, World!
Process #3 says Hello, World!
Process #5 says Hello, World!
Process #6 says Hello, World!

汇聚

gather 集合通信操作把通信器中每个进程产生的值汇聚到"根"进程(由 gather 的参数指定)上的一个值向量中. 向量中的第 /i/ 个元素对应从第 /i/ 个进程汇聚来的值. 例如, 在下面的程序中, 每个进程计算自己的随机数. 所有这些随机数都汇聚到进程 0(这里是"根"), 由它打印对应每个处理器的值.(random_gather.cpp)

#include <boost/mpi.hpp>
#include <iostream>
#include <vector>
#include <cstdlib>
namespace mpi = boost::mpi;

int main()
{
  mpi::environment env;
  mpi::communicator world;

  std::srand(time(0) + world.rank());
  int my_number = std::rand();
  if (world.rank() == 0) {
    std::vector<int> all_numbers;
    gather(world, my_number, all_numbers, 0);
    for (int proc = 0; proc < world.size(); ++proc)
      std::cout << "Process #" << proc << " thought of "
                << all_numbers[proc] << std::endl;
  } else {
    gather(world, my_number, 0);
  }

  return 0;
}

用 7 个进程执行该程序会得到如下输出. 尽管随机值每次运行都会变化, 但输出中进程的顺序保持不变, 因为只有进程 0 向 std::cout 写入.

Process #0 thought of 332199874
Process #1 thought of 20145617
Process #2 thought of 1862420122
Process #3 thought of 480422940
Process #4 thought of 1253380219
Process #5 thought of 949458815
Process #6 thought of 650073868

gather 操作把每个进程的值收集到一个进程上的向量中. 如果要把每个进程的值收集成每个进程上都相同的向量, 则应使用 all_gather 算法, 它在语义上等价于调用 gather 后再对所得向量执行 broadcast.

散发

scatter 集合通信操作把通信器中"根"进程上一个向量中的值散发到通信器所有进程的值中. 向量中的第 /i/ 个元素对应第 /i/ 个进程接收到的值. 例如, 在下面的程序中, 根进程生成一个随机数向量, 并向每个进程发送一个值, 各进程将其打印出来.(random_scatter.cpp)

#include <boost/mpi.hpp>
#include <boost/mpi/collectives.hpp>
#include <iostream>
#include <cstdlib>
#include <vector>

namespace mpi = boost::mpi;

int main(int argc, char* argv[])
{
  mpi::environment env(argc, argv);
  mpi::communicator world;

  std::srand(time(0) + world.rank());
  std::vector<int> all;
  int mine = -1;
  if (world.rank() == 0) {
    all.resize(world.size());
    std::generate(all.begin(), all.end(), std::rand);
  }
  mpi::scatter(world, all, mine, 0);
  for (int r = 0; r < world.size(); ++r) {
    world.barrier();
    if (r == world.rank()) {
      std::cout << "Rank " << r << " got " << mine << '\n';
    }
  }
  return 0;
}

用 7 个进程执行该程序会得到如下输出. 尽管随机值每次运行都会变化, 但由于屏障(barrier)的存在, 输出中进程的顺序保持不变.

Rank 0 got 1409381269
Rank 1 got 17045268
Rank 2 got 440120016
Rank 3 got 936998224
Rank 4 got 1827129182
Rank 5 got 1951746047
Rank 6 got 2117359639

归约

reduce 集合通信操作把每个进程的值汇总为用户指定"根"进程上的单个值. Boost.MPI 的 reduce 操作在精神上类似于 STL 的 accumulate 操作, 因为它接收一列值(每个进程一个)并通过函数对象把它们合并起来. 例如, 我们可以在每个进程中随机生成值, 然后通过调用 reduce 计算所有进程的最小值(random_min.cpp):

#include <boost/mpi.hpp>
#include <iostream>
#include <cstdlib>
namespace mpi = boost::mpi;

int main()
{
  mpi::environment env;
  mpi::communicator world;

  std::srand(time(0) + world.rank());
  int my_number = std::rand();

  if (world.rank() == 0) {
    int minimum;
    reduce(world, my_number, minimum, mpi::minimum<int>(), 0);
    std::cout << "The minimum value is " << minimum << std::endl;
  } else {
    reduce(world, my_number, mpi::minimum<int>(), 0);
  }

  return 0;
}

使用 mpi::minimum<int> 表示应计算最小值. mpi::minimum<int> 是一个二元函数对象, 它通过 < 比较两个参数并返回较小的值. 任何可结合的二元函数或函数对象都可以使用, 只要它是无状态的. 例如, 要用 reduce 拼接字符串, 可以使用函数对象 std::plus<std::string>(string_cat.cpp):

#include <boost/mpi.hpp>
#include <iostream>
#include <string>
#include <functional>
#include <boost/serialization/string.hpp>
namespace mpi = boost::mpi;

int main()
{
  mpi::environment env;
  mpi::communicator world;

  std::string names[10] = { "zero ", "one ", "two ", "three ",
                            "four ", "five ", "six ", "seven ",
                            "eight ", "nine " };

  std::string result;
  reduce(world,
         world.rank() < 10? names[world.rank()]
                          : std::string("many "),
         result, std::plus<std::string>(), 0);

  if (world.rank() == 0)
    std::cout << "The result is " << result << std::endl;

  return 0;
}

在该示例中, 我们为每个进程计算一个字符串, 然后执行一次归约, 把所有字符串拼接成一个长字符串. 用 7 个处理器执行该程序会得到如下输出:

The result is zero one two three four five six
用于 reduce 的二元操作

reduce 可以使用任何类型的二元函数对象. 例如, C++ 标准 <functional> 头文件和 Boost.MPI 头文件 <boost/mpi/operations.hpp> 中就有许多这样的函数对象. 你也可以创建自己的函数对象. 与 reduce 一起使用的函数对象必须是可结合的, 即 f(x, f(y, z)) 必须等价于 f(f(x, y), z). 如果它们还是可交换的(即 f(x, y) == f(y, x)), Boost.MPI 就能为 reduce 使用更高效的实现. 要声明一个函数对象是可交换的, 你需要特化 is_commutative 类. 例如, 我们可以通过告诉 Boost.MPI 字符串拼接是可交换的来修改前面的示例:

namespace boost { namespace mpi {

  template<>
  struct is_commutative<std::plus<std::string>, std::string>
    : mpl::true_ { };

} } // end namespace boost::mpi

在 main() 之前加入这段代码, Boost.MPI 就会假定字符串拼接是可交换的, 并为 reduce 操作采用另一种并行算法. 使用该算法时, 用 7 个进程运行程序会输出:

The result is zero one four five six two three

注意结果字符串中数字的顺序不同: 这是 Boost.MPI 重排操作的直接结果. 本例中结果与非可交换情形不同, 因为字符串拼接并非可交换操作: f("x", "y") 不等于 f("y", "x"), 因为参数顺序有影响. 对于真正可交换的操作(例如整数加法), 更高效的可交换算法将产生与非可交换算法相同的结果. Boost.MPI 还会把 <functional> 中的函数对象直接映射到 MPI 预定义的 MPI_Op 值(例如 MPI_SUM、MPI_MAX); 如果你有自己的能利用这一映射的函数对象, 请参见类模板 is_mpi_op.

警告

由于底层 MPI 的限制, 必须注意该操作必须是无状态的.

全进程变体

与 gather 一样, reduce 也有一个名为 all_reduce 的"all"变体, 它执行归约操作并把结果广播给所有进程. 例如, 在建立全局最小值或最大值时, 这一变体很有用.

下面的代码(global_min.cpp)展示了 random_min.cpp 示例的广播版本:

#include <boost/mpi.hpp>
#include <iostream>
#include <cstdlib>
namespace mpi = boost::mpi;

int main(int argc, char* argv[])
{
  mpi::environment env(argc, argv);
  mpi::communicator world;

  std::srand(world.rank());
  int my_number = std::rand();
  int minimum;

  mpi::all_reduce(world, my_number, minimum, mpi::minimum<int>());

  if (world.rank() == 0) {
      std::cout << "The minimum value is " << minimum << std::endl;
  }

  return 0;
}

在该示例中我们同时提供了输入值和输出值, 需要两倍的空间, 视传输数据的大小, 这可能成为问题. 如果无需保留输入值, 可以省略输出值. 此时输入值会被输出值覆盖, 并且 Boost.MPI 在某些情况下能够用更省空间的方案实现该操作(使用 MPI C 映射的 MPI_IN_PLACE 标志), 如下面的示例(in_place_global_min.cpp):

#include <boost/mpi.hpp>
#include <iostream>
#include <cstdlib>
namespace mpi = boost::mpi;

int main(int argc, char* argv[])
{
  mpi::environment env(argc, argv);
  mpi::communicator world;

  std::srand(world.rank());
  int my_number = std::rand();

  mpi::all_reduce(world, my_number, mpi::minimum<int>());

  if (world.rank() == 0) {
      std::cout << "The minimum value is " << my_number << std::endl;
  }

  return 0;
}

用户自定义数据类型

在前面的示例中包含 boost/serialization/string.hpp 非常重要: 它使 std::string 类型的值变得可序列化, 从而能够用 Boost.MPI 传输. 一般而言, 内置 C++ 类型(int、float、字符等)可以通过 MPI 直接传输, 而用户自定义和库自定义的类型则需要先序列化(打包)为适合传输的格式. Boost.MPI 依靠 Boost.Serialization 库来序列化和反序列化数据类型.

对于标准库定义的类型(如 std::string 或 std::vector)以及 Boost 中的某些类型(如 boost::variant), Boost.Serialization 库已经包含全部所需的序列化代码. 在这些情况下, 只需从 boost/serialization 目录包含相应的头文件即可.

对于尚无序列化头文件的类型, 在能够用 Boost.MPI 传输之前, 需要先实现序列化代码. 考虑一个简单的类 gps_position, 它包含成员 degrees、minutes 和 seconds. 把它设为 boost::serialization::access 的友元并引入模板化的 serialize() 函数, 即可使其可序列化, 如下: 

class gps_position
{
private:
    friend class boost::serialization::access;

    template<class Archive>
    void serialize(Archive & ar, const unsigned int version)
    {
        ar & degrees;
        ar & minutes;
        ar & seconds;
    }

    int degrees;
    int minutes;
    float seconds;
public:
    gps_position(){};
    gps_position(int d, int m, float s) :
        degrees(d), minutes(m), seconds(s)
    {}
};

让类型可序列化的完整信息超出了本教程的范围. 更多信息请参阅 Boost.Serialization 库教程, 上面的示例即摘自该教程. 让类型可序列化对 Boost.MPI 而言还有一个重要的附带好处: 它们对任何其他用途也成为可序列化的, 例如把对象存储到磁盘并以 XML 操作它们.

某些可序列化类型, 如上面的 gps_position, 在固定偏移处存储固定数量的数据, 并完全由其数据成员的值确定(大多数不含指针的 POD 类型就是很好的例子). 在这种情况下, Boost.MPI 可以通过避免多余的拷贝操作来优化其序列化和传输. 要启用这一优化, 用户必须特化类型特征 is_mpi_datatype, 例如:

namespace boost { namespace mpi {
  template <>
  struct is_mpi_datatype<gps_position> : mpl::true_ { };
} }

对于非模板类型, 我们定义了一个宏, 用于简化把类型声明为 MPI 数据类型的过程

BOOST_IS_MPI_DATATYPE(gps_position)

对于复合特征, is_mpi_datatype 的特化可能依赖于 is_mpi_datatype 本身. 例如, 一个 boost::array 对象只有在其存储的参数类型固定时才是固定的:

namespace boost { namespace mpi {
  template <typename T, std::size_t N>
  struct is_mpi_datatype<array<T, N> >
    : public is_mpi_datatype<T> { };
} }

冗余拷贝消除优化只能在数据类型的形状完全固定时应用. 变长类型(例如字符串、链表)和存储指针的类型无法使用该优化, 但 Boost.MPI 无法在编译期检测出这一错误. 在不正确的情况下尝试进行该优化, 很可能导致段错误及其他奇怪的程序行为.

Boost.MPI 可以把任何用户自定义数据类型从一个进程传输到另一个进程. 内置类型无需任何额外工作即可传输; 库自定义类型需要包含序列化头文件; 用户自定义类型则需要添加序列化代码. 固定数据类型可以使用 is_mpi_datatype 类型特征针对传输进行优化.

管理通信器

与 Boost.MPI 的通信总是在一个通信器上进行. 通信器包含一组可以在彼此之间发送消息并执行集合通信操作的进程. 单个程序中可以有许多通信器, 每个通信器都包含自己独立的通信空间, 与其他通信器互不影响.

当 MPI 环境初始化时, 只有"world"通信器(在 MPI C 和 Fortran 绑定中称为 MPI_COMM_WORLD)可用. "world"通信器通过默认构造一个 mpi::communicator 对象来访问, 它包含程序开始执行时存在的全部 MPI 进程. 随后可以通过复制"world"通信器或构建其子集来构造其他通信器. 例如, 在下面的程序中, 我们把进程分为两组: 一组用于生成数据的进程, 另一组用于收集数据的进程.(generate_collect.cpp)

#include <boost/mpi.hpp>
#include <iostream>
#include <cstdlib>
#include <boost/serialization/vector.hpp>
namespace mpi = boost::mpi;

enum message_tags {msg_data_packet, msg_broadcast_data, msg_finished};

void generate_data(mpi::communicator local, mpi::communicator world);
void collect_data(mpi::communicator local, mpi::communicator world);

int main()
{
  mpi::environment env;
  mpi::communicator world;

  bool is_generator = world.rank() < 2 * world.size() / 3;
  mpi::communicator local = world.split(is_generator? 0 : 1);
  if (is_generator) generate_data(local, world);
  else collect_data(local, world);

  return 0;
}

当通信器以这种方式拆分时, 其进程同时保留在原通信器(拆分不改变它)和新通信器中的成员资格. 不过, 进程的秩在不同通信器之间可能不同, 因为通信器内的秩值始终是从零开始的连续值. 在上面的示例中, 前三分之二的进程成为"生成者", 其余进程成为"收集者". "收集者"在 world 通信器中的秩为 2/3 world.size() 及更大, 而相同的收集者进程在 local 通信器中的秩则从零开始. 以下摘自 collect_data()(位于 generate_collect.cpp 中)的片段说明了如何管理多个通信器:

mpi::status msg = world.probe();
if (msg.tag() == msg_data_packet) {
  // Receive the packet of data
  std::vector<int> data;
  world.recv(msg.source(), msg.tag(), data);

  // Tell each of the collectors that we'll be broadcasting some data
  for (int dest = 1; dest < local.size(); ++dest)
    local.send(dest, msg_broadcast_data, msg.source());

  // Broadcast the actual data.
  broadcast(local, data, 0);
}

这段摘录中的代码由"主"收集者执行, 即秩为 2/3 world.size() 的节点: 它在 world 通信器中的秩为 2/3 以上, 而在 local(收集者)通信器中秩为 0. 它通过 world 通信器从生成者接收一条消息, 然后通过 local 通信器把该消息广播给每个收集者.

若要在为进程子组创建通信器时有更多控制, Boost.MPI 的 group 提供了一些设施, 可以计算两个组的并集(|)、交集(&)和差集(-), 生成任意子组等.

笛卡尔通信器

通信器可以组织成笛卡尔网格, 下面是一个基本示例:

#include <vector>
#include <iostream>

#include <boost/mpi/communicator.hpp>
#include <boost/mpi/collectives.hpp>
#include <boost/mpi/environment.hpp>
#include <boost/mpi/cartesian_communicator.hpp>

#include <boost/test/minimal.hpp>

namespace mpi = boost::mpi;
int test_main(int argc, char* argv[])
{
  mpi::environment  env;
  mpi::communicator world;

  if (world.size() != 24)  return -1;
  mpi::cartesian_dimension dims[] = {{2, true}, {3,true}, {4,true}};
  mpi::cartesian_communicator cart(world, mpi::cartesian_topology(dims));
  for (int r = 0; r < cart.size(); ++r) {
    cart.barrier();
    if (r == cart.rank()) {
      std::vector<int> c = cart.coordinates(r);
      std::cout << "rk :" << r << " coords: "
                << c[0] << ' ' << c[1] << ' ' << c[2] << '\n';
    }
  }
  return 0;
}

线程

越来越多的混合并行应用把分布式内存并行与共享内存并行结合在一起. 要知道如何支持这种模型, 需要了解 MPI 实现保证何种级别的线程支持. mpi::threading::level 描述了 4 个有序的线程支持级别. 最低级别下根本不应使用线程, 最高级别下任何线程都可以执行 MPI 调用.

如果你想在 MPI 应用中使用多线程, 应当在环境构造函数中指明你偏好的线程支持级别. 然后探测库实际提供的级别, 并据此决定你能做什么(也可能什么都做不了, 此时中止是合理的选择):

#include <boost/mpi/environment.hpp>
#include <boost/mpi/communicator.hpp>
#include <iostream>
namespace mpi = boost::mpi;
namespace mt  = mpi::threading;

int main()
{
  mpi::environment env(mt::funneled);
  if (env.thread_level() < mt::funneled) {
     env.abort(-1);
  }
  mpi::communicator world;
  std::cout << "I am process " << world.rank() << " of " << world.size()
            << "." << std::endl;
  return 0;
}

结构与内容分离

通过 MPI 传输对 MPI 而言非基本的数据类型(例如字符串、列表和用户自定义数据类型)时, Boost.MPI 必须先把这些数据类型序列化到缓冲区中再进行传输; 接收方随后把结果拷贝到缓冲区, 再在另一端反序列化为对象. 对于某些数据类型, 这一开销可以通过 is_mpi_datatype 消除. 然而, 诸如字符串和列表之类的变长数据类型不能成为 MPI 数据类型.

Boost.MPI 支持第二种提升性能的技术: 把这些变长数据结构的结构与其中存储的内容分离开来. 只有当数据结构的形状保持不变而其内容需要多次通信时, 该特性才有收益. 例如, 在有限元分析中, 网格的结构可能在计算开始时就已固定, 但网格各单元上的各种变量(温度、应力等)会在迭代分析过程中被多次通信. 在这种情况下, Boost.MPI 允许先发送一次网格的"骨架", 然后多次传输"内容". 由于内容无需包含关于数据类型结构的任何信息, 它可以在不创建独立通信缓冲区的情况下传输.

为了说明骨架和内容的用法, 我们来看一个更受限的示例: 主进程生成随机数序列存入一个列表, 并把它们传输给若干从进程. 列表的长度在程序启动时固定, 因此列表的内容(即当前的数字序列)可以高效传输. 完整示例见 example/random_content.cpp. 我们从主进程(秩 0)开始, 它构建一个列表, 通过 skeleton 传达其结构, 然后反复生成随机数序列, 并通过 content 广播给从进程:

// Generate the list and broadcast its structure
std::list<int> l(list_len);
broadcast(world, mpi::skeleton(l), 0);

// Generate content several times and broadcast out that content
mpi::content c = mpi::get_content(l);
for (int i = 0; i < iterations; ++i) {
  // Generate new random values
  std::generate(l.begin(), l.end(), &random);

  // Broadcast the new content of l
  broadcast(world, c, 0);
}

// Notify the slaves that we're done by sending all zeroes
std::fill(l.begin(), l.end(), 0);
broadcast(world, c, 0);

从进程的结构与主进程非常相似. 它们(通过 broadcast() 调用)接收数据结构的骨架, 然后用它构建自己的整数列表. 在每次迭代中, 它们通过另一个 broadcast() 接收数据结构中的新内容并计算数据的某种属性:

// Receive the content and build up our own list
std::list<int> l;
broadcast(world, mpi::skeleton(l), 0);

mpi::content c = mpi::get_content(l);
int i = 0;
do {
  broadcast(world, c, 0);

  if (std::find_if
       (l.begin(), l.end(),
        std::bind1st(std::not_equal_to<int>(), 0)) == l.end())
    break;

  // Compute some property of the data.

  ++i;
} while (true);

任何可序列化数据类型的骨架和内容, 既可以通过 send 和 recv 成员(它们属于 communicator 类, 用于点对点通信器)传输, 也可以通过 broadcast() 集合通信操作广播. 在把数据结构拆分为骨架和内容时, 要小心不要在未重新传输骨架的情况下修改数据结构(无论在发送端还是接收端). Boost.MPI 无法检测对数据结构的这种意外修改, 这很可能导致传输不正确的数据或程序不稳定.

序列化优化

对于不含任何指针的小型定长数据类型, 要获得最佳性能, 用 Boost.MPI 和 Boost.Serialization 的类型特征来标记它们是非常重要的.

前面已经讨论过, 不含指针的定长类型可以用作 is_mpi_datatype, 例如:

namespace boost { namespace mpi {
  template <>
  struct is_mpi_datatype<gps_position> : mpl::true_ { };
} }

或等价的宏

BOOST_IS_MPI_DATATYPE(gps_position)

此外, 如果不使用指向这些类型的指针, 通过使用 Boost.Serialization 的特征类或辅助宏来关闭这些类型的跟踪与版本控制, 可以带来可观的性能提升:

BOOST_CLASS_TRACKING(gps_position,track_never)
BOOST_CLASS_IMPLEMENTATION(gps_position,object_serializable)

同构机器

在同构机器上还有更多优化可能: 避免调用 MPI_Pack/MPI_Unpack, 而是使用直接的按位拷贝. 通过定义宏 BOOST_MPI_HOMOGENEOUS(位于包含文件 boost/mpi/config.hpp 中), 该特性默认开启. 构建 Boost.MPI 与构建应用程序时, 该定义必须保持一致.

此外, 所有类都需要同时标记为 is_mpi_datatype 和 is_bitwise_serializable, 方法是使用 Boost.Serialization 的辅助宏:

BOOST_IS_BITWISE_SERIALIZABLE(gps_position)

通常, 对 is_mpi_datatype 为真的类使用按位二进制拷贝来序列化是安全的. 例外情况是某些成员应被跳过而不参与序列化的类.
