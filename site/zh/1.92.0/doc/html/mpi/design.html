设计理念

并行 MPI 库的设计理念非常简单: 既方便又高效. MPI 是为高性能应用而构建的库, 但其以 FORTRAN 为中心、性能至上的设计, 从 C++ 的角度看相当不灵活: 把一个字符串从一个进程传递到另一个进程很不方便, 需要若干条消息和显式缓冲; 把一个字符串容器从一个进程传递到另一个进程需要额外一层手工记账; 而把一个从字符串到字符串容器的映射传递过去更是让人抓狂. 并行 MPI 库允许用同样简单的 send() 和 recv() 原语传递所有这些数据类型. 同样, 像 reduce() 这样的集合通信操作允许任意数据类型和函数对象, 很像 C++ 标准库的做法.

为便利而提供的更高层抽象不得影响应用程序的性能. 例如, 通过 send 发送一个整数必须与调用 MPI_Send 一样高效, 这意味着它必须通过对 MPI_Send 的简单调用来实现; 同样, 一个整数 reduce()(即使用 std::plus<int>)必须通过对整数调用 MPI_Reduce 并使用 MPI_SUM 操作来实现: 任何达不到这一标准的方式都会影响性能. 从本质上说, 这就是"不为你不用的东西付费"原则: 如果用户不传输字符串, 就不应付出与字符串相关的开销.

有时, 要获得最大性能就意味着放弃方便的抽象, 使用更低层的原语实现某些功能. 因此, 始终可以从 Boost.MPI 的抽象中提取足够的信息, 把 Boost.MPI 与 C MPI 库之间的对接所需的工作量降到最低.
