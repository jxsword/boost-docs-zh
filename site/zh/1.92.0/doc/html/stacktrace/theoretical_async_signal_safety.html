理论上的异步信号安全性

理论上, 在不进行解码和修饰名还原的情况下遍历调用栈应当是异步信号安全的.

但实际上并非如此:

  • 在容器化/虚拟化的 Windows 系统上, 转储回溯期间发生的缺页错误似乎有可能导致死锁. 缺页错误很容易发生, 因为我们必须将转储内容写入内存或文件.
  • 在 POSIX 系统上, 如果在抛出异常时收到信号, 就可能发生死锁 #131. 理论上可以通过以下方式规避: 在异常抛出时绕过 C++ 运行时的互斥锁加锁(示例实现 见 🐙 userver 框架), 或者使用非常新的运行时(glibc-2.35+ 搭配 新版 libgcc 或 新版 LLVM 的 libunwind).
  • -fomit-frame-pointer 之类的标志会给栈遍历实现带来额外的复杂性, 这也可能对信号安全性造成不利影响.

经验法则: 不要 在信号处理器中捕获堆栈回溯, 除非你完全确信自己的环境并检查过其全部源代码.
