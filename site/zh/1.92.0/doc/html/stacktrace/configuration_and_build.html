在 CMake 中使用

CMake 库 Boost::stacktrace 提供最佳可用实现:

target_link_libraries(${PROJECT}
  PUBLIC
    Boost::stacktrace
)

另有用于细粒度选择实现的 CMake 库:

  • Boost::stacktrace_windbg
  • Boost::stacktrace_windbg_cached
  • Boost::stacktrace_backtrace
  • Boost::stacktrace_addr2line
  • Boost::stacktrace_basic
  • Boost::stacktrace_noop

注意默认不使用 Boost::stacktrace_from_exception, 如需其功能请显式添加:

target_link_libraries(${PROJECT}  # your project
  PUBLIC
    Boost::stacktrace
    Boost::stacktrace_from_exception
)

若 Boost 已安装到系统, 为项目获取它的最佳方式是通过 find_package:

find_package(
    Boost
    REQUIRED stacktrace stacktrace_from_exception
    CONFIG
)

CMake 构建说明

使用 CMake 构建 Boost.Stacktrace 库时, 由 BOOST_STACKTRACE_ENABLE_* 选项控制构建. 例如:

  • cmake -DBOOST_STACKTRACE_ENABLE_NOOP=0 -DBOOST_STACKTRACE_ENABLE_BACKTRACE=1 -DBOOST_STACKTRACE_ENABLE_FROM_EXCEPTION=1 - 不构建 noop 实现, 并强制构建 backtrace 与 from_exception.
  • cmake -DBOOST_STACKTRACE_ENABLE_NOOP=1 -DBOOST_STACKTRACE_ENABLE_WINDBG=1 -DBOOST_STACKTRACE_ENABLE_WINDBG_CACHED=0 - 构建 noop 与 windbg 实现并禁用 windbg_cached 的构建.

若未提供这些选项, 将自动检测, 检测结果会打印出来并在构建时隐式使用.

B2 构建说明

使用 b2 构建 Boost.Stacktrace 库时, 可用 boost.stacktrace.* 选项控制构建. 例如:

  • b2 boost.stacktrace.noop=off boost.stacktrace.backtrace=on boost.stacktrace.from_exception=on - 不构建 noop 实现, 并强制构建 backtrace 和 from_exception 实现.
  • b2 boost.stacktrace.noop=on boost.stacktrace.windbg=on boost.stacktrace.windbg_cached=off - 构建 noop 和 windbg 实现, 并禁用 windbg_cached 的构建.

若未提供这些选项, 将自动检测, 检测结果会打印出来并在构建时隐式使用.

[d] 如果你使用搭配 libstdc++ 的 Clang, 在包含 <backtrace.h> 时可能遇到麻烦: 在某些平台上, Clang 不会在 GCC 的包含路径中搜索头文件, 而任何将 GCC 包含路径加入搜索范围的尝试都会导致链接器错误. 要显式指定 <backtrace.h> 头文件的路径, 可以将 BOOST_STACKTRACE_BACKTRACE_INCLUDE_FILE 定义为该头文件的完整路径. 例如, 在 Ubuntu Xenial 上用 Clang 构建时, 请使用命令行选项 -DBOOST_STACKTRACE_BACKTRACE_INCLUDE_FILE=</usr/lib/gcc/x86_64-linux-gnu/5/include/backtrace.h>.

示例:

  • 如果你希望在 Clang/MinGW 上切换到更强大的实现, 且 BOOST_STACKTRACE_LINK 已定义, 只需链接 "-lboost_stacktrace_backtrace -ldl -lbacktrace" 或 "-lboost_stacktrace_addr2line -ldl" 即可
  • 如果你希望禁用回溯, 且 BOOST_STACKTRACE_LINK 已定义, 只需链接 -lboost_stacktrace_noop 即可
  • 如果你希望禁用回溯, 且以仅头文件库模式使用该库, 只需为整个项目定义 BOOST_STACKTRACE_USE_NOOP 并重新编译即可

MinGW 和 MinGW-w64 专属说明

MinGW-w64 和 MinGW(不带 -w64)的用户需要安装 libbacktrace 才能获得更好的堆栈回溯. 请按以下说明操作:

假设你已将 MinGW 安装到 C:\MinGW, 并将 libbacktrace 源代码 下载到了 C:\libbacktrace-master

  • 从控制台配置并构建 libbacktrace:
    • C:\MinGW\msys\1.0\bin\sh.exe
    • cd /c/libbacktrace-master
    • ./configure CC=/c/MinGW/bin/gcc.exe CXX=/c/MinGW/bin/g++.exe
    • make
    • ./libtool --mode=install /usr/bin/install -c libbacktrace.la '/c/libbacktrace-master'
  • 将以下信息添加到 Boost 文件夹中的 project-config.jam:
    • using gcc : 6 : "C:\MinGW\bin\g++.exe" : <compileflags>-I"C:\libbacktrace-master\" <linkflags>-L"C:\libbacktrace-master\" ;
  • 现在, 通过为你的项目定义 BOOST_STACKTRACE_USE_BACKTRACE 即可使用仅头文件库版本, 或者在 Boost 文件夹中构建 stacktrace 库:
    • b2.exe toolset=gcc-6 --with-stacktrace

Windows 部署与符号文件

将应用程序部署到其他系统之后, 函数名可能无法解析.

如果你随应用程序一起分发 PDB 文件, 有多种方法可以处理该问题:

  • 在链接应用程序和共享库时, 正确设置 /PDBALTPATH 标志, 例如 /PDBALTPATH:%_PDB%. 更多信息参见 官方文档.
  • 将目标系统的 _NT_ALT_SYMBOL_PATH 或 _NT_SYMBOL_PATH 环境变量设置为 PDB 文件的路径. 更多信息参见 官方文档.
