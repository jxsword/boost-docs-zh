The Statistical Accumulators Library

本节介绍如何使用 Boost.Accumulators 框架创建新的累加器, 以及如何使用现有的统计累加器执行增量统计计算. 有关 Boost.Accumulators 中特定组件的详细信息, 请参阅 参考 一节.

Hello, World!

下面是一个完整示例, 演示如何使用累加器框架和统计累加器执行增量统计计算. 它计算一个 double 序列的均值和二阶矩.

#include <iostream>
#include <boost/accumulators/accumulators.hpp>
#include <boost/accumulators/statistics/stats.hpp>
#include <boost/accumulators/statistics/mean.hpp>
#include <boost/accumulators/statistics/moment.hpp>
using namespace boost::accumulators;

int main()
{
    // Define an accumulator set for calculating the mean and the
    // 2nd moment ...
    accumulator_set<double, stats<tag::mean, tag::moment<2> > > acc;

    // push in some data ...
    acc(1.2);
    acc(2.3);
    acc(3.4);
    acc(4.5);

    // Display the results ...
    std::cout << "Mean:   " << mean(acc) << std::endl;
    std::cout << "Moment: " << moment<2>(acc) << std::endl;

    return 0;
}

该程序显示如下内容:

Mean:   2.85
Moment: 9.635

概念

累加器框架是用于执行增量计算的框架. 该框架的使用遵循以下模式:

  • 用户通过选择自己感兴趣的计算, 或自行编写符合该框架的计算原语, 来构建一个称为 accumulator_set<> 的计算对象.
  • 用户一次一个样本地将数据推入 accumulator_set<> 对象.
  • accumulator_set<> 以尽可能高效的方法计算所请求的量, 解析所请求计算之间的依赖关系, 并可能缓存中间结果.

累加器框架定义了定义基本计算元素 (称为 累加器) 所需的实用工具. 它还提供上文所述的 accumulator_set<> 类型.

术语

以下术语在文档其余部分中使用.

样本 (Sample)

推入 accumulator_set<> 的一个数据. 样本的类型即 样本类型.

权重 (Weight)

随样本一起传递的可选标量值, 用于指定该样本的权重. 从概念上讲, 每个样本都与其权重相乘. 权重的类型即 权重类型.

特性 (Feature)

一种抽象的基本计算实体. 在定义 accumulator_set<> 时, 用户指定自己感兴趣的特性, accumulator_set<> 则会找出最能提供这些特性的 累加器. 特性可能依赖于其他特性; 如果依赖, 累加器集合会确定应添加哪些累加器以满足这些依赖关系.

累加器 (Accumulator)

一种具体的基本计算实体. 累加器是某个特性的具体实现, 它恰好满足一个抽象特性. 多个不同的累加器可以提供同一特性, 但可能代表不同的实现策略.

累加器集合 (Accumulator Set)

累加器的集合. 累加器集合由一个样本类型和一个特性列表指定. 累加器集合利用这些信息, 依据特性依赖图生成一个有序的累加器集合. 累加器集合每次接受一个数据作为样本, 并按顺序将其传播到每个累加器. 任何时候都可以从累加器集合中提取结果.

提取器 (Extractor)

可用于从 accumulator_set<> 中提取结果的函数或函数对象.

使用 accumulator_set<>

我们对 accumulator_set<> 类模板的讲解从前向声明开始:

template< typename Sample, typename Features, typename Weight = void >
struct accumulator_set;

模板参数的含义如下:

Sample

将被累加的数据的类型.

Features

一个 MPL 序列, 列出要计算的特性.

Weight

(可选的) 权重参数的类型.

例如, 下面这行代码声明了一个 accumulator_set<> , 它将逐个接受 double 序列并计算最小值和均值:

accumulator_set< double, features< tag::min, tag::mean > > acc;

注意, 我们使用 features<> 模板来指定要计算的特性列表. features<> 是一个由特性组成的 MPL 序列.

注释

features<> 是 mpl::vector<>的同义词. 实际上, 如果我们愿意, 也可以使用 mpl::vector<> 或任意 MPL 序列, 含义相同.

定义好 accumulator_set<>之后, 我们就可以向其中推送数据, 它会计算出你所请求的量, 如下所示.

// push some data into the accumulator_set ...
acc(1.2);
acc(2.3);
acc(3.4);

由于 accumulator_set<> 将其 accumulate 函数定义为函数调用运算符, 我们可能想将 accumulator_set<> 用作标准算法 (如 std::for_each) 的 UnaryFunction. 这没有问题, 但请记住: 标准算法按值接收 UnaryFunction 对象, 这意味着要复制 accumulator_set<> 对象. 请看下面的例子:

// The data for which we wish to calculate statistical properties:
std::vector< double > data( /* stuff */ );

// The accumulator set which will calculate the properties for us:    
accumulator_set< double, features< tag::min, tag::mean > > acc;

// Use std::for_each to accumulate the statistical properties:
acc = std::for_each( data.begin(), data.end(), acc );

注意, 我们必须将 std::for_each 的返回值重新赋回 accumulator_set<>. 这样做可行, 但有些累加器的复制代价很高. 例如, tail 和 tail_variate<> 累加器必须存储一个 std::vector<>, 因此复制这些累加器会涉及动态分配. 在这种情况下, 借助 boost::bind() 和 boost::ref()按引用传递累加器可能更好. 参见下例:

// The data for which we wish to calculate statistical properties:
std::vector< double > data( /* stuff */ );

// The accumulator set which will calculate the properties for us:
accumulator_set< double, features< tag::tail<left> > > acc(
    tag::tail<left>::cache_size = 4 );

// Use std::for_each to accumulate the statistical properties:
std::for_each( data.begin(), data.end(), bind<void>( ref(acc), _1 ) );

现在注意, 我们不再关心 std::for_each() 的返回值, 因为 std::for_each() 直接修改了 acc .

注释

要使用 boost::bind() 以及 boost::ref(), 你必须 #include <boost/bind.hpp> 以及 <boost/ref.hpp>

提取结果

声明了 accumulator_set<> 并向其中推送数据之后, 我们需要能够从中提取结果. 对于可以添加到 accumulator_set<>的每个特性, 都有一个对应的提取器用于获取其结果. 通常, 提取器与特性同名, 只是位于不同的命名空间中. 例如, 如果我们累加 tag::min 以及 tag::max 特性, 就可以用 min 以及 max 提取器来提取结果, 如下所示:

// Calculate the minimum and maximum for a sequence of integers.
accumulator_set< int, features< tag::min, tag::max > > acc;
acc( 2 );
acc( -1 );
acc( 1 );

// This displays "(-1, 2)"
std::cout << '(' << min( acc ) << ", " << max( acc ) << ")\n";

所有提取器都声明在 boost::accumulators::extract 命名空间中, 但通过一条 boost::accumulators 声明被引入 using 命名空间.

提示

在 Windows 平台上, min 以及 max 是在 WinDef.h中定义的预处理器宏. 要使用 min 以及 max 提取器, 你应当在定义了 NOMINMAX 的情况下编译, 或者像这样调用提取器: (min)( acc ) 以及 (max)( acc ). 括号可以阻止宏被调用展开.

从 accumulator_set<> 中提取结果的另一种方法是使用 extract_result() 函数. 如果某个特性没有现成的提取器对象, 这种方式可能更为方便. 上面显示结果的那一行代码也可以等价地写成:

// This displays "(-1, 2)"
std::cout << '('  << extract_result< tag::min >( acc )
          << ", " << extract_result< tag::max >( acc ) << ")\n";

最后, 我们可以使用 extractor<> 类模板定义自己的提取器. 例如, 避免 min / max 宏问题的另一种办法, 是定义名字与宏不冲突的提取器, 如下所示:

extractor< tag::min > min_;
extractor< tag::min > max_;

// This displays "(-1, 2)"
std::cout << '(' << min_( acc ) << ", " << max_( acc ) << ")\n";

传递可选参数

有些累加器需要初始化参数. 此外, 也许某些辅助信息需要随每个样本一起传入 accumulator_set<> . Boost.Accumulators 使用 Boost.Parameter 库的命名参数来处理这些情况.

例如, 考虑 tail 以及 tail_variate<> 特性. tail 保存最大的 N 个样本的有序列表, 其中 N 可以在构造时指定. 另外, 依赖于 tail_variate<> 的 tail特性会跟踪某些与 N 所跟踪的 tail个样本协变的数据. 下面的代码展示了这一切是如何工作的, 稍后会更详细地说明.

// Define a feature for tracking covariate data
typedef tag::tail_variate< int, tag::covariate1, left > my_tail_variate_tag;

// This will calculate the left tail and my_tail_variate_tag for N == 2
// using the tag::tail<left>::cache_size named parameter
accumulator_set< double, features< my_tail_variate_tag > > acc(
    tag::tail<left>::cache_size = 2 );

// push in some samples and some covariates by using 
// the covariate1 named parameter
acc( 1.2, covariate1 =  12 );
acc( 2.3, covariate1 = -23 );
acc( 3.4, covariate1 =  34 );
acc( 4.5, covariate1 = -45 );

// Define an extractor for the my_tail_variate_tag feature
extractor< my_tail_variate_tag > my_tail_variate;

// Write the tail statistic to std::cout. This will print "4.5, 3.4, "
std::ostream_iterator< double > dout( std::cout, ", " );
std::copy( tail( acc ).begin(), tail( acc ).end(), dout );

// Write the tail_variate statistic to std::cout. This will print "-45, 34, "
std::ostream_iterator< int > iout( std::cout, ", " );
std::copy( my_tail_variate( acc ).begin(), my_tail_variate( acc ).end(), iout );

关于上面的代码, 有几点需要注意. 首先, 注意我们不必请求计算 tail 特性——这是隐式的, 因为 tail_variate<> 特性依赖于 tail 特性. 其次, 注意 acc 对象是如何初始化的: acc( tag::tail<left>::cache_size = 2 ). 这里, cache_size 是一个命名参数, 用于告知 tail 以及 tail_variate<> 累加器要存储多少样本和协变量. 从概念上讲, 每个构造参数都会提供给累加器集合中的每个累加器.

我们还使用命名参数将协变量数据随样本一起传入累加器集合. 与构造参数一样, accumulate 函数的所有参数都会提供给集合中的所有累加器. 在本例中, 只有 my_tail_variate 特性对应的累加器会对 covariate1 命名参数的值感兴趣.

关于上面的示例, 我们还可以做最后一点观察. 由于 tail 以及 tail_variate<> 是多值特性 (multi-valued features) , 为它们提取的结果表示为一个迭代器范围. 这就是为什么我们可以写 tail( acc ).begin() 以及 tail( acc ).end().

连提取器都可以接受命名参数. 稍后我们会看到这样做很有用的情形.

加权样本

有些累加器——特别是统计累加器——处理的是 加权的数据. 推入累加器的每个样本都有一个关联的权重, 样本在概念上与其权重相乘. 统计累加器库提供了各种此类加权统计累加器. 许多非加权统计累加器也有加权变体. 例如, sum 累加器的加权变体称为 weighted_sum, 其计算方式是累加所有样本与其权重相乘的结果.

要声明接受加权样本的 accumulator_set<> , 你必须将权重参数的类型指定为第 3 个模板参数, 如下所示:

// 3rd template parameter 'int' means this is a weighted
// accumulator set where the weights have type 'int'
accumulator_set< int, features< tag::sum >, int > acc;

指定权重后, 集合中的所有累加器都会被替换为它们的加权等价物. 例如, 上面的 accumulator_set<> 声明等价于以下代码:

// Since we specified a weight, tag::sum becomes tag::weighted_sum
accumulator_set< int, features< tag::weighted_sum >, int > acc;

向累加器集合传递样本时, 你还必须指定每个样本的权重. 可以用 weight 命名参数来做到这一点, 如下所示:

acc(1, weight = 2); //   1 * 2
acc(2, weight = 4); //   2 * 4
acc(3, weight = 6); // + 3 * 6
                    // -------
                    // =    28

然后你可以用 sum() 提取器提取结果, 如下所示:

// This prints "28"
std::cout << sum(acc) << std::endl;
注释

使用统计累加器库中的加权统计累加器时, 务必包含相应的头文件. 例如, weighted_sum 定义于 <boost/accumulators/statistics/weighted_sum.hpp>.

数值运算符子库

本节描述 boost::numeric 命名空间中的函数对象, 该子库提供与 C++ 中缀运算符相对应的函数对象和元函数.

在 boost::numeric::operators 命名空间中还有一些额外的运算符重载, 用于标准库未提供的一些有用操作, 例如 std::complex<> 与标量的乘法.

在 boost::numeric::functional 命名空间中是中缀运算符的函数对象等价物. 这些函数对象类型是异构的, 因此比 <functional> 头文件中的标准函数对象更为通用. 它们使用 Boost.Typeof 库来推导所求值的中缀表达式的返回类型. 此外, 它们会在 boost::numeric::operators 命名空间中查找可能在那里定义的任何额外重载.

在 boost::numeric 命名空间中是与 boost::numeric::functional 命名空间中定义的函数对象类型相对应的全局多态函数对象. 例如, boost::numeric::plus(a, b) 等价于 boost::numeric::functional::plus<A, B>()(a, b), 两者都等价于 using namespace boost::numeric::operators; a + b;.

数值运算符子库还提供了多种子类化途径, 以及一种对操作进行子类化和特化的方法. 一种方式基于操作数类型的标签分派 (tag dispatching) ; 另一种方式基于操作数的编译期属性.

定义新累加器

所有新累加器都必须满足 Accumulator Concept (累加器概念) . 下面是一个满足累加器概念的示例类, 它只是对传入的所有样本的值求和.

#include <boost/accumulators/framework/accumulator_base.hpp>
#include <boost/accumulators/framework/parameters/sample.hpp>

namespace boost {                           // Putting your accumulators in the
namespace accumulators {                    // impl namespace has some
namespace impl {                            // advantages. See below.

template<typename Sample>
struct sum_accumulator                      // All accumulators should inherit from
  : accumulator_base                        // accumulator_base.
{
    typedef Sample result_type;             // The type returned by result() below.

    template<typename Args>                 // The constructor takes an argument pack.
    sum_accumulator(Args const & args)
      : sum(args[sample | Sample()])        // Maybe there is an initial value in the
    {                                       // argument pack. ('sample' is defined in
    }                                       // sample.hpp, included above.)

    template<typename Args>                 // The accumulate function is the function
    void operator ()(Args const & args)     // call operator, and it also accepts an
    {                                       // argument pack.
        this->sum += args[sample];
    }

    result_type result(dont_care) const     // The result function will also be passed
    {                                       // an argument pack, but we don't use it here,
        return this->sum;                   // so we use "dont_care" as the argument type.
    }
private:
    Sample sum;
};

}}}

上面的大部分内容应当一目了然, 但参数包 (argument pack) 的用法在你从未使用过 Boost.Parameter 库时可能令人困惑. 参数包是一组值的集合, 其中每个值都可以用键来访问. 因此 args[sample] 从参数包中提取与 sample 键相关联的值. 而看起来神秘的 args[sample | Sample()] 则求值为与 sample 键相关联的值 (如果存在) , 否则求值为默认构造的 Sample .

上面的示例展示了累加器最常见的属性. 还有一些具有特殊含义的可选成员函数. 具体来说:

可选的累加器成员函数

on_drop(Args)

定义当此累加器被丢弃时要采取的操作. 参见 可丢弃累加器 (Droppable Accumulators) 一节.

访问集合中的其他累加器

有些累加器依赖于同一累加器集合中的其他累加器. 在这些情况下, 需要能够访问那些其他累加器. 为使之可行, accumulator_set<> 在调用其包含的累加器的成员函数时会传递对自身的引用. 可以将特殊的 accumulator 键与参数包一起使用来访问它. 想想我们可以如何实现 mean_accumulator:

// Mean == (Sum / Count)
template<typename Sample>
struct mean_accumulator : accumulator_base
{
    typedef Sample result_type;
    mean_accumulator(dont_care) {}

    template<typename Args>
    result_type result(Args const &args) const
    {
        return sum(args[accumulator]) / count(args[accumulator]);
    }
};

mean 依赖于 sum 以及 count 累加器. (我们将在下一节中看到如何指定这些依赖关系. ) 均值累加器的结果只是和累加器的结果除以计数累加器的结果. 考虑我们可以这样写: sum(args[accumulator]) / count(args[accumulator]). 表达式 args[accumulator] 求值为对 accumulator_set<> 的引用, 它包含此 mean_accumulator. 它还包含 sum 以及 count 累加器, 我们可以用为这些特性定义的提取器来访问它们的结果: sum 以及 count.

注释

继承自 accumulator_base 的累加器会得到一个空的 operator (), 因此像上面的 mean_accumulator 这样的累加器无需定义它.

所有接受参数包的成员函数都可以访问外围的 accumulator_set<> , 使用键 accumulator , 构造函数也不例外. 集合中的累加器按照其相互依赖关系确定的顺序构造. 因此, 累加器在构造期间访问其所依赖的另一个累加器是安全的.

中缀表示法与数值运算符子库

尽管并非必需, 但把你的累加器实现放在 boost::accumulators::impl 命名空间中是个好主意. 该命名空间通过 using 指令引入了定义于 boost::numeric::operators 命名空间中的运算符. 数值运算符子库定义了一些额外的重载, 使你的累加器能够处理各种数据类型.

考虑上文定义的 mean_accumulator . 它将样本之和除以计数. 计数的类型为 std::size_t. 如果样本类型没有定义除以 std::size_t的除法怎么办? 对于 std::complex<>正是这种情况. 你可能认为, 如果样本类型是 std::complex<>, 代码将无法工作, 但实际上却可以. 这是因为数值运算符子库定义了一个重载的 operator/ 用于 std::complex<> 以及 std::size_t. 该运算符定义在 boost::numeric::operators 命名空间中, 并会在 boost::accumulators::impl 命名空间中被找到. 这就是把累加器放在那里的好理由.

可丢弃累加器

"可丢弃" (droppable) 一词指的是可以从 accumulator_set<>中移除的累加器. 你可以使用 droppable<> 类模板来要求把某个累加器做成可丢弃的.

// calculate sum and count, make sum droppable:
accumulator_set< double, features< tag::count, droppable<tag::sum> > > acc;

// add some data
acc(3.0);
acc(2.0);

// drop the sum (sum is 5 here)
acc.drop<tag::sum>();

// add more data
acc(1.0);

// This will display "3" and "5"
std::cout << count(acc) << ' ' << sum(acc);

为了满足对可丢弃累加器的依赖而添加到累加器集合中的任何累加器, 其本身也是可丢弃的. 考虑以下累加器:

// Sum is not droppable. Mean is droppable. Count, brought in to 
// satisfy mean's dependencies, is implicitly droppable, too.
accumulator_set< double, features< tag::sum, droppable<tag::mean> > > acc;

mean 依赖于 sum 以及 count. 由于 mean 是可丢弃的, 所以 count也是可丢弃的. 但是, 我们已显式要求 sum 不可丢弃, 因此它并非可丢弃. 如果在上述声明中省略 tag::sum , 那么 sum 累加器本来会隐式地成为可丢弃的.

可丢弃累加器是按引用计数的, 只有在所有依赖它的累加器都已被丢弃之后, 它才真正被丢弃. 这在某些情况下会导致一些令人意外行为.

// calculate sum and mean, make mean droppable. 
accumulator_set< double, features< tag::sum, droppable<tag::mean> > > acc;

// add some data
acc(1.0);
acc(2.0);

// drop the mean. mean's reference count
// drops to 0, so it's really dropped. So
// too, count's reference count drops to 0
// and is really dropped.
acc.drop<tag::mean>();

// add more data. Sum continues to accumulate!
acc(3.0);

// This will display "6 2 3"
std::cout << sum(acc) << ' '
          << count(acc) << ' '
          << mean(acc);

注意, 在 mean 被丢弃时, sum 为 3, count 为 2, 因此 mean 为 1.5. 但由于 sum 在 mean 被丢弃之后仍在继续累加, mean 的值会继续变化. 如果你想记住 mean 被丢弃时的值, 应当把它的值保存到一个局部变量中.

以下规则更精确地规定了可丢弃与非可丢弃累加器在累加器集合中的行为.

  • 累加器有两种类型: 可丢弃与非可丢弃. 默认为非可丢弃.
  • 对于任何特性 X, X 以及 droppable<X> 都满足 X 依赖关系.
  • 如果特性 X 依赖于 Y 以及 Z, 那么 droppable<X> 依赖于 droppable<Y> 以及 droppable<Z>.
  • 所有累加器都有 add_ref() 以及 drop() 成员函数.
  • 对于非可丢弃累加器, drop() 是空操作 (no-op) , 而 add_ref() 会在与当前累加器所依赖的特性相对应的所有累加器上调用 add_ref() .
  • 可丢弃累加器具有引用计数, 并定义了 add_ref() 以及 drop() 来操纵该引用计数.
  • 对于可丢弃累加器, add_ref() 会增加累加器的引用计数, 还会对与当前累加器所依赖的特性相对应的累加器同样执行 add_ref()操作.
  • 对于可丢弃累加器, drop() 会减少累加器的引用计数, 还会对与当前累加器所依赖的特性相对应的累加器同样执行 drop()操作.
  • accumulator_set 构造函数会遍历 用户指定的 特性列表, 并对每个特性对应的累加器执行 add_ref()操作. (注意: 这意味着, 并非由用户指定、只是为满足依赖而存在于集合中的累加器, 会在其所有依赖均被丢弃后立即被丢弃. 而用户指定的累加器, 则要等到其依赖已被丢弃 以及 用户已显式丢弃该累加器之后才会被丢弃. )
  • 可丢弃累加器在其 accumulate 成员函数中检查自己的引用计数. 如果引用计数为 0, 该函数就是空操作.
  • 不允许用户丢弃既非用户指定、又未标记为可丢弃的特性.

另外, 作为一种优化:

  • 如果用户指定了非可丢弃特性 X, 它依赖于 Y 以及 Z, 那么 Y 以及 Z 对应的累加器可以安全地设为非可丢弃, 它们所依赖的任何累加器也是如此.
定义新特性

实现了一个累加器之后, 我们必须为它定义一个特性, 以便用户在声明 accumulator_set<>时可以指定该特性. 我们通常把这些特性放进一个嵌套命名空间, 以便稍后定义同名的提取器. 所有特性都必须满足 Feature Concept (特性概念) . 使用 depends_on<> 可以使满足该概念变得简单. 下面是一个特性定义的示例.

namespace boost { namespace accumulators { namespace tag {

struct mean                         // Features should inherit from
  : depends_on< count, sum >        // depends_on<> to specify dependencies
{
    // Define a nested typedef called 'impl' that specifies which
    // accumulator implements this feature. 
    typedef accumulators::impl::mean_accumulator< mpl::_1 > impl;
};

}}}

要定义 mean 特性, 我们只需要做两件事: 用 depends_on<> 指定依赖关系, 并定义嵌套的 impl typedef. 即使没有任何依赖的特性也应继承自 depends_on<>. 嵌套的 impl 类型必须是一个 MPL Lambda 表达式. 而表达式 mpl::apply< impl, sample-type, <SP> weight-type <SP> >::type 必须是实现该特性的累加器的类型. 使用 MPL 占位符 (如 mpl::_1 ) 可以非常容易地把诸如 mean_accumulator<> 这样的模板变成 MPL Lambda 表达式. 这里, mpl::_1 将被替换为样本类型. 如果我们改用 mpl::_2, 则它将被替换为权重类型.

那么不是模板的累加器类型怎么办? 如果你有一个 foo_accumulator (它是一个普通 struct 而非模板) , 你可以把它转换为一个 MPL Lambda 表达式 , 方法是使用 mpl::always<>, 如下所示:

// An MPL lambda expression that always evaluates to
// foo_accumulator:
typedef mpl::always< foo_accumulator > impl;

如果你拿不准, 或者对 MPL lambda 表达式不太熟悉, 你总是可以显式定义 impl :

// Same as 'typedef mpl::always< foo_accumulator > impl;'
struct impl
{
    template< typename Sample, typename Weight >
    struct apply
    {
        typedef foo_accumulator type;
    };
};

这里, impl 是一个二元 MPL 元函数类, 它是 MPL Lambda 表达式的一种. 嵌套的 apply<> 模板是元函数类协议的一部分, 它告诉 MPL 在给定样本类型和权重类型时如何构建累加器类型.

所有特性还必须提供一个嵌套的 is_weight_accumulator typedef. 它必须是 mpl::true_ 或者 mpl::false_. depends_on<> 为所有继承自它的特性提供了 mpl::false_ . 当特性表示的是关于权重而非样本的信息累积时, 我们可以用 typedef mpl::true_ is_weight_accumulator;把该特性标记为这种特性. 如果权重类型是用 external<> 模板指定的, 权重累加器将被做成外部 (external) 的.

定义新提取器

现在我们有了累加器和特性, 唯一欠缺的就是从累加器集合中获取结果的方法. 累加器框架提供了 extractor<> 类模板, 使为你的特性定义提取器变得简单. 下面是我们上面定义的 mean 特性的提取器:

namespace boost {
namespace accumulators {                // By convention, we put extractors
namespace extract {                     // in the 'extract' namespace

extractor< tag::mean > const mean = {}; // Simply define our extractor with
                                        // our feature tag, like this.
}
using extract::mean;                    // Pull the extractor into the
                                        // enclosing namespace.
}}

一旦定义, mean 提取器就可以用于提取 tag::mean 特性的结果 (来自 accumulator_set<>) .

参数化特性使这幅简单的图景变得复杂. 考虑 moment 特性, 它用于计算 N阶矩, 其中 N 被指定为一个模板参数:

// An accumulator set for calculating the N-th moment, for N == 2 ...
accumulator_set< double, features< tag::moment<2> > > acc;

// ... add some data ...

// Display the 2nd moment ...
std::cout << "2nd moment is " << accumulators::moment<2>(acc) << std::endl;

在表达式 accumulators::moment<2>(acc)中, moment是什么? 它不可能是对象——C++ 的语法不允许这样做. 显然, 如果我们想提供这种语法, 就必须把 moment 做成函数模板. 下面是 moment 提取器的定义:

namespace boost {
namespace accumulators {                // By convention, we put extractors
namespace extract {                     // in the 'extract' namespace

template<int N, typename AccumulatorSet>
typename mpl::apply<AccumulatorSet, tag::moment<N> >::type::result_type
moment(AccumulatorSet const &acc)
{
    return extract_result<tag::moment<N> >(acc);
}

}
using extract::moment;                  // Pull the extractor into the
                                        // enclosing namespace.
}}

返回类型值得解释一下. 每个 accumulator_set<> 类型实际上都是一个一元 MPL 元函数类. 当你 mpl::apply<> 一个 accumulator_set<> 和一个特性时, 结果是集合中实现该特性的累加器的类型. 而且每个累加器都提供一个嵌套的 result_type typedef, 指明其返回类型是什么. 提取器只是把工作委托给 extract_result() 函数.

控制依赖关系

累加器框架基于特性的依赖解析旨在允许每个特性有多种不同的实现策略. 例如, 两个不同的累加器可能用不同的舍入模式计算同一个量, 或者使用在大小/速度之间有不同权衡的不同算法. 依赖该量的其他累加器不应关心它是如何计算的. 累加器框架通过允许多个不同的累加器满足同一特性来处理这一点.

用 feature_of<>为特性依赖取别名

假设你想实现一个假想的 fubar 统计量, 并且你知道在一批样本上计算 fubar 的两种方法: 精确但慢的计算, 以及近似但快的计算. 你可能选择把精确计算作为默认, 于是你实现两个累加器并称之为 impl::fubar_impl 以及 impl::fast_fubar_impl. 你还要定义 tag::fubar 以及 tag::fast_fubar 特性, 如 上文所述. 现在, 你想告知累加器框架: 从依赖解析的角度看, 这两个特性是等同的. 你可以用 feature_of<>来做到这一点, 如下所示:

namespace boost { namespace accumulators
{
    // For the purposes of feature-based dependency resolution,
    // fast_fubar provides the same feature as fubar
    template<>
    struct feature_of<tag::fast_fubar>
      : feature_of<tag::fubar>
    {
    };
}}

上面的代码告知累加器框架: 如果集合中的另一个累加器依赖于 tag::fubar 特性, 那么 tag::fast_fubar 特性是一个可接受的替代品.

用 as_feature<>注册特性变体

你可能已经注意到, 累加器框架中的一些特性变体可以用更友好的语法来指定. 例如, 可以不用 tag::mean 以及 tag::immediate_mean 而分别用 tag::mean(lazy) 以及 tag::mean(immediate) 来指定它们. 这些仅仅是别名, 但这种语法使两者之间的关系更清晰. 你可以用 as_feature<> 特征 (trait) . 对于上面的 fubar 示例, 你可能决定为 tag::fubar(accurate) 与 tag::fubar 以及 tag::fubar(fast) 与 tag::fast_fubar分别建立别名. 你会这样做:

namespace boost { namespace accumulators
{
    struct fast {};     // OK to leave these tags empty
    struct accurate {};

    template<>
    struct as_feature<tag::fubar(accurate)>
    {
        typedef tag::fubar type;
    };

    template<>
    struct as_feature<tag::fubar(fast)>
    {
        typedef tag::fast_fubar type;
    };
}}

做到这一点之后, 你的 fubar 累加器的用户就可以请求 tag::fubar(fast) 以及 tag::fubar(accurate) 这两个特性, 并在定义 accumulator_set时得到正确的累加器.

特化数值运算符

本节介绍如何使第三方数值类型适配累加器框架.

累加器框架的许多数值运算并不依赖内建运算符, 而是依赖 数值运算符子库 中定义的函数和运算符重载. 这是为了能够给算术运算赋予非标准的含义. 例如, 用两个整数相除来计算平均值时, 标准的整数除法行为对大多数统计量来说在数学上是不正确的. 因此, 累加器框架不使用 x / y, 而是使用 numeric::fdiv(x, y), 即使 x 以及 y 都是整数, 它也执行浮点除法.

数值运算符子库另一个有用的场景是: 某个类型没有定义某些统计计算所需的运算符重载. 例如, std::vector<> 没有重载任何算术运算符, 但把 std::vector<> 用作样本或变量 (variate) 类型可能很有用. 数值运算符子库在 boost::numeric::operators 命名空间中定义了必要的运算符重载, 累加器框架通过 using 指令将其引入作用域.

数值函数对象与标签分派

数值运算符子库定义的数值函数对象是如何与 std::vector<>这样的类型协同工作的? boost::numeric 命名空间中的自由函数是用 boost::numeric::functional 命名空间中的函数对象实现的. 因此, 举例来说, 要让 boost::numeric::fdiv() 对某个 std::vector<>做出有意义的行为, 我们需要偏特化 boost::numeric::functional::fdiv<> 函数对象.

这些函数对象使用一种称为 标签分派 (tag dispatching) 的技术来为给定的操作数选择合适的实现. 其工作方式如下:

namespace boost { namespace numeric { namespace functional
{
    // Metafunction for looking up the tag associated with
    // a given numeric type T.
    template<typename T>
    struct tag
    {
        // by default, all types have void as a tag type
        typedef void type;
    };

    // Forward declaration looks up the tag types of each operand
    template<
        typename Left
      , typename Right
      , typename LeftTag = typename tag<Left>::type
      , typename RightTag = typename tag<Right>::type
    >
    struct fdiv;
}}}

如果你有某个用户自定义类型 MyDouble , 想为它定制 numeric::fdiv()的行为, 你应当特化 numeric::functional::fdiv<> ——方法是先定义一个标签类型, 如下所示:

namespace boost { namespace numeric { namespace functional
{
    // Tag type for MyDouble
    struct MyDoubleTag {};

    // Specialize tag<> for MyDouble.
    // This only needs to be done once.
    template<>
    struct tag<MyDouble>
    {
        typedef MyDoubleTag type;
    };

    // Specify how to divide a MyDouble by an integral count
    template<typename Left, typename Right>
    struct fdiv<Left, Right, MyDoubleTag, void>
    {
        // Define the type of the result
        typedef ... result_type;

        result_type operator()(Left & left, Right & right) const
        {
            return ...;
        }
    };
}}}

完成之后, 只要第一个实参是 numeric::fdiv() 对象, numeric::functional::fdiv<> 就会使用你对 MyDouble 的特化. 数值运算符子库中的所有函数对象都可以用类似的方式定制.

weighted_variance 及其变体

加权方差的惰性或迭代计算. 惰性计算与 tag::lazy_weighted_variance 特性相关联, 迭代计算与 tag::weighted_variance 特性相关联. 两者都可以用 tag::weighted_variance() 提取器提取. 更多实现细节请参见 lazy_weighted_variance_impl 以及 weighted_variance_impl

结果类型

numeric::functional::fdiv<
    numeric::functional::multiplies<sample-type, weight-type>::result_type
  , std::size_t
>::result_type

依赖于

tag::lazy_weighted_variance 依赖于 tag::weighted_moment<2> 以及 tag::weighted_mean
tag::weighted_variance 依赖于 tag::count 以及 tag::immediate_weighted_mean

变体

tag::lazy_weighted_variance (又名 tag::weighted_variance(lazy))
tag::weighted_variance (又名 tag::weighted_variance(immediate))

初始化参数

none

累加器参数

weight

提取器参数

none

累加器复杂度

O(1)

提取器复杂度

O(1)

示例 

// lazy weighted_variance
accumulator_set<int, stats<tag::weighted_variance(lazy)>, int> acc1;

acc1(1, weight = 2);    //  2
acc1(2, weight = 3);    //  6
acc1(3, weight = 1);    //  3
acc1(4, weight = 4);    // 16
acc1(5, weight = 1);    //  5

// weighted_mean = (2+6+3+16+5) / (2+3+1+4+1) = 32 / 11 = 2.9090909090909090909090909090909

BOOST_CHECK_EQUAL(5u, count(acc1));
BOOST_CHECK_CLOSE(2.9090909, weighted_mean(acc1), 1e-5);
BOOST_CHECK_CLOSE(10.1818182, accumulators::weighted_moment<2>(acc1), 1e-5);
BOOST_CHECK_CLOSE(1.7190083, weighted_variance(acc1), 1e-5);

// immediate weighted_variance
accumulator_set<int, stats<tag::weighted_variance>, int> acc2;

acc2(1, weight = 2);
acc2(2, weight = 3);
acc2(3, weight = 1);
acc2(4, weight = 4);
acc2(5, weight = 1);

BOOST_CHECK_EQUAL(5u, count(acc2));
BOOST_CHECK_CLOSE(2.9090909, weighted_mean(acc2), 1e-5);
BOOST_CHECK_CLOSE(1.7190083, weighted_variance(acc2), 1e-5);

// check lazy and immediate variance with random numbers

// two random number generators
boost::lagged_fibonacci607 rng;
boost::normal_distribution<> mean_sigma(0,1);
boost::variate_generator<boost::lagged_fibonacci607&, boost::normal_distribution<> > normal(rng, mean_sigma);

accumulator_set<double, stats<tag::weighted_variance>, double > acc_lazy;
accumulator_set<double, stats<tag::weighted_variance(immediate)>, double > acc_immediate;

for (std::size_t i=0; i<10000; ++i)
{
    double value = normal();
    acc_lazy(value, weight = rng());
    acc_immediate(value, weight = rng());
}

BOOST_CHECK_CLOSE(1., weighted_variance(acc_lazy), 1.);
BOOST_CHECK_CLOSE(1., weighted_variance(acc_immediate), 1.);
