如何访问属性树中的数据

属性树类似于 (几乎就是) 一个值类型为 pair<string, ptree> 的标准容器. 它具有常用的成员函数, 如 insert, push_back, find, erase 等. 当然可以用它们来填充和访问树. 例如, 以下代码添加键 "pi", 其数据为(近似于)数学上的 pi 值:

ptree pt;
pt.push_back(ptree::value_type("pi", ptree("3.14159")));

要查找 pi 的值, 可以这样做:

ptree::const_assoc_iterator it = pt.find("pi");
double pi = boost::lexical_cast<double>(it->second.data());

这看起来相当繁琐, 如果 pi 的值不是 stored 在靠近树顶的位置, 而我们又想多处理一些错误, 那就更加繁琐了. 幸运的是, 还有一种正确的做法:

ptree pt;
pt.put("pi", 3.14159);                // put double
double pi = pt.get<double>("pi");     // get double

没有比这更简单的了. 基本上有两族成员函数, get 和 put, 它们提供对树中存储数据(无论是否为直接子节点)的直观访问.

获取数据的三种方式

get 有三个版本: get, get (默认值版本) 和 get_optional, 它们的失败处理策略不同. 所有版本都接受路径说明符, 用于确定在哪个键中查找值. 它可以是单个键, 也可以是指向键的路径, 路径元素之间用特殊字符分隔(默认为 '.'). 例如 debug.logging.errorlevel 可能是以点为分隔符的有效路径.

  1. 抛出异常的版本 (get):

    ptree pt;
/* ... */
float v = pt.get<float>("a.path.to.float.value");

    此调用在树中定位相应节点, 并尝试将其数据字符串转换为 float 值. 若失败则抛出异常. 若路径不存在, 抛出的将是 ptree_bad_path 异常; 若值无法转换, 抛出的则是 ptree_bad_data. 两者均派生自 ptree_error, 以便统一处理.

  2. 默认值版本 (get):

    ptree pt;
/* ... */
float v = pt.get("a.path.to.float.value", -1.f);

    它与上面的做法相同, 但若失败, 将返回由第二个参数(此处为 -1.f)指定的默认值而不是抛出异常. 这在希望允许省略某些键的常见场景中非常有用. 注意: 抛出异常版本所需的类型说明在此通常不必写出, 因为类型已由默认值参数确定.

  3. 可选值版本 (get_optional):

    ptree pt;
/* ... */
boost::optional<float> v = pt.get_optional<float>("a.path.to.float.value");

    此版本使用 boost::optional 类处理提取失败. 提取成功时, 返回以提取值初始化的 boost::optional; 否则返回未初始化的 boost::optional.

要从这棵树本身(而非某个子键)取值, 使用 get_value, get_value (默认值版本) 和 get_value_optional. 它们与 get 函数语义相同, 只是不接受 path 参数. 不要调用 get 并传入空 path 来实现这一点, 因为那样会尝试提取名为空的子键的内容.

要使用默认 '. 之外的分隔字符, 需要显式构造一个 path 对象. ptree 的 path 类型是 string_path 的实例化, 因此引用它最简单的方式是 ptree::path_type. 这样你就可以使用键中带点的树:

typedef ptree::path_type path;
pt.get<float>(path("p.a.t.h/t.o/v.a.l.u.e", '/'));
pt.get(path("p.a.t.h/t.o/v.a.l.u.e", '/'), 0, NULL);
pt.get_optional<std::string>(path("p.a.t.h/t.o/v.a.l.u.e", '/'));

注意: PropertyTree 预发布版本中接受分隔字符的 get 和 get_optional 特殊重载已被移除, 原因是这些重载与每次调用的数据转换器相冲突.

写入数据的两种方式

作为 get 的补充, 还有 put 和 add. 与 get 不同, 它们各自只有一个变体, 因为添加数据时无需处理值缺失的情况. 若提供的值无法转换为树的数据类型, 这些函数将抛出 ptree_bad_data.

ptree pt;
pt.put("a.path.to.float.value", 3.14f);
// Overwrites the value
pt.put("a.path.to.float.value", 2.72f);
// Adds a second node with the new value.
pt.add("a.path.to.float.value", 3.14f);

调用 put 会在指定路径插入新值, 这样对同一路径调用 get 即可取回它. 此外, put 会在路径遍历过程中插入缺失的路径元素. 例如, 在空树上调用 put("key1.key2.key3", 3.14f) 将插入三个新子节点: key1, key1.key2 和 key1.key2.key3. 最后一个将得到字符串 "3.14" 作为数据, 前两个的数据字符串为空. put 总是把新键插到现有序列的末尾. put 与 add 的区别在于: put 会覆盖已有值(如果存在), 而 add 即使指定路径已存在节点也会创建新节点来保存该值.

与 get_value 类似, 还有一个 put_value 函数. 它对本属性树的作用, 相当于 put 对其子节点的作用. 因此它不接受 path:

ptree pt;
pt.put_value(3.14f);

不存在 add_value 函数.
