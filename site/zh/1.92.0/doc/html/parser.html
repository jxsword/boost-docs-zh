设计理由

引言

Boost.Parser 是一个解析器组合子库. 也就是说, 它由一组底层原始解析器, 以及可用于将这些解析器组合成更复杂解析器的操作组成.

有一些原始解析器用于解析 epsilon (空字符串)、char、int、float 等.

还有一些操作可以将解析器组合成新的解析器. 例如, Kleene 星号操作接受一个已有的解析器 p, 并创建一个匹配零个或多个 p 所匹配内容的新解析器. 组合操作既使用可调用对象, 也使用运算符重载. 例如, operator*() 用于 Kleene 星号, 你也可以写 repeat(n)[p] 来创建恰好重复 n 次 p 的解析器.

Boost.Parser 还试图兼容人们从解析代码中获取解析结果的多种常见方式. 某些解析最适合通过返回一个表示解析结果的对象来完成. 另一些解析最适合通过填充已有的数据结构来完成. 还有一些解析最适合通过解析大文档的小片段, 并在子解析器完成时通过回调报告其结果来完成. Boost.Parser 兼容所有这些工作方式, 甚至可以在不重写任何代码的情况下进行基于回调或不基于回调的解析 (只需将顶层调用从 parse() 改为 callback_parse()).

Boost.Parser 的所有公开接口都支持哨兵与范围, 就像 std::ranges 中的接口一样.

Boost.Parser 从头到尾都感知 Unicode. 当你解析 char 的范围时, Boost.Parser 不假定任何特定编码——既不是 Unicode, 也不是任何其他编码. 解析非纯 char 的输入时, 则假定输入为 Unicode. 在感知 Unicode 的代码路径中, 所有解析都通过匹配码点完成. 这意味着你可以将 UTF-8 字符串作为输入或在解析器内部传入 Boost.Parser, 并发生正确的匹配. 例如, 如果你的解析器试图匹配 char '\xcc' 的重复 (这是一个 UTF-8 序列的前导字节, 如果后面没有跟随合适的 UTF-8 码元, 则是格式错误的 UTF-8), 它将不会匹配 "\xcc\x80" (码点 U+0300 的 UTF-8) 的开头. Boost.Parser 知道匹配必须按完整码点进行, 因此它将 char '\xcc' 解释为码点 U+00CC.

正确地进行错误报告很重要, 让错误易于理解也很重要, 这对最终用户尤其如此. Boost.Parser 产生的运行期解析错误消息与使用 GCC 和 Clang 编译时得到的诊断非常相似 (它甚至支持不会导致解析失败警告). 与诊断相关联的确切标记可以报告给用户, 同时引用所在行, 并用标记直接指向该标记. Boost.Parser 会为你处理好这些; 你的解析器不需要包含任何特殊代码. 当然, 如果默认的错误处理器不符合你的需求, 你也可以完全替换它.

调试复杂解析器可能是一场真正的噩梦. Boost.Parser 让获取整个解析过程的跟踪变得轻而易举, 跟踪中带有易于阅读 (且非常详细) 的指示, 标明每个部分在解析中的位置、解析产生的值的状态等. 同样, 你无需为此编写任何代码——只需向 parse() 传递一个参数即可.

在 C++ 中, 依赖管理仍然是一场噩梦, 因此 Boost.Parser 可以作为一个纯粹独立的库使用, 不依赖 Boost.
