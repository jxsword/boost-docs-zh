配置与可选特性

Boost.Parser 可以完全独立使用. 如果 Boost 可用, Boost 提供的额外功能也可用.

默认情况下, Boost.Parser 完全可以独立使用. 唯一需要显式选择加入的 Boost 用途是 Boost.Hana. 如果您开启 Hana 的使用, Boost.Parser 中通篇使用的元组类型将是 boost::hana::tuple, 而不是 std::tuple. 要启用此功能, 只需定义 BOOST_PARSER_USE_HANA_TUPLE. Boost.Hana 的元组要好得多, 因为它有一个 operator[], 还有大量非常有用的算法; 在教程和示例中您会到处看到这个运算符的使用. 我鼓励您使用 Hana 元组, 但我也明白, 用它来替代 std::tuple 这种做法并不常见, 后者是 C++ 的词汇表模板, 因此默认仍使用它.

重要

Boost.Parser 定义了一个模板别名 boost::parser::tuple (默认情况下使用的正是它), 而 boost::hana::tuple 则用于定义了 std::tuple 的情况下. BOOST_PARSER_DISABLE_HANA_TUPLE您可以通过使用 boost::parser::tuple 来让代码稍微面向未来一些, 这样无论 BOOST_PARSER_DISABLE_HANA_TUPLE 是否被定义, 代码都是良构的. 出于同样的原因, Boost.Parser 还提供了一个通用的 boost::parser::get, 它对这两种元组都适用 (因为 std::tuple 没有 operator[], 而 boost::hana::tuple 不能配合 std::get 使用).

Boost 头文件是否存在是通过 __has_include() 来检测的. 当检测到 Boost 时, 会使用所有典型的 Boost 约定; 否则使用非 Boost 的替代方案. 这适用于 BOOST_ASSERT 与 assert 的取舍, 以及使用 Boost.TypeIndex 还是 std::typeinfo 来打印类型名.

注释

如果您想禁用 C 宏 assert 的使用, 请定义 BOOST_DISABLE_ASSERTS. 无论 BOOST_ASSERT 是否可用, 这一点都成立.

重要

Boost.Parser 对所有使用可选 Boost 特性的函数和类型的定义都包裹在内联命名空间中; 该内联命名空间的名称取决于是否使用了 Boost 实现. 因此, 如果一个编译单元可以使用 Boost.TypeIndex, 而另一个编译单元必须使用 std::typeinfo, 也不会产生 ODR 违规. 例外情况是 BOOST_ASSERT/assert 的使用; 断言宏本质上是 ODR 陷阱.

Boost.Parser 在许多情况下会自动把聚合类型 struct 当作元组来对待. 这背后有一些元编程逻辑, 该逻辑对所能处理的 struct 的大小有一个硬性上限. 有一个配置宏 BOOST_PARSER_MAX_AGGREGATE_SIZE 可以调整, 以防默认值太小. 注意, 大幅调高该值会显著增加编译时间. 另外, MSVC 在处理大值时似乎比较吃力; 我在 MSVC 上成功将该值设为 50, 但 100 则完全破坏了 MSVC 构建.

Boost.Parser 内部使用 std::optional 和 std::variant. 这一点无法改变. 不过, 当 Boost.Parser 因解析而生成值时 (参见 属性生成), 如果您告诉它这样做, 它可以把这些值放入其他实现的 optional 和/或 variant 中. 您可以通过特化相关的变量模板来告诉它哪些模板可用作 optional 或 variant. 例如, 下面是告诉 Boost.Parser boost::optional 是一个 optional 类型的方法:

template<typename T>
constexpr bool boost::parser::enable_optional<boost::optional<T>> = true;

下面是对 boost::variant2::variant 执行相同操作的方法:

template<typename... Ts>
constexpr bool boost::parser::enable_variant<boost::variant2::variant<Ts...>> = true;

用作 optional 的模板所需满足的要求非常简单, 因为 Boost.Parser 对它几乎只做赋值操作. 对于一个类型 O 而言, 要成为可用的 optional, 您必须能够向 O 赋值, 并且 O 必须拥有一个 operator*, 其返回所存储的值, 或返回对所存储值的 (可能带 cv 限定符的) 引用.

对于 variant, 要求更简单; variant 类型只需可赋值即可.

注释

受 enable_variant 影响的唯一事项是打印. 如果您的 variant 模板仅用 std::cout << v 就能打印 (其中 v 显然是一个 variant), 那么您无需为您的 variant 模板定义 enable_variant.

Boost.Parser 大量使用 std::ranges::subrange. 然而, C++17 中没有与之等价的特性. 因此, 对于 C++17 构建有一个 boost::parser::subrange 供 C++17 构建使用. 为了在代码中透明地切换这两者, 同时保持 CTAD 可用, Boost.Parser 定义了 BOOST_PARSER_SUBRANGE. 这是模板的名字, 因此如果您在自己的代码中使用它, 可以像 BOOST_PARSER_SUBRANGE<I> 这样来实例化.

Boost.Parser 允许您通过向 trace::on 传递 parse() 来调试您的解析器. 有时, 您的运行环境中没有终端. 如果您在 Visual Studio 调试器中运行 Boost.Parser 代码, 可以通过定义 BOOST_PARSER_TRACE_TO_VS_OUTPUT, 让跟踪输出显示在 Visual Studio 调试器的输出面板中, 而不是终端里.
