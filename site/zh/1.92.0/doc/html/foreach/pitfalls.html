陷阱

本节描述 BOOST_FOREACH 的一些常见陷阱.

带逗号的类型

由于 BOOST_FOREACH 是宏, 它必须恰好有两个实参, 且恰好由一个逗号分隔. 这并不总是方便, 尤其当循环变量的类型是模板时. 考虑尝试遍历一个 std::map:

std::map<int,int> m;

// ERROR! Too many arguments to BOOST_FOREACH macro.
BOOST_FOREACH(std::pair<const int,int> p, m) // ...

一种解决办法是使用 typedef.

std::map<int,int> m;
typedef std::pair<const int,int> pair_t;

BOOST_FOREACH(pair_t p, m) // ...

另一种解决办法是预先声明循环变量:

std::map<int,int> m;
std::pair<const int,int> p;

BOOST_FOREACH(p, m) // ...

提升与迭代器失效

在底层, BOOST_FOREACH 使用迭代器遍历元素序列. 循环执行之前, end 迭代器被缓存到一个局部变量中. 这称为 提升, 是一项重要的优化. 但它假定序列的 end 迭代器是稳定的. 通常确实如此, 但如果我们在遍历序列的同时通过添加或删除元素来修改序列, 就可能搬起石头砸自己的脚.

Consider the following code: 

std::vector<int> vect(4, 4);
BOOST_FOREACH(int i, vect)
{
    vect.push_back(i + 1);
}

这段代码可以编译, 但具有未定义行为. 因为它在逻辑上等价于以下代码:

std::vector<int> vect(4, 4);
for(std::vector<int>::iterator it1 = vect.begin(), it2 = vect.end();
    it1 != it2; ++it1)
{
    int i = *it1;
    vect.push_back(i + 1); // Oops! This invalidates it1 and it2!
}

对 vect.push_back() 的调用会使 vect 的所有迭代器失效, 包括 it1 和 it2. 循环的下一次迭代将使用失效的迭代器. 这是个坏消息.

这个故事告诉我们的道理是: 在向正在遍历的序列中添加或删除元素之前要三思. 如果这样做可能导致迭代器失效, 就不要做. 改用普通的 for 循环.
