可扩展性

如果我们想用 BOOST_FOREACH 遍历某种新的集合类型, 必须"教会" BOOST_FOREACH 如何与我们的类型交互. 由于 BOOST_FOREACH 构建在 Boost.Range 之上, 扩展 Boost.Range 才能扩展 BOOST_FOREACH. 扩展 Boost.Range 一节详细探讨了这个主题.

下面是一个扩展 BOOST_FOREACH 以遍历子字符串类型的示例, 该类型包含两个指向 std::string 的迭代器.

namespace my
{
    // sub_string: part of a string, as delimited by a pair
    // of iterators
    struct sub_string
    {
        std::string::iterator begin;
        std::string::iterator end;

        /* ... implementation ... */
    };

    // Add overloads of range_begin() and range_end() in the
    // same namespace as sub_string, to be found by Argument-Dependent Lookup.

    inline std::string::iterator range_begin( sub_string & x )
    {
        return x.begin;
    }

    inline std::string::iterator range_end( sub_string & x )
    {
        return x.end;
    }

    // Also add overloads for const sub_strings. Note we use the conversion
    // from string::iterator to string::const_iterator here.

    inline std::string::const_iterator range_begin( sub_string const & x )
    {
        return x.begin;
    }

    inline std::string::const_iterator range_end( sub_string const & x )
    {
        return x.end;
    }
}

namespace boost
{
    // specialize range_mutable_iterator and range_const_iterator in namespace boost
    template<>
    struct range_mutable_iterator< my::sub_string >
    {
        typedef std::string::iterator type;
    };

    template<>
    struct range_const_iterator< my::sub_string >
    {
        typedef std::string::const_iterator type;
    };
}

既然我们已经就我们的类型"教会"了 Boost.Range (进而也教会了 BOOST_FOREACH), 现在就可以用 BOOST_FOREACH 来遍历我们的 sub_string 类型了.

my::sub_string substr;
BOOST_FOREACH( char ch, substr )
{
    // Woo-hoo!
}

扩展 BOOST_FOREACH 时有一些可移植性问题需要注意. 务必查看 可移植性 一节. 特别是, 如果你的编译器不支持实参依赖查找, Boost.Range 可移植性 一节提供了一些推荐的变通办法.

让 BOOST_FOREACH 支持不可拷贝的序列类型

对于不可拷贝的序列类型, 我们需要告诉 BOOST_FOREACH 不要尝试拷贝. 如果我们的类型继承自 boost::noncopyable, 则无需进一步操作. 否则, 必须如下特化 boost::foreach::is_noncopyable<> 模板:

class noncopy_vector
{
    // ...
private:
    noncopy_vector( noncopy_vector const & ); // non-copyable!
};

namespace boost { namespace foreach
{
    template<>
    struct is_noncopyable< noncopy_vector >
      : mpl::true_
    {
    };
}}

达到同样效果的另一种方式是重载全局 boost_foreach_is_noncopyable() 函数. 这种做法的优点是对较老的编译器也可移植.

// At global scope...
inline boost::mpl::true_ *
boost_foreach_is_noncopyable( noncopy_vector *&, boost::foreach::tag )
{
    return 0;
}
提示

尽管我们必须告诉 BOOST_FOREACH 我们的类型不可拷贝, 这并不意味着 BOOST_FOREACH 总是会拷贝我们的序列类型. 显然, 这样做的代价很高, 有时甚至是错误的. BOOST_FOREACH 对于何时拷贝、何时不拷贝相当聪明. is_noncopyable<> 特征用于省略拷贝, 该拷贝位于可能永远不会执行的分支上.

为轻量代理序列类型优化 BOOST_FOREACH

在某些编译器上, BOOST_FOREACH 有时必须走稍慢的代码路径, 以保证对存储在临时对象中的序列的正确处理. 它会自问: "我要不要拷贝这个对象?" 稍后又会问: "我到底拷贝了没有?" 对于某些类型的序列, 这是多余的. 考虑一个由一对简单迭代器构成的序列. 大费周章地避免拷贝它毫无意义, 因为拷贝它非常廉价.

一对迭代器是轻量代理的一个例子. 它并不存储序列的值, 而是存储指向这些值的迭代器. 这意味着遍历代理对象的副本与使用对象本身会得到相同的结果. 对于这类类型, BOOST_FOREACH 提供了一个钩子, 让我们告诉它不必担心拷贝的开销. 这可以使循环执行稍快一些. 只需如下特化 boost::foreach::is_lightweight_proxy<> 特征:

struct sub_string
  : boost::iterator_range< std::string::iterator >
{
    // ...
};

namespace boost { namespace foreach
{
    template<>
    struct is_lightweight_proxy< sub_string >
      : mpl::true_
    {
    };
}}

或者, 我们可以通过重载全局 boost_foreach_is_lightweight_proxy() 函数来达到同样的效果, 如下所示:

// At global scope...
inline boost::mpl::true_ *
boost_foreach_is_lightweight_proxy( sub_string *&, boost::foreach::tag )
{
    return 0;
}

这种方法对较老的编译器也可移植.
