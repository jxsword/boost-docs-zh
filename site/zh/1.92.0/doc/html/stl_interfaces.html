设计理由

引言

编写 STL 迭代器、视图与容器出人意料地困难. 有很多地方可能悄悄出错. 它还非常繁琐, 这当然也使其容易出错.

迭代器拥有大量 typedef 与操作, 尽管给定迭代器的所有操作其实都可以用至多四个操作 (通常只有三个) 实现. 编写所有其余操作会产生外观极为相似、难以评审的代码, 并且几乎必然要求你为每个迭代器编写全覆盖的测试.

编写 std::ranges 中的那些视图类型同样费时费力, 鉴于每种视图类型的大部分 API 都可以从 begin() 与 end() 推导得到. C++20 提供了一个恰好完成此任务的模板 std::ranges::view_interface; Boost.STLInterfaces 提供了对 C++20 之前标准友好的实现.

由于不同编译器为其 C++20 视图适配器实现 operator| 支持的方式互不一致, 尝试编写一个可跨多个 C++ 版本移植、甚至在以 C++20 模式构建的多个编译器之间移植的视图适配器格外棘手. Boost.STLInterfaces 提供了一个类型 boost::stl_interfaces::range_adaptor_closure, 它与 C++23 的 std::range_adaptor_closure 兼容, 并且也能用于更早版本的 C++. Boost.STLInterfaces 还提供了一些辅助模板, 使得编写带 operator| 支持的视图适配器容易得多.

最令人生畏的是编写满足标准中容器要求的类型或模板的任务. Boost.STLInterfaces 提供了另一个名为 sequence_container_interface 的模板, 可大幅减少实现与测试负担.

注释

提供了 iterator_interface 与 sequence_container_interface 的 C++20 版本 (C++20 提供 std::view_interface). 这些是使用 C++20 概念 (concept) 约束的模板, 位于 boost::stl_interfaces::v2 命名空间中. iterator_interface 还有一个 C++23 版本, 它使用推导 this 而非 CRTP. 如果不做任何设置, 根据编译器的语言支持, 你会得到内联的最新 vN 命名空间.

快速示例

下面是库中迭代器部分的示例. 假设我们想制作一个随机访问迭代器, 表示通过重复一个较短字符串构造的任意长度的字符串. 把这个迭代器称为 repeated_chars_iterator. 下面是它的实际使用:

repeated_chars_iterator first("foo", 3, 0); // 3 is the length of "foo", 0 is this iterator's position.
repeated_chars_iterator last("foo", 3, 7);  // Same as above, but now the iterator's position is 7.
std::string result;
std::copy(first, last, std::back_inserter(result));
assert(result == "foofoof");

标准库中没有任何东西能为我们提供这种行为, 所以我们必须自己编写. 本库力求把我们编写的内容从这个:

struct repeated_chars_iterator
{
    using value_type = char;
    using difference_type = std::ptrdiff_t;
    using pointer = char const *;
    using reference = char const;
    using iterator_category = std::random_access_iterator_tag;

    constexpr repeated_chars_iterator() noexcept :
        first_(nullptr),
        size_(0),
        n_(0)
    {}
    constexpr repeated_chars_iterator(
        char const * first,
        difference_type size,
        difference_type n) noexcept :
        first_(first),
        size_(size),
        n_(n)
    {}

    constexpr reference operator*() const noexcept
    {
        return first_[n_ % size_];
    }

    constexpr value_type operator[](difference_type n) const noexcept
    {
        return first_[(n_ + n) % size_];
    }

    constexpr repeated_chars_iterator & operator++() noexcept
    {
        ++n_;
        return *this;
    }
    constexpr repeated_chars_iterator operator++(int)noexcept
    {
        repeated_chars_iterator retval = *this;
        ++*this;
        return retval;
    }
    constexpr repeated_chars_iterator & operator+=(difference_type n) noexcept
    {
        n_ += n;
        return *this;
    }

    constexpr repeated_chars_iterator & operator--() noexcept
    {
        --n_;
        return *this;
    }
    constexpr repeated_chars_iterator operator--(int)noexcept
    {
        repeated_chars_iterator retval = *this;
        --*this;
        return retval;
    }
    constexpr repeated_chars_iterator & operator-=(difference_type n) noexcept
    {
        n_ -= n;
        return *this;
    }

    friend constexpr bool operator==(
        repeated_chars_iterator lhs, repeated_chars_iterator rhs) noexcept
    {
        return lhs.first_ == rhs.first_ && lhs.n_ == rhs.n_;
    }
    friend constexpr bool operator!=(
        repeated_chars_iterator lhs, repeated_chars_iterator rhs) noexcept
    {
        return !(lhs == rhs);
    }
    friend constexpr bool operator<(
        repeated_chars_iterator lhs, repeated_chars_iterator rhs) noexcept
    {
        return lhs.first_ == rhs.first_ && lhs.n_ < rhs.n_;
    }
    friend constexpr bool operator<=(
        repeated_chars_iterator lhs, repeated_chars_iterator rhs) noexcept
    {
        return lhs == rhs || lhs < rhs;
    }
    friend constexpr bool operator>(
        repeated_chars_iterator lhs, repeated_chars_iterator rhs) noexcept
    {
        return rhs < lhs;
    }
    friend constexpr bool operator>=(
        repeated_chars_iterator lhs, repeated_chars_iterator rhs) noexcept
    {
        return rhs <= lhs;
    }

    friend constexpr repeated_chars_iterator
    operator+(repeated_chars_iterator lhs, difference_type rhs) noexcept
    {
        return lhs += rhs;
    }
    friend constexpr repeated_chars_iterator
    operator+(difference_type lhs, repeated_chars_iterator rhs) noexcept
    {
        return rhs += lhs;
    }
    friend constexpr repeated_chars_iterator
    operator-(repeated_chars_iterator lhs, difference_type rhs) noexcept
    {
        return lhs -= rhs;
    }
    friend constexpr difference_type operator-(
        repeated_chars_iterator lhs, repeated_chars_iterator rhs) noexcept
    {
        return lhs.n_ - rhs.n_;
    }

private:
    char const * first_;
    difference_type size_;
    difference_type n_;
};

(这是很多代码!) 变成这个:

struct repeated_chars_iterator : boost::stl_interfaces::iterator_interface<
#if !BOOST_STL_INTERFACES_USE_DEDUCED_THIS
                                     repeated_chars_iterator,
#endif
                                     std::random_access_iterator_tag,
                                     char,
                                     char>
{
    constexpr repeated_chars_iterator() noexcept :
        first_(nullptr),
        size_(0),
        n_(0)
    {}
    constexpr repeated_chars_iterator(
        char const * first, difference_type size, difference_type n) noexcept :
        first_(first),
        size_(size),
        n_(n)
    {}

    constexpr char operator*() const noexcept { return first_[n_ % size_]; }
    constexpr repeated_chars_iterator & operator+=(std::ptrdiff_t i) noexcept
    {
        n_ += i;
        return *this;
    }
    constexpr auto operator-(repeated_chars_iterator other) const noexcept
    {
        return n_ - other.n_;
    }

private:
    char const * first_;
    difference_type size_;
    difference_type n_;
};

啊, 这样好多了. repeated_chars_iterator 的这两个定义具有相同的语义与性能特征. 只是写第二个的代码量少得多, 而且对新手更友好.

注释

Boost.STLInterfaces 的 iterator_interface 实现了满足 C++20 迭代器概念 (concept) 的迭代器.
