版本历史

Boost 1.92

  • 新特性 (backmp11):

    • 为日志支持提供观察者 API (#220)

    • 无需转换即把 Kleene 事件转发给动作和守卫 (#229)

    • 确保基本异常保证并向调用者传播异常 (#221)

    • 为 Boost.Serialization, Boost.JSON 和 nlohmann/json 提供反射 API 与序列化支持 (#197)

    • 重新设计终止与中断状态的处理, 并提供 machine_state 枚举 (#244)

    • 可配置的事件池与内联存储 (#239)

    • API 参考与示例现已可用

  • 缺陷修复 (backmp11):

    • 状态机在未运行时仍处理事件 (#198)

  • 破坏性变更 (backmp11):

    • process_event(…​) 中的事件不再自动入队, 以减少内存占用; 请在动作中使用 enqueue_event(…​) (#178)

    • 后端不再把构造函数参数转发给前端, 前端必须可默认构造. 要使用自定义构造函数, 请在后端中定义 (#232)

    • 已弃用的 API process_queued_events() 与 process_single_queued_event() 被移除, 请改用 process_event_pool(…​)

    • 默认活动状态切换策略被设为 "after source exit", 以符合 UML 规范. 其他选项不符合 UML, 将被移除 (#222)

    • 后端使用自己的 process_result 类型并采用新的枚举值, 而不再别名引用 back 命名空间的枚举. 旧的枚举值已弃用 (#242) 并将被移除

  • fix(back, back11): 正交区域中事件延迟导致的无限递归 (1.78 引入的回归) (#184)

Boost 1.91

  • 新特性 (backmp11):

    • 改进分层状态机中对 deferred_events 属性的支持 (#173)

    • 支持使用 deferred_events 属性进行条件延迟 (#155)

    • 简化的仿函数签名 (#175)

    • 把排队事件与延迟事件合并为单一事件池 (#168)

    • 事件池中事件的小对象优化 (#172)

    • 通过 flat_fold 分发策略提升运行期性能 (#180)

    • 进一步优化编译, 与 1.90 版相比编译时间最多加快 25%, 内存消耗更低

  • 缺陷修复 (backmp11):

    • FSM 在对 on_entry(…​) 和 on_exit(…​) 的调用中类型不正确 (#167)

    • 完成事件触发过于频繁 (#166)

    • 分层状态机中的转移未被正确选择 (favor_compile_time) (#200)

    • state_machine 无法移动 (#205)

  • 破坏性变更 (backmp11): 对事件池的直接访问从 public 改为 protected, 因为在库代码之外操纵它会导致未定义行为.

Boost 1.90

  • feat(backmp11): 新后端 backmp11, 需要 C++ 17

  • fix(back): boost::any 无法再用作 Kleene 事件 (#87)

  • feat: 文档已翻新, 现使用 Antora 构建

Boost 1.85

  • 后端更新 (back11). 需要 C++ 11. 文档现已以其为默认.

  • 新前端 (PlantUML). 需要 C++ 20

  • 若干缺陷修复

Boost 1.72

  • 从 develop 分支合并了延迟事件的新实现

  • 若干缺陷修复

Boost 1.57

  • 修复了 BOOST_MSM_EUML_EVENT_WITH_ATTRIBUTES (在 1.56 中损坏).

  • 修复了 execute_queued_events, 新增 execute_single_queued_event

  • 修复了未使用变量的警告

Boost 1.56

  • 缺陷修复: 抛出异常时的 no_transition.

  • 缺陷修复: Trac 9280

  • 缺陷修复: eUML 中命名空间名称不完整

Boost 1.55

  • 新特性: 中断状态现在支持用一组事件来结束中断

  • 缺陷修复: Trac 8686.

Boost 1.54

  • 缺陷修复: 在 favor_compile_time 策略下出口点损坏.

  • 缺陷修复: 复制操作破坏子子状态机的出口点.

  • 缺陷修复: Trac 8046.

从 V2.23 到 V2.24 (Boost 1.51)

  • 支持 boost::any 或 kleene 作为可接受的事件.

  • 缺陷修复: 使用 fsm 内部表与 none (复合) 事件时的编译器错误.

  • 缺陷修复: euml::defer_ 导致的栈溢出.

从 V2.22 到 V2.23 (Boost 1.50)

  • eUML : 为仅以转移表形式定义的 eUML 前端提供更好的语法. 注意: 破坏性变更!

  • 缺陷修复: 图构建只有在 initial_state 定义为序列时才能工作

  • 缺陷修复: 为 Terminate 或 Interrupt 状态定义的标志不再破坏这些状态的阻止功能.

  • 缺陷修复: 来自多个区域的多个延迟事件并非在所有情况下都能工作.

  • 缺陷修复: 访问器以传值方式被传给子状态机.

  • 缺陷修复: no_transition 对向自身发送事件的子状态机未被调用.

  • 修复了 gcc 的警告

从 V2.21 到 V2.22 (Boost 1.48)

  • eUML: 新增更简单的事件重处理方式: process(event_) 和 reprocess()

  • 重写了内部转移表. 存在一些缺陷 (子子状态机的内部转移表递归失败) 和一个缺失特性 (主状态机未使用的内部转移表).

  • 若干缺陷修复

    • 把 favor_compile_time 策略回退到 Boost 1.46 的状态

    • none 事件现在可以从任何其他事件转换而来

    • eUML 与伪出口状态

    • 修复了 Flag_AND 不工作的问题

    • 修复了在同一子状态机中导致同一事件被多次处理的罕见缺陷, 该子状态机的转移表同时包含该事件及其基事件.

    • gcc 关于未使用变量的警告

  • 破坏性变更: 新的内部转移表特性带来一处小的破坏性变更. 在子状态机中, 使用 internal_transition_table 声明的内部表的守卫 / 动作的 "Fsm" 模板参数现在是该子状态机, 而不是更高层的状态机. 在更高层状态机中使用内部行声明的内部转移保持其行为 ("Fsm" 参数是更高层状态机). 概括地说, 内部转移的 "Fsm" 参数是包含该转移的最近的状态机.

从 V2.20 到 V2.21 (Boost 1.47)

  • 在后端中新增了 stop() 方法.

  • Added partial support for Boost.Phoenix functors in eUML

  • 新增了选择 state switching 何时发生的可能.

  • 若干缺陷修复

    • Trac 5117, 5253, 5533, 5573

    • gcc 关于未使用变量的警告

    • favor_compile_time 后端策略的更好实现

    • eUML 与状态构造的缺陷

    • 不正确的 eUML 事件与状态宏

    • 传给直接入口状态的 on_entry 动作的事件类型不正确

    • 更多示例

从 V2.12 到 V2.20 (Boost 1.46)

  • 使用 mpl_graph 进行编译期状态机分析:

    • checking of region orthogonality.

    • search for unreachable states.

    • automatic region index search for pseudo entry or explicit entry states.

  • Boost.Parameter interface definition 用于 msm::back::state_machine<> 模板参数.

  • Possibility to provide a container 用于事件队列和延迟事件队列. 提供了基于更高效的 Boost.CircularBuffer 的策略实现.

  • msm::back::state_machine<>::is_flag_active 方法改为 const.

  • 新增了 enqueue events 以实现延迟处理的可能性.

  • 若干缺陷修复

    • Trac 4926

    • 使用 Defer 仿函数时的栈溢出

    • 子状态机的匿名转移未对初始状态调用

从 V2.10 到 V2.12 (Boost 1.45)

  • 支持 serialization

  • Possibility to use normal functors (来自 Functor 前端) 也可在 eUML 中使用.

  • New constructors 的子状态 / 子状态机可作为参数. 这允许向子状态机的构造函数传递参数.

  • 若干缺陷修复

从 V2.0 到 V2.12 (Boost 1.44)

  • 全新文档

  • 内部转移. 既可作为转移表的一部分, 也可使用状态的内部转移表

  • 提升分发与复制速度

  • new row types 用于基本前端

  • 新的 eUML 语法, 更好的属性支持, 以及让开发者生活更轻松的宏. 连 VC8 似乎都更喜欢它了.

  • 以分发速度为代价缩短编译时间的新策略

  • 支持基事件

  • 可以选择初始事件
