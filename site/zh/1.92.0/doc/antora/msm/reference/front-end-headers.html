前端头文件

msm/front/common_states.hpp

该头文件包含用作状态或状态机基类的预定义类型:

  • default_base_state: 非多态的空类型.

  • polymorphic_state: 带虚析构函数的类型, 它使所有状态成为多态.

msm/front/completion_event.hpp

该头文件包含一个类型 none. 该类型在转移表中有几种含义:

  • 作为动作或守卫: 表示没有动作或守卫

  • 作为目标状态: 表示该转移是内部转移

  • 作为事件: 该转移是匿名 (完成) 转移

Row

定义

template <class Source,class Event,class Target,class Action,class Guard> Row

标签

每个特化中 row_type_tag 的定义都不同:

  • 给出全部 5 个模板参数表示一条带动作和守卫的普通转移: typedef row_tag row_type_tag;

  • Row<Source,Event,Target,none,none> 一条不带动作或守卫的普通转移: typedef _row_tag row_type_tag;

  • Row<Source,Event,Target,Action,none> 一条不带守卫的普通转移: typedef a_row_tag row_type_tag;

  • Row<Source,Event,Target,none,Guard> 一条不带动作的普通转移: typedef g_row_tag row_type_tag;

  • Row<Source,Event,none,Action,none> 一条不带守卫的内部转移: typedef a_irow_tag row_type_tag;

  • Row<Source,Event,none,none,Guard> 一条不带动作的内部转移: typedef g_irow_tag row_type_tag;

  • Row<Source,Event,none,none,Guard> 一条带动作和守卫的内部转移: typedef irow_tag row_type_tag;

  • Row<Source,Event,none,none,none> 一条不带动作或守卫的内部转移: typedef _irow_tag row_type_tag;

方法

与其他前端一样, Row 实现了调用动作和守卫所需的两个静态函数. 每个函数的参数包括处理事件的 (最深层) 状态机、事件本身、源状态和目标状态, 以及状态机中包含的所有状态.

msm/front/states.hpp

该头文件为基本前端 (或与其他前端混用) 提供各种状态 (状态机除外).

类型

该头文件提供以下类型:

no_sm_ptr

已弃用: 状态的默认策略. 它表示状态不需要保存指向其所属状态机的指针.

sm_ptr

已弃用: 状态策略. 它表示状态需要保存指向其所属状态机的指针. 后端看到该标志时, 会调用 set_sm_ptr(fsm*) 并把自己作为参数传入.

state

简单状态的基本类型. 继承该类型来定义一个简单状态. 如果你想让自己的状态 (以及具体状态机中使用的所有其他状态) 继承某个用于日志记录或提供公共行为的基本类型, 就需要第一个参数.

template<class Base = default_base_state,class SMPtrPolicy = no_sm_ptr> state

terminate_state

终止状态的基本类型. 继承该类型来定义一个终止状态. 如果你想让自己的状态 (以及具体状态机中使用的所有其他状态) 继承某个用于日志记录或提供公共行为的基本类型, 就需要第一个参数.

template<class Base = default_base_state,class SMPtrPolicy = no_sm_ptr> terminate_state

interrupt_state

中断状态的基本类型. 中断状态会阻止一切后续事件处理, 直到发出 EndInterruptEvent. 继承该类型来定义一个终止状态. 第一个参数是结束中断的事件的名称. 如果你想让自己的状态 (以及具体状态机中使用的所有其他状态) 继承某个用于日志记录或提供公共行为的基本类型, 就需要第二个参数.

EndInterruptEvent 也可以是一个事件序列: mpl::vector<EndInterruptEvent,EndInterruptEvent2>.

template<class EndInterruptEvent,class Base = default_base_state,

class SMPtrPolicy = no_sm_ptr> interrupt_state

explicit_entry

除了所期望的状态类型之外 还要继承该类型, 以使该状态可被直接进入. 模板参数给出该状态的区域 id (区域按 initial_state typedef 的顺序编号).

template <int ZoneIndex=-1> explicit_entry

entry_pseudo_state

入口伪状态的基本类型. 入口伪状态是预先定义的进入子状态机的入口, 并连接两条转移. 第一个参数是该状态进入的区域的 id (区域按 initial_state typedef 的顺序编号). 如果你想让自己的状态 (以及具体状态机中使用的所有其他状态) 继承某个用于日志记录或提供公共行为的基本类型, 就需要第二个参数.

template<int RegionIndex=-1,class Base = default_base_state,

文法

`transition table

转移表接受以下文法:

Stt := Row | (Stt ',' Stt)
Row := (Target '==' (SourcePlusEvent)) /* first syntax*/
       | ( (SourcePlusEvent) '==' Target ) /* second syntax*/
       | (SourcePlusEvent) /* internal transitions */
SourcePlusEvent := (BuildSource '+' BuildEvent)/* standard transition*/
                   | (BuildSource) /* anonymous transition */
BuildSource := state_tag | (state_tag '/' Action) | (state_tag '[' Guard ']')
            | (state_tag '[' Guard ']' '/' Action)
BuildEvent := event_tag | (event_tag '/' Action) | (event_tag '[' Guard ']')
            | (event_tag '[' Guard ']' '/' Action)

文法 Action 与 Guard 分别定义在 state_grammar.hpp 和 guard_grammar.hpp 中. state_tag 与 event_tag 分别继承自 euml_state (或其他状态变体) 与 euml_event. 例如, 以下声明是可能的:

target == source + event [guard] / action,
source + event [guard] / action == target,
source + event [guard] / (action1,action2) == target,
target == source + event [guard] / (action1,action2),
target == source + event,
source + event == target,
target == source + event [guard],
source + event [guard] == target,
target == source + event / action,
source + event /action == target,
source / action == target, /*anonymous transition*/
target == source / action, /*anonymous transition*/
source + event /action, /* internal transition*/

内部转移表

内部转移表接受以下文法:

IStt := BuildEvent | (IStt ',' IStt)

其中 BuildEvent 对内部转移表和标准转移表都有定义.

msm/front/euml/guard_grammar.hpp

该头文件包含上一节使用的 Guard 文法. 该文法虽长但相当简单:

Guard := action_tag | (Guard '&&' Guard)
        | (Guard '||' Guard) | ... /* operators*/
        | (if_then_else_(Guard,Guard,Guard)) | (function (Action,...Action))

支持大多数 C++ 运算符 (取地址除外). function 表示任何 eUML 预定义函数或任何自制函数 (使用 MSM_EUML_METHOD 或 MSM_EUML_FUNCTION). Action 是定义在 state_grammar.hpp 中的文法.

该头文件提供动作的文法, 以及用 eUML 构建状态的各种文法和函数.

动作文法

与守卫文法一样, 该文法支持相关的 C++ 运算符和 eUML 函数:

Action := action_tag | (Action '+' Action)
          | ('--' Action) | ... /* operators*/
          | if_then_else_(Guard,Action,Action) | if_then_(Action)
          | while_(Guard,Action)
          | do_while_(Guard,Action) | for_(Action,Guard,Action,Action)
          | (function(Action,...Action))
ActionSequence := Action | (Action ',' Action)

相关运算符有: ++ (前置/后置), — (前置/后置), 解引用,
(一元/二元), - (一元/二元), *, /, %, &(按位), | (按位), ^(按位), +=, -=, *=, /=, %=, <⇐, >>=, <<, >>, =, [].

属性

该文法用于给状态 (或状态机) 或事件添加属性: 其求值结果是一个 fusion::map. 可以使用两种形式:

  • attributes_ << no_attributes_

  • attributes_ << attribute_1 << …​ << attribute_n

属性可以是任何可默认构造的类型 (fusion 要求).

configure

该文法也有两种形式:

  • configure_ << no_configure_

  • configure_ << type_1 << …​ << type_n

该文法用于在一个语法内部创建:

  • 标志: configure_ << some_flag, 其中 some_flag 继承自 euml_flag<some_flag>, 或使用 BOOST_MSM_EUML_FLAG 定义.

  • 延迟事件: configure_ << some_event, 其中 some_event 继承自 euml_event<some_event>, 或使用 BOOST_MSM_EUML_EVENT 或 BOOST_MSM_EUML_EVENT_WITH_ATTRIBUTES 定义.

  • 配置 (消息队列, 手动延迟, 异常处理): configure_ << some_config, 其中 some_config 继承自 euml_config<some_config>. 目前有三个预定义对象 (位于 msm//front/euml/common.hpp):

    • no_exception: 禁用异常捕获

    • no_msg_queue: 禁用消息队列

    • deferred_events: 手动启用延迟事件处理

if_then_(False_(),/* some action never called */)

Int_<int value>

为转移或状态行为返回整数值的仿函数. 与所有常量一样, 只有仿函数形式存在, 因此必须加括号. 示例:

target_(m_ringing_cpt) = Int_<RINGING_TIME>() // RINGING_TIME is a constant

Char_<char value>

为转移或状态行为返回 char 值的仿函数. 与所有常量一样, 只有仿函数形式存在, 因此必须加括号. 示例:

// look for 'S' in event.m_song
[string_find_(event_(m_song),Char_<'S'>(),Size_t_<0>()) != Npos_<string>()]

Size_t_<size_t value>

为转移或状态行为返回 size_t 值的仿函数. 与所有常量一样, 只有仿函数形式存在, 因此必须加括号. 示例:

substr_(event_(m_song),Size_t_<1>()) // returns a substring of event.m_song

String_ < mpl::string >

为转移或状态行为返回字符串的仿函数. 与所有常量一样, 只有仿函数形式存在, 因此必须加括号. mpl::string 需要 boost >= 1.40.

示例:

// adds "Let it be" to fsm.m_src_container
push_back_(fsm_(m_src_container), String_<mpl::string<'Let','it ','be'> >())

Predicate_ < some_stl_compatible_functor >

该仿函数让一个 STL 仿函数与 eUML 兼容 (供算法使用). 这是必要的, 因为转移表中的一切都必须是 eUML 终端.

示例:

//equivalent to:
//std::accumulate(fsm.m_vec.begin(),fsm.m_vec.end(),1,std::plus<int>())== 1
accumulate_(begin_(fsm_(m_vec)),end_(fsm_(m_vec)),Int_<1>(),
            Predicate_<std::plus<int> >()) == Int_<1>())

process_

该函数通过在其上调用 process_event 把事件发送给最多 4 个状态机:

  • process_(some_event) : 在当前 (包含) 状态机中处理一个事件.

  • process_(some_event [,fsm1…​fsm4] ) : 在作为参数传入的 1-4 个状态机中处理同一事件.

process2_

该函数通过在其上调用 process_event 把事件发送给最多 3 个状态机, 并以第二个参数传入的数据复制构造事件:

  • process2_(some_event, some_data) : 在当前 (包含) 状态机中处理一个事件.

  • process2_(some_event, some_data [,fsm1…​fsm3] ) : 在作为参数传入的 1-3 个状态机中处理同一事件.

示例:

// processes NotFound on current state machine,
// copy-constructed with event.m_song
process2_(NotFound,event_(m_song))

给定以下定义:

BOOST_MSM_EUML_DECLARE_ATTRIBUTE(std::string,m_song)//declaration of m_song
NotFound (const string& data) // copy-constructor of NotFound

is_flag_

该函数通过在当前状态机或作为参数传入的状态机上调用 is_flag_active 来判断某个标志是否处于活动状态:

  • is_flag_(some_flag) : 在当前 (包含) 状态机上调用 is_flag_active.

  • is_flag_(some_flag, some_fsm) : 在作为参数传入的状态机上调用 is_flag_active.

defer_

该对象通过在当前状态机上调用 defer_event 来延迟当前事件. 示例:

Empty() + play() / defer_

explicit_(submachine-name,state-name)

用作转移的目标时, 导致从给定子状态机显式进入给定状态. 多个以逗号分隔的 explicit_ 作为目标表示一个分叉. 该状态必须已用 BOOST_MSM_EUML_EXPLICIT_ENTRY_STATE 如此声明.

entry_pt_(submachine-name,state-name)

从包含状态机出发用作转移的目标时, 导致使用给定的入口伪状态进入 submachine-name. 该状态必须已用 BOOST_MSM_EUML_ENTRY_STATE 声明为伪入口.

exit_pt_(submachine-name,state-name)

从包含状态机出发用作转移的源时, 导致使用给定的出口伪状态离开 submachine-name. 该状态必须已用 BOOST_MSM_EUML_EXIT_STATE 声明为伪出口.

MSM_EUML_FUNCTION

该宏基于一个自由函数, 创建一个 eUML 函数和一个供 Functor 前端使用的仿函数:

  • 第一个参数: 仿函数的名称

  • 第二个参数: 底层函数

  • 第三个参数: eUML 函数名

  • 第四个参数: 用于转移行为时的返回类型

  • 第五个参数: 用于状态行为 (入口/出口) 时的返回类型

注意, 该函数本身最多可接受 5 个参数.

示例:

MSM_EUML_FUNCTION(BinarySearch_,std::binary_search,binary_search_,bool,bool)

可以这样使用:

binary_search_(begin_(fsm_(m_var)),end_(fsm_(m_var)),Int_<9>())

MSM_EUML_METHOD

该宏基于一个方法, 创建一个 eUML 函数和一个供 Functor 前端使用的仿函数:

  • 第一个参数: 仿函数的名称

  • 第二个参数: 底层函数

  • 第三个参数: eUML 函数名

  • 第四个参数: 用于转移行为时的返回类型

  • 第五个参数: 用于状态行为 (入口/出口) 时的返回类型

注意, 该方法本身最多可接受 4 个参数 (比自由函数的 5 个少 1 个, 少掉的用于方法调用的对象).

示例:

struct Empty : public msm::front::state<> , public euml_state<Empty>
{
     void activate_empty() {std::cout << "switching to Empty " << std::endl;}
...
};
MSM_EUML_METHOD(ActivateEmpty_,activate_empty,activate_empty_,void,void)

可以这样使用:

Empty == Open + open_close / (close_drawer , activate_empty_(target_))

BOOST_MSM_EUML_ACTION(action-instance-name)

该宏声明一个行为类型和一个 const 实例, 供状态或转移行为使用. 动作实现本身紧跟在宏声明之后, 例如:

BOOST_MSM_EUML_ACTION(good_disk_format)
{
     template <class Fsm,class Evt,class SourceState,class TargetState>
     void/bool operator()(Evt const& evt,Fsm&,SourceState& ,TargetState& ){...}
};

BOOST_MSM_EUML_FLAG(flag-instance-name)

该宏声明一个标志类型和一个 const 实例, 供行为使用.

BOOST_MSM_EUML_FLAG_NAME(flag-instance-name)

该宏返回由 BOOST_MSM_EUML_FLAG 生成的标志类型的名称. 在需要该类型的地方 (通常是后端方法 is_flag_active) 会用到它. 例如:

fsm.is_flag_active<BOOST_MSM_EUML_FLAG_NAME(CDLoaded)>()

BOOST_MSM_EUML_DECLARE_ATTRIBUTE(event-type,event-name)

该宏声明一个名为 event-name、类型为 event-type 的属性. 随后可用 BOOST_MSM_EUML_ATTRIBUTES 把该属性加入属性列表.

BOOST_MSM_EUML_ATTRIBUTES(attributes-expression,attributes-name)

该宏基于作为第一个参数的表达式, 声明一个名为 attributes-name 的属性列表. 随后这些属性可以用 BOOST_MSM_EUML_EVENT_WITH_ATTRIBUTES 加入某个事件, 作为 BOOST_MSM_EUML_STATE 的第 3 个参数加入某个状态, 或作为 BOOST_MSM_EUML_DECLARE_STATE_MACHINE 的第 5 个参数加入某个状态机.

属性通过左移添加, 例如:

// m_song is of type std::string
BOOST_MSM_EUML_DECLARE_ATTRIBUTE(std::string,m_song)
// contains one attribute, m_song
BOOST_MSM_EUML_ATTRIBUTES((attributes_ << m_song ), FoundDef)

BOOST_MSM_EUML_EVENT(event-instance name)

该宏定义一个事件类型 (event-instance-name_helper), 并声明该事件类型的一个名为 event-instance-name 的 const 实例, 供转移表或状态行为使用.

BOOST_MSM_EUML_EVENT_WITH_ATTRIBUTES(event-instance-name,attributes)

该宏定义一个事件类型 (event-instance-name_helper), 并声明该事件类型的一个名为 event-instance-name 的 const 实例, 供转移表或状态行为使用. 该事件将以第二个参数传入的内容作为属性:

BOOST_MSM_EUML_EVENT_WITH_ATTRIBUTES(Found,FoundDef)

创建的事件实例支持 operator()(attributes), 因此

my_back_end.process_event(Found(some_string))

是可行的.

BOOST_MSM_EUML_EVENT_NAME(event-instance-name)

该宏返回由 BOOST_MSM_EUML_EVENT 或 BOOST_MSM_EUML_EVENT_WITH_ATTRIBUTES 生成的事件类型的名称. 在需要该类型的地方 (通常在后端定义内部) 会用到它. 例如:

typedef msm::back::state_machine<Playing_,
msm::back::ShallowHistory<mpl::vector<BOOST_MSM_EUML_EVENT_NAME(end_pause)
> > > Playing_type;

BOOST_MSM_EUML_STATE(build-expression,state-instance-name)

该宏定义一个状态类型 (state-instance-name_helper), 并声明该状态类型的一个名为 state-instance-name 的 const 实例, 供转移表或状态行为使用.

表达式语法有几种可能的形式:

  • (): 无入口或出口动作的状态.

  • (Expr1): 有入口动作但无出口动作的状态.

  • (Expr1,Expr2): 有入口和出口动作的状态.

  • (Expr1,Expr2,Attributes): 带入口和出口动作的状态, 并定义一些属性.

  • (Expr1,Expr2,Attributes,Configure): 带入口和出口动作的状态, 并定义一些属性以及标志 (标准 MSM 标志) 或延迟事件 (标准 MSM 延迟事件).

  • (Expr1,Expr2,Attributes,Configure,Base): 带入口和出口动作的状态, 并定义一些属性、标志和延迟事件 (普通 msm 延迟事件) 以及一个非默认基状态 (如标准 MSM 中所定义).

BOOST_MSM_EUML_INTERRUPT_STATE(build-expression,state-instance-name)

该宏定义一个中断状态类型 (state-instance-name_helper), 并声明该状态类型的一个名为 state-instance-name 的 const 实例, 供转移表或状态行为使用.

表达式语法有几种可能的形式. 在所有形式中, 第一个参数都是结束中断的事件的名称 (由前面的某个宏生成):

  • (end_interrupt_event): 无入口或出口动作的中断状态.

  • (end_interrupt_event,Expr1): 有入口动作但无出口动作的中断状态.

  • (end_interrupt_event,Expr1,Expr2): 有入口和出口动作的中断状态.

  • (end_interrupt_event,Expr1,Expr2,Attributes): 有入口和出口动作的中断状态, 并定义一些属性.

  • (end_interrupt_event,Expr1,Expr2,Attributes,Configure): 有入口和出口动作的中断状态, 并定义一些属性以及标志 (标准 MSM 标志) 或延迟事件 (标准 MSM 延迟事件).

  • (end_interrupt_event,Expr1,Expr2,Attributes,Configure,Base): 有入口和出口动作的中断状态, 并定义一些属性、标志和延迟事件 (普通 msm 延迟事件) 以及一个非默认基状态 (如标准 MSM 中所定义).

BOOST_MSM_EUML_TERMINATE_STATE(build-expression,state-instance-name)

该宏定义一个终止伪状态类型 (state-instance-name_helper), 并声明该状态类型的一个名为 state-instance-name 的 const 实例, 供转移表或状态行为使用.

表达式语法有几种可能的形式:

  • (): 无入口或出口动作的终止伪状态.

  • (Expr1,Expr2): 有入口和出口动作的终止伪状态.

BOOST_MSM_EUML_EXIT_STATE(build-expression,state-instance-name)

该宏定义一个出口伪状态类型 (state-instance-name_helper), 并声明该状态类型的一个名为 state-instance-name 的 const 实例, 供转移表或状态行为使用.

表达式语法有几种可能的形式:

  • (forwarded_event): 无入口或出口动作的出口伪状态.

  • (forwarded_event,Expr1): 有入口动作但无出口动作的出口伪状态.
