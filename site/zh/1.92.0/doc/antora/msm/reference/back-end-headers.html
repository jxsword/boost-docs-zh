后端头文件

msm/back/state_machine.hpp

该头文件提供一个类型 state_machine, 即 MSM 状态机引擎的实现.

template <class Derived,class HistoryPolicy=NoHistory,class CompilePolicy=favor_runtime_speed> state_machine

模板参数

Derived

前端状态机定义的名称. 三种前端均可使用.

HistoryPolicy

所需的历史策略. 可以是: AlwaysHistory, NoHistory, ShallowHistory. 默认为 NoHistory.

CompilePolicy

性能 / 编译期之间的取舍. 有两个预定义策略: favor_runtime_speed 和 favor_compile_time. 默认为 favor_runtime_speed, 即最佳性能、更长的编译时间. 见后端.

方法

start

必须在任何 process_event 调用之前调用 start 方法. 它会激活初始状态的入口动作. 这让你可以选择状态机何时启动. 见后端.

void start

process_event

事件处理方法实现了双重分派. 每次以新的事件类型调用该函数都会实例化一个新的分发算法, 并增加编译时间.

template <class Event> HandledEnum process_event

Event const&

current_state

返回当前活动状态的 id. 通常只有在调试或日志记录时才需要用到它.

const int* current_state const

get_state_by_id

返回给定 id 对应的状态. 由于具体状态机的所有状态共享同一个基状态, 返回值是一个基状态. 如果 id 不对应任何状态, 则返回空指针.

const BaseState* get_state_by_id const

int id

is_contained

辅助方法, 若该状态机作为子状态机被包含于另一个状态机之中则返回 true.

bool is_contained const

get_state

以指针形式返回状态机中所需的状态. 如果该状态在状态机中找不到, 将产生编译错误.

template <class State> State* get_state

get_state

以引用形式返回状态机中所需的状态. 如果该状态在状态机中找不到, 将产生编译错误.

template <class State> State& get_state

is_flag_active

若给定标志当前处于活动状态则返回 true. 当某个区域的活动状态带有该标志 (BinaryOp 使用 OR) 或 所有区域的活动状态都带有该标志 (BinaryOp 使用 AND) 时, 该标志为活动.

template <class Flag,class BinaryOp> bool is_flag_active

is_flag_active

若给定标志当前处于活动状态则返回 true. 当某个区域的活动状态带有该标志时, 该标志为活动.

template <class Flag> bool is_flag_active

visit_current_states

访问所有活动状态及其子状态. 状态通过不带参数的 accept 方法访问. 所有状态的基类必须提供 accept_sig 类型.

void visit_current_states

visit_current_states

访问所有活动状态及其子状态. 状态通过带参数的 accept 方法访问. 所有状态的基类必须提供 accept_sig 类型, 该类型定义签名, 从而定义参数的数量和类型.

void visit_current_states

任意类型 param1, 任意类型 param2,…​

defer_event

延迟所提供的事件. 只有在至少一个状态延迟了某个事件, 或者状态机直接提供 activate_deferred_events (见示例) 类型, 或通过 eUML 的 deferred_events 配置 (configure_ << deferred_events) 提供该类型时, 才能调用此方法.

template <class Event> void defer_event

Event const&

类型

nr_regions

状态机中包含的正交区域的数量

entry_pt

该嵌套类型为入口点伪状态提供必要的 typedef. state_machine<…​>::entry_pt<state_name> 是包含它的状态机的转移表中一条转移的合法目标.

entry_pt

exit_pt

该嵌套类型为出口点伪状态提供必要的 typedef. state_machine<…​>::exit_pt<state_name> 是包含它的状态机的转移表中一条转移的合法源.

exit_pt

direct

该嵌套类型为子状态机内部的显式入口提供必要的 typedef. state_machine<…​>::direct<state_name> 是包含它的状态机的转移表中一条转移的合法目标.

direct

stt

调用 state_machine<frontend>::stt 会返回一个包含状态机转移表的 mpl::vector. 该类型随后可用于 generate_state_set 或 generate_event_set.

args.hpp

该头文件提供一个类型 args, 它为访问器实现提供所需的类型.

msm/back/history_policies.hpp

该头文件提供 MSM 支持的开箱即用的历史策略. 这样的策略共有 3 个.

每种历史策略都必须实现以下方法:

set_initial_states

该方法由 msm::back::state_machine 在构造时调用. 它给策略一个机会来保存所有初始状态的 id (以数组形式传入).

void set_initial_states

int* const

history_exit

该方法由 msm::back::state_machine 在退出子状态机时调用. 它给策略一个机会来记住该子状态机最后活动的子状态的 id (以数组形式传入).

void history_exit

int* const

history_entry

该方法由 msm::back::state_machine 在进入子状态机时调用. 它给策略一个机会, 按照策略的目标设置活动状态. 策略以激活该子状态机的事件为参数, 并返回一个由活动状态 id 组成的数组.

template <class Event> int* const history_exit

Event const&

开箱即用的策略:

NoHistory

该策略是 state_machine 使用的默认策略. 不记住子状态机的任何活动状态, 子状态机每次被重新激活时都会激活初始状态.

AlwaysHistory

该策略是对 UML 标准的非标准扩展. 子状态机的活动状态总是会在子状态机每次被重新激活时被记住.

ShallowHistory

如果事件出现在策略的事件列表中, 该策略会激活子状态机的活动状态.

msm/back/default_compile_policy.hpp

该头文件包含 favor_runtime_speed 的定义. 该策略有两项设定:

  • 子状态机分发更快, 因为它们的转移被加入包含它们的机器的转移表, 而不是简单转发事件.

  • 它在编译期解决转移冲突

msm/back/favor_compile_time.hpp

该头文件包含 favor_compile_time 的定义. 该策略有两项设定:

  • 子状态机分发较慢, 因为所有事件, 即使没有分发机会的事件, 都会被转发给子状态机. 作为交换, 包含它们的机器的转移表中不添加任何行, 从而缩短编译时间.

  • 它在运行期解决转移冲突.

msm/back/metafunctions.hpp

该头文件包含供库使用的元函数. 其中三个元函数可能对用户有用:

  • generate_state_set< stt >: 生成转移表 stt 引用的所有状态的列表. 如果 stt 是递归表 (由 recursive_get_transition_table 生成), 该元函数会递归找出所有子状态机的状态. 非递归表可以通过 some_backend_fsm::stt 获得.

  • generate_event_set< stt>: 生成转移表 stt 引用的所有事件的列表. 如果 stt 是递归表 (由 recursive_get_transition_table 生成), 该元函数会递归找出所有子状态机的事件. 非递归表可以通过 some_backend_fsm::stt 获得.

  • recursive_get_transition_table<fsm>: 用子状态机的表递归扩展状态机 fsm 的转移表.

msm/back/tools.hpp

该头文件包含几个用于从状态机提取信息的元编程工具.

fill_state_names

属性

fill_state_names 有如下属性:

  • char const** m_names: 一个已分配的 const char* 数组, 状态机各状态的 typeid 生成名称将写入其中.

构造函数

char const** names_to_fill

用法

fill_state_names 用于在遍历状态列表的 mpl::for_each 中, 把状态名称写入一个预先分配的数组. 示例:

typedef some_fsm::stt Stt;
typedef msm::back::generate_state_set<Stt>::type all_states; //states
static char const* state_names[mpl::size<all_states>::value];
// array to fill with names
// fill the names of the states defined in the state machine
mpl::for_each<all_states,boost::msm::wrap<mpl::placeholders::_1> >
    (msm::back::fill_state_names<Stt>(state_names));
// display all active states
for (unsigned int i=0;i<some_fsm::nr_regions::value;++i)
{
    std::cout << " -> "
              << state_names[my_fsm_instance.current_state()[i]]
              << std::endl;
}

get_state_name

属性

get_state_name 有如下属性:

  • std::string& m_name: 迭代的返回值

  • int m_state_id: 要查找的状态的 id

构造函数

构造函数的参数是一个引用 (指向要用状态名称填充的字符串) 以及要查找的 id.

string& name_to_fill,int state_id

用法

该类型用于与上一个示例相同的查找, 用 mpl::for_each 遍历状态. 迭代完成后, 状态名称引用即被设置.

// we need a fsm's table
typedef player::stt Stt;
typedef msm::back::generate_state_set<Stt>::type all_states; //all states
std::string name_of_open; // id of Open is 1
// fill name_of_open for state of id 1
boost::mpl::for_each<all_states,boost::msm::wrap<mpl::placeholders::_1> >
          (msm::back::get_state_name<Stt>(name_of_open,1));
std::cout << "typeid-generated name Open is: " <<  name_of_open << std::endl;

display_type

属性

none

用法

复用上一个示例中的状态列表, 我们可以输出所有状态名称:

mpl::for_each<all_states,boost::msm::wrap<mpl::placeholders::_1> >(msm::back::display_type ());
