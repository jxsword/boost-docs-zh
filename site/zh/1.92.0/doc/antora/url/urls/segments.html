段

分层方案常把路径解释为由斜杠分隔的、称为段 (segments) 的百分号编码字符串序列. 在本库中, 可以使用以下独立的、引用底层 URL 的双向视图类型访问段:

类型 访问器 说明

segments_view

segments

解码段的只读范围.

segments_ref

segments

解码段的可修改范围.

segments_encoded_view

encoded_segments

段的只读范围.

segments_encoded_ref

encoded_segments

段的可修改范围.

首先我们观察这些关于路径和段的不变式:

  • 所有 URL 都有路径

  • 路径要么是绝对的, 要么是相对的, 要么为空

  • 以 "/" 开头的路径是绝对路径

  • 相对路径绝不能出现在权威组件之后

  • 每条路径都映射到唯一的段范围, 外加一个 bool 指示路径是否为绝对路径.

  • 每个段范围, 外加一个指示路径是否为绝对路径的 bool, 都映射到唯一的路径.

下面的 URL 包含一个有三个段的路径: "path"、"to" 和 "file.txt":

http://www.example.com/path/to/file.txt

为了理解路径与段之间的关系, 我们定义函数 segs, 它返回与段容器中元素对应的字符串列表:

auto segs( core::string_view s ) -> std::list< std::string >
{
    url_view u( s );
    std::list< std::string > seq;
    for( auto seg : u.encoded_segments() )
        seq.push_back( seg.decode() );
    return seq;
}

这意味着两条路径可能映射到相同的段序列. 在路径 usr 和 ./usr 中, ./ 是一个前缀, 可能是维持 url_view_base 实例始终引用有效 URL 这一不变式所必需的. 因此, 两条路径都映射到 { "usr" }. 另一方面, 对于给定的 URL, 每个序列确定唯一的路径. 例如, 把段设置为 {"a"} 总是映射到 ./a 或 a 之一, 取决于是否需要 "." 前缀来保持 URL 有效.

当需要保持 URL 有效时, 序列不会迭代出前导的 ".". 因此, 当我们把 { "x", "y", "z" } 赋给段之后, 该序列始终包含 { "x", "y", "z" }. 它绝不会包含 { ".", "x", "y", "z" }, 因为 . 需要被包含进来. 换句话说, 段容器的内容是权威的, 路径字符串是它们的函数; 反之则不然.

修改路径单个段或设置整个路径的库算法, 尽量表现得与在等价序列上执行该操作的预期行为一致. 例如, 如果某路径映射到三元素序列 { "a", "b", "c" }, 那么擦除中间的段应得到序列 { "a", "c" }. 本库总是力求完全按照调用方的请求行事; 但在某些情况下, 这会导致无效的 URL, 或使 URL 的语义发生剧烈且不符合预期的改变.

例如考虑以下 URL:

url u = url().set_path( "kyle:xy" );

本库产生的 URL 字符串是 kyle%3Axy 而不是 kyle:xy, 因为后者会带有非预期的方案. 下表演示对包含路径的 URL 执行各种修改所得到的结果:

操作路径和段的容器与函数的完整集合, 请参阅参考文档.

用于整体解码路径的函数 path 和 set_path 在某个段中含有编码的 %2F 时无法正确往返转换, 因为对应的解码 / 字符会被用作路径段之间的分隔符.

如果段本身包含编码的 /, 重新编码时它会被解释为路径分隔符, 使得无法区分真正的分隔符与编码的 / 字符.

要进行无损往返转换, 请使用 encoded_path、set_encoded_path、segments 或 encoded_segments API.
