规范化

规范化使我们能够判断两个 URL 是否指向同一资源. URL 比较服务于同样的目的, 即把两个字符串按已规范化的方式进行比较.

在不完全了解或控制两个 URL 的情况下, 无法确定它们是否指向同一资源. 因此, 等价性基于字符串比较, 并辅以额外的 URL 和方案规则. 这意味着仅靠比较不足以判断两个 URL 是否标识不同资源, 因为同一资源总是可能从不同地址提供.

因此, 比较方法的设计目标是尽量减少假阴性, 同时严格避免假阳性. 换句话说, 如果两个 URL 比较相等, 它们一定代表同一资源; 如果被认为不同, 根据应用的不同它们仍可能指向同一资源.

可以考虑与上下文相关的规则来减少假阴性的数量, 其中越廉价的方法产生假阴性的可能性越高:

  • 简单字符串比较

  • 基于语法的规范化

  • 基于方案的规范化

  • 基于协议的规范化

简单字符串比较

可以通过访问 URL 的底层缓冲区来执行简单字符串比较:

url_view u1("https://www.boost.org/index.html");
url_view u2("https://www.boost.org/doc/../index.html");
assert(u1.buffer() != u2.buffer());

仅考虑 rfc3986 的规则时, 简单字符串比较无法识别出上述 URL 指向同一资源.

基于语法的规范化

比较运算符实现了基于语法的规范化, 即执行 rfc3986 定义的规则.

url_view u1("https://www.boost.org/index.html");
url_view u2("https://www.boost.org/doc/../index.html");
assert(u1 == u2);

在可变 URL 中, 成员函数 normalize 也可用于对 URL 应用基于语法的规范化. 规范化后的 URL 由规范字符串表示, 任何两个本应比较相等的字符串最终都具有相同的底层表示. 换句话说, 两个规范化 URL 的简单字符串比较等价于基于语法的规范化.

url_view u1("https://www.boost.org/index.html");
url u2("https://www.boost.org/doc/../index.html");
assert(u1.buffer() != u2.buffer());
assert(u1 == u2);
u2.normalize();
assert(u1.buffer() == u2.buffer());
assert(u1 == u2);

基于语法的规范化流程

规范化使用 rfc3986 的以下定义来减少假阴性:

  • 大小写规范化: 百分号编码三元组规范化为大写字母

  • 百分号编码规范化: 解码无需百分号编码的八位组

  • 路径段规范化: 解析路径段 "." 和 ".."

下面的示例规范化 URL 的百分号编码和路径段:

url u("https://www.boost.org/doc/../%69%6e%64%65%78%20file.html");
u.normalize();
assert(u.buffer() == "https://www.boost.org/index%20file.html");

基于方案和协议的规范化

基于语法的规范化也可以用作基于方案和基于协议规范化的第一步. 一个常见的方案特有规则是忽略该方案的默认端口和空的绝对路径:

auto normalize_http_url =
    [](url& u)
{
    u.normalize();
    if (u.port() == "80" ||
        u.port().empty())
        u.remove_port();
    if (u.has_authority() &&
        u.encoded_path().empty())
        u.set_path_absolute(true);
};

url u1("https://www.boost.org");
normalize_http_url(u1);
url u2("https://www.boost.org/");
normalize_http_url(u2);
url u3("https://www.boost.org:/");
normalize_http_url(u3);
url u4("https://www.boost.org:80/");
normalize_http_url(u4);

assert(u1.buffer() == "https://www.boost.org/");
assert(u2.buffer() == "https://www.boost.org/");
assert(u3.buffer() == "https://www.boost.org/");
assert(u4.buffer() == "https://www.boost.org/");

通常用于减少特定方案假阴性的其他标准还有:

  • 把空权威组件视为错误或 localhost

  • 对默认权威组件用空字符串替换权威组件

  • 对含大小写不敏感数据的附加子组件进行规范化

  • 对含大小写不敏感数据的路径进行规范化
