快速一览

本节旨在让读者简要了解本库的特性与接口风格.

集成

全文使用的示例代码和标识符都假定以下声明已生效:

#include <boost/url.hpp>
using namespace boost::urls;

我们首先包含库头文件, 把所有符号引入作用域.

#include <boost/url.hpp>

也可以包含单个头文件, 以获取特定类型的声明.

Boost.URL 是一个需编译库. 你需要将程序与已构建的 Boost.URL 库链接. 必须把二进制文件安装在链接器可以找到的位置.

如果你按照 Boost 入门 指引操作, 这一步已经替你完成.

解析

假设你要解析以下 URL:

boost::core::string_view s = "https://user:pass@example.com:443/path/to/my%2dfile.txt?id=42&name=John%20Doe+Jingleheimer%2DSchmidt#page%20anchor";

在本例中, 我们使用 string_view 类型, 它由 Boost.Core 提供. 这是一种 string_view 实现, 可隐式转换为 std::string_view. 库命名空间中包含别名 string_view、error_code 和 result.

可以调用以下函数来解析该字符串:

boost::system::result<url_view> r = parse_uri( s );

函数 parse_uri 返回类型为 result<url_view> 的对象, 这是一个类似 variant 的容器, 其中持有错误或对象. 有多种函数可用于解析不同类型的 URL.

我们可以立即调用 result::value 来获得 url_view.

url_view u = r.value();

或者直接:

url_view u = *r;

当没有错误时, result::value 返回 url_view 的实例, 其中持有解析结果. result::value 在解析出错时抛出异常.

另外, 也可以使用函数 result::has_value 和 result::has_error 来检查字符串是否已无错解析.

值得注意的是, parse_uri 不进行任何动态内存分配. 与 string_view 一样, url_view 不保留底层字符串缓冲区的所有权.

只要原始字符串的内容未被修改, 构造出的 URL 视图就始终包含以正确序列化形式呈现的有效 URL.

如果输入不符合 URL 文法, 将通过 result 报告错误码, 而不是抛出异常. 仅当输入长度过长时才抛出异常.

访问

访问 URL 的各部分很简单:

url_view u( "https://user:pass@example.com:443/path/to/my%2dfile.txt?id=42&name=John%20Doe+Jingleheimer%2DSchmidt#page%20anchor" );
assert(u.scheme() == "https");
assert(u.authority().buffer() == "user:pass@example.com:443");
assert(u.userinfo() == "user:pass");
assert(u.user() == "user");
assert(u.password() == "pass");
assert(u.host() == "example.com");
assert(u.port() == "443");
assert(u.path() == "/path/to/my-file.txt");
assert(u.query() == "id=42&name=John Doe+Jingleheimer-Schmidt");
assert(u.fragment() == "page anchor");

URL 路径可以用函数 url_view::segments 进一步划分为路径段. 虽然 URL 查询字符串常用于表示键/值对, 但 rfc3986 并未定义这种解释. 用户可以把查询当作单一实体. url_view 提供了函数 url_view::params 来提取这种键/值对视图.

  • 代码

  • 输出

for (auto seg: u.segments())
    std::cout << seg << "\n";
std::cout << "\n";

for (auto param: u.params())
    std::cout << param.key << ": " << param.value << "\n";
std::cout << "\n";

这些函数返回引用底层 URL 子字符串与子范围的视图. 通过在内部直接引用 URL 字符串的相关部分, 其组件可以表示百分号解码后的字符串, 并无需预先分配内存即可转换为其他类型.

std::string h = u.host();
assert(h == "example.com");

还可以使用一种特殊的 string_token 类型来指定 URL 的某一部分应如何编码和返回.

std::string h = "host: ";
u.host(string_token::append_to(h));
assert(h == "host: example.com");

这些函数也可能返回空字符串

url_view u1 = parse_uri( "http://www.example.com" ).value();
assert(u1.fragment().empty());
assert(!u1.has_fragment());

对空组件和不存在的组件都是如此

url_view u2 = parse_uri( "http://www.example.com/#" ).value();
assert(u2.fragment().empty());
assert(u2.has_fragment());

许多组件没有类似 url_view::has_authority 这样的函数来检查其存在性. 这是因为某些 URL 组件是必备的.

在适用的情况下, 编码组件也可以通过 string_view 直接访问, 完全无需分配内存:

std::cout <<
    "url       : " << u                     << "\n"

    "authority : " << u.encoded_authority() << "\n"
    "userinfo  : " << u.encoded_userinfo()  << "\n"
    "user      : " << u.encoded_user()      << "\n"
    "password  : " << u.encoded_password()  << "\n"
    "host      : " << u.encoded_host()      << "\n"
    "port      : " << u.port()              << "\n"

百分号编码

decode_view 的实例提供多个函数来持久化解码后的字符串:

  • 代码

  • 输出

decode_view dv("id=42&name=John%20Doe%20Jingleheimer%2DSchmidt");
std::cout << dv << "\n";
id=42&name=John Doe Jingleheimer-Schmidt

decode_view 及其解码函数不进行内存分配, 除非结果需要存入另一个容器. 对象可以被回收以复用其内存, 把分配推迟到应用程序真正需要时进行.

在上面的示例中, str 拥有的内存可以复用来存储其他结果. 这在操作 URL 时同样有用:

url      u1 = parse_uri( "http://www.example.com" ).value();
url_view u2 = parse_uri( "http://other.example.com" ).value();
u1.set_host(u2.host());

如果 u2.host() 返回值类型, 则该操作需要两次内存分配. 另一个常见用例是把 URL 路径段转换为文件系统路径:

  • 代码

  • 输出

boost::filesystem::path p;
for (auto seg: u.segments())
    p.append(seg.begin(), seg.end());
std::cout << "path: " << p << "\n";
path: "path/to/my-file.txt"

在本例中, 只需进行 filesystem::path 的内部分配. 在许多常见用例中根本无需任何分配, 例如在 Web 服务器中为 URL 查找合适的路由:

auto match = [](
    std::vector<std::string> const& route,
    url_view u)
{
    auto segs = u.segments();
    if (route.size() != segs.size())
        return false;
    return std::equal(
        route.begin(),
        route.end(),
        segs.begin());
};

这使我们能够轻松匹配 Web 服务器文档根目录中的文件:

std::vector<std::string> route =
    {"community", "reviews.html"};
if (match(route, u))
{
    handle_route(route, u);
}

复合元素

URL 的路径和查询部分受到本库的特殊对待. 它们既可以作为单独的编码字符串访问, 也可以通过特殊的视图类型访问.

这段代码调用 url_view::encoded_segments 来获取路径段, 得到一个返回编码字符串的容器:

  • 代码

  • 输出

segments_encoded_view segs_encoded = u.encoded_segments();
for( auto v : segs_encoded )
{
    std::cout << v << "\n";
}

to
my%2dfile.txt

与其他返回编码字符串的 url_view 函数一样, 编码段容器不分配内存, 而是返回对 URL 所引用的底层编码缓冲区相应部分的视图.

与其他库函数一样, decode_view 允许访问复合元素中的元素, 同时完全避免内存分配:

  • 代码

  • 输出

segments_encoded_view segs_encoded = u.encoded_segments();

for( pct_string_view v : segs_encoded )
{
    decode_view dv = *v;
    std::cout << dv << "\n";
}

to
my-file.txt

  • 代码

  • 输出

params_encoded_view params_ref_view = u.encoded_params();

for( auto v : params_ref_view )
{
    decode_view dk(v.key);
    decode_view dv(v.value);

    std::cout <<
        "key = " << dk <<
        ", value = " << dv << "\n";
}

修改

本库提供容器 url 和 static_url 来支持修改 URL 内容. url 或 static_url 必须从现有的 url_view 构造.

与不获得底层字符缓冲区所有权的 url_view 不同, url 容器使用默认分配器来管理其拥有的可变大小字符缓冲区.

url u = parse_uri( s ).value();

另一方面, static_url 具有固定容量存储, 不需要动态内存分配.

static_url<1024> su = parse_uri( s ).value();

url 类型的对象满足 std::regular. 与 int 等内建类型类似, url 可复制、可移动、可赋值、可默认构造且可相等比较. 它们支持 url_view 的所有检查函数, 还提供修改 URL 所有组件的函数.

更改方案很简单:

u.set_scheme( "https" );

也可以使用预定义常量:

u.set_scheme_id( scheme::https ); // equivalent to u.set_scheme( "https" );

但方案必须有效, 否则会抛出异常. 所有修改函数都会对输入进行验证.

  • 试图把 URL 方案或端口设置为无效字符串会抛出异常.

  • 试图把其他 URL 组件设置为无效字符串时, 原始输入会被恰当地按该组件的要求进行百分号编码.

url 不可能持有语法非法的文本.

修改函数返回对对象的引用, 因此可以链式调用:

  • 代码

  • 输出

u.set_host_ipv4( ipv4_address( "192.168.0.1" ) )
    .set_port_number( 8080 )
    .remove_userinfo();
std::cout << u << "\n";
https://192.168.0.1:8080/path/to/my%2dfile.txt?id=42&name=John%20Doe#page%20anchor

所有非 const 操作都提供强异常安全保证.

url 返回的路径段和查询参数容器通过容器成员函数提供可修改的范围功能:

  • 代码

  • 输出

params_ref p = u.params();
p.replace(p.find("name"), {"name", "John Doe"});
std::cout << u << "\n";
https://192.168.0.1:8080/path/to/my%2dfile.txt?id=42&name=Vinnie%20Falco#page%20anchor
