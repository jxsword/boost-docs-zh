解析规则

Rule 是一个对象, 它尝试把输入字符缓冲区的开头与特定语法进行匹配. 匹配成功时返回包含值的 boost::system::result, 失败时返回 error_code. 规则不会被直接调用, 而是作为值连同要处理的输入字符缓冲区一起传递给 parse 函数. 第一个重载要求整个输入字符串都匹配, 否则发生错误. 第二个重载在成功时把输入缓冲区指针推进到第一个未消费的字符, 从而可以顺序解析数据流:

template< class Rule >
auto parse( core::string_view s, Rule const& r)
    -> system::result< typename Rule::value_type >;

template< class Rule >
auto parse( char const *& it, char const* end, Rule const& r)
    -> system::result< typename Rule::value_type >;

要满足 Rule 概念, class 或 struct 必须声明嵌套类型 value_type (表示成功时返回的值的类型) , 以及一个具有规定签名的 const 成员函数 parse. 在下面的代码中, 我们定义一个匹配单个逗号的规则:

struct comma_rule_t
{
    // The type of value returned upon success
    using value_type = core::string_view;

    // The algorithm which checks for a match
    system::result< value_type >
    parse( char const*& it, char const* end ) const
    {
        if( it != end && *it == ',')
            return core::string_view( it++, 1 );

        return error::mismatch;
    }
};

由于规则按值传递, 为书写方便我们声明该类型的一个 constexpr 变量. 规则变量名通常以 _rule 为后缀:

constexpr comma_rule_t comma_rule{};

现在我们可以用输入字符串和规则变量这样调用 parse:

system::result< core::string_view > rv = parse( ",", comma_rule );

assert( rv.has_value() && rv.value() == "," );

规则表达式可以有几种风格. 上面定义的规则是编译期常量. unsigned_rule 匹配无符号十进制整数. 这里我们在运行期构造规则, 并用模板参数指定用于保存结果的无符号整数类型:

system::result< unsigned short > rv =
    parse( "16384", unsigned_rule< unsigned short >{} );

函数 delim_rule 返回一个匹配所传入字符字面量的规则. 它是我们先前定义的逗号规则的更一般版本. 还有一个重载用于从字符集中精确匹配一个字符.

system::result< core::string_view > rv = parse( ",", delim_rule(',') );

错误处理

当规则匹配失败, 或规则检测到输入存在无法恢复的问题时, 它返回一个由 error_code 赋值的、指示失败的结果. 在使用以字符指针同时作为输入和输出参数的 parse 重载时, 出错时指针指向哪个字符由规则自行定义. 当规则成功匹配时, 指针总是被改为指向输入中第一个未消费的字符; 若所有输入都被消费, 则指向 end 指针.

如果一次解析操作未成功且希望用不同的规则再次尝试解析相同输入, 库实现和用户定义的 复合规则 (后文解释) 有责任回退其内部指针. 通过定义自定义规则来扩展本库文法的用户, 应遵循上述关于错误处理和修改调用方输入指针的行为.
