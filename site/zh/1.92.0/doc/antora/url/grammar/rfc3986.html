RFC 3986

像 parse_uri 这样的函数足以完成 URL 转换, 但它们要求整个字符串被完整消费. 当 URL 作为更大文法的组成部分出现时, 就希望使用基于规则组合的解析, 把 URL 与其他可能同资源定位符无关的元素一起处理. 为此, 本库为 rfc3986 中的顶层 BNF 产生式提供了规则, 并提供一条用于匹配百分号编码字符串的规则.

百分号编码

当组件中某个字符不在允许的字符集内, 或被用作组件内外的分隔符时, 百分号编码机制用于表示该组件中的数据八位组. 编码后的八位组 (也称为 转义) 编码为百分号字符 ('%') 后跟两位十六进制数字, 表示该八位组的数值:

pct-encoded   = "%" HEXDIG HEXDIG

可能含有百分号编码字符的 URL 组件在组件 BNF 中用 pct-encoded 产生式规定, 同时指明哪些字符不被视为保留集的一部分. 例如, RFC 的 3.3 Path 一节是这样描述路径字符的:

pchar         = unreserved / pct-encoded / sub-delims / ":" / "@"

本库提供 pct_encoded_rule 用于匹配百分号编码的字符串. 该函数接受一个可在不转义情况下使用的字符集合, 并返回一个合适的规则. 如果输入有效——即不存在无效的转义序列——该规则返回一个 decode_view. 它是一个字符的 forward range (前向范围) , 迭代时执行百分号解码. 它还支持与未编码字符串进行相等和大小比较, 且不分配内存. 在下面的示例中, 我们把字符串 s 解析为零个或多个 pchars 的序列:

system::result< pct_string_view > rv = parse( s, pct_encoded_rule( pchars ) );

本库提供并使用以下常量来指定百分号编码 URL 组件的规则:

名称 BNF

gen_delim_chars

 
gen-delims    = ":" / "/" / "?" / "#" / "[" / "]" / "@"

pchars

 
pchar     = unreserved / pct-encoded / sub-delims / ":" / "@"

reserved_chars

(除 unreserved_chars 之外的所有内容)

sub_delim_chars

 
sub-delims    = "!" / "$" / "&" / "'" / "(" / ")"
              / "*" / "+" / "," / ";" / "="

unreserved_chars

 
unreserved    = ALPHA / DIGIT / "-" / "." / "_" / "~"

URL 规则

当 URL 可能出现在更大文法的语境中时, 可能希望把外层文法表达为一条把 URL 作为元素的单一规则. 为此, 本库公开了用于把完整字符串作为 URL 组件进行高层解析的规则, 使这些组件可以作为包含非 URL 元素的更大字符串的一部分来解析. 这里我们给出一条适用于解析 HTTP request-line 的规则:

// request-line   = method SP request-target SP HTTP-version CRLF

constexpr auto request_line_rule = tuple_rule(
    not_empty_rule( token_rule( alpha_chars ) ),    // method
    squelch( delim_rule( ' ' ) ),                   // SP
    variant_rule(
        absolute_uri_rule,                          // absolute-uri or
        relative_ref_rule),                         // relative-ref
    squelch( delim_rule( ' ' ) ),
    squelch( literal_rule( "HTTP/" ) ),             // "HTTP/"
    delim_rule( digit_chars ),                      // DIGIT
    squelch( delim_rule( '.' ) ),                   // "."
    delim_rule( digit_chars ),                      // DIGIT
    squelch( literal_rule( "\r\n" ) ) );            // CRLF

本库提供以下规则, 使自定义规则定义能够整合各种风格的有效 URL 规则:

名称 BNF

absolute_uri_rule

 
absolute-URI    = scheme ":" hier-part [ "?" query ]

hier-part       = "//" authority path-abempty
                / path-absolute
                / path-rootless
                / path-empty

authority_rule

 
authority       = [ userinfo "@" ] host [ ":" port ]

origin_form_rule

 
origin-form    = absolute-path [ "?" query ]

absolute-path = 1*( "/" segment )

relative_ref_rule

 
relative-ref    = relative-part [ "?" query ] [ "#" fragment ]

uri_reference_rule

 
URI-reference   = URI / relative-ref

uri_rule

 
URI     = scheme ":" hier-part [ "?" query ] [ "#" fragment ]
