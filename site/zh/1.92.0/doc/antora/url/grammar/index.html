定制

对于广泛的应用场景, 本库的容器接口足以处理使用通用语法或知名方案的 URL. 但也有更复杂的情况, 需要超越本库已有的能力:

  • 为其他方案创建新的自定义容器

  • 把 URL 的解析纳入外层文法

  • 在非 URL 语境中解析 rfc3986 元素 (authority_view 就是一个例子)

  • 定义用于解析非 URL 字符串的新 ABNF 规则

为支持这些用例, 本库提供了一套用于处理低 ASCII 字符串的通用工具, 并公开了 rfc3986 中有用规则的接口. 这些工具的设计目标是:

  • 不使用 std::locale 或 std::char_traits

  • 不使用古怪的字符类型, 只用低 ASCII 的 char

  • 无内存分配 (或有界的内存分配)

  • 可与非终结规则灵活组合

  • 针对 RFC 中常见文法优化

  • 便于下游使用者扩展

通用工具嵌套在完全限定的命名空间 boost::urls::grammar 中, 而 rfc3986 专用解析算法的头文件位于 <boost/url/rfc/> include 目录. 本节说明如何设计与使用这些通用工具来定义和解析新文法.

语法记法

本库的文档与参考通篇使用增广巴科斯-诺尔范式 (ABNF) 记法来规定文法规则. 要最好地学习如何使用自定义解析特性, 必须理解这种记法.

本定制章节中的代码示例与标识符的写法, 假定以下声明已生效:

#include <boost/url/grammar.hpp>

using namespace ::boost::urls::grammar;
