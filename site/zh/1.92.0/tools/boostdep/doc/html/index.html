引言

Boost 模块化
构建 Boostdep
运行 Boostdep

Boostdep 是一个用于生成 Boost 依赖报告的工具. 它扫描 Boost 库的头文件或源文件, 查找 #include 指令, 根据这些信息构建依赖图, 并以纯文本或 HTML 输出其发现结果.

Boost 模块化

Boostdep 需要所谓的 "Boost 模块化" 目录结构.

如果你已经拥有 Boost 模块化安装, 可以跳过本节. 否则, 请继续阅读.

Boost 库位于 libs 目录下的子目录中. 例如, Boost.Filesystem 库的内容位于 libs/filesystem. 其中包括构建脚本 (位于 libs/filesystem/build), 源文件 (位于 libs/filesystem/src), 测试 (位于 libs/filesystem/test), 文档 (位于 libs/filesystem/doc), 等等.

过去, 当 Boost 使用 SVN 作为版本控制系统时, 头文件是个例外. 所有库的头文件都存放在 boost 子目录中, 因而无法准确判定哪个头文件属于哪个库.

当 Boost 改用 Git 进行版本控制时, 头文件被移至各自的库中, 放入 include 子目录. Boost.Filesystem 的头文件现在位于 libs/filesystem/include.

为了兼容性, boost 现在是一个 "虚拟" 目录, 其中包含指向头文件的链接. 它由 Boost.Build 自动维护. (命令 b2 headers 会创建或重建 boost 目录的内容.)

这一新结构使 Boostdep 能够判定: 当遇到 #include <boost/filesystem.hpp> 指令时, 该头文件属于 Boost.Filesystem, 因而当前正在扫描的库依赖于 Boost.Filesystem.

遗憾的是, Boost 发布版并不具有这种结构. 为了向后兼容, 发布版含有一个旧式的 boost 目录, 其中包含所有头文件, 而各库的 include 子目录则不存在. 因此, Boostdep 无法用于下载的 Boost 发布版.

要使用 Boostdep, 你需要转而克隆 Boost Git 仓库. 为此, 请执行以下命令:

git clone https://github.com/boostorg/boost.git boost

这一步将下载 Boost "超级项目" (主项目, 不含任何库), 并将其放入当前目录的 boost 子目录中. 若要覆盖目录名, 请将其作为第二个实参传入, 而不是 boost:

git clone https://github.com/boostorg/boost.git mydir

你现在可以 cd 到新创建的目录中:

cd mydir

该目录称为 "Boost 根目录" (Boost root). 以下所有命令均假定它是当前目录.

上述 git clone 命令下载 Boost Git 仓库的默认分支, 即 master. 这是 Boost 当前较为稳定的版本.

要验证这一点, 请执行以下命令

git status

在 Boost 根目录下执行. 该命令将输出

# On branch master
nothing to commit, working directory clean

若要改为下载特定发布版 (例如 1.58.0), 请在 git clone 之后, 在 Boost 根目录下执行以下命令:

git checkout boost-1.58.0

此时 git status 将显示

# HEAD detached at boost-1.58.0
nothing to commit, working directory clean

然后, 下载所有库:

git submodule update --init

这一步需要一些时间.

如果一切顺利, 你现在将拥有 Boost 最新 master 分支的完整内容 (若你未曾按名称 checkout 某个特定发布版), 或相应的 Boost 发布版 (若你曾这样做).

你可以通过执行以下命令, 在 master 分支、develop (不稳定) 分支和某个发布版之间切换:

对于 master 分支:

git checkout master
git pull
git submodule update --init

(git pull 会从服务器更新你本地 master 分支的副本, 以防其自你最初检出之后发生了变化.)

对于 develop 分支:

git checkout develop
git pull
git submodule update --init

对于 boost-1.58.0 发布版:

git checkout boost-1.58.0
git submodule update --init

对于 boost-1.57.0 发布版:

git checkout boost-1.57.0
git submodule update --init

请注意, 虽然首次 git submodule update 相当慢 (因为它需要下载所有库), 但后续调用的速度快得多.

另请注意, 如果某个新的 Boost 库 (例如 libs/convert) 存在于 (比如说) master 中, 并且你已将其检出, 那么当你之后切换到 boost-1.58.0 (该库并不存在于其中) 时, Git 将不会删除 libs/convert. 在这种情况下, git status 将输出

# HEAD detached at boost-1.58.0
# Untracked files:
#   (use "git add <file>..." to include in what will be committed)
#
#       libs/convert/
nothing added to commit but untracked files present (use "git add" to track)

你需要手动删除 libs/convert.

一旦你拥有了想要进行依赖分析的 Boost 内容, 就可继续下一步: 构建 Boostdep.

构建 Boostdep

要构建 Boostdep, 请在 Boost 根目录下执行以下命令:

b2 tools/boostdep/build

这会使用默认的 "工具集" (toolset, Boost.Build 术语, 意为 "编译器") 从源码构建 Boostdep, 若构建成功, 会将其放入 dist/bin 子目录. 该命令假定 b2 (Boost.Build 的可执行文件) 位于你的 path 环境变量中. 如果你没有 b2, 请执行

.\bootstrap

在 Windows 下; 或

./bootstrap.sh

在类 Unix 系统下执行, 这应会构建 b2 并将其放入当前目录. 之后你便可以使用 ./b2 代替 b2.

运行 Boostdep

一旦你构建好了 Boostdep, 就可以用以下命令执行它:

dist/bin/boostdep

或者

dist\bin\boostdep

在 Windows 下. 下面给出的命令均以 dist/bin/boostdep 为例; 如果你使用的是 Windows, 请改用 dist\bin\boostdep.

这将打印出以下帮助消息:

Usage:

    boostdep --list-modules
    boostdep --list-buildable
    boostdep [--track-sources] [--track-tests] --list-dependencies
    boostdep --list-exceptions
    boostdep --list-missing-headers
    boostdep --list-buildable-dependencies

    boostdep [options] --module-overview
    boostdep [options] --module-levels
    boostdep [options] --module-weights

    boostdep [options] [--primary] <module>

    boostdep [options] --reverse <module>
    boostdep [options] --subset <module>
    boostdep [options] [--header] <header>
    boostdep --test <module>

    boostdep --pkgconfig <module> <version> [<var>=<value>] [<var>=<value>]...
    boostdep [options] --subset-for <directory>

简单查询

要列出特定库的依赖, 请使用命令

dist/bin/boostdep library

例如, 对于 Boost.Filesystem, 请输入

dist/bin/boostdep filesystem

这将打印出与以下内容相似的结果:

Primary dependencies for filesystem:

assert:
    <boost/assert.hpp>
        from <boost/filesystem/operations.hpp>
        from <boost/filesystem/path_traits.hpp>

config:
    <boost/config.hpp>
        from <boost/filesystem/config.hpp>
        from <boost/filesystem/convenience.hpp>
        from <boost/filesystem/fstream.hpp>
        from <boost/filesystem/operations.hpp>
        from <boost/filesystem/path.hpp>
        from <boost/filesystem/path_traits.hpp>
    ...

functional:
    <boost/functional/hash_fwd.hpp>
        from <boost/filesystem/path.hpp>

io:
    <boost/io/detail/quoted_manip.hpp>
        from <boost/filesystem/path.hpp>

iterator:
    <boost/iterator/iterator_facade.hpp>
        from <boost/filesystem/path.hpp>
    ...

这列出了 Boost.Filesystem 的直接依赖. assert: 是库, <boost/assert.hpp> 是被包含的文件, from <boost/filesystem/config.hpp> 则显示 <boost/assert.hpp> 是在哪里被包含的.

Boostdep 以库 (或模块) 所在的目录名来命名它们. 例如, libs/filesystem 目录就是 filesystem 模块. libs/numeric/conversion 目录则是 numeric~conversion 模块, 这是 Boostdep 的命名约定.

之所以用波浪号替换正斜杠, 是因为 numeric~conversion 是有效的文件名, 这让生成 HTML 报告稍微容易一些.

要查看某个给定头文件位于何处以及谁包含它, 请输入

dist/bin/boostdep header

例如, 对于 boost/filesystem.hpp, 请输入

dist/bin/boostdep boost/filesystem.hpp

这将打印出大致如下的内容

Inclusion report for <boost/filesystem.hpp> (in module filesystem):

    from spirit:
        <boost/spirit/home/x3/support/utility/testing.hpp>

这说明 boost/filesystem.hpp 属于 Boost.Filesystem, 且只被包含一次, 来自 <boost/spirit/home/x3/support/utility/testing.hpp>. 其他头文件 (如 boost/shared_ptr.hpp) 使用得更广泛, 你可以尝试以下命令来看到这一点:

dist/bin/boostdep boost/shared_ptr.hpp

要打印某个库的反向依赖, 请使用

dist/bin/boostdep --reverse library

例如,

dist/bin/boostdep --reverse filesystem

将列出哪些库依赖于 Boost.Filesystem:

Reverse dependencies for filesystem:

graph_parallel:
    <boost/filesystem/operations.hpp>
        from <boost/graph/distributed/adjlist/serialization.hpp>
    <boost/filesystem/path.hpp>
        from <boost/graph/distributed/adjlist/serialization.hpp>

log:
    <boost/filesystem/config.hpp>
        from <boost/log/detail/config.hpp>
    <boost/filesystem/path.hpp>
        from <boost/log/sinks/event_log_backend.hpp>
        from <boost/log/sinks/text_file_backend.hpp>
        from <boost/log/sinks/text_multifile_backend.hpp>

spirit:
    <boost/filesystem.hpp>
        from <boost/spirit/home/x3/support/utility/testing.hpp>
    <boost/filesystem/fstream.hpp>
        from <boost/spirit/home/x3/support/utility/testing.hpp>
    <boost/filesystem/path.hpp>
        from <boost/spirit/home/x3/support/utility/error_reporting.hpp>

wave:
    <boost/filesystem/operations.hpp>
        from <boost/wave/util/cpp_include_paths.hpp>
        from <boost/wave/util/cpp_iterator.hpp>
        from <boost/wave/util/filesystem_compatibility.hpp>
    <boost/filesystem/path.hpp>
        from <boost/wave/cpp_context.hpp>
        from <boost/wave/util/cpp_include_paths.hpp>
        from <boost/wave/util/cpp_iterator.hpp>
        from <boost/wave/util/cpp_macromap.hpp>
        from <boost/wave/util/filesystem_compatibility.hpp>

HTML 报告

Boostdep 的主要用途是生成 HTML 依赖报告. 典型情况下, 会生成两类报告: 一类是包含所有模块信息的概览, 另一类是针对特定库列出信息的单模块报告.

Boostdep 可以生成三种第一类报告: 模块概览 (module overview)、模块层级 (module levels) 和模块权重 (module weights). 要生成模块概览, 请使用命令

dist/bin/boostdep --html --module-overview > module-overview.html

要生成模块层级报告, 请使用

dist/bin/boostdep --html --module-levels > module-levels.html

要生成模块权重报告, 请使用

dist/bin/boostdep --html --module-weights > module-weights.html

在这些报告中, 诸如 module 这样的模块名是指向 module.html 的 HTML 链接.

为了让这些链接按预期工作, 你可以按如下方式为每个模块生成 HTML 报告:

dist/bin/boostdep --html-title "Dependency Report for module" --html --primary module --secondary module --reverse module > module.html

如果你先用以下命令生成一个模块列表, 这一步可以自动化:

dist/bin/boostdep --list-modules > list-modules.txt

该列表每行包含一个模块名, 然后用一个脚本对每个模块名执行前述命令.

有关 Boostdep 的选项和命令的更多信息, 请参见 参考 一节.

有关报告生成脚本的示例, 请参见文件 tools/boostdep/examples/report.bat. 它是一个 Windows 批处理文件, 但将其改写为 Unix 风格的 shell 脚本应该很直接.

为方便起见, tools/boostdep/examples/report.bat 的内容如下:

SET BOOSTDEP=dist\bin\boostdep.exe

FOR /f %%i IN ('git rev-parse HEAD') DO @SET REV=%%i

FOR /f %%i IN ('git rev-parse --short HEAD') DO @SET SHREV=%%i

FOR /f %%i IN ('git rev-parse --abbrev-ref HEAD') DO @SET BRANCH=%%i

SET FOOTER=Generated on %DATE% %TIME% from revision %REV% on branch '%BRANCH%'

SET OUTDIR=..\report-%BRANCH%-%SHREV%

mkdir %OUTDIR%

%BOOSTDEP% --list-modules > %OUTDIR%\list-modules.txt

%BOOSTDEP% --html-footer "%FOOTER%" --html --module-overview > %OUTDIR%\module-overview.html
%BOOSTDEP% --html-footer "%FOOTER%" --html --module-levels > %OUTDIR%\module-levels.html
%BOOSTDEP% --html-footer "%FOOTER%" --html --module-weights > %OUTDIR%\module-weights.html

FOR /f %%i IN (%OUTDIR%\list-modules.txt) DO %BOOSTDEP% --html-title "Dependency Report for %%i" --html-footer "%FOOTER%" --html --primary %%i --secondary %%i --reverse %%i > %OUTDIR%%%i.html

--list-modules

boostdep --list-modules 打印模块列表. Boostdep 将 libs 的某个子目录视为一个模块, 条件是该子目录含有 include 子目录.

此命令通常在脚本中使用, 脚本随后利用该列表对每个模块执行一条命令.

--list-buildable

boostdep --list-buildable 打印需要构建的模块的列表. Boostdep 将含有名为 build 和 src 的子目录的模块视为需要构建.

此命令通常在脚本中使用.

--list-dependencies

boostdep --list-dependencies 打印一个模块列表, 其中每行的形式为

module -> dependency1 dependency2 ...

默认情况下, 只扫描 include 目录以查找 #include 指令. 如果给出选项 --track-sources, 则也扫描 src 目录. 如果给出选项 --track-tests, 则还扫描 test 目录.

此命令通常在脚本中使用. 其输出在纯文本方面与 --module-overview 几乎相同, 但对机器稍微更友好.

--list-exceptions

boostdep --list-exceptions 打印那些未包含在其对应模块的 include 目录中的头文件的列表.

--list-missing-headers

boostdep --list-missing-headers 打印被其他头文件包含、但缺失的头文件的列表.

--list-buildable-dependencies

boostdep --list-buildable-dependencies 以如下形式打印可构建库的依赖列表:

module = dependency1 dependency2 ... ;

这是有效的 Boost.Build 语法, 因此输出可以用作 Boost.Build 模块. 所有仅头文件库被视为一个名为 headers 的库.

--module-overview

boostdep --module-overview 生成模块概览, 可以是纯文本或 HTML. 纯文本输出的形式为

Module Overview:

accumulators -> array assert circular_buffer concept_check config core fusion iterator mpl numeric~conversion numeric~ublas parameter preprocessor range static_assert throw_exception tuple type_traits typeof
algorithm -> array assert bind concept_check config core exception function iterator mpl range regex static_assert tuple type_traits unordered
align -> assert config core static_assert throw_exception

而 HTML 输出则类似于

Module Overview

accumulators

⇢ array assert circular_buffer concept_check config core fusion iterator mpl numeric~conversion numeric~ublas parameter preprocessor range static_assert throw_exception tuple type_traits typeof

其中 accumulators 是指向 accumulators.html 的链接.

与前面一样, 如果给出 --track-sources, 则 src 子目录也会被扫描以查找 #include 指令.

HTML 输出由 --html 选项启用. --html-title 和 --html-footer 选项设置 HTML <title> 和页面页脚, 且需要放在 --html 之前, 如下例所示:

dist/bin/boostdep --html-title "Module Overview" --html-footer "Generated on 21.05.2015 20:53:11" --html --module-overview > module-overview.html

--module-levels

boostdep --module-levels 生成按层级对模块分组的报告. 层级的确定方式如下: 层级为 N 的模块绝不依赖于层级大于 N 的模块, 且在没有循环依赖的情况下, 也不依赖其他层级为 N 的模块. 它接受与 --module-overview 相同的选项.

dist/bin/boostdep --html-title "Module Levels" --html-footer "Generated on 21.05.2015 20:53:11" --html --module-levels > module-levels.html

--module-weights

boostdep --module-weights 生成按权重列出模块的报告. 模块权重是其依赖的总数. 这包括间接依赖.

--module-weights 接受与 --module-overview 相同的选项.

dist/bin/boostdep --html-title "Module Weights" --html-footer "Generated on 21.05.2015 20:53:11" --html --module-weights > module-weights.html

--primary

boostdep --primary module 列出 module 的主 (直接) 依赖. 它接受与 --module-overview 相同的选项.

dist/bin/boostdep --html-title "Primary Dependencies of filesystem" --html-footer "Generated on 21.05.2015 20:53:11" --html --primary filesystem > filesystem-primary.html

--secondary

boostdep --secondary module 列出 module 的次级 (间接) 依赖. 它接受与 --module-overview 相同的选项.

dist/bin/boostdep --html-title "Secondary Dependencies of filesystem" --html-footer "Generated on 21.05.2015 20:53:11" --html --secondary filesystem > filesystem-secondary.html

你可以在一次调用中组合 --primary 和 --secondary.

dist/bin/boostdep --html-title "Dependencies of filesystem" --html-footer "Generated on 21.05.2015 20:53:11" --html --primary filesystem --secondary filesystem > filesystem.html

--reverse

boostdep --reverse module 列出 module 的反向依赖, 即列出哪些模块依赖于 module. 它接受与 --module-overview 相同的选项.

dist/bin/boostdep --html-title "Reverse Dependencies of filesystem" --html-footer "Generated on 21.05.2015 20:53:11" --html --reverse filesystem > filesystem-reverse.html

你可以将 --reverse 与 --primary 和 --secondary 组合使用, 以获得完整的模块报告.

dist/bin/boostdep --html-title "Dependency Report for filesystem" --html-footer "Generated on 21.05.2015 20:53:11" --html --primary filesystem --secondary filesystem --reverse filesystem > filesystem.html

--subset

boostdep --subset module 列出 module 的子集依赖, 即列出构成 module 得以可用所需的子集的模块. 这些依赖通过追踪 #include 指令来确定, 追踪从 module 的头文件开始.

使用 --subset 报告的模块, 与使用 --primary 和 --secondary 之和所报告的模块, 两者的区别在于: 前者仅保证 module 可用, 而后者保证子集中的每个模块都可用.

--subset 接受与 --module-overview 相同的选项.

dist/bin/boostdep --html-title "Subset Dependencies of filesystem" --html-footer "Generated on 21.05.2015 20:53:11" --html --subset filesystem > filesystem-subset.html

你可以将 --subset 与其他模块报告选项组合使用.

--header

boostdep --header header 为 header 创建包含报告. 它接受与 --module-overview 相同的选项.

dist/bin/boostdep --html-title "Inclusion Report for <boost/shared_ptr.hpp>" --html-footer "Generated on 21.05.2015 20:53:11" --html --header boost/shared_ptr.hpp > header-boost-shared_ptr.html

--test

boostdep --test module 列出 module 的测试依赖, 即列出需要存在哪些模块, 才能运行 module 的测试.

dist/bin/boostdep --test filesystem

--cmake

boostdep --cmake module 生成一个 CMakeLists.txt 文件 (针对 module).

--pkgconfig

boostdep --pkgconfig module version var=value... 输出一个 pkg-config .pc 文件 (针对 module).

dist/bin/boostdep --pkgconfig system 1.65.0 prefix=/usr/local includedir=${prefix}/include libdir=${prefix}/lib

--subset-for

boostdep --subset-for directory 扫描 directory 以查找 #include 指令, 并列出通过这些 #include 所能到达的 Boost 模块.

其用途是确定用户应用程序或库需要 Boost 的哪个子集.

dist/bin/boostdep --subset-for d:\my_app

--brief

boostdep --brief module 生成一份针对 module 的简明依赖报告. 所有主依赖与次级依赖都会被列出, 每行一个.

dist/bin/boostdep --brief filesystem

--boost-root

--boost-root path-to-boost 指示 Boostdep 在 path-to-boost 处查找 Boost 根目录. 如果未给出该选项, 将在当前目录及其各级父目录中搜索名为 Jamroot 的文件. 如果找到, 则假定该目录为根目录. 如果未找到, 则假定环境变量 BOOST_ROOT 包含指向 Boost 根目录的路径.

--track-sources

--track-sources 选项指示 Boostdep 扫描 src 库子目录以查找 #include 指令. 若未启用, 则只扫描 include 子目录. 该选项在 1.77 及更高版本中默认开启, 并可用 --no-track-sources 关闭.

--track-tests

--track-tests 选项指示 Boostdep 扫描 test 库子目录以查找 #include 指令. 默认情况下, test 子目录不被扫描.

--html-title

--html-title title 设置 HTML <title> 标签的内容. 它必须放在 --html 之前才能生效.

--html-footer

--html-footer footer 设置 HTML 页面页脚文本. 如果未给出 --html, 则不起作用.

--html-stylesheet

--html-stylesheet stylesheet 设置 HTML 样式表 URL. 如果未给出 --html, 则不起作用.

--html-prefix

--html-prefix prefix 设置 HTML 前缀; 该前缀会紧跟在 <body> 标签之后输出. 如果未给出 --html, 则不起作用.

--html

--html 切换到 HTML 输出模式 (默认为纯文本). 它必须放在生成输出的命令之前.

--csv

--csv 切换到 CSV 输出模式 (默认为纯文本). 它必须放在生成输出的命令之前. 它支持与 --html 相同的操作 (--module-overview, --module-levels...). 默认情况下, 每个操作都会创建一个表, 该表以描述该操作的表标记和描述列名的表头开头. 例如, 以下命令:

--csv-separator

--csv-separator separator 设置 CSV 列分隔符字符串. 默认分隔符是逗号字符 (','). 如果未给出 --csv, 则不起作用. 以下命令将创建一个使用分号 (';') 作为分隔符的 CSV 文件:

dist/bin/boostdep --csv --csv-separator ';' --primary assert

--csv-table-marker

--csv-table-marker 为 CSV 文件中创建的每个表激活一行标记, 形式为 [Operation] <csv-separator> <arg>. 该功能默认开启. 它允许检测每个操作, 每个操作会在 CSV 文件中创建自己的表. 如果给出 --csv-no-table-marker, 则不输出标记行. 如果未给出 --csv, 则不起作用. 以下命令

dist/bin/boostdep --csv --csv-no-table-marker --csv-no-table-header --primary assert

将输出一个不带 [Primary],assert 标记行的标准 CSV 文件:

config,boost/config/workaround.hpp,boost/assert/source_location.hpp
config,boost/cstdint.hpp,boost/assert/source_location.hpp

--csv-table-header

--csv-table-header 为 CSV 文件中创建的每个表激活一行描述该表各列的表头. 该功能默认开启. 它使得列的含义更易识别, 也更容易导入数据库. 如果给出 --csv-no-table-marker, 则不输出标记行. 如果未给出 --csv, 则不起作用. 以下命令

dist/bin/boostdep --csv --csv-no-table-header --primary assert
