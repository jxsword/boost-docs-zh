理解 AutoIndex 工作流程

  1. 加载脚本文件(通常是 index.idx), 逐行处理, 每个(非注释)行产生一个或多个索引词条.
  2. 读完所有行后会构建一个 待索引词条 列表. 其中一部分可能是你直接在脚本文件中定义的词条, 另一些可能是通过 !scan-path 指令所指定的 C++ 头文件和源文件扫描得到的词条.
  3. 一旦 待索引词条 的完整列表就绪, 它就加载 Docbook XML 文件.(如果该文件来自 Quickbook/Doxygen/Boostbook/Docbook, 那么这就是转换为 Docbook 格式之后的完整文档).
  4. AutoIndex 为 Docbook XML 构建一个内部的 文档对象模型 (DOM). 然后扫描这一内部表示, 查找 待索引词条 的出现. 这种扫描在 XML 段落层级(或同级的表格、代码块等)上进行, 因此段落内的所有 XML 编码都被扁平化为纯文本.
    这种扁平化意味着, 用于搜索 待索引词条 的正则表达式可以找到完全包含在一个段落(或代码块等)之内的任何内容.
  5. 对找到的每个词条, 一个 indexterm Docbook 元素会被插入 文档对象模型 (DOM)(前提是内部索引生成处于关闭状态),
  6. 同时 AutoIndex 的内部索引表示也会得到更新.
  7. 一旦整个 XML 文档索引完毕, 如果 AutoIndex 被指示自行生成索引, 它就会创建必要的 XML 并插入 文档对象模型 (DOM).
  8. 最后, 整个 文档对象模型 (DOM) 会被写出为一个新的 Docbook XML 文件, 随后经由 XSL 样式表(通过 xsltproc)继续正常处理, 真正构建最终的人类可读文档.
