脚本文件 (.idx) 参考

脚本中可以出现以下元素:

注释与空行

仅由空白字符构成的空行会被忽略, 以 # 开头的行同样会被忽略.

注释

你不能把 # 注释追加到行尾!

索引词条的包含 
term [regular-expression1 [regular-expression2 [category]]]

项(term)

待索引词条.

该索引词条会在索引中构成一个主条目, 以包含该词条的小节标题作为次条目; 同时, 在该索引词条出现的每个小节标题之下, 它也会被用作一个次条目.

regular-expression1

索引词条搜索器.

可选的正则表达式: 文档文本中正则表达式的每次出现都会生成一个索引词条.

如果省略正则表达式(默认情况)或将其设为 "", 则以 索引词条 本身作为搜索文本, 且只对匹配 索引词条 的整词出现进行索引.

例如:

foobar

会对任意小节中 "foobar" 的出现进行索引, 而

foobar \<\w*(foo|bar)\w*\>

会对其内包含 "foo" 或 "bar" 的任意整词进行索引. 当你想把许多相似或相关的词收录到同一个条目之下时, 这很有用.

reflex

只会把 "reflex" 作为整词的出现进行索引, 而:

reflex \<reflex\w*\>

会把 "reflex"、"reflexes"、"reflexing" 和 "reflexed" 的出现全部收录到同一个条目 reflex 之下.

你经常需要用它来处理复数及其他词形变化.

regular-expression2

小节选择器.

一个约束, 指定对 词条 索引哪些小节: 只有当小节的 ID 与 regular-expression2 完全匹配时, 该小节才会对 词条 的出现进行索引.

例如, 把索引限制在 某一个特定小节(不包括其下层的子小节):

myclass "" "mylib\.examples"

例如, 把索引限制在特定小节, 以及其下层的子小节:

myclass "" "mylib\.examples.*"

会把 "myclass" 作为整词的出现进行索引, 但仅限于小节 ID 以 "mylib.examples" 开头的小节, 而

myclass "\<myclass\w*\>" "mylib\.examples.*"

还会对复数形式 myclass、myclasses、myclasss ... 进行索引

以及:

myclass "" "(?!mylib\.introduction).*"

会对任意小节中 "myclass" 的出现进行索引, 但小节 ID 以 "mylib.introduction" 开头的小节除外.

最后, 可以把两个(或更多)小节用 OR 组合起来加以排除:

myclass "" "(?!mylib\.introduction|mylib\.reference).*"

这会排除在 ID 以 "mylib.introduction" 或 "mylib.reference" 开头的小节中搜索该词条.

如果省略这第三个字段(默认情况)或将其设为 "", 则对该词条索引 所有小节.

category

索引类别约束.

可选地指定一个类别, 用于放置 索引词条 的出现. 如果你有多个索引, 这就是赋给索引 "type" 属性的名称.

例如:

myclass "" "" class_name

会对 myclass 的出现进行索引, 如果存在类索引则将其放入其中.

可以让一个索引词条在脚本文件中出现不止一次:

  • 如果它们的 category 名称不同, 则它们会被完全分开处理.
  • 否则它们会被合并, 即取所提供正则表达式的逻辑或.

因此:

myterm search_expression1 constrait_expression2 foo
myterm search_expression1 constrait_expression2 bar

会被当作不同的词条处理, 各自拥有自己的条目, 而:

myterm search_expression1 constrait_expression2 mycategory
myterm search_expression1 constrait_expression2 mycategory

会被合并为单个词条, 等价于:

myterm (?:search_expression1|search_expression1) (?:constrait_expression2|constrait_expression2) mycategory
源文件扫描 
!scan source-file-name

扫描 C/C++ 源文件 source-file-name, 查找 函数、类、宏或 typedef 的定义, 并把其中的每一个都作为待索引词条. 找到的词条会依据其在源文件中出现的方式被指派到索引类别 "function_name"、"class_name"、"macro_name" 或 "typedef_name". 随后它们可被收入 "type" 属性具有相同类别名的专门索引.

重要

在实际为文档编制索引时, 扫描器并不会对源文件中找到的词条的任意出现都进行索引, 而是查找类定义或函数/typedef 声明. 这减少了进入索引的虚假匹配数量, 但也可能漏掉一些正当的词条: 关于如何改变这一点, 参见 define-scanner 命令.

目录与源文件扫描 
!scan-path directory-name file-name-regex [recurse]

directory-name

要扫描的目录: 该路径应相对于脚本文件(或相对于命令行 prefix=path 选项指定的路径), 且其文件名中应全部使用正斜杠.

file-name-regex

一个正则表达式: 目录中名称匹配该正则表达式的任何文件都会被扫描以查找待索引词条.

recurse

一个可选的布尔值, 取值为 "true" 或 "false", 指示是否递归进入子目录. 默认为 "false".

排除词条 
!exclude term-list

把以空白分隔的 term-list 中的所有词条排除在索引之外. 它应放在任何可能使这些词条被收录的 !scan 或 !scan-path 规则 之后. 换言之, 这会把词条从扫描器内部的待索引列表中移除.

改写小节名称 
!rewrite-id regular-expression new-name

regular-expression

一个正则表达式: 所有与该表达式完全匹配的小节 ID, 其索引条目将使用 new-name 而非其标题.

new-name

该小节在索引中显示所用的名称.

!rewrite-name regular-expression format-text

regular-expression

一个正则表达式: 所有标题与该正则表达式完全匹配的小节, 其索引条目将由正则表达式的匹配结果与正则表达式格式串 format-text 组合而成.

format-text

用于重新格式化标题的 Perl 风格格式串.

例如:

!rewrite-name "(?:A|An|The)\s+(.*)" "\1"

会从所有索引条目中移除开头的 "A"、"An" 或 "The", 从而避免在 "The" 等之下出现大量条目!

定义或更改文件扫描器 
!define-scanner type file-search-expression xml-regex-formatter term-formatter id-filter filename-filter

使用 !scan 或 !scan-path 规则扫描源文件时, 会用一系列正则表达式在该文件中查找应当被索引的类、函数、宏或 typedef. 为此提供了一组默认正则表达式(见下文), 但有时你可能想替换默认值, 或添加新的扫描器. 该规则的参数为:

type

使用该规则找到的条目将被指派的 type; 从源文件创建并在 XML 中被发现的索引词条, 其 type 属性会设为该值, 随后可能出现在具有相同 type 属性的专门索引中

file-search-expression

用于扫描源文件以查找索引词条的正则表达式, 与该表达式匹配的结果将由后两个参数进行转换.

xml-regex-formatter

一个正则表达式格式串, 从源文件中匹配 file-search-expression 的内容里提取关键信息, 并创建 一个新的正则表达式, 用于在待索引文档中搜索该索引词条的出现.

term-formatter

一个正则表达式格式串, 从源文件中匹配 file-search-expression 的内容里提取关键信息, 并创建将出现在索引中的索引词条.

id-filter

可选. 一个正则表达式, 限制在待索引文档中搜索哪些小节 ID: 只有 ID 属性与该表达式完全匹配的小节, 才会被考虑索引该扫描器找到的词条.

filename-filter

可选. 一个正则表达式, 限制该扫描器扫描哪些文件: 只有文件名与该表达式完全匹配的文件才会被扫描以查找可用的索引词条. 注意与之匹配的文件名很可能是绝对路径, 并且可能包含正斜杠或反斜杠路径分隔符.

如果在扫描第一个文件时, 不存在 type 为 "class_name"、"typedef_name"、"macro_name" 或 "function_name" 的扫描器, 则会安装默认扫描器. 它们等价于:

!define-scanner class_name "^[[:space:]]*(template[[:space:]]*<[^;:{]+>[[:space:]]*)?(class|struct)[[:space:]]*(\<\w+\>([[:blank:]]*\([^)]*\))?[[:space:]]*)*(\<\w*\>)[[:space:]]*(<[^;:{]+>)?[[:space:]]*(\{|:[^;\{()]*\{)" "(?:class|struct)[^;{]+\<\5\>[^;{]+\{" \5
!define-scanner typedef_name "typedef[^;{}#]+?(\w+)\s*;"  "typedef[^;]+\<\1\>\s*;" "\1"
!define-scanner "macro_name" "^\s*#\s*define\s+(\w+)" "\<\1\>" "\1"
!define-scanner "function_name" "\w++(?:\s*+<[^>]++>)?[\s&*]+?(\w+)\s*(?:BOOST_[[:upper:]_]+\s*)?\([^;{}]*\)\s*[;{]" "\\<\\w+\\>(?:\\s+<[^>]*>)*[\\s&*]+\\<\1\\>\\s*\\([^;{]*\\)" "\1"

注意, 如果你已提供了带有这些 type 名称的自定义版本, 则不会安装这些默认值. 在这种情况下, 如果你想让默认扫描器与你的扫描器同时生效, 应把上述内容包含到你的脚本文件中. 也完全允许多个扫描器具有相同的 type 而其他字段不同.

最后你应当注意, 默认扫描器对查找内容相当严格, 例如类扫描器只会为具有如下形式类定义的类创建索引条目:

class my_class : public base_classes
{
   // etc

出现在文档中, 因此类名的简单提及 不会 被索引, 只有类概要(如果有的话)才会被索引. 如果这不是你想要的方式, 可把上面的 class_name 扫描器定义加入你的脚本文件, 并把 xml-regex-formatter 字段改为更宽松的内容, 例如:

!define-scanner class_name "^[[:space:]]*(template[[:space:]]*<[^;:{]+>[[:space:]]*)?(class|struct)[[:space:]]*(\<\w+\>([[:blank:]]*\([^)]*\))?[[:space:]]*)*(\<\w*\>)[[:space:]]*(<[^;:{]+>)?[[:space:]]*(\{|:[^;\{()]*\{)" "\<\5\>" \5

会对扫描器在文档中找到的类名的 任何 出现进行查找.

调试扫描

如果你在索引中看到某个词条, 却不明白它为什么会在那里, 可以添加一条 debug 指令:

!debug regular-expression

此后, 只要 regular-expression 匹配到找到的索引词条、其出现的小节标题, 或扫描器的 type 字段, 就会打印出如下所示的诊断信息:

Debug term found, in block with ID: spirit.qi.reference.parser_concepts.parser
Current section title is: Notation
The main index entry will be : Notation
The indexed term is: parser
The search regex is: [P|p]arser
The section constraint is: .qi.reference.parser_concepts.
The index type for this entry is: qi_index

这会在你的日志文件中产生大量输出, 但在你对文件选择和扫描过程感到满意之前, 值得将其开启.
