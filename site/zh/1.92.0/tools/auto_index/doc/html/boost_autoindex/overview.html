概述

AutoIndex 是一个工具, 用于免除为描述 C/C++ 代码的 Boostbook/Docbook 文档(可能由你的 Quickbook 文件 mylibrary.qbk 生成, 也可能还使用了 Doxygen 自动文档)编制索引的繁琐工作.

传统上, 要为 Docbook 文档编制索引, 你必须手工添加大量 <indexterm> 标记: 实际上, 每个待索引词条的每次出现都需要一个 <indexterm>.

AutoIndex 则会自动扫描一个或多个 C/C++ 头文件, 提取这些头文件所定义的全部 函数、类、宏和 typedef 名称, 然后替你把 <indexterm> 标记插入 Docbook XML 文档.

AutoIndex 也可以依据脚本文件(例如 index.idx)中指定的索引词条列表进行扫描. 这些手工提供的词条可以是正则表达式, 从而让用户能够找到一些在 C++ 头文件中可能不会出现的术语引用. 当然, 手工提供一份待索引的搜索词条列表是件繁琐的工作(尤其是处理复数和变体形式), 并且需要对库有足够的了解才能猜到用户想查什么, 但至少查找词条并列出页码这类真正的"苦差事"已经自动化了.

AutoIndex 按如下方式创建索引条目:

对于每个搜索词条的每次出现, 它会创建两个索引条目:

  1. 以搜索词条作为 主索引键, 以其出现的 小节标题 作为子词条.
  2. 以小节标题作为主索引条目, 以搜索词条作为子条目.

这样用户就有两次机会找到所需内容: 既可以通过小节名称, 也可以通过 函数、类、宏或 typedef 名称.

注释

此行为可以更改, 使其只创建一个索引条目(以搜索词条作为键, 且不使用小节名称, 除非作为搜索词条的子条目).

当然, 这些自动生成的索引条目可能并不完全符合你的预期: 常常会出现一些多余的条目、一些缺失的条目, 以及一些以小节名称作为索引条目却不尽理想的条目. 因此 AutoIndex 提供了一些基于正则表达式的强大规则, 允许你添加、删除、约束或改写条目. 通常只需在 AutoIndex 的脚本文件中写几行内容, 就足以调整输出以符合作者的期望(从而也希望符合索引使用者的期望!).

AutoIndex 还支持多个索引(Docbook 也如此). 由于它知道哪些搜索词条是 函数、类、宏或 typedef 名称, 因此可以向 XML 添加必要的属性, 让你为这些不同类型分别建立独立的索引. 这些专门的索引只包含 函数、类、宏或 typedef 名称的条目; 与主"收录一切"索引不同, 小节名称在这里绝不用作主索引词.

最后, Docbook XSL 样式表为 PDF 输出生成的索引十分美观, 附带页码, 相比之下 HTML 索引则显得逊色, 因为它们用小节标题代替页码... 而且由于 AutoIndex 使用小节标题作为索引条目, 这会导致大量重复. 因此作为替代方案, 可以指示 AutoIndex 自行构建索引. 这比使用 XSL 样式表更快, 并且此时每个索引条目都是指向相应小节的超链接:

最后, 你可以选择用哪种 XML 容器来包裹内部生成的索引, 默认为 <section>...</section>, 但你既可以使用命令行选项, 也可以使用 Boost.Build 的 Jamfile 特性来选择其他包裹容器——例如 appendix 或 chapter 都是不错的选择, 只要最适合文档的行文即可. 你甚至可以把容器包裹器的类型设为 index, 前提是关闭 XSL 样式表的索引生成功能, 例如在 Jamfile 中设置如下构建需求:

<format>html:<auto-index-internal>on       # Use internally generated indexes.
<auto-index-type>index                     # Use <index>...</index> as the XML wrapper.
<format>html:<xsl:param>generate.index=0   # Don't let the XSL stylesheets generate indexes.
