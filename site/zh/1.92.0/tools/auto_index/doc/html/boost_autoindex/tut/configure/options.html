可用的索引选项

可用的选项有:

<auto-index>off/on

开启文档的索引功能, 默认为 "off", 因此如果你希望调用 AutoIndex, 请务必设置此项!

<auto-index-internal>off/on

选择是由 AutoIndex 自行创建索引(特性为 on), 还是只插入必要的 DocBook 标记, 让 DocBook XSL 样式表来创建索引. 默认为 "off".

<auto-index-script>filename

指定要加载的脚本的名称.

<auto-index-no-duplicates>off/on

当为 on 时, AutoIndex 在任一小节中对一个词条只索引一次; 否则(默认情况), 如果词条在同一小节中出现多次, 可能会创建多个索引条目.

<auto-index-section-names>off/on

当为 on 时, AutoIndex 会为找到的每个词条创建两个索引条目——一个以词条本身作为主索引键, 另一个使用外围小节名称. 为 off 时不创建使用小节标题的索引条目. 默认为 "on"

<auto-index-verbose>off/on

默认为 "off". 开启后 AutoIndex 会打印进度信息——在设置阶段用于调试很有用.

<auto-index-prefix>filename

可选地指定一个目录, 作为前缀应用于脚本文件中的所有相对文件路径.

你可以这样做来减少路径名的键入, 和/或在路径无法相对于脚本文件位置定位时使用, 典型情况是头文件位于 Boost 主干(trunk), 而脚本文件位于 Boost 沙盒(sandbox).

对于 Boost 标准库布局, <auto-index-prefix>../../.. 会让你回到 Boost 树的"根"目录, 因此 !scan-path boost/mylibrary/ 就是你的头文件所在位置, 而 libs/mylibrary 用于其他文件. 如果不使用前缀, 所有相对路径都相对于脚本文件的位置.

<auto-index-type>element-name

指定用于包裹内部生成索引的 XML 元素的名称: 默认为 section, 但也可以是 appendix 或 chapter, 或其他任何带有正式标题的块级元素. 可用选项的实际列表取决于 Quickbook 文档类型, 下表给出了可用选项(假定索引位于顶层, 而非某个子小节或其他容器中):

文档类型

允许的索引类型

book

appendix（附录） index（索引） article（文章） chapter（章） reference（参考） part（部分）

article

section appendix index sect1

chapter

section index sect1

library

与 Chapter 相同 (section index sect1)

part

appendix index article chapter reference

appendix

section index sect1

preface

section index sect1

qandadiv

不适用: 索引必须放在文档的某个子小节内.

qandaset

不适用: 索引必须放在文档的某个子小节内.

reference

不适用: 索引必须放在文档的某个子小节内.

set

不适用: 索引必须放在文档的某个子小节内.

于是, <auto-index-type>element-name 的选择在很大程度上取决于你希望对索引应用的格式化:

索引所用的 XML 容器

XSL 样式表应用的格式化

appendix

开启一个新页面.

article

开启一个新页面.

chapter

开启一个新页面.

索引

仅当其位于 article 或 book 内部时才开启新页面.

part

开启一个新页面.

reference

开启一个新页面.

sect1

只要不是第一个小节就开启新页面(但受 XSL 参数 chunk.section.depth 和/或 chunk.first.sections 控制).

section

只要不是第一个小节或未嵌套在另一个小节内就开启新页面(但受 XSL 参数 chunk.section.depth 和/或 chunk.first.sections 控制).

在几乎所有情况下, 默认值(section)都是正确的选择——例外情况是把索引直接放在 book 或 part 内部, 此时索引所用的 XML 容器可能与 book 或 part 中各细分部分所用的容器相同. 无论如何, 把 section 放进 book 或 part 都会产生无效的 XML.

最后, 如果你使用 Quickbook 生成文档, 那么你可能希望向工程需求添加:

<include>$boost-root/tools/auto_index/include

(把 $boost-root 替换为 Boost 树根目录的路径), 这样就可以只用一条命令把文件 auto_index_helpers.qbk 包含进你的 quickbook 源文件:

[include auto_index_helpers.qbk]
