Boost 概念检查库 (BCCL)

概念检查库允许以 提议的 C++ 语言扩展的风格, 显式声明并检查 概念.

概要

C++ 泛型编程的特点是使用模板参数来表示抽象数据类型 (或 "概念"). 然而, C++ 语言本身并未提供一种机制, 让类模板或函数模板的作者显式声明用户提供的模板实参应满足 (或符合) 的概念. 模板参数通常以其要求满足的概念命名, 作为对用户的提示, 并使概念要求在代码中显式可见. 但编译器并不会特殊对待这些特殊名称: 名为 RandomAccessIterator 的参数与名为 T 的参数对编译器而言毫无区别. 此外,

  • 由错误的模板实参导致的编译器错误信息可能特别难以解读. 通常错误并不指向模板调用点的位置, 而是暴露模板的内部实现, 而用户本不应看到这些内容.
  • 没有编译器检查时, 文档化的要求往往含糊、不正确或根本不存在, 用户因此无法确切知道期望什么样的实参.
  • 文档化的概念要求可能未完全 覆盖 实际模板的需要, 这意味着即使所提供的模板实参满足文档要求, 用户也可能遇到编译错误.
  • 文档化的概念要求可能过于严苛, 要求了模板实际并不需要的内容.
  • 代码中的概念名称可能与文档化的要求渐渐脱节.

Boost 概念检查库提供:

  • 一种在模板参数使用点插入编译期检查的机制.
  • 一种通过概念检查类指定概念要求的框架.
  • 一种验证概念要求是否覆盖模板的机制.
  • 一套与 C++ 标准库中的概念要求相匹配的概念检查类和原型 (archetype) 类.
  • 一种替代特征类 (traits classes) 来访问关联类型的机制, 其语法与下一版 C++ 标准提议的语法一致.

这些机制使用标准 C++ 实现, 不引入任何运行期开销. 使用该机制的主要代价在于编译期.

每个编写类模板或函数模板的程序员都应把概念检查作为其日常编码惯例的一部分. 组件公有接口中的每个模板参数都应插入一个概念检查. 如果该概念是标准库中的概念之一, 直接使用 BCCL 中匹配的概念检查类即可. 若不是, 则编写一个新的概念检查类 - 毕竟它们通常只有几行. 对于新概念, 还应创建匹配的原型 (archetype) 类, 即该概念的最小骨架实现

引言

概念 是一组要求 (有效表达式、关联类型、语义不变式、复杂度保证等), 类型必须满足这些要求才能作为实参正确用于泛型算法的调用. 在 C++ 中, 概念由函数模板 (泛型算法) 的形参模板参数表示. 然而, C++ 没有表示概念的显式机制 - 模板参数只是占位符. 按照惯例, 这些参数被赋予与所需概念对应的名称, 但当模板参数绑定到实际类型时, C++ 编译器并不强制其符合该概念.

自然, 如果泛型算法以不满足概念至少语法要求的类型调用, 就会发生编译期错误. 然而, 该错误本身 并未 反映类型未满足概念全部要求这一事实. 相反, 错误可能出现在实例化层次结构的深处, 即表达式对该类型无效之处, 或假定的关联类型不可用之处. 由此产生的错误信息大多毫无信息量, 基本上无法解读.

所需的是一种在实例化点 (或其附近) 强制实施 "概念安全" 的机制. Boost 概念检查库利用一些标准 C++ 构造来尽早强制概念符合性, 并在不符合时提供更具信息量的错误消息.

注意: 该技术只处理概念的语法要求 (有效表达式与关联类型). 我们不处理语义不变式或复杂度保证, 而它们也是概念要求的一部分..

动机示例

我们给出一个简单示例, 说明模板库的错误用法及由此产生的错误消息. 在下面的代码中, 标准模板库 (STL) 的泛型 std::stable_sort() 算法[3, 4,5] 被应用于一个链表.

  bad_error_eg.cpp:
1 #include <vector>
2 #include <complex>
3 #include <algorithm>
4 
5 int main()
6 {
7     std::vector<std::complex<float> > v;
8     std::stable_sort(v.begin(), v.end());
9 }

此处, std::stable_sort() 算法的原型如下:

  template <class RandomAccessIterator>
  void stable_sort(RandomAccessIterator first, RandomAccessIterator last);

本例中, 根本错误在于 std:complex<float> 不满足 LessThanComparable 概念. 遗憾的是, 错误信息中没有任何内容向用户指出这一点.

对模板库有足够经验的 C++ 程序员或许能一眼看出错误所在, 但这条消息对新手难以理解的原因有以下几点:

  1. 错误信息与 std::stable_sort() 及 LessThanComparable 的文档要求之间没有任何文字上的关联.
  2. 错误信息过长, 列出了用户不 (也不应该!) 了解或关心的 STL 内部函数 (例如 __insertion_sort).
  3. 错误信息中列出如此多内部库函数, 程序员很容易误以为问题出在库中, 而不是自己的代码里.

这条消息纠正了标准错误信息的若干不足.

  • 消息明确指出了用户可以在 STL 文档中查阅的概念 (LessThanComparable).
  • 错误信息现在短得多, 既不暴露 STL 内部函数, 甚至也不指向 std::stable_sort.
  • 错误信息中出现的 concept_check.hpp 提醒用户: 错误出在用户代码中, 而不在库的实现中.

历史

本概念检查系统的第一个版本由 Jeremy Siek 在 SGI 的 C++ 编译器与库小组工作期间开发. 该版本现已成为 SGI STL 发行版的一部分. 最初以 boost 概念检查库名义引入的系统与 SGI STL 中的概念检查的区别在于: 概念检查类的定义大为简化, 代价是错误消息中的辅助说明文字较少. 2006 年, Dave Abrahams 重写了该系统 (保持向后兼容), 使其更易使用, 更接近 C++ 核心语言提议的概念支持, 并给出更好的错误消息.
