概念覆盖与原型

我们已经讨论过为组件的输入选择最小要求 (概念) 有多么重要, 但同样重要的是验证所选概念能否 覆盖 该算法. 也就是说, 任何可能的用户错误都应当被概念检查捕获, 而不能漏过去. 概念覆盖可以通过使用 原型类 (archetype class) 来验证. 原型类是与特定概念关联的接口的精确实现. 原型类的运行期行为并不重要, 其函数可以留空. 然后可以编写一个简单的测试程序, 以原型类作为组件的输入进行编译. 如果程序能编译通过, 就可以确定概念覆盖了该组件. 下面的代码给出了 Input Iterator 概念的原型类. 必须小心确保原型与概念精确匹配. 例如, 概念规定 operator*() 的返回类型必须可转换为值类型, 但并未规定更严格的要求, 即返回类型必须是 T& 或 const T&. 这意味着在原型类的返回类型上使用 T& 或 const T& 将是一个错误. 正确的做法是创建一个人工的、可转换为 T 的返回类型, 正如我们在这里用 reference 所做的那样. 原型类测试的有效性完全取决于它与概念精确匹配, 这必须通过仔细的 (人工) 检查来验证.

template <class T>
class input_iterator_archetype
{
private:
  typedef input_iterator_archetype self;
public:
  typedef std::input_iterator_tag iterator_category;
  typedef T value_type;
  struct reference {
    operator const value_type&() const { return static_object<T>::get(); }
  };
  typedef const T* pointer;
  typedef std::ptrdiff_t difference_type;
  self& operator=(const self&) { return *this;  }
  bool operator==(const self&) const { return true; }
  bool operator!=(const self&) const { return true; }
  reference operator*() const { return reference(); }
  self& operator++() { return *this; }
  self operator++(int) { return *this; }
};

泛型算法通常通过用若干常见输入类型实例化来进行测试. 例如, 可以以基本指针类型作为迭代器来调用 std::stable_sort(). 尽管这适合测试算法的运行期行为, 但对确保概念覆盖没有帮助, 因为 C++ 类型永远不会精确匹配特定概念. 相反, 它们通常提供比任何一个概念所需的最小功能更多的功能. 即使函数模板带有概念检查并能用给定类型编译, 这些检查仍可能不足以覆盖实际使用的全部功能. 这就是为什么除了用常见输入类型测试之外, 还要用原型类编译测试, 这一点很重要.

下面摘录自 stl_concept_covering.cpp, 展示了如何用原型类检查 std::stable_sort() 的要求文档. 在这个例子中, SGI STL 文档似乎遗漏了 CopyConstructible 和 Assignable 要求 (试着移除那些原型). Boost 的原型类经过设计可以分层. 在此例中, 迭代器的值类型由三个原型复合而成. 在 原型类参考中, 名为 Base 的模板参数指出了可以使用分层原型范式之处.

{
  typedef less_than_comparable_archetype< 
      sgi_assignable_archetype<> > ValueType;
  random_access_iterator_archetype<ValueType> ri;
  std::stable_sort(ri, ri);
}
