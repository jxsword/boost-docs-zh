创建概念检查类

作为如何创建概念检查类模板的示例, 我们看一下如何为 InputIterator 概念创建相应的检查. 完整定义如下:

template <class X>
struct InputIterator
  : Assignable<X>, EqualityComparable<X>
{
 private:
    typedef std::iterator_traits<X> t;
 public:
    typedef typename t::value_type value_type;
    typedef typename t::difference_type difference_type;
    typedef typename t::reference reference;
    typedef typename t::pointer pointer;
    typedef typename t::iterator_category iterator_category;

    BOOST_CONCEPT_ASSERT((SignedInteger<difference_type>));
    BOOST_CONCEPT_ASSERT((Convertible<iterator_category, std::input_iterator_tag>));
        
    BOOST_CONCEPT_USAGE(InputIterator)
    {
        X j(i);             // require copy construction
        same_type(*i++,v);  // require postincrement-dereference returning value_type
        X& x = ++j;         // require preincrement returning X&
    }
    
 private:
    X i;
    value_type v;

    // Type deduction will fail unless the arguments have the same type.
    template <typename T>
    void same_type(T const&, T const&);
};

逐步讲解

首先, 按照惯例, 我们以概念命名概念检查类. 其次, 由于 InputIterator 是 Assignable 和 EqualityComparable 的细化, 我们从这两个概念的检查类派生出它的概念检查类. 这样, 每当库检查 InputIterator 概念时, 它都会自动检查对 Assignable 和 EqualityComparable 的符合性.

接下来, 我们把概念的 关联类型声明为成员 typedef. 关联的 difference type 要求是有符号整数, 迭代器类别必须可转换为 std::input_iterator_tag, 因此我们断言这些关系. 通过概念检查模板访问关联类型的语法, 与 C++0x 中 提议的关联类型访问语法一致. 最后, 我们使用 BOOST_CONCEPT_USAGE 宏来声明练习该概念所有有效表达式的函数. 注意, 此时你有时需要一点创造性: 例如, 为了检查 *i++ 返回迭代器的值类型, 我们把两个值都传给 same_type 成员函数模板, 它要求两个实参类型相同 (引用和 cv 限定除外). 这是一个不完美的检查, 但总比没有好.

用法模式所需的值应声明为数据成员

你可能好奇为什么在上面的例子中我们把 i 和 v 声明为数据成员. 为什么不直接写成下面这样呢?

BOOST_CONCEPT_USAGE(InputIterator)
{
    X i;                // create the values we need
    value_type v;

    X j(i);             // require copy construction
    same_type(*i++,v);  // require postincrement-dereference returning value_type
    X& x = ++j;         // require preincrement returning X&
}

遗憾的是, 那样写效果并不好, 因为它会无意中施加这样的要求: X 及其值类型都必须可默认构造. 另一方面, 由于 InputIterator 模板的实例永远不会被构造, 编译器无需检查其数据成员将如何构造 (C++ 标准第 14.7.1 节第 9 条). 出于这个原因, 你应该 总是把用法模式所需的值声明为数据成员.

概念定义中的这类错误可以通过使用 概念原型 (Concept Archetypes) 来检测, 但最好还是预先避免它们.

与提议的 C++0x 概念语言支持的相似性

本库用于概念细化和关联类型访问的语法, 与 C++0x 中 提议的相应语法一致. 不过, C++0x 将使用 "签名" (signature) 而不是用法模式来描述参与概念的类型的有效操作, 因此在把你的概念检查类转换为语言支持的概念时, 你需要把用法函数翻译成一系列签名.
