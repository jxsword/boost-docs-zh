使用概念检查

每个概念都有一个概念检查类模板, 可用来确保给定类型 (或一组类型) 是该概念的模型. Boost 概念检查库 (BCCL) 包含 C++ 标准库中用到的所有概念的概念检查类模板, 还有一些额外的. 完整清单见 参考一节. 此外, 其他 Boost 库也自带针对这些库特有概念的概念检查类. 例如, 有 图概念和 属性映射概念. 而且, 任何人编写函数模板时, 只要需要表达尚未由现有概念陈述的要求, 就应当创建新的概念检查类. 具体做法在 创建概念检查类中说明.

BCCL 中概念检查类的一个例子是 EqualityComparableConcept 类. 该类对应 C++ 标准 20.1.1 节描述的 EqualityComparable 要求, 以及 SGI STL 文档中描述的 EqualityComparable 概念.

template <class T>
struct EqualityComparable;

模板实参是被检查的类型. 也就是说, EqualityComparable<T> 的目的是确保 T 是 EqualityComparable 概念的模型.

BOOST_CONCEPT_ASSERT()

检查概念要求的最灵活方式是使用 BOOST_CONCEPT_ASSERT() 宏. 你可以在任何作用域使用该宏, 只需传入括在圆括号中的概念检查模板特化. 注释: 这意味着 BOOST_CONCEPT_ASSERT 的调用形式上会使用 双层圆括号.

// In my library:
template <class T>
void generic_library_function(T x)
{
  BOOST_CONCEPT_ASSERT((EqualityComparable<T>));
  // ...
};

template <class It>
class generic_library_class
{
  BOOST_CONCEPT_ASSERT((RandomAccessIterator<It>));
  // ...
};

// In the user's code:  
class foo {
  //... 
};

int main() {
  foo x;
  generic_library_function(x);
  generic_library_class<std::vector<char>::iterator> y;
  //... 
}

BOOST_CONCEPT_REQUIRES

提议的 C++0x 声明受概念约束的函数模板的语法的一个优点是: 约束是函数 声明的一部分, 因而对客户可见. BOOST_CONCEPT_ASSERT 只能在函数模板定义内表达约束, 这把约束隐藏在函数体中. 除了损失自文档化接口之外, 仅在函数体内断言符合性还可能带来不理想的效果: 如果函数在与调用点不同的翻译单元中被显式实例化, 或者编译器进行链接期实例化, 检查会被不必要地推迟.

BOOST_CONCEPT_REQUIRES 宏可用于函数模板声明中, 检查某个类型是否是某个概念的模型. 它接受两个参数: 一个 约束列表和函数模板的返回类型. 约束列表的形式是若干相邻的概念检查模板特化组成的序列, 放在双层圆括号中, 函数的返回类型也必须加圆括号. 例如, 标准 stable_sort 算法可以这样声明:

template <class RanIter>
BOOST_CONCEPT_REQUIRES(
    ((Mutable_RandomAccessIterator<RanIter>))
    ((LessThanComparable<typename Mutable_RandomAccessIterator<RanIter>::value_type>)),
    (void)) // return type
    stable_sort(RanIter,RanIter);

请注意, 该算法要求迭代器的值类型是 LessThanComparable, 并且它通过 Mutable_RandomAccessIterator 概念检查模板访问该值类型. 一般而言, Boost 概念检查类把关联类型暴露为嵌套的成员 typedef, 使你可以使用这种语法, 它模仿了为 C++ 下一版本提议的概念支持所采用的方式.

多类型概念

有些概念涉及不止一个类型. 在这种情况下, 相应的概念检查类会有多个模板参数. 下面的例子展示了如何把 BOOST_CONCEPT_REQUIRES 与 ReadWritePropertyMap 概念配合使用, 该概念接受两个类型参数: 一个属性映射和该映射的键类型.

尽管概念检查是为泛型库实现者设计的, 它们对最终用户也很有用. 有时你可能不确定某个类型是否是特定概念的模型. 至少, 句法上的要求可以很容易地通过编写一个小程序, 并对相关的类型和概念使用 BOOST_CONCEPT_ASSERT 来检查. 例如:

// Make sure list<int> has bidirectional iterators.
BOOST_CONCEPT_ASSERT((BidirectionalIterator<std::list<int>::iterator>));
