内省函数模板技术

函数模板与函数一样, 可以是用户自定义类型中的实体. 正如用户自定义类型中的函数可以是成员函数或静态成员函数, 用户自定义类型中的函数模板可以是成员函数模板或静态成员函数模板. 在这个意义上, 函数模板与函数相关联. 函数模板表示一族可能的函数. 在这个意义上, 它们又与类模板相似, 类模板表示一族可能的类类型.

TTI 库内省类模板的技术取自 Boost MPL 库中该技术的实现. 对于使用模板类型参数形式的 BOOST_TTI_HAS_TEMPLATE, 它直接使用 Boost MPL 库的功能; 而对于使用特定形式的 BOOST_TTI_HAS_TEMPLATE, 它以类似方式复刻了 Boost MPL 库中的大部分技术. 内省类模板的这两种技术都直接依赖于 C++ 中可以使用所谓 “模板模板” 参数类型把模板作为参数传给另一个模板这一事实.

关于模板模板参数类型的一个显而易见的事实是, 它是类模板. 我们可以把类模板作为模板参数传递, 却不能把函数模板作为模板参数传递, 这正是为什么在编译期内省函数模板签名没有与内省类模板签名等效的方法.

使用实例化后的函数模板进行内省

虽然 TTI 无法内省函数模板签名, 但存在内省函数模板的替代方法. 只要该实例化中所有较低级别的单个类型在内省发生时都存在, 就可以在编译期检查嵌套函数模板的某个特定 实例化 是否存在而不产生编译器错误. 用更通俗的 C++ 术语来说, 我们把函数模板的实例化称为 “调用 (或 invoking) 函数模板”. 虽然在编译期检查嵌套函数模板的某个特定实例化是否存在并不能证明该嵌套函数模板本身具有特定签名 (因为即使嵌套函数模板确实存在, 实例化本身也可能失败), 但它提供了一种可行的内省函数模板的方法, 因为绝大多数函数模板都设计为接受任意类型并避免编译期失败. 而且, 当我们使用函数模板实例化来内省嵌套函数模板时, 我们复刻的正是 C++ 中函数模板的实际使用方式.

为了概括性地说明这在 TTI 库中如何工作, 我将给出一个用户自定义类型中嵌套函数模板的例子.

struct AType
  {
  template<class X,class Y,class Z> double AFuncTemplate(X x,Y * y,Z & z)
    { ...some code using x,y,z; return 0.0; }
  };

代码展示了名为 AType 的用户自定义结构体中的一个成员函数模板. 理想情况下, 我们希望能够验证 template<class X,class Y,class Z> double AFuncTemplate(X,Y *,Z &) 的函数模板签名存在于 AType 类型中, 但在 TTI 中做不到这一点. 如果我们调用 AFuncTemplate (在 AType 类型内的某个功能中), 我们会用一些实参替换 X,Y *,Z &, C++ 编译器就能推断出 X、Y 和 Z 的类型并创建要调用的函数.

如果从编译期编程 (又称模板元编程) 的角度来看, 我们真正关心的是: 是否存在名为 AFuncTemplate 的函数模板, 它位于名为 AType 的类型中, 并且可以以 X、Y 和 Z 类型作为某组类型被调用, 等价于以某组实参调用 AFuncTemplate. 假设我们想调用 AFuncTemplate, 以一个 int 值作为第一个实参、long * 作为第二个实参、一个 bool & 作为第三个实参. 那么用 TTI 的函数模板内省术语来说, 我们要做的就是检查是否能把函数模板实例化为:

double AFuncTemplate<int,long,bool>(int,long *,bool &)

这就是函数模板 AFuncTemplate 的单个可能实例化的形式. 当后文说明如何使用函数模板的实例化来检查内部函数模板是否存在时, 指的就是这个. 当我们内省函数模板时, 实例化本身并不存在, 但实例化签名的所有部分都会用于内省过程. 应当认识到, 我们可以使用有效类型或值的任意组合来创建给定函数模板的理论实例化, 只要这些类型和/或值能产生一个不含编译期错误的有效可调用函数.

我们在内省的函数模板实例化中使用的实际类型和/或值, 在做内省时必须已声明. 对内置类型而言这总是成立的. 如果出于某种原因, 我们在给定实例化中使用用户自定义类型, 那么在调用执行内省的元函数时, 该类型必须已声明.

文档的后续部分将分别说明如何使用函数模板的实例化来内省成员函数模板、静态成员函数模板或任意内部函数模板. 我们使用的技术与内省任何嵌套实体的方式非常相似, 只不过我们寻找的不是声明该嵌套实体的签名, 而是代表函数模板某个实例化的签名.
