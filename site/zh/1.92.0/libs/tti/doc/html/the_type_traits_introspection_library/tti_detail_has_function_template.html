内省函数模板

我们可以使用下面将要说明的 TTI 功能来内省用户自定义类型的成员函数模板或静态成员函数模板.

用户自定义类型的函数模板可以是成员函数模板或静态成员函数模板. 一个例子是:

struct AType
  {
  template<class X,class Y,class Z> double AFuncTemplate(X x,Y * y,Z & z)
    { ...some code using x,y,z; return 0.0; }
  template<class X,int Y> static int AFuncTemplate(X x)
    { ...some code using x; return Y; }
  };

函数模板 AFuncTemplate 是用户自定义类型 AType 的成员函数模板, 而另一个同样名为 AFuncTemplate 的函数模板是用户自定义类型 AType 的静态成员函数模板.

为了内省其中任一函数模板, 我们使用 AFuncTemplate 的一些理论上的有效实例化. 函数模板的实例化已在前文 “内省函数模板技术” 一节中说明.

为便于说明, 我们将使用的实例化是:

double AFuncTemplate<char,bool,int>(char,bool *,int &)

TTI 内省 template<class X,class Y,class Z> double AFuncTemplate(X,Y *,Z &) 结构体内的函数模板 AType 所需要的信息如下:

  • AFuncTemplate 的名称
  • char,bool,int 的模板参数
  • AType 的外围类型
  • double 的返回类型
  • char,bool *,int & 的函数参数

生成元函数

与 TTI 内省用户自定义类型中实体的所有功能一样, 内省函数模板是一个两步过程. 第一步是使用宏生成元函数. 用于函数模板的宏是 BOOST_TTI_HAS_FUNCTION_TEMPLATE. 该宏接受成员函数模板的名称和实例化后的模板参数, 即上面列表中的前两项:

BOOST_TTI_HAS_FUNCTION_TEMPLATE(AFuncTemplate,char,bool,int)

对于不支持变长宏的编译器, 也可以使用另一种形式 (同样适用于支持变长宏的编译器): 使用 Boost PP 数组将实例化的模板参数指定为单个宏参数:

BOOST_TTI_HAS_FUNCTION_TEMPLATE(AFuncTemplate,(3,(char,bool,int)))

该宏基于 “has_function_template_'name_of_inner_function_template'” 的模式生成元函数, 在本例中即为 has_function_template_AFuncTemplate.

调用元函数

要用该宏测试我们的函数模板是否存在, 可以用外围类型、实例化后的返回类型和实例化后的函数参数来调用该宏创建的元函数, 得到的 value 是一个编译期布尔常量: 若函数模板存在则为 true, 否则为 false. 我们将所需的各个类型作为独立参数传入, 函数参数则放在 MPL 前向序列中. 写法如下:

has_function_template_AFuncTemplate<AType,double,boost::mpl::vector<char,bool *,int &> >::value

内省另一个函数模板

如果我们选择尝试内省第二个 AFuncTemplate, 它位于 AType 内, 可以选择如下实例化:

int AFuncTemplate<long,7435>(long)

我们对元函数的生成将是:

BOOST_TTI_HAS_FUNCTION_TEMPLATE(AFuncTemplate,long,7435)

或者

BOOST_TTI_HAS_FUNCTION_TEMPLATE(AFuncTemplate,(2,(long,7435)))

而我们对元函数的调用现在是:

has_function_template_AFuncTemplate<AType,int,boost::mpl::vector<long> >::value

其他注意事项

在上面的两个示例中, 我们无法使用 BOOST_TTI_HAS_FUNCTION_TEMPLATE 宏在同一个命名空间中内省两个函数模板, 因为那样会生成两个同名的元函数, 即 has_function_template_AFuncTemplate, 从而违反单一定义规则 (ODR). 解决办法是使用复杂宏形式.

与 TTI 库中的其他宏一样, 用于生成内省函数模板的元函数的宏也有复杂宏形式, 最终用户可以直接指定要生成的元函数的名称. 对应的宏是 BOOST_TTI_TRAIT_HAS_FUNCTION_TEMPLATE, 其第一个参数是要生成的元函数的名称, 第二个参数是成员函数模板的名称, 其余参数是实例化后的模板参数.

对于第一个示例, 我们可以写:

BOOST_TTI_TRAIT_HAS_FUNCTION_TEMPLATE(FirstMetafunction,char,bool,int)

或者使用非变长宏形式:

BOOST_TTI_TRAIT_HAS_FUNCTION_TEMPLATE(FirstMetafunction,(3,(char,bool,int)))

它生成的元函数名称为 FirstMetafunction.

对于第二个示例, 我们可以写:

BOOST_TTI_TRAIT_HAS_FUNCTION_TEMPLATE(SecondMetafunction,AFuncTemplate,long,7435)

或者使用非变长宏形式:

BOOST_TTI_TRAIT_HAS_FUNCTION_TEMPLATE(SecondMetafunction,AFuncTemplate,(2,(long,7435)))

它生成的元函数名称为 SecondMetafunction.

在其他所有方面, 生成的元函数的工作方式与前面演示的较简单宏形式完全相同.

如果你确实使用简单宏形式 (它根据你要内省的函数模板的名称生成元函数名), 而又不想记住生成元函数名称的模式, 可以使用相应的宏, 以函数模板的名称作为单个参数来创建合适的元函数名. 该宏名为 BOOST_TTI_HAS_FUNCTION_TEMPLATE_GEN, 例如

BOOST_TTI_HAS_FUNCTION_TEMPLATE_GEN(AFuncTemplate)

它将生成名称 has_function_template_AFuncTemplate.

调用相应元函数时, 可以可选地给出第四个模板参数, 它持有一个 Boost FunctionTypes 标签类型. 这个可选模板参数对函数模板的用处远小于对非静态成员函数模板的用处, 因为静态成员函数模板与静态成员函数一样不能有 cv 限定, 而许多 Boost FunctionTypes 标签提供的正是这种限定. 尽管如此, 这个可选的 Boost FunctionTypes 标签仍可供最终用户使用, 在某些罕见情况下可能派上用场, 例如需要为函数模板指定某种调用约定限定时. 如果你确实使用用于 cv 限定的 Boost FunctionTypes 标签类型 (例如 boost::function_types::const_qualified) 来查找函数模板, 该标签将在匹配成员函数模板一侧的内省时生效, 但会确保匹配静态成员函数模板一侧的内省始终失败. 无论哪种情况都不会产生编译器错误.
