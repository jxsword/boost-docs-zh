内省内部类型

内省特定的用户自定义类型

TTI 宏 BOOST_TTI_HAS_TYPE 内省类的嵌套类型. 它内省的类型可以是 typedef, 或 C++11 及以上中的类型别名; 也可以是类/结构体、枚举或联合体等用户自定义类型.

BOOST_TTI_HAS_TYPE 宏接受单个参数, 即程序员想要检查其存在性的内部类型的名称. 该宏生成一个名为 “has_type_'name_of_inner_type'” 的元函数.

生成的元函数的主要目的是按名称检查内部类型的存在性. 该元函数还可用于调用以内部类型为参数的 MPL lambda 表达式. 这一附加功能最常见的用途之一是检查内部类型是否是另一个类型的别名 (通过 typedef 或类型别名).

通过向该元函数传入要内省的外围类型来调用它. 还可以向元函数传入第二个类型, 即接受内部类型并返回布尔常量的 MPL lambda 表达式.

该元函数返回一个名为 'type' 的单一类型, 它是一个 boost::mpl::bool_. 为方便起见, 元函数直接以名为 'value' 的编译期布尔常量返回该类型的值. 根据内部类型是否存在, 该值为 true 或 false.

如果传入了第二个可选类型, 该类型必须是 MPL lambda 表达式, 且仅当内部类型存在时才会调用该表达式. 此时元函数根据 MPL lambda 表达式返回 true 还是 false 而返回 true 或 false. 若内部类型不存在, 则即使指定了 MPL lambda 表达式也绝不会调用它, 元函数返回 false.

生成元函数

通过以内部类型的名称调用宏来生成元函数:

BOOST_TTI_HAS_TYPE(AType)

在当前作用域中生成一个名为 'has_type_AType' 的元函数.

调用元函数

通过以要内省的外围类型实例化模板 (可选地再传入一个 MPL lambda 表达式) 来调用元函数. 名为 'value' 的返回值是一个编译期布尔常量.

has_type_AType<Enclosing_Type>::value
has_type_AType<Enclosing_Type,ALambdaExpression>::value

示例

首先我们为各种内部类型名称生成元函数:

#include <boost/tti/has_type.hpp>

BOOST_TTI_HAS_TYPE(MyTypeDef)
BOOST_TTI_HAS_TYPE(AType)
BOOST_TTI_HAS_TYPE(ATypeDef)
BOOST_TTI_HAS_TYPE(MyType)

接下来让我们创建一些想要内省的用户自定义类型.

struct Top
  {
  typedef int MyTypeDef;
  struct AType { };
  };
struct Top2
  {
  typedef long ATypeDef;
  struct MyType { };
  };

最后我们调用元函数并得到值.

has_type_MyTypeDef<Top>::value;  // true
has_type_MyTypeDef<Top2>::value; // false

has_type_AType<Top>::value;  // true
has_type_AType<Top2>::value; // false

has_type_ATypeDef<Top>::value;  // false
has_type_ATypeDef<Top2>::value; // true

has_type_MyType<Top>::value;  // false
has_type_MyType<Top2>::value; // true

示例 — 使用 lambda 表达式

我们可以进一步以第二个类型 (一个 MPL lambda 表达式) 调用元函数.

MPL lambda 表达式是模板元编程中极为有用的技术, 它允许我们将一个元函数传给其他元函数. 我们传入的元函数可以是占位符表达式或元函数类的形式. 在我们的场景中, 作为 MPL lambda 表达式传给 has_type_'name_of_inner_type' 元函数的元函数必须返回布尔常量表达式.

示例 — 使用占位符表达式形式的 MPL lambda 表达式

我们将首先演示把占位符表达式形式的 MPL lambda 表达式作为第二个模板参数传给 has_type_'name_of_inner_type' 元函数的用法. 一个常用且简单的占位符表达式是 'boost::is_same<_1,SomeType>', 用于检查找到的内部类型是否为特定类型. 当内部类型是某个其他类型的 typedef 时这尤其有用.

首先, 为方便起见我们再包含一些头文件和一个 using 声明.

#include <boost/mpl/placeholders.hpp
#include <boost/type_traits/is_same.hpp
using namespace boost::mpl::placeholders;

接下来我们调用元函数:

has_type_MyTypeDef<Top,boost::is_same<_1,int> >::value; // true
has_type_MyTypeDef<Top,boost::is_same<_1,long> >::value; // false

has_type_ATypeDef<Top2,boost::is_same<_1,int> >::value; // false
has_type_ATypeDef<Top2,boost::is_same<_1,long> >::value; // true

示例 — 使用元函数类形式的 MPL lambda 表达式

接下来我们演示把元函数类形式的 MPL lambda 表达式作为第二个模板参数传给 has_type_'name_of_inner_type' 元函数的用法.

元函数类是拥有名为 'apply' 的嵌套类模板的类型. 在元函数类示例中, 我们将检查内部类型是否为内置整数类型. 首先让我们写出元函数类:

#include <boost/type_traits/is_integral.hpp>

class OurMetafunctionClass
  {
  template<class T> struct apply :
      boost::is_integral<T>
      {
      };
  };

现在可以调用元函数:

has_type_MyTypeDef<Top,OurMetafunctionClass>::value; // true
has_type_AType<Top,OurMetafunctionClass>::value; // false

has_type_ATypeDef<Top2,OurMetafunctionClass>::value; // true
has_type_MyType<Top2,OurMetafunctionClass>::value; // true

元函数的复用

该宏只编码了我们正在搜索的内部类型的名称, 以及我们正在外围类型中内省内部类型这一事实.

因此, 一旦我们创建了按名称内省内部类型的元函数, 就可以针对该名称, 将该元函数复用于内省任何拥有任何内部类型的外围类型.

此外, 由于我们只编码了要内省的内部类型的名称, 我们不仅可以按名称内省该内部类型, 还可以使用同一个元函数添加不同的 lambda 表达式来检查该内部类型, 以了解我们想知道的任何信息.

内省特定的用户自定义类型

正如可以使用 tti 在某个外围类、结构体或联合体中查找一般类型一样, 你也可以查找特定的用户自定义内部类型. 此功能的唯一区别是, 针对每种特定的用户自定义类型, 宏和生成元函数的默认名称会变化. 其余功能的工作方式与前面介绍查找一般内部类型时所述完全相同, 包括在找到特定内部类型时可选地使用 MPL lambda 表达式.

特定内部类型、对应的宏以及默认生成的元函数名称见下表:

表 1.3. TTI 特定内部类型

内部元素

简单宏

默认模板名称

类或结构体

BOOST_TTI_HAS_CLASS(name)

has_class_'name'

枚举

BOOST_TTI_HAS_ENUM(name)

has_enum_'name'

联合体

BOOST_TTI_HAS_UNION(name)

has_union_'name'


与一般类型一样, 你也可以分别使用复杂宏形式 BOOST_TTI_TRAIT_HAS_CLASS(trait,name)、BOOST_TTI_TRAIT_HAS_ENUM(trait,name) 与 BOOST_TTI_TRAIT_HAS_UNION(trait,name) 来直接生成元函数名称.

如果你以给定名称内省特定的用户自定义类型, 而找到的是具有该名称的其他类型, 元函数会返回预期的 'false' 值, 但不会产生编译器错误.

在其他所有方面, 针对特定内部用户自定义类型使用这些宏/元函数的工作方式与查找一般内部类型时所述完全相同. 特定内部类型功能为最终用户提供了比在外围用户自定义类型中查找一般类型更细粒度的内省设施.
