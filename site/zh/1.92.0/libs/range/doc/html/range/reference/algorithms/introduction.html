引言与动机

在最简单的形式中, Range Algorithm (范围算法) (或基于范围的算法) 只是把基于迭代器的算法中的 两个 迭代器实参替换为 一个 范围实参而已. 例如, 我们可以写

#include <boost/range/algorithm.hpp>
#include <vector>

std::vector<int> vec = ...;
boost::sort(vec);

而不是

std::sort(vec.begin(), vec.end());

然而, 范围算法的返回类型几乎总是与现有基于迭代器的算法不同.

有一组算法 (如 boost::sort()) 只是简单地返回相同的范围, 使我们可以继续传递该范围和/或进一步修改它. 因此我们可以写

boost:unique(boost::sort(vec));

以先对范围排序, 然后在已排序的范围上运行 unique()

诸如 boost::unique() 之类的算法属于另一组算法, 它们返回原范围的 (可能) 收窄的视图. 默认情况下, boost::unique(rng) 返回范围 [boost::begin(rng), found), 其中 found 表示 std::unique(boost::begin(rng), boost::end(rng)) 返回的迭代器

因此, 通过如下写法即可恰好拷贝那些唯一的值

boost::copy(boost::unique(boost::sort(vec)),
            std::ostream_iterator<int>(std::cout));

诸如 boost::unique 之类的算法通常返回范围: [boost::begin(rng), found) . 不过, 可以通过向算法提供一个 range_return_value 作为模板参数来改变这种行为:

表达式

Return

boost::unique<boost::return_found>(rng)

返回单个迭代器, 如 std::unique

boost::unique<boost::return_begin_found>(rng)

返回范围 [boost::begin(rng), found) (这是默认行为)

boost::unique<boost::return_begin_next>(rng)

返回范围 [boost::begin(rng), boost::next(found))

boost::unique<boost::return_found_end>(rng)

返回范围 [found, boost::end(rng))

boost::unique<boost::return_next_end>(rng)

返回范围 [boost::next(found),boost::end(rng))

boost::unique<boost::return_begin_end>(rng)

返回整个原始范围.

此功能有以下优点:

  1. 它支持 无缝的函数式风格编程, 无需使用命名的局部变量来存储中间结果
  2. 它非常 安全, 因为算法可以验证越界条件, 并处理导致空范围的棘手情形

例如, 考虑我们可以多么轻松地擦除已排序容器中的重复元素:

std::vector<int> vec = ...;
boost::erase(vec, boost::unique<boost::return_found_end>(boost::sort(vec)));

注意这里对 boost::return_found_end 的使用. 如果我们想擦除除其中一个之外的所有重复元素, 该怎么办? 在老式的 STL 编程中, 我们可能会写

// assume 'vec' is already sorted
std::vector<int>::iterator i = std::unique(vec.begin(), vec.end());

// remember this check or you get into problems
if (i != vec.end())
    ++i;

vec.erase(i, vec.end());

同样的任务可以简单地用如下方式完成

boost::erase(vec, boost::unique<boost::return_next_end>(vec));

而且无需担心生成无效的范围. 此外, 如果容器比较复杂, 多次调用 vec.end() 将比使用范围算法更昂贵.
