引言与动机

一个 Range Adaptor (范围适配器) 是包装现有范围以提供具有不同行为的新范围的类. 由于范围的行为由其关联的迭代器决定, Range Adaptor 只是用新的特殊迭代器包装底层迭代器. 在此示例中

#include <boost/range/adaptors.hpp>
#include <boost/range/algorithm.hpp>
#include <iostream>
#include <vector>

std::vector<int> vec;
boost::copy( vec | boost::adaptors::reversed,
             std::ostream_iterator<int>(std::cout) );

来自 vec 的迭代器被包装为 reverse_iterator 类的迭代器. 底层 Range Adapter 的类型未在文档中说明, 因为你无需知道它. 所有相关的是表达式

vec | boost::adaptors::reversed

返回一个 Range Adaptor, 其迭代器类型现在就是范围 vec 的迭代器类型, 包装于 reverse_iterator 之中. 表达式 boost::adaptors::reversed 被称为 Adaptor Generator (适配器生成器)

构造范围适配器有两种方式. 第一种是通过使用 operator|() . 这是我偏好的技术, 然而在与他人讨论范围适配器的过程中, 显然本库的一些用户强烈偏好更熟悉的函数语法, 因此添加了现在时形式的等价函数作为替代语法. 例如, 与 rng | reversed 等价的例如是 adaptors::reverse(rng).

为什么我偏好 operator| 语法? 答案是可读性:

std::vector<int> vec;
boost::copy( boost::adaptors::reverse(vec),
             std::ostream_iterator<int>(std::cout) );

这可能看起来还不算太糟, 但当我们应用多个适配器时, 情况会糟糕得多. 只需比较

std::vector<int> vec;
boost::copy( boost::adaptors::unique( boost::adaptors::reverse( vec ) ),
             std::ostream_iterator<int>(std::cout) );

to 

std::vector<int> vec;
boost::copy( vec | boost::adaptors::reversed
                 | boost::adaptors::uniqued,
             std::ostream_iterator<int>(std::cout) );

此外, 有些适配器生成器本身还接受实参, 而这些实参也用函数调用记法表达. 在这些情形下, 你会真正体会到 operator|() 的简洁.

适配器的组合

Range 适配器是 Range 算法的有力补充. 原因在于适配器与算法是 正交 的. 例如, 考虑这些 Range 算法:

  • boost::copy( rng, out )
  • boost::count( rng, pred )

如果我们只想在元素 a 满足某个谓词 (比如 pred(a)) 时才拷贝它, 该怎么办? 如果我们只想统计满足同一谓词的元素个数, 又该怎么办? 朴素的回答是使用这些算法:

  • boost::copy_if( rng, pred, out )
  • boost::count_if( rng, pred )

这些算法之所以被定义, 仅仅是为了与标准库算法保持一一对应. 这种添加算法的方式会遭受组合爆炸. 不可避免地, 许多算法缺少 _if 变体, 并且每新增一个算法都有冗余的开发开销. Adaptor Generator 正是针对该问题的设计方案. 可以设想, 某些算法能够通过将过滤器与算法紧密耦合来实现优化. 适配器提供了更通用的解决方案, 对正交关注点的分离也更胜一筹.

copy_if 算法的 Range 适配器替代方案 

boost::copy_if( rng, pred, out );

可表达为

boost::copy( rng | boost::adaptors::filtered(pred), out );

count_if 算法的 Range 适配器替代方案 

boost::count_if( rng, pred );

可表达为

boost::size( rng | boost::adaptors::filtered(pred) );

这意味着许多算法不再需要、也不再受益于带有 _if 后缀的优化实现. 此外, 事实证明带有 _copy 后缀的算法通常也不再需要. 考虑 replace_copy_if(), 它可以用作

std::vector<int> vec;
boost::replace_copy_if( rng, std::back_inserter(vec), pred, new_value );

利用适配器和算法, 我们可以将其表达为

std::vector<int> vec;
boost::push_back(vec, rng | boost::adaptors::replaced_if(pred, new_value));

后一种代码有以下几个优点:

1. 它更加 高效, 因为我们避免了像 std::back_inserter 那样可能发生的额外分配

2. 它 灵活, 因为随后还可以应用更多适配器, 例如:

boost::push_back(vec, rng | boost::adaptors::replaced_if(pred, new_value)
                          | boost::adaptors::reversed);

3. 它更 安全, 因为不使用无界输出迭代器.

通过这种方式, Range 适配器的 组合 会带来以下结果:

1. 我们不再需要算法的许多 _if, _copy, _copy_if 和 _n 变体.

2. 我们可以即时生成大量新算法, 例如, 上文我们生成了 reverse_replace_copy_if()

换言之:

Range 适配器之于算法, 就像算法之于容器
