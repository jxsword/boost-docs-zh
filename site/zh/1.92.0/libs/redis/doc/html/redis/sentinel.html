哨兵 (Sentinel)

Boost.Redis 支持 Redis 哨兵 (Sentinel) 部署. connection 中的 Sentinel 处理是内置的: async_run 会自动连接 Sentinel、解析主服务器地址并连接到主服务器.

配置使用 config::sentinel 完成:

config cfg;

// To enable Sentinel, set this field to a non-empty list
// of (hostname, port) pairs where Sentinels are listening
cfg.sentinel.addresses = {
    {"sentinel1.example.com", "26379"},
    {"sentinel2.example.com", "26379"},
    {"sentinel3.example.com", "26379"},
};

// Set master_name to the identifier that you configured
// in the "sentinel monitor" statement of your sentinel.conf file
cfg.sentinel.master_name = "mymaster";

设置完成后, 连接对象即可正常使用. 完整程序参见我们的 Sentinel 示例.

连接到副本

默认情况下, 库连接到 Redis 主服务器. 您可以使用 config::sentinel::server_role 连接到它的某个副本. 如果您的所有命令都只从服务器读取数据而从不写入, 这可用于平衡负载. 将随机选择特定的副本.

config cfg;

// Set up Sentinel
cfg.sentinel.addresses = {
    {"sentinel1.example.com", "26379"},
    {"sentinel2.example.com", "26379"},
    {"sentinel3.example.com", "26379"},
};
cfg.sentinel.master_name = "mymaster";

// Ask the library to connect to a random replica of 'mymaster', rather than the master node
cfg.sentinel.server_role = role::replica;

Sentinel 身份验证

如果您的 Sentinel 需要身份验证, 可以使用 config::sentinel::setup 提供凭据. 此请求在连接 Sentinel 后立即执行, 且在任何其他命令之前:

// Set up Sentinel
config cfg;
cfg.sentinel.addresses = {
    {"sentinel1.example.com", "26379"},
    {"sentinel2.example.com", "26379"},
    {"sentinel3.example.com", "26379"},
};
cfg.sentinel.master_name = "mymaster";

// By default, setup contains a 'HELLO 3' command.
// Override it to add an AUTH clause to it with out credentials.
cfg.sentinel.setup.clear();
cfg.sentinel.setup.push("HELLO", 3, "AUTH", "sentinel_user", "sentinel_password");

// cfg.sentinel.setup applies to Sentinels, only.
// Use cfg.setup to authenticate to masters/replicas.
cfg.use_setup = true; // Required for cfg.setup to be used, for historic reasons
cfg.setup.clear();
cfg.setup.push("HELLO", 3, "AUTH", "master_user", "master_password");

在 Sentinel 中使用 TLS

通过调整 config::sentinel::use_ssl 和 config::use_ssl, 您可以仅在 Sentinel 上使用 TLS、仅在主/从上使用 TLS, 或两者都用:

// Set up Sentinel
config cfg;
cfg.sentinel.addresses = {
    {"sentinel1.example.com", "26379"},
    {"sentinel2.example.com", "26379"},
    {"sentinel3.example.com", "26379"},
};
cfg.sentinel.master_name = "mymaster";

// Adjust these switches to enable/disable TLS
cfg.use_ssl = true;          // Applies to masters and replicas
cfg.sentinel.use_ssl = true; // Applies to Sentinels

Sentinel 算法

本节详细介绍 async_run 如何与 Sentinel 交互. 该算法的大部分遵循 官方 Sentinel 客户端指南. 这些细节可能因库版本而异.

  • 连接维护一个内部 Sentinel 列表, 由 config::sentinel::addresses 引导初始化.

  • 按以下步骤联系列表中的第一个 Sentinel:

    • 建立物理连接.

    • 执行 setup 请求.

    • 使用 SENTINEL GET-MASTER-NAME-BY-ADDR 解析主服务器地址.

    • 如果 config::sentinel::server_role 为 role::replica, 则使用 SENTINEL REPLICAS 获取副本地址. 随机选择一个副本.

    • 使用 SENTINEL SENTINELS 检索同样监视此主服务器的其他 Sentinel 的地址.

  • 如果某个 Sentinel 不可达、不知道所配置的主服务器, 或在执行上述请求时返回错误, 则尝试列表中的下一个 Sentinel.

  • 如果所有 Sentinel 都尝试失败, 则等待 config::reconnect_wait_interval, 然后重新开始该过程.

  • 成功收到 Sentinel 响应后, 内部 Sentinel 列表会更新为包含任何新发现的 Sentinel. config::sentinel::addresses 中的 Sentinel 始终保留在列表中, 即使它们未出现在 SENTINEL SENTINELS 的输出中.

  • 检索到的地址用于与主服务器或副本建立连接. 一条 ROLE 命令被添加到 setup 请求的末尾. 这用于检测 Sentinel 因故障转移进行中而返回过时信息的情形. 如果 ROLE 未输出预期的角色 ("master" 或 "slave", 取决于 config::sentinel::server_role) , 则等待 config::reconnect_wait_interval 并重新联系 Sentinel.

  • 与主/从的连接像任何其他连接一样运行. 如果发生网络错误或超时, 则等待 config::reconnect_wait_interval 并重新联系 Sentinel.
