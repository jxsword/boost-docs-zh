变更日志

Boost 1.92

  • (拉取请求 428) 修复了 connection 中的一处未定义行为: 当尝试取消一个已完成但其处理器尚未被调用的请求时会触发. 这是由于对 std::deque 的 erase-remove 用法不正确所致. 感谢 Lorentz-Andrea Romeo (@L0rentz) 提供修复.

  • (拉取请求 415) 优化了缓冲区轮转, 以降低当许多小消息在单个网络包中到达时的 CPU 消耗.

  • (拉取请求 424) 为 config 结构体中的所有成员添加了初始化器. 这使得可以使用指派初始化器 (designated initializers) 创建 config 对象.

  • (拉取请求 409) 从 CMake 中移除了独立 (standalone) 工作流. 这是一种未写入文档的以 CMake 使用 Boost.Redis 的方式, 仅面向内部开发.

Boost 1.91

  • (拉取请求 345、391 及 issue 237) 添加了对哨兵 (Sentinel) 部署的内置支持, 可使用 config::sentinel 进行配置. 库会自动处理主/从发现、错误检测与重连.

  • (拉取请求 340、356、358、378、383 及 issue 263) 添加了 generic_flat_response, 它是 flat_response 的高性能替代品, 使用连续内存并在稳态下零分配. 非常感谢 Nikolai Vladimirov 提交该 PR.

  • 对服务器推送处理的总体改进:

    • (拉取请求 375 及 issue 367) 添加了订阅跟踪支持, 它会在每次重连后恢复活动订阅. 可使用 request::subscribe、request::psubscribe、request::unsubscribe 和 request::punsubscribe 访问.

    • (拉取请求 390 及 issue 349) 添加了 push_parser, 这是一个便于解析 PubSub 相关消息的视图.

    • (拉取请求 381、340 及 issue 331) connection::async_receive 与 connection::receive 现已弃用. 用户应改用 async_receive2, 后者支持更快的批量处理.

    • consume_one 现已弃用. 用户应改用 generic_flat_response::clear. 更多细节请参见 PubSub 示例.

    • 改进了文档与示例.

  • (拉取请求 392) config::username、config::password、config::client_name 和 config::database_index 现已弃用. 用户应改用 config::setup. 添加了 request::hello 和 request::hello_setname 以简化 setup 请求的组装.

  • (拉取请求 389 及 issue 395) 日志消息级别已调整为更有针对性: level::error 用于配置与网络错误, level::info 用于连接成功, level::debug 用于详细输出.

  • (拉取请求 342 及 issue 341) 添加了 request::append(), 用于拼接请求对象.

  • (拉取请求 363 及 issue 360) 修复了 request::push_range 在传入包含 std::tuple 个元素的范围时会生成无效命令的问题.

  • (拉取请求 364 及 issue 361) 从公开头文件中移除了 <ostream>, 使其更加轻量.

Boost 1.90

  • (拉取请求 310) 改进了 async_exec() 中的按操作取消支持. 现在请求可在任意时刻被取消, 且取消不会以任何方式干扰其他请求. 在之前的版本中, 一次取消可能导致 async_run() 被取消, 使取消行为不可预测.

  • (Issue 226) 添加了对 asio::cancel_after 和 asio::cancel_at 完成标记的支持 (用于 async_exec() 和 async_run()) .

  • (Issue 319) 在 async_run() 中添加了对按操作取消的支持.

  • (拉取请求 329 和 334) cancel_on_connection_lost 与 cancel_if_not_connected 标志 (位于 request::config 中) 已被弃用, 并将在后续版本中移除. 要限制 async_exec 可能花费的时间, 请改用 asio::cancel_after. cancel_on_connection_lost 的默认值已改为 false. 这不会造成太大影响, 因为 cancel_on_connection_lost 并不是限制 async_exec 可能花费时间的可靠方式.

  • (拉取请求 321) 调用 cancel 时传入 operation::resolve、operation::connect、operation::ssl_handshake、operation::reconnection 和 operation::health_check 现已弃用. 这些枚举项将在后续版本中移除. 用户应改用 cancel(operation::run).

  • (Issue github.com/boostorg/redis/issues/302[302] 及拉取请求 303) 添加了对自定义 setup 请求的支持, 使用 config::setup 和 config::use_setup. 设置这些字段后, 用户可以将库生成的 HELLO 请求替换为任意其他请求. 该请求会在每次与服务器建立新的物理连接时执行. 此特性可用于与不支持 HELLO 的系统交互、处理身份验证以及连接到副本.

  • (拉取请求 305) request::config::hello_with_priority 与 request::has_hello_priority() 已被弃用, 并将在后续版本中移除. 该标志规范不明, 应当只由库自身使用. 如果您需要在任何其他请求之前执行一个请求, 请改用 config::setup.

  • (Issue 296) Valkey 长期支持: 自本版本起我们保证与 Valkey 兼容. 更早的版本也可能可用, 但未在该数据库系统上测试过.

  • (Issue 341) 添加了 request::append() 函数, 用于拼接请求对象.

  • (Issue 104) 健康检查算法已重新设计, 以避免高负载下的误报. PING 命令现在仅在连接空闲时发出, 而不是周期性地发出.

  • (拉取请求 283) 添加了 config::read_buffer_append_size, 用于控制连接读缓冲区的扩展.

  • (拉取请求 311) 添加了 usage::bytes_rotated, 用于衡量从服务器读取和解析数据时的数据拷贝.

  • (Issue 298) 添加了对空密码但非默认用户名的用户进行身份验证的支持.

  • (Issue 318) 修复了 cancel() 函数 (属于 connection 和 basic_connection) 中若干可能导致取消被忽略的竞态条件.

  • (Issue 290) 修复了 HELLO 期间发生的错误可能导致重连期间后续 HELLO 尝试失败的问题.

  • (Issue 297) HELLO 期间的错误现在会被正确记录.

  • (Issue 287) 修复了将包含中间错误的响应解析为 generic_response 时抛出异常的缺陷.

Boost 1.89

  • (拉取请求 256、266 和 273) connection 与 basic_connection 中的以下成员现已弃用, 并将在后续版本中移除:

  • next_layer() 与 next_layer_type: 没有理由直接访问底层流对象. 应改用连接的成员函数.

  • get_ssl_context(): 在从 SSL 上下文创建 asio::ssl::stream 对象之后, 绝不应再修改该上下文. 属性应在将上下文传递给构造函数之前设置好. 此后没有理由再访问该 SSL 上下文.

  • reset_stream(): 连接内部实现已重构为在需要时自动重置 SSL 流. 该函数现在是空操作 (no-op) .

  • 不接受任何参数的 async_run() 重载: 请改用 async_run 重载, 并显式传入一个 config 对象.

  • (Issue 213) 日志接口已重写:

  • 现在可以通过向 logger 构造函数传递函数对象来自定义日志. 这允许与第三方日志库 (如 spdlog) 集成. 这一新日志接口是公开的, 并将长期维护.

  • 由 logger::on_xxx 函数构成的旧的不稳定接口已被移除.

  • connection 与 basic_connection 构造函数现在接受一个 logger 对象. 这是现在配置日志的首选方式. async_run() 重载 (接受 logger 对象) 现已弃用, 并将在后续版本中移除.

  • config::log_prefix 现已弃用, 并将在后续版本中移除. 用户可以通过向 logger 构造函数传递自定义日志函数来达到同样的效果.

  • 默认日志函数 (输出到 stderr) 现在基于 printf, 因而是线程安全的. 旧函数使用 std::cerr, 在多线程程序中可能导致输出交错.

  • 默认日志级别现在是 logger::level::info, 低于原先的 logger::level::debug. 这使得默认输出不再那么冗长.

  • (Issue 272) 添加了对使用 UNIX 域套接字连接 Redis 的支持. 可使用 config::unix_socket 访问该特性.

  • (Issue 255) 修复了 async_run 在遇到连接建立错误时即完成的问题 (即使 config::reconnect_wait_interval 指定了重连) .

  • (Issue 265) connection::async_exec 现在使用 ignore 作为默认响应, 而不是没有默认响应. 这与 basic_connection::async_exec 的行为一致.

  • (Issue 260) 修复了影响在 config::log_prefix 中配置的日志器前缀的内存损坏问题.

  • (拉取请求 254) 修复了一些关于未使用变量、名字遮蔽和窄化转换的警告.

  • (Issue 252) 修复了重连会忽略在 config::reconnect_wait_interval 中配置的重连等待时间的缺陷.

  • (Issue 238) 修复了 Boost 1.88 中引入的一个缺陷, 该缺陷导致 response<T> 对某些整数类型无法编译.

  • (Issue 247) 文档已完成现代化改造, 并添加了更完整的参考章节.

  • 对部分内部实现进行了重构, 以便更好地进行测试并缩短编译时间.

Boost 1.88

  • (Issue 233) 为了处理可能在 Redis 服务器中不存在的键, 库支持 std::optional, 例如 response<std::optional<std::vector<std::string>>>. 但在某些情况下, 例如 MGET 命令, 向量中的每个元素都可能不存在, 现在可以将响应指定为 response<std::optional<std::vector<std::optional<std::string>>>>.

  • (Issue 225) 使用 deferred 作为连接的默认完成标记.

  • (Issue 128) 添加了一个新的 async_exec 重载, 允许传递响应适配器. 这使得可以直接在自定义数据结构中接收 Redis 响应, 从而避免不必要的数据拷贝. 感谢 Ruben Perez (@anarthal) 实现此特性.

  • 本版本还包含其他多项小改进, 用户可查阅 git 历史了解更多细节.

Boost 1.87

  • (Issue 205) 通过使用 wait_for_one_error 替代 wait_for_all, 改进了对断连的反应时间. 函数 connection::async_run 也已改为在从服务器收到该错误时向用户返回 EOF. 这是一项破坏性变更.

  • (Issue 210) 修复了空嵌套响应的适配器.

  • (Issues 211 和 212) 修复了在某些条件下会挂起的重连循环, 更多细节参见所链接的 issue.

  • (Issue 219) 将默认日志级别从 disabled 改为 debug.

Boost 1.85

  • (Issue 170) 在高负载和低延迟网络下, 可能在写操作完成之前、请求仍被标记为暂存 (staged) 未写入时就开始接收响应. 这会干扰将响应分类为是否为主动推送 (unsolicited) 的启发式判断.

  • (Issue 168) . 提供了一种向连接传递自定义 SSL 上下文的方式. 此处的设计与 Boost.Beast 和 Boost.MySql 的设计不同, 因为在 Boost.Redis 中连接拥有该上下文, 而不是仅存储对用户提供的上下文的引用. 这样做是可以的, 因为整个应用程序只需一个连接, 这使得每个连接一个 SSL 上下文的开销可以忽略不计.

  • (Issue 181) . 关于该缺陷的详细描述参见 此评论.

  • (Issue 182) . 将 "default" 设为 config::username 的默认值. 这使得在 Redis 中使用 requirepass 配置更为简单.

  • (Issue 189) . 通过使用 std::size_t 替代 std::uint64_t 来表示批量 (bulk) 与聚合 (aggregate) 的大小, 修复了窄化转换问题. 现在代码依赖 std::from_chars 在 std::size_t 大小为 32 的平台上收到大于 32 的值时返回错误.

Boost 1.84 (首次进入 Boost 的发布)

  • 弃用了接受响应的 async_receive 重载. 用户现在应先调用 set_receive_response, 以避免不断且不必要地设置相同的响应.

  • 使用 std::function 对响应适配器进行类型擦除. 这一变更不应以任何方式影响用户, 但使连接内部实现得到重要简化, 从而带来了大幅性能提升.

  • 连接新增了成员 get_usage(), 用于返回连接使用信息, 例如写入、接收的字节数等.

  • 服务器推送的消费有大幅性能改进: 推送现在通过 asio::channel 传达, 因此可以缓冲, 从而避免阻塞套接字读取循环. 通过 channel.try_send 也支持批量读取, 缓冲的消息可用 connection::receive 同步消费. 添加了函数 boost::redis::cancel_one, 以简化处理同一个 generic_response 中包含的多个服务器推送. 重要: 这些变更可能导致 connection::async_receive 恢复时响应中包含不止一个推送. 因此用户在调用 resp.clear() 时必须小心: 要么确保所有消息都已处理, 要么直接使用 consume_one.

v1.4.2 (纳入了为符合 Boost 评审要求所做的修改等)

  • 添加了 boost::redis::config::database_index, 使得在开始运行命令之前 (例如在自动重连之后) 可以选择数据库.

  • 大幅性能提升. 我的一项测试从 140k req/s 提升到 390k/s. 这得益于一次解析器简化, 减少了重新调度和缓冲区轮转的次数.

  • 添加了 Redis stream 示例.

  • 将项目更名为 Boost.Redis, 并将代码移入命名空间 boost::redis.

  • 正如评审中所指出的, to_bulk 与 from_bulk 这两个名称对于 ADL 定制点来说过于泛化. 它们加上了前缀 boost_redis_.

  • 将 boost::redis::resp3::request 移至 boost::redis::request.

  • 添加了新的 typedef boost::redis::response, 应使用它替代 std::tuple.

  • 添加了新的 typedef boost::redis::generic_response, 应使用它替代 std::vector<resp3::node<std::string>>.

  • 将 redis::ignore 更名为 redis::ignore_t.

  • 更改了 async_exec, 使其接收 redis::response 而不是适配器, 也就是说, 用户不应再传递 adapt(resp), 而应直接传递 resp.

  • 引入 boost::redis::adapter::result, 用于存储对命令的响应 (包括可能的 resp3 错误) 而不丢失错误诊断部分. 现在访问值应使用 std::get<N>(resp).value() 而不是 std::get<N>(resp).

  • 实现了全双工通信. 在这些变更之前, 连接会等待响应到达后再发送下一个请求. 现在请求会被持续合并并写入套接字. request::coalesce 变得不再必要, 已被移除. 通过这些变更我可以测量到显著的性能提升.

  • 改进了使用 Boost.Describe 序列化为 JSON 和 protobuf 的示例. 更多细节参见 cpp20_json.cpp 和 cpp20_protobuf.cpp.

  • 升级到 Boost 1.81.0.

  • 修复了使用 libc++ 的构建.

  • 为连接类添加了高层功能. 例如, boost::redis::connection::async_run 会自动进行解析、连接、重连并执行健康检查.

v1.4.0-1

  • 将 retry_on_connection_lost 更名为 cancel_if_unresponded. (v1.4.1)

  • 移除了对 Boost.Hana、boost::string_view、Boost.Variant2 和 Boost.Spirit 的依赖.

  • 修复构建并在 Windows 上搭建 CI.

v1.3.0-1

  • 升级到 Boost 1.80.0

  • 移除了 HELLO 命令的自动发送. 若不使连接类臃肿, 就无法恰当地实现该功能. 现在发送 HELLO 是用户的责任. 包含它的请求优先于其他请求, 并被移到队列前端, 参见 aedis::request::config

  • 自动名称解析与连接已从 aedis::connection::async_run 中移除. 用户现在必须手动执行这一步骤. 做出这一变更的原因是内置这些功能无法为 Boost 用户提供所需的足够灵活性.

  • 移除了健康检查和空闲超时. 这些功能现在必须由用户实现, 参见示例. 这是让 Aedis 对更广泛的受众有用并适合 Boost 评审流程的一部分工作.

  • aedis::connection 现在使用指向 net::ip::tcp::socket 的 typedef, aedis::ssl::connection 则指向 net::ssl::stream<net::ip::tcp::socket>. 需要使用其他流类型的用户现在必须特化 aedis::basic_connection.

  • 添加了一个底层异步代码示例.

v1.2.0

  • aedis::adapt 现在支持用 std::tie 创建的元组. aedis::ignore 现在是 std::ignore 类型的别名.

  • 为 aedis::connection 类中使用的内部队列提供了分配器支持.

  • 更改了 async_run 的行为: 如果收到 asio::error::eof 则以成功完成. 这使得用 awaitable 运算符编写组合操作更加容易.

  • 在 aedis::request 中添加了分配器支持 (由 Klemens Morgenstern 贡献) .

  • 将 aedis::request::push_range2 更名为 push_range. 后缀 2 曾用于消歧. Klemens 用 SFINAE 解决了这个问题.

  • 将 fail_on_connection_lost 更名为 aedis::request::config::cancel_on_connection_lost. 现在, 只有当 async_run 完成时它才会导致连接被取消.

  • 引入了 aedis::request::config::cancel_if_not_connected: 如果在连接建立之前调用了 async_exec, 请求将被取消.

  • 引入了新的请求标志 aedis::request::config::retry: 若设为 true, 当请求已发送到 Redis 但在 async_run 完成后仍未得到响应时, 该请求将不会被取消. 它提供了一种避免重复执行命令的方式.

  • 移除了以请求和适配器为参数的 aedis::connection::async_run 重载.

  • 更改了 aedis::adapt() 在 std::vector<aedis::resp3::node<T>> 下的行为. 收到 RESP3 简单错误、blob 错误或 null 不再引发错误, 而是会作为普通响应处理. 检查向量中的内容是用户的责任.

  • 修复了 connection::cancel(operation::exec) 中的一个缺陷. 现在该调用只会取消尚未写入的请求.

  • 为 aedis::connection::async_exec 实现了按操作隐式取消支持. 下面的调用 co_await (conn.async_exec(…​) || timer.async_wait(…​)) 将取消请求, 只要它尚未被写入.

  • 将 aedis::connection::async_run 的完成签名更改为 f(error_code). 过去就是这样的, 第二个参数没有什么用处.

  • 将 operation::receive_push 更名为 aedis::operation::receive.

v1.1.0-1

  • 将 coalesce_requests 从 aedis::connection::config 中移除, 它现在是请求属性, 参见 aedis::request::config::coalesce.

  • 将 max_read_size 从 aedis::connection::config 中移除. 现在最大读取大小可以作为 aedis::adapt() 函数的参数指定.

  • 移除了 aedis::sync 类, 关于如何执行同步且线程安全的调用请参见 intro_sync.cpp. 只有在 Boost 1.80 中才可能实现, 因为它需要 boost::asio::deferred.

  • 从 boost::optional 迁移到 std::optional. 这是迁移到 C++17 的一部分.

  • 更改了第二个 aedis::connection::async_run 重载的行为, 使其在连接丢失时总是返回错误.

  • 添加了 TLS 支持, 参见 intro_tls.cpp.

  • 添加了一个展示如何通过哨兵 (Sentinel) 解析地址的示例, 参见 subscriber_sentinel.cpp.

  • 添加了 aedis::connection::timeouts::resp3_handshake_timeout. 这是用于发送 HELLO 命令的超时时间.

  • 添加了 aedis::endpoint, 除主机和端口外, 用户还可选择提供用户名、密码以及预期的服务器角色 (参见 aedis::error::unexpected_server_role) .

  • aedis::connection::async_run 检查 hello 命令中收到的服务器角色是否与 aedis::endpoint 中指定的预期服务器角色相等. 要跳过此检查, 请将 role 变量留空.

  • 从 aedis::connection 中移除了重连功能. 在简单的重连策略中可行, 但在更复杂的场景下 (例如有哨兵 (Sentinel) 、身份验证和 TLS 时) 会使类变得臃肿. 这在单独的协程中实现起来很简单. 因此 enum event 与 async_receive_event 也已从该类中移除.

  • 修复了 connection::async_receive_push 中一个阻止传递 adapt(std::vector<node>) 以外的任何响应适配器的缺陷.

  • 更改了 aedis::adapt() 导致 RESP3 错误被忽略的行为. 其后果之一是 connection::async_run 在要求身份验证的服务器上不会以失败退出.

  • 更改了 connection::async_run 在 connection::async_exec 中发生错误时会以成功完成的行为.

  • 将构建系统从 autotools 移植到 CMake.

v1.0.0

  • 为 Windows 用户添加了实验性的 CMake 支持.

  • 添加了新类 aedis::sync, 它以线程安全的同步 API 封装 aedis::connection. sync.hpp 中的所有自由函数现在是 aedis::sync 的成员函数.

  • 将 aedis::connection::async_receive_event 拆分为两个函数, 一个用于接收事件, 另一个用于服务器端推送, 参见 aedis::connection::async_receive_push.

  • 消除了 aedis::adapter::adapt 与 aedis::adapt 之间的冲突.

  • 添加了 connection::operation 枚举, 用一个接收应取消操作作为参数的取消函数替代 cancel_* 成员函数.

  • 缺陷修复: 修复了在 connection 对象有未发送命令的状态下重连的一个缺陷. 在某些条件下它可能导致 async_exec 永不完成.

  • 缺陷修复: adapt() 函数的文档在 Doxygen 中缺失.

v0.3.0

  • 添加了 experimental::exec 与 receive_event 函数, 以线程安全的同步方式跨线程执行请求. 示例参见 intro_sync.cpp 和 subscriber_sync.cpp.

  • connection::async_read_push 已更名为 async_receive_event.

  • connection::async_receive_event 现在用于向用户传达内部事件, 如解析、连接、推送等. 示例参见 cpp20_subscriber.cpp 和 connection::event.

  • aedis 目录已移至 include, 以便看起来更接近 Boost 库的风格. 用户现在应在编译器标志中将 -I/aedis-path 替换为 -I/aedis-path/include.

  • AUTH 与 HELLO 命令现在会自动发送. 实现重连需要这一变更. AUTH 中使用的用户名和密码应由用户在 connection::config 上提供.

  • 添加了重连支持. 参见 connection::enable_reconnect.

  • 修复了 connection::async_run(host, port) 重载中导致重连时崩溃的缺陷.

  • 修复了连接类中执行器的使用. 在这些变更之前, 它会向用户强加 any_io_executor.

  • connection::async_receiver_event 在 connection::async_run 退出时不再被取消. 此变更使用户代码更简单.

  • connection::async_exec 的主机和端口重载已被移除. 请使用另一个 connection::async_run 重载.

  • connection::async_run 中的主机和端口参数已被移至 connection::config, 以更好地支持身份验证和故障转移.

  • chat_room 示例中做了许多简化.

  • 修复了 clang 编译器下的构建, 并对文档做了一些改进.
