boost::redis::basic_connection::async_run

启动底层连接操作.

概要

声明于 <boost/redis/connection.hpp>

template<class CompletionToken = asio::default_completion_token_t<executor_type>>
auto
async_run(
    config const& cfg,
    CompletionToken&& token = {});

说明

此函数建立到 Redis 服务器的连接, 并通过执行以下操作来保持其健康:

  • 对于哨兵 (Sentinel) 部署 (config::sentinel::addresses 非空) , 会联系 Sentinel 以获取所配置主服务器 (master) 的地址.

  • 对于 TCP 连接, 解析在 boost::redis::config::addr 中传入的服务器主机名.

  • 建立与服务器的物理连接. 对于 TCP 连接, 连接到名称解析得到的端点之一. 对于 UNIX 域套接字连接, 则连接到 boost::redis::config::unix_socket.

  • 如果 boost::redis::config::use_ssl 为 true, 则执行 TLS 握手.

  • 执行由传入的 config 对象定义的 setup 请求. 默认情况下, 这是一条 HELLO 命令, 但也可以包含任何其他任意命令. 更多信息参见 config::setup 文档.

  • 启动一个健康检查操作, 其中 PING 命令会在连接空闲时按 config::health_check_interval 指定的时间间隔发送. 更多信息参见 config::health_check_interval 的文档.

  • 启动读写操作. 使用 async_exec 发出、且在 async_run 被调用之前发出的请求会立即写入服务器.

当连接因任何原因丢失时, 会自动建立新连接. 要禁用重连, 请将 boost::redis::config::reconnect_wait_interval 设置为零.

完成标记必须具有以下签名

void f(system::error_code);

按操作取消

此操作支持以下取消类型:

  • asio::cancellation_type_t::terminal.

  • asio::cancellation_type_t::partial.

在两种情况下, 取消都等价于调用 basic_connection::cancel 并以 operation::run 作为参数.

操作完成后, 标记关联的取消槽可能仍保有与此连接关联的取消处理器. 您应确保在连接被销毁之后不要调用它. 这与其他 Asio I/O 对象的行为一致.

关于如何调用此函数的示例, 请参阅 cpp20_intro.cpp 或任何其他示例.
