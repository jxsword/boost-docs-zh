请求与响应

请求

Redis 请求由一条或多条命令组成. 在 Redis 文档中, 请求被称为 流水线. 例如:

// Some example containers.
std::list<std::string> list {...};
std::map<std::string, mystruct> map { ...};

// The request can contain multiple commands.
request req;

// Command with variable length of arguments.
req.push("SET", "key", "some value", "EX", "2");

// Pushes a list.
req.push_range("SUBSCRIBE", list);

// Same as above but as an iterator range.
req.push_range("SUBSCRIBE", std::cbegin(list), std::cend(list));

// Pushes a map.
req.push_range("HSET", "key", map);

如前所述, 向 Redis 发送请求通过 connection::async_exec 完成. 请求在构造时接受一个 boost::redis::request::config 对象, 该对象规定在重连等情形下如何处理请求. 建议读者仔细阅读它.

响应

Boost.Redis 使用以下策略处理 Redis 响应:

  • boost::redis::response 应在请求的命令数量于编译期已知时使用.

  • boost::redis::generic_response 应在命令数量是动态的时候使用.

例如, 下面的请求包含三条命令:

request req;
req.push("PING");
req.push("INCR", "key");
req.push("QUIT");

因此, 它的响应也将包含三个元素. 可以使用以下响应对象:

response<std::string, int, std::string>

响应的行为类似 std::tuple, 其元素数量必须与请求中的命令数量相同 (例外见下文) . 此外, 每个元组元素必须能够存储它所对应命令的响应, 否则将发生错误.

要忽略请求中单个命令的响应, 请使用标记 boost::redis::ignore_t. 例如:

// Ignore the second and last responses.
response<std::string, ignore_t, std::string, ignore_t>

例如, 对以下请求的响应

request req;
req.push("HELLO", 3);
req.push_range("RPUSH", "key1", vec);
req.push_range("HSET", "key2", map);
req.push("LRANGE", "key3", 0, -1);
req.push("HGETALL", "key4");
req.push("QUIT");

可以在以下响应对象中读取:

response<
   redis::ignore_t,  // hello
   int,              // rpush
   int,              // hset
   std::vector<T>,   // lrange
   std::map<U, V>,   // hgetall
   std::string       // quit
> resp;

要执行请求并读取响应, 请使用 async_exec:

co_await conn->async_exec(req, resp);

如果想完全忽略响应, 请使用 ignore:

// Ignores the response
co_await conn->async_exec(req, ignore);

包含嵌套聚合或异构数据类型的响应将在后面的 一般情形 一节中获得特殊处理. 截至撰写本文时, Redis 服务器并未使用所有 RESP3 类型, 这意味着实际上用户只需关注 RESP3 规范的一个缩减子集.

推送

没有响应的命令, 例如

  • "SUBSCRIBE"

  • "PSUBSCRIBE"

  • "UNSUBSCRIBE"

不得包含在响应元组中. 例如, 以下请求

request req;
req.push("PING");
req.subscribe({"channel"});
req.push("QUIT");

必须在响应对象 response<std::string, std::string> 中读取.

Null

应用程序访问 Redis 服务器中不存在的键或已过期的键的情况并不少见. 为处理这些用例, 请将该类型用 std::optional 包裹:

response<
   std::optional<A>,
   std::optional<B>,
   ...
   > resp;

其余一切保持不变.

事务

要读取事务的响应, 我们必须首先注意到 Redis 会将事务命令排队, 并将它们各自的响应作为数组的元素发送. 该数组本身是对 EXEC 命令的响应. 例如, 要读取以下请求的响应

req.push("MULTI");
req.push("GET", "key1");
req.push("LRANGE", "key2", 0, -1);
req.push("HGETALL", "key3");
req.push("EXEC");

使用以下响应类型:

response<
   ignore_t,  // multi
   ignore_t,  // QUEUED
   ignore_t,  // QUEUED
   ignore_t,  // QUEUED
   response<
      std::optional<std::string>, // get
      std::optional<std::vector<std::string>>, // lrange
      std::optional<std::map<std::string, std::string>> // hgetall
   > // exec
> resp;

完整示例参见 cpp20_containers.cpp.

一般情形

有些情况下对 Redis 命令的响应不适合上述模型. 一些例子如下:

  • 响应没有固定 RESP3 类型的命令 (如 set) . 期望 int 却收到 blob-string 会导致错误.

  • 包含嵌套聚合的 RESP3 聚合无法读入 STL 容器.

  • 命令数量动态的事务无法读入 response.

为处理这些情况, Boost.Redis 提供了 boost::redis::resp3::node 类型抽象, 它是响应中元素的最一般形式, 无论是简单 RESP3 类型还是聚合的元素. 其定义如下:

template <class String>
struct basic_node {
   // The RESP3 type of the data in this node.
   type data_type;

   // The number of elements of an aggregate (or 1 for simple data).
   std::size_t aggregate_size;

   // The depth of this node in the response tree.
   std::size_t depth;

   // The actual data. For aggregate types this is always empty.
   String value;
};

对 Redis 命令的任何响应都可以解析为 boost::redis::generic_response 及其对应物 boost::redis::generic_flat_response. 该向量可以看作响应树的前序视图. 它的用法与其他类型没有区别:

// Receives any RESP3 simple or aggregate data type.
boost::redis::generic_response resp;
co_await conn->async_exec(req, resp);

例如, 假设我们想用 HGETALL 从 Redis 检索一个哈希数据结构, 可选方案有

  • boost::redis::generic_response 和 boost::redis::generic_flat_response: 总是有效.

  • std::vector<std::string>: 高效且平坦, 所有元素均为字符串.

  • std::map<std::string, std::string>: 如果您需要将数据作为 std::map 使用, 则很高效.

  • std::map<U, V>: 如果您存储的是序列化数据, 则很高效. 避免临时对象, 且需要 boost_redis_from_bulk 来支持 U 和 V.

除上述之外, 用户还可以使用容器的无序版本. 同样的推理也适用于集合 (例如 SMEMBERS) 以及一般的其他数据结构.
