has_not_equal_to 

template <class Lhs, class Rhs=Lhs, class Ret=dont_care>
struct has_not_equal_to : public true_type-or-false_type {};

继承自: 若 (i) lhs (其类型为 Lhs) 与 rhs (其类型为 Rhs) 可用于表达式 lhs!=rhs, 并且 (ii) Ret=dont_care 或表达式 lhs!=rhs 的结果可转换为 Ret, 则继承自 true_type, 否则继承自 false_type.

默认行为 (Ret=dont_care) 是不检查二元运算符 operator!=的返回值. 如果 Ret 不同于默认的 dont_care 类型, 则会检查返回值能否转换为 Ret. 可转换为 Ret 意味着运算符的返回值可用作期望 Ret的函数的实参:

void f(Ret);
Lhs lhs;
Rhs rhs;
f(lhs!=rhs); // is valid if has_not_equal_to<Lhs, Rhs, Ret>::value==true

如果 Ret=void, 则会检查返回类型是否恰好为 void.

头文件: #include <boost/type_traits/has_not_equal_to.hpp> 或 #include <boost/type_traits/has_operator.hpp> 或 #include <boost/type_traits.hpp>

编译器兼容性: 要求可正常工作的 SFINAE (即未设置 BOOST_NO_SFINAE). 只有少数相当老的编译器不支持这一点.

示例:

has_not_equal_to<Lhs, Rhs, Ret>::value_type 是类型 bool.

has_not_equal_to<Lhs, Rhs, Ret>::value 是一个 bool 整型常量表达式.

has_not_equal_to<int>::value 是一个 bool 整型常量表达式, 求值为 true.

has_not_equal_to<long> 继承自 true_type.

has_not_equal_to<int, int, bool> 继承自 true_type.

has_not_equal_to<int, double, bool> 继承自 true_type.

has_not_equal_to<const int> 继承自 true_type.

has_not_equal_to<int*, int> 继承自 false_type.

has_not_equal_to<int*, double*> 继承自 false_type.

has_not_equal_to<int, int, std::string> 继承自 false_type.

参见: 运算符类型特征

已知问题:

对于现代编译器 (支持任意 SFINAE 表达式和 decltype/declval 的编译器), 该特征提供近乎完美的检测. 在这种情况下, 宏 BOOST_TT_HAS_ACCURATE_BINARY_OPERATOR_DETECTION 在包含 <boost/type_traits/has_not_equal_to.hpp>之后将被定义. 但请注意, 检测仅基于函数签名; 如果该运算符是函数模板, 则 has_not_equal_to 无法对模板函数体进行内省, 以确保该类型满足实际代码的全部概念要求.

示例:

#include <boost/type_traits/has_not_equal_to.hpp>
#include <iostream>

template <class T>
struct contains
{
   T data;
   contains(const T& d) : data(d) {}
};

template <class T>
bool operator != (const contains<T> &lhs, const contains<T> &rhs) {
    return f(lhs.data, rhs.data);
}

class bad { };
class good { };
good f(const good&, const good&) { return /*something*/; }

int main() {
    std::cout<<std::boolalpha;
    // works fine for contains<good>
    std::cout<<boost::has_not_equal_to< contains< good > >::value<<'\n'; // true
    contains<good> g;
    g&g; // ok
    // does not work for contains<bad>
    std::cout<<boost::has_not_equal_to< contains< bad > >::value<<'\n'; // true, should be false
    contains<bad> b;
    b&b; // compile time error
    return 0;
}

对于较老的编译器 (BOOST_TT_HAS_ACCURATE_BINARY_OPERATOR_DETECTION 未定义), 存在以下若干问题:

  • 该特征无法检测二元运算符 operator!= 是否为公有: 如果 operator!= 被定义为 Lhs 的私有成员, 那么实例化 has_not_equal_to<Lhs> 将导致编译器错误. 因此, has_not_equal_to 不能用于判定某个类型是否拥有公有的 operator!=.
struct A { private: bool operator != (const A&); };
boost::has_not_equal_to<A>::value; // error: A::operator != (const A&) is private
  • 如果该运算符只对类型 A 存在, 而 B 可以转换为 A, 则存在一个问题: 此时编译器会报告重载歧义.
struct A { };
bool operator != (const A&, const A&);
struct B { operator A(); };
boost::has_not_equal_to<A>::value; // this is fine
boost::has_not_equal_to<B>::value; // error: ambiguous overload
  • volatile 限定符未被正确处理, 会导致未定义行为
