aligned_storage 

template <std::size_t Size, std::size_t Align>
struct aligned_storage
{
   typedef see-below type;
};

类型: 一个大小为 Size, 对齐为 Align的倍数的内置类型或 POD 类型.

头文件: #include <boost/type_traits/aligned_storage.hpp> 或 #include <boost/type_traits.hpp>

在 GCC 和 Visual C++ 编译器 (或与之兼容的编译器) 上, 我们支持请求对齐超过任何内置类型上限的类型 (最高 128 位对齐). Visual C++ 用户应注意, 这类 "扩展" 类型不能作为按值传递的函数实参传入栈中.

重要

Visual C++ 用户应当知道, MSVC 对对齐有一种 "弹性" 定义, 例如考虑以下代码:

typedef boost::aligned_storage<8,8>::type align_t;
assert(boost::alignment_of<align_t>::value % 8 == 0);
align_t a;
assert(((std::uintptr_t)&a % 8) == 0);
char c = 0;
align_t a1;
assert(((std::uintptr_t)&a1 % 8) == 0);

在这段代码中, 最后的 assert 在 32 位构建中将会失败, 因为变量 a1 未按 8 字节边界对齐. 如果我们使用 MSVC 内建特性 __alignof 代替 alignment_of 或 std::aligned_storage 代替 boost::aligned_storage, 结果不会有任何不同. 在 MSVC 中, 对齐要求/承诺实际上只适用于堆上的变量, 而不适用于栈上的变量.

此外, 尽管 MSVC 具有生成带任意对齐要求的新类型的机制, 但这类类型不能作为函数实参在程序栈上传递. 因此, 如果 boost::aligned_storage<8,8>::type 是用 __declspec(align(8)) 声明的类型, 我们就会破坏大量依赖能通过程序栈传递此类类型的现有代码.
