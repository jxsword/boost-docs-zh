common_type

头文件: #include <boost/type_traits/common_type.hpp> 或 #include <boost/type_traits.hpp> 

namespace boost {
  template <class... T> struct common_type;
  template<class... T> using common_type_t = typename common_type<T...>::type; // C++11 and above
}

common_type 是一个特征类, 用于推导若干类型共同拥有的类型, 可用作对多种输入类型进行运算的函数 (例如混合模式算术) 的返回类型.

嵌套的 typedef ::type 可以定义如下:

template <class... T>
struct common_type;

template <class T, class U, class... V>
struct common_type<T, U, V...> {
    typedef typename common_type<typename common_type<T, U>::type, V...>::type type;
};

template <>
struct common_type<> {
};

template <class T>
struct common_type<T> {
    typedef typename decay<T>::type type;
};

template <class T, class U>
struct common_type<T, U> {
    typedef typename decay<
        decltype( declval<bool>()?
            declval<typename decay<T>::type>():
            declval<typename decay<U>::type>() )
    >::type type;
};

所有参数类型都必须是完整的. 若至少一个模板参数是用户定义类型, 则允许用户特化该特征. 注释: 当只希望在 common_type 实参之间进行显式转换时, 就需要这类特化.

注意, 当编译器不支持变参模板 (且宏 BOOST_NO_CXX11_VARIADIC_TEMPLATES 已定义) 时, 模板实参的最大个数是 9.

Tutorial

简而言之, common_type 是一个接受 1 个或多个类型并返回一个所有类型都可转换到的类型的特征. 默认定义要求这种转换是隐式的. 但是, 对于希望把类型间转换限制为显式、同时又想与 common_type 设施互操作的用户定义类型, 可以对该特征进行特化.

示例: 

template <class T, class U>
complex<typename common_type<T, U>::type>
operator+(complex<T>, complex<U>);

在上面的例子中, 允许 "混合模式" 的复数算术. 返回类型由 common_type描述. 例如, 把一个 complex<float> 与一个 complex<double> 相加的结果类型可能是一个 complex<double>.

下面是有人可能生成变参比较函数的方式:

template <class ...T>
typename common_type<T...>::type
min(T... t);

这是一个非常有用且适用面很广的工具.

如何获得带显式转换类型的公共类型?

前一例中运算符的作者还可以这样选择:

template <class T, class U>
typename common_type<complex<T>, complex<U> >::type
operator+(complex<T>, complex<U>);

由于 common_type 的默认定义要求转换必须是隐式的, 我们需要按如下方式为复数类型特化该特征.

template <class T, class U>
struct common_type<complex<T>, complex<U> > {
    typedef complex< common_type<T, U> > type;
};
对于 common_type<> 模板实参而言, 其顺序有多重要?

模板参数的顺序很重要.

common_type<A,B,C>::type 并不等价于 common_type<C,A,B>::type, 而是等价于 common_type<common_type<A,B>::type, C>::type.

考虑:

struct A {};
struct B {};
struct C {
    C() {}
    C(A const&) {}
    C(B const&) {}
    C& operator=(C const&) {
        return *this;
    }
};

下面的代码无法编译

typedef boost::common_type<A, B, C>::type ABC; // Does not compile

而

typedef boost::common_type<C, A, B>::type ABC;

则能编译.

因此, 由于 common_type<A,B>::type 未定义, common_type<A,B,C>::type 也未定义.

希望 common_type<A, B> 具有良构定义的客户端应当自行定义它:

namespace boost
{

template <>
struct common_type<A, B> {typedef C type;};

}

现在这个客户端就可以使用 common_type<A, B, C> (并获得相同的答案).

想要查询 common_type<A, B, C> 且无论顺序如何都得到相同结果的客户端, 还需要额外添加:

namespace boost
{

template <> struct common_type<B, A>
: public common_type<A, B> {};

}

这样做是必要的, 因为 common_type<A, B> 的特化不会被隐式地用于 common_type<B, A>.

两个类型的 common_type 能是第三个类型吗?

鉴于前面的例子, 有人可能期望 common_type<A,B>::type 为 C, 而无需用户做任何干预. 但默认的 common_type<> 实现并不允许这一点. 对于希望 common_type<A, B> 具有良构定义的客户端, 应当自行定义它:

namespace boost
{

template <>
struct common_type<A, B> {typedef C type;};

template <> struct common_type<B, A>
: public common_type<A, B> {};

}

现在这个客户端就可以使用 common_type<A, B>.

对于 common_type, 它对指针的行为如何?

考虑:

struct C { }:
struct B : C { };
struct A : C { };

难道 common_type<A*,B*>::type 不应该是 C*吗? 我认为应该是, 但默认实现会使其非良构.

本库可以为指针添加一个特化, 如

namespace boost
{

    template <typename A, typename B>
    struct common_type<A*, B*> {
        typedef common_type<A, B>* type;
    };
}

但由于缺乏有说服力的用例, 我们宁愿不添加超出标准规定的内容.

当然, 用户总是可以自行做出这个特化.

能否解释一下 common_type 相比 Boost.Typeof 的优缺点?

尽管它们看起来很接近, 但 common_type 和 typeof 的用途不同. 你使用 typeof 来获取表达式的类型, 而使用 common_type 来显式设定模板函数的返回类型. 两者互为补充, 实际上 common_type 大致等价于 decltype(declval<bool>() ? declval<T>() : declval<U>()).

common_type 也类似于 promote_args<class ...T> 中的 boost/math/tools/promotion.hpp, 尽管它与 promote_args 也不完全相同. common_type<T1, T2>::type 只是表示对 T1 和 T2进行某种运算的结果, 并默认为把 T1 和 T2 放入条件语句所得到的类型.

如果这个默认行为不合适, 它应当是可定制的 (通过特化).
