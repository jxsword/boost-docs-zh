动机

如今应用程序发展迅速, 变得日益复杂, 难以测试和调试. 多数情况下应用程序运行在远端, 开发者几乎没有机会监视其运行状况; 一旦发生故障, 也很难查明原因. 此外, 如果应用程序的行为严重依赖于异步的外部事件, 例如设备反馈或其他进程的活动, 即使是本地调试也可能成为难题.

这正是日志能发挥作用的地方. 应用程序将其执行过程中的所有关键信息记录到日志中, 一旦出现问题, 便可以利用这些信息分析程序行为并进行必要的修正. 日志还有其他非常有用的用途, 例如收集统计信息和突出显示事件 (即指示某种情况已经发生, 或应用程序遇到了某些问题). 这些任务已被证明对许多实际工业应用至关重要.

本库旨在让应用程序开发者的日志工作显著简化. 它提供了丰富的开箱即用工具, 并提供用于扩展库功能的公开接口. 该库的主要目标是:

  • 简单. 一个小的示例代码片段就足以感受该库, 并准备好使用其基本功能.
  • 可扩展性. 用户应能够扩展库的功能, 以收集信息并将其存入日志.
  • 性能. 该库应尽可能减少对用户应用程序的性能影响.

如何阅读本文档

本文档面向新手和有经验的库用户. 不过, 假定用户已熟悉常用的 Boost 组件, 例如 shared_ptr、make_shared (参见 Boost.SmartPtr) 和 function (Boost.Function). 文档的某些部分会按需引用其他 Boost 库.

如果您是初次接触本库, 建议先阅读 设计概述 一节, 以初步了解该库的能力与架构. 安装 和 教程 两节将帮助您上手试验该库. 教程通过示例代码片段概述了库的各项功能. 部分教程步骤提供了两种形式: 简单形式和进阶形式. 简单形式通常描述完成任务最常用、最简便的方法, 建议新用户阅读. 进阶形式通常给出完成同一任务的扩展方式, 但附带深入讲解, 并支持一些额外的定制. 这种形式可能对更有经验的用户有用; 一般而言, 如果简便方法不能满足您的需求, 则应阅读进阶形式.

除教程之外还有 功能详解 一章. 这一部分描述库提供的、教程未涉及的其他工具. 本章最好按需逐项查阅.

最后同样重要的是, 还有 参考 一节, 对库组件接口给出了正式描述.

为使本文档中的代码片段保持简洁, 假定已定义以下命名空间别名:

namespace logging = boost::log;
namespace sinks = boost::log::sinks;
namespace src = boost::log::sources;
namespace expr = boost::log::expressions;
namespace attrs = boost::log::attributes;
namespace keywords = boost::log::keywords;

请注意, 大多数示例后都附有链接, 指向完整可编译的代码示例, 其中包含文档中为求简洁而省略的所有必要 include 和辅助代码 (如有). 各节开头也列出了相关的 include.

术语定义

以下是全文广泛使用的一些术语的定义:

日志记录

从用户应用程序收集到的单条信息组合, 是写入日志的候选对象. 在最简单的情况下, 日志记录经过日志库处理后, 会表现为日志文件中的一行文本.

Attribute

"属性"是可用于对日志记录进行特化的一段元信息. 在 Boost.Log 中, 属性以具有特定接口的函数对象表示, 调用时返回实际的属性值. 属性的例子有: 返回当前时钟时间的函数、返回单调递增的日志记录计数器的函数等.

属性值

属性值是从属性获取的实际数据. 这些数据附着于特定的日志记录, 并由库进行处理. 值可以具有不同的类型 (整数、字符串以及更复杂的类型, 包括用户自定义类型). 属性值的例子有: 当前时间戳值、文件名、行号、当前作用域名称等. 属性值被封装在一个类型擦除包装器中, 因此属性的实际类型在接口中不可见. 值的实际 (擦除后的) 类型有时称为存储类型.

(属性) 值访问

处理属性值的一种方式. 这种方式需要一个作用于属性值的函数对象 (访问器). 访问器需要知道属性值的存储类型才能对其进行处理.

(属性) 值提取

当调用方尝试获得对存储值的引用时处理属性值的一种方式. 调用方需要知道属性值的存储类型才能提取它.

日志源

用户应用程序写入日志记录的入口. 在简单情况下, 它是一个对象 (日志器), 维护一组属性, 在用户请求时用于构成日志记录. 不过, 当然也可以创建在某种外部事件发生时发出日志记录的日志源 (例如, 通过拦截并解析另一个应用程序的控制台输出).

日志接收器

从用户应用程序收集到的所有日志记录最终送往的目标. 接收器定义日志记录将被存储或处理的位置和方式.

日志过滤器

一种谓词, 接受日志记录并判断该记录应继续传递以进行后续处理还是被丢弃. 该谓词通常根据记录附带的属性值作出判断.

日志格式化器

一种从日志记录生成最终文本输出的函数对象. 某些接收器 (例如二进制日志接收器) 可能不需要它, 但几乎所有基于文本的接收器都会使用格式化器来组织输出.

日志核心

维护接收器列表并对日志源生成的记录应用过滤器的全局实体. 在用户应用程序中, 它主要用于配置日志库. 一个应用程序中只有一个日志核心实例.

i18n

国际化. 操作宽字符的能力.

TLS

线程局部存储. 指一个变量对每个尝试访问它的线程都拥有独立取值的概念.

RTTI

运行期类型信息. 这是 dynamic_cast 和 typeid 运算符正常工作所需的 C++ 语言支持数据结构.
