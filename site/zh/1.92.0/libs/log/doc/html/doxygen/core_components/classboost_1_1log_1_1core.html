类 core

boost::log::core — 日志库核心类.

概要

// In header: <boost/log/core/core.hpp>


class core {
public:
  // types
  typedef unspecified exception_handler_type;  // Exception handler function type. 

  // public member functions
  ~core();
  bool set_logging_enabled(bool = true);
  bool get_logging_enabled() const;
  void set_filter(filter const &);
  void reset_filter();
  void add_sink(shared_ptr< sinks::sink > const &);
  void remove_sink(shared_ptr< sinks::sink > const &);
  void remove_all_sinks();
  void flush();
  std::pair< attribute_set::iterator, bool > 
  add_global_attribute(attribute_name const &, attribute const &);
  void remove_global_attribute(attribute_set::iterator);
  attribute_set get_global_attributes() const;
  void set_global_attributes(attribute_set const &);
  std::pair< attribute_set::iterator, bool > 
  add_thread_attribute(attribute_name const &, attribute const &);
  void remove_thread_attribute(attribute_set::iterator);
  attribute_set get_thread_attributes() const;
  void set_thread_attributes(attribute_set const &);
  void set_exception_handler(exception_handler_type const &);
  record open_record(attribute_set const &);
  record open_record(attribute_value_set const &);
  record open_record(attribute_value_set &&);
  void push_record(record &&);
  core(core const &) = delete;
  core & operator=(core const &) = delete;

  // public static functions
  static core_ptr get();
};

说明

日志核心用于互连日志源与接收器. 它还提供许多基本功能, 例如全局过滤以及全局和线程特定的属性存储.

日志核心是单例. 用户可以通过调用静态方法 get 获取核心实例.

core 公有成员函数

  1. ~core();

    析构函数. 销毁核心, 释放所有已注册的接收器和属性.

  2. bool set_logging_enabled(bool enabled = true);

    该方法启用或禁用日志记录.

    将此状态设置为 false 可以完全消除任何日志记录活动, 包括过滤和属性值的生成. 如果想在运行中的应用程序中完全禁用日志记录, 该功能很有用. 日志记录的状态不会改变日志库的任何其他属性(例如过滤器或接收器), 因此可以在禁用日志记录时的设置完全不变的情况下重新启用日志记录. 如果要对日志记录配置进行重大更改, 并且不希望应用程序在打开或推送日志记录时阻塞, 该功能也可能有用.

    默认情况下日志记录是启用的.

    参数:

    enabled

    日志记录活动的实际标志.

    返回:

    日志记录启用/禁用标志的先前值

    		 
  3. bool get_logging_enabled() const;

    该方法用于检测日志记录是否已启用. 参见 set_logging_enabled 的说明.

  4. void set_filter(filter const & filter);

    该方法设置全局日志过滤器. 该过滤器会应用于处理的每条日志记录.

    参数:

    filter

    要安装的过滤器函数对象.

    		 
  5. void reset_filter();

    该方法移除全局日志过滤器. 所有日志记录在传递给接收器时都不再应用全局过滤.

  6. void add_sink(shared_ptr< sinks::sink > const & s);

    该方法添加新的接收器. 接收器在添加之后立即参与日志记录过程, 直到被移除. 同一接收器不能同时添加多次. 如果接收器已注册, 该调用会被忽略.

    参数:

    s

    要注册的接收器.

    		 
  7. void remove_sink(shared_ptr< sinks::sink > const & s);

    该方法从输出中移除接收器. 移除后接收器将不会收到任何日志记录. 如果接收器未注册, 该调用没有效果.

    参数:

    s

    要注销的接收器.

    		 
  8. void remove_all_sinks();

    该方法从输出中移除所有已注册的接收器. 移除后这些接收器将不会收到任何日志记录.

  9. void flush();

    该方法对所有已注册的接收器执行刷新.

    注释

    该方法可能需要较长时间才能完成, 因为它可能会阻塞, 直到所有接收器处理完所有缓冲的日志记录. 该调用还会阻塞所有日志记录尝试, 直到操作完成.

  10. std::pair< attribute_set::iterator, bool > 
add_global_attribute(attribute_name const & name, attribute const & attr);

    该方法将属性添加到全局属性集合. 该属性会被隐式添加到每条日志记录中.

    参数:

    name

    属性名.

    attr

    属性工厂.

    返回:

    一对值. 若第二个成员为 true, 则属性已添加, 第一个成员指向该属性. 否则属性未被添加, 第一个成员指向阻止添加的属性.

    		 
  11. void remove_global_attribute(attribute_set::iterator it);

    该方法从全局属性集合中移除属性.

    参数:

    it

    指向先前添加的属性的迭代器.

    要求:

    该属性是通过 add_global_attribute 调用添加的.

    后置条件:

    该属性不再注册为全局属性. 迭代器在移除后失效.

    		 
  12. attribute_set get_global_attributes() const;

    该方法返回当前注册的全部全局属性的完整集合的副本.

  13. void set_global_attributes(attribute_set const & attrs);

    该方法用所提供的集合替换当前注册的全部全局属性的完整集合.

    注释

    该方法使可能已从 add_global_attribute 方法返回的所有迭代器和引用失效.

    参数:

    attrs

    要安装的属性集合.

    		 
  14. std::pair< attribute_set::iterator, bool > 
add_thread_attribute(attribute_name const & name, attribute const & attr);

    该方法将属性添加到线程特定属性集合. 该属性会被隐式添加到当前线程产生的每条日志记录中.

    注释

    在单线程构建中, 效果与全局添加属性相同. 但这并不意味着线程特定属性与全局属性的迭代器可以互换.

    参数:

    name

    属性名.

    attr

    属性工厂.

    返回:

    一对值. 若第二个成员为 true, 则属性已添加, 第一个成员指向该属性. 否则属性未被添加, 第一个成员指向阻止添加的属性.

    		 
  15. void remove_thread_attribute(attribute_set::iterator it);

    该方法从线程特定属性集合中移除属性.

    参数:

    it

    指向先前添加的属性的迭代器.

    要求:

    该属性是通过 add_thread_attribute 调用添加的.

    后置条件:

    该属性不再注册为线程特定属性. 迭代器在移除后失效.

    		 
  16. attribute_set get_thread_attributes() const;

    该方法返回当前注册的全部线程特定属性的完整集合的副本.

  17. void set_thread_attributes(attribute_set const & attrs);

    该方法用所提供的集合替换当前注册的全部线程特定属性的完整集合.

    注释

    该方法使可能已从 add_thread_attribute 方法返回的所有迭代器和引用失效.

    参数:

    attrs

    要安装的属性集合.

    		 
  18. void set_exception_handler(exception_handler_type const & handler);

    该方法设置异常处理函数. 在 open_record 或 push_record 方法执行期间发生异常时, 将以无参形式调用该函数. 由于异常处理器是从 catch 语句中调用的, 可以重新抛出异常以确定其类型.

    默认情况下不安装任何处理器, 因此任何异常都会照常传播.

    参见: 参见: utility/exception_handler.hpp

    注释

    异常处理器可能在多个线程中被并发调用. 线程中断不受异常处理器影响.

    参数:

    handler

    异常处理函数

    		 
  19. record open_record(attribute_set const & source_attributes);

    该方法尝试打开一条要写入的新记录. 在尝试打开日志记录时会应用所有过滤. 成功打开的记录可以通过调用 push_record 方法进一步推送给接收器, 或者直接销毁返回的对象来丢弃.

    允许多条打开的记录同时存在, 这些记录相互独立. 所有属性值都在打开记录时获取, 且不会在记录之间相互影响.

    返回的记录可以被复制, 但不得在不同线程之间传递.

    抛出: 若已安装异常处理器, 则仅当处理器抛出时才抛出. 否则, 若某个接收器抛出异常或达到某些系统资源限制, 则可能抛出.

    参数:

    source_attributes

    要附加到待打开记录的日志源特定属性集合.

    返回:

    若记录被打开, 则为有效的日志记录; 否则(例如因未通过过滤)为无效的记录对象.

    		 
  20. record open_record(attribute_value_set const & source_attributes);

    该方法尝试打开一条要写入的新记录. 在尝试打开日志记录时会应用所有过滤. 成功打开的记录可以通过调用 push_record 方法进一步推送给接收器, 或者直接销毁返回的对象来丢弃.

    允许多条打开的记录同时存在, 这些记录相互独立. 所有属性值都在打开记录时获取, 且不会在记录之间相互影响.

    返回的记录可以被复制, 但不得在不同线程之间传递.

    抛出: 若已安装异常处理器, 则仅当处理器抛出时才抛出. 否则, 若某个接收器抛出异常或达到某些系统资源限制, 则可能抛出.

    参数:

    source_attributes

    要附加到待打开记录的日志源特定属性值集合.

    返回:

    若记录被打开, 则为有效的日志记录; 否则(例如因未通过过滤)为无效的记录对象.

    		 
  21. record open_record(attribute_value_set && source_attributes);

    该方法尝试打开一条要写入的新记录. 在尝试打开日志记录时会应用所有过滤. 成功打开的记录可以通过调用 push_record 方法进一步推送给接收器, 或者直接销毁返回的对象来丢弃.

    允许多条打开的记录同时存在, 这些记录相互独立. 所有属性值都在打开记录时获取, 且不会在记录之间相互影响.

    返回的记录可以被复制, 但不得在不同线程之间传递.

    抛出: 若已安装异常处理器, 则仅当处理器抛出时才抛出. 否则, 若某个接收器抛出异常或达到某些系统资源限制, 则可能抛出.

    参数:

    source_attributes

    要附加到待打开记录的日志源特定属性值集合. 此调用之后该容器的内容未指定.

    返回:

    若记录被打开, 则为有效的日志记录; 否则(例如因未通过过滤)为无效的记录对象.

    		 
  22. void push_record(record && rec);

    该方法将记录推送给接收器. 在此过程中记录被移走.

    抛出: 若已安装异常处理器, 则仅当处理器抛出时才抛出. 否则, 若某个接收器抛出异常则可能抛出.

    参数:

    rec

    先前成功打开的日志记录.

    要求:

    !!rec == true

    后置条件:

    !rec == true
