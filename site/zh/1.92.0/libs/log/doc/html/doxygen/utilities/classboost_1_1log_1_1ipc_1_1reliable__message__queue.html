类 reliable_message_queue

boost::log::ipc::reliable_message_queue — 可靠的进程间消息队列.

说明

该队列实现从一个或多个写入者向单个读取者传递消息的可靠单向通道. 消息的格式由用户定义, 并且必须在所有写入者和读取者之间保持一致. 除了消息应以连续字节数组的形式提供之外, 该队列不强制任何特定的消息格式.

该队列内部使用由 object_name(队列名)标识的进程共享存储. 有关对象名所受限制的详细信息, 请参阅 object_name 文档.

队列存储组织为固定数量、固定大小的块. 块大小必须是 2 的整数次幂, 以字节表示. 每条写入的消息连同队列添加的一些元数据会占用整数个块. 读取者接收的每条已读消息会释放为该消息分配的块. 因此, 消息的最大大小略小于块大小乘以队列容量. 出于效率考虑, 建议选择足够大的块大小, 以容纳大部分要通过队列传递的消息.

当没有消息入队(所有块都空闲)时, 队列被视为空. 在入队消息时, 如果没有足够的空闲块容纳该消息, 队列被视为满.

该队列是可靠的: 除了最后一个使用者销毁非空队列的情况之外, 它不会丢弃已成功发送但未被读取者接收的消息. 如果写入者因队列已满而无法将消息入队, 根据创建队列时指定的策略, 队列可以阻塞写入者、返回错误或抛出异常. 该策略是对象本地的, 即不同的写入者和读取者可以有不同的溢出策略.

如果队列为空且读取者尝试从队列取出消息, 它将阻塞, 直到某个写入者将消息入队.

阻塞的读取者或写入者可以通过调用 stop_local 解除阻塞. 调用该方法之后, 阻塞在该特定对象上的所有线程都被释放并返回 operation_result::aborted. 队列的其他实例(在当前或其他进程中)不受影响. 要在 stop_local 调用之后恢复队列实例的正常功能, 用户必须调用 reset_local.

该队列不保证从不同写入者线程接收消息的任何特定顺序. 特定写入者线程发送的消息将按发送顺序被接收.

除非另有说明, 该类的方法不是线程安全的.

  18. void stop_local();

    该方法唤醒所有在调用 send() 或 receive() 时阻塞的线程. 这些调用随后将返回 operation_result::aborted. 注意, 该方法不会阻塞直到被唤醒的线程实际从 send() 或 receive() 返回. 需要用其他手段确保对 send() 或 receive() 的调用已经返回, 例如加入(join)可能在这些调用上阻塞的线程.

    该方法还将对象置为停止状态. 处于停止状态时, 对 send() 或 receive() 的调用在原本运行状态下会阻塞的情形下将立即返回, 返回值为 operation_result::aborted.

    允许并发调用该方法以及 send()、try_send()、receive()、try_receive() 和 clear().

    要求:

    is_open() == true 

  19. void reset_local();

    该方法将对象置为运行状态, 在该状态下对 send() 或 receive() 的调用可能阻塞. 该方法不是线程安全的.

    要求:

    is_open() == true 

  20. void close() noexcept;

    该方法解除与关联消息队列(如有)的关联. 调用该方法之前不应有其他线程正在使用该对象. stop_local() 方法可用于使当前阻塞在 send() 或 receive() 中的线程返回, 并防止后续对这些方法的调用阻塞. 通常, 在调用该方法之前, 应先调用 stop_local(), 然后加入(join)所有可能阻塞在 send() 或 receive() 上的线程, 以确保它们已从调用中返回. 如果该对象代表对消息队列的最后一个未决引用, 关联的消息队列将被销毁.

    后置条件:

    is_open() == false 

  21. operation_result send(void const * message_data, size_type message_size);

    该方法向关联的消息队列发送消息. 当对象处于运行状态且队列没有空闲空间容纳该消息时, 根据打开/创建队列时指定的溢出策略, 该方法要么阻塞要么抛出异常. 若阻塞策略生效, 可以通过调用 stop_local() 中断阻塞, 此时该方法返回 operation_result::aborted. 当对象已处于停止状态时, 该方法不阻塞, 而是立即返回, 返回值为 operation_result::aborted.

    传递 0 给参数 message_size 即可发送空消息.

    允许并发调用 send()、try_send()、receive()、try_receive()、stop_local() 和 clear().

    抛出: 若消息大小超过队列容量则抛出 std::logic_error, 若原生 OS 方法失败则抛出 system_error.

    参数:

    message_data

    要发送的消息数据. 当 message_size 为 0 时被忽略.

    message_size

    消息数据的大小, 以字节计. 如果大小超过关联消息队列的容量, 将抛出 std::logic_error 异常.

    要求:

    is_open() == true

    参数:

    container

    用于存储接收到的消息的容器. 容器的值类型应为 char、signed char 或 unsigned char, 并支持在末尾插入元素.

    要求:

    is_open() == true

    返回:

    true, 若消息成功接收; 否则为 false(例如队列为空时).

reliable_message_queue 友元函数

  1. void swap(reliable_message_queue & a, reliable_message_queue & b) noexcept;
    交换两个 reliable_message_queue 对象.

reliable_message_queue 公有静态函数

  1. static void remove(object_name const & name);

    该方法释放与所给名称的进程间队列相关联的系统级资源. 在此调用时, 指定名称所引用的队列不得在任何进程中打开. 此调用成功后, 可以创建具有指定名称的新队列.

    该调用有助于从先前的进程异常行为中恢复(例如崩溃时未正确关闭消息队列). 在这种情况下, 为进程间队列分配的资源在最后一个进程关闭队列之后可能仍保持分配状态, 进而可能阻止创建具有相同名称的新队列. 通过在创建队列之前调用该方法, 应用程序可以尝试确保从干净状态开始.

    在某些平台上, 当最后一个使用这些资源的进程终止时(即使是异常终止), 操作系统会自动回收与队列相关联的资源. 在这些平台上, 该调用可能是空操作. 但是, 可移植代码仍应在适当位置调用该方法, 以确保与其他平台以及可能改变队列实现的未来库版本兼容.

    参数:

    name

    要移除的消息队列的名称.
