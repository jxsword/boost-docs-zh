boost::log::sinks::asynchronous_sink — 异步日志接收器前端.

说明

该前端在构造时启动一个单独的线程. 所有日志记录都在这个专用线程中传递给后端.

用户可以在构造时通过将 start_thread 参数指定为 false 来阻止生成内部线程. 在这种情况下, 日志记录会缓冲在内部队列中, 直到用户在自己的线程中调用 run、feed_records 或 flush. 日志记录的排队策略由 QueueingStrategyT 模板参数指定.

asynchronous_sink 公有成员函数

  1. explicit asynchronous_sink(bool start_thread = true);

    默认构造函数. 构造接收器后端实例. 要求后端可默认构造.

    参数:

    start_thread

    若为 true, 前端会创建一个线程将日志记录传送给后端. 否则不启动线程, 并假定用户将自己调用 run、feed_records 或 flush.

    		 
  2. explicit asynchronous_sink(shared_ptr< sink_backend_type > const & backend, 
                           bool start_thread = true);

    附加用户构造的后端实例的构造函数

    参数:

    backend

    指向后端实例的指针.

    start_thread

    若为 true, 前端会创建一个线程将日志记录传送给后端. 否则不启动线程, 并假定用户将自己调用 run、feed_records 或 flush.

    要求:

    backend 不为 NULL.

    		 
  3. template<typename... Args> explicit asynchronous_sink(Args &&... args);

    将任意命名参数传递给进程间接收器后端构造函数的构造函数. 受支持的参数列表参见后端文档.

    前端使用以下命名参数:

    • start_thread - 若为 true, 前端会创建一个线程将日志记录传送给后端. 否则不启动线程, 并假定用户将自己调用 run、feed_records 或 flush.

  4. ~asynchronous_sink() noexcept;

    析构函数. 如果专用的传送线程正在运行, 则隐式停止它.

  5. locked_backend_ptr locked_backend();

    附加后端的加锁访问器

  6. virtual void consume(record_view const & rec);

    将日志记录入队到后端

  7. virtual bool try_consume(record_view const & rec);

    该方法尝试将日志记录传递给后端

  8. void run();

    该方法启动记录传送循环, 并有效阻塞直到发生以下任一情况:

    • 由于调用 stop 导致线程被中断

    • 在后端处理日志记录时抛出异常, 且该异常未被异常处理器(若已安装)终止

    要求:

    接收器前端必须在不生成专用线程的情况下构造

    		 
  9. void stop();

    该方法软中断记录传送循环. 当必须中断 run、feed_records 或 flush 方法的执行时, 必须调用该方法. 与常规线程中断不同, 调用 stop 不会在记录处理中途将其打断. 相反, 接收器前端会尝试完成正在进行的记录处理, 然后返回. 无论接收器是以内部专用线程创建的, 还是传送循环由用户启动的, 都可以调用该方法.

    如果当前没有正在进行的记录传送操作, 调用 stop 会标记该接收器前端, 使下一次传送操作立即停止.

    注释

    从该方法返回并不保证接收器前端中没有残留缓冲的记录. 在该方法调用期间和之后, 日志记录仍可能不断到来. 在该方法执行过程中的某个时点, 日志记录停止被处理, 此后到来的所有记录都会放入队列. 这些记录将在后续调用 run 或 feed_records 时被处理.

    注释

    如果记录传送循环在用户线程中运行(即在前端构造时 start_thread 被指定为 false), 该方法不保证返回时线程已从记录传送循环返回, 也不保证它将来不会再进入该循环. 该方法仅确保记录传送线程最终会从传送循环返回. 与用户的记录传送线程同步是用户的责任.

  10. void feed_records();

    该方法将可能已缓冲的日志记录传送给后端, 然后返回

    要求:

    接收器前端必须在不生成专用线程的情况下构造

    		 
  11. virtual void flush();

    该方法将所有可能已缓冲的日志记录传送给后端, 然后返回. 与 feed_records 不同, 在有序排队的情况下, 该方法还会传送在排序窗口期间入队的记录, 尝试完全排空队列.
