基本日志器 

#include <boost/log/sources/basic_logger.hpp>

库提供的最简单的日志源是日志器 logger 及其线程安全版本 logger_mt (对应宽字符日志的 wlogger 和 wlogger_mt). 这些日志器只提供在自身存储日志源专属属性的能力, 当然还有构成日志记录的能力. 当不需要严重级别检查等高级功能时, 或许应使用这种类型的日志器. 它完全可以用作收集应用程序统计信息和登记应用程序事件的工具, 例如通知和警报. 在这种情况下, 日志器通常与 作用域属性 配合使用, 将所需数据附加到通知事件上. 下面是一个用法示例:

class network_connection
{
    src::logger m_logger;
    logging::attribute_set::iterator m_remote_addr;

public:
    void on_connected(std::string const& remote_addr)
    {
        // Put the remote address into the logger to automatically attach it
        // to every log record written through the logger
        m_remote_addr = m_logger.add_attribute("RemoteAddress",
            attrs::constant< std::string >(remote_addr)).first;

        // The straightforward way of logging
        if (logging::record rec = m_logger.open_record())
        {
            rec.attribute_values().insert("Message",
                attrs::make_attribute_value(std::string("Connection established")));
            m_logger.push_record(boost::move(rec));
        }
    }
    void on_disconnected()
    {
        // The simpler way of logging: the above "if" condition is wrapped into a neat macro
        BOOST_LOG(m_logger) << "Connection shut down";

        // Remove the attribute with the remote address
        m_logger.remove_attribute(m_remote_addr);
    }
    void on_data_received(std::size_t size)
    {
        // Put the size as an additional attribute
        // so it can be collected and accumulated later if needed.
        // The attribute will be attached only to this log record.
        BOOST_LOG(m_logger) << logging::add_value("ReceivedSize", size) << "Some data received";
    }
    void on_data_sent(std::size_t size)
    {
        BOOST_LOG(m_logger) << logging::add_value("SentSize", size) << "Some data sent";
    }
};

上面代码片段中的 network_connection 类展示了一种在网络相关应用程序中实现简单日志和统计信息收集的方法. 该类展示的每个方法实际上标记了一个对应的事件, 可以在接收器层面跟踪和收集. 此外, 该类的其他方法 (为简洁起见未在此展示) 也能够写日志. 注意, network_connection 对象在连接状态下创建的每条日志记录都会被隐式标记上远端站点的地址.

支持严重级别的日志器 

#include <boost/log/sources/severity_feature.hpp>
#include <boost/log/sources/severity_logger.hpp>

根据某种严重级别或重要性区分部分日志记录, 是最常被要求的功能之一. 类模板 severity_logger 和 severity_logger_mt (以及它们对应的宽字符版本 wseverity_logger 和 wseverity_logger_mt) 提供了此功能.

这些日志器会自动注册一个特殊的日志源专属属性 "Severity", 可以用命名参数 severity (传递给构造函数和/或 open_record 方法) 以紧凑高效的方式为每条记录设置. 如果传递给日志器构造函数, severity 参数将设置严重级别的默认值, 当 open_record 参数中未提供时将使用该默认值. severity 参数 (传递给 open_record 方法) 设置正在创建的特定日志记录的级别. 严重级别类型可以作为日志器类模板的模板参数提供. 默认类型为 int.

该属性的实际值及其含义完全由用户定义. 不过, 建议以相当于零的级别作为其他值的基准点. 这是因为默认构造的日志器对象将其默认严重级别设为零. 还建议为整个应用程序定义相同的严重级别, 以避免日后写出的日志产生混淆. 下面的代码片段展示了 severity_logger 的用法.

// We define our own severity levels
enum severity_level
{
    normal,
    notification,
    warning,
    error,
    critical
};

void logging_function()
{
    // The logger implicitly adds a source-specific attribute 'Severity'
    // of type 'severity_level' on construction
    src::severity_logger< severity_level > slg;

    BOOST_LOG_SEV(slg, normal) << "A regular message";
    BOOST_LOG_SEV(slg, warning) << "Something bad is going on but I can handle it";
    BOOST_LOG_SEV(slg, critical) << "Everything crumbles, shoot me now!";
}


void default_severity()
{
    // The default severity can be specified in constructor.
    src::severity_logger< severity_level > error_lg(keywords::severity = error);

    BOOST_LOG(error_lg) << "An error level log record (by default)";

    // The explicitly specified level overrides the default
    BOOST_LOG_SEV(error_lg, warning) << "A warning level log record (overrode the default)";
}

或者, 如果您更喜欢不使用宏的日志方式:

void manual_logging()
{
    src::severity_logger< severity_level > slg;

    logging::record rec = slg.open_record(keywords::severity = normal);
    if (rec)
    {
        logging::record_ostream strm(rec);
        strm << "A regular message";
        strm.flush();
        slg.push_record(boost::move(rec));
    }
}

当然, 严重级别日志器也提供 基本日志器 所具有的相同功能.

支持通道的日志器 

#include <boost/log/sources/channel_feature.hpp>
#include <boost/log/sources/channel_logger.hpp>

有时, 将日志记录与某个应用程序组件关联非常重要, 例如模块或类名、所记录信息与应用程序某项特定功能领域的关系 (例如网络或文件系统相关消息), 或某个稍后可用于将这些记录路由到特定接收器的任意标记. 该功能由日志器 channel_logger、channel_logger_mt 及其宽字符对应版本 wchannel_logger、wchannel_logger_mt 实现. 这些日志器会自动注册一个名为 "Channel" 的属性. 默认通道名称可以在日志器构造函数中用命名参数 channel 设置. 通道属性值的类型可以指定为日志器的模板参数, 默认为 std::string (宽字符日志器为 std::wstring). 除此之外, 用法与 基本日志器 类似:

class network_connection
{
    src::channel_logger< > m_net, m_stat;
    logging::attribute_set::iterator m_net_remote_addr, m_stat_remote_addr;

public:
    network_connection() :
        // We can dump network-related messages through this logger
        // and be able to filter them later
        m_net(keywords::channel = "net"),
        // We also can separate statistic records in a different channel
        // in order to route them to a different sink
        m_stat(keywords::channel = "stat")
    {
    }

    void on_connected(std::string const& remote_addr)
    {
        // Add the remote address to both channels
        attrs::constant< std::string > addr(remote_addr);
        m_net_remote_addr = m_net.add_attribute("RemoteAddress", addr).first;
        m_stat_remote_addr = m_stat.add_attribute("RemoteAddress", addr).first;

        // Put message to the "net" channel
        BOOST_LOG(m_net) << "Connection established";
    }

    void on_disconnected()
    {
        // Put message to the "net" channel
        BOOST_LOG(m_net) << "Connection shut down";

        // Remove the attribute with the remote address
        m_net.remove_attribute(m_net_remote_addr);
        m_stat.remove_attribute(m_stat_remote_addr);
    }

    void on_data_received(std::size_t size)
    {
        BOOST_LOG(m_stat) << logging::add_value("ReceivedSize", size) << "Some data received";
    }

    void on_data_sent(std::size_t size)
    {
        BOOST_LOG(m_stat) << logging::add_value("SentSize", size) << "Some data sent";
    }
};

也可以为单条日志记录设置通道名称. 当使用 全局日志器 而不是对象专属日志器时, 这可能很有用. 通道名称可以通过在日志器上调用 channel 修改器来设置, 或使用专门的日志宏. 例如:

// Define a global logger
BOOST_LOG_INLINE_GLOBAL_LOGGER_CTOR_ARGS(my_logger, src::channel_logger_mt< >, (keywords::channel = "general"))

class network_connection
{
    std::string m_remote_addr;

public:
    void on_connected(std::string const& remote_addr)
    {
        m_remote_addr = remote_addr;

        // Put message to the "net" channel
        BOOST_LOG_CHANNEL(my_logger::get(), "net")
            << logging::add_value("RemoteAddress", m_remote_addr)
            << "Connection established";
    }

    void on_disconnected()
    {
        // Put message to the "net" channel
        BOOST_LOG_CHANNEL(my_logger::get(), "net")
            << logging::add_value("RemoteAddress", m_remote_addr)
            << "Connection shut down";

        m_remote_addr.clear();
    }

    void on_data_received(std::size_t size)
    {
        BOOST_LOG_CHANNEL(my_logger::get(), "stat")
            << logging::add_value("RemoteAddress", m_remote_addr)
            << logging::add_value("ReceivedSize", size)
            << "Some data received";
    }

    void on_data_sent(std::size_t size)
    {
        BOOST_LOG_CHANNEL(my_logger::get(), "stat")
            << logging::add_value("RemoteAddress", m_remote_addr)
            << logging::add_value("SentSize", size)
            << "Some data sent";
    }
};

注意, 更改通道名称是持久的, 因此除非重置通道名称, 后续记录也将属于新通道.

提示

出于性能考虑, 建议在可能的情况下避免为每条日志记录单独动态设置通道名称. 更改通道名称涉及动态内存分配. 为不同通道使用不同的日志器可以避免这种开销.

支持异常处理的日志器 

#include <boost/log/sources/exception_handler_feature.hpp>

库提供一个日志器特性, 使用户能够在日志器级别处理和/或抑制异常. exception_handler 特性为日志器添加了 set_exception_handler 方法, 允许设置一个函数对象, 当日志核心在过滤或处理日志记录期间抛出异常时调用它. 可以使用 库提供的适配器 来简化异常处理器的实现. 用法示例如下:

enum severity_level
{
    normal,
    warning,
    error
};

// A logger class that allows to intercept exceptions and supports severity level
class my_logger_mt :
    public src::basic_composite_logger<
        char,
        my_logger_mt,
        src::multi_thread_model< boost::shared_mutex >,
        src::features<
            src::severity< severity_level >,
            src::exception_handler
        >
    >
{
    BOOST_LOG_FORWARD_LOGGER_MEMBERS(my_logger_mt)
};

BOOST_LOG_INLINE_GLOBAL_LOGGER_INIT(my_logger, my_logger_mt)
{
    my_logger_mt lg;

    // Set up exception handler: all exceptions that occur while
    // logging through this logger, will be suppressed
    lg.set_exception_handler(logging::make_exception_suppressor());

    return lg;
}

void logging_function()
{
    // This will not throw
    BOOST_LOG_SEV(my_logger::get(), normal) << "Hello, world";
}

提示

日志核心 和 接收器前端 也支持安装异常处理器.

混合特性的日志器 

#include <boost/log/sources/severity_channel_logger.hpp>

如果您想知道能否在一个日志器中使用多个日志器特性的混合组合, 那么答案是肯定的, 当然可以. 库提供了 severity_channel_logger 和 severity_channel_logger_mt (宽字符对应版本为 wseverity_channel_logger 和 wseverity_channel_logger_mt), 它们结合了前述日志器的特性, 并支持 严重级别 和 通道. 组合日志器同样是模板, 这允许您指定严重级别和通道类型. 您也可以设计自己的日志器特性, 并与库提供的特性组合, 如 扩展本库 一节所述.

使用具有多个特性的日志器, 在概念上与使用单一特性的日志器没有区别. 例如, severity_channel_logger_mt 可以这样使用:

enum severity_level
{
    normal,
    notification,
    warning,
    error,
    critical
};

typedef src::severity_channel_logger_mt<
    severity_level,     // the type of the severity level
    std::string         // the type of the channel name
> my_logger_mt;


BOOST_LOG_INLINE_GLOBAL_LOGGER_INIT(my_logger, my_logger_mt)
{
    // Specify the channel name on construction, similarly as with the channel_logger
    return my_logger_mt(keywords::channel = "my_logger");
}

void logging_function()
{
    // Do logging with the severity level. The record will have both
    // the severity level and the channel name attached.
    BOOST_LOG_SEV(my_logger::get(), normal) << "Hello, world!";
}

日志器的全局存储 

#include <boost/log/sources/global_logger_storage.hpp>

有时, 拥有一个能写日志的日志器对象并不方便. 这个问题常见于函数式风格的代码中, 因为没有明显的位置可以存放日志器. 另一个存在该问题的领域是能从日志中受益的泛型库. 在这种情况下, 拥有一个或多个全局日志器更为方便, 以便在需要时在任意位置轻松访问它们. 在这方面, std::cout 就是此类日志器的一个好例子.

库提供了一种声明全局日志器的方式, 可以像 std::cout 一样方便地访问. 实际上, 该功能可用于任何日志器, 包括用户自定义的. 声明全局日志器后, 可以确信从应用程序代码的任何位置都能线程安全地访问该日志器实例. 库还保证全局日志器实例即使在模块边界之间也是唯一的. 这使得即使是可能编译进不同模块的仅头文件组件也可以使用日志.

有人可能疑惑, 为什么创建全局日志器还需要特殊机制. 为什么不在命名空间作用域声明一个日志器变量, 需要时直接使用? 虽然技术上可行, 但声明和使用全局日志器变量因以下原因而复杂:

  • C++ 标准未规定命名空间作用域变量的初始化顺序. 这意味着通常不能在这个初始化阶段 (即在 main 之前) 使用日志器.
  • 命名空间作用域变量的初始化不是线程安全的. 您可能最终将同一个日志器初始化两次, 或使用未初始化的日志器.
  • 在仅头文件库中使用命名空间作用域变量相当复杂. 要么必须声明一个具有外部链接的变量, 且只在单个翻译单元中定义 (即放在单独的 .cpp 文件中, 这违背了"仅头文件"的初衷); 要么定义一个具有内部链接的变量, 或作为特例放在匿名命名空间中 (当头文件用于不同翻译单元时, 这很可能破坏 ODR 并产生意外结果). 还有其他编译器特定和标准技巧可以解决该问题, 但它们都不够简单且可移植.
  • 在大多数平台上, 命名空间作用域变量局部于编译它们的模块. 也就是说, 如果变量 a 具有外部链接且编译进了模块 X 和 Y, 每个模块都有自己的 a 变量副本. 更糟的是, 在其他平台上该变量可能在模块之间共享.

全局日志器存储旨在消除所有这些问题.

声明全局日志器最简单的方式是使用以下宏:

BOOST_LOG_INLINE_GLOBAL_LOGGER_DEFAULT(my_logger, src::severity_logger_mt< >)

my_logger 参数为日志器指定一个名称, 可用于获取日志器实例. 该名称充当所声明日志器的标记. 第二个参数表示日志器类型. 在多线程应用程序中, 当日志器可能从不同线程访问时, 用户通常希望使用线程安全版本的日志器.

如果需要向日志器构造函数传递参数, 还有另一个宏:

BOOST_LOG_INLINE_GLOBAL_LOGGER_CTOR_ARGS(
    my_logger,
    src::severity_channel_logger< >,
    (keywords::severity = error)(keywords::channel = "my_channel"))

宏的最后一个参数是 Boost.Preprocessor 序列, 表示传递给日志器构造函数的实参. 不过, 使用非常量表达式和对象引用作为构造函数实参时要小心, 因为这些实参只求值一次, 且往往难以确定求值的确切时机. 日志器在应用程序中首次请求 (由知晓该日志器声明的部分发起) 时构造. 确保此时所有实参都处于有效状态是用户的职责.

本节的第三个宏提供最大的初始化灵活性, 允许用户实际定义创建日志器的逻辑.

BOOST_LOG_INLINE_GLOBAL_LOGGER_INIT(my_logger, src::severity_logger_mt)
{
    // Do something that needs to be done on logger initialization,
    // e.g. add a stop watch attribute.
    src::severity_logger_mt< > lg;
    lg.add_attribute("StopWatch", attrs::timer());
    // The initializing routine must return the logger instance
    return lg;
}

与 BOOST_LOG_INLINE_GLOBAL_LOGGER_CTOR_ARGS 宏一样, 初始化代码只在首次请求日志器时调用一次.

重要

注意 One Definition Rule (ODR) 问题. 无论您选择哪种日志器声明方式, 都应确保 日志器在所有出现处以完全相同的方式声明, 并且 声明中涉及的所有符号名都解析为相同的实体. 后者包括 BOOST_LOG_INLINE_GLOBAL_LOGGER_INIT 宏初始化例程中使用的名称, 例如对外部变量、函数和类型的引用. 库会在一定程度上自我保护以避免 ODR 违规, 但一般而言, 如果违反该规则, 行为是未定义的.

为了缓解 ODR 问题, 可以将日志器声明与其初始化例程分离. 库提供了以下宏来实现这一点:

  • BOOST_LOG_GLOBAL_LOGGER 提供日志器声明. 它可以用在头文件中, 与上述 BOOST_LOG_INLINE_GLOBAL_LOGGER* 宏类似.
  • BOOST_LOG_GLOBAL_LOGGER_INIT、BOOST_LOG_GLOBAL_LOGGER_DEFAULT 和 BOOST_LOG_GLOBAL_LOGGER_CTOR_ARGS 定义日志器初始化例程. 它们的语义和用法与对应的 BOOST_LOG_INLINE_GLOBAL_LOGGER* 宏类似, 唯一例外是: 这些宏应在单个 .cpp 文件中使用.

例如:

// my_logger.h
// ===========

BOOST_LOG_GLOBAL_LOGGER(my_logger, src::severity_logger_mt)


// my_logger.cpp
// =============

#include "my_logger.h"

BOOST_LOG_GLOBAL_LOGGER_INIT(my_logger, src::severity_logger_mt)
{
    src::severity_logger_mt< > lg;
    lg.add_attribute("StopWatch", attrs::timer());
    return lg;
}

无论使用哪个宏声明日志器, 都可以通过日志器标记的静态 get 函数获取日志器实例:

src::severity_logger_mt< >& lg = my_logger::get();

日志器的后续使用与使用相应类型的常规日志器对象完全相同.

警告

需要指出, 不建议在应用程序的去初始化阶段使用全局日志器. 与应用程序中的任何其他全局对象一样, 全局日志器可能在您尝试使用它之前已被销毁. 在这种情况下, 最好拥有一个专门的日志器对象, 保证在需要期间始终可用.
