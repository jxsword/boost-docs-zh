为什么使用文件接收器时应用程序在进程终止时会崩溃?

Boost.Filesystem 存在一些已知问题 (例如 #8642 和 #9219), 会影响 Boost.Log 的文件接收器后端. 当文件接收器销毁时, 它会尝试执行最终的日志文件轮转, 这涉及使用 Boost.Filesystem 移动文件. 这通常发生在 Boost.Log 核心去初始化时, 即离开 main() 之后的全局去初始化阶段. 问题的症结在于, Boost.Filesystem 内部使用一个全局 locale 对象来为 path 执行字符编码转换, 而该 locale 可能在 Boost.Log 去初始化之前被销毁, 从而导致崩溃.

Boost.Log 无法影响全局去初始化的顺序, 但该问题可以在用户侧规避. 一种解决方案是确保 locale 在 Boost.Log 之前初始化. 可以通过在应用程序启动早期、执行任何 Boost.Log 调用之前调用 boost::filesystem::path::codecvt() 或 boost::filesystem::path::imbue() 来实现. 例如:

int main(int argc, char* argv[])
{
    boost::filesystem::path::imbue(std::locale("C"));
    initialize_log();

    // ...
}

注意, 在这种情况下, 您不能在全局构造函数中使用 Boost.Log, 或者必须确保 boost::filesystem::path::imbue() 仍被最先调用.

另一种解决方案是在从 main() 返回之前, 从日志核心中移除并销毁文件接收器. 这样, 文件轮转会在离开 main() 之前、locale 仍有效时发生. 文件接收器既可以逐个移除, 也可以作为 remove_all_sinks() 调用的一部分移除:

int main(int argc, char* argv[])
{
    // ...

    logging::core::get()->remove_all_sinks();

    return 0;
}

最后, 您可以为您注册到日志核心的每个文件接收器禁用最终日志文件轮转. 对于以编程方式添加的接收器, 可以通过在接收器后端上调用 enable_final_rotation(false) 来实现. 如果接收器是从 settings 创建的, 可以通过将 EnableFinalRotation 参数设置为 "false" 来实现.
