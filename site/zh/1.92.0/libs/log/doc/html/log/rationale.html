为什么作用域名称使用字符串字面量?

有人可能想知道, 为什么不允许使用任意字符串作为命名作用域名称. 答案很简单: 出于性能和安全考虑. 命名作用域支持功能与库的其他属性相关功能有一个重要区别. 即使不进行任何日志记录, 作用域栈也会被维护, 因此如果函数 foo 的函数体中有 BOOST_LOG_FUNCTION() 语句, 它总是造成减速. 允许作用域名称为任意字符串会显著加大减速, 因为需要分配内存并复制字符串 (更不用说还需要预先格式化它, 这同样有开销).

动态内存分配还引入异常安全问题: BOOST_LOG_FUNCTION() 语句 (及类似语句) 会成为潜在的异常来源. 如果用户想优雅地解决内存分配问题, 这些问题会使代码复杂化.

一种可能的替代方案是在某处池化预格式化并预分配的作用域名称, 但这无疑会进一步降低性能, 并引入何时更新或释放池化字符串的问题.

因此, 限制为字符串字面量似乎是最优决定, 既减少了动态内存使用, 又为常见需求提供了足够的灵活性.
