为什么不使用惰性流式输出?

库的一种可能实现方式是使用惰性表达式来延迟日志记录的格式化. 本质上, 表达式:

logger << "Hello, world!";

会变成一个 lambda 表达式, 只有在过滤成功时才会被调用. 尽管这种方式有优点, 但必须指出, 惰性表达式构造在性能、代码体积和编译时间方面并非零开销. 以下表达式:

logger << "Received packet from " << ip << " of " << packet.size() << " bytes";

会生成相当数量的代码 (与流输出运算符的数量成正比), 在过滤发生之前执行. 另一个缺点是, packet.size() 总是被调用, 无论记录是否实际写入日志. 为了延迟这一调用, 还需要更多辅助设施, 可能涉及 Boost.Bind、Boost.Lambda 或 Boost.Phoenix. 对于这样一个基础用例, 这种复杂化是不可接受的.

虽然库没有开箱即用提供惰性流式输出, 但没有什么能阻止在单独的日志器层次中开发它. 更多信息参见 扩展本库 一节.
