变更日志

2.34, Boost 1.91

  • 默认在 Cygwin 上启用进程间通信支持的构建.

2.33, Boost 1.90

  • 修复了 value_ref 访问中错失的一个优化.
  • 修复了 text_file_backend 中日志文件轮转时可能出现的长时间无用循环: 当日志文件名模式不包含文件计数器且日志文件大小超过 rotation_size 限制时, 接收器后端会反复尝试以不同的计数器值打开新日志文件, 结果每次都打开同一个文件. (GH#252)
  • 使 text_file_backend 中的文件大小检查对整数溢出更加健壮.

2.32, Boost 1.89

  • 新增对 BOOST_LOG_WITHOUT_ASIO 配置宏的支持, 该宏可用于移除对 Boost.Asio 的依赖并禁用相关功能.
  • 在 text_file_backend 中组合日志文件名时, 对文件计数器使用与区域设置无关的格式化. 这修复了 file_collector::scan_for_files 中后续解析文件名失败的问题. (PR#246)
  • 新增 wrap_filter 实用工具, 简化了在过滤表达式中注入用户自定义函数对象的操作. (GH#195)

2.31, Boost 1.88

  • 在 C++20 及更高标准模式下禁用了 std::codecvt<char16_t> 和 std::codecvt<char32_t> 语言环境 facet, 因为它们在 C++20 中已被弃用. 这意味着在 C++20 及更高标准中, 与 char16_t 和 char32_t 之间的字符编码转换不再可用.
  • 修复了使用 CMake 和 MinGW-w64 时的构建问题. (PR#241)
  • 修复了 text_file_backend 使用错误文件计数器的问题: 当后端被配置为追加到已有文件, 且当前写入的文件名模式不含计数器占位符而目标文件名模式含有计数器占位符, 并且日志文件直接写入目标存储时会出现此问题. (GH#245)

2.30, Boost 1.87

  • 将 Boost.Thread 同步原语替换为 C++ 标准库中的等价物. 这可能提升多线程性能, 但也会对用户产生如下影响:
    • 不再支持 Boost.Thread 线程中断. Boost.Log 不再对 thread_interrupted 异常 (Boost.Thread 用于实现线程中断) 做特殊处理. 该异常将像其他异常一样被处理. 特别地, 现在用户指定的异常处理器可能会在存在 thread_interrupted 未决异常时被调用.
    • 对于限时等待操作, 超时时间现在使用 std::chrono 时间单位. 这意味着 ordering_window 命名参数 (由 bounded_ordering_queue 和 unbounded_ordering_queue 类支持) 现在接受 std::chrono::duration 类型的值, 而不再是 boost::posix_time::time_duration (来自 Boost.DateTime).
    • 当线程同步原语指示错误时, 现在抛出 std::system_error 异常, 而不是 Boost.Thread 的异常类型.
  • 为 strictest_lock 增加了对 C++ 标准库锁类型的支持.

2.29, Boost 1.86

  • 为 windres.exe 的问题添加了一种变通方法, 该问题出现在 CMake 在 MinGW-w64 上编译事件日志资源文件时. (PR#231)

2.28, Boost 1.84

  • 不再支持 C++03. 需要 C++11 或更高版本的编译器.
  • 当使用符合要求的 C++11 编译器构建 (足以使用 Boost.Regex v5) 时, Boost.Log 不再链接 Boost.Regex 预编译库, 因为 Boost.Regex v5 是仅头文件库.
  • 对 Windows 10 之前版本的支持已被弃用, 并将在 Boost 1.87 中移除.

2.27, Boost 1.83

  • 修复了 text_file_backend 中可能出现的无限循环: 当格式化后的日志记录大小超过 rotation_size 限制时. (GH#209)

2.26, Boost 1.82

  • 由于 Boost.Log 所用的 Boost 库发生变化, 对 C++03 的支持已被弃用. 从 Boost.Log 1.84 起, C++11 将成为最低要求.

2.25, Boost 1.80

缺陷修复:

  • 修复了基于 UDP 套接字的 syslog_backend 在 syslog 服务器使用 IPv6 地址时绑定错误本地地址的问题. (GH#181)
  • 为 gcc 11.2 的 libstdc++ 中的一个 缺陷 添加了变通方法. 当 max_size_decor 用于格式化流时, std::codecvt::do_length 会错误地访问输入缓冲区并导致缓冲区溢出.

2.24, Boost 1.79

一般变更:

  • 在 text_file_backend 中, 当使用文件轮转且日志文件名使用文件计数器时, 增加了对追加写入先前已写日志文件的支持. 为使其生效, 目标存储目录必须与当前日志文件的写入目录相同, 并且必须在发出任何日志记录之前调用 text_file_backend::scan_for_files, 以发现目标存储目录中最后使用的文件计数器. 以前, 在这种配置下, 接收器后端会生成新的文件名, 而不是追加到最后写入的文件.
  • 破坏性变更: collector 接口已更改:
    • scan_for_files 方法返回一个 scan_result 结构, 其中包含扫描期间收集的信息;
    • 新增 is_in_storage 方法, 用于测试路径是否指向目标存储目录内的文件.
  • 新增 invoke_manip 流操纵器, 可用于将用户函数注入流输出表达式.

缺陷修复:

  • 修复了当用户多次调用 text_file_backend::scan_for_files 且第二次及后续调用未发现任何新文件时, 文件计数器被置为零的问题. (GH#179)

2.23, Boost 1.78

一般变更:

  • 更新了 std::codecvt 特化对 char16_t 和 char32_t 的检测, 以兼容 C++17 及更高版本. (PR#159)
  • 新增了对 C++17 std::byte 类型的支持, 用于 进程间消息队列 的接收方法.
  • 在 Windows 上, 为 Windows 8 或更高版本构建库时, 库将在版本命名空间中使用 nt62 标签来表示目标 OS ABI. 例如, 版本命名空间可命名为 v2_mt_nt62. 该名称将成为库导出的所有符号的一部分. 在构建 Boost 和您的代码时, 请一致地使用 BOOST_USE_WINAPI_VERSION 宏来指定最低目标 Windows 版本.
  • 改进了 dump 流操纵器的 SSSE3 和 AVX2 实现的性能.
  • 增加了对 CMake 构建系统的支持. 目前仅支持库构建, 运行测试仍使用 Boost.Build.

缺陷修复:

  • 修复了 POSIX 系统上 reliable_message_queue::open_or_create 或等效构造函数中的竞态条件. 多个线程或进程在从同一队列发送或接收消息的同时并发调用 open_or_create, 可能导致队列内容损坏, 甚至使进程崩溃. (GH#162)
  • 为 b2 install 在 Windows 上因缺少 boost_log_setup 库而失败 (当定义了 BOOST_LOG_WITHOUT_SETTINGS_PARSERS 时) 的问题添加了变通方法. (GH#164)

2.22, Boost 1.77

缺陷修复:

  • 修复了 Linux 上 riscv32 目标的编译问题. (PR#150)
  • 设置 std::ios_base::app 文件打开模式 (在 text_file_backend 中) 现在也隐含 std::ios_base::ate. 这修复了为追加而打开的日志文件的初始大小统计不正确的问题. (GH#151)

2.21, Boost 1.76

缺陷修复:

  • 修正了 unbounded_fifo_queue 策略 (属于 asynchronous_sink 前端) 所用线程安全日志记录队列实现中的一个形式上的竞态条件. TSAN 可以检测到该竞态, 但在大多数现有 CPU 架构和编译器上它并非实际问题. (GH#139)
  • 复制带有通道属性的日志器时 (例如 channel_logger), 现在会从原始日志器深拷贝通道属性. 这意味着修改新日志器中的通道将不再影响原始日志器.
  • 在模板参数中, 将 std::allocator<void> 的使用替换为新的标记类型 boost::log::use_std_allocator, 以消除 libc++ 关于前者在 C++17 及更高版本中被弃用的警告. 该标记指示实例化的模板应在内部使用 std::allocator 的特化来分配动态内存, 因此该变更没有功能性影响. (GH#141)
  • Boost.Log 在 MinGW 和 MinGW-w64 上不再定义 __MSVCRT_VERSION__ 宏. 该宏用于选择目标 C 运行时库. 定义该宏会导致与 UCRT 不兼容, 而 UCRT 是较新 MinGW-w64 中的一个可选项. (PR#149)

2.20, Boost 1.75

缺陷修复:

  • 修正了 text_file_backend 在日志文件轮转时生成目标文件名 (基于 set_target_file_name_pattern 方法设置的模式) 所使用的文件计数器. 以前后端会使用文件计数器的下一个值, 这可能导致应用程序重启时跳过某些计数器值. (GH#125)
  • 将 basic_sink_frontend 中的 volatile 版本计数器替换为原子变量. 这应能消除 clang-cl 关于 volatile 已弃用用法的警告. (GH#128)
  • 在 asynchronous_sink 前端中, 解决了 flush 与 run 方法之间可能存在的冲突: 如果 run 是从用户线程而非前端生成的内部专用线程调用. run 和 feed_records 方法会在 flush 正在进行时等待其完成. 此外, stop 现在明确不会等待正在进行的记录馈送操作完成. (GH#131)

2.19, Boost 1.74

缺陷修复:

  • syslog 接收器后端现在会校验用户设置的本地地址和目标地址的 IP 版本. 这些地址的 IP 版本必须与接收器后端构造时在 ip_version 命名参数中指定的相同 (默认为 IPv4). 当地址通过主机名解析获得时, 只考虑 IP 版本匹配的地址. (GH#119)

新特性:

  • 各组件的移动构造函数和移动赋值运算符被标记为 noexcept.
  • 新增 range_manip 流操纵器, 可用于输出范围中的元素, 可选地以分隔符分隔.
  • 新增 tuple_manip 流操纵器, 可用于输出元组或其他异构序列的元素, 可选地以分隔符分隔.
  • 新增 optional_manip 流操纵器, 可用于输出可能存在的值.

2.18, Boost 1.73

新特性:

  • 当日志核心中未注册任何接收器时, 简单日志使用的默认接收器现在会在每条日志记录后自动刷新输出. (GH#103)
  • 当未注册任何接收器时, core::flush 现在会对简单日志使用的默认接收器执行刷新.

缺陷修复:

  • 为某些 syslog API 实现 (例如 glibc) 添加了变通方法, 这些实现不会在 openlog 调用中保存应用程序标识字符串. 此类实现可能在每次 syslog 调用时访问已释放的内存, 从而导致未定义行为. (GH#97)
  • 修复了在每月特定日期进行日志文件轮转 (例如 rotation_at_time_point(boost::gregorian::greg_day(1))) 可能被静默忽略而不执行的问题. (GH#98)
  • 修复了 text_file_backend::rotate_file 可能抛出异常的问题: 当尚未写入任何日志记录且已设置目标文件名模式时, 该方法会尝试重命名一个不存在的文件, 从而导致异常. 注意, 如果被轮转的日志文件被第三方删除, rotate_file 仍可能因日志文件缺失而抛出异常.
  • 将库的多个组件移植到 std::allocator_traits, 以提升与 C++20 分配器的兼容性.
  • 修复了在 MSYS2 Cygwin 环境中构建时的编译错误. (GH#102)

2.17, Boost 1.71

新功能:

  • 改进了对 C++17 std::string_view 的支持 (在 basic_formatting_ostream 中). 字符串视图现在可以参与输出时的字符编码转换.
  • 新增 auto_newline 格式化器 和 流操纵器. 它可用于确保格式化输出总是以换行符结尾, 同时避免出现重复的换行符.
  • 在 输出流、文本文件 和 文本多文件 接收器后端中, 增加了对配置"在每条格式化日志记录后追加结尾换行符"这一行为的支持. 用户可以指定 auto_newline_mode 枚举的值, 方式是在后端构造函数的 auto_newline_mode 命名参数中传入, 或在构造之后调用后端的 set_auto_newline_mode 方法. auto_newline_mode 命名参数在用于初始化接收器的 便捷函数 中同样受支持. 从 settings 或配置文件初始化时, 该行为由接收器的新参数 "AutoNewline" 控制.
注释

与之前的 Boost.Log 版本相比, 结尾换行符的默认行为略有变化. 现在后端只会在格式化后的日志消息字符串中尚无换行符时才添加结尾换行符. 在之前的版本中, 换行符是无条件添加的. 一般来说, 建议用户配置自己的格式化器, 在需要时在其中添加结尾换行符 (例如使用 auto_newline 格式化器), 并在接收器后端中禁用自动插入结尾换行符. 该功能主要为向后兼容而存在, 可视为已弃用.

  • 输出流 和 文本多文件 接收器后端现在可以通过命名参数构造.
  • 增加了在接收器构造函数和用于初始化接收器的 便捷函数 的 filter 和 format 命名参数中传递任意函数对象的支持 (此前仅支持 Boost.Phoenix 函数对象). 例如, 现在可以在这些参数中直接指定 C++11 lambda 函数. (GH#63)
  • 在 过滤器和格式化器解析器 使用的默认过滤器和格式化器工厂中, 增加了对类型为 boost::log::trivial::severity_level 的严重级别属性值的支持. 对于过滤器, 该支持仅限于名称为 "Severity" 的属性. 这使用户无需注册过滤器和格式化器工厂, 即可将 boost::log::trivial::severity_level 用于从字符串或 settings 解析的过滤器和格式化器. 注意, 其他任何自定义严重级别枚举仍必须像以前一样 注册.

缺陷修复:

  • 修复了 文本文件接收器后端 在扫描文件时对轮转文件名各组成部分解析不正确的问题. 如果文件名模式以占位符结尾 (例如文件计数器), scan_for_files 方法将无法在目标存储中找到匹配该模式的文件, 导致这些文件处于无人管理状态. 特别是, 这些文件不会被删除以释放目标存储空间. (GH#78)
  • 更新了 basic_formatting_ostream 和 basic_record_ostream, 使得可以为指向用户自定义类型的指针重载流输出运算符. 当指针被写入某个 Boost.Log 流时, 编译器现在应能选取用户定义的 operator<< 重载 (接受 std::basic_ostream 和一个指针参数). (GH#84)

2.16, Boost 1.70

新功能:

  • 在 文本文件接收器后端 中增加了在收集文件之前生成另一个日志文件名的支持. 这使得可以将 追加写入 现有日志文件与日志文件名中的时间戳和文件计数器结合起来, 从而也可以正常进行 文件收集. 要启用该功能, 必须在文本文件接收器后端中设置目标文件名模式 (通过 target_file_name 命名参数、text_file_backend::set_target_file_name_pattern 方法调用, 或 settings 中的 "TargetFileName" 接收器参数). 当文件写完即将被收集时, 将使用该模式生成新的文件名. 因此, 原始 (活动) 文件名可以设置为稳定模式 (例如 "app.log"), 以便追加写入先前已写的文件; 而目标文件名可以包含时间戳或计数器 (例如 "app-2019-01-05.log"), 使不同轮转文件在目标存储中互不冲突.

2.15, Boost 1.69

缺陷修复:

2.10, Boost 1.63

一般变更:

  • 移除了先前已弃用的 type_info_wrapper. 如之前的建议, 推荐使用 Boost.TypeIndex 作为替代.

新功能:

2.9, Boost 1.62

新功能:

  • 为本地机器上的进程间日志增加了新工具. 实现包括一个 资源名称包装器、一个 进程间消息队列 和一个 接收器后端. 新功能是可选的, 可以在库构建时通过定义 BOOST_LOG_WITHOUT_IPC 宏来禁用. 感谢 Lingxi Li 提供初始补丁.

缺陷修复:

  • 修复了日志流可能在不同的日志记录之间保留格式化设置的问题. (#12178)

2.8, Boost 1.61

一般变更:

  • 增加了对限制文件收集器目标目录中存储日志文件数量的支持. 该限制可通过 max_files 命名参数在 make_collector 或 add_file_log 调用中指定, 也可作为设置文件中接收器的 "MaxFiles" 参数指定. 感谢 Erich Keane 提供补丁. (#8746)

缺陷修复:

  • 修复了 Windows CE 的各种编译问题.
  • 修复了 Solaris 上的编译问题.
  • 为 MSVC-10 和 11 在某些情况下为格式化器生成错误代码的问题添加了变通方法. (#12025)

2.7, Boost 1.60

一般变更:

  • 在 Windows 上, 库不再使用配置宏 BOOST_LOG_USE_WINNT6_API. 目标 Windows 版本应通过将宏 BOOST_USE_WINAPI_VERSION 定义为所需的 WinAPI 版本来配置 (例如 Windows XP 为 0x0501). 除 Boost.Log 外, 多个不同的 Boost 库也使用该宏.
  • 默认目标 Windows 版本现在为: 在带有足够新 Windows SDK 的编译器上是 Vista, 其他情况下是 XP. 该默认值不再由 Boost.Log 选择, 而是由不同 Boost 库共用的 WinAPI 子模块选择.

2.0, 13 April 2013

一般变更:

  • 库现在与 Boost 1.53 或更新版本兼容. 不再支持 Boost.Filesystem v2.
  • 库现在不再为不同字符类型引入单独的日志核心. 许多其他库组件也变得与字符类型无关. 应用程序现在可以将不同字符类型的日志器与公共日志核心一起使用. 库会按需执行字符编码转换. 可以使用 Boost.Locale 构造 locale 对象以进行正确的编码转换.
  • 配置宏 BOOST_LOG_NO_COMPILER_TLS 已被含义相反的 BOOST_LOG_USE_COMPILER_TLS 取代. 编译器 TLS 内建函数的支持现在默认禁用.
  • 增加了配置宏 BOOST_LOG_WITHOUT_DEBUG_OUTPUT、BOOST_LOG_WITHOUT_EVENT_LOG 和 BOOST_LOG_WITHOUT_SYSLOG. 宏 BOOST_LOG_NO_SETTINGS_PARSERS_SUPPORT 重命名为 BOOST_LOG_WITHOUT_SETTINGS_PARSERS. 新宏允许选择性地禁用对相应接收器后端的支持.
  • 库现在内部使用 Boost.Xpressive 而非 Boost.Regex, 因此使用本库时无需构建后者. 在用户侧仍支持 Boost.Regex.
  • 让部分内部代码在未通过 BOOST_LOG_USE_WINNT6_API 宏显式启用时, 在运行期检测 Windows NT6 API 的可用性. 未定义该宏编译的代码仍可在 NT5 上运行, 但在 NT6 上运行时效率会更高. 定义该宏后生成的代码将无法在 NT5 上运行, 但在 NT6 上会比不定义该宏时略更高效.
  • 引入了默认接收器的概念. 当日志核心中未配置任何接收器时, 使用默认接收器. 该接收器是同步且线程安全的, 无需任何配置, 并会被用户在核心中配置的任何接收器取代. 默认接收器会将日志消息写入控制台, 并在前面加上时间戳、线程 id 和严重级别.
  • 简单日志不再隐式初始化库. 除非对库作了其他配置, 否则将使用默认接收器显示日志消息. 现在可以同时使用简单日志和高级日志.
  • 现在可以在过滤之后向日志记录添加属性值. 这些属性值不参与过滤, 但可被格式化器和接收器使用. 日志记录消息现在是这类属性值之一, 不再能从日志记录接口直接访问.
  • 格式化器和接收器不再作用于日志记录, 而是作用于 record_view. 记录在被推入核心进行后续处理时会被移走 (move-from). 这样做是为了消除推入核心之后不安全地修改记录的可能性. 因此, 日志记录不再能被复制, 只允许移动. 记录视图可以被复制和移动; 复制是浅层操作.
  • 实现现在提供了若干流操纵器. 其中, to_log 操纵器允许为特定类型和属性自定义格式化, 而无需更改常规流运算符. 另外, add_value 操纵器可用于日志表达式中, 将属性值附加到记录上.
  • 为加快代码编译做了大量改进.

属性:

  • 更改了属性值的接口和处理方式. 属性值现在是围绕值持有者的 pimpl 包装器. 库各组件中的 attribute_value 类不再通过 shared_ptr 指向, 而是按值处理. 这使得简单场景下的属性值处理得以简化.
  • 与属性值类似, 属性的接口也按 pimpl 方式进行了重构. 所有属性现在都派生自 attribute 基类, 该基类持有对实现的引用. 所有属性现在都必须按值创建, 而不是由用户包装进 shared_ptr, 这使代码更加简洁.
  • 增加了将属性从基类 attribute 向下转换为实际属性类型的支持. 当具体属性工厂提供额外接口时, 这会很有用.
  • 属性值不再有 get 方法. 请改用 extract 函数作为替代.
  • 属性集和属性值集的键类型已更改. 新的键类型名为 attribute_name. 它可以从字符串构造, 因此在大多数情况下用户无需更改代码. 更多信息参见 此处.
  • 属性值视图 (attribute values view) 已更名为属性值集 (attribute value set). 该容器现在支持在构造之后继续添加属性值.
  • 属性集和属性值集不再维护元素的顺序. 虽然此前未明确说明, 但这些容器过去是有序关联容器. 现在元素的顺序是未指定的. 实现经过重构, 加快了属性的插入/移除、属性查找以及值集的构建. 缺点是某些情况下内存占用可能增加.
  • 属性集现在使用小型内存池来加快元素的插入/移除.
  • 头文件 scoped_attribute.hpp 从 utility 移到了 attributes 目录. 头文件 attribute_value_extractor.hpp (位于 utility) 已被 boost/log/attributes/value_extraction.hpp 和 boost/log/attributes/value_visitation.hpp 头文件取代 (位于 attributes 目录). 这两个新头文件分别定义了修订后的属性值提取和访问 API. 更多细节参见 此处.
  • 作用域属性 宏得到简化. 属性构造函数参数直接在属性类型旁指定, 且不再需要标记类型.
  • current_thread_id 属性不再使用 boost::thread::id 类型来标识线程. 现在使用一种内部类型, 可通过 current_thread_id::value_type 访问. 新的线程 id 取自底层 OS API, 因此与调试器和系统诊断工具可能显示的内容关联更紧密.
  • 新增 current_process_name 属性. 该属性生成一个包含当前进程可执行文件名的字符串.
  • functor 属性已更名为 function. 生成器函数已从 make_functor_attr 更名为 make_function. 头文件已从 functor.hpp 更名为 function.hpp.

日志源:

  • 修复了日志器异常处理功能的编译问题.
  • 全局日志器存储对默认设置隐藏可见性的环境更加友好.
  • 增加了用于分离全局日志器声明和定义的宏. 旧宏已重命名以更好地反映其作用 (BOOST_LOG_DECLARE_GLOBAL_LOGGER_INIT 改为 BOOST_LOG_INLINE_GLOBAL_LOGGER_INIT, BOOST_LOG_DECLARE_GLOBAL_LOGGER 改为 BOOST_LOG_INLINE_GLOBAL_LOGGER_DEFAULT, BOOST_LOG_DECLARE_GLOBAL_LOGGER_CTOR_ARGS 改为 BOOST_LOG_INLINE_GLOBAL_LOGGER_CTOR_ARGS). 此外, 这些宏不再定义用于获取日志器的 get_logger 自由函数. 请改用 logger::get. 更多信息参见 此处.
  • 通道日志器现在支持在构造之后更改通道名称. 通道名称可以通过调用修改方法设置, 也可以在日志语句中指定. 新增 BOOST_LOG_STREAM_CHANNEL 和 BOOST_LOG_STREAM_CHANNEL_SEV (以及它们的简写 BOOST_LOG_CHANNEL 和 BOOST_LOG_CHANNEL_SEV) 宏, 允许为日志记录指定通道名称.

日志接收器:

  • syslog 和事件日志的整数常量类型已重命名, 去掉了 _t 后缀.
  • 格式化功能已移至接收器前端. 支持记录格式化的接收器后端派生自 basic_formatting_sink_backend 类模板, 该模板向前端表明需要记录格式化. 这破坏了库的用户侧 API: 格式化器和 locale 必须设置到前端而不是后端.
  • 格式化支持不再强制要求前端进行线程同步. 格式化在为后端处理记录而加锁之前完成, 可以在多个线程中并发执行.
  • 增加了对接收器刷新的支持. 支持刷新的接收器后端必须定义具有以下签名的公有方法: void flush().
  • 异步接收器前端经过重构, 有序异步接收器已移除. asynchronous_sink 类模板现在允许指定记录排队策略. 提供了多种策略, 包括 unbounded_fifo_queue (默认) 和 unbounded_ordering_queue, 后两者涵盖了 1.x 版本中异步接收器前端的功能. 更多细节参见 异步接收器前端 文档.
  • 异步接收器中的无锁 FIFO 记录排队经过重构, 以减少日志记录处理停顿.
  • 为文本文件接收器增加了 Append 配置文件参数. 如果该参数设置为 true, 接收器将把日志记录追加到现有日志文件中, 而不是覆盖它.
  • 增加了异步接收器前端的有界变体. 实现了两种处理队列溢出的策略: 或者丢弃日志记录, 或者阻塞日志线程直到队列中有空间.

过滤器和格式化器:

  • 作为字符类型统一的结果, 过滤器不再依赖于字符类型.
  • 引入了两个新类型, 用于动态存储过滤器和格式化器: filter 和 basic_formatter. 这两个新类型都实现了类型擦除, 并提供函数调用运算符来调用所存储的过滤器或格式化器.
  • 过滤器和格式化器经过重写. 新实现基于 Boost.Phoenix, 位于 expressions 命名空间中. 属性占位符现在可与其他基于 Boost.Phoenix 的模板表达式互操作. 所有模板表达式头文件现在都位于 expressions 子目录中.
  • 库现在支持为属性定义关键字 (参见 BOOST_LOG_ATTRIBUTE_KEYWORD 宏). 关键字可以在模板表达式中代替属性占位符使用, 也可用作容器查找中的键.
  • 当属性值无法用于完成函数时 (例如值缺失或类型不当), 过滤器和格式化器默认不再抛出异常. 在这种情况下, 出错的过滤器子表达式将返回 false, 格式化器将以空字符串代替该值. 可以通过在过滤/格式化表达式中对属性值占位符调用 or_default 或 or_throw 成员函数来更改该行为.
  • 日期和时间格式化器实现不再基于 Boost.DateTime 的 IO facet. 新实现提升了格式化性能. 该格式化器已更名为 format_date_time.
  • 命名作用域格式化器现在支持作用域格式说明. 作用域格式可以包含作用域名称, 以及文件名和行号. 该格式化器已更名为 format_named_scope.
  • 字符装饰器 已更名为 c_decor、c_ascii_decor、xml_decor 和 csv_decor. 通用字符装饰器现在名为 char_decor.
  • 新增 通道严重级别过滤器. 该过滤器允许为不同通道设置严重级别阈值. 过滤器将日志记录的严重级别与该记录所属通道对应的阈值进行比较.

文档变更:

  • 文档中的大多数代码示例已被提取为可编译的独立示例, 可用于测试和试验该库.
  • 为文档添加了大量交叉引用, 应能简化导航.

其他:

  • 修复了一个缺陷: 如果接收器抛出异常且该异常被核心中设置的异常处理器抑制, 日志核心可能在 push_record 内进入无限循环.
  • 更改了类型分派实现, 以减少虚函数的使用. 这大幅减小了库的体积.
  • 类型分派器对默认设置隐藏可见性的环境更加友好.
  • 类型分派器的接口已更改. 分派器现在按值返回 type_visitor 实例, 访问器不再是分派值的实际接收者的基类. 相反, 如果接收者能够消费该值, 访问器现在会引用接收者. visit 方法已更名为 operator (). 静态类型分派器现在在构造时需要接收者的引用, 不再要求接收者派生自分派器.
  • slim_string 实用工具已被移除. 没有替代品.
  • 库现在使用了最新 C++ 标准 (即 C++11) 的许多特性. 例如, 许多库组件现在支持移动语义. 在兼容 C++03 的编译器上, 使用 Boost.Move 进行移动语义模拟.

1.0, 09 May 2010

本版本主要修复代码和文档中的缺陷. 下一个大版本 (2.0) 将包含破坏性变更和新功能. 1.0 分支将不再接收任何功能更新.

  • 为线程局部存储添加了一些优化. 在 Windows 环境下, 如果在应用程序运行期动态加载 Boost.Log 二进制文件, 该优化可能导致崩溃. 在这种情况下, 可以在库构建过程中定义 BOOST_LOG_NO_COMPILER_TLS 来禁用它. 该宏也影响其他平台, 如果您的编译器不支持 TLS, 这可能有用.
  • 为严重级别日志器和通道日志器添加了一些公有访问器和便捷构造函数.
  • 增加了在指定时间点轮转日志文件的能力. rotation_interval 关键字不再可用. 相同功能可通过新的 time_based_rotation 关键字和 rotation_at_time_interval 谓词实现. 更多细节参见 此处.
  • 改进了对 MinGW 和 Cygwin 的支持.
  • 修复了若干缺陷. 增加了在 GCC 4.2 上编译的变通方法.
  • 文档中的大量修正.

Release Candidate 4, 08 Jan 2010

  • 文档大幅改进. 教程一节经过重新组织.
  • 库头文件经过重新组织. 此前被头文件包含的一些其他 Boost 库改为可选. 这些依赖被提取到 support 目录中的独立头文件中. 顶层库头文件现在大多只包含嵌套头文件.
  • 关键字已移至专用的 keywords 命名空间. 命名空间中不再有嵌套的 keywords 命名空间 (如 sinks、attributes 等). 所有关键字已被提取到 keywords 目录中的独立头文件中.
  • 移除了轮转文件流. 作为替代, 增加了 新的文件接收器, 可以达到相同效果并增加了更多功能.
  • 新增了 多文件 (multifile) 接收器后端.
  • 新增了有序异步接收器前端.
  • syslog 接收器后端现在也支持 Windows. 该接收器不再要求原生支持 POSIX syslog API, 而是能够通过 UDP 将 syslog 包发送到远程服务器.
  • 日志器实现得到改进. 特性组合机制经过清理.
  • 增加了对作用域日志的支持. 现在有一个独立的 日志记录实体, 由核心作为过滤结果返回. 用户可以用任意方式填充记录消息, 而不必使用流式表达式. 记录对象现在由接收器和格式化器处理.
  • 增加了对异常控制的支持. 用户可以在三个层次之一注册异常处理器: 针对特定接收器、在核心层, 以及针对特定日志器 (前提是它具有相应特性). 接收器和核心默认不抑制异常. 如果找不到请求的属性值, 过滤器和格式化器将抛出异常.
  • 新增了几个名为字符装饰器的格式化器. 它们可用于在将格式化输出传给接收器之前对其进行后处理.
  • 增加了线程和进程标识符属性. 这些标识符在调用 add_common_attributes 之后自动添加.
  • 辅助初始化函数 (例如 init_log_to_file) 现在接受更多作为命名实参的自定义选项.
  • 公开了新的 初始化接口. 可以填充 settings 容器并使用它来初始化库.
  • 库安装支持代码已被提取到单独的二进制文件中. 后续, 该二进制文件将改为可选构建.
  • 增加了一种新的日志模式, 称为简单日志. 在这种模式下, 库完全无需初始化, 但不提供太多自定义方式.
  • 修复了若干缺陷.
  • 增加了一些优化, 以提升多线程应用程序的性能.
  • 移除了针对旧版 Boost 的一些缺陷变通方法. 库现在要求 Boost 1.39 或更新版本.

Release Candidate 3, 08 Feb 2009

  • 增加了几个 Windows 专用接收器: 事件日志 (简化版和高级版)、Windows 调试器, 以及面向 Windows Vista 及更高版本的实验性事件跟踪 (Event Trace).

  • 增加了测试.
