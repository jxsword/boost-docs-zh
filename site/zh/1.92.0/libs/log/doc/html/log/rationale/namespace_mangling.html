为什么我的应用程序无法与 Boost.Log 链接? 库命名空间是怎么回事?

库声明了 boost::log 命名空间, 客户端代码应使用它来访问库组件. 不过, 库内部使用另一个嵌套命名空间进行实际实现. 命名空间名称取决于配置和平台, 可能随库的不同版本而变化, 因此绝不应在用户侧代码中使用. 这样做是为了让库配置与应用程序尽可能同步, 并消除配置不匹配引起的问题.

大多数时候, 用户甚至不会注意到这个内部命名空间的存在, 但它经常出现在编译器和链接器错误中, 在某些情况下了解如何解读其名称会有帮助. 目前, 命名空间名称由以下元素组成:

<version><linkage>_<threading>_<system>
  • <version> 部分描述库的主版本. 目前为 v2.
  • <linkage> 部分表明库是静态链接还是动态链接. 静态链接时为 s, 否则为空.
  • <threading> 部分在单线程构建中为 st, 在多线程构建中为 mt.
  • <system> 部分描述库使用的底层 OS API. 目前仅对多线程构建指定. 视目标平台和配置而定, 它可以是 posix、nt5、nt6 或 nt62.

举两个简单例子: v2s_st 对应库的 v2 静态单线程构建, 而 v2_mt_posix 对应 POSIX 系统 API 的 v2 动态多线程构建.

如果应用程序配置不当, 命名空间修饰可能导致链接错误. 一个常见错误是构建了库的动态版本, 但在构建应用程序时未定义 BOOST_LOG_DYN_LINK 或 BOOST_ALL_DYN_LINK, 导致库默认假定静态链接. 每当出现此类链接错误时, 可以解读缺失符号和 Boost.Log 库导出符号中的命名空间名称, 并相应调整库或应用程序的 配置.
