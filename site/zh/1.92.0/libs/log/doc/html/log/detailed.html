日志核心

日志记录 

#include <boost/log/core/record.hpp>

日志库处理的所有信息都打包在一个 record 类型的对象中. 所有附带的数据 (包括消息文本) 都表示为命名属性值, 可由过滤器、格式化器和接收器获取和处理. 特定属性值可以用不同方式访问, 下面是几个简单的例子:

  • 通过 值访问与提取.

enum severity_level { ... };
std::ostream& operator<< (std::ostream& strm, severity_level level);

struct print_visitor
{
    typedef void result_type;
    result_type operator() (severity_level level) const
    {
        std::cout << level << std::endl;
    };
};

// Prints severity level through visitation API
void print_severity_visitation(logging::record const& rec)
{
    logging::visit< severity_level >("Severity", rec, print_visitor());
}

// Prints severity level through extraction API
void print_severity_extraction(logging::record const& rec)
{
    logging::value_ref< severity_level > level = logging::extract< severity_level >("Severity", rec);
    std::cout << level << std::endl;
}

  • 通过搜索 属性值集 (可由记录的 attribute_values 方法访问).

// Prints severity level by searching the attribute values
void print_severity_lookup(logging::record const& rec)
{
    logging::attribute_value_set const& values = rec.attribute_values();
    logging::attribute_value_set::const_iterator it = values.find("Severity");
    if (it != values.end())
    {
        logging::attribute_value const& value = it->second;

        // A single attribute value can also be visited or extracted
        std::cout << value.extract< severity_level >() << std::endl;
    }
}

  • 通过用属性关键字应用下标运算符. 这实际上是值提取 API 的便捷包装.

BOOST_LOG_ATTRIBUTE_KEYWORD(severity, "Severity", severity_level)

// Prints severity level by using the subscript operator
void print_severity_subscript(logging::record const& rec)
{
    // Use the attribute keyword to communicate the name and type of the value
    logging::value_ref< severity_level, tag::severity > level = rec[severity];
    std::cout << level << std::endl;
}

日志记录不能被复制, 只能移动. 记录可以默认构造, 此时处于空状态; 这样的记录基本不可用, 不应传递给库处理. 非空日志记录只能由 日志核心 在过滤成功后创建. 非空记录包含从属性获取的属性值. 过滤之后可以向非空记录添加更多属性值. 新增的值不会影响过滤结果, 但仍可被格式化器和接收器使用.

在多线程环境中, 非空日志记录构造之后被视为绑定到当前线程, 因为它可能引用某些线程专属资源. 例如, 记录可能包含一个引用命名作用域列表的属性值, 而该列表存储在栈上. 因此, 日志记录不得在不同线程之间传递.

记录视图 
#include <boost/log/core/record_view.hpp>

记录用于填充信息, 而库使用另一种类型来实际处理信息. 记录视图提供与记录类似的接口, 但有几个显著区别:

  • 记录视图是不可变的. 这可以防止格式化器和接收器在处理记录时修改记录.
  • 记录视图是可复制的. 由于其内容是常量, 复制操作是浅层的, 因此开销很小.

库会通过调用 lock 方法自动从记录创建记录视图. 如果接收器是异步的, 该调用还会确保生成的视图不与当前线程关联. lock 调用是一次性操作; 之后记录将处于空状态. 前文针对日志记录描述的所有与属性值交互的 API 同样适用于记录视图, 可在自定义格式化器和接收器中使用.

#include <boost/log/core/core.hpp>

日志核心是提供以下设施的中心枢纽:

  • 维护全局属性集和线程专属属性集.
  • 对日志记录执行全局过滤.
  • 通过应用接收器专属过滤器, 在各接收器之间分派日志记录.
  • 为异常处理器提供全局钩子.
  • 为日志源提供写入日志记录的入口.
  • 提供 flush 方法, 可用于强制所有日志接收器进入同步状态.

日志核心是应用程序级的单例, 因此每个日志源都可以访问它. 核心实例可通过静态方法 get 访问.

void foo()
{
    boost::shared_ptr< logging::core > core = logging::core::get();

    // ...
}
属性集

为了向核心添加或移除全局或线程专属属性, 有相应的方法: add_global_attribute、remove_global_attribute、add_thread_attribute 和 remove_thread_attribute. 属性集提供类似于 std::map 的接口, 因此 add_* 方法接受属性名字符串 (键) 和指向属性的指针 (映射值), 并返回由迭代器和布尔值组成的对, 就像 std::map< ... >::insert 那样. remove_* 方法接受指向先前添加属性的迭代器.

void foo()
{
    boost::shared_ptr< logging::core > core = logging::core::get();

    // Add a global attribute
    std::pair< logging::attribute_set::iterator, bool > res =
        core->add_global_attribute("LineID", attrs::counter< unsigned int >());

    // ...

    // Remove the added attribute
    core->remove_global_attribute(res.first);
}
提示

必须说明, 在多线程环境中日志核心的所有方法都是线程安全的. 不过, 其他组件 (例如迭代器或属性集) 可能并非如此.

可以获取整个属性集 (全局或线程专属) 的副本, 或将其安装到核心中. 方法 get_global_attributes、set_global_attributes、get_thread_attributes 和 set_thread_attributes 用于此目的.

警告

将整个属性集安装到核心后, 相应 add_* 方法先前返回的所有迭代器都会失效. 这尤其会影响 作用域属性, 因此用户在切换属性集时必须小心.

全局过滤

全局过滤由过滤器函数对象处理, 可通过 set_filter 方法提供. 有关创建过滤器的更多内容见 本节. 这里只需说明: 过滤器接受一组属性值, 并返回一个布尔值, 表明具有这些属性值的日志记录是否通过过滤. 全局过滤器应用于应用程序中创建的每条日志记录, 因此可用于快速清除多余的日志记录.

全局过滤器可通过 reset_filter 方法移除. 当核心中没有设置过滤器时, 假定不会有记录被过滤掉. 这是日志核心初始构造后的默认状态.

enum severity_level
{
    normal,
    warning,
    error,
    critical
};

void foo()
{
    boost::shared_ptr< logging::core > core = logging::core::get();

    // Set a global filter so that only error messages are logged
    core->set_filter(expr::attr< severity_level >("Severity") >= error);

    // ...
}

核心还提供另一种禁用日志的方式. 通过以布尔实参调用 set_logging_enabled, 可以完全禁用或重新启用日志, 包括应用过滤. 与设置一个总是失败的全局过滤器相比, 用该方法禁用日志对应用程序性能可能更有利.

接收器管理

应用全局过滤之后, 日志接收器开始行动. 为了添加和移除接收器, 核心提供了 add_sink 和 remove_sink 方法. 这两个方法都接受指向接收器的指针. add_sink 会在接收器尚未添加的情况下将其添加到核心中. remove_sink 方法会在先前添加的接收器内部列表中查找提供的接收器, 找到则将其移除. 核心内部处理接收器的顺序是未指定的.

void foo()
{
    boost::shared_ptr< logging::core > core = logging::core::get();

    // Set a sink that will write log records to the console
    boost::shared_ptr< sinks::text_ostream_backend > backend =
        boost::make_shared< sinks::text_ostream_backend >();
    backend->add_stream(
        boost::shared_ptr< std::ostream >(&std::clog, boost::null_deleter()));

    typedef sinks::unlocked_sink< sinks::text_ostream_backend > sink_t;
    boost::shared_ptr< sink_t > sink = boost::make_shared< sink_t >(backend);
    core->add_sink(sink);

    // ...

    // Remove the sink
    core->remove_sink(sink);
}

异常处理

核心提供了建立集中式异常处理的方式. 如果在过滤或某个已添加接收器的处理过程中发生异常, 且已通过 set_exception_handler 方法安装了异常处理器, 核心将调用该处理器. 异常处理器是一个无参函数对象, 在 catch 子句内部被调用. 库提供了 工具 来简化异常处理器的构造.

提示

日志核心中的异常处理器是全局的, 因此旨在对错误执行一些通用操作. 日志接收器和日志源也提供异常处理设施 (参见 此处 和 此处), 可用于更细粒度的错误处理.

struct my_handler
{
    typedef void result_type;

    void operator() (std::runtime_error const& e) const
    {
        std::cout << "std::runtime_error: " << e.what() << std::endl;
    }
    void operator() (std::logic_error const& e) const
    {
        std::cout << "std::logic_error: " << e.what() << std::endl;
        throw;
    }
};

void init_exception_handler()
{
    // Setup a global exception handler that will call my_handler::operator()
    // for the specified exception types
    logging::core::get()->set_exception_handler(logging::make_exception_handler<
        std::runtime_error,
        std::logic_error
    >(my_handler()));
}

馈送日志记录

日志核心最重要的功能之一, 是为所有日志源提供馈送日志记录的入口. 这通过 open_record 和 push_record 方法完成.

第一个方法用于发起记录日志过程. 它接受日志源专属的属性集. 该方法构造三类属性集 (全局、线程专属和日志源专属) 的公共属性值集, 并应用过滤. 如果过滤成功, 即至少有一个接收器接受具有这些属性值的记录, 该方法返回一个非空的 记录对象, 可用于填充日志记录消息. 如果过滤失败, 则返回空的记录对象.

当日志源准备好完成日志过程时, 它必须调用 push_record 方法, 并传入 open_record 方法返回的记录. 注意, 不应以空记录调用 push_record. 记录应作为右值引用传递. 调用期间将从记录构造记录视图. 该视图随后会被传递给在过滤中接受它的接收器. 这可能涉及记录格式化和后续处理, 例如将其存储到文件或通过网络发送. 之后, 记录对象即可销毁.

void logging_function(logging::attribute_set const& attrs)
{
    boost::shared_ptr< logging::core > core = logging::core::get();

    // Attempt to open a log record
    logging::record rec = core->open_record(attrs);
    if (rec)
    {
        // Ok, the record is accepted. Compose the message now.
        logging::record_ostream strm(rec);
        strm << "Hello, World!";
        strm.flush();

        // Deliver the record to the sinks.
        core->push_record(boost::move(rec));
    }
}

所有这些逻辑通常都隐藏在库提供的日志器和宏中. 不过, 这对开发新日志源的人可能有用.
