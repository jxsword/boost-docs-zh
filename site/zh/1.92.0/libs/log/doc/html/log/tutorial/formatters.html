日志记录格式化

如果您尝试运行前面章节的示例, 可能已经注意到只有日志记录消息被写入文件. 这是未设置格式化器时库的默认行为. 即使您向日志核心或日志器添加了属性, 除非指定使用这些值的格式化器, 否则属性值不会到达输出.

回到前面教程章节的一个示例:

void init()
{
    logging::add_file_log
    (
        keywords::file_name = "sample_%N.log",
        keywords::rotation_size = 10 * 1024 * 1024,
        keywords::time_based_rotation = sinks::file::rotation_at_time_point(0, 0, 0),
        keywords::format = "[%TimeStamp%]: %Message%"
    );

    logging::core::get()->set_filter
    (
        logging::trivial::severity >= logging::trivial::info
    );
}

对于 add_file_log 函数, format 参数允许指定日志记录的格式. 如果您更喜欢手动设置接收器, 接收器前端为此提供了 set_formatter 成员函数.

可以用多种方式指定格式, 下文将进一步说明.

Lambda 风格格式化器

您可以用如下 lambda 风格表达式创建格式化器:

void init()
{
    logging::add_file_log
    (
        keywords::file_name = "sample_%N.log",
        // This makes the sink to write log records that look like this:
        // 1: <normal> A normal severity message
        // 2: <error> An error severity message
        keywords::format =
        (
            expr::stream
                << expr::attr< unsigned int >("LineID")
                << ": <" << logging::trivial::severity
                << "> " << expr::smessage
        )
    );
}

查看完整代码.

这里, stream 是用于格式化记录的流的占位符. 其他插入实参, 例如 attr 和 message, 是定义应存储到流中的内容的操纵器. 我们已在过滤表达式中见过 severity 占位符, 这里它用在格式化器中. 这是一个很好的统一: 您可以在过滤器和格式化器中使用相同的占位符. attr 占位符类似于 severity 占位符, 它也表示属性值. 区别在于, severity 占位符表示名称为 "Severity"、类型为 trivial::severity_level 的特定属性, 而 attr 可用于表示任意属性. 除此之外, 两个占位符是等价的. 例如, 可以将 severity 替换为如下写法:

expr::attr< logging::trivial::severity_level >("Severity")
提示

如上一节所示, 可以为用户的属性定义像 severity 这样的占位符. 除了在模板表达式中语法更简单之外, 这类占位符还有一个额外好处: 将关于属性的全部信息 (名称和值类型) 集中在占位符定义中. 这使编码更不容易出错 (您不会拼错属性名称或指定错误的值类型), 因此是定义新属性并在模板表达式中使用它们的推荐方式.

还有其他 格式化器操纵器 为日期、时间和其他类型提供高级支持. 一些操纵器接受自定义其行为的附加实参. 其中大多数实参是命名的, 可以按 Boost.Parameter 风格传递.

换个花样, 我们看看手动初始化接收器时怎么做:

void init()
{
    typedef sinks::synchronous_sink< sinks::text_ostream_backend > text_sink;
    boost::shared_ptr< text_sink > sink = boost::make_shared< text_sink >();

    sink->locked_backend()->add_stream(
        boost::make_shared< std::ofstream >("sample.log"));

    sink->set_formatter
    (
        expr::stream
               // line id will be written in hex, 8-digits, zero-filled
            << std::hex << std::setw(8) << std::setfill('0') << expr::attr< unsigned int >("LineID")
            << ": <" << logging::trivial::severity
            << "> " << expr::smessage
    );

    logging::core::get()->add_sink(sink);
}

查看完整代码.

可以看到, 可以在表达式中绑定改变格式的操纵器; 这些操纵器将在格式化日志记录时影响后续属性值的格式, 就像流一样. 更多操纵器在 功能详解 一节中描述.

Boost.Format 风格格式化器

作为替代, 您可以用类似 Boost.Format 的语法定义格式化器. 与上述相同的格式化器可以写成如下形式:

void init()
{
    typedef sinks::synchronous_sink< sinks::text_ostream_backend > text_sink;
    boost::shared_ptr< text_sink > sink = boost::make_shared< text_sink >();

    sink->locked_backend()->add_stream(
        boost::make_shared< std::ofstream >("sample.log"));

    // This makes the sink to write log records that look like this:
    // 1: <normal> A normal severity message
    // 2: <error> An error severity message
    sink->set_formatter
    (
        expr::format("%1%: <%2%> %3%")
            % expr::attr< unsigned int >("LineID")
            % logging::trivial::severity
            % expr::smessage
    );

    logging::core::get()->add_sink(sink);
}

查看完整代码.

format 占位符接受格式字符串, 其中以位置方式指定所有要格式化的实参. 注意, 目前只支持位置格式. 同样的格式说明可用于 add_file_log 及类似函数.

专用格式化器

库为若干类型 (如日期、时间和命名作用域) 提供了专用格式化器. 这些格式化器对格式化的值提供扩展控制. 例如, 可以用与 Boost.DateTime 兼容的格式字符串描述日期和时间格式:

void init()
{
    logging::add_file_log
    (
        keywords::file_name = "sample_%N.log",
        // This makes the sink to write log records that look like this:
        // YYYY-MM-DD HH:MI:SS: <normal> A normal severity message
        // YYYY-MM-DD HH:MI:SS: <error> An error severity message
        keywords::format =
        (
            expr::stream
                << expr::format_date_time< boost::posix_time::ptime >("TimeStamp", "%Y-%m-%d %H:%M:%S")
                << ": <" << logging::trivial::severity
                << "> " << expr::smessage
        )
    );
}

查看完整代码.

同一格式化器也可以在 Boost.Format 风格格式化器的上下文中使用.

字符串模板作为格式化器

在某些上下文中, 文本模板被接受为格式化器. 此时将调用库初始化支持代码来解析模板并重构相应的格式化器. 使用这种方式时需要牢记一些注意事项, 但这里只需简要描述模板格式即可.

void init()
{
    logging::add_file_log
    (
        keywords::file_name = "sample_%N.log",
        keywords::format = "[%TimeStamp%]: %Message%"
    );
}

查看完整代码.

这里, format 参数接受这样一个格式模板. 模板可以包含若干用百分号 (%) 括起来的占位符. 每个占位符必须包含一个属性值名称, 用于替换该占位符. %Message% 占位符将被替换为日志记录消息.

注释

接收器后端的 set_formatter 方法不接受文本格式模板. 要将文本模板解析为格式化器函数, 必须调用 parse_formatter 函数. 更多细节参见 此处.

自定义格式化函数

可以向支持格式化的接收器后端添加自定义格式化器. 格式化器实际上是支持以下签名的函数对象:

void (logging::record_view const& rec, logging::basic_formatting_ostream< CharT >& strm);

这里 CharT 是目标字符类型. 每当日志记录视图 rec 通过过滤并即将存入日志时, 格式化器就会被调用.

提示

记录视图与记录非常相似. 显著区别在于视图是不可变的, 并实现浅拷贝. 格式化器和接收器只作用于记录视图, 这防止它们在记录仍可能被其他线程中的其他接收器使用时修改记录.

格式化后的记录应通过插入到与标准库兼容的输出流 strm 来组成. 下面是自定义格式化器函数用法的示例:

void my_formatter(logging::record_view const& rec, logging::formatting_ostream& strm)
{
    // Get the LineID attribute value and put it into the stream
    strm << logging::extract< unsigned int >("LineID", rec) << ": ";

    // The same for the severity level.
    // The simplified syntax is possible if attribute keywords are used.
    strm << "<" << rec[logging::trivial::severity] << "> ";

    // Finally, put the record message to the stream
    strm << rec[expr::smessage];
}

void init()
{
    typedef sinks::synchronous_sink< sinks::text_ostream_backend > text_sink;
    boost::shared_ptr< text_sink > sink = boost::make_shared< text_sink >();

    sink->locked_backend()->add_stream(
        boost::make_shared< std::ofstream >("sample.log"));

    sink->set_formatter(&my_formatter);

    logging::core::get()->add_sink(sink);
}
