如 教程 中所指出的, 过滤器和格式化器可以指定为带有属性值占位符的 Lambda 表达式. 本节将描述可用于构建更复杂 Lambda 表达式的占位符.

还有一种以字符串模板形式指定过滤器的方式. 这对于从应用程序设置进行初始化可能有用. 库的这一部分在 此处 描述.

通用属性占位符

自定义回退策略
属性标记与自定义格式化运算符
#include <boost/log/expressions/attr_fwd.hpp>
#include <boost/log/expressions/attr.hpp>

attr 占位符在模板表达式中表示一个属性值. 给定记录视图或属性值集, 该占位符会在被调用时尝试从实参中提取指定的属性值. 这大致可以用以下伪代码描述:

logging::value_ref< T, TagT > val = expr::attr< T, TagT >(name)(rec);

其中 val 是对提取值的 引用, name 和 T 是属性值的 名称 和类型, TagT 是可选的标记 (稍后我们会回到它), 而 rec 是日志 记录视图 或 属性值集. T 可以是 Boost.MPL 类型序列, 包含该值可能的预期类型; 如果值的类型与序列中的某个类型匹配, 提取将成功.

attr 占位符可以用在 Boost.Phoenix 表达式中, 包括 bind 表达式.

bool my_filter(logging::value_ref< severity_level, tag::severity > const& level,
               logging::value_ref< std::string, tag::tag_attr > const& tag)
{
    return level >= warning || tag == "IMPORTANT_MESSAGE";
}

void init()
{
    // ...

    namespace phoenix = boost::phoenix;
    sink->set_filter(phoenix::bind(&my_filter, severity.or_none(), tag_attr.or_none()));

    // ...
}

该占位符既可用于过滤器, 也可用于格式化器:

sink->set_filter
(
    expr::attr< int >("Severity") >= 5 &&
    expr::attr< std::string >("Channel") == "net"
);

sink->set_formatter
(
    expr::stream
        << expr::attr< int >("Severity")
        << " [" << expr::attr< std::string >("Channel") << "] "
        << expr::smessage
);

调用 set_filter 会注册一个由两个基本子过滤器组成的复合过滤器: 第一个检查严重级别, 第二个检查通道名称. 调用 set_formatter 会安装一个格式化器, 它组成一个字符串, 其中包含严重级别、通道名称以及消息文本.

自定义回退策略

默认情况下, 当记录中未找到请求的属性值时, attr 将返回空引用. 对于过滤器, 这会在任何排序表达式中导致 false; 对于格式化器, 占位符的输出将为空. 可以更改此行为:

  • 抛出异常 (missing_value 或 invalid_type, 取决于失败原因). 添加 or_throw 修饰符:
sink->set_filter
(
    expr::attr< int >("Severity").or_throw() >= 5 &&
    expr::attr< std::string >("Channel").or_throw() == "net"
);
  • 改为使用默认值. 添加带有所需默认值的 or_default 修饰符:
sink->set_filter
(
    expr::attr< int >("Severity").or_default(0) >= 5 &&
    expr::attr< std::string >("Channel").or_default(std::string("general")) == "net"
);
提示

您还可以使用 has_attr 谓词来实现以属性值是否存在为条件的过滤器和格式化器.

默认行为也可以通过 or_none 修饰符访问. 修改后的占位符可以像未修改的占位符一样用于过滤器和格式化器.

在 bind 表达式中, 绑定的函数对象仍将以 value_ref 包装的值代替修改后的 attr 占位符. 尽管 or_throw 和 or_default 两种修饰符都保证绑定函数会收到已填充的引用, 但当值类型指定为类型序列时, 仍需要 value_ref. 此外, 引用包装器可能包含标记类型, 这对格式化定制可能有用.

属性标记与自定义格式化运算符

TagT 类型在上文 抽象描述 (针对 attr) 中是可选的, 默认为 void. 这是一个属性标记, 可用于自定义格式化器针对不同属性产生的输出. 当提取的属性值被放入流时, 该标记会被转发给 to_log 操纵器 (该行为由 value_ref 实现保证). 下面是一个简单示例:

// We define our own severity levels
enum severity_level
{
    normal,
    notification,
    warning,
    error,
    critical
};

// The operator is used for regular stream formatting
std::ostream& operator<< (std::ostream& strm, severity_level level)
{
    static const char* strings[] =
    {
        "normal",
        "notification",
        "warning",
        "error",
        "critical"
    };

    if (static_cast< std::size_t >(level) < sizeof(strings) / sizeof(*strings))
        strm << strings[level];
    else
        strm << static_cast< int >(level);

    return strm;
}

// Attribute value tag type
struct severity_tag;

// The operator is used when putting the severity level to log
logging::formatting_ostream& operator<<
(
    logging::formatting_ostream& strm,
    logging::to_log_manip< severity_level, severity_tag > const& manip
)
{
    static const char* strings[] =
    {
        "NORM",
        "NTFY",
        "WARN",
        "ERRR",
        "CRIT"
    };

    severity_level level = manip.get();
    if (static_cast< std::size_t >(level) < sizeof(strings) / sizeof(*strings))
        strm << strings[level];
    else
        strm << static_cast< int >(level);

    return strm;
}

void init()
{
    logging::add_console_log
    (
        std::clog,
        // This makes the sink to write log records that look like this:
        // 1: <NORM> A normal severity message
        // 2: <ERRR> An error severity message
        keywords::format =
        (
            expr::stream
                << expr::attr< unsigned int >("LineID")
                << ": <" << expr::attr< severity_level, severity_tag >("Severity")
                << "> " << expr::smessage
        )
    );
}

查看完整代码.

这里我们为包裹在 to_log_manip 操纵器 (以标记 severity_tag 标注) 中的严重级别指定了一个不同的格式化运算符. 该运算符将在格式化日志记录时被调用, 而常规的 operator<< 将在其他上下文中使用.

定义属性关键字 

#include <boost/log/expressions/keyword_fwd.hpp>
#include <boost/log/expressions/keyword.hpp>

属性关键字可以用作过滤器和格式化器中 attr 占位符的替代, 同时提供更简洁、更不易出错的语法. 属性关键字可以用 BOOST_LOG_ATTRIBUTE_KEYWORD 宏声明:

BOOST_LOG_ATTRIBUTE_KEYWORD(keyword, "Keyword", type)

这里宏声明了关键字 keyword, 对应名为 "Keyword"、值类型为 type 的属性. 此外, 该宏还定义了属性标记类型 keyword (位于 tag 命名空间中). 我们可以将前一个示例改写为:

// We define our own severity levels
enum severity_level
{
    normal,
    notification,
    warning,
    error,
    critical
};

// Define the attribute keywords
BOOST_LOG_ATTRIBUTE_KEYWORD(line_id, "LineID", unsigned int)
BOOST_LOG_ATTRIBUTE_KEYWORD(severity, "Severity", severity_level)

// The operator is used for regular stream formatting
std::ostream& operator<< (std::ostream& strm, severity_level level)
{
    static const char* strings[] =
    {
        "normal",
        "notification",
        "warning",
        "error",
        "critical"
    };

    if (static_cast< std::size_t >(level) < sizeof(strings) / sizeof(*strings))
        strm << strings[level];
    else
        strm << static_cast< int >(level);

    return strm;
}

// The operator is used when putting the severity level to log
logging::formatting_ostream& operator<<
(
    logging::formatting_ostream& strm,
    logging::to_log_manip< severity_level, tag::severity > const& manip
)
{
    static const char* strings[] =
    {
        "NORM",
        "NTFY",
        "WARN",
        "ERRR",
        "CRIT"
    };

    severity_level level = manip.get();
    if (static_cast< std::size_t >(level) < sizeof(strings) / sizeof(*strings))
        strm << strings[level];
    else
        strm << static_cast< int >(level);

    return strm;
}

void init()
{
    logging::add_console_log
    (
        std::clog,
        // This makes the sink to write log records that look like this:
        // 1: <NORM> A normal severity message
        // 2: <ERRR> An error severity message
        keywords::format =
        (
            expr::stream
                << line_id
                << ": <" << severity
                << "> " << expr::smessage
        )
    );
}

属性关键字的行为与 attr 占位符相同, 既可用于过滤器也可用于格式化器. or_throw 和 or_default 修饰符同样受支持.

关键字还可以用于日志记录和属性值集中的属性值查找表达式:

void print_severity(logging::record_view const& rec)
{
    logging::value_ref< severity_level, tag::severity > level = rec[severity];
    std::cout << level << std::endl;
}

记录占位符 

#include <boost/log/expressions/record.hpp>

record 占位符可用于 bind 表达式中, 将整个日志 记录视图 传递给绑定的函数对象.

void my_formatter(logging::formatting_ostream& strm, logging::record_view const& rec)
{
    // ...
}

namespace phoenix = boost::phoenix;
sink->set_formatter(phoenix::bind(&my_formatter, expr::stream, expr::record));
注释

对于过滤器, 该占位符将对应 属性值集 而不是日志记录本身. 这是因为在过滤时记录尚未构造, 过滤器只在属性值集上操作.

消息文本占位符 

#include <boost/log/expressions/message.hpp>

日志记录通常包含一个特殊的 "Message" 属性, 其值为某种字符串类型 (更具体地说, 是一个 std::basic_string 特化). 该属性包含在记录创建时构造的日志消息文本. 该属性只在过滤之后构造, 因此过滤器无法使用它. 有几个关键字可用于访问该属性值:

  • smessage - 属性值预期为 std::string
  • wmessage - 属性值预期为 std::wstring
  • message - 属性值预期为 std::string 或 std::wstring

message 关键字必须在不同的字符串类型之间分派, 因此比其他两个关键字效率略低. 如果应用程序能够保证日志消息的字符类型固定, 建议使用相应的关键字以获得更好的性能.

// Sets up a formatter that will ignore all attributes and only print log record text
sink->set_formatter(expr::stream << expr::message);

属性存在过滤器 
#include <boost/log/expressions/predicates/has_attr.hpp>

过滤器 has_attr 检查具有指定名称 (以及可选的指定类型) 的属性值是否附加在日志记录上. 如果未给过滤器指定类型, 只要找到具有指定名称的任意值, 过滤器就返回 true. 如果以 MPL 兼容的类型序列指定值类型, 只要找到具有指定名称且属于指定类型之一的值, 过滤器就返回 true.

该过滤器通常与 条件格式化器 配合使用, 但也可以用作基于日志记录结构的快速过滤器. 例如, 可以用该过滤器提取统计记录并将其路由到特定接收器.

// Declare attribute keywords
BOOST_LOG_ATTRIBUTE_KEYWORD(stat_stream, "StatisticStream", std::string)
BOOST_LOG_ATTRIBUTE_KEYWORD(change, "Change", int)

// A simple sink backend to accumulate statistic information
class my_stat_accumulator :
    public sinks::basic_sink_backend< sinks::synchronized_feeding >
{
    // A map of accumulated statistic values,
    // ordered by the statistic information stream name
    typedef std::map< std::string, int > stat_info_map;
    stat_info_map m_stat_info;

public:
    // Destructor
    ~my_stat_accumulator()
    {
        // Display the accumulated data
        stat_info_map::const_iterator it = m_stat_info.begin(), end = m_stat_info.end();
        for (; it != end; ++it)
        {
            std::cout << "Statistic stream: " << it->first
                << ", accumulated value: " << it->second << "\n";
        }
        std::cout.flush();
    }

    // The method is called for every log record being put into the sink backend
    void consume(logging::record_view const& rec)
    {
        // First, acquire statistic information stream name
        logging::value_ref< std::string, tag::stat_stream > name = rec[stat_stream];
        if (name)
        {
            // Next, get the statistic value change
            logging::value_ref< int, tag::change > change_amount = rec[change];
            if (change_amount)
            {
                // Accumulate the statistic data
                m_stat_info[name.get()] += change_amount.get();
            }
        }
    }
};

// The function registers two sinks - one for statistic information,
// and another one for other records
void init()
{
    boost::shared_ptr< logging::core > core = logging::core::get();

    // Create a backend and attach a stream to it
    boost::shared_ptr< sinks::text_ostream_backend > backend =
        boost::make_shared< sinks::text_ostream_backend >();
    backend->add_stream(
        boost::shared_ptr< std::ostream >(new std::ofstream("test.log")));

    // Create a frontend and setup filtering
    typedef sinks::synchronous_sink< sinks::text_ostream_backend > log_sink_type;
    boost::shared_ptr< log_sink_type > log_sink(new log_sink_type(backend));
    // All records that don't have a "StatisticStream" attribute attached
    // will go to the "test.log" file
    log_sink->set_filter(!expr::has_attr(stat_stream));

    core->add_sink(log_sink);

    // Create another sink that will receive all statistic data
    typedef sinks::synchronous_sink< my_stat_accumulator > stat_sink_type;
    boost::shared_ptr< stat_sink_type > stat_sink(new stat_sink_type());
    // All records with a "StatisticStream" string attribute attached
    // will go to the my_stat_accumulator sink
    stat_sink->set_filter(expr::has_attr(stat_stream));

    core->add_sink(stat_sink);
}

// This simple macro will simplify putting statistic data into a logger
#define PUT_STAT(lg, stat_stream_name, change)\
    if (true) {\
        BOOST_LOG_SCOPED_LOGGER_TAG(lg, "StatisticStream", stat_stream_name);\
        BOOST_LOG(lg) << logging::add_value("Change", (int)(change));\
    } else ((void)0)

void logging_function()
{
    src::logger lg;

    // Put a regular log record, it will go to the "test.log" file
    BOOST_LOG(lg) << "A regular log record";

    // Put some statistic data
    PUT_STAT(lg, "StreamOne", 10);
    PUT_STAT(lg, "StreamTwo", 20);
    PUT_STAT(lg, "StreamOne", -5);
}

查看完整代码.

在此示例中, 用 PUT_STAT 宏发出的日志记录将被定向到 my_stat_accumulator 接收器后端, 该后端会累积 "Change" 属性值中传递的变更. 所有其他记录 (即使是通过同一日志器产生的) 都会被传递给 filter 接收器. 这是通过为两个接收器设置互斥的过滤器实现的.

请注意, 在上例中我们从两个方面扩展了库: 定义了新的接收器后端 my_stat_accumulator 和新的宏 PUT_STAT. 另请注意, has_attr 可以接受属性关键字来标识要检查的属性.

范围检查过滤器 
#include <boost/log/expressions/predicates/is_in_range.hpp>

is_in_range 谓词检查属性值是否落在半开区间内 (即它返回 true 的条件是: 属性值 x 满足 left <= x < right). 例如:

sink->set_filter
(
    // drops all records that have level below 3 or greater than 4
    expr::is_in_range(expr::attr< int >("Severity"), 3, 5)
);

该属性也可以用属性关键字或名称与类型来标识:

sink->set_filter
(
    expr::is_in_range(severity, 3, 5)
);

sink->set_filter
(
    expr::is_in_range< int >("Severity", 3, 5)
);
简单字符串匹配过滤器 
#include <boost/log/expressions/predicates/begins_with.hpp>
#include <boost/log/expressions/predicates/ends_with.hpp>
#include <boost/log/expressions/predicates/contains.hpp>

谓词 begins_with、ends_with 和 contains 提供了匹配字符串属性值的简单方式. 顾名思义, 这些函数构造的过滤器分别在属性值以指定子字符串开头、结尾或包含该子字符串时返回 true. 字符串比较区分大小写.

sink->set_filter
(
    // selects only records that are related to Russian web domains
    expr::ends_with(expr::attr< std::string >("Domain"), ".ru")
);

该属性也可以用属性关键字或名称与类型来标识.

高级字符串匹配过滤器 
#include <boost/log/expressions/predicates/matches.hpp>

// Supporting headers
#include <boost/log/support/regex.hpp>
#include <boost/log/support/std_regex.hpp>
#include <boost/log/support/xpressive.hpp>
#include <boost/log/support/spirit_qi.hpp>
#include <boost/log/support/spirit_classic.hpp>

matches 函数创建一个将正则表达式或解析器应用于字符串属性值的过滤器. 正则表达式可由 Boost.Regex 或 Boost.Xpressive 提供. 也支持 Boost.Spirit 和 Boost.Spirit2 的解析器. 如果正则表达式匹配或解析器成功解析属性值, 过滤器返回 true.

注释

要使用该谓词, 还应包含相应的支持头文件.

sink->set_filter
(
    expr::matches(expr::attr< std::string >("Domain"), boost::regex("www\\..*\\.ru"))
);

该属性也可以用属性关键字或名称与类型来标识.

按通道的严重级别阈值过滤器 
#include <boost/log/expressions/predicates/channel_severity_filter.hpp>

该过滤器针对一个特定但常见的用例. channel_severity_filter 函数创建一个将日志记录严重级别与阈值进行比较的谓词. 该谓词允许为不同通道设置不同的阈值. 通道名称与严重级别阈值之间的映射可以按 std::map 风格填充: 使用下标运算符, 或在过滤器本身上调用 add 方法 (即 channel_severity_filter_actor 实例). 我们来看一个示例:

// We define our own severity levels
enum severity_level
{
    normal,
    notification,
    warning,
    error,
    critical
};

// Define the attribute keywords
BOOST_LOG_ATTRIBUTE_KEYWORD(line_id, "LineID", unsigned int)
BOOST_LOG_ATTRIBUTE_KEYWORD(severity, "Severity", severity_level)
BOOST_LOG_ATTRIBUTE_KEYWORD(channel, "Channel", std::string)


void init()
{
    // Create a minimal severity table filter
    typedef expr::channel_severity_filter_actor< std::string, severity_level > min_severity_filter;
    min_severity_filter min_severity = expr::channel_severity_filter(channel, severity);

    // Set up the minimum severity levels for different channels
    min_severity["general"] = notification;
    min_severity["network"] = warning;
    min_severity["gui"] = error;

    logging::add_console_log
    (
        std::clog,
        keywords::filter = min_severity || severity >= critical,
        keywords::format =
        (
            expr::stream
                << line_id
                << ": <" << severity
                << "> [" << channel << "] "
                << expr::smessage
        )
    );
}

// Define our logger type
typedef src::severity_channel_logger< severity_level, std::string > logger_type;

void test_logging(logger_type& lg, std::string const& channel_name)
{
    BOOST_LOG_CHANNEL_SEV(lg, channel_name, normal) << "A normal severity level message";
    BOOST_LOG_CHANNEL_SEV(lg, channel_name, notification) << "A notification severity level message";
    BOOST_LOG_CHANNEL_SEV(lg, channel_name, warning) << "A warning severity level message";
    BOOST_LOG_CHANNEL_SEV(lg, channel_name, error) << "An error severity level message";
    BOOST_LOG_CHANNEL_SEV(lg, channel_name, critical) << "A critical severity level message";
}

查看完整代码.

控制台接收器的过滤器由 channel_severity_filter_actor 过滤器和一个通用严重级别检查组成. 当日志记录没有通道属性, 或通道名称不在 channel_severity_filter_actor 初始化时指定的那些之中时, 将使用该通用检查. 需要说明的是, 可以设置阈值过滤器在这种情况下的默认结果; 默认结果可通过 set_default 方法设置. channel_severity_filter_actor 过滤器被配置为限制通道 "general"、"network" 和 "gui" 的记录严重级别 —— 这些通道中级别低于指定阈值的所有记录都不会通过过滤器, 将被忽略.

阈值过滤器实现为对通道的 std::map 等价物, 这意味着通道值类型必须支持偏序. 显然, 严重级别类型也必须支持排序, 才能与阈值进行比较. 默认情况下, 该谓词将使用 std::less 等价物对通道名称排序, 并使用 std::greater_equal 等价物比较严重级别. 可以自定义排序谓词. 有关模板参数, 请查阅 channel_severity_filter_actor 类和 channel_severity_filter 生成器的参考.

调试器存在过滤器 
#include <boost/log/expressions/predicates/is_debugger_present.hpp>

该过滤器仅为 Windows 实现. 如果应用程序在调试器下运行, is_debugger_present 过滤器返回 true, 否则返回 false. 它不使用日志记录中的任何属性值. 该谓词通常与 调试器输出 接收器一起使用.

// Complete sink type
typedef sinks::synchronous_sink< sinks::debug_output_backend > sink_t;

void init_logging()
{
    boost::shared_ptr< logging::core > core = logging::core::get();

    // Create the sink. The backend requires synchronization in the frontend.
    boost::shared_ptr< sink_t > sink(new sink_t());

    // Set the special filter to the frontend
    // in order to skip the sink when no debugger is available
    sink->set_filter(expr::is_debugger_present());

    core->add_sink(sink);
}

在过滤表达式中注入用户自定义函数 
#include <boost/log/expressions/predicates/wrap_filter.hpp>

用户可能希望将自定义过滤函数对象与 Boost.Log 提供的过滤器组合起来. 为了能够将用户自定义函数集成到过滤表达式中, 必须将该函数适配为 Boost.Phoenix 函数对象. 一种方法是使用 BOOST_PHOENIX_ADAPT_* 宏之一 (由 Boost.Phoenix 提供), 为用户的过滤函数创建惰性函数. 例如:

// Define the attribute keywords
BOOST_LOG_ATTRIBUTE_KEYWORD(severity, "Severity", severity_level)
BOOST_LOG_ATTRIBUTE_KEYWORD(channel, "Channel", std::string)

// User-defined filter function
bool my_filter(logging::attribute_value_set const& values)
{
    // Filter implementation. Returns true if the log record passed the filter and false otherwise.
    return values[channel] == "network";
}

namespace lazy {
BOOST_PHOENIX_ADAPT_FUNCTION(bool, my_filter, ::my_filter, 1)
}

void init()
{
    logging::add_console_log
    (
        std::clog,
        keywords::filter =
            severity >= critical || lazy::my_filter(boost::phoenix::placeholders::_1),
        keywords::format =
            expr::stream << "<" << severity << "> [" << channel << "] " << expr::smessage
    );
}

查看完整代码.

这里, 使用 BOOST_PHOENIX_ADAPT_FUNCTION 宏, 我们创建了一个 lazy::my_filter 工厂函数, 调用它时会创建一个与 Boost.Phoenix 模板表达式兼容的函数对象. 该函数对象成为过滤表达式的一部分, 在日志记录过滤期间被调用时, 会将调用转发给用户定义的被包装的 my_filter 函数. 过滤表达式中的 _1 占位符指定将被转发给 my_filter 函数的属性值集. 该函数必须返回 true 以表明日志记录通过了过滤器, 否则返回 false.

提示

也可以使用 boost::phoenix::bind 代替 BOOST_PHOENIX_ADAPT_* 宏. boost::phoenix::bind 同样会创建一个可与 Boost.Phoenix 表达式集成的函数对象:

logging::add_console_log
(
    std::clog,
    keywords::filter =
        severity >= critical || boost::phoenix::bind(&my_filter, boost::phoenix::placeholders::_1),
    keywords::format =
        expr::stream << "<" << severity << "> [" << channel << "] " << expr::smessage
);

不过, Boost.Log 提供了专门的 wrap_filter 实用工具, 无需创建工厂函数或指定参数占位符. 该函数包装用户自定义函数对象, 使其能够参与过滤表达式. 上面的示例可以简化如下:

// Define the attribute keywords
BOOST_LOG_ATTRIBUTE_KEYWORD(severity, "Severity", severity_level)
BOOST_LOG_ATTRIBUTE_KEYWORD(channel, "Channel", std::string)

// User-defined filter function
bool my_filter(logging::attribute_value_set const& values)
{
    // Filter implementation. Returns true if the log record passed the filter and false otherwise.
    return values[channel] == "network";
}

void init()
{
    logging::add_console_log
    (
        std::clog,
        keywords::filter =
            severity >= critical || expr::wrap_filter(&my_filter),
        keywords::format =
            expr::stream << "<" << severity << "> [" << channel << "] " << expr::smessage
    );
}

查看完整代码.

注意, wrap_filter 允许包装任意函数对象, 包括 C++11 lambda 函数, 只要被包装的函数对象可以用单个 attribute_value_set 类型的参数调用, 并返回可转换为 bool 的值.

如 教程 中所述, 库提供了几种表达格式化器的方式, 最著名的是流式语法和 Boost.Format 风格表达式. 选择哪种格式由相应的锚定表达式决定. 要使用流式语法, 应以 stream 关键字开始格式化器定义, 如下所示:

#include <boost/log/expressions/formatters/stream.hpp>

sink->set_formatter(expr::stream << expr1 << expr2 << ... << exprN);

这里, 表达式 expr1 到 exprN 可以是本节描述的操纵器, 也可以是其他产生支持放入标准库输出流的对象的表达式.

要使用 Boost.Format 风格语法, 应使用 format 构造:

#include <boost/log/expressions/formatters/format.hpp>

sink->set_formatter(expr::format("format string") % expr1 % expr2 % ... % exprN);

传递给 format 关键字的格式字符串应包含相应表达式的位置占位符. 对于宽字符日志, 格式字符串应为宽字符. 表达式 expr1 到 exprN 的含义与流式变体相同. 不过需要注意, 使用流式语法通常会产生比用 format 关键字构造的格式化器更快的格式化器.

表达格式化器的另一种有用方式是使用字符串模板. 库的这一部分在 本节 中描述, 主要用于支持从应用程序设置进行初始化.

命名作用域格式化器 
#include <boost/log/expressions/formatters/named_scope.hpp>

格式化器 format_named_scope 旨在为 命名作用域 属性值提供灵活的格式化支持. 基本用法非常直接, 其结果类似于 attr 所提供的:

// Puts the scope stack from outer ones towards inner ones: outer scope -> inner scope
sink->set_formatter(expr::stream << expr::format_named_scope("Scopes", "%n"));

第一个参数命名属性, 第二个是格式字符串. 该字符串可以包含以下占位符:

表 1.5. 命名作用域格式占位符

占位符

含义

示例

%n

作用域名称

"void bar::foo()"

%c

函数名, 若作用域用 BOOST_LOG_FUNCTION 标记; 否则为完整作用域名称. 参见下文说明.

"bar::foo"

%C

不带函数作用域的函数名, 若作用域用 BOOST_LOG_FUNCTION 标记; 否则为完整作用域名称. 参见下文说明.

"foo"

作用域的源文件名

"/home/user/project/foo.cpp"

%F

作用域的源文件名, 不含路径

"foo.cpp"

%l

源文件中的行号

"45"


注释

如 命名作用域 属性描述所述, 可以使用 BOOST_LOG_FUNCTION 宏从外围函数名自动生成作用域名称. 遗憾的是, 生成字符串的实际格式取决于编译器, 且在许多情况下包含函数的完整签名. 当指定 "%c" 或 "%C" 格式标志时, 库会尝试解析生成的字符串以提取函数名. 由于 C++ 语法高度依赖上下文且非常复杂, 不可能在所有情况下都正确解析函数签名, 因此库基本上是在猜测. 取决于字符串格式, 这可能失败或产生不正确的结果. 特别是, 类型转换运算符可能给解析器带来问题. 如果解析器无法识别函数签名, 库会退回使用整个字符串 (即行为等同于 "%n" 标志). 为缓解此问题, 用户可以将有问题的 BOOST_LOG_FUNCTION 用法替换为 BOOST_LOG_NAMED_SCOPE 宏, 并显式写出所需的作用域名称. 用 BOOST_LOG_NAMED_SCOPE 标记的作用域名称不会被库解释, 将原样输出. 总的来说, 出于可移植性和运行期性能的考虑, 最好始终使用 BOOST_LOG_NAMED_SCOPE 和 "%n" 格式标志.

格式字符串描述列表中每个命名作用域的呈现方式, 而以下命名参数允许自定义列表的遍历和格式化:

  • format. 命名作用域格式字符串, 如上所述. 当使用其他命名参数时, 此参数用于指定格式.
  • iteration. 该参数描述遍历作用域的方向. 可以取值 forward (默认) 或 reverse.
  • delimiter. 该参数可用于指定作用域之间的分隔符. 默认分隔符取决于 iteration 参数. 若为 iteration == forward, 默认 delimiter 为 "->", 否则为 "<-".
  • depth. 该参数可用于限制写入日志的作用域数量. 格式化器将打印最内层的 depth 个作用域, 如果还有剩余作用域, 则在写出的序列后附加省略号. 默认情况下, 格式化器会写出所有作用域名称.
  • incomplete_marker. 该参数可用于指定用于表示列表已被 depth 参数限制的字符串. 默认使用 "..." 字符串作为标记.
  • empty_marker. 该参数可用于指定在作用域列表为空时输出的字符串. 默认情况下, 此时不输出任何内容.

下面是几个用法示例:

// Puts the scope stack in reverse order:
// inner scope (file:line) <- outer scope (file:line)
sink->set_formatter
(
    expr::stream
        << expr::format_named_scope(
            "Scopes",
            keywords::format = "%n (%f:%l)",
            keywords::iteration = expr::reverse)
);

// Puts the scope stack in reverse order with a custom delimiter:
// inner scope | outer scope
sink->set_formatter
(
    expr::stream
        << expr::format_named_scope(
            "Scopes",
            keywords::format = "%n",
            keywords::iteration = expr::reverse,
            keywords::delimiter = " | ")
);

// Puts the scope stack in forward order, no more than 2 inner scopes:
// ... outer scope -> inner scope
sink->set_formatter
(
    expr::stream
        << expr::format_named_scope(
            "Scopes",
            keywords::format = "%n",
            keywords::iteration = expr::forward,
            keywords::depth = 2)
);

// Puts the scope stack in reverse order, no more than 2 inner scopes:
// inner scope <- outer scope <<and more>>...
sink->set_formatter
(
    expr::stream
        << expr::format_named_scope(
            "Scopes",
            keywords::format = "%n",
            keywords::iteration = expr::reverse,
            keywords::incomplete_marker = " <<and more>>..."
            keywords::depth = 2)
);
提示

可以指定空字符串作为 incomplete_marker 参数, 此时将不会指示列表被截断.

条件格式化器 
#include <boost/log/expressions/formatters/if.hpp>

有些情况下, 用户希望对日志记录检查某个条件, 并根据该条件进行格式化. 这种需求的一个例子是根据运行期类型格式化属性值. 条件格式化器的一般语法如下:

expr::if_ (filter)
[
    true_formatter
]
.else_
[
    false_formatter
]

熟悉 Boost.Phoenix lambda 表达式的用户会觉得这种语法很眼熟. filter 参数是一个过滤器, 应用于正在格式化的记录. 如果它返回 true, 则执行 true_formatter, 否则执行 false_formatter. else_ 部分 (带 false_formatter) 是可选的. 如果省略该部分且 filter 结果为 false, 则不执行任何格式化器. 下面是一个示例:

sink->set_formatter
(
    expr::stream
        // First, put the current time
        << expr::format_date_time("TimeStamp", "%Y-%m-%d %H:%M:%S.%f") << " "
        << expr::if_ (expr::has_attr< int >("ID"))
           [
               // if "ID" is present then put it to the record
               expr::stream << expr::attr< int >("ID")
           ]
           .else_
           [
               // otherwise put a missing marker
               expr::stream << "--"
           ]
        // and after that goes the log record text
        << " " << expr::message
);
自动插入换行符 
#include <boost/log/expressions/formatters/auto_newline.hpp>

这是 auto_newline 操纵器 在格式化表达式中的适配版本. auto_newline 格式化器可能很有用, 例如, 当一个日志源生成的日志消息以换行符结尾 (且该行为不易更改), 而其他消息不是如此时. 该格式化器会确保所有消息都可靠地以换行符结尾, 且不会出现重复的换行符. 与操纵器一样, 除非插入到流中的最后一个字符就是换行符, 否则它会插入一个换行符. 例如:

sink->set_formatter
(
    expr::stream
        // Ensure that the sink outputs one message per line,
        // regardless whether the message itself ends with a newline or not
        << expr::message << expr::auto_newline
);
字符装饰器

有时用户希望在将组合好的字符串传递给接收器后端之前对其进行额外的后处理. 例如, 为了将日志存储到 XML 文件中, 应检查格式化后的日志记录中是否含有在 XML 文档中具有特殊含义的字符. 这正是装饰器的用武之地.

注释

与大多数其他格式化器不同, 装饰器依赖于格式化输出的字符类型, 且该类型无法从被装饰的格式化器推导出来. 默认情况下, 假定字符类型为 char. 如果格式化器用于组合宽字符串, 请在装饰器名前加上 w 字母 (例如使用 wxml_decor 代替 xml_decor). 此外, 每个装饰器都有一个生成器函数, 该函数接受字符类型作为模板参数; 该函数的命名与装饰器类似, 但带有 make_ 前缀 (例如 make_xml_decor).

XML 字符装饰器 
#include <boost/log/expressions/formatters/xml_decorator.hpp>

该装饰器将 XML 特殊字符 (&、<、>、" 和 ') 替换为对应的标记 (分别为 &amp;、&lt;、&gt;、&quot; 和 &apos;). 用法如下:

xml_sink->set_formatter
(
    // Apply the decoration to the whole formatted record
    expr::stream << expr::xml_decor
    [
        expr::stream << expr::message
    ]
);

由于字符装饰器是另一种格式化器, 在其他适合使用格式化器的上下文中使用它们也没有问题. 例如, 这也是一个有效示例:

xml_sink->set_formatter
(
    expr::format("<message>%1%: %2%</message>")
        % expr::attr< unsigned int >("LineID")
        % expr::xml_decor[ expr::stream << expr::message ]; // Only decorate the message text
);

有一个将库设置为记录日志到 XML 文件的示例, 参见 此处.

CSV 字符装饰器 
#include <boost/log/expressions/formatters/csv_decorator.hpp>

该装饰器用于确保结果字符串符合 CSV 格式要求. 特别地, 它会将格式化字符串中的引号字符加倍.

csv_sink->set_formatter
(
    expr::stream
        << expr::attr< unsigned int >("LineID") << ","
        << expr::csv_decor[ expr::stream << expr::attr< std::string >("Tag") ] << ","
        << expr::csv_decor[ expr::stream << expr::message ]
);
C 风格字符装饰器 
#include <boost/log/expressions/formatters/c_decorator.hpp>

该头文件定义了两个字符装饰器: c_decor 和 c_ascii_decor. 第一个将以下字符替换为其转义形式: \ (反斜杠, 0x5c)、\a (响铃字符, 0x07)、\b (退格, 0x08)、\f (换页, 0x0c)、\n (换行, 0x0a)、\r (回车, 0x0d)、\t (水平制表, 0x09)、\v (垂直制表, 0x0b)、' (单引号, 0x27)、" (双引号, 0x22)、? (问号, 0x3f). c_ascii_decor 装饰器做同样的事, 但还会将所有其他不可打印和非 ASCII 字符替换为 C 表示法的转义十六进制字符码 (例如 "\x8c"). 用法与其他字符装饰器类似:

sink->set_formatter
(
    expr::stream
        << expr::attr< unsigned int >("LineID") << ": ["
        << expr::c_decor[ expr::stream << expr::attr< std::string >("Tag") ] << "] "
        << expr::c_ascii_decor[ expr::stream << expr::message ]
);
通用字符装饰器 
#include <boost/log/expressions/formatters/char_decorator.hpp>

该装饰器允许用户以两种形式之一定义自己的字符替换映射. 第一种形式是一个由字符串组成的 std::pair 范围 (可以是 C 风格字符串或字符范围, 包括 std::string). 对偶的 first 元素中的字符串将被替换为对应对偶的 second 元素.

std::array< std::pair< const char*, const char* >, 3 > shell_escapes =
{
    { "\"", "\\\"" },
    { "'",  "\\'" },
    { "$",  "\\$" }
};

sink->set_formatter
(
    expr::stream << expr::char_decor(shell_escapes)
    [
        expr::stream << expr::message
    ]
);

第二种形式是两个等长的字符串序列; 第一个包含查找模式, 第二个包含对应的替换内容.

std::array< const char*, 3 > shell_patterns =
{
    "\"", "'", "$"
};
std::array< const char*, 3 > shell_replacements =
{
    "\\\"", "\\'", "\\$"
};

sink->set_formatter
(
    expr::stream << expr::char_decor(shell_patterns, shell_replacements)
    [
        expr::stream << expr::message
    ]
);

在这两种情况下, 模式都不会被解释, 而是按原始形式在格式化后的字符中查找.

字符串长度限制装饰器 
#include <boost/log/expressions/formatters/max_size_decorator.hpp>

有时, 能够限制格式化器输出或其一部分的大小会很有用. 例如, 该限制可能由接收器或所需的输出格式施加. max_size_decor 装饰器允许实施这种限制. 我们来看一个简单示例:

sink->set_formatter
(
    expr::stream << expr::max_size_decor< char >(20)
    [
        expr::stream << expr::message
    ]
);
注释

max_size_decor 的显式模板参数指定格式化器使用的字符类型. 在本示例中, 格式化器产生的字符串包含 char 类型的字符, 因此需要该模板参数.

在此示例中, 装饰器将日志消息限制为不超过 20 个 编码单元 (类型为 char), 并从输出中移除其余部分. 因此, 如果我们有这样一条日志记录:

BOOST_LOG(lg) << "The quick brown fox jumps over the lazy dog";

产生的输出将如下所示:

The quick brown fox

但是, 在日志文件中查看该输出时, 无法确定原始输出是否还包含其他内容. 用户可能希望指示消息被截断这一事实 (如果发生了截断). 为此, 装饰器允许指定一个溢出标记, 在发生截断时, 该标记将被放在截断输出的末尾. 我们可以像这样修改上面的示例:

sink->set_formatter
(
    expr::stream << expr::max_size_decor(20, ">>>")
    [
        expr::stream << expr::message
    ]
);
提示

格式化器的字符类型从溢出标记的字符类型推导而来, 因此可以省略.

现在我们的日志记录在输出中将如下所示:

The quick brown f>>>

这样的输出更清楚地表明原始消息还有更多内容. 另请注意, 输出长度仍为 20 个字符; 标记替换了截断输出的最后几个字符.

提示

为了使字符截断和标记定位在多字节编码中正确工作, 格式化器所使用的 locale 必须正确设置, 这一点很重要. 特别是, locale 中的 std::codecvt facet 必须能正确识别对应输出中单个字符的多字节序列. 可以使用 Boost.Locale 生成 locale, 然后通过调用 imbue 将其安装到接收器前端 (参见 basic_formatting_sink_frontend 参考). 如果输出字符类型为 wchar_t、char16_t 或 char32_t, 库将假定输出按 UTF-16 或 UTF-32 编码 (取决于字符类型的大小). 由于截断可能发生在多单元字符的中间, 装饰器产生的截断输出有时会比指定的限制略短.

与任何其他格式化器一样, max_size_decor 可以参与更复杂的格式化表达式, 只限制消息的一部分长度.

sink->set_formatter
(
    expr::stream
        << expr::format_date_time("TimeStamp", "%Y-%m-%d %H:%M:%S.%f") << " ["
        << expr::max_size_decor(20, ">>>")
           [
               expr::stream << expr::message
           ]
        << "]"
);

上面的格式化器可以产生如下输出:

2016-08-10 00:36:44.028473 [The quick brown f>>>]
在格式化表达式中注入用户自定义函数 
#include <boost/log/expressions/formatters/wrap_formatter.hpp>

鉴于格式化表达式是 Boost.Phoenix 表达式, 可以使用 Boost.Phoenix 的设施 (例如 BOOST_PHOENIX_ADAPT_* 宏或 boost::phoenix::bind) 将用户自定义函数注入格式化器.

// Define the attribute keywords
BOOST_LOG_ATTRIBUTE_KEYWORD(severity, "Severity", severity_level)
BOOST_LOG_ATTRIBUTE_KEYWORD(channel, "Channel", std::string)

// User-defined formatting function
std::string extract_channel(logging::record_view const& rec)
{
    logging::value_ref< std::string, tag::channel > chan = rec[channel];
    if (chan)
        return chan.get();
    else
        return "-";
}

namespace lazy {
BOOST_PHOENIX_ADAPT_FUNCTION(std::string, extract_channel, ::extract_channel, 1)
}

void init()
{
    logging::add_console_log
    (
        std::clog,
        keywords::format =
            expr::stream << "<" << severity << "> ["
                << lazy::extract_channel(boost::phoenix::placeholders::_1)
                << "] " << expr::smessage
    );
}

查看完整代码.

这里, 使用 BOOST_PHOENIX_ADAPT_FUNCTION 宏, 我们创建了一个 lazy::extract_channel 工厂函数, 调用它时会创建一个与 Boost.Phoenix 模板表达式兼容的函数对象. 该函数对象作为格式化器的一部分被调用时, 会将调用转发给我们的 extract_channel 函数来完成实际工作.

请记住, 格式化器具有如下签名:

void (logging::record_view const& rec, logging::basic_formatting_ostream< CharT >& stream) const

这里, rec 是包含所有捕获属性值的日志 记录视图, stream 是接收格式化输出的输出流. 为了将日志记录传递给 extract_channel 函数, 我们使用 _1 占位符来标识格式化器的第一个参数.

extract_channel 函数接受日志记录视图, 并返回将在格式化表达式中输出到流的对象. 在本例中, 返回的字符串只是日志记录中 "Channel" 属性的值 (如果存在), 否则是替换字符串. 如有需要, 输出流会在接收 extract_channel 返回的字符串时执行字符编码转换.

提示

为了使用 boost::phoenix::bind 代替 BOOST_PHOENIX_ADAPT_* 宏, 可以将格式化表达式写为如下形式:

logging::add_console_log
(
    std::clog,
    keywords::format =
        expr::stream << "<" << severity << "> ["
            << boost::phoenix::bind(&extract_channel, boost::phoenix::placeholders::_1)
            << "] " << expr::smessage
);

在格式化流中返回待输出对象的协议虽然简单且富有表现力, 但当需要更复杂的格式化逻辑时, 可能过于受限或低效. 为了应对这些高级用例, Boost.Log 提供了 wrap_formatter 实用工具, 它包装用户自定义格式化函数, 并在格式化过程中调用它. 用户自定义格式化器可以是支持上述签名的任意可调用对象, 因此无需返回任何内容, 可以直接使用提供的流进行输出.

// Define a custom attribute value type
struct host_address
{
    std::string hostname;
    std::uint_least16_t port = 0;
};

// Define the attribute keywords
BOOST_LOG_ATTRIBUTE_KEYWORD(severity, "Severity", severity_level)
BOOST_LOG_ATTRIBUTE_KEYWORD(host, "Host", host_address)

// User-defined formatter for the Host attribute values
void format_host(logging::record_view const& rec, logging::formatting_ostream& stream)
{
    // Formatter implementation outputs directly into the formatting stream
    logging::value_ref< host_address, tag::host > host_ref = rec[host];
    if (host_ref)
    {
        stream << host_ref->hostname;

        if (host_ref->port != 0)
            stream << ":" << host_ref->port;
    }
    else
    {
        stream << "-";
    }
}

void init()
{
    logging::add_console_log
    (
        std::clog,
        keywords::format =
            expr::stream << "<" << severity << "> ["
                << expr::wrap_formatter< char >(&format_host)
                << "] " << expr::smessage
    );
}

查看完整代码.

在此示例中, 应用程序使用 "Host" 属性, 其值为自定义的 host_address 类型, 用于标识应用程序连接的网络主机. 应用程序可能发出与给定主机相关或无关的日志记录, 这由 "Host" 属性的存在与否指示. 我们定义 format_host 函数来实现主机地址的完整格式化逻辑, 然后使用 wrap_formatter 实用工具将其注入格式化表达式. 注意, 尽管格式化表达式的语法暗示 wrap_formatter 返回的值会被输出到格式化流, 但实际并非如此.
