编写自己的属性 

#include <boost/log/attributes/attribute.hpp>
#include <boost/log/attributes/attribute_value.hpp>
#include <boost/log/attributes/attribute_value_impl.hpp>

开发自己的属性相当简单. 一般而言, 需要执行以下步骤:

  1. 定义属性值是什么. 它很可能是一段希望参与过滤和格式化的常量数据. 将这些数据封装到一个派生自 impl 接口的类中; 这就是属性值实现类. 该对象必须实现 dispatch 方法, 将存储的数据 (即存储的值) 提取到类型分派器. 在大多数情况下, 可以使用库提供的 attribute_value_impl 类.
  2. 使用 attribute_value 类作为接口类, 持有对属性值实现的引用.
  3. 定义属性值将如何产生. 在极端情况下, 值不需要产生 (例如库提供的 constant 属性), 但通常需要调用某些逻辑来获取属性值. 该逻辑必须集中在一个派生自 impl 接口的类中, 更准确地说是在 get_value 方法中. 这个类就是属性实现类. 可以把它看作属性值工厂.
  4. 定义派生自 attribute 的属性接口类. 按惯例, 接口类应在构造时创建相应的实现, 并将指向实现的指针传递给 attribute 类构造函数. 接口类可以拥有接口方法, 但通常不应包含任何数据成员, 因为属性加入库后数据会丢失. 所有相关数据应放在实现类中.

设计属性时, 应力求使其尽可能独立于它产生的值. 属性可能被不同线程并发调用以产生值. 一旦产生, 属性值可能被库使用多次 (甚至可能并发使用), 其生存期可能长于创建它的属性对象, 且同一属性产生的多个属性值可以同时存在.

从库的角度看, 每个属性值都被视为独立于其他属性值或属性本身. 尽管如此, 仍然可以实现既是属性又是属性值的类, 从而在某些情况下优化性能. 这只有在满足以下要求时才可能:

  • 属性值从不变化, 因此可以将其存储在属性自身中. constant 属性就是一个例子.
  • 属性将其值存储在全局 (相对于属性而言是外部的) 存储中, 可从任何属性值访问. 但属性值必须保证其存储的值不随时间变化, 并且可以安全地从不同线程并发访问.

作为第二点的特例, 可以将属性值 (或其部分) 存储在线程专属存储中. 不过, 在这种情况下, 用户必须正确实现属性值实现的 detach_from_thread 方法. 该方法的结果 —— 另一个属性值 —— 必须独立于调用它的线程, 但其存储的值应与原始属性值等价. 当属性值传递到与创建它的线程不同的线程时, 库会调用该方法. 目前, 这只会发生在 异步日志接收器 的情况下.

但在绝大多数情况下, 属性值必须是自包含对象, 不依赖其他实体. 实际上, 这种情况非常常见, 以至于库提供了开箱即用的属性值实现类模板 attribute_value_impl 和 make_attribute_value 生成器函数. 类模板必须以存储值类型实例化, 并且存储值必须提供给类构造函数. 例如, 我们实现一个返回系统运行秒数的属性. 这就是属性实现类:

// The function returns the system uptime, in seconds
unsigned int get_uptime();

// Attribute implementation class
class system_uptime_impl :
    public logging::attribute::impl
{
public:
    // The method generates a new attribute value
    logging::attribute_value get_value()
    {
        return attrs::make_attribute_value(get_uptime());
    }
};

由于不需要特殊的属性值类, 我们可以使用 make_attribute_value 函数来创建值封装.

提示

对于这种情况, 即属性值可以通过单次函数调用获得, 通常更方便的做法是使用 function 属性.

属性的接口类可以定义如下:

// Attribute interface class
class system_uptime :
    public logging::attribute
{
public:
    system_uptime() : logging::attribute(new system_uptime_impl())
    {
    }
    // Attribute casting support
    explicit system_uptime(attrs::cast_source const& source) : logging::attribute(source.as< system_uptime_impl >())
    {
    }
};

如前所述, 默认构造函数会创建实现实例, 使默认构造的属性可被库使用.

第二个构造函数增加了对 属性转换 的支持. 构造函数参数包含对属性实现对象的引用, 通过对其调用 as, 构造函数尝试将其向上转换为我们自定义属性的实现对象. 如果向上转换失败, as 方法将返回 NULL, 这将导致在失败时构造出空属性.

定义好这两个类后, 就可以像往常一样将该属性与库一起使用:

void init_logging()
{
    boost::shared_ptr< logging::core > core = logging::core::get();

    // ...

    // Add the uptime attribute to the core
    core->add_global_attribute("SystemUptime", system_uptime());
}
