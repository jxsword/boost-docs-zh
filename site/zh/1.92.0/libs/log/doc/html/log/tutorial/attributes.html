为日志添加更多信息: 属性

前面的章节中我们已多次提到属性和属性值. 这里我们将了解如何使用属性向日志记录添加更多数据.

每条日志记录都可以附带若干命名属性值. 属性可以表示关于日志记录发生条件的任何关键信息, 例如代码中的位置、可执行模块名称、当前日期和时间, 或与您的特定应用程序和执行环境相关的任何数据. 属性可以表现为值生成器, 此时它会为它参与的每条日志记录返回不同的值. 属性一产生值, 后者就独立于创建者, 可被过滤器、格式化器和接收器使用. 但要使用属性值, 必须知道其名称和类型, 或至少知道它可能具有的类型集合. 库实现了许多常用属性, 其值类型可在文档中找到.

除此之外, 如 设计概述 一节所述, 属性有三种可能的作用域: 日志源专属、线程专属和全局. 创建日志记录时, 来自这三类集合的属性值被合并成一个集合并传递给接收器. 这意味着属性的来源对接收器没有任何区别. 任何属性都可以注册在任何作用域中. 注册时, 属性会被赋予唯一名称, 以便能够查找它. 如果同名属性恰好出现在多个作用域中, 在任何后续处理 (包括过滤和格式化) 中, 将采用来自最具体作用域的属性. 这种行为使得可以用注册在本地日志器中的属性覆盖全局或线程作用域的属性, 从而减少线程间的相互干扰.

下面是属性注册过程的说明.

常用属性

有些属性几乎在任何应用程序中都会用到. 日志记录计数器和时间戳就是很好的候选. 它们可以通过一次函数调用添加:

logging::add_common_attributes();

通过这次调用, "LineID"、"TimeStamp"、"ProcessID" 和 "ThreadID" 属性被全局注册. "LineID" 属性是一个计数器, 每创建一条记录就递增, 第一条记录的标识符为 1. "TimeStamp" 属性总是产生当前时间 (即日志记录创建的时间, 而不是写入接收器的时间). 最后两个属性标识发出每条日志记录的进程和线程.

注释

在单线程构建中, 不注册 "ThreadID" 属性.

提示

默认情况下, 应用程序启动时, 库中没有注册任何属性. 应用程序必须在开始写日志之前将所有必要的属性注册到库中. 这可以作为库初始化的一部分完成. 细心的读者可能已经好奇: 简单日志是如何工作的? 答案是, 默认接收器组成输出时实际上不使用任何属性值, 只用严重级别. 这样做是为了避免简单日志需要任何初始化. 一旦您使用过滤器或格式化器以及非默认接收器, 就必须注册所需的属性.

add_common_attributes 函数是 此处 描述的几个便捷辅助函数之一.

有些属性会在日志器构造时自动注册. 例如, severity_logger 注册一个日志源专属属性 "Severity", 可用于为不同日志记录添加强调程度. 例如:

// We define our own severity levels
enum severity_level
{
    normal,
    notification,
    warning,
    error,
    critical
};

void logging_function()
{
    // The logger implicitly adds a source-specific attribute 'Severity'
    // of type 'severity_level' on construction
    src::severity_logger< severity_level > slg;

    BOOST_LOG_SEV(slg, normal) << "A regular message";
    BOOST_LOG_SEV(slg, warning) << "Something bad is going on but I can handle it";
    BOOST_LOG_SEV(slg, critical) << "Everything crumbles, shoot me now!";
}

提示

您可以通过为该类型定义 operator << 来定义严重级别的自定义格式化规则. 库格式化器会自动使用它. 更多细节参见 本节.

BOOST_LOG_SEV 宏的行为与 BOOST_LOG 几乎相同, 只是它为日志器的 open_record 方法接受一个额外实参. BOOST_LOG_SEV 宏可以替换为如下等价写法:

void manual_logging()
{
    src::severity_logger< severity_level > slg;

    logging::record rec = slg.open_record(keywords::severity = normal);
    if (rec)
    {
        logging::record_ostream strm(rec);
        strm << "A regular message";
        strm.flush();
        slg.push_record(boost::move(rec));
    }
}

可以看到, open_record 可以接受命名实参. 库提供的某些日志器类型支持这类附加参数, 用户在编写自己的日志器时当然也可以使用这种方式.

更多属性

我们来看看简单形式一节中使用的 add_common_attributes 函数的内部实现. 它可能类似于这样:

void add_common_attributes()
{
    boost::shared_ptr< logging::core > core = logging::core::get();
    core->add_global_attribute("LineID", attrs::counter< unsigned int >(1));
    core->add_global_attribute("TimeStamp", attrs::local_clock());

    // other attributes skipped for brevity
}

这里, counter 和 local_clock 组件是属性类, 它们派生自公共属性接口 attribute. 库还提供了许多其他 属性类, 包括在获取值时调用某个函数对象的 function 属性. 例如, 我们可以用类似的方式注册一个 named_scope 属性:

core->add_global_attribute("Scope", attrs::named_scope());

这将使我们能够为应用程序创建的每条日志记录在日志中存储作用域名称. 用法如下:

void named_scope_logging()
{
    BOOST_LOG_NAMED_SCOPE("named_scope_logging");

    src::severity_logger< severity_level > slg;

    BOOST_LOG_SEV(slg, normal) << "Hello from the function named_scope_logging!";
}

日志器专属属性与全局属性同样有用. 严重级别和通道名称是最明显适合在日志源层面实现的候选. 没有什么能阻止您向日志器添加更多属性, 像这样:

void tagged_logging()
{
    src::severity_logger< severity_level > slg;
    slg.add_attribute("Tag", attrs::constant< std::string >("My tag value"));

    BOOST_LOG_SEV(slg, normal) << "Here goes the tagged record";
}

现在, 通过该日志器产生的所有日志记录都会带有该特定属性的标记. 该属性值之后可用于过滤和格式化.

属性的另一个好用途是标记应用程序不同部分产生的日志记录, 以突出与单个进程相关的活动. 甚至可以实现一个粗略的性能分析工具来检测性能瓶颈. 例如:

void timed_logging()
{
    BOOST_LOG_SCOPED_THREAD_ATTR("Timeline", attrs::timer());

    src::severity_logger< severity_level > slg;
    BOOST_LOG_SEV(slg, normal) << "Starting to time nested functions";

    logging_function();

    BOOST_LOG_SEV(slg, normal) << "Stopping to time nested functions";
}

现在, 从 logging_function 函数或它调用的任何其他函数产生的每条日志记录都将包含 "Timeline" 属性, 其值为自该属性注册以来经过的高精度时长. 基于这些读数, 可以检测代码的哪些部分执行耗时较多或较少. 离开函数 timed_logging 的作用域时, "Timeline" 属性将被注销.

库提供的属性的详细说明参见 属性 一节. 本节的完整代码可在 此处 获取.

定义属性占位符

正如后续章节将看到的, 定义一个描述应用程序所用的特定属性的关键字很有用. 该关键字能够参与过滤和格式化表达式, 就像前面章节使用的 severity 占位符一样. 例如, 要为前面示例中使用的某些属性定义占位符, 可以这样写:

BOOST_LOG_ATTRIBUTE_KEYWORD(line_id, "LineID", unsigned int)
BOOST_LOG_ATTRIBUTE_KEYWORD(severity, "Severity", severity_level)
BOOST_LOG_ATTRIBUTE_KEYWORD(tag_attr, "Tag", std::string)
BOOST_LOG_ATTRIBUTE_KEYWORD(scope, "Scope", attrs::named_scope::value_type)
BOOST_LOG_ATTRIBUTE_KEYWORD(timeline, "Timeline", attrs::timer::value_type)

每个宏定义一个关键字. 第一个实参是占位符名称, 第二个是属性名称, 最后一个参数是属性值类型. 定义后, 该占位符可用于模板表达式和库的其他一些上下文. 定义属性关键字的更多细节见 此处.
