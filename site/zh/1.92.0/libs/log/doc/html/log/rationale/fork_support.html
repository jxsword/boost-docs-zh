Boost.Log 是否支持进程 fork?

不支持, 目前 Boost.Log 不支持进程 fork (即 UNIX 系统中的 fork 调用). 进程 fork 存在若干问题, 例如:

  • 文件接收器不会尝试重新打开日志文件, 也不会在父进程和子进程之间同步对文件的访问. 产生的输出可能是乱码.
  • 文件收集器不允许多个进程试图将日志文件收集到同一目标目录. 这可能导致日志文件轮转时出现虚假失败.
  • current_process_id 属性值不会在子进程中更新.
  • 在多线程应用程序中, 通常无法保证在某一线程 fork 时, 其他线程没有正在执行某些 Boost.Log 代码. 某些 Boost.Log 资源可能在 fork 出的进程中处于不可逆的锁定或损坏状态. 这一限制并非 Boost.Log 特有, 其他库甚至应用程序本身也容易受此影响.

可能还有其他问题. Boost.Log 似乎不太可能在近期内增加对 fork 的支持.

注释

这并不妨碍 fork+exec 序列正常工作. 只要 fork 出的进程不尝试使用任何 Boost.Log 代码, 该进程应该能够调用 exec 或类似函数来加载并启动另一个可执行文件.
