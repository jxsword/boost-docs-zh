创建日志器并写入日志

专用日志器对象

既然我们已经定义了日志存储的位置和方式, 现在是时候看看如何发出日志记录了. 为了能够产生日志记录, 必须先创建一个日志源. 在本例中就是一个日志器对象, 简单得很:

src::logger lg;
注释

细心的读者可能已经注意到, 我们尝试简单日志时并没有创建任何日志器. 在那种情况下, 日志器由库提供, 并在幕后使用.

与接收器不同, 日志源无需在任何地方注册, 因为它们直接与日志核心交互. 另请注意, 库提供两个版本的日志器: 线程安全版本和非线程安全版本. 对于非线程安全的日志器, 不同线程通过不同日志器实例写日志是安全的, 因此每个写日志的线程应有独立的日志器. 线程安全的对应版本可以从不同线程并发访问, 但这会涉及加锁, 在争用激烈时可能拖慢速度. 线程安全日志器类型的名称带有 _mt 后缀.

无论线程安全性如何, 库提供的所有日志器都可默认构造和复制构造, 并支持交换, 因此把日志器作为类的成员应该没有问题. 后文将看到, 这种做法还能带来额外的好处.

库提供了许多具有不同特性的日志器, 例如严重级别和通道支持. 这些特性可以相互组合, 以构造更复杂的日志器. 更多细节参见 此处.

全局日志器对象

如果无法把日志器放进您的类中 (假设您没有这样的类), 库提供了一种声明全局日志器的方式, 像这样:

BOOST_LOG_INLINE_GLOBAL_LOGGER_DEFAULT(my_logger, src::logger_mt)

这里 my_logger 是用户定义的标记名称, 稍后用于获取日志器实例, logger_mt 是日志器类型. 库提供的或用户定义的任何日志器类型都可以参与这种声明. 不过, 由于日志器只有一个实例, 在多线程应用程序中您通常希望使用线程安全的日志器作为全局日志器.

提示

还有其他宏可用于更复杂的情况. 详细描述见 本节.

之后您可以像这样获取日志器:

src::logger_mt& lg = my_logger::get();

然后, lg 将引用整个应用程序中唯一的日志器实例, 即使应用程序由多个模块组成. get 函数本身是线程安全的, 因此无需在其周围进行额外的同步.

写入日志

无论您使用哪种日志器 (类成员或全局, 线程安全与否), 要向日志器写入一条日志记录, 可以这样写:

logging::record rec = lg.open_record();
if (rec)
{
    logging::record_ostream strm(rec);
    strm << "Hello, World!";
    strm.flush();
    lg.push_record(boost::move(rec));
}

这里, 对 open_record 函数的调用确定要构造的记录是否会被至少一个接收器消费. 过滤在此阶段应用. 如果记录将被消费, 函数返回一个有效的记录对象, 此时可以填充记录消息字符串. 之后, 可以通过调用 push_record 完成记录处理.

当然, 上述语法很容易包装在宏中; 实际上, 鼓励用户编写自己的宏, 而不是直接使用 C++ 日志器接口. 上面的日志记录可以这样写:

BOOST_LOG(lg) << "Hello, World!";

看起来更短了, 不是吗? BOOST_LOG 宏与其他类似的宏一起由库定义. 它自动提供一个类似标准库的输出流, 以便用普通的插入表达式格式化消息. 写好、编译并执行所有这些代码后, 您应该能在 "sample.log" 文件中看到 "Hello, world!" 记录. 本节的完整代码可在 此处 找到.
