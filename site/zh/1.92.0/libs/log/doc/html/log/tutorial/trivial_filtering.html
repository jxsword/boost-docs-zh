带过滤器的简单日志

虽然严重级别可以用于提供信息的目的, 但您通常希望应用过滤器只输出重要记录并忽略其余记录. 通过在库核心中设置全局过滤器很容易做到, 像这样:

void init()
{
    logging::core::get()->set_filter
    (
        logging::trivial::severity >= logging::trivial::info
    );
}

int main(int, char*[])
{
    init();

    BOOST_LOG_TRIVIAL(trace) << "A trace severity message";
    BOOST_LOG_TRIVIAL(debug) << "A debug severity message";
    BOOST_LOG_TRIVIAL(info) << "An informational severity message";
    BOOST_LOG_TRIVIAL(warning) << "A warning severity message";
    BOOST_LOG_TRIVIAL(error) << "An error severity message";
    BOOST_LOG_TRIVIAL(fatal) << "A fatal severity message";

    return 0;
}

现在, 如果运行这个代码示例, 前两条日志记录将被忽略, 而其余四条将传递到控制台.

重要

请记住, 流式表达式只在记录通过过滤时才执行. 不要在流式表达式中指定业务关键调用, 因为如果记录被过滤掉, 这些调用可能不会被执行.

关于过滤器设置表达式还需说明几句. 由于我们设置的是全局过滤器, 必须获取 日志核心 实例. 这正是 logging::core::get() 所做的 —— 它返回指向核心单例的指针. 日志核心的 set_filter 方法设置全局过滤函数.

本示例中的过滤器构造为 Boost.Phoenix lambda 表达式. 在本例中, 该表达式由单个逻辑谓词组成, 其左实参是描述要检查的属性的占位符, 右实参是要与之比较的值. severity 关键字是库提供的占位符. 该占位符在模板表达式中标识严重级别属性值; 该值应具有名称 "Severity" 和类型 severity_level. 在简单日志的情况下, 该属性由库自动提供; 用户只需在日志语句中提供其值. 该占位符与排序运算符一起创建一个函数对象, 该函数对象将被日志核心调用以过滤日志记录. 结果, 只有严重级别不低于 info 的日志记录才会通过过滤器并出现在控制台上.

可以构建更复杂的过滤器, 将这样的逻辑谓词彼此组合, 甚至定义自己的函数 (包括 C++11 lambda 函数) 充当过滤器. 我们将在后面的章节中回到过滤话题.
