类 unit_test_log_t

boost::unit_test::unit_test_log_t — 管理日志记录器集合、其流和日志级别.

概要

// In header: <boost/test/unit_test_log.hpp>


class unit_test_log_t : public boost::unit_test::test_observer {
public:

  // public member functions
  virtual void test_start(counter_t, test_unit_id);
  virtual void test_finish();
  virtual void test_aborted();
  virtual void test_unit_start(test_unit const &);
  virtual void test_unit_finish(test_unit const &, unsigned long);
  virtual void test_unit_skipped(test_unit const &, const_string);
  virtual void test_unit_aborted(test_unit const &);
  virtual void test_unit_timed_out(test_unit const &);
  virtual void exception_caught(execution_exception const &);
  virtual int priority();
  void set_stream(std::ostream &);
  void set_stream(output_format, std::ostream &);
  std::ostream * get_stream(output_format) const;
  log_level set_threshold_level(log_level);
  log_level set_threshold_level(output_format, log_level);
  void add_format(output_format);
  void set_format(output_format);
  unit_test_log_formatter * get_formatter(output_format);
  void set_formatter(unit_test_log_formatter *);
  void add_formatter(unit_test_log_formatter *);
  void set_checkpoint(const_string, std::size_t, 
                      const_string = const_string());
  unit_test_log_t & operator<<(log::begin const &);
  unit_test_log_t & operator<<(log::end const &);
  unit_test_log_t & operator<<(log_level);
  unit_test_log_t & operator<<(const_string);
  unit_test_log_t & operator<<(lazy_ostream const &);
  unspecified operator()(log_level);
  void configure();
  virtual void test_unit_skipped(test_unit const &);
  virtual void assertion_result(unit_test::assertion_result);
};

说明

Boost.Test 框架允许同时拥有多个格式化器/日志记录器, 每个都有自己的日志级别和输出流.

该类用于

  • 向测试框架公开接口 (作为 boost::unit_test::test_observer)

  • 向测试工具公开接口

  • 管理多个日志记录器

注释

对该类公开的函数的访问通过单例 boost::unit_test::unit_test_log 进行.

希望实现自己格式化器的用户/开发者需要:

  • 实现一个将输出所需格式的 boost::unit_test::unit_test_log_formatter

  • 在例如全局夹具期间使用方法 set_formatter 注册格式化器 (通过框架单例).

警告

该观察器的优先级高于 boost::unit_test::results_collector_t. 这意味着与每个测试单元关联的各个 boost::unit_test::test_results 在 test_unit_start、test_unit_finish ... 被调用时可能尚不可用.

参见:

  • boost::unit_test::test_observer

  • boost::unit_test::unit_test_log_formatter

unit_test_log_t 公有成员函数

  1. virtual void test_start(counter_t, test_unit_id);
    在框架开始执行测试用例之前调用. 

  2. virtual void test_finish();
    在框架结束执行测试用例之后调用.
    注释

    调用以相反的优先级顺序进行.

  3. virtual void test_aborted();
    在检测到严重错误时调用.

    严重错误主要是系统发送并被 Boost.Test 框架捕获的信号. 由于正在运行的二进制程序可能处于不一致/不稳定状态, 测试执行会被中止, 所有剩余的测试都会被丢弃.

    注释

    可能会在 test_observer::test_unit_finish() 之前被调用

  4. virtual void test_unit_start(test_unit const &);
    在框架开始执行测试单元之前调用. 

  5. virtual void test_unit_finish(test_unit const &, unsigned long);
    在测试单元每次结束时调用. 

  6. virtual void test_unit_skipped(test_unit const &, const_string);
  7. virtual void test_unit_aborted(test_unit const &);
    在测试单元指示致命错误时调用.

    以下情况会发生致命错误:

    • 强断言 (带 REQUIRE) 失败, 这表明测试用例无法继续

    • Boost.Test 框架捕获到非预期的异常

  8. virtual void test_unit_timed_out(test_unit const &);
    在测试超时时调用.

    调用该函数以发出测试单元 (用例或套件) 超时的信号. 有效的测试单元可通过 boost::unit_test::framework::current_test_unit 获取

  9. virtual void exception_caught(execution_exception const &);
    在拦截到异常时调用.

    在拦截到异常的情况下, 该调用发生在 test_unit_aborted 调用之前, 以便记录关于该异常的附加数据.

  10. virtual int priority();
    优先级指示该观察器在 UTF 框架中被初始化和拆除的顺序. 顺序为从最低优先级到最高优先级.
  11. void set_stream(std::ostream &);
    为所有日志记录器设置流.

    这将覆盖所有日志记录器的日志接收器/流, 无论其是否启用.

  12. void set_stream(output_format, std::ostream &);
    为特定日志记录器设置流.
    注释

    如果未找到指定的格式, 则无效

    自 Boost 1.62 起. 

  13. std::ostream * get_stream(output_format) const;
    返回指向与特定日志记录器关联的流的指针.
    注释

    如果未找到格式, 则返回空指针

    自 Boost 1.67 起. 

  14. log_level set_threshold_level(log_level);
    为所有日志记录器/格式化器设置阈值级别.

    这将覆盖所有日志记录器的日志级别, 无论其是否启用.

    返回:

    所有格式化器先前日志级别中的最小值 (Boost 1.73 新增)

    		 
  15. log_level set_threshold_level(output_format, log_level);
    设置特定格式的阈值/日志级别.
    注释

    如果未找到指定的格式, 则无效

    自 Boost 1.62 起.

    返回:

    相应格式化器先前的日志级别 (Boost 1.73 新增)

    		 
  16. void add_format(output_format);
    向日志记录器集合添加一种格式.

    添加日志记录器意味着指定的日志记录器被启用. 日志级别由格式化器自身管理, 并指定哪些事件被转发到底层格式化器.

    自 Boost 1.62 起. 

  17. void set_format(output_format);
    设置日志记录器的格式.

    这将成为日志的唯一活动格式.

  18. unit_test_log_formatter * get_formatter(output_format);
    返回特定格式的日志记录器实例.

    自 Boost 1.62 起.

    返回:

    日志记录器/格式化器实例, 如果未找到格式, 则为 (unit_test_log_formatter*)0.

    		 
  19. void set_formatter(unit_test_log_formatter *);
    设置日志记录器实例.

    指定的日志记录器成为唯一的活动记录器. 自定义日志格式化器的格式为 OF_CUSTOM_LOGGER. 如果该格式已存在, 其格式化器将被参数中给定的格式化器替换.

    新格式化器的日志级别和输出流取自当前活动的日志记录器. 如果有多个日志记录器处于活动状态, 优先级顺序为 CUSTOM、HRF、XML 和 JUNIT. 如果参数为 (unit_test_log_formatter*)0, 则自定义日志记录器 (如果存在) 会被移除.

    注释

    指针的所有权转移给 Boost.Test 框架. 该调用等同于

    • 调用 add_formatter

    • 调用 set_format(OF_CUSTOM_LOGGER)

    • 使用先前配置的流和日志级别配置新添加的日志记录器.

  20. void add_formatter(unit_test_log_formatter * the_formatter);
    向格式化器集合添加自定义日志格式化器.

    指定的日志记录器以格式 OF_CUSTOM_LOGGER 添加, 以便后续可以选择它或指定其流/日志级别. 如果已经存在自定义日志记录器 (格式为 OF_CUSTOM_LOGGER), 则现有的记录器将被参数中给定的记录器替换. 提供的日志记录器以启用状态添加. 如果参数为 (unit_test_log_formatter*)0, 则自定义日志记录器 (如果存在) 会被移除, 并且不执行其他操作.

    注释

    指针的所有权转移给 Boost.Test 框架.

    自 Boost 1.62 起. 

  21. void set_checkpoint(const_string file, std::size_t line_num, 
                    const_string msg = const_string());
  22. unit_test_log_t & operator<<(log::begin const &);
  23. unit_test_log_t & operator<<(log::end const &);
  24. unit_test_log_t & operator<<(log_level);
  25. unit_test_log_t & operator<<(const_string);
  26. unit_test_log_t & operator<<(lazy_ostream const &);
  27. unspecified operator()(log_level);
  28. void configure();
    在日志级别、流和格式设置完毕后准备内部状态.
  29. virtual void test_unit_skipped(test_unit const &);
    向后兼容
  30. virtual void assertion_result(unit_test::assertion_result);
