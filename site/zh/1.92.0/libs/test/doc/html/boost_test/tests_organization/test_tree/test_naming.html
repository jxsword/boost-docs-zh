测试命名

名称的可接受字符

单元测试框架对测试单元(测试用例/套件)的命名很灵活, 可以使用各种各样的字符. 不过在某些场景下, 测试单元名可能与单元测试框架的其他特性冲突. 例如:

  • 某个字符可能与用于选择测试树子集的特定命令行过滤器冲突. 这些字符包括: '@'、'+'或'/'(更多细节见本节)
  • 名称包含为 shell/终端保留的字符, 如 '!'、'*' 等, 可能使测试名无法按原样传递到命令行.

为防止任何冲突声明, 单元测试框架在把测试加入测试树之前, 会对给予测试单元(用例或套件)的名称进行清理. 任何冲突字符都会被替换为下划线'_'.

注释

空格不被视为特殊字符并被保留, 但去除首尾空格除外.

注释

测试单元名的清理在Boost 1.67中引入.

测试名的约束

如果两个兄弟测试用例同名, 单元测试框架会视为错误. 该一致性检查在运行期执行, 且对测试过滤不敏感.

对自动注册的测试用例, 且在同一编译单元内, 名称冲突时编译器应产生编译错误. 对手动注册的测试用例, 若发生冲突, 可以使用工具BOOST_TEST_CASE_NAME.

数据驱动测试在独立的测试套件中自动创建, 且名称按样本建立索引.

注释

该约束不适用于测试套件: 打开/关闭测试套件声明会把测试用例加入该名称的既有或新建测试套件.
