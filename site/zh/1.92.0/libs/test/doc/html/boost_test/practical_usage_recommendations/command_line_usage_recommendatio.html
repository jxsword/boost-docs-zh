命令行使用建议

如果在测试用例内部某处发生了致命异常, 通过添加额外的命令行参数让程序生成核心转储(core-dump)

如果你在运行测试时收到"内存访问违例"消息(或任何其他指示致命错误或系统错误的消息), 想获得更多关于错误位置的信息, 请在测试运行命令行中添加

--catch_system_error=no

现在再次运行测试, 它会生成一个核心转储, 你可以用惯用的调试器分析它. 或者一开始就在调试器下运行, 程序会在失败点中断.

如何在自动化回归测试设施的管理下使用以 Boost.Test 框架构建的测试模块?

我的第一条建议是: 通过添加参数

--catch_system_error=yes

到所有测试模块的调用中, 确保测试框架捕获所有致命错误. 否则测试程序可能弹出多余的对话框(取决于编译器和操作系统), 中断你的回归测试运行. 第二条建议是: 通过添加参数

--report_level=no

抑制结果报告输出, 并通过添加参数

--log_level=nothing

抑制测试日志输出, 这样测试模块就不会产生反正也没人会看的无用输出. 我们建议只依赖结果码, 它对所有测试程序都是一致的. 第二条建议的替代方案是把日志和报告都指向单独的文件, 供你日后分析. 此外, 你还可以让 Boost.Test 以 XML 或 JUNIT 格式生成它们, 使用的参数是

--output_format=XML

或者

--log_format=JUNIT

然后用某个自动化工具按你喜欢的方式格式化这些信息.
