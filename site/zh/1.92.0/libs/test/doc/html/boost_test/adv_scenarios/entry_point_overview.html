测试模块的入口点

通常, 每个 C++ 程序都恰好包含函数main的一个定义: 即程序的入口点. 使用单元测试框架时你不必自己定义它. 函数main会由框架替你生成. 唯一需要你做的是: 当你的程序由多个翻译单元(cpp文件)组成时, 要告知框架应在哪个文件中生成函数main. 具体做法是: 在包含任何框架头文件之前定义宏BOOST_TEST_MODULE. 该宏的值既用作测试模块的名称, 也用作主测试套件的名称.

替你定义函数main的原因有两点:

  1. 这使得单元测试框架能够执行某些自定义的测试模块初始化.
  2. 这样可以防止你自己定义main时, 因疏忽而忘记运行所有测试(在这种情况下, 运行程序会错误地显示一次干净的运行结果).

默认情况下, 测试模块入口点采用如下签名定义:

int main(int argc, char* argv[]);

它先调用测试模块初始化函数, 然后调用测试模块运行器, 并把其返回值传递给环境.

默认入口点在大多数情况下就够用了. 偶尔也可能需要声明一个名称或签名不同的入口点. 关于覆盖默认测试模块入口点的定义:

  • 参见此处, 适用于仅头文件使用变体,
  • 参见此处, 适用于静态库使用变体,
  • 参见此处, 适用于共享库使用变体.
