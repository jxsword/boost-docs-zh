定制模块的入口点

在静态库变体中, 定制主入口点相当麻烦, 因为函数main的定义已经编译进静态库. 这要求你重新构建单元测试框架静态库, 并在构建时定义符号BOOST_TEST_NO_MAIN. 在 Boost 根目录下你需要执行命令

> b2 --with-test link=static define=BOOST_TEST_NO_MAIN define=BOOST_TEST_ALTERNATIVE_INIT_API install
警告

这种把入口点定义从静态库中移除的做法会影响所有链接该库的其他用户. 改用共享库使用变体可能是侵入性更小的选择.

在某个源文件中, 你现在需要定义自定义入口点, 并手动调用默认的测试运行器 unit_test_main, 以默认初始化函数 init_unit_test作为第一个参数. 无需在源代码中定义BOOST_TEST_NO_MAIN, 但需要在主文件中定义BOOST_TEST_ALTERNATIVE_INIT_API:

#define BOOST_TEST_MODULE test module name
#define BOOST_TEST_ALTERNATIVE_INIT_API
#include <boost/test/unit_test.hpp>

// entry point:
int main(int argc, char* argv[], char* envp[])
{
  return utf::unit_test_main(init_unit_test, argc, argv);
}
