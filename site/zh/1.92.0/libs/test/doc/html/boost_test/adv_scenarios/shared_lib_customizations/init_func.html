定制模块的初始化函数

在共享库变体中, 若不定制入口点就无法定制初始化函数. 两者必须同时定制. 在某个源文件中, 你需要定义自定义入口点和初始化函数 init_unit_test; 然后手动调用默认的测试运行器 unit_test_main, 并以init_unit_test作为参数. 你不要在主文件中定义BOOST_TEST_MODULE:

在恰好一个文件中

在所有其他文件中

 
#define BOOST_TEST_DYN_LINK
#include <boost/test/unit_test.hpp>

// initialization function:
bool init_unit_test()
{
  return true;
}

// entry point:
int main(int argc, char* argv[])
{
  return boost::unit_test::unit_test_main( &init_unit_test, argc, argv );
}

#define BOOST_TEST_DYN_LINK
#include <boost/test/unit_test.hpp>

//
// test cases
//

// test cases
//

//
// test cases
//

用于报告初始化期间可能发生的错误,

  • 要么你返回false(仅对新 API 有效, 见BOOST_TEST_ALTERNATIVE_INIT_API)
  • 要么你抛出一个异常, 例如std::runtime_error或boost::unit_test::framework::setup_error

在该函数中报告的错误会中止测试模块的执行.
