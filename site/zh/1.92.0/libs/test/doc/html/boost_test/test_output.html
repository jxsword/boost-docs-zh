控制输出的 API 汇总

测试模块产生的输出是单元测试框架带给用户的主要资产之一. 与任何手动/断言式方案相比, 单元测试框架提供以下服务:

所有测试错误被统一报告

测试执行监视器连同所有包含的测试工具的标准化输出, 为包括内存访问违例和未捕获异常等致命错误在内的所有错误提供统一的报告.

错误来源的详细信息

单元测试框架基于测试工具的断言会尽可能多地提供错误成因信息, 通常让你无需进入调试器或核心转储分析即可推断问题所在.

测试错误描述(测试日志)与结果报告摘要(测试结果报告)相分离

测试执行期间产生的信息, 包括来自测试工具的所有错误、警告和提示消息, 以及被执行测试单元的通知, 构成了测试日志.

测试完成后, 单元测试框架可以生成详细程度不同的摘要测试报告.

输出内容的灵活性

单元测试框架支持配置测试日志和测试报告中显示的内容. 该配置既支持运行期(从命令行), 也支持编译期(在测试模块内部).

输出格式的灵活性

单元测试框架支持配置测试模块输出的格式. 目前只有三种格式受单元测试框架自身支持. 不过, 定义良好的公共接口允许你按自己的目的定制输出.
