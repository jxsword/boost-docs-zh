测试模块的初始化

单元测试模块要成功链接并执行, 必须能访问测试模块的初始化函数. 模块的初始化函数在程序执行期间只被调用一次, 恰在测试模块运行器运行之前. 默认情况下, 单元测试框架提供初始化函数的默认定义. 你唯一要做的是告知框架需要在哪个翻译单元(cpp文件)中提供该定义. 具体做法是在指定文件中定义宏BOOST_TEST_MODULE. 默认实现会为测试模块和主测试套件指定名称. 要指定的名称由宏BOOST_TEST_MODULE的值决定.

重要

对于由多个源文件组成的测试模块, 你只需在一个测试文件中定义BOOST_TEST_MODULE. 否则最终会出现初始化函数的多个实例.

实际上几乎从不需要改变测试模块初始化函数的默认行为. 单元测试框架为执行定制任务提供了更优的工具:

  • 关于在测试树中自动注册测试用例和测试套件, 见测试的组织一节;
  • 要为主测试套件指定自定义名称, 将宏BOOST_TEST_MODULE定义为期望值;
  • 要访问命令行参数(单元测试框架自行消费的参数除外), 使用主测试套件的接口;
  • 要执行测试用例所需状态的全局初始化, 全局夹具提供了更优的替代方案: 你可以在一处指定全局建立(set-up)和拆除(tear-down), 允许每个测试用例访问全局数据, 并保证在程序执行期间每次重新运行测试时都会重复清理和拆除;
  • 如果对自定义模块初始化的需求仅仅源于遗留代码(针对单元测试框架旧版本编写), 建议更新你程序的代码.

框架提供的默认初始化函数在全局命名空间中以如下签名定义:

bool init_unit_test();

返回值true表示初始化成功. 值false表示初始化失败.

要覆盖默认定义:

  • 参见此处, 适用于仅头文件使用变体,
  • 参见此处, 适用于静态库使用变体,
  • 参见此处, 适用于共享库使用变体.
