常见问题(FAQ)

Boost 测试库的最新版本在哪里?

Boost 测试库的最新版本可在http://www.boost.org/libs/test在线获取.

缺陷报告或功能请求: 我该怎么做?

你可以把缺陷报告或功能请求发送到 boost 用户邮件列表 boost-users@lists.boost.org, 和/或在项目的 GitHub issues 上建一个工单: https://github.com/boostorg/test.

如何用单元测试框架创建测试用例?

要创建测试用例, 使用宏

BOOST_AUTO_TEST_CASE( test_function );

更多细节见单元测试框架的BOOST_AUTO_TEST_CASE文档.

Boost.Test 是线程安全的吗?

简短回答: 不是, 但我们欢迎补丁!

较长的回答: Boost.Test 目前没有任何同步机制来避免多线程调用断言宏时产生竞态. 例如这段代码

BOOST_TEST_CASE(test_parallel)
{
    std::vector<std::string> vect(10);
    std::for_each(
        std::execution::par_unseq,
        vect.begin(),
        vect.end(),
        [](auto const& str)
        {
            BOOST_TEST(str == "");
        });
}

不会按预期工作, 因为断言BOOST_TEST会被多个线程调用.

要创建测试套件, 使用宏

更多细节见单元测试框架的BOOST_AUTO_TEST_SUITE文档.

为什么编译测试程序时出现链接器错误?

Boost 测试库组件提供多种使用变体: 创建测试程序时, 你可以链接某个预编译库变体, 或使用仅头文件变体. 例如, 要使用单元测试框架, 你可以包含

#include <boost/test/unit_test.hpp>

并链接

libunit_test_framework.lib

或者你可以包含

#include <boost/test/included/unit_test.hpp>

此时你不需要链接任何预编译组件. 另外请注意, 你必须严格遵循初始化函数的规范, 否则某些编译器可能产生类似这样的链接器错误.

Unresolved external init_unit_test_suite(int, char**).

这个错误的原因是, 在你的实现中, init_unit_test_suite的第二个参数必须与规范完全一致, 即: char* [].

如何重定向测试输出?

使用

unit_test_log::instance().set_log_output( std::ostream & )

更多细节见单元测试框架的输出测试流文档.

我想要不同的默认日志跟踪级别

使用环境变量BOOST_TEST_LOG_LEVEL来定义期望的日志跟踪级别. 你仍然可以在命令行上重设该值. 可接受值的列表见单元测试框架的运行期配置文档.

Win32 平台上是否有 Boost.Test 组件的 DLL 版本?

有. 从 Boost 1.34.0 开始提供.

如何搭建使用单元测试框架的 CMake 工程(扩展)

假设你正从一个翻译单元test_file.cpp构建测试模块. 首先, 让我们以仅头文件使用变体(属于单元测试框架)来做这件事.

我们把以下内容粘贴到CMakeLists.txt中, 位置与我们的测试文件test_file.cpp相同:

cmake_minimum_required(VERSION 2.8.7)
project(my_first_test)
enable_testing()

# indicates the location of the boost installation tree.
# hard-coded for our simple example.
set(BOOST_INCLUDE_DIRS $boost_installation_prefix/include)

# creates the executable
add_executable(test_executable test_file.cpp)
# indicates the include paths
target_include_directories(test_executable PRIVATE ${BOOST_INCLUDE_DIRS})

# declares a test with our executable
add_test(NAME test1 COMMAND test_executable)

现在我们为该工程创建构建目录(单独的目录), 配置并构建工程, 如下:

> cd $test_path
> mkdir build     
> cd build
> cmake  ..       
> cmake --build . 
> ctest

如果你使用共享库形式的单元测试框架变体, 则需要在 CMakeLists.txt 中做一些修改.

cmake_minimum_required(VERSION 2.8.11)
project(my_first_test)
enable_testing()

# replace XX with the version you have
set(Boost_ADDITIONAL_VERSIONS "1.XX" "1.XX.0")

# finds boost, triggers an error otherwise
find_package(Boost XX REQUIRED COMPONENTS unit_test_framework)

# creates the executable
add_executable(test_executable test_file.cpp)
# indicates the include paths
target_include_directories(test_executable PRIVATE ${Boost_INCLUDE_DIRS})
# indicates the shared library variant
target_compile_definitions(test_executable PRIVATE "BOOST_TEST_DYN_LINK=1")
# indicates the link paths
target_link_libraries(test_executable ${Boost_UNIT_TEST_FRAMEWORK_LIBRARY})

# declares a test with our executable
add_test(NAME test1 COMMAND test_executable)

现在我们为该工程创建构建目录(单独的目录), 配置并构建工程, 如下:

> cd $test_path
> mkdir build 
> cd build
> cmake -DBOOST_ROOT=$boost_installation_prefix .. 
> cmake --build . 
> ctest
