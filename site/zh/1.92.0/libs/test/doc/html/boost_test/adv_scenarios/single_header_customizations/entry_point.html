定制模块的入口点

在这种使用变体中, 在包含BOOST_TEST_MODULE定义的那个翻译单元里, 你需要在包含任何框架头文件之前定义宏BOOST_TEST_NO_MAIN和BOOST_TEST_ALTERNATIVE_INIT_API(其值无关紧要). 接下来, 你需要定义自定义入口点, 并手动调用默认的测试运行器 unit_test_main, 以默认初始化函数 init_unit_test作为参数.

示例: 使用自定义入口点

代码

 
#define BOOST_TEST_MODULE custom_main
#define BOOST_TEST_NO_MAIN
#define BOOST_TEST_ALTERNATIVE_INIT_API
#include <boost/test/included/unit_test.hpp>
#include <iostream>
namespace utf = boost::unit_test;

BOOST_AUTO_TEST_CASE(test1)
{
  BOOST_TEST(false);
}

void make_use_of(char**)
{
  std::cout << "Using custom entry point..." << std::endl;
}

int main(int argc, char* argv[], char* envp[])
{
  make_use_of(envp);
  return utf::unit_test_main(init_unit_test, argc, argv);
}

输出

 
> custom_main
Using custom entry point...
Running 1 test case...
test.cpp(10): error: in "test1": check false has failed

*** 1 failure is detected in the test module "custom_main"

在上面的示例中, 之所以选择自定义入口点, 是因为测试模块除了命令行参数之外, 还需要获取环境变量的信息.

注释

上面的示例还表明, 同时定义BOOST_TEST_MODULE和BOOST_TEST_NO_MAIN是有意义的. 这样框架就不会生成main, 但BOOST_TEST_MODULE指定的名称会被赋给主测试套件.

注释

定义BOOST_TEST_ALTERNATIVE_INIT_API的原因在此处说明.
