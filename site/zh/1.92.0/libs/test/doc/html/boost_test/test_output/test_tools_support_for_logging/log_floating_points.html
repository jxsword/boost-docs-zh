记录浮点类型数值

看起来单元测试框架显示浮点数时使用了过多的十进制小数位. 但显示的位数是经过选择的, 以避免出现明显荒谬的显示, 诸如[1.00000 != 1.00000]——这种显示出现在把恰好等于 1 的值与仅增加一个最低有效二进制位的值进行比较时, 使用的是 float 的默认精度(仅 6 个十进制位, 由std::numeric_limits<float>::digits10给出). 用于确定显示小数位数的函数是为未来 C++ 标准提议的A Proposal to add a max significant decimal digits value, 将称为std::numeric_limits::max_digits10();. 对 32 位 float 而言, 需要 9 个十进制位才能保证单个位的变化产生不同的十进制数字串.

因此, 使用 9 个十进制位会得到更有帮助的显示: [1.00000000 != 1.00000012], 表明这两个值实际上不同.

对IEEE754 32 位 float 值 - 显示 9 个十进制位. 对 64 位IEEE754 double - 显示 17 个十进制位. 对使用 80 位的IEEE754扩展 long double - 显示 21 个十进制位. 对 128 位IEEE754四倍 long double 以及 SPARC 128 位扩展 long double - 显示 36 个十进制位. 对浮点类型, 计算max_digits10的一个便捷公式是: 2 + std::numeric_limits<FPT>::digits * 3010/10000;

注释

注意, 用户自定义浮点类型 UDFPT 必须定义std::numeric_limits<UDFPT>::is_specialized = true, 并为std::numeric_limits<UDFPT>::digits(用于有效数字/尾数的位数)提供适当的值. 例如, 对 SPARC 128 位扩展 long double, 有效数字使用 113 位(其中一位是隐含的).
