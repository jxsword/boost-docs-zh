Boost.Test v3.10 / boost 1.70
新特性
  • 新增了关于自定义命令行参数的文档章节
  • 自定义数据集不再需要声明内部类型sample
  • Boost.Test 不再依赖 Boost.Timer(后者此前还会把 Boost.Chrono 和 Boost.System 作为传递依赖引入).
  • 现在, 当测试用例在 Windows 上超时后, Boost.Test 会抛出异常. 在本版本之前, Windows 上的超时不会使测试用例失败. 注意 Windows 上不支持信号机制, 因此即使发生超时也无法中断测试.
  • 超时现在同样适用于测试套件: 如果测试套件超出分配的时间, 就会被标记为超时. 在超时时间点尚未执行的测试单元将被跳过.
  • 现在可以通过工具BOOST_TEST_CONTEXT为同一个上下文传递多个值.
  • 新增宏BOOST_TEST_INFO_SCOPE, 可以以粘滞(sticky)方式为当前作用域定义上下文.

  • 现在可以在不把两个操作数都强制转换为浮点类型的情况下使用浮点比较. 对于如下表达式, Boost.Test 现在会使用浮点比较

    BOOST_TEST(3.0001 == 3);

    更多信息见本节.

破坏性变更

  • Boost.Test minimal.hpp现在会显示弃用警告. minimal.hpp早已被弃用, 并将在不久后移除. 请改用例如 Boost.Test 的仅头文件变体. 使用minimal.hpp的测试可以轻松转换为仅头文件变体. 例如, 以下代码:

    #include <boost/test/minimal.hpp>
int test_main( int, char *[] )
{
  ...
}

    可以改写为:

    #include <boost/test/included/unit_test.hpp>
BOOST_AUTO_TEST_CASE(test_main)
{
  ...
}
  • 浮点比较行为的这一变化可能使原本使用直接关系运算符比较的地方改用此类比较. 特别地, 这可能产生新的警告.
  • 成员函数boost::unit_test::unit_test_log_formatter::log_build_info略有变化, 会接受一个额外的布尔参数. 如果你有自定义日志记录器, 需要更新其签名.

  • Boost.Test 学会了把':'解释为测试过滤器的分隔符: 传给--run_test的字符串会像重复了--run_test一样生成标记, 这使得可以通过关联的环境变量BOOST_TEST_RUN_FILTERS设置多个测试过滤器
  • 单元测试框架学会了以 xUnit/JUNIT 日志格式记录消息. 更多细节见此处.
  • 单元测试框架学会了同时拥有多个日志记录器, 每个记录器都有自己的日志级别和日志接收器. 更多细节见关联的命令行开关--logger和对应的环境变量BOOST_TEST_LOGGER.
  • 日志记录器现在能够指示其默认输出流和日志级别.

Boost.Test v3.1 / boost 1.60
新的重大特性
  • 改进了数据集 API
    • 现在可以使用初始化列表
    • 不再需要把make用作左上数据集
  • 改进的命令行界面
    • 更清晰的 help 命令
    • 现在在有歧义时会给出最接近的匹配命令

    • 报告无效或有歧义的参数: 当向测试模块提供用户自定义命令时, 这可能破坏现有调用. 应采用以下调用约定:

      • 如果测试模块使用用户提供的命令, 这些命令应传在一个空标记--之后
      • 所有 boost.test 相关命令都应传在--之前(如有)

      示例: 调用

      test_module --user-arg1=xy --log_level=test_suite

      应改写为

      test_module --log_level=test_suite -- --user-arg1=xy
