定制模块的初始化函数

在静态库变体中, 定制主入口点相当麻烦, 因为编译进静态库的默认测试运行器使用的是已过时的初始化函数签名. 这要求你重新构建单元测试框架静态库, 并在构建时定义符号BOOST_TEST_ALTERNATIVE_INIT_API. 在 Boost 根目录下你需要执行命令

> b2 --with-test link=static define=BOOST_TEST_ALTERNATIVE_INIT_API install
警告

对静态库的这种改动会影响所有链接该库的其他用户. 可以考虑改用已过时的测试初始化函数, 它不需要重新构建. 或者, 改用共享库使用变体可能是侵入性更小的选择.

在某个源文件中, 你现在需要用如下签名定义自定义初始化函数:

bool init_unit_test();

默认的测试运行器会用它来初始化测试模块. 在源代码中你不再定义宏BOOST_TEST_MODULE; 而是需要在主文件中定义BOOST_TEST_ALTERNATIVE_INIT_API:

在恰好一个文件中

在所有其他文件中

 
#define BOOST_TEST_ALTERNATIVE_INIT_API
#include <boost/test/unit_test.hpp>

// init func:
bool init_unit_test()
{
  return true;
}

#include <boost/test/unit_test.hpp>

//
// test cases
//

// test cases
//

用于报告初始化期间可能发生的错误,

  • 要么你返回false(仅对新 API 有效, 见BOOST_TEST_ALTERNATIVE_INIT_API)
  • 要么你抛出一个异常, 例如std::runtime_error或boost::unit_test::framework::setup_error

在该函数中报告的错误会中止测试模块的执行.

注释

定义BOOST_TEST_ALTERNATIVE_INIT_API的原因在此处说明.
