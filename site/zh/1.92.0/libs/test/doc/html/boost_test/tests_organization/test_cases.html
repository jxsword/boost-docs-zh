测试用例是由测试运行器运行的一个执行单元. 它包含指令和断言, 其执行由单元测试框架监视. 执行信息会被记录, 并生成日志/报告.

应让测试运行器知晓测试用例以便运行它: 测试用例应当被注册, 以纳入测试树.

单元测试框架涵盖以下测试用例场景:

  • 无参数测试用例: 类似于在测试运行器的受控环境中运行一个函数.
  • 带参数测试用例: 这种用法旨在用可能不同的多个参数运行同一函数, 每次不同参数的调用都由测试运行器处理.
  • 模板测试用例: 该场景是针对若干类型测试同一模板实现.

针对上述每个场景, 测试用例有不同的声明 API. 首选的 API 会声明测试用例并自动把它注册到测试树中, 无需手动注册.

手动注册

虽然自动注册是首选的测试用例声明 API, 也可以手动声明测试. 对这些 API, 单元测试框架选择了基于通用回调方式的最低侵入设计, 其签名取决于所声明测试用例的种类.

单个测试模块可以混用自动与手动测试用例注册. 换言之, 在同一测试模块内, 既可以有远程实现并在测试模块初始化函数中手动注册的测试用例, 也可以有在实现点自动注册的测试用例.

注意

单元测试框架的手动测试用例声明 API 设计假定测试用例实现(测试函数主体)与测试用例创建/注册点是分离的. 结果, 你可能忘记注册某个测试用例, 它就永远不会被执行, 尽管它存在于测试文件中.

在决定使用手动注册之前, 你必须确信已穷尽采用自动注册 API 的所有可能方式. 具体而言:

  • 如果需要可选地包含/排除某些测试用例, 考虑改用enabled / disabled / enable_if装饰器
  • 如果需要基于某些数据注册参数化测试用例, 考虑改用数据驱动测试用例
  • 如果需要指定复杂的测试单元依赖, 可以改用depends_on装饰器
  • 如果需要在测试单元间共享逻辑, 考虑改用夹具
