测试用例夹具

测试用例夹具是由测试用例消费的夹具: 夹具setup在测试用例执行之前被调用, 夹具teardown在测试用例结束执行之后被调用, 与其执行状态无关.

单元测试框架提供了多种为测试用例定义夹具的方式, 各有其性质:

  • 为单个测试用例声明夹具, 让测试用例访问夹具的成员,
  • 为单个测试用例声明一个或多个夹具, 不访问成员且接口灵活,
  • 为由子树定义的一组测试用例声明夹具, 可访问夹具的成员.

单个测试用例夹具

以下两种方法可用于声明附着于某个特定测试用例的夹具:

  • 使用宏BOOST_FIXTURE_TEST_CASE替代BOOST_AUTO_TEST_CASE, 它允许访问夹具的成员
  • 使用装饰器fixture, 它不允许访问成员, 但支持为一个测试用例定义多个夹具.
夹具与 BOOST_FIXTURE_TEST_CASE

BOOST_FIXTURE_TEST_CASE用作带夹具的测试用例声明, 应替代带BOOST_AUTO_TEST_CASE的测试用例声明使用:

BOOST_FIXTURE_TEST_CASE(test_case_name, fixture_name);

与宏BOOST_AUTO_TEST_CASE的唯一区别是多出一个参数fixture_name. 夹具的 public 和 protected 成员可从测试用例主体直接访问. 一个测试用例只能附着一个夹具[4].

注释

你无法访问夹具的 private 成员, 但话说回来, 你为什么要把它设为 private 呢?

示例: 每测试用例夹具

代码

 
#define BOOST_TEST_MODULE example
#include <boost/test/included/unit_test.hpp>

struct F {
  F() : i( 0 ) { BOOST_TEST_MESSAGE( "setup fixture" ); }
  ~F()         { BOOST_TEST_MESSAGE( "teardown fixture" ); }

  int i;
};

BOOST_FIXTURE_TEST_CASE( test_case1, F )
{
  BOOST_TEST( i == 1 );
  ++i;
}

BOOST_FIXTURE_TEST_CASE( test_case2, F )
{
  BOOST_CHECK_EQUAL( i, 1 );
}

BOOST_AUTO_TEST_CASE( test_case3 )
{
  BOOST_TEST( true );
}

输出

 
> example --log_level=message
Running 3 test cases...
setup fixture
test.cpp(13): error in "test_case1": check i == 1 has failed
teardown fixture
setup fixture
test.cpp(19): error in "test_case2": check i == 1 has failed [0 != 1]
teardown fixture

*** 2 failures are detected in test suite "example"

在此示例中, 只有test_case1和test_case2被指定了夹具F. 你仍然需要在每个测试用例中引用夹具名. 本节解释了如何为测试套件下的子树声明同一夹具.

夹具与 fixture 装饰器

通过使用装饰器fixture, 可以:

  • 把多个夹具附着到一个测试用例
  • 使用灵活的夹具接口(见此处)
注释

使用装饰器方式时, 无法访问夹具的成员(当夹具实现为类时)

完整子树的夹具

如果测试子树中的所有测试用例都需要同一夹具(你可以按所需夹具把测试用例分组到测试套件中), 你可以再向测试夹具分配的自动化迈出一步. 要为测试套件中的所有测试用例分配同一共享夹具, 请使用宏BOOST_FIXTURE_TEST_SUITE替代宏BOOST_AUTO_TEST_SUITE来自动创建和注册测试套件.

BOOST_FIXTURE_TEST_SUITE(suite_name, fixture_name);

与宏BOOST_AUTO_TEST_SUITE的用法再次只有一点区别: 多出一个参数 - 夹具名. 而现在, 你不仅可以直接访问夹具的 public 和 protected 成员, 还无需在测试用例定义中引用夹具名. 所有测试用例都会自动获得同一夹具.

提示

如有必要, 你可以使用宏BOOST_FIXTURE_TEST_CASE为特定测试用例重设夹具. 类似地, 可以使用BOOST_FIXTURE_TEST_SUITE为特定子测试套件重设夹具.

注释

夹具分配是深层的. 换言之, 除非被另一个BOOST_FIXTURE_TEST_SUITE或BOOST_FIXTURE_TEST_CASE定义重设, 同一夹具会被分配给测试套件的所有测试用例, 包括属于子测试套件的那些.

示例: 测试套件级夹具

代码

 
#define BOOST_TEST_MODULE fixture_02
#include <boost/test/included/unit_test.hpp>

struct F {
  F() : i( 0 ) { BOOST_TEST_MESSAGE( "setup fixture" ); }
  ~F()         { BOOST_TEST_MESSAGE( "teardown fixture" ); }

  int i;
};

BOOST_FIXTURE_TEST_SUITE(s, F)

  BOOST_AUTO_TEST_CASE(test_case1)
  {
    BOOST_TEST_MESSAGE("running test_case1");
    BOOST_TEST(i == 0);
  }

  BOOST_AUTO_TEST_CASE(test_case2)
  {
    BOOST_TEST_MESSAGE("running test_case2");
    BOOST_TEST(i == 0);
  }

BOOST_AUTO_TEST_SUITE_END()

输出

 
> fixture_02 --log_level=message
Running 2 test cases...
setup fixture
running test_case1
teardown fixture
setup fixture
running test_case2
teardown fixture

*** No errors detected
注意

夹具的构造/建立与拆除/析构会为每个测试用例调用(夹具的状态不在测试用例间共享).


[4] 仍然可以定义一个继承多个夹具的类, 充当代理夹具.
