夹具模型

单元测试框架支持多种夹具接口. 接口的选择主要取决于夹具的用法.

夹具类模型

单元测试框架把通用夹具类模型定义如下:

struct <fixture-name>{
  <fixture-name>();      // setup function
  ~<fixture-name>();     // teardown function
};

换言之, 夹具预期实现为一个类, 类构造函数充当setup方法, 类析构函数充当teardown方法.

不过上面的类模型有一些限制:

  • 拆除函数中不能有异常, 特别是任何中止当前测试用例的测试断言都不可用(因为它们使用异常)
  • 有时更自然的做法是用构造函数/析构函数执行夹具所需的资源分配/释放(供测试用例消费), 并在单独的函数中检查夹具的恰当状态. 这些检查是测试用例运行的前置条件, 以及测试用例运行后应满足的后置条件.

这就是为什么单元测试框架还支持(自 Boost 1.65 起)可选的setup和/或teardown函数, 如下所示:

struct <fixture-name>{
  <fixture-name>();      // ctor
  ~<fixture-name>();     // dtor
  void setup();          // setup, optional
  void teardown();       // teardown, optional
};
注释

如前所述, setup和teardown的声明/实现是可选的: 单元测试框架会检查它们是否存在并适时调用. 但在 C++98 中, 若它们是继承而来的则无法检测到(对支持auto和decltype的编译器则工作正常).

与BOOST_FIXTURE_TEST_CASE和BOOST_FIXTURE_TEST_SUITE配合使用的夹具应符合此模型.

灵活模型

除BOOST_FIXTURE_TEST_CASE和BOOST_FIXTURE_TEST_SUITE之外, 单元测试框架还允许使用装饰器fixture把夹具与测试单元关联. 该装饰器支持声明setup和teardown的附加模型:

  • 按上述夹具类模型定义的夹具

  • 按扩展夹具类模型定义的夹具, 它允许夹具构造函数接受一个参数. 例如:

    struct Fx
{
  std::string s;
  Fx(std::string s_ = "") : s(s_)
      { BOOST_TEST_MESSAGE("ctor " << s); }
  void setup()
      { BOOST_TEST_MESSAGE("optional setup " << s); }
  void teardown()
      { BOOST_TEST_MESSAGE("optional teardown " << s); }
  ~Fx()
      { BOOST_TEST_MESSAGE("dtor " << s); }
};

  • 定义为一对自由函数的夹具, 分别用于setup和teardown(后者可选)

    void setup() { BOOST_TEST_MESSAGE("set up"); }
void teardown() { BOOST_TEST_MESSAGE("tear down"); }

使用这些模型的测试模块完整示例请参见装饰器fixture.
