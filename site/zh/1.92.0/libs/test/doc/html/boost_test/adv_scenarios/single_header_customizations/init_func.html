定制模块的初始化函数

在这种使用变体中, 你不定义宏BOOST_TEST_MODULE, 而是提供函数init_unit_test的定义. 它将成为自定义初始化函数. 默认的测试运行器会用它来初始化测试模块.

示例: 使用自定义初始化函数

代码

 
#define BOOST_TEST_ALTERNATIVE_INIT_API
#include <boost/test/included/unit_test.hpp>
#include <iostream>

BOOST_AUTO_TEST_CASE(test1)
{
  BOOST_TEST(false);
}

bool init_unit_test()
{
  std::cout << "using custom init" << std::endl;
  return true;
}

输出

 
> custom_init
using custom init
Running 1 test case...
test.cpp(7): error: in "test1": check false has failed

*** 1 failure is detected in the test module "Master Test Suite"
注释

由于我们覆盖了默认初始化函数, 它不再为主测试套件指定任何名称. 因此将使用默认名称("Master Test Suite").

用于报告初始化期间可能发生的错误,

  • 要么你返回false(仅对新 API 有效, 见BOOST_TEST_ALTERNATIVE_INIT_API)
  • 要么你抛出一个异常, 例如std::runtime_error或boost::unit_test::framework::setup_error

在该函数中报告的错误会中止测试模块的执行.

注释

定义BOOST_TEST_ALTERNATIVE_INIT_API的原因在此处说明.
