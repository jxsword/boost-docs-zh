使用变体

单元测试框架支持三种不同的使用变体:

  1. 仅头文件变体
  2. 静态库变体
  3. 共享库变体

多数情况下, 选择使用哪一种不应成为难题, 因为对每种都有明确的偏好理由. 以下各节可帮助你做决定.

仅头文件使用变体

如果你希望避免编译独立库, 应使用单元测试框架的仅头文件变体. 该变体只要求你包含唯一的头文件: #include <boost/test/included/unit_test.hpp>, 无需链接任何库. 初始化有几种方式, 最简单的方式如下:

#define BOOST_TEST_MODULE test module name
#include <boost/test/included/unit_test.hpp> /* path is different than the other variants! */

宏BOOST_TEST_MODULE需要在包含之前先定义, 并应指明测试模块的名称. 该名称可以包含空格, 且无需用引号包裹.

本节给出了如何定制该使用变体的更多细节. 特别是, 该变体可以配合多个编译单元使用, 见多翻译单元的仅头文件用法一节的说明.

静态库使用变体

对多数能获取预构建静态库[1](属于单元测试框架)或能自行构建它的用户来说, 以下用法可能是最通用且最简单的方式. 该使用变体包含两个步骤.

  1. 首先, 需要把以下行添加到测试模块的所有翻译单元:

    #include <boost/test/unit_test.hpp>

    有且仅有一个翻译单元应包含以下行:

    #define BOOST_TEST_MODULE test module name
#include <boost/test/unit_test.hpp>

    宏BOOST_TEST_MODULE需要在包含之前先定义, 并应指明测试模块的名称. 该名称可以包含空格, 且无需用引号包裹.

  2. 第二步是与单元测试框架的静态库链接.
注释

头文件<boost/test/unit_test.hpp>是一个聚合头文件: 它包含含有单元测试框架定义的大多数其他头文件.

该使用变体的缺点是, 遵循此变体的每个测试模块都会与单元测试框架静态链接, 这可能是你想避免的(例如为了节省空间). 关于这些配置选项的更多信息见本节.

共享库使用变体

在包含大量测试模块的工程中, 单元测试框架的静态库变体可能让你浪费大量磁盘空间. 解决方案是把测试模块与构建为共享库的单元测试框架动态链接. 该使用变体包含两个步骤.

  1. 首先你需要把以下行添加到测试模块的所有翻译单元:

    #define BOOST_TEST_DYN_LINK
#include <boost/test/unit_test.hpp>

    且有且仅有一个翻译单元应包含以下行

    #define BOOST_TEST_MODULE test module name
#define BOOST_TEST_DYN_LINK
#include <boost/test/unit_test.hpp>

    宏BOOST_TEST_MODULE和BOOST_TEST_DYN_LINK需要在包含之前先定义. BOOST_TEST_MODULE应设为测试模块名. 该名称可以包含空格, 且无需用引号包裹.

  2. 第二步是与单元测试框架的共享库链接.

该使用变体的缺点是, 你需要确保测试模块在运行期能够访问单元测试框架共享库.

此外, 共享库使用变体支持自定义测试运行器. 更多信息见本节.

注意

在 Windows 上, 测试模块与单元测试框架共享库应链接到相同的 CRT. 不这样做(例如单元测试框架共享库为release模式而测试模块为debug模式)会导致崩溃.
