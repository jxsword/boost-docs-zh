集合比较

除了把一个值与另一个值比较之外, 常常还需要比较值的集合. 一个集合以及间接包含的值可以从多个角度看待:

  • 集合作为值的序列: 例如N值存储在容器中时就属于这种情况. 此时容器用于存储多个值, 对容器的迭代产生可逐元素比较的序列. 为了能够比较序列, 迭代应按先验已知的顺序进行[10]. 集合中的值彼此独立, 子集也可以参与比较.
  • 集合作为整体: 此时集合的元素定义一个实体, 任何元素都不能与其他元素分离. 例如自然语言中特定单词的字母集合; 在这种设定下, 单词/集合中的任何字符都在语义上依赖其他字符, 若取出子集就会破坏单词的含义. 另一个例子是大小为N、表示N维空间中一个点的向量, 用关系"<"与另一个点比较: 这种比较是应用特定的, 一种可能的比较是字典序[11].

可以得出以下观察:

  • 比较集合时应根据集合的含义恰当选择所用的方法,
  • 以逐元素方式比较序列常常需要在测试主体中编写循环; 如果已有专用工具, 测试主体将在清晰度和表达力上获益(包括失败时的报告),
  • 某些比较方法(如字典序)具有良好的一般行为(例如全序、为不同大小的集合定义), 但有时并不合适.

BOOST_TEST为比较集合提供了专用工具:

  • 使用集合容器的原生 [12]运算符, 即默认行为所述,
  • 使用提供扩展失败诊断的逐元素比较,
  • 以及使用提供扩展失败诊断的字典序比较,

关于单元测试框架中集合概念的更多细节在此处给出.

默认比较

默认比较会分派到已有的重载比较运算符. 单元测试框架区分两种用例

  1. 比较操作数都不是 C 数组, 此时使用容器默认行为
  2. 其中一个比较操作数是 C 数组, 此时我们模仿 std::vector的行为
容器默认行为

给定两个不是 C 数组的容器c_a和c_b,

BOOST_TEST(c_a op c_b)

就测试成败而言等价于

auto result = c_a op c_b;
BOOST_TEST(result);

在下面的示例中, operator==未对不同类型的std::vector定义, 若取消相应行的注释, 程序将无法编译(std::vector默认使用字典序比较).

注释

在默认比较的情况下, 单元测试框架不提供额外的诊断. 见下文BOOST_TEST_SPECIALIZED_COLLECTION_COMPARE一节.

示例: BOOST_TEST 容器比较默认

代码

 
#define BOOST_TEST_MODULE boost_test_sequence
#include <boost/test/included/unit_test.hpp>
#include <vector>

BOOST_AUTO_TEST_CASE( test_collections_vectors )
{
  std::vector<int> a{1,2,3}, c{1,5,3,4};
  std::vector<long> b{1,5,3};

  // the following does not compile
  //BOOST_TEST(a == b);
  //BOOST_TEST(a <= b);

  // stl defaults to lexicographical comparison
  BOOST_TEST(a < c);
  BOOST_TEST(a >= c);
  BOOST_TEST(a != c);
}

C 数组默认行为

一旦其中某个操作数是 C 数组, 就不存在单元测试框架可以分派的默认行为. 这就是在这种情况下比较会模仿std::vector行为的原因.

示例: BOOST_TEST C 数组

代码

 
#define BOOST_TEST_MODULE boost_test_containers_c_arrays
#include <boost/test/included/unit_test.hpp>
#include <vector>

namespace tt = boost::test_tools;

BOOST_AUTO_TEST_CASE( test_collections_on_c_arrays )
{
  int a[] = {1, 2, 3};
  int b[] = {1, 5, 3, 4};
  std::vector<long> c{1, 5, 3, 4};
  BOOST_TEST(a == a); // element-wise compare
  BOOST_TEST(a == b); // element-wise compare
  BOOST_TEST(a != b);
  BOOST_TEST(a < b); // lexicographical compare
  BOOST_TEST(b < c); // lexicographical compare
  BOOST_TEST(c < a); // lexicographical compare
}

逐元素比较

通过指定操纵器boost::test_tools::per_element, 容器元素的比较会按容器前向迭代器给出的顺序逐元素进行. 这是对容器生成的元素序列的比较, 单元测试框架为其提供高级诊断.

更详细地, 设c_a = (a_1,... a_n)和c_b = (b_1,... b_n)为两个长度相同但不一定类型相同的序列. 这些序列对应各容器按其迭代器顺序给出的内容. 设op为某个二元比较运算符.

BOOST_TEST(c_a op c_b, boost::test_tools::per_element() );

等价于

if(c_a.size() == c_b.size())
{
  for(int i=0; i < c_a.size(); i++)
  {
    BOOST_TEST_CONTEXT("index " << i)
    {
      BOOST_TEST(a_i op b_i);
    }
  }
}
else
{
  BOOST_TEST(c_a.size() == c_b.size());
}
警告

这与使用容器默认比较运算符(默认行为)有本质区别.

警告

这不是容器上的序关系. 副作用是, 有可能出现

BOOST_TEST(c_a == c_b)

以及

BOOST_TEST(c_a != c_b)

同时失败

序列使用指定的运算符op进行比较, 对各序列的左右元素求值. 被比较元素的顺序由各容器的迭代器给出[13]. 失败时, 返回不满足op的元素的索引.

示例: BOOST_TEST 序列比较

代码

 
#define BOOST_TEST_MODULE boost_test_sequence_per_element
#include <boost/test/included/unit_test.hpp>
#include <vector>
#include <list>
namespace tt = boost::test_tools;

BOOST_AUTO_TEST_CASE( test_sequence_per_element )
{
  std::vector<int> a{1,2,3};
  std::vector<long> b{1,5,3};
  std::list<short> c{1,5,3,4};

  BOOST_TEST(a == b, tt::per_element()); // nok: a[1] != b[1]

  BOOST_TEST(a != b, tt::per_element()); // nok: a[0] == b[0] ...
  BOOST_TEST(a <= b, tt::per_element()); // ok
  BOOST_TEST(b  < c, tt::per_element()); // nok: size mismatch
  BOOST_TEST(b >= c, tt::per_element()); // nok: size mismatch
  BOOST_TEST(b != c, tt::per_element()); // nok: size mismatch
}

BOOST_AUTO_TEST_CASE( test_compare_c_arrays_element_wise )
{
  int a[] = {1, 2, 3};
  int b[] = {1, 5, 3};
  std::vector<long> c{1, 5, 3};
  BOOST_TEST(a == b, boost::test_tools::per_element());
  BOOST_TEST(a != b, boost::test_tools::per_element());
  BOOST_TEST(a < b, boost::test_tools::per_element());
  BOOST_TEST(b < c, boost::test_tools::per_element());
  BOOST_TEST(c < a, boost::test_tools::per_element());
}

要求

要使序列可以逐元素比较, 应满足以下条件:

  • 容器应满足序列定义,
  • 容器应产生相同数量的元素,
  • op应为比较运算符==、!=、<、<=、>、>=之一
  • 应定义a_i op b_i, 其中a_i和b_i的类型是各集合解引用运算符返回的类型.
注意

"c_a == c_b"的结果类型是一个assertion_result: 无法在BOOST_TEST语句上再叠加多个比较:

BOOST_TEST(c_a == c_b == 42, boost::test_tools::per_element() ); // does not compile

字典序比较

通过指定操纵器boost::test_tools::lexicographic, 容器将按字典序进行比较, 单元测试框架在失败时为其提供附加诊断.

BOOST_TEST(c_a op c_b, boost::test_tools::lexicographic() );

比较按容器前向迭代器给出的顺序进行.

提示

字典序比较在容器上产生全序: 语句c_a < c_b与c_b <= c_a互斥.

注释

相等==与不等!=不可用于这类比较.

示例: 使用字典序的 BOOST_TEST 容器比较

代码

 
#define BOOST_TEST_MODULE boost_test_container_lex
#include <boost/test/included/unit_test.hpp>
#include <vector>

namespace tt = boost::test_tools;

BOOST_AUTO_TEST_CASE( test_collections_vectors_lex )
{
  std::vector<int> a{1,2,3}, b{1,2,2}, c{1,2,3,4};

  BOOST_TEST(a < a, tt::lexicographic());
  BOOST_TEST(a < b, tt::lexicographic());
  BOOST_TEST(a < c, tt::lexicographic());
  BOOST_TEST(a >= c, tt::lexicographic());

  //BOOST_TEST(a == c, tt::lexicographic()); // does not compile
  //BOOST_TEST(a != c, tt::lexicographic()); // does not compile
}

BOOST_AUTO_TEST_CASE( test_compare_c_arrays_lexicographic )
{
  int a[] = {1, 2, 3};
  int b[] = {1, 5, 3};
  std::vector<long> c{1, 5, 3};
  // BOOST_TEST(a == b, boost::test_tools::lexicographic()); // does not compile
  // BOOST_TEST(a != b, boost::test_tools::lexicographic()); // does not compile
  BOOST_TEST(a < b, boost::test_tools::lexicographic());
  BOOST_TEST(b < c, boost::test_tools::lexicographic());
  BOOST_TEST(c < a, boost::test_tools::lexicographic());
}

特定容器的默认扩展诊断

如上所见,

  • 测试相等时, ==关系要么是显式的(使用boost::test_tools::per_element()), 要么是隐式的(当容器重载/实现了这类比较时),
  • 测试不等时, <(及其派生操作)的字典序比较要么是显式的(使用boost::test_tools::lexicographic()), 要么是隐式的(当容器重载/实现了这类比较时).

当默认使用容器实现时, 无法享受扩展失败诊断. 单元测试框架提供了一种机制, 经由单元测试框架而非容器运算符执行同样的比较, 所用宏为BOOST_TEST_SPECIALIZED_COLLECTION_COMPARE, 用法如下:

示例: 默认std::vector<int>到带扩展诊断的字典序

代码

 
#define BOOST_TEST_MODULE boost_test_container_lex_default
#include <boost/test/included/unit_test.hpp>
#include <vector>

namespace tt = boost::test_tools;

BOOST_TEST_SPECIALIZED_COLLECTION_COMPARE(std::vector<int>)

BOOST_AUTO_TEST_CASE( test_collections_vectors_lex )
{
  std::vector<int> a{1,2,3}, b{1,2,2};
  std::vector<long int> c{1,2,3,5}, d{1,2,3,4};

  BOOST_TEST(a < a); // lexcographic
  BOOST_TEST(a < b); // lexcographic
  BOOST_TEST(a == b); // element-wise
  BOOST_TEST(a != b); // extended diagnostic
  BOOST_TEST(c < d); // no extended diagnostic
  BOOST_TEST(c == d); // no extended diagnostic
}

什么是序列?

序列由对前向可迭代容器的迭代给出. 前向可迭代容器是:

  • C 数组, 或
  • 或是一个class/struct, 并实现成员函数begin和end.

对于集合比较, 两个序列还要求不同于string序列. 在这种情况下, 序列会被分派到字符串比较.

警告

string(或wstring)按定义满足序列概念, 但它们用BOOST_TEST的处理方式不同. 更多细节见字符串与 C 字符串比较.

提示

如果BOOST_TEST的行为不符合预期, 你总是可以使用原始比较. 细节见本节.

注释

自Boost.Test 3.6(Boost 1.65)起, 集合概念的要求已放宽, 也包括 C 数组

注释

自Boost.Test 3.7(Boost 1.67)起, 不再要求集合类型中定义const_iterator和value_type(对正确支持decltype的编译器).

检测满足这些要求的容器类型的工作委托给了类boost::unit_test::is_forward_iterable, 它在 C++11 下检测所需的成员函数和字段. 但对 C++03, 提供序列的类型应通过单元测试框架的boost::unit_test::is_forward_iterable特化[14]显式指出.


[10] 例如std::unordered_map可能不满足这一点, 其桶可能依插入顺序不同而被不同地填充.

[11] 此时v_a < v_b表示点v_a位于矩形(原点, v_b)之内

[12] 由容器定义或由用户定义

[13] 对容器所包含的固定元素集合, 容器应产生相同的序列

[14] STL的标准容器被识别为前向可迭代容器.
