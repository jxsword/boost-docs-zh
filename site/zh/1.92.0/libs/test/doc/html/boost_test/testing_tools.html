编写测试的 API 汇总

测试用例声明之后, 就应编写该测试的主体. 测试用例是一个操作序列, 其中插入断言. 这些断言对实现待验证期望的语句求值, 并根据日志级别以统一的方式报告失败和/或信息.

单元测试框架提供了一套断言工具箱, 以简化测试用例的创建与维护, 并提供统一的错误报告机制. 该工具箱大部分以宏声明的形式提供. 由宏BOOST_TEST为它们全部实现了一个(近乎)统一的接口.

注释

所有宏参数只计算一次, 因此可以放心地在参数位置传入复杂表达式.

所有工具都会自动提供错误位置: 文件名和行号, 而且这两者都可以被覆盖.

注意

测试工具面向单元测试代码而非库或生产代码; 在库或生产代码中, 抛出异常、使用assert()、boost::concept_check或BOOST_STATIC_ASSERT()可能是检测和报告错误的更合适方式.
