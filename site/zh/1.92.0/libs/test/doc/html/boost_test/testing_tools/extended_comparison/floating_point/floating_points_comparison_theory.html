浮点比较背后的理论

比较两个浮点值u和v在给定绝对容差epsilon下是否接近, 最显然的方式如下:

abs(u - v) <= epsilon; // (1)

然而在许多情形下, 这并非我们想要的. 同一绝对容差值0.01可能太小而无法有意义地比较数量级为10e12的两个值, 同时又太小而无法有意义地比较数量级为10e-12的值. 示例见Squassabia.

我们不想对巨大和微小的数字应用同样的绝对容差. 相反, 我们希望把epsilon用u和v进行缩放. 单元测试框架实现的浮点比较算法基于Knuth给出的方案:

   abs(u - v) <= epsilon * abs(u)
&& abs(u - v) <= epsilon * abs(v)); // (2)

定义了容差下非常接近 epsilon的关系, 存在于u与v之间, 而

   abs(u - v) <= epsilon * abs(u)
|| abs(u - v) <= epsilon * abs(v); // (3)

定义了容差下足够接近 epsilon的关系, 存在于u与v之间.

两种关系都满足交换律但不可传递. (2)定义的关系强于(3)定义的关系, 因为(2)必然蕴含(3).

不等式右侧的乘法可能引发不期望的下溢. 为避免这一点, 实现使用(2)和(3)的修改版本, 对被检查的差值而非epsilon进行缩放:

   abs(u - v)/abs(u) <= epsilon
&& abs(u - v)/abs(v) <= epsilon; // (4)

   abs(u - v)/abs(u) <= epsilon
|| abs(u - v)/abs(v) <= epsilon; // (5)

这样所有下溢和上溢情形都可以安全防范. 但当v或u为零时上述方法不可用. 此时解决办法是采用其他算法, 例如(1).

容差选择的考量

在没有领域特定要求的情况下, 容差值可以选为被比较值的"相对舍入误差"预测上限之和. "舍入"是把实数值 'x' 用 'p' 个二进制位(比特)的浮点格式表示为浮点值X的操作. "相对舍入误差"是实数值与浮点值之差相对实数值的比值: abs(x-X)/abs(x). 实数值与浮点值之间的偏差可能由以下原因造成:

  • 类型提升
  • 算术运算
  • 从十进制表示到二进制表示的转换
  • 非算术运算

前两类运算已被证明其相对舍入误差不超过

half_epsilon = half of the 'machine epsilon value'

对于相应的浮点类型FPT [9]. 遗憾的是, 到二进制表示的转换没有这样的要求. 因此我们不能假设float(1.1)接近实数1.1(以 float 的容差half_epsilon)(尽管对 11./10 我们可以这样假设). 非算术运算要么没有预测的相对舍入误差上限.

注释

注意, 算术运算和非算术运算都可能产生其他"非舍入"错误, 如下溢/上溢、除零或"运算错误".

所有关于舍入误差上限的定理, 包括half_epsilon的定理, 都只针对"舍入"运算, 别无其他. 这意味着"运算错误", 即运算本身在舍入之外引入的误差, 未被考虑. 为了让数值软件能够实际预测误差界, IEEE754标准要求算术运算"正确或精确舍入". 即, 要求给定运算的内部计算使得浮点结果是舍入到工作位数的确切结果. 换言之, 要求运算本身使用的计算不引入任何额外误差. IEEE754标准并不要求大多数非算术运算具有同样的行为. 下溢/上溢和除零错误可能导致舍入误差的上限不可预测.

最后要注意, half_epsilon规则不具有传递性. 换言之, 两个算术运算的组合可能产生显著超过2*half_epsilon的舍入误差. 总之, 关于如何选择容差没有通用规则, 用户需要运用常识和领域/问题特定知识来决定容差值.

为简化多数使用场景, 下面的算法最新版本选择使用百分比值来指定容差(而非相关值的分数). 换言之, 现在你用它检查两个值之差不超过百分之 x.
