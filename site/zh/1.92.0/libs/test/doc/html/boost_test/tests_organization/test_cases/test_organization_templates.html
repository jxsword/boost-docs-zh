模板测试用例

要测试基于模板的组件, 经常需要针对用不同模板参数实例化的组件执行同一组检查.

对用不同模板参数实例化的组件执行同一组检查的一种方式是:

template <typename T>
void single_test()
{
  BOOST_CHECK( /* test assertion */ );
}

void combined_test()
{
  single_test<int>();
  single_test<float>();
  single_test<unsigned char>();
}

上述做法存在若干问题/不便, 包括:

  • 某次调用中的致命错误会停止整个测试用例, 并跳过对其他类型的调用
  • 你需要为所有感兴趣的参数手动重复函数调用
  • 你需要两个函数来实现该测试

单元测试框架提供了一种设施, 即模板测试用例, 用于基于期望类型列表和无参函数创建一系列测试用例. 该设施同时提供自动与手动注册接口.

提示

测试用例模板设施优于上面示例中的做法, 因为每个子测试用例的执行都受单独保护和计数. 它产生更好的测试日志/结果报告(上例中一旦失败, 你无法说出是哪个类型出的问题), 并且即使其中一个类型导致子测试用例终止, 你仍能对所有类型完成测试.

带自动注册的模板测试用例

自动注册且在实现处注册的模板测试用例, 通过宏BOOST_AUTO_TEST_CASE_TEMPLATE声明:

BOOST_AUTO_TEST_CASE_TEMPLATE(test_case_name, formal_type_parameter_name, collection_of_types);

参数如下:

  1. test_case_name: 测试用例模板名: 唯一的测试用例模板标识符
  2. formal_type_parameter_name: 形式模板参数的名称: 测试用例模板以其进行实例化的类型的名称
  3. collection_of_types: 用于实例化测试用例模板的类型集合. 这是一个任意 MPL 序列, 或包裹在std::tuple中的类型序列(自单元测试框架 v3.7起, 若编译器支持)

测试的最终名称是test_case_name参数与当前被测类型的组合. 自单元测试框架 v3.12起, 框架会尝试统一结果类型在各平台上的名称, 使它们更易于从命令行过滤器引用.

示例: 带自动注册的测试用例模板

代码

 
#define BOOST_TEST_MODULE example
#include <boost/test/included/unit_test.hpp>
#include <boost/mpl/list.hpp>

typedef boost::mpl::list<int,long,unsigned char> test_types;

BOOST_AUTO_TEST_CASE_TEMPLATE( my_test, T, test_types )
{
  BOOST_TEST( sizeof(T) == (unsigned)4 );
}

typedef std::tuple<int, long, unsigned char> test_types_w_tuples;

BOOST_AUTO_TEST_CASE_TEMPLATE( my_tuple_test, T, test_types_w_tuples )
{
  BOOST_TEST( sizeof(T) == (unsigned)4 );
}

输出

 
> example
Running 3 test cases...
test.cpp(17): error: in "my_test<unsigned char>": check sizeof(T) == (unsigned)4 has failed [1 != 4]

*** 1 failure is detected in the test module "example"
警告

自单元测试框架 v3.7起, 单元测试框架不允许同一测试套件下出现重名测试用例. 由于测试名从collection_of_types中的类型派生, 这间接意味着出现重复类型(于collection_of_types中)将导致错误.

注释

如果你更希望把模板参数列表直接放在BOOST_AUTO_TEST_CASE_TEMPLATE的声明中, 可以使用宏BOOST_IDENTITY_TYPE. 前面的示例变成(注意 MPL 列表两侧的双层括号):

#include <boost/utility/identity_type.hpp>

BOOST_AUTO_TEST_CASE_TEMPLATE(
  my_test,
  T,
  BOOST_IDENTITY_TYPE((boost::mpl::list<
    int,
    long,
    unsigned char
  >)) )
{
  BOOST_TEST( sizeof(T) == (unsigned)4 );
}
带手动注册的模板测试用例

要手动注册模板测试用例, 需要两个宏:

  • BOOST_TEST_CASE_TEMPLATE_FUNCTION用于定义模板测试用例主体
  • BOOST_TEST_CASE_TEMPLATE用于在先前声明的基础上注册测试用例

宏BOOST_TEST_CASE_TEMPLATE_FUNCTION需要两个参数:

  1. 测试用例模板的名称, 以及
  2. 形式类型参数的名称
BOOST_TEST_CASE_TEMPLATE_FUNCTION(test_case_name, type_name);

BOOST_TEST_CASE_TEMPLATE_FUNCTION( test_case_name, type_name )
{
  // test case template body
}

宏BOOST_TEST_CASE_TEMPLATE_FUNCTION应替代无参函数模板签名使用:

template <typename type_name>
void test_case_name()
{
  // test case template body
}

唯一的区别是BOOST_TEST_CASE_TEMPLATE_FUNCTION使测试用例模板名可在模板实参列表中使用.

BOOST_TEST_CASE_TEMPLATE需要两个参数:

  1. 测试用例模板的名称, 以及
  2. 用于实例化它的 Boost.MPL 兼容类型集合.

传给两个宏的名称应当相同.

BOOST_TEST_CASE_TEMPLATE(test_case_name, collection_of_types);
示例: 手动注册的测试用例模板

代码

 
#include <boost/test/included/unit_test.hpp>
#include <boost/mpl/list.hpp>
using namespace boost::unit_test;

BOOST_TEST_CASE_TEMPLATE_FUNCTION( my_test, T )
{
  BOOST_TEST( sizeof(T) == 4U );
}

test_suite* init_unit_test_suite( int /*argc*/, char* /*argv*/[] )
{
  typedef boost::mpl::list<int,long,unsigned char> test_types;

  framework::master_test_suite().
    add( BOOST_TEST_CASE_TEMPLATE( my_test, test_types ) );

  return 0;
}

输出

 
> example
Running 3 test cases...
test.cpp(15): error: in "my_test<unsigned char>": check sizeof(T) == 4U has failed [1 != 4]

*** 1 failure is detected in the test module "Master Test Suite"

BOOST_TEST_CASE_TEMPLATE创建测试用例生成器的一个实例. 当传给方法test_suite::add时, 生成器为所给类型集合中的每个类型产生一个单独的子测试用例, 并立即把它注册到测试套件. 每个测试用例基于以特定测试类型实例化的测试用例模板主体.

子测试用例的名称从宏参数test_case_name推导. 如果你希望指定不同的测试用例名, 需要改用底层的make_test_case接口. 测试用例的创建和注册都在测试模块初始化函数中执行.

警告

自单元测试框架 v3.7起, 单元测试框架不允许同一测试套件下出现重名测试用例. 由于测试名从collection_of_types中的类型派生, 这间接意味着collection_of_types中类型重复会导致错误.
