IDE 使用建议

这条建议以 Microsoft Visual Studio 为例展示, 但你可以在不同的 IDE 中采用类似步骤.

使用自定义构建步骤在编译后自动启动测试程序

我发现最方便的做法是把测试程序的执行作为编译的构建后(post-build)步骤. 为此请使用工程属性页:

"Command Line"字段所需的完整命令是:

"$(TargetDir)$(TargetName).exe" --result_code=no --report_level=no

注意报告级别和结果码都被抑制了. 这样, 该命令可能产生的唯一输出就是可能的运行期错误. 但最棒的是, 你可以像分析编译错误时那样, 用惯用的键盘快捷键/鼠标点击跳转到这些错误:

如果在测试用例内部某处发生了致命异常, 通过添加额外的命令行参数让调试器在失败点中断

如果你在运行测试时收到"内存访问违例"消息(或任何其他指示致命错误或系统错误的消息), 想获得更多关于错误位置的信息, 请向测试运行命令行添加

--catch_system_error=no

现在在调试器下再次运行测试, 它会在失败点中断.
