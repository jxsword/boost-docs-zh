术语表

以下是本文档中通篇使用的术语列表.

测试模块

这是执行测试的单个二进制文件. 物理上, 测试模块由一个或多个测试源文件组成, 可构建为可执行文件或动态库. 由单个测试源文件组成的测试模块称为单文件测试模块, 否则称为多文件测试模块. 逻辑上, 每个测试模块由四部分组成:

  1. 测试建立(或测试初始化),
  2. 测试主体
  3. 测试清理
  4. 测试运行器

测试运行器部分是可选的. 如果测试模块构建为可执行文件, 测试运行器是内置的. 如果测试模块构建为动态库, 则由外部测试运行器运行.

警告

测试模块应至少定义一个测试用例, 否则视为错误.

测试主体

这是测试模块中实际执行测试的部分. 逻辑上, 测试主体是包在测试用例中的测试断言的集合, 这些测试用例被组织成一棵测试树.

测试树

这是由测试套件(非叶节点)和测试用例(叶节点)构成的层次结构. 更多细节可在此处找到.

测试单元

这是指代测试套件或测试用例时的统称. 更多细节见本节.

测试断言

这是测试模块检查的单个二元条件(二元是指它有两个结果: 通过与失败).

关于一个测试用例应包含多少测试断言, 存在不同流派. 两个极端立场分别是 TDD 追随者主张的"每个测试用例一个断言", 以及与此相反的"单个测试用例包含全部测试断言"(为只关心测试模块中第一个错误的人所主张). 单元测试框架同时支持这两种方式.

测试用例

这是测试模块内被独立监视的函数, 由一个或多个测试断言组成. 上述定义中的独立监视一词强调了这样一个事实: 所有测试用例都被独立监视. 未捕获的异常或其他正常的测试用例执行终止都不会导致测试停止. 相反, 错误会被测试用例执行监视器捕获, 由单元测试框架报告, 测试继续进行到下一个测试用例. 稍后你会看到, 这正是偏好多个小测试用例而非单个大测试函数的主要原因之一.

测试套件

这是一个容纳一个或多个测试用例的容器. 测试套件让你能把测试用例分组为单个可引用的实体. 你可能出于多种原因选择这样做, 包括:

  • 按被测单元的子系统对测试用例分组.
  • 共享测试用例的建立/清理代码.
  • 只运行选定的测试用例组.
  • 查看按测试用例组拆分的测试报告.
  • 依据测试树中另一个测试单元的结果跳过测试用例组.

测试套件还可以包含其他测试套件, 从而形成层次化的测试树结构. 单元测试框架要求测试树至少包含一个测试套件, 且该套件至少包含一个测试用例. 顶层测试套件 - 测试树的根节点 - 称为主测试套件.

测试建立

这是测试模块中负责测试准备的部分. 它包括在测试开始之前发生的以下操作:

  • 单元测试框架的初始化
  • 测试树的构建
  • 全局测试模块建立(setup)代码
  • 逐测试用例的建立代码会为它所归属的每个测试用例调用, 也被归入测试初始化, 尽管它作为测试用例的一部分执行.

测试清理

这是测试模块中负责清理操作的部分.

测试夹具

相互匹配的建立与清理操作经常被合并成一个称为测试夹具(test fixture)的单一实体.

测试运行器

这是一个编排器或驱动器, 给定测试树后, 它确保测试树被初始化、测试被执行并生成必要的报告. 更多信息见此处.

测试日志

这是测试期间发生的所有事件的记录.

测试报告

这是测试完成后由单元测试框架生成的报告, 指明哪些测试用例/测试套件通过、哪些失败.
