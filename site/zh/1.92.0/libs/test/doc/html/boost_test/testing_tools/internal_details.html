BOOST_TEST: 表达式细节

让我们考虑以下示例:

示例: BOOST_TEST 报告

代码

 
#define BOOST_TEST_MODULE boost_test_macro3
#include <boost/test/included/unit_test.hpp>

BOOST_AUTO_TEST_CASE( test_op_reportings )
{
  int a = 13, b = 12;
  BOOST_TEST(a == b);
  BOOST_TEST(a < b);
  BOOST_TEST(a - 1 < b);
  BOOST_TEST(b > a - 1);
}

输出

 
> ./boost_test_macro3 --log_level=all
Running 1 test case...
Entering test module "boost_test_macro3"
test.cpp(12): Entering test case "test_op_reportings"
test.cpp(15): error: in "test_op_reportings": check a == b has failed [13 != 12]
test.cpp(16): error: in "test_op_reportings": check a < b has failed [13 >= 12]
test.cpp(17): error: in "test_op_reportings": check a - 1 < b has failed [13 - 1 >= 12]
test.cpp(18): error: in "test_op_reportings": check b > a - 1 has failed [12 <= 12]
test.cpp(12): Leaving test case "test_op_reportings"; testing time: 484us
Leaving test module "boost_test_macro3"; testing time: 588us

*** 2 failures are detected in the test module "boost_test_macro3"

前面已经提到, 报告是不对称的(见此处). 表达式由statement构造, 它出现在BOOST_TEST宏中. 该表达式允许诸如"13 - 1 >= 12" failed的求值和报告, 同时带有statement的副本, 其中包含比"a - 1 < b" failed更多的细节. 具体而言, 发生的事情如下:

  1. 一个特殊对象, 即表达式的seed, 由statement的左侧组合而成. 这一初始组合相对受支持的操作具有最高优先级. 下面的表达式:

    a op1 b op2 c op3 d

    实际上被看作

    ( seed a ) op1 b op2 c op3 d

  2. "seed a"返回一个expression对象, 该对象跟踪a的类型. 该表达式为从左到右的结合性提供了重载, 操作op1、op2等被链式接在该表达式对象的右侧:

    a op1 b

    产生如下伪代码

    expression1 = create-expression(a)
expression2 = create-expression(expression1, op1, b)

    expression1和expression2会记录其左右操作数以及对这些操作数执行的操作. 表达式还会记录关联子表达式的结果类型. 在上面的示例中, expression1和expression2的结果类型分别为decltype(a)和decltype(a op1 b). 结果类型允许链接子表达式.

  3. C++ 运算符优先级规则在任何情况下都适用. 表达式所能看到的是从左到右组合可达的内容. 在到达表达式右操作数之前发生的任何其他操作都不会被解析为子表达式, 而是被视为单一操作数: 右操作数不会被框架进一步展开. 假设下面的op2优先级高于op1, 那么

    a op1 b op2 c

    等价于:

    create-expression(create-expression(a), op1, (b op2 c))

    在上面的语句中, 最终表达式只能看到其右侧(b op2 c)的结果, 日志中无法为其提供进一步细节. 对从右到左结合的运算符, 例如!、~、-(一元取负)等, 也是如此.

    注意

    由于expression对象是从左到右组合而成的, 它实际观察到的是一条操作链, 而不是完整的表达式树.

  4. 完整的表达式链构建完成后, 它会按照与上述组合规则完全一致的方式, 作为从左到右的子表达式链求值. 被求值的元素是表达式本身的元素. 表达式

    a op1 b

    产生如下求值链:

    expression2.result = expression1.result op1 b
expression1.result = a

    语句的最终表达式被转换为布尔值, 后者再由单元测试框架求值.

下面的示例展示了从左到右链式表达式的构建过程.

示例: BOOST_TEST 复合语句

代码

 
#define BOOST_TEST_MODULE boost_test_macro2
#include <boost/test/included/unit_test.hpp>

BOOST_AUTO_TEST_CASE( test_op_precedence )
{
  int a = 13, b = 2, c = 12;
  // left term of == is expanded in the logs
  BOOST_TEST(a % b == c);
  // right term of == is not expanded in the logs
  BOOST_TEST(a == c % b);
}

BOOST_AUTO_TEST_CASE( test_op_right_associative )
{
  int a = 1;
  BOOST_TEST(a);
  BOOST_TEST(!a);
  BOOST_TEST(--a);
}
