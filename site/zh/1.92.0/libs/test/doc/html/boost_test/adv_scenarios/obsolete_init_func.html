已过时的初始化函数

为了向后兼容, 单元测试框架还允许定制另一种类型的初始化函数. 这称为已过时的初始化函数. 其签名如下:

boost::unit_test::test_suite* init_unit_test_suite(int argc, char* argv[]);

单元测试框架最初的设计要求程序员自行实现它. 其用途是完成初始化并返回主测试套件. 当时还不提供测试用例自动注册. 空指针值被视为初始化错误.

在仅头文件使用变体中, 只要在测试模块代码中省略宏BOOST_TEST_ALTERNATIVE_INIT_API的定义, 就会退回使用已过时的初始化函数签名.

示例: 使用已过时的初始化函数

代码

 
#include <boost/test/included/unit_test.hpp>
#include <iostream>

BOOST_AUTO_TEST_CASE(test1)
{
  BOOST_TEST(false);
}

boost::unit_test::test_suite* init_unit_test_suite(int /*argc*/, char* /*argv*/[])
{
  std::cout << "using obsolete init" << std::endl;
  return 0;
}

输出

 
> custom_obsolete_init
using obsolete init
Running 1 test case...
test.cpp(6): error: in "test1": check false has failed

*** 1 failure is detected in the test module "Master Test Suite"

在静态库使用变体中, 你需要在测试模块中省略宏BOOST_TEST_ALTERNATIVE_INIT_API的定义, 并在编译单元测试框架静态库时不带编译标志BOOST_TEST_ALTERNATIVE_INIT_API(这是默认情形).

在共享库使用变体中, 无法使用已过时的初始化函数.

即使你决定使用已过时的初始化函数, 也建议遵循以下做法:

  1. 始终返回空指针值, 并通过test_suite::add安装主测试套件, 如此处所示. 当前框架不再把空指针值视为失败.
  2. 通过抛出boost::unit_test::framework::setup_error异常来报告失败.
  3. 通过主测试套件的接口访问命令行参数, 而忽略函数参数argc和argv.
注意

正如其名所示, 已过时的初始化函数已被弃用. 建议迁移到新 API, 并依靠测试单元自动注册以及夹具(包括全局夹具)来完成其他设置工作.
