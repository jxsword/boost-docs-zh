开始开发新库/类/程序时, 你要做的第一件事是什么? 没错 - 你需要从单元测试模块开始(希望大家都给出了这个答案!). 偶尔, 用若干assert实现简单测试也能应付, 但任何专业开发者很快就会发现这种方式有所欠缺. 对于简单但重复的单元测试任务, 它过于耗时和乏味; 对于多数非平凡任务, 它又过于僵化.

Boost.Test 库提供了一套既易用又灵活的接口, 用于编写测试程序、把测试组织成简单的测试用例和测试套件, 以及控制它们的运行期执行. Boost.Test 的某些接口在生产(非测试)环境中同样有用.

入门示例

一个最小的单文件测试程序如下所示:

#define BOOST_TEST_MODULE My Test 
#include <boost/test/included/unit_test.hpp> 

BOOST_AUTO_TEST_CASE(first_test) 
{
  int i = 1;
  BOOST_TEST(i); 
  BOOST_TEST(i == 2); 
}

宏BOOST_TEST_MODULE定义我们程序的名字, 该名字将用于消息中.

这会以"仅头文件"模式包含全部单元测试框架; 它甚至会定义函数main, 由后者调用随后定义的测试用例.

宏BOOST_AUTO_TEST_CASE声明一个测试用例, 名为first_test, 它进而会在受控测试环境中运行first_test的内容.

此测试检查i是否非零.

此测试检查i的值是否为2(而不只是对相等运算符求值).

运行时产生如下输出:

Running 1 test case...
test_file.cpp(8): error: in "first_test": check i == 2 has failed [1 != 2]

*** 1 failure is detected in the test module "My Test"
