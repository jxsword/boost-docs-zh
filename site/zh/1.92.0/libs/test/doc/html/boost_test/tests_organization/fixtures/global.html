全局夹具

任何需要在任何测试开始之前执行的全局初始化, 或需要在全部测试结束后执行的清理, 都称为全局夹具. 全局夹具等价于测试套件进入/退出夹具(只执行一次), 只不过此时测试套件是主测试套件.

单元测试框架的全局夹具设计基于通用测试类夹具模型. 全局夹具设计允许在构成测试模块的任何测试文件中定义任意数量的全局夹具. 虽然某些初始化可以在测试模块初始化函数中实现, 但有若干理由更倾向于全局夹具方式:

  • 初始化函数中没有用于cleanup/teardown操作的位置.
  • 与初始化函数不同, 全局夹具的构造、setup和teardown方法的调用受执行监视器保护. 这意味着初始化期间发生的所有未捕获错误都会被妥善报告.
  • 可以定义任意数量的不同全局夹具, 这允许你按类别拆分初始化代码.
  • 夹具允许你在测试模块代码中把匹配的setup/teardown代码放在彼此贴近的位置.
  • 如果整个测试树都是自动构建的, 初始化函数为空并由单元测试框架自动生成. 引入初始化函数可能比使用全局夹具设施要做更多工作, 而全局夹具更切题.
  • 由于所有夹具都遵循同一通用模型, 你可以轻松从局部的每测试用例夹具切换到全局夹具.

要定义全局测试模块夹具, 你需要:

  1. 实现一个符合夹具模型的类
  2. 并把该类作为参数传给宏BOOST_TEST_GLOBAL_FIXTURE.
BOOST_TEST_GLOBAL_FIXTURE( fixture_name );

// if your fixture is within a namespace
namespace enclosing_namespace {
  struct fixture_in_namespace { /* ... */ };
}

namespace enclosing_namespace {
  BOOST_TEST_GLOBAL_FIXTURE( fixture_in_namespace );
}
注意

定义全局夹具的语句必须驻留在单个编译单元中(不能放头文件).

注意

当心其他编译单元中同名的其他夹具: 如果夹具定义不同, 会导致 ODR 违规.

示例: 全局夹具

代码

 
#define BOOST_TEST_MODULE fixture_04
#include <boost/test/included/unit_test.hpp>

struct MyGlobalFixture {
  MyGlobalFixture() {
      BOOST_TEST_MESSAGE( "ctor fixture i=" << i );
  }
  void setup() {
      BOOST_TEST_MESSAGE( "setup fixture i=" << i );
      i++;
  }
  void teardown() {
      BOOST_TEST_MESSAGE( "teardown fixture i=" << i );
      i += 2;
  }
  ~MyGlobalFixture() {
      BOOST_TEST_MESSAGE( "dtor fixture i=" << i );
  }
  static int i;
};
int MyGlobalFixture::i = 0;

BOOST_TEST_GLOBAL_FIXTURE( MyGlobalFixture );

BOOST_AUTO_TEST_CASE(test_case1)
{
  BOOST_TEST_MESSAGE("running test_case1");
  BOOST_TEST(MyGlobalFixture::i == 1);
}

BOOST_AUTO_TEST_CASE(test_case2)
{
  BOOST_TEST_MESSAGE("running test_case2");
  BOOST_TEST(MyGlobalFixture::i == 3);
}
