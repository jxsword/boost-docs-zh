预期失败规范

虽然在理想世界中, 为使测试模块通过, 所有测试断言都应当通过, 但某些情况下可能希望暂时允许特定测试失败. 例如, 某个特性尚未实现而又需要准备发布库, 或某个测试在某些平台上失败. 为避免回归测试表中不断出现的红色框, 可以使用预期失败特性.

该特性允许为每个测试单元指定期望的失败断言数量. 该值在测试树构建期间指定, 且无法在测试执行期间更新.

该特性并不打算用于检查预期的功能失败. 要检查某个特定输入是否导致异常被抛出, 请使用BOOST_<level>_THROW测试工具家族.

此特性的使用应有所节制, 且仅在深思熟虑后使用. 一般而言, 只有在必须让测试模块通过而又不实际修复问题时才应使用它. 显然, 过度使用预期失败会使单元测试失去意义. 大多数情况下只需临时应用.

还需要记住, 预期失败规范是针对每个测试用例的. 这意味着该测试用例内任何失败的断言都能满足预期失败配额. 也就是说, 可能发生一个意外失败恰好满足该配额的情形.

注释

如果出错的断言被修复并通过, 而预期失败规范仍然存在, 失败数量将小于预期. 测试会被报告为通过; 相反, 会发出一条警告消息.

预期失败规范

装饰器expected_failures定义对应测试单元内预期失败的断言数量. 当失败断言数大于声明的预期失败数时, 会报告为失败. 若失败断言数小于预期失败数, 则报告一条消息. 给定测试套件S的预期失败总数, 是S中声明的预期失败数与所有嵌套测试单元的预期失败数之和:

示例: 装饰器 expected_failures

代码

 
#define BOOST_TEST_MODULE decorator_10
#include <boost/test/included/unit_test.hpp>
namespace utf = boost::unit_test;

BOOST_AUTO_TEST_SUITE(suite1,
  * utf::expected_failures(1))

  BOOST_AUTO_TEST_CASE(test1,
    * utf::expected_failures(2))
  {
    BOOST_TEST(false);
    BOOST_TEST(false);
  }

  BOOST_AUTO_TEST_CASE(test2)
  {
    BOOST_TEST(false);
    BOOST_TEST(false);
  }

BOOST_AUTO_TEST_SUITE_END()

输出

 
> decorator_10
Running 2 test cases...
test.cpp(11): error: in "suite1/test1": check false has failed
test.cpp(12): error: in "suite1/test1": check false has failed
test.cpp(17): error: in "suite1/test2": check false has failed
test.cpp(18): error: in "suite1/test2": check false has failed

*** 4 failures are detected (3 failures are expected) in the test module "decorator_10"


> decorator_10 --run_test=suite1/test1
Running 1 test case...
test.cpp(11): error: in "suite1/test1": check false has failed
test.cpp(12): error: in "suite1/test1": check false has failed

*** No errors detected

在上面的示例中, 我们首先运行全部测试用例, 其中有四个失败断言. 预期失败总数为 3: 1(针对测试suite1)+ 2(针对test1). 由于超出了预期失败计数, 会报告错误. 在第二种情形中, 我们只运行测试用例suite1/test1: 发生两个失败, 预期两个失败, 因此不报告错误.

与自动注册测试用例配合使用

注意

这种用法被视为已弃用. 请考虑改用expected_failures装饰器.

为了向后兼容, 可以在测试用例定义之前用BOOST_AUTO_TEST_CASE_EXPECTED_FAILURES [15]指明预期失败.

BOOST_AUTO_TEST_CASE_EXPECTED_FAILURES(test_case_name, number_of_expected_failures);

你既可以在文件作用域也可以在测试套件内部使用该宏. 而且, 即使测试单元名称在不同测试套件中重名也可以使用. 预期失败规范适用于与BOOST_AUTO_TEST_CASE_EXPECTED_FAILURES同属一个测试套件的测试单元.

示例: 自动注册测试用例的预期失败规范

代码

 
#define BOOST_TEST_MODULE example
#include <boost/test/included/unit_test.hpp>

BOOST_AUTO_TEST_CASE_EXPECTED_FAILURES( my_test1, 1 )

BOOST_AUTO_TEST_CASE( my_test1 )
{
  BOOST_TEST( 2 == 1 );
}

BOOST_AUTO_TEST_SUITE( internal )

BOOST_AUTO_TEST_CASE_EXPECTED_FAILURES( my_test1, 2 )

BOOST_AUTO_TEST_CASE( my_test1 )
{
  BOOST_CHECK_EQUAL( sizeof(int), sizeof(char) );
  BOOST_CHECK_EQUAL( sizeof(int*), sizeof(char) );
}

BOOST_AUTO_TEST_SUITE_END()

输出

 
> example --report_level=short
Running 2 test cases...
test.cpp(10): error in "my_test1": check 2 == 1 has failed
test.cpp(21): error in "my_test1": check sizeof(int) == sizeof(char) has failed [4 != 1]
test.cpp(22): error in "my_test1": check sizeof(int*) == sizeof(char) has failed [4 != 1]

Test suite "example" passed with:
  3 assertions out of 3 failed
  3 failures expected
  2 test cases out of 2 passed

与手动注册测试用例配合使用

注意

这种用法被视为已弃用. 请考虑改用expected_failures装饰器.

要为手动注册的测试单元设置预期失败的值, 请在测试单元注册期间把它作为test_suite::add调用的第二个参数传入.

示例: 手动注册测试用例的预期失败规范

代码

 
#include <boost/test/included/unit_test.hpp>
using namespace boost::unit_test;

void free_test_function()
{
  BOOST_TEST( 2 == 1 );
}

test_suite* init_unit_test_suite( int, char* [] )
{
  framework::master_test_suite().
    add( BOOST_TEST_CASE( &free_test_function ), 2 );

  return 0;
}

输出

 
> example --log_level=message
Running 1 test case...
test.cpp(8): error in "free_test_function": check 2 == 1 has failed
Test case has less failures then expected

*** No errors detected
