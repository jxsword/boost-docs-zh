为什么需要数据驱动测试用例?

有些测试需要针对一系列不同输入参数重复执行. 实现这一点的一种方式是为每个参数手动注册一个测试用例. 你也可以在测试用例内部手动用全部参数调用测试函数, 像这样:

void single_test( int i )
{
  BOOST_TEST( /* test assertion */ );
}

void combined_test()
{
  int params[] = { 1, 2, 3, 4, 5 };
  std::for_each( params, params+5, &single_test );
}

上面的做法有几个缺点:

  • 运行测试的逻辑在测试自身内部: 上例中的single_test由测试用例combined_test运行, 而其执行本应由单元测试框架处理
  • 如果上面param数组中某个值发生致命失败(比如BOOST_TEST_REQUIRE中的失败), 测试combined_test会被中止, 测试树中的下一个测试用例被执行.
  • 失败时, 报告不够精确: 调试会话中测试理应被人重新运行, 或者应在测试自身中实现额外的报告逻辑.
参数生成、可伸缩性与组合

在某些情况下, 人们希望对任意大的值集运行参数化测试. 手工枚举参数不是伸缩性好的解决方案, 尤其当这些参数可以由另一个生成这些值的函数描述时. 不过, 这种解决方案也有局限

  • 生成函数: 假设我们有一个函数func(float f), 其中f是 [0, 1] 中的任意数. 我们对精确值兴趣不大, 而想测试func. 与其写出f将针对的func, 何不随机选取 [0, 1] 中的f? 又何不只用一个f值, 而是对任意多的数字运行测试? 从这个小例子可以轻易看出, 当提供生成函数而不是在测试中写下常量值时, 需要参数的测试会更强大.
  • 可伸缩性: 假设我们有一个针对func1的测试用例, 在测试文件中以常量形式写下了N个值. 该测试保证了什么? 我们可以保证func1在这些N个值上工作正常. 但在此设定下N必然有限且通常很小. 我们如何轻松扩展或伸缩N? 一种解决办法是能够生成新值, 并能够针对类——即func1的可能输入——定义测试, 函数在这些输入上应当有确定的行为. 从某种意义上说, 写在测试中的N个常量只是func1可能输入的一个摘录, 而针对输入类工作会给测试带来更大的灵活性和威力.

  • 组合: 假设我们已有针对两个函数func1和func2的测试用例, 它们分别以类型T1和T2为参数. 现在我们要测试一个新函数func3, 它以类型T3为参数, 该类型包含T1和T2, 并通过已知算法调用func1和func2. 这种设定的一个例子是

    // Returns the log of x
// Precondition: x strictly positive.
double fast_log(double x);

// Returns 1/(x-1)
// Precondition: x != 1
double fast_inv(double x);

struct dummy {
  unsigned int field1;
  unsigned int field2;
};

double func3(dummy value)
{
  return 0.5 * (exp(fast_log(value.field1))/value.field1 + value.field2/fast_inv(value.field2));
}

    在此示例中,

    • func3继承fast_log和fast_inv的前置条件: 它分别在(0, +infinity)和[-C, +C] - {1}中为field1和field2定义(C为任意大的常数).
    • 如上所定义, func3在其定义域上处处应接近 1.
    • 我们希望把fast_log和fast_inv的性质复用到复合函数func3中, 并断言func3在任意大的定义域上都有良好定义.

    对func3做参数化测试几乎无法告诉我们可能的数值性质或接近点{field1 = 0, field2 = 1}时的不稳定性. 的确, 参数化测试可能测试 (0,1) 附近的某些点, 但无法提供函数接近该点时的渐近行为.

Boost.Test 框架中的数据驱动测试

单元测试框架提供的设施解决了上述问题:

  • 数据集的概念简化了测试用例输入类的描述. 数据集还实现了若干操作, 使它们的组合能够创建新的更复杂的数据集,
  • 两个宏BOOST_DATA_TEST_CASE和BOOST_DATA_TEST_CASE_F, 分别不带和带夹具支持, 用于在值(样本)集合上声明并注册测试用例,
  • 与唯一值关联的每个测试用例独立于其他测试用例执行. 这些测试受到与常规测试用例相同的保护, 这使得对数据集每个样本的测试执行是隔离的、健壮的、可重复的, 并便于调试,
  • 单元测试框架提供了若干数据集生成函数

本节余下部分介绍单元测试框架关于数据驱动测试用例的概念与特性, 特别是:

  1. 介绍数据集与样本的概念
  2. 解释数据驱动测试用例的声明与注册,
  3. 详述数据集上的操作
  4. 最后介绍内置的数据集生成器.
