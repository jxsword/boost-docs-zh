测试套件

如果把测试用例看作测试树上的叶子, 那么测试套件可以看作枝条, 而主测试套件则是根. 不过与真实的树不同, 我们的树在许多情况下只由直接附着在根上的叶子组成. 所有测试用例直接位于主测试套件中是常见情形. 如果你确实想构建层次化的测试套件结构, 单元测试框架同时提供了手动与自动的测试套件创建和注册设施:

  1. 带自动注册的测试套件
  2. 手动注册的测试套件

此外, 单元测试框架提出了主测试套件的概念. 了解该组件最重要的原因是, 它提供了访问传给测试模块的命令行参数的能力.

自动注册

单元测试框架为自动测试套件创建和注册提供的方案, 旨在支持多点定义、任意测试套件深度, 以及与自动测试用例创建和注册的平滑集成. 与手动显式注册相比, 该设施应能显著简化测试树的构建过程.

该实现基于单个编译单元内文件作用域变量定义的顺序. 此设施的语义与 C++ 的命名空间特性非常相似, 包括对测试套件扩展的支持. 用宏BOOST_AUTO_TEST_SUITE开始测试套件, 用宏BOOST_AUTO_TEST_SUITE_END结束测试套件. 同一测试套件可以在同一测试文件内或不同测试文件中多次重新打开. 结果, 所有测试单元都将成为所构建测试树中同一测试套件的成员.

BOOST_AUTO_TEST_SUITE(test_suite_name);
BOOST_AUTO_TEST_SUITE_END();

在测试套件开始与结束声明之间定义的测试单元成为该测试套件的成员. 测试单元总是成为最近声明的测试套件的成员. 在测试文件作用域声明的测试单元成为主测试套件的成员. 测试套件嵌套深度没有限制.

本示例创建的测试树与手动测试套件注册示例中创建的完全一致.

示例: 带自动注册的测试套件

代码

 
#define BOOST_TEST_MODULE example
#include <boost/test/included/unit_test.hpp>

BOOST_AUTO_TEST_SUITE( test_suite1 )

BOOST_AUTO_TEST_CASE( test_case1 )
{
  BOOST_TEST_WARN( sizeof(int) < 4U );
}

BOOST_AUTO_TEST_CASE( test_case2 )
{
  BOOST_TEST_REQUIRE( 1 == 2 );
  BOOST_FAIL( "Should never reach this line" );
}

BOOST_AUTO_TEST_SUITE_END()
BOOST_AUTO_TEST_SUITE( test_suite2 )

BOOST_AUTO_TEST_CASE( test_case3 )
{
  BOOST_TEST( true );
}

BOOST_AUTO_TEST_CASE( test_case4 )
{
  BOOST_TEST( false );
}

BOOST_AUTO_TEST_SUITE_END()

输出

 
> example
Running 4 test cases...
test.cpp(21): fatal error: in "test_suite1/test_case2": critical check 1 == 2 has failed [1 != 2]
test.cpp(35): error: in "test_suite2/test_case4": check false has failed

*** 2 failures are detected in the test module "example"

可以看到, 本示例中测试树的构建更直接且更自动化.

在下例中, 测试套件test_suite由两部分组成. 它们的定义彼此远离, 且被另一个测试用例隔开. 实际上这些部分甚至可以位于不同的测试文件中. 得到的测试树保持不变. 从输出可以看到, test_case1和test_case2都位于同一测试套件test_suite中.

示例: 用自动注册设施扩展测试套件

代码

 
#define BOOST_TEST_MODULE example
#include <boost/test/included/unit_test.hpp>

BOOST_AUTO_TEST_SUITE( test_suite )

BOOST_AUTO_TEST_CASE( test_case1 )
{
  BOOST_ERROR( "some error 1" );
}

BOOST_AUTO_TEST_SUITE_END()


BOOST_AUTO_TEST_CASE( test_case_on_file_scope )
{
  BOOST_TEST( true );
}

BOOST_AUTO_TEST_SUITE( test_suite )

BOOST_AUTO_TEST_CASE( test_case2 )
{
  BOOST_ERROR( "some error 2" );
}

BOOST_AUTO_TEST_SUITE_END()

手动注册的测试套件

要手动创建测试套件, 你需要

  1. 创建boost::unit_test::test_suite类的实例,
  2. 把它注册到测试树, 并
  3. 用测试用例(或更低层测试套件)填充它.
测试单元注册接口

单元测试框架用类boost::unit_test::test_suite来建模测试用例容器 - 测试套件 - 的概念. 完整的类接口参考见本文档的进阶章节. 这里你只需要关心单个测试单元注册接口:

void test_suite::add( test_unit* tc, counter_t expected_failures = 0, int timeout = 0 );

第一个参数是指向新建测试单元的指针. 第二个可选参数 - expected_failures - 定义测试单元内预期失败的测试断言数量. 默认不预期任何错误.

注意

为测试套件提供预期失败数量时要当心. 默认情况下, 单元测试框架把测试套件的预期失败数量计算为构成它的所有测试单元中相应值之和. 改变这一点通常没有意义.

第三个可选参数 - timeout - 定义测试单元的超时值. 目前单元测试框架尚不能为测试套件执行设置超时, 因此该参数只对测试用例注册有意义. 默认不设置超时. 关于超时值的更多细节见方法boost::unit_test::test_suite::add.

要在一次函数调用中注册一组测试单元, test_suite类提供了另一个add接口, 见本文档进阶章节的介绍.

测试套件实例的构造

要手动创建测试套件实例, 使用宏BOOST_TEST_SUITE. 它隐藏了所有实现细节, 你只需指定测试套件名:

BOOST_TEST_SUITE(test_suite_name);

BOOST_TEST_SUITE创建类boost::unit_test::test_suite的一个实例并返回指向所构造实例的指针. 或者, 你也可以自己创建类boost::unit_test::test_suite的实例.

注意

boost::unit_test::test_suite实例必须在堆上分配, 编译器不允许你在栈上创建.

新建的测试套件必须使用add接口注册到父套件中. 测试套件的创建和注册都在测试模块初始化函数中执行.

下面的示例创建的测试树可以用如下层次结构表示:

示例: 手动注册的测试套件

代码

 
#include <boost/test/included/unit_test.hpp>
using namespace boost::unit_test;

void test_case1() { /* ... */ }
void test_case2() { /* ... */ }
void test_case3() { /* ... */ }
void test_case4() { /* ... */ }

test_suite* init_unit_test_suite( int /*argc*/, char* /*argv*/[] )
{
  test_suite* ts1 = BOOST_TEST_SUITE( "test_suite1" );
  ts1->add( BOOST_TEST_CASE( &test_case1 ) );
  ts1->add( BOOST_TEST_CASE( &test_case2 ) );

  test_suite* ts2 = BOOST_TEST_SUITE( "test_suite2" );
  ts2->add( BOOST_TEST_CASE( &test_case3 ) );
  ts2->add( BOOST_TEST_CASE( &test_case4 ) );

  framework::master_test_suite().add( ts1 );
  framework::master_test_suite().add( ts2 );

  return 0;
}
