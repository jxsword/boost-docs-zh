测试框架, 所为何来?

测试程序应如何报告错误? 显示错误消息是一种显而易见的方式:

if( something_bad_detected )
  std::cout << "something bad has been detected" << std::endl;

但这要求每次运行后检查程序的输出以判断是否发生了错误. 由于测试程序经常作为回归测试套件的一部分运行, 人工检查输出以发现错误消息既耗时又不可靠. GNU/expect 之类的测试框架可以自动完成检查, 但对简单测试而言过于复杂.

一种更好的简单报错方式是: 测试程序在圆满完成时返回EXIT_SUCCESS(通常为 0), 检测到错误时返回EXIT_FAILURE. 这让简单的回归测试脚本能自动且无歧义地判定成功或失败. 脚本可以据此采取适当的后续动作, 如生成 HTML 表格或发送告警邮件, 并且可以随意修改, 无需改动实际的 C++ 测试程序.

基于"测试程序返回EXIT_SUCCESS或EXIT_FAILURE"这一策略的测试协议不需要任何辅助工具; C++ 语言和标准库就足够了. 不过程序员必须记得捕获所有异常并把它们转换为以非零返回码退出程序. 程序员还必须记得在测试代码中不要使用标准库的assert()宏, 因为在某些系统上它会产生不良副作用, 例如弹出需要人工干预的消息.

Boost 测试库的单元测试框架正是为自动化这些任务而设计的. 库提供的main()使用户免于繁琐的错误检测与报告职责. 用户可以使用提供的测试工具执行复杂的验证任务. 我们来看下面这个简单的测试程序:

#include <my_class.hpp>

int main( int, char* [] )
{
  my_class test_object( "qwerty" );
  return test_object.is_valid() ? EXIT_SUCCESS : EXIT_FAILURE;
}

上面的测试存在几个问题.

  1. 你需要把is_valid结果转换成正确的结果码.
  2. 如果在 test_object 构造或方法is_valid调用中发生异常, 程序会崩溃.
  3. 如果你手动运行这个测试, 将看不到任何输出.

单元测试框架能解决所有这些问题. 要与它集成, 上述程序需要改为:

#include <my_class.hpp>
#define BOOST_TEST_MODULE MyTest
#include <boost/test/unit_test.hpp>

BOOST_AUTO_TEST_CASE( my_test )
{
  my_class test_object( "qwerty" );
  BOOST_TEST( test_object.is_valid() );
}

现在, 即使发生异常你也会得到统一的结果码, 而且如果你选择查看, 还能获得BOOST_TEST工具的格式化输出. 还有其他执行检查的方式吗? 下面的示例测试程序展示了几种在add()函数中检测并报告错误的不同方法.

#define BOOST_TEST_MODULE MyTest
#include <boost/test/unit_test.hpp>

int add( int i, int j ) { return i + j; }

BOOST_AUTO_TEST_CASE(my_test)
{
  // six ways to detect and report the same error:

  // continues on error
  BOOST_TEST( add(2, 2) == 4 );          

  // throws on error
  BOOST_TEST_REQUIRE( add(2, 2) == 4 );  

  //continues on error
  if (add(2, 2) != 4)
    BOOST_ERROR( "Ouch..." );            

  // throws on error
  if (add(2, 2) != 4)
    BOOST_FAIL( "Ouch..." );             

  // throws on error
  if (add(2, 2) != 4)
    throw "Ouch...";                     

  // continues on error
  BOOST_TEST( add(2, 2) == 4,            
              "2 plus 2 is not 4 but " << add(2, 2));
}

这种方法使用工具BOOST_TEST, 它会显示错误消息(默认输出到std::cout), 内容包括失败的表达式、表达式两侧的值、源文件名和源文件行号. 它还会递增错误计数. 程序终止时, 单元测试框架会自动显示错误计数.

这种方法使用工具BOOST_TEST_REQUIRE, 与方法 #1 类似, 区别在于显示错误后会抛出异常, 由单元测试框架捕获. 这种方法适合编写显式的测试程序, 且错误严重到使继续测试失去意义的情形.

这种方法与方法 #1 类似, 区别在于错误检测和错误报告是分开编码的. 当被测的特定条件需要多条独立语句和/或不能直接表明失败原因时, 这种方法最有用.

这种方法与方法 #2 类似, 区别在于错误检测和错误报告是分开编码的. 当被测的特定条件需要多条独立语句和/或不能直接表明失败原因时, 这种方法最有用.

这种方法抛出异常, 异常会被单元测试框架捕获并报告. 如果异常派生自std::exception, 或是char*或std::string, 捕获异常时显示的错误消息将最有意义.

这种方法使用带附加消息参数的工具BOOST_TEST, 与方法 #1 类似, 区别在于与方法 #3 相同, 会显示作为第二个参数指定的替代错误消息.
