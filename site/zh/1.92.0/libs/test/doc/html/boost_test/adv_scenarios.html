如果你正在阅读本章, 说明前面各节涵盖的大量工具和接口不足以满足你构想中的测试场景. 你来到这里是想让单元测试框架听命于你......我们不会阻止你. 相反, 我们会尽力引导你, 让那些黑暗角落看起来不那么可怕.

在多数情况下, 单元测试框架会作为系统库的一部分或你公司所用库集合的一部分提供给你. 但如果你需要构建自己的单元测试框架静态库或动态库, 或出于任何原因需要定制构建, 构建单元测试框架一节涵盖了所有必要步骤.

为了让设置测试模块的过程更加顺畅, 单元测试框架为测试模块提供了一些默认初始化逻辑. 通常默认的测试模块初始化就够用了, 但如果你想实现某些自定义初始化, 或想改变默认初始化的行为, 首先应查看测试模块初始化一节. 你将在那里了解单元测试框架为定制该行为而提供的各种选项.

框架中负责加载、初始化并执行你的测试模块的部分称为测试运行器. 每种使用变体都自带默认测试运行器. 反过来, 如果你更愿意自行实现测试模块的入口点(例如需要自己实现main函数而不使用单元测试框架提供的那一个), 你就需要了解测试运行器操作所涉及的单元测试框架接口. 这些内容在测试运行器一节中介绍. 再强调一次, 只有当诸如夹具或装饰器这类常规的初始化逻辑定制手段不足以满足你的需求时, 你才需要阅读该节.
