夹具

夹具模型
测试用例夹具
测试套件进入/退出夹具
全局夹具

一般而言, 测试夹具或测试上下文是执行测试所需的一个或多个下列项的集合:

  • 前置条件
  • 被测单元的特定状态
  • 必要的清理步骤

尽管这些任务出现在许多(甚至全部)测试用例中, 但让测试夹具与众不同之处在于重复. 普通测试用例实现会自己完成全部准备和清理工作, 而测试夹具允许把这些工作实现在一个单独的可复用单元中.

随着 eXtreme Programming (XP)的引入, 要求重复测试建立/清理的测试风格变得更加流行. 采用 XP 的单个测试模块可能包含数百个单断言测试用例, 其中许多需要非常相似的测试建立/清理. 这正是测试夹具设计要解决的问题.

实践中, 测试夹具通常是setup和teardown函数的组合, 并与测试用例关联. 前者服务于测试建立的目的, 后者专门负责清理任务. 理想情况下, 我们希望测试模块作者能够在栈上定义夹具中使用的变量, 同时又能在测试用例中直接引用它们.

重要的是要理解, C++ 提供了一种实现直接测试夹具方案的方式, 它几乎满足我们的要求, 而无需测试框架的任何额外支持. 带这种夹具的简单测试模块可能如下所示:

struct MyFixture {
  MyFixture()   { i = new int; *i = 0 }
  ~MyFixture()  { delete i; }

  int* i;
};

BOOST_AUTO_TEST_CASE( test_case1 )
{
  MyFixture f;
  // do something involving f.i
}

BOOST_AUTO_TEST_CASE( test_case2 )
{
  MyFixture f;
  // do something involving f.i
}

这是一个可用于实现任何共享建立或清理过程的通用方案. 不过, 这种基于纯 C++ 的夹具方案仍存在一些或大或小的实际问题:

  • 我们需要在每个测试用例中手动添加夹具声明语句.
  • 夹具中定义的对象是带有<fixture-instance-name>前缀的引用.
  • 没有地方执行全局夹具, 以在测试前后执行全局建立/清理过程.

单元测试框架让你按照若干通用接口定义夹具, 从而帮助你完成以下任务:

  • 为单个或一组测试用例定义共享的建立/拆除过程
  • 定义每个测试套件执行一次的建立/拆除过程
  • 定义每个测试模块执行一次的全局建立/拆除过程
