调试断言

如果你在单元测试中观察到失败, 并使用调试器来确定原因, 那么单步进入断言内的表达式可能非常困难. 由于BOOST_TEST会在求值之前构建表达式树, 调试器的"Step Into"功能必须先单步进入表达式树构建的每一步, 你才能进入表达式的求值.

为缓解这个问题, 可以以禁用断言内表达式树构建的模式构建测试模块. 在该模式下, 断言做的第一件事就是急切(eager)求值被测表达式. 通过定义符号BOOST_TEST_TOOLS_UNDER_DEBUGGER(借助#define或编译器选项-D), 并在包含任何单元测试框架头文件之前进行, 即可启用该模式.

注意

开启表达式的急切求值后, 表达式会按字面方式求值: 这会自动禁用任何特殊语义, 如浮点类型的容差或boost::test_tools::per_element版本的序列比较. 这可能把通过断言变为失败断言, 反之亦然. 在对序列做boost::test_tools::per_element比较的情况下, 若比较的序列类型不同, 还可能造成程序非良构.

BOOST_TEST_TOOLS_UNDER_DEBUGGER的不便之处在于必须重新编译测试模块. 单元测试框架还提供了另一个选项: 编译两个版本的断言, 并根据测试模块是否在调试器下运行来动态选择使用哪个. 该模式通过定义符号BOOST_TEST_TOOLS_DEBUGGABLE(借助#define或编译器选项-D)来启用, 需在包含任何单元测试框架头文件之前进行.

为了判断测试模块是否在调试器下运行, 会使用函数boost::debug::under_debugger.

注意

目前, 函数boost::debug::under_debugger只能在 MSVC 和少数 Linux 变体上正确检测调试器.
