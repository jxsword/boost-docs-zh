用数据集声明和注册测试用例

为了声明并注册数据驱动测试用例, 应使用宏BOOST_DATA_TEST_CASE或BOOST_DATA_TEST_CASE_F. 这两种形式等价, 区别在于BOOST_DATA_TEST_CASE_F支持夹具.

这些宏是变参的, 可用如下形式使用:

BOOST_DATA_TEST_CASE(test_case_name, dataset) { /* dataset1 of arity 1 */ }
BOOST_DATA_TEST_CASE(test_case_name, dataset, var1) { /* datasets of arity 1 */ }
BOOST_DATA_TEST_CASE(test_case_name, dataset, var1, ..., varN) { /* datasets of arity N  */ }

BOOST_DATA_TEST_CASE_F(fixture, test_case_name, dataset) { /* dataset1 of arity 1 with fixture */ }
BOOST_DATA_TEST_CASE_F(fixture, test_case_name, dataset, var1) { /* dataset1 of arity 1 with fixture */ }
BOOST_DATA_TEST_CASE_F(fixture, test_case_name, dataset, var1, ..., varN) { /* dataset1 of arity N with fixture */ }

宏的第一种形式用于元数为 1 的数据集. 测试主体正在执行的样本的值通过自动变量sample获得(xrange顾名思义是一个值的范围):

BOOST_DATA_TEST_CASE( test_case_arity1_implicit, data::xrange(5) )
{
  BOOST_TEST((sample <= 4 && sample >= 0));
}

第二种形式也用于元数为 1 的数据集, 但不再用变量sample, 而是把当前样本引入var1:

BOOST_DATA_TEST_CASE( test_case_arity1, data::xrange(5), my_var )
{
  BOOST_TEST((my_var <= 4 && my_var >= 0));
}

第三种形式是前一形式对元数为N的数据集的扩展. 样本是多态元组, 每个变量var1, ..., varN对应样本的索引 1, ... N:

// The following definition of the dataset test case throws an exception before the
// test module starts (zip of non infinite or singleton datasets of different length)
BOOST_DATA_TEST_CASE( test_case_arity2, data::xrange(2) ^ data::xrange(5), apples, potatoes)
{
  BOOST_TEST((apples <= 1 && apples >= 0));
  BOOST_TEST((potatoes <= 4 && potatoes >= 0));
}

接下来的三种声明形式(带BOOST_DATA_TEST_CASE_F)与前面几种等价, 区别在于支持对每个样本在测试主体之前执行夹具. 该夹具应遵循此处详述的期望接口.

数据集的元数与变量数量应完全一致, 第一种形式是元数为 1 时的快捷方式.

提示

会对数据集元数与变量var1... varN数量的一致性执行编译期检查. 对无 C++11支持的编译器, 支持的最大元数由宏BOOST_TEST_DATASET_MAX_ARITY控制, 可在包含单元测试框架头文件之前覆盖.

注意

宏BOOST_DATA_TEST_CASE和BOOST_DATA_TEST_CASE_F仅对支持变参宏的编译器可用.

样本与测试树

应当强调, 这些宏并不声明单个测试用例(如BOOST_AUTO_TEST_CASE那样), 而是按参数给定数据集中的样本数量声明并注册同样多的测试用例. 每个测试用例恰好在数据集的一个样本上运行.

更准确地说,

BOOST_DATA_TEST_CASE(test_case_name, dataset)

做的事情如下:

  • 它注册一个测试套件, 名为"test_case_name",
  • 它按"dataset"中的样本数量注册同样多的测试用例, 每个测试用例的名称对应样本在数据库中的索引, 以_为前缀, 从索引0开始("_0"、"_1"、... "_(N-1)", 其中N为数据集大小)

这使得以下操作变得容易:

  • 识别哪个样本失败(比如"test_case_name/_3"),
  • 使用测试过滤特性(由单元测试框架提供)从命令行重放一个或多个样本(或完整数据集)的测试,
  • 对数据集的每个单独测试用例应用装饰器, 就像装饰器应用于测试套件一样.

与常规测试用例完全一样, 每个测试用例(关联到特定样本)都以受监视方式执行:

  • 测试执行相互独立: 如果某个样本发生错误, 其余样本的执行不受影响,
  • 发生错误时, 连同发生错误的样本索引的上下文会一并报告在日志中. 该上下文包含测试失败的样本名称和值, 有助于调试.
