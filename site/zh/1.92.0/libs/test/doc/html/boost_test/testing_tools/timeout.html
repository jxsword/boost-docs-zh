测试用例的超时

单元测试框架提供了装饰器timeout, 为特定测试单元指定超时. 参数 time 始终以秒和墙上时钟时间表示.

对测试用例而言, 超时值设定测试允许的最长持续时间. 若超过该时间, 测试用例会被报告为失败. 在某些系统上, 单元测试框架能够通过SIGALRM信号强制测试用例停止(见下文).

对测试套件而言, 超时值设定整个套件完成所允许的最长持续时间. 该持续时间是根植于该测试套件的子树中所有测试用例的累计时间, 加上单元测试框架所需的一些额外执行时间. 对带超时的测试套件下的每个测试单元, 其允许的最长持续时间被设为: 测试套件超时减去该测试单元执行之前的累计执行时间. 如果该测试单元是测试用例, 则等价于为该测试用例设置装饰器timeout, 超时值按前述方式表达.

若测试套件超时, 该套件会被标记为timed-out和failed, 且在超时时间点尚未执行的 所有测试单元(套件和用例)全部被跳过.

示例: 装饰器 timeout

代码

 
#define BOOST_TEST_MODULE decorator_11
#include <boost/test/included/unit_test.hpp>
namespace utf = boost::unit_test;

BOOST_AUTO_TEST_CASE(test1, * utf::timeout(2))
{
#ifdef BOOST_SIGACTION_BASED_SIGNAL_HANDLING
  for(;;) {}
  BOOST_TEST(true);
#else
  BOOST_TEST(false);
#endif
}

输出

 
> decorator_11
Running 1 test case...
unknown location(0): fatal error: in "test1": signal: SIGALRM (timeout while executing function)
test.cpp(5): last checkpoint: "test1" entry.

*** 1 failures is detected in test module "decorator_11"
注释

宏BOOST_SIGACTION_BASED_SIGNAL_HANDLING在 Boost.Test 能够强制测试用例停止时被定义. 例如 Windows 不支持该特性. 单元测试框架仍将能够把测试用例报告为失败(一旦该测试用例结束).

注释

测试套件级超时的支持在Boost 1.70 / 单元测试框架 v3.10中加入
