管理测试依赖

一般而言, 把任何测试写得尽可能独立于其他测试是良好实践, 但有些情况下无法避免依赖, 需要为测试执行规定顺序.

在一般设定下, 对任意两个测试用例TA和TB, TB不应想当然地认为TA已经执行过, 即使TA与TB声明在同一翻译单元中且前者在前. 单元测试框架默认给出的唯一与顺序相关的保证是: 若测试用例TA和TB声明在同一测试套件中, 则来自任何其他测试套件的测试用例(称为TX)不会在TA与TB之间执行, 即使TX的声明出现在TA与TB的声明之间. 换言之, 一个套件的所有测试一次性连续执行, 即使测试套件命名空间被多次打开.

尽管顺序没有保证, 它也可能碰巧在多次运行间保持不变. 为确保测试用例彼此不依赖, 可以用附加的命令行参数random调用测试模块, 打乱测试单元顺序, 从而对错误的隐式顺序更加健壮.

声明测试用例依赖

如果测试单元之间存在依赖, 且这些测试的执行需要规定顺序, 必须显式声明. 单元测试框架中的依赖影响测试单元的两个维度, 即:

  • 这些单元的执行顺序
  • 某个测试单元的执行, 它以其父单元的状态为条件

装饰器 depends_on把被装饰的测试用例(称为TB)与按名称指定的另一个测试用例(称为TA)关联起来. 这以两种方式影响测试树的处理:

  1. 第一, 测试用例TA被命令为在TB之前运行, 与它们声明或加入测试树的顺序无关,
  2. 第二, 若TB被指定依赖的TA处于禁用或跳过状态, 或已执行并被标记为失败, 则跳过其执行.
示例: 装饰器 depends_on

代码

 
#define BOOST_TEST_MODULE decorator_07
#include <boost/test/included/unit_test.hpp>

namespace utf = boost::unit_test;

// test1 and test2 defined at the bottom

BOOST_AUTO_TEST_CASE(test3, * utf::depends_on("s1/test1"))
{
  BOOST_TEST(false);
}

BOOST_AUTO_TEST_CASE(test4, * utf::depends_on("test3"))
{
  BOOST_TEST(false);
}

BOOST_AUTO_TEST_CASE(test5, * utf::depends_on("s1/test2"))
{
  BOOST_TEST(false);
}

BOOST_AUTO_TEST_SUITE(s1)

  BOOST_AUTO_TEST_CASE(test1)
  {
    BOOST_TEST(true);
  }

  BOOST_AUTO_TEST_CASE(test2, * utf::disabled())
  {
    BOOST_TEST(false);
  }

BOOST_AUTO_TEST_SUITE_END()
