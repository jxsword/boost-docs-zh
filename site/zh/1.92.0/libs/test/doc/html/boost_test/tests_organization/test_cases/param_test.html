参数化测试用例

注意

本页呈现的功能已被数据驱动测试用例设施取代.

有些测试需要针对一系列不同输入参数重复执行. 实现这一点的一种方式是像前面的示例那样为每个参数手动注册一个测试用例. 你也可以在测试用例内部手动用全部参数调用测试函数, 像这样:

void single_test( int i )
{
  BOOST_CHECK( /* test assertion */ );
}

void combined_test()
{
  int params[] = { 1, 2, 3, 4, 5 };
  std::for_each( params, params+5, &single_test );
}

单元测试框架为该问题提供了更好的解决方案: 基于一元函数的测试用例, 也称参数化测试用例. 一元测试函数可以是自由函数、一元仿函数(例如用boost::bind创建的)或绑定了测试类实例的类的一元方法. 测试函数用宏BOOST_PARAM_TEST_CASE转换为测试用例. 该宏期望一个参数集合(以两个输入迭代器传入)和一个一元测试函数:

BOOST_PARAM_TEST_CASE(test_function, params_begin, params_end);

BOOST_PARAM_TEST_CASE创建测试用例生成器的一个实例. 当传给方法test_suite::add时, 生成器为参数集合中的每个参数产生一个单独的子测试用例, 并立即把它注册到测试套件. 每个测试用例基于绑定了按值传入参数的测试函数, 即使测试函数期望按引用传参. 参数值与绑定的测试函数一起存储, 这一事实使你无需管理参数的生命周期. 例如, 它们可以定义在测试模块初始化函数作用域内.

所有子测试用例的名称都从宏参数test_function推导. 如果你希望指定不同名称, 必须改用底层的make_test_case接口. 测试用例的创建和注册都在测试模块初始化函数中执行.

参数化测试用例设施优于上面示例中的做法, 因为每个子测试用例的执行都受独立保护和计数. 它产生更好的测试日志/结果报告(上例中一旦失败, 你无法说出是哪个参数出的问题), 并且即使其中一个参数导致某个子测试用例终止, 你仍能对其余参数完成测试.

与为每个参数手动注册测试用例的方式相比, 参数化测试用例设施更简洁且更易扩展.

在下面的简单示例中, 以free_test_function实现的同一测试对 5 个不同参数执行. 参数定义在测试模块初始化函数作用域内. 主测试套件包含 5 个独立测试用例.

示例: 基于一元自由函数的测试用例

代码

 
#include <boost/test/included/unit_test.hpp>
#include <boost/test/parameterized_test.hpp>
using namespace boost::unit_test;

void free_test_function( int i )
{
  BOOST_TEST( i < 4 /* test assertion */ );
}

test_suite* init_unit_test_suite( int /*argc*/, char* /*argv*/[] )
{
  int params[] = { 1, 2, 3, 4, 5 };

  framework::master_test_suite().
    add( BOOST_PARAM_TEST_CASE( &free_test_function, params, params+5 ) );

  return 0;
}

输出

 
> example
Running 5 test cases...
test.cpp(15): error: in "free_test_function": check i < 4 has failed [4 >= 4]
test.cpp(15): error: in "free_test_function": check i < 4 has failed [5 >= 4]

*** 2 failures are detected in the test module "Master Test Suite"

下一个示例与之类似, 但用类的方法代替自由函数. 尽管参数按引用传入测试方法, 你仍然可以在测试模块初始化函数作用域内定义它们. 本例采用了备选的测试模块初始化函数规定.

示例: 基于一元类方法的测试用例

代码

 
#define BOOST_TEST_ALTERNATIVE_INIT_API
#include <boost/test/included/unit_test.hpp>
#include <boost/test/tools/floating_point_comparison.hpp>
#include <boost/test/parameterized_test.hpp>
#include <boost/bind/bind.hpp>
using namespace boost::unit_test;
namespace tt=boost::test_tools;


class test_class {
public:
  void test_method( double d )
  {
    BOOST_TEST( d * 100 == (double)(int)(d*100), tt::tolerance(0.0001) );
  }
} tester;

bool init_unit_test()
{
  using boost::bind;
  using boost::placeholders::_1;
  double params[] = { 1., 1.1, 1.01, 1.001, 1.0001 };

  boost::function<void (double)> test_method = bind( &test_class::test_method, &tester, _1);

  framework::master_test_suite().
    add( BOOST_PARAM_TEST_CASE( test_method, params, params+5 ) );

  return true;
}

输出

 
> example
Running 5 test cases...

test.cpp(23): error: in "test_method": check d * 100 == (double)(int)(d*100) has failed [1.0001 * 100 != 100]. Relative difference exceeds tolerance [0.0001 > 0.0001]
