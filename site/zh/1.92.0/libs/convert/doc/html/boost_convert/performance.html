转换器对比

Boost.Convert 的性能完全取决于所部署转换器的性能. 若干转换器已针对字符串到基本类型以及到用户定义类型的转换进行了测试.

而每个具体转换器的性能又取决于平台、所用编译器以及底层转换组件 (小字符串优化、std::stream、printf、Boost.Spirit 等) 的具体实现. 因此, 以下结果仅是上述转换器在受测平台上 相对 性能的大致指示.

在 64 位 Ubuntu 22.04 上用 gcc-11.2.0 编译时, 测试产生了以下结果:

str-to-int: spirit/strtol/lcast/scanf/stream/charconv= 0.15/0.13/1.99/0.86/0.67/0.16 seconds.
str-to-lng: spirit/strtol/lcast/scanf/stream/charconv= 0.12/0.15/2.04/0.88/0.66/0.12 seconds.
str-to-dbl: spirit/strtol/lcast/scanf/stream/charconv= 0.15/0.53/5.12/1.06/1.68/0.19 seconds.
int-to-str: spirit/strtol/lcast/prntf/stream/charconv= 0.39/0.29/0.43/1.09/0.68/0.29 seconds.
lng-to-str: spirit/strtol/lcast/prntf/stream/charconv= 0.39/0.29/0.45/1.11/0.68/0.31 seconds.
dbl-to-str: spirit/strtol/lcast/prntf/stream/charconv= 1.12/1.17/7.34/5.05/4.65/1.07 seconds.

综合上述情况, 我倾向于得出以下结论:

  • 基于 Spirit.Qi、受 strtol 启发以及基于 charconv 的转换器在字符串到基本类型 (int、double) 的转换中最快. 因此, 对于执行此类转换的任务, 它们可能是好的候选 (同时要牢记 Spirit.Qi 在转换方面的限制);
  • 基于 std::iostream 的转换器相对较慢. 不过, 鉴于其成熟度、可用性与格式化支持, 若转换性能不是你的首要关注点, 它可以是一个值得考虑的选项;
  • 基于 boost::lexical_cast 的转换器始终明显最慢 (由于其底层设计);
  • 基于 charconv 以及受 strtol 启发的转换器总体上最快, 且带格式化支持, 可能是吸引人的多面手.

对于用户定义类型, 转换器的测试结果如下:

str-to-user-type: lcast/stream/strtol/charconv=0.13/0.05/0.01/0.02 seconds.
user-type-to-str: lcast/stream/strtol/charconv=0.11/0.03/0.01/0.01 seconds.

为提供 string-to-user-type 与 user-type-to-string 转换, 前两者部署了同一个标准 std::iostream 库. 尽管如此, 在这些测试中 boost::cnv::cstream 明显优于 boost::lexical_cast. 这反映了不同的底层设计. 即, 标准 Boost.Convert 部署模式是 一次性 创建一个或多个转换器, 然后复用它们. 而 boost::lexical_cast 在每次调用该函数时都会创建然后销毁一个 std::stream 实例, 且 boost::lexical_cast 性能表表明 "std::stringstream 含构造" 操作比 "std::stringstream 不含构造" 昂贵得多.

boost::cnv::strtol 与 boost::cnv::charconv 对用户类型的支持以类似方式实现, 但没有 std::stream 相关的开销. 这带来了明显更好的性能结果.

基于性能数据, 我倾向于得出结论: 鉴于 Boost.Convert 框架提供的类型安全与种种好处, 对于与转换相关的任务, 它 (配合适当的转换器) 或许应当是首选.
