目的

boost::mem_fn 是标准函数 std::mem_fun 与 std::mem_fun_ref 的泛化. 它支持带多于一个实参的成员函数指针, 且返回的函数对象可以接受指针、引用或智能指针指向的对象实例作为其第一个实参. mem_fn 还支持数据成员指针: 把它们视为不接受实参并返回对该成员的 (const) 引用的函数.

mem_fn 的目的有二. 其一, 它允许用户以熟悉的

std::for_each(v.begin(), v.end(), boost::mem_fn(&Shape::draw));

语法在容器上调用成员函数, 即使容器存储的是智能指针.

其二, 它可以用作构建块, 供想把成员函数指针当作函数对象对待的库开发者使用. 库可以定义一个增强的 for_each 算法, 提供形如下式的重载:

template<class It, class R, class T> void for_each(It first, It last, R (T::*pmf) ())
{
    std::for_each(first, last, boost::mem_fn(pmf));
}

从而允许这样的便捷语法:

for_each(v.begin(), v.end(), &Shape::draw);

在为该特性撰写文档时, 库作者只需说明:

template<class It, class R, class T> void for_each(It first, It last, R (T::*pmf) ());
  • 效果: 等价于 std::for_each(first, last, boost::mem_fn(pmf)).

其中 boost::mem_fn 可以是指向本页的链接. 示例参见 bind 的文档.

mem_fn 接受一个实参 - 成员指针 - 并返回适合与标准或用户自定义算法配合使用的函数对象:

struct X
{
    void f();
};

void g(std::vector<X> & v)
{
    std::for_each(v.begin(), v.end(), boost::mem_fn(&X::f));
};

void h(std::vector<X *> const & v)
{
    std::for_each(v.begin(), v.end(), boost::mem_fn(&X::f));
};

void k(std::vector<boost::shared_ptr<X> > const & v)
{
    std::for_each(v.begin(), v.end(), boost::mem_fn(&X::f));
};

返回的函数对象接受的实参与输入成员函数相同, 外加一个表示对象实例的"灵活"第一个实参.

当函数对象以第一个实参 x 被调用, 且该实参既不是指向相应类 (上例中的 X) 的指针也不是其引用时, 它会使用 get_pointer(x) 从 x 获取指针. 库作者可以通过提供适当的 get_pointer 重载来"注册"其智能指针类, 使 mem_fn 能够识别并支持它们.

[注释: get_pointer 并不限于返回指针. 任何能用于成员函数调用表达式 (x->*pmf)(...) 的对象都可以.]

[注释: 本库对 get_pointer 使用非限定调用. 因此, 通过实参相关查找, 它会找到与相应智能指针类定义在同一命名空间中的 get_pointer 重载, 以及任何 boost::get_pointer 重载.]

由 mem_fn 返回的所有函数对象都暴露一个 result_type typedef, 表示成员函数的返回类型. 对数据成员而言, result_type 定义为该成员的类型.

常见问题(FAQ)

能否用 mem_fn 取代标准的 std::mem_fun[_ref] 适配器?

可以. 对简单用途而言, mem_fn 提供标准适配器所不具备的额外功能. 把 std::bind1st, std::bind2nd 或 Boost.Compose 与标准适配器组合使用的复杂表达式, 可以改用 boost::bind 重写, 它会自动利用 mem_fn.

我是否应当把现有代码中出现的每一处 std::mem_fun[_ref] 都替换为 mem_fn?

不必, 除非你有充分的理由. mem_fn 与标准适配器并非 100% 兼容, 尽管已经相当接近. 特别是, mem_fn 不像标准适配器那样返回 std::[const_]mem_fun[1][_ref]_t 类型的对象, 并且无法用标准的 argument_type 与 first_argument_type 嵌套 typedef 完整描述第一个实参的类型. 需要可适配函数对象才能工作的库可能不喜欢 mem_fn.

mem_fn 能配合 COM 方法使用吗?

可以, 只要你 `#define BOOST_MEM_FN_ENABLE_STDCALL.

为什么 BOOST_MEM_FN_ENABLE_STDCALL 没有被自动定义?

一般而言, 不可移植的扩展应当默认关闭, 以防止厂商锁定. 如果 BOOST_MEM_FN_ENABLE_STDCALL 被自动定义, 你可能在不知不觉中用上它, 而没有意识到你的代码可能因此不再可移植. 此外, 默认调用约定有可能恰好是 __stdcall, 此时启用 __stdcall 支持会导致重复定义.

接口

概要 

namespace boost
{
    template<class T> T * get_pointer(T * p);

    template<class R, class T> unspecified-1 mem_fn(R (T::*pmf) ());

    template<class R, class T> unspecified-2 mem_fn(R (T::*pmf) () const);

    template<class R, class T> unspecified-2-1 mem_fn(R T::*pm);

    template<class R, class T, class A1> unspecified-3 mem_fn(R (T::*pmf) (A1));

    template<class R, class T, class A1> unspecified-4 mem_fn(R (T::*pmf) (A1) const);

    template<class R, class T, class A1, class A2> unspecified-5 mem_fn(R (T::*pmf) (A1, A2));

    template<class R, class T, class A1, class A2> unspecified-6 mem_fn(R (T::*pmf) (A1, A2) const);

    // implementation defined number of additional overloads for more arguments
}

共同要求

概要中提到的所有 unspecified-N 类型都是 CopyConstructible 与 Assignable 的. 其拷贝构造函数与赋值运算符不抛出异常. unspecified-N::result_type 定义为作为实参传给 mem_fn 的成员函数指针的返回类型 (概要中的 R). unspecified-2-1::result_type 定义为 R.

get_pointer 

template<class T> T * get_pointer(T * p)
  • 返回: p.
  • 抛出: 无.

mem_fn 

template<class R, class T> unspecified-1 mem_fn(R (T::*pmf) ())
  • 返回: 一个函数对象 ϝ, 使得表达式 ϝ(t) 等价于 (t.*pmf)() (当 t 是 T 类型或其派生类型的左值时), 否则等价于 (get_pointer(t)->*pmf)().
  • 抛出: 无.
template<class R, class T> unspecified-2 mem_fn(R (T::*pmf) () const)
  • 返回: 一个函数对象 ϝ, 使得表达式 ϝ(t) 等价于 (t.*pmf)() (当 t 的类型为 T [const] 或其派生类型时), 否则等价于 (get_pointer(t)->*pmf)().
  • 抛出: 无.
template<class R, class T> unspecified-2-1 mem_fn(R T::*pm)
  • 返回: 一个函数对象 ϝ, 使得表达式 ϝ(t) 等价于 t.*pm (当 t 的类型为 T [const] 或其派生类型时), 否则等价于 get_pointer(t)->*pm.
  • 抛出: 无.
template<class R, class T, class A1> unspecified-3 mem_fn(R (T::*pmf) (A1))
  • 返回: 一个函数对象 ϝ, 使得表达式 ϝ(t, a1) 等价于 (t.*pmf)(a1) (当 t 是 T 类型或其派生类型的左值时), 否则等价于 (get_pointer(t)->*pmf)(a1).
  • 抛出: 无.
template<class R, class T, class A1> unspecified-4 mem_fn(R (T::*pmf) (A1) const)
  • 返回: 一个函数对象 ϝ, 使得表达式 ϝ(t, a1) 等价于 (t.*pmf)(a1) (当 t 的类型为 T [const] 或其派生类型时), 否则等价于 (get_pointer(t)->*pmf)(a1).
  • 抛出: 无.
template<class R, class T, class A1, class A2> unspecified-5 mem_fn(R (T::*pmf) (A1, A2))
  • 返回: 一个函数对象 ϝ, 使得表达式 ϝ(t, a1, a2) 等价于 (t.*pmf)(a1, a2) (当 t 是 T 类型或其派生类型的左值时), 否则等价于 (get_pointer(t)->*pmf)(a1, a2).
  • 抛出: 无.
template<class R, class T, class A1, class A2> unspecified-6 mem_fn(R (T::*pmf) (A1, A2) const)
  • 返回: 一个函数对象 ϝ, 使得表达式 ϝ(t, a1, a2) 等价于 (t.*pmf)(a1, a2) (当 t 的类型为 T [const] 或其派生类型时), 否则等价于 (get_pointer(t)->*pmf)(a1, a2).
  • 抛出: 无.

参数数量

本实现支持至多八个实参的成员函数. 这不是设计上的固有限制, 而是实现细节.

__stdcall, __cdecl 与 __fastcall 支持

某些平台允许多种成员函数类型, 它们以调用约定相区分 (调用函数的规则: 实参如何传递, 返回值如何处理, 以及由谁清理栈 - 如果需要清理的话).

例如, Windows API 函数与 COM 接口成员函数使用称为 __stdcall 的调用约定. Borland VCL 组件使用 __fastcall. OpenOffice.org 的组件模型 UDK 使用 __cdecl.

要把 mem_fn 与 __stdcall 成员函数配合使用, 请 #define 宏 BOOST_MEM_FN_ENABLE_STDCALL, 然后再包含 <boost/mem_fn.hpp>.

要把 mem_fn 与 __fastcall 成员函数配合使用, 请 #define 宏 BOOST_MEM_FN_ENABLE_FASTCALL, 然后再包含 <boost/mem_fn.hpp>.

要把 mem_fn 与 __cdecl 成员函数配合使用, 请 #define 宏 BOOST_MEM_FN_ENABLE_CDECL, 然后再包含 <boost/mem_fn.hpp>.

最好在项目选项中定义这些宏, 即通过命令行上的 -D, 或作为使用 mem_fn 的翻译单元 (.cpp 文件) 的第一行. 不遵守这一规则可能导致难以理解错误: 当某个头文件在宏定义之前包含 mem_fn.hpp 时会出现难懂的错误.

[注释: 这是不可移植的扩展, 不属于接口的一部分.]

[注释: 某些编译器对 __stdcall 关键字只提供最基本的支持.]
