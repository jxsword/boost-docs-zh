目的

boost::bind 是标准函数 std::bind1st 与 std::bind2nd 的泛化. 它支持任意函数对象、函数、函数指针和成员函数指针, 能够把任意参数绑定到特定值, 或把输入实参路由到任意位置. bind 对函数对象不作任何要求; 特别是, 它不需要 result_type, first_argument_type 与 second_argument_type 这些标准 typedef.

对函数与函数指针使用 bind

给定这些定义:

int f(int a, int b)
{
    return a + b;
}

int g(int a, int b, int c)
{
    return a + b + c;
}

bind(f, 1, 2) 会产生一个"零参"函数对象, 它不接受任何实参并返回 f(1, 2). 类似地, bind(g, 1, 2, 3)() 等价于 to g(1, 2, 3).

可以选择性地只绑定部分实参. bind(f, _1, 5)(x) 等价于 f(x, 5); 这里 _1 是一个 占位符 实参, 意为"以第一个输入实参替代".

作为对比, 下面是用标准库原语表达的同一操作:

std::bind2nd(std::ptr_fun(f), 5)(x);

bind 也涵盖 std::bind1st 的功能:

std::bind1st(std::ptr_fun(f), 5)(x);   // f(5, x)
bind(f, 5, _1)(x);                     // f(5, x)

bind 可以处理多于两个实参的函数, 且其实参替换机制更为通用:

bind(f, _2, _1)(x, y);                 // f(y, x)
bind(g, _1, 9, _1)(x);                 // g(x, 9, x)
bind(g, _3, _3, _3)(x, y, z);          // g(z, z, z)
bind(g, _1, _1, _1)(x, y, z);          // g(x, x, x)

注意, 在最后一个示例中, 由 bind(g, _1, _1, _1) 产生的函数对象不包含对第一个实参之后任何实参的引用, 但它仍可以在多于一个实参的情况下使用. 任何多余的实参都被静默忽略, 就像第三个示例中第一个和第二个实参被忽略一样.

bind 接受的实参会被复制并由返回的函数对象在内部保存. 例如, 在下面的代码中:

int i = 5;
bind(f, i, _1);

i 的值的一份副本被存入该函数对象. boost::ref 与 boost::cref 可用于让函数对象保存对对象的引用而非副本:

int i = 5;
bind(f, ref(i), _1);
bind(f, cref(i), _1);

对函数对象使用 bind

bind 并不限于函数; 它接受任意函数对象. 一般情况下, 必须显式指定生成的函数对象的 operator() 的返回类型 (若没有 typeof 运算符, 返回类型无法推断):

struct F
{
    int operator()(int a, int b) { return a - b; }
    bool operator()(long a, long b) { return a == b; }
};

F f;
int x = 104;
bind<int>(f, _1, _1)(x);		// f(x, x), i.e. zero

某些编译器对 bind<R>(f, ...) 语法处理得不好. 出于可移植性考虑, 支持用另一种方式表达上述内容:

boost::bind(boost::type<int>(), f, _1, _1)(x);

但请注意, 该替代语法仅作为变通办法提供, 它不属于接口的一部分.

当函数对象暴露一个名为 result_type 的嵌套类型时, 显式返回类型可以省略:

int x = 8;
bind(std::less<int>(), _1, 9)(x);	// x < 9

[注释: 并非所有编译器都支持省略返回类型.]

默认情况下, bind 会复制提供的函数对象. boost::ref 与 boost::cref 可用于让它保存对函数对象的引用而非副本. 当函数对象不可复制、复制代价高或含有状态时, 这会很有用; 当然, 在这种情况下, 程序员需要自行确保函数对象在被使用期间不被销毁.

struct F2
{
    int s;

    typedef void result_type;
    void operator()(int x) { s += x; }
};

F2 f2 = { 0 };
int a[] = { 1, 2, 3 };

std::for_each(a, a+3, bind(ref(f2), _1));

assert(f2.s == 6);

对成员指针使用 bind

成员函数指针与数据成员指针不是函数对象, 因为它们不支持 operator(). 为方便起见, bind 接受成员指针作为其第一个实参, 其行为如同已用 boost::mem_fn 把该成员指针转换为函数对象. 换言之, 表达式

bind(&X::f, args)

等价于

bind<R>(mem_fn(&X::f), args)

其中 R 是 X::f 的返回类型 (对成员函数而言), 或该成员的类型 (对数据成员而言).

[注释: mem_fn 创建的函数对象能够接受指针、引用或智能指针指向的对象作为其第一个实参; 更多信息参见 mem_fn 的 文档.]

示例:

struct X
{
    bool f(int a);
};

X x;
shared_ptr<X> p(new X);
int i = 5;

bind(&X::f, ref(x), _1)(i);		// x.f(i)
bind(&X::f, &x, _1)(i);			// (&x)->f(i)
bind(&X::f, x, _1)(i);			// (internal copy of x).f(i)
bind(&X::f, p, _1)(i);			// (internal copy of p)->f(i)

最后两个示例很有意思, 因为它们产生"自包含"的函数对象. bind(&X::f, x, _1) 保存了 x 的一份副本. bind(&X::f, p, _1) 保存了 p 的一份副本, 且由于 p 是一个 boost::shared_ptr, 该函数对象保留对其 X 实例的引用, 即使 p 离开作用域或被 reset() 仍保持有效.

用嵌套 bind 进行函数组合

传给 bind 的某些实参本身可以是嵌套的 bind 表达式:

bind(f, bind(g, _1))(x);               // f(g(x))

当函数对象被调用时, 内层 bind 表达式 会在外层 bind 之前以未指明的顺序求值; 求值结果随后在外层 bind 求值时替换到其相应位置. 在上例中, 当函数对象以实参列表 (x) 被调用时, 先求值 bind(g, _1)(x), 得到 g(x), 然后求值 bind(f, g(x))(x), 得到最终结果 f(g(x)).

bind 的这一特性可用于执行函数组合. 参见 bind_as_compose.cpp, 其中的示例演示了如何用 bind 实现与 Boost.Compose 类似的功能.

注意, 第一个实参 - 即被绑定的函数对象 - 不会被求值, 即使它是由 bind 产生的函数对象或 占位符 实参也一样, 所以下面的示例不会按预期工作:

typedef void (*pf)(int);

std::vector<pf> v;
std::for_each(v.begin(), v.end(), bind(_1, 5));

期望的效果可以通过一个辅助函数对象 apply 实现, 它把其第一个实参 (作为函数对象) 应用到其实参列表的其余部分. 为方便起见, apply 的一个实现已在 apply.hpp 头文件中提供. 下面是前一个示例修改后的样子:

typedef void (*pf)(int);

std::vector<pf> v;
std::for_each(v.begin(), v.end(), bind(apply<void>(), _1, 5));

虽然第一个实参默认不求值, 其余所有实参都会求值. 有时需要不对第一个之后的实参求值, 即使它们是嵌套的 bind 子表达式. 这可以借助另一个函数对象 protect 实现, 它对类型加以遮蔽, 使 bind 无法识别并求值它. 被调用时, protect 只是把实参列表原封不动地转发给另一个函数对象.

头文件 protect.hpp 包含 protect 的一个实现. 要把 bind 函数对象 protect 以免被求值, 请使用 protect(bind(f, ...)).

重载运算符 (Boost 1.33 新增)

为方便起见, 由 bind 产生的函数对象重载了逻辑非运算符 ! 以及关系与逻辑运算符 ==, !=, <, <=, >, >=, &&, ||.

!bind(f, ...) 等价于 bind(logical_not(), bind(f, ...)), 其中 logical_not 是一个接受实参 x 并返回 !x 的函数对象.

bind(f, ...) op x (其中 op 是关系或逻辑运算符) 等价于 bind(relation(), bind(f, ...), x), 其中 relation 是一个接受实参 a 与 b 并返回 a op b 的函数对象.

实践中这意味着你可以方便地对 bind 的结果取反:

std::remove_if(first, last, !bind(&X::visible, _1)); // remove invisible objects

并把 bind 的结果与某个值比较:

std::find_if(first, last, bind(&X::name, _1) == "Peter");
std::find_if(first, last, bind(&X::name, _1) == "Peter" || bind(&X::name, _1) == "Paul");

与某个 占位符 比较:

bind(&X::name, _1) == _2

或与另一个 bind 表达式 比较:

std::sort(first, last, bind(&X::name, _1) < bind(&X::name, _2)); // sort by name

示例

在标准算法中使用 bind 

class image;

class animation
{
public:
    void advance(int ms);
    bool inactive() const;
    void render(image & target) const;
};

std::vector<animation> anims;

template<class C, class P> void erase_if(C & c, P pred)
{
    c.erase(std::remove_if(c.begin(), c.end(), pred), c.end());
}

void update(int ms)
{
    std::for_each(anims.begin(), anims.end(), boost::bind(&animation::advance, _1, ms));
    erase_if(anims, boost::mem_fn(&animation::inactive));
}

void render(image & target)
{
    std::for_each(anims.begin(), anims.end(), boost::bind(&animation::render, _1, boost::ref(target)));
}

对 Boost.Function 使用 bind 

class button
{
public:
    boost::function<void()> onClick;
};

class player
{
public:
    void play();
    void stop();
};

button playButton, stopButton;
player thePlayer;

void connect()
{
    playButton.onClick = boost::bind(&player::play, &thePlayer);
    stopButton.onClick = boost::bind(&player::stop, &thePlayer);
}

局限

一般而言, 由 bind 生成的函数对象按引用接受其实参, 因此不能接受非 const 临时对象或字面常量. 这是 C++ 语言当前 (2003) 形态的固有限制, 称为 转发问题. (它将在下一个标准 (通常称为 C++0x) 中得到解决.)

本库使用如下形式的签名

template<class T> void f(T & t);

来接受任意类型的实参并原样传递. 如前所述, 这对非 const 右值不适用.

在支持函数模板偏序的编译器上, 一种可能的解决方案是添加一个重载:

template<class T> void f(T & t);
template<class T> void f(T const & t);

遗憾的是, 这要求为九个实参提供 512 个重载, 不切实际. 库选择了一个小子集: 对至多两个实参, 它完整提供 const 重载; 对三个及以上元数的情形, 它提供单个附加重载, 其中所有实参均按 const 引用接受. 这覆盖了相当大一部分使用场景.

常见问题(FAQ)

为什么这段代码编译不过?

参见专门的 故障排除一节.

为什么这段代码能编译? 它本不该编译通过.

很可能是因为你使用了通用的 bind<R>(f, ...) 语法, 从而指示 bind 不要"检视" f 来探测元数和返回类型错误.

bind(f, ...) 与 bind<R>(f, ...) 有什么区别?

第一种形式指示 bind 检视 f 的类型, 以确定其元数 (实参个数) 与返回类型. 元数错误会在"绑定时刻"被探测到. 当然, 这种语法对 f 提出了一些要求. 它必须是函数、函数指针、成员函数指针, 或定义了名为 result_type 的嵌套类型的函数对象; 简言之, 它必须是 bind 能识别的东西.

第二种形式指示 bind 不要尝试识别 f 的类型. 它一般用于不暴露或无法暴露 result_type 的函数对象, 但也可用于非标准函数. 例如, 当前实现不会自动识别 printf 这类变参函数, 所以你必须使用 bind<int>(printf, ...). 注意, 出于可移植性考虑, 还支持另一种 bind(type<R>(), f, ...) 语法.

另一个需要考虑的重要因素是: 不支持偏特化或函数模板偏序的编译器, 在 f 是函数对象时无法处理第一种形式, 而且在大多数情况下, 当 f 是函数 (指针) 或成员函数指针时也无法处理第二种形式.

bind 能配合 Windows API 函数使用吗?

可以, 只要你 #define BOOST_BIND_ENABLE_STDCALL. 另一种办法是把该函数当作 泛型函数对象 对待, 并使用 bind<R>(f, ...) 语法.

bind 能配合 COM 方法使用吗?

可以, 只要你 #define BOOST_MEM_FN_ENABLE_STDCALL.

bind 能配合 Mac toolbox 函数使用吗?

可以, 只要你 #define BOOST_BIND_ENABLE_PASCAL. 另一种办法是把该函数当作 泛型函数对象 对待, 并使用 bind<R>(f, ...) 语法.

bind 能配合 extern "C" 函数使用吗?

视情况而定. 在某些平台上, 指向 extern "C" 函数的指针与"普通"函数指针等价, 因此工作正常. 其他平台把它们当作不同类型. bind 的平台特定实现应当透明地处理这一问题; 本实现没有这样做. 与往常一样, 变通办法是把该函数当作 泛型函数对象 对待, 并使用 bind<R>(f, ...) 语法.

为什么 bind 不能自动识别非标准函数?

一般而言, 不可移植的扩展应当默认关闭, 以防止厂商锁定. 如果 相应宏 被自动定义, 你可能在不知不觉中用上它们, 而没有意识到你的代码可能因此不再可移植. 此外, 某些编译器提供选项可把 __stdcall (__fastcall) 设为其默认调用约定, 此时就不需要单独的支持了.

故障排除

参数数量不正确

在 bind(f, a1, a2, ..., aN) 表达式中, 函数对象 f 必须恰好能接受 N 个实参. 该错误通常在"绑定时刻"被探测到; 换言之, 编译错误会在调用 bind() 的那一行报告:

int f(int, int);

int main()
{
    boost::bind(f, 1);    // error, f takes two arguments
    boost::bind(f, 1, 2); // OK
}

这一错误的一个常见变体是忘记成员函数有一个隐式的 "this" 实参:

struct X
{
    int f(int);
}

int main()
{
    boost::bind(&X::f, 1);     // error, X::f takes two arguments
    boost::bind(&X::f, _1, 1); // OK
}

函数对象无法以指定实参调用

与普通函数调用一样, 被绑定的函数对象必须与实参列表兼容. 这种不兼容通常会在"调用时刻"由编译器探测到, 结果通常是在形如下面的行上的 bind.hpp 中报错:

return f(a[a1_], a[a2_]);

这类错误的一个示例:

int f(int);

int main()
{
    boost::bind(f, "incompatible");      // OK so far, no call
    boost::bind(f, "incompatible")();    // error, "incompatible" is not an int
    boost::bind(f, _1);                  // OK
    boost::bind(f, _1)("incompatible");  // error, "incompatible" is not an int
}

访问不存在的参数

占位符 _N 会在"调用时刻"传入的实参列表中选择位于位置 N 的实参. 自然, 试图访问超出该列表末尾的位置是一个错误:

int f(int);

int main()
{
    boost::bind(f, _1);                  // OK
    boost::bind(f, _1)();                // error, there is no argument number 1
}

该错误通常在 bind.hpp 中报告, 出错行类似于:

return f(a[a1_]);

在模拟 std::bind1st(f, a) 时, 这一类别的常见错误是把 bind(f, a, _2) 写成 bind(f, a, _1) (正确写法) 的错误形式.

不当使用 bind(f, ...)

bind(f, a1, a2, ..., aN) 这种 形式 会对 f 的类型进行自动识别. 它不适用于任意函数对象; f 必须是函数或成员函数指针.

可以在定义了 result_type 的函数对象上使用这种形式, 但仅限于支持偏特化与偏序的编译器. 特别是, MSVC 7.0 及更早版本不支持对函数对象使用这一语法.

不当使用 bind<R>(f, ...)

bind<R>(f, a1, a2, ..., aN) 这种 形式 支持任意函数对象.

可以把这种形式用于函数或成员函数指针 (但不推荐), 但仅限于支持偏序的编译器. 特别是, MSVC 7.0 及更早版本不完全支持对函数和成员函数指针使用这一语法.

绑定非标准函数

默认情况下, bind(f, a1, a2, ..., aN) 这种 形式 能识别"普通" C++ 函数与函数指针. 使用不同调用约定的函数, 或 std::printf 这类变参函数, 则不适用. 通用的 bind<R>(f, a1, a2, ..., aN) 这种 形式 可用于非标准函数.

在某些平台上, 像 std::strcmp 这样的 extern "C" 函数不会被 bind 的短形式识别.

另请参见 __stdcall 与 pascal 支持.

绑定重载函数

尝试绑定重载函数通常会导致错误, 因为无法得知想要绑定的是哪个重载. 这是具有 const 与非 const 两个重载的成员函数的常见问题, 如下面这个简化示例:

struct X
{
    int& get();
    int const& get() const;
};

int main()
{
    boost::bind(&X::get, _1);
}

歧义可以通过把 (成员) 函数指针显式转换为目标类型来手工消解:

int main()
{
    boost::bind(static_cast< int const& (X::*) () const >(&X::get), _1);
}

另一种可以说更具可读性的替代办法是引入一个临时变量:

int main()
{
    int const& (X::*get) () const = &X::get;
    boost::bind(get, _1);
}

建模 STL 函数对象概念

由 bind 产生的函数对象不建模 STL 的 Unary Function 或 Binary Function 概念, 即使这些函数对象是一元或二元运算也是如此, 因为函数对象类型缺少公有 typedef result_type 与 argument_type, 或 first_argument_type 与 second_argument_type. 不过, 在需要这些 typedef 的场合, 可以用工具函数 make_adaptable 把一元与二元函数对象适配到这些概念. 这使得由 bind 产生的一元与二元函数对象能够与 std::unary_negate 和 std::binary_negate 等 STL 模板配合使用.

make_adaptable 函数定义在 <boost/bind/make_adaptable.hpp> 中, 除 <boost/bind/bind.hpp> 之外还必须显式包含它:

#include <boost/bind/make_adaptable.hpp>

template <class R, class F> unspecified-type make_adaptable(F f);

template<class R, class A1, class F> unspecified-unary-functional-type make_adaptable(F f);

template<class R, class A1, class A2, class F> unspecified-binary-functional-type make_adaptable(F f);

template<class R, class A1, class A2, class A3, class F> unspecified-ternary-functional-type make_adaptable(F f);

template<class R, class A1, class A2, class A3, class A4, class F> unspecified-4-ary-functional-type make_adaptable(F f);

本示例演示如何用 make_adaptable 制作"不是空白"的谓词:

typedef char char_t;
std::locale loc("");
const std::ctype<char_t>& ct = std::use_facet<std::ctype<char_t> >(loc);

auto isntspace = std::not1(boost::make_adaptable<bool, char_t>(boost::bind(&std::ctype<char_t>::is, &ct, std::ctype_base::space, _1)));

在本例中, bind 创建"是空白"的 (一元) 谓词. 然后把它传给 make_adaptable, 以便创建一个建模 Unary Function 概念的函数对象, 作为 std::not1 的实参.

const 在签名中

包括 MSVC 6.0 与 Borland C++ 5.5.1 在内的一些编译器, 对函数签名中顶层的 const 有问题:

int f(int const);

int main()
{
    boost::bind(f, 1);     // error
}

变通办法: 从实参中移除 const 限定符.

MSVC 特有: using boost::bind;

在 MSVC (7.0 及更早版本) 上, 当通过 using 声明把 boost::bind 引入作用域时:

using boost::bind;

语法 bind<R>(f, ...) 不起作用. 变通办法: 要么使用限定名 boost::bind, 要么改用 using 指示:

using namespace boost;

MSVC 特有: 类模板遮蔽函数模板

在 MSVC (7.0 及更早版本) 上, 名为 bind 的嵌套类模板会遮蔽函数模板 boost::bind, 从而破坏 bind<R>(f, ...) 语法. 遗憾的是, 某些库含有名为 bind 的嵌套类模板 (讽刺的是, 这样的代码往往正是针对 MSVC 的变通办法).

变通办法是使用另一种 bind(type<R>(), f, ...) 语法.

MSVC 特有: 签名中的 ... 被当作类型

MSVC (7.0 及更早版本) 把变参函数 (例如 std::printf) 中的省略号当作一个类型. 因此它会接受 (在当前实现中不正确的) 形式:

bind(printf, "%s\n", _1);

并拒绝正确的版本:

bind<int>(printf, "%s\n", _1);

共同要求

所有 unspecified-N 类型 (由 bind 返回) 都是 CopyConstructible 的. unspecified-N::result_type 定义为 unspecified-N::operator() 的返回类型.

所有 unspecified-placeholder-N 类型都是 CopyConstructible 的. 其拷贝构造函数不抛出异常.

共同定义

函数 μ(x, v1, v2, ..., vm) (其中 m 是非负整数) 定义为:

  • x.get(), 当 x 的类型为 boost::reference_wrapper<T> (对某个类型 T) 时;
  • vk, 当 x 是占位符 _k 的 (副本) 时, 其中 k 为某个正整数;
  • x(v1, v2, ..., vm), 当 x 是由 bind 返回的函数对象的 (副本) 时;
  • x, 其他情况.

bind 

template<class R, class F> unspecified-1 bind(F f)
  • 返回: 一个函数对象 λ, 使得表达式 λ(v1, v2, ..., vm) 等价于 f() (隐式转换为 R).
  • 抛出: 无, 除非 F 的拷贝构造函数抛出异常.
template<class F> unspecified-1-1 bind(F f)
  • 效果: 等价于 bind<typename F::result_type, F>(f).
  • 注释: 允许实现作为扩展, 通过其他手段推断 f 的返回类型, 而不依赖 result_type 成员.
template<class R> unspecified-2 bind(R (*f) ())
  • 返回: 一个函数对象 λ, 使得表达式 λ(v1, v2, ..., vm) 等价于 f().
  • 抛出: 无.
template<class R, class F, class A1> unspecified-3 bind(F f, A1 a1)
  • 返回: 一个函数对象 λ, 使得表达式 λ(v1, v2, ..., vm) 等价于 f(μ(a1, v1, v2, ..., vm)) (隐式转换为 R).

__stdcall, __cdecl, __fastcall 与 pascal 支持

某些平台允许多种 (成员) 函数类型, 它们以调用约定相区分 (调用函数的规则: 实参如何传递, 返回值如何处理, 以及由谁清理栈 - 如果需要清理的话).

例如, Windows API 函数与 COM 接口成员函数使用称为 __stdcall 的调用约定. Borland VCL 组件使用 __fastcall. Mac toolbox 函数使用 pascal 调用约定.

要把 bind 与 __stdcall 函数配合使用, 请 #define 宏 BOOST_BIND_ENABLE_STDCALL, 然后再包含 <boost/bind/bind.hpp>.

要把 bind 与 __stdcall 成员函数配合使用, 请 #define 宏 BOOST_MEM_FN_ENABLE_STDCALL, 然后再包含 <boost/bind/bind.hpp>.

要把 bind 与 __fastcall 函数配合使用, 请 #define 宏 BOOST_BIND_ENABLE_FASTCALL, 然后再包含 <boost/bind/bind.hpp>.

要把 bind 与 __fastcall 成员函数配合使用, 请 #define 宏 BOOST_MEM_FN_ENABLE_FASTCALL, 然后再包含 <boost/bind/bind.hpp>.

要把 bind 与 pascal 函数配合使用, 请 #define 宏 BOOST_BIND_ENABLE_PASCAL, 然后再包含 <boost/bind/bind.hpp>.

要把 bind 与 __cdecl 成员函数配合使用, 请 #define 宏 BOOST_MEM_FN_ENABLE_CDECL, 然后再包含 <boost/bind/bind.hpp>.

最好在项目选项中定义这些宏, 即通过命令行上的 -D, 或作为使用 bind 的翻译单元 (.cpp 文件) 的第一行. 不遵守这一规则可能导致难以理解错误: 当某个头文件在宏定义之前包含 bind.hpp 时会出现难懂的错误.

[注释: 这是不可移植的扩展, 不属于接口的一部分.]

[注释: 某些编译器对 __stdcall 关键字只提供最基本的支持.]
