元组 (或 N 元组) 是大小固定的元素集合. 对 (pair)、三元组 (triple)、四元组 (quadruple) 等都是元组. 在程序设计语言中, 元组是一种以其他对象为元素的数据对象. 这些元素对象可以是不同类型.

元组在许多场合都很方便. 例如, 元组使得定义返回多个值的函数变得容易.

某些程序设计语言 (如 ML、Python 和 Haskell) 内置了元组构造. 遗憾的是 C++ 没有. 为了弥补这一"缺陷", Boost Tuple Library 使用模板实现了元组构造.

使用本库

要使用本库, 只需包含:

#include "boost/tuple/tuple.hpp"

比较运算符可通过如下方式包含:

#include "boost/tuple/tuple_comparison.hpp"

要使用元组的输入输出运算符,

#include "boost/tuple/tuple_io.hpp"

tuple_io.hpp 和 tuple_comparison.hpp 都包含了 tuple.hpp.

所有定义都位于命名空间 ::boost::tuples 中, 但最常用的名字通过 using 声明提升到命名空间 ::boost. 这些名字是: tuple、make_tuple、tie 和 get. 此外, ref 和 cref 直接定义在 ::boost 命名空间之下.

元组类型

元组类型是 tuple 模板的实例化. 模板参数指定元组元素的类型. 当前版本支持 0 至 10 个元素的元组. 如有必要, 该上限可以增加到几十个元素. 数据元素可以是任何 C++ 类型. 注意, void 和普通函数类型是有效的 C++ 类型, 但这种类型的对象不能存在. 因此, 如果元组类型把这样的类型作为元素, 该元组类型可以存在, 但不能有该类型的对象. 对于不能拷贝或不能默认构造的元素类型, 存在自然的限制 (见下文'构造元组').

例如, 以下定义是有效的元组实例化 (A、B 和 C 是某些用户定义的类):

tuple<int>
tuple<double&, const double&, const double, double*, const double*>
tuple<A, int(*)(char, int), B(A::*)(C&), C>
tuple<std::string, std::pair<A, B> >
tuple<A*, tuple<const A*, const B&, C>, bool, void*>

构造元组

元组构造函数以元组元素为实参. 对于 n 元元组, 构造函数可以以 k 个实参调用, 其中 0 <= k <= n. 例如:

tuple<int, double>()
tuple<int, double>(1)
tuple<int, double>(1, 3.14)

如果某个元素没有提供初始值, 它会被默认初始化 (因此必须可默认初始化). 例如:

class X {
  X();
public:
  X(std::string);
};

tuple<X,X,X>()                                              // error: no default constructor for X
tuple<X,X,X>(string("Jaba"), string("Daba"), string("Duu")) // ok

特别地, 引用类型没有默认初始化:

tuple<double&>()                // error: reference must be
                                // initialized explicitly

double d = 5;
tuple<double&>(d)               // ok

tuple<double&>(d+3.14)          // error: cannot initialize
                                // non-const reference with a temporary

tuple<const double&>(d+3.14)    // ok, but dangerous:
                                // the element becomes a dangling reference

为无法拷贝的元素提供初始值会导致编译期错误:

class Y {
  Y(const Y&);
public:
  Y();
};

char a[10];

tuple<char[10], Y>(a, Y()); // error, neither arrays nor Y can be copied
tuple<char[10], Y>();       // ok

需要特别注意的是, 以下做法完全没有问题:

Y y;
tuple<char(&)[10], Y&>(a, y);

也可能构造出一个无法构造的元组类型. 当无法初始化的元素的索引低于需要初始化的元素时就会发生这种情况. 例如: tuple<char[10], int&>.

总而言之, 元组构造在语义上只是一组相互独立的逐元素构造.

make_tuple 函数

也可以使用 make_tuple (对照 std::make_pair) 辅助函数构造元组. 这使构造更加方便, 程序员无需显式指定元素类型:

tuple<int, int, double> add_multiply_divide(int a, int b) {
  return make_tuple(a+b, a*b, double(a)/double(b));
}

默认情况下, 元素类型被推导为普通的非引用类型. 例如:

void foo(const A& a, B& b) {
  ...
  make_tuple(a, b);

make_tuple 调用会产生 tuple<A, B> 类型的元组.

有时并不想要普通的非引用类型, 例如元素类型无法拷贝时. 因此, 程序员可以控制类型推导, 声明应使用 const 引用或非 const 引用类型作为元素类型. 这通过两个辅助模板函数实现: boost::ref 和 boost::cref. 任何实参都可以用这些函数包装以获得所需类型. 该机制不会破坏 const 正确性, 因为用 ref 包装的 const 对象会产生 const 引用类型的元组元素 (见下面第五个示例). 例如:

A a; B b; const A ca = a;
make_tuple(cref(a), b);      // creates tuple<const A&, B>
make_tuple(ref(a), b);       // creates tuple<A&, B>
make_tuple(ref(a), cref(b)); // creates tuple<A&, const B&>
make_tuple(cref(ca));        // creates tuple<const A&>
make_tuple(ref(ca));         // creates tuple<const A&>

make_tuple 函数的数组实参默认被推导为 const 引用类型; 无需用 cref 包装它们. 例如:

make_tuple("Donald", "Daisy");

这会创建 tuple<const char (&)[7], const char (&)[6]> 类型的对象 (注意, 字符串字面量的类型是 const 字符的数组, 而不是 const char*). 然而, 要让 make_tuple 创建包含非 const 数组类型元素的元组, 必须使用 ref 包装器.

函数指针被推导为普通的非引用类型, 即普通函数指针. 元组也可以持有对函数的引用, 但这样的元组不能用 make_tuple 构造 (会产生带 const 限定的函数类型, 这是非法的):

void f(int i);
  ...
make_tuple(&f); // tuple<void (*)(int)>
  ...
tuple<tuple<void (&)(int)> > a(f) // ok
make_tuple(f);                    // not ok

访问元组元素

元组元素通过以下表达式访问:

t.get<N>()

或者

get<N>(t)

其中 t 是元组对象, N 是指定要访问元素索引的常量整数表达式. 根据 t 是否为 const, get 以 const 或非 const 类型的引用返回第 N 个元素. 第一个元素的索引是 0, 因此 N 必须介于 0 与 k-1 之间, 其中 k 是元组中元素的个数. 违反这些约束会在编译期检测出来. 示例:

double d = 2.7; A a;
tuple<int, double&, const A&> t(1, d, a);
const tuple<int, double&, const A&> ct = t;
  ...
int i = get<0>(t); i = t.get<0>();        // ok
int j = get<0>(ct);                       // ok
get<0>(t) = 5;                            // ok
get<0>(ct) = 5;                           // error, can't assign to const
  ...
double e = get<1>(t); // ok
get<1>(t) = 3.14;     // ok
get<2>(t) = A();      // error, can't assign to const
A aa = get<3>(t);     // error: index out of bounds
  ...
++get<0>(t);  // ok, can be used as any variable

[注释: MS Visual C++ 编译器不支持成员 get 函数. 此外, 若无显式命名空间限定符, 该编译器难以找到非成员 get 函数. 因此, 在编写需要用 MSVC++ 6.0 编译的代码时, 所有 get 调用都应限定为 tuples::get<N>(a_tuple).]

拷贝构造与元组赋值

只要元素类型可逐元素拷贝构造, 元组就可以从另一个元组拷贝构造. 类似地, 只要元素类型可逐元素赋值, 元组就可以赋给另一个元组. 例如:

class A {};
class B : public A {};
struct C { C(); C(const B&); };
struct D { operator C() const; };
tuple<char, B*, B, D> t;
  ...
tuple<int, A*, C, C> a(t); // ok
a = t;                     // ok

两种情况下执行的转换是:

  • char -> int,
  • B* -> A* (派生类指针到基类指针),
  • B -> C (用户定义的转换), 以及
  • D -> C (用户定义的转换).

注意, 从 std::pair 类型进行的赋值也有定义:

tuple<float, int> a = std::make_pair(1, 'a');

关系运算符

元组将运算符 ==、!=、<、>、<= 和 >= 归约为相应的基本运算符. 这意味着, 如果这些运算符中的某一个在两个元组的所有元素之间都有定义, 那么该运算符在元组之间也有定义. 两个元组 a 和 b 的相等运算符定义为:

  • a == b 当且仅当对每个 i: ai == bi
  • a != b 当且仅当存在 i: ai != bi

运算符 <、>、<= 和 >= 实现字典序.

注意, 比较两个长度不同的元组会导致编译期错误. 此外, 比较运算符是"短路"的: 基本比较从第一个元素开始, 只进行到结果明确为止.

示例:

tuple<std::string, int, A> t1(std::string("same?"), 2, A());
tuple<std::string, long, A> t2(std::string("same?"), 2, A());
tuple<std::string, long, A> t3(std::string("different"), 3, A());

bool operator==(A, A) { std::cout << "All the same to me..."; return true; }

t1 == t2;               // true
t1 == t3;               // false, does not print "All the..."

层级

层组 (tier) 是所有元素均为非 const 引用类型的元组. 它们通过调用 tie 函数模板构造 (对照 make_tuple):

int i; char c; double d;
  ...
tie(i, c, a);

上面的 tie 函数创建 tuple<int&, char&, double&> 类型的元组. 同样的结果也可以通过调用 make_tuple(ref(i), ref(c), ref(a)) 得到.

包含非 const 引用作为元素的元组可用于把另一个元组"解包"到变量中. 例如:

int i; char c; double d;
tie(i, c, d) = make_tuple(1,'a', 5.5);
std::cout << i << " " <<  c << " " << d;

此代码将 1 a 5.5 打印到标准输出流. 类似这样的元组解包操作可见于 ML 和 Python 等语言. 在调用返回元组的函数时非常方便.

绑定 (tying) 机制同样适用于 std::pair 模板:

int i; char c;
tie(i, c) = std::make_pair(1, 'a');

Ignore

还有一个名为 ignore 的对象, 它允许你忽略元组赋值的某个元素. 其设想是: 函数可能返回一个元组, 而你只对其中一部分感兴趣. 例如 (注意, ignore 位于 tuples 子命名空间中):

char c;
tie(tuples::ignore, c) = std::make_pair(1, 'a');

流式输出

全局 operator<< 已针对 std::ostream 进行重载, 使得元组通过对每个元素递归调用 operator<< 来输出.

类似地, 全局 operator>> 也被重载, 用于从 std::istream 中通过对每个元素递归调用 operator>> 来提取元组.

元素之间的默认分隔符是空格, 元组被括在圆括号中. 例如:

tuple<float, int, std::string> a(1.0f,  2, std::string("Howdy folks!");

cout << a;

将元组输出为: (1.0 2 Howdy folks!)

本库定义了三个用于更改默认行为的操纵器:

  • set_open(char) 定义第一个元素之前输出的字符.
  • set_close(char) 定义最后一个元素之后输出的字符.
  • set_delimiter(char) 定义元素之间的分隔符字符.

注意, 这些操纵符定义在 tuples 子命名空间中. 例如:

cout << tuples::set_open('[') << tuples::set_close(']') << tuples::set_delimiter(',') << a;

将同一元组 a 输出为: [1.0,2,Howdy folks!]

同样的操纵符也适用于 operator>> 和 istream. 设 cin 流包含以下数据:

(1 2 3) [4:5]

如下代码:

tuple<int, int, int> i;
tuple<int, int> j;

cin >> i;
cin >> tuples::set_open('[') >> tuples::set_close(']') >> tuples::set_delimiter(':');
cin >> j;

将数据读入元组 i 和 j.

注意, 使用 std::string 或 C 风格字符串元素提取元组通常行不通, 因为流式元组表示可能无法被无歧义地解析.

性能

所有元组访问与构造函数都是简短的内联单行代码. 因此, 一个像样的编译器可以消除使用元组相对于手写类元组类的任何额外开销. 特别是, 使用像样的编译器时, 这段代码:

class hand_made_tuple {
  A a; B b; C c;
public:
  hand_made_tuple(const A& aa, const B& bb, const C& cc)
    : a(aa), b(bb), c(cc) {};
  A& getA() { return a; };
  B& getB() { return b; };
  C& getC() { return c; };
};

hand_made_tuple hmt(A(), B(), C());
hmt.getA(); hmt.getB(); hmt.getC();

与这段代码:

tuple<A, B, C> t(A(), B(), C());
t.get<0>(); t.get<1>(); t.get<2>();

注意, 存在一些广泛使用的编译器 (如 bcc 5.5.1) 无法优化这种元组用法.

取决于编译器的优化能力, 与使用非 const 引用参数作为从函数返回多个值的机制相比, tier 机制可能带来微小的性能损失. 例如, 假设以下函数 f1 和 f2 具有等价的功能:

void f1(int&, double&);
tuple<int, double> f2();

那么, 在下面的代码中, 调用 #1 可能比 #2 略快:

int i; double d;
  ...
f1(i,d);         // #1
tie(i,d) = f2(); // #2

关于效率的更深入讨论参见 [1, 2].

对编译期的影响

由于模板实例化数量过多, 编译元组可能很慢. 取决于编译器和元组长度, 编译一个元组构造可能比编译等价的显式编写的类 (如上面的 hand_made_tuple 类) 慢 10 倍以上. 不过, 由于一个现实的程序除了元组定义外还可能包含大量代码, 这一差异可能察觉不到. 对非常频繁使用元组的程序, 测得编译时间增加 5% 到 10%. 在同样的测试程序上, 编译的内存消耗增加 22% 到 27%. 详情参见 [1, 2].
