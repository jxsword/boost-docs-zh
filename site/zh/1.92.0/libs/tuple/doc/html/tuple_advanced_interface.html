元组类型的元函数

设 T 是一个元组类型, N 是一个常量整数表达式.

element<N, T>::type

给出第 N 个元素在元组类型 T 中的类型. 若 T 为 const, 则结果类型同样带 const 限定. 注意, T 的常量性不影响引用类型的元素.

length<T>::value

给出元组类型 T 的长度.

cons 列表

元组在内部表示为 cons 列表. 例如, 元组

tuple<A, B, C, D>

继承自类型

cons<A, cons<B, cons<C, cons<D, null_type> > > >

tuple 模板提供 typedef inherited 来访问 cons 列表表示. 例如: tuple<A>::inherited 是类型 cons<A, null_type>.

空元组

空元组 tuple<> 的内部表示是 null_type.

头与尾

tuple 模板与 cons 模板都提供 typedef head_type 和 tail_type. head_type typedef 给出元组 (或 cons 列表) 第一个元素的类型. tail_type typedef 给出移除第一个元素后剩余的 cons 列表. 头元素存储在成员变量 head 中, 尾列表存储在成员变量 tail 中. cons 列表提供成员函数 get_head() 用于获取 cons 列表头的引用, 以及 get_tail() 用于获取尾的引用. 这两个函数都有 const 与非 const 版本.

注意, 在单元素元组中, tail_type 等于 null_type, 且 get_tail() 函数返回 null_type 类型的对象.

空元组 (null_type) 没有头也没有尾, 因此不提供 get_head 和 get_tail 函数.

把元组当作 cons 列表处理, 为定义操作元组的泛型函数提供了便利手段. 例如, 下面这对函数模板将 0 赋给元组的每个元素 (显然, 赋值对元素类型必须是有效操作):

inline void set_to_zero(const null_type&) {};

template <class H, class T>
inline void set_to_zero(cons<H, T>& x) { x.get_head() = 0; set_to_zero(x.get_tail()); }

构造 cons 列表

只要所有元素都能默认构造, cons 列表就可以默认构造.

cons 列表可以由其头和尾构造. 构造函数的原型为:

cons(typename access_traits<head_type>::parameter_type h, const tail_type& t)

针对头参数的特征模板为不同种类的元素类型选择正确的参数类型 (对引用元素, 参数类型等于元素类型; 对非引用类型, 参数类型是 const 非 volatile 元素类型的引用).

对单元素 cons 列表, 尾实参 (null_type) 可以省略.

元组元素类型的特征类

access_traits

模板 access_traits 定义了三个类型函数. 设 T 为元组中某元素的类型:

  • access_traits<T>::non_const_type 将 T 映射到非 const 访问函数的返回类型 (非成员与成员 get 函数, 以及 get_head 函数).
  • access_traits<T>::const_type 将 T 映射到 const 访问函数的返回类型.
  • access_traits<T>::parameter_type 将 T 映射到元组构造函数的参数类型.

make_tuple_traits

用 make_tuple 函数创建的元组, 其元素类型通过类型函数 make_tuple_traits 计算. 类型函数调用 make_tuple_traits<T>::type 实现以下类型映射:

  • 任何引用类型 -> 编译期错误
  • 任何数组类型 -> 该数组类型的常量引用
  • reference_wrapper<T> -> T&
  • T -> T

reference_wrapper 类型的对象通过 ref 和 cref 函数创建 (参见 make_tuple 函数).

引用包装器最初是元组库的一部分, 但现在已是 boost 的通用工具. reference_wrapper 模板以及 ref 和 cref 函数定义在主 boost include 目录下的单独文件 ref.hpp 中, 并直接位于 boost 命名空间中.
