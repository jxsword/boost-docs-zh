可选返回值

让我们编写并使用一个把 std::string 转换为 int 的转换函数. 对于给定的字符串 (如 "cat"), 可能不存在能表示转换结果的 int 类型的值. 我们不把这种情况视为错误. 我们期望该转换器只被用于检查转换是否可能. 该函数的一个自然签名可以是:

#include <boost/optional.hpp>
boost::optional<int> convert(const std::string& text);

所有必需的功能都可以用一个头文件 <boost/optional.hpp> 包含. 上述函数签名意味着该函数要么返回类型 int 的值, 要么返回一个标志, 表明没有可用的 int 值. 这并不表示错误. 它就像 int 的一个附加取值. 我们可以这样使用该函数:

const std::string& text = /*... */;
boost::optional<int> oi = convert(text); // move-construct
if (oi)                                  // contextual conversion to bool
  int i = *oi;                           // operator*

为了测试 optional 是否包含值, 我们使用到类型 bool 的按语境转换. 由此, 我们可以把可选对象的初始化与测试合并成一条指令:

if (boost::optional<int> oi = convert(text))
  int i = *oi;

我们用 operator* (以及在有意义之处用 operator->) 提取所含的值. 试图从未初始化的可选对象提取所含值是一种 未定义行为 (UB). 本实现用 BOOST_ASSERT 保护该调用. 因此在提取之前, 你应当确定所含值确实存在. 例如, 以下代码在合理程度上是 UB 安全的:

int i = *convert("100");

这是因为我们知道字符串值 "100" 会转换为 int 的有效值. 如果你不喜欢这种潜在的 UB, 可以使用另一种提取所含值的方式:

try {
  int j = convert(text).value();
}
catch (const boost::bad_optional_access&) {
  // deal with it
}

该版本在试图访问不存在的所含值时会抛出异常. 若你应对缺失值的方式是使用某个默认值, 如 0, 还有另一种选择:

int k = convert(text).value_or(0);

这采用类似 atoi 的转换方式: 若 text 不表示一个整数, 就直接返回 0. 最后, 你可以提供一个回调, 在尝试访问所含值失败时调用:

int fallback_to_default()
{
  cerr << "could not convert; using -1 instead" << endl;
  return -1;
}

int l = convert(text).value_or_eval(fallback_to_default);

这将调用所提供的回调并返回回调的返回值. 该回调可以有副作用: 只有当可选对象不含值时才会观察到这些副作用.

现在, 让我们考虑如何实现函数 convert.

boost::optional<int> convert(const std::string& text)
{
  std::stringstream s(text);
  int i;
  if ((s >> i) && s.get() == std::char_traits<char>::eof())
    return i;
  else
    return boost::none;
}

观察两个 return 语句. return i 使用能把 optional<T> 从 T 创建出来的转换构造函数. 这样构造出的可选对象是已初始化的, 其值是 i 的副本. 另一个 return 语句使用来自特殊标签 boost::none 的另一个转换构造函数. 它用于表明我们想创建一个未初始化的可选对象.
