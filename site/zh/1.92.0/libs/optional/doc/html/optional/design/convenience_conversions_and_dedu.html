便捷转换与推导

与 std::optional 不同, boost::optional 不提供许多 "便捷" 转换构造函数、混合关系运算以及类模板参数推导.

std::optional oi = 1;                 // OK

std:string_view sv = "hi";
std::optional<std::string> os = sv;   // OK
os == sv;                             // OK

std::optional<std::string> osv;
std::optional<std::string> os2 = osv; // OK
os2 == osv;                           // OK

它们很实用, 有时也来自对一致性的论证: 若 (optT && *optT == u) 可行, 那么 (optT == u) 也应当可行.

然而, 这些智能的便捷函数有时会产生与程序员意图相悖的结果, 并造成无声的缺陷.

考虑一个更复杂的例子:

Threshold th = /*...*/;
std::optional o = th;
assert (o);

在这段代码中, 我们能否期望这样初始化的 optional 包含一个值?答案是: 这取决于 Threshold 的类型. 它可以定义为:

using Threshold = std::optional<int>;

然后断言将触发. 这是因为在这种情形下, 智能逻辑认定: 既然我们已经有一个 optional, 再包装进另一个 optional 是不必要的.

如果我们显式指定模板类型, 情况也不会变得不那么复杂.

Threshold th;
std::optional<Threshold> o = th;
assert(o);

这个断言会触发吗?现在我们有两个相互竞争的构造函数:

template <typename U>
optional(U const&);

template <typename U>
optional(optional<U> const&);

哪一个会被选中?实际上我们很幸运, 由于概念技巧, 被选中的将是第一个. 但让我们试一个不同的例子:

Threshold th;
std::optional<Threshold> o = th;
assert(o);
assert(o == th);

这里, 第一个断言通过, 但第二个触发. 这是因为比较运算符有两个相互竞争的重载:

template <typename T, typename U>
bool operator==(optional<T> const&, U const&);

template <typename T, typename U>
bool operator==(optional<T> const&, optional<U> const&);

而这一次没有概念技巧, 因此第二个重载被选中, 并给出不同结果: 我们在比较一个不含值的 optional 对象 th 与一个含值的 optional 对象 o.

这一问题——操作能编译, 但运行期行为与程序员直觉相悖——随着概念引入 C++ 而获得了新的意义.

static_assert(std::equality_comparable_with<std::optional<Threshold>, Threshold>);

概念既有语法约束, 也有语义约束. 语法约束由编译器静态检查. 对语义约束而言, 使用该概念的函数相信程序员会满足这些约束; 若不满足, 就是 未定义行为.

这些是 std::optional 的问题. boost::optional 没有这些问题, 因为它不提供上述便捷操作.

boost::optional 的设计原则是: 不提供那种在 95% 的情形中能很好地推断程序员意图、而在其余 5% 的情形中产生与程序员预期相悖效果的功能.

相反, 本库建议使用在 100% 的情形中都有效的更啰嗦的语法:

Threshold th;
auto o = boost::make_potional(th);   // *always* add a new layer of optionality

return boost::equal_pointees(o, th); // *always* unpack optionals for comparison
return o && *o == th;    // *always* treat the right-hand side argument as value
