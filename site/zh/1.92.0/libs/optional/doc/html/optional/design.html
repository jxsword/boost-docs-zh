设计目标

在 C++ 中, 你可以创建一个标量类型的自动对象并操纵它, 而不给它赋初值.

{
  int i; // indeterminate value
  populate(&i);
  cout << i;
}

这样的对象被称为具有 不确定值. 如果你随后为该对象赋予恰当的值, 一切正常; 但若程序试图读取不确定值, 这是 未定义行为, 且自 C++26 起这是 错误行为. 无论如何, 程序现在很可能做出程序员未曾打算的事情. 如果你有一个对象 i, 但不知道它具有的是不确定值还是正常的、预期的值, 没有办法检查它, 因为检查本身就需要读取该值.

这是 optional 旨在解决的主要问题之一: 让你可以拥有一个知道自己是否被赋予了恰当值的类型, 并且在被要求时能告诉你.

对于类型 int, 这样一个类的内部表示可以是:

class OptionalInt
{
  bool _has_value = false;
  int _value;
};

一般情况下, 内部表示等价于:

template <typename T>
class Optional
{
  bool _has_value = false;
  alignas(T) char _value [sizeof(T)];
};

或者:

template <typename T>
class Optional
{
  bool _has_value = false;
  union {
    T         _value;
    DummyType _non_value;
  };
};

接下来, 因为我们需要把这些 "可选的" int 像普通 int 一样四处传递 (比如从函数返回它们), 在复制时, 我们需要复制 _has_value (它表明我们是否有值), 并且仅当我们确实有值时, 才还要复制 _value.

这意味着我们的类型需要 深复制 语义.
