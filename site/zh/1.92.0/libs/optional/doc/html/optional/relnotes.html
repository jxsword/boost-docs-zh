发布说明

Boost 1.92 发布

  • 修复了 optional<bool> 复制初始化中的回归. 这修复了 issue #146.

Boost 1.91 发布

  • 对完整支持 C++11 (包括 "不受约束的联合" 与引用限定符) 的编译器, 把实现从对齐存储改为联合存储. 这启用了渐进式的 constexpr 支持:

    • 在 C++11 中, 对满足特定约束的类型, 一些构造函数与 const 限定的访问器变得可在编译期上下文中使用 (是 核心常量表达式).
    • 在 C++14 中, 甚至一些修改性操作也成为核心常量表达式 (那些不需要把 optional 的状态从无值改为有值的操作), 适用于配合的类型.
    • 在 C++17 中, 所有构造函数 (包括复制与移动) 对配合的类型而言都成为核心常量表达式.

    这解决了问题 #132 与 #143.

  • 破坏性变更. 在所述实现中, 放弃了用于定制 swap 的机制. 几乎没有人知道该机制, 且它从未被记录在文档中.
  • 在所述实现中, 做了几处小改动以更接近 std::optional 的接口:
    • 启用了 o = {} 语法, 用于把可选对象置为无值状态.
    • 启用了 o.value_or({}) 语法, 它使用一个默认构造的 T.
    • 构造 o = u (其中 o 的类型为 optional<T>, u 的类型为 U (可转换为 T)) 不会创建临时对象 T.
  • 在所述实现中, 加入了一个从 optional<T>& 到 optional<T&> 的转换. 这解决了 issue #142.
  • none_t 现在是 std::equality_comparable 的, 这意味着 none_t 与 optional<T> 建模概念 std::equality_comparable_with (对 std::equality_comparable 的 T 而言), 这意味着你可以对一个可选对象的范围使用 std::ranges::find(rng, boost::none).

  • 警告. 在未来发布中, 我们打算在 optional 中引入范围接口, 使 std::ranges::range<optional<T>> 成为 true. 这可能影响那些基于 std::ranges::range 这类谓词做决策的程序中的重载决议. 例如, 以下代码将开始表现不同:

    template <typename T>
void serialize(T const& v)
{
  if constexpr (std::ranges::range<T>)
    serialize_as_range(v);
  else if constexpr (custom::is_optional_like<T>)
    serialize_as_optional(v);
  else
    serialize_as_value(v);
}

Boost 1.87 发布

  • 破坏性变更. 放弃对 C++03 的支持. 现在最低要求 C++11 (至少部分 C++11 特性).
  • 放弃对 Boost.Utility 的依赖.
  • 放弃对 Boost.Predef 的依赖.
  • 放弃对 Boost.StaticAssert 的依赖.
  • 放弃对 Boost.Move 的依赖.
  • 一些关系运算的实现略微加快.
  • 警告. 在未来发布中, 我们打算在 optional 中引入范围接口, 使 std::ranges::range<optional<T>> 成为 true. 这可能影响那些基于 std::ranges::range 这类谓词做决策的程序中的重载决议.
  • 标签 in_place_init 与 in_place_init_if 成为 inline constexpr, 从而在可执行文件中留下更小的足迹. 这解决了 issue #103.

Boost 1.85 发布

  • 修复了平凡类型的实现. 现在它更慢, 因为它总是初始化 T, 但避免了在复制 optional<T> 时的未定义行为. 这修复了 issue #108.
  • 修复了 GCC 12 中的一些 -Wmaybe-uninitialized 警告. 感谢 Christian Mazakas 提供修复.
  • 放弃对 Boost.Detail 的依赖.

Boost 1.83 发布

  • 弃用对 C++03 及更早版本的支持; 1.86 发布将要求 C++11.

Boost 1.80 发布

  • 破坏性变更: 加入了 std::hash<boost::optional<T>> 的特化. 这修复了 issue #55. 当你的程序为 std::hash<boost::optional<T>> 提供特化时, 你可能会遇到编译器报错. 若发生这种情况, 请定义宏 BOOST_OPTIONAL_CONFIG_DO_NOT_SPECIALIZE_STD_HASH 以禁用本库中 std::hash 的特化.

Boost 1.79 发布

  • 修复了 issue #98.
  • 修复了 issue #92.
  • 加入了对 BOOST_NO_IOSTREAM 的支持.
  • 现在对齐存储使用 unsigned char 而非 char, 以避免 UB.
  • 现在使用 cv 未限定的 value_type 配合 placement new, 以避免 UB.

Boost 1.76 发布

  • 修复了 MSVC 警告 C4702.

Boost 1.75 发布

  • boost::none 是 constexpr 声明的.
  • 修复了 issue #78.

Boost 1.73 发布

  • 修复了 issue #78.
  • boost::none 现在被声明为内联变量 (在支持的编译器上): 在所有翻译单元中只有一个 boost::none 实例.
  • 修复了 GCC 4.4.7 中 optional<T> 对平凡 T 的若干编译错误. 感谢 Robert Leahy 提供修复. 详情见 pr #78.
  • 现在抑制警告 -Wweak-vtables.

Boost 1.69 发布

  • 从 reset() 方法 (不带实参的版本) 中移除了弃用标记.
  • 修复了 issue #59.
  • 修复了在使用 -std=c++03 的 clang 中某些包装类型初始化的缺陷. 见 pr #64.

Boost 1.68 发布

  • 加入了成员函数 has_value(), 用于与 std::optional 保持兼容 (issue #52).
  • 加入了成员函数 map(), 用于把 optional<T> 变换为 optional<U> (使用类型为 T -> U 的函数).
  • 加入了成员函数 flat_map(), 用于把 optional<T> 变换为 optional<U> (使用类型为 T -> optional<U> 的函数).

Boost 1.67 发布

  • 修复了 issue #46.
  • 修复了 -Wzero-as-null-pointer-constant 警告.

Boost 1.66 发布

  • 在较新的编译器上, optional 对标量 T 而言现在是平凡可复制的. 这使用了一种不同的存储 (只是 T 而非 aligned_storage). 我们要求编译器支持 defaulted 函数.
  • 更改了 operator== 的实现, 以消除来自 GCC 的 -Wmaybe-uninitialized 误报警告.

Boost 1.63 发布

  • 加入了两个新的就地构造函数. 它们的工作方式类似 emplace() 函数: 通过完美转发所获得的实参来初始化所含值. 一个构造函数总是初始化所含值, 另一个则依据布尔条件.
  • 语法 o = {} 现在能正确地把 optional 置为未初始化, 就像在 std::optional 中那样.
  • 修复了 Trac #12203.
  • 修复了 Trac #12563.

Boost 1.62 发布

  • 修复了 Trac #12179.

Boost 1.61 发布

  • 现在 boost::optional 针对引用参数进行了特化. 这解决了几个问题:
    • 可选引用的 sizeof 与指针的相同,
    • 一些与复制可选引用相关的缺陷已被消除,
    • 某些编译器上由不正确的引用绑定导致的全部运行期缺陷, 现在都变成了编译期错误,
    • 你可以交换可选引用: 就像交换指针一样: 浅层交换, 底层对象不受影响,
    • 指向抽象类型的可选引用可用.
  • 为嵌套 typedef 补充了文档 (Trac #5193).
  • 把完美转发构造函数做成对 SFINAE 友好, 这修复了 Trac #12002. 不过, 这只在正确实现 C++11 <type_traits> 的较新平台上有效.
  • 修复了 Trac #10445.

Boost 1.60 发布

  • 再次更改了 boost::none 的实现. 现在它是一个具有内部链接的 const 对象 (与任何其他标签一样). 这修复了 Trac #11203.

Boost 1.59 发布

  • 对 C++03 编译器, 为成员函数 emplace() 加入了 0 实参重载, 从而移除了对 <boost/utility/in_place_factory.hpp> 的依赖.
  • 修复了 Trac #11241.

Boost 1.58 发布

  • boost::none_t 不再可以从字面量 0 转换构造. 这避免了一个缺陷: optional<rational<int>> oi = 0; 会用不含值的方式初始化一个 optional 对象.
  • 改进了阻止 optional 在没有头文件 optional_io.hpp 时被流输出的技巧, 使用了 safe-bool 惯用法. 这解决了 Trac #10825.
  • IOStream 运算符现在已在文档中说明.
  • 加入了一种手动禁用移动语义的方式: 只需定义宏 BOOST_OPTIONAL_CONFIG_NO_RVALUE_REFERENCES. 这可用于规避 Trac #10399.
  • 不再可能把 optional<U> 赋给 optional<T>, 若 U 不可赋值或不可转换为 T (Trac #11087).
  • 值访问器现在能正确地作用于 optional<T&> 的右值 (Trac #10839).

Boost 1.57 发布

  • Git pull #9: "提供 <string> 以修复 logic_error("...") 上的 C++03 编译错误".

Boost 1.56 发布

  • 加入了对右值引用的支持. 现在 optional<T> 可用于可移动但不可复制的 T,
  • 改进了 swap (现在使用移动操作),
  • 加入了函数 emplace(). 这是 Trac #1841 请求中的最后一个,
  • optional 是可移动的, 包括条件性的 noexcept 规格说明, 这使其对 move_if_noexcept 友好,
  • 在支持的平台上使用显式 operator bool() (Trac #4227) (破坏性变更),
  • 对 operator<<(ostream&, optional const&) 进行前向声明, 以防止 optional 对象被无意地错误序列化,
  • 从示例中移除了已弃用的函数 reset() (Trac #9005),
  • 与 boost::none 的相等比较不要求 T 是 EqualityComparable 的,
  • 可选右值引用被显式禁止,
  • 把临时对象绑定到可选引用被显式禁止 (破坏性变更),
  • 更多访问所含值的方式, 函数 value()、value_or()、value_or_eval(),
  • 更新并重组了文档, 加入了教程与快速指南章节.
