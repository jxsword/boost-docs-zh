可选引用赋值的重绑定语义

若你向一个 未初始化 的 optional<T&> 赋值, 其效果是 (首次) 绑定到该对象. 显然, 别无选择.

int x = 1 ;
int& rx = x ;
optional<int&> ora ;
optional<int&> orb(x) ;
ora = orb ; // now 'ora' is bound to 'x' through 'rx'
*ora = 2 ; // Changes value of 'x' through 'ora'
assert(x==2);

若你向一个裸的 C++ 引用赋值, 该赋值被转发给被引用对象; 其值发生改变, 但引用永远不会被重绑定.

int a = 1 ;
int& ra = a ;
int b = 2 ;
int& rb = b ;
ra = rb ; // Changes the value of 'a' to 'b'
assert(a==b);
b = 3 ;
assert(ra!=b); // 'ra' is not rebound to 'b'

现在, 若你向一个 已初始化 的 optional<T&> 赋值, 其效果是 重绑定 到新对象, 而不是给被引用者赋值. 这不同于裸的 C++ 引用.

int a = 1 ;
int b = 2 ;
int& ra = a ;
int& rb = b ;
optional<int&> ora(ra) ;
optional<int&> orb(rb) ;
ora = orb ; // 'ora' is rebound to 'b'
*ora = 3 ; // Changes value of 'b' (not 'a')
assert(a==1);
assert(b==3);
设计原理

为 已初始化 的 optional 引用的赋值选择重绑定语义, 是为了提供 各初始化状态之间的一致性, 即使以牺牲与裸 C++ 引用语义的一致性为代价. 确实, optional<U> 力求在其已初始化时表现得尽可能像 U; 但在 U 是 T& 的情形下, 这样做会导致相对于左值初始化状态不一致的行为.

设想 optional<T&> 把赋值转发给被引用对象 (即改变被引用对象的值但不重绑定), 并考虑以下代码:

optional<int&> a = get();
int x = 1 ;
int& rx = x ;
optional<int&> b(rx);
a = b ;

这个赋值会做什么?

若 a 是 未初始化 的, 答案很清楚: 它绑定到 x (我们现在有了另一个指向 x 的引用). 但若 a 已经是 已初始化 的呢?它会改变被引用对象的值 (无论那是什么); 这与其他可能情形不一致.

若 optional<T&> 像 T& 那样赋值, 那么你将永远无法在不显式处理先前初始化状态的情况下使用 Optional 的赋值, 除非你的代码在赋值之后无论 a 是否仍然别名同一对象 (与 b 相同) 都能正常工作.

也就是说, 你必须加以区分才能保持一致.

若在你的代码中重绑定到另一个对象不是一个选项, 那么首次绑定很可能也不是. 在这种情形下, 向一个 未初始化 的 optional<T&> 赋值应被禁止. 很有可能在这种场景下, 前提条件是该左值必须已经初始化. 若并非如此, 则首次绑定没问题而重绑定不行——依我看来这非常不可能. 在这种场景下, 你可以直接赋值本身, 如:

assert(!!opt);
*opt=value;
