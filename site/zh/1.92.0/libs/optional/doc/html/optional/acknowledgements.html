致谢

正式评审前

  • Peter Dimov 建议了 "optional" 这个名称, 并第一个指出对对齐存储的需求.
  • Douglas Gregor 开发了 'type_with_alignment', 后来 Eric Friedman 编写了 'aligned_storage', 它们是 optional 类实现的核心.
  • Andrei Alexandrescu 与 Brian Parker 也研究过对齐存储技术, 他们的工作影响了当前的实现.
  • Gennadiy Rozental 提出了大量且重要的意见, 塑造了该设计.
  • Vesa Karvonen 与 Douglas Gregor 在 optional、variant 与 any 之间做了相当有用的比较, 并提出了其他相关意见.
  • Douglas Gregor 与 Peter Dimov 对比较运算与布尔上下文中的求值发表了意见.
  • Eric Friedman 帮助理解了对齐存储、移动/复制操作与异常安全所涉及的问题.
  • 许多其他人提供了有用的意见: Aleksey Gurotov、Kevlin Henney、David Abrahams, 还有一些我记不起名字的人.

正式评审后

  • William Kempf 仔细考量了最初提出的接口, 并建议了现在使用的全新接口. 他还发起并推动了关于 optional<>/智能指针类比以及关系运算符的讨论.
  • Peter Dimov、Joel de Guzman、David Abrahams、Tanton Gibbs 与 Ian Hanson 关注 optional 的关系语义 (最初是未定义的), 得出结论: 类指针接口并不能使它成为指针, 因此它应当拥有深层的关系运算符.
  • Augustus Saunders 同样探讨了 optional<> 与指针之间不同的关系语义, 并开发了 OptionalPointee 概念, 以帮助避免泛型代码中的潜在冲突.
  • Joel de Guzman 指出 optional<> 可以被看作是 variant<T,nil_t> 之上的一个 API.
  • Dave Gomboc 解释了 Haskell 中与 optional<> 类似物的含义与用法: Maybe 类型构造器 (该类比最初由 David Sankel 指出).
  • 其他意见由 Vincent Finn、Anthony Williams、Ed Brey、Rob Stewart 等人发表.
  • Joel de Guzman 论证了对引用的支持, 并帮助确定了恰当的语义.
  • Mat Marcus 展示了面向值的接口的优点, 影响了当前设计, 并贡献了 "none" 的想法.
  • Vladimir Batov 对 Boost.Convert 库的设计促成了 optional 的值访问器的开发: 函数 value、value_or、value_or_eval.
