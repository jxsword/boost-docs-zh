可选引用绑定

许多编译器错误地把整型类型的 const 左值当作右值对待, 并在某些表达式中绑定到 const 左值引用时创建非法临时对象. 这可能导致创建一个实际上绑定到意外临时对象而非预期对象的可选左值引用. 为了防止难以发现的运行期缺陷, 本库执行编译期检查, 阻止那些本会把可选引用绑定到意外临时对象的表达式. 结果是, 在某些编译器上, 可选引用的某些功能缺失. 为了保持代码在不同编译器之间的可移植性, 建议你只坚持可选引用的最小可移植接口: 对可选引用优先使用直接初始化与复制赋值, 而不是从 T& 进行复制初始化与赋值:

const int i = 0;
optional<const int&> or1;
optional<const int&> or2 = i;  // caution: not portable
or1 = i;                       // caution: not portable

optional<const int&> or3(i);   // portable
or1 = optional<const int&>(i); // portable

已知存在这些缺陷的编译器包括 GCC 4.2、4.3、4.4、4.5、5.1、5.2 版本; QCC 4.4.2; MSVC 8.0、9.0、10.0、11.0、12.0 版本. 要检查你的编译器是否正确实现引用绑定, 请使用此测试程序.

#include <cassert>

const int global_i = 0;

struct TestingReferenceBinding
{
  TestingReferenceBinding(const int& ii)
  {
    assert(&ii == &global_i);
  }

  void operator=(const int& ii)
  {
    assert(&ii == &global_i);
  }

  void operator=(int&&) // remove this if your compiler doesn't have rvalue refs
  {
    assert(false);
  }
};

int main()
{
  const int& iref = global_i;
  assert(&iref == &global_i);

  TestingReferenceBinding ttt = global_i;
  ttt = global_i;

  TestingReferenceBinding ttt2 = iref;
  ttt2 = iref;
}
