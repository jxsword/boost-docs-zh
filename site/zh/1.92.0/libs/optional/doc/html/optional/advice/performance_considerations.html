性能考量

撇开技术细节, optional<T> (对于泛型 T) 的内存布局大致如下:

template <typename T>
class optional
{
  bool _initialized;
  std::aligned_storage_t<sizeof(t), alignof(T)> _storage;
};

T 在 _storage 内部的生命期通过 placement-new 与伪析构调用手动控制. 不过, 对于标量 T, 我们采用不同的存储方式: 简单地持有一个 T:

template <typename T>
class optional
{
  bool _initialized;
  T _storage;
};

我们称之为 直接 存储. 这使得 optional<T> 对标量 T 成为平凡可复制类型. 这只对支持 defaulted 函数 (包括 defaulted 移动赋值与构造函数) 的编译器有效. 在不支持 defaulted 函数的编译器上, 我们仍使用直接存储, 但 optional<T> 不再被识别为平凡可复制. 除标量类型外, 我们为程序员留出定制其类型的途径, 使其能被 optional 认定为优化存储的候选: 通过特化类型特征 boost::optional_config::optional_uses_direct_storage_for:

struct X // not trivial
{
  X() {}
};

namespace boost { namespace optional_config {

  template <> struct optional_uses_direct_storage_for<X> : boost::true_type {};

}}
控制大小

为便于下面的分析, 考虑内存布局时, 我们可以把它想成:

template <typename T>
class optional
{
  bool _initialized;
  T _storage;
};

这意味着在同样的内存空间中, 你能装下的 int 是 optional<int> 的两倍. 因此, 若对象大小对你的应用很关键 (例如你想利用 CPU 缓存来提升性能), 且你已确定愿意牺牲代码清晰度, 建议你直接使用类型 int, 并用某个 "魔法值" 表示 not-an-int, 或使用 markable 这样的库.

即使你腾不出任何 int 的值来表示 not-an-int (例如每个值都有用, 或者你就是想显式表示 not-an-int), 至少对 Trivial 类型, 你应当考虑把值与 bool 标志 (它表示 空状态) 分开存储. 考虑下面这个类:

可选函数参数

把类型为 const optional<T>& 的函数参数可能带来与 T 的复制构造相关的某些意外运行期开销. 考虑以下代码.

void fun(const optional<Big>& v)
{
  if (v) doSomethingWith(*v);
  else   doSomethingElse();
}

int main()
{
  optional<Big> ov;
  Big v;
  fun(none);
  fun(ov); // no copy
  fun(v);  // copy constructor of Big
}

在这里, 复制消除或移动语义都无法让我们避免对类型 Big 的复制. 并不是我们真的需要这次复制, 而是 optional 就是这么工作的. 为了避免这种情况下的复制, 可以提供 fun 的第二个重载:

void fun(const Big& v)
{
  doSomethingWith(v);
}

int main()
{
  optional<Big> ov;
  Big v;
  fun(ov); // no copy
  fun(v);  // no copy: second overload selected
}

或者, 你可以考虑改用可选引用:

void fun(optional<const Big&> v) // note where the reference is
{
  if (v) doSomethingWith(*v);
  else   doSomethingElse();
}

int main()
{
  optional<Big> ov;
  Big v;
  fun(none);
  fun(ov); // doesn't compile
  fun(v);  // no copy
}
