何时使用 Optional

建议在如下情形使用 optional<T>: 存在唯一且 (对各方而言) 明确的理由说明 T 类型可以无值, 并且无值与拥有任何常规的 T 值同样自然. 这类情形的一个例子是, 在某个 GUI 表单中请用户可选地指定某个 int 值的上限, 但允许用户说 "我希望该数值不受最大值约束". 再举一例, 考虑一个指定应用程序应启动多少线程的配置参数: 让该参数保持未指定意味着应用程序应自行决定. 还有一例, 考虑一个返回 vector 中最小元素索引的函数. 我们需要为 vector 为空的情形做好准备. 因此, 这类函数的一个自然签名是:

template <typename T>
optional<size_t> find_smallest_elem(const std::vector<T>& vec);

此处, 收到一个空的 vec 而没有 size_t 可返回, 并不是 失败, 而是一种 正常 的、尽管不规则的情形.

另一种典型情形是表示我们还没有值, 但预期稍后会有值. 这一概念可用于实现惰性初始化或两阶段初始化等方案.

optional 可用于取一个非 DefaultConstructible 类型 T, 并创建一个带有默认构造函数的姊妹类型. 这是一种为任何尚不具有 空状态 的类型添加该状态的方法.

有时类型 T 已经提供了内建的空状态, 但把它包装进 optional 仍然可能有用. 考虑 std::string. 当你从 GUI 表单或数据库表读取一段文本时, 空字符串几乎从来只表示文本缺失, 而不表示别的. 而且有些数据库甚至不区分 null 字符串条目与长度为 0 的非 null 字符串. 尽管如此, 使用 optional<string> 在返回类型中表明我们想在一条专门的处理路径中对待空字符串, 仍可能是实用的:

if(boost::optional<std::string> name = ask_user_name()) {
    assert(*name != "");
    logon_as(*name);
}
else {
    skip_logon();
}

在上面的示例中, 断言表明: 若我们选择使用该技术, 就必须把空字符串状态转换为不含值 (在函数 ask_user_name 内部) 的可选对象.

不推荐的用法

不建议使用 optional 来表示我们因某种 失败 而无法计算出一个值. 失败是什么很难定义, 但它通常有一个共同特征: 与失败原因相关联的信息. 这可以是异常对象的类型与成员数据, 或一个错误码. 发出失败信号却不告知原因是糟糕的设计. 如果你不想使用异常, 又不喜欢通过返回错误码导致无法返回计算出的值, 可以使用 Expected 库. 它类似于 Boost.Variant, 或者包含计算出的值, 或者包含计算失败的原因.

有时, 什么是失败、什么是有效但不规则的结果, 其界限是模糊的, 取决于具体用法与个人偏好. 考虑一个把 string 转换为 int 的函数. 无法转换算失败吗?在某些情况下算, 但在另一些情况下, 你调用它恰恰是为了弄清给定的 string 是否可转换, 甚至对结果值并不感兴趣. 有时转换失败时你可能并不认为它是失败, 但你需要知道为什么不能转换; 例如, 在哪个字符处确定转换不可能. 此时返回 optional<T> 是不够的. 最后, 还有一种用例: 不表示 int 的输入字符串并非失败条件, 但在转换过程中我们使用的资源的获取可能失败. 此时自然的表示是既返回 optional<int> 又发出失败信号:

optional<int> convert1(const string& str); // throws
expected<ErrorT, optional<int>> convert2(const string& str); // return either optional or error
