接口设计

接口的一部分用于修改和设置对象的初始状态. 它必须能表达:

  • 我们想存储一个类型为 T 的特定值,
  • 我们想不存储任何值.

默认构造函数不存储值. 除此之外, 我们要求从 T 进行的赋值与构造反映前者, 而用一个特殊 标签 值 none 进行的赋值与构造反映后一种需求.

optional<int> o1;        // contains no value
optional<int> o2 = 2;    // contains value 2
optional<int> o3 = none; // contains no value

o1 = 1;    // assign value 1
o2 = none; // assign a no-value
o3 = {};   // assign a no-value
检查状态

检查一个可选对象的状态需要两步:

  • 检查我们是否有值,
  • 若有, 读取存储的值.

这一 '流程' 是 C++ 中检查指针的特征, 因此选择了类指针的语法来表示这一点.

void inspect (optional<string> os)
{
  if (os) {               // contextual conversion to `bool`
    read_string(*os);     // `operator*` to access the stored value
    read_int(os->size()); // `operator->` as shortcut for accessing members
  }
}

另外, 与指针类似, 若在值不存在时访问它, 你会触发 未定义行为. 本库通过 BOOST_ASSERT() 检测并报告它. 指针与 optional<> 的这一共同属性已被形式化为一个概念 OptionalPointee.

不过, 还有反直觉的部分. 所有指针都内嵌 浅复制 语义: 当你复制一个指针时, 被指对象留在原处, 你可以通过任一指针访问它. 这与 optional 对象不同, 后者所表示的值会随复制一起被复制.

注意

可选对象不是指针.

在关系运算方面也有类似区别: 对 optional<> 而言它们是深层比较, 而对指针而言是浅层比较.

注释

当你在泛型上下文中需要既适用于 optional<> 又适用于指针的深层关系运算时, 请使用函数 equal_pointees() 与 less_pointees().
