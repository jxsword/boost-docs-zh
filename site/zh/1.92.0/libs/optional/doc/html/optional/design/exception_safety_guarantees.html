异常安全保证

本库假定 T 的析构函数不抛出异常. 若它抛出, optional<T> 上许多操作的行为是未定义的.

以下修改性操作从不抛出异常:

  • optional<T>::operator= ( none_t ) noexcept
  • optional<T>::reset() noexcept

此外, 以下构造函数与析构函数从不抛出异常:

  • optional<T>::optional() noexcept
  • optional<T>::optional( none_t ) noexcept

关于以下赋值函数:

  • optional<T>::operator= ( optional<T> const& )
  • optional<T>::operator= ( T const& )
  • template<class U> optional<T>::operator= ( optional<U> const& )
  • template<class InPlaceFactory> optional<T>::operator= ( InPlaceFactory const& )
  • template<class TypedInPlaceFactory> optional<T>::operator= ( TypedInPlaceFactory const& )
  • optional<T>::reset( T const& )

它们把调用转发给相应的 T 的构造函数或赋值 (取决于该可选对象是否已初始化); 因此, 若 T 的构造函数与赋值都提供强异常安全保证, 则 optional<T> 的赋值也提供强异常安全保证; 否则我们只能得到基本保证. 另外, 若所涉及的 T 的构造函数与赋值都从不抛出, optional<T> 的赋值也从不抛出.

除非 T 的构造函数或赋值抛出异常, 对 optional<T> 的赋值自身不会抛出任何其他东西. 赋值期间的抛出绝不会改变任何相关可选对象的初始化状态:

optional<T> opt1(val1);
optional<T> opt2(val2);
assert(opt1);
assert(opt2);

try
{
  opt1 = opt2; // throws
}
catch(...)
{
  assert(opt1);
  assert(opt2);
}

这也适用于移动赋值/构造函数. 不过, 移动操作更常被做到不抛出.

操作 emplace 提供基本异常安全保证. 若它抛出, 该可选对象将变为未初始化状态, 而无论其初始状态如何, 且其先前所含的值 (若有) 被销毁. 它不会在 T 上调用任何赋值或移动/复制构造函数.

交换

除非 optional 上的 swap 被定制, 其主要实现会把调用转发给 T 的 swap 或移动构造函数 (取决于可选对象的初始化状态). 因此, 若 T 的 swap 与移动构造函数都从不抛出, swap 在 optional<T> 上从不抛出. 类似地, 若 T 的 swap 与移动构造函数都提供强保证, swap 在 optional<T> 上也提供强保证.

若 optional 上的 swap 被定制, 对 T 的移动构造函数的调用会被替换为先调用 T 的默认构造函数, 随后调用 swap. (在不支持移动语义的较旧编译器上, 当想获得更强的异常安全保证时, 这更有用.) 此时 swap 的异常安全保证依赖于 T 的 swap 与默认构造函数的保证
