映射特征

Icl 映射的行为因其如何处理 单位元 而异, 单位元属于关联类型 CodomainT.

关于单位元的评述

在下面的伪代码片段中, 0 将用于表示 identity elements, 它可以是不同的对象, 例如 const double 0.0, 空集, 空字符串, 零向量等, 取决于参数 CodomainT 的实例类型. 存在关于 单位元 相对于 operator+= 的存在性, 是模板类型 CodomainT 的一项要求.

单位元的定义性与存储

icl 映射有两个 性质 或 特征, 可通过模板参数 Traits 加以选择. 第一特征 关系到映射的 定义性. icl 映射可以是 部分 或 完全 的, 作用在由定义域类型 DomainT 给出的值集上.

  • 一个 部分 映射只在已插入到映射中的那些键元素上有定义. 这通常是所期望的, 因此 部分定义性 是默认值.
  • 另一种选择是 icl 映射可以是 完全的. 此时对于所有未存储在映射中的键值, 该映射被视为包含一个 中性值.

第二特征 与 identity elements 在映射中的表示有关. icl 映射可以是一个 单位元吸收器 或一个 单位元充实器.

  • 一个 单位元吸收器 从不存储携带单位元的值对 (k,0).
  • 一个 单位元充实器 会存储值对 (k,0).

对于 icl 映射的模板参数 Traits, 我们有如下四个取值.

单位元充实器

partial

partial_absorber (默认)

partial_enricher

total

total_absorber

total_enricher

映射特征的由来

映射特征是对 icl 的一个后期扩展. 在 Cortex Software GmbH, 区间映射已经在多种应用中使用了几年时间, 其实现类似于默认特征. 直到为 boost 准备该库的过程中, 对 icl 的 聚合映射概念 的更深入分析才引出了映射特征的引入.

聚合映射中的加减悖论

吸收器/充实器特性的根源在于一个小小的悖论.

我们可以通过 相加 的方式, 借助运算 add, += 或 + 向映射插入值对:

{} + {(k,1)} == {(k,1)} // addition

对公共键的进一步相加会触发聚合:

{(k,1)} + {(k,1)} == {(k,2)} // aggregation for common key k

对已有值对进行相减

{(k,2)} - {(k,2)} == {(k,0)} // aggregation for common key k

会得到与 0 值或 identity elements 相关联的值对.

因此一旦为键 k 创建了值对, 就无法再通过相减 (subtract, -= 或 -) 把它从映射中移除.

关于集合的一条非常基本的事实, 即我们可以移除先前添加的内容,

x - x = {}

在此并不成立.

这就是 单位元吸收器 特性的动机. 单位元吸收器映射把携带单位元的值对当作 不存在 来处理, 从而保住了这条定律:

x - x = {}

然而这引入了一个新问题: 使用这样的 单位元吸收器, 我们 按定义 无法在映射中存储值 (k,0). 这可能不利, 因为它与 stl::maps 的行为不一致, 库的客户端也未必期望如此.

该问题的解决方案是引入单位元充实器特性, 用户可以根据自己的需要选择映射变体.

部分映射与完全映射

单位元吸收映射的思路是: 所关联的单位元 值为值对 (k,0) 编码了不存在, 其键为 k. 因此该值对 (k,0) 一旦在映射中出现, 便会立即隧穿进入不存在的领域.

{(k,0)} == {}

如果单位元不是编码 不存在 而是编码 零量化的存在, 那么我们也可以设想这样一个映射: 它对 每个 键 k 都关联一个单位元, 该键没有异于 0 的关联值. 因此, 与把 所有 中性值对 (k,0)建模为 不存在 相反, 我们可以把 所有 中性值对 (k,0)建模为 隐式存在.

按这种方式建模的映射, 是一个大向量, 其中值 v 对应每个键 k , 定义域类型为 DomainT . 但实际存储的只有非单位元值. 这就是在 icl Maps 上引入定义性特性的动机.

一个 部分 映射建模的是这样一种直观观点: 只有存储在映射中的值对才存在. 一个 完全 映射则利用了这样一种可能性: 所有未存储的值对都可以被视为存在, 并以单位元加以 量化.

映射特征的实用层面

从实用的角度看, 映射值携带 identity elements 的值对往往可以忽略. 例如, 如果我们统计插入到一个 interval_map 中的区间的重叠次数 (参见示例 重叠计数器 ), 大多数时候我们并不关心某个重叠是被计了 0 次还是根本没有被计数. 只有当我们想区分不存在与 0 量化时, 才需要单位元充实器映射.

下面的区分对一个 不能 partial_absorber 映射做出, 但对一个 partial_enricher 映射却可以做出:

(k,v) does not exist in the map: Pair (k,v) has NOT been dealt with
(k,0) key k carries 0          : Pair (k,v) has     been dealt with resulting in v=0

有时需要这种细微的区分. 此时 partial_enricher 是正确的选择. 此外, 如果我们想让两个 icl::Maps 共享同一组键, 以便比如说同步地迭代两个映射, 那么我们需要 充实器.
