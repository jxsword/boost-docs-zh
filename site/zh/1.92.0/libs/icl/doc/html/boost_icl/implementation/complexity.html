复杂度

元素容器的复杂度

由于 元素容器 std::set 和 icl::map 只是 stl::set 与 stl::map 的扩展, 它们的复杂度特性也相应如此. 因此它们的主要运算 — 插入 (相加), 删除与搜索 — 都使用对数时间.

区间容器的复杂度

区间容器 上的运算表现不同, 原因在于区间与元素不同, 可以与容器中任意数量的其他区间重叠. 只要区间相对较小或只是单点区间, 区间容器的表现就类似于元素容器. 但对于大区间, 区间容器上运算的时间消耗可能更差, 因为可能必须访问容器的大多数或所有区间. 作为示例, 下面简要讨论区间容器上 相加 的时间复杂度.

添加一个 元素 或 元素值对 总是在 对数时间 内完成, 其中 n 是区间容器中的区间数量. 同一行复杂度也适用于向容器插入一个 段 (一个区间或一个区间值对) 的 最好情况, 此时被插入的段只与容器中 少量 区间重叠.

在 最坏情况 下, 被插入的段与容器中所有区间重叠, 算法会迭代遍历所有被重叠的段. 利用对段的原地操作与带提示的插入, 有可能使每次迭代步骤上的所有必要操作都在 常量时间 内完成. 这使得所有区间容器的段相加具有 线性最坏情况时间 复杂度.

在对一个 interval_set 或一个 separate_interval_sets 执行过一次与 n 个区间重叠的最坏情况相加之后, 需要进行 n 次不重叠的 对数时间 相加, 才能再次触发一次 O(n) 最坏情况相加. 因此对区间或区间值对的相加, 我们只有 摊还对数时间.

对于 区间容器 的相加, 复杂度为 O(m log(n+m)). 因此对于 最坏情况 — 容器大小 n 与 m 相等且两个容器覆盖相同范围 — 容器相加的复杂度是 线性对数. 对于现实应用中经常出现的其他情形, 性能可以好得多. 如果被添加的容器 operand 远小于 object, 且 operand 中的区间相对较小, 性能可以达到 对数. 如果 m 相比 n 较小, 而 operand 中的区间较大, 性能则趋向于 线性.
