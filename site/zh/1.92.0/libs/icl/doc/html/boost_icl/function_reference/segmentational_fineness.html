分段精细度

对于中缀运算符的重载表, 我们需要把 interval_sets 和 interval_maps 细分到具体的类模板

S1

interval_set

S2

separate_interval_set

S3

split_interval_set

M1

interval_map

M3

split_interval_map

选取 Si 和 Mi 作为占位符.

Si 和 Mi 的下标 i 表示一个称为 分段精细度 (简称 精细度) 的性质, 它是区间容器上的一个 类型特征.

segmentational_fineness<Si>::value == i

segmentational_fineness<Mi>::value == i

分段精细度表达了这样一个事实: 对于持有相同元素的区间容器, 一个拆分型区间容器可能包含比分离型容器更多的段, 而后者又可能包含比连接型容器更多的段. 因此对于一个

operator >

其中

x > y   // means that
x is_finer_than y

// we have

finer                                             coarser
split_interval_set                           interval_set
                   > separate_interval_set >
split_interval_map                           interval_map

需要这一关系来解析中缀运算符的实例化, 例如 T operator + (P, Q) (针对两个区间容器类型 P 和 Q). 如果 P 和 Q 都是结果类型 T 的候选, 编译器必须选择其中一个. 我们选择分段上更精细的类型作为结果类型 T. 这样我们就不会丢失 段信息 — 即不会丢失存储在 更精细 的容器类型 P 和 Q 中的那一份.

// overload tables for
T operator + (T, const P&)
T operator + (const P&, T)

element containers:     interval containers:
+  | e b s m            +  | e  i  b  p  S1 S2 S3 M1 M3
---+--------            ---+---------------------------
e  |     s              e  |             S1 S2 S3
b  |       m            i  |             S1 S2 S3
s  | s   s              b  |                      M1 M3
m  |   m   m            p  |                      M1 M3
                        S1 | S1 S1       S1 S2 S3
                        S2 | S2 S2       S2 S2 S3
                        S3 | S3 S3       S3 S3 S3
                        M1 |       M1 M1          M1 M3
                        M3 |       M3 M3          M3 M3

因此, 为例如 T operator + (interval_map, split_interval_map) (它等价于 T operator + (M1, M3)) 查找一个类型组合时, 我们会发现: 对于行类型 M1 与列类型 M3, M3 会被指定为结果类型, 因为 M3 比 M1 更精细. 于是该类型组合会导致编译器选择这个

split_interval_map operator + (const interval_map&, split_interval_map)

实现.
