映射

根据定义, 映射是序对的集合. 因此我们会期望映射服从与集合相同的定律. 然而 icl 映射的语义可能有所不同, 因为它具有聚合设施 — 聚合用的合并运算会被传入, 用于合并映射的关联值. 事实证明, 重叠聚合原则赋予 icl 映射一些语义性质, 使得有效等式的集合取决于映射关联值类型 CodomainT 的语义.

这并不像初看上去那么神奇. 例如, 如果我们实例化一个 interval_map 来收集并连接与区间相关联的 std::strings,

interval_map<int,std::string> cat_map;
cat_map += make_pair(interval<int>::rightopen(1,5),std::string("Hello"));
cat_map += make_pair(interval<int>::rightopen(3,7),std::string(" World"));
cout << "cat_map: " << cat_map << endl;

我们将无法应用 operator -= 

// This will not compile because string::operator -= is missing.
cat_map -= make_pair(interval<int>::rightopen(3,7),std::string(" World"));

因为 std::sting 自身没有实现 -=, 这样写无法通过编译. 因此所有 定律 — 那些依赖 operator -= 或 - 的 — 不仅无效, 甚至无法表述. 这把对一个更丰富的 CodomainT 类型可能有效的定律集合缩减为一个更小的集合, 从而得到更少受限的语义.

目前我们已研究并验证了 icl::Maps 的两种主要实例化,

  • 集合的映射 — 我们将称之为 收集器, 以及
  • 数的映射 — 我们将称之为 量词

二者看起来都有许多有趣的实际应用场景. 与 数 这一术语相关联的语义是: 对于无符号数是一个 交换幺半群, 对于有符号数是一个 交换群或阿贝尔群. 从实践角度看, 我们可以把数看作对映射键值的计数或量化.

Icl 的 集合的映射 或 收集器 是概念 Set 的模型. 这意味着上一章中作为 icl::Sets 语义表述的全部定律对 Maps of Sets 也成立. 相反, Icl 的 数的映射 或 量词 则不是概念 Set 的模型. 但是, 存在大量同时适用于 Collectors 与 Quantifiers 的定律.
