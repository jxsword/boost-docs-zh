区间与区间容器的定义域类型 DomainT 必须满足概念 Regular 的要求, 这隐含着复制构造函数与默认构造函数的存在等性质. 此外, IsIncrementable 或 HasUnitElement 对 DomainT 是必需的. 在 icl 中, 我们把空闭合区间表示为区间 [b,a], 其中 a < b (这里 < 表示 Compare<DomainT>()). 为了对任意类型 DomainT 把这些空区间之一构造为默认构造函数的结果, 我们选择 [1,0], 其中 0 是一个零值或 identity_element, 而 1 是一个单位值或 unit_element:

interval() := [unit_element<DomainT>::value(), identity_element<DomainT>::value()] //pseudocode

Identity_elements 通过调用 DomainT 的默认构造函数来实现. unit_element<T>::value() 被实现为 by default 一个 identity_element, 它被递增一次.

template <class Type>
inline Type unit_element<Type>::value(){ return succ(identity_element<Type>::value()); };

因此一个 DomainT 是 incrementable 的类型也会有 unit_element. 如果没有, 可以提供一个 unit_element. unit_element 可以是任何大于 identity_element 的值 (按所给 Compare 排序). 有一个类型具有 identity_element 但没有递增运算, 它是 string. 因此对 std::string, unit_element 这样实现:

// Smallest 'visible' string that is greater than the empty string.
template <>
inline std::string unit_element<std::string>::value(){ return std::string(" "); };

正如 std::sets 与 maps 的键类型一样, 模板参数 Compare 必须是 DomainT 上的一个严格弱排序.

最后, 如果 DomainT 是整数类型, 则 DomainT 需要是 incrementable 且 decrementable 的. 这种 '双向可增减性' 需要在该整数类型的最小可能单元上实现. 这看似平常, 但存在像 boost::date_time::ptime 这样本质上是整数却不提供最小可增单元上的所需递增与递减的类型. 对于 icl::intervals, 递增与递减用于开边界到闭边界之间的计算, 例如 [2,43) == [2,42]. 如果 DomainT 是整数类型, 这类计算总是只需一次递增或递减.

对 IntervalT 的要求

对 IntervalT 参数的要求与 DomainT 参数密切相关. IntervalT 自身有两个关联类型 — 元素类型与比较排序 — 它们必须与其区间容器的元素及排序参数保持一致. 于是 IntervalT 必须实现一个称为 exclusive_less 的排序. 两个区间 x, y 是 exclusive_less 的,

icl::exclusive_less(x, y)

如果所有 DomainT 元素 — 即 x 的元素 — 都小于 y 的元素 (按 Compare 排序).

对关联值类型 CodomainT — 其属于某个 icl::map 或 interval_map — 的要求取决于其聚合功能的用法. 如果从不使用重叠时的聚合, 即 +, +=, add, -, -=, subtract, &, &=, add_intersection 这些相加, 相减与交集运算都未在 interval_map 上使用, 则 CodomainT 只需要是 Regular 的.

Regular 对象语义隐含 DefaultConstructible 和 EqualityComparable, 也就是说它有一个默认构造函数 CodomainT() 和一个 operator ==.

如果关联值不可相加但仍关联到区间, 请使用 interval_maps 的 无聚合 方式 — 你仍希望用 interval_maps 来处理它们. 只要这些值用 insert 添加并用 erase 删除, interval_maps 对这类值就能正常工作.

如果 相加 仅经由 interval_map's 的 +, += 或 add 使用而不使用相减, 那么 CodomainT 需要是 Combinable 的, 这是对函数对象模板 Combine 而言. 这意味着, 在大多数使用 inplace_plus 作为 Combine 的默认实现的情况下, CodomainT 必须实现 operator +=.

对于可相加但不可相减的关联值类型, 例如 std::string, 通常合理的做法是用相加来合并值, 但不希望有逆合并.

interval_map<int,std::string> cat_map;
cat_map += make_pair(interval<int>::rightopen(1,5),std::string("Hello"));
cat_map += make_pair(interval<int>::rightopen(3,7),std::string(" world"));
cout << "cat_map: " << cat_map << endl;
//cat_map: {([1,3)->Hello)([3,5)->Hello world)([5,7)-> world)}

要获得 完整的聚合功能, 需要 Map 的 CodomainT 上有一个逆聚合函数对象. icl 为此提供了一个元函数 inverse. 使用默认的 Combine = inplace_plus — 它依赖 operator += 在类型 CodomainT 上的存在 — 元函数 inverse 会推断出 inplace_minus 作为逆函数对象, 后者要求 operator -= 在类型 CodomainT 上成立.

在 icl 的设计中, 特别是对于参数 Combine = inplace_plus 的默认设置, 我们假定类型 CodomainT 具有一个中性元素或 identity_element , 就 Combine 函数对象而言.
