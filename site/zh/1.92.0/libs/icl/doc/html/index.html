注释

C++03 支持 在 Boost.Icl 1.84 中已被弃用, 并在 Boost.Icl 1.86 中被移除.

区间在软件开发中几乎无处不在. 然而, 人们通常只用一对数字把它们很简单地编码进用户自定义的类里, 因此大多数时候它们只是被 隐式 地使用. 区间的含义很简单: 它们表示介于其下界与上界之间的所有元素, 从而构成一个集合. 但与集合不同, 区间通常无法被加成一个单一的新区间. 如果你想把一些区间加入一个仍能表示 集合 的区间收集结构, 你就得到了本库所提供的 interval_sets 的思想.

ICL 的区间容器最初由 Cortex Software GmbH 开发, 用于解决医院信息系统语境下与日期时间区间计算相关的问题. 在统计程序、计费程序与治疗安排程序中, 需要处理带有诸如 发票金额 或 治疗集合 等关联值的时间区间. ICL 正是从这些工业用例中诞生的. 它从日期时间问题领域中提炼出有助于解决常见问题的通用代码, 同样也能在其他领域发挥作用.

区间容器最有优势的方面之一, 是它对集合与映射极为紧凑的表示. 如果在给定的问题领域中, 元素通常以连续成块的形式出现, 那么使用 元素的 集合与映射可能非常低效. 除了能大幅降低空间与时间成本的关联容器紧凑表示之外, ICL 还提供了一种通用的聚合机制: 当区间在插入时发生重叠, 它允许以有意义的方式合并关联值.

想要简明的介绍与概览, 可以参阅 关于 ICL 的演示材料 (见 BoostCon2009).

定义与基本示例

区间容器库 (ICL) 提供 intervals 以及两类区间容器: interval_sets 和 interval_maps.

  • interval_set 是一种 集合, 它实现为区间的集合.
  • interval_map 是一种 映射, 它实现为区间值对的映射.
两个侧面

Interval_sets 与 interval_maps 在其接口中暴露出两个不同的侧面: (1) 集合或映射的功能, 这是较为 抽象的侧面; (2) 区间容器的功能, 这是更具体且与 实现相关的侧面. 在实践中两个侧面都有用, 因此都得到支持.

第一个侧面将被称为 基本 侧面, 也是更重要的一个. 它意味着我们可以像使用集合或映射那样使用 interval_set 或 interval_map — 这里的集合与映射是 元素的. 它暴露出相同的函数.

interval_set<int> mySet;
mySet.insert(42);
bool has_answer = contains(mySet, 42);

第二个侧面将被称为 分段性 侧面, 它允许我们利用这样一个事实: interval_sets 与 interval_maps 的元素聚集成我们可以迭代的 区间 或 段.

// Switch on my favorite telecasts using an interval_set
interval<seconds>::type news(make_seconds("20:00:00"), make_seconds("20:15:00"));
interval<seconds>::type talk_show(make_seconds("22:45:30"), make_seconds("23:30:50"));
interval_set<seconds> myTvProgram;
myTvProgram.add(news).add(talk_show);

// Iterating over elements (seconds) would be silly ...
for(interval_set<seconds>::iterator telecast = myTvProgram.begin();
    telecast != myTvProgram.end(); ++telecast)
    //...so this iterates over intervals
   TV.switch_on(*telecast);

只要集合的元素以连续成块的形式出现, 使用 interval_sets 与 interval_maps 就可能大有裨益: intervals. 在许多问题领域中显然都是这种情况, 尤其是在处理与日期时间相关计算的领域.

可加性与可减性

与 std::sets 和 maps 不同, interval_sets 与 interval_maps 实现了概念 Addable 与 Subtractable. 因此 interval_sets 定义了一个 operator +=, 它自然地实现为 集合并; 还定义了一个 operator -=, 它相应地实现为 集合差. 在 Icl 中, interval_maps 同样是可加可减的. 事实证明, 在如下情形中把加法或减法传播到 interval_map's 关联值上是非常有成效的: 当向一个 interval_map 插入区间值对时, 插入的区间值对与 interval_map 中已有的区间值对发生了冲突. 这种运算传播被称为 重叠聚合.

重叠聚合

这是第一个动机示例 — 一个非常小的聚会, 演示 重叠聚合 原理, 对象是 interval_maps:

在示例中, Mary 最先进入聚会. 她在时间区间 [20:00,22:00) 期间出席. Harry 稍后进入. 他停留在 [21:00,23:00) 之内.

typedef std::set<string> guests;
interval_map<time, guests> party;
party += make_pair(interval<time>::right_open(time("20:00"), time("22:00")), guests("Mary"));
party += make_pair(interval<time>::right_open(time("21:00"), time("23:00")), guests("Harry"));
// party now contains
[20:00, 21:00)->{"Mary"}
[21:00, 22:00)->{"Harry","Mary"} //guest sets aggregated on overlap
[22:00, 23:00)->{"Harry"}

在区间 重叠 时, 相应的名字集合会被 累加. 在 重叠点 处, 区间会被 拆分. 区间重叠时内容的累加通过一个 operator += 完成, 必须为 interval_map 的关联值实现该运算. 在示例中关联值是 guest sets, 因此一个 guest set 必须把 operator += 实现为集合并.

从示例可以看出, interval_map 既有 分解性行为 (在时间维度上), 也有 累加性行为 (在关联值上).

可加性与重叠聚合是 interval_maps 上经由函数 add 与 operator += 实现的有用特性. 但你也可以把它们与 传统 的 insert 语义 — 其行为类似于针对区间插入泛化后的 std::map::insert — 一起使用.

Icl 的类模板

除区间容器之外, 我们还可以使用在 行为上等价 于区间容器的元素容器: 在基本侧面上, 它们具有完全相同的功能. STL 的 std::set 就是这样一个等价的集合实现. 由于 icl 区间映射的聚合设施, std::map 在基本侧面上并不与 interval_map 完全等价. 因此 icl 中有一个额外的 icl::map 类模板, 用于元素的映射.

  • std::set 与 interval_sets 在 基本 侧面上行为等价.
  • icl::map 与 interval_maps 在 基本 侧面上行为等价. 具体而言, icl::map 实现了 重叠聚合, 对元素容器而言它被称为 冲突聚合.

连接型区间容器

Interval_set 与 interval_map 始终处于 最小表示 状态. 在许多区间插入点或交点无关紧要的情形中, 这很有用. 因此在大多数情况下, interval_set 与 interval_map 将是区间容器的首选.

拆分型区间容器

相反, Split_interval_set 与 split_interval_map 具有 插入记忆. 它们会从加法和交集操作中累积区间边界. 如果我们想用某些时间网格充实区间容器, 例如月份、日历周或两者兼有, 这一点特别有用. 参见示例 月份与周的时间网格.

分离型区间容器

Separate_interval_set 实现分离风格. 该风格保留从未被重叠区间越过的边界. 因此, 如果插入 separate_interval_set 的所有区间都由某个从不越过 (比如说) 月份边界的网格生成, 那么这些边界会在 separate_interval_set 中得到保留.
