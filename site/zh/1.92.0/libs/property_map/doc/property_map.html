Boost 属性映射库

Boost 属性映射库主要由以概念形式给出的接口规范组成(类似于 STL 中的迭代器概念 [2]). 这些接口规范供泛型库的实现者使用, 用于向用户传达对模板参数的要求. 具体而言, Boost 属性映射概念定义了一个把键对象映射到相应值对象的通用接口, 从而向算法隐藏映射实现方式的细节. 满足属性映射接口的类型的实现由算法的使用者提供. 属性映射要求有意让键对象和值对象的类型保持宽泛, 以使泛型库的函数模板具备最大程度的泛化能力.

对属性映射接口的需求来自 Boost Graph Library (BGL), 其中包含许多使用属性映射概念规定其接口的算法示例. 例如, 请注意 ColorMap 模板参数, 它位于 breadth_first_search 中. 此外, BGL 还包含许多实现属性映射接口的具体类型示例. adjacency_list 类实现了用于访问附着在图的顶点和边上的对象(属性)的属性映射.

Boost 属性映射库还包含 一些适配器, 它们把实现映射操作的常用数据结构——例如内置数组(指针)、迭代器和 std::map——转换为具有属性映射接口的形式. 这些适配器并非要满足所有映射需求, 而是作为如何实现该接口的示例, 同时覆盖若干常见情形. 详情请参见头文件.

属性映射是静态类型化的实体. 如果你需要在更动态的环境下访问属性映射(例如, 因为你要从文件中读取一组未知的属性), 可以使用 dynamic_properties 类, 通过动态类型化的接口访问一组属性映射.

属性映射概念

属性映射接口由一组概念组成(关于"概念"的定义见 [1] 和 [2]), 这些概念定义了把键对象映射到相应值对象的语法. 由于属性映射操作是全局函数(实际上它们不必是全局函数, 但它们总是以非限定方式调用, 并且可以通过实参依赖查找找到), 因此可以重载这些映射函数, 使几乎任意的属性映射类型和键类型都能使用. 属性映射的接口由三个函数组成: get()、put() 和 operator[]. 下面这个来自 example1.cpp 的具体示例展示了如何用这三个函数访问与各种人员相关联的地址. 我们在这里使用一个单独的函数模板, 以突出程序中使用属性映射概念接口的部分. 在 main() 函数中我们使用 std::map 和 boost::associative_property_map, 但使用任何满足属性映射要求的类型(包括你自己创建的自定义类型)也是可以的. 
#include <iostream>
#include <map>
#include <string>
#include <boost/property_map/property_map.hpp>


template <typename AddressMap>
void foo(AddressMap address)
{
  typedef typename boost::property_traits<AddressMap>::value_type value_type;
  typedef typename boost::property_traits<AddressMap>::key_type key_type;

  value_type old_address, new_address;
  key_type fred = "Fred";
  old_address = get(address, fred);
  new_address = "384 Fitzpatrick Street";
  put(address, fred, new_address);

  key_type joe = "Joe";
  value_type& joes_address = address[joe];
  joes_address = "325 Cushing Avenue";
}

int
main()
{
  std::map<std::string, std::string> name2address;
  boost::associative_property_map< std::map<std::string, std::string> >
    address_map(name2address);

  name2address.insert(make_pair(std::string("Fred"), 
				std::string("710 West 13th Street")));
  name2address.insert(make_pair(std::string("Joe"), 
				std::string("710 West 13th Street")));

  foo(address_map);
  
  for (std::map<std::string, std::string>::iterator i = name2address.begin();
       i != name2address.end(); ++i)
    std::cout << i->first << ": " << i->second << "\n";

  return EXIT_SUCCESS;
}

对于每个属性映射对象, 都存在一组 有效键, 对这些键到值对象的映射是有定义的. 对 无效 键调用属性映射函数会导致未定义行为. 属性映射概念并不规定这组有效键如何创建或修改. 使用属性映射的函数必须在其前置条件中指明预期的有效键集合.

对属性映射的需求源自 Boost Graph Library 的设计, 其算法需要一个接口来访问附着在图中顶点和边上的属性. 在此语境下, 顶点和边的描述符就是属性映射的键类型.

若干类别的属性映射提供不同的访问能力:

可读
关联的属性数据只能读取. 数据按值返回. 许多定义问题输入的属性映射(例如边权重)可以定义为可读属性映射.

可写
关联的属性只能写入. 用于在广度优先搜索树中记录路径的父数组就是一个应定义为可写的属性映射的例子.

读/写
关联的属性既可写也可读. Dijkstra 最短路径算法中使用的距离属性就需要同时提供读和写能力.

左值
关联的属性实际在内存中表示, 并且可以取得对它的引用. 左值类别的属性映射还满足读/写属性映射的要求.

四个属性映射类别各自定义了一个独立的概念. 这些属性映射概念列在下面, 并附有指向各自文档的链接.

  • 可读属性映射 (ReadablePropertyMap)
  • 可写属性映射 (WritablePropertyMap)
  • 读/写属性映射 (ReadWritePropertyMap)
  • 左值属性映射 (LvaluePropertyMap)

属性映射类别标签

每个属性映射类别都有一个标签结构体, 定义在头文件 <boost/property_map/property_map.hpp> 中. 

namespace boost {

  struct readable_property_map_tag { };

  struct writable_property_map_tag { };

  struct read_write_property_map_tag :
    public readable_property_map_tag,
    public writable_property_map_tag { };

  struct lvalue_property_map_tag : 
    public read_write_property_map_tag { };

}

属性映射特征

与 STL 的 std::iterator_traits 类类似, 存在一个 boost::property_traits 类, 可用于推导与属性映射类型相关联的类型: 键类型、值类型以及属性映射类别. boost::property_traits 有一个特化, 使指针可以用作属性映射对象. 此外, 属性映射函数对指针进行了重载. 这些特征类和函数定义在 <boost/property_map/property_map.hpp> 中. 

namespace boost {

  template <typename PropertyMap>
  struct property_traits {
     typedef typename PropertyMap::key_type key_type;
     typedef typename PropertyMap::value_type value_type;
     typedef typename PropertyMap::reference reference;
     typedef typename PropertyMap::category category;
  };

}

属性映射类型

  • 内置 C++ 指针类型.
    property_traits 类的以下特化以及 put() 和 get() 的重载, 使得内置 C++ 指针类型可以用作属性映射. 它们定义在 boost/property_map/property_map.hpp 中. 更具体地说, 这意味着 T* 是 LvaluePropertyMap 的模型, 前提是键类型至少可转换为 std::ptrdiff_t. 
    namespace boost {
  // specialization for using pointers as property maps
  template <typename T>
  struct property_traits<T*> {
    typedef T value_type;
    typedef T& reference;
    typedef std::ptrdiff_t key_type;
    typedef random_access_iterator_pa_tag category;
  };

  // overloads of the property map functions for pointers
  template<>
  void put(T* pmap, std::ptrdiff_t k, const T& val) { pmap[k] = val;  }

  template<>
  const T& get(const T* pmap, std::ptrdiff_t k) { return pmap[k]; }

}

历史

属性映射接口起源于 Dietmar Kühl 关于泛型图算法的硕士论文中的 数据访问器. 属性映射的思想还以 装饰器 的名义出现在 Generic Graph Component Library (GGCL, 现为 Boost Graph Library (BGL))的早期版本中. 属性映射接口的主要动机是支持访问图中与顶点和边相关联的数据, 尽管属性映射的适用范围远不止于此.
