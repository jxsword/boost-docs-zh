序列化

模板序列化 - shared_ptr<class T>
下面包含的所有代码片段都定义在 boost::serialization 命名空间内.

shared_ptr<T> 定义于 shared_ptr.hpp .

shared_ptr<T> 的大致类轮廓如下:

shared_ptr<T> 包含:
T *px;
shared_count pn;, 它包含一个指向以下内容的指针:
sp_counted_base_impl<T, ...>, 它派生自多态抽象类
sp_counted_base
序列化过程沿上面的树向下进行.

为 shared_ptr 实现序列化的第一步只是序列化 shared_ptr 的相关成员. 这几乎毫不费力: 


template<class Archive, class T>
inline void serialize(
    Archive & ar,
    shared_ptr<T> & t,
    const unsigned int file_version,
    int
){
    ar & t.px; // save the raw pointer
    ar & t.pn; // save the shared reference count
}
到目前为止一切顺利. 接下来是 shared_count 的序列化: 

template<class Archive>
inline void save(
    Archive & ar,
    const boost::detail::shared_count & t,
    const unsigned int file_version
){
    ar << t.pi_;
}

template<class Archive>
inline void load(
    Archive & ar,
    boost::detail::shared_count & t,
    const unsigned int file_version
){
    ar >> t.pi_;
}
本库的一个关键特性是: 能够在不改动类或模板的声明或定义的情况下指定类或模板的序列化. 这称为 非侵入式 序列化.

shared_count 的 pi_ 成员是指向 sp_counted_base_impl 实例的指针. 由于该类没有默认构造函数, 序列化需要指定以下重载: 


template<class Archive, class P, class D>
inline void save_construct_data(
    Archive & ar,
    const boost::detail::sp_counted_base_impl<P, D> * t, 
    const unsigned int file_version
){
    // variables used for construction
    ar << t->ptr;
    ar << *t;
}

template<class Archive, class P, class D>
inline void load_construct_data(
    Archive & ar,
    boost::detail::sp_counted_base_impl<P, D> * t, 
    const unsigned int file_version
){
    P ptr_;
    ar >> ptr_;
    // placement new
    ::new(t)boost::detail::sp_counted_base_impl<P, D>(ptr_,  D());
    ar >> *t;
}
语句 ar >> ptr_ 是关键. 它反序列化与上面反序列化过的同一个指针. 默认的对象跟踪会确保最多只创建该对象的一个实例, 并且多次反序列化返回的指针全都相同. 因此, 无论为特定对象创建了多少个 shared_ptr/shared_count 实例, 它们都将指向同一个对象.

由于 sp_counted_base_impl<P, D> 派生自 sp_counted_base, 需要以下内容: 


template<class Archive, class P, class D>
inline void serialize(
    Archive & ar,
    boost::detail::sp_counted_base_impl<P, D> & t,
    const unsigned int file_version,
    int
){
    ar & boost::serialization::base_object<
	boost::detail::sp_counted_base
    >(*this);
}
这又要求其基类的序列化: 

inline void serialize(
    Archive & ar,
    boost::detail::sp_counted & t,
    const unsigned int file_version,
    int
){
}
看起来我们已完成, 但用这段代码运行测试程序 demo_shared_ptr.cpp 会产生如下输出. 

a = 0x003017A0 use count = 2
a1 = 0x003017A0 use count = 2
unique element count = 1
a = 0x00000000 use count = 0
a1 = 0x00000000 use count = 0
unique element count = 0
a = 0x00303060 use count = 1
a1 = 0x00303060 use count = 1
unique element count = 1
这表明我们还没有完全完成. 由于默认的对象跟踪, sp_counted_base_impl<P, D> 只会被创建一次, 无论有多少个共享指针指向同一对象. 当然, 也必须如此. 引用计数从 1 开始且从不递增. 必须在序列化函数中加入代码来维护正确的引用计数.

序列化一个空基类——sp_counted_base——的过程看似额外的开销. 考察 base_object.hpp 中的代码可以发现 base_object.hpp 提供两个函数:

  • 调用基类数据的序列化
  • 作为副作用, "注册"基类/派生类关系这一事实, 使得可以在运行期进行基类与派生类指针之间的转换.
在本例中我们只需要后一个函数, 因此可以把基对象序列化替换为: 

// register the relationship between each derived class
// and its polymorphic base
void_cast_register<
    boost::detail::sp_counted_base_impl<P, D>
    boost::detail::sp_counted_base, 
>();
而且不必为 sp_counted_base 包含一个平凡的序列化器.

最后, 如果我们希望把这个序列化用于 XML 档案, 还需要指定名值对包装器.

实际上, 即使这些也只是一个开始. 本实现未处理的问题包括:

  • weak_ptr 未处理. 我甚至没有研究过这一点.
  • 可能与 shared_ptr 交互的其他智能指针完全没有处理. 要确信实现是完整且正确的, 所有这些都应当处理.
  • 异常处理尚未被彻底考虑.
  • 其他有待发现的问题.
已经考虑过的一件事是 shared_ptr 的导出. 声明共享指针序列化的头文件包含一些用于导出共享指针的特殊宏: 
BOOST_SHARED_POINTER_EXPORT(T)
BOOST_SHARED_POINTER_EXPORT_GUID(T, K)
它们是用于导出通过裸指针序列化的类的宏的特化版本.

清晰、完整、正确且异常安全的智能指针序列化将是一项挑战. 我希望本实现能为这样的工作提供一个有用的起点.
