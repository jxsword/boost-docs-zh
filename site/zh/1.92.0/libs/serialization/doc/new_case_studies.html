这些并不是库本身的一部分, 而是关于如何使用库来处理特定情况的技术.

序列化函数对象

一个关于如何序列化函数对象的示例. 我相信这可以通过序列化指向相关对象的指针来完成. 由于序列化库会以正确类型复现指针, 这应当很容易实现.

如果一组函数对象都派生自同一个多态基类——也许通过多重继承——那么函数对象实际上就变成了一个封装代码的"变量".

本案例研究将展示如何做到这一点.

档案适配器

用户常常想为现有档案添加自己的特殊功能. 例如针对特定类型的性能增强、对 xml 档案输出语法的调整, 以及在档案写入和/或读取时进行日志/调试输出. 如果这一功能实现为一个以基类作为模板实参的"适配器"模板, 那么只要该功能有意义, 就可以把它附加到任何档案上. 例如, 用于生成 xml schema 的适配器可以同时附加到 xml 档案的宽字符版本和窄字符版本上.

本案例研究将展示如何制作一个实用的档案适配器.

档案辅助对象

有些类型按现状是不可序列化的. 也就是说, 它们不满足"可序列化概念"的要求. 标志性示例是 boost::shared_ptr. 有时可以通过在库内部添加代码使这些类型可序列化. 当然, 那样做会让库作者背上终身的无偿工作. 与其向库本身添加一堆特殊代码, 不如把这些代码打包成一个"辅助类" (helper) 或"混入类" (mix-in) . 然后从"基"档案类和"辅助"类两者派生新档案. boost::shared_ptr 就是这样实现的.

还可以制作一个"通用运行期辅助类", 实际上扩展库的 API. 此前库中包含这样一个辅助类. 它已被移除, 改用当前实现. 但这一功能应当通过另一个适配器加回来, 使其成为库的一部分.
