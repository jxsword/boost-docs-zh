序列化

数据流迭代器

动机

考虑把任意长度的 8 位字节序列转换为 base64 文本的问题. 这样的过程可以概括为:

source => 8 bit bytes => 6 bit integers => encode to base64 characters => insert line breaks => destination

我们更倾向于这样的解决方案:

  • 可分解. 这样我们可以独立地编写、测试、验证和使用转换的每个 (简单) 阶段.
  • 可组合. 这样我们可以把这个组合体在其他地方当作新组件使用.
  • 高效. 这样我们不必重新实现一遍.
  • 可伸缩. 这样它对短的以及任意长的序列都能良好工作.
最接近满足这些要求的方法是 Iterator Adaptors 所描述并实现的方法. Iterator Adaptor 模板使我们感兴趣的基本特性是: 它接受一个基迭代器作为参数, 并从中获得输入. 这表明类似下面的事情也许是可能的. 

typedef 
    insert_linebreaks<         // insert line breaks every 76 characters
        base64_from_binary<    // convert binary values to base64 characters
            transform_width<   // retrieve 6 bit integers from a sequence of 8 bit bytes
                const char *,
                6,
                8
            >
        > 
        ,76
    > 
    base64_text; // compose all the above operations in to a new iterator

std::copy(
    base64_text(address),
    base64_text(address + count),
    ostream_iterator<CharType>(os)
);
的确, 这看起来正是迭代器适配器旨在解决的那类问题. Iterator Adaptor 库已经包含可以配置来实现上述部分操作的模块. 例如, 其中包含 transform_iterator , 可用于实现 6 位整数 => base64 编码.

数据流迭代器

遗憾的是, 并非所有继承自 Iterator Adaptors 的迭代器都能保证满足上述可组合性目标. 为达到这一目的, 编写它们时必须考虑一些额外事项. 我们把数据流迭代器定义为继承自 iterator_adaptor 并满足一小组额外要求的类.

模板化构造函数

模板化构造函数的形式为: 


template<class T>
dataflow_iterator(T start) :
    iterator_adaptor(Base(start))
{}
把这些构造函数应用于上面的示例时, 会生成以下代码: 

std::copy(
    insert_linebreaks(
        base64_from_binary(
            transform_width(
                address
            ),
        )
    ),
    insert_linebreaks(
        base64_from_binary(
            transform_width(
                address + count
            )
        )
    )
    ostream_iterator<char>(os)
);
该模板的递归应用正是自动生成上例中构造函数 base64_text(const char *) 的机制. 最初的 Iterator Adaptors 包含一个 make_xxx_iterator 来实现这一功能. 不过我认为, 与上面使用模板化构造函数的方案相比, 它们用起来很笨重.

解引用

解引用某些迭代器可能引发问题. 例如, 编写 remove_whitespace 迭代器的一种自然方式是在构造迭代器时跳过开头的空白字符. 如果传给构造函数的迭代器"指向"字符串末尾, 这将会失败. filter_iterator 就是以这种方式实现的, 因此不能用于我们的场景. 所以, 在实现该迭代器时, 空白移除被推迟到迭代器真正被解引用之时.

比较

iterator_adaptor 的迭代器相等性的默认实现只是对基迭代器调用相等运算符. 一般来说这是令人满意的. 但这意味着其他操作 (例如解引用) 不得提前递增基迭代器. 避免这一点在某些情况下可能非常棘手 (例如 transform_width) .

库中包含的迭代器

序列化库的数据流迭代器都定义在命名空间 boost::archive::iterators 中, 这里包含的有:
base64_from_binary
把整数序列转换为 base64 文本
binary_from_base64
把 base64 字符序列转换为整数序列
insert_linebreaks
给定一个序列, 创建一个插入了换行符的序列
mb_from_wchar
把宽字符序列转换为多字节字符序列
remove_whitespace
给定一个字符序列, 返回一个移除了空白字符的序列. 这是一个派生, 来自 boost::filter_iterator
transform_width
把 x 位元素序列转换为 y 位元素序列. 这是在 base64 文本之间相互转换的迭代器的关键组件.
wchar_from_mb
把当前 locale 中的多字节字符序列转换为宽字符.
xml_escape
转义 xml 文本中的 xml 元字符
xml_unescape
反转义 xml 转义序列以生成普通文本序列

标准流迭代器对我们来说不太适用. 在把 wchar_t 实现为无符号短整数的系统上 (例如 VC 6) , 它们不能按我预期的方式工作. 我还做了一些调整以与我们的数据流迭代器概念保持一致. 与其余迭代器一样, 它们位于命名空间 boost::archive::interators 中, 以避免与标准库版本冲突.
