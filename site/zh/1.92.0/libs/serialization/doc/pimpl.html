序列化

PIMPL
PIMPL 是 Herb Sutter [10] 描述的一种 C++ 编程惯用法, 代表 "Private Implementation". 它也被称为 "Handle Body Idiom". 本库包含一个名为 demo_pimpl.cpp 的程序, 演示它的用法. 文件 demo_pimpl_A.hpp 包含 A 类的声明, 它通过包含一个仅以指针形式定义的 struct B 指针来隐藏其实现. 

// class whose declaration is hidden by a pointer
struct B;

struct A {
    // class a contains a pointer to a "hidden" declaration
    B *pimpl;
    template<class Archive>
    void serialize(Archive & ar, const unsigned int file_version);
    A();
};
A 的序列化需要访问 B 的定义. 但这并不意味着需要从头文件获得这一访问权. 由于 B 是指针, 声明 class B 就足够了. A 序列化的实现包含了在单独编译的模块 demo_pimpl_A.cpp 中通过如下方式定义的类 B 的定义: 

#include "demo_pimpl_A.hpp"

// "hidden" definition of class B
struct B {
    int b;
    template<class Archive>
    void serialize(Archive & ar, const unsigned int file_version){
        ar & b;
    }
};

A::A() :
    pimpl(new B)
{}

A::~A(){
    delete pimpl;
}

// now we can define the serialization for class A
template<class Archive>
void A::serialize(Archive & ar, const unsigned int file_version){
    ar & pimpl;
}
如 [10] 所述, 这带来以下优点:
  • 可以使用类型 "B" 而无需使用其头文件.
  • B 的实现可以改动, 而不会引发一连串重新编译.
于是, 我们编译这些模块, 一切正常. 然而在链接时, 我们得到一个错误. 有两个符号未定义: 

void A::serialize(boost::archive::text_oarchive & ar, const unsigned int file_version);
void A::serialize(boost::archive::text_iarchive & ar, const unsigned int file_version);
问题在于编译上面的代码时, serialize 模板没有任何实例化. 也不可能有——因为尚"不知道"序列化将与哪些类型的档案一起使用. 因此尝试链接时这些函数是"缺失"的. 解决办法是为将要使用的那些档案显式实例化序列化代码. 在本例中, 在任意 *.cpp 文件中包含以下代码即可: 
 #include <boost/archive/text_iarchive.hpp> #include <boost/archive/text_oarchive.hpp> template void A::serialize<boost::archive::text_iarchive>( boost::archive::text_iarchive & ar, const unsigned int file_version ); template void A::serialize<boost::archive::text_oarchive>( boost::archive::text_oarchive & ar, const unsigned int file_version );
程序现在应当既能编译也能链接.

这样做的缺点是, 必须知道哪些档案将与隐藏的序列化一起使用. 这是使用模板驱动代码的一个副作用. 可以为所有已知模板显式调用实例化, 并假定链接器会排除未被引用的代码. 这应该可行, 但依赖于平台.
