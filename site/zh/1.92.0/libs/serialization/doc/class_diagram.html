此图展示了为文本档案实现保存 (输出序列化) 的各个类之间的关系. 对于加载以及其他类型的档案, 层次结构和组织方式也类似. 图中, 以 蓝色 书写的类实现给定档案类型的保存 (此处是文本档案) . 用户包含 红色 的类, 以从特定类型的档案保存他们的数据. 名称为黑色的其他类实现本库, 永远不应改动. 它们位于 namespace boost::archive::detail
basic_oarchive
实现类导出、版本控制和对象跟踪的核心库功能. 由于它没有模板参数, 因此被编译进库中.

interface_oarchive<text_oarchive>
声明标准档案接口的类. 它被分解出来, 以便既可以用作 polymorphic_oarchive 的基类, 也可以用作档案实现的基类.

common_oarchive<text_oarchive>
该类的功能是在 basic_oarchive 使用的虚函数接口与档案类实现使用的模板接口之间建立连接.

basic_text_oarchive<text_oarchive>
实现简单文本档案的基本功能. 原始 save 函数已被分解出来, 因此它可以用于其他基于文本的档案, 例如 XML 档案.

basic_text_oprimitive<basic_ostream>
实现所有原始类型的 save 重载. 这是一个带有描述流的参数的模板.

text_oarchive_impl<text_oarchive>
继承上面两个类来实现文本档案.

text_oarchive
这只是 text_oarchive_impl<text_oarchive> 的简写. 我们不能用 typedef, 因为 typedef 不能在其定义中引用自身. 这是用于向文本档案序列化的类名.

interface_oarchive<polymorphic_oarchive>
与上面相同的模板. 不过这次 Archive 参数指的是带虚函数接口的多态档案, 而不是 common_oarchive 使用的模板接口.

polymorphic_oarchive
一个为所有原始类型 T 提供虚 save(T &t) 列表的类. 这是用于为现有和未来所有档案对类进行预编译序列化的类.

polymorphic_oarchive_route<text_oarchive_impl<text_oarchive> >

该类以某个具体类来实现 polymorphic_oarchive. 虚函数调用被路由到实现类. 在这个例子中, 实现类是 text_oarchive_impl.

polymorphic_text_oarchive
这只是一个 typedef, 以便我们可以写 polymorphic_text_archive 而不是 polymorphic_oarchive_route<text_oarchive_impl<text_oarchive> >
