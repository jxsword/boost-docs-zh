本库包含大量文件. 它们按照上面索引中列出的用途进行组织和分类.

类和模板的 namespace 与文件所在的目录保持同步. 例如, 类声明 


boost::archive::text_oarchive
通过以下声明包含 

#include <boost/archive/text_oarchive.hpp>

用户程序包含的文件

使用本库需要包含本节列出的头文件. 应当不需要显式包含任何其他头文件.

档案实现

这些头文件包含用于向每种档案保存和恢复数据的声明. 根据代码模块所需的设施包含相应档案.

boost/archive/binary_oarchive.hpp
用于保存的原生二进制输出档案.
boost/archive/text_iarchive.hpp
用于加载的文本输入档案.
boost/archive/text_oarchive.hpp
用于保存的文本输出档案.
boost/archive/text_wiarchive.hpp
用于加载的宽字符文本输入档案.
boost/archive/text_woarchive.hpp
用于保存的宽字符文本输出档案.
boost/archive/xml_iarchive.hpp
用于加载的 xml 输入档案.
boost/archive/xml_oarchive.hpp
用于保存的 xml 输出档案.
boost/archive/xml_wiarchive.hpp
用于加载的宽字符 xml 输入档案.
boost/archive/xml_woarchive.hpp
用于保存的宽字符 xml 输出档案.

序列化声明

要指定某个类型如何序列化, 需要为序列化函数编写模板. 在最简单的情况下, 这不需要为此包含任何头文件. 在大多数情况下, 必须包含以下一个或多个头文件, 以完成或细化给定类序列化实现的描述.
boost/serialization/base_object.hpp
用于基类的序列化.
boost/serialization/nvp.hpp
把名称标签与可序列化对象关联. 要正确渲染包含对象名的 xml 档案, 这是必需的.
boost/serialization/split_free.hpp
把 非侵入式 序列化的实现拆分为独立的 save 和 load 函数.
boost/serialization/split_member.hpp
把 侵入式 序列化的实现拆分为独立的 save 和 load 函数.
boost/serialization/export.hpp
通过键导出实现对派生类指针的序列化.
boost/serialization/assume_abstract.hpp
这只是一个薄封装, 允许显式指明某个特定类型是抽象基类. 对于不支持 boost type traits 的 is_abstact 实现的编译器, 需要使用它.
这一组用得较少. 它们用于为指定类型覆盖序列化过程默认实现的某些方面.
boost/serialization/version.hpp
覆盖分配给类的默认版本号 (0) .
boost/serialization/level.hpp
覆盖为某类型指定的默认实现级别特征.
boost/serialization/tracking.hpp
覆盖为某类型指定的默认跟踪特征.
boost/serialization/type_info_implementation.hpp
默认情况下, 库使用 RTTI 在运行期识别类型. 在某些情况下 (例如不支持 RTTI 的平台) , 可以包含此头文件, 以允许覆盖默认的运行期类型识别系统.

序列化实现

这一组头文件包含为标准库或 Boost 库模板实现序列化的模板. 任何使用这些模板的程序, 只需包含相应头文件即可调用这些类型对象的序列化.

按照惯例, 这些头文件命名为 boost/serialization/xxx.hpp, 其中 xxx 是包含待序列化类型的头文件的名称. 例如, 声明 


#include <boost/serialization/list.hpp>
包含实现 STL std::list 类型序列化的代码. 而 

#include <boost/serialization/shared_ptr.hpp>
包含实现 BOOST boost::shared_ptr 类型序列化的代码. 注意, 包含某类型的序列化头文件会自动包含待序列化类型的相应头文件. 截至撰写本文时, 本库包含所有 STL 库模板的模板, 以及 boost::optional、boost::shared_ptr 和 boost::scoped_ptr 的模板. 预计这一列表会随时间推移而扩展.

实现本库的文件

档案开发

这些头文件包含用于创建具体档案类型的基本类型声明, 这些具体档案类型已在上面提供给用户. 希望自制档案类型的用户可能想研究这些头文件, 看看库中包含的档案是如何构建的.
boost/archive/basic_archive.hpp
此文件包含某些类型的声明, 这些类型必须在所有档案实现中加以处理. 序列化系统依赖某些特殊类型 (如 class_id_type 等) 在档案中记录重建原始数据结构所需的信息. 它们与其他任何可序列化类型的处理方式完全相同. 也就是说, 它们可以像简单文本文件中那样作为简单原始数据处理, 也可以像 xml 档案中那样用特殊代码处理.
boost/archive/basic_text_oprimitive.hpp
boost/archive/basic_text_iprimitive.hpp
以字符或宽字符文本流的形式实现原始类型的序列化. 它用于文本档案和 xml 档案的实现. 可以设想, 它对实现其他变体的文本档案 (如用户友好的文本或 Windows ini 文件) 也会有用.
boost/archive/basic_binary_oprimitive.hpp
boost/archive/basic_binary_iprimitive.hpp
以字符或宽字符二进制流的形式实现原始类型的序列化.
boost/archive/basic_binary_oarchive.hpp
boost/archive/basic_binary_iarchive.hpp
以字符或宽字符二进制流的形式实现所有类型的序列化. 它与上面的二进制原语实现分开分解. 这有助于将来创建其他类型的二进制档案, 也保持了与库其余部分的类比性和对称性, 有助于理解.
boost/archive/basic_text_oarchive.hpp
boost/archive/basic_text_iarchive.hpp
boost/archive/basic_xml_oarchive.hpp
boost/archive/basic_xml_iarchive.hpp
以字符或宽字符文本流的形式实现所有类型的序列化. 这些类逐类型地指定档案类型特定的行为. 例如, basic_xml_oarchive.hpp 包含保证任何未附加名称的对象在编译期被拦截的代码. 另一方面, basic_text_oarchive.hpp 包含剥离并忽略附加到对象上的任何名称的代码.

boost/archive/detail/common_iarchive.hpp
boost/archive/detail/common_oarchive.hpp
所有档案实现都从这些头文件派生. 它们提供到库内部实现细节的接口.

档案内部机制

接口 (见 档案概念 ) 与实现被分解到独立的类中, 以尽量减少代码重复. 这些文件位于目录 boost/archive/detail 中. 它们由上面列出的档案类实现按需包含. 这有一个不幸的副作用: 使实现不那么透明. 用户应当永远不需要改动这些文件.

boost/archive/detail/interface_iarchive.hpp
这里是 archive_concept 的声明和定义. 该类把对档案接口的调用重定向到最派生档案类中名为 save_override 的函数.
save_override 在档案层次结构的每个类中声明并实现. 

template<class T>
void save_override(T & t, BOOST_PFTO int){
    // All for otherwise unhandled types are forwarded to the base class.
    // This emulates behavior for function overloading.
    this->base::save_override(t, 0);
}
void save_override(const some_type & t, int){
    // any special handling for some type
    // this will usually entail forwarding some other operation
    // in the most derived class.
    this->This()->...
    // or in one of its parents basic_text_oprimitive
    this->This()->save(static_cast<int>(t));
}
... // other special type handling
注意 部分函数模板排序 的用法, 它用于选择正确的 save 实现.

档案库代码模块

库的一部分以库代码实现. 所有这些代码都以 *.cpp 的形式位于 libs/serialization/src 中. 目录 boost/archive/impl 包含实现模板的 *.ipp 文件. 这些模板只由档案实现实例化, 因此通常不包含在用户代码模块中.

通过预编译代码与模板化头文件实现库的权衡是众所周知的. 本库两者兼用. 它使用模板化头文件生成序列化用户类型和原始类型的代码, 并使用预编译库代码来实现只依赖档案类型的那部分代码. 构建库时会为所有已实现的档案生成并编译代码.

  • 用户类型和原始类型的序列化以最高速度运行. 这与先前不使用模板实现档案的库版本有明显差别.
  • 从不改变的库实现代码只需编译一次, 而不必在每次重新编译用户程序时都编译. 这可以节省大量开发时间.
  • 只与实现相关的头文件只需包含在库代码模块中. 这防止用户程序意外依赖序列化库的某个实现特性.
  • 在构建库的过程中, 我得出结论: 关于静态代码/数据实例化, 可能出现一些情形, 若没有代码模块就无法令人满意地解决. 遗憾的是, 我已经忘记促使我得出这一结论的具体情形.
一个例子是库中对 spirit 库的使用. 它编译耗时长且包含许多其他文件. 只在库中包含它, 比在每个使用 xml 序列化的程序中都包含它方便得多.

数据流迭代器

在开发本库的过程中, 构建一组可组合的迭代器适配器来处理档案文本变得很方便. 应用包括转义与反转义 xml 文本、实现与 base64 的相互转换等.

这本身就是一个值得深入的主题. boost 迭代器 库、 View Template Library 等都有所涉及.

这些迭代器的代码实际上独立于本库. 但由于它尚未、且可能不会在此上下文之外被评审, 我把它放在序列化库本地的目录中: boost/archive/iterators . 这些迭代器在 数据流迭代器 中有描述.
