与 Boost 1.58 的差异

  • 取消对 Borland 编译器以及 7.1 之前 Microsoft 编译器的支持.
  • 取消对不支持部分函数模板排序 (pfto) 的编译器的支持.
  • 为 GCC 编译器加入对"visibility hidden"的支持. 共享库将只暴露实际需要的符号, 而不是库中的所有符号. 这应当会产生更小、加载更快的共享库.

与 Boost 1.48 的差异

  • 加入对 C++11 类型 (如 std::shared_ptr、std::array 等) 的支持.
  • 实现了"辅助类" (Helper) 概念, 可用于实现那些原本不可序列化的类型的序列化.
  • 使库兼容 C++11, 同时保持与 C++03 的兼容性.

与 Boost 1.45 的差异

自 1.42 版发布以来, 发现 1.42-1.44 版创建的二进制档案并不总能被最新的二进制档案代码读取. 查明这些异常来源的工作一直在进行, 那些附带测试用例报告的异常已经修复. 截至撰写本文时, 尚不知道是否所有用这些版本创建的二进制档案都能加载.

与 Boost 1.43 的差异

  • 修复了虚基类序列化中的缺陷. 多亏 Takatoshi Kondo 的卓越努力.
  • 在 1.42 和 1.43 版本下创建的原生二进制档案存在一个严重问题. 它们很可能无法被这个最新版本读取. 原因在于 1.42 对某些类型的二进制格式做了一些改动. 通常这可以通过检测写入档案头的库版本号来处理. 遗憾的是, 这个库版本号在 1.42 时没有按应当的那样递增. 于是现在我们有了两个库版本号相同但二进制档案版本不同的版本.

    对此的解决办法是在示例目录中加入一个名为 fix_six.cpp 的小工具. 应当用如下命令行运行它: 

        fix_six <file name>
    这会把 7 赋给档案的库版本号. 此修复需要应用到用 boost 1.42 和 1.43 创建的原生二进制档案上.

与 Boost 1.42 的差异

  • 修复了序列化通过 enable_shared_from_this 创建的指针时 shared_ptr 序列化失败的问题.
  • 添加了一个可用作调试日志的简单档案示例. 该示例演示档案概念的实现, 以帮助理解创建自己的档案类所需的知识. 得到的档案对调试很有用: 它只有 160 行代码, 而且是仅头文件的——也就是说, 不需要链接序列化库.
  • 替换了用于演示如何从现有档案派生的示例. 这个示例创建的 XML 档案类不包含 class_id、class_version 等序列化特征. 它可能对把自己的类信息导出给某个 XML 处理器和/或调试程序有用.
  • 实现了编译期警告, 用以检测那些虽然正确、但会导致与用户预期不同的操作或副作用的做法.
  • 修复了与 void_cast 相关的一些内存泄漏.

与 Boost 1.41 的差异

  • 做了调整以尽量减少编译期警告.
  • 实现了编译期警告, 用以检测那些虽然正确、但会导致与用户预期不同的操作或副作用的做法.
  • 修复了与 void_cast 相关的一些内存泄漏.

与 Boost 1.40 的差异

本库已针对 Boost 1.39 和 1.40 版进行测试.

对库中包含的档案类做了更改. 把这些当作制作自己档案类指南的用户会发现它们可能无法再编译. 可以通过在实例化这些档案类的代码中做以下更改来补救.

旧代码: 
...
#include <boost/archive/impl/archive_pointer_iserializer.ipp>
...
template class detail::archive_pointer_iserializer<naked_text_iarchive> ;
...
template class detail::archive_pointer_iserializer<text_iarchive> ;
应替换为以下新代码: 
#include <boost/archive/impl/archive_serializer_map.ipp>
...
template class detail::archive_serializer_map<naked_text_iarchive> ;
...
template class detail::archive_serializer_map<text_iarchive> ;

与 Boost 1.39 的差异

  • 现在可以通过指向实现了自身 new/delete 运算符的类的指针序列化对象. 这一功能在某些编译器上不可用.
  • 多态对象的序列化已大幅提速.
截至撰写本文时, 所有以 TRAK 工单形式提交的缺陷报告均已处理. 还有一些待处理的 TRAK 工单, 最好归类为功能请求. 参见 待解决问题 .

与 Boost 1.37 的差异

本版本没有新特性. 截至撰写本文时, 所有以 TRAK 工单形式提交的缺陷报告均已处理. 还有一些待处理的 TRAK 工单, 最好归类为功能请求. 参见 待解决问题 .

与 Boost 1.36 的差异

本版本没有新特性. 截至撰写本文时, 所有以 TRAK 工单形式提交的缺陷报告均已处理.

与 Boost 1.35 的差异

  • 本库现在是线程安全的. 也就是说, 可以在不同线程中打开多个档案. 这是用无锁算法实现的, 以避免任何性能瓶颈.
  • 现在支持对共享库中定义的类型进行序列化. 共享库 (DLL) 可以在运行期动态加载/卸载. 这包括对抽象基类实例的序列化, 使程序可以编写为与尚未定义、尚未实现的代码兼容.
  • 扩展类型信息系统已得到增强, 以实现上述功能. 它现在是一个通用系统, 用于创建和转换只知道字符串 ID 和抽象基类的类型.
  • 所有以 TRAK 工单形式提交的缺陷报告都已处理.
  • 截至撰写本文时, 本库在较旧的编译器 (如 7.1 之前的 MSVC 和较旧版本的 Borland 编译器) 上会构建失败. 未来这可能会也可能不会改变.

与 Boost 1.34 的差异

  • 增强了对原生二进制档案快速序列化的支持. 由 Mattias Troyer 完成.
  • 改进了"导出"功能的实现. 移除了头文件顺序要求, 并免除了对预先确定的"已知档案"列表的维护. 由 David Abrahams 完成.
  • 改进了对 STLPort 的支持.

与 Boost 1.33 的差异

  • 原生二进制档案使用 std::streambuf 接口. 这在许多情况下应能带来明显更快的执行速度.

与 Boost 1.32 的差异

  • 面向支持动态链接库 (DLL 和共享库) 的平台. 参见 Windows 上的自动链接 .
  • 为能够支持该特性的编译器实现自动链接.
  • 更好地支持 实参依赖查找 和两阶段查找. 这带来了关于序列化特化放置在哪些命名空间的更简单规则.
  • 增强文档以帮助解释上述内容的用法.
  • 调整以改进对合规性较差编译器的支持.
  • 改进了 save/load 运算符的 const 正确性. 注意, 这可能在先前 boost 发布版中编译无误的代码中产生编译期错误. 大多数情况下修复很简单. 其他情况下, 应当仔细审查代码, 确保它没有以可能给程序引入隐蔽缺陷的方式使用序列化系统. 关于这一问题的更完整解释可在 此处 找到.
  • 为 shared_ptr<T> 提供了新的序列化实现. 它与 shared_ptr<T> 的公共接口兼容, 因此应当更健壮, 将来也不必改动. 该实现可选地包含加载 boost 1.32 创建的档案中所存 shared_ptr<T> 的代码. 这段代码存放在头文件 boost/serialization/shared_ptr_132.hpp 中. 如果你的应用程序需要加载用 boost 1.32 库创建的档案, 请在每次包含 boost/serialization/shared_ptr.hpp 之前包含上述头文件.
  • 测试并支持了更多编译器.
  • 若干杂项缺陷修复.

待解决问题

  • 右值无法被序列化. 对未跟踪类型实现这一点是可能的, 但尚未做.
  • 指向指针的指针目前无法被序列化
  • std::string 和 std::wstring 中可能包含诸如 '' 和 -1 (EOF) 之类的字符, 在没有转义机制的情况下无法在文本档案和 XML 档案中呈现. 目前尚未实现这样的转义机制.
  • 本版本修复了 std::map 序列化实现中的一个微妙错误. 遗憾的是, 对于不支持模板偏特化的编译器, 该修复破坏了 std::map 的序列化. 此外, 包含指针或被跟踪的类型可能无法正确工作.
  • 虚基类的序列化依赖 RTTI. 在未启用 RTTI 的系统上使用将会失败.

除上述之外, 还有一些与特定平台相关的问题. 它们列在 特定编译器/库问题 中.
