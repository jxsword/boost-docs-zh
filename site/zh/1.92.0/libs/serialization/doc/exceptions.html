档案运算符可以抛出 boost::archive_exception 对象, 应用程序可以捕获它. 这些异常定义在文件 archive_exception.hpp 和 basic_xml_archive.hpp 中. 

namespace boost {
namespace archive {

class archive_exception  : public std::exception
{
public:
    typedef enum {
        unregistered_class,     // attempt to serialize a pointer of
                                // an unregistered class
        invalid_signature,      // first line of archive does not contain
                                // expected string
        unsupported_version,    // archive created with library version subsequent
                                // to this one
        pointer_conflict        // an attempt has been made to directly serialize
                                // an object after having already serialized the same
                                // object through a pointer.  Were this permitted, 
                                // the archive load would result in the creation
                                // of an extraneous object.
        incompatible_native_format, // attempt to read native binary format
                                // on incompatible platform
        array_size_too_short,   // array being loaded doesn't fit in array allocated
        input_stream_error      // error on stream input
        invalid_class_name,     // class name greater than the maximum permitted.
                                // most likely a corrupted archive or an attempt
                                // to insert virus via buffer overrun method.
        unregistered_cast,      // base - derived relationship not registered with 
                                // void_cast_register
        unsupported_class_version, // type saved with a version # greater than the 
                            // one used by the program.  This indicates that the program
                            // needs to be rebuilt.
        multiple_code_instantiation, // code for implementing serialization for some
                            // type has been instantiated in more than one module.
        output_stream_error     // error on stream output
    } exception_code;
    exception_code code;
    archive_exception(exception_code c) : code(c) {}
    virtual const char *what( ) const throw();
};

class xml_archive_exception : public virtual archive_exception
{
public:
    typedef enum {
        xml_archive_parsing_error,  // archive doesn't contain expected data 
	xml_archive_tag_mismatch,   // start/end tag in archive doesn't match program
        xml_archive_tag_name_error  // tag name contains invalid characters

    } exception_code;
    xml_archive_exception(exception_code c){}
    virtual const char *what( ) const throw();
};

} // archive
} // boost

unregistered_class

试图通过指针序列化一个多态类, 却既没有注册它, 也没有用导出键关联它. 当使用一个新档案而其类名尚未通过 BOOST_ARCHIVE_CUSTOM_ARCHIVE_TYPES 宏加入系统时, 也会发生此异常.

invalid_signature

档案以一个已知字符串启动. 如果打开档案时找不到这个字符串, 则假定该文件不是有效档案, 并抛出此异常.

unsupported_version

本系统会把当前库版本号记录到所有创建的档案中. 注意, 这与应用程序使用的类的版本号毫无关系. 这里指的是创建档案所用序列化系统的版本. 该序列化系统的未来版本将能够识别在先前 (即本) 系统下创建的档案, 并相应调整加载过程. 因此, 此序列化系统的未来增强不应使任何现有档案文件作废. 只有当较新的系统创建的档案在格式上与当前系统不兼容时, 才需要递增此版本号.

如果较旧的程序尝试读取格式已改变的较新档案, 就会抛出此异常.

unsupported_class_version

试图加载一个其版本号在程序编写之后被递增的类. 假设某个类被指定版本号 3, 程序已构建并发送给第三方. 现在假设该类的定义被改动, 版本号递增到 4, 并构建了新档案. 如果尝试用原程序加载这些新档案, 就会抛出此异常.

pointer_conflict

要理解这个异常的含义, 考虑以下场景 

template<class Archive>
void T::save(Archive &ar) const
{
    const A * aptr = &a;
    ar << aptr;          // save an instance of object of class A through a pointer
    ...
    ar << a;             // save an instance of an object of class A
    assert(aptr == &a);  // this must be true
}

template<class Archive>
void T::load(Archive &ar)
{
    A * aptr;
    ar >> aptr;          // create and initialize a new instance of class A
    ...
    ar >> a;             // restore state of on object of class A
    assert(aptr == &a);  // this won't be true
}
一个对象先通过指针保存, 然后又被直接保存. 按相同顺序加载回来时, 我们先创建一个新对象并把数据加载进去. 然后我们又把数据加载到另一个已存在的对象中. 保存时我们只有一个对象, 恢复后却有两个对象. 在更实际的情况下, 这个错误可能非常难以发现. 所幸这些情况可以在档案创建时检测到. 发生这种情况时, 会抛出此异常.

incompatible_native_format

本库目前支持 char 文本、宽字符文本和原生二进制档案文件. 每个档案的开头都会写入一个签名, 表明档案的类型. 当试图读取以不同格式写入的档案时会抛出此异常.

array_size_too_short

试图读取一个大于数组大小的数组. 这应当只在档案创建之后代码中的数组大小被缩小的情况下发生.

input_stream_error
output_stream_error

流输入或输出期间发生错误. 除了损坏或被截断的输入文件等常见情况外, 还有一些不太明显的情况偶尔出现.

这包括试图读取越过文件末尾. 文本文件在文件末尾需要一个终止换行符, 它在档案析构函数被调用时追加. 请确保在同一个流上打开输入档案之前, 输出档案已被销毁. 也就是说, 不要使用类似这样的写法: 


std::stringstream ss;
std::vector<V> v;
boost::archive::text_oarchive oa(ss);
oa << v;
boost::archive::text_iarchive ia(ss);
ia >> v;
而应使用 

std::stringstream ss;
std::vector<V> v;
{
    boost::archive::text_oarchive oa(ss);
    oa << v;
}
{
    boost::archive::text_iarchive ia(ss);
    ia >> v;
}

另一个是传入未初始化的数据. 一般来说, 向序列化库传入未初始化数据时的行为是未定义的. 如果能够检测到, 它会在调试构建中触发断言. 否则, 取决于档案类型, 它可能安然通过, 也可能导致档案中出现意外的数据. 这进而可能导致抛出此异常.

invalid_class_name

类名长度超过允许的最大值. 最可能的原因是档案损坏, 或有人试图通过缓冲区溢出方法植入病毒.

unregistered_cast

为了在运行期支持基类与派生类指针之间的转换, 系统维护着一个合法转换的集合. 通常这个集合的维护不需要库使用者做任何显式操作. 不过, 存在某些特殊情况需要显式完成且可能被遗漏. 这在 运行期转换 中有描述. 如果试图在两个尚未注册其关系的指针之间转换, 就会抛出此异常,

multiple_code_instantiation

当检测到同一类型的序列化被实例化多次时抛出此异常. 这可能发生在序列化代码同时被主程序和一个或多个 DLL 实例化的情况下.

xml_archive_parsing_error

序列化过程生成的 XML 与 C++ 类结构、对象之间的关系以及序列化规格紧密耦合. 如果这些以任何方式失去同步, XML 可能无法映射到加载序列化, 就可能抛出此异常. 这可能是以下原因之一造成的:
  • 档案在序列化系统之外被编辑过. 如果只改了数据而 XML 属性和嵌套结构保持不变, 这也许是可行的. 但任何其他编辑都可能使档案无法被序列化库读取.
  • 序列化已被改动, 而正在读取的是旧代码生成的档案. 也就是说, 没有正确运用版本控制来正确反序列化先前创建的档案.

xml_archive_tag_mismatch

如果 XML 元素的开始或结束标签与程序中为对象指定的名称不匹配, 就会抛出此异常.

xml_archive_tag_name_error

如果标签名包含无效字符, 就会抛出此异常. XML 标签的有效字符是: 大小写字母、数字, 以及以下标点: . (句点) 、_ (下划线) 、: (冒号) 和 - (连字符) .
