记法

在以下描述中
  • SA 是建模 保存档案概念 的类型.
  • sa 是 SA 类型的一个实例.
  • LA 是建模 加载档案概念 的类型.
  • la 是 LA 类型的一个实例.
  • T 是一个 Serializable 类型.
  • x 是 T 类型的一个实例.
  • u,v 是指向 T 类型实例的指针.
  • count 是可转换为 std::size_t 的类型的一个实例.

保存档案概念

关联类型

直观地说, 建模此概念的类型会生成对应于任意 C++ 数据结构集合的字节序列. 每个建模保存档案概念 (SA) 的类型都可以关联到另一个建模 加载档案概念 的类型 (LA) . 这个关联类型执行逆操作. 也就是说, 给定由 SA 生成的字节序列, 它会生成一组与原来等价的 C++ 数据结构. 等价的概念由这对档案的实现以及数据以 可序列化 方式渲染的方法定义.

有效表达式

SA::is_saving

返回 Boost MPL 整型常量类型 boost::mpl::bool_<true>

SA::is_loading

返回 Boost MPL 整型常量类型 boost::mpl::bool_<false>

sa << x
sa & x

这些表达式必须执行完全相同的功能. 它们把 x 的值连同其他信息追加到 sa. 这些其他信息由档案的实现定义. 通常, 这些信息是对应的加载档案类型正确恢复 x 的值所需的.

返回对 sa 的引用.

sa.save_binary(u, count)

把 size_t(count) 个字节 (位于 u 处) 追加到档案.

sa.register_type<T>()
sa.register_type(u)

向档案追加关于类 T 的信息. 当对应的加载档案类型加载派生类指针时, 这些信息用于构造正确的类. 调用该成员函数称为"类注册". 详见 特别注意事项 - 派生指针 . 包含第二种语法是为了在 sa 是模板实参时, 允许在不合标准的编译器上调用此函数. 更多信息参见 模板调用语法

sa.get_library_version()

返回一个无符号整数, 包含序列化库的当前版本号. 每当库以可能改变某个类型序列化的方式被修改时, 该数字都会递增. 例如, 假设用于统计集合成员数量的类型发生了变化. 加载集合的代码可以依据库版本进行分支, 以确保由先前版本库创建的库仍然可读.

sa.get_helper<Helper>(void * const helper_instance_id = 0)

参见下文的 la.get_helper<Helper>(void * const helper_instance_id = 0).

加载档案概念

关联类型

此概念的每个模型都假定存在一个对应的建模 保存档案概念 的类型. 此概念实例的用途是把由该对应类型生成的字节序列转换为与原来等价的一组 C++ 数据结构.

有效表达式

LA::is_saving

返回 Boost MPL 整型常量类型 boost::mpl::bool_<false>

LA::is_loading

返回 Boost MPL 整型常量类型 boost::mpl::bool_<true>

la >> x
la & x

这些表达式必须执行完全相同的功能. 把 x 设置为从 la 获取的值.

返回对 la 的引用.

la.load_binary(u, count)

从 la 获取 size_t(count) 个字节, 并存储到从 u 开始的内存中.

la.register_type<T>()
la.register_type(u)

从档案获取关于类 T 的信息. 当加载程序中未以名称提及的派生类指针时, 这些信息用于构造正确的类. 调用该成员函数称为"类注册". 详见 特别注意事项 - 派生指针 . 包含第二种语法是为了在 la 是模板实参时, 允许在不合标准的编译器上调用此函数. 更多信息参见 模板调用语法

la.get_library_version()

返回一个无符号整数, 包含创建该档案的序列化库的版本号. 每当库以可能改变某个类型序列化的方式被修改时, 该数字都会递增. 例如, 假设用于统计集合成员数量的类型发生了变化. 加载集合的代码可以依据库版本进行分支, 以确保由先前版本库创建的库仍然可读.

la.get_helper<Helper>(void * const helper_instance_id)

某些原本不可序列化的类型可以通过引入一个辅助 (helper) 对象变为可序列化. 标志性示例是 shared_ptr, 它需要这个辅助对象来跟踪先前加载的 shared_ptr 实例, 以便它们能与随后加载的实例"配对". 当 la.get_helper<Helper>(void * const helper_instance_id) 第一次以给定的 helper_instance_id (即 Helper) 被调用时, 会创建一个默认构造的 Helper 对象, 将其附加到 la 并返回其引用. 之后以相同 id 值调用 la.get_helper<Helper>(void * const helper_instance_id) 会返回先前构造对象的引用. 以这种方式创建的所有对象都会在 la 析构时销毁. 辅助对象的用途在 特别注意事项 - 辅助对象支持 中讨论.

la.reset_object_address(v, u)

告知档案: 原先位于地址 u 的对象已被移动到地址 v.

当对象被加载到临时变量、之后又移动到另一位置时, 必须调用此函数来告知这一事实. 这使档案能正确实现对象跟踪. 要正确实现指向派生类实例的指针的序列化, 对象跟踪是必需的.

la.delete_created_pointers()

删除通过加载指针创建的所有对象. 它可用于避免内存泄漏——如果正在加载指针而档案加载遇到异常, 本来可能发生泄漏.
有基于文本、二进制和 XML 文件格式的档案, 但它们都具有上述接口. 鉴于所有档案都呈现相同的公共接口, 对序列化的规定对所有档案都完全相同. 档案类还有这里未提及的其他成员. 不过它们与库的内部运作相关, 并非供档案使用者调用. 新档案的实现将在 新档案 - 实现 中讨论.

<< 和 >> 的存在暗示档案与 C++ i/o 流之间存在某种关系. 档案不是 C++ i/o 流 . 本系统包含的所有档案都在构造函数中接受一个流作为实参, 该流用于输出或输入. 但这并不是序列化函数或档案接口的要求. 只是到目前为止所写的档案都发现基于流来实现很有用.

档案模型

本库包含档案概念的多种实现. 档案由两个互补的类定义. 一个用于保存数据, 另一个用于加载数据. 本库包含多个"开箱即用"的档案实现, 可满足最常见的需求. 这些类针对不同的数据格式实现档案概念. 它们可以"按原样"使用, 也可以作为开发自己特定档案类型的基础. 档案由两个互补的类定义. 一个用于保存数据, 另一个用于加载数据. 要使用这些档案之一调用序列化, 必须在包含序列化代码的代码模块中包含以下一个或多个头文件. 

// a portable text archive
boost::archive::text_oarchive // saving
boost::archive::text_iarchive // loading

// a portable text archive using a wide character stream
boost::archive::text_woarchive // saving
boost::archive::text_wiarchive // loading

// a portable XML archive
boost::archive::xml_oarchive // saving
boost::archive::xml_iarchive // loading

// a portable XML archive which uses wide characters - use for utf-8 output
boost::archive::xml_woarchive // saving
boost::archive::xml_wiarchive // loading

// a non-portable native binary archive
boost::archive::binary_oarchive // saving
boost::archive::binary_iarchive // loading
所有这些档案实现相同的接口. 因此, 只需详细描述其中一个即可. 为此我们将使用文本档案. 

namespace boost {
namespace archive {

enum archive_flags {
    no_header = 1,          // suppress archive header info
    no_codecvt = 2,         // suppress alteration of codecvt facet
    no_xml_tag_checking = 4 // suppress checking of xml tags - ignored on saving
};

} // archive
} // boost


namespace boost {
namespace archive {

class text_oarchive : ...
{
    ...
public:
    ... // implementation of the Saving Archive concept
    text_oarchive(std::ostream & os, unsigned int flags = 0);
    ~text_oarchive();
};

} // archive
} // boost

text_oarchive(std::ostream & os, unsigned int flags = 0);

构造档案时以一个打开的 stream 作为实参, 并接受可选标志. 对大多数应用而言, 无需使用标志. 标志由 enum archive_flags 枚举定义. 多个标志可以用 | 运算符组合. 默认情况下, 档案会在输出前加上初始数据, 有助于把它们识别为本系统产生的档案. 这样就可以更从容地处理试图从无效文件格式加载档案的情况. 除此之外, 每种档案可能有自己的信息. 例如, 原生二进制档案包含关于原生类型大小和字节序的信息, 以从容处理错误地假定此类档案可跨平台移植的情况. 在某些情况下, 如果认为这些额外开销不可接受, 可以用 no_header 标志将其禁止.

在某些情况下, 档案可能改变 (之后恢复) 流 locale 的 codecvt facet. 要禁止这一行为, 请包含 no_codecvt 标志.

XML 档案包含表示数据字段开始和结束的嵌套标签. 加载数据时通常会检查这些标签与对象名是否一致. 如果不一致则抛出异常. 这可能不是所期望的行为. 要禁止对 XML 标签的这种检查, 请使用 no_xml_tag_checking 标志.

~text_oarchive();

档案的析构函数. 应在流关闭之前调用. 它把任何被改变的流 facet 恢复到档案打开之前的状态.

namespace boost {
namespace archive {

class text_iarchive : ...
{
    ...
public:
    ... // implementation of the Loading Archive concept
    text_iarchive(std::istream & is, unsigned int flags = 0);
    ~text_iarchive();
};

} //namespace archive
) //namespace boost

text_iarchive(std::istream & is, unsigned int flags = 0);

构造档案时以一个打开的 stream 作为实参, 并接受可选标志. 如果使用标志, 应与创建档案时使用的标志相同. 标志的功能和用法见上文.

~text_iarchive();

档案的析构函数. 应在流关闭之前调用. 它把任何被改变的流 facet 恢复到档案打开之前的状态.

binary_oarchive 和 binary_iarchive 类是基于更基础的 std::streambuf 实现的. 因此, 除上述公共类接口之外, 它们还包括以下构造函数:

binary_oarchive(std::streambuf & bsb, unsigned int flags = 0);

and

binary_iarchive(std::streambuf & bsb, unsigned int flags = 0);

异常

包含的所有档案类都可能抛出异常. 可能抛出的异常列表见本文档的 档案异常 一节.

字符集

本库包含两个用于 XML 的档案类. 宽字符版本 (xml_w?archive) 把输出渲染为 UTF-8, 可以无信息损失地处理任何宽字符. std::string 数据使用当前 locale 从多字节格式转换为宽字符格式. 因此这个版本在所有情况下都应能对所有 C++ 数据给出合理的渲染. 这可能导致一些出乎意料的行为. 假设创建了一个 std::string, 其 locale 字符集设为希伯来字符. 输出时它会转换为宽字符. 但在输入时, 如果 locale 未设置成与创建档案时相同, 就可能出问题.

普通字符版本 (xml_?archive) 不经任何转换地渲染 std::string 输出. 虽然这对序列化可能没有问题, 但如果把 XML 档案用于其他用途, 可能会造成困难.
