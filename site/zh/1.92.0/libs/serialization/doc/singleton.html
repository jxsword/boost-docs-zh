动机

序列化库依赖许多静态变量和表的存在来存储与运行期类型相关的信息. 例如, 把导出名称关联到类型的表, 以及把基类关联到派生类的表. 这些变量的构造、析构和使用需要考虑以下问题:
  • 一些静态数据变量和常量条目会引用其他条目. 初始化的顺序不能任意, 而必须按正确的顺序进行.
  • 许多静态变量没有被显式引用, 若不采取特别防范措施, 大多数代码优化器会把它们剔除
  • 这些变量中许多由模板创建, 必须特别小心以确保它们被实例化
  • 在多线程系统中, 这些静态变量可能被不同线程并发访问. 这会产生具有不可预测行为的竞争条件
这个 singleton 类解决了上述所有问题.

特性

这个单例实现有以下特性:
  • 任何实例都会在任何访问它的尝试之前被构造.
  • 用模板创建的任何实例都保证被实例化.
  • 无论实例是否被显式引用过, 在以 release 模式构建可执行文件时它都不会被优化器剔除.
  • 所有实例都在 main 被调用之前构造, 无论它们在程序中的何处被引用. 在多任务系统中, 这保证任何实例的构造期间都不会有竞争条件. 不需要线程锁来保证这一点.
  • 上面的论述意味着任何 const 实例在整个程序期间都是线程安全的. 同样, 不需要线程锁.
  • 如果创建了可变实例, 并且在多线程系统中该实例在 main 被调用之后被修改, 则存在发生竞争条件的可能. 序列化库注意保证: 在少数需要可变单例的地方, 它不会在 main 被调用之后被改动. 对于更通用的用途, 可以很容易地为该单例实现线程锁. 但由于序列化库不需要它, 就没有实现.

类接口 


namespace boost { 
namespace serialization {

template <class T>
class singleton : public boost::noncopyable
{
public:
    static const T & get_const_instance();
    static T & get_mutable_instance();
    static bool is_destroyed();
};

} // namespace serialization 
} // namespace boost



static const T & get_const_instance();

获取该类型单例的常量引用.


static T & get_mutable_instance();

获取该类型单例的可变引用.


static bool is_destroyed();

如果该单例的析构函数已被调用则返回 true, 否则返回 false.

要求

要用作 singleton<T> , 类型 T 必须可默认构造. 它不要求静态变量——尽管可以有. 由于库保证 singleton<T> 只存在一个实例, 且所有访问都通过上述静态接口函数进行, T 的普通成员函数在功能上等价于 static 函数.

示例

至少有两种不同的方式来使用这个类模板. 序列化库两者都用了.

第一种方法由文件 extended_type_info.cpp 中的摘录说明, 其中包含如下代码: 


typedef std::set<const extended_type_info *, key_compare> ktmap;
...
void
extended_type_info::key_register(const char *key) {
    ...
    result = singleton<ktmap>::get_mutable_instance().insert(this);
    ...
}
只要在程序中任何地方引用该单例实例, 就能保证整个程序中存在一个且仅一个指定类型 (本例中为 ktmap) 的实例. 无需任何其他声明或定义.

第二种方法是使用 singleton<T> 作为该类型的基类之一. 这由 extended_type_info_typeid.hpp 的简化摘录说明 


template<class T>
class extended_type_info_typeid : 
    public detail::extended_type_info_typeid_0,
    public singleton<extended_type_info_typeid<const T> >
{
    friend class singleton<extended_type_info_typeid<const T> >;
private:
    // private constructor to inhibit any existence other than the 
    // static one.  Note: not all compilers support this !!!
    extended_type_info_typeid() :
        detail::extended_type_info_typeid_0()
    {
        type_register(typeid(T));
    }
    ~extended_type_info_typeid(){}
    ...
};
这种用法允许使用更自然的语法: 

extended_type_info_typeid<T>::get_const_instance()
同样, 在程序中任何地方包含上述一条或多条语句, 都会保证创建并引用一个且仅一个实例.

多线程

只要小心遵守一条简单的规则, 该单例就可以安全地用于多线程应用程序:

当多个线程正在运行时不要调用 get_mutable_instance! 序列化库中使用的所有单例都遵守这条规则. 为帮助检测对这条规则的意外违反, 存在单例加锁/解锁函数. 


void boost::serialization::singleton_module::lock();
void boost::serialization::singleton_module::unlock();
bool boost::serialization::singleton_module::is_locked();
在为调试编译的程序中, 当库处于"已锁定"状态时, 任何对 get_mutable_instance() 的调用都会在断言处被拦截. 单例模块的锁状态初始化为"未锁定", 以允许在 main 被调用之前改动静态变量. lock() 和 unlock() 是"全局"的, 它们影响此模板定义的所有单例. 所有序列化测试都在程序开始时调用 lock(). 对于以 release 模式编译的程序, 这些函数没有任何效果.
