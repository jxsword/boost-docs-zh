有时创建一个临时对象来支持某些底层数据的序列化会很方便. 这允许档案类对该类型定义特殊处理. 本库包含若干这样的类型, 各有不同用途.

某些档案需要以特殊方式对待包装器, 因此这些包装器类的 is_wrapper 特征被设为 true.

二进制对象

二进制对象就是存储为原始二进制数据的字节序列. 它最可能用于大量"轻量"数据, 例如像素图或内嵌的二进制文件. 头文件 binary_object.hpp 包含构造函数: 

boost::serialization::binary_object(void * t, size_t size);
boost::serialization::make_binary_object(void * t, size_t size);
它会构造一个临时二进制对象, 可以像任何其他对象一样被序列化. 其默认序列化是使用档案类原语 save_binary 和 load_binary. 注意, 它不分配任何存储也不创建任何对象. 它的唯一目的是把数据大小和地址作为一对传给档案类.

数组

数组是同质数据类型的连续序列, 例如内建 C 数组、boost::array<T> 或 std::vector<T>. 这个包装器的用途是支持为同类型对象的连续序列提供优化序列化的档案类型 (例如二进制档案) . 头文件 array.hpp 包含函数 

template <T>
boost::serialization::make_array(T* t, std::size_t size);
, 它会构造一个临时 array 对象 

template<class T>
class array
{
public:    
    typedef T value_type;
    array(value_type* t, std::size_t s);
    value_type* address() const;
    std::size_t count() const;
};
, 可以像任何其他对象一样被序列化. 其默认序列化是逐个序列化数组元素. 注意, 它不分配任何存储也不创建任何对象. 它的唯一目的是把数据类型、大小和地址传给档案类. 能够为同质数据类型连续数组提供优化实现的档案类型应当重载 array 的序列化.

BOOST_STRONG_TYPEDEF

序列化包装器的另一个例子是 BOOST_STRONG_TYPEDEF 模板. 序列化库用它们把特定种类的整数 (例如 object_id、version 等) 传给档案类. 鉴于这些整数现在可以按类型区分, XML 档案可以对这些类型应用特殊处理. 例如, 版本号会以 "version=12" 的形式呈现为 XML 属性. 在没有任何特定重写的情况下, 这些类型会自动转换为底层整数类型, 因此用于 XML 档案的特殊重写对其他档案并不需要.

集合大小

强 typedef 的一个例子是 collection_size_type, 位于头文件 collection_size_type.hpp 中. 此类型应当用于序列化 C++ 集合的大小, 使档案能为集合大小的序列化挑选最佳整数表示. 这是必要的, 因为虽然 std::size_t 被保证是足以表示特定平台上集合大小的整数类型, 档案可能希望以不同于该类型的方式序列化大小. 例如, collection_size_type 在可移植二进制档案中可能被序列化为变长整数.

名值对

XML 档案是一个 somewhat 特殊的情况. XML 格式具有嵌套结构, 与序列化系统使用的"递归类成员访问器"模式映射良好. 然而, XML 与其他格式的不同之处在于它要求每个类数据成员都有名称. 我们的目标是在把这一信息加入类序列化规定的同时, 仍允许序列化代码用于任何档案.

我们的解决办法是把要序列化的类成员包装在 名值对 中. 该结构定义于 nvp.hpp . 它只是对数据成员的引用, 加上一个指向 const char * (对应 XML 名称) 的指针. 它实现了名值对的默认序列化函数. 默认行为只是忽略条目名称, 按常规方式序列化数据值. 对于没有为名值对做任何特殊处理的档案类, 序列化名值对时调用的就是这一行为. 因此, 把数据值包装进名值对, 在用于没有为此包装器做特殊处理的档案时不会有任何影响.

xml 档案类包含类似这样的代码: 


// special treatment for name-value pairs.
template<class T>
xml_oarchive & operator&(const boost::serialization::nvp<T> & t)
{
    // write an xml start tag
    start_tag(t.name());

    // serialize the data as usual
    *this & t.value();

    // write an xml end tag
    end_tag(t.name());
}
分配为 XML 数据项名称的最显然、最方便的名称——出乎意料吧! ——正是 C++ 类数据成员的名称. 因此我们的序列化代码看起来像: 

ar & make_nvp("my_variable", my_variable);
为简化输入并增强可读性, 定义了一个宏, 使我们可以写: 

ar & BOOST_SERIALIZATION_NVP(my_variable);
类似地, 还存在一个宏定义, 允许我们写: 

BOOST_SERIALIZATION_BASE_OBJECT_NVP(my_base_class)
注意, 这些宏必须在类所在的命名空间中使用, 且实参中不限定命名空间.

demo_gps.hpp 为所有数据成员包含 NVP 包装器. demo_xml.cpp 向 XML 档案保存和加载数据. 此处 是与本教程示例对应的 XML 档案示例.

组合

包装器的设计应当使其能够按需组合. 例如, 要把二进制数据作为名值对传递, 使用: 

ar & make_nvp("named_binary_object", make_binary_object(address, size));
