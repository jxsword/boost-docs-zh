动机

序列化库需要一个像 type_info/typeid() 这样的系统来执行以下功能
  1. 给定指向类型 T 的指针, 发现所指向的真实类型.
  2. 给定一个"外部"键——确定要创建什么类型的对象.

问题出在 std::type_info

  • 我们需要的主要函数——std::typeid()——并非在所有环境中都可用. 对该函数的支持取决于编译器的运行期类型 (RTTI) 支持. 由于被认为低效等原因, 它可能不存在或未启用.
  • std::type_info 包含一个含有类型名的字符串. 这看起来能满足上面的 2). 但这个字符串的格式在编译器、库和操作系统之间并不一致. 这使得它无法用于支持可移植档案.
  • 即使类型名字符串能以某种方式做到可移植, 也无法保证类的头文件在不同应用程序中会被包含在相同的命名空间里. 事实上, 把不同的头文件包含在不同的命名空间中, 是避免命名空间冲突的一种公认做法. 因此 namespace::class_name 不能用作键.
  • 存在这样的可能性: 不同的类使用不同的类型 id 机制. 类头文件可能包含这一信息. 如果我们想跨应用程序导入类头文件, 最好让类型 id 机制支持跨不同类型 id 系统的互操作.

特性

extended_type_info 是 std::type_info 功能的一个实现, 具有以下特性:
  • 构建一组 extended_type_info 记录——每个被序列化的类型一条.
  • 允许把任意字符串键与某个类型关联. 这个键通常是类名——但不一定是. 这个键被称为 GUID (全局唯一标识符) . 按理它在全世界应当唯一. 通常这个 GUID 放在头文件中, 用于跨应用程序匹配类型. 可以调用宏 BOOST_CLASS_EXPORT 把字符串键与任何已知类型关联. 我们把这类类型称为"导出类型".
  • 允许"混用"类型信息系统. 例如, 一个类可能用 typeid() 来查找类的外部标识符, 而另一个类可能不用.
导出类型保存在一个全局表中, 因此给定字符串键就能找到对应类型. 序列化库利用这一设施来构造通过基类指针序列化的类型.

运行期接口 


namespace boost { 
namespace serialization {

class extended_type_info
{
protected:
    // this class can't be used as is. It's just the 
    // common functionality for all type_info replacement
    // systems.  Hence, make these protected
    extended_type_info(
        const unsigned int type_info_key,
        const char * key
    );
    ~extended_type_info();
    void key_register();
    void key_unregister();
public:
    const char * get_key() const;
    bool operator<(const extended_type_info &rhs) const;
    bool operator==(const extended_type_info &rhs) const;
    bool operator!=(const extended_type_info &rhs) const {
        return !(operator==(rhs));
    }
    // for plugins
    virtual void * construct(unsigned int count = 0, ...) const;
    virtual void destroy(void const * const p) const;
    static const extended_type_info * find(const char *key);
};

} // namespace serialization 
} // namespace boost

一般而言, 每个类型会创建一个且仅一个 extended_type_info 实例. 不过, 这仅在可执行模块级别上强制. 也就是说, 如果程序包含一些共享库或 DLL, 对应特定类型可能存在多个该类的实例. 因此, 下面的比较函数不能只比较该实例的地址, 而必须编写为比较实例实际包含的信息.


extended_type_info(unsigned int type_info_key, const char *key);

所有派生类都应调用此构造函数. 第一个参数应当是具体实现的编号. 对于这个基于 typeid() 的默认实现, 该值为 1. 每个系统必须有自己的整数. 这个值用于实现不同类型信息系统之间的互操作.

第二个参数是一个 const 字符串, 是本记录对应类型的外部名称. 它有时被称为 GUID—— G lobal U nique ID entifier. 它通过档案从一个程序调用传递到另一个程序调用, 以唯一标识档案包含的类型. 如果不打算使用"导出"设施, 这个值可以是 NULL.


void key_register();
void key_unregister();

该系统维护一个全局表, 把外部字符串关联到 extended_type_info 记录. 加载通过基类指针序列化的对象时会用到这个表. 此时, 档案包含一个字符串, 在该表中查找它, 以确定用哪个 extended_type_info 来创建新对象.

这些函数由实现 extended_type_info 的类的构造函数和析构函数调用, 用于向该表添加和删除条目.


const char *get_key() const;

获取 extended_type_info 实例的键. 如果没有与该实例关联的键, 则返回 NULL.


bool operator<(const extended_type_info & rhs) const;
bool operator==(const extended_type_info & rhs) const;
bool operator!=(const extended_type_info & rhs) const;

这些函数用于比较 extended_type_info 对象. 它们在所有 extended_type_info 记录上强加一个严格全序.


virtual void * construct(unsigned int count = 0, ...) const;

构造本 extended_type_info 记录所对应类型的一个新实例. 该函数接受最多 4 个任意类型的可变参数. 这些参数在运行期被传给该类型的构造函数. 要使用该设施, 必须为构造函数参数声明一个类型序列. 此函数的实参在数量和类型上必须与导出该类型时指定的相匹配. 该函数使得仅凭 BOOST_CLASS_EXPORT 分配的导出 GUID 就能创建任何导出类型的实例. 如果这些类型定义在运行期加载的 DLL 或共享库中, 则在这些模块被卸载之前都可以调用这些构造函数. 这类模块被称为 插件 . 


virtual void destroy(void const * const p) const;

销毁由上述构造函数创建的实例.


static const extended_type_info * find(const char *key);

给定字符串键或 GUID , 返回对应 extended_type_info 对象的地址.

对实现的要求

要被序列化库使用, extended_type_info 的实现 (此处称为 ETI) 必须从 extended_type_info 派生, 并实现以下内容: 

template<class ETI>
const extended_type_info *
ETI::get_derived_extended_type_info(const T & t) const;

返回对应类型 T 的"真实类型"的 extended_type_info 实例指针. "真实类型"是类层次结构中最低的类型. 类型 T 总是可以通过 static cast 转换为"真实类型". 该函数的实现因类型 id 系统而异, 有时会对可以用特定 extended_type_info 实现标识的类型 T 作出假定.

virtual bool ETI::is_less_than(const extended_type_info &rhs) const;

使用同一 extended_type_info 实现将本实例与另一个实例比较.

virtual bool ETI::is_equal(const extended_type_info &rhs) const;

使用同一 extended_type_info 实现将本实例与另一个实例比较. 如果所指类型相同则返回 true, 否则返回 false 

const char ETI::get_key() const;

获取该类的外部键 (即 GUID) .

virtual void * construct(unsigned int count, ...) const;

用所含的实参列表构造对应类型的一个实例.

virtual void * destroy(void const * const ptr ) const;

销毁该类型的一个实例. 它会调用正确的析构函数并回收分配的内存.

模型

序列化库包含两个不同的 extended_type_info 实现.

extended_type_info_typeid

基于标准的 typeid() 实现. 它假定编译器启用了 RTTI 支持.

extended_type_info_no_rtti

以不依赖 RTTI 存在的方式实现. 它改为要求所有多态类型都被显式导出. 此外, 如果要使用导出设施通过基类指针序列化类型, 这些类型必须实现一个具有如下签名的虚函数: 
virtual const char * get_key();
它返回唯一标识此类最派生对象的字符串. 该函数必须是虚函数, 以便实现上文所述 ETI::get_derived_extended_type_info 所要求的功能.

对每个类型的要求

要由系统管理的每个类型都必须单独"注册". 这通过实例化模板来完成. 例如, 如果类型 T 要使用 type_info 系统, 则应包含如下代码: 
namespace boost {
namespace serialization {
template
struct extended_type_info_typeid<T>;
template
struct extended_type_info_typeid<const T>;
} // serialization
} // boost
对于使用序列化库的用户, 这一步可以跳过, 因为它会自动完成. 序列化库包含宏: 
BOOST_CLASS_TYPE_INFO(
    my_type, 
    extended_type_info_typeid<my_class>
)
用于指定对给定类型使用哪个 extended_type_info 系统.

extended_type_info 包含一个在不知道确切类型的情况下构造类型实例的设施. 它通过函数 virtual void * extended_type_info::construct(unsigned int count = 0, ...) const; 完成. 例如: 

struct base {
...
};
struct derived : public base {
...
};
...
extended_type_info *eti = extended_type_info::find("my_class")
base * b = eti->construct(...);

construct 接受一个参数个数和最多四个任意类型的参数. 这些参数被传给"my_class"的构造函数. 完整示例可在 此处 找到
