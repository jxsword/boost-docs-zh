1. RapidXml 是什么?

RapidXml 致力于创建尽可能快的 XML DOM 解析器, 同时保持可用性、可移植性与合理的 W3C 兼容性. 它是一个用 C++ 编写的原位解析器, 解析速度接近对同一数据执行 strlen() 函数的速度.

整个解析器包含在单个头文件中, 因此无需构建或链接. 要使用它, 只需将 rapidxml.hpp 文件复制到方便的位置 (例如你的项目目录) , 并在需要的地方包含它. 你可能还想使用头文件 rapidxml_print.hpp.

1.1 依赖与兼容性

RapidXml 具有 无依赖, 仅依赖标准 C++ 库的一个很小的子集 (<cassert>、<cstdlib>、<new> 和 <exception>, 除非禁用异常) . 它应当能在任何相当符合标准的编译器上编译, 并已在 Visual C++ 2003、Visual C++ 2005、Visual C++ 2008、gcc 3、gcc 4 与 Comeau 4.3.3 上测试. 已注意确保在这些编译器上不产生任何警告, 即使启用了最高警告级别.

1.2 字符类型与编码

RapidXml 与字符类型无关, 既可使用窄字符也可使用宽字符. 当前版本尚未完全支持 UTF-16 或 UTF-32, 因此宽字符的使用有些受限. 不过, 如果数据的字节序与机器一致, 它应能成功解析包含 UTF-16 或 UTF-32 的 wchar_t 字符串. 完全支持 UTF-8, 包括所有数字字符引用, 它们会被展开为相应的 UTF-8 字节序列 (除非启用 parse_no_utf8 标志) .

注意 RapidXml 不做解码——name() 与 value() 函数返回的字符串将包含以与源文件相同编码的文本. Rapidxml 能理解并展开以下字符引用: &apos; &amp; &quot; &lt; &gt; &#...; 其他字符引用不会被展开.

1.3 错误处理

默认情况下, RapidXml 使用 C++ 异常报告错误. 如果这种行为不合需要, 可定义 RAPIDXML_NO_EXCEPTIONS 来禁用异常代码. 更多信息参见 parse_error 类与 parse_error_handler() 函数.

1.4 内存分配

RapidXml 使用特殊的内存池对象来分配节点与属性, 因为直接使用 new 运算符分配会太慢. 池执行的底层内存分配可通过 memory_pool::set_allocator() 函数定制. 更多信息参见类 memory_pool.

1.5 W3C 符合性

RapidXml 不是符合 W3C 的解析器, 主要因为它忽略 DOCTYPE 声明. 还有一些其他小的不兼容之处. 尽管如此, 它仍能成功解析 W3C 符合性套件中的所有有效 XML 文件并生成完整的树 (该套件包含 1000 多个专门为找出 XML 处理器缺陷而设计的文件) . 在破坏模式下, 它对一小组内建实体执行空白规范化与字符实体替换.

1.6 API 设计

RapidXml API 极简, 以尽可能减少代码体积, 便于在嵌入式环境中使用. 额外的便利函数在单独的头文件中提供: rapidxml_utils.hpp 与 rapidxml_print.hpp. 这些头文件的内容不是库的核心部分, 目前也没有文档 (仅有代码中的注释) .

1.7 可靠性

RapidXml 非常健壮, 并带有大量单元测试. 无论输入什么源文本, 都已特别注意确保解析器的稳定性. 其中一个单元测试生成 100,000 个随机损坏的 XML 文档变体 (未损坏时包含 RapidXml 能识别的所有结构) . 当 RapidXml 正确识别出已引入错误且不崩溃或无限循环时, 即通过该测试.

另一个单元测试让 RapidXml 与另一个成熟的 XML 解析器正面对比, 验证它们在各种各样的与大小的文档上输出一致.

还有一个测试用 W3C 符合性套件中的 1000 多个测试文件喂给 RapidXml, 验证获得正确结果. 还有额外的测试分别验证每个 API 函数, 并测试各种解析模式按预期工作.

1.8 致谢

我要感谢 Arseny Kapoulkine 在 pugixml 上的工作, 它为本项目提供了灵感. 另外感谢 Kristen Wegner 创建了 pugxml, pugixml 即衍生自它. Janusz Wohlfeil 慷慨地在我无法访问的硬件上运行了 RapidXml 速度测试, 使我能够扩充性能对比表.

2. 两分钟教程

2.1 解析

以下代码使 RapidXml 解析名为 text 的以零结尾的字符串: 
using namespace rapidxml;
xml_document<> doc;    // character type defaults to char
doc.parse<0>(text);    // 0 means default parse flags
doc 对象现在是 DOM 树的根, 包含解析后的 XML 的表示. 由于所有 RapidXml 接口都包含在命名空间 rapidxml 中, 用户必须将该命名空间的内容引入作用域, 或对所有名称完全限定. 类 xml_document 表示 DOM 层次结构的根. 通过公有继承, 它也是一个 xml_node 和一个 memory_pool. xml_document::parse() 函数的模板参数用于指定解析标志, 可用于微调解析器的行为. 注意标志必须是编译期常量.

2.2 访问 DOM 树

要访问 DOM 树, 使用 xml_node 与 xml_attribute 类的方法: 
cout << "Name of my first node is: " << doc.first_node()->name() << "\n";
xml_node<> *node = doc.first_node("foobar");
cout << "Node foobar has value " << node->value() << "\n";
for (xml_attribute<> *attr = node->first_attribute();
     attr; attr = attr->next_attribute())
{
    cout << "Node foobar has attribute " << attr->name() << " ";
    cout << "with value " << attr->value() << "\n";
}

2.3 修改 DOM 树

解析器生成的 DOM 树完全可修改. 节点与属性可以添加/移除, 其内容可以修改. 下面的示例创建一个 HTML 文档, 其唯一内容是指向 google.com 网站的链接: 
xml_document<> doc;
xml_node<> *node = doc.allocate_node(node_element, "a", "Google");
doc.append_node(node);
xml_attribute<> *attr = doc.allocate_attribute("href", "google.com");
node->append_attribute(attr);
一个特别之处是节点与属性 不拥有 其名称与值的文本. 这是因为它们通常只存储指向源文本的指针. 因此, 为节点赋予新名称或值时, 必须注意确保字符串的适当生命期. 最简单的办法是从 xml_document 内存池分配字符串. 在上面的示例中这不是必需的, 因为我们只赋值字符常量. 但下面的代码使用 memory_pool::allocate_string() 函数分配节点名称 (它与文档具有相同的生命期) , 并将其赋给新节点: 
xml_document<> doc;
char *node_name = doc.allocate_string(name);        // Allocate string and copy name into it
xml_node<> *node = doc.allocate_node(node_element, node_name);  // Set node name to node_name
查看 参考 一节以了解整个接口的描述.

2.4 打印 XML

你可以将 xml_document 与 xml_node 对象打印为 XML 字符串. 使用 print() 函数或 operator <<, 它们定义在头文件 rapidxml_print.hpp 中. 
using namespace rapidxml;
xml_document<> doc;    // character type defaults to char
// ... some code to fill the document

// Print to stream using operator <<
std::cout << doc;   

// Print to stream using print function, specifying printing flags
print(std::cout, doc, 0);   // 0 means default printing flags

// Print to string using output iterator
std::string s;
print(std::back_inserter(s), doc, 0);

// Print to memory buffer using output iterator
char buffer[4096];                      // You are responsible for making the buffer large enough!
char *end = print(buffer, doc, 0);      // end contains pointer to character after last printed character
*end = 0;                               // Add string terminator after XML

3. 与常规 XML 解析器的差异

RapidXml 是一个 原位解析器, 这使它能达到非常高的解析速度. 原位意味着解析器不复制字符串, 而是将指向 源文本 的指针放入 DOM 层次结构.

3.1 源文本的生命期

原位解析要求源文本的生命期至少与文档对象一样长. 如果源文本被销毁, DOM 树中节点的名称与值也将失效. 此外, 空白处理、字符实体转换与字符串零结尾要求在解析期间修改源文本 (但参见非破坏模式) . 这使得文本一旦被 RapidXml 解析后就无法再用于进一步处理.

然而在很多情况下, 这些都不是严重问题.

3.2 字符串的所有权

RapidXml 生成的节点与属性不拥有其名称与值字符串, 它们只保存指向它们的指针. 这意味着手动设置这些值时必须小心, 使用 xml_base::name(const Ch *) 或 xml_base::value(const Ch *) 函数. 必须注意确保传入字符串的生命期至少与节点/属性的生命期一样长. 最简单的办法是从文档拥有的 memory_pool 分配字符串. 为此可使用 memory_pool::allocate_string() 函数.

3.3 破坏模式与非破坏模式

默认情况下, 解析器在解析过程中会修改源文本. 这是实现字符实体转换、空白规范化与字符串零结尾所必需的.

在某些情况下这种行为可能不合需要, 例如源文本位于只读内存中, 或直接从文件映射到内存. 通过使用适当的解析器标志 (parse_non_destructive) , 可以禁用对源文本的修改. 但由于 RapidXml 采用原位解析, 显然有以下副作用:
  • 不进行空白规范化
  • 不进行实体引用转换
  • 名称与值不以零结尾, 必须使用 xml_base::name_size() 和 xml_base::value_size() 函数来告知其结束位置

4. 性能

RapidXml 通过使用几种技术实现其速度:
  • 原位解析. 构建 DOM 树时, RapidXml 不复制字符串数据 (如节点名称与值) , 而是存储指向源文本内部的指针.
  • 使用模板元编程技术. 这使它能把大量工作移到编译期. 借助模板的魔力, C++ 编译器会为你所用的解析器标志的任意组合生成一份单独的解析代码副本. 在每个副本中, 所有可能的决策都在编译期做出, 所有未使用的代码都被省略.
  • 在解析中大量使用查找表.
  • 手工调优的 C++, 并在几种最流行的 CPU 上进行了性能剖析.
这产生非常小且快的代码: 每次调用都会生成完全符合确切需求的定制解析器.

类模板 rapidxml::memory_pool

定义于 rapidxml.hpp
的基类, 用于 xml_document

说明

解析器使用该类创建新节点与属性, 没有动态内存分配的开销. 在大多数情况下, 你不需要直接使用该类. 但是, 如果你需要手动创建节点或修改节点的名称/值, 建议使用相关的 memory_pool (属于相应的 xml_document) 来分配内存. 这不仅比使用 new 运算符分配更快, 而且它们的生命期将与文档的生命期绑定, 可能简化内存管理.

调用 allocate_node() 或 allocate_attribute() 函数从池中获取新节点或属性. 也可以调用 allocate_string() 函数分配字符串. 这样的字符串随后可用作节点的名称或值, 而无需担心其生命期. 注意没有 free() 函数——当调用 clear() 函数或销毁池时, 所有分配会一次性释放.

也可以创建独立的 memory_pool, 并用它分配生命期不与任何文档绑定的节点.

池维护 RAPIDXML_STATIC_POOL_SIZE 字节的静态分配内存. 在静态内存耗尽之前, 不会进行动态内存分配. 静态内存耗尽时, 池会通过全局 RAPIDXML_DYNAMIC_POOL_SIZE 与 new[] 运算符分配 delete[] 大小的附加内存块. 可通过设置自定义分配例程改变此行为. 使用 函数设置.

节点、属性与字符串的分配按 RAPIDXML_ALIGNMENT 字节对齐. 该值默认为目标架构上指针的大小.

要从解析器获得绝对最佳性能, 所有节点都从单个连续内存块分配非常重要. 否则, 在两个 (或更多) 不相交内存块之间跳转时的缓存未命中会大大减慢解析. 如有需要, 你可以调整 RAPIDXML_STATIC_POOL_SIZE、RAPIDXML_DYNAMIC_POOL_SIZE 与 RAPIDXML_ALIGNMENT 以获得浪费内存与性能之间的最佳折中. 为此, 在包含 rapidxml.hpp 文件之前定义它们的值.

参数

Ch
所创建节点的字符类型.

构造函数 memory_pool::memory_pool

概要

memory_pool();

说明

用默认分配函数构造空池.

析构函数 memory_pool::~memory_pool

概要

~memory_pool();

说明

销毁池并释放所有内存. 这会导致池分配的节点所占用的内存被释放. 从池分配的节点不再有效.

函数 memory_pool::allocate_node

概要

xml_node<Ch>* allocate_node(node_type type, const Ch *name=0, const Ch *value=0, std::size_t name_size=0, std::size_t value_size=0);

说明

从池中分配新节点, 并可选地为其指定名称与值. 如果无法满足分配请求, 该函数将抛出 std::bad_alloc. 如果通过定义 RAPIDXML_NO_EXCEPTIONS 禁用了异常, 该函数将调用 rapidxml::parse_error_handler() 函数.

参数

类型
要创建的节点的类型.

常量 parse_no_data_nodes

概要

const int parse_no_data_nodes = 0x1;

说明

解析标志, 指示解析器不创建数据节点. 除非同时指定 rapidxml::parse_no_element_values 标志, 第一个数据节点的文本仍会放入父元素的值中. 可通过 | 运算符与其他标志组合.

参见 xml_document::parse() 函数.

常量 parse_no_element_values

概要

const int parse_no_element_values = 0x2;

说明

解析标志, 指示解析器不将第一个数据节点的文本用作父元素的值. 可通过 | 运算符与其他标志组合. 注意打印时, 元素节点的子数据节点优先于其值. 也就是说, 如果元素有一个或多个子数据节点 且 有值, 值将被忽略. 如果想通过元素的值操作数据, 使用 rapidxml::parse_no_data_nodes 标志阻止创建数据节点.

参见 xml_document::parse() 函数.

常量 parse_default

概要

const int parse_default = 0;

说明

表示解析器默认行为的解析标志集. 它始终等于 0, 因此所有其他标志可以简单地进行或运算. 通常无需通过与它们的否定 (~) 值做与运算来麻烦地禁用标志. 这也意味着每个标志的含义是对默认设置的 否定. 例如, 若标志名为 rapidxml::parse_no_utf8, 则表示默认 启用 utf-8, 使用该标志将禁用它.

参见 xml_document::parse() 函数.

常量 parse_non_destructive

概要

const int parse_non_destructive = parse_no_string_terminators | parse_no_entity_translation;

说明

禁止对源文本做任何修改的解析标志组合. 这也使解析更快. 但注意会发生以下情况:
  • 节点的名称与值不会以零结尾, 必须使用 xml_base::name_size() 与 xml_base::value_size() 函数来确定名称与值的结束位置
  • 实体不会被转换
  • 空白不会被规范化
参见 xml_document::parse() 函数.

常量 parse_fastest

概要

const int parse_fastest = parse_non_destructive | parse_no_data_nodes;

说明

在不牺牲重要数据的前提下实现最快解析的解析标志组合.

参见 xml_document::parse() 函数.

概要
