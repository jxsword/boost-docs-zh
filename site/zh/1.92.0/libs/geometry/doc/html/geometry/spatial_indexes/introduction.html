引言

Boost.Geometry.Index 旨在汇集称为空间索引的数据结构, 这些结构可用于加速空间中对象的搜索. 一般而言, 空间索引存储几何对象的表示, 并允许搜索占据某空间或靠近空间中某点的对象.

目前只实现了一个空间索引——R-tree.

R-tree

R-tree 是一种用于空间搜索的树形数据结构. 它由 Antonin Guttman 于 1984 年 [1] 提出作为 B-tree 面向多维数据的扩展. 它可用于存储点或体积数据以执行空间查询. 例如, 该查询可以返回位于某个区域内或靠近空间中某个点的对象 [2]. 可以插入新对象或移除已存储的对象.

R-tree 的结构如下图所示. R-tree 的每个节点存储一个描述其子节点所占据空间的 box. 在结构的底部, 是包含值 (几何对象表示) 的叶节点.

R-tree 是一种自平衡数据结构. 平衡算法的关键部分是节点分裂算法 [3] [4]. 每种算法产生不同的分裂, 因此树的内部结构可能各不相同. 一般来说, 越复杂的算法对元素的分析越好, 产生的节点重叠越少. 在搜索过程中, 为找到目标对象需要遍历的节点更少. 另一方面, 更复杂的分析需要更多时间. 一般来说, 插入越快, 搜索越慢, 反之亦然. R-tree 的性能取决于平衡算法、参数以及插入到容器中的数据.

此外, 还有一些算法可以创建包含一定数量对象的 R-tree. 这种技术称为批量装载, 通过使用打包算法 [5] [6] 完成. 这种方法更快, 并且产生的 R-tree 内部结构更好. 这意味着查询性能得到提升.

实现细节

该 R-tree 实现的主要特性有:

  • 能够存储任意 Value 类型,
  • 三种不同的平衡算法——linear、quadratic 或 rstar,
  • 使用打包算法创建,
  • 参数 (包括元素的最大与最小数量) 可作为编译期或运行期参数传入; 编译期版本中, 节点元素存储在静态大小的容器中,
  • 高级查询, 例如搜索距某个点最近的 5 个 Value, 且与某个 Geometry 相交但不在另一个之内,
  • 通过迭代器进行迭代式查询,
  • 符合 C++11——移动语义、有状态分配器,
  • 能够存储没有默认构造函数的 Value 类型,
  • 使用默认 std::allocator<> 进行内存内存储,
  • 其他存储选项——使用 Boost.Interprocess 分配器的共享内存与映射文件.
Dependencies

R-tree 依赖 Boost.Container、Boost.Core、Boost.Move、Boost.MPL、Boost.Range、Boost.Tuple.
