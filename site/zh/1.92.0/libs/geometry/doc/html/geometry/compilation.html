编译

注意

Boost 1.73 中的 Boost.Geometry 已弃用对 C++03 的支持, 并将从 Boost 1.75 起要求 C++14

Boost.Geometry 是一个仅头文件库. 用户只需在程序中包含该库的头文件, 即可使用 Boost.Geometry 库提供的定义与算法, 无需链接任何二进制文件.

Boost.Geometry 仅依赖其他仅头文件的 Boost 库, 不会对任何二进制库引入间接依赖.

为了使用 Boost.Geometry, 用户唯一需要做的就是下载并/或安装 Boost, 并指定包含目录的位置, 这样本方案的 include 指令即可正常工作:

#include <boost/...>

支持的编译器

Boost.Geometry 库源代码应当能够在任何完整支持 C++14 的编译器上成功编译.

有关当前已测试编译器的实际列表, 请查看从 README.md 链接的库 CI 构建结果, 或查看库仓库 develop 分支 中的 CI 服务配置文件.

Boost.Geometry 使用 Boost.Build (一种基于文本的软件开发与测试系统) 来配置、构建并执行单元测试与示例程序. 构建配置以一组 Jamfile 文件的形式提供.

对于 gcc, 可以使用标志 -Wno-long-long 来抑制部分源自 Boost 的警告.

包含

包含全部算法与策略的最方便的头文件是 geometry.hpp:

#include <boost/geometry.hpp>

这是 Boost.Geometry 库的主头文件, 建议包含该文件.

也可以单独包含 Boost.Geometry 的各个头文件. 但这可能不太方便, 因为头文件将来可能会不时被重命名或移动.

另一个常用头文件是 geometries.hpp:

#include <boost/geometry/geometries/geometries.hpp>

其中包含库所提供的全部几何类型的定义:

  • point,
  • linestring,
  • polygon,
  • ring,
  • multi_point,
  • multi_linestring,
  • multi_polygon,
  • box,
  • segment.

文件 geometries.hpp 未包含在 geometry.hpp 头文件中, 因为应当让用户可以自由使用自己的几何类型而不限于内置几何类型. 不过, 对想要使用内置几何类型的 Boost.Geometry 用户来说, 包含该文件很有用.

高级包含

拥有自己的几何类型并想使用 Boost.Geometry 算法的用户, 可以包含含有注册宏的头文件, 例如:

#include <boost/geometry/geometries/register/point.hpp>

性能

下面的列举并不详尽, 但包含一些提升性能的提示:

  • 对于 Microsoft MSVC, 请为预处理器设置宏定义 _SECURE_SCL=0.
  • 对于 Microsoft MSVC, 请为预处理器设置宏定义 _HAS_ITERATOR_DEBUGGING=0.
  • 使用 STLport (一个流行的开源 STL 实现) 可能会得到比使用 MSVC 自带 C++ 标准库快得多的代码.
  • 打开编译器优化, 以 release 模式编译.

IntelliSense 的问题

MSVC 2005 和 2008 两个版本 (包括 Express 版) 在输入括号或尖括号时, 都可能在尝试解析符号并给出 IntelliSense 建议时挂起. 这与 Boost.Geometry 没有直接关系, 而是由于该 IDE 在处理 Boost 和 Boost.Geometry 这类大量使用模板的大型 C++ 代码库时存在问题. 如果这造成不便, 可以关闭 IntelliSense:

“(...) 在 VC++ 中禁用 IntelliSense. 有一个名为 feacp.dll 的文件位于 <VS8INSTALL>/VC/vcpackages 文件夹中. 重命名该文件即可禁用 IntelliSense 功能.”

-- Visual C++ 2005 中的 IntelliSense 问题
