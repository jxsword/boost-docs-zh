示例: 适配旧几何对象模型

Boost.Geometry 的主要优势之一, 也是其采用相当复杂的基于模板的实现的原因, 在于它允许与旧类/旧对象集成.

通过定义 Boost.Geometry 概念与现有旧对象模型之间的关系, 可以用旧对象代替 Boost.Geometry 自身的几何类.

之后 Boost.Geometry 便可以直接对旧对象进行读写, 将其视为原生 Boost.Geometry 对象.

这意味着可以以极小的运行期开销把 Boost.Geometry 的算法和方法适配到任何现有的旧几何对象模型, 这对大多数几何库来说根本不可能: 使用它们时必须为所用几何库专门构造一个中间对象.

下面的示例将演示如何适配旧几何对象模型以便与 Boost.Geometry 配合使用.

适配共享几何旧对象模型

示例代码: 对象层次结构 

class QPoint
{
    public:
        double x;
        double y;
        QPoint(double x, double y) : x(x), y(y) {}
};

class QLineString
{
    public:
        bool cw;
        std::vector<QPoint*> points;
};

class QRing
{
    public:
        std::vector<QLineString*> lines;
};

class QPolygon
{
    public:
        QRing* exterior;
        std::vector<QRing*> interiors;
};

旧对象层次结构基于拓扑 (例如两个 QRing 可能共享一个 QLineString) 而非直接基于点 (即每个对象并不直接指向其 QPoint), 并且它还使用指针进行访问.

这是处理几何的另一常见方式, 例如可使面之间共享边界. Boost.Geometry 的方法使用简单要素, 不支持共享几何.

表示方式上的不匹配可以通过创建自定义迭代器来解决, 该迭代器为每个对象暴露一个由 Point 组成的 Boost.Range. 这样, Boost.Geometry 的函数就会把 QRing 当作 Point 集合来操作, 而这正是概念的要求.

适配 QPoint

QPoint 的适配 相当直接, 只需实现各项要求即可.

尽管旧对象模型中的几何使用 QPoint 指针, Boost.Geometry 会在内部自动处理从 Point 指针到 Point 引用的转换, 因此我们不必手动转换.

或者, 我们可以使用辅助宏 BOOST_GEOMETRY_REGISTER_POINT_2D(QPoint, double, cs::cartesian, x, y), 其效果与手动适配完全相同.

示例代码使用 traits 类的特化将 QPoint 适配到 Point 概念.

适配 QLineString

QLineString 的适配 表面上非常简单, 只是 "将 linestring_tag 定义为类型的 traits::tag 特化". 或者, 我们可以使用辅助宏 BOOST_GEOMETRY_REGISTER_LINESTRING(QLineString), 其效果与手动适配完全相同.

然而, LineString 概念 还要求 Point 集合 "必须表现得像 Boost.Range 随机访问范围", 并且 "由元函数 range_value<...>::type 定义的类型必须满足 Point 概念".

这意味着我们必须做两件事:

  • 让 QLineString 表现得像一个 Boost.Range, 满足随机访问要求
  • 确保该 Boost.Range 遍历的是 QPoint, 而我们已完成对 QPoint 的适配

这看起来工作量不小, 但我们很幸运: std::vector 几乎就是一个 Boost.Range, 且已经遍历 QPoint 指针, 而 Boost.Geometry 会处理这些指针. 因此, 让 QLineString 成为 Boost.Range 的代码 相当简单直接.

适配 QRing

QRing 的适配 与 QLineString 大体相同: 同样有一个 tag 和一个待遍历的集合. 或者, 我们可以使用辅助宏 BOOST_GEOMETRY_REGISTER_RING(QRing), 其效果与手动适配完全相同.

然而, QRing 暴露的是指向 QLineString 的指针, 而非直接暴露 QPoint, 这正是 Ring 概念所要求的, 因此简单地把 std::vector 变成 Boost.Range 是不够的. 我们需要创建一个暴露 QPoint 的 Boost.Iterator; 并且由于面对的是旧对象模型, 我们不能修改类定义.

实现这一点的 自定义迭代器 使用了 Boost.Iterator Facade, 与 Boost.Iterator 自身文档中提供的示例 (链接) 相差不大, 只是我们需要的 Boost.Range 必须支持随机访问.

现在, 自定义迭代器已完成, 我们可以 定义 Boost.Range 来遍历 QPoint 了.

适配 QPolygon

将 QPolygon 适配到 Polygon 概念 比其他几何类型要复杂一些.

唯一不易直接适配的要求是 interior_rings 的 get 方法.

Boost.Geometry 的 Polygon 操作的是 Ring 对象, 而遗憾的是, Boost.Geometry 不会在内部自动处理 Ring 的指针到引用转换 (如前所述, 仅对 Point 如此).
