C++11 改变了游戏规则

随着 Boost.MPL 被广泛接受, C++ 元编程看似已成定局. MPL 也许并不理想, 但它已经足够好, 好到实在没有必要去寻找或创造替代品.

C++11 改变了游戏规则. 变参模板及其伴随的参数包把编译期类型列表结构直接加入了语言. 从前每个元编程库都要定义自己的类型列表, MPL 甚至定义了好几个; 而在 C++11 中, 类型列表简单到只需要

// C++11
template<class... T> struct type_list {};

而且几乎没有理由使用其他任何东西.

模板别名是另一个改变格局的特性. 从前, “元函数”——即接受一个类型并产出另一个类型的模板——看起来像

// C++03
template<class T> struct add_pointer { typedef T* type; };

并且按如下方式使用:

// C++03
typedef typename add_pointer<X>::type Xp;

在 C++11 中, 元函数可以是模板别名, 而不必是类模板:

// C++11
template<class T> using add_pointer = T*;

上面例子中的用法于是变成

// C++11
typedef add_pointer<X> Xp;

或者, 如果你希望显得精通 C++11, 则是

// C++11
using Xp = add_pointer<X>;

在更复杂的表达式中, 这是一个相当可观的改进:

// C++03
typedef
    typename add_reference<
        typename add_const<
            typename add_pointer<X>::type
        >::type
    >::type Xpcr;
// C++11
using Xpcr = add_reference<add_const<add_pointer<X>>>;

(这个例子还利用了 C++11 的另一个特性——现在可以用 >> 来闭合模板, 而不会被解释为右移.)

此外, 模板别名可以传给模板模板参数:

// C++11
template<template<class... T> class F> struct X
{
};

X<add_pointer>; // works!

这些语言改进使得 C++11 元编程与其惯用的 C++03 等价物大不相同. Boost.MPL 已不再够用, 是时候做点什么了. 但做什么呢?

类型列表与 mp_rename

让我们从基础开始. 我们的基本数据结构将是类型列表:

template<class... T> struct mp_list {};

为什么用 mp_ 前缀? mp 显然代表元编程 (metaprogramming), 但我们难道不能用命名空间吗?

确实可以. 然而, 过去使用 Boost.MPL 的经验表明, 我们的元编程原语与标准标识符 (例如 list) 以及关键字 (例如 if、int 或 true) 之间的名字冲突将会很常见, 并会成为问题的根源. 加上前缀, 我们就能避开所有这些麻烦.

于是我们有了类型列表, 并且可以往里放东西:

using list = mp_list<int, char, float, double, void>;

但目前还不能对它做其他任何事情. 我们需要一个对这些 mp_list 进行操作的原语库. 不过在深入之前, 先考虑另一个有趣的问题.

假设我们有了能对 mp_list 做各种操作的原语库, 但其他代码交给我们的类型列表并不是 mp_list, 例如一个 std::tuple<int, float, void*>, 或者 std::packer<int, float, void*>.

假设我们需要以某种方式修改这个外来的类型列表 (比如把类型变成指针), 并以收到时的形式归还变换结果, 第一种情形是 std::tuple<int*, float*, void**>, 第二种是 std::packer<int*, float*, void**>.

要做到这一点, 我们需要先把 std::tuple<int, float, void*> 转换为 mp_list<int, float, void*>, 对每个元素应用 add_pointer 得到 mp_list<int*, float*, void**>, 然后再转换回 std::tuple.

这类转换步骤相当常见, 我们将编写一个帮助我们完成它们的原语, 称为 mp_rename. 我们想要

mp_rename<std::tuple<int, float, void*>, mp_list>

给我们

mp_list<int, float, void*>

反过来,

mp_rename<mp_list<int, float, void*>, std::tuple>

给我们

std::tuple<int, float, void*>

下面是 mp_rename 的实现:

template<class A, template<class...> class B> struct mp_rename_impl;

template<template<class...> class A, class... T, template<class...> class B>
    struct mp_rename_impl<A<T...>, B>
{
    using type = B<T...>;
};

template<class A, template<class...> class B>
    using mp_rename = typename mp_rename_impl<A, B>::type;

(这种由模板别名转发到实际工作的类模板的模式很常见; 类模板可以被特化, 而模板别名不能.)

注意 mp_rename 不把任何列表类型当作特殊, 甚至 mp_list 也不例外; 它可以把任意变参类模板重命名为任何其他模板. 你可以用它把 std::packer 重命名为 std::tuple 再重命名为 std::variant (一旦有这样东西的话), 它都会乐意照办.

事实上, 它甚至可以重命名非变参类模板, 如下例所示:

mp_rename<std::pair<int, float>, std::tuple>        // -> std::tuple<int, float>
mp_rename<mp_list<int, float>, std::pair>           // -> std::pair<int, float>
mp_rename<std::shared_ptr<int>, std::unique_ptr>    // -> std::unique_ptr<int>

魔法是有限度的; unique_ptr 不能被重命名为 shared_ptr:

mp_rename<std::unique_ptr<int>, std::shared_ptr>    // error

因为 unique_ptr<int> 实际上是 unique_ptr<int, std::default_delete<int>>, 而 mp_rename 把它重命名为 shared_ptr<int, std::default_delete<int>>, 这无法编译. 但它在比我们最初天真预期的多得多的情形下仍然有效.

转换不再成问题之后, 让我们继续讨论原语, 并出于练习定义一个简单的原语 mp_size. 我们希望 mp_size<mp_list<T...>> 给出列表中元素的数量, 也就是表达式 sizeof...(T) 的值.

template<class L> struct mp_size_impl;

template<class... T> struct mp_size_impl<mp_list<T...>>
{
    using type = std::integral_constant<std::size_t, sizeof...(T)>;
};

template<class L> using mp_size = typename mp_size_impl<L>::type;

这相对直接, 除了那个 std::integral_constant. 它是什么, 为什么需要它?

std::integral_constant 是一个标准的 C++11 类型, 它把整型常量 (即编译期常量整数值) 包装成一个类型.

由于元编程操作的是只能容纳类型的类型列表, 把编译期常量表示为类型会很方便. 这使我们可以统一地处理类型列表和值列表. 因此, 在元编程中, 惯例是接受和返回类型而不是值, 我们也正是这样做的. 如果在之后的某个时刻我们想要实际的值, 可以用表达式 mp_size<L>::value 来获取它.

我们现在有了 mp_size, 但你可能已经注意到 mp_size 与 mp_rename 之间有一个有趣的差异. 我特意让 mp_rename 不把 mp_list 当作特例, 而 mp_size 却明确这样做:

template<class... T> struct mp_size_impl<mp_list<T...>>

这真的有必要吗? 难道我们不能在 mp_size 的实现中使用与 mp_rename 中相同的技术吗?

template<class L> struct mp_size_impl;

template<template<class...> class L, class... T> struct mp_size_impl<L<T...>>
{
    using type = std::integral_constant<std::size_t, sizeof...(T)>;
};

template<class L> using mp_size = typename mp_size_impl<L>::type;

完全可以, 这一改进使我们能把 mp_size 用于任何其他类型列表, 例如 std::tuple. 它把 mp_size 变成了真正通用的原语.

这很好. 好到我要主张我们所有的元编程原语都应当具有这一性质. 如果有人以 std::tuple 的形式交给我们一个类型列表, 我们应当能够直接对其操作, 避免与 mp_list 之间的来回转换.

那么我们是否不再需要 mp_rename 了? 不完全. 除了有时我们确实需要重命名类型列表之外, mp_rename 还有一个令人意外的用途.

为了说明它, 让我引入原语 mp_length. 它与 mp_size 类似, 但 mp_size 接受一个类型列表作为实参, 而 mp_length 接受一个变参数包并返回其长度; 或者换句话说, 它返回其实参个数:

template<class... T> using mp_length =
    std::integral_constant<std::size_t, sizeof...(T)>;

我们要如何基于 mp_size 来实现 mp_length? 一种选择是把后者的实现直接代入前者:

template<template<class...> class L, class... T> struct mp_size_impl<L<T...>>
{
    using type = mp_length<T...>;
};

但还有另一种方式, 远没有那么平淡无奇. 想想 mp_size 做了什么. 它接受实参

mp_list<int, void, float>

并返回

mp_length<int, void, float>

我们是否已经有一个做类似事情的原语?

(没什么可选的, 不是吗?)

确实有, 它叫 mp_rename.

template<class L> using mp_size = mp_rename<L, mp_length>;

我不知道你怎么想, 但我觉得这个技法令人着迷. 它利用了列表 L<T...> 与元函数“调用” F<T...> 之间的结构相似性, 以及语言以相同方式看待两者并允许我们把模板别名 mp_length 传给 mp_rename 的事实 (仿佛它就是像 mp_list 那样的普通类模板).

(其他元编程库为这项工作提供了一个专用的 apply 原语. apply<F, L> 以列表 F 的内容调用元函数 L. 为了可读性, 我们将添加一个调用 mp_apply<F, L> 的别名 mp_rename<L, F>.)

template<template<class...> class F, class L> using mp_apply = mp_rename<L, F>;

mp_transform

让我们重温我之前给出的例子——有人交给我们 std::tuple<X, Y, Z>, 我们需要计算 std::tuple<X*, Y*, Z*>. 我们已经有了 add_pointer:

template<class T> using add_pointer = T*;

所以我们只需把它应用到输入元组的每个元素上.

接受一个函数和一个列表并把函数应用到每个元素的算法, 在 Boost.MPL 和 STL 中称为 transform, 在函数式语言中称为 map. 我们将使用 transform, 以与既有的 C++ 惯例保持一致 (map 在 STL 和 Boost.MPL 中都是一种数据结构.)

我们把算法称为 mp_transform, 而它 mp_transform<F, L> 会把 F 应用到 L 的每个元素并返回结果. 通常实参顺序相反, 函数放在最后. 我们把它放在最前面的理由稍后就会显现.

实现 mp_transform 的方式有很多; 我们将选择的那种会用到另一个原语 mp_push_front. mp_push_front<L, T> 顾名思义, 会把 T 添加为 L 的第一个元素:

template<class L, class T> struct mp_push_front_impl;

template<template<class...> class L, class... U, class T>
    struct mp_push_front_impl<L<U...>, T>
{
    using type = L<T, U...>;
};

template<class L, class T>
    using mp_push_front = typename mp_push_front_impl<L, T>::type;

不过没有理由把 mp_push_front 限制为单个元素. 在 C++11 中, 变参模板应当是我们的默认选择, 而能接受任意数量元素的 mp_push_front 的实现几乎完全相同:

template<class L, class... T> struct mp_push_front_impl;

template<template<class...> class L, class... U, class... T>
    struct mp_push_front_impl<L<U...>, T...>
{
    using type = L<T..., U...>;
};

template<class L, class... T>
    using mp_push_front = typename mp_push_front_impl<L, T...>::type;

接下来是 mp_transform:

template<template<class...> class F, class L> struct mp_transform_impl;

template<template<class...> class F, class L>
    using mp_transform = typename mp_transform_impl<F, L>::type;

template<template<class...> class F, template<class...> class L>
    struct mp_transform_impl<F, L<>>
{
    using type = L<>;
};

template<template<class...> class F, template<class...> class L, class T1, class... T>
    struct mp_transform_impl<F, L<T1, T...>>
{
    using _first = F<T1>;
    using _rest = mp_transform<F, L<T...>>;

    using type = mp_push_front<_rest, _first>;
};

这是一个直白的递归实现, 对有函数式编程背景的人来说应该很熟悉.

我们能做得更好吗? 事实证明, 在 C++11 中可以.

template<template<class...> class F, class L> struct mp_transform_impl;

template<template<class...> class F, class L>
    using mp_transform = typename mp_transform_impl<F, L>::type;

template<template<class...> class F, template<class...> class L, class... T>
    struct mp_transform_impl<F, L<T...>>
{
    using type = L<F<T>...>;
};

这里我们利用了包展开内置于语言这一事实, 所以 F<T>... 部分替我们完成了全部迭代工作.

现在我们可以解决最初的挑战: 给定一个由类型构成的 std::tuple, 返回一个由指向这些类型的指针构成的 std::tuple:

using input = std::tuple<int, void, float>;
using expected = std::tuple<int*, void*, float*>;

using result = mp_transform<add_pointer, input>;

static_assert( std::is_same<result, expected>::value, "" );

mp_transform, 第二部分

如果我们有一对元组作为输入, 需要产生对应的由 pair 构成的元组呢? 例如, 给定

using input = std::pair<std::tuple<X1, X2, X3>, std::tuple<Y1, Y2, Y3>>;

我们需要产生

using expected = std::tuple<std::pair<X1, Y1>, std::pair<X2, Y2>, std::pair<X3, Y3>>;

我们需要取用由元组表示的两个输入列表, 并用 std::pair 成对地组合它们. 如果把 std::pair 看作函数 F, 这个任务看起来非常类似于 mp_transform, 只不过我们需要使用二元函数和两个列表.

把一元变换算法改成二元的并不难:

template<template<class...> class F, class L1, class L2>
    struct mp_transform2_impl;

template<template<class...> class F, class L1, class L2>
    using mp_transform2 = typename mp_transform2_impl<F, L1, L2>::type;

template<template<class...> class F,
    template<class...> class L1, class... T1,
    template<class...> class L2, class... T2>
    struct mp_transform2_impl<F, L1<T1...>, L2<T2...>>
{
    static_assert( sizeof...(T1) == sizeof...(T2),
        "The arguments of mp_transform2 should be of the same size" );

    using type = L1<F<T1,T2>...>;
};

现在我们可以做

using input = std::pair<std::tuple<X1, X2, X3>, std::tuple<Y1, Y2, Y3>>;
using expected = std::tuple<std::pair<X1, Y1>, std::pair<X2, Y2>, std::pair<X3, Y3>>;

using result = mp_transform2<std::pair, input::first_type, input::second_type>;

static_assert( std::is_same<result, expected>::value, "" );

再次利用元函数与普通类模板 (例如 std::pair) 之间的相似性, 不过这次是反方向; 我们在 std::pair 期望元函数的位置传入 mp_transform2.

但是, 我们真的必须为每个元数使用单独的变换算法吗? 如果我们需要一个接受三元函数和三个列表的变换算法, 难道要把它命名为 mp_transform3? 不, 这正是我们把函数放在最前面的原因. 我们只需把 mp_transform 改成变参的:

template<template<class...> class F, class... L> struct mp_transform_impl;

template<template<class...> class F, class... L>
    using mp_transform = typename mp_transform_impl<F, L...>::type;

然后添加一元和二元特化:

template<template<class...> class F, template<class...> class L, class... T>
    struct mp_transform_impl<F, L<T...>>
{
    using type = L<F<T>...>;
};

template<template<class...> class F,
    template<class...> class L1, class... T1,
    template<class...> class L2, class... T2>
    struct mp_transform_impl<F, L1<T1...>, L2<T2...>>
{
    static_assert( sizeof...(T1) == sizeof...(T2),
        "The arguments of mp_transform should be of the same size" );

    using type = L1<F<T1,T2>...>;
};

我们还可以添加三元及更多元的特化.

有可能实现真正变参的 mp_transform (可以处理任意数量列表的那个) 吗? 原则上可以, 为完整起见, 这里给出一个可能的简略实现:

template<template<class...> class F, class E, class... L>
    struct mp_transform_impl;

template<template<class...> class F, class... L>
    using mp_transform = typename mp_transform_impl<F, mp_empty<L...>, L...>::type;

template<template<class...> class F, class L1, class... L>
    struct mp_transform_impl<F, mp_true, L1, L...>
{
    using type = mp_clear<L1>;
};

template<template<class...> class F, class... L>
    struct mp_transform_impl<F, mp_false, L...>
{
    using _first = F< typename mp_front_impl<L>::type... >;
    using _rest = mp_transform< F, typename mp_pop_front_impl<L>::type... >;

    using type = mp_push_front<_rest, _first>;
};

但会省略它所使用的原语. 这些原语是

  • mp_true —— std::integral_constant<bool, true> 的别名.

  • mp_false —— std::integral_constant<bool, false> 的别名.

  • mp_empty<L...> —— 若所有列表都为空, 返回 mp_true, 否则返回 mp_false.

  • mp_clear<L> —— 返回与 L 同类型的空列表.

  • mp_front<L> —— 返回 L 的第一个元素.

  • mp_pop_front<L> —— 返回去掉第一个元素的 L.

递归式 mp_transform 实现与基于语言特性的实现之间有一个有趣的差异. mp_transform<add_pointer, std::pair<int, float>> 在 F<T>... 实现下可以工作, 在递归实现下会失败, 因为 std::pair 不是真正的类型列表, 只能恰好容纳两个类型.

大名鼎鼎的 tuple_cat 挑战

Eric Niebler 在其《Tiny Metaprogramming Library》一文中给出了函数 std::tuple_cat, 作为一种元编程挑战. tuple_cat 是一个变参模板函数, 接受若干元组并把它们拼接成另一个 std::tuple. 下面是 Eric 的解法:

namespace detail
{
    template<typename Ret, typename...Is, typename ...Ks,
        typename Tuples>
    Ret tuple_cat_(typelist<Is...>, typelist<Ks...>,
        Tuples tpls)
    {
        return Ret{std::get<Ks::value>(
            std::get<Is::value>(tpls))...};
    }
}

template<typename...Tuples,
    typename Res =
        typelist_apply_t<
            meta_quote<std::tuple>,
            typelist_cat_t<typelist<as_typelist_t<Tuples>...> > > >
Res tuple_cat(Tuples &&... tpls)
{
    static constexpr std::size_t N = sizeof...(Tuples);
    // E.g. [0,0,0,2,2,2,3,3]
    using inner =
        typelist_cat_t<
            typelist_transform_t<
                typelist<as_typelist_t<Tuples>...>,
                typelist_transform_t<
                    as_typelist_t<make_index_sequence<N> >,
                    meta_quote<meta_always> >,
                meta_quote<typelist_transform_t> > >;
    // E.g. [0,1,2,0,1,2,0,1]
    using outer =
        typelist_cat_t<
            typelist_transform_t<
                typelist<as_typelist_t<Tuples>...>,
                meta_compose<
                    meta_quote<as_typelist_t>,
                    meta_quote_i<std::size_t, make_index_sequence>,
                    meta_quote<typelist_size_t> > > >;
    return detail::tuple_cat_<Res>(
        inner{},
        outer{},
        std::forward_as_tuple(std::forward<Tuples>(tpls)...));
}

好吧, 挑战接受. 看看我们能做什么.

正如 Eric 所解释的, 这个实现依赖一个巧妙的技巧: 把输入元组打包进一个元组, 创建两个索引数组 inner 和 outer, 然后用外层索引索引外层元组, 用内层索引索引结果 (它是我们的某个输入元组).

例如, 如果 tuple_cat 这样被调用:

std::tuple<int, short, long> t1;
std::tuple<> t2;
std::tuple<float, double, long double> t3;
std::tuple<void*, char*> t4;

auto res = tuple_cat(t1, t2, t3, t4);

我们会创建元组

std::tuple<std::tuple<int, short, long>, std::tuple<>,
    std::tuple<float, double, long double>, std::tuple<void*, char*>> t{t1, t2, t3, t4};

然后通过以下方式提取 t 的元素:

std::get<0>(std::get<0>(t)), // t1[0]
std::get<1>(std::get<0>(t)), // t1[1]
std::get<2>(std::get<0>(t)), // t1[2]
std::get<0>(std::get<2>(t)), // t3[0]
std::get<1>(std::get<2>(t)), // t3[1]
std::get<2>(std::get<2>(t)), // t3[2]
std::get<0>(std::get<3>(t)), // t4[0]
std::get<1>(std::get<3>(t)), // t4[1]

(t2 为空, 所以我们不从它取任何东西.)

第一列整数是 outer 数组, 第二列是 inner 数组, 这正是我们需要计算的. 但首先, 让我们处理 tuple_cat 的返回类型.

tuple_cat 的返回类型只是各实参视为类型列表后的拼接. 拼接列表的元编程算法称为 meta::concat (在 Eric Niebler 的 Meta 库中), 但我把它称为 mp_append, 沿用其经典的 Lisp 名称.

(Lisp 是今天的拉丁语. 受过教育的人理应学过然后忘掉它.)

template<class... L> struct mp_append_impl;

template<class... L> using mp_append = typename mp_append_impl<L...>::type;

template<> struct mp_append_impl<>
{
    using type = mp_list<>;
};

template<template<class...> class L, class... T> struct mp_append_impl<L<T...>>
{
    using type = L<T...>;
};

template<template<class...> class L1, class... T1,
    template<class...> class L2, class... T2, class... Lr>
    struct mp_append_impl<L1<T1...>, L2<T2...>, Lr...>
{
    using type = mp_append<L1<T1..., T2...>, Lr...>;
};

这相当容易. 实现 mp_append 还有其他方式, 但这一种展示了语言如何通过包展开替我们完成大部分工作. 这是 C++11 中的常见主题.

注意 mp_append 返回与其第一个实参相同的列表类型. 当然, 在没有给定实参的情形下, 没有第一个实参可供取类型, 所以我任意选择返回空的 mp_list.

现在 tuple_cat 的声明已经就绪:

template<class... Tp,
    class R = mp_append<typename std::remove_reference<Tp>::type...>>
    R tuple_cat( Tp &&... tp );

我们需要 remove_reference 的原因在于右值引用参数, 它们用于实现完美转发. 如果实参是左值, 例如上面的 t1, 其对应类型将是元组的引用——即 std::tuple<int, short, long>& (在 t1 的情形下). 我们的各原语不把元组的引用识别为类型列表, 所以需要把它们剥掉.

不过, 我们的返回类型计算有两个问题. 其一, 如果 tuple_cat 在没有任何实参的情况下被调用怎么办? 我们在那种情况下返回 mp_list<>, 但正确的结果是 std::tuple<>.

其二, 如果我们用一个 tuple_cat 作为第一个实参来调用 std::pair 怎么办? 我们会试图向 std::pair 追加更多元素, 而这会失败.

我们可以通过用一个空元组作为 mp_append 的第一个实参来解决这两个问题:

template<class... Tp,
    class R = mp_append<std::tuple<>, typename std::remove_reference<Tp>::type...>>
    R tuple_cat( Tp &&... tp );

返回类型解决后, 现在继续计算 inner. 我们的输入是

[x1, x2, x3], [], [y1, y2, y3], [z1, z2]

而需要输出

[0, 0, 0, 2, 2, 2, 3, 3]

它是以下内容的拼接:

[0, 0, 0], [], [2, 2, 2], [3, 3]

这里每个元组与输入大小相同, 但填充了一个常量, 表示它在实参列表中的索引. 第一个元组填充 0, 第二个填充 1, 第三个填充 2, 依此类推.

如果我们先计算一个索引列表 (在我们的例子中是 [0, 1, 2, 3]), 然后对这两个列表使用二元 mp_transform, 就能得到这个结果.

[[x1, x2, x3], [], [y1, y2, y3], [z1, z2]]
[0, 1, 2, 3]

以及一个接受列表和一个整数 (以 std::integral_constant 的形式) 并返回一个与原列表大小相同、但用第二个实参填充的列表的函数.

我们将把这个函数称为 mp_fill, 沿用 std::fill 的名字.

函数式程序员会立刻意识到 mp_fill 就是 mp_transform 配上一个返回常量的函数, 以下是沿此思路的一个实现:

template<class V> struct mp_constant
{
    template<class...> using apply = V;
};

template<class L, class V>
    using mp_fill = mp_transform<mp_constant<V>::template apply, L>;

这是另一个实现:

template<class L, class V> struct mp_fill_impl;

template<template<class...> class L, class... T, class V>
    struct mp_fill_impl<L<T...>, V>
{
    template<class...> using _fv = V;
    using type = L<_fv<T>...>;
};

template<class L, class V> using mp_fill = typename mp_fill_impl<L, V>::type;

它们展示了不同的风格, 在这里选择哪一个很大程度上是品味问题. 第一种情形组合既有原语; 第二种情形则在 mp_const 的函数体里“内联”了 mp_transform 甚至 mp_fill_impl.

大多数 C++11 程序员可能会觉得第二种实现更易读.

我们现在可以 mp_fill, 但还需要 [0, 1, 2, 3] 索引序列. 我们可以为它写一个算法 mp_iota (以 std::iota 命名), 但恰好 C++14 已经有一种生成索引序列的标准方式, 称为 std::make_index_sequence. 由于 Eric 的原始解法使用了 make_index_sequence, 我们就遵照他的做法.

严格来说, 这使我们超出了 C++11 的范围, 但 make_index_sequence 并不难实现 (如果不考虑效率):

template<class T, T... Ints> struct integer_sequence
{
};

template<class S> struct next_integer_sequence;

template<class T, T... Ints> struct next_integer_sequence<integer_sequence<T, Ints...>>
{
    using type = integer_sequence<T, Ints..., sizeof...(Ints)>;
};

template<class T, T I, T N> struct make_int_seq_impl;

template<class T, T N>
    using make_integer_sequence = typename make_int_seq_impl<T, 0, N>::type;

template<class T, T I, T N> struct make_int_seq_impl
{
    using type = typename next_integer_sequence<
        typename make_int_seq_impl<T, I+1, N>::type>::type;
};

template<class T, T N> struct make_int_seq_impl<T, N, N>
{
    using type = integer_sequence<T>;
};

template<std::size_t... Ints>
    using index_sequence = integer_sequence<std::size_t, Ints...>;

template<std::size_t N>
    using make_index_sequence = make_integer_sequence<std::size_t, N>;

我们现在可以获得一个 index_sequence<0, 1, 2, 3>:

template<class... Tp,
    class R = mp_append<std::tuple<>, typename std::remove_reference<Tp>::type...>>
    R tuple_cat( Tp &&... tp )
{
    std::size_t const N = sizeof...(Tp);

    // inner

    using seq = make_index_sequence<N>;
}

但 make_index_sequence<4> 返回的是 integer_sequence<std::size_t, 0, 1, 2, 3>, 这不是类型列表. 要使用它, 我们需要把它转换为类型列表, 所以我们将引入一个完成此事的函数 mp_from_sequence.

template<class S> struct mp_from_sequence_impl;

template<template<class T, T... I> class S, class U, U... J>
    struct mp_from_sequence_impl<S<U, J...>>
{
    using type = mp_list<std::integral_constant<U, J>...>;
};

template<class S> using mp_from_sequence = typename mp_from_sequence_impl<S>::type;

现在我们可以计算出想要用 mp_fill 变换的那两个列表了:

template<class... Tp,
    class R = mp_append<std::tuple<>, typename std::remove_reference<Tp>::type...>>
    R tuple_cat( Tp &&... tp )
{
    std::size_t const N = sizeof...(Tp);

    // inner

    using list1 = mp_list<typename std::remove_reference<Tp>::type...>;
    using list2 = mp_from_sequence<make_index_sequence<N>>;

    // list1: [[x1, x2, x3], [], [y1, y2, y3], [z1, z2]]
    // list2: [0, 1, 2, 3]

    return R{};
}

并完成计算 inner 的工作:

template<class... Tp,
    class R = mp_append<std::tuple<>, typename std::remove_reference<Tp>::type...>>
    R tuple_cat( Tp &&... tp )
{
    std::size_t const N = sizeof...(Tp);

    // inner

    using list1 = mp_list<typename std::remove_reference<Tp>::type...>;
    using list2 = mp_from_sequence<make_index_sequence<N>>;

    // list1: [[x1, x2, x3], [], [y1, y2, y3], [z1, z2]]
    // list2: [0, 1, 2, 3]

    using list3 = mp_transform<mp_fill, list1, list2>;

    // list3: [[0, 0, 0], [], [2, 2, 2], [3, 3]]

    using inner = mp_rename<list3, mp_append>; // or mp_apply<mp_append, list3>

    // inner: [0, 0, 0, 2, 2, 2, 3, 3]

    return R{};
}

对于 outer, 我们同样有

[x1, x2, x3], [], [y1, y2, y3], [z1, z2]

而需要输出

[0, 1, 2, 0, 1, 2, 0, 1]

它是以下内容的拼接:

[0, 1, 2], [], [0, 1, 2], [0, 1]

这里的区别是, 我们需要填充的不是常量值, 而是从 0 开始递增的值, 也就是 make_index_sequence<N> 的结果, 其中 N 是元素数量.

直接的做法是定义一个按我们的要求行事的元函数 F, 然后用 mp_transform 把它应用到输入上:

template<class N> using mp_iota = mp_from_sequence<make_index_sequence<N::value>>;

template<class L> using F = mp_iota<mp_size<L>>;

template<class... Tp,
    class R = mp_append<std::tuple<>, typename std::remove_reference<Tp>::type...>>
    R tuple_cat( Tp &&... tp )
{
    std::size_t const N = sizeof...(Tp);

    // outer

    using list1 = mp_list<typename std::remove_reference<Tp>::type...>;
    using list2 = mp_transform<F, list1>;

    // list2: [[0, 1, 2], [], [0, 1, 2], [0, 1]]

    using outer = mp_rename<list2, mp_append>;

    // outer: [0, 1, 2, 0, 1, 2, 0, 1]

    return R{};
}

嗯, 这很容易. 出奇地容易. 一个小小的不便是我们不能在 F 内部定义 tuple_cat ——模板不能在函数内定义.

让我们把所有东西放在一起.

template<class N> using mp_iota = mp_from_sequence<make_index_sequence<N::value>>;

template<class L> using F = mp_iota<mp_size<L>>;

template<class R, class...Is, class... Ks, class Tp>
R tuple_cat_( mp_list<Is...>, mp_list<Ks...>, Tp tp )
{
    return R{ std::get<Ks::value>(std::get<Is::value>(tp))... };
}

template<class... Tp,
    class R = mp_append<std::tuple<>, typename std::remove_reference<Tp>::type...>>
    R tuple_cat( Tp &&... tp )
{
    std::size_t const N = sizeof...(Tp);

    // inner

    using list1 = mp_list<typename std::remove_reference<Tp>::type...>;
    using list2 = mp_from_sequence<make_index_sequence<N>>;

    // list1: [[x1, x2, x3], [], [y1, y2, y3], [z1, z2]]
    // list2: [0, 1, 2, 3]

    using list3 = mp_transform<mp_fill, list1, list2>;

    // list3: [[0, 0, 0], [], [2, 2, 2], [3, 3]]

    using inner = mp_rename<list3, mp_append>; // or mp_apply<mp_append, list3>

    // inner: [0, 0, 0, 2, 2, 2, 3, 3]

    // outer

    using list4 = mp_transform<F, list1>;

    // list4: [[0, 1, 2], [], [0, 1, 2], [0, 1]]

    using outer = mp_rename<list4, mp_append>;

    // outer: [0, 1, 2, 0, 1, 2, 0, 1]

    return tuple_cat_<R>( inner(), outer(),
        std::forward_as_tuple( std::forward<Tp>(tp)... ) );
}

这几乎可以编译, 只是我们的 inner 恰好是一个 std::tuple, 而我们的辅助函数期望一个 mp_list. (碰巧, outer 已经是一个 mp_list, 纯属侥幸.) 我们可以很容易地修正这一点.

return tuple_cat_<R>( mp_rename<inner, mp_list>(), outer(),
    std::forward_as_tuple( std::forward<Tp>(tp)... ) );

让我们定义一个 print_tuple 函数, 看看一切是否正确.

template<int I, int N, class... T> struct print_tuple_
{
    void operator()( std::tuple<T...> const & tp ) const
    {
        using Tp = typename std::tuple_element<I, std::tuple<T...>>::type;

        print_type<Tp>( " ", ": " );

        std::cout << std::get<I>( tp ) << ";";

        print_tuple_< I+1, N, T... >()( tp );
    }
};

template<int N, class... T> struct print_tuple_<N, N, T...>
{
    void operator()( std::tuple<T...> const & ) const
    {
    }
};

template<class... T> void print_tuple( std::tuple<T...> const & tp )
{
    std::cout << "{";
    print_tuple_<0, sizeof...(T), T...>()( tp );
    std::cout << " }\n";
}

int main()
{
    std::tuple<int, long> t1{ 1, 2 };
    std::tuple<> t2;
    std::tuple<float, double, long double> t3{ 3, 4, 5 };
    std::pair<void const*, char const*> t4{ "pv", "test" };

    using expected = std::tuple<int, long, float, double, long double,
        void const*, char const*>;

    auto result = ::tuple_cat( t1, t2, t3, t4 );

    static_assert( std::is_same<decltype(result), expected>::value, "" );

    print_tuple( result );
}

输出:

{ int: 1; long: 2; float: 3; double: 4; long double: 5; void const*: 0x407086;
    char const*: test; }

似乎可以工作. 但至少还剩一个错误. 要明白原因, 把第一个元组

std::tuple<int, long> t1{ 1, 2 };

换成一个 pair:

std::pair<int, long> t1{ 1, 2 };

现在我们在

using inner = mp_rename<list3, mp_append>;

处得到一个错误, 因为 list3 的第一个元素是一个 std::pair, 而 mp_append 试图把它用作返回类型却失败了.

有两种修复方法. 第一种是应用我们为返回类型所用的相同技巧, 在 mp_list 的前面插入一个空的 list3, 让 mp_append 把它用作返回类型:

using inner = mp_rename<mp_push_front<list3, mp_list<>>, mp_append>;

第二种方法是直接把所有输入转换为 mp_list:

using list1 = mp_list<
    mp_rename<typename std::remove_reference<Tp>::type, mp_list>...>;

在这两种情况下, inner 现在都会是一个 mp_list, 因此我们可以省略对 mp_rename 调用中的 tuple_cat_.

我们完成了. 结果但愿能说明一切.

高阶元编程, 或其缺失

也许你现在会纳闷, 既然到目前为止我们讲的内容并不特别简单, 为什么这篇文章叫 “Simple C++11 metaprogramming”.

我们方法的相对 简单性源于这样一个事实: 我们一直没有做任何高阶元编程, 也就是说, 我们还没有引入任何返回元函数的原语, 例如 compose, bind, 或者 lambda 库.

我认为, 在大多数情况下, 这种高阶元编程在 C++11 中是不必要的. 例如, 考虑上面给出的 Eric Niebler 的解法:

using outer =
    typelist_cat_t<
        typelist_transform_t<
            typelist<as_typelist_t<Tuples>...>,
            meta_compose<
                meta_quote<as_typelist_t>,
                meta_quote_i<std::size_t, make_index_sequence>,
                meta_quote<typelist_size_t> > > >;

这个 meta_compose 表达式接受另外三个 (“引用的”) 元函数, 并创建一个按顺序应用它们的新元函数. Eric 用这个例子作为动机, 引入“元函数类”的概念, 然后提供各种操作元函数类的原语.

但当我们有元函数 F、G 和 H 时, 在 C++11 中不必使用 meta_compose, 而是可以直接这样写

template<class... T> using Fgh = F<G<H<T...>>>;

就这样. 语言让定义复合函数变得容易, 不需要库支持. 如果要组合的函数是 as_typelist_t、std::make_index_sequence 和 typelist_size_t, 我们只需定义

template<class... T>
    using F = as_typelist_t<std::make_index_sequence<typelist_size_t<T...>::value>>;

类似地, 如果我们需要一个返回 sizeof(T) < sizeof(U) 的元函数, 不必像下面这样求助于元编程 lambda 库:

lambda<_a, _b, less<sizeof_<_a>, sizeof_<_b>>>>

我们可以直接内联定义它:

template<class T, class U> using sizeof_less = mp_bool<(sizeof(T) < sizeof(U))>;

还有一件事

最后, 让我展示 mp_count 和 mp_count_if 的实现, 理由仅仅是我觉得它们有趣. mp_count<L, V> 返回类型 V 在列表 L 中出现的次数; mp_count_if<L, P> 统计 L 中使 P<T> 为 true.

作为第一步, 我将实现 mp_plus. mp_plus 是一个变参 (不只是二元) 元函数, 返回其各实参之和.

template<class... T> struct mp_plus_impl;

template<class... T> using mp_plus = typename mp_plus_impl<T...>::type;

template<> struct mp_plus_impl<>
{
    using type = std::integral_constant<int, 0>;
};

template<class T1, class... T> struct mp_plus_impl<T1, T...>
{
    static constexpr auto _v = T1::value + mp_plus<T...>::value;

    using type = std::integral_constant<
        typename std::remove_const<decltype(_v)>::type, _v>;
};

现在有了 mp_plus, mp_count 就只是

template<class L, class V> struct mp_count_impl;

template<template<class...> class L, class... T, class V>
    struct mp_count_impl<L<T...>, V>
{
    using type = mp_plus<std::is_same<T, V>...>;
};

template<class L, class V> using mp_count = typename mp_count_impl<L, V>::type;

这是参数包展开威力的又一个例证. 遗憾的是我们不能在 mp_plus 中也使用包展开来直接得到

T1::value + T2::value + T3::value + T4::value + ...

要是能支持 T::value + ... 就好了, 而且看起来在 C++17 中将会支持.

mp_count_if 的实现同样直白:

template<class L, template<class...> class P> struct mp_count_if_impl;

template<template<class...> class L, class... T, template<class...> class P>
    struct mp_count_if_impl<L<T...>, P>
{
    using type = mp_plus<P<T>...>;
};

template<class L, template<class...> class P>
    using mp_count_if = typename mp_count_if_impl<L, P>::type;

至少在我们要求 P 返回 bool 的情况下是这样. 否则, 我们必须把 P<T>::value 强制转换为 0 或 1, 否则计数将不正确.

template<bool v> using mp_bool = std::integral_constant<bool, v>;

template<class L, template<class...> class P> struct mp_count_if_impl;

template<template<class...> class L, class... T, template<class...> class P>
    struct mp_count_if_impl<L<T...>, P>
{
    using type = mp_plus<mp_bool<P<T>::value != 0>...>;
};

template<class L, template<class...> class P>
    using mp_count_if = typename mp_count_if_impl<L, P>::type;

我要展示的最后一个原语是 mp_contains. mp_contains<L, V> 返回列表 L 是否包含类型 V:

template<class L, class V> using mp_contains = mp_bool<mp_count<L, V>::value != 0>;

乍一看, 这个实现显得极其幼稚低效——如果我们只关心布尔结果, 为什么还要统计所有出现次数然后扔掉——但它实际上相当有竞争力, 完全可用. 我们只需给 mp_plus (即 mp_count 和 mp_contains 背后的引擎) 添加一个小小的优化:

template<class T1, class T2, class T3, class T4, class T5,
    class T6, class T7, class T8, class T9, class T10, class... T>
    struct mp_plus_impl<T1, T2, T3, T4, T5, T6, T7, T8, T9, T10, T...>
{
    static constexpr auto _v = T1::value + T2::value + T3::value + T4::value +
        T5::value + T6::value + T7::value + T8::value + T9::value + T10::value +
        mp_plus<T...>::value;

    using type = std::integral_constant<
        typename std::remove_const<decltype(_v)>::type, _v>;
};

这将模板实例化的次数大约削减为十分之一.

结论

我概述了一种 C++11 元编程方法, 它

  • 利用变参模板、参数包展开和模板别名;

  • 在任何变参模板 L<T...> 上操作, 把它当作基本数据结构, 而不强制特定的类型列表表示;

  • 使用模板别名作为元函数, 表达式 F<T...> 充当函数调用的等价物;

  • 利用数据结构 L<T...> 与元函数调用 F<T...> 之间的结构相似性;

  • 尽可能利用参数包展开, 而不是使用传统的递归实现;

  • 依靠模板别名的内联定义来进行函数组合, 而不是为这一任务提供库支持.
