概述

Mp11 是一个 C++11 元编程库, 用于对包含类型的数据结构进行编译期操作. 它基于模板别名和变参模板, 实现了文章 "Simple C++ metaprogramming" 及其续篇 中概述的方法. 在继续阅读本文档之前, 强烈 建议先读这两篇文章.

Mp11 构建所依据的一般原则是: 算法和元函数都是形如 F<T…​> 的模板别名, 而数据结构是形如 L<T…​> 的列表, 库对 L 不作任何要求. mp_list<T…​> 是内置的列表类型, 但 std::tuple<T…​>、std::pair<T1, T2> 和 std::variant<T…​> 也都是完全合法的列表类型, 当然 std::pair<T1, T2> 由于恰好有两个元素, 不可调整大小, 因而无法与需要添加或删除元素的算法配合使用.

这种方法另一个显著的特点是, 列表 (L<T…​>) 与元函数 (F<T…​>) 具有相同的形式, 因此可以当作元函数使用. 例如, 通过 std::add_pointer_t 把 std::tuple<int, float> 应用到列表 mp_transform<std::add_pointer_t, std::tuple<int, float>> 会得到 std::tuple<int*, float*>, 但我们也可以把 mp_list 应用到同一个元组:

using R = mp_transform<mp_list, std::tuple<int, float>>;

并得到 std::tuple<mp_list<int>, mp_list<float>>.

定义

一个列表 是一个——通常但不必然是变参的——类模板的实例化, 其所有参数都是类型, 例如 mp_list<char[], void>、mp_list<>、std::tuple<int, float, char>、std::pair<int, float>、std::shared_ptr<X>.

一个元函数 是一个类模板或模板别名, 其所有参数都是类型, 例如 std::add_pointer_t、std::is_const、mp_second、mp_push_front、mp_list、std::tuple、std::pair、std::shared_ptr, 或

template<class...> using F1 = void;

template<class T> using F2 = T*;

template<class... T> using F3 = std::integral_constant<std::size_t, sizeof...(T)>;

一个引用元函数 是一个具有公有元函数成员的类, 该成员名为 fn, 例如

struct Q1 { template<class...> using fn = void; };

struct Q2 { template<class T> using fn = T*; };

struct Q3 { template<class... T> using fn =
  std::integral_constant<std::size_t, sizeof...(T)>; };

一个整型常量类型 是一个具有公有成员 value 的类, 该成员是 C++ 意义上的整型常量. 例如, std::integral_constant<int, 7>, 或

struct N { static int constexpr value = 2; };

一个集合 是元素唯一的列表.

一个映射 是一个由列表构成的列表, 内层列表至少有一个元素 (即键). 映射的键必须唯一. 例如:

using M1 = std::tuple<std::pair<int, int*>, std::pair<float, float*>,
    std::pair<void, void*>>;

using M2 = mp_list<mp_list<int, int*>, mp_list<float>,
    mp_list<char, char[1], char[2]>>;

一个值列表 是一个模板类, 其所有参数都是值 (非类型模板参数). 值列表匹配 template<auto…​> class L, 并且需要 C++17 (因为 auto 模板参数是 C++17 的特性.)

只有少数原语支持值列表. Mp11 的主要关注点是类型操作. 要处理值列表, 通常的做法是先用 mp_rename 把值列表转换为类型列表, 操作该类型列表, 然后用 mp_rename_v 转换回值列表.

示例

生成测试用例

假设我们已经写了一个元函数 result<T, U>:

template<class T> using promote = typename std::common_type<T, int>::type;

template<class T, class U> using result =
    typename std::common_type<promote<T>, promote<U>>::type;

它应当表示对整型 T 和 U 进行算术运算的结果, 例如 t + u. 我们想测试对于 result<T, U> 和 T 的各种组合, U 是否给出正确结果, 于是我们编写函数

template<class T1, class T2> void test_result()
{
    using T3 = decltype( T1() + T2() );
    using T4 = result<T1, T2>;

    std::cout << ( std::is_same<T3, T4>::value? "[PASS]": "[FAIL]" ) << std::endl;
}

然后需要把它调用很多次:

int main()
{
    test_result<char, char>();
    test_result<char, short>();
    test_result<char, int>();
    test_result<char, unsigned>();
    // ...
}

手工写出所有这些类型组合既笨拙又容易出错, 最糟的是枯燥乏味. 这就是我们如何利用 Mp11 来自动化这项任务:

#include <boost/mp11.hpp>
#include <boost/core/demangle.hpp>
#include <type_traits>
#include <iostream>
#include <typeinfo>

using namespace boost::mp11;

template<class T> std::string name()
{
    return boost::core::demangle( typeid(T).name() );
}

template<class T> using promote = typename std::common_type<T, int>::type;

template<class T, class U> using result =
    typename std::common_type<promote<T>, promote<U>>::type;

template<class T1, class T2> void test_result( mp_list<T1, T2> const& )
{
    using T3 = decltype( T1() + T2() );
    using T4 = result<T1, T2>;

    std::cout << ( std::is_same<T3, T4>::value? "[PASS] ": "[FAIL] " )
        << name<T1>() << " + " << name<T2>() << " -> " << name<T3>()
        << ", result: " << name<T4>() << std::endl;
}

int main()
{
    using L = std::tuple<char, short, int, unsigned, long, unsigned long>;
    tuple_for_each( mp_product<mp_list, L, L>(), [](auto&& x){ test_result(x); } );
}

它是如何工作的?

mp_product<F, L1, L2> 调用 F<T1, T2>, 其中 T1 遍历 L1 的元素, T2 遍历 L2 的元素, 如同执行两个嵌套循环. 然后它返回由这些结果构成的列表, 类型与 L1 相同.

在我们的例子中, 两个列表都是同一个 std::tuple, 且 F 是 mp_list, 所以 mp_product<mp_list, L, L> 将为我们得到 std::tuple<mp_list<char, char>, mp_list<char, short>, mp_list<char, int>, …​, mp_list<unsigned long, long>, mp_list<unsigned long, unsigned long>>.

然后我们默认构造这个元组并把它传给 tuple_for_each. tuple_for_each(tp, f) 对每个元组元素调用 f; 我们使用一个 (C++14) lambda 来调用 test_result.

在纯 C++11 中, 我们不能使用带 auto&& 参数的 lambda, 所以必须把 test_result 做成一个带有模板化 operator() 的函数对象, 并把它直接传给 tuple_for_each:

struct test_result
{
    template<class T1, class T2> void operator()( mp_list<T1, T2> const& ) const
    {
        using T3 = decltype( T1() + T2() );
        using T4 = result<T1, T2>;

        std::cout << ( std::is_same<T3, T4>::value? "[PASS] ": "[FAIL] " )
            << name<T1>() << " + " << name<T2>() << " -> " << name<T3>()
            << ", result: " << name<T4>() << std::endl;
    }
};

int main()
{
    using L = std::tuple<char, short, int, unsigned, long, unsigned long>;
    tuple_for_each( mp_product<mp_list, L, L>(), test_result() );
}

编写 common_type 特化

标准特征 std::common_type 用于获得一个其所有实参都能在不必要损失精度的情况下转换为它的类型; 当其默认实现 (基于三元 ?: 运算符) 不适用时, 可以由用户对其特化.

让我们写一个 common_type 特化, 用于两个 std::tuple 实参. 为此, 我们需要一个元函数, 把 std::common_type 应用到每一对元素并把结果收集进一个元组:

template<class... T> using common_type_t =
    typename std::common_type<T...>::type; // standard in C++14

template<class Tp1, class Tp2> using common_tuple =
    mp_transform<common_type_t, Tp1, Tp2>;

然后用它特化 common_type:

namespace std
{

    template<class... T1, class... T2>
    struct common_type<std::tuple<T1...>, std::tuple<T2...>>:
        mp_defer<common_tuple, std::tuple<T1...>, std::tuple<T2...>>
    {
    };

} // std

(无需为多于两个实参对 std::common_type 进行特化——它会根据二元情形自动合成适当的语义.)

这里的微妙之处在于使用 mp_defer. 我们本可以定义一个内层 type 来 common_tuple<std::tuple<T1…​>, std::tuple<T2…​>>, 这样在所有有效情形下仍然可以工作. 不过, 让 mp_defer 来定义 type, 能让我们的特化 对 SFINAE 友好.

也就是说, 当我们的 common_tuple 导致替换失败而不是硬错误时, mp_defer 将不会定义内层 type, 而 common_type_t (定义为 typename common_type<…​>::type) 也会导致替换失败.

作为另一个例子, 考虑假想的类型 expected<T, E…​>, 它表示要么成功返回一个 T 类型的值, 要么失败返回列表 E…​ 中某种类型的错误码. expected<T1, E1, E2, E3> 与 expected<T2, E1, E4, E5> 的公共类型是 expected<common_type_t<T1, T2>, E1, E2, E3, E4, E5>. 也就是说, 可能的返回值被合并成它们的公共类型, 而错误类型的集合则取并集.

因此:

template<class T1, class E1, class T2, class E2> using common_expected =
    mp_rename<mp_push_front<mp_unique<mp_append<E1, E2>>, common_type_t<T1, T2>>,
        expected>;

namespace std
{

    template<class T1, class... E1, class T2, class... E2>
    struct common_type<expected<T1, E1...>, expected<T2, E2...>>:
        mp_defer<common_expected, T1, mp_list<E1...>, T2, mp_list<E2...>>
    {
    };

} // std

这里我们采用了不同的思路; 我们不把 expected 类型传给 common_expected, 而是传入 T 类型和由 E 类型构成的列表. 这让我们的工作更容易. mp_unique<mp_append<E1, E2>> 给出 E1 与 E2 去除重复后的拼接; 然后我们把 common_type_t<T1, T2> 通过 mp_push_front 加到最前面; 最后, 我们 mp_rename 所得的 mp_list 为 expected.

修正 tuple_cat

文章 Simple C++11 metaprogramming 构建了标准函数 tuple_cat 的一个实现, 最终结果如下:

template<class L> using F = mp_iota<mp_size<L>>;

template<class R, class...Is, class... Ks, class Tp>
R tuple_cat_( mp_list<Is...>, mp_list<Ks...>, Tp tp )
{
    return R{ std::get<Ks::value>(std::get<Is::value>(tp))... };
}

template<class... Tp,
    class R = mp_append<std::tuple<>, typename std::remove_reference<Tp>::type...>>
    R tuple_cat( Tp &&... tp )
{
    std::size_t const N = sizeof...(Tp);

    // inner

    using list1 = mp_list<
        mp_rename<typename std::remove_reference<Tp>::type, mp_list>...>;

    using list2 = mp_iota_c<N>;

    using list3 = mp_transform<mp_fill, list1, list2>;

    using inner = mp_apply<mp_append, list3>;

    // outer

    using list4 = mp_transform<F, list1>;

    using outer = mp_apply<mp_append, list4>;

    //

    return tuple_cat_<R>( inner(), outer(),
        std::forward_as_tuple( std::forward<Tp>(tp)... ) );
}

然而, 这个函数并不完全正确, 它没有正确处理某些情形. 例如, 尝试拼接含有仅移动元素 (如 unique_ptr) 的元组会失败:

std::tuple<std::unique_ptr<int>> t1;
std::tuple<std::unique_ptr<float>> t2;

auto result = ::tuple_cat( std::move( t1 ), std::move( t2 ) );

尝试拼接 const 元组会失败:

std::tuple<int> const t1;
std::tuple<float> const t2;

auto result = ::tuple_cat( t1, t2 );

最后, 标准 tuple_cat 被规定可用于任意元组式类型 (即所有支持 tuple_size、tuple_element 和 get) 的类型), 而我们的实现只能用于 tuple 和 pair. std::array 例如就会失败:

std::array<int, 2> t1{ 1, 2 };
std::array<float, 3> t2{ 3.0f, 4.0f, 5.0f };

auto result = ::tuple_cat( t1, t2 );

让我们逐个修复. 如果知道该看哪里, 支持仅移动类型很容易. 问题在于, Tp (我们要把它传给辅助 tuple_cat_) 是 (正确的) tuple<unique_ptr<int>&&, unique_ptr<float>&&>, 但 std::get<0>(tp) 仍然返回 unique_ptr<int>&, 因为 tp 是左值. 这个行为有点令人意外, 但其目的是防止无意的双重移动.

长话短说, 我们需要在 std::move(tp) 中使用 tuple_cat_ 来使 tp 成为右值:

template<class R, class...Is, class... Ks, class Tp>
R tuple_cat_( mp_list<Is...>, mp_list<Ks...>, Tp tp )
{
    return R{ std::get<Ks::value>(std::get<Is::value>(std::move(tp)))... };
}

接下来是带 const 限定的元组. 这里的问题在于, 我们从输入元组中去除了引用, 却没有去除 const. 结果, 我们试图用 Mp11 算法操纵 tuple<int> const 这样的类型, 而这些类型不符合列表概念. 我们只需要把限定符也去除, 办法是定义标准库中莫名其妙缺失的实用原语 remove_cv_ref:

template<class T> using remove_cv_ref = typename std::remove_cv<

然后用 remove_cv_ref<Tp> 代替 typename std::remove_reference<Tp>::type:

{
    std::size_t const N = sizeof...(Tp);

    // inner

    using list1 = mp_list<mp_rename<remove_cv_ref<Tp>, mp_list>...>;

    // ...

最后是元组式类型. 迄今为止我们利用了 std::pair 和 std::tuple 是有效 Mp11 列表这一事实, 但一般而言, 任意元组式类型并不是, 所以需要把它们转换成列表. 为此, 我们需要定义一个元函数 from_tuple_like, 它接受任意元组式类型, 并在我们的情形中返回对应的 mp_list.

严格来说, 更有原则的做法是返回 std::tuple, 但在这里 mp_list 会证明更加方便.

我们需要的是: 给定一个元组式类型 Tp, 获得 mp_list<std::tuple_element<0, Tp>::type, std::tuple_element<1, Tp>::type, …​, std::tuple_element<N-1, Tp>::type>, 其中 N 是 tuple_size<Tp>::value. 下面是一种做法:

template<class T, class I> using tuple_element =
    typename std::tuple_element<I::value, T>::type;

template<class T> using from_tuple_like =
    mp_product<tuple_element, mp_list<T>, mp_iota<std::tuple_size<T>>>;

(mp_iota<N> 是一个算法, 它返回一个 mp_list, 其元素为 mp_size_t<0>, mp_size_t<1>, …​, mp_size_t<N-1>.)

记住 mp_product<F, L1, L2> 执行的是等价于对 L1 和 L2 的元素做两个嵌套循环, 并把 F 应用到这两个变量上收集结果. 在我们的例子中, L1 只由单个元素 T 组成, 所以只剩下第二个循环 (遍历 mp_iota<N>, 其中 N 是 tuple_size<T>), 我们得到一个与 L1 类型相同的列表 (一个 mp_list), 其内容为 tuple_element<T, mp_size_t<0>>, tuple_element<T, mp_size_t<1>>, …​, tuple_element<T, mp_size_t<N-1>>.

为了完整起见, 这里是达到相同结果的另一种更传统的方式:

template<class T> using from_tuple_like =
    mp_transform_q<mp_bind_front<tuple_element, T>, mp_iota<std::tuple_size<T>>>;

应用所有这些修复后, 我们功能完备的 tuple_cat 现在看起来像这样:

template<class L> using F = mp_iota<mp_size<L>>;

template<class R, class...Is, class... Ks, class Tp>
R tuple_cat_( mp_list<Is...>, mp_list<Ks...>, Tp tp )
{
    return R{ std::get<Ks::value>(std::get<Is::value>(std::move(tp)))... };
}

template<class T> using remove_cv_ref = typename std::remove_cv<
    typename std::remove_reference<T>::type>::type;

template<class T, class I> using tuple_element =
    typename std::tuple_element<I::value, T>::type;

template<class T> using from_tuple_like =
    mp_product<tuple_element, mp_list<T>, mp_iota<std::tuple_size<T>>>;

template<class... Tp,
    class R = mp_append<std::tuple<>, from_tuple_like<remove_cv_ref<Tp>>...>>
    R tuple_cat( Tp &&... tp )
{
    std::size_t const N = sizeof...(Tp);

    // inner

    using list1 = mp_list<from_tuple_like<remove_cv_ref<Tp>>...>;
    using list2 = mp_iota_c<N>;

    using list3 = mp_transform<mp_fill, list1, list2>;

    using inner = mp_apply<mp_append, list3>;

    // outer

    using list4 = mp_transform<F, list1>;

    using outer = mp_apply<mp_append, list4>;

    //

    return tuple_cat_<R>( inner(), outer(),
        std::forward_as_tuple( std::forward<Tp>(tp)... ) );
}

计算返回类型

C++17 有一个标准的 variant 类型, 称为 std::variant. 它还定义了一个函数模板 std::visit, 可用于把函数应用到一个或多个 variant 所包含的值上. 例如, 如果 variant v1 包含 1, 而 variant v2 包含 2.0f, 那么 std::visit(f, v1, v2) 将调用 f(1, 2.0f).

然而, std::visit 有一个限制: 除非函数的所有可能应用都具有相同的返回类型, 否则它无法返回结果. 例如, 如果 v1 和 v2 都是 std::variant<short, int, float> 类型,

std::visit( []( auto const& x, auto const& y ){ return x + y; }, v1, v2 );

将无法编译, 因为 x + y 的结果可能是 int 或 float, 取决于 v1 和 v2 所持有的值.

能够保存 int 或 float 的类型已经存在, 出人意料的是它叫 std::variant<int, float>. 让我们编写自己的函数模板 rvisit, 它与 visit 相同, 但返回一个 variant:

template<class F, class... V> auto rvisit( F&& f, V&&... v )
{
    using R = /*...*/;

    return std::visit( [&]( auto&&... x )
        { return R( std::forward<F>(f)( std::forward<decltype(x)>(x)... ) ); },
        std::forward<V>( v )... );
}

它所做的基本上是调用 std::visit 来完成工作, 但传给它的不是 f, 而是一个 lambda, 它做的事情与 f 相同, 只是把结果转换为公共类型 R. R 应当是 std::variant<…​>, 其中省略号表示用 variant 值的所有可能组合调用 f 所得的返回类型.

我们先定义一个辅助引用元函数 Qret<F>, 它返回把 F 应用到 T…​ 类型实参上的结果:

template<class F> struct Qret
{
    template<class... T> using fn =
        decltype( std::declval<F>()( std::declval<T>()... ) );
};

事实证明, C++17 已经包含了一个元函数, 它返回把函数 F 应用到 T…​ 类型实参的结果: std::invoke_result_t<F, T…​>. 我们可以利用它来把我们的 Qret 简化为

template<class F> struct Qret
{
    template<class... T> using fn = std::invoke_result_t<F, T...>;
};

而在 Mp11 中, 这可以更简洁地表示为

using Qret = mp_bind_front<std::invoke_result_t, F>;

有了 Qret, 可能返回类型的 variant 只需把它应用到 variant 值的所有可能组合上即可:

using R = mp_product_q<Qret, remove_cv_ref<V>...>;

为什么这样可行? mp_product<F, L1<T1…​>, L2<T2…​>, …​, Ln<Tn…​>> 返回 L1<F<U1, U2, …​, Un>, …​>, 其中 Ui 遍历列表值的所有可能组合. 由于在我们的例子中所有 Li 都是 std::variant, 结果也将是 std::variant. (mp_product_q 与 mp_product 相同, 但用于像我们的 Qret 这样的引用元函数.)

还剩最后一步. 假设如上所述, 我们传入两个 std::variant<short, int, float> 类型的 variant, 且 F 是 []( auto const& x, auto const& y ){ return x + y; }. 这会生成一个长度为 9 的 R, 每个组合对应一个元素, 但其中许多元素是相同的, 要么是 int 要么是 float, 我们需要过滤掉重复项. 于是把结果传给 mp_unique:

using R = mp_unique<mp_product_q<Qret, remove_cv_ref<V>...>>;

然后就完成了:

#include <boost/mp11.hpp>
#include <boost/core/demangle.hpp>
#include <variant>
#include <type_traits>
#include <typeinfo>
#include <iostream>

using namespace boost::mp11;

template<class T> using remove_cv_ref = typename std::remove_cv<
    typename std::remove_reference<T>::type>::type;

template<class F, class... V> auto rvisit( F&& f, V&&... v )
{
    using Qret = mp_bind_front<std::invoke_result_t, F>;

    using R = mp_unique<mp_product_q<Qret, remove_cv_ref<V>...>>;

    return std::visit( [&]( auto&&... x )
        { return R( std::forward<F>(f)( std::forward<decltype(x)>(x)... ) ); },
        std::forward<V>( v )... );
}

template<class T> std::string name()
{
    return boost::core::demangle( typeid(T).name() );
}

template<class V> void print_variant( char const * n, V const& v )
{
    std::cout << "(" << name<decltype(v)>() << ")" << n << ": ";

    std::visit( []( auto const& x )
        { std::cout << "(" << name<decltype(x)>() << ")" << x << std::endl; }, v );
}

int main()
{
    std::variant<char, int, float> v1( 1 );

    print_variant( "v1", v1 );

    std::variant<short, int, double> const v2( 3.14 );

    print_variant( "v2", v2 );

    auto v3 = rvisit( []( auto const& x, auto const& y ){ return x + y; }, v1, v2 );

    print_variant( "v3", v3 );
}

template<template<class...> class F, class... L> using mp_transform = /*...*/;

mp_transform<F, L1<T1…​>, L2<T2…​>, …​, Ln<Tn…​>> 把 F 应用到每一组连续的元素元组上, 并返回 L1<F<T1, T2, …​, Tn>…​>.

L…​ 中的所有列表必须大小相同. 否则, 结果为替换失败.

在 C++17 下以 L…​ 的形式提供对值列表的有限支持 (适用于一至三个列表.) 此时, 元素会用 mp_value 包装, 然后才传给 F, 之后解包. 结果为 L1<F<mp_value<T1>, mp_value<T2>, …​>::value…​>.

代码示例 67. 使用 mp_transform 从指针对象列表生成指针列表
template<class T> using add_pointer_t =
    typename std::add_pointer<T>::type;  // std::add_pointer_t in C++14

using L1 = std::tuple<void, int, float>;
using R1 = mp_transform<add_pointer_t, L1>; // std::tuple<void*, int*, float*>
代码示例 68. 使用 mp_transform 比较两个类型列表的内容
using L1 = std::tuple<void, int, float>;
using L2 = mp_list<void, int, float>;

using R1 = mp_apply<mp_all, mp_transform<std::is_same, L1, L2>>; // mp_true
代码示例 69. 使用 mp_transform 比较两个整型常量列表的内容
template<class T1, class T2> using eq = mp_bool<T1::value == T2::value>;

using L1 = std::tuple<mp_int<1>, mp_int<2>, mp_int<3>>;
using L2 = mp_list<mp_size_t<1>, mp_size_t<2>, mp_size_t<3>>;

using R1 = mp_apply<mp_all, mp_transform<eq, L1, L2>>; // mp_true

using R1 = mp_and<mp_true, mp_true>;   // mp_true

using R2 = mp_and<mp_false, void>;     // mp_false, void is not reached

using R3 = mp_and<mp_false, mp_false>; // mp_false

using R4 = mp_and<void, mp_true>;      // mp_false (!)

mp_all<T…​>

template<class... T> using mp_all = /*...*/;

mp_all<T…​> 当 mp_true 对 mp_to_bool<U> 中的所有类型 mp_true 都为 U 时为 T…​, 否则为 mp_false. 与 mp_and 相同, 但不执行短路求值. mp_and<mp_false, void> 为 mp_false, 但 mp_all<mp_false, void> 是错误的, 因为 void 没有内嵌的 value. 好处是 mp_all 可能更快, 并且不会像 mp_and 那样掩盖替换失败.

代码示例 91. mp_all 的行为
using R1 = mp_all<mp_true, mp_true>;   // mp_true

using R2 = mp_all<mp_false, void>;     // compile-time error

using R3 = mp_all<mp_false, mp_false>; // mp_false

using R4 = mp_all<void, mp_true>;      // compile-time error

mp_or<T…​>

template<class... T> using mp_or = /*...*/;

mp_or<T…​> 依次把 mp_to_bool 应用到 T…​ 中的类型上. 如果某次应用的结果是 mp_true, 则 mp_or 返回 mp_true. 如果所有结果都是 mp_false, 则返回 mp_false. mp_or<> 为 mp_false.

代码示例 92. mp_or 的行为
using R1 = mp_or<mp_true, mp_false>;   // mp_true

using R2 = mp_or<mp_true, void>;       // mp_true, void is not reached

using R3 = mp_or<mp_false, mp_false>;  // mp_false

using R4 = mp_or<void, mp_true>;       // compile-time error

mp_any<T…​>

template<class... T> using mp_any = /*...*/;

mp_any<T…​> 当 mp_true 对 mp_to_bool<U> 中的任一类型 mp_true 为 U 时为 T…​, 否则为 mp_false. 与 mp_or 相同, 但不执行短路求值.

代码示例 93. mp_any 的行为
using R1 = mp_any<mp_true, mp_false>;  // mp_true

using R2 = mp_any<mp_true, void>;      // compile-time error

using R3 = mp_any<mp_false, mp_false>; // mp_false

using R4 = mp_any<void, mp_true>;      // compile-time error

mp_same<T…​>

template<class... T> using mp_same = /*...*/;

mp_same<T…​> 为 mp_true (若 T…​ 中的所有类型都是同一类型), 否则为 mp_false. mp_same<> 为 mp_true.

mp_similar<T…​>

template<class... T> using mp_similar = /*...*/;

mp_similar<T…​> 为 mp_true (若 T…​ 中的所有类型都是同一类型, 或都是同一个类模板的实例化且其参数全为类型), 否则为 mp_false. mp_similar<> 为 mp_true.

代码示例 94. mp_similar
using R1 = mp_similar<void>;                        // mp_true
using R2 = mp_similar<void, void>;                  // mp_true
using R3 = mp_similar<void, void, void>;            // mp_true
using R4 = mp_similar<void, void, float>;           // mp_false

template<class T> struct X;
template<class... T> struct Y;

using R5 = mp_similar<X<int>, X<void>, X<float>>;   // mp_true
using R6 = mp_similar<Y<>, Y<void>, Y<void, void>>; // mp_true
using R7 = mp_similar<X<void>, Y<void>>;            // mp_false

mp_plus<T…​>

template<class... T> using mp_plus = /*...*/;

mp_plus<T…​> 是一个整型常量类型, 其值为对 U::value 中的所有类型 U 求 T…​ 之和. mp_plus<> 为 mp_int<0>.

mp_less<T1, T2>

template<class T1, class T2> using mp_less = /*...*/;

mp_less<T1, T2> 为 mp_true (当 T1::value 的数值小于 T2::value 的数值时), 否则为 mp_false

(注意, 在有符号与无符号类型之间比较时, 这不一定等同于 T1::value < T2::value; -1 < 1u 为 false, 但 mp_less<mp_int<-1>, mp_size_t<1>> 为 mp_true.)

mp_min<T1, T…​>

template<class T1, class... T> using mp_min = mp_min_element<mp_list<T1, T...>, mp_less>;

mp_min<T…​> 返回 U (属于 T…​) 中 U::value 最低的那个类型.

mp_max<T1, T…​>

template<class T1, class... T> using mp_max = mp_max_element<mp_list<T1, T...>, mp_less>;

mp_max<T…​> 返回 U (属于 T…​) 中 U::value 最高的那个类型.

绑定, <boost/mp11/bind.hpp>

mp_arg<I>

template<std::size_t I> struct mp_arg;

mp_arg<I> 是一个引用元函数, 其内嵌模板 fn<T…​> 返回 I 的第 T…​ 个从零开始的元素.

_1, …​, _9

using _1 = mp_arg<0>;
using _2 = mp_arg<1>;
using _3 = mp_arg<2>;
using _4 = mp_arg<3>;
using _5 = mp_arg<4>;
using _6 = mp_arg<5>;
using _7 = mp_arg<6>;
using _8 = mp_arg<7>;
using _9 = mp_arg<8>;

_1 到 _9 是占位符类型, 等价于 boost::bind 的占位符.

mp_bind<F, T…​>

template<template<class...> class F, class... T> struct mp_bind;

mp_bind<F, T…​> 是一个引用元函数, 实现了 boost::bind 的基于类型的等价物. 其内嵌模板 fn<U…​> 返回 F<V…​>, 其中 V…​ 是 T…​, 其中的占位符被 U…​ 的对应元素替换, 而 mp_bind、mp_bind_front 和 mp_bind_back 表达式则被针对 U…​ 求值的结果替换.

例如, mp_bind<F, int, _2, mp_bind<G, _1>>::fn<float, void> 是 F<int, void, G<float>>.

mp_bind_q<Q, T…​>

template<class Q, class... T> using mp_bind_q = mp_bind<Q::template fn, T...>;

如同 mp_bind, 但接受一个引用元函数.

mp_bind_front<F, T…​>

template<template<class...> class F, class... T> struct mp_bind_front;

mp_bind_front<F, T…​> 把 F 最左边的实参绑定到 T…​. 其内嵌模板 fn<U…​> 返回 F<T…​, U…​>.

mp_bind_front_q<Q, T…​>

template<class Q, class... T> using mp_bind_front_q =
    mp_bind_front<Q::template fn, T...>;

如同 mp_bind_front, 但接受一个引用元函数.

mp_bind_back<F, T…​>

template<template<class...> class F, class... T> struct mp_bind_back;

mp_bind_back<F, T…​> 把 F 最右边的实参绑定到 T…​. 其内嵌模板 fn<U…​> 返回 F<U…​, T…​>.

mp_bind_back_q<Q, T…​>

template<class Q, class... T> using mp_bind_back_q =
    mp_bind_back<Q::template fn, T...>;

如同 mp_bind_back, 但接受一个引用元函数.

Lambda 表达式, <boost/mp11/lambda.hpp>

mp_lambda<T>

template<class T> using mp_lambda = /*...*/;

mp_lambda<T> 是一个引用元函数, 其内嵌模板 fn<U…​> 返回一个类型 V, 它与 T 具有相同的语法定义, 只是 T 中出现的占位符被 U…​ 的对应元素替换.

例如, mp_lambda<std::pair<_1, _2*>>::fn<int, char> 是 std::pair<int, char*>.

对于 T 中因以非类型模板参数实例化类模板而产生的那些组成部分, 不会发生替换.

注释
 在 GCC 4.8 中, 一个编译器缺陷会导致返回的类型 const 中的 volatile 和 V 限定符被剥离 (当它们应用于函数或成员函数类型时除外).
注释
 mp_lambda 在 VS2013 及更早版本中因编译器限制而不受支持.

整型序列, <boost/mp11/integer_sequence.hpp>

integer_sequence<T, I…​>

template<class T, T... I> struct integer_sequence
{
};

integer_sequence<T, I…​> 保存一个 T 类型的整数序列. 与 C++14 的 std::integer_sequence 相同.

make_integer_sequence<T, N>

template<class T, T N> using make_integer_sequence = /*...*/;

make_integer_sequence<T, N> 为 integer_sequence<T, 0, 1, …​, N-1>. 与 C++14 的 std::make_integer_sequence 相同.

index_sequence<I…​>

template<std::size_t... I> using index_sequence = integer_sequence<std::size_t, I...>;

index_sequence<I…​> 是 integer_sequence<size_t, I…​> 的别名. 与 C++14 的 std::index_sequence 相同.

make_index_sequence<N>

template<std::size_t N> using make_index_sequence =
    make_integer_sequence<std::size_t, N>;

make_index_sequence<N> 为 index_sequence<0, 1, …​, N-1>. 与 C++14 的 std::make_index_sequence 相同.

index_sequence_for<T…​>

template<class... T> using index_sequence_for =
    make_integer_sequence<std::size_t, sizeof...(T)>;

index_sequence_for<N> 为 make_index_sequence<sizeof…​(T)>. 与 C++14 的 std::index_sequence_for 相同.

元组操作, <boost/mp11/tuple.hpp>

tuple_apply(f, tp)

template<class F, class Tp> constexpr /*...*/ tuple_apply(F&& f, Tp&& tp);

tuple_apply(f, tp) 返回 std::forward<F>(f)(std::get<J>(std::forward<Tp>(tp))…​) (其中 J 取 0..N-1, N 为 std::tuple_size<typename std::remove_reference<Tp>::type>::value). 与 C++17 中的 std::apply 相同.

construct_from_tuple<T>(tp)

template<class T, class Tp> T construct_from_tuple(Tp&& tp);

construct_from_tuple<T>(tp) 返回 T(std::get<J>(std::forward<Tp>(tp))…​) (其中 J 取 0..N-1, N 为 std::tuple_size<typename std::remove_reference<Tp>::type>::value). 与 C++17 中的 std::make_from_tuple 相同. 该函数的名称与 C++17 版本不同, 以便在两者同时可见或在非限定调用时避免歧义.

tuple_for_each(tp, f)

template<class Tp, class F> constexpr F tuple_for_each(Tp&& tp, F&& f);

tuple_for_each(tp, f) 按顺序把函数对象 f 应用到 tp 的每个元素上, 通过求值表达式 f(std::get<J>(std::forward<Tp>(tp))) (对 J 取 0..N-1, 其中 N 为 std::tuple_size<typename std::remove_reference<Tp>::type>::value) 实现.

返回 std::forward<F>(f).

tuple_transform(f, tp…​)

template<class F, class... Tp> constexpr /*...*/ tuple_transform(F const& f, Tp&&... tp);

tuple_transform(f, tp…​) 接受一个函数对象 f, 后跟一个或多个等长元组 (std::tuple、std::pair 和 std::array 也被视为元组.)

可调用对象 f 必须能接受与元组数量相同的实参个数. 函数对象依次以各元组的第一个元素、各元组的第二个元素等被调用, 就像求值表达式 f(std::get<J>(std::forward<Tp>(tp))…​) (对 J 取 0..N-1, 其中 N 是元组的长度).

元组元素被处理的顺序未作规定.

结果以 std::tuple<T…​> 返回, 其中 T…​ 由 f 的返回值推导 (左值引用被保留, 右值引用按值返回).

便捷头文件, <boost/mp11.hpp>

便捷头文件 <boost/mp11.hpp> 包含本参考前面列出的所有头文件.

MPL 支持, <boost/mp11/mpl.hpp>

头文件 <boost/mp11/mpl.hpp> 被包含时, 会为 mp_list 和 std::tuple 定义必要的支持基础设施, 使它们成为有效的 MPL 序列.

注释
 mpl.hpp 不会被 <boost/mp11.hpp> 包含.

也可以只启用对 mp_list 的支持, 办法是包含 <boost/mp11/mpl_list.hpp>; 对 std::tuple 则包含 <boost/mp11/mpl_tuple.hpp>. 之所以可能需要这样做, 是因为某些库 (例如 Boost.Fusion) 自带针对 std::tuple 的 MPL 支持, 与 Mp11 的支持相冲突.
