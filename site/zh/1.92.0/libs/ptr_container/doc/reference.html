Clonable 概念

精化自

  • Heap Allocable
  • Heap Deallocable

引入 Clonable 概念是为了把拷贝堆上分配对象的要求形式化. 类型 T 即使不可赋值 (Assignable) 或不可拷贝构造 (Copy Constructible), 也可能是可克隆 (Clonable) 的. 注意, 容器上的许多操作甚至不要求所存类型是可克隆的.

记法

类型 对象 (const 或非 const) 指针 描述
T a ptr 一个可克隆 (Clonable) 的类型

有效表达式

表达式 类型 语义 后置条件
new_clone(a); T* 分配一个新对象, 可视为等价于对象 a typeid(*new_clone(a)) == typeid(a)
delete_clone(ptr); void 释放一个先前用 allocate_clone() 分配的对象. 不得抛出异常  

默认实现

头文件 <boost/ptr_container/clone_allocator.hpp> 中给出了这两个函数的默认实现:

namespace boost
{
    template< class T >
    inline T* new_clone( const T& t )
    {
        return new T( t );
    }

    template< class T >
    void delete_clone( const T* t )
    {
        checked_delete( t );
    }
}

注意, 这一实现使普通的可拷贝构造 (Copy Constructible) 类自动成为可克隆 (Clonable) 类, 除非 operator new() 或 operator delete() 被隐藏.

这两个函数表示一层间接, 这是支持默认情况下不可拷贝构造的类所必需的. 注意, 该实现依赖实参依赖查找 (ADL) 来找到 new_clone() 和 delete_clone() 的正确版本. 这意味着你不需要在 boost 命名空间中重载或特化这些函数, 而是可以把它们与类的其余接口放在一起. 如果你是在头文件中内联实现类, 请记得前向声明这些函数.

警告: 我们正在考虑移除上述默认实现. 因此, 请务必为你的类型重载这些函数, 并以任何方式都不要依赖默认实现.

Clone Allocator 概念

引入 Clone Allocator 概念是为了把指针容器控制所存对象 (而非指向所存对象的指针) 内存的方式形式化. 克隆分配器允许用户为克隆的对象应用自定义的分配器/释放器.

更多信息见下:

  • Clone Allocator 要求
  • 类 heap_clone_allocator
  • 类 view_clone_allocator

Clone Allocator 要求

记法

类型 对象 (const 或非 const) 描述
T a 一个类型
T* ptr 指向 T

有效表达式

表达式 类型 语义 后置条件
CloneAllocator::allocate_clone(a); T* 分配一个新对象, 可视为等价于对象 a typeid(*CloneAllocator::allocate_clone(a)) == typeid(a)
CloneAllocator::deallocate_clone(ptr); void 释放一个先前用 CloneAllocator::allocate_clone() 或兼容分配器分配的对象. 不得抛出异常.  

本库自带两个预定义的克隆分配器.

类 heap_clone_allocator

这是所有指针容器使用的默认克隆分配器. 对大多数用途而言, 你永远不必更改这一默认值.

定义

namespace boost
{        
    struct heap_clone_allocator
    {
        template< class U >
        static U* allocate_clone( const U& r )
        {
            return new_clone( r );
        }

        template< class U >
        static void deallocate_clone( const U* r )
        {
            delete_clone( r );
        }
    };
}

注意, 上面的定义允许你依靠 new_clone() 和 delete_clone() 来支持自定义分配方案.

类 view_clone_allocator

该类提供了一种移除指针容器所有权属性的方式. 顾名思义, 这意味着你可以把指针容器用作对既有容器的视图.

定义

namespace boost
{
    struct view_clone_allocator
    {
        template< class U >
        static U* allocate_clone( const U& r )
        {
            return const_cast<U*>(&r);
        }

        template< class U >
        static void deallocate_clone( const U* )
        {
            // empty
        }
    };
}

序列化

自 Boost 1.34.0 版起, 本库经由 Boost.Serialization 支持序列化.

当然, 要使序列化工作, 要求所存类型本身可序列化. 对于 map, 键类型和被映射类型都必须可序列化.

处理序列化时 (尤其是多态对象的序列化), 请特别注意 Boost.Serialization 的以下部分:

  1. 输出/保存要求 const 引用:

    //
// serialization helper: we can't save a non-const object
// 
template< class T >
inline T const& as_const( T const& r )
{
    return r;
}
...
Container cont;

std::ofstream ofs("filename");
boost::archive::text_oarchive oa(ofs);
oa << as_const(cont);

    详情参见 Compile time trap when saving a non-const value.

  1. 派生类需要调用 base_object() 函数:

    struct Derived : Base
{
    template< class Archive >
    void serialize( Archive& ar, const unsigned int version )
    {
        ar & boost::serialization::base_object<Base>( *this );
        ...
    }   
};

    详情参见 Derived Classes.

  1. 你需要使用 BOOST_CLASS_EXPORT 来在类层次结构中注册派生类:

    BOOST_CLASS_EXPORT( Derived )

    详情参见 Export Key 和 Object Tracking.

记住这三个问题, 也许能帮你省去一些麻烦.

类 nullable

该类的目的很简单: 告诉容器应允许空值. 其定义非常简单:

namespace boost
{
    template< class T >
    struct nullable
    {
        typedef T type;
    };  
}

请注意, nullable 对容器接口没有影响 (is_null() 函数除外). 例如, 下面这样的做法没有意义:

boost::ptr_vector< boost::nullable<T> > vec;
vec.push_back( 0 );                      // ok
vec.push_back( new boost::nullable<T> ); // no no!
boost::nullable<T>& ref = vec[0];        // also no no!

异常类

本库抛出三种异常. 异常层次结构如下:

namespace boost
{
    class bad_ptr_container_operation : public std::exception
    {
    public:
        bad_ptr_container_operation( const char* what );
    };
    
    class bad_index : public bad_ptr_container_operation
    {
    public:
        bad_index( const char* what );
    };

    class bad_pointer : public bad_ptr_container_operation
    {
    public:
        bad_pointer();
        bad_pointer( const char* what );
    };
}

禁用异常的使用

自 Boost 1.34.0 版起, 本库允许你完全禁用异常. 这意味着本库更适合不使用异常的领域. 此外, 这还能稍微加快操作速度. 本库不再抛出异常, 而是直接调用 BOOST_ASSERT.

要禁用异常, 只需在包含任何头文件之前定义这个宏:

#define BOOST_PTR_CONTAINER_NO_EXCEPTIONS 1
#include <boost/ptr_container/ptr_vector.hpp>

不过, 建议你在命令行上定义该宏, 这样你就能绝对确定所有头文件都以相同方式编译. 否则你最终可能违反单一定义规则 (One Definition Rule).

若定义了 BOOST_NO_EXCEPTIONS, 则 BOOST_PTR_CONTAINER_NO_EXCEPTIONS 也会被定义.
