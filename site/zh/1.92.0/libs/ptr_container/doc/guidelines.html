选择合适的容器

容器类的推荐使用模式与普通标准容器相同.

ptr_vector、ptr_list 和 ptr_deque 为程序员提供不同的复杂度权衡, 应据此选用. ptr_vector 是默认应使用的序列类型. ptr_list 适用于需要在序列中部频繁插入和删除、且容器相当大 (例如超过 100 个元素) 的场合. ptr_deque 适用于大多数插入和删除发生在序列开头或结尾的场合. 特殊容器 ptr_array 可在容器大小不变且编译期已知时使用.

关联容器若对每个键至多包含一个元素, 则支持唯一键; 否则支持等价键. ptr_set 和 ptr_map 支持唯一键. ptr_multiset 和 ptr_multimap 支持等价键.

面向对象编程的推荐实践

C++ 中的惯用面向对象编程与其他语言的做法略有不同. 部分原因在于 C++ 同时具有值语义和引用语义, 部分原因在于 C++ 比其他语言更灵活. 下面是一些建议遵循的推荐做法:

1. 让基类抽象且不含数据

这样做有以下优点:

  1. 它减少了耦合, 因为你不必维护或更新状态
  1. 它帮助你避免对象切片
  1. 它确保你重写 (override) 的是正确的函数

你或许还想阅读以下文章:

  • Kevlin Henney 的 Six of the best
  • Jack Reeves 的 Multiple Inheritance Considered Useful

2. 把虚函数设为私有, 并提供一个非虚的公有转发函数

用代码表示:

class Polymorphic
{
private:
    virtual int do_foo() = 0;
    
public:
    int foo()
    {
        return do_foo();
    }
    ...
};

这样做有以下优点:

  1. 它确保对虚函数的所有调用总是经过代码中的同一处
  1. 它使你能够在转发函数内部检查前置条件和后置条件

你或许还想阅读 Herb Sutter 的文章 Virtuality.

3. 让你的基类派生自 boost::noncopyable

拥有抽象基类可以在涉及基类时防止切片, 但不能防止层次结构中更下层的类的切片. 这正是 boost::noncopyable 派上用场的地方:

class Polymorphic : boost::noncopyable
{
  ...
};

4. 在容器中避免空指针 (如果可能)

默认情况下, 指针容器不允许你在其中存储空指针. 如你所知, 这一行为可以通过使用 boost::nullable 显式改变.

避免空指针的首要原因是: 每次使用容器时都必须检查空指针. 这种额外的检查很容易被遗忘, 而且与面向对象的精神有些矛盾 — 面向对象用动态分派取代特例处理.

然而, 你常常需要在容器中放置某个特殊对象, 因为你没有足够的信息来构造完整的对象. 此时你或许可以使用空对象模式, 它只要求你把抽象基类的虚函数实现为空函数或返回哑值. 这意味着你的面向对象代码仍然无需担心空指针.

你或许想阅读

  • Kevlin Henney 的 Null Object - Something for Nothing

最后, 你可能陷入连空对象都帮不上忙的境地. 那时你才真正需要 container< nullable<T> >.
