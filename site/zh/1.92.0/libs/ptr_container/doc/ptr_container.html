概述

Boost.Pointer Container 提供一些容器, 用于以异常安全的方式、以最小的开销保存堆上分配的对象. 本库的目标尤其在于, 通过为处理面向对象特有的问题建立一套标准的类、方法与设计, 使 C++ 中的面向对象编程更加容易

动机

每当程序员想要一个保存指向堆上分配对象的指针的容器时, 通常只有一种异常安全的方式: 使用 boost::shared_ptr 之类的智能指针容器. 以下情况中, 这种方式并非最优:

  1. 所存对象不是共享的, 而是独占拥有的; 或者
  1. 智能指针带来的开销不合适

因此, 本库提供类似标准的容器, 用于存储堆上分配的或克隆的对象 (对于 map, 被映射的对象必须是堆上分配或克隆的对象). 对每种标准容器, 都有一个等价的指针容器, 以异常安全的方式取得对象的所有权. 在这方面, 本库旨在解决所谓的多态类问题.

指针容器的优点有

  1. 异常安全的指针存储与操作.
  1. 与使用指针的容器相比在书写上更方便.
  1. 可用于既非可赋值 (Assignable) 也非可拷贝构造 (Copy Constructible) 的类型.
  1. 没有智能指针容器可能有的内存开销 (参见 [11] 和 [12]).
  1. 通常比使用智能指针容器更快 (参见 [11] 和 [12]).
  1. 接口略微向指针领域作了调整, 而不是依赖常规的基于值的接口. 例如, 现在 pop_back() 可以返回被移除的元素.
  1. 传播 const 性, 使得无法经由 const_iterator 修改对象.
  1. 内建深拷贝语义支持, 途径是Clonable 概念

缺点是

  1. 灵活性不如智能指针容器, 例如 boost::shared_ptr

当你确实需要共享语义时, 本库并非你所需要的.

升级: 自 Boost v. 1.33.*

如果你从 Boost 的这些版本升级, 会有一处重大接口变化: map 迭代器现在模拟 std::map 的迭代器. 以前你可能这样写

for( boost::ptr_map<std::string,T>::iterator i = m.begin(), e = m.end();
     i != e; ++i )
{
  std::cout << "key:" << i.key();
  std::cout << "value:" << *i;
  i->foo(); // call T::foo()
}

而现在需要改写为

for( boost::ptr_map<std::string,T>::iterator i = m.begin(), e = m.end();
     i != e; ++i )
{
  std::cout << "key:" << i->first;
  std::cout << "value:" << *i->second;
  i->second->foo(); // call T::foo()
}

除上述变化外, 本库现在还引入了

  • std::auto_ptr<T> 重载:

    std::auto_ptr<T> p( new T );
container.push_back( p );

  • transfer() 中的派生类到基类转换:

    boost::ptr_vector<Base>  vec;
boost::ptr_list<Derived> list;
...
vec.transfer( vec.begin(), list ); // now ok

另请注意, Boost.Assign 为指针容器提供了更好的支持.

升级: 自 Boost v. 1.34.*

感谢 Sebastian Ramacher, 序列化现在成为可选功能. 你只需包含 <boost/ptr_container/serialize.hpp>, 或者也许只包含某个更专门的头文件.

所有容器现在都可拷贝构造和可赋值. 例如现在可以:

boost::ptr_vector<Derived> derived = ...;
boost::ptr_vector<Base>    base( derived );
base = derived;

如示例所示, 也允许派生类到基类的转换.

新增了几个通用函数:

VoidPtrContainer&       base();
const VoidPtrContainer& base() const;

它们允许直接访问被包装的容器, 当你想提供额外功能时有时会需要这样.

为序列新增了几个函数:

void resize( size_type size );
void resize( size_type size, T* to_clone );

ptr_vector<T> 新增了几个辅助函数, 以便与 C 数组更好地配合:

void transfer( iterator before, T** from, size_type size, bool delete_from = true );
T**  c_array();

最后, 现在还可以通过调用 move() 来 "拷贝" 和 "赋值" 一个 auto_type 指针:

boost::ptr_vector<T>::auto_type move_ptr = ...;
return boost::ptr_container::move( move_ptr );

升级: 自 Boost v. 1.35.*

本库已相当稳定, 但又支持了几个新容器:

  • boost::ptr_unordered_set<T>, 位于 <boost/ptr_container/ptr_unordered_set.hpp>
  • boost::ptr_unordered_map<Key,T>, 位于 <boost/ptr_container/ptr_unordered_map.hpp>
  • boost::ptr_circular_buffer<T>, 位于 <boost/ptr_container/ptr_circular_buffer.hpp>

这些类尚无文档, 但它们分别与 boost::ptr_set<T>、boost::ptr_map<Key,T> 和 boost::ptr_array<T,N> 几乎完全相同. 其底层容器来自以下两个 Boost 库

  • Boost.Unordered
  • Boost.Circular Buffer

此外, 还增加了插入迭代器.

升级: 自 Boost v. 1.66.*

自 Boost v. 1.67.0 起, Boost.Pointer Container 将使用 Boost.Config 有条件地提供基于 std::unique_ptr 的接口, 作为使用 std::auto_ptr 的接口的补充或替代. 详情见 Compatible Smart Pointer 页面, 该页面还解释了本文档中使用

compatible-smart-ptr<T>

来表示这类条件接口的约定.

对 C++98/03 用户而言, 这一变化没有可观察到的影响.

对 C++11/14 用户而言, 对使用先前版本 Boost.Pointer Container 的既有代码没有影响, 但现在所有接受 std::auto_ptr 形参的函数重载都伴随着接受 std::unique_ptr 的重载. 至于返回类型, 仍始终使用 std::auto_ptr. 但请注意, 直到 C++17 之前, 都可以从 std::auto_ptr<T> 隐式构造 std::unique_ptr<T>. 因此, 用户可以自由地把代码中任何对 std::auto_ptr 的显式提及替换为 std::unique_ptr, 以使其代码现代化. 这一改动差一点就是查找替换式的转换, 因为某些代码可能曾依赖 std::auto_ptr 可拷贝这一事实. 但这类情形会导致编译期错误, 应当很容易修复.

尽管 std::auto_ptr 已自 ISO C++17 起被正式移除, 某些编译器或标准库供应商出于向后兼容的考虑选择保留它. 对于未保留它的编译器和标准库, 使用 Boost v. 1.66.* 或更早版本时, 使用 Boost.Pointer Container 的代码无法以 C++17 编译. 这一情况自 Boost v. 1.67.0 起已得到修复.

后续开发

有迹象表明, 与基于 T* 的实现相比, void* 实现有轻微的性能开销. 此外, 基于 T* 的实现在配合算法进行类型安全使用时要容易得多. 因此我预计会迁移到基于 T* 的实现.

此外, 克隆分配器或许可以允许拥有状态. 这一设计还需要一些思考, 所以如果你对此有好的想法和使用场景, 请不要犹豫与我联系.

另外, 对 Boost.Interprocess 的支持已在待办清单上.

有一些对 boost::ptr_multi_index_container<T,...> 的请求. 我调查了实现的难度, 结果确实比较困难, 尽管并非不可能. 但未来数年内我都没有资源来实现这个庞然大物, 所以如果有人真的需要这个容器, 我建议私下与我谈谈如何实现.
