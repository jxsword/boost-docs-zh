指针容器库

约定

有一些设计决策会影响这些类的使用方式. 除此之外, 这些类与普通标准容器非常相似, 并提供几乎相同的接口. 新的约定如下:

  • 默认不允许空指针
  • 所有默认迭代器都多应用一层间接
  • 所有比较操作都在被指对象上进行, 而不是在指针层面
  • 对于一部分操作, 要求存储的元素可克隆 (Cloneable)
  • 凡对象被插入容器, 都会在插入前先克隆
  • 凡指针被插入容器, 所有权即转移给容器
  • 所有权可以按单个指针为单位从容器转移出去
  • 所有权可以按迭代器范围为单位从一个容器转移到另一个容器
  • 容器可以从函数中廉价返回, 途径是克隆一份或放弃容器的所有权
  • 迭代器的失效方式与对应的标准容器相同

默认不允许空指针

如果用户试图插入空指针, 该操作将抛出 bad_pointer 异常 (参见 示例 1).

使用 nullable 以允许空指针.

请注意, 所有形如下述形式的前置条件

x != 0;

当你以 nullable<T> 实例化容器 (如下所示) 时, 它们并不生效

boost::ptr_vector< boost::nullable<animal> > vec;
vec.push_back( 0 ); // ok

所有默认迭代器都多应用一层间接

这样做是为了让容器更易用、更安全. 它推崇一种 "无指针式" 编程风格, 类的使用者无需关心指针, 只需在分配指针时留意 (参见 示例 2). 由于在极少数情况下可能有用, 库也提供了访问裸指针的迭代器. 例如, begin() 返回一个迭代器时, ptr_begin() 会返回一个可用于遍历所存指针的迭代器.

所有比较操作都在被指对象上进行, 而不是在指针层面

例如, 在 ptr_set<T> 中, 排序默认由 boost::ptr_less<T> 完成, 它比较的是指针间接所指的对象. 类似地, operator==() 对于 container<Foo> 而言, 会用 operator==(const Foo&, const Foo&) 比较所有对象.

对于一部分操作, 要求存储的元素可克隆 (Cloneable)

这是因为大多数多态对象无法直接拷贝, 但通常可以通过某个成员函数来拷贝 (参见 示例 4). 而克隆对象常常根本没有意义, 此时大部分操作仍然可用.

凡对象被插入容器, 都会在插入前先克隆

这是必要的, 因为所有指针容器都取得所存对象的所有权 (参见 示例 5).

凡指针被插入容器, 所有权即转移给容器

所有容器都取得所存指针的所有权, 因此容器需要拥有自己的副本 (参见 示例 5).

所有权可以按单个指针为单位从容器转移出去

这当然也带来了便利. 每当发生这种情况, 都会使用一个 SmartContainer::auto_type 对象来提供异常安全的转移 (参见 示例 6).

所有权可以按迭代器范围为单位从一个容器转移到另一个容器

这使得可以在不同指针容器之间安全地交换数据, 而无需再次克隆对象 (参见 示例 7).

容器可以从函数中廉价返回, 途径是克隆一份或放弃容器的所有权

两个特殊的成员函数 clone() 和 release() 都返回一个 compatible-smart-ptr<SmartContainer>, 它可以赋给另一个指针容器. 这实际上把返回容器的开销降低为一次堆分配外加一次 swap() 调用 (参见 示例 3).

迭代器的失效方式与对应的标准容器相同

由于本库的容器是对标准容器的封装, 迭代器失效的规则与相应标准容器的规则相同.

例如, 对 boost::ptr_vector<T> 和 std::vector<U> 而言, 插入和删除只会使被删除的元素及其后的元素失效; 被插入/删除元素之前的所有元素仍然有效.
