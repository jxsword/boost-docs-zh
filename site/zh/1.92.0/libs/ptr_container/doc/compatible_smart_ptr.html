指针容器库

兼容智能指针类型

在接口中指定形参或返回类型时, 本库的文档使用伪类型

compatible-smart-ptr<T>

来表示: 编译器所支持的 C++ 标准被用来有选择地提供或移除接受 std::auto_ptr<T> 或 std::unique_ptr<T> 的接口. 其确切含义视智能指针类型是形参类型还是返回类型而定.

形参类型:

诸如这样的接口

void container::push_back( compatible-smart-ptr<T> );

表示 container::push_back 存在接受 std::auto_ptr<T> 和/或 std::unique_ptr<T> 的重载; Boost.Pointer Container 为编译器支持的每种类型都提供重载. 完全明确地说: 若编译器提供 std::auto_ptr, 则

void container::push_back( std::auto_ptr<T> );

存在. 若编译器提供 std::unique_ptr, 则

void container::push_back( std::unique_ptr<T> );

存在. 若两者都提供, 则两个重载都存在.

在实践中, 这意味着 C++98/03 用户可以使用 std::auto_ptr 重载; C++11/14 用户可以使用同时接受 std::auto_ptr 和 std::unique_ptr 的重载; 而 C++17 及以后的用户只能使用 std::unique_ptr 重载.

上述约定意味着, 在某些情况下文档会引用一个接受兼容智能指针伪形参的单一函数, 而实际上存在两个不同的重载函数. 当然, 实际接口取决于编译器设置, 因此为清晰起见, 类层次结构参考将始终只提及单一函数.

返回类型:

返回类型的情形按与形参类型相同的思路处理, 当然要受限于 C++ 函数不能按返回类型重载这一约束. 因此, 诸如这样的接口

compatible-smart-ptr<T> container::release( );

表示 std::auto_ptr<T> 或 std::unique_ptr<T> 中恰好一个被用作返回类型. 若编译器提供 std::auto_ptr<T>, 则

std::auto_ptr<T> container::release( );

存在, 即使编译器也提供 std::unique_ptr. 对于只提供 std::unique_ptr 的编译器, 上述接口变为

std::unique_ptr<T> container::release( );

在实践中, 这意味着对 C++98/03/11/14 用户而言, 这类返回类型总是 std::auto_ptr; 对 C++17 及以后的用户而言, 返回类型是 std::unique_ptr.

细节:

ISO C++11 标准增加了智能指针类模板 std::unique_ptr, 并随之正式弃用了 std::auto_ptr. 在经历 C++11 和 C++14 的弃用状态之后, std::auto_ptr 已自 ISO C++17 标准起被正式移除. 因此, 提及 std::auto_ptr 的头文件, 在使用 C++17 或更新标准且标准库实现禁用了 std::auto_ptr 的情况下可能无法使用. Boost.Pointer Container 的诞生早于 std::unique_ptr 的出现, 并且自 Boost v. 1.34 起就为其接口提供了 std::auto_ptr 重载. 为了跨一系列 C++ 标准提供兼容性, 库中使用宏在编译期对 std::auto_ptr 接口进行重载或替换为 std::unique_ptr 接口.

Boost.Config 定义了宏 BOOST_NO_CXX11_SMART_PTR (用于 std::unique_ptr 不可用的编译器), 以及宏 BOOST_NO_AUTO_PTR (用于 std::auto_ptr 被移除 (或有缺陷) 的编译器). 这些宏用于在编译期依据形参和返回类型选择接口. 对于接受智能指针形参的接口, Boost.Pointer Container 相互独立地使用 BOOST_NO_AUTO_PTR 和 BOOST_NO_CXX11_SMART_PTR, 以提供接受 std::auto_ptr 和/或 std::unique_ptr 作为形参的接口. 对于以智能指针作为返回类型的接口, 先使用 Boost.Config 宏检查 std::auto_ptr 是否可用, 仅为提供 std::unique_ptr 但不提供 std::auto_ptr 的编译器提供 std::unique_ptr 作为返回类型.

因此, 所有对

compatible-smart-ptr<T>

的提及都应理解为: Boost.Config 已按上述方式使用, 以提供与编译器设置兼容的智能指针接口.
