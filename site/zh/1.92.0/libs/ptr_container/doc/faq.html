调用 assign() 的代价很高, 而我其实不需要存储克隆的对象; 我只需要覆盖既有的对象; 该怎么办?

调用 std::copy( first, last, c.begin() );.

哪些会改动元素顺序的算法可以安全地用于指针?

任何通过交换来移动元素的会改动元素顺序的算法. 一个重要的例子是 std::sort(); 不安全算法的例子有 std::unique() 和 std::remove().

为什么 ptr_map<T>::insert()/replace() 接受两个实参 (键和指针) 而不是一个 std::pair? 为什么键以非 const 引用传递?

这是该函数能以异常安全方式实现的唯一途径; 由于键的拷贝构造函数可能抛出异常, 且函数实参不保证从左到右求值, 我们需要确保对第一个实参的求值不会抛出异常. 以引用传递键正好能做到这一点.

用类型 T 实例化指针容器时, T 在该处允许是不完整类型吗?

不能. 这是 shared_ptr 的独特性质, 它意味着一定的开销.

不过, 可以让 T 在头文件中保持不完整:

// foo.hpp
class Foo { ... };
new_clone( const Foo& ) { ... }
delete_clone( const Foo* )     { ... }

// x.hpp
class Foo; // Foo is incomplete here
class X { ptr_deque<Foo> container; ... }

// x.cpp
#include <x.hpp>
#include <foo.hpp> // now Foo is not incomplete anymore
...

为什么迭代器范围的插入能提供强异常安全保证?

这难道不是很低效吗? 之所以这样做, 是因为它实际上是可以承受的; 开销只是一次堆分配, 相对于克隆 N 个对象而言相当小.

什么是多态类问题?

该问题指的是 C++ 在涉及指向多态对象的指针容器时对面向对象编程支持得较为麻烦这一情况. 在没有垃圾回收的语言中, 你最终要么使用智能指针的容器, 要么使用取得指针所有权的容器. 困难之处在于找到一个安全、快速且优雅的解决方案.

指针容器是否比智能指针容器更快、内存占用更优?

简短的回答是肯定的: 它们更快, 内存占用也更少; 事实上, 它们是获得 C++ 零开销美名的唯一途径. 智能指针通常每个指针有一字或更多的内存开销, 因为必须维护引用计数. 而既然必须维护引用计数, 也就存在运行期开销. 如果你的对象很大, 内存开销往往可以忽略; 但如果你有很多小对象, 情况就不同了. 延伸阅读见这些文献: [11] 和 [12].

当存储的指针不能为 0 时, 我该如何允许这种 "空" 行为?

在一列指针中存储空指针并不符合面向对象范式. 最优雅的设计是使用空对象模式 (Null-Object Pattern), 即基本上实现一个具体类, 其虚函数为哑实现. 详情参见 [13].
