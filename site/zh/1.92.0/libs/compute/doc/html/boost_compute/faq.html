支持哪些计算设备 (如 GPU)?

任何实现了 OpenCL 标准的设备都受支持, 包括 NVIDIA、AMD 和 Intel 的 GPU, AMD 和 Intel 的 CPU, 以及 Xeon Phi 等其他加速卡.

能否把 Boost.Compute 与 Thrust、Bolt 和 VexCL 等其他 GPGPU 库做个比较?

Thrust 为 GPU 与 CPU 实现了类 STL 的 C++ API, 并以多个后端构建. NVIDIA GPU 使用 CUDA 后端, 多核 CPU 可使用 Intel TBB 或 OpenMP 后端. 但 Thrust 无法在 AMD 显卡或其他知名度较低的加速器上工作. 我认为 Boost.Compute 的优势在于它使用厂商中立的 OpenCL 库, 从而在所有类型的计算设备上获得可移植性.

Bolt 是 AMD 专用的 OpenCL API C++ 封装, 它扩展了基于 C99 的 OpenCL 语言以支持 C++ 特性 (最显著的是模板). 它与 NVIDIA 的 Thrust 库类似, 也有着同样的不足: 缺乏可移植性.

VexCL 是一个基于表达式模板的 OpenCL 线性代数库, 其目标与范围和 Boost Compute 库略有不同. VexCL 在本质上更接近 Eigen 库, 而 Boost.Compute 更接近 C++ 标准库. 我认为 Boost.Compute 与 VexCL 并不扮演完全相同的角色. 事实上, VexCL 近来的版本允许将 Boost.Compute 用作其后端之一, 这使得两个库之间的协作变得轻而易举.

另请参阅这个 StackOverflow 问题: http://stackoverflow.com/questions/20154179/differences-between-vexcl-thrust-and-boost-compute

为什么不直接为 Thrust 编写一个新的 OpenCL 后端?

无法为 OpenCL 提供 Thrust 所期望的同一 API. 根本原因在于, 传递给 Thrust 算法的函数/函数对象是实际编译好的 C++ 函数, 而对 Boost.Compute 而言, 这些构成表达式对象, 随后被翻译成 C99 代码, 再由 OpenCL 编译.

为什么不以 CUDA 为目标并/或支持多个后端?

CUDA 与 OpenCL 是两种截然不同的技术. OpenCL 的工作方式是在运行期编译 C99 代码来生成内核对象, 随后在 GPU 上执行; 而 CUDA 的工作方式是使用专用编译器 (nvcc) 编译其内核, 生成可在 GPU 上执行的二进制文件.

OpenCL 已经有多个实现, 使其可用于各种平台 (如 NVIDIA GPU、Intel CPU 等). 我认为在 Boost.Compute 内部再增加一个抽象层只会让库更复杂、更臃肿.

能否在 Boost.Compute 中使用普通的 C++ 函数/函数对象或 C++11 lambda?

遗憾的是不能. OpenCL 依赖在运行期可用的 C99 源代码才能在 GPU 上执行代码. 因此, 已编译的 C++ 函数或 C++11 lambda 无法简单地传入 OpenCL 环境在 GPU 上执行.

这正是我编写 Boost.Compute lambda 库的原因. 它基本上是把 C++ lambda 表达式 (如 _1 * sqrt(_1) + 4) 转换成 C99 源代码片段 (如 "input[i] * sqrt(input[i]) + 4)"), 然后交给 Boost.Compute 的 STL 风格算法执行. 虽然并不完美, 但它让用户能够编写更接近 C++ 的代码, 且仍可通过 OpenCL 执行.

另请查看 BOOST_COMPUTE_FUNCTION() 宏, 它允许在 C++ 代码中内联定义 OpenCL 函数. 示例可参见 monte_carlo 示例代码.

出现在所有算法中的 command_queue 参数是什么?

命令队列指定算法执行所用的上下文与设备. 对所有标准算法而言, command_queue 参数是可选的. 若未提供, 将为默认 GPU 设备创建一个默认 command_queue, 算法将在那里执行.

如何打印 GPU 上缓冲区/向量的内容?

使用通用的 boost::compute::copy() 算法配合 std::ostream_iterator<T> 即可轻松完成. 例如:

std::cout << "vector: [ ";
boost::compute::copy(
    vector.begin(), vector.end(),
    std::ostream_iterator<int>(std::cout, ", "),
    queue
);
std::cout << "]" << std::endl;

Boost.Compute 支持零拷贝内存吗?

零拷贝内存允许 OpenCL 内核直接操作主机内存区域 (如果平台支持).

Boost.Compute 以多种方式支持零拷贝内存. 底层接口通过分配 buffer 对象并以 CL_MEM_USE_HOST_PTR 标志提供. 高层接口由 mapped_view<T> 类提供, 它为主机内存区域提供类似 std::vector 的接口, 并可直接与所有 Boost.Compute 算法配合使用.

Boost.Compute 是线程安全的吗?

Boost.Compute 的底层 API 提供与底层 OpenCL 库实现相同的线程安全保证. 但高层 API 使用了若干全局静态对象来实现自动程序缓存等特性, 因此默认不是线程安全的.

要以线程安全模式编译 Boost.Compute, 请在包含任何 Boost.Compute 头文件之前定义 BOOST_COMPUTE_THREAD_SAFE. 默认情况下这要求你的应用/库与 Boost.Thread 库链接.
