注释

递归内联函数

把 at 这类函数应用于 前向序列 (例如 list) 时, 有一个有趣的特性: 本可能是线性运行期复杂度的操作, 由于编译器对 C++ 内联函数的优化, 无论递归多深 (当然受编译器的一定限制), 实际上都变成常数 O(1). 编译期复杂度仍保持线性.

重载函数

关联序列使用函数重载来实现成员测试和类型关联的键查找. 这相当于常数运行期复杂度和均摊常数编译期复杂度. 存在一个重载函数 f(k), 对应每个键 type k. 给定键 k, 编译器会选择适当的函数.

标签分派

标签分派是一种用于选择模板特化的泛型编程技术. 标签分派机制通常涉及 3 个组成部分:

  1. 一个需要适当模板特化的类型
  2. 一个把该类型与标签类型关联起来的元函数
  3. 一个针对标签类型进行特化的模板

例如, fusion 的 result_of::begin 元函数实现如下:

template <typename Sequence>
struct begin
{
    typedef typename
        result_of::begin_impl<typename traits::tag_of<Sequence>::type>::
        template apply<Sequence>::type
    type;
};

在此情形中:

  1. Sequence 是这样的类型: 需要为它提供 result_of::begin_impl 的适当实现
  2. traits::tag_of 是把 Sequence 与适当标签关联起来的元函数
  3. result_of::begin_impl 是被特化来为每个标签类型提供实现的模板

可扩展性

与 MPL 不同, fusion 中没有可扩展序列概念. 这并不意味着 Fusion 序列不可扩展. 事实上, 所有 Fusion 序列天然都是可扩展的. 只是由于 fusion 算法 的惰性本质, Fusion 中序列扩展的方式与 STL 和 MPL 都不同. STL 容器通过 push_back 和 insert 等成员函数就地扩展自身. 而 MPL 序列则通过实际返回完整序列的"内蕴"函数来扩展. MPL 是纯函数式的, 不能有副作用. 例如, MPL 的 push_back 并不会实际修改一个 mpl::vector. 它做不到. 相反, 它返回一个扩展后的 mpl::vector.

与 MPL 一样, Fusion 也是纯函数式的, 不能有副作用. 出于运行期效率的考虑, Fusion 序列通过返回 视图 的泛型函数来扩展. 视图 是并不实际包含数据的序列, 而是对来自一个或多个底层序列的数据提供另一种呈现. 视图 是代理. 它们为可能代价高昂的序列操作提供了一种高效而纯函数式的处理方式. 例如, 给定一个 vector, Fusion 的 push_back 返回一个 joint_view, 而不是实际扩展后的 vector. 一个 joint_view 持有对原序列的引用以及追加的数据 —— 这使它传递起来非常廉价.

元素转换

接收基本值以构成序列的函数 (例如 make_list) 会把其实参转换为适合作为序列元素存储的形式. 一般而言, 元素类型以普通值存储. 示例:

make_list(1, 'x')

返回一个 list<int, char>.

但也有少数例外.

数组:

数组实参被推导为 const 引用类型. 例如 [14]:

make_list("Donald", "Daisy")

创建一个类型为如下所示的 list 

list<const char (&)[7], const char (&)[6]>

函数指针:

函数指针被推导为普通非引用类型 (即普通函数指针). 示例:

void f(int i);
  ...
make_list(&f);

创建一个类型为如下所示的 list 

list<void (*)(int)>

引用包装器

Fusion 的生成函数 (例如 make_list) 默认把元素类型存储为普通非引用类型. 示例:

void foo(const A& a, B& b) {
    ...
    make_list(a, b)

创建一个类型为如下所示的 list 

list<A, B>

有时并不希望使用普通非引用类型. 你可以改用 boost::ref 和 boost::cref 来存储引用或 const 引用 (分别对应). 该机制不会破坏 const 正确性, 因为用 ref 包装的 const 对象会产生 const 引用类型的元组元素 (见下面第五行代码). 示例:

例如:

A a; B b; const A ca = a;
make_list(cref(a), b);          // creates list<const A&, B>
make_list(ref(a), b);           // creates list<A&, B>
make_list(ref(a), cref(b));     // creates list<A&, const B&>
make_list(cref(ca));            // creates list<const A&>
make_list(ref(ca));             // creates list<const A&>

详情参见 Ref utility.

自 C++11 起, 标准引用包装器 (std::ref 和 std::cref) 也可以使用.

adt_attribute_proxy

要适配不允许直接访问其成员、但允许通过表达式 (例如 get 和 set 方法的调用) 间接访问的任意数据类型, 可以使用 fusion 的 BOOST_FUSION_ADAPT_xxxADTxxx 家族 (例如 BOOST_FUSION_ADAPT_ADT). 由于表示 fusion 序列元素的并非真正的左值, 而是访问元素的成对表达式序列, 为绕过这一限制, fusion 内蕴序列访问函数 (at、at_c、at_key、deref 和 deref_data) 的实际返回类型是一个代理类型, 即 adt_attribute_proxy 的实例, 它封装了这些表达式.

adt_attribute_proxy 定义在命名空间 boost::fusion::extension 中, 并有三个模板参数:

namespace boost { namespace fusion { namespace extension
{
    template<
        typename Type
      , int Index
      , bool Const
    >
    struct adt_attribute_proxy;
}}}

适配类类型时, 会为被适配序列的每个元素特化 adt_attribute_proxy, 其中 Type 是被适配的类类型, Index 是元素的从 0 开始的索引, Const 同时是 true 和 false. 对被适配类类型的第 N 个元素 (类类型为 type_name), fusion 内蕴序列访问函数的返回类型是 adt_attribute_proxy<type_name, N, Const>, 其中 Const 为 true (当 type_name 是常量实例时) 或 false (当其为非常量实例时).

记法约定

type_name

要适配的类型, 具有 M 个属性

inst

type_name 类型的对象

const_inst

type_name const 类型的对象

(attribute_typeN, attribute_const_typeN, get_exprN, set_exprN)

第 N 个属性的属性描述符, 该属性属于传给适配宏的 type_name, 0≤N<M

proxy_typeN

adt_attribute_proxy<type_name, N, false>, 其中 N 为整型常量, 0≤N<M

const_proxy_typeN

adt_attribute_proxy<type_name, N, true>, 其中 N 为整型常量, 0≤N<M

proxyN

proxy_typeN 类型的对象

const_proxyN

const_proxy_typeN 类型的对象

表达式语义

表达式

语义

proxy_typeN(inst)

创建一个 proxy_typeN 的实例, 其底层对象为 inst

const_proxy_typeN(const_inst)

创建一个 const_proxy_typeN 的实例, 其底层对象为 const_inst

proxy_typeN::type

attribute_typeN 的另一个名称

const_proxy_typeN::type

const_attribute_typeN 的另一个名称

proxyN=t

调用 set_exprN, 其中 t 是任意对象. set_exprN 可以访问名为 obj 的变量, 其类型为 type_name&, 表示 type_name 的对应实例; 以及名为 val 的变量, 其类型为任意 const 限定引用模板类型参数 Val, 表示 t.

proxyN.get()

调用 get_exprN 并转发其返回值. get_exprN 可以访问名为 obj 的变量, 其类型为 type_name&, 表示 type_name 的底层实例. attribute_typeN 可指定 get_exprN 所指代的类型.

const_proxyN.get()

调用 get_exprN 并转发其返回值. get_exprN 可以访问名为 obj 的变量, 其类型为 type_name const&, 表示 type_name 的底层实例. attribute_const_typeN 可指定 get_exprN 所指代的类型.

此外, proxy_typeN 和 const_proxy_typeN 可拷贝构造、可拷贝赋值, 并可隐式转换为 proxy_typeN::type 或 const_proxy_typeN::type.

提示

为避免代理类型的陷阱, 也可以使用 fusion 的 内蕴扩展机制 直接适配任意类类型.


[14] 注意, 字符串字面量的类型是 const 字符的数组, 而不是 const char*. 要让 make_list 创建一个含有非常量数组类型元素的 list, 必须使用 ref 包装器 (参见 Reference Wrappers).
