完整扩展机制

Fusion 库设计为可扩展的, 可以方便地添加新的序列类型. 事实上, 库对 std::pair、boost::array 和 MPL 序列的支持完全是通过扩展机制提供的.

向 Fusion 添加新序列类型的过程是:

  1. 为你的序列类型启用 Fusion 所使用的 标签分派 机制
  2. 为该序列设计一个迭代器类型
  3. 为新 Fusion 序列的内蕴操作提供特化行为
我们的示例

为了演示启用一个新序列类型以配合 Fusion 使用, 我们将使用如下类型:

namespace example
{
    struct example_struct
    {
        std::string name;
        int age;
        example_struct(
            const std::string& n,
            int a)
            : name(n), age(a)
        {}
    };
}

我们将假定该类型由第三方库提供, 因而不能修改. 我们将完整走完所有必要步骤, 使 example_struct 能够按照 快速入门 指南的描述充当一个 关联序列.

启用标签分派

Fusion 扩展机制使用 标签分派 为给定序列类型调用正确的代码. 为了利用标签分派机制, 我们必须首先为该机制声明一个新的标签类型. 例如:

namespace example {
    struct example_sequence_tag; // Only definition needed
}

接下来, 我们需要启用 traits::tag_of 元函数, 使其在涉及我们序列的操作中返回我们新选定的标签类型. 这通过为我们的序列类型特化 traits::tag_of 来完成.

#include <boost/fusion/support/tag_of_fwd.hpp>
#include <boost/fusion/include/tag_of_fwd.hpp>

namespace boost { namespace fusion { namespace traits {
    template<>
    struct tag_of<example_struct>
    {
        typedef example::example_sequence_tag type;
    };
}}}

traits::tag_of 还有第二个模板实参, 可与 boost::enable_if 结合使用, 为一组相关类型提供标签支持. 该特性对我们的序列并非必需, 但示例代码参见:

#include <boost/fusion/adapted/array/tag_of.hpp>
#include <boost/fusion/include/tag_of.hpp>
设计合适的迭代器

我们需要一个迭代器来描述位置并提供对序列内数据的访问. 由于这很简单, 我们将在示例中提供一个随机访问迭代器.

我们将使用一个简单的设计: example_struct 的 2 个成员分别赋予编号索引, name 为 0, age 为 1.

template<typename Struct, int Pos>
struct example_struct_iterator
    : boost::fusion::iterator_base<example_struct_iterator<Struct, Pos> >
{
    BOOST_STATIC_ASSERT(Pos >=0 && Pos < 3);
    typedef Struct struct_type;
    typedef boost::mpl::int_<Pos> index;
    typedef boost::fusion::random_access_traversal_tag category;

    example_struct_iterator(Struct& str)
        : struct_(str) {}

    Struct& struct_;
};

我们的迭代器细节概要如下:

  1. 该迭代器以其所遍历的类型和当前元素的索引为模板参数.
  2. typedef struct_type 和 index 提供了对实现后续所需信息的便捷访问.
  3. typedef category 使 traits::category_of 元函数能够确定该迭代器的遍历类别.
  4. 构造函数保存对正在被遍历的 example_struct 的引用.

我们还需要为我们的迭代器类型启用 标签分派, 即对 traits::tag_of 做另一个特化.

孤立地看, 迭代器的实现相当枯燥. 随着我们为实现添加功能, 一切会逐渐清晰起来.

最初的几个有启发性的功能

首先, 我们要让 result_of::value_of 元函数工作起来. 为此, 我们为迭代器的标签类型提供 boost::fusion::extension::value_of_impl 模板的一个特化.

template<>
struct value_of_impl<example::example_struct_iterator_tag>
{
    template<typename Iterator>
    struct apply;

    template<typename Struct>
    struct apply<example::example_struct_iterator<Struct, 0> >
    {
        typedef std::string type;
    };

    template<typename Struct>
    struct apply<example::example_struct_iterator<Struct, 1> >
    {
        typedef int type;
    };
};

实现本身相当简单, 它只是根据迭代器的索引, 用 2 个部分特化来提供 example_struct 的 2 个不同成员的类型.

要理解库如何使用 value_of_impl, 我们来看一下 result_of::value_of 的实现:

template <typename Iterator>
struct value_of
    : extension::value_of_impl<typename detail::tag_of<Iterator>::type>::
        template apply<Iterator>
{};

所以 result_of::value_of 使用 标签分派 选择一个 MPL 元函数类 来提供其功能. 在 Fusion 的整个实现中你都会注意到这种模式.

好, 现在让我们启用迭代器的解引用. 此时我们必须提供 deref_impl 的一个适当特化.

template<>
struct deref_impl<example::example_struct_iterator_tag>
{
    template<typename Iterator>
    struct apply;

    template<typename Struct>
    struct apply<example::example_struct_iterator<Struct, 0> >
    {
        typedef typename mpl::if_<
            is_const<Struct>, std::string const&, std::string&>::type type;

        static type
        call(example::example_struct_iterator<Struct, 0> const& it)
        {
            return it.struct_.name;
        }
    };

    template<typename Struct>
    struct apply<example::example_struct_iterator<Struct, 1> >
    {
        typedef typename mpl::if_<
            is_const<Struct>, int const&, int&>::type type;

        static type
        call(example::example_struct_iterator<Struct, 1> const& it)
        {
                return it.struct_.age;
            }
        };
    };
}

deref_impl 的用法与 value_of_impl 非常相似, 但这次它还通过 call 静态成员函数提供了一些运行期功能. 要了解 deref_impl 的用法, 让我们看一下 deref 的实现:

namespace result_of
{
    template <typename Iterator>
    struct deref
        : extension::deref_impl<typename detail::tag_of<Iterator>::type>::
            template apply<Iterator>
    {};
}

template <typename Iterator>
typename result_of::deref<Iterator>::type
deref(Iterator const& i)
{
    typedef result_of::deref<Iterator> deref_meta;
    return deref_meta::call(i);
}

同样, result_of::deref 使用 标签分派 的方式与 result_of::value_of 的实现完全相同. deref 所用的运行期功能由所选 call 静态函数提供, 该函数来自 MPL 元函数类.

deref_impl 的实际实现比 value_of_impl 略复杂一些. 我们还需要实现 call 函数, 它返回对底层序列相应成员的引用. 若底层序列为 const, 我们还需要一点元编程来返回 const 引用.

注释

虽然要产生一个功能完备的 Fusion 序列还有相当多的工作要做, 但 result_of::value_of 和 deref 已展示了所需的全部重要概念. 其余过程非常重复, 只需为每个特性实现一个合适的 xxxx_impl xxxx.

实现其余的迭代器功能

好, 现在我们已经了解了 result_of::value_of 和 deref 的工作方式, 其余的一切都会以几乎相同的方式工作. 让我们从向前迭代开始, 提供一个 next_impl:

template<>
struct next_impl<example::example_struct_iterator_tag>
{
    template<typename Iterator>
    struct apply
    {
        typedef typename Iterator::struct_type struct_type;
        typedef typename Iterator::index index;
        typedef example::example_struct_iterator<struct_type, index::value + 1> type;

        static type
        call(Iterator const& i)
        {
             return type(i.struct_);
        }
    };
};

这与我们的 deref_impl 实现非常相似, 我们此后会反复使用这种方法. 我们的设计只是递增 index 计数器以移到下一个元素. 我们需要执行的其他各种迭代器操作都只涉及对 index 变量的简单计算.

我们还需要提供合适的 equal_to_impl, 使迭代器能够被正确比较. 双向迭代器 还需要实现 prior_impl. 对于 随机访问迭代器, 还需提供 distance_impl 和 advance_impl 以满足必要的复杂度保证. 由于我们的迭代器是 随机访问迭代器, 我们必须实现所有这些函数.

示例代码中提供了 prior_impl、advance_impl、distance_impl 和 equal_to_impl 的完整实现.

实现序列的内蕴函数

为了使 Fusion 能把我们的序列正确识别为 Fusion 序列, 我们需要为序列类型启用 is_sequence. 照例, 我们只需为我们的序列标签创建一个特化的 impl 类型:

template<>
struct is_sequence_impl<example::example_sequence_tag>
{
    template<typename T>
    struct apply : mpl::true_ {};
};

我们还有一些类似的例行手续要完成: 提供 category_of_impl 使 Fusion 能正确识别我们的序列类型, 以及 is_view_impl 使 Fusion 能正确识别我们的序列不是 视图 类型. 实现已在示例代码中给出.

现在我们完成了一些例行手续, 接下来是更有趣的功能. 让我们让 begin 工作起来, 以便获得一个迭代器来开始访问序列中的数据.

template<>
struct begin_impl<example::example_sequence_tag>
{
    template<typename Sequence>
    struct apply
    {
        typedef example::example_struct_iterator<Sequence, 0> type;

        static type
        call(Sequence& seq)
        {
            return type(seq);
        }
    };
};

该实现使用了我们一贯采用的相同思路, 此处我们只是创建我们先前开发的其中一个迭代器, 指向序列中的第一个元素. end 的实现非常相似, 已在示例代码中给出.

对于我们的 随机访问序列, 我们还需要实现 size_impl、value_at_impl 和 at_impl.

启用我们的类型作为关联序列

为了使 example_struct 能够充当关联前向序列, 我们需要相应地调整序列和迭代器的遍历类别, 并启用 3 个内蕴序列查找特性: at_key、result_of::value_at_key 和 has_key. 我们还需要启用 3 个迭代器查找特性: result_of::key_of、result_of::value_of_data 和 deref_data.

为了实现 at_key_impl, 我们需要把 fields::name 和 fields::age 类型 (在 快速入门 指南中描述) 与 example_struct 的相应成员关联起来. 我们的实现如下:

template<>
struct at_key_impl<example::example_sequence_tag>
{
    template<typename Sequence, typename Key>
    struct apply;

    template<typename Sequence>
    struct apply<Sequence, fields::name>
    {
        typedef typename mpl::if_<
            is_const<Sequence>,
            std::string const&,
            std::string&>::type type;

        static type
        call(Sequence& seq)
        {
            return seq.name;
        };
    };

    template<typename Sequence>
    struct apply<Sequence, fields::age>
    {
        typedef typename mpl::if_<
            is_const<Sequence>,
            int const&,
            int&>::type type;

        static type
        call(Sequence& seq)
        {
            return seq.age;
        };
    };
};

这一切都与我们之前看到的实现非常相似, 例如 deref_impl 和 value_of_impl. 现在我们不再按索引或位置识别成员, 而是使用 fields::name 和 fields::age 类型来选择它们. 其他函数的实现同样简单直接, 已在示例代码中给出.

小结

我们现在已经完成了添加新随机访问序列的整个过程, 并使我们的类型能够充当关联序列. 该实现略显冗长, 但遵循一个简单的重复模式.

对 std::pair、MPL 序列和 boost::array 的支持都使用相同的方法, 并为各种类型提供了该方法的更多示例.
