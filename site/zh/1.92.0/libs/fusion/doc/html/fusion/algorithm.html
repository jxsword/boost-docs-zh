惰性求值

与 MPL 不同, Fusion 算法是惰性的[12], 且不保持序列类型[13]. 这是有意为之的设计. 运行期效率被赋予很高的优先级. 与 MPL 相同而与 STL 不同的是, fusion 算法在本质上大多是函数式的, 即算法不修改输入 (无副作用). 然而, 由于返回 vector、list 等完整序列的代价高昂, Fusion 算法改为返回视图. 例如, transform 算法并不实际返回原序列的变换版本, transform 返回一个 transform_view. 该视图持有对原序列的引用以及变换函数. 对 transform_view 的迭代将按需对序列元素应用变换函数. 这种惰性求值方案允许我们任意串联多个算法, 而不会带来高昂的运行期开销.

序列扩展

惰性求值方案 (其中 算法 返回 视图) 也使 push_back 之类的操作得以完全泛化. 在 Fusion 中, push_back 实际上是一个适用于所有序列的泛型算法. 给定输入序列 s 和值 x, Fusion 的 push_back 算法只是返回一个 joint_view: 一个持有对原序列 s 的引用以及值 x 的视图. 原先针对特定序列、需要在 N 种不同序列上实现 N 次的函数, 现在只需实现一次. 也就是说, Fusion 序列的扩展代价很低.

为了重新获得原序列, 库提供了 转换 函数. 可以使用其中一个 转换 函数转换回原序列类型.
