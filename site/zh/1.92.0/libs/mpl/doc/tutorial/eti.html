ETI

在 C++ 模板问题的语境下, ETI 是 "Early Template Instantiation" (早期模板实例化) 的缩写——一个 Microsoft Visual C++ 特有的问题, 在 Microsoft 开发者于 Visual C++ 7.1 (2003 .NET) 中修复它之前, 它一直是该平台上任何严肃模板工作的障碍. 虽然只要在整个代码库中系统地应用正确的技术, 这个问题相对容易绕过, 但这种方法肯定繁琐且耗时. 所以, 如果有一天你发现自己在该问题上耗费了太多时间, 考虑升级到更新版本的编译器. 事实上, 无论如何都应认真考虑升级. 节省的时间、金钱和挫败感的收益完全值回票价.

The Problem

下面用 MSVC 6.x 简短演示一下该问题:

template< typename F, typename T > struct apply1
{
    typedef typename F::template apply<T>::type type;
};

尝试编译这段看似无害的代码, 我们得到:

portability.cpp(4) : error C2903: 'apply' : symbol is neither a class template 
            nor a function template
        portability.cpp(5) : see reference to class template instantiation 
            'apply1<F,T>' being compiled
portability.cpp(4) : error C2143: syntax error : missing ',' before '<'
        portability.cpp(5) : see reference to class template instantiation 
            'apply1<F,T>' being compiled
portability.cpp(4) : error C2059: syntax error : '<'
        portability.cpp(5) : see reference to class template instantiation 
            'apply1<F,T>' being compiled

诊断信息中 "symbol is neither a class template nor a function template" 这一部分实际上往往表明存在与 ETI 相关的问题. 另一个典型的错误消息通常会说某某嵌套类型不是全局命名空间的成员.

两种情形是同一个编译器缺陷的两面, 我们称之为 "早期模板实例化": 编译器出于内部目的, 为了处理类模板定义, 会用哑模板参数 (int) 实例化类模板. 这可能发生在解析模板定义期间 (这类错误最容易识别和修复——模板定义本身无法编译; 上面的例子就属于这一类), 也可能稍后在模板实例化期间发生, 这类难以发现——缺陷只会在某些特定上下文中触发.

ETI 总是在解析命名空间作用域模板定义期间进行, 这基本上意味着, 任何把其模板参数替换为 int 后失效的模板定义都可能无法编译, 正如我们的例子所发生的那样:

template< typename F, typename T > struct apply1
{
    // typedef typename F::template apply<T>::type type;
    // ETI generates this: 
    typedef typename int::template apply<int>::type type;
};

如果你编译它, 你会得到完全相同的诊断信息.

注意我们说的是 "可能无法编译", 因为......嗯, 简短的回答是 "视情况而定". 我们尚未分析到能告诉你 ETI 何时导致错误、何时不导致的准确条件的程度, 但这并不太重要——如果是错误, 修掉它即可 (我们稍后会展示怎么做); 如果不是, 就保持原样. 如果有一天潜在问题变成真实问题, 那就应用我们即将给出的变通办法.

症状

我们已经看过典型的诊断信息, 就不再重复了. 只提一点: MSVC 的许多 INTERNAL COMPILER ERROR (ICE) 实际上是由实例化栈深处某个与 ETI 相关的问题引起的.

解决办法

在这种情况下我们无法改变编译器的行为, 所以我们要做的是适应它, 同时仍让模板做我们想做的事. 出人意料的是, 在大多数情况下这相当容易实现:

// potentially unsafe
template< typename F > struct apply0
{
    typedef typename F::type type;
};

// now ETI-safe
template<> struct apply0<int>
{
    typedef int type;
};

由于原模板本来就不可能以 int 实例化, 提供一个 int 的桩特化完全无碍.
