实现乘法

乘法比加法和减法要复杂一些. 迄今为止, 实参和结果的量纲都是相同的, 但在相乘时, 结果的量纲通常与任一实参的量纲都不同. 对乘法而言, 关系式:

(xa)(xb) == x (a + b)

意味着结果量纲的指数应是来自实参量纲的相应指数之和. 除法类似, 只是把求和换成求差.

要从两个序列中合并对应元素, 我们将使用 MPL 的 transform 算法. transform 是一个元函数, 它并行地遍历两个输入序列, 把每个序列中的一个元素传给任意的二元元函数, 并把结果放入输出序列.

template <class Sequence1, class Sequence2, class BinaryOperation>
struct transform;  // returns a Sequence

如果你熟悉 STL 的 transform 算法 (它接受两个运行期序列作为输入), 上面的签名应该看起来很眼熟:

template <
    class InputIterator1, class InputIterator2
  , class OutputIterator, class BinaryOperation
>
void transform(
    InputIterator1 start1, InputIterator2 finish1
  , InputIterator2 start2
  , OutputIterator result, BinaryOperation func);

现在我们只需传入一个做加法或减法的 BinaryOperation, 就能用 mpl::transform 来乘除量纲. 如果翻阅the MPL reference manual, 你会看到 plus 和 minus 元函数, 它们做的正是你所期望的事:

#include <boost/static_assert.hpp>
#include <boost/mpl/plus.hpp>
#include <boost/mpl/int.hpp>
namespace mpl = boost::mpl;

BOOST_STATIC_ASSERT(( 
    mpl::plus<
        mpl::int_<2>
      , mpl::int_<3>
    >::type::value == 5
));

BOOST_STATIC_ASSERT

是一个宏, 当其实参为假时引发编译错误. 双层括号是必需的, 因为 C++ 预处理器无法解析模板: 否则它会因逗号而误以为条件是两个独立的宏实参. 与其运行期对应物 assert(...) 不同, BOOST_STATIC_ASSERT 还可以在类作用域使用, 使我们能够在元函数中放置断言. 深入讨论参见第 8 章.

此时看起来我们似乎已经有了答案, 但还差一点. 在 operator* 的实现中直接应用 transform 算法的天真尝试会产生编译错误:

#include <boost/mpl/transform.hpp>

template <class T, class D1, class D2>
quantity< 
    T
  , typename mpl::transform<D1,D2,mpl::plus>::type
>
operator*(quantity<T,D1> x, quantity<T,D2> y) { ... }

它失败是因为协议规定元函数实参必须是类型, 而 plus 不是类型, 而是类模板. 我们需要设法让 plus 这类元函数符合元数据的模子.

在元函数与元数据之间引入多态的一种自然方式, 是采用曾为我们提供类型与整型常量之间多态性的包装惯用法. 我们可以使用嵌套在元函数类中的类模板, 而不是嵌套的整型常量:

struct plus_f
{
    template <class T1, class T2>
    struct apply
    {
       typedef typename mpl::plus<T1,T2>::type type;
    };
};

定义

元函数类是一个类, 带有一个可公开访问的、名为 apply 的嵌套元函数.

元函数是模板而非类型, 而元函数类把该模板包装在一个普通的非模板类中, 后者是一个类型. 由于元函数操作并返回类型, 元函数类可以作为实参传给另一个元函数, 或从另一个元函数返回.

至此, 我们终于有了一个可以传给 transform 而不引发编译错误的 BinaryOperation 类型:

template <class T, class D1, class D2>
quantity< 
    T
  , typename mpl::transform<D1,D2,plus_f>::type  // new dimensions
>
operator*(quantity<T,D1> x, quantity<T,D2> y)
{
    typedef typename mpl::transform<D1,D2,plus_f>::type dim;
    return quantity<T,dim>( x.value() * y.value() );
}

现在, 如果我们想计算重力作用在一台 5 千克笔记本电脑上的力, 那就是重力加速度 (9.8 m/sec2) 乘以笔记本的质量:

quantity<float,mass> m(5.0f);
quantity<float,acceleration> a(9.8f);
std::cout << "force = " << (m * a).value();

我们的 operator* 把运行期值相乘 (得到 6.0f), 而我们的元程序代码使用 transform 对基本量纲指数的元序列求和, 使结果类型包含一个新的指数列表的表示, 大致如下:

mpl::vector_c<int,1,1,-2,0,0,0,0>

但是, 如果我们尝试写:

quantity<float,force> f = m * a;

我们会遇到一个小问题. 虽然 m * a 的结果确实表示一个力, 其质量、长度和时间的指数分别为 1, 1 和 -2, 但 transform 返回的类型并不是 vector_c 的特化. 相反, transform 以泛型方式处理其输入的元素, 构建一个由相应元素组成的新序列: 该类型具有与 mpl::vector_c<int,1,1,-2,0,0,0,0> 许多相同的序列性质, 但却是完全不同的 C++ 类型. 如果你想看该类型的全名, 可以自己编译这个示例并查看错误消息, 但确切细节并不重要. 重点是 force 命名的是另一个类型, 因此上面的赋值会失败.

为解决该问题, 我们可以为乘法的结果类型添加一个到 quantity<float,force> 的隐式转换. 由于我们无法预测任何计算中所涉量纲的确切类型, 这一转换必须模板化, 大致如下:

template <class T, class Dimensions>
struct quantity
{
    // converting constructor
    template <class OtherDimensions>
    quantity(quantity<T,OtherDimensions> const& rhs)
      : m_value(rhs.value())
    {
    }
    ...

遗憾的是, 这种宽泛的转换破坏了我们的整个目标, 允许如下这类无意义的东西:

// Should yield a force, not a mass!
quantity<float,mass> bogus = m * a;

我们可以使用另一个 MPL 算法 equal 来纠正这个问题, 它测试两个序列是否具有相同的元素:

template <class OtherDimensions>
quantity(quantity<T,OtherDimensions> const& rhs)
  : m_value(rhs.value())
{
    BOOST_STATIC_ASSERT((
       mpl::equal<Dimensions,OtherDimensions>::type::value
    ));
}

现在, 若两个量的量纲不匹配, 断言将引发编译错误.
