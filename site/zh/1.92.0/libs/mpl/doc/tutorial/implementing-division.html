实现除法

除法与乘法类似, 但不是把指数相加, 而是必须相减. 与其写出近乎重复的 plus_f, 我们可以用下面的技巧让 minus_f 简单得多:

struct minus_f
{
    template <class T1, class T2>
    struct apply
      : mpl::minus<T1,T2> {};
};

这里 minus_f::apply 利用继承来暴露其基类 mpl::minus 的嵌套 type, 因此我们不必写:

typedef typename ...::type type

这里我们不必写 typename (事实上那样写是非法的), 因为编译器知道 apply 初始化列表中的依赖名称必定是基类. [2] 这一强大的简化技术被称为元函数转发; 随着本书的推进我们会经常应用它. [3]

[2]顺便一提, 同样的方法本也可用于 plus_f, 但由于它稍显微妙, 我们先介绍了直白但冗长的写法.
[3]EDG 编译器的用户应查阅本书的附录 C, 了解关于元函数转发的一个注意事项. 你可以通过检查预处理符号 __EDG_VERSION__ (所有基于 EDG 的编译器都会定义它) 来判断自己是否在使用 EDG 编译器.

尽管有这些句法上的小技巧, 编写平凡类来包装既有元函数很快就会变得乏味. 虽然 minus_f 的定义远不如 plus_f 冗长, 但要敲的内容仍然很多. 所幸, MPL 为我们提供了一种简单得多的传递元函数的方式. 无需构建完整的元函数类, 我们可以这样调用 transform:

typename mpl::transform<D1,D2, mpl::minus<_1,_2> >::type

那些看起来很滑稽的实参 (_1 和 _2) 被称为占位符, 它们表示: 当 transform 的 BinaryOperation 被调用时, 其第一个和第二个实参将分别按照 _1 和 _2 所指示的位置传递给 minus. 整个类型 mpl::minus<_1,_2> 被称为一个占位符表达式.

注释

MPL 的占位符位于 mpl::placeholders 命名空间中, 定义于 boost/mpl/placeholders.hpp. 在本书中, 我们通常假设你已经写了:

#include<boost/mpl/placeholders.hpp>
using namespace mpl::placeholders;

以便无需限定即可访问它们.

下面是使用占位符表达式编写的除法运算符:

template <class T, class D1, class D2>
quantity< 
    T
  , typename mpl::transform<D1,D2,mpl::minus<_1,_2> >::type
>
operator/(quantity<T,D1> x, quantity<T,D2> y)
{
   typedef typename 
     mpl::transform<D1,D2,mpl::minus<_1,_2> >::type dim;

   return quantity<T,dim>( x.value() / y.value() );
}

这段代码相当简洁. 我们还可以进一步简化它, 把计算新量纲的代码提取到它自己的元函数中:

template <class D1, class D2>
struct divide_dimensions
  : mpl::transform<D1,D2,mpl::minus<_1,_2> > // forwarding again
{};

template <class T, class D1, class D2>
quantity<T, typename divide_dimensions<D1,D2>::type>
operator/(quantity<T,D1> x, quantity<T,D2> y)
{
   return quantity<T, typename divide_dimensions<D1,D2>::type>(
      x.value() / y.value());
}

现在我们可以通过反向执行来验证 "笔记本电脑上的力" 这一计算, 如下所示:

quantity<float,mass> m2 = f/a;
float rounding_error = std::abs((m2 - m).value());

如果我们把一切都做对了, rounding_error 应当非常接近零. 这些计算很枯燥, 但一旦做错, 它们恰恰是能毁掉整个程序 (或更糟) 的那类东西. 如果我们当初写的是 a/f 而不是 f/a, 就会出现编译错误, 阻止错误在程序中蔓延.
