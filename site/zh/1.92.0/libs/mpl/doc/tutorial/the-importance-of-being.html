惰性的重要性

回想上一章中 always_int 的定义:

struct always_int
{
    typedef int type;
};

零元元函数乍看之下似乎不太重要, 因为像 add_pointer<int> 这样的东西, 在其出现的任何 lambda 表达式中都可以被 int* 替代. 但并非所有零元元函数都这么简单:

typedef mpl::vector<int, char*, double&> seq;
typedef mpl::transform<seq, boost::add_pointer<_> > calc_ptr_seq;

注意 calc_ptr_seq 是一个零元元函数, 因为它拥有 transform 的嵌套 ::type. 然而, C++ 模板直到我们真正 "查看其内部" 时才被实例化. 仅仅提及 calc_ptr_seq 并不会使其被求值, 因为我们尚未访问其 ::type.

元函数可以惰性地调用, 而不是在提供其全部实参时立即调用. 当元函数的结果只会有条件地使用时, 我们可以运用惰性求值来改善编译时间. 有时我们还可以通过命名一个无效的计算而不实际执行它, 来避免扭曲程序结构. 这就是我们在上面对 calc_ptr_seq 所做的事, 因为 double&* 是无法合法构成的. 惰性及其种种优点将是贯穿全书的反复出现的主题.
