Placeholders

"占位符" 的定义可能会让你吃惊:

定义

占位符是形如 mpl::arg<X> 的元函数类.

实现

便捷名称 _1, _2,... _5 其实是 mpl::arg 特化的 typedef, 这些特化只是为任意 N 选择第 N 个实参. [6] 占位符的实现大致如下:

[6]MPL 默认提供五个占位符. 有关如何更改所提供占位符数量的说明, 参见the MPL reference manual 的 Configuration Macros 一节.
 
namespace boost { namespace mpl { namespace placeholders {

template <int N> struct arg; // forward declarations
struct void_;

template <>
struct arg<1>
{
    template <
      class A1, class A2 = void_, ... class Am = void_>
    struct apply
    {
        typedef A1 type; // return the first argument
    };
};
typedef arg<1> _1;

template <>
struct arg<2>
{
    template <
      class A1, class A2, class A3 = void_, ...class Am = void_
    >
    struct apply
    {
        typedef A2 type; // return the second argument
    };
};
typedef arg<2> _2;

more specializations and typedefs...

}}}

记住, 调用元函数类等同于调用其嵌套的 apply 元函数. 当 lambda 表达式中的占位符被求值时, 它会以表达式的实际实参被调用, 只返回其中之一. 结果随后被代回 lambda 表达式, 求值过程继续进行.

无名占位符

有一个特殊的占位符, 被称为无名占位符, 我们还未定义它:

namespace boost { namespace mpl { namespace placeholders {

typedef arg<-1> _; // the unnamed placeholder

}}}

其实现的细节并不重要; 关于无名占位符, 你真正需要知道的是它会受到特殊对待. 当 lambda 表达式正被 mpl::lambda 变换为元函数类时,

无名占位符在给定模板特化中的第 n 次出现会被替换为 _n.

例如, 下面的表 1.1 中每一行都包含两个等价的 lambda 表达式.

无名占位符语义 
mpl::plus<_,_>

mpl::plus<_1,_2>

boost::is_same<
    _
  , boost::add_pointer<_>
>

boost::is_same<
    _1
  , boost::add_pointer<_1>
>

mpl::multiplies<
   mpl::plus<_,_>
 , mpl::minus<_,_>
>

mpl::multiplies<
   mpl::plus<_1,_2>
 , mpl::minus<_1,_2>
>

尤其是在简单的 lambda 表达式中使用时, 无名占位符往往恰好消除足够多的语法 "噪声", 从而显著提高可读性.
