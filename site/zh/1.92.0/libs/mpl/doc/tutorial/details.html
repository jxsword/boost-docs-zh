详情

读到这里, 你应该已经对一般模板元编程以及 Boost 元编程库的基本概念和语言有了相当完整的认识. 本节回顾其中的要点.

元函数转发.
一种技术: 通过公有继承访问基类提供的嵌套 type, 以此供给元函数的嵌套 type 成员.
元函数类.
把编译期函数表述为可被视为多态元数据 (即类型) 的最基本方式. 元函数类是一个带有名为 apply 的嵌套元函数的类.
MPL.

本书的大多数示例都会使用 Boost 元编程库. 与 Boost type traits 头文件一样, MPL 头文件遵循一个简单的约定:

#include <boost/mpl/component-name.hpp>

但是, 若组件名以下划线结尾, 相应的 MPL 头文件名则不包含末尾的下划线. 例如, mpl::bool_ 可在 <boost/mpl/bool.hpp> 中找到. 库偏离此约定之处, 我们一定会向你指出.

高阶函数.
操作函数或返回函数的函数. 使元函数与其他元数据具备多态性, 是高阶元编程的关键要素.
lambda 表达式.
简言之, lambda 表达式就是可调用的元数据. 没有某种形式的可调用元数据, 高阶元函数将无从谈起. lambda 表达式有两种基本形式: 元函数类和占位符表达式.
占位符表达式.

一种 lambda 表达式, 通过使用占位符, 支持就地元函数偏应用和元函数组合. 正如你将在本书中处处看到的那样, 这些特性赋予我们真正令人惊叹的能力: 在使用点直接由更基础的元函数构建几乎任何类型的复杂类型计算:

// find the position of a type x in some_sequence such that:
//         x is convertible to 'int'
//      && x is not 'char'
//      && x is not a floating type
typedef mpl::find_if<
      some_sequence
    , mpl::and_<
          boost::is_convertible<_1,int>
        , mpl::not_<boost::is_same<_1,char> >
        , mpl::not_<boost::is_float<_1> >
      >
    >::type iter;

占位符表达式兑现了算法复用的承诺, 而不必强迫我们编写新的元函数类. 在 STL 的运行期世界里, 相应的能力常常令人扼腕, 因为尽管标准算法在正确性和效率上有优势, 手写一个循环往往比使用它们容易得多.

lambda 元函数.
把 lambda 表达式变换为相应元函数类的元函数. 有关 lambda 及 lambda 求值过程的详细信息, 请参阅 the MPL reference manual.
apply 元函数.
以其余实参调用其第一个实参 (必须是 lambda 表达式) 的元函数. 一般而言, 要调用 lambda 表达式, 你应当始终把它连同要应用它的实参一起传给 mpl::apply, 而不要使用 lambda 然后 "手动" 调用其结果.
惰性求值.
把求值延迟到需要结果时才进行的策略, 从而避免任何不必要的计算及随之而来的不必要的错误. 只有在我们访问元函数的嵌套 ::type 时才会调用它们, 因此我们可以在不执行任何计算的情况下提供其全部实参, 把求值推迟到最后一刻.
