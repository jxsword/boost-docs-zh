常见问题

图构造

应选择哪个容器选择器(vecS、listS、setS)?

选择器 存储 稳定? 注释

vecS

vector

否

快速迭代; 允许平行边

listS

list

是

O(E) 查找; 允许平行边

setS

tree

是(边)

O(log E) 查找; 不允许平行边

经验法则: 两个槽位都用 vecS, 除非你要主动移除顶点(此时顶点槽位用 listS), 或需要去重的出边(边槽位用 setS).

我能否把 std::vector<std::list<…​>> 当作图来用?

可以. 包含 <boost/graph/vector_as_graph.hpp> 后, 该容器本身就建模 BGL 的关联图和顶点列表概念. 顶点描述符是外层向量的索引; 内层列表的每个元素是一个整数边目标.

#include <boost/graph/vector_as_graph.hpp>
#include <boost/graph/breadth_first_search.hpp>
#include <iostream>
#include <list>
#include <vector>

int main() {
    using namespace boost;
    std::vector<std::list<int>> g(4);
    g[0].push_back(1); g[0].push_back(2);
    g[1].push_back(3);
    g[2].push_back(3);

    std::cout << "V = " << num_vertices(g) << "\n";
    for (std::size_t u = 0; u < g.size(); ++u)
        for (int v : g[u])
            std::cout << "  " << u << " -> " << v << "\n";
}
V = 4
  0 -> 1
  0 -> 2
  1 -> 3
  2 -> 3

属性

捆绑属性还是内部(基于标签的)属性: 应该用哪个?

捆绑属性. 语法更短, 运行期开销相同, 且现代算法在接受属性映射的地方都接受 get(&Bundle::field, g). 只在某算法硬编码内部标签时才使用内部标签(例如 DIMACS 流读取器的 edge_capacity_t). 完整对比见 捆绑属性 一页.

我得到 error_property_not_found. 这是什么意思?

error: no match for
`boost::detail::error_property_not_found & ==
 boost::detail::error_property_not_found &'

算法期望图上有某个命名属性(权重、颜色、vertex_index 等)但没有找到. 把该属性作为捆绑结构的一个字段添加, 并通过命名参数 API(weight_map(…​)、color_map(…​)、vertex_index_map(…​) 等)显式传入.

#include <boost/graph/adjacency_list.hpp>
#include <boost/graph/dijkstra_shortest_paths.hpp>
#include <iostream>
#include <vector>

using namespace boost;
struct Edge { int weight; };
using Graph = adjacency_list<vecS, vecS, directedS, no_property, Edge>;

int main() {
    Graph g(3);
    add_edge(0, 1, Edge{5}, g);
    add_edge(1, 2, Edge{3}, g);
    add_edge(0, 2, Edge{9}, g);

    std::vector<int> d(num_vertices(g));
    // Graph has no edge_weight_t tag; pass the bundled field as the weight map.
    dijkstra_shortest_paths(g, 0,
        weight_map(get(&Edge::weight, g))
            .distance_map(make_iterator_property_map(
                d.begin(), get(vertex_index, g))));

    std::cout << "shortest distance 0 -> 2 = " << d[2] << "\n";
}
shortest distance 0 -> 2 = 8

boost/property_map.hpp 在哪里?

很久以前就移走了. 包含 boost/property_map/property_map.hpp.

修改图

如何从 adjacency_list 中移除顶点?

先调用 clear_vertex, 再调用 remove_vertex. remove_vertex 不会触及关联边; 对仍有边的顶点调用它会留下悬空的边描述符, 并最终导致段错误.

#include <boost/graph/adjacency_list.hpp>
#include <iostream>

int main() {
    using namespace boost;
    using Graph = adjacency_list<listS, listS, undirectedS>;
    Graph g(3);
    auto it = vertices(g).first;
    auto a = *it, b = *++it, c = *++it;
    add_edge(a, b, g);
    add_edge(b, c, g);
    add_edge(a, c, g);

    std::cout << "before: " << num_vertices(g) << " vertices, "
              << num_edges(g) << " edges\n";

    clear_vertex(b, g);    // drop all edges incident to b
    remove_vertex(b, g);   // now safe to erase

    std::cout << "after:  " << num_vertices(g) << " vertices, "
              << num_edges(g) << " edges\n";
}
before: 3 vertices, 3 edges
after:  2 vertices, 1 edges

我的顶点或边描述符何时失效?

使用 VertexList = vecS 时, remove_vertex 会重新索引之后的所有顶点. 被移除顶点之后保存的任何描述符都会失效. 使用 listS 或 setS 时, 描述符是指针, 在移除操作后仍然有效. 边描述符对 OutEdgeList 遵循同样的规则.

#include <boost/graph/adjacency_list.hpp>
#include <iostream>

int main() {
    using namespace boost;

    // vecS: descriptors are indices into a vector. Removing 1 shifts 2 -> 1.
    using Vec = adjacency_list<vecS, vecS, directedS>;
    Vec g(3);
    std::cout << "before remove: ";
    for (auto v : make_iterator_range(vertices(g))) std::cout << v << " ";
    remove_vertex(1, g);
    std::cout << "\nafter  remove: ";
    for (auto v : make_iterator_range(vertices(g))) std::cout << v << " ";
    std::cout << "\n";
    // What used to be vertex 2 is now vertex 1. Any saved descriptor is stale.
}
before remove: 0 1 2
after  remove: 0 1

如何创建边已排序或去重的图?

选择 setS 作为 OutEdgeList 选择器. 出边按目标顶点顺序保存, 重复项在插入时被丢弃.

#include <boost/graph/adjacency_list.hpp>
#include <iostream>

int main() {
    using namespace boost;
    using Graph = adjacency_list<setS, vecS, directedS>;

    Graph g(1);
    add_edge(0, 3, g);
    add_edge(0, 1, g);
    add_edge(0, 2, g);
    add_edge(0, 2, g);  // duplicate; setS drops it

    std::cout << "out-edges of 0:";
    for (auto e : make_iterator_range(out_edges(0, g)))
        std::cout << " " << target(e, g);
    std::cout << "\n";
}
out-edges of 0: 1 2 3

使用算法

如何提前停止搜索?

从访问器抛出异常, 并在算法调用周围捕获. 这是唯一受支持的机制. 算法没有“提前返回”钩子.

#include <boost/graph/adjacency_list.hpp>
#include <boost/graph/breadth_first_search.hpp>
#include <iostream>

using namespace boost;
using Graph = adjacency_list<vecS, vecS, undirectedS>;
using Vertex = graph_traits<Graph>::vertex_descriptor;

struct Found {};

struct StopAt : default_bfs_visitor {
    Vertex target;
    explicit StopAt(Vertex t) : target(t) {}
    void discover_vertex(Vertex v, const Graph&) const {
        std::cout << "visit " << v << "\n";
        if (v == target) throw Found{};
    }
};

int main() {
    Graph g(5);
    add_edge(0, 1, g); add_edge(0, 2, g);
    add_edge(1, 3, g); add_edge(2, 4, g);

    try {
        breadth_first_search(g, 0, visitor(StopAt{3}));
    } catch (const Found&) {
        std::cout << "stopped at target\n";
    }
}
visit 0
visit 1
visit 2
visit 3
stopped at target

有没有不抛异常的方式提前停止 Dijkstra 或 BFS?

目前没有. 公共 API 中每条提前退出路径都会从访问器抛出异常. Boost.Graph 2026 研讨会上的社区反馈将此列为痛点; 优雅终止钩子已在库路线图上, 但尚未实现.

为什么算法 X 用 vecS 可以而 listS 不行?

该算法需要顶点索引. 使用 VertexList = vecS 时, adjacency_list 会合成一个; 使用 listS 时则不会, 因此必须自己提供. 在捆绑结构中加入索引字段, 并通过 vertex_index_map 命名参数传入.

#include <boost/graph/adjacency_list.hpp>
#include <boost/graph/breadth_first_search.hpp>
#include <iostream>

using namespace boost;
struct V { std::size_t idx; };
using Graph = adjacency_list<listS, listS, undirectedS, V>;

int main() {
    Graph g;
    for (std::size_t i = 0; i < 4; ++i) add_vertex(V{i}, g);

    auto it = vertices(g).first;
    auto s = *it; auto t = *++it;
    add_edge(s, t, g);

    breadth_first_search(g, s,
        visitor(default_bfs_visitor())
            .vertex_index_map(get(&V::idx, g)));

    std::cout << "bfs ok on listS using bundled vertex_index_map\n";
}
bfs ok on listS using bundled vertex_index_map

为什么访问器按值传递?

因为临时对象不能绑定到非 const 的引用, 而 BGL 希望接受在调用点就地构造的访问器. 因此访问器内部的可变状态存在于内部副本上, 不会泄漏回来. 若需要, 请以指针或引用持有状态.

#include <boost/graph/adjacency_list.hpp>
#include <boost/graph/breadth_first_search.hpp>
#include <iostream>

using namespace boost;
using Graph = adjacency_list<vecS, vecS, undirectedS>;

struct Counter : default_bfs_visitor {
    int* n;  // indirection so mutations escape the copy
    explicit Counter(int* p) : n(p) {}
    template <typename V, typename G>
    void discover_vertex(V, const G&) const { ++*n; }
};

int main() {
    Graph g(4);
    add_edge(0, 1, g); add_edge(1, 2, g); add_edge(2, 3, g);

    int n = 0;
    breadth_first_search(g, 0, visitor(Counter{&n}));
    std::cout << "discovered " << n << " vertices\n";
}
discovered 4 vertices

视图、适配器、I/O

filtered_graph 还是 subgraph?

filtered_graph 是由两个谓词(顶点、边)构建的非所有权 视图. 不复制, 不堆分配; 原图不变. 用它在子集上运行算法.

subgraph 拥有边的副本并跟踪父子关系. 当你需要一个可变的独立图, 并在 add_edge 时镜像回父图时使用它.

经验法则: 优先考虑 filtered_graph.

#include <boost/graph/adjacency_list.hpp>
#include <boost/graph/filtered_graph.hpp>
#include <iostream>

using namespace boost;
using Graph = adjacency_list<vecS, vecS, undirectedS>;

struct KeepEven {
    const Graph* g = nullptr;
    bool operator()(graph_traits<Graph>::vertex_descriptor v) const {
        return v % 2 == 0;
    }
    bool operator()(graph_traits<Graph>::edge_descriptor e) const {
        return (*this)(source(e, *g)) && (*this)(target(e, *g));
    }
};

int main() {
    Graph g(6);
    for (int u = 0; u < 6; ++u)
        for (int v = u + 1; v < 6; ++v)
            add_edge(u, v, g);  // K6

    KeepEven p{&g};
    filtered_graph<Graph, KeepEven, KeepEven> sub(g, p, p);

    std::cout << "filtered vertices:";
    for (auto v : make_iterator_range(vertices(sub))) std::cout << " " << v;

    // num_edges on a filtered_graph returns the underlying count; count manually.
    int kept = 0;
    for (auto e : make_iterator_range(edges(sub))) { (void)e; ++kept; }
    std::cout << "\nfiltered edges: " << kept << "\n";
}
filtered vertices: 0 2 4
filtered edges: 3

如何用自定义属性读取 GraphML 或 GraphViz?

两个读取器都接受 boost::dynamic_properties 对象. 把你想填充的每个属性映射注册到一个与文件中属性匹配的字符串名下. 完整示例见 GraphML 和 GraphViz 页面.

C++ 与库设计

为什么 graph_traits<Graph>::vertex_descriptor 在我的函数模板内无法编译?

Graph 是模板参数, 因此 graph_traits<Graph>::vertex_descriptor 是一个 依赖 名称. C++ 要求你以 typename 为前缀来告诉编译器它命名的是一个类型.

#include <boost/graph/adjacency_list.hpp>
#include <iostream>

using namespace boost;

template <typename G>
typename graph_traits<G>::vertices_size_type  // note: typename required
count_vertices(const G& g) {
    return num_vertices(g);
}

int main() {
    using Graph = adjacency_list<vecS, vecS, undirectedS>;
    Graph g(5);
    std::cout << "|V| = " << count_vertices(g) << "\n";
}
|V| = 5

为什么用自由函数而不是成员函数?

自由函数可以为第三方类型重载而无需修改其源码. BGL 正是这样适配 LEDA、Stanford GraphBase 甚至裸 std::vector<std::list<…​>> 的. 基于成员函数的 API 会迫使每个集成都要经过适配器类.
