Edmonds-Karp 最大流

使用 Ford-Fulkerson 算法的 Edmonds-Karp 变体计算网络的最大流.

复杂度: O(V E2); 若整数容量以 U 为界则为 O(V E U)
定义于: <boost/graph/edmonds_karp_max_flow.hpp>

示例

#include <boost/graph/adjacency_list.hpp>
#include <boost/graph/edmonds_karp_max_flow.hpp>
#include <iostream>
#include <vector>

using namespace boost;

// Bundled edge data replaces the nested `property<edge_capacity_t, ...>`
// chain. The reverse descriptor field links each edge to its counterpart.
using Traits = adjacency_list_traits<vecS, vecS, directedS>;
struct Edge {
    int capacity;
    int residual_capacity;
    Traits::edge_descriptor reverse;
};

using Graph = adjacency_list<vecS, vecS, directedS, no_property, Edge>;
using Descriptor = graph_traits<Graph>::edge_descriptor;
using Vertex = graph_traits<Graph>::vertex_descriptor;

void add_flow_edge(Graph& g, int from, int to, int cap) {
    Descriptor e = add_edge(from, to, g).first;
    Descriptor r = add_edge(to, from, g).first;
    g[e].capacity = cap; g[e].reverse = r;
    g[r].capacity = 0;   g[r].reverse = e;
}

int main() {
    Graph g(4);
    add_flow_edge(g, 0, 1, 10);
    add_flow_edge(g, 0, 2, 10);
    add_flow_edge(g, 1, 3, 5);
    add_flow_edge(g, 2, 3, 15);
    add_flow_edge(g, 1, 2, 4);

    // 8-arg positional form accepts explicit capacity / residual / reverse maps.
    std::vector<default_color_type> color(num_vertices(g));
    std::vector<Descriptor> pred(num_vertices(g));
    auto color_map = make_iterator_property_map(color.begin(), get(vertex_index, g));
    auto pred_map  = make_iterator_property_map(pred.begin(),  get(vertex_index, g));

    int flow = edmonds_karp_max_flow(g, Vertex(0), Vertex(3),
        get(&Edge::capacity, g),
        get(&Edge::residual_capacity, g),
        get(&Edge::reverse, g),
        color_map, pred_map);
    std::cout << "Edmonds-Karp max flow: " << flow << "\n";
}
Edmonds-Karp max flow: 19

template <class Graph,
          class CapacityEdgeMap, class ResidualCapacityEdgeMap,
          class ReverseEdgeMap, class ColorMap, class PredEdgeMap>
typename property_traits<CapacityEdgeMap>::value_type
edmonds_karp_max_flow(
    Graph& g,
    typename graph_traits<Graph>::vertex_descriptor src,
    typename graph_traits<Graph>::vertex_descriptor sink,
    CapacityEdgeMap cap, ResidualCapacityEdgeMap res,
    ReverseEdgeMap rev, ColorMap color, PredEdgeMap pred);
方向 参数 说明

IN

Graph& g

一个有向图. 图的类型必须是 顶点列表图 和 关联图 的模型. 对于图中的每条边 (u,v), 反向边 (v,u) 也必须在图中.

IN

vertex_descriptor src

流网络图的源顶点.

IN

vertex_descriptor sink

流网络图的汇顶点.

IN

CapacityEdgeMap cap

边容量属性映射. 该类型必须是常量 左值属性映射 的模型. 映射的键类型必须是图的边描述符类型.

OUT

ResidualCapacityEdgeMap res

它把边映射到其剩余容量. 该类型必须是可变 左值属性映射 的模型. 映射的键类型必须是图的边描述符类型.

IN

ReverseEdgeMap rev

一个边属性映射, 把图中的每条边 (u,v) 映射到反向边 (v,u). 该映射必须是常量 左值属性映射 的模型. 映射的键类型必须是图的边描述符类型.

UTIL

ColorMap color

供算法在广度优先搜索阶段记录进度. 算法结束时, 白色顶点定义最小割集. 该映射必须是可变 左值属性映射 的模型. 映射的键类型应为图的顶点描述符类型, 值类型必须是 Color Value 的模型.

UTIL

PredEdgeMap pred

供算法存储增广路径. 该映射必须是可变 左值属性映射 的模型. 键类型必须是图的顶点描述符类型, 值类型必须是图的边描述符类型.

IN

vertex_index_map(VertexIndexMap i_map)

把图的每个顶点映射到范围 [0, num_vertices(g)) 内的唯一整数. 只有在使用颜色或前驱映射的默认值时才需要此属性映射. 顶点索引映射必须是 可读属性映射 的模型. 映射的键类型必须是图的顶点描述符类型.
默认: get(vertex_index, g). 注意: 如果使用此默认值, 请确保你的图拥有内部属性 vertex_index. 例如, adjacency_list (带 VertexList=listS) 就没有内部属性 vertex_index.

说明

edmonds_karp_max_flow() 函数实现 Edmonds-Karp 算法 来计算网络的最大流. 最大流的描述参见 网络流算法 一节. 计算出的最大流将作为函数的返回值. 函数还会计算 E 中所有 (u,v) 的流值 f(u,v), 它们以剩余容量 r(u,v) = c(u,v) - f(u,v) 的形式返回.

该算法对输入图和属性映射参数有几个特殊要求. 首先, 表示网络的已向图 G=(V,E) 必须扩充, 为 E 中的每条边加入反向边. 也就是说, 输入图应当是 Gin = (V,{E U ET}). ReverseEdgeMap 实参 (rev) 必须把原图中的每条边映射到其反向边, 即对 E 中的所有 (u,v) 有 (u,v) → (v,u). CapacityEdgeMap 实参 (cap) 必须把 E 中的每条边映射到一个正数, 把 ET 中的每条边映射到 0.

该算法出自 Edmonds and Karp, 不过我们使用的是 Network Flows 中描述的变体, 称为"标记算法".

该算法为最大流问题提供了一个非常简单且易于实现的解决方案. 然而, 有几个原因使它不如 push_relabel_max_flow() 或 boykov_kolmogorov_max_flow() 算法.

  • 在非整数容量情形下, 时间复杂度为 O(V E2), 除了最稀疏的图外, 都比 push-relabel 算法的 O(V2E1/2) 差.

  • 在整数容量情形下, 若容量上界 U 非常大, 该算法将耗时很久.

返回

网络的最大流值.
