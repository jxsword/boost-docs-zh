用 BGL 构造图算法

BGL 的 主要 目标不是提供一个漂亮的图类, 也不是提供一套全面的可复用图算法(尽管这些也是目标). BGL 的主要目标是鼓励他人编写可复用的图算法. 所谓可复用, 我们指的是最大程度可复用. 泛型编程是使算法最大程度可复用的一种方法论, 本节将讨论如何把泛型编程应用于构造图算法.

为了说明泛型编程的过程, 我们将逐步构造一个图着色算法. 图着色问题(或更具体地说, 顶点着色问题)是为图 G 中的每个顶点标记一种颜色, 使得任何两个相邻顶点不会被标记为相同颜色, 且所用的颜色数量最少. 一般而言, 图着色问题是 NP 完全的, 因此不可能在合理的时间内找到最优解. 不过, 有许多算法使用启发式方法来找到接近最小值的着色.

我们在此给出的特定算法基于线性时间的 SEQ 子程序, 该子程序用于估计稀疏雅可比矩阵和黑塞矩阵 [6,4,3]. 该算法按照输入顺序定义的顺序访问图中所有顶点. 在每个顶点处, 算法标记相邻顶点的颜色, 然后为当前顶点选择最小的未标记颜色. 若所有颜色都已被标记, 则创建新颜色. 若某个颜色的标记号等于当前顶点号, 则该颜色视为已标记. 这省去了为每个顶点重置标记的麻烦. 该算法的有效性高度依赖于输入的顶点顺序. 有若干排序算法, 包括 最大度优先 [26]、最小度最后 [24] 和 关联度 [27] 算法, 它们可以提高此着色算法的有效性.

构造泛型图算法时, 首先要决定实现该算法需要哪些图操作, 以及这些操作对应哪些图概念. 在此算法中, 我们需要遍历所有顶点以初始化顶点颜色, 还需要访问相邻顶点. 因此我们选择 顶点列表图 概念, 因为它是包含这些操作的最小概念. 图类型将在此算法的模板函数中参数化. 我们不把图类型限制到特定的图类, 例如 BGL 的 adjacency_list, 因为这会极大限制算法的可复用性(迄今编写的大多数算法都是如此). 我们确实把图类型限制为建模 顶点列表图 的那些类型. 这通过在算法中使用这些图操作来强制, 并进一步通过以概念检查形式添加显式要求 BOOST_CONCEPT_ASSERT() 来强制(关于概念检查的更多细节, 见 概念检查 一节).

接下来需要考虑算法将使用哪些顶点或边属性. 在此例中, 唯一的属性是顶点颜色. 指定顶点颜色访问的最灵活方式是使用属性映射接口. 这让算法的用户可以自行决定如何存储属性. 由于我们既需要读取也需要写入颜色, 我们把要求指定为 ReadWritePropertyMap. 颜色映射的 key_type 必须是来自图的 vertex_descriptor, 且 value_type 必须是某种整数类型. 我们还把 order 参数的接口指定为属性映射, 此处为 ReadablePropertyMap. 对于顺序参数, key_type 是整数偏移, value_type 是 vertex_descriptor. 我们再次用概念检查来强制这些要求. 此算法的返回值是为图着色所需的颜色数量, 因此函数的返回类型是图的 vertices_size_type. 下面的代码以模板函数形式展示了我们图算法的接口、概念检查以及一些 typedef. 实现很直接, 上文未讨论的唯一步骤是颜色初始化步骤, 即把所有顶点的颜色设为“未着色”.

namespace boost {
  template <class VertexListGraph, class Order, class Color>
  typename graph_traits<VertexListGraph>::vertices_size_type
  sequential_vertex_color_ting(const VertexListGraph& G,
    Order order, Color color)
  {
    typedef graph_traits<VertexListGraph> GraphTraits;
    typedef typename GraphTraits::vertex_descriptor vertex_descriptor;
    typedef typename GraphTraits::vertices_size_type size_type;
    typedef typename property_traits<Color>::value_type ColorType;
    typedef typename property_traits<Order>::value_type OrderType;

    BOOST_CONCEPT_ASSERT(( VertexListGraphConcept<VertexListGraph> ));
    BOOST_CONCEPT_ASSERT(( ReadWritePropertyMapConcept<Color, vertex_descriptor> ));
    BOOST_CONCEPT_ASSERT(( IntegerConcept<ColorType> ));
    BOOST_CONCEPT_ASSERT(( ReadablePropertyMapConcept<Order, size_type> ));
    BOOST_STATIC_ASSERT((is_same<OrderType, vertex_descriptor>::value));

    size_type max_color = 0;
    const size_type V = num_vertices(G);
    std::vector<size_type>
      mark(V, numeric_limits_max(max_color));

    typename GraphTraits::vertex_iterator v, vend;
    for (boost::tie(v, vend) = vertices(G); v != vend; ++v)
      color[*v] = V - 1; // which means "not colored"

    for (size_type i = 0; i < V; i++) {
      vertex_descriptor current = order[i];

      // mark all the colors of the adjacent vertices
      typename GraphTraits::adjacency_iterator ai, aend;
      for (boost::tie(ai, aend) = adjacent_vertices(current, G); ai != aend; ++ai)
        mark[color[*ai]] = i;

      // find the smallest color unused by the adjacent vertices
      size_type smallest_color = 0;
      while (smallest_color < max_color && mark[smallest_color] == i)
        ++smallest_color;

      // if all the colors are used up, increase the number of colors
      if (smallest_color == max_color)
        ++max_color;

      color[current] = smallest_color;
    }
    return max_color;
  }
} // namespace boost
