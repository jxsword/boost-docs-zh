最大基数匹配

使用 Edmonds 算法在无向图中找出最大基数匹配.

复杂度: O(mn alpha(m,n))
定义于: <boost/graph/max_cardinality_matching.hpp>

示例

#include <iostream>
#include <vector>
#include <boost/graph/adjacency_list.hpp>
#include <boost/graph/max_cardinality_matching.hpp>

int main() {
    using Graph = boost::adjacency_list<boost::vecS, boost::vecS, boost::undirectedS>;
    using Vertex = boost::graph_traits<Graph>::vertex_descriptor;
    Graph g(6);
    boost::add_edge(0, 1, g); boost::add_edge(0, 3, g);
    boost::add_edge(1, 2, g); boost::add_edge(2, 3, g);
    boost::add_edge(4, 5, g);

    std::vector<Vertex> mate(num_vertices(g));
    auto mate_map = boost::make_iterator_property_map(
        mate.begin(), get(boost::vertex_index, g));
    boost::edmonds_maximum_cardinality_matching(g, mate_map);

    std::cout << "Maximum matching (" << boost::matching_size(g, mate_map,
        get(boost::vertex_index, g)) << " edges):\n";
    for (Vertex v = 0; v < num_vertices(g); ++v) {
        if (mate[v] != boost::graph_traits<Graph>::null_vertex() && v < mate[v])
            std::cout << "  " << v << " - " << mate[v] << "\n";
    }
}
Maximum matching (3 edges):
  0 - 3
  1 - 2
  4 - 5

说明

所谓 匹配, 是图的一个边子集, 其中任何两条边不共享公共顶点. 下面展示了同一图中两个不同的匹配 (匹配中的边着为蓝色). 左边的匹配是 极大匹配, 意为不能通过添加边来增大它的规模. 右边的匹配是 最大基数匹配, 意为它在图中所有匹配中规模最大.

edmonds_maximum_cardinality_matching 和 checked_edmonds_maximum_cardinality_matching 都可以在任何无向图中找出最大基数匹配. 匹配通过 MateMap 返回, 它是一个把顶点映射到顶点的 ReadWritePropertyMap. 在返回的映射中, 每个顶点要么映射到它匹配到的顶点, 要么在未参与匹配时映射到 graph_traits<Graph>::null_vertex(). 若未提供 VertexIndexMap, 两个函数都假定 VertexIndexMap 作为内部图属性提供, 可通过调用 get(vertex_index,g) 获取. edmonds_maximum_cardinality_matching 与 checked_edmonds_maximum_cardinality_matching 的唯一区别是, 后者作为最后一步会对计算出的匹配运行一次简单验证, 当且仅当该匹配确实是最大基数匹配时返回 true.

给定匹配 M, 任何未被 M 中的边覆盖的顶点都称为 自由 顶点. 任何恰好包含 2n + 1 条边、起止于自由顶点、且包含来自 M 的 n 条边的简单路径称为一条 交错路径. 给定一条交错路径 p, p 上所有匹配边与非匹配边可以互换, 得到一个比原匹配恰好多一条边的新匹配. 这种逐步增大匹配规模的方法, 连同下面的事实, 构成了 Edmonds 匹配算法的基础:

穿过匹配 M 的交错路径存在, 当且仅当 M 不是最大基数匹配.

困难的部分当然在于: 只要存在增广路径就把它找出来. 我们用于求最大基数匹配的算法由三个基本步骤组成:

  1. 创建一个初始匹配.

  2. 反复寻找增广路径并利用它增大匹配的规模, 直到不存在增广路径.

  3. 验证找到的匹配是最大基数匹配.

如果使用 checked_edmonds_maximum_cardinality_matching 或 edmonds_maximum_cardinality_matching, 这三个步骤都已为你选定; 但使用下文讨论的泛型 matching 函数, 很容易为这三步换用不同的算法 — 事实上, checked_edmonds_maximum_cardinality_matching 和 edmonds_maximum_cardinality_matching 都只是该函数的内联特化.

在引用算法的时间界时, 我们假定 VertexIndexMap 是一个支持顶点与索引之间常数时间映射的属性映射 (例如当顶点存储在连续内存中时很容易做到). 我们用 n 和 m 分别表示输入图顶点集与边集的规模.

创建初始匹配的算法

  • empty_matching: 用时 O(n) 初始化空匹配.

  • greedy_matching: 遍历各边, 若与已有匹配中的边不冲突则加入, 由此得到匹配. 该匹配是极大的, 因此保证至少含有最大匹配所含边数的一半. 用时 O(m log n).

  • extra_greedy_matching: 按每条边所含顶点的度递增排序各边, 然后由这些边构造贪心匹配. 同样是极大匹配, 有时可能比简单的 greedy_matching 更接近最大基数匹配. 用时 O(m log n), 但相关常数使其比 greedy_matching 慢.

寻找增广路径的算法

  • edmonds_augmenting_path_finder: 用时 O(m alpha(m,n)) 找到一条增广路径, 其中 alpha(m,n) 是 Ackermann 函数的某个反函数. alpha(m,n) 是计算机科学中自然出现的增长最慢的函数之一; 实质上, 对我们可能希望运行此算法的任何图都有 alpha(m,n) ⇐ 4. 由于增广 O(n) 次匹配后即得到最大基数匹配, 整个算法用时 O(mn alpha(m,n)). Edmonds 的原始算法发表于 [58], 但我们对 Edmonds 算法的实现紧密遵循 Tarjan 在 [22] 中对该算法的描述.

  • no_augmenting_path_finder: 若不希望增广初始匹配, 可以使用.

验证算法

  • maximum_cardinality_matching_verifier: 当且仅当找到的匹配是最大基数匹配时返回 true. 用时 O(m alpha(m,n)), 与 Edmonds 算法单次迭代同阶.

  • no_matching_verifier: 总是返回 true.

为什么需要验证算法? Edmonds 算法相当复杂, 一个人若没有几天空闲时间, 几乎不可能弄清 edmonds_matching 在一个有比如 100 个顶点、500 条边的图上产生的匹配是否确实是最大基数匹配. 验证算法可以机械地完成这件事, 而且通过检查来确认验证算法实现正确, 要比通过检查确认 Edmonds 算法实现正确容易得多. Boost 图库使验证器所需的子例程 (例如找出图中所有奇数基数的连通分量, 或在带特定标签的所有顶点上创建导出图) 只需几行代码即可完成, 简便至极.

理解验证器的工作原理需要一些图论事实. 设 m(G) 为图 G 中最大基数匹配的规模. 用 o(G) 表示 G 中奇数基数连通分量的个数, 对顶点集 X, 用 G - X 表示顶点集 V(G) - X 上的导出图. 那么 Tutte-Berge 公式断言:

2 * m(G) = min ( |V(G)| + |X| - o(G-X) )

其中最小值取遍顶点集 V(G) 的所有子集 X. Edmonds 花收缩算法的一个附带作用是计算图的所谓 Edmonds-Gallai 分解: 它把图分解为三个不相交的顶点集, 其中一个可在 Tutte-Berge 公式中取得最小值.

我们验证过程的概要如下: 给定 Graph g 和 MateMap mate,

  1. 检查确认 mate 是 g 上的有效匹配.

  2. 运行一次 edmonds_augmenting_path_finder (在 g 和 mate 上). 若它找到一条增广路径, 该匹配就不是最大基数匹配. 否则, 我们取回 vertex_state 映射的一个副本, 该映射由 edmonds_augmenting_path_finder 使用. Edmonds-Gallai 分解告诉我们, 标记为 V_ODD (由 vertex_state 映射标记) 的顶点集可以用作 X 集合, 在 Tutte-Berge 公式中取得最小值.

  3. 统计标记为 V_ODD 的顶点数, 并存入 num_odd_vertices.

  4. 创建一个 filtered_graph, 由所有未标记为 V_ODD 的顶点组成. 统计此图中奇连通分量的个数, 并把结果存入 num_odd_connected_components.

  5. 用 |X| = num_odd_vertices 和 o(G-X) = num_odd_connected_components 检验 Tutte-Berge 公式中的等式是否成立. 成立则返回 true, 否则返回 false.

假定这些步骤实现正确, 验证器绝不会返回假阳性; 只有当 edmonds_augmenting_path_finder 未正确计算 vertex_state 映射时才会返回假阴性, 此时 edmonds_augmenting_path_finder 工作不正常.

创建自己的匹配算法

创建匹配算法很简单: 把上面描述的算法插入泛型 matching 函数即可.

为你提供的匹配函数只是该函数的内联特化: edmonds_maximum_cardinality_matching 使用 edmonds_augmenting_path_finder 作为 AugmentingPathFinder, extra_greedy_matching 作为 InitialMatchingFinder, no_matching_verifier 作为 MatchingVerifier. checked_edmonds_maximum_cardinality_matching 使用相同的参数, 只是 maximum_cardinality_matching_verifier 被用作 MatchingVerifier.

这些未必是任何情形下的最佳选择 — 例如, 文献中有观点认为, 对稀疏图, 若不为 Edmonds 算法提供初始匹配, 它会更快收敛到最大基数匹配. 这样的算法很容易组装: 调用 matching 时传入

  • AugmentingPathFinder = edmonds_augmenting_path_finder

  • InitialMatchingFinder = empty_matching

并根据你想要多大程度的严谨来选择 MatchingVerifier.

假设你想快速得到一个相对较大的匹配, 但并不执著于最大匹配. extra_greedy_matching 和 greedy_matching 都能找到极大匹配, 这意味着它们保证至少是最大基数匹配规模的一半, 因此你可以调用 matching, 传入

  • AugmentingPathFinder = no_augmenting_path_finder

  • InitialMatchingFinder = extra_greedy_matching

  • MatchingVerifier = maximum_cardinality_matching_verifier

得到的算法会在 O(m log n) 时间内额外找出一个贪心匹配, 而不寻找增广路径. 附带的好处是, 该函数的返回值为 true 当且仅当这个额外的贪心匹配恰好是最大基数匹配.

返回

edmonds_maximum_cardinality_matching 返回 void. 匹配存储在输出参数 MateMap 中.

checked_edmonds_maximum_cardinality_matching 返回 true, 当且仅当计算出的匹配是最大基数匹配.

泛型 matching 函数返回 true, 当且仅当 MatchingVerifier 确认该匹配.

注释

  • Edmonds 的原始算法发表于 [58]. 我们的实现紧密遵循 Tarjan 在 [22] 中的描述.

  • 验证算法基于 Tutte-Berge 公式与 Edmonds-Gallai 分解, 它们作为 Edmonds 花收缩算法的附带产物被计算.
