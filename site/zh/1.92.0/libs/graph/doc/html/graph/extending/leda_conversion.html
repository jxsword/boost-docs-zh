把现有图转换为 BGL

如何把现有图转换为 BGL

虽然 BGL 的主要目标是帮助开发新应用和图算法, 但现有代码中有相当一部分可以从使用 BGL 算法中受益. 将 BGL 算法用于现有图数据结构的一种方式, 是把数据从旧的图格式复制到 BGL 图中, 然后在 BGL 算法中使用该图. 这种做法的问题在于复制可能代价高昂. 另一种方法是用 BGL 接口包装现有的图数据结构.

适配器模式 [9] 通常要求被适配对象包含在一个提供所需接口的新类中. 为 BGL 包装图时不需要这种包含, 因为 BGL 图接口完全由自由(全局)函数构成. 你无需创建新的图类, 只需重载接口要求的全部自由函数. 我们把这种自由函数包装方法称为 外部适配.

比较常用的图类之一是 LEDA 参数化 GRAPH 类 [18]. 本节将展示如何为该类创建 BGL 接口. 第一个问题是应当实现哪些 BGL 接口(或概念). 以下概念在 LEDA 之上实现起来直接明了: 顶点列表图、双向图 和 可变图.

BGL 图类关联的所有类型都通过 graph_traits 类访问. 我们可以按如下方式为 LEDA GRAPH 类部分特化此特征类. node 和 edge 是 LEDA 用于表示顶点和边的类型. LEDA 的 GRAPH 用于有向图, 因此我们选择 directed_tag 作为 directed_category. LEDA 的 GRAPH 不会自动阻止平行边的插入, 因此我们选择 allow_parallel_edge_tag 作为 edge_parallel_category. LEDA 函数 number_of_nodes() 和 number_of_edges() 的返回类型是 int, 因此我们为图的 vertices_size_type 和 edges_size_type 选用该类型. 迭代器类型会更复杂一些, 因此留到后面处理.

namespace boost {
  template <class vtype, class etype>
  struct graph_traits< GRAPH<vtype,etype> > {
    typedef node vertex_descriptor;
    typedef edge edge_descriptor;

    // iterator typedefs...

    typedef directed_tag directed_category;
    typedef allow_parallel_edge_tag edge_parallel_category;
    typedef int vertices_size_type;
    typedef int edges_size_type;
  };
} // namespace boost

首先编写 source() 和 target() 这两个函数, 它们属于 关联图 概念, 而该概念是 顶点列表图 概念的一部分. 图参数使用 LEDA GRAPH 类型, 并用 graph_traits 指定边参数和顶点返回类型. 这里也可以直接使用 LEDA 类型 node 和 edge, 但始终使用 graph_traits 是更好的实践. 若需要更改关联的顶点或边类型, 只需在 graph_traits 的特化中改一处, 而不必改动整个代码. LEDA 提供 source() 和 target() 函数, 因此我们只需调用它们.

namespace boost {
  template <class vtype, class etype>
  typename graph_traits< GRAPH<vtype,etype> >::vertex_descriptor
  source(
    typename graph_traits< GRAPH<vtype,etype> >::edge_descriptor e,
    const GRAPH<vtype,etype>& g)
  {
    return source(e);
  }

  template <class vtype, class etype>
  typename graph_traits< GRAPH<vtype,etype> >::vertex_descriptor
  target(
    typename graph_traits< GRAPH<vtype,etype> >::edge_descriptor e,
    const GRAPH<vtype,etype>& g)
  {
    return target(e);
  }
} // namespace boost

关联图 中下一个需要实现的函数是 out_edges(). 此函数返回一对出边迭代器. 由于 LEDA 不使用 STL 风格的迭代器, 我们需要自己实现一些. Boost 有一个非常方便的迭代器实现工具, 称为 iterator_adaptor. 编写符合标准的迭代器类实际上相当困难, 比你想的要难. 使用 iterator_adaptor 类, 你只需实现一个策略类, 其余都会被妥善处理. 下面的代码是我们出边迭代器的策略类. 在 LEDA 中, 边对象本身就像迭代器一样使用. 它有 Succ_Adj_Edge() 和 Pred_Adj_Edge() 函数用于移动到下一条和上一条(后继和前驱)边. 把 LEDA edge 用作迭代器有一个陷阱, 出现在 dereference() 函数中, 该函数只是返回边对象. 符合标准的迭代器的解引用运算符必须是 const 成员函数, 这就是边参数为 const 的原因. 但是返回类型不应为 const, 因此需要 const_cast.

namespace boost {
  struct out_edge_iterator_policies
  {
    static void increment(edge& e)
    { e = Succ_Adj_Edge(e,0); }

    static void decrement(edge& e)
    { e = Pred_Adj_Edge(e,0); }

    template <class Reference>
    static Reference dereference(type<Reference>, const edge& e)
    { return const_cast<Reference>(e); }

    static bool equal(const edge& x, const edge& y)
    { return x == y; }
  };
} // namespace boost

现在回到 graph_traits 类, 使用 iterator_adaptor 填充 out_edge_iterator. 我们使用 iterator 类型来指定迭代器的关联类型, 包括迭代器类别和值类型.

  namespace boost {
    template <class vtype, class etype>
    struct graph_traits< GRAPH<vtype,etype> > {
      // ...
      typedef iterator_adaptor<edge,
        out_edge_iterator_policies,
        iterator<std::bidirectional_iterator_tag,edge>
      > out_edge_iterator;
      // ...
    };
  } // namespace boost

有了 out_edge_iterator(在 graph_traits 中定义), 我们就可以定义 out_edges() 函数了. 下面的定义乍一看复杂, 实际上相当简单. 返回类型应是一对出边迭代器, 因此我们使用 std::pair, 然后用 graph_traits 访问出边迭代器类型. 在函数体中, 我们构造出边迭代器: 传入第一条邻接边作为 begin 迭代器, 传入 0 作为 end 迭代器(LEDA 中用作结束哨兵). First_Adj_Edge 的 0 参数告诉 LEDA 我们要的是出边(而非入边).

namespace boost {
  template <class vtype, class etype>
  inline std::pair<
    typename graph_traits< GRAPH<vtype,etype> >::out_edge_iterator,
    typename graph_traits< GRAPH<vtype,etype> >::out_edge_iterator >
  out_edges(
    typename graph_traits< GRAPH<vtype,etype> >::vertex_descriptor u,
    const GRAPH<vtype,etype>& g)
  {
    typedef typename graph_traits< GRAPH<vtype,etype> >
      ::out_edge_iterator Iter;
    return std::make_pair( Iter(First_Adj_Edge(u,0)), Iter(0) );
  }
} // namespace boost

其余的迭代器类型和接口函数都用与上文相同的技术构造. LEDA 包装接口的完整代码见 boost/graph/leda_graph.hpp. 在下面的代码中, 我们使用 BGL 概念检查来确保正确实现了 BGL 接口. 这些检查不测试实现的运行期行为; 运行期行为在 test/graph.cpp 中测试.

  #include <boost/graph/graph_concepts.hpp>
  #include <boost/graph/leda_graph.hpp>

  int
  main(int,char*[])
  {
    typedef GRAPH<int,int> Graph;
    BOOST_CONCEPT_ASSERT(( VertexListGraphConcept<Graph> ));
    BOOST_CONCEPT_ASSERT(( BidirectionalGraphConcept<Graph> ));
    BOOST_CONCEPT_ASSERT(( MutableGraphConcept<Graph> ));
    return 0;
  }
