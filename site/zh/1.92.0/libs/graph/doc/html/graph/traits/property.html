property<Tag, T, NextProperty>

把内部属性附加到 adjacency_list 或 adjacency_matrix 的旧式方式. 属性是一个(标签, 值, 其余)三元组; 第三个参数在同一附加点(顶点、边或图)串联更多属性.

定义于: <boost/pending/property.hpp>, 经 <boost/graph/properties.hpp> 重新导出.

对新代码, 优先使用 捆绑属性 — 它们是普通结构, 可读性好得多. 当你需要与查找知名标签的算法互操作时使用 property<>(例如标签 edge_weight_t), 或当你被要求显式声明 vertex_index_t(如 listS 顶点存储)时.

概要

namespace boost {

template <class Tag, class T, class NextProperty = no_property>
struct property : public NextProperty {
    typedef NextProperty next_type;
    typedef Tag          tag_type;
    typedef T            value_type;

    property();
    property(const T& v);
    property(const T& v, const NextProperty& b);

    T m_value;
};

} // namespace boost
模板参数 说明 默认值

Tag

诸如 edge_weight_t 的属性标签类型. 唯一命名该属性, 使算法能通过 get(Tag(), g) 找到它.

T

为每个顶点/边/图存储的此属性的值类型.

NextProperty

在同一附加点串联的另一个 property<…>, 或链尾的 no_property.

no_property

示例

// Nested `property<>` declarations let you stack multiple interior
// properties on a single kind (vertex, edge, or graph).
//
// New code should prefer bundled properties (structs) — see
// property_maps/bundled. Nested property<> is still needed when you
// want to coexist with algorithms that lookup a specific tag
// (e.g. edge_weight_t) OR when you need to declare vertex_index_t
// for a listS-based graph.

#include <boost/graph/adjacency_list.hpp>
#include <iostream>
#include <string>

using namespace boost;

// Two edge properties: weight (int) nested inside a name (string).
using EdgeProps =
    property<edge_weight_t, int,
    property<edge_name_t,   std::string>>;

using Graph = adjacency_list<vecS, vecS, directedS, no_property, EdgeProps>;

int main() {
    Graph g(3);
    // Values are supplied positionally, outermost tag first.
    add_edge(0, 1, EdgeProps(5, property<edge_name_t, std::string>("a->b")), g);
    add_edge(1, 2, EdgeProps(3, property<edge_name_t, std::string>("b->c")), g);

    auto w = get(edge_weight, g);
    auto n = get(edge_name,   g);

    for (auto e : make_iterator_range(edges(g))) {
        std::cout << get(n, e) << " weight=" << get(w, e) << '\n';
    }
}
a->b weight=5
b->c weight=3

最外层的 property<> 会最先被 add_edge 消费. 若你串联两个以上的属性, 语法(和编译错误)会糟糕到捆绑属性几乎总是更好的选择.

预定义属性标签

下面的标签声明在 <boost/graph/properties.hpp> 中. 每个标签 foo_t 都伴随一个该类型的常量, 写作 foo, 用作 get(foo, g) 的运行期实参.

顶点标签

标签 典型用途

vertex_index_t

[0, num_vertices(g)) 中的整数索引. 对 vecS 顶点存储自动提供; 对 listS / setS 你必须自己声明并填充.

vertex_name_t

顶点标签, 通常是 std::string.

vertex_color_t

BFS/DFS 类算法使用的遍历颜色.

vertex_distance_t

到源点的最短路径距离.

vertex_predecessor_t

最短路径树或生成树中的前驱顶点.

vertex_degree_t / vertex_in_degree_t / vertex_out_degree_t

缓存的或外部跟踪的度(很少需要作为内部属性).

vertex_current_degree_t, vertex_priority_t

Sloan 排序的工作映射.

vertex_discover_time_t, vertex_finish_time_t

DFS 事件时间戳.

vertex_rank_t, vertex_root_t

不相交集合的秩和双亲映射.

vertex_centrality_t

介数中心性值.

vertex_lowpoint_t

双连通分量低位点.

vertex_potential_t

最小费用流的对偶变量.

边标签

标签 典型用途

edge_weight_t

主边权重 / 长度 / 费用.

edge_index_t

边索引. 从不 自动 — 若任何算法需要边索引映射, 你必须在 add_edge 内自行声明并赋值.

edge_name_t

边标签.

edge_color_t

边遍历颜色.

edge_capacity_t, edge_residual_capacity_t, edge_reverse_t, edge_flow_t

最大流和最小费用流算法族所需的属性.

edge_centrality_t

边介数中心性(由 bc_clustering 使用).

edge_discover_time_t, edge_finished_t

DFS / 遍历标记.

图标签

标签 典型用途

graph_name_t

随图存储(GraphViz / GraphML I/O 使用).

graph_visitor_t

某些算法在内部使用的访问器覆盖.
BGL 还定义了捆绑标签(vertex_bundle_t、edge_bundle_t、graph_bundle_t)、*_all_t(附加在该点的所有内容), 以及用于分布式图的 *_global_t / *_local_t / *_owner_t. 你很少会直接点名这些.

成员

成员 说明

next_type

NextProperty 模板参数.

tag_type

Tag 模板参数.

value_type

T 模板参数.

property()

默认构造 m_value 和基类链. 要求链中的每个 T 都是 DefaultConstructible.

property(const T& v)

把 m_value 设置为 v; 其余默认.

property(const T& v, const NextProperty& b)

把 m_value 设置为 v, 并从 b 复制初始化其余部分.
