宏 BOOST_SCOPE_EXIT

BOOST_SCOPE_EXIT — 此宏声明一个作用域退出.

概要

// In header: <boost/scope_exit.hpp>

BOOST_SCOPE_EXIT(capture_list)

说明

作用域退出声明安排在退出外围作用域时执行作用域退出体:

{ // Some local scope.
    ...
    BOOST_SCOPE_EXIT(capture_list) {
        ... // Body code.
    } BOOST_SCOPE_EXIT_END
    ...
}

外围作用域必须是局部作用域. 如果在同一外围作用域内声明了多个作用域退出, 各作用域退出体会按其声明顺序的逆序执行. 注意作用域退出体的结尾必须用 BOOST_SCOPE_EXIT_END 标记.

参数:

capture_list 在支持可变参数宏的编译器上 (另见 Boost.Config BOOST_NO_CXX11_VARIADIC_MACROS), 捕获列表语法由以下文法定义: 
capture_list:
        void | capture_tuple | capture_sequence
capture_tuple:
        capture, capture, ...
capture_sequence:
        (capture) (capture) ...
capture:
        [&]variable | this_
在不支持可变参数宏的编译器上, capture_tuple 无法使用: 
capture_list:
        void | capture_sequence
此外, 如果 BOOST_SCOPE_EXIT_CONFIG_USE_LAMBDAS 在支持 lambda 函数的 C++11 编译器上已有定义 (即 Boost.Config 的 BOOST_NO_CXX11_LAMBDAS 未定义), 那么可以用分号 ; 来代替 BOOST_SCOPE_EXIT_END 且 this 可用来代替 this_: 
capture:
        [&]variable | this_ | this
(词法约定: token1 | token2 表示 token1 或 token2; [token] 表示 token 或空; {expression} 表示由该表达式产生的记号.)

注意, 在支持可变参数宏的编译器上 (大多数现代编译器和所有 C++11 编译器), 捕获列表可以指定为以逗号分隔的记号列表 (这是首选语法). 不过, 在所有编译器上, 同一个宏 BOOST_SCOPE_EXIT 也允许把捕获列表指定为 Boost.Preprocessor 记号序列 (用于支持无可变参数宏的编译器, 以及与本库较旧版本保持向后兼容).

每个被捕获变量的名称 variable 必须是外围作用域中的有效名称, 且在捕获列表中必须恰好出现一次. 如果捕获以与号 & 开头, 对应的变量将在作用域退出体内以引用方式可用; 否则, 会在作用域退出声明处创建该变量的一个副本, 该副本在作用域退出体内可用 (在这种情况下, 变量的类型必须是 CopyConstructible).

在成员函数内部, 对象 this 可以通过在捕获列表和作用域退出体中使用特殊名称 this_ 来捕获 (在作用域退出体中用 this 代替 this_ 会导致未定义行为).

可以把捕获列表指定为 void, 从而不捕获任何变量 (与是否支持可变参数宏无关).

在作用域退出体内只能使用捕获列表中列出的变量、静态变量、来自外围作用域的 extern 变量、全局变量、函数和枚举.

在各种 GCC 版本上, 在模板内必须使用特殊宏 BOOST_SCOPE_EXIT_TPL 来代替 BOOST_SCOPE_EXIT (为了最大可移植性, 建议在模板内始终使用 BOOST_SCOPE_EXIT_TPL).

在 C++11 上, 可以使用宏 BOOST_SCOPE_EXIT_ALL 捕获作用域内的所有变量, 而无需逐个列出其名称.

一般而言, 当需要在同一行上展开多个作用域退出声明时, 必须使用特殊宏 BOOST_SCOPE_EXIT_ID 来代替 BOOST_SCOPE_EXIT.

警告: 实现会在析构函数中执行作用域退出体, 因此为了符合 STL 异常安全要求, 作用域退出体绝不能抛出异常.

注释: 实现使用 Boost.Typeof 自动推导被捕获变量的类型. 为了在 type-of 模拟模式下编译代码, 所有类型都必须在 Boost.Typeof 中正确注册 (参见 入门 一节).
