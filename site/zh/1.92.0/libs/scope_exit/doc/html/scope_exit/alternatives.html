附录: 替代方案

本节介绍与 Boost.ScopeExit 相关的一些替代方案和相关工作.

Try-Catch

这是一个使用设计不佳的 file 类的示例. file 的实例不会在其析构函数中关闭文件, 程序员需要显式调用 close 成员函数. 例如 (另见 try_catch.cpp):

file passwd;
try {
    passwd.open("/etc/passwd");
    // ...
    passwd.close();
} catch(...) {
    std::clog << "could not get user info" << std::endl;
    if(passwd.is_open()) passwd.close();
    throw;
}

注意这种方式存在以下问题:

  1. passwd 对象定义在 try 块之外, 因为在 catch 块内需要该对象来关闭文件.
  2. passwd 对象直到 open 成员函数返回之后才完成构造.
  3. 如果打开文件时抛出异常, 则不应调用 passwd.close(), 因此有了对 passwd.is_open() 的调用.

Boost.ScopeExit 方式没有上述任何问题. 例如 (另见 try_catch.cpp):

try {
    file passwd("/etc/passwd");
    BOOST_SCOPE_EXIT(&passwd) {
        passwd.close();
    } BOOST_SCOPE_EXIT_END
} catch(...) {
    std::clog << "could not get user info" << std::endl;
    throw;
}

RAII

RAII 对于上文介绍的 file 类来说完美无缺. 使用一个设计得当的 file 类会是这样:

try {
    file passwd("/etc/passwd");
    // ...
} catch(...) {
    std::clog << "could not get user info" << std::endl;
    throw;
}

然而, 使用 RAII 来建立强保证可能引入大量不可复用的 RAII 类型. 例如:

persons_.push_back(a_person);
pop_back_if_not_commit pop_back_if_not_commit_guard(commit, persons_);

pop_back_if_not_commit 类要么定义在作用域之外, 要么定义为局部类:

class pop_back_if_not_commit {
    bool commit_;
    std::vector<person>& vec_;
    // ...
    ~pop_back_if_not_commit() {
        if(!commit_) vec_.pop_back();
    }
};

在某些情况下, 强保证可以用标准工具实现:

std::auto_ptr<Person> superman_ptr(new superman());
persons_.push_back(superman_ptr.get());
superman_ptr.release(); // persons_ successfully took ownership

或者使用专门的容器, 例如 Boost.PointerContainer 或 Boost.Multi-Index.

作用域守护

假设在执行事务之前引入了一种新汇率 (另见 []):

bool commit = false;
std::string currency("EUR");
double rate = 1.3326;
std::map<std::string, double> rates;
bool currency_rate_inserted =
        rates.insert(std::make_pair(currency, rate)).second;
// Transaction...

如果事务没有完成, 则必须从 rates 中删除该货币. 这可以用 ScopeGuard 和 Boost.Lambda (或 Boost.Phoenix) 来完成:

using namespace boost::lambda;

ON_BLOCK_EXIT(
    if_(currency_rate_inserted && !_1) [
        bind(
            static_cast<
                std::map<std::string, double>::size_type
                (std::map<std::string, double>::*)(std::string const&)
            >(&std::map<std::string, double>::erase)
          , &rates
          , currency
        )
    ]
  , boost::cref(commit)
  );

// ...

commit = true;

注意这种方式存在以下问题:

  1. Boost.Lambda 表达式很难正确编写 (例如, 如上例所示, 重载函数必须显式转换).
  2. if_ 表达式中的条件并非直接引用 commit 变量, 而是通过 _1 占位符间接引用, 这降低了可读性.
  3. 在 if_[...] 内部设置断点需要对 Boost.Lambda 以及调试技术有深入了解.

使用 C++11 lambda 后, 这段代码会好得多:

ON_BLOCK_EXIT(
    [currency_rate_inserted, &commit, &rates, &currency]() {
        if(currency_rate_inserted && !commit) rates.erase(currency);
    }
);

// ...

commit = true;

有了 Boost.ScopeExit, 我们只需按如下方式实现即可 (另见 scope_guard.cpp):

BOOST_SCOPE_EXIT(currency_rate_inserted, &commit, &rates, &currency) {
    if(currency_rate_inserted && !commit) rates.erase(currency);
} BOOST_SCOPE_EXIT_END

// ...

commit = true;

D 编程语言

Boost.ScopeExit 类似于 scope(exit) 这一内置于 D 语言的特性.

细心的读者可能会注意到, 本库并未实现 scope(success) 和 scope(failure) 这两个 D 语言结构. 遗憾的是, 这些在 C++ 中无法实现, 因为失败或成功条件无法通过调用 std::uncaught_exception 来判定 (Guru of the Week #47 详细讨论了 std::uncaught_exception 以及它究竟有没有好的用处). 不过, 这并不是什么大问题, 因为这两个 D 结构可以用 scope(exit) 加上一个 bool commit 变量来表达 (与本手册 教程 一节中的一些示例类似).

C++11 Lambda

使用 C++11 lambda 可以相对容易地实现 Boost.ScopeExit 结构. 例如 (另见 world_cxx11_lambda.cpp):

#include <functional>

struct scope_exit {
    scope_exit(std::function<void (void)> f) : f_(f) {}
    ~scope_exit(void) { f_(); }
private:
    std::function<void (void)> f_;
};

void world::add_person(person const& a_person) {
    bool commit = false;

    persons_.push_back(a_person);
    scope_exit on_exit1([&commit, this](void) { // Use C++11 lambda.
        if(!commit) persons_.pop_back(); // `persons_` via captured `this`.
    });

    // ...

    commit = true;
}

不过, 本库允许以在 C++03 与 C++11 编译器之间可移植的方式来编写 Boost.ScopeExit 结构.
