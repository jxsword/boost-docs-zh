本节说明如何使用本库.

捕获变量

假设我们想在某个 world 类的 world::add_person 成员函数中对该类的数据成员做大量修改. 我们先向 persons 向量添加一个新的 person 对象:

void world::add_person(person const& a_person) {
    bool commit = false;

    persons_.push_back(a_person);           // (1) direct action
    ...

后续的某些操作可能会抛出异常, 此时对相关对象的所有更改都应回滚. 这种全部完成或全部不做 (all-or-nothing) 的语义也称为 强保证.

特别地, 如果函数抛出异常, 最后添加的 person 必须从 persons_ 中删除. 我们所需做的只是在直接动作 (资源获取) 之后紧接着定义一个延迟动作 (资源释放). 例如 (另见 world.cpp):

void world::add_person(person const& a_person) {
    bool commit = false;

    persons_.push_back(a_person);           // (1) direct action
    // Following block is executed when the enclosing scope exits.
    BOOST_SCOPE_EXIT(&commit, &persons_) {
        if(!commit) persons_.pop_back();    // (2) rollback action
    } BOOST_SCOPE_EXIT_END

    // ...                                  // (3) other operations

    commit = true;                          // (4) disable rollback actions
}

点 (1) 之后的代码块是一条 Boost.ScopeExit 声明. 与点 (1) 不同, Boost.ScopeExit 体的执行将被延迟到当前作用域结束之时. 在本例中, 它将在点 (4) 之后或发生任何异常时执行. (在 GCC 编译器的各个版本上, 在模板内部必须使用 BOOST_SCOPE_EXIT_TPL 而非 BOOST_SCOPE_EXIT, 详情见本节后文.)

Boost.ScopeExit 声明以调用宏 BOOST_SCOPE_EXIT 开始, 该宏接受一个以逗号分隔的捕获变量列表 (在不支持可变参数宏的编译器上, 以及为向后兼容本库旧版本, 也接受 Boost.Preprocessor 序列, 见 无可变参数宏 一节). 如果捕获以 & 符号开头, 则 Boost.ScopeExit 体内将可以使用对被捕获变量的引用; 否则, 变量的副本将在 Boost.ScopeExit 声明处 (即点 (1)) 制作, 体内将只有该副本可用 (此时, 被捕获变量的类型必须是 CopyConstructible).

在上面的示例中, 变量 commit 和 persons_ 以引用方式捕获, 因为需要用 commit 变量的最终值来决定是否执行回滚动作, 并且该动作应当修改的是 persons_ 对象本身而非其副本. 这是最常见的情形, 但按值传递变量有时也同样有用.

最后, Boost.ScopeExit 体的结尾必须用宏 BOOST_SCOPE_EXIT_END 标记, 该宏必须紧跟在 } 之后, 也就是紧跟在 Boost.ScopeExit 体末尾的闭花括号之后.

重要

为符合 STL 异常安全要求, Boost.ScopeExit 体绝不能抛出异常 (因为本库的实现是在析构函数调用中执行该体的). 对于 C++03 和 C++11 上的所有 Boost.ScopeExit 宏 (包括下文将看到的 BOOST_SCOPE_EXIT_TPL 和 BOOST_SCOPE_EXIT_ALL) 都是如此.

考虑一个更复杂的例子, 其中 world::add_person 可以在某个时点保存中间状态, 并回滚到最后保存的状态. 我们用 person::evolution_ 来存储这些更改的一个版本号, 并通过递增它来取消与这些更改相关联的所有回滚动作. 如果我们按值传递 evolution_ 的当前值 (该值保存在 checkpoint 变量中), 那么它在 Boost.ScopeExit 体内保持不变, 这样我们就可以将它与 evolution_ 的最终值进行比较. 如果后者自我们保存以来未被递增, 则应执行 Boost.ScopeExit 体内的回滚动作. 例如 (另见 world_checkpoint.cpp):

void world::add_person(person const& a_person) {
    persons_.push_back(a_person);

    // This block must be no-throw.
    person& p = persons_.back();
    person::evolution_t checkpoint = p.evolution;
    BOOST_SCOPE_EXIT(checkpoint, &p, &persons_) {
        if(checkpoint == p.evolution) persons_.pop_back();
    } BOOST_SCOPE_EXIT_END

    // ...

    checkpoint = ++p.evolution;

    // Assign new identifier to the person.
    person::id_t const prev_id = p.id;
    p.id = next_id_++;
    BOOST_SCOPE_EXIT(checkpoint, &p, &next_id_, prev_id) {
        if(checkpoint == p.evolution) {
            next_id_ = p.id;
            p.id = prev_id;
        }
    } BOOST_SCOPE_EXIT_END

    // ...

    checkpoint = ++p.evolution;
}

当在同一外围作用域中声明了多个 Boost.ScopeExit 块时, 各 Boost.ScopeExit 体将按其声明的相反顺序执行.

捕获对象 this

在成员函数内部, 还可以捕获对象 this. 不过, 必须使用特殊符号 this_ 而非 this, 才能在 Boost.ScopeExit 声明和体中捕获并访问该对象. 例如 (另见 world_this.cpp):

BOOST_SCOPE_EXIT(&commit, this_) { // Capture object `this_`.
    if(!commit) this_->persons_.pop_back();
} BOOST_SCOPE_EXIT_END

无法以引用方式捕获对象 this_, 因为 C++ 不允许对 this 取引用. 如果外围成员函数是 const 的, 则被捕获的对象也是 const 的; 否则被捕获的对象是可变的.

不捕获任何变量

Boost.ScopeExit 声明也可以不捕获任何变量. 在这种情况下, 捕获变量列表用关键字 void 代替 (类似于 C++ 中用 result-type function-name(void) 声明无参数函数的语法). [3] 例如, 当 Boost.ScopeExit 体只需要访问全局变量时, 这会很有用 (另见 world_void.cpp):

struct world_t {
    std::vector<person> persons;
    bool commit;
} world; // Global variable.

void add_person(person const& a_person) {
    world.commit = false;
    world.persons.push_back(a_person);

    BOOST_SCOPE_EXIT(void) { // No captures.
        if(!world.commit) world.persons.pop_back();
    } BOOST_SCOPE_EXIT_END

    // ...

    world.commit = true;
}

(支持与不支持可变参数宏的编译器都使用这一相同的语法来表示不捕获任何变量, 更多信息见 无可变参数宏 一节.)

捕获所有变量 (仅限 C++11)

在 C++11 编译器上, 还可以使用特殊宏 BOOST_SCOPE_EXIT_ALL 代替 BOOST_SCOPE_EXIT, 无需逐一列举即可捕获作用域内的所有变量. [4]

按照 C++11 lambda 函数所采用的相同语法, 宏 BOOST_SCOPE_EXIT_ALL 接受一个以逗号分隔的捕获列表, 该列表必须以 & 或 = 开头, 分别表示按引用或按值捕获作用域内的所有变量 (注意, 这些前置捕获不指定任何变量名). 对特定变量的额外捕获可以跟在前置的 & 或 = 之后, 并且它们将覆盖默认的引用或值捕获. 例如 (另见 world_checkpoint_all.cpp):

void world::add_person(person const& a_person) {
    persons_.push_back(a_person);

    // This block must be no-throw.
    person& p = persons_.back();
    person::evolution_t checkpoint = p.evolution;
    // Capture all by reference `&`, but `checkpoint` and `this` (C++11 only).
    BOOST_SCOPE_EXIT_ALL(&, checkpoint, this) { // Use `this` (not `this_`).
        if(checkpoint == p.evolution) this->persons_.pop_back();
    }; // Use `;` (not `SCOPE_EXIT_END`).

    // ...

    checkpoint = ++p.evolution;

    // Assign new identifier to the person.
    person::id_t const prev_id = p.id;
    p.id = next_id_++;
    // Capture all by value `=`, but `p` (C++11 only).
    BOOST_SCOPE_EXIT_ALL(=, &p) {
        if(checkpoint == p.evolution) {
            this->next_id_ = p.id;
            p.id = prev_id;
        }
    };

    // ...

    checkpoint = ++p.evolution;
}

第一个 Boost.ScopeExit 声明按引用捕获作用域内的所有变量, 但变量 checkpoint 和对象 this 被显式按值捕获 (特别地, p 和 persons_ 在此处被隐式按引用捕获). 第二个 Boost.ScopeExit 声明则按值捕获作用域内的所有变量, 但 p 被显式按引用捕获 (特别地, checkpoint, prev_id 和 this 在此处被隐式按值捕获).

注意, 宏 BOOST_SCOPE_EXIT_ALL 遵循的是 C++11 lambda 函数语法, 遗憾的是它与宏 BOOST_SCOPE_EXIT 的语法不同. 特别是:

  1. 宏 BOOST_SCOPE_EXIT_ALL 在不捕获对象 this 的情况下无法捕获数据成员, 而宏 BOOST_SCOPE_EXIT 则无此限制. [5]
  2. 宏 BOOST_SCOPE_EXIT_ALL 使用 this 而非 this_ 来捕获作用域中的对象. [6]
  3. BOOST_SCOPE_EXIT_ALL 体以分号 ; 结束, 而不是以宏 BOOST_SCOPE_EXIT_END 结束.

如果程序员定义了配置宏 BOOST_SCOPE_EXIT_CONFIG_USE_LAMBDAS, 则宏 BOOST_SCOPE_EXIT 的实现将使用 C++11 lambda 函数, 并且宏 BOOST_SCOPE_EXIT 将采用与宏 BOOST_SCOPE_EXIT_ALL 相同的语法, 即 C++11 lambda 函数语法. 不过, BOOST_SCOPE_EXIT 将不再向后兼容, 使用 BOOST_SCOPE_EXIT 的旧代码可能无法再编译 (如果显式捕获了数据成员).

模板变通方案 (GCC)

GCC 编译器的多个版本无法在模板内部编译 BOOST_SCOPE_EXIT (更多信息见 参考 一节). 作为变通方案, 在这些情况下应使用 BOOST_SCOPE_EXIT_TPL 而非 BOOST_SCOPE_EXIT. [7] 宏 BOOST_SCOPE_EXIT_TPL 的语法与 BOOST_SCOPE_EXIT 完全相同. 例如 (另见 world_tpl.cpp):

template<typename Person>
void world<Person>::add_person(Person const& a_person) {
    bool commit = false;
    persons_.push_back(a_person);

    BOOST_SCOPE_EXIT_TPL(&commit, this_) { // Use `_TPL` postfix.
        if(!commit) this_->persons_.pop_back();
    } BOOST_SCOPE_EXIT_END

    // ...

    commit = true;
}

建议在模板内部始终使用 BOOST_SCOPE_EXIT_TPL, 以便在不同编译器之间获得最大的可移植性.

同行展开

一般而言, 宏 BOOST_SCOPE_EXIT, BOOST_SCOPE_EXIT_TPL, BOOST_SCOPE_EXIT_END 和 BOOST_SCOPE_EXIT_ALL 无法在同一行上展开多次. [8]

因此, 本库提供了附加宏 BOOST_SCOPE_EXIT_ID, BOOST_SCOPE_EXIT_ID_TPL, BOOST_SCOPE_EXIT_END_ID 和 BOOST_SCOPE_EXIT_ALL_ID, 只要程序员将一个唯一标识符指定为这些宏的第一个参数, 它们就可以在同一行上展开多次. 该唯一标识符可以是 C++ 预处理器能够拼接的任意记号 (不限于数字) (例如 scope_exit_number_1_at_line_123). [9]

宏 BOOST_SCOPE_EXIT_ID, BOOST_SCOPE_EXIT_ID_TPL 和 BOOST_SCOPE_EXIT_ALL_ID 接受捕获列表, 其语法分别与 BOOST_SCOPE_EXIT 和 BOOST_SCOPE_EXIT_ALL 完全相同. 例如 (另见 same_line.cpp):

#define SCOPE_EXIT_INC_DEC(variable, offset) \
    BOOST_SCOPE_EXIT_ID(BOOST_PP_CAT(inc, __LINE__), /* unique ID */ \
            &variable, offset) { \
        variable += offset; \
    } BOOST_SCOPE_EXIT_END_ID(BOOST_PP_CAT(inc, __LINE__)) \
    \
    BOOST_SCOPE_EXIT_ID(BOOST_PP_CAT(dec, __LINE__), \
            &variable, offset) { \
        variable -= offset; \
    } BOOST_SCOPE_EXIT_END_ID(BOOST_PP_CAT(dec, __LINE__))

#define SCOPE_EXIT_INC_DEC_TPL(variable, offset) \
    BOOST_SCOPE_EXIT_ID_TPL(BOOST_PP_CAT(inc, __LINE__), \
            &variable, offset) { \
        variable += offset; \
    } BOOST_SCOPE_EXIT_END_ID(BOOST_PP_CAT(inc, __LINE__)) \
    \
    BOOST_SCOPE_EXIT_ID_TPL(BOOST_PP_CAT(dec, __LINE__), \
            &variable, offset) { \
        variable -= offset; \
    } BOOST_SCOPE_EXIT_END_ID(BOOST_PP_CAT(dec, __LINE__))

#define SCOPE_EXIT_ALL_INC_DEC(variable, offset) \
    BOOST_SCOPE_EXIT_ALL_ID(BOOST_PP_CAT(inc, __LINE__), \
            =, &variable) { \
        variable += offset; \
    }; \
    BOOST_SCOPE_EXIT_ALL_ID(BOOST_PP_CAT(dec, __LINE__), \
            =, &variable) { \
        variable -= offset; \
    };

template<typename T>
void f(T& x, T& delta) {
    SCOPE_EXIT_INC_DEC_TPL(x, delta) // Multiple scope exits on same line.
    BOOST_TEST(x == 0);
}

int main(void) {
    int x = 0, delta = 10;

    {
        SCOPE_EXIT_INC_DEC(x, delta) // Multiple scope exits on same line.
    }
    BOOST_TEST(x == 0);

    f(x, delta);

#ifndef BOOST_NO_CXX11_LAMBDAS
    {
        SCOPE_EXIT_ALL_INC_DEC(x, delta) // Multiple scope exits on same line.
    }
    BOOST_TEST(x == 0);
#endif // LAMBDAS

    return boost::report_errors();
}

如上例所示, 当需要在用户自定义宏内多次调用 BOOST_SCOPE_EXIT_ID, BOOST_SCOPE_EXIT_ID_TPL, BOOST_SCOPE_EXIT_END_ID 和 BOOST_SCOPE_EXIT_ALL_ID 这些宏时, 它们特别有用 (因为 C++ 预处理器是在同一行上展开所有嵌套宏的).


[3] 设计理由. 遗憾的是, 无法以无参数形式直接调用 Boost.ScopeExit 宏, 即无法像 BOOST_SCOPE_EXIT() 那样调用, 因为当宏参数可能以非字母数字符号开头时 (按引用捕获变量 &variable 时即是如此), C++ 预处理器无法检测该参数是否为空.

[4] 设计理由. 宏 BOOST_SCOPE_EXIT_ALL 仅为未定义 Boost.Config 宏 BOOST_NO_CXX11_LAMBDAS 的 C++11 编译器而定义. 在 C++03 编译器上使用 BOOST_SCOPE_EXIT_ALL, 如果该编译器定义了 BOOST_NO_CXX11_LAMBDAS, 将产生 (可能晦涩难懂的) 编译器错误. 注意, 之所以需要引入新宏 BOOST_SCOPE_EXIT_ALL 而不复用 BOOST_SCOPE_EXIT, 是因为用 C++ 预处理器无法把 BOOST_SCOPE_EXIT(&) 和 BOOST_SCOPE_EXIT(=) 与 BOOST_SCOPE_EXIT(void) 或 BOOST_SCOPE_EXIT(this_) 区分开, 原因在于符号 & 和 = 的前后都没有字母数字记号 (对于宏 BOOST_SCOPE_EXIT_ALL 这不是问题, 因为其第一个捕获始终是非字母数字的 & 或 =, 因此对该宏而言, 第一个捕获的记号根本不会与 void 和 this_ 中的任何一个进行比较).

[5] 目前似乎已有一些讨论, 拟允许 C++11 lambda 函数在不捕获对象 this 的情况下捕获数据成员. 如果 C++11 标准将来被修改为允许这一点, 宏 BOOST_SCOPE_EXIT_ALL 的语法可以扩展为宏 BOOST_SCOPE_EXIT 的超集, 同时保持完全向后兼容.

[6] 在支持按 C++11 标准所允许的那样在模板之外使用 typename 的编译器上, BOOST_SCOPE_EXIT_ALL 既可以用 this 也可以用 this_ 来捕获作用域中的对象 (值得注意的是, MSVC 10.0 编译器并非如此).

[7] 设计理由. 符合 C++11 的 GCC 版本不存在这一问题, 并且鉴于 BOOST_SCOPE_EXIT_ALL 仅在 C++11 编译器上可用, 因此不需要 BOOST_SCOPE_EXIT_ALL_TPL 宏.

[8] 设计理由. 本库的宏在内部使用 __LINE__ 来生成唯一标识符. 因此, 如果同一个宏在同一行上被展开多于一次, 生成的标识符将不再唯一, 代码将无法编译. (这一限制不适用于 MSVC 以及其他提供非标准宏 __COUNTER__ 的编译器.)

[9] 由于 C++ 预处理器能够拼接的记号集合存在限制, 且并非所有编译器都正确实现了这些限制, 因此一般建议将唯一标识符指定为字母数字记号的组合.
