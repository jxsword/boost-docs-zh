本文档

程序员在阅读了 引言, 入门 和 教程 各节之后, 就应具备使用本库所需的足够知识. 参考 一节可在日后需要快速查阅时再行参考. 本文档的所有其他小节均可视为可选内容.

一些脚注以"设计理由"一词标示. 它们解释本库设计与实现过程中所作决策背后的原因.

在本文档给出的大多数示例中, 使用了 Boost.Detail/LightweightTest (boost/detail/lightweight_test.hpp) 宏 BOOST_TEST 来检查正确性条件. BOOST_TEST 宏在概念上类似于 assert, 但被检查条件失败时不会中止程序, 而是使 boost::report_errors 返回非零的程序退出码. [2]

编译器与平台

作者最初在 Linux, Cygwin 和 Windows 7 下, 使用 GNU 编译器套件 (GCC) C++ 3.3, 3.4, 4.1, 4.2, 4.5.3 (带与不带 C++11 特性 -std=c++0x), Microsoft Visual C++ (MSVC) 8.0 以及 Intel 10.1 开发并测试了本库. 不过, 除以下情况外, 本库应当可用于任何支持 Boost.Typeof 的编译器:

  • 如果包含 Boost.ScopeExit 的函数被多个翻译单元包含, 则 MSVC 7.1 和 8.0 将无法链接.
  • GCC 3.3 无法编译位于模板内部的 Boost.ScopeExit (详情参见 http://lists.boost.org/Archives/boost/2007/02/116235.php).

支持的编译器和平台的详细信息请参见本库的 回归测试结果. 请查看本库回归测试的 Jamfile.v2, 了解特定编译器可能需要的特殊配置.

安装

本库仅由头文件组成, 因此没有需要安装的预编译目标文件. 程序员只需告知编译器到哪里查找本库的头文件 (GCC 上是 -I 选项, MSVC 上是 /I 选项, 等等), 然后编译使用本库的代码即可.

本库的实现使用 Boost.Typeof 自动推导 Boost.ScopeExit 所捕获变量的类型 (参见 教程 一节). 要以 type-of 模拟 模式编译代码, 所有类型都应使用 BOOST_TYPEOF_REGISTER_TYPE 和 BOOST_TYPEOF_REGISTER_TEMPLATE 正确注册, 或者应包含相应的 Boost.Typeof 头文件 (参见本文档大多数示例的源代码).


[2] 设计理由. 使用 Boost.Detail/LightweightTest 可以把这些示例加入本库回归测试, 从而确保它们始终能够正确编译和运行.
