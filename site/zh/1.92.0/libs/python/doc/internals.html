  1. 当你执行以下操作时会发生什么:

    struct boring {};
...etc...
class_<boring>("boring")
    ;

看起来有不少事情在进行.

  • Python 需要注册一个新的 ClassType.
  • 我们需要构造一个能容纳我们那个乏味结构体 (boring) 的新类型.
  • 需要为该类型注册向内和向外转换器.

你能大致指点一下这些事情都在哪里完成吗?

我现在只有时间给出一个 "凭印象" 的回答; 我建议你读完之后用调试器单步执行代码, 看看它如何工作, 补充细节, 并确认我没有漏掉什么.

通过调用元类型 Boost.Python.class, 创建 Boost.Python.Instance 的一个新 (Python) 子类 (见 libs/python/src/object/class.cpp):

>>> boring = Boost.Python.class(
...     'boring'
...   , bases_tuple       # in this case, just ()
...   , { 
...         '__module__' : module_name
...       , '__doc__' : doc_string # optional
...     }
... )

该对象的句柄被塞入与 typeid(boring) 相关联的注册项的 m_class_object 字段中. 注册表会永远让该对象存活, 即使你抹掉扩展模块的 'boring' 属性 (这可能不是件好事).

因为你没有指定 class<boring, non_copyable, ...>, 为 boring 注册了一个到 Python 转换器, 它把其参数复制到由 Python boring 对象持有的 value_holder 中.

因为你没有指定 class<boring ...>(no_init), 一个 __init__ 函数对象被加入类字典, 它在由 Python boring 对象持有的 value_holder (因为你没有指定某个智能指针或派生包装器类作为持有器) 中默认构造一个 boring.

register_class_from_python 用于为 shared_ptr<boring> 注册一个从 Python 转换器. boost::shared_ptr 在智能指针中很特别, 因为它们的 Deleter 参数可以被用来管理整个 Python 对象, 而不仅仅是它包含的 C++ 对象, 无论 C++ 对象是如何被持有的.

如果有 bases<>, 我们还会在上/下转型图 (inheritance.[hpp/cpp]) 中注册这些基类与 boring 之间的关系.

在代码的早期版本中, 我们会在这里为该类注册左值从 Python 转换器, 但现在, 如果源 Python 对象的元类是 Boost.Python 元类, 被包装类的从 Python 转换会在查询注册表之前作为特殊情况处理.

嗯, 那个从 Python 转换器也许应当按类转换器的方式处理, 不注册任何显式转换.

从 C++ 到 Python:

这取决于类型以及所用的调用策略, 或者对 call<>(...)、call_method<>(...) 或 object(...) 而言, 取决于是否使用了 ref 或 ptr. 到 Python 转换还有两个基本类别: "返回值" 转换 (用于 Python->C++ 调用) 和 "参数" 转换 (用于 C++->Python 调用和显式 object() 转换). 这两个类别的行为在多个方面有微妙差别, 细节我一时想不起来. 你或许能在上面的参考文献中找到答案, 在代码中肯定能找到.

"默认" 情形是按值 (复制) 转换, 它使用 to_python_value 作为到 Python 转换器.

既然合理地讲任何类型到 Python 只能有一种转换方式 (暂时不考虑作用域化注册表的想法), 到 Python 转换可以通过特化模板来处理就在情理之中. 如果该类型是内建转换 (builtin_converters.hpp) 所处理的类型之一, 就会使用 to_python_value 的相应模板特化.

否则, to_python_value 使用该 C++ 类型注册项中的 m_to_python 函数.

其他转换, 如按引用转换, 仅对被包装类可用, 并且通过使用 ref(...)、ptr(...) 或为调用指定不同的 CallPolicies 来显式请求, 后者可能导致使用不同的到 Python 转换器. 这些转换从不在任何地方注册, 但它们确实需要使用注册项来查找被引用 C++ 类型对应的 Python 类. 它们只是构建一个新的 Python 实例, 并把适当的 Holder 实例塞进去.

从 Python 到 C++:

我再次认为 "返回值" 转换与 "参数" 转换之间有区别, 而我忘了区别究竟是什么.

发生什么取决于是否需要左值转换 (见 http://mail.python.org/pipermail/c++-sig/2002-May/001023.html). 所有左值转换也注册在类型的右值转换链中, 因为当右值可以奏效时, 左值肯定也足够好.

左值转换可以一步完成 (只要给我指向对象的指针——如果无法转换, 它可以是 NULL), 而右值转换需要两步, 以支持被包装函数重载和给定 C++ 目标类型的多个转换器: 第一步告诉我转换是否可能, 然后第二步构造转换后的对象.
