这里介绍一些用 Boost.Python 包装代码时可以使用的实用技巧.

创建包

Python 包是向用户提供某种功能的模块集合. 如果你不熟悉如何创建包, Python 教程 中提供了很好的介绍.

但我们是在用 Boost.Python 包装 C++ 代码. 我们如何向用户提供一个漂亮的包接口? 为了更好地解释一些概念, 让我们通过一个例子来演练.

我们有一个处理声音的 C++ 库: 读写各种格式, 对声音数据应用滤波器等. 它 (恰如其分地) 命名为 sounds. 我们的库已经有整洁的 C++ 命名空间层次结构, 如下:

sounds::core
sounds::io
sounds::filters

我们想向 Python 用户呈现同样的层次结构, 让他能写出这样的代码:

import sounds.filters
sounds.filters.echo(...) # echo is a C++ function

第一步是编写包装代码. 我们必须用 Boost.Python 分别导出每个模块, 像这样:

/* file core.cpp */
BOOST_PYTHON_MODULE(core)
{
    /* export everything in the sounds::core namespace */
    ...
}

/* file io.cpp */
BOOST_PYTHON_MODULE(io)
{
    /* export everything in the sounds::io namespace */
    ...
}

/* file filters.cpp */
BOOST_PYTHON_MODULE(filters)
{
    /* export everything in the sounds::filters namespace */
    ...
}

编译这些文件将生成以下 Python 扩展: core.pyd、io.pyd 和 filters.pyd.

注释

扩展 .pyd 用于 Python 扩展模块, 它们只是共享库. 使用你系统的默认值, 比如 Unix 上用 .so、Windows 上用 .dll, 也同样可行.

现在, 我们为 Python 包创建这个目录结构:

sounds/
    __init__.py
    core.pyd
    filters.pyd
    io.pyd

文件 __init__.py 告诉 Python 目录 sounds/ 实际上是一个 Python 包. 它可以是空文件, 但也可以执行一些魔法, 稍后会展示.

现在我们的包就绪了. 用户要做的只是把 sounds 放入其 PYTHONPATH 并启动解释器:

>>> import sounds.io
>>> import sounds.filters
>>> sound = sounds.io.open('file.mp3')
>>> new_sound = sounds.filters.echo(sound, 1.0)

不错吧?

这是创建包层次结构的最简单方式, 但不够灵活. 例如, 如果我们想给 filters 包添加一个纯 Python 函数——比如一个一次性对声音对象应用 3 个滤波器的函数——怎么办? 当然, 你可以在 C++ 中实现并导出它, 但为什么不用 Python 呢? 你无需重新编译扩展模块, 而且写起来也更容易.

如果我们想要这种灵活性, 就得稍微复杂化包层次结构. 首先, 我们必须更改扩展模块的名称:

/* file core.cpp */
BOOST_PYTHON_MODULE(_core)
{
    ...
    /* export everything in the sounds::core namespace */
}

注意我们在模块名中加了下划线. 文件名也必须改为 _core.pyd, 我们对其他扩展模块做同样的处理. 现在, 我们像这样更改包层次结构:

sounds/
    __init__.py
    core/
        __init__.py
        _core.pyd
    filters/
        __init__.py
        _filters.pyd
    io/
        __init__.py
        _io.pyd

注意, 我们为每个扩展模块创建了一个目录, 并给每个目录添加了 __init__.py. 但如果保持原样, 用户将不得不用这种语法访问 core 模块中的函数:

>>> import sounds.core._core
>>> sounds.core._core.foo(...)

这不是我们想要的. 但这时 __init__.py 的魔法登场: 带入 __init__.py 命名空间的一切都可以被用户直接访问. 所以, 我们要做的只是把 _core.pyd 的整个命名空间带到 core/__init__.py. 为此在 sounds/core/__init__.py 中加入这行代码:

from _core import *

我们对其他包做同样的处理. 现在用户像以前那样访问扩展模块中的函数和类:

>>> import sounds.filters
>>> sounds.filters.echo(...)

附带的好处是, 我们可以轻松地向任何模块添加纯 Python 函数, 用户无法分辨 C++ 函数与 Python 函数. 让我们添加一个纯 Python 函数 echo_noise 到 filters 包. 该函数按顺序把 echo 和 noise 滤波器都应用到给定的 sound 对象上. 我们创建一个名为 sounds/filters/echo_noise.py 的文件并编写函数:

import _filters
def echo_noise(sound):
    s = _filters.echo(sound)
    s = _filters.noise(sound)
    return s

接下来, 把这行代码加入 sounds/filters/__init__.py:

from echo_noise import echo_noise

就是这样. 用户现在可以像访问 filters 包中的其他函数一样访问这个函数:

>>> import sounds.filters
>>> sounds.filters.echo_noise(...)

在 Python 中扩展被包装对象

多亏 Python 的灵活性, 你可以轻松地为类添加新方法, 即使它已经创建:

>>> class C(object): pass
>>>
>>> # a regular function
>>> def C_str(self): return 'A C instance!'
>>>
>>> # now we turn it in a member function
>>> C.__str__ = C_str
>>>
>>> c = C()
>>> print c
A C instance!
>>> C_str(c)
A C instance!

是的, Python 棒极了.

对用 Boost.Python 包装的类, 我们也可以这样做. 假设我们在 C++ 中有一个类 point:

class point {...};

BOOST_PYTHON_MODULE(_geom)
{
    class_<point>("point")...;
}

如果我们使用上一节 (创建包) 的技术, 可以直接在 geom/__init__.py 中写代码:

from _geom import *

# a regular function
def point_str(self):
    return str((self.x, self.y))

# now we turn it into a member function
point.__str__ = point_str

所有从 C++ 创建的 point 实例也将拥有这个成员函数! 这一技术有几个优点:

  • 这些附加函数的编译时间降为零
  • 把内存占用几乎降为零
  • 把重新编译的需求降到最低
  • 快速原型 (如有需要可以把代码移到 C++ 而无需更改接口)

另一个有用的想法是用工厂函数替代构造函数:

_point = point

def point(x=0, y=0):
    return _point(x, y)

在这个简单的例子里收益不大, 但对有许多重载和/或参数的构造函数而言, 这通常是极大的简化, 同样几乎零内存占用, 且关键字支持的编译期开销为零.

缩短编译时间

如果你曾经导出过大量类, 你知道编译 Boost.Python 包装器要花相当长的时间. 此外内存消耗也很容易变得过高. 如果这给你造成困扰, 你可以把 class_ 定义拆分到多个文件中:

/* file point.cpp */
#include <point.h>
#include <boost/python.hpp>

void export_point()
{
    class_<point>("point")...;
}

/* file triangle.cpp */
#include <triangle.h>
#include <boost/python.hpp>

void export_triangle()
{
    class_<triangle>("triangle")...;
}

现在你创建一个文件 main.cpp, 其中包含 BOOST_PYTHON_MODULE 宏, 并在其中调用各个导出函数.

void export_point();
void export_triangle();

BOOST_PYTHON_MODULE(_geom)
{
    export_point();
    export_triangle();
}

一起编译并链接所有这些文件, 产生的结果与常规方法相同:

#include <boost/python.hpp>
#include <point.h>
#include <triangle.h>

BOOST_PYTHON_MODULE(_geom)
{
    class_<point>("point")...;
    class_<triangle>("triangle")...;
}

但内存保持在可控范围.

如果你正在开发 C++ 库并同时把它导出到 Python, 也推荐这种方法: 对一个类的修改只需编译单个 cpp, 而不是整个包装代码.

注释

如果在编译大型源文件时收到错误消息 "fatal error C1204:Compiler limit:internal structure overflow", 这种方法也很有用, 如常见问题 (FAQ)中所述.
