现在让我们把一个 C++ 类暴露给 Python.

考虑一个我们想暴露给 Python 的 C++ 类/结构体:

struct World
{
    void set(std::string msg) { this->msg = msg; }
    std::string greet() { return msg; }
    std::string msg;
};

我们可以通过编写对应的 Boost.Python C++ 包装器把它暴露给 Python:

#include <boost/python.hpp>
using namespace boost::python;

BOOST_PYTHON_MODULE(hello)
{
    class_<World>("World")
        .def("greet", &World::greet)
        .def("set", &World::set)
    ;
}

这里, 我们编写了一个 C++ 类包装器, 暴露成员函数 greet 和 set. 现在, 把我们的模块构建为共享库之后, 就可以在 Python 中使用我们的类 World. 下面是一个 Python 会话示例:

>>> import hello
>>> planet = hello.World()
>>> planet.set('howdy')
>>> planet.greet()
'howdy'

构造函数

我们前面的例子没有任何显式构造函数. 由于 World 被声明为普通结构体, 它有一个隐式默认构造函数. Boost.Python 默认暴露默认构造函数, 这正是我们能够写出

>>> planet = hello.World()

我们可能想包装一个带非默认构造函数的类. 让我们在前面的例子上继续:

struct World
{
    World(std::string msg): msg(msg) {} // added constructor
    void set(std::string msg) { this->msg = msg; }
    std::string greet() { return msg; }
    std::string msg;
};

这次 World 没有默认构造函数; 当库试图暴露它时, 我们之前的包装代码将无法编译. 我们必须改为告诉 class_<World> 我们想暴露的构造函数.

#include <boost/python.hpp>
using namespace boost::python;

BOOST_PYTHON_MODULE(hello)
{
    class_<World>("World", init<std::string>())
        .def("greet", &World::greet)
        .def("set", &World::set)
    ;
}

init<std::string>() 暴露接受 std::string 的构造函数 (在 Python 中, 构造函数写作 ""__init__"").

我们可以通过传入更多 init<...> 给 def() 成员函数来暴露额外的构造函数. 例如, 假设我们有另一个接受两个 double 的 World 构造函数:

class_<World>("World", init<std::string>())
    .def(init<double, double>())
    .def("greet", &World::greet)
    .def("set", &World::set)
;

另一方面, 如果我们根本不想暴露任何构造函数, 可以改用 no_init:

class_<Abstract>("Abstract", no_init)

这实际上添加了一个 __init__ 方法, 它总是引发 Python RuntimeError 异常.

类数据成员

数据成员也可以暴露给 Python, 使它们可以作为相应 Python 类的属性来访问. 我们希望暴露的每个数据成员都可视为只读或读写. 考虑这个类 Var:

struct Var
{
    Var(std::string name) : name(name), value() {}
    std::string const name;
    float value;
};

我们的 C++ Var 类及其数据成员可以暴露给 Python:

class_<Var>("Var", init<std::string>())
    .def_readonly("name", &Var::name)
    .def_readwrite("value", &Var::value);

然后, 在 Python 中, 假设我们像之前那样把 Var 类放在 hello 命名空间中:

>>> x = hello.Var('pi')
>>> x.value = 3.14
>>> print x.name, 'is around', x.value
pi is around 3.14

注意, name 暴露为只读, 而 value 暴露为读写.

>>> x.name = 'e' # can't change name
Traceback (most recent call last):
  File "<stdin>", line 1, in ?
AttributeError: can't set attribute

类属性

在 C++ 中, 带公有数据成员的类通常不被看好. 善用封装的精心设计的类会隐藏类的数据成员. 访问类数据的唯一途径是访问 (getter/setter) 函数. 访问函数暴露类的属性. 下面是一个例子:

struct Num
{
    Num();
    float get() const;
    void set(float value);
    ...
};

然而, 在 Python 中属性访问没问题; 让用户直接处理属性不一定破坏封装, 因为属性可以只是方法调用的另一种语法. 使用 Boost.Python 包装我们的 Num 类:

class_<Num>("Num")
    .add_property("rovalue", &Num::get)
    .add_property("value", &Num::get, &Num::set);

最后, 在 Python 中:

>>> x = Num()
>>> x.value = 3.14
>>> x.value, x.rovalue
(3.14, 3.14)
>>> x.rovalue = 2.17 # error!

注意, 类属性 rovalue 暴露为只读, 因为没有传入 rovalue setter 成员函数:

.add_property("rovalue", &Num::get)

继承

在前面的例子中, 我们处理的是非多态的类. 但情况往往不是这样. 很多时候, 我们要包装的是多态类以及由继承关联起来的类层次结构. 我们经常要为派生自抽象基类的类编写 Boost.Python 包装器.

考虑这个简单的继承结构:

struct Base { virtual ~Base(); };
struct Derived : Base {};

以及一组操作 Base 和 Derived 对象实例的 C++ 函数:

void b(Base*);
void d(Derived*);
Base* factory() { return new Derived; }

我们已经看到如何包装基类 Base:

class_<Base>("Base")
    /*...*/
    ;

现在我们可以把 Derived 与其基类 Base 之间的继承关系告知 Boost.Python. 如下:

class_<Derived, bases<Base> >("Derived")
    /*...*/
    ;

这样做之后, 我们免费得到一些好处:

  1. Derived 自动继承 Base 的全部 Python 方法 (被包装的 C++ 成员函数)
  2. 如果 Base 是多态的, Derived 对象——已经通过指向 Base 的指针或引用传给 Python——可以在期望指向 Derived 的指针或引用之处传入.

现在, 我们将暴露 C++ 自由函数 b、d 和 factory:

def("b", b);
def("d", d);
def("factory", factory);

注意, 自由函数 factory 被用来生成类 Derived 的新实例. 在这种情况下, 我们用 return_value_policy<manage_new_object> 指示 Python 接管指向 Base 的指针, 并把该实例保存在一个新的 Python Base 对象中, 直到该 Python 对象销毁. 稍后我们会更多地了解 Boost.Python 的调用策略.

// Tell Python to take ownership of factory's result
def("factory", factory,
    return_value_policy<manage_new_object>());

类虚函数

在本节中, 我们将学习如何通过虚函数让函数表现出多态行为. 继续我们的例子, 给 Base 类添加一个虚函数:

struct Base
{
    virtual ~Base() {}
    virtual int f() = 0;
};

Boost.Python 的目标之一是对既有 C++ 设计的侵入最小化. 原则上, 应当可以在不改动第三方库的情况下暴露其接口. 向我们的类 Base 添加任何东西都不理想. 然而, 当你有一个将在 Python 中被改写、并从 C++多态调用的虚函数时, 我们需要添加一些支架代码让一切正常工作. 我们要做的, 是编写一个派生自 Base 的类包装器, 它将以非侵入方式挂接虚函数, 使得可以调用 Python 改写:

struct BaseWrap : Base, wrapper<Base>
{
    int f()
    {
        return this->get_override("f")();
    }
};

还要注意, 除了从 Base 继承之外, 我们还多重继承了 wrapper<Base> (参见Wrapper). wrapper 模板让包装打算在 Python 中被改写的类这一工作变得更容易.

MSVC6/7 变通办法

如果你使用 Microsoft Visual C++ 6 或 7, 必须把 f 写成:

return call<int>(this->get_override("f").ptr());.

BaseWrap 被改写的虚成员函数 f 实际上通过 get_override 调用 Python 对象的相应方法.

最后, 暴露 Base:

class_<BaseWrap, boost::noncopyable>("Base")
    .def("f", pure_virtual(&Base::f))
    ;

pure_virtual 向 Boost.Python 表明函数 f 是纯虚函数.

注释

成员函数与方法

与许多面向对象语言一样, Python 使用方法一词. 方法大致对应 C++ 的成员函数

带默认实现的虚函数

我们在前一节已经看到带纯虚函数的类如何用 Boost.Python 的类包装器设施包装. 如果我们想包装的不是纯虚函数, 机制稍有不同.

回想前一节中, 我们包装了一个带纯虚函数的类, 该函数随后由 C++ 或派生的 Python 类实现. 我们的基类:

struct Base
{
    virtual int f() = 0;
};

有一个纯虚函数 f. 然而, 如果其成员函数 f 未被声明为纯虚:

struct Base
{
    virtual ~Base() {}
    virtual int f() { return 0; }
};

我们这样包装它:

struct BaseWrap : Base, wrapper<Base>
{
    int f()
    {
        if (override f = this->get_override("f"))
            return f(); // *note*
        return Base::f();
    }

    int default_f() { return this->Base::f(); }
};

注意我们如何实现 BaseWrap::f. 现在, 我们必须检查 f 是否有改写. 如果没有, 就调用 Base::f().

MSVC6/7 变通办法

如果你使用 Microsoft Visual C++ 6 或 7, 必须把带有 *note* 的那一行改写为:

return call<char const*>(f.ptr());.

最后, 暴露:

class_<BaseWrap, boost::noncopyable>("Base")
    .def("f", &Base::f, &BaseWrap::default_f)
    ;

注意我们同时暴露 &Base::f 和 &BaseWrap::default_f. Boost.Python 需要跟踪 1) 分派函数 f 和 2) 转发到其默认实现的函数 default_f. 为此有一个特殊的 def 函数.

在 Python 中, 结果会符合预期:

>>> base = Base()
>>> class Derived(Base):
...     def f(self):
...         return 42
...
>>> derived = Derived()

调用 base.f():

>>> base.f()
0

调用 derived.f():

>>> derived.f()
42

类运算符/特殊函数

Python 运算符

C 语言以运算符丰富而闻名. C++ 通过允许运算符重载把这一点推向极致. Boost.Python 利用这一点, 使包装满载运算符的 C++ 类变得容易.

考虑一个文件位置类 FilePos 和一组作用于 FilePos 实例的运算符:

class FilePos { /*...*/ };

FilePos     operator+(FilePos, int);
FilePos     operator+(int, FilePos);
int         operator-(FilePos, FilePos);
FilePos     operator-(FilePos, int);
FilePos&    operator+=(FilePos&, int);
FilePos&    operator-=(FilePos&, int);
bool        operator<(FilePos, FilePos);

这个类和各种运算符可以相当容易而直观地映射到 Python:

class_<FilePos>("FilePos")
    .def(self + int())          // __add__
    .def(int() + self)          // __radd__
    .def(self - self)           // __sub__
    .def(self - int())          // __sub__
    .def(self += int())         // __iadd__
    .def(self -= other<int>())
    .def(self < self);          // __lt__

上面的代码片段非常清晰, 几乎不需要任何解释. 它与运算符的签名几乎相同. 只需注意 self 指 FilePos 对象. 此外, 并非你可能在运算符表达式中与之交互的每个类 T 都是 (廉价) 可默认构造的. 编写 "self 表达式" 时, 你可以用 other<T>() 代替实际的 T 实例.

特殊方法

Python 还有几个特殊方法. Boost.Python 支持真正的 Python 类实例所支持的全部标准特殊方法名. 一组类似的直观接口也可用于包装对应这些 Python 特殊函数的 C++ 函数. 例如:

class Rational
{ public: operator double() const; };

Rational pow(Rational, Rational);
Rational abs(Rational);
ostream& operator<<(ostream&,Rational);

class_<Rational>("Rational")
    .def(float_(self))                  // __float__
    .def(pow(self, other<Rational>))    // __pow__
    .def(abs(self))                     // __abs__
    .def(str(self))                     // __str__
    ;
