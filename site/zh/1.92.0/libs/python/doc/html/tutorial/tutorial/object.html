Python 是动态类型的, 不像静态类型的 C++. Python 变量可以持有整数、浮点数、list、dict、tuple、str、long 等. 在 Boost.Python 与 C++ 的视角中, 这些 Python 式变量只是类 object 的实例. 本章我们将看到如何处理 Python 对象.

如前所述, Boost.Python 的目标之一是在保持 Python 风格的同时提供 C++ 与 Python 之间的双向映射. Boost.Python 的 C++ object 尽可能贴近 Python. 这应当能显著减少学习曲线.

基本接口

类 object 包装 PyObject*. 处理 PyObject 的种种复杂之处——比如管理引用计数——都由 object 类处理. C++ 对象互操作是无缝的. 事实上, Boost.Python 的 C++ object 可以从任何 C++ 对象显式构造.

为了说明, 看这段 Python 代码片段:

def f(x, y):
     if (y == 'foo'):
         x[3:7] = 'bar'
     else:
         x.items += y(3, x)
     return x

def getfunc():
   return f;

可以用 Boost.Python 设施以如下方式用 C++ 重写:

object f(object x, object y) {
     if (y == "foo")
         x.slice(3,7) = "bar";
     else
         x.attr("items") += y(3, x);
     return x;
}
object getfunc() {
    return object(f);
}

除了因为用 C++ 写代码而带来的表面差异之外, Python 程序员应当能立即认出其外观和手感.

派生对象类型

Boost.Python 自带一组与 Python 对应的派生 object 类型:

  • list
  • dict
  • tuple
  • str
  • long_
  • enum

这些派生 object 类型的行为就像真正的 Python 类型. 例如:

str(1) ==> "1"

在适当之处, 特定的派生 object 具有对应 Python 类型的方法. 例如, dict 有一个 keys() 方法:

d.keys()

提供 make_tuple 用于声明元组字面量. 例如:

make_tuple(123, 'D', "Hello, World", 0.0);

在 C++ 中, 当 Boost.Python object 用作函数参数时, 需要子类型匹配. 例如, 当如下声明的函数 f 被包装时, 它只接受 Python 的 str 类型及其子类型的实例.

void f(str name)
{
    object n2 = name.attr("upper")();   // NAME = name.upper()
    str NAME = name.upper();            // better
    object msg = "%s is bigger than %s" % make_tuple(NAME,name);
}

更细致地说:

str NAME = name.upper();

说明我们以 C++ 成员函数的形式提供了 str 类型方法的版本.

object msg = "%s is bigger than %s" % make_tuple(NAME,name);

演示你可以写出 "format" % x,y,z 在 Python 中的 C++ 等价物, 这很有用, 因为在标准 C++ 中没有容易的办法做到这一点.

当心一个常见陷阱: 忘记大多数 Python 可变类型的构造函数会制作副本, 就像在 Python 中一样.

Python: 

>>> d = dict(x.__dict__)     # copies x.__dict__
>>> d['whatever'] = 3        # modifies the copy

C++: 

dict d(x.attr("__dict__"));  // copies x.__dict__
d['whatever'] = 3;           // modifies the copy

作为对象的 class_<T>

由于 Boost.Python 对象的动态本性, 任何 class_<T> 也可能是这些类型之一! 下面的代码片段包装了类 (类型) 对象.

我们可以用它创建被包装的实例. 例如:

object vec345 = (
    class_<Vec2>("Vec2", init<double, double>())
        .def_readonly("length", &Point::length)
        .def_readonly("angle", &Point::angle)
    )(3.0, 4.0);

assert(vec345.attr("length") == 5.0);

提取 C++ 对象

某个时候, 我们需要从 object 实例中取出 C++ 值. 这可以用 extract<T> 函数实现. 考虑以下代码:

double x = o.attr("length"); // compile error

在上面的代码中, 我们遇到了编译错误, 因为 Boost.Python object 不能隐式转换为 double. 上面想做的事情可以这样写来实现:

double l = extract<double>(o.attr("length"));
Vec2& v = extract<Vec2&>(o);
assert(l == v.length());

第一行尝试提取 Boost.Python object 的 "length" 属性. 第二行尝试提取 Vec2 对象——由 Boost.Python object 所持有.

注意我们上面说的是 "尝试". 如果 Boost.Python object 实际上并不持有 Vec2 类型怎么办? 鉴于 Python object 的动态本性, 这当然有可能. 保险起见, 如果无法提取 C++ 类型, 将抛出适当的异常. 为避免异常, 我们需要测试可提取性:

extract<Vec2&> x(o);
if (x.check()) {
    Vec2& v = x(); ...

敏锐的读者可能已经注意到, extract<T> 设施实际上解决了可变复制问题:

dict d = extract<dict>(x.attr("__dict__"));
d["whatever"] = 3;          // modifies x.__dict__ !

枚举

Boost.Python 有一个巧妙的设施来捕获并包装 C++ 枚举. 虽然 Python 没有 enum 类型, 我们常常想把 C++ 枚举作为 int 暴露给 Python. Boost.Python 的枚举设施使这变得容易, 同时处理好从 Python 动态类型到 C++ 强静态类型的正确转换 (在 C++ 中, int 不能隐式转换为枚举). 为了说明, 给定一个 C++ 枚举:

enum choice { red, blue };

如下构造:

enum_<choice>("choice")
    .value("red", red)
    .value("blue", blue)
    ;

可用于暴露给 Python. 新的枚举类型在当前 scope() 中创建, 它通常是当前模块. 上面的代码片段创建了一个派生自 Python 的 int 类型的 Python 类, 该类与作为其第一个参数传入的 C++ 类型相关联.

注释

什么是作用域?

scope 是一个类, 它有一个关联的全局 Python 对象, 该对象控制新的扩展类和被包装函数将以属性形式定义于其中的 Python 命名空间. 细节可在此处找到.

你可以在 Python 中这样访问这些值

>>> my_module.choice.red
my_module.choice.red

其中 my_module 是声明枚举的模块. 你还可以在类周围创建一个新的作用域:

scope in_X = class_<X>("X")
                .def( ... )
                .def( ... )
            ;

// Expose X::nested as X.nested
enum_<X::nested>("nested")
    .value("red", red)
    .value("blue", blue)
    ;

创建 boost::python::object——自 PyObject*

当你想让 boost::python::object 管理一个指向 PyObject* pyobj 的指针时, 可以这样做:

boost::python::object o(boost::python::handle<>(pyobj));

在这种情况下, o 对象管理 pyobj, 构造时不会增加引用计数.

否则, 若要使用借用引用:

boost::python::object o(boost::python::handle<>(boost::python::borrowed(pyobj)));

在这种情况下, 会调用 Py_INCREF, 因此当对象 o 离开作用域时 pyobj 不会被析构.
