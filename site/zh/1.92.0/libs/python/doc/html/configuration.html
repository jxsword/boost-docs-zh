引言

Boost.Python 在 <boost/config.hpp> 中使用了若干配置宏, 还使用了应由应用提供的配置宏. 这些宏在此处说明.

应用定义的宏

这些是使用 Boost.Python 的应用可以定义的宏. 注意, 如果把对 C++ 标准的严格解释扩展到动态库, 那么在编译不同库 (包括扩展模块和 Boost.Python 库本身) 时使用这些宏的不同取值, 就违反了 ODR. 不过, 我们不知道有任何 C++ 实现能够检测出这种特定违规或因此产生问题.

宏

默认值

含义

BOOST_PYTHON_MAX_ARITY

15

要包装的任何函数、成员函数或构造函数的最大元数, 即 Boost.Python 函数调用中被指定为接受参数 x1, x2,...Xn 的最大数目. 这尤其包括 object::operator()(...) 或 call_method<R>(...) 之类的回调机制.

BOOST_PYTHON_MAX_BASES

10

bases<...> 类模板的模板参数最大个数, 该类模板用于指定被包装 C++ 类的基类.

BOOST_PYTHON_STATIC_MODULE

未定义

如果定义, 则在支持在代码中作出这一区分的平台上, 阻止你的模块初始化函数被视为导出符号

BOOST_PYTHON_ENABLE_CDECL

未定义

如果定义, 则允许包装使用 __cdecl 调用约定的函数.

BOOST_PYTHON_ENABLE_STDCALL

未定义

如果定义, 则允许包装使用 __stdcall 调用约定的函数.

BOOST_PYTHON_ENABLE_FASTCALL

未定义

如果定义, 则允许包装使用 __fastcall 调用约定的函数.

库定义的宏

这些宏由 Boost.Python 定义, 属于实现细节, 只有实现者以及向新平台移植的人员才需要关心.

宏

默认值

含义

BOOST_PYTHON_TYPE_ID_NAME

未定义

如果定义, 表示在本平台上跨共享库边界的 type_info 比较无法工作. 换言之, 如果 shared-lib-1 把 typeid(T) 传给 shared-lib-2 中某个函数, 该函数将其与 typeid(T) 比较, 那么该比较可能返回 false. 如果此宏被 #define, Boost.Python 会改用并比较 typeid(T).name(), 而不是直接使用和比较 std::type_info 对象.

BOOST_PYTHON_NO_PY_SIGNATURES

未定义

如果对某个模块定义了此宏, 则不会为该模块函数的文档字符串生成 Python 式签名, 并且该模块注册的任何转换器都不会关联 Python 类型. 这也会把模块的二进制体积减少约 14% (gcc 编译). 如果对 boost_python 运行库定义了此宏, 则 docstring_options.enable_py_signatures() 的默认值被设为 false.

BOOST_PYTHON_SUPPORTS_PY_SIGNATURES

已定义, 如果 BOOST_PYTHON_NO_PY_SIGNATURES 为未定义

定义此宏是为了能从不支持 Python 式签名的旧版 Boost.Python 平滑过渡. 用法示例参见此处.

BOOST_PYTHON_PY_SIGNATURES_PROPER_INIT_SELF_TYPE

未定义

如果定义, 则会正确生成 __init__ 方法 "self" 参数的 Python 类型, 否则使用 object. 默认未定义, 因为它会使模块的二进制体积增大约 14% (gcc 编译).
