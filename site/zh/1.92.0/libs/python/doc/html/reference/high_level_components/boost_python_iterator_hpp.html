引言

<boost/python/iterator.hpp> 提供从 C++ 容器与迭代器创建 Python 迭代器 的类型和函数. 注意, 如果你的 class_ 支持随机访问迭代器, 实现 __getitem__ (也称为序列协议) 可能比使用这个设施更适合你: Python 会自动为你创建一个迭代器类型 (参见 iter()), 且每次访问都可以做范围检查, 从而不存在通过失效的 C++ 迭代器访问的可能.

类模板 iterator

iterator<C,P> 的实例持有一个对可调用 Python 对象的引用, 从 Python 调用时它期望一个可转换为 C 的单参数 c, 并创建一个遍历 [c.begin(), c.end()) 的 Python 迭代器. 可选的 CallPolicies P 可用于控制在迭代期间如何返回元素.

在下表中, c 是 Container 的一个实例.

结果会将其参数转换为 c, 并调用 c.begin() 和 c.end() 来获取迭代器. 要调用 Container 的 const begin() 与 end() 函数, 请把它声明为 const.

NextPolicies

一个可默认构造的 CallPolicies 模型.

一个未指定的 CallPolicies 模型, 它总是对解引用底层 C++ 迭代器的结果制作副本

类模板 iterator 构造函数 

iterator()

效果

用以下结果初始化其基类:

range<NextPolicies>(&iterators<Container>::begin, &iterators<Container>::end)
Postconditions

this->get() 指向一个 Python 可调用对象, 它按上文所述创建 Python 迭代器.

Rationale

为常见情形提供创建迭代器的简便方法, 即被包装的 C++ 类提供 begin() 与 end().

类模板 iterators

一个实用类模板, 提供可靠调用其参数的 begin() 与 end() 成员函数的方法. 注意, 没有可移植的方法来获取 C++ 标准库容器的成员函数地址, 因此在包装它们时 iterators<> 可能特别有用.

在下表中, x 是 C 的一个实例.

类型

x.begin()

若 C 是 const 类型则可转换为 C::const_iterator; 否则可转换为 C::iterator.

x.end()

若 C 是 const 类型则可转换为 C::const_iterator; 否则可转换为 C::iterator.

 
namespace boost { namespace python
{
  template <class C>
  struct iterators
  {
      typedef typename C::const_iterator iterator;
      static iterator begin(C& x);
      static iterator end(C& x);
  };
}}

Functions 

template <class NextPolicies, class Target, class Accessor1, class Accessor2>
object range(Accessor1 start, Accessor2 finish);

template <class NextPolicies, class Accessor1, class Accessor2>
object range(Accessor1 start, Accessor2 finish);

template <class Accessor1, class Accessor2>
object range(Accessor1 start, Accessor2 finish);

Requires

NextPolicies 是一个可默认构造的 CallPolicies 模型.

效果

第一种形式创建一个 Python 可调用对象, 被调用时它把参数转换为 Target 对象 x, 并创建一个遍历 [bind(start,_1)(x), bind(finish,_1)(x)) 的 Python 迭代器, 把 NextPolicies 应用于迭代器的 next() 函数. 第二种形式与第一种相同, 只是 Target 从 Accessor1 推导如下:

  1. 如果 Accessor1 是函数类型, Target 是其第一个参数的类型.
  2. 如果 Accessor1 是形如 R (T::*) 的数据成员指针, Target 与 T 相同.
  3. 如果 Accessor1 是形如 R (T::*)(arguments...) cv-opt 的成员函数指针, 其中 cv-opt 是可选的 cv 限定符, Target 与 T 相同.

第三种形式与第二种相同, 只是 NextPolicies 是一个未指定的 CallPolicies 模型, 它总是对解引用底层 C++ 迭代器的结果制作副本

Rationale

使用 boost::bind() 允许通过函数、成员函数或数据成员指针访问 C++ 迭代器. 当复制被包装类类型的序列元素代价高昂时, 定制 NextPolicies (例如使用 return_internal_reference) 很有用. 当 Accessor1 是函数对象, 或者否则会推导出预期目标类型的某个基类时, 定制 Target 很有用.

Example 

#include <boost/python/module.hpp>
#include <boost/python/class.hpp>

#include <vector>

using namespace boost::python;
BOOST_PYTHON_MODULE(demo)
{
    class_<std::vector<double> >("dvec")
        .def("__iter__", iterator<std::vector<double> >())
        ;
}
