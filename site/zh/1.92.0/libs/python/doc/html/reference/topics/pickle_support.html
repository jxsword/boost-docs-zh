引言

Pickle 是一个用于对象序列化的 Python 模块, 序列化也称为持久化、编组或展平.

经常需要把对象的内容保存到文件并恢复. 解决这个问题的一种方法是编写一对以特殊格式从文件读写的函数. 一种强大的替代方法是使用 Python 的 pickle 模块. 利用 Python 的自省能力, pickle 模块递归地把几乎任意的 Python 对象转换为可写入文件的字节流.

Boost Python 库通过 pickle 的 Python 库参考 中详细描述的接口支持 pickle 模块. 该接口涉及下文描述的特殊方法 __getinitargs__、__getstate__ 和 __setstate__. 注意, Boost.Python 也与 Python 的 cPickle 模块完全兼容.

Pickle 接口

在用户层面, Boost.Python pickle 接口涉及三个特殊方法:

__getinitargs__

当一个 Boost.Python 扩展类的实例被 pickle 时, pickler 会测试该实例是否有 __getinitargs__ 方法. 此方法必须返回一个 Python tuple (最方便的是使用 boost::python::tuple). 当实例被 unpickler 恢复时, 此元组的内容被用作类构造函数的参数.

如果未定义 __getinitargs__, pickle.load 将不带参数调用构造函数 (__init__); 也就是说, 对象必须是可默认构造的.

__getstate__

当 Boost.Python 扩展类的实例被 pickle 时, pickler 会测试该实例是否有 __getstate__ 方法. 此方法应返回一个表示实例状态的 Python 对象.

__setstate__

当 Boost.Python 扩展类的实例被 unpickler (pickle.load) 恢复时, 首先用 __getinitargs__ 的结果作为参数构造它 (见上文). 随后, unpickler 测试新实例是否有 __setstate__ 方法. 如果有, 则以 __getstate__ 的结果 (一个 Python 对象) 作为参数调用该方法.

上述三个特殊方法可以由用户单独 .def(). 不过, Boost.Python 通过 boost::python::pickle_suite 类提供了一个易用的高层接口, 该接口还强制一致性: __getstate__ 与 __setstate__ 必须成对定义. 以下示例演示了此接口的使用.

python/test 中有三个文件展示了如何提供 pickle 支持.

pickle1.cpp

本示例中的 C++ 类可以通过向构造函数传递适当的参数来完全恢复. 因此只需定义 pickle 接口方法 __getinitargs__ 即可. 做法如下: C++ pickle 函数的定义:

struct world_pickle_suite : boost::python::pickle_suite
{
  static
  boost::python::tuple
  getinitargs(world const& w)
  {
      return boost::python::make_tuple(w.get_country());
  }
};

建立 Python 绑定:

class_<world>("world", args<const std::string&>())
      // ...
      .def_pickle(world_pickle_suite())
      // ...

pickle2.cpp

本示例中的 C++ 类包含任何构造函数都无法恢复的成员数据. 因此有必要提供 __getstate__/__setstate__ 这对 pickle 接口方法:

C++ pickle 函数的定义:

struct world_pickle_suite : boost::python::pickle_suite
  {
    static
    boost::python::tuple
    getinitargs(const world& w)
    {
      // ...
    }

    static
    boost::python::tuple
    getstate(const world& w)
    {
      // ...
    }

    static
    void
    setstate(world& w, boost::python::tuple state)
    {
      // ...
    }
  };

为整个套件建立 Python 绑定:

class_<world>("world", args<const std::string&>())
    // ...
    .def_pickle(world_pickle_suite())
    // ...

为简单起见, __dict__ 未包含在 __getstate__ 的结果中. 这一般不推荐, 但如果预计对象的 __dict__ 总是为空, 这是一种有效做法. 注意, 下文描述的安全防护会捕获违反这一假设的情形.

pickle3.cpp

本示例与 pickle2.cpp 类似. 然而, 对象的 __dict__ 包含在 __getstate__ 的结果中. 这需要多一点代码, 但如果对象的 __dict__ 并非总是为空, 这是不可避免的.

陷阱与安全防护

上述 pickle 协议有一个重要陷阱, Boost.Python 扩展模块的最终用户可能没有意识到:

__getstate__ 已定义且实例的 __dict__ 非空.

Boost.Python 扩展类的作者可能提供 __getstate__ 方法, 而没有考虑以下可能性: * 他的类在 Python 中被用作基类. 很可能派生类实例的 __dict__ 需要被 pickle 才能正确恢复实例. * 用户直接向实例的 __dict__ 添加条目. 同样, 此时实例的 __dict__ 也需要被 pickle.

为了让用户注意到这个极不明显的问题, 提供了一个安全防护. 如果 __getstate__ 已定义且实例的 __dict__ 非空, Boost.Python 会测试该类是否有属性 __getstate_manages_dict__. 如果未定义此属性, 将引发异常:

RuntimeError: Incomplete pickle support (__getstate_manages_dict__ not set)

要解决这个问题, 应首先确认 __getstate__ 和 __setstate__ 方法正确管理实例的 __dict__. 注意, 这可以在 C++ 层面或 Python 层面完成. 最后, 应有意地覆盖安全防护. 例如在 C++ 中 (来自 pickle3.cpp):

struct world_pickle_suite : boost::python::pickle_suite
{
  // ...

  static bool getstate_manages_dict() { return true; }
};

或者在 Python 中:

import your_bpl_module
class your_class(your_bpl_module.your_class):
  __getstate_manages_dict__ = 1
  def __getstate__(self):
    # your code here
  def __setstate__(self, state):
    # your code here

实用建议

  • 在带有许多扩展类的 Boost.Python 扩展模块中, 为所有类提供完整的 pickle 支持将是很大的开销. 一般而言, 只应为最终会被 pickle 的扩展类实现完整的 pickle 支持.
  • 避免使用 __getstate__, 如果实例还能通过 __getinitargs__ 重建的话. 这样自动避免了上述陷阱.
  • 如果需要 __getstate__, 应把实例的 __dict__ 包含在返回的 Python 对象中.

轻量替代: 用 Python 实现的 pickle 支持

pickle4.cpp 示例演示了实现 pickle 支持的另一种技术. 首先, 我们通过 class_::enable_pickling() 成员函数指示 Boost.Python 只定义 pickle 所需的基本属性:

class_<world>("world", args<const std::string&>())
    // ...
    .enable_pickling()
    // ...

这会启用 Python 文档所描述的标准 Python pickle 接口. 通过向被包装类的定义中 "注入" 一个 __getinitargs__ 方法, 我们使所有实例都可以被 pickle:

# import the wrapped world class
from pickle4_ext import world

# definition of __getinitargs__
def world_getinitargs(self):
  return (self.get_country(),)

# now inject __getinitargs__ (Python is a dynamic language!)
world.__getinitargs__ = world_getinitargs

另请参阅教程中关于从 Python 注入额外方法的一节.
