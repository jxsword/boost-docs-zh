引言

本页定义两个概念, 用于描述管理 Python 对象、且旨在支持以类 Python 语法使用的类.

ObjectWrapper 概念要求

ObjectWrapper 概念的模型以 object 作为可公开访问的基类, 并用于通过 (通常是模板的) 成员函数提供特殊的构造行为和/或额外的便利功能. 除非返回类型 R 本身是一个 TypeWrapper, 否则形如下式的成员函数调用

x.some_function(a1, a2,...an)

总是具有与下式等价的语义:

extract<R>(x.attr("some_function")(object(a1), object(a2),...object(an)))()

(见下文注意事项).

TypeWrapper 概念要求

TypeWrapper 是 ObjectWrapper 的细化, 它与特定的 Python 类型 X 相关联. 对于给定的 TypeWrapper T, 一个有效的构造表达式

T(a1, a2,...an)

构建一个新的 T 对象, 管理以对应于下面的参数调用 X 所得到的结果

object(a1), object(a2),...object(an)

. 当用作被包装 C++ 函数的参数, 或用作 extract<> 的模板参数时, 只有相关联 Python 类型的实例才会被视为匹配.

注意事项

当返回类型是 TypeWrapper 时, 特殊成员函数调用规则的结局是: 返回的对象有可能管理着一个类型不当的 Python 对象. 这通常不是严重问题; 最坏的结果是错误在运行期被检测到的时间比原本稍晚一些. 关于这种情况如何发生的一个例子: 注意 dict 的成员函数 items 返回一个 list 类型的对象. 现在假设用户在 Python 中定义了这个 dict 子类:

>>> class mydict(dict):
...     def items(self):
...         return tuple(dict.items(self)) # return a tuple

由于 mydict 的实例也是 dict 的实例, 当用作被包装 C++ 函数的参数时, boost::python::dict 可以接受 Python 类型为 mydict 的对象. 对这个对象调用 items() 可能得到一个 boost::python::list 实例, 而它实际持有的是 Python tuple. 随后在这个对象上使用 list 方法 (例如 append, 或任何其他修改性操作) 的尝试都会引发与你试图从 Python 这样做时相同的异常.
