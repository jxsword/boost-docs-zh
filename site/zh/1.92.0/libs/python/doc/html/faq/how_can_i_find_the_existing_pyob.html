如何找到持有某个 C++ 对象的既有 PyObject?

"我正在包装一个总是返回指向已被持有的 C++ 对象的指针的函数."

一种做法是借用用于包装带虚函数的类的机制. 如果你创建一个以 PyObject* 作为首构造函数参数的包装器类, 并把该 PyObject* 存储为 "self", 就可以在一个薄包装函数中向下转型到该包装器类型来取回它. 例如:

class X { X(int); virtual ~X(); ... };
X* f();  // known to return Xs that are managed by Python objects


// wrapping code

struct X_wrap : X
{
  X_wrap(PyObject* self, int v) : self(self), X(v) {}
  PyObject* self;
};

handle<> f_wrap()
{
  X_wrap* xw = dynamic_cast<X_wrap*>(f());
  assert(xw != 0);
  return handle<>(borrowed(xw->self));
}

...

def("f", f_wrap());
class_<X,X_wrap,boost::noncopyable>("X", init<int>())
 ...
 ;

当然, 如果 X 没有虚函数, 你就得使用 static_cast 而不是 dynamic_cast, 且没有运行期有效性检查. 这种方法还只在 X 对象是从 Python 构造的情况下才有效, 因为从 C++ 构造的 X 当然永远不会是 X_wrap 对象.

另一种方法要求你略微修改你的 C++ 代码; 如果这对你可行, 它可能是更好的路线——这反正也是我们一直打算要做的工作. 当一个 shared_ptr<X> 从 Python 转换而来时, shared_ptr 实际上管理着对包含它的 Python 对象的引用. 当 shared_ptr<X> 被转换回 Python 时, 库会检查它是否属于那些 "Python 对象管理器", 若是则直接返回原来的 Python 对象. 因此你只需写 object(p) 即可取回 Python 对象. 要利用这一点, 你必须能够修改被包装的 C++ 代码, 使其改用 shared_ptr 而不是裸指针.

还有其他方法. 接收你最终想返回的那个 Python 对象的函数, 可以用一个薄包装器来包装, 记录对象地址与其包含 Python 对象之间的对应关系; 然后让你的 f_wrap 函数在该映射中查找以取出 Python 对象.
