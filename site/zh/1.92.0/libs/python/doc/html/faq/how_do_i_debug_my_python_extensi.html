如何调试我的 Python 扩展?

Greg Burley 为 Unix GCC 用户给出了如下解答:

为你的 C++ 库或类创建 boost python 扩展之后, 你可能需要调试代码. 毕竟, 这正是用 Python 包装库的原因之一. 使用 BPL 的一个预期副作用 (或好处) 是, 调试应当被隔离到被测试的 C++ 库, 因为 Python 代码极少, 而 boost::python 要么能用要么不能用 (即: 当包装方法无效时固然可能出错, 但大多数错误会被编译器捕获 ;-).

这里给出了启动 gdb 会话以经由 Python 调试 C++ 库所需的基本步骤. 不过请注意, 你应当在包含你的 BPL my_ext.so 模块的目录中启动 gdb 会话.

(gdb) target exec python
(gdb) run
>>> from my_ext import *
>>> [C-c]
(gdb) break MyClass::MyBuggyFunction
(gdb) cont
>>> pyobj = MyClass()
>>> pyobj.MyBuggyFunction()
Breakpoint 1, MyClass::MyBuggyFunction ...
Current language:  auto; currently c++
(gdb) do debugging stuff

在 Emacs 的 "gdb" 命令下, Greg 的方法效果更好, 因为单步调试时它会逐行显示源代码.

在 Windows 上, 我最喜爱的调试方案是 Microsoft Visual C++ 7 自带的调试器. 这个调试器似乎能处理所有版本的 Microsoft 和 Metrowerks 工具集生成的代码; 它坚如磐石, "开箱即用", 无需用户使用任何特殊技巧.

Raoul Gough 为 Windows 上的 gdb 提供了以下内容:

gdb 对 Windows DLL 的支持近来有所改进, 因此现在可以通过一些技巧来调试 Python 扩展. 首先, 你需要一个支持从 DLL 提取最小符号的新版 gdb. 版本 6 起的任何 gdb, 或 Cygwin gdb-20030214-1 及更新版本都可以. 合适的版本会在 gdb.info 文件中 Configuration - Native - Cygwin Native - Non-debug DLL symbols 一节下有相应内容. 有关这里所述过程的更多细节, 请参阅该信息节.

其次, 似乎必须在 Python 解释器中设置断点, 而不是用 ^C 中断执行. 设置该断点的好位置是 PyOS_Readline, 它会在读取每条交互式 Python 命令之前立即停止执行. 你必须先让 Python 在调试器下启动一次, 使它加载自己的 DLL, 然后才能设置断点:

$ gdb python
GNU gdb 2003-09-02-cvs (cygwin-special)
[...]

(gdb) run
Starting program: /cygdrive/c/Python22/python.exe
Python 2.2.2 (#37, Oct 14 2002, 17:02:34) [MSC 32 bit (Intel)] on win32
Type "help", "copyright", "credits" or "license" for more information.
>>> ^Z


Program exited normally.
(gdb) break *&PyOS_Readline
Breakpoint 1 at 0x1e04eff0
(gdb) run
Starting program: /cygdrive/c/Python22/python.exe
Python 2.2.2 (#37, Oct 14 2002, 17:02:34) [MSC 32 bit (Intel)] on win32
Type "help", "copyright", "credits" or "license" for more information.

Breakpoint 1, 0x1e04eff0 in python22!PyOS_Readline ()
   from /cygdrive/c/WINNT/system32/python22.dll
(gdb) cont
Continuing.
>>> from my_ext import *

Breakpoint 1, 0x1e04eff0 in python22!PyOS_Readline ()
   from /cygdrive/c/WINNT/system32/python22.dll
(gdb) # my_ext now loaded (with any debugging symbols it contains)

通过 Boost.Build 调试扩展

如果你用 Boost.Build 的 boost-python-runtest 规则来启动你的扩展模块测试, 可以通过在 bjam 命令行中添加 "--debugger=调试器" 让它替你启动调试器:

bjam -sTOOLS=vc7.1 "--debugger=devenv /debugexe" test
bjam -sTOOLS=gcc -sPYTHON_LAUNCH=gdb test

运行测试时添加 -d+2 选项也可能极为有用, 因为 Boost.Build 随后会向你显示它用来调用测试的确切命令. 这通常涉及设置 PYTHONPATH 以及你的调试器为使一切正常工作可能需要的其他重要环境变量, 例如 LD_LIBRARY_PATH.
