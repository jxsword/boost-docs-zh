return_internal_reference 高效吗?

问: /我有一个由 12 个 double 组成的对象. 另一个类的成员函数返回指向该对象的 const&. 从在 Python 中使用返回对象的角度看, 我不在乎得到的是副本还是对该对象的引用. 在 Boost.Python 中我可以选择使用 copy_const_reference 或 return_internal_reference. 是否有某些考虑会让我倾向于其中一个, 例如生成代码的大小或内存开销?/

答: copy_const_reference 会创建一个实例, 其中带有可存放你的对象之一的存储空间, size = base_size + 12 * sizeof(double). return_internal_reference 会创建一个实例, 其中带有可存放指向你的对象之一的指针的存储空间, size = base_size + sizeof(void*). 然而, 它还会创建一个放入源对象 weakreflist 的弱引用对象, 以及一个用于管理内部引用对象生存期的特殊回调对象. 我的猜测? copy_const_reference 在这里是你的朋友, 它带来更少的总体内存使用与更少的碎片, 总周期数可能也更少.
