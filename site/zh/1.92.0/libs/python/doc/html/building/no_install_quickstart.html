开始使用 Boost.Python 并不需要“安装 Boost”. 以下说明使用 Boost.Build 工程, 它会在需要那些二进制文件时立即构建它们. 在等待 Boost.Python 构建完成期间, 你的首次测试可能要多花一点时间, 但这样做可以让你不必操心构建上的种种细节, 比如针对特定编译器配置该用哪些库二进制文件, 以及自己琢磨出正确的编译器选项.

注释

当然, 也可以使用其他构建系统来构建 Boost.Python 及其扩展, 但 Boost 官方不支持它们. 而且, 在没有先按这些说明操作的情况下, 所有“我无法构建 Boost.Python”的问题中 99% 都源于试图使用其他构建系统.

如果你无论如何都想使用另一个系统, 我们建议你先按这些说明操作, 然后带上下面这个选项调用 bjam

-a -o文件名

选项, 把它执行的构建命令转储到文件中, 这样你就能看到你的替代构建系统需要做什么.

基本步骤

1. 获取 Boost; 参见 Boost 入门指南 的第 1 和第 2 节.

2. 获取 bjam 构建驱动程序. 参见 Boost 入门指南 的第 5 节.

3. cd 到你的 Boost.Python 安装中的 example/quickstart/ 目录, 其中包含一个小的示例项目.

4. 调用 bjam. 把 “stage“ 参数——取自 Boost 入门指南 第 5 节的示例调用——替换为 “test,“, 以构建所有测试目标. 再添加参数 “--verbose-test” 以查看测试运行时生成的输出. 在 Windows 上, 你的 bjam 调用可能类似于:

C:\\...\\quickstart> bjam toolset=msvc --verbose-test test

在 Unix 变体上则可能是,

.../quickstart$ bjam toolset=gcc --verbose-test test
注释

为简洁起见, 本指南余下部分将在路径名中使用 Unix 风格的正斜杠, 而不是 Windows 用户可能更熟悉的反斜杠. 正斜杠应当处处可用, 但 命令提示符 窗口除外, 在那里应使用反斜杠.

如果你成功按照此步骤操作, 你将构建出一个名为 extending 的扩展模块, 并通过运行一个名为 test_extending.py 的 Python 脚本测试了它. 你还将构建并运行一个名为 embedding 的、嵌入 Python 的简单应用.

遇到问题时

如果你看到大量编译器和/或链接器错误消息, 原因很可能是 Boost.Build 无法找到你的 Python 安装. 你可能想传入 --debug-configuration 选项给 bjam, 在最初几次调用时确保 Boost.Build 正确定位你 Python 安装的所有组成部分. 如果没有, 考虑按下面详述的 配置 Boost.Build 操作.

如果仍然遇到问题, 以下邮件列表中的某个人或许能帮上忙:

  • Boost.Build 邮件列表, 用于与 Boost.Build 相关的问题
  • Boost.Python 邮件列表, 用于专门与 Boost.Python 相关的问题

一切似乎正常时

庆祝吧! 如果你是 Boost.Python 的新手, 此时不妨暂时把构建问题放在一边, 专注通过阅读 教程 以及也许还有部分 参考手册 来学习这个库, 并通过修改快速入门项目来实践你学到的 API 知识.

更改你的扩展模块的名称

如果你满足于把扩展模块永远保存在 Boost.Python 发行版内一个名为 extending.cpp 的源文件中, 并且永远以 extending 导入它, 那么你就可以到此为止. 不过, 你很可能想做一些改动. 有些事情无需深入学习 Boost.Build 就能做到.

你刚构建的项目由当前目录中的两个文件指定: boost-build.jam, 它告诉 bjam 在哪里可以找到 Boost 构建系统的解释执行代码; 以及 Jamroot, 它描述了你刚构建的目标. 这些文件带有大量注释, 因此应当易于修改. 但要注意保留空白. 如果 ; 之类的标点没有被空白包围, bjam 将无法按预期识别它们.

迁移项目位置

你可能想把这个项目复制到别处, 这样就可以在不改动 Boost 发行版的情况下修改它. 为此, 只需

a. 把整个 example/quickstart/ 目录复制到一个新目录.

b. 在 boost-build.jam 与 Jamroot 的新副本中, 找到文件顶部附近由注释清楚标出的相对路径, 并编辑该路径, 使其指向你的 Boost 发行版的同一目录——即与该文件还在 example/quickstart/ 目录中的原始位置时所指向的目录相同.

例如, 如果你把项目从 /home/dave/boost_1_34_0/libs/python/example/quickstart 移到 /home/dave/my-project, 你可以把 boost-build.jam 中的第一个路径从

../../../../tools/build/src

to 

/home/dave/boost_1_34_0/tools/build/src

并把 Jamroot 中的第一个路径从

../../../..

to 

/home/dave/boost_1_34_0
添加新源文件或更改现有源文件的名称

构建你的扩展模块或嵌入应用所涉及的其他源文件的名称, 可以分别在 Jamroot 中直接列在 extending.cpp 或 embedding.cpp 旁边. 只需确保每个文件名周围留有空白:

… file1.cpp file2.cpp file3.cpp …

自然, 如果你想更改某个源文件的名称, 可以通过编辑 Jamroot 中的名称告知 Boost.Build.

更改你的扩展模块的名称

扩展模块的名称由两件事决定:

  1. Jamroot 中紧跟在 python-extension 后面的名称, 以及
  2. 传给 BOOST_PYTHON_MODULE 的、位于 extending.cpp 中的名称.

要把扩展模块的名称从 extending 改为 hello, 你需要编辑 Jamroot, 把

python-extension extending : extending.cpp ;

to 

python-extension hello : extending.cpp ;

并编辑 extending.cpp, 改动

BOOST_PYTHON_MODULE(extending)

to 

BOOST_PYTHON_MODULE(hello)
