Python 调试构建

Python 可以用一种特殊的 “python debugging” 配置构建, 它增加了对扩展模块开发者非常有用的额外检查和插桩. 调试配置使用的数据结构包含额外的成员, 因此启用了 python debugging 构建的 Python 可执行程序不能与未启用该配置编译的扩展模块或库一起使用, 反之亦然.

由于大多数 Python 发行版都不提供预构建的 “python debugging” 版本的 Python 可执行程序和库, [5] 而我们又不想强迫用户去构建它们, Boost.Build 不会在其 debug 构建变体 (即默认变体) 中自动启用 python debugging. 取而代之的是一个名为 python-debugging 的特殊构建特性, 当把它用作构建特性时, 会定义正确的预处理器符号并选择正确的库进行链接.

在 Unix 变体平台上, 只有当符号 Py_DEBUG 被定义时才会使用调试版本的 Python 数据结构. 在许多 Windows 编译器上, 当扩展模块以预处理器符号 _DEBUG 构建时, Python 默认会强制与 Python DLL 的特殊调试版本链接. 由于该符号即使在没有 Python 的情况下也十分常用, Boost.Python 会临时取消定义 _DEBUG——当 Python.h 从 boost/python/detail/wrap_python.hpp 中被 #include 时——除非 BOOST_DEBUG_PYTHON 已被定义. 结论是: 如果你想要 “python debugging” 而又不使用 Boost.Build, 就应当确保 BOOST_DEBUG_PYTHON 已被定义, 否则 python debugging 会被抑制.


[5] 在 Unix 及类似平台上, 通过在配置 Python 构建时添加 --with-pydebug 来构建调试版 Python 及相关库. 在 Windows 上, 调试版 Python 由完整 Python 源代码发行版 PCBuild 子目录中 Visual Studio 工程的 "Win32 Debug" 目标生成.
