选择 Boost.Python 库二进制文件

动态二进制文件
静态二进制文件

如果你——而不是让 Boost.Build 自动构造并链接正确的库——选择使用预构建的 Boost.Python 库, 就需要考虑链接哪一个. Boost.Python 二进制文件有静态和动态两种形态. 请注意为你的应用选择正确的形态. [3]

动态二进制文件

动态库是最安全、用途最广的选择:

  • 用给定工具集构建的所有扩展模块共用一份库代码副本. [4]
  • 该库包含一个类型转换注册表. 由于该注册表由所有扩展模块共享, 在一个动态加载的扩展模块中暴露给 Python 的类的实例, 可以传递给在另一个此类模块中暴露的函数.

静态二进制文件

在以下任何情况下, 使用静态 Boost.Python 库可能是合适的:

  • 你在扩展 Python, 并且你的动态加载扩展模块中暴露的类型不需要被任何其他 Boost.Python 扩展模块使用, 而且你也不在乎核心库代码在这些模块间重复.
  • 你在应用中嵌入 Python, 且满足以下条件之一:
    • 你的目标是 MacOS 或 AIX 以外的 Unix 变体操作系统, 在这些系统上, 动态加载的扩展模块可以“看到”作为可执行文件一部分的 Boost.Python 库符号.
    • 或者, 你已经把一些 Boost.Python 扩展模块静态链接进你的应用, 而你不在乎任何动态加载的 Boost.Python 扩展模块是否能使用你的静态链接扩展模块所暴露的类型 (反之亦然).

[3] 关于如何在 Windows / Unix 变体 上识别 Boost.Python 静态与动态构建的信息

[4] 由于大多数 *nix 平台在动态加载对象之间共享符号的方式, 我不能确定用不同编译器工具集构建的扩展模块在被加载到同一个 Python 实例中时, 是否总会使用不同的 Boost.Python 库副本. 如果各编译器具有兼容的 ABI, 不使用不同的库也许是件好事, 因为用这两个库构建的扩展模块将可互操作. 否则, 这可能招致灾难, 因为扩展模块与 Boost.Python 库对类布局等问题的理解会各不相同. 若有人做实验弄清实际会发生什么, 我将不胜感激.
