配置 Boost.Build

Python 配置参数
示例

如 Boost.Build 参考手册 所述, 你的主目录下一个名为 user-config.jam 的文件用于向构建系统指定可用的工具和库. 你可能需要创建或编辑 user-config.jam, 告诉 Boost.Build 如何调用 Python、#include 其头文件, 并与其库链接.

注释

如果你使用 Unix 变体操作系统并运行过 Boost 的 configure 脚本, 它可能已经为你生成了 user-config.jam. [2] 如果你的 configure/make 序列执行成功且构建出了 Boost.Python 二进制文件, 你的 user-config.jam 文件很可能已经是正确的.

如果你的平台上只有一个相当“标准”的 Python 安装, 你可能无需做任何特别描述. 如果你没有在 user-config.jam 中配置 Python (并且没有在 Boost.Build 命令行上指定 --without-python), Boost.Build 会自动执行与下面等价的操作

import toolset : using ;
using python ;

它会自动在最可能的位置查找 Python. 不过, 只有在使用 Boost.Python 工程文件时 (例如像快速入门方法中那样被另一个工程引用) 才会发生这种情况. 反之, 如果你是针对单独编译的 Boost.Python 二进制文件进行链接, 就应当建立一个 user-config.jam 文件, 至少包含上面那段最简配置.

Python 配置参数

如果你安装了多个 Python 版本, 或者 Python 的安装方式不寻常, 你可能希望给 using python 提供以下可选参数中的一个或全部.

version

要使用的 Python 版本. 应为 Major.Minor 格式, 例如 2.3. 不要包含子小版本号 (即不要写成 2.5.1). 如果安装了多个 Python 版本, 版本参数通常将是唯一必需的配置参数.

cmd-or-prefix

最好是一个调用 Python 解释器的命令. 也可以是 Python 库与头文件的安装前缀. 仅在没有合适的 Python 可执行程序可用时才使用后一种形式.

includes

Python 头文件的 #include 路径. 通常正确的路径会自动从 version 和/或 cmd-or-prefix 推导得出.

libraries

Python 库二进制文件的路径. 在 MacOS/Darwin 上, 你也可以传入 Python framework 的路径. 通常正确的路径会自动从 version 和/或 cmd-or-prefix 推导得出.

condition

如果指定, 应为一组 Boost.Build 特性, 在 Boost.Build 选择要使用的 Python 配置时与构建配置进行匹配. 详情见下面的示例.

extension-suffix

附加到扩展模块名称之后、真实文件扩展名之前的字符串. 你几乎肯定不需要使用它. 通常该后缀只在面向 Windows 的 Python 调试构建时使用, 并且会根据 <python-debugging> 特性的取值自动为你设置. 不过, 至少有一个 Linux 发行版 (Ubuntu Feisty Fawn) 提供了一个特殊配置的 <python-dbg> 包, 声称使用这种后缀.

示例

注意, 在下面的示例中, 大小写和尤其是空白都很重要.

  • 如果你同时安装了 python 2.5 和 python 2.4, user-config.jam 的内容可能是

    using python : 2.5 ;  # Make both versions of Python available
using python : 2.4 ;  # To build with python 2.4, add python=2.4
                      # to your command line.

    先配置的版本 (2.5) 成为默认版本. 要针对 python 2.4 构建, 请把 python=2.4 添加到 bjam 命令行中.

  • 如果 Python 安装在不寻常的位置, 你可以在 cmd-or-prefix 参数中提供解释器的路径:

    using python : : /usr/local/python-2.6-beta/bin/python ;

  • 如果你有一个专门配合特定工具集使用的 Python 构建, 你可以在 condition 参数中提供该工具集:

    using python ;  # use for most toolsets

# Use with Intel C++ toolset
using python
     : # version
     : c:\\Devel\\Python-2.5-IntelBuild\\PCBuild\\python # cmd-or-prefix
     : # includes
     : # libraries
     : <toolset>intel # condition
     ;

  • 如果你下载了 Python 源代码并在 Windows 上从源码构建了普通版本与 "python debugging" 版本两种构建, 你可能会看到:

    using python : 2.5 : C:\\src\\Python-2.5\\PCBuild\\python ;
using python : 2.5 : C:\\src\\Python-2.5\\PCBuild\\python_d
  : # includes
  : # libs
  : <python-debugging>on ;

  • 你可以设置 user-config.jam, 使在 Windows 下构建的 bjam 能够构建/测试 Windows 与 Cygwin_ 的 Python 扩展. 只需把 <target-os>cygwin 传入 cygwin Python 安装的 condition 参数中:

    # windows installation
using python ;

# cygwin installation
using python : : c:\\cygwin\\bin\\python2.5 : : : <target-os>cygwin ;

    当你在构建请求中加入 target-os=cygwin 时, 它应当使用 cygwin 版本的 Python 构建: _

    bjam target-os=cygwin toolset=gcc

    反过来也应当可行 (用 Cygwin 的 bjam 面向 Windows 的 Python), 但撰写本文时 Boost.Build 工具集中对这种构建方式的支持似乎已损坏.

  • 注意, 由于 Boost.Build 当前选择候选目标的方式, 你可能需要在构建请求中写得非常明确. 例如, 给定:

    using python : 2.5 ; # a regular windows build
using python : 2.4 : : : : <target-os>cygwin ;

    用以下方式构建

    bjam target-os=cygwin

    会产生一个错误. 相反, 你需要写

    bjam target-os=cygwin/python=2.4

[2] configure 会在备份旧版本之后, 覆盖你主目录中已有的 user-config.jam (如果存在).
