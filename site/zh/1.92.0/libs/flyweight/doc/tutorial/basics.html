引言

假设我们正在编写一款大型多人在线游戏, 需要在内存中维护数十万乃至数百万个以下类的实例:

struct user_entry
{
  std::string first_name;
  std::string last_name;
  int         age;
  ...
};

在这类环境中内存资源十分宝贵, 因此我们寻求使 user_entry 尽可能紧凑的方法. 通常, 社区用户的名和姓存在非常高的重复度, 因此一个显而易见的优化是把 user_entry::first_name 和 user_entry::last_name 对象移到一个公共仓库中以避免重复, 并在 user_entry 内部保留对它们的引用. 这正是 Boost.Flyweight 以对程序员最简单的方式所做的事情:

#include <boost/flyweight.hpp>

struct user_entry
{
  flyweight<std::string> first_name;
  flyweight<std::string> last_name;
  int                    age;
  ...
};

Boost.Flyweight 会在幕后自动执行刚才描述的优化, 因此这一改动的净效果是程序的内存使用量按与用户名冗余度成比例的因子减少.

flyweight<std::string> 在许多方面的行为类似于 std::string; 例如, 以下代码在重新定义 user_entry 之后无需改动即可工作:

// flyweight<T> can be constructed in the same way as T objects can,
// even with multiple argument constructors

user_entry::user_entry(const char* f,const char* l,int a,...):
  first_name(f),
  last_name(l),
  age(a),
  ...
{}

// flyweight classes have relational operators replicating the
// semantics of the underyling type

bool same_name(const user_entry& user1,const user_entry& user2)
{
  return user1.first_name==user2.first_name &&
         user1.last_name==user2.last_name;
}

// flyweight<T> provides operator<< and operator>> internally
// forwarding to T::operator<< and T::operator>>

std::ostream& operator<<(std::ostream& os,const user_entry& user)
{
  return os<<user.first_name<<" "<<user.last_name<<" "<<user.age;
}

std::istream& operator>>(std::istream& is,user_entry& user)
{
  return is>>user.first_name>>user.last_name>>user.age;
}

此外, flyweight<T> 可隐式转换为 const T&, 也可使用 get 成员函数显式转换. 还可以使用智能指针语法:

std::string full_name(const user_entry& user)
{
std::string full;

full.reserve(
user.first_name.get().size()+ // get() returns the underlying const std::string&
user.last_name->size()+1);    // flyweights also work as pointers to their
                              // underlying value
full+=user.first_name;        // implicit conversion is used here
full+=" ";
full+=user.last_name;

return full;
}

用等价享元替换类时, 需要考虑的最重要限制是: 享元不可变. 由于多个享元对象可以共享同一个表示值, 修改该值是不允许的. 另一方面, 享元对象可以被赋予新值:

void change_name(
  user_entry& user,
  const std::string& f,const std::string& l)
{
  user.first_name=f;
  user.last_name=l;
}

一般来说, flyweight<T> 的接口设计得使从普通 T 的过渡尽可能直接. 请查阅参考以了解类模板 flyweight 接口的更多细节. 示例一节探讨了 Boost.Flyweight 的一些常见使用场景.

序列化

flyweight<T> 可以通过 Boost Serialization Library 序列化, 只要其底层 T 可序列化. 支持常规档案和 XML 档案. 要使用 Boost.Flyweight 的序列化能力, 必须包含特定头文件 "boost/flyweight/serialize.hpp".

#include <boost/flyweight/serialize.hpp>

template<class Archive>
void serialize(Archive& ar,user_entry& user,const unsigned int)
{
  ar&user.first_name;
  ar&user.last_name;
  ar&user.age;
  ...
}

正如使用 Boost.Flyweight 因内部共享重复值而减少内存消耗一样, 序列化 flyweight 也能带来更小的档案文件: 公共值只存储一次, 而与之关联的各个 flyweight 被保存为对它的引用. 即使 flyweight 底层类型未被 Boost.Serialization跟踪, 这一策略也会被遵循.

使用 Boost.Flyweight 序列化能力的说明示例见示例一节中的 示例 6.

享元要求

要使 flyweight<T> 可实例化, T 必须是MoveConstructible 且 EqualityComparable, 并必须与 Boost.ContainerHash 互操作. 第一个要求用户大概无需额外努力即可满足, 而另外两个则不然 — 除了 C++ 和标准库最常见的那些基本类型. T 的相等性和哈希被 flyweight<T> 的内部工厂在内部使用, 以维护享元对象所引用的唯一 T 值的公共仓库. 有关为自定义数据类型扩展该库的内容, 请查阅 Boost.Hash 文档的相应小节.

如前所述, 对 T 的相等性和哈希要求, 由享元工厂的特定类型施加, 该工厂由 flyweight<T> 内部使用. 我们稍后会看到, 用户可以定制该工厂以使用不同于默认值的相等性和哈希谓词, 甚至切换到可能对 T 施加其他要求的完全不同类型的工厂, 如配置 Boost.Flyweight一节所述.
