这篇对 lambda 表达式的简短介绍面向不熟悉 Boost MPL Library 的读者, 他们希望在 Boost.Flyweight 中使用这些概念, 需要快速获得基本概念的实际应用知识. 超出这些入门性说明的更多信息请参阅 Boost.MPL 文档.

Boost.Flyweight 定义的指定器严重依赖 Lambda Expression 概念 (由 Boost MPL Library 定义). lambda 表达式可以看作编译期的 "类型函数": 一个实体 (实际上是具体类型), 可以用一组类型调用, 并返回某个关联类型. 例如考虑一个任意的类模板:

template<typename T,typename Q>
class foo
{
  ...
};

并假设我们想要一个 lambda 表达式, 当以某些泛型类型 Arg1 和 Arg2 调用时返回 foo<Arg1,Arg2>. 这样的 lambda 表达式可以有两种实现方式

  1. 作为一个MPL Metafunction Class, 即带有名为 apply 的特殊嵌套类模板的类型: 
    struct foo_specifier
{
  template<typename Arg1,typename Arg2>
  struct apply
  {
    // this is the "return type" of foo_specifier
    typedef foo<Arg1,Arg2> type;
  };
};
  2. 作为一个MPL Placeholder Expression, 即用一个或多个占位符实例化的类模板: 
    typedef foo<boost::mpl::_1,boost::mpl::_2> foo_specifier;
    注意, 此时的 foo_specifier 是具体类型, 正如 int 或 std::set<std::string> 一样; 然而, MPL 的内部机制能够检测出该类型是用占位符 boost::mpl::_1 和 boost::mpl::_2 实例化类模板而得到的, 并把这些占位符当作槽位, 在调用 foo_specifier 时替换为实际类型 (分别为第一个和第二个传入类型). 因此, foo 的一个实例化可以用来反向引用 foo 类模板本身! 净效果与元函数相同, 但占位符表达式免去了我们编写样板元函数类的必要 — 而且它们所依赖的那种元编程魔法有着不可否认的魅力.
到目前为止, 所示示例只是把实参 Arg1 和 Arg2 直接转发给类模板而没有进一步加工, 但没有什么能阻止我们做一点实参处理, 例如交换它们的位置: 

struct foo_specifier
{
  template<typename Arg1,typename Arg2>
  struct apply{typedef foo<Arg2,Arg1> type;};
};

typedef foo<boost::mpl::_2,boost::mpl::_1> foo_specifier;

把占位符子表达式作为实参传给整个表达式:

struct foo_specifier
{
  template<typename Arg1,typename Arg2>
  struct apply{typedef foo<boost::shared_ptr<Arg1>,std::less<Arg2> > type;};
};

typedef foo<
  boost::shared_ptr<boost::mpl::_1>,
  std::less<boost::mpl::_2>
> foo_specifier;

或者接受比类模板自身更少或更多的实参 (lambda 表达式的参数个数称为它的元数 (arity)):

struct foo_specifier
{
  template<typename Arg1>
  struct apply{typedef foo<Arg1,std::less<Arg1> type;};
};

typedef foo<boost::mpl::_1,std::less<boost::mpl::_1> > foo_specifier;

struct foo_specifier
{
  template<typename Arg1,typename Arg2,typename Arg3>
  struct apply{typedef foo<Arg1,foo<Arg2,Arg3> > type;};
};

typedef foo<boost::mpl::_1,foo<boost::mpl::_2,boost::mpl::_3> > foo_specifier;
