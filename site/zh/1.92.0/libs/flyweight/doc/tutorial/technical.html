静态数据初始化

对任何给定的 T, 类型 flyweight<T> 维护一些类级别 (静态) 数据, 需要在类被使用之前恰当地初始化. Boost.Flyweight 的内部机制保证: 静态数据初始化会在程序中首次使用特定 flyweight<T> 实例化之前自动进行, 并且无论如何总是在程序启动序列的所谓动态初始化阶段期间完成. 虽然 C++ 标准并没有严格如此要求, 但在当前实践中, 动态初始化会在 main() 开始之前完成.

因此, 从所有实际目的来看, 静态数据初始化在 main() 之前、或在类的首个 pre-main() 使用之前执行, 例如我们声明一个全局 static flyweight<T> 对象时. 这以透明的方式覆盖了绝大多数使用情形, 但仍有一些场景会使 Boost.Flyweight 的自动静态数据初始化策略失效:

// global thread pool

class thread_pool
{
public:
  thread_pool()
  {
    for(int i=0;i<100;++i)p[i]=shared_ptr<thread>(new thread(thread_fun));
  }

private:
  static void thread_fun()
  {
    // uses flyweight<std::string>
  }
  array<shared_ptr<thread>,100> p;
};

static thread_pool thpool;

int main()
{
  ...

该示例的全局线程池启动了多个线程, 每个线程内部使用 flyweight<std::string>. 如果两个线程恰好在首次使用 flyweight<std::string> 时相撞, 静态数据初始化可能并发执行两次: Boost.Flyweight 的初始化不考虑线程安全. 因此, 我们需要在启动线程之前, 在线程安全的上下文中显式处理静态数据初始化:

class thread_pool
{
public:
  thread_pool()
  {
    flyweight<std::string>::init();
    for(int i=0;i<100;++i)p[i]=shared_ptr<thread>(new thread(thread_fun));
  }
  ...

静态成员函数 init 也不是线程安全的: 在我们的特定例子中, 它恰好在单线程环境中被调用. 当可能发生并发时, flyweight<T>::init 必须由程序员使用某种互斥机制来恰当地同步.

以下是 Boost.Flyweight 所提供的默认静态初始化可能失效的另一个例子:

static std::vector<flyweight<std::string> > v;

int main()
{
  // use v
}

在某些环境中, 上面的程序在退出时失败. 例如, 若在 Microsoft Visual C++ 环境中以调试模式运行, 终止时会触发断点, 调试输出窗口显示如下消息:

HEAP[test.exe]: HEAP: Free Heap block 3a6488 modified at 3a6650 after it was
freed
Windows has triggered a breakpoint in test.exe.
This may be due to a corruption of the heap, and indicates a bug in test.exe
or any of the DLLs it has loaded.
The output window may have more diagnostic information

问题是什么? 虽然 v 的类型涉及 flyweight<std::string>, 把 v 构造为空 vector 未必创建任何真正的享元对象; 因此完全可能 flyweight<std::string> 的静态初始化晚于 v 的构造; 若是如此, 关联工厂的静态销毁将早于 v 的销毁发生, 给 vector 留下悬垂的享元. 同样, 解决办法是显式强制 flyweight<std::string> 的静态实例化 — 在 v 被创建之前. 这里, 调用函数 flyweight<std::string>::init 有点繁琐, 所以我们可以借助工具类型 flyweight<std::string>::initializer 来替我们完成这项工作:

// equivalent to calling flyweight<std::string>::init()
static flyweight<std::string>::initializer  fwinit;
static std::vector<flyweight<std::string> > v;

int main()
{
  // use v; no dangling flyweights at termination now
}
