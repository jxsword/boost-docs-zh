头文件 "boost/flyweight/flyweight.hpp" 概要

类模板 flyweight

flyweight<...> 类型的对象提供对 flyweight<...>::value_type 类型不可变值的访问, 相比使用普通 value_type 对象有以下优点:

  • 值等价的享元对象共享同一表示 (关联的 value_type 对象).
  • 享元的大小通常与一个指针相当, 一般小于 sizeof(value_type).
因此, 如果冗余度 (对象总数与不同值数量之比) 足够高, 用 flyweight 的一个合适实例化替换 value_type 就会带来内存使用的减少.

flyweight 依据以下方面进行参数化:

  • 类型 key_value 和 value_type (可以相同), 其中 key_type 用作键类型, 用于查找并构造 value_type 对象的内部共享实例.
  • 一个可选的标签类型, 用于在语法上区分其他方面完全相同的实例化.
  • 用于存储和取回共享值对象的工厂类.
  • 用于实例化享元工厂和互斥量对象的持有器的类型, 两者对 flyweight 类模板的每个特化都是唯一的.
  • 确定内部访问共享资源的同步机制的锁定策略.
  • 一个跟踪策略, 控制当所有关联的享元对象都被销毁时如何处理这些值.
这些方面以下列方式影响 flyweight 实例化的内部结构和行为:
  • flyweight 的每个实例化内部都拥有一个唯一的工厂对象和一个唯一的同步互斥量对象, 两者都通过使用关联的持有器类型创建.
  • 享元工厂存储一个未公开类型 Entry 的元素, 该类型可隐式转换为 const key_type&, 工厂还存储一个 value_type 的子对象. 每个享元对象都与工厂中存储的某个 value_type 对象的一个 Entry 子对象相关联.
  • 关联的互斥量对象用于保护对内部享元工厂插入和删除函数的所有调用.
  • 每个享元对象内部存储某个未公开类型 Handle 的值. Handle 和上文提到的 Entry 类型通过调用关联的跟踪策略获得, 方式如该概念的说明所述.
在下文中, 我们隐含地假定 key_type 等价性指的是所使用的工厂类诱导的等价关系. 同样, value_type 的两个值若由等价键构造, 或是由由等价键构造的对象的副本, 则被视为等价. 

#include <initializer_list>

template<
  typename T,
  typename Arg1,typename Arg2,typename Arg3,typename Arg4,typename Arg5
>
class flyweight
{
public:
  typedef dependent on T key_type;
  typedef dependent on T value_type;

  // static data initialization:

  static bool init();
  class initializer{public:initializer();};
    
  // construct/copy/destroy:
  
  flyweight();

  template<typename... Args>
  explicit flyweight(Args&&... args);

  template<typename V>
  flyweight(std::initializer_list<V> list);

  flyweight(const flyweight& x) noexcept;
  flyweight(flyweight& x) noexcept;
  flyweight(const flyweight&& x) noexcept;
  flyweight(flyweight&& x) noexcept;
 
  explicit flyweight(const value_type& x);
  explicit flyweight(value_type& x);
  explicit flyweight(const value_type&& x);
  explicit flyweight(value_type&& x);

  template<typename V>
  flyweight& operator=(std::initializer_list<V> list);

  flyweight& operator=(const flyweight& x) noexcept;  

  flyweight& operator=(const value_type& x);
  flyweight& operator=(value_type&& x);

  // convertibility to underlying type:

  const key_type&   get_key() const noexcept(see below);
  const value_type& get() const noexcept;
  const value_type& operator*() const noexcept;
  operator const    value_type&() const noexcept;  
  const value_type* operator->() const noexcept;

  // modifiers:

  void swap(flyweight& x) noexcept;
};

实例化类型

T 可以是:

  • 任意类型,
  • 形式为 key_value<Key,Value[,KeyFromValue]> 的类型.
第一种情况下, 嵌套类型 key_type 和 value_type 都等于 T. 第二种情况下, key_type=Key、value_type=Value; 此时我们说 flyweight 的实例化是一个键值享元. value_type 是享元对象提供访问的值的类型, 而值的查找基于关联的 key_type 值. key_value 必须是MoveConstructible, 且 value_type 必须可从 key_type 构造; 此外, key_value 必须满足所用工厂类型施加的任何额外要求. 对于键值享元, 保证创建或赋值一个享元对象最多导致一次 value_type 对象的构造 (某些特定情况下为拷贝构造), 并且该构造只在享元工厂中先前不存在等价值的情况下发生.

类型 Arg1、…、Arg5 (如果提供) 必须是以下之一, 顺序不限:

  • 一个标签,
  • 一个工厂指定器,
  • 一个持有器指定器,
  • 一个锁定策略,
  • 一个跟踪策略.
任何方面都不得指定两次. flyweight 实例化的每个内部组件都通过使用相应的指定器获得; 例如, 工厂来自对给定工厂指定器的某次 (MPL) 调用, 内部互斥量来自给定的锁定策略, 等等. 默认配置实参为:
  • 无标签,
  • hashed_factory<>,
  • static_holder,
  • simple_locking,
  • refcounted 跟踪策略.

静态数据初始化

给定 flyweight 实例化内部的静态数据 (工厂实例等) 在程序的动态初始化阶段构造, 且总是在该实例化类首次被程序范围使用之前. 当需要对构造时机做更多控制时, 可以使用以下工具.

static bool init();
效果: 执行该函数后, 与 flyweight 实例化关联的静态数据保证已构造.
注释: 并发执行该函数不是线程安全的.
initializer::initializer();
效果: 执行 init().

构造函数、拷贝与赋值

flyweight();
效果: 以值 flyweight 构造一个 value_type(key_type()) 对象, 若 flyweight 为键值型; 否则以 value_type() 构造.
template<typename... Args>
explicit flyweight(Args&&... args);
效果: 以值 flyweight 构造一个 value_type(key_type(std::forward<Args>(args)...)) 对象, 若 flyweight 为键值型; 否则以 value_type(std::forward<Args>(args)...) 构造.
注释: 在不支持变参模板的编译器上, 实现会用若干重载来替代该构造函数, 这些重载接受 const/非 const 左值/右值引用实参的任意组合, 数量上限可由用户全局配置.
template<typename V>
flyweight(std::initializer_list<V> list);
效果: 以值 flyweight 构造一个 value_type(key_type(list)) 对象, 若 flyweight 为键值型; 否则以 value_type(list) 构造.
注释: 该成员函数模板针对特定 std::initializer_list<V'> 的特化不可用, 除非 key_type 可从 std::initializer_list<V'> 构造.
flyweight(const flyweight& x) noexcept;
flyweight(flyweight& x) noexcept;
flyweight(const flyweight&& x) noexcept;
flyweight(flyweight&& x) noexcept;
效果: 构造一个 flyweight 对象, 与 x 关联到相同的值.
explicit flyweight(const value_type& x);
explicit flyweight(value_type& x);
explicit flyweight(const value_type&& x);
explicit flyweight(value_type&& x);
要求: value_type 可从实参的类型构造. 若 flyweight 为键值型, 则 Key Extractor KeyFromValue 必须已作为 key_value<> 构造的一部分提供.
效果: 构造一个 flyweight, 关联到 x 的一个副本, 或关联到一个 value_type, 它以与 x 所关联键等价的键构造. 对于非键值享元, x 就是它自己的键; 对于键值享元, 键通过使用 KeyFromValue 类型的对象提取.
template<typename V>
flyweight& operator=(std::initializer_list<V> list);
效果: *this=flyweight(list).
返回: *this.
注释: 该成员函数模板针对特定 std::initializer_list<V'> 的特化不可用, 除非 key_type 可从 std::initializer_list<V'> 构造.
flyweight& operator=(const flyweight& x) noexcept;
效果: 把 flyweight 对象关联到与 x 相同的值.
返回: *this.
flyweight& operator=(const value_type& x);
flyweight& operator=(value_type&& x);
效果: *this=flyweight(x) (第一个重载), *this=flyweight(std::move(x)) (第二个重载).
返回: *this.

到底层类型的可转换性

返回: value_type 的键的副本, 该键被用于构造与 flyweight 对象相关联的享元.
注释: noexcept, 若 flyweight 不是键值型, 或未提供 KeyFromValue, 或 noexcept(std::declval<KeyFromValue>()(std::declval<const value_type&>())).
const value_type& get() const noexcept;

返回: 与 flyweight 对象相关联的值.
const value_type* operator->() const noexcept;

修改器

效果: 交换每个享元对象所关联的 value_type. 不交换 key_type 或 value_type 对象.

哈希支持

为 flyweight 提供哈希支持, 既可通过 std::hash 也可通过boost::hash. 两种情况下, 计算都不涉及对关联的 value_type 对象本身做哈希; 因此 value_type 是否可哈希无关紧要. std::hash 和 boost::hash 对同一个 flyweight 对象给出的结果通常不同.
注释: 哈希支持可以禁用, 以解决与用户已定义此类功能的代码的冲突.

namespace std{
template<typename T,typename Arg1,...,typename Arg5>
struct hash<boost::flyweight<T,Arg1,...,Arg5> >;
}
该模板特化满足类模板 std::hash (见 [unord.hash]) 的要求. 其函数调用运算符为 noexcept.
template<typename T,typename Arg1,...,typename Arg5>
inline std::size_t hash_value(const flyweight<T,Arg1,...,Arg5>& x) noexcept;
返回: x 的哈希值, 供 Boost.ContainerHash 使用.

配置宏

BOOST_FLYWEIGHT_LIMIT_PERFECT_FWD_ARGS
在无变参模板支持的编译器中, 全局定义该宏以设置 flyweight 转发构造函数接受的实参个数上限, 默认为 5.
BOOST_FLYWEIGHT_DISABLE_HASH_SUPPORT
若定义了该宏, 则不提供哈希支持. 这对于应对用户已定义了通用 flyweight 哈希的遗留代码很有用.

头文件 "boost/flyweight/serialize.hpp" 概要

serialize.hpp 包含使 flyweight 能够与 Boost.Serialization 互操作所需的功能.

序列化

flyweight 可以通过 Boost.Serialization 存入档案和取出. 支持常规档案和 XML 档案. 序列化以高效方式完成, 因此保存等价的 flyweight 时, 它们共同的 key_type 值只会存储一次, 无论 key_type 是否被 Boost.Serialization跟踪.

操作: 把 flyweight 对象 x 保存到输出档案 (XML 档案) ar.
要求: key_type 可序列化 (可 XML 序列化).
效果: 值 k=x.get_key() 被保存到 ar 中, 作为本操作或先前对 flyweight 对象 (具有相同键) 的保存操作的一部分.
异常安全性: 就 x 而言为强保证. 若抛出异常, ar 可能处于不一致状态.
操作: 加载 flyweight x' — 自输入档案 (XML 档案) ar.
要求: key_type 可序列化 (可 XML 序列化).
效果: x' 被关联到一个值, 该值由与 k' 等价的键构造, 是上文定义的值 k 的还原副本.
异常安全性: 就 x' 而言为强保证. 若抛出异常, ar 可能处于不一致状态.
