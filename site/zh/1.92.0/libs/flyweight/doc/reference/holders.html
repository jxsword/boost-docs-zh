持有器与持有器指定器

给定类型 C, 类型 Holder 被称为 C 的持有器, 如果表达式 Holder::get() 返回对 C 类型默认初始化对象的引用, 且该对象对 Holder 而言唯一. 除了可能是程序中的第一次调用之外, 对 Holder::get() 的任何调用都不抛出异常. flyweight 私有地使用一个持有器来实例化一个工厂以及一些附加数据 (例如用于内部同步的互斥量), 这些数据对类模板的每个实例化类型都是唯一的.

若满足以下条件, 则类型 S 是一个持有器指定器:

  1. 满足以下条件之一:
    1. is_holder<S>::type 是 boost::mpl::true_,
    2. S 的形式为 holder<S'>.
  2. S, 或 (当 (b) 适用时的) S', 是一个MPL Lambda Expression, 以类型 C 调用它将解析为 C 的持有器.

头文件 "boost/flyweight/holder_tag.hpp" 概要

namespace boost{

namespace flyweights{

struct holder_marker;

template<typename T>
struct is_holder;

template<typename T>
struct holder;

} // namespace boost::flyweights

} // namespace boost

类模板 is_holder

除非用户特化, is_holder<T>::type 为 boost::mpl::true_ (当 T 派生自 holder_marker 时), 否则为 boost::mpl::false_.

类模板 holder

holder<T> 是一种语法构造, 用于表明 T 是持有器指定器, 而不借助 is_holder 类模板所提供的机制.

头文件 "boost/flyweight/intermodule_holder.hpp" 概要

类模板 intermodule_holder_class

intermodule_holder_class<C> 维护一个 C 实例, 即使在程序的不同动态链接模块之间该实例也保持唯一. 一般来说, static_holder_class 不提供这一保证, 因为大多数 C++ 实现无法合并存储在程序不同动态模块中的静态变量的副本.

类 intermodule_holder

Holder Specifier, 用于 intermodule_holder_class.
