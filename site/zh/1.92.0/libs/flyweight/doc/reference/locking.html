预备概念

互斥量是这样一种类型: 其对象可处于两种状态之一, 称为锁定和解锁, 并且具有如下性质: 当线程 A 已锁定互斥量 m 而另一线程 B 试图锁定 m 时, B 会被阻塞, 直到 A 解锁 m. 此外, 若线程能够对已被该线程自身锁定的互斥量成功调用加锁操作, 则称该互斥量支持递归锁定; 此时要求线程执行的解锁操作次数与它为使互斥量真正解锁而执行的加锁操作次数相同. 作用域锁是与某个互斥量类型关联的类型, 其对象在构造/析构时对互斥量加锁/解锁.

在下表中, Mutex 是一个互斥量类型, m 是 Mutex 类型的一个对象, Lock 是与 Mutex 关联的作用域锁, lk 是 Lock 的一个值.

互斥量与作用域锁要求.
表达式 返回类型 断言/注释
前/后置条件
Mutex m;   后置: m 处于解锁状态.
(&m)->~Mutex(); void 前置: m 处于解锁状态.
Lock lk(m);   把 m 关联到 lk 并锁定 m.
(&lk)->~Lock(); void 解锁与 lk 关联的互斥量.

这些概念与Boost Thread Library中描述的同名概念非常相似, 但并不完全等价.

锁定策略

锁定策略描述一个互斥量类型和与之关联的作用域锁类型. flyweight使用给定的锁定策略来同步对其内部工厂的访问.

若满足以下条件, 则类型 Locking 是一个锁定策略:

  • 满足以下条件之一:
    1. is_locking<Locking>::type 是 boost::mpl::true_,
    2. Locking 的形式为 locking<Locking'>.
  • 类型 Locking::mutex_type (或当 (b) 适用时的 Locking'::mutex_type) 是Mutex的一个模型, 且支持递归锁定.
  • 类型 Locking::lock_type (或当 (b) 适用时的 Locking'::lock_type) 是上文所述互斥量的一个Scoped Lock.

头文件 "boost/flyweight/locking_tag.hpp" 概要

namespace boost{

namespace flyweights{

struct locking_marker;

template<typename T>
struct is_locking

template<typename T>
struct locking;

} // namespace boost::flyweights

} // namespace boost

类模板 is_locking

除非用户特化, is_locking<T>::type 为 boost::mpl::true_ (当 T 派生自 locking_marker 时), 否则为 boost::mpl::false_.

类模板 locking

locking<T> 是一种语法构造, 用于表明 T 是锁定策略, 而不借助 is_locking 类模板所提供的机制.

头文件 "boost/flyweight/simple_locking.hpp" 概要

类 simple_locking

Locking Policy, 指定一个基于环境所提供的最简单同步机制的基本互斥量类型; 当没有线程能力可用时, simple_locking 指定一个没有实际同步能力的哑类型.

类 no_locking

空Locking Policy: 它指定一个满足Mutex概念的形式要求、但不执行线程阻塞的哑类型. no_locking 只应在单线程环境中使用.
