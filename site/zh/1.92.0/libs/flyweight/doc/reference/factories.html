工厂与工厂指定器

给定类型 Key 和一个MoveConstructible 类型 Entry (可隐式转换为 const Key&), 一个 Entry 元素的工厂 (隐式关联到 Key) 是一个DefaultConstructible 实体, 能够存储和取回 Entry 类型的不可变元素. 工厂由定义在 Key 上的关联等价关系管辖, 因此任何两个 Entry 对象, 只要可转换为等价的 Key, 就不能同时存储在工厂中. 不同的工厂类型可以使用不同的等价关系.

在下表中, Factory 是一个 Entry 类型元素的工厂, f 表示 Factory 类型的一个对象, x 表示 Entry 类型的非 const 右值, h 是 Factory::handle_type 的一个值.

f.insert(x); handle_type 插入 x 的一个副本, 条件是 f 中没有等价条目;

f.entry(h); const Entry& 返回指向与 h 相关联的元素的引用.
该操作不抛出异常.

除了对包括 C++ 标准库大多数组件在内的多数类都隐含假定的基本线程安全保证之外, 还要求成员函数 entry 可以从不同线程同时调用, 即使存在对 insert 和 erase 的并发访问 (只要 entry 返回的条目不是正在被擦除的那个).

若满足以下条件, 则称类型 S 为工厂指定器:

  1. 满足以下条件之一:
    1. is_factory<S>::type 是 boost::mpl::true_,
    2. S 的形式为 factory<S'>.
  2. S, 或 (当 (b) 适用时的) S', 是一个MPL Lambda Expression, 以类型 (Entry, Key) 调用它将解析为 Entry 元素的工厂类型 (隐式关联到 Key).

头文件 "boost/flyweight/factory_tag.hpp" 概要

namespace boost{

namespace flyweights{

struct factory_marker;

template<typename T>
struct is_factory;

template<typename T>
struct factory;

} // namespace boost::flyweights

} // namespace boost

类模板 is_factory

除非用户特化, is_factory<T>::type 为 boost::mpl::true_ (当 T 派生自 factory_marker 时), 否则为 boost::mpl::false_.

类模板 factory

factory<T> 是一种语法构造, 用于表明 T 是工厂指定器, 而不借助 is_factory 类模板所提供的机制.

头文件 "boost/flyweight/hashed_factory.hpp" 概要

类模板 hashed_factory_class

hashed_factory_class 是一个Factory, 以哈希容器实现.

template<
  typename Entry,typename Key,
  typename Hash,typename Pred,typename Allocator
>
class hashed_factory_class
{
public:
  typedef implementation defined handle_type;
  
  handle_type  insert(Entry&& x);
  void         erase(handle_type h);
  const Entry& entry(handle_type h);
};

Hash 是一个DefaultConstructible Hash 函数对象, 用于 Key 类型的实参. Pred 是一个DefaultConstructible BinaryPredicate, 在 Key 的元素上诱导一个等价关系. 要求 Hash 对象对在 Pred 下等价的对象返回相同的值. 与工厂关联的 Key 上的等价关系即由 Pred 诱导的那个. Hash 和 Pred 的默认实参分别是 boost::hash<Key> 和 std::equal_to<Key>. Allocator 必须是 Allocator, 适用于 Entry 对象. 默认实参为 std::allocator<Entry>. hashed_factory_class 所基于的内部哈希容器以 Hash、Pred 和 Allocator 类型的默认初始化对象构造.

类模板 hashed_factory

Factory Specifier, 用于 hashed_factory_class.

template<typename Hash,typename Pred,typename Allocator>
struct hashed_factory;

hashed_factory<Hash,Pred,Allocator> 是一个MPL Metafunction Class, 使得类型

boost::mpl::apply<
  hashed_factory<Hash,Pred,Allocator>,
  Entry,Key
>::type

与

boost::mpl::apply<
  hashed_factory_class<boost::mpl::_1,boost::mpl::_2,Hash,Pred,Allocator>,
  Entry,Key
>::type

这意味着 Hash、Pred 和 Allocator 可以被MPL Placeholder Expressions, 解析为 hashed_factory_class 所用的实际类型.

头文件 "boost/flyweight/concurrent_factory.hpp" 概要

类模板 concurrent_factory_class

concurrent_factory_class 是一个Factory, 以并发哈希容器实现. 该工厂不需要外部锁, 即使在多线程场景中亦然. 它也不需要任何跟踪机制: 不再被任何享元引用的值不会被确定性地擦除, 而是由运行在专门线程中的内部垃圾收集器周期性地移除.

template<
  typename Entry,typename Key,
  typename Hash,typename Pred,typename Allocator
>
class concurrent_factory_class
{
public:
  typedef implementation defined handle_type;
  
  handle_type  insert(Entry&& x);
  void         erase(handle_type h);
  const Entry& entry(handle_type h);
};

Hash 是一个Hash 函数对象, 用于 Key 类型的实参. Pred 是一个DefaultConstructible BinaryPredicate, 在 Key 的元素上诱导一个等价关系. 要求 Hash 对象对在 Pred 下等价的对象返回相同的值. 与工厂关联的 Key 上的等价关系即由 Pred 诱导的那个. Hash 和 Pred 的默认实参分别是 boost::hash<Key> 和 std::equal_to<Key>. Allocator 必须是 Allocator, 适用于 Entry 对象. 默认实参为 std::allocator<Entry>. concurrent_factory_class 所基于的内部并发容器以 Hash、Pred 和 Allocator 类型的默认初始化对象构造.

头文件 "boost/flyweight/set_factory.hpp" 概要

类模板 set_factory_class

set_factory_class 是一个Factory, 构建于有序关联容器之上.

template<
  typename Entry,typename Key,
  typename Compare,typename Allocator
>
class set_factory_class
{
public:
  typedef implementation defined handle_type;
  
  handle_type  insert(Entry&& x);
  void         erase(handle_type h);
  const Entry& entry(handle_type h);
};

Compare 是一个DefaultConstructible BinaryPredicate, 在 Key 的值上诱导一个严格弱序. 两个 Key (即 x 和 y) 被视为等价, 条件是 !c(x,y)&&!c(y,x) 成立, 其中 c 的类型为 Compare. Compare 的默认实参为 std::less<Key>. Allocator 必须是 Allocator, 适用于 Entry 对象. 默认实参为 std::allocator<Entry>. set_factory_class 所基于的内部容器以 Compare 和 Allocator 类型的默认初始化对象构造.

类模板 set_factory

Factory Specifier, 用于 set_factory_class.

template<typename Compare,typename Allocator>
struct set_factory;

set_factory<Compare,Allocator> 是一个MPL Metafunction Class, 使得类型

boost::mpl::apply<
  set_factory<Compare,Allocator>,
  Entry,Key
>::type

与

boost::mpl::apply<
  set_factory_class<boost::mpl::_1,boost::mpl::_2,Compare,Allocator>,
  Entry,Key
>::type

这意味着 Compare 和 Allocator 可以被MPL Placeholder Expressions, 解析为 set_factory_class 所用的实际类型.

头文件 "boost/flyweight/assoc_container_factory.hpp" 概要

类模板 assoc_container_factory_class

assoc_container_factory_class 包装一个合适的关联容器, 以提供Factory 接口.

template<typename Container>
class assoc_container_factory_class
{
public:
  typedef typename Container::iterator handle_type;
  
  handle_type insert(typename Container::value_type&& x);
  void        erase(handle_type h);
  const typename Container::value_type& entry(handle_type h);
};

Container 必须是一个 (有序或无序) 关联容器, 且满足

  1. Container::key_type 与 Container::value_type 相同 (后者是与该工厂关联的条目类型).
  2. 支持唯一键 (而非等价键).
  3. Container 是稳定的, 即其迭代器不会因插入或擦除操作而失效.
与 assoc_container_factory_class 关联的等价关系即由 Container 诱导的那个. 若 Container::value_type 元素的等价性仅依据 value_type' 可隐式转换到的某个类型 value_type 来确定, 则 assoc_container_factory_class 是一个 value_type 类型条目的工厂, 隐式关联到 value_type'. 例如, 实例化 

assoc_container_factory_class<
  std::set<derived,std::less<base> > // derived inherits from base
>

是一个 derived 元素的工厂, 隐式关联到 base.

类模板 assoc_container_factory

Factory Specifier, 用于 assoc_container_factory_class.

template<typename ContainerSpecifier>
struct assoc_container_factory;

ContainerSpecifier 必须是一个MPL Lambda Expression, 当以 (Entry, Key) 调用时解析为类型 Container, 使得 assoc_container_factory_class<Container> 是一个 Entry 元素的工厂, 隐式关联到 Key.
