Boost.Flyweight 的未来版本可以纳入新功能, 以满足用户需求, 并利用即将到来的 C++ 特性和新的 Boost 库. 以下是候选新增项列表.

目录

  • 内省 API
  • 读/写锁策略
  • 与新 Boost 库的集成

内省 API

目前没有办法访问 flyweight 实例化的内部组件 (工厂、持有器等), 甚至无法得知这些组件的类型. 有了这样的 API, 就可以像下面这个例子那样对 Boost.Flyweight 的使用进行插桩和监控:

typedef flyweight<std::string> fw_type;
...
std::cout<<"factory used:  "<<typeid(fw_type::factory_type).name()<<std::endl;
std::cout<<"values stored: "<<fw_type::factory().size()<<std::endl;

读/写锁策略

享元模式的本质意味着, 对内部享元工厂的大多数访问不会引起新的插入, 因此可视为只读. 这提示了使用基于读/写锁的锁定策略的便利性, 例如 Boost.Thread 提供的那些. 实现锁定策略还需要扩展 Factory 概念, 以允许纯查找操作. Tim Blechmann 已提供了这一想法的一个初步实现. 在承诺进行这一库扩展之前, 有必要先做性能剖析研究, 以确定读/写锁是否真能提升性能.

与新 Boost 库的集成

最近被接受的 Boost 库, 如 Boost.Functional/Forward 和 Boost.Functional/Factory, 未来或许可用于替换 Boost.Flyweight 的一些内部机制.
