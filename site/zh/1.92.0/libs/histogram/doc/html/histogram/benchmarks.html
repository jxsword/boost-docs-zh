该库的设计目标就是快速. 配置得当时, 它是市面上最快的库之一. 如果你发现比 Boost.Histogram 更快的库, 请在 Github 上提交 issue. 我们重视性能.

话虽如此, 填充直方图所花的时间通常不是应用程序的瓶颈. 只有在处理非常大的数据集时, 直方图的性能才可能变得重要.

所有基准测试均在配备 2,9 GHz Intel Core i5 处理器的笔记本电脑上使用 Apple LLVM (clang-1001.0.46.4) 以及标志 -DNDEBUG -O3 -funsafe-math-optimizations 编译. 添加 -fno-exceptions -fno-rtti 可将 Boost.Histogram 性能再提高 (10-20) %, 但出于公平起见此处未这样做, 因为 ROOT 直方图无法用这些选项编译.

填充性能

将 Boost.Histogram 不同配置的填充性能与其他库的直方图类和函数进行比较. 来自均匀分布和正态分布的随机数被填充到具有 1、2、3、6 个轴的直方图中. 1、2、3 轴情形每轴使用 100 个区间; 6 轴情形每轴使用 10 个区间. 直方图用调用运算符 operator() 以及更高效的 fill 方法填充, 后者一次接受大块值. GSL 只提供 1D 和 2D 直方图, 因此更高维的基准测试中没有对应条目. 原始计时结果被转换为每个输入值所用的平均 CPU 周期数.

每个基准测试对应一根条形, 其上端有一段阴影部分. 完整条形是直方图填充随机正态分布数据的结果, 其中约 10 % 的情况落在轴域之外. 这会不时使 CPU 中的分支预测器失效, 从而降低性能. 无阴影部分的条形是直方图填充始终位于轴范围内的均匀随机数的结果.

Boost.Histogram 比其他库更快. 同时, 它也更加灵活, 因为轴和存储器类型可以定制. 使用 operator() 时, 编译期配置轴的直方图 (boost-sta-...) 总是比其他库的等效替代方案更快. 运行期配置轴的直方图 (boost-dyn-...) 与其他库相当或更慢, 但提供了替代方案所不具备的运行期灵活性. 若使用 fill 方法, 填充任一类型的直方图都比填充其他库的直方图快得多 (最高 6 倍), 且编译期与运行期配置轴之间的性能差异大多消失.

迭代性能

Boost.Histogram 提供 boost::histogram::indexed 范围生成器, 用于便捷地遍历直方图单元格. 使用范围生成器非常方便, 且比编写嵌套 for 循环更快.

// nested for loops over 2d histogram
for (int i = 0; i < h.axis(0).size(); ++i) {
  for (int j = 0; j < h.axis(1).size(); ++j) {
    std::cout << i << " " << j << " " << h.at(i, j) << std::endl;
  }
}

// same, with indexed range generator
for (auto&& x : boost::histogram::indexed(h)) {
  std::cout << x.index(0) << " " << x.index(1) << " " << *x << std::endl;
}

针对将轴保存在 std::tuple (元组)、std::vector (向量) 以及 std::vector<boost::histogram::axis::variant> (variant 向量) 中的直方图, 比较了这两种迭代策略的每区间访问时间. 每区间访问时间在每轴 4 到 128 个区间的轴上进行测量.
