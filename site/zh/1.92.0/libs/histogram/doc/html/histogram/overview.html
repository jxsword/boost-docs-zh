引言

直方图 是统计分析中的基本工具. 直方图由数据空间中若干互不重叠的单元格组成. 当一个输入值传给直方图时, 找到包住该值的对应单元格并递增其关联的计数器.

分析大型低维数据集时, 使用输入值的直方图比使用原始值更方便. 在内存中保存单元格计数以进行分析和/或处理计数, 所需资源远少于在内存中保存原始值并处理它们. 原始数据中包含的信息也可以从直方图[1]中提取. 这样会丢失一些信息, 但若单元格足够小[2], 损失可以忽略不计. 直方图是一种有损数据压缩. 它也常用作输入数据 概率密度函数 的简单估计器. 存在更复杂的密度估计器, 但直方图仍然具有吸引力, 因为它易于推理.

本库为多维数据提供直方图. 在多维情形中, 输入由属于一起、描述同一实体不同方面的值元组组成. 例如, 用相机拍摄数字图像时, 光子撞击像素探测器. 光子是实体, 它有两个坐标值表示它撞击探测器的位置. 相机只统计光子撞击每个单元格的频次, 因此这是创建二维直方图的真实例子. 二维直方图收集的信息比两个独立的一维直方图 (每个坐标一个) 更多. 例如, 若二维图像看起来像棋盘, 高低密度沿每个坐标交替出现, 那么沿每个坐标的一维直方图会显得平坦. 完全看不出二维中存在复杂结构.

直方图 一词通常严格用于在离散或连续数据上具有单元格的东西. 此直方图类也可以处理分类变量, 甚至允许非连续的单元格 (如有需要). 输入也不限于数字. 任何 C++ 类型都可以喂给直方图, 只要用户提供专门的轴类将该类型的值映射到单元格索引. 剩下的唯一限制是单元格互不重叠, 因为必须存在从输入值到单元格的唯一映射. 库无法为用户提供的轴类自动保证这一点, 因此责任在用户.

此外, 直方图可以处理加权输入. 通常, 与输入元组关联的单元格计数器加一, 但有时按权重 (整数或浮点数) 递增更有用. 最后, 直方图可以配置为在每个单元格中存储任何类型的累加器. 任意样本可以传给此累加器, 它可以从归入单元格的样本计算均值或其他有趣的量. 当累加器计算均值时, 结果称为 轮廓. 功能集借鉴了流行的科学计算库, 特别是 CERN 的 ROOT 框架 和 GNU 科学库.

该库由三个正交组件组成:

  • 直方图宿主类: 直方图宿主类定义公共用户接口, 并保存轴对象 (每个维度一个) 和一个存储器对象. 用户可以选择轴对象保存在静态元组、vector 还是 variant 的 vector 中.
  • 轴类型: 定义输入值如何映射到区间. 提供多种轴类型, 实现不同的专门化. 用户可以按照轴概念创建自己的轴类型并与库一起使用. 提供了 variant 类型, 可保存若干具体轴类型之一.
  • 存储器类型: 管理区间计数器集合. 对存储器的要求与 STL 容器不同, 它需要遵循存储器概念. 提供了两种实现.

直方图宿主类

直方图保存轴对象和一个存储器对象. 一维直方图有一个轴, 多维直方图有多个. 当你传入输入元组 (例如 (v1, v2, v3)) 时, 第一个轴将 v1 映射为索引 i1, 第二个轴将 v2 映射为 i2, 依此类推, 生成索引元组 (i1, i2, i3). 直方图宿主类随后将这些索引转换为线性全局索引, 用于在存储器对象中寻址区间计数器.

注释

要理解多维直方图的必要性, 想想点的坐标. 如果你考虑的所有点都在一条线上, 只需要一个值来描述该点. 如果所有点都在一个平面内, 需要两个值来描述位置. 空间中的点需要三个值. 直方图在线、平面或空间上放置离散网格, 并统计每个网格单元格中有多少个点. 要近似线上的点分布, 一维直方图就足够了. 要在三维空间中做同样的事, 需要三维直方图.

本库支持不同的轴类型, 用户可以精确定制映射方式, 参见 轴类型. 此外, 用户可以在直方图中存储轴类型的多种方式之间进行选择.

当轴的数量和类型在编译期已知时, 直方图宿主类将轴类型保存在 std::tuple 中. 我们称之为 静态直方图. 访问特定轴时, 应使用编译期数字作为索引 (运行期索引也可以, 但有一些限制). 静态直方图极其快速 (参见 基准测试), 因为没有开销, 编译器可以内联代码、展开循环等等. 此外, 许多用户错误可以在编译期而非运行期捕获.

静态直方图是最好的形式, 但当直方图要用只在运行期才知道的轴配置创建时无法使用. 例如, 从 Python 或图形用户界面创建直方图时就是这种情况. 因此也支持更动态的直方图形式.

动态性有两个层级. 直方图可以在 std::vector 中保存单一轴类型的实例. 此时每个直方图的轴实例数量可以在运行期变化, 但所有实例的轴类型必须相同. 我们称之为 半动态直方图.

若轴类型也需要在运行期变化, 可以把 boost::histogram::axis::variant 类型放入 std::vector 中, 后者可以保存一组不同具体轴类型之一. 我们称之为 动态直方图. 动态直方图是单一类型, 可以存储任意序列的不同轴类型, 这些类型可以在运行期生成. 然而, 通用 boost::histogram::axis::variant 类型的多态行为有运行期开销. 通常, 性能比静态直方图降低约一半.

注释

将轴类型保存在类 variant 类型 boost::histogram::axis::variant 中的设计决策相比各种运行期多态形式有几个优势. 首先, 它保证属于同一直方图的轴对象在内存中局部地存放在一起, 当直方图在紧凑循环中遍历轴对象 (它经常这样做) 时, 这减少了缓存未命中. 其次, 在此方案中每个轴可以接受不同的值类型. 带虚表的传统多态要求所有类共享相同的方法调用签名, 但我们希望允许不同的轴接受不同类型的实参. variant 非常适合这种情况.

轴类型

轴定义 (一段) 输入值到区间的单射映射. 逻辑封装在轴类型中. 用户可以通过实现 Axis 概念 来创建自己的轴类并与库一起使用. 库自带四种内置类型, 实现不同的专门化.

  • boost::histogram::axis::regular 将实数归入等宽区间. regular 轴还支持单调变换, 在输入值传给轴时应用. 这可用于制作快速的对数轴, 其区间在变量的对数中等宽.
  • boost::histogram::axis::variable 将实数归入宽度可变的区间.
  • boost::histogram::axis::integer 是 regular 轴针对单位区间宽度的整数范围的特化. 它比 regular 轴快得多.
  • boost::histogram::axis::category 是唯一值与区间索引之间的双射映射. 这可用于离散类别数据, 例如 "red"、"green"、"blue".

每种内置轴类型都有一些编译期选项, 用于改变其行为.

  • 所有轴类型都可以有可选的溢出区间. 启用溢出区间后, 若输入值高于轴覆盖的范围, 它不会被丢弃, 而是计入溢出区间.
  • 除 category 轴外, 所有轴类型都可以有可选的下溢区间. 启用下溢区间后, 若输入值低于轴覆盖的范围, 它不会被丢弃, 而是计入下溢区间.
  • 除 category 轴外, 所有轴类型都可以是循环式的, 即轴范围是周期性的. 这对极角等周期性数据很有用.
  • 所有轴类型都可以选择增长. 当输入值超出配置为增长的轴的范围时, 轴的范围会扩展直到该值在范围内. 此选项与循环选项不兼容, 只能激活其中之一.

存储器类型

存储器类型保存实际的单元格值. 它使用一维索引进行单元格查找, 该索引由直方图宿主根据其轴生成的索引计算得到. 存储器无需了解轴. 用户可以通过实现 存储器概念 将自己的存储器类与库集成. 标准容器可以用作存储器后端, 库用 boost::histogram::storage_adaptor 对它们进行适配.

单元格查找经常发生在紧凑循环中且是随机访问. 普通的 std::vector 作为存储器后端工作良好. 有时这是最佳解决方案, 但这种方法有一些注意事项. 用户必须决定用哪种类型表示单元格计数, 这并非显而易见的选择. 整数类型必须足够大以避免计数器溢出, 但若其容量太大, 又只用到一小部分位. 这样就浪费了内存. 浪费内存时会发生更多缓存未命中, 性能下降 (见基准测试). 现代 CPU 的性能很大程度上取决于 CPU 缓存的有效利用, 而缓存仍然很小. 用浮点数代替整数也很危险. 它们不会溢出, 但当尾数位用尽时会限制区间计数.

库中使用的默认存储器是 boost::histogram::unlimited_storage. 它基于以下洞见, 通过动态计数器类型管理解决这些问题. 维数灾难 使区间总数随直方图维度增长而快速增长. 然而, 区间多也会减少每个区间的典型计数, 因为输入值现在分布在多得多的区间上. 这意味着对高维直方图, 小计数器通常就足够了.

因此默认存储器从每单元格最小内存开始, 使用 1 字节. 若任一单元格中的计数即将溢出, 所有单元格同时切换到下一个更大的整数类型. 如此继续, 每当容量用尽时每单元格容量就翻倍, 直到达到每区间 8 字节. 下面的图片以 3 个区间计数器的存储器演示这一过程. 当第一个计数器达到其容量上限时, 总是为所有计数器分配新的内存块.

注释

不溢出保证仅在直方图不使用加权填充或所有权重都是整数时适用. 使用浮点权重时, 默认存储器切换到每单元格一个 double 计数器来存储此类权重之和. double 无法提供不溢出保证.

最好的一点: 尽管动态处理计数器类型有运行期开销, 这种方法对足够大的直方图甚至更快. 基准测试表明, 更好利用缓存带来的收益超过了向正确的区间计数器类型动态派发的运行期开销和偶尔的分配成本. 每次将区间计数器大小翻倍也有帮助, 因为对 N 次递增, 分配只发生 O(logN) 次.


[1] 感兴趣的参数 (如分布的中心) 可以从直方图而不是原始数据集中提取; 同样, 统计模型可以拟合到直方图上.

[2] 多小才算小必须逐案决定.
