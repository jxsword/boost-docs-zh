动机

C++ 缺少一个广泛使用的免费多维直方图类. 编写一维直方图很容易, 但编写通用的多维直方图更具挑战性. 若在愿望清单上再加上科学专业人员需要的几个功能, 实现就变得不平凡, 一个经过充分测试的库解决方案就变得可取.

GNU 科学库 (GSL) 和 CERN 的 ROOT 框架 都有直方图实现. GSL 用 C 提供一维和二维直方图. 这些实现不可定制. ROOT 有经过充分测试的直方图实现, 但它们不可定制且不易正确使用. ROOT 还有类似本库的 beta 阶段新实现, 但它们仍然不够灵活、不易使用, 且离开 ROOT 的其余部分无法使用, 而仅仅为了直方图安装如此庞大的库代价很高.

本库的模板化直方图类具有最小接口, 专注于从输入数据创建直方图这一核心任务. 它通过用户提供的类高度可定制和可扩展. 单一实现同时用于一维和多维直方图. 在安全、可定制和方便的同时, 直方图也非常快. 静态版本 (轴配置在编译期硬编码) 比任何经过测试的竞争对手都快.

核心设计目标之一是隐藏直方图内部计数器的实现细节. 内部计数机制封装在存储器类中, 可以替换. 默认存储器使用自适应内存管理, 使用安全、节省内存且快速. 安全性来自计数不会溢出或被封顶的保证. 这是一个罕见的保证, 在其他库中很难找到. 在标准配置下, 直方图在任何情况下都 直接可用. 有特殊需求的用户可以实现自己的自定义存储器类, 或使用替代的内置基于 array 的存储器.

准则

本库的编写基于在大数据领域 (更确切地说是粒子物理学与天体粒子物理学领域) 工作十年积累的经验. 设计遵循 Bjarne Stroustrup、Scott Meyers、Herb Sutter、Andrei Alexandrescu 和 Chandler Carruth 等人的建议. Python 之禅 (也适用于其他语言) 以及 Eigen 库 的思想都是灵感来源. 功能集设计为 ROOT 框架 和 GNU 科学库 (GSL) 所提供功能的超集.

库的设计目标:

  • 为普通用户提供简单方便的默认行为, 同时为高级用户提供最大程度的定制. 遵循"不为你不使用的东西付费"原则. 你不使用的功能不应对你的性能产生负面影响.
  • 为一维和多维直方图提供相同的接口. 这使接口更易学习, 也更容易把项目从一维分析迁移到多维分析.
  • 隐藏区间计数器如何工作的细节. 这种设计允许有趣的实现, 例如提供不溢出保证的默认存储器, 这是其他库都不提供的.
  • 极简主义、STL 与 Boost 兼容. 将库专注于创建直方图的任务. 其上的功能 (绘图、进一步处理等) 应来自其他库. 这给用户最大的灵活性来混合搭配库. 直方图提供迭代器范围, 允许其他库访问直方图状态. 库提供访问其内部计数器的迭代器, 使其与 STL 算法和其他 Boost 库兼容. 此外, 库还与 Boost.Accumulators 和 Boost.Range 兼容.

不用 lambda 作为轴类型

曾考虑并否决将 lambda 作为简单用户自定义轴类型的形式, 因为它们不允许访问其状态, 例如当前轴大小. lambda 可以完全被局部定义的结构体替代. 局部结构体不能模板化, 也不能有模板方法, 但这不是问题. 在创建结构体的局部上下文中, 所有相关类型必须已经知道, 因此局部定义的结构体可以直接使用这些具体类型, 无需模板.

下溢与溢出区间

轴实例默认添加额外区间, 用于对落在轴覆盖范围之下或之上的值计数 (对那些有意义的类型). 这些额外区间分别称为下溢和溢出区间. 为节省内存, 可以为每个轴单独关闭额外区间, 但通常建议保留它们. 不含下溢和溢出的普通区间称为 内部区间.

下溢和溢出区间在一维直方图中很有用, 在多维直方图中几乎是必需的. 以下是优点:

  • 无丢失: 所有区间计数的总和严格等于直方图被填充的次数. 甚至 NaN 值也会被计数, 按惯例放入溢出区间.
  • 诊断: 意外的极端值会出现在额外区间中, 否则可能被忽视.
  • 归约直方图的能力: 在多维直方图中, 一个轴上的超范围值可能与另一个轴上的范围内的值配对. 若缺少下溢和溢出区间, 这样的值对会完全丢失. 若对直方图应用 reduce 操作 (通过对该维度所有计数求和来移除某些轴), 这会导致直方图沿剩余轴的失真. 当下溢和溢出区间存在时, reduce 操作总是产生与用原始数据填充得到的直方图相同的子直方图.

额外区间的存在不妨碍正常索引. 在带 n 个区间的轴上, 第一个区间的索引为 0, 最后一个区间为 n-1, 而下溢和溢出区间分别可以在索引 -1 和 n 处访问. 这一选择为不知道这些额外区间存在的用户做了优化. 他们会觉得另一种索引方案令人意外, 那种方案从下溢区间的 0 开始, 第一个普通区间在 1. 此外, 所选方案允许在创建直方图的代码中关闭额外区间, 而无需更改下游任何用索引寻址内部区间的代码.

轴的 size 方法返回带符号整数

标准库以无符号整数返回容器大小, 因为容器大小不可能为负. 直方图类的 size() 方法遵循此规则, 但轴类型的 size() 方法返回带符号整数类型. 为什么?

如 关于下溢和溢出的章节 所解释的, 直方图轴可以有可选的下溢区间, 由索引 -1 寻址. 由此可知, 对所有轴类型, 索引类型都必须是带符号整数.

任何轴的 size() 方法都返回同一带符号整数类型. 轴的大小不可能为负, 但这一选择有两个优点. 首先, size() 本身返回的值保证是有效索引, 这很好, 因为它可能用于寻址溢出区间. 其次, 索引与 size() 返回值之间的比较很频繁. 若 size() 返回无符号整数类型, 编译器会为每次比较产生警告, 而且这是应该的. 在大多数机器上, 会发生糟糕的事情: 当你把 -1 与无符号整数 -1 < 1u == false 比较时, 这会在下面这个看似无害的循环中造成严重缺陷:

auto my_axis = /* ... */;
// naive loop to iterate over all bins, including underflow and overflow
for (int i = -1; i <= my_axis.size(); ++i) {
  // body is never executed if return value of my_axis.size() is an unsigned integral type
}

这一选择的优点明显压倒其缺点.

连续轴接受实值单元格索引

每个轴都有一个称为 value(index_type) 的方法, 将索引转换为该索引处的等效值. 若轴是连续的, 在两个相邻整数索引之间的区间中存在许多可能的值. 用户常常想访问这种区间的中心. 访问中心值的一种简单且非常高效的方式是让该方法接受实值索引. 这样, 索引 i 与 i+1 之间第一个区间的中心可以通过传入 i+0.5 简单获得.

这种方案计算高效且直观. 每个连续轴都要求接受实值索引, 事实上, 库的内部代码就利用这一点来检测轴是连续的还是离散的.

关于方差估计

直方图填充后, 可以用 at(...) 方法访问区间计数器. 一些累加器提供 value() 方法返回单元格值 k, 以及 variance() 方法, 返回该单元格 v 方差 的估计.

若直方图的输入值来自 随机过程, 方差估计提供了有用的额外信息. 随机过程的例子包括物理实验或随机某人填写问卷 [3]. 方差 v 是 标准差 的平方. 标准差是一个数字, 告诉我们如果我们或别人用新的随机输入重复实验, 预期观测值会波动多少.

方差估计在许多方面有用:

  • 误差棒: 绘制 误差棒 覆盖区间 (k - sqrt(v), k + sqrt(v)), 是对区间值 k 预期随机散布的简单可视化, 前提是直方图被清空并用另一个同样大小的独立样本重新填充 (例如重复物理实验或请更多人填写问卷). 若你将结果与拟合模型比较 (见下一项), 若模型正确, 大约 2/3 的误差棒应与模型重叠.
  • 最小二乘拟合: 通常你对每区间预期计数 lambda 有一个模型, 它是参数值未知的函数. 为这些参数值找到好 (有时是最佳) 估计的简单方法是变动它们, 直到残差平方和 (k - lambda)^2/v 最小. 这就是 最小二乘法, 其中区间值 k 和方差估计 v 都要参与.
  • pull 分布: 若你有两个填充了相同数量样本的直方图, 想知道它们是否一致, 可以比较所谓的 pull 分布. 它通过将计数相减再除以其方差平方根构成 (k1 - k2)/sqrt(v1 + v2). 若两个直方图相同, pull 分布随机散布在零附近, 大约 2/3 的值位于区间 [ -1, 1] 中.

为什么返回方差 v 而不是标准差 s = sqrt(v)? 原因是方差可以直接相加, 返回方差在计算上更高效. 独立样本的方差可以相加, 如同普通数字 v3 = v1 + v2. 标准差则不然, 其相加法则更复杂 s3 = sqrt(s1^2 + s2^2). 从这个意义上说, 在数据处理过程中使用方差更直接. 用户可以在处理结束时取平方根, 按需获得标准差.

普通计数直方图的方差估计 v 是如何计算的? 若我们知道每区间的预期计数 lambda, 我们可以按 v = lambda 计算方差, 因为直方图中的计数遵循 泊松分布 [4]. 填充直方图后, 我们不知道任何特定区间的预期计数 lambda, 但我们知道观测计数 k, 它与 lambda 相差不太远. 因此我们可能想把公式 v = lambda = k 中的 lambda 替换为 k. 这实际上就是基于 代入原理 的所谓方差的非参数估计. 若我们对生成输入的底层随机过程一无所知 (或想假装无知), 这是方差的最好 (也是唯一) 估计.

加权填充支持

直方图将输入值归入区间, 若输入值落入某区间覆盖的范围, 则递增该区间的计数器. standard storage 使用整数类型存储这些计数, 关于如何避免整数溢出参见 存储器章节. 然而, 有时直方图需要用带有权重 w 的值填充. 在这种情况下, 相应的区间计数器不是加一, 而是增加权重值 w.

注释

加权递增有多个用例. 在粒子物理学中的主要用途是将实验的模拟数据适配到真实数据. 模拟用于确定各种修正和效率, 但模拟实验几乎从来不是真实实验的完美复制品. 此外, 模拟的代价很高. 因此, 当发现模拟分布中某个变量存在偏差时, 通常不会重新运行模拟, 而是赋予权重使模拟分布与真实分布匹配.

使用 weight_storage 时, 直方图可以用加权的值元组填充. 此时每个区间存储两个实数. 第一个跟踪权重和. 第二个跟踪权重平方和, 即此情形下的方差估计. 前者用区间计数器的 value() 方法访问, 后者用 variance() 方法访问.

为什么权重平方和是方差估计, 可以从 方差的数学性质 推导. 设某区间以固定权重 w1 填充 k1 次. 权重和即为 w1 k1. 由方差性质可得 Var(w1 k1) = w1^2 Var(k1). 使用前面的推理, k1 的估计方差为 k1, 因此 Var(w1 k1) = w1^2 Var(k1) = w1^2 k1. 独立样本的方差可加. 若该区间再以权重 w2 填充 k2 次, 权重和为 w1 k1 + w2 k2, 方差为 w1^2 k1 + w2^2 k2. 这对 k1 = k2 = 1 也成立. 因此, 权重 w[i] 之和的方差为 w[i]^2 之和. 换言之, 要增量地跟踪权重和的方差, 需要跟踪权重平方和.

Python 支持

Python 是数据科学界流行的脚本语言. 因此, 库的设计必须支持单独开发的 Python 绑定. 直方图应可用作 C++ 编写的复杂模拟或数据存储系统与 Python 中数据分析/绘图之间的接口. 用户可以在 Python 中定义直方图, 让它在 C++ 一侧被填充, 然后取回以进行进一步的数据分析或绘图.

这是拒绝纯静态设计 (直方图必须在编译期完全配置) 的一个主要原因. 虽然这会生成更高效的代码, 但它无法与 Python 配合, 后者要求在运行期配置直方图而无需重新编译代码.

对 Boost.Accumulators 的支持

Boost.Histogram 可以配置为使用任意累加器作为单元格, 特别是 Boost.Accumulators 中的累加器. 样本值可以传给单元格累加器, 它可以用这些值计算归入每个单元格样本的均值、中位数、方差或其他统计量.

对 Boost.Range 的支持

直方图类是有效范围, 可以与 Boost.Range 库一起使用. 该库提供自定义适配器生成器 indexed, 类似于 Boost.Range 中对应的适配器生成器, 但带可能多维的索引.

对序列化的支持

序列化使用 Boost.Serialization 实现. 若能有一个支持浮点数据的可移植二进制档案来高效存储和读取直方图, 那就太好了, 但目前尚不可得. 库必须对其他序列化库保持开放.

与 Boost.Accumulators 的比较

Boost.Histogram 与 Boost.Accumulators 有少量重叠, 但两者的适用范围相当不同. Boost.Accumulators 中的统计累加器 density 和 weighted_density 生成一维直方图. 轴范围和区间宽度从初始值缓存样本自动确定. 它们不能用于多维数据. Boost.Histogram 专注于多维数据, 并让用户完全控制每个维度应如何分箱.

自动分箱对 Boost.Histogram 不是一个选项, 因为它不能很好地扩展到多维. 由于维数灾难, 需要收集的样本数量会大到不可行.

注释

关于如何以最优方式自动分箱, 科学界没有共识, 主要是因为对代价函数没有共识 (文献中有许多给出不同解决方案的文章). 这个问题对一维数据尚未解决, 对多维数据更甚.

建议:

  • Boost.Accumulators
    • 你有一维数据且对其一无所知, 想快速得到直方图而不操心分箱细节.
  • Boost.Histogram
    • 你有多维数据, 或怀疑以后会切换到多维数据.
    • 你想手动定制分箱, 例如使区间边缘与特殊值重合, 或处理值的特殊性质, 如定义在圆上的角度.

为什么 Boost.Histogram 不构建在 Boost.MultiArray 之上?

Boost.MultiArray 实现多维数组, 它同样把索引元组转换为用于访问数组元素的全局索引. Boost.Histogram 与 Boost.MultiArray 共享此功能, 但 Boost.Histogram 无法使用 Boost.MultiArray 作为后端. Boost.MultiArray 把数组的秩作为编译期属性, 而本库需要秩是动态的.

Boost.MultiArray 也不允许动态更改元素类型. 实现上文提到的自适应存储器需要这一点. 使用 variant 类型作为 Boost.MultiArray 的元素类型行不通, 因为它会产生这种浪费的布局:

[type-index 1][value 1][type-index 2][value 2]...

每个单元格都会存储一个类型索引. 此外, variant 总是和联合中最大类型一样大, 因此当区间计数较小时, 无法像自适应存储器那样通过使用较小的类型来节省内存. 自适应存储器对整个数组只使用一个类型索引, 并分配大小与值类型精确匹配的同类型值的同构数组, 产生如下布局:

[type-index][value 1][value 2][value 3]...

只有一个类型索引, 且为数组分配的字节数可以动态适配值类型的大小.

轴元数据与相等性检查

Boost.Histogram 库允许为直方图轴附加元数据. 元数据的预期用途是区分其他方面相同的轴, 例如区分 axis::regular(10, 0, 10, "time in seconds") 与 axis::regular(10, 0, 10, "length in meters"). 库不为元数据赋予任何含义, 但在比较轴 (和直方图) 时会检查其相等性. 单元格布局相同但轴元数据不同的直方图不相等, 也不能相加. 这里的假设是, 只有对布局完全相同的直方图才能进行有意义的相加——不仅是相同的单元格布局, 还有这些轴含义上的逻辑布局.

若不需要此检查, 有两种方式可以抑制它. 若元数据类由用户控制, 只需重写 operator== 使其始终返回 true 即可. 另一种选择是从内置轴继承自定义轴, 并重写其 operator==, 使其不检查元数据的相等性.
