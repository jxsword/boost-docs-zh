连通分量并行搜索

namespace graph { namespace distributed {
  template<typename Graph, typename ComponentMap>
  typename property_traits<ComponentMap>::value_type
  connected_components_ps(const Graph& g, ComponentMap c)
} }

connected_components_ps() 函数通过从多个源并行执行广度优先搜索来计算图的连通分量, 同时记录并最终解决碰撞.

定义位置

<boost/graph/distributed/connected_components_parallel_search.hpp>

参数

IN: const Graph& g
图类型必须是 分布图 的模型. 图类型还必须对 关联图 建模, 且为有向图.
OUT: ComponentMap c
该算法计算图中有多少个连通分量, 并为每个分量分配一个整数标签. 然后通过在分量属性映射中记录分量编号, 记录图中每个顶点属于哪个分量. ComponentMap 类型必须是 分布式属性映射. 其值类型必须是图的 vertices_size_type, 键类型必须是图的顶点描述符类型.

复杂度

O(PN^2 + VNP) 的工作量, 耗时 O(N + V), 其中 N 是映射数量, V 是本地顶点数量.

算法描述

每第 N 个节点在第 1 个超步中从其本地顶点列表的第一个顶点开始一次并行搜索 (其余节点在第 1 个超步期间保持空闲, 以减少分量编号时的冲突). 在每个超步中, 处理来自远程节点的所有新分量映射. 如果没有来自远程更新的工作, 则从本地列表中移除一个新顶点并将其加入工作队列.

分量从 component_value_allocator 对象分配, 该对象确保给定的分量编号在系统中唯一, 目前通过使用秩 (rank) 与进程数量来跨步分配.

当发现两个分量实际上是同一分量时, 会记录一次碰撞. 解决时优先采用较小的分量编号, 以保证分量编号的解析是一致的. 在搜索穷尽图中所有顶点之后, 该映射会与所有进程共享, 各进程独立地解析分量映射. 如果能找到一种巧妙的归并算法, 这一阶段很可能显著提速.
