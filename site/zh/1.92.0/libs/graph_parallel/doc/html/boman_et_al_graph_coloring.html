boman_et_al_graph_coloring 函数对无向分布图的顶点着色, 使得任何两个相邻顶点都不具有相同颜色. 给定颜色的所有顶点构成图中的一个独立集. 图着色已被用于解决各类问题, 包括编译器中的寄存器分配、优化问题以及调度问题.

用尽可能少的颜色为图着色的问题是 NP 完全的, 因此许多算法 (包括此处实现的算法) 都是启发式算法, 它们试图使颜色数量最少, 但不保证给出最优解. 本算法 [BBC05] 与 sequential_vertex_coloring 算法类似, 后者对顶点进行一次遍历, 并为当前顶点选择可用的编号最小的颜色. 因此在顺序情形下, 着色结果与颜色数量取决于顶点的排列顺序.

分布式 boman_et_al_graph_coloring 算法所产生的着色结果会随顶点的排列与分布、以及协同执行着色的并行进程数量而有所不同.

该算法返回为图着色所使用的颜色数量 num_colors.

<boost/graph/distributed/boman_et_al_graph_coloring.hpp>

参数

IN: Graph& g
图类型必须是 分布式顶点列表图 与 分布式边列表图 的模型.
UTIL/OUT: ColorMap color
保存每个顶点的颜色, 颜色为 [0, num_colors) 范围内的值. ColorMap 类型必须对 读/写属性映射 概念建模, 并且必须是 分布式属性映射.
IN: vertices_size_type s

每个超步 (superstep) 内着色的顶点数量. 在 s 个顶点被着色后, 边界顶点的颜色将被发送给其进程外的邻居. 较小的值通信更频繁, 但可能降低冲突风险; 较大的值在通信步骤之间完成更多工作, 但可能产生许多冲突.

默认: 100

IN: ChooseColor choose_color

在给定邻居颜色的情况下为顶点选择颜色的函数对象. 该函数对象会接收一个值向量 (marked) 与一个 marked_true 值, 并应返回一个 color 值, 使得 color >= marked.size() 或 marked[color] != marked_true.

默认: boost::graph::distributed::first_fit_color<color_type>(), 其中 color_type 是 ColorMap 属性映射的值类型.

IN: VertexOrdering ordering

对图中顶点提供全序的一个二元谓词函数对象. 每当发生冲突时, 相关进程之中只有一个会在下一轮为该顶点重新着色, 而此排序决定哪个顶点被视为冲突顶点 (随后由其属主进程处理该冲突). 理想情况下, 该谓词对顶点的排序应使冲突顶点均匀分布在各进程之间. 但是, 该谓词 必须 在两个处理器上以相同方式求解.

默认: 未指定

IN: VertexIndexMap index

从顶点描述符到 [0, num_vertices(g)) 范围内索引的一个映射. 它必须是 可读属性映射, 其键类型为顶点描述符, 值类型为整数类型, 通常是图的 vertices_size_type.

默认: get(vertex_index, g)

复杂度

该算法的复杂度难以刻画, 因为它很大程度上取决于算法执行期间发生的 冲突 数量. 当一个 边界顶点 (即与存储在不同处理器上的顶点相邻的顶点) 与与之相邻的另一个边界顶点 (但在另一处理器上) 被赋予相同颜色时, 就会发生冲突. 发生冲突的顶点必须被赋予新颜色, 这需要额外的工作与通信. 为冲突顶点重新分配颜色所需的工作量为 O(d), 其中 d 是该顶点的度, 并且需要 O(1) 条大小为 O(1) 的消息来解决冲突. 注意, 冲突数量会随 (1) 进程数量和 (2) 进程间边的数量而增长.
