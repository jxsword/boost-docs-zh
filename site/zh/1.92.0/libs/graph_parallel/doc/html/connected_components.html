连通分量

connected_components() 函数计算无向图的连通分量. 分布式连通分量算法使用连通分量算法的顺序版本计算本地子图的连通分量, 然后执行算法的并行阶段. 连通分量算法的并行部分大致基于 Goddard、Kumar 与 Prins 的工作. 其接口是 BGL 顺序连通分量 算法接口的超集.

在执行算法的顺序阶段之前, 每个进程标识其本地分量的根. 然后在每个分量的根顶点处构造一个由所有与该分量成员相邻的顶点组成的邻接表.

分布式连通分量算法的并行阶段由一系列超步组成. 在每个超步中, 每个根都尝试通过把其父指针赋给邻接表中的某个成员来挂接 (hook) 到该成员. 挂接仅限于在逻辑上小于当前顶点的顶点, 以防止形成环. 挂接成功的顶点从根列表中移除, 并放入另一个已完成顶点的列表. 随后所有已完成顶点执行指针跳转 (pointer jumping) 步骤, 直到每个已完成顶点的父指针都指向某个分量的根. 通过加入 Johnson 与 Metaxas 提出的环归约 (Cycle Reduction, CR) 规则, 该指针跳转步骤还可以进一步优化, 不过目前的性能评估表明这对算法整体性能的影响可以忽略. 这些 CR 规则把指针跳转步骤的次数从 O(n) 降到 O(log n). 在该指针跳转步骤之后, 本阶段中已挂接的根会把其邻接表传送给新的父顶点. 剩余的根接收这些边, 并对其邻接表执行剪枝步骤, 以移除现在已成为其分量成员的顶点. 当没有任何根成功挂接时, 算法的并行阶段即告完成. 并行阶段完成后, 对所有顶点执行最后一次指针跳转步骤, 把初始本地子图分量的叶顶点的父指针赋为其最终父顶点 (此时已确定).

分布式连通分量算法最大的性能瓶颈是糟糕的顶点分布对算法的影响. 对于只有一个大分量的稀疏图, 许多根可能挂接到同一分量, 导致拥有该分量的进程出现严重的负载不均衡. 已经实现了多种修改挂接策略以避免这种行为的方法, 但迄今为止尚无一成功.

定义位置

<boost/graph/connected_components.hpp>

参数

IN: Graph& g
图类型必须是 分布图 的模型.
OUT: ComponentMap c
该算法计算图中有多少个连通分量, 并为每个分量分配一个整数标签. 然后通过在分量属性映射中记录分量编号, 记录图中每个顶点属于哪个分量. ComponentMap 类型必须是 分布式属性映射. 其值类型必须是图的 vertices_size_type, 键类型必须是图的顶点描述符类型. 如果不希望计算分量编号, 可传入 dummy_property_map 作为分量映射, 此时父信息将通过父映射提供.
UTIL: ParentMap p
可向算法提供一个父映射; 若未提供, 父映射将被自动构造. ParentMap 类型必须是 分布式属性映射. 其值类型与键类型必须是图的顶点描述符类型.
OUT: property_traits<ComponentMap>::value_type
找到的分量数量将作为分量映射的值类型返回.

复杂度

算法的本地阶段为 O(V + E). 算法的并行阶段最多需要 O(d) 个超步, 其中 d 是初始根的数量. d 至多为 O(V), 但随着 E 的增加会显著变小. 每个超步内的指针跳转阶段在每个已完成的根上最多需要 O(c) 步, 其中 c 是最长环的长度. 应用 CR 规则可将其降至 O(log c).
