non_distributed_betweenness_centrality() 函数计算图中顶点与边的介数中心性. 这个名称有些令人困惑: 图 g 并不是分布式图, 但该算法确实以并行方式运行. 该算法变体并非并行化介数中心性所需的各个最短路径计算, 而是并行执行最短路径计算: pg 中的每个进程使用 BGL 的 Dijkstra 最短路径 实现, 从不同的源顶点集合计算最短路径. 每个进程累计到其本地中心性映射中, 一旦所有最短路径计算完成, 就执行一次归并以组合来自所有进程的中心性.

参与介数中心性计算的各进程在其上进行通信的进程组. 进程组类型必须对 进程组 概念建模.
IN: const Graph& g
图类型必须是 关联图 概念的模型.
IN: CentralityMap centrality

可向算法提供一个中心性映射; 若未提供, 则将使用 dummy_property_map, 且不会记录任何顶点中心性信息. CentralityMap 的键类型必须是图的顶点描述符类型.

默认: 一个 dummy_property_map.

IN: EdgeCentralityMap edge_centrality_map

可向算法提供一个边中心性映射; 若未提供, 则将使用 dummy_property_map, 且不会记录任何边中心性信息. EdgeCentralityMap 的键类型必须是图的顶点描述符类型.

默认: 一个 iterator_property_map, 其基于

距离映射记录算法最短路径部分中到达各顶点的距离. 其键类型必须是图的顶点描述符类型.

依赖映射记录算法中心性计算部分中每个顶点的依赖. 其键类型必须是图的顶点描述符类型.

默认: 一个 iterator_property_map, 其基于
std::vector, 其元素类型为 CentralityMap 的值类型.
IN: PathCountMap path_count

路径计数映射记录算法中心性计算部分中每个顶点所位于的最短路径的数量. 其键类型必须是图的顶点描述符类型.

默认: 一个 iterator_property_map, 其基于
std::vector, 元素为图的度数量类型.
IN: VertexIndexMap vertex_index

一个 可读属性映射 模型, 其键类型为图 g 的顶点描述符类型, 值类型为整数类型. 该属性映射应把顶点映射到其 (本地) 索引, 索引范围为 [0, num_vertices(g)).

默认: get(vertex_index, g)

IN: WeightMap weight_map
一个 可读属性映射 模型, 其键类型为图 g 的边描述符类型. 若未提供, 介数中心性的计算将不带权重.
IN: Buffer sources

一个 缓冲区 模型, 包含算法的起始顶点. 若 sources 为空, 则将使用 g 中的所有顶点执行完整的介数中心性计算. 缓冲区的值类型必须是图的顶点描述符类型.

默认: 一个 int 类型的空 boost::queue.

复杂度

每个最短路径计算的复杂度为 O(V log V), 且每个计算都可以并行运行 (pg 中每进程一个). 在最短路径阶段结束时计算总中心性的归并阶段为 O(V log V).

算法描述

该算法使用非分布式 (顺序) 图以及非分布式属性映射. 每个进程包含顺序图 g 的一个独立副本. 为了使算法正确, 这些 g 副本必须完全相同. sources 缓冲区包含在用图的顶点子集近似介数中心性时, 用作单源最短路径计算源点的顶点. 如果 sources 为空, 则使用所有顶点执行完整的介数中心性计算.

在算法的顺序阶段, 每个进程使用 BGL 介数中心性实现中的 Brandes 最短路径方法, 从图的顶点子集计算最短路径. 在算法的并行阶段, 执行一次归并, 把各进程为图中所有顶点计算出的值求和.

根据是否传入 WeightMap, 计算带权或不带权的介数中心性.
