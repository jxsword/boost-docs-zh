分布式队列适配器

template<typename ProcessGroup, typename Buffer>
class distributed_queue
{
public:
  typedef ProcessGroup                     process_group_type;
  typedef Buffer                           buffer_type;
  typedef typename buffer_type::value_type value_type;
  typedef typename buffer_type::size_type  size_type;

  explicit
  distributed_queue(const ProcessGroup& process_group = ProcessGroup(),
                    const Buffer& buffer = Buffer(),
                    bool polling = false);

  distributed_queue(const ProcessGroup& process_group, bool polling);

  void push(const value_type& x);
  void pop();
  value_type& top();
  const value_type& top() const;
  bool empty() const;
  size_type size() const;
};

template<typename ProcessGroup, typename Buffer>
inline distributed_queue<ProcessGroup, Buffer>
make_distributed_queue(const ProcessGroup& process_group, const Buffer& buffer,
                       bool polling = false);

类模板 distributed_queue 在进程组之上实现一个分布式队列. 分布式队列是对既有 (本地) 队列的适配器, 后者必须对 缓冲区 概念建模. 每个进程存储本地队列的一个独立副本, 并通过 pop 与 top 成员从中取出或移除元素.

本地队列的值类型必须对 全局描述符 概念建模. 分布式队列的 push 操作 (经由消息) 把值传递给其属主处理器. 因此, 特定本地队列中的元素保证以拥有该本地队列的进程为属主.

分布式队列的同步发生在 empty 与 size 函数中, 只有当整个分布式队列为空时, 它们才会返回 "空" 值 (分别为 true 或 0). 如果本地队列为空但分布式队列非空, 该操作将阻塞, 直到任一条件改变. 当非空队列的 size 函数返回时, 它返回本地队列的大小. 选择这些语义是为了使通过以下惯用法处理队列中元素的顺序代码能够通过引入分布式队列而并行化:

distributed_queue<...> Q;
Q.push(x);
while (!Q.empty()) {
  // do something, that may push a value onto Q
}

在并行版本中, 初始的 push 操作将把值 x 放入其属主的队列. 所有进程将在对 empty 的调用处同步, 且只有拥有 x 的进程被允许执行循环 (Q.empty() 返回 false). 该迭代可能依次把值推入其他远程队列, 因此当该进程完成循环体的执行且所有进程在 empty 中再次同步时, 可能有更多进程拥有非空的本地队列可执行. 一旦所有本地队列为空, Q.empty() 对所有进程返回 false.

分布式队列可以在两个不同时刻接收消息: 在同步期间以及轮询 empty 时. 消息总是在同步期间被接收, 以确保能确定准确的本地队列大小. 而 empty 是否应轮询消息则作为构造函数的一个选项指定. 当队列元素的处理顺序不重要时, 可能希望轮询, 因为它允许更少的同步步骤与更少的通信开销. 然而, 当需要更严格的顺序保证时, 轮询可能在语义上不正确. 通过禁用轮询, 可以确保使用上述惯用法的并行执行不会在较早 "层" 的元素之前处理较晚 "层" 的元素.

分布式队列几乎对 缓冲区 概念建模. 但 push 例程不一定会使 size() 的结果加一 (尽管全局队列的大小确实会加一).

成员函数

explicit
distributed_queue(const ProcessGroup& process_group = ProcessGroup(),
                  const Buffer& buffer = Buffer(),
                  bool polling = false);

构建一个新的分布式队列, 它通过给定的 process_group 通信, 其本地队列经由 buffer 初始化, 且可以轮询消息, 也可以不轮询.

distributed_queue(const ProcessGroup& process_group, bool polling);

构建一个新的分布式队列, 它通过给定的 process_group 通信, 其本地队列默认初始化, 且可以轮询消息, 也可以不轮询.

void push(const value_type& x);

把一个元素推入分布式队列.

该元素将被发送到其属主进程, 以加入该进程的本地队列. 如果该队列启用了轮询且属主进程是当前进程, 该值将被立即推入本地队列.

复杂度: 将传输 O(1) 条大小为 O(sizeof(value_type)) 的消息.

void pop();

从本地队列弹出一个元素. 队列不得为 empty().

value_type& top();
const value_type& top();

返回本地队列的顶部元素. 队列不得为 empty().

bool empty() const;

判断队列是否为空.

当本地队列非空时, 返回 true. 如果本地队列为空, 则与进程组中的所有其他进程同步, 直到 (1) 本地队列非空 (返回 true) 或 (2) 整个分布式队列为空 (返回 false).

size_type size() const;

确定本地队列的大小.

此例程的行为等价于 empty 的行为, 区别在于: 当 empty 返回 true 时, 此函数返回本地队列的大小; 当 empty 返回 false 时, 此函数返回零.
