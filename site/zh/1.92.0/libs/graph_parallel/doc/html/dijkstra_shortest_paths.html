dijkstra_shortest_paths() 函数求解带权无向或有向分布图上的单源最短路径问题. 分布式 Dijkstra 算法有两种实现, 它们提供不同的性能权衡. 两者都可以通过 dijkstra_shortest_paths() 函数访问 (以与顺序 BGL 程序保持兼容). 分布式 Dijkstra 算法与其顺序版本非常相似. 此处仅强调差异; 更多细节请参阅 顺序 Dijkstra 实现. 对大多数情况而言, 性能最好的实现是 Delta-Stepping 算法; 不过也可以采用更保守的 Crauser 等人的算法 或简单的 Eager Dijkstra 算法.

定义位置

<boost/graph/dijkstra_shortest_paths.hpp>

参数

顺序 Dijkstra 实现 的所有参数都受支持, 且含义基本相同. 分布式 Dijkstra 实现引入了一个新参数, 用于选择 Eager Dijkstra 算法 并控制其执行的工作量. 此处仅记录差异与新参数.

IN: Graph& g
图类型必须是 分布图 的模型.
IN: vertex_descriptor s
起始顶点在每个进程中必须相同.
OUT: predecessor_map(PredecessorMap p_map)

前驱映射必须是 分布式属性映射 或 dummy_property_map, 尽管只有映射的本地部分会被写入.

默认: dummy_property_map

UTIL/OUT: distance_map(DistanceMap d_map)
距离映射必须是 分布式属性映射 或 dummy_property_map. 它将被赋予 vertex_distance 角色.
IN: visitor(DijkstraVisitor vis)
访问器必须是分布式 Dijkstra 访问器. 顺序与分布式 Dijkstra 访问器之间的细微差别在 访问器事件点 一节中讨论.
UTIL/OUT: color_map(ColorMap color)
颜色映射必须是 分布式属性映射, 其进程组与图 g 相同, 且其颜色必须单调加深 (white -> gray -> black). 默认值是由 default_color_type 的 std::vector 创建的分布式 iterator_property_map.

IN: lookahead(distance_type look)

当提供该参数时, 实现将使用具有给定前瞻 (lookahead) 值的 Eager Dijkstra 算法. 前瞻允许分布式 Dijkstra 算法投机性地处理其到源点的最短距离可能尚未确定的顶点. 当所得距离即为最短距离时, 并行性得到提升, 算法可能更早终止. 然而, 若该距离不是最短距离, 该顶点稍后需要重新处理, 从而产生更多工作量.

类型 distance_type 是 DistanceMap 属性映射的值类型. 它是一个非负值, 指定 Dijkstra 算法可以超前处理多远.

默认: 无值 (不使用前瞻; 使用 Crauser 等人的算法).

访问器事件点

Dijkstra 访问器 概念定义了 7 个事件点, 它们将由 顺序 Dijkstra 实现 触发. 分布式 Dijkstra 保留这些事件点, 但所触发事件的序列以及每个事件发生的进程会随图的分布、前瞻与边权重而变化.

initialize_vertex(s, g)
每个进程都会为其每个本地顶点调用此事件.
discover_vertex(u, g)
每当一个进程发现新顶点 u 时都会调用此事件. 由于分布式属性映射中的信息不完整, 同一顶点 u 可能多次触发此事件.
examine_vertex(u, g)
此事件由拥有顶点 u 的进程调用. 当图包含负权边或使用前瞻时, 同一顶点可能多次触发此事件.
examine_edge(e, g)
此事件由拥有 e 的源顶点的进程调用. 与 examine_vertex 一样, 同一条边可能多次触发此事件.
edge_relaxed(e, g)
与 examine_edge 类似, 此事件由拥有源顶点的进程调用, 并且可能多次调用 (即使没有前瞻或负权边).
edge_not_relaxed(e, g)
与 edge_relaxed 类似. 顺序 Dijkstra 会触发的某些 edge_not_relaxed 事件在分布式 Dijkstra 算法中会变为 edge_relaxed 事件.
finish_vertex(e, g)
参见 examine_vertex 的文档. 注意, 如果允许前瞻或图中存在负权边, 一个 "已完成" 的顶点未必真正完成.

Crauser、Mehlhorn、Meyer 与 Sanders 提出的 Dijkstra 算法表述 [CMMS98a] 通过增加给定超步中可处理的顶点数量, 提高了并行 Dijkstra 算法的可扩展性. 该算法能很好地适应各种图类型, 且使用简单, 无需额外的用户输入即可获得合理的性能. 其缺点在于实现需要管理三个优先队列, 这会在每个节点上产生大量工作.

分布式 dijkstra_shortest_paths() 默认使用该算法.

定义位置

<boost/graph/distributed/crauser_et_al_shortest_paths.hpp>

复杂度

该算法在 d + 1 个 BSP 超步中执行 O(V log V) 的工作量, 其中 d 至多为 O(V), 但通常要小得多. 对于边权重取自 [0, 1) 的有向 Erdos-Renyi 图, 超步的期望数量 d 以高概率为 O(n^(1/3)).

在每个超步中, 并行 Dijkstra 算法通常只处理距离等于全局最小距离的节点, 因为这些距离可保证是正确的. 该算法的这一变体允许算法处理其距离与最小距离相差某个常数以内的所有顶点. 该值称为 "前瞻" (lookahead) 值, 由用户作为函数的第五个参数提供. 较小的前瞻值可能导致并行化机会有限, 而较大的值会暴露更多并行性, 但可能引入 (非无限的) 循环并导致额外工作. 前瞻参数的最优值取决于输入图; 参见 [CMMS98b] 与 [MS98].

当向 dijkstra_shortest_paths() 提供前瞻值时, 将使用该算法.

定义位置

<boost/graph/distributed/eager_dijkstra_shortest_paths.hpp>

复杂度

该算法在 d + 1 个 BSP 超步中执行 O(V log V) 的工作量, 其中 d 至多为 O(V), 但取决于前瞻值可能更小. 当提供较大的前瞻值时, 算法可能执行更多工作, 因为顶点会被重新处理.

delta-stepping 算法 [MS98] 是并行 Dijkstra 算法的另一个变体. 与 Eager Dijkstra 算法一样, 它使用一个前瞻 (delta) 值, 允许处理器在尚未保证找到最小距离之前处理顶点, 从而实现比保守策略更多的并行性. delta-stepping 还引入了一种多级桶数据结构, 与其他 Dijkstra 变体采用的优先队列相比, 它提供了更宽松的排序约束, 降低了向中央数据结构插入、松弛与删除的复杂度. delta-stepping 算法是各 Dijkstra 变体中性能最好的.

前瞻值 delta 决定 delta-stepping 队列中每个 "桶" 的大小: 第 i 个桶包含试探距离位于 delta``*i 与 ``delta``*(i+1). ``delta 必须为正值. 若省略, delta 将被设为最大边权除以最大度.
