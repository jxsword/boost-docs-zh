并行最短路径

为了演示 Parallel Boost Graph Library 的使用, 我们同时使用顺序与并行 BGL 来求下图简单图形中从顶点 A 到其他每个顶点的最短路径:

使用顺序 BGL 时, 计算最短路径的程序分为三个阶段. 熟悉 BGL 的读者可以直接跳到 对图进行分布 一节.

  • 定义图类型
  • 构造图
  • 调用 Dijkstra 算法

定义图类型

对于此问题, 我们使用图的邻接表表示, 并采用 BGL 的 adjacency_list``_ 类 模板. 它 将 是 一个 有向 图 (``directedS 参数), 其顶点存储于 std::vector (vecS 参数), 每个顶点的出边存储于 std::list (listS 参数). 我们为每条边附加一个整数权重.

typedef adjacency_list<listS, vecS, directedS,
                       no_property,                 // Vertex properties
                       property<edge_weight_t, int> // Edge properties
                       > graph_t;
typedef graph_traits < graph_t >::vertex_descriptor vertex_descriptor;
typedef graph_traits < graph_t >::edge_descriptor edge_descriptor;

构造图

为了构建该图, 我们声明一个包含节点名称的枚举 (供我们自己使用), 并创建两个数组: 第一个数组 edge_array 包含每条边的源点与目标点, 第二个数组 weights 包含每条边的整数权重. 我们通过指针 (此处用作迭代器) 把数组的内容传给图构造函数以构建图:

typedef std::pair<int, int> Edge;
const int num_nodes = 5;
enum nodes { A, B, C, D, E };
char name[] = "ABCDE";
Edge edge_array[] = { Edge(A, C), Edge(B, B), Edge(B, D), Edge(B, E),
  Edge(C, B), Edge(C, D), Edge(D, E), Edge(E, A), Edge(E, B)
};
int weights[] = { 1, 2, 1, 2, 7, 3, 1, 1, 1 };
int num_arcs = sizeof(edge_array) / sizeof(Edge);

graph_t g(edge_array, edge_array + num_arcs, weights, num_nodes);

调用 Dijkstra 算法

要调用 Dijkstra 算法, 我们首先需要决定希望如何接收算法的结果, 即到每个顶点的距离以及每个顶点的前驱 (以便重建最短路径本身). 在本例中, 我们将创建两个向量: p 用于前驱, d 用于距离.

接下来, 我们用 s 确定起始顶点, 即在 vertex 操作之上, 使用 adjacency_list``_ 并 调用 ``dijkstra_shortest_paths``_ 以 图 ``g, 即起始顶点 s, 并传入两个 属性 映射``_ 其 指示 算法 把 前驱 存入 ``p 向量, 并把距离存入 d 向量. 该算法会自动使用存储在图中的边权重, 不过这一能力可以被覆盖.

// Keeps track of the predecessor of each vertex
std::vector<vertex_descriptor> p(num_vertices(g));
// Keeps track of the distance to each vertex
std::vector<int> d(num_vertices(g));

vertex_descriptor s = vertex(A, g);
dijkstra_shortest_paths
  (g, s,
   predecessor_map(
     make_iterator_property_map(p.begin(), get(vertex_index, g))).
   distance_map(
     make_iterator_property_map(d.begin(), get(vertex_index, g)))
   );

对图进行分布

前述计算完全是顺序的, 图存储在单一地址空间内. 要把图分布到多个不共享地址空间的处理器上, 我们需要表示处理器及它们之间的通信, 并修改图类型.

处理器及其交互通过一个 进程组 来抽象. 在本例中, 我们将使用 MPI 进行通信, 进程间消息被立即发送:

typedef mpi::process_group<mpi::immediateS> process_group_type;

接下来, 我们指示 adjacency_list 模板把图的顶点分布到我们的进程组上, 并把本地顶点存储在 std::vector 中:

typedef adjacency_list<listS,
                       distributedS<process_group_type, vecS>,
                       directedS,
                       no_property,                 // Vertex properties
                       property<edge_weight_t, int> // Edge properties
                       > graph_t;
typedef graph_traits < graph_t >::vertex_descriptor vertex_descriptor;
typedef graph_traits < graph_t >::edge_descriptor edge_descriptor;

注意, 与顺序 BGL 的唯一区别是使用了 distributedS 选择器, 它标识一个分布式图. 图的顶点将分布在各个处理器上, 拥有某顶点的处理器同时存储从该顶点出发的边以及与该顶点或其边相关联的任何属性. 使用三个处理器和默认的分块分布时, 图将按如下方式分布:

处理器 0 (红色) 拥有顶点 A 和 B, 包括从这些顶点出发的所有边; 处理器 1 (绿色) 拥有顶点 C 和 D (及其边); 处理器 2 (蓝色) 拥有顶点 E. 构造该图所用的语法与顺序图相同, 如 构造图 一节所示.

对 dijkstra_shortest_paths 的调用在语法上与顺序调用等价, 但其使用的机制截然不同. 传给 dijkstra_shortest_paths 的属性映射实际上是 分布式 属性映射, 它们存储本地边或顶点的属性, 并在需要时通过隐式通信访问远程边或顶点的属性. Dijkstra 算法的表述也略有不同, 因为每个处理器只能尝试松弛从本地顶点出发的边: 当发现到某个顶点的更短路径时, 发送给拥有该顶点的处理器的消息会指明该顶点可能需要重新处理.
