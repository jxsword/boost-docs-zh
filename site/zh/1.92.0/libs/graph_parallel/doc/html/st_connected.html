st_connected() 函数判定图 g 中是否存在从 s 到 t 的路径. 如果路径存在, 该函数返回 true, 否则返回 false.

该算法目前是 层同步 的, 即搜索树中给定层的所有顶点都会在处理树中后续任何层的顶点之前被处理 (可能并行处理). 这对算法的正确性并非必要, 而只是一个实现细节. 可以使用触发器把该算法改写为完全异步的, 从而消除层同步行为.

定义位置

<boost/graph/distributed/st_connected.hpp>

参数

IN: const DistributedGraph& g
图类型必须是 分布图 的模型. 图类型还必须对 关联图 建模.

IN: vertex_descriptor s

IN: vertex_descriptor t

UTIL/OUT: color_map(ColorMap color)
颜色映射必须是 分布式属性映射, 其进程组与图 g 相同, 且其颜色必须单调加深 (white -> gray/green -> black). 默认值是一个分布式 two_bit_color_map.
IN: OwnerMap owner
属主映射必须按 GlobalDescriptor 概念的描述, 把顶点映射到拥有它们的进程.
OUT: bool
如果找到从 s 到 t 的路径, 该算法返回 true, 否则返回 false.

复杂度

该算法在 d/2 + 1 个 BSP 超步中执行 O(V + E) 的工作量, 其中 d 是从 s 到 t 的最短距离. 在所有超步中, 共传输 O(E) 条恒定大小的消息.

算法描述

该算法由分别从 s 与 t 出发的两个同时进行的广度优先遍历组成. 该算法为两次遍历使用单个队列: 从 s 出发的遍历在颜色映射中以 gray 条目标记, 从 t 出发的遍历以 green 条目标记. 遍历方法与广度优先搜索类似, 但不调用任何访问器事件点. 当任一进程检测到两次遍历发生碰撞 (通过尝试把一个 gray 顶点设为 green, 或反之), 它会通知所有进程在下一个超步终止, 并且所有进程返回 true. 如果所有进程上的队列都为空且未检测到碰撞, 则所有进程终止并返回 false.
