引言

分布式邻接表以邻接表表示实现了一种图数据结构. 其接口与行为大致等价于 Boost Graph Library 的 adjacency_list 类模板. 然而, 分布式邻接表把图的顶点划分到多个进程上 (这些进程无需共享地址空间). 从任一顶点出发的边同样存储在存储该顶点的进程上, 但无向图例外, 此时源点或目标点之一可存储该边.

template<typename OutEdgeListS, typename ProcessGroup, typename VertexListS,
         typename DirectedS, typename VertexProperty, typename EdgeProperty,
         typename GraphProperty, typename EdgeListS>
class adjacency_list<OutEdgeListS,
                     distributedS<ProcessGroup, VertexListS>,
                     DirectedS, VertexProperty,
                     EdgeProperty, GraphProperty, EdgeListS>;

定义分布式邻接表

要创建分布式邻接表, 首先按照这些 指南 确定图在单一地址空间中的表示. 然后, 把顶点列表选择器 (VertexListS) 替换为 distributedS 的实例化, 其中包括:

  • 选择一个 进程组 类型, 用于表示将要存储该分布式图的各个协作进程, 例如 MPI 进程组.
  • 一个选择器, 指示每个进程中的顶点列表将如何存储. 目前只有 vecS 与 listS 选择器得到良好支持.

下面的 typedef 定义了一个包含有向边的分布式邻接表. 图的顶点将分布在多个进程上, 并使用 MPI 进程组进行通信. 在每个进程中, 顶点与出边将存储在 STL 向量中. 图的顶点或边未附加任何属性.

using namespace boost;
typedef adjacency_list<vecS,
                       distributedS<graph::distributed::mpi_process_group, vecS>,
                       directedS>
  Graph;

分布式顶点与边属性

分布式图的顶点与边属性与其在非分布式图中的对应物类似. 但对于分布式图, 顶点与边属性只存储在拥有该顶点或边的进程中.

把属性附加到分布式图上最直接的方式, 是创建一个将附加到图的每个顶点与边上的结构. 例如, 如果我们希望对一个简单的美国州际公路系统地图建模, 可以声明图的顶点是城市、边是公路, 然后定义我们为每个城市和公路所维护的信息:

struct City {
  City() { }
  City(const std::string& name, const std::string& mayor = "Unknown", int population = 0)
    : name(name), mayor(mayor), population(population) { }

  std::string name;
  std::string mayor;
  int population;

  // Serialization support is required!
  template<typename Archiver>
  void serialize(Archiver& ar, const unsigned int /*version*/) {
    ar & name & mayor & population;
  }
};

struct Highway {
  Highway() { }
  Highway(const std::string& name, int lanes, int miles_per_hour, int length)
    : name(name), lanes(lanes), miles_per_hour(miles_per_hour), length(length) { }

  std::string name;
  int lanes;
  int miles_per_hour;
  int length;

  // Serialization support is required!
  template<typename Archiver>
  void serialize(Archiver& ar, const unsigned int /*version*/) {
    ar & name & lanes & miles_per_hour & length;
  }
};

为了创建公路地图的分布式图, 我们把 City 与 Highway 分别作为第四与第五个参数提供给 adjacency_list:

typedef adjacency_list<vecS,
                       distributedS<graph::distributed::mpi_process_group, vecS>,
                       directedS,
                       City, Highway>
  RoadMap;

内部属性的属性映射借助 分布式属性映射 在分布式图上保持其原有行为, 后者自动完成进程间的通信, 使得 put 与 get 操作可以施加于非本地顶点与边. 然而, 对于把顶点存储在向量中的分布式邻接表 (VertexListS 为 vecS), 自动的 vertex_index 属性映射把 put 与 get 操作的定义域限制为执行该操作的进程本地的顶点. 例如, 我们可以如下创建一个访问每条公路长度的属性映射:

RoadMap map; // distributed graph instance

typedef property_map<RoadMap, int Highway::*>::type
  road_length = get(&Highway::length, map);

此时, 基于边描述符 e, 可以用表达式 get(road_length, e) 访问任意一条路的长度, 而无论边 e 存储在哪个进程中.

命名顶点

图的顶点通常与应用领域中的命名实体相对应. 在上一节的公路地图示例中, 图中的顶点表示城市. 分布式邻接表支持命名顶点, 它提供了从应用领域中顶点名称 (例如城市名, 如 "Bloomington") 到分布式图内实际存储的顶点描述符 (例如处理器 1 上的第三个顶点) 的隐式映射. 通过启用对命名顶点的支持, 在操作图时可以按名称引用顶点. 例如, 可以添加一条从 Indianapolis 到 Chicago 的公路:

add_edge("Indianapolis", "Chicago", Highway("I-65", 4, 65, 151), map);

分布式邻接表会查找与名称 "Indianapolis" 和 "Chicago" 相关联的顶点, 然后在这两个顶点之间添加一条表示 I-65 的边. 这些顶点可以存储在任何处理器上, 本地或远程均可.

要启用命名顶点, 请为附加到图中顶点上的结构特化 internal_vertex_name 属性. internal_vertex_name 包含唯一一个成员 type, 它是函数对象的类型, 该函数对象接受一个顶点属性并返回存储在该顶点属性中的名称. 在我们的公路地图中, name 字段包含每个城市的名称, 因此我们使用 member 函数对象 (来自 Boost.MultiIndex 库) 来提取名称, 例如:

namespace boost { namespace graph {

template<>
struct internal_vertex_name<City>
{
  typedef multi_index::member<City, std::string, &City::name> type;
};

} }

就这样! 现在在与分布式邻接表交互时, 可以按名称引用顶点.

当使用一个不存在的顶点名称时会发生什么? 例如, 在上面的 add_edge 调用中, 如果名为 "Indianapolis" 的顶点尚未添加到图中, 会发生什么? 默认情况下, 如果命名顶点尚不存在, 分布式邻接表将抛出异常. 不过, 可以通过指定一个仅凭顶点名称构造顶点属性实例 (例如 City) 的函数对象来自定义这一行为. 该自定义通过 internal_vertex_constructor 特征实现. 例如, 使用 vertex_from_name 模板 (由 Parallel BGL 提供), 我们可以声明 City 可以通过其第二个构造函数直接从城市名称构造:

namespace boost { namespace graph {

template<>
struct internal_vertex_constructor<City>
{
  typedef vertex_from_name<City> type;
};

} }

现在, 可以自由地按顶点名称添加边, 无需担心顶点的显式添加. mayor 与 population 字段将具有默认值, 但图结构将是正确的.

构建分布式图

在确定了图类型的布局 (包括具体的数据结构与属性) 之后, 就该通过添加适当的顶点与边来构造图实例了. 分布式图的构造可能比普通非分布式图数据结构的构造稍微复杂, 因为必须同时考虑顶点与边的分布以及多个并发执行的进程. 构造分布式图有三种主要方式:

1. 序列构造器: 如果你的数据可以容易地由一对产生 (源点, 目标点) 对的迭代器生成, 就可以使用序列构造器并行地构建分布式图. 在创建基准测试时通常首选此方法, 因为 sorted_erdos_renyi_iterator 之类的随机图生成器会创建适当的输入序列. 注意, 必须在所有进程上提供相同的输入迭代器序列. 该方法的优点是: 顺序建图代码与并行建图代码完全相同. 以下是以这种方式构造随机图的示例:

typedef boost::sorted_erdos_renyi_iterator<boost::minstd_rand, Graph> ERIter;
boost::minstd_rand gen;
unsigned long n = 1000000; // 1M vertices
Graph g(ERIter(gen, n, 0.00005), ERIter(), n);

2. 按顶点编号添加边: 如果你能够把顶点映射到随机 [0, n) 中的值, 其中 n 是分布式图中顶点的数量. 当你的算法不容易改造为输入迭代器, 或者无法复制输入序列时, 请使用此方法而非序列构造器. 例如, 你可能正在从输入文件读取图:

Graph g(n); // initialize with the total number of vertices, n
if (process_id(g.process_group()) == 0) {
  // Only process 0 loads the graph, which is distributed automatically
  int source, target;
  for (std::cin >> source >> target)
    add_edge(vertex(source, g), vertex(target, g), g);
}

// All processes synchronize at this point, then the graph is complete
synchronize(g.process_group());

3. 按名称添加边: 如果你使用命名顶点, 只需以源顶点与目标顶点的名称调用 add_edge 即可构造图. 注意确保每条边只由一个进程添加 (是哪个进程无关紧要), 否则最终会得到多重边. 例如, 在下面的程序中, 我们从进程 0 的标准输入读取边, 并按名称添加这些边. 顶点与边将被自动创建并分布.

Graph g;
if (process_id(g.process_group()) == 0) {
  // Only process 0 loads the graph, which is distributed automatically
  std:string source, target;
  for(std::cin >> source >> target)
    add_edge(source, target, g);
}

// All processes synchronize at this point, then the graph is complete
synchronize(g.process_group());

图概念

分布式邻接表对 图 概念建模, 尤其是对 分布图 概念建模. 它还对 关联图 与 邻接图 概念建模, 但把操作的输入定义域限制为仅本地顶点. 例如, 只有当某个顶点存储在本进程中时, 进程才能访问其出边. 无向与双向分布式邻接表对 双向图 概念建模, 具有相同的定义域限制. 分布式邻接表还对 可变图 概念 (有定义域限制; 参见 参考 一节)、属性图 概念与 可变属性图 概念建模.

与非分布式的对应物不同, 分布式邻接表 不 对 顶点列表图 或 边列表图 概念建模, 因为无法在分布式图中枚举所有顶点或边. 相反, 它对较弱的 分布式顶点列表图 与 分布式边列表图 概念建模, 后者允许访问每个处理器上的本地边与顶点. 注意, 如果分布式图所在进程组中的所有进程都对其各自的顶点或边列表进行迭代, 则所有顶点与边都将被覆盖一次.

构造一个具有 n 个顶点、且边由范围 [first, last) 给出的边列表指定的分布式邻接表. EdgeIterator 必须是 输入迭代器 的模型. EdgeIterator 的值类型必须是 std::pair, 其中 pair 中的类型为整数类型. 这些整数对应于顶点, 并且都必须落在 [0, n) 范围内. 当提供 ep_iter 时, 它指向一个边属性列表 [ep_iter, ep_iter + m), 其中包含每条边的属性.

此构造函数是集合操作, 必须由每个进程以相同的参数列表并发执行. 最重要的是, 提供给每个进程中构造函数的边列表应当等价. 顶点将按照 distribution 划分到各进程, 边放置在拥有该边源点的进程上. 注意, 这一行为允许顺序建图代码自动并行化, 而与底层分布无关.

结构修改

unspecified add_edge(vertex_descriptor u, vertex_descriptor v, adjacency_list& g);
unspecified add_edge(vertex_name_type u, vertex_descriptor v, adjacency_list& g);

unspecified add_edge(vertex_name_type u, vertex_name_type v, adjacency_list& g);

把边 (u,v) 添加到图中. 返回类型本身未指定, 但该类型可拷贝构造并可隐式转换为 std::pair<edge_descriptor,bool>. 边描述符描述所添加 (或找到) 的边. 对于不允许平行边的图, 如果该边已在图中, 则不会添加重复边, 且 bool 标志将为 false. 此外, 如果 u 和 v 是同一顶点的描述符 (构成自环) 且图是无向的, 则不会添加该边, 且标志将为 false. 当标志为 false 时, 返回的边描述符指向已存在的边.

参数 u 与 v 既可以是顶点描述符, 也可以 (在图使用命名顶点时) 是顶点的名称. 如果具有给定名称的顶点不存在, 将调用内部顶点构造器来创建新的顶点属性, 并把具有该属性的顶点隐式添加到图中. 默认的内部顶点构造器会抛出异常.

从图中移除边 e. 如果有向选择器为 bidirectionalS 或 undirectedS, 则图的源顶点或目标顶点之一必须是本地的. 如果有向选择器为 directedS, 则源顶点必须是本地的.

void remove_edge(out_edge_iterator iter, adjacency_list& g);

这与 remove_edge(*iter, g) 具有相同的效果. 对于有向 (但非双向) 图, 这会比 remove_edge(*iter, g) 更高效.

template <class Predicate >
void remove_out_edge_if(vertex_descriptor u, Predicate predicate,
                        adjacency_list& g);

从图中移除顶点 u 的所有满足谓词的出边. 即, 如果谓词作用于某边描述符时返回 true, 则该边被移除. 顶点 u 必须是本地的.

对描述符与迭代器稳定性的影响与对每条被移除的边调用 remove_edge() 相同.

template <class Predicate >
void remove_in_edge_if(vertex_descriptor v, Predicate predicate,
                       adjacency_list& g);

从图中移除顶点 v 的所有满足谓词的入边. 即, 如果谓词作用于某边描述符时返回 true, 则该边被移除. 顶点 v 必须是本地的.

对描述符与迭代器稳定性的影响与对每条被移除的边调用 remove_edge() 相同.

此操作可用于无向与双向 adjacency_list 图, 但不适用于有向图.

template <class Predicate>
void remove_edge_if(Predicate predicate, adjacency_list& g);

从图中移除所有满足谓词的边. 即, 如果谓词作用于某边描述符时返回 true, 则该边被移除.

对描述符与迭代器稳定性的影响与对每条被移除的边调用 remove_edge() 相同.

vertex_descriptor add_vertex(adjacency_list& g);

向图中添加一个顶点并返回新顶点的顶点描述符. 该顶点将存储在本地进程中. 使用命名顶点时此函数不可用.

unspecified add_vertex(const VertexProperties& p, adjacency_list& g);
unspecified add_vertex(const vertex_name_type& p, adjacency_list& g);

向图中添加一个具有指定属性的顶点. 如果图使用顶点名称, 该顶点将被添加到 "拥有" 该名称的进程上. 否则, 该顶点将存储在本地进程中. 注意, 第二个构造函数会调用用户可定制的内部顶点构造器, 后者 (默认情况下) 在遇到未知顶点时抛出异常.

返回类型未指定, 但可拷贝构造, 并可隐式转换为顶点描述符.

void clear_vertex(vertex_descriptor u, adjacency_list& g);

移除所有与顶点 u 相连 (作为源点或目标点) 的边. 该顶点仍会出现在图的顶点集中.

对描述符与迭代器稳定性的影响与对所有以 u 为源点或目标点的边调用 remove_edge() 相同.

此操作不适用于有向图, 因为顶点 u 的入边是未知的.

void clear_out_edges(vertex_descriptor u, adjacency_list& g);

移除顶点 u 的所有出边. 该顶点仍会出现在图的顶点集中.

对描述符与迭代器稳定性的影响与对所有以 u 为源点的边调用 remove_edge() 相同.

此操作不适用于无向图 (应改用 clear_vertex()).

void clear_in_edges(vertex_descriptor u, adjacency_list& g);

移除顶点 u 的所有入边. 该顶点仍会出现在图的顶点集中.

对描述符与迭代器稳定性的影响与对所有以 u 为目标点的边调用 remove_edge() 相同.

此操作仅适用于双向图.

void remove_vertex(vertex_descriptor u, adjacency_list& g);

从图的顶点集中移除顶点 u. 假定在移除时不存在与顶点 u 相连的边. 确保这一点的一种方式是事先调用 clear_vertex(). 顶点 u 必须本地存储.

属性映射访问器

template <class PropertyTag>
property_map<adjacency_list, PropertyTag>::type
get(PropertyTag, adjacency_list& g);

template <class PropertyTag>
property_map<adjacency_list, Tag>::const_type
get(PropertyTag, const adjacency_list& g);

返回由 PropertyTag 指定的顶点属性的属性映射对象. PropertyTag 必须匹配图的 VertexProperty 模板参数中指定的属性之一. 返回的属性映射将是 分布式属性映射.

template <class PropertyTag , class X>
typename property_traits<property_map<adjacency_list, PropertyTag>::const_type>::value_type
get(PropertyTag, const adjacency_list& g, X x);

此函数返回 x 的属性值, 其中 x 是顶点描述符或边描述符. 描述符 x 所引用的实体必须存储在本地进程中.

template <class PropertyTag , class X, class Value>
void put(PropertyTag, const adjacency_list& g, X x, const Value& value);

此函数把 x 的属性值设为 value. x 是顶点描述符或边描述符. Value 必须可转换为 typename property_traits<property_map<adjacency_list, PropertyTag>::type>::value_type.
