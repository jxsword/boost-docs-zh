广度优先搜索

// named parameter version
template <class Graph, class P, class T, class R>
void breadth_first_search(Graph& G,
  typename graph_traits<Graph>::vertex_descriptor s,
  const bgl_named_params<P, T, R>& params);

// non-named parameter version
template <class Graph, class Buffer, class BFSVisitor,
          class ColorMap>
void breadth_first_search(const Graph& g,
   typename graph_traits<Graph>::vertex_descriptor s,
   Buffer& Q, BFSVisitor vis, ColorMap color);

breadth_first_search() 函数对有向图或无向图执行分布式广度优先遍历. 分布式 BFS 在语法上等价于其 顺序版本, 后者提供了更多背景与讨论. 本文重点说明语义上的差异, 其余细节请读者参阅 顺序广度优先搜索 的文档.

该分布式广度优先搜索算法实现了一种 层同步 (level-synchronized) 的广度优先搜索, 即 BFS 树中给定层的所有顶点都会在处理树的后续任何层的顶点之前被处理 (可能并行处理). 分布式广度优先搜索访问器应考虑这一行为, 该主题在 访问器事件点 中进一步讨论.

参数默认值

顺序广度优先搜索 的所有参数都受支持, 且含义基本相同. 此处仅记录差异部分.

IN: Graph& g
图类型必须是 分布图 的模型.
IN: vertex_descriptor s
起始顶点在每个进程中必须相同.
IN: visitor(BFSVisitor vis)
访问器必须是分布式 BFS 访问器. 顺序与分布式 BFS 访问器之间的细微差别在 访问器事件点 一节中讨论.
UTIL/OUT: color_map(ColorMap color)
颜色映射必须是 分布式属性映射, 其进程组与图 g 相同, 且其颜色必须单调加深 (white -> gray -> black). 默认值是由 default_color_type 的 std::vector 创建的分布式 iterator_property_map.
UTIL: buffer(Buffer& Q)

队列必须是分布式队列, 它把顶点传递给其属主进程. 如果已访问的顶点不应被再次访问 (BFS 的典型情形), 该队列必须自行过滤重复项. 队列控制算法内的同步: 其 empty() 方法在所有本地队列为空之前不得返回 true.

默认: 一个 distributed_queue, 其封装了 filtered_queue, 而后者包覆于
标准 boost::queue 之上. 该队列过滤重复顶点并恰当地分发顶点.

复杂度

该算法在 d + 1 个 BSP 超步中执行 O(V + E) 的工作量, 其中 d 是被搜索连通分量的直径. 在所有超步中, 共传输 O(E) 条恒定大小的消息.

访问器事件点

BFS 访问器 概念定义了 9 个事件点, 它们将由 顺序广度优先搜索 触发. 分布式 BFS 保留这九个事件点, 但所触发事件的序列以及每个事件发生的进程会随图的分布而变化.

initialize_vertex(s, g)
每个进程都会为其每个本地顶点调用此事件.
discover_vertex(u, g)
每当一个进程发现新顶点 u 时都会调用此事件. 由于分布式属性映射中的信息不完整, 同一顶点 u 可能多次触发此事件.
examine_vertex(u, g)
此事件由拥有顶点 u 的进程调用. 如果分布式队列阻止重复项, 则对特定顶点 u 只会调用一次.
examine_edge(e, g)
此事件由拥有 e 的源顶点的进程调用. 如果分布式队列阻止重复项, 则对特定边 e 只会调用一次.
tree_edge(e, g)
与 examine_edge 类似, 此事件由拥有源顶点的进程调用, 并且可能只调用一次. 与顺序 BFS 不同, 即使目标顶点已被发现 (但由不同进程发现), 此事件也可能被触发. 因此, 顺序 BFS 中的某些 non_tree_edge 事件在分布式 BFS 中可能变为 tree_edge.
non_tree_edge(e, g)
顺序 BFS 中的某些 non_tree_edge 事件在分布式 BFS 中可能变为 tree_edge 事件. 更多细节参见 tree_edge 的说明.
gray_target(e, g)
与 tree_edge 一样, 在不知道另一进程何时已发现某顶点的情况下, 由于给定处理器上信息的缺乏, 当顺序 BFS 中可能发生 black_target 事件时, 分布式 BFS 中却可能发生 gray_target 事件. 边 e 的源顶点对执行此事件的进程而言是本地的.
black_target(e, g)
参见 gray_target
finish_vertex(e, g)
参见 examine_vertex 的文档.

使访问器对分布式 BFS 安全

为分布式 BFS 更新既有 BFS 访问器或编写新的分布式 BFS 访问器时, 要记住的三件最重要的事情是:

  1. 确保所有状态要么完全是本地的, 要么位于与图使用相同进程组的分布式数据结构 (很可能是属性映射!) 中.
  2. 确保访问器不要求分布式 BFS 无法保证的精确事件序列, 例如要求 tree_edge 与 non_tree_edge 事件完全区分开.
  3. 确保访问器能够在信息不完整的情况下运作. 这通常包括在 分布式属性映射 中使用恰当的归并 (reduction) 操作, 并验证写入的结果比先前写入的结果 "更好".

分布式 BFS 访问器示例

为说明顺序与分布式 BFS 访问器之间的差异, 我们考虑一个把源顶点到其他每个顶点的距离放入属性映射的 BFS 访问器. 顺序访问器非常简单:

template<typename DistanceMap>
struct bfs_discovery_visitor : bfs_visitor<>
{
  bfs_discovery_visitor(DistanceMap distance) : distance(distance) {}

  template<typename Edge, typename Graph>
  void tree_edge(Edge e, const Graph& g)
  {
    std::size_t new_distance = get(distance, source(e, g)) + 1;
    put(distance, target(e, g), new_distance);
  }

 private:
  DistanceMap distance;
};

为了针对分布式 BFS 重新审视这段代码, 我们考虑 使访问器对分布式 BFS 安全 一节中的三个要点:

  1. 距离映射需要成为分布式映射, 因为到每个顶点的距离应存储在拥有该顶点的进程中. 这实际上是对用户提出的要求, 即提供这样一个分布式属性映射; 尽管在许多情况下属性映射会自动成为分布式的, 不需要任何语法上的更改.

  2. 此访问器 确实 要求一个可能随分布式 BFS 而变化的精确事件序列. 可能出现的多余 tree_edge 事件会导致针对单个顶点多次尝试把距离写入距离映射. 因此我们需要考虑第 3 条.

  3. 由于每个顶点可能写入多个距离值, 我们必须始终选择所能找到的最佳值来更新距离映射. 分布式属性映射 distance 需要把距离解析为其所见的最小距离. 例如, 进程 0 可能在第 3 层发现顶点 u, 而进程 1 在第 5 层发现它: 距离必须保持为 3. 为此, 我们声明该属性映射的 角色 是距离映射, 这将引入一个恰当的归并操作:

    set_property_map_role(vertex_distance, distance);

由此得到的分布式 BFS 访问器 (它同样适用于顺序 BFS, 无需任何更改) 与我们最初的顺序 BFS 访问器非常相似. 注意构造函数中的单行差异:

template<typename DistanceMap>
struct bfs_discovery_visitor : bfs_visitor<>
{
  bfs_discovery_visitor(DistanceMap distance) : distance(distance)
  {
    set_property_map_role(vertex_distance, distance);
  }

  template<typename Edge, typename Graph>
  void tree_edge(Edge e, const Graph& g)
  {
    std::size_t new_distance = get(distance, source(e, g)) + 1;
    put(distance, target(e, g), new_distance);
  }

 private:
  DistanceMap distance;
};
