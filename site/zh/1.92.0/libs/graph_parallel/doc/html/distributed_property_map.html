分布式属性映射

分布式属性映射适配器是这样一种属性映射: 其存储的值分布在多个进程上互不重叠的内存空间中. 当前进程本地的值存储在本地属性映射中, 可以通过 get 与 put 立即访问. 存储在远程进程上的值也可以通过 get 与 put 访问, 但行为略有不同:

  • put 操作更新一个本地幽灵单元 (ghost cell), 并向拥有该值的进程发送一条 "put" 消息. 属主可以随意更新自己的 "官方" 值, 也可以忽略该 put 请求.
  • get 操作返回本地幽灵单元的内容. 如果没有可用的幽灵单元, 则使用一个 (可定制的) 默认值创建一个.

使用分布式属性映射比使用本地顺序属性映射需要多加小心. 尽管语法与语义相似, 但分布式属性映射可能包含过期的信息, 只有通过在所有进程中调用 synchronize 函数才能保证同步.

为了解决值过期的问题, 分布式属性映射支持多种 一致性模型, 并可为其提供 归并操作.

分布式属性映射满足 可读属性映射 的要求, 并可能满足 可写属性映射 与 读/写属性映射 概念的要求. 但是, 分布式属性映射 不 满足 左值属性映射 概念的要求, 因为驻留在另一进程中的元素无法直接寻址. 分布式属性映射有以下几种形式:

  • 分布式属性映射适配器
  • 分布式迭代器属性映射
  • 分布式安全迭代器属性映射
  • 本地属性映射

一致性模型

分布式属性映射提供多种一致性模型, 它们影响从远程键读取与写入的值同属主进程中存储的该键 "官方" 值之间的关系. 分布式属性映射的一致性模型可通过成员函数 set_consistency_model 设为 boost::parallel::consistency_model 枚举中各标志的按位或. 各个标志为:

  • cm_forward: 默认的一致性模型, 它把远程处理器上 put 操作的值向前传播给被更改值的属主.
  • cm_backward: 在所有值都被转发或刷写到属主进程之后, 每个进程会收到其每个幽灵单元的更新值. 同步之后, 保证幽灵单元中的值与属主处理器上存储的值一致.
  • cm_bidirectional: cm_forward 与 cm_backward 的组合.
  • cm_flush: 在同步开始时, 把本地存储在幽灵单元中的所有值发送给其属主处理器.
  • cm_reset: 在同步之后执行 reset() 操作, 把每个幽灵单元中的值设为默认值.
  • cm_clear: 在同步之后执行 clear() 操作, 消除所有幽灵单元.

有几种常见的标志组合会产生有意义的一致性模型. 其中一些组合为:

  • cm_forward: 单独使用时, 向前一致性模型可使 Dijkstra 最短路径 与 广度优先搜索 等算法正确运作.
  • cm_flush & cm_reset: 所有更新值先在本地排队, 然后在同步步骤中刷写. 一旦刷写完成, 幽灵单元将恢复为其默认值. PageRank 实现使用该一致性模型在本地为每个节点累计排名.

归并操作

归并操作通过决定对属性映射的多次写入如何解析、以及在请求未知值时属性映射应当做什么, 来维持一致性. 更具体地说, 归并操作在两种情况下被使用:

  1. 当需要一个远程键的值但当前没有可用的值时, 归并操作提供一个合适的默认值. 例如, 存储距离的分布式属性映射可以有返回无穷大作为默认值的归并操作, 而顶点颜色的分布式属性映射可能返回白色作为默认值.
  2. 当从远程进程收到一个值时, 拥有与该值相关联的键的进程必须决定哪个值——本地存储的值、从远程进程收到的值、或两者的某种组合——将作为 "官方" 值存储在属性映射中. 归并操作把本地值与远程值变换为要存储的 "官方" 值.

分布式属性映射的归并操作可通过 distributed_property_map 的 set_reduce 方法设置. 归并操作是带有两个签名的函数对象. 第一个签名接受一个 (远程) 键并返回其默认值, 而第二个签名接受一个键与两个值 (先本地后远程), 并返回将存储在本地属性映射中的组合值. 归并操作还必须包含一个静态常量 non_default_resolver , 它声明归并操作的默认值是否真正表现得像默认值. 它应为 ``true, 当默认值有意义时 (例如距离的无穷值); 当不应使用默认值时为 false.

分布式 PageRank 算法使用以下归并操作. 远程节点的默认排名为 0. 排名先在本地累计, 然后归并操作通过相加来组合本地值与远程值. 与 "把所有值刷写到属主然后本地重置" 的一致性模型相结合, 由此得到的属性映射将在每个处理器上计算部分和, 然后在属主处理器上累计结果. PageRank 归并操作定义如下.

template<typename T>
struct rank_accumulate_reducer {
  static const bool non_default_resolver = true;

  // The default rank of an unknown node
  template<typename K>
  T operator()(const K&) const { return T(0); }

  template<typename K>
  T operator()(const K&, const T& x, const T& y) const { return x + y; }
};

分布式属性映射适配器

分布式属性映射适配器从一个本地属性映射、一个应在其上进行分布的 进程组、以及一个索引该分布式属性映射的 全局描述符 类型创建分布式属性映射.

模板参数

ProcessGroup:
属性映射分布其上的进程组的类型, 同时也是通信的媒介.
LocalPropertyMap:
将为该处理器本地的键存储值的属性映射的类型. 该属性映射的 value_type 将成为分布式属性映射的 value_type. 分布式属性映射对与 LocalPropertyMap 相同的属性映射概念建模, 但有一个例外: 分布式属性映射不能是 左值属性映射 (因为远程值不可寻址), 因此限于 读/写属性映射.
Key:
分布式属性映射的 key_type, 它必须对 全局描述符 概念建模. Key 参数的进程 ID 类型必须与 ProcessGroup 的进程 ID 类型一致, 且 Key 的本地描述符类型必须可转换为 LocalPropertyMap 的 key_type.
GhostCellS:

一个选择器类型, 指示幽灵单元应如何存储在分布式属性映射中. 视编译器而定, 有两到三个选项:

  • boost::parallel::gc_mapS (默认): 使用 STL map 存储每个进程的幽灵单元.
  • boost::parallel::gc_vector_mapS: 使用排序的 STL vector 存储每个进程的幽灵单元. 该选项适用于幽灵单元中可能只有少量插入的情形; 例如, 如果使用的唯一幽灵单元是用于相邻顶点的, 属性映射可以用每个相邻顶点的单元来初始化, 提供比 map 更快的查找并使用更少的空间.
  • boost::parallel::gc_hash_mapS: 使用 GCC 的 hash_map 存储幽灵单元. 对于幽灵单元集合无法预先确定的大问题规模, 该选项可能比 map 提升性能.

自由函数

reference get(distributed_property_map pm, const key_type& key);

获取 pm 中与给定 key 相关联的元素. 如果键指向本地存储的数据, 返回与该键相关联的实际值. 如果键指向非本地数据, 返回幽灵单元的值. 如果幽灵单元不存在, 行为取决于当前的归并操作: 如果已设置归并操作且其 non_default_resolver 设为 true, 则将按照归并操作提供的默认值创建一个幽灵单元. 否则, 对 get 的调用将中止, 因为该远程单元不存在值. 要避免此问题, 可以设置一个生成默认值的归并操作, 或对该值调用 request() 然后执行同步步骤, 或在读取之前向该单元 put 一个值.

void
put(distributed_property_map pm, const key_type& key, const value_type& value);

把与 key 相关联的给定 value 放入属性映射 pm. 如果键指向本地存储的数据, 该值会被立即更新. 如果键指向存储在远程进程中的数据, 则更新 (或创建) 包含该键此值的本地幽灵单元, 并把新值发送给属主进程. 注意, 属主进程可能基于归并操作拒绝该值, 但这要到下一个同步步骤才会被检测到.

void
local_put(distributed_property_map pm, const key_type& key, const value_type& value);

等价于 put(pm, key, value), 但当非本地键的值被更改时, 不会向属主进程发送消息.

void synchronize(distributed_property_map& pm);

同步存储在分布式属性映射中的值. 每个进程必须同时执行 synchronize, 之后每个进程中的幽灵单元将反映属主进程中存储的实际值.

本地属性映射

一种属性映射适配器, 它访问底层属性映射, 后者的键类型为 Key 类型的本地部分, 用于键的本地子集. 本地属性映射通常由分布式图类型用于顶点索引属性.

概要

template<typename ProcessGroup, typename GlobalKey, typename LocalMap>
  class local_property_map
  {
  public:
  typedef typename property_traits<LocalMap>::value_type value_type;
  typedef GlobalKey                                      key_type;
  typedef typename property_traits<LocalMap>::reference  reference;
  typedef typename property_traits<LocalMap>::category   category;

  explicit
  local_property_map(const ProcessGroup& process_group = ProcessGroup(),
                     const LocalMap& local_map = LocalMap());

  reference operator[](const key_type& key);
};

reference get(const local_property_map& pm, key_type key);
void put(local_property_map pm, const key_type& key, const value_type& value);

模板参数

ProcessGroup:全局键分布其上的进程组的类型.
GlobalKey:本地属性映射的 key_type, 它必须对 全局描述符 概念建模. GlobalKey 参数的进程 ID 类型必须与 ProcessGroup 的进程 ID 类型一致, 且 GlobalKey 的本地描述符类型必须可转换为 LocalMap 的 key_type.
LocalMap:将为该处理器本地的键存储值的属性映射的类型. 该属性映射的 value_type 将成为本地属性映射的 value_type. 本地属性映射对与 LocalMap 相同的属性映射概念建模.
