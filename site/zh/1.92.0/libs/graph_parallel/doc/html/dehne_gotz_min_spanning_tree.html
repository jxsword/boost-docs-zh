最小生成树

Parallel BGL 包含四种用于无向带权分布图的 最小生成树 (MST) 算法 [DG98]. 图不必是连通的: 当给定非连通图时, 每种算法都会计算最小生成森林 (MSF).

四种算法的接口与顺序 BGL 中 'Kruskal 算法'_ 的实现类似. 每种算法至少接受一个图、一个权重映射和一个输出迭代器. MST (或 MSF) 的边将通过进程 0 上的输出迭代器输出: 其他进程也可能在其输出迭代器上收到边, 但依据算法的不同, 该集合可能并不完整. 这些算法的参数一并说明, 因为它们差别不大. 有关算法选择的建议, 参见 选择 MST 算法 一节.

图本身必须对 顶点列表图 概念与分布式边列表图概念建模. 由于最常见的分布式图结构 分布式邻接表 只对分布式顶点列表图概念建模, 因此只有把它包装在适当的适配器 (例如 vertex_list_adaptor) 中时, 才能将其用于这些算法.

说明

稠密 Boruvka 分布式最小生成树算法是 Boruvka 的顺序 MST 算法的直接并行化. 该算法首先把每个顶点构成一个 超顶点. 然后, 在每次迭代中, 它找到与每个顶点关联的最小权边, 沿这些边收缩超顶点, 并移除所有自环. 顺序算法与并行算法的唯一区别在于: 并行算法执行一次 all-reduce 操作, 使所有进程都拥有全局最小边集.

与其他三种算法不同, 该算法在所有进程上都通过输出迭代器输出最小生成森林的完整边列表. 因此, 在并行化顺序 BGL 程序时, 它可能比其他算法更有用.

复杂度

该分布式算法需要 O(log n) 个 BSP 超步, 每个超步每个进程需要 O(m/p + n) 的时间与 O(n) 的通信量.

说明

合并本地 MST 算法的运作方式是: 先从每个进程上存储的边计算最小生成森林, 然后各进程沿一棵树合并其边列表. 子节点停止参与计算, 而父节点则根据新获得的边重新计算 MSF. 在最后一轮中, 树的根在经由树收到来自所有其他进程的候选边之后, 计算全局 MSF.

复杂度

该算法需要 O(log_D p) 个 BSP 超步 (其中 D 是树中子节点的数量, 目前固定为 3). 每个超步每个进程需要 O((m/p) log (m/p) + n) 的时间与 O(m/p) 的通信量.

说明

该算法把 Boruvka 步骤与本地 MSF 合并步骤结合在一起, 以获得比任何单一算法更好的渐近性能. 它首先执行 Boruvka 步骤, 直到只剩 n/(log_d p)^2 个超顶点, 然后对剩余的边与超顶点执行本地 MSF 合并, 完成 MSF 计算.

复杂度

该算法需要 log_D p + log log_D p 个 BSP 超步. 每个超步所需的时间取决于所执行超步的类型; 详情参见分布式 Boruvka 算法或本地 MSF 合并算法.

说明

该算法把 Boruvka 步骤与本地 MSF 合并步骤结合在一起, 以获得比任何单一方法更好的渐近性能. 在每次迭代中, 该算法先执行一个 Boruvka 步骤, 然后合并基于超顶点图计算出的本地 MSF.

复杂度

该算法需要 log_D p 个 BSP 超步. 每个超步所需的时间取决于所执行超步的类型; 详情参见分布式 Boruvka 算法或本地 MSF 合并算法. 不过, 当图足够稠密 (即 m/n >= p) 时, 该算法的通信是可选的 (总体通信量为 O(n)).

选择 MST 算法

Dehne 与 Gotz 在评估这四种算法时报告了 [DG98] 混合的结果: 没有哪种算法在所有情况下都明显优于其他算法. 然而, 渐近意义上最优的算法 (boruvka_mixed_merge) 在他们的测试中似乎表现不如其他基于合并的算法. 以下性能图表展示了这四种最小生成树实现的性能.

总体而言, 对于我们测试的图, dense_boruvka_minimum_spanning_tree 给出了一致性最好的性能与可扩展性. 此外, 它可能更适合于正在并行化的顺序程序, 因为它在每个进程中都通过输出迭代器输出完整的 MSF 边列表.
