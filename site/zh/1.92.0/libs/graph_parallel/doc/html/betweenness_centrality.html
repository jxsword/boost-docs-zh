brandes_betweenness_centrality() 函数计算图中顶点与边的介数中心性. 以 O(V) 空间计算介数中心性的方法出自 Brandes [Brandes01]. 该算法本身是 Edmonds [Edmonds09] 对 Brandes 算法的一个修改.

参数

IN: const Graph& g
图类型必须是 分布图 的模型. 图类型还必须对 关联图 概念建模. g 中权重为 0 的边将导致未定义行为.
IN: CentralityMap centrality

可向算法提供一个中心性映射 (centrality map); 若未提供, 则将使用 dummy_property_map, 且不会记录任何顶点中心性信息. CentralityMap 类型必须是 分布式属性映射. 其键类型必须是图的顶点描述符类型.

默认: 一个 dummy_property_map.

IN: EdgeCentralityMap edge_centrality_map

可向算法提供一个边中心性映射 (edge centrality map); 若未提供, 则将使用 dummy_property_map, 且不会记录任何边中心性信息. EdgeCentralityMap 类型必须是 分布式属性映射. 其键类型必须是图的顶点描述符类型.

默认: 一个 dummy_property_map.

IN: IncomingMap incoming

入边映射 (incoming map) 保存指向某顶点、且属于通往该顶点的最短路径的那些入边. IncomingMap 类型必须是 分布式属性映射. 其键类型与值类型都必须是图的顶点描述符类型.

默认: 一个 iterator_property_map, 其基于
std::vector 的 std::vector (元素为图的顶点描述符类型).
IN: DistanceMap distance

距离映射记录算法最短路径部分中到达各顶点的距离. DistanceMap 类型必须是 分布式属性映射. 其键类型必须是图的顶点描述符类型.

默认: 一个 iterator_property_map, 其基于
std::vector, 其元素类型为 CentralityMap 的值类型.
IN: DependencyMap dependency

依赖映射 (dependency map) 记录算法中心性计算部分中每个顶点的依赖. DependencyMap 类型必须是 分布式属性映射. 其键类型必须是图的顶点描述符类型.

默认: 一个 iterator_property_map, 其基于
std::vector, 其元素类型为 CentralityMap 的值类型.

IN: PathCountMap path_count

路径计数映射 (path count map) 记录算法中心性计算部分中每个顶点所位于的最短路径的数量. PathCountMap 类型必须是 分布式属性映射. 其键类型必须是图的顶点描述符类型.

默认: 一个 iterator_property_map, 其基于
std::vector, 元素为图的度数量类型.
IN: VertexIndexMap vertex_index

一个 可读属性映射 模型, 其键类型为图 g 的顶点描述符类型, 值类型为整数类型. 该属性映射应把顶点映射到其 (本地) 索引, 索引范围为 [0, num_vertices(g)).

默认: get(vertex_index, g)

IN: WeightMap weight_map
一个 可读属性映射 模型, 其键类型为图 g 的边描述符类型. 若未提供, 介数中心性的计算将不带权重.
IN: Buffer sources

一个 缓冲区 模型, 包含算法的起始顶点. 若 sources 为空, 则将使用 g 中的所有顶点执行完整的介数中心性计算. 缓冲区的值类型必须是图的顶点描述符类型.

默认: 一个 int 类型的空 boost::queue.

复杂度

计算最短路径、对它们计数并计算对中心性映射的贡献为 O(V log V). 计算精确介数中心性需要对 g 中所有顶点的最短路径进行计数, 因此精确介数中心性为 O(V^2 log V).

算法描述

对于 sources 中的顶点 (当 sources 为空时为 g 中的所有顶点), 算法首先调用 delta_stepping_shortest_paths 的一个定制实现, 该实现使用 IncomingMap 维护一棵最短路径树. IncomingMap 包含最短路径上所有入边的来源.

IncomingMap 在最短路径树中各边的目标点处定义了最短路径 DAG. 在双向情形下, 可使用边标志把最短路径信息转换到边的源点. 在最短路径计算期间设置边标志, 而不是使用 IncomingMap, 将会使最短路径计算的内层循环增加一个 O(V) 因子, 以顾及在发现新的最短路径时必须清除边标志. 这会提高算法的复杂度. 渐近意义上, 当前实现更优; 但在双向情形中使用边标志会把所需超步 (superstep) 的数量减少到每个顶点最短路径 DAG 的深度. 目前, outgoing 映射是通过简单地反转入边映射中的边来显式构造的. outgoing 映射构造完成后, 会从最短路径计算的源点开始按依赖顺序遍历它, 以计算路径计数. 路径计数计算完毕后, 再次从源点开始按依赖顺序遍历最短路径 DAG, 以计算每个顶点的依赖与中心性.

当 g 中所有顶点的中心性都计算完毕后, 算法结束.
