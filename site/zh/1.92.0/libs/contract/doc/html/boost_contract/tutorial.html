本节是本库基本用法的指南.

非成员函数

非成员函数的契约使用 boost::contract::function 编写. 例如 (参见 non_member.cpp):

#include <boost/contract.hpp>

// Contract for a non-member function.
int inc(int& x) {
    int result;
    boost::contract::old_ptr<int> old_x = BOOST_CONTRACT_OLDOF(x);
    boost::contract::check c = boost::contract::function()
        .precondition([&] {
            BOOST_CONTRACT_ASSERT(x < std::numeric_limits<int>::max());
        })
        .postcondition([&] {
            BOOST_CONTRACT_ASSERT(x == *old_x + 1);
            BOOST_CONTRACT_ASSERT(result == *old_x);
        })
        .except([&] {
            BOOST_CONTRACT_ASSERT(x == *old_x);
        })
    ;

    return result = x++; // Function body.
}

本库所需的全部头文件通过 #include <boost/contract.hpp> 包含. 或者, 程序员可以从 boost/contract/*.hpp 中选择性地只包含实际需要的头文件 (参见 入门).

可以为非成员函数指定前置条件、后置条件和异常保证 (参见 前置条件、后置条件 和 异常保证).

boost::contract::function 函数返回一个 RAII 对象, 该对象必须始终被赋给一个类型为 boost::contract::check 的局部变量 (否则本库将产生运行期错误, 参见 BOOST_CONTRACT_ON_MISSING_CHECK_DECL). [19] 此外, 此处不能使用 C++11 的 auto 声明, 必须显式指定 boost::contract::check 类型 (否则本库在 C++17 之前将产生编译期错误, 在 C++17 之后将产生运行期错误). [20] 函数体紧跟在这个 RAII 对象的声明之后编写.

注释

在某些情况下, 可能需要在契约之前编写一些代码. 例如, 获取检查契约时要用的资源 (如旧值), 以及在多线程程序中锁定互斥量 (或其他同步机制).

构造时, 用于非成员函数的 boost::contract::check RAII 对象执行以下操作 (即外围函数的入口):

  1. 检查前置条件, 方法是调用传递给 r() 的零元仿函数 .precondition(r).

析构时 (即外围函数的出口):

  1. 如果函数体没有抛出异常:
    1. 检查后置条件, 方法是调用传递给 s() 的零元仿函数 .postcondition(s).
  2. 否则:
    1. 检查异常保证, 方法是调用传递给 e() 的零元仿函数 .except(e).

这保证非成员函数契约在运行期被正确检查 (参见 函数调用). (另需注意, 即使通过函数指针、函数对象等调用函数, 它们也会正确检查自己的契约. )

注释

出于效率考虑, 非成员函数可以不调用 boost::contract::function, 但前提是它没有前置条件、没有后置条件, 也没有异常保证.

前置条件

指定前置条件时, 用一个仿函数编写, 并传递给 r, 它可以不带参数地调用, 如 .precondition(r). 没有前置条件的契约干脆不调用 r(). 当这些条件都存在时, 前置条件必须位于后置条件和异常保证之前 (参见 .precondition(...)后置条件 和 异常保证).

C++11 lambda 函数便于编写前置条件, 但也可以使用任何其他零元仿函数 (参见 不使用 lambda 函数 一节). [21] 例如, 对于 boost::contract::function (公有函数同理; 析构函数没有前置条件, 而构造函数使用 boost::contract::constructor_precondition, 参见 公有函数、析构函数 和 构造函数):

void f(...) {
    boost::contract::check c = boost::contract::function()  // Same for all other contracts.
        .precondition([&] {                                 // Capture by reference or value...
            BOOST_CONTRACT_ASSERT(...);                     // ...and should not modify captures.
            ...
        })
        ...
    ;

    ...
}

前置条件仿函数应当捕获断言前置条件所需的全部变量. 当复制这些变量的开销可以接受时, 可以按值捕获. [22] 无论如何, 程序员不应编写会修改被捕获变量值的前置条件断言, 即使这些变量是按引用捕获的 (参见 常量正确性).

前置条件仿函数中可以编写任何代码, 但建议保持这段代码简单, 主要使用断言和 if 语句 (避免编写复杂的前置条件——它们可能有缺陷, 并且在运行期检查起来也慢). 还建议使用 BOOST_CONTRACT_ASSERT 来编写前置条件断言, 因为这样当被断言的条件求值为假时, 本库能够打印信息丰富的错误消息 (注意这不是可变参数宏, 参见 不使用宏):

BOOST_CONTRACT_ASSERT(boolean-condition)
// Or, if `boolean-condition` contains commas `,` not already within parenthesis `()`...
BOOST_CONTRACT_ASSERT((boolean-condition)) // ...use extra parenthesis (not a variadic macro).

如果 boost::contract::precondition_failure 的任一条件为假, 或者更一般地, 调用通过 BOOST_CONTRACT_ASSERT 指定的仿函数时抛出了任何异常, 本库将自动调用失败处理器 .precondition(...). 默认情况下, 该失败处理器向 std::cerr 打印错误消息, 并调用 std::terminate 终止程序 (参见 失败时抛出异常 以把失败处理器改为抛出异常、以错误码退出程序等).

注释

当契约的断言只使用调用者可访问的公有成员时最有用, 这样调用者才能恰当地检查和使用契约. 特别是, 使用非公有成员的公有函数或构造函数的前置条件在本质上是不正确的, 因为调用者无法完整检查它们 (实际上, Eiffel 在这种情况下会产生编译期错误). 不过, 本库不强制这一约束, 而是把编写契约时 (尤其是断言前置条件时) 只使用公有成员的责任留给程序员 (参见 规约与实现).

后置条件

指定后置条件时, 用一个仿函数编写, 并传递给 s, 它可以不带参数地调用, 如 .postcondition(s). 没有后置条件的契约干脆不调用 s(). 当这些条件都存在时, 后置条件必须位于前置条件之后、异常保证之前 (参见 .postcondition(...)前置条件 和 异常保证).

C++11 lambda 函数便于编写后置条件, 但也可以使用任何其他零元仿函数 (参见 不使用 lambda 函数 一节). 例如, 对于 boost::contract::function (所有其他契约同理):

void f(...) {
    boost::contract::check c = boost::contract::function()  // Same for all other contracts.
        ...
        .postcondition([&] {                                // Capture by reference...
            BOOST_CONTRACT_ASSERT(...);                     // ...but should not modify captures.
            ...
        })
        ...
    ;

    ...
}

后置条件仿函数应当捕获断言后置条件所需的全部变量. 一般而言, 这些变量应按引用捕获而不是按值捕获 (因为后置条件需要访问这些变量在函数出口处的值, 而不是后置条件仿函数首次声明时这些变量的值). 后置条件还可以捕获返回值和旧值 (参见 返回值 与 旧值). 无论如何, 程序员不应编写会修改被捕获变量值的后置条件断言, 即使这些变量是按引用捕获的 (参见 常量正确性).

后置条件仿函数中可以编写任何代码, 但建议保持这段代码简单, 主要使用断言和 if 语句 (避免编写复杂的后置条件——它们可能有缺陷, 并且在运行期检查起来也慢). 还建议使用 BOOST_CONTRACT_ASSERT 来编写后置条件断言, 因为这样当被断言的条件求值为假时, 本库能够打印信息丰富的错误消息 (注意这不是可变参数宏, 参见 不使用宏):

BOOST_CONTRACT_ASSERT(boolean-condition)
// Or, if `boolean-condition` has commas `,` not already within parenthesis `()`...
BOOST_CONTRACT_ASSERT((boolean-condition)) // ...use extra parenthesis (not a variadic macro).

如果 boost::contract::postcondition_failure 的任一条件为假, 或者更一般地, 调用通过 BOOST_CONTRACT_ASSERT 指定的仿函数时抛出了任何异常, 本库将自动调用失败处理器 .postcondition(...). 默认情况下, 该失败处理器向 std::cerr 打印错误消息, 并调用 std::terminate 终止程序 (参见 失败时抛出异常 以把失败处理器改为抛出异常、以错误码退出程序等).

对于非 void 虚公有函数和非 void 公有函数覆盖, 传递给 s 的仿函数 .postcondition(s) 不是零元仿函数, 而是一元仿函数, 它以保存返回值的变量为其唯一参数 s(result) (这是为了恰当地支持子契约, 参见 虚公有函数 与 公有函数覆盖).

返回值

在非 void 函数中, 后置条件可能需要访问函数返回值来编写断言. 在这些情况下, 程序员有责任在契约之前声明一个局部变量, 并在函数出口处 (当函数不抛出异常时) 把它赋值为返回值. [23] 例如, 对于 boost::contract::function (所有其他契约同理):

return_type f(...) {
    return_type result;                                     // Must be later assigned to return value.
    boost::contract::check c = boost::contract::function()  // Same for all other contracts.
        ...
        .postcondition([&] {                                // Also capture `result` reference...
            BOOST_CONTRACT_ASSERT(result == ...);           // ...but should not modify captures.
            ...
        })
        ...
    ;

    ...
    return result = ...;                                    // Assign `result` at each return.
}

在外围函数返回的任何位置, 程序员都有责任把结果变量赋值为被返回的表达式. 做到这一点的方法是确保函数中的 所有 return 语句都形如:

return-type result;
...
return result = return-expression;                           // Assign `result` at each return.

用于编写后置条件的仿函数应当按引用而不是按值捕获结果变量 (因为后置条件必须访问结果变量在函数出口处的值, 而不是后置条件仿函数首次声明时结果变量的值). 返回值绝不应在前置条件、旧值复制或异常保证中使用 (因为在前置条件被检查、旧值被复制时, 或者函数抛出异常时, 返回值尚未被正确求值和设置). 无论如何, 程序员不应在契约断言中修改结果变量 (参见 常量正确性).

当函数返回类型没有默认构造函数, 或者首次声明结果变量时执行默认构造函数代价过高或不可取时, 也可以用 boost::optional 来声明结果变量 (参见 可选返回值).

非 void 虚公有函数和非 void 公有函数覆盖必须始终声明并使用结果变量, 即使后置条件并不直接使用函数返回值 (这是为了恰当地支持子契约, 参见 虚公有函数 与 公有函数覆盖).

旧值

当后置条件或异常保证中使用旧值时, 程序员有责任在契约之前声明局部变量, 并使用 BOOST_CONTRACT_OLDOF 把它们赋值为相关的旧值表达式. [24] 例如, 对于 boost::contract::function (所有其他契约同理):

void f(...) {
    boost::contract::old_ptr<old_type> old_var = BOOST_CONTRACT_OLDOF(old_expr);
    ...                                                     // More old value declarations here if needed.
    boost::contract::check c = boost::contract::function()  // Same for all other contracts.
        ...                                                 // Preconditions shall not use old values.
        .postcondition([&] {                                // Capture by reference...
            BOOST_CONTRACT_ASSERT(*old_var == ...);         // ...but should not modify captures.
            ...
        })
        .except([&] {                                       // Capture by reference...
            BOOST_CONTRACT_ASSERT(old_var->...);            // ...but should not modify captures.
            ...
        })
    ;

    ...
}

本库使用智能指针类模板 boost::contract::old_ptr 来处理旧值 (因此程序员无需直接管理所指向内存的分配和释放). [25] 所指向的旧值类型会被自动限定为 const (这样契约断言就不会误改旧值, 参见 常量正确性). 本库保证到检查后置条件和异常保证时, 旧值指针总是非空的 (因此程序员可以在后置条件和异常保证断言中安全地解引用并使用这些指针, 使用 operator* 和 operator->, 而无需先检查旧值指针是否非空).

旧值不应在前置条件中使用, 而且本库不保证检查前置条件时旧值指针总是非空. [26] 关于把旧值的复制推迟到类不变式 (对于构造函数、析构函数和公有函数) 和前置条件检查之后, 参见 在函数体处复制的旧值 (必要时, 这允许在类不变式和前置条件断言已得到满足这一简化假定下编写旧值表达式).

BOOST_CONTRACT_OLDOF 是可变参数宏, 在虚公有函数或公有函数覆盖中使用时会接受一个额外参数 (参见 虚公有函数 与 公有函数覆盖). 为简洁起见, C++11 的 auto 声明可以与 BOOST_CONTRACT_OLDOF 一起使用 auto old_variable-name = BOOST_CONTRACT_OLDOF(expression) (但另参见 旧值要求). 参见 不使用宏 一节, 了解不使用 BOOST_CONTRACT_OLDOF 编写旧值的方法 (例如在不支持可变参数宏的编译器上).

注释

本库保证旧值只被复制一次. 本库还保证, 当通过同时定义 BOOST_CONTRACT_NO_POSTCONDITIONS 和 BOOST_CONTRACT_NO_EXCEPTS 来禁用后置条件和异常保证时, 旧值绝不会被复制 (注意这两个宏必须都定义; 只定义 BOOST_CONTRACT_NO_POSTCONDITIONS 或只定义 BOOST_CONTRACT_NO_EXCEPTS 不足以避免旧值复制的运行期开销).

异常保证

指定异常保证时, 用一个仿函数编写, 并传递给 e, 它可以不带参数地调用, 如 .except(e). 没有异常保证的契约干脆不调用 e(). 当这些条件都存在时, 异常保证必须位于前置条件和后置条件之后 (参见 .except(...)前置条件 和 后置条件).

C++11 lambda 函数便于编写异常保证, 但也可以使用任何其他零元仿函数 (参见 不使用 lambda 函数 一节). 例如, 对于 boost::contract::function (所有其他契约同理):

void f(...) {
    boost::contract::check c = boost::contract::function()  // Same for all other contracts.
        ...
        .except([&] {                                       // Capture by reference...
            BOOST_CONTRACT_ASSERT(...);                     // ...but should not modify captures.
            ...
        })
    ;

    ...
}

异常保证仿函数应当捕获断言异常保证所需的全部变量. 一般而言, 这些变量应按引用捕获而不是按值捕获 (因为异常保证需要访问这些变量在函数抛出异常时的值, 而不是异常保证仿函数首次声明时这些变量的值). 异常保证还可以捕获旧值 (参见 旧值), 但不应访问函数返回值 (因为函数抛出异常时返回值尚未被正确设置). 无论如何, 程序员不应编写会修改被捕获变量值的异常保证断言, 即使这些变量是按引用捕获的 (参见 常量正确性).

注释

在真实的生产代码中, 如果不求助于会拖慢执行的昂贵旧值复制, 可能很难编写有意义的异常保证. 因此, 作者们承认, 即使本库支持异常保证, 它们在实践中也可能不常被使用 (本文档其余部分列出的大多数示例也没有使用它们). 无论如何, 这些性能考量最终由程序员及其具体应用领域决定.

异常保证仿函数中可以编写任何代码, 但建议保持这段代码简单, 主要使用断言和 if 语句 (避免编写复杂的异常保证——它们可能有缺陷, 并且在运行期检查起来也慢). 还建议使用 BOOST_CONTRACT_ASSERT 来编写异常保证断言, 因为这样当被断言的条件求值为假时, 本库能够打印信息丰富的错误消息 (注意这不是可变参数宏, 参见 不使用宏):

BOOST_CONTRACT_ASSERT(boolean-condition)
// Or, if `boolean-condition` has commas `,` not already within parenthesis `()`...
BOOST_CONTRACT_ASSERT((boolean-condition)) // ...use extra parenthesis (not a variadic macro).

本库将自动调用失败处理器 boost::contract::except_failure 或 BOOST_CONTRACT_ASSERT, 如果 .except(...) 的任一条件为假, 或者更一般地, 当在函数入口或出口分别检查不变式时 std::cerr 函数抛出了异常. 默认情况下, 这些处理器向 std::terminate 打印错误消息, 并调用 终止程序 (参见 失败时抛出异常

注释

虽然从技术上讲, 程序员可以指定在异常保证失败时抛出异常的异常保证处理器, 但这会迫使 C++ 终止程序. 因为该处理器会在栈上已有一个活动异常时再抛出异常 (即最初触发异常保证检查的、由函数体抛出的异常). 因此, 程序员不应把异常保证失败处理器改为抛出异常.

类不变式

可以把公有成员函数、构造函数和析构函数编写为同时检查类不变式. 指定类不变式时, 把它们编写在一个公有 const 函数中, 名为 invariant, 不带参数, 返回 void. 没有不变式的类干脆不声明 invariant 函数. [27] 例如:

class u {
public:                                 // Must be public.
    void invariant() const {            // Must be const.
        BOOST_CONTRACT_ASSERT(...);
        ...
    }

    ...
};

这个成员函数必须是 const 的, 因为契约不应修改对象状态 (参见 常量正确性). 如果缺少 const 限定符, 本库将产生编译期错误 (除非定义了 BOOST_CONTRACT_PERMISSIVE).

invariant 函数中可以编写任何代码, 但建议保持这段代码简单, 主要使用断言和 if 语句 (避免编写复杂的不变式——它们可能有缺陷, 并且在运行期检查起来也慢). 还建议使用 BOOST_CONTRACT_ASSERT 来编写类不变式断言, 因为这样当被断言的条件求值为假时, 本库能够打印信息丰富的错误消息 (注意这不是可变参数宏, 参见 不使用宏):

BOOST_CONTRACT_ASSERT(boolean-condition)
// Or, if `boolean-condition` has commas `,` not already within parenthesis `()`...
BOOST_CONTRACT_ASSERT((boolean-condition)) // ...use extra parenthesis (not a variadic macro).

本库将自动调用失败处理器 boost::contract::entry_invariant_failure 或 boost::contract::exit_invariant_failure, 如果 BOOST_CONTRACT_ASSERT 的任一条件为假, 或者更一般地, 当在函数入口或出口分别检查不变式时 invariant 函数抛出了异常. 默认情况下, 这些处理器向 std::cerr 打印错误消息, 并调用 std::terminate 终止程序 (参见 失败时抛出异常 以把这些失败处理器改为抛出异常、以错误码退出程序等).

参见 访问说明符 一节, 了解如何避免把 invariant 成员函数设为 public. [28] 参见 BOOST_CONTRACT_INVARIANT_FUNC, 以使用不同于 invariant 的名字 (例如因为 invariant 与用户自定义类中的其他名字冲突).

注释

直接访问数据成员时不检查契约断言 (连类不变式也不检查) (这与 Eiffel 不同——在 Eiffel 中, 即使是访问公有数据成员也会检查类不变式). 因此, 对于拥有不变式的 class 和 struct (以及 union, 参见 联合 (union)) 而言, 最好不要有可变的公有数据成员, 而只通过适当的公有函数 (如设置器和获取器) 公开访问数据成员——这些函数可以用本库编写为检查类不变式.

参见 volatile 公有函数 一节, 了解如何为具有 volatile 公有函数的类编写不变式.

静态类不变式

可以把静态公有函数编写为检查静态类不变式. 指定静态类不变式时, 把它们编写在一个公有 static 函数中, 名为 static_invariant, 不带参数, 返回 void. 没有静态类不变式的类干脆不声明 static_invariant 函数. [29] 例如:

class u {
public:                                 // Must be public.
    static void static_invariant() {    // Must be static.
        BOOST_CONTRACT_ASSERT(...);
        ...
    }

    ...
};

这个成员函数必须是 static 的 (并且它正确地无法访问对象 this). 如果缺少 static 限定符, 本库将产生编译期错误 (除非定义了 BOOST_CONTRACT_PERMISSIVE 宏).

static_invariant 函数中可以编写任何代码, 但建议保持这段代码简单, 主要使用断言和 if 语句 (避免编写复杂的静态不变式——它们可能有缺陷, 并且在运行期检查起来也慢). 还建议使用 BOOST_CONTRACT_ASSERT 来编写断言, 因为这样当被断言的条件求值为假时, 本库能够打印信息丰富的错误消息 (注意这不是可变参数宏, 参见 不使用宏):

BOOST_CONTRACT_ASSERT(boolean-condition)
// Or, if `boolean-condition` has commas `,` not already within parenthesis `()`...
BOOST_CONTRACT_ASSERT((boolean-condition)) // ...use extra parenthesis (not a variadic macro).

本库将自动调用失败处理器 boost::contract::entry_invariant_failure 或 boost::contract::exit_invariant_failure, 如果 BOOST_CONTRACT_ASSERT 的任一条件为假, 或者更一般地, 当在函数入口或出口分别检查不变式时 static_invariant 函数抛出了异常. 默认情况下, 这些处理器向 std::cerr 打印错误消息, 并调用 std::terminate 终止程序 (参见 失败时抛出异常 以把这些失败处理器改为抛出异常、以错误码退出程序等).

参见 访问说明符 一节, 了解如何避免把 static_invariant 成员函数设为 public. [30] 参见 BOOST_CONTRACT_STATIC_INVARIANT_FUNC, 以使用不同于 static_invariant 的名字 (例如因为 static_invariant 与用户自定义类中的其他名字冲突). [31]

构造函数

构造函数的契约使用 boost::contract::constructor 函数和 boost::contract::constructor_precondition 基类编写. 例如 (参见 public.cpp):

class unique_identifiers :
    private boost::contract::constructor_precondition<unique_identifiers>
{
public:
    void invariant() const {
        BOOST_CONTRACT_ASSERT(size() >= 0);
    }


public:
    // Contract for a constructor.
    unique_identifiers(int from, int to) :
        boost::contract::constructor_precondition<unique_identifiers>([&] {
            BOOST_CONTRACT_ASSERT(from >= 0);
            BOOST_CONTRACT_ASSERT(to >= from);
        })
    {
        boost::contract::check c = boost::contract::constructor(this)
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(size() == (to - from + 1));
            })
        ;

        // Constructor body.
        for(int id = from; id <= to; ++id) vect_.push_back(id);
    }


    /* ... */
};

无法使用 .precondition(...) 为构造函数指定前置条件 (如果在 .precondition(...) 返回的对象上使用 boost::contract::constructor, 本库将产生编译期错误). 构造函数的前置条件改用 boost::contract::constructor_precondition 基类指定 (在 前置条件 一节所作的考量同样适用于传递给 boost::contract::constructor_precondition 的前置条件仿函数). 程序员不应从构造函数前置条件中访问对象 *this (因为构造函数体执行之前对象尚不存在). [32] 没有前置条件的构造函数干脆不显式初始化 boost::contract::constructor_precondition 基类 (因为 boost::contract::constructor_precondition 的默认构造函数不检查任何契约). 使用 boost::contract::constructor_precondition 基类时: [33]

  • 它应当被指定为继承列表中的第一个类 (这样构造函数前置条件会在初始化任何其他基类或数据成员之前被检查).
  • 它的继承访问说明符应当始终是 private (这样这个额外的基类就不会改变其派生类的公有继承树).
  • 它绝不应被声明为 virtual 基类 (因为虚基类在整个继承层次中只初始化一次, 这会阻止其他基类的前置条件被检查).
  • 它以派生类作为模板参数. [34]
注释

出于效率考虑, 类可以不继承 boost::contract::constructor_precondition, 但前提是它的所有构造函数都没有前置条件.

可以为构造函数指定后置条件 (参见 后置条件), 但程序员不应在构造函数后置条件中访问对象的旧值 *this (因为构造函数体执行之前对象尚不存在). [35] 也可以为构造函数指定异常保证 (参见 异常保证), 但程序员不应在构造函数异常保证中访问对象 *this 或其旧值 (因为构造函数体执行之前对象不存在, 而且既然构造函数体抛出了异常, 对象也就没有被正确构造). [36] boost::contract::constructor 函数以 this 作为参数 (因为构造函数会检查类不变式, 参见 类不变式).

boost::contract::constructor 函数返回一个 RAII 对象, 该对象必须始终被赋给一个类型为 boost::contract::check 的局部变量 (否则本库将产生运行期错误, 参见 BOOST_CONTRACT_ON_MISSING_CHECK_DECL). 此外, 此处不能使用 C++11 的 auto 声明, 必须显式指定 boost::contract::check 类型 (否则本库在 C++17 之前将产生编译期错误, 在 C++17 之后将产生运行期错误). 构造函数体紧跟在这个 RAII 对象的声明之后编写.

构造时, 用于构造函数的 boost::contract::check RAII 对象执行以下操作 (即外围构造函数的入口):

  1. 检查静态类不变式, 方法是调用 type-of(*this)::static_invariant() (但不检查非静态类不变式, 因为对象尚不存在).

析构时 (即外围构造函数的出口):

  1. 检查静态类不变式, 方法是调用 type-of(*this)::static_invariant().
  2. 如果构造函数体没有抛出异常:
    1. 检查非静态类不变式, 方法是调用 this->invariant().
    2. 检查后置条件, 方法是调用传递给 s() 的零元仿函数 .postcondition(s).
  3. 否则:
    1. 检查异常保证, 方法是调用传递给 e() 的零元仿函数 .except(e).

这一点与 C++ 的基类对象构造机制以及 boost::contract::constructor_precondition 的使用一起, 保证构造函数契约在运行期被正确检查 (参见 构造函数调用).

注释

出于效率考虑, 构造函数可以不调用 boost::contract::constructor, 但前提是它没有后置条件、没有异常保证, 且其类没有不变式 (即使派生类没有使用 boost::contract::constructor, 基类构造函数的契约仍会被 C++ 对象构造机制正确检查).

由 C++ 自动生成的默认构造函数和复制构造函数不会检查契约. 因此, 除非这些构造函数不是公有的, 或者它们没有前置条件、没有后置条件、没有异常保证且其类没有不变式, 否则程序员应当用 boost::contract::constructor 和 boost::contract::constructor_precondition 手动定义它们. 对于 C++ 自动生成的所有其他构造函数 (例如移动构造函数), 同样适用这些考量.

私有构造函数与受保护构造函数

私有构造函数和受保护构造函数可以省略 boost::contract::constructor (因为它们不属于类的公有接口, 因此不要求检查类不变式, 参见 构造函数调用). 它们仍然可以使用 boost::contract::constructor_precondition 在成员初始化之前检查前置条件, 甚至可以使用 boost::contract::function (但不是 boost::contract::constructor) 来只检查后置条件和异常保证, 而不检查类不变式, 也不调用 .precondition(...) (参见 私有函数与受保护函数). 例如:

class u : private boost::contract::constructor_precondition<u> {
protected:
    // Contract for a protected constructor (same for private constructors).
    u() : // Still use this base class to check constructor preconditions.
        boost::contract::constructor_precondition<u>([&] {
            BOOST_CONTRACT_ASSERT(...);
            ...
        })
    {
        // Following will correctly not check class invariants.
        boost::contract::check c = boost::contract::function()
            // Do not use `.precondition(...)` here.
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(...);
                ...
            })
            .except([&] {
                BOOST_CONTRACT_ASSERT(...);
                ...
            })
        ;

        ... // Constructor body.
    }

    ...
};

析构函数

析构函数的契约使用 boost::contract::destructor 编写. 例如 (参见 public.cpp):

class unique_identifiers :
    private boost::contract::constructor_precondition<unique_identifiers>
{
public:
    void invariant() const {
        BOOST_CONTRACT_ASSERT(size() >= 0);
    }


public:
    // Contract for a destructor.
    virtual ~unique_identifiers() {
        // Following contract checks class invariants.
        boost::contract::check c = boost::contract::destructor(this);

        // Destructor body here... (do nothing in this example).
    }


    /* ... */
};

无法为析构函数指定前置条件 (如果在此使用 .precondition(...), 本库将产生编译期错误; 这是因为析构函数可以在构造之后的任何时刻被调用, 所以它们没有前置条件). 可以为析构函数指定后置条件 (参见 后置条件, 示例另见 静态公有函数), 但程序员不应在析构函数后置条件中访问对象 *this (因为析构函数体执行完毕后对象已不存在). [37] 也可以为析构函数指定异常保证 (参见 异常保证; 尽管在 C++ 中析构函数通常应被编写为不抛出异常, 实际上自 C++11 起析构函数被隐式声明为 noexcept). [38] boost::contract::destructor 函数以 this 作为参数 (因为析构函数会检查类不变式, 参见 类不变式).

boost::contract::destructor 函数返回一个 RAII 对象, 该对象必须始终被赋给一个类型为 boost::contract::check 的局部变量 (否则本库将产生运行期错误, 参见 BOOST_CONTRACT_ON_MISSING_CHECK_DECL). 此外, 此处不能使用 C++11 的 auto 声明, 必须显式指定 boost::contract::check 类型 (否则本库在 C++17 之前将产生编译期错误, 在 C++17 之后将产生运行期错误). 析构函数体紧跟在这个 RAII 对象的声明之后编写.

构造时, 用于析构函数的 boost::contract::check RAII 对象执行以下操作 (即外围析构函数的入口):

  1. 检查静态和非静态类不变式, 方法是调用 type-of(*this)::static_invariant() AND this->invariant().

析构时 (即外围析构函数的出口):

  1. 检查静态类不变式, 方法是调用 type-of(*this)::static_invariant().
  2. 如果析构函数体没有抛出异常:
    1. 检查后置条件, 方法是调用传递给 s() 的零元仿函数 .postcondition(s).
  3. 否则 (尽管在 C++ 中析构函数通常应被编写为不抛出异常):
    1. 检查非静态类不变式, 方法是调用 this->invariant() (因为对象未成功析构).
    2. 检查异常保证, 方法是调用传递给 e() 的零元仿函数 .except(e).

这一点与 C++ 的基类对象析构机制一起, 保证析构函数契约在运行期被正确检查 (参见 析构函数调用).

注释

出于效率考虑, 析构函数可以不调用 boost::contract::destructor, 但前提是它没有后置条件、没有异常保证, 且其类没有不变式 (即使派生类没有使用 boost::contract::destructor, 基类析构函数的契约仍会被 C++ 对象析构机制正确检查).

由 C++ 自动生成的默认析构函数不会检查契约. 因此, 除非析构函数不是公有的, 或者它没有后置条件、没有异常保证且其类没有不变式, 否则程序员应当用 boost::contract::destructor 手动定义它.

私有析构函数与受保护析构函数

私有析构函数和受保护析构函数可以省略 boost::contract::destructor (因为它们不属于类的公有接口, 因此不要求检查类不变式, 参见 析构函数调用). 它们可以使用 boost::contract::function (但不是 boost::contract::destructor) 来只检查后置条件和异常保证, 而不检查类不变式, 也不调用 .precondition(...) (参见 私有函数与受保护函数). 例如:

class u {
protected:
    // Contract for a protected destructor (same for private destructors).
    virtual ~u() {
        // Following will correctly not check class invariants.
        boost::contract::check c = boost::contract::function()
            // Do not use `.precondition(...)` here.
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(...);
                ...
            })
            // Could use `.except(...)` here in rare cases of destructors declared to throw.
        ;

        ... // Destructor body.
    }

    ...
};

公有函数

公有函数的契约使用 boost::contract::public_function 编写. 本节考虑既非静态、也非虚、且不覆盖任何基类函数的公有函数. 例如 (参见 public.cpp):

class unique_identifiers :
    private boost::contract::constructor_precondition<unique_identifiers>
{
public:
    void invariant() const {
        BOOST_CONTRACT_ASSERT(size() >= 0);
    }


public:
    // Contract for a public function (but no static, virtual, or override).
    bool find(int id) const {
        bool result;
        boost::contract::check c = boost::contract::public_function(this)
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(id >= 0);
            })
            .postcondition([&] {
                if(size() == 0) BOOST_CONTRACT_ASSERT(!result);
            })
        ;

        // Function body.
        return result = std::find(vect_.begin(), vect_.end(), id) !=
                vect_.end();
    }


    /* ... */
};

可以为公有函数指定前置条件、后置条件和异常保证 (参见 前置条件、后置条件 和 异常保证). 从非静态公有函数中调用时, boost::contract::public_function 函数以 this 作为参数 (因为公有函数会检查类不变式, 参见 类不变式).

boost::contract::public_function 函数返回一个 RAII 对象, 该对象必须始终被赋给一个类型为 boost::contract::check 的局部变量 (否则本库将产生运行期错误, 参见 BOOST_CONTRACT_ON_MISSING_CHECK_DECL). 此外, 此处不能使用 C++11 的 auto 声明, 必须显式指定 boost::contract::check 类型 (否则本库在 C++17 之前将产生编译期错误, 在 C++17 之后将产生运行期错误). 公有函数体紧跟在这个 RAII 对象的声明之后编写.

构造时, 用于公有函数的 boost::contract::check RAII 对象执行以下操作 (即外围公有函数的入口):

  1. 检查静态和非静态类不变式, 方法是调用 type-of(*this)::static_invariant() AND this->invariant().
  2. 检查前置条件, 方法是调用传递给 r() 的零元仿函数 .precondition(r).

析构时 (即外围公有函数的出口):

  1. 检查静态和非静态类不变式, 方法是调用 type-of(*this)::static_invariant() AND this->invariant() (即使函数体抛出了异常).
  2. 如果函数体没有抛出异常:
    1. 检查后置条件, 方法是调用传递给 s() 的零元仿函数 .postcondition(s).
  3. 否则:
    1. 检查异常保证, 方法是调用传递给 e() 的零元仿函数 .except(e).

这保证公有函数契约在运行期被正确检查 (参见 公有函数调用).

注释

出于效率考虑, 公有函数可以不调用 boost::contract::public_function, 但前提是它没有前置条件、没有后置条件、没有异常保证, 不是虚函数, 不覆盖任何虚函数, 且其类没有不变式.

由 C++ 自动生成的默认复制赋值运算符不会检查契约. 因此, 除非该运算符不是公有的, 或者它没有前置条件、没有后置条件、没有异常保证且其类没有不变式, 否则程序员应当用 boost::contract::public_function 手动定义它. 对于 C++ 自动生成的所有其他运算符 (例如移动运算符), 同样适用这些考量.

虚公有函数

公有函数的契约使用 boost::contract::public_function 编写. 本节考虑是虚函数、但不覆盖任何基类函数的公有函数. 例如 (参见 public.cpp):

class unique_identifiers :
    private boost::contract::constructor_precondition<unique_identifiers>
{
public:
    void invariant() const {
        BOOST_CONTRACT_ASSERT(size() >= 0);
    }


public:
    // Contract for a public virtual function (but no override).
    virtual int push_back(int id, boost::contract::virtual_* v = 0) { // Extra `v`.
        int result;
        boost::contract::old_ptr<bool> old_find =
                BOOST_CONTRACT_OLDOF(v, find(id)); // Pass `v`.
        boost::contract::old_ptr<int> old_size =
                BOOST_CONTRACT_OLDOF(v, size()); // Pass `v`.
        boost::contract::check c = boost::contract::public_function(
                v, result, this) // Pass `v` and `result`.
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(id >= 0);
                BOOST_CONTRACT_ASSERT(!find(id)); // ID cannot be already present.
            })
            .postcondition([&] (int const result) {
                if(!*old_find) {
                    BOOST_CONTRACT_ASSERT(find(id));
                    BOOST_CONTRACT_ASSERT(size() == *old_size + 1);
                }
                BOOST_CONTRACT_ASSERT(result == id);
            })
        ;

        // Function body.
        vect_.push_back(id);
        return result = id;
    }


    /* ... */
};

虚公有函数必须声明一个类型为 boost::contract::virtual_* 的额外尾随参数, 默认值为 0 (即 nullptr). [39] 这个额外参数是最后一个参数且带默认值, 因此它不会改变虚函数的调用接口 (调用者即使需要处理这个额外参数也极少见, 只有直接操纵虚函数类型做函数指针类型转换等情况除外). 程序员必须把这个额外的虚参数作为第一个实参传递给虚公有函数定义中的所有 BOOST_CONTRACT_OLDOF 和 boost::contract::public_function 调用. [40]

从虚公有函数中调用时, boost::contract::public_function 函数以 this 作为参数 (因为公有函数会检查类不变式, 参见 类不变式). 对于返回 void 的虚公有函数:

class u {
public:
    // A void virtual public function (that does not override).
    virtual void f(t_1 a_1, ..., t_n a_n, boost::contract::virtual_* v = 0) {
        boost::contract::check c = boost::contract::public_function(
                v, this)                                    // No result parameter...
            .precondition([&] { ... })
            .postcondition([&] { ... })                     // ...so nullary functor.
            .except([&] { ... })
        ;

        ...
    }

    ...
}

对于不返回 void 的虚公有函数, 程序员还必须把函数返回值的引用作为第二个实参传递给 boost::contract::public_function. 此时, 本库会把这个返回值引用传递给后置条件仿函数, 因此该仿函数必须只接受一个与返回类型匹配的参数, 否则本库将产生编译期错误 (仿函数参数可以是常量引用 const&, 以避免返回值的额外复制): [41] 

class u {
public:
    // A void virtual public function (that does not override).
    virtual t f(t_1 a_1, ..., t_n a_n, boost::contract::virtual_* v = 0) {
        t result;
        boost::contract::check c = boost::contract::public_function(
                v, result, this)                            // Result parameter...
            .precondition([&] { ... })
            .postcondition([&] (t const& result) { ... })   // ...so unary functor.
            .except([&] { ... })
        ;

        ...                                                 // Assign `result` at each return.
    }

    ...
}
重要

在虚公有函数内, 把额外的虚参数 v 传递给所有 BOOST_CONTRACT_OLDOF 和 boost::contract::public_function 调用, 并对非 void 虚公有函数在 v 之后把返回值引用传递给 boost::contract::public_function, 是程序员的责任. 如果程序员没有做到这一点, 本库无法自动产生编译期错误 (但这一般会阻止本库在运行期正确检查契约). [42]

助记法:

当存在 v 时, 总是把它作为第一个实参传递给 boost::contract::public_function 和 BOOST_CONTRACT_OLDOF.

对于非 void 函数, 总是把 result 紧跟在 boost::contract::public_function 之后传递给 v.

其余方面, 在 公有函数 一节所作的考量同样适用于虚公有函数.

注释

虚公有函数应当始终调用 boost::contract::public_function (即使它没有前置条件、没有后置条件、没有异常保证且其类没有不变式), 否则本库将无法在子契约中正确使用它.

公有函数覆盖 (子契约)

公有函数的契约使用 boost::contract::public_function 编写. 本节考虑 (无论是否为虚函数) 覆盖其一个或多个公有基类中的虚公有函数的公有函数. 例如 (参见 public.cpp): [43] 

class identifiers
    #define BASES public unique_identifiers
    : BASES
{
public:
    typedef BOOST_CONTRACT_BASE_TYPES(BASES) base_types; // Bases typedef.
    #undef BASES

    void invariant() const { // Check in AND with bases.
        BOOST_CONTRACT_ASSERT(empty() == (size() == 0));
    }


public:
    // Contract for a public function override.
    int push_back(int id, boost::contract::virtual_* v = 0) /* override */ {
        int result;
        boost::contract::old_ptr<bool> old_find =
                BOOST_CONTRACT_OLDOF(v, find(id));
        boost::contract::old_ptr<int> old_size =
                BOOST_CONTRACT_OLDOF(v, size());
        boost::contract::check c = boost::contract::public_function<
            override_push_back // Pass override type plus below function pointer...
        >(v, result, &identifiers::push_back, this, id) // ...and arguments.
            .precondition([&] { // Check in OR with bases.
                BOOST_CONTRACT_ASSERT(id >= 0);
                BOOST_CONTRACT_ASSERT(find(id)); // ID can be already present.
            })
            .postcondition([&] (int const result) { // Check in AND with bases.
                if(*old_find) BOOST_CONTRACT_ASSERT(size() == *old_size);
            })
        ;

        // Function body.
        if(!find(id)) unique_identifiers::push_back(id); // Else, do nothing.
        return result = id;
    }
    BOOST_CONTRACT_OVERRIDE(push_back) // Define `override_push_back`.


    /* ... */
};

用 typedef 声明的这个额外 BOOST_CONTRACT_BASE_TYPES 是本库对派生类的要求, 本库在内部用它来检测用于子契约的基类 (参见 基类). 如果在任何用于子契约的公有基类中都没有合适的可覆盖虚函数, 本库将产生编译期错误. [44]

从公有函数覆盖中调用时, boost::contract::public_function 函数模板接受一个显式模板实参 override_function-name, 该实参必须用 BOOST_CONTRACT_OVERRIDE 定义:

BOOST_CONTRACT_OVERRIDE(function-name)

它可以在外围类的公有段中的任何位置声明 (参见 访问说明符 一节, 了解如何在类的非公有段中使用 BOOST_CONTRACT_OVERRIDE). BOOST_CONTRACT_OVERRIDE 在一个类中对给定的函数名只使用一次, 重载函数可以复用同一个 override_function-name 定义 (参见 函数重载). BOOST_CONTRACT_NAMED_OVERRIDE 可用于生成不同于 override_function-name 的名字 (例如, 避免为已以下划线 "__" 开头的函数名生成包含双下划线 "_" 的 C++ 保留名, 参见 命名覆盖). 为方便起见, BOOST_CONTRACT_OVERRIDES 可以一次接受多个函数名, 而不必为每个函数名重复 BOOST_CONTRACT_OVERRIDE (在支持可变参数宏的编译器上). 例如, 对于名为 f、g 和 h 的三个函数 (对任何其他数量的函数同理), 下面的写法:

BOOST_CONTRACT_OVERRIDES(f, g, h)

等价于: [45] 

BOOST_CONTRACT_OVERRIDE(f)
BOOST_CONTRACT_OVERRIDE(g)
BOOST_CONTRACT_OVERRIDE(h)

如果被覆盖的基类虚函数签名中带有这个参数, 那么公有函数覆盖必须始终列出这个类型为 boost::contract::virtual_* 的额外尾随参数, 默认值为 0 (即 nullptr), 即使它们没有被声明为 virtual. 程序员必须把这个额外的虚参数作为第一个实参传递给公有函数覆盖定义中的所有 BOOST_CONTRACT_OLDOF 和 boost::contract::public_function 调用 (参见 虚公有函数).

从公有函数覆盖中调用时, boost::contract::public_function 函数接受一个指向外围函数的指针、对象 *this (因为公有函数覆盖会检查类不变式, 参见 类不变式), 以及按函数声明中的出现顺序排列的各函数实参的引用. [46] 对于返回 void 的公有函数覆盖:

class u {
public:
    // A void public function override.
    void f(t_1 a_1, ..., t_n a_n, boost::contract::virtual_* v = 0) /* override */ {
        boost::contract::check c = boost::contract::public_function<override_f>(
                v, &u::f, this, a_1, ..., a_n)              // No result parameter...
            .precondition([&] { ... })
            .postcondition([&] { ... })                     // ...so nullary functor.
            .except([&] { ... })
        ;

        ...
    }
    BOOST_CONTRACT_OVERRIDE(f)

    ...
}

对于不返回 void 的公有函数覆盖, 程序员还必须把函数返回值的引用作为第二个实参传递给 boost::contract::public_function (否则本库将产生编译期错误). [47] 此时, 本库会把这个返回值引用传递给后置条件仿函数, 因此该仿函数必须只接受一个与返回类型匹配的参数, 否则本库将产生编译期错误 (仿函数参数可以是常量引用 const&, 以避免返回值的额外复制, 与不覆盖的非 void 虚公有函数 类似):

class u {
public:
    // A non-void public function override.
    t f(t_1 a_1, ..., t_n a_n, boost::contract::virtual_* v = 0) /* override */ {
        t result;
        boost::contract::check c = boost::contract::public_function<override_f>(
                v, result, &u::f, this, a_1, ..., a_n)      // Result parameter...
            .precondition([&] { ... })
            .postcondition([&] (t const& result) { ... })   // ...so unary functor.
            .except([&] { ... })
        ;

        ...                                                 // Assign `result` at each return.
    }
    BOOST_CONTRACT_OVERRIDE(f)

    ...
}

如果程序员为派生类中的公有函数覆盖指定的返回值与基类中被覆盖虚公有函数的返回类型不一致, 本库将抛出 boost::contract::bad_virtual_result_cast. [48]

重要

在公有函数覆盖内, 把额外的虚参数 v 传递给所有 BOOST_CONTRACT_OLDOF 和 boost::contract::public_function 调用, 并对非 void 公有函数覆盖在 v 之后把返回值引用传递给 boost::contract::public_function, 是程序员的责任. 如果程序员没有做到这一点, 本库并不总能产生编译期错误 (但这一般会阻止本库在运行期正确检查契约).

助记法:

当存在 override_... 时, 总是把它作为模板参数传递给 boost::contract::public_function.

当存在 v 时, 总是把它作为第一个实参传递给 boost::contract::public_function 和 BOOST_CONTRACT_OLDOF.

对于非 void 函数, 总是把 result 紧跟在 boost::contract::public_function 之后传递给 v.

构造时, 用于公有函数覆盖的 boost::contract::check RAII 对象执行以下操作 (即外围公有函数覆盖的入口):

  1. 检查所有被覆盖基类和派生类的静态和非静态类不变式, AND 彼此取或, 方法是调用 type-of(overridden-base_1)::static_invariant() AND overridden-base_1.invariant() AND... type-of(overridden-base_n)::static_invariant() AND overridden-base_n.invariant() AND type-of(*this)::static_invariant() AND this->invariant().
  2. 检查所有被覆盖基类函数和派生类覆盖函数的前置条件, OR 彼此取或, 方法是调用零元仿函数 r_1() OR... r_n() OR r() 传递给 .precondition(r_1), …… .precondition(r_n)、.precondition(r) (分别对应所有被覆盖函数和覆盖函数).

析构时 (即外围公有函数覆盖的出口):

  1. 检查所有被覆盖基类和派生类的静态和非静态类不变式, AND 彼此取或, 方法是调用 type-of(overridden-base_1)::static_invariant() AND overridden-base_1.invariant() AND... type-of(overridden-base_n)::static_invariant() AND overridden-base_n.invariant() AND type-of(*this)::static_invariant() AND this->invariant() (即使函数体抛出了异常).
  2. 如果函数体没有抛出异常:
    1. 检查所有被覆盖基类函数和派生类覆盖函数的后置条件, AND 彼此取或, 方法是调用零元仿函数 s_1() AND... s_n() AND s() 传递给 .postcondition(s_1), …… .postcondition(s_n)、.postcondition(s) (分别对应所有被覆盖函数和覆盖函数; 对于非 void 公有函数覆盖, 则改用一元仿函数 s_1(result) AND... s_n(result) AND s(result)).
  3. 否则:
    1. 检查所有被覆盖基类函数和派生类覆盖函数的异常保证, AND 彼此取或, 方法是调用零元仿函数 e_1() AND... e_n() AND e() 传递给 .except(e_1), …… .except(e_n)、.except(e) (分别对应所有被覆盖函数和覆盖函数).

这保证公有函数覆盖的契约与子契约依照替换原则 在运行期被正确检查 (参见 公有函数调用).

其余方面, 在 虚公有函数 一节所作的考量同样适用于公有函数覆盖.

注释

公有函数覆盖应当始终调用 boost::contract::public_function (即使它没有前置条件、没有后置条件、没有异常保证且其类没有不变式), 否则本库将无法在子契约中正确使用它.

基类 (子契约)

为了支持子契约, 程序员必须为派生类指定基类: 声明一个名为 base_types 的公有成员类型, 经由 typedef 并使用 BOOST_CONTRACT_BASE_TYPES. 例如 (参见 base_types.cpp):

class chars
    #define BASES /* local macro (for convenience) */ \
        private boost::contract::constructor_precondition<chars>, \
        public unique_chars, \
        public virtual pushable<char>, \
        virtual protected has_size, \
        private has_empty
    : BASES // Bases of this class.
{
public:
    typedef BOOST_CONTRACT_BASE_TYPES(BASES) base_types; // Bases typedef.
    #undef BASES // Undefine local macro.

    /* ... */

为方便起见, 可以使用一个名为 的局部宏BASES 来避免重复书写基类列表两次 (第一次在派生类声明 class class-name : base-list 中, 第二次在调用 BOOST_CONTRACT_BASE_TYPES(base-list) 时). 作为一个局部宏, BASES 必须用 #undef BASES 在其用于声明 base_types typedef 之后取消定义 (以避免名字冲突和宏重定义错误). [49]

BOOST_CONTRACT_BASE_TYPES 是可变参数宏, 接受以逗号分隔的基类列表 (不使用宏编写 的方法参见 不使用宏base_types 一节). 如构造函数 一节所述, 当额外的基类 boost::contract::constructor_precondition 用于编写构造函数前置条件时, 其继承访问级别必须始终为 private, 且必须指定为第一个基类.

重要

传递给 BOOST_CONTRACT_BASE_TYPES 的每个基类都必须显式 指定其继承访问级别 public、protected 或 private (不过 virtual 是可选的, 与 C++ 惯常做法一样, 可以放在访问级别之前或之后). 如果第一个基类缺少继承访问级别, 本库将产生编译期错误; 但对于第一个之后的基类, 本库并不总能对缺失访问级别产生错误. [50] 确保传递给 BOOST_CONTRACT_BASE_TYPES 的所有基类都显式指定其继承访问级别是程序员的责任 (C++ 中继承访问级别反而是可选的, 因为对 private 类型隐式假定为 class, 对 public 类型隐式假定为 struct).

助记法:

对于传递给 public 的基类, 总是显式指定其继承访问级别 protected、private 或 BOOST_CONTRACT_BASE_TYPES.

参见 访问说明符 一节, 了解如何避免把 base_types 成员类型设为 public. [51] 参见 BOOST_CONTRACT_BASES_TYPEDEF, 以使用不同于 base_types 的名字 (例如因为 base_types 与用户自定义类中的其他名字冲突).

静态公有函数

公有函数的契约使用 boost::contract::public_function 编写. 本节考虑静态公有函数. 例如 (参见 static_public.cpp):

template<class C>
class make {
public:
    static void static_invariant() { // Static class invariants.
        BOOST_CONTRACT_ASSERT(instances() >= 0);
    }

    // Contract for a static public function.
    static int instances() {
        // Explicit template parameter `make` (check static invariants).
        boost::contract::check c = boost::contract::public_function<make>();

        return instances_; // Function body.
    }

    /* ... */

可以为静态公有函数指定前置条件、后置条件和异常保证 (参见 前置条件、后置条件 和 异常保证). 从静态公有函数中调用时, boost::contract::public_function 不能以对象 this 为参数 (因为静态成员函数中没有对象 this), 因此外围类类型要通过显式模板参数指定, 如 boost::contract::public_function<class-type> (检查静态类不变式需要类类型, 参见 类不变式):

class u {
public:
    // A static public function.
    static void f() {
        boost::contract::check c = boost::contract::public_function<u>() // Class type `u` as explicit template parameter.
            .precondition([&] { ... })
            .postcondition([&] { ... })
            .except([&] { ... })
        ;

        ...
    }

    ...
};

boost::contract::public_function 函数返回一个 RAII 对象, 该对象必须被赋给一个类型为 boost::contract::check 的局部变量 (否则本库将产生运行期错误, 参见 BOOST_CONTRACT_ON_MISSING_CHECK_DECL). 此外, 此处不能使用 C++11 的 auto 声明, 必须显式指定 boost::contract::check 类型 (否则本库在 C++17 之前将产生编译期错误, 在 C++17 之后将产生运行期错误). 静态公有函数体紧跟在这个 RAII 对象的声明之后编写.

构造时, 用于静态公有函数的 boost::contract::check RAII 对象执行以下操作 (即外围静态公有函数的入口):

  1. 检查静态类不变式, 方法是调用 class-type::static_invariant() (但绝不检查非静态类不变式).
  2. 检查前置条件, 方法是调用传递给 r() 的零元仿函数 .precondition(r).

析构时 (即外围静态公有函数的出口):

  1. 检查静态类不变式, 方法是调用 class-type::static_invariant() (即使函数体抛出了异常; 但绝不检查非静态类不变式).
  2. 如果函数体没有抛出异常:
    1. 检查后置条件, 方法是调用传递给 s() 的零元仿函数 .postcondition(s).
  3. 否则:
    1. 检查异常保证, 方法是调用传递给 e() 的零元仿函数 .except(e).

这保证静态公有函数契约在运行期被正确检查 (静态公有函数不进行子契约, 因为它们没有对象 this, 因而没有继承; 参见 公有函数调用).

注释

出于效率考虑, 静态公有函数可以不调用 boost::contract::public_function, 但前提是它没有前置条件、没有后置条件、没有异常保证, 且其类没有静态不变式 (该类仍然可以有非静态不变式或基类).

[42] 设计理由: 在不覆盖的虚公有函数中使用 boost::contract::public_function 时, 本库不要求程序员指定函数类型. 因此, 本库不知道外围函数是否有非 void 返回类型, 也就无法检查是否按要求为不覆盖的虚公有函数传递了返回值引用. 而对于虚公有函数覆盖, 函数类型会传递给本库, 这也使本库能够在这些情况下缺失返回值引用时产生编译期错误.

[43] 本文档中, 函数覆盖常用代码注释 /* override */ 标记. 在支持 C++11 虚说明符的编译器上, 可以改用 override 标识符 (本文档不使用 override, 只是因为虚说明符尚未获得广泛支持——即使是支持 C++11 lambda 函数的编译器也是如此).

[44] 本库在这种情况下产生的编译期错误, 在原理上类似于 C++11 override 说明符产生的错误, 但它仅限于带有额外 boost::contract::virtual_* 参数的函数, 并且只在传递给 public 的 BOOST_CONTRACT_BASE_TYPES 基类中递归查找, 因为只有这些基类才被纳入子契约的考虑.

[45] 没有等价的、一次处理多个函数名的 BOOST_CONTRACT_NAMED_OVERRIDE (BOOST_CONTRACT_NAMED_OVERRIDE 预期不会被频繁使用, 因此需要时简单重复多次即可).

[46] 设计理由: 对象 this 在函数指针之后传递, 是为了遵循 std::bind 的语法. 公有函数覆盖需要函数指针以及所有函数实参的引用, 因为本库必须在内部调用被覆盖的虚公有函数以检查它们的契约来实现子契约 (即使本库实际上不会执行被覆盖函数的函数体).

[47] 设计理由: 与不覆盖的虚公有函数一样, 公有函数覆盖在子契约时也使用额外的返回值参数把它传递给被覆盖函数. 对于公有函数覆盖, 本库手头有函数指针, 因此当函数为非 void 而程序员忘记指定额外的返回值参数时, 本库将产生编译期错误 (而对于不覆盖的虚公有函数则无法做这种额外的错误检查, 因为它们的契约不接受函数指针作为参数, 参见 虚公有函数).

[48] 设计理由: 此处没有使用 boost::bad_any_cast 异常, 因为它不打印源类型和目标类型名 (因此描述性不够).

[49] 这个局部宏的名字是任意的, 但本文档中常用 BASES.

[50] 设计理由: 本库显式要求继承访问级别, 因为派生类只能从公有基类进行子契约, 而不能从受保护或私有基类进行 (参见 公有函数调用). BOOST_CONTRACT_BASE_TYPES 使用预处理器元编程检查每个继承访问级别, 并把非公有基类从内部用于子契约的基类列表中移除. 然而, 当程序员忘记指定继承访问级别时, 本库并不总能检测出来, 因为当用逗号分隔传递给基类的模板参数时, 预处理器将无法正确使用逗号来识别继承列表中的下一个基类记号 (预处理器无法区分未被圆括号保护的逗号, 比如模板中使用的逗号). 因此, 本库用继承访问级别关键字 public、protected 或 private 代替逗号 ,, 以便预处理器能正确找到继承列表中的下一个基类记号 (因此程序员必须为每个基类显式指定继承访问级别).

[51] 为了简单起见, 本文档中的 base_type 成员类型常被声明为 public. 然而, 在生产代码中, 通过添加 base_types 类型来扩充类的公有成员可能不可接受 (可以使用 boost::contract::access 来避免, 如访问说明符 一节所述).
