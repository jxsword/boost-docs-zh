纯虚公有函数

在 C++ 中, 纯虚函数允许拥有默认实现, 只要这类实现按非内联 (out-of-line) 方式编写, 即定义在声明该纯虚函数的类之外 virtual ... = 0;.

纯虚公有函数的契约使用 boost::contract::public_function 函数编写, 与 (非纯) 虚公有函数的做法相同 (在 虚公有函数 中所作的全部考量均适用). 不过, 契约必须以非内联方式编写, 即写在纯虚函数的默认实现中. 例如 (参见 pure_virtual_public.cpp):

template<typename Iterator>
class range {
public:
    // Pure virtual function declaration (contract in definition below).
    virtual Iterator begin(boost::contract::virtual_* v = 0) = 0;


    /* ... */
};


// Pure virtual function default implementation (out-of-line in C++).
template<typename Iterator>
Iterator range<Iterator>::begin(boost::contract::virtual_* v) {
    Iterator result; // As usual, virtual pass `result` right after `v`...
    boost::contract::check c = boost::contract::public_function(v, result, this)
        .postcondition([&] (Iterator const& result) {
            if(empty()) BOOST_CONTRACT_ASSERT(result == end());
        })
    ;

    // Pure function body (never executed by this library).
    assert(false);
    return result;
}

当本库为检查子契约契约而调用纯虚函数的默认实现时, 它绝不会真正执行该纯虚函数的函数体. 因此, 如果程序员打算让该函数体永远不被执行, 可以安全地在函数体开头写 assert(false) (或者, 如果需要像 C++ 中惯常那样使用纯虚函数默认实现, 也可以编写一个实际可用的函数体).

子契约前置条件恒为真或恒为假

如 公有函数覆盖 中所述, 覆盖公有函数的前置条件会在 OR 中与被覆盖虚公有函数的前置条件一同检查. 因此, 如果基类中的虚公有函数未指定前置条件, 则其派生类中所有覆盖函数所指定的前置条件都将不起作用 (因为与基类中没有前置条件的被覆盖函数一同检查时, 它们总是通过):OR with the overridden function from the base class that has no preconditions, they will always pass):

class u { // Some base class.
public:
    virtual void f(boost::contract::virtual_* v = 0) {
        boost::contract::check c = boost::contract::public_function(v, this)
            // No preconditions, same as `ASSERT(true)`.
            ...
        ;

        ...
    }

    ...
};

这正确反映了如下事实: 基类中被覆盖的函数可以从任何上下文调用 (因为它没有前置条件), 因此按照替换原则, 其在所有派生类中的覆盖函数也必须如此. [52] 换言之, 上面的代码等同于在基类中为该虚公有函数声明一个总是平凡通过的前置条件 BOOST_CONTRACT_ASSERT(true):

class u { // Some base class.
public:
    virtual void f(boost::contract::virtual_* v = 0) {
        boost::contract::check c = boost::contract::public_function(v, this)
            .precondition([] {
                BOOST_CONTRACT_ASSERT(true); // Same as no preconditions.
            })
            ...
        ;

        ...
    }

    ...
};

反过来说, 程序员有时可能会考虑在基类中为纯虚公有函数声明一个总是失败的前置条件 BOOST_CONTRACT_ASSERT(false). 这表明该纯虚公有函数除非被派生类重新定义, 否则永远不能被调用 (C++ 的纯虚函数本来也是如此), 同时也表明基类设计者有意把为相关纯虚函数指定前置条件的工作留给派生类. 这种技巧可能只对纯虚公有函数的前置条件才有意义 (否则 BOOST_CONTRACT_ASSERT(false) 会阻止在具体基类中调用虚公有函数). 例如 (参见 named_override.cpp):

template<typename T>
class generic_unary_pack {
public:
    virtual void _1(T const& value, boost::contract::virtual_* v = 0) = 0;
    virtual T _1(boost::contract::virtual_* v = 0) const = 0;
};

template<typename T>
void generic_unary_pack<T>::_1(T const& value, boost::contract::virtual_* v) {
    boost::contract::check c = boost::contract::public_function(v, this)
        .precondition([&] {
            BOOST_CONTRACT_ASSERT(false); // Defer preconditions to overrides.
        })
    ;
    assert(false);
}

/* ... */

话虽如此, 需要声明这种总是失败的前置条件 BOOST_CONTRACT_ASSERT(false) 也可能表明基类接口设计不当. 一般而言, 基类接口仍应包含编写其契约所需的全部函数 (必要时可将其声明为纯虚).

可选返回值

当程序员无法在契约之前的声明点构造结果变量时 (例如, 返回类型在该处没有合适的构造函数可用, 或者仅仅因为在运行期额外执行一次返回值初始化的代价过高), 可以使用 boost::optional 来处理返回值. [53] 例如 (参见 optional_result.cpp):

template<unsigned Index, typename T>
T& get(std::vector<T>& vect) {
    boost::optional<T&> result; // Result not initialized here...
    boost::contract::check c = boost::contract::function()
        .precondition([&] {
            BOOST_CONTRACT_ASSERT(Index < vect.size());
        })
        .postcondition([&] {
            BOOST_CONTRACT_ASSERT(*result == vect[Index]);
        })
    ;

    // Function body (executed after preconditions checked).
    return *(result = vect[Index]); // ...result initialized here instead.
}

本例中返回类型是一个引用, 因此它没有默认构造函数, 无法用来在契约声明之前初始化 result. 此外, Index 需要先由前置条件验证它小于 size(), 然后才能用它取得引用并赋给 result, 所以 vect[Index] 不能用来在契约声明之前初始化 result. 因此, boost::optional 用于推迟 result 的真正初始化, 直到函数体执行之时 (位于契约声明之后), 在那里 Index 已由前置条件验证, 并且 vect[Index] 可以安全地求值以初始化 result.

如 返回值 中所述, 程序员有责任确保 result 总是被设置为返回值 (当函数不抛出异常而退出时). 这也确保 result 总是在检查后置条件之前已被设置, 因此程序员始终可以在后置条件中对 result 进行解引用以访问返回值 (使用 operator* 和 operator->, 如同平常使用 boost::optional 那样, 且无需显式检查 result 是否是一个空的 boost::optional 对象). 做到这一点的方法是确保函数中的 所有 return 语句都形如:

boost::optional<return-type> result;
...
return *(result = return-expression); // Assign `result` at each return.
虚公有函数中的可选结果

类似地, boost::optional 可用于处理传递给虚公有函数 (无论是否纯虚) 契约以及公有函数覆盖契约的返回值. 如 纯虚公有函数、虚公有函数 以及 公有函数覆盖 中所述, 在这些情形下, 返回值 result 必须作为参数传递给 boost::contract::public_function, 位置紧跟在参数 v 之后, 该参数类型为 boost::contract::virtual_*. 然后, 传递给 .postcondition(...) 的仿函数只接受一个类型为 boost::optional<return-type const&> const& 的参数. 例如 (参见 optional_result_virtual.cpp):

template<typename T>
T& accessible<T>::at(unsigned index, boost::contract::virtual_* v) {
    boost::optional<T&> result;
    // Pass `result` right after `v`...
    boost::contract::check c = boost::contract::public_function(v, result, this)
        .precondition([&] {
            BOOST_CONTRACT_ASSERT(index < size());
        })
        // ...plus postconditions take `result` as a parameter (not capture).
        .postcondition([&] (boost::optional<T const&> const& result) {
            BOOST_CONTRACT_ASSERT(*result == operator[](index));
        })
    ;

    assert(false);
    return *result;
}

内层 const& 在后置条件仿函数参数类型 boost::optional<... const&> ... 中是必须的 (而外层 const& 在后置条件仿函数参数类型 boost::optional<...> const& 中则不是).

私有函数与受保护函数

私有函数和受保护函数不检查类不变式 (因为它们不属于类的公有接口), 也不进行子契约 (因为在使用替换原则 的调用点处它们不可访问, 参见 函数调用). 不过, 当程序员想要检查其实现与使用的正确性时 (从类内部、基类、友元类或友元函数等处), 仍可能希望为私有和受保护函数指定前置条件与后置条件. 当程序员决定为私有和受保护函数指定契约时, 可以使用 boost::contract::function (因为与非成员函数一样, 这样做既不检查类不变式, 也不进行子契约). 例如 (参见 private_protected.cpp):

class counter {
protected: // Protected functions use `function()` (like non-members).
    void set(int n) {
        boost::contract::check c = boost::contract::function()
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(n <= 0);
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(get() == n);
            })
        ;

        n_ = n;
    }

private: // Private functions use `function()` (like non-members).
    void dec() {
        boost::contract::old_ptr<int> old_get = BOOST_CONTRACT_OLDOF(get());
        boost::contract::check c = boost::contract::function()
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(
                        get() + 1 >= std::numeric_limits<int>::min());
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(get() == *old_get - 1);
            })
        ;

        set(get() - 1);
    }

    int n_;

    /* ... */

如 非成员函数 中所述的考量同样适用于私有和受保护函数. 如何为私有和受保护的构造函数与析构函数编写契约, 参见 构造函数 与 析构函数 两节.

虚私有函数与虚受保护函数

当私有函数和受保护函数为虚函数时, 它们仍应声明类型为 boost::contract::virtual_* 的额外虚参数, 默认值为 0 (参见 虚公有函数), 即使该参数不必传递给 BOOST_CONTRACT_OLDOF 且 boost::contract::function 也不接受这样的实参 (因此这个额外的虚参数将保持未用, 也不需要名字). [55] 这是必要的, 否则这些私有和受保护的虚函数将无法被派生类中指定契约的公有函数覆盖 (因为 boost::contract::virtual_* = 0 参数必须成为公有函数覆盖签名的一部分). 例如 (参见 private_protected_virtual.cpp):

class counter {
    // Virtual private and protected functions still declare extra
    // `virtual_* = 0` parameter (otherwise they cannot be overridden), but...
protected:
    virtual void set(int n, boost::contract::virtual_* = 0) {
        boost::contract::check c = boost::contract::function() // ...no `v`.
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(n <= 0);
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(get() == n);
            })
        ;

        n_ = n;
    }

private:
    virtual void dec(boost::contract::virtual_* = 0) {
        boost::contract::old_ptr<int> old_get = BOOST_CONTRACT_OLDOF(get()); // ...no `v`.
        boost::contract::check c = boost::contract::function() // ...no `v`.
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(
                        get() + 1 >= std::numeric_limits<int>::min());
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(get() == *old_get - 1);
            })
        ;

        set(get() - 1);
    }

    int n_;

    /* ... */

不过, 派生类中覆盖基类私有或受保护虚函数的公有函数, 不应为 override_... 指定这个额外的 boost::contract::public_function 模板参数, 因为被覆盖的函数是私有的或受保护的, 不是公有的, 因而不参与子契约 (如果指定了 override_..., 本库将产生编译期错误, 因为基类中不存在可供覆盖的虚 public 函数). 例如 (参见 private_protected_virtual.cpp):

class counter10
    #define BASES public counter
    : BASES
{
public:
    typedef BOOST_CONTRACT_BASE_TYPES(BASES) base_types;
    #undef BASES

    // Overriding from non-public members so no subcontracting, no override_...

    virtual void set(int n, boost::contract::virtual_* v = 0) /* override */ {
        boost::contract::check c = boost::contract::public_function(v, this)
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(n % 10 == 0);
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(get() == n);
            })
        ;

        counter::set(n);
    }

    virtual void dec(boost::contract::virtual_* v = 0) /* override */ {
        boost::contract::old_ptr<int> old_get = BOOST_CONTRACT_OLDOF(v, get());
        boost::contract::check c = boost::contract::public_function(v, this)
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(
                        get() + 10 >= std::numeric_limits<int>::min());
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(get() == *old_get - 10);
            })
        ;

        set(get() - 10);
    }

    /* ... */

此外, 使用多重继承时, 可以覆盖在一个基类中为私有或受保护、而在另一个基类中为公有的函数. 此时, 派生类中的公有函数覆盖将为 override_... 指定这个额外的 boost::contract::public_function 模板参数 (因为被覆盖的函数在一个基类中是私有或受保护的, 那些函数不参与子契约; 而在另一个基类中是公有的, 这些函数则参与子契约). 例如 (参见 private_protected_virtual_multi.cpp):

class countable {
public:
    void invariant() const {
        BOOST_CONTRACT_ASSERT(get() <= 0);
    }

    virtual void dec(boost::contract::virtual_* v = 0) = 0;
    virtual void set(int n, boost::contract::virtual_* v = 0) = 0;
    virtual int get(boost::contract::virtual_* v = 0) const = 0;
};

/* ... */


class counter10
    #define BASES public countable, public counter // Multiple inheritance.
    : BASES
{
public:
    typedef BOOST_CONTRACT_BASE_TYPES(BASES) base_types;
    #undef BASES

    // Overriding from public members from `countable` so use `override_...`.

    virtual void set(int n, boost::contract::virtual_* v = 0) /* override */ {
        boost::contract::check c = boost::contract::public_function<
                override_set>(v, &counter10::set, this, n)
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(n % 10 == 0);
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(get() == n);
            })
        ;

        counter::set(n);
    }

    virtual void dec(boost::contract::virtual_* v = 0) /* override */ {
        boost::contract::old_ptr<int> old_get = BOOST_CONTRACT_OLDOF(v, get());
        boost::contract::check c = boost::contract::public_function<
                override_dec>(v, &counter10::dec, this)
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(
                        get() + 10 >= std::numeric_limits<int>::min());
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(get() == *old_get - 10);
            })
        ;

        set(get() - 10);
    }

    BOOST_CONTRACT_OVERRIDES(set, dec)

    /* ... */

警告

遗憾的是, 上面的代码在 MSVC 上无法编译 (至少到 Visual Studio 2015 为止), 因为当 SFINAE 因私有或受保护访问级别而失败时, MSVC 会错误地给出编译期错误. 相反, GCC 和 Clang 正确实现了因私有和受保护函数导致的 SFINAE 失败, 因此上面的代码在 GCC 和 Clang 上可以正确编译. 因此, 目前在使用本库时, 无法在 MSVC 上 (至少到 Visual Studio 2015 为止) 覆盖在一个基类中为公有、而在其他基类中为私有或受保护的函数, 但在 GCC 或 Clang 上则可以正确做到.

友元函数

一般而言, 友元函数不是成员函数, 因此使用 boost::contract::function 来编写其契约, 且 非成员函数 中所作的全部考量均适用. 例如 (参见 friend.cpp):

class buffer;

class byte {
    friend bool operator==(buffer const& left, byte const& right);

private:
    char value_;

    /* ... */


class buffer {
    // Friend functions are not member functions...
    friend bool operator==(buffer const& left, byte const& right) {
        // ...so check contracts via `function` (which won't check invariants).
        boost::contract::check c = boost::contract::function()
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(!left.empty());
                BOOST_CONTRACT_ASSERT(!right.empty());
            })
        ;

        for(char const* x = left.values_.c_str(); *x != '\0'; ++x) {
            if(*x != right.value_) return false;
        }
        return true;
    }

private:
    std::string values_;

    /* ... */

不过, 在某些情况下, 友元函数可能以一个对象作为参数, 并且可以在逻辑上被视为该对象公有接口的扩展 (本质上与该对象的公有函数处于同一层次). 在这些情况下, 程序员可能选择使用 boost::contract::public_function (而不是 boost::contract::function) 来编写友元函数契约, 以便同时检查作为参数传递的对象的类不变式 (而不仅仅是前置条件与后置条件). 例如 (参见 friend_invariant.cpp): [56] 

template<typename T>
class positive {
public:
    void invariant() const {
        BOOST_CONTRACT_ASSERT(value() > 0);
    }

    // Can be considered an extension of enclosing class' public interface...
    friend void swap(positive& object, T& value) {
        boost::contract::old_ptr<T> old_object_value =
                BOOST_CONTRACT_OLDOF(object.value());
        boost::contract::old_ptr<T> old_value = BOOST_CONTRACT_OLDOF(value);
        // ...so it can be made to check invariants via `public_function`.
        boost::contract::check c = boost::contract::public_function(&object)
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(value > 0);
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(object.value() == *old_value);
                BOOST_CONTRACT_ASSERT(value == *old_object_value);
            })
        ;

        T saved = object.value_;
        object.value_ = value;
        value = saved;
    }

private:
    T value_;

    /* ... */

这一技巧也可以扩展到以多个对象作为参数、且可在逻辑上被视为其中每个对象的公有接口之扩展的友元函数. 例如:

// Can be considered an extension of multiple objects' public interfaces.
friend void f(class1& object1, class2* object2, type3& value3) {
    // Check preconditions.
    boost::contract::check pre = boost::contract::function()
        .precondition([&] {
            BOOST_CONTRACT_ASSERT(object2 != nullptr);
            ...
        })
    ;
    // Check class invariants for each object (programmers chose the order).
    boost::contract::check inv1 = boost::contract::public_function(&object1);
    boost::contract::check inv2 = boost::contract::public_function(object2);
    // Check postconditions and exception guarantees.
    boost::contract::check postex = boost::contract::function()
        .postcondition(...)
        .except(...)
    ;

    ... // Function body.
}

改变上面各 boost::contract::check 声明的顺序, 程序员可以选择在传递给友元函数的多个对象之间检查类不变式的顺序, 也可以选择是在友元函数的前置条件、后置条件和异常保证之前还是之后检查这些不变式 (参见 非成员函数 与 公有函数, 了解由 boost::contract::function 与 boost::contract::public_function 返回的 RAII 对象如何检查契约条件). 上面的例子编写为先检查 class1 的不变式、后检查 class2 的不变式 (但如果程序员选择, 该顺序也可以反过来).

注释

在上面的例子中, 前置条件被有意编写为在类不变式之前检查, 以便传给友元函数的对象在作为指针传递给 boost::contract::public_function 之前先由前置条件验证 (例如检查 object2 非空). (而在成员函数中, 对象指针 this 总是良构的, 永远不需要验证它, 且 boost::contract::public_function 会先检查类不变式再检查前置条件, 因此编写前置条件时可以假定类不变式已经满足而加以简化, 参见 公有函数调用. )

函数重载

将本库用于重载函数或重载构造函数时无需特别注意. 唯一的例外是公有函数覆盖传递给 boost::contract::public_function 的函数指针 (参见 公有函数覆盖). 当公有函数覆盖的名字本身也被重载时, 编译器无法自动推导相关的函数指针, 因此程序员必须使用 static_cast 来消歧 (与 C++ 中指向重载函数的指针的惯常做法一样). [57] 例如, 注意 static_cast 在下面这些对 boost::contract::public_function 的调用中是如何使用的 (参见 overload.cpp):

class string_lines
    #define BASES public lines
    : BASES
{
public:
    typedef BOOST_CONTRACT_BASE_TYPES(BASES) base_types;
    #undef BASES

    BOOST_CONTRACT_OVERRIDES(str) // Invoked only once for all `str` overloads.

    std::string str(boost::contract::virtual_* v = 0) const /* override */ {
        std::string result;
        boost::contract::check c = boost::contract::public_function<
                override_str>(
            v, result,
            // `static_cast` resolves overloaded function pointer ambiguities.
            static_cast<std::string (string_lines::*)(
                    boost::contract::virtual_*) const>(&string_lines::str),
            this
        );

        return result = str_;
    }

    // Overload on (absence of) `const` qualifier.
    std::string& str(boost::contract::virtual_* v = 0) /* override */ {
        boost::contract::check c = boost::contract::public_function<
                override_str>(
            v, str_,
            // `static_cast` resolves overloaded function pointer ambiguities.
            static_cast<std::string& (string_lines::*)(
                    boost::contract::virtual_*)>(&string_lines::str),
            this
        );

        return str_;
    }

    BOOST_CONTRACT_OVERRIDES(put) // Invoked only once for all `put` overloads.

    void put(std::string const& x,
            boost::contract::virtual_* v = 0) /* override */ {
        boost::contract::old_ptr<std::string> old_str =
                BOOST_CONTRACT_OLDOF(v, str());
        boost::contract::check c = boost::contract::public_function<
                override_put>(
            v,
            // `static_cast` resolves overloaded function pointer ambiguities.
            static_cast<void (string_lines::*)(std::string const&,
                    boost::contract::virtual_*)>(&string_lines::put),
            this, x
        )
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(str() == *old_str + x + '\n');
            })
        ;

        str_ = str_ + x + '\n';
    }

    // Overload on argument type.
    void put(char x, boost::contract::virtual_* v = 0) /* override */ {
        boost::contract::old_ptr<std::string> old_str =
                BOOST_CONTRACT_OLDOF(v, str());
        boost::contract::check c = boost::contract::public_function<
                override_put>(
            v,
            // `static_cast` resolves overloaded function pointer ambiguities.
            static_cast<void (string_lines::*)(char,
                    boost::contract::virtual_*)>(&string_lines::put),
            this, x
        )
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(str() == *old_str + x + '\n');
            })
        ;

        str_ = str_ + x + '\n';
    }

    // Overload on argument type and arity (also with default parameter).
    void put(int x, bool tab = false,
            boost::contract::virtual_* v = 0) /* override */ {
        boost::contract::old_ptr<std::string> old_str =
                BOOST_CONTRACT_OLDOF(v, str());
        boost::contract::check c = boost::contract::public_function<
                override_put>(
            v,
            // `static_cast` resolves overloaded function pointer ambiguities.
            static_cast<void (string_lines::*)(int, bool,
                    boost::contract::virtual_*)>(&string_lines::put),
            this, x, tab
        )
            .postcondition([&] {
                std::ostringstream s;
                s << x;
                BOOST_CONTRACT_ASSERT(
                        str() == *old_str + (tab ? "\t" : "") + s.str() + '\n');
            })
        ;

        std::ostringstream s;
        s << str_ << (tab ? "\t" : "") << x << '\n';
        str_ = s.str();
    }

private:
    std::string str_;
};

重载函数拥有相同的函数名, 因此在给定类中, 同一个 override_function-name 类型可以作为所有 boost::contract::public_function 调用的模板参数重复使用. 因此, 对于给定类中的一个函数名, 即使该函数名被重载, BOOST_CONTRACT_OVERRIDE 也只需调用一次.

Lambda 表达式、循环、代码块 (及 constexpr)

契约通常最有用于编写函数与类接口的规约, 但本库也允许为实现代码 (lambda 函数、循环、代码块等) 检查契约条件.

Lambda 函数不是成员函数, 不属于类的公有接口, 因此它们不检查类不变式, 也不进行子契约. 它们可以使用 boost::contract::function 来指定前置条件、后置条件和异常保证 (在 非成员函数 中所作的考量均适用). 例如 (参见 lambda.cpp):

int total = 0;
std::for_each(v.cbegin(), v.cend(),
    // Contract for a lambda function.
    [&total] (int const x) {
        boost::contract::old_ptr<int> old_total =
                BOOST_CONTRACT_OLDOF(total);
        boost::contract::check c = boost::contract::function()
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(
                        total < std::numeric_limits<int>::max() - x);
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(total == *old_total + x);
            })
        ;

        total += x; // Lambda function body.
    }
);

类似地, boost::contract::function 可用于为循环编写前置条件、后置条件和异常保证. 例如, 可用于 for 循环, while 循环及其他所有循环同理 (参见 loop.cpp):

int total = 0;
// Contract for a for-loop (same for while- and all other loops).
for(std::vector<int>::const_iterator i = v.begin(); i != v.end(); ++i) {
    boost::contract::old_ptr<int> old_total = BOOST_CONTRACT_OLDOF(total);
    boost::contract::check c = boost::contract::function()
        .precondition([&] {
            BOOST_CONTRACT_ASSERT(
                    total < std::numeric_limits<int>::max() - *i);
        })
        .postcondition([&] {
            BOOST_CONTRACT_ASSERT(total == *old_total + *i);
        })
    ;

    total += *i; // For-loop body.
}

更一般地, boost::contract::function 可用于为给定函数中的任意代码块编写前置条件、后置条件和异常保证. 例如 (参见 code_block.cpp):

/* ... */

// Contract for a code block.
{ // Code block entry (check preconditions).
    boost::contract::old_ptr<int> old_total = BOOST_CONTRACT_OLDOF(total);
    boost::contract::check c = boost::contract::function()
        .precondition([&] {
            BOOST_CONTRACT_ASSERT(v.size() == 3);
        })
        .postcondition([&] {
            BOOST_CONTRACT_ASSERT(total == *old_total + v[0] + v[1] + v[2]);
        })
    ;

    total += v[0] + v[1] + v[2]; // Code block body.
} // Code block exit (check postconditions and exceptions guarantees).

/* ... */

本库不支持为以 constexpr 声明的函数和类提供契约. [58]

实现检查

本库还提供了一种在实现代码内部检查断言的机制 (不同于前置条件、后置条件、异常保证和类不变式——那些是在实现函数体的代码之前或之后检查的). 这些实现检查通过一个零元仿函数编写, 该仿函数直接赋给一个 boost::contract::check 对象声明, 位置就在代码中需要执行这些检查的地方 (此情况下无需调用 boost::contract::function、boost::contract::public_function 等). 例如 (参见 check.cpp):

int main() {
    // Implementation checks (via nullary functor).
    boost::contract::check c = [] {
        BOOST_CONTRACT_ASSERT(gcd(12, 28) == 4);
        BOOST_CONTRACT_ASSERT(gcd(4, 14) == 2);
    };

    return 0;
}

实现检查仿函数应当捕获其断言所需的全部变量. 当复制这些变量的开销可以接受时, 可以按值捕获这些变量. 无论如何, 程序员都不应编写会修改被捕获变量值的实现检查, 即使这些变量是按引用捕获的 (参见 常量正确性).

实现检查仿函数中可以编写任何代码, 但建议保持这段代码简单, 主要使用断言和 if 语句 (避免编写复杂的检查——它们可能有缺陷, 并且在运行期检查起来也慢). 还建议使用 BOOST_CONTRACT_ASSERT 来编写断言, 因为这样当被断言的条件求值为假时, 本库能够打印信息丰富的错误消息 (注意这不是可变参数宏, 参见 不使用宏):

BOOST_CONTRACT_ASSERT(boolean-condition)
// Or, if `boolean-condition` contains commas `,` not already within parenthesis `()`...
BOOST_CONTRACT_ASSERT((boolean-condition)) // ...use extra parenthesis (not a variadic macro).

如果 boost::contract::check_failure 的任一条件为假, 或者更一般地, 调用实现检查仿函数时抛出了任何异常, 本库将自动调用失败处理器 BOOST_CONTRACT_ASSERT. 默认情况下, 该失败处理器向 std::cerr 打印错误消息, 并调用 std::terminate 终止程序 (参见 失败时抛出异常 以把失败处理器改为抛出异常、以错误码退出程序等).

与 C 风格的 assert 宏类似 (该宏在定义 NDEBUG 时被禁用), 实现检查在定义 BOOST_CONTRACT_NO_CHECKS 时被禁用 (参见 禁用契约检查). 这会在运行期跳过全部实现检查, 但并不能消除执行和编译相关 boost::contract::check 声明的一部分开销. 或者, 本库提供了 BOOST_CONTRACT_CHECK 宏, 在定义了 BOOST_CONTRACT_NO_CHECKS 时, 它可以完全消除实现检查的运行期和编译期开销 (注意这不是可变参数宏):

BOOST_CONTRACT_CHECK(boolean-condition)
// Or, if `boolean-condition` contains commas `,` not already within parenthesis `()`...
BOOST_CONTRACT_CHECK((boolean-condition)) // ...use extra parenthesis (not a variadic macro).

例如 (参见 check_macro.cpp):

int main() {
    // Implementation checks (via macro, disable run-/compile-time overhead).
    BOOST_CONTRACT_CHECK(gcd(12, 28) == 4);
    BOOST_CONTRACT_CHECK(gcd(4, 14) == 2);

    return 0;
}

BOOST_CONTRACT_CHECK 宏类似于 C 风格的 assert 宏, 因为它接受的是布尔条件 (而不是像 boost::contract::check 那样的零元仿函数). [59] 使用 BOOST_CONTRACT_CHECK 在本质上等同于使用 C 风格的 assert 宏, 除以下几点之外:

  • 实现检查通过定义 BOOST_CONTRACT_NO_CHECKS 来禁用 (而要禁用 NDEBUG, 则定义 assert).
  • 如果被断言的布尔条件为假, 或者其求值抛出异常, 那么本库将调用 boost::contract::check_failure (而 assert 在被断言的条件为假时调用 std::abort, 并且在条件求值抛出异常时展开栈).
  • 当使用本库指定的其他契约条件正在被检查时, 实现检查会被自动禁用 (以避免无限递归, 参见 BOOST_CONTRACT_ALL_DISABLE_NO_ASSERTION):

在函数体处复制的旧值

在前文示例中, 类型为 boost::contract::old_ptr 的旧值变量一经声明就立即初始化为传递给 BOOST_CONTRACT_OLDOF 的表达式的一个副本. 这确实发生在函数体执行之前, 但也在契约声明之前, 因此在函数入口处对类不变式 (对于公有函数) 和前置条件的检查之前也已完成. 在大多数实际情况下这也许工作良好, 但严格来说, 旧值应当在执行函数体之前复制, 却要在函数入口处检查类不变式和前置条件之后再进行 (参见 断言). 具体而言, 可能存在这样的情形: 只有在假定类不变式和前置条件中编写的断言为真时, 求值传递给 BOOST_CONTRACT_OLDOF 的表达式才有意义.

本库允许使用默认构造函数 (等价于空指针) 构造 boost::contract::old_ptr 变量, 然后再把它们赋值为由 BOOST_CONTRACT_OLDOF 在传递给 d() 的零元仿函数 .old(d) 中所指定表达式的一个副本. 本库会在函数体执行之前调用仿函数 d(), 但只会在类不变式和前置条件检查之后. 当这些条件都存在时, 通过 .old(...) 进行的旧值赋值必须位于前置条件之后、后置条件和异常保证之前 (参见 前置条件、后置条件 和 异常保证). [60]

例如, 下面传递给 s[index] 的旧值表达式 BOOST_CONTRACT_OLDOF 只有在前置条件检查了 index 位于有效范围 index < s.size() 之内后才有效. 因此, old_char 先用其默认构造函数声明 (即初始化为空指针), 然后再赋值为 s[index] 的副本, 赋值位置在 .old(...) 中, 且在前置条件检查了 index 之后进行 (参见 old.cpp):

char replace(std::string& s, unsigned index, char x) {
    char result;
    boost::contract::old_ptr<char> old_char; // Null, old value copied later...
    boost::contract::check c = boost::contract::function()
        .precondition([&] {
            BOOST_CONTRACT_ASSERT(index < s.size());
        })
        .old([&] { // ...after preconditions (and invariants) checked.
            old_char = BOOST_CONTRACT_OLDOF(s[index]);
        })
        .postcondition([&] {
            BOOST_CONTRACT_ASSERT(s[index] == x);
            BOOST_CONTRACT_ASSERT(result == *old_char);
        })
    ;

    result = s[index];
    s[index] = x;
    return result;
}

传递给 .old(...) 的仿函数应当捕获它对求值传递给 BOOST_CONTRACT_OLDOF 的旧值表达式所需的全部变量. 一般而言, 这些变量应按引用捕获而不是按值捕获 (因为旧值需要复制的是被捕获变量在即将执行函数体之前所具有的值, 而不是传递给 .old(...) 的仿函数首次声明时这些变量所具有的值). 无论如何, 程序员编写的传递给 .old(...) 的仿函数应只修改旧值, 而不修改其他被捕获变量的值, 即使那些变量是按引用捕获的 (参见 常量正确性).

如果调用通过 boost::contract::old_failure 指定的仿函数时抛出了异常, 本库将自动调用失败处理器 .old(...) (默认情况下, 该处理器向 std::cerr 打印错误消息, 并调用 std::terminate 终止程序, 但参见 失败时抛出异常 以抛出异常、以错误码退出程序等).

注释

如果旧值指针在其构造点直接初始化而不使用 .old(...), 那么传递给 BOOST_CONTRACT_OLDOF 的旧值表达式抛出的异常, 或者更一般地, 旧值指针初始化抛出的任何异常, 都会导致该异常由外围函数沿栈向上抛出. 可以说这不如调用 boost::contract::old_failure 正确, 因为旧值副本抛出的异常会导致程序无法检查其后置条件和异常保证, 但不应自动导致外围函数抛出异常 (实践中这可能不是显著的差别, 但这可以是在契约之前声明旧值时使用 .old(...) 而非在声明处赋旧值的另一个理由). [61]

命名覆盖

如 公有函数覆盖 中所述, 必须使用宏 BOOST_CONTRACT_OVERRIDE 来声明类型 override_..., 公有函数覆盖会把它作为显式模板参数传递给 boost::contract::public_function. 传递给 BOOST_CONTRACT_OVERRIDE (以及 BOOST_CONTRACT_OVERRIDES) 的函数名绝不应以下划线开头, 以免生成包含双下划线的名字 override__... (因为 C++ 标准中所有包含双下划线 ...__... 的符号都是保留符号). 另有一个单独的宏 BOOST_CONTRACT_NAMED_OVERRIDE, 可用于显式指定所声明类型的名字: [62] 

BOOST_CONTRACT_OVERRIDE(function-name)                  // Generate `override_...`.
BOOST_CONTRACT_NAMED_OVERRIDE(type-name, function-name) // Generate `type-name`.

例如, 下面的公有函数覆盖命名为 _1, 因此 BOOST_CONTRACT_OVERRIDE(_1) 将声明一个名为 override__1 的类型 (该名字是 C++ 保留符号, 因为它包含双下划线 __), 所以改用 BOOST_CONTRACT_NAMED_OVERRIDE(override1, _1) 把类型命名为 override1 (参见 named_override.cpp):

template<typename T>
class positive_unary_pack
    #define BASES public generic_unary_pack<T>
    : BASES
{
public:
    typedef BOOST_CONTRACT_BASE_TYPES(BASES) base_types;
    #undef BASES

    // BOOST_CONTRACT_OVERRIDE(_1) would generate reserved name `override__1`.
    BOOST_CONTRACT_NAMED_OVERRIDE(override1, _1) // Generate `override1`.

    virtual void _1(T const& value, boost::contract::virtual_* v = 0)
            /* override */ {
        // Use `override1` generated by BOOST_CONTRACT_NAMED_OVERRIDE above.
        boost::contract::check c = boost::contract::public_function<override1>(
            v,
            static_cast<void (positive_unary_pack::*)(T const&,
                    boost::contract::virtual_*)>(&positive_unary_pack::_1),
            this,
            value
        )
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(value > 0);
            })
        ;
        value1_ = value;
    }

    /* ... */

宏 BOOST_CONTRACT_NAMED_OVERRIDE 也可用于: 当名字 override_... (由 BOOST_CONTRACT_OVERRIDE 生成) 会与用户代码中的其他名字冲突时、需要生成 CamelCase 或其他任意偏好风格的名字时, 以及任何程序员需要或偏好生成不同于 override_... 的名字的情形.

注意, 并不存在 BOOST_CONTRACT_NAMED_OVERRIDES 宏, 因此需要对每个函数名分别调用 BOOST_CONTRACT_NAMED_OVERRIDE (不过存在一个 BOOST_CONTRACT_OVERRIDES 宏, 如 公有函数覆盖 中所示). [63]

访问说明符

如前文所示, 本库要求程序员通过声明以下额外成员来修饰其类:

  • 成员函数 invariant 与 static_invariant (用于检查类不变式, 参见 类不变式).
  • base_types 成员 typedef 经由 BOOST_CONTRACT_BASE_TYPES 声明 (用于实现子契约, 参见 公有函数覆盖).
  • override_... 成员类型 (经由 BOOST_CONTRACT_OVERRIDE、BOOST_CONTRACT_NAMED_OVERRIDE 和 BOOST_CONTRACT_OVERRIDES 声明, 用于为覆盖函数实现子契约, 参见 公有函数覆盖). [64]

一般而言, 这些成员必须在用户类中声明为 public, 本库才能访问它们. [65] 不过, 程序员可能需要更精确地控制其类的公有成员, 以防止对封装成员的错误访问. 所有这些成员都可以声明为 private, 只要把 boost::contract::access 类声明为用户类的 friend. 例如 (参见 access.cpp):

template<typename T>
class vector
    #define BASES public pushable<T>
    : BASES
{ // Private section of the class.
    friend class boost::contract::access; // Friend `access` class so...

    typedef BOOST_CONTRACT_BASE_TYPES(BASES) base_types; // ...private bases.
    #undef BASES

    void invariant() const { // ...private invariants.
        BOOST_CONTRACT_ASSERT(size() <= capacity());
    }

    BOOST_CONTRACT_OVERRIDE(push_back) // ...private overrides.

public: // Public section of the class.
    void push_back(T const& value, boost::contract::virtual_* v = 0)
            /* override */ {
        boost::contract::old_ptr<unsigned> old_size =
                BOOST_CONTRACT_OLDOF(v, size());
        boost::contract::check c = boost::contract::public_function<
                override_push_back>(v, &vector::push_back, this, value)
            .precondition([&] {
                BOOST_CONTRACT_ASSERT(size() < max_size());
            })
            .postcondition([&] {
                BOOST_CONTRACT_ASSERT(size() == *old_size + 1);
            })
        ;

        vect_.push_back(value);
    }

    /* ... */

本文档的大多数示例只是为了简洁而未使用这一技巧. 鼓励程序员在实际生产代码中按需自由使用 boost::contract::access.

警告

如果不把 boost::contract::access 声明为用户类的友元, 在某些编译器上 (如 MSVC) 可能导致编译错误, 因为检查契约所需的私有成员将不可访问. 在其他编译器上 (如 GCC 和 Clang), 私有访问级别反而会导致 SFINAE 失败, 不报告编译错误, 而不变式与子契约会在运行期被静默跳过. 因此, 程序员应始终确保要么把不变式函数和基类型 typedef 声明为公有成员, 要么把 boost::contract::access 声明为友元.

失败时抛出异常 (及 noexcept)

如果使用 BOOST_CONTRACT_ASSERT 检查的条件求值为假, 或者更一般地, 指定的任何契约代码抛出了异常 (BOOST_CONTRACT_ASSERT 只是展开为抛出 boost::contract::assertion_failure 异常的代码, 参见 不使用宏), 本库将按如下方式调用相应的契约失败处理器 函数:

  • 前置条件: BOOST_CONTRACT_ASSERT 断言为假, 以及 .precondition(...) 内部抛出的异常, 将调用 boost::contract::precondition_failure.
  • 后置条件: BOOST_CONTRACT_ASSERT 断言为假, 以及 .postcondition(...) 内部抛出的异常, 将调用 boost::contract::postcondition_failure.
  • 异常保证: BOOST_CONTRACT_ASSERT 断言为假, 以及 .except(...) 内部抛出的异常, 将调用 boost::contract::except_failure.
  • 类不变式: BOOST_CONTRACT_ASSERT 断言为假, 以及从 invariant() 和 static_invariant() 抛出的异常, 将在函数入口处检查时调用 boost::contract::entry_invariant_failure, 在函数出口处检查时调用 boost::contract::exit_invariant_failure.
  • 在函数体处复制的旧值: 在 .old(...) 中从函数体处复制的旧值抛出的异常, 将调用 boost::contract::old_failure.
  • 实现检查: BOOST_CONTRACT_ASSERT 断言为假, 以及从实现检查 boost::contract::check c = nullary-functor 和 BOOST_CONTRACT_CHECK(...) 抛出的异常, 将调用 boost::contract::check_failure.

默认情况下, 这些契约失败处理器向标准错误 std::cerr 打印一条消息, 然后调用 std::terminate 终止程序. [66] 不过, 程序员可以使用以下各函数分别覆盖默认的契约失败处理器, 以便在契约失败时执行任何自定义操作:

  • 前置条件: boost::contract::set_precondition_failure.
  • 后置条件: boost::contract::set_postcondition_failure.
  • 异常保证: boost::contract::set_except_failure.
  • 类不变式: boost::contract::set_entry_invariant_failure 与 boost::contract::set_exit_invariant_failure, 或 boost::contract::set_invariant_failure (为方便起见, 一次性设置入口和出口不变式失败处理器).
  • 在函数体处复制的旧值: boost::contract::set_old_failure.
  • 实现检查: boost::contract::set_check_failure.

这些 set_..._failure(f) 函数调用返回它们所接受的输入参数——契约失败处理器仿函数 f 的引用 (因此可以链式连接). [67] 例如 (参见 throw_on_failure.cpp):

int main() {
    boost::contract::set_precondition_failure(
    boost::contract::set_postcondition_failure(
    boost::contract::set_invariant_failure(
    boost::contract::set_old_failure(
        [] (boost::contract::from where) {
            if(where == boost::contract::from_destructor) {
                // Shall not throw from C++ destructors.
                std::clog << "ignored destructor contract failure" << std::endl;
            } else throw; // Re-throw (assertion_failure, user-defined, etc.).
        }
    ))));
    boost::contract::set_except_failure(
        [] (boost::contract::from) {
            // Already an active exception so shall not throw another...
            std::clog << "ignored exception guarantee failure" << std::endl;
        }
    );
    boost::contract::set_check_failure(
        [] {
            // But now CHECK shall not be used in destructor implementations.
            throw; // Re-throw (assertion_failure, user-defined, etc.).
        }
    );

    /* ... */

在编写抛出异常而非终止程序的自定义失败处理器时, 程序员应注意以下几点:

  • 为了符合 C++ 与 STL 的异常安全, 析构函数绝不应抛出异常 (实际上自 C++11 起, 析构函数被隐式声明为 noexcept). 本库向用于前置条件、后置条件、类不变式以及在函数体处复制的旧值的契约失败处理器传递一个 boost::contract::from 参数 (分别参见 boost::contract::precondition_failure、boost::contract::postcondition_failure、boost::contract::entry_invariant_failure、boost::contract::exit_invariant_failure 和 boost::contract::old_failure 各节). 这个 boost::contract::from 参数表明契约失败是发生在析构函数、构造函数还是函数调用中, 因此程序员可以用它来编写绝不会从析构函数抛出异常的自定义契约失败处理器函数. (在上面的示例中, 来自析构函数的契约失败被简单地忽略——尽管在实际生产代码中这样做很可能永远都不安全. )
  • 即使在派生类析构函数抛出异常时, C++ 的栈展开也会执行基类析构函数. 因此, 当契约失败处理器被编写为在来自析构函数的契约失败时抛出异常的情况下, 基类析构函数的契约仍将继续被检查 (这也是不要从析构函数抛出异常的又一个理由——即使是因为契约失败也不要抛).
  • 用于异常保证的契约失败处理器 boost::contract::except_failure 绝不应抛出异常 (无论其 boost::contract::from 参数取何值), 因为在调用 boost::contract::except_failure 时栈上已经有一个活动异常——即最初触发异常保证检查的那个异常 (在已有活动异常的情况下再抛出异常, 将强制程序终止或在 C++ 中导致未定义行为).
  • 实现检查可以出现在任何代码中, 包括析构函数的实现代码, 因此 boost::contract::check_failure 也绝不应抛出异常, 否则就不要在析构函数中使用实现检查——不然这些析构函数将抛出异常 (注意 boost::contract::check_failure 不提供 boost::contract::from 参数, 因此无法区分实现检查是因析构函数失败还是因代码的其他部分失败).
注释

当程序员编写的自定义契约失败处理器抛出异常而非终止程序时, 他们需要决定如何处理来自析构函数的契约失败 (考虑到 C++ 和 STL 的异常安全规则要求析构函数绝不抛出异常). 这不是一个简单的两难问题, 在 C++ 中断言失败时终止程序而非抛出异常也许是个好理由 (本库以及 C 风格的 assert 默认都是如此).

抛出用户自定义异常

契约断言可以被编写为使用 boost::contract::assertion_failure 来抛出 BOOST_CONTRACT_ASSERT(condition), 如前文所示 (参见 不使用宏). 或者, 契约断言也可以被编写为抛出任何其他异常 (包括用户自定义异常), 所用代码类似如下:

if(!condition) throw exception-object;

例如, 下面的前置条件仿函数在其第一个断言处抛出 boost::contract::assertion_failure (经由 BOOST_CONTRACT_ASSERT), 在其第二个断言处抛出用户自定义异常 too_large_error (这两个异常都会使本库调用上面列出的自定义 boost::contract::precondition_failure, 该处理器继而把这些异常沿栈向上重新抛出, 参见 throw_on_failure.cpp):

struct too_large_error {};

template<unsigned MaxSize>
class cstring
    #define BASES private boost::contract::constructor_precondition<cstring< \
            MaxSize> >
    : BASES
{


public:
    /* implicit */ cstring(char const* chars) :
        boost::contract::constructor_precondition<cstring>([&] {
            BOOST_CONTRACT_ASSERT(chars); // Throw `assertion_failure`.
            // Or, throw user-defined exception.
            if(std::strlen(chars) > MaxSize) throw too_large_error();
        })
    {


    /* ... */
};

异常说明符 (noexcept 与 throw`)

声明契约的外围函数、构造函数或析构函数的异常说明符 noexcept (C++11 起引入) 和 throw (在 C++11 中已弃用) 同样正确适用于契约代码. 因此, 即使契约失败处理器被重新编写为在契约失败时抛出异常, 如果不符合同一操作的异常说明符, 这些异常也绝不会在该外围操作的上下文之外抛出 (具体而言, 注意所有析构函数在 C++11 中都被隐式声明为 noexcept).

例如, 下面的代码将正确地永远不从 noexcept 析构函数抛出异常——即使析构函数入口处检查的类不变式抛出 too_large_error, 且用于不变式的契约失败处理器被编写为从析构函数抛出异常也是如此 (此情形下程序将总是终止, 参见 throw_on_failure.cpp):

struct too_large_error {};

template<unsigned MaxSize>
class cstring
    #define BASES private boost::contract::constructor_precondition<cstring< \
            MaxSize> >
    : BASES
{


public:
    void invariant() const {
        if(size() > MaxSize) throw too_large_error(); // Throw user-defined ex.
        BOOST_CONTRACT_ASSERT(chars_); // Or, throw `assertion_failure`.
        BOOST_CONTRACT_ASSERT(chars_[size()] == '\0');
    }

    ~cstring() noexcept { // Exception specifiers apply to contract code.
        // Check invariants.
        boost::contract::check c = boost::contract::destructor(this);
    }


    /* ... */
};


/* ... */

// Warning... might cause destructors to throw (unless declared noexcept).
boost::contract::set_invariant_failure(
    [] (boost::contract::from) {
        throw; // Throw no matter if from destructor, etc.
    }
);

/* ... */

[57] 设计理由: 为避免复制, 当在公有函数覆盖中使用时, 本库把传递给 boost::contract::public_function 的所有函数实参和返回值都作为引用来接受. 因此, 本库无法区分实际的函数实参类型和返回类型何时按引用传递、何时不按引用传递. 结果是, 本库无法自动重构外围公有函数的类型, 所以该类型必须从程序员传递给 boost::contract::public_function 的函数指针推导出来. 当因函数名重载而无法自动推导时, 程序员必须像 C++ 中处理指向重载函数的指针时惯常的做法那样, 显式使用 static_cast 来消歧.

[58] 设计理由: 一般而言, 为 constexpr 函数和字面值类 (literal class) 指定契约可能有用. 然而, 本库当前实现无法支持 constexpr 函数和类的契约, 因为 C++ 目前不允许 constexpr 函数做以下事情: 声明具有非平凡 constexpr 析构函数的 (字面值) 类型的局部变量 (本库用这一 RAII 技巧在出口处检查不变式、后置条件和异常保证); 用 try-catch 语句调用其他 constexpr 函数 (本库用它报告契约断言失败, 并捕获对被断言条件求值时可能抛出的任何其他异常); 使用 lambda 函数 (本库为方便起见用它编写检查前置条件、后置条件和异常保证的仿函数). 另需注意, 即使受支持, constexpr 函数的契约很可能也不会使用旧值 (因为 constexpr 阻止函数产生任何对调用者可见的副作用, 而记录这类副作用的变量通常正是旧值副本的候选对象), 也不会有子契约 (因为 constexpr 函数不能是虚函数).

BOOST_CONTRACT_CHECK([&] -> bool {
    if(even_numbers) return gcd(x, y) == 2;
    else return gcd(x, y) == 3;
} ());
