本节展示如何设置并开始使用本库.

本文档

程序员读完引言、入门 和 教程 之后, 就应当能够开始使用本库. 本文档的其他章节 (例如 高级主题 和 附加内容) 可以在稍后查阅, 以更深入地了解本库. 已经熟悉契约式编程方法学的程序员可以跳过 契约式编程概述.

本文档列出的部分源代码包含形如 //[... 和 //] 的特殊代码注释. 它们标记的代码段会被自动从源代码中提取出来, 作为本文档的一部分呈现. [5] 需要指出, 本文档所有示例的目的都是说明如何使用本库, 而不是展示真实的生产代码.

部分脚注标有 "设计理由" 字样. 它们解释本库设计和实现过程中的一些决策.

编译器与平台

总体而言, 本库要求 C++ 编译器对 SFINAE 以及 C++03 标准支持的其他模板元编程技术有健全的实现. 可以在不使用 C++11 lambda 函数的情况下使用本库, 但需要大量样板代码来手动编写独立的仿函数以指定前置条件、后置条件等 (因此, 不使用 C++11 lambda 函数使用本库是可行的, 但不推荐, 参见 不使用 lambda 函数 一节). 也可以在不使用可变参数宏的情况下使用本库, 只需手动编写少量样板代码 (不过大多数乃至所有现代 C++ 编译器早在 C++99 和 C++11 之前就支持可变参数宏, 因此实践中绝不应有此需要, 参见 不使用宏 一节).

本文档的部分内容使用语法 type-of(...) 来表示一个在逻辑上等价于 C++11 decltype(...) 的运算符. 不过, 本库实现实际上并没有在这些情况下使用类型推导 (因为库内部已经知道所涉类型), 因此并不真正需要支持 C++11 decltype 或其他 type-of 实现 (这就是本文档使用 type-of 而不是真正的 decltype 运算符的原因).

本库使用以下环境开发和测试:

  • Windows 上的 Visual Studio 2015 (MSVC cl 版本 19.00.24215.1).
  • Cygwin 上的 GCC 5.4.0 (启用 C++11 特性 -std=c++11).
  • Cygwin 上的 Clang 3.8.1 (启用 C++11 特性 -std=c++11).

关于其他编译器和平台的信息, 参见本库的回归测试. 本库的开发与维护托管于 GitHub.

代码组织

设 boost-root 为安装 Boost 源文件的目录. 本库文件的组织如下:

boost-root/libs/contract        # Directory where this library files are.
    build/                      # Build files (using BJam).
    doc/                        # Documentation (using Boost.QuickBook).
    example/                    # Examples (also those listed in this documentation).
    include/                    # DO NOT USE: Use copies of these files from
        boost/                  # boost-root/boost/ instead:
            contract.hpp        #   - Include all headers at once.
            contract_macro.hpp  #   - Include library macro interface.
            contract/           #   - Header files that can be included one-by-one.
                core/           #   - Fundamental headers (usually indirectly included by other headers).
                detail/         #   - Implementation code (should never be included or used directly).
    src/                        # Library source code to be compiled.
    test/                       # Tests.

本库所需的全部头文件可以通过以下方式一次性包含:

#include <boost/contract.hpp>

或者, 在使用本库宏接口时通过以下方式 (参见 禁用契约编译):

#include <boost/contract_macro.hpp>

另外, 所有 boost/contract/*.hpp 头文件彼此独立, 可以根据所用的本库具体功能逐个选择性地包含 (但实测表明这在编译期不会带来可感知的差别, 因此大多数情况下可以直接包含 boost/contract.hpp). boost/contract/core/*.hpp 头文件则不独立于其他头文件; 当已经包含了 boost/contract.hpp 或 boost/contract/*.hpp 头文件时, 用户代码无需直接包含它们.

下 boost/contract/detail/ 目录下的所有文件、boost::contract::detail 命名空间中的名字、以 BOOST_CONTRACT_DETAIL... 开头的宏, 以及所有以 boost_contract_detail... 开头的名字 (在任何命名空间中, 包括用户自定义命名空间) 都属于本库实现, 绝不应在用户代码中直接使用. 以 BOOST_CONTRACT_ERROR... 开头的名字被本库用于报告某些编译期错误 (因此在编译器错误消息中发现这些名字可能有助于排障).

构建

设 boost-root 为安装 Boost 源文件的目录. 本库作为 Boost 的一部分, 使用 BJam 安装和编译.

警告

强烈建议在构建 Boost 时定义 BOOST_ALL_DYN_LINK 宏 (或至少 BOOST_CONTRACT_DYN_LINK), 把本库编译为共享库 (即动态链接库, DLL) 来使用. 使用 BJam 构建 Boost 时, 可以通过 link=shared 参数做到这一点 (这已是默认值, 所以 bjam 实际上无需额外参数).

也可以把本库编译为静态库使用 (通过定义 BOOST_CONTRACT_STATIC_LINK 宏), 或作为仅头文件库使用 (让 BOOST_CONTRACT_DYN_LINK 和 BOOST_CONTRACT_STATIC_LINK 都保持未定义). 不过, 在这些情况下不保证本库始终正确工作. 具体而言, 当本库跨不同程序单元使用时 (不同程序、同一程序中的不同共享库等), 除非把它编译为共享库, 否则它可能无法在检查其他契约期间正确禁用契约, 也可能无法调用正确的用户自定义契约失败处理器.

基于 Linux 的系统

例如, 构建包括本库在内的所有 Boost 库 (构建为共享库; 另参见 Boost 文档):

$ cd boost-root
$ ./bootstrap.sh
$ ./bjam

编译并运行 boost-root/libs/contract/example/features/introduction.cpp 示例:

$ cd boost-root/libs/contract/example
$ ../../../bjam features-introduction

编译并运行本库的全部测试 (这可能需要一段时间):

$ cd boost-root/libs/contract/test
$ ../../../bjam

在不使用 BJam 的情况下编译并运行使用本库的代码 (Clang 类似):

$ cd /tmp
$ g++ -std=c++11 -D BOOST_CONTRACT_DYN_LINK -I boost-root boost-root/stage/lib/system-prefixboost_contract.dll boost-root/libs/contract/example/features/introduction.cpp -o introduction
$ export PATH=$PATH:boost-root/stage/lib
$ ./introduction
基于 Windows 的系统

例如, 构建包括本库在内的所有 Boost 库 (构建为 DLL; 另参见 Boost 文档):

>cd boost-root
>bootstrap.bat
>bjam

编译并运行 boost-root/libs/contract/example/features/introduction.cpp 示例:

>cd boost-root\libs\contract\example
>..\..\..\bjam features-introduction

编译并运行本库的全部测试 (这可能需要一段时间):

>cd boost-root\libs\contract\test
>..\..\..\bjam

在不使用 BJam 的情况下编译并运行使用本库的代码:

>cd C:\Temp
>cl /MDd /EHs /std:c++11 /D BOOST_CONTRACT_DYN_LINK /I boost-root /link /DLL /LIBPATH:boost-root\stage\lib boost-root\libs\contract\example\features\introduction.cpp /out:introduction
>set PATH=%PATH%;boost-root/stage/lib
>introduction

[5] 设计理由: 这可以确保本文档展示的大多数示例代码始终是最新的, 并能用本库的最新实现进行构建和运行.
