“我们的领域需要更多的形式化, 但业界还没有意识到这一点. ”

-- Bertrand Meyer (参见 [Meyer97] 第 400 页)

本库为 C++ 编程语言实现契约式编程 (又称契约式设计或 DbC) [1]. 本库支持全部契约式编程特性: 子契约、类不变式 (也适用于静态和 volatile 成员函数)、后置条件 (带旧值和返回值)、前置条件、可自定义的断言失败动作 (例如终止程序或抛出异常)、断言的可选编译、在检查其他断言期间禁用断言 (以避免无限递归) 等 (参见 特性摘要).

引言

契约式编程允许指定前置条件、后置条件和类不变式, 它们会在函数于运行期执行时被自动检查. 这些条件把程序规约写入源代码本身, 从而有助于在测试期间更快地发现缺陷、使代码自文档化, 并提升整体软件质量 (参见 契约式编程概述).

例如, 考虑下面的函数 inc, 它把实参 x 增加 1; 我们先用代码注释写出它的契约 (参见 introduction_comments.cpp):

void inc(int& x)
    // Precondition:    x < std::numeric_limit<int>::max()
    // Postcondition:   x == oldof(x) + 1
{
    ++x; // Function body.
}

前置条件表明: 在函数入口处, 实参 x 必须严格小于其类型所允许的最大值 (这样它可以被增加 1 而不溢出). 后置条件表明: 在函数出口处, 实参 x 必须增加 1, 相对于旧值——即 x 在执行函数之前所具有的值 (此处用 oldof(x) 表示). 注意, 后置条件只应在函数体的执行不抛出异常时才被检查.

现在用本库来编写这个函数及其契约 (参见 introduction.cpp 与 非成员函数):

#include <boost/contract.hpp>

void inc(int& x) {
    boost::contract::old_ptr<int> old_x = BOOST_CONTRACT_OLDOF(x); // Old value.
    boost::contract::check c = boost::contract::function()
        .precondition([&] {
            BOOST_CONTRACT_ASSERT(x < std::numeric_limits<int>::max()); // Line 17.
        })
        .postcondition([&] {
            BOOST_CONTRACT_ASSERT(x == *old_x + 1); // Line 20.
        })
    ;

    ++x; // Function body.
}

当调用上面的函数 inc 时, 本库将:

  • 首先, 执行传递给 .precondition(...) 的、断言 inc 前置条件的仿函数.
  • 然后, 执行 inc 的函数体 (即紧跟在 boost::contract::check c = ... 声明之后的全部代码).
  • 最后, 执行传递给 .postcondition(...) 的、断言 inc 后置条件的仿函数 (除非 inc 的函数体抛出了异常).

例如, 如果调用 inc 的代码有缺陷, 导致函数被调用时 x 等于 std::numeric_limits<int>::max(), 那么程序将终止并输出类似如下的错误消息 (而且显然缺陷在调用代码中):

precondition assertion "x < std::numeric_limits<int>::max()" failed: file "introduction.cpp", line 17

相反, 如果 inc 的实现有缺陷, 导致函数体执行之后 x 没有被增加 1, 那么程序将终止并输出类似如下的错误消息 (而且显然缺陷在 inc 的函数体中): [2] 

postcondition assertion "x == *old_x + 1" failed: file "introduction.cpp", line 20

默认情况下, 断言失败时本库会向标准错误 std::cerr 打印一条类似上述的错误消息, 并调用 std::terminate 终止程序 (这一行为可以自定义以执行任何用户指定的操作, 包括抛出异常, 参见 失败时抛出异常). 注意, 本库打印的错误消息包含全部必要信息, 可以轻松且唯一地确定代码中契约断言失败的位置. [3]

注释

要想使用本库而不手动编写大量样板代码来编写断言契约的仿函数, C++11 lambda 函数是必需的 (参见 不使用 lambda 函数 一节). 话虽如此, 本库的实现并未使用 C++11 特性, 应当可以在大多数现代 C++ 编译器上工作 (参见 入门).

除了上面示例所示的非成员函数契约之外, 本库还允许为构造函数、析构函数和成员函数编写契约. 它们可以检查类不变式, 还可以子契约——从基类继承并扩展契约 (参见 introduction_public.cpp 与 公有函数覆盖): [4] 

template<typename T>
class vector
    #define BASES public pushable<T>
    : BASES
{
public:
    typedef BOOST_CONTRACT_BASE_TYPES(BASES) base_types; // For subcontracting.
    #undef BASES

    void invariant() const { // Checked in AND with base class invariants.
        BOOST_CONTRACT_ASSERT(size() <= capacity());
    }

    virtual void push_back(T const& value,
            boost::contract::virtual_* v = 0) /* override */ { // For virtuals.
        boost::contract::old_ptr<unsigned> old_size =
                BOOST_CONTRACT_OLDOF(v, size()); // Old values for virtuals.
        boost::contract::check c = boost::contract::public_function< // For overrides.
                override_push_back>(v, &vector::push_back, this, value)
            .precondition([&] { // Checked in OR with base preconditions.
                BOOST_CONTRACT_ASSERT(size() < max_size());
            })
            .postcondition([&] { // Checked in AND with base postconditions.
                BOOST_CONTRACT_ASSERT(size() == *old_size + 1);
            })
        ;

        vect_.push_back(value);
    }
    BOOST_CONTRACT_OVERRIDE(push_back) // Define `override_push_back` above.

    // Could program contracts for those as well.
    unsigned size() const { return vect_.size(); }
    unsigned max_size() const { return vect_.max_size(); }
    unsigned capacity() const { return vect_.capacity(); }

private:
    std::vector<T> vect_;
};

语言支持

本库的作者主张把契约加入核心语言. 把契约式编程加入 C++ 标准相对任何库实现都有诸多优势 (编写契约的语法更短更简洁、在声明而非定义中指定契约、强制契约常量正确性、预期编译期和运行期更快、厂商可以开发静态分析工具在可能时静态识别并检查契约、可以基于契约条件改进编译器优化等).

[P0380] 提案支持基本的契约式编程, 它已被接受并将纳入 C++20. 这无疑是朝正确方向迈出的一步, 但遗憾的是 [P0380] 只支持前置条件和后置条件, 缺失类不变式和后置条件中的旧值等重要特性, 更不用说缺少子契约这类更高级的特性 (更完整的提案如 [N1962] 曾被 C++ 标准委员会拒绝). 本库则支持全部契约式编程特性 (本库支持的特性与各契约式编程提案所列特性的详细比较参见 特性摘要; 设计和实现本库期间考虑的参考文献列表——包括提交给 C++ 标准委员会的绝大多数契约式编程提案——参见 参考文献).


[1] 契约式设计 (Design by Contract, DbC) 是 Eiffel Software 公司的注册商标, 最早由 Eiffel 编程语言引入 (参见 [Meyer97]).

[2] 在本例中, 函数体只由一条简单的指令 ++x 组成, 因此很容易通过目视检查确认它不含任何缺陷、总是把 x 增加 1, 从而函数后置条件绝不会失败. 在真实的生产代码中, 函数体很少这么简单, 可能隐藏缺陷, 因此检查后置条件是有用的.

[3] 设计理由: 本库打印的断言失败消息遵循的格式类似于 Clang 在 C 风格的 assert 宏失败时打印的消息格式.

[4] 本例中使用 pushable 基类只是为了展示子契约, 这有一定随意性, 在实际生产代码中可能不会出现.
