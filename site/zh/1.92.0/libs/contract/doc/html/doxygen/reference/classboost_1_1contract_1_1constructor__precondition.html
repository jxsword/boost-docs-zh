类模板 constructor_precondition

boost::contract::constructor_precondition — 为构造函数编写前置条件.

概要

// In header: <boost/contract/core/constructor_precondition.hpp>

template<typename Class> 
class constructor_precondition {
public:

  // public member functions
  constructor_precondition();
  template<typename F> explicit constructor_precondition(F const &);
};

说明

此类必须是声明前置条件所属构造函数的类的第一个基类 (这样, 构造函数实参在用于初始化其他基类之前就能由前置条件检查):

class u
    #define BASES private boost::contract::constructor_precondition<u>, \
            public b
    : BASES
{
    friend class boost::contract::access;

    typedef BOOST_CONTRACT_BASE_TYPES(BASES) base_types;
    #undef BASES

public:
    explicit u(unsigned x) :
        boost::contract::constructor_precondition<u>([&] {
            BOOST_CONTRACT_ASSERT(x != 0);
            ...
        }),
        b(1.0 / float(x))
    {
        ...
    }

    ...
};

用户自定义类应私有继承此类 (以免改变用户自定义类的公有接口). 此外, 此类绝不应被声明为虚基类 (因为虚基类在整个继承层次中只初始化一次, 这会阻止其他基类的前置条件被检查).

在 union 中不能这样使用此类, 因为 C++ 中联合不能有基类. 取而代之, 在 union 中使用此类, 在构造函数定义内、恰好在 boost::contract::constructor 之前声明一个局部对象 (参见 联合 (union)).

参见: 构造函数

模板参数

  1. typename Class

    为其编写前置条件的构造函数的类类型.

constructor_precondition 公有成员函数

  1. constructor_precondition();
    构造此对象而不指定构造函数前置条件.

    对于未指定前置条件的被契约类的构造函数, 会隐式调用此构造函数.

    注释

    本库的实现经过优化, 调用这个默认构造函数的开销在编译期和运行期都应可忽略不计 (很可能被大多数编译器完全优化掉).

  2. template<typename F> explicit constructor_precondition(F const & f);
    构造此对象并指定构造函数前置条件.

    参数:

    f

    本库调用这个零元仿函数来检查构造函数前置条件 f(). 此仿函数调用内的断言通常用 BOOST_CONTRACT_ASSERT 编写, 但调用此仿函数抛出的任何异常都表示契约失败 (并将导致本库调用 boost::contract::precondition_failure). 此仿函数应按 (常量) 值捕获变量, 或者最好按 (常量) 引用捕获以避免额外复制.
