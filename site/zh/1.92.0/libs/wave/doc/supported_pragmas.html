Wave 库支持的 pragma 指令

Wave 预处理器库原生支持#pragma once 和#pragma message("...") 指令.

#pragma once 指令规定 pragma 所在的文件只被包含 (打开) 一次. 这可用于优化包含大量文件的较大编译单元的预处理. 但请注意, #pragma once 指令只有在编译库时给出编译期常量BOOST_WAVE_SUPPORT_PRAGMA_ONCE 的情况下才受支持.

#pragma message(...) 指令生成一条包含给定消息文本的备注. 这对于直接从被预处理的文件生成状态消息可能很有用. 但请注意, 只有在编译库时给出编译期常量BOOST_WAVE_SUPPORT_PRAGMA_MESSAGE 的情况下才支持 #pragma message(...) 指令. 另外请注意, 当编译库时定义了BOOST_WAVE_PREPROCESS_PRAGMA_BODY 编译期常量时, 消息体会被预处理.

Wave 工具支持的 pragma 指令

Wave 预处理工具还支持特定的#pragma 指令, 可用于控制该工具的某些特性. 这些#pragma 指令使用interpret_pragma() 预处理钩子实现 (见此处) .

这里描述的所有指令既可用作常规#pragma 指令, 也可用作operator _Pragma (如果启用了变参宏) . 例如, 以下指令在功能上完全相同:

    #pragma wave trace(enable)

以及

    _Pragma("wave trace(enable)")

所有Wave 特定的 pragma 必须具有一般形式'wave option[(value)]', 其中'wave' 是特定关键字 (可通过BOOST_WAVE_PRAGMA_KEYWORD 编译期常量配置, 更多信息见此处) , 'option' 是要触发的具体 pragma 功能, 'value' 是提供给'option' 功能的可选值. 下表列出了Wave 库支持的所有可能的 pragma 功能. 对于所有这种一般形式的可识别 pragma, 都会调用来自preprocessing_hooks 策略内部的 interpret_pragma 钩子函数, 因此库的用户负责对这些 pragma 的正确解释.

支持的 pragma

pragma option

pragma value

description

trace

enable/on/1
disable/off/0

启用或禁用宏展开过程的跟踪. 即使给出了 --trace 命令行选项也需要这一操作, 因为只有在发现至少一条 trace(enable) pragma 时才会生成跟踪输出.

stop

message

停止Wave 的执行并打印给定的消息. 这对直接调试非常有用.

system

命令

尝试把“command”作为新的操作系统命令启动, 并截获生成的 stdout 和 stderr. 该命令的 stdout 输出 (如果有) 会被重新记号化, 并用作整个 pragma 的替换文本, stderr 输出被忽略. 当返回值为零时该命令被视为成功, 否则报告错误.
这条#pragma 只有在指定了命令行选项 -x 时才可用. Wave 驱动程序在未指定该命令行参数却遇到#pragma wave system() 指令时会发出一条备注

timer

restart/0
<no value>
suspend
resume

值restart 把当前经过时间设为 0 并重新启动计时器.

如果未提供值, 当前经过时间会被打印到 std::cerr 流.

值suspend 和resume 允许暂时停止和恢复计时.

option

line: [0 | 1 | push | pop]
preserve: [0 | 1 | 2 | push | pop]
output: ["filename" | null | default | push | pop]

option(line: ...) 指令允许控制是否在输出流中生成#line 指令. 选项参数应指定为 '0' 或 '1'. 所有其他值都会被标记为非法.

option(preserve: ...) 指令允许控制输出流中生成的空白量. 值 '0' 移除任何不需要的空白, 值 '1' 仅保留注释, 值 '2' 不移除任何空白.

option(output: ...) 指令允许指定输出生成到的文件的名称. 可以指定一个有效的文件名 (将相对于被处理文件的目录进行解释) , 指定值null 完全禁用输出, 或指定值default 使用命令行中通过 --output/-o 选项指定的输出.

pragma 值push 和pop 可用于所有选项 (line、preserve 和output) , 以保存和恢复相应选项的当前值.

所有未在此列出但被标记为'wave' 的 pragma 目前都会作为错误报告. 对其余所有 pragma 的处理取决于编译常量BOOST_WAVE_RETURN_PRAGMA_DIRECTIVES, 它允许指定这些 pragma 是在输出流中原样保留还是不保留. 请注意, operator _Pragma 变体在 pragma 本身被求值之前总是要经过完整预处理. #pragma 变体只有在编译时指定了BOOST_WAVE_PREPROCESS_PRAGMA_BODY 编译常量时才会经过预处理. 有关可能的编译常量的更多信息, 请看此处.

实现你自己的#pragma wave ... 指令相当容易. 你要做的就是实现自己的interpret_pragma 预处理钩子函数 (见此处) , 它应当处理这些附加指令. 有关如何做的示例, 你可以看看 Wave 驱动应用程序, 它借助一个提供的interpret_pragma 函数实现了上面列出的所有 pragma (例如#pragma wave timer() 指令) .
