引言

Wave C++ 预处理器库是一个符合标准的 C99/C++ 预处理器功能实现, 封装在简单易用的接口之后, 并与标准模板库 (STL) 的惯用做法很好地集成.

Wave C++ 预处理器不是一个单体应用程序, 而是一个模块化库, 主要暴露一个上下文对象和一个迭代器接口. 上下文对象帮助配置实际的预处理过程 (如搜索路径、预定义宏等) . 暴露的迭代器也由这个上下文对象生成. 遍历由这两个迭代器定义的序列将返回预处理后的记号, 它们是根据给定输入流即时构建的.

C++ 预处理迭代器本身由一个实现抽象接口的 C++ 词法分析器迭代器提供输入. Wave 库附带的 C++ 词法分析器也可以独立使用, 与 C++ 预处理迭代器完全没有绑定关系.

为了使 C++ 预处理库模块化, C++ 词法分析器与预处理器完全分离并独立. 为证明这一概念, 实现了两个不同但功能相同的 C++ 词法分析器. 此外还实现了一个 IDL 词法分析器, 允许把预处理库用作面向 IDL 工具的词法分析组件. 所有这些词法分析器都实现上述抽象接口, 因此 C++ 预处理迭代器可以与它们中的任何一个配合使用. 把词法分析器从预处理迭代器库中抽象出来, 是为了允许插入不同的词法分析器而无需重新实现预处理器. 这将允许对预处理过程本身进行基准测试和特定的精细调优.

这些 C++ 词法分析器中的第一个借助广为人知的Re2C [3] 工具实现, 它从给定的正则表达式生成 C 代码. 用Re2C 生成的词法分析器以速度极快著称, 因为它们不是表驱动的, 而是直接对记号构建逻辑编码 (与手写词法分析器非常相似) .

这些 C++ 词法分析器中的第二个围绕一个表驱动词法分析器构建, 其 DFA 表 (离散有限自动机表) 借助一个名为Slex [5] 的基于 Spirit 的词法分析器生成框架从正则表达式生成. Slex 在运行期接受记号定义 (正则表达式) 作为输入, 并生成由此得到的 DFA 表. 该表用于把输入字符组合成对应的词素 (记号) . 生成的 DFA 表可以保存到磁盘, 以避免在程序启动时进行生成过程.

Wave 也可用于预处理 IDL 文件, 因为 IDL 语言所需的记号集合与 C++ 记号集合非常相似. 这正是Wave 预处理器库还包含一个 IDL 词法分析器的原因. IDL 词法分析器同样基于Re2C 工具, 但识别一组不同的记号. 因此该词法分析器不识别任何关键字 (true 和false 除外, 预处理器本身需要它们) . 这是必要的, 因为存在不同的 IDL 语言方言, 其中一种方言的标识符可能是另一种方言的关键字——好吧, 这要求把关键字识别推迟到预处理之后, 但允许对所有的 IDL 衍生语言使用 Wave.

如有需要, 也可以构建其他 C++ 词法分析器. 目前的计划是适配Spirit C++ 词法分析器示例cpplexer [6], 它完全基于静态Spirit[4] 文法.

自带的两个词法分析器以及库本身都能够以符合 C99 的模式运行. 在这种模式下, 词法分析器拒绝 C++ 特有记号 ('::'、'->*'、'.*' 以及诸如'and' 等替用关键字) . 预处理器还处理 placemarker (空宏参数) 和变参宏 (参数个数可变的宏) . 作为对 C++ 标准的扩展, 可以让库在 C++ 模式下也处理 placemarker 和变参宏.
