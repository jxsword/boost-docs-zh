引言

boost::wave::context<> 对象是Wave 库的主要用户可见对象. 它的存在是为了生成一对迭代器, 解引用时返回预处理后的记号. 此外, 它还用于控制预处理的其他方面, 例如

包含搜索路径, 定义用#include <...> 和#include "..." 指令包含文件时去哪里搜索
预定义哪些宏、取消定义哪些预定义宏
若干其他选项, 例如控制是否启用 C++ 标准的若干扩展 (如变参宏和 placemarker 记号) .

模板参数

boost::wave::context 对象有三个模板参数, 用于指定其操作的具体行为. 下表更详细地描述了这些参数.

boost::wave::context 类所需的模板参数
Iterator

底层迭代器的类型, 输入流通过它访问.
它至少应当是forward_iterator 类型的迭代器.
LexIterator

Wave 库用于识别输入流中记号的词法分析器类型.
InputPolicy

输入策略类的类型, 它允许定制 Wave 库的行为以及在包含和打开被包含文件时所使用的迭代器类型.
ContextPolicy

上下文策略类的类型, 它允许定制预处理行为的多个方面. 该策略的要求及其提供的可用定制点在此处描述.
Derived

派生自上下文类型的类型 (如果有) . 该模板参数是可选的, 默认为 'this_type', 表示在不存在派生类型时将使用上下文类型本身.

有关所用词法分析器类型的更多信息, 请参阅词法分析器接口 (The Lexer Interface) .

如果省略模板参数InputPolicy, 则使用模板boost::wave::iteration_context_policies::load_file_to_string. 有关输入策略的更多信息, 请参阅主题输入策略 (The Input Policy) .

如果省略模板参数 ContextPolicy, 则使用boost::wave::context_policies::eat_whitespace 策略类型, 它实现普通 (默认) 执行所需的某些基本预处理钩子. 有关上下文策略的更多信息, 请参阅主题上下文策略 (The Context Policy) .

成员函数

构造函数

    context(Iterator const &first, 
        Iterator const &last, char const *filename, 
        ContextPolicy const& ctx_policy);

在辅助迭代器对[first, last) 给定的输入流之上构造一个上下文对象. 这些迭代器至少应当是forward_iterator 类型的迭代器. filename 参数仅用于提供信息. 该字符串用于指示输入流内部的记号位置, 不会对照文件系统进行验证. 如果未给出 filename 参数, 它默认为"<Unknown>". 如果未提供 ctx_policy 参数, 它默认为一个默认构造的ContextPolicy 对象.

此外, 宏符号表会被填充预定义宏, 当前引用目录被设为给定文件名的路径. 如果该文件名不引用有效的文件系统条目, 则当前引用目录被设为当前系统目录. (当前引用目录是文件系统路径, 在处理#include "..." 指令时用作目标目录) .

迭代器接口

由context::begin 和context::end 函数返回的迭代器对是从预处理器引擎访问预处理后记号的主接口. 在遍历给定迭代器范围[begin, end) 时, 返回的是预处理后的 C++ 记号, 它们由底层输入流即时生成. 返回的迭代器在概念上是forward_iterator 类型.

begin

    iterator_type begin();
    iterator_type begin(Iterator const &first,
         Iterator const &last, );

初始化并返回预处理记号流的起始迭代器. 参数[first, last) 给出的迭代器对指定要预处理的输入序列. 该函数的第一个版本使用构造函数指定的输入流.

end

    iterator_type end() const;

初始化并返回流末尾迭代器, 用于比较以检测预处理记号流的结束.

维护包含路径

Wave 库维护两条独立的包含文件搜索路径:一条用于用户包含文件的搜索路径, 一条用于系统包含文件的搜索路径. 在调用set_sysinclude_delimiter() 函数之前用add_include_path() 函数指定的所有目录只在#include "..." 指令的情况下被搜索, #include <file> 指令不会搜索它们. 也就是说, 这些目录被加入用户包含搜索路径.

如果在调用set_sysinclude_delimiter() 函数之后用add_include_path() 函数指定了其他目录, 则所有#include 指令都会搜索这些目录. 也就是说, 这些目录被加入系统包含搜索路径.

此外, 调用set_sysinclude_delimiter() 函数会抑制把当前引用目录用作#include "..." 指令的第一个搜索目录. 因此, 只有在通过调用add_include_path(".") 显式请求时才会搜索当前引用目录.

同时调用set_sysinclude_delimiter() 和add_include_path(".") 这两个函数, 可以精确控制在当前目录之前搜索哪些目录、之后搜索哪些目录.

这些函数仿照流行的 gcc 编译器实现的命令行行为设计.

add_include_path

    bool add_include_path(char const *path);

把给定的文件系统路径加入用户包含搜索路径. 在调用set_sysinclude_delimiter() 之后, 该函数会把给定的文件系统路径加入系统包含搜索路径. 但请注意, 给定路径会对照文件系统进行验证.

如果给定的路径字符串不是一个有效文件系统目录项的名称, 该函数返回false. 如果给定路径成功加入相关的包含搜索路径, 该函数返回true.

add_sysinclude_path

    bool add_sysinclude_path(char const *path);

把给定的文件系统路径加入系统包含搜索路径. 无论add_include_path() 处于何种操作模式, 该函数都作用于系统包含搜索路径. 但请注意, 给定路径会对照文件系统进行验证.

如果给定的路径字符串不是一个有效文件系统目录项的名称, 该函数返回false. 如果给定路径成功加入系统包含搜索路径, 该函数返回true.

set_sysinclude_delimiter

    void set_sysinclude_delimiter();

切换add_include_path() 函数的操作模式. 默认情况下, 给定的文件系统路径被加入用户包含搜索路径. 调用该函数之后, 随后对add_include_path() 的调用会把给定的文件系统路径加入系统包含搜索路径. 此外, 它还抑制把当前引用目录用作#include "..." 指令的第一个搜索目录.

get_iteration_depth

    size_t get_iteration_depth() const;

返回实际的包含迭代深度, 即在到达主 (最顶层) 迭代上下文之前, 要从包含迭代上下文中弹出的当前包含层次数.

维护已定义宏

add_macro_definition

    bool add_macro_definition(
        std::string macrostring, bool is_predefined);

向宏符号表添加一个新的宏定义. 参数macrostring 应包含以命令行格式给出的待定义宏, 即类似MACRO(x)=definition 的内容. 下表更详细地描述了该格式. 参数is_predefined 在定义预定义宏时应为 true, 即不能用#undef 指令从被预处理的输入流内部取消定义的宏. 如果未给出该参数, 它默认为false.

定义宏的可能格式汇总
MACRO define MACRO as 1
MACRO= define MACRO as nothing (empty)
MACRO=definition define MACRO as definition
MACRO(x) define MACRO(x) as 1
MACRO(x)= define MACRO(x) as nothing (empty)
MACRO(x)=definition define MACRO(x) as definition

如果要定义的宏已被定义且新定义与现有定义等价, 该函数返回false; 如果新宏成功加入宏符号表, 则返回 true.

如果给定的宏定义构成一次重定义且新宏与已定义宏不相同 (按 C++ 标准的定义) , 该函数抛出相应的preprocess_exception.

is_defined_macro

    template <typename String>
    bool is_defined_macro(String const &name) const;

返回具有给定name 的宏是否已定义, 即它是否包含在宏符号表中.

get_macro_definition

    template <typename String>
    bool get_macro_definition(
        String const &name, bool &is_function_style, 
        bool &is_predefined, position_type &pos, 
        std::vector<token_type> &parameters, 
        token_sequence_type &definition) const;

允许检索与某个宏定义相关的所有已知信息. 参数name 指定要返回其信息的宏的名称. 参数is_function_style 和is_predefined 分别返回该宏是否被定义为函数式宏或预定义宏. 参数pos 将包含宏定义所在的位置. 参数parameters 将包含宏定义时所用的参数名, 参数definition 将包含定义 (宏体) 的记号序列.

如果宏已定义且所请求的信息成功检索到, 该函数返回true, 否则返回false.

remove_macro_definition

    template <typename String>
    bool remove_macro_definition(
        String const &name, bool even_predefined);

从宏符号表中移除具有给定name 的宏的定义. 该操作等价于在输入流内执行一条带有该name 的#undef 指令. 如果参数even_predefined 为true, 那么即使该宏被定义为预定义宏, 也会从宏符号表中移除.

但请注意, 以下宏在任何情况下都不可取消定义:__FILE__、__LINE__、__DATE__、__TIME__、__cplusplus、__STDC__. 如果未给出参数even_predefined, 它默认为false.

如果要取消定义的宏未被定义, 该函数返回false, 否则返回true.

如果要移除的宏不可取消定义 (它是预定义宏且参数even_predefined 被设为false, 或者它是上文提到的不可取消定义的宏之一) , 该函数抛出preprocess_exception.

reset_macro_definitions

    void reset_macro_definitions();

把宏符号表重置为初始状态, 即取消定义所有用户定义的宏, 并按此处所述插入内部预定义宏.

macro_names_begin, macro_names_end 

    name_iterator macro_names_begin();
    name_iterator macro_names_end();
    const_name_iterator macro_names_begin() const;
    const_name_iterator macro_names_end() const;

macro_names_begin 和macro_names_end 函数返回迭代器, 允许遍历所有已定义宏的名称.

获取版本信息

get_version

    static std::string get_version();

返回一个字符串, 包含格式为0xvvrsbbbb 的当前 Wave 版本 (这是等价十六进制数的字符串表示) , 其中'vv' 是版本号, 'r' 是发布号, 's' 是子发布号, 'bbbb' 是构建号. 可能的返回值形如0x00910454. 返回值与展开预定义宏__WAVE_VERSION__ 时插入预处理记号流的值相同.

get_version_str

    static std::string get_version_str();

返回一个字符串, 包含格式为"v.rr.ss.bbbb" 的当前 Wave 版本, 其中'v' 是版本号, 'rr' 是发布号, 'ss' 是子发布号, 'bbbb' 是构建号. 可能的返回值形如"0.9.1.454". 返回值与展开预定义宏__WAVE_VERSION_STR__ 时插入预处理记号流的值相同.

控制扩展选项

set_language
get_language

    void set_language(language_support language, 
        bool reset_macros = true);
    language_support get_language() const;

该函数允许指定Wave 库应当工作的语言模式. 可能的语言模式由枚举类型language_support 定义:

    enum language_support {
    // support flags for C++98
        support_normal = 0x01,
        support_cpp = support_normal,

    // support flags for C99
        support_option_long_long = 0x02,
        support_option_variadics = 0x04,
        support_c99 = support_option_variadics | support_option_long_long | 0x08,

    // support flags for C++11
        support_option_no_newline_at_end_of_file = 0x20,
        support_cpp0x = support_option_variadics | support_option_long_long |
            support_option_no_newline_at_end_of_file | 0x10,
        support_cpp11 = support_cpp0x,    

    //  support flags for C++17
        support_option_has_include = 0x10000,
        support_cpp1z = support_option_variadics | support_option_long_long |
            support_option_no_newline_at_end_of_file | support_option_has_include | 0x20000,
        support_cpp17 = support_cpp1z

    //  support flags for C++20
        support_option_va_opt = 0x40000,
        support_cpp2a = support_option_variadics | support_option_long_long |
            support_option_no_newline_at_end_of_file | support_option_has_include |
            support_option_va_opt | 0x80000,
        support_cpp20 = support_cpp2a,

    // the mask for the main language settings
        support_option_mask = 0xFFC0,

    // additional fine tuning of the general behavior
        support_option_emit_contline = 0x0040,
        support_option_insert_whitespace = 0x0080,
        support_option_preserve_comments = 0x0100,
        support_option_no_character_validation = 0x0200,
        support_option_convert_trigraphs = 0x0400,
        support_option_single_line = 0x0800,
        support_option_prefer_pp_numbers = 0x1000,
        support_option_emit_line_directives = 0x2000,
        support_option_include_guard_detection = 0x4000,
        support_option_emit_pragma_directives = 0x8000
    };

与support_option_variadics 一起使用时, 在普通 C++ 模式下启用对变参宏、placemarker 记号和operator _Pragma() 的支持. 与support_option_long_long 一起使用时, 在 C++ 模式下启用对 long long 后缀的支持.

support_c99 开启 C99 语言支持, 默认启用变参宏、placemarker 记号、operator _Pragma 和 long long 后缀. 此外它禁用 C++ 特有的记号, 如'->*'、'.*'、'::' 等.

support_option_... 值应与主语言设置 (support_normal 和support_c99) 结合使用.

  • 如果设置了support_option_insert_whitespace 标志, Wave 库会在两个记号拼接后的字符串表示将构成另一个有效 C++ 记号的位置插入额外空白. 这对于避免生成的输出随后被 C++ 编译器处理时的误解释非常重要.
  • 如果设置了support_option_preserve_comments 标志, Wave 库会保留源代码中几乎所有注释. 唯一不保留的是宏定义内部的注释. 如果未设置该标志, 所有注释都会被替换为一个空格.
  • 如果设置了support_option_no_character_validation 标志, Wave 库不会验证通用字符字面量 (以'u1234' 或'U12345678' 形式给出) 是否在允许的取值范围内. 该标志仅用于测试框架的内部目的, 库的用户很少会用到.
  • 如果设置了support_option_convert_trigraphs 标志, Wave 库会把所有出现的三联符 (trigraph) 字符替换为其非三联符字符序列 (即'??=' 替换为'#' 等) . 默认不执行任何替换.
  • 如果设置了support_option_single_line 标志, Wave 库将以单行模式运行, 除其他事项外, 如果被处理输入的最后一行未以换行符结束, 也不会报错. 该标志主要用于测试框架的内部目的, 库的用户很少会用到. 要禁用文件末尾换行检查, 请使用support_option_no_newline_at_end_of_file (C++11 及之后的默认值) .
  • 如果设置了support_option_prefer_pp_numbers 标志, Wave 库将被指示正确识别输入流中的 pp-number (预处理数字) . 它们在被返回给调用应用程序之前会被识别为“普通”数字记号. 该标志默认设置, 仅用于内部目的, 库的用户很少会重置它.
  • 如果设置了support_option_emit_line_directives 标志, Wave 库会在适当的时候在生成的记号流中发出#line 指令. 该标志默认设置; 要阻止库生成#line 指令, 必须显式重置它.
  • 如果设置了support_option_include_guard_detection 标志, Wave 库会在处理被包含文件期间尝试自动识别包含保护宏 (include guard) . 包含包含保护宏的文件会被当作含有 #pragma once 来处理, 即这些文件不会被打开两次, 即使在第二条#include 语句中再次指定.

在此过程中, 库会识别两种形式的包含保护宏:

 #ifndef INCLUDE_GUARD_MACRO
 #define INCLUDE_GUARD_MACRO
 ...
 #endif
or
 #if !defined(INCLUDE_GUARD_MACRO)
 #define INCLUDE_GUARD_MACRO
 ...
 #endif

注意, 第二种形式中的圆括号是可选的 (即!defined INCLUDE_GUARD_MACRO 也同样有效) . 代码允许在#if/#ifndef 之前以及最后的#endif 之后出现任意空白、换行和单个 '#' 记号, 包含保护宏仍可被识别.

该标志默认开启, 因此如果你不希望库自动识别包含保护宏, 需要显式重置它.

  • 如果设置了support_option_emit_pragma_directives 标志, Wave 库会把所有未知的#pragma 指令发送到输出. 该支持选项只有在编译期间BOOST_WAVE_EMIT_PRAGMA_DIRECTIVES 被定义为不等于零的值时才会被识别 (更多信息见此处) .
  • 如果设置了support_option_emit_contlines 标志, Wave 库会发出输入中遇到的所有反斜杠换行序列. 它会为每个这样的字符序列生成一个T_CONTLINE 记号. 请注意, 该选项仅受自定义 SLex 词法分析器模块支持. 可用的示例见 cpp_tokens 示例.

如果参数reset_macros 为 true, set_language 函数会在内部重置已定义宏的列表, 因此请小心, 不要在你已经定义了自己的宏之后再调用它.

set_max_include_nesting_depth
get_max_include_nesting_depth
