示例

Wave 库包含若干示例, 展示如何使用不同的特性. 本节描述这些示例及其主要特点.

quick_start 示例

quick_start 示例展示了使用Wave 预处理器库的最简方式. 它只是打开以第一个命令行参数给定的文件, 在假定没有任何额外包含路径或已定义宏的情况下对其进行预处理, 并输出从给定输入文件生成的记号的文本表示. 该示例可用于让自己初步了解Wave, 因为它不包含更复杂的示例所暴露的那些潜在附加复杂性.

lexed_tokens 示例

lexed_tokens 示例展示了在不使用预处理器的情况下使用 Wave 的 C++ 词法分析组件的最简方式. 它打开以第一个命令行参数指定的文件, 并打印从词法分析器返回的记号的内容.

cpp_tokens 示例

cpp_tokens 示例转储Wave 库提供的迭代器返回的记号中包含的信息. 它展示了如何把Wave 库与自定义词法分析器和自定义记号类型配合使用. 该示例中使用的词法分析器基于SLex [5], 即它在运行期 (启动时) 接受记号定义 (正则表达式) 作为输入, 并生成由此得到的 DFA 表. 该表用于记号识别, 随后保存到磁盘, 以避免在下一次程序启动时进行表生成过程. DFA 表保存到的文件的名称是wave_slex_lexer.dfa.

这个基于SLex 的词法分析器与默认的基于Re2C [3] 生成的词法分析器相比, 其主要优点是:它不仅提供特定记号被识别处的行信息, 还提供相关的列位置. 除此之外, 基于SLex 的词法分析器在功能上与基于Re2C 的完全兼容, 也就是说, 如果你还需要从预处理中获得列信息, 随时可以把应用程序切换为使用它.

由于该示例不支持额外的命令行参数, 如果包含文件与被检查的输入文件不在同一目录, 它就无法很好地工作. 命令行语法非常直白:

    cpp_tokens input_file

list_includes 示例

list_includes 示例展示了如何使用Wave 库为特定输入文件生成包含文件依赖列表. 它完全依赖默认的库配置. 该示例的命令行语法如下:

    Usage: list_includes [options] file ...:
        -h [ --help ]        : print out program usage (this message)
        -v [ --version ]     : print the version number
        -I [ --path ] dir    : specify additional include directory
        -S [ --syspath ] dir : specify additional system include directory

但请注意, 该示例只会输出那些对预处理器可见的包含文件名, 也就是说, 给定下面的代码片段, 预处理期间只会触发两条包含文件指令中的一条, 因此list_includes 示例只会报告对应的文件名: 

    #if defined(INCLUDE_FILE_A)
    #  include "file_a.h" 
    #else
    #  include "file_b.h"
    #endif

advanced_hooks 示例

advanced_hooks 示例基于上面提到的quick_start 示例. 它展示了你可能想如何利用高级预处理钩子 (属于Wave 库) , 使输出不仅包含来自已求值条件块的预处理记号, 还包含在未求值条件块内识别到的记号. 为了使生成的记号流可用于进一步处理, 来自未求值条件块的记号被注释掉.

下面是advanced_hooks 示例功能的一个小示例. 考虑以下输入:

    #define TEST 1
    #if defined(TEST)
    "TEST was defined: " TEST
    #else
    "TEST was not defined!"
    #endif

其输出为:

    //"#if defined(TEST)
    "TEST was defined: " 1
    //"#else
    //"TEST was not defined!"
    //"#endif

如你所见, 该示例应用程序同样以注释掉的方式打印出条件指令.

wave 示例

由于具有普遍的实用性, wave 示例不位于库的示例目录中, 而是位于 Boost 的 tools 目录内. wave 示例可用作任何其他 C++ 编译器之上的功能完备的预处理器可执行程序. 它输出从给定输入文件生成的预处理后记号的文本表示. 更详细的描述见此处.

waveidl 示例

waveidl 示例的要点是展示如何把一个完全独立的词法分析器类型与Wave 库的默认记号类型配合使用. 该示例中使用的词法分析器假定用于基于 IDL 语言的预处理器. 它同样基于Re2C 工具, 但识别一组不同于Wave 库内含的默认 C++ 词法分析器的记号. 因此该词法分析器不识别任何关键字 (true 和false 除外, 预处理器本身需要它们) . 这是必要的, 因为存在不同的 IDL 语言, 其中一种语言的标识符可能是另一种语言的关键字. 当然这要求把关键字识别推迟到预处理之后, 但允许对所有的 IDL 衍生语言使用Wave.

之所以可以只用Wave 库来编写 IDL 预处理器, 是因为两种语言的记号集合非常相似. waveidl IDL 语言预处理器要识别的记号几乎是完整 C++ 记号集合的一个完全子集.

该示例可用的命令行语法如下所示:

  Usage: waveidl [options] [@config-file(s)] file:


    Options allowed on the command line only:
      -h [ --help ]           : print out program usage (this message)
      -v [ --version ]        : print the version number
      -c [ --copyright ]      : print out the copyright statement
      --config-file filepath  : specify a config file (alternatively: @filepath)

        
    Options allowed additionally in a config file:
      -o [ --output ] path    : specify a file to use for output instead of stdout
      -I [ --include ] path   : specify an additional include directory
      -S [ --sysinclude ] syspath : specify an additional system include directory
      -D [ --define ] macro[=[value]] : specify a macro to define
      -P [ --predefine ] macro[=[value]] : specify a macro to predefine
      -U [ --undefine ] macro : specify a macro to undefine

hannibal 示例

hannibal 示例展示了如何把 Spirit 文法构建在Wave 库之上. 它最初由 Danny Havenith 编写并贡献给Wave 库 (见其相关网页此处) . 该示例的文法使用Wave 作为其预处理器. 它实现了The C++ Programming Language, Third Edition 中大约 250 条文法规则中的约 120 条. 这 120 条规则允许解析 C++ 源文件中的全部类型信息和声明. 事实上这个文法的解析能力相当全面:它解析 C++ 声明 (包括类和模板定义) , 但跳过函数体. 如果按此配置, 程序将输出生成解析树的 XML 转储.

对于诸如某些 UML 建模工具所做的那种逆向工程, 它可以是一个很好的文法起点. 或者, 无论你能为一个能给出文件中所有模板、类及其成员列表的文法找到什么用途.

check_macro_naming 示例

check_macro_naming 示例演示如何使用上下文钩子来了解宏在代码库中是如何定义的. 一些项目 (例如 Boost 本身) 对宏的命名有约定. 该示例将递归搜索一个目录, 查找头文件并在其中搜索宏定义. 任何不符合所提供约定 (默认为^BOOST_.*) 的宏都会被报告, 如果它们被用作包含保护宏, 还会附注说明. 用户还可以指定任意数量的目录在过程中忽略.

命令行语法:

Usage: check_macro_naming [options] directory:
  -h [ --help ]            print out options
  --match arg (=^BOOST_.*) pattern defined macros must match
  --exclude arg            subdirectory to skip

用法示例:

$ check_macro_naming --exclude ./test/testwave/testfiles include
CPP_CONTEXT_HPP_907485E2_6649_4A87_911B_7F7225F3E5B8_INCLUDED include/boost/wave/cpp_context.hpp (guard)
WHITESPACE_HANDLING_HPP_INCLUDED include/boost/wave/whitespace_handling.hpp (guard)
...
TRACE_CPP_TIME_CONVERSION include/boost/wave/util/time_conversion_helper.hpp
spirit_append_actor include/boost/wave/util/time_conversion_helper.hpp
spirit_assign_actor include/boost/wave/util/time_conversion_helper.hpp

custom_directives 示例

custom_directives 示例展示了如何通过重写found_unknown_directive 钩子来定义自己的指令, 以添加#version 和#extension 指令 (来自 GLSL) .

emit_custom_line_directives 示例

emit_custom_line_directives 示例展示了如何使用emit_line_directive 预处理钩子来自定义任何生成的#line 指令的格式. 该示例将发出与 gcc 生成的格式兼容的 #line 指令:

    # <lineno> <rel_file_name>

preprocess_pragma_output 示例

preprocess_pragma_output 示例演示使用interpret_pragma 钩子安装自定义 pragma 处理代码. 具体来说, 它定义了一个新的#pragma wave pp(), 在当前预处理器上下文中解释一个字符串. 示例输入使用该机制从传递给pp 的带引号字符串内部定义新宏.

real_positions 示例

real_positions 示例演示:
  • 使用generated_token 钩子
  • 在不更改词法分析器的情况下将 Wave 用于新的记号类型

通过展示如何纠正返回记号内部的位置, 使它们看起来是连续的 (忽略来自宏定义的位置) .

token_statistics 示例

token_statistics 示例统计预处理输入中每种类型记号的数量并加以报告. 它演示:
  • 使用 Xpressive 词法分析器
  • 设置自定义的局部和系统包含搜索路径
