Wave 驱动程序

Wave 库实现了一个驱动程序, 它几乎利用了该库的全部功能. 它可以用作在任何其他 C++ 编译器之上运行的预处理器可执行程序. 它输出由给定输入文件生成的预处理记号的文本表示. 该驱动程序具有以下命令行语法:

Usage: wave [options] [@config-file(s)] file:
 
  Options allowed on the command line only:
    -h [--help]:            print out program usage (this message)
    -v [--version]:         print the version number
    -c [--copyright]:       print out the copyright statement
    --config-file filepath: specify a config file (alternatively: @filepath)
 
  Options allowed additionally in a config file:
    -o [--output] path:          specify a file [path] to use for output instead of 
                                 stdout or disable output [-]
    -E [ --autooutput ]:         output goes into a file named <input_basename>.i
    -I [--include] path:         specify an additional include directory
    -S [--sysinclude] syspath:   specify an additional system include directory
    -F [--forceinclude] file:    force inclusion of the given file
    -D [--define] macro[=[value]]:    specify a macro to define
    -P [--predefine] macro[=[value]]: specify a macro to predefine
    -U [--undefine] macro:       specify a macro to undefine
    -u [--undefineall]:          undefine all macrodefinitions
    -n [--nesting] depth:        specify a new maximal include nesting depth
	
  Extended options (allowed everywhere)
    -t [--traceto] arg:          output trace info to a file [arg] or to stderr [-]
    --timer:                     output overall elapsed computing time
    --long_long:                 enable long long support if C++ mode
    --variadics:                 enable variadics and placemarkers in C++ mode
    --c99:                       enable C99 mode (implies variadics and placemarkers)
    --c++11:                     enable C++11 mode (implies --variadics and --long_long)
    --c++20:                     enable C++20 mode (adds __VA_OPT__ to variadics)
                                                   (implies --variadics and --long_long)
    -l [ --listincludes ] arg:   list included file to a file [arg] or to stdout [-]
    -m [ --macronames ] arg:     list names of all defined macros to a file [arg] or 
                                 to stdout [-]
    -c [ --macrocounts ] arg     list macro invocation counts to a file [arg] or to
                                 stdout [-]
    -p [ --preserve ] arg (=0):  preserve whitespace
                                 0: no whitespace is preserved (default),
                                 1: begin of line whitespace is preserved,
                                 2: comments and begin of line whitespace is preserved,
                                 3: all whitespace is preserved
    -L [ --line ] arg (=1):      control the generation of #line directives
                                 0: no #line directives are generated
                                 1: #line directives will be emitted (default)
    -x [ --extended ]:           enable the #pragma wave system() directive
    -G [ --noguard ]:            disable include guard detection
    -g [ --listguards ]:         list names of files flagged as 'include once' to a
                                 file [arg] or to stdout [-]
    -s [ --state ] arg:          load and save state information from/to the given
                                 file [arg] or 'wave.state' [-] (interactive mode
                                 only)

可用的选项都很直观且不言自明. 下面更详细地描述其中一些选项. 请注意, 扩展选项 (--c99 和 --variadics) 仅在驱动程序编译时定义了常量 WAVE_SUPPORT_VARIADICS_PLACEMARKERS 的情况下才可用.

-o [--output] path

指定用于生成的预处理输出流的文件名. 如果未给出此选项, 则使用标准输出 (stdout). 如果给定的文件名等于 '-' (不含引号), 则最初不生成任何输出. 这尤其适用于仅进行语法检查, 或与 #pragma wave option(output: ...) 指令结合使用, 以将生成的输出仅限制到特定部分 (相关描述见支持的 pragma 指令).

-E [--autooutput]

生成的输出将写入一个以输入文件基本名命名、扩展名为 '.i' 的文件, 即对于输入文件 'inputfile.cpp', 输出将写入 'inputfile.i'. 如果通过 --output 选项指定了输出文件名, 则此选项不会产生任何效果.

-I [--include] 选项

把目录 dir 加到搜索头文件的目录列表的头部. 这可用于覆盖某个系统头文件, 替换为你自己的版本, 因为这些目录会在系统头文件目录之前被搜索. 但是, 不应使用此选项来添加包含厂商提供的系统头文件的目录 (为此应使用 '-S'). 如果使用多个 '-I' 选项, 则按从左到右的顺序扫描这些目录, 标准系统目录排在最后.

如果标准系统包含目录或用 '-S' 指定的目录也用 '-I' 指定了, 则 '-I' 选项会被忽略. 该目录仍会被搜索, 但会作为系统包含链中处于其正常位置的系统目录来搜索.

-I- [--include-] 选项

Wave 库为包含文件维护两条独立的搜索路径. 一条用于用户包含文件, 一条用于系统包含文件, 用户包含路径先于系统包含路径被搜索.

在可能给出的 '-I-' 选项之前用 '-I' 选项指定的任何目录, 只在 '#include "file"' (用户包含文件) 的情形下被搜索; 对 '#include <file>' 指令 (系统包含文件) 则不搜索它们. 如果在给出 '-I-' 选项之后又用 '-I' 选项指定了其他目录, 则这些目录会为所有 '#include' 指令而搜索 (通常所有 '-I' 目录都按此方式使用).

此外, '-I-' 选项禁止把当前目录 (当前输入文件来自的目录) 用作 '#include "file"' 指令的第一个搜索目录. 使用 '-I.' 可以指定搜索调用编译器时所在的目录. 这与预处理器默认的做法不完全相同, 但通常也能令人满意.

-S [--sysinclude] 选项

把给定目录加到搜索系统头文件的目录列表的头部. 如果使用多个 '-S' 选项, 则按从左到右的顺序扫描这些目录. 此选项在 wave.cfg 配置文件中最为有用, 用于指定在哪里搜索系统包含文件.

-F [--forceinclude] 选项

把给定文件作为普通输入来处理, 并在开始处理常规输入文件之前包含其全部输出结果. 如果给出了多个此类选项, 则按这些文件在命令行上出现的顺序预先包含它们.

-D [--define] 宏[=定义]
-P [--predefine] 宏[=定义]

此选项允许从命令行定义 ('-D') 或预定义 ('-P') 一个宏. 与 '-D' 或 '-P' 选项一起给出的字符串应符合惯用语法 MACRO(x)=definition, 更详细的描述见此处.

'-D' 与 '-P' 选项之间唯一的区别是, 后者以这样的方式预定义宏: 它不能 通过被预处理程序内部的#undef 指令取消定义.

-U [--undefine] macro

这允许取消定义Wave 库自动预定义的一些宏 (见预定义宏). 唯一的例外是__LINE__, __FILE__, __DATE__, __TIME__, __STDC__ 和 __cplusplus 预定义宏, 它们不可取消定义. 如果对同一个名字同时指定了 -U 和 -D, 则该名字不会被预定义.

-n [--nesting] depth

指定一个新的最大包含嵌套深度. 如果预处理达到此包含文件嵌套深度, 则会在发出一条错误消息后中止预处理. 默认的包含文件嵌套深度为 1024.

-t [--traceto] path

启用 Wave 库内置的跟踪设施. path 指定用于输出生成的跟踪日志的文件名. 如果给定的文件名等于 '-' (不含引号), 则跟踪日志被写入标准错误流 (stderr).

只对输入中已通过 #pragma wave trace(enable) 或 _Pragma("wave trace(enable)") 指令显式启用跟踪的部分执行跟踪. 更多细节见此处.

--timer

启用对处理给定输入文件所需的总耗时的跟踪. 在编译完成后, 所耗时间被打印到 stdout.

--variadics

在普通 C++ 模式下启用对变参宏 (带可变参数列表的宏)、placemarker 记号 (空宏实参) 和 operator _Pragma 的支持. 此选项会预定义一个特殊的预定义宏 __WAVE_HAS_VARIADICS__.

--c99

启用 C99 模式. 此模式启用某些 C99 特有的特性, 如变参宏 (带可变参数列表的宏)、placemarker 记号 (空宏实参) 和 operator _Pragma 支持, 并禁用某些 C++ 特有的记号类型, 例如 '::', '->*' 和 '->.'. 此模式下有若干预定义宏有所不同, 有关预定义宏的更多信息可参阅此处.

--c++11

启用 C++11 模式. 此模式启用 C++11 特有的关键字与特性, 如变参宏 (带可变参数列表的宏)、placemarker 记号 (空宏实参) 和 operator _Pragma 支持. 此模式下有若干预定义宏有所不同, 有关预定义宏的更多信息可参阅此处.

-l [--listincludes] path

启用对所有已打开的包含文件名的输出. path 指定用于输出生成的包含日志的文件名. 如果给定的文件名等于 '-' (不含引号), 则包含日志被写入标准输出流 (stdout).

-m [--macronames] path

启用对所有已定义宏的输出. 这包括宏名、其参数名 (如果该宏是函数式宏) 及其定义. path 指定用于输出生成的宏列表的文件名. 如果给定的文件名等于 '-' (不含引号), 则宏列表被写入标准输出流 (stdout).

-c [--macrocounts] path

启用对所有宏调用计数的输出. path 指定用于输出生成列表的文件名. 如果给定的文件名等于 '-' (不含引号), 则宏列表被写入标准输出流 (stdout).

-p [--preserve] arg

保留输入流中不位于宏定义内部的空白. 该参数定义要保留的空白量. 值为 '0' (零) 时跳过所有空白, 值为 '1' 时只保留行首空白, 值为 '2' 时保留所有注释和所有行首空白, 值为 '3' 时保留输出中的所有空白.

即使此选项以非 '0' (零) 的参数指定, 位于宏定义内部的注释也会被跳过. 如果命令行上未指定此选项, 则只保留必要的空白 (相当于参数值为 '0').

-L [--line]

控制 Wave 工具是否生成 #line 指令. 若参数为 '1', 则会发出这些指令; 若参数值为 '0', 则不会生成 #line 指令. 如果未指定此选项, Wave 总是会生成 #line 指令.

-x [--extended]

启用 #pragma wave system() 指令. 该指令现在默认禁用, 因为它可能导致潜在的安全威胁. 当 Wave 驱动程序在未指定此命令行参数的情况下遇到 #pragma wave system() 指令时, 会发出一条提示信息.

-G [--noguard]

此选项禁用 Wave 库在处理被包含文件时通常执行的自动包含保护宏 (include guard) 检测. 有关自动包含保护宏检测的更多信息, 请参阅 上下文对象 类参考.

-g [--listguards] arg

此选项把所有发现的包含 #pragma once 或含有包含保护宏 (include guard) 的包含文件列出到给定文件中. 如果给定的文件名等于 '-' (不含引号), 则保护日志被写入标准输出流 (stdout). 有关自动包含保护宏检测的更多信息, 请参阅 上下文对象 类参考.

-s [--state]

此选项指示 Wave 工具从作为参数给出的文件加载序列化信息, 并在会话结束时把内部状态信息保存回同一文件. 使用此选项时, Wave 会加载并保存所有已定义的宏 (甚至包括预定义宏) 以及被标记为 #pragma once 和/或被识别为具有包含保护宏 (include guard) 的已处理头文件的相关信息.

注释: 此选项仅在交互模式下有效.

@ [--config-file] 选项

某些可能的命令行选项可以在特殊的配置文件中指定. 这作为不同全局配置的简写非常有用. 配置文件可以包含附加选项 (即 -I、-S、-F、-U、-D 和 -P 选项), 每行一个选项. 空行和以 '#' 字符开头的行会被忽略 (被视为注释行). 注意, '#' 字符只有当它是某行中第一个非空白字符时才被视为注释的开始. 下面的小示例展示了受支持的配置文件语法:

    # 
    # enable variadics et.al. in C++ mode
    #
    --variadics
    #
    # enable timer support
    #
    --timer
    #
    # emulate gcc V3.3.2
    #
    -D__GNUC__=3
    -D__GNUC_MINOR__=3
    -D__GNUC_PATCHLEVEL__=2
    -D__GNUG__
    # 
    # add Boost to the system include search paths
    #
    -S/usr/local/boost

在命令行上指定配置文件有一种简写方式: 只需在相应文件名之前紧挨着使用 '@' 字符.

在配置文件中找到的选项, 其解释方式如同把它们放置在命令行上该配置文件选项的位置一样.

Wave 驱动程序在启动时会从输入文件所在的目录开始, 沿文件系统层次结构向上在每一级目录中查找名为 'wave.cfg' 的配置文件. 找到的第一个文件会终止搜索. 如果存在这样的文件, 它会被当作普通配置文件处理, 其中指定的选项被解释为如同它们是命令行上最先给出的选项. 此特性对于为 Wave 预处理器驱动程序定义全局环境非常有用.
