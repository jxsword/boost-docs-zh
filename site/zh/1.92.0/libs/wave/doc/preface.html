前言

最近一段时间, 作为对Spirit [4] 解析器构建框架的补充, 许多新特性被开发出来. 我们越来越觉得, 拥有一个“真实世界”的示例会非常有帮助, 它可以作为测试某些特性可用性的沙盒. 此外, 最近 Boost 邮件列表上的一次讨论表明, 开发者们对拥有一个现代的开源 C++ 预处理器库来把玩有着广泛的兴趣. 于是我们萌生了实现一个满足这些需求的 C++ 预处理器的想法——Wave 就此诞生.

Wave C++ 预处理器库使用 Spirit[4] 解析器构建库来实现一个具有符合 ISO/ANSI 标准预处理能力的 C++ 词法分析器. 它暴露一个迭代器接口, 从输入流返回当前预处理后的记号. 这个预处理后的记号是在遍历预处理器迭代器序列时即时生成的 (用 STL 的术语来说, 这些迭代器是前向迭代器) .

C++ 预处理器是一个宏处理器, 通常由你的 C++ 编译器在真正编译之前自动调用, 用来变换你的程序. 它之所以被称为宏处理器, 是因为它允许定义宏——即对较长构造的简短缩写. C++ 预处理器提供四个独立的设施, 你可以酌情使用:

包含头文件
宏展开
条件编译
行控制

如今这些特性被大大低估了; 更有甚者, 预处理器长期以来饱受非议, 以至于在几年前的 Boost 预处理器库[7] 问世之前, 它的用法一直没有得到有效推广. 直到今天我们才开始理解, 预处理器的生成式元编程与 C++ 中的模板元编程相结合, 是迄今任何语言所支持的最强大的编译期反射/元编程设施之一.

C++ 标准[2] 早在 1998 年就获得通过, 但据我所知, 至今仍没有任何商业 C++ 编译器能对该标准中规定的相当简单的预处理器要求提供无缺陷的实现. 这可能是前述低估所致, 也可能是近几年良好编程风格甚至排斥预处理器使用所致, 也可能源于用于描述它的那种有些别扭的标准英语行文. 有两个开源项目是例外: gcc 和 Clang (LLVM 的子项目) , 两者都提供了标准符合性非常好的预处理器.

因此, Wave 项目的主要目标是:

完全符合 C++ 标准 (ISO/IEC 14882:1998) [1] 和 C99 标准 (INCITS/ISO/IEC 9899:1999) [2]
把Spirit[4] 用于解析部分 (当然 :-)
最大限度地使用 STL 和/或Boost 库 (为了紧凑和可维护性)
便于直接扩展以实现附加特性
构建一个能满足不同 C++ 词法分析和预处理需求的灵活库

在最初阶段, 并不打算打造一个性能极高或体积极小的 C++ 预处理器. 如果你追求这些目标, 可能得另寻他处. 不过我们的 C++ 预处理迭代器按预期工作, 并可用作参考实现, 例如用于测试其他面向预处理的库, 如 Boost Preprocessor 库[7] 等. 尽管如此, 最近的工作带来了性能上的显著提升 (与早期版本相比) . Wave 在简单输入文件上仍比某些基于 EDG 的预处理器 (Intel、Comeau) 略慢, 但随着复杂度增加, EDG 上的时间呈指数级膨胀. Wave 下的预处理时间呈线性膨胀, 这使其在复杂度增加时轻松超越基于 EDG 的预处理器.

测试表明, Wave 库非常符合 C++ 标准, 以至于它能编译若干严格符合标准的宏定义, 这些定义甚至连基于 EDG 的预处理器 (如 Comeau 或 Intel) 都无法编译.
