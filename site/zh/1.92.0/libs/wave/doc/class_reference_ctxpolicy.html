引言

上下文策略用于提供回调钩子, 每当出现以下情况时, 库会从内部调用这些钩子进入用户代码:

  • 识别到 (或未识别到) 一条预处理指令,
  • 一个记号即将从预处理器返回,
  • 一个宏被定义或取消定义,
  • 一个宏被展开或重新扫描,
  • 发出一条#line 指令,
  • 在文件系统中搜索一个包含文件,
  • 一个包含文件被打开或关闭,
  • 求值了一个条件表达式,
  • 某个记号因为位于未被求值的条件块内而必须被跳过, 或者
  • 识别到形如'wave option[(value)]' 的 pragma.

该策略类型用作boost::wave::context<> 对象的模板参数, 默认策略仅提供空的钩子函数.

头文件 wave/preprocessing_hooks.hpp 概要

namespace boost {
namespace wave {
namespace context_policies {
 
    struct default_preprocessing_hooks {

        // general hook functions
        template <typename ContextT, typename TokenT>
        bool found_directive(ContextT const &ctx, 
            TokenT const &directive);

        template <typename ContextT, typename ContainerT>
        bool found_unknown_directive(ContextT const& ctx,
            ContainerT const& line, ContainerT& pending);

        template <typename ContextT, typename ExceptionT>
        void throw_exception(ContextT const &ctx, 
            ExceptionT const& e);

        // test, whether a given token may be skipped
        template <typename ContextT>
        bool may_skip_whitespace (ContextT const& ctx,
            TokenT &token, bool &skipped_newline);


        // Conditional compilation
        template <
            typename ContextT, typename TokenT, 
            typename ContainerT
        >
        bool evaluated_conditional_expression(
            ContextT const &ctx, TokenT const& directive, 
            ContainerT const& expression, bool expression_value);

        template <typename ContextT, typename TokenT>
            void skipped_token(ContextT const &ctx, 
            TokenT const& token);

        template <typename ContextT, typename TokenT>
        TokenT const& generated_token(ContextT const &ctx, 
            TokenT const& token);


        // macro expansion tracing
        template <
            typename ContextT, typename TokenT, typename ContainerT,
            typename IteratorT
        >
        bool expanding_function_like_macro(
            ContextT const &ctx, TokenT const &macrodef, 
            std::vector<TokenT> const &formal_args, 
            ContainerT const &definition, TokenT const &macrocall, 
            std::vector<ContainerT> const &arguments,
            IteratorT const &seqstart, Iterator const &seqend);
 
        template <typename ContextT, typename TokenT, typename ContainerT>
        bool expanding_object_like_macro(
            ContextT const &ctx, TokenT const &macro, 
            ContainerT const &definition, TokenT const &macrocall);
 
        template <typename ContextT, typename ContainerT>
        void expanded_macro(ContextT const &ctx, 
            ContainerT const &result);
 
        template <typename ContextT, typename ContainerT>
        void rescanned_macro(ContextT const &ctx, 
            ContainerT const &result);


        // include file tracing functions
        template <typename ContextT>
        bool found_include_directive(ContextT const &ctx, 
            std::string const &filename, bool include_next);

        template <typename ContextT>
        bool locate_include_file(ContextT& ctx, std::string &file_path, 
            bool is_system, char const *current_name,
            std::string &dir_path, std::string &native_name);

        template <typename ContextT>
        void opened_include_file(ContextT const &ctx, 
            std::string const &relname, std::string const& absname,
            bool is_system_include); 

        template <typename ContextT>
        void returning_from_include_file(ContextT const &ctx);

        template <typename ContextT>
        void detected_include_guard(ContextT const &ctx, 
            std::string const& filename,
            std::string const& include_guard);

        template <typename ContextT, typename TokenT>
        void detected_pragma_once(ContextT const &ctx,
            TokenT const& pragma_token, 
            std::string const& filename);


        // interpretation of #pragmas of the form 
        // 'wave option[(value)]'
        template <typename ContextT, typename ContainerT>
        bool interpret_pragma(ContextT const &ctx, ContainerT &pending, 
            typename ContextT::token_type const &option, 
            ContainerT const &values, 
            typename ContextT::token_type const &pragma_token);


        // macro definition hooks
        template <
            typename ContextT, typename TokenT, 
            typename ParametersT, typename DefinitionT
        >
        void defined_macro(ContextT const &ctx, TokenT const &name, 
            bool is_functionlike, ParametersT const &parameters, 
            DefinitionT const &definition, bool is_predefined);

        template <typename ContextT, typename TokenT>
        void undefined_macro(ContextT const &ctx, 
            TokenT const &name);


        // #error and #warning directive hooks
        template <typename ContextT, typename ContainerT>
        bool found_warning_directive(ContextT const &ctx, 
            ContainerT const &message);

        template <typename ContextT, typename ContainerT>
        bool found_error_directive(ContextT const &ctx, 
            ContainerT const &message);

        // #line directive hooks
        template <typename ContextT, typename ContainerT>
        void found_line_directive(ContextT const &ctx, 
            ContainerT const &arguments, unsigned int line,
            std::string const& filename);

        template <typename ContextT, typename ContainerT>
        bool emit_line_directive(ContextT const& ctx, ContainerT &pending, 
            typename ContextT::token_type const& act_token);

    };

}}}   // namespace boost::wave::context_policies

成员函数

通用钩子函数

found_directive

    template <typename ContextT, typename TokenT>
    bool found_directive(ContextT const& ctx, TokenT const &directive);

函数found_directive会在预处理器检测到预处理指令 (#define、#undef、#if、#idef、#ifndef、#elif、#endif、#error、#include、#pragma 或#warning) 之一时被调用.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数directive 引用包含检测到的预处理指令的记号.

如果返回值为true, 该指令将被完全跳过, 即不做任何预处理. 整条指令会被一个换行字符替换. 如果返回值为false, 指令按正常方式处理.

found_unknown_directive

    template <typename ContextT, typename ContainerT>
    bool found_unknown_directive(ContextT const& ctx,
        ContainerT const& line, ContainerT& pending);

只要遇到未知的预处理指令, 就会调用函数found_unknown_directive.

参数ctx 是对用户实例化预处理迭代器所用的上下文对象的引用.

参数line 保存包含未知指令的整行源代码的记号.

参数pending 可用于把记号推回输入流, 这些记号将用作包含未知指令的整行的替换文本.

返回值定义给定表达式是否已被钩子函数正确解释. 如果该函数返回false, 库将抛出ill_formed_directive 异常. 否则, 推回pending 的记号会被传递给用户程序.

throw_exception

    template <typename ContextT, typename ExceptionT>
    void throw_exception(ContextT const &ctx, 
        ExceptionT const& e);

每当发生预处理异常时, 就会调用函数throw_exception.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数e 是包含详细错误信息的异常对象.

may_skip_whitespace

    template <typename ContextT, typename TokenT>
    bool may_skip_whitespace(ContextT const& ctx, TokenT &token, 
        bool& skipped_newline);

每当一个记号即将返回给调用应用程序时, 库都会调用函数may_skip_whitespace.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用. 注意, 该参数是在 Wave V1.2.4 发布版中新增的.

token 参数保存对当前记号的引用. 策略可以在需要时自由修改这个记号.

skipped_newline 参数保存对一个布尔值的引用, 每当将要跳过一个换行时, 策略函数应把该值设为 true.

如果返回值为true, 给定的记号将被跳过, 预处理继续处理下一个记号. 如果返回值为false, 给定的记号会返回给调用应用程序. 必须谨慎使用, 因为通过返回true, 策略函数能够强制跳过即使是重要的记号, 而不仅仅是空白.

条件编译钩子函数

evaluated_conditional_expression

   template <typename ContextT, typename TokenT, typename ContainerT>
    bool evaluated_conditional_expression(ContextT const& ctx, 
        TokenT const& directive, ContainerT const& expression, 
        bool expression_value);

函数evaluated_conditional_expression在预处理器遇到#if、#elif、#ifdef 或#ifndef 指令时被调用. 该钩子会收到未展开的条件表达式 (即被分析源文件中给出的原样) 以及该表达式在当前预处理上下文中求值的结果.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

token 参数保存对已求值指令记号的引用.

参数expression 保存构成被求值表达式的未展开记号序列.

参数expression_value 包含该表达式在当前预处理上下文中的求值结果.

返回值定义给定表达式是否必须再次求值, 从而允许决定应当展开哪个条件分支. 你需要从这个钩子函数返回“true”来强制重新求值该表达式.

skipped_token

    template <typename ContextT, typename TokenT>
    void skipped_token(ContextT const& ctx, TokenT const& token);

函数skipped_token在一个记号由于预处理器条件为假而即将被跳过时被调用 (即在未求值的#if/#else/#endif 分支内要跳过的代码片段) .

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数token 引用要跳过的记号.

generated_token

    template <typename ContextT, typename TokenT>
    TokenT const& generated_token(ContextT const& ctx, TokenT const& token);

每当一个记号即将从库返回时, 就会调用函数generated_token.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数token 引用即将从库返回的记号. 该函数可以修改这个记号, 但在这种情况下必须以记号参数的非 const 引用来实现, 允许就地修改记号.

默认行为是把传入的记号引用原封不动地返回给调用者.

宏展开跟踪函数

expanding_function_like_macro

   template <typename ContextT, typename TokenT, typename ContainerT>
    bool expanding_function_like_macro(
        ContextT const& ctx, TokenT const &macrodef, 
        std::vector<TokenT> const &formal_args, 
        ContainerT const &definition, TokenT const &macrocall, 
        std::vector<ContainerT> const &arguments,
        IteratorT const &seqstart, Iterator const &seqend);

每当一个类函数宏即将被展开时, 就会调用函数expanding_function_like_macro, 即在实际展开开始之前.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

macroname 参数标记要展开的宏定义所在的位置. 它包含在相应宏定义内部标识宏名的记号.

formal_args 参数保存宏定义时使用的形参.

definition 参数保存要跟踪的宏的宏定义. 这是一个标准 STL 容器, 包含在宏定义期间被识别为宏替换列表的记号序列.

macrocall 参数标记该宏被调用的位置. 它包含在预处理输入流内部标识宏调用的记号.

arguments 参数保存宏调用期间使用的宏实参. 这是一个由标准 STL 容器组成的向量, 其中包含在宏调用位置识别出的记号序列, 作为宏展开期间要使用的实参.

参数seqstart 和seqend 指向输入记号流, 允许访问构成宏调用的完整记号序列 (从左括号开始, 到右括号之后结束) .

如果返回值为true, 宏不被展开, 即包括参数在内的整个宏调用序列会被不加进一步处理地复制到输出. 如果返回值为false, 宏按预期展开.

expanding_object_like_macro

    template <typename ContextT, typename TokenT, typename ContainerT>
    bool expanding_object_like_macro(
        ContextT const& ctx, TokenT const &macro, 
        ContainerT const &definition, TokenT const &macrocall);

每当一个类对象宏即将被展开时, 就会调用函数expanding_object_like_macro, 即在实际展开开始之前.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

macroname 参数标记要展开的宏定义所在的位置. 它包含在相应宏定义内部标识宏名的记号.

definition 参数保存要跟踪的宏的宏定义. 这是一个标准 STL 容器, 包含在宏定义期间被识别为宏替换列表的记号序列.

macrocall 参数标记该宏被调用的位置. 它包含在预处理输入流内部标识宏调用的记号.

如果返回值为true, 宏不被展开, 即宏符号被不加进一步处理地复制到输出. 如果返回值为false, 宏按预期展开.

expanded_macro

    template <typename ContextT, typename ContainerT>
    void expanded_macro(ContextT const& ctx, ContainerT const &result);

函数expanded_macro在一个宏的展开完成、替换列表被完全扫描且其中的宏已被替换为对应的展开结果、但尚未开始重新扫描过程时被调用.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数result 包含迄今为止宏展开的结果. 这是一个标准 STL 容器, 包含生成的记号序列.

rescanned_macro

    template <typename ContextT, typename ContainerT>
    void rescanned_macro(ContextT const& ctx, ContainerT const &result);

每当一个宏的重新扫描完成时 (即宏展开完成) , 就会调用函数rescanned_macro.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数result 包含整个宏展开的结果. 这是一个标准 STL 容器, 包含生成的记号序列.

包含文件跟踪函数

found_include_directive

    template <typename ContextT>
    bool found_include_directive(ContextT const& ctx, 
        std::string const &filename, bool include_next);

每当定位到一条 #include 指令时, 就会调用函数found_include_directive.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数filename 包含#include 指令后找到的 (已展开的) 文件名. 其格式为<file>、"file" 或file. 格式<file> 或"file" 用于预处理记号流中发现的#include 指令, 格式file 用于通过 --force_include 命令行参数指定的文件.

参数include_next 在找到的指令是一条#include_next 指令且预处理常量BOOST_WAVE_SUPPORT_INCLUDE_NEXT 被定义为非零值时被设为 true.

如果返回值为true, 则不执行该包含指令, 即不加载也不处理要包含的文件. 整条指令会被一个换行字符替换. 如果返回值为false, 指令按正常方式执行.

locate_include_file

    template <typename ContextT>
    bool locate_include_file(ContextT& ctx, std::string &file_path, 
        bool is_system, char const *current_name, std::string &dir_path, 
        std::string &native_name)

函数locate_include_file在遇到一条#include 指令时被调用. 它应当定位给定的文件, 并返回被定位文件的完整文件名. 该文件名应当能够唯一标识被引用的文件.

参数ctx 是对用户实例化预处理迭代器所用的上下文对象的引用.

参数file_path 包含#include 指令后找到的 (已展开的) 文件名. 该参数保存#include 指令中指定的字符串原样, 即<file> 或"file" 会得到参数值 'file'.

参数is_system 被设为true, 如果本次调用是#include <file> 指令的结果; 否则为false, 即对于#include "file" 指令.

参数current_name 仅在遇到#include_next 指令时使用 (且BOOST_WAVE_SUPPORT_INCLUDE_NEXT 被定义为非零值) . 此时它指向当前包含文件 (如果有) 的唯一完整名称. 否则该参数被设为NULL.

参数dir_path 在返回时应当包含被定位文件的目录部分.

参数native_name 在返回时应当包含被定位文件的唯一完整文件名.

返回值定义文件是否被成功定位.

opened_include_file

    template <typename ContextT>
    void opened_include_file(ContextT const& ctx, 
        std::string const &rel_filename, std::string const &abs_filename, 
        bool is_system_include);

函数opened_include_file在一条#include 指令所引用的文件被成功定位并打开时被调用.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数rel_filename 包含被打开文件的 (规范化后的) 可能是相对路径的文件系统路径. 该文件名的具体格式取决于之前提供给库的包含搜索路径的格式.

参数abs_filename 包含被打开文件的 (规范化后的) 完整文件系统路径.

is_system_include 参数表示给定文件是否是作为#include <...> 指令的结果被找到的.

returning_from_include_file

    template <typename ContextT>
    void returning_from_include_file(ContextT const& ctx);

每当一个被包含文件在处理完成后即将被关闭时, 就会调用函数returning_from_include_file.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

detected_include_guard

    template <typename ContextT>
    void detected_include_guard(ContextT const& ctx, 
        std::string const& filename,
        std::string const& include_guard);

每当一个包含文件因检测到包含保护方案而即将被加入 #pragma once 头文件列表时, 函数detected_include_guard 就会被调用. 这意味着该头文件不会再被打开和解析, 即使它在后面的#include 指令中被再次指定.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数filename 包含被打开文件的文件系统路径 (它相对于当前被处理文件的目录, 或者是绝对路径, 取决于作为包含搜索路径给出的路径) .

参数include_guard 包含检测到的包含保护宏的名称.

detected_pragma_once

    template <typename ContextT, typename TokenT>
    void detected_pragma_once(ContextT const& ctx,
        TokenT const& pragma_token,
        std::string const& filename);

函数detected_pragma_once每当一个包含文件因检测到#pragma once 指令而即将被加入 #pragma once 头文件列表时就会被调用. 这意味着该头文件不会再被打开和解析, 即使它在后面的#include 指令中被再次指定.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数 pragma_token 引用触发该预处理钩子的记号 "#pragma".

参数filename 包含被打开文件的文件系统路径 (它相对于当前被处理文件的目录, 或者是绝对路径, 取决于作为包含搜索路径给出的路径) .

#pragma 的解释

interpret_pragma

    template <typename ContextT, typename ContextT, typename ContainerT>
    bool interpret_pragma(ContextT const &ctx, ContainerT &pending, 
        typename ContextT::token_type const &option, 
        ContainerT const &values, 
        typename ContextT::token_type const &pragma_token);

每当在输入流中发现无法识别的#pragma wave ... 或运算符_Pragma("wave ...") 时, 就会调用函数interpret_pragma.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

pending 参数可用于把记号推回输入流, 这些记号将用作整条#pragma wave() 指令的替换文本. 如果该序列留空, 则不进行任何替换, 即被解释的指令会从生成的记号流中移除.

option 参数包含被解释 pragma 的名称.

values 参数保存提供给 pragma 运算符的参数值.

pragma_token 参数包含实际的 #pragma 记号, 可用于提取位置信息以供某些错误输出使用.

如果返回值为 'false', 整个 #pragma 指令将被视为未知并发出相应的错误消息. 返回值 'true' 表示给定的 #pragma 已被成功解释.

宏定义

defined_macro

    template <
        typename ContextT, typename TokenT, typename ParametersT, 
        typename DefinitionT
    >
    void defined_macro(ContextT const& ctx, 
        TokenT const &name, bool is_functionlike,
        ParametersT const &parameters, DefinitionT const &definition,
        bool is_predefined);

每当一个宏被成功定义时, 就会调用函数defined_macro.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数name 是对保存宏名的记号的引用.

每当新定义的宏被定义为类函数宏时, 参数is_functionlike 被设为 true.

参数parameters 保存宏定义的参数记号. 如果宏没有参数, 或者它是类对象宏, 则该容器为空.

参数definition 包含作为新定义宏的替换序列 (定义部分) 给出的记号序列.

对于库初始化阶段预定义的所有宏, 参数is_predefined 被设为 true.

undefined_macro

    template <typename ContextT, typename TokenT>
    void undefined_macro(ContextT const& ctx, TokenT const &name);

每当一个宏定义被成功移除时, 就会调用函数undefined_macro.

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数name 保存其定义被移除的宏的记号.

found_warning_directive

    template <typename ContextT, typename ContainerT>
    bool found_warning_directive(ContextT const& ctx, 
        ContainerT const &message);

函数found_warning_directive 在遇到一条#warning 指令时被调用. 只有当编译期常量BOOST_WAVE_SUPPORT_WARNING_DIRECTIVE 被定义为不等于零的值时才会调用该函数 (更多信息见编译期配置) .

ctx 参数提供对用户实例化预处理迭代器时所用的context_type 的引用.

参数message 引用所遇#warning 指令的参数记号序列.

如果返回值为false, 库会抛出类型为warning_directive 的预处理器异常 (正常执行继续) ; 如果返回值为true, 执行将像没有找到#warning 指令那样继续, 整条指令会被一个换行符替换.

emit_line_directive

    template <typename ContextT, typename ContainerT>
    bool emit_line_directive(ContextT const& ctx, ContainerT &pending, 
        typename ContextT::token_type const& act_token);

函数emit_line_directive在需要把一条#line 指令发到生成的输出中时被调用.

参数ctx 是对用户实例化预处理迭代器所用的上下文对象的引用.

参数pending 可用于把记号推回输入流, 这些记号将替代为#line 指令生成的默认输出.

参数act_token 包含实际的#pragma 记号, 可用于错误输出. 保存在该记号中的行号可以用作#line 指令中发出的行号.

如果返回值为false, 库会发出一条默认的#line 指令. 返回值true 将抑制任何后续动作, pending 中包含的记号会被逐字复制到输出.
