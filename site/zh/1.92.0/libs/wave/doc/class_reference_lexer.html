引言

每个要与Wave 库配合使用的词法分析器都必须返回由输入流形成的记号. 这些记号应当符合记号类型 (The Token Type) 主题中描述的概要. 词法分析器类型应当暴露一个至少符合forward_iterator (按 C++ 标准定义的意义) 并返回记号类型的接口. 下面的代码示例没有展示这个前向迭代器接口的定义, 因为它高度依赖具体实现.

Wave 词法分析器概要 (头文件: wave/cpplexer/cpp_lexer_interface.hpp)

    struct lex_iterator
    {
        typedef boost::wave::lex_token<> token_type;

    // Every lex_iterator should implement at least a complete 
    // forward_iterator interface (not shown here)
        typedef std::forward_iterator_tag iterator_category;

    // additional requirements
        lex_iterator();

        template <typename Iterator>
        lex_iterator(Iterator const &first, Iterator const &last
            typename token_type::position_type const &pos, 
            boost::wave::language_support language)
    };

请注意, lex_iterator 定义于库头文件wave/cpplexer/cpp_lexer_interface.hpp 中, 它实际上是一个模板类, 以要使用的记号类型作为其模板参数. 上面的概要中省略了这一点, 因为它是 Wave 库提供的 Re2C 词法分析器的实现细节.

如果你想把 Wave 与自己的词法分析组件配合使用, 它只需符合上述接口即可.

公共 typedef

除了 C++ 标准为forward_iterator 规定的 typedef 之外, 每个要与Wave 库配合使用的词法分析器还应当定义以下 typedef:

boost::wave::context 类定义的公共 typedef
token_type

词法分析器返回的token 类型. 该类型也用作boost::wave::context 对象提供的主迭代器的返回值.

成员函数

除了 C++ 标准规定应为forward_iterators 提供的函数之外, 每个要与Wave 库配合使用的词法分析器还必须实现以下函数:

构造函数

    lex_iterator();

默认构造函数应构造一个词法分析器迭代器, 它可用作所提供迭代器范围的结束迭代器.

    template <typename Iterator>
    lex_iterator(Iterator const &first, Iterator const &last,
        typename token_type::position_type const &pos, 
        boost::wave::language_support language);

第二个构造函数应构造一个词法分析器迭代器, 它可用作遍历由词法分析器类生成的记号序列的迭代器.

迭代器对first 和last 应当表示要由给定词法分析器类进行记号化的输入流.

参数pos 包含用于记号生成的初始位置信息.

参数language 控制初始化词法分析器所需的模式.
