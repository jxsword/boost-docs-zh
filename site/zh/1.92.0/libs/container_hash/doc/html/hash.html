引言

boost::hash 是对 C++11 规定的 哈希函数 对象 std::hash 的一个增强实现. 它是 Boost.Unordered、Boost.Intrusive 的无序关联容器、Boost.MultiIndex 的哈希索引以及 Boost.Bimap 的 unordered_set_of 的默认哈希函数.

开箱即用, boost::hash 支持

  • 标准整数类型 (整数、字符类型与 bool);

  • 标准浮点类型 (float, double, long double);

  • 指针 (指向对象与函数, 但不包括成员指针) 与 nullptr;

  • 枚举类型;

  • C 数组;

  • std::complex;

  • 类元组类型, 例如 std::pair, std::tuple, 以及特化了 std::tuple_size 并提供 get<I> 的用户自定义类型;

  • 类序列类型, 包括标准与用户自定义的 (类序列类型具有返回迭代器的 begin() 与 end() 成员函数);

  • 无序序列, 标准或用户自定义的 (哈希值不依赖元素顺序的序列, 例如 std::unordered_set 与 std::unordered_map);

  • 被描述的结构体与类 - 即已用 BOOST_DESCRIBE_STRUCT 或 BOOST_DESCRIBE_CLASS 宏加以注解的类型 (宏来自 Boost.Describe);

  • std::unique_ptr, std::shared_ptr;

  • std::type_index;

  • std::error_code, std::error_condition;

  • std::optional;

  • std::variant, std::monostate.

boost::hash 是可扩展的; 用户自定义类型 X 可以使自身可经由 boost::hash<X> 进行哈希, 方法是定义函数 hash_value 的适当重载. 许多 (即便不是大多数) Boost 类型已经包含了必要的支持.

boost::hash 满足 C++11 标准对 std::hash 规定的要求, 即: 对两个不同的输入值, 其对应的哈希值要么保证不同, 要么相同 (哈希冲突) 的概率很小. 标准无序容器以及基于哈希的 Boost 容器, 都设计为能与这类哈希函数良好配合.

boost::hash 不满足在更一般语境中常对哈希函数提出的更强要求. 特别是, 该哈希函数不是密码学安全的, 对蓄意的攻击者不具备抗冲突性, 也未必具有良好的"雪崩"性质; 也就是说, 输入中的微小 (单比特) 扰动不一定导致输出中的巨大 (半数比特改变) 扰动.

特别是, boost::hash 传统上对所有能放入 std::size_t 的整数类型都是恒等函数, 因为这保证无冲突且速度最快.

近期变更

Boost 1.92.0

  • 对无值的 std::variant 实例进行哈希不再抛出异常.

Boost 1.89.0

  • 新增了 hash_is_avalanching 特征类.

Boost 1.84.0

  • 不再支持 C++03.

Boost 1.82.0

  • 新增了 hash_value 对 std::nullptr_t 的一个重载.

  • 新增 is_tuple_like, 并为类元组类型新增了 hash_value 的重载.

  • 字符串哈希改为使用 mulxp1_hash, 质量与速度均得到提升. 这改变了类字符串类型 (char, signed char, unsigned char, std::byte, char8_t 的范围) 的哈希值.

Boost 1.81.0

重大更新.

  • boost::hash 的特化已被移除; 它现在总是调用 hash_value.

  • 对 BOOST_HASH_NO_EXTENSIONS 的支持已被移除. 扩展始终启用.

  • 现在支持所有标准容器. 包括 std::forward_list 与无序关联容器.

  • 用户自定义容器 (具有返回迭代器的 begin() 与 end() 成员函数的类型) 现在开箱即受支持.

  • 被描述的结构体与类 (用 BOOST_DESCRIBE_STRUCT 或 BOOST_DESCRIBE_CLASS 注解的类型) 现在开箱即受支持.

  • hash_combine 已得到改进. 这会改变复合类型 (容器与元组) 以及大于 size_t 的标量类型的哈希值.

  • 字符串哈希的性能 (以及质量, 得益于上述变更) 已得到改进. 字符串的 boost::hash 现在在 64 位模式下通过了 SMHasher.

  • 文档已大幅修订以反映这些变更.

Boost 1.78.0

  • 修复了 hash_combine, 使其行为不再依赖于 size_t 是否与 boost::uint64_t 完全同型 (在 macOS 上并非如此). 这会改变 macOS 上复合类型 (容器与元组) 的哈希值.

教程

使用 Boost.Unordered 这类 Boost 容器时, 无需做任何事即可使用 boost::hash, 因为它就是默认哈希函数. 要了解如何使用用户自定义类型, 请阅读 为用户类型扩展 boost::hash 一节.

若想把 boost::hash 与标准无序关联容器配合使用, 请将其作为模板参数传入:

std::unordered_multiset<int, boost::hash<int> >
        set_of_ints;

std::unordered_set<std::pair<int, int>, boost::hash<std::pair<int, int> > >
        set_of_pairs;

std::unordered_map<int, std::string, boost::hash<int> > map_int_to_string;

要直接使用 boost::hash, 创建一个实例并像函数一样调用它:

#include <boost/container_hash/hash.hpp>

int main()
{
    boost::hash<std::string> string_hash;
    std::size_t h = string_hash("Hash me");
}

或者也可以:

#include <boost/container_hash/hash.hpp>

int main()
{
    std::size_t h = boost::hash<std::string>()("Hash me");
}

作为泛型用法的示例, 下面是一个生成 vector 的函数, 该 vector 包含容器各元素的哈希值:

template <class Container>
std::vector<std::size_t> get_hashes(Container const& x)
{
    std::vector<std::size_t> hashes;
    std::transform(x.begin(), x.end(), std::back_inserter(hashes),
        boost::hash<typename Container::value_type>());

    return hashes;
}

为用户类型扩展 boost::hash

boost::hash 的实现方式是调用函数 hash_value. 该命名空间未加限定, 以便通过实参相关查找探测重载. 因此, 若在用户类型所在的命名空间中有自由函数 hash_value, 它就会被调用.

如果你有一个结构 library::book, 其中每本书由其成员 id 唯一确定:

namespace library
{
    struct book
    {
        int id;
        std::string author;
        std::string title;

        // ....
    };

    bool operator==(book const& a, book const& b)
    {
        return a.id == b.id;
    }
}

那么你所需做的就是编写函数 library::hash_value:

namespace library
{
    std::size_t hash_value(book const& b)
    {
        boost::hash<int> hasher;
        return hasher(b.id);
    }
}

现在你可以对 book 使用 boost::hash 了:

library::book knife(3458, "Zane Grey", "The Hash Knife Outfit");
library::book dandelion(1354, "Paul J. Shanley",
    "Hash & Dandelion Greens");

boost::hash<library::book> book_hasher;
std::size_t knife_hash_value = book_hasher(knife);

// If std::unordered_set is available:
std::unordered_set<library::book, boost::hash<library::book> > books;
books.insert(knife);
books.insert(library::book(2443, "Lindgren, Torgny", "Hash"));
books.insert(library::book(1953, "Snyder, Bernadette M.",
    "Heavenly Hash: A Tasty Mix of a Mother's Meditations"));

assert(books.find(knife) != books.end());
assert(books.find(dandelion) == books.end());

完整示例见 examples/books.hpp 与 examples/books.cpp.

提示
 编写哈希函数时, 首先考察相等函数如何工作. 相等的对象必须产生相同的哈希值. 不相等的对象应当产生不同的哈希值. 此处对象的相等仅基于 id, 因此哈希函数只对 id 做哈希. 若相等基于对象的名称与作者, 哈希函数就应把它们考虑在内 (如何做到这一点将在下一节讨论).

合并哈希值

假设你有一个 point 类, 表示二维位置:

class point
{
    int x;
    int y;

public:

    point() : x(0), y(0) {}
    point(int x, int y) : x(x), y(y) {}

    bool operator==(point const& other) const
    {
        return x == other.x && y == other.y;
    }
};

并且你想把它用作某个 unordered_map 的键. 你需要为该结构定制哈希. 为此需要合并 x 与 y 的哈希值. 函数 boost::hash_combine 正是为此而提供的:

class point
{
    ...

    friend std::size_t hash_value(point const& p)
    {
        std::size_t seed = 0;

        boost::hash_combine(seed, p.x);
        boost::hash_combine(seed, p.y);

        return seed;
    }

    ...
};

对 hash_combine 的调用会以 point 的不同成员逐步构建哈希值, 它可以针对任意数量的元素被反复调用. 它对提供的元素调用 hash_value, 并将其与种子合并.

本示例的完整代码位于 examples/point.cpp.

注意, 使用 boost::hash_combine 时调用的顺序很重要.

std::size_t seed = 0;
boost::hash_combine(seed, 1);
boost::hash_combine(seed, 2);

以及

std::size_t seed = 0;
boost::hash_combine(seed, 2);
boost::hash_combine(seed, 1);

会在 seed 中产生不同的值.

要计算迭代器范围的哈希, 可以使用 boost::hash_range:

std::vector<std::string> some_strings;
std::size_t hash = boost::hash_range(some_strings.begin(), some_strings.end());

由于 hash_range 的工作方式是对范围元素反复调用 hash_combine, 哈希值也会依赖于元素的顺序.

如果你在为数据顺序无关的范围 (例如 unordered_set) 计算哈希值, 可以改用 boost::hash_unordered_range.

std::unordered_set<std::string> set;
std::size_t hash = boost::hash_unordered_range(set.begin(), set.end());

编写模板类时, 你可能不想包含 hash.hpp 主头文件, 因为它的包含代价相当高, 会带入许多其他头文件; 此时可以改为包含 <boost/container_hash/hash_fwd.hpp> 头文件, 它前置声明了 boost::hash, boost::hash_combine, boost::hash_range 与 boost::hash_unordered_range. 在实例化 boost::hash 之前, 你需要包含主头文件. 使用依赖 boost::hash 的容器时, 它应当会替你完成这一点, 因此你的类型可以与 Boost 哈希容器正常配合. 相关示例见 examples/template.hpp 与 examples/template.cpp.

为避免连 hash_fwd.hpp 也包含 - 它仍要求 Boost.ContainerHash 的内容实际存在 - 你可以把 hash_fwd.hpp 中的声明 (且仅这些声明) 直接复制到你自己的头文件中. 这是本库保证的一个特例; 一般而言, 声明库函数 (无论 Boost 还是其他) 都有在后续发布版中损坏的风险.

用 Boost.Describe 对用户类型进行哈希

再来看看我们的 point 类:

class point
{
    int x;
    int y;

public:

    point() : x(0), y(0) {}
    point(int x, int y) : x(x), y(y) {}
};

如果你使用 C++14 或更高版本, 把 boost::hash 支持添加到 point 的一个容易得多的办法是使用 Boost.Describe (并免费获得 operator== 的自动定义):

#include <boost/describe/class.hpp>
#include <boost/describe/operators.hpp>

class point
{
    int x;
    int y;

    BOOST_DESCRIBE_CLASS(point, (), (), (), (x, y))

public:

    point() : x(0), y(0) {}
    point(int x, int y) : x(x), y(y) {}
};

using boost::describe::operators::operator==;
using boost::describe::operators::operator!=;

(本示例的完整代码位于 examples/point2.cpp.)

由于 point 类已用 BOOST_DESCRIBE_CLASS 注解, 库可以枚举其成员 (及基类) 并自动为其合成适当的 hash_value 重载, 无需我们动手.

hash_combine

template<class T> void hash_combine( std::size_t& seed, T const& v );

被反复调用, 以从多个变量增量构建哈希值.

效果:

以一个新哈希值更新 seed, 该新值由其当前值与 boost::hash<T>()(v) 的结果确定性合并产生.

抛出:

仅当 boost::hash<T>()(v) 抛出异常时才抛出. 发生异常时, seed 不会被更新.

备注:

等价于 seed = combine(seed, boost::hash<T>()(v)), 其中 combine(s, v) 是一个混合函数, 它接受两个 std::size_t 类型的实参并返回 std::size_t, 且具有下列理想性质:

  1. 对固定的 s, 当 v 取遍所有可能的 size_t 值时, combine(s, v) 也应取遍所有可能的 size_t 值, 产生一个接近随机的序列; 也就是说, 它应当是一个随机排列.

    这保证了对给定的 seed, combine 在 boost::hash<T>(v) 未产生哈希冲突的情况下不会引入哈希冲突; 也就是说, 它不会丢失输入的信息. 它还意味着 combine(s, v) 作为 v 的函数具有良好的雪崩性质; 即输入 v 中的微小扰动 (例如单比特) 会导致返回值的大幅扰动 (平均而言一半的输出比特发生改变).

  2. 对两个不同的种子 s1 与 s2, combine(s1, v) 与 combine(s2, v) 作为 v 的函数, 应产生两个不同的随机排列.

  3. combine(0, 0) 不应为 0. 由于 seed 的常见初始值为零, combine(0, 0) == 0 将意味着对任意长度的全零序列应用 hash_combine 都会产生零. 这是不可取的, 因为它会导致例如 std::vector<int>() 与 std::vector<int>(4) 拥有相同的哈希值.

当前实现使用函数 mix(s + 0x9e3779b9 + v) 作为 combine(s, v), 其中 mix(x) 是一个高质量的混合函数, 它是 std::size_t 各取值上的双射, 形如

x ^= x >> k1;
x *= m1;
x ^= x >> k2;
x *= m2;
x ^= x >> k3;

其中常量 k1, k2, k3, m1, m2 经过恰当选取.

注意 mix(0) 为 0. 这就是为什么要加上任意常量 0x9e3779b9 以满足上面的第三条要求.

hash_range

template<class It> void hash_range( std::size_t& seed, It first, It last );
效果:

当 typename std::iterator_traits<It>::value_type 不是 char, signed char, unsigned char, std::byte 或 char8_t 时,

for( ; first != last; ++first )
{
    boost::hash_combine<typename std::iterator_traits<It>::value_type>( seed, *first );
}

否则, 来自 [first, last) 的字节会以未指明方式合并后再哈希. 这样做是为了在哈希字符串时提升性能.

备注:

对 char 而言, 当前实现使用 mulxp1_hash (当 std::size_t 为 64 位时), 以及 mulxp1_hash32 (当其为 32 位时).

效果:

boost::hash_range( seed, first, last );
return seed;

设计与实现说明

哈希函数的质量

许多哈希函数力求输入值与输出值之间几乎没有相关性. 它们试图让非常相似的输入产生均匀分布的输出值. 本哈希函数不做这种尝试. 事实上, 对整数而言, 哈希函数的结果往往就是输入值本身. 因此相似但不同的输入值往往会得到相似但不同的输出值. 这意味着它不适合作为通用哈希函数. 例如, 哈希表可能会丢弃哈希函数结果的一些比特, 从而导致高概率冲突, 或在哈希值聚集时冲突消解效果不佳. 在这类情况下, 本哈希函数表现不佳.

但标准对哈希函数没有这样的要求, 它只要求两个不同值的哈希不太可能冲突. 为配合标准哈希函数而设计的容器或算法, 必须实现为在哈希函数输出与其输入相关时也能良好工作. 既然它们已经付出了这一代价, 更高质量的哈希函数反而会造成浪费.

hash_value 定制点

为用户类型定制标准 std::hash 函数对象的方式是特化. boost::hash 选择了不同的机制 - 在用户命名空间中定义自由函数 hash_value 的重载, 经由实参相关查找找到.

两种方式各有利弊. 特化函数对象更为严格, 因为它只适用于精确类型, 不适用于派生或可转换类型. 而定义函数则更容易、更方便, 因为可以直接在类型定义中以 inline friend 的形式完成.

重载可以经转换被调用这一事实, 在本库早先的迭代中确实引发过问题, 当时的版本为所有整数类型分别定义了 hash_value (其中包括 bool). 特别是在没有 explicit 转换运算符的 C++03 下, 一些类型可转换为 bool 以便在例如 if 语句中被测试, 这导致它们被哈希成 0 或 1, 很少是人们期望或想要的结果.

不过, 这一问题已通过把内建 hash_value 重载声明为受 (例如 std::is_integral 或其等价物) 约束的模板而得到修复. 这使得可转换为整数的类型不再匹配, 从而避免了该问题.

哈希值的稳定性

一般而言, 本库不承诺哈希值在版本之间保持不变 (否则改进将无从谈起). 不过, 历史上这些值一直相当稳定. 在 1.81 发布版之前, 此前的变更发生在 1.56 (更好的 hash_combine) 与 1.78 (针对 hash_combine 的 macOS 特定变更).

代码通常不应依赖特定的哈希值, 但对愿意承担因哈希值变化而偶发中断风险的人来说, 本库现在有一个测试, 它把若干类型的哈希值与参考值 (test/hash_reference_values.cpp) 进行核对, 其 版本历史 可以粗略地指示哈希值何时发生变化以及涉及哪些类型.

hash_combine

本库的最初实现基于 库扩展技术报告问题清单 的 Issue 6.18 (第 63-67 页), 其中提出了如下 hash_combine 实现:

template<class T>
void hash_combine(size_t & seed, T const & v)
{
    seed ^= hash_value(v) + (seed << 6) + (seed >> 2);
}

取自 Timothy C. Hoad 与 Justin Zobel 的论文 "Methods for Identifying Versioned and Plagiarised Documents".

在 Boost 正式评审期间, Dave Harris 指出这一方案存在所谓的"零陷阱"; 若 seed 初始为 0, 且所有输入都为 0 (或哈希为 0), 则无论合并多少个输入值, seed 都保持为 0.

这是一个不理想的性质, 因为它导致全零容器无论大小如何, 哈希值都为零.

为修复此问题, 计算中加入任意常量 0x9e3779b9 (32 位定点表示下的黄金比率), 得到

template<class T>
void hash_combine(size_t & seed, T const & v)
{
    seed ^= hash_value(v) + 0x9e3779b9 + (seed << 6) + (seed >> 2);
}

这就是随 Boost 1.33 - 包含本库的第一个发布版 - 交付的版本.

在其所处时代, 当输入由 char 组成时, 该函数是质量与速度之间的合理折中; 但对合并任意 size_t 输入而言, 它就不那么合适了.

在 Boost 1.56 中, 它被从 Austin Appleby 的 MurmurHash2 哈希函数轮次 派生的函数取代.

在 Boost 1.81 中, 它再次变更 - 等价于 mix(seed + 0x9e3779b9 + hash_value(v)), 其中 mix(x) 是一个高质量的混合函数, 它是 size_t 各取值上的双射, 形如

x ^= x >> k1;
x *= m1;
x ^= x >> k2;
x *= m2;
x ^= x >> k3;

这类混合函数最初由 Austin Appleby 设计, 作为其 MurmurHash3 哈希函数的"最终混合"部分. 他使用

x ^= x >> 33;
x *= 0xff51afd7ed558ccd;
x ^= x >> 33;
x *= 0xc4ceb9fe1a85ec53;
x ^= x >> 33;

作为 64 位函数 fmix64, 并使用

x ^= x >> 16;
x *= 0x85ebca6b;
x ^= x >> 13;
x *= 0xc2b2ae35;
x ^= x >> 16;

作为 32 位函数 fmix32.

64 位函数随后出现了多个改进版本, 分别由 David Stafford, Pelle Evensen 与 Jon Maiga 提出. 我们目前使用 Jon Maiga 的函数

x ^= x >> 32;
x *= 0xe9846af9b1a615d;
x ^= x >> 32;
x *= 0xe9846af9b1a615d;
x ^= x >> 28;

在 32 位下, 我们使用 "TheIronBorn" 在 Chris Wellons 的 Hash Prospector 仓库 的一个 Github issue 中提出的混合函数:

x ^= x >> 16;
x *= 0x21f0aaad;
x ^= x >> 15;
x *= 0x735a2d97;
x ^= x >> 15;

有了改进后的 hash_combine, 字符串的 boost::hash 现在能通过 Austin Appleby 的 SMHasher 测试套件 (在 64 位 size_t 下).

hash_range

hash_range(seed, first, last) 的传统实现一直是

for( ; first != last; ++first )
{
    boost::hash_combine<typename std::iterator_traits<It>::value_type>( seed, *first );
}

(需要显式模板实参以支持具有代理返回类型的迭代器, 例如 std::vector<bool>::iterator.)

这在逻辑上合理、一致且直接. 但在 typename std::iterator_traits<It>::value_type 为 char 的常见情形 - 即 boost::hash<std::string> 的常见情形 - 下, 这会损失大量性能, 因为逐个处理 char 远不如批量处理多个元素高效.

在 Boost 1.81 中, hash_range 被改为一次处理四个 char, signed char, unsigned char, std::byte 或 char8_t 类型的元素. uint32_t 由 first[0] 到 first[3] 组合而成, 再把该 uint32_t 喂给 hash_combine.

在 Boost 1.82 中, 这些类型的 hash_range 被改为使用 mulxp1_hash. 这同时提升了字符串哈希的质量与速度.

注意, hash_range 传统上也保证相同的元素序列无论迭代器类型如何都会产生相同的哈希值. 在对 char 范围哈希做出变更后, 这一性质依然成立. 把 hash_range 应用于 char 序列 { 'a', 'b', 'c' }, 无论该序列来自 char[3], std::string, std::deque<char> 还是 std::list<char>, 结果值都相同.

Boost 1.44.0

  • 新增选项: 阻止调用 hash_value 时发生隐式转换, 方法是定义 BOOST_HASH_NO_IMPLICIT_CASTS. 当对某个使用 boost::hash 的类型而言, 它没有声明 hash_value, 但确实能隐式转换为拥有相应声明的类型时, 它会使用该隐式转换来哈希. 这有时会错得很离谱, 例如转换为 bool 后只有 2 种可能的哈希值. 由于修复它是破坏性变更, 且在发布周期接近尾声时才被提出、讨论甚少, 目前为可选启用. 这一机制或类似机制将在未来版本中成为默认.
