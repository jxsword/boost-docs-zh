概述

类 file_descriptor_source、file_descriptor_sink 与 file_descriptor 通过操作系统文件句柄或文件描述符提供文件访问. 这些 设备 的行为与 文件包装器 basic_file_source、basic_file_sink 与 basic_file 非常相似, 但有以下重要区别:

  • 文件描述符设备可以用已经打开的文件描述符构造.
  • 唯一的 缓冲由 Boost Iostreams 库提供.
  • 没有自动的行尾转换.
  • 不支持宽字符流.

复制文件描述符设备时, 结果表示同一个底层文件描述符. 底层文件描述符不会被复制.

类 file_descriptor 在底层操作系统或运行库支持 64 位寻位偏移时即予支持. 目前, 文件描述符设备对以非阻塞模式打开的文件描述符可能无法正确工作.

如有需要, 可使用类 newline_filter 提供行尾转换. 使用模板 code_converter 可如下定义宽字符版本的文件描述符设备: 

    #include <boost/iostreams/code_converter.hpp>
    #include <boost/iostreams/maped_file.hpp>

    typedef code_converter<file_descriptor_source>  wfile_descriptor_source;
    typedef code_converter<file_descriptor_sink>    wfile_descriptor_sink;

致谢

文件描述符设备基于 Nicolai Josuttis 的工作 ([Josuttis1] pp. 672-3 与 [Josuttis2]).

安装

文件描述符设备依赖源文件 <libs/iostreams/src/file_descriptor.cpp>, 该文件会根据用户的操作系统使用 Windows 或 POSIX 头文件. 安装说明参见 安装.

参考

类 file_descriptor_source

说明

SeekableSource 与 Closable 的模型, 通过操作系统文件描述符提供对文件的只读访问.

概要

namespace boost { namespace iostreams {

enum file_descriptor_flags {
    never_close_handle,
    close_handle
};

class file_descriptor_source {
public:
    typedef char                      char_type;
    typedef [implementation-defined]  handle_type;
    typedef [implementation-defined]  category;
    file_descriptor_source();
    template<typename Path>
    file_descriptor_source( const Path& pathname,
                            std::ios_base::open_mode mode = 
                                std::ios_base::in );
    file_descriptor_source( int fd, file_descriptor_flags );

    // Windows-only
    file_descriptor_source( HANDLE hFile, file_descriptor_flags );

    // Deprecated
    file_descriptor_source( int fd, bool close_on_exit = false );

    // Deprecated, Windows-only
    file_descriptor_source( HANDLE hFile, bool close_on_exit = false );

    template<typename Path>
    void open( const Path& pathname,
                     std::ios_base::open_mode mode = 
                         std::ios_base::in );
    void open( int fd, file_descriptor_flags );   

    // Windows-only
    void open( HANDLE hFile, file_descriptor_flags );

    // Deprecated
    void open( int fd, bool close_on_exit = false );   

    // Deprecated, Windows-only
    void open( HANDLE hFile, bool close_on_exit = false );

    bool is_open() const;

    handle_type handle() const;
};

} } // End namespace boost::io

    file_descriptor_source();

    // Windows-only
    file_descriptor_source( HANDLE hFile, file_descriptor_flags );

第一个成员构造一个空的 file_descriptor_source.

第二个成员构造一个 file_descriptor_source, 访问具有给定路径名的文件. Path 应为字符串或 Boost.Filesystem 路径. 参数 mode 的含义与 (mode | std::ios_base::in) 在 std::basic_filebuf::open 中相同.[1]

第三个成员构造一个 file_descriptor_source, 访问具有给定操作系统或运行库文件描述符的文件. 若第二参数为 close_handle, 则当被构造的 file_descriptor_source (或其副本之一) 被关闭或销毁时, 该文件描述符会被关闭.

第四个成员与第三个相同, 只是它接受 Windows 文件句柄而非文件描述符. 若第二参数为 close_handle, 则当被构造的 file_descriptor_source (或其副本之一) 被关闭或销毁时, 该文件描述符会被关闭.

这些已弃用的成员用于提供与旧版本的向后兼容. 要使用它们, 需要定义 BOOST_IOSTREAMS_USE_DEPRECATED. 描述符总是由 close 关闭, 但只有在 close_on_exit 为 true 时才会在析构函数中关闭.

file_descriptor_source::open

    template<typename Path>
    void open( const Path& pathname,
                     std::ios_base::open_mode mode = 
                         std::ios_base::in );
    void open( int fd, file_descriptor_flags );

    // Windows-only
    void open( HANDLE hFile, file_descriptor_flags );

    // Deprecated
    void open( int fd, bool close_on_exit = false );

    // Deprecated, Windows-only
    void open( HANDLE hFile, bool close_on_exit = false );

open 的参数与相应构造函数的参数相同. 若文件描述符已持有文件, 该文件将被关闭 (除非是以 never_close_handle 打开或构造的).

file_descriptor_source::is_open

    bool is_open() const;

返回 true, 若底层文件已成功打开.

file_descriptor_source::handle

    handle_type handle() const;

返回底层 OS 文件描述符. 在 Windows 上这是一个 HANDLE; 在其他系统上它是一个 int.
