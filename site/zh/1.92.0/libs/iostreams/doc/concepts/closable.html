Closable

说明

Closable 过滤器或设备会在包含它的流或流缓冲被关闭之前收到通知.

动机

C++ 标准库没有"任意流或流缓冲处于 打开或关闭状态"的概念. 然而对 Iostreams 库而言, 打开和关闭流与流缓冲的概念十分重要. 某些过滤器和设备为流末尾保留了特殊行为 — 例如, 一个 OutputFilter 可能会以换行字符结束每个数据序列. 另一些过滤器或设备会在一系列 I/O 操作期间维护状态, 在过滤器或设备被复用之前必须重置这些状态. 这类过滤器和设备需要在流被关闭之前收到通知, 并应满足 Closable.

关闭通知

Iostreams 库通过调用函数 close 发送关闭通知. 对大多数 Closable 过滤器或设备, close 委托给成员函数 close; 对非 Closable 设备, close 调用 flush. 细节 — 即 close 何时以及如何被调用 — 比较复杂. 不过, 定义一个接收关闭通知的过滤器或设备却很容易, 如下面几节所示.

单序列设备

如果设备控制单个字符序列, 只需指定一个 类别标签 — 它可转换为 closable_tag — 并添加成员函数 close, 即可使其成为 Closable, 如下:

    void close() {  /* process closure notification */  }

从 便利模板与 typedef 派生的过滤器和设备, 会自动获得可转换为 closable_tag 的类别标签.

单序列过滤器

对于控制单个序列的过滤器, close 的签名为:

    template<typename Device>
    void close(Device&);

双序列设备

如果设备控制相互独立的输入和输出序列, close 的签名为:

    void close(std::ios_base::openmode);

此函数会被调用两次: 第一次以 std::ios_base::in 为参数, 表示输入序列关闭; 稍后以 std::ios_base::out 为参数, 表示输出序列关闭.

双序列过滤器

如果过滤器控制相互独立的输入和输出序列, close 的签名为:

    template<typename Device>
    void close(Device&, std::ios_base::openmode);

此函数会被调用两次: 第一次以 std::ios_base::in 为参数, 表示输入序列关闭; 稍后以 std::ios_base::out 为参数, 表示输出序列关闭.

双用途过滤器

close 在 DualUserFilters 中的签名与双序列过滤器的相同:

    template<typename Device>
    void close(Device&, std::ios_base::openmode);

此函数只会被调用一次, 取决于过滤器是用于输入还是输出.

异常

执行 close 期间发生的错误通过抛出异常来指示. 若此类异常在流或流缓冲析构函数执行期间发生, 则会被捕获并忽略.
