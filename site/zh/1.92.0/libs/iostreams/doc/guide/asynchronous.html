3.6 异步与非阻塞 I/O

概述

Boost.Iostreams 提供的 Filter 与 设备 概念经过设计, 允许 Boost.Iostreams 的未来版本支持异步与非阻塞 I/O. 实现方式是: 为函数 get、read、put 与 write 提供一种手段, 用于在尚未到达流末尾且未发生错误的情况下, 表明产生的或消费的字符少于请求量. 我们将这种指示称为 暂时失败通知. 主要挑战来自函数 get: 为了允许 get 表明输入暂时不可用, 必须引入类模板 boost::iostreams::char_traits — 它是 std::char_traits 的替代品, 多了一个成员函数 would_block.

完整细节参见 Filter 与 设备 概念的定义.

设备

当前的设备概念可以处理非阻塞 I/O, 但不能处理异步 I/O; 要完整支持异步 I/O, 还需要更多设备概念. 这在预料之中, 因为同步设备与异步设备的工作方式差别很大. 参见 Blocking.

过滤器

允许过滤器传播暂时失败通知: 如果下游设备消费或产生的字符少于过滤器请求的数量, 且因此过滤器无法满足读或写请求, 则过滤器可以返回一个值, 表明输入或输出暂时不可用. 希望这一能力足以让当前的过滤器概念既用于异步 I/O 也用于非阻塞 I/O. 然而, 为了同样适用于阻塞 I/O, 过滤器绝不能返回暂时失败通知, 除非它已从下游设备收到这样的通知. 这一要求可概括为: 过滤器必须是 保持阻塞 的. 参见 Blocking.

流与流缓冲

尽管 Boost.Iostreams 的 Filter 与设备概念可以容纳非阻塞 I/O, 但 C++ 标准库的流和流缓冲接口做不到, 因为它们缺乏区分满足读或写请求的暂时失败与永久失败的手段. 因此, 非阻塞设备无法与模板 stream、stream_buffer、filtering_stream 与 filtering_streambuf 正常配合工作.
