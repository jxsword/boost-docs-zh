Iostreams 库的基本构件是以下概念: Source — 提供对字符序列的读访问; Sink — 提供对字符序列的写访问; InputFilter — 过滤从源读取的输入; 以及 OutputFilter — 过滤写入汇的输出. Source、Sink 及其细化称为 设备. InputFilter、OutputFilter 及其细化称为 过滤器.

标准流和流缓冲是设备; 例如, 输入流是 源, 输出流是 汇.[1]

一般而言, 过滤器或设备可以提供对 输入序列 的访问 (用于读取)、对 输出序列 的访问 (用于写入), 或两者兼备. 两个序列之间的关系, 以及可对它们执行的操作, 取决于过滤器或设备类型. 输入与输出之间的各种可能关系称为 模式.[2] Iostreams 库为八种模式各提供一个设备概念和一个过滤器概念. Source、Sink、InputFilter 与 OutputFilter 对应于模式 input 与 output, 是过滤器和设备概念中迄今最重要的.

最常见的设备和过滤器概念单独成文. 刚接触 Iostreams 库的读者应先熟悉四个核心概念: Source、Sink、InputFilter 与 OutputFilter. 过滤器和设备概念的全部要求汇总在概念 Device 与 Filter 的定义中, 它们是概念层次结构的根.

为简化定义新过滤器和设备类型的任务, Iostreams 库提供了许多 便利模板与 typedef .

设备概念

最重要的设备概念如下:

  • Device: 所有设备概念的基, 提供关联的字符类型与类别.
  • Source: 提供对字符序列的只读访问.
  • Sink: 提供对字符序列的只写访问.
  • BidirectionalDevice: 提供对两个相互独立的字符序列的访问, 一个用于读取, 另一个用于写入.
  • SeekableDevice: 提供对单个字符序列的读写访问, 只有一个可重新定位的读/写头.

过滤器概念

最重要的过滤器概念如下:

  • Filter: 所有过滤器概念的基, 提供关联的字符类型与类别.
  • InputFilter: 过滤从源读取的字符.
  • OutputFilter: 过滤写入汇的字符
  • BidirectionalFilter: 过滤两个相互独立的字符序列: 一个从汇读取, 另一个写入汇.
  • SeekableFilter: 过滤由 SeekableDevice 控制的单个字符序列, 通过单个可重新定位的读/写头提供过滤后的输入、输出和随机访问

可选行为

Boost.Iostreams 提供了若干概念, 对应于过滤器或设备可能实现的可选行为:

  • Blocking: 一种设备, 在收到读或写请求时会阻塞, 直到所有请求的字符都可用, 或到达流末尾.
  • Direct: 一种设备, 以内存区域的形式提供对其受控序列的访问, 而非经由类套接字接口.
  • Closable: 一种过滤器或设备, 在流被关闭之前立即收到通知.
  • Flushable 一种过滤器或设备, 在流被刷新时收到通知.
  • Localizable: 一种过滤器或设备, 当流或流缓冲的 locale 被使用 basic_ios::imbue 或 basic_streambuf::pubimbue 设置时收到通知.
  • Multi-Character: 一种过滤器, 经由类套接字接口一次提供对其受控序列中若干个字符的访问.
  • OptimallyBuffered 一种过滤器或设备, 若用户未显式请求缓冲区大小, 将为其配备自定义大小的缓冲区.
  • Peekable: 一种源, 允许将字符回退到输入序列.
  • Pipable: 一种过滤器, 可以出现在 管道中.

便利模板与 typedef

Iostreams 库提供了若干模板, 供用户自定义的过滤器和设备类型派生. 它们通过提供成员类型和若干成员函数的默认实现, 简化了定义过滤器和设备的任务.

模板 device 及其特化 source 与 sink 帮助用户定义新的设备类型; 模板 filter 及其特化 input_filter 与 output_filter 帮助用户定义新的过滤器类型; 模板 multichar_filter 及其特化 multichar_input_filter 与 multichar_output_filter 帮助用户定义新的多字符过滤器类型. 这些模板还有宽字符版本 wdevice、wfilter 与 multichar_wfilter, 以及相应的宽字符 typedef.

[2]更精确的定义见 模式.
