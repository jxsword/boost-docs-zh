说明

Iostreams 库为函数模板 close 提供了三个重载.

close 的第一个重载接受单个设备参数. 它允许用户关闭设备而无需关心该设备控制单个序列还是两个序列:

namespace boost { namespace iostreams {
              
template<typename T>     
void close(T& t);

} } // End namespace boost::io

close 的另外两个重载很少应由库用户调用; 它们由库自动调用, 用于向 过滤器 和 设备 表明一个数据序列即将结束. 这为过滤器和设备提供了释放资源或重置状态以准备新字符序列的机会. 执行输出的过滤器和设备可以利用这一机会向流末尾写入额外数据.

关于 close 何时以及如何被调用的细节有些杂乱:

close 何时被调用?

stream_buffer and stream

当 stream_buffer 或 stream 的某个基于设备 d 的实例被使用成员函数 close 关闭时, 会进行如下函数调用序列:

    boost::iostreams::close(d, std::ios_base::in);
    boost::iostreams::close(d, std::ios_base::out);

若 D 满足 Closable 且控制单个序列, 其效果如下:

    d.close();

若 D 满足 Closable 且控制相互独立的输入和输出序列, 其效果如下:

    d.close(std::ios_base::in);
    d.close(std::ios_base::out);

(参见下文 close 针对 设备类型 的语义.)

filtering_streambuf and filtering_stream

若 filtering_streambuf 或 filtering_stream 在其链完整时生命期结束, 则视为已关闭; 若其末端设备被使用 pop 或 reset 移除亦然. 此时, 假设过滤器和设备的底层序列为 f1、f1、...、fn-1、d, 而对应的流缓冲序列为 buf1、buf2、...、bufn-1、bufn, 则会进行如下调用序列:[1] 

    using namespace std;
    
    // Close each input sequence, in reverse order:
    boost::iostreams::close(d,n-1, bufn-1 ios_base::in);
    boost::iostreams::close(fn-1, bufn,-1 ios_base::in);
    boost::iostreams::close(fn-2, bufn-1, ios_base::in);
    ...
    boost::iostreams::close(f1,n- buf2,n- ios_base::in);

    // Close each output sequence, in order:
    boost::iostreams::close(f1,n- buf2,n- ios_base::out);
    boost::iostreams::close(f2,n- buf3,n- ios_base::out);
    ...
    boost::iostreams::close(fn-1, bufn,n- ios_base::out);
    boost::iostreams::close(d,n-1, bufn-1 ios_base::out);

这意味着

  • 对于由只读组件组成的过滤链, 链的元素按逆序关闭
  • 对于由只写组件组成的过滤链, 链的元素按正序关闭
  • 控制相互独立的输入和输出序列的过滤器和设备会收到两次关闭通知: 第一次以 ios_base::in 为参数, 第二次以 ios_base::out 为参数.

(参见下文 close 针对 Filter 与 Device 类型的语义.)

template<typename T>     
void close(T& t);

void close(T& t, std::ios_base::openmode which);

void close(T& t, Device& next, std::ios_base::openmode which);

} } // End namespace boost::io

函数模板 close — 便利函数

模板参数

T- 某种 设备 概念的模型.

语义

template<typename T>     
void close(T& t);

close 的这个重载先调用 close(t, std::ios_base::in) 再调用 close(t, std::ios_base::out). 它确保 t 被正确关闭, 无论 模式 或 t 如何.

函数模板 close — 设备的关闭通知

模板参数

T- 某种 设备 概念的模型.

语义

template<typename T>     
void close(T& t, std::ios_base::openmode which);

若 t 是 过滤流或流缓冲, 则 close 会调用 pop — 条件是 t 为 完整. 其语义取决于其 类别, 如下:

category<T>::type语义
可转换为 input 但不可转换为 output 调用 t.pop() — 若 t 完整且 which == ios_base::in
otherwise 调用 t.pop() — 若 t 完整且 which == ios_base::out

对于非过滤流或流缓冲的设备, close 的语义取决于设备 T 的 类别, 如下:

category<T>::type语义
不可转换为 closable_tag 调用 flush
可转换为 closable_tag 与 bidirectional 调用 t.close(which)
可转换为 closable_tag 与 input, 但不可转换为 output 调用 t.close() — 若 which == ios_base::in
可转换为 closable_tag 与 output, 但不可转换为 bidirectional 调用 t.close() — 若 which == ios_base::out

简而言之:

  • 若 T 不满足 Closable, 则 close 调用 flush.
  • 若 T 满足 Closable 且控制两个相互独立的序列, 则 close 委托给成员函数 close, 该函数接受单个 openmode 参数.
  • 否则, close 委托给不接受参数的成员函数 close, 但仅当其 openmode 参数与 T 的模式一致时.

最后一个条件防止控制单个序列的设备被连续关闭两次.

注意: 从 Boost 1.35 开始, 以 openmode (std::ios_base::in 或 std::ios_base::out 以外) 调用此函数已被弃用. 要一次关闭两个序列, 请使用 

close(t)
而非 
close(t, std::ios_base::in | std::ios_base::out)

函数模板 close — 过滤器的关闭通知

模板参数

T- 某种 Filter 概念的模型
Device- 一种 Blocking 的 设备, 其 模式 细化 T 的模式.

语义

template<typename T, typename Device>
void close(T& t, Device& next, std::ios_base::openmode which);

对于过滤器类型, close 的语义取决于类型 T 的 类别, 如下:

category<T>::type语义
不可转换为 closable_tag 调用 flush
可转换为 closable_tag 与 bidirectional 调用 t.close(next, which)
可转换为 closable_tag 与 input, 但不可转换为 output 调用 t.close(next) — 若 which == ios_base::in
可转换为 closable_tag 与 output, 但不可转换为 bidirectional 调用 t.close(next) — 若 which == ios_base::out

简而言之:

  • 若 T 不满足 Closable, 则 close 调用 flush.
  • 若 T 满足 Closable 且控制两个相互独立的序列, 则 close 委托给成员函数 close, 该函数接受 openmode 与流缓冲参数.
  • 否则, close 委托给接受单个流缓冲参数的成员函数 close, 但仅当其 openmode 参数与 T 的模式一致时.

最后一个条件防止控制单个序列的过滤器被连续关闭两次.

注意: 从 Boost 1.35 开始, 以 openmode (std::ios_base::in 或 std::ios_base::out 以外) 调用此函数已被弃用.

[1]对于 pop, 可以通过调用成员函数 set_auto_close 并传入参数 false 来禁用此行为. 例如参见 filtering_stream::set_auto_close.
