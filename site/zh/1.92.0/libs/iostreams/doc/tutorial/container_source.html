2.1.2. 编写 container_source

假设你想编写一个从 STL 容器读取字符的设备. 只支持读取的设备称为 源. 典型的窄字符源如下所示: 

#include <iosfwd>                          // streamsize
#include <boost/iostreams/categories.hpp>  // source_tag

namespace io = boost::iostreams;

class my_source {
public:
    typedef char        char_type;
    typedef source_tag  category;

    std::streamsize read(char* s, std::streamsize n)
    {
        // Read up to n characters from the underlying data source
        // into the buffer s, returning the number of characters
        // read; return -1 to indicate EOF
    }

    /* Other members */
};

此处成员类型 char_type 指示 my_source 所处理字符的类型, 几乎总是 char 或 wchar_t. 成员类型 category 指示设备支持哪些基本 I/O 操作. 类别标签 source_tag 表示仅支持 read.

成员函数 read 将至多 n 个字符读入缓冲区 s 并返回读取的字符数 — 除非该数为 0 且已到达流末尾, 此时返回特殊值 -1. 一般而言, 即使尚未到达流末尾, 源的成员函数 read 返回的字符也可能少于请求的数量; 这类源被称为 非阻塞. 不过, 非阻塞设备与标准流和流缓冲的交互不佳, 因此大多数设备应是 Blocking 的. 参见 异步与非阻塞 I/O.

你也可以将上面的示例写为如下形式:

#include <boost/iostreams/concepts.hpp>  // source

class my_source : public source {
public:
    std::streamsize read(char* s, std::streamsize n);

    /* Other members */
};

此处 source 是一个便利基类, 它提供成员类型 char_type 与 category, 以及成员函数 close 与 imbue 的空操作实现 — 此处并不需要.

现在你可以开始编写你的 container_source 了. 为简单起见, 假设你的容器的迭代器是 RandomAccessIterator.

#include <algorithm>                       // copy, min
#include <iosfwd>                          // streamsize
#include <boost/iostreams/categories.hpp>  // source_tag

namespace boost { namespace iostreams { namespace example {

template<typename Container>
class container_source {
public:
    typedef typename Container::value_type  char_type;
    typedef source_tag                      category;
    container_source(Container& container)
        : container_(container), pos_(0)
        { }
    std::streamsize read(char_type* s, std::streamsize n)
    {
        using namespace std;
        streamsize amt = static_cast<streamsize>(container_.size() - pos_);
        streamsize result = (min)(n, amt);
        if (result != 0) {
            std::copy( container_.begin() + pos_, 
                       container_.begin() + pos_ + result, 
                       s );
            pos_ += result;
            return result;
        } else {
            return -1; // EOF
        }
    }
    Container& container() { return container_; }
private:
    typedef typename Container::size_type   size_type;
    Container&  container_;
    size_type   pos_;
};

} } } // End namespace boost::iostreams:example

此处注意

  • 成员类型 char_type 被定义为等于容器的 value_type;
  • 成员类型 category 告诉 Iostreams 库: container_source 是 Source 的模型; 且
  • container_source 可以由 Container 的实例构造 — 该实例以引用方式传入并存储, 可经由成员函数 container() 访问.

read() 实现背后的主要思想很简单: 首先, 计算要读取的字符数, 即容器中剩余未读字符数与请求字符数两者的最小值. 其次, 若要读取的字符数非零, 则从容器复制该数量的字符到提供的缓冲区, 并更新当前读取位置. 若字符数为零 — 即容器中的所有字符已被之前的 read 调用消费 (或容器本来就是空的) — 则返回 -1 以表示流末尾.

可以如下从 container_source 读取

#include <cassert>
#include <string>
#include <boost/iostreams/stream.hpp>
#include <libs/iostreams/example/container_device.hpp> // container_source

namespace io = boost::iostreams;
namespace ex = boost::iostreams::example;

int main()
{
    using namespace std;
    typedef ex::container_source<string> string_source;

    string                     input = "Hello World!";
    string                     output;
    io::stream<string_source>  in(input);
    getline(in, output);
    assert(input == output);
}

最后, 我应指出 Iostreams 库提供了更简便的从 STL 容器读取的方式: boost::iterator_range 的实例可以直接添加到 过滤流与流缓冲. 因此可以写:

#include <cassert>
#include <string>
#include <boost/iostreams/filtering_stream.hpp>
#include <boost/range/iterator_range.hpp>

namespace io = boost::iostreams;

int main()
{
    using namespace std;

    string                 input = "Hello World!";
    string                 output;
    io::filtering_istream  in(boost::make_iterator_range(input));
    getline(in, output);
    assert(input == output);
}
