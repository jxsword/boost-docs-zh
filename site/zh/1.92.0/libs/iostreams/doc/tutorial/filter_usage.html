2.2.2. 过滤器用法示例

过滤器通常与 过滤流与流缓冲 结合使用. 例如, 假设你有一些文本, 想先压缩, 再做 Base64 编码, 然后写入文件. 如果你有合适的 OutputFilter compressor 与 base64_encoder, 可以按如下方式完成:[1] 

#include <boost/iostreams/device/file_descriptor.hpp>
#include <boost/iostreams/filtering_stream.hpp>

namespace io = boost::iostreams;

int main()
{   
    io::filtering_ostream out;
    out.push(compressor());
    out.push(base64_encoder());
    out.push(file_sink("my_file.txt"));
    // write to out using std::ostream interface
}

与所有 过滤流与流缓冲 一样, filtering_ostream 维护一个内部的过滤器和设备链. (另参见 chain.) 当数据写入此链时, 它按组件被推入的顺序流经各组件. 上例中最后推入的组件可以是任何 汇 模型, 包括 std::ostream, 例如 std::cout.

现在假设你想恢复原始数据. 如果你有合适的 InputFilter decompressor 与 base64_decoder, 可以按如下方式完成:[2] 

#include <boost/iostreams/device/file.hpp>
#include <boost/iostreams/filtering_stream.hpp>

namespace io = boost::iostreams;

int main()
{   
    io::filtering_istream in;
    in.push(decompressor());
    in.push(base64_decoder());
    in.push(file_source("my_file.txt"));
    // read from in using std::istream interface
}

这里展示了过滤链的另一种用法. 当从链中读取数据时, 数据按逆序流经各组件, 从最后推入的组件开始. 最后推入的组件可以是任何 源 模型, 包括 std::istream, 例如 std::cin.

[1]严格说来, 此处最好使用 file_descriptor_sink 而非 file_sink, 因为 file_descriptor_sink 从不执行 代码转换.

[2]严格说来, 此处最好使用 file_descriptor_source 而非 file_source, 因为 file_descriptor_source 从不执行 代码转换.
