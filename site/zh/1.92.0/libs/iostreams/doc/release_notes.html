发布说明

1.46

  • 使用 BOOST_ASSERT 代替 assert.
  • 修复了 flush 回归, 参见 #4590

1.44

此版本包含大量修复, 几乎全部由 Steven Watanabe 完成.

文件描述符修复:

  • 破坏性变更: 新增了从文件描述符/句柄构造的构造函数和 open 方法, 适用于 file_descriptor、file_descriptor_source 与 file_descriptor_sink. 详情参见 文档. 若定义了 BOOST_IOSTREAMS_USE_DEPRECATED, 旧方法仍然可用 (#3517).
  • 添加 BOOST_IOSTREAMS_DECL 到 file_descriptor_source 与 file_descriptor_sink, 修复它们在动态库中的使用 (#4335).
  • 重新调整 file_descriptors 对 std::ios_base::openmode 的处理以匹配 std::fstream. 特别地, 若传入 std::ios_base::trunc 则截断现有文件 (#3323).
  • 在 Windows 上, 当传入 std::ios_base::app 时以追加模式打开文件, 而不是每次写入时都寻位到末尾 (#3323).

压缩/解压修复:

  • 不要过早结束通过对称过滤器读取产生的流 (#2318).
  • 允许构建 zlib 1.2.4+, 使用 glob 只包含实际存在的源文件 (#4091).
  • 修复压缩空字符串的问题.
  • 即使尚未读取任何输入, 也允许关闭 bzip2 过滤器 (#3348).
  • 在 bzip2_decompressor 中遇到意外的文件末尾时抛出异常, 而不是陷入无限循环 (#2783).
  • 复用过滤器时重置 zlib 的 crc.
  • 使 gzip_decompressor 成为 DualUseFilter (#1579).
  • 允许 bzip2_decompressor 处理多个拼接的流 (#3853).

其他修复:

  • 使 aggregate_filter 支持宽字符 (#3851).
  • 使 symmetric_filter 能用 wchar_t 编译 (#3279).
  • 修复 boost/iostreams/detail/resolve.hpp 在 xlc 上的编译.
  • 修复 multichar_dual_use_filter_tag 的定义 (#3689).
  • 使 concept_adapter 支持自定义 char_traits (#2356).
  • 在 Windows 上, 以只读/写权限打开映射文件, 而不是完全控制 — 后者可能不可用 (#2996).
  • 确保 direct_streambuf 与 indirect_streambuf 在打开时被正确重置 (#4102).
  • 使 basic_file 与 basic_file_sync 成为 Flushable (#2998).
  • 若干文档改进, 包括记录使用 mapped_file 的私有映射 (#1612).
  • 通过使用 Boost.Filesystem 的 unique_path 代替 tmpnam, 使测试更可靠 (#2325).

1.35

1. close 的语义已被修改:

  • 调用 close 时传入 std::ios_base::openmode — in 或 out 以外的值 — 已被弃用.
  • 为方便起见, 提供了 close 的接受单个设备参数的新重载.
  • DualUseFilters 只接收一次关闭通知.
  • 泛型流与流缓冲 与 过滤流与流缓冲 现在是 Closable 的. 对于过滤流和流缓冲, close 调用 pop.

这些变更会破坏一些现有代码. 之所以需要这些变更, 是为了解决先前规范中导致大量已报告缺陷的不一致之处.

2. 引入了函数模板 slice 作为 restrict 的别名, 适用于将 restrict 视为关键字的平台.

3. 修复了大量缺陷, 其中许多与 close、copy 及 文件描述符 有关.
