为什么我写入 filtering_stream 的数据没有到达链末尾的汇?

你可能需要刷新流. 但请注意: 无法保证写入 filtering_stream 的所有数据都会在流关闭之前被转发到最终的汇 — 除非底层 chain 中的所有过滤器都满足 Flushable.

也有可能是一个有缺陷的过滤器正在以你不期望的方式修改数据, 例如悄悄丢弃数据.

如何同时写入多个 ostream?

使用 tee_filter 或 tee_device. 参见 tee.

如何访问已添加到链中、或已附加到 stream 或 stream_buffer?

如果你使用的是 stream 或 stream_buffer, 请使用 operator* 或 operator->.

如果你使用的是 filtering_stream、filtering_streambuf 或 chain, 请使用成员函数模板 component_type 与 component. 或者, 使用 引用包装器 以引用方式将你的过滤器或设备添加到链中.

如何使用大 (64 位) 偏移量执行文件定位操作?

如果你使用的是原始设备, 且你的编译器支持 64 位整数类型, 则可以将大偏移量直接传给 seek. 要将 seek 的返回值转换为整数类型, 请使用 position_to_offset.

如果你使用的是 stream_buffer 或 filtering_streambuf, 请将偏移量转换为 std::streampos — 使用 offset_to_position — 然后将其传给 pubseekpos. 要将 seek 的返回值转换为整数类型, 请使用 position_to_offset.

如果你使用的是 stream 或 filtering_stream, 请将偏移量转换为 std::streampos — 使用 offset_to_position — 然后将其传给 seekg 或 seekp 的接受单个 std::streampos 参数的重载. 要将 seek 的返回值转换为整数类型, 请使用 position_to_offset.

参见 流偏移量.

如何对 STL 序列进行读写?

可以使用 back_insert_device 或函数 boost::iostreams::back_inserter 向 STL 序列追加数据. 可以通过将 boost::itertator_range 的实例添加到 filtering_stream 或 filtering_streambuf 来从 STL 序列读取.

参见 编写 container_source 与 编写 container_sink.

如何编写可读取或写入多字节字符编码的流?

使用 code_converter. 参见 Code Conversion.

能否在一系列 I/O 操作的中途交换过滤器或设备?

如果你在执行输出, 且链中的所有过滤器都满足 Flushable, 那么可以. 先调用 strict_sync. 若其返回 true, 则可以安全地对一个或多个组件调用 set_auto_close(false) 与 pop 而不关闭流. 这适用于 filtering_stream、filtering_streambuf 与 chain 的实例.

为什么我的过滤链可与 std::cout 一起工作, 却不能与另一个 ostream 一起工作?

Iostreams 库以引用方式存储流和流缓冲; 因此, 流和流缓冲的生存期必须长于任何添加了它们的过滤链. 这对 std::cout 不是问题, 因为它保证存活到程序结束.

请检查 ostream 是否未在 filtering_stream 之前被销毁. 如果两个对象都是在同一代码块内的栈上构造的, 请确保 ostream 是先构造的.

为什么我得到指出 operator| 有歧义的错误?

在对涉及 operator| 的表达式进行重载决议时, 编译器可能正在考虑从整数类型到 Pipable 过滤器的隐式转换. 请确保你的所有 Pipable 过滤器都有 explicit 构造函数. 参见 管道.

编译 finite_state_filter 示例时为什么出错?

模板 finite_state_filter 要求编译器高度符合标准. 详情参见 可移植性 与 编译器状态表.
