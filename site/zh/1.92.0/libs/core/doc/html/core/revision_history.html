1.91.0 中的变更

  • 头文件 boost/is_placeholder.hpp 已从 Bind 移至 Core. (#90)

1.90.0 中的变更

  • 宏 BOOST_TEST_THROWS 和 BOOST_TEST_NO_THROW (定义于 boost/core/lightweight_test.hpp) 的实现已更改, 以避免在某些编译器上、当这些宏用于 if/else 块中时出现编译器警告. 此更改的副作用是, 宏后面的分号现在是必需的. (PR#205)
  • 当编译器提供后者时, boost::data 和 boost::size 现在分别是 std::data 和 std::size 的别名. 这解决了当编译器同时找到 boost:: 和 std:: 两种候选 (例如作为 ADL 的结果) 时的潜在歧义. (#206)

1.89.0 中的变更

  • 修复了 bit_ceil, 使其在输入为 0 时按规范返回 1. (PR#199)
  • 添加了对 std::format 的支持 (位于 boost::core::string_view 中). (#190)

1.86.0 中的变更

  • 添加了 boost/core/pointer_in_range.hpp 头文件, 其中包含函数模板 pointer_in_range, 用于检查一个指针是否位于给定范围内.
  • 修复了 type_name 在抽象类上的问题. (#172)
  • 修复了 boost/core/type_name.hpp 在 MSVC 上、当原生 wchar_t 类型被禁用时的编译错误. (#173)
  • 为 MSVC 的一个 缺陷 添加了变通办法, 该缺陷会导致 empty_value 与嵌套类一起使用时出现编译错误. (PR#175)

1.85.0 中的变更

  • 添加了新的 boost/core/functor.hpp 头文件, 其中包含类模板 functor, 用于把原始函数包装成函数对象类.

  • 更改了 null_deleter、fclose_deleter 和 checked deleter 的定义, 使它们不会在如下情况中把命名空间 boost 带入实参相关查找:

    std::unique_ptr< std::FILE, boost::fclose_deleter > p1, p2;
swap(p1, p2); // no longer looks for boost::swap as part of ADL

    用户可能需要显式限定被调用函数的命名空间, 或者添加 using 声明.

1.84.0 中的变更

  • 工具函数 boost::swap 已更名为 boost::core::invoke_swap, 以避免在实参不可交换时形成潜在的无限递归. 新函数定义于 boost/core/invoke_swap.hpp, 功能上等同于 boost::swap. 旧的 boost::swap 名称为了向后兼容而保留, 但已被弃用, 并将在未来的版本中移除. 其 noexcept 规格说明已被移除, 以避免编译期递归导致的编译错误. 在过渡期间, 可定义 BOOST_ALLOW_DEPRECATED_SYMBOLS 或 BOOST_ALLOW_DEPRECATED 来抑制弃用警告. (#148)
  • 头文件 boost/swap.hpp、boost/utility/swap.hpp 和 boost/core/swap.hpp 已弃用并将被移除. 请改用 boost/core/invoke_swap.hpp. 可定义 BOOST_ALLOW_DEPRECATED_HEADERS 或 BOOST_ALLOW_DEPRECATED 来抑制弃用警告.

1.83.0 中的变更

  • 为 boost::core::type_name 添加了对不完整类型的支持.
  • boost/core/bit.hpp 中的位操作函数在近期的 MSVC 版本 (VS2019 update 5 及更高) 上现在是 constexpr 的.
  • 添加了 boost::core::byteswap (C++23 中 std::byteswap 的一种实现) 到 boost/core/bit.hpp.
  • 把让出 (yield) 原语 sp_thread_pause、sp_thread_yield、sp_thread_sleep 从 SmartPtr 实现细节移至 boost/core/yield_primitives.hpp.

1.82.0 中的变更

  • 添加了 boost/core/snprintf.hpp 头文件, 其中包含 snprintf、vsnprintf 及其 wchar_t 对应物的可移植定义.
  • 弃用了 boost/core/is_same.hpp 和 boost::core::is_same. 该头文件将在未来的版本中移除. 建议用户改用 Boost.TypeTraits 或 C++ 标准库类型特征.
  • 为 boost::ref 成员函数及相关方法标注 noexcept.
  • 为 boost::swap 函数标注 noexcept, 具体取决于该类型是否支持不抛出异常的 swap 操作.
  • 添加了 boost::core::launder, 即 std::launder 的可移植实现.
  • 添加了 BOOST_CORE_ALIGNOF, 即 alignof 的可移植实现.
  • 添加了 boost::core::max_align_t (std::max_align_t 的可移植等价物) 以及 boost::core::max_align, 即 max_align_t 的对齐.
  • 添加了 boost::core::memory_resource, 即 C++17 中 std::pmr::memory_resource 的可移植等价物.
  • 添加了 boost/core/serialization.hpp, 这是一组原语, 允许库为其类型实现 Boost.Serialization 支持, 而无需包含 Serialization 头文件, 从而避免其库依赖于 Serialization.
  • 添加了 boost::data, 即 std::data 的一种实现.
  • 添加了 boost::size, 即 std::size 的一种实现.
  • 更新了 boost::span 以使用 boost::data, 后者增加了从 std::initializer_list 进行范围构造的支持.
  • 添加了 boost::identity, 即 std::identity 的一种实现. 该设施已从 Boost.Functional 移入.

1.81.0 中的变更

  • empty_value 成员现在被标记为 constexpr.
  • 添加了 fclose_deleter 这个删除器, 它调用 std::fclose, 作用于指向 std::FILE 的指针上.
  • boost/core/bit.hpp 中的位操作工具现在在输入上显式要求无符号整数. (#129)
  • bit_width 现在返回 int, 而不是输入实参类型的值. 这遵循 LWG3656 的决议.

1.80.0 中的变更

  • 在 boost/core/allocator_access.hpp 中, 添加了对分配器的 construct 和 destroy 成员的检测.
  • 头文件 boost/core/alloc_construct.hpp 现已弃用, 并将在未来的版本中移除. 其功能已移至 boost/core/allocator_access.hpp. 特别是, 新增了用于分配和销毁数组的 allocator_construct_n 和 allocator_destroy_n 方法.
  • 为 MSVC 的一个缺陷添加了变通办法, 该缺陷导致在包含 Boost.Range 头文件时无法在 C++17 模式下编译 span. (#105, PR#115)
  • 在 type_name 中添加了对 128 位整数类型的支持.
  • 在 pointer_traits 中, 指针重绑定现在支持 C++03 编译器.

1.79.0 中的变更

  • 添加了 boost::allocator_traits, 即 std::allocator_traits 的一种实现.
  • 使 boost::pointer_traits 对 SFINAE 友好.
  • boost/iterator.hpp 已弃用, 并将在未来的版本中移除. 该头文件定义了 boost::iterator 模板, 它等同于 std::iterator (位于 <iterator> 头文件中). 然而, 由于 std::iterator 本身在 C++17 中已被弃用, 建议用户从其代码中移除 boost::iterator 或 std::iterator 的使用.
  • 添加了 boost::core::verbose_terminate_handler, 一个旨在传递给 std::set_terminate 的工具函数, 它把关于未捕获异常的信息打印到 stderr.

1.78.0 中的变更

  • 为 boost/core/cmath.hpp 添加了通用实现, 在 BOOST_CORE_USE_GENERIC_CMATH 已定义或平台未在 <cmath> 中提供必要设施时启用.
  • 添加了 boost::core::type_name, 一个以字符串形式返回类型名称的工具函数.
  • 添加了 boost::span, C++20 的 std::span 的一个 C++11 实现.

1.77.0 中的变更

  • boost/core/uncaught_exceptions.hpp 已为兼容 Mac OS 10.4 及更早版本而修改.

1.76.0 中的变更

  • 添加了兼容的引用包装器之间的隐式转换.
  • 添加了 boost/core/cmath.hpp, 即 <cmath> 中浮点分类函数的可移植实现.
  • 添加了 boost/core/bit.hpp, 即 C++20 标准头文件 <bit> 的可移植实现.
  • 修复了 C++20 下字符类型的 BOOST_TEST_EQ 和 BOOST_TEST_NE.
  • 修订了分配器访问工具 (现在支持 VS2013, 且没有变通办法使用 allocator_traits.)

1.74.0 中的变更

  • 实现了分配器访问工具, 它们为 allocator_traits 提供了替代, 针对每种设施提供单独的特征和函数. 它们在可能的情况下支持 C++11 分配器模型, 并为 C++98 兼容性提供回退.
  • 向 Lightweight Test 添加了 BOOST_TEST_WITH.

1.71.0 中的变更

  • 添加了函数 alloc_construct、alloc_construct_n、alloc_destroy 和 alloc_destroy_n (位于 <boost/core/alloc_construct.hpp> 中), 用于分配器感知且异常安全的对象和数组构造与销毁.
  • 添加了 constexpr 函数 first_scalar (位于 <boost/core/first_scalar.hpp> 中), 用于获取指向数组第一个标量元素的指针. 给定 T* 类型的指针, 它们返回 remove_all_extents_t<T>* 类型的指针.
  • 添加了类模板 noinit_adaptor (位于 <boost/core/noinit_adaptor.hpp> 中), 它是一个分配器适配器, 把任意分配器转换为其 construct(ptr) 通过 placement new 执行默认初始化, 且其 destroy(ptr) 直接调用 value_type 析构函数的分配器.
  • 添加了类模板 default_allocator (位于 <boost/core/default_allocator.hpp> 中), 它可用作一个最小默认分配器: 具有类似于 C++20 std::allocator 的接口, 支持禁用异常的配置, 且不把 std 作为关联命名空间. 该分配器使用 operator new 和 operator delete 进行分配.
  • 在头文件 <boost/core/uncaught_exceptions.hpp> 中, 为使用 libc++/libc++abi 库时更好地兼容 QNX SDP 7.0 添加了变通办法.
  • 头文件 <boost/detail/sp_typeinfo.hpp> 现已被标记为弃用, 并将在未来的版本中移除. 应改用 <boost/core/typeinfo.hpp>.

1.69.0 中的变更

  • 实现了 boost::empty_value, 供库作者方便地利用空基类优化 (EBO) 来存储可能为空的类型的对象.
  • 实现了 boost::quick_exit, 以提供 C++11 标准库设施 std::quick_exit 的功能.
  • 减少了 Lightweight Test 中静态变量的数量, 并对 MSVC 编译器在未能调用 boost::report_errors 时采用较轻量的中止行为.

1.67.0 中的变更

  • 更新了 to_address 和 pointer_traits, 以反映 P0653R2 中为 C++20 采用的设计.

1.65.0 中的变更

  • 为 C++03 及更高版本实现了 pointer_traits, 它实现了 P0653r0.
  • 向 Lightweight Test 添加了 BOOST_TEST_GT 和 BOOST_TEST_GE.
