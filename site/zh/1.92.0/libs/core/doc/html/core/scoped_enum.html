概述

头文件 boost/core/scoped_enum.hpp 包含若干宏, 若编译器支持 C++11 作用域枚举 (scoped enum, 7.2 [dcl.enum]) 特性, 这些宏可用于生成 C++11 作用域枚举, 否则以 C++03 构造来模拟. 来自 Boost.Config 的宏 BOOST_NO_CXX11_SCOPED_ENUMS 用于检测编译器对该特性的支持.

标准库中定义的部分枚举是作用域枚举.

enum class future_errc
{
    broken_promise,
    future_already_retrieved,
    promise_already_satisfied,
    no_state
};

用户可以按如下方式可移植地声明这类枚举:

BOOST_SCOPED_ENUM_DECLARE_BEGIN(future_errc)
{
    broken_promise,
    future_already_retrieved,
    promise_already_satisfied,
    no_state
}
BOOST_SCOPED_ENUM_DECLARE_END(future_errc)

这些宏允许在几乎所有情况下像使用作用域枚举一样使用 future_errc.

future_errc ev = future_errc::no_state;

可以指定该枚举的底层类型:

BOOST_SCOPED_ENUM_UT_DECLARE_BEGIN(future_errc, unsigned int)
{
    broken_promise,
    future_already_retrieved,
    promise_already_satisfied,
    no_state
}
BOOST_SCOPED_ENUM_DECLARE_END(future_errc)

该枚举支持从底层类型的显式转换.

该枚举可以前置声明:

BOOST_SCOPED_ENUM_FORWARD_DECLARE(future_errc);

不过存在一些限制. 模拟的作用域枚举不是 C++ 枚举, 因此 is_enum< future_errc > 将为 false_type.

模拟的作用域枚举不能用于 switch, 也不能用于模板实参. 对于这些情况, 用户需要使用一些辅助设施. 不要这样写:

switch (ev)
{
case future_errc::broken_promise:
    // ...

而使用

switch (boost::native_value(ev))
{
case future_errc::broken_promise:
    // ...

也不要这样写:

template <>
struct is_error_code_enum< future_errc > :
    public true_type
{
};

而使用

template <>
struct is_error_code_enum< BOOST_SCOPED_ENUM_NATIVE(future_errc) > :
    public true_type
{
};

到底层类型的显式转换应使用 boost::underlying_cast 而非 static_cast 来执行:

unsigned int val = boost::underlying_cast< unsigned int >(ev);

在 C++03 中, 当调用重载函数且其中一个重载以作用域枚举为形参、另一个以整数类型为形参时, 作用域枚举的行为有所不同. 考虑以下代码:

enum enum_regular { REGULAR_A, REGULAR_B };

BOOST_SCOPED_ENUM_DECLARE_BEGIN(enum_scoped)
{
    a, b
}
BOOST_SCOPED_ENUM_DECLARE_END(enum_scoped)

void regular_or_int(enum_regular); // (1)
void regular_or_int(int);          // (2)
void scoped_or_int(enum_scoped);   // (3)
void scoped_or_int(int);           // (4)

regular_or_int(REGULAR_A);                  // calls (1) in C++03 and C++11
scoped_or_int(enum_scoped::a);              // calls (3) in C++11 but (4) in C++03!
scoped_or_int(enum_scoped(enum_scoped::a)); // calls (3) in C++03 and C++11

下面是用法示例:

BOOST_SCOPED_ENUM_UT_DECLARE_BEGIN(algae, char)
{
    green,
    red,
    cyan
}
BOOST_SCOPED_ENUM_DECLARE_END(algae)
...
algae sample( algae::red );
void foo( algae color );
...
sample = algae::green;
foo( algae::cyan );

已弃用的语法

在该头文件的早期版本中, 有两种声明作用域枚举的方式, 各有优缺点. 另一种方式使用了一组不同的宏:

BOOST_SCOPED_ENUM_START(algae)
{
    green,
    red,
    cyan
};
BOOST_SCOPED_ENUM_END
...
BOOST_SCOPED_ENUM(algae) sample( algae::red );
void foo( BOOST_SCOPED_ENUM(algae) color );
...
sample = algae::green;
foo( algae::cyan );

这里 BOOST_SCOPED_ENUM_START 对应 BOOST_SCOPED_ENUM_DECLARE_BEGIN, BOOST_SCOPED_ENUM_END 对应 BOOST_SCOPED_ENUM_DECLARE_END, BOOST_SCOPED_ENUM 对应 BOOST_SCOPED_ENUM_NATIVE. 还要注意 BOOST_SCOPED_ENUM_END 之前的分号.

在当前版本中, 这些宏产生与上述宏等同的结果, 并被视为已弃用.

获取枚举的底层类型

头文件 boost/core/underlying_type.hpp 定义了元函数 boost::underlying_type, 可用于获取作用域枚举的底层类型. 该元函数支持用 boost/core/scoped_enum.hpp 中的宏声明的模拟作用域枚举. 当编译器支持原生作用域枚举时, 该元函数等同于 std::underlying_type.

遗憾的是, 存在实现了作用域枚举但不支持 std::underlying_type 的配置. 在这种情况下, boost::underlying_type 必须由用户来特化. 定义宏 BOOST_NO_UNDERLYING_TYPE 用于指示这类情况.
