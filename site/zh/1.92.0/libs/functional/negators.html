取反器

头文件 functional.hpp 提供 C++ 标准库 (§20.3.5) 中两个取反器适配器的增强版本:

  • unary_negate
  • binary_negate

以及对应的辅助函数

  • not1
  • not2

不过, 本库中的取反器在两方面优于标准版本:

  • 它们使用 函数对象特征, 使得对函数 (而非可适配函数对象) 取反时无需 ptr_fun.
  • 它们使用 Boost call traits 来确定声明实参并将其传递给被适配函数的最佳方式 (参见 下文).

用法

用法与标准取反器完全相同. 例如,

bool bad(const Foo &foo) { ... }
...
std::vector<Foo> c;
...
std::find_if(c.begin(), c.end(), boost::not1(bad));

实参类型

C++ 标准 (§20.3.5) 把一元取反器定义如下 (二元取反器类似):

template <class Predicate>
  class unary_negate
    : public unary_function<typename Predicate::argument_type,bool> {
public:
  explicit unary_negate(const Predicate& pred);
  bool operator()(const typename Predicate::argument_type& x) const;
};

注意: 如果 Predicate 的 argument_type 是引用, 那么 operator() 实参的类型就会是引用的引用. 这在当前 C++ 中是非法的 (但参见 C++ 标准核心语言活跃问题列表).

然而, 如果我们改为让 operator() 原样接受 Predicate 的 argument_type, 那么当它是值类型时就会带来不必要的低效: 该实参将被复制两次 - 一次在调用 unary_negate 的 operator() 时, 另一次在 operator() 调用被适配函数时.

因此, operator() 的实参应如何声明, 取决于 Predicate 的 argument_type 是否为引用. 若是引用, 就直接声明为 argument_type; 若是值, 则声明为 const argument_type&.

Boost call_traits 类模板包含一个 param_type typedef, 它利用偏特化来精确做出这一决定. 如果我们把 operator() 声明为

bool operator()(typename call_traits<typename Predicate::argument_type>::param_type x) const

即可达到期望的效果 - 在不损失效率的情况下消除引用的引用. 实际上, 真正的声明因使用函数对象特征而稍复杂一些, 但效果相同.

局限

由于实现这些改进所用的函数对象特征与 call 特征都依赖偏特化, 这些改进仅在支持该特性的编译器上可用. 在其他编译器上, 本库的取反器行为与标准中的非常相似 - 对函数进行适配仍需要 ptr_fun, 且不会避免引用的引用.
