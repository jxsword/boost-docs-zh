简述

boost::forward_adapter 为函数对象提供了一个可复用的适配器模板. 它把右值作为 const 引用转发, 而左值保持原样.

struct g // function object that only accept LValues
{
    template< typename T0, typename T1, typename T2 >
    void operator()(T0 & t0, T1 & t1, T2 & t2) const;

    typedef void result_type;
};

// Adapted version also accepts RValues and forwards
// them as references to const, LValues as-is
typedef boost::forward_adapter<g> f;

另一个适配器 boost::lighweight_forward_adapter 则借助用户的帮助进行转发: 对引用参数, 它接受并解包引用包装 (参见 Boost.Ref); 对所有其他参数则添加 const 限定.

目标函数必须与 Boost.ResultOf 兼容, 这些适配器也是如此.

Background

假设我们有一个函数 f, 可以这样调用它:

f(123,a_variable);

现在我们想编写另一个泛型函数 g, 它能以同样的方式被调用, 并返回某个对象, 该对象用相同的参数调用 f.

f(123,a_variable) == g(f,123,a_variable).call_f()

话说回来, 我们为什么想这么做?

也许我们想多次运行 f. 也许我们想在另一个线程中运行它. 也许我们只是想暂时封装这个调用表达式, 然后把它与其他允许组合更复杂表达式的代码一起使用, 再用 C++ 模板将其分解, 让编译器生成一些机制, 最终在运行期调用 f (换句话说, 就是应用一种通常被称为表达式模板 (Expression Templates) 的技术).

那么, 该怎么做呢?

坏消息是: 这不可能做到.

原因在于变量与求值为其值的表达式之间存在细微的差别: 给定

int y;
int const z = 0;

以及

template< typename T > void func1(T & x);

我们就可以调用

func1(y); // x is a reference to a non-const object
func1(z); // x is a reference to a const object

其中

func1(1); // fails to compile.

这样我们就能安全地让 func1 保存其引用参数, 同时编译器会阻止我们保存指向临时生存期对象的引用.

必须认识到: 非常量性与对象能否绑定到非常量引用参数是两个不同的性质. 后者正是左值与右值的区别. 这两个名字源于赋值表达式的左侧和右侧, 因此左值通常是可以被赋值的对象, 而右值是来自右侧表达式的临时结果.

y = 1+2;        // a is LValue, 1+2 is the expression producing the RValue,
// 1+2 = a;     // usually makes no sense. 

func1(y);       // works, because y is an LValue
// func1(1+2);  // fails to compile, because we only got an RValue.

若我们给参数加上 const 限定, 我们的函数也能接受右值:

template< typename T > void func2(T const & x);

// [...] function scope:
func2(1); // x is a reference to a const temporary, object,
func2(y); // x is a reference to a const object, while y is not const, and
func2(z); // x is a reference to a const object, just like z.

在所有情况下, x 中参数 func2 都是一个带 const 限定的左值. 我们可以用函数重载来识别非常量左值:

template< typename T > void func3(T const & x); // #1
template< typename T > void func3(T & x);       // #2

// [...] function scope:
func3(1); // x is a reference to a const, temporary object in #1,
func3(y); // x is a reference to a non-const object in #2, and
func3(z); // x is a reference to a const object in #1.

注意: 重载函数 x 中的所有参数 func3 都是左值. 事实上, 在 C++98 中没有办法把右值原样传入函数. 还要注意, 我们无法区分原本是带 const 限定的左值还是右值.

这就是用 C++98 手段能得到的、与上述泛型转发函数 g 最接近的形式. 关于这一问题的极详尽讨论 (包括需要更改语言的解决方案) 参见 The Forwarding Problem 一文.

实际实现时, 对 N 个参数 (每个都有带与不带 const 限定符两个版本) 的每种参数个数, 我们需要 2^N 个重载 (即 2^(Nmax+1) - 2^Nmin). 没错, 这意味着编译期复杂度是 O(2^N); 不过系数很小, 因此对合理数量 (< 10) 的参数效果相当好.

forward_adapter

说明

其实例可用左值和右值参数调用的函数对象适配器模板. 右值参数以 const 引用类型的左值形式转发.

可以提供第二个数值非类型模板参数作为元数 (arity), 以把转发限制到特定元数. 若存在第三个数值非类型模板参数, 则第二、第三个模板参数分别被视为最小和最大元数. 指定元数有助于提高诊断消息的可读性和编译期性能.

Boost.ResultOf 可用于确定特定调用表达式的结果类型.

头文件 
#include <boost/functional/forward_adapter.hpp>
概要 
namespace boost
{
    template< class Function,
        int Arity_Or_MinArity = unspecified, int MaxArity = unspecified >
    class forward_adapter;
}

记法约定

F

可能带 const 限定的函数对象类型或其引用类型

f

可转换为 F 的对象

FA

类型 forward_adapter<F>

fa

一个 FA, 以 f 初始化的实例对象

a0...aN

传给 fa 的实参

目标函数调用的结果类型必须为

boost::result_of<F*(TA0 [const]&...TAN [const]&])>::type

其中 TA0...TAN 表示 a0...aN 的实参类型.

表达式语义

表达式

语义

FA(f)

创建一个适配器, 用 f 初始化目标函数.

FA()

创建一个适配器, 尝试使用 F 的默认构造函数.

fa(a0...aN)

以实参 f...a0 调用 aN.
限制

宏 BOOST_FUNCTIONAL_FORWARD_ADAPTER_MAX_ARITY 可以用来设定最大调用元数. 其默认值为 6.

复杂度

预处理时间: O(2^N), N 为元数上限. 编译时间: O(2^N), N 取决于元数范围. 运行时间: 若编译器内联则为 O(0), 否则为 O(1).

lightweight_forward_adapter

说明

其实例可用左值和右值参数调用的函数对象适配器模板. 所有参数都以 const 引用类型的左值形式转发, 但引用包装除外——它们会被解包, 并可能产生非常量左值.

可以提供第二个数值非类型模板参数作为元数 (arity), 以把转发限制到特定元数. 若存在第三个数值非类型模板参数, 则第二、第三个模板参数分别被视为最小和最大元数. 指定元数有助于提高诊断消息的可读性和编译期性能.

Boost.ResultOf 可用于确定特定调用表达式的结果类型.

头文件 
#include <boost/functional/lightweight_forward_adapter.hpp>
概要 
namespace boost
{
    template< class Function,
        int Arity_Or_MinArity = unspecified, int MaxArity = unspecified >
    struct lightweight_forward_adapter;
}
