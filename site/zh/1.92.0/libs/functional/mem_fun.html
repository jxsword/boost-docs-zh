成员函数适配器

头文件 functional.hpp 包含 C++ 标准库 (§20.3.8) 中全套成员函数适配器的增强版本:

  • mem_fun_t
  • mem_fun1_t
  • const_mem_fun_t
  • const_mem_fun1_t
  • mem_fun_ref_t
  • mem_fun1_ref_t
  • const_mem_fun_ref_t
  • const_mem_fun1_ref_t

以及对应的一组重载辅助函数

  • mem_fun
  • mem_fun_ref

相对于标准中的规定, 这些适配器做了如下修改:

  • const_ 系列成员函数适配器的 first_argument_type typedef 已被修正 (参见下文).
  • 传递给 mem_fun1_t 及其变体的实参, 使用成员函数实参类型对应的 call_traits::param_type 传递.

first_argument_type

例如, 标准对 const_mem_fun1_t 的规定如下:

template <class S, class T, class A> class const_mem_fun1_t
  : public binary_function<T*, A, S> {
public:
  explicit const_mem_fun1_t(S (T::*p)(A) const);
  S operator()(const T* p, A x) const;
};

注意: binary_function 的第一个实参是 T*, 尽管事实上 operator() 的第一个实参的实际类型是 const T*.

这有影响吗? 考虑一下当我们写下

struct Foo { void bar(int) const; };
const Foo *cp = new Foo;
std::bind1st(std::mem_fun(&Foo::bar), cp);

时会发生什么: 我们创建了一个 const_mem_fun1_t 对象, 它实际上将包含如下内容

typedef Foo* first_argument_type;

随后 bind1st 会创建一个 binder1st 对象, 该对象把这个 typedef 用作某个成员的类型, 而该成员将以 cp 初始化. 换句话说, 我们将不得不用 const Foo* 指针来初始化一个 Foo* 成员! 这显然不可能, 因此标准库厂商要实现它, 只能强行转换掉 cp 的常量性 (很可能在 bind1st 的函数体内完成).

这种做法对本库中增强的 绑定器行不通, 因此我们还必须同时提供修正版的成员函数适配器.

实参类型

例如, 标准对 mem_fun1_t 的定义如下 (§20.3.8 ¶2):

template <class S, class T, class A> class mem_fun1_t
  : public binary_function<T*, A, S> {
public:
  explicit mem_fun1_t(S (T::*p)(A));
  S operator()(T* p, A x) const;
};

注意: operator() 的第二个实参类型与成员函数的实参类型完全相同. 如果这是值类型, 该实参将按值传递并被复制两次.

然而, 如果我们改为把实参声明为 const A& 来消除这一低效, 那么当 A 是引用类型时, 就会出现引用的引用, 这在当前是非法的 (但参见 C++ 核心语言问题编号 106)

因此, operator() 的第二个实参应如何声明, 取决于成员函数的实参是否为引用. 若是引用, 就直接声明为 A; 若是值, 则声明为 const A&.

Boost call_traits 类模板包含一个 param_type typedef, 它利用偏特化来精确做出这一决定. 把 operator() 声明为

S operator()(T* p, typename call_traits<A>::param_type x) const

即可达到期望的效果 - 既提高了效率, 又不会产生引用的引用.

局限

用于实现上述改进的 call traits 模板依赖偏特化, 因此这些改进仅在支持该特性的编译器上可用. 在其他编译器上, 传递给成员函数的实参 (mem_fun1_t 家族中) 将总是按引用传递, 从而仍可能产生引用的引用.
