改进的函数对象适配器

头文件 functional.hpp 对 C++ 标准库 (第 20.3.5 至 20.3.8 节) 规定的函数对象适配器提供了增强. 这些增强主要得益于两项改动:

  1. 我们使用 Boost 的 call_traits 模板来避免引用的引用问题, 并提高参数传递的效率.
  2. 我们使用两个 函数对象特征类模板, 使本库的适配器不再需要 ptr_fun.

用法

使用这些适配器应当与使用标准函数对象适配器几乎一样; 唯一的区别是你需要写 boost:: 而不是 std::, 而且你会少受些头疼之苦.

例如, 假设你有一个 Person 类, 其中包含 set_name 函数:

class Person
{
  public:
    void set_name(const std::string &name);
  // ...
};

你可以这样写来重命名集合 c 中的一群人:

std::for_each(c.begin(), c.end(), 
              boost::bind2nd(boost::mem_fun_ref(&Person::set_name), "Fred"));

如果改用标准适配器, 这段代码通常将无法编译, 因为 set_name 接受引用参数. 原因参见 绑定器文档 中的说明.

编译器兼容性

该头文件与测试程序已用以下编译器编译:

编译器 备注
Borland C++Builder 4 Update 2 无已知问题.
Borland C++ 5.5 无已知问题.
g++ 2.95.2 无已知问题.
Microsoft Visual C++ Service Pack 3 编译器缺少偏特化, 因此本库相对标准适配器几乎提供不了更多东西:
  • call_traits 机制无法防止引用的引用, 因此本库的适配器可在更少的情况下使用.
  • function_traits 机制无法确定函数的参数与结果类型, 因此适配函数仍需要 ptr_fun.

未来方向

本库的首要焦点是解决引用的引用问题, 同时尽可能保持与标准库的兼容. 这使你能够在今天的许多编译器上使用书刊中介绍的技术.

从长远来看, 可能会有更好的解决方案:

  1. 若干 Boost 成员正在开发表达式模板库. 它们将为组合与适配函数提供更自然的语法. 由于这是一项新技术, 它可能还需要一段时间才能成熟并被主流编译器广泛支持, 但前景可观. 在此期间, functional.hpp 库填补了这一空缺.
  2. 标准委员会已经认识到模板实例化过程中出现的引用的引用问题, 并已着手修订标准 (见 C++ 标准核心语言活跃问题列表).
