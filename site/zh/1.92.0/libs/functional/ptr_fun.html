函数指针适配器

头文件 functional.hpp 提供 C++ 标准库 (§20.3.7) 中两个函数指针适配器的增强版本:

  • pointer_to_unary_function
  • pointer_to_binary_function

以及对应的辅助函数模板:

  • ptr_fun

不过, 由于我们使用了 函数对象特征, 你应当无需把这些适配器与本库中的适配器配合使用. 但如果你的实现无法与我们的特征类正常配合 (因缺乏偏特化), 或者你想使用来自第三方的函数对象适配器, 那么仍然需要用到它们.

用法

如果需要使用这些适配器, 其用法与标准函数指针适配器完全相同. 例如,

bool bad(std::string foo) { ... }
...
std::vector<std::string> c;
...
std::vector<std::string>::iterator it
     = std::find_if(c.begin(), c.end(), std::not1(boost::ptr_fun(bad)));

但请注意: 本库包含支持函数对象特征的增强版 取反器, 因此上面一行同样可以写作

std::vector<std::string>::iterator it
     = std::find_if(c.begin(), c.end(), boost::not1(bad));

实参类型

标准对 pointer_to_unary_function 的定义如下 (§20.3.8 ¶2):

template <class Arg, class Result>
class pointer_to_unary_function : public unary_function<Arg, Result> {
public:
  explicit pointer_to_unary_function(Result (* f)(Arg));
  Result operator()(Arg x) const;
};

注意: operator() 的实参类型与被包装函数的实参类型完全相同. 如果这是值类型, 该实参将按值传递并被复制两次. pointer_to_binary_function 也有类似的问题.

然而, 如果我们改为把实参声明为 const Arg& 来消除这一低效, 那么当 Arg 是引用类型时, 就会出现引用的引用, 这在当前是非法的 (但参见 C++ 核心语言问题编号 106)

因此, operator() 的实参应如何声明, 取决于被包装函数的实参是否为引用. 若是引用, 就直接声明为 Arg; 若是值, 则声明为 const Arg&.

Boost call_traits 类模板包含一个 param_type typedef, 它利用偏特化来精确做出这一决定. 把 operator() 声明为

Result operator()(typename call_traits<Arg>::param_type x) const

即可达到期望的效果 - 既提高了效率, 又不会产生引用的引用.

局限

用于实现这一改进的 call traits 模板依赖偏特化, 因此该改进仅在支持该特性的编译器上可用. 在其他编译器上, 传递给函数的实参将总是按引用传递, 从而仍可能产生引用的引用.
