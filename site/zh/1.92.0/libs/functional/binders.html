绑定器

头文件 functional.hpp 提供 C++ 标准库 (§20.3.6) 中两个绑定器函数对象适配器的增强版本:

  • binder1st
  • binder2nd

以及对应的辅助函数

  • bind1st
  • bind2nd

这些适配器相对标准库中对应组件的关键优势在于: 它们避免了 引用的引用问题.

用法

用法与标准绑定器完全相同. 例如,

class Foo {
public:
  void bar(std::ostream &);
  // ...
};
// ...
std::vector<Foo> c;
// ...
std::for_each(c.begin(), c.end(), 
              boost::bind2nd(boost::mem_fun_ref(&Foo::bar), std::cout));

引用的引用

考虑上面的用法示例

class Foo {
public:
  void bar(std::ostream &);
  // ...
};
// ...
std::for_each(c.begin(), c.end(), 
              boost::bind2nd(boost::mem_fun_ref(&Foo::bar), std::cout));

如果这段代码改用 std::bind2nd 与 std::mem_fun_ref 编写, 那么它多半无法编译.

问题出在 bar 接受一个引用实参. 标准对 std::mem_fun_ref 的定义使得它创建的函数对象, 其 second_argument_type 将是 std::ostream&.

对 bind2nd 的调用会创建一个 binder2nd, 标准将其定义如下:

template <class Operation>
class binder2nd
    : public unary_function<typename Operation::first_argument_type,
                            typename Operation::result_type> {
...
public:
  binder2nd(const Operation& x,
            const typename Operation::second_argument_type& y);
  ...

由于我们的操作的 second_argument_type 是 std::ostream&, 构造函数中 y 的类型将是 std::ostream&&. 由于不能存在引用的引用, 此时应得到一个编译错误, 因为引用的引用在 C++ 中是非法的 (但参见 C++ 标准核心语言活跃问题列表).

本库中的绑定器通过使用 Boost call_traits 模板避免了这一问题.

我们的构造函数声明为

binder2nd(const Operation& x,
          typename call_traits<
             typename binary_traits<Operation>::second_argument_type
          >::param_type y)

于是, y 的类型为 std::ostream&, 我们的示例得以编译.
