简述

模板 boost::factory 允许你把 new 表达式封装为函数对象; boost::value_factory 则封装一次不使用 new 的构造函数调用.

boost::factory<T*>()(arg1,arg2,arg3)
// same as new T(arg1,arg2,arg3)

boost::value_factory<T>()(arg1,arg2,arg3)
// same as T(arg1,arg2,arg3)

在 C++11 之前, 函数对象的参数必须是左值. 同时接受右值的工厂可以用 boost::forward_adapter 或 boost::bind 组合得到. 在 C++11 或更高版本中, 参数可以是左值或右值.

Background

在传统的面向对象程序设计中, 工厂 (Factory) 是一个实现了一个或多个方法之接口的对象, 这些方法构造符合已知接口的对象.

// assuming a_concrete_class and another_concrete_class are derived
// from an_abstract_class

struct a_factory {
    virtual an_abstract_class* create() const = 0;
    virtual ~a_factory() { }
};

struct a_concrete_factory
    : a_factory {
    an_abstract_class* create() const {
        return new a_concrete_class();
    }
};

struct another_concrete_factory
    : a_factory {
    an_abstract_class* create() const {
        return new another_concrete_class();
    }
};

// [...]

int main()
{
    boost::ptr_map<std::string, a_factory> factories;

    // [...]

    factories.insert("a_name",
        std::unique_ptr<a_factory>(new a_concrete_factory));
    factories.insert("another_name",
        std::unique_ptr<a_factory>(new another_concrete_factory));

    // [...]

    std::unique_ptr<an_abstract_class> x(factories.at(some_name).create());

    // [...]
}

这种做法有几个缺点. 最明显的是存在大量样板代码. 换句话说, 表达一个相当简单的意图却要写太多代码. 我们可以用模板消掉一部分, 但这种做法仍然不够灵活:

  • 我们可能想要一个工厂, 它接受一些被转发给构造函数的参数,
  • 我们多半会想使用智能指针,
  • 我们可能想要多个成员函数来创建不同种类的对象,
  • 我们未必需要为这些对象提供一个多态基类,
  • 正如我们将看到的, 我们根本不需要工厂基类,
  • 我们可能想直接调用构造函数——不通过 new 而在栈上创建对象,
  • 最后, 我们可能想使用定制的内存管理.

经验表明, 使用函数对象以及用于组合它们的通用 Boost 组件, 那些描述回调机制的设计模式 (在纯面向对象方法论下通常需要大比例的样板代码) 只需几行代码、无需额外的类即可实现.

工厂是构造函数的回调机制, 因此我们提供两个类模板 boost::value_factory 和 boost::factory, 分别通过直接应用构造函数和 new 运算符来封装对象构造.

我们让这些函数对象把参数转发给它们所封装的构造表达式. 在此基础上, boost::factory 还可选地允许使用智能指针和分配器 (Allocator).

可以在适当之处使用编译期多态,

template<class T>
void do_something()
{
    // [...]
    T x = T(a, b);

    // for conceptually similar objects x we neither need virtual
    // functions nor a common base class in this context.
    // [...]
}

现在, 为了允许为 T 传入的类型其构造函数具有不一致的签名, 我们可以使用 value_factory 和 boost::bind 来在它们之间做归一化.

template<class ValueFactory>
void do_something(ValueFactory make_obj = ValueFactory())
{
    // [...]
    typename ValueFactory::result_type x = make_obj(a, b);

    // for conceptually similar objects x we neither need virtual
    // functions nor a common base class in this context.
    // [...]
}

int main()
{
    // [...]

    do_something(boost::value_factory<X>());
    do_something(boost::bind(boost::value_factory<Y>(), _1, 5, _2));
    // construct X(a, b) and Y(a, 5, b), respectively.

    // [...]
}

也许我们希望对象在函数作用域结束后仍然存活, 这时就必须使用动态分配;

template<class Factory>
whatever do_something(Factory new_obj = Factory())
{
    typename Factory::result_type ptr = new_obj(a, b);

    // again, no common base class or virtual functions needed,
    // we could enforce a polymorphic base by writing e.g.
    //     boost::shared_ptr<base>
    // instead of
    //     typename Factory::result_type
    // above.
    // Note that we are also free to have the type erasure happen
    // somewhere else (e.g. in the constructor of this function's
    // result type).

    // [...]
}

// [... call do_something like above but with boost::factory instead
// of boost::value_factory]

尽管前一个例子中我们可能创建的是多态对象, 但工厂用到的仍是编译期多态. 若想擦除工厂的类型从而允许运行期多态, 可以使用 Boost.Function 来实现. 第一个示例可以改写如下.

typedef boost::function<an_abstract_class*()> a_factory;

// [...]

int main()
{
    std::map<std::string, a_factory> factories;

    // [...]

    factories["a_name"] = boost::factory<a_concrete_class*>();
    factories["another_name"] = boost::factory<another_concrete_class*>();

    // [...]
}

当然, 我们同样可以轻松创建接受参数和/或返回 Smart Pointers 的工厂.

factory

说明

为模板参数给出的指针类型动态构造所指对象的函数对象模板. 模板参数可以使用智能指针, 只要 pointer_traits<Pointer>::element_type 能给出所指类型.

若提供了分配器 (Allocator), 则用它进行内存分配, 并使用 new 运算符的 placement 形式来构造对象. 一个调用析构函数并用分配器副本释放内存的函数对象被用作 Pointer 的第二个构造参数 (因此它必须是一个提供合适构造函数的智能指针 (Smart Pointer), 例如 boost::shared_ptr).

若第三个模板参数为 factory_passes_alloc_to_smart_pointer, 则分配器本身被用作 Pointer 的第三个构造参数 (此时 boost::shared_ptr 会用该分配器管理其单独分配的引用计数的内存).

头文件 

#include <boost/functional/factory.hpp>

概要 

namespace boost {

enum factory_alloc_propagation {
    factory_alloc_for_pointee_and_deleter,
    factory_passes_alloc_to_smart_pointer
};

template<class Pointer,
    class Allocator = void,
    factory_alloc_propagation Policy = factory_alloc_for_pointee_and_deleter>
class factory;

} // boost

变更

Boost 1.72.0

Glen Fernandes 重写了 factory 和 value_factory 的实现, 以提供以下特性:

  • 在可用时支持右值参数
  • 在可用时通过变参模板支持任意数量的参数
  • 支持 final 分配器
  • 支持使用花式指针 (fancy pointer) 的分配器
  • 支持禁用异常 (BOOST_NO_EXCEPTIONS)
  • 缩短编译时间

以下特性已被移除:

  • 通过 BOOST_FUNCTIONAL_VALUE_FACTORY_MAX_ARITY 提高 C++03 编译器的上限
  • 通过 boost::none_t 用 void 取代 BOOST_FUNCTIONAL_FACTORY_SUPPORT_NONE_T

Boost 1.58.0

为了移除对 Boost.Optional 的依赖, 分配器的默认参数已从 boost::none_t 改为 void. 若你有代码因为使用了 boost::none_t 而停止工作, 一个快速的解决办法是定义 BOOST_FUNCTIONAL_FACTORY_SUPPORT_NONE_T, 它会恢复相关支持; 但该宏将在未来版本中被移除. 妥善修复这个问题应当相对容易.
