引言

本教程开发一个小型命令行程序, 用于列出文件与目录的信息——本质上是 POSIX ls 或 Windows dir 命令的极大简化版. 我们将从最简单的版本开始, 逐步走向更复杂的功能. 过程中我们会穿插讲解理解 Boost.Filesystem 所需的主题.

每个教程程序的源代码都可获得, 鼓励你对它进行编译、测试与试验. 为节省篇幅, 我们不会总是在这里展示样板代码, 但提供的源代码是完整的, 可以直接构建.

准备工作

如果尚未安装, 请安装 Boost 发行版. 参见Boost 入门文档.

本教程假定你已按《入门》一文的描述完成 Boost.Build 的引导 (bootstrap) 并编译了 Boost.Filesystem. b2 可执行文件应当可以在 PATH 中找到.

启动你的命令行解释器, 并输入以下命令:

如果 tut1 命令输出 "Usage: tut1 path", 那么一切正常. 教程示例程序位于 boost-root/libs/filesystem/example. 随着教程推进, 如果你修改并试验它们, 只需再次调用 b2 tutorial 重新构建.

如果有地方不能正常工作, 下面是一些排障建议:

  • 如果找不到 b2 程序可执行文件, 请检查你的 path 环境变量或参见Boost 入门.
  • 查看 Boost 引导 (bootstrap) 输出, 尝试找出问题的迹象.

报告文件大小 - (tut1.cpp)

开始吧. 第一个示例程序 tut1.cpp 报告文件的大小:

#include <iostream>
#include <boost/filesystem.hpp>
using namespace boost::filesystem;

int main(int argc, char* argv[])
{
  if (argc < 2)
  {
    std::cout << "Usage: tut1 path\n";
    return 1;
  }
  std::cout << argv[1] << " " << file_size(argv[1]) << '\n';
  return 0;
}

Boost.Filesystem file_size 函数返回一个 uintmax_t, 其中包含参数所命名文件的大小. 声明形如:

uintmax_t file_size(const path& p);

眼下你只需要知道 class path 具有接受 const char * 及其他字符串类型的构造函数. (如果你迫不及待想了解更多, 可以跳到教程的类 path一节. )

使用状态查询确定文件存在性与类型 - (tut2.cpp)

Boost.Filesystem 包含诸如 exists、is_directory 和 is_regular_file 的状态查询函数. 它们返回 bool, 如果其名称所描述的条件满足则返回 true. 否则返回 false, 包括当路径参数的任何元素找不到时.

tut2.cpp 使用多个状态查询函数来应对不存在的文件与不同种类的文件:

#include <iostream>
#include <boost/filesystem.hpp>
using namespace std;
using namespace boost::filesystem;

int main(int argc, char* argv[])
{
  if (argc < 2)
  {
    cout << "Usage: tut2 path\n";
    return 1;
  }

  path p(argv[1]);  // avoid repeated path construction below

  if (exists(p))    // does path p actually exist?
  {
    if (is_regular_file(p))        // is path p a regular file?
      cout << p << " size is " << file_size(p) << '\n';

    else if (is_directory(p))      // is path p a directory?
      cout << p << " is a directory\n";

    else
      cout << p << " exists, but is not a regular file or directory\n";
  }
  else
    cout << p << " does not exist\n";

  return 0;
}

目录迭代加捕获异常 - (tut3.cpp)

Boost.Filesystem 的 directory_iterator 类正是我们这里需要的. 它遵循标准库 istream_iterator 的一般模式. 从路径构造后, 它对目录内容进行迭代. 默认构造的 directory_iterator 充当尾迭代器.

directory_iterator 的值类型是 directory_entry. directory_entry 对象包含 path 与 file_status 信息. directory_entry 对象可以直接使用, 也可以传给函数调用中的 path 参数.

另一个需要是在可能影响文件系统操作的多种错误面前提高健壮性. 我们可以在每次调用 Boost.Filesystem 函数的层面做到这一点 (参见错误报告), 但为简单起见, tut3.cpp 使用一个整体的 try/catch 块.

#include <iostream>
#include <boost/filesystem.hpp>
using std::cout;
using namespace boost::filesystem;

int main(int argc, char* argv[])
{
  if (argc < 2)
  {
    cout << "Usage: tut3 path\n";
    return 1;
  }

  path p (argv[1]);

  try
  {
    if (exists(p))
    {
      if (is_regular_file(p))
        cout << p << " size is " << file_size(p) << '\n';

      else if (is_directory(p))
      {
        cout << p << " is a directory containing:\n";

        for (directory_entry& x : directory_iterator(p))
          cout << "    " << x.path() << '\n';
      }
      else
        cout << p << " exists, but is not a regular file or directory\n";
    }
    else
      cout << p << " does not exist\n";
  }

  catch (const filesystem_error& ex)
  {
    cout << ex.what() << '\n';
  }

  return 0;
}

使用 path 分解, 加排序结果 - (tut4.cpp)

对目录, tut4.cpp 先构建一个包含所有条目的 std::vector, 排序后再写入 cout.

#include <iostream>
#include <vector>
#include <algorithm>
#include <boost/filesystem.hpp>
using std::cout;
using namespace boost::filesystem;

int main(int argc, char* argv[])
{
  if (argc < 2)
  {
    cout << "Usage: tut4 path\n";
    return 1;
  }

  path p (argv[1]);

  try
  {
    if (exists(p))
    {
      if (is_regular_file(p))
        cout << p << " size is " << file_size(p) << '\n';

      else if (is_directory(p))
      {
        cout << p << " is a directory containing:\n";

        std::vector<path> v;

        for (auto&& x : directory_iterator(p))
          v.push_back(x.path());

        std::sort(v.begin(), v.end());

        for (auto&& x : v)
          cout << "    " << x.filename() << '\n';
      }
      else
        cout << p << " exists, but is not a regular file or directory\n";
    }
    else
      cout << p << " does not exist\n";
  }

  catch (const filesystem_error& ex)
  {
    cout << ex.what() << '\n';
  }

  return 0;
}

tut3.cpp 与 tut4.cpp 之间的唯一差别是对目录的处理方式. 我们把:

for (const directory_entry& x : directory_iterator(p))
  cout << " " << x.path() << '\n';

改为:

std::vector<path> v;

for (auto&& x : directory_iterator(p))
  v.push_back(x.path());

std::sort(v.begin(), v.end());

for (auto&& x : v)
  cout << " " << x.filename() << '\n';

filename() 是类 path 若干分解函数之一. 它从路径中提取文件名部分 (即 "index.html" 取自 "/home/beman/boost/trunk/index.html"). 这些分解函数在本教程的Path iterators, observers, composition, decomposition and query部分有更完整的探讨.

为了清晰, 上面的代码写成了两行. 其实可以写得更简洁:

v.push_back(it->path().filename()); // we only care about the filename

类 path: 构造函数, 包括 Unicode - (tut5.cpp)

传统 C 接口以 const char* 参数传递路径. C++ 接口可以添加 const std::string& 重载, 但如果需要支持宽字符、容器与迭代器范围, 添加重载就难以为继了.

以 const path& 参数传递路径要简单得多, 然而又灵活得多, 因为类 path 本身要灵活得多:

  1. 类 path 支持多种字符类型与编码, 包括 Unicode, 以便于国际化.
  2. 类 path 支持多种源类型, 例如用于以空字符结尾序列的迭代器、迭代器范围、字符串类类型 (包括 std::basic_string 和 std::basic_string_view) 以及 directory_entry, 因此接受路径的函数无需提供多个重载.
  3. 类 path 同时支持原生与通用路径名格式, 因此程序可以在操作系统之间可移植, 同时在需要时使用原生格式.
  4. 类 path 提供整套迭代器、观察器、组合、分解与查询函数, 使路径名操作简单、方便、可靠且可移植.

下面说明 (1) 与 (2) 是如何工作的. 类 path 的构造函数、赋值与追加都有针对源类型的成员模板. 例如, 下面是接受源的构造函数:

template <class Source>
  path(Source const& source);
template <class InputIterator>
  path(InputIterator begin, InputIterator end);

让我们看一个小程序, 它展示类 path 对 C 风格字符串、C++ 字符串以及通过 C++ 迭代器中的窄字符与宽字符都处理得多么自如:

#include <boost/filesystem/fstream.hpp>
#include <string>
#include <list>
namespace fs = boost::filesystem;

int main()
{
  // \u263A is "Unicode WHITE SMILING FACE = have a nice day!"
  std::string narrow_string ("smile2");
  std::wstring wide_string (L"smile2\u263A");
  std::list<char> narrow_list;
  narrow_list.push_back('s');
  narrow_list.push_back('m');
  narrow_list.push_back('i');
  narrow_list.push_back('l');
  narrow_list.push_back('e');
  narrow_list.push_back('3');
  std::list<wchar_t> wide_list;
  wide_list.push_back(L's');
  wide_list.push_back(L'm');
  wide_list.push_back(L'i');
  wide_list.push_back(L'l');
  wide_list.push_back(L'e');
  wide_list.push_back(L'3');
  wide_list.push_back(L'\u263A');

  { fs::ofstream f("smile"); }
  { fs::ofstream f(L"smile\u263A"); }
  { fs::ofstream f(narrow_string); }
  { fs::ofstream f(wide_string); }
  { fs::ofstream f(fs::path(narrow_list.begin(), narrow_list.end())); }
  { fs::ofstream f(fs::path(wide_list.begin(), wide_list.end())); }
  narrow_list.pop_back();
  narrow_list.push_back('4');
  wide_list.pop_back();
  wide_list.pop_back();
  wide_list.push_back(L'4');
  wide_list.push_back(L'\u263A');
  { fs::ofstream f(fs::path(narrow_list.begin(), narrow_list.end())); }
  { fs::ofstream f(fs::path(wide_list.begin(), wide_list.end())); }

  return 0;
}

类 path 会处理特定操作系统所需的任何字符类型或编码转换. 因此正如 tut5 所展示的, 即使底层操作系统使用窄字符, 把宽字符串传给 Boost.Filesystem 操作函数也不成问题, 反之亦然. 对接受 const path& 参数的用户自备函数同样如此.

类 path 还提供跨操作系统可移植的路径语法、元素迭代器, 以及用于操作路径元素的观察器、组合、分解与查询函数. 本教程下一节讨论路径语法.

类 path: 通用格式与原生格式

类 path 处理两种不同的路径名格式——通用格式与原生格式. 对类 POSIX 文件系统, 这两种格式是相同的. 但对 Windows 及其他非 POSIX 文件系统的用户, 这一区分很重要. 即使是面向类 POSIX 系统编写的程序员, 如果希望其代码可移植到非 POSIX 系统, 也需要理解这一区分.

通用格式是类 POSIX 操作系统 (如 Unix 变体、Linux 和 Mac OS X) 使用的熟悉的 /my_directory/my_file.txt 格式. Windows 也识别通用格式, 它是人们熟悉的 Internet URL 格式的基础. 目录分隔符总是一个或多个斜杠字符.

原生格式是特定操作系统定义的格式. 对 Windows, 斜杠或反斜杠都可用作目录分隔符, 因此 /my_directory\my_file.txt 也能正常工作. 当然, 如果在 C++ 字符串字面量中这样写, 它就变成 "/my_directory\\my_file.txt".

如果 Windows 系统的路径名中出现驱动器指示符或反斜杠, 它总是被当作原生格式.

类 path 具有观察器函数, 让你能以原生格式或通用格式获得 path 对象的字符串表示. 具体如何, 参见下一节.

与原生 C 风格 API 以及与用户交流时, 通用格式与原生格式的区分很重要. 两者都倾向于期望原生格式的路径, 可能会被通用格式弄糊涂. 不过, 对于编写不依赖操作系统的可移植程序, 通用格式非常好用.

下一节介绍类 path 的观察器、组合、分解、查询以及路径元素的迭代.

类 path: 迭代器、观察器、组合、分解与查询 - (path_info.cpp)

path_info.cpp 程序对了解类 path 的迭代器、观察器、组合、分解与查询函数在你的系统上如何工作很方便.

#include <iostream>
#include <boost/filesystem.hpp>
using namespace std;
using namespace boost::filesystem;

const char * say_what(bool b) { return b ? "true" : "false"; }

int main(int argc, char* argv[])
{
  if (argc < 2)
  {
    cout << "Usage: path_info path-element [path-element...]\n"
            "Composes a path via operator/= from one or more path-element arguments\n"
            "Example: path_info foo/bar baz\n"
#            ifdef BOOST_FILESYSTEM_POSIX_API
            "         would report info about the composed path foo/bar/baz\n";
#            else  // BOOST_FILESYSTEM_WINDOWS_API
            "         would report info about the composed path foo/bar\\baz\n";
#            endif
    return 1;
  }

  path p;
  for (; argc > 1; --argc, ++argv)
    p /= argv[1];  // compose path p from the command line arguments

  cout  <<  "\ncomposed path:\n";
  cout  <<  "  operator<<()---------: " << p << "\n";
  cout  <<  "  make_preferred()-----: " << p.make_preferred() << "\n";

  cout << "\nelements:\n";
  for (auto element : p)
    cout << "  " << element << '\n';

  cout  <<  "\nobservers, native format:" << endl;
# ifdef BOOST_FILESYSTEM_POSIX_API
  cout  <<  "  native()-------------: " << p.native() << endl;
  cout  <<  "  c_str()--------------: " << p.c_str() << endl;
# else  // BOOST_FILESYSTEM_WINDOWS_API
  wcout << L"  native()-------------: " << p.native() << endl;
  wcout << L"  c_str()--------------: " << p.c_str() << endl;
# endif
  cout  <<  "  string()-------------: " << p.string() << endl;
  wcout << L"  wstring()------------: " << p.wstring() << endl;

  cout  <<  "\nobservers, generic format:\n";
  cout  <<  "  generic_string()-----: " << p.generic_string() << endl;
  wcout << L"  generic_wstring()----: " << p.generic_wstring() << endl;

  cout  <<  "\ndecomposition:\n";
  cout  <<  "  root_name()----------: " << p.root_name() << '\n';
  cout  <<  "  root_directory()-----: " << p.root_directory() << '\n';
  cout  <<  "  root_path()----------: " << p.root_path() << '\n';
  cout  <<  "  relative_path()------: " << p.relative_path() << '\n';
  cout  <<  "  parent_path()--------: " << p.parent_path() << '\n';
  cout  <<  "  filename()-----------: " << p.filename() << '\n';
  cout  <<  "  stem()---------------: " << p.stem() << '\n';
  cout  <<  "  extension()----------: " << p.extension() << '\n';

  cout  <<  "\nquery:\n";
  cout  <<  "  empty()--------------: " << say_what(p.empty()) << '\n';
  cout  <<  "  is_absolute()--------: " << say_what(p.is_absolute()) << '\n';
  cout  <<  "  has_root_name()------: " << say_what(p.has_root_name()) << '\n';
  cout  <<  "  has_root_directory()-: " << say_what(p.has_root_directory()) << '\n';
  cout  <<  "  has_root_path()------: " << say_what(p.has_root_path()) << '\n';
  cout  <<  "  has_relative_path()--: " << say_what(p.has_relative_path()) << '\n';
  cout  <<  "  has_parent_path()----: " << say_what(p.has_parent_path()) << '\n';
  cout  <<  "  has_filename()-------: " << say_what(p.has_filename()) << '\n';
  cout  <<  "  has_stem()-----------: " << say_what(p.has_stem()) << '\n';
  cout  <<  "  has_extension()------: " << say_what(p.has_extension()) << '\n';

  return 0;
}

我们将详细过一遍上面的代码, 以更好地理解正在发生什么.

一个常见需求是从路径的组成目录构建路径. 类 path 使用 / 与 /= 运算符来追加元素. 这提醒我们: 这些操作会在需要时追加操作系统的首选目录分隔符. 首选目录分隔符在类 POSIX 系统上是斜杠, 在类 Windows 系统上是反斜杠.

这正是这段代码在显示结果 path p (使用 class path 流插入符) 之前所做的事情:

  path p;
  for (; argc > 1; --argc, ++argv)
    p /= argv[1];  // compose path p from the command line arguments

  cout  <<  "\ncomposed path:\n";
  cout  <<  "  operator<<()---------: " << p << "\n";
  cout  <<  "  make_preferred()-----: " << p.make_preferred() << "\n";

思考路径的一种抽象是把它看作元素的序列, 元素即目录名与文件名. 为支持这一抽象, 类 path 提供迭代器以及 begin() 和 end() 函数.

下面是产生上述输出列表中元素列表的代码:

cout << "\nelements:\n";
for (auto element : p)
  cout << " " << element << '\n';

与操作系统或用户交互时应使用原生格式观察器; 那正是他们所期望的.

当结果需要无论操作系统为何都保持可移植与一致时, 应使用通用格式观察器.

path 对象总是以原生格式保存路径名, 但除此之外不改源地保留其源内容. preferred() 函数会在原生格式有几种形式时转换为首选形式. 因此在 Windows 上, 它会把斜杠转换为反斜杠.

错误报告

Boost.Filesystem 的 file_size 函数与许多操作函数一样, 有两个重载:

uintmax_t file_size(const path& p);
uintmax_t file_size(const path& p, system::error_code& ec);

两者唯一的重要差别是报告错误的方式.

第一个签名会抛出异常来报告错误. 发生操作错误时会抛出 filesystem_error 异常. filesystem_error 派生自 std::runtime_error. 它有成员函数可获取错误来源报告的 error_code. 它还有成员函数可获取导致错误的路径.

第二个签名的动机: 在错误时抛出异常曾是 Boost.Filesystem 最早版本的全部错误报告机制, 而且对许多应用而言, 在错误时抛出异常确实工作得非常好. 但用户反馈陆续而来: 一些代码被 try 与 catch 块塞满, 以至于不可读、不可维护. 在某些应用中 I/O 错误并非异常情况, 这正是第二个签名的用例.

带 system::error_code& 参数的函数会设置该参数以报告操作错误状态, 因而在发生 I/O 相关错误时不抛出异常. 完整说明参见参考文档中的错误报告.
