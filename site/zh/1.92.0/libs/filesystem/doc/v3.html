Boost Filesystem Version 3

Version 3 是 Boost Filesystem 库的一次重大修订. 重要变更包括:

  • 单一类 path 处理国际化的所有方面, 取代了先前的模板及其 path 与 wpath 实例化. 支持字符类型 char、wchar_t、char16_t 和 char32_t. 这是对路径抽象的重大简化, 对接受路径参数的函数尤其如此.
  • 新的 class path 成员包括:
    • has_stem()
    • has_extension()
    • is_absolute(). 它把 is_complete() 改名, 后者现已弃用.
    • is_relative()
    • make_preferred()
       
  • 新增或改进的操作函数包括:
    • absolute(). 它取代了操作函数 complete(), 后者现已弃用. 现在为 Windows 边界情形 (base 参数不是绝对路径) 提供了语义. 以前这会导致抛出异常.
    • create_symlink() 现在在 POSIX 与 Windows 上都受支持.
    • read_symlink() 函数已添加. POSIX 与 Windows 上都受支持. 用于读取符号链接本身的内容.
    • resize_file() 函数已添加. POSIX 与 Windows 上都受支持. 用于收缩或增长普通文件.
    • unique_path() 函数已添加. POSIX 与 Windows 上都受支持. 用于生成安全的临时路径名.
  • 通过 error_code 进行错误报告的支持现在在整个操作函数中保持一致.
  • 文档经过重做, 包括大部分章节的重写.
  • 新的教程为新用户提供了希望更加平缓、更加完整的入门介绍. 现有用户可能想重温与类 path 相关的三节.

已弃用的名称与其他特性

过渡辅助手段使大量现有代码在使用 Version 3 时无需修改即可编译, 参见已弃用特性页面.

破坏性变更

为便于过渡, Version 2 与 Version 3 曾同时包含在其后的几个 Boost 发布中. Version 2 已在 Boost 1.50.0 中移除.

类 path

  • 类模板 basic_path 及其特化被单一 class path 取代. 因此, 任何依赖 path 与 wpath 是两个不同类型的代码 (如重载函数) 将无法编译, 必须重构. 重构可能像移除一个重载那样简单, 但也可能需要更复杂的重新设计.
  • 某些函数现在返回 path 对象而不是 string or wstring 对象:
    • root_name()
    • root_directory()
    • filename()
    • stem()
    • extension()

    并非所有用法都会失败; 如果函数在被接受 path 的上下文中调用, 那就没有问题. 如果结果被用在要求 std::string 或 std::wstring 的上下文中, 则必须在函数调用后分别追加 .string() 或 .wstring().

  • path::iterator::value_type 和 path::const_iterator::value_type 是 path 而不是 basic_string.

编译器支持

  • 不完全支持宽字符与宽字符串 (std::wstring) 的编译器与标准库不再受支持.
  • 1.7 之前的 Cygwin 版本不再受支持, 因为它们缺少宽字符串支持. Cygwin 现在只针对 POSIX API 和路径语法编译.
  • 不支持宽字符串的 MinGW 版本不再受支持.
  • Microsoft VC++ 7.1 及更早版本不再受支持.
