Boost Filesystem Version 4

Version 4 是 Boost Filesystem 库的一次重大修订, 使其接口与行为更接近 C++17 引入、并在后续标准中更新的 std::filesystem. 它移除了 Version 3 中已弃用的特性, 并作出多项破坏性变更.

用户可以在编译代码时把 BOOST_FILESYSTEM_VERSION 宏定义为 4 来选择 Boost.Filesystem v4 版本. 无需为每个库版本单独编译 Boost.Filesystem——单个二进制文件同时支持 v3 和 v4. 用户应避免在同一应用中同时使用 v3 与 v4, 因为这可能引入隐蔽的缺陷.

破坏性变更

  • path::filename 不再返回根名称或根目录, 如果路径不包含其他元素. 例如, 在 Windows 上 path("C:").filename() 过去返回 "C:" 而 path("C:\").filename() 过去返回 "\", 现在两者都将返回空路径. 这也影响 path::stem 和 path::extension 方法, 因为它们基于 path::filename.
  • path::stem 与 path::extension 不再把以点号开头且没有其他点号的文件名视为扩展名. 以点号开头的文件名通常被视为带空扩展名的文件名. 在多数类 UNIX 系统上, 前导点号用于指示隐藏文件.
  • path::filename 与 path::iterator 不再返回隐式的结尾点号 (".") 元素, 如果路径以目录分隔符结尾. 改为返回空路径, 类似于 C++17 std::filesystem. 这也影响以迭代器或文件名定义的其他方法, 例如 path::stem、path::compare 或 lexicographical_compare. 例如, path("a/b/") == path("a/b/.") 不再成立.
  • path::lexically_normal 不再在规范化路径中产生结尾点号 (".") 元素, 并省略结尾 dot-dot ("..") 元素之后的目录分隔符.
  • path::lexically_normal、path::make_preferred、path::generic_string 及类似方法不再在返回路径的根名称中转换正斜杠与反斜杠.
  • path 追加会考虑被追加路径的根名称与根目录. 如果被追加路径是绝对路径, 或存在根名称且与源路径不同, 则结果路径等价于被追加的路径. 如果存在根目录, 则结果是重新定基于源路径根名称之上的根目录与相对路径. 否则, 行为类似于 v3. 该行为类似于 C++17 std::filesystem.
  • path 不再支持从字符容器进行构造、赋值或追加. 请改用字符串类型或迭代器作为这些操作的来源.
  • path::remove_filename 保留结尾目录分隔符, 因此 path::has_filename 返回 false——在成功调用 path::remove_filename 之后.
  • directory_entry 构造函数与修改器 (初始化或修改目录项的路径) 现在会自动调用 directory_entry::refresh, 而不是清除缓存的文件状态. 这意味着在调用点, 新路径所标识的文件需要能在文件系统中访问.
  • directory_entry 构造函数与修改器 (接受 file_status 参数以初始化缓存的文件状态) 已被移除. 缓存数据量是 directory_entry 的实现细节, 将来可能不限于仅文件状态. 用户应依赖缓存数据的自动刷新.
  • equivalent 现在会失败, 如果输入路径中只有一个存在.
