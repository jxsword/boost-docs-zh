引言

UUID (universally unique identifier, 通用唯一标识符) 用于在分布式环境中唯一地标识信息, 而无需大量的中央协调. 它可用于为生存期极短的对象打标签, 也可用于在网络上可靠地标识非常持久的对象.

UUID 的正式定义见 RFC 4122 和 RFC 9562.

UUID 有许多应用. 下面举一些例子: 数据库可以用 UUID 来标识行或记录, 以确保它们在不同数据库之间是唯一的, 或者用于发布/订阅服务. 网络消息可以用 UUID 来标识, 以确保消息的不同部分能够重新拼合在一起. 分布式计算可以用 UUID 来标识一次远程过程调用. 事务以及序列化所涉及的类可以用 UUID 来标识. Microsoft 的组件对象模型 (COM) 使用 UUID 来区分不同的软件组件接口. Microsoft Office 程序生成的文档中会插入 UUID. UUID 用于标识高级系统格式 (ASF) 中的音频或视频流. UUID 还是 OID (对象标识符) 和 URN (统一资源名称) 的基础.

与其他替代方案相比, UUID 的一个吸引人之处是其相对较小的尺寸, 即 128 位 (16 字节). 另一个吸引人之处是创建 UUID 不需要中央权威机构.

当 UUID 由所定义的某种机制生成时, 它们要么保证唯一, 即不同于所有其他已生成的 UUID (也就是说, 该 UUID 此前从未被生成过, 也将永远不会再次生成), 要么极有可能唯一 (取决于具体机制).

修订历史

Boost 1.91.0 中的变更

  • 添加了 from_chars 到 boost/uuid/uuid_io.hpp 中.

  • 添加了 noexcept operator() 重载到 string_generator.

  • string_generator 现在除 char 和 wchar_t 之外还支持 Unicode 字符类型.

  • 大多数 uuid 访问器, 操作以及 to_chars 在可能时现在是 constexpr 的 (在 C++14 及更高版本和较新的编译器上).

  • 添加了 to_chars 的 SIMD 实现, 在 UUID 格式化方面可带来最高 5.5 倍的性能提升. (Andrey Semashev)

  • 添加了 from_chars 的 SIMD 实现, 在 UUID 解析方面可带来最高 13 倍的性能提升. (Andrey Semashev)

  • 添加了 uuid_from_string 到 boost/uuid/uuid_io.hpp 中.

  • 添加了专门的 invalid_uuid 异常类, 为向后兼容而派生自 std::runtime_error.

Boost 1.90.0 中的变更

  • string_generator 在 C++14 及更高版本上现在是 constexpr 的.

  • 添加了头文件 boost/uuid/constants.hpp.

  • 将 boost/uuid/uuid_generators.hpp 重命名为 boost/uuid/generators.hpp. 旧名称为兼容性起见而保留.

Boost 1.87.0 中的变更

  • 恢复了在 1.86 中被意外丢失的构造 constexpr uuid 的能力.

Boost 1.86.0 中的变更 (重大更新)

  • 不再支持 C++03, 需要 C++11 编译器. 这包括 GCC 4.8 或更高版本, MSVC 14.0 或更高版本, 以及 MinGW-w64.

  • 移除了对 Core, Io, Move, NumericConversion, StaticAssert, TTI, Random, ContainerHash 的直接依赖. 本库现在总共只有五个 Boost 依赖 (而 Boost 1.85 中有 39 个).

  • 将 std::hash 支持从 uuid_hash.hpp 移到了 uuid.hpp.

  • 将序列化支持从 uuid_serialize.hpp 移到了 uuid.hpp.

  • 改进了 hash_value 的质量和速度.

  • 添加了 operator<=>.

  • is_nil, operator==, operator<, swap 和 operator<=> 的通用 (非 SIMD) 实现在该类型可用时现在使用 __uint128_t 操作, 否则使用 uint64_t 操作.

  • 添加了便捷头文件 <boost/uuid.hpp>.

  • 移除了平台特定的熵提供程序; 实现现在使用 std::random_device 作为熵的来源.

  • basic_random_generator 已被移到其自己的头文件 boost/uuid/basic_random_generator.hpp 中.

  • basic_random_generator 已被改为按值持有底层生成器, 以避免动态分配并恢复可复制性.

  • random_generator_pure 现在是 basic_random_generator<std::random_device> 的别名, 不鼓励使用它.

  • random_generator_mt19937 现在是 basic_random_generator<std::mt19937> 的别名, 不鼓励使用它.

  • random_generator 现在使用密码学强伪随机数生成器 (ChaCha20/12), 并以来自 std::random_device 的熵作种子. 它是生成版本 4 UUID 的推荐方式.

  • 由于 basic_name_generator 只有两个有效实例化, 且两者都已提供 (name_generator_md5 和 name_generator_sha1), 它被改成了私有的实现细节, 不再是公共接口的一部分.

  • 虽然 name_generator 和 name_generator_latest 仍为兼容性而提供, 但不再鼓励使用它们.

  • 基于名称的生成器现在接受 Unicode 字符串; 这些字符串在哈希之前会被转换为 UTF-8.

  • 众所周知的 RFC 4122 命名空间的定义已被移到其自己的头文件 boost/uuid/namespaces.hpp 中.

  • 添加了 time_generator_v1, 一个生成版本 1 基于时间的 UUID 的生成器.

  • 添加了 time_generator_v6, 一个生成版本 6 基于时间的 UUID 的生成器.

  • 添加了 time_generator_v7, 一个生成版本 7 基于时间的 UUID 的生成器.

  • 添加了 uuid_clock, 一个与 <chrono> 兼容的时钟, 其纪元和分辨率符合 RFC 4122 的规定.

  • 为 uuid 添加了时间戳, 时间点, 时钟序列和节点标识符的访问器.

  • 改进了 what() 字符串, 它们来自 std::runtime_error 异常 (由 string_generator 抛出).

  • 添加了 to_chars 的重载, 接受 Ch* first, Ch* last 和 Ch(&)[N].

  • uuid 的默认构造函数现在产生 nil UUID, 而不是未初始化的 UUID.

  • u.data() (其中 u 的类型为 uuid) 现在返回指向表示形式中第一个 uint8_t 的指针 (与 u.begin() 相同). 为向后兼容起见, data 是一个带有 operator() 的函数对象, 而不是成员函数, 这使得 data 作为公有成员的大多数现有用法仍然有效, 只是不再受到鼓励.

  • uuid 现在具有与 std::uint64_t 相同的对齐. 它之前是无对齐的 (对齐为 1, 与 std::uint8_t 相同). 要恢复 1.85 的行为, 请定义宏 BOOST_UUID_DISABLE_ALIGNMENT.

配置

本库无需构建或任何特殊配置即可使用. 不过, 有几个选项可以通过在包含库头文件之前定义宏来启用.

指令集

宏 说明

BOOST_UUID_NO_SIMD

如果定义了此宏, 则会禁用对支持 SIMD 的处理器的所有优化, 改用算法的通用版本. 这可能导致性能欠佳. 默认情况下, 当本库能够在编译期检测到 SIMD 扩展可用时, 将使用优化后的算法.

BOOST_UUID_USE_SSE2

如果定义了此宏, 则会为 x86 处理器中可用的 SSE2 扩展启用优化.

BOOST_UUID_USE_SSE3

如果定义了此宏, 则会为 x86 处理器中可用的 SSE3 扩展启用优化.

BOOST_UUID_USE_SSSE3

如果定义了此宏, 则会为 x86 处理器中可用的 SSSE3 扩展启用优化.

BOOST_UUID_USE_SSE41

如果定义了此宏, 则会为 x86 处理器中可用的 SSE4.1 扩展启用优化.

BOOST_UUID_USE_AVX

如果定义了此宏, 则会为 x86 处理器中可用的 AVX 扩展启用优化.

BOOST_UUID_USE_AVX2

如果定义了此宏, 则会为 x86 处理器中可用的 AVX2 扩展启用优化.

BOOST_UUID_USE_AVX512_V1

如果定义了此宏, 则会为 x86 处理器中可用的 AVX-512 F, VL, CD, BW 和 DQ 扩展启用优化 (例如 Intel Skylake-X 中).

BOOST_UUID_USE_AVX10_1

如果定义了此宏, 则会为 x86 处理器中可用的 AVX-512 和 AVX10.1 扩展启用优化. 当由用户定义时, 该宏表示支持 AVX10.1 中定义的完整指令集. 当由本库自动检测时, 即使并非所有 AVX10.1 子集都已启用, 该宏也可能被定义, 只要检测到的子集足以满足本库需要即可.

默认情况下, 本库会在编译期尝试检测目标 CPU 中 SIMD 扩展的可用性, 并在成功时自动定义相应的宏. 如果自动检测失败, 且已知目标 CPU 将具有相应扩展, 用户可以定义 BOOST_UUID_USE_SSE* 和 BOOST_UUID_USE_AVX* 宏. 除非确定这些扩展在将运行你的程序的任何机器上都总是可用, 否则不要启用它们. 本库不执行任何运行期检查, 因此如果缺少某个扩展, 程序很可能会崩溃. 注意, 启用更高级的扩展意味着更基础的扩展也可用.

对齐

宏 说明

BOOST_UUID_DISABLE_ALIGNMENT

如果定义了此宏, 则使 uuid 保持无对齐 (对齐为 1, 与 std::uint8_t 相同). 这是 1.86 版发布之前的行为.

默认情况下, uuid 与 std::uint64_t 具有相同的对齐. 定义 BOOST_UUID_DISABLE_ALIGNMENT 可使其保持无对齐.

示例

打标签

// example of tagging an object with a uuid
// see boost/libs/uuid/test/test_tagging.cpp

#include <boost/uuid/uuid.hpp>
#include <boost/uuid/generators.hpp>

class object
{
public:
    object()
        : tag(boost::uuids::random_generator()())
        , state(0)
    {}

    explicit object(int state)
        : tag(boost::uuids::random_generator()())
        , state(state)
    {}

    object(object const& rhs)
        : tag(rhs.tag)
        , state(rhs.state)
    {}

    bool operator==(object const& rhs) const {
        return tag == rhs.tag;
    }

    object& operator=(object const& rhs) {
        tag = rhs.tag;
        state = rhs.state;
    }

    int get_state() const { return state; }
    void set_state(int new_state) { state = new_state; }

private:
    boost::uuids::uuid tag;

    int state;
};

object o1(1);
object o2 = o1;
o2.set_state(2);
assert(o1 == o2);

object o3(3);
assert(o1 != o3);
assert(o2 != o3);

字节提取

有时直接访问 uuid 的 16 个字节会很有用. 典型用法如下:

boost::uuids::uuid u;
std::vector<std::uint8_t> v(u.size());
std::copy(u.begin(), u.end(), v.begin());

注释: boost::uuids::uuid::size() 总是返回 16.

    using reference = std::uint8_t&;
    using const_reference = std::uint8_t const&;

    using iterator = std::uint8_t*;

    using difference_type = std::ptrdiff_t;

    constexpr iterator begin() noexcept;
    constexpr iterator end() noexcept;

    constexpr const_iterator begin() const noexcept;
    constexpr const_iterator end() const noexcept;

    // data

    constexpr std::uint8_t* data() noexcept;
    constexpr std::uint8_t const* data() const noexcept;

    // size

    constexpr size_type size() const noexcept;
    static constexpr size_type static_size() noexcept;

    // is_nil

    constexpr bool is_nil() const noexcept;

    // variant

    enum variant_type
    {
        variant_ncs, // NCS backward compatibility
        variant_rfc_4122, // defined in RFC 4122 document
        variant_microsoft, // Microsoft Corporation backward compatibility
        variant_future // future definition

类 time_generator_v1 生成基于时间的版本 1 UUID. 它支持三种运作模式.

默认且推荐的方式是使用其默认构造函数. 这将指示生成器使用伪随机的节点标识符和初始时钟序列.

如果需要对节点标识符 (或时钟序列) 有更多控制, 例如, 如果生成的 UUID 必须使用在程序生命周期内甚至跨程序运行都持久存在的特定节点标识符, 则提供了一个接受节点标识符和一个 state_type 的构造函数. (timestamp 字段 (位于所提供的 state_type 中) 通常应为零.)

最后, 如果程序中有多个需要使用相同节点标识符的 time_generator_v1 实例 (例如每个线程一个), 则第三个构造函数接受一个节点标识符和对 std::atomic<state_type> 的引用. 生成器使用该原子状态来确保不会产生重复的 UUID.

构造函数

time_generator_v1();
效果:

使用来自 std::random_device 的熵, 在 node_ 中生成伪随机的 48 位节点标识符, 并在 state_.clock_seq 中生成伪随机的 14 位时钟序列. 将 state_.timestamp 初始化为零.

备注:

设置 node_ 的多播位以表示本地节点标识符, 如 RFC 4122 第 4.5 节 所建议.

time_generator_v1( uuid::node_type const& node, state_type const& state ) noexcept;
效果:

将 node_ 初始化为 node, 将 state_ 初始化为 state.

time_generator_v1( uuid::node_type const& node, std::atomic<state_type>& state ) noexcept;
效果:

将 node_ 初始化为 node, 将 ps_ 初始化为 &state.

operator()

result_type operator()() noexcept;
效果:

使用 state_ 中的状态 (当 ps_ 为 nullptr 时), 或使用 *ps_ 中的状态 (当 ps_ 不是 nullptr 时), 以原子方式计算并设置一个新状态: 如同通过 uuid_clock::now() 获取系统时间, 如同通过 uuid_clock::to_timestamp 将其转换为时间戳, 将结果存入 state.timestamp, 并且如果新时间戳小于或等于先前的时间戳, 则将 state.clock_seq 递增 (对 0x4000 取模).

使用来自 node_ 的节点标识符以及新的时间戳和时钟序列创建一个版本 1 UUID 并返回它.

构造函数

time_generator_v7();
效果:

初始化内部密码学强伪随机数生成器 (CSPRNG) rng_, 所用熵取自 std::random_device.

time_generator_v7( time_generator_v7 const& rhs );
效果:

将 rhs 的状态复制到 *this, 然后重新播种 this->rng_, 所用熵取自 std::random_device.

备注:

重新播种可确保两个生成器在复制之后不会产生相同的随机数序列.

time_generator_v7( time_generator_v7&& rhs ) noexcept;
效果:

将 rhs 的状态复制到 *this, 然后扰动 rhs.rng_ 的状态, 使其不再产生相同的随机数序列.

赋值

time_generator_v7& operator=( time_generator_v7 const& rhs ) noexcept;
效果:

将 rhs 的状态复制到 *this, 但 this->rng_ 除外, 它保持不修改.

返回:

*this.

备注:

不修改 this->rng_ 可确保两个生成器继续产生不同的随机数.

time_generator_v7& operator=( time_generator_v7&& rhs ) noexcept;
效果:

将 rhs 的状态复制到 *this, 然后扰动 rhs.rng_ 的状态, 使其不再产生相同的随机数序列.

返回:

*this.

operator()

result_type operator()() noexcept;
效果:

  1. 获取一个新时间戳, 如同通过 std::chrono::system_clock::now() 获取系统时间并将其转换为自 Unix 纪元起的微秒数.

  2. 创建一个新的版本 7 UUID, 并用时间戳中的毫秒数初始化其 unix_ts_ms 字段.

  3. 用时间戳中剩余的微秒数初始化 rand_a 字段.

  4. 将 rand_b 字段中变体之后的 6 个位初始化为一个冲突解决计数器, 这样, 如果使用相同的时间戳生成了不止一个 UUID, 仍能确保单调性.

  5. 将 rand_b 字段的其余部分初始化为取自内部 CSPRNG rng_ 的随机值.

  6. 返回该 UUID.

备注:

operator() 生成单调递增的 UUID 序列, 前提是满足以下要求:

  • 系统时钟从不回退.

  • 系统时钟具有至少毫秒级的分辨率.

  • 每微秒生成的 UUID 不超过 64 个 (每 16 纳秒不超过一个).
