Voronoi 构建器

Voronoi 构建器是事件生成器结构, 它实现扫描线算法, 扫描二维空间并产生两类事件: 站点事件与圆事件. 每个事件都会报告给输出数据结构构建器. 该结构之所以冠以 Voronoi 之名, 是因为它生成的事件提供了足够的信息, 可用于构造点与线段集合的 Voronoi 图. 通过坐标类型特征模板参数配置的输入/输出几何坐标类型需满足以下要求:
  • 输入坐标类型 (用于输入点及输入线段的端点) 不要求为整数 (integral), 不过它仍应是整数类型
  • 输出坐标类型 (用于 Voronoi 顶点) 要求为 IEEE-754 浮点类型

重要

鼓励用户使用 voronoi.hpp 头文件中定义的默认静态方法来构造 Voronoi 图. 不过也可以显式地使用 Voronoi 构建器, 尤其当用户希望去掉 MPL (元编程库) 之类的外部依赖时. 下面的 include 集合不依赖任何外部头文件 (STL 和 boost/cstdint.hpp 除外), 甚至不依赖 Boost.Polygon 库本身:

#include <voronoi_builder.hpp>
#include <voronoi_diagram.hpp>

声明

头文件: boost/polygon/voronoi_builder.hpp

template <typename T,
typename CTT = detail::voronoi_ctype_traits<T>,
typename VP = detail::voronoi_predicates<CTT> >
class voronoi_builder;

T - 指定输入几何 (点和线段) 的坐标类型.
CTT - 定义 Voronoi 谓词 (VP) 所使用的输入/输出坐标类型特征.
VP - 谓词内核, 包含稳健且高效的谓词与函子.
Voronoi 构建器数据结构在 32 位带符号整数输入坐标类型下开箱即用. 用户可以把输入坐标范围扩展到其他整数类型 (例如 64 位整数), 但这同时也需要手动设置坐标类型特征. 只要坐标类型特征定义的类型满足本页末尾所解释的要求, 默认谓词内核就能提供正确而高效的谓词. 如果这些要求不满足, 则需要相应的谓词内核实现.

成员函数

voronoi_builder() 默认构造函数.
size_t insert_point(const int_type& x,
                    const int_type& y) 		把具有指定坐标的点对象插入 Voronoi 构建器.
返回所插入点的索引.
size_t insert_segment(const int_type& x1,
                      const int_type& y1,
                      const int_type& x2,
                      const int_type& y2) 		把具有指定坐标的线段对象插入 Voronoi 构建器.
返回所插入线段的索引.
template <typename OUTPUT>
void construct(OUTPUT* output) 		对已插入几何的集合运行扫描线算法, 并向 OUTPUT 数据结构生成站点事件和圆事件. 由输出数据结构负责处理这些事件.
复杂度: O(N * log N), 其中 N 为输入点和线段的总数.
void clear() 清空已插入几何的列表. 把输入几何索引设置为零.

Voronoi 坐标类型特征

库为 32 位带符号整数类型提供了默认的坐标类型特征特化:

template <typename T>
struct voronoi_ctype_traits;

template <>
struct voronoi_ctype_traits<int32> {
    typedef int32 int_type;
    typedef int64 int_x2_type;
    typedef uint64 uint_x2_type;
    typedef extended_int<128> big_int_type;
    typedef fpt64 fpt_type;
    typedef extended_exponent_fpt<fpt_type> efpt_type;
    typedef ulp_comparison<fpt_type> ulp_cmp_type;
    typedef type_converter_fpt to_fpt_converter_type;
    typedef type_converter_efpt to_efpt_converter_type;
};

 本库最重要的特性之一是, Voronoi 构建器的输出几何是在定义的相对误差 (64 个机器 epsilon) 内构造的. 这意味着, 用户提供的 fpt_type 的尾数位越多, 输出几何的精度就越高. 为了使用户自定义的特征与默认的 Voronoi 构建器谓词内核保持一致, 用户应定义以下这组特征 (这里假设输入几何具有 X 位带符号整数坐标类型):

int_type 至少 X 位的带符号整数类型.
int_x2_type 至少 2X 位的带符号整数类型.
uint_x2_type 至少 2X 位的无符号整数类型.
big_int_type 若输入数据集仅包含点, 则至少为 8X 位带符号整数类型.
若输入数据集包含线段, 则至少为 64X 位带符号整数类型.
fpt_type IEEE-754 浮点类型, 尾数至少 (X+16) 位, 指数能处理 32X 位无符号整数类型.
efpt_type IEEE-754 浮点类型, 尾数至少 (X+16) 位, 指数能处理 64X 位无符号整数类型.
ulp_cmp_type ulp 比较结构, 检查两个 fpt_type 值是否在给定的 ulp 范围 (相对误差范围) 内.
to_fpt_converter_type 类型转换器结构, 使用 operator() 把上述任何整数类型以及 efpt_type 转换为 fpt_type.
to_efpt_converter_type 类型转换器结构, 使用 operator() 把上述任何整数类型转换为 efpt_type.

注释:

  • 使用四种不同的整数类型 (而不是单一的大整数类型) 以略微提高算法性能并减少内存使用.
  • 由于 big_int_type 所需的最大尺寸是预先已知的, 可以使用固定的、栈上分配的多精度整数类型.
  • 定义了两个独立的浮点类型, 因为对于具有 32 位带符号整数坐标的输入几何, double 类型无法处理 2048 位 (64 个 32 位块) 整数, 因为它们会使 double 的指数溢出. 在 gcc 编译器上, 两个浮点类型都可以使用 80 位 long double, 但 MSVC 编译器不支持这一点.
  • 构造点集合的 Voronoi 图时不使用 efpt_type 与 to_efpt_converter_type (使用模拟实现即可).
  • 用户自定义坐标类型特征的示例参见Voronoi 进阶教程.
