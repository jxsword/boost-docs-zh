Polygon 45 集合概念

polygon_45_set 概念的标签是 polygon_45_set_concept

polygon_45_set 的语义是: 零个或多个几何区域, 其顶点处的角是相对于坐标轴的 45 度倍数. Polygon 45 集合概念在浮点数下没有意义, 但目前并未提供静态断言来阻止它与浮点坐标一起使用, 这种用法的结果未定义. 当两条 45 度边相交产生偏离整数网格的顶点时, 处理方式是在偏离网格的交点附近、在这两条 45 度边之间插入一条单位长度的边. 在所表示的数据不含 45 度角且为 Manhattan 几何的情形下, 运行期检查会退回到 Manhattan 算法; 其结果与 45 度算法所得完全相同, 但效率更高.

提供 polygon_45_set 的动机是: 把库的 Manhattan 几何特例能力扩展到稍不那么常见但仍然重要的特例——即由相对于坐标轴为 45 度倍数的角所描述的几何. 这简化了几何算法的实现, 并带来许多优化机会. 45 度算法可以比任意角度算法快 50 倍, 并且需要提供完整的功能集, 以满足 Manhattan 与 45 度几何是常见特例的应用领域的性能要求.

建议用户使用用户自定义多边形的 std::vector 与 std::list, 或库提供的 polygon_45_set_data<coordinate_type> 对象. polygon_45_concept 或 polygon_45_with_holes_concept 模型的 list 和 vector 会自动成为 polygon_45_set_concept 的模型.

如果经运行期判定符合所有边都轴平行的约束, polygon_45_set_concept 模型的对象可以被视作 polygon_90_set_concept 的模型. 这种概念转换通过view_as<>() 函数完成.

view_as<polygon_90_set_concept>(polygon_set_object)

view_as<>() 的返回值可以传入任何期望其模板参数所指概念类型对象的接口. 多边形集合不能被视作单个多边形或矩形, 因为一般而言, 不把多边形集合转换为多边形就无法知道它是否只含单个多边形.

Operators

某些运算符的返回类型是polygon_45_set_view 运算符模板类型. 该类型本身就是 polygon 90 集合概念的一个模型, 此外还可用作polygon_45_set_data 构造函数与赋值运算符的实参. 运算符模板的存在是为了在布尔运算符链接在一起时消除中间结果的临时拷贝.

Polygon 45 集合数据对象

polygon 45 集合数据类型封装了作为实现多边形裁剪布尔运算的扫描线算法输入的内部数据格式. 它还在内部跟踪该数据是否已被排序或扫描, 并维护这样的不变式: 当其标志表明数据已排序或已扫描时, 数据未被改变以致违反该假设. 在上述函数中直接使用 Polygon 45 Set Data 类型可能比使用多边形的 list 和 vector 更高效, 因为它能强制执行一些不变式, 从而有机会让数据保持已排序形式, 而不必一路转换到多边形、再为后续操作重新排序那些顶点.

Polygon 45 Set Data 的声明如下:

template <typename T>
class polygon_45_set_data;

该类以坐标数据类型为参数. 受益于了解该类所强制不变式的算法以成员函数形式实现, 使其能够访问关于这些不变式的信息.
