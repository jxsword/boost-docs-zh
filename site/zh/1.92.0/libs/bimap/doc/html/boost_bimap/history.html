MultiIndex 与 Bimap

从 Code Project 到 Boost 的漫漫长路

2002 —— bimap 出现在 Code Project

Joaquin Lopez Muñoz 于 2002 年发布了他的第一个 bimap 库. 大量用户一直在使用它. 随后他在 2003 年 向邮件列表询问大家对这个库的兴趣. 幸运的是, 兴趣很大, Joaquin 开始将代码 boostify (改造为 Boost 风格) . 在某一个时点, 所有开发者似乎达成了共识: 与其做一个双向映射, 不如开发一个 N 索引集合, 把 Joaquin 的库作为其特例包含在内.

2003 —— multiindex_set

这个库急剧膨胀, 并于 2003 年准备好接受正式评审. 此时, 这个容器的功能已经强大得多, 但一切都有代价——这个新巨兽失去了最初 bimap 的简洁性.

2004 —— indexed_set

2004 年, 正式评审对新的多索引容器圆满结束. 这把瑞士军刀引入了若干新特性, 如非唯一索引、哈希索引和序列索引. 在该库的改进清单中, 有人提到应当在这个容器之上实现一个双向映射.

2005 —— multi_index_container

进入 Boost 后, 该库更名为如今广为人知的 “Boost.MultiIndex”. 2004 年末, 它正式成为 Boost 的一员. Joaquin 继续增强这个库, 加入了复合键和随机访问索引等新特性.

2006 —— Multi Index Specialized Containers SoC 项目

2006 年, 在 Boost.Property_tree 的正式评审期间, 对构建于 Boost.MultiIndex 之上的双向映射容器的需求再次浮现. 与此同时, Boost 作为导师组织加入了 Google SoC 2006. Joaquin 自荐担任导师. 他提议不仅构建一个双向映射, 而是构建大量的多索引专用容器. Matias Capeletto 提交了为 SoC 编写 Boost.Misc 的申请, 并与其他九名学生一同入选. Matias 和 Joaquin 的 SoC 项目以一个可运行的 bimap 库实现收尾, 该实现被提交到一次非正式评审. 到年底, 这个库已排入正式评审的队列.

2007 —— Boost.Bimap

正式评审于当年年初举行, Boost.Bimap 被接受进入 Boost.
