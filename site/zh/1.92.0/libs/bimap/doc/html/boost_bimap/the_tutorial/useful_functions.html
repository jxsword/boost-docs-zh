迭代器的投影

迭代器可以被投影到 bimap 的三个视图中的任何一个. bimap 提供三个成员函数来处理投影: project_left、project_right 和 project_up, 分别把迭代器投影到 左 map 视图、右 map 视图 和 关系集合视图. 这些函数接受来自 bimap 的任何迭代器, 并返回投影视图上指向同一元素的迭代器.

下面是一个使用投影的例子:

转到源代码 

typedef bimap<std::string,multiset_of<int,std::greater<int> > > bm_type;

bm_type bm;
bm.insert( bm_type::value_type("John" ,34) );
bm.insert( bm_type::value_type("Peter",24) );
bm.insert( bm_type::value_type("Mary" ,12) );

// Find the name of the next younger person after Peter

bm_type::left_const_iterator name_iter = bm.left.find("Peter");

bm_type::right_const_iterator years_iter = bm.project_right(name_iter);

++years_iter;

std::cout << "The next younger person after Peter is " << years_iter->second;

replace 和 modify

这些函数是 bimap 视图的成员, 在其标准对应物中不存在.

replace 家族的成员函数按如下例所示对给定元素执行就地替换:

转到源代码 

typedef bimap< int, std::string > bm_type;
bm_type bm;

bm.insert( bm_type::value_type(1,"one") );

// Replace (1,"one") with (1,"1") using the right map view
{
    bm_type::right_iterator it = bm.right.find("one");

    bool successful_replace = bm.right.replace_key( it, "1" );

    assert( successful_replace );
}

bm.insert( bm_type::value_type(2,"two") );

// Fail to replace (1,"1") with (1,"two") using the left map view
{
    assert( bm.size() == 2 );

    bm_type::left_iterator it = bm.left.find(1);

    bool successful_replace = bm.left.replace_data( it, "two" );

    assert( ! successful_replace );
    assert( bm.size() == 2 );
}

it 在这里仍然有效, 而 bimap 保持不变

replace 函数按如下方式执行这一替换:

  • 如果被修改的元素相对于所有视图保持其原来的顺序, 复杂度为常数时间; 否则为对数时间.
  • 迭代器与引用的有效性得到保持.
  • 该操作是强异常安全的, 即如果抛出了某个异常 (由系统或用户的数据类型引起) , bimap 保持不变.

replace 函数是标准 STL 容器未提供的强大操作, 在需要强异常安全性时尤其方便.

细心的读者可能已经注意到, replace 的便利是有代价的: 即为了完成更新, 整个元素必须被拷贝 两次 (一次在取回它时, 另一次在 replace 中) . 如果元素的拷贝代价很高, 对于只修改对象极小一部分的操作来说, 这可能是相当大的计算开销. 为了应对这种情况, Boost.Bimap 提供了另一种更新机制: modify 函数.

modify 函数接受一个 functor (或函数指针) , 它接受对要修改数据的引用, 从而免去了多余的拷贝. 与 replace 函数一样, modify 函数也确实保持 bimap 的所有索引的内部排序. 然而, modify 函数的语义并不完全等价于 replace 函数. 考虑一下如果修改元素导致冲突 (即被修改的元素相对于某个唯一视图与另一个元素冲突) 会发生什么. 对于 replace 函数, 原来的值被保留, 方法返回而容器未被更改; 但 modify 函数无法承受这种做法, 因为修改用的 functor 不会留下元素先前值的任何痕迹. 因此完整性约束导致了如下策略: 当调用 modify 函数的过程中发生冲突时, 该元素被擦除, 方法返回 false. replace 与 modify 函数之间的这种行为差异必须由程序员逐例考虑.

Boost.Bimap 定义了名为 _key 和 _data 的新占位符, 以提供更稳健的解决方案. 必须包含 <boost/bimap/support/lambda.hpp> 才能使用它们.

转到源代码 

typedef bimap< int, std::string > bm_type;
bm_type bm;
bm.insert( bm_type::value_type(1,"one") );

// Modify (1,"one") to (1,"1") using the right map view
{
    bm_type::right_iterator it = bm.right.find("one");

    bool successful_modify = bm.right.modify_key( it , _key = "1" );

    assert( successful_modify );
}

bm.insert( bm_type::value_type(2,"two") );

// Fail to modify (1,"1") to (1,"two") using the left map view
{
    assert( bm.size() == 2 );

    bm_type::left_iterator it = bm.left.find(1);

    bool successful_modify = bm.left.modify_data( it, _data = "two" );

    assert( ! successful_modify );
    assert( bm.size() == 1 );
}

it 不再有效, 而 (1,"1") 已从 bimap 中移除

范围的获取

标准的 lower_bound 和 upper_bound 函数可用于查找给定范围内的所有元素.

假设我们想从一个 bimap<int,std::string> 中取回左值位于范围 [20,50] 内的所有元素

typedef bimap<int,std::string> bm_type;
bm_type bm;

// ...

bm_type::left_iterator iter_first  = bm.left.lower_bound(20);
bm_type::left_iterator iter_second = bm.left.upper_bound(50);

// range [iter_first,iter_second) contains the elements in [20,50]

当考虑严格不等式时, 需要对代码做细微的修改. 要取回大于 20 且小于 50 的元素, 代码必须重写为

bm_type::left_iterator iter_first  = bm.left.upper_bound(20);
bm_type::left_iterator iter_second = bm.left.lower_bound(50);

// range [iter_first,iter_second) contains the elements in (20,50)

更让人头疼的是, 细心的程序员还必须考虑到所搜索区间的下界和上界要相互兼容: 例如, 如果下界是 50 而上界是 20, 上面代码产生的迭代器 iter_first 和 iter_second 将是逆序的; 如果尝试从 iter_first 遍历到 iter_second, 可能产生灾难性的后果. 所有这些细节使范围搜索成为一项乏味且容易出错的任务.

range 成员函数——通常与 lambda 表达式结合使用——可以极大地帮助缓解这种情况:

typedef bimap<int,std::string> bm_type;
bm_type bm;

// ...

bm_type::left_range_type r;

r = bm.left.range( 20 <= _key, _key <= 50 ); // [20,50]

r = bm.left.range( 20 <  _key, _key <  50 ); // (20,50)

r = bm.left.range( 20 <= _key, _key <  50 ); // [20,50)

range_type 是一个方便的 typedef, 等价于 std::pair<iterator,iterator>. 同时也提供了 const_range_type, 它等价于 std::pair<const_iterator,const_iterator>

_key 是一个 Boost.Lambda 占位符. 要使用它, 你必须包含 <boost/bimap/support/lambda.hpp>

range 只是简单地接受指定所搜索区间下界和上界的谓词. 请查阅参考, 以获得关于可传递给 range 的谓词的详细说明.

可以使用特殊的 unbounded 标记省略一个或两个边界:

r = bm.left.range( 20 <= _key, unbounded ); // [20,inf)

r = bm.left.range( unbounded , _key < 50 ); // (-inf,50)

r = bm.left.range( unbounded , unbounded ); // (-inf,inf)

这等价于 std::make_pair(s.begin(),s.end())
