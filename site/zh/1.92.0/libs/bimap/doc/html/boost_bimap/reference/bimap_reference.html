视图概念

bimap 实例化由两个侧视图以及一个编译期指定的关系的视图组成. 每个视图都以确定的方式允许对所含元素进行读写访问, 并与某个 STL 容器的签名相匹配.

视图不是孤立的对象, 因此不能单独构造; 它们是 bimap 的一个组成部分. 视图类实现本身的名字从不直接暴露给用户, 用户只能访问与之关联的视图类型规范符.

元素的插入和删除始终通过 bimap 的三个视图中任何一个的相应接口来执行; 不过这些操作也会影响所有其他视图: 例如, 通过某个给定视图进行的插入可能失败, 因为存在另一个视图为了保持其不变式 (例如元素的唯一性) 而禁止该操作. 在任一视图中联合执行的全局操作可以归约为六种原语:

  • 拷贝
  • 插入一个元素
  • 提示插入, 即建议一个已存在的元素以提高操作的效率
  • 删除一个元素
  • 替换元素的值, 这可能触发该元素在一个或多个视图中的重新排列, 也可能禁止替换
  • 修改元素, 以及随后由各个视图进行的重新排列/禁止

最后两种原语值得进一步解释: 为了保证与每个视图相关联的不变式 (例如某种确定的排序) , 一个 bimap 的元素是不可变的. 为了克服这一限制, 各视图暴露了用于更新和修改的成员函数, 允许以受控的方式改变元素.

复杂度签名

视图接口的某些成员函数由上面清单中的全局原语实现. 因此, 这些操作的复杂度取决于给定 bimap 的所有视图, 而不仅仅是当前使用的视图.

为了建立复杂度估计, 一个视图由其复杂度签名来刻画, 签名由以下关于元素个数的关联函数组成:

  • c(n): 拷贝
  • i(n): 插入
  • h(n): 提示插入
  • d(n): 删除
  • r(n): 替换
  • m(n): 修改

如果关系的集合类型是 left_based 或 right_based, 并且我们用 l 下标表示左视图、用 r 表示右视图, 那么向这样的容器中插入一个元素的复杂度为 O(i_l(n)+i_r(n)), 其中 n 是元素个数. 如果关系的集合类型不是基于侧的, 那么还要加上由关系的集合类型视图所贡献的一项. 用 a 表示上述视图, 插入的复杂度将为 O(i_l(n)+i_r(n)+i_a(n)). 为了缩写记法, 我们采用如下定义:

  • C(n) = c_l(n) + c_r(n) [ + c_a(n) ]
  • I(n) = i_l(n) + i_r(n) [ + i_a(n) ]
  • H(n) = h_l(n) + h_r(n) [ + h_a(n) ]
  • D(n) = d_l(n) + d_r(n) [ + d_a(n) ]
  • R(n) = r_l(n) + r_r(n) [ + r_a(n) ]
  • M(n) = m_l(n) + m_r(n) [ + m_a(n) ]

集合类型规范

集合类型规范符作为实例化参数传递给 bimap, 并提供合并相应视图所需的信息. 目前, Boost.Bimap 提供以下集合类型规范符. 侧集合类型 规范符定义 bimap 的两个 map 视图的约束. 关系的集合类型 规范符定义主集合视图的约束. 如果使用 left_based (默认参数) 或 right_based, 那么关系的集合类型将相应地基于左侧或右侧集合类型.

标签

标签只是用来助记 bimap 中所存类型的常规名称. Boost.Bimap 使用 tagged 习语让用户指定这些标签.

头文件 "boost/bimap/bimap.hpp" 概要 

namespace boost {
namespace bimaps {

template< class Type, typename Tag >
struct tagged;

// bimap template class

template
<
    class LeftCollectionType, class RightCollectionType,

    class AdditionalParameter_1 = detail::not_specified,
    class AdditionalParameter_2 = detail::not_specified
>
class bimap - implementation defined { : public SetView } -
{
    public:

    // Metadata

    typedef -unspecified- left_tag;
    typedef -unspecified- left_map;

    typedef -unspecified- right_tag;
    typedef -unspecified- right_map;

    // Shortcuts
    // typedef -side-_map::-type- -side-_-type-;

    typedef -unspecified- info_type;

    // Map views

     left_map  left;
    right_map right;

    // Constructors

    bimap();

    template< class InputIterator >
    bimap(InputIterator first,InputIterator last);

    bimap(const bimap &);

    bimap& operator=(const bimap& b);

    // Projection of iterators

    template< class IteratorType >
    left_iterator project_left(IteratorType iter);

    template< class IteratorType >
    left_const_iterator project_left(IteratorType iter) const;

    template< class IteratorType >
    right_iterator project_right(IteratorType iter);

    template< class IteratorType >
    right_const_iterator project_right(IteratorType iter) const;

    template< class IteratorType >
    iterator project_up(IteratorType iter);

    template< class IteratorType >
    const_iterator project_up(IteratorType iter) const;

    // Support for tags

    template< class Tag >
    struct map_by;

    template< class Tag >
    map_by<Tag>::type by();

    template< class Tag >
    const map_by<Tag>::type & by() const;

    template< class Tag, class IteratorType >
    map_by<Tag>::iterator project(IteratorType iter);

    template< class Tag, class IteratorType >
    map_by<Tag>::const_iterator project(IteratorType iter) const

};


} // namespace bimap
} // namespace boost

复杂度

在 bimap 操作的描述中, 我们采用复杂度签名一节中概述的方案.

实例化类型

bimap 用以下类型实例化:

  1. LeftCollectionType 和 RightCollectionType 是可选带标签的集合类型规范, 或任何可选带标签的类型——在后一种情况下, 该侧充当集合.
  2. AdditionalParameter_{1/2} 可以是以下各项的任意有序子集:
    • CollectionTypeOfRelation 规范
    • Allocator
嵌套类型 
left_tag, right_tag

bimap 每一侧的标签. 如果用户没有指定任何标签, 标签默认为 member_at::left 和 member_at::right 

left_key_type, right_key_type

每一侧的键类型. 在 bimap<A,B> 中, left_key_type 是 A, 而 right_key_type 是 B. 如果有标签, 最好使用: Bimap::map_by<Tag>::key_type 

left_data_type, right_data_type

每一侧的数据类型. 在 bimap<A,B> 中 left_key_type 是 B, right_key_type 是 A. 如果有标签, 最好使用: Bimap::map_by<Tag>::data_type 

left_value_type, right_value_type

用于视图的值类型. 如果有标签, 最好使用: Bimap::map_by<Tag>::value_type 

left_iterator, right_iterator
left_const_iterator, right_const_iterator

视图使用的迭代器. 如果有标签, 最好使用: Bimap::map_by<Tag>::iterator 和 Bimap::map_by<Tag>::const_iterator 

left_map, right_map

每一侧的 map 视图类型. 如果有标签, 最好使用: Bimap::map_by<Tag>::type

构造函数、拷贝与赋值 
bimap();
  • 效果: 构造一个空的 bimap.
  • 复杂度: 常数.
template<typename InputIterator>
bimap(InputIterator first,InputIterator last);
  • 要求: InputIterator 是元素类型为 relation 或可转换为 relation 的 Input Iterator 的一个模型. last 从 first 可达.
  • 效果: 构造一个空的 bimap, 并用范围 [first,last) 中的元素填充它. 每个元素的插入可能成功也可能不成功, 取决于 bimap 的集合类型是否接受.
  • 复杂度: O(m*H(m)), 其中 m 是 [first,last) 中的元素个数.
bimap(const bimap & x);
  • 效果: 构造 x 的副本, 同时复制其元素和内部对象 (键提取器、比较对象、分配器) .
  • 后置条件: *this == x. bimap 的视图顺序也被保留.
  • 复杂度: O(x.size()*log(x.size()) + C(x.size()))
~bimap()
  • 效果: 销毁 bimap 及其包含的所有元素. 元素被销毁的顺序未指定.
  • 复杂度: O(n).
bimap& operator=(const bimap& x);
  • 效果: 用来自 x 的副本替换 bimap 的元素和内部对象.
  • 后置条件: *this==x. bimap 的视图上的顺序也被保留.
  • 返回: *this.
  • 复杂度: O(n + x.size()*log(x.size()) + C(x.size())).
  • 异常安全性: 强——只要 ctor_args_list 的类型的拷贝和赋值操作不抛出异常.
投影操作

给定一个带有视图 v1 和 v2 的 bimap, 如果满足以下条件, 我们说一个 v1 迭代器 it1 和一个 v2 迭代器 it2 是等价的:

  • it1 == i1.end() AND it2 == i2.end(),
  • 或者 it1 与 it2 指向同一个元素.
template< class IteratorType >
left_iterator project_left(IteratorType iter);

template< class IteratorType >
left_const_iterator project_left(IteratorType iter) const;
  • 要求: IteratorType 是一个 bimap 视图迭代器. it 是 *this 的某个视图的有效迭代器 (即不指向某个其他 bimap. )
  • 效果: 返回与 it 等价的左 map 视图迭代器.
  • 复杂度: 常数.
  • 异常安全性: 不抛出异常.
template< class IteratorType >
right_iterator project_right(IteratorType iter);

template< class IteratorType >
right_const_iterator project_right(IteratorType iter) const;
  • 要求: IteratorType 是一个 bimap 视图迭代器. it 是 *this 的某个视图的有效迭代器 (即不指向某个其他 bimap. )
  • 效果: 返回与 it 等价的右 map 视图迭代器.
  • 复杂度: 常数.
  • 异常安全性: 不抛出异常.
template< class IteratorType >
iterator project_up(IteratorType iter);

template< class IteratorType >
const_iterator project_up(IteratorType iter) const;
  • 要求: IteratorType 是一个 bimap 视图迭代器. it 是 *this 的某个视图的有效迭代器 (即不指向某个其他 bimap. )
  • 效果: 返回与 it 等价的关系集合视图迭代器.
  • 复杂度: 常数.
  • 异常安全性: 不抛出异常.
对用户自定义名称的支持 
template< class Tag >
struct map_by;
  • map_by<Tag>::type 产生以 Tag 标记的 map 视图类型. map_by<Tag>::-type name- 等价于 map_by<Tag>::type::-type name-.
  • 要求: Tag 是该 bimap 的一个有效用户定义名称.
template< class Tag >
map_by<Tag>::type by();

template< class Tag >
const map_by<Tag>::type & by() const;
  • 要求: Tag 是该 bimap 的一个有效用户定义名称.
  • 效果: 返回以 Tag 标记、由 *this 所持有的 map 视图的引用.
  • 复杂度: 常数.
  • 异常安全性: 不抛出异常.
template< class Tag, class IteratorType >
map_by<Tag>::iterator project(IteratorType iter);

template< class Tag, class IteratorType >
map_by<Tag>::const_iterator project(IteratorType iter) const
  • 要求: Tag 是该 bimap 的一个有效用户定义名称. IteratorType 是一个 bimap 视图迭代器. it 是 *this 的某个视图的有效迭代器 (即不指向某个其他 bimap. )
  • 效果: 返回以 Tag 标记、由 *this 所持有的 map 视图的引用.
  • 复杂度: 常数.
  • 异常安全性: 不抛出异常.
序列化

一个 bimap 可以用 Boost.Serialization 进行存档和取回. Boost.Bimap 不暴露公共序列化接口, 因为这是由 Boost.Serialization 自身提供的. 常规档案和 XML 档案都受支持.

组成给定 bimap 的每个集合规范都贡献其自己的前置条件以及对取回容器的保证. 在描述这些时, 使用以下概念. 类型 T 是 可序列化 (相应地, XML 可序列化) 的, 如果该类型的任何对象 T 都能保存到输出档案 (XML 档案) 中, 之后从与同一存储关联的输入档案 (XML 档案) 中取回. 如果 x’ (类型为 T) 是从另一个对象 x 所保存的序列化信息加载而来的, 我们就说 x’ 是 x 的一个 恢复副本. 给定一个 二元谓词 (Binary Predicate) Pred (作用于 (T, T) 的) , 以及对象 p 和 q (类型为 Pred) 时, 我们说 q 是 序列化兼容 于 p, 如果

  • p(x,y) == q(x',y')

对于每个 x 和 y (类型为 T) , 以及 x’ 和 y’ 分别是 x 和 y 的恢复副本,

操作: 将一个 bimap b 保存到输出档案 (XML 档案) ar.

  • 要求: Value 是可序列化的 (XML 可序列化) . 此外, b 的每个视图都可以施加其他要求.
  • 异常安全性: 相对于 b 是强保证. 如果抛出异常, ar 可能处于不一致状态.

操作: 加载一个 bimap m’——从输入档案 (XML 档案) ar.

  • 要求: Value 是可序列化的 (XML 可序列化) . 此外, b’ 的每个视图都可以施加其他要求.
  • 异常安全性: 基本保证. 如果抛出异常, ar 可能处于不一致状态.
