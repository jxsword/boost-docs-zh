一个新的视角

能够更改 bimap 关系视图的集合类型是另一个非常重要的特性. 记住, 这个视图允许用户把容器看作所存储关系的集合. 这个视图具有 set 语义而非 map 语义.

默认情况下, Boost.Bimap 将把关系的集合类型建立在左侧集合的类型之上. 如果左侧集合类型是 set, 那么关系的集合类型将是与左视图顺序相同的 set.

一般来说, Boost.Bimap 用户会把关系的集合类型建立在两侧之一集合的类型之上. 但有时为这个集合指定其他约束, 或者只是以不同的方式排序, 也是有用的. 用户可以在以下选项之间选择:

  • left_based
  • right_based
  • set_of_relation<>
  • multiset_of_relation<>
  • unordered_set_of_relation<>
  • unordered_multiset_of_relation<>
  • list_of_relation
  • vector_of_relation
  • unconstrained_set_of_relation
提示

前两个选项和最后一个会产生更快的 bimap, 因此尽可能优先选择它们.

关系的集合类型可用于创建强大的容器. 例如, 如果你需要最大化查找速度, 那么最好的双向映射是把一个 unordered_set 中的元素与另一个 unordered_set 中的元素关联起来的容器. 问题是这个容器不能被迭代. 如果你需要知道容器内部的关系列表, 就需要另一种关系的集合类型. 在这种情况下, list_of_relation 是一个不错的选择. 得到的容器以插入和删除时间为代价, 换取快速查找能力和双向迭代的可能性.

转到源代码 

#include <iostream>
#include <string>
#include <boost/bimap/bimap.hpp>
#include <boost/bimap/list_of.hpp>
#include <boost/bimap/unordered_set_of.hpp>

struct english {};
struct spanish {};

int main()
{
    using namespace boost::bimaps;

    typedef bimap
    <
        unordered_set_of< tagged< std::string, spanish > >,
        unordered_set_of< tagged< std::string, english > >,
        list_of_relation

    > translator;

    translator trans;

    // We have to use `push_back` because the collection of relations is
    // a `list_of_relation`

    trans.push_back( translator::value_type("hola"  ,"hello"   ) );
    trans.push_back( translator::value_type("adios" ,"goodbye" ) );
    trans.push_back( translator::value_type("rosa"  ,"rose"    ) );
    trans.push_back( translator::value_type("mesa"  ,"table"   ) );

    std::cout << "enter a word" << std::endl;
    std::string word;
    std::getline(std::cin,word);

    // Search the queried word on the from index (Spanish)

    translator::map_by<spanish>::const_iterator is
        = trans.by<spanish>().find(word);

    if( is != trans.by<spanish>().end() )
    {
        std::cout << word << " is said "
                  << is->get<english>()
                  << " in English" << std::endl;
    }
    else
    {
        // Word not found in Spanish, try our luck in English

        translator::map_by<english>::const_iterator ie
            = trans.by<english>().find(word);

        if( ie != trans.by<english>().end() )
        {
            std::cout << word << " is said "
                      << ie->get<spanish>()
                      << " in Spanish" << std::endl;
        }
        else
        {
            // Word not found, show the possible translations

            std::cout << "No such word in the dictionary"      << std::endl;
            std::cout << "These are the possible translations" << std::endl;

            for( translator::const_iterator
                    i = trans.begin(),
                    i_end = trans.end();

                    i != i_end ; ++i )
            {
                std::cout << i->get<spanish>()
                          << " <---> "
                          << i->get<english>()
                          << std::endl;
            }
        }
    }
    return 0;
}

配置参数

每种关系的集合类型都有不同的参数来控制其行为. 例如, 在 set_of_relation 规范中, 你可以传入一个比较两种类型的 Functor 类型. 所有参数与标准库容器的完全相同, 只是类型 (被设置为 bimap 关系) 和分配器类型除外. 为了帮助用户创建每个 functor, 关系的集合类型模板接受一个 mpl lambda 表达式, 关系类型将在稍后对其求值. bimap 用户可以使用一个名为 _relation 的占位符.

下表列出了每种关系的集合类型各参数的含义.

name

附加参数

left_based

不是模板.

right_based

不是模板.

set_of_relation<KeyComp>

multiset_of_relation<KeyComp>

KeyComp 是一个用小于比较两种类型的 Functor. 默认情况下, 小于运算符为 std::less<_relation>.

unordered_set_of_relation<HashFunctor,EqualKey>

unordered_multiset_of_relation<HashFunctor,EqualKey>

HashFunctor 把 relation 转换为一个 std::size_t 值. 默认为 boost::hash<_relation>.

EqualKey 是一个测试两个关系是否相等的 Functor. 默认情况下, 相等运算符为 std::equal_to<_relation>.

list_of_relation

不是模板.

vector_of_relation

不是模板.

unconstrained_set_of_relation

不是模板.

示例

考虑这个例子:

template< class Rel >
struct RelOrder
{
    bool operator()(Rel ra, Rel rb) const
    {
        return (ra.left+ra.right) < (rb.left+rb.right);
    }
};

typedef bimap
<
        multiset_of< int >,
        multiset_of< int >,
        set_of_relation< RelOrder<_relation> >

> bimap_type;

这里, bimap 的关系视图使用两侧的信息进行排序. 因为使用了 set_of_relation, 这个容器只允许唯一的关系, 但 bimap 每一侧的元素可以重复.

struct name         {};
struct phone_number {};

typedef bimap
<
    tagged< unordered_multiset_of< string >, name         >,
    tagged< unordered_set_of     < int    >, phone_number >,
    set_of_relation<>

> bimap_type;

在另一种情况下, bimap 将把姓名关联到电话号码. 姓名可以重复, 电话号码唯一. 你可以按姓名或电话号码进行快速搜索, 并且可以使用关系视图以有序方式查看该容器.
