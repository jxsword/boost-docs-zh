Boost.Serialization

bimap 可以通过 Boost.Serialization 库进行存档和取回. 常规档案和 XML 档案都受支持. 用法非常直观, 与其他任何可序列化类型没有区别. 例如:

转到源代码 

typedef bimap< std::string, int > bm_type;

// Create a bimap and serialize it to a file
{
    bm_type bm;
    bm.insert( bm_type::value_type("one",1) );
    bm.insert( bm_type::value_type("two",2) );

    std::ofstream ofs("data");
    boost::archive::text_oarchive oa(ofs);

    oa << const_cast<const bm_type&>(bm); 

    const bm_type::left_iterator left_iter = bm.left.find("two");
    oa << left_iter;

    const bm_type::right_iterator right_iter = bm.right.find(1);
    oa << right_iter;
}

// Load the bimap back
{
    bm_type bm;

    std::ifstream ifs("data", std::ios::binary);
    boost::archive::text_iarchive ia(ifs);

    ia >> bm;

    assert( bm.size() == 2 );

    bm_type::left_iterator left_iter;
    ia >> left_iter;

    assert( left_iter->first == "two" );

    bm_type::right_iterator right_iter;
    ia >> right_iter;

    assert( right_iter->first == 1 );
}

我们必须进行 const 转换, 因为 Boost.Serialization 的档案只保存 const 对象. 这一决定背后的设计理由请阅读 Boost.Serialization 文档

只有先序列化 bimap 之后才能序列化其迭代器. 注意这里不需要 const 转换, 因为我们把迭代器创建为 const.

只需链接相应的 Boost.Serialization 库模块即可自动获得序列化支持: 除了声明本过程中所用档案类型的头文件之外, 无需显式包含任何来自 Boost.Serialization 的头文件. 然而, 如果不使用序列化, 可以通过全局定义宏 BOOST_BIMAP_DISABLE_SERIALIZATION 来禁用序列化支持. 对 Boost.MultiIndex 禁用序列化可以略微缩短构建时间, 并且在那些无法正确处理 Boost.Serialization 头文件的有缺陷的编译器上可能是必需的.

警告

Boost.Bimap 与 Boost.MultiIndex 共享大量序列化代码. 宏 BOOST_BIMAP_DISABLE_SERIALIZATION 会在 两个 库中都禁用序列化. 定义 BOOST_MULTI_INDEX_DISABLE_SERIALIZATION 时也是如此.

取回已存档的 bimap 不仅会恢复元素, 还会恢复它们在容器各个视图中的排列顺序. 不过这条规则有一个例外: 对于无序集合, 恢复后的容器中元素的迭代顺序没有任何保证; 一般而言, 依赖哈希视图中元素的顺序是不明智的, 因为在插入或 rehash 期间该顺序可能以任意方式改变——这正是哈希索引和 TR1 无序关联容器不定义相等运算符的原因.

bimap 的迭代器也可以被序列化. 迭代器的序列化必须在其对应容器序列化之后进行.

Boost.Assign

这个库的目的是通过重载 operator,() 和 operator()() 来简化向容器填充数据的过程. 这两个运算符可以构造值列表, 然后复制到容器中.

这些列表在学习、测试和原型设计场景中特别有用, 但在其他情况下也很方便. 本库为标准库的容器提供了预定义运算符, 但大多数功能可用于任何符合标准的容器. 本库还可以扩展用户自定义类型, 例如可以针对值列表调用成员函数, 而不是其常规实参.

Boost.Assign 可以与 bimap 容器一起使用. bimap 的各个视图与其标准对应物是签名兼容的, 因此我们可以对它们使用其他 Boost.Assign 工具.

转到源代码 

 typedef bimap< multiset_of< int >, list_of< std::string > > bm_type;

 // We can use assign::list_of to initialize the container.

 bm_type bm = assign::list_of< bm_type::relation > 
     ( 1, "one"   )
     ( 2, "two"   )
     ( 3, "three" );

 // The left map view is a multiset, again we use insert

 assign::insert( bm.left )
     ( 4, "four" )
     ( 5, "five" )
     ( 6, "six"  );

 // The right map view is a list so we use push_back here
 // Note the order of the elements in the list!

 assign::push_back( bm.right )
     ( "seven" , 7 )
     ( "eight" , 8 );

 assign::push_front( bm.right )
     ( "nine"  ,  9 )
     ( "ten"   , 10 )
     ( "eleven", 11 );

// Since it is left_based the main view is a multiset, so we use insert

 assign::insert( bm )
     ( 12, "twelve"   )
     ( 13, "thirteen" );

注意, 必须使用 bm_type::relation 而不是 bm_type::value_type. 与 value_type 不同, relation 类型以非 const 方式存储元素, 这是 assign::list_of 的要求

Boost.Hash

哈希函数是无序集合快速查找能力的核心: 哈希器 (hasher) 只是一个一元函数 (Unary Function) , 针对任何给定的键返回一个 std::size_t 值. 一般来说, 让每个键都映射到不同的哈希值是不可能的, 因为键空间可能大于允许的哈希码数量: 衡量一个好的哈希器的标准是碰撞 (两个不同的键具有相同的哈希值) 的概率尽可能接近于零.

这是一个统计性质, 取决于给定应用中键的典型分布, 因此不可能有一个在每种可能场景下都表现优异的通用哈希函数; 该参数的默认值使用 Boost.Hash, 它通常能提供足够好的结果.

Boost.Hash 可以针对自定义数据类型进行扩展, 使无序集合类型的默认参数可用于任何用户类型.

Boost.Lambda

Boost Lambda 库 (下文简称 BLL) 是一个 C++ 模板库, 为 C++ 实现了 lambda 抽象的一种形式. 该术语源自函数式编程和 lambda 演算, 其中 lambda 抽象定义了一个匿名函数. Lambda 表达式对于构造 bimap 视图中一些函数所需的函数对象非常有用.

Boost.Bimap 在 <boost/bimap/support/lambda.hpp> 中定义了新的占位符, 以提供更稳健的解决方案. 这些占位符名为 _key 和 _data, 两者都等价于 boost::lambda::_1. 引入这些占位符有两个原因: 使用它们代码更美观, 并且避免了 lambda::_1 与 Boost.Bind 中 boost::_1 之间的冲突问题.

转到源代码 

typedef bimap< std::string, int > bm_type;

bm_type bm;
bm.insert( bm_type::value_type("one",1) );
bm.insert( bm_type::value_type("two",2) );

bm.right.range( 5 < _key, _key < 10 );

bm.left.modify_key( bm.left.find("one"), _key = "1" );

bm.left.modify_data( bm.left.begin(), _data *= 10 );

Boost.Range

Boost.Range 是一组概念和实用工具, 对于指定和实现泛型算法特别有用. 泛型算法迄今为止都是以两个或多个迭代器来指定的. 两个迭代器共同构成算法可以处理的值范围. 这带来了非常通用的接口, 但也导致算法使用起来有些笨拙, 容器名被冗余地重复指定. 因此我们希望提高算法的抽象层次, 使其尽可能以范围 (Range) 来指定接口.

由于 Boost.Bimap 的视图与其标准容器对应物签名兼容, 它们与范围概念兼容. 作为附加特性, 有序 bimap 视图提供了一个名为 range 的函数, 可用于获取一个值的范围.

如果我们有一些接受范围的泛型函数:

template< class ForwardReadableRange, class UnaryFunctor >
UnaryFunctor for_each(const ForwardReadableRange & r, UnaryFunctor func)
{
    typedef typename
    boost::range_const_iterator<ForwardReadableRange>::type const_iterator;

    for(const_iterator i= boost::begin(r), iend= boost::end(r); i!=iend; ++i )
    {
        func(*i);
    }

    return func;
}

template< class ForwardReadableRange, class Predicate >
typename boost::range_difference<ForwardReadableRange>::type
    count_if(const ForwardReadableRange & r, Predicate pred)
{
    typedef typename
    boost::range_const_iterator<ForwardReadableRange>::type const_iterator;

    typename boost::range_difference<ForwardReadableRange>::type c = 0;

    for( const_iterator i = boost::begin(r), iend = boost::end(r); i != iend; ++i )
    {
        if( pred(*i) ) ++c;
    }

    return c;
}

借助 range 函数, 我们可以把它们用于 Boost.Bimap.

struct pair_printer
{
    pair_printer(std::ostream & o) : os(o) {}
    template< class Pair >
    void operator()(const Pair & p)
    {
        os << "(" << p.first << "," << p.second << ")";
    }
    private:
    std::ostream & os;
};

struct second_extractor
{
    template< class Pair >
    const typename Pair::second_type & operator()(const Pair & p)
    {
        return p.second;
    }
};

int main()
{
    typedef bimap< double, multiset_of<int> > bm_type;

    bm_type bm;
    bm.insert( bm_type::value_type(2.5 , 1) );
    bm.insert( bm_type::value_type(3.1 , 2) );
    //...
    bm.insert( bm_type::value_type(6.4 , 4) );
    bm.insert( bm_type::value_type(1.7 , 2) );

    // Print all the elements of the left map view

    for_each( bm.left, pair_printer(std::cout) );

    // Print a range of elements of the right map view

    for_each( bm.right.range( 2 <= _key, _key < 6 ), pair_printer(std::cout) );

    // Count the number of elements where the data is equal to 2 from a
    // range of elements of the left map view

    count_if( bm.left.range( 2.3 < _key, _key < 5.4 ),
              bind<int>( second_extractor(), _1 ) == 2 );

    return 0;
}

Boost.Foreach

在 C++ 中, 编写遍历序列的循环十分繁琐. 我们要么使用迭代器——这需要相当多的样板代码; 要么使用 std::for_each() 算法并把循环体移入一个谓词——这同样需要不少样板代码, 还迫使我们的逻辑远离使用它的地方. 相比之下, 其他一些语言 (如 Perl) 提供了专门的 “foreach” 构造来自动化这一过程. BOOST_FOREACH 就是 C++ 中这样的构造. 它替我们遍历序列, 使我们免于直接处理迭代器或编写谓词.

你可以将 BOOST_FOREACH 宏用于 Boost.Bimap 视图. 生成的代码将与 std::for_each 迭代一样高效. 下面是一些例子:

typedef bimap< std::string, list_of<int> > bm_type;

bm_type bm;
bm.insert( bm_type::value_type("1", 1) );
bm.insert( bm_type::value_type("2", 2) );
bm.insert( bm_type::value_type("3", 4) );
bm.insert( bm_type::value_type("4", 2) );

BOOST_FOREACH( bm_type::left_reference p, bm.left )
{
    ++p.second; 
}

BOOST_FOREACH( bm_type::right_const_reference p, bm.right )
{
    std::cout << p.first << "-->" << p.second << std::endl;
}

我们可以修改右侧元素, 因为我们在右侧使用了可变集合类型.

也可以直接将它用于范围:

BOOST_FOREACH( bm_type::left_reference p,
             ( bm.left.range( std::string("1") <= _key, _key < std::string("3") ) ))
{
    ++p.second;
}

BOOST_FOREACH( bm_type::left_const_reference p,
             ( bm.left.range( std::string("1") <= _key, _key < std::string("3") ) ))
{
    std::cout << p.first << "-->" << p.second << std::endl;
}

Boost.Typeof

等到 C++0x 发布后, 我们将能够写出这样的代码:

auto iter = bm.by<name>().find("john");

而不是更冗长的

bm_type::map_by<name>::iterator iter = bm.by<name>().find("john");

Boost.Typeof 定义了宏 BOOST_AUTO, 在我们等待下一个标准期间, 它可以作为 auto 关键字的库解决方案.

如果我们有

typedef bimap< tagged<std::string,name>, tagged<int,number> > bm_type;
bm_type bm;
bm.insert( bm_type::value_type("one"  ,1) );
bm.insert( bm_type::value_type("two"  ,2) );

以下代码片段

for( bm_type::map_by<name>::iterator iter = bm.by<name>().begin();
     iter!=bm.by<name>().end(); ++iter)
{
    std::cout << iter->first << " --> " << iter->second << std::endl;
}

bm_type::map_by<number>::iterator iter = bm.by<number>().find(2);
std::cout << "2: " << iter->get<name>();

可以改写为

for( BOOST_AUTO(iter, bm.by<name>().begin()); iter!=bm.by<name>().end(); ++iter)
{
    std::cout << iter->first << " --> " << iter->second << std::endl;
}

BOOST_AUTO( iter, bm.by<number>().find(2) );
std::cout << "2: " << iter->get<name>();

Boost.Xpressive

使用 Boost.Xpressive, 我们可以在同一步骤中解析文件并将关系插入 bimap. 四行代码竟有如此威力, 实在令人惊叹. 下面是一个例子 (美极了)

typedef bimap< std::string, int > bm_type;
bm_type bm;

std::string rel_str("one <--> 1     two <--> 2      three <--> 3");

sregex rel = ( (s1= +_w) >> " <--> " >> (s2= +_d) )
[
    xp::ref(bm)->*insert( xp::construct<bm_type::value_type>(s1, as<int>(s2)) )
];

sregex relations = rel >> *(+_s >> rel);

regex_match(rel_str, relations);

assert( bm.size() == 3 );

Boost.Property_map

Boost Property Map 库主要由以概念形式给出的接口规范组成 (类似于 STL 中的迭代器概念) . 这些接口规范供泛型库的实现者使用, 用于向用户传达对模板参数的要求. 特别是, Boost Property Map 概念定义了将键对象映射到相应值对象的通用接口, 从而对算法隐藏了映射实现方式的细节.

对属性映射接口的需求来自 Boost Graph Library (BGL) , 其中包含许多使用属性映射概念来指定接口的算法示例. 例如, 请注意 breadth_first_search 的 ColorMap 模板参数. 此外, BGL 还包含许多实现属性映射接口的具体类型的例子. adjacency_list 类实现了用于访问附着到图顶点和边上的对象 (属性) 的属性映射.

Boost.Bimap map 的两个视图的对应物——set 和 unordered_set——是可读写的属性映射. 为了使用它们, 你需要包含以下头文件之一:

#include <boost/bimap/property_map/set_support.hpp>
#include <boost/bimap/property_map/unordered_set_support.hpp>

下面这个例子改编自 Boost.PropertyMap 文档中的示例.

转到源代码 

template <typename AddressMap>
void foo(AddressMap & address_map)
{
    typedef typename boost::property_traits<AddressMap>::value_type value_type;
    typedef typename boost::property_traits<AddressMap>::key_type key_type;

    value_type address;
    key_type fred = "Fred";
    std::cout << boost::get(address_map, fred);
}

int main()
{
    typedef bimap<std::string, multiset_of<std::string> > Name2Address;
    typedef Name2Address::value_type location;

    Name2Address name2address;
    name2address.insert( location("Fred", "710 West 13th Street") );
    name2address.insert( location( "Joe", "710 West 13th Street") );

    foo( name2address.left );

    return 0;
}
