插入

记住, map 可以被解释为两个集合之间的关系. 在 bimap 中, 我们可以自由地更改两个集合类型, 并对它们各自施加约束. 一些我们理所当然认为会在标准 map 中成功的插入, 在 bimap 中会失败. 例如:

bimap<int,std::string> bm;

bm.left.insert(1,"orange");
bm.left.insert(2,"orange"); // No effect! returns make_pair(iter,false)

只有当 bimap 的所有视图都允许时, 插入才会成功. 在下面的代码片段中, 我们把右侧集合定义为 multiset; 当我们尝试插入同样的两个元素时, 第二次插入被左 map 视图允许 (因为两个值不同) , 也被右 map 视图允许 (因为它是非唯一集合类型) .

bimap<int, multiset_of<std::string> > bm;

bm.left.insert(1,"orange");
bm.left.insert(2,"orange"); // Insertion succeed!

如果我们使用自定义的关系集合类型, 插入也必须得到它的允许.

iterator::value_type

Bimap 中存储的关系在大多数情况下不能直接通过迭代器修改, 因为两侧都被用作 基于键 集合的键. 当解引用一个 bimap<A,B> 左视图迭代器时, 返回类型与某个 签名兼容 的类型std::pair< const A, const B >. 不过有些集合类型不是 key_based 的, 例如 list_of. 如果 Bimap 使用了这些集合类型之一, 修改该侧的数据没有任何问题. 以下代码是有效的:

typedef bimap< int, list_of< std::string > > bm_type;
bm_type bm;
bm.insert( bm_type::relation( 1, "one" ) );
...
bm.left.find(1)->second = "1"; // Valid

在这种情况下, 解引用迭代器时返回的类型与某个 签名兼容 的类型std::pair<const int, std::string>.

operator[] 和 at()

set_of 和 unordered_set_of map 视图重载了 operator[], 仅当另一个集合类型是可变的时候才检索给定键的关联数据. 在这些情况下, 它的工作方式与标准相同.

bimap< unorderd_set_of< std::string>, list_of<int> > bm;

bm.left["one"] = 1; // Ok

标准为 map 和 unordered_map 定义了一个访问函数:

const data_type & at(const key_type & k) const;
      data_type & at(const key_type & k);

这些函数查找键并返回关联的数据值, 但如果找不到键则抛出 std::out_of_range 异常.

在 bimap 中, 这些函数的 const 版本对 set_of 和 unorderd_set_of map 视图都会提供, 与另一个集合类型无关. 只有当另一个集合类型可变时才提供可变版本.

下面的例子展示了 at(key) 的行为

转到源代码 

typedef bimap< set_of< std::string >, list_of< int > > bm_type;
bm_type bm;

try
{
    bm.left.at("one") = 1; // throws std::out_of_range
}
catch( std::out_of_range & e ) {}

assert( bm.empty() );

bm.left["one"] = 1; // Ok

assert( bm.left.at("one") == 1 ); // Ok


typedef bimap< multiset_of<std::string>, unordered_set_of<int> > bm_type;
bm_type bm;

bm.right[1] = "one"; // compilation error

bm.right.insert( bm_type::right_value_type(1,"one") );

assert( bm.right.at(1) == "one" ); // Ok

try
{
    std::cout << bm.right.at(2); // throws std::out_of_range
}
catch( std::out_of_range & e ) {}

bm.right.at(1) = "1"; // compilation error
