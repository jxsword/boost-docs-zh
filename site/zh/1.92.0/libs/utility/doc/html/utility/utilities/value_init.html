引言

在 C++ 中以泛型方式构造和初始化对象是困难的. 问题在于有多种不同的规则适用于初始化. 根据类型的不同, 新构造对象的值可以是零初始化 (逻辑上的 0)、默认构造 (使用默认构造函数), 或者是不确定的. 在编写泛型代码时, 必须处理这一问题. 模板 value_initialized 为标量类型、联合类型和类类型的值初始化提供了一致语法的解决方案. 此外, value_initialized 还为与值初始化相关的各种编译器问题提供了变通办法.

此外, 还提供了 const 对象 initialized_value, 以避免在从 value_initialized<T> 对象中取值时重复类型名.

在 C++ 中有多种初始化变量的方式. 以下声明都 可能 使局部变量初始化为其默认值:

T1 var1;
T2 var2 = 0;
T3 var3 = {};
T4 var4 = T4();

遗憾的是, 这些声明是否能正确初始化变量在很大程度上取决于其类型. 根据定义, 第一个声明对任何 可默认构造 类型都有效.

var1 的值是 不确定的, 当其类型是算术类型 (如 int、float 或 char) 时.

算术变量当然可以被第二个声明 T2 var2 = 0 正确初始化. 但是这种初始化形式通常不适用于类类型, 除非该类经过专门编写以支持这种方式初始化.

第三种形式 T3 var3 = {} 用于初始化聚合, 通常是 "C 风格" 的 struct 或 "C 风格" 数组. 但是, 在开发本库时, 该语法不允许用于具有显式声明构造函数的类.

第四种形式是其中最泛型的形式, 因为它可用于初始化算术类型、类类型、聚合、指针及其他类型. 声明 T4 var4 = T4() 应作如下理解: 首先通过 T4() 创建一个临时对象. 该对象是 值初始化 的. 接着把该临时对象拷贝到具名变量 var4. 之后, 临时对象被销毁. 虽然拷贝与销毁很可能被优化掉, C++ 仍然要求类型 T4 是 可拷贝构造 的. 因此 T4 需要既 是 可默认构造 的 又是 可拷贝构造 的.

类可能不是可拷贝构造的, 例如它可能有私有的且未定义的拷贝构造函数, 或者它可能派生自 boost::noncopyable. Scott Meyers [2] 解释了为什么类会那样定义.

第四种形式 T4 var4 = T4() 还有另一个不太明显的缺点: 它受到各种 编译器问题 的影响, 在某些特定于编译器的情况下导致变量未被初始化.

模板 value_initialized 提供了一种初始化对象的泛型方法, 如 T4 var4 = T4(), 但不要求其类型是 可拷贝构造 的. 它还为那些与值初始化相关的编译器问题提供了变通办法. 它允许获取任意类型的已初始化变量; 它 仅 要求该类型是 可默认构造 的. 通过以下声明构造一个经过正确 值初始化 的 T 类型对象:

value_initialized<T> var;

模板 initialized 同时提供值初始化与直接初始化. 它作为数据成员类型尤其有用, 允许同一个对象进行直接初始化或值初始化.

const 对象 initialized_value 允许按如下方式对变量进行值初始化:

T var = initialized_value;

这种初始化形式在语义上等价于 T4 var4 = T4(), 但对上述编译器问题是稳健的.

细节

C++ 标准 [3] 包含 zero-initialization 与 default-initialization 的定义. 非正式地说, 零初始化意味着给对象赋予转换为该类型的初始值 0; 默认初始化意味着 POD [4] 类型被零初始化, 而非 POD 类类型则用其相应的默认构造函数初始化.

声明 可以包含一个 初始化器, 它指定对象的初始值. 初始化器可以只是 '()', 它表明对象应被值初始化 (但见下文). 然而, 如果一个 声明 没有 初始化器 且它是非 const、非 static 的 POD 类型, 那么初始值是不确定的 (准确定义参见 §8.5 [dcl.init]).

int x; // no initializer. x value is indeterminate.
std::string s; // no initializer, s is default-constructed.

int y = int();
// y is initialized using copy-initialization
// but the temporary uses an empty set of parentheses as the initializer,
// so it is default-constructed.
// A default constructed POD type is zero-initialized,
// therefore, y == 0.

void foo ( std::string ) ;
foo ( std::string() ) ;
// the temporary string is default constructed
// as indicated by the initializer ()
值初始化

第一个 C++ 标准技术勘误 (TC1), 其草案于 2001 年 11 月向公众发布, 在众多议题中引入了 Core Issue 178.

该议题引入了 value-initialization 的新概念, 并修正了零初始化的措辞. 非正式地说, 值初始化类似于默认初始化, 区别在于某些情况下非静态数据成员和基类子对象也会被值初始化.

区别在于, 被值初始化的对象将不会 (或至少不太可能) 出现数据成员和基类子对象的不确定值; 与默认构造的对象不同 (规范性描述参见 Core Issue 178).

为了指定对象的值初始化, 我们需要使用空集初始化器: ().

与之前一样, 没有初始化器的声明指定默认初始化, 而带有非空初始化器的声明指定拷贝 (=xxx) 或直接 (xxx) 初始化.

template<class T> void eat(T);

int x ; // indeterminate initial value.

std::string s; // default-initialized.

eat ( int() ) ; // value-initialized

eat ( std::string() ) ; // value-initialized
值初始化语法

值初始化使用 () 来指定. 但是, 空括号集不被初始化器语法允许, 因为它会被解析为一个不接受实参的函数的声明:

int x() ; // declares function int(*)()

因此, 空的 () 必须放在某种其他初始化上下文中.

一种替代方法是使用拷贝初始化语法:

int x = int();

这对 POD 类型完全可行. 但对于非 POD 类类型, 拷贝初始化会搜索合适的构造函数, 例如可能是拷贝构造函数. 它还会搜索合适的转换序列, 但这不适用于此上下文.

对于任意的未知类型, 使用这种语法可能达不到预期的值初始化效果, 因为我们不知道从默认构造对象的拷贝是否与默认构造的对象完全相同; 而且在某些情况下, 编译器被允许 (但从不被要求) 优化掉该拷贝.

一种可能的泛型解决方案是使用非静态数据成员的值初始化:

template<class T>
struct W
{
    // value-initialization of 'data' here.
    W() : data() {}

    T data;
};

W<int> w;
// w.data is value-initialized for any type.

这就是 value_initialized<T> 模板类的早期版本所提供的解决方案. 遗憾的是, 这种方法受到各种编译器问题的影响.

编译器问题

各种编译器尚未完全实现值初始化. 因此, 当一个对象根据 C++ 标准应当被 值初始化 时, 由于这些编译器问题, 它在实践中 可能 仍然未被初始化. 很难对这些问题的具体表现做出概括, 因为它们取决于你使用的编译器、其版本号以及你希望值初始化的对象类型.

我们迄今为止测试过的所有编译器都能正确支持算术类型的值初始化. 然而, 各种编译器在某些 聚合 类型应当被值初始化时可能使其未被初始化. 指向成员的指针类型的对象的值初始化在各种编译器上也可能出错.

在撰写本文时 (2010 年 5 月), 当前编译器发行版中仍然存在以下已报告的与值初始化相关的问题:

  • Microsoft Visual Studio Feedback ID 100744, Value-initialization in new-expression: 由 Pavel Kuznetsov (MetaCommunications Engineering) 于 2005 年报告.
  • Microsoft Visual Studio Feedback ID 484295, VC++ does not value-initialize members of derived classes without user-declared constructor 由 Sylvester Hesp 于 2009 年报告.
  • Microsoft Visual Studio Feedback ID 499606, Presence of copy constructor breaks member class initialization 由 Alex Vakulenko 于 2009 年报告
  • Embarcadero/C++Builder Report 83751, Value-initialization: arrays should have each element value-initialized 由 Niels Dekker (LKEB) 于 2010 年报告.
  • Embarcadero/C++Builder Report 83851, Value-initialized temporary triggers internal backend error C1798 由 Niels Dekker 于 2010 年报告.
  • Embarcadero/C++Builder Report 84279, Internal compiler error (F1004), value-initializing member function pointer by "new T()" 由 Niels Dekker 于 2010 年报告
  • Sun CR 6947016: Sun 5.10 可能无法对非 POD 聚合的对象进行值初始化. 由 Niels Dekker 于 2010 年报告给 Steve Clamage.
  • IBM 的 XL V10.1 与 V11.1 可能无法对非 POD 聚合的临时对象进行值初始化. 由 Niels Dekker 于 2010 年报告给 Michael Wong.
  • Intel 支持问题 589832: 尝试对指向成员的指针进行值初始化会在 Intel 11.1 上触发内部错误. 由 John Maddock 于 2010 年报告.

注意, 所有已知的与值初始化相关的 GCC 问题都已在 GCC 4.4 版本中修复, 包括 GCC Bug 30111. 据我们所知, 随着 Clang Bug 7139 的修复, Clang 也已完全实现了值初始化.

新版本的 value_initialized (Boost 发布版本 1.35 或更高) 为这些问题提供了变通办法: value_initialized 现在可以在构造其包含的对象之前清空其内部数据. 它会基于 编译器缺陷宏 BOOST_NO_COMPLETE_VALUE_INITIALIZATION, 为需要这种变通办法的编译器这样做.

类型与对象

template class value_initialized<T> 
namespace boost {

template<class T>
class value_initialized
{

  public :

    value_initialized() : x() {}

    operator T const &() const { return x ; }

    operator T&() { return x ; }

    T const &data() const { return x ; }

    T& data() { return x ; }

    void swap( value_initialized& );

  private :

    [unspecified] x ;

} ;

template<class T>

T const& get ( value_initialized<T> const& x )
{
  return x.data();
}

template<class T>
T& get ( value_initialized<T>& x )
{
  return x.data();
}

template<class T>
void swap ( value_initialized<T>& lhs, value_initialized<T>& rhs )
{
  lhs.swap(rhs);
}

} // namespace boost

这个模板类的对象是一个 T 包装器, 可转换为 'T&', 其被包装对象 (类型为 T 的数据成员) 在此包装类默认初始化时被 值初始化:

int zero = 0;
value_initialized<int> x;
assert( x == zero ) ;

std::string def;
value_initialized< std::string > y;
assert( y == def ) ;

这个包装器的目的是为标量类型、联合类型和类类型 (POD 与非 POD) 的值初始化提供一致的语法, 因为值初始化的正确语法各不相同 (参见 值初始化语法).

被包装的对象可以通过转换运算符 T&、成员函数 data() 或非成员函数 get() 访问:

void watch(int);

value_initialized<int> x;

watch(x) ; // operator T& used.
watch(x.data());
watch( get(x) ) // function get() used

const 与非 const 对象都可以被包装. 可变对象可以在包装器内部直接修改, 但常量对象不行:

当 T 是 可交换 类型时, value_initialized<T> 也可交换, 既可以通过调用其 swap 成员函数, 也可以通过调用 boost::swap.

value_initialized<int> x;
static_cast<int&>(x) = 1 ; // OK
get(x) = 1 ; // OK

value_initialized<int const> y ;
static_cast<int&>(y) = 1 ; // ERROR: cannot cast to int&
static_cast<int const&>(y) = 1 ; // ERROR: cannot modify a const value
get(y) = 1 ; // ERROR: cannot modify a const value
警告

Boost 1.40.0 及更早版本的 value_initialized 实现允许从常量包装器对被包装对象进行 非 const 访问, 既通过其转换运算符, 也通过其 data() 成员函数.

例如:

value_initialized<int> const x_c;
int& xr = x_c ; // OK, conversion to int& available even though x_c is itself const.
xr = 2 ;

这种晦涩行为的原因是某些编译器不接受以下有效代码:

struct X
{
  operator int&() ;
    operator int const&() const ;
  };
  X x ;
  (x == 1) ; // ERROR HERE!

value_initialized 的当前版本不再有这种晦涩行为. 由于如今的编译器广泛支持通过提供 const 与 non-const 版本来重载转换运算符, 我们决定相应地修复这一问题. 因此, 当前版本支持逻辑常性的理念.

推荐做法: 非成员 get() 惯用法

能够从常量包装器内部修改非 const 被包装对象的晦涩行为 (value_initialized 的先前版本支持这样做), 可以通过始终使用 get() 惯用法来访问被包装对象而避免:

value_initialized<int> x;
get(x) = 1; // OK
value_initialized<int const> cx;
get(x) = 1; // ERROR: Cannot modify a const object

value_initialized<int> const x_c;
get(x_c) = 1; // ERROR: Cannot modify a const object

value_initialized<int const> const cx_c;
get(cx_c) = 1; // ERROR: Cannot modify a const object
template class initialized<T> 
namespace boost {

template<class T>
class initialized
{

  public :

    initialized() : x() {}

    explicit initialized(T const & arg) : x(arg) {}

    operator T const &() const;

    operator T&();

    T const &data() const;

    T& data();

    void swap( initialized& );

  private :

    [unspecified] x ;

};

template<class T>
T const& get ( initialized<T> const& x );

template<class T>
T& get ( initialized<T>& x );

template<class T>
void swap ( initialized<T>& lhs, initialized<T>& rhs );

} // namespace boost

模板类 boost::initialized<T> 同时支持值初始化与直接初始化, 因此其接口是 value_initialized<T> 接口的超集: 其默认构造函数像 value_initialized<T> 的默认构造函数一样对被包装对象进行值初始化, 但 boost::initialized<T> 还提供一个额外的 explicit 构造函数, 它用指定的值对被包装对象进行直接初始化.

initialized<T> 在被包装对象必须根据运行期条件进行值初始化或直接初始化时特别有用. 例如, initialized<T> 可以保存一个数据成员的值, 该数据成员可能被某些构造函数值初始化, 而被另一些构造函数直接初始化.

另一方面, 如果事先知道对象必须 总是 被值初始化, value_initialized<T> 可能更可取. 而如果对象必须总是被直接初始化, 那么这两个包装器实际上都不需要使用.

initialized_value 
namespace boost {
class initialized_value_t
{
  public :
    template <class T> operator T() const ;
};

initialized_value_t const initialized_value = {} ;

} // namespace boost

initialized_value 提供了一种获取已初始化值的便捷方式: 其转换运算符提供一个适当的 值初始化 对象, 适用于任何 可拷贝构造 类型.

假设你需要一个类型为 T 的已初始化变量. 你可以这样做:

T var = T();

但如前所述, 这种形式受到各种编译器问题的影响. 模板 value_initialized 提供了一种变通办法:

T var = get( value_initialized<T>() );

遗憾的是, 两种形式都重复了类型名, 它现在相当短 (T), 但当然可能更像 Namespace::Template<Arg>::Type.

作为替代, 可以按如下方式使用 initialized_value:

T var = initialized_value;
