引言

类模板 result_of 有助于确定调用表达式的类型. 例如, 给定一个左值 f, 其类型为 F, 以及左值 t1、t2、...、tN (类型分别为 T1、T2、...、TN), 类型 result_of<F(T1, T2, ..., TN)>::type 定义了表达式 f(t1, t2, ...,tN) 的结果类型.

这一实现允许类型 F 为函数指针、函数引用、成员函数指针或类类型. 默认情况下, N 可以是 0 到 16 之间的任意值. 要更改上限, 请把宏 BOOST_RESULT_OF_NUM_ARGS 定义为 N 的最大值. 类模板 result_of 位于头文件 <boost/utility/result_of.hpp> 中.

如果你编译器对 decltype 的支持足够, result_of 会自动使用它来推导调用表达式的类型, 此时 result_of<F(T1, T2, ..., TN)>::type 命名了类型 decltype(boost::declval<F>()(boost::declval<T1>(), boost::declval<T2>(), ..., boost::declval<TN>())), 如下例所示.

struct functor {
    template<class T>
    T operator()(T x)
    {
        return x;
    }
};

typedef boost::result_of<functor(int)>::type type; // type is int

你可以测试 result_of 是否在使用 decltype, 方法是检查宏 BOOST_RESULT_OF_USE_DECLTYPE 是否已在包含 result_of.hpp 之后定义. 你也可以强制 result_of 使用 decltype, 方法是先定义 BOOST_RESULT_OF_USE_DECLTYPE 再包含 result_of.hpp.

如果不使用 decltype, 则函数对象的自动结果类型推导是不可能的. 作为替代, result_of 使用以下协议让程序员指定类型. 当 F 是具有成员类型 result_type 的类类型时, result_of<F(T1, T2, ..., TN)>::type 为 F::result_type. 当 F 不包含 result_type 时, result_of<F(T1, T2, ..., TN)>::type 为 F::result<F(T1, T2, ..., TN)>::type (当 N > 0 时) 或 void (当 N = 0 时).

注意, 程序员有责任确保函数对象通过这一协议准确地宣告其结果类型, 如下例所示.

struct functor {
    template <class> struct result;

    template<class F, class T>
    struct result<F(T)> {
        typedef T type;
    };

    template<class T>
    T operator()(T x)
    {
        return x;
    }
};

typedef boost::result_of<functor(int)>::type type; // type is int

由于 decltype 是 C++11 标准化的语言特性, 如果你编写的函数对象要与 result_of 一起使用, 那么为了最大的可移植性, 即使你的编译器对 decltype 有正确的支持, 你也可以考虑遵循上述协议.

如果你希望在支持 decltype 的编译器上继续使用该协议, 有两种选择:

  • 你可以使用 boost::tr1_result_of, 它也定义在 <boost/utility/result_of.hpp> 中.
  • 或者, 你可以定义宏 BOOST_RESULT_OF_USE_TR1, 这会使 result_of 使用上述协议而不是 decltype. 如果你选择遵循该协议, 请注意确保 result_type 与 result<> 成员在给定调用表达式时准确表示 operator() 的返回类型.

此外, boost::result_of 提供了第三种操作模式, 某些用户可能会觉得方便. 当定义了 BOOST_RESULT_OF_USE_TR1_WITH_DECLTYPE_FALLBACK 时, boost::result_of 的行为如下: 如果函数对象具有成员类型 result_type 或成员模板 result<>, 则 boost::result_of 将使用 TR1 协议.

否则, boost::result_of 将使用 decltype. 以 decltype 作为后备来使用 TR1 可以解决某些问题, 但代价是可移植性. 例如:

  • 有缺陷的编译器: 如果你的代码要求 boost::result_of 能处理不完整返回类型, 但你编译器的 decltype 实现不支持不完整返回类型, 那么你可以使用 TR1 协议作为变通办法. 对不完整返回类型的支持是在 C++11 标准化过程的后期加入的 (参见 N3276), 某些编译器并未实现它.
  • 有缺陷的旧代码: 如果你现有的 TR1 函数对象宣告的类型与 decltype 推导出的实际结果类型不同, 那么以 decltype 作为后备来使用 TR1 将允许你同时使用现有的 TR1 函数对象和新的 C++11 函数对象. 如果你的旧函数对象误用了 TR1 协议, 就可能出现这种情况. 参见关于已知 差异 的文档 (boost::result_of 与 TR1 之间).
  • result_of 的这一实现要求类模板部分特化、正确解析函数类型的能力以及对 SFINAE 的支持. 如果你的编译器不支持 result_of, 包含头文件 <boost/utility/result_of.hpp> 将定义宏 BOOST_NO_RESULT_OF.

有关 result_of 的更多信息, 参见 C++ 库技术报告 N1836; 动机与设计理由参见 result_of 的 提案.

boost::result_of 的使用指南

以下是关于何时以及如何使用 boost::result_of 的一般建议.

  1. 如果你的目标是 C++11, 且不关心向不符合标准的编译器或标准的先前版本的移植, 那么请使用 std::result_of. 如果 std::result_of 满足你的需求, 那么没有理由停止使用它.
  2. 如果你的目标是 C++11, 但将来可能把代码移植到旧编译器, 那么请使用 boost::result_of 并配合 decltype. 当使用 decltype 时, boost::result_of 与 std::result_of 通常可以互换. 参见关于已知 差异 的文档 (boost::result_of 与 C++11 std::result_of 之间).
  3. 如果需要编译器可移植性, 请使用 boost::result_of 并采用 TR1 协议

无论你如何配置 boost::result_of, 都要记住: 函数的返回类型可能随其实参而变化; 此外, 成员函数的返回类型可能随对象的 cv 限定而变化. 必须向 boost::result_of 传递适当 cv 限定的类型, 才能推导出相应的返回类型.

例如:

struct functor {
    int& operator()(int);
    int const& operator()(int) const;

    float& operator()(float&);
    float const& operator()(float const&);
};

typedef boost::result_of<
    functor(int)
>::type type1; // type1 is int &

typedef boost::result_of<
    const functor(int)
>::type type2; // type2 is int const &

typedef boost::result_of<
    functor(float&)
>::type type3; // type3 is float &

typedef boost::result_of<
    functor(float const&)
>::type type4; // type4 is float const &

TR1 result_of 协议的使用指南

在符合标准的 C++11 编译器上, boost::result_of 可以使用 decltype 来推导任何调用表达式的类型, 包括对函数对象的调用. 但是, 在 C++11 之前的编译器或不支持足够 decltype 的编译器上, 如上所述, 函数对象需要额外的辅助设施. 以下是关于如何使用 TR1 协议的建议.

  • 当返回类型不依赖于实参类型或函数对象的 cv 限定时, 只需定义 result_type. 除非返回类型会变化, 否则无需使用 result 模板.
  • 在定义函数原型时使用协议指定的类型. 这有助于确保实际返回类型不会与协议规范不同步. 例如:
struct functor {
    typedef int result_type;
    result_type operator()(int);
};
  • 始终把 result 特化指定在相应的 operator() 重载附近. 这可以使特化更容易与重载保持同步. 例如:
struct functor {
    template<class> struct result;

    template<class F>
    struct result<F(int)> {
        typedef int& type;
    };
    result<functor(int)>::type operator()(int);

    template<class F>
    struct result<const F(int)> {
        typedef int const& type;
    };
    result<const functor(int)>::type operator()(int) const;
};
  • 使用类型变换来简化 result 模板特化. 例如, 下面使用 Boost.TypeTraits 对 result 模板进行特化, 使单个 operator() 既能在 const 又能在非 const 函数对象上以左值或右值实参进行调用.
struct functor {
    template<class> struct result;

    template<class F, class T>
    struct result<F(T)>
        : boost::remove_cv<
              typename boost::remove_reference<T>::type
          >
    {};

    template<class T>
    T operator()(T const&amp; x) const;
};

boost::result_of 与 boost::tr1_result_of 之间的已知差异

当使用 decltype 时, boost::result_of 会忽略 TR1 协议, 而是直接通过 decltype 推导函数对象的返回类型. 在大多数情况下, 只要用户正确使用协议, 就不会注意到差异. 以下情况下, boost::result_of 推导出的类型已知会因使用 decltype 还是 TR1 协议而不同.

TR1 协议误用: 使用 TR1 协议时, boost::result_of 无法检测对函数对象的调用的实际类型是否与协议指定的类型相同, 这就有可能在指定类型与实际类型之间出现无意的不匹配. 使用 decltype 时, 这些细微的缺陷可能导致编译错误. 例如:

struct functor {
   typedef short result_type;
   int operator()(short);
};

#ifdef BOOST_RESULT_OF_USE_DECLTYPE

BOOST_STATIC_ASSERT((
   boost::is_same<boost::result_of<functor(short)>::type, int>::value
));

#else

BOOST_STATIC_ASSERT((
   boost::is_same<boost::result_of<functor(short)>::type, short>::value
));

#endif

注意, 用户可以强制 boost::result_of 即使在支持 decltype 的平台上也使用 TR1 协议, 办法是定义 BOOST_RESULT_OF_USE_TR1.

空参函数对象: 使用 TR1 协议时, boost::result_of 并不总是能推导对空参函数对象的调用的类型, 此时类型默认为 void. 使用 decltype 时, boost::result_of 总是给出调用表达式的实际类型. 例如:

struct functor {
   template<class> struct result {
       typedef int type;
   };
   int operator()();
};

#ifdef BOOST_RESULT_OF_USE_DECLTYPE

BOOST_STATIC_ASSERT((
   boost::is_same<boost::result_of<functor()>::type, int>::value
));

#else

BOOST_STATIC_ASSERT((
   boost::is_same<boost::result_of<functor()>::type, void>::value
));

#endif

注意, 针对空参函数问题有一些变通办法. 只要返回类型不变, 无论元数如何, 都可以使用 result_type 来指定返回类型. 如果返回类型会变化, 那么用户可以为空参调用对 boost::result_of 本身进行特化.

非类纯右值与 cv 限定: 使用 TR1 协议时, boost::result_of 将报告 result_type 或 result 模板所指定的 cv 限定类型, 而不管调用表达式的实际 cv 限定. 使用 decltype 时, boost::result_of 将报告调用表达式的实际类型; 当表达式是非类纯右值时, 该类型不带 cv 限定. 例如:

struct functor {
   template<class> struct result;
   template<class F, class T> struct result<F(const T)> {
       typedef const T type;
   };

   const short operator()(const short);
   int const & operator()(int const &);
};

// Non-prvalue call expressions work the same with or without decltype.

BOOST_STATIC_ASSERT((
   boost::is_same<
       boost::result_of<functor(int const &)>::type,
       int const &
::value
));

// Non-class prvalue call expressions are not actually cv-qualified,
// but only the decltype-based result_of reports this accurately.

#ifdef BOOST_RESULT_OF_USE_DECLTYPE

BOOST_STATIC_ASSERT((
   boost::is_same<
       boost::result_of<functor(const short)>::type,
       short
::value
));

#else

BOOST_STATIC_ASSERT((
   boost::is_same<
       boost::result_of<functor(const short)>::type,
       const short
::value
));

#endif

boost::result_of 与 C++11 result_of 之间的已知差异

使用 decltype 时, boost::result_of 实现了 C++11 std::result_of 规范的大部分内容. 一个已知的例外是 boost::result_of 未实现有关成员数据指针的要求.
