引言

类模板 base_from_member 支持 base-from-member 惯用法. 在开发类时, 有时基类需要用当前类的某个成员来初始化. 作为一个朴素的示例:

#include <streambuf>  /* for std::streambuf */
#include <ostream>    /* for std::ostream */

class fdoutbuf
  : public std::streambuf
{
public:
    explicit fdoutbuf( int fd );
    //...
};

class fdostream
  : public std::ostream
{
protected:
    fdoutbuf buf;
public:
    explicit fdostream( int fd )
      : buf( fd ), std::ostream( &buf ) {}
    //...
};

这是未定义的, 因为 C++ 的初始化顺序规定基类在其所使用的成员之前初始化. R. Samuel Klatchko 找到了一种解决办法: 让初始化顺序为自己所用. 基类按声明顺序初始化, 因此把所需的成员移到另一个基类中, 并使该基类在所需基类之前初始化, 即可确保正确的初始化.

可以为这一惯用法定制一个基类:

#include <streambuf>  /* for std::streambuf */
#include <ostream>    /* for std::ostream */

class fdoutbuf
  : public std::streambuf
{
public:
    explicit fdoutbuf( int fd );
    //...
};

struct fdostream_pbase
{
    fdoutbuf sbuffer;

    explicit fdostream_pbase( int fd )
      : sbuffer( fd ) {}
};

class fdostream
  : private fdostream_pbase
  , public std::ostream
{
    typedef fdostream_pbase  pbase_type;
    typedef std::ostream     base_type;

public:
    explicit fdostream( int fd )
      : pbase_type( fd ), base_type( &sbuffer ) {}
    //...
};

其他项目可以使用类似的自定义基类. 这一技术足够基础, 可以做成模板, 本库中就提供了一个示例模板类. 主要的模板参数是被包含成员的类型. 该模板类具有若干 (显式) 构造函数成员模板, 它们隐式推导构造函数实参的类型并把它们传递给该成员. 该模板类使用隐式拷贝构造与赋值, 若被包含成员不可拷贝则将其取消.

如果构造和/或拷贝需求对于所提供的模板类而言过于复杂, 或者编译器不够先进而无法使用它, 那么手动编写基类可能更好.

由于基类没有名字, 一个类不能拥有多个相同类型的 (直接) 基类. 所提供的模板类有一个额外的模板参数 (一个整数), 它存在的唯一目的是提供类型区分. 该参数有默认值, 因此单独使用某个特定成员类型时无需关心该整数.

概要 

#include <type_traits>  /* exposition only */

#ifndef BOOST_BASE_FROM_MEMBER_MAX_ARITY
#define BOOST_BASE_FROM_MEMBER_MAX_ARITY  10
#endif

template < typename MemberType, int UniqueID = 0 >
class base_from_member
{
protected:
    MemberType  member;

#if C++11 is in use
    template< typename ...T >
    explicit constexpr base_from_member( T&& ...x )
     noexcept( std::is_nothrow_constructible<MemberType, T...>::value );
#else
    base_from_member();

    template< typename T1 >
    explicit  base_from_member( T1 x1 );

    template< typename T1, typename T2 >
    base_from_member( T1 x1, T2 x2 );

    //...

    template< typename T1, typename T2, typename T3, typename T4,
     typename T5, typename T6, typename T7, typename T8, typename T9,
     typename T10 >
    base_from_member( T1 x1, T2 x2, T3 x3, T4 x4, T5 x5, T6 x6, T7 x7,
     T8 x8, T9 x9, T10 x10 );
#endif
};

template < typename MemberType, int UniqueID >
class base_from_member<MemberType&, UniqueID>
{
protected:
    MemberType& member;

    explicit constexpr base_from_member( MemberType& x )
        noexcept;
};

该类模板的第一个模板参数 MemberType 表示成员基类的类型. 它的最后一个模板参数 UniqueID 是一个 int, 用于区分使用相同成员基类类型的多个基类. 若省略, 最后一个模板参数的默认值为零. 该类模板有一个名为 member 的受保护数据成员, 派生类可以在后续基类或自身中使用它.

如果存在相应的 C++11 特性, 则将只有一个构造函数模板. 它实现 完美转发, 以调用 member 的最佳构造函数 (如果有的话). 该构造函数模板同时以 constexpr 和 explicit 标记. 若 member 的相应内部构造函数调用不具有该标记, 则前者将被忽略. 后者的绑定方式相反; 总是生效, 即使内部构造函数调用不具有该标记. 该构造函数模板会传播内部构造函数调用的 noexcept 状态. 该构造函数模板有一个带默认值的尾部参数, 当其签名与 base_from_member 自动定义的非模板拷贝和/或移动构造函数的签名过于接近时, 该参数会禁用此模板.

在较早标准的编译器上, 存在一个默认构造函数和若干构造函数成员模板. 这些构造函数模板可以接受尽可能多的实参 (当前最多十个), 并把它们传递给数据成员的某个构造函数.

针对成员引用的特化提供了一个单一的构造函数, 它接受一个 MemberType&, 这是初始化引用的唯一方式.

由于 C++ 不允许以任何方式显式指定模板化构造函数的模板参数, 请确保实参已尽可能接近数据成员所需构造函数中使用的实际类型. 可能需要显式转换.

BOOST_BASE_FROM_MEMBER_MAX_ARITY 宏常量为构造函数模板指定最大实参长度. 如果需要更多 (或更少) 的实参配置, 可以覆盖该常量. 对于像该类模板一样可扩展且需要保持相同最大大小的代码, 可以读取该常量. (示例代码可以是一个类, 它把该类模板用作某个成员的基类, 该成员具有灵活的构造函数集合.) 当存在 C++11 特性时, 该常量将被忽略.

基本用法

对于开头的示例, fdoutbuf 子对象需要封装在一个基类中, 且该基类要在 std::ostream 之前被继承.

#include <boost/utility/base_from_member.hpp>

#include <streambuf>  // for std::streambuf
#include <ostream>    // for __std_ostream__

class fdoutbuf
  : public std::streambuf
{
public:
    explicit fdoutbuf( int fd );
    //...
};

class fdostream
  : private boost::base_from_member<fdoutbuf>
  , public std::ostream
{
    // Helper typedef's
    typedef boost::base_from_member<fdoutbuf>  pbase_type;
    typedef std::ostream                        base_type;

public:
    explicit fdostream( int fd )
      : pbase_type( fd ), base_type( &member ){}
    //...
};

base-from-member 惯用法是一个实现细节, 因此不应对 fdostream 的客户 (或任何派生类) 可见. 由于初始化顺序, fdoutbuf 子对象会在 std::ostream 子对象之前初始化, 使得前一个子对象在后一个子对象的构造中可以安全使用. 由于最终类型的 fdoutbuf 子对象是唯一具有名字 member 的子对象, 该名字可以在最终类中不加限定地使用.

多个子对象

base-from-member 类模板通常应当只涉及一个 base-from-member 子对象, 通常用于把流缓冲区附加到 I/O 流. 下一个示例演示如何使用多个 base-from-member 子对象以及由此产生的限定问题.

#include <boost/utility/base_from_member.hpp>

#include <cstddef>  /* for NULL */

struct an_int
{
    int  y;

    an_int( float yf );
};

class switcher
{
public:
    switcher();
    switcher( double, int * );
    //...
};

class flow_regulator
{
public:
    flow_regulator( switcher &, switcher & );
    //...
};

template < unsigned Size >
class fan
{
public:
    explicit fan( switcher );
    //...
};

class system
  : private boost::base_from_member<an_int>
  , private boost::base_from_member<switcher>
  , private boost::base_from_member<switcher, 1>
  , private boost::base_from_member<switcher, 2>
  , protected flow_regulator
  , public fan<6>
{
    // Helper typedef's
    typedef boost::base_from_member<an_int>       pbase0_type;
    typedef boost::base_from_member<switcher>     pbase1_type;
    typedef boost::base_from_member<switcher, 1>  pbase2_type;
    typedef boost::base_from_member<switcher, 2>  pbase3_type;

    typedef flow_regulator  base1_type;
    typedef fan<6>          base2_type;

public:
    system( double x );
    //...
};

system::system( double x )
  : pbase0_type( 0.2 )
  , pbase1_type()
  , pbase2_type( -16, &this->pbase0_type::member.y )
  , pbase3_type( x, static_cast<int *>(NULL) )
  , base1_type( pbase3_type::member, pbase1_type::member )
  , base2_type( pbase2_type::member )
{
    //...
}

最终类有多个名为 member 的子对象, 因此对该名字的任何使用都需要用适当基类型的名字进行限定. 使用 typedef 可以轻松提及基类型.

但是, 当需要指针时, 这一修正会引入一个新问题. 对用其类名限定的子对象使用取地址运算符会得到指向成员的指针 (此处类型为 an_int boost::base_from_member<an_int, 0>::*), 而不是指向该成员的指针 (类型为 an_int*). 通过用 this-> 限定该子对象可以解决这个新问题, 并且只有指针需要这样做, 引用或值不需要.

初始化中存在一些实参转换. pbase0_type 的构造函数实参从 double 转换为 float. pbase2_type 的第一个构造函数实参从 int 转换为 double.

pbase3_type 的第二个构造函数实参是必要转换的一个特例; C++ 中空指针字面量的所有形式 (C++11 的 nullptr 除外) 看起来也像编译期整数表达式, 因此当存在既能接受整数又能接受指针的重载时, C++ 总是把这类代码解释为整数.

编译器需要最后一次转换, 以调用使用 switcher 的构造函数中确切指针类型的构造函数形式. (如果使用 C++11 的 nullptr, 当构造函数调用可以接受多种指针类型而 std::nullptr_t 不能时, 仍然需要转换.)
