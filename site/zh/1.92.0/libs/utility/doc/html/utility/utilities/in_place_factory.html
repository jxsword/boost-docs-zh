引言

假设我们有一个类

struct X
{
  X ( int, std::string ) ;
};

以及一个支持空状态的容器. 也就是说, 一个可以包含零个对象的容器:

struct C
{
   C() : contained_(0) {}
  ~C() { delete contained_ ; }
  X* contained_ ;
};

设计为支持空状态的容器通常不要求所包含类型是 可默认构造 的, 但通常要求它是 可拷贝构造 的, 以此作为初始化要存储对象的机制:

struct C
{
   C() : contained_(0) {}
   C ( X const& v ) : contained_ ( new X(v) ) {}
  ~C() { delete contained_ ; }
  X* contained_ ;
};

这有一个微妙的问题: 由于用于初始化所存对象的机制是拷贝构造, 因此必须存在一个先前构造好的源对象供拷贝. 该对象很可能是临时的, 除了作为源之外别无用途:

void foo()
{
  // Temporary object created.
  C c( X(123,"hello") ) ;
}

该问题的一种解决办法是支持直接在容器的存储中构造所包含的对象.

在这一方案中, 用户把 X 构造函数的实参直接提供给容器:

struct C
{
   C() : contained_(0) {}
   C ( X const& v ) : contained_ ( new X(v) ) {}
   C ( int a0, std::string a1 ) : contained_ ( new X(a0,a1) ) {}
  ~C() { delete contained_ ; }
  X* contained_ ;
};

void foo()
{
  // Wrapped object constructed in-place
  // No temporary created.
  C c(123,"hello");
}

显然, 这一方案的扩展性不佳, 因为容器必须复制所包含类型的所有构造函数重载, 或至少复制所有要在容器中直接支持的重载.

框架

本库提出一个框架, 允许某些容器直接就地构造所包含的对象, 而无需来自所包含类型的整套构造函数重载. 它还允许容器移除对所包含类型的 可拷贝构造 要求, 因为对象可以直接就地构造而无需拷贝.

对容器的唯一要求是它必须提供合适的存储. 也就是说, 容器应当正确对齐且大小正确. 自然, 容器通常会支持未初始化的存储, 以避免就地构造覆盖一个已完整构造的对象, 因为那将使就地构造失去意义.

为此, 该框架提供了两个概念: InPlaceFactories 与 TypedInPlaceFactories. 用于声明这些类的辅助工具声明在 <boost/utility/in_place_factory.hpp> 与 <boost/utility/typed_in_place_factory.hpp> 中.

本质上, 这些类持有一系列实际参数以及一个使用这些参数就地构造对象的方法. 该家族的每个成员仅在参数列表的数量和类型上有所不同. 第一个家族在为此目的提供的方法中直接给出要构造对象的类型, 而第二个家族则把该类型并入工厂类本身. 从容器的角度看, 使用该框架相当于调用工厂的方法来就地构造对象. 从用户的角度看, 这相当于创建合适的工厂对象来持有参数并将其传递给容器.

下面这个简化示例展示了基本思想. 框架的正式规格说明之后附有一个完整示例:

struct C
{
   template <class InPlaceFactory>
   C ( InPlaceFactory const& aFactory )
    :
    contained_ ( uninitialized_storage() )
   {
     aFactory.template apply<X>(contained_);
   }

  ~C()
  {
    contained_ -> X::~X();
    delete[] contained_ ;
  }

  char* uninitialized_storage() { return new char[sizeof(X)] ; }

  char* contained_ ;
};

void foo()
{
  C c( in_place(123,"hello") ) ;
}

规格说明

下面是 InPlaceFactory 类家族的第一个成员及其对应的辅助模板函数. 该家族其余成员仅在模板参数与构造函数参数的数量和类型上有所不同.

namespace boost {

struct in_place_factory_base {};

template<class A0>
class in_place_factory : public in_place_factory_base
{
  public:
    in_place_factory ( A0 const& a0 ) : m_a0(a0) {}

    template< class T >
    void apply ( void* address ) const
    {
      new (address) T(m_a0);
    }

  private:
      A0 const& m_a0 ;
};

template<class A0>
in_place_factory<A0> in_place ( A0 const& a0 )
{
  return in_place_factory<A0>(a0);
}

}

类似地, 下面是 typed_in_place_factory 类家族的第一个成员及其对应的辅助模板函数. 该家族其余成员仅在模板参数与构造函数参数的数量和类型上有所不同.

namespace boost {

struct typed_in_place_factory_base {};

template<class T, class A0>
class typed_in_place_factory : public typed_in_place_factory_base
{
  public:
    typed_in_place_factory ( A0 const& a0 ) : m_a0(a0) {}

    void apply ( void* address ) const
    {
      new (address) T(m_a0);
    }

  private:
    A0 const& m_a0 ;
};

template<class T, class A0>
typed_in_place_factory<A0> in_place ( A0 const& a0 )
{
  return typed_in_place_factory<T,A0>(a0);
}
}

可以看到, in_place_factory 与 typed_in_place_factory 模板类仅在指定目标类型的方式上有所不同: 第一个家族中, 类型作为模板实参提供给 apply 成员函数; 第二个家族中, 类型直接作为工厂类的一部分给出.

当容器持有唯一的非多态类型时 (例如 Boost.Optional 的情况), 它知道所包含对象的确切动态类型, 并可以将其传递给非类型化工厂的 apply() 方法. 在这种情况下, 最终用户可以使用 in_place_factory 实例, 该实例可以在不知道要构造对象类型的情况下构造.

但是, 如果容器持有异构或多态对象 (例如 Boost.Variant 的情况), 则工厂必须知道要构造对象的动态类型. 在这种情况下, 最终用户必须改用 typed_in_place_factory.

容器侧用法

如开头的简化示例所示, 容器类必须包含接受这些工厂实例并把对象存储传递给工厂 apply 方法的方法.

但是, 工厂类的类型不能在容器类中完全指定, 因为那将使工厂失去其全部意义, 即允许容器为其所包含对象的构造函数接受可变实参列表.

正确的函数重载必须基于每个家族中所有类唯一而共同的特性: 基类.

根据容器类, 你可以使用 enable_if 生成正确的重载, 或者使用 Boost.Optional 类中所用的以下分派技术:

struct C
{
   C() : contained_(0) {}
   C ( X const& v ) : contained_ ( new X(v) ) {}

   template <class Expr>
   C ( Expr const& expr )
    :
    contained_ ( uninitialized_storage() )
   {
    construct(expr,&expr);
   }

  ~C() { delete contained_ ; }

  template<class InPlaceFactory>
  void construct ( InPlaceFactory const& aFactory, const boost::in_place_factory_base* )
  {
    aFactory.template apply<X>(contained_);
  }

  template<class TypedInPlaceFactory>
  void construct ( TypedInPlaceFactory const& aFactory, const boost::typed_in_place_factory_base* )
  {
    aFactory.apply(contained_);
  }

  X* uninitialized_storage() { return static_cast<X*>(new char[sizeof(X)]) ; }

  X* contained_ ;
};

用户侧用法

最终用户向容器传递一个工厂对象实例, 其中持有直接在容器内构造所包含对象所需的实际参数. 为此, 要使用辅助模板函数 in_place.

调用 in_place(a0,a1,a2,...,an) 会用给定的实参列表构造一个 (非类型化的) in_place_factory 实例.

调用 in_place<T>(a0,a1,a2,...,an) 会用给定的实参列表构造一个 typed_in_place_factory 实例, 其目标类型为 T.

void foo()
{
  C a( in_place(123, "hello") ) ;    // in_place_factory passed
  C b( in_place<X>(456, "world") ) ; // typed_in_place_factory passed
}
