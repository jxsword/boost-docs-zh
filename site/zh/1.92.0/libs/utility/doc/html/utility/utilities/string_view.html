引言

类 boost::string_view 及其他派生自 basic_string_view 的类表示对字符串或子串的引用. 当你从某个外部来源解析/处理字符串时, 经常需要把一段文本传递给某个过程做专门处理. 在 std::string_view 出现之前, 规范的做法是使用 std::string, 但这有一些缺点:

1) 如果你正在处理一段文本缓冲区 (例如 HTTP 响应或文件内容), 那么你必须从想要传递的文本创建字符串, 这涉及内存分配和数据拷贝.

2) 如果某个例程接收到一个常量 std::string 并想把该字符串的一部分传递给另一个例程, 那么它必须为该子串创建一个新字符串.

3) 如果某个例程接收到一个常量 std::string 并想返回字符串的一部分, 那么它必须创建一个新字符串来返回.

boost::string_view 的设计目的就是解决这些效率问题. boost::string_view 是对连续字符序列的只读引用, 提供了 std::string 的大部分功能. boost::string_view 的创建、拷贝与按值传递都很廉价, 因为它实际上并不拥有它所指向的存储.

boost::string_view 被实现为一个小的结构体, 其中包含一个指向字符 data 起始位置的指针以及一个 count. boost::string_view 的创建与拷贝都很廉价.

boost::string_view 充当容器; 它包含你所期望的容器的所有方法, 包括迭代支持、operator[]、at 和 size. 它可以与 STL 中任何基于迭代器的算法一起使用 - 只要你不需要更改底层数据. 例如, std::sort 与 std::remove 将无法工作.

除了通用容器功能之外, boost::string_view 还提供了 std::string 接口的一个子集. 这使得把类型为 const std::string & 的形参替换为 boost::string_view 变得容易. 与 std::string 一样, boost::string_view 有一个名为 npos 的静态成员变量, 用于表示搜索失败的结果以及"末尾"的含义.

注意

由于 boost::string_view 并不拥有它所引用的数据, 它把生存期问题引入到使用它的代码中. 程序员必须确保 string_view 所引用的数据与 string_view 存活得一样久.

注释

Boost.Utility 还包括类 string_ref:

- string_ref 是 Jeffrey Yaskin 的 N3442: string_ref: a non-owning reference to a string 的初始实现.

- string_view 是为反映 Library Fundamentals TS N4480: [string.view] 而更新的实现.

请优先使用 string_view / basic_string_view 而不是 string_ref / basic_string_ref:

- basic_string_view 类与 std::basic_string_view 匹配得更好.

- basic_string_view 具有多得多的 constexpr 支持.

- 使用 basic_string_ref 的代码应当能继续工作.

- 已经没有多少代码依赖于 basic_string_ref 了.

示例

把 string_view 集成到你的代码中相当简单. 凡是你以 const std::string & 或 std::string 作为形参的地方, 都是传入 boost::string_view 的候选位置.

std::string extract_part ( const std::string &bar ) {
    return bar.substr ( 2, 3 );
}

if ( extract_part ( "ABCDEFG" ).front() == 'C' ) { /* do something */ }

让我们弄清楚这个人为构造的示例中发生了什么.

  • 首先, 从字符串字面量 "ABCDEFG" 创建一个临时字符串, 并把它 (按引用) 传递给例程 extract_part.
  • 然后在调用 std::string::substr 时创建了第二个字符串, 并返回给 extract_part (这个拷贝可能被 RVO 消除).
  • 然后 extract_part 把该字符串返回给调用者 (同样, 这个拷贝可能被消除).
  • 第一个临时字符串被释放, 然后对第二个字符串调用 front, 之后它也被释放.

创建了两个 std::string 和两次拷贝操作. 这可能意味着四次内存分配与释放, 以及相应的数据拷贝.

现在我们用 string_view 来看看相同的代码:

boost::string_view extract_part ( boost::string_view bar ) {
    return bar.substr ( 2, 3 );
}

if ( extract_part ( "ABCDEFG" ).front() == "C" ) { /* do something */ }

没有内存分配. 没有字符数据拷贝. 除类型之外代码没有任何更改. 创建了两个 string_view, 拷贝了两个 string_view, 但这些都是廉价的操作.

概要

头文件 <boost/utility/string_view.hpp> 定义了一个模板 boost::basic_string_view, 以及四个特化 string_view、wstring_view、u16string_view、u32string_view - 分别用于 char / wchar_t / char16_t / char32_t.

#include <boost/utility/string_view.hpp>

构造与拷贝:

constexpr basic_string_view ();    // Constructs an empty string_view
constexpr basic_string_view(const charT* str); // Constructs from a NULL-terminated string
constexpr basic_string_view(const charT* str, size_type len); // Constructs from a pointer, length pair
template<typename Allocator>
basic_string_view(const std::basic_string<charT, traits, Allocator>& str); // Constructs from a std::string
basic_string_view (const basic_string_view &rhs);
basic_string_view& operator=(const basic_string_view &rhs);

string_view 没有定义移动构造函数或移动赋值运算符, 因为拷贝一个 string_view 与移动它一样廉价.

基本的类容器函数:

constexpr size_type size()     const ;
constexpr size_type length()   const ;
constexpr size_type max_size() const ;
constexpr bool empty()         const ;
