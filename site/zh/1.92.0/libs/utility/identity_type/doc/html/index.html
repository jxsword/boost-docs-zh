本库允许把类型包裹在圆括号内, 使其始终可以作为宏参数传递.

动机

考虑下面这个宏, 它声明一个名为 varn 的变量, 其类型为指定的 type (另见 var_error.cpp):

#define VAR(type, n) type var ## n

VAR(int, 1);                    // OK.
VAR(std::map<int, char>, 2);    // Error.

第一次宏调用正确地声明了名为 var1、类型为 int 的变量. 然而, 第二次宏调用失败, 产生类似如下的预处理器错误:

error: macro "VAR" passed 3 arguments, but takes just 2

这是因为作为第一个宏参数传入的 std::map 类型包含一个逗号 , 而未被圆括号 () 包裹. 预处理器把那个未包裹的逗号解释为宏参数之间的分隔符, 从而认定传给宏的参数共有三个 (而不是两个), 顺序如下:

  1. std::map<int
  2. char>
  3. 2

请注意: 与编译器不同, 预处理器只识别圆括号 (). 解析宏参数时, 预处理器不识别尖括号 <> 和方括号 [].

解决办法

某些情况下, 或许可以完全避免把类型表达式传给宏, 从而绕开这个问题. 例如, 上面的情形本可以用一个 typedef 在宏之外指定带逗号的类型表达式 (另见 var.cpp):

typedef std::map<int, char> map_type;
VAR(map_type, 3); // OK.

当这种做法既不可行也不合意时 (例如, 见下文小节中的函数模板 f), 本库头文件 boost/utility/identity_type.hpp 定义了宏 BOOST_IDENTITY_TYPE, 它可以在把类型表达式保留为宏参数之一的同时绕开这个问题 (另见 var.cpp).

#include <boost/utility/identity_type.hpp>

VAR(BOOST_IDENTITY_TYPE((std::map<int, char>)), 4); // OK.

该宏 BOOST_IDENTITY_TYPE 展开为一个在编译期求值为指定类型的表达式. 指定的类型永远不会被拆分成多个宏参数, 因为它总是被一组额外的圆括号 () 包裹. 实际上, 必须使用两组圆括号: 调用宏的括号 BOOST_IDENTITY_TYPE(...), 以及包裹传给宏的类型的内部括号 BOOST_IDENTITY_TYPE((...)).

该宏可在任何 C++03 编译器上工作 (且不使用 变参宏). [1] 作者最初在 Cygwin 上的 GNU Compiler Collection (GCC) C++ 4.5.3 (无论是否启用 C++11 特性 -std=c++0x) 以及 Windows 7 上的 Miscrosoft Visual C++ (MSVC) 8.0 中开发和测试了本库. 支持的编译器与平台的更多信息请参见本库的 回归测试结果.

模板

在模板内使用时, 该宏必须以 typename 作为前缀. 例如, 我们来编写一个宏, 它声明一个名为 argn 的函数参数, 其类型为指定的 type (另见 template.cpp):

#define ARG(type, n) type arg ## n

template<typename T>
void f( // Prefix macro with `typename` in templates.
    ARG(typename BOOST_IDENTITY_TYPE((std::map<int, T>)), 1)
) {
    std::cout << arg1[0] << std::endl;
}


std::map<int, char> a;
a[0] = 'a';

f<char>(a); // OK...
// f(a);    // ... but error.

但是请注意: 模板参数 char 必须像 f<char>(a) 这样在调用函数时手工指定. 实际上, 当 BOOST_IDENTITY_TYPE 宏用于包裹函数模板参数时, 编译器将无法再像 f(a) 原本会做的那样从函数调用中自动推导该模板参数. [2] (该限制不适用于类模板, 因为类模板参数总是必须显式指定.) 换句话说, 若不使用 BOOST_IDENTITY_TYPE 宏, C++ 通常能够自动推导函数模板参数, 如下所示:

template<typename T>
void g(
    std::map<int, T> arg1
) {
    std::cout << arg1[0] << std::endl;
}


g<char>(a); // OK...
g(a);       // ... and also OK.

抽象类型

在某些编译器上 (例如 GCC), 对抽象类型 (即含有一个或多个纯虚函数的类) 使用该宏会产生编译错误. 这可以通过对该类型进行操作——添加再移除一个引用——来避免.

我们来编写一个对 模板元编程 (TMP) 元函数执行静态断言的宏 (类似于 Boost.MPL 的 BOOST_MPL_ASSERT). 该宏 BOOST_IDENTITY_TYPE 可用于把带有多个模板参数的元函数传给断言宏 (以便处理分隔模板参数的逗号). 此时, 若元函数是抽象类型, 则需要通过添加再移除一个引用来操作它 (另见 abstract.cpp):

#define TMP_ASSERT(metafunction) \
    BOOST_STATIC_ASSERT(metafunction::value)

template<typename T, bool b>
struct abstract {
    static const bool value = b;
    virtual void f(T const& x) = 0;     // Pure virtual function.
};

TMP_ASSERT(
    boost::remove_reference<            // Add and remove
        BOOST_IDENTITY_TYPE((           // reference for
            boost::add_reference<       // abstract type.
                abstract<int, true>
            >::type
        ))
    >::type
);

附录: 用法

该宏 BOOST_IDENTITY_TYPE 既可以在调用用户自定义宏时使用 (如前文的示例所示), 也可以在实现用户自定义宏时在内部使用 (如下所示). 当 BOOST_IDENTITY_TYPE 用于用户自定义宏的实现中时, 用户宏的调用者将必须指定额外的括号 (另见 paren.cpp):

#define TMP_ASSERT_PAREN(parenthesized_metafunction) \
    /* use `BOOST_IDENTITY_TYPE` in macro definition instead of invocation */ \
    BOOST_STATIC_ASSERT(BOOST_IDENTITY_TYPE(parenthesized_metafunction)::value)

#define TMP_ASSERT(metafunction) \
    BOOST_STATIC_ASSERT(metafunction::value)

// Specify only extra parenthesis `((...))`.
TMP_ASSERT_PAREN((boost::is_const<std::map<int, char> const>));

// Specify both the extra parenthesis `((...))` and `BOOST_IDENTITY_TYPE` macro.
TMP_ASSERT(BOOST_IDENTITY_TYPE((boost::is_const<std::map<int, char> const>)));

但是请注意: 调用者 总是 必须指定额外的括号, 即使宏参数中不包含逗号:

TMP_ASSERT_PAREN((boost::is_const<int const>)); // Always extra `((...))`.

TMP_ASSERT(boost::is_const<int const>); // No extra `((...))` and no macro.

某些情况下, 在用户自定义宏的实现中使用 BOOST_IDENTITY_TYPE 可能为调用者提供最佳语法. 例如 BOOST_MPL_ASSERT 就是如此: 因为大多数模板元编程表达式都含有未包裹的逗号, 让用户总是指定额外括号 ((...)) 比使用 BOOST_IDENTITY_TYPE 更不容易混淆:

BOOST_MPL_ASSERT(( // Natural syntax.
    boost::mpl::and_<
          boost::is_const<T>
        , boost::is_reference<T>
    >
));

然而, 在另一些情况下, 更可取的做法可能是不在常见情形中要求额外括号, 而是使用 BOOST_IDENTITY_TYPE 把逗号作为特殊情形来处理. 例如 BOOST_LOCAL_FUNCTION 就是如此: 若总是要求类型周围有额外括号 ((...)), 会导致局部函数签名的语法很不自然:

int BOOST_LOCAL_FUNCTION( ((int&)) x, ((int&)) y ) { // Unnatural syntax.
    return x + y;
} BOOST_LOCAL_FUNCTION_NAME(add)

改为只在需要时才要求用户指定 BOOST_IDENTITY_TYPE, 就可以在参数类型不含逗号的常见情形下使用更自然的语法 BOOST_LOCAL_FUNCTION(int& x, int& y) (同时仍允许在特殊情形下用 BOOST_LOCAL_FUNCTION(BOOST_IDENTITY_TYPE((std::map<int, char>))& x, int& y) 指定含逗号的参数类型).

附录: 实现

本库宏的实现等价于如下代码: [3] 

#include <boost/type_traits/function_traits.hpp>

#define BOOST_IDENTITY_TYPE(parenthesized_type) \
    boost::function_traits<void parenthesized_type>::arg1_type

本质上, 该类型被包裹在圆括号 (std::map<int, char>) 之间, 因此即使它包含逗号, 也可以作为单个宏参数传递. 然后, 这个带括号的类型被转换为一个返回 void、以指定类型作为第一个也是唯一一个实参类型的函数的类型 void (std::map<int, char>). 最后, 在编译期用 arg1_type 元函数提取第一个实参的类型 function_traits, 从而从带括号的类型中还原出原始类型 (相当于剥去指定类型周围额外的括号).

参考

头文件 <boost/utility/identity_type.hpp>

用圆括号包裹类型表达式, 使其即使包含逗号也能传给宏.


BOOST_IDENTITY_TYPE(parenthesized_type)

宏 BOOST_IDENTITY_TYPE

BOOST_IDENTITY_TYPE —— 该宏允许把指定的类型表达式包裹在额外的圆括号内, 使该类型即使包含逗号 (且尚未被圆括号包裹) 也能作为单个宏参数传递.

概要

// In header: <boost/utility/identity_type.hpp>

BOOST_IDENTITY_TYPE(parenthesized_type)

说明

参数:

parenthesized_type要作为宏参数传递的类型表达式, 由一组圆括号 (...) 包裹. 该类型表达式可以包含任意数量的逗号.

该宏可在任何 C++03 编译器上工作 (它不使用变参宏).

在模板内使用时, 该宏必须以 typename 作为前缀. 请注意: 当函数模板参数被该宏包裹时, 编译器将无法自动确定它们 (这些参数需要在调用函数模板时显式指定).

在某些编译器上 (如 GCC), 对抽象类型使用该宏需要添加再移除一个对指定类型的引用.


[1] 若使用变参宏, 本可以只要求一组额外括号 BOOST_IDENTITY_TYPE(type) 而不是两组 BOOST_IDENTITY_TYPE((type)), 但变参宏不是 C++03 的一部分 (尽管如今大多数现代编译器都支持它们, 且它们也是 C++11 的一部分).

[2] 这是因为 BOOST_IDENTITY_TYPE 的实现把指定类型包裹在一个元函数内.

[3] 绝对无法保证该宏实际上是使用本文档所列代码实现的. 所列代码仅用于解释说明.
