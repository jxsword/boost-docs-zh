设计决策与标准偏离

C++14 要求

constexpr 支持

利用 C++14 放宽的 constexpr 定义, 本库几乎所有功能都可以是 constexpr. 这使 Boost.Decimal 能够更好地模拟内置类型所具有的功能.

Boost.Math 集成

Boost.Math 要求 C++14 作为本库的最低语言标准. 通过满足这一要求以及 Boost.Math 对用户自定义类型的概念要求, 我们能够开箱即用地提供统计、插值、求积等功能.

IEEE 偏离

<cmath> 函数不符合正确舍入的定义

IEEE 754 对正确舍入的规定: "本标准把无限精度结果转换为浮点数的方法, 由适用的舍入方向决定. 如此获得的浮点数称为正确舍入的." 这些函数都不符合正确舍入的定义 (这将意味着 0.5 ULP 的精度). 引用 Intel libdfp README: "例如在 C 或其他编译器数学库中实现的二进制浮点数学函数通常也不是正确舍入的". 严格来说, IEEE 754 在第 5 条中区分了强制运算 (例如 fma、sqrt 等) 的规范, 在第 9 条中区分了推荐运算 (例如 exp、log 等) 的规范, 但我们关于半 ULP 精度的说明适用于所有非布尔结果 <cmath> 函数. 这不适用于 isnan 等具有布尔结果的第 5 条函数, 因为 ULP 精度不适用.

不支持浮点异常标志

在 C++ 中设置和获取当前浮点异常标志的常规方法是通过 std::fegetexceptflag 与 std::fesetexceptflag. 于是决策变成了: 我们是支持 constexpr 还是浮点异常? 我们认为前者远比后者有用. 另一种选择是使用 C 风格的函数, 例如:

decimal64_t dec64_add(decimal64_t a, decimal64_t b, rounding_mode round, int* floating_point_flags);

这种函数风格用于 Intel libdfp, 因为它是一个 C 库. 我们认为这对现代 C++ 库来说既不符合习惯用法也不符合人体工学.

C++ 标准偏离

from_chars 区分上溢与下溢

std::from_chars 在 LWG 有一个未决议题: https://cplusplus.github.io/LWG/lwg-active.html#3081. <charconv> 标准不像 strtod 那样区分下溢与上溢. 为了以偏离标准的方式向用户传达这一点, boost::decimal::from_chars 修改了 value. 这一行为与 boost::charconv::from_chars_erange 相同.

from_chars 支持舍入模式

C++ 规范规定 from_chars 所得值应舍入到最近. 由于本库中的类型对舍入模式差异更敏感, from_chars 使用 fegetround() 报告的当前全局舍入模式进行舍入.

from_chars 与 to_chars 都有一个额外的 chars_format 选项

为了支持 IEEE 754 关于打印值时包含其群组信息的要求, 我们引入了一个额外的 chars_format 选项 cohort_preserving_scientific. 群组保留只在科学格式下有意义, 因为它才是类型布局的实际表示, 因此不支持其他保留群组的格式.

istream 非有限值是允许的

与内置二进制浮点类型不同, 本库允许输入非有限值, 如下所示:

std::istringstream is("INF");
decimal32_t x;
is >> x;
const auto endpos {is.tellg()};

assert(isinf(x));
assert(endpos == 3);

tellg() 的结果只会解析到找到完整的非有限值为止, 然后终止. 例如 nanfinity 将构造一个 NAN 并设置 endpos = 3, 或者 nan(snan)JUNK 将构造 SNAN 并设置 endpos = 9, 因为 nan(snan) 包含有效载荷. 这样设计是为了匹配 r.ptr 在 <charconv> 中的值.

不支持本地化刻面

N2849 第 3.10 节讨论的刻面尚未实现.
