本库提供了多个接口, 使用户在使用 Pool 时具有极大的灵活性. 请阅读 concepts 文档以基本了解各种池的工作方式.

术语与权衡

对象用法与 Singleton 用法

对象用法是每个 Pool 都是一个可创建和销毁的对象的方式. 销毁一个 Pool 会隐式释放从其分配的所有内存块.

Singleton 用法是每个 Pool 都是具有静态存储期的对象的方式; 即在程序退出之前它不会被销毁. 采用 Singleton 用法的 Pool 对象可以被共享; 因此, Singleton 用法也意味着线程安全. 采用 Singleton 用法的 Pool 对象所分配的系统内存可以通过 release_memory 或 purge_memory 释放.

内存不足情形: 异常与空返回

某些 Pool 接口在内存不足时抛出异常; 其他接口则会 return 0. 一般而言, 除非标准强制要求, Pool 接口总是倾向于 return 0 而不是抛出异常.

有序与无序

有序池按每个空闲块的地址顺序维护其空闲列表 - 如果你可能分配对象数组, 这是最有效率的方式. 但是, 释放一个对象在当前空闲块数量上可能是 O(N) 的, 在某些情况下开销可能大得无法承受.

无序池不按任何特定顺序维护其空闲列表, 因此分配和释放单个对象非常快, 但分配数组可能较慢 (特别是, 池可能意识不到它已包含足够的空闲内存来满足分配请求, 从而不必要地分配更多内存).

pool

pool 接口是一个简单的带空返回的对象用法接口.

pool 是一个快速的内存分配器, 并保证所有已分配内存块的正确对齐.

pool.hpp 提供了两个 UserAllocator 类和一个 template class pool, 后者对 简单分隔存储 方案提供的框架进行了扩展与泛化. 有关其他基于池的接口的信息, 请参见其他 Pool 接口.

概要

提供了两个 UserAllocator 类. 它们都位于 pool.hpp 中.

模板参数 UserAllocator 的默认值始终是 default_user_allocator_new_delete.

struct default_user_allocator_new_delete
{
  typedef std::size_t size_type;
  typedef std::ptrdiff_t difference_type;

  static char * malloc(const size_type bytes)
  { return new (std::nothrow) char[bytes]; }
  static void free(char * const block)
  { delete [] block; }
};

struct default_user_allocator_malloc_free
{
  typedef std::size_t size_type;
  typedef std::ptrdiff_t difference_type;

  static char * malloc(const size_type bytes)
  { return reinterpret_cast<char *>(std::malloc(bytes)); }
  static void free(char * const block)
  { std::free(block); }
};

template <typename UserAllocator = default_user_allocator_new_delete>
class pool
{
  private:
    pool(const pool &);
    void operator=(const pool &);

  public:
    typedef UserAllocator user_allocator;
    typedef typename UserAllocator::size_type size_type;
    typedef typename UserAllocator::difference_type difference_type;

    explicit pool(size_type requested_size);
    ~pool();

    bool release_memory();
    bool purge_memory();

    bool is_from(void * chunk) const;
    size_type get_requested_size() const;

    void * malloc();
    void * ordered_malloc();
    void * ordered_malloc(size_type n);

    void free(void * chunk);
    void ordered_free(void * chunk);
    void free(void * chunks, size_type n);
    void ordered_free(void * chunks, size_type n);
};

示例: 

void func()
{
  boost::pool<> p(sizeof(int));
  for (int i = 0; i < 10000; ++i)
  {
    int * const t = p.malloc();
    ... // Do something with t; don't take the time to free() it.
  }
} // on function exit, p is destroyed, and all malloc()'ed ints are implicitly freed.

对象池

template class object_pool 接口是一个带空返回的对象用法接口, 但它知道为其分配内存块的对象的类型. 在销毁时, 从该 object_pool 分配的所有内存块都会调用其析构函数.

object_pool.hpp 提供了一个可用于快速高效内存分配的模板类型. 它还提供对未释放对象的自动析构.

有关其他基于池的接口的信息, 请参见其他 Pool 接口.

概要 

template <typename ElementType, typename UserAllocator = default_user_allocator_new_delete>
class object_pool
{
  private:
    object_pool(const object_pool &);
    void operator=(const object_pool &);

  public:
    typedef ElementType element_type;
    typedef UserAllocator user_allocator;
    typedef typename pool<UserAllocator>::size_type size_type;
    typedef typename pool<UserAllocator>::difference_type difference_type;

    object_pool();
    ~object_pool();

    element_type * malloc();
    void free(element_type * p);
    bool is_from(element_type * p) const;

    element_type * construct();
    // other construct() functions
    void destroy(element_type * p);
};

模板参数

ElementType

该模板参数是要分配/释放的对象类型. 它必须具有不抛出异常的析构函数.

UserAllocator

定义底层 Pool 从系统分配内存所使用的方法. 默认为 default_user_allocator_new_delete. 详见 __UserAllocator.

示例: 

struct X { ... }; // has destructor with side-effects.

void func()
{
  boost::object_pool<X> p;
  for (int i = 0; i < 10000; ++i)
  {
    X * const t = p.malloc();
    ... // Do something with t; don't take the time to free() it.
  }
} // on function exit, p is destroyed, and all destructors for the X objects are called.
Singleton 池

singleton_pool interface (位于 singleton_pool.hpp) 是一个带空返回的 Singleton 用法接口. 它与 pool 接口完全相同, 只是改用 Singleton 用法.

概要 

template <typename Tag, unsigned RequestedSize,
    typename UserAllocator = default_user_allocator_new_delete>
struct singleton_pool
{
  public:
    typedef Tag tag;
    typedef UserAllocator user_allocator;
    typedef typename pool<UserAllocator>::size_type size_type;
    typedef typename pool<UserAllocator>::difference_type difference_type;

    static const unsigned requested_size = RequestedSize;

  private:
    static pool<size_type> p; // exposition only!

    singleton_pool();

  public:
    static bool is_from(void * ptr);

    static void * malloc();
    static void * ordered_malloc();
    static void * ordered_malloc(size_type n);

    static void free(void * ptr);
    static void ordered_free(void * ptr);
    static void free(void * ptr, std::size_t n);
    static void ordered_free(void * ptr, size_type n);

    static bool release_memory();
    static bool purge_memory();
};

注释

底层池 p (由 singleton_pool 中的静态函数所引用) 实际上以下列方式声明, 使其:

  • 如果在 main() 开始之前和 main() 结束之后只有一个线程在运行, 则是线程安全的. singleton_pool 的所有静态函数都会同步它们对 p 的访问.
  • 保证在使用之前已构造, 因此上面概要中的简单静态对象实际上是不正确的实现. 为保证这一点, 实际实现要复杂得多.

注意 对每组不同的模板参数 (包括实现特有的参数), 都存在一个不同的底层池 p.

模板参数

Tag

Tag 模板参数允许存在不同的无界 singleton 池集合. 例如, pool 分配器使用两个 tag 类来确保两种不同的分配器类型永远不会共享同一个底层 singleton 池.

Tag 实际上从不被 singleton_pool 使用.

RequestedSize 要分配的内存块的请求大小. 该值作为构造函数参数传递给底层池. 必须大于 0.

UserAllocator

定义底层池从系统分配内存所使用的方法. 详见用户分配器.

示例: 

struct MyPoolTag { };

typedef boost::singleton_pool<MyPoolTag, sizeof(int)> my_pool;
void func()
{
  for (int i = 0; i < 10000; ++i)
  {
    int * const t = my_pool::malloc();
    ... // Do something with t; don't take the time to free() it.
  }
  // Explicitly free all malloc()'ed ints.
  my_pool::purge_memory();
}
pool_allocator

pool_allocator interface 是一个带异常的 Singleton 用法接口. 它构建在 singleton_pool 接口之上, 并提供一个符合标准分配器要求的类 (用于容器等).

引言

pool_alloc.hpp

提供两个可用于快速高效内存分配的模板类型. 这两个类型都满足标准分配器要求 [20.1.5] 以及 [20.1.5/4] 中的附加要求, 因此可用于标准容器或用户提供的容器.

有关其他基于池的接口的信息, 请参见其他 Pool 接口.

概要 

struct pool_allocator_tag { };

template <typename T,
    typename UserAllocator = default_user_allocator_new_delete>
class pool_allocator
{
  public:
    typedef UserAllocator user_allocator;
    typedef T value_type;
    typedef value_type * pointer;
    typedef const value_type * const_pointer;
    typedef value_type & reference;
    typedef const value_type & const_reference;
    typedef typename pool<UserAllocator>::size_type size_type;
    typedef typename pool<UserAllcoator>::difference_type difference_type;

    template <typename U>
    struct rebind
    { typedef pool_allocator<U, UserAllocator> other; };

  public:
    pool_allocator();
    pool_allocator(const pool_allocator &);
    // The following is not explicit, mimicking std::allocator [20.4.1]
    template <typename U>
    pool_allocator(const pool_allocator<U, UserAllocator> &);
    pool_allocator & operator=(const pool_allocator &);
    ~pool_allocator();

    static pointer address(reference r);
    static const_pointer address(const_reference s);
    static size_type max_size();
    static void construct(pointer ptr, const value_type & t);
    static void destroy(pointer ptr);

    bool operator==(const pool_allocator &) const;
    bool operator!=(const pool_allocator &) const;

    static pointer allocate(size_type n);
    static pointer allocate(size_type n, pointer);
    static void deallocate(pointer ptr, size_type n);
};

模板参数

T 第一个模板参数是要分配/释放的对象类型.

UserAllocator 定义底层 Pool 从系统分配内存所使用的方法. 详见用户分配器.

示例: 

void func()
{
  std::vector<int, boost::pool_allocator<int> > v;
  for (int i = 0; i < 10000; ++i)
    v.push_back(13);
} // Exiting the function does NOT free the system memory allocated by the pool allocator.
  // You must call
  //  boost::singleton_pool<boost::pool_allocator_tag, sizeof(int)>::release_memory();
  // in order to force freeing the system memory.
