类模板 object_pool

boost::object_pool — 一个可用于对对象进行快速高效内存分配的模板类. 它还提供对未释放对象的自动析构.

概要

// In header: <boost/pool/object_pool.hpp>

template<typename T, typename UserAllocator> 
class object_pool : protected boost::pool< UserAllocator > {
public:
  // types
  typedef T                                      element_type;     // ElementType. 
  typedef UserAllocator                          user_allocator;   // User allocator. 
  typedef pool< UserAllocator >::size_type       size_type;        // pool<UserAllocator>::size_type 
  typedef pool< UserAllocator >::difference_type difference_type;  // pool<UserAllocator>::difference_type 

  // construct/copy/destruct
  explicit object_pool(const size_type = 32, const size_type = 0);
  ~object_pool();

  // protected member functions
  pool< UserAllocator > & store();
  const pool< UserAllocator > & store() const;

  // protected static functions
  static void *& nextof(void *const);

  // public member functions
  element_type * malloc();
  void free(element_type *const);
  bool is_from(element_type *const) const;
  element_type * construct();
  template<typename Arg1, ...class ArgN> 
    element_type * construct(Arg1 &, ...ArgN &);
  void destroy(element_type *const);
  size_type get_next_size() const;
  void set_next_size(const size_type);
};

说明

T 要分配/释放的对象类型. T 必须具有不抛出异常的析构函数.

UserAllocator 定义底层 Pool 从系统分配内存所使用的分配器. 详见 用户分配器.

类 object_pool 是一个可用于对对象进行快速高效内存分配的模板类. 它还提供对未释放对象的自动析构.

当对象池被销毁时, 会对每个尚未释放的已分配 T 调用类型 T 的析构函数. O(N).

每当类型为 ObjectPool 的对象需要从系统获取内存时, 它都会向其 UserAllocator 模板参数发出请求. 请求量由倍增算法确定; 即每次分配更多系统内存时, 请求的系统内存量都会翻倍. 用户可以通过传递给 object_pool 构造函数的参数来控制这一倍增算法.

object_pool 公有构造/复制/析构

  1. explicit object_pool(const size_type arg_next_size = 32, 
                     const size_type arg_max_size = 0);

    构造一个新的 ObjectPool (默认为空).

    要求:

    next_size != 0. 

  2. ~object_pool();

object_pool 受保护成员函数

  1. pool< UserAllocator > & store();

    返回:

    *this 所使用的底层 boost:: pool 存储.

    		 
  2. const pool< UserAllocator > & store() const;

    返回:

    *this 所使用的底层 boost:: pool 存储.

object_pool 受保护的静态函数

  1. static void *& nextof(void *const ptr);

    返回:

    ptr 之后的下一个内存块 (为提高代码可读性 :)

object_pool 公有成员函数

  1. element_type * malloc();

    分配可容纳一个 ElementType 类型对象的内存.

    若内存不足, 则返回 0.

    摊还 O(1).

  2. void free(element_type *const chunk);

    释放保存一个 ElementType 类型内存块的内存.

    注意 p 不得为 0.

    注意不会调用 p 的析构函数. O(N).

  3. bool is_from(element_type *const chunk) const;

    如果该内存块是从其他池分配的, 或可能作为未来从其他池分配的结果而返回, 则返回 false.

    否则, 返回值毫无意义.

    注释

    此函数不可用于可靠地测试随机指针值!

    返回:

    如果该内存块是从 *this 分配的, 或可能作为未来从 *this 分配的结果而返回, 则为 true.

    		 
  4. element_type * construct();

    返回:

    指向 T 类型对象的指针, 从底层池的内存中分配并默认构造. 返回的对象可通过调用 destroy 释放. 否则, 当 *this 被销毁时, 返回的对象将被自动销毁.

    		 
  5. template<typename Arg1, ...class ArgN> 
  element_type * construct(Arg1 &, ...ArgN &);

    注释

    由于此函数的参数数量与类型完全任意, 我们建立了一套简单的系统来自动生成模板 construct 函数. 该系统基于宏预处理器 m4, 它是 UNIX 系统上的标准工具, 也可用于 Win32 系统.

    detail/pool_construct.m4 与 m4 一起运行时, 会生成文件 detail/pool_construct.ipp, 其中仅为正确的参数数量定义 construct 函数. 参数数量可作为 m4 宏 NumberOfArguments 传入该文件; 若未提供, 则默认为 3.

    对每个不同的参数数量 (1 到 NumberOfArguments), 都会生成一个模板函数. 模板参数的数量与实参数量相同, 且每个实参的类型是对相应 (可能带 cv 限定) 模板实参的引用. cv 限定的每种可能排列也都会生成.

    由于对每个可能的参数数量都会生成每种排列, 所包含文件的大小随构造函数参数数量呈指数增长, 而非线性增长. 为了保证合理的编译时间, 只使用所需的参数数量即可.

    另外还提供了 detail/pool_construct.bat 与 detail/pool_construct.sh, 用于调用 m4, 并将 NumberOfArguments 定义为其命令行参数. 更多细节参见这些文件.

    返回:

    指向 T 类型对象的指针, 从底层池的内存中分配, 并由实参 Arg1 到 ArgN 构造. 返回的对象可通过调用 destroy 释放. 否则, 当 *this 被销毁时, 返回的对象将被自动销毁.

    		 
  6. void destroy(element_type *const chunk);

    销毁一个由 construct 分配的对象.

    等价于:

    p->~ElementType(); this->free(p);

    要求:

    p 必须此前已通过调用 construct 从 *this 分配.

    		 
  7. size_type get_next_size() const;

    返回:

    下次内存耗尽时将分配的内存块数量.

    		 
  8. void set_next_size(const size_type x);

    设置下次内存耗尽时要分配的新内存块数量.

    参数:

    x

    期望的 next_size (不得为零).
