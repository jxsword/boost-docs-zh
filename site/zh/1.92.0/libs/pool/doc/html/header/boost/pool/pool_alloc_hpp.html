头文件 <boost/pool/pool_alloc.hpp>

与 C++ 标准库兼容的基于池的分配器.

该头文件提供了两个模板类型 - pool_allocator 与 fast_pool_allocator - 可与 C++ 标准库容器结合用于快速高效的内存分配.

这两个类型都满足标准分配器要求 [20.1.5] 以及 [20.1.5/4] 中的附加要求, 因此可用于标准容器或用户提供的容器.

此外, fast_pool_allocator 还提供了一个额外的分配函数和一个额外的释放函数:

Expression 返回类型 语义等价
PoolAlloc::allocate() T * PoolAlloc::allocate(1)  
PoolAlloc::deallocate(p) void PoolAlloc::deallocate(p, 1)  

typedef user_allocator 发布 UserAllocator 模板参数的值.

注释

如果分配函数内存不足, 它们将抛出 std::bad_alloc.

分配器所使用的底层 Pool 类型可通过 Singleton Pool 接口访问. pool_allocator 使用的标识标签是 pool_allocator_tag, fast_pool_allocator 使用的标签是 fast_pool_allocator_tag. 分配器的所有模板参数 (包括实现特有的参数) 都决定底层 Pool 的类型, 第一个参数 T 除外, 代之以使用其大小.

由于使用 T 的大小来确定底层 Pool 的类型, 相同大小的不同类型的分配器将共享同一个底层池. tag 类防止在 pool_allocator 与 fast_pool_allocator 之间共享池. 例如, 在 sizeof(int) == sizeof(void *) 的系统上, pool_allocator<int> 与 pool_allocator<void *> 将在同一个池上进行分配/释放.

如果在 main() 开始之前和结束之后只有一个线程在运行, 则两个分配器都是完全线程安全的.

编译器与 STL 说明

许多常见 STL 库在使用分配器时包含缺陷. 具体而言, 它们向 deallocate 函数传递空指针, 这被标准 [20.1.5 Table 32] 明确禁止. 若检测到这些库, PoolAlloc 会采用变通方案; 目前已针对以下库提供变通方案: 使用默认 (RogueWave) 库的 Borland C++ (Builder 与命令行编译器) 5 及更早版本, STLport (任意编译器) 4.0 及更早版本.

namespace boost {
  struct pool_allocator_tag;

  template<typename T, typename UserAllocator, typename Mutex, 
           unsigned NextSize, unsigned MaxSize> 
    class pool_allocator;

  template<typename UserAllocator, typename Mutex, unsigned NextSize, 
           unsigned MaxSize> 
    class pool_allocator<void, UserAllocator, Mutex, NextSize, MaxSize>;

  struct fast_pool_allocator_tag;

  template<typename T, typename UserAllocator, typename Mutex, 
           unsigned NextSize, unsigned MaxSize> 
    class fast_pool_allocator;

  template<typename UserAllocator, typename Mutex, unsigned NextSize, 
           unsigned MaxSize> 
    class fast_pool_allocator<void, UserAllocator, Mutex, NextSize, MaxSize>;
}
