摘要

QVM 是一个用于处理静态大小的四元数、向量和矩阵的泛型库. 特性:

  • 侧重于图形、电子游戏和仿真应用所需的 2、3 和 4 维运算.

  • 自由函数模板可作用于任何兼容的用户自定义四元数、向量或矩阵类型.

  • 使来自不同库的四元数、向量和矩阵类型能够安全地混用在同一个表达式中.

  • 在兼容的左值类型之间进行类型安全的映射, 不产生临时对象; 例如 transpose 是对元素访问的重映射, 而不是对矩阵做变换.

  • 只需 C++03.

  • 零依赖.

教程

四元数、向量、矩阵

开箱即用, QVM 定义了泛型而简单的 quat、vec 和 mat 类型. 例如, 下面的代码片段创建一个绕 X 轴旋转的四元数对象:

quat<float> rx = rotx_quat(3.14159f);

类似地, 可以按如下方式创建一个按给定向量平移的矩阵:

vec<float,3> v = {0,0,7};
mat<float,4,4> tr = translation_mat(v);

常用的四元数、向量和矩阵运算都可以作用于这些 QVM 类型, 然而这些运算与任何特定类型解耦: 它们可作用于任何通过特化 quat_traits、vec_traits 和 mat_traits 模板注册过的合适类型.

例如, 一个用户自定义的 3D 向量类型 float3 可以按如下方式引入 QVM:

struct float3 { float a[3]; };

namespace boost { namespace qvm {

  template <>
  struct vec_traits<float3> {

    static int const dim=3;
    typedef float scalar_type;

    template <int I>
    static inline scalar_type & write_element( float3 & v ) {
      return v.a[I];
    }

    template <int I>
    static inline scalar_type read_element( float3 const & v ) {
      return v.a[I];
    }

    static inline scalar_type & write_element_idx( int i, float3 & v ) {
      return v.a[i];
    } //optional

    static inline scalar_type read_element_idx( int i, float3 const & v ) {
      return v.a[i];
    } //optional

  };

} }

等价地, 使用 vec_traits_defaults 模板, 上面的代码可以简化为:

namespace boost { namespace qvm {

  template <>
  struct vec_traits<float3>: vec_traits_defaults<float3,float,3> {

    template <int I>
    static inline scalar_type & write_element( float3 & v ) {
      return v.a[I];
    }

    static inline scalar_type & write_element_idx( int i, float3 & v ) {
      return v.a[i];
    } //optional

  };

} }

在对 mat_traits 模板为一个用户自定义的 3x3 矩阵类型 float33 做了类似特化之后, QVM 头文件定义的向量与矩阵运算的完整集合便自动可用:

float3 v;
X(v) = 0;
Y(v) = 0;
Z(v) = 7;
float vmag = mag(v);
float33 m = rotx_mat<3>(3.14159f);
float3 vrot = m * v;

用户自定义的四元数类型同样通过特化 quat_traits 模板引入 QVM.

为了支持无法以引用方式提供元素访问的向量类型, write_element / write_element_idx 静态成员函数可以定义为 void 函数, 接受一个标量并写入某个元素, 例如:

template <int I>
static inline void write_element( float3 & v, scalar_type s ) {
  v.a[I] = s;
}

Boost QVM 会自动检测提供的是哪一种形式.

C/C++ 数组

在 boost/qvm/quat_traits_array.hpp、vec_traits_array.hpp 和 mat_traits_array.hpp 中, QVM 定义了相应的 quat_traits、vec_traits 和 mat_traits 特化, 使 QVM 函数可以直接操作普通的老式 C 数组:

float v[3] = {0,0,7};
float3 vrot = rotx_mat<3>(3.14159f) * v;

自然, 如果表达式的所有元素都是内建类型, 运算符重载不会生效. 下面仍然是非法的:

float v[3] = {0,0,7};
v *= 42;

vref 和 mref 函数模板可以用来绕过这一问题:

float v[3] = {0,0,7};
vref(v) *= 42;

如果 C++-11 可用, 相同的头文件还会定义相应的 quat_traits、vec_traits 和 mat_traits, 用于 std::array 对象.

视图代理

QVM 定义了各种函数模板, 在(可能是用户自定义的)四元数、向量和矩阵类型之间提供静态映射. 下面的示例把矩阵 m 的第 1 列(QVM 索引始终从零开始)乘以一个标量:

void multiply_column1( float33 & m, float scalar ) {
  col<1>(m) *= scalar;
}

表达式 col<1>(m) 是一个未指明的 3D 向量类型的左值, 它引用 m 的第 1 列. 但请注意, 这不会创建任何临时对象; 相反, 上面的 operator*= 直接使用对 m 的引用进行工作.

下面是另一个示例, 把矩阵的转置视图乘以一个某用户自定义类型 float3 的向量:

float3 v = {0,0,7};
float3 vrot = transposed(rotx_mat<3>(3.14159f)) * v;

一般而言, 各种视图代理函数返回未指明的、不可复制类型的引用, 这些引用指向原始对象. 它们可以从任何兼容的向量或矩阵类型赋值, 或转换为这些类型.

Swizzling

QVM 允许通过 swizzling 访问向量元素, 暴露不同维度的向量视图, 和/或元素被重排的视图. 下面的示例把 v 绕 X 轴旋转, 并把结果向量存回 v, 但 X 和 Y 元素互换:

float3 v = {0,0,7};
YXZ(v) = rotx_mat<3>(3.14159f) * v;

swizzling 的一个特例为向量对象提供下一维度视图, 在其末尾添加 0 或 1 作为最后一个分量. 假设 float3 是 3D 向量类型, float4 是 4D 向量类型, 则以下语句是合法的:

float3 v = {0,0,7};
float4 point = XYZ1(v); //{0,0,7,1}
float4 vector = XYZ0(v); //{0,0,7,0}

swizzling 多次寻址同一个向量元素也是合法的:

float3 v = {0,0,7};
float4 v1 = ZZZZ(v); //{7,7,7,7}

QVM 为 1D、2D、3D 和 4D swizzling 定义了 X、Y、Z、W 的全部排列, 此外每个维度还定义了在任意位置使用 0 或 1 的变体 (如果 0 或 1 出现在第一个位置, swizzling 函数名以下划线开头, 例如 _1XY).

swizzling 语法还可以用来把标量绑定为向量. 例如:

float3 v = _00X(42.0f); //{0,0,42}

SFINAE/enable_if

SFINAE 是 Substitution Failure Is Not An Error (替换失败不是错误)的缩写. 它指的是 C++ 中这样一种情形: 模板参数的无效替换(包括作为非限定调用的结果而隐式推导这些参数时)本身并不构成错误.

在没有概念支持的情况下, SFINAE 可以用来禁用那些原本会呈现过于笼统签名的函数模板重载. 更正式地说, 这由 Boost enable_if 库提供支持.

例如, QVM 定义了 operator* 重载, 它可与任何用户自定义的矩阵和向量类型一起工作. 朴素的声明方式如下:

template <class Matrix,class Vector>
Vector operator*( Matrix const & m, Vector const & v );

即使函数定义中包含的代码只能对 Matrix 和 Vector 类型编译, 由于函数声明本身是有效的, 在对任意两种类型的对象做乘法时它都会参与重载决议. 这通常会使重载决议产生歧义, 编译器(正确地)报告错误.

通过使用 enable_if, QVM 以如下方式声明这类重载: 保留其泛型签名, 但仅当传入的参数依据所定义运算的语义有意义时才参与重载决议:

template <class A,class B>
typename enable_if_c<
  is_mat<A>::value && is_vec<B>::value && mat_traits<A>::cols==vec_traits<B>::dim, //Condition
  B>::type //Return type
operator*( A const & a, B const & b );

为简洁起见, 本文档中的函数声明只给出控制其是否被启用的条件, 而不具体说明使用什么 enable_if 构造来实现这一效果.

互操作性

QVM 的一个重要设计目标是, 它能与第三方四元数、向量和矩阵类型及库无缝协作. 即使这类库重载了与 QVM 相同的 C++ 运算符, 通过以下指定把整个 boost::qvm 命名空间引入作用域也是安全的:

using namespace boost::qvm;

上面的 using 指令不会与第三方库定义的函数和运算符重载产生歧义, 因为:

  • 大多数 boost::qvm 函数重载和全部运算符重载都使用了 SFINAE/enable_if, 这使得除非表达式使用了定义了适当 QVM 特定类型特征的类型, 否则它们会"消失";

  • 每当这类重载与给定表达式兼容时, 它们的签名都极其泛化, 这意味着任何其他(用户自定义的)兼容重载在任何重载决议中都会是更好的匹配.

把整个 boost::qvm 命名空间引入作用域, 在访问第三方库定义的类型(而非函数)时可能引入歧义. 在这种情况下, 你可以安全地改为把 boost::qvm::sfinae 命名空间引入作用域, 它只包含使用 SFINAE/enable_if 的函数和运算符重载.

为二元运算指定返回类型

把 boost::qvm 命名空间引入作用域, 可以让你把来自不同 API 的向量和矩阵类型混入一个共同的、类型安全的框架. 但在这种情况下, 应当考虑以值返回对象的二元运算应该返回什么类型. 例如, 如果你把 3x3 矩阵 m1 (类型为 user_matrix1) 与 3x3 矩阵 m2 (类型为 user_matrix2) 相乘, 该运算应该返回什么类型?

答案是, 默认情况下 QVM 返回某种兼容的矩阵类型, 所以这样写总是安全的:

auto & m = m1 * m2; // auto requires C++11

不过, 默认推导出的类型可以隐式转换为任何兼容的矩阵类型, 因此下面的写法也有效, 代价是一个临时对象:

user_matrix1 m = m1 * m2;

虽然许多编译器可以把临时对象优化掉, 但通过特化 deduce_mat2 模板可以完全避免它. 例如, 要指定 user_matrix1 与 user_matrix2 相乘总是产生 user_matrix1 对象, 可以这样写:

namespace boost { namespace qvm {

  template <>
  struct deduce_mat2<user_matrix1,user_matrix2,3,3> {
    typedef user_matrix1 type;
  };

  template <>
  struct deduce_mat2<user_matrix2,user_matrix1,3,3> {
    typedef user_matrix1 type;
  };

} }

在独立的库中使用 deduce_quat2、deduce_vec2 和 deduce_mat2 时, 要注意潜在的 ODR 违规. 例如, 如果 lib1 把 deduce_vec2<lib1::vec,lib2::vec>::type 定义为 lib1::vec, 而同一程序中 lib2 把 deduce_vec2<lib1::vec,lib2::vec>::type 定义为 lib2::vec, 就可能发生这种情况.

最好把这类特化放在 lib1 和 lib2 之外. 当然, lib1 和 lib2 随时都可以安全地使用 convert_to 在 lib1::vec 和 lib2::vec 类型之间按需转换.

为一元运算指定返回类型

可能令人意外的是, 以值返回对象的一元运算也有类似但更简单的问题. 这是因为调用它们时所用的参数可能不可复制, 如下:

float m[3][3];
auto & inv = inverse(m);

在上面的例子中, inverse 返回并由 inv 捕获的对象不能是 float[3][3] 类型, 因为该类型不可复制. 默认情况下 QVM "直接可用", 它返回一个可复制的适当矩阵类型的对象. 这一推导过程可以通过特化 deduce_mat 模板来控制.

在不同四元数、向量和矩阵类型之间转换

任何时候你需要从任何其他兼容的矩阵类型创建某个特定 C++ 类型的矩阵, 都可以使用 convert_to 函数:

user_matrix2 m=convert_to<user_matrix2>(m1 * m2);

类型特征系统

QVM 设计为可与用户自定义的四元数、向量和矩阵类型以及用户自定义的标量类型协作. 本节正式定义了集成此类类型的方式.

标量要求

有效的标量类型 S 必须具有可访问的析构函数、默认构造函数、拷贝构造函数和赋值运算符, 并且必须支持以下运算:

S operator*( S, S );
S operator/( S, S );
S operator+( S, S );
S operator-( S, S );

S & operator*=( S &, S );
S & operator/=( S &, S );
S & operator+=( S &, S );
S & operator-=( S &, S );

bool operator==( S, S );
bool operator!=( S, S );

此外, 表达式 S(0) 应构造值为零的标量, S(1) 应构造值为一的标量, 否则必须适当特化 scalar_traits 模板.

is_scalar

返回:

  • signed/unsigned long,

主 quat_traits 模板的成员未作规定. 有效的特化必须定义以下成员:

  • 如果 write_element_idx 被定义, write_element 也必须被定义.

  • scalar_type: 表达式 mat_traits<Matrix>::scalar_type 必须是满足标量要求的值类型.

此外, mat_traits 模板的有效特化可以把以下访问函数定义为静态成员, 其中 m 是类型为 Matrix 的对象, R 和 C 是编译期整数常量, r 和 c 是类型为 int 的变量:

  • read_element: 表达式 mat_traits<Matrix>::read_element<R,C>(m) 返回一份副本或一个 const 引用, 引用位于第 R 行、第 C 列的元素, 该元素属于 m.

  • read_element_idx: 表达式 mat_traits<Matrix>::read_element_idx(r,c,m) 返回一份副本或一个 const 引用, 引用位于第 r 行、第 c 列的元素, 该元素属于 m.

  • write_element: 表达式 mat_traits<Matrix>::write_element<R,C>(m) 返回一个可变引用, 指向位于第 R 行、第 C 列的元素, 该元素属于 m.

  • write_element_idx: 表达式 mat_traits<Matrix>::write_element_idx(r,c,m) 返回一个可变引用, 指向位于第 r 行、第 c 列的元素, 该元素属于 m.

或者, write_element 和 write_element_idx 可以定义为 void 函数, 它们接受(作为最后一个参数)一个标量并写入指定元素. QVM 通过检查 write_element 模板的签名自动检测这种情况.

除非 is_mat<Matrix>::value 为真, 否则调用上述任何函数都是非法的. 即便如此, 矩阵类型也允许只定义这些访问函数的一个子集. 总体要求是:

  • read_element 或 write_element 中至少一个必须被定义;

  • 如果 read_element_idx 被定义, read_element 也必须被定义;

  • 如果 write_element_idx 被定义, write_element 也必须被定义.

下面是一个用户自定义 3x3 矩阵类型及其相应的 mat_traits 模板特化的示例:

#include <boost/qvm/mat_traits.hpp>

struct float33 { float a[3][3]; };

namespace boost { namespace qvm {

  template <>
  struct mat_traits<float33> {

    static int const rows=3;
    static int const cols=3;
    typedef float scalar_type;

    template <int R,int C>
    static inline scalar_type & write_element( float33 & m ) {
      return m.a[R][C];
    }

    template <int R,int C>
    static inline scalar_type read_element( float33 const & m ) {
      return m.a[R][C];
    }

    static inline scalar_type & write_element_idx( int r, int c, float33 & m ) {
      return m.a[r][c];
    }

    static inline scalar_type read_element_idx( int r, int c, float33 const & m ) {
      return m.a[r][c];
    }

  };

} }

等价地, 我们可以使用 <<mat_traits_defaults,mat_traits_defaults 模板把上述代码简化为:

namespace boost { namespace qvm {

  template <>
  struct mat_traits<float33>: mat_traits_defaults<float33,float,3,3> {

    template <int R,int C> static inline scalar_type & write_element( float33 & m ) { return m.a[R][C]; }

    static inline scalar_type & write_element_idx( int r, int c, float33 & m ) {
      return m.a[r][c];
    }

  };

} }

mat_traits_defaults

#include <boost/qvm/mat_traits_defaults.hpp>
namespace boost { namespace qvm {

  template <class MatType,class ScalarType,int Rows,int Cols>
  struct mat_traits_defaults
  {
    typedef MatType mat_type;
    typedef ScalarType scalar_type;
    static int const rows=Rows;
    static int const cols=Cols;

    template <int Row,int Col>
    static BOOST_QVM_INLINE_CRITICAL
    scalar_type write_element( mat_type const & x ) {
      return mat_traits<mat_type>::template write_element<Row,Col>(const_cast<mat_type &>(x));
    }

    static BOOST_QVM_INLINE_CRITICAL
    scalar_type read_element_idx( int r, int c, mat_type const & x ) {
      return mat_traits<mat_type>::write_element_idx(r,c,const_cast<mat_type &>(x));
    }

    protected:

    static BOOST_QVM_INLINE_TRIVIAL
    scalar_type & write_element_idx( int r, int c, mat_type & m ) {
      /* unspecified */
    }
  };

} }

mat_traits_defaults 模板设计为用作 mat_traits 模板的用户自定义特化的公有基类, 以便轻松定义所需的成员. 如果使用它, 用户在 mat_traits 特化中唯一必须定义的成员是 write_element; mat_traits_defaults 基类会自动定义 read_element 以及 scalar_type、rows 和 cols.

此外, 用户还可以选择定义 write_element_idx, 此时 mat_traits_defaults 基类会自动提供合适的 read_element_idx 定义. 否则, mat_traits_defaults 会定义 write_element_idx 的一个受保护实现; 当为其特化的矩阵类型无法高效地按索引访问时, 派生的 mat_traits 特化可以把它公开. 这个 write_element_idx 函数效率较低(使用元编程实现), 它以必需的用户自定义 write_element 为基础实现.

要求:

  • is_mat<M,R,C,S>::value 为 true;

  • is_mat<deduce_mat<M,R,C,S>::type>::value 必须是 true;

YX(v) = v2;

上面的代码会让 Z 和 W 元素(属于 v)保持不变, 但会把 Y 元素(属于 v2)赋给 X 元素(属于 v), 并把 X 元素(属于 v2)赋给 Y 元素(属于 v).

最后, 标量也可以被"swizzle"为向量来访问: 表达式 _0X01(42.0f) 是一个 4D 向量, 其中 X=0、Y=42.0、Z=0、W=1.

#include <boost/qvm/quat_operations.hpp>
namespace boost { namespace qvm {

  //Only enabled if:
  //  is_quat<A>::value && is_quat<B>::value && is_scalar<C>
  template <class A,class B,class C>
  typename deduce_quat2<A,B> >::type
  slerp180( A const & a, B const & b, C c );

  //Only enabled if:
  //  is_quat<A>::value && is_quat<B>::value && is_scalar<C>
  template <class A,class B,class C>
  typename deduce_quat2<A,B> >::type
  slerp360( A const & a, B const & b, C c );

  //Only enabled if:
  //  is_quat<A>::value && is_quat<B>::value && is_scalar<C>
  template <class A,class B,class C>
  typename deduce_quat2<A,B> >::type
  slerp( A const & a, B const & b, C c ) // Deprecated
    {
    return slerp360(a, b, t);
    }

} }
前置条件:

t>=0 && t<=1.

返回:

一个四元数, 它是对四元数 a 和 b 以及插值参数 c 做球面线性插值的结果. 当 slerp 作用于单位四元数时, 四元数路径以标准方式映射为穿过 3D 旋转的路径. 其效果是绕固定旋转轴以均匀角速度进行的旋转.

当 a 和 b 所表示的旋转相隔超过 180 度时, slerp180 总是走球面上较短的路径, 而 slerp360 则不会. 两种行为都有相应的用例, 因为它们各自在不同条件下会引入不连续性.

从数学上讲:

auto q = slerp180(a, b, t);

等价于

auto q = slerp360(dot(a, b) < 0 ? -a : a, b, t);
QVM 的先前版本只实现了 slerp360 行为, 但使用的是名称 slerp. 出于兼容性考虑这一名称仍然保留, 但 slerp 现已弃用. 请使用 slerp180 或 slerp360.

BOOST_QVM_STATIC_ASSERT
#include <boost/qvm/static_assert.hpp>
namespace boost { namespace qvm {

  #ifndef BOOST_QVM_STATIC_ASSERT
  #include <boost/static_assert.hpp>
  #define BOOST_QVM_STATIC_ASSERT BOOST_STATIC_ASSERT
  #endif

} }

QVM 中的所有静态断言都使用 BOOST_QVM_STATIC_ASSERT 宏.

THROW_EXCEPTION

BOOST_QVM_THROW_EXCEPTION
#include <boost/qvm/throw_exception.hpp>
namespace boost { namespace qvm {

  #ifndef BOOST_QVM_THROW_EXCEPTION
  #include <boost/throw_exception.hpp>
  #define BOOST_QVM_THROW_EXCEPTION BOOST_THROW_EXCEPTION
  #endif

} }

每当 QVM 抛出异常时都会使用该宏. 覆盖标准 BOOST_QVM_THROW_EXCEPTION 行为的用户必须确保: 被调用时, 替换后的实现不会把控制权返回给调用者. 下面是调用 BOOST_QVM_THROW_EXCEPTION 的所有 QVM 函数的列表:

  • 四元数运算:

    • inverse

    • rot_quat

    • normalize

    • normalized

  • 向量运算:

    • normalize

    • normalized

  • 矩阵运算:

    • inverse

    • rot_mat

设计原理

C++ 是 3D 图形以及其他需要 3D 变换的领域的理想语言: 定义向量和矩阵类型, 然后重载适当的运算符以实现标准的代数运算. 由于这相对直接, 因此有许多库都这样做, 各自提供自定义的向量和矩阵类型, 然后为这些类型定义相同的运算(例如矩阵乘法).

这些库往往是更高层系统的一部分. 例如, 电子游戏程序员通常在渲染引擎中使用一套向量/矩阵类型, 而在物理仿真引擎中使用另一套.

QVM 通过把标准代数函数与其操作的类型解耦, 在所有这些不同的类型和 API 之间提供互操作性——同时不损害类型安全. 这些运算可作用于任何已特化了适当特征的类型. 使用 QVM, 无须在不同的四元数、向量或矩阵类型之间做转换; 它们可以在同一个表达式中安全而高效地混用.

这一设计使 QVM 能够在编译期生成类型和适配器, 与任何其他 QVM 类型或用户自定义类型兼容. 例如, 转置矩阵不需要存储结果: 它既不修改其参数也不返回新对象, 而是通过一个生成的类型绑定原矩阵对象, 该类型会在访问元素时即时重映射.

此外, QVM 还有助于在性能关键之处选择性地优化个别类型或运算以获得最高性能. 例如, 用户可以针对特定类型重载特定运算, 或者定义高度优化的、可能是平台特定的或因某些原因难以使用的类型, 然后在程序中性能不关键的部分把它们与更易用的类型混合搭配.

代码生成器

虽然 QVM 定义了作用于任意静态维度的矩阵和向量类型的泛型函数, 它还提供了一个代码生成器, 可用于创建兼容的头文件, 针对特定维度定义这些函数的简单得多的特化版本. 这在调试时很有用, 因为生成的代码比充满模板元编程的泛型实现容易读得多. 它对优化器也可能更友好.

代码生成器是一个命令行实用程序. 其源代码位于 boost/libs/qvm/gen 目录. 它被用来生成随 QVM 一起发布的以下头文件:

  • 2D、3D 和 4D 矩阵运算:

    • boost/qvm/gen/mat_operations2.hpp (大小为 2x2、2x1 和 1x2 的矩阵, 由 boost/qvm/mat_operations2.hpp 包含)

    • boost/qvm/gen/mat_operations3.hpp (大小为 3x3、3x1 和 1x3 的矩阵, 由 boost/qvm/mat_operations3.hpp 包含)

    • boost/qvm/gen/mat_operations4.hpp (大小为 4x4、4x1 和 1x4 的矩阵, 由 boost/qvm/mat_operations4.hpp 包含)

  • 2D、3D 和 4D 向量运算:

    • boost/qvm/gen/v2.hpp (由 boost/qvm/vec_operations2.hpp 包含)

    • boost/qvm/gen/v3.hpp (由 boost/qvm/vec_operations3.hpp 包含)

    • boost/qvm/gen/v4.hpp (由 boost/qvm/vec_operations4.hpp 包含)

  • 2D、3D 和 4D 向量-矩阵运算:

    • boost/qvm/gen/vm2.hpp (由 boost/qvm/vec_mat_operations2.hpp 包含)

    • boost/qvm/gen/vm3.hpp (由 boost/qvm/vec_mat_operations3.hpp 包含)

    • boost/qvm/gen/vm4.hpp (由 boost/qvm/vec_mat_operations4.hpp 包含)

  • 2D、3D 和 4D 向量 swizzling 运算:

    • boost/qvm/gen/sw2.hpp (由 boost/qvm/swizzle2.hpp 包含)

    • boost/qvm/gen/sw3.hpp (由 boost/qvm/swizzle3.hpp 包含)

    • boost/qvm/gen/sw4.hpp (由 boost/qvm/swizzle4.hpp 包含)

任何此类生成的头文件都必须在包含相应的泛型头文件之前包含. 例如, 如果你创建了一个头文件 boost/qvm/gen/m5.hpp, 那么它必须在 boost/qvm/mat_operations.hpp 被包含之前包含. 不过, 泛型头文件 (boost/qvm/mat_operations.hpp、boost/qvm/vec_operations.hpp、boost/qvm/vec_mat_operations.hpp 和 boost/qvm/swizzle.hpp) 已经包含上面列表中的生成头文件, 因此不需要手动包含生成头文件.

boost/qvm/gen 下的头文件不属于 QVM 的公共接口. 例如, 不应直接包含 boost/qvm/gen/mat_operations2.hpp; 应改为包含 #include <boost/qvm/mat_operations2.hpp>.

已知的怪癖与问题

捕获视图代理: auto

按照设计, 视图代理 不得返回临时对象. 它们返回的是对其按 (const) 引用接受的某个参数的引用, 该引用被转换为一种不可复制的未指明类型的引用. 因此, 视图代理的返回值无法用 auto 按值捕获:

auto tr = transposed(m); //Error: the return type of transposed can not be copied.

对视图代理使用 auto 的正确方式是:

auto & tr = transposed(m);
许多视图代理不是只读的, 也就是说, 它们是左值; 在视图代理上所做的修改会作用于原始对象. 这也是它们不能用 auto 按值捕获的另一个原因.

从不相关的命名空间绑定 QVM 重载

命名空间 boost::qvm 中的运算符重载被设计为与用户自定义类型协作. 通常, 通过 using namespace boost::qvm 让这些运算符在使用它们的命名空间中可用就足够了. 如果使用该运算符的作用域不受用户控制, 就会出现问题. 例如:

namespace ns1 {

  struct float2 { float x, y; };

}

namespace ns2 {

  using namespace boost::qvm;

  void f() {
    ns1::float2 a, b;
    a==b; //OK
    ns1::float2 arr1[2], arr2[2];
    std::equal(arr1,arr1+2,arr2); //Error: operator== is inaccessible from namespace std
  }

}

在上面的 std::equal 表达式中, 尽管 boost::qvm::operator== 在命名空间 ns2 中已可见——这得益于 using namespace boost::qvm——但调用源自命名空间 std. 在这种情况下, 编译器无法绑定 boost::qvm::operator==, 因为通过 ADL 只有命名空间 ns1 可见, 而它不包含合适的声明. 解决办法是在命名空间 ns1 中声明 operator==, 可以这样做:

namespace ns1 {

  using boost::qvm::operator==;

}

以 int 参数调用数学函数时的链接错误

QVM 不直接调用标准数学函数(例如 sin、cos 等). 相反, 它调用在 boost/qvm/math.hpp 中声明的、位于命名空间 boost::qvm 的函数模板. 这允许用户为用户自定义的标量类型特化这些模板.

QVM 本身只为 float 和 double 定义了数学函数模板的特化, 但不提供泛型定义. 这样做是为了保护用户, 避免无意中编写出这样的代码: 在传递较低类型的参数时, 绑定到接受 double 的标准数学函数, 那样做是次优的.

因此, 例如调用 rot_mat(axis,1) 会编译成功但链接失败, 因为它调用了例如 boost::qvm::sin<int>, 而后者是未定义的. 由于按整数弧度进行的旋转很少用到, QVM 对这类错误没有提供保护. 在这种情况下, 解决办法是改用 rot_mat(axis,1.0f).

Q&A

  1. QVM 背后的动机是什么? 为什么不直接使用 uBLAS/Eigen/CML/GLM 等?

    QVM 的主要领域是实时图形和仿真应用, 因此它不是一个完整的线性代数库. 虽然(自然地)它与这类库有一些重叠, 但 QVM 侧重于 2、3 和 4 维的零开销运算 (因此才有 Swizzling 这样的领域特定特性).

  2. qvm::vec (或 qvm::mat, 或 qvm::quat) 模板与其他库的向量类型相比如何?

    qvm::vec 模板与 QVM 定义的向量运算毫无中心关系. 这些运算被设计为可与任何用户自定义向量类型或第三方向量类型(例如 D3DVECTOR)协作, 而 qvm::vec 模板只是表达式的默认返回类型——这些表达式使用了在 QVM 之外互不兼容的不同类型的参数. 例如, 如果 deduce_mat2 未被特化, 调用 cross 时传入用户自定义类型 vec3 和用户自定义类型 float3, 将返回一个 qvm::vec.

  3. QVM 为什么不使用 [] 或 () 来访问向量和矩阵元素?

    因为它被设计为可与用户自定义类型协作, 而 C++ 标准要求这些运算符必须是成员. 当然, 如果用户自定义类型定义了 operator[] 或 operator(), 它们也可以与其他 QVM 函数一起使用, 但 QVM 为 访问四元数元素、访问向量元素 (以及 swizzling) 和 访问矩阵元素 定义了自己的机制.
