单元测试

Boost.Atomic 提供了一个单元测试套件来验证实现按预期工作:

  • atomic_api.cpp 和 atomic_ref_api.cpp 验证所有原子操作具有正确的值语义 (例如 "fetch_add" 确实加上期望的值并返回之前的值). 后者测试 atomic_ref 而非 atomic 和 atomic_flag. 它是一个粗略的 "冒烟测试", 用于排除最明显的错误 (如位宽溢出、有符号/无符号扩展等). 这些测试也在定义了 BOOST_ATOMIC_FORCE_FALLBACK 宏的情况下运行, 以测试基于锁池的实现.
  • lockfree.cpp 验证 BOOST_ATOMIC_*_LOCKFREE 宏是否按照对给定平台的期望正确设置, 以及它们是否与 atomic 对象实例的 is_always_lock_free 和 is_lock_free 成员相符.
  • atomicity.cpp 和 atomicity_ref.cpp 让两个线程相互竞争修改一个共享变量, 验证操作在适当时表现出原子性. 就其本质而言, 该测试必然是随机性的, 测试会自我校准, 使阳性结果以 99% 的置信度表明不存在错误. 该测试在已支持抢占的单处理器系统上非常有用.
  • ordering.cpp 和 ordering_ref.cpp 让两个线程相互竞争访问多个共享变量, 验证操作表现出预期的排序行为. 就其本质而言, 该测试必然是随机性的, 测试会尝试自我校准, 使阳性结果以 99% 的置信度表明不存在错误. 该测试只在真正的多处理器 (或多核) 系统上有效. 在单处理器系统或模拟器上不会产生任何结果 (因为即使在 order=relaxed 情形下也不存在可观察的重排), 并会报告这一事实.
  • wait_api.cpp 和 wait_ref_api.cpp 用于验证等待与通知操作的行为. 由于存在伪唤醒的可能, 若等待操作多次提前返回, 这些测试可能失败. 在这种情况下测试会重试几次, 但仍可能失败.
  • wait_fuzz.cpp 是针对等待与通知操作的模糊测试, 它创建若干线程阻塞在同一个原子对象上, 然后多次唤醒其中一个或全部线程. 该测试旨在作为冒烟测试, 以防实现存在长期的不稳定性或竞争 (主要是在锁池实现中).
  • ipc_atomic_api.cpp、ipc_atomic_ref_api.cpp、ipc_wait_api.cpp 和 ipc_wait_ref_api.cpp 与不带 ipc_ 前缀的测试类似, 但测试的是 IPC 原子类型.

已测试的编译器

本库要求 C++11 (或更高) 编译器. Boost.Atomic 已在以下编译器/平台上测试并确认可用:

  • gcc 4.6 及更新版本: i386、x86_64、ppc32、ppc64、sparcv9、armv6、alpha
  • clang 3.5 及更新版本: i386、x86_64
  • Windows 10 及更高版本上的 Visual Studio 2015 (MSVC-14.0) 及更新版本: x86、x64、ARM
  • Windows 10 及更高版本上的 MinGW-w64 gcc 8.1.0: x86、x86_64. 注意: 由于 MinGW-w64 上的 Windows SDK 头文件默认将 _WIN32_WINNT 定义为较旧的 Windows 版本, 你可能需要定义 _WIN32_WINNT=0x0A00 或 BOOST_USE_WINAPI_VERSION=0x0A00, 当编译 Boost.Atomic 及使用 Boost.Atomic 的代码时.
