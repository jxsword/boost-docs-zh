引用计数

实现
用法
讨论

引用计数器 的目的是统计指向某个对象的指针数量. 一旦引用计数器达到零, 该对象即可被销毁.

实现 

#include <boost/intrusive_ptr.hpp>
#include <boost/atomic.hpp>

class X {
public:
  typedef boost::intrusive_ptr<X> pointer;
  X() : refcount_(0) {}

private:
  mutable boost::atomic<int> refcount_;
  friend void intrusive_ptr_add_ref(const X * x)
  {
    x->refcount_.fetch_add(1, boost::memory_order::relaxed);
  }
  friend void intrusive_ptr_release(const X * x)
  {
    if (x->refcount_.fetch_sub(1, boost::memory_order::release) == 1) {
      boost::atomic_thread_fence(boost::memory_order::acquire);
      delete x;
    }
  }
};

用法 

X::pointer x = new X;

讨论

增加引用计数总是可以用 memory_order::relaxed 完成: 对对象的新引用只能从现有引用产生, 而把现有引用从一个线程传递到另一个线程必须已经提供了所需的全部同步.

重要的一点是强制: 在一个线程中对对象的任何可能访问 (通过现有引用) 必须 happen before 另一个线程中对该对象的删除. 这通过在放弃一个引用之后执行 "release" 操作 (通过该引用对对象的任何访问显然必须先于此发生), 以及在删除对象之前执行 "acquire" 操作来实现.

使用 memory_order::acq_rel 作为 fetch_sub 操作也是允许的, 但这会在引用计数尚未达到零时造成不必要的 "acquire" 操作, 并可能带来性能损失.

自旋锁 的目的是防止多个线程并发访问共享数据结构. 与互斥量不同, 线程会忙等待并浪费 CPU 周期, 而不是把 CPU 让给另一个线程. 除非你确信自己理解其后果, 否则不要使用自旋锁.

实现 

#include <boost/atomic.hpp>

class spinlock {
private:
  typedef enum {Locked, Unlocked} LockState;
  boost::atomic<LockState> state_;

public:
  spinlock() : state_(Unlocked) {}

  void lock()
  {
    while (state_.exchange(Locked, boost::memory_order::acquire) == Locked) {
      /* busy-wait */
    }
  }
  void unlock()
  {
    state_.store(Unlocked, boost::memory_order::release);
  }
};

用法 

spinlock s;

s.lock();
// access data structure here
s.unlock();

讨论

自旋锁的目的是确保对共享数据结构的一次访问总是严格地 "happens before" 另一次访问. 在 lock/unlock 中使用 acquire/release 是保证这一排序所必需且充分的.

把 "lock" 操作写成如下形式也是正确的:

lock()
{
  while (state_.exchange(Locked, boost::memory_order::relaxed) == Locked) {
    /* busy-wait */
  }
  atomic_thread_fence(boost::memory_order::acquire);
}

然而这种 "优化" a) 无用, b) 实际可能有害: a) 由于线程将在被阻塞的自旋锁上不停地自旋, 它把 CPU 周期浪费在单纯的 "exchange" 操作上, 还是浪费在既无用 "exchange" 又无用 "acquire" 的操作上, 并没有区别. b) 在某些系统上, 不含通过 "acquire" 操作引入的任何内存同步指令的紧凑 "exchange" 循环会独占内存子系统, 降低其他系统组件的性能.

双重检查锁定模式的单例

实现
用法
讨论

双重检查锁定模式的单例 的目的是确保某个特定对象最多创建一个实例. 若已经创建了一个实例, 对现有对象的访问应尽可能轻量.

实现 

#include <boost/atomic.hpp>
#include <boost/thread/mutex.hpp>

class X {
public:
  static X * instance()
  {
    X * tmp = instance_.load(boost::memory_order::consume);
    if (!tmp) {
      boost::mutex::scoped_lock guard(instantiation_mutex);
      tmp = instance_.load(boost::memory_order::consume);
      if (!tmp) {
        tmp = new X;
        instance_.store(tmp, boost::memory_order::release);
      }
    }
    return tmp;
  }
private:
  static boost::atomic<X *> instance_;
  static boost::mutex instantiation_mutex;
};

boost::atomic<X *> X::instance_(0);

用法 

X * x = X::instance();
// dereference x

讨论

互斥量确保对象的实例至多被创建一次. instance 方法必须确保对对象的任何解引用严格地 "happens after" 在另一个线程中创建该实例. 在创建并初始化对象之后使用 memory_order::release, 以及在解引用对象之前使用 memory_order::consume, 提供了这一保证.

用 memory_order::acquire 代替 memory_order::consume 也是允许的, 但这提供了超出所需的更强保证, 因为只有依赖于该指针值的操作才需要排序.

无等待环形缓冲区

实现
用法
讨论

无等待环形缓冲区 提供一种机制, 将对象从一个单独的 "生产者" 线程传递给一个单独的 "消费者" 线程, 而不需要任何锁. 该数据结构上的操作是 "无等待" (wait-free) 的, 即每个操作在常数步内完成. 这使得该数据结构适合用于硬实时系统, 或用于与中断/信号处理器通信.

实现 

#include <boost/atomic.hpp>

template<typename T, size_t Size>
class ringbuffer {
public:
  ringbuffer() : head_(0), tail_(0) {}

  bool push(const T & value)
  {
    size_t head = head_.load(boost::memory_order::relaxed);
    size_t next_head = next(head);
    if (next_head == tail_.load(boost::memory_order::acquire))
      return false;
    ring_[head] = value;
    head_.store(next_head, boost::memory_order::release);
    return true;
  }
  bool pop(T & value)
  {
    size_t tail = tail_.load(boost::memory_order::relaxed);
    if (tail == head_.load(boost::memory_order::acquire))
      return false;
    value = ring_[tail];
    tail_.store(next(tail), boost::memory_order::release);
    return true;
  }
private:
  size_t next(size_t current)
  {
    return (current + 1) % Size;
  }
  T ring_[Size];
  boost::atomic<size_t> head_, tail_;
};

用法 

ringbuffer<int, 32> r;

// try to insert an element
if (r.push(42)) { /* succeeded */ }
else { /* buffer full */ }

// try to retrieve an element
int value;
if (r.pop(value)) { /* succeeded */ }
else { /* buffer empty */ }

讨论

该实现确保环形索引不会互相 "套圈" (lap-around), 以保证不会有元素丢失或被读取两次.

此外它还必须保证, 对 pop 中某个特定对象的读访问 "happens after" 其在 push 中被写入. 这通过以 "release" 写入 head_ 并以 "acquire" 读取它来实现. 反过来, 该实现还通过对 tail_ 使用适当的排序约束, 确保对某个特定环形元素的读访问 "happens before" 该元素被新值重写.

无锁多生产者队列

无锁多生产者队列 的目的是允许任意数量的生产者入队对象, 这些对象由单一消费者按 FIFO 顺序取出并处理.

实现 

template<typename T>
class lockfree_queue {
public:
  struct node {
    T data;
    node * next;
  };
  void push(const T &data)
  {
    node * n = new node;
    n->data = data;
    node * stale_head = head_.load(boost::memory_order::relaxed);
    do {
      n->next = stale_head;
    } while (!head_.compare_exchange_weak(stale_head, n, boost::memory_order::release));
  }

  node * pop_all(void)
  {
    T * last = pop_all_reverse(), * first = 0;
    while(last) {
      T * tmp = last;
      last = last->next;
      tmp->next = first;
      first = tmp;
    }
    return first;
  }

  lockfree_queue() : head_(0) {}

  // alternative interface if ordering is of no importance
  node * pop_all_reverse(void)
  {
    return head_.exchange(0, boost::memory_order::consume);
  }
private:
  boost::atomic<node *> head_;
};

用法 

lockfree_queue<int> q;

// insert elements
q.push(42);
q.push(2);

// pop elements
lockfree_queue<int>::node * x = q.pop_all()
while(x) {
  X * tmp = x;
  x = x->next;
  // process tmp->data, probably delete it afterwards
  delete tmp;
}

讨论

该实现通过以逆处理顺序构建对象的单链表, 保证所有入队的对象按其入队顺序被处理. 消费者原子地清空队列 (该操作不仅是无锁的, 还是无等待的) 并恢复正确顺序.

必须保证生产者对将入队对象的任何访问 "happens before" 消费者的任何访问. 这通过以 release 内存序将对象插入链表、并以 consume 内存序将其出队来保证. acquire 内存序无需用于 waitfree_queue::pop_all, 因为所涉及的所有操作都通过解引用依赖于该原子指针的值.
