变更日志

Boost 1.91

  • 修复了 thread_pause 在 PowerPC 上使用 Apple 编译器时的编译问题. (GH#79)

Boost 1.89

  • 在基于汇编的 x86、AArch32、AArch64 和 PPC 后端中加入了 TSAN 插桩. 这消除了使用 Boost.Atomic 进行线程同步的代码中的 TSAN 误报.
  • 按照 Boost 1.84 中的公告, 移除了对 Windows 10 之前 Windows 版本的支持.
    • 给 MinGW-w64 用户的提示. 由于 MinGW-w64 上的 Windows SDK 头文件默认将 _WIN32_WINNT 定义为较旧的 Windows 版本, 在编译 Boost.Atomic 及使用 Boost.Atomic 的代码时, 你可能需要定义 _WIN32_WINNT=0x0A00 或 BOOST_USE_WINAPI_VERSION=0x0A00.
  • 对 Windows CE 的支持已被弃用, 并将在未来的发布中移除.
  • 加入了对定时等待操作的支持.
  • 公开了 thread_pause 操作, 它可用作自旋循环中的退避手段. 在 thread_pause 中加入了对 PowerPC 的支持并改进了对 AArch64 的支持.
  • 移除了 BOOST_ATOMIC_NO_ATOMIC_FLAG_INIT 宏定义. 由于本库现在要求 C++11, BOOST_ATOMIC_FLAG_INIT 总是受支持.
  • 为原子枚举启用了位运算. 当枚举被用于实现位掩码时, 这会很有用.

Boost 1.87

  • 修复了内存重新分配时原子等待状态列表的初始化问题. (GH#72)

Boost 1.86

  • 在 OpenBSD 上改用 futex(2) 系统调用, 因为较新的 OpenBSD 版本已移除对 syscall(2) 的支持.

Boost 1.85

  • 在 RISC-V 上加入了对 pause 指令的支持. (PR#65)

Boost 1.84

  • 不再支持 C++03, 最低要求的语言版本为 C++11.
  • 加入了对精度降低的 x87 扩展双精度类型的支持, 该类型用于 FreeBSD 和 OpenBSD. (GH#14)
  • 对 Windows 10 之前版本的支持已被弃用, 并将在 Boost 1.87 中移除.

Boost 1.83

  • 修复了 atomic_ref 用于 const 限定类型时的编译问题. 注意, 即使是 const 限定的原子对象也仍必须位于可读写内存中. (GH#62)

Boost 1.82

  • 由于 Boost.Atomic 所使用的 Boost 库发生了变化, 对 C++03 的支持已被弃用. 从 Boost.Atomic 1.84 开始, C++11 将成为最低要求.
  • 在为支持 AVX 的 x86 目标编译时, 128 位原子加载与存储操作现在会使用向量指令.
  • 对于 32 位 x86 目标, 具有 memory_order_seq_cst 语义的 64 位原子加载与存储操作现在会发出一条内存序指令.
  • 移除了 Boost.Atomic 1.73 中已弃用的 atomic<T>::storage() 访问器和 atomic<T>::storage_type 类型. 建议用户改用 atomic<T>::value() 和 atomic<T>::value_type.

Boost 1.80

  • 改进了在 ARM、AArch32 和 AArch64 目标上字节序检查的可移植性. (GH#59)
  • 修复了在 C++17 模式下使用 MSVC 14.0 (Visual Studio 2015) 编译的问题. (GH#61)

Boost 1.79

  • 修复了针对通用 Windows 平台 (UWP) 的编译问题. (GH#54)
  • 加入了 BOOST_ATOMIC_NO_DARWIN_ULOCK 配置宏. 该宏影响 Darwin 系统上的编译, 并禁用基于 ulock 的等待与通知操作实现. 这有助于满足 Apple App Store 的要求. (GH#55)

Boost 1.78

  • 在 Android 上对非 IPC 的等待与通知操作使用进程本地 futex 操作.
  • 加入了对仅定义 SYS_futex_time64 系统调用的 Linux 目标 (如 riscv32) 的支持.
  • 加入了针对 clang 8 在 32 位 x86 目标上处理 64 位类型时 std::alignment_of 结果不正确问题的变通方案.
  • 为自 Mac OS 10.12、iOS 10.0、tvOS 10.0 或 watchOS 3.0 起的 Darwin 系统上的等待与通知操作加入了 ulock 后端. 该后端支持原生的 32 位进程本地等待与通知操作; 而自 Mac OS 10.15、iOS 13.0、tvOS 13.0 或 watchOS 6.0 起, 还支持 64 位进程本地操作以及 32 位和 64 位进程间操作.
  • 在 Windows 上, 修正了以 Windows 8 及更高版本为目标时 atomic-type::always_has_native_wait_notify 与相应能力宏之间的不一致. 本库现在会直接从公共头文件使用 WaitOnAddress 及相关 API, 并会因此要求用户链接 synchronization.lib, 如果用户通过定义 BOOST_USE_WINAPI_VERSION、_WIN32_WINNT 或类似宏而要求 Windows 8 或更高版本. 在支持自动链接的编译器 (如 MSVC) 上, 本库会自动链接.
  • 在提供清除填充位方法的编译器上, 加入了对带填充位类型的支持 (联合类型除外). gcc 11 和 MSVC 14.2 (编译器版本 19.27) 及更新版本支持该特性, 支持类似内置函数的其他编译器亦然. 在不允许清除填充位的编译器上, 带填充的类型通常仍不受支持, 但 x86 目标上的 80 位 long double 除外. 新定义了 BOOST_ATOMIC_NO_CLEAR_PADDING 能力宏, 用于指示何时支持清除填充.
  • atomic_ref 和 ipc_atomic_ref 的初始化构造函数不再使用原子指令清除被引用对象中的填充位. 这降低了原子引用构造的开销. 这被认为是安全的, 因为清除填充不会对构成对象值的字节发出写入. 不过, 某些线程安全检查软件可能会将其误判为数据竞争.
  • atomic 和 ipc_atomic 的初始化构造函数现在对枚举、类和浮点类型是 constexpr 的. 对于类和浮点类型, 当以下条件满足时, 这些构造函数是 constexpr 的: 编译器支持 constexpr std::bit_cast、该类型没有填充字节、且实现原生原子操作无需填充 (即, 对 atomic<T> 而言, T 类型的对象恰好完全装入原子的内部存储).
  • 按照 C++20, atomic 和 ipc_atomic 的默认构造函数现在会对所含对象执行值初始化. 对于没有用户定义默认构造函数的类型, 这意味着默认构造的原子对象将被零初始化.
  • 加入了针对 AIX 上汇编工具不支持数字标签所导致编译错误的变通方案. (PR#50)
  • 加入了针对 Update 3 之前的 Visual Studio 2015 编译错误的变通方案. (GH#52)

Boost 1.77

  • 加入了 make_atomic_ref 和 make_ipc_atomic_ref 工厂函数, 用于构造原子引用对象.
  • 为 atomic_ref 和 ipc_atomic_ref 加入了 C++17 模板实参推导指引, 以便在模板实参可从构造函数实参推导出来时省略它们.

Boost 1.76

  • 修复了使用 MSVC for ARM 编译的问题. (PR#49)

Boost 1.75

  • 实现了用于内部锁池实现的地址查找算法的 SSE2 和 SSE4.1 版本. 这可能改善高度争用情况下等待与通知操作的性能.
  • 修复了 AArch64 目标上由为带立即数的位运算 (逻辑运算) 生成错误指令所导致的可能编译错误. (GH#41)

Boost 1.74

  • 加入了 const 限定符, 补齐 atomic_ref 中部分操作所缺失的限定符.
  • 在 ARMv8-A 上加入了对 yield 指令的支持. 该指令在自旋循环内部使用, 以降低 CPU 功耗.
  • 加入了对 C++20 等待与通知操作的支持. 实现包括涉及内部锁池的通用后端, 以及针对 Windows、Linux、FreeBSD、DragonFly BSD 和 NetBSD 的专用后端. 原子类型提供了新方法 has_native_wait_notify、静态布尔常量 always_has_native_wait_notify 以及一组能力宏, 用于检测实现是否支持对给定类型的原生等待与通知操作.
  • 将 atomic_flag 的内部表示改为使用 32 位存储. 这使得某些平台上对 atomic_flag 的等待与通知操作更加高效.
  • 加入了对内部锁池大小的构建期配置支持. 用户可定义 BOOST_ATOMIC_LOCK_POOL_SIZE_LOG2 宏来指定锁池大小的以 2 为底的对数. 默认值为 8, 即锁池大小为 256, 高于上一版本所用的 64.
  • 加入了对专用于 进程间通信的一组新原子类型的支持: ipc_atomic_flag、ipc_atomic 和 ipc_atomic_ref. 建议用户将使用非 IPC 类型进行进程间通信的代码移植到新类型. 新类型提供与其非 IPC 对应物相同的操作集, 区别如下:
    • 大多数操作增加了一个前置条件: 对给定原子对象, is_lock_free 返回 true. 若编译期已知该前置条件不满足, 本库将发出编译期错误.
    • 所提供的所有操作都是地址无关的 (address-free), 即原子对象 (对于 ipc_atomic_ref 则是其引用的对象) 可以位于进程共享内存中, 或以多个不同地址映射到同一进程.
    • 新的 has_native_wait_notify 操作和 always_has_native_wait_notify 常量表示对原生进程间等待与通知操作的支持. 若不支持该能力, 这些操作将以忙循环实现, 效率较低, 但仍是地址无关的. 另有一组单独的能力宏用于指示这种支持.
  • 加入了 C++20 中引入的新的 atomic_unsigned_lock_free 和 atomic_signed_lock_free 类型. 这些类型分别表示无符号或带符号整数的原子对象类型, 它是无锁的, 并且最好对等待与通知操作有原生支持.
  • 为 ARMv8-A (AArch32 与 AArch64 两者) 加入了新的 gcc 汇编后端. 新后端用于实现编译器内置函数不支持的操作 (包括 AArch64 上的 128 位操作), 也可在编译器内置函数不可用时使用. 小端与大端目标均受支持. AArch64 后端支持 ARMv8.1 和 ARMv8.3 中定义的扩展.
  • 在基于 gcc 汇编块的旧式 ARM 后端 (该后端用于 ARMv7 及更旧目标) 中加入了对大端目标的支持. 此前后端假定小端内存布局, 这对 64 位操作有重要影响.
  • 通过使用 lock 前缀指令替代 mfence, 改进了 x86 上 seq_cst 存储与线程栅栏的性能. 这意味着这些操作不再影响非临时 (non-temporal) 存储, 而此前这也并未得到保证. 请使用专用指令和内置函数来为非临时内存访问排序.
  • 修复了 x86 目标上 80 位 long double 的能力宏在 128 位原子操作可用时仍未指示无锁操作的问题.
  • 修复了 Alpha 目标上 gcc asm 块的编译问题.
  • 在 gcc __sync* 内置函数后端中, 修复了大对象 (大于指针大小) 的存储与加载操作可能非原子的问题. 当前实现假定在现代所有体系结构上, 小对象都可以用单条指令原子地存储.

Boost 1.73

  • 实现了 C++20 的 atomic_ref. 参见 文档, 尤其是 注意事项一节.
  • 实现了 C++20 中引入的 atomic_flag::test 操作.
  • atomic<T> 现在应考虑 T 的对齐要求; 若这些要求高于 atomic 内部存储的对齐要求, 这会产生影响.
  • 加入了静态断言, 强制实施对值类型 T 的要求, 该类型与 atomic 和 atomic_ref 一起使用. 这应能禁止无效类型被用作原子类型.
  • 改进了内部锁池实现. 锁池更大, 且锁的选择会考虑原子对象的对齐, 这应能降低线程争用的可能性.
  • 修复了 8 位和 16 位实参上 bit_test_and_* 操作生成的错误 x86 代码. 其他体系结构不受影响.
  • 修复了 compare_exchange_* 操作中可能出现的非对齐内存访问, 该问题发生于 value_type 的对齐要求低于 atomic 内部存储的对齐要求时.
  • boost/atomic/atomic.hpp 不再包含 boost/atomic/atomic_flag.hpp 和 boost/atomic/fences.hpp, 而只定义 boost::atomic 类模板及相关 typedef. 请显式包含其他头文件, 或使用 boost/atomic.hpp 来包含 Boost.Atomic 的全部内容.
  • atomic<T>::storage() 访问器及关联的 atomic<T>::storage_type 类型已被弃用. 作为替代, 建议用户分别使用 atomic<T>::value() 和 atomic<T>::value_type. 用户可定义 BOOST_ATOMIC_SILENCE_STORAGE_DEPRECATION 以在过渡期间禁用弃用警告. 被弃用的部分将在未来发布中移除.
  • 移除了对 BOOST_ATOMIC_DETAIL_HIGHLIGHT_OP_AND_TEST 的支持. 该宏曾用于帮助过渡到 Boost.Atomic 1.67 中 *_and_test 操作更新后的返回值, 该版本比 1.73 早两年发布.

Boost 1.72

  • 加入了针对某些版本 libstdc++ 不将 __float128 视为浮点类型问题的变通方案.
  • 改进了与 clang-win 编译器的兼容性.

Boost 1.67

  • 破坏性变更: 将 Boost 1.66 加入的 (op)_and_test 操作的结果改为了相反值——若操作结果非零, 这些函数现在返回 true. 这与 Boost.Atomic 中的其他 test 方法以及 C++ 标准库保持一致. 用户可在编译其代码时定义 BOOST_ATOMIC_DETAIL_HIGHLIGHT_OP_AND_TEST, 以在每次使用被更改的函数时发出警告, 借此定位需要更新的代码. (GH#11)
  • C++2a 更新. 在支持作用域枚举的 C++11 编译器上, memory_order 枚举现在成为作用域枚举, 并包含名称更短的常量, 如 acquire、release 或 seq_cst (即用户可以使用 memory_order::acquire 代替 memory_order_acquire). 旧常量也为了向后兼容而保留. (P0439R0)
  • C++2a 更新. 加入了对浮点类型原子操作的实验性支持. 除通用操作外, 还支持 add、sub、negate 操作及其 fetch_(op) 和 opaque_(op) 版本. 无锁特性可用新的宏 BOOST_ATOMIC_FLOAT/DOUBLE/LONG_DOUBLE_LOCK_FREE 测试. 对浮点类型的支持是可选的, 可通过定义 BOOST_ATOMIC_NO_FLOATING_POINT 禁用. (P0020R6)
  • 加入了新的实验性操作:
    • negate_and_test 和 complement_and_test: 执行取负或按位取补, 并在结果非零时返回 true.
    • add、sub、negate、bitwise_and、bitwise_or、bitwise_xor、bitwise_complement 操作: 执行该运算并返回其结果.
  • 对于通用 atomic<T> 特化, 若 T 的默认构造函数是平凡的 (trivial), 则其默认构造函数现在也是平凡的.
  • atomic<T> 的内部实现已更新, 以避免源自带符号整数溢出的未定义行为. 按照 C++ 标准的要求, 本库内部使用带符号整数的二进制补码表示及相应的溢出规则. 目前, 本库要求原生带符号整数类型也使用二进制补码表示 (但溢出语义未定义).
  • 改进了 Clang 支持. 特别地, 修复了 DCAS 非无锁的问题, 以及 32 位 x86 上可能生成错误代码的问题.
  • 改进了 MinGW 支持. 对于最高至 4.6 的 gcc 版本, 修复了 x86 上 DCAS 的编译问题.
  • 在 x86 PIE 代码中, asm 块现在会保留 ebx 的值.

Boost 1.66

  • 实现了一组针对整数类型的实验性扩展原子操作:
    • fetch_negate、fetch_complement - 原子地将值替换为取负或按位取补后的值, 并返回原值
    • opaque_<op> - 等价于 fetch_<op>, 但不返回原值
    • <op>_and_test - 原子地应用 <op>, 并在结果为零时返回 true. 注释: 这些操作的结果在 Boost 1.67 中将改为相反值. 使用这些函数的代码将需要更新.
    • bit_test_and_set、bit_test_and_reset、bit_test_and_complement - 原子地设置、重置或取补指定比特, 并返回该比特的原值
  • 遵循 C++17 (P0558R1), 不再提供针对非对象类型指针的算术运算.
  • 同样遵循 C++17, 在适用时将 atomic<T>::value_type 和 atomic<T>::difference_type 成员 typedef 公开到用户代码.
  • 改进了与 gcc 7 的兼容性. 特别地, 在 x86-64 上使用 128 位操作应该不再需要链接 libatomic (编译器提供的库).

Boost 1.64

  • 修复了在 32 位 x86 上使用早于 4.7 的 gcc 版本及兼容编译器进行 64 位原子操作时可能生成错误代码的问题.

Boost 1.63

  • 为符合 C++17, 加入了静态常量 atomic<T>::is_always_lock_free. 该常量表明给定特化总是提供原子操作的无锁实现.
  • 改进了 Oracle Studio 在 x86 目标上的支持.

发布后说明:

  • 在 32 位 x86 上使用早于 4.7 的 gcc 版本及兼容编译器进行 64 位原子操作可能生成错误代码. 该问题已在 此提交中修复.

Boost 1.62

  • 改进了对 Oracle Studio 和 SPARC 的支持. 本库现在在 SPARCv8+ 上提供原生原子操作.

Boost 1.60

  • 强制实施 atomic<> 存储的正确对齐. 这应能修复在支持大于原生字长数据单元原子操作的平台上可能出现的问题. 这也可能改变含有 atomic<> 成员的用户数据结构的二进制布局.
  • 修复了使用 IBM XL C++ 编译器编译 PowerPC 的问题. 修正了 PowerPC 汇编中的内存栅栏.
  • 修复了使用 MSVC-8 for ARM 的编译问题.
  • 修复了在 x86-64 上使用 128 位原子操作时 gcc 4.4 的编译问题. (#10994)
  • 优化了 x86/x86-64 的一些 gcc 汇编块以减少所用寄存器数量. 这可能需要 binutils 2.10 或更高版本.

Boost 1.56

  • 本库经过重新设计. 除内部重构外, 还修复了各种缺陷, 包括特性测试宏的取值错误和整数溢出处理.
  • 更改了 memory_order 枚举的值. 具体取值不属于接口的一部分, 但若该枚举被用于用户的接口, 此更改可能潜在地破坏 ABI.
  • 实现了在 Windows x64 上配合 MSVC 的 128 位原子操作支持. 本库假定目标 CPU 中存在 cmpxchg16b 指令. 某些早期 AMD CPU 不支持该指令; 若要面向这些 CPU, 请定义 BOOST_ATOMIC_NO_CMPXCHG16B 宏.
  • 实现了配合 MSVC 的 Windows ARM 目标实验性支持.
  • 实现了配合 GCC 的 DEC Alpha 目标实验性支持.
  • 改进了 GCC 对 ARMv6 及更高版本的支持. 以汇编块而非基于 CAS 的循环实现了所有原子操作. 64 位操作在 ARMv7 上受支持.
  • 实现了对 BOOST_ATOMIC_FLAG_INIT 宏及 atomic_flag 静态初始化的可选支持. (#8158)
  • 修复了 SPARCv9 目标的编译问题. (#9446)
  • 修复了 PowerPC 目标的编译问题. (#9447)
  • 修复了 Clang 在 x86 和 x86-64 上的若干兼容性问题. (#9610, #9842)
  • 移除了 IA64 平台上 Windows 的专用代码.

Boost 1.55

  • 在 x86 目标上为 GCC、MSVC 及兼容编译器加入了对 64 位原子操作的支持. 当编译期已知目标 CPU 支持所需指令时, 该支持被启用.
  • 在 x86-64 目标上为 GCC 及兼容编译器加入了对 128 位原子操作的支持. 当编译期已知目标 CPU 支持所需指令时, 该支持被启用. 可用新的 BOOST_ATOMIC_INT128_LOCK_FREE 宏测试该支持是否可用.
  • 为 atomic<> 加入了更高效的实现, 其基于 GCC 4.7 起可用的 __atomic* 内置函数.
  • 加入了对更多 ARM v7 CPU 的支持, 改进了对 Thumb 2 的检测.
  • 在 GCC 及兼容编译器上加入了对 x32 (即带 32 位指针的 64 位 x86) 目标的支持.
  • 移除了对 Boost.Thread 的依赖.
  • 内部锁池现在包含恰当的填充与对齐, 以避免伪共享 (false sharing).
  • 修复了在 Windows 上使用 Intel 编译器的编译问题. 移除了在 Windows 上编译时内部宏的重复定义.
  • 进行了部分代码重构, 以便在可用时使用 C++11 特性.
