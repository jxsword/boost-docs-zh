Boost.Locale
处理日期、时间、时区与日历.

引言

标准 C、C++ 以及 Boost 库在处理日期与时间方面存在几个重要缺陷:

  1. 大多数提供日期运算的库最大的缺陷是它们只支持格里高利历. boost::date_time , std::tm , 以及 localtime 和 gmtime 等标准函数, 都假定使用格里高利历.
  2. 未提供本地一周起始日的信息.
    例如标准 C 与 C++ 库提供了 mktime 和 localtime, 但它们不会向用户提供一周第一天是哪一天的信息. 该信息取决于 locale: 在法国是周一, 在美国是周日.

Boost.Locale 提供通用的 date_time 与 calendar 类, 可对希伯来历、伊斯兰历、日本历等非格里高利历的日期与时间执行运算.

非 ICU 后端 仅支持格里高利历. 与 boost::date_time 不同, 它们完全感知本地一周的第一天. 因此, 若当前星期几为周一, 将"星期几"设置为周日, 在俄语或法语 locale 中会把实际日期向前移动 6 天, 而在美国和以色列 locale 中会向后移动 1 天.

处理日期与时间

  • boost::locale::calendar – 表示日历的通用信息, 与特定时间点无关. 例如, 可以获取特定日历中一个月的最大天数.
  • boost::locale::date_time – 表示一个时间点. 它由日历构造而来, 并允许对各种时间段进行操作.
  • boost::locale::period – 保存一组表示各种周期 (如月、年、日、小时) 的函数, 用于操作日期与时间. 你可以将周期相加、乘以整数、获取或设置它们, 或将它们加到 date_time 对象上.

例如:

using namespace boost::locale;
date_time now; // 创建 date_time 类, 其默认日历初始化为当前时间
date_time tomorrow = now + period::day();
cout << "Let's meet tomorrow at " << as::date << tomorrow << endl;
date_time some_point = period::year(1995) + period::january() + period::day(1);
// 将 some_point 的日期设为 1995-Jan-1.
cout << "The "<< as::date << some_point << " is the "
<< as::ordinal << some_point / period::day_of_week_local() << " day of the week" << endl;

可以通过将日期之差除以一个周期来计算日期间的差值:

date_time now;
cout << " There are " << (now + 2 * period::month() - now) / period::day() << " days "
"between " << as::date << now << " and " << now + 2*period::month() << endl;

也可以使用另一种语法 (较少的运算符重载)

date_time now;
cout << " There are " << period::day(now + period::month(2) - now) << " days "
"between " << as::date << now << " and " << now + period::month(2) << endl;

date_time – 提供成员函数 minimum 和 maximum, 用于获取特定时间下某个周期可能的最小值与最大值的信息.

例如, 二月的 maximum(period::day()) 为 28 (闰年为 29), 一月则为 31.

注释
对日历的假设务必非常小心. 例如, 希伯来历中闰年与平年的月数是不同的.

建议查看本库附带的 calendar.cpp 示例, 以了解如何使用这些类操作日期与时间.

要在各种日历日期之间转换, 可以通过 time 成员函数获取当前 POSIX 时间.

例如:

using namespace boost::locale;
using namespace boost::locale::period;
generator gen;
// 创建使用希伯来历与格里高利历 (默认) 的 locale.
std::locale l_hebrew=gen("en_US.UTF-8@calendar=hebrew");
std::locale l_gregorian=gen("en_US.UTF-8");
// 由字段创建格里高利日期
date_time greg(year(2010) + february() + day(5),l_gregorian);
// 将取自格里高利日期的时间点赋给 date_time
// 采用希伯来历的 date_time
date_time heb(greg.time(),l_hebrew);
// 现在可以查询年份了.
std::cout << "Hebrew year is " << heb / year << std::endl;

注释

非 ICU 后端支持与 mktime 和 localtime C 库函数相同的日期时间范围.

  • Unix 32 位: 1901 至 2038 年之间的日期
  • Unix 64 位: 自公元前 1 年起的日期
  • Windows: 自 1970 年起的日期. 若 time_t 为 32 位宽 (mingw), 则上限为 2038 年

时区

默认使用当前操作系统的时区, 但可以在多个不同层级修改时区:

  1. 日历层级: 在构造函数中创建新的 boost::locale::calendar 实例时可以指定时区.
  2. iostream 层级: 可以使用 as::time_zone 操纵器为 iostream 设置特定时区, 使所有日期与时间都以该时区表示
  3. 可以通过调用 boost::locale::time_zone::global(std::string const &) 指定默认全局时区. 该时区将成为新建 iostream 对象与日历实例的默认时区.
注释

非 ICU 后端 仅支持两类时区:

  1. 当前操作系统时区, 由 localtime 和 mktime 标准库函数处理 - 默认时区
  2. 格式为 "GMT+HH:MM" 的简单时区 - 使用相对 UTC 的固定偏移表示的时区, 不支持夏令时.

date_time 对象的 I/O 运算

写入一个 date_time 等价于:

  • 在流上应用 as::datetime 操纵器
  • 以数字形式写出 POSIX 时间, 该数字通过调用 date_time::time() 函数获取.
  • 恢复操纵器之前的效果.

例如以下代码:

using namespace boost::locale;
date_time now;
std::cout << now << std::endl;

输出类似如下内容 (使用默认格式):

2/3/2011 12:00 am

但如果需要改变默认行为 (例如只显示日期), 则需要使用特定的 iostream 操纵器来显示当前日期或时间.

例如:

using namespace boost::locale;
date_time now;
std::cout << as::date << now << std::endl;

输出类似如下内容:

2/3/2011

务必记住 date_time 对象总是在 iostream's locale 与时区的上下文中呈现和解析, 而不在特定 date_time 对象的上下文中.

问答

当我只需要格里高利历时, 为什么应使用 Boost.Locale 而不是 Boost.DateTime?

  • Boost.DateTime 是与 locale 无关的库, 忽略了一周第一天随 locale 而异的事实.
  • Boost.Locale 以感知时区的方式提供对日期与时间的统一访问. 它将时间表示为通用标量 - POSIX 时间, 并在此基础上构建日期、本地时间与时区处理.
    例如, 由于夏令时, date_time(some_time.time() + 3600) 可能不等于 some_time + hour().

为什么不使用 Boost.DateTime 的时区支持?

Boost.DateTime 的时区支持是有缺陷的. 时区无法用一张简单规则表表示, 夏令时并不仅取决于某月第 n 个星期几. 夏令时可能因年份、政治因素以及其他诸多原因而变化.

大多数现代操作系统 (Linux、*BSD、Mac OS X、OpenVMS) 和许多重要软件包 (ICU、Java、Python) 都使用所谓的 Olson 数据库来正确处理夏令时.

如果需要完整的时区数据库支持, 应使用 ICU 库.
