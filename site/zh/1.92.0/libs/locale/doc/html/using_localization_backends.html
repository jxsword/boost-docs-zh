Boost.Locale
使用本地化后端

默认情况下, Boost.Locale 使用 ICU 执行所有本地化和文本操作任务. 它是现有最强大的库, 但有时我们并不需要它的全部能力, 或者想减少对第三方库的依赖, 而 ICU 绝不是一个小型库.

Boost.Locale 提供了使用非 ICU 本地化后端的选项. 这些后端虽然通常功能较弱, 但往往已提供你所需要的一切: 消息格式化、货币、日期、时间、数字格式化、基本排序和大小写处理. 它们使用标准操作系统 API 或 C/C++ 库实现.

何时使用非 ICU 后端

有些情况下使用基于非 ICU 的本地化是合适的:

  • 嵌入式系统, ICU 库在其中非常庞大.
  • 只需要消息、日期和时间格式化以及基本排序等基本功能的应用程序, 对它们来说使用 ICU 这样的第三方库过于复杂.
  • 性能. ICU 是非常强大的库, 但通常比标准库慢. 有时使用更简单但更快的本地化后端更好.

非 ICU 后端

所有替代后端都有以下限制:

  • 仅支持格里高利历, 且其基于 mktime 函数的能力 (包括日期范围)
  • 没有边界分析.
  • 大小写处理非常简单, 基于单码点转换, 不过它们对 UTF-8 的处理仍然优于标准库.
  • 时区指定非常有限: 只能是本地时间或 "GMT+HH:MM" 格式的时区.
  • 没有百分比格式化, 也没有拼写式或序数数字格式化.
  • 除 winapi 后端外, 排序都限于单一级别, 与 strcoll 所做的类似.

std——标准 C++ 库后端

该本地化后端基于标准 C++ 库.

它在所有平台上都受支持, 但只有在标准库支持 "C" 和 "POSIX" 之外 locale 的平台上才真正有用: 使用 GCC 或 Intel 编译器的 Linux, 以及 MSVC 编译器.

它规避了标准库的一些常见缺陷, 例如数字格式化生成无效 UTF-8, 并且在 MSVC 下提供了原本缺失的 POSIX locale 名称和 UTF-8 支持.

当编译器和库确实提供良好的本地化支持时它非常有用, 例如 Linux 下的 GCC 或 Windows 下的 MSVC.

posix——POSIX 2008 C 库

该后端基于最新的 POSIX 2008 标准, 使用 newlocale、freelocale、strftime_l 等 POSIX API 函数. 它在 Linux 和 Mac OS X 平台上可用.

它提供简单而现成的本地化支持, 在 Mac OS X 上尤为显著, 因为 GCC 的 libstdc++ 不支持 locale.

注释
POSIX 后端仅支持 UTF-8、单字节和双字节编码.

winapi——Win32 API.

基于 Win32 API 的本地化后端提供了不错的 UTF-8/UTF-16 locale 支持. 它基于 GetLocaleInfoW、LCMapStringW、GetDateFormatW 等 Windows API 函数, 即使在通常在这方面有问题的 MinGW 和 Cygwin 平台上也能提供良好的本地化支持.

注释
  • 如果在 Windows 下使用 GCC 编译器, 需要 GCC-4.x 系列才能使用它, 不支持 GCC-3.4
  • 仅支持 UTF-8 作为窄 locale 编码、UTF-16 作为宽编码.

使用本地化后端

访问本地化后端通过 boost::locale::localization_backend_manager 类完成.

你可以创建自己的 boost::locale::localization_backend_manager——先通过 boost::locale::localization_backend_manager::global 静态成员函数取得全局后端, 再对其进行修改.

例如:

localization_backend_manager my = localization_backend_manager::global();
// 获取全局后端
my.select("std");
// 选择 std 后端作为默认
generator gen(my);
// 创建使用该后端的生成器.
localization_backend_manager::global(my);
// 全局设置该后端
generator gen2();
// 现在这个生成器将使用新的全局后端.

你还可以混合使用多个后端, 例如一种操作用 icu, 其余操作用 std:

localization_backend_manager my = localization_backend_manager::global();
// 获取全局后端
my.select("std");
// 为所有类别选择 std 后端作为默认
my.select("icu",boundary_facet);
// 为边界分析选择 icu 后端 (因为 \c std 不支持它)
