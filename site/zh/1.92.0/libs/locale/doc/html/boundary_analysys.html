基础

Boost.Locale 提供边界分析工具, 允许你把文本切分为字符、单词或句子. 它常用于寻找合适的换行位置.

注释
这可不是一件小事!
Unicode 码点与字符并不等价. 例如, 希伯来语单词 Shalom - "שָלוֹם" - 由 4 个字符和 6 个码点组成 (4 个基本字母和 2 个变音符号).
在某些语言 (如日语或汉语) 中, 单词可能不由空格字符分隔.

Boost.Locale 为边界分析提供了 2 个主要类:

  • boost::locale::boundary::segment_index - 保存文本中 segment 索引 (如单词、字符、句子) 的对象. 它通过迭代器提供对 segment 对象的访问.
  • boost::locale::boundary::boundary_point_index - 保存文本中边界点索引的对象. 它可以遍历 boundary_point 对象.

上述每个类都以迭代器类型作为模板参数. 这两个类的构造函数都接受:

  • 定义边界分析 boundary_type 的标志.
  • 定义待分析文本范围的迭代器对
  • 一个 locale 参数 (若未给出, 则使用全局 locale)

例如:

namespace ba=boost::locale::boundary;
std::string text= ... ;
std::locale loc = ... ;
ba::segment_index<std::string::const_iterator> map(ba::word,text.begin(),text.end(),loc);
boost::locale::boundary
该命名空间包含文本边界分析所需的全部操作.

每个类都实现了成员 begin()、end() 和 find(), 从而可以遍历文本中选定的 segment 或边界, 或者针对给定迭代器找出 segment 或边界的位置.

还提供了 ssegment_index 或 wcboundary_point_index 之类的便捷 typedef, 其中 "w"、"u16" 和 "u32" 前缀定义字符类型 wchar_t、char16_t 和 char32_t, 而 "c" 和 "s" 前缀定义使用的是 std::basic_string<CharType>::const_iterator 还是 CharType const *.

遍历 segment

基本迭代

文本 segment 分析使用 segment_index 类完成.

它提供返回 segment 对象的双向迭代器. segment 对象表示一对定义该 segment 的迭代器, 以及据以选中它的规则. 它可以自动转换为 std::basic_string 对象.

要执行边界分析, 我们先创建一个索引对象, 然后遍历它:

例如:

using namespace boost::locale::boundary;
boost::locale::generator gen;
std::string text="To be or not to be, that is the question."
// 使用全局 locale 为 token 迭代器创建文本映射.
ssegment_index map(word,text.begin(),text.end(),gen("en_US.UTF-8"));
// 打印所有 "单词" -- 单词边界的分块
for(ssegment_index::iterator it=map.begin(),e=map.end();it!=e;++it)
std::cout << "\""<< * it << "\", ";
std::cout << std::endl;

使用规则

可以使用 rule() 和 full_select() 成员函数自定义 segment 的选取.

默认情况下, segment_index 的迭代器返回由两个边界点界定的每个文本 segment, 而不论其选取方式如何. 因此在上面的示例中, 我们会看到 "." 或 " " 这样被当作单词的文本 segment.

使用 rule() 成员函数, 我们可以指定一个规则的二进制掩码, 用 word、line 和 sentence 边界规则来选取边界点.

例如, 调用

map.rule(word_any);
boost::locale::boundary::word_any
constexpr rule_type word_any

在开始迭代过程之前, 指定一个选取掩码, 获取: 数字、字母、假名字母和表意字符, 忽略所有与单词无关的字符, 如空白或标点符号.

于是代码:

using namespace boost::locale::boundary;
std::string text="To be or not to be, that is the question."
// 使用全局 locale 为 token 迭代器创建文本映射.
ssegment_index map(word,text.begin(),text.end());
// 定义一条规则
map.rule(word_any);
// 打印所有 "单词" -- 单词边界的分块
for(ssegment_index::iterator it=map.begin(),e=map.end();it!=e;++it)
std::cout <<"\""<< * it << "\", ";
std::cout << std::endl;

将打印:

"To", "be", "or", "not", "to", "be", "that", "is", "the", "question",

对于给定的 text="生きるか死ぬか、それが問題だ. " 以及 rule(word_ideo), 上面的示例将打印:

"生", "死", "問題",

可以使用 segment::rule() 成员函数确定 segment 被选中的原因. 返回值是规则的位掩码.

例如:

boost::locale::generator gen;
using namespace boost::locale::boundary;
std::string text="生きるか死ぬか、それが問題だ. ";
ssegment_index map(word,text.begin(),text.end(),gen("ja_JP.UTF-8"));
for(ssegment_index::iterator it=map.begin(),e=map.end();it!=e;++it) {
std::cout << "Segment " << *it << " contains: ";
if(it->rule() & word_none)
std::cout << "white space or punctuation marks ";
if(it->rule() & word_kana)
std::cout << "kana characters ";
if(it->rule() & word_ideo)
std::cout << "ideographic characters";
std::cout<< std::endl;
}

注意, 在决定是否包含某个 segment 时, 规则应用于该 segment 的结束边界. 在某些情况下这会导致意外的行为.

例如, 考虑如下文本:

Hello! How
are you?

假设我们想从文本中提取全部句子.

sentence 规则 有两个选项:

  • 在检测到句末终止符 (如 ".!?") 处切分文本: sentence_term
  • 在检测到句子分隔符 (如 "换行符") 处切分文本: sentence_sep

自然地, 要忽略句子分隔符, 我们会用 sentence_term 参数调用 segment_index::rule(rule_type v), 然后运行迭代器.

boost::locale::generator gen;
using namespace boost::locale::boundary;
std::string text= "Hello! How\n"
"are you?\n";
ssegment_index map(sentence,text.begin(),text.end(),gen("en_US.UTF-8"));
map.rule(sentence_term);
for(ssegment_index::iterator it=map.begin(),e=map.end();it!=e;++it)
std::cout << "Sentence [" << *it << "]" << std::endl;

出现这些 (可能出乎意料的) 结果, 是因为 "How\n" 仍被视为一个句子, 但它是由另一条规则选中的.

可以通过把 segment_index::full_select(bool) 设置为 true 来改变这一行为. 它会强制迭代器把当前 segment 与之前所有 segment 合并, 即使它们不符合所需规则.

于是我们添加这一行:

map.full_select(true);

放在 "map.rule(sentence_term);" 之后, 得到预期的输出:

Sentence [Hello! ]
Sentence [How
are you?
]

定位 segment

有时, 找到某个特定迭代器所指向的 segment 会很有用.

例如, 假设我们想找到用户点击的那个单词.

segment_index 为此提供了 find(base_iterator p) 成员函数.

该函数返回一个迭代器, 指向包含 p 的 segment.

例如:

text="to be or ";
ssegment_index map(word,text.begin(),text.end(),gen("en_US.UTF-8"));
ssegment_index::iterator p = map.find(text.begin() + 4);
if(p!=map.end())
std::cout << *p << std::endl;

将打印:

be
注释

如果迭代器位于某个 segment 内部, 则返回该 segment. 如果该 segment 不符合选取规则, 则返回请求位置之后第一个符合规则的 segment.

例如: 对 word 边界分析使用 word_any 规则时:

  • "t|o be or " 将指向 "to" - 迭代器位于 segment "to" 中间.
  • "to |be or " 将指向 "be" - 迭代器位于 segment "be" 开头.
  • "to| be or " 将指向 "be" - 迭代器未指向符合所需规则的 segment, 因此选取的下一个有效 segment 是 "be".
  • "to be or| " 将指向 end, 因为找不到有效的 segment.

遍历边界点

基本迭代

boundary_point_index 的接口与 segment_index 相似, 但角色不同. 它不返回文本块 (segment, 而是返回 boundary_point 对象, 表示文本中的一个位置 - 即用于遍历源文本 C++ 字符的基础迭代器. boundary_point 对象还提供 rule() 成员函数, 返回该边界被选中的原因, 即匹配的规则.

注释
文本的开头和结尾都被视为边界点, 因此即使是空文本也至少包含一个边界点.

让我们看一个从文本中选取前两个句子的示例:

using namespace boost::locale::boundary;
boost::locale::generator gen;
// 我们的文本示例
std::string const text="First sentence. Second sentence! Third one?";
// 创建一个索引
sboundary_point_index map(sentence,text.begin(),text.end(),gen("en_US.UTF-8"));
// 统计两个边界点
sboundary_point_index::iterator p = map.begin(),e=map.end();
int count = 0;
while(p!=e && count < 2) {
++count;
++p;
}
if(p!=e) {
std::cout << "First two sentences are: "
<< std::string(text.begin(),p->iterator())
<< std::endl;
}
else {
std::cout <<"There are less than two sentences in this "
<<"text: " << text << std::endl;
}

使用规则

与 segment_index 一样, boundary_point_index 也提供 rule(rule_type mask) 成员函数, 用于过滤我们感兴趣的边界点.

它允许设置 word、line 和 sentence 规则来过滤边界点.

让我们把上面的示例稍作修改:

// 我们的文本示例
std::string const text= "First sentence. Second\n"
"sentence! Third one?";

如果按原样对上述示例运行程序, 将得到:

First two sentences are: First sentence. Second

这并不是我们真正期望的结果, 因为 "Second\n" 被视为一个独立的句子, 由行分隔符 "Line Feed" 分隔出来.

不过, 我们可以设置规则 sentence_term, 迭代器将只使用由 ".!?" 之类句末终止符产生的边界点.

于是, 添加:

map.rule(sentence_term);

放在索引生成之后, 我们将得到期望的输出:

First two sentences are: First sentence. Second
sentence!

还可以使用 boundary_point::rule() 成员函数, 通过与适当的掩码比较来了解该边界点产生的原因.

例如:

using namespace boost::locale::boundary;
boost::locale::generator gen;
// 我们的文本示例
std::string const text= "First sentence. Second\n"
"sentence! Third one?";
sboundary_point_index map(sentence,text.begin(),text.end(),gen("en_US.UTF-8"));
for(sboundary_point_index::iterator p = map.begin(),e=map.end();p!=e;++p) {
if(p->rule() & sentence_term)
std::cout << "There is a sentence terminator: ";
else if(p->rule() & sentence_sep)
std::cout << "There is a sentence separator: ";
if(p->rule()!=0) // 若存在某条规则则打印
std::cout << "[" << std::string(text.begin(),p->iterator())
<< "|" << std::string(p->iterator(),text.end())
<< "]\n";
}

定位边界点

有时, 根据给定迭代器找到特定的边界点会很有用.

boundary_point_index 提供了 iterator find(base_iterator p) 成员函数.

它返回 p 上的边界点, 若 p 未指向合适的位置, 则返回紧跟 p 之后的位置.

例如, 对于单词边界分析:

  • 若基础迭代器指向 "to |be", 则返回的边界点将是 "to |be" (相同位置)
  • 若基础迭代器指向 "t|o be", 则返回的边界点将是 "to| be" (下一个有效位置)

例如, 若想选取特定边界点周围的 6 个单词, 可以使用如下代码:

using namespace boost::locale::boundary;
boost::locale::generator gen;
// 我们的文本示例
std::string const text= "To be or not to be, that is the question.";
// 创建一个映射
sboundary_point_index map(word,text.begin(),text.end(),gen("en_US.UTF-8"));
// 忽略空白字符
map.rule(word_any);
// 定义我们的任意点
std::string::const_iterator pos = text.begin() + 12; // "no|t";
// 获取搜索范围
sboundary_point_index::iterator
begin = map.begin(),
end = map.end(),
it = map.find(pos); // 查找一个边界
// 向后回退 3 个单词
for(int count = 0;count <3 && it!=begin; count ++)
--it;
// 保存起点
std::string::const_iterator start = *it;
// 向前走 6 个单词
for(int count = 0;count < 6 && it!=end; count ++)
++it;
// 确保我们在有效位置
if(it==end)
--it;
// 打印文本
std::cout << std::string(start,it->iterator()) << std::endl;

将打印:

 be or not to be, that
