Boost.Locale
Microsoft Windows 下的默认编码

所有现代操作系统都使用 Unicode.

  • Unix 操作系统家族默认使用 UTF-8 编码.
  • Microsoft Windows 已迁移到 Wide/UTF-16 API. 窄编码已被弃用, 操作系统原生 API 变成了所谓的 "Wide API"

由于两种方式截然不同, 编写可移植的感知 Unicode 的应用程序非常困难.

Boost Locale 完全支持窄与宽两种 API. 在 Windows 上默认字符编码假定为 UTF-8.

因此, 若操作系统的默认 locale 为 "English_USA.1252", 则 Windows 上 Boost.Locale 的默认 locale 将为 "en_US.UTF-8".

当创建的 locale 对象被全局安装后, 任何使用 std::codecvt 在窄 API 与原生宽 API 之间转换的库都能正确处理 UTF-8.

这类库的一个典型例子是 Boost.Filesystem v3.

例如

#include <boost/locale.hpp>
#include <boost/filesystem/path.hpp>
#include <boost/filesystem/fstream.hpp>
int main()
{
// 创建并安装全局 locale
std::locale::global(boost::locale::generator().generate(""));
// 让 boost.filesystem 使用它
boost::filesystem::path::imbue(std::locale());
// 现在配合 UTF-8 完全正常工作!
boost::filesystem::ofstream hello("שלום.txt");
}

但这种行为可能破坏那些假定当前编码为单字节编码 (如代码页 1252) 的既有软件.

boost::locale::generator 类有一个属性 use_ansi_encoding(), 可将行为改回旧方式, 并选择 ANSI 代码页作为默认系统编码.

因此, 当当前 locale 为 "English_USA.1252" 且 use_ansi_encoding 开启时, 默认 locale 将为 "en_US.windows-1252".

注释
winapi 后端不支持 ANSI 编码; 因此窄字符始终使用 UTF-8 编码.
