Boost.Locale
C++ 标准库本地化支持简介

熟悉标准 C++ locale

C++ 标准库提供了一种简单而强大的方式来提供特定于 locale 的信息. 它通过 std::locale 类实现, 该容器保存着与特定文化相关的全部所需信息, 例如数字格式化模式、日期时间格式化、货币、大小写转换等.

所有这些信息都由刻面提供, 它们是从 std::locale::facet 基类派生的特殊类. 这类刻面被装入 std::locale 类中, 使你能够提供关于 locale 的任意信息. std::locale 类为已安装的刻面维护引用计数, 并且可以被高效地复制.

每个安装到 std::locale 对象中的刻面都可以用 std::use_facet 函数获取. 例如, std::ctype<Char> 刻面提供了大小写转换规则, 因此可以这样把字符转换为大写:

std::ctype<char> const &ctype_facet = std::use_facet<std::ctype<char> >(some_locale);
char upper_a = ctype_facet.toupper('a');

locale 对象可以被注入到 iostream 中, 使其按该 locale 格式化信息:

cout.imbue(std::locale("en_US.UTF-8"));
cout << 1345.45 << endl;
cout.imbue(std::locale("ru_RU.UTF-8"));
cout << 1345.45 << endl;

将显示:

    1,345.45 1.345,45

你也可以创建自己的刻面, 并把它们安装到已有的 locale 对象中. 例如:

class measure : public std::locale::facet {
public:
typedef enum { inches, ... } measure_type;
measure(measure_type m,size_t refs=0)
double from_metric(double value) const;
std::string name() const;
...
};

现在你可以简单地把该信息提供给一个 locale:

std::locale::global(std::locale(std::locale("en_US.UTF-8"),new measure(measure::inches)));

现在可以按照正确的 locale 打印距离:

void print_distance(std::ostream &out,double value)
{
measure const &m = std::use_facet<measure>(out.getloc());
// 从流中获取 locale 信息
out << m.from_metric(value) << " " << m.name();
}

Boost.Locale 库采用了这一技术, 以提供强大而正确的本地化. 它没有使用功能非常有限的 C++ 标准库刻面, 而是在底层使用 ICU 来创建自己强大得多的刻面.

标准库的常见严重问题

标准库中存在大量使其无法发挥全部能力的问题, 另外还有以下几个问题:

  • 设置全局 locale 会带来不良副作用.
    考虑以下代码:
    int main()
    {
    std::locale::global(std::locale(""));
    // 将系统默认 locale 设为全局
    std::ofstream csv("test.csv");
    csv << 1.1 << "," << 1.3 << std::endl;
    }

    test.csv 的内容会是什么? 它可能是 "1.1,1.3", 也可能是 "1,1,1,3", 而不是你所期望的结果.
    不仅如此, 它甚至会影响 printf 以及 boost::lexical_cast 之类的库, 导致不正确或出乎意料的格式化. 事实上, 在这种情况下许多第三方库都会出问题.
    与标准本地化库不同, 即使使用基于 std 的本地化后端, Boost.Locale 也从不改变基本的数字格式, 因此默认情况下, 数字始终按 C 风格 locale 格式化. 本地化的数字格式化需要特定的标志.
  • 某些 locale 下的数字格式化是坏的.
    一些 locale 使用不换行空格 u00A0 字符作千位分隔符, 因此在 ru_RU.UTF-8 locale 中, 数字 1024 应显示为 "1 024", 其中的空格是码点为 u00A0 的 Unicode 字符. 遗憾的是, 许多库都不能正确处理它, 例如 GCC 和 SunStudio 会显示 "\xC2" 字符, 而不是表示该码点的 UTF-8 序列 "\xC2\xA0" 的首字符, 实际上生成了无效的 UTF-8.
  • locale 名称并未标准化. 例如, 在 MSVC 下你需要提供名称 en-US 或 English_USA.1252 , 而在 POSIX 平台上则是 en_US.UTF-8 或 en_US.ISO-8859-1
    不仅如此, MSVC 完全不支持 UTF-8 locale.
  • 许多标准库只提供 C 和 POSIX locale, 因此 GCC 仅在 Linux 下支持本地化. 在所有其他平台上, 尝试创建 "C" 或 "POSIX" 之外的 locale 都会失败.
