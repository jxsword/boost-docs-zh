构建 Boost.Locale

依赖

  • 使用 ICU 构建时需要 4.8.1 或更高版本的 ICU 库
  • 若未提供 ICU 库, 则 POSIX 平台上需要 iconv 支持.

平台说明

  • 在 MinGW gcc 下使用 Boost.Locale DLL 需要与运行库 libstdc++ 和 libgcc 动态链接. 一些 gcc 构建默认使用静态链接, 因此请确保使用正确的链接选项.
  • AIX 的 iconv 缺少 Boost.Locale 所需的重要字符集, 因此你需要使用 GNU iconv 或链接 ICU 库.
  • 如果在 Darwin/Mac OS X 构建中找不到 iconv 库, 请确保没有多个 iconv 安装, 并提供 -sICONV_PATH 构建选项以指向 iconv 库的正确位置.
    强烈建议使用 HomeBrew 安装的 GNU IConv!

构建过程

现在你只需调用 b2:

./b2 --with-locale stage

或在 Windows 上

.\b2 --with-locale stage

如果你使用自定义的 ICU 构建, 或者使用 Microsoft Windows, 则需要使用 -sICU_PATH 选项提供 ICU 库所在位置的路径

例如:

  • 如果你的 ICU 构建位于 /opt/icu48, 文件布局如下:
    /opt/icu48/include/unicode/uversion.h
    /opt/icu48/include/unicode/calendar.h
    ...
    /opt/icu48/lib/libicudata.so
    /opt/icu48/lib/libicui18n.so
    ...
    那么你需要提供选项 -sICU_PATH=/opt/icu48 
        ./b2 --with-locale -sICU_PATH=/opt/icu48  stage
  • 如果你的 ICU 构建位于 C:\icu48, 文件布局如下:
    C:\icu48\include\unicode\uversion.h
    C:\icu48\include\unicode\calendar.h
    ...
    C:\icu48\bin\icudt.dll
    C:\icu48\bin\icuin.dll
    ...
    C:\icu48\lib\icudt.lib
    C:\icu48\lib\icuin.lib
    ...
    那么你需要提供选项 -sICU_PATH=C:\icu48 
        .\b2 --with-locale -sICU_PATH=C:\icu48  stage
注释
使用 Microsoft Visual Studio 时, 别忘了把 ICU 库的 debug 和 release 两个版本都放进该路径, 这样 Boost.Build 才能正确链接 Boost.Locale 的 debug 和 release 版本.

构建选项

Boost.Locale 支持以下选项, 取值为 off 或 on

  • boost.locale.icu=off 即使 ICU 库存在也阻止构建 ICU 后端
  • boost.locale.iconv 启用或禁用 iconv 后端. 在 Windows 和 Solaris 上默认关闭
  • boost.locale.winapi=off 禁用 winapi 后端. 在 Windows 和 Cygwin 上默认开启
  • boost.locale.std 启用或禁用 std 后端. 使用 Sun Studio 时 std 后端默认禁用.
  • boost.locale.posix 启用或禁用 POSIX 后端支持. 在 Linux 和 Mac OS X 上默认开启

此外 Boost.Locale 还支持以下选项

  • -sICU_PATH=/path/to/location/of/icu - ICU 库的位置
  • -sICONV_PATH=/path/to/location/of/iconv - iconv 库的位置

例如:

  • 在 Windows 上仅以 ICU 后端构建库: 
        .\b2 boost.locale.winapi=off boost.locale.std=off -sICU_PATH=C:\icu48 --with-locale stage
  • 在 Linux 上仅以 std 后端构建库 
        ./b2 boost.locale.posix=off boost.locale.icu=off --with-locale stage

运行单元测试

你可以通过调用 b2 并附带 libs/locale/test 工程参数来运行单元测试

./b2 libs/locale/test

二进制兼容性

Boost.Locale 在构建时考虑了二进制兼容性. 打开或关闭本地化后端, 是否使用 iconv, 都不影响二进制兼容性. 因此, 如果某个动态库以所有可用后端构建, 其他仅以 std、posix 或 winapi 后端编译的动态库仍然与它二进制兼容.

使用二进制文件中未包含的功能会抛出异常. 例如, 当库不支持 ICU 后端时, 若你尝试使用边界分析或日历刻面, 将得到异常.
