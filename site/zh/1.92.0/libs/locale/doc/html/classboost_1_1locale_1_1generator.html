详细说明

用于 locale 生成的主要类

该类用于指定 locale 生成与缓存所需的全部参数. 若 locale 类的实现是线程安全的, 则该类的 const 成员函数也是线程安全的.

示例
boundary.cpp, calendar.cpp, collate.cpp, conversions.cpp, hello.cpp, wboundary.cpp, wconversions.cpp 和 whello.cpp.

◆ add_messages_domain()

void boost::locale::generator::add_messages_domain ( const std::string & domain)

添加一个新的要生成的消息域. 必须设置它才能启用消息支持.

消息域的格式如下: "name" 或 "name/encoding", 其中 name 是存储目录的 "mo" 文件的基本名 (不含 ".mo" 扩展名). 例如对于文件 /usr/share/locale/he/LC_MESSAGES/blog.mo, 它应为 blog.

你可以通过添加 "/encoding_name" 可选地指定源中键的编码. 例如 blog/cp1255.

若未定义, 则所有键都假定为 UTF-8 编码.

注释
使用 dgettext 或 message API 为程序选择域时, 不需要指定编码部分. 例如, 若提供的域名为 "blog/windows-1255", 则翻译时应使用 dgettext("blog","Hello")

◆ add_messages_path()

void boost::locale::generator::add_messages_path ( const std::string & path)

添加查找词典的搜索路径.

注释
  • 在 Windows 平台上, 路径按 locale 的编码处理, 因此如果你创建 locale "en_US.windows-1251", 路径将按 cp1255 处理; 若为 en_US.UTF-8, 则按 UTF-8 处理. 文件名始终以宽文件名打开, 因为宽文件名是 Windows 上的原生文件名.
  • 在 POSIX 平台上, 所有路径按原样传递, 不考虑编码, 因为窄编码是 POSIX 平台的原生编码.

◆ use_ansi_encoding()

void boost::locale::generator::use_ansi_encoding ( bool enc)

在 Windows 下选择 ANSI 编码作为默认系统编码, 而不是默认的 UTF-8.

默认是最可移植且最强大的编码 UTF-8, 但在处理旧应用程序时, 用户可以选择 "系统" 编码
