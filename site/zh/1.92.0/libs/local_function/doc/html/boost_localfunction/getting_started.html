本文档

读完引言、入门和教程章节后, 程序员应具备使用本库所需的足够知识. 进阶主题和参考章节可在后续查阅, 以更深入地了解本库. 本文档的所有其他章节均可视为可选内容.

一些脚注以"设计理由"一词标示. 它们解释本库设计与实现过程中所作决策背后的原因.

在本文档展示的大多数示例中, 使用 Boost.Detail/LightweightTest (boost/detail/lightweight_test.hpp) 宏 BOOST_TEST 来检查正确性条件. BOOST_TEST 宏在概念上类似于 assert, 但被检查条件失败时不会中止程序, 而是使 boost::report_errors 返回非零的程序退出码. [3]

编译器与平台

本库的实现使用预处理器元编程与模板元编程 (由 Boost.Preprocessor 和 Boost.MPL 支持)、带偏特化的模板和函数指针 (类似于 Boost.Function), 以及自动类型推导 (由 Boost.Typeof 支持). 作者最初在以下环境上开发和测试本库:

  1. GNU 编译器套件 (GCC) C++ 4.5.1, Ubuntu Linux 10.
  2. GCC 4.3.4 和 4.5.3 (分别启用与不启用 C++11 特性 -std=c++0x), Cygwin.
  3. Microsoft Visual C++ (MSVC) 8.0, Windows XP 和 Windows 7.

支持的编译器与平台的详细信息请见本库回归测试结果.

安装

本库仅由头文件组成. 因此没有需要安装或链接的预编译目标文件. 程序员只需告知 C++ 编译器在何处查找库头文件 (GCC 用 -I 选项, MSVC 用 /I 选项等), 即可开始编译使用本库的代码.

库实现使用 Boost.Typeof 自动推导被绑定变量的类型 (见教程章节). 要在 type-of 仿真模式下编译代码, 所有类型都应使用 BOOST_TYPEOF_REGISTER_TYPE 和 BOOST_TYPEOF_REGISTER_TEMPLATE 正确注册, 或者包含适当的 Boost.Typeof 头文件 (见本文档多数示例的源代码).

以下内容属于库的私有 API, 未被文档化, 程序员不应直接使用: [4]

  • boost/local_function/aux_/ 或 boost/local_function/detail/ 目录内文件定义的任何符号 (程序员不应直接包含这些头文件).
  • boost::local_function::aux 或 boost::local_function::detail 命名空间内的任何符号.
  • 以 boost_local_function_aux_... 或 boost_local_function_detail_... 为前缀的任何符号 (无论其命名空间).
  • 以 BOOST_LOCAL_FUNCTION_AUX_... 或 BOOST_LOCAL_FUNCTION_DETAIL_... 为前缀的任何符号 (无论其命名空间).

可以通过定义特殊的配置宏在编译期改变库的某些行为. 若配置宏未定义, 库会使用适当的默认值. 所有配置宏都定义在头文件 boost/local_function/config.hpp 中. 强烈建议除非确有必要, 否则不要更改库配置宏的定义.


[3] 设计理由. 使用 Boost.Detail/LightweightTest 可以把示例加入库回归测试, 确保它们始终能正确编译和运行.

[4] 设计理由. 本库把程序员指定的符号 (例如局部函数名) 与其他符号 (例如特殊前缀或文件行号) 拼接, 以构成名称唯一的内部符号, 避免名称冲突. 拼接时这些符号之间以字母 "X" 分隔, 便于调试时阅读 (不能用下划线字符 "_" 代替字母 "X", 因为若原始符号已含有前导或尾随下划线, 拼接可能产生双下划线符号 "__", 这被 C++ 标准保留). "aux" 符号是本库私有的; "detail" 符号可能被 Boost 中其他库使用, 但仍不属于本库的公共 API.
