GCC Lambda (不含 C++11)

把局部函数与 GCC 编译器非标准的 语句表达式 扩展结合, 即使没有 C++11 支持, 也可以为 GCC 编译器实现 lambda 函数.

警告

此代码只能在支持 GCC 语句表达式扩展或支持 C++11 lambda 函数 的编译器上工作.

例如 (另见 gcc_lambda.cpp 和 gcc_cxx11_lambda.cpp):

使用局部函数 (仅限 GCC)

C++11 Lambda

 

int val = 2;
int nums[] = {1, 2, 3};
int* end = nums + 3;

int* iter = std::find_if(nums, end,
    GCC_LAMBDA(const bind val, int num, return bool) {
        return num == val;
    } GCC_LAMBDA_END
);


int val = 2;
int nums[] = {1, 2, 3};
int* end = nums + 3;

int* iter = std::find_if(nums, end,
    [val](int num) -> bool {
        return num == val;
    }
);

GCC lambda 函数宏使用局部函数实现 (另见 gcc_lambda.hpp):

#   define GCC_LAMBDA_(binds, params, results) \
        ({ /* open statement expression (GCC extension only) */ \
        BOOST_LOCAL_FUNCTION( \
            BOOST_PP_LIST_ENUM(BOOST_PP_LIST_APPEND(binds, \
                BOOST_PP_LIST_APPEND(params, \
                    BOOST_PP_IIF(BOOST_PP_LIST_IS_NIL(results), \
                        (return void, BOOST_PP_NIL) /* default for lambdas */ \
                    , \
                        results \
                    )\
                ) \
            )) \
        )


#define GCC_LAMBDA_END_(id) \
    BOOST_LOCAL_FUNCTION_NAME(BOOST_PP_CAT(gcc_lambda_, id)) \
    BOOST_PP_CAT(gcc_lambda_, id); \
    }) /* close statement expression (GCC extension only) */

这是可能的, 因为 GCC 语句表达式允许在表达式内使用声明语句, 从而可以在表达式内声明局部函数. 这些宏会自动检测编译器是否支持 C++11 lambda 函数; 若支持, 实现会使用原生 lambda 而非 GCC 语句表达式中的局部函数. 但是, C++11 lambda 函数 不支持常量绑定, 因此最好只使用 const bind variable (等同于 =variable, 用于 C++11 lambda 函数) 和 bind& variable (等同于 &variable, 用于 C++11 lambda 函数'), 因为这些在局部函数实现与原生 lambda 实现之间具有完全相同的语义. 此外, 局部函数允许直接绑定数据成员, 而 C++11 lambda 函数 需要通过绑定对象 this 来访问数据成员. 遗憾的是, 简写绑定 & 和 = (C++11 lambda 函数 自动按引用或按值绑定作用域内所有变量) 不受这些 GCC lambda 函数宏支持, 因为局部函数也不支持它们. 最后, 结果类型 return result-type 是可选的, 未指定时假定为 void (与 C++11 lambda 函数 相同).

常量块

可以使用局部函数在相互之间检查被断言表达式内保持常量的变量. 这是有利的, 因为断言不应改变程序状态, 理想情况下编译器不会编译修改变量的断言.

例如, 考虑以下断言, 其中我们错误地把 operator= 编成了 operator==:

int x = 1, y = 2;
assert(x = y); // Mistakenly `=` instead of `==`.

理想情况下, 这样的代码将无法编译; 然而此示例不仅编译通过, 断言甚至通过了运行期检查, 没有产生任何错误. [N1613] 论文引入了 常量块 的概念, 可用于包裹上述断言并在编译期捕获这一编程错误. 类似地, 以下代码在错误地把 operator= 用作 operator== 时会产生编译期错误, 因为 x 和 y 在执行断言的代码块内都被 (使用局部函数) 变为常量 (另见 const_block_error.cpp):

使用局部函数

N1613 常量块

 

int x = 1, y = 2;
CONST_BLOCK(x, y) { // Constant block.
    assert(x = y);  // Compiler error.
} CONST_BLOCK_END


int x = 1, y = 2;
const {             // Constant block.
    assert(x = y);  // Compiler error.
}

常量块宏使用局部函数实现 (另见 const_block.hpp):

#define CONST_BLOCK_(variables) \
    void BOOST_LOCAL_FUNCTION( \
        BOOST_PP_IIF(BOOST_PP_LIST_IS_NIL(variables), \
            void BOOST_PP_TUPLE_EAT(3) \
        , \
            BOOST_PP_LIST_FOR_EACH_I \
        )(CONST_BLOCK_BIND_, ~, variables) \
    )


#define CONST_BLOCK_END_(id) \
    BOOST_LOCAL_FUNCTION_NAME(BOOST_PP_CAT(const_block_, id)) \
    BOOST_PP_CAT(const_block_, id)(); /* call local function immediately */

常量块宏使用一个按常量引用 const bind& 绑定所有指定变量的局部函数实现 (因此变量在代码块内是常量, 但它们不需要是 CopyConstructible, 也不执行额外拷贝). 该局部函数在其函数体内执行 assert 指令, 并在定义之后立即被调用. 更一般地, 常量块可用于在所有指定变量均为常量的代码块内求值任何指令 (不限于断言).

遗憾的是, 常量块无法用 C++11 lambda 函数 实现, 因为后者不支持常量绑定. 用 C++11 lambda 函数 按值绑定的变量 (variable, =variable 和 =) 是常量, 但它们必须是 CopyConstructible, 并且引入了可能代价高昂的拷贝操作. [29] 当然, 始终可以引入额外的常量变量并把它们绑定到 C++11 lambda 函数, 但常量块代码随后就必须管理这些额外变量的声明和初始化, 并且必须使用额外变量名而非原变量名:

int x = 1, y = 2;
const decltype(x)& const_x = x; // Constant so cannot be modified
const decltype(y)& const_y = y; // and reference so no copy.
[&const_x, &const_y]() {        // Lambda functions (C++11 only).
    assert(const_x = const_y);  // Unfortunately, `const_` names.
}();

在许多情况下, 使用额外常量变量 const_x 是可以接受的; 但在其他情况下, 在函数体内保持同一变量名 x 可能更可取.

作用域退出

作用域退出允许在外围作用域退出时执行任意代码, 它们由 Boost.ScopeExit 库提供.

出于好奇, 这里展示如何用局部函数重新实现作用域退出. 使用局部函数的作用域退出有一个小优点: 支持常量绑定. Boost.ScopeExit 不直接支持常量绑定 (不过, 总是可以引入一个额外的 const 局部变量, 把要绑定的值赋给它, 再绑定该 const 变量, 从而让 Boost.ScopeExit 也实现常量绑定).

注释

总体而言, 作者建议在可能的情况下使用 Boost.ScopeExit 而非本示例列出的代码 (因为 Boost.ScopeExit 是一个专门为支持作用域退出构造而设计的库).

以下示例按常量引用绑定 p, 因此该变量在作用域退出体内不能修改, 但它未被拷贝, 且其呈现的是外围作用域退出时的值, 而非作用域退出声明时的值 (另见 scope_exit.cpp):

使用局部函数

Boost.ScopeExit 

person& p = persons_.back();
person::evolution_t checkpoint = p.evolution_;

SCOPE_EXIT(const bind checkpoint, const bind& p, bind this_) {
    if (checkpoint == p.evolution_) this_->persons_.pop_back();
} SCOPE_EXIT_END


person& p = persons_.back();
person::evolution_t checkpoint = p.evolution_;

BOOST_SCOPE_EXIT(checkpoint, &p, this_) { // Or extra variable `const_p`.
    if (checkpoint == p.evolution_) this_->persons_.pop_back();
} BOOST_SCOPE_EXIT_END

作用域退出宏的实现方式是: 在构造以下类的对象时传入一个局部函数 (另见 scope_exit.hpp):

struct scope_exit {
    scope_exit(boost::function<void (void)> f): f_(f) {}
    ~scope_exit(void) { f_(); }
private:
    boost::function<void (void)> f_;
};


#   define SCOPE_EXIT(...) \
        void BOOST_LOCAL_FUNCTION(__VA_ARGS__)


#define SCOPE_EXIT_END_(id) \
    BOOST_LOCAL_FUNCTION_NAME(BOOST_PP_CAT(scope_exit_func_, id)) \
    scope_exit BOOST_PP_CAT(scope_exit_, id)( \
            BOOST_PP_CAT(scope_exit_func_, id));

外围作用域内的一个局部变量用于保存该对象, 因此析构函数会在外围作用域退出时被调用, 继而调用局部函数执行作用域退出指令. 作用域退出局部函数没有参数, 结果类型为 void, 但它支持绑定和常量绑定.

Boost.Phoenix 函数

局部函数可用于创建 Boost.Phoenix 函数. 例如 (另见 phoenix_factorial_local.cpp 和 phoenix_factorial.cpp):

局部函数

全局仿函数

 

int main(void) {
    using boost::phoenix::arg_names::arg1;

    int BOOST_LOCAL_FUNCTION(int n) { // Unfortunately, monomorphic.
        return (n <= 0) ? 1 : n * factorial_impl(n - 1);
    } BOOST_LOCAL_FUNCTION_NAME(recursive factorial_impl)

    boost::phoenix::function< boost::function<int (int)> >
            factorial(factorial_impl); // Phoenix function from local function.

    int i = 4;
    BOOST_TEST(factorial(i)() == 24);      // Call.
    BOOST_TEST(factorial(arg1)(i) == 24);  // Lazy call.
    return boost::report_errors();
}


struct factorial_impl { // Phoenix function from global functor.
    template<typename Sig>
    struct result;

    template<typename This, typename Arg>
    struct result<This (Arg)> : result<This (Arg const&)> {};

    template<typename This, typename Arg>
    struct result<This (Arg&)> { typedef Arg type; };

    template<typename Arg> // Polymorphic.
    Arg operator()(Arg n) const {
        return (n <= 0) ? 1 : n * (*this)(n - 1);
    }
};

int main(void) {
    using boost::phoenix::arg_names::arg1;

    boost::phoenix::function<factorial_impl> factorial;

    int i = 4;
    BOOST_TEST(factorial(i)() == 24);      // Call.
    BOOST_TEST(factorial(arg1)(i) == 24);  // Lazy call.
    return boost::report_errors();
}

此处介绍主要是出于好奇, 因为由局部函数创建的 Boost.Phoenix 函数有一个重要限制: 不能多态. [30] 因此, 在许多情况下, 从全局仿函数创建 Boost.Phoenix 函数 (可能借助 Boost.Phoenix 适配宏) 也许更有用.

GCC 嵌套函数

GCC C 编译器以 嵌套函数 的名义作为非标准扩展支持局部函数. 注意, 嵌套函数纯粹是 GCC 编译器的 C 扩展 (C++ 不支持, 即使 GCC 编译器也不支持; 它们不属于任何 C 或 C++ 标准, MSVC 等其他编译器也不支持).
