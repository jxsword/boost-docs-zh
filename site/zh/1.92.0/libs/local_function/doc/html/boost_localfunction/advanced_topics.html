本节展示本库的进阶用法. 文末还列出了本库的已知限制.

默认参数

本库允许为局部函数参数指定默认值. 但是, 使用赋值符号 = 的通常 C++ 默认参数语法不能使用. [17] 应改用关键字 default:

parameter-type parameter-name, default parameter-default-value, ...

例如, 我们来编写一个局部函数 add(x, y), 其中第二个参数 y 是可选的, 默认值为 2 (另见 add_default.cpp):

int BOOST_LOCAL_FUNCTION(int x, int y, default 2) { // Default parameter.
    return x + y;
} BOOST_LOCAL_FUNCTION_NAME(add)

BOOST_TEST(add(1) == 3);

若程序员认为如下定义的 WITH_DEFAULT 宏比上述语法更具可读性, 可以定义类似的宏 (另见 add_with_default.cpp): [18] 

#define WITH_DEFAULT , default


int BOOST_LOCAL_FUNCTION(int x, int y WITH_DEFAULT 2) { // Default.
    return x + y;
} BOOST_LOCAL_FUNCTION_NAME(add)

BOOST_TEST(add(1) == 3);

宏中的逗号与符号

C++ 预处理器不允许宏参数中出现逗号 ,, 除非逗号被圆括号 () 包裹 (详见 Boost.Utility/IdentityType 文档). 因此, 在局部函数参数和绑定中使用逗号会产生 (晦涩难懂的) 预处理器错误, 除非像本文所述那样用额外的一对圆括号 () 包裹.

注释

此外, 逗号被尖括号 <> (模板等) 或方括号 [] (多维数组访问等) 包裹的宏参数, 也需要按本文所述用额外的圆括号 () 包裹 (这是因为预处理器只识别圆括号, 不识别尖括号、方括号或其他任何括号). 不过, 逗号已经被圆括号 () 包裹的宏参数没有问题 (函数调用、某些值表达式等).

另外, 局部函数参数类型不能以非字母数字符号开头 (字母数字符号为 A-Z、a-z 和 0-9). [19] 若参数类型以非字母数字符号开头, 库会产生 (晦涩难懂的) 预处理器错误.

让我们考虑以下示例:

void BOOST_LOCAL_FUNCTION(
    const std::map<std::string, size_t>& m,                 // (1) Error.
    ::sign_t sign,                                          // (2) Error.
    const size_t& factor,
            default key_sizeof<std::string, size_t>::value, // (3) Error.
    const std::string& separator, default cat(":", " ")     // (4) OK.
) {
    ...
} BOOST_LOCAL_FUNCTION_NAME(f)

(1) 参数类型 const std::map<std::string, size_t>& 含有一个逗号 ,, 该逗号位于第一个模板参数 std::string 之后. 此逗号未被任何圆括号 () 包裹, 因此会导致预处理器错误. [20] Boost.Utility/IdentityType 宏 BOOST_IDENTITY_TYPE((type-with-commas)) 定义于 boost/utility/identity_type.hpp 头文件中, 可用于把类型包裹在额外括号 () 中, 从而克服此问题:

#include <boost/utility/identity_type.hpp>

void BOOST_LOCAL_FUNCTION(
    BOOST_IDENTITY_TYPE((const std::map<std::string, size_t>&)) m, // OK.
    ...
) {
    ...
} BOOST_LOCAL_FUNCTION_NAME(f)

此宏展开为一个表达式, 该表达式 (在编译期) 求值结果恰为指定类型 (而且此宏不使用变参宏, 因此可在任何 C++03 编译器上使用). 注意, 总共需要两对括号 (): 调用 BOOST_IDENTITY_TYPE(...) 宏的括号, 加上包裹类型表达式 (以及它包含的任何逗号 ,) 的括号, 该表达式作为实参传给 BOOST_IDENTITY_TYPE((...)) 宏. 最后, BOOST_IDENTITY_TYPE 宏必须以 typename 关键字 typename BOOST_IDENTITY_TYPE(parenthesized-type) 为前缀, 才能在模板中与 BOOST_LOCAL_FUNCTION_TPL 宏一起使用.

注释

通常, 可能有更好的方法克服这一限制, 得到比使用 BOOST_IDENTITY_TYPE 宏更具可读性的代码.

例如, 此处本可以使用外围作用域中的 typedef 来得到以下有效且也许更易读的代码:

typedef std::map<std::string, size_t> map_type;
void BOOST_LOCAL_FUNCTION(
    const map_type& m, // OK (and more readable).
    ...
) BOOST_LOCAL_FUNCTION_NAME(f)

(2) 参数类型 ::sign_t 以非字母数字符号 :: 开头, 因此用作局部函数参数类型时会产生预处理器错误. BOOST_IDENTITY_TYPE 宏也可用于解决此问题:

void BOOST_LOCAL_FUNCTION(
    ...
    BOOST_IDENTITY_TYPE((::sign_t)) sign, // OK.
    ...
) {
    ...
} BOOST_LOCAL_FUNCTION_NAME(f)
注释

通常, 可能有更好的方法克服这一限制, 得到比使用 BOOST_IDENTITY_TYPE 宏更具可读性的代码.

例如, 此处本可以直接去掉符号 ::, 得到以下有效且也许更易读的代码:

void BOOST_LOCAL_FUNCTION(
    ...
    sign_t sign, // OK (and more readable).
    ...
) {
    ...
} BOOST_LOCAL_FUNCTION_NAME(f)

(3) 默认参数值 key_sizeof<std::string, size_t>::value 含有一个逗号 ,, 该逗号位于第一个模板参数 std::string 之后. 同样, 此逗号未被任何括号 () 包裹, 因此会导致预处理器错误. 由于这是一个值表达式 (而非类型表达式), 只需用额外的一对圆括号 () 包裹即可:

void BOOST_LOCAL_FUNCTION(
    ...
    const size_t& factor,
            default (key_sizeof<std::string, size_t>::value), // OK.
    ...
) {
    ...
} BOOST_LOCAL_FUNCTION_NAME(f)

(4) 默认参数值 cat(":", " ") 则没有问题, 因为它包含的逗号 , 已被括号 () 包裹 (该括号属于函数调用 cat(...)).

考虑以下完整示例 (另见 macro_commas.cpp):

void BOOST_LOCAL_FUNCTION(
    BOOST_IDENTITY_TYPE((const std::map<std::string, size_t>&)) m,
    BOOST_IDENTITY_TYPE((::sign_t)) sign,
    const size_t& factor,
            default (key_sizeof<std::string, size_t>::value),
    const std::string& separator, default cat(":", " ")
) {
    // Do something...
} BOOST_LOCAL_FUNCTION_NAME(f)

赋值与返回

局部函数是函数对象, 因此可以把它们赋给其他仿函数, 如 Boost.Function 的 boost::function, 以便把局部函数存入变量、作为参数传给另一个函数, 或从外围函数返回.

例如 (另见 return_assign.cpp):

void call1(boost::function<int (int) > f) { BOOST_TEST(f(1) == 5); }
void call0(boost::function<int (void)> f) { BOOST_TEST(f() == 5); }

boost::function<int (int, int)> linear(const int& slope) {
    int BOOST_LOCAL_FUNCTION(const bind& slope,
            int x, default 1, int y, default 2) {
        return x + slope * y;
    } BOOST_LOCAL_FUNCTION_NAME(lin)

    boost::function<int (int, int)> f = lin; // Assign to local variable.
    BOOST_TEST(f(1, 2) == 5);

    call1(lin); // Pass to other functions.
    call0(lin);

    return lin; // Return.
}

void call(void) {
    boost::function<int (int, int)> f = linear(2);
    BOOST_TEST(f(1, 2) == 5);
}

警告

与 C++11 lambda 函数一样, 程序员有责任确保被绑定变量在调用局部函数对象的任何作用域内都有效. 若在某个被绑定变量于局部函数调用处的作用域中已失效的情况下, 在其声明作用域之外返回并调用局部函数, 将导致未定义行为 (关于把局部函数作为闭包返回时需要的额外注意, 更多示例见示例章节). 相反, 在局部函数的外围作用域内调用它总是安全的.

此外, 局部函数可以绑定并调用其他局部函数. 局部函数应始终按常量引用 const bind& 绑定, 以避免不必要的拷贝. 例如, 以下局部函数 inc_sum 绑定了局部函数 inc, 因此 inc_sum 可以调用 inc (另见 transform.cpp):

int offset = 5;
std::vector<int> v;
std::vector<int> w;

for(int i = 1; i <= 2; ++i) v.push_back(i * 10);
BOOST_TEST(v[0] == 10); BOOST_TEST(v[1] == 20);
w.resize(v.size());

int BOOST_LOCAL_FUNCTION(const bind& offset, int i) {
    return ++i + offset;
} BOOST_LOCAL_FUNCTION_NAME(inc)

std::transform(v.begin(), v.end(), w.begin(), inc);
BOOST_TEST(w[0] == 16); BOOST_TEST(w[1] == 26);

int BOOST_LOCAL_FUNCTION(bind& inc, int i, int j) {
    return inc(i + j); // Call the other bound local function.
} BOOST_LOCAL_FUNCTION_NAME(inc_sum)

offset = 0;
std::transform(v.begin(), v.end(), w.begin(), v.begin(), inc_sum);
BOOST_TEST(v[0] == 27); BOOST_TEST(v[1] == 47);

嵌套

可以把局部函数相互嵌套. 例如 (另见 nesting.cpp):

int x = 0;

void BOOST_LOCAL_FUNCTION(bind& x) {
    void BOOST_LOCAL_FUNCTION(bind& x) { // Nested.
        x++;
    } BOOST_LOCAL_FUNCTION_NAME(g)

    x--;
    g(); // Nested local function call.
} BOOST_LOCAL_FUNCTION_NAME(f)

f();

访问类型 (concept 等)

本库从不要求显式指定被绑定变量的类型 (例如, 这减少了维护工作: 只要局部函数语义仍然有效, 即使被绑定变量的类型发生变化, 局部函数的声明和定义也不必改动). 在局部函数内部, 程序员可以使用以下宏访问被绑定变量的类型:

BOOST_LOCAL_FUNCTION_TYPEOF(bound-variable-name)

BOOST_LOCAL_FUNCTION_TYPEOF 宏展开为一个类型表达式, 该表达式 (在编译期) 求值为具有指定名称的被绑定变量的完全限定类型. 说它是完全限定的, 是因为若变量按常量 const bind[&] 绑定, 该类型表达式将是常量类型; 若变量按引用 [const] bind& 绑定, 它还将是引用类型 (如有需要, 程序员可以去除 const 和 & 限定符, 所用工具为 boost::remove_const 和 boost::remove_reference, 见 Boost.TypeTraits).

推导出的被绑定类型可在函数体内用于检查 concept、声明局部变量等. 例如 (另见 typeof.cpp 和 addable.hpp):

int sum = 0, factor = 10;

void BOOST_LOCAL_FUNCTION(const bind factor, bind& sum, int num) {
    // Type-of for concept checking.
    BOOST_CONCEPT_ASSERT((Addable<boost::remove_reference<
            BOOST_LOCAL_FUNCTION_TYPEOF(sum)>::type>));
    // Type-of for declarations.
    boost::remove_reference<BOOST_LOCAL_FUNCTION_TYPEOF(
            factor)>::type mult = factor * num;
    sum += mult;
} BOOST_LOCAL_FUNCTION_NAME(add)

add(6);

在模板内, BOOST_LOCAL_FUNCTION_TYPEOF 不应以 typename 关键字为前缀, 但进行类型操纵时仍需要 typename 前缀 (另见 typeof_template.cpp 和 addable.hpp):

template<typename T>
T calculate(const T& factor) {
    T sum = 0;

    void BOOST_LOCAL_FUNCTION_TPL(const bind factor, bind& sum, T num) {
        // Local function `TYPEOF` does not need `typename`.
        BOOST_CONCEPT_ASSERT((Addable<typename boost::remove_reference<
                BOOST_LOCAL_FUNCTION_TYPEOF(sum)>::type>));
        sum += factor * num;
    } BOOST_LOCAL_FUNCTION_NAME_TPL(add)

    add(6);
    return sum;
}

在此语境下, 最好使用 BOOST_LOCAL_FUNCTION_TYPEOF 宏而非 Boost.Typeof, 以减少 Boost.Typeof 被调用的次数 (要么库内部已经使用过一次 Boost.Typeof, 此时使用此宏不会再调用 Boost.Typeof; 要么被绑定变量类型已由程序员按下文所示显式指定, 此时使用此宏完全不会调用 Boost.Typeof).

此外, 在局部函数体内, 可以使用 result_type 访问结果类型, 使用 arg1_type 访问第一个参数的类型, 使用 arg2_type 访问第二个参数的类型, 等等. [21]

指定类型 (不使用 Boost.Typeof)

虽然并非必需, 但可以显式指定被绑定变量的类型, 这样库内部就不会使用 Boost.Typeof 自动推导类型. 指定时, 被绑定变量类型必须跟在 bind "关键字"之后, 并包裹在圆括号 () 中:

bind(variable-type) variable-name           // Bind by value with explicit type.
bind(variable-type)& variable-name          // Bind by reference with explicit type.
const bind(variable-type) variable-name     // Bind by constant value with explicit type.
const bind(variable-type)& variable-name    // Bind by constant reference with explicit type.
bind(class-type*) this_                     // Bind object `this` with explicit type.
const bind(class-type*) this_               // Bind object `this` by constant with explicit type.

注意, 在局部函数体内, 始终可以使用 BOOST_LOCAL_FUNCTION_TYPEOF 来抽象对被绑定变量类型的访问 (即使在局部函数声明中显式指定了被绑定变量类型).

本库还使用 Boost.Typeof 来确定局部函数结果类型 (因为该类型是在 BOOST_LOCAL_FUNCTION 宏之外指定的). 因此, 也可以把局部函数结果类型指定为 BOOST_LOCAL_FUNCTION 宏的参数之一, 并以 return 为前缀, 这样库就不会使用 Boost.Typeof 推导结果类型:

BOOST_LOCAL_FUNCTION_TYPE(return result-type, ...)

注意, 结果类型只能指定一次: 要么在宏之前指定 (不带 return 前缀), 要么作为宏参数之一指定 (带 return 前缀). 与往常一样, 结果类型可以是 void, 以声明不返回任何内容的函数 (因此当结果类型作为宏参数之一指定时, 允许 return void).

以下示例指定了所有被绑定变量和结果类型 (另见 add_typed.cpp): [22] 

struct adder {
    adder(void) : sum_(0) {}

    int sum(const std::vector<int>& nums, const int& factor = 10) {
        // Explicitly specify bound variable and return types (no type-of).
        BOOST_LOCAL_FUNCTION(const bind(const int&) factor,
                bind(adder*) this_, int num, return int) {
            return this_->sum_ += factor * num;
        } BOOST_LOCAL_FUNCTION_NAME(add)

        std::for_each(nums.begin(), nums.end(), add);
        return sum_;
    }

private:
    int sum_;
};

除非必要, 建议不指定被绑定变量和结果类型. 让库推导这些类型, 这样局部函数语法会更简洁, 且当被绑定变量类型变化时局部函数声明无需改动 (减少维护工作量).

注释

当所有被绑定变量和结果类型都显式指定时, 库实现将不使用 Boost.Typeof.

内联

局部函数可以声明为 内联, 以提高编译器通过内联生成的汇编代码来减少局部函数调用运行期的机会. 声明局部函数为内联的方法是以关键字 inline 为其名称加前缀:

result-type BOOST_LOCAL_FUNCTION(parameters) {
    ... // Body.
} BOOST_LOCAL_FUNCTION_NAME(inline name) // Inlining.

内联局部函数时, 请注意以下几点:

  • 在符合 C++03 的编译器上, 内联局部函数的运行期始终与其等效的局部仿函数实现相当 (见替代方案章节). 但是, 内联局部函数有一个重要限制: 它们不能赋给其他仿函数 (如 boost::function), 也不能作为模板参数传递.
  • 在 C++11 编译器上, inline 没有效果, 因为即使局部函数未声明为内联, 本库也会自动生成使用 C++11 特有特性的代码, 尽可能内联局部函数调用. 此外, 非 C++11 的局部函数即使声明为内联, 也始终可以作为模板参数传递. [23]
重要

建议不要将局部函数声明为内联, 除非为了优化纯 C++03 代码而确有必要 (因为在所有其他情况下, 本库都会自动利用 C++11 特性优化局部函数调用, 同时始终允许把局部函数作为模板参数传递).

例如, 以下局部函数声明为内联 (因此为了可移植性, 需要使用 for 循环, 而不是把局部函数作为模板参数传给 std::for_each 算法, 另见 add_inline.cpp):

int sum = 0, factor = 10;

void BOOST_LOCAL_FUNCTION(const bind factor, bind& sum, int num) {
    sum += factor * num;
} BOOST_LOCAL_FUNCTION_NAME(inline add) // Inlining.

std::vector<int> v(100);
std::fill(v.begin(), v.end(), 1);

for(size_t i = 0; i < v.size(); ++i) add(v[i]); // Cannot use for_each.

递归

局部函数可以声明为 递归, 从而可以从其函数体内递归调用自身 (与通常的 C++ 函数一样). 声明局部函数为递归的方法是以 recursive "关键字"为其名称加前缀 (因此 recursive 不能用作局部函数名):

result-type BOOST_LOCAL_FUNCTION(parameters) {
    ... // Body.
} BOOST_LOCAL_FUNCTION_NAME(recursive name) // Recursive.

例如, 以下局部函数用于递归计算指定 vector 中所有数字的阶乘 (另见 factorial.cpp):

struct calculator {
    std::vector<int> results;

    void factorials(const std::vector<int>& nums) {
        int BOOST_LOCAL_FUNCTION(bind this_, int num,
                bool recursion, default false) {
            int result = 0;

            if(num <= 0) result = 1;
            else result = num * factorial(num - 1, true); // Recursive call.

            if(!recursion) this_->results.push_back(result);
            return result;
        } BOOST_LOCAL_FUNCTION_NAME(recursive factorial) // Recursive.

        std::for_each(nums.begin(), nums.end(), factorial);
    }
};

尚未观察到任何编译器能够内联递归局部函数调用, 即使递归局部函数同时声明为内联也一样:

... BOOST_LOCAL_FUNCTION_NAME(inline recursive factorial)

递归局部函数绝不应在其声明作用域之外被调用. [24]

警告

若局部函数从外围函数返回并在不同作用域中被调用, 则行为未定义 (并且很可能导致运行期错误).

相对于 C++11 lambda 函数, 这不算限制, 因为 lambda 绝不能递归调用自身 (换句话说, 不存在能在其声明作用域之外成功调用的递归 lambda 函数, 因为根本不存在递归 lambda 函数).

Overloading

由于局部函数是仿函数, 可以使用 boost::overloaded_function 仿函数 (Boost.Functional/OverloadedFunction 的, 来自 boost/functional/overloaded_function.hpp 头文件) 对它们进行重载 (详见 Boost.Functional/OverloadedFunction 文档).

在以下示例中, 重载的函数对象 add 可以使用局部函数 add_s、局部函数 add_d、带额外默认参数的局部函数 add_d 或函数指针 add_i 的签名来调用 (另见 overload.cpp):

int add_i(int x, int y) { return x + y; }


std::string s = "abc";
std::string BOOST_LOCAL_FUNCTION(
        const bind& s, const std::string& x) {
    return s + x;
} BOOST_LOCAL_FUNCTION_NAME(add_s)

double d = 1.23;
double BOOST_LOCAL_FUNCTION(const bind d, double x, double y, default 0) {
    return d + x + y;
} BOOST_LOCAL_FUNCTION_NAME(add_d)

boost::overloaded_function<
      std::string (const std::string&)
    , double (double)
    , double (double, double) // Overload giving default param.
    , int (int, int)
> add(add_s, add_d, add_d, add_i); // Overloaded function object.

BOOST_TEST(add("xyz") == "abcxyz"); // Call `add_s`.
BOOST_TEST((4.44 - add(3.21)) <= 0.001); // Call `add_d` (no default).
BOOST_TEST((44.44 - add(3.21, 40.0)) <= 0.001); // Call `add_d`.
BOOST_TEST(add(1, 2) == 3); // Call `add_i`.

异常规范

可以为局部函数编写异常规范: 在 BOOST_LOCAL_FUNCTION 宏之后、函数体代码块 { ... } 之前指定它们.

重要

注意, 异常规范只作用于程序员指定的函数体代码, 不作用于宏展开为实现局部函数而自动生成的其余代码. 例如, 即使函数体代码用 throw () { ... } 指定为不抛出任何异常, 宏自动生成的库代码的执行仍可能抛出异常 (如内存不足等).

例如 (另见 add_except.cpp):

double sum = 0.0;
int factor = 10;

void BOOST_LOCAL_FUNCTION(const bind factor, bind& sum,
        double num) throw() { // Throw nothing.
    sum += factor * num;
} BOOST_LOCAL_FUNCTION_NAME(add)

add(100);

存储类说明符

局部函数参数照常支持 C++03 的存储类说明符. auto 存储类说明符的指定方式为: [25] 

auto parameter-type parameter-name

register 存储类说明符的指定方式为:

register parameter-type parameter-name

同行展开

通常, 不能在同一行上多次展开 BOOST_LOCAL_FUNCTION 和 BOOST_LOCAL_FUNCTION_TPL 宏. [26]

因此, 本库提供了额外宏 BOOST_LOCAL_FUNCTION_ID 和 BOOST_LOCAL_FUNCTION_ID_TPL, 只要程序员把唯一标识符指定为宏的第一个参数, 它们就可以在同一行上多次展开. 唯一标识符可以是任何能被预处理器成功拼接的记号 (不限于数字), 例如 local_function_number_1_at_line_123. [27]

BOOST_LOCAL_FUNCTION_ID 和 BOOST_LOCAL_FUNCTION_ID_TPL 宏接受局部函数参数声明列表, 其语法与 BOOST_LOCAL_FUNCTION 完全相同. 例如 (另见 same_line.cpp):

#define LOCAL_INC_DEC(offset) \
    int BOOST_LOCAL_FUNCTION_ID(BOOST_PP_CAT(inc, __LINE__), /* unique ID */ \
            const bind offset, const int x) { \
        return x + offset; \
    } BOOST_LOCAL_FUNCTION_NAME(inc) \
    \
    int BOOST_LOCAL_FUNCTION_ID(BOOST_PP_CAT(dec, __LINE__), \
            const bind offset, const int x) { \
        return x - offset; \
    } BOOST_LOCAL_FUNCTION_NAME(dec)

#define LOCAL_INC_DEC_TPL(offset) \
    T BOOST_LOCAL_FUNCTION_ID_TPL(BOOST_PP_CAT(inc, __LINE__), \
            const bind offset, const T x) { \
        return x + offset; \
    } BOOST_LOCAL_FUNCTION_NAME_TPL(inc) \
    \
    T BOOST_LOCAL_FUNCTION_ID_TPL(BOOST_PP_CAT(dec, __LINE__), \
            const bind offset, const T x) { \
        return x - offset; \
    } BOOST_LOCAL_FUNCTION_NAME_TPL(dec)

template<typename T>
void f(T& delta) {
    LOCAL_INC_DEC_TPL(delta) // Multiple local functions on same line.
    BOOST_TEST(dec(inc(123)) == 123);
}

int main(void) {
    int delta = 10;
    LOCAL_INC_DEC(delta) // Multiple local functions on same line.
    BOOST_TEST(dec(inc(123)) == 123);
    f(delta);
    return boost::report_errors();
}

如上例所示, 当需要在用户自定义宏内多次调用 BOOST_LOCAL_FUNCTION_ID 和 BOOST_LOCAL_FUNCTION_ID_TPL 宏时, 它们特别有用 (因为预处理器会把所有嵌套宏展开在同一行上).

[a] 设计理由. 让局部函数类继承另一个局部函数类本来是可行的. 但这一"继承"特性并未实现, 因为它看起来毫无用处: 局部函数可以相互绑定, 因此可以直接互相调用, 无需借助动态绑定或基类函数调用.
运算符

局部函数不能是运算符. 把局部函数命名为 operator... 会导致编译期错误. [28]

例如, 以下代码无法编译 (另见 operator_error.cpp):

bool BOOST_LOCAL_FUNCTION(const point& p, const point& q) {
    return p.x == q.x && p.y == q.y;
} BOOST_LOCAL_FUNCTION_NAME(operator==) // Error: Cannot use `operator...`.

Goto

可以在局部函数体内使用 goto 跳转. 例如, 以下代码可以编译 (另见 goto.cpp):

int error(int x, int y) {
    int BOOST_LOCAL_FUNCTION(int z) {
        if(z > 0) goto success; // OK: Can jump within local function.
        return -1;
    success:
        return 0;
    } BOOST_LOCAL_FUNCTION_NAME(validate)

    return validate(x + y);
}

但是, 不能使用 goto 从局部函数体内跳转到外围作用域中定义的标号. 例如, 以下代码无法编译 (另见 goto_error.cpp):

int error(int x, int y) {
    int BOOST_LOCAL_FUNCTION(int z) {
        if(z <= 0) goto failure;    // Error: Cannot jump to enclosing scope.
        else goto success;          // OK: Can jump within local function.
    success:
        return 0;
    } BOOST_LOCAL_FUNCTION_NAME(validate)

    return validate(x + y);
failure:
    return -1;
}


[17] 设计理由. 赋值符号 = 不能用于指定默认参数值, 因为默认值不属于参数类型, 无法用模板元编程处理. 默认参数值需要用预处理器从参数声明的其余部分中分离出来. 具体而言, 本库需要使用预处理器元编程在构造局部函数类型时移除默认值, 还要统计默认值的数量, 以便为局部仿函数提供正确的调用运算符集合. 因此, 不能使用符号 =, 因为预处理器元编程无法处理它 (预处理器元编程无法检测非字母数字符号, 因为预处理器无法拼接它们).

[18] 作者个人并不觉得使用 WITH_DEFAULT 宏更具可读性, 他们更喜欢直接使用 default 关键字. 此外, WITH_DEFAULT 对不支持变参宏的编译器 #define WITH_DEFAULT (default) 需要不同的定义, 因此程序员只能根据自己决定使用的语法来定义它 (见无变参宏章节).

[19] 设计理由. 此限制是因为本库使用预处理器记号拼接 ## 来检查宏参数 (以区分函数参数、被绑定变量等), 而 C++ 预处理器不允许拼接非字母数字记号.

[20] 预处理器总是把未包裹的逗号解释为宏参数的分隔符. 因此在这种情况下, 该逗号会向预处理器表明第一个宏参数是 const std::map<std::tring, 第二个宏参数是 size_t>& m, 等等, 而不是把 const std::map<std::string, size_t>& m 作为单个宏参数传递.

[21] 设计理由. 类型名 result_type 和 argN_type 遵循 Boost.TypeTraits 的函数特征命名约定.

[22] 在本文档的示例中, 被绑定变量、函数参数和结果类型按此顺序指定, 因为这是 C++11 lambda 函数 使用的顺序. 不过, 本库接受被绑定变量、函数参数和结果类型以任意顺序出现.

[23] 设计理由. 本库通过函数指针进行间接函数调用, 以便把局部函数作为模板参数传递 (见实现章节). 尚未观察到任何编译器能够内联使用这种间接函数指针调用的函数调用. 因此, 内联局部函数不使用这种间接函数指针调用 (因而更有可能被优化), 但也因此不能作为模板参数传递. 在 C++03 上需要这种间接函数指针调用, 而在 C++11 上则不需要 (见 [N2657] 和 Boost.Config 的 BOOST_NO_CXX11_LOCAL_CLASS_TEMPLATE_PARAMETERS), 因此本库会在 C++11 编译器上自动生成可以内联的局部函数调用 (即使局部函数未声明为内联).

[24] 设计理由. 此限制源于: 用于把局部函数作为模板参数传递 (并最终可能返回到声明作用域之外) 的全局仿函数并不知道局部函数名, 因此用于递归调用的局部函数名无法在全局仿函数中设置. 这一限制加上无法内联的可能性, 就是局部函数默认不递归、除非程序员显式声明其为 recursive 的原因.

[25] auto 存储类说明符是 C++03 标准的一部分, 因此本库支持它. 但是, auto 关键字的含义和用法在 C++11 中发生了变化. 因此, 使用 auto 存储类说明符时需照常谨慎, 以避免编写出在 C++11 上无法工作的 C++03 代码.

[26] 设计理由. BOOST_LOCAL_FUNCTION 和 BOOST_LOCAL_FUNCTION_TPL 宏在内部使用 __LINE__ 生成唯一标识符. 因此, 若这些宏在同一行上多次展开, 生成的标识符将不再唯一, 代码将无法编译. (此限制不适用于 MSVC 以及其他提供非标准 __COUNTER__ 宏的编译器.) 注意, BOOST_LOCAL_FUNCTION_NAME 宏总是可以在同一行上多次展开, 因为该宏使用唯一的局部函数名 (而非 __LINE__) 来生成唯一标识符 (因此不需要 BOOST_LOCAL_FUNCTION_NAME_ID 宏).

[27] 由于预处理器可拼接的记号集合存在限制, 且并非所有编译器都正确实现这些限制, 一般建议用字母数字记号的组合来指定唯一标识符.

[28] 设计理由. 这是因为局部函数名必须是有效的局部变量名 (用于保存局部仿函数的局部变量), 而运算符不能用作局部变量名.
