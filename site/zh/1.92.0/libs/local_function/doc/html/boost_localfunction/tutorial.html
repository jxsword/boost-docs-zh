本节展示本库的基本用法.

局部函数

局部函数使用头文件 boost/local_function.hpp 中的宏定义. 这些宏必须在声明性上下文中使用 (这是相对 C++11 lambda 函数 的一个限制, 后者还可以在表达式内声明):

#include <boost/local_function.hpp> // This library header.

...
{ // Some declarative context.
    ...
    result-type BOOST_LOCAL_FUNCTION(parameters) {
        body-code
    } BOOST_LOCAL_FUNCTION_NAME(name)
    ...
}

宏展开的代码声明一个函数对象 (或仿函数), 其名称由 BOOST_LOCAL_FUNCTION_NAME 指定为局部函数名. [5] 通常的 C++ 作用域可见性规则适用于局部函数: 局部函数只在其被声明的外围作用域内可见.

局部函数结果类型在 BOOST_LOCAL_FUNCTION 宏之前指定.

局部函数体使用通常的 C++ 语句语法在代码块 { ... } 中指定, 位于 BOOST_LOCAL_FUNCTION 和 BOOST_LOCAL_FUNCTION_NAME 宏之间. 函数体在所有宏之外指定, 因此编译器错误消息和相关行号保持其通常的含义和格式. [6]

局部函数参数以逗号分隔的记号列表形式传给 BOOST_LOCAL_FUNCTION 宏 (不支持变参宏的编译器见无变参宏章节):

BOOST_LOCAL_FUNCTION(parameter-type1 parameter-name1, parameter-type2 parameter-name2, ...)

可传给局部函数的最大参数数量由配置宏 BOOST_LOCAL_FUNCTION_CONFIG_ARITY_MAX 在编译期控制. 例如, 我们来编写一个名为 add 的局部函数, 把两个整数 x 和 y 相加 (另见 add_params_only.cpp):

int BOOST_LOCAL_FUNCTION(int x, int y) { // Local function.
    return x + y;
} BOOST_LOCAL_FUNCTION_NAME(add)

BOOST_TEST(add(1, 2) == 3); // Local function call.

若局部函数没有参数, 可以把 void 传给 BOOST_LOCAL_FUNCTION 宏 (类似于允许使用 result-type function-name(void) 声明无参函数的 C++ 语法): [7] 

BOOST_LOCAL_FUNCTION(void) // No parameter.

例如, 我们来编写一个始终返回 10 的局部函数 (另见 ten_void.cpp):

int BOOST_LOCAL_FUNCTION(void) { // No parameter.
    return 10;
} BOOST_LOCAL_FUNCTION_NAME(ten)

BOOST_TEST(ten() == 10);

绑定变量

作用域内的变量 (局部变量、外围函数参数、数据成员等) 可以绑定到局部函数声明. 只有被绑定变量、静态变量、全局变量、函数以及来自外围作用域的枚举才能在局部函数体内访问. 被绑定变量的类型由本库使用 Boost.Typeof 自动推导. [8]

本库引入了新的"关键字" bind [9], 用于替代参数类型, 指定要绑定的作用域内变量名 (因此, bind 不能用作局部函数参数类型). 变量可以按值绑定:

bind variable-name // Bind by value.

或按引用绑定, 方法是在变量名前加 &:

bind& variable-name // Bind by reference.

此外, "关键字" bind 可以加前缀 const, 以按常量值绑定变量:

const bind variable-name // Bind by constant value.

或按常量引用绑定:

const bind& variable-name // Bind by constant value.

注意, 使用 const 时, 它必须始终位于 bind 之前. [10]

若变量按值绑定, 则在局部函数声明处取得该变量值的一个副本. 若变量按引用绑定, 则该变量将引用其在局部函数调用时的值. 此外, 程序员有责任确保按引用绑定的变量比局部函数的存在作用域存活得更久, 否则被绑定的引用在局部函数被调用时将失效, 导致未定义行为 (换句话说, 对按引用绑定的变量必须像使用 C++ 引用一样照常小心).

被绑定变量的类型使用 Boost.Typeof 自动推导, 它与在外围作用域中声明该变量所用的类型完全相同, 但有以下说明:

  • 若被绑定变量在外围作用域中声明为常量, 则即使使用 bind... 而非 const bind... , 它也始终按常量值或常量引用绑定. 但是, 若被绑定变量在外围作用域中未声明为常量, 则除非用 const bind... 强制常量绑定, 否则不会按常量绑定. (注意, 按常量引用绑定不受 C++11 lambda 函数 支持, 但本库支持.) [11]
  • 若被绑定变量在外围作用域中声明为引用, 则除非用 bind& 或 const bind& 显式按引用绑定, 否则它仍按值绑定. [12]

当变量按值绑定 (无论是否常量) 时, 其类型必须是CopyConstructible (即必须提供拷贝构造函数). 与向通常的 C++ 函数传参一样, 当复杂类型的变量绑定到局部函数时, 程序员可能希望按 (可能是常量的) 引用而非按值绑定这些变量, 以避免代价高昂的拷贝操作.

例如, 我们来编写局部函数 add, 它来自 引言 章节的示例. 我们按常量值绑定局部变量 factor (因为其值不应被局部函数修改), 按非常量引用绑定局部变量 sum (因为其值需要用求和结果更新), 并编写函数体执行求和 (另见 add.cpp):

int main(void) {                            // Some local scope.
    int sum = 0, factor = 10;               // Variables in scope to bind.

    void BOOST_LOCAL_FUNCTION(const bind factor, bind& sum, int num) {
        sum += factor * num;
    } BOOST_LOCAL_FUNCTION_NAME(add)

    add(1);                                 // Call the local function.
    int nums[] = {2, 3};
    std::for_each(nums, nums + 2, add);     // Pass it to an algorithm.

    BOOST_TEST(sum == 60);                  // Assert final summation value.
    return boost::report_errors();
}

绑定对象 this

当对象 this 在作用域内时 (例如从外围的非静态成员函数中), 也可以绑定它. 做法是在局部函数声明中把特殊符号 this_ (而非 this) 用作要绑定的变量名, 并在局部函数体内用它访问该对象. [13]

警告

若在局部函数声明中错误地用 this 代替 this_ 来绑定对象, 库将产生编译期错误. 但是, 若在局部函数体内错误地用 this 代替 this_ 来访问对象, 将导致未定义行为, 且不一定产生编译期错误. [14] 程序员最终有责任确保 this 从不在局部函数内使用.

对象 this 可以按值绑定:

bind this_ // Bind the object `this` by value.

在这种情况下, 当外围作用域不是常量成员时, 局部函数将能够修改该对象; 当外围作用域是常量成员时, 局部函数将不能修改该对象. 否则, 对象 this 可以按常量值绑定:

const bind this_ // Bind the object `this` by constant value.

在这种情况下, 局部函数永远不能修改该对象 (无论外围作用域是否为常量成员).

注意, 对象 this 永远不能按引用绑定, 因为 C++ 不允许获取 this 的引用 (若程序员试图使用 bind& this_ 或 const bind& this_, 库将产生编译期错误). 注意, this 是一个指针, 因此即使 this 按值绑定, 被指对象也不会被拷贝 (而且也不能直接绑定 *this, 因为 *this 是表达式而非变量名).

例如, 我们来编写一个局部函数 add, 类似于引言章节示例中的那个, 但使用成员函数来说明如何绑定对象 this (另见 add_this.cpp):

struct adder {
    adder() : sum_(0) {}

    int sum(const std::vector<int>& nums, const int factor = 10) {

        void BOOST_LOCAL_FUNCTION(const bind factor, bind this_, int num) {
            this_->sum_ += factor * num; // Use `this_` instead of `this`.
        } BOOST_LOCAL_FUNCTION_NAME(add)

        std::for_each(nums.begin(), nums.end(), add);
        return sum_;
    }

private:
    int sum_;
};

注意, 局部函数通过被绑定的对象 this_ 可以访问所有类成员, 无论其访问级别如何 (public、protected 或 private). [15] 具体而言, 上例中局部函数更新了私有数据成员 sum_.

模板

当局部函数在模板内编写时, 需要使用特殊宏 BOOST_LOCAL_FUNCTION_TPL 和 BOOST_LOCAL_FUNCTION_NAME_TPL 来声明: [16] 

#include <boost/local_function.hpp> // This library header.

...
{ // Some declarative context within a template.
    ...
    result-type BOOST_LOCAL_FUNCTION_TPL(parameters) {
        body-code
    } BOOST_LOCAL_FUNCTION_NAME_TPL(name)
    ...
}

BOOST_LOCAL_FUNCTION_TPL 和 BOOST_LOCAL_FUNCTION_NAME_TPL 宏的语法与我们迄今所见的 BOOST_LOCAL_FUNCTION 和 BOOST_LOCAL_FUNCTION_NAME 宏完全相同.

例如, 我们来编写一个类似于引言章节中那个的局部函数, 但在模板内 (另见 add_template.cpp):

template<typename T>
T total(const T& x, const T& y, const T& z) {
    T sum = T(), factor = 10;

    // Must use the `..._TPL` macros within templates.
    T BOOST_LOCAL_FUNCTION_TPL(const bind factor, bind& sum, T num) {
        return sum += factor * num;
    } BOOST_LOCAL_FUNCTION_NAME_TPL(add)

    add(x);
    T nums[2]; nums[0] = y; nums[1] = z;
    std::for_each(nums, nums + 2, add);

    return sum;
}


[5] 设计理由. 局部函数名必须传给结束函数定义的宏 BOOST_LOCAL_FUNCTION_NAME, 这样该宏才能声明一个以局部函数名命名的局部变量来保存局部函数对象. 因此, 局部函数名不能在 BOOST_LOCAL_FUNCTION 中指定, 而必须出现在局部函数体之后 (即使这不同于通常的 C++ 函数声明语法).

[6] 设计理由. 若把局部函数体作为宏参数传递, 它将被展开在单行代码上 (因为宏总是展开为单行代码). 因此, 编译器错误行号将全部报告相同的值, 不再有助于定位错误.

[7] 设计理由. C++03 标准不允许向宏传空参数, 因此宏不能以 BOOST_LOCAL_FUNCTION() 方式调用. 在正确实现空宏参数支持的 C99 编译器上, 本可以允许 BOOST_LOCAL_FUNCTION(), 但 MSVC 已经不支持这种写法, 所以为确保更好的可移植性, 从不允许这种语法.

[8] 设计理由. 通过绑定作用域内的变量, 局部函数声明表明: 无论该变量的类型如何, 它都应能在局部函数体内访问. 从语义上讲, 这种绑定应视为把被绑定变量的作用域从外围作用域"扩展"到局部函数体的作用域. 因此, 与传递函数参数的语义相反, 绑定变量的语义不取决于变量类型, 而只取决于变量名: "作用域内名为 x 的变量应能在名为 f 的局部函数内访问". 例如, 这减少了维护工作: 若某个被绑定变量的类型发生变化, 局部函数声明不必改动.

[9] 显然, 记号 bind 并非 C++ 语言的关键字. 本库在宏展开期间使用预处理器元编程解析记号 bind (见实现章节). 因此, bind 只能在本库宏语法定义所及的预处理器元编程层面上被视为一个新的"关键字" (因此仅在带引号时称其为"关键字").

[10] 设计理由. 库宏本可以实现为同时等价地接受 const bind ... 和 bind const ... 两种语法. 然而, 同时处理两种语法会使宏实现复杂化而不增加任何特性, 因此只支持 const bind ... 一种语法.

[11] 一段历史说明: 作用域内变量的常量绑定是最初促使作者开发本库的主要用例. 作者需要在局部创建一段代码来断言某些正确性条件, 同时这些断言不应修改它们使用的任何变量 (见 Contract++ 库). 当时的做法是按常量引用 const bind& 绑定断言所需的变量, 然后编写局部函数体来检查断言. 这样, 若任何断言错误地修改了被绑定变量 (例如把运算符 == 误用为 =), 编译器会正确地产生错误, 因为被绑定变量在局部函数体内是 const 类型 (另见 常量块, 载于示例章节).

[12] 设计理由. 原本声明为引用的变量按值绑定, 除非使用 [const] bind&, 这样引用既可以按值 [const] bind 也可以按引用 [const] bind& 绑定 (这与 Boost.ScopeExit 采用的绑定语义相同). 但是, 原本声明为常量的变量绝不应丢失其 const 限定符 (以防止其不仅在外围作用域而且在局部作用域中被修改), 因此即使使用 bind[&] 而非 const bind[&], 它们也始终按常量绑定.

[13] 设计理由. 特殊名称 this_ 的选定遵循 Boost 惯例: 以关键字命名的标识符加下划线后缀 (此处是 C++ 关键字 this). 之所以需要特殊符号 this_, 是因为 this 是 C++ 保留关键字, 不能用作把被绑定对象传给局部函数体的内部参数名. 本可以在局部函数体内使用 this (而非 this_), 但代价是要么拷贝被绑定对象 (这会引入运行期开销, 并带来被绑定对象必须具有深拷贝构造函数的严格要求), 要么依赖 static_cast 的未定义行为 (这可能并非在所有平台上都有效, 牺牲可移植性).

[14] 设计理由. 为了支持递归, 局部函数体不能是局部仿函数对象的静态成员函数 (因为局部函数名由 BOOST_LOCAL_FUNCTION_NAME 宏在函数体之后才指定, 所以必须通过以局部函数命名的仿函数数据成员使之可用, 而 C++ 中局部类不能有静态数据成员); 为了支持嵌套, 也是如此 (因为实参绑定变量必须声明为数据成员, 才能在嵌套于函数体成员函数内的局部函数中可见) -- 见实现章节. 因此, 在局部函数体内, 变量 this 可见, 但它指的是局部仿函数而非被绑定的对象.

[15] 设计理由. 这之所以可能, 是因为 C++ 缺陷 45 的修复使内部类型和局部类型能够访问外部类的所有成员, 无论其访问级别如何.

[16] 设计理由. 在模板内, 本库需要使用 typename 显式表明某些表达式求值为类型. 由于 C++03 不允许在模板之外使用 typename, 因此使用特殊的 ..._TPL 宏来指示外围作用域是模板, 这样本库就可以安全地使用 typename 来消解表达式类型的歧义. C++11 及其他编译器即使在不使用 ..._TPL 宏的情况下也可能编译模板内的局部函数. 不过, 建议在模板内始终使用 ..._TPL 宏, 以最大程度保证可移植性.
