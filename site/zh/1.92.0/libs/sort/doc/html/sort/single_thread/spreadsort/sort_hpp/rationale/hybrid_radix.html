混合基数

基于基数的排序主要有两种类型:

最高位优先基数排序 (MSD) 基于最高的未排序比特递归划分数据. 这种方法对划分良好的均匀分布很高效, 并且可以原位完成 (额外内存使用有限). 每轮迭代处理切分结构都有相当大的常数开销. 此处提供的算法的基数排序部分使用 MSD 基数排序. MSD 基数排序的主要缺点是: 当数据被切成小块时, 额外递归调用的开销开始主导运行时间, 这使其最坏情况行为比 𝑶(N*log(N)) 差得多.

相比之下, integer_sort、float_sort 与 string_sort 都会检查基于基数还是基于比较的排序具有更好的最坏情况运行时间, 并做出相应的递归调用. 由于基于比较的排序算法在小块数据上很高效, MSD 基数排序 把问题切小的倾向被这些混合排序转化为优势. 很难想象有什么常见用例会让纯 MSD 基数排序 相对混合算法具有显著优势.

最低位优先 基数排序 (LSD) 先按最低有效位排序. 这需要对被排序数据做一份完整副本, 占用大量额外内存. LSD 基数排序的主要优点是: 除一些常数开销和内存分配外, 它对每个元素使用固定的时间来排序, 与分布或列表大小无关. 该时间与基数的长度成正比. LSD 基数排序的另一个优点是它是稳定排序算法, 因此键相同的元素会保持其原始顺序.

缺点之一是 LSD 基数排序对"简单"排序问题与"困难"排序问题花费相同的时间, 而根据数据类型的长度以及比较、内存分配和随机访问的相对速度, 这些时间最终可能超过高效的 𝑶(N*log(N)) 算法 (如 introsort) 在大型数据集上排序"困难"问题所花的时间.

LSD 基数排序的另一个主要缺点是其内存开销. 它只对大型数据集更快, 而大型数据集本身占用大量内存, LSD 基数排序还需要复制这些数据. LSD 基数排序对变长元素 (如字符串) 没有意义; 可以从最长元素的末尾开始实现, 但效率会极低.

尽管如此, LSD 基数排序在某些场合是合适且最快的解决方案, 因此创建一个类似 integer_sort 与 float_sort 的模板化 LSD 基数排序是合理的. 在比较极其缓慢的场合, 它最为适用.
