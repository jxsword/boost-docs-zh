并行算法

此表简要描述了本库的并行算法.

                      |       |                        |                              |
Algorithm             |Stable |   Additional memory    |Best, average, and worst case |
----------------------+-------+------------------------+------------------------------+
block_indirect_sort   |  no   |block_size * num_threads| N, N LogN , N LogN           |
sample_sort           |  yes  |        N               | N, N LogN , N LogN           |
parallel_stable_sort  |  yes  |      N / 2             | N, N LogN , N LogN           |
                      |       |                        |                              |

  • Sample_sort 是 Francisco Tapia 对 Samplesort 算法 的一种实现.
  • Parallel_stable_sort 基于 samplesort 算法, 但只使用 sample_sort 一半的内存, 由 Francisco Tapia 构思并实现.
  • Block_indirect_sort 是一种新颖的并行排序算法, 非常快速, 额外内存消耗低, 由 Francisco Tapia 构思并实现.

block_size 是算法的内部参数, 为达到最高速度, 它会根据下一张表中待排序对象的大小而变化. 字符串使用 128 的 block_size.

                                |        |         |         |         |         |         |          |
object size (bytes)             | 1 - 15 | 16 - 31 | 32 - 63 | 64 - 127|128 - 255|256 - 511| 512 -    |
--------------------------------+--------+---------+---------+---------+---------+---------+----------+
block_size (number of elements) |  4096  |  2048   |   1024  |   768   |   512   |   256   |  128     |
                                |        |         |         |         |         |         |          |

线程规格

并行算法有一个整数参数, 指示排序过程中要使用的 线程数, 它始终是调用中的最后一个值.

默认值 (如果未指定) 是程序运行所在机器的硬件线程数, 由 std::thread::hardware_concurrency() 提供. 若该数为 1 或 0, 算法将以单线程运行.

线程数不是固定数值, 而是在每次执行时计算得出. 传入的线程数可以大于机器的硬件线程数: 在只有 4 个硬件线程的机器上可以传入 100 个线程; 同样地, 也可以传入 (std::thread::hardware_concurrency() / 4 ) 这样的函数结果. 若此值为 0, 程序将以单线程执行.

编程

只需包含 boost/sort/sort.hpp 文件即可使用这些算法.

所有算法都位于命名空间 boost::sort 中

#include <boost/sort/sort.hpp>

并行算法有 4 种调用格式:

algorithm ( first iterator, last iterator, comparison object, number of threads )
algorithm ( first iterator, last iterator, comparison object )
algorithm ( first iterator, last iterator, number of threads )
algorithm ( first iterator, last iterator )

这些算法需要 符合 C++11 的编译器, 但不需要任何其他代码或库. 使用更旧的编译器不保证正确运行.

如果未指定线程数, 则使用 std::thread::hardware_concurrency() 的结果

这些算法使用 比较对象, 方式与标准库排序算法相同. 如果不定义, 比较对象默认为 std::less, 其内部使用 < 运算符进行比较.

这些算法是 异常安全的, 即算法产生的异常保证待排序对象的完整性, 但不保证它们的相对顺序. 如果异常由对象内部产生 (在移动或复制构造函数中), 则结果未定义.

内部描述

排序算法的并行化主要有两类.

细分算法

对数据进行过滤并生成两个或更多部分. 所得的每个部分再由其他线程过滤和划分. 这一过滤与划分过程持续进行, 直到部分的大小小于预定义的大小, 然后由单线程对其排序.

在过滤与排序中最常用的算法是快速排序

这些算法在少量线程下很快, 但在大量线程下效率不高. 此类别的例子有

  • Intel Threading Building Blocks (TBB)
  • Microsoft PPL Parallel Sort.
归并算法

将数据划分为若干部分, 每个部分由一个线程排序. 各部分排序完成后, 再归并以得到最终结果. 这些算法需要额外的内存进行归并, 通常与数据大小相同.

在少量线程下, 这些算法与细分算法速度相近, 但在大量线程下快得多.

此类别的例子有

  • GCC Parallel Sort (based on OpenMP)
  • Microsoft PPL Parallel Buffered Sort

这产生了 不良的二元性. 少量线程下的最优算法并非大量线程下的最优算法.

因此, 为 小机器设计的软件对 大机器是 不合适的, 反之亦然.

只使用 归并算法, 则有 额外内存占用 的问题, 通常与数据大小相同.

新的并行排序算法 (Block Indirect Sort)

该算法名为 Block Indirect Sort, 为以共享内存相连的处理器而设计, 是一种混合算法.

  • 在少量线程下, 它是一个细分算法.
  • 在大量线程下, 它是一个归并算法, 只需少量辅助内存 (block_size * 线程数).

该算法 消除了这种二元性. 同一代码在少量与大量线程下都有 最优性能.

要使用的线程数在每次执行时评估. 当程序以 少量线程运行时, 算法内部使用 细分算法, 性能与 TBB 相近; 当以 大量线程运行时, 内部使用 新算法, 具有 GCC Parallel Sort 的性能, 还带有 内存消耗更少 的额外优势.


设计过程

最初构想

最初的构想是构建一个 归并算法, 使其 在大量线程下快速, 且额外内存占用少.

该算法 不基于任何其他构想或算法. 算法中使用的技巧 (间接块) 是全新的, 专为该算法构思并实现.

作为其结果的一个示例, 可以看到在 12 线程机器上对随机生成的 100 000 000 个 64 位数字进行排序.

                                  |             |             |
Algorithm                         | Time (secs) | Memory used |
----------------------------------+-------------+-------------+
Open MP Parallel Sort             |   1.1990    |  1564 MB    |
Threading Building Blocks (TBB)   |   1.6411    |   789 MB    |
Block Indirect Sort               |   0.9270    |   790 MB    |
                                  |             |             |

关于该算法, 最好的说明是它的 基准测试结果

设计过程

这一过程 漫长而艰辛, 主要是因为不确定这些构想是否正确、是否快到足以实用. 而直到代码最后一部分完成并跑完第一次基准测试之前, 我们都无法确定效率, 这使得情况更加复杂.

但这也是一个 非常令人兴奋的过程, 每解决一个问题, 就设计并测试一个新的内部算法……并一步步看到进展.

在此过程中我发现了 许多新问题, 此前无人知晓, 这迫使我去设计 新的内部算法来解决它们, 并把工作拆分为许多部分以并行执行. 因此, 在这个排序算法内部可以找到许多为解决并并行化内部问题而编写的精巧算法.
