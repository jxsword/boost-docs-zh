概述

说明

本库实现了一个类型安全的判别/标签联合类型 variant<T…​>, 与 C++17 标准的 std::variant<T…​> API 兼容.

variant<T1, T2, …​, Tn> 变量可以持有 T1、T2、…、Tn 中任意类型的值. 例如, variant<int64_t, double, std::string> 可以持有 int64_t 值、double 值或 string 值.

这样的类型有时被称为"标签联合", 因为它大致等价于

struct V
{
    enum tag { tag_int64_t, tag_double, tag_string };

    tag tag_;

    union
    {
        int64_t     i_;
        double      d_;
        std::string s_;
    };
};

用法示例

变体可用于表示动态类型的值. 形如下面的配置文件

server.host=test.example.com
server.port=9174
cache.max_load=0.7

可以表示为 std::map<std::string, variant<int64_t, double, std::string>>.

变体也可以表示多态. 举一个经典的例子, 一个多态的形状集合:

#define _USE_MATH_DEFINES
#include <iostream>
#include <vector>
#include <memory>
#include <cmath>

class Shape
{
public:

    virtual ~Shape() = default;
    virtual double area() const = 0;
};

class Rectangle: public Shape
{
private:

    double width_, height_;

public:

    Rectangle( double width, double height ):
        width_( width ), height_( height ) {}

    virtual double area() const { return width_ * height_; }
};

class Circle: public Shape
{
private:

    double radius_;

public:

    explicit Circle( double radius ): radius_( radius ) {}
    virtual double area() const { return M_PI * radius_ * radius_; }
};

double total_area( std::vector<std::unique_ptr<Shape>> const & v )
{
    double s = 0.0;

    for( auto const& p: v )
    {
        s += p->area();
    }

    return s;
}

int main()
{
    std::vector<std::unique_ptr<Shape>> v;

    v.push_back( std::unique_ptr<Shape>( new Circle( 1.0 ) ) );
    v.push_back( std::unique_ptr<Shape>( new Rectangle( 2.0, 3.0 ) ) );

    std::cout << "Total area: " << total_area( v ) << std::endl;
}

可以改用 variant<Rectangle, Circle> 值的集合来表示. 这要求预先知道可能的 Shape 类型, 而情况通常正是如此. 作为回报, 我们不再需要虚函数, 也不需要用 new Rectangle 和 new Circle 在堆上分配值:

#define _USE_MATH_DEFINES
#include <iostream>
#include <vector>
#include <cmath>

#include <boost/variant2/variant.hpp>
using namespace boost::variant2;

struct Rectangle
{
    double width_, height_;
    double area() const { return width_ * height_; }
};

struct Circle
{
    double radius_;
    double area() const { return M_PI * radius_ * radius_; }
};

double total_area( std::vector<variant<Rectangle, Circle>> const & v )
{
    double s = 0.0;

    for( auto const& x: v )
    {
        s += visit( []( auto const& y ){ return y.area(); }, x );
    }

    return s;
}

int main()
{
    std::vector<variant<Rectangle, Circle>> v;

    v.push_back( Circle{ 1.0 } );
    v.push_back( Rectangle{ 2.0, 3.0 } );

    std::cout << "Total area: " << total_area( v ) << std::endl;
}

构造与赋值

如果我们查看

    v.push_back( Circle{ 1.0 } );

这一行, 可以推断 variant<Rectangle, Circle> 可以 (隐式) 从 Circle (以及 Rectangle) 构造, 事实也确实如此. 它还可以被赋予 Circle 或 Rectangle:

variant<Rectangle, Circle> v = Circle{ 1.0 }; // v holds Circle
v = Rectangle{ 2.0, 3.0 };                    // v now holds Rectangle

如果我们尝试构造 variant<int, float>, 而所用之物既非 int 也非 float, 比如 (short)1, 那么行为"如同" variant 声明了两个构造函数,

variant::variant(int x);
variant::variant(float x);

然后使用标准的重载决议规则来选择实际使用的那个. 因此 variant<int, float>((short)1) 将持有一个 int.

检查值

把值放入 variant 很容易, 但取出值必然要绕一些弯. variant<int, float> 不可能定义成员函数 get() const, 因为这样的函数需要在编译期固定返回类型, 而正确的返回类型是 int 还是 float 只有在运行期才能知道.

有几种绕开的办法. 首先, 有访问器成员函数

std::size_t variant::index() const noexcept;

它返回当前类型从零开始的索引. 对 variant<int, float> 而言, 返回值 0 对应 int, 而 1 对应 float.

得到索引后, 就可以用自由函数 get<N> 获取值. 由于我们把类型索引传给了 get, 它知道该返回什么. get<0>(v) 会返回 int, get<1>(v) 会返回 float:

void f( variant<int, float> const& v )
{
    switch( v.index() )
    {
    case 0:

        // use get<0>(v)
        break;

    case 1:

        // use get<1>(v)
        break;

    default:

        assert(false); // never happens
    }
}

如果我们调用 get<0>(v) 而 v.index() 当前不是 0, 将抛出异常 (类型为 bad_variant_access).

另一种办法是使用 get<int>(v) 或 get<float>(v). 用法类似.

另一种避免 bad_variant_access 可能性的办法是使用 get_if. 它不返回对所含值的引用, 而是返回指向它的指针, 并在类型不匹配时返回 nullptr. get_if 接受指向 variant 的指针, 因此在我们的示例中会采用类似下面的写法:

void f( variant<int, float> const& v )
{
    if( int const * p = get_if<int>(&v) )
    {
        // use *p
    }
    else if( float const * p = get_if<float>(&v) )
    {
        // use *p
    }
    else
    {
        assert(false); // never happens
    }
}

遍历

最后但同样重要的是 visit. visit(f, v) 调用函数对象 f, 实参为 variant v 所含的值, 并返回结果. 当 v 是 variant<int, float> 时, 它会调用 f, 实参为 int 或 float. 函数对象必须准备好同时接受两者.

在实践中, 这可以通过让函数接受一个既能传入 int 又能传入 float 的类型来实现, 例如 double:

double f( double x ) { return x; }

double g( variant<int, float> const& v )
{
    return visit( f, v );
}

使用带重载 operator() 的函数对象:

struct F
{
    void operator()(int x) const { /* use x */ }
    void operator()(float x) const { /* use x */ }
};

void g( variant<int, float> const& v )
{
    visit( F(), v );
}

或者像我们在 Circle/Rectangle 示例中那样使用多态 lambda:

void g( variant<int, float> const& v )
{
    visit( [&]( auto const& x ){ std::cout << x << std::endl; }, v );
}

visit 也可以接受多于一个 variant. visit(f, v1, v2) 会调用 f(x1, x2), 其中 x1 是 v1 所含的值, x2 是 v2 中的值.

默认构造

variant 的默认构造函数对列表中的第一个类型进行值初始化. variant<int, float>{} 持有 0 (类型为 int), variant<float, int>{} 持有 0.0f.

这通常是想要的行为. 然而, 在 variant<std::mutex, std::recursive_mutex> 这类情形下, 人们可能有正当理由希望避免默认构造一个 std::mutex. 库提供了一个类型 monostate, 可以在这些场景中作为第一个类型使用. variant<monostate, std::mutex, std::recursive_mutex> 会默认构造一个 monostate, 这基本上是个无操作, 因为 monostate 实际上是一个空的 struct.

修订历史

1.91.0 中的变更

  • holds_alternative<T> 和 get<T> 的要求已放宽, 不再要求 T 在备选项列表中恰好出现一次. 现在只要求至少出现一次.

  • 更多函数被标记为 constexpr, 包括 ~variant. 这在 C++20 之前无关紧要, 现在则有影响.

  • 索引改用最小的适当无符号类型.

  • 添加了 uses_double_storage().

  • 添加了对 boost::json::value_from 和 boost::json::value_to 的支持.

1.79.0 中的变更

  • 添加了 operator<<, 适用于 monostate.

1.78.0 中的变更

  • 添加了 <boost/variant2.hpp>.

  • 添加了 unsafe_get<I>.

  • 添加了 visit_by_index.

  • 添加了 operator<<.

1.76.0 中的变更

  • 改进了双缓冲情形下生成的代码.

1.74.0 中的变更

  • 添加了对派生类型的支持: visit

  • 改进了大量 (数百个) 备选项时的编译性能.

  • 添加了对以下项的支持: visit<R>

1.73.0 中的变更

  • 添加了对 std::hash、boost::hash 的支持.

  • variant<T…​> 现在是平凡的 (当 T…​ 中所有类型都是平凡的时). 这使其可以在寄存器中传入和传出函数, 从而提升性能.

1.71.0 中的变更

在 Boost 正式评审之后, 实现已改为提供强异常安全保证 (而非基本保证). expected 已被移除.

设计

特性

这一 variant 实现有两个显著特点:

  • 它永远不会"无值", 也就是说, variant<T1, T2, …​, Tn> 有一个不变式: 它总是包含 T1、T2、…、Tn 中某个类型的有效值.

  • 它在赋值和 emplace 上提供强异常安全保证.

这是通过使用双重存储实现的, 除非所有被包含的类型都具有不抛出的移动构造函数.

设计理由

Never Valueless

直观上讲, variant<X, Y, Z> 只应能持有 X、Y 或 Z 类型的值, 而不能是别的东西.

如果将 variant 视为 union 的扩展: 由于 union 有一个称为"无活跃成员"的状态, 可以论证 variant<X, Y, Z> 也应当有这样一个额外状态, 即不持有 X、Y、Z 中的任何一个.

然而, 这会使 variant 在实践中不那么方便, 作为构建基础也不那么有用. 如果我们确实需要一个只持有 X、Y 或 Z 的变量, 这个额外的空状态会带来需要绕开的麻烦. 而在确实需要这个额外空状态的场合, 我们直接使用 variant<empty, X, Y, Z> 加上一个合适的 struct empty {}; 就可以了.

从纯设计角度来看, 不设额外空状态的论据是站得住脚的. 然而实现上的考虑却恰恰相反.

当我们把 variant 的当前值 (比如类型为 X) 替换为另一个值 (类型为 Y) 时, 由于新值需要占用与旧值相同的存储, 我们必须先销毁旧的 X, 然后在其位置上构造新的 Y. 但由于这是 C++, 构造可能因异常而失败. 此时 variant 就处于我们已约定不可能出现的"无活跃成员"状态.

这是一个实实在在的问题, 正是这个问题使得拥有空/无值状态如此有吸引力. 只要在异常时把 variant 留空就行了.

不过如前所述, 这在设计角度是不可取的, 因为它使该组件没那么有用, 也没那么优雅.

有几种绕开这一问题的办法. 最直接的一种是直接禁止构造可能抛出异常的类型. 由于我们总可以先创建一个临时值, 再用移动构造函数初始化 variant 中的那个值, 因此只要求移动构造函数不抛出即可, 无须所有构造函数都不抛出.

遗憾的是, 在至少一个流行的标准库实现中, 像 std::list 和 std::map 这样的基于节点的容器具有可能抛出异常的移动构造函数. 禁止 variant<X, std::map<Y, Z>> 几乎不切实际, 因此异常情形无法避免.

发生异常时, 我们也可以构造某个其他值, 使 variant 保持有效; 但在一般情形下, 该构造同样可能抛出异常. 如果某个类型有不抛出的默认构造函数, 我们可以用它; 否则就不行.

Boost.Variant 在这里采取的做法是在堆上分配值的一个临时副本. 发生异常时, 可以把指向该临时副本的指针存入 variant. 指针操作不会抛出.

另一个选项是使用双缓冲. 如果我们的 variant 占用两倍存储, 就可以在未使用的那一半中构造新值, 构造成功后再销毁另一半中的旧值.

std::variant 标准化时, 这些做法没有一个被认为可取, 因为它们要么引入开销, 要么对 variant 能包含的类型限制过严. 于是作为一种折中, std::variant 选择了一条可以 (不带善意地) 称之为"鱼与熊掌想要兼得"的道路.

由于上述异常情形相对少见, std::variant 设有一个称为"valueless"(无值) 的特例, 异常时进入该状态, 但接口尽可能少地承认它的存在, 让用户可以假装它不存在.

从实践角度看, 这可以说没那么糟, 但仍让许多人不满. "从不"发生的罕见状态往往测试不足, 而当这个"从不"真的发生时, 通常正值最不方便的时候.

本实现不遵循 std::variant; 它静态保证 variant 永远不会处于无值状态. 函数 valueless_by_exception 仅为兼容性而提供, 但它总是返回 false.

相反, 如果被包含的类型使得在更改所含值时无法避免异常情形, 则使用双重存储.

强异常安全性

最初提交只提供基本异常安全保证. 如果更改所含值的尝试 (通过赋值或 emplace) 因异常而失败, 且备选项中存在具有不抛出默认构造函数的类型, 就会在 variant 中创建该类型的一个值. 这一决定的优点是双重存储的需要较少.

评审者相当一致地讨厌它. 构造一个随机的类型被认为太不可预测, 也不符合基本保证的精神. 所选类型的默认构造函数即使不抛出, 仍可能有不良副作用. 或者即便没有副作用, 该类型的值对周围代码也可能有特殊含义. 因此有人主张, variant 应当要么保持旧值, 要么转变为新值, 而不合成其他状态.

而在光谱的另一端, 有人认为双重存储不可接受. 但他们认为它在原则上不可接受, 与使用频率无关.

结果, 在赋值和 emplace 上提供强异常安全保证被宣布为验收条件.

事后来看, 这是正确的决定. 强保证通常不被提供的原因是它不可组合. 当 X 和 Y 在赋值上提供基本保证时, struct { X x; Y y; }; 也提供. 类似地, 当 X 和 Y 的赋值不抛出时, struct 的赋值也不抛出. 但这对强保证不成立.

通常的做法是在赋值上提供基本保证, 并让用户用不抛出的 swap 或不抛出的移动赋值合成"强"赋值. 也就是说, 给定 x1 和 x2 (类型均为 X), 不使用"基本"的 x1 = x2;, 而使用 X(x2).swap(x1); 或 x1 = X(x2);.

几乎所有类型都提供不抛出的 swap 或不抛出的移动赋值, 因此这个办法很有效. 几乎所有 -- 除了 variant, 它在一般情形下既无不抛出的 swap, 也无不抛出的移动赋值. 如果 variant 自身不提供强保证, 用户就无法合成它.

所以它应当提供, 而它也确实提供了.

与 std::variant 的差异

本实现与 std::variant 的主要差异是:

  • 没有因异常而无值的状态: valueless_by_exception() 总是返回 false.

  • 在赋值和 emplace 上提供强异常安全保证.

  • emplace 先构造新值再销毁旧值; 在单存储情形下, 这意味着先构造一个临时对象, 再将其移动到位.

  • 作为扩展, 提供了从例如 variant<int, float> 到 variant<float, double, int> 的转换构造函数.

  • 反向操作, 即从 variant<float, double, int> 到 variant<int, float>, 以成员函数 subset<U…​> 的形式提供. (如果变体的当前状态无法表示, 该操作可能抛出异常.)

  • unsafe_get 是 get 和 get_if 的不检查版本, 作为扩展提供.

  • visit_by_index 是一个访问函数, 接受单个变体和若干函数对象 (每个备选项一个), 作为扩展提供.

  • C++20 对 std::variant 的增补和变更尚未实现.

与 Boost.Variant 的差异

本库与 std::variant API 兼容. 因此, 其接口与 Boost.Variant 不同. 例如, 访问通过 visit 而非 apply_visitor 进行.

不支持递归变体.

使用双重存储而非临时堆备份. 这一 variant 始终"基于栈", 从不分配内存, 自身从不抛出 bad_alloc.

    unsafe_get(const variant<T...>& v);
template<size_t I, class... T>
  constexpr const variant_alternative_t<I, variant<T...>>&&
    unsafe_get(const variant<T...>&& v);

  • 要求:

    v.index() == I.

    返回:

    对 variant 中所存对象的引用.

关系运算符

template<class... T>
  constexpr bool operator==(const variant<T...>& v, const variant<T...>& w);

  • 返回:

    v.index() == w.index() && get<I>(v) == get<I>(w), 其中 I 为 v.index().

template<class... T>
  constexpr bool operator!=(const variant<T...>& v, const variant<T...>& w);

  • 返回:

    !(v == w).

template<class... T>
  constexpr bool operator<(const variant<T...>& v, const variant<T...>& w);

  • 返回:

    v.index() < w.index() || (v.index() == w.index() && get<I>(v) < get<I>(w)), 其中 I 为 v.index().

template<class... T>
  constexpr bool operator>(const variant<T...>& v, const variant<T...>& w);

  • 返回:

    w < v.

template<class... T>
  constexpr bool operator<=(const variant<T...>& v, const variant<T...>& w);

  • 返回:

    v.index() < w.index() || (v.index() == w.index() && get<I>(v) <= get<I>(w)), 其中 I 为 v.index().

template<class... T>
  constexpr bool operator>=(const variant<T...>& v, const variant<T...>& w);

  • 返回:

    w <= v.

swap

template<class... T>
  void swap(variant<T...>& v, variant<T...>& w) noexcept( /*see below*/ );

  • 效果:

    等价于 v.swap(w).

visit

template<class R = /*unspecified*/, class F, class... V>
  constexpr /*see below*/ visit(F&& f, V&&... v);

  • 返回:

    std::forward<F>(f)(get<I>(std::forward<V>(v))…​), 其中 I…​ 为 v.index()…​.

    备注:

    若显式给出 R, 如 visit<int> 中那样, 则返回类型为 R. 否则, 由 F 推导得出. 对 variant 备选项应用 F 的所有可能结果都必须具有相同的返回类型, 此推导才能成功.

visit_by_index (扩展)

template<class R = /*unspecified*/, class V, class... F>
  constexpr /*see below*/ visit_by_index(V&& v, F&&... f);

  • 要求:

    variant_size<V>::value == sizeof…​(F), 否则程序非良构.

    返回:

    std::forward<Fi>(fi)(get<i>(std::forward<V>(v))), 其中 i 为 v.index(), 而 Fi 和 fi 分别为第 i 个元素, 取自 F…​ 与 f…​.

    备注:

    若显式给出 R, 如 visit_by_index<int> 中那样, 则返回类型为 R. 否则, 由 F…​ 和 V 推导得出. 将 Fi 应用于相应 variant 备选项的所有情形都必须具有相同的返回类型, 此推导才能成功.

流插入 (扩展)

template<class Ch, class Tr, class... T>
  std::basic_ostream<Ch, Tr>&
    operator<<( std::basic_ostream<Ch, Tr>& os, variant<T...> const& v );

  • 要求:

    sizeof…​(T) != 0.

    返回:

    os << get<I>(v), 其中 I 为 v.index().
