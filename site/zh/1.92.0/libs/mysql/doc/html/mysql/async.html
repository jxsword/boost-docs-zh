转向异步

按照 Boost.Asio 的惯例, 所有网络操作都有对应的异步版本, 其名称以 async_ 为前缀. 异步操作的最后一个参数是 CompletionToken, 它决定了异步操作的管理方式以及函数的返回类型. 这些 async_ 函数称为异步发起函数.

每个异步发起函数都有一个关联的处理器类型, 它决定了异步操作如何将结果传回给调用者. 该处理器类型总是具有以下两种形式之一:

  1. void(error_code). 用于没有实际结果的操作, 例如 connection::async_connect.
  2. void(error_code, T). 用于有结果的操作, 例如 connection::async_prepare_statement (此时, T 为 statement).

所有异步函数都提供了接受可选 diagnostics 输出参数的重载. 在调用完成处理器之前, 该参数会被填充以服务器提供的任何错误信息.

每个连接同时只允许一个未完成的操作

如 本节所述, 每个连接在同一时刻只能有一个未完成的异步操作. 如果需要并行执行查询, 请打开更多与服务器的连接.

完成标记

任何可用于 Boost.Asio 的完成标记也可以用于本库. 下面列出了一些最常用的:

  • C++20 协程, 使用 asio::co_spawn 和 asio::deferred. 将 deferred 传递给发起函数会返回一个可被 co_await 的对象. 可以将 deferred 与 with_diagnostics 结合使用以获得更好的错误报告.

    详见 异步教程.

  • 有栈协程, 可用于在 C++11 中获得类似协程的功能. 通过 asio::spawn 和 asio::yield_context 访问该功能, 也可与 with_diagnostics 结合使用. 使用这些协程需要链接 Boost.Context.

    详见 该示例.

  • 回调. 可以传入一个可调用对象 (函数指针或函数对象), 其签名与为该操作指定的处理器签名相同. 该可调用对象将在操作完成时被调用. 发起函数将返回 void.

    该示例演示了如何将异步函数与回调结合使用.

  • future. 此时, 传入常量 asio::use_future 作为完成标记. 发起函数将返回以下之一:

    • std::future<void>, 若完成处理器具有 1) 所给的形式.
    • std::future<T>, 若完成处理器具有 2) 所给的形式.

    可以通过调用 future::get 来等待该 future. 如果发生错误, future::get 将抛出异常. 注意, 该异常由 Asio 自身抛出, 并且始终为 boost::system::system_error 类型, 即使有可用的诊断信息也是如此.

  • 任何满足 CompletionToken 类型要求的其他类型. 这里列出了最常用的几种, 但你也可以自己定制完成标记并将其用于本库的异步操作.

with_diagnostics 完成标记

with_diagnostics 是一个完成标记适配器, 可在使用异常的异步操作中使用. with_diagnostics 使你的操作抛出 error_with_diagnostics, 就像同步函数那样.

with_diagnostics(asio::deferred) 是本库大多数操作的默认完成标记. 如果按照教程中的建议使用 C++20 协程, 那么你已经在使用它了.

当使用涉及异常的其他完成标记风格时, 例如 asio::yield_context, 可能需要显式使用 with_diagnostics. 该示例展示了具体做法.

with_diagnostics 只在使用异常时才有意义. 使用错误码时, 可以照常继续使用 asio::as_tuple 和 asio::redirect_error.

取消与超时

本库中的所有异步操作都支持 逐操作取消. 所有操作仅支持 terminal asio::cancellation_type. 这意味着, 如果一个异步操作被取消, connection 对象将处于未指定状态, 此后你应当关闭或销毁该连接. 特别要注意, 重试被取消的操作是 不安全的.

支持取消使你可以在库没有显式支持的情况下实现超时. 该教程深入讨论了这一主题.

注意, 取消发生在 Boost.Asio 层面, 而不是 MySQL 操作层面. 这意味着, 取消一个操作时, 当前的网络读或写会被取消. 该操作可能已经到达服务器并被执行. 如上所述, 操作被取消后, 连接将处于未指定状态, 你应当关闭或销毁它.
