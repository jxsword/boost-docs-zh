遗留连接类

你可能会遇到使用 connection 或其别名 tcp_connection、tcp_ssl_connection、unix_connection 的代码. 在 Boost 1.87 中 any_connection 变得稳定之前, 这是创建客户端连接的主要方式.

connection 并未被弃用, 但我们不建议在新代码中使用它. any_connection 更易使用, 且提供同等的效率.

流与类型别名

connection 以 Stream 类为模板参数, 该类实现读写线上字节的传输层.

库为最常见情形提供了辅助类型别名:

相比之下, any_connection 不是模板. 上述三种传输同样可与 any_connection 配合使用.

构造连接

connection 的构造函数接受与底层 Stream 构造函数相同的实参. 对于 tcp_ssl_connection , 我们需要传递一个执行上下文和一个 asio::ssl::context:

// The execution context, required for all I/O operations
asio::io_context ctx;

// The SSL context, required for connections that use TLS.
asio::ssl::context ssl_ctx(asio::ssl::context::tlsv12_client);

// Construct the connection. The arguments are forwarded
// to the stream type (asio::ssl::stream<asio::ip::tcp::socket>).
mysql::tcp_ssl_connection conn(ctx, ssl_ctx);

建立连接

使用 connection::connect 或 connection::async_connect 来建立连接. 此函数接受两个参数:

  • 要连接的端点. 端点类型取决于流类型. 对于 TCP 连接, 它是一个 asio::asio::ip::tcp::endpoint , 包含 IP 地址和端口. 对于 UNIX 套接字, 则是 asio::asio::local::stream_protocol::endpoint , 包含 UNIX 路径.
  • 一个 handshake_params 实例, 包含执行 MySQL 握手所需的全部参数.

若使用 TCP, 必须自行执行主机名解析. 例如:

// Resolve the hostname to get a collection of endpoints.
// default_port_string is MySQL's default port, 3306
// Hostname resolution may yield more than one host
asio::ip::tcp::resolver resolver(ctx);
auto endpoints = resolver.resolve(server_hostname, mysql::default_port_string);

// Parameters specifying how to perform the MySQL handshake operation.
// Similar to connect_params, but doesn't contain the server address and is non-owning
mysql::handshake_params params(
    mysql_username,
    mysql_password,
    "boost_mysql_examples"  // database to use
);

// Connect to the server using the first endpoint returned by the resolver
conn.connect(*endpoints.begin(), params);

与 connect_params 不同, handshake_params 并不拥有它所包含的字符串 (如用户名和密码). 你需负责让它们在 connect 操作完成前保持存活.

handshake_params 的所有功能在 connect_params 中都有等价物. 更多信息参见 参考表.

使用连接

连接之后, connection 和 any_connection 几乎可以等价地使用:

// Issue a query, as you would with any_connection
mysql::results result;
conn.execute("SELECT 1", result);

一些差异:

  • 一些较新的 API, 如 async_set_character_set 和 async_run_pipeline , 在 connection 中不存在.
  • 默认情况下, connection 的完成标记是 asio::deferred 而非 mysql::with_diagnostics(asio::deferred). 在使用带异常的协程时, 若想要带额外信息的异常, 需要显式传入 mysql::with_diagnostics.

TLS 支持

要使用 TLS, 必须将 connection 与支持 TLS 的 Stream 一起使用. 支持 TLS 的流 必须继承自 asio::ssl::stream_base. 最常见的是 asio::ssl::stream (由 tcp_ssl_connection 使用).

使用不支持 TLS 的流类型时, 如 tcp_connection 或 unix_connection , handshake_params::ssl 会被忽略.

UNIX 套接字

要使用 UNIX 套接字, 请使用 unix_connection:

// The execution context, required for all I/O operations
asio::io_context ctx;

// A UNIX connection requires only an execution context
mysql::unix_connection conn(ctx);

// The socket path where the server is listening
asio::local::stream_protocol::endpoint ep("/var/run/mysqld/mysqld.sock");

// MySQL handshake parameters, as in the TCP case.
mysql::handshake_params params(
    mysql_username,
    mysql_password,
    "boost_mysql_examples"  // database to use
);

// Connect to the server
conn.connect(ep, params);

// Use the connection normally

握手与退出

除 connect 和 close 之外, connection 还暴露了两个额外的 I/O 操作:

  • connection::handshake 类似于 connect , 但不连接底层 Stream.
  • connection::quit 类似于 close , 但不关闭底层 Stream.

可以这样使用它们:

// The execution context, required for all I/O operations
asio::io_context ctx;

// The SSL context, required for connections that use TLS.
asio::ssl::context ssl_ctx(asio::ssl::context::tlsv12_client);

// We're using TLS over TCP
mysql::tcp_ssl_connection conn(ctx, ssl_ctx);

// Resolve the server hostname into endpoints
asio::ip::tcp::resolver resolver(ctx);
auto endpoints = resolver.resolve(server_hostname, mysql::default_port_string);

// Connect the underlying stream manually.
// asio::connect tries every endpoint in the passed sequence
// until one succeeds. any_connection uses this internally.
// lowest_layer obtains the underlying socket from the ssl::stream
asio::connect(conn.stream().lowest_layer(), endpoints);

// Perform MySQL session establishment.
// This will also perform the TLS handshake, if required.
mysql::handshake_params params(
    mysql_username,
    mysql_password,
    "boost_mysql_examples"  // database to use
);
conn.handshake(params);

// Use the connection normally
mysql::results result;
conn.execute("SELECT 1", result);

// Terminate the connection. This also performs the TLS shutdown.
conn.quit();

// Close the underlying stream.
// The connection's destructor also closes the socket,
// but doing it explicitly will throw in case of error.
conn.stream().lowest_layer().close();

这些函数在以下情况下很有用:

  • 当你想自行执行流连接建立时. 例如, 想使用上文示例中的 asio::connect 范围重载时.
  • 使用特殊的 Stream 类型时. connect 和 close 只能在 Stream 类型满足 SocketStream 时使用 — 即其最底层类型是套接字. 上表中的所有流类型都满足这一点, 但 asio::windows::stream_handle 不满足.

重连

connection 的重连能力比 any_connection 更有限. 具体来说, 使用支持 TLS 的流时, connection 在关闭或遇到致命错误后无法复用. 这是因为 asio::ssl::stream 无法复用. 此限制在 any_connection 中不存在.

若你使用 tcp_connection 或 unix_connection 或任何其他支持重连的流, 并且想复用连接:

  • 调用 connection::close , 或手动关闭底层流, 即使你遇到了致命错误.
  • 正常调用 connection::connect , 即使 close 操作失败.
  • 若你的 connection::connect 操作失败, 可以再次调用 connection::connect 重新尝试打开它.

若你的 Stream 类型不满足 SocketStream 概念, 则需要使用 handshake 和 quit 而非 connect 和 close , 并自行执行传输层连接建立.

与 any_connection 一样, connection 不执行任何内置重试策略.

迁移到 any_connection

我们建议将使用模板化连接的代码迁移到 any_connection. 大多数情况下, 只需将连接建立代码改为使用 connect_params 而非 handshake_params.
