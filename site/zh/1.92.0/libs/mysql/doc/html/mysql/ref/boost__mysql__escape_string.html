escape_string

转义字符串, 使其可安全用于组合查询.

概要

定义于头文件 <boost/mysql/escape_string.hpp> 

template<
    class OutputString>
error_code
escape_string(
    string_view input,
    const format_options& opts,
    quoting_context quot_ctx,
    OutputString& output);
说明

给定字符串 input , 计算出转义了特殊字符的字符串, 并将其放入 output 中. 该函数是组合客户端侧查询 (含运行期字符串值) 的底层构件, 可避免 SQL 注入漏洞. 若可以, 建议优先使用更高级的函数, 如 format_sql.

转义规则因字符串所使用的上下文而异. quot_ctx 用于标识字符串将出现在查询中的位置. 可能的值如下:

  • quoting_context::double_quote : 字符串由双引号包围.
  • quoting_context::single_quote : 字符串由单引号包围.
  • quoting_context::backtick : 字符串由反引号包围, 转义标识符时即属这种情况.

默认情况下, MySQL 在字符串值中将反斜杠字符视为转义符 (例如, 字符串 "\n" 被视为换行符). 该行为默认启用, 但可通过启用 NO_BACKSLASH_ESCAPES SQL 模式将其禁用. 禁用后, 反斜杠不再具有特殊含义, 这会改变转义规则. opts.backslash_escapes 应设置为 true (若反斜杠表示转义符, 即 NO_BACKSLASH_ESCAPES 未启用时), 否则应设置为 false.

MySQL 可配置为将双引号字符串视为标识符而非值. 通过激活 ANSI_QUOTES 或 ANSI SQL 模式可启用此行为. 服务器不会向客户端报告该模式是否启用. 该函数不直接支持此 SQL 模式.

opts.charset 应标识连接的字符集 (由 character_set_client 会话变量给出). 该字符集用于遍历输入字符串. 它必须是 ASCII 兼容的字符集 (如 utf8mb4_charset). character_set_client 允许的所有字符集均满足此要求.

可使用 any_connection::format_opts 检索适合你的连接的 opts 值.

异常安全性

基本保证. 内存分配可能抛出异常.

复杂度

与 input.size() 成线性关系.

误差

client_errc::invalid_encoding — 当 input 包含按 opts.charset 判定无效的字符串时.
