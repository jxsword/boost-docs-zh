说明

连接池会创建并管理 any_connection 对象. 使用池可以复用会话, 避免建立会话的部分开销. 它还内置错误处理和重连功能. 关于何时使用该类的更多细节, 请参见讨论和示例.

连接通过 async_get_connection 获取, 它会产生一个 pooled_connection 对象. 当 pooled_connection 被销毁时, 或通过调用 pooled_connection::return_without_reset, 连接会被归还到池中.

池需要先运行才能返回连接. 请使用 async_run 来运行. 池只能运行一次.

连接由池按照明确定义的状态模型在内部创建、连接和管理. 详情请参见讨论.

由于 Boost.Asio 通用异步模型的一些特殊之处, 该类只提供异步函数. 可以使用 asio::use_future 将它们转换为同步函数 (详情请阅读讨论).

这是一个仅可移动 (move-only) 的类型.

默认完成标记

该类所有异步操作的默认完成标记是 with_diagnostics(asio::deferred), 它允许你使用 co_await 并在出错时抛出预期的异常.

线程安全

池由一个内部状态对象加上指向该状态的句柄组成. 每个组件有不同的线程安全规则.

关于 内部状态, 连接池 默认不是线程安全的, 但可以通过在构造时将 pool_params::thread_safe 设为 true 使其安全. 内部状态也会被 connection_pool 之外的某些函数改变, 例如归还连接.

以下操作意味着池状态的变更, 在启用线程安全时由 strand 保护:

  • 调用 connection_pool::async_run.
  • 调用 connection_pool::async_get_connection.
  • 通过发出取消信号来取消 async_get_connection.
  • 通过销毁 pooled_connection 或调用 pooled_connection::return_without_reset 归还连接.
  • 通过调用 connection_pool::cancel 取消池, 为 async_run 发出取消信号, 或销毁 connection_pool 对象.

指向池状态的 句柄是 永远非线程安全的, 即使对于启用了线程安全的池也是如此. 赋值等函数会修改句柄, 若与其他函数并发调用会导致竞态条件. 其他对象 (如 pooled_connection) 拥有自己的状态句柄, 因此只与池状态交互.

如果配置为线程安全, 保护只作用于池的状态. 特别要注意使用 asio::cancel_after 和类似标记时的情况. 更多信息请阅读 此页.

总结:

  • 不同对象: 安全.
  • 共享对象: 不安全. 将 pool_params::thread_safe 设为 true 会使某些函数变得安全.
对象生命周期

连接池对象会创建一个内部状态对象, 该对象被其他对象和操作引用 (例如 pooled_connection). 即使在 connection_pool 对象被销毁之后, 该对象也会以共享所有权语义保持存活. 这带来了直观的生命周期规则.
