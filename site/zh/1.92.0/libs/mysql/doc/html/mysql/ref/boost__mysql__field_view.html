说明

这是一个类似 variant 的类, 与 field 类似, 但为半所有权且只读. 此类型的值通常由库创建, 而非由用户直接创建. 其构造和复制开销很小, 是从 MySQL 读取值时的主要库接口.

与 variant 类似, field_view 在任何时刻始终指向某一特定类型的值. 可通过 field_view::kind 和 is_xxx 之类的函数查询其类型, 例如 field_view::is_int64. 分别使用 as_xxx 和 get_xxx 进行受检和不带检查的值访问. 与 field 不同, 这些函数返回值而非引用.

对象生命周期

根据构造方式的不同, field_view 可具有值语义或引用语义:

  • 若由库创建, 该 field_view 将关联一个 row、rows 或 results 对象, 该对象持有 field_view 所指向的内存. 只要该对象分配的内存有效, 此对象即保持有效.
  • 若由 field 创建 (通过调用 operator field_view), 该 field_view 充当指向该 field 对象的引用, 只要 field 有效即保持有效.
  • 若由标量 (null、整数、浮点数、date、datetime 或 time) 创建, 该 field_view 具有值语义, 且始终有效.
  • 若由字符串或 blob 类型创建, 该 field_view 充当一个 string_view 或 blob_view , 只要原字符串/blob 有效即保持有效.

对已失效的 field_view 调用任何成员函数将导致未定义行为.
