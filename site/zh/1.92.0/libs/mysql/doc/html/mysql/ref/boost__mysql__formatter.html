formatter

用于定制 SQL 格式化的扩展点.

概要

定义于头文件 <boost/mysql/format_sql.hpp> 

template<
    class T>
struct formatter;
说明

可针对自定义类型特化此类型, 使其可格式化. 这使它们满足 Formattable 概念, 从而可用于 format_sql 及类似函数.

针对类型 formatter 的 T 特化应具有如下形式:

template <>
struct formatter<T>
{
    const char* parse(const char* begin, const char* end); // parse format specs
    void format(const T& value, format_context_base& ctx) const; // perform the actual formatting
};

当带有自定义格式化器的值被格式化时 (使用 format_sql 或类似函数), 库会执行以下操作:

  • 会默认构造一个 formatter<T> 实例, 其中 T 为被格式化值在去除 const 和引用后的类型.
  • 会在此构造出的实例上调用 parse 函数, 其中 [begin, end) 指向当前替换字段所具有的格式说明符. 若 parse 找到了它能理解的说明符, 它应当记住它们, 通常是在 formatter 实例中设置某个标志. parse 必须返回指向范围中第一个未解析字符的迭代器 (若全部解析完毕, 则返回 end 迭代器). 以下是一些会传递给 parse 的示例:
    • 在 "SELECT {}" 中, 该范围为空.
    • 在 "SELECT {:abc}" 中, 该范围为 "abc".
    • 在 "SELECT {0:i}" 中, 该范围为 "i".
  • 若 parse 未能解析所有传入的说明符 (即其返回的迭代器与传入范围的末尾不同), 则会发出 client_errc::format_string_invalid_specifier , 格式化操作随之结束.
  • 否则, format 会在格式化器实例上被调用, 传入要格式化的值以及 format_context_base (格式化操作正在其上运行). 此函数应执行实际的格式化, 通常是在传入的上下文上调用 format_sql_to.

不要为内置类型特化 formatter , 例如 int、std::string 或 optional (正式地说, 即任何满足 WritableField 的类型), 因为这些特化将被忽略.
