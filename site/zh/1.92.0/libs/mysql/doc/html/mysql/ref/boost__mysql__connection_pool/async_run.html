connection_pool::async_run

运行负责管理连接的池任务.

概要 
template<
    class CompletionToken = with_diagnostics_t<asio::deferred_t>>
auto
async_run(
    CompletionToken&& token = {});
说明

该函数会创建并连接新连接, 并重置和 ping 已创建的连接. 需要调用该函数, async_get_connection 才能成功.

该异步操作会无限期运行, 直到池被取消 (通过调用 cancel 或对 async_run 操作使用逐操作取消). 一旦所有内部连接操作 (包括连接、ping 和重置) 完成, 操作即完成.

在调用 cancel 之后调用该函数是安全的.

前置条件

对于单个池, 该函数最多只能调用一次. 形式上, async_run 之前尚未在 *this 或任何用于移动构造或移动赋值 *this 的对象上被调用过.

此外, this->valid() == true.

对象生命周期

在操作未完成期间, 池的内部数据会保持存活. 在操作未完成期间销毁 *this 是安全的.

处理器签名

该操作的处理器签名是 void(boost::mysql::error_code)

Executor

最终处理器使用 token 的关联执行器执行, 若该标记没有关联执行器则使用 this->get_executor(). 最终处理器的调用方式如同通过 asio::post 提交, 且绝不会在该函数内被内联调用.

如果池构造时启用了线程安全, 中间完成处理器将通过包装 this->get_executor() 的内部 strand 执行. 否则, 中间处理器使用 this->get_executor() 执行. 无论哪种情况, 标记的关联执行器只用于最终处理器.

逐操作取消

该操作支持逐操作取消. 取消 async_run 等价于调用 connection_pool::cancel. 支持以下 asio::cancellation_type_t 值:

  • asio::cancellation_type_t::terminal
  • asio::cancellation_type_t::partial

注意, 不支持 asio::cancellation_type_t::total, 因为调用 async_run 总是会产生可观察的副作用.

误差

该函数总是成功完成. 处理器签名确保与 Boost.Asio 基础设施的最大兼容性.

线程安全

读取内部状态句柄. 修改池状态. 如果池构造时启用了线程安全, 它可以与不修改状态句柄的其他函数并发调用.
