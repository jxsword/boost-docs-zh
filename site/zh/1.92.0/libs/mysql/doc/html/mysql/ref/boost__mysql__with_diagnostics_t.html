说明

传递给异步发起函数时, 会将其处理器签名从 void(error_code, T...) 变换为 void(std::exception_ptr, T...). 利用 Boost.MySQL 内部机制, 捕获操作可能产生的任何 diagnostics , 以创建指向 std::exception_ptr 对象的 error_with_diagnostics. 成功时, 生成的 std::exception_ptr 将为 nullptr.

使用 with_diagnostics 包装会抛出异常的标记 (如 deferred + co_await 或 yield_context) 会用诊断信息增强抛出的异常, 与同步函数抛出的异常一致. 若不使用此标记, Asio 将使用 system_error 异常, 包含的信息较少.

此标记只能用于涉及 Boost.MySQL 的操作, 因为它依赖其内部机制.

与 asio::as_tuple 类似, 此类包装另一个完成标记. 例如, with_diagnostics(asio::deferred) 会生成一个带适配签名的延迟操作, 在被 error_with_diagnostics 时会抛出 co_await.

若将此标记应用于处理器签名与 void(error_code, T...) 不匹配的函数, 该标记将作为直通: 它不修改签名, 直接调用底层标记的发起. 这有以下影响:

  • asio::as_tuple(with_diagnostics(X)) 等价于 asio::as_tuple(X).
  • asio::redirect_error(with_diagnostics(X)) 等价于 asio::redirect_error(X).
  • 当 asio::as_tuple 是默认完成标记时 (如 asio::redirect_error 的情况), 像 with_diagnostics 和 any_connection 这样的标记可以用作部分标记.
