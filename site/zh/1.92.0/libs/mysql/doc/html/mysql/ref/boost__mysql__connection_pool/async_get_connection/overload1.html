connection_pool::async_get_connection (2 个重载中的第 1 个)

从池中获取一个连接.

概要 
template<
    class CompletionToken = with_diagnostics_t<asio::deferred_t>>
auto
async_get_connection(
    CompletionToken&& token = {});
说明

从池中取出一个空闲连接以供使用.

如果该函数成功完成 (错误码为空), 返回的 pooled_connection 将具有 valid() == true 并且可用. 如果以非空错误码完成, 它将具有 valid() == false.

如果操作启动时存在空闲连接, 它会立即以该连接完成. 否则, 它会等待某个连接变为空闲 (若池配置允许, 可能在此过程中创建新连接), 直到操作被取消 (通过发出取消信号) 或池被取消 (通过调用 connection_pool::cancel). 如果池未在运行, 操作会立即失败.

如果操作被取消, 且使用了带 diagnostics 的重载, 输出的诊断信息将包含尝试连接的连接所产生的最近错误 (通过 any_connection::async_connect), 如果有的话. 在 async_get_connection 因连接无法连接而未能完成的情况下, 该特性有助于定位问题所在.

前置条件

this->valid() == true

对象生命周期

在操作未完成期间, 池的内部数据会保持存活. 在操作未完成期间销毁 *this 是安全的.

处理器签名

该操作的处理器签名是 void(boost::mysql::error_code, boost::mysql::pooled_connection)

Executor

如果最终处理器有关联的立即执行器且操作立即完成, 最终处理器会被派发给它. 否则, 最终处理器的调用方式如同通过 asio::post 提交, 且绝不会在该函数内被内联调用. 立即完成只可能发生在未启用线程安全时.

最终处理器使用 token 的关联执行器执行, 若该标记没有关联执行器则使用 this->get_executor().

如果池构造时启用了线程安全, 中间完成处理器将通过包装 this->get_executor() 的内部 strand 执行. 否则, 中间处理器使用 token 的关联执行器 (如果有的话) 执行, 若没有则使用 this->get_executor().

注意: 同时使用线程安全和 asio::cancel_after 时要小心, 因为可能导致无意中的竞态条件. 更多信息请参见 此页.

逐操作取消

该操作支持逐操作取消. 取消 async_get_connection 没有可观察的副作用. 支持以下 asio::cancellation_type_t 值:

  • asio::cancellation_type_t::terminal
  • asio::cancellation_type_t::partial
  • asio::cancellation_type_t::total
误差
  • client_errc::no_connection_available, 若 async_get_connection 操作在连接变为可用之前被取消.
  • client_errc::pool_not_running, 若 async_get_connection 操作在调用 async_run 之前被取消.
  • client_errc::pool_cancelled, 若池在操作完成之前被取消, 或对已取消的池调用了 async_get_connection.
线程安全

读取内部状态句柄. 修改池状态. 如果池构造时启用了线程安全, 它可以与不修改状态句柄的其他函数并发调用.
