pooled_connection

连接池所拥有连接的代理对象, 在销毁时将连接归还给连接池.

说明

pooled_connection 的行为类似于 std::unique_ptr: 它独占拥有一个由连接池创建的 any_connection. 销毁时, 它将连接归还给连接池. pooled_connection 也可能不拥有任何东西. 我们称这样的连接为无效 (this->valid() == false).

该类可移动但不可复制.

对象生命周期

只要 *this 存活, connection_pool 的内部数据就会被自动保持存活. 在 connection_pool 之前销毁 *this 对象是安全的.

线程安全

此对象与其可能指向的 any_connection 对象 不是线程安全的 , 即使用于获取它们的连接池在构造时将 pool_params::thread_safe 设为 true.

将底层连接归还连接池的函数会导致连接池状态对象的变更. 仅当连接池在构造时将 pool_params::thread_safe 设为 true, 对从同一连接池获取的对象调用此类函数才是线程安全的.

换言之, 各个连接不能在线程间共享. 仅当连接池在构造时将 pool_params::thread_safe 设为 true, 连接池才可以共享.

  • 不同对象: 若获取这些对象时所用的 connection_pool 在创建时将 pool_params::thread_safe 设为 true, 则安全. 否则不安全.
  • 共享对象: 始终不安全.
