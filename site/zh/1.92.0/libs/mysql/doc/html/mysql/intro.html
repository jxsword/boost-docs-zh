引言

Boost.MySQL 是面向 MySQL 和 MariaDB 数据库服务器的 C++11 客户端, 基于 Boost.Asio.

动机

MySQL 和 MariaDB 是广泛使用的 SQL 数据库服务器. MySQL 客户端连接到服务器以执行 SQL 查询. 为此, MySQL 使用一种专用协议. Boost.MySQL 是该协议客户端侧的一个实现.

本库是 MySQL 客户端/服务器协议 的完整实现. 它旨在以高效且易用的方式暴露协议原语. 其功能范围与官方的 libmysqlclient 类似, 但可与 Asio 互操作, 更安全且更具表现力. 注意, Boost.MySQL 不使用 libmysqlclient: 它是对 MySQL 协议的完整实现, 这使其天然兼容 Asio.

本库相对底层. 它让你可以访问文本 SQL 查询和预处理语句. 不要指望它是一个 ORM. 本节对库的主要功能做了一个快速导览.

本库的设计目标如下:

  • 与 Asio 互操作: 本库采用与 Boost.Asio 和 Boost.Beast 相同的原则. 任何这些库的用户都能立即理解 Boost.MySQL, 并能轻松将其集成到自己的程序中.
  • 进一步抽象的基础: 它允许高效访问 MySQL 客户端/服务器协议, 使其可以作为构建块被更高层的组件使用. 只做一件事, 并把它做好.
  • 高效率.
  • 易用性: MySQL 协议充满陷阱. 我们崇尚简洁. 在保留对重要部分的控制的同时, 库尽可能对用户隐藏协议的复杂性.

非目标:

  • 成为 ORM.
  • 成为 SQL 查询生成器. 本库不专注于生成查询的工具. 不要指望类似 table("orders").select(["id", "quantity"]).where("id", 42) 这样的语法糖.
  • 对其他 SQL 数据库的可移植性. 本库专注于 MySQL. 它不能与 Postgres 或 SQLite 一起使用.

何时使用

如果以下任何一条陈述成立, 你可以考虑使用 Boost.MySQL:

  • 你的应用使用 Boost.Asio 并且需要访问 MySQL 服务器.
  • 你需要从 C++ 应用异步访问 MySQL 服务器.
  • 你需要从 C++ 应用高效访问 MySQL 服务器.
  • 你需要一个采用 BSL 许可证的库来访问你的 MySQL 服务器.
  • 你正在编写更高层的数据库访问库, 例如 ORM.

用例可能包括 web 服务器、ETL 流程和 IoT 系统.

在以下情况下, 它可能不适合你:

  • 你只需要对 MySQL 服务器的同步访问, 且效率对你的应用无关紧要. 这种情况下, 官方客户端库可能更适合你.
  • 你需要对不同 SQL 数据库进行同构的 SQL 访问 (而不仅仅是 MySQL 访问). 使用 sqlpp11 或类似的封装库可能更有价值.

已测试的编译器与系统

Boost.MySQL 在以下编译器下测试:

  • gcc 5.4 至 gcc 15.0 (Linux)
  • clang 4 至 clang 20.0 (Linux)
  • Apple clang 14.0 (OSX)
  • MSVC 14.1 - Visual Studio 2017 (Windows)
  • MSVC 14.2 - Visual Studio 2019 (Windows)
  • MSVC 14.3 - Visual Studio 2022 (Windows)

以及以下 RDBMS 系统:

  • MySQL v5.7.41.
  • MySQL v8.4.1.
  • MariaDB v11.4.2.
