错误处理与可用重载

本节描述使用本库时可以采用的不同错误处理策略, 以及每个涉及网络传输的函数可用的不同重载.

本库使用 Boost.System 的错误码和异常, 与 Asio 和 Beast 相同. 某些服务器报告的错误可能包含额外的诊断信息. 例如, 如果发出一个查询而其引用的某个字段不存在, 服务器将返回一条错误消息, 指出是哪个字段出了问题. 本库通过以下类和函数提供这些诊断信息:

diagnostics

包含关于某个错误的额外诊断信息的对象. diagnostics::server_message 包含服务器生成的错误字符串 (如果有).

error_with_diagnostics

继承自 boost::system::system_error并包含一个 diagnostics对象的异常.

with_diagnostics

一种完成标记, 可将诊断信息嵌入异步函数抛出的异常中.

is_fatal_error

检查一个 error_code是否为 致命错误 (即需要重新建立连接).

每个涉及网络传输的功能都提供四种版本:

  • 同步, 使用异常. 失败时, 它们抛出 error_with_diagnostics 异常.
  • 同步, 使用 error_code 和 diagnostics. 这些函数通过左值引用输出一个 error_code和一个 diagnostics对象来报告失败.
  • 异步, 不带 diagnostics. 失败时, 它们以非空的 error_code调用完成处理器.
  • 异步, 带 diagnostics. 它们有一个 diagnostics&参数, 位于 CompletionToken之前. 失败时, 它们将 diagnostics参数设置为服务器提供的诊断信息 (如果有), 然后以非空的 error_code调用完成处理器.

致命错误与非致命错误

当已建立连接上的操作 (如查询执行) 出现错误时, 可能发生两种情况:

  • 连接对象处于一个明确已知的状态. 可以安全地使用该对象继续执行后续操作而没有问题. 例如, 如果一个查询因表名拼写错误而以 common_server_errc::er_no_such_table失败, 那么在失败的查询之后运行其他查询是安全的. 这类错误称为 非致命错误.
  • 连接对象处于未知状态. 后续操作将以不可预测的结果失败. 你应当关闭并重新建立连接. 这些是 致命错误, 包括协议错误和网络错误.

可以使用 is_fatal_error 来区分致命与非致命错误码.

诊断信息的安全注意事项

diagnostics::server_message 给出的错误消息 可能包含用户提供的输入, 应视为不可信. 对于某些错误, MySQL 服务器会包含出错的字段名和值, 其中可能包含任意输入. 请谨慎使用.

该消息可能包含非 ASCII 字符. 它使用连接的字符集编码.

使用 boost::system::result

某些函数 (例如 basic_format_context::get) 使用 boost::system::result<T> 来传递错误. result<T>要么包含一个值 (T的一个实例), 要么在操作失败时包含一个 error_code. result<T>与 std::expected类似, 但只需要 C++11.

给定一个 result<T>对象 r, 可以通过调用 r.value()来获取其包含的值. 如果 r包含错误, 将抛出携带所含错误码的 boost::system::result异常. r.has_value()、r.has_error()和 r.error()可用于检查该对象.
