any_connection::async_connect (2 个重载中的第 1 个)

建立与 MySQL 服务器的连接.

概要 
template<
    class CompletionToken = with_diagnostics_t<asio::deferred_t>>
auto
async_connect(
    const connect_params& params,
    diagnostics& diag,
    CompletionToken&& token = {});
说明

该函数执行以下操作:

  • 如果已经建立过连接 (通过之前对 connect 或 async_connect 的调用), 则在传输层将其关闭 (通过关闭所有底层套接字), 并丢弃与其关联的所有协议状态. (如果你需要干净关闭, 请在使用该函数前调用 close 或 async_close).
  • 如果连接被配置为使用 TCP (params.server_address.type() == address_type::host_and_port), 则将传入的主机名解析为一组端点. 空主机名等价于 "localhost".
  • 建立物理连接 (执行 TCP 或 UNIX 套接字连接).
  • 执行 MySQL 握手以建立会话. 如果连接被配置为使用 TLS, TLS 握手会作为此步骤的一部分执行.
  • 如果以上任何步骤失败, TCP 或 UNIX 套接字连接将被关闭.

可以使用 connect_params 结构配置一些选项.

是否使用 TLS 按以下规则决定:

  • 如果传输方式不是 TCP (params.server_address.type() != address_type::host_and_port), 连接将永远不会使用 TLS.
  • 如果传输方式是 TCP 且 params.ssl == ssl_mode::disable, 连接将不使用 TLS.
  • 如果传输方式是 TCP 且 params.ssl == ssl_mode::enable, 仅当服务器支持时连接才会使用 TLS.
  • 如果传输方式是 TCP 且 params.ssl == ssl_mode::require, 连接将始终使用 TLS. 如果服务器不支持, 操作将以 client_errc::server_doesnt_support_ssl 失败.

如果 params.connection_collation 属于一组已知排序规则, 该函数会设置当前字符集, 使 current_character_set 返回非空值. 默认排序规则 (utf8mb4_general_ci) 是唯一保证位于已知排序规则集合中的.

对象生命周期

在操作完成之前必须保持 params 存活, 因为库不会制作副本.

处理器签名

该操作的处理器签名是 void(boost::mysql::error_code).

Executor

中间完成处理器以及最终处理器都使用 token 的关联执行器执行, 若该标记没有关联执行器则使用 this->get_executor().

如果最终处理器有关联的立即执行器且操作立即完成, 最终处理器会被派发给它. 否则, 最终处理器的调用方式如同通过 asio::post 提交, 且绝不会在该函数内被内联调用.
