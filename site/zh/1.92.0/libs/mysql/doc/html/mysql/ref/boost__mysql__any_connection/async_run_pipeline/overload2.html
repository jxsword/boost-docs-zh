any_connection::async_run_pipeline (2 个重载中的第 2 个)

运行一组以管道方式发送的请求.

概要 
template<
    class CompletionToken = with_diagnostics_t<asio::deferred_t>>
auto
async_run_pipeline(
    const pipeline_request& req,
    std::vector< stage_response >& res,
    diagnostics& diag,
    CompletionToken&& token = {});
说明

运行 req 所描述的管道, 并将其响应存储在 res 中. 操作完成后, res 将包含与 req 中阶段数相同的元素, 即使操作失败也是如此.

服务器将请求阶段视为一系列互不相关的请求. 因此, 即使前面的阶段失败, 所有阶段也总是会被执行.

如果所有阶段都成功, 操作将成功完成. 因此, 若此操作成功完成, 则无需检查 res 中的逐阶段错误码.

如果任何阶段以非致命错误失败 (依据 is_fatal_error), 操作的结果是首个遇到的错误. 可以通过检查 res 中的每个阶段来确定哪些阶段成功、哪些失败.

如果任何阶段以致命错误失败, 操作的结果是该致命错误. 后续阶段将被标记为以该致命错误失败. 服务器可能已处理或未处理这些阶段.

处理器签名

该操作的处理器签名是 void(boost::mysql::error_code).

Executor

中间完成处理器以及最终处理器都使用 token 的关联执行器执行, 若该标记没有关联执行器则使用 this->get_executor().

如果最终处理器有关联的立即执行器且操作立即完成, 最终处理器会被派发给它. 否则, 最终处理器的调用方式如同通过 asio::post 提交, 且绝不会在该函数内被内联调用.

对象生命周期

请求和响应对象必须保持存活, 且在操作完成之前不应被修改.
