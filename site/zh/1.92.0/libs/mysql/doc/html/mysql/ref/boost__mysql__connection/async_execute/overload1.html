connection::async_execute (2 个重载中的第 1 个)

执行文本查询或预处理语句.

概要 
template<
    class ExecutionRequest,
    class ResultsType,
    class CompletionToken>
auto
async_execute(
    ExecutionRequest&& req,
    ResultsType& result,
    CompletionToken&& token);
说明

将 req 发送到服务器执行, 并将响应读入 result. result 可以是 results 或 static_results 对象. req 应当是可转换为 string_view 的、包含合法 SQL 的类型, 或通过调用 statement::bind 得到的已绑定预处理语句. 如果是字符串, 必须使用连接的字符集编码. 提供给 statement::bind 的任何字符串参数也应使用连接的字符集编码.

此操作成功完成后, result.has_value() == true.

result 中的元数据将按 this->meta_mode() 填充.

对象生命周期

如果 CompletionToken 是延迟完成标记 (例如 use_awaitable), 调用者需按以下规则负责管理 req 的有效性:

  • 如果 req 是 string_view, 则 req 所指向的字符串必须由调用者保持存活, 直到操作被发起.
  • 如果 req 是 bound_statement_tuple 且任一参数是引用类型 (如 string_view), 调用者必须保持这些引用所指向的值存活, 直到操作被发起.
  • 如果 req 是 bound_statement_iterator_range, 调用者必须保持传给 statement::bind 的迭代器范围中的对象存活, 直到操作被发起.
处理器签名

该操作的处理器签名是 void(boost::mysql::error_code).

Executor

中间完成处理器以及最终处理器都使用 token 的关联执行器执行, 若该标记没有关联执行器则使用 this->get_executor().

如果最终处理器有关联的立即执行器且操作立即完成, 最终处理器会被派发给它. 否则, 最终处理器的调用方式如同通过 asio::post 提交, 且绝不会在该函数内被内联调用.
