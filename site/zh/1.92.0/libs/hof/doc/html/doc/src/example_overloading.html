条件重载¶

条件重载接受一组函数, 并调用其中第一个可调用的函数. 这是解决重载歧义的方式之一, 但更重要的是, 它允许在第一个函数不可调用时使用替代函数.

Stringify¶

请看这个在 stackoverflow 上定义 stringify 函数的示例 此处.

用户希望编写 stringify, 在适用时调用 to_string, 并回退到使用 sstream 转换为字符串. 多数最佳答案通常涉及一定量的元编程, 使用 void_t 或 is_detected (见 n4502):

template<class T>
using to_string_t = decltype(std::to_string(std::declval<T>()));

template<class T>
using has_to_string = std::experimental::is_detected<to_string_t, T>;

template<typename T> 
typename std::enable_if<has_to_string<T>{}, std::string>::type 
stringify(T t)
{
    return std::to_string(t);
}
template<typename T> 
typename std::enable_if<!has_to_string<T>{}, std::string>::type 
stringify(T t)
{
    return static_cast<std::ostringstream&>(std::ostringstream() << t).str();
}

不过, 使用 Boost.HigherOrderFunctions 可以简单地写成这样:

BOOST_HOF_STATIC_LAMBDA_FUNCTION(stringify) = first_of(
    [](auto x) BOOST_HOF_RETURNS(std::to_string(x)),
    [](auto x) BOOST_HOF_RETURNS(static_cast<std::ostringstream&>(std::ostringstream() << x).str())
);

因此, 使用 BOOST_HOF_RETURNS 不仅推导函数的返回类型, 还根据表达式是否有效来约束函数. 于是, 通过编写 BOOST_HOF_RETURNS(std::to_string(x)), 第一个函数会尽可能调用 std::to_string 函数. 若不可能, 则调用第二个函数.

第二个函数仍使用 BOOST_HOF_RETURNS, 因此该函数仍受 << 流运算符是否可用这一条件的约束. 虽然因为已经没有其他函数, 这似乎没有必要, 但这使函数可组合. 于是我们可以用它定义一个 serialize 函数: 先尝试调用 stringify, 否则查找成员 .serialize():

BOOST_HOF_STATIC_LAMBDA_FUNCTION(serialize) = first_of(
    [](auto x) BOOST_HOF_RETURNS(stringify(x)),
    [](auto x) BOOST_HOF_RETURNS(x.serialize())
);

static_if¶

此外, 这可以与 boost::hof::if_ 装饰器配合, 在 C++17 之前的编译器上创建类似 static_if 的构造. 例如, Baptiste Wicht 讨论了如何在 C++ 中编写 static_if, 见 此处.

他希望能够这样写:

template<typename T>
void decrement_kindof(T& value){
    if constexpr(std::is_same<std::string, T>()){
        value.pop_back();
    } else {
        --value;
    }
}

然而, 在 C++17 之前这不可能. 使用 Boost.HigherOrderFunctions 可以简单地写成这样:

template<typename T>
void decrement_kindof(T& value)
{
    eval(first_of(
        if_(std::is_same<std::string, T>())([&](auto id){
            id(value).pop_back();
        }),
        [&](auto id){
            --id(value);
        }
    ));
}

传递给 lambda 的 id 参数是 identity 函数. 如该文所述, 通过把它变成依赖类型 (即类型依赖于模板参数) 来延迟类型查找, 这是避免编译错误所必需的. 被调用的 eval 函数会把这个 identity 函数传递给各个 lambda.

使用 Boost.HigherOrderFunctions 而不是 Baptiste Wicht 博客中的解决方案, 其优点是 first_of 允许不止两个条件. 因此, 若还有另一个要检查的特征, 如 is_stack, 可以这样写:

template<typename T>
void decrement_kindof(T& value)
{
    eval(first_of(
        if_(is_stack<T>())([&](auto id){
            id(value).pop();
        }),
        if_(std::is_same<std::string, T>())([&](auto id){
            id(value).pop_back();
        }),
        [&](auto id){
            --id(value);
        }
    ));
}

类型特征¶

此外, 该技术也可用于编写类型特征. Jens Weller 当时在寻找一种为指针操作数 (如 * 和 ->) 定义通用检测的方法. 实现方式之一如下:

// Check that T has member function for operator* and ope
template<class T>
auto has_pointer_member(const T&) -> decltype(
    &T::operator*,
    &T::operator->,
    std::true_type{}
);

BOOST_HOF_STATIC_LAMBDA_FUNCTION(has_pointer_operators) = first_of(
    BOOST_HOF_LIFT(has_pointer_member),
    [](auto* x) -> bool_constant<(!std::is_void<decltype(*x)>())> { return {}; },
    always(std::false_type{})
);

template<class T>
struct is_dereferenceable
: decltype(has_pointer_operators(std::declval<T>()))
{};

这比已写出的其他实现简单得多, 后者的代码量约为 3 倍 (见 此处).

has_pointer_operators 函数的工作方式是: 首先尝试调用 has_pointer_member, 它会返回 true_type —— 前提是该类型拥有成员函数 operator* 与 operator->, 否则该函数不可调用. 下一个函数仅对指针可调用, 若它不是 void* 指针则返回 true (因为 void* 指针不可解引用). 最后, 若这些函数都不匹配, 最后一个函数将总是返回 false_type.
