更多示例¶

由于 Boost.HigherOrderFunctions 是与函数相关的泛型工具集合, 它有许多有用的用例; 而这些工具的关键点之一是: 它们可以用比传统元编程简单得多的构造解决这些问题. 让我们看看使用 Boost.HigherOrderFunctions 的一些用例.

初始化¶

BOOST_HOF_STATIC_FUNCTION 有助于在全局作用域初始化函数对象, 并确保它在编译期被初始化, 且 (在支持该能力的平台上) 在各翻译单元间具有唯一地址, 从而减少可执行文件膨胀与潜在的 ODR 违例.

此外, BOOST_HOF_STATIC_LAMBDA_FUNCTION 允许以同样的方式初始化 lambda. 这使得在使用泛型 lambda 与函数适配器时, 函数定义可以简单而紧凑.

当然, 对于偏好避免全局函数对象的用户, 不使用全局函数对象也能使用本库, 他们仍会觉得本库有用.

投影¶

与其在算法中多次书写投影 (projection):

std::sort(std::begin(people), std::end(people),
          [](const Person& a, const Person& b) {
            return a.year_of_birth < b.year_of_birth;
          });

我们可以使用 proj 适配器把 year_of_birth 投影到比较运算符上:

std::sort(std::begin(people), std::end(people),
        proj(&Person::year_of_birth, _ < _));

实参求值排序¶

当我们写 f(foo(), bar()) 时, 标准不保证 foo() 与 bar() 实参的求值顺序. 因此借助 apply_eval, 我们可以把它们按从左到右排序:

apply_eval(f, [&]{ return foo(); }, [&]{ return bar(); });

扩展方法¶

把许多函数链接在一起 (像基于范围的库所做的那样) 会让人难以阅读:

auto r = transform(
    filter(
        numbers,
        [](int x) { return x > 2; }
    ),
    [](int x) { return x * x; }
);

若能这样写就好了:

auto r = numbers
    .filter([](int x) { return x > 2; })
    .transform([](int x) { return x * x; });

统一调用语法 (UFCS) 提案 N4165 本可允许把 x.f(y) 的函数调用变为 f(x, y). 然而, 该提案被委员会否决了. 因此, 可以改用可管道化函数来实现扩展方法. 于是可以这样写:

auto r = numbers
    | filter([](int x) { return x > 2; })
    | transform([](int x) { return x * x; });

现在, 若有些用户对重载 按位或 运算符略感担忧, 可管道化函数也可以配合 flow 使用, 像这样:

auto r = flow(
    filter([](int x) { return x > 2; }),
    transform([](int x) { return x * x; })
)(numbers);

没有花哨或令人困惑的运算符重载, 一切仍然相当可读.
