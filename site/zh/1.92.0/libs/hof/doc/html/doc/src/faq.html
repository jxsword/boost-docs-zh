常见问题 (FAQ)¶

问: 为什么函数对象上的调用运算符要求 const?¶

可变 (mutable) 函数对象并非被禁止, 它们只需要通过 mutable_ 适配器显式声明. 这样做的主要原因是它可能导致许多令人意外 (surprising) 的行为. 函数对象在很多时候都以值复制的方式到处传递. 例如,

struct counter
{
    int i;
    counter() : i(0)
    {}

    template<class... Ts>
    int operator()(Ts&&...)
    {
        return i++;
    }
};


counter c{};
proj(mutable_(c))(1,1);
// Prints 0, not 2
std::cout << c.i << std::endl;

该示例永远不会产生期望的值, 因为函数修改的是对象的一个副本. 相反, 应使用 std::ref:

counter c{};
proj(std::ref(c))(1,1);
// Prints 2
std::cout << c.i << std::endl;

这将打印期望的值.

要求 const 的另一个原因是为了在 C++11 编译器上支持 constexpr. 在 C++11 中, constexpr 蕴含 const, 因而不可能为 constexpr 的函数提供非 const 重载. 相反, constexpr 必须显式写出. 考虑到可变函数对象的种种陷阱, 让可变性显式化比 constexpr 更好.

问: BOOST_HOF_STATIC_LAMBDA 中的 reinterpret 转换是否未定义行为?¶

并不是, 因为这些对象是空的, 不存在数据访问. 库中有静态断言来防止违反这一限制.

当然, 可能存在某种疯狂实现导致这不起作用 (也许 lambda 因某种奇怪的原因非空), 那时本库将不得不采用其他技术使其工作. 不过, 考虑到 C++ 未来大概率会引入 constexpr lambda 与内联变量, 这种情况相当不可能.

或者, 可以改用工厂模式代替 BOOST_HOF_STATIC_LAMBDA_FUNCTION, 它不需要 reinterpret 转换:

struct sum_factory
{
    auto operator*() const
    {
        return [](auto x, auto y)
        {
            return x + y;
        };
    }
}

BOOST_HOF_STATIC_FUNCTION(sum) = boost::hof::indirect(sum_factory{});
