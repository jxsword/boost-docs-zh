入门¶

高阶函数¶

本库的核心部分是高阶函数. 高阶函数是接受函数作为实参或返回函数的函数. 为了能定义高阶函数, 我们必须能把函数当作一等对象来引用. 高阶函数的一个例子是 std::accumulate. 它接受一个自定义二元运算符作为参数.

引用函数的一种方式是使用函数指针 (或成员函数指针). 因此, 若我们有自己的自定义 sum 函数, 可以把它直接传给 std::accumulate:

int sum(int x, int y)
{
    return x + y;
}
// Pass sum to accumulate
std::vector<int> v = { 1, 2, 3 };
int total = std::accumulate(v.begin(), v.end(), 0, &sum);

然而, 函数指针只能引用函数重载集中的一个函数, 并且需要显式转换来选定那个重载.

例如, 若我们有一个模板化的 sum 函数想要传给 std::accumulate, 就需要显式转换:

template<class T, class U>
auto sum(T x, U y)
{
    return x + y;
}

auto sum_int = (int (*)(int, int))&sum;
// Call integer overload
int i = sum_int(1, 2);
// Or pass to an algorithm
std::vector<int> v = { 1, 2, 3 };
int total = std::accumulate(v.begin(), v.end(), 0, sum_int);

函数对象¶

函数对象允许把整个重载集封装到一个对象中. 这可以通过定义一个重载调用运算符的类来实现, 像这样:

// A sum function object
struct sum_f
{
    template<class T, class U>
    auto operator()(T x, U y) const
    {
        return x + y;
    }
};

关于这一点有几点要注意. 首先, 调用运算符成员函数总是声明为 const, 这通常是配合 Boost.HigherOrderFunctions 使用所要求的. (注: mutable_ 适配器可用于让可变函数对象拥有 const 调用运算符, 但一般应避免这样做). 其次, sum_f 类必须先构造才能调用:

auto sum = sum_f();
// Call sum function
auto three = sum(1, 2);
// Or pass to an algorithm
std::vector<int> v = { 1, 2, 3 };
int total = std::accumulate(v.begin(), v.end(), 0, sum);

由于该函数是模板化的, 它可以对任何具有加法 + 运算符的类型调用, 而不只是整数. 此外, sum 变量可用来引用整个重载集.

提升函数¶

定义函数对象的另一种替代方式, 是用 BOOST_HOF_LIFT 提升模板化函数. 这会把整个重载集变成一个类似函数对象的对象:

template<class T, class U>
auto sum(T x, U y)
{
    return x + y;
}

// Pass sum to an algorithm
std::vector<int> v = { 1, 2, 3 };
int total = std::accumulate(v.begin(), v.end(), 0, BOOST_HOF_LIFT(sum));

然而, 由于 C++14 的限制, 这不会保留 constexpr. 在这些情形下, 最好使用函数对象.

声明函数¶

现在, 这对局部函数很有用. 然而, 很多时候我们想编写函数并让他人可用. Boost.HigherOrderFunctions 提供 BOOST_HOF_STATIC_FUNCTION, 用于在全局或命名空间作用域声明函数对象:

BOOST_HOF_STATIC_FUNCTION(sum) = sum_f();

BOOST_HOF_STATIC_FUNCTION 按 N4381 概述的最佳实践声明全局变量. 这包括使用 const 来避免全局状态, 在编译期初始化函数对象以避免 静态初始化顺序灾难, 以及让函数对象的外部地址在各个翻译单元之间相同, 以避免可能的单一定义规则 (ODR) 违例. 在 C++17 中, 这可以用 inline 变量实现:

inline const constexpr auto sum = sum_f{};

BOOST_HOF_STATIC_FUNCTION 宏提供了一种可移植的方式来做到这一点, 它支持 C++17 之前的编译器与 MSVC.

适配器¶

现在我们已把函数定义为函数对象, 可以为该函数添加新的 "增强". 一种增强是编写 "扩展" 方法. 统一调用语法 (UFCS) 提案 N4165 本可允许把 x.f(y) 的函数调用变为 f(x, y). 由于 C++ 没有 UFCS, 我们可以改用可管道化 (pipable) 函数, 它会把 x | f(y) 转换为 f(x, y). 要让 sum_f 函数变为可管道化, 使用 pipable 适配器, 我们只需写:

BOOST_HOF_STATIC_FUNCTION(sum) = pipable(sum_f());

然后参数可以通过管道传入, 像这样:

auto three = 1 | sum(2);

可管道化函数可以像 . 运算符一样多次链接:

auto four = 1 | sum(2) | sum(1);

或者, 不使用 | 运算符, 可管道化函数也可以用 flow 适配器链接在一起:

auto four = flow(sum(2), sum(1))(1);

对函数可做的另一种增强, 是使用 infix 适配器定义具名中缀运算符:

BOOST_HOF_STATIC_FUNCTION(sum) = infix(sum_f());

并且可以这样调用:

auto three = 1 <sum> 2;

此外, 还提供了支持简单函数式运算 (如 部分应用 与 函数组合) 的适配器:

auto add_1 = partial(sum)(1);
auto add_2 = compose(add_1, add_1);
auto three = add_2(1);

Lambda¶

编写函数对象可能有点冗长. C++ 提供 lambda, 它用于定义函数的语法简洁得多. 当然, lambda 可以与本库所有适配器配合, 然而, 若我们想用 lambda 声明函数, BOOST_HOF_STATIC_FUNCTION 不起作用. 作为替代, 可以用 BOOST_HOF_STATIC_LAMBDA_FUNCTION 把 lambda 声明为函数, 这会在编译期初始化该函数并避免可能的 ODR 违例:

BOOST_HOF_STATIC_LAMBDA_FUNCTION(sum) = [](auto x, auto y)
{
    return x + y;
};

此外, 还可以使用适配器, 因此 sum 的可管道化版本可以这样写:

// Pipable sum
BOOST_HOF_STATIC_LAMBDA_FUNCTION(sum) = pipable([](auto x, auto y)
{
    return x + y;
});
