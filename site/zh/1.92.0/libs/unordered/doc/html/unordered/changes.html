变更日志

1.92.0 发布

  • 为库中的所有容器添加了与 C++20 范围 (ranges) 的互操作性: insert_range (并发容器另有 insert_range_(or|and)_[c]visit), std::from_range 构造及相关的 CTAD 推导指引. 提供 boost::unordered::from_range 构造标签是为了作为 C++23 std::from_range 的替代, 或在该特性不可用时使用.

  • 修复了封闭寻址容器在超大容器规模下重新哈希时的性能问题 (PR#348). 由 Daniel Král 贡献.

1.91.0 发布

  • 修复了并发容器中范围插入的返回值 (PR#344).

1.89.0 发布

  • 已弃用的 boost::unordered::hash_is_avalanching 现在等价于 boost::hash_is_avalanching 位于 <boost/container_hash/hash_is_avalanching.hpp> 中的一条 using 声明. 请改为直接使用该头文件. <boost/unordered/hash_traits.hpp> 将来会被移除.

  • 为开放寻址容器添加了 pull(const_iterator). 该操作支持通过移动构造高效地移除并取回元素.

1.88.0 发布

  • 使用 Antora 将文档迁移为多页面格式.

1.87.0 发布 - 重大更新

  • 添加了基于节点的并发容器 boost::concurrent_node_map 和 boost::concurrent_node_set.

  • 为并发容器添加了 insert_and_visit(x, f1, f2) 及类似操作, 允许在插入之后立即访问该元素 (相比之下, insert_or_visit(x, f) 仅在 未 发生插入时才访问元素).

  • 在某些 boost::concurrent_flat_set 操作中将访问改为排他锁定, 以支持对元素进行安全的可变修改 (PR#265).

  • 在 Visual Studio Natvis 中, 支持分配器使用花式指针 (fancy pointer) 的任意容器. 这适用于任何花式指针类型, 只要为该花式指针类型编写了相应的 Natvis 定制点 "Intrinsic" 函数即可.

  • 为所有容器和迭代器添加了 GDB pretty-printer. 对于分配器使用花式指针的容器, 只有当为该花式指针类型本身编写了相应的 pretty-printer 时, 这些工具才能工作.

  • 修复了开放寻址容器的 std::initializer_list 赋值问题 (PR#277).

  • 现在允许把不可复制的可调用对象传递给 std::initializer_list 重载 (用于并发容器 insert_{and|or}_[c]visit), 做法是在内部将该可调用对象的 std::reference_wrapper 传递给迭代器对重载.

1.86.0 发布

  • 添加了容器别名 pmr (在头文件 <memory_resource> 可用时). 别名 boost::unordered::pmr::[container] 指的是 boost::unordered::[container] (带有 std::pmr::polymorphic_allocator 分配器类型).

  • 使开放寻址容器和并发容器能够在内部计算并提供受哈希函数质量影响的统计指标. 该功能由全局宏 BOOST_UNORDERED_ENABLE_STATS 启用.

  • 雪崩式哈希函数 (avalanching hash function) 现在必须通过一个 is_avalanching typedef 来标记, 其内嵌的 value 常量设为 true (通常是将 is_avalanching 定义为 std::true_type). using is_avalanching = void 已弃用, 但为了向后兼容仍然允许.

  • 为容器和迭代器添加了 Visual Studio Natvis 框架的自定义可视化. 这适用于所有分配器使用裸指针的容器. 在本发布中, 分配器使用花式指针的容器和迭代器尚不受支持. 后续发布可能会解决此问题.

1.85.0 发布

  • 优化了 emplace() 在 value_type 或 init_type (如适用) 参数下的表现, 以跳过中间对象的创建. 此时参数本身已经是与原本会创建的中间对象相同的类型.

  • 优化了 emplace() 对 map 容器 k,v 参数的处理, 将对象的构造推迟到确定应插入元素之时. 当 map 的 key_type 可移动构造, 或 k 参数是 key_type 时, 会进行此优化.

  • 修复了对带有 explicit 复制构造函数的分配器的支持 (PR#234).

  • 修复了 const 版本的 unordered_multimap::find(k, hash, eq) 中的缺陷 (PR#238).

1.84.0 发布 - 重大更新

  • 添加了 boost::concurrent_flat_set.

  • 为并发容器添加了 [c]visit_while 操作, 包括串行和并行两种变体.

  • 添加了 boost::unordered_flat_(map|set) 从 boost::concurrent_flat_(map|set) (以及反向) 的高效移动构造.

  • 为并发容器添加了批量访问, 以提升查找性能.

  • 添加了调试模式机制, 用于检测用户代码对并发容器的非法重入.

  • 为所有容器及其 (非局部) 迭代器类型添加了 Boost.Serialization 支持.

  • 为开放寻址容器和并发容器添加了对花式指针的支持. 这使得诸如使用 Boost.Interprocess 分配器在共享内存中构造容器之类的场景成为可能.

  • 修复了封闭寻址容器的局部迭代器的成员指针访问运算符中的缺陷 (PR#221, 感谢 GitHub 用户 vslashg 发现并修复此问题).

  • 从本发布开始, boost::unordered_[multi]set 和 boost::unordered_[multi]map 仅支持 C++11 及以上版本.

1.83.0 发布 - 重大更新

  • 添加了 boost::concurrent_flat_map, 一个基于开放寻址的快速线程安全哈希映射.

  • 加快了开放寻址容器的迭代速度.

  • 在开放寻址容器中, erase(iterator) 此前不返回任何值, 现在返回一个可转换为指向下一个元素的迭代器的代理对象. 这使得典型的 it = c.erase(it) 惯用法成为可能, 且在不使用返回的代理对象时不会带来任何性能损失.

1.82.0 发布 - 重大更新

  • 计划弃用 C++03 支持. Boost 1.84.0 将不再支持 C++03 模式, C++11 将成为使用本库的最低要求.

  • 添加了基于节点的开放寻址容器 boost::unordered_node_map 和 boost::unordered_node_set.

  • 按照 P2363 的规定, 将异构查找扩展到更多成员函数.

  • 用一种基于扩展常数乘法的新算法取代了开放寻址容器原先的后混合 (post-mixing) 过程.

  • 修复了内部 emplace() 实现中的缺陷: 栈上局部类型此前未使用容器的 Allocator 正确构造, 这会破坏 uses-allocator 构造.

1.48.0 发布 - 重大更新

这是一项重大变更, 已转换为使用 Boost.Move 的移动仿真, 并更加符合 C++11 标准. 详情参见 符合性一节.

容器现在满足 C++11 的复杂度要求, 但为此要多使用一些内存. 这意味着不再需要 quick_erase 和 erase_return_void, 它们将在未来版本中被移除.

C++11 支持带来了一些破坏性变更:

  • 相等比较已改为 C++11 规范. 在具有等价键的容器中, 键相等的元素组内元素过去必须保持相同顺序才视为相等, 现在它们可以是彼此的排列. 要使用旧的行为, 请定义宏 BOOST_UNORDERED_DEPRECATED_EQUALITY.

  • 当待交换的两个容器具有不相等的分配器时, swap 的行为有所不同. 过去会使用相应的分配器分配新节点, 现在如果分配器具有成员结构 propagate_on_container_swap 且使 propagate_on_container_swap::value 为真, 则直接交换分配器.

  • 分配器的 construct 和 destroy 函数现在以裸指针调用, 而不是以分配器的 pointer 类型调用.

  • emplace 过去模拟了早期 C++0x 草案中出现的可变参数 pair 构造函数. 由于它们已被移除, 现在不再模拟. 它确实模拟了新的 piecewise_construct pair 构造函数——只是你需要使用 boost::piecewise_construct. 要使用旧的可变参数构造函数模拟, 请定义 BOOST_UNORDERED_DEPRECATED_PAIR_CONSTRUCT.

1.41.0 发布 - 重大更新

  • 最初的版本大量使用宏来规避一些较旧编译器糟糕的模板支持. 但由于我不再支持那些编译器, 而宏的使用也开始成为维护负担, 因此实现类被重写为使用模板而非宏.

1.38.0 发布

  • 使用 boost::swap.

  • Ticket 2237: 在文档中说明: 若两个对象的相等谓词不等价, 则这两个对象的相等与不等运算符未定义. 感谢 Daniel Krügler.

  • Ticket 1710: 使用更大的质数列表. 感谢 Thorsten Ottosen 和 Hervé Brönnimann.

  • 使用 aligned storage 存储类型. 这改变了使用分配器构造节点的方式. 过去通过两次调用分配器的 construct 方法来构造节点——一次用于指针, 一次用于值. 现在只通过一次 construct 调用来构造节点, 然后使用就地构造 (in place construction) 构造值.
