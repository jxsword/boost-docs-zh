标准符合性

封闭寻址容器

boost::unordered_[multi]set 和 boost::unordered_[multi]map 为 C++11 (或更高) 编译器提供了 C++ 无序关联容器最新标准修订版的符合性实现, 仅存在下文所述的极小偏差. 这些容器完全满足 AllocatorAware 要求, 并支持 花式指针.

推导指引

类模板实参推导 (CTAD) 的推导指引仅在 C++17 (或更高) 编译器上可用.

分段 pair 构造

按照标准规范, boost::unordered_[multi]map::emplace 支持分段 pair 构造:

boost::unordered_multimap<std::string, std::complex> x;

x.emplace(
    std::piecewise_construct,
    std::make_tuple("key"), std::make_tuple(1, 2));

此外, 还通过非标准的 boost::unordered::piecewise_construct 和 Boost.Tuple 提供相同的功能:

x.emplace(
    boost::unordered::piecewise_construct,
    boost::make_tuple("key"), boost::make_tuple(1, 2));

此功能为与 Boost.Unordered 早期版本向后兼容而保留: 建议用户更新代码, 改用 std::piecewise_construct 和 std::tuple.

Swap

交换时, Pred 和 Hash 目前不会通过调用 swap 来交换, 而是使用其复制构造函数. 因此, 交换时可能会从它们的复制构造函数抛出异常.

开放寻址容器

C++ 标准目前没有提供任何可遵循的开放寻址容器规范, 因此 boost::unordered_flat_set/unordered_node_set 和 boost::unordered_flat_map/unordered_node_map 分别从 std::unordered_set 和 std::unordered_map 中汲取灵感, 并在方便之处或由其内部数据结构 (与标准强制的封闭寻址结构截然不同) 决定之处偏离其接口.

Boost.Unordered 提供的开放寻址容器只能在相当符合标准的 C++11 (或更高) 编译器上工作. 移动语义、可变参数模板参数等语言级特性因此不作仿真. 这些容器完全满足 AllocatorAware 要求, 并支持 花式指针.

与 C++ 无序关联容器的主要差异如下:

  • 总体而言:

    • begin() 不是常量时间.

    • erase(iterator) 不返回指向下一个元素的迭代器, 而是返回一个代理对象, 需要时可转换为该迭代器; 这避免了在不需要时执行可能代价高昂的迭代器递增操作.

    • 没有用于桶处理的 API (bucket_count 除外).

    • 容器的最大负载因子由内部管理, 用户无法设置. 通过公开函数 max_load 暴露的最大负载, 在高负载条件下擦除元素时可能减小.

  • 平坦容器 (boost::unordered_flat_set 和 boost::unordered_flat_map):

    • value_type 必须可移动构造.

    • 重新哈希时不保持指针稳定性.

    • 没有用于节点提取/插入的 API.

并发容器

C++ 标准目前对此类或其他任何并发数据结构均无规范. boost::concurrent_flat_set/boost::concurrent_node_set 和 boost::concurrent_flat_map/boost::concurrent_node_map 的 API 分别仿照 std::unordered_flat_set 和 std::unordered_flat_map 建模, 关键差异在于不提供迭代器——因为迭代器在并发场景中存在固有问题 (高争用, 易死锁): 因此, Boost.Unordered 并发容器在技术上并不是 Container 的模型, 但除了隐含迭代器的那些要求之外, 它们满足 AllocatorAware 容器的全部要求 (包括 花式指针 支持).

在非并发的无序容器中, 迭代器有两个主要用途:

  • 访问先前通过查找定位的元素.

  • 容器遍历.

Boost.Unordered 并发容器不使用迭代器, 而是使用 内部访问 设施作为线程安全的替代. 返回指向容器中已有元素的迭代器的经典操作, 例如:

iterator find(const key_type& k);
std::pair<iterator, bool> insert(const value_type& obj);

被改造为接受一个传入该元素的 访问函数:

template<class F> size_t visit(const key_type& k, F f);
template<class F> bool insert_or_visit(const value_type& obj, F f);

(在第二种情况下, f 仅在表中存在等价于 obj 的元素时才会被调用, 而不是在插入成功时). 容器遍历由以下操作提供:

template<class F> size_t visit_all(F f);

在实现了标准并行算法的 C++17 编译器上, 这些操作还有并行化版本. 总体而言, 并发容器的接口由对应的非并发版本接口派生而来, 方法是在适用之处以访问替代迭代器, 过程相当直接. 对于常规 map, iterator 和 const_iterator 分别提供对元素的可变访问和 const 访问; 而在这里, 访问函数获得可变访问还是 const 访问取决于所用成员函数的常量性 (还有用于显式 const 访问的 *cvisit 重载); 对于 boost::concurrent_flat_set, 访问总是 const.

boost::concurrent_flat_map/boost::concurrent_node_map 未提供的一个值得注意的操作是 operator[]/at, 它可以由 try_emplace_or_visit 以更曲折的方式取代.
