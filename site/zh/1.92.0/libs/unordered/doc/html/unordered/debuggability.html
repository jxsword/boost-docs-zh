可调试性

Visual Studio Natvis

所有容器和迭代器在 Natvis 框架中都有自定义可视化.

在你的项目中使用

要在你的项目中通过 Natvis 框架可视化 Boost.Unordered 容器, 只需将文件 /extra/boost_unordered.natvis 作为 "Existing Item" 添加到你的 Visual Studio 项目中.

可视化结构

这些可视化与标准无序容器的可视化一致. 一个容器一次最多显示 100 个元素. 每个 set 元素的条目名称列为 [i], 其中 i 是显示中的索引, 从 0 开始. 每个 map 元素的条目名称默认列为 [{key-display}]. 例如, 如果第一个元素是 pair ("abc", 1), 条目名称将是 ["abc"]. 可以通过使用视图 "ShowElementsByIndex" 改变这一行为, 该视图将 map 的显示行为切换为按索引命名元素. 标准无序容器也使用同样的视图名.

默认情况下, 封闭寻址容器会显示 [hash_function] 和 [key_eq], (如适用时) [spare_hash_function] 和 [spare_key_eq], [allocator], 以及各元素. 使用视图 "detailed" 会额外显示 [bucket_count] 和 [max_load_factor]. 反之, 使用视图 "simple" 则只显示元素, 不显示其他条目.

默认情况下, 开放寻址容器会显示 [hash_function]、[key_eq]、[allocator] 以及各元素. 使用视图 "simple" 则只显示元素, 不显示其他条目. SIMD 和非 SIMD 实现均可通过 Natvis 框架查看.

迭代器的显示方式与其标准对应物类似. 迭代器显示为其所指向的元素的样子. 尾后迭代器则简单显示为 { end iterator }.

花式指针

如果你的分配器使用了花式指针 (例如 boost::interprocess::offset_ptr), 容器可视化同样有效. 虽然这种情况很少见, 但 Boost.Unordered 提供了 natvis 定制点以支持任何类型的花式指针. boost::interprocess::offset_ptr 的支持已在 Boost.Interprocess 库中定义, 你也可以按照文件 /extra/boost_unordered.natvis 末尾附近注释中的说明为自己的类型添加支持.

GDB Pretty-Printer

所有容器和迭代器都有自定义的 GDB pretty-printer.

在你的项目中使用

使用 pretty-printer 时, 始终必须像下面这样启用 pretty-printing. 这通常是一次性设置.

(gdb) set print pretty on

默认情况下, 如果你编译为 ELF 二进制格式, 你的二进制文件将包含 Boost.Unordered pretty-printer. 要使用内嵌的 pretty-printer, 请确保像下面这样允许自动加载. 每次加载 GDB 时都必须执行此操作, 或者将其添加到 ".gdbinit" 文件中.

(gdb) add-auto-load-safe-path [/path/to/executable]

你可以选择将二进制编译为 不含 内嵌 pretty-printer 的形式, 方法是定义 BOOST_ALL_NO_EMBEDDED_GDB_SCRIPTS, 这会为所有具备此功能的 Boost 库禁用内嵌的 GDB pretty-printer.

你可以通过非内嵌的 Python 脚本在外部加载 pretty-printer. 添加脚本 /extra/boost_unordered_printers.py, 使用如下所示的 source 命令.

(gdb) source [/path/to/boost]/libs/unordered/extra/boost_unordered_printers.py

可视化结构

这些可视化与标准无序容器一致. map 容器显示从键到映射值的关联. set 容器显示从索引到值的关联. 迭代器要么与其条目一起显示, 要么显示为尾后迭代器. 下面是一个 boost::unordered_map 示例、一个 boost::unordered_set 示例以及它们各自的 begin 和 end 迭代器可能显示的内容.

(gdb) print example_unordered_map
$1 = boost::unordered_map with 3 elements = {["C"] = "c", ["B"] = "b", ["A"] = "a"}
(gdb) print example_unordered_map_begin
$2 = iterator = { {first = "C", second = "c"} }
(gdb) print example_unordered_map_end
$3 = iterator = { end iterator }
(gdb) print example_unordered_set
$4 = boost::unordered_set with 3 elements = {[0] = "c", [1] = "b", [2] = "a"}
(gdb) print example_unordered_set_begin
$5 = iterator = { "c" }
(gdb) print example_unordered_set_end
$6 = iterator = { end iterator }

其他容器的显示完全相同, 只是在显示容器本身时将 “boost::unordered_{map|set}” 替换为相应的模板名. 注意, 每个子元素 (即键、映射值或值) 都根据其自身的打印设置显示, 其中可能包括其自身的 pretty-printer.

SIMD 和非 SIMD 实现均可通过 GDB pretty-printer 查看.

对于启用了 容器统计 的开放寻址容器, 可以在 GDB 中对容器调用 get_stats() 来获取这些统计信息. 在 GDB 中它被重载为 xmethod, 因此不会调用任何 C++ 同步代码. 有关预期格式的示例, 请参见下面的输出.

(gdb) print example_flat_map.get_stats()
$1 = [stats] = {[insertion] = {[count] = 5, [probe_length] = {avg = 1.0, var = 0.0, dev = 0.0}},
  [successful_lookup] = {[count] = 0, [probe_length] = {avg = 0.0, var = 0.0, dev = 0.0},
    [num_comparisons] = {avg = 0.0, var = 0.0, dev = 0.0}}, [unsuccessful_lookup] = {[count] = 5,
    [probe_length] = {avg = 1.0, var = 0.0, dev = 0.0},
    [num_comparisons] = {avg = 0.0, var = 0.0, dev = 0.0}}}

花式指针

如果你的分配器使用了花式指针 (例如 boost::interprocess::offset_ptr), pretty-printer 同样有效. 虽然这种情况很少见, 但 Boost.Unordered 提供了 GDB pretty-printer 定制点以支持任何类型的花式指针. boost::interprocess::offset_ptr 的支持已在 Boost.Interprocess 库中定义, 你也可以按照文件 /extra/boost_unordered_printers.py 末尾附近注释中的说明为自己的类型添加支持.
