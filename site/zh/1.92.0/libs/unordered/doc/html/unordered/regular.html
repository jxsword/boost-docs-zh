常规容器

Boost.Unordered 的封闭寻址容器 (boost::unordered_set、boost::unordered_map、boost::unordered_multiset 和 boost::unordered_multimap) 完全符合 C++ 无序关联容器规范, 因此对于知道如何使用 std::unordered_set、std::unordered_map 等的人来说, 它们在 Boost.Unordered 中的同名容器是直接替代品. 开放寻址容器 (boost::unordered_node_set、boost::unordered_node_map、boost::unordered_flat_set 和 boost::unordered_flat_map) 的接口非常相似, 但存在一些细微差异, 列在专门的 标准符合性一节 中.

对于没有哈希容器使用经验、但熟悉普通关联容器 (std::set、std::map、std::multiset 和 std::multimap) 的读者, Boost.Unordered 容器的使用方式与之类似:

typedef boost::unordered_map<std::string, int> map;
map x;
x["one"] = 1;
x["two"] = 2;
x["three"] = 3;

assert(x.at("one") == 1);
assert(x.find("missing") == x.end());

但由于元素是无序的, 下面代码的输出:

for(const map::value_type& i: x) {
    std::cout<<i.first<<","<<i.second<<"\n";
}

可以是任意顺序. 例如, 可能是:

two,2
one,1
three,3

还有其他一些差异, 列在 与关联容器的比较 一节中.

迭代器失效

标准未规定 rehash 和 reserve 以外的成员函数如何影响桶数量, 不过 insert 只有在插入导致容器负载大于最大允许值时才会使迭代器失效. 对大多数实现而言, 这意味着 insert 只会在发生这种情况时改变桶数量. 对 insert、rehash 和 reserve 的调用可能使迭代器失效.

至于指针和引用, 对于基于节点的容器 (boost::unordered_[multi]set、boost::unordered_[multi]map、boost::unordered_node_set、boost::unordered_node_map), 它们永远不会失效; 但对于 boost::unordered_flat_set 和 boost::unordered_flat_map, 重新哈希发生时会失效: 这是因为这些容器把元素直接存储在其持有的桶中, 因此在分配新桶数组时, 必须通过移动构造来转移元素.

与使用 reserve 处理 vector 的方式类似, 在插入大量元素之前调用 reserve 可能是个好主意. 这样可以避免代价高昂的重新哈希, 并且可以放心地保存迭代器, 因为知道它们不会失效. 如果你要插入 n 个元素到容器 x 中, 可以先调用:

x.reserve(n);
注释

reserve(n) 为至少 n 个元素预留空间, 分配足够的桶以不超过最大负载因子.

由于最大负载因子定义为元素数除以可用桶总数, 该函数在逻辑上等价于:

x.rehash(std::ceil(n / x.max_load_factor()))

更多细节请参见 参考 (关于 rehash 函数).
