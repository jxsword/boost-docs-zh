引言

哈希表 是极为流行的计算机数据结构, 几乎任何编程语言中都能以某种形式找到它. 其他关联结构 (如 rb-tree, 在 C++ 中被 std::set 和 std::map 使用) 的插入和查找具有对数时间复杂度, 而哈希表在配置得当的情况下, 这些操作平均为常量时间, 并且通常快得多.

C++ 在 C++11 中引入了 无序关联容器 std::unordered_set、std::unordered_map、std::unordered_multiset 和 std::unordered_multimap, 但此后对哈希表的研究从未停止: CPU 架构的进步——如更强大的缓存、SIMD 操作以及日益普及的 多核处理器——为改进的基于哈希的数据结构和 2011 年规范中的无序关联容器根本无法企及的新用例开辟了可能.

Boost.Unordered 提供了一系列具有不同标准符合程度、性能和预期使用场景的哈希容器:

  • 封闭寻址容器 完全符合 C++ 无序关联容器规范, 在所需标准接口的技术约束下, 是市场上实现最快的容器之一.

  • 开放寻址容器 依靠快得多的数据结构和算法 (典型场景中快 2 倍以上), 同时为适配实现而稍稍偏离标准接口. 有两种变体: 平坦 (最快) 和 基于节点, 后者以较慢为代价在重新哈希时提供指针稳定性.

  • 最后, 并发容器 的设计和实现面向高性能多线程场景. 其接口与常规 C++ 容器截然不同. 提供平坦和基于节点两种变体.

Boost.Unordered 中的所有 set 和 map 的实例化方式分别与 std::unordered_set 和 std::unordered_map 类似:

namespace boost {
    template <
        class Key,
        class Hash = boost::hash<Key>,
        class Pred = std::equal_to<Key>,
        class Alloc = std::allocator<Key> >
    class unordered_set;
    // same for unordered_multiset, unordered_flat_set, unordered_node_set,
    // concurrent_flat_set and concurrent_node_set

    template <
        class Key, class Mapped,
        class Hash = boost::hash<Key>,
        class Pred = std::equal_to<Key>,
        class Alloc = std::allocator<std::pair<Key const, Mapped> > >
    class unordered_map;
    // same for unordered_multimap, unordered_flat_map, unordered_node_map,
    // concurrent_flat_map and concurrent_node_map
}

将对象存储到无序关联容器中既需要键相等函数也需要哈希函数. 标准容器中的默认函数对象支持一些基本类型, 包括整数类型、浮点类型、指针类型和标准字符串. 由于 Boost.Unordered 使用 boost::hash, 它还支持其他一些类型, 包括标准容器. 要使用这些方法不支持的类型, 你必须扩展 Boost.Hash 以支持该类型, 或使用自己的自定义相等谓词和哈希函数. 更多细节请参见 相等谓词与哈希函数 一节.
