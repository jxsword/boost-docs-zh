类模板 concurrent_flat_map

boost::concurrent_flat_map——一种将唯一键与另一个值关联起来的哈希表, 允许并发地进行元素插入、擦除、查找和访问, 而无需外部同步机制.

尽管它表现得像一个容器, boost::concurrent_flat_map 并不符合标准 C++ 的 Container 概念. 特别是, 不提供迭代器及相关操作 (begin、end 等). 元素的访问和修改通过用户提供的 访问函数 完成, 这些函数被传递给 concurrent_flat_map 操作, 并在其中以受控的方式于内部执行. 这种基于访问的 API 支持低争用的并发使用场景.

boost::concurrent_flat_map 的内部数据结构与 boost::unordered_flat_map 类似. 由于使用开放寻址技术, value_type 必须可移动构造, 且重新哈希时不保持指针稳定性.

说明

模板参数

Key

Key 和 T 必须满足 MoveConstructible. std::pair<const Key, T> 必须 EmplaceConstructible 到表中, 即可从任何可转换为它的 std::pair 对象构造, 并且还必须可从表中 Erasable.

T

Hash

一种一元函数对象类型, 充当 Key 的哈希函数. 它接受一个 Key 类型的参数, 并返回一个 std::size_t 类型的值.

Pred

一种二元函数对象, 在 Key 类型的值上定义等价关系. 它接受两个 Key 类型的参数, 并返回一个 bool 类型的值.

Allocator

一种 value_type 与表的 value_type 相同的分配器. 支持使用 花式指针 的分配器.

表的元素保存在一个内部 桶数组 中. 元素被插入到由其哈希码确定的桶中, 但如果该桶已被占用 (即发生 冲突), 则使用原始位置附近的一个可用桶.

桶数组的大小可以通过调用 insert/emplace 自动增加, 或者作为调用 rehash/reserve 的结果而增加. 表的 负载因子 (元素数除以桶数) 永远不会大于 max_load_factor(), 小尺寸情形除外——此时实现可能决定允许更高的负载.

如果 hash_is_avalanching<Hash>::value 为 true, 则哈希函数按原样使用; 否则, 会添加一个位混合后处理阶段, 以额外的计算开销为代价提高哈希质量.

并发要求与保证

并发调用 operator() 且针对 Hash 或 Pred 的同一 const 实例时, 要求不得引入数据竞争. 当 Alloc 为 Allocator 或从 Allocator 重绑得到的任何分配器类型时, 在同一实例 al (类型为 Alloc) 上并发调用以下操作, 要求不得引入数据竞争:

  • 复制构造自 al——分配器重绑自 Alloc

  • std::allocator_traits<Alloc>::allocate

  • std::allocator_traits<Alloc>::deallocate

  • std::allocator_traits<Alloc>::construct

  • std::allocator_traits<Alloc>::destroy

一般而言, 如果这些类型不带状态, 或相关操作只涉及对内部数据成员的常量访问, 则对 Hash、Pred 和 Allocator 的这些要求即得到满足.

除销毁之外, 在同一 concurrent_flat_map 实例上对任何操作的并发调用都不会引入数据竞争——也就是说, 它们是线程安全的.

如果操作 op 被显式指定为 阻塞于 x (其中 x 是 boost::concurrent_flat_map 的一个实例), 则此前在 x 上的阻塞操作与 op 同步. 因此, 在多线程场景中, 对同一 concurrent_flat_map 的阻塞操作按顺序执行.

一个操作被称为 阻塞于重新哈希 x, 如果它仅在发出内部重新哈希时才阻塞于 x.

当由 boost::concurrent_flat_map 在内部执行时, 用户提供的访问函数对所传入元素的以下操作不会引入数据竞争:

  • 对元素的读访问.

  • 对元素的非可变修改.

  • 对元素的可变修改:

    • 在接受两个访问函数的容器函数中, 总是针对第一个函数.

    • 在名称不含 cvisit 的非 const 容器函数中, 针对最后一个 (或唯一一个) 访问函数.

任何 boost::concurrent_flat_map operation, 只要它插入或修改元素 e, 都与对 e 的访问函数内部调用同步.

由 boost::concurrent_flat_map x 执行的访问函数不得对 x 调用任何操作; 对不同的 boost::concurrent_flat_map 实例 y 调用操作, 仅当 y 上尚在进行的并发操作不直接或间接访问 x 时才被允许.

推导指引

如果以下任一条件为真, 推导指引将不参与重载决议:

  • 它有一个 InputIterator 模板参数, 但为该参数推导出的类型不符合输入迭代器 (input iterator) 的条件.

  • 它有一个 Allocator 模板参数, 但为该参数推导出的类型不符合分配器 (allocator) 的条件.

  • 它有一个 Hash 模板参数, 但为该参数推导出的类型是整数类型, 或符合分配器 (allocator) 的条件.

  • 它有一个 Pred 模板参数, 但为该参数推导出的类型符合分配器 (allocator) 的条件.

推导指引中的 size_­type 参数类型指向由该推导指引推导出的表类型的 size_­type 成员类型. 其默认值与所选构造函数的默认值一致.
