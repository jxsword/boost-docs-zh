std::numeric_limits<> 常量

is_specialized

true 对所有算术类型(整数、浮点和定点)成立, 只要std::numeric_limits<T>::numeric_limits 已针对该类型特化.

典型的测试是

if (std::numeric_limits<T>::is_specialized == false)
{
  std::cout << "type " << typeid(T).name()  << " is not specialized for std::numeric_limits!" << std::endl;
// ...
}

通常,numeric_limits<T>::is_specialized 为true (对所有T, 其中numeric_limits 的编译期常量成员确实在编译期已知, 且不在运行期变化). 例如, 具有运行期可变精度的浮点数类型(如mpfr_float) 没有numeric_limits 特化, 因为不可能在编译期定义所有成员. 相反, 诸如mpfr_float_50 之类的类型的精度在编译期已知, 因此它确实 有numeric_limits 特化.

注意, 并非std::numeric_limits 的所有成员常量和函数都对所有用户自定义类型(UDT)有意义, 例如这里提供的十进制和二进制 multiprecision 类型. 有关此点的更多信息见下文各节.

infinity

对于浮点数类型, 只要有可能就会定义 ∞, 但显然无穷大对任意精度算术后端没有意义; 还有一种浮点数类型(GMP 的mpf_t, 见gmp_float)完全没有无穷大或 NaN 的概念.

测试是否实现了无穷大的典型方法是

if(std::numeric_limits<T>::has_infinity)
{
   std::cout << std::numeric_limits<T>::infinity() << std::endl;
}

强烈建议使用这样的测试以提高可移植性.

警告

若后端切换到不支持无穷大(或类似地 NaN)的类型, 那么没有这样的检查就会出麻烦.

is_signed

std::numeric_limits<T>::is_signed == true (当类型T 为有符号时).

对于基本(内建)二进制类型, 符号保存在单个位中; 但对其他类型(cpp_dec_float 和cpp_bin_float)而言, 它可能是单独的存储元素, 通常是bool.

is_exact

std::numeric_limits<T>::is_exact == true (若类型 T 使用精确表示).

对所有整数类型, 此值定义为true; 对浮点数类型则定义为false.

一个可用的定义 已有讨论.

C++ 标准提到的 ISO/IEC 10967-1 (与语言无关的算术) 定义了

A floating-point type F shall be a finite subset of [real].

重要的实际区别在于, 所有整数(直到max())都可以精确存储.

有理数 类型(使用两个整数类型)也是精确的.

浮点数类型无法存储所有实数值(ℜ 集合中的值)精确. 例如, 0.5 可以在二进制浮点数中精确存储, 但 0.1 不行. 存储的是最近的可表示实值, 即按就近舍入.

定点类型(通常是十进制)也被定义为精确的, 因为它们只存储定点精度, 因此半分或半便士(或更小)无法存储. 计算结果会向上或向下舍入, 就像整数除法的结果存为整数结果一样.

有多项关于为 C++ 增加十进制浮点数支持的提案.

Decimal TR.

以及C++ 二进制定点算术.

is_bounded

std::numeric_limits<T>::is_bounded == true (若类型T 所表示的值集是有限的).

true 对所有基本(内建)类型的整数、定点和浮点数类型以及大多数多精度类型成立.

false (仅个别任意精度类型如cpp_int 除外).

有理数和固定指数表示是精确的, 但不是整数.

is_modulo

std::numeric_limits<T>::is_modulo 定义为true (当把类型 T 的两个正值相加可能得到小于任一操作数的结果时).

is_modulo == true 表示该类型不会溢出, 但例如对max() 值加一会"回绕"到零.

对大多数基本(内建)整数类型,std::numeric_limits<>::is_modulo 为true.

bool 是唯一的例外.

回绕行为有时有用, 但也可能是出乎意料的, 有时甚至是不希望的行为.

有符号整数的溢出尤其可能出乎意料, 可能导致符号改变.

Boost.Multiprecision 整数类型cpp_int 不是回绕的, 因为作为任意精度类型, 它会扩展以容纳机器资源允许的任何值.

不过, 定点精度的cpp_int 若未开启检查则可能是回绕的(即其行为就像基本(内建)整数一样), 但若开启检查则不会(溢出会引发异常).

基本(内建)和多精度浮点数类型通常不是回绕的.

在可能的情况下, 溢出会变成std::numeric_limits<>::infinity() (前提是std::numeric_limits<>::has_infinity == true).

radix

常量std::numeric_limits<T>::radix 返回 2(对于基本(内建)和二进制类型)或 10(对于十进制类型).

digits

可以无变化表示的radix 位数:

  • 对整数类型, 是有效数字中非符号位的位数.
  • 对浮点类型, 是有效数字中基数位的位数.

这些值包括任何隐含位. 例如, 对无处不在的double (使用 64 位, 即IEEE binary64),digits == 53, 尽管表示中实际存储的有效数字只有 52 位.digits 的值反映了存在一个始终置为 1 的隐含位这一事实.

Boost.Multiprecision 的二进制类型不使用隐含位, 因此digits 成员准确反映所要求的精度位数:

typedef number<cpp_bin_float<53, digit_base_2> >   float64;
typedef number<cpp_bin_float<113, digit_base_2> >  float128;
std::numeric_limits<float64>::digits == 53.
std::numeric_limits<float128>::digits == 113.

对于最常见的情况radix == 2,std::numeric_limits<T>::digits 是表示中的位数, 不计任何符号位.

对十进制整数类型, 当radix == 10 时, 它是十进制位数.

digits10

常量std::numeric_limits<T>::digits10 返回可以无变化、无损失地表示的十进制位数.

例如,numeric_limits<unsigned char>::digits10 为 2.

这个有些难懂的定义意味着unsigned char 可以保存十进制值0..99 而不损失精度或准确度(损失通常来自截断).

若定义是 3, 那将意味着它可以保存 0..999; 但众所周知, 8 位的unsigned char 只能保存 0..255, 试图存储 256 或更大的值会有损失或改变.

对有界整数, 因此它少一于显示最大整数std::numeric_limits<T>::max() 所需的十进制位数. 该值可用于预测以下内容所需的布局宽度

std::cout
  << std::setw(std::numeric_limits<short>::digits10 +1 +1) // digits10+1, and +1 for sign.
  << std::showpos << (std::numeric_limits<short>::max)() // +32767
  << std::endl
  << std::setw(std::numeric_limits<short>::digits10 +1 +1)
  << (std::numeric_limits<short>::min)() << std::endl;   // -32767

例如,unsigned short 通常存储在 16 位中, 因此最大值是 0xFFFF 即 65535.

std::cout
  << std::setw(std::numeric_limits<unsigned short>::digits10 +1 +1) // digits10+1, and +1 for sign.
  << std::showpos << (std::numeric_limits<unsigned short>::max)() //  65535
  << std::endl
  << std::setw(std::numeric_limits<unsigned short>::digits10 +1 +1) // digits10+1, and +1 for sign.
  << (std::numeric_limits<unsigned short>::min)() << std::endl;   //      0

对有界浮点数类型, 若我们创建一个double, 其值有digits10 (通常为 15)位十进制数字, 比如1e15 或1000000000000000 :

std::cout.precision(std::numeric_limits<double>::max_digits10);
double d =  1e15;
double dp1 = d+1;
std::cout << d << "\n" << dp1 << std::endl;
// 1000000000000000
// 1000000000000001
std::cout <<  dp1 - d << std::endl; // 1

并且我们可以把这个值按预期递增到1000000000000001, 也可以显示差值.

但若我们尝试用多于digits10 位数字重复此操作,

std::cout.precision(std::numeric_limits<double>::max_digits10);
double d =  1e16;
double dp1 = d+1;
std::cout << d << "\n" << dp1 << std::endl;
// 10000000000000000
// 10000000000000000
  std::cout << dp1 - d << std::endl; // 0 !!!

就会发现加一没有任何效果, 且显示表明存在精度损失. 参见有效位损失或抵消误差.

因此digits10 是保证正确的十进制位数.

例如,double 的"往返转换":

  • 若把一个最多有digits10( == 15)位有效十进制数字的十进制字符串转换为double, 然后再转换回相同数量的有效十进制数字, 则最终的字符串将与原来的 15 位十进制字符串一致.
  • 若把一个double 浮点数转换为至少有 17 位十进制数字的十进制字符串, 然后再转换回double, 则结果在二进制上与原来的double 值完全相同.

对大多数用途, 你更可能想要的是std::numeric_limits<>::max_digits10 - 它是保证最低有效位(最后一位的单位 (ULP))变化会产生不同十进制数字字符串的十进制位数.

对于最常见的double 浮点数类型,max_digits10 为digits10+2, 但应尽可能使用 C++11 的max_digits10 (见下文).

max_digits10

std::numeric_limits<T>::max_digits10 是为浮点数而增加的, 因为digits10 位十进制数字不足以显示最低有效位(ULP)的变化, 从而产生如下令人困惑的显示

0.666666666666667 != 0.666666666666667

例如因"往返转换"失败导致的:

double write = 2./3; // Any arbitrary value that cannot be represented exactly.
double read = 0;
std::stringstream s;
s.precision(std::numeric_limits<double>::digits10); // or `float64_t` for 64-bit IEE754 double.
s << write;
s >> read;
if(read != write)
{
  std::cout <<  std::setprecision(std::numeric_limits<double>::digits10)
    << read << " != " << write << std::endl;
}

若你希望确保最低有效位(ULP)的变化会产生不同的十进制数字字符串, 那么应使用的精度是max_digits10.

例如:

double pi = boost::math::double_constants::pi;
std::cout.precision(std::numeric_limits<double>::max_digits10);
std::cout << pi << std::endl; // 3.1415926535897931

将以double 所能达到的最大精度显示 π.

对精度高得多的类型也类似:

using namespace boost::multiprecision;

typedef number<cpp_dec_float<50> > cpp_dec_float_50; // 50 decimal digits.

// or using boost::multiprecision::cpp_dec_float_50;

cpp_dec_float_50 pi = boost::math::constants::pi<cpp_dec_float_50>();
std::cout.precision(std::numeric_limits<cpp_dec_float_50>::max_digits10);
std::cout << pi << std::endl;
// 3.141592653589793238462643383279502884197169399375105820974944592307816406

对整数类型,max_digits10 由实现决定, 但通常为digits10 + 2. 这是类型 T 的最大值所需的输出字段宽度std::numeric_limits<T>::max() (包括符号和一个空格).

这样就能产生整齐的列.

std::cout << std::setw(std::numeric_limits<int>::max_digits10) ...

多出来的两三位最低有效数字是"嘈杂的", 可能是垃圾数据; 但若你想"往返转换" - 把值打印为十进制数字字符串再读回来 - (最常见于序列化和反序列化期间), 你必须使用os.precision(std::numeric_limits<T>::max_digits10).

注释

在 Microsoft Visual Studio 2010 中,std::numeric_limits<float>::max_digits10 被错误地定义为 8, 应为 9.

注释

对于 2013 之前的 Microsoft Visual Studio 和默认浮点格式, 一小部分双精度浮点值(有效数字约在 0.0001 到 0.004 之间, 指数值为 1010 到 1014)不能精确往返转换, 会相差一个最低有效位, 大概每第三个有效数字值就会出现一次.

一种变通方法是使用科学计数或指数格式std::scientific.

其他较老的编译器也无法完全无错地实现往返转换, 例如参见GCC 和 GLIBC 中不正确的舍入转换.

更多细节参见Visual C++ 中不正确的往返转换 及其中的参考文献, 以及Easy Accurate Reading and Writing of Floating-Point Numbers, Aubrey Jaffer (August 2018).

Microsoft VS2017 和其他新近编译器现在使用Ulf Adams 的 Ryu 快速浮点数转字符串算法, 据称对 32 位和 64 位浮点数既精确又快速.

round_style

舍入样式决定当运算结果无法在有效数字中精确表示时如何处理浮点数运算的结果. 可以提供各种舍入模式:

  • 就近舍入, 向上或向下(浮点数类型的默认值).
  • 向上舍入(朝正无穷方向).
  • 向下舍入(朝负无穷方向).
  • 向零舍入(整数类型).
  • 不舍入(若基数为 10).
  • 舍入模式不可判定.

对整数类型,std::numeric_limits<T>::round_style 总是向零舍入, 因此

std::numeric_limits<T>::round_style == std::round_to_zero;

十进制类型cpp_dec_float 不按任何特定方向舍入, 也就是说它根本不舍入. 而且由于有若干保护位, 它也不真正等同于截断(向零舍入).

对浮点数类型, 通常按就近舍入.

std::numeric_limits<T>::round_style == std::round_to_nearest;

舍入可能造成的最大误差(以 ULP 计)参见函数std::numeric_limits<T>::round_error.

has_denorm_loss

true (若精度损失被检测为非规格化损失, 而不是不精确结果).

对整数类型始终为false.

false (对所有不满足has_denorm ==std::denorm_present 的类型).

denorm_style

非规格化值 是指数位数可变的表示, 可以允许渐进下溢; 也就是说, 若类型 T 为double.

std::numeric_limits<T>::denorm_min() < std::numeric_limits<T>::min()

类型可以取以下enum float_denorm_style 值之一:

  • std::denorm_absent (若不允许非规格化值. 所有整数类型和精确类型总是使用此值).
  • std::denorm_present (若浮点数类型允许非规格化值.)
  • std::denorm_indeterminate (若在编译期无法确定.)
舍入前的微小性检测

bool std::numeric_limits<T>::tinyness_before

true (若类型能在舍入之前确定一个值过小而无法表示为规格化值).

对is_iec559 浮点内建类型通常为真, 但对整数类型为假.

符合标准的 IEEE 754 浮点实现可以在三个预定义时刻检测浮点下溢:

  1. 在计算出绝对值小于std::numeric_limits<T>::min() 的结果之后, 此类实现会检测舍入前微小性 (例如 UltraSparc).
  2. 在把结果舍入到std::numeric_limits<T>::digits 位之后, 若结果微小, 此类实现会检测舍入后微小性 (例如 SuperSparc).
  3. 若把舍入后的微小结果转换为非规格化形式造成了精度损失, 此类实现会检测到非规格化损失.
