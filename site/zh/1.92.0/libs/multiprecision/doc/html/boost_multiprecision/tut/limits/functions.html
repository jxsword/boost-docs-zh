std::numeric_limits<> 函数

max 函数

函数(std::numeric_limits<T>::max)() 返回类型 T 能表示的最大有限值. 若不存在这样的值(且numeric_limits<T>::bounded 为false), 则返回T().

对基本(内建)类型, 通常有对应的宏值 TYPE_MAX, 其中 TYPE 为 CHAR、INT、FLOAT 等.

其他类型, 包括由 typedef 提供的类型, 例如INT64_T_MAX (用于int64_t), 也可能提供宏定义.

为了应对没有numeric_limits 特化可用的情况(例如因为类型的精度在运行期变化), 我们用下面的方式提供了该函数(及其他函数)的封装版本

#include <boost/math/tools/precision.hpp>

T = boost::math::tools::max_value<T>();

当然, 这些封装在可用时只是使用(std::numeric_limits<T>::max)(), 否则会"做一些合理的事情".

lowest 函数

自 C++11 起:std::numeric_limits<T>::lowest() 是

  • 对整数类型, 与函数min() 相同.
  • 对浮点数类型, 一般是max() 的相反数(但由实现决定).
-(std::numeric_limits<double>::max)() == std::numeric_limits<double>::lowest();
min 函数

函数(std::numeric_limits<T>::min)() 返回类型 T 能表示的最小有限值.

对基本(内建)类型, 通常有对应的宏值 TYPE_MIN, 其中 TYPE 为 CHAR、INT、FLOAT 等.

其他类型, 包括由typedef 提供的类型, 例如INT64_T_MIN 用于int64_t, 也可能提供宏定义.

对浮点数类型, 它更完整的定义是最小正规格化值.

最小的非规格化值见std::numeric_limits<T>::denorm_min() (前提是

std::numeric_limits<T>::has_denorm == std::denorm_present

为了应对没有numeric_limits 特化可用的情况(例如因为类型的精度在运行期变化), 我们用下面的方式提供了该函数(及其他函数)的封装版本

#include <boost/math/tools/precision.hpp>

T = boost::math::tools::min_value<T>();

当然, 这些封装在可用时只是使用std::numeric_limits<T>::min().

denorm_min 函数

函数std::numeric_limits<T>::denorm_min() 返回最小的非规格化值 (前提是

std::numeric_limits<T>::has_denorm == std::denorm_present

std::cout.precision(std::numeric_limits<double>::max_digits10);
if (std::numeric_limits<double>::has_denorm == std::denorm_present)
{
  double d = std::numeric_limits<double>::denorm_min();

    std::cout << d << std::endl; //  4.9406564584124654e-324

    int exponent;

    double significand = frexp(d, &exponent);
    std::cout << "exponent = " << std::hex << exponent << std::endl; //  fffffbcf
    std::cout << "significand = " << std::hex << significand << std::endl; // 0.50000000000000000
}
else
{
  std::cout << "No denormalization. " << std::endl;
}

指数实际上从 -308 缩减到 -324(尽管它仍编码为零, 且有效数字前面出现前导零, 从而损失精度, 直到有效数字变为零).

round_error

函数std::numeric_limits<T>::round_error() 返回任何基本算术运算可能造成的最大误差(以最后一位的单位 (ULP) 为单位).

round_style == std::round_indeterminate;

舍入样式在编译期不可判定.

对浮点数类型, 当按就近舍入时, 舍入只损失半个位, 且round_error == 0.5. 相反, 当向零或正/负无穷舍入时, 舍入最多可能损失一个位, 且round_error == 1.

对整数类型, 总是向零舍入, 因此最坏情况下几乎可以舍掉一个位, 所以round_error == 1.

round_error() 可以与std::numeric_limits<T>::epsilon() 一起使用, 以估计舍入可能造成的最大潜在误差. 对典型的浮点数类型,round_error() = 1/2, 因此半个 epsilon 就是最大潜在误差.

double round_err = std::numeric_limits<double>::epsilon() // 2.2204460492503131e-016
                 * std::numeric_limits<double>::round_error(); // 1/2
std::cout << round_err << std::endl; // 1.1102230246251565e-016

当然, 在很多情况下会发生大得多的精度损失, 例如由有效位损失或抵消误差或非常多的迭代造成.

epsilon

函数std::numeric_limits<T>::epsilon() 仅对非整数类型有意义.

它返回1.0 与浮点数类型 T 可表示的下一个值之间的差. 也就是说, 它是该浮点值一个最低有效位的变化.

对double (float_64t) 而言, 它是2.2204460492503131e-016, 显示了全部可能有意义的 17 位十进制数字.

std::cout.precision(std::numeric_limits<double>::max_digits10);
double d = 1.;
double eps = std::numeric_limits<double>::epsilon();
double dpeps = d+eps;
std::cout << std::showpoint // Ensure all trailing zeros are shown.
  << d << "\n"           // 1.0000000000000000
  << dpeps << std::endl; // 2.2204460492503131e-016
std::cout << dpeps - d   // 1.0000000000000002
  << std::endl;

我们可以用函数boost::math::float_next() 显式地增加一个位, 结果与加上epsilon 相同.

double one = 1.;
double nad = boost::math::float_next(one);
std::cout << nad << "\n"  //  1.0000000000000002
  << nad - one // 2.2204460492503131e-016
  << std::endl;

加上任何更小的值, 例如半个epsilon, 对此值都不会有效果.

std::cout.precision(std::numeric_limits<double>::max_digits10);
double d = 1.;
double eps = std::numeric_limits<double>::epsilon();
double dpeps = d + eps/2;

std::cout << std::showpoint // Ensure all trailing zeros are shown.
  << dpeps << "\n"       // 1.0000000000000000
  << eps/2 << std::endl; // 1.1102230246251565e-016
std::cout << dpeps - d   // 0.00000000000000000
  << std::endl;

因此, 尽管加了半个epsilon, 这个抵消误差仍使两个值相等.

为了在不同平台和浮点数类型之间获得更好的可移植性, Boost.Math 和 Boost.Multiprecision 提供了一组在标准numeric_limits 不可用时"做一些合理的事情"的函数. 要使用这些函数, 请#include <boost/math/tools/precision.hpp>.

可以用这个版本的 epsilon 这样定义容差:

RealType tolerance = boost::math::tools::epsilon<RealType>() * 2;
浮点数比较的容差

机器 epsilon ε 在比较浮点值时对计算容差非常有用 - 这项任务比通常想象的要困难得多.

C++ 标准规定了std::numeric_limits<>::epsilon(), Boost.Multiprecision 为其程序定义类型(类似于基本(内建)浮点数类型, 如double float)尽可能地实现了这一点.

更多你可能不想知道(但仍然需要)的信息见What Every Computer Scientist Should Know About Floating-Point Arithmetic

把两个值的绝对差与容差直接比较的天真测试, 在值过大或过小时不会给出有用的结果.

因此 Boost.Test 使用了由 Knuth 首创的算法, 用于可靠地检查浮点值是否足够接近.

见 Donald. E. Knuth. The art of computer programming (vol II). Copyright 1998 Addison-Wesley Longman, Inc., 0-201-89684-2. Addison-Wesley Professional; 3rd edition. (相关公式在 4.2.2 节, 式 36 和 37.)

更多细节见Boost.Math floating_point comparison.

Boost.Test Floating-Point_Comparison

例如, 若我们想要一个大约适合 9 次算术运算的容差, 比如 sqrt(9) = 3, 我们可以定义:

T tolerance =  3 * std::numeric_limits<T>::epsilon();

在 Boost.Math 测试中, 它通过 Boost.Test 的宏BOOST_CHECK_CLOSE_FRACTION 

T expected = 1.0;
T calculated = 1.0 + std::numeric_limits<T>::epsilon();

BOOST_CHECK_CLOSE_FRACTION(expected, calculated, tolerance);

用法如下:

cd ./test
BOOST_CHECK_CLOSE_FRACTION(expected, calculated, tolerance);

(还有一个 BOOST_CHECK_CLOSE 版本, 其容差用百分比而不是分数表示; 通常分数版本更易使用.)

using boost::multiprecision::number;
using boost::multiprecision::cpp_dec_float;
using boost::multiprecision::et_off;

typedef number<cpp_dec_float<50>, et_off > cpp_dec_float_50; // 50 decimal digits.
注释

这是因为 Boost.Test 尚不允许在开启表达式模板的情况下进行浮点数比较, 因此默认的表达式模板参数已被替换为et_off.

cpp_dec_float_50 tolerance =  3 * std::numeric_limits<cpp_dec_float_50>::epsilon();
cpp_dec_float_50 expected = boost::math::constants::two_pi<cpp_dec_float_50>();
cpp_dec_float_50 calculated = 2 * boost::math::constants::pi<cpp_dec_float_50>();

BOOST_CHECK_CLOSE_FRACTION(expected, calculated, tolerance);
无穷大 - 正与负

仅适用于满足std::numeric_limits<T>::has_infinity == true 的浮点数类型, 函数std::numeric_limits<T>::infinity() 为 ∞ 提供一个由实现定义的表示.

"表示"是为无穷大保留的特定位模式. 对于 IEEE754 系统(满足std::numeric_limits<T>::is_iec559 == true), 所有已定义的浮点数类型都为正无穷和负无穷分配了位模式.

令人困惑的是, 输出此表示所产生的字符串同样由实现定义. 而可用于输入以生成该表示的字符串也由实现定义.

例如, 在 Microsoft 系统上输出是1.#INF, 而在大多数 *nix 平台上是inf.

这种由实现决定的特性阻碍了无穷大(和 NaN)的使用, 但Boost.Math 和Boost.Multiprecision 努力为所有 浮点数类型(而不仅仅是基本(内建)类型)提供合理的表示; 通过使用合适的 facet 来定义输入和输出字符串, 可以可移植地使用这些有用的特性, 包括Boost.Serialization.

非数字 (NaN)
Quiet_NaN

仅适用于满足std::numeric_limits<T>::has_quiet_NaN == true 的浮点数类型, 函数std::numeric_limits<T>::quiet_NaN() 为 NaN 提供一个由实现定义的表示.

NaN 是用来表示赋值或计算结果无意义的值. 一个典型的例子是0/0, 但还有很多其他情况.

NaN 也可用于表示缺失值: 例如, 按约定, 在计算均值等统计量时可以忽略它们.

表示非数字的许多问题(与无穷大的问题类似)阻碍了其可移植使用.

NaN 可以与cpp_bin_float_quad 这样的二进制 multiprecision 类型一起使用:

using boost::multiprecision::cpp_bin_float_quad;

if (std::numeric_limits<cpp_bin_float_quad>::has_quiet_NaN == true)
{
  cpp_bin_float_quad NaN =  std::numeric_limits<cpp_bin_float_quad>::quiet_NaN();
  std::cout << "cpp_bin_float_quad NaN is "  << NaN << std::endl; //   cpp_bin_float_quad NaN is nan

  cpp_bin_float_quad expected = NaN;
  cpp_bin_float_quad calculated = 2 * NaN;
  // Comparisons of NaN's always fail:
  bool b = expected == calculated;
  std::cout << b << std::endl;
  BOOST_CHECK_NE(expected, expected);
  BOOST_CHECK_NE(expected, calculated);
}
else
{
  std::cout << "Type " << typeid(cpp_bin_float_quad).name() << " does not have NaNs!" << std::endl;
}

但使用 Boost.Math 和合适的 facet 可以让 NaN 以及正负无穷大都得到可移植的使用.

见boost:/libs/math/example/nonfinite_facet_sstream.cpp, 我们还需要

#include <boost/math/special_functions/nonfinite_num_facets.hpp>

这样我们同样可以使用 multiprecision 类型 cpp_bin_float_quad:

using boost::multiprecision::cpp_bin_float_quad;

typedef cpp_bin_float_quad T;

using boost::math::nonfinite_num_put;
using boost::math::nonfinite_num_get;
{
  std::locale old_locale;
  std::locale tmp_locale(old_locale, new nonfinite_num_put<char>);
  std::locale new_locale(tmp_locale, new nonfinite_num_get<char>);
  std::stringstream ss;
  ss.imbue(new_locale);
  T inf = std::numeric_limits<T>::infinity();
  ss << inf; // Write out.
 BOOST_MP_ASSERT(ss.str() == "inf");
  T r;
  ss >> r; // Read back in.
  BOOST_MP_ASSERT(inf == r); // Confirms that the floating-point values really are identical.
  std::cout << "infinity output was " << ss.str() << std::endl;
  std::cout << "infinity input was " << r << std::endl;
}

infinity output was inf
infinity input was inf

类似地, 对 NaN 也可以这样做(只是不能使用assert (因为任何与 NaN 的比较总是返回 false).

{
  std::locale old_locale;
  std::locale tmp_locale(old_locale, new nonfinite_num_put<char>);
  std::locale new_locale(tmp_locale, new nonfinite_num_get<char>);
  std::stringstream ss;
  ss.imbue(new_locale);
  T n;
  T NaN = std::numeric_limits<T>::quiet_NaN();
  ss << NaN; // Write out.
  BOOST_MP_ASSERT(ss.str() == "nan");
  std::cout << "NaN output was " << ss.str() << std::endl;
  ss >> n; // Read back in.
  std::cout << "NaN input was " << n << std::endl;
}

NaN output was nan
NaN input was nan
信号 NaN

仅适用于满足std::numeric_limits<T>::has_signaling_NaN == true 的浮点数类型, 函数std::numeric_limits<T>::signaling_NaN() 为 NaN 提供一个会触发硬件陷阱的由实现定义的表示. 但应当注意, 此函数至少有一个实现只要调用std::numeric_limits<T>::signaling_NaN() 就会触发硬件陷阱, 而不仅仅是使用返回值时才触发.
