cpp_double_fp_backend

#include <boost/multiprecision/cpp_double_fp.hpp> 

namespace boost { namespace multiprecision {

template <class FloatingPointType>
class cpp_double_fp_backend;

typedef number<cpp_double_fp_backend<float>, et_off> cpp_double_float;
typedef number<cpp_double_fp_backend<double>, et_off> cpp_double_double;
typedef number<cpp_double_fp_backend<long double>, et_off> cpp_double_long_double;
typedef number<cpp_double_fp_backend<boost::float128_type>, et_off> cpp_double_float128; // Only when boost::float128_type is available

} } // namespaces

cpp_double_fp_backend 后端是一个相对简单的双 limb 后端类型. 它由两个 IEEE 浮点数之和构成. 二者组合出一个复合宽度约为其单个部分两倍的类型.cpp_double_fp_backend 后端与number 配合使用, 充当一个纯 C++ 仅头文件的浮点数类型.

该实现依赖双字算术(double-word arithmetic), 即把一个实数表示为两个浮点数之和的技术. 其常用别名还有double-double 或double-word 算术.

cpp_double_fp_backend 类型具有固定宽度且不分配内存. 例如类型cpp_double_double 由两个内建double 分量组成. 在大多数常见系统上, 内建double 是双精度 IEEE 浮点数. 由此得到的cpp_double_double 具有 106 个二进制位和约 32 位十进制精度.

这些类型的指数范围与构成它们的类型相比略有受限(在负方向上). 再看类型cpp_double_double, 它由两个双精度 IEEE 浮点数构成. 在常见系统上, 此类型的最大十进制指数为 308(与单个双精度浮点数相同). 但负的最小指数约为 -291, 比独立 double 的 -307 范围更小. 限制的原因在于复合类型的低位 limb 的值低于其高位 limb. 若高位 limb 取其通常的最小值, 复合类型很容易下溢或变为非规格化数.

此类型有完整的标准库和std::numeric_limits 支持.

注意,cpp_double_float128 的可用性取决于boost::float128_type 的可用性, 后者可在编译期通过配置宏BOOST_HAS_FLOAT128 查询. 目前它主要在 GNU 标准模式的 GCC 编译器上可用, (GCC 14 及更高版本)在严格 ANSI 模式下也可用.

运行期性能是cpp_double_fp_backend 类型的最高要求. 不过这些类型仍然支持无穷大、NaN 以及(当然)零. 但出于效率考虑, 不支持带符号的负零. 所有的零都按正零处理.

cpp_double_fp_backend 类型与 Boost.Math 和 Boost.Math.Constants 互操作. 这提供了以cpp_double_fp_backend 类型实例化的丰富 Boost 数学工具.

使用cpp_double_fp_backend 类型时你应当知道的事项:

  • 尽管这些类型由两个独立的 IEEE 浮点分量构成, 但它们在复合形式上明确地不是 IEEE 类型.
  • 因此, 这些类型的行为可能与 IEEE 浮点数类型有细微差别.
  • 这些类型不能与某些编译器的fast-math 变体一起使用. 例如在 GCC/clang 上, 不能使用-ffast-math(应使用默认设置或显式设置-fno-fast-math). 在 MSVC 上, 不能使用/fp:fast, 且/fp:precise(默认值)在 MSVC 编译器上是强制的. 这是因为其算法, 特别是加法、减法、乘法、除法和平方根的算法, 依赖精确的浮点舍入.
  • 复合类型的精度不如其组成成分. 有关误差界的信息, 见下方参考文献中的 Joldes 等人的论文.
  • 这些类型有std::numeric_limits 特化.
  • cpp_double_fp_backend 实现的几乎所有方法都是constexpr. 唯一的例外是从字符串读取, 它还不是constexpr, 但将来可能会实现.
  • 与字符串的来回转换在内部使用一个中间cpp_bin_float 值. 这有点别扭, 可能在未来的改进中消除.
