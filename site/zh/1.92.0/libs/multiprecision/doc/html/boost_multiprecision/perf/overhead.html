数值类封装中的开销

使用一个简单的 后端类 来封装任意 基本内建 算术类型, 我们可以测量把某个类型封装进 number 前端所带来的开销, 以及开启表达式模板的效果. 下表比较了 double 与 double (后者被封装进类 number 内) 之间的性能:

表 1.12. Bessel 函数 (16 位精度)

类型

时间

arithmetic_backend<double>

2.09301 (0.00133409s)

arithmetic_backend<double> - 无表达式模板

1 (0.000637403s)

double

1.07956 (0.000688113s)


如您所见, 是否存在开销以及开销有多大取决于实际情况, 但无论哪种情况开销都很小. 表达式越复杂, 由于要判断如何最好地展开并求值表达式, 表达式模板增加的开销通常也越大; 但当然, 这也正是能节省更多临时对象的情形. 对于像这样的'平凡'后端, 节省临时对象没有收益, 但对更大的类型则是更大的赢面.

下表比较了 long long 或 number<arithmetic_backend<long long> > 在 voronoi 图构建器测试 中的算术性能:

该测试主要涉及创建大量临时对象并对其执行少量算术运算, 原生类型与"封装"类型之间的性能差异非常小.
