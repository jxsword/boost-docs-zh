后端要求

对Backend 模板参数(即number 的模板参数)的要求分为两类: 强制性与可选.

强制性要求在库中没有默认实现, 因此如果要支持其实现的功能, 后端就必须自行实现它们.

可选性要求带有默认实现, 当后端未提供自己的实现时会调用该默认实现. 后端通常会实现这些要求以提升性能.

在下表中, 类型 B 是Backend 模板实参, 其宿主类型为number,b 和b2 是类型为 B 的变量,pb 是 B* 类型的变量,cb,cb2 和cb3 是const B 类型的常量,rb 是B&& 类型的变量,a 和a2 是 Arithmetic 类型的变量,s 是const char* 类型的变量,ui 是unsigned 类型的变量,bb 是bool 类型的变量,pa 是指向算术类型的指针类型的变量,exp 是B::exp_type 类型的变量,pexp 是B::exp_type* 类型的变量,i 是int 类型的变量,pi 是指向int 类型变量的指针, B2 是另一个满足这些要求的类型, b2 是 B2 类型的变量,ss 是std::streamsize 类型的变量, 而ff 是std::ios_base::fmtflags 类型的变量.

当上表未对某个运算提出抛出方面的要求时, 由实现该概念的每个类型自行决定何时或是否抛出异常. 但是, 抛出的异常应当总是该类型本身, 或者继承自类型std::runtime_error. 例如, 浮点数类型可以选择在运算结果将为无穷时抛出std::overflow_error, 在结果将舍入为零时抛出std::underflow_error.

注释

非成员函数全部以 "eval_" 前缀命名, 以避免与同名模板类冲突 - 实际上这种命名约定本无必要, 只是为了绕过一些编译器缺陷.
