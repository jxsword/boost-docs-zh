safe_base 仅适用于标量类型

以下改述自 Andrzej Krzemieński 在 github issue 中提出的问题. 它触及本库背后的基本思想, 以及这些思想与库的实现如何与现实发生冲突.

“在当前实现中, safe<T> 只能用于 T 为 C++ 标量类型的情况. 因此制定说明允许哪些操作的一般类型要求是多余的, 并且令人困惑 (因为它暗示 safe<> 更通用).”

刚开始时, 我清楚地希望 "safe" 类型看起来像 "numeric" 类型. 很快也清楚地意识到实现中会有大量的模板元编程. 像 std::is_integer 这样的普通类型特征定义在 std 命名空间中, 不鼓励扩展它. 另外, 我需要一些编译期的 "max" 和 "lowest" 值. 这使我把设计建立在 std::numeric_limits 之上. 但 std::numeric_limits 天然可扩展到任何 "numeric" 类型. 例如, 货币是数值类型但不是内建类型. 所以看来我需要定义一个 "numeric" 概念, 要求任何类型 T (例如这里的货币) 都有 std::numeric_limits 的实现. 拿不准的时候 - 我倾向于想得远大.

不过目前我不打算处理它. 无论如何, 我的偏好是做类似这样的事情:

template<typename T>
struct range {
    T m_lowest;
    T m_highest;
    // default implementation
    range(
        const & T t_min, 
        const & T t_max
    ) :
        m_lowest(std::numeric_limits<T>::lowest(t_min),
        m_highest(std::numeric_limits<T>::max(t_max)
    {}
};

然后相应地重新声明 safe_base 等.

另请注意, 对于 C++20, 模板值参数不再限于整数原始类型, 也可以是类类型. 这意味着本库可以扩展到用户类类型, 而无需更改当前的模板签名.

其他待解决问题

  • 本库目前仅限于整数. 如果有兴趣, 可以扩展到浮点数, 甚至可能的用户自定义类型.

  • 尽管为使本库可移植而做了努力, 但实现的至少某些部分 - 特别是 checked 整数算术 - 依赖于整数的二进制补码表示. 因此本库目前可能无法移植到所有其他可能的 C++ 架构. 如今, 这在实践中不太可能成为限制. 从 C++20 开始, C++ 标准将保证整数算术采用二进制补码.

  • std::common_type 用于包括 std::chrono 在内的各种泛型库. 如果没有针对 safe<T> 的特化, 就无法把 safe 包装器用作 (例如) std::chrono::duration 的表示.
