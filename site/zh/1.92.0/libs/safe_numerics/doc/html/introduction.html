Scope

本库旨在作为任何程序中所有内建整数类型的直接替代品, 这些程序必须:

  • 可证明且可验证地正确.

  • 检测每一种用户错误, 例如输入、赋值等.

  • 在上述约束下尽可能高效.

Problem

C/C++ 中的算术运算不保证产生正确的数学结果. 这一特性继承自 C 的早期. int, unsigned int 等的行为被设计为紧密映射到底层硬件. 计算机硬件把这些类型实现为固定数量的位. 当算术运算的结果超过这个位数时, 结果将不会在算术上正确. 以下示例仅说明导致问题的一个例子.

int f(int x, int y){
    // this returns an invalid result for some legal values of x and y !
    return x + y;
}

C/C++ 程序员有责任保证这种行为不会导致程序的不正确或意外操作. 没有实现这种保证的语言设施. 程序员需要逐一检查每个表达式, 才能知道他的程序不会返回无效结果. 有多种方法可以做到这一点. 在上例中, [INT32-C] 似乎推荐以下方法:

int f(int x, int y){
  if (((y > 0) && (x > (INT_MAX - y))) 
  || ((y < 0) && (x < (INT_MIN - y)))) {
    /* Handle error */
  }
  return x + y;
}

这确实能捕获错误. 然而, 让程序员以这种方式修改代码将是繁琐费力的. 对所有算术运算都以这种方式修改代码很可能使代码不可读, 并增加另一个潜在编程错误来源. 当表达式稍微复杂一点时, 这种方法显然就不可用了, 如下例所示.

int f(int x, int y, int z){
    // this returns an invalid result for some legal values of x and y !
    return x + y * z;
}

此示例只解决把加法运算应用于类型 int 时与溢出相关的未定义/错误行为问题. 类似问题也出现在其他内建整数类型上, 例如 unsigned, long 等. 它也适用于减法、乘法等其他运算. 在实现二元运算的过程中, C/C++ 常常自动、静默地把某些整数类型转换为其他类型. 有时这种转换会静默改变算术值, 从而注入错误. C/C++ 标准把某些行为 (如对负数右移) 定为 "实现定义行为". 如今机器通常按程序员预期行事 - 但这种行为没有保证. 依赖这种行为会产生无法保证可移植的程序. 然后还有未定义行为. 在这种情况下, 编译器作者没有义务做任何特定事情. 有时这会意外破坏程序. 至少, 程序变得不可移植. 最后还有一开始就在算术上错误的行为 - 例如除零. 某些运行环境会直接终止程序, 其他可能抛出某种异常. 无论如何, 执行已经以无法恢复的方式失败了.

以上所有情况都是创建永不失败的程序的障碍. Safe Numerics 库 (至少就整数运算而言) 处理了所有这些情况.

由于问题及其解决方案类似, 我们把当前的讨论局限于上面展示的那一个示例.

解决方案

本库实现了 int, unsigned 等的特殊版本, 其行为与原始版本完全相同, 除 了这些运算的结果保证要么在算术上正确, 要么引发错误. 使用本库, 上面的示例将写成:

#include <boost/safe_numerics/safe_integer.hpp>
using namespace boost::safe_numerics;
safe<int> f(safe<int> x, safe<int> y){
  return x + y; // throw exception if correct result cannot be returned
}
注释

本文档中的库代码位于命名空间 boost::safe_numerics 中. 为了提高文本可读性, 该命名空间通常已从文本、代码和示例中省略.

加法表达式会在运行期或 (如果可能) 编译期被检查, 以捕获任何可能导致不正确算术行为的错误. 算术表达式不会产生错误结果. 相反, 保证以下情形之一发生且仅发生一个.

  • 表达式将产生正确的数学结果

  • 表达式将产生编译错误.

  • 表达式将引发运行期异常.

本库绝对保证任何整数算术表达式都不会产生不正确的结果

工作原理

本库实现了 int, unsigned 的特殊版本, 命名为 safe<int>, safe<unsigned int> 等. 这些类型的行为与底层类型完全相同, 除 了使用这些类型的表达式满足上述保证. 这些 "safe" 类型旨在作为同名内建类型的 "直接替代品". 因此合法的事情 - 例如把 signed 赋给 unsigned 值 - 不会在编译期被拦截, 因为它们是合法的 C/C++ 代码. 相反, 会在运行期检查它们, 以捕获这种 (合法的) 运算导致算术上不正确结果的情况.

注意, 本库处理的是由直接的 C/C++ 表达式产生的算术错误. 其中一些算术错误被定义为符合 C/C++ 标准, 另一些则不符合. 因此, 把本库描述为仅处理 C/C++ 数值表达式的未定义行为会产生误导.

采用了 C++14 特有的设施来最小化任何运行期开销. 在许多情况下完全没有运行期开销. 在其他情况下, 使用本库的程序稍加改动即可在没有任何运行期开销的情况下实现上述保证.

附加特性

safe 类型的行为由模板参数决定, 这些参数指定一对 策略类 来规定类型提升和错误处理的行为. 除了用作标准整数类型的直接替代品外, 本库的用户还可以:

  • 选择或定义异常策略类以规定异常的处理.

    • 运行期抛出异常, 尽可能在编译期设陷.

    • 在编译期设陷所有可能在运行期失败的操作.

    • 指定在运行期检测到错误时应调用的自定义函数.

  • 选择或定义提升策略类以改变 C/C++ 类型提升规则. 这可用于

    • 使用 C/C++ 原生类型提升规则, 这样除了对产生不正确算术行为的运算抛出/设陷异常外, 使用和不使用 safe 类型时程序的行为完全相同. 如果只在调试和测试时启用 safe 类型, 可以这样做.

    • 用算术上等价但尽量减少对算术结果运行期检查需求的规则替代 C/C++ 原生提升规则. 这样的策略实际上会改变 C++ 程序的语义. 它不再是真正的 C++. 不能期望程序与使用普通整数类型时表现相同.

    • 用模拟其他机器架构的规则替代 C/C++ 原生提升规则. 这旨在允许在开发平台上测试将要运行在另一台机器上的 C/C++ 代码. 为嵌入式系统开发代码时经常出现这种情况.

  • 使用有界整数类型来强制其他程序要求. 本库包含范围和字面量类型. 违反这些要求的操作将在编译期或运行期被拦截, 而不会静默返回无效值. 这些类型可用于提高程序的正确性和性能.

要求

本库完全由 C++ 头文件组成. 它需要兼容 C++14 标准的编译器.

使用本库必须安装以下 Boost 库

  • mp11

  • integer

  • config

  • tribool

  • enable_if

  • type_traits

Safe Numerics 库随附一套全面的测试程序.

适用范围

本库目前仅适用于内建整数类型. 浮点类型也会出现类似问题, 但本版本库尚未处理它们. 用户或库定义的类型 (如任意精度整数) 也可能有此问题. 将本库扩展到这些其他类型目前尚未在开发中, 但将来可能会处理. 这是库名为 "safe numeric" 而非 "safe integer" 库的原因之一.
