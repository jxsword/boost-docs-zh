Safe Numerics

隐式转换可能导致错误的结果

在 CPPCon 2016 上, Jon Kalb 做了一个非常有趣 (且令人不安) 的闪电演讲 , 主题与 C++ 表达式相关.

该演讲包含一个非常非常简单的示例, 类似于下面这个:

#include <iostream>

#include <boost/safe_numerics/safe_integer.hpp>

int main(){
    std::cout << "example 4: ";
    std::cout << "implicit conversions change data values" << std::endl;
    std::cout << "Not using safe numerics" << std::endl;
    
    // problem: implicit conversions change data values
    try{
        signed int   a{-1};
        unsigned int b{1};
        std::cout << "a is " << a << " b is " << b << '\n';
        if(a < b){
            std::cout << "a is less than b\n";
        }
        else{
            std::cout << "b is less than a\n";
        }
        std::cout << "error NOT detected!" << std::endl;
    }
    catch(const std::exception &){
        // never arrive here - just produce the wrong answer!
        std::cout << "error detected!" << std::endl;
        return 1;
    }

    // solution: replace int with safe<int> and unsigned int with safe<unsigned int>
    std::cout << "Using safe numerics" << std::endl;
    try{
        using namespace boost::safe_numerics;
        safe<signed int>   a{-1};
        safe<unsigned int> b{1};
        std::cout << "a is " << a << " b is " << b << '\n';
        if(a < b){
            std::cout << "a is less than b\n";
        }
        else{
            std::cout << "b is less than a\n";
        }
        std::cout << "error NOT detected!" << std::endl;
        return 1;
    }
    catch(const std::exception & e){
        // never arrive here - just produce the correct answer!
        std::cout << e.what() << std::endl;
        std::cout << "error detected!" << std::endl;
    }
    return 0;
}

example 3: implicit conversions change data values
Not using safe numerics
a is -1 b is 1
b is less than a
error NOT detected!
Using safe numerics
a is -1 b is 1
converted negative value to unsigned: domain error
error detected!

普通人阅读上面的代码会对此目瞪口呆. 代码并没有按照代数规则像文字所说的那样行事. 但 C++ 不遵循代数规则 - 它有自己的规则. 通常没有编译期错误. 如果设置某些特定编译期开关, 可以得到编译期警告. 解释在于审视 C++ 如何调和操作数类型不同的二元表达式 (此处 a < b 是一个表达式). 在处理该表达式时, 编译器:

  • 确定两个操作数的 "最佳" 公共类型. 在此例中, 应用 C++ 标准中的规则规定该类型将是 unsigned int.

  • 把每个操作数转换为该公共类型. 在 32 位整数的机器上, 有符号值 -1 被转换为具有相同位内容的无符号值 0xFFFFFFFF. 对应的十进制值为 4294967295.

  • 执行计算 - 此例中是 < , 即 "小于" 运算. 由于 1 小于 4294967295, 程序打印 "b is less than a".

为了检测和理解这个错误, 程序员应当非常熟悉 C++ 标准的隐式转换规则. 这些规则可见于标准文本, 也可见于权威参考书 The C++ Programming Language (两者都超过 1200 页!). 即使是经验丰富的程序员也不会注意到这个问题并知道采取预防措施来避免它. 而这还是相对容易发现的一个. 更一般的情况下, 它会使用不对应于容易辨认的数字的整数, 和/或被埋在更复杂表达式的一部分中.

这个示例产生了大量网络讨论以及每个人的心爱建议. 例如参见 一篇汇集大家最爱 "解决方案" 的博文 . 所有提出的 "解决方案" 都有缺点, 尽管如此 - 或者也许正因为 - 其中的 情绪化内容 , 就如何处理达成一致的尝试最终都徒劳无功. 我们的解决方案是迄今最简单的: 如上例所示, 直接使用 safe numerics 库.

注意, 在这个特定案例中, 使用 safe 类型使得使用 safe 整数库没有任何运行期开销. 生成的代码的效率将持平或超过使用原始整数类型.
