Safe Numerics

编译期算术并非总是正确

如果程序编译期间发生除零错误, 不能保证它会被检测到. 本示例展示了一个用近期版本 CLang 编译的真实案例.

  • 源代码包含一个含有简单算术错误的常量表达式.

  • 编译器发出警告, 但在其他方面计算出错误的结果.

  • 把 int 替换为 safe<int> 将保证在运行期检测到该错误

  • 使用 safe 类型的运算被标记为 constexpr. 因此我们可以通过把结果标记为 constexpr 来强制运算在编译期发生. 如果运算无法正确计算, 这将在编译期产生错误.

#include <stdexcept>
#include <iostream>

#include <boost/safe_numerics/safe_integer.hpp>

int main(int, const char *[]){
    // problem: cannot recover from arithmetic errors
    std::cout << "example 14: ";
    std::cout << "cannot detect compile time arithmetic errors" << std::endl;
    std::cout << "Not using safe numerics" << std::endl;

    try{
        const int x = 1;
        const int y = 0;
        // will emit warning at compile time
        // will leave an invalid result at runtime.
        std::cout << x / y; // will display "0"!
        std::cout << "error NOT detected!" << std::endl;
    }
    catch(const std::exception &){
        std::cout << "error detected!" << std::endl;
    }
    // solution: replace int with safe<int>
    std::cout << "Using safe numerics" << std::endl;
    try{
        using namespace boost::safe_numerics;
        const safe<int> x = 1;
        const safe<int> y = 0;
        // constexpr const safe<int> z = x / y; // note constexpr here!
        std::cout << x / y; // error would be detected at runtime
        std::cout << " error NOT detected!" << std::endl;
    }
    catch(const std::exception & e){
        std::cout << "error detected:" << e.what() << std::endl;
    }
    return 0;
}
