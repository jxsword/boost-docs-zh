Safe Numerics

使用 safe_range 和 safe_literal

在试图避免上述类型的算术错误时, 程序员会选择足够宽的数据类型, 以容纳足够大的值, 确保结果不会溢出, 但又不至于太大而使程序效率不必要地低下. 在下面的示例中, 我们假定知道要处理的值落在范围 [-24,82] 内. 所以我们 "知道" 程序总会得到正确结果. 但由于我们不信任任何人, 并且程序可能改变、表达式可能被替换, 我们仍会使用 loose_trap_policy 异常策略, 在编译期验证我们 "知道" 为真的事情事实上为真.

#include <iostream>

#include <boost/safe_numerics/safe_integer_range.hpp>
#include <boost/safe_numerics/safe_integer_literal.hpp>
#include <boost/safe_numerics/exception.hpp>
#include <boost/safe_numerics/native.hpp>
#include "safe_format.hpp" // prints out range and value of any type

using namespace boost::safe_numerics;

// create a type for holding small integers in a specific range
using safe_t = safe_signed_range<
    -24,
    82,
    native,           // C++ type promotion rules work OK for this example
    loose_trap_policy // catch problems at compile time
>;

// create a type to hold one specific value
template<int I>
using const_safe_t = safe_signed_literal<I, native, loose_trap_policy>;

// We "know" that C++ type promotion rules will work such that
// addition will never overflow. If we change the program to break this,
// the usage of the loose_trap_policy promotion policy will prevent compilation.
int main(int, const char *[]){
    std::cout << "example 83:\n";

    constexpr const const_safe_t<10> x;
    std::cout << "x = " << safe_format(x) << std::endl;
    constexpr const const_safe_t<67> y;
    std::cout << "y = " << safe_format(y) << std::endl;
    auto zx = x + y;
    const safe_t z = zx;
    //auto z = x + y;
    std::cout << "x + y = " << safe_format(x + y) << std::endl;
    std::cout << "z = " << safe_format(z) << std::endl;
    return 0;
}

  • safe_signed_range 定义了一个限于所指示范围的类型. 超出范围的赋值将在可能时于编译期检测 (如本例), 必要时在运行期检测.

  • 可以用相同的最小值和最大值定义一个 safe range, 从而有效地把该类型限制为只持有一个特定值. 这正是 safe_signed_literal 所做的.

  • 用 safe_signed_literal 定义常量使本库能够在编译期正确预判算术表达式结果的正确范围.

  • 使用 loose_trap_policy 意味着任何对 z 的、可能超出其合法范围的赋值都将导致编译期错误.

  • 所有 safe 整数运算都实现为常量表达式. 使用 constexpr 将保证 z 在编译期可用于任何后续使用.

  • 因此, 如果该程序能编译, 就保证返回有效结果.

输出使用了一个针对 safe 类型的自定义输出操纵器 safe_format 来显示底层类型及其范围以及当前值. 该程序产生如下运行期输出.

example 83:
x = <signed char>[10,10] = 10
y = <signed char>[67,67] = 67
x + y = <int>[77,77] = 77
z = <signed char>[-24,82] = 77

注意各种变量类型:

  • x 和 y 是具有包含单个值的固定范围的 safe 类型. 它们只能保存在编译期被赋予的那个值.

  • The sum x + y can also be determined at compile time.

  • z 的类型定义使其只能容纳闭区间 -24,82 中的值. 我们可以赋值 x + y 之和, 因为它在 z 保证能容纳的范围内. 如果无法保证之和落在 z 的范围内, 那么由于我们使用了 loose_trap_policy 异常策略, 我们会得到编译期错误.

关于变量范围和值的全部这些信息都在编译期确定. 没有运行期开销. 使用 safe 类型不会以任何方式改变计算或结果. 因此 safe_t 和 const_safe_t 可以分别重定义为 int 和 const int , 程序将以相同方式运行 - 我们可以为另一台机器编译该程序 - 这在构建嵌入式系统时很常见, 并且 (假定目标机器架构与我们的本机相同) 知道永远不会产生错误结果.
