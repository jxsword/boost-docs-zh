Safe Numerics

使用自动类型提升

C++ 标准描述了如何处理不同整数类型上的二元运算. 以下是规则的简化版本:

  • 把任何小于 int 的操作数提升为 int 或 unsigned int

  • 若有符号操作数的大小大于无符号操作数的大小, 则结果类型为有符号. 否则结果类型为无符号.

  • 把每个操作数的类型转换为结果的类型, 必要时扩展大小.

  • 对得到的两个操作数执行运算.

因此, 某个二元运算的结果类型可能不同于原始操作数中的一个或两个的类型.

如果值很大, 结果可能超出结果整数类型所能容纳的大小. 这就是我们所称的 "溢出". C/C++ 标准将其定性为未定义行为, 并把如何处理这种情况的决定留给编译器实现者. 通常, 这只是把结果截断以适应结果类型 - 这有时会使结果在算术上不正确. 不过, 视编译器与编译期开关设置而定, 这类情况可能导致某种运行期异常, 或静默地产生某个任意结果.

safe 整数类型的完整签名为:

template <
    class T,                  // underlying integer type
    class P = native,         // type promotion policy class
    class E = default_exception_policy // error handling policy class
>
safe;

算术运算的提升规则在默认的 native 类型提升策略中实现, 与标准 C++ 的规则一致.

到目前为止, 我们一直关注检测算术错误何时发生, 并调用异常或其他类型的错误处理器.

但现在我们来看另一个选项. 使用 automatic 类型提升策略, 我们可以把 safe 类型的 C++ 算术规则改为类似下面的样子:

  • 对于任何 C++ 数值类型, 我们从 std::numeric_limits 得知变量所能取的最大值和最小值 - 这定义了一个闭区间.

  • 对这些类型的任何二元运算, 我们都可以在编译期计算结果的区间.

  • 从这个区间, 我们可以选择一个保证能容纳结果的新类型, 并用它进行计算. 这大致等价于以下代码:

    int x, y;
int z = x + y               // could overflow
// so replace with the following:
int x, y;
long z = (long)x + (long)y; // can never overflow

    可以通过像上面那样手动编辑代码来做到这一点, 但这样的任务繁琐、易错、不可移植, 并且使生成的代码难以阅读和验证. 使用 automatic 类型提升策略可以在没有这些问题的情况下达到等价的结果.

使用 automatic 类型提升策略时, 对于给定的二元运算, 我们静默地把操作数类型提升为更宽的结果类型, 使结果不会溢出. 这是对 C++ 标准行为的根本偏离.

如果结果的区间不能保证容纳在机器能处理的最大类型中 (如今通常是 64 位), 则使用具有正确结果符号的最大可用整数类型. 因此, 即使采用我们的 "自动" 类型提升方案, 仍可能溢出. 所以虽然我们的 automatic 类型提升策略或许能消除上例中的异常, 但不能保证对所有程序都消除.

使用 loose_trap_policy 异常策略会在任何可能发生错误的时候产生编译期错误.

这个小示例演示了如何使用自动类型提升来消除所有运行期开销.

//  Copyright (c) 2018 Robert Ramey
//

// accompanying file LICENSE_1_0.txt or copy at
// http://www.boost.org/LICENSE_1_0.txt)

#include <iostream>

#include <boost/safe_numerics/safe_integer.hpp>
#include <boost/safe_numerics/exception_policies.hpp>
#include <boost/safe_numerics/automatic.hpp>
#include "safe_format.hpp" // prints out range and value of any type

using safe_t = boost::safe_numerics::safe<
    int,
    boost::safe_numerics::automatic, // note use of "automatic" policy!!!
    boost::safe_numerics::loose_trap_policy
>;

int main(int, const char *[]){
    std::cout << "example 82:\n";
    safe_t x(INT_MAX);
    safe_t y = 2;
    std::cout << "x = " << safe_format(x) << std::endl;
    std::cout << "y = " << safe_format(y) << std::endl;
    std::cout << "x + y = " << safe_format(x + y) << std::endl;
    return 0;
}

  • automatic 类型提升策略把两个 integers 之和的结果呈现为 safe<long> 类型.

  • 我们的程序无错编译 - 即使使用 loose_trap_policy 异常策略. 这是因为一个 long 总能容纳两个整数之和.

  • 我们不需要用 try/catch 惯用法来处理算术错误 - 我们将没有任何异常.

  • 我们只需修改两行代码, 就实现了保证程序正确且无运行期开销的目标.

上面的程序产生如下输出:

example 82:
x = <int>[-2147483648,2147483647] = 2147483647
y = <int>[-2147483648,2147483647] = 2
x + y = <long>[-4294967296,4294967294] = 2147483649

注意, 如果将来某时把 safe<int> 改为 safe<long long>, 程序现在可能溢出. 但由于我们使用了 loose_trap_policy, 修改后的程序将无法编译. 此时我们必须再次修改程序以消除运行期开销, 或者放弃零运行期开销的目标, 把异常策略改为 default_exception_policy .

注意, 一旦使用自动类型提升, 我们的编程语言就不再是 C/C++ 了. 所以不要试图做类似下面的事情:

// DON'T DO THIS !
#if defined(NDEBUG)
using safe_t = boost::numeric::safe<
    int,
    boost::numeric::automatic, // note use of "automatic" policy!!!
    boost::numeric::loose_trap_policy
>;
#else
using safe_t = boost::numeric::safe<int>;
#endif
