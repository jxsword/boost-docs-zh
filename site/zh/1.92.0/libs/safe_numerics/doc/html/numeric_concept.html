关于 std::numeric_limits

说明

如果一个类型具有数字的性质, 它就是 Numeric.

更具体地说, 如果存在 std::numeric_limits<T> 的一个特化, 则类型 T 是 Numeric. 参见标准库类 numeric_limits 的文档. 标准库为所有内建数值类型提供了这样的特化. 注意, 这一概念不同于 C++ 标准库类型特征 is_integral 和 is_arithmetic . 后者满足 Numeric 概念的要求. 但也可能存在满足 Numeric 概念却不满足 std::is_arithmetic<T> == false 的类型.

出于我们的目的, 不能用 std::is_arithmetic<T> 来识别类数字类型, 原因有多个:

  • 我们的 Numeric<T> 概念的主要目的是表明类型 T 的范围可供查询. 由于 Numeric<T> 的所有特化在 std::numeric_limits<T> 中都有一个成员, 我们可以在需要时通过成员 std::numeric_limits<T>::min() 和 std::numeric_limits<T>::max() 访问该信息.

  • 有些类型不满足 std::arithmetic<T> (即不是内建数值类型), 但仍满足 Numeric<T> 概念 (类数字的 "东西").

  • 本库为每个表达式创建新的结果类型, 这些类型也应满足 Numeric 概念. 但 is_arithmetic<T> 不能为用户类型特化.

因此 is_arithmetic<T> 对应的类型集合与 Numeric<T> 不相同.

关联类型

std::numeric_limits<T> numeric_limits 类模板为 C++ 程序提供关于实现的算术类型表示的各种属性的信息. 参见 C++ 标准 18.3.2.2.

有效表达式

除了 Assignable 中定义的表达式外, 以下表达式必须有效. 在 safe_numerics 库中, 一个类型当且仅当它在 std::numeric_limits 表中有包含以下成员的条目时才被视为 Numeric. 注意这与 std::is_arithmetic 的定义不同: 后者要求支持全部有效表达式, 而 Numeric 不要求支持所有这些表达式, 只要求在定义时被正确实现. 另外 is_arithmetic 只对内建数值类型定义, 而 Numeric 适用于任何 "看起来像" 数字的用户类型.

关于 std::numeric_limits 用法的说明

这又引出了另一个问题: 特化 std::numeric_limits 以用于诸如 safe<int> 这样的自有类型是否 "合法". 在我看来, 标准对此表述含糊. 参见各种解读:

  • is-it-ok-to-specialize-stdnumeric-limitst-for-user-defined-number-like-class

  • cppreference.com/w/cpp/types/numeric_limits

无论如何, 显然这样做不会有坏处. 尽管对这个问题做了考虑, 但结果发现并没有实现这些谓词的真正需要. 例如, safe numerics 库中没有实现 "is_numeric<T>". 不过将来这可能会改变. 即使未使用, 在本文档中定义并维护这些类型要求对保持概念和代码更加统一和易懂也非常有价值.

请记住, 上述考虑也适用于本库中使用的其他数值类型, 尽管我们没有对每种情况都显式重复这些信息.
