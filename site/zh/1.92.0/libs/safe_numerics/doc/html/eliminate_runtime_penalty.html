到目前为止, 我们主要关注检测何时产生不正确的结果, 并通过抛出异常或调用某个指定函数来处理这些情况. 我们已经实现了检测和处理算术上不正确行为的目标 - 但代价是在运行期检查许多算术运算. 许多 C++ 程序员会认为这种权衡不可接受, 这是事实. 于是问题出现了: 我们如何才能最小化或消除这一运行期开销.

第一步是确定程序中哪些部分可能引发异常. 以下程序与前面的示例类似, 但使用了一个特殊的异常策略: loose_trap_policy

#include <iostream>

#include <boost/safe_numerics/safe_integer.hpp>
#include <boost/safe_numerics/exception_policies.hpp> // include exception policies

using safe_t = boost::safe_numerics::safe<
    int,
    boost::safe_numerics::native,
    boost::safe_numerics::loose_trap_policy  // note use of "loose_trap_exception" policy!
>;

int main(){
    std::cout << "example 81:\n";
    safe_t x(INT_MAX);
    safe_t y(2);
    safe_t z = x + y; // will fail to compile !
    return 0;
}

现在, 任何在运行期 可能 失败的表达式都会被标记为编译期错误. 不再需要 try/catch 块. 由于该程序无法编译, 本库绝对 保证任何算术表达式 都不会产生不正确的结果. 此外, 它绝对保证永远不会抛出异常. 这正是我们最初的目标.

现在我们要做的就是让程序通过编译. 有几种方法可以做到这一点.
