Safe Numerics

与其他库组合

多年来, Boost 一直包含一个表示和操作 有理数 的库. 它制作精良, 文档完善, 且维护良好. 使用 rational 库就像用表达式 rational r(n, d) 构造一个实例一样简单, 其中 n 和 d 是相同类型的整数. 从那时起, 它几乎可以像任何其他数字一样使用. 带着 safe integers 的视角阅读文档, 会发现

精度受限的整数类型 [例如 int] 可能会在其允许的负值范围和正值范围的大小上引发问题. 如果负数范围更大, 则极端负数在正数范围内将没有加法逆元, 使它们无法用作分母值, 因为它们无法规范化为正值 (除非用户幸运地使输入分量在规范化前不互素).

这暗示了麻烦. 检查代码可以发现, 其实现运算时似乎注意避免溢出、捕获除零等. 但代码本身似乎并未一致地贯彻这一思想. 于是我们写一个小的演示程序:

//  Copyright (c) 2018 Robert Ramey
//
// Distributed under the Boost Software License, Version 1.0. (See
// accompanying file LICENSE_1_0.txt or copy at
// http://www.boost.org/LICENSE_1_0.txt)

#include <iostream>
#include <limits>

#include <boost/rational.hpp>
#include <boost/safe_numerics/safe_integer.hpp>

int main(int, const char *[]){
    // simple demo of rational library
    const boost::rational<int> r {1, 2};
    std::cout << "r = " << r << std::endl;
    const boost::rational<int> q {-2, 4};
    std::cout << "q = " << q << std::endl;
    // display the product
    std::cout << "r * q = " << r * q << std::endl;

    // problem: rational doesn't handle integer overflow well
    const boost::rational<int> c {1, INT_MAX};
    std::cout << "c = " << c << std::endl;
    const boost::rational<int> d {1, 2};
    std::cout << "d = " << d << std::endl;
    // display the product - wrong answer
    std::cout << "c * d = " << c * d << std::endl;

    // solution: use safe integer in rational definition
    using safe_rational = boost::rational<
        boost::safe_numerics::safe<int>
    >;

    // use rationals created with safe_t
    const safe_rational sc {1, std::numeric_limits<int>::max()};

    std::cout << "c = " << sc << std::endl;
    const safe_rational sd {1, 2};
    std::cout << "d = " << sd << std::endl;
    std::cout << "c * d = ";
    try {
        // multiply them. This will overflow
        std::cout << (sc * sd) << std::endl;
    }
    catch (std::exception const& e) {
        // catch exception due to multiplication overflow
        std::cout << e.what() << std::endl;
    }

    return 0;
}

它产生如下输出

r = 1/2
q = -1/2
r * q = -1/4
c = 1/2147483647
d = 1/2
c * d = 1/-2
c = 1/2147483647
d = 1/2
c * d = multiplication overflow: positive overflow error

rational 库文档 对底层类型的 类型要求 规定得非常具体. 结果发现, 我们自己的整数类型定义满足 (实际上超越了) 这些要求. 因此我们有理由希望可以用 safe<int> 作为底层类型来创建我们或许可以称之为 "safe_rational" 的东西. 我们已经在上面的示例中这样做了, 演示如何把 rational 库与 safe numerics 库组合, 从而创建相当于 safe_rational 库的东西 - 而无需写一行代码! 不过, 事情并不完美. 由于 有理数库 通过抛出异常实现了自己的除零检查, safe numerics 中处理此情况的代码 - 包括异常策略 - 将不会得到遵守. 总结:

  • 在某些情况下, safe 类型可以用作其他类型的模板参数, 向目标类型注入 "无错误结果" 的概念.

  • 这种组合不保证可行. 必须以一定的细节审查目标类型.
