说明

异常策略规定当 safe 运算无法返回有效结果时要发生什么. 如果一个类型具有用于处理 safe 数值运算过程中发生的异常事件的函数, 它就是一个 ExceptionPolicy.

记法

EP 满足 ExceptionPolicy 要求的一个类型
e 来自 safe_numerics_error 的一个错误码
message 指向关于异常原因的文本消息的 const char *

有效表达式

每当运算产生无效结果时, 将调用以下函数之一.

表达式 返回值 在以下情况下调用:
EP::on_arithmetic_error(e, message) void 运算无法产生有效的算术结果, 例如溢出、除零等.
EP::on_undefined_behavior(e, message) void 结果被 C++ 标准定义为未定义
EP::on_implementation_defined_behavior(e, message) void 根据 C++ 标准, 结果取决于实现定义的行为
EP::on_uninitialized_value(e, message) void 变量未初始化

dispatch<EP>(const safe_numerics_error & e, const char * msg)

此函数用于针对特定异常码调用异常处理策略.

概要
template<class EP>
constexpr void
dispatch<EP>(const boost::numeric::safe_numerics_error & e, char const * const & msg);
使用示例
#include <boost/safe_numerics/exception_policies.hpp"

dispatch<boost::numeric::loose_exception_policy>(
    boost::numeric::safe_numerics_error::positive_overflow_error, 
    "operation resulted in overflow"
);

模型

本库头文件 <boost/safe_numerics/exception_policies.hpp> 包含许多预制的异常策略:

  • boost::numeric::loose_exception_policy

    在算术错误上抛出异常, 忽略其他错误. 有些应用忽略这些问题仍然正常工作, 我们不想更新它们.

  • boost::numeric::loose_trap_policy

    与上面类似, 它不检查各种未定义行为, 但对硬性算术错误在编译期设陷. 该策略适用于依赖位操作运算才能工作的旧式嵌入式系统.

  • boost::numeric::strict_exception_policy

    几乎允许一切, 对任何类型的错误在运行期抛出异常. 推荐用于新代码. 尽可能在编译期检查一切, 必要时在运行期检查. 视情况设陷 (Trap) 或抛出 (Throw). 应保证代码可跨架构移植.

  • boost::numeric::strict_trap_policy

    与上面相同, 但要求以使错误不可能发生的方式编写代码. 这自然需要额外的编码工作, 但对嵌入式和/或安全关键系统可能是合理的.

  • boost::numeric::default_exception_policy

    strict_exception_policy 的别名. 可以先使用它. 经过试验后, 可以切换到上述策略之一, 或许还可以使用自定义策略.
