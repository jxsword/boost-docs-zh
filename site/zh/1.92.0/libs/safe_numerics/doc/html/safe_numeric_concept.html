说明

它保存一个算术值, 可用作内建 C++ 算术值的替代品. 这些类型与其内建对应类型的区别在于保证不会产生无效的算术结果. 这些运算返回 safe 类型而非内建类型.

关联类型

PromotionPolicy 在 C++ 表达式中, 实参必须是同一类型. 若不是, 所有实参都会按照 C++ 标准的规则转换为公共类型. 对 safe numerics 库的某些应用, 我们可能想要不同于标准规则的转换. 此类类型实现要与被实例化的 safe 数值类型一起使用的转换函数.
ExceptionPolicy 异常策略规定当 safe 运算无法返回有效结果时要发生什么. 如果一个类型具有处理 safe 数值运算过程中发生的异常事件的特定函数, 它就是一个 ExceptionPolicy.

  • 任何二元运算中只要有一个或两个操作数是 SafeNumeric 类型, 其结果也是 SafeNumeric 类型. 具体类型由 get_promotion_policy<S> (S 为结果类型) 返回的 PromotionPolicy 中实现的提升规则确定.

  • 上表中的所有表达式都是 constexpr 表达式.

  • 非赋值的二元表达式且其操作数都是 safe 类型时, 要求操作数的提升策略和异常策略相同.

  • Operations on safe types are supported if and only if the same operation is supported on the underlying types. For example, the binary operations |, &, ^ 和 ~ 运算为 safe 无符号整数类型定义. 但它们没有为浮点类型定义. 目前它们也为有符号整数类型定义. 尚不清楚这是否是正确的决定. 一方面, 在有符号类型上使用这些运算几乎肯定是程序逻辑错误. 但把它作为错误拦截与让 safe 类型成为相应内建类型 "直接替代品" 的目标冲突. 鉴于此, 目前像普通内建类型那样支持这些运算.

  • 在适当时, Safe Numeric 类型会被隐式转换为内建类型. 以下是一个示例:

    void f(int);

int main(){
    long x;
    f(x);         // OK - builtin implicit version
    safe<long> y;
    f(y);
    return 0;
}

    此行为支持 safe<T> 作为 T 的 "直接替代品" 这一概念.

不变式

SafeNumeric 类型的基本要求是, 它以防止返回不正确算术结果的方式实现其基类型允许的所有 C++ 运算. 此概念的各种实现可能以不同方式处理产生这类结果的情况 (抛出异常、编译期设陷等). 但任何实现都不应返回算术上不正确的结果.
