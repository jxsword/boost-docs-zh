Safe Numerics

cpp<int C, int S, int I, int L, int LL>

说明

此策略按 C++ 标准中的规则在算术表达式中提升 safe 类型. 但它不使用编译器支持的原生 C++ 标准类型, 而是使用以位数为单位、由模板参数指定长度的类型.

此策略对运行测试程序很有用, 这些程序使用 C++ 可移植整数类型, 但注定要在与构建和运行测试程序的平台不同的架构上运行. 为嵌入式系统开发代码时可能出现这种情况. 为某一架构开发或借鉴但面向另一架构的算法可以在桌面上测试.

注意此策略仅适用于基类型为满足 Integer 类型要求的类型的 safe 类型.

模板参数
参数 类型 说明
C int char 的位数
S int short 的位数
I int int 的位数
L int long 的位数
LL int long long 的位数

使用示例

考虑以下问题. 有人正在开发使用非常小的微处理器和非常受限的 C 编译器的软件. 芯片非常小, 无法从代码中打印任何内容, 也无法记录日志、调试或做其他事情. 只能用 "烧录-崩溃" 法调试代码 - 烧录芯片 (下载代码), 运行代码, 观察结果, 修改后再试. 这是通常使用的粗糙方法, 但可能相当耗时.

考虑另一种方案. 以可测试的模块构建和编译代码. 为每个模块编写一个测试, 以运行所有代码并使其工作. 最后把代码下载到芯片中 - 瞧 - 产品就能工作了. 这听起来很棒, 但有一个问题. 我们的目标处理器 - 这里是 Microchip Technology 的 PIC162550 - 只是 8 位 CPU. 我们使用的编译器把 INT 定义为 8 位. 这 (以及其他一些问题) 使我们的算法测试环境与目标环境不同. 我们可以通过把 INT 定义为范围为 8 位的 safe 整数来解决. 通过使用自定义提升策略, 我们可以强制测试环境中 C++ 表达式的求值与目标环境相同. 同时在目标环境中, 我们可以捕获任何溢出或其他错误. 于是我们可以在桌面系统上编写和测试代码, 然后把代码下载到目标, 并且知道它必须能工作. 这极大节省时间并增强信心. 关于如何做到这一点的扩展示例, 参见 安全关键嵌入式控制器 .
