说明

在 C++ 表达式中, 实参必须是同一类型. 若不是, 所有实参都会按照 C++ 标准的规则转换为公共类型. 对 safe numerics 库的某些应用, 我们可能想要不同于标准规则的转换. 此类类型实现要与被实例化的 safe 数值类型一起使用的转换函数.

int x;
char y;
auto z = x + y

z 的类型将是 int . 这是 C/C++ 算术标准类型提升规则的结果. 本库的一个关键特性是允许通过 PromotionPolicy 类指定自己的类型提升规则.

记法

PP 满足 PromotionPolicy 要求的一个类型
T, U 对 Numeric 概念建模的一个类型
R 对 Numeric 建模的类型的对象, 可用于构造 SafeNumeric 类型.

有效表达式

任何产生无法表示为某个 Numeric 类型的整数的运算都将抛出异常. 这些表达式返回一个类型, 可作为创建 SafeNumeric 类型的基础.

表达式 返回值
PP::addition_result<T, U>::type 未指定的 Numeric 类型
PP::subtraction_result<T, U>::type 未指定的 Numeric 类型
PP::multiplication_result<T, U>::type 未指定的 Numeric 类型
PP::division_result<T, U>::type 未指定的 Numeric 类型
PP::modulus_result<T, U>::type 未指定的 Numeric 类型
PP::comparison_result<T, U>::type bool
PP::left_shift_result<T, U>::type 未指定的 Numeric 类型
PP::right_shift_result<T, u>::type 未指定的 Numeric 类型
PP::bitwise_or_result<T, U>::type 未指定的 Numeric 类型
PP::bitwise_and_result<T, U>::type 未指定的 Numeric 类型
PP::bitwise_xor_result<T, U>::type 未指定的 Numeric 类型

模型

本库包含许多预制的提升策略:

  • boost::numeric::native

    使用普通的 C/C++ 表达式类型提升规则.

    int x;
char y;
auto z = x + y; // could result in overflow
safe<int, native> sx;
auto sz = sx + y; // standard C++ code which detects errors

    类型 sz 将是基于 的 SafeNumericint 类型. 如果结果超过 int 中能存储的最大值, 则检测到错误.

    native 策略在 Promotion Policies - native 中有说明.

  • boost::numeric::automatic

    使用优化的表达式类型提升规则. 这些规则用旨在产生更高效计算的其他规则替代普通的 C/C++ 类型提升规则. 表达式类型被提升为保证能无溢出容纳结果的最小类型. 若没有这样的类型, 则对结果进行溢出检查. 考虑以下示例:

    int x;
char y;
auto z = x + y; // could result in overflow
safe<int, automatic> sx;
auto sz = sx + y; 
    // sz is a safe type based on long
    // hence sz is guaranteed not to overflow.
safe_unsigned_range<1, 4> a;
safe_unsigned_range<2, 4> b;
auto c = a + b; // c will be a safe type with a range [3,8] and cannot overflow

    类型 sz 将是保证能容纳 x + y 结果的 SafeNumeric 类型. 此时它将是 long int (或可能是 long long), 视编译器和机器架构而定. 这种情况下, 无需对结果做任何特殊检查, 也不会溢出.

    c 的类型将是有符号字符, 因为该类型可保证容纳和, 所以不进行溢出检查.

    此策略在 Promotion Policies - automatic

  • boost::numeric::cpp

    使用表达式类型提升规则来模拟另一个处理器. 使用此策略时, safe 整数的 C++ 类型遵循目标处理器上的编译器会使用的规则. 这允许在一个处理器上测试面向另一个处理器的代码. 一种非常非常有用的情况是测试面向微控制器的代码, 而微控制器没有桌面所具有的日志、调试和输入/输出设施.

    // specify a promotion policy to support proper emulation of 
// PIC 18f2520 types on the desktop
using pic16_promotion = boost::numeric::cpp<
    8,  // char      8 bits
    16, // short     16 bits
    16, // int       16 bits
    16, // long      16 bits
    32  // long long 32 bits
>;
...
safe<std::uint16_t, pic16_promotion> x, y;
...

x + y; // detect possible overflow on the pic.

    完整示例参见 安全关键嵌入式控制器.
