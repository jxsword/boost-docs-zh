说明

safe<T, PP , EP> 可以用在任何能使用类型 T 的地方. 任何使用此类型的表达式都保证返回算术上正确的值, 或以某种方式设陷.

关联类型

EP 异常策略. 包含在无法返回正确结果时被调用的成员的类型

有效表达式

实现基类型 T 支持的全部表达式且仅这些表达式. 注意所有这些表达式都是 constexpr . 此类表达式的结果类型将是另一个 safe 类型. 此类表达式结果的实际类型取决于具体的提升策略模板参数.

当二元操作应用于两个 safe<T, PP, EP> 实例时, 以下之一必须为真:

  • 两个操作数的提升策略必须相同, 或其中之一为 void

  • 两个操作数的异常策略必须相同, 或其中之一为 void

如果以上任一条件不成立, 将产生编译错误.

使用示例

最常见的用法是使用默认提升策略和异常策略的 safe<T>. 该类型旨在作为内建整数类型的 "直接替代品". 也就是说, 涉及这些类型的表达式将按反映 C++ 表达式求值标准规则的方式求值得到结果类型. 如果这种求值无法返回正确结果, 将抛出异常.

此类型的行为有两个方面可以用策略定制. 第一个是算术运算的结果类型. C++ 根据运算的组成类型定义了规定结果类型的规则. 这里我们把这些规则称为 "类型提升" 规则. 这些规则有时会产生无法容纳运算实际算术结果的类型. 这正是创建本库的最初动机. 处理此问题的一种方法是用我们自己的类型提升规则取代 C++ 的规则.

作为标准整数类型的直接替代品.

如果若干事件中的任何一个导致不正确的算术结果, 以下程序将在运行期抛出异常并发出错误消息. 该程序的行为可能因所涉及的机器架构而异.

#include <exception>
#include <iostream>
#include <safe_integer.hpp>

void f(){
    using namespace boost::safe_numerics;
    safe<int> j;
    try {
        safe<int> i;
        std::cin >> i;  // could overflow !
        j = i * i;      // could overflow
    }
    catch(std::exception & e){
       std::cout << e.what() << std::endl;
    }
    std::cout << j;
}

"直接替代品" 这一说法道出了本库的期望. 在大多数情况下, 这一期望得以实现. 在下面的示例中, 对 safe 整数的普通隐式转换与对内建整数的行为相同.

//  Copyright (c) 2018 Robert Ramey
//
// Distributed under the Boost Software License, Version 1.0. (See
// accompanying file LICENSE_1_0.txt or copy at
// http://www.boost.org/LICENSE_1_0.txt)

#include <boost/safe_numerics/safe_integer.hpp>
using namespace boost::safe_numerics;

int f(int i){
    return i;
}

using safe_t = safe<long>;

int main(){
    const long x = 97;
    f(x);   // OK - implicit conversion to int
    const safe_t y = 97;
    f(y);   // Also OK - checked implicit conversion to int
    return 0;
}

当调用 safe<long> 时, int 被隐式转换为 f , 此时会检查该值以确保其位于 int 的合法范围内, 否则将引发异常. 通过把上例中的异常处理策略改为 loose_trap_policy , 我们可以轻松验证这一点. 这将对任何可能引发运行期异常的转换产生编译期错误.

//  Copyright (c) 2018 Robert Ramey
//
// Distributed under the Boost Software License, Version 1.0. (See
// accompanying file LICENSE_1_0.txt or copy at
// http://www.boost.org/LICENSE_1_0.txt)

#include <boost/safe_numerics/safe_integer.hpp>
#include <cstdint> // uint8_t
using namespace boost::safe_numerics;

uint8_t f(uint8_t i){
    return i;
}

using safe_t = safe<long, native, loose_trap_policy>;

int main(){
    const long x = 97;
    f(x);   // OK - implicit conversion to int can never fail
    const safe_t y = 97;
    f(y);   // could overflow so trap at compile time
    return 0;
}

但这引出了它自己的问题. 我们可以看到在此示例中, 程序永远不会失败:

  • 值 97 被赋给 y

  • y 被转换为 int

  • 并用作 f 的实参

该转换绝不会失败, 因为值 97 总能放入 int. 但库代码检测不到这一点, 即使不必要也会生成检查代码.

这可以通过使用 safe_literal 来解决. safe 字面量只能包含一个值. 本库中的所有函数都标记为 constexpr . 因此可以在编译期确定转换为 int 绝不会失败, 无需生成运行期检查代码. 做出这一小改动, 上面的示例就能以零运行期开销运行, 同时保证永远不会发生错误.

//  Copyright (c) 2018 Robert Ramey
//
// Distributed under the Boost Software License, Version 1.0. (See
// accompanying file LICENSE_1_0.txt or copy at
// http://www.boost.org/LICENSE_1_0.txt)

#include <boost/safe_numerics/safe_integer.hpp>
#include <boost/safe_numerics/safe_integer_literal.hpp>

using namespace boost::safe_numerics;

int f(int i){
    return i;
}

template<intmax_t N>
using safe_literal = safe_signed_literal<N, native, loose_trap_policy>;

int main(){
    const long x = 97;
    f(x);   // OK - implicit conversion to int
    const safe_literal<97> y;
    f(y);   // OK - y is a type with min/max = 97;
    return 0;
}

对于这个简单的示例, 这样的努力几乎谈不上必要. 但在更复杂的情况中 (可能包括编译期算术表达式), 验证常量有效和/或不需要检查代码可能困难得多. 而且在应用程序的生命周期中, 编译期常量可能改变, 从而使任何临时分析失效. 使用 safe_literal 将使你的代码免受善意但破坏代码的更新影响.

调整类型提升规则.

避免诸如溢出之类算术错误的另一种方法是在做算术之前把类型提升为更大的大小.

退一步看, 如果结果类型更大, 许多无效算术的情况就不会存在. 因此我们可以用表达式自己的类型提升规则替代 C++ 的规则来避免这些问题. 这可以通过指定提升策略 automatic 来完成. 该策略把表达式的结果存储在能容纳表达式可能产生的最大值的最小尺寸类型中. 无需检查异常. 以下示例演示了这一点.

#include <boost/safe_numerics/safe_integer.hpp>
#include <iostream>

int main(int, char[]){
    using safe_int = safe<
        int, boost::numeric::automatic, 
        boost::numeric::default_exception_policy
    >; 
    safe_int i;
    std::cin >> i; // might throw exception
    auto j = i * i; // won't ever trap - result type can hold the maximum value of i * i
    static_assert(boost::numeric::is_safe<decltype(j)>::value); // result is another safe type
    static_assert(
        std::numeric_limits<decltype(i * i)>::max() >=
        std::numeric_limits<safe_int>::max() * std::numeric_limits<safe_int>::max()
    ); // always true

    return 0;
}
