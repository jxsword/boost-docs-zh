说明

从 4 个函数对象创建有效的异常策略. 它规定对不同类型的无效结果要采取的动作.

记法

符号 说明
e safe_numerics_error 类型的实例
message 指向 const char * 错误消息的指针

模板参数

参数 类型要求 在以下情况下调用:
AE 可用表达式 AE()(e, message) 调用的函数对象

运算无法产生有效的算术结果, 例如溢出、除零等.
UB 可用表达式 UB()(e, message) 调用的函数对象

结果被 C++ 标准定义为未定义
IDB 可用表达式 IDB()(e, 调用的函数对象

根据 C++ 标准, 结果取决于实现定义的行为
UV 可用表达式 UV()(e, message) 调用的函数对象

变量未初始化

建模

ExceptionPolicy

继承的有效表达式

该类实现了 ExceptionPolicy 类型要求中的所有有效操作. 除此之外, 没有实现其他操作.

函数对象

要创建异常策略, 需要一些函数对象. 本库包含一些适当的示例:

名称 说明
ignore_exception 忽略任何运行期异常并直接返回 - 从而传播错误. 这是不安全数据类型会发生的情况
throw_exception 抛出 std::system_error 类型的异常
trap_exception 调用一个未定义的函数. 当且仅当存在运行期错误的可能性时, 编译器才会包含此函数. 反之, 只要运算有可能在运行期失败, 就会产生编译期错误. 使用该动作可保证你的应用程序永远不会产生无效结果. 任何运算调用

当然, 你也可以自由提供自己的函数对象. 以下是一个可用于异常条件的函数对象示例.

// log an exception condition but continue processing as though nothing has happened
// this would emulate the behavior of an unsafe type.
struct log_runtime_exception {
    log_runtime_exception() = default;
    void operator () (
        const boost::safe_numerics::safe_numerics_error & e,
        const char * message
    ){
        std::cout
            << "Caught system_error with code "
            << boost::safe_numerics::literal_string(e)
            << " and message " << message << '\n';
    }
};

库提供的策略

上述函数对象可以通过此类组合成异常策略. 本库提供了常用的、开箱即用的策略. 在下表中, "loose" 一词表示实现定义行为和未定义行为不被视为异常情况, 而 "strict" 则相反. "exception" 一词表示将抛出运行期异常. "trap" 一词表示仅存在错误条件的可能性就会导致编译期错误.

名称 说明
loose_exception_policy 在任何算术错误上抛出运行期异常. 只要不产生算术错误, 允许未定义行为和实现定义行为.
loose_trap_policy 在任何可能导致算术错误的情况下引发编译期错误.
strict_exception_policy 在任何算术错误上抛出运行期异常. 任何未定义行为或实现定义行为也会导致抛出异常.
strict_trap_policy 在任何可能导致算术错误、未定义行为或实现定义行为的情况下引发编译期错误
default_exception_policy strict_exception_policy 的别名

如果以上都不符合你的需要, 你可以自由创建自己的策略. 下面这个示例在宽松异常策略中使用上面定义的日志函数对象作为组件, 它记录任何算术错误并忽略其他类型的错误.

// logging policy
// log arithmetic errors but ignore them and continue to execute
// implementation defined and undefined behavior is just executed
// without logging.

using logging_exception_policy = exception_policy<
    log_runtime_exception,    // arithmetic error
    ignore_exception,         // implementation defined behavior
    ignore_exception,         // undefined behavior
    ignore_exception          // uninitialized value
>;
