动机

迭代器在现代 C++ 编程中扮演着重要角色. 迭代器是标准库算法的中心抽象, 使算法能够在各种各样的上下文中重用. C++ 标准库包含多种多样的有用迭代器. 每个标准容器都带有常量迭代器与可变迭代器2, 还有以相反方向遍历容器的上述迭代器的反向版本. 标准库还提供了用于从流读取和向流写入的 istream_iterator 与 ostream_iterator, 用于向容器插入元素的 insert_iterator、front_insert_iterator 与 back_insert_iterator, 以及用于初始化原始内存的 raw_storage_iterator [7].

尽管标准库提供了许多迭代器, 一些显而易见且有用的迭代器仍然缺失, 而创建新的迭代器类型对 C++ 程序员来说仍是常见任务. 文献中记载了若干此类迭代器, 例如 line_iterator [3] 与 Constant_iterator [9]. 迭代器抽象如此强大, 我们预计程序员将始终需要发明新的迭代器类型.

尽管创建 几乎 符合标准的迭代器很容易, 但迭代器要求中包含一些微妙之处, 这使得创建一个 真正 符合标准的迭代器相当困难. 此外, 迭代器接口十分丰富, 包含许多在技术上冗余且实现起来繁琐的运算符. 为了自动化构建迭代器的重复性工作, 我们提出 iterator_facade——一个迭代器基类模板, 它提供标准迭代器的丰富接口, 并把实现委托给派生类的成员函数. 除了减少创建迭代器所需的代码量之外, iterator_facade 还提供编译期错误检测. 由于派生类的实现必须匹配 iterator_facade 的预期, 那些常被忽视的迭代器实现错误会转化为编译期错误.

迭代器构造的一种常见模式是对一个迭代器进行适配以形成新的迭代器. 迭代器的功能由四个正交的方面组成: 遍历、间接引用、相等比较与距离测量. 适配旧迭代器来创建新迭代器常常可以节省工作量, 因为可以重用其中一个功能方面而重新定义其余方面. 例如, 标准库提供了 reverse_iterator, 它通过反转遍历方向来适配任何双向迭代器 (Bidirectional Iterator). 与普通迭代器一样, 标准之外定义的迭代器适配器在文献中已屡见不鲜:

  • Checked iter[13] 为既有迭代器添加边界检查.
  • View Template Library[14] 的迭代器适配容器, 其本身就是底层迭代器之上的适配器.
  • 智能迭代器 [5] 通过对被引用对象应用一个函数对象并返回结果, 来适配迭代器的解引用行为.
  • Custom iterators [4], 其中列举了多种适配器类型.
  • Compound iterators [1], 它访问容器的容器中的一个切片.
  • 来自 MTL [12] 的若干迭代器适配器. MTL 包含一个跨步迭代器 (strided iterator), 其每次对 operator++() 的调用都会把迭代器向前移动某个常数因子; 还有一个缩放迭代器 (scaled iterator), 它把解引用得到的值乘以某个常数.
[1]我们用术语概念 (concept) 表示一个类型为了与特定模板形参一起使用而必须满足的一组要求.
[2]术语可变迭代器 (mutable iterator) 指其对象可通过向解引用结果赋值而改变的迭代器, 而常量迭代器 (constant iterator) 指其对象不可修改的迭代器.

为满足构建适配器的需求, 我们提出 iterator_adaptor 类模板. iterator_adaptor 的实例化可作为新迭代器的基类, 提供把所有操作转发给底层迭代器的默认行为. 用户可以在派生迭代器类中选择性地替换这些特性. 本提案还包含若干更特化的适配器, 例如在迭代器解引用期间应用某个用户指定函数的 transform_iterator.

对标准的影响

本提案纯粹是对 C++ 标准库的附加. 但请注意, 本提案依赖于新迭代器概念 (New Iterator Concepts) 提案.

设计

迭代器概念

本提案按照 iterator concepts 的提案 (见 n1550) 来表述, 因为用户定义的、尤其是经过适配的迭代器深受当前迭代器类别所固有的众所周知的分类问题之苦.

本提案并不严格依赖于提案 n1550, 因为新旧类别之间存在直接映射. 若 n1550 未被接受, 本提案可以借助该映射重新表述.

互操作性

迭代器互操作性问题在当前标准中未得到很好的解决. 目前有两份与互操作性问题相关的缺陷报告.

问题 179 涉及如下事实: 可变容器迭代器类型只要求可转换为对应的常量迭代器类型, 但并不要求这些类型的对象在比较或减法表达式中可互操作. 这种情况在实践中十分繁琐, 且与内建类型的工作方式不一致. 本提案实现了问题 179 的建议解决方案, 如今大多数标准库实现也是如此. 换言之, 若迭代器类型 A 拥有到迭代器类型 B 的隐式转换或用户定义转换, 则这两个迭代器类型可互操作, 且常用的一组运算符均可用.

问题 280 涉及目前反向迭代器类型之间缺乏互操作性的问题. 提议的新 reverse_iterator 模板修复了 280 中提出的问题. 它在不引入多余重载的情况下提供了所需的互操作性.

迭代器外观

尽管迭代器接口十分丰富, 但接口中存在一个为全部功能所必需的核心子集. 我们已为迭代器确定出以下核心行为:

  • 解引用
  • 递增
  • 递减
  • 相等比较
  • 随机访问移动
  • 距离测量

除上述行为之外, 核心接口元素还包括通过迭代器特征 (iterator traits) 暴露的关联类型: value_type、reference、difference_type 与 iterator_category.

迭代器外观使用了奇特递归模板模式 (Curiously Recurring Template Pattern, CRTP) [Cop95], 使用户能够在派生类中指定 iterator_facade 的行为. 先前的设计使用策略对象 (policy object) 来指定行为, 但该方案因若干原因被放弃:

  1. 策略对象的创建及最终的拷贝可能产生额外开销, 而当前方案可以避免这种开销.
  2. 策略对象方案不允许在所创建的迭代器类型上定义自定义构造函数, 而若 iterator_facade 要用于其他库的实现, 这是必不可少的特性.
  3. 若不使用 CRTP, 标准关于迭代器的 operator++ 必须返回迭代器类型本身的要求将意味着: 用本库构建的所有迭代器都不得不成为 iterator_facade<...> 的特化, 而不能是 indirect_iterator<T*> 这样更具描述性的名字. 构建新的参数化迭代器将需要繁琐的类型生成元函数, 而独立的 iterator_adaptor 层也将无从实现.

用法

iterator_facade 的用户从一个 iterator_facade 特化派生自己的迭代器类, 并把派生迭代器类作为 iterator_facade 的第一个模板参数传递. 其余模板参数的顺序经过精心选择, 以便利用有用的默认值. 例如, 在定义一个常量左值迭代器时, 用户可以把该迭代器 value_type 的 const 限定版本作为 iterator_facade 的 Value 参数传入, 并省略紧随其后的 Reference 参数.

派生迭代器类必须定义实现迭代器核心行为的成员函数. 下表描述了根据派生迭代器类型的类别而必须有效的表达式. 这些成员函数在下文有简要描述, 并在迭代器外观要求一节中有更详细的说明.

表达式 效果
i.dereference() 访问所引用的值
i.equal(j) 与如下对象进行相等比较: j
i.increment() 前进一个位置
i.decrement() 后退一个位置
i.advance(n) 前进 n 个位置
i.distance_to(j) 测量到如下对象的距离: j

除了实现核心接口函数之外, 从 iterator_facade 派生的迭代器通常还会定义若干构造函数. 要模型化任何标准迭代器概念, 该迭代器至少必须有一个拷贝构造函数. 此外, 若迭代器类型 X 预期与另一迭代器类型 Y 自动互操作 (如常量迭代器与可变迭代器那样), 则必须存在从 X 到 Y 或从 Y 到 X 的隐式转换 (但两者不可兼有), 通常以转换构造函数实现. 最后, 若该迭代器要模型化前向遍历迭代器或更精化的迭代器概念, 则需要一个默认构造函数.

迭代器核心访问

iterator_facade 与运算符实现需要能够访问派生类中的核心成员函数. 把核心成员函数设为公有会把实现细节暴露给用户. 这里采用的设计确保实现细节不会出现在派生迭代器类型的公有接口中.

阻止对核心成员函数的直接访问有两个优点. 首先, 用户不可能在本想访问 value_type 的成员时误用迭代器的成员函数. 这在过去曾是智能指针实现的一个问题. 第二个也是主要的优点是, 库实现者可以放心地把手写的迭代器实现替换为基于 iterator_facade 的实现, 而不必担心破坏直接访问公有核心成员函数的代码.

在朴素的实现中, 把派生类的核心成员函数保持为私有, 将要求它向 iterator_facade 以及七个运算符中的每一个授予友元关系. 为了减轻限制访问的负担, 本库提供了 iterator_core_access——一个充当通往派生迭代器类中核心成员函数之网关的类. 派生类的作者只需向 iterator_core_access 授予友元关系, 即可使其核心成员函数对本库可用.

iterator_core_access 通常实现为一个空类, 其中只包含调用迭代器核心成员函数的私有静态成员函数. 不过, 无需对网关协议进行标准化. 注意, 即使 iterator_core_access 使用公有成员函数, 也不会打开安全漏洞, 因为每个核心成员函数都保持迭代器的不变式.

operator[]

泛化迭代器的下标运算符带来特殊的挑战. 随机访问迭代器的 operator[] 只要求返回可转换为其 value_type 的东西. 若要求它返回左值, 将排除当前合法的、把被引用值保存在数据成员中的随机访问迭代器 (例如 counting_iterator), 因为 *(p+n) 是指向临时迭代器 p+n 的引用, 而该临时对象在 operator[] 返回时即被销毁.

用 iterator_facade 构建的可写迭代器实现了 issue 299 的首选决议所要求、并由提案 n1550 采纳的语义: p[n] 的结果是一个可转换为迭代器 value_type 的对象, 且 p[n] = x 等价于 *(p + n) = x (注意: 该结果对象可实现为包含 p+n 副本的代理). 无论其实现的其他细节如何, 该方法对任何随机访问迭代器都能正常工作. 对自己迭代器的实现了解更多细节的用户, 可以在派生迭代器类中自行实现一个返回左值的 operator[]; 它会向该迭代器的客户隐藏 iterator_facade 所提供的那个.

operator->

可读迭代器 (以及如今的输入迭代器) 的 reference 类型实际上不必是引用, 只要它可转换为该迭代器的 value_type 即可. 然而, 当 value_type 是类类型时, 仍必须能够通过 operator-> 访问成员. 因此, 其 reference 类型实际上不是引用的迭代器, 必须从其 operator-> 返回一个包含被引用值副本的代理.

iterator_facade 的 operator-> 与 operator[] 的返回类型未被显式指定. 作为替代, 这些类型以一组要求来描述, iterator_facade 的实现必须满足这组要求.

[Cop95][Coplien, 1995] Coplien, J., Curiously Recurring Template Patterns, C++ Report, 1995 年 2 月, 第 24-27 页.

迭代器适配器

iterator_adaptor 类模板把某个 Base3 类型适配成一个新迭代器. iterator_adaptor 的实例化派生自对应的 iterator_facade 实例化, 并依据 Base 类型实现核心行为. 本质上, iterator_adaptor 只是把所有操作转发给它作为成员存储的 Base 类型实例.

[3]这里的术语 "Base" 并非指基类, 也无意暗示使用派生. 我们沿用了标准库的做法——标准库提供 base() 函数来访问 reverse_iterator 适配器的底层迭代器对象.

iterator_adaptor 的用户创建一个派生自 iterator_adaptor 某个实例化的类, 然后有选择地重新定义 iterator_facade 核心要求表中所描述的部分核心成员函数. Base 类型不必满足迭代器的全部要求; 它只需支持未被用户派生类重新定义的 iterator_adaptor 核心接口函数所使用的操作.

iterator_adaptor 的若干模板参数默认为 use_default. 这使用户即使想要指定参数列表中靠后的某个参数, 也能利用默认参数. 此外, 相应关联类型的默认值颇为复杂, 需要元编程来计算, 而 use_default 有助于简化实现. 最后, use_default 类型的身份并非留而不定, 因为明确指定它有助于突出 Reference 模板参数未必总是与迭代器的 reference 类型相同, 并可避免用户基于该假设犯错.

特化适配器

本提案还包含若干特化适配器的示例, 它们用 iterator_adaptor 便可轻松实现:

  • indirect_iterator, 它遍历迭代器、指针或智能指针, 并施加额外一层解引用.
  • 新的 reverse_iterator, 它反转 Base 迭代器的移动方向, 同时允许被适配的常量迭代器与可变迭代器以预期的方式互动 (不同于大多数 C++98 实现中的版本).
  • transform_iterator, 它在解引用时对底层值应用用户定义的函数对象.
  • filter_iterator, 它提供迭代器范围的一个视图, 其中底层范围的某些元素被跳过.
  • counting_iterator, 它适配任何可递增类型 (如整数、迭代器), 使得对被适配迭代器的递增/递减与解引用能产生 Base 类型的相继值.
  • function_output_iterator, 它使创建自定义输出迭代器更加容易.

基于 Boost 库中的示例, 用户已经生成了许多新适配器, 其中有对随机访问迭代器施加某种置换的置换适配器 (permutation adaptor), 以及通过把移动单位乘以常数因子来适配随机访问迭代器的跨步适配器 (strided adaptor). 此外, Boost 图库 (BGL) 使用迭代器适配器把 LEDA [10]、Stanford GraphBase [8] 等其他图库适配到 BGL 接口 (该接口要求符合 C++ 标准的迭代器).

迭代器外观 [lib.iterator.facade]

iterator_facade 是一个基类模板, 它依据少数核心函数与关联类型实现标准迭代器的接口, 这些函数与类型由派生迭代器类提供.

类模板 iterator_facade

template <
    class Derived
  , class Value
  , class CategoryOrTraversal
  , class Reference  = Value&
  , class Difference = ptrdiff_t
>
class iterator_facade {
 public:
    typedef remove_const<Value>::type value_type;
    typedef Reference reference;
    typedef Value* pointer;
    typedef Difference difference_type;
    typedef /* see below */ iterator_category;

    reference operator*() const;
    /* see below */ operator->() const;
    /* see below */ operator[](difference_type n) const;
    Derived& operator++();
    Derived operator++(int);
    Derived& operator--();
    Derived operator--(int);
    Derived& operator+=(difference_type n);
    Derived& operator-=(difference_type n);
    Derived operator-(difference_type n) const;
 protected:
    typedef iterator_facade iterator_facade_;
};

iterator_facade 的 iterator_category 成员为

iterator-category(CategoryOrTraversal, value_type, reference)

其中 iterator-category (迭代器类别) 定义如下:

iterator-category(C,R,V) :=
   if (C is convertible to std::input_iterator_tag
       || C is convertible to std::output_iterator_tag
   )
       return C

   else if (C is not convertible to incrementable_traversal_tag)
       the program is ill-formed

   else return a type X satisfying the following two constraints:

      1. X is convertible to X1, and not to any more-derived
         type, where X1 is defined by:

           if (R is a reference type
               && C is convertible to forward_traversal_tag)
           {
               if (C is convertible to random_access_traversal_tag)
                   X1 = random_access_iterator_tag
               else if (C is convertible to bidirectional_traversal_tag)
                   X1 = bidirectional_iterator_tag
               else
                   X1 = forward_iterator_tag
           }
           else
           {
               if (C is convertible to single_pass_traversal_tag
                   && R is convertible to V)
                   X1 = input_iterator_tag
               else
                   X1 = C
           }

      2. category-to-traversal(X) is convertible to the most
         derived traversal tag type to which X is also
         convertible, and not to any more-derived traversal tag
         type.

[注意: 意图在于, 当可转换为某个遍历标签并不增加任何信息时, 允许 iterator_category 是原先五个类别标签之一]

上文使用的 enable_if_interoperable 模板仅用于说明. 只要派生类型 Dr1 与 Dr2 可互操作——即至少其中一个类型可转换为另一个——成员运算符才应进入重载集. enable_if_interoperable 方式使用 SFINAE 在类型不可互操作时把运算符移出重载集. 这些运算符的行为应当 如同 enable_if_interoperable 被定义为:

indirect_iterator 通过施加 额外 一层嵌入 operator*() 内部的解引用来适配迭代器. 例如, 这个迭代器适配器使查看指针容器 (如 list<foo*>) 如同查看被指向类型的容器 (如 list<foo>) 成为可能. indirect_iterator 依赖两个辅助特征 pointee 与 indirect_reference, 以支持其 value_type 不是迭代器的底层迭代器.

indirect_iterator 模型化的概念

除 iterator_category 与 iterator_traversal<indirect_iterator>::type 所指示的概念之外, indirect_iterator 的特化还模型化以下概念, 其中 v 是 iterator_traits<Iterator>::value_type 的对象:

  • 若 reference(*v) 可转换为 value_type, 则为可读迭代器.
  • 若 reference(*v) = t 是有效表达式 (其中 t 是 indirect_iterator::value_type 类型的对象), 则为可写迭代器
  • 若 reference 是引用类型, 则为左值迭代器.

indirect_iterator<X,V1,C1,R1,D1> 与 indirect_iterator<Y,V2,C2,R2,D2> 可互操作, 当且仅当 X 与 Y 可互操作.

过滤迭代器

过滤迭代器适配器创建迭代器范围的一个视图, 其中范围的某些元素被跳过. 一个谓词函数对象控制哪些元素被跳过. 当谓词应用于某个元素时, 若其返回 true 则该元素被保留, 若返回 false 则该元素被跳过. 在跳过元素时, 过滤适配器必须知道何时停止, 以免越过底层范围的末尾. 因此, 过滤迭代器用一对迭代器来构造, 指示未过滤序列中要遍历的元素范围.

if (CategoryOrTraversal is not use_default)
    return CategoryOrTraversal

    return iterator-category(
