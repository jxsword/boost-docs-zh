摘要:Boost 迭代器库包含两部分. 第一部分是一个 概念体系, 扩展了 C++ 标准迭代器要求. 第二部分是一个组件框架, 用于基于这些扩展概念构建迭代器, 并包含若干有用的迭代器适配器. 扩展的迭代器概念经过精心设计, 使旧式迭代器能够契合新概念, 也使新式迭代器与旧式算法兼容——不过算法若想充分利用新式迭代器的能力, 可能需要更新. 本库的若干组件已被 C++ 标准技术报告接受. Boost 迭代器库的组件取代了旧的 Boost Iterator Adaptor 库.

新式迭代器

C++98 中定义的迭代器类别极其受限, 因为它们把两个正交的概念捆绑在一起: 遍历与元素访问. 例如, 由于随机访问迭代器被要求在解引用时返回引用 (而非代理), 因此无法用 C++98 类别捕捉 vector<bool>::iterator 的能力. 这就是臭名昭著的 "vector<bool> 不是容器, 其迭代器也不是随机访问迭代器" 的溃败事件, Herb Sutter 为标准委员会就此写过两篇论文 (n1185 与 n1211) 以及一篇 Guru of the Week. 新式迭代器远不止是修补 vector<bool>: 还有许多已在使用的迭代器无法被现有概念充分表达. 关于新迭代器概念的细节, 参见我们的

Standard Proposal For New-Style Iterators (PDF)

迭代器外观与适配器

编写符合标准的迭代器颇有技巧性, 但这种需求经常出现. 为了简化新迭代器的实现, Boost.Iterator 库提供了 iterator_facade 类模板, 它实现了许多有用的默认行为与编译期检查, 旨在帮助迭代器作者确保其迭代器的正确性.

同样常见的是定义一个与某个底层迭代器或类迭代器类型相似、但修改底层类型行为某些方面的新迭代器. 为此, 本库提供了 iterator_adaptor 类模板, 它经过专门设计, 能够尽可能多地利用底层类型的行为.

这两个类的文档可在以下网页找到:

  • iterator_facade (PDF)
  • iterator_adaptor (PDF)

iterator_facade 与 iterator_adaptor 以及下文提到的许多 特化适配器 都已被提议标准化, 并被第一个 C++ 技术报告接受; 参见我们的

特化适配器

迭代器库提供了一套有用的符合标准的迭代器模板, 基于 Boost iterator facade and adaptor.

  • counting_iterator (PDF): 一个遍历连续值序列的迭代器. 实现"惰性序列"
  • filter_iterator (PDF): 一个遍历某序列中满足给定谓词的元素子集的迭代器
  • function_input_iterator (PDF): 一个包装生成器 (无参函数对象) 的输入迭代器; 每次解引用迭代器时, 都会调用函数对象以取得要返回的值.
  • function_output_iterator (PDF): 一个包装一元函数对象的输出迭代器; 每次向解引用后的迭代器写入元素时, 该元素都作为参数传递给函数对象.
  • generator_iterator: 一个包装对生成器 (无参函数对象) 的引用的输入迭代器; 每次解引用迭代器时, 都会调用函数对象以取得要返回的值. 它是 function_input_iterator 的更过时对应物.
  • indirect_iterator (PDF): 一个遍历某序列元素所指向对象的迭代器.
  • permutation_iterator (PDF): 一个遍历某随机访问序列元素的迭代器, 依照某个整数索引序列重新排列.
  • reverse_iterator (PDF): 一个反向遍历某双向序列元素的迭代器. 修正了 C++98 的 std::reverse_iterator 的许多缺陷.
  • shared_container_iterator: 一个遍历某容器元素的迭代器, 该容器的生存期由迭代器中存储的 shared_ptr 维护.
  • transform_iterator (PDF): 一个遍历元素的迭代器, 这些元素是对底层序列元素施加某种函数变换的结果. 该组件还取代了旧的 projection_iterator_adaptor.
  • zip_iterator (PDF): 一个遍历元组的迭代器, 元组由各底层迭代器对应位置上的元素组成.

迭代器工具

特征

  • pointee.hpp (PDF): 提供在泛型代码中推导指针、智能指针与迭代器的引用对象类型的能力. 用于 indirect_iterator.
  • iterator_traits.hpp (PDF): 提供与 MPL 兼容的元函数, 用于获取迭代器的特征. 同时修正 std::iterator_traits 的有缺陷实现.

测试与概念检查

  • iterator_concepts.hpp (PDF): 新迭代器概念的概念检查类.
  • iterator_archetypes.hpp (PDF): 新迭代器概念的概念原型类.

从旧版 Boost Iterator Adaptor 库升级

如果你一直使用旧的 Boost Iterator Adaptor 库来实现迭代器, 你可能编写过一个 Policies 类来捕获迭代器的核心操作. 在新库设计中, 你将把同样的核心操作移入迭代器类本身的主体中. 如果你编写的是一个迭代器家族, 你可能编写过一个 类型生成器 来构建所需的 iterator_adaptor 特化; 在新库设计中不需要类型生成器 (不过你可能想保留它作为对旧代码的兼容辅助), 因为由于奇特递归模板模式 (CRTP) [Cop95] 的使用, 你现在可以自己定义迭代器类, 并通过继承 iterator_facade 或 iterator_adaptor 来获得功能. 这样一来, 你对迭代器如何工作还拥有精细得多的控制: 可以添加额外的构造函数, 甚至重写库提供的迭代器功能.

如果你在寻找旧的 projection_iterator 组件, 其功能已被并入 transform_iterator: 只要函数对象的 result_type (或显式指定的 Reference 模板实参) 是真正的引用类型, transform_iterator 的行为就会与 projection_iterator 过去的行为一样.

历史

2000 年, Dave Abrahams 正在为一个指针容器编写迭代器, 该迭代器在解引用时访问被指向的元素. 自然而然地, 作为库作者, 他决定将这一想法泛化, Boost Iterator Adaptor 库就此诞生. Dave 受 Andrei Alexandrescu 的一些著述启发, 选择了基于策略的设计 (尽管他可能没有很好地捕捉 Andrei 的想法——所有迭代器正交属性只有一个策略类). 很快 Jeremy Siek 意识到自己需要这个库, 于是他们合作产出了一个 "Boost 化" 的版本, 经过评审被接受入库. 他们撰写了一篇论文, 并对代码做了若干重要修订.

最终, 旧库的若干缺陷开始使重写的必要性变得明显. Dave 和 Jeremy 从 2002 年圣克鲁斯 C++ 委员会会议开始合作, 并很快生成了一个可运行的原型. 在 Mat Marcus 的敦促下, 他们决定采用 GenVoca/CRTP 模式方法, 把策略移入迭代器类本身. Thomas Witt 表达了兴趣, 并成为该项目严格编译期检查的代言人, 他添加了 SFINAE 技术的使用, 以从重载集中剔除虚假的转换构造函数与运算符. 他还认识到需要一个独立的 iterator_facade, 并把它从 iterator_adaptor 中分解出来. 最后, 在对原型进行近乎完全的重写之后, 他们得到了你今天看到的这个库.

[Cop95][Coplien, 1995] Coplien, J., Curiously Recurring Template Patterns, C++ Report, 1995 年 2 月, 第 24-27 页.
