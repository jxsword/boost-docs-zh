迭代器适配器

参考
教程

iterator_adaptor 类模板把某个 Base _ 类型适配成一个新迭代器. iterator_adaptor 的实例化派生自对应的 iterator_facade 实例化, 并依据 Base 类型实现核心行为. 本质上, iterator_adaptor 只是把所有操作转发给它作为成员存储的 Base 类型实例.

.. 这里的术语 "Base" 并非指基类, 也无意暗示使用派生. 我们沿用了标准库的做法——标准库提供 base() 函数来访问 reverse_iterator 适配器的底层迭代器对象.

iterator_adaptor 的用户创建一个派生自 iterator_adaptor 某个实例化的类, 然后有选择地重新定义 iterator_facade 核心要求表中所描述的部分核心成员函数. Base 类型不必满足迭代器的全部要求; 它只需支持未被用户派生类重新定义的 iterator_adaptor 核心接口函数所使用的操作.

iterator_adaptor 的若干模板参数默认为 use_default. 这使用户即使想要指定参数列表中靠后的某个参数, 也能利用默认参数. 此外, 相应关联类型的默认值颇为复杂, 需要元编程来计算, 而 use_default 有助于简化实现. 最后, use_default 类型的身份并非留而不定, 因为明确指定它有助于突出 Reference 模板参数未必总是与迭代器的 reference 类型相同, 并可避免用户基于该假设犯错.

参考

概要 

template <
    class Derived
  , class Base
  , class Value               = use_default
  , class CategoryOrTraversal = use_default
  , class Reference           = use_default
  , class Difference = use_default
>
class iterator_adaptor
  : public iterator_facade<Derived, *V'*, *C'*, *R'*, *D'*> // see details
{
    friend class iterator_core_access;
 public:
    iterator_adaptor();
    explicit iterator_adaptor(Base const& iter);
    typedef Base base_type;
    Base const& base() const;
 protected:
    typedef iterator_adaptor iterator_adaptor\_;
    Base const& base_reference() const;
    Base& base_reference();
 private: // Core iterator interface for iterator_facade.
    typename iterator_adaptor::reference dereference() const;

    template <
        class OtherDerived, class OtherIterator, class V, class C, class R, class D
    >
    bool equal(iterator_adaptor<OtherDerived, OtherIterator, V, C, R, D> const& x) const;

    void advance(typename iterator_adaptor::difference_type n);
    void increment();
    void decrement();

    template <
        class OtherDerived, class OtherIterator, class V, class C, class R, class D
    >
    typename iterator_adaptor::difference_type distance_to(
        iterator_adaptor<OtherDerived, OtherIterator, V, C, R, D> const& y) const;

 private:
    Base m_iterator; // exposition only
};

__ base_parameters_

.. _requirements:

要求

static_cast<Derived*>(iterator_adaptor*) 必须是良构的. Base 实参必须可赋值且可拷贝构造.

.. _base_parameters:

基类参数

V'、C'、R' 与 D' 诸参数 (即 iterator_facade——它在上面 iterator_adaptor 的概要中用作基类——的参数) 定义如下:

   V' = if (Value is use_default)
             return iterator_traits<Base>::value_type
         else
             return Value

   C' = if (CategoryOrTraversal is use_default)
             return iterator_traversal<Base>::type
         else
             return CategoryOrTraversal

   R' = if (Reference is use_default)
             if (Value is use_default)
                 return iterator_traits<Base>::reference
             else
                 return Value&
         else
             return Reference

   D' = if (Difference is use_default)
             return iterator_traits<Base>::difference_type
         else
             return Difference

操作

公有 

iterator_adaptor();

要求: Base 类型必须可默认构造.
返回: 一个 iterator_adaptor 实例, 其 m_iterator 为默认构造.

explicit iterator_adaptor(Base const& iter);

返回: 一个 iterator_adaptor 实例, 其 m_iterator 由 iter 拷贝构造.

Base const& base() const;

Returns: m_iterator

受保护 

Base const& base_reference() const;

返回: 指向 m_iterator 的 const 引用.

Base& base_reference();

返回: 指向 m_iterator 的非 const 引用.

私有 

typename iterator_adaptor::reference dereference() const;

返回: *m_iterator 

template <
class OtherDerived, class OtherIterator, class V, class C, class R, class D
>
bool equal(iterator_adaptor<OtherDerived, OtherIterator, V, C, R, D> const& x) const;

返回: m_iterator == x.base() 

void advance(typename iterator_adaptor::difference_type n);

Effects: m_iterator += n; 

void increment();

Effects: ++m_iterator; 

void decrement();

Effects: --m_iterator; 

template <
    class OtherDerived, class OtherIterator, class V, class C, class R, class D
>
typename iterator_adaptor::difference_type distance_to(
    iterator_adaptor<OtherDerived, OtherIterator, V, C, R, D> const& y) const;

返回: y.base() - m_iterator

.. |fac_tut| replace:: iterator_facade tutorial .. _fac_tut: iterator_facade.html#tutorial-example

node_base* 确实 是 一个迭代器

它其实不是一个很有意思的迭代器, 因为 node_base 是抽象类: 指向 node_base 的指针只是指向某个其他类实例的某个基子对象, 而递增一个 node_base* 会把它移过该基子对象, 移到谁知道哪里? 对这个递增后的位置, 我们最多能做的就是拿另一个 node_base* 与它比较. 换言之, 原迭代器遍历的是一个单元素数组.

你可能没有这样想过, 但 node_base* 这个作为 node_iterator 底层的对象本身就是一个迭代器, 与所有其他指针一样. 如果我们从迭代器视角仔细审视该指针, 可以看到它与我们在构建的 node_iterator 有许多共同之处. 首先, 它们共享大部分相同的关联类型 (value_type、reference、pointer 与 difference_type). 其次, 甚至部分核心功能也相同: operator* 与 operator== 在 node_iterator 上返回对底层指针调用相同操作的结果 (经由 node_iterator 的 |dereference_and_equal|_). node_base* 与 node_iterator 之间唯一真正的行为差异在递增时可以观察到: node_iterator 跟随 m_next 指针, 而 node_base* 只是应用一个地址偏移.

.. |dereference_and_equal| replace:: dereference 与 equal 成员函数 .. _dereference_and_equal: iterator_facade.html#implementing-the-core-operations

事实证明, 在另一个类迭代器类型 (即 Base _ 类型) 之上构建迭代器、同时只修改底层类型行为的少数几个方面, 是一种极为常见的模式, 也是 iterator_adaptor 所针对的模式. 使用 iterator_adaptor 与使用 iterator_facade 非常相似, 但由于 iterator_adaptor 尽力模仿 Base 类型的行为, 我们既不必提供 Value 实参, 也不必实现 increment 之外的任何核心行为. 于是 node_iter 的实现简化为:

template <class Value>
class node_iter
  : public boost::iterator_adaptor<
        node_iter<Value>                // Derived
      , Value*                          // Base
      , boost::use_default              // Value
      , boost::forward_traversal_tag    // CategoryOrTraversal
    >
{
 private:
    struct enabler {};  // a private type avoids misuse

 public:
    node_iter()
      : node_iter::iterator_adaptor_(0) {}

    explicit node_iter(Value* p)
      : node_iter::iterator_adaptor_(p) {}

    template <class OtherValue>
    node_iter(
        node_iter<OtherValue> const& other
      , typename boost::enable_if<
            boost::is_convertible<OtherValue*,Value*>
          , enabler
        >::type = enabler()
    )
      : node_iter::iterator_adaptor_(other.base()) {}

 private:
    friend class boost::iterator_core_access;
    void increment() { this->base_reference() = this->base()->next(); }
};

注意这里对 node_iter::iterator_adaptor_ 的使用: 由于 iterator_adaptor 定义了一个指向自身的嵌套 iterator_adaptor_ 类型, 这为我们提供了一种便捷方式来引用 node_iter<Value> 复杂的基类类型. [注意: 已知该技术在 Borland C++ 5.6.4 与 9.0 之前的 Metrowerks CodeWarrior 版本上不适用]

你可以参见一个演练这一版本节点迭代器的示例程序 here.

就 node_iter 而言, 把 boost::use_default 作为 iterator_adaptor 的 Value 实参并不十分可取; 我们本可以直接把 node_iter 的 Value 传给 iterator_adaptor, 那甚至更短! 用 iterator_adaptor 构建的大多数迭代器类模板都以另一个迭代器类型为参数, 而不是以其 value_type 为参数. 例如, boost::reverse_iterator 接受一个迭代器类型实参并反转其遍历方向, 由于原迭代器与反转后的迭代器拥有全部相同的关联类型, iterator_adaptor 把默认类型委托给其 Base 的做法使 boost::reverse_iterator 的实现者免于编写:

std::iterator_traits<Iterator>::*some-associated-type*

至少四次.

我们敦促你查阅 |reverse_iterator|_ 与其他 Boost specialized iterator adaptors__ 的文档与实现, 以了解用 iterator_adaptor 能做些什么. 特别请看看 |transform_iterator| (它也许是最直接的适配器) 以及 |counting_iterator| (它表明 iterator_adaptor 的 Base 类型不必是迭代器).
