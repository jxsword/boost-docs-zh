从旧版 Boost Iterator Adaptor 库升级

如果你一直使用旧的 Boost Iterator Adaptor 库来实现迭代器, 你可能编写过一个 Policies 类来捕获迭代器的核心操作. 在新库设计中, 你将把同样的核心操作移入迭代器类本身的主体中. 如果你编写的是一个迭代器家族, 你可能编写过一个 类型生成器 来构建所需的 iterator_adaptor 特化; 在新库设计中不需要类型生成器 (不过你可能想保留它作为对旧代码的兼容辅助), 因为由于奇特递归模板模式 (CRTP) [Cop95]_ 的使用, 你现在可以自己定义迭代器类, 并通过继承 iterator_facade 或 iterator_adaptor 来获得功能. 这样一来, 你对迭代器如何工作还拥有精细得多的控制: 可以添加额外的构造函数, 甚至重写库提供的迭代器功能.

如果你在寻找旧的 projection_iterator 组件, 其功能已被并入 transform_iterator: 只要函数对象的 result_type (或显式指定的 Reference 模板实参) 是真正的引用类型, transform_iterator 的行为就会与 projection_iterator 过去的行为一样.
