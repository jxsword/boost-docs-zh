Boost Format 库

<boost/format.hpp> format 类以类型安全的方式提供类 printf 的格式化功能, 并允许输出用户自定义类型.

概要

format 对象由格式化串构造, 然后通过反复调用 operator% 来提供参数.
随后每个参数都被转换为字符串, 再根据格式化串把这些字符串组合成一个字符串.

cout << boost::format("writing %1%,  x=%2% : %3%-th try") % "toto" % 40.23 % 50; 
     // prints "writing toto,  x=40.230 : 50-th try"

工作原理

  1. 当你调用 format(s)(其中 s 为格式化串)时, 它会构造一个对象, 该对象解析格式化串, 查找其中的所有指令, 并为下一步准备内部结构.
  2. 然后, 要么像 
    cout << format("%2% %1%") % 36 % 77;
    这样立即进行, 要么像 
    format fmter("%2% %1%");
fmter % 36; fmter % 77;
    那样稍后进行, 把变量 喂入格式化器.
    这些变量会被送入一个内部流, 该流的状态按照格式化串中给定的格式化选项(如果有的话)设置, 而 format 对象则把字符串结果保存起来留待最后一步使用.
  3. 一旦所有参数都已喂入, 你就可以把 format 对象输出到流, 或者用 str() 成员函数, 或命名空间 boost 中的自由函数 str(const format& ) 获取其字符串值. 结果字符串会一直保存在 format 对象中, 直到传入另一个参数时才被重新初始化. 
    
// fmter was previously created and fed arguments, it can print the result :
cout << fmter ;  

// You can take the string result :
string s  = fmter.str();

// possibly several times :
s = fmter.str( );

// You can also do all steps at once :
cout << boost::format("%2% %1%") % 36 % 77; 

// using the str free function :
string s2 = str( format("%2% %1%") % 36 % 77 );
  4. 可选地, 在第 3 步之后, 你可以复用 format 对象并从第 2 步重新开始: fmter % 18 % 39;
    用同一个格式化串格式化新变量, 从而省去第 1 步中开销很大的处理.
总而言之, format 类把一个格式化串(可能带有类 printf 的指令)转化为对内部流的操作, 并最终把格式化的结果作为字符串返回, 或直接写入输出流.

示例

using namespace std;
using boost::format;
using boost::io::group;
  • 简单的输出, 带重排: 
    
cout << format("%1% %2% %3% %2% %1% \n") % "11" % "22" % "333"; // 'simple' style.
    它打印: "11 22 333 22 11 \n"
  • 更精细的格式化, 使用 Posix-printf 位置指令: 
    
cout << format("(x,y) = (%1$+5d,%2$+5d) \n") % -23 % 35;     // Posix-Printf style
    它打印: "(x,y) = ( -23, +35) \n"
  • 经典 printf 指令, 无重排: 
    
cout << format("writing %s,  x=%s : %d-th step \n") % "toto" % 40.23 % 50;
    它打印: "writing toto, x=40.23 : 50-th step \n"
  • 表达同一件事的多种方式: 
    
cout << format("(x,y) = (%+5d,%+5d) \n") % -23 % 35;
cout << format("(x,y) = (%|+5|,%|+5|) \n") % -23 % 35;

cout << format("(x,y) = (%1$+5d,%2$+5d) \n") % -23 % 35;
cout << format("(x,y) = (%|1$+5|,%|2$+5|) \n") % -23 % 35;
    所有这些都会打印: "(x,y) = ( -23, +35) \n"
  • 使用操纵器修改格式化串: 
    
format fmter("_%1$+5d_ %1$d \n");

format fmter2("_%1%_ %1% \n");
fmter2.modify_item(1, group(showpos, setw(5)) ); 

cout << fmter % 101 ;
cout << fmter2 % 101 ;
    两者打印的结果相同: "_ +101_ 101 \n"
  • 使用带参数的操纵器: 
    
cout << format("_%1%_ %1% \n") % group(showpos, setw(5), 101);
    操纵器会应用于 %1% 的每次出现, 因此它打印: "_ +101_ +101 \n"
  • 新的格式化特性: "绝对制表位", 在循环内很有用, 可以确保某个字段从一行到下一行都打印在相同位置, 即使前面参数的宽度变化很大. 
    
for(unsigned int i=0; i < names.size(); ++i)
    cout << format("%1%, %2%, %|40t|%3%\n") % names[i] % surname[i] % tel[i];
    对于某个 std::vector names、surnames 和 tel (见 sample_new_features.cpp), 它打印: 
    Marc-François Michel, Durand,           +33 (0) 123 456 789
Jean, de Lattre de Tassigny,            +33 (0) 987 654 321

语法

boost::format( 格式化串 ) % arg1 % arg2 % ... % argN

格式化串 包含文本, 其中的特殊指令将被替换为由给定参数格式化得到的字符串.
C 和 C++ 世界中的传统语法就是 printf 所用的语法, 因此 format 可以直接使用 printf 格式化串并产生相同的结果(几乎所有情况下如此, 详见 与 printf 的不兼容之处)
这一核心语法经过了扩展, 以支持新特性, 同时也适应 C++ 流的语境. 因此, format 接受格式化串中指令的多种形式:

  • 传统 printf 格式化串: %spec, 其中 spec 是一个 printf 格式说明
    . spec 传递格式化选项, 如宽度、对齐、格式化数字所用进制, 以及其他特定标志. 但 printf 经典的 类型说明 标志在 format 中含义较弱. 它只在内部流上设置相应的标志和/或格式化参数, 而不要求对应参数具有特定类型.
    例如: 说明 2$x 对 printf 意为"以十六进制打印第 2 个参数(它是一个整数)", 而对 format 仅意味着"以流基域标志设为 hex 的方式打印参数 2".
  • %|spec|, 其中 spec 是一个 printf 格式说明.
    引入这种以竖线分隔的语法, 是为了提高格式化串的可读性, 但主要是为了使 spec 中的 类型转换字符 成为可选. 对 C++ 变量而言这一信息并非必需, 但在直接 printf 语法中, 必须始终给出类型转换字符, 原因仅仅是该字符对确定格式说明的结束位置至关重要.
    例如: "%|-5|" 将以宽度 5 和左对齐格式化下一个变量, 与以下 printf 指令相同: "%-5g"、"%-5f"、"%-5s" 等.
  • %N%
    这种简单的位置记法请求格式化第 N 个参数, 不带任何格式化选项.
    (它只是 printf 位置指令(如 "%N$s")的简写, 但一个主要好处是可读性好得多, 并且不使用"类型转换"字符)
在标准 printf 格式说明之上, 还实现了新特性, 例如居中对齐. 详见 新增格式说明.

printf 格式说明

Boost.format 支持的 printf 格式说明遵循 Unix98 Open-group printf 的精确语法, 而非标准 C printf——后者不支持位置参数.(常见标志在两者中含义相同, 因此不应对任何人造成困扰)
注意, 在同一个格式化串中把位置格式说明(如 %3$+d)与非位置格式说明混用(如 %+d)是错误的.
在 Open-group 规范中, 多次引用同一个参数(如 "%1$d %1$d")的行为是未定义的. Boost.format 在这种情况下的行为是允许每个参数被引用任意多次. 唯一的约束是它期望恰好 P 个参数, P 是格式化串中用到的最大参数编号.(例如, 对于 "%1$d %10$d", P == 10)
提供多于或少于 P 个参数会抛出异常.(除非另行设置, 见 异常)

一个说明 spec 具有如下形式: 

    [ N$ ] [ flags ] [ width ] [ . precision ] [ argument-type ] conversion-specifier
方括号内的字段是可选的. 这些字段将在下面的列表中逐一说明:

  • N $ (可选字段) 指定该格式说明应用于第 N 个参数(这称为 位置格式说明).
    如果没有这一项, 参数将逐个取用.(而且此后再提供参数编号就是错误的)

  • flags 是由以下任意项组成的序列:
    标志 含义 对内部流的影响
    '-' 左对齐 不适用 (稍后在字符串上应用)
    '=' 居中对齐 不适用 (稍后在字符串上应用)
    - 注: 新增特性, printf 中没有 -
    '_' 内部对齐 设置内部对齐
    - 注: 新增特性, printf 中没有 -
    '+' 即使对正数也显示符号 设置 showpos
    '#' 显示进制前缀和小数点 设置 showbase 和 showpoint
    '0' 用 0 填充(插入在符号或进制指示符之后) 如果不是左对齐, 则调用 setfill('0') 并设置 internal
    . 在流转换之后会采取额外动作以处理 用户自定义输出.
    ' ' 如果字符串不以 + 或 - 开头, 则在转换后的字符串之前插入一个 空格 不适用 (稍后在字符串上应用)
    与 printf 的行为不同: 它不受内部对齐影响

  • width 为转换得到的字符串指定最小宽度. 如有必要, 将按照在流上通过操纵器设置的、或由格式化串指定的对齐与填充字符对字符串进行填充(例如标志 '0'、'-' 等).
    注意, width 并不只是设置在转换流上. 为了支持 用户自定义类型 的输出(它们可能对多个成员多次调用 operator<<), 宽度是在整个参数对象完成流转换之后由 format 类代码处理的.

  • precision (前面带一个点) 设置流的 precision
    • 输出浮点类型数字时, 设置最大位数
      • 在 fixed 或 scientific 模式下指小数点后的位数
      • 在默认模式("general 模式", 类似 %g)下指总位数
    • 与类型字符 s 或 S 一起使用时有另一个含义: 转换字符串将被截断为前 precision 个字符.(注意, 向 width 的最终填充是在截断之后进行的.)

  • argument-type 被 printf 系列函数用来正确处理通过变长参数传入的参数. 而使用 boost::format 时, 参数通过 operator % 喂入 format, 这使模板能够携带参数类型. 因此经典的 printf 风格参数类型会被消费并忽略. 可识别的参数类型有 hh、h、l、ll、j、z 和 L, 以及微软扩展 w、I(大写 i)、I32 和 I64. ISO C99 标准中的参数类型 t 不被识别为参数类型, 因为多年来它在 boost::format 中一直被用作表格输出的转换说明符.

  • conversion-specifier 并 不会 强制相关参数属于某个受限的类型集合, 而只是设置与类型说明相关联的 ios 标志:
    转换说明符 含义 对流的影响
    b 布尔字符串输出 设置 boolalpha; 仅对类型 bool
    有效. 要定制结果字符串, 参见 std::numpunct.
    p 或 x 十六进制输出 设置 hex
    o 八进制输出 设置 oct
    a 十六进制指数记法 把 floatfield 位设置为 scientific | fixed (等价于 hexfloat)
    e 科学计数浮点格式 把 floatfield 位设置为 scientific
    f 定点浮点格式 把 floatfield 位设置为 fixed
    g 常规(默认)浮点格式 清除所有 floatfield 位
    X, A, E, F 或 G 效果与其小写对应物相同, 但数字输出(指数、十六进制数字等)使用大写字母. 分别与 'x'、'a'、'e'、'f' 或 'g' 效果相同, 外加 大写
    d, i 或 u 十进制类型输出 把 basefield 位设置为 dec
    s 或 S 字符串输出 precision 说明未设置, 其值进入一个内部字段, 供稍后的"截断"使用.(见上文 precision 的解释)
    c 或 C 单字符输出 只使用转换字符串的第一个字符.
    % 打印字符 % N/A

    注意, 'n' 转换说明符(及其对应参数)会被忽略, 因为它不适合此处语境.

新增格式说明

  • 如标志表所述, 新增了居中对齐和内部对齐标志(' = ' 和 ' _ ').
  • %{nt} (其中 n 为正数)插入一个 绝对制表位. 意思是, format 会在必要时用字符填充字符串, 直到目前生成的字符串长度达到 n 个字符.(参见 示例)
  • %|nTX| 以相同方式插入制表位, 但使用 X 作为填充字符, 而不是流当前的 "fill" 字符(处于默认状态的流该字符为 空格)

与 printf 的行为差异

假设你有一些变量 x1, x2 (C 的 printf 支持的内置类型),
以及一个打算这样配合 printf 函数使用的格式化串 s: 
printf(s, x1, x2);

在几乎所有情况下, 结果都将与此命令相同: 
cout << format(s) % x1 % x2;

但由于某些 printf 格式说明不能很好地转化为流的格式化选项, Boost.format 模拟 printf 的方式存在一些明显的不完善之处.
无论如何, format 类都会安静地忽略不支持的选项, 因此 printf 格式化串总能被 format 接受, 并产生与 printf 几乎相同的输出.


下面是这些差异的完整清单:
  • '0' 和 ' ' 选项: printf 对非数值转换忽略这些选项, 但 format 会把它们应用于所有类型的变量.(因此可以把这些选项用于用户自定义类型, 例如 Rational 类等)
  • precision 对整数类型参数在 printf 中有特殊含义:
    printf( "(%5.3d)" , 7 ) ; 打印 « ( 007) »
    而 format 与流一样, 对整数类型转换忽略 precision 参数.
  • printf 的 ' 选项(用千位分组字符格式化)在 format 中没有效果.
  • 设置为星号(*)的宽度或精度被 printf 用来从参数中读取该字段. 例如 printf("%1$d:%2$.*3$d:%4$.*3$d\n", hour, min, precision, sec);
    该类目前不支持这种机制, 因此解析时会安静地忽略此类精度或宽度字段.
  • 参数类型被忽略
另外, 注意特殊的 'n' 类型说明(用于告诉 printf 把格式化输出的字符数保存到一个变量中)在 format 中没有效果.
因此, 含有该类型说明的格式化串由 printf 或 format 应当产生相同的转换字符串. 它不会造成 printf 与 format 之间格式化字符串的差异.
要用 Boost.Format 获取格式化字符串的字符数, 可以使用 size() 成员函数: 
format formatter("%+5d");
cout << formatter % x;
unsigned int n = formatter.size();

用户自定义类型的输出

所有被转化为对流状态修改的标志都会在用户自定义类型内部递归起作用.(这些标志保持有效, 所需的格式化选项也一样, 对用户自定义类可能调用的每个 '<<' 操作都如此)

例如, 对于一个 Rational 类, 我们会遇到类似这样的情况: 
Rational ratio(16,9);
cerr << format("%#x \n")  % ratio;  // -> "0x10/0x9 \n"

其他格式化选项则情况不同. 例如, 设置宽度作用于对象最终产生的输出, 而不是其每一次内部输出, 而这正合我们意:

cerr << format("%-8d")  % ratio;  // -> "16/9    "      and not    "16      /9       "
cerr << format("%=8d")  % ratio;  // -> "  16/9  "      and not    "   16   /    9   "


但 0 和 ' ' 选项同样如此(与 '+' 不同, 后者通过 showpos 直接转化到流状态. 但 printf 的 0 和空格选项没有对应的流标志)
而这就不那么自然了:

cerr << format("%+08d \n")  % ratio;  // -> "+00016/9"
cerr << format("% 08d \n")  % ratio;  // -> "000 16/9"
通过精心设计 Rational 的 operator<<, 让它自行处理流的宽度、对齐和 showpos 参数, 可以获得更好的行为. sample_userType.cpp 对此做了演示.

操纵器与流的内部状态

format 的内部流状态会在输出参数之前保存、之后恢复; 因此, 修饰符不是粘性的, 只影响它们所应用的那个参数.
标准规定的流默认状态为: precision 6、width 0、右对齐, 以及设置了 decimal 标志.

内部 format 流的状态可以通过与参数一起传入的操纵器改变; 借助 group 函数, 像这样:

cout << format("%1% %2% %1%\n") % group(hex, showbase, 40) % 50; // prints "0x28 50 0x28\n"


当在一个 'group' 中传入 N 项时, Boost.format 需要以不同于普通参数的方式处理操纵器, 因此使用 group 受以下约束:

  1. 要打印的对象必须作为 group 中的最后一项传入
  2. 前 N-1 项被视为操纵器, 如果它们产生了输出, 该输出会被丢弃

这样的操纵器会在每次出现时、紧接着下一个参数之前传给流. 注意, 以这种方式传入的流状态修饰符会覆盖格式化串中指定的格式化选项. 例如在下面的代码中, hex 操纵器的优先级高于格式化串中本会设置十进制输出的 d 类型说明:

cout << format("%1$d %2% %1%\n") % group(hex, showbase, 40) % 50; 
// prints "0x28 50 0x28\n"

替代方案

  • printf 是经典的替代方案, 它不是类型安全的, 也不能扩展到用户自定义类型.
  • Karl Nelson 的 ofrstream.cc 设计是本 format 类的一大灵感来源.
  • James Kanze 的库有一个 format 类(位于 srcode/Extended/format ), 看起来打磨得非常好. 其设计与本类的共同点在于: 使用内部流进行实际转换, 并且使用运算符传递参数.(不过他的类与 ofrstream 一样使用 operator<< 而 不是 operator% )
  • Karl Nelson 的库 是在 Boost 邮件列表讨论 Boost.format 设计时, 作为备选方案的演示而写成的.
  • {fmt}, 作者 Victor Zverovich.

异常

Boost.format 对 format 对象的使用施加了若干规则: 格式化串必须遵守上文所述的语法; 在输出到最终目的地之前, 用户必须恰好提供数量正确的参数; 如果使用 modify_item 或 bind_arg, 条目和参数的索引不得越界.
当 format 检测到其中某条规则未被满足时, 会抛出相应的异常, 使错误不会被漏掉或置之不理.
但用户可以改变这种行为以适应自己的需要, 使用以下函数选择哪些类型的错误会抛出异常:


unsigned char exceptions(unsigned char newexcept); // query and set
unsigned char exceptions() const;                  // just query

用户可以用二元算术组合以下原子量, 计算出参数 newexcept:

  • boost::io::bad_format_string_bit 选择因格式化串格式错误导致的错误.
  • boost::io::too_few_args_bit 选择因在所有参数传入之前就请求字符串结果导致的错误.
  • boost::io::too_many_args_bit 选择因传入过多参数导致的错误.
  • boost::io::out_of_range_bit 选择因调用 modify_item 或其他接受条目索引(或参数索引)的函数时用户提供的索引越界导致的错误.
  • boost::io::all_error_bits 选择全部错误
  • boost::io::no_error_bits 不选择任何错误.

例如, 如果你不想让 Boost.format 检测参数个数错误, 可以定义一个特定的包装函数, 用正确的异常设置来构建 format 对象:


boost::format  my_fmt(const std::string & f_string) {
    using namespace boost::io;
    format fmter(f_string);
    fmter.exceptions( all_error_bits ^ ( too_many_args_bit | too_few_args_bit )  );
    return fmter;
}
因此, 允许提供多于所需的参数(它们会被简单地忽略): 

cout << my_fmt(" %1% %2% \n") % 1 % 2 % 3 % 4 % 5;
而如果我们在所有参数提供完毕之前请求结果, 结果的相应部分就只是空的 

cout << my_fmt(" _%2%_ _%1%_ \n") % 1 ;
// prints      " __ _1_ \n"

关于性能的说明

对于带重排的少量内置类型参数格式化, boost::format 的性能可以与 Posix-printf 以及等价的手工流操作相比较, 以衡量其带来的开销. 结果可能极大地取决于编译器、标准库实现, 以及格式化串和参数的具体选择.

常见的流实现最终会调用 printf 系列函数来实际格式化数字. 一般而言, 由于重排的开销(为存储字符串片段而进行的分配、每个条目格式化时的流初始化等), printf 会明显快于直接的流操作. 直接的流操作会比 boost::format 快——预期比率在 2 到 5 甚至更高.

当迭代格式化成为性能瓶颈时, 可以通过把格式化串解析为一个 format 对象, 并在每次格式化时复制该对象, 来略微提高性能, 如下所示:

    const boost::format fmter(fstring);
    dest << boost::format(fmter) % arg1 % arg2 % arg3 ;

作为性能结果的一个示例, 作者用 4 种不同方法测量了迭代格式化的执行时间:

  1. posix printf
  2. 手工流输出(输出到一个哑 nullStream 流, 把字节送入虚空)
  3. 如上所示, 从 const 对象复制的 boost::format
  4. 直接的 boost::format 用法

测试用 g++-3.3.3 编译, 测得如下计时(以秒为单位, 并给出比率):

double     arg2=12.34;
int        arg3=23;

设计理由

该类的目标是提供一个更好的、C++ 的、类型安全且类型可扩展的 printf 等价物, 与流配合使用.

确切地说, format 的设计目标是提供以下特性:
  • 支持位置参数(国际化所必需)
  • 接受不限个数的参数.
  • 使格式化命令在视觉上自然.
  • 除格式化串语法之外, 还支持使用操纵器来修改参数的显示.
  • 接受任何类型的变量, 实际转换成字符串的过程交给流完成. 这尤其针对用户自定义类型, 其格式化选项的效果应当直觉自然.
  • 在类型安全且类型可扩展的语境下, 尽可能提供 printf 兼容性.

在设计过程中遇到了许多问题, 也做出了一些可能并不直觉正确的选择. 但每种情况下的选择都有 相应理由.
