常见问题 (FAQ)

我为什么要用 Boost.CallableTraits?

如果你不编写泛型代码, 就不应该使用 Boost.CallableTraits.

如果你 确实 在编写泛型代码, 花点时间浏览你的头文件, 看看能否找到类似这样的代码:

template<class Return, class First, class Second>
class foo<Return(First, Second)> {
    //    ^^^^^^^^^^^^^^^^^^^^^
};

或者也许像这样:

template<class Return, class ...Args>
class foo<Return(*)(Args...)> {
    //    ^^^^^^^^^^^^^^^^^^
};

或者, 如果你 实在 不走运, 会像这样:

template<class Return, class T, class ...Args>
class foo<Return(T::*)(Args..., ...) const volatile & noexcept> {
    //    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
};

有了 Boost.CallableTraits, 你可以摆脱所有这些模板特化 (就目前而言, 除非你要处理平台特定的调用约定). 即使你只是对 Return(Args...) 这样的简单函数类型做特化, Boost.CallableTraits 也可能对你有用. 你会发现 Boost.CallableTraits 能帮助你的代码更易读、更易维护、更通用、更不易出错.

Boost.CallableTraits 在许多平台上经过了充分测试. Boost.CallableTraits 正确处理了许多经常被忽视的边角情况. 随着 C++ 不断增加新特性, 对一个正规库方案的需求也在增长.

Boost 是一个庞大的依赖. 我真的需要它吗?

不需要! Boost.CallableTraits 没有任何依赖, 你只需要 Boost.CallableTraits 头文件.

为什么添加成员函数引用限定符时要使用引用折叠规则?

尽管是人为规定的, 引用折叠规则是良定义的, 且已为许多 C++ 开发者所熟知. 其他任何规则都会成为记忆负担. 这也与 <type_traits> 中提供的元函数相呼应.

当模板约束被违反时, 本库的许多特性会导致"替换失败". 这是否意味着我可以在 SFINAE 上下文中违反约束, 只要存在另一个合法的替换?

可以. 违反约束时的 SFINAE 可用性已在受支持的编译器上得到广泛测试.

调用约定呢?

我最初为各种平台特定的调用约定实现了相应特性. 然而, 这些特性需要多得多的平台特定测试用例. 代码在设计上仍然可以容纳此类特性, 因此如果有人感兴趣, 我会考虑在将来添加.
