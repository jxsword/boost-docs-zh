差分进化

概要 

#include <boost/math/optimization/differential_evolution.hpp>

namespace boost::math::optimization {

template <typename ArgumentContainer> struct differential_evolution_parameters {
    using Real = typename ArgumentContainer::value_type;
    ArgumentContainer lower_bounds;
    ArgumentContainer upper_bounds;
    Real mutation_factor = static_cast<Real>(0.65);
    double crossover_probability = 0.5;
    // Population in each generation:
    size_t NP = 200;
    size_t max_generations = 1000;
    size_t threads = std::thread::hardware_concurrency();
    ArgumentContainer const * initial_guess = nullptr;
};

template <typename ArgumentContainer, class Func, class URBG>
ArgumentContainer differential_evolution(
    const Func cost_function, differential_evolution_parameters<ArgumentContainer> const &de_params, URBG &g,
    std::invoke_result_t<Func, ArgumentContainer> target_value = std::numeric_limits<std::invoke_result_t<Func, ArgumentContainer>>::quiet_NaN(),
    std::atomic<bool> *cancellation = nullptr,
    std::atomic<std::invoke_result_t<Func, ArgumentContainer>> *current_minimum_cost = nullptr,
    std::vector<std::pair<ArgumentContainer, std::invoke_result_t<Func, ArgumentContainer>>> *queries = nullptr);

} // namespaces

differential_evolution 函数实现了 (经典) 差分进化优化算法, 通常以 de/rand/bin/1 为标签. 它能够最小化定义在由一组界表示的连续空间上的代价函数. 此函数的设计更多着眼于进度可观测、优雅取消和事后数据分析, 而非收敛速度. 我们援引 Wolpert 和 Macready 的“没有免费的午餐”定理来为这一设计选择辩护, 该定理表明“对任何算法而言, 在一类问题上的任何优异表现都会被在另一类问题上的表现所抵消”.

参数

  • lower_bounds: 一个容器, 表示优化空间沿每个维度的下界. 边界的 .size() 应返回问题的维度.
  • upper_bounds: 一个容器, 表示优化空间沿每个维度的上界. 它应与 lower_bounds 大小相同, 且每个元素应 >= lower_bounds 的对应元素.
  • mutation_factor: 文献中也称为 F 或缩放因子. 它控制种群演化的速率 (默认为 0.65).
  • crossover_probability: 交叉概率, 决定探索与利用之间的权衡 (默认为 0.5).
  • NP: 种群规模 (默认为 200). 并行化在种群上进行, 因此此值应“较大”.
  • max_generations: 优化的最大代数 (默认为 1000).
  • threads: 用于并行化的线程数 (默认为硬件并发数). 若目标函数本身已多线程, 则应设为 1 以避免超额订阅.
  • initial_guess: 一个可选的初值, 指示应从何处开始寻找解.

默认值是阅读 Price、Storn 和 Lampinen 第 3 章后选定的; 种群规模除外 - 我们选得比书中找到的稍大一些, 因为自该文献发表以来核心数量已经增加, 且并行化发生在每一代内部. 注意, 在寻找全局极小值与收敛速度之间存在权衡. 降低陷入局部极小值概率的最稳健方法是增大种群规模.

函数 

template <typename ArgumentContainer, class Func, class URBG>
ArgumentContainer differential_evolution(const Func cost_function,
                                         differential_evolution_parameters<ArgumentContainer> const &de_params,
                                         URBG &gen,
                                         std::invoke_result_t<Func, ArgumentContainer> value_to_reach
                                           = std::numeric_limits<std::invoke_result_t<Func, ArgumentContainer>>::quiet_NaN(),
                                         std::atomic<bool> *cancellation = nullptr,
                                         std::atomic<std::invoke_result_t<Func, ArgumentContainer>> *current_minimum_cost = nullptr,
                                         std::vector<std::pair<ArgumentContainer, std::invoke_result_t<Func, ArgumentContainer>>> *queries = nullptr)

参数:

  • cost_function: 要最小化的代价函数.
  • de_params: 如上所述的算法参数.
  • rng: 一个均匀随机位生成器, 例如 std::mt19937_64.
  • value_to_reach: 一个可选值, 一旦达到即停止优化. 这是终止计算最稳健的方式, 但在大多数情况下代价函数的最优值是未知的. 如果已知, 就用它! 关于何时可以推导出目标值, 所引著作中有清晰的示例.
  • cancellation: 一个可选的原子布尔量, 允许用户停止计算并优雅地返回到该时刻为止所找到的最佳结果. 注意: 取消不是立即生效的; 正在进行的当前代会执行完毕.
  • current_minimum_cost: 一个可选的原子变量, 用于在优化期间存储当前最小代价. 这使开发者可以 (例如) 绘制最小化随时间的进展曲线, 并与取消实参配合, 在进展停滞时终止计算. 有关此方法的注意事项参见 Price、Storn 和 Lampinen 第 3.2 节.
  • queries: 一个可选的向量, 用于存储优化过程中的中间结果. 这对调试以及 (或许) 在计算完成后对目标函数做体渲染很有用.

返回:

与优化找到的最小代价相对应的 ArgumentContainer.

注意: 终止准则是“或”而不是“与”. 因此, 一旦达到最大代数, 迭代就会停止, 即使 (比方说) 尚未达到 value_to_reach.

注意事项

我们决定只支持经典的 de/rand/1/bin, 因为就现状而言该类的参数已经太多, 而且我们还没有看到表明该算法其他变体表现更好的基准测试. 如果有人给出令人信服的用例, 可以添加对 de/x/y/z 变体的支持.

支持的终止准则是: 显式请求终止、要达到的值 (value-to-reach) 和最大代数. Price、Storn 和 Lampinen 第 2.8 节还列出了种群统计量以及多代内无可接受试验等合理的终止准则. 若有需求, 这些也可以支持.

使用 std::thread 进行并行化确实有开销 - 对非常快的函数调用尤其如此. 我们发现, 若要并行化明确带来收益, 函数调用大约需要 1 微秒. 不过, 我们没有提供条件并行化, 因为计算代价低廉的代价函数是例外而非常态. 如果有条件并行化的明确用例 (维度非常高但代价函数很便宜就是一个好例子), 我们可以提供.
