与用户自定义类型一起使用

高精度用户自定义类型最常见的例子大概是 Boost.Multiprecision.

在用户自定义类型上使用函数调用常数的语法与模板类中相同, 也就是说我们使用:

#include <boost/math/constants/constants.hpp>

boost::math::constants::pi<UserDefinedType>();

例如:

boost::math::constants::pi<boost::multiprecision::cpp_dec_float_50>();

得到精度为 50 位十进制数字的 π.

然而, 由于用户自定义类型的精度可能远高于内建浮点类型, 返回值的创建方式如下:

  • 如果类型的精度在编译期已知:
    • 如果精度小于等于某个 float 的精度, 且该类型可以从 float 构造, 那么我们的代码返回一个 float 字面量. 如果用户自定义类型是字面类型, 那么返回该常数的函数调用将是一个 constexp.
    • 如果精度小于等于某个 double 的精度, 且该类型可以从 double 构造, 那么我们的代码返回一个 double 字面量. 如果用户自定义类型是字面类型, 那么返回该常数的函数调用将是一个 constexp.
    • 如果精度小于等于某个 long double 的精度, 且该类型可以从 long double 构造, 那么我们的代码返回一个 long double 字面量. 如果用户自定义类型是字面类型, 那么返回该常数的函数调用将是一个 constexp.
    • 如果精度小于等于某个 __float128 的精度 (且编译器支持这样的类型), 且该类型可以从 __float128 构造, 那么我们的代码返回一个 __float128 字面量. 如果用户自定义类型是字面类型, 那么返回该常数的函数调用将是一个 constexp.
    • 如果精度小于 100 位十进制数字, 则该常数将从常数的字符串表示构造 (仅构造一次, 然后以线程安全的方式缓存). 在这种情况下, 该值作为对缓存值的 const 引用返回.
    • 否则, 该值将被计算 (仅计算一次, 然后以线程安全的方式缓存). 在这种情况下, 该值作为对缓存值的 const 引用返回.
  • 如果精度在编译期未知, 那么:
    • 如果运行期精度 (通过调用 boost::math::tools::digits<T>() 获得) 小于 100 位十进制数字, 则该常数从常数的字符串表示 "即时" 构造.
    • 否则, 该值通过使用该类型当前的默认精度计算常数来 "即时" 构造. 注意, 这可能使常数的使用相当昂贵.

此外, 可以把一个 Policy 类型作为第二个模板参数传入, 并用它来控制精度:

#include <boost/math/constants/constants.hpp>

typedef boost::math::policies::policy<boost::math::policies::digits2<80> > my_policy_type;
boost::math::constants::pi<MyType, my_policy_type>();
注释

Boost.Math 不知道如何控制 MyType 的内部精度; policy 只控制上述选择过程如何进行, 以及在结果被计算时的计算精度.

也可以通过特化 traits 类 construction_traits 来控制用哪种方法构造常数:

namespace boost{ namespace math{ namespace constant{

template <class T, class Policy>
struct construction_traits
{
   typedef std::integral_constant<int, N> type;
};

}}} // namespaces

其中 N 取以下值之一:

N

含义

0

精度在编译期不可用; 根据运行期精度, 要么从十进制数字字符串构造, 要么即时计算.

1

返回 float 精度的常数.

2

返回 double 精度的常数.

3

返回 long double 精度的常数.

4

从字符串表示构造结果, 并缓存结果.

任何其他值 N

把编译期精度设为 N 位.
GPU 支持

所有 Boost.Math 常数都用 BOOST_MATH_GPU_ENABLED 标记, 可在主机和设备上使用. 注意, 在设备上运行时, 你只能使用 float 和 double 类型.

定制特化常数

此外, 对需要特殊处理的用户自定义类型, 可以部分特化每个常数使用的内部结构. 例如, 假设我们使用围绕 MPFR 的 C++ 封装 mpfr_class: 它有自己的 Pi 表示, 我们很可能希望用它来取代上述机制. 我们可以通过特化类模板 boost::math::constants::detail::constant_pi 来实现:

namespace boost{ namespace math{ namespace constants{ namespace detail{

template<>
struct constant_pi<mpfr_class>
{
   template<int N>
   static mpfr_class get(const std::integral_constant<int, N>&)
   {
      // The template param N is one of the values in the table above,
      // we can either handle all cases in one as is the case here,
      // or overload "get" for the different options.
      mpfr_class result;
      mpfr_const_pi(result.get_mpfr_t(), GMP_RNDN);
      return result;
   }
};

}}}} // namespaces
诊断元编程代码在做什么

最后, 由于诊断元编程代码在做什么可能很棘手, 提供了一个诊断例程, 打印关于本库将如何处理特定类型的信息, 可以这样使用它:

#include <boost/math/constants/info.hpp>

int main()
{
   boost::math::constants::print_info_on_type<MyType>();
}

如果你愿意, 也可以向 print_info_on_type 函数传递一个可选的 std::ostream 参数. 用户自定义类型的典型输出如下:
