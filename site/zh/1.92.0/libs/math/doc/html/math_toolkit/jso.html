jSO 算法

概要 

#include <boost/math/optimization/jso.hpp>

namespace boost::math::optimization {

template <typename ArgumentContainer> struct jso_parameters {
    using Real = typename ArgumentContainer::value_type;
    ArgumentContainer lower_bounds;
    ArgumentContainer upper_bounds;
    size_t initial_population_size = 0;
    size_t max_function_evaluations = 0;
    ArgumentContainer const * initial_guess = nullptr;
};

template <typename ArgumentContainer, class Func, class URBG>
ArgumentContainer jso(
    const Func cost_function, jso_parameters<ArgumentContainer> const &jso_params, URBG &gen,
    std::invoke_result_t<Func, ArgumentContainer> target_value = std::numeric_limits<std::invoke_result_t<Func, ArgumentContainer>>::quiet_NaN(),
    std::atomic<bool> *cancellation = nullptr,
    std::atomic<std::invoke_result_t<Func, ArgumentContainer>> *current_minimum_cost = nullptr
    std::vector<std::pair<ArgumentContainer, std::invoke_result_t<Func, ArgumentContainer>>> *queries = nullptr);

} // namespaces

jso 函数提供了 Brest 等人 2017 年论文中描述的 jSO 算法的 (希望是) 忠实实现. 该算法在 2017 年进化计算竞赛中获得第二名. 它是对经典差分进化算法的改进, 以这样一种方式自适应调整参数: 在算法早期阶段偏向探索, 在后期阶段偏向开发. 特别地, 它融入了文献中的诸多思想 (尤其是 SHADE 和 L-SHADE) 以帮助快速收敛. 这些思想包括: 使用被拒绝向量的历史档案来提供收敛方向信息, 根据交叉和变异参数是否与成功更新相关联来对其进行自适应调整, 种群规模的线性缩减, 以及"current-to-p-best"变异.

与我们的差分进化实现一样, 它最小化一个定义在由一组界表示的连续空间上的代价函数. 同样, 该函数的设计更多是为了进度可观测性、优雅取消和事后数据分析, 而非收敛速度.

参数

  • lower_bounds: 一个容器, 表示优化空间沿每个维度的下界. 边界的 .size() 应返回问题的维度.
  • upper_bounds: 一个容器, 表示优化空间沿每个维度的上界. 它应与 lower_bounds 大小相同, 且每个元素应 >= lower_bounds 的对应元素.
  • initial_population_size: 第一代种群应有多大. 默认为 ceil(25log(D+1)sqrt(D)), 其中 D 是问题的维数.
  • max_function_evaluations: 默认为 10000D, 其中 D 是空间的维数.
  • initial_guess: 一个可选的初值, 指示应从何处开始寻找解.

这些默认值取自对 Brest 2017 的研读.

函数 

template <typename ArgumentContainer, class Func, class URBG>
ArgumentContainer jso(const Func cost_function,
                      jso_parameters<ArgumentContainer> const &jso_params,
                      URBG &gen,
                      std::invoke_result_t<Func, ArgumentContainer> value_to_reach
                        = std::numeric_limits<std::invoke_result_t<Func, ArgumentContainer>>::quiet_NaN(),
                      std::atomic<bool> *cancellation = nullptr,
                      std::atomic<std::invoke_result_t<Func, ArgumentContainer>> *current_minimum_cost = nullptr,
                      std::vector<std::pair<ArgumentContainer, std::invoke_result_t<Func, ArgumentContainer>>> *queries = nullptr)

参数:

  • cost_function: 要最小化的代价函数.
  • jso_params: 如上所述的算法参数.
  • gen: 一个均匀随机位生成器, 例如 std::mt19937_64.
  • value_to_reach: 一个可选值, 一旦达到即停止优化. 这是终止计算最稳健的方式, 但在大多数情况下代价函数的最优值是未知的. 如果已知, 就用它! 物理上的考虑常可用于求出代价函数的最优值.
  • cancellation: 一个可选的原子布尔量, 允许用户停止计算并优雅地返回到该时刻为止所找到的最佳结果. 注意: 取消不是立即生效的; 正在进行的当前代会执行完毕.
  • current_minimum_cost: 一个可选的原子变量, 用于在优化期间存储当前最小代价. 这使开发者可以 (例如) 绘制最小化随时间的进展曲线, 并与 cancellation 实参配合, 在进展停滞时终止计算.
  • queries: 一个可选的向量, 用于存储优化过程中的中间结果. 这对调试以及 (或许) 在计算完成后对目标函数做体渲染很有用.

返回:

与优化找到的最小代价对应的参数向量.

注意: 终止准则是“或”而不是“与”. 因此, 一旦达到最大代数, 迭代就会停止, 即使 (比方说) 尚未达到 value_to_reach.

如果想更深入地观察优化过程, 请以 -DBOOST_MATH_DEBUG_JSO=1 编译
