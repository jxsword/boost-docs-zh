设计理由

<boost/cstdfloat.hpp> 的实现旨在利用 1989 年 C 标准定义的 <float.h>. 预处理器用于查询 <float.h> 中的某些预处理器定义, 如 FLT_MAX、DBL_MAX 等. 根据这些查询的结果, 会尝试自动检测具有指定宽度的内置浮点类型执行一项要求符合 IEEE_floating_point (IEC599) 的明确测试, 该测试基于 std::numeric_limits<>::is_iec559, 并使用 static_assert.

此外, 该 Boost 实现 <boost/cstdfloat.hpp> 支持 80 位浮点 typedef (如果可以检测到) 和 128 位浮点 typedef (如果可以检测到), 前提是底层类型符合 IEEE-754 precision extension (该类型的 std::numeric_limits<>::is_iec559 == true 已提供).

头文件 <boost/cstdfloat.hpp> 使标准化的浮点 typedef 得以在 namespace boost 中安全可用, 而不向 namespace std 放置任何名称. 其意图是与未来可能包含这些 typedef 的 C/C++ 标准库互补而非竞争. 如果未来的某个 C/C++ 标准包含 <stdfloat.h> 和 <cstdfloat>, 那么 <boost/cstdfloat.hpp> 将继续工作, 但会变得冗余, 可以安全地弃用.

因为 <boost/cstdfloat.hpp> 是 Boost 头文件, 其名称遵循 Boost 头文件命名约定, 而非 C++ 标准库头文件命名约定.

注释

<boost/cstdfloat.hpp> 在编译器未提供底层类型时, 无法合成或创建 typedef . 例如, 如果编译器没有 128 位的底层浮点类型 (科学和数值编程中非常渴望的), 那么 float128_t 及其对应的 least 和 fast 类型 不会 由 <boost/cstdfloat.hpp> 提供.

警告

如果 <boost/cstdfloat.hpp> 使用了编译器特有的非标准化类型 (并非 派生自 float, double, 或 long double) 作为其一个或多个浮点 typedef, 则无法保证这些类型会有 numeric_limits<> 的特化可用. 通常, numeric_limits<> 的特化只有当编译器自身支持底层类型对应的特化时才可用; 例外是 GCC 的 __float128 类型和 Intel 的 _Quad 类型, 它们通过我们自己的代码显式支持.

警告

作为实现的附带产物, <float.h> 中的某些 C 宏名可能对 <boost/cstdfloat.hpp> 的用户可见. 不要依赖使用这些宏; 它们不属于任何 Boost 指定的接口. 请改用 std::numeric_limits<> 来获取浮点范围等.

提示

为获得最佳结果, <boost/cstdfloat.hpp> 应在其他定义使用 <cmath> 中标准库函数的泛型代码的头文件之前被 #include.

这是因为 <boost/cstdfloat.hpp> 可能定义标准库函数的重载, 其中某个指定宽度类型使用了非标准类型 (即 float、double 或 long double 以外的类型). 如果泛型代码 (例如在另一个 Boost.Math 头文件中) 调用标准库函数, 那么只有当这些重载在使用点之前已定义时才会找到正确的重载. 更多细节参见 overloading template functions with float128_t 以及 cstdfloat.hpp 的实现.

因此, 把 #include <boost/cstdfloat.hpp> 作为 第一个包含 通常最好.
