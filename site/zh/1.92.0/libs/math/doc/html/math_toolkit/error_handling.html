错误处理

快速参考

本库对错误的处理分为两个正交的部分:

  • 引发了哪种错误?
  • 错误引发时应当做什么?
警告

默认的错误动作是抛出带有详尽错误信息的异常. 如果你不试图捕获该异常, 你将看不到这条消息!

默认行为是通过 boost::throw_exception 抛出异常. 该设施对无异常环境有特殊处理. 若定义了 BOOST_MATH_STANDALONE, 则使用标准库设施 (例如 throw) 进行异常处理.

可以引发的错误种类有:

定义域错误

当函数的一个或多个参数超出范围时发生.

极点错误

当特定参数导致函数在某个没有明确定义残值的极点处求值时发生. 例如, 若 tgamma 恰好在 -2 处求值, 则从稍高于 -2 或稍低于 -2 的方向逼近会得到不同的极限值. 因此函数在此点没有明确定义的值, 将引发极点错误.

上溢错误

当结果为无穷大, 或大到无法用函数返回的数值类型表示时发生.

下溢错误

当结果不为零, 但小到无法用函数返回类型中的任何其他值表示时发生.

非规格化错误

当返回结果将是非规格化值时发生.

舍入错误

当舍入函数 trunc、round 与 modf 之一的参数无法表示为整数类型, 或超出结果类型的范围时发生.

求值错误

当不知道任何求值方法, 或者发生了阻止结果求值的内部错误时发生: 这本不应发生, 但如果发生, 很可能是迭代方法收敛得不够快.

不确定结果错误

当函数对传入的值没有定义的结果时发生.

每种错误条件采取的动作由当前生效的 Policy 决定. 可以通过设置一些配置宏在整个程序范围内更改, 或在命名空间作用域更改, 或在调用点更改 (在函数调用中指定特定的 policy).

可用的动作有:

throw_on_error

抛出最适合该错误条件的异常.

errno_on_error

把 ::errno 设为适当的值, 然后返回最合适的结果

ignore_error

忽略错误, 直接返回最合适的结果.

user_error

调用 用户提供的错误处理器.

设计原理

当前实现的灵活性应当相当明显: 默认行为是根据本库正式评审期间的反馈选择的. 当时的考虑是:

  • 真正的错误应当用异常标记, 而不是遵循 C 兼容行为并设置 ::errno.
  • 数值下溢与非规格化结果在大多数情况下不被视为致命错误, 因此决定忽略它们.
  • 如果存在多个错误, 抛出消息中只报告第一个被检测到的错误.

下面更详细地描述各类错误.

定义域错误

当传给特殊函数的参数超出该函数定义的取值范围时, 函数返回以下结果:

boost::math::policies::raise_domain_error<T>(FunctionName, Message, Val, Policy);

其中 T 是传给函数的浮点类型, FunctionName 是函数名, Message 是描述问题的错误消息, Val 是超出范围的值, Policy 是被调用函数当前使用的 policy.

该函数的默认 policy 行为是抛出 std::domain_error C++ 异常. 但如果 Policy 是忽略错误或设置全局 ::errno, 则将返回 NaN.

选择这一行为是为了协助兼容 ISO/IEC 9899:1999 Programming languages - C 的行为以及 Draft Technical Report on C++ Library Extensions, 2005-06-24, section 5.2.1, paragraph 6:

“上面声明的每个函数, 若任一参数值为 NaN, 则应返回 NaN (Not a Number), 但不应报告定义域错误. 否则, 上面声明的每个函数应仅对满足以下条件的参数值报告定义域错误:
函数描述的 Returns 子句显式规定了定义域, 且这些参数落在规定的定义域之外; 或
对应的数学函数值有非零的虚部分量; 或
对应的数学函数在数学上没有定义.
注 2: 如果一个数学函数对给定的一组参数值是显式定义的, 或者其极限值存在且与逼近方向无关, 则称该数学函数对这组参数值在数学上有定义.”

注意, 为了在抛出异常时支持信息丰富的错误消息, Message 必须包含 Boost.Format 可识别的格式说明符: 参数 Val 会按所用说明符插入错误消息.

例如, 若 Message 含有 "%1%", 则它会被替换为 Val 以 T 的全部精度表示的值; 而 "%.3g" 则会包含 Val 的 3 位数字的值. 更多细节参见 Boost.Format 文档.

在极点处求值

当传给特殊函数的参数位于某个没有明确定义残值的极点时, 函数返回以下结果:

boost::math::policies::raise_pole_error<T>(FunctionName, Message, Val, Policy);

其中 T 是传给函数的浮点类型, FunctionName 是函数名, Message 是描述问题的错误消息, Val 是位于极点处的参数值, Policy 是被调用函数当前使用的 policy.

该函数的默认行为是抛出 std::domain_error 异常. 但可以使用 错误处理策略 改变它, 例如改为 ignore_error 并返回 NaN.

注意, 为了在抛出异常时支持信息丰富的错误消息, Message 必须包含 Boost.Format 可识别的格式说明符: 参数 val 会按所用说明符插入错误消息.

例如, 若 Message 含有 "%1%", 则它会被替换为 val 以 T 的全部精度表示的值; 而 "%.3g" 则会包含 val 的 3 位数字的值. 更多细节参见 Boost.Format 文档.

数值上溢

当特殊函数的结果大到无法放入参数的浮点类型时, 函数返回以下结果:

boost::math::policies::raise_overflow_error<T>(FunctionName, Message, Policy);

其中 T 是传给函数的浮点类型, FunctionName 是函数名, Message 是描述问题的错误消息, Policy 是被调用函数当前使用的 policy.

该函数的默认 policy 是抛出 std::overflow_error C++ 异常. 但如果使用例如 ignore_error policy, 则返回 std::numeric_limits<T>::infinity(). 在这种情况下, 若类型 T 不支持无穷大, 则返回该类型的最大值.

数值下溢

如果已知特殊函数的结果非零, 但计算结果下溢为零, 则函数返回以下结果:

boost::math::policies::raise_underflow_error<T>(FunctionName, Message, Policy);

其中 T 是传给函数的浮点类型, FunctionName 是函数名, Message 是描述问题的错误消息, Policy 是被调用函数当前使用的 policy.

该函数的默认版本返回零. 但使用其他 policy (如 throw_on_error) 时, 会抛出 std::underflow_error C++ 异常.

非规格化错误

如果特殊函数的结果是非规格化值 z, 则函数返回以下结果:

boost::math::policies::raise_denorm_error<T>(z, FunctionName, Message, Policy);

其中 T 是传给函数的浮点类型, FunctionName 是函数名, Message 是描述问题的错误消息, Policy 是被调用函数当前使用的 policy.

该函数的默认版本返回 z. 但使用其他 policy (如 throw_on_error) 时, 会抛出 std::underflow_error C++ 异常.

求值错误

当特殊函数计算出已知有误的结果, 或结果无法计算时, 它会调用:

boost::math::policies::raise_evaluation_error<T>(FunctionName, Message, Val, Policy);

其中 T 是传给函数的浮点类型, FunctionName 是函数名, Message 是描述问题的错误消息, Val 是错误值, Policy 是被调用函数当前使用的 policy.

该函数的默认行为是抛出 boost::math::evaluation_error.

注意, 为了在抛出异常时支持信息丰富的错误消息, Message 必须包含 Boost.Format 可识别的格式说明符: 参数 val 会按所用说明符插入错误消息.

例如, 若 Message 含有 "%1%", 则它会被替换为 val 以 T 的全部精度表示的值; 而 "%.3g" 则会包含 val 的 3 位数字的值. 更多细节参见 Boost.Format 文档.

不确定结果错误

当特殊函数对传入的值结果不确定时, 函数返回以下结果:

boost::math::policies::raise_overflow_error<T>(FunctionName, Message, Val, Default, Policy);

其中 T 是传给函数的浮点类型, FunctionName 是函数名, Message 是描述问题的错误消息, Val 是结果不确定的值, Default 是 ignore_error 与 errno_on_erro policy 必须返回的替代默认结果, Policy 是被调用函数当前使用的 policy.

该函数的默认 policy 是 ignore_error: 注意这一错误类型保留给结果在数学上未定义或不确定、但惯例上仍约定结果应为何值的情形: 例如 C99 标准规定 00 的结果为 1, 尽管该结果实际上在数学上是不确定的.

舍入错误

当以没有整数表示、或大到无法用结果类型表示的参数调用舍入函数 round、trunc 或 modf 之一时, 返回的值是以下调用的结果:

boost::math::policies::raise_rounding_error<T>(FunctionName, Message, Val, Policy);

其中 T 是传给函数的浮点类型, FunctionName 是函数名, Message 是描述问题的错误消息, Val 是错误的参数, Policy 是被调用函数当前使用的 policy.

该函数的默认行为是抛出 boost::math::rounding_error.

注意, 为了在抛出异常时支持信息丰富的错误消息, Message 必须包含 Boost.Format 可识别的格式说明符: 参数 val 会按所用说明符插入错误消息.

例如, 若 Message 含有 "%1%", 则它会被替换为 val 以 T 的全部精度表示的值; 而 "%.3g" 则会包含 val 的 3 位数字的值. 更多细节参见 Boost.Format 文档.

类型转换错误

许多特殊函数以高于参数的精度求值其结果, 以保证结果具有完整的机器精度: 例如, 传入 float 参数的函数可能在内部用 double 精度求值结果. 因此, 上面列出的许多错误可能不在求值期间发生, 而是在把结果转换为较窄的结果类型时发生. 函数:

template <class T, class Policy, class U>
T checked_narrowing_cast(U const& val, const char* function);

用于执行这些转换, 并会在 上溢、下溢或 非规格化时调用上面列出的错误处理器.
