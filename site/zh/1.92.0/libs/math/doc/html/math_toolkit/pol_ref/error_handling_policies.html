错误处理策略

错误处理有两个正交的方面:

  • 如何处理错误 (如果有处理的话).
  • 引发的是什么类型的错误.
错误引发时的可用行动

如何处理错误由一个枚举类型封装:

namespace boost { namespace math { namespace policies {

enum error_policy_type
{
   throw_on_error = 0, // throw an exception.
   errno_on_error = 1, // set ::errno & return 0, NaN, infinity or best guess.
   ignore_error = 2, // return 0, NaN, infinity or best guess.
   user_error = 3  // call a user-defined error handler.
};

}}} // namespaces

各个枚举值具有以下含义:

throw_on_error

将根据错误类型抛出以下异常之一:

错误类型

异常

定义域错误

std::domain_error

极点错误

std::domain_error

上溢错误

std::overflow_error

下溢错误

std::underflow_error

非规格化错误

std::underflow_error

求值错误

boost::math::evaluation_error

不确定结果错误

std::domain_error

errno_on_error

将根据错误类型把全局 ::errno ::errno 设置为下列值之一 (通常 EDOM = 33, ERANGE = 34), 然后返回与忽略该错误时相同的值:

错误类型

errno 值

定义域错误

EDOM

极点错误

EDOM

上溢错误

ERANGE

下溢错误

ERANGE

非规格化错误

ERANGE

求值错误

EDOM

不确定结果错误

EDOM

ignore_error

将根据错误类型返回下列值之一 (::errno 不会改变)::

错误类型

返回值

定义域错误

std::numeric_limits<T>::quiet_NaN()

极点错误

std::numeric_limits<T>::quiet_NaN()

上溢错误

std::numeric_limits<T>::infinity()

下溢错误

0

非规格化错误

非规格化值.

求值错误

对结果的最佳猜测 (可能是 NaN): 可能存在显著误差.

不确定结果错误

取决于发生错误的函数
user_error

将调用用户定义的错误处理器: 这些处理器在 boost/math/policies/error_handling.hpp 中前向声明, 但实际定义必须由用户提供:

namespace boost{ namespace math{ namespace policies{

template <class T>
T user_domain_error(const char* function, const char* message, const T& val);

template <class T>
T user_pole_error(const char* function, const char* message, const T& val);

template <class T>
T user_overflow_error(const char* function, const char* message, const T& val);

template <class T>
T user_underflow_error(const char* function, const char* message, const T& val);

template <class T>
T user_denorm_error(const char* function, const char* message, const T& val);

template <class T>
T user_rounding_error(const char* function, const char* message, const T& val);

template <class T, class TargetType>
TargetType user_rounding_error(const char* function, const char* message, const T& val, const TargetType& t);

template <class T>
T user_indeterminate_result_error(const char* function, const char* message, const T& val);

}}} // namespaces

注意, 字符串 function 和 message 可能包含旨在与 Boost.Format 配合使用的 "%1%" 格式说明符. 如果这些字符串要呈现给程序的最终用户, 那么 function 字符串中的 "%1%" 格式说明符应替换为类型 T 的名称, 并且如果 message 字符串中有 %1% 说明符, 则应替换为 val 的值.

关于用户定义错误处理器的更多信息见 tutorial here.

引发的错误种类

本库报告六种错误, 汇总于下表:

错误类型

策略类

说明

定义域错误

boost::math::policies::domain_error<action>

当一个或多个参数超出函数的定义范围时引发.

默认为 boost::math::policies::domain_error<throw_on_error>

当 action 设为 throw_on_error 时, 抛出 std::domain_error

极点错误

boost::math::policies::pole_error<action>

当一个或多个参数会导致在极点处对函数求值时引发.

默认为 boost::math::policies::pole_error<throw_on_error>

当 action 为 throw_on_error 时, 抛出 std::domain_error

上溢错误

boost::math::policies::overflow_error<action>

当函数结果超出所用浮点类型的可表示范围时引发.

默认为 boost::math::policies::overflow_error<throw_on_error>.

当 action 为 throw_on_error 时, 抛出 std::overflow_error.

下溢错误

boost::math::policies::underflow_error<action>

当函数结果太小而无法在所用浮点类型中表示时引发.

默认为 boost::math::policies::underflow_error<ignore_error>

当指定的 action 为 throw_on_error 时, 抛出 std::underflow_error

非规格化错误

boost::math::policies::denorm_error<action>

当函数结果是非规格化值时引发.

默认为 boost::math::policies::denorm_error<ignore_error>

当 action 为 throw_on_error 时, 抛出 std::underflow_error

舍入错误

boost::math::policies::rounding_error<action>

当舍入函数 round、trunc 或 modf 之一被调用且参数没有整数表示, 或太大而无法在结果类型中表示时引发

默认为 boost::math::policies::rounding_error<throw_on_error>

当 action 为 throw_on_error 时, 抛出 boost::math::rounding_error

求值错误

boost::math::policies::evaluation_error<action>

当函数结果良定义且有限, 但我们无法计算它时引发. 通常发生在迭代方法未能收敛时. 当然, 理想情况下永远不应引发此错误: 如果出现了, 尽管作为缺陷报告!

默认为 boost::math::policies::evaluation_error<throw_on_error>

当 action 为 throw_on_error 时, 抛出 boost::math::evaluation_error

不确定结果错误

boost::math::policies::indeterminate_result_error<action>

当函数对传入的值结果未定义时引发.

默认为 boost::math::policies::indeterminate_result_error<ignore_error>

当 action 为 throw_on_error 时, 抛出 std::domain_error

示例

假设我们希望调用 tgamma 时以兼容 C 的方式行事, 设置全局 ::errno 而不是抛出异常, 我们可以在调用处使用以下方式实现:

#include <boost/math/special_functions/gamma.hpp>
using boost::math::tgamma;

//using namespace boost::math::policies; may also be convenient.
using boost::math::policies::policy;
using boost::math::policies::evaluation_error;
using boost::math::policies::domain_error;
using boost::math::policies::overflow_error;
using boost::math::policies::domain_error;
using boost::math::policies::pole_error;
using boost::math::policies::errno_on_error;

// Define a policy:
typedef policy<
  domain_error<errno_on_error>,
  pole_error<errno_on_error>,
  overflow_error<errno_on_error>,
  evaluation_error<errno_on_error>
> my_policy;

double my_value = 0.; // 

// Call the function applying my_policy:
double t1 = tgamma(my_value, my_policy());

// Alternatively (and equivalently) we could use helpful function
// make_policy and define everything at the call site:
double t2 = tgamma(my_value,
  make_policy(
    domain_error<errno_on_error>(),
    pole_error<errno_on_error>(),
    overflow_error<errno_on_error>(),
    evaluation_error<errno_on_error>() )
  );

假设我们希望统计分布返回无穷大而不是抛出异常, 那么可以使用:

#include <boost/math/distributions/normal.hpp>
using boost::math::normal_distribution;

using namespace boost::math::policies;

// Define a specific policy:
typedef policy<
      overflow_error<ignore_error>
      > my_policy;

// Define the distribution, using my_policy:
typedef normal_distribution<double, my_policy> my_norm;

// Construct a my_norm distribution, using default mean and standard deviation,
// and get a 0.05 or 5% quantile:
double q = quantile(my_norm(), 0.05); // = -1.64485
