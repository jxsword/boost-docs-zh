每种形式都提供了默认构造函数, 它将每个分量初始化为其类型的默认值 (即浮点数的零). 该构造函数还可以接受一到八个基类型参数. 还提供了一个用一到四个共享同一基类型的复数构建八元数的构造函数, 以及另一个接受一或两个共享同一基类型的四元数的构造函数. 未特化的模板还带有模板化的拷贝构造函数, 而特化形式具有从另外两个特化形式拷贝的构造函数, 当存在精度损失风险时它们是 explicit 的. 对于未特化形式, 基类型的构造函数不得抛出异常.

析构函数和非模板化的拷贝构造函数 (来自同一类型) 由编译器提供. 转换拷贝构造函数使用"detail"子命名空间中的模板化辅助函数.

其他成员函数

实部与非实部 
T            real()   const;
octonion<T>  unreal() const;

与复数一样, 八元数确实有有意义的"实部"概念, 但与复数不同, 八元数没有有意义的"虚部"概念. 取而代之的是一个"非实部"概念, 它本身是一个八元数, 通常没有更简单的形式 (与复数的情形不同). 这些由前两个函数返回.

单个实分量 
T   R_component_1() const;
T   R_component_2() const;
T   R_component_3() const;
T   R_component_4() const;
T   R_component_5() const;
T   R_component_6() const;
T   R_component_7() const;
T   R_component_8() const;

八元数有八个实分量, 它们由这八个函数返回. 因此 real 和 R_component_1 返回相同的值.

单个复分量 
::std::complex<T> C_component_1() const;
::std::complex<T> C_component_2() const;
::std::complex<T> C_component_3() const;
::std::complex<T> C_component_4() const;

八元数同样有四个复分量. 实际上, 八元数确实是复数上的一个 (左) 向量场, 但要小心, 因为对任意八元数 o = α + βi + γj + δk + εe' + ζi' + ηj' + θk' 我们也有 o = (α + βi) + (γ + δi)j + (ε + ζi)e' + (η - θi)j' (注意最后一个因子中的 负 号). 然而, C_component_n 函数返回的是可用于通过构造函数构建八元数的复数, 而不是 八元数在基 (1, j, e', j') 上的分量.

单个四元数分量 
::boost::math::quaternion<T> H_component_1() const;
::boost::math::quaternion<T> H_component_2() const;

同样, 对任意八元数 o = α + βi + γj + δk + εe' + ζi' + ηj' + θk' 我们也有 o = (α + βi + γj + δk) + (ε + ζi + ηj - θj)e', 尽管不存在基于四元数的类似向量空间的有意义结构. H_component_n 函数返回的是可用于通过构造函数构建八元数的四元数.

八元数成员运算符

赋值运算符 
octonion<T> & operator = (octonion<T> const & a_affecter);
template<typename X>
octonion<T> & operator = (octonion<X> const & a_affecter);
octonion<T> & operator = (T const & a_affecter);
octonion<T> & operator = (::std::complex<T> const & a_affecter);
octonion<T> & operator = (::boost::math::quaternion<T> const & a_affecter);

这些运算符执行预期的赋值, 必要时会修改类型 (例如, 从基类型赋值会将实部设置为该值, 并将所有其他分量设为零). 对于未特化形式, 基类型的赋值运算符不得抛出异常.

其他成员运算符 
octonion<T> & operator += (T const & rhs)
octonion<T> & operator += (::std::complex<T> const & rhs);
octonion<T> & operator += (::boost::math::quaternion<T> const & rhs);
template<typename X>
octonion<T> & operator += (octonion<X> const & rhs);

这些运算符执行数学运算 (*this)+rhs 并将结果存入 *this. 未特化形式具有异常保护, 而特化形式没有, 以保证异常安全. 对于未特化形式, 基类型的赋值运算符不得抛出异常.

octonion<T> & operator -= (T const & rhs)
octonion<T> & operator -= (::std::complex<T> const & rhs);
octonion<T> & operator -= (::boost::math::quaternion<T> const & rhs);
template<typename X>
octonion<T> & operator -= (octonion<X> const & rhs);

这些运算符执行数学运算 (*this)-rhs 并将结果存入 *this. 未特化形式具有异常保护, 而特化形式没有, 以保证异常安全. 对于未特化形式, 基类型的赋值运算符不得抛出异常.

octonion<T> & operator *= (T const & rhs)
octonion<T> & operator *= (::std::complex<T> const & rhs);
octonion<T> & operator *= (::boost::math::quaternion<T> const & rhs);
template<typename X>
octonion<T> & operator *= (octonion<X> const & rhs);

这些运算符按此顺序执行数学运算 (*this)*rhs (顺序很重要, 因为对八元数而言乘法不满足交换律) 并将结果存入 *this. 未特化形式具有异常保护, 而特化形式没有, 以保证异常安全. 对于未特化形式, 基类型的赋值运算符不得抛出异常. 此外, 为清晰起见, 应始终将乘法中的因子按两个一组进行分组, 因为乘法对八元数甚至不满足结合律 (当然有些情况下这无关紧要, 但通常是有影响的).

octonion<T> & operator /= (T const & rhs)
octonion<T> & operator /= (::std::complex<T> const & rhs);
octonion<T> & operator /= (::boost::math::quaternion<T> const & rhs);
template<typename X>
octonion<T> & operator /= (octonion<X> const & rhs);

这些运算符按此顺序执行数学运算 (*this)*inverse_of(rhs) (顺序很重要, 因为对八元数而言乘法不满足交换律) 并将结果存入 *this. 未特化形式具有异常保护, 而特化形式没有, 以保证异常安全. 对于未特化形式, 基类型的赋值运算符不得抛出异常. 至于乘法, 请记住用括号将任意两个因子分组.
