超几何分布 

#include <boost/math/distributions/hypergeometric.hpp>
namespace boost{ namespace math{

template <class RealType = double,
          class Policy   = policies::policy<> >
class hypergeometric_distribution;

template <class RealType, class Policy>
class hypergeometric_distribution
{
public:
   typedef RealType value_type;
   typedef Policy   policy_type;
   // Construct:
   hypergeometric_distribution(uint64_t r, uint64_t n, uint64_t N); // r=defective/failures/success, n=trials/draws, N=total population.
   // Accessors:
   uint64_t total()const;
   uint64_t defective()const;
   uint64_t sample_count()const;
};

typedef hypergeometric_distribution<> hypergeometric;

}} // namespaces

超几何分布描述 "事件" 的个数 k, 其中样本 n 从总体 N 中无放回抽取.

设想我们有 N 个对象的样本, 其中 r 个是 "有缺陷的", N-r 个是 "无缺陷的" (也使用 "成功/失败" 或 "红/蓝" 这类说法). 如果我们抽取 n 个对象且无放回, 那么样本中恰好有 k 个对象有缺陷的概率是多少? 答案由超几何分布的 pdf f(k; r, n, N) 给出, 而 k 个或更少有缺陷的概率由 F(k; r, n, N) 给出, 其中 F(k) 是超几何分布的 CDF.

注释

与本库中几乎所有其他分布不同, 超几何分布是严格离散的: 它不能扩展到参数或随机变量取实数值的情形.

成员函数 
hypergeometric_distribution(uint64_t r, uint64_t n, uint64_t N);

构造一个超几何分布, 总体有 N 个对象, 其中 r 个有缺陷, 从中抽取 n 个.

uint64_t total()const;

返回对象总数 N.

uint64_t defective()const;

返回对象个数 r (即总体 N 中有缺陷的对象个数).

uint64_t sample_count()const;

返回对象个数 n, 它们从总体 N 中抽取.

警告

参数的命名/符号与参数顺序都令人困惑, 没有哪两个实现是一致的! 参见 Wolfram Mathematica Hypergeometric Distribution 与 Wikipedia Hypergeometric Distribution 以及 Python scipy.stats.hypergeom.

非成员访问器

对所有分布通用的一系列常规非成员访问函数都受支持: Cumulative Distribution Function, Probability Density Function, Quantile, Hazard Function, Cumulative Hazard Function, __logcdf, __logpdf, mean, median, mode, variance, standard deviation, skewness, kurtosis, kurtosis_excess, range 和 support.

随机变量的定义域是范围 [max(0, n + r - N), min(n, r)] 内的 64 位无符号整数. 如果随机变量超出此范围, 或不是整数值, 则抛出 domain_error.

注意

分位数函数默认返回向外取整后的整数结果. 也就是说, 下分位数 (概率小于 0.5) 向下取整, 上分位数 (概率大于 0.5) 向上取整. 这种行为确保当请求 X% 分位数时, 中心区域至少具有所请求的覆盖率, 而尾部至多具有所请求的覆盖率.

可以通过 Policies 改变这一行为, 使分位数函数采用不同的舍入方式. 强烈建议在对超几何分布使用分位数函数之前, 先阅读教程 理解离散分布的分位数 . 参考文档 说明了如何更改这些分布的舍入策略.

不过请注意, 分位数函数的实现方法总是返回整数值, 因此尝试使用要求 (或产生) 实值结果的 Policy 将导致编译期错误.

精度

对于较小的 N, 使得 N < boost::math::max_factorial<RealType>::value 时, 基于表的查表结果精度可达几个 epsilon. boost::math::max_factorial<RealType>::value 在 double 或 long double 精度下为 170.

对于较大的 N, 使得 N < boost::math::prime(boost::math::max_prime) 时, 计算只需要基本的算术运算, 精度通常 < 20 个 epsilon. 这可以处理最大到 104729 的 N.

对于 N > boost::math::prime(boost::math::max_prime) 时, 精度会迅速下降, 当 N = 110000 时会损失 5 到 6 位十进制数字.

一般来说, 对于非常大的 N, 用户应预期在计算过程中损失 log10N 位十进制精度, 当 N >= 1015 时结果将变得没有意义.

计算素数之积需要小心处理以防止数值上溢; 我们使用一种新颖的递归方法, 把计算拆分为一系列子乘积, 每当下一次乘法会导致上溢或下溢时就启动一个新的子乘积. 这些子乘积存放在程序栈上的链表中, 并在最后一个子乘积算完之后, 按保证不会发生上溢或不必要下溢的顺序合并.

只要 N 小于素数表中存储的最大素数 (目前为 104729), 就可以使用此方法. 该方法相对较慢 (计算指数所需的时间最多), 但计算结果只需要很少的算术运算 (事实上, 一旦求出指数, 就不存在只用基本算术的更短方法), 因此该方法比其它方法准确得多.

对于更大的 N, 我们可以使用 lgamma 由阶乘计算 PDF, 也可以直接组合 lanczos 近似以避免通过对数计算. 我们使用后一种方法, 因为它通常比用 lgamma 通过对数计算多 1 到 2 位十进制数字的精度. 不过, 在 N > 104729 这一区域, 用户应预期最坏情况下计算过程中会损失大约 log10N 位十进制数字.
