为什么使用高精度库而不是内置浮点类型?

对几乎所有应用, 内置浮点类型 double (以及 long double, 若它比 double 精度更高) 提供的精度已经足够, 通常是一打 (12 位) 十进制数字.

想要使用更高精度的一些原因:

  • 更精确的结果 (多得多的位数) 本身就是需求.
  • 计算值的范围超出类型的范围: 阶乘是教科书式的例子.
  • 使用 double 不够精确 (或可能不够精确).
  • 使用 long double 不够精确 (或可能不够精确).
  • 使用以软件实现的扩展精度类型 (如 double-double, 见 Darwin) 有时精度不可预测地差.
  • 极端参数或 抵消误差造成的精度损失或不准确.
  • 要求所选内置浮点类型能达到尽可能好的精度.
  • 作为参考值, 例如用来确定用内置浮点类型计算得到的值的不准确度 (甚至可能用的是某种快速而粗糙的算法). Boost.Math 中许多函数与分布的精度就是这样用极高精度 (高达 1000 位十进制数字) 的表测得的.

许多函数与分布与精确值的差异只有几个最低有效位 — 即计算噪声. 另一些函数 (通常是那些没有解析解的) 需要近似与迭代: 它们可能损失好几位十进制数字的精度.

对 边界或 角落用例, 可能发生大得多的精度损失, 通常由 抵消误差造成.

(一些最糟糕也最常见的 抵消误差或精度损失例子可以通过使用 补集来避免: 参见 为何使用补集?).

如果你需要一个在浮点类型中能表示得尽可能准确的值, 即最近可表示值且按最近正确舍入、误差小于半个 最低有效位或 ulp, 那么使用更高精度的类型 (例如 cpp_dec_float_50) 生成该值可能有用. 把这个值转换为内置浮点类型 ("float"、double 或 long double) 不会造成进一步的精度损失. 十进制数字字符串也会被编译器精确地"读"入内置浮点类型, 取最近可表示值.

注释

相比之下, 从 std::istream 读取值到内置浮点类型, C++ 标准并不保证得到最近可表示值.

William Kahan 为正确舍入函数这一问题创造了 Table-Maker's Dilemma 一词. 使用高得多的精度 (50 或 100 位十进制数字) 是生成 (几乎总是) 正确舍入值的实用方法.
