概述

头文件 <boost/cstdfloat.hpp> 提供 可选 的标准化浮点 typedef, 具有 指定宽度. 这些类型对编写可移植代码很有用, 因为它们在所有平台上的行为应当完全一致. 这些 typedef 是 <cstdint> 与 stdint.h 中指定宽度整数的浮点对应物.

typedef 基于 N3626 (为新的 C++14 标准头文件 <cstdfloat> 提议) 以及 N1703 (为新的 C 语言标准头文件 <stdfloat.h> 提议).

所有 typedef 都位于 namespace boost 中 (如果最终被标准化, 将位于命名空间 std 中).

typedef 包括 float16_t, float32_t, float64_t, float80_t, float128_t、与之对应的 least 和 fast 类型, 以及对应的最大宽度类型. typedef 基于诸如 float、double 或 long double 之类的底层内建类型, 或提议的 N2016 short float type, 或基于其他编译器特定的非标准类型 (如 __float128). 这些 typedef 的底层类型必须符合 IEEE_floating_point 浮点格式中 binary16、binary32、binary64 和 binary128 的相应规范, 以及 std::numeric_limits<>::is_iec559 == true.

128 位浮点类型 (在科学和数值编程中极受关注) 在 Boost 头文件中不是必需的, 并且可能并非在所有平台/编译器上都提供, 因为 C 标准和 C++ 标准都没有强制要求编译器支持 128 位浮点类型.

如果支持 128 位浮点, 则包含 boost/cstdfloat.hpp 会提供 原生 的 128 位类型, 并包含文件夹 boost/math/cstdfloat 中的其他头文件, 这些头文件为 C 数学函数 提供针对 <cmath>、<limits>、<iostream>、<complex> 以及可用浮点类型的 C++ quad 支持.

更稳妥的做法是包含 boost/multiprecision/float128.hpp, 它提供一个薄封装: 如果可用, 则从 cstdfloat 中选择合适的 128 位原生类型, 否则选择 128 位多精度类型.

Jahnke-Emden-Lambda 函数示例 展示了同时使用 <cmath> 函数和 Boost.Math 函数来求值一个颇有意思的函数——即 Jahnke-Emden-Lambda 函数, 并以 正态分布 作为来自 Boost.Math 的统计分布示例.
