引言

问题所在

C++98 标准未规定 infinity与 NaN 在文本流中的表示方式. 结果, 不同平台使用不同的字符串表示. 当文本文件在不同平台之间移动时, 这可能导致未定义行为. 有些平台甚至无法解析自己输出的内容! 因此输出的"往返" (route-tripping) 或环回到输入是不可能的. 例如, 下面的测试在 MSVC 上失败:

stringstream ss;
double inf = numeric_limits<double>::infinity();
double r;
ss << inf; // Write out.
ss >> r; // Read back in.

cout << "infinity output was " << inf << endl; // 1.#INF
cout << "infinity input was " << r << endl; // 1

assert(inf == y); // Fails!
解决方案

刻面 nonfinite_num_put 与 nonfinite_num_get 以一致且可移植的方式格式化与解析所有浮点数, 包括 infinity 与 NaN.

下面的测试在 MSVC 上成功.

locale old_locale;
locale tmp_locale(old_locale, new nonfinite_num_put<char>);
locale new_locale(tmp_locale, new nonfinite_num_get<char>);
提示

要添加两个刻面 nonfinite_num_put 与 nonfinite_num_get, 你可能必须借助一个临时 locale 一次添加一个.

或者你可以一步创建一个新 locale

std::locale new_locale(std::locale(std::locale(std::locale(), new boost::math::nonfinite_num_put<char>), new boost::math::nonfinite_num_get<char>));

并例如用它为输入与输出 stringstream imbue.

提示

要只改变一个输入或输出流, 你可以简写为 cout.imbue (std::locale(std::locale(), new boost::math::nonfinite_num_put<char>)); 或 cin.imbue (std::locale(std::locale(), new boost::math::nonfinite_num_get<char>)); 

stringstream ss;
ss.imbue(new_locale);
double inf = numeric_limits<double>::infinity();
ss << inf; // Write out.
BOOST_MATH_ASSERT(ss.str() == "inf");
double r;
ss >> r; // Read back in.
BOOST_MATH_ASSERT(inf == r); // Confirms that the double values really are identical.

cout << "infinity output was " << ss.str() << endl;
cout << "infinity input was " << r << endl;
// But the string representation of r displayed will be the native type
// because, when it was constructed, cout had NOT been imbued
// with the new locale containing the nonfinite_numput facet.
// So the cout output will be "1.#INF on MS platforms
// and may be "inf" or other string representation on other platforms.
infinity 与 NaN 输出的 C++0X 标准

C++0X (最终) 草案标准并未明确规定非有限值的表示 (与输入), 而是留作实现定义. 因此若不采取特定措施, 非有限值的输入输出不可移植.

infinity 与 NaN 输出的 C99 标准

C99 标准 确实规定了 infinity 与 NaN 如何由 printf 及类似输出函数格式化, 以及如何由 scanf 及类似输入函数解析.

使用以下字符串表示:

"inf" or "infinity"

"nan" or "nan(...)"

负无穷大

"-inf" or "-infinity"

负 NaN

"-nan" or "-nan(...)"


因此遵循 C99 为 C++ 中非有限值的输入输出提供了一种合理的"标准"方式, 本实现遵循其中大部分格式.

信号 NaN

一种特殊的 NaN 是信号 NaN (signaling NaN). 通常的发信号机制是引发浮点异常. 信号 NaN 由 IEEE 754-2008 定义.

布局为 s111 1111 1axx xxxx xxxx xxxx xxxx xxxx 的浮点值, 其中 s 是符号, x 是载荷, 位 a 决定 NaN 的类型.

若位 a = 1, 则它是安静 NaN.

若位 a 为零且载荷 x 非零, 则它是信号 NaN.

尽管信号 NaN 引发异常的能力 (例如防止使用未初始化的变量) 在理论上引人关注, 但实际上对大多数现有处理器而言, 信号 NaN 似乎没有有用的应用. C++0X 18.3.2.2 仍规定了信号 NaN 的 (实现定义的) 表示, static constexpr bool has_signaling_NaN 提供了检查浮点类型是否有信号 NaN 表示的方法.

但实践中, 大多数平台把信号 NaN 与安静 NaN 同等对待. 例如, 它们以 C99 格式输出为 "nan", 并被 Microsoft 编译器输出为 1.#QNAN.

注释

C99 标准不区分安静 NaN 与信号 NaN 的值. 安静 NaN 几乎在所有算术运算中传播而不引发浮点异常; 信号 NaN 作为算术操作数出现时通常会引发浮点异常.

C99 规范没有定义信号 NaN 的行为. 由 IEC 60559 运算产生的 NaN 总是安静的. 因此本实现遵循 C99, 把信号 NaN 位当作 NaN 载荷字段的一部分. 所以本实现不区分这两类 NaN.

注释

实现可以给零与非数值 (如无穷大与 NaN) 带符号, 也可以让它们不带符号. 凡这类值不带符号处, C99 标准中获取符号的要求将产生未指定的符号, 设置符号的要求将被忽略.

这可能适用于用户定义类型, 但实践中内置浮点类型 float、double 与 long double 的符号行为良好.

数字的类型可以是 float、double 与 long double. 正数可以带可选的 + 号 (由 ios 操纵器 showpos 控制). 函数 printf 及类似的 C++ 函数使用标准格式化标志把内容全部小写或全部大写 (由 std::ios 操纵器 uppercase 与 lowercase 控制).

函数 scanf 及类似的输入函数不区分大小写.

nan(...) 中的点号代表任意字符串. 该字符串的含义取决于实现. 它可用于传达关于 NaN 的额外信息, 即"载荷". 例如, 载荷的特定值可能用来指示缺失值.
