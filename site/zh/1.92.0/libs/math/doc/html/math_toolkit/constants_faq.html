数学常量常见问题 (FAQ)

为什么选择这些常量?

当然, 这样一份清单不可能让每个人都满意.

我们采用的部分标准是:

  • 在 Boost.Math 中使用.
  • 常用.
  • 计算代价高昂.
  • 用户要求.
  • 在科学和数学中使用.
  • 不含整数值 (因为构造整数的代价极低).

(如果觉得方便, 你可以很容易地定义自己的常量, 例如: FPT one =static_cast<FPT>(42);).

常量如何命名?
  • 不是宏, 所以不用大写.
  • 全小写 (遵循 C++ 标准命名).
  • 不用 CamelCase.
  • 用下划线 _ 作为单词间的分隔符.
  • 数字拼写为单词而非十进制数字 (pow 之后除外).
  • 缩写约定:
    • root 表示平方根.
    • cbrt 表示立方根.
    • pow 表示 pow 函数, 使用十进制数字, 如 pow23 表示 n2/3.
    • div 表示除以或运算符 /.
    • minus 表示运算符 -, plus 表示运算符 +.
    • sqr 表示平方.
    • cubed 表示立方 n3.
    • 希腊字母用单词表示, 如 π、ζ 和 Γ.
    • 分数用 half、third、three_quarters、sixth 之类的单词表示. (数字容易混淆).
    • log10 表示 log10
    • ln 表示 loge
常量是如何导出的?

所有常量都使用高达 300 位精度的高精度软件计算, 得到约 100 位十进制数字. (精度可以任意选择, 仅受计算时间限制).

常量的精度如何?

所选的最低精度 (100 位十进制数字) 超过了可合理预见的浮点硬件 (256 位) 的精度, 应能满足大多数高精度计算的需要.

常量是如何测试的?
  1. 使用 Boost.Test 的 BOOST_CHECK_CLOSE_FRACTION 配合 long double 字面量进行比较, 至少 35 位十进制数字, 足以对所有 long double 实现保持准确. 容差通常是 long double epsilon 的两倍.
  2. 与 long double 精度下的计算进行比较. 由于舍入等带来的计算噪声, 尤其在调用三角函数等时, 这往往需要比两倍 epsilon 稍高的容差.
  3. 与独立发表的值进行比较, 例如使用 The On-Line Encyclopedia of Integer Sequences (OEIS), 同样使用至少 35 位十进制数字的字符串.
  4. 与使用 Mathematica 等任意精度工具独立计算的值进行比较, 同样使用至少 35 位十进制数字的字面量字符串.
警告

我们尚未能够验证是否所有常量在完整的任意精度 (目前为 100 位十进制数字) 下都是准确的. 但某些关键值 (如 e 和 pi) 似乎是准确的, 且内部一致性表明其他常量也达到了这一精度.

为什么可移植性很重要?

使用数学常量编写的代码即使在不同浮点类型、不同精度之间也很容易移植.

期望计算结果完全相同是一个错误的认识, 但你可以做到对所使用的浮点类型获得尽可能好的精度.

这对用户没有额外开销, 却能减少由浮点计算固有的有限精度所引起的恼人、常常令人困惑且极难追踪的影响.

这种限制的一个无害症状是最低有效位出现伪值; 最坏的情况下, 稍不准确的常量有时会使迭代算法剧烈发散, 因为内部比较直接失败.

常量的内部格式是什么, 为什么?

正常用法参见上文的教程; 本 FAQ 解释常量所用的内部细节.

常量以 100 位十进制数字的值存储. 但一些编译器不接受这么长的十进制数字字符串. 因此常量被拆分为两部分, 第一部分至少包含 128 位 long double 精度 (35 位十进制数字), 且为保持一致应采用带符号指数的科学计数法.

第二部分是表示为字符串字面量的常量值, 精确到至少 100 位十进制数字 (实践中意味着至少 102 位). 同样为保持一致, 使用带符号指数的科学计数法.

对于精度高于 long double 的类型, 若 T 可从 const char* 构造, 则直接从字符串构造; 否则我们回退到 lexical_cast 以转换到类型 T. (使用字符串是必要的, 因为不能使用数值常量, 因为即使是 long double 也可能没有足够的位数).

因此, 例如像 pi 这样的常量在内部定义为

BOOST_DEFINE_MATH_CONSTANT(pi, 3.141592653589793238462643383279502884e+00, "3.14159265358979323846264338327950288419716939937510582097494459230781640628620899862803482534211706798214808651e+00");

此例中有效数字为 109 位十进制数字, 确保 100 位十进制数字精确, 指数为零.

有关计算新常量的方法, 参见 defining new constants.

这样的宏定义可以在方便时粘贴到用户代码中, 或者 (若要加入 Boost.Math 库) 粘贴到 boost/math/constants.hpp 中.

我可以使用哪些浮点类型?

除了内建浮点类型 float、double、long double 之外, 还有若干任意精度浮点类可用, 但大多数未授权用于商业用途.

Christopher Kormanyos 和 John Maddock 的 Boost.Multiprecision

这是一个维护良好、功能完备的库, 提供众多高精度类型, 以及对 MPFR 等其他流行库的封装.

NTL 类 quad_float

Victor Shoup 的 NTL 具有定点和任意高精度的定点与浮点类型. 但这些类型均未授权用于商业用途.

#include <NTL/quad_float.h> // quad precision 106-bit, about 32 decimal digits.
using NTL::to_quad_float; // Less precise than arbitrary precision NTL::RR.

NTL 类 quad_float 提供一种四精度形式, 106 位有效数字 (但没有扩展的指数范围). 使用 IEC559/IEEE 754 兼容的处理器, 例如 Intel X86 系列 (64 位 double、53 位有效数字), 若使用两个 64 位 double 的有效数字, 且 std::numeric_limits<double>::digits10 为 16, 则可获得大约两倍的精度, 因此 std::numeric_limits<quad_float>::digits10() 应为 32. (默认的 std::numeric_limits<RR>::digits10() 应约为 40). (这似乎与实验一致). 我们通过追加 2 或 3 位额外的十进制数字来输出常量 (包含一些噪声位, 即对 std::numeric_limits<RR>::max_digits10() 的近似), 因此使用 quad_float::SetOutputPrecision(32 + 3);

Apple Mac/Darwin 对其内建 类型使用了类似的doubledoublelong double 106 位表示.

注释

所有 doubledouble 浮点类型的精度都相当古怪, 给出的值只是近似值.

新项目应使用 Boost.Multiprecision.

NTL 类 RR

使用 NTL 类 RR 的任意精度浮点, 默认 150 位 (约 50 位十进制数字); 此处使用 300 位以输出 100 位十进制数字, 对许多实际的非“数论”类 C++ 应用已经足够.

NTL A Library for doing Number Theory 未授权用于商业用途

Boost.Math 使用了这个类, 在使用 big_number 项目计算新数学常量时它也是一种选择.

新项目应使用 Boost.Multiprecision.

GMP 与 MPFR

GMP 和 MPFR 也曾被用于计算常量, 但它们以 Lesser GPL license 许可, 未授权用于商业用途

之前为 Boost 提议的一批常量怎么样了?

一次评审的结论是: 这些常量的呈现方式不能满足许多人的需要. 当时提出的所有方法都无法满足许多用户的基本需求, 即能够简单地写 pi 而不是 pi(). 许多科学和工程方程读起来困难, 因为函数调用括号容易与其他经常需要的众多括号混淆. 当时提出的避免括号的所有方法都未能满足全部需要, 常常以复杂或对各种现实场景缺乏适用性为由被否决.

因此, 曾单独提出但在首次评审中被否决的简单命名空间方法被加了进来, 让用户可以方便地访问 float、double 和 long double 值, 同时结合模板结构体和函数, 使其能与其他非内建浮点类型一同使用.

为什么常量 (在内部) 用结构体而不是简单函数?

之前版本的 Boost.Math 提供的是函数机制.

新机制允许偏特化. 参见上文的“自定义特化常量”. 它还应能与其他包 (如 ttmath Bignum C++ library.) 配合使用.

物理常量在哪里?

不在此处, 因为物理常量:

  • 是对测量值的记录, 并非真正的常量.
  • 并非真正恒定, 且会随着计量学的进步而不断变化.
  • 具有固有的不确定度.
  • 数学常量以不同精度存储和表示, 但绝不应不准确.

一些物理常量或许可在 Boost.Units 中找到.
