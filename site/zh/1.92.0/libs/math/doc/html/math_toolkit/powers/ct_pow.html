运行期底数的编译期幂

pow 函数有效地计算运行期底数的编译期整数次幂.

概要

#include <boost/math/special_functions/pow.hpp> 

namespace boost { namespace math {

template <int N, typename T>
BOOST_MATH_GPU_ENABLED constexpr calculated-result-type pow(T base);

template <int N, typename T, class Policy>
BOOST_MATH_GPU_ENABLED constexpr calculated-result-type pow(T base, const Policy& policy);

}}
设计理由与用法

以编译期已知的指数计算数的幂是程序员的常见需求. 在这种情况下, 通常的做法是通过对如下表达式硬编码来避免 pow、powf 和 powl 这些 C 函数的开销:

// Hand-written 8th power of a 'base' variable
double result = base*base*base*base*base*base*base*base;

然而, 这类表达式并不真正可读 (要知道指数的值需要数 base 出现的次数), 容易出错 (很容易漏写一次), 语法上臃肿, 并且在性能上不是最优的.

Boost.Math 的 pow 函数有助于编写这类表达式, 并解决上面列出的所有问题:

// 8th power of a 'base' variable using math::pow
double result = pow<8>(base);

表达式现在更短、更易读、更安全, 甚至更快. 实际上, pow 会这样计算表达式: 对 N 次幂只做 log2(N) 次乘积. 例如在上面的示例中, 所得表达式将与我们手写如下内容相同, 且每个相同的子表达式只计算一次:

// Internal effect of pow<8>(base)
double result = ((base*base)*(base*base))*((base*base)*(base*base));

实际只计算了 3 个不同的乘积.

返回类型

这些函数的返回类型按 结果类型计算规则 确定. 例如:

  • 如果 T 是 float, 则返回类型是 float.
  • 如果 T 是 long double, 则返回类型是 long double.
  • 否则, 返回类型是 double.
constexpr

从 C++14 起, 该函数可在 constexpr 上下文中使用.

策略

最后一个 Policy 参数是可选的,可用于控制函数的行为:如何处理错误、使用什么精度级别等. 详情请参阅 policy 文档.

错误处理

使用 pow 时可能发生两类错误:

  • 在底数为零且指数为负的情况下, 会发生 overflow_error, 因为该运算相当于除以 0 (等于 1/0).
  • 在底数为零且指数为零的情况下, 会发生 indeterminate_result_error, 因为该运算的结果是不确定的. 这些错误遵循 Boost.Math 的通用错误处理策略.

默认的上溢错误策略是 throw_on_error. 因此像 pow<-2>(0) 这样的调用会抛出 std::overflow_error 异常. 如上面给出的链接所示, 也可以使用其他错误处理策略:

  • errno_on_error: 将 ::errno 设置为 ERANGE 并返回 std::numeric_limits<T>::infinity().
  • ignore_error: 返回 std::numeric_limits<T>::infinity().
  • user_error: 返回 boost::math::policies::user_overflow_error 的结果: 该函数必须由用户定义.

默认的不确定结果错误策略是 ignore_error, 对该函数它返回 1, 因为这是 0 的幂最常选取的结果. 这里同样可以使用其他错误处理策略:

  • throw_on_error: 抛出 std::domain_error
  • errno_on_error: 将 ::errno 设置为 EDOM 并返回 1.
  • user_error: 返回 boost::math::policies::user_indeterminate_result_error 的结果: 该函数必须由用户定义.

下面是一个错误处理定制的示例, 我们希望指定出错时必须返回的结果. 为此我们将使用 user_error 策略, 把一个以 user_error 模板化的 overflow_error 策略实例作为第二个参数传入:

// First we open the boost::math::policies namespace and define the `user_overflow_error`
// by making it return the value we want in case of error (-1 here)

namespace boost { namespace math { namespace policies {
template <class T>
T user_overflow_error(const char*, const char*, const T&)
{ return -1; }
}}}


// Then we invoke pow and indicate that we want to use the user_error policy
using boost::math::policies;
double result = pow<-5>(base, policy<overflow_error<user_error> >());

// We can now test the returned value and treat the special case if needed:
if (result == -1)
{
    // there was an error, do something...
}

另一种方法是使用 BOOST_MATH_OVERFLOW_ERROR_POLICY 宏重新定义默认的 overflow_error 策略. 一旦 user_overflow_error 函数如上定义, 我们就可以像这样达到相同的效果:

// Redefine the default error_overflow policy
#define BOOST_MATH_OVERFLOW_ERROR_POLICY user_error
#include <boost/math/special_functions/pow.hpp>

// From this point, passing a policy in argument is no longer needed, a call like this one
// will return -1 in case of error:

double result = pow<-5>(base);
