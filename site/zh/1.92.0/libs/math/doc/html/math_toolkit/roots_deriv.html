带导数求根: Newton-Raphson、Halley 与 Schroeder

概要 
#include <boost/math/tools/roots.hpp>

namespace boost { namespace math {
namespace tools { // Note namespace boost::math::tools.
// Newton-Raphson
template <class F, class T>
BOOST_MATH_GPU_ENABLED T newton_raphson_iterate(F f, T guess, T min, T max, int digits);

template <class F, class T>
BOOST_MATH_GPU_ENABLED T newton_raphson_iterate(F f, T guess, T min, T max, int digits, std::uintmax_t& max_iter);

// Halley
template <class F, class T>
T halley_iterate(F f, T guess, T min, T max, int digits);

template <class F, class T>
T halley_iterate(F f, T guess, T min, T max, int digits, std::uintmax_t& max_iter);

// Schroeder
template <class F, class T>
T schroder_iterate(F f, T guess, T min, T max, int digits);

template <class F, class T>
T schroder_iterate(F f, T guess, T min, T max, int digits, std::uintmax_t& max_iter);

template <class F, class ComplexType>
Complex complex_newton(F f, Complex guess, int max_iterations = std::numeric_limits<typename ComplexType::value_type>::digits);

template<class T>
auto quadratic_roots(T const & a, T const & b, T const & c);

}}} // namespaces boost::math::tools.
说明

这些函数全都执行 使用导数 的迭代求根:

  • newton_raphson_iterate 执行二阶 Newton-Raphson iteration.
  • halley_iterate 和 schroder_iterate 执行三阶 Halley 和 Schröder 迭代.
  • complex_newton 对复解析函数执行 Newton 方法.
  • solve_quadratic 使用各种技巧求解二次方程, 以防止判别式计算中发生灾难性消去.

实值求根函数的参数

F f

类型 F 必须是可调用的函数对象 (或 C++ lambda), 接受一个参数并返回 std::pair, std::tuple, boost::tuple 或 boost::fusion::tuple:

对二阶迭代方法 (Newton Raphson), tuple 应有 两个 元素, 包含函数的求值及其一阶导数.

对三阶方法 (Halley 和 Schroeder), tuple 应有 三个 元素, 包含函数的求值及其一阶和二阶导数.

T guess

初始起始值. 好的猜测对快速收敛至关重要!

T min

结果可能的最小值, 用作初始下括号.

T max

结果可能的最大值, 用作初始上括号.

int digits

所需的二进制位数精度.

uintmax_t& max_iter

可选的要执行的最大迭代次数. 退出时, 该值会被更新为实际执行的迭代次数.

使用这些函数时应注意:

  • 默认的 max_iter = (std::numeric_limits<std::uintmax_t>::max)() 实际上意味着'永远迭代'.
  • 它们可能对初始猜测值非常敏感: 通常, 如果初始猜测值的前两三位十进制数字是正确的, 它们会收敛得非常快. 然而, 如果初始猜测值距离正确值很远且导数接近于零, 收敛速度可能不会比 bisect 更好, 在某些罕见情况下甚至会比 bisect 更差.
  • 这些函数包含处理一阶导数为零 (在适当时还有二阶导数) 的特殊情形, 并在这种情况下回退到 bisect. 不过, 如果把函子 F 定义为返回一个 具有正确符号 的任意小值而非零, 将会有所帮助.
  • 这些函数将抛出 evaluation_error, 如果参数 min 和 max 的顺序颠倒, 或者迭代收敛到局部极小值.
  • 如果当前最佳猜测值处的导数为无穷大 (或非常接近无穷大), 这些函数可能过早终止. 很大的一阶导数会导致很小的下一步步长, 从而触发终止条件. 在这种情况下, 基于导数的迭代可能并不合适.
  • 如果函数'表现真的良好' (单调且只有一个根), 区间边界 min 和 max 不妨设置为最宽的界限, 例如零和 numeric_limits<T>::max().
  • 但如果函数更复杂, 可能有不止一个根或极点, 那么边界的选取就是防止跳出去寻找'错误'根的保护措施.
  • 如果计算出的下一步会使下一个值越出边界, 这些函数会回退到 bisect. 边界在每一步之后都会更新, 以确保这最终走向收敛. 不过, 由渐近紧致的边界支撑的良好初始猜测会极大提升性能, 而不是依赖 bisection.
  • digits 的值对这些函数能否良好运作至关重要: 如果设置得过高, 最好的情况是得到一次多余的 (不必要的) 迭代, 最坏的情况是最后几步只能靠 bisection 进行. 请记住, 返回值的精度永远不会超过 f(x) 可被求值的精度; 而且如果 f(x) 在趋于零时遭受抵消误差, 那么计算出的步长实际上将是随机的. digits 的值应设置得使迭代在此之前终止: 请记住, 对于二阶和三阶方法, 结果中正确数字的个数在每次迭代中都在大幅增加, 因此 digits 应通过实验设置, 使得最后一次迭代恰好把下一个值带入 f(x) 变得不准确的区域. digits 的一个良好起点是: Newton 迭代取 0.6*D, Halley 或 Shröder 迭代取 0.4*D, 其中 D 是 std::numeric_limits<T>::digits.
  • 如果需要一些诊断输出来了解发生了什么, 可以先 #define BOOST_MATH_INSTRUMENT 再 #include <boost/math/tools/roots.hpp>, 并通过 cout.precision(std::numeric_limits<double>::digits10) 确保显示所有有效数字, 或通过 cout.precision(std::numeric_limits<double>::max_digits10) 显示可能的有效数字: 但请注意, 这可能产生大量输出!
  • 最后: 通过手工编写所用的启发式方法使其针对特定函数量身定制, 你很可能可以做得比这些函数更好. 你还可能以比计算导数本身更高效的方式计算这些方法所用的导数之比. 一如既往, 代数化简可能带来巨大收益.

该方法保证至少二次收敛 (与 Newton 方法相同), 并且已知在存在多重根时工作良好: 这是 Newton 方法和 Halley 方法都做不到的.

复数 Newton 方法的工作方式与其余方法略有不同: 由于无法在复平面上界定根, 因此不接受 min 和 max 参数. 未能求得根的情况通过返回 nan 值来传达. 请记住, 如果函数有很多根, 那么复数 Newton 方法会收敛到哪个根基本上无法先验预测; 更多信息请参见 Newton 分形.

二次方程

要求解二次方程 ax2 + bx + c = 0, 可以使用

auto [x0, x1] = boost::math::tools::quadratic_roots(a, b, c);

如果根为实数, 它们会被排列成 x0 ≤ x1. 如果根为复数且输入为实数, 则 x0 和 x1 都是 std::numeric_limits<Real>::quiet_NaN(). 在这种情况下, 必须把 a、b 和 c 转换为复数类型才能提取复根. 如果 a、b 和 c 是整数类型, 则根的类型为 double. 如果你的架构支持融合乘加指令, 该例程会快得多; 如果 fma 不可用, 函数会退而使用缓慢的模拟. 最后, 针对你的特定架构进行编译也能提升速度. 例如, 如果不带任何架构标志编译, 那么 std::fma 调用会编译为 call _fma, 它根据架构的能力动态选择是模拟还是执行 vfmadd132sd 指令. 相反, 如果用 (比如) -march=native 编译, 则不会做动态选择: 只要可用就总是执行 vfmadd132sd 指令, 不可用则使用模拟.
