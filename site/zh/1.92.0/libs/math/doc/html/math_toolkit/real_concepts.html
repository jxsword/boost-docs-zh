实数类型的概念要求

本库中的函数和统计分布可以与满足下述概念要求的任何类型 RealType 一起使用. 所有内置浮点类型 (如 double) 都满足这些要求. (内置类型也称为 fundamental (built-in) types).

满足概念要求的用户定义类型也可以使用. 例如, 通过 a thin wrapper class, 可以使用 NTL (RR) 提供的类型之一. 但既然 Boost.Multiprecision 库已可用, 它已成为首选的实数类型, 通常是 cpp_dec_float 或 cpp_bin_float.

也仍然欢迎提交与其他扩展精度类型的绑定.

这些要求背后的指导原则是: RealType 的行为就像内置浮点类型一样.

注意:

  1. 函数 log_max_value 和 log_min_value 可以从其他函数合成, 因此不需要显式特化.
  2. 函数 epsilon 可以从其他函数合成, 因此只要 RealType 的精度不在运行期变化, 就不需要显式特化 (精度在运行期变化的示例参见头文件 boost/math/bindings/rr.hpp).
  3. 函数 digits、max_value 和 min_value 都会从 std::numeric_limits 自动合成. 但是, 如果 numeric_limits 未针对类型 RealType 特化, 那么当代码尝试使用这些函数时会出现编译器错误, 除非 你显式特化它们. 例如, 如果 RealType 的精度在运行期变化, 那么 numeric_limits 支持可能不合适, 示例参见 boost/math/bindings/rr.hpp.
警告

如果 std::numeric_limits<> 未特化 RealType 类型, 那么包括以下程序在内的其他 Boost 程序将使用默认的 6 位十进制数字 float 精度:

Boost.Test: 给出如下有误导性的错误消息

"difference between {9.79796} and {9.79796} exceeds 5.42101e-19%".

Boost.LexicalCast 和 Boost.Serialization 在把数字转换为字符串时, 会导致输出上可能严重的精度损失.

虽然 RealType 应该要求特化 std::numeric_limits 看似显而易见, 但这对 NTL::RR 和类似的 位数是运行期参数 的类来说并不合理 (而 numeric_limits 的一切都必须在编译期固定).

注意, 上表只列出了已知被 (或可能在不久的将来被) 本库使用的标准库函数. 以下函数: acos、atan2、fmod、cosh、sinh、tanh、log10、lround、llround、ltrunc、lltrunc 和 modf 目前未被使用, 但如果将来添加更多特殊函数, 则可能会使用.

注意, round、trunc 和 modf 函数不属于当前 C++ 标准: 它们是加入 C99 的增补的一部分, 很可能会进入下一个 C++ 标准. 作为后备提供了这些函数的 Boost 版本, 并且这些函数总是以无限定名称调用, 以便可以进行参数依赖查找.

此外, 为了获得高效且准确的结果, 强烈建议有 Lanczos approximation. 你或许可以从 boost/math/special_functions/lanczos.hpp 或 boost/math/bindings/detail/big_lanczos.hpp 改编现有的近似: 在前者的情况下, 你需要把 static_cast 改为 lexical_cast, 并把常量改为 字符串 (以确保系数不会被截断为 long double), 然后针对类型 T 特化 lanczos_traits. 否则, 你可能不得不修改 libs/math/tools/lanczos_generator.cpp 来为你的 RealType 找到合适的近似. 即使你不这样做, 代码也仍会编译, 但任何使用 gamma/beta/erf 函数族的函数的精度和效率都会有所折损.
