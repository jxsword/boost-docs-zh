设计理由

  • 这些标志实现为刻面的 const 数据成员. 刻面是引用计数的, 且 locale 可以共享刻面. 因此更改刻面的标志会产生难以预料的影响. 另一种设计是用 std::ios_base::xalloc 与 std::ios_base::iword 实现这些标志, 这样就可以安全地修改标志, 并可以定义做这件事的操纵器. 然而, 要使之适用于动态链接库, 必须向库中添加 .cpp 文件. 经权衡, 拥有仅头文件库比拥有可变标志与操纵器更可取.
  • 刻面 nonfinite_num_put 在设置了 trap_infinity 或 trap_nan 标志且试图格式化 infinity 或 NaN 时会抛出异常. 若刻面能设置流的 fail bit 会更好. 然而, 派生自 std::num_put 的刻面无法访问流状态.
