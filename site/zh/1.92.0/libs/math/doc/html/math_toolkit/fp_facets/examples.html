示例

std::stringstreams 简单示例 
locale old_locale;
locale tmp_locale(old_locale, new nonfinite_num_put<char>);
locale new_locale(tmp_locale, new nonfinite_num_get<char>);

stringstream ss;
ss.imbue(new_locale);
double inf = numeric_limits<double>::infinity();
ss << inf; // Write out.
BOOST_MATH_ASSERT(ss.str() == "inf");
double r;
ss >> r; // Read back in.
BOOST_MATH_ASSERT(inf == r); // Confirms that the double values really are identical.

cout << "infinity output was " << ss.str() << endl;
cout << "infinity input was " << r << endl;
// But the string representation of r displayed will be the native type
// because, when it was constructed, cout had NOT been imbued
// with the new locale containing the nonfinite_numput facet.
// So the cout output will be "1.#INF on MS platforms
// and may be "inf" or other string representation on other platforms.
与 lexical_cast 一起使用
注释

自 Boost 1.48 起, lexical_cast 不再在内部使用 stringstream, 现在在大多数平台上能够原生处理无穷大与 NaN.

如果不使用包含 nonfinite 刻面的新 locale, 在发现非有限值时, 以前使用 stringstream 的 lexical_cast 版本不可移植 (且经常失败).

locale old_locale;
locale tmp_locale(old_locale, new nonfinite_num_put<char>);
locale new_locale(tmp_locale, new nonfinite_num_get<char>);

尽管其他示例为单个流 imbue 新 locale, 但对于 lexical_cast 内部构造的流, 必须赋值给全局 locale.

locale::global(new_locale);

lexical_cast 之后即可按预期工作, 即使有 infinity 与 NaN 也是如此.

double x = boost::lexical_cast<double>("inf");
assert(x == std::numeric:limits<double>::infinity());

string s = boost::lexical_cast<string>(numeric_limits<double>::infinity());
assert(s == "inf");
警告

如果你在自己的函数内部使用 stringstream, 可能仍需要使用全局 locale 才能正确处理非有限值. 或者需要为你的 stringstream imbue 合适的 get 与 put 刻面.

警告

你应当知道, C++ 规范并未明确要求十进制数字字符串的输入经舍入转换为最近的可表示浮点二进制值. (相比之下, 编译器读取的十进制数字, 例如像 double d = 1.234567890123456789 这样的赋值, 保证把最近的可表示值赋给 double d). 这意味着, 无论你提供多少位十进制数字, 结果二进制值都存在最低有效位 1 位的潜在不确定性.

conversion and rounding 提供关于 最近可表示与 舍入的更多信息, Exploring Binary 则详细介绍输入与往返转换的困难.

实际上, 大多数 iostream 库对所有输入值都能达到理想的 最近可表示浮点二进制值. 然而有一个流行的 STL 库对 64 位 double 并未完全做到. 离奇的完整细节参见 Decimal digit string input to double may be 1 bit wrong.

如果你期望对 lexical_cast 或 serialization 做“往返” (round-trip), 例如存档与加载, 并且想绝对确信总能得到完全相同的 double 值二进制模式, 你应当使用下面建议的、被认为在所有平台上都有效的“变通方法”.

你应当以所有可能有意义的十进制数字输出, 即把流精度设为 std::numeric_limits<double>::max_digits10 (若不是 double, 则为相应浮点类型的对应值), 并且关键是, 要求 scientific 格式, 而不是 fixed 或自动 (默认), 例如:

double output_value = any value;
std::stringstream s;
s << setprecison(std::numeric_limits<double>::max_digits10) << scientific << output_value;
s >> input_value;
与序列化档案一起使用

保存档案与加载档案时使用相同的 locale 至关重要, 否则加载档案可能失败. 默认情况下, 档案以经典 C locale 并附加 boost::archive::codecvt_null 刻面进行保存与加载. 通常你不必为此担心.

档案类的构造函数会作为副作用为流 imbue 这样的 locale. 然而, 如果你想把刻面 nonfinite_num_put 与 nonfinite_num_get 用于档案, 就必须手动管理 locale. 方法是在调用档案构造函数时传入标志 boost::archive::no_codecvt, 从而确保档案构造函数不会为流 imbue 新 locale.

下面的代码展示了如何把 nonfinite_num_put 与 text_oarchive 一起使用.

locale default_locale(locale::classic(), new boost::archive::codecvt_null<char>);
locale my_locale(default_locale, new nonfinite_num_put<char>);

ofstream ofs("test.txt");
ofs.imbue(my_locale);

boost::archive::text_oarchive oa(ofs, no_codecvt);

double x = numeric_limits<double>::infinity();
oa & x;

同样的方法也适用于 nonfinite_num_get 与 text_iarchive.

如果在序列化档案中把 nonfinite_num_put 与 trap_infinity 和/或 trap_nan 标志一起使用, 那么必须设置流的异常掩码. 序列化档案不检查流状态.
