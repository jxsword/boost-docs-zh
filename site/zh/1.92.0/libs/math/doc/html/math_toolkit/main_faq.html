Boost.Math 常见问题 (FAQ)

  1. 我是 FORTRAN/NAG/SPSS/SAS/Cephes/MathCad/R 用户, 看不到 dnorm(mean, sd) 这类函数在 Boost.Math 的什么位置?

    几乎所有函数都有提供, 还有更多, 如 mean (均值) 、skewness (偏度) 、quantiles (分位数) 、complements (补函数) 等……但 Boost.Math 充分利用了 C++, 所以外观有些不同. 不必惊慌! 参见关于构造的章节和大量示例. 简而言之, 分布用参数 (如位置和尺度) 来构造 (即形如 P(X=k|n, p) 表示中 | 之后的量, 或常见 pdf 表示 f(x; μσ2) 中 ; 之后的量) . pdf、cdf 这类函数以该分布的名称以及通常记作 x 或 k 的随机变量来调用. 例如, normal my_norm(0, 1); pdf(my_norm, 2.0);

  2. 我是 New SAS Functions for Computing Probabilities 的用户.

    你会发现接口更熟悉; 至于按名称 (也许用字符串) 选择分布, 请参见 Extras/Future Directions 一节, 以及 /boost/libs/math/dot_net_example/boost_math.cpp——它是用于创建 C# (C sharp) 实用程序的示例 (你可能也会觉得有用) : 参见 Statistical Distribution Explorer.

  3. 我讨厌读手册, 更喜欢通过示例学习.

    别担心——你并不孤单! 函数和分布都有许多示例. 有些在正文中直接引用, 其他可在 \boost_latest_release\libs\math\example 找到. 例如, 如果你是 Visual Studio 用户, 应该可以从其中每一个创建项目, 只要确保 Boost 库在包含目录列表中 (通常没有任何必须构建的库) .

  4. 如何确保 Boost 库在 Visual Studio 的包含目录列表中?

    可以添加包含路径, 例如你的 Boost 所在位置 /boost-latest_release, 比如 X:/boost_1_70_0/ (如果你用单独的分区 X 存放 Boost 发行版) . 或者可以使用设置为 Boost 所在位置的环境变量 BOOST_ROOT 并包含它. 2010 之前的 Visual Studio 通过 Tools、Options、VC++ Directories 控制目录; Visual Studio 2010 改为提供属性表来辅助. 你可能会发现, 在 $(IncludePath) 的现有包含项中新建一个并加上 \boost-latest_release; 会很方便.

  5. 我是 FORTRAN/NAG/SPSS/SAS/Cephes/MathCad/R 用户, 看不到 mean (均值) 、median (中位数) 、mode (众数) 、variance (方差) 、skewness (偏度) 等分布属性在 Boost.Math 的什么位置?

    它们全部可用 (前提是对你构造分布所用的参数有定义) , 通过 Cumulative Distribution Function、Probability Density Function、Quantile、Hazard Function、Cumulative Hazard Function、__logcdf、__logpdf、mean、median、mode、variance、standard deviation、skewness、kurtosis、kurtosis_excess、range 和 support 获得.

  6. 我是 C 程序员. 可以在 C 中使用 Boost.Math 吗?

    可以, 包括所有特殊函数以及 isnan 等 TR1 函数. 通过声明为 "extern C", 它们以 C 函数的形式出现.

  7. 我是 C# (Basic? F#? FORTRAN? 其他 CLI? ) 程序员. 可以在 C# (或其他语言) 中使用 Boost.Math 吗?

    可以, 包括所有特殊函数以及 isnan 等 TR1 函数. 但你 必须把 Boost.Math 构建为动态库 (.dll) , 并使用 /CLI 选项编译. 参见 boost/math/dot_net_example 文件夹, 其中包含一个构建带 GUI 的简单统计分布应用的示例. 参见 Statistical Distribution Explorer

  8. 这些 “policy” (策略) 是干什么用的?

    policy 是一种强大 (尽管必然复杂) 的细粒度机制, 让你能按精确需求定制 Boost.Math 库的行为. 参见 Policies. 不过, 很可能默认行为已能满足你的需要, 无需了解更多.

  9. 我是 C 用户, 希望像全局 C 风格那样::errno 为上溢/错误等设定好?

    你可以达到目的——参见 error handling policies、user error handling 以及许多示例.

  10. 我是 C 用户, 希望上溢时静默返回最大值?

    你 (以及 C++ 用户) 可以在上溢时返回任何想要的值——参见 overflow_error、error handling policies 以及若干示例.

  11. 我不想要任何上溢等错误消息?

    你可以精确控制所有异常情形下发生的一切, 包括返回的值. 参见 domain_error、overflow_error error handling policies user error handling 等以及示例.

  12. 我的环境不允许和/或我不想要异常. 还能使用 Boost.Math 吗?

    可以, 但必须定制错误处理: 参见 user error handling 和 changing policies defaults.

  13. 文档长达数百页! 可以离线或打印阅读吗?

    可以——可以从 Sourceforge 下载当前 Boost 发行版大部分文档的 pdf 压缩包 (包括 Boost.Math) , 例如 https://sourceforge.net/projects/boost/files/boost-docs/1.45.0/boost_pdf_1_45_0.tar.gz/download. 你可以打印所需的任何页面 (甚至打印全部——但要注意有好几百页! ) . html 和 pdf 版本都带有大量超链接. 整个 Boost.Math pdf 可用 Adobe Reader 的 Edit、Find……搜索. 这往往能找到你要的内容, 算是完整索引的部分替代.

  14. 我想要一个用于嵌入式应用的紧凑版本. 可以用 float 精度吗?

    可以——把 RealType 模板参数选为 float: 例如 normal_distribution<float> your_normal(mean, sd); (但内部仍可能使用 double, 因此节省的空间可能不如预期) . 也可以更改提升 (promotion) policy, 但精度可能大幅降低.

  15. 与其他程序相比, 我得到的结果似乎有些不同. 为什么?

    我们希望 Boost.Math 更精确: 我们的优先级是精度 (而非速度) . 参见关于精度的一节. 但对于需要迭代的求值, 有一些参数可以改变所需精度 (参见 Policies) . 你可以用运行时间为代价换取略多 (或略少) 的精度.

  16. 与其他数学函数和统计库相比, 我的程序会运行得更慢吗?

    可能会, 但并非总是如此, 差距也不大: 我们的优先级是精度. 对大多数函数而言, 确保使用开启了全部优化的最新编译器版本是提速的关键. 对需要迭代的求值, 你可以牺牲精度换取一点速度. 详细建议与结果参见 performance.

  17. 如何可移植地处理无穷大和 NaN?

    浮点无穷大与 NaN 的 Facet 参见 nonfinite fp_facets.

  18. 预构建的库在哪里?

    好消息——你很可能一个都不需要! 只需 #include <boost/math/distribution_you_want>. 但在极少数确实需要的情况下, 参见 building libraries.

  19. 我看不到我想要的函数或分布.

    可以发邮件问作者——但不作保证!

  20. 我的数值/计算需要更多十进制数字.

    可以把 Boost.Math 与 Boost.Multiprecision 一起使用: 通常 cpp_dec_float 是很有用的用户自定义类型, 可提供固定的十进制位数, 一般为 50 或 100 位.

  21. 为什么不能写一些非常简单的东西, 比如 cpp_int one(1); cpp_dec_float_50 two(2); one * two;

    因为 cpp_int 可能大于 cpp_dec_float can hold, 所以必须进行 显式转换. 参见 mixed multiprecision arithmetic 和 conversion.

  22. 如何在 Boost.Multiprecision 的 cpp_bin_50 和 cpp_dec_50 之间选择?

    除非您有选择 cpp_dec_ 的特定理由, 否则默认选择应当是 cpp_bin_, 例如使用便捷的 typedefs, 例如 boost::multiprecision::cpp_bin_50 或 boost::multiprecision::cpp_bin_100.

    一般来说, 两者都工作良好, 给出相同的结果, 速度也大致相同, 其中 cpp_dec_50 有时更快.

    cpp_dec_ 先开发出来, 为 cpp_bin_ 铺平了道路. cpp_dec_ 有若干保护位且完全不做舍入, 用“蛮力”保证承诺的十进制位数正确, 但难以推断精度和计算不确定性, 例如参见 https://svn.boost.org/trac10/ticket/12133. 它还有一个快速但不精确的除法运算符, 有时会给出令人意外的结果, 参见 https://svn.boost.org/trac10/ticket/11178.

    cpp_bin_ 经过正确/精确舍入, 因而可以推断结果的精度和舍入.

  23. 如何查看或报告缺陷和特性请求, 以及申请新函数?

    当前开放的缺陷报告可以在 GITHUB 上此处查看.

    包括已关闭在内的所有旧缺陷报告可在 Trac (现为只读) 此处查看, 较新的 issue 在 GIThub 上此处查看.

  24. 如何判断我的编译器能否配合 Boost.Math 工作?

你首先应该假定你的编译器/平台 能够编译通过, 即使它只支持 C++03 标准.

Boost 总体上并 不“支持”某个特定的 C++ 标准、编译器或平台. 每个库都有自己的要求; 对 Boost.Math 而言, 每个单独的函数、分布或工具可能有不同的要求, 可能在某个特定编译器上可用, 也可能不可用.

所以简短的回答是: 试一试, 看看什么适合你.

一些较新的函数要求更新的标准, 甚至可能是尚未标准化的特性. 需求的一些线索可以从测试和示例 (见 jamfiles) 以及文档中的需求说明中搜集. 你可以查阅 Boost Test Matrix, 查看多平台多编译器上 Boost.Math 测试的当前结果. 但请记住, 测试或演示代码为了方便可能使用 C++11 或更高特性, 如 std::numeric_limits<>max_digits10、auto、lambdas ...; 你的应用可能并不需要这些.
