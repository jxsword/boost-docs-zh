立方根求根算法比较

在下表中, 使用四种算法为三种 fundamental (built-in) types 浮点类型以及一个 50 位十进制精度的 Boost.Multiprecision 类型 cpp_bin_float 计算 28 的立方根.

"精确"答案是使用 100 位十进制类型计算的:

cpp_bin_float_100 full_answer ("3.036588971875662519420809578505669635581453977248111123242141654169177268411884961770250390838097895");

时间使用 Boost.Timer 以 class cpu_timer 测量.

  • Its 是找到根所用的迭代次数.
  • Times 是以任意单位计的 CPU 耗时.
  • Norm 是相对于最快算法 (值为 1.00) 的归一化时间.
  • Dis 是与"精确"根的最接近可表示值之间的距离 (以位计). 与"精确"答案的距离用函数 Boost.Math float_distance 测量. 一两位的距离意味着所有结果实际上是"正确"的. 零表示"精确" - 即浮点类型的最接近 可表示值.

立方根函数是一个简单函数, 是求根的一个人为示例. 它确实让我们得以研究一些控制效率的因素, 这些因素可以外推到更复杂的函数.

所用的程序是 root_finding_algorithms.cpp. 对每种浮点类型和算法进行了 100000 次求值, 且从重复运行来看, CPU 时间的误差为 10%. 比较 double 和 long double 的 MSVC (二者在该平台上相同) 可以为计时的不确定性提供参考.

  • C++ 标准的立方根函数 std::cbrt 仅为内置或基本类型定义, 因此不能与任何用户定义浮点类型 (如 Boost.Multiprecision) 一起使用. 这一点, 加上立方函数的绝佳表现, 使得实现者可以使用许多技巧来实现快速计算. 在某些平台上, std::cbrt 的速度是更一般的 boost::math::cbrt 的数倍; 而在其他平台/编译器选项上, boost::math::cbrt 明显更快. 总的来说, 结果高度依赖于所使用的代码生成/处理器架构选择等编译器选项. 可以假定标准库在编译时使用了对其安装平台 接近 最优的选项, 而用户对 Boost.Math 使用的选项有更多选择. 选择过于通用/保守的选项会损失性能, 而选择利用最新指令集操作码的选项则会明显提速.
  • 比较了两个处于优化模式的编译器: 在相同硬件上使用 Netbeans IDE 的 GCC 4.9.1 和 Microsoft Visual Studio 2013 (Update 1). 迭代次数似乎一致, 但相对运行时间却出人意料地不同.
  • boost::math::cbrt 允许与 任何用户定义浮点类型 一起使用, 便捷地支持 Boost.Multiprecision. 与 n 次根求根示例中更一般的实现相比, 它同样可以利用立方函数的良好表现. 例如, 它使用多项式近似来生成比将指数除以三更好的初始猜测, 并且可以避免 Newton-Raphson iteration 中为防止搜索大幅偏离而需要的复杂检查. 对已知的精度, 还可以固定迭代次数, 从而允许内联和循环展开. 它还在代数上简化了 Halley 步骤, 与分别计算导数再在 Halley 代码中组合的"黑盒"实现相比, 大幅减少了所需的浮点运算次数. 典型地, 我们发现使用类型 double 直接采用各种求根算法计算时, 耗时是手工编码/优化的 cbrt 例程的数倍.
  • 获得良好初始猜测的重要性可以从多精度情形的迭代次数看出: 这里我们稍微"作弊"了一下, 把以 double 精度计算的立方根用作初始猜测. 这种策略的局限是可能的 (指数) 值的范围可能小于多精度类型.
  • 对于 fundamental (built-in) types, 三种导数方法之间几乎没有差别, 但对于 cpp_bin_float, Newton-Raphson iteration 快了一倍. 注意, 立方根是一个极端的测试用例, 因为调用函子的代价非常低, 运行时间主要受迭代代码复杂度的支配.
  • 使用优化编译使计算时间减半, 算法之间的差异几乎可以忽略不计. TOMS Algorithm 748: enclosing zeros of continuous functions 的优化加速尤为明显.
  • 使用像 cpp_bin_float_50 这样的多精度类型达到 50 位十进制精度耗时要长得多, 这在预期之中, 因为大部分计算使用软件而非 64 位浮点硬件. 速度往往慢 50 倍以上.
  • 使用 cpp_bin_float_50 时, TOMS Algorithm 748: enclosing zeros of continuous functions 慢得多, 显示了使用导数的益处. Newton-Raphson iteration 被发现比两种二阶导数方法都快一倍: 不过这是一个极端情形, 函数及其导数的计算代价非常低, 以至于我们实际测量的只是样板求根代码的复杂度.
  • 对多精度类型, 无论使用哪种算法, 只需一两次额外的 迭代 就能得到剩余的 35 位数字. (当然, 这些类型所花的时间要长得多).
  • 使用 100 位十进制类型只会让时间翻倍, 且只需多几次迭代, 因此额外精度的代价主要是计算更多位数的底层代价, 而不在于算法的运作方式. 这证实了之前使用 NTL A Library for doing Number Theory 高精度类型的观察.
