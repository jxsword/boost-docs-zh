C99 与 C++ TR1 C 风格函数

本库包含的许多特殊函数也是 C99 Standard ISO/IEC 9899:1999 或 Technical Report on C++ Library Extensions 的一部分. 因此本库包含一个轻量封装头 boost/math/tr1.hpp, 提供与这两个标准的兼容性.

以这种方式使用本库各有优劣:

优点:

  • 要包含的头文件很轻量 (即编译速度快) .
  • 函数具有 extern "C" 链接, 因此可以从其他语言 (不仅是 C 和 C++) 调用.
  • 符合 C99 和 C++ TR1 标准.

缺点:

  • 需要编译并链接外部 Boost.Math 库.
  • 仅支持 float、double 和 long double 类型.
  • 错误处理通过设置 ::errno 并返回 NaN 和无穷大来完成: 这可能不如基于 C++ 异常的方式灵活.
注释

只有当你选择使用 boost/math/tr1.hpp 而非其他 Boost.Math 头文件时, 才需要单独的库; Boost.Math 的其余部分仍是仅头文件库.

使用 tr1.hpp 所需的单独库可以在 libs/math/build 目录内用 bjam 编译, 或在 Boost 根目录下用通常的 Boost 全局安装过程编译. 另外, 源文件位于 libs/math/src, 每个文件与其实现的函数同名. 各库命名如下:

其中 <suffix> 编码了构建这些库所用的编译器和构建选项: 例如 "libboost_math_tr1-vc80-mt-gd.lib" 是供 Visual C++ 8.0 在多线程调试模式、DLL VC++ 运行库下使用的静态链接 TR1 库, 而 "boost_math_tr1-vc80-mt.lib" 则是供 Visual C++ 8.0 在 release 多线程 DLL VC++ 运行库下使用的 TR1 DLL 导入库. 入门指南中有关于 <suffix> 含义的完整解释.

注释

Visual C++ 用户通常无需自行选择: boost/math/tr1.hpp 会根据你的编译器设置选择要链接的正确库变体.

如果用户想链接这些库的 DLL 版本而非静态版本, 则在构建代码时需要定义 BOOST_MATH_TR1_DYN_LINK.

用户可以在构建时定义 BOOST_MATH_TR1_NO_LIB 来禁用自动链接: 这通常只在链接定制构建的库时使用.

注释

Linux 和 Unix 用户通常只安装了这些库的一个变体, 一般直接链接 -lboost_math_tr1 等即可.

使用建议

本库现在给用户提供了选择:

  • 包含函数的仅头文件版本, 链接更容易, 但编译时间更长.
  • 包含 TR1 头文件并链接外部库.

选择哪个选项很大程度上取决于你的工作习惯和系统配置.

例如, 只需要 acosh 函数的临时用户, 最好包含 <boost/math/special_functions/acosh.hpp> 并在代码中使用 boost::math::acosh(x).

然而, 对于编译时间很重要、且 Boost 库已在系统上构建并安装的大型软件开发, 包含 <boost/math/tr1.hpp> 并使用 boost::math::tr1::acosh(x) 会加快编译、减小目标文件大小 (因为不再实例化模板) , 还能加快调试运行——因为外部编译的库可以用编译器优化选项构建, 而不是用完整设置构建——release 和 debug 构建的性能差异可达 20 倍, 因此对复杂应用来说这是很大的收益.
