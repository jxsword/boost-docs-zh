更改策略默认值

本库使用的默认策略通过常用的配置宏方法更改.

例如, 向编译器传递 -DBOOST_MATH_DOMAIN_ERROR_POLICY=errno_on_error 会导致定义域错误设置 ::errno 并返回 NaN, 而不是抛出 std::domain_error 异常的通常默认行为.

提示

对于 Microsoft Visual Studio, 你可以在 Project Property Page、C/C++、Preprocessor、Preprocessor definitions 中添加如下内容:

BOOST_MATH_ASSERT_UNDEFINED_POLICY=0
BOOST_MATH_OVERFLOW_ERROR_POLICY=errno_on_error

这可能有助于避免与预编译头相关的复杂情况, 后者可能意味着源代码中的等价定义:

#define BOOST_MATH_ASSERT_UNDEFINED_POLICY false
#define BOOST_MATH_OVERFLOW_ERROR_POLICY errno_on_error
  • 会被忽略*.

编译器命令行显示:

/D "BOOST_MATH_ASSERT_UNDEFINED_POLICY=0"
/D "BOOST_MATH_OVERFLOW_ERROR_POLICY=errno_on_error"

不过, 对此有一个非常重要的告诫:

重要

通过设置配置宏更改的默认策略必须在程序的每个编译单元中统一更改.

不遵守这一规则可能导致违反"单一定义规则 (ODR)", 并造成不可预测的程序行为.

这意味着只有两种安全的方式可以使用这些宏:

  • 在 boost/math/tools/user.hpp 中编辑它们, 使默认值以安装级方式设置. 遗憾的是, 如果你使用的是预安装的 Boost 发行版 (例如在 Linux 上), 这可能不方便.
  • 在项目的 Makefile 或构建环境中设置这些定义, 使它们在所有编译单元中统一设置.

你 不应 做的是:

  • 在源文件中通过 #define 设置这些定义, 因为这样做几乎必然破坏你的程序, 除非你完全确定程序被限制在单个编译单元内.

而且, 是的, 你会在我们的测试程序中找到违反这一规则的示例: 但这只是因为我们知道始终只会有单个编译单元: 别说没人警告过你!

下面的示例演示了遇到无效参数时设置宏 BOOST_MATH_DOMAIN_ERROR_POLICY 的效果. 在本示例中, 我们将向 Student t 分布传入负的自由度参数.

由于我们知道这是一个单文件程序, 我们可以直接添加:

#define BOOST_MATH_DOMAIN_ERROR_POLICY ignore_error

到源文件顶部, 把默认策略改为在发生定义域错误时简单地返回 NaN 的策略. 或者我们也可以使用:

#define BOOST_MATH_DOMAIN_ERROR_POLICY errno_on_error

以确保在发生定义域错误时设置 ::errno 并返回 NaN.

只要程序由单个编译单元组成 并且 我们把定义放在任何 #include 之前, 这就是安全的. 注意, 如果我们把定义放在 include 之后, 它将没有任何效果! 出现如下警告:

warning C4005: 'BOOST_MATH_OVERFLOW_ERROR_POLICY' : macro redefinition

则是一个明确的信号, 表明它 不会 产生预期的效果.

我们将从所需的 include 开始编写示例程序:

   #define BOOST_MATH_DOMAIN_ERROR_POLICY ignore_error

// Boost
#include <boost/math/distributions/students_t.hpp>
   using boost::math::students_t;  // Probability of students_t(df, t).

// std
#include <iostream>
   using std::cout;
   using std::endl;

#include <stdexcept>


#include <cstddef>
   // using ::errno

接下来我们将定义程序的 main() 以带无效自由度参数调用 Student t 分布, 程序被设置为可以处理异常或 NaN:

int main()
{
   cout << "Example error handling using Student's t function. " << endl;
   cout << "BOOST_MATH_DOMAIN_ERROR_POLICY is set to: "
      << BOOST_MATH_STRINGIZE(BOOST_MATH_DOMAIN_ERROR_POLICY) << endl;

   double degrees_of_freedom = -1; // A bad argument!
   double t = 10;

   try
   {
      errno = 0; // Clear/reset.
      students_t dist(degrees_of_freedom); // exception is thrown here if enabled.
      double p = cdf(dist, t);
      // Test for error reported by other means:
      if((boost::math::isnan)(p))
      {
         cout << "cdf returned a NaN!" << endl;
         if (errno != 0)
         { // So errno has been set.
           cout << "errno is set to: " << errno << endl;
         }
      }
      else
         cout << "Probability of Student's t is " << p << endl;
   }
   catch(const std::exception& e)
   {
      std::cout <<
         "\n""Message from thrown exception was:\n   " << e.what() << std::endl;
   }
   return 0;
} // int main()

以下是默认构建 (会抛出异常 的构建) 时程序输出的样子:

Example error handling using Student's t function.
BOOST_MATH_DOMAIN_ERROR_POLICY is set to: throw_on_error

Message from thrown exception was:
   Error in function boost::math::students_t_distribution<double>::students_t_distribution:
   Degrees of freedom argument is -1, but must be > 0 !

或者让我们用如下方式构建:

#define BOOST_MATH_DOMAIN_ERROR_POLICY ignore_error

现在程序输出是:

Example error handling using Student's t function.
BOOST_MATH_DOMAIN_ERROR_POLICY is set to: ignore_error
cdf returned a NaN!

最后让我们用如下方式构建:

#define BOOST_MATH_DOMAIN_ERROR_POLICY errno_on_error

输出显示 errno:

Example error handling using Student's t function.
BOOST_MATH_DOMAIN_ERROR_POLICY is set to: errno_on_error
cdf returned a NaN!
errno is set to: 33
