同样支持补集——以及何时使用补集

通常你要的不是 CDF 的值, 而是它的补集, 也就是说 1-p 而非 p. 人们很容易想到先计算 CDF 再用 1 减去它, 但如果 p 非常接近 1, 消去误差会使你损失精度, 甚至可能完全损失.

参见下文 "为什么以及何时使用补集?"

在本库中, 每当你想获得补集时, 只需把所有函数参数包裹在一次 complement(...) 调用中, 例如:

students_t dist(5);
cout << "CDF at t = 1 is " << cdf(dist, 1.0) << endl;
cout << "Complement of CDF at t = 1 is " << cdf(complement(dist, 1.0)) << endl;

不过等一下, 既然有了补集, 我们还必须能够使用它. 任何接受概率作为参数的函数也都可以接受补集, 只需把它的所有参数包裹在一次 complement(...) 调用中, 例如:

students_t dist(5);

for(double i = 10; i < 1e10; i *= 10)
{
   // Calculate the quantile for a 1 in i chance:
   double t = quantile(complement(dist, 1/i));
   // Print it out:
   cout << "Quantile of students-t with 5 degrees of freedom\n"
           "for a 1 in " << i << " chance is " << t << endl;
}

临界值就是分位数

一些文献使用分位数、百分位数或 fractile 这类说法, 另一些则使用临界值, 基本规则是:

下临界值 与分位数相同.

上临界值 与从概率的补集求得的分位数相同.

例如, 假设我们有一个 Bernoulli 过程, 产生成功率为 0.1、总试验次数为 100 的二项分布. 概率 0.05 对应的 下临界值 由下式给出:

quantile(binomial(100, 0.1), 0.05)

而 上临界值 由下式给出:

quantile(complement(binomial(100, 0.1), 0.05))

分别返回 4.82 和 14.63.

究竟为什么要用补集?

人们很想省掉补集, 在需要时简单地用 1 减去概率. 然而, 想想当概率非常接近 1 时会发生什么: 假设以 float 精度表示的概率是 0.999999940f, 那么 1 - 0.999999940f = 5.96046448e-008, 但结果实际上只精确到 一个比特: 唯一没有被消去的那个比特!

换个角度看: 假设在 Student t 检验中, 我们想把错误拒绝零假设的风险设为十亿分之一, 样本量为 10,000. 这给出概率 1 - 10-9, 以 float 精度计算时它恰好等于 1. 在这种情况下, 从补集计算分位数恰好解决了这个问题, 例如:

quantile(complement(students_t(10000), 1e-9))

返回预期的 t 统计量 6.00336, 而:

quantile(students_t(10000), 1-1e-9f)

会引发上溢错误, 因为它等价于:

quantile(students_t(10000), 1)

后者没有有限结果.

对所有分布, 即使概率更为合理 (除非 p 的值能在浮点类型中精确表示), 如果简单地用 1 - p 计算概率, 精度损失也会很快变得显著 (因为当 p ≈ 1 时结果大部分是垃圾数字).

因此务必避免, 例如, 使用像 0.99999 这样接近 1 的概率

quantile(my_distribution, 0.99999)

而应使用

quantile(complement(my_distribution, 0.00001))

因为使用浮点算术时, 1 - 0.99999 并不精确等于 0.00001.

这假设 0.00001 这个值要么是常量, 要么可以用从 1 中减去 0.99999 之外的某种方式计算得到.
