用 float128_t 重载模板函数

为 quadmath 提供 C++ 标准库支持的副作用可能要求把 <boost/cstdfloat.hpp> 包含在其他头文件之前.

考虑一个调用 fabs(x) 且先前已把 std::fabs() 通过 using 指令注入局部作用域的函数:

template <class T>
bool unsigned_compare(T a, T b)
{
   using std::fabs;
   return fabs(a) == fabs(b);
}

在该函数中, fabs 的正确重载可以通过 argument-dependent-lookup (ADL) 或调用 std::fabs 重载之一找到. 但两者有一个关键区别: 与 T 同一命名空间、通过 ADL 找到的重载在函数声明时不必已定义. 然而, <boost/cstdfloat.hpp> 中声明的所有类型都是基础类型, 因此对这些类型我们要依赖在命名空间 std 中找到已声明的重载. 但在这种情况下, 所有此类重载必须在函数 unsigned_compare 的定义之前声明, 否则它们不会被考虑.

如果 <boost/cstdfloat.hpp> 在上述函数定义之后才被包含, 那么 fabs 的正确重载虽然存在, 却根本不会被视为重载集的一部分. 于是编译器先尝试把 float128_t 参数向下转换为 long double, 再转换为 double, 再转换为 float; 由于结果有歧义, 编译失败. 然而编译器的错误信息会显得极其晦涩, 出现在看似无关的行号上, 且完全未提及 float128: 单词 ambiguous 是问题所在的线索.

只要你包含 #include <boost/cstdfloat.hpp> 先于任何含通用浮点代码的头文件 (例如其他 Boost.Math 头文件), 编译器就会知道并使用 std::fabs(std::float128_t) (由我们在 #include <boost/cstdfloat.hpp> 中提供).
