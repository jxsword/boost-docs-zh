性能测试应用程序

在 boost-path/libs/math/reporting/performance 下, 你会找到本库一些相当全面的性能测试应用程序.

为了生成本文档中你已见过的表格 (或针对你的特定编译器的其他表格), 你需要在该目录中使用支持 C++11 的编译器调用 bjam. 注意, 结果会扩展/覆盖 boost-path/libs/math/reporting/performance/doc/performance_tables.qbk 中已有的任何内容; 开始之前你可能想删除该文件, 以便为你的特定系统重新开始.

这些程序以 Boost 的 Quickbook 格式生成结果, 该格式可读性不佳. 如果你将 user-config.jam 配置为能够构建 Docbook 文档, 那么还将在 boost-path/libs/math/reporting/performance/html/index.html 获得所有数据的 HTML 格式完整汇总. 假设你在类 'nix 平台上, 操作步骤是先安装 xsltproc、Docbook DTD 和 Bookbook XSL 软件包. 然后:

  • 将 boost-path/tools/build/example/user-config.jam 复制到你的主目录.
  • 在文件末尾添加 using xsltproc ; (注意每个记号周围的空格, 包括最后的 ";", 这很重要!) 这假定 xsltproc 在你的 path 中.
  • 在文件末尾添加 using boostbook : path-to-xsl-stylesheets : path-to-dtd ;. path-to-dtd 应指向 Docbook DTD 4.2.x 版本, 而 path-to-xsl-stylesheets 应指向包含最新 XSLT 样式表的文件夹. 即使在 Windows 上, 两个路径也应全部使用正斜杠.

至此你应该能够运行测试并生成 HTML 汇总. 如果编译器路径中存在 GSL、RMath 或 libstdc++, 它们会被自动测试. 对于 DCDFLIB, 你需要将 C 源码放到 boost-path/libs/math/reporting/performance/third_party/dcdflib.

如果你想比较多个编译器, 或同一编译器的多个选项, 则需要多次调用 bjam, 每个编译器一次. 注意, 为了测试同一编译器的多种配置, 每种配置都必须在测试程序中赋予唯一名称, 否则它们都会编辑相同的表格单元格. 假设你想测试带与不带 -ffast-math 选项的 GCC, 此时先按如下方式调用 bjam:

bjam toolset=gcc -a cxxflags=-std=gnu++11

这将使用默认优化选项 (-O3) 运行测试, 然后我们可以再用 -ffast-math 运行一次:

bjam toolset=gcc -a cxxflags='-std=gnu++11 -ffast-math' define=COMPILER_NAME='"GCC with -ffast-math"'

在上面的命令行中, -a 标志强制完全重建, 预处理器定义 COMPILER_NAME 需设置为描述编译器配置的字符串字面量, 因此需要双引号 - 一个用于命令行, 一个用于编译器.
