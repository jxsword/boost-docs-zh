获取最后一位单位 (ULP) 的大小

函数 ulp 给出指定浮点值的最后一位单位大小.

概要 
#include <boost/math/special_functions/ulp.hpp>

namespace boost{ namespace math{

template <class FPT>
FPT ulp(const FPT& x);

template <class FPT, class Policy>
FPT ulp(const FPT& x, const Policy&);

}} // namespaces
说明 - ulp

返回 unit in the last place (最后一位单位) , 即 x 的一个 ULP.

边界情形按如下方式处理:

  • 若实参为 NaN, 则抛出 domain_error.
  • 若实参为无穷大, 则抛出 overflow_error.
  • 若实参为零, 则返回最小可表示值: 例如对类型 double, 结果为 std::numeric_limits<double>::min() 或 std::numeric_limits<double>::denorm_min(), 取决于是否支持非规格化数 (其值分别为 2.2250738585072014e-308 和 4.9406564584124654e-324) .
  • 若结果太小而无法表示, 则返回最小可表示值.
  • 始终返回正值, 使得 ulp(x) == ulp(-x).

重要: 该函数的行为与 Java's ulp function 对齐; 但请注意, 此函数只应用于粗略计算, 因为其边界情形之多足以困住甚至细心的程序员. 特别是:

  • 该函数是非对称的: 给定 u = ulp(x), 若 x > 0, 则 x + u 是下一个浮点值, 但 x - u 未必是上一个值. 类似地, 若 x < 0, 则 x - u 是上一个浮点值, 但 x + u 未必是下一个值. 边界情形出现在 2 的幂边界处.
  • 当实参变得非常小时, 可能不存在表示一个 ULP 的浮点值. 是否如此不仅取决于硬件是否 有时支持非规格化数 (由 boost::math::detail::has_denorm_now<FPT>() 指示) , 还取决于这些支持在运行期是否被启用 (例如在 SSE 硬件上, DAZ 或 FTZ 标志会禁用非规格化支持) . 在这种情况下, ulp 函数可能返回一个大了许多个数量级的值.

鉴于上述问题, 我们建议:

  • 在相邻浮点值之间移动时, 始终使用 float_next、float_prior 或 nextafter (std::nextafter 是另一个候选, 但我们的经验是它也经常失效, 取决于当前生效的优化和硬件标志) .
  • 要一次移动多个浮点值, 使用 float_advance.
  • 要计算两个浮点数之间的编辑距离, 使用 Boost.Math float_distance.

不过, 该函数仍有一个重要用例:

如果已知某函数的真实结果是 xt, 计算结果是 xc, 则以 ulp 度量的误差就是 fabs(xt - xc) / ulp(xt).
