Gauss-Kronrod 求积

概述

Gauss-Kronrod 求积是 Gaussian 求积的扩展, 它为积分提供事后误差估计.

Gaussian 求积背后的思想是: 选择 n 个节点与权重, 使 2n-1 阶多项式能被精确积分. 然而, 多项式的积分是平凡的, 很少用数值方法完成. 实际上, 通过 Gaussian 求积积分的是超越函数与数值定义的函数, 于是关键问题变成如何估计余项. 仅靠 Gaussian 求积本身 (不做某种形式的区间拆分) 无法回答这个问题.

可以计算一个 n 阶 Gaussian 求积和另一个 (比如说) 2n+1 阶的求积, 并把两者的差作为误差估计. 但这并非最优, 因为不同阶数的 Legendre 多项式 (Gaussian 求积的节点) 的零点从不相同, 所以必须做 3n+1 次函数求值. Kronrod 研究了如何把节点交错嵌入 Gaussian 求积, 使所有先前的函数求值都能复用, 同时提高可被精确积分的多项式阶数. 这样既提供事后误差估计, 又保持指数收敛. Kronrod 发现, 向 n 阶 Gaussian 求积添加 n+1 个节点 (由 Legendre-Stieltjes 多项式的零点计算), 他可以精确积分 3n+1 阶多项式.

这里提供的积分例程既可执行自适应也可执行非自适应求积, 应当用于积分无端点奇点的光滑函数. 对困难的函数或有端点奇点的函数, 请参考 双指数积分方案.

#include <boost/math/quadrature/gauss_kronrod.hpp>

template <class Real, unsigned N, class Policy = boost::math::policies::policy<> >
class gauss_kronrod
{
   static const RandomAccessContainer& abscissa();
   static const RandomAccessContainer& weights();

   template <class F>
   static auto integrate(F f,
                         Real a, Real b,
                         unsigned max_depth = 15,
                         Real tol = tools::root_epsilon<Real>(),
                         Real* error = nullptr,
                         Real* pL1 = nullptr)->decltype(std::declval<F>()(std::declval<Real>()));
};

说明 

static const RandomAccessContainer& abscissa();
static const RandomAccessContainer& weights();

这些函数提供对执行求积所用横坐标与权重的直接访问: 返回类型取决于 Points 模板参数, 但始终是 RandomAccessContainer 类型. 注意只保存正 (或零) 的横坐标与权重, 且它们同时包含 Gauss 点与 Kronrod 点.

template <class F>
static auto integrate(F f,
                            Real a, Real b,
                            unsigned max_depth = 15,
                            Real tol = tools::root_epsilon<Real>(),
                            Real* error = nullptr,
                            Real* pL1 = nullptr)->decltype(std::declval<F>()(std::declval<Real>()));

在区间 (a,b) 上对函数 f 执行自适应 Gauss-Kronrod 求积.

max_depth 设置停止前允许的最大区间拆分次数. 非自适应求积把它设为零. 注意该算法按深度优先下降遍历树, 因此只有积分的"困难"区域才会导致区间拆分.

tol 设置结果的最大相对误差, 不应把它设得过分接近机器 epsilon, 否则函数只会原地挣扎, 很可能无法返回准确结果. 另一方面, 默认值可能过于悲观.

error 当非空时, *error 被设为 (N-1)/2 点 Gauss 近似与 N 点 Gauss-Kronrod 近似之差.

pL1 当非空时, *pL1 被设为结果的 L1 范数, 若它与返回值有显著差异, 则结果很可能是病态的.

选择点的数量

Points 模板参数中指定的点数必须是奇数: 从而给出一个 (N-1)/2 点 Gauss 求积作为误差估计的比较基准.

类 gauss_kronrod 在内部为 15、31、41、51 与 61 个 Gauss-Kronrod 点预计算了最高 100 位十进制精度的横坐标与权重表. 这意味着例如使用 gauss_kronrod<double, 31>::integrate 时, 计算横坐标/权重对完全没有设置开销. 当使用精度低于 100 位的多精度类型时, 会有一次性的较小初始成本, 因为横坐标/权重对要从字符串构造.

然而, 对更高精度的类型, 或点数不同于上述给定值的情形, 横坐标/权重对会在首次需要时计算并缓存供将来使用, 这确实会带来可观的额外开销. 如果这可能成为问题, 那么:

  • 定义 BOOST_MATH_GAUSS_NO_COMPUTE_ON_DEMAND 将导致编译期错误: 每当使用没有预计算值的数字类型与点数组合时就会报错.
  • 有一个程序 gauss_kronrod_constants.cpp, 它曾用于提供 gauss_kronrod.hpp 中已有的预计算值. 稍加修改即可让该程序为其他精度与点数生成代码与常数.

复数求积

Gauss-Kronrod 求积支持定义在实数轴上并返回复数值的被积函数. 此时模板参数是实数类型, 复数类型经由函数的返回类型推导.

示例

我们首先在 (0,+∞) 上用 7 项 Gauss 法则与 15 项 Kronrod 法则积分 exp(-t2/2), 先把被积函数定义为 C++ lambda 表达式:

using namespace boost::math::quadrature;

auto f1 = [](double t) { return std::exp(-t*t / 2); };

我们先做一次性 (即非自适应) 积分, 并跟踪估计误差:

double error;
double Q = gauss_kronrod<double, 15>::integrate(f1, 0, std::numeric_limits<double>::infinity(), 0, 0, &error);

得到 Q = 1.25348207361, 其绝对误差为 1e-4, 而估计误差为 5e-3: 这是相当典型的情形, Gauss 与 Gauss-Kronrod 方案之间的差远大于实际误差. 在继续自适应求积之前, 让我们用更多的点再试一次, 实际上用的是我们缓存的最大 Gauss-Kronrod 方案 (30/61):

Q = gauss_kronrod<double, 61>::integrate(f1, 0, std::numeric_limits<double>::infinity(), 0, 0, &error);

得到绝对误差 3e-15, 而估计为 1e-8, 这在 double 精度下差不多是能达到的最好结果.

不过, 与其继续增加点数, 不如切换到自适应积分, 把期望相对误差设为 1e-14, 最大深度设为 5:

Q = gauss_kronrod<double, 15>::integrate(f1, 0, std::numeric_limits<double>::infinity(), 5, 1e-14, &error);

得到实际误差为零, 而估计为 4e-15. 实际上在此情形下, 所要求的容差几乎可以肯定设得过低: 如上所见, 对光滑函数, 达到的精度往往是估计值的两倍, 因此如果我们以 1e-9 的容差积分:

Q = gauss_kronrod<double, 15>::integrate(f1, 0, std::numeric_limits<double>::infinity(), 5, 1e-9, &error);

仍然达到 1e-15 精度, 误差估计为 1e-10.

注意事项

对定义域上有界的几乎所有解析被积函数, 该例程提供的误差估计都悲观得可怜. 实际上, 此情形下误差非常接近 (N-1)/2 阶 Gaussian 求积公式的误差, 而 Kronrod 扩展在 Gaussian 估计之外呈指数收敛. 存在估计误差的非常精巧的方法, 但都要求被积函数属于特定的函数空间. 对特定函数空间中元素更精细的事后误差估计留给用户.

这些例程刻意保持相对简单: 当它们工作时, 工作得非常好也非常快. 但是, 没有做过任何努力使这些例程对端点奇点或其他"困难"积分表现良好. 这类情形请使用 双指数积分方案, 它们通常稳健得多.
