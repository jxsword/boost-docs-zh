n 次根求根算法比较

第二个例子比较四种广义 n 次根求根算法, 用于计算单个值 28.0 的各种 n 次根 (5、7 和 13), 涉及四种浮点类型: float、double、long double 以及一个 Boost.Multiprecision 类型 cpp_bin_float_50. 在每种情况下, 目标精度都使用我们"推荐"的精度限制设置 (或至少是能成为良好起点的限制 - 它很可能在不诉诸不必要迭代的情况下给出接近完全精度的结果).

从这一有限的试验中可以得出一些初步结论.

  • 也许令人惊讶, 对 fundamental (built-in) types 浮点类型而言, 各种算法之间几乎没有差别. 使用第一导数 (Newton-Raphson iteration) 通常最好, 虽然相比无导数的 TOMS Algorithm 748: enclosing zeros of continuous functions 在迭代次数上有相当大的改进, 但执行时间上却很少. 这反映了这样的事实: 我们为其求根的函数求值非常简单, 因此运行时间由每种方法中样板代码所花的时间主导.
  • 求值第二导数 (Halley 或 Schröder) 的额外代价通常太高, 得不偿失: 与立方根一样, 这些函子的求值代价如此之低, 以至于运行时间在很大程度上由求根方法的复杂度主导.
  • 对于 Boost.Multiprecision 浮点类型, Newton-Raphson iteration 是明显的赢家, 比 TOMS Algorithm 748: enclosing zeros of continuous functions 快数倍, 而二阶导数算法同样没有改进.
  • 50 位十进制的 Boost.Multiprecision 的运行时间约为 double 的 30 倍.
  • 'dis' 列显示与正确结果相距的位数. Newton-Raphson 算法的精度比 TOMS Algorithm 748: enclosing zeros of continuous functions 好 1 到 2 位.
  • "猜测"的好坏对 Boost.Multiprecision 尤为关键. 单独的实验表明, 使用 double 求值"猜测"可以在一两次迭代内收敛到最终精确结果. 所以在这个人为示例中, 用"猜测"粗略地把指数除以 N, 远不如使用 pow<double> 或 (若需更精确) pow<long double> 函数来估计"猜测". 这种策略的局限是可能的 (指数) 值的范围可能小于多精度类型.
  • 使用浮点扩展 SSE2 instructions 带来了适度的百分之十加速.
  • 使用 MSVC 时, 64 位带来了一些改进, 对 Boost.Multiprecision 尤为明显.
  • GCC 编译器 4.9.1 使用 64 位时比 32 位至少快 5 倍, 显然反映了更好的优化.

显然, 你的实际效果 会有所不同, 但总而言之, Newton-Raphson iteration 似乎是算法的首选, 而寻找良好"猜测"的努力是第一个加速目标, 尤其对 Boost.Multiprecision 而言. 当然, 编译器优化对速度至关重要.
