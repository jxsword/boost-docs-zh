在模板代码中使用

在函数模板内使用这些常数时, 我们需要确保使用对模板参数精度正确的常数. 为此, 可以像这样调用常数的函数模板版本 pi<FPType>():

#include <boost/math/constants/constants.hpp>

template <class Real>
Real area(Real r)
{
   using namespace boost::math::constants;
   return pi<Real>() * r * r;
}

尽管这种语法不如非模板版本那么 "可爱", 但代码效率毫不逊色 (至少对内建类型 float、double 和 long double 而言): 常数的函数模板版本是简单的内联函数, 返回对所用类型精度正确的常数. 此外, 对支持这一点的编译器, 这些函数被声明为 constexp, 只要模板参数是字面类型, 就允许在常量表达式中使用结果.

提示

请记住变量版本 (只是 pi) 与模板函数版本的区别: 模板函数既需要 <floating-point-type> 也需要函数调用括号 (), 例如: pi<double>(). 你不能写 double p = pi<>(), 也不能写 double p = pi().

注释

你总是可以同时使用 两种 版本——变量版本和模板函数版本——只要调用是完全限定的, 例如:

double my_pi1 = boost::math::constants::pi<double>();
double my_pi2 = boost::math::double_constants::pi;
警告

人们可能想简单地定义

using namespace boost::math::double_constants;
using namespace boost::math::constants;

但如果你真的定义了两个命名空间, 这当然会造成歧义!

double my_pi = pi(); // error C2872: 'pi' : ambiguous symbol
double my_pi2 = pi; // Context does not allow for disambiguation of overloaded function

虽然上面的错误相当明显, 但不小心犯下这种错误也不太难, 更糟的是, 还可能在别人的代码中造成这种错误.

因此, 谨慎的做法是像上面那样 把这类定义的作用域局部化, 以避免这一风险.

提示

对作为参数提供的类型要非常小心. 例如, 提供 整数 而非浮点类型可能是灾难性的 (这是 C++ 的一个特性).

cout << "Area = " << area(2) << endl; // Area = 12!!!

你应当会得到一个编译器警告

warning : 'return' : conversion from 'double' to 'int', possible loss of data

不理会这个警告可能导致非常错误的答案!

你也可以通过显式指定 Area 的类型来避免这一点.

cout << "Area = " << area<double>(2) << endl; // Area = 12.566371
