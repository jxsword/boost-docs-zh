是否以及如何构建 Boost.Math 库及其示例和测试

构建库 (shared、动态 .dll 或静态 .lib)

你需要问自己的第一个问题是“我真的需要构建什么吗?”, 因为本库的大部分是仅头文件库: 意味着只需 #include 必要的头文件即可使用.

对大多数简单用途而言, 包含一个 (或少数几个) 头文件对编译时间和程序体积最有利.

关于使用 TR1 组件相对于仅头文件版本的利弊, 请参考 C99 and C++ TR1 C-style Functions.

唯一 需要 构建此库的情形, 是你想使用 extern "C" 函数 (声明于 <boost/math/tr1.hpp> 中). 要用 Boost.Build 构建它, 请在命令行的 boost 根目录下发出如下命令:

bjam toolset=gcc --with-math install

在 Linux 上这条命令即可完成任务, 而:

bjam toolset=msvc --with-math --build-type=complete stage

在 Windows 上效果更好 (库会构建在 Boost 根目录下的子文件夹 /stage 中). 无论如何, 你都应查阅入门指南以获取更多信息.

你也可以在自己喜欢的 IDE 或命令行工具中构建这些库: 声明于 extern "C" 中的每个 <boost/math/tr1.hpp> 函数在 libs/math/src/tr1 中都有同名的源文件. 只需选择与你所用函数对应的源文件, 把它们构建成库, 或直接把它们添加到你的项目中. 注意, 目录 libs/math/src/tr1 也必须位于编译器的 #include 路径以及 boost 根目录中 (MSVC: Tools, Options, Projects and Solutions, VC++ Directories, Include files).

注释

如果你使用支持自动链接的 Windows 编译器, 并且自己构建了这些源文件 (或直接把它们加入项目), 那么你需要防止 <boost/math/tr1.hpp> 尝试自动链接到 Boost.Build 生成的二进制文件. 办法是在项目级定义 BOOST_MATH_NO_LIB 或 BOOST_ALL_NO_LIB (这样这些定义会传递给每次编译器调用).

可选地, libs/math/src/tr1 中的源文件支持把 libs/math/src/tr1/pch.hpp 用作预编译头 (如果你的编译器支持预编译头). 注意, 通常这个头文件是个什么都不做的 #include 要激活此头文件、使其 #include 所有源文件所需的全部内容, 你需要在命令行定义 BOOST_BUILD_PCH_ENABLED, 构建预编译头和构建源文件时都要定义. Boost.Build 会在适当的时候自动完成这一步.

构建示例

所有示例都位于 libs/math/example 中, 它们都可以在不引用任何外部库的情况下构建, 既可以用 Boost.Build 配合随附的 Jamfile, 也可以用编译器命令行. 唯一的要求是 Boost 头文件位于编译器的 #include 搜索路径中.

构建测试

测试位于 libs/math/test 中, 最好使用 Boost.Build 和随附的 Jamfile 构建. 如果你打算在自己喜欢的 IDE 中单独构建它们, 则需要把 libs/math/test 加入编译器的搜索路径列表.

许多测试还需要构建并链接 Boost.Regex 库: 可以按照入门指南在命令行中构建, 使用如下命令:

bjam toolset=gcc --with-regex install

or bjam toolset=clang --with-regex install or bjam toolset=gcc,clang --with-regex install or bjam toolset=msvc --with-regex --build-type=complete stage

具体取决于你使用的是 Linux 还是 Windows.

许多测试使用头文件 libs/math/test/pch.hpp 提供可选的预编译头支持. 注意, 通常这个头文件是个什么都不做的 include: 要激活此头文件、使其 #include 所有源文件所需的全部内容, 你需要在命令行定义 BOOST_BUILD_PCH_ENABLED, 构建预编译头和构建源文件时都要定义. Boost.Build 会在适当的时候自动完成这一步.
