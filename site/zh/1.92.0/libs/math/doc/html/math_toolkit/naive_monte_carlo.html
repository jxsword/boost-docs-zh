朴素蒙特卡洛积分

概要 

#include <boost/math/quadrature/naive_monte_carlo.hpp>
namespace boost { namespace math { namespace quadrature {

template<class Real, class F, class RNG = std::mt19937_64, class Policy = boost::math::policies::policy<>,
         typename std::enable_if<std::is_trivially_copyable<Real>::value, bool>::type = true>
class naive_monte_carlo
{
public:
    naive_monte_carlo(const F& integrand,
                      std::vector<std::pair<Real, Real>> const & bounds,
                      Real error_goal,
                      bool singular = true,
                      size_t threads = std::thread::hardware_concurrency());

    std::future<Real> integrate();

    void cancel();

    Real current_error_estimate() const;

    std::chrono::duration<Real> estimated_time_to_completion() const;

    void update_target_error(Real new_target_error);

    Real progress() const;

    Real current_estimate() const;

    size_t calls() const;
};
}}} // namespaces

说明

类 naive_monte_carlo 在区域 Ω 上对平方可积函数 f 执行蒙特卡洛积分. 蒙特卡洛积分的理论背景在 Wikipedia 上有很好的讨论, 此处不再赘述. 不过, 尽管它“朴素”, 却不能误以为朴素蒙特卡洛积分不强大: 方法的简单性带来了更精巧的工具不易提供的稳健性. 该例程的多线程特性使我们可以极快地计算大量采样点, 从而借助现代硬件的全部算力缓解收敛缓慢的问题.

Boost 提供的朴素蒙特卡洛积分体现了应对高性能计算所需的编程技术. 例如, 由于收敛速度只有 𝑶(N-1/2), 计算时间对误差目标非常敏感. 用户很容易指定一个会让计算持续数月 (或只需几秒) 的误差目标. 没有进度报告, 这种情况让人不知所措, 用户会变得偏执. 即便有进度报告, 由于所在机构的优先级变化, 用户可能仍需取消任务, 因此必须支持取消. 取消的任务若不返回任何结果便是浪费, 所以取消必须是优雅的, 要返回迄今为止对结果的最佳估计. 此外, 任务可能已经完成, 而用户很可能想试试更低的误差界. 因此必须支持在不损失先前工作量的情况下重新开始. 最后, 在 HPC 系统上, 我们通常希望用满所有可用线程. 但如果计算在用户工作站上进行, 占满所有线程会导致浏览器、邮件或音乐应用失去响应, 因此留出一个线程给其他应用是受欢迎的做法.

所有这些用例都受支持, 那么来看代码:

// Define a function to integrate:
auto g = [](std::vector<double> const & x)
{
  constexpr const double A = 1.0 / (M_PI * M_PI * M_PI);
  return A / (1.0 - cos(x[0])*cos(x[1])*cos(x[2]));
};
std::vector<std::pair<double, double>> bounds{{0, M_PI}, {0, M_PI}, {0, M_PI}};
double error_goal = 0.001
naive_monte_carlo<double, decltype(g)> mc(g, bounds, error_goal);

std::future<double> task = mc.integrate();
while (task.wait_for(std::chrono::seconds(1)) != std::future_status::ready)
{
    // The user must decide on a reasonable way to display the progress depending on their environment:
    display_progress(mc.progress(),
                     mc.current_error_estimate(),
                     mc.current_estimate(),
                     mc.estimated_time_to_completion());
    if (some_signal_heard())
    {
        mc.cancel();
        std::cout << "\nCancelling because this is too slow!\n";
    }
}
double y = task.get();

首先, 定义想要积分的函数. 该函数必须接受一个 std::vector<Real> const &, 并返回一个 Real.

Nota bene: Real 必须是可平凡复制 (trivially copyable) 的类型.

接下来定义积分区域. 无穷区域用边界 std::numeric_limits<Real>::infinity() 表示. 调用

naive_monte_carlo<double, decltype(g)> mc(g, bounds, error_goal);

创建一个蒙特卡洛积分器实例. 这里也可以设置线程数, 例如

naive_monte_carlo<double, decltype(g)> mc(g, bounds, error_goal, true, std::thread::hardware_concurrency() - 1);

可能更适合在用户的硬件上运行 (默认会占用全部线程) . 对 integrate() 的调用并不返回积分值, 而是返回一个 std::future<Real>. 这让我们可以通过下面的方式从主线程报告进度

while (task.wait_for(std::chrono::seconds(1)) != std::future_status::ready)
{
    // some reasonable method of displaying progress, based on the requirements of your app.
    display_progress(mc.progress(),
                     mc.current_error_estimate(),
                     mc.current_estimate(),
                     mc.estimated_time_to_completion());
}

文件 example/naive_monte_carlo_example.cpp 给出了 display_progress 的一个实现, 对命令行应用来说相当合理. 另外, 可以在这个循环中调用 mc.cancel() 来停止积分. 如果你不小心传入了非平方可积的被积函数, 进度报告尤其有用——方差无界增长, 进度从某个带噪声的初值随时间降到零. 调用 task.get() 返回当前估计值. 一旦 future 就绪, 就可以通过下面的方式获得积分值

double result = task.get();

此时, 用户可能希望降低误差目标. 这通过下面的方式实现

double new_target_error = 0.0005;
mc.update_target_error(new_target_error);
task = mc.integrate();
y = task.get();

还有一个“高级”参数: 被积函数在边界上是否奇异. 如果被积函数在边界上 不奇异, 则被积函数在闭集 ∏i [ ai, bi ] 上求值. 如果被积函数奇异 (默认) , 则被积函数在闭集 ∏i [ /a(1+ε)/, /b(1-ε)/ ] 上求值. (遗憾的是, 浮点算术中并不存在开集这种东西. ) 什么时候这个差别会要紧? 回想那条箴言: 不要剥高维橙子, 因为剥完就什么都不剩了. 同样的道理适用于此. 距边界 ε 以内的体积占比约为 εd, 其中 d 是维数. 如果维数很大而类型精度很低, 则可能一个正确数字都得不到. 如果被积函数在边界上奇异, 你别无选择, 只能诉诸更高精度的计算. 如果被积函数在边界上不奇异, 则可以通过下面的方式告知积分例程

naive_monte_carlo<double, decltype(g)> mc(g, bounds, error_goal, /*singular = */ false);

这样就不会遇到这个问题. 实践中, 在 16 位浮点下需要约 1,000 维才会触及该问题, 32 位浮点下约需 100,000 维, 而双精度下则需要天文数字的维数.

最后, 可以为该类提供替代的随机数生成器. 默认随机数生成器是标准库的 std::mt19937_64. 不过下面这个例子改用 32 位 Mersenne twister 随机数生成器:

naive_monte_carlo<Real, decltype(g), std::mt19937> mc(g, bounds, (Real) 0.001);
