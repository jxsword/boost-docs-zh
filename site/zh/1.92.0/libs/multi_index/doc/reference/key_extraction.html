键提取器

键提取类被 基于键的索引 用来从 multi_index_container 的元素取得索引键. 若满足以下条件, 则称 CopyConstructible 与 CopyAssignable 类的 KeyFromValue 是从类型 Type 提取键的键提取器:

  1. 定义了类型 KeyFromValue::result_type,
  2. k1(ca) 有定义, 且其返回值可转换为 const KeyFromValue::result_type&,
  3. 若 k2 是 k1 的副本, 则 k1(ca) 与 k2(ca) 是相同的值,
对于每个 k1、k2——其类型为 const KeyFromValue, 以及 ca——其类型为 const Type&.

此外, KeyFromValue 是 可读写 键提取器, 前提是满足以下附加条件:

  1. remove_reference_t<KeyFromValue::result_type> 不带 const 限定.
  2. k1(a) 有定义, 且其返回值可转换为 KeyFromValue::result_type&,
  3. k1(a) 绑定到与 k1(const_cast<const Type&>(a)) 相同的对象,
对于每个 k1——其类型为 const KeyFromValue, 以及 a——其类型为 Type&.

Boost.MultiIndex 提供十二个通用键提取器:

  • identity,
  • member,
  • const_mem_fun (以及三个 变体) ,
  • mem_fun (以及三个 变体) ,
  • global_fun 以及
  • composite_key,
另外, 在符合 C++17 的环境中, 还有一个别名模板 key 允许以极为简洁的语法指明前面的各提取器 (除 identity 之外) .

链式指针

Boost.MultiIndex 提供的键提取器按类型 Type 模板化, 不仅可用于从 Type 类型的对象提取键, 还可用于从 Boost.Ref 提供的引用包装器以及 链式指针——即指向 Type (或 Type 的引用包装器) 者——提取键: 链式指针是任意类型 P, 使得对于对象 p——其类型为 const P——

  • *p 产生 Type& 类型或 boost::reference_wrapper<Type> 类型的对象, 或
  • *p 产生指向 Type 的链式指针,
即链式指针是指针类对象的任意组合, 最终解引用到 Type& 或 boost::reference_wrapper<Type> 的值.

类模板 identity

identity 是一个 Key Extractor, 充当什么也不做的恒等仿函数.

template<typename Type>
struct identity
{
  typedef Type result_type;

  // only provided if const ChainedPtr& is not convertible to const Type&
  template<typename ChainedPtr> Type& operator()(const ChainedPtr& x)const;

  const Type& operator()(const Type& x)const; 
  Type&       operator()(Type& x)const; // only provided if Type is non-const

  // only provided if Type is non-const
  const Type& operator()(const reference_wrapper<const Type>& x)const; 

  // only provided if Type is const
  Type& operator()(
    const reference_wrapper<typename remove_const<Type>::type>& x)const; 

  Type& operator()(const reference_wrapper<Type>& x)const;
};

identity<Type> 是以下概念的模型:

  • 可读写 Key Extractor——提取自 Type,
  • Key Extractor——提取自 reference_wrapper<const Type>,
  • 可读写 Key Extractor——提取自 reference_wrapper<Type>,
  • Key Extractor——来自任意 链式指针——即指向 const Type 者,
  • 可读写的 Key Extractor——来自任意 链式指针——即指向 Type 者.

类模板 member

member 是一个 Key Extractor, 用于访问类的给定成员.

template<class Class,typename Type,Type Class::*PtrToMember>
struct member
{
  typedef Type result_type;

  // only provided if const ChainedPtr& is not convertible to const Class&
  template<typename ChainedPtr> Type& operator()(const ChainedPtr& x)const;

  const Type& operator()(const Class& x)const;
  Type&       operator()(Class& x)const; // only provided if Type is non-const
  const Type& operator()(const reference_wrapper<const Class>& x)const;
  Type&       operator()(const reference_wrapper<Class>& x)const;
};

PtrToMember 模板实参指定指向待提取成员的具体 Type Class::*. member<Class,Type,PtrToMember> 是以下概念的模型:

  • Key Extractor——提取自 Class, 若 Type 不带 const 限定则可读写,
  • Key Extractor——提取自 reference_wrapper<const Class>,
  • Key Extractor——提取自 reference_wrapper<Class>, 若 Type 不带 const 限定则可读写,
  • Key Extractor——来自任意 链式指针——即指向 const Class 者,
  • Key Extractor——来自任意 链式指针——即指向 Class 者, 若 Type 不带 const 限定则可读写.

宏 BOOST_MULTI_INDEX_MEMBER

此宏最初设计为旧编译器的可移植机制——在这些编译器上无法支持 member. 因此在现代环境中已不再需要它, 不过有些用户可能仍偏好它而非普通 member, 因为它提供了稍微更简洁的语法.

类模板 const_mem_fun

const_mem_fun 是一个 Key Extractor, 以调用类的给定 const 成员函数的结果作为键.

template<class Class,typename Type,Type (Class::*PtrToMemberFunction)()const>
struct const_mem_fun
{
  typedef typename remove_reference<Type>::type result_type;

  // only provided if const ChainedPtr& is not convertible to const Class&
  template<typename ChainedPtr> Type operator()(const ChainedPtr& x)const;

  Type operator()(const Class& x)const;
  Type operator()(const reference_wrapper<const Class>& x)const;
  Type operator()(const reference_wrapper<Class>& x)const;
};

PtrToMemberFunction 模板实参指定提取中所用的指向该 const 成员函数的具体 Type (Class::*PtrToMemberFunction)()const. const_mem_fun<Class,Type,PtrToMemberFunction> 是以下概念的模型:

  • Key Extractor——提取自 Class,
  • Key Extractor——提取自 reference_wrapper<const Class>,
  • Key Extractor——提取自 reference_wrapper<Class>,
  • Key Extractor——来自任意 链式指针——即指向 const Class 者,
  • Key Extractor——来自任意 链式指针——即指向 Class 者,
且在所有这些情形下, 若 Type 是指向非 const 限定类型的左值引用, 则它同样是可读写的.

类模板 global_fun

global_fun 是一个 Key Extractor, 基于给定的全局函数或静态成员函数——该函数接受基类型为实参并返回相应的键.

template<class Value,typename Type,Type (*PtrToFunction)(Value)>
struct global_fun
{
  typedef typename remove_reference<Type>::type result_type;

  // Only provided under the following circumstances:
  //   - If Value is a reference to a constant type, only provided
  //     when const ChainedPtr& is not convertible to Value;
  //   - if Value is a reference to a non-const type, only provided
  //     when ChainedPtr& is not convertible to Value;
  //   - else, only provided when const ChainedPtr& is not
  //     convertible to const Value&.
  Type operator()(const ChainedPtr& x)const;
  
  // only provided if Value is a reference type
  Type operator()(Value x)const;

  // only provided if Value is not a reference type
  Type operator()(const Value& x)const;

  // only provided if Value is not a reference type
  Type operator()(const reference_wrapper<const Value>& x)const;

  // only provided if Value is a reference type
  Type operator()(
    const reference_wrapper<
      remove_reference<Value>::type>& x)const;

  // only provided if Value is not a reference type or is
  // a reference to a constant type
  Type operator()(
    const reference_wrapper<
      typename remove_const<
        typename remove_reference<Value>::type>::type>& x)const;
};

PtrToFunction 指定用于提取键的具体函数——该键的类型为 Type, 提取自某个 BaseType. global_fun 支持以下函数签名:

  • Type f(BaseType) (Value 为 BaseType) ,
  • Type f(const BaseType&) (Value 为 const BaseType&) ,
  • Type f(BaseType&) (Value 为 BaseType&) .
global_fun<Type,Value,PtrToFunction> 是以下概念的模型:
  • Key Extractor——提取自 reference_wrapper<BaseType>,
  • Key Extractor——来自任意 链式指针——即指向 BaseType 者.
当 Value 为 BaseType 或 const BaseType& 时, global_fun<Type,Value,PtrToFunction> 也是以下概念的模型:
  • Key Extractor——提取自 BaseType,
  • Key Extractor——提取自 reference_wrapper<const BaseType>,
  • Key Extractor——来自任意 链式指针——即指向 const BaseType 者.
在上述五种情形中, global_fun<Type,Value,PtrToFunction> 同样是可读写的, 若 Type 是指向非 const 限定类型的左值引用.

类模板 composite_key

composite_key 是一个 Key Extractor, 返回若干键提取器的组合值, 其类型在编译期指定. 返回的对象类型为 composite_key_result<composite_key>.

template<typename Value,typename KeyFromValue,typename... KeyFromValues>
struct composite_key
{
  typedef std::tuple<KeyFromValue,KeyFromValues...> key_extractor_tuple;
  typedef Value                                     value_type;
  typedef composite_key_result<composite_key>       result_type;

  // only provided if number of arguments is not greater than the number
  // of elements and each argsi&& is convertible to const KeyFromValuesi&
  template<typename... Args>
  composite_key(Args&&... args);

  composite_key(const key_extractor_tuple& x);
  
  // only provided if number of elements is not greater than
  // the maximum length of a boost::tuple
  composite_key(const boost::tuple<KeyFromValue,KeyFromValues...>& x);

  const key_extractor_tuple& key_extractors()const;
  key_extractor_tuple&       key_extractors()

  // only provided if const ChainedPtr& is not convertible to const value_type&
  template<typename ChainedPtr>
  result_type operator()(const ChainedPtr& x)const;
  
  result_type operator()(const value_type& x)const;
  result_type operator()(const reference_wrapper<const value_type>& x)const;
  result_type operator()(const reference_wrapper<value_type>& x)const;
};

KeyFromValue 与 KeyFromValues... 是组合进复合键的键提取器的类型. 这些类型中的每一个都必须是 Key Extractor——提取自 Value. composite_key 内部保存每个组成键提取器类型的一个对象. composite_key<Value,KeyFromValue,KeyFromValues...> 是以下概念的模型:

  • Key Extractor——提取自 Value,
  • Key Extractor——提取自 reference_wrapper<const Value>,
  • Key Extractor——提取自 reference_wrapper<Value>,
  • Key Extractor——来自任意 链式指针——即指向 const Value 者,
  • Key Extractor——来自任意 链式指针——即指向 Value 者.

composite_key_hash 基于一个基本哈希仿函数集合, 为 composite_key_result 的实例化产生哈希值.

template<typename Hash,typename... Hashes>
struct composite_key_hash
{
  typedef std::tuple<Hash,Hashes...> key_hasher_tuple;

  // only provided if number of arguments is not greater than the number
  // of elements and each argsi&& is convertible to const Hashesi&
  template<typename... Args>
  composite_key_hash(Args&&... args);
  
  composite_key_hash(const key_hasher_tuple& x);

  // only provided if number of elements is not greater than
  // the maximum length of a boost::tuple
  composite_key_hash(const boost::tuple<Hash,Hashes...>& x);
  
  const key_hasher_tuple& key_hash_functions()const;
  key_hasher_tuple&       key_hash_functions();

  template<typename CompositeKey>
  std::size_t operator()(
    const composite_key_result<CompositeKey>& x)const;
  
  template<typename... Values>
  std::size_t operator()(
    const std::tuple<Values...>& x)const;

  template<typename... Values>
  std::size_t operator()(
    const boost::tuple<Values...>& x)const;
};

Hash 与 Hashes... 是 composite_key_hash 所保存的哈希一元函数对象的类型. 这些对象中的每一个都必须是 CopyConstructible 与 CopyAssignable, 并返回 std::size_t 类型的值——其取值范围为 [0, std::numeric_limits<std::size_t>::max())). composite_key_hash 是 CopyConstructible 与 CopyAssignable. 它同样是 DefaultConstructible——若 Hash 与 Hashes... 中的每一个也同样是 DefaultConstructible.

下文中我们使用同一 记号——即为 composite_key_result 而引入者.

类模板 composite_key_result_hash

已弃用. 请改用 boost::hash<CompositeKeyResult>.

boost::hash 针对 composite_key 结果的特化

boost::hash<CompositeKeyResult>——其中 CompositeKeyResult 是 composite_key_result 的实例化——表现为 composite_key_hash 的一个特化, 其中提供的所有哈希仿函数都是 boost::hash 的实例化.

namespace boost{

template<typename CompositeKey>
struct hash<multi_index::composite_key_result<CompositeKey> >
{
  typedef multi_index::composite_key_result<CompositeKey> argument_type;
  typedef std::size_t                                     result_type;

  template<typename CompositeKey>
  std::size_t operator()(
    const multi_index::composite_key_result<CompositeKey>& x)const;
  
  template<typename... Values>
  std::size_t operator()(
    const std::tuple<Values...>& x)const;

  template<typename... Values>
  std::size_t operator()(
    const boost::tuple<Values...>& x)const;
};

} // namespace boost

CompositeKeyResult 必须是 composite_key_result 对某个类型 composite_key<KeyFromValue0,...,KeyFromValuen> 的实例化. 此时 boost::hash<CompositeKeyResult>::operator() 等价于 composite_key_hash<Hash0,...,Hashn>::operator(), 取

Hashi = boost::hash<KeyFromValuei::result_type>, 对每个 i = 0,...,n.

除施加于 Hashi 的 composite_key_hash 要求之外, 这些类型中的每一个都必须是 DefaultConstructible. boost::hash<CompositeKeyResult> 是 DefaultConstructible、CopyConstructible 与 CopyAssignable.

语义——composite_key_result

为 composite_key_result 对象设计相等、比较与哈希操作所依据的理由如下: composite_key_result 被视为一个“虚拟”元组, 其每个元素都是相应基本键提取器的结果. 据此, 任何给定操作都化解为相应逐元素操作的组合. 这一映射保持了所涉基本操作的基本性质; 例如, 若基本谓词自身诱导等价关系, 它便定义了一个真正的等价关系. 我们可以如下形式化地陈述这些事实.

考虑 composite_key_equal_to 的一个实例化, 其类型为 Pred0, ..., Predn, 使得每个 Predi 在某类型 Ti 上诱导等价关系, 并令 CompositeKey 为形如 composite_key<Value,KeyFromValue0,...,KeyFromValuej> 的类型——其中 j <= n——且满足

KeyFromValuei::result_type = Ti, 对每个 i = 0,...,j.
于是, composite_key_equal_to 在类型为 composite_key_result<CompositeKey> 的元素上诱导等价关系; 若两个对象的所有基本键提取器值也都等价, 则这两个对象等价. 另外, 给定一个实例化 composite_key_hash<Hash0,...,Hashj>, 以下类型构成 Compatible Keys——针对 (composite_key_hash, composite_key_equal_to) 与 composite_key_result<CompositeKey>:
tuple<Q0,...,Qj>,
composite_key_result<composite_key<K0,...,Kj> >, 其中 Ki::result_type = Qi 对每个 i = 0,...,j 成立,
前提是每个 Qi 要么是 Ti, 要么是 Compatible Key——其对象为 (Hashi, Predi).

至于比较, 考虑 composite_key_compare 的一个实例化, 其类型为 Compare0, ..., Comparen, 使得每个 Comparei 在类型 Ti 上诱导严格弱序. 于是, 对于按上述方式定义的 CompositeKey 类型, composite_key_compare 在 composite_key_result<CompositeKey> 类型的元素上诱导严格弱序, 且所诱导的顺序是字典序. 此外, 以下类型构成 Compatible Keys——针对 composite_key_compare 与 composite_key_result<CompositeKey>:

tuple<Q0,...,Qk>、k <= n,
composite_key_result<composite_key<K0,...,Kk> >, 其中 Ki::result_type = Qi 对每个 i = 0,...,k 成立,
前提是
  • 对 i = 0,...,min(j,k)-1 而言, Qi 要么是 Ti, 要么 不粗于 Ti (Qi 是 Compatible Key——其对象为 Comparei——且 Ti 中不存在两个不同元素等价于 Qi 的单个元素) ;
  • Qm (连同 m = min(j,k)) 要么是 Tm, 要么是 Compatible Key——其对象为 Comparem.
. 此时, 比较仅按字典序施加于前 1+min(j,k) 个元素.

composite_key_result 的相等与比较运算符也成立类似的性质. 但请注意, 相等只在长度相同的对象之间定义, 而比较则取所考虑操作数的最小长度. 因此, x==y 诱导的等价类是关联到 !(x<y)&&!(y<x) 的等价类的子集.

别名模板 key

在符合 C++17 的环境中, key 为 Boost.MultiIndex 预定义键提取器的指定提供了非常简洁的语法. 传递给 key 的模板实参个数必须大于零. key<Key> 解析为:

  • member<Class,Type,Key>, 若 Key 的类型为 Type Class::*,
  • const_mem_fun<Class,Type,Key>, 若 Key 的类型为 Type (Class::*)()const (带或不带 noexcept 说明) ,
  • cv_mem_fun<Class,Type,Key>, 若 Key 的类型为 Type (Class::*)()const volatile (带或不带 noexcept 说明) ,
  • cref_mem_fun<Class,Type,Key>, 若 Key 的类型为 Type (Class::*)()const& (带或不带 noexcept 说明) ,
  • cvref_mem_fun<Class,Type,Key>, 若 Key 的类型为 Type (Class::*)()const volatile& (带或不带 noexcept 说明) ,
  • mem_fun<Class,Type,Key>, 若 Key 的类型为 Type (Class::*)() (带或不带 noexcept 说明) ,
  • volatile_mem_fun<Class,Type,Key>, 若 Key 的类型为 Type (Class::*)()volatile (带或不带 noexcept 说明) ,
  • ref_mem_fun<Class,Type,Key>, 若 Key 的类型为 Type (Class::*)()& (带或不带 noexcept 说明) ,
  • vref_mem_fun<Class,Type,Key>, 若 Key 的类型为 Type (Class::*)()volatile& (带或不带 noexcept 说明) ,
  • global_fun<Value,Type,Key>, 若 Key 的类型为 Type (*)(Value) (带或不带 noexcept 说明) ,
, 否则引发未定义行为. 传入两个或更多实参时, key<Key0,...,Keyn> 解析为 composite_key<Value,KeyFromValue0,...,KeyFromValuen>, 其中:
  • KeyFromValuei = key<Keyi>, 对每个 i = 0,...,n,
  • Value = std::decay_t<Value0> ⊗ std::decay_t<Value1> ⊗ ··· ⊗ std::decay_t<Valuen>,
, 其中 Valuei 对应于 Class 或 Value——即与 KeyFromValuei 相关联的类型; 且 T ⊗ Q 是最小泛类型——即 T 与 Q 之间的, 定义为 T, 若 std::is_convertible_v<const T&,const Q&>, Q 若 std::is_convertible_v<const Q&,const T&>, 否则未定义.
