索引概念

multi_index_container 的实例化包含一个或多个在编译期指定的索引. 每个索引以确定的方式提供对所含元素的读写访问. 例如, 有序索引 为元素提供类集合的接口, 而 序列索引 则模仿 std::list 的功能.

索引不是孤立的对象, 因此无法单独构造. 它们被嵌入到 multi_index_container 中, 具体由一个 索引说明符 所指定. 索引类实现本身的名称从不直接暴露给用户, 用户只能访问相应的索引说明符.

元素的插入与擦除总是通过 multi_index_container 的某个索引的相应接口执行; 不过这些操作也会影响所有其他索引: 例如, 通过某个索引进行插入可能失败, 因为存在另一个索引为保持其不变量 (如元素的唯一性) 而禁止该操作. 这种情况非但不是障碍, 反而造就了 Boost.MultiIndex 的强大能力: 基于手工组合标准容器的等价构造必须额外编写相当数量的代码, 才能在全局保持每个容器的不变量的同时保证它们彼此同步. 各索引联合执行的全局操作可以归结为六种原语:

  • 拷贝,
  • 插入一个元素,
  • 带提示插入, 即建议一个已存在的元素以提高操作的效率,
  • 删除一个元素,
  • 替换元素的值, 这可能触发该元素在一个或多个索引中的重排, 或导致替换被禁止,
  • 修改一个元素, 以及随后各索引对其的重排/禁止.
最后两种原语值得进一步说明: 为了保证与各索引相关联的不变量 (例如某种确定的排序) , multi_index_container 的元素是不可变的. 为了克服这一限制, 各索引提供了替换与修改成员函数, 允许以受控的方式变更元素. 元素的不可变性不会显著影响有序索引与哈希索引的接口, 因为它们分别基于关联容器与无序关联容器的接口, 而这些容器的元素同样不可变; 但对于序列索引与随机访问索引而言可能令人意外, 它们的设计基于 std::list 所提供的功能.

这些全局操作并不直接暴露给用户, 而是由各索引酌情包装 (例如, 有序索引提供一套类集合的插入成员函数, 而序列索引与随机访问索引则提供 push_back 与 push_front 操作) . Boost.MultiIndex 对索引的接口没有施加特殊条件, 不过每个提供的索引都在本库概念框架允许的范围内尽可能满足 C++ 对标准容器的要求.

复杂度签名

索引接口的一些成员函数由上述列表中的全局原语实现. 因此这些操作的复杂度取决于给定 multi_index_container 的所有索引, 而不仅仅是当前使用的索引.

为建立复杂度估计, 每个索引以其 复杂度签名 刻画, 它由下列关于元素个数的关联函数组成:

  • c(n): 拷贝,
  • i(n): 插入,
  • h(n): 带提示插入,
  • d(n): 删除,
  • r(n): 替换,
  • m(n): 修改.

每个函数给出该索引对相应全局原语的贡献的复杂度估计. 考虑 multi_index_container 的一个实例化, 它有 N 个索引, 标记为 0,…,N-1, 其复杂度签名为 (ci,ii,hi,di,ri,mi); 向这样的容器插入一个元素的复杂度即为 O(i0(n)+···+iN-1(n)), 其中 n 是元素个数. 为简化记号, 我们采用以下定义:
  • C(n)=c0(n)+···+cN-1(n),
  • I(n)=i0(n)+···+iN-1(n),
  • H(n)=h0(n)+···+hN-1(n),
  • D(n)=d0(n)+···+dN-1(n),
  • R(n)=r0(n)+···+rN-1(n),
  • M(n)=m0(n)+···+mN-1(n).
例如, 考虑一个 multi_index_container, 它有两个有序索引, 故 i(n)=log(n), 另有一个序列索引, 其 i(n)=1 (常量时间插入) . 向该 multi_index_container 插入元素的复杂度即为
O(I(n))=O(2*log(n)+1)=O(log(n)).

索引指定

索引说明符作为实例化参数传递给 multi_index_container, 并提供纳入相应索引所需的信息. Boost.MultiIndex 的未来版本可能允许指定用户自定义索引. 在此之前, 索引说明符的要求仍由实现定义. 目前, Boost.MultiIndex 提供以下索引说明符

  • ordered_unique 与 ordered_non_unique 用于 有序索引,
  • ranked_unique 与 ranked_non_unique 用于 排名索引,
  • hashed_unique 与 hashed_non_unique 用于 哈希索引,
  • sequenced 用于 序列索引,
  • 以及 random_access 用于 随机访问索引.

头文件 "boost/multi_index/indexed_by.hpp" 概要

namespace boost{

namespace multi_index{

template<typename T,typename... Ts>
struct indexed_by;

} // namespace boost::multi_index 

} // namespace boost

类模板 indexed_by

indexed_by 用于指定一个编译期索引列表, 充当 IndexSpecifierList——即 multi_index_container 的列表实参.

template<typename T,typename... Ts>
struct indexed_by;

indexed_list 的每个用户提供的元素都必须是索引说明符. 必须至少提供一个元素.

标签

标签只是充当 multi_index_container 的各索引的助记类型, 例如成员函数 get. 每个索引可以不关联、关联一个或多个标签. 标签赋给给定索引的方式取决于具体的索引说明符. 不过为方便起见, Boost.MultiIndex 的所有索引都支持通过类模板 tag 打标签.

头文件 "boost/multi_index/tag.hpp" 概要

namespace boost{

namespace multi_index{

template<typename... Ts>
struct tag;

} // namespace boost::multi_index 

} // namespace boost

类模板 tag

tag 是一个类型列表构造, 用于指定在实例化时赋给某个索引的编译期标签序列.

template<typename... Ts>
struct tag;

tag 的元素可以是任意类型, 但用户应提供具有助记名称的类. 不允许重复元素.

Boost.MultiIndex 提供的索引

基于键的索引

此类型的索引围绕从元素取得的 键 组织, 如 键提取参考 所述.

  • 有序索引 按键对元素排序并提供快速查找能力.
  • 排名索引 是有序索引的变体, 提供基于 排名 的额外操作, 排名即元素在序列中的数值位置.
  • 哈希索引 通过散列技术提供高效访问.

其他类型

  • 序列索引 允许像双向链表那样排列元素.
  • 随机访问索引 提供常量时间的按位置访问以及元素的自由排序.

索引视图

非基于键的索引的重排设施使用以下概念. 给定一个索引 i, 类型为 Index, 它的 视图——关于 i——是任意区间 [first,last), 其中 first 与 last 是满足以下条件的输入迭代器:

  1. Iterator 的关联值类型可转换为 const Index::value_type&
  2. 且 i 的每个元素在 [first,last) 中恰好出现一次.
注意, 视图引用的是 i 的实际元素, 而非其副本. 此外, 视图被称为 自由 的条件是: 其遍历顺序不受 i. 自由视图的例子有:
  • [c.begin(),c.end()), 其中 c 是保存引用包装器的任意容器 (来自 Boost.Ref) , 这些包装器指向 i 的元素, 且对每个元素恰含一个引用.
  • [i'.begin(),i'.end()), 其中 i' 是同一 multi_index_container——即 i 所属的那个——中除 i 本身之外的任意索引.
  • 上述范围的任意排列, 例如 [c.rbegin(),c.rend()), 或借助 Boost.Iterator 的 permutation_iterator 由前者得到的范围.
