索引说明符 hashed_unique 与 hashed_non_unique

这些 索引说明符 分别允许插入 哈希索引——分别对应不允许与允许重复元素的情形. hashed_unique 与 hashed_non_unique 的语法一致, 因此我们将它们放在一起描述. hashed_unique 与 hashed_non_unique 依据是否为索引提供标签列表而有两种不同的实例化形式:

template<
  typename KeyFromValue,
  typename Hash=boost::hash<KeyFromValue::result_type>,
  typename Pred=std::equal_to<KeyFromValue::result_type>
>
struct (hashed_unique | hashed_non_unique);

template<
  typename TagList,
  typename KeyFromValue,
  typename Hash=boost::hash<KeyFromValue::result_type>,
  typename Pred=std::equal_to<KeyFromValue::result_type>
>
struct (hashed_unique | hashed_non_unique);

若提供, TagList 必须是类模板 tag 的实例化. 模板参数由相应的索引实现使用, 有关其可接受类型值的进一步说明, 请参阅 哈希索引 参考一节.

哈希索引

哈希索引通过散列技术提供对 multi_index_container 元素的快速检索. 哈希索引依据给定的 Key Extractor——它从 multi_index_container 的元素中提取键——以及为键返回哈希值的 Hash 函数对象和一个二元谓词 Pred (该谓词在 Key 的值上充当等价关系) 而具体化.

哈希索引有两种变体: 唯一, 不允许出现重复元素 (相对于其关联的等价谓词) ; 以及 非唯一, 接受此类重复元素. 这两种变体的接口相同, 因此一并加以说明, 凡有细微差异之处均会明确指出.

除特别注明或相应接口不存在之处外, 哈希索引 (无论唯一还是非唯一) 均满足 C++ 标准在 [unord.req] 处对无序关联容器的要求 (分别支持唯一键与等价键) . 迭代器 (包括指向索引末端的迭代器) 以及指向元素的指针和引用, 在关联容器的生存期内保持有效 (交换时可能改变) , 或直到被引用元素被擦除或提取为止; 指向已提取元素的指针和引用在该元素重新插入后重新变为有效, 但迭代器则不然. 某些情况下, 所提供的异常安全性保证实际上强于标准的要求. 我们只对不完全符合标准要求或标准未作规定的类型和操作提供描述.

复杂度签名

此处以及哈希索引各操作的说明中, 我们采用 复杂度签名一节 所概述的方案. 哈希索引的复杂度签名为:

  • 拷贝: c(n)=n*log(n),
  • 插入: 平均情形 i(n)=1 (摊还常量) , 最坏情形 i(n)=ndist,
  • 带提示插入: 平均情形 h(n)=1 (摊还常量) , 最坏情形 h(n)=ndist,
  • 删除: d(n)=1 (常量) ,
  • 替换:
    • 若新元素的键与原键等价, 为 r(n)=1 (常量) ,
    • 否则, 平均情形 r(n)=1 (常量) , 最坏情形 r(n)=ndist,
  • 修改: 平均情形 m(n)=1 (常量) , 最坏情形 m(n)=ndist,
, 其中 ndist 为总元素数 n 中非等价元素的个数.

实例化类型

哈希索引在 multi_index_container 内部实例化, 并通过 indexed_by 配合 索引说明符 hashed_unique 与 hashed_non_unique 加以指定. 实例化依赖于以下类型:

  • Value 来自 multi_index_container,
  • Allocator 来自 multi_index_container,
  • TagList 来自索引说明符 (若提供; 否则默认为 tag<>) ,
  • KeyFromValue 来自索引说明符,
  • Hash 来自索引说明符,
  • Pred 来自索引说明符.
TagList 必须是 tag 的实例化. 类型 KeyFromValue 决定从 Value 提取键的机制, 必须是 Key Extractor 的模型——提取自 Value. Hash 是 CopyConstructible 的一元函数对象, 接受单个 KeyFromValue::result_type 类型实参并返回 std::size_t 类型的值, 取值范围为 [0, std::numeric_limits<std::size_t>::max()). Pred 是 CopyConstructible 的二元谓词, 在 KeyFromValue::result_type 的元素上诱导等价关系. 要求 Hash 对象对在 Pred 下等价的键返回相同的值.

这些类型是前向迭代器. 它们仅依赖于 node_type、索引在 multi_index_container 中的位置, 以及索引是否唯一 (这意味着, 例如从唯一索引转移到非唯一索引的元素的迭代器将会失效) .

构造函数、拷贝与赋值

如 索引概念一节 所述, 索引没有公有的构造函数或析构函数. 但另一方面, 赋值是提供的. 构造后, max_load_factor() 为 1.0.

修改器

template<typename... Args>

要求: value_type 满足 EmplaceConstructible 要求, 即 multi_index_container 可由 args 构造.

  • 该索引为非唯一, 或不存在键等价的其他元素,
  • 且 multi_index_container 的所有其他索引均允许插入.

复杂度: O(I(n)).
异常安全性: 强保证, 但即使操作失败也可能发生重哈希.

复杂度: O(M(n)).
异常安全性: 强保证, 但若 mod 或 back 抛出异常, 或 back(e) 未能正确恢复该元素, 或在调用 back(e) 之后某个用户提供的操作抛出异常, 则被修改的元素被擦除. 若 back 在处理代码中抛出异常——该处理代码于其他某个用户提供的操作抛出异常后执行——则重新抛出的是 back 所生成的异常.

查找

哈希索引提供 [unord.req] 所要求的完整查找功能, 即 find、count 与 equal_range. 此外, 这些成员函数被模板化以允许非标准参数, 从而扩展了允许的查找操作类型. 调用查找成员函数时可接受的参数类型由以下概念定义.

考虑一个二元组 (Hash, Pred), 其中 Hash 是定义在 Key 类型值上的哈希仿函数, Pred 是在 Key 上诱导等价关系的二元谓词, 并附加约束: 等价的键必须具有相同的哈希值. 若下述条件成立, 则称类型三元组 (CompatibleKey, CompatibleHash, CompatiblePred) 构成 兼容扩展, 其对象为 (Hash, Pred):

  1. CompatibleHash 是定义在 CompatibleKey 类型值上的哈希仿函数,
  2. CompatiblePred 是定义在 (Key, CompatibleKey) 上的二元谓词,
  3. CompatiblePred 是定义在 (CompatibleKey, Key) 上的二元谓词,
  4. 若 c_eq(ck,k1) 则 c_eq(k1,ck),
  5. 若 c_eq(ck,k1) 且 eq(k1,k2) 则 c_eq(ck,k2),
  6. 若 c_eq(ck,k1) 且 c_eq(ck,k2) 则 eq(k1,k2),
  7. 若 c_eq(ck,k1) 则 c_hash(ck)==hash(k1),
对于每个 c_hash——其类型为 CompatibleHash; 对于 c_eq——其类型为 CompatiblePred; 对于 hash——其类型为 Hash; 对于 eq——其类型为 Pred; 对于 ck——其类型为 CompatibleKey——以及 k1; 对于 k2——其类型为 Key.

此外, 类型 CompatibleKey 称为 兼容键, 针对 (Hash, Pred) 而言, 条件是 (CompatibleKey, Hash, Pred) 构成 (Hash, Pred) 的兼容扩展. 这意味着 Hash 与 Pred 接受 CompatibleKey 类型的参数, 这通常意味着它们为其对应的 operator() 成员函数提供了多个重载.

在兼容扩展或兼容键的语境下, 表达式“等价键”取其显而易见的含义.

比较

template<implementation defined>
bool operator==(const index class name& x,const index class name& y);
要求: x.key_extractor()、x.hash_function() 与 x.key_eq() 的行为与 y 中相应对象相同. 对于任意两个元素 e1、e2——位于 x 或 y 中——若 e1==e2 则其键等价.
返回: 返回 true, 当且仅当 x 与 y 大小相同, 且对每个键 k——出现在 x 中——区间 x.equal_range(k)——以 == 运算符衡量, 该运算符来自 value_type——在元素任意重排下与 y.equal_range(k) 相等.
复杂度: 设 k1,…,km 为 x 中出现的不同键:
  • 若对每个 ki, x.equal_range(ki) 的排列顺序与 y.equal_range(ki) 相同, 则平均情形为 O(x.size()), 最坏情形为 O(x.size()2).
  • 否则, 平均情形为 O(Σ(x.count(ki)2)), 最坏情形为 O(x.size()2).
(对于唯一索引, 上述公式化为平均情形 O(x.size())、最坏情形 O(x.size()2). )

序列化

索引本身无法被序列化, 只能作为其嵌入的 multi_index_container 的一部分被序列化. 在描述哈希索引相对于其嵌入容器序列化的附加前置条件与保证时, 我们使用 multi_index_container 序列化一节 中定义的概念.

操作: 将 multi_index_container m 保存至输出存档 (XML archive) ar.
要求: 除容器所施加的要求外无其他要求.
操作: 载入 multi_index_container m'——来自输入存档 (XML archive) ar.
要求: 除一般要求外, 二元谓词 value_eq(m'.get<i>()) 必须与 value_eq(m.get<i>()) 序列化兼容, 其中 value_eq(c)(x,y) 定义为 c.key_eq()(c.key_extractor()(x),c.key_extractor()(y)), i 是哈希索引在容器中的位置.
后置条件: 载入成功后, 区间 [begin(), end()) 包含 [m.get<i>().begin(), m.get<i>().end()) 中每个元素的恢复副本, 但顺序不一定相同.
操作: 将 iterator 或 const_iterator it 保存至输出存档 (XML archive) ar.
要求: it 是该索引的有效迭代器. 关联的 multi_index_container 之前已被保存.
操作: 载入 iterator 或 const_iterator it'——来自输入存档 (XML archive) ar.
后置条件: 载入成功后, 若 it 原先可解引用, 则 *it' 是 *it 的恢复副本, 否则为 it'==end().
注释: 允许 it 为 const_iterator 而恢复后的 it' 为 iterator, 或反之.
操作: 将 local_iterator 或 const_local_iterator it 保存至输出存档 (XML archive) ar.
要求: it 是该索引的有效局部迭代器. 关联的 multi_index_container 之前已被保存.
操作: 载入 local_iterator 或 const_local_iterator it'——来自输入存档 (XML archive) ar.
后置条件: 载入成功后, 若 it 原先可解引用, 则 *it' 是 *it 的恢复副本; 若 it 曾为 m.get<i>().end(n)——对应某个 n——则 it'==m'.get<i>().end(n) (其中 m 是原 multi_index_container, m' 是其恢复副本, i 是该索引的序号) .
注释: 允许 it 为 const_local_iterator 而恢复后的 it' 为 local_iterator, 或反之.
