Boost 1.92 发布

  • 花式指针支持已扩展: multi_index_container 的迭代器现在通过分配器的指针类型存储对元素的引用. 特别是, 这意味着迭代器现在可以借助 Boost.Interprocess 分配器放入共享内存.
  • 修复了哈希索引在超大容器尺寸下重哈希时的性能问题 (PR#94). 由 Daniel Král 贡献.

Boost 1.91 发布

  • 破坏性变更: 库接受或提供的所有类型列表 (indexed_by、tag、嵌套 typedef index_specifier_type_list、index_type_list、iterator_type_list 与 const_iterator_type_list) 不再基于 Boost.MPL, 而现在是 Boost.Mp11 列表. 因此, Boost.MultiIndex 不再依赖 Boost.MPL. 预计大多数用户代码不会受此变更影响, 不过可以通过全局定义宏 BOOST_MULTI_INDEX_ENABLE_MPL_SUPPORT 来恢复先前的行为. 对 Boost.MPL 的遗留支持将来可能最终被弃用并移除.
  • 破坏性变更: composite_key 及其关联的类模板 (composite_key_equal_to、composite_key_compare、composite_key_hash) 已改为可变参数形式 (此前模板实参的最大数目受 BOOST_MULTI_INDEX_LIMIT_COMPOSITE_KEY_SIZE 限制). 此变更对用户应当是透明的, 例外是 composite_key::key_extractors 现在返回 std::tuple 而不是 boost::tuple (其余受影响的类模板亦然).
  • 移除了为支持 C++11 之前编译器而设的内部变通与回退实现.

Boost 1.84 发布

  • 修复了在不支持 ADL 的旧编译器上与序列化相关的编译期缺陷 (issue #70).

Boost 1.83 发布

  • 更新了非唯一有序索引中的范围 insert, 以保持等价元素的插入顺序 (issue #68).
  • 序列化现在使用 std::size_t 而不是 unsigned long 来保存与载入 multi_index_container 的大小 (在 LLP64 数据模型中 unsigned long 小于 std::size_t). 为反映这一变更, multi_index_container 序列化的 类版本 已从 3 升至 4.

Boost 1.82 发布

  • 序列化现在使用 unsigned long 而不是 collection_size_type, 为反映这一变更, multi_index_container 序列化的 类版本 已从 2 升至 3. 对于对 collection_size_type 值作特殊处理的自定义档案类型, 读取旧档案可能失败: 若是这种情况, 请全局定义宏 BOOST_MULTI_INDEX_ENABLE_SERIALIZATION_COMPATIBILITY_V2 以确保读取操作的向后兼容.
  • 维护性工作.

Boost 1.78 发布

  • 为基于键的索引添加了 contains (issue #35).
  • 为基于键的索引添加了 merge 操作. 其功能在多个方面超越了 (无序) 关联容器的标准规范, 最显著的包括:
    • 源索引可以是任何类型, 包括非基于键的索引.
    • 提供部分合并: 例如, x.merge(y,first,last) 只合并 y 中位于 [first, last) 内的元素.
  • 序列索引与随机访问索引的 splice 先前版本是破坏性的, 即元素被复制插入到目标后从源中擦除. 现在, splice 基于节点转移, 与基于键的索引中的 merge 十分相似, 并同样扩展为可接受任何类型的源索引: 实际上, splice 可视为 merge 在基于键的索引中所提供同一功能的前端. 出于向后兼容的原因, 当源容器与目标容器的分配器不相等时, splice 的破坏性行为予以保留.
  • 已记录如下事实: 索引迭代器类型只取决于 node_type 以及该索引在其 multi_index_container 中的位置 (哈希索引除外, 其唯一性/非唯一性也是依赖项). 这对由 merge 或 splice 转移的元素的迭代器有效性有影响. 该性质是 C++ 标准邮件列表中所称 SCARY 迭代器 的一个变种. 目前 (2021 年 8 月) 标准容器并不强制要求 SCARY 性.
  • 迭代器 SCARY 性现在也在 安全模式 下得到保持.

Boost 1.73 发布

  • multi_index_container 现在满足 AllocatorAware 要求.
  • 内部 KeyFromValue、Compare、Hash 与 Pred 对象的交换, 现在会在合适的 swap 函数——std::swap 或 ADL 候选——之间作出选择, 符合 [swappable.requirements] 中的标准规范 (issue #29).
  • 提供了一些内部复制构造函数与赋值运算符, 其默认隐式定义自 C++11 起已被弃用 ([depr.impldec]), 一些编译器曾对此发出警告.
  • 维护性工作.

Boost 1.71 发布

Boost 1.70 发布

Boost 1.66 发布

  • 使 modify 与 modify_key 更加稳健: 若修改器抛出异常或回滚函子未能正确恢复该元素, 被修改的元素将被擦除 (完整讨论见 ticket #12542). 这在技术上属于向后不兼容; 例如, 以下代码:
    c.modify(c.begin(),[](auto&){throw 0;});
    在 Boost 先前的版本中会保持容器 c 原样不动, 而现在 c.begin() 会被擦除. 感谢 Jon Kalb 提出此问题.
  • 维护性修复.

Boost 1.58 发布

  • 在查找操作涉及生成 key_type 临时值的情形下, 其效率已得到提升. 例如考虑以下代码:
    typedef multi_index_container<
  std::string,
  indexed_by<
    ordered_unique<identity<std::string> >
  >
> multi_t;
...
multi_t m=...;
m.find("boost"); // passed a const char*, not a std::string
    在库先前的版本中, find 操作会生成多个 std::string 临时对象 (每次内部比较生成一个). 在足够先进的编译器上, 现在已避免这一点, 只创建一个临时对象.
  • 维护性修复.

Boost 1.56 发布

  • 哈希索引的 erase(iterator) 成员函数在低负载条件下曾因必须返回指向下一元素的迭代器而性能不佳 (见 ticket #4264). 根据 LWG issue #579 的决议, 在保持 erase 接口的前提下修复了此问题, 代价是每个元素多用一个机器字的内存. 实际上, 针对无序关联容器的 C++ 复杂度要求已为哈希索引作出改进, 即
    • 删除给定元素无条件地为常量时间,
    • 最坏情形性能不是 O(n) 而是 O(ndist), 其中 ndist 是索引中非等价元素的数目.
    由于哈希索引依赖新的数据结构, 其迭代器与局部迭代器的内部表示已改变, 这影响序列化: 其对应的序列化 类版本 已从 0 升至 1. 涉及哈希索引 (局部) 迭代器的旧档案可由 Boost 1.56 版的 Boost.MultiIndex 载入, 但反之不行.
  • 哈希索引现在提供 reserve.
  • 哈希索引现在可以按照 [unord.req] 中 (适当调整后的) C++ 标准规范进行相等与不等比较.
  • Boost.MultiIndex 的公开接口在适当之处提供了 noexcept 规范 (针对合规的编译器).
  • 改进了向 multi_index_container 插入失败时的性能.
  • 移除了大量为支持 MSVC++ 7.0 及更早版本而设的内部代码. 没有这些遗留代码后, 编译时间可能略快.
  • 修复了经由解引用为右值的迭代器插入时的缺陷 (ticket #9665).
  • 使 Boost.MultiIndex 与 BOOST_BIND_NO_PLACEHOLDERS 兼容 (ticket #9798).
  • 维护性修复.

Boost 1.55 发布

  • Boost.MultiIndex 已提升到与 C++11 更高的合规水平.
    • multi_index_container 现在可以高效移动.
    • 支持初始化值列表.
    • 提供 emplace 函数.
    • 支持不可复制的元素 (如 std::unique_ptr<T>). 这包括插入区间 [first, last)——其迭代器指向可转换为元素类型的类型: 此过程中不发生复制构造.
    • 随机访问索引提供 shrink_to_fit().
    关于 C++11 之前编译器的限制, 参见编译器特定事项一节.
  • 以下类已弃用:
    • member_offset,
    • const_mem_fun_explicit,
    • mem_fun_explicit,
    • composite_key_result_equal_to,
    • composite_key_result_less,
    • composite_key_result_greater,
    • composite_key_result_hash.
  • 维护性修复.

Boost 1.36 发布

  • 在库先前的版本中, 哈希索引的 update 成员函数 可能在更新时改变元素的位置, 即使关联的键并未因更新而改变. 这是合法但可能出乎意料的行为. 这些函数已被重写, 以提供附加保证: 在哈希索引中, 键未修改的元素不会改变位置——正如有序索引一贯的情形. 这些保证现在已记录在参考文档中.
  • 添加了构造函数 multi_index_container::multi_index_container(const allocator_type&), 以模仿 STL 序列容器中的等价接口.
  • 维护性修复.

Boost 1.35 发布

  • 新增 global_fun 预定义键提取器.
  • 添加了 iterator_to 设施.
  • 纳入了对非标准分配器的 支持——例如 Boost.Interprocess 的那些分配器——这使 multi_index_container 可置于共享内存中.
  • 新增带回滚的 modify 与 modify_key 版本, 如 教程 中所述.
  • 各索引提供新的 cbegin、cend 以及 (在适用时) crbegin 与 crend 成员函数, 符合 C++ 标准下一版修订的最新草案.
  • 有序索引中的提示插入完全遵循 C++ 标准库 Defect Report 233 的决议. 插入点必须总是尽可能靠近提示这一新要求, 引入了与 Boost.MultiIndex 先前版本不同的行为, 可能导致向后兼容问题; 但无论如何, 这些兼容性问题在真实场景中出现的可能性极低.
  • 序列索引与随机访问索引现在遵循 C++ 标准对序列容器中 assign(f,l) 与 insert(p,f,l) 操作的要求 (23.1.1/9): 若 f 与 l 是同一整型类型, 则避免使用这些成员函数基于迭代器的重载:
    typedef multi_index_container<
  int,indexed_by<sequenced<> >
> sequenced_container;

std::list<int>      l(...);
sequenced_container c;

// iterator-based overload of assign
c.assign(l.begin(),l.end()); 

// The following is equivalent to
//   c.assign(
//      static_cast<sequenced_container::size_type>(10),100);
// that is, "10" and "100" are not taken to be iterators as
// in the previous expression.
c.assign(10,100);
  • 有序索引 range 与 equal_range 的性能已得到改进.
  • 维护性修复.

Boost 1.34 发布

  • 添加了 随机访问索引.
  • 非基于键的索引提供了新的 重排设施, 允许与外部修改算法交互.
  • 针对给定类型 T 实例化的所有预定义 Boost.MultiIndex 键提取器, 都能处理派生自或可转换为 T 的类型对象 (以及指向它们的 链式指针). 此前, 只接受确切指定类型的对象 (连同 reference_wrapper 实例与指向它们的链式指针).
  • composite_key_compare 及相关类接受不在元组中的操作数, 如同其被传入长度为 1 的元组; 这使用户在涉及组合键的查找操作中只提供第一个键时, 可以省略元组包裹.
  • 有序索引的核心算法已优化, 插入时间估计减少约 5%.
  • 在多数平台上, 有序索引节点头的大小已借助一种众所周知的 优化技术 缩减 25%.
  • 教程已重构, 并新增了示例.
  • 维护性修复.

Boost 1.33.1 发布

  • 对于有序索引与哈希索引, erase(it) 与 erase(first,last) 现在返回指向被删元素之后元素的迭代器 (此前不返回任何内容), 依据是 C++ 标准库 Defect Report 130 及 TR1 问题列表 的 issue 6.19.
  • Boost.MultiIndex 提供大多数 STL 实现所给出的关于多线程代码的通常保证:
    1. 对不同容器的并发访问是安全的.
    2. 对同一容器的并发只读访问是安全的.
    在库先前的版本中, 若设置了 安全模式, 后一保证未得到妥善维持. 此问题现已修复.
  • 维护性修复.

Boost 1.33 发布

  • 添加了 哈希索引, 其接口基于 C++ 标准库技术报告 (TR1) 对无序关联容器的规范.
  • 为 Boost.Serialization 添加了 序列化支持.
  • multi_index_container 的销毁与 clear 成员函数现在执行得更快.
  • 内部改动旨在缩短编译器生成的符号名长度; 相对于 Boost 1.32 发布, 最多可缩短 50%. 这使错误信息更短更易读, 对符号名长度有严格限制的编译器也有益处. 此外, 还增加了关于进一步缩短符号名长度的一节.
  • 重构了文档的某些部分, 新增示例.
  • 维护性修复.
