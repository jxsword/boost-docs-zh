引言

STL 关联容器有键的概念, 尽管形式尚属初步. 此类容器的键由嵌套类型 key_type 标识; 对 std::set 与 std::multiset 而言, key_type 与 value_type 相同, 即键就是元素本身. std::map 与 std::multimap 管理类型为 std::pair<const Key,T> 的元素, 其中第一个成员是键. 无论哪种情形, 从给定元素取得键的过程都被隐式固定, 用户无法定制.

像 STL 关联容器所执行的那种固定键提取机制, 在 Boost.MultiIndex 的语境下不能很好地伸缩——其中多个索引共享同一 value_type 定义, 却可能具有完全不同的查找语义. 因此, Boost.MultiIndex 把 Key Extractor 概念形式化, 使其在基于键索引的定义中明确且可控.

直观地说, 键提取器是一个函数对象, 接受指向元素的引用并返回其关联的键. 形式化概念还对这一过程的稳定性施加了若干合理约束, 即假定提取器在传入相同元素时返回相同的键: 这与如下非正式理解一致——键实际上是元素的某个“部分”, 不依赖外部数据.

读/写键提取器

键提取器被称为 读/写 的, 如果它在传入非常量元素时返回键的非常量引用; 否则称为 只读 的. Boost.MultiIndex 要求在使用基于键索引的 modify_key 成员函数时, 键提取器是读/写的. 在所有其他情形下, 只读提取器即可满足要求. Boost.MultiIndex 键提取器的高级特性 一节展示了预定义键提取器为读/写的典型情形.

预定义键提取器

identity

identity 键提取器返回整个基础对象作为关联的键:

#include <boost/multi_index_container.hpp>
#include <boost/multi_index/ordered_index.hpp>
#include <boost/multi_index/identity.hpp>

multi_index_container<
  int,
  indexed_by<
    ordered_unique<
      identity<int> // the key is the entire element
    >
  >
> cont;

member

member 键提取器返回基础对象指定数据字段的引用. 例如, 在我们熟悉的员工容器的以下版本中:

#include <boost/multi_index_container.hpp>
#include <boost/multi_index/ordered_index.hpp>
#include <boost/multi_index/identity.hpp>
#include <boost/multi_index/member.hpp>

typedef multi_index_container<
  employee,
  indexed_by<
    ordered_unique<identity<employee> >,
    ordered_non_unique<member<employee,std::string,&employee::name> >,
    ordered_unique<member<employee,int,&employee::ssnumber> >
  >
> employee_set;

第二与第三个索引使用 member 提取器, 分别作用于 employee::name 与 employee::ssnumber. member 实例化的规定简单却略显刻意:

member<(base type),(key type),(pointer to member)>

乍看之下, 第一与第二个参数似乎是多余的, 因为基础对象与关联数据字段的类型已隐含在成员指针实参中: 遗憾的是, 以现有的 C++ 机制无法提取这一信息, 这使 member 的语法略显冗长.

const_mem_fun 与 mem_fun

有时, 索引的键不是元素的具体数据成员, 而是某个特定成员函数返回的值. 这类似于某些关系数据库支持的 计算索引 概念. Boost.MultiIndex 通过 const_mem_fun 支持这类键提取. 考虑以下容器, 其中第三个索引的排序基于 name 字段的长度:

#include <boost/multi_index_container.hpp>
#include <boost/multi_index/ordered_index.hpp>
#include <boost/multi_index/identity.hpp>
#include <boost/multi_index/member.hpp>
#include <boost/multi_index/mem_fun.hpp>

struct employee
{
  int         id;
  std::string name;

  employee(int id,const std::string& name):id(id),name(name){}

  bool operator<(const employee& e)const{return id<e.id;}

  // returns the length of the name field
  std::size_t name_length()const{return name.size();}
};

typedef multi_index_container<
  employee,
  indexed_by<
    // sort by employee::operator<
    ordered_unique<identity<employee> >,
    
    // sort by less<string> on name
    ordered_non_unique<member<employee,std::string,&employee::name> >,
    
    // sort by less<int> on name_length()
    ordered_non_unique<
      const_mem_fun<employee,std::size_t,&employee::name_length>
    >
  >
> employee_set;

const_mem_fun 的使用语法与 member 类似:

const_mem_fun<(base type),(key type),(pointer to member function)>

被引用的成员函数必须是 const 的, 不接受参数并返回指定键类型的值. 几乎总是应使用 const 成员函数, 因为 multi_index_container 中的元素被视为常量, 正如 std::set 的元素一样. 不过, 也提供了 mem_fun 对应版本, 用于非常量成员函数; 其适用性在 Boost.MultiIndex 键提取器的高级特性 一段中讨论.

其他成员函数类型的变体

考虑以下无法编译的代码:

struct employee
{
  ...
  std::size_t salary()const&; // note the &
};

typedef multi_index_container<
  employee,
  indexed_by<
    ...
    ordered_non_unique<
      // compiler error: can't convert &employee::salary to
      // std::size_t (employee::*)() const
      const_mem_fun<employee,std::size_t,&employee::salary>
    >
  >
> employee_set;

这里的问题在于 &employee::salary 的类型——它是 引用限定 的——与 const_mem_fun 所期望的不完全匹配. 所幸, Boost.MultiIndex 提供了适用的变体:

typedef multi_index_container<
  employee,
  indexed_by<
    ...
    ordered_non_unique<
      cref_mem_fun<employee,std::size_t,&employee::salary>
    >
  >
> employee_set;

global_fun

const_mem_fun 及其变体基于基础类型中从中提取键的给定成员函数, 而 global_fun 则接受一个以基础类型为参数并返回键的全局函数 (或静态成员函数):

#include <boost/multi_index_container.hpp>
#include <boost/multi_index/ordered_index.hpp>
#include <boost/multi_index/global_fun.hpp>

struct rectangle
{
  int x0,y0;
  int x1,y1;
};

unsigned long area(const rectangle& r)
{
  return (unsigned long)(r.x1-r.x0)*(r.x1-r.x0)+
         (unsigned long)(r.y1-r.y0)*(r.y1-r.y0);
}

typedef multi_index_container<
  rectangle,
  indexed_by<
    // sort by increasing area
    ordered_non_unique<global_fun<const rectangle&,unsigned long,&area> >
  >
> rectangle_container;

global_fun 的规定遵循以下语法:

global_fun<(argument type),(key type),(pointer to function)>

其中实参类型与键类型必须与所用函数签名中的 完全 一致; 例如, 上例中实参类型是 const rectangle&, 不省略 “const” 与 “&” 部分. 因此, 尽管多数时候基础类型会以常量引用被接受, global_fun 也准备好接受按值或按非常量引用接受实参的函数: 后一种情形一般不能直接用于 multi_index_container 的规定, 因为其元素被视为常量, 但 Boost.MultiIndex 键提取器的高级特性 一节描述了基于这类带非常量引用实参函数的键提取的合法用例.

用户自定义键提取器

尽管 Boost.MultiIndex 提供的 预定义键提取器 旨在应对大多数情形, 用户在更特殊的情况下也可以提供自己的键提取器, 只要它们符合 Key Extractor 概念.

// some record class
struct record
{
  boost::gregorian::date d;
  std::string            str;    
};

// extracts a record's year
struct record_year
{
  // result_type typedef required by Key Extractor concept
  typedef boost::gregorian::greg_year result_type; 
  
  result_type operator()(const record& r)const // operator() must be const
  {
    return r.d.year();
  }
};

// example of use of the previous key extractor
typedef multi_index_container<
  record,
  indexed_by<
    ordered_non_unique<record_year> // sorted by record's year
  >
> record_log;

组合键

在关系数据库中, 组合键依赖于给定表的两个或更多字段. Boost.MultiIndex 中的类似概念通过 composite_key 建模, 如示例所示:

#include <boost/multi_index_container.hpp>
#include <boost/multi_index/ordered_index.hpp>
#include <boost/multi_index/member.hpp>
#include <boost/multi_index/composite_key.hpp>

struct phonebook_entry
{
  std::string family_name;
  std::string given_name;
  std::string phone_number;

  phonebook_entry(
    std::string family_name,
    std::string given_name,
    std::string phone_number):
    family_name(family_name),given_name(given_name),phone_number(phone_number)
  {}
};

// define a multi_index_container with a composite key on
// (family_name,given_name)
typedef multi_index_container<
  phonebook_entry,
  indexed_by<
    // non-unique as some subscribers might have more than one number
    ordered_non_unique< 
      composite_key<
        phonebook_entry,
        member<phonebook_entry,std::string,&phonebook_entry::family_name>,
        member<phonebook_entry,std::string,&phonebook_entry::given_name>
      >
    >,
    ordered_unique< // unique as numbers belong to only one subscriber
      member<phonebook_entry,std::string,&phonebook_entry::phone_number>
    >
  >
> phonebook;

composite_key 接受作用于同一个值 (此处为 phonebook_entry) 的若干键提取器. 组合键上的查找操作通过传入含有所搜索值的元组来完成:

phonebook pb;
...
// search for Dorothea White's number
phonebook::iterator it=pb.find(std::make_tuple("White","Dorothea"));
std::string number=it->phone_number;

组合键按字典序排序, 即先按第一个键排序, 若相等再按第二个键, 依此类推. 这种顺序允许只指定前几个键的部分查找:

phonebook pb;
...
// look for all Whites
std::pair<phonebook::iterator,phonebook::iterator> p=
  pb.equal_range(std::make_tuple("White"));

作为一种记法上的便利, 当只指定第一个键时, 可以直接传递实参而不把它包进元组:

phonebook pb;
...
// look for all Whites
std::pair<phonebook::iterator,phonebook::iterator> p=pb.equal_range("White");

另一方面, 不允许不指定前几个键的部分查找.

默认情况下, 组合键的每个子键使用相应的 std::less 谓词. 可以用 composite_key_compare 指定替代的比较谓词:

// phonebook with given names in reverse order

typedef multi_index_container<
  phonebook_entry,
  indexed_by<
    ordered_non_unique<
      composite_key<
        phonebook_entry,
        member<phonebook_entry,std::string,&phonebook_entry::family_name>,
        member<phonebook_entry,std::string,&phonebook_entry::given_name>
      >,
      composite_key_compare<
        std::less<std::string>,   // family names sorted as by default
        std::greater<std::string> // given names reversed
      >
    >,
    ordered_unique<
      member<phonebook_entry,std::string,&phonebook_entry::phone_number>
    >
  >
> phonebook;

组合键与哈希索引

组合键也可以直接与哈希索引配合使用:

struct street_entry
{
  // quadrant coordinates
  int x;
  int y;

  std::string name;

  street_entry(int x,int y,const std::string& name):x(x),y(y),name(name){}
};

typedef multi_index_container<
  street_entry,
  indexed_by<
    hashed_non_unique< // indexed by quadrant coordinates
      composite_key<
        street_entry,
        member<street_entry,int,&street_entry::x>,
        member<street_entry,int,&street_entry::y>
      >
    >,
    hashed_non_unique< // indexed by street name
      member<street_entry,std::string,&street_entry::name>
    >
  >
> street_locator;

street_locator sl;
...
void streets_in_quadrant(int x,int y)
{
  std::pair<street_locator::iterator,street_locator::iterator> p=
    sl.equal_range(std::make_tuple(x,y));

  while(p.first!=p.second){
    std::cout<<p.first->name<<std::endl;
    ++p.first;
  }
}

注意哈希是自动处理的: boost::hash 被特化为按 boost::hash 对各元素取值的函数来哈希组合键. 若需要为组合键的元素指定不同的哈希函数, 可以用 composite_key_hash 工具显式做到:

struct tuned_int_hash
{
  int operator()(int x)const
  {
    // specially tuned hash for this application
  }
};

typedef multi_index_container<
  street_entry,
  indexed_by<
    hashed_non_unique< // indexed by quadrant coordinates
      composite_key<
        street_entry,
        member<street_entry,int,&street_entry::x>,
        member<street_entry,int,&street_entry::y>
      >,
      composite_key_hash<
        tuned_int_hash,
        tuned_int_hash
      >
    >,
    hashed_non_unique< // indexed by street name
      member<street_entry,std::string,&street_entry::name>
    >
  >
> street_locator;

此外, 组合键的相等性可用 composite_key_equal_to 调整, 不过在多数情况下, 默认等价谓词 (依赖元素类型的 std::equal_to 实例化) 会是正确的选择.

与有序索引不同, 我们无法执行只指定组合键前几个元素的部分查找:

// try to locate streets in quadrants with x==0
// compile-time error: hashed indices do not allow such operations
std::pair<street_locator::iterator,street_locator::iterator> p=
  sl.equal_range(std::make_tuple(0));

这一限制的原因很合逻辑: 由于组合键的哈希值取决于其全部元素, 无法从部分信息计算出它.

C++17 简洁键规范语法

C++17 引入了 auto 模板参数的声明, 可借此消除 Boost.MultiIndex 预定义键提取器规定中的某些冗余. 例如, 代替经典写法:

typedef multi_index_container<
  employee,
  indexed_by<
    ordered_unique<identity<employee> >,
    ordered_non_unique<member<employee,std::string,&employee::name> >,
    ordered_non_unique<
      const_mem_fun<employee,std::size_t,&employee::name_length>
    >
  >
> employee_set;
现在可以这样写: 
#include <boost/multi_index/key.hpp>
...
typedef multi_index_container<
  employee,
  indexed_by<
    ordered_unique<identity<employee>>,
    ordered_non_unique<key<&employee::name>>,
    ordered_non_unique<key<&employee::name_length>>
  >
> employee_set;

所得定义类型完全相同, 因为 key 构造只是旧语法的别名. key 可用于缩短以下各项的规定: member、 const_mem_fun (及其 变体)、 mem_fun (及其 变体), global_fun 以及——带来额外简洁收益的—— composite_key:

typedef multi_index_container<
  phonebook_entry,
  indexed_by<
    // composite key on family name and given name
    ordered_non_unique<
      key<&phonebook_entry::family_name,&phonebook_entry::given_name>
    >,
    // unique index on phone number
    ordered_unique<key<&phonebook_entry::phone_number>>
  >
> phonebook;
本例中, 第一次使用 key 替代了明显更为繁琐的: 
composite_key<
  phonebook_entry,
  member<phonebook_entry,std::string,&phonebook_entry::family_name>,
  member<phonebook_entry,std::string,&phonebook_entry::given_name>
>
注意我们甚至不必指定第一个 phonebook_entry 实参: key 的内部机制会自动为我们推导它. 技术细节请查阅 参考文档 .

Boost.MultiIndex 键提取器的高级特性

Key Extractor 概念允许同一对象从若干不同类型提取键, 可能是通过适当定义的 operator() 重载:

// example of a name extractor from employee and employee *
struct name_extractor
{
  typedef std::string result_type;

  const result_type& operator()(const employee& e)const{return e.name;}
  result_type&       operator()(employee* e)const{return e->name;}
};

// name_extractor can handle elements of type employee...
typedef multi_index_container<
  employee,
  indexed_by<
    ordered_unique<name_extractor>
  >
> employee_set;

// ...as well as elements of type employee *
typedef multi_index_container<
  employee*,
  indexed_by<
    ordered_unique<name_extractor>
  >
> employee_ptr_set;

Boost.MultiIndex 提供的预定义键提取器充分利用了这一可能性, 使定义元素为指针或实际对象引用的 multi_index_container 更简单. 以下规定了一个按姓名排序的指向员工的指针的 multi_index_container.

typedef multi_index_container<
  employee *,
  indexed_by<
    ordered_non_unique<member<employee,std::string,&employee::name> > >
> employee_set;

注意其规定方式与实际的 multi_index_container——针对 employee 对象——完全一致: member 负责访问 employee::name 所需的额外解引用. 为与 Boost.Ref 的引用包装器互操作, 也提供了类似功能:

typedef multi_index_container<
  boost::reference_wrapper<const employee>,
  indexed_by<
    ordered_non_unique<member<employee,std::string,&employee::name> > >
> employee_set;

事实上, 对指针的支持进一步扩展为接受我们所说的 链式指针. 链式指针通过归纳定义: 它是指向实际元素、指向元素的引用包装器或 指向另一链式指针 的原始指针、智能指针或迭代器; 也就是说, 链式指针是指针类似类型的任意组合, 最终解引用到要从中提取键的元素. 指向 employee 的链式指针的例子有:

  • employee *,
  • const employee *,
  • std::unique_ptr<employee>,
  • std::list<boost::reference_wrapper<employee> >::iterator,
  • employee **,
  • boost::shared_ptr<const employee *>.
一般而言, 解引用距离大于 1 的链式指针不太可能出现在普通程序中, 但它们可能出现在把“视图”构造为 multi_index_container 的框架中——由既有的 multi_index_container 构造而成.

为简要总结在存在引用包装器与指针时 Boost.MultiIndex 键提取器的不同用法, 考虑以下最终类型:

struct T
{
  int        i;
  const int  j;
  int        f()const;
  int        g();
  static int gf(const T&);
  static int gg(T&);
};

“适用于 const 元素?”一列说明相应的键提取器在传入常量元素时是否可用 (此处指第一列中规定的元素, 而非被引用的 T 对象). 仅有的否定情形是 T::g 与 T:gg——当元素是原始 T 对象时; 这是有道理的, 因为我们面对的是非常量成员函数 (T::g) 和按非常量引用接受 T 的函数: 这也意味着 multi_index_container——其元素类型为 T——不能按 T::g 或 T::gg 排序, 因为 multi_index_container 中包含的元素被视为常量.

“是否读/写?”一列显示了哪些组合产生 读/写键提取器.

保持 const 正确性这一点, 在规定 member 键提取器时须加以留意: 某种意义上, const 限定符会传递到成员部分, 即使该特定成员并未定义为 const. 例如, 若元素类型为 const T *, 按 T::i 排序 不应 规定为 member<const T,int,&T::i>, 而应规定为 member<T,const int,&T::i>.
