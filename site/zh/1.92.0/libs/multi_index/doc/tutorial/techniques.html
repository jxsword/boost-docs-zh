标准容器模拟——基于 multi_index_container

模拟关联容器

撇开学术动机不谈, 用 multi_index_container 模拟标准关联容器具有实际意义, 即可以利用 multi_index_container 在查找、区间查询与更新方面提供的扩展功能.

为了模拟 std::set, 可以遵循替换规则:

std::set<Key,Compare,Allocator> ->
  multi_index_container<
    Key,
    indexed_by<ordered_unique<identity<Key>,Compare> >,
    Allocator
  >

在 Compare=std::less<Key> 与 Allocator=std::allocator<Key> 的默认情形下, 替换规则简化为

std::set<Key> -> multi_index_container<Key>

用 multi_index_container 替代 std::set 保留了 std::set 提供的全部功能, 因此原则上它是无需进一步调整的直接替代品.

std::multiset 可以类似的方式模拟, 遵循以下规则:

std::multiset<Key,Compare,Allocator> ->
  multi_index_container<
    Key,
    indexed_by<ordered_non_unique<identity<Key>,Compare> >,
    Allocator
  >

考虑默认值时, 该规则呈现如下形式:

std::multiset<Key> ->
  multi_index_container<
    Key,
    indexed_by<ordered_non_unique<identity<Key> > >
  >

std::multiset 的模拟——借助 multi_index_container——会在所提供的接口上产生细微差异: 成员函数 insert(const value_type&) 不返回 iterator——与 std::multiset 不同——而是返回 std::pair<iterator,bool>, 体现 std::set 的精神. 不过在这个特定情形下, 返回 pair 的 bool 成员总是 true.

std::map 与 std::multimap 的情形无法通过 multi_index_container 如此直接地模拟. 主要问题在于 multi_index_container 的元素被视为常量, 而 std::map 与 std::multimap 处理类型为 std::pair<const Key,T> 的对象, 从而允许自由修改值部分. 为克服这一困难, 需要创建一个特设的 pair 类:

template <typename T1,typename T2>
struct mutable_pair
{
  typedef T1 first_type;
  typedef T2 second_type;

  mutable_pair():first(T1()),second(T2()){}
  mutable_pair(const T1& f,const T2& s):first(f),second(s){}
  mutable_pair(const std::pair<T1,T2>& p):first(p.first),second(p.second){}

  T1         first;
  mutable T2 second;
};

于是替换规则为:

std::map<Key,T,Compare,Allocator> ->
  multi_index_container<
    Element,
    indexed_by<
      ordered_unique<member<Element,Key,&Element::first>,Compare>
    >,
    typename Allocator::template rebind<Element>::other
  >

std::multimap<Key,T,Compare,Allocator> ->
  multi_index_container<
    Element,
    indexed_by<
      ordered_non_unique<member<Element,Key,&Element::first>,Compare>
    >,
    typename Allocator::template rebind<Element>::other
  >

(with Element=mutable_pair<Key,T>)

若考虑默认值, 规则呈现如下形式:

std::map<Key,T> ->
  multi_index_container<
    Element,
    indexed_by<ordered_unique<member<Element,Key,&Element::first> > >
  >

std::multimap<Key,T> ->
  multi_index_container<
    Element,
    indexed_by<ordered_non_unique<member<Element,Key,&Element::first> > >
  >

(with Element=mutable_pair<Key,T>)

与标准 set 不同, 这些 multi_index_container 模拟的 map 的接口与 std::map 及 std::multimap 的接口并不完全一致. 最明显的差异是缺少 operator [] (读或写模式皆然); 不过, 通过适当使用 find 与 insert 可以模拟它.

这些用 multi_index_container 对标准关联容器的模拟, 在空间与时间效率上可与原构造相媲美. 更多细节见 性能一节.

模拟 std::list

与关联容器的情况不同, 在 Boost.MultiIndex 中模拟 std::list 并不增加任何显著的功能, 因此以下内容仅为完整性而给出.

与标准 map 十分类似, 模拟 std::list 时要克服的主要困难源于 multi_index_container 元素的常量性质. 同样, 需要某种适配类, 例如以下:

template <typename T>
struct mutable_value
{
  mutable_value(const T& t):t(t){}
  operator T&()const{return t;}

private:
  mutable T t;
};

它使我们能够使用替换规则:

std::list<T,Allocator> ->
  multi_index_container<
    Element,
    indexed_by<sequenced<> >,
    typename Allocator::template rebind<Element>::other
  >

(with Element=mutable_value<T>)

或者, 若使用默认值 Allocator=std::allocator<T>:

std::list<T> ->
  multi_index_container<mutable_value<T>,indexed_by<sequenced<> > >

元编程与 multi_index_container

Boost.MultiIndex 提供了大量设施, 旨在允许用元编程分析与综合 multi_index_container 实例化.

分析

给定一个 multi_index_container 实例化, 提供以下嵌套类型用于在编译期检视 multi_index_container 定义中出现的各种类型:

  • index_specifier_type_list,
  • index_type_list,
  • iterator_type_list,
  • const_iterator_type_list.
这些类型中的每一个都是一个 Mp11 list , 其元素数目与构成该 multi_index_container 的索引数目相同. 例如, n 号元素 (取自 iterator_type_list ) 等同于 nth_index<n>::type::iterator. Boost.Mp11 使检查与操作这些列表变得非常容易: 

using indexed_t=multi_index_container<
  int,
  indexed_by<
    ordered_unique<identity<int> >,
    sequenced<>
  >
>;

boost::mp11::mp_for_each<indexed_t::index_specifier_type_list>([](auto I){
  std::cout << boost::typeindex::type_id<decltype(I)>().pretty_name() << "\n";
});

// Output:
//
// struct boost::multi_index::ordered_unique<struct boost::multi_index::identity<int>,void,void>
// struct boost::multi_index::sequenced<struct boost::multi_index::tag<> >

index_specifier_type_list 与 index_type_list 之间存在一个微妙而重要的区别: 前一列表持有 说明符——即定义 multi_index_container 实例化时所用的索引说明符——而后者提供对每个说明符对应的实际实现类的访问. 在上例中, indexed_t::index_specifier_type_list 是一个类型列表, 其元素为

ordered_unique<identity<int>>
sequenced<>

而 indexed_t::index_type_list 持有类型

multi_index_container::nth_type<0>::type
multi_index_container::nth_type<1>::type

因此两个列表截然不同.

综合

虽然索引通常通过 indexed_by 构造来规定, 实际上也可以提供任何 Mp11 列表来代替:

using index_list_t=std::tuple<ordered_unique<identity<int> >,sequenced<>> ;

typedef multi_index_container<
  int,
  index_list_t
> indexed_t;

这一可能性使得通过元编程综合 multi_index_container 的实例化成为可能, 如下例所示:

// original multi_index_container instantiation
using indexed_t1=multi_index_container<
  int,
  indexed_by<
    ordered_unique<identity<int> >
  >
>;

// we take its index list and add an index
using index_list_t2=boost::mp11::mp_push_front<
  indexed_t1::index_specifier_type_list,
  sequenced<>
>;

// augmented multi_index_container
using indexed_t2=multi_index_container<
  int,
  index_list_t2
>;
