调试支持

契约式设计 的概念最初作为 Bertrand Meyer 的 Eiffel 语言的一部分而发展, 它围绕库使用者与实现者之间 契约 的制定: 前者被要求在调用库的方法时遵守对所传值的某些 前置条件, 而实现者作为回报保证结果满足某些约束 (后置条件), 并遵守指定的内部一致性规则——称为 不变量. Eiffel 通过构造 require、ensure 与 invariant 原生支持上述契约的三个部分.

C++ 不直接支持契约式设计技术: 它们通常以断言代码实现, 且常出于性能原因在发布模式下关闭. 遵循这一思路, Boost.MultiIndex 提供两种不同的调试模式:

  • 安全模式 检查对库设施的调用的前置条件,
  • 不变量检查模式 执行事后检查, 旨在确保库的内部一致性得以保持.
这两种模式相互独立, 可以分别单独开启或关闭. 值得注意的是, 安全模式检测到的错误原则上源于用户程序中的错误代码, 而不变量检查模式检测的则是 Boost.MultiIndex 实现中潜在的 内部 缺陷.

安全模式

向 STL 添加前置条件检查设施作为调试辅助的想法, 最初由 Cay S. Horstmann 在其 Safe STL 库中提出, 后被 STLport Debug Mode 采纳. 类似地, Boost.MultiIndex 提供所谓的 安全模式, 在处理库的迭代器与函数时检查各种前置条件.

Boost.MultiIndex 安全模式通过全局定义宏 BOOST_MULTI_INDEX_ENABLE_SAFE_MODE 来开启. 错误条件通过宏 BOOST_MULTI_INDEX_SAFE_MODE_ASSERT 检查, 它默认解析为对 BOOST_ASSERT 的调用.

若用户决定定义自己的 BOOST_MULTI_INDEX_SAFE_MODE_ASSERT 版本, 它必须采用如下形式

BOOST_MULTI_INDEX_SAFE_MODE_ASSERT(expr,error_code)

其中 expr 是被检查的条件, error_code 是 safe_mode::error_code 枚举的一个值:

namespace boost{

namespace multi_index{

namespace safe_mode{

enum error_code
{
  invalid_iterator,             // vg. default cted or pointing to erased element
  not_dereferenceable_iterator, // iterator is not dereferenceable
  not_incrementable_iterator,   // iterator points to end of sequence
  not_decrementable_iterator,   // iterator points to beginning of sequence 
  not_owner,                    // iterator does not belong to the container
  not_same_owner,               // iterators belong to different containers
  invalid_range,                // last not reachable from first
  inside_range,                 // iterator lies within a range (and it mustn't)
  out_of_bounds,                // move attempted beyond container limits
  same_container,               // containers ought to be different
  unequal_allocators            // allocators ought to be equal
};

} // namespace multi_index::safe_mode

} // namespace multi_index

} // namespace boost

例如, 以下对 BOOST_MULTI_INDEX_SAFE_MODE_ASSERT 的替换会抛出异常而不是断言:

#include <boost/multi_index_container/safe_mode_errors.hpp>

struct safe_mode_exception
{
  safe_mode_exception(boost::multi_index::safe_mode::error_code error_code):
    error_code(error_code)
  {}

  boost::multi_index::safe_mode::error_code error_code;
};

#define BOOST_MULTI_INDEX_SAFE_MODE_ASSERT(expr,error_code) \
if(!(expr)){throw safe_mode_exception(error_code);}

// This has to go before the inclusion of any header from Boost.MultiIndex,
// except possibly safe_error_codes.hpp.

其他可能性, 如输出到日志或触发某种警报, 也可以实现.

警告: 安全模式在空间与时间上给程序增加非常重要的开销, 因此一般不应为 NDEBUG 构建开启它. 此外, 该模式仅用作调试辅助, 程序不得把它作为正常执行流的一部分来依赖: 特别是, 不保证诊断出所有可能的前置条件错误, 也不保证这些检查在不同版本的库之间保持稳定.

序列化与安全模式

从档案恢复的迭代器不受安全模式检查. 这是因为仅凭序列化信息无法自动得知迭代器所关联的 multi_index_container. 不过, 若有需要, 可以用以下变通办法把恢复的迭代器转换为经检查的值:

employee_set es;
employee_set::nth_index<1>::iterator it;

// restore es and it from an archive ar
ar>>es;
ar>>it; // it won't benefit from safe mode checks

// Turn it into a checked value by providing Boost.MultiIndex
// with info about the associated container.
// This statement has virtually zero cost if safe mode is turned off.
it=es.project<1>(it);

置于共享内存中的容器

一般而言, 安全模式 不能使用 于把 multi_index_container 置于共享内存进行进程间通信的场合 (如 此示例 中那样). 这一限制有几个根本原因:

  • 一个进程的操作可能使驻留在另一进程非共享内存中的迭代器失效或改变其所有权: 安全模式机制无法访问它们进行簿记.
  • 安全模式使用不适合进程间同步或持久化到内存映射文件的内部互斥量.

不变量检查模式

Boost.MultiIndex 的所谓 不变量检查模式 可以通过全局定义宏 BOOST_MULTI_INDEX_ENABLE_INVARIANT_CHECKING 来开启. 该模式生效时, Boost.MultiIndex 的所有公开函数都会执行事后测试, 旨在确保所管理数据结构的基本内部不变量得以保持.

若某个不变量测试失败, Boost.MultiIndex 会通过一元宏 BOOST_MULTI_INDEX_INVARIANT_ASSERT 指示失败. 除非用户为该宏提供定义, 它默认为 BOOST_ASSERT. 任何此类断言原则上都应视为库中的缺陷. 请把此类问题连同尽可能多的上下文信息报告给库的维护者.

建议 Boost.MultiIndex 的用户在调试构建中始终开启不变量检查模式.
