示例 2: 将函数用作键

参见 源代码.

通常, 赋予索引的键基于元素的某个成员变量, 但也可以定义从成员函数或全局函数取值的键提取器. 这与某些关系数据库引擎支持的 计算键 概念有几分相似. 本示例展示如何使用预定义的 const_mem_fun 与 global_fun 键提取器来处理这种情况.

基于函数的键通常不是实际的引用, 而是调用所用成员函数得到的临时值. 这意味着 modify_key 不能应用于这类键提取器, 不过这本来就是一个完全合理的限制.

示例 4: 双向映射

参见 源代码.

本示例展示如何用 multi_index_container 构造双向映射. 所谓 双向映射, 是指一个保存 (const FromType,const ToType) 对的容器, 其中不存在第一个或第二个分量相同的两个元素 (std::map 仅保证第一个分量的唯一性) . 两种键均可快速查找. 程序实现了一个小小的西班牙语-英语词典, 支持对两种语言的单词进行在线查询.

此双向映射可视为 Boost.Bimap 所提供的成熟容器的一个原始前身.

示例 6: 复杂查找与外键

参见 源代码.

本程序示例说明在使用 multi_index_container 构建复杂数据结构时可采用的一些高级技术. 考虑一个用于存储汽车信息的 car_model 类. 初步方案中, car_model 可定义为:

struct car_model
{
  std::string model;
  std::string manufacturer;
  int         price;
};

这一设计存在一个任何熟悉关系数据库的读者都能轻易看出的缺陷: manufacturer 成员在所有具有同一制造商的汽车之间重复出现. 这既浪费空间, 又在例如必须更改制造商名称时带来困难. 按照关系数据库设计的一般原则, 恰当的设计是将制造商保存在独立的 multi_index_container 中, 并在 car_model 中保存指向它们的指针:

struct car_manufacturer
{
  std::string name;
};

struct car_model
{
  std::string             model;
  const car_manufacturer* manufacturer;
  int                     price;
};

尽管预定义的 Boost.MultiIndex 键提取器能够处理许多涉及指针的情形 (参见教程中的 Boost.MultiIndex 键提取器的高级特性) , 本例已足够复杂, 需要定义一个合适的键提取器. 以下实用工具将两个键提取器级联起来:

template<class KeyExtractor1,class KeyExtractor2>
struct key_from_key
{
public:
  typedef typename KeyExtractor1::result_type result_type;

  key_from_key(
    const KeyExtractor1& key1_=KeyExtractor1(),
    const KeyExtractor2& key2_=KeyExtractor2()):
    key1(key1_),key2(key2_)
  {}

  template<typename Arg>
  result_type operator()(Arg& arg)const
  {
    return key1(key2(arg));
  }

private:
  KeyExtractor1 key1;
  KeyExtractor2 key2;
};

从而, 从 car_model 到 name 字段——该字段位于其关联的 car_manufacturer 中——的访问可按如下方式完成

key_from_key<
  member<car_manufacturer,const std::string,&car_manufacturer::name>,
  member<car_model,const car_manufacturer *,&car_model::manufacturer>
>

程序要求用户提供汽车制造商与一个价格区间, 并返回满足这些要求的车型. 这是一种无法用单一操作完成的复杂查找. 粗略地说, 执行该选择的一种过程是:

  1. 借助 equal_range 选出具有给定制造商的元素,
  2. 将这些元素放入一个按价格排序的 multi_index_container,
  3. 使用 lower_bound 与 upper_bound 按价格进行选择;
或者等价地:
  1. 用 lower_bound 与 upper_bound 选出价格区间内的元素,
  2. 将这些元素放入一个按制造商排序的 multi_index_container,
  3. 使用 equal_range 定位具有给定制造商的元素.
本示例中一个有趣的技术在于中间层 multi_index_container 的构造. 为避免对象拷贝, 定义了合适的 视图 类型, 令 multi_index_container 的元素为指向 car_model 的指针而非实际对象. 这些视图还需辅以适当的解引用键提取器.

示例 7: 复合键

参见 源代码.

Boost.MultiIndex 的 composite_key 构造提供了一种灵活的工具, 可用于创建排序准则非平凡的索引. 该程序实现了一个简易的文件系统模拟, 并附带一个交互式类 Unix shell. 文件条目由以下结构表示:

struct file_entry
{
  std::string       name;
  unsigned          size;
  bool              is_dir; // true if the entry is a directory
  const file_entry* dir;    // directory this entry belongs in
};

条目保存在一个 multi_index_container 中, 后者维护两个复合键索引:

  • 按目录与名称排序的主索引,
  • 按目录与大小排序的次索引.
之所以首先按文件所在目录排序, 是源于 shell 命令的局部性质, 例如 ls. 该 shell 模拟只有三个命令:
  • cd [.|..|<directory>]
  • ls [-s] (-s 按大小对输出排序)
  • mkdir <directory>
当用户在命令提示符处按下 Enter 键时程序退出.

欢迎读者为程序添加更多功能; 例如:

  • 实现更多命令, 例如 cp.
  • 增加对绝对路径的处理.
  • 使用 序列化 在程序各次运行之间保存和恢复文件系统状态.

示例 9: 序列化与 MRU 列表

参见 源代码.

序列化能力的一个典型应用, 是让程序在各次运行之间恢复用户上下文. 本示例程序要求用户输入单词, 并记录最近输入的十个单词——无论是本次会话还是之前会话的输入. 这一经序列化的数据结构有时称为 MRU (most recently used) 列表, 其本身也有几分趣味: MRU 列表表现为常规的 FIFO 队列, 不同之处在于, 插入已存在的条目时它不会出现两次, 而是被移动到列表前部. 在许多带有“Recent files”菜单命令的程序中都可以观察到这种行为. 该数据结构用 multi_index_container 实现, 方式是组合一个序列索引与一个 hashed_unique 类型的索引.

示例 11: 索引重排

参见 源代码.

坊间流传一种相当普遍的说法: 一副牌必须连续洗七次才能完全混匀. 这一说法源自数学家 Persi Diaconis 关于 鸽尾式洗牌 的工作: 这种洗牌技术把整副牌分成大小大致相等的两叠, 然后让两叠的牌交替落下、彼此交错. 已经证明, 重复此过程七次后, 牌的统计分布已相当接近真正随机排列所对应的分布. “随机性”的程度可以通过计数 递增序列 来估计: 考虑序列 1,2, ..., n 的一个排列, 递增序列是连续元素 m, m+1, ..., m+r 的极大链, 且按升序排列. 例如, 排列 125364789 由两个递增序列 1234 和 56789 组成, 把序列显示成 125364789 的样子便一目了然. n 个元素的随机排列中递增序列的平均数目为 (n+1)/2: 相比之下, 对一副初始有序的牌做一次鸽尾式洗牌后, 递增序列不可能超过两个. 随着连续鸽尾式洗牌次数的增加, 递增序列的平均数目趋近 (n+1)/2, 对一副 52 张的扑克牌而言, 洗七次即得到接近的结果. Brad Mann 的论文 “How many times should you shuffle a deck of cards?” 对这一主题给出了严谨而又平易的论述.

本示例程序估计一副 52 张的牌在重复鸽尾式洗牌以及施加完全随机排列之后递增序列的平均数目. 整副牌用如下容器建模:

multi_index_container<
  int,
  indexed_by<
    random_access<>,
    random_access<> 
  >
>
其中第一个索引保存牌当前的排列顺序, 第二个索引用于记住起始位置. 这种表示使递增序列计数算法能够在线性时间内高效实现. rearrange 用于把在外部辅助数据结构上执行的洗牌施加到整副牌上.
