通知式索引

通知式索引 可作为既有索引类型之上的装饰器来实现, 其附加功能是将索引的内部事件 (插入、删除、修改元素) 通知给外部实体——例如借助 Boost.Signals 库. 此功能可应用于:

  1. 日志记录,
  2. 与基于 GUI 的应用程序对接,
  3. 相互独立的数据结构之间的同步.

以下是对通知式索引一种可能实现的概略描述:

struct insert_log
{
  void operator()(int x)
  {
    std::clog<<"insert: "<<x<<std::endl;
  }
};

int main()
{
  typedef multi_index_container<
    int,
    indexed_by<
      notifying<ordered_unique<identity<int> > >, // notifying index
      ordered_non_unique<identity<int> >
    >
  > indexed_t;

  indexed_t t;

  // on_insert is the signal associated to insertions
  t.on_insert.connect(insert_log());

  t.insert(0);
  t.insert(1);

  return 0;
}

// output:
//   insert: 0
//   insert: 1

约束

上文所述的通知式索引功能利用了一种基于 索引适配器 的强大设计模式——即位于既有索引之上的装饰器, 它们为底层索引添加某些功能或以某种方式改变其语义. 该模式可用于实现 约束——即依据某个验证谓词限制索引所接受元素的适配器. 以下是对约束语法可能形态的一种实现设想:

struct is_even
{
  bool operator()(int x)const{return x%2==0;}
};

typedef multi_index_container<
  int,
  indexed_by<
    constrained<ordered_unique<identity<int> >,is_even>
  >
> indexed_t;

用户自定义索引

Boost.MultiIndex 协调 multi_index_container 所持各索引操作的机制足够简单, 值得加以说明, 以便 (大胆的) 用户能够为自己的索引编写实现.

可索引映射

multi_index_container 已足够丰富, 可为实现 可索引映射 (即可以用多个不同键进行查找的映射) 提供基础. 拥有这种容器的动机主要是审美上的便利, 因为它相对于直接基于 multi_index_container 的类似构造不会提供任何额外特性.

编写可索引映射的主要挑战在于设计一个尽可能接近 std::map 的合理接口. 把 std::map 的语法扩展到多个键似乎存在根本性的困难. 举一个例子, 考虑如下情形:

indexed_map<int,string,double> m;
// keys are int and string, double is the mapped to value

...

cout<<m[0]<<endl;      // OK
cout<<m["zero"]<<endl; // OK
m[1]=1.0;              // !!

在示例的最后一句中, 用户没有办法提供 string 键, 使其映射到与 m[1] 相同的值. 在设计潜在的可索引映射接口时, 必须对这一问题及类似问题进行仔细研究.
