概述

本库实现了一个可扩展的框架, 用于实现能够支持用户自定义类型的哈希算法. 其结构在很大程度上基于 Howard Hinnant、Vinnie Falco 和 John Bytheway 的论文 "Types don’t know #" .

该设计的关键特性是在以下两者之间做出了清晰的分离: 一边是 哈希算法 (hash algorithm) ——它接收一个无类型的字节流 (一个 message) 并产出一个哈希值 (一个 message digest (消息摘要) ) ; 另一边是 hash_append 函数——它接收一个类型, 负责把该类型的值转换为字节序列并把它们提供给 哈希算法.

这使得对用户自定义类型的哈希支持只需编写一次, 之后即可自动用于任何哈希算法, 甚至包括在定义该类型时还不存在的算法.

本库提供了以下流行的哈希算法:

  • FNV-1a

  • xxHash

  • SipHash

  • MD5

  • SHA-1

  • SHA-2

  • SHA-3

  • BLAKE2

  • RIPEMD-160, RIPEMD-128

  • HMAC

但用户也可以自行编写; 只要哈希算法符合该概念, hash_append 就能配合它使用, 所有支持 hash_append的用户自定义类型也是如此.

对字节序列进行哈希

本库处理两大使用场景: 对无类型的字节序列进行哈希, 以及对 C++ 对象进行哈希.

无类型的字节序列 (也称为 message (消息) ) 会通过传递给 哈希算法 (hash algorithm) 来进行哈希, 由其产生一个哈希值 (或 message digest (消息摘要) ) .

同一个 哈希算法在被给予同一个 message (消息) 时, 总是会产生同一个 digest (摘要) . (已发表的算法会提供 message 与对应的 digest 配对, 称为 test vectors (测试向量) , 以便对独立实现进行验证. )

(要对 C++ 对象进行哈希, 先把它转换 (序列化) 为字节序列, 然后传递给 哈希算法. )

哈希算法要求

一个 哈希算法 (hash algorithm) 必须具有以下结构, 并满足以下最低要求:

struct HashAlgorithm
{
    using result_type = /*integral or array-like*/;

    static constexpr std::size_t block_size = /*...*/; // optional

    HashAlgorithm();
    explicit HashAlgorithm( std::uint64_t seed );
    HashAlgorithm( void const* seed, std::size_t n );

    HashAlgorithm( HashAlgorithm const& r );
    HashAlgorithm& operator=( HashAlgorithm const& r );

    void update( void const* data, std::size_t n );

    result_type result();
};

result_type

嵌套类型 result_type 是所产生的哈希值的类型. 它可以是无符号整数类型 (不能是 bool) , 通常是 std::uint32_t 或者 std::uint64_t, 或者是一个类似于 std::array的类型, 其值类型为 unsigned char.

通常, 非密码学哈希函数具有整数类型的 result_type, 而密码学哈希函数具有类数组 (array-like) 的 result_type, 但这不是必需的.

所提供的实用函数 get_integral_result 可以用于从任何有效的 result_type获得整数哈希值.

block_size

密码学哈希函数提供一个 block_size 值, 即其块大小 (例如 MD5 为 64, SHA2-512 为 128) ; 实现相应的 HMAC时需要用到它.

block_size 是一个可选要求.

默认构造函数

全部 哈希算法 都必须可默认构造. 默认构造函数把哈希算法的内部状态初始化为其规范中公布的初始值.

例如, md5_128 的默认构造函数对应于调用参考实现的函数 MD5_Init .

接受整数种子的构造函数

全部 哈希算法 都必须能从 std::uint64_t类型的值构造, 该值作为种子.

使用种子值 0 等价于默认构造.

不同的种子值会使内部状态以不同方式初始化, 因此, 用不同种子初始化的哈希算法实例在被给予相同消息时会产生不同的哈希值.

使用随机 (外部不可观测的) 值做种子有助于防范 哈希泛洪攻击 (hash flooding attacks) .

接受字节序列种子的构造函数

全部 哈希算法 都可以从 unsigned char 值的种子序列构造 (这使得所有哈希算法都成为 带密钥的哈希函数 (keyed hash functions) ) .

空序列 (长度为 0 的序列) 产生默认构造的实例.

不同的种子序列产生不同初始化的实例.

虽然这一要求使所有哈希算法都可用作 MAC (消息认证码 (Message Authentication Codes) ) , 但作为一般规则, 你应当优先使用成熟的 MAC 算法, 例如 HMAC. (本库提供了 HMAC 实现. )

拷贝构造函数、拷贝赋值

哈希算法可拷贝构造和拷贝赋值, 并为这些操作提供通常的保证. 也就是说, 副本与原对象等价.

update

函数 update 是向哈希算法提供输入消息的机制.

调用 update 多次等价于把这些调用各自的字节序列拼接起来后调用一次. 也就是说, 输入消息可以分部分提供, 其拆分方式无关紧要, 也不会影响最终的哈希值.

给定

Hash hash; // some hash algorithm
unsigned char message[6] = { /*...*/ }; // some input message

如下 update 调用

hash.update( message, 6 );

等价于

hash.update( message, 4 );
hash.update( message + 4, 2 );

以及

for( int i = 0; i < 6; ++i ) hash.update( &message[i], 1 );

result

在通过调用 update提供了完整的输入消息之后, 可以调用 result来获得最终的哈希值.

对 result 的调用会终结内部状态: 按具体算法的规范对消息进行填充, 可选地把消息长度并入状态, 并按具体算法的规定对状态执行终结操作.

随后通过变换内部状态得到最终的哈希值并返回.

注意, result 是非 const 的, 因为它会改变内部状态. 允许 result 被调用多次; 后续调用会再次执行状态终结, 从而产生一个由 result_type 值组成的伪随机序列. 这可以有效扩展哈希函数的输出. 例如, 对于 result_type 为 64 位的哈希算法, 可以通过调用 result 四次来获得 256 位的结果.

作为一个玩具示例 ( 不适用于生产环境) , 下面演示了如何在本库提供的 FNV-1a 实现之上编写一个随机数生成器:

std::uint64_t random()
{
    static boost::hash2::fnv1a_64 hash;
    return hash.result();
}

编译期哈希

在 C++14 下, 可以在编译期调用某些哈希算法. 这些算法提供以下接口:

struct HashAlgorithm
{
    using result_type = /*integral or array-like*/;

    static constexpr std::size_t block_size = /*...*/; // optional

    constexpr HashAlgorithm();
    explicit constexpr HashAlgorithm( std::uint64_t seed );
    HashAlgorithm( void const* seed, std::size_t n );
    constexpr HashAlgorithm( unsigned char const* seed, std::size_t n );

    constexpr HashAlgorithm( HashAlgorithm const& r );
    constexpr HashAlgorithm& operator=( HashAlgorithm const& r );

    void update( void const* data, std::size_t n );
    constexpr void update( unsigned char const* data, std::size_t n );

    constexpr result_type result();
};

除了新增的 constexpr 限定符之外, 唯一的区别是字节种子构造函数和 update 都有一个接受 unsigned char const* 而不是 void const*的第二个重载. (在 C++26 之前, 指向 void 的指针不能在 constexpr 函数中使用. )

提供的哈希算法

FNV-1a

本库提供 Fowler-Noll-Vo 哈希函数 作为逐字节处理其输入的那一类哈希函数的代表. 对于每个输入字符 ch , 32 位或 64 位状态通过运算 state = (state ^ ch) * fnv_prime来更新.

FNV-1a 是非密码学的, 与最先进的哈希函数相比相对较弱 (尽管在其类别中表现良好) , 但在输入字符串较短时速度很快.

xxHash

xxHash 是 Yann Collet 开发的一种快速非密码学哈希算法.

它的速度 ( xxhash_32约为 5GB/s, xxhash_64 约为 10GB/s, 测量于 Xeon E5-2683 v4 @ 2.10GHz) 使它非常适合快速生成文件或数据完整性校验和.

SipHash

SipHash 由 Jean-Philippe Aumasson 和 Daniel J. Bernstein 设计 (论文) , 其目的是抵御针对接收外部不可信输入的哈希表 (例如 HTTP 消息头或 JSON 对象) 的 哈希泛洪攻击 (hash flooding attacks) .

它不是密码学哈希函数 (尽管其设计与密码学哈希函数相似) , 因为在初始种子已知时它不提供抗碰撞性.

不过, 它是一个密码学强度高的带密钥哈希函数 (或伪随机函数, PRF) . 如果攻击者不知道初始种子, 那么从计算上构造碰撞或通过观察输出来恢复种子都是困难的.

SipHash 已被采纳为可能暴露于外部输入的哈希表的事实标准哈希函数, 并用于 Python、Perl、Ruby、Rust 及其他语言.

对于暴露于外部输入的哈希表, SipHash 是推荐的哈希函数. 作为最佳实践, 应当用随连接而变化的随机值 (而不是每个进程固定的值) 来为它做种子.

MD5

由 Ron Rivest 于 1991 年设计的 MD5 曾是最著名、使用最广泛的 密码学哈希函数 (cryptographic hash function) , 但它已被破解, 不再被视为可用于任何用途的密码学哈希. 它产生 128 位摘要.

当需要密码学强度时, 新代码不应再使用 MD5, 除非是在实现要求使用它的现有规范或协议.

应改用 SHA2-512/256 (32 位代码中用 SHA2-256) .

如果你需要的摘要恰好是 128 位, 请改用 RIPEMD-128. 但请注意, 128 位摘要已不再被视为密码学安全的, 因为复杂度为 264 的攻击已在资金充足的攻击者能力范围之内.

SHA-1

SHA-1 是一种由 NSA 设计的密码学哈希函数, 并于 1995 年 发布 , 发布者为 NIST , 作为 联邦信息处理标准 (Federal Information Processing Standard) (FIPS) . 它产生 160 位摘要.

SHA-1 现在被认为对资金充足的攻击者而言是不安全的, 新代码中不应再使用. 应改用 SHA2-512/256 (32 位代码中用 SHA2-256) , 或者——如果你需要的摘要恰好是 160 位——改用 RIPEMD-160.

SHA-2

SHA-2 是一个密码学哈希函数家族, 同样由 NSA 设计, 由 NIST 于 2002 年 首次发布 , 并于 2015 年 更新 . 它包括 SHA2-224、SHA2-256、SHA2-384、SHA2-512、SHA2-512/224 和 SHA2-512/256, 每个都产生相应位长度的摘要.

其中, SHA2-256 和 SHA2-512 是基础版本, 其余是截断摘要的变体.

尽管存在更新的标准 (SHA-3) , SHA-2 函数尚未被破解, 并且仍在广泛使用.

SHA2-256 及其截断变体 SHA2-224 使用 32 位运算, 因此在 32 位平台上不会损失性能.

SHA2-512 及其截断变体 SHA2-384、SHA2-512/224 和 SHA2-512/256 使用 64 位运算, 在 64 位平台上比 SHA2-256 快约 1.5 倍, 但在 32 位代码中慢一倍.

在 64 位平台上, 应优先选择 SHA2-512/256 和 SHA2-512/224 而非 SHA2-256 和 SHA2-224, 这不仅是因为速度, 还因为它们能抵抗长度扩展攻击——它们不会在最终摘要中暴露其内部状态的全部位.

SHA-3

SHA-3 是安全哈希算法 (Secure Hash Algorithm) 标准中最新增加的成员, 2015 年作为 FIPS 202发布.

SHA-3 包含 6 个算法: SHA3-224、SHA3-256、SHA3-384、SHA3-512、SHAKE128 和 SHAKE256.

SHA3 函数输出固定大小的摘要, 而 SHAKE128 和 SHAKE256 是经批准的可扩展输出函数 (extendable-output function) , 也称为 XOF. XOF 允许以确定的方式生成任意长的消息摘要.

与 SHA-2 不同, SHA3-224 并不是 SHA3-256 算法的截断版本. 相反, 所有 SHA-3 算法都是通过截断经 Keccak 算法置换后的 1600 位状态的较低部分来创建其摘要的. XOF 以固定大小的块增量式地返回其摘要, 采用 FIPS 202 算法 8 第 8 步规定的截断方式.

SHA-3 家族中的所有算法都使用 64 位运算.

BLAKE-2

BLAKE-2 是一种以高速度著称的密码学哈希函数, 其速度远超 MD5、SHA-1、SHA-2 和 SHA-3 等其他常见算法. 本库实现了 BLAKE2b (针对 64 位平台优化) 和 BLAKE2s (针对 8 至 32 位平台优化) . BLAKE2b 的摘要固定为 512 位, BLAKE2s 使用 256 位摘要.

BLAKE2 在设计上也明确考虑了带密钥哈希, 使其在功能上等价于消息认证码 (MAC) . 带种子的构造函数充当密钥: BLAKE2b 最多使用输入的前 64 字节作为密钥, BLAKE2s 最多使用前 32 字节. 多余的输入通过传递给 update() 函数来处理, 然后调用 result() . 为方便起见, 也为与 Noise等现有协议兼容, 仍然提供了 HMAC typedef. 在与 hmac<H>一起使用时, BLAKE2 的行为与其他所有密码学哈希函数相同.

RIPEMD-160, RIPEMD-128

设计于 1996 年的 RIPEMD-160 是一种密码学哈希函数, 是一种密码学哈希函数, 其知名度曾不及 MD5 和 SHA-1, 但由于在比特币及其他加密货币中的使用而近来变得流行.

尽管它尚未被破解, 但在新代码中没有理由优先选择它而不是 SHA-2.

RIPEMD-128 是 RIPEMD-160 的截断变体. (请注意, 128 位摘要已不再被视为密码学安全的, 因为复杂度为 264 的攻击已在资金充足的攻击者能力范围之内. )

HMAC

HMAC (基于哈希的消息认证码, Hash-based Message Authentication Code) 是一种利用密码学哈希函数导出 消息认证码 (message authentication code) 的算法. 它在 RFC 2104中有描述.

消息认证码与摘要的区别在于: 它既依赖于消息的内容, 也依赖于一个保密的 密钥 (key) ; 相比之下, 消息摘要只依赖于消息的内容.

尽管本库提供的所有哈希算法都可以用来产生消息认证码——方法是通过调用接受字节序列的构造函数, 一开始就用一个保密密钥为哈希算法做种子——但哈希算法通常并未按这种方式使用来设计, 这种用法也没有经过密码学分析和审查. (SipHash 是个例外; 它专门被设计为 MAC. )

HMAC 算法以类模板 hmac<H> 的形式提供, 用于适配密码学哈希算法 H. hmac<H> 满足密码学哈希算法的要求.

为常见的 HMAC 实例化提供了便捷别名. 例如, 定义了 md5.hpp 的头文件 md5_128 也定义了 hmac_md5_128 作为 hmac<md5_128>的别名.

选择哈希算法

如果你的使用场景需要密码学强度, 请使用 SHA2-512/256 (32 位代码中用 SHA2-256) 来计算摘要, 并使用相应的 HMAC 来计算消息认证码.

注释
 当需要或希望具备密码学安全性时, 不再推荐使用长度少于 256 位的摘要.

对于计算文件或内容校验和的场景, 当速度至关重要且外部诱发的碰撞不是问题时, 请使用 xxHash-64.

注释
 xxHash-32 在 32 位代码中会更快, 但由于它只产生 32 位结果, 当条目数量达到数万时碰撞会成为问题, 这通常是不可接受的.

对于大量条目 (数百万量级) , 64 位可能不够; 在这种情况下, 请使用 MD5, 或使用 扩展到 128 位的 xxHash-64.

注释
 尽管 MD5 已不再具有密码学安全性, 但在不需要密码学强度时仍然可以使用它.

对于哈希表, 默认请使用 SipHash, 并配合 随机 (外部不可预测) 的种子 , 该种子随连接或随容器而变化. 避免使用全进程固定的种子. 绝不要在无种子的情况下使用 SipHash.

对于键非常短 (3-4-5 字节) 且不暴露于外部输入的哈希表, 你可以使用 FNV-1a, 不过例如 boost::unordered_flat_map 的默认哈希函数通常表现更好.

对 C++ 对象进行哈希

对 C++ 对象进行哈希的传统做法是让对象自己负责提供哈希值. 例如, 标准库遵循这一做法, 让每个类型 T 负责实现 std::hash<T>的特化, 调用时传入一个值即返回其 size_t 哈希.

当然, 这意味着具体的哈希算法因类型而异, 而且在一般情况下完全不透明.

本库采取了不同的做法: 哈希算法是已知的、由用户选择的. 对 C++ 对象进行哈希时, 先把它转换为表示其值的字节序列 (一个 message (消息) ) , 然后将该序列传递给哈希算法.

该转换必须遵守以下要求:

  • 相等的对象必须产生相同的消息;

  • 不同的对象应产生不同的消息;

  • 对象应始终产生非空消息.

前两个要求直接来自哈希值的要求, 而第三个要求则更为微妙, 其目的是防止诸如不同的序列 [[1], [], []] 以及 [[], [1], []] 产生相同消息这类情况. (这类似于要求所有 C++ 对象——包括空对象——的 sizeof 都不为零的规则. )

在本库中, 该转换由函数 hash_append完成. 它声明如下:

template<class Hash, class Flavor = default_flavor, class T>
constexpr void hash_append( Hash& h, Flavor const& f, T const& v );

而调用 hash_append(h, f, v) 的效果是调用 h.update(p, n) 一次或多次 (但绝不会是零次. ) 这些调用的组合结果构成与 v相对应的消息.

hash_append 会原生处理以下类型 T:

  • 整数类型 (有符号和无符号整数、字符类型、 bool) ;

  • 浮点类型 (float 以及 double) ;

  • 枚举类型;

  • 指针类型 (对象指针和函数指针, 但不包括成员指针类型) ;

  • C 数组;

  • 容器和范围 (提供 begin() 以及 end()的类型) ;

  • 无序容器和无序范围;

  • 常量大小容器 (std::array、 boost::array) ;

  • 类元组类型 (std::pair、 std::tuple) ;

  • std::optional;

  • std::variant;

  • std::monostate;

  • Described 类 (使用 Boost.Describe) .

不属于上述类别的用户自定义类型可以提供对 hash_append 的支持, 方法是声明 tag_invoke 函数的带适当参数的重载.

传给 hash_append的第二个实参——即 flavor (风格) ——用于在存在多种可能且可取的行为时控制序列化过程. 它目前包含以下成员:

  • static constexpr endian byte_order; // native, little, or big

  • using size_type = std::uint32_t; // or std::uint64_t

flavor 的 byte_order 成员影响标量 C++ 对象被序列化为字节的方式. 例如, uint32_t 类型的整数 0x01020304 在 { 0x01, 0x02, 0x03, 0x04 } 为 byte_order 时会被序列化为 endian::big, 而在 { 0x04, 0x03, 0x02, 0x01 } 为 byte_order 时则会被序列化为 endian::little.

值 endian::native 表示使用当前平台的字节序. 这通常会带来更高的性能, 因为它使 hash_append 能够把底层对象字节直接传给哈希算法, 无需任何处理.

flavor 的 size_type 成员类型影响容器和范围的大小 (通常为 size_t类型) 如何被序列化. 由于 size_t 的字节大小可能变化, 直接序列化该类型会导致为 64 位或 32 位编译时得到不同的哈希值. 使用固定宽度类型可以避免这一点.

在 boost/hash2/flavor.hpp中定义了三个预定义的 flavor:

struct default_flavor
{
    using size_type = std::uint32_t;
    static constexpr auto byte_order = endian::native;
};

struct little_endian_flavor
{
    using size_type = std::uint32_t;
    static constexpr auto byte_order = endian::little;
};

struct big_endian_flavor
{
    using size_type = std::uint32_t;
    static constexpr auto byte_order = endian::big;
};

当调用 hash_append 而未传入 flavor 时, 使用默认的那个: hash_append(h, {}, v);. 它会带来更高的性能, 但哈希值依赖于字节序.

可连续哈希的类型

hash_append(h, f, v) 做的第一件事是检查该类型在请求的字节序下是否 可连续哈希 (contiguously hashable) ——测试方式是 is_contiguously_hashable<T, Flavor::byte_order>::value. 当结果为 true时, 它会调用 h.update(&v, sizeof(v)).

整数类型

当 T 是整数类型 (bool, 即 int 或者 unsigned long之类的有符号或无符号整数类型, 或 char8_t 或者 char32_t之类的字符类型) 时, v 会在请求的字节序下被转换为它的字节表示 (一个 unsigned char 数组, 大小为 sizeof(T)) .

hash_append 则调用 h.update(p, n), 其中 p 是该表示的地址, 而 n 是它的大小.

例如, 值 0x01020304 (类型 std::uint32_t, 当 Flavor::byte_order 为 endian::little时) 会被转换为数组 { 0x04, 0x03, 0x02, 0x01 }.

int main()
{
    boost::hash2::fnv1a_32 h1;
    std::uint32_t v1 = 0x01020304;
    boost::hash2::hash_append( h1, boost::hash2::little_endian_flavor(), v1 );

    boost::hash2::fnv1a_32 h2;
    unsigned char v2[] = { 0x04, 0x03, 0x02, 0x01 };
    h2.update( v2, sizeof(v2) );

    assert( h1.result() == h2.result() );
}

浮点类型

当 T 是浮点类型 (目前仅支持 float 以及 double ) 时, v 会先转换为同等大小的无符号整数类型 (使用与 std::bit_cast等价的方式) , 随后 hash_append 被调用, 传入该转换后的值.

int main()
{
    boost::hash2::fnv1a_32 h1;
    float v1 = 3.14f;
    boost::hash2::hash_append( h1, {}, v1 );

    boost::hash2::fnv1a_32 h2;
    std::uint32_t v2 = 0x4048f5c3;
    boost::hash2::hash_append( h2, {}, v2 );

    assert( h1.result() == h2.result() );
}

然而, 这里有一个微妙之处. 对哈希函数 H 的要求指出: 如果 x == y, 则 H(x) == H(y). 但是 +0.0 == -0.0——尽管这两个值的位表示并不相同.

因此, 为了满足该要求, 如果 v 是负零, 会先把它替换为同一类型的正零, 然后再 bit_cast 转换为整数.

int main()
{
    boost::hash2::fnv1a_32 h1;
    boost::hash2::hash_append( h1, {}, +0.0 );

    boost::hash2::fnv1a_32 h2;
    boost::hash2::hash_append( h2, {}, -0.0 );

    assert( h1.result() == h2.result() );
}

枚举类型

当 T 是枚举类型时, v 会被转换为 T的底层类型, 然后转换后的值被传给 hash_append.

enum E: int
{
    v1 = 123
};

int main()
{
    boost::hash2::fnv1a_32 h1;
    boost::hash2::hash_append( h1, {}, v1 );

    boost::hash2::fnv1a_32 h2;
    int v2 = 123;
    boost::hash2::hash_append( h2, {}, v2 );

    assert( h1.result() == h2.result() );
}

指针

当 T 是指针类型时, 它会被转换为 std::uintptr_t ——使用 reinterpret_cast——然后转换后的值被传给 hash_append.

int x1 = 0;

int main()
{
    boost::hash2::fnv1a_32 h1;
    boost::hash2::hash_append( h1, {}, &x1 );

    boost::hash2::fnv1a_32 h2;
    boost::hash2::hash_append( h2, {}, reinterpret_cast<std::uintptr_t>(&x1) );

    assert( h1.result() == h2.result() );
}

数组

当 T 是数组类型 U[N]时, v 的元素会按顺序传给 hash_append .

这通过调用 hash_append_range(h, f, v + 0, v + N)来完成.

int main()
{
    boost::hash2::fnv1a_32 h1;
    int v1[4] = { 1, 2, 3, 4 };
    boost::hash2::hash_append( h1, {}, v1 );

    boost::hash2::fnv1a_32 h2;
    boost::hash2::hash_append_range( h2, {}, v1 + 0, v1 + 4 );

    assert( h1.result() == h2.result() );

    boost::hash2::fnv1a_32 h3;
    boost::hash2::hash_append( h3, {}, v1[0] );
    boost::hash2::hash_append( h3, {}, v1[1] );
    boost::hash2::hash_append( h3, {}, v1[2] );
    boost::hash2::hash_append( h3, {}, v1[3] );

    assert( h1.result() == h3.result() );
}

范围

当 T 是一个 范围 (range) (boost::container_hash::is_range<T>::value 为 true) 时, 其元素会按如下方式传给 hash_append :

  • 当 T 是一个 无序范围 (unordered range) (boost::container_hash::is_unordered_range<T>::value 为 true) 时, hash_append 会调用 hash_append_unordered_range(h, f, v.begin(), v.end()). hash_append_unordered_range 会从范围元素导出哈希值, 其方式使元素的顺序不影响该哈希值.

  • 当 T 是一个 连续范围 (contiguous range) (boost::container_hash::is_contiguous_range<T>::value 为 true) 时, hash_append 会先调用 hash_append_range(h, f, v.data(), v.data() + v.size()), 然后, 如果 has_constant_size<T>::value 为 false, 则调用 hash_append_size(h, f, v.size()).

  • 否则, hash_append 会先调用 hash_append_range(h, f, v.begin(), v.end()), 然后, 如果 has_constant_size<T>::value 为 false, 则调用 hash_append_size(h, f, m), 其中 m 为 std::distance(v.begin(), v.end()).

作为一种特殊情况, 为了满足对 hash_append 的调用必须总是导致至少一次对 Hash::update的调用这一要求, 对于常量大小为 0 的范围, 会调用 hash_append(h, f, '\x00') .

int main()
{
    boost::hash2::fnv1a_32 h1;
    std::vector<int> v1 = { 1, 2, 3, 4 };
    boost::hash2::hash_append( h1, {}, v1 );

    boost::hash2::fnv1a_32 h2;
    std::list<int> v2 = { 1, 2, 3, 4 };
    boost::hash2::hash_append( h2, {}, v2 );

    assert( h1.result() == h2.result() );

    boost::hash2::fnv1a_32 h3;
    boost::hash2::hash_append_range( h3, {}, v1.data(), v1.data() + v1.size() );
    boost::hash2::hash_append_size( h3, {}, v1.size() );

    assert( h1.result() == h3.result() );

    boost::hash2::fnv1a_32 h4;
    boost::hash2::hash_append_range( h4, {}, v2.begin(), v2.end() );
    boost::hash2::hash_append_size( h4, {}, std::distance(v2.begin(), v2.end()) );

    assert( h2.result() == h4.result() );
}

元组

当 T 是元组 (boost::container_hash::is_tuple_like<T>::value 为 true) 时, 其元素——由 get<I>(v) 针对 I 于 [0, std::tuple_size<T>::value) 中取得——会依次传给 hash_append.

作为一种特殊情况, 为了满足对 hash_append 的调用必须总是导致至少一次对 Hash::update的调用这一要求, 对于大小为 0 的元组, 会调用 hash_append(h, f, '\x00') .

int main()
{
    boost::hash2::fnv1a_32 h1;
    std::tuple<int, int, int> v1 = { 1, 2, 3 };
    boost::hash2::hash_append( h1, {}, v1 );

    boost::hash2::fnv1a_32 h2;
    boost::hash2::hash_append( h2, {}, get<0>(v1) );
    boost::hash2::hash_append( h2, {}, get<1>(v1) );
    boost::hash2::hash_append( h2, {}, get<2>(v1) );

    assert( h1.result() == h2.result() );
}

std::optional

当 T 是 std::optional的实例时, 先调用 hash_append(h, f, v.has_value()) , 然后, 如果 v 已包含值 (engaged) , 则调用 hash_append(h, f, *v) .

std::variant

当 T 是 std::variant的实例时:

  • 如果 T 无值 (valueless) , 则调用 hash_append(h, f, '\x00') ;

  • 否则, hash_append(h, f, v.index()) 被调用, 随后调用 hash_append(h, f, w), 其中 w 是 v当前活跃的备选项 (alternative) .

std::monostate

当 T 为 std::monostate时, 会调用 hash_append(h, f, '\x00') .

Described 类

当 T 是一个 described class (Described 类) (boost::container_hash::is_described_class<T>::value 为 true) 时, 会使用 Boost.Describe 原语来枚举其基类和成员; 然后, 对于 b 的每个基类子对象 v, 会调用 hash_append(h, f, b) ; 接着, 对于 m 的每个成员子对象 v, 会调用 hash_append(h, f, m) .

struct X
{
    int a;
};

BOOST_DESCRIBE_STRUCT(X, (), (a))

struct Y: public X
{
    int b;
};

BOOST_DESCRIBE_STRUCT(Y, (X), (b))

int main()
{
    boost::hash2::fnv1a_32 h1;
    X v1 = { { 1 }, 2 };
    boost::hash2::hash_append( h1, {}, v1 );

    boost::hash2::fnv1a_32 h2;
    boost::hash2::hash_append( h2, {}, v1.a );
    boost::hash2::hash_append( h2, {}, v1.b );

    assert( h1.result() == h2.result() );
}

作为一种特殊情况, 为了满足对 hash_append 的调用必须总是导致至少一次对 Hash::update的调用这一要求, 对于没有任何基类或成员的类, 会调用 hash_append(h, f, '\x00') .

用户自定义类型

当 T 是不属于上述任何类别的用户自定义类型时, 它需要通过定义适当的 tag_invoke 重载来提供自己的哈希支持.

这个 tag_invoke 重载需要具有以下形式:

template<class Provider, class Hash, class Flavor>
void tag_invoke( boost::hash2::hash_append_tag const&, Provider const& pr, Hash& h, Flavor const& f, X const* v );

其中 X 是该用户自定义类型.

它可以在 X的命名空间中定义为独立的自由函数, 但推荐的做法是把它定义为 friend 定义中的内联 X:

#include <boost/hash2/hash_append_fwd.hpp>
#include <string>

class X
{
private:

    std::string a;
    int b;

    // not part of the salient state
    void const* c;

public:

    friend bool operator==( X const& x1, X const& x2 )
    {
        return x1.a == x2.a && x1.b == x2.b;
    }

    template<class Provider, class Hash, class Flavor>
    friend void tag_invoke(
        boost::hash2::hash_append_tag const&, Provider const&,
        Hash& h, Flavor const& f, X const* v )
    {
        boost::hash2::hash_append(h, f, v->a);
        boost::hash2::hash_append(h, f, v->b);
    }
};

这个重载需要满足哈希函数的三个要求. 在实践中, 这意味着相等 (operator==) 与哈希 (tag_invoke) 的定义必须就哪些成员需要纳入达成一致.

在上面的示例中, 成员 c 不是对象状态的一部分, 因此它既不在 operator==中参与比较, 也不在 中被纳入对象的 message (消息) tag_invoke.

tag_invoke 的具体实现因类型而异. 一般而言, 它需要在最终产生的 message (消息) 中包含对象值的全部关键部分, 但具体做法取决于类型.

作为另一个示例, 下面演示了如何为"内联字符串"类型 (一种把字符 (最多某个最大数量) 直接存储在类型自身中的字符串) 实现 tag_invoke :

#include <boost/hash2/hash_append_fwd.hpp>
#include <algorithm>
#include <cstdint>

class Str
{
private:

    static constexpr std::size_t N = 32;

    std::uint8_t size_ = 0;
    char data_[ N ] = {};

public:

    friend constexpr bool operator==( Str const& x1, Str const& x2 )
    {
        return x1.size_ == x2.size_ && std::equal( x1.data_, x1.data_ + x1.size_, x2.data_ );
    }

    template<class Provider, class Hash, class Flavor>
    friend constexpr void tag_invoke(
        boost::hash2::hash_append_tag const&, Provider const&,
        Hash& h, Flavor const& f, Str const* v )
    {
        boost::hash2::hash_append_range_and_size( h, f, v->data_, v->data_ + v->size_ );
    }
};
注释
 这个示例仅作说明之用; 实际上, 上述类型很可能会提供 begin()、 end()、 data()和 size() 成员函数, 这将使它成为一个 连续范围 (contiguous range) , 从而内建支持会自动做正确的事情.

我们在 Provider 中忽略的 tag_invoke 实参会接收到一个 hash_append_provider类型的对象. 该对象包含静态成员函数, 它们是 <boost/hash2/hash_append_fwd.hpp>中声明的函数的副本. 这使得可以在编写 tag_invoke 重载时无需包含 <boost/hash2/hash_append_fwd.hpp>, 从而使该头文件不依赖 Hash2 的任何内容.

例如, 我们也可以这样声明上面的用户自定义类型 X :

#include <string>

class X
{
private:

    std::string a;
    int b;

    // not part of the salient state
    void const* c;

public:

    friend bool operator==( X const& x1, X const& x2 )
    {
        return x1.a == x2.a && x1.b == x2.b;
    }

    template<class Provider, class Hash, class Flavor>
    friend void tag_invoke(
        boost::hash2::hash_append_tag const&, Provider const& pr,
        Hash& h, Flavor const& f, X const* v )
    {
        pr.hash_append(h, f, v->a);
        pr.hash_append(h, f, v->b);
    }
};

用法示例

与无序容器一起使用

要把我们的 哈希算法 之一 (例如 fnv1a_64) 与无序容器 (例如 boost::unordered_flat_map) 一起使用, 我们需要创建一个适配器类, 使其暴露与 std::hash<T>兼容的接口.

为此, 在我们适配器的 operator()(T const& v) 成员函数中, 我们需要创建 h 哈希算法 的一个实例, 用 hash_append(h, {}, v) 把 v 发送给它, 然后用 h.result() 提取结果并作为 std::size_t返回.

下面的最小可运行示例演示了这一做法.

#include <boost/hash2/fnv1a.hpp>
#include <boost/hash2/hash_append.hpp>
#include <boost/hash2/get_integral_result.hpp>
#include <boost/unordered/unordered_flat_map.hpp>
#include <string>

template<class T, class H> class hash
{
public:

    std::size_t operator()( T const& v ) const
    {
        H h;
        boost::hash2::hash_append( h, {}, v );
        return boost::hash2::get_integral_result<std::size_t>( h );
    }
};

int main()
{
    using hasher = hash<std::string, boost::hash2::fnv1a_64>;

    boost::unordered_flat_map<std::string, int, hasher> map;

    map[ "foo" ] = 1;
    map[ "bar" ] = 2;
}

由于 hash<T, H> 不仅以键类型 T为模板参数, 还以哈希算法类型 H为模板参数, 我们可以很容易地从 fnv1a_64 切换到另一个哈希算法 (例如 siphash_64) , 只需修改这一行:

    using hasher = hash<std::string, boost::hash2::fnv1a_64>;

to

    using hasher = hash<std::string, boost::hash2::siphash_64>;

这样可以工作, 但 SipHash 并不打算在没有初始随机种子的情况下使用, 而我们没有传入任何种子. 为了纠正这一点, 让我们修改 hash<T, H> , 使其具有一个接受 uint64_t类型种子的构造函数:

#include <boost/hash2/siphash.hpp>
#include <boost/hash2/hash_append.hpp>
#include <boost/hash2/get_integral_result.hpp>
#include <boost/unordered/unordered_flat_map.hpp>
#include <string>

template<class T, class H> class hash
{
private:

    std::uint64_t seed_;

public:

    explicit hash( std::uint64_t seed ): seed_( seed )
    {
    }

    std::size_t operator()( T const& v ) const
    {
        H h( seed_ );
        boost::hash2::hash_append( h, {}, v );
        return boost::hash2::get_integral_result<std::size_t>( h );
    }
};

int main()
{
    std::uint64_t seed = 0x0102030405060708ull;

    using hasher = hash<std::string, boost::hash2::siphash_64>;

    boost::unordered_flat_map<std::string, int, hasher> map( 0, hasher( seed ) );

    map[ "foo" ] = 1;
    map[ "bar" ] = 2;
}
注释
 在真实的代码中, 种子不会是硬编码的常量; 理想情况下, 每个无序容器实例都应拥有自己的随机且不可预测的种子.

由于所有符合本库要求的 哈希算法 都可以用 uint64_t类型的初始种子构造, 上面的代码可以配合其中任何一个工作.

这对于任何实际用途都足够了, 但原则上, 按照规范 SipHash64 接受 16 字节的种子, 而我们 (实际) 只传了 8 字节. 我们可以再次修改 hash , 这次使用一个接受字节序列作为种子的构造函数:

#include <boost/hash2/siphash.hpp>
#include <boost/hash2/hash_append.hpp>
#include <boost/hash2/get_integral_result.hpp>
#include <boost/unordered/unordered_flat_map.hpp>
#include <string>

template<class T, class H> class hash
{
private:

    H h_;

public:

    hash( unsigned char const* p, std::size_t n ): h_( p, n )
    {
    }

    std::size_t operator()( T const& v ) const
    {
        H h( h_ );
        boost::hash2::hash_append( h, {}, v );
        return boost::hash2::get_integral_result<std::size_t>( h );
    }
};

int main()
{
    unsigned char const seed[ 16 ] =
    {
        0x01, 0x02, 0x03, 0x04, 0x05, 0x06, 0x07, 0x08,
        0x09, 0x0A, 0x0B, 0x0C, 0x0D, 0x0E, 0x0F, 0x10
    };

    using hasher = hash<std::string, boost::hash2::siphash_64>;

    boost::unordered_flat_map<std::string, int, hasher> map( 0, hasher( seed, sizeof(seed) ) );

    map[ "foo" ] = 1;
    map[ "bar" ] = 2;
}

和前面一样, 从字节序列构造是 哈希算法 接口的必备部分, 因此上面的代码可以配合其中任何一个工作.

为了避免像我们在 uint64_t 的情形中那样存储初始种子——这会需要一次分配, 因为 n 可以是任意长度的, 从而必须使用 std::vector<unsigned char> ——我们构造哈希算法的一个实例 h_ , 把种子传给它, 以捕获初始的带种子状态, 然后在 operator()中复制这个带种子的实例.

但一旦这样做, 我们可能会注意到: 可以用三个受支持的构造函数中的任何一个来构造这个初始实例 h_ , 而不只是接受字节序列的那个:

这种 hash<T, H> 变体是通用的; 它可以在无种子、带无符号整数种子、带字节序列种子的情况下使用.

注释
 在真实的代码中, 你可能会想省略默认构造函数, 以避免意外使用未做种子的哈希算法.

对 hash还可以做最后一个修改. 在上面的示例中, 我们无条件地使用 SipHash 的 64 位变体, 尽管我们只需要 std::size_t 类型的结果——因为这是 std::hash 所要求的.

从性能角度看, 更好的做法是: 当 siphash_32 为 32 位时使用 std::size_t , 为 64 位时使用 siphash_64 .

为此, 我们可以让 hash 接受两个哈希算法——一个 32 位、一个 64 位——并让它自动选择合适的一个:

#include <boost/hash2/siphash.hpp>
#include <boost/hash2/md5.hpp>
#include <boost/hash2/hash_append.hpp>
#include <boost/hash2/get_integral_result.hpp>
#include <boost/unordered/unordered_flat_map.hpp>
#include <boost/core/type_name.hpp>
#include <type_traits>
#include <string>
#include <iostream>

template<class T, class H1, class H2 = H1> class hash
{
public:

    using hash_type = typename std::conditional<
        sizeof(typename H1::result_type) == sizeof(std::size_t), H1, H2
    >::type;

private:

    hash_type h_;

public:

    hash(): h_()
    {
    }

    explicit hash( std::uint64_t seed ): h_( seed )
    {
    }

    hash( unsigned char const* p, std::size_t n ): h_( p, n )
    {
    }

    std::size_t operator()( T const& v ) const
    {
        hash_type h( h_ );
        boost::hash2::hash_append( h, {}, v );
        return boost::hash2::get_integral_result<std::size_t>( h );
    }
};

int main()
{
    {
        using hasher = hash<std::string, boost::hash2::siphash_32, boost::hash2::siphash_64>;

        std::cout << boost::core::type_name<hasher>() << " uses "
            << boost::core::type_name<hasher::hash_type>() << std::endl;

        boost::unordered_flat_map<std::string, int, hasher> map;

        map[ "foo" ] = 1;
        map[ "bar" ] = 2;
    }

    {
        using hasher = hash<std::string, boost::hash2::md5_128>;

        std::cout << boost::core::type_name<hasher>() << " uses "
            << boost::core::type_name<hasher::hash_type>() << std::endl;

        boost::unordered_flat_map<std::string, int, hasher> map;

        map[ "foo" ] = 1;
        map[ "bar" ] = 2;
    }
}

md5sum

一个命令行实用工具, 打印作为参数传入的文件列表的 MD5 摘要.

#include <boost/hash2/md5.hpp>
#include <array>
#include <string>
#include <cerrno>
#include <cstdio>

static void md5sum( std::FILE* f, char const* fn )
{
    boost::hash2::md5_128 hash;

    int const N = 4096;
    unsigned char buffer[ N ];

    for( ;; )
    {
        std::size_t n = std::fread( buffer, 1, N, f );

        if( std::ferror( f ) )
        {
            std::fprintf( stderr, "'%s': read error: %s\n", fn, std::strerror( errno ) );
            return;
        }

        if( n == 0 ) break;

        hash.update( buffer, n );
    }

    std::string digest = to_string( hash.result() );

    std::printf( "%s *%s\n", digest.c_str(), fn );
}

int main( int argc, char const* argv[] )
{
    for( int i = 1; i < argc; ++i )
    {
        std::FILE* f = std::fopen( argv[i], "rb" );

        if( f == 0 )
        {
            std::fprintf( stderr, "'%s': open error: %s\n", argv[i], std::strerror( errno ) );
            continue;
        }

        md5sum( f, argv[i] );

        std::fclose( f );
    }
}

结果扩展

我们的某些哈希算法 (例如 xxhash_64 以及 siphash_64) 拥有超过 64 位的内部状态, 却只产生 64 位的结果.

如果我们正在用其中某个算法生成文件或内容校验和、不容忍碰撞、并且要处理大量文件或条目 (数百万量级) , 那么改用 128 位摘要可能更好.

由于这些算法维护着超过 64 位的状态, 我们可以调用 result() 两次, 得到有意义的 128 位结果.

下面的示例演示了具体做法. 它定义了一个算法 xxhash_128 , 其实现方式是包装 xxhash_64 并适当地重新定义其 result_type 以及 result 成员:

#include <boost/hash2/xxhash.hpp>
#include <boost/hash2/digest.hpp>
#include <boost/endian/conversion.hpp>

class xxhash_128: private boost::hash2::xxhash_64
{
public:

    using result_type = boost::hash2::digest<16>;

    using xxhash_64::xxhash_64;
    using xxhash_64::update;

    result_type result()
    {
        std::uint64_t r1 = xxhash_64::result();
        std::uint64_t r2 = xxhash_64::result();

        result_type r = {};

        boost::endian::store_little_u64( r.data() + 0, r1 );
        boost::endian::store_little_u64( r.data() + 8, r2 );

        return r;
    }
};

#include <string>
#include <iostream>

int main()
{
    std::string tv( "The quick brown fox jumps over the lazy dog" );

    xxhash_128 hash( 43 );
    hash.update( tv.data(), tv.size() );

    std::cout << hash.result() << std::endl;
}

特征 (trait) is_trivially_equality_comparable 被本库用于检测 可平凡相等比较 (trivially equality comparable) 的类型.

如果对于该类型的两个值 以及 , x 等价于 y , 则该类型是 x == y 可平凡相等比较 (trivially equality comparable) std::memcmp( &x, &y, sizeof(x) ) == 0的.

也就是说, 对于可平凡相等比较的类型, 比较它们的值等同于比较它们的存储字节表示.

这使 hash_append 可以假定标识对象值的 message (消息) 就是对象的存储字节.

is_trivially_equality_comparable 可针对用户自定义类型进行特化, 如果默认实现不能给出正确结果.

例如, 对于以下类型

struct X
{
    int v;
};

bool operator==( X const& x1, X const& x2 )
{
    return x1.v == x2.v;
}

(在假定它没有填充字节的前提下, 即 sizeof(X) == sizeof(int)) is_trivially_equality_comparable<X>::value 默认将为 false , 但该类型满足可平凡相等比较的要求, 因此可以添加一个特化:

template<> struct boost::hash2::is_trivially_equality_comparable<X>: std::true_type {};

或者, 如果你想保险一些,

template<> struct boost::hash2::is_trivially_equality_comparable<X>:
  std::integral_constant<bool, sizeof(X) == sizeof(int)> {};

另一方面, 以下类型

enum E: unsigned {};

bool operator==( E e1, E e2 )
{
    return e1 % 256 == e2 % 256;
}

不是可平凡相等比较的 (因为 (E)0x204 == (E)0x704, 但 memcmp 会给出非零结果) , 而 is_trivially_equality_comparable<E>::value 默认将为 true .

在这种 (相当罕见的) 情况下, 可以添加一个特化来报告 false:

template<> struct boost::hash2::is_trivially_equality_comparable<E>: std::false_type {};

把 v 的表示追加到存储在 h中的消息.

效果:

  • 如果 is_contiguously_hashable<T, Flavor::byte_order>::value 为 true, 则调用 h.update(&v, sizeof(v));

  • 如果 std::is_integral<T>::value 为 true, 则在 v 所请求的字节序下取得 Flavor::byte_order的字节表示, 然后调用 h.update(p, n) , 其中 p 是该表示的地址, 而 n 为 sizeof(v);

  • 如果 std::is_floating_point<T>::value 为真, 先在 v 为负零时把它替换为正零, 然后调用 hash_append(h, f, std::bit_cast<U>(v)), 其中 U 是与 T大小相同的无符号整数类型;

  • 如果 std::is_pointer<T>::value 为 true, 则调用 hash_append(h, f, reinterpret_cast<std::uintptr_t>(v));

  • 如果 T 为 std::nullptr_t, 则调用 hash_append(h, f, static_cast<void*>(v));

  • 如果 T 是数组类型 U[N], 则调用 hash_append_range(h, f, v + 0, v + N);

  • 如果 tag_invoke 存在适用于 T的合适重载, 则 (无限定地) 调用 tag_invoke(hash_append_tag(), hash_append_provider(), h, f, v);

  • 如果 std::is_enum<T>::value 为 true, 则调用 hash_append(h, f, w), 其中 w 是 v 转换为 T底层类型后的值;

  • 如果 boost::container_hash::is_unordered_range<T>::value 为 true, 则调用 hash_append_unordered_range(h, f, v.begin(), v.end());

  • 如果 boost::container_hash::is_contiguous_range<T>::value 为 true 并且

    • has_constant_size<T>::value 为 true, 则调用 hash_append_range(h, f, v.data(), v.data() + v.size());

    • has_constant_size<T>::value 为 false, 则调用 hash_append_range_and_size(h, f, v.data(), v.data() + v.size());

  • 如果 boost::container_hash::is_range<T>::value 为 true 并且

    • has_constant_size<T>::value 为 true, 则调用 hash_append_range(h, f, v.begin(), v.end());

    • has_constant_size<T>::value 为 false, 则调用 hash_append_range_and_size(h, f, v.begin(), v.end());

  • 如果 boost::container_hash::is_tuple_like<T>::value 为 true, 则对每个元组元素 hash_append(h, f, w) 调用 w;

  • 如果 boost::container_hash::is_described_class<T>::value 为 true, 则对 hash_append(h, f, b) 的每个基类子对象 b 调用 v, 然后对 hash_append(h, f, m) 的每个成员子对象 m 调用 v;

  • 如果 T 是 std::optional的实例, 则调用 hash_append(h, f, v.has_value()), 然后, 如果 v 已包含值 (engaged) , 则调用 hash_append(h, f, *v);

  • 如果 T 是 std::variant的实例, 且 v 非无值 (valueless) , 则调用 hash_append_size(h, f, v.index()) 以及 hash_append(h, f, w) , 其中 w 是 v当前活跃的备选项 (alternative) ;

  • 如果 T 为 std::monostate, 则调用 hash_append(h, f, '\x00');

  • 否则, 结果为编译期错误.

备注:

如果按上述描述不会产生任何调用 (例如, 对于常量大小为零的范围、无值的 std::variant, 或没有基类和成员的 described struct ) , 则会进行一次对 hash_append(h, f, '\x00') 的调用, 以满足 hash_append 总是导致至少一次对 Hash::update的调用这一要求.

hash_append_range
template<class Hash, class Flavor = default_flavor, class It>
constexpr void hash_append_range( Hash& h, Flavor const& f, It first, It last );

把范围 [first, last) 的元素的表示追加到存储在 h中的消息.

要求:

It 必须是 iterator (迭代器) 类型. [first, last) 必须是有效的 迭代器范围 (iterator range) .

效果:

  • 如果 It 为 T* 以及 is_contiguously_hashable<T, Flavor::byte_order>::value 为 true, 则调用 h.update(first, (last - first) * sizeof(T));.

  • 否则, 对于 v 所表示的范围中的每个元素 [first, last), 调用 hash_append(h, f, v);.

备注:

如果 hash_append_range 在常量表达式中被调用, 则可连续哈希优化仅适用于 unsigned char* 以及 unsigned char const*.

hash_append_size
template<class Hash, class Flavor = default_flavor, class T>
constexpr void hash_append_size( Hash& h, Flavor const& f, T const& v );

把 v的表示 (转换为 Flavor::size_type后) 追加到存储在 h中的消息.

要求:

T 必须是整数类型.

效果:

Equivalent to hash_append(h, f, static_cast<typename Flavor::size_type>(v));

hash_append_range_and_size
template<class Hash, class Flavor = default_flavor, class It>
constexpr void hash_append_range_and_size( Hash& h, Flavor const& f, It first, It last );

把范围 [first, last)的元素的表示 (随后跟上该范围的大小) 追加到存储在 h中的消息.

要求:

It 必须是 iterator (迭代器) 类型. [first, last) 必须是有效的 迭代器范围 (iterator range) .

效果:

等价于 hash_append_range(h, f, first, last); hash_append_size(h, f, m);, 其中 m 为 std::distance(first, last).

hash_append_unordered_range
template<class Hash, class Flavor = default_flavor, class It>
constexpr void hash_append_unordered_range( Hash& h, Flavor const& f, It first, It last );

从范围 [first, last)的元素的表示构造一个值, 其构造方式使元素的顺序不影响结果, 然后把该值 (随后跟上该范围的大小) 追加到存储在 h中的消息.

要求:

It 必须是 iterator (迭代器) 类型. [first, last) 必须是有效的 迭代器范围 (iterator range) .

效果:

对于 v 所表示的范围中的每个元素 [first, last), 通过如下方式取得一个哈希值 r :

Hash h2(h);
hash_append(h2, f, v);
auto r = h2.result();

然后以一种对其顺序不敏感的方式组合这样得到的 r 值, 产生组合值 q. 调用 hash_append(h, f, q), 随后调用 hash_append(h, f, m), 其中 m 为 std::distance(first, last).

struct hash_append_tag
{
};

hash_append_tag 是一个标签类型, 用作 tag_invoke 重载的第一个实参, 以标识 hash_append 操作.

hash_append_provider
struct hash_append_provider
{
    template<class Hash, class Flavor, class T>
    static constexpr void hash_append( Hash& h, Flavor const& f, T const& v );

    template<class Hash, class Flavor, class It>
    static constexpr void hash_append_range( Hash& h, Flavor const& f, It first, It last );

    template<class Hash, class Flavor, class T>
    static constexpr void hash_append_size( Hash& h, Flavor const& f, T const& v );

    template<class Hash, class Flavor, class It>
    static constexpr void hash_append_range_and_size( Hash& h, Flavor const& f,
        It first, It last );

    template<class Hash, class Flavor, class It>
    static constexpr void hash_append_unordered_range( Hash& h, Flavor const& f,
        It first, It last );
};

一个 hash_append_provider 类型的对象会作为 tag_invoke 重载的第二个实参传入.

其所有成员函数都会调用 boost::hash2中同名对应函数.
