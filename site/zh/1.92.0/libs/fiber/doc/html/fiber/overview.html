概述

Implementations: fcontext_t, ucontext_t and WinFiber

Boost.Fiber 提供了一个以协作方式调度的微线程/用户态线程 (纤程) 框架. 该 API 包含用于管理和同步纤程的类与函数, 与 标准线程支持库 类似.

每个纤程都有自己的栈.

纤程可以保存当前执行状态——包括所有寄存器和 CPU 标志位、指令指针和栈指针——并在之后恢复这一状态. 其思想是利用协作式调度 (相对于抢占式调度的线程) 让多个执行路径运行在单个线程上. 正在运行的纤程显式决定何时让出以允许另一个纤程运行 (上下文切换). Boost.Fiber 内部使用 call/cc (来自 Boost.Context); 本库中的类负责管理、调度并在需要时同步这些执行上下文. 在 x86 上, 线程间的上下文切换通常需要数千个 CPU 周期, 而纤程切换只需不到一百个周期. 纤程在任何时刻都只运行在单个线程上.

要使用这里描述的类和函数, 可以包含每个类或函数说明中指定的具体头文件, 也可以包含库的主头文件:

#include <boost/fiber/all.hpp>

该头文件会依次包含所有其他头文件.

使用的命名空间如下:

namespace boost::fibers
namespace boost::this_fiber

纤程与线程

控制权在给定线程上启动的纤程之间协作式传递. 在给定时刻, 在给定线程上, 至多只有一个纤程在运行.

在给定线程上派生更多纤程并不会把你的程序分布到更多硬件核心上, 尽管它可以更有效地利用程序当前运行的核心.

另一方面, 纤程可以安全地访问其父线程独占的任何资源, 而无需显式地保护该资源免受同一线程上其他纤程的并发访问. 你已经得到保证: 该线程上没有其他纤程正在并发地触碰该资源. 在向遗留代码引入并发时, 这一点可能特别重要. 你可以安全地启动运行旧代码的纤程, 并使用异步 I/O 来交错执行.

实际上, 纤程提供了一种基于异步 I/O 组织并发代码的自然方式. 运行在纤程上的代码不必把完成处理器串成链, 而是可以进行看起来像普通阻塞函数调用的调用. 该调用可以低开销地挂起调用方纤程, 让同一线程上的其他纤程运行. 当操作完成时, 被挂起的纤程恢复运行, 无需显式保存或恢复其状态. 其局部栈变量在调用期间持续存在.

纤程可以从一个线程迁移到另一个线程, 不过该库默认并不这样做. 你可以提供一个自定义调度器来在线程之间迁移纤程. 你可以指定自定义纤程属性来帮助你的调度器决定哪些纤程允许迁移. 更多细节请参见 跨线程迁移纤程 和 定制.

Boost.Fiber 支持 multiplex fibers across multiple cores (参见 numa::work_stealing).

在特定线程上启动的纤程会继续在该线程上运行, 除非被迁移. 它可能被其他线程解除阻塞 (见下文 阻塞), 但那只会把该纤程在其当前线程上从 "blocked" 转变为 "ready"——它不会导致该纤程在解除其阻塞的线程上恢复运行.

thread-local storage

除非被迁移, 纤程可以访问线程局部存储; 然而该存储会由运行在同一线程上的所有纤程共享. 关于纤程局部存储, 请参见 fiber_specific_ptr.

BOOST_FIBERS_NO_ATOMICS

本库提供的纤程同步对象默认会安全地同步运行在不同线程上的纤程. 然而, 通过以定义了 BOOST_FIBERS_NO_ATOMICS 的方式构建本库, 可以 (出于性能考虑) 移除这一层同步. 当库以该宏构建时, 你必须确保引用特定同步对象的所有纤程都运行在同一线程中. 请参见 同步.

阻塞

通常, 当本文档说某个特定纤程 阻塞 (或等价地, 挂起) 时, 意思是它让出控制权, 允许同一线程上的其他纤程运行. Boost.Fiber 提供的同步机制都具有这种行为.

当然, 纤程可以使用普通的线程同步机制; 然而, 调用这些机制中任何一种的纤程会阻塞其整个线程, 使该线程在此期间无法运行任何其他纤程. 例如, 当一个纤程想等待同一线程中另一个纤程的值时, 使用 std::future 将是不幸的: std::future::get() 会阻塞整个线程, 阻止另一个纤程传递其值. 请改用 future<>.

类似地, 调用普通阻塞 I/O 操作的纤程会阻塞其整个线程. 我们鼓励纤程作者始终使用异步 I/O. Boost.Asio 和其他异步 I/O 操作可以直截了当地适配到 Boost.Fiber: 参见 将纤程与异步回调集成.

Boost.Fiber 依赖于 Boost.Context. 需要 Boost 1.61.0 或更高版本.

注释

This library requires C++11!

重要

Windows using fcontext_t: turn off global program optimization (/GL) and change /EHsc (compiler assumes that functions declared as extern "C" never throw a C++ exception) to /EHs (tells compiler assumes that functions declared as extern "C" may throw an exception).
