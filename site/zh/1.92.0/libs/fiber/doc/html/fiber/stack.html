Stack allocation

Support for valgrind
Support for sanitizers

fiber 内部使用一个 __econtext__ 来管理一组寄存器和一个栈. 栈所用内存的分配/释放通过 stack_allocator 完成, 该分配器必须满足 栈分配器概念.

stack_allocator 可以传递给 fiber::fiber() 或 fibers::async().

栈分配器概念

stack_allocator 必须满足下表所示的 栈分配器概念 要求, 其中 a 是 stack_allocator 类型的对象, sctx 是一个 stack_context, 而 size 是 std::size_t:

表达式

返回类型

notes

a(size)

creates a stack allocator

a.allocate()

stack_context

creates a stack

a.deallocate( sctx)

void

deallocates the stack created by a.allocate()

重要

The implementation of allocate() might include logic to protect against exceeding the context's available stack size rather than leaving it as undefined behaviour.

重要

调用 deallocate() 时, 若传入的 stack_context 并非由 allocate() 获得, 则会导致未定义行为.

注释

栈内存并不要求对齐; 对齐在 __econtext__ 内部进行.

另见 Boost.Context 栈分配. 特别是, traits_type 的各方法与 boost::context::stack_traits 中所述一致.

protected_fixedsize_stack 类

Boost.Fiber 提供了类 protected_fixedsize_stack, 它满足 栈分配器概念. 它在每个栈的末尾追加一个保护页, 以防止栈越界. 若保护页被访问 (读或写操作), 操作系统将产生段错误/访问违例.

重要

使用 protected_fixedsize_stack 代价高昂. 以这种类型的栈启动新纤程需要付出设置内存保护的额外开销; 一旦分配完成, 该栈的使用效率与 fixedsize_stack 一样高.

注释

The appended guard page is not mapped to physical memory, only virtual addresses are used. 

#include <boost/fiber/protected_fixedsize.hpp>

namespace boost {
namespace fibers {

struct protected_fixedsize {
    protected_fixesize(std::size_t size = traits_type::default_size());

    stack_context allocate();

    void deallocate( stack_context &);
}

}}

Member function allocate() 

stack_context allocate();

前置条件:

traits_type::minimum_size() <= size 和 traits_type::is_unbounded() || ( size <= traits_type::maximum_size() ).

效果:

分配至少 size 字节的内存, 并把指向栈的指针及其实际大小存入 sctx. 视体系结构而定 (栈向下/向上增长), 存储的地址是栈的最高/最低地址.

Member function deallocate() 

void deallocate( stack_context & sctx);

前置条件:

sctx.sp 有效, traits_type::minimum_size() <= sctx.size 和 traits_type::is_unbounded() || ( sctx.size <= traits_type::maximum_size() ).

效果:

Deallocates the stack space.

pooled_fixedsize_stack 类

Boost.Fiber 提供了类 pooled_fixedsize_stack, 它满足 栈分配器概念. 与 protected_fixedsize_stack 不同, 它不在每个栈的末尾追加保护页. 内存由 boost::pool<> 内部管理.

#include <boost/fiber/pooled_fixedsize_stack.hpp>

namespace boost {
namespace fibers {

struct pooled_fixedsize_stack {
    pooled_fixedsize_stack(std::size_t stack_size = traits_type::default_size(), std::size_t next_size = 32, std::size_t max_size = 0);

    stack_context allocate();

    void deallocate( stack_context &);
}

}}

Constructor 

pooled_fixedsize_stack(std::size_t stack_size, std::size_t next_size, std::size_t max_size);

前置条件:

traits_type::is_unbounded() || ( traits_type::maximum_size() >= stack_size) 和 0 < next_size.

效果:

分配至少 stack_size 字节的内存, 并将指向栈及其实际大小的指针存入 sctx. 存储的地址是栈的最高/最低地址, 取决于架构 (栈向下/向上增长). 参数 next_size 决定 *this 第一次需要分配系统内存时向系统请求的栈数量. 第三个参数 max_size 控制可为栈分配多少内存——值为零表示没有上限.

Member function allocate() 

stack_context allocate();

前置条件:

traits_type::is_unbounded() || ( traits_type::maximum_size() >= stack_size).

效果:

分配至少 stack_size 字节的内存, 并把指向栈的指针及其实际大小存入 sctx. 视体系结构而定 (栈向下/向上增长), 存储的地址是栈的最高/最低地址.

Member function deallocate() 

void deallocate( stack_context & sctx);

前置条件:

sctx.sp 有效, traits_type::is_unbounded() || ( traits_type::maximum_size() >= sctx.size).

效果:

Deallocates the stack space.

注释

该栈分配器不是线程安全的.

fixedsize_stack 类

Boost.Fiber 提供了类 fixedsize_stack, 它满足 栈分配器概念. 与 protected_fixedsize_stack 不同, 它不在每个栈的末尾追加保护页. 内存仅由 std::malloc() 和 std::free() 管理.

#include <boost/context/fixedsize_stack.hpp>

namespace boost {
namespace fibers {

struct fixedsize_stack {
    fixedsize_stack(std::size_t size = traits_type::default_size());

    stack_context allocate();

    void deallocate( stack_context &);
}

}}

Member function allocate() 

stack_context allocate();

前置条件:

traits_type::minimum_size() <= size 和 traits_type::is_unbounded() || ( traits_type::maximum_size() >= size).

效果:

分配至少 size 字节的内存, 并把指向栈的指针及其实际大小存入 sctx. 视体系结构而定 (栈向下/向上增长), 存储的地址是栈的最高/最低地址.

Member function deallocate() 

void deallocate( stack_context & sctx);

前置条件:

sctx.sp 有效, traits_type::minimum_size() <= sctx.size 和 traits_type::is_unbounded() || ( traits_type::maximum_size() >= sctx.size).

效果:

Deallocates the stack space.

segmented_stack 类

Boost.Fiber 支持使用 segmented_stack, 即栈按需增长. 纤程创建时具有最小栈大小, 并会按需增加. 类 segmented_stack 满足 栈分配器概念. 与 protected_fixedsize_stack 和 fixedsize_stack 不同, 它创建的栈按需增长.

注释

分段栈目前仅受 gcc (自版本 4.7 起) 和 clang (自版本 3.4 起) 支持. 要使用 segmented_stack, Boost.Fiber 必须以属性 segmented-stacks 构建, 例如 toolset=gcc segmented-stacks=on, 并在 b2/bjam 命令行上应用 BOOST_USE_SEGMENTED_STACKS.

注释

分段栈只能与使用属性 context-impl=ucontext 的 callcc() 一起使用.

#include <boost/fiber/segmented_stack.hpp>

namespace boost {
namespace fibers {

struct segmented_stack {
    segmented_stack(std::size_t stack_size = traits_type::default_size());

    stack_context allocate();

    void deallocate( stack_context &);
}

}}

Member function allocate() 

stack_context allocate();

前置条件:

traits_type::minimum_size() <= size 和 traits_type::is_unbounded() || ( traits_type::maximum_size() >= size).

效果:

分配至少 size 字节的内存, 并把指向栈的指针及其实际大小存入 sctx. 视体系结构而定 (栈向下/向上增长), 存储的地址是栈的最高/最低地址.

Member function deallocate() 

void deallocate( stack_context & sctx);

前置条件:

sctx.sp 有效, traits_type::minimum_size() <= sctx.size 和 traits_type::is_unbounded() || ( traits_type::maximum_size() >= sctx.size).

效果:

Deallocates the stack space.

注释

若该库以分段栈方式编译, 则 segmented_stack 是唯一可用的栈分配器.
