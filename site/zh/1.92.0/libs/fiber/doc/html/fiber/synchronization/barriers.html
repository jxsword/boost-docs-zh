屏障

屏障是一个概念, 也称为会合点, 它是多个执行上下文 (纤程) 之间的同步点. 屏障为特定数量的纤程 (n) 进行配置, 纤程到达屏障时必须等待, 直到全部 n 个纤程都已到达. 一旦第 n 个纤程到达屏障, 所有等待的纤程即可继续执行, 屏障也被重置.

屏障会自动重置这一点很重要. 考虑这样一种情形: 启动若干纤程, 但只想等待其中第一个完成. 你可能会想用 barrier(2) 作为同步机制, 让每个新纤程调用其 barrier::wait() 方法, 然后在启动纤程中调用 wait(), 等待第一个其他纤程完成.

这确实会解除启动纤程的阻塞. 不幸的是, 它会继续阻塞其余纤程.

考虑以下场景:

  1. 纤程 “main” 启动纤程 A、B、C 和 D, 然后调用 barrier::wait().
  2. 纤程 C 最先完成, 同样调用 barrier::wait().
  3. 纤程 “main” 如预期解除阻塞.
  4. 纤程 B 调用 barrier::wait(). 纤程 B 被阻塞!
  5. 纤程 A 调用 barrier::wait(). 纤程 A 和 B 解除阻塞.
  6. 纤程 D 调用 barrier::wait(). 纤程 D 被无限期阻塞.

(另见 when_any, 简单完成.)

注释

将屏障的生命周期与其任何一个参与纤程绑定是不明智的. 尽管在概念上所有等待的纤程会“同时,”被唤醒, 但由于纤程的本性, 实际上它们将按不确定的顺序逐个醒来.[1] 其余等待的纤程仍将阻塞在 wait() 中, 该函数在返回前必须访问屏障对象中的数据成员.

barrier 类

#include <boost/fiber/barrier.hpp>

namespace boost {
namespace fibers {

class barrier {
public:
    explicit barrier( std::size_t);

    barrier( barrier const&) = delete;
    barrier & operator=( barrier const&) = delete;

    bool wait();
};

}}

barrier 的实例不可复制、不可移动.

构造函数 
explicit barrier( std::size_t initial);

效果:

为 initial 个纤程构造一个屏障.

抛出:

fiber_error

错误条件:

invalid_argument: 若 initial 为零.

Member function wait() 

bool wait();

效果:

阻塞直到 initial 个纤程调用了 wait (在 *this 上). 当第 initial 个纤程调用 wait 时, 所有等待的纤程都被解除阻塞, 屏障也被重置.

返回:

对每批等待纤程中的恰好一个纤程返回 true, 否则返回 false.

抛出:

fiber_error


[1] 当前实现按 FIFO 顺序唤醒纤程: 第一个调用 wait() 的最先被唤醒, 依此类推. 但依赖各纤程到达 wait() 调用的顺序是危险的.
