when_any, 简单完成

最简单的情况是: 你只需要知道一组异步任务中的第一个已经完成——不需要获取返回值, 并且确信它们不会抛出异常.

为此我们引入一个 Done 类, 用于包装一个 bool 变量, 它带有一个 condition_variable 和一个 mutex:

// Wrap canonical pattern for condition_variable + bool flag
struct Done {
private:
    boost::fibers::condition_variable   cond;
    boost::fibers::mutex                mutex;
    bool                                ready = false;

public:
    typedef std::shared_ptr< Done >     ptr;

    void wait() {
        std::unique_lock< boost::fibers::mutex > lock( mutex);
        cond.wait( lock, [this](){ return ready; });
    }

    void notify() {
        {
            std::unique_lock< boost::fibers::mutex > lock( mutex);
            ready = true;
        } // release mutex
        cond.notify_one();
    }
};

本节通篇遵循的模式是: 把一个指向相关同步对象的 std::shared_ptr<> 传给各个任务的纤程函数. 这消除了关于同步对象相对于最后一个纤程之生命周期的恼人问题.

wait_first_simple() 对 Done 采用了这一策略:

template< typename ... Fns >
void wait_first_simple( Fns && ... functions) {
    // Use shared_ptr because each function's fiber will bind it separately,
    // and we're going to return before the last of them completes.
    auto done( std::make_shared< Done >() );
    wait_first_simple_impl( done, std::forward< Fns >( functions) ... );
    done->wait();
}

wait_first_simple_impl() 是对参数包的普通递归, 为每个新纤程捕获 Done::ptr:

// Degenerate case: when there are no functions to wait for, return
// immediately.
void wait_first_simple_impl( Done::ptr) {
}

// When there's at least one function to wait for, launch it and recur to
// process the rest.
template< typename Fn, typename ... Fns >
void wait_first_simple_impl( Done::ptr done, Fn && function, Fns && ... functions) {
    boost::fibers::fiber( [done, function](){
                              function();
                              done->notify();
                          }).detach();
    wait_first_simple_impl( done, std::forward< Fns >( functions) ... );
}

如所承诺, 纤程 lambda 的函数体极其简单: 调用该函数, 返回时通知 Done. 第一个这样做的纤程使 wait_first_simple() 得以返回——这正是让 std::shared_ptr<Done> 管理我们 Done 对象的生命周期 (而不是在 wait_first_simple() 中把它声明为栈变量) 的用意所在.

调用方式如下:

wait_first_simple(
        [](){ sleeper("wfs_long",   150); },
        [](){ sleeper("wfs_medium", 100); },
        [](){ sleeper("wfs_short",   50); });

在这个例子中, 当 wait_first_simple() 完成时, 控制会在 sleeper("wfs_short", 50) 之后恢复——即使另外两个 sleeper() 纤程仍在运行.
