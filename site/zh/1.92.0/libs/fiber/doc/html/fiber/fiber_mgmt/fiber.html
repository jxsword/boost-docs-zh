fiber 类

#include <boost/fiber/fiber.hpp>

namespace boost {
namespace fibers {

class fiber {
public:
    class id;

    constexpr fiber() noexcept;

    template< typename Fn, typename ... Args >
    fiber( Fn &&, Args && ...);

    template< typename Fn, typename ... Args >
    fiber( launch, Fn &&, Args && ...);

    template< typename StackAllocator, typename Fn, typename ... Args >
    fiber( std::allocator_arg_t, StackAllocator &&, Fn &&, Args && ...);

    fiber( launch, std::allocator_arg_t, StackAllocator &&, Fn &&, Args && ...);

    id get_id() const noexcept;

    PROPS & properties();
};

}}
默认构造函数 
constexpr fiber() noexcept;

效果:

构造一个 fiber 实例, 它引用 not-a-fiber.

后置条件:

this->get_id() == fiber::id()

抛出:

无

构造函数 
template< typename Fn, typename ... Args >
fiber( Fn && fn, Args && ... args);

template< typename Fn, typename ... Args >
fiber( launch policy, Fn && fn, Args && ... args);

template< typename StackAllocator, typename Fn, typename ... Args >
fiber( std::allocator_arg_t, StackAllocator && salloc, Fn && fn, Args && ... args);

template< typename StackAllocator, typename Fn, typename ... Args >
fiber( launch policy, std::allocator_arg_t, StackAllocator && salloc,
       Fn && fn, Args && ... args);

前置条件:

Fn 必须可复制或可移动.

效果:

fn 会被复制或移动到内部存储中, 供新纤程访问. 如果 launch 被指定 (或缺省) 为 post, 新纤程会被标记为 "ready", 并将在下一个机会被进入. 如果 launch 被指定为 dispatch, 调用方纤程被挂起, 新纤程被立即进入.

后置条件:

*this 引用新创建的执行纤程.

抛出:

如果发生错误则为 fiber_error.

注释:

需要 StackAllocator 来为内部 __econtext__ 分配栈. 如果未显式传入 StackAllocator, 默认栈分配器取决于 BOOST_USE_SEGMENTED_STACKS: 如果已定义, 将得到 segmented_stack, 否则得到 fixedsize_stack.

参见:

std::allocator_arg_t, 栈分配

移动构造函数 
fiber( fiber && other) noexcept;

效果:

把 other 所管理的纤程的所有权转移给新构造的 fiber 实例.

后置条件:

other.get_id() == fiber::id() 与 get_id() 返回构造之前 other.get_id() 的值

抛出:

无

移动赋值运算符 
fiber & operator=( fiber && other) noexcept;

效果:

把 other (如果有的话) 所管理的纤程的所有权转移给 *this.

后置条件:

other->get_id() == fiber::id() 与 get_id() 返回赋值之前 other.get_id() 的值.

抛出:

无

析构函数 
~fiber();

效果:

如果纤程是 fiber::joinable(), 则调用 std::terminate. 销毁 *this.

注释:

程序员必须确保析构函数永远不会在纤程仍处于 fiber::joinable() 状态时执行. 即使你知道纤程已完成, 也必须先调用 fiber::join() 或 fiber::detach(), 然后才能销毁 fiber 对象.

Member function joinable() 

bool joinable() const noexcept;

返回:

true——若 *this 引用一个执行纤程 (可能已完成, 也可能尚未完成); 否则为 false.

抛出:

无

Member function join() 

void join();

前置条件:

纤程是 fiber::joinable().

效果:

等待被引用的执行纤程完成.

后置条件:

进入时所引用的执行纤程已完成. *this 不再引用任何执行纤程.

抛出:

fiber_error

错误条件:

resource_deadlock_would_occur: 如果 this->get_id() == boost::this_fiber::get_id(). invalid_argument: 如果纤程不是 fiber::joinable().

Member function detach() 

void detach();

前置条件:

纤程是 fiber::joinable().

效果:

该执行纤程变为分离状态, 不再有关联的 fiber 对象.

后置条件:

*this 不再引用任何执行纤程.

抛出:

fiber_error

错误条件:

invalid_argument: 如果纤程不是 fiber::joinable().

Member function get_id() 

fiber::id get_id() const noexcept;

返回:

如果 *this 引用一个执行纤程, 则为表示该纤程的 fiber::id 实例; 否则返回默认构造的 fiber::id.

抛出:

无

参见:

this_fiber::get_id()

模板成员函数 properties() 

template< typename PROPS >
PROPS & properties();

前置条件:

*this 引用一个执行纤程, 且 use_scheduling_algorithm() 已从本线程被调用, 传入的是 algorithm_with_properties<> 的子类, 其模板实参同为 PROPS.

返回:

对 *this 的调度器属性实例的引用.

抛出:

std::bad_cast——如果调用 use_scheduling_algorithm() 时传入的 algorithm_with_properties 子类带有不同于 PROPS 的模板形参.

注释:

algorithm_with_properties<> 为用户编写的调度器提供了一种把扩展属性 (如优先级) 与纤程实例关联起来的方式. 此方法允许访问这些用户提供的属性.

参见:

定制

Member function swap() 

void swap( fiber & other) noexcept;

效果:

交换 *this 与 other 所关联的执行纤程, 使 *this 关联到原先与 other 关联的纤程, 反之亦然.

后置条件:

this->get_id() 返回调用前与 other.get_id() 相同的值. other.get_id() 返回调用前与 this->get_id() 相同的值.

抛出:

无

Non-member function swap() 

void swap( fiber & l, fiber & r) noexcept;

效果:

与 l.swap( r) 相同.

抛出:

无

Non-member function operator<() 

bool operator<( fiber const& l, fiber const& r) noexcept;

返回:

true——若 l.get_id() < r.get_id() 是 true; 否则为 false.

抛出:

无.

Non-member function use_scheduling_algorithm() 

template< typename SchedAlgo, typename ... Args >
void use_scheduling_algorithm( Args && ... args) noexcept;

效果:

指示 Boost.Fiber 使用 SchedAlgo (必须是 algorithm 的具体子类) 作为当前线程中所有纤程的调度算法. 把所需的 SchedAlgo 构造函数实参作为 args 传入.

注释:

如果你希望给定线程使用非默认的调度算法, 让该线程调用 use_scheduling_algorithm(), 且要在任何其他 Boost.Fiber 入口点之前. 如果到 Boost.Fiber 需要使用调度器时尚未为当前线程设置调度器, 该库将为此线程创建一个默认的 round_robin 实例.

抛出:

无

参见:

调度, 定制

Non-member function has_ready_fibers() 

bool has_ready_fibers() noexcept;

返回:

如果调度器有就绪可运行的纤程, 则为 true.

抛出:

无

注释:

可用于工作窃取 (work-stealing) 以查找空闲的调度器.
