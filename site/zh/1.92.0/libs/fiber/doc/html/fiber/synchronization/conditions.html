条件变量

概要 
enum class cv_status; {
    no_timeout,
    timeout
};

class condition_variable;
class condition_variable_any;

类 condition_variable 为纤程提供了一种等待来自另一纤程通知的机制. 当纤程从等待中醒来时, 它会检查相应条件现在是否为真, 若为真则继续执行. 若条件不为真, 则纤程再次调用 wait 以继续等待. 最简单的情况下, 该条件只是一个布尔变量:

boost::fibers::condition_variable cond;
boost::fibers::mutex mtx;
bool data_ready = false;

void process_data();

void wait_for_data_to_process() {
    {
        std::unique_lock< boost::fibers::mutex > lk( mtx);
        while ( ! data_ready) {
            cond.wait( lk);
        }
    }   // release lk
    process_data();
}

注意 lk 被传递给 condition_variable::wait(): wait() 会原子性地把该纤程加入等待该条件变量的纤程集合, 并解锁 mutex. 当该纤程被唤醒时, mutex 会在 wait() 调用返回前再次被锁定. 这允许其他纤程获取 mutex 以更新共享数据, 并确保与条件相关的数据被正确同步.

wait_for_data_to_process() 也可以等价地写作:

void wait_for_data_to_process() {
    {
        std::unique_lock< boost::fibers::mutex > lk( mtx);
        // make condition_variable::wait() perform the loop
        cond.wait( lk, [](){ return data_ready; });
    }   // release lk
    process_data();
}

与此同时, 另一个纤程把 data_ready 设为 true, 然后调用 condition_variable::notify_one() 或 condition_variable::notify_all() (作用于 condition_variable cond ), 分别唤醒一个等待的纤程或所有等待的纤程.

void retrieve_data();
void prepare_data();

void prepare_data_for_processing() {
    retrieve_data();
    prepare_data();
    {
        std::unique_lock< boost::fibers::mutex > lk( mtx);
        data_ready = true;
    }
    cond.notify_one();
}

注意 mutex 在更新共享数据之前已被锁定, 但 mutex 不必在 condition_variable::notify_one() 调用期间一直保持锁定.

加锁很重要, 因为 Boost.Fiber 提供的同步对象可用于同步运行在不同线程上的纤程.

Boost.Fiber 同时提供了 condition_variable 和 condition_variable_any. boost::fibers::condition_variable 只能等待 std::unique_lock< boost::fibers::mutex >, 而 boost::fibers::condition_variable_any 则可等待用户定义的锁类型.

无虚假唤醒

condition_variable 和 condition_variable_any 都不会发生虚假唤醒: condition_variable::wait() 只能在调用 condition_variable::notify_one() 或 condition_variable::notify_all() 时被唤醒. 即便如此, 谨慎起见仍应使用 wait( lock, predicate ) 的某个重载.

考虑一组消费者纤程, 从 std::queue 中取条目进行处理. 该队列由一组生产者纤程持续填充.

消费者纤程在一个 condition_variable 上等待是合理的, 只要队列保持 empty() 状态.

由于生产者纤程可能以突发方式向队列 push() 条目, 它们调用 condition_variable::notify_all() 而不是 condition_variable::notify_one().

但某个消费者纤程完全可能从 condition_variable::wait() 中醒来, 却发现队列 empty(), 因为其他消费者纤程可能已经处理完所有待处理条目.

(另见 虚假唤醒.)

枚举 cv_status

限时等待操作可能因超时而返回, 也可能不是.

enum class cv_status {
    no_timeout,
    timeout
};
no_timeout

效果:

条件变量是通过 notify_one 或 notify_all 被唤醒的.

timeout

效果:

条件变量因超时而被唤醒.

condition_variable_any 类

#include <boost/fiber/condition_variable.hpp>

namespace boost {
namespace fibers {

class condition_variable_any {
public:
    condition_variable_any();
    ~condition_variable_any();

    condition_variable_any( condition_variable_any const&) = delete;
    condition_variable_any & operator=( condition_variable_any const&) = delete;

    void notify_one() noexcept;
    void notify_all() noexcept;

    template< typename LockType >
    void wait( LockType &);

    template< typename LockType, typename Pred >
    void wait( LockType &, Pred);

    template< typename LockType, typename Clock, typename Duration >
    cv_status wait_until( LockType &,
                          std::chrono::time_point< Clock, Duration > const&);

    template< typename LockType, typename Clock, typename Duration, typename Pred >
    bool wait_until( LockType &,
                     std::chrono::time_point< Clock, Duration > const&,
                     Pred);

    template< typename LockType, typename Rep, typename Period >
    cv_status wait_for( LockType &,
                        std::chrono::duration< Rep, Period > const&);

    template< typename LockType, typename Rep, typename Period, typename Pred >
    bool wait_for( LockType &,
                   std::chrono::duration< Rep, Period > const&,
                   Pred);
};

}}

Member function notify_one() 

void notify_one() noexcept;

效果:

若有纤程当前正 阻塞 等待于 *this (在调用 wait、wait_for 或 wait_until 时), 则解除这些纤程之一的阻塞.

抛出:

无.

注释:

恢复哪个等待的纤程是任意的.

Member function notify_all() 

void notify_all() noexcept;

效果:

若有纤程当前正 阻塞 等待于 *this (在调用 wait、wait_for 或 wait_until 时), 则解除所有这些纤程的阻塞.

抛出:

无.

注释:

这就是为什么等待的纤程还必须 另外 使用 condition_variable_any 以外的某种机制检查所期望的程序状态, 并重试等待直到达到该状态. 在达到期望状态之前, 等待 condition_variable_any 的纤程很可能会醒来多次.

模板成员函数 wait() 

template< typename LockType >
    void wait( LockType & lk);

template< typename LockType, typename Pred >
void wait( LockType & lk, Pred pred);

前置条件:

lk 已被当前纤程锁定, 并且: 要么当前没有其他纤程在 *this 上等待, 要么执行 mutex() 成员函数, 作用对象为 lk 对象 (由调用 wait 时, 当前所有等待 *this 的纤程所提供), 所得值须与 lk->mutex() 在本次对 wait 的调用中返回的值相同.

效果:

原子性地调用 lk.unlock() 并阻塞当前纤程. 当通过对 this->notify_one() 或 this->notify_all() 的调用收到通知时, 该纤程将解除阻塞. 当纤程被解除阻塞时 (无论原因如何), 锁会先通过调用 lk.lock() 重新获取, 之后 wait 调用才返回. 若函数因异常退出, 锁同样会通过调用 lk.lock() 重新获取. 接受 pred 的成员函数是以下写法的简写:

while ( ! pred() ) {
    wait( lk);
}

后置条件:

lk 已被当前纤程锁定.

抛出:

如果发生错误则为 fiber_error.

注释:

这条前置条件有些难读. 它只是说, 所有并发调用 wait 于 *this 的纤程, 都必须在 lk 对象上等待, 这些对象管理着同一 mutex. 任何 condition_variable_any::wait() 调用都涉及三个不同的对象: condition_variable_any 本身、在纤程之间协调访问的 mutex, 以及一个局部锁对象 (例如 std::unique_lock). 一般而言, 可以把给定 condition_variable_any 实例的生命周期划分为有一个或多个纤程在其上等待的时段, 各时段之间由没有纤程等待的时段分隔. 当有多个纤程在该 condition_variable_any 上等待时, 它们都必须传入引用同一 mutex 实例的锁对象.

模板成员函数 wait_until() 

template< typename LockType, typename Clock, typename Duration >
cv_status wait_until( LockType & lk,
                      std::chrono::time_point< Clock, Duration > const& abs_time);

template< typename LockType, typename Clock, typename Duration, typename Pred >
bool wait_until( LockType & lk,
                 std::chrono::time_point< Clock, Duration > const& abs_time,
                 Pred pred);

前置条件:

lk 已被当前纤程锁定, 并且: 要么当前没有其他纤程在 *this 上等待, 要么执行 mutex() 成员函数, 作用对象为 lk 对象 (由调用 wait、wait_for 或 wait_until 时, 当前所有等待 *this 的纤程所提供), 所得值须与 lk.mutex() 在本次对 wait_until 的调用中返回的值相同.

效果:

原子性地调用 lk.unlock() 并阻塞当前纤程. 当通过对 this->notify_one() 或 this->notify_all() 的调用收到通知, 或系统时间将等于或晚于指定的 abs_time 时, 该纤程将解除阻塞. 当纤程被解除阻塞时 (无论原因如何), 锁会先通过调用 lk.lock() 重新获取, 之后 wait_until 调用才返回. 若函数因异常退出, 锁同样会通过调用 lk.lock() 重新获取. 接受 pred 的成员函数是以下写法的简写:

while ( ! pred() ) {
    if ( cv_status::timeout == wait_until( lk, abs_time) )
        return pred();
}
return true;

也就是说, 即使 wait_until() 超时, 它仍可能返回 true——若此时 pred() 返回 true.

后置条件:

lk 已被当前纤程锁定.

抛出:

fiber_error (若发生错误), 或超时相关异常.

返回:

不带 pred 的重载返回 cv_status::no_timeout——若它由 notify_one() 或 notify_all() 唤醒; 或返回 cv_status::timeout——若因系统时间已过 abs_time 而唤醒.

返回:

接受 pred 的重载返回 false——若调用返回是因为已到达 abs_time 所指定的时间, 且谓词返回 false, true 否则.

注释:

参见 注释 (关于 condition_variable_any::wait()).

模板成员函数 wait() 

void wait( std::unique_lock< mutex > & lk);

template< typename Pred >
void wait( std::unique_lock< mutex > & lk, Pred pred);

前置条件:

lk 已被当前纤程锁定, 并且: 要么当前没有其他纤程在 *this 上等待, 要么执行 mutex() 成员函数, 作用对象为 lk 对象 (由调用 wait 时, 当前所有等待 *this 的纤程所提供), 所得值须与 lk->mutex() 在本次对 wait 的调用中返回的值相同.

    wait( lk);
}

lk 已被当前纤程锁定.

抛出:

如果发生错误则为 fiber_error.

这条前置条件有些难读. 它只是说, 所有并发调用 wait 于 *this 的纤程, 都必须在 lk 对象上等待, 这些对象管理着同一 mutex. 任何 condition_variable::wait() 调用都涉及三个不同的对象: condition_variable 本身、在纤程之间协调访问的 mutex, 以及一个局部锁对象 (例如 std::unique_lock). 一般而言, 可以把给定 condition_variable 实例的生命周期划分为有一个或多个纤程在其上等待的时段, 各时段之间由没有纤程等待的时段分隔. 当有多个纤程在该 condition_variable 上等待时, 它们都必须传入引用同一 mutex 实例的锁对象.
