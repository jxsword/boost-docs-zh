性能

Performance measurements were taken using std::chrono::highresolution_clock, with overhead corrections. The code was compiled with gcc-6.3.1, using build options: variant = release, optimization = speed. Tests were executed on dual Intel XEON E5 2620v4 2.2GHz, 16C/32T, 64GB RAM, running Linux (x86_64).

标记为 1C/1T 的测量是在单线程进程中运行的.

Alexander Temerev 的 微基准测试 syknet 被移植并用于性能测量. 测试在根节点生成 10 个执行线程 (ToE), 例如 actor/goroutine/fiber 等. 每个生成的 ToE 会再生成另外 10 个 ToE... 直到创建出 1,000,000 个 ToE. ToE 返回其序号 (0 ... 999,999), 序号在上一层求和并向上游回传, 直到到达根节点. 该测试运行 10-20 次, 为每次测量产生一个取值范围.

Pthreads 以 8kB 的栈大小创建, 而 std::thread 使用系统默认值 (1MB - 2MB). 该微基准测试 无法 以 1,000,000 个线程 运行, 原因是 资源耗尽 (pthread 和 std::thread). 作为替代, 该测试只在 10,000 个线程下运行.

该测试使用 16 核并启用对称多线程 (32 个逻辑 CPU). 纤程栈由 fixedsize_stack 分配.

正如基准测试所示, 内存分配算法对多线程环境下的性能影响显著. 测试使用了 glibc 的内存分配算法 (基于 ptmalloc2) 以及 Google 的 TCmalloc (通过 linkflags="-ltcmalloc").[9]

在 work_stealing 调度算法中, 每个线程都有自己的本地队列. 就绪可运行的纤程被压入本地队列并从中弹出. 如果队列耗尽了就绪纤程, 就从其他参与线程的本地队列窃取纤程.
