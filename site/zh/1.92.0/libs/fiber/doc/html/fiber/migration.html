跨线程迁移纤程

概述

每个纤程拥有一个栈并管理其执行状态, 包括所有寄存器和 CPU 标志位、指令指针和栈指针. 这意味着, 一般来说, 纤程并不绑定到特定线程.[3],[4]

把纤程从工作负载繁重的逻辑 CPU 迁移到工作负载较轻的另一个逻辑 CPU 可能会加快整体执行. 注意, 对于 NUMA 架构, 在线程之间迁移数据并不总是可取的. 假设纤程 f 正在逻辑 CPU cpu0 上运行, 该 CPU 属于 NUMA 节点 node0. f 的数据分配在位于 node0 的物理内存上. 把纤程从 cpu0 迁移到属于另一个 NUMA 节点 nodeX 的逻辑 CPU cpuX, 可能会因内存访问延迟增加而降低应用程序的性能.

只有包含在 algorithm 的就绪队列中的纤程才能在线程之间迁移. 你不能迁移正在运行的纤程, 也不能迁移 blocked 的纤程. 你也不能迁移其 context::is_context() 方法返回 true (针对 pinned_context) 的纤程.

在 Boost.Fiber 中, 纤程迁移通过在纤程迁出的线程上调用 context::detach(), 并在纤程迁入的线程上调用 context::attach() 来完成.

因此, 纤程迁移是通过在不同线程上运行的、用户编写的 algorithm 实现的各实例之间共享状态来完成的. 纤程的原始线程调用 algorithm::awakened(), 并传入该纤程的 context*. awakened() 实现会调用 context::detach().

稍后的某个时刻, 当同一个或另一个线程调用 algorithm::pick_next() 时, pick_next() 实现会选取一个就绪纤程, 并在返回它之前对其调用 context::attach().

如上所述, 一个 context——若其满足 is_context(pinned_context) == true——绝不能传给 context::detach() 或 context::attach(). 它只能从 pick_next() 返回, 且只能由 相同 的线程返回——即把该上下文传给 awakened() 的那个线程.

工作共享示例

在示例 work_sharing.cpp 中, 多个工作纤程在主线程上创建. 每个纤程在构造时获得一个字符作为参数. 该字符会被打印十次. 在每次迭代之间, 纤程会调用 this_fiber::yield(). 这会把该纤程放入当前线程上运行的纤程调度器 shared_ready_queue 的就绪队列. 下一个就绪待执行的纤程会从共享就绪队列中出队, 并由运行在 任何参与线程 上的 shared_ready_queue 恢复.

shared_ready_queue 的所有实例共享一个用作就绪队列的全局并发队列. 这一机制在 shared_ready_queue 的所有实例之间——也就是所有参与线程之间——共享所有工作纤程.

线程与纤程的设置

在 main() 中安装纤程调度器, 并启动工作纤程和线程.

boost::fibers::use_scheduling_algorithm< boost::fibers::algo::shared_work >(); 

for ( char c : std::string("abcdefghijklmnopqrstuvwxyz")) { 
    boost::fibers::fiber([c](){ whatevah( c); }).detach();
    ++fiber_count; 
}
boost::fibers::detail::thread_barrier b( 4);
std::thread threads[] = { 
    std::thread( thread, & b),
    std::thread( thread, & b),
    std::thread( thread, & b)
};
b.wait(); 
{
    lock_type lk( mtx_count);
    cnd_count.wait( lk, [](){ return 0 == fiber_count; } ); 
} 
BOOST_ASSERT( 0 == fiber_count);
for ( std::thread & t : threads) { 
    t.join();
}

等待线程终止

线程的启动由一个屏障同步. 每个线程 (包括主线程) 的主纤程会被挂起, 直到所有工作纤程都完成. 当主纤程从 condition_variable::wait() 返回时, 该线程终止: 主线程汇合所有其他线程.

void thread( boost::fibers::detail::thread_barrier * b) {
    std::ostringstream buffer;
    buffer << "thread started " << std::this_thread::get_id() << std::endl;
    std::cout << buffer.str() << std::flush;
    boost::fibers::use_scheduling_algorithm< boost::fibers::algo::shared_work >(); 
    b->wait(); 
    lock_type lk( mtx_count);
    cnd_count.wait( lk, [](){ return 0 == fiber_count; } ); 
    BOOST_ASSERT( 0 == fiber_count);
}

与其他线程同步: 允许它们开始处理

挂起主纤程, 同时恢复工作纤程. 当所有工作纤程都完成时, 主纤程被恢复 (例如从 condition_variable_any::wait() 返回).

每个工作纤程执行函数 whatevah(), 以字符 me 作为参数. 纤程在循环中让出, 并且如果它被迁移到另一个线程则打印一条消息.

void whatevah( char me) {
    try {
        std::thread::id my_thread = std::this_thread::get_id(); 
        {
            std::ostringstream buffer;
            buffer << "fiber " << me << " started on thread " << my_thread << '\n';
            std::cout << buffer.str() << std::flush;
        }
        for ( unsigned i = 0; i < 10; ++i) { 
            boost::this_fiber::yield(); 
            std::thread::id new_thread = std::this_thread::get_id(); 
            if ( new_thread != my_thread) { 
                my_thread = new_thread;
                std::ostringstream buffer;
                buffer << "fiber " << me << " switched to thread " << my_thread << '\n';
                std::cout << buffer.str() << std::flush;
            }
        }
    } catch ( ... ) {
    }
    lock_type lk( mtx_count);
    if ( 0 == --fiber_count) { 
        lk.unlock();
        cnd_count.notify_all(); 
    }
}

调度纤程

纤程调度器 shared_ready_queue 类似于 round_robin, 区别在于它在所有参与线程之间共享一个公共就绪队列. 线程通过执行 use_scheduling_algorithm() 来加入该池, 这要在任何其他 Boost.Fiber 操作之前进行.

关于就绪队列的重点是, 它是一个类静态成员, 为 shared_ready_queue 的所有实例所共有. 因此, 经由 algorithm::awakened() 入队的纤程 (就绪待恢复的纤程) 对所有线程都可用. 必须为线程的主纤程和分派纤程保留一个单独的、调度器特定的队列: 这些纤程 不得 在线程之间共享! 当我们收到这两种纤程之一时, 应把它推入那里而不是共享队列: 让线程 B 取回并尝试执行线程 A 的主纤程将是一件糟糕的事.
