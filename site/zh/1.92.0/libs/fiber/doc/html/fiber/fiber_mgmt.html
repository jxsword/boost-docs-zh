教程

每个 fiber 表示一个微线程, 它将由调度器以协作方式启动和管理. fiber 类型的对象是只能移动的.

boost::fibers::fiber f1; // not-a-fiber

void f() {
    boost::fibers::fiber f2( some_fn);

    f1 = std::move( f2); // f2 moved to f1
}

启动

启动新纤程的方式是传入一个可调用类型的对象, 该对象可以不带参数地调用. 如果该对象不可复制或移动, 则可使用 std::ref 传入对该函数对象的引用. 在这种情况下, 用户必须确保被引用对象的寿命长于新创建的纤程.

struct callable {
    void operator()();
};

boost::fibers::fiber copies_are_safe() {
    callable x;
    return boost::fibers::fiber( x);
} // x is destroyed, but the newly-created fiber has a copy, so this is OK

boost::fibers::fiber oops() {
    callable x;
    return boost::fibers::fiber( std::ref( x) );
} // x is destroyed, but the newly-created fiber still has a reference
  // this leads to undefined behaviour

被创建的 fiber 并不会立即开始运行. 它会被加入可运行纤程列表, 等调度器处理到它时才会运行.

异常

从传给 fiber 构造函数的函数或可调用对象中逃逸的异常会调用 std::terminate(). 如果你需要知道抛出的是哪个异常, 请使用 future<> 或 packaged_task<>.

分离

一个 fiber 可以通过显式调用其 fiber::detach() 成员函数来分离. 在纤程对象上调用 fiber::detach() 之后, 该对象代表 not-a-fiber. 此后可以安全地销毁该纤程对象.

boost::fibers::fiber( some_fn).detach();

Boost.Fiber 提供了多种等待运行中纤程完成的方式. 即使纤程已分离, 你也可以使用 mutex 或 condition_variable 或库提供的任何其他 同步对象 来进行协调.

如果线程的主纤程终止时被分离的纤程仍在运行, 该线程将不会关闭.

汇合

为等待一个纤程完成, 可以使用 fiber::join() 成员函数 (属于 fiber 对象). fiber::join() 将阻塞, 直到 fiber 对象完成为止.

void some_fn() {
    ...
}

boost::fibers::fiber f( some_fn);
...
f.join();

如果纤程已经完成, fiber::join() 会立即返回, 且被汇合的 fiber 对象将变为 not-a-fiber.

销毁

当代表有效执行上下文的 fiber 对象 (即纤程尚未被 fiber::joinable()) 被销毁时, 程序会终止. 如果你打算让纤程的寿命长于启动它的 fiber 对象, 请使用 fiber::detach() 方法.

{
    boost::fibers::fiber f( some_fn);
} // std::terminate() will be called

{
    boost::fibers::fiber f(some_fn);
    f.detach();
} // okay, program continues

纤程 ID

fiber::id 类的对象可用于标识纤程. 每个运行中的 fiber 都有一个唯一的 fiber::id, 可以通过调用相应 fiber 的 fiber::get_id() 成员函数获得. fiber::id 类的对象可以复制, 并可用作关联容器中的键: 提供了全部比较运算符. 还可以使用流插入运算符把它们写入输出流, 但输出格式未作规定.

fiber::id 的每个实例要么引用某个纤程, 要么是 not-a-fiber. 引用 not-a-fiber 的实例彼此比较相等, 但与引用实际纤程的任何实例比较都不相等. fiber::id 上的比较运算符对每个不相等的 fiber::id 产生一个全序.

枚举 launch

launch 规定控制权是否立即传入新启动的纤程.

enum class launch {
    dispatch,
    post
};

dispatch

效果:

以 launch == dispatch 启动的纤程会被立即进入. 换言之, 以 dispatch 启动纤程会挂起调用方 (先前运行的纤程), 直到纤程调度器稍后有机会恢复它.

post

效果:

以 launch == post 启动的纤程会作为就绪状态传递给纤程调度器, 但尚未被进入. 调用方 (先前运行的纤程) 继续执行. 新启动的纤程将在纤程调度器稍后有机会恢复它时被进入.

注释:

如果未显式指定 launch, 则默认为 post.
