概述

Boost.Fiber 的主要优势之一, 是既能利用异步操作来提高效率, 又能让调用代码的结构看起来 仿佛 这些操作是同步的. 异步操作以多种方式提供完成通知, 但大多数都会涉及某种回调函数. 本节讨论将 Boost.Fiber 与任意异步操作对接的技巧.

为便于说明, 请看下面这个假想的 API:

class AsyncAPI {
public:
    // constructor acquires some resource that can be read and written
    AsyncAPI();

    // callbacks accept an int error code; 0 == success
    typedef int errorcode;

    // write callback only needs to indicate success or failure
    template< typename Fn >
    void init_write( std::string const& data, Fn && callback);

    // read callback needs to accept both errorcode and data
    template< typename Fn >
    void init_read( Fn && callback);

    // ... other operations ...
};

关于 init_write() 和 init_read() 各自的要点如下:

  • AsyncAPI 方法只负责发起操作. 它会立即返回, 而所请求的操作仍在进行中.
  • 该方法接受一个回调. 当操作完成时, 会以相关参数 (错误码, 若适用还包括数据) 调用该回调.

我们希望把这些异步方法封装成看似同步的函数, 其做法是阻塞调用方纤程, 直到操作完成. 这样我们就能利用封装函数的返回值来传递相关数据.
