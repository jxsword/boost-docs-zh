概述

早期计算时代的一条智慧至今仍然适用: 更倾向于用指令指针而非布尔标志来为程序状态建模. 换句话说, 如果程序必须 “做某件事”, 然后再做几乎相同但略有改动的事情……或许应当把该事情的部分内容拆分为更小的独立函数, 而不是引入标志来改变一个单体函数的内部行为.

对此我们要补充: 更倾向于使用 C++ 原生构造 (如函数调用、if、while、for、do 等) 来描述控制流, 而不是用回调链.

的巨大优势之一在于, Boost.Fiber 赋予编码者极大的灵活性, 可以把应用从回调链重构为直白的 C++ 语句序列, 即使该纤程中的代码实际上与其他纤程中运行的代码交织在一起.

近来关于 when_any 与 when_all 功能之益处的讨论颇多. 在处理异步且可能不可靠的服务时, 这些是有价值的习语. 但当然, when_any 和 when_all 与回调链的使用紧密相关.

本节给出了一些方法, 用于在如下场景中达成同样的目的: 某个纤程希望在一个或多个其他独立活动完成时 “做某件事”. 因此, 这些是 wait_something() 函数而不是 when_something() 函数. 预期是调用纤程请求启动那些独立活动, 然后等待它们, 再顺序进行依赖这些结果的后续处理.

所示函数名 (例如 wait_first_simple()) 仅用于说明, 因为所有这些函数都打包在一个源文件中. 假如 (比如说) wait_first_success() 最适合你的应用需求, 你可以用名称 wait_any() 引入那个变体.

注释

本节介绍的函数接受任务函数的可变参数列表. 接受任务函数容器的相应 wait_something() 函数留作有兴趣的读者的练习. 那些其实应该更简单. 大部分复杂性将来自为两种用途重载同一个名称.

本节的全部源代码见 wait_stuff.cpp.

示例任务函数

我们发现用下面这个函数来建模异步任务会很方便:

template< typename T >
T sleeper_impl( T item, int ms, bool thrw = false) {
    std::ostringstream descb, funcb;
    descb << item;
    std::string desc( descb.str() );
    funcb << "  sleeper(" << item << ")";
    Verbose v( funcb.str() );

    boost::this_fiber::sleep_for( std::chrono::milliseconds( ms) );
    if ( thrw) {
        throw std::runtime_error( desc);
    }
    return item;
}

以及类型特定的 sleeper() “前端” (用于 std::string、double 和 int)

Verbose 只是简单地在构造和析构时向 std::cout 打印一条消息.

基本行为如下:

  1. sleeper() 打印一条启动消息;
  2. 休眠指定的毫秒数;
  3. 若 thrw 作为 true 传入, 则抛出所传入 item 的字符串描述;
  4. 否则返回所传入的 item.
  5. 在退出时, sleeper() 产生一条停止消息.

这个函数将出现在下文介绍的各个函数的示例调用中.
