事件驱动程序

考虑一个经典的事件驱动程序, 它围绕一个获取并分发传入 I/O 事件的主循环组织. 你引入 Boost.Fiber 是因为某些异步 I/O 序列在逻辑上是顺序的, 对这些序列你希望编写和维护看起来且行为都像顺序执行的代码.

你在应用程序的主线程上启动纤程, 是因为纤程的某些操作会影响其用户界面, 而应用程序的 UI 框架只允许在主线程上进行 UI 操作. 或者, 也许这些纤程需要访问主线程的数据, 而用线程同步原语稳健地保护每个这样的数据项在运行期 (或开发期) 的代价太高.

你必须确保应用程序的主循环 自身 不会独占处理器: 即它启动的纤程能获得所需的 CPU 周期.

解决方案与任何可能长时间占用 CPU 的纤程相同: 引入对 this_fiber::yield() 的调用. 最直接的做法是在现有主循环的每次迭代中调用 yield(). 实际上, 这会把应用程序的主循环与 Boost.Fiber 的内部主循环统一起来. yield() 允许纤程管理器运行自应用程序主循环上一次迭代以来变为就绪的所有纤程. 当这些纤程轮过一遍之后, 控制权交给线程的主纤程, 后者从 yield() 返回并恢复应用程序的主循环.
