嵌入式主循环

更具挑战性的是应用程序的主循环嵌入在其他某个库或框架中的情况. 这样的应用程序通常在完成所有必要的设置之后, 把控制权交给某种 run() 函数, 直到应用程序关闭控制权才会返回.

一个 Boost.Asio 程序可能就以这种方式调用 io_service::run().

一般而言, 诀窍在于安排频繁地把控制权交给 this_fiber::yield(). 你可以为此使用一个 Asio 定时器. 你可以实例化该定时器, 安排它在到期时调用某个处理器函数. 该处理器函数可以调用 yield(), 然后重置定时器, 并安排在下次到期时再次唤醒.

由于在这个思想实验中, 我们总是通过 yield() 把控制权交给纤程管理器, 调用方纤程永远不会被阻塞. 因此总是至少有一个就绪纤程. 因此纤程管理器从不调用 algorithm::suspend_until().

使用 io_service::post() 来代替为某个非零间隔设置定时器, 对其他线程并不友好. 当所有 I/O 都在等待且所有纤程都被阻塞时, io_service 和纤程管理器只会来回交接控制权, 空转 CPU. 使用定时器可以调整该线程相对于其他线程的响应速度.
