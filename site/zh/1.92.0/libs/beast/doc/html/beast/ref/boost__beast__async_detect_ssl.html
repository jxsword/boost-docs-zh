async_detect_ssl

在流上异步检测 TLS/SSL 握手.

概要

定义于头文件 <boost/beast/core/detect_ssl.hpp> 

template<
    class AsyncReadStream,
    class DynamicBuffer,
    class CompletionToken = net::default_completion_token_t<beast::executor_type<AsyncReadStream>>>
DEDUCED
async_detect_ssl(
    AsyncReadStream& stream,
    DynamicBuffer& buffer,
    CompletionToken&& token = net::default_completion_token_t< beast::executor_type< AsyncReadStream > >{});
说明

此函数从流异步读取, 以确定是否正在接收客户端握手消息.

此调用总是立即返回. 异步操作将持续到以下条件之一成立:

  • 检测到 TLS 客户端起始握手,
  • 接收到的数据对 TLS 客户端握手无效, 或
  • 发生错误.

该算法称为 composed asynchronous operation, 它以对下一层 async_read_some 函数的调用实现. 程序必须确保在本操作完成之前不执行对 async_read_some 的其他调用.

从流读取的字节将存储在传入的动态缓冲区中; 若检测器返回 true, 该缓冲区可用于执行 TLS 握手, 否则调用者可根据预期协议消费它.

参数

名称

说明

stream

要读取的流. 此类型必须满足 AsyncReadStream 的要求.

buffer

要使用的动态缓冲区. 此类型必须满足 DynamicBuffer 的要求.

token

用于确定异步操作结果提供方式的完成标记. 若它是完成处理器, 实现将通过衰减复制取得处理器的所有权, 且处理器的等效函数签名必须是:

void handler(
    error_code const & error,    // Set to the error, if any
    bool result                 // The result of the detector
);

若处理器有关联的立即执行器, 将向它派发立即完成. 否则, 处理器不会在此函数内部被调用. 处理器的调用将以与使用 net::post 等效的方式进行.
