此流包装一个 net::basic_stream_socket, 提供以下特性:

  • 一个 Executor 可以与流关联, 用于调用尚未有关联执行器的任何完成处理器. 这实现了对 [P1322R0] Networking TS enhancement to enable custom I/O executors 的支持.
  • 对执行任何读、写或连接的每个逻辑异步操作, 都可以指定超时.
  • 一个 RatePolicy 可以与流关联, 通过策略的接口实现速率限制.

尽管流支持多个并发未完成的异步操作, 流对象本身不是线程安全的. 调用者负责确保流同一时刻只被一个线程访问, 包括流及其底层套接字被网络实现访问的时候. 为满足这一线程安全要求, 流的所有异步操作都必须在同一个隐式 strand 中执行 (仅一个线程net::io_context::run) , 或在同一个显式 strand (如 net::strand 的实例) 中执行.

带有显式关联执行器的完成处理器 (例如因使用 net::bind_executor 而产生的) 将由流使用关联执行器调用. 否则, 完成处理器将由构造时与流关联的执行器调用. 与此流一起使用的执行器类型必须满足以下要求:

  • 提交到执行器的函数对象彼此不得并发运行.

执行器类型 net::strand 满足这些要求. 在流类模板中使用 strand 作为执行器还带来额外的记法便利: 无需在每次发起函数调用中单独指定 strand.

与其他流封装不同, 底层套接字通过 socket 成员函数访问, 而不是 next_layer. 这导致对 basic_stream 的调用会返回 get_lowest_layer.

用法

要使用此流, 先声明类的实例. 然后, 在每个希望有超时的逻辑操作之前, 以时长调用 expires_after, 或以时间点调用 expires_at. 或者调用 expires_never 来为后续逻辑操作禁用超时. 逻辑操作是指对超时流的异步读、异步写或异步连接函数的一次或多次直接或间接调用构成的任意序列.

当设置了超时并执行混合操作 (例如同时包含读和写的操作) 时, 超时作用于外层操作使用的所有中间异步操作. 这使得超时可以应用于并非专为超时编写的流算法——只要向这些算法传入设置了超时的超时流.

发生超时时套接字将被关闭, 取消任何挂起的 I/O 操作. 这些被取消操作的完成处理器将以错误 beast::error::timeout 被调用.

示例

此函数带超时地读取一个 HTTP 请求, 然后以不同的超时发送 HTTP 响应.

void process_http_1 (tcp_stream& stream, net::yield_context yield)
{
    flat_buffer buffer;
    http::request<http::empty_body> req;

    // Read the request, with a 15 second timeout
    stream.expires_after(std::chrono::seconds(15));
    http::async_read(stream, buffer, req, yield);

    // Calculate the response
    http::response<http::string_body> res = make_response(req);

    // Send the response, with a 30 second timeout.
    stream.expires_after (std::chrono::seconds(30));
    http::async_write (stream, res, yield);
}

上面的示例稍作修改即可用单个超时表达. 下面的函数先读取 HTTP 请求再发送 HTTP 响应, 使用一个作用于整个读写组合操作的超时:

void process_http_2 (tcp_stream& stream, net::yield_context yield)
{
    flat_buffer buffer;
    http::request<http::empty_body> req;

    // Require that the read and write combined take no longer than 30 seconds
    stream.expires_after(std::chrono::seconds(30));

    http::async_read(stream, buffer, req, yield);

    http::response<http::string_body> res = make_response(req);
    http::async_write (stream, res, yield);
}

某些流算法 (例如 ssl::stream::async_handshake) 同时执行读和写. 在调用此类组合流算法的发起函数之前设置的超时将作用于整个组合操作. 例如, 可以这样对 SSL 握手设置超时:

void do_ssl_handshake (net::ssl::stream<tcp_stream>& stream, net::yield_context yield)
{
    // Require that the SSL handshake take no longer than 10 seconds
    stream.expires_after(std::chrono::seconds(10));

    stream.async_handshake(net::ssl::stream_base::client, yield);
}
阻塞式 I/O

同步函数的行为与被封装的 net::basic_stream_socket 完全相同. 执行阻塞调用时超时不可用.

模板参数

类型

说明

Protocol

满足 Protocol 要求的类型, 表示 basic 流套接字要使用的协议. 常见选择是 net::ip::tcp.

Executor

满足 Executor 要求的类型, 用于提交尚未有关联执行器的所有完成处理器. 若省略此类型, 将使用默认值 net::any_io_executor.
线程安全

Distinct objects: 安全.

Shared objects: 不安全. 应用还必须确保所有异步操作都在同一个隐式或显式 strand 中执行.
