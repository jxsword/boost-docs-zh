Streams流

一个 流 是一种通信信道, 数据以有序字节序列可靠传输. 流可以是同步或异步的, 可以允许读、写或两者兼有. 注意, 某个具体类型可以建模多个 concept. 例如 networking 类型 tcp::socket 和 net::ssl::stream 同时支持 SyncStream 和 AsyncStream. Beast 中的所有流算法都声明为使用这些 concept 的模板函数:

表 1.4. 流 concept

概念

说明

SyncReadStream

支持面向缓冲区的阻塞读取.

SyncWriteStream

支持面向缓冲区的阻塞写入.

SyncStream

支持面向缓冲区的阻塞读写的流.

AsyncReadStream

支持面向缓冲区的异步读取.

AsyncWriteStream

支持面向缓冲区的异步写入.

AsyncStream

支持面向缓冲区的异步读写的流.

这些模板元函数检查给定类型是否满足各种流 concept 的要求, 另有一些附加的实用工具. 库在内部使用这些类型检查, 并把它们作为公共接口提供, 用户可以用同样的技术增强自己的代码. 使用这些类型检查有助于在编译期间提供更简洁的错误信息:

表 1.5. 类型特征与元函数

名称

说明

executor_type

返回对象类型的别名 (由 get_executor.

has_get_executor

判断 get_executor 成员函数是否存在.

is_async_read_stream

判断类型是否满足 AsyncReadStream.

is_async_stream

判断类型是否同时满足 AsyncReadStream 和 AsyncWriteStream.

is_async_write_stream

判断类型是否满足 AsyncWriteStream.

is_sync_read_stream

判断类型是否满足 SyncReadStream.

is_sync_stream

判断类型是否同时满足 SyncReadStream 和 SyncWriteStream.

is_sync_write_stream

判断类型是否满足 SyncWriteStream.

把类型检查与 static_assert 一起用于函数或类模板类型, 可以为用户提供有用的错误信息并防止未定义行为. 本示例展示向同步流写入的模板函数如何检查其实参:

template<class SyncWriteStream>
void write_string(SyncWriteStream& stream, string_view s)
{
    static_assert(is_sync_write_stream<SyncWriteStream>::value,
        "SyncWriteStream type requirements not met");
    net::write(stream, net::const_buffer(s.data(), s.size()));
}
