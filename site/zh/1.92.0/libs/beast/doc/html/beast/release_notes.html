Boost 1.74

API 变更

  • Asio 的 API 发生了变更. 详情请参见 Asio 发布说明.
  • Beast 已更新以跟踪并尊重开发者在 Asio 使用上的选择. 特别是:
    • 定义 BOOST_ASIO_NO_DEPRECATED 以禁用已弃用的调用钩子.
    • 定义 BOOST_ASIO_NO_TS_EXECUTORS 以确保执行器符合 标准执行器 proposal.
    • 定义 BOOST_ASIO_USE_TS_EXECUTOR_AS_DEFAULT 以选择 Networking TS 风格的执行器. 如果未定义此宏, Asio 默认执行器将是 标准执行器 implementation.
  • #1897 Parser body_limit 变为可选 (API 变更) 需要采取的行动
    • 的签名已更改. 它现在接受一个可选的 basic_parser<>::body_limit(n). 调用方可通过调用 std::uint64_t 来表明不需要正文限制. body_limit(boost::none). 默认限制仍然保留, 以维持 "默认即安全" 的行为.
  • #1934 移除已弃用的接口 (API 变更) 需要采取的行动
    • 宏 BOOST_BEAST_NO_DEPRECATED 将不再被 Beast 识别. 现在启用已弃用功能的唯一方式是宏 BOOST_BEAST_ALLOW_DEPRECATED (默认未定义) . 也就是说, 所有已弃用的行为默认都被禁用.
    • 以下已弃用的函数已被移除:
      • websocket::async_accept_ex
      • websocket::async_handshake_ex
      • websocket::accept_ex
      • websocket::handshake_ex 仍在使用这些名称的程序应重构为使用 decorator 特性以及其余的 handshake 和 accept 函数.
    • websocket::role_type 已被移除. 用户应使用 beast::role_type.
    • handler_ptr 已被移除. 用户应使用 net::bind_handler 和/或 bind_front_handler.
    • 依赖 mutable_data_type 的代码应重构为使用 mutable_buffers_type. 受影响的类有:
      • buffers_adaptor
      • flat_buffer
      • flat_static_buffer
      • multi_buffer
      • static_buffer
    • 该 reset 函数已从 flat_static_buffer 中移除. 请改用 clear 函数.
    • 该 core/type_traits.hpp 公共头文件已被移除, 随之移除的还有类型特征 is_completion_handler. Beast 使用 Asio 提供的 CompletionHandler 正确性检查. 在 C++20 环境中, 这些检查会转换为 concept 检查.
    • 错误码枚举 invalid_code_lenths (原文如此) 曾是 invalid_code_lengths 的同义词. 受影响的程序应修改为使用 invalid_code_lengths.
    • 文件 core/buffers_adapter.hpp 已被移除, 随之移除的还有已弃用的别名类型 buffers_adapter. 受影响的程序应使用 core/buffers_adapator.hpp 以及类型 buffers_adaptor.
  • #1956 弃用 string_param (API Change) 需要采取的行动 string_param (先前设置字段值时的参数类型) 已被 string_view 取代. 因此, 不能再直接以整数设置报文字段值; 用户必须在调用 fields::set 等之前把数值参数转换为字符串类型. 为此 Beast 提供了非分配的 to_static_string() 函数. 要手动设置 Content-Length 字段, 请调用 message::content_length.

  • (#849) WebSocket permessage-deflate 支持现在是编译期特性. 这增加了一个额外的 bool 模板参数到 websocket::stream 当 deflateSupported 为 true, 流将能按配置的运行时设置协商 permessage-deflate websocket 扩展. 当 deflateSupported 为 false, 流将永远不会协商 permessage-deflate websocket 扩展. 此外, 实现 permessage-deflate 扩展所需的全部代码都会被排除在函数实例化之外. 将 deflateSupported 设置为 false 来实例化流, 程序体积会更小.
