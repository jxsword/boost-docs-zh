websocket::stream::async_read_some (2 of 2 overloads)

异步读取部分报文数据.

概要 
template<
    class MutableBufferSequence,
    class ReadHandler = net::default_completion_token_t<                executor_type>>
DEDUCED
async_read_some(
    MutableBufferSequence const& buffers,
    ReadHandler&& handler = net::default_completion_token_t< executor_type >{});
说明

此函数用于异步读取部分报文数据.

此调用总是立即返回. 异步操作将持续到以下条件之一成立:

  • 部分报文数据已接收.
  • 收到了关闭帧. 此时函数指示的错误为 error::closed.
  • 发生错误.

该算法称为 组合异步操作, 是通过调用下一层的 async_read_some 和 async_write_some 函数. 程序必须确保没有对 read, read_some, async_read 或 async_read_some 的其他调用.

收到的报文数据会被追加到缓冲区. 函数 got_binary 和 got_text 可用于查询流并确定最后收到的报文的类型. 函数 is_message_done 可用于判断最后一次读取操作收到的报文是否完整.

在此操作完成之前, 实现会读取传入的控制帧并自动按以下方式处理:

  • 该 control_callback 将在每个控制帧上被调用.
  • 对收到的每个 ping 帧, 都会自动发送一个 pong 帧.
  • 如果收到关闭帧, 将执行 WebSocket 关闭过程. 此时函数返回的错误为 error::closed 将被指示.

读取操作未完成期间, 实现发送的 pong 帧和关闭帧不会妨碍应用程序同时写入报文数据、发送 ping、发送 pong 或发送关闭帧.

参数

名称

说明

buffers

用于写入报文数据的缓冲区序列. 缓冲区从开头起原有的内容会被覆盖. 实现会按需复制此对象, 但不转移底层内存的所有权. 调用方负责确保缓冲区序列所指向的内存位置在完成处理器被调用之前保持有效.

handler

操作完成时要调用的完成处理器. 实现通过衰减复制取得处理器的所有权. 处理器的等效函数签名必须是:

void handler(
    error_code const & ec,       // Result of operation
    std::size_t bytes_written   // Number of bytes written to the buffers
);

若处理器有关联的立即执行器, 将向它派发立即完成. 否则, 处理器不会在此函数内部被调用. 处理器的调用将通过派发到立即执行器完成. 若未指定立即执行器, 这等同于使用 net::post.
逐操作取消

此异步操作支持以下 net::cancellation_type 值的取消:

  • net::cancellation_type::terminal
  • net::cancellation_type::total

total: 若操作因正在进行的控制操作 (如 ping/pong) 而挂起, 则取消会成功.

terminal: 在底层流支持时, 取消会成功.

terminal: 取消会使流处于未定义状态, 此时只有关闭操作保证能成功.
