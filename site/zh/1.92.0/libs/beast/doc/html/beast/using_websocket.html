WebSocket

WebSocket 协议支持在受控环境中运行不可信代码的客户端与选择加入该代码通信的远程主机之间进行双向通信. 该协议由一个开场握手加基本报文成帧组成, 分层于 TCP 之上. 此技术的目标是为需要与服务器双向通信的基于浏览器的应用提供一种机制, 而不必依赖打开多个 HTTP 连接.

Beast 为开发者提供了构建于 Boost.Asio 之上、采用现代 C++ 方法、具有一致异步模型的健壮 WebSocket 实现.

注释

本文档假定读者熟悉 Boost.Asio 以及 rfc6455 的协议规范. 本节出现的示例代码和标识符都以下列声明生效为前提书写:

#include <boost/beast.hpp>
#include <boost/asio.hpp>
#include <boost/asio/ssl.hpp>


namespace net = boost::asio;
namespace beast = boost::beast;
using namespace boost::beast;
using namespace boost::beast::websocket;

net::io_context ioc;
tcp_stream sock(ioc);
net::ssl::context ctx(net::ssl::context::tlsv12);

构造

WebSocket 连接需要一个有状态对象, Beast 中以单一类模板 websocket::stream 表示. 接口采用分层流模型. websocket 流对象包含另一个流对象 (称为 "下一层") , 用它执行 I/O. 各模板参数说明如下:

namespace boost {
namespace beast {
namespace websocket {

template<
    class NextLayer,
    bool deflateSupported = true>
class stream;

} // websocket
} // beast
} // boost

表 1.30. WebSocket 流模板参数

名称

说明

NextLayer

下一层的类型. 此类型的对象将被构造并在流的生存期内维护. 所有读写都要经过下一层. 此类型必须满足 SyncStream, AsyncStream 之一或两者都满足, 取决于要执行的 I/O 风格.

deflateSupported

当此值为 true 时, 流将支持 (但不要求) permessage-deflate 扩展. 流在握手期间是否实际请求或接受该扩展取决于另一个可配置选项.

当值为 false 时扩展被禁用. 流在客户端角色下永远不会请求该扩展, 在服务器角色下也不会接受扩展请求. 禁用扩展的额外好处是编译更快, 生成的可执行程序代码更少.

构造流时, 提供给构造函数的任何实参都会被转发给下一层对象的构造函数. 下面声明一个位于普通 TCP/IP 套接字之上、使用 I/O 上下文的流:

// This newly constructed WebSocket stream will use the specified
// I/O context and have support for the permessage-deflate extension.

stream<tcp_stream> ws(ioc);
提示

websocket 流使用其自身协议特定的超时特性. 将 websocket 流与 tcp_stream 或 basic_stream 类模板配合使用时, 连接建立后应禁用 TCP 流或 basic 流上的超时, 否则流的行为未定义.

与大多数 I/O 对象一样, websocket 流 不是线程安全的. 两个不同线程并发访问该对象会导致未定义行为. 对多线程程序, tcp_stream 可以由执行器构造 (此处为 strand) . 下面声明的流将使用 strand 调用所有完成处理器:

// The `tcp_stream` will be constructed with a new
// strand which uses the specified I/O context.

stream<tcp_stream> ws(net::make_strand(ioc));

如果下一层支持移动构造, 则 websocket 流可以从移动后的对象构造.

// Ownership of the `tcp_stream` is transferred to the websocket stream

stream<tcp_stream> ws(std::move(sock));

可以通过调用 stream::next_layer.

// Calls `close` on the underlying `beast::tcp_stream`
ws.next_layer().close();

使用 SSL

要通过 SSL 使用 WebSocket, 请把 net::ssl::stream 类模板的实例用作流的模板类型. 所需的 net::io_context 和 net::ssl::context 实参被转发给被包装流的构造函数:

// The WebSocket stream will use SSL and a new strand
stream<net::ssl::stream<tcp_stream>> wss(net::make_strand(ioc), ctx);
重要

使用 Asio SSL 类型声明 websocket 流对象的代码必须包含文件 <boost/beast/websocket/ssl.hpp>.

与前述一样, 可以通过调用 next_layer.

// Perform the SSL handshake in the client role
wss.next_layer().handshake(net::ssl::stream_base::client);

对于上面这样的多层流, 使用链式调用 next_layer 的方式进行. 为此提供了函数 get_lowest_layer 返回分层流中层栈里的最后一个流. 这里我们访问最底层以取消所有未完成的 I/O.

// Cancel all pending I/O on the underlying `tcp_stream`
get_lowest_layer(wss).cancel();

非阻塞模式

请注意, websocket 流不支持非阻塞模式.
