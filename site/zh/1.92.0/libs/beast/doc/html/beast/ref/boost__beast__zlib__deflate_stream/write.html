zlib::deflate_stream::write

压缩输入并写出输出.

概要 
void
write(
    z_params& zs,
    Flush flush,
    error_code& ec);
说明

此函数尽可能多地压缩数据, 并在输入缓冲区变空或输出缓冲区变满时停止. 除非被强制刷新, 否则它可能引入一些输出延迟 (读取输入而不产生任何输出) .

每次调用会执行以下动作中的一个或两个:

  • 从 zs.next_in 开始压缩更多输入, 并相应更新 zs.next_in 和 zs.avail_in. 如果并非所有输入都能被处理 (因为输出缓冲区空间不足) , zs.next_in 和 zs.avail_in 会被更新, 处理将在下一次调用时从此处继续.
  • 从 zs.next_out 开始压缩更多输入, 并相应更新 zs.next_out 和 zs.avail_out. 若参数 flush 不是 Flush::none, 则强制执行此动作. 频繁强制刷新会降低压缩率, 因此仅应在必要时设置此参数 (交互式应用中) . 即使未设置 flush, 也可能产生部分输出.

调用之前, 应用程序必须通过提供更多输入和/或消费更多输出来确保至少有一个动作可执行, 并相应更新 zs.avail_in 或 zs.avail_out; zs.avail_out 在调用之前绝不能为零. 应用程序可以在其需要时消费压缩输出, 例如当输出缓冲区已满 (zs.avail_out == 0) 时, 或在每次调用 write 之后. 若 write 以零 zs.avail_out 返回无错误, 则必须在腾出输出缓冲区空间后再次调用, 因为可能还有更多输出待决.

通常参数 flush 设置为 Flush::none, 让 deflate 自行决定在产出输出前累积多少数据, 以最大化压缩率.

如果参数 flush 设置为 Flush::sync, 则所有待决输出都会刷新到输出缓冲区, 且输出对齐到字节边界, 使解压器能获得目前为止的全部输入数据. 特别是调用后 zs.avail_in 若调用前提供了足够的输出空间, 则变为零. 刷新可能降低某些压缩算法的压缩率, 因此只在必要时使用. 此操作会完成当前 deflate 块, 并在其后追加一个空存储块: 三比特加上填充到下一字节的填充位, 随后是四个字节 { 0x00, 0x00 0xff 0xff }.

如果 flush 设置为 Flush::partial, 则所有待决输出都会刷新到输出缓冲区, 但输出不对齐到字节边界. 与 Z_SYNC_FLUSH 一样, 到目前为止的所有输入数据都可供解压器使用. 此操作会完成当前 deflate 块, 并在其后追加一个长度为 10 位的空定长码块. 这保证了输出足够多的字节, 使解压器能在该空定长码块之前完成当前块的处理.

如果 flush 设置为 Flush::block, 会完成并发出一个 deflate 块, 如同 Flush::sync, 但输出不对齐到字节边界, 且当前块最多保留七位, 留待下一个 deflate 块完成后作为下一字节写出. 此时, 解压器此时可能得不到足够的位来完成对已提供给压缩器的数据的解压, 可能需要等待下一个块发出. 这适用于需要控制 deflate 块发出的高级应用.

如果 flush 设置为 Flush::full, 所有输出都会像 Flush::sync 一样被刷新, 且压缩状态被重置, 这样若先前压缩的数据损坏或需要随机访问, 解压可以从这一点重新开始. 过于频繁地使用 Flush::full 会严重降低压缩率.

如果 write 返回 zs.avail_out == 0, 必须以相同的 flush 参数值和更多的输出空间 (更新 zs.avail_out) 再次调用本函数, 直到刷新完成 (write 返回非零 zs.avail_out) . 对于 Flush::full或 Flush::sync, 请确保 zs.avail_out 大于 6, 以避免因 zs.avail_out == 0 而在返回时出现重复的刷新标记.

如果参数 flush 设置为 Flush::finish, 待决输入会被处理, 待决输出会被刷新, 且 deflate 返回错误 error::end_of_stream (若输出空间足够) ; 若 deflate 无错误返回, 则必须以 Flush::finish 和更多输出空间 (更新 zs.avail_out) 再次调用本函数, 但不再提供输入数据, 直到它返回错误 error::end_of_stream 或其他错误. 在 write 已返回 error::end_of_stream 错误之后, 对流唯一可能的操作就是重置或销毁.

Flush::finish 若所有压缩要在单步中完成, 可在初始化之后立即使用. 此时, zs.avail_out 至少应为 upper_bound 返回的值 (见下文) . 然后 write 保证返回 error::end_of_stream 错误. 如果未提供足够的输出空间, deflate 将不会返回 error::end_of_stream, 必须如上所述再次调用.

write: 若取得了一些进展 (处理了更多输入或产出了更多输出) 则返回无错误, error::end_of_stream (所有输入都已消费且所有输出都已产出时, 仅当 flush 设置为 Flush::finish), error::stream_error (流状态不一致时, 例如 zs.next_in 或 zs.next_out 为 nullptr), error::need_buffers (无法取得进展时, 例如 zs.avail_in 或 zs.avail_out 为零) . 注意, error::need_buffers 并非致命错误, write 可以在提供更多输入和输出空间后再次调用以继续压缩.
