zlib::inflate_stream::write

解压输入并产出输出.

概要 
void
write(
    z_params& zs,
    Flush flush,
    error_code& ec);
说明

此函数尽可能多地解压数据, 并在输入缓冲区变空或输出缓冲区变满时停止. 除非被强制刷新, 否则它可能引入一些输出延迟 (读取输入而不产生任何输出) .

会执行以下动作中的一个或两个:

  • 从 zs.next_in 开始压缩更多输入, 并相应更新 zs.next_in 和 zs.avail_in. 如果并非所有输入都能被处理 (因为输出缓冲区空间不足) , zs.next_in 会被更新, 处理将在下一次调用时从此处继续.
  • 从 zs.next_out 开始压缩更多输入, 并相应更新 zs.next_out 和 zs.avail_out. write 会尽可能多地提供输出, 直到没有更多输入数据或输出缓冲区没有更多空间 (关于 flush 参数见下文) .

调用之前, 应用程序应通过提供更多输入和/或消费更多输出来确保至少有一个动作可执行, 并相应更新 zs 中的值. 应用程序可以在其需要时消费未压缩的输出, 例如当输出缓冲区已满 (zs.avail_out == 0) 时, 或在每次调用之后. 若 write 返回无错误且 zs.avail_out 返回无错误, 则必须在腾出输出缓冲区空间后再次调用, 因为可能还有更多输出待决.

flush 参数可以是 Flush::none, Flush::sync, Flush::finish, Flush::block 或 Flush::trees. Flush::sync: 请求将尽可能多的输出刷新到输出缓冲区. Flush::block: 请求在到达下一个 deflate 块边界时停止. 解码 zlib 或 gzip 格式时, 这会使 write 在头部之后、第一个块之前立即返回. 执行 raw inflate 时, write 会继续处理第一个块, 并在到达该块末尾或数据耗尽时返回.

该 Flush::block 选项有助于拼接或合并 deflate 流. 为此, 返回时 write 会将 zs.data_type 设置为从 zs.next_in 取出的最后一个字节中未使用的位数; 若 write 正在解码 deflate 流的最后一个块, 则加 64; 若 write 在解码块结束码之后、或解码完整头部直至 deflate 流第一个字节之前立即返回, 则再加 128. 在该块的未压缩数据全部写入 zs.next_out 之前, 不会指示块结束. 未使用位数通常可能大于七, 除非 zs.data_type 的第 7 位被设置, 此时未使用位数将小于八. zs.data_type 会按这里所述在 write 以任何 flush 选项返回时设置, 因此可用于确定当前已消费输入的位数.

该 Flush::trees 选项的行为如同 Flush::block, 但它还会在每个 deflate 块头的末尾、解码该块中任何实际数据之前返回. 这使调用方能够确定 deflate 块头的长度, 以便日后在 deflate 块内进行随机访问. 此时 zs.data_type 的值加上 256 (当 write 在到达 deflate 块头末尾后立即返回时) .

write 通常应一直调用直到它返回 error::end_of_stream 或其他错误. 但如果所有解压要在单步中完成 (即单次调用 write) , 参数 flush 应设置为 Flush::finish. 此时所有待决输入都会被处理, 所有待决输出都会被刷新; zs.avail_out 必须足够大以容纳全部未压缩数据, 操作才能完成. (压缩器可能已为这一目的保存了未压缩数据的大小. ) 使用 Flush::finish 并非单步解压所必需, 但它可用于告知 inflate 在这一次调用中可以使用更快的处理方式. Flush::finish 还会让 inflate 在流完成时不维护滑动窗口, 从而降低 inflate 的内存占用. 若流未完成 (或因为未提供完整流, 或因为输出空间不足) , 则会分配滑动窗口, 且 write 可以再次调用以继续操作, 如同 Flush::none 被使用过一样.

在本实现中, write 总是尽可能多地把输出刷新到输出缓冲区, 并且总是在第一次调用时使用更快的处理方式. 因此本实现中 flush 参数的影响体现在 write 的返回值上, 如下所述: 当 write 提前返回时 (当使用 Flush::block 或 Flush::trees 时) , 以及当 write 避免为滑动窗口分配内存时 (当使用 Flush::finish 时) .

如果此调用之后需要预设字典, write 会设置 zs.adler 设置为压缩器所选字典的 Adler-32 校验和, 并返回 error::need_dictionary; 否则将 zs.adler 设置为目前为止全部输出 (即 zs.total_out bytes) 的 Adler-32 校验和, 并返回无错误、error::end_of_stream, 或下文所述的错误码. 在流结束时, write 会检查其计算的 adler32 校验和是否与压缩器保存的一致, 仅当校验和正确时才返回 error::end_of_stream.

此函数在取得进展 (处理了更多输入或产出了更多输出) 时返回无错误; error::end_of_stream (已到达压缩数据末尾且全部未压缩输出已产出时) ; error::need_dictionary (此时需要预设字典时) ; error::invalid_data (输入数据损坏时: 输入流不符合 zlib 格式或校验值不正确) ; error::stream_error (流结构不一致时, 例如 zs.next_in 或 zs.next_out 为 null) ; error::need_buffers (无法取得进展, 或使用 Flush::finish 时输出缓冲区空间不足) . 注意, error::need_buffers 并非致命错误, write 可以在提供更多输入和输出空间后再次调用以继续解压.
