报文容器

Beast 提供单一类模板 message 以及若干别名, 用于建模 HTTP/1 与 HTTP/2 报文:

表 1.16. 报文

名称

说明

message 

/// An HTTP message
template<
    bool isRequest,             // `true` for requests, `false` for responses
    class Body,                 // Controls the container and algorithms used for the body
    class Fields = fields>      // The type of container to store the fields
class message;

request 

/// A typical HTTP request
template<class Body, class Fields = fields>
using request = message<true, Body, Fields>;

response 

/// A typical HTTP response
template<class Body, class Fields = fields>
using response = message<false, Body, Fields>;

该容器提供值语义; 若 Body 和 Fields 支持则包括移动和复制. 用户自定义的模板函数参数可以接受任何报文, 或用偏特化只接受请求或响应. 默认的 fields 是库提供的关联容器, 使用标准分配器, 支持字段的修改与检查. 按照 rfc7230 的规定, 字段名使用不区分大小写的比较. 字段可以使用用户自定义类型. Body 类型决定用于表示正文的容器类型, 以及向容器传入和从容器传出缓冲区的算法. 库自带一组常用正文类型. 与字段一样, 正文类型也可以用户自定义.

有时只需要处理头部. Beast 提供单一类模板 header 以及若干别名, 用于建模 HTTP/1 与 HTTP/2 头部:

表 1.17. 头部

名称

说明

header 

/// An HTTP header
template<
    bool isRequest,             // `true` for requests, `false` for responses
    class Fields = fields>      // The type of container to store the fields
class header;

request_header 

/// A typical HTTP request header
template<class Fields>
using request_header = header<true, Fields>;

response_header 

/// A typical HTTP response header
template<class Fields>
using response_header = header<false, Fields>;

请求与响应共享版本、字段和正文, 但各自有少数类型特有的成员. 这通过把头部类声明为 isRequest. message 派生自 header; 报文可以作为实参传给以相应类型头部为形参的函数. 此外, header 公开派生自 Fields; 报文继承 Fields 的所有成员函数. 下图展示头部与报文之间的继承关系, 以及各偏特化中成员的一些显著差异:

正文类型

Beast 定义了 Body concept, 它既决定 message::body 成员的类型 (如上图所示) , 也可以包含传入和传出缓冲区的算法. 这些算法在解析和序列化期间使用. 用户可以定义满足要求的自己的正文类型, 或使用库自带的正文类型:

名称

说明

buffer_body

正文, 其 value_type 保存指向调用方所提供缓冲区的原始指针和大小. 这允许对来自外部来源的正文数据进行序列化, 并使用固定大小缓冲区对报文正文内容进行增量解析.

dynamic_body

basic_dynamic_body

正文, 其 value_type 是一个 DynamicBuffer. 它继承底层动态缓冲区选择的插入复杂度. 具有此正文类型的报文可以被序列化和解析.

empty_body

特殊的正文, 其 value_type 为空, 表示报文没有正文. 具有此正文的报文可以被序列化和解析; 但解析具有此正文的报文时收到的正文八位组会产生一个特定错误.

file_body

basic_file_body

此正文由一个以读或写方式打开的文件表示. 具有此正文的报文可以被序列化和解析. HTTP 算法将使用打开的文件进行读写, 实现流式与增量收发.

span_body

正文, 其 value_type 是一个 span (不拥有所有权) , 是对单个线性字节缓冲区的引用. 具有此正文类型的报文可以被序列化和解析.

string_body

basic_string_body

正文, 其 value_type 为 std::basic_string 或 std::string. 插入复杂度为均摊常数时间, 容量按几何级数增长. 具有此正文类型的报文可以被序列化和解析. 示例中使用的正文就是这种类型.

vector_body

正文, 其 value_type 为 std::vector. 插入复杂度为均摊常数时间, 容量按几何级数增长. 具有此正文类型的报文可以被序列化和解析.
用法

这些示例展示如何创建并填充请求与响应对象: 这里我们构建一个带空报文正文的 HTTP GET 请求:

表 1.18. 创建请求

Statements

序列化结果

 
request<empty_body> req;
req.version(11);   // HTTP/1.1
req.method(verb::get);
req.target("/index.htm");
req.set(field::accept, "text/html");
req.set(field::user_agent, "Beast");

GET /index.htm HTTP/1.1\r\n
Accept: text/html\r\n
User-Agent: Beast\r\n
\r\n

在这段代码中, 我们创建了一个状态码表示成功的 HTTP 响应. 该报文具有长度非零的正文. 函数 message::prepare_payload 会根据 body 成员的内容和类型自动设置 Content-Length 或 Transfer-Encoding 字段. 此函数的使用是可选的; 这些字段也可以显式设置.

表 1.19. 创建响应

Statements

序列化结果

 
response<string_body> res;
res.version(11);   // HTTP/1.1
res.result(status::ok);
res.set(field::server, "Beast");
res.body() = "Hello, world!";
res.prepare_payload();

HTTP/1.1 200 OK\r\n
Server: Beast\r\n
Content-Length: 13\r\n
\r\n
Hello, world!

实现会在序列化报文时根据状态码自动填写已废弃的 reason-phrase. 也可以用 header::reason.
