此类的实例模拟传统套接字, 同时提供对单元测试有用的特性. 每个端点维护一个称为输入区的独立缓冲区. 一端的写入会把数据追加到对端的待决输入区. 当一端执行读取且输入区中有数据时, 数据会被交付给阻塞或异步操作; 否则操作会被阻塞或推迟, 直到数据可用或端点断开连接.

凡是算法接受同步或异步读/写流引用的地方, 都可以使用这些流. 可以在调用 net::read_until 时使用测试流, 也可以在调用 boost::beast::http::async_write 时使用, 例如.

与 Boost.Asio 的 I/O 对象一样, stream 以对 net::io_context 的引用来构造, 该对象用于处理异步 I/O. 对于异步操作, 该流遵循与传统 asio 套接字相同的规则来执行异步操作的完成处理器.

为便于测试, 这些流支持一些附加特性:

  • 输入区由一个 beast::basic_flat_buffer 表示, 调用方可以在远程端点写入数据之前或之后直接访问它以检查内容. 这使单元测试能够验证收到的数据是否匹配.
  • 可以手动向输入区追加数据. 这些数据将在下一次调用 stream::read_some 或 stream::async_read_some 时交付. 这样就可以为测试读取算法预先设置好测试向量.
  • 流可以带失败计数构造. 在执行一定数量的操作后, 流将以预定义错误失败, 操作次数由测试控制. 当测试对一组操作计数进行循环时, 可以触发被测算法的每一个可能的失败点. 正确使用该技术可以让测试达到很高的代码覆盖率.
线程安全

Distinctobjects: 安全.

Sharedobjects: 不安全. 应用程序还必须确保所有异步操作都在同一个隐式或显式 strand 中执行.
