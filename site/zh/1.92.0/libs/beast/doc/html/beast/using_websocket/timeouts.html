超时

虽然 basic_stream 和 tcp_stream 支持一般逻辑操作的超时之外, websocket 流还内置了更复杂的超时机制, 可以启用和配置. 使用 websocket 流时不应使用 TCP 流或 basic 流的超时特性. 这些超时特性的接口如下表所示.

表 1.36. WebSocket 超时接口

名称

说明

stream_base::timeout

这表示 websocket 流的已配置超时设置.

stream_base::timeout::suggested

此函数返回给定角色 (客户端或服务器) 的建议超时设置.

stream::set_option

此函数在流上设置超时和其他选项.

流上有三个可以独立设置的超时设置:

表 1.37. WebSocket 超时接口 (2)

名称

类型

说明

timeout::handshake_timeout

duration

这是握手超时所需的时间. 握手超时适用于客户端握手、服务器握手, 以及连接任一端希望关闭时执行的 websocket 关闭握手. stream_base::none() 可被赋值以禁用此超时.

timeout::idle_timeout

duration

如果在等于空闲超时的时间内没有从对端收到数据或控制帧, 连接将超时. stream_base::none() 可被赋值以禁用此超时.

timeout::keep_alive_pings

bool

如果启用了空闲超时, 此设置的值决定: 当在空闲超时区间的一半时间内没有收到数据时, 是否向对端发送 ping 帧.

默认情况下, websocket 流的超时是禁用的. 开启它们最简单的方式是把建议的超时设置设置到流上.

// Apply suggested timeout options for the server role to the stream
ws.set_option(stream_base::timeout::suggested(role_type::server));

要手动控制这些设置, 可以构造超时选项对象. 这里我们只启用握手超时.

stream_base::timeout opt{
    std::chrono::seconds(30),   // handshake timeout
    stream_base::none(),        // idle timeout
    false
};

// Set the timeout options on the stream.
ws.set_option(opt);

超时通知通过以错误码 error::timeout 的错误调用未完成异步读取操作的完成处理器来交付给调用方. 实现会在交付此错误之前关闭套接字或流. 无需手动关闭连接, 因为它已经被关闭. 必须有未完成的读取操作, 错误才能被交付.

ws.async_read(b,
    [](error_code ec, std::size_t)
    {
        if(ec == beast::error::timeout)
            std::cerr << "timeout, connection closed!";
    });
注释

websocket 超时特性只有在使用异步 I/O 时可用.

websocket 流上的超时与 tcp_stream 中使用的超时不兼容. 从启用了超时的 tcp 流构造 websocket 流时, 应先禁用超时再构造 websocket 流, 如下所示.

// Disable any timeouts on the tcp_stream
sock.expires_never();

// Construct the websocket stream, taking ownership of the existing tcp_stream
stream<tcp_stream> ws(std::move(sock));
