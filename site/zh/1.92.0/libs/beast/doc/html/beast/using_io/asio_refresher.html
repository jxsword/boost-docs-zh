温习

要有效使用 Beast, 需要事先理解 Networking. 本节回顾这些概念, 作为温习和进一步学习的指引.

一个 网络使位于任何地方的程序在建立 连接 (选择加入通信) 之后交换信息. 数据可以通过连接双向可靠传输 (全双工) , 字节按发送顺序到达. 这些连接连同用于表示它们的对象和类型, 统称为 流. 连接到网络的计算机或设备称为 主机, 已建立连接另一端的程序称为 对端.

该 互联网是由互联计算机组成的全球网络, 它们使用各种标准化通信协议交换信息. 最流行的协议是 TCP/IP, 本库完全依赖它. 该协议负责低层细节, 使应用程序看到的是 stream, 即上述携带有序字节集的可靠全双工连接. 服务器 是位于知名网络名称或网络地址上、持续在线并提供数据服务的强大主机. 客户端 是临时性的对端, 它连接到服务器交换数据, 然后离线.

供应商提供一个称为 设备驱动 的程序, 使网络硬件 (如 以太网适配器) 能够与操作系统通信. 这进而允许运行中的程序通过各种风格的接口 (如 Berkeley 套接字 或 Windows Sockets 2 ("Winsock") .

C++ 中的 Networking 以 Boost.Asio, Asio 和 Networking TS 为代表, 提供一层抽象, 可移植地与操作系统设施交互, 不仅限于网络, 还包括一般 输入/输出 ("I/O") .

缓冲区

一个 缓冲区 保存执行 I/O 时使用的连续字节序列. 类型 net::const_buffer 和 net::mutable_buffer 把这些内存区域表示为类型安全的指针/大小对:

net::const_buffer cb("Hello, world!", 13);
assert(string_view(reinterpret_cast<char const*>(
    cb.data()), cb.size()) == "Hello, world!");

char storage[13];
net::mutable_buffer mb(storage, sizeof(storage));
std::memcpy(mb.data(), cb.data(), mb.size());
assert(string_view(reinterpret_cast<char const*>(
    mb.data()), mb.size()) == "Hello, world!");
提示

const_buffer 和 mutable_buffer 优先于 std::span<byte> 和 span<byte const> 因为 std::span 做了太多事情: 它不仅对原始指针做类型擦除, 还把它重铸为字节指针. 操作系统对此并不在意, 但如果用户想发送和接收其他类型的数组, 把它表示为支持位运算的字节数组并无必要. 自定义缓冲区类型还使实现能够提供有针对性的特性, 例如 缓冲区调试, 而不必改动更通用的词汇类型.

concept ConstBufferSequence 和 MutableBufferSequence 描述值类型可分别转换为 const_buffer 和 mutable_buffer 的双向范围. 这些序列允许在单次函数调用中处理多个缓冲区, 这一技术称为 分散/聚集 I/O. 缓冲区与缓冲区序列不拥有内存; 复制产生的是浅引用而非底层内存的副本. 以下每条语句都声明了一个缓冲区序列:

net::const_buffer b1;                   // a ConstBufferSequence by definition
net::mutable_buffer b2;                 // a MutableBufferSequence by definition
std::array<net::const_buffer, 3> b3;    // A ConstBufferSequence by named requirements

函数 net::buffer_size 和 net::buffer_copy 分别用于确定缓冲区序列中的总字节数, 以及把字节从一个缓冲区序列部分或全部地转移到另一个. 函数 buffer_size 是一个定制点: 可以在外部命名空间定义用户重载, 调用方应不加命名空间限定地调用 buffer_size. 函数 net::buffer_sequence_begin 和 net::buffer_sequence_end 用于获得遍历序列的迭代器对. Beast 提供一组缓冲区序列类型与算法, 例如 buffers_cat, buffers_front, buffers_prefix, buffers_range 和 buffers_suffix. 本示例把缓冲区序列中的字节作为字符串返回:

template <class ConstBufferSequence>
std::string string_from_buffers (ConstBufferSequence const& buffers)
{
    // check that the type meets the requirements using the provided type traits
    static_assert(
        net::is_const_buffer_sequence<ConstBufferSequence>::value,
        "ConstBufferSequence type requirements not met");

    // optimization: reserve all the space for the string first
    std::string result;
    result.reserve(beast::buffer_bytes(buffers));        // beast version of net::buffer_size

    // iterate over each buffer in the sequence and append it to the string
    for(auto it = net::buffer_sequence_begin(buffers);  // returns an iterator to beginning of the sequence
        it != net::buffer_sequence_end(buffers);)       // returns a past-the-end iterator to the sequence
    {
        // A buffer sequence iterator's value_type is always convertible to net::const_buffer
        net::const_buffer buffer = *it++;

        // A cast is always required to out-out of type-safety
        result.append(static_cast<char const*>(buffer.data()), buffer.size());
    }
    return result;
}

该 DynamicBuffer concept 定义了可调整大小的缓冲区序列接口. 当内存需求事先未知时 (例如从流读取 HTTP 报文时) , 算法可以用动态缓冲区表达. Beast 提供了一整套动态缓冲区类型, 例如 buffers_adaptor, flat_buffer, multi_buffer 和 static_buffer. 下面的函数从 tcp_stream 读入动态缓冲区, 直到遇到换行符, 并使用 net::buffers_iterator 把缓冲区内容当作字符范围:

// Read a line ending in '\n' from a socket, returning
// the number of characters up to but not including the newline
template <class DynamicBuffer>
std::size_t read_line(net::ip::tcp::socket& sock, DynamicBuffer& buffer)
{
    // this alias keeps things readable
    using range = net::buffers_iterator<
        typename DynamicBuffer::const_buffers_type>;

    for(;;)
    {
        // get iterators representing the range of characters in the buffer
        auto begin = range::begin(buffer.data());
        auto end = range::end(buffer.data());

        // search for "\n" and return if found
        auto pos = std::find(begin, end, '\n');
        if(pos != range::end(buffer.data()))
            return std::distance(begin, end);

        // Determine the number of bytes to read,
        // using available capacity in the buffer first.
        std::size_t bytes_to_read = std::min<std::size_t>(
              std::max<std::size_t>(512,                // under 512 is too little,
                  buffer.capacity() - buffer.size()),
              std::min<std::size_t>(65536,              // and over 65536 is too much.
                  buffer.max_size() - buffer.size()));

        // Read up to bytes_to_read bytes into the dynamic buffer
        buffer.commit(sock.read_some(buffer.prepare(bytes_to_read)));
    }
}
同步 I/O

同步输入输出通过阻塞式函数调用完成, 调用返回时即得到操作结果. 这类操作通常无法取消, 也没有设置超时的方法. SyncReadStream 和 SyncWriteStream concept 为 同步流 定义了要求: 一种可移植的 I/O 抽象, 使用缓冲区序列表示字节来传输数据, 并以 error_code 或异常来报告失败. net::basic_stream_socket 是常用于建立 TCP/IP 连接的同步流. 满足要求的用户自定义类型也是可能的:

// Meets the requirements of SyncReadStream
struct sync_read_stream
{
    // Returns the number of bytes read upon success, otherwise throws an exception
    template <class MutableBufferSequence>
    std::size_t read_some(MutableBufferSequence const& buffers);

    // Returns the number of bytes read successfully, sets the error code if a failure occurs
    template <class MutableBufferSequence>
    std::size_t read_some(MutableBufferSequence const& buffers, error_code& ec);
};

// Meets the requirements of SyncWriteStream
struct sync_write_stream
{
    // Returns the number of bytes written upon success, otherwise throws an exception
    template <class ConstBufferSequence>
    std::size_t write_some(ConstBufferSequence const& buffers);

    // Returns the number of bytes written successfully, sets the error code if a failure occurs
    template <class ConstBufferSequence>
    std::size_t write_some(ConstBufferSequence const& buffers, error_code& ec);
};

一个 同步流算法 写成函数模板, 接受满足同步读、写或读写命名要求的流对象. 本示例展示一个写入文本并用异常指示错误的算法:

template <class SyncWriteStream>
void hello (SyncWriteStream& stream)
{
    net::const_buffer cb("Hello, world!", 13);
    do
    {
        auto bytes_transferred = stream.write_some(cb); // may throw
        cb += bytes_transferred; // adjust the pointer and size
    }
    while (cb.size() > 0);
}

同一算法也可以改用错误码而非异常来表达:

template <class SyncWriteStream>
void hello (SyncWriteStream& stream, error_code& ec)
{
    net::const_buffer cb("Hello, world!", 13);
    do
    {
        auto bytes_transferred = stream.write_some(cb, ec);
        cb += bytes_transferred; // adjust the pointer and size
    }
    while (cb.size() > 0 && ! ec);
}
异步 I/O

异步操作以调用 发起函数 开始, 发起函数启动操作后立即返回调用方. 此 未完成的 异步操作并发进行, 不阻塞调用方. 当外部可观察的副作用完全确立后, 一个可移动的函数对象 (称为 完成处理器, 在发起函数调用中提供) 会连同结果 (可能包括错误码和其他特定信息) 一起排队等待执行. 此时称异步操作已 已完成的 (完成处理器入队后) . 下面的代码展示如何异步地向套接字写入文本, 并在操作完成时调用一个 lambda:

// initiate an asynchronous write operation
net::async_write(sock, net::const_buffer("Hello, world!", 13),
    [](error_code ec, std::size_t bytes_transferred)
    {
        // this lambda is invoked when the write operation completes
        if(! ec)
            assert(bytes_transferred == 13);
        else
            std::cerr << "Error: " << ec.message() << "\n";

        (void)bytes_transferred;
    });
// meanwhile, the operation is outstanding and execution continues from here

每个完成处理器 (也称为 延续) 都同时具有 关联分配器 (由 net::get_associated_allocator 返回) , 关联取消槽 (由 net::get_associated_cancellation_slot, 以及 关联执行器 (由 net::get_associated_executor. 这些关联可以侵入式地指定:

// The following is a completion handler expressed
// as a function object, with a nested associated
// allocator and a nested associated executor.
struct handler
{
    using allocator_type = std::allocator<char>;
    allocator_type get_allocator() const noexcept;

    using executor_type = boost::asio::io_context::executor_type;
    executor_type get_executor() const noexcept;

    using cancellation_slot_type =  boost::asio::cancellation_slot;
    cancellation_slot_type get_cancellation_slot() const noexcept;

    void operator()(boost::beast::error_code, std::size_t);
};

或者, 也可以通过特化类模板 net::associated_allocator , net::associated_cancellation_slot 和 net::associated_executor:

namespace boost {
namespace asio {

template<class Allocator>
struct associated_allocator<handler, Allocator>
{
    using type = std::allocator<void>;

    static
    type
    get(handler const& h,
        Allocator const& alloc = Allocator{}) noexcept;
};

template<class Executor>
struct associated_executor<handler, Executor>
{
    using type = any_io_executor;

    static
    type
    get(handler const& h,
        Executor const& ex = Executor{}) noexcept;
};

template<class CancellationSlot>
struct associated_cancellation_slot<handler, CancellationSlot>
{
    using type = cancellation_slot;

    static
    type
    get(handler const& h,
        CancellationSlot const& cs = CancellationSlot{}) noexcept;
};


} // boost
} // asio

函数 net::bind_executor 可用于调用方想更改完成处理器执行器的场合.

实现用分配器获取执行操作所需的任何临时存储. 临时分配总是在完成处理器被调用之前释放. 执行器是一个复制代价低廉的对象, 提供调用完成处理器的算法. 除非调用方自定义, 完成处理器默认使用 std::allocator<void> 以及相应 I/O 对象的执行器.

函数 net::bind_allocator 可用于调用方想为操作指派自定义分配器的场合.

完成标记的关联 cancellation_slot 可用于取消单个操作. 它通常由完成标记传递, 例如 net::use_awaitable 或 net::yield_context .

可用的 取消类型如下.

  1. terminal: 请求取消; 成功取消后, I/O 对象上唯一安全的操作是关闭或销毁.
  2. partial: 请求取消; 成功取消后可能产生部分副作用或没有副作用. 取消后, I/O 对象处于已知状态, 可继续用于后续操作.
  3. total: 请求取消; 成功取消后没有明显副作用. 取消后, I/O 对象处于与操作之前相同的可观察状态.

Networking 规定了确定处理器运行上下文的设施. 每个 I/O 对象都关联 ExecutionContext, 用于取得调用完成处理器所用的 Executor 实例. 执行器决定完成处理器在何处以及如何被调用. 从 net::io_context 实例获得的执行器提供基本保证: 处理器只会从当前正在调用 net::io_context::run.

该 AsyncReadStream 和 AsyncWriteStream concept 为 异步流: 一种可移植的 I/O 抽象, 使用缓冲区序列表示字节异步交换数据, 并以 error_code 报告失败. 异步流算法 写成模板化的发起函数, 接受满足异步读、写或读写命名要求的流对象. 本示例展示一个向异步流写入文本的算法:

template <class AsyncWriteStream, class WriteHandler>
void async_hello (AsyncWriteStream& stream, WriteHandler&& handler)
{
    net::async_write (stream,
        net::buffer("Hello, world!", 13),
        std::forward<WriteHandler>(handler));
}
并发

套接字和流等 I/O 对象 不是线程安全的. 尽管可以同时有多个操作未完成 (例如同时进行异步读与异步写) , 流对象本身一次只能被一个线程访问. 这意味着移动构造函数、析构函数或发起函数等成员函数不得并发调用. 通常这借助互斥量等同步原语实现, mutex, 但并发网络程序需要更好的共享资源访问方式, 因为获取互斥量可能阻塞线程去执行无竞争的工作. 出于效率考虑, networking 采用无显式锁的线程模型, 要求对 I/O 对象的所有访问都在 strand.

通用模型

由于完成处理器会导致控制流反转, 有时需要其他挂接延续的手段. Networking 提供了 异步操作通用模型, 提供可自定义的手段来变换发起函数的签名, 用其他类型的对象和方法替代完成处理器回调. 例如, 异步地向套接字写入字符串并使用 std::future 接收传输的字节数, 可以这样写:

std::future<std::size_t> f = net::async_write(sock,
    net::const_buffer("Hello, world!", 13), net::use_future);

此功能通过传入变量 net::use_future (类型为 net::use_future_t<>) 替代完成处理器来启用. 同一个 async_write 函数重载可以配合用 纤程 启动的 asio::spawn:

asio::spawn(
    sock.get_executor(),
    [&sock](net::yield_context yield)
    {
        std::size_t bytes_transferred = net::async_write(sock,
            net::const_buffer("Hello, world!", 13), yield);
        (void)bytes_transferred;
    },
    asio::detached);

在这两种情形中, 都是用特定类型的对象替代完成处理器, 并且发起函数的返回值从 void 变换为 std::future<std::size_t> 或 std::size_t 被变换. 此处的处理器有时被称为 CompletionToken (在此上下文中) . 返回类型的变换由发起函数签名中的定制点支持. 下面是 net::async_write:

注意, spawn 函数本身具有完成签名, 但示例中我们使用 asio::detached.

template<
    class AsyncWriteStream,
    class ConstBufferSequence,
    class CompletionToken>
auto
async_write(
    AsyncWriteStream* stream,                       // references are passed as pointers
    ConstBufferSequence const& buffers,
    CompletionToken&& token)                        // a handler, or a special object.
    ->
    typename net::async_result<                     // return-type customization point.
        typename std::decay<CompletionToken>::type, // type used to specialize async_result.
        void(error_code, std::size_t)               // underlying completion handler signature.
            >::return_type;

函数返回值的类型由 net::async_result 定制点决定, 它为常见库类型 (如 std::future) 提供了特化, 也可为用户自定义类型特化. 发起函数的函数体会调用 net::async_initiate 辅助函数来捕获实参并转发给 async_result. 另外还提供一个 "发起函数" 对象, async_result 可用它立即启动操作, 或把启动推迟到未来某个时点 (这称为 "惰性执行") . 发起函数对象接收内部完成处理器, 其签名与发起函数所期望的签名一致:

return net::async_initiate<
    CompletionToken,
    void(error_code, std::size_t)>(
        run_async_write{},              // The "initiation" object.
        token,                          // Token must come before other arguments.
        &stream,                        // Additional captured arguments are
        buffers);                       //   forwarded to the initiation object.

这个变换后的内部处理器负责把操作结果交付给调用方的收尾步骤. 例如, 使用 net::use_future 时, 内部处理器将通过在发起函数返回的 promise 对象上调用 std::promise::set_value 来交付结果.

使用 Networking

大多数库流算法需要一个 tcp::socket, net::ssl::stream, 或其他 流 对象, 且该对象已与远程对端建立通信. 下面的示例作为套接字使用方法的提示:

// The resolver is used to look up IP addresses and port numbers from a domain and service name pair
tcp::resolver r{ioc};

// A socket represents the local end of a connection between two peers
tcp::socket stream{ioc};

// Establish a connection before sending and receiving data
net::connect(stream, r.resolve("www.example.com", "http"));

// At this point `stream` is a connected to a remote
// host and may be used to perform stream operations.
