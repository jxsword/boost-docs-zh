websocket::stream::async_handshake (2 of 2 overloads)

以客户端角色异步执行 WebSocket 握手.

概要 
template<
    class HandshakeHandler = net::default_completion_token_t<executor_type>>
DEDUCED
async_handshake(
    response_type& res,
    string_view host,
    string_view target,
    HandshakeHandler&& handler = net::default_completion_token_t< executor_type >{});
说明

此发起函数用于异步开始执行 WebSocket 握手, 这是发送和接收报文之前必需的步骤. 在握手期间, 客户端发送 WebSocket 升级 HTTP 请求, 服务器以指示握手结果的 HTTP 响应作为回复.

此调用总是立即返回. 异步操作将持续到以下条件之一成立:

  • 请求已发送且响应已收到.
  • 发生错误.

该算法称为 组合异步操作, 是通过调用下一层的 async_read_some 和 async_write_some 函数. 在此操作完成之前, 不得在流上执行任何其他操作.

如果收到的 HTTP 响应表明服务器接受了升级 (以 status-code 的 beast::http::status::switching_protocols.

参数

名称

说明

res

远程端点返回的 HTTP 升级响应. 调用方可以用该响应访问服务器发送的任何附加信息. 此对象会在完成处理器被调用之前被赋值.

host

远程主机的名称. HTTP 协议要求用它设置 "Host" 头字段. 发起函数返回后, 实现不会再访问该字符串数据.

target

request-target (origin-form 形式) . 服务器可以用目标来区分同一监听端口上的不同服务. 发起函数返回后, 实现不会再访问该字符串数据.

handler

操作完成时要调用的完成处理器. 实现通过衰减复制取得处理器的所有权. 处理器的等效函数签名必须是:

void handler(
    error_code const & ec    // Result of operation
);

若处理器有关联的立即执行器, 将向它派发立即完成. 否则, 处理器不会在此函数内部被调用. 处理器的调用将通过派发到立即执行器完成. 若未指定立即执行器, 这等同于使用 net::post.
示例 
response_type res;
ws.async_handshake(res, "localhost" , "/" ,
    [&res](error_code ec)
    {
        if (ec)
            std::cerr << "Error: " << ec.message() << "\n" ;
        else
            std::cout << res;

    });
