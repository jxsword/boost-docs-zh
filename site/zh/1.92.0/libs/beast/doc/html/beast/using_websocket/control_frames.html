控制帧

控制帧是完全包含在单个 WebSocket 帧中的小报文 (小于 128 字节) . 已建立连接上的任何一端都可以随时发送, 并可以出现在报文的续帧之间. 控制帧有三种类型: ping、pong 和 close.

发送 ping 表示发送方希望收到 pong. pong 是对 ping 的响应. pong 可以随时主动发送. 主动发送 pong 的一个用途是在长期无活动后告知远程对端会话仍然活跃. 关闭帧表示远程对端希望关闭 WebSocket 连接. 当每一方都已发送并接收关闭帧时, 即视为连接已优雅关闭.

读取操作期间, Beast 自动读取并处理控制帧. 若注册了控制回调, 回调会收到传入控制帧的通知. 实现会自动响应 ping. 收到关闭帧会启动 WebSocket 关闭过程, 最终在后续读取操作中把错误码 error::closed 交付给调用方 (前提是没有其他错误发生) .

这种自动行为的一个后果是: 调用方发起的读取操作可能导致套接字写入. 但这些写入不会与调用方发起的写操作竞争. 就流不变量的正确性而言, 调用方发起的读取操作仍只计作读取. 这意味着调用方可以同时进行读、写和 ping/pong 操作, 而实现同时自动处理控制帧.

控制回调

ping、pong 和 close 报文是控制帧, 已建立的 WebSocket 连接上任何一端都可以随时发送. 它们通过函数 ping, pong 和 close 发送. 要收到控制帧通知, 调用方可注册 控制回调, 使用 control_callback. 随此选项提供的对象应能以以下签名调用:

ws.control_callback(
    [](frame_type kind, string_view payload)
    {
        // Do something with the payload
        boost::ignore_unused(kind, payload);
    });

注册控制回调后, 通过同步或异步读取函数收到的所有 ping、pong 和关闭帧都会调用它. 帧的类型和载荷文本作为参数传给控制回调. 若帧是关闭帧, 可以通过调用 reason.

与调用异步发起函数时使用的常规完成处理器不同, 控制回调只需设置一次. 回调被调用后不会被重置. 同步与异步读取使用同一个回调. 回调是被动的; 必须有流读取操作在进行, 它才会被调用.

注释

当异步读取函数收到控制帧时, 控制回调以与调用相应读取函数的最终完成处理器相同的方式被调用.

关闭帧

WebSocket 协议定义了发起会话关闭的过程和控制报文. 此过程中, 主机通过发送 关闭帧. 请求关闭请使用诸如 close 或 async_close:

ws.close(close_code::normal);

close 函数会发送一个关闭帧, 读取并丢弃传入的报文数据直到收到关闭帧, 然后在返回前关闭底层连接.

读取操作期间收到关闭帧时, 实现会自动以关闭帧响应, 然后在返回前关闭底层连接. 此时读取操作将以错误码 error::closed 完成. 这向调用方表明连接已被干净地关闭.

重要

要收到 error::closed 错误, 必须有一个读取操作.

自动分片

为确保控制帧的及时交付, 可以把大的传出报文拆分成较小的帧. 自动分片选项开启此特性, 写缓冲区大小选项决定片段的最大大小:

ws.auto_fragment(true);
ws.write_buffer_bytes(16384);
