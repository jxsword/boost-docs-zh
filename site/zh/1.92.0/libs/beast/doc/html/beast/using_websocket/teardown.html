Teardown

RFC6455 第 7.1.1 节描述的 WebSocket 协议要求概述了一种称为 关闭 WebSocket 连接 的操作. 此操作干净地丢弃接收端点剩余的字节, 并关闭底层 TCP/IP 连接. 有序关闭总是首选; 对 TLS 或 SSL 流, 期望协议级关闭. 这给 stream 实现带来一个小问题: 流的 NextLayer 模板类型只要求 SyncStream 或 AsyncStream, 但这些 concept 不支持关闭连接所需的操作.

为使实现能够执行关闭操作的关闭部分, 库暴露了两个定制点, 以与下一层类型关联的自由函数表达:

  • teardown: 此函数的重载同步地排空并关闭流.
  • async_teardown: 此函数的重载异步地排空并关闭流.

当 websocket 流使用 Asio 类型 tcp::socket 或 net::ssl::stream 实例化下一层时, 实现提供了 teardown 定制点的适当重载, 此时无需用户操作. 但当 websocket 流以用户自定义类型实例化时, 若未为该类型提供定制点, 将导致编译错误. 此外, 包装了前述 Asio 对象之一的用户自定义类型, 可能希望为被包装对象调用 teardown 定制点. 这些任务的完成方式如下.

用户自定义 Teardown

要为用户自定义类型提供 teardown 重载, 只需以正确的签名声明这两个自由函数, 接受对用户自定义类型的引用作为流参数:

struct custom_stream;

void
teardown(
    role_type role,
    custom_stream& stream,
    error_code& ec);

template<class TeardownHandler>
void
async_teardown(
    role_type role,
    custom_stream& stream,
    TeardownHandler&& handler);

实现调用异步 teardown 函数时, 总是使用可调用的完成处理器. 创建 async_teardown.

调用 Teardown

要调用定制点, 先用 using 语句把默认实现引入作用域. 然后不加命名空间限定地调用定制点, 让参数依赖查找生效:

template <class NextLayer>
struct custom_wrapper
{
    NextLayer next_layer;

    template<class... Args>
    explicit
    custom_wrapper(Args&&... args)
        : next_layer(std::forward<Args>(args)...)
    {
    }

    friend
    void
    teardown(
        role_type role,
        custom_wrapper& stream,
        error_code& ec)
    {
        using boost::beast::websocket::teardown;
        teardown(role, stream.next_layer, ec);
    }

    template<class TeardownHandler>
    friend
    void
    async_teardown(
        role_type role,
        custom_wrapper& stream,
        TeardownHandler&& handler)
    {
        using boost::beast::websocket::async_teardown;
        async_teardown(role, stream.next_layer, std::forward<TeardownHandler>(handler));
    }
};
