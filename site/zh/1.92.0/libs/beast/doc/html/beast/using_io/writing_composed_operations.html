编写组合操作

异步操作通过调用称为异步 发起函数 的自由函数或成员函数来启动. 该函数接受特定于操作的参数以及 CompletionToken. 标记要么是完成处理器, 要么是定义如何把异步操作结果通知调用方的类型. Networking 提供特殊标记 net::use_future 和 net::yield_context 分别用于 future 和协程. 这种自定义返回值与完成通知方式的体系称为 通用异步模型 (描述于 N3747, 并内建于 Networking TS. 下面是一个发起函数示例, 它从流读取一行并回显. 该函数将在下一节进一步展开:

template<
    class AsyncStream,
    class DynamicBuffer,
    class CompletionToken>
auto
async_echo (AsyncStream& stream, DynamicBuffer& buffer, CompletionToken&& token)
提示

此发起函数按左值引用接收动态缓冲区, 而不是 networking 规定的右值引用. 关于这一差异的解释见 [P1100R0] Efficient composition with DynamicBuffer.

使用 Beast 的作者可以复用库的原语来创建自己的发起函数: 在调用最终完成处理器之前执行一系列其他中间异步操作. 发起函数产生的这一组中间动作称为 组合操作. 为确保完全互操作与良定义的行为, Boost.Asio 对组合操作的实现施加了要求. 以下类和函数使开发发起函数及其组合操作更加容易:

表 1.13. 异步辅助设施

名称

说明

async_base stable_async_base

此类设计为在编写以中间完成处理器表达的组合异步操作时作为基类使用. 它免除了传播关联执行器与关联分配器所需的大量样板代码.

allocate_stable

对于需要为临时对象提供稳定存储的组合操作算法, 可以使用此函数. 稳定存储的内存使用与最终完成处理器关联的分配器分配. 实现会在最终完成处理器被调用之前、或中间完成处理器被销毁时, 自动销毁临时对象.

bind_handler

此函数创建一个新处理器, 被调用时以绑定的参数列表调用原始处理器. 调用时传入的任何参数将替换绑定参数列表中出现的占位符. 未匹配到占位符的参数被静默丢弃.

传入的处理器与参数被转发到返回的处理器中, 其关联分配器与关联执行器将与原始处理器相同.

bind_front_handler

此函数创建一个新处理器: 调用时, 它以绑定的实参列表调用原处理器, 并把调用实参列表放在实参列表的前端或后端. 不支持占位符.

传入的处理器与参数被转发到返回的处理器中, 其关联分配器与关联执行器将与原始处理器相同.

saved_handler

此包装器安全地保存一个完成处理器以便稍后调用, 使实现能够 "暂停" 操作, 直到满足某个条件.
