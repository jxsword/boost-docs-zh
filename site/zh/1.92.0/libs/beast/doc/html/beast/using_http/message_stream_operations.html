报文流操作

Beast 提供在流上解析和序列化 HTTP/1 线上格式报文的同步与异步算法. 这些函数构成面向报文的流接口:

表 1.20. 报文流操作

名称

说明

read

从 message 读取 SyncReadStream.

async_read

从 message 读取 AsyncReadStream.

write

向 message 写入 SyncWriteStream.

async_write

向 message 写入 AsyncWriteStream.

所有同步流操作都有两种形式. 一种在出错时抛出异常, 另一种在最后一个参数接受 error_code& 类型的实参. 若发生错误, 该实参会被设置为包含错误码.

读取

由于序列化的头部没有长度前缀, 从流解析报文的算法出于效率考虑可能读取超出报文末尾的数据. 为容纳这些多余数据, 所有流读取操作都使用传入的 DynamicBuffer, 且必须在多次调用之间保持其生存期, 直到到达流末尾或流对象被销毁. 每次读取操作可能消费缓冲区中剩余的字节, 也可能留下新的字节. 在本示例中, 我们声明缓冲区和报文变量, 然后同步读取一个完整的 HTTP 请求:

flat_buffer buffer;         // (The parser is optimized for flat buffers)
request<string_body> req;
read(sock, buffer, req);

本示例使用 flat_buffer. Beast 的 basic_parser 为位于单个连续 (flat) 内存缓冲区中的结构化 HTTP 数据而优化. 若不使用平坦缓冲区, 实现可能执行额外的内存分配, 把输入重组为单个缓冲区以供解析.

提示

的其他实现DynamicBuffer 可以通过始终返回长度为一的缓冲区序列来避免解析器的内存分配.

报文也可以异步读取. 执行异步流读取操作时, 流、缓冲区和报文变量必须保持有效, 直到操作完成. Beast 的异步发起函数使用 Asio 的完成处理器模型. 此调用异步读取报文并在完成时报告错误码. 处理器被调用时会传入发生的错误 (如有) 以及解析的字节数. 该数值可用于衡量执行工作的相对多少, 也可以像本示例那样忽略.

flat_buffer buffer;
response<string_body> res;
async_read(sock, buffer, res,
    [&](error_code ec, std::size_t bytes_transferred)
    {
        boost::ignore_unused(bytes_transferred);
        std::cerr << ec.message() << std::endl;
    });

如果读取流算法在不超出所提供动态缓冲区最大指定大小的情况下无法完成操作, 将返回错误 buffer_overflow. 这是一种可用于限制 HTTP 报文头最大大小、防范缓冲区溢出攻击的技术. 下面的代码会打印错误消息:

// This buffer's max size is too small for much of anything
flat_buffer buffer{10};

// Try to read a request
error_code ec;
request<string_body> req;
read(sock, buffer, req, ec);
if(ec == http::error::buffer_overflow)
    std::cerr << "Buffer limit exceeded!" << std::endl;
写入

一组自由函数可以把整个 HTTP 报文序列化到流. 本示例构造并发送一个 HTTP 响应:

response<string_body> res;
res.version(11);
res.result(status::ok);
res.set(field::server, "Beast");
res.body() = "Hello, world!";
res.prepare_payload();

error_code ec;
write(sock, res, ec);

也可以改用异步版本:

async_write(sock, res,
    [&](error_code ec, std::size_t bytes_transferred)
    {
        boost::ignore_unused(bytes_transferred);
        if(ec)
            std::cerr << ec.message() << std::endl;
    });

完成处理器被调用时会传入写入流的字节数, 其中包括协议特定数据 (如头部中的分隔符与行结尾) . 该数值可用于衡量传输的数据量, 也可以像示例中那样忽略.
