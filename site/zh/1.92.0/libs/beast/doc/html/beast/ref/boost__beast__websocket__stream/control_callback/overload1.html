websocket::stream::control_callback (1 of 2 overloads)

设置在每个传入控制帧上调用的回调.

概要 
void
control_callback(
    std::function< void(frame_type, string_view)> cb);
说明

设置在调用以下函数期间每当收到 ping、pong 或 close 控制帧时都要调用的回调:

  • beast::websocket::stream::read
  • beast::websocket::stream::read_some
  • beast::websocket::stream::async_read
  • beast::websocket::stream::async_read_some

与完成处理器不同, 该回调在调用任何同步或异步读取函数期间都会对每个控制帧被调用. 此操作是被动的, 没有关联的错误码, 由读取触发.

对于关闭帧, 可以通过调用函数 reason.

参数

名称

说明

cb

要调用的函数对象, 必须能以此等效签名调用:

void
callback(
    frame_type kind,       // The type of frame
    string_view payload    // The payload in the frame
);

实现会对回调做类型擦除, 这可能需要动态分配. 要避免动态分配的可能性, 可使用 std::ref 包装回调. 若收到控制帧的读取操作是异步操作, 回调将以与调用最终处理器相同的方式被调用.
备注

传入的 ping 和关闭帧会被自动处理: ping 以 pong 应答, 关闭帧以关闭帧应答并最终关闭流. 无需在控制回调内手动发送 ping、pong 或关闭帧. 收到关闭帧后再在控制回调内尝试手动发送关闭帧会导致未定义行为.
