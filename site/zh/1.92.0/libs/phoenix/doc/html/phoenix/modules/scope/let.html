let 

#include <boost/phoenix/scope/let.hpp>

使用如下语法声明局部变量:

let(local-declarations)
[
    let-body
]

let 允许 1..N 个局部变量声明 (其中 N == BOOST_PHOENIX_LOCAL_LIMIT) . 每个声明遵循如下形式:

local-id = lambda-expression
注释

可以设置BOOST_PHOENIX_LOCAL_LIMIT, 即 let 表达式中预定义的最大局部变量声明数. 默认情况下, BOOST_PHOENIX_LOCAL_LIMIT 被设为BOOST_PHOENIX_LIMIT.

示例:

let(_a = 123, _b = 456)
[
    _a + _b
]

引用保留

局部变量的类型采用 lambda 表达式的类型. 类型推导是保留引用的. 例如:

let(_a = arg1, _b = 456)

_a 采用arg1 的类型:对一个参数的引用, 而_b 的类型是int.

考虑如下代码:

int i = 1;

let(_a = arg1)
[
    cout << --_a << ' '
]
(i);

cout << i << endl;

上面代码的输出是: 0 0

而使用如下代码时:

int i = 1;

let(_a = val(arg1))
[
    cout << --_a << ' '
]
(i);

cout << i << endl;

输出是: 0 1

引用保留是必要的, 因为我们需要对 (尤其是参数这类) 外层 lambda 作用域进行左值 (L-value) 访问. arg 和ref 是左值. val 是右值.

可见性

局部变量的作用域和生存期限制在 let 体之内. let 块可以嵌套. 局部变量可以遮蔽外层局部变量. 例如:

let(_x = _1, _y = _2)
[
    // _x here is an int: 1

   let(_x = _3) // hides the outer _x
   [
       cout << _x << _y // prints "Hello, World"
   ]
](1," World","Hello,");

参数 _1、_2 和 _3 的实际值由let 末尾的括号列表提供.

目前有一个限制:内层let 不能以常量提供, 例如let(_x = 1).

每个局部声明的右侧 (lambda 表达式) 不能引用任何左侧的局部标识符. 此时局部标识符还不进入作用域; 它们只在 let 体中进入作用域. 下面的代码是错误的:

let(
    _a = 1
  , _b = _a // Error: _a is not in scope yet
)
[
    // _a and _b's scope starts here
    /*. body .*/
]

不过, 如果存在外层 let 作用域, 则会在其中查找. 由于局部声明右侧的作用域是包围该 let 的外层作用域, 局部声明的右侧可以引用外层作用域的局部变量:

let(_a = 1)
[
    let(
        _a = _1
      , _b = _a // Ok. _a refers to the outer _a
    )
    [
        /*. body .*/
    ]
](1)
