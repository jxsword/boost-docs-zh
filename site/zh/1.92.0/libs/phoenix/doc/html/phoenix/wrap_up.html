总结

迟早会有更多的 FP 技术成为标准实践, 因为人们将在学术界之外、在主流中认识到这一编程规范的真正价值. 正如 70 年代的结构化编程、80 年代的面向对象编程和 90 年代的泛型编程塑造了我们对更稳健软件工程的认识一样, FP 必将是一个把我们推向更强大的软件设计与工程、迈向新千年的范式.

让我引用 Boost.org 的 Doug Gregor 关于函数式风格程序设计库的话:

它们正在获得认可, 但在一定程度上受制于到处可见的破损编译器. C++ 社区正在更深入地迈向所谓“STL 风格”的编程范式, 它把函数式编程的许多方面纳入其中. 例如, 看看 Spirit 解析器, 了解这类函数对象如何被用来构建类似 Yacc 的文法, 其语义动作可以即时构建抽象语法树. 这种类型的函数式组合正在加速发展.

确实如此. Phoenix 是把更多 FP 技术引入主流的又一次尝试. 它不仅是一个让程序员生活更轻松的工具. 就其本身而言, 这个库的实际设计本身就是真正的 C++ FP 实践的典范. 该库以严格但清晰、规范的 FP 意义进行设计和构造. 请务必把这个库当作工具来用. 但对于那些想进一步了解 C++ 中 FP 的人, 不要止步于此, 我邀请你更仔细地审视这个库本身的设计.

就这么多了. 玩得开心! FP 世界见.
