惰性运算符

你可以使用常用的一组运算符来构造表达式. 示例:

arg1 * arg1
ref(x) = arg1 + ref(z)
arg1 = arg2 + (3 * arg3)
ref(x) = arg1[arg2] // assuming arg1 is indexable and arg2 is a valid index

注意表达式: 3 * arg3. 这个表达式实际上是val(3) * arg3 的简写等价形式. 在大多数情况下 (如上) , 你可以侥幸通过. 但在某些情况下, 你必须用val 显式包装你的值. 经验法则:

  • 在二元表达式中 (例如3 * arg3) , 至少一个操作数必须是 phoenix 原语或表达式.
  • 在一元表达式中 (例如arg1++) , 唯一的操作数必须是 phoenix 原语或表达式.

如果不遵循这些基本规则, 结果要么是错误, 要么被立即求值. 几个示例:

ref(x) = 123    // lazy
x = 123         // immediate

ref(x)[0]       // lazy
x[0]            // immediate

ref(x)[ref(i)]  // lazy
ref(x)[i]       // lazy (equivalent to ref(x)[val(i)])
x[ref(i)]       // illegal (x is not a phoenix primitive or expression)
ref(x[ref(i)])  // illegal (x is not a phoenix primitive or expression)

为什么最后两个表达式非法? 虽然operator[] 看起来与上面的operator= 一样像二元运算符; 区别在于前者必须是一个成员 (即x 必须有一个以 phoenix 原语或表达式为参数的operator[]) . 这多半不是事实.

第一个实际示例

我们已经铺垫得够多了, 可以给出一个现实世界的示例. 我们想找出 STL 容器中第一个奇数. 通常我们使用一个函数对象或函数指针, 把它传给 STL 的find_if 泛型函数:

编写一个函数:

bool
is_odd(int arg1)
{
    return arg1 % 2 == 1;
}

把指向该函数的指针传给 STL 的find_if 算法:

std::find_if(c.begin(), c.end(), &is_odd)

使用 Phoenix, 同样的事情可以直接用一行代码完成:

std::find_if(c.begin(), c.end(), arg1 % 2 == 1)

表达式arg1 % 2 == 1 自动地 (automagically) 创建了一个具有预期行为的函数对象. 在 FP 中, 这个匿名函数被称为 lambda 函数. 与单态的函数指针版本 (只期望并只处理固定的 int 类型参数) 不同, Phoenix 版本是完全多态的, 可作用于任何容器 (int 的、long 的、bignum 的等等) , 只要其元素能处理arg1 % 2 == 1 表达式.

(参见find_if.cpp)
