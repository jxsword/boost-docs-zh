基础

在 Phoenix 库中, 几乎一切可被求值的东西都是f(a1, a2, ..., a/n/) 形式的函数, 其中n 是函数的元数 (arity) , 即函数期望的参数个数. 运算符也是函数. 例如, a + b 就是一个元数为 2 (二元) 的函数. a + b 等价于add(a, b), a + b + c 等价于add(add(a, b), c).

注释

有趣的是, 函数甚至可以返回函数. 稍后我们将看到这意味着什么.

部分函数应用

把函数想象成一个黑盒:你传入参数, 它返回某个东西. 下图描绘了典型的情形.

完全求值的函数是指给出了全部参数的函数. 纯 C++ 中的所有函数都是完全求值的. 调用sin(x) 函数时, 你必须传入一个数 x. 函数将返回结果: x 的正弦值. 调用add(x, y) 函数时, 你必须传入两个数 x 和 y. 函数将返回两数之和. 下图是一个完全求值的add 函数.

而部分应用的函数是指未给出全部参数的函数. 如果我们能够部分应用上面的函数add, 则可以只传入第一个参数. 这样一来, 该函数并没有获得执行其计算并返回结果这一任务所需的全部信息. 它转而返回另一个函数——一个 lambda 函数. 与元数为 2 的原函数add 不同, 所得的 lambda 函数元数为 1. 为什么? 因为我们已经提供了部分输入:2

现在, 当我们把一个数塞进我们的 lambda 函数时, 它将返回 2 加上我们传入的任何数. 这个 lambda 函数本质上记住了 1) 原函数add 和 2) 部分输入 2. 下图展示了我们向 lambda 函数传入 3、随后返回 5 的情形:

显然, 如上所示, 部分应用add 函数在 C++ 中无法直接完成, 因为 C++ 要求提供函数期望的全部参数. 这正是 Phoenix 库的用武之地. 该库提供了进行部分函数应用的设施. 更进一步, 有了 Phoenix, 这些结果函数不再是黑盒.

STL 与高阶函数

那么, 有什么大惊小怪的? 是什么让部分函数应用如此有用? 回想前一节中的原始示例:

std::find_if(c.begin(), c.end(), arg1 % 2 == 1)

表达式arg1 % 2 == 1 求值为一个 lambda 函数. arg1 是一个占位符, 表示稍后提供的参数. 因此, 由于只有一个未提供的参数, 这个 lambda 函数的元数为 1. 恰好find_if 在从c.begin() 循环到c.end() 的过程中提供了这个未提供的参数.

注释

高阶函数是指可以接受其他函数作为参数、也可能返回函数作为结果的函数. 高阶函数被当作与其他对象一样的对象来对待, 可以用作函数的参数和返回值.

惰性求值

更准确地说, 在 Phoenix 中, 函数求值分为两个阶段:

  1. 部分应用
  2. 最终求值

第一阶段由一组生成器函数处理. 它们是你的前端 (从客户的角度看) . 这些生成器 (通过部分函数应用) 创建出高阶函数, 可以像任何其他函数指针或函数对象一样传递. 第二阶段是实际的函数调用, 可以在未来的任何时候调用或执行, 也可以根本不执行; 这就是“惰性”的含义.

仔细观察, 第一步涉及部分函数应用:

arg1 % 2 == 1

第二步是实际的函数调用 (在find_if 函数内部完成. 这些是后端 (最终调用通常根本不会被客户看到) . 在我们的示例中, find_if, 如果深入其内部, 我们会看到类似这样的内容:

template <class InputIterator, class Predicate>
InputIterator
find_if(InputIterator first, InputIterator last, Predicate pred)
{
    while (first != last && !pred(*first))  // <--- The lambda function is called here
        ++first;                            //      passing in *first
    return first;
}

同样, 通常我们作为客户只看到第一步. 不过, 在本文档以及提供的示例和测试中, 看到第一步和第二步并列出现以便说明 Phoenix 表达式的完整语义时, 不必感到惊讶. 示例:

int x = 1;
int y = 2;

std::cout << (arg1 % 2 == 1)(x) << std::endl; // prints 1 or true
std::cout << (arg1 % 2 == 1)(y) << std::endl; // prints 0 or false

转发函数问题

通常, 作为客户, 我们编写回调函数, 而库 (如 STL) 提供被调用者 (例如find_if) . 如果角色反转, 例如你必须编写一个接受谓词的 STL 算法, 或开发一个接受事件处理器的 GUI 库, 那么你必须了解 C++ 中一个鲜为人知的问题, 即“转发函数问题”.

再看一下上面的代码:

多态函数

除非另有说明, Phoenix 生成的函数是完全多态的. 例如, 上面的add 示例可应用于整数、浮点数、用户自定义复数甚至字符串. 示例:

std::string h("Hello");
char const* w = " World";
std::string r = add(arg1, arg2)(h, w);

求值为std::string("Hello World"). 细心的读者可能注意到, 这个函数调用实际上接受异构参数, 其中arg1 的类型是std::string, 而arg2 的类型是char const*. add 仍然有效, 因为 C++ 标准库允许表达式a + b, 其中a 是一个std::string, 而b 是一个char const*.
