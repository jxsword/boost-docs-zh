2014 和 2015 年维护 Boost Phoenix 的经验.

本节用于阐述 Boost Phoenix 的维护策略及其执行方式. 这样做的原因之一是 2015 年 1 月 Boost 社区内部就如何最好地开展这项工作进行了大量讨论. 还有一些问题我并不清楚答案, 我将在这里把它们列出来.

Phoenix 是一个复杂的库, 当前的版本 3 构建在另外两个库Boost.Proto 和Boost.Fusion 之上, 而这两个库本身就相当复杂. Phoenix 的版本 3 是使用Boost.Proto 对前一版本的重建.

使用 Phoenix 有两种方式.

  • 一种是忽略前面的论述, 假定一切正常.
  • 第二种是理解这些库之间的关系.

遗憾的是, 虽然大部分东西现在都能工作, 但仍有一些微妙的缺陷导致行为不符合预期, 这就是对从未编写过该库任何版本的维护者而言的挑战所在.
