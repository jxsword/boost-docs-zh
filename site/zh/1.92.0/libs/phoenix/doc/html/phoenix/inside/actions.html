再谈动作 (Action)

如Actor 详解一节所述, 动作 (Action) 正是赋予 Phoenix 表达式树生命的东西.

处理 Phoenix 表达式树时, 求值自顶向下进行. 示例:

_1 + 3 * _2

可以用如下方式将其可视化为 AST:

以动作来表述, 这意味着:

  • 匹配rule::plus
  • 求值左部:
    • 匹配rule::placeholder
  • 求值右部:
    • 匹配rule::multiplies
      • 求值左部:
        • 匹配rule::value
      • 求值右部:
        • 匹配rule::placeholder

每当一条规则被匹配, 就会调用一个动作. 动作决定了 Phoenix AST 的遍历方式.

编写动作

如Actor 详解所述, 动作是Proto 原语变换 (Primitive Transform) . 为方便起见, Phoenix 为此提供了一个抽象:

template <typename Fun>
struct call;

它类似于proto::call, 但做得更多. 它会调用作为模板参数传入的Fun 函数对象, 传入Context 以及与该规则相关联的表达式的子节点.

让我们看一个 (简化的) 示例, 说明如何为rule::plus 编写求值动作:

struct plus_eval
{
    typedef int result_type;

    template <typename Lhs, typename Rhs, typename Context>
    result_type operator()(Lhs const& lhs, Rhs const &rhs, Context & ctx)
    {
        return eval(lhs, ctx) + eval(rhs, ctx);
    }
};

template <>
struct default_actions::when<rule::plus>
    : call<plus_eval>
{};

就是这样. 对plus 表达式求值时, plus_eval 可调用体将以左侧表达式、右侧表达式以及关联的 Context 为参数被调用.

但还有更多: 由于动作可以是完整的Proto 变换 (Transform) , 你实际上可以使用任何你能想到的 proto 表达式作为动作. Phoenix 预定义了一组可调用体和变换来处理随行传递的 Context 信息, 当然, 每个 Phoenix 表达式都可以用作 Phoenix 文法或Proto 直通变换 (Pass Through Transform) .

functional::context(Env, Actions)

一个Proto 可调用变换 (Callable Transform) , 从Env 和Actions 参数创建新的上下文

functional::env(Context)

一个Proto 可调用变换 (Callable Transform) , 从Context 参数返回环境

functional::actions(Context)

一个Proto 可调用变换 (Callable Transform) , 从Context 参数返回动作

_context

一个Proto 原语变换 (Primitive Transform) , 返回当前上下文

_env

一个Proto 原语变换 (Primitive Transform) , 返回当前环境

_actions

一个Proto 原语变换 (Primitive Transform) , 返回当前动作

context(env, actions)

一个创建上下文的普通函数

env(ctx)

一个从给定上下文返回环境的普通函数

actions(ctx)

一个从给定上下文返回动作的普通函数

Phoenix 内置了一组预定义的表达式、规则和动作, 使你在入门套件和模块各节中学到的所有东西得以运转. 更多细节参见下一节!
