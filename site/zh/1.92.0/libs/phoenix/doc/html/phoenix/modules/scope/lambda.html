lambda 

#include <boost/phoenix/scope/lambda.hpp>

很多时候, 你会想编写一个接受一个或多个函数的惰性函数 (高阶函数) . 例如会想到 STL 算法. 考虑一个惰性版本的stl::for_each:

struct for_each_impl
{
    template <typename C, typename F>
    struct result
    {
        typedef void type;
    };

    template <typename C, typename F>
    void operator()(C& c, F f) const
    {
        std::for_each(c.begin(), c.end(), f);
    }
};

function<for_each_impl> const for_each = for_each_impl();

注意该函数接受另一个函数f 作为参数. 这个函数f 的作用域限制在operator() 之内. 当f 在std::for_each 内部被调用时, 它存在于一个新的作用域中, 伴随着新参数以及可能的局部变量. 这个新作用域与operator() 之外的外层作用域毫无关联.

简单语法:

lambda
[
    lambda-body
]

与let 一样, 可以声明局部变量, 允许 1..N 个局部变量声明 (其中 N == BOOST_PHOENIX_LOCAL_LIMIT) :

lambda(local-declarations)
[
    lambda-body
]

关于作用域和可见性的限制同样适用. 每个局部声明的右侧 (lambda 表达式) 不能引用任何左侧的局部标识符. 局部标识符此时还不在作用域内; 只有在 lambda 体中它们才进入作用域:

lambda(
    _a = 1
  , _b = _a // Error: _a is not in scope yet
)

更多信息参见let 可见性.

示例:使用我们的惰性for_each 来打印容器中的所有元素:

for_each(arg1, lambda[cout << arg1])

就参数 (arg1..argN) 而言, lambda 体所在的作用域是全新的. 左侧的arg1 引用传给for_each 的参数 (一个容器) . 右侧的arg1 引用由std::for_each 传入的参数 (一个容器元素) , 这是当我们最终调用operator() (即上面的for_each_impl) 时传入的.

不过, 我们可能希望从外层作用域获取信息. 虽然我们无法访问外层作用域中的参数, 但我们仍然可以访问外层作用域中的局部变量. 我们或许只能通过局部变量把与参数相关的信息从外层lambda 作用域传递进来.

注释

这是let 与lambda 之间的关键区别:let 不引入新参数; 而lambda 引入.

另一个示例:使用我们的惰性for_each 和一个惰性push_back:

struct push_back_impl
{
    template <typename C, typename T>
    struct result
    {
        typedef void type;
    };

    template <typename C, typename T>
    void operator()(C& c, T& x) const
    {
        c.push_back(x);
    }
};

function<push_back_impl> const push_back = push_back_impl();

编写一个接受以下内容的 lambda 表达式:

  1. 一个二维容器 (例如vector<vector<int> >)
  2. 一个容器元素 (例如int)

并把该元素 push-back 到每个vector<int> 中.

解决方案:

for_each(arg1,
    lambda(_a = arg2)
    [
        push_back(arg1, _a)
    ]
)

由于我们无法访问 lambda 体之外外层作用域的参数, 我们引入一个局部变量_a 来捕获第二个外层参数:arg2. 因此: _a = arg2. 这个局部变量在 lambda 作用域内可见.
