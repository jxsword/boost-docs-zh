改进的迭代器类别与要求

引言

标准的迭代器类别与要求是有缺陷的, 因为它们用单一的需求层次来处理两个正交的问题: 迭代器遍历 与 解引用返回类型. 现行的迭代器需求层次主要面向迭代器遍历 (类别名称即由此而来), 而涉及解引用返回类型的需求则散见于各处. 下表总结了现行迭代器类别中关于解引用返回类型的需求.

表 1. 现有解引用返回类型要求小结.
输出迭代器 *i = a
输入迭代器 *i 可转换为 T
前向迭代器 *i 为 T& (或在 issue 200 解决后为 const T& )
随机访问迭代器 i[n] 可转换为 T (这很奇怪, 因为运算语义说 i[n] 等价于 *(i + n) , 后者的返回类型应为 T& )

无法 "纳入" 的有用迭代器示例

由于迭代器遍历与解引用返回类型混在一起, 许多有用的迭代器无法被恰当归类. 例如, vector<bool>::iterator 几乎是一个随机访问迭代器, 但其返回类型不是 bool& (见 issue 96 与 Herb Sutter 的论文 J16/99-0008 = WG21 N1185). 因此, 这些迭代器只满足输入迭代器与输出迭代器的要求. 这非常违反直觉, 以致至少有一个实现错误地把 random_access_iterator_tag 赋为其 iterator_category . 此外, vector<bool> 并不是不返回真正引用的有用迭代器的唯一例子: 还有常被引用的基于磁盘的集合的例子.

另一个例子是计数迭代器, 即在递增和解引用时返回整数序列的迭代器 (参见 boost::counting_iterator ). 实现这种迭代器有两种方式: 1) 使 reference 类型成为真正的引用 (对计数迭代器的整数数据成员的引用), 或 2) 使 reference 类型与 value_type 相同. 选项 1) 会遇到 Issue 198 中讨论的问题: 迭代器销毁后引用将失效. 因此选项 2) 是更好的选择, 但这样一来我们就得到一个不能成为随机访问迭代器的计数迭代器.

再一个例子是变换迭代器, 即对被包装迭代器的解引用值应用一元函数对象的迭代器适配器 (参见 boost::transform_iterator ). 对于 std::times 这样的一元函数, operator* 的返回类型显然需要是函数对象的 result_type , 这通常不是引用. 然而, 按照现有迭代器要求, 若用变换迭代器包装 int* , 你得到的不是预期的随机访问迭代器, 而是输入迭代器.

第四个例子见 Boost Graph Library 的顶点与边迭代器. 这些迭代器返回顶点与边描述符, 它们是即时创建的轻量句柄, 必须按值返回. 结果, 它们当前的标准迭代器类别是 std::input_iterator_tag , 这意味着严格来说你不能把这些迭代器用于 std::min_element() 之类的算法. 作为临时解决方案, 我们引入了 Multi-Pass Input Iterator 概念来描述顶点与边描述符, 但正如该概念的设计说明所指出的, 需要更好的解决方案.

简而言之, 有许多有用的迭代器不适合当前的标准迭代器类别. 结果, 会发生以下坏事:

  • 迭代器经常被错误归类.
  • 算法要求比必要的更严格, 因为它们无法把对随机访问的需求与对真引用返回类型的需求分开.

新迭代器类别与要求提案

迭代器要求应拆分为两个层次. 一组概念负责处理返回类型语义:
  • Readable Iterator
  • Writable Iterator
  • Swappable Iterator
  • Constant Lvalue Iterator
  • Mutable Lvalue Iterator
另一组概念负责处理迭代器遍历:
  • Forward Traversal Iterator
  • Bidirectional Traversal Iterator
  • Random Access Traversal Iterator
现行的 Input Iterator 与 Output Iterator 要求将继续按原样使用. 注意, Input Iterator 蕴含 Readable Iterator, 而 Output Iterator 蕴含 Writable Iterator.

注释: 我们曾考虑定义一个单遍迭代器 (Single-Pass Iterator), 它可以与 Readable Iterator 或 Writable Iterator 组合以取代 Input Iterator 与 Output Iterator 要求. 我们否决了这个想法, 因为 Input Iterator 与 Output Iterator 之间存在若干差异, 使它们难以合并: Input Iterator 要求 Equality Comparable 而 Output Iterator 不要求; Input Iterator 要求可赋值而 Output Iterator 不要求.

新的类别与 traits 类

每个新的迭代器要求都需要一个类别标签. 
namespace std {

  // Return Type Categories
  struct readable_iterator_tag { };
  struct writable_iterator_tag { };
  struct swappable_iterator_tag { };
  struct mutable_lvalue_iterator_tag : virtual public writable_iterator_tag,
    virtual public readable_iterator_tag { };
  struct constant_lvalue_iterator_tag : public readable_iterator_tag { };

  // Traversal Categories
  struct forward_traversal_tag { };
  struct bidirectional_traversal_tag : public forward_traversal_tag { };
  struct random_access_traversal_tag : public bidirectional_traversal_tag { };

}
此外, 还需要有一种借助 traits 机制访问这些类别标签的方法. 向 std::iterator_traits 添加新的 typedef 不是可接受的解决方案, 因为那会破坏所有现存迭代器. 作为替代, 我们提议两个新的 traits 类. 至关重要的是, 这些 traits 类要 向后兼容, 也就是说, 对于任何存在有效的 std::iterator_traits 定义的迭代器, 它们都应当能够工作. 这可以通过让 traits 类的默认行为把迭代器的 iterator_category 映射到适当的返回或遍历类别来实现. 对于新迭代器, 既可以为这些 traits 类定义特化, 也可以让迭代器提供嵌套 typedef 并继承 new_iterator_base (这只是向 traits 类表明它是新迭代器的信号). 与 std::iterator_traits 一样, 针对 T* 的特化也已提供. 
namespace std {

  struct new_iterator_base { };

  template <typename Iterator>
  struct return_category
  {
    // Pseudo-code
    if (Iterator inherits from new_iterator_base) {
      typedef typename Iterator::return_category type;
    } else {
      typedef std::iterator_traits<Iterator> OldTraits;
      typedef typename OldTraits::iterator_category Cat;
      if (Cat inherits from std::forward_iterator_tag)
	if (is-const(T))
	  typedef boost::constant_lvalue_iterator_tag type;
	else
	  typedef boost::mutable_lvalue_iterator_tag type;
      else if (Cat inherits from std::input_iterator_tag)
	typedef boost::readable_iterator_tag type;
      else if (Cat inherits from std::output_iterator_tag)
	typedef boost::writable_iterator_tag type;
    }
  };

  template <typename T>
  struct return_category<T*>
  {
    // Pseudo-code
    if (is-const(T))
      typedef boost::constant_lvalue_iterator_tag type;
    else
      typedef boost::mutable_lvalue_iterator_tag type;
  };

  template <typename Iterator>
  struct traversal_category
  {
    // Pseudo-code
    if (Iterator inherits from new_iterator_base) {
      typedef typename Iterator::traversal_category type;
    } else {
      typedef std::iterator_traits<Iterator> OldTraits;
      typedef typename OldTraits::iterator_category Cat;

      if (Cat inherits from std::random_access_iterator_tag)
	typedef boost::random_access_traversal_tag type;
      else if (Cat inherits from std::bidirectional_iterator_tag)
	typedef boost::bidirectional_traversal_tag type;
      else if (Cat inherits from std::forward_iterator_tag)
	typedef boost::forward_traversal_tag type;
    }
  };

  template <typename T>
  struct traversal_category<T*>
  {
    typedef boost::random_access_traversal_tag type;
  };

}

对标准算法的影响

由于现行迭代器类别过于粗糙, 许多标准算法对其迭代器参数施加了超出必要的需求. 采用新的迭代器类别可以获得更好的匹配, 从而提高算法的可复用性. 这些变化不会影响用户代码, 但需要标准库实现者作出改动: 分派应基于新的类别, 而且在某些地方可能需要更小心地处理返回值. 特别是, std::swap() 的使用将需要替换为 std::iter_swap(), 而 std::iter_swap() 将需要调用 std::swap().

Writable Iterator

Writable Iterator 是一种可用于通过解引用赋值表达式来存储值的迭代器.

定义

若 x 是类型为 X 的 Writable Iterator, 则表达式 *x = a; 将值 a 存入 x. 注意, operator= 与其他 C++ 函数一样可能被重载; 事实上它甚至可以是模板函数. 因此一般而言, a 可以是几种不同类型中的任意一种. 类型 A 属于 值类型集合 (相对于 X 而言) , 如果对于 a (其类型为 A) , *x = a; 是良定义的, 且不需要对 a 执行任何非平凡转换.

Swappable Iterator

Swappable Iterator 是一种其解引用到的值可以被交换的迭代器.

注释: Swappable Iterator 的要求依赖于 std::swap() 相关问题的解决. 这里我们假定该问题将通过允许为用户自定义类型重载 std::swap() 来解决.
