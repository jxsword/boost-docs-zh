这份全面 (且篇幅较长) 的教程将通过一个示例, 讲解如何使用 GIL 计算图像梯度.

我们将从一些非常简单、非泛型的代码入手, 并在过程中逐步使其泛化. 先从水平梯度开始, 采用最简单的梯度近似 - 中心差分.

像素 x 处的梯度可以用其两个相邻像素的半差来近似:

D[x] = (I[x-1] - I[x+1]) / 2

为简单起见, 我们也将忽略边界情形 - 即图像边缘处某个邻居未定义的像素. 本文档的重点是如何使用 GIL, 而不是如何设计一个好的梯度生成算法.

接口与粘合代码

我们首先以 8 位无符号灰度图像为输入, 以 8 位有符号灰度图像为输出.

我们的算法的接口如下所示:

#include <boost/gil.hpp>

using namespace boost::gil;

void x_gradient(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  assert(src.dimensions() == dst.dimensions());
  ...    // compute the gradient
}

gray8c_view_t 是源图像视图的类型 - 8 位灰度视图, 其像素为只读 (由 “c” 表示).

输出是具有 8 位有符号 (由 “s” 表示) 整数通道类型的灰度视图. GIL 为具体类型命名所用约定的完整说明见附录 1.

GIL 区分图像与图像视图. GIL 的 图像视图 是像素矩形网格的浅层轻量视图. 它提供对像素的访问, 但不拥有像素. 拷贝构造视图不会深拷贝像素. 图像视图不会将其 const 性传播给像素, 因此应始终以 const 引用传入. 视图是可变的还是只读的 (不可变的), 由视图类型决定.

而 GIL 的 图像 则是带有所有权的视图. 它是像素的容器; 其构造函数/析构函数分配/释放像素, 其拷贝构造函数对像素执行深拷贝, 其 operator== 对像素执行深比较. 图像也会将其 const 性传播给像素 - 图像的常量引用不允许修改其像素.

大多数 GIL 算法操作图像视图; 很少需要用到图像本身. GIL 的设计与 STL 非常相似. GIL 图像在 STL 中的对应物是容器, 如 std::vector; 而 GIL 图像视图对应 STL 范围, 后者常以一对迭代器表示. STL 算法操作范围, 正如 GIL 算法操作图像视图.

GIL 的图像视图可以从原始数据构造 - 即尺寸、每行字节数与像素; 对于交织式 (chunky) 视图, 像素由一个指针表示. 下面演示如何在你的代码与 GIL 之间提供粘合代码:

void ComputeXGradientGray8(
    unsigned char const* src_pixels, std::ptrdiff_t src_row_bytes,
    int w, int h,
    signed char* dst_pixels, std::ptrdiff_t dst_row_bytes)
{
  gray8c_view_t src = interleaved_view(w, h, reinterpret_cast<gray8_pixel_t const*>(src_pixels), src_row_bytes);
  gray8s_view_t dst = interleaved_view(w, h, reinterpret_cast<gray8s_pixel_t*>(dst_pixels), dst_row_bytes);
  x_gradient(src, dst);
}

这段粘合代码非常快速, 视图也很轻量 - 在上例中, 视图的大小为 16 字节. 它由一个指向左上角像素的指针和三个整数 - 宽、高与每行字节数 - 组成.

第一个实现

为简单起见而牺牲速度, 我们可以这样计算水平梯度:

void x_gradient(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  for (int y = 0; y < src.height(); ++y)
      for (int x = 1; x < src.width() - 1; ++x)
          dst(x, y) = (src(x-1, y) - src(x+1, y)) / 2;
}

我们使用图像视图的 operator(x,y) 获取给定位置像素的引用, 并将其设为左右邻居的半差. operator() 返回灰度像素的引用. 灰度像素可转换为其通道类型 (unsigned char 对于 src), 也可以从通道拷贝构造. (这仅对灰度像素成立.)

上面的代码易读, 但速度不快, 因为二元 operator() 要计算像素在二维网格中的位置, 这涉及加法与乘法. 下面是更快的版本:

void x_gradient(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  for (int y = 0; y < src.height(); ++y)
  {
      gray8c_view_t::x_iterator src_it = src.row_begin(y);
      gray8s_view_t::x_iterator dst_it = dst.row_begin(y);

      for (int x = 1; x < src.width() - 1; ++x)
          dst_it[x] = (src_it[x-1] - src_it[x+1]) / 2;
  }
}

我们使用在每行起始处初始化的像素迭代器. GIL 的迭代器是随机访问遍历迭代器. 如果你不熟悉随机访问迭代器, 可以把它们当作指针来理解. 实际上, 在上例中这两个迭代器类型就是原始 C 指针, 其 operator[] 就是快速的指针下标运算符.

在垂直方向计算梯度的代码非常相似:

void y_gradient(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  for (int x = 0; x < src.width(); ++x)
  {
      gray8c_view_t::y_iterator src_it = src.col_begin(x);
      gray8s_view_t::y_iterator dst_it = dst.col_begin(x);

      for (int y = 1; y < src.height() - 1; ++y)
          dst_it[y] = (src_it[y-1] - src_it[y+1]) / 2;
  }
}

我们不按行循环, 而是按列循环, 并创建一个 y_iterator, 即垂直移动的迭代器. 此时无法使用简单指针, 因为相邻两个像素之间的距离等于图像每行的字节数. GIL 在此使用一个特殊的步进迭代器类, 其大小是水平方向迭代器的两倍 - 它包含一个原始 C 指针和一个步长. 其 operator[] 将下标乘以步长.

但由于内存访问模式的缘故, 上述 y_gradient 版本比 x_gradient 慢得多 (很容易慢一个数量级); 垂直遍历图像会产生大量缓存未命中. 更高效且对缓存友好的版本应把列循环放在内层:

void y_gradient(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  for (int y = 1; y < src.height() - 1; ++y)
  {
      gray8c_view_t::x_iterator src1_it = src.row_begin(y-1);
      gray8c_view_t::x_iterator src2_it = src.row_begin(y+1);
      gray8s_view_t::x_iterator dst_it = dst.row_begin(y);

      for (int x = 0; x < src.width(); ++x)
      {
          *dst_it = ((*src1_it) - (*src2_it)) / 2;
          ++dst_it;
          ++src1_it;
          ++src2_it;
      }
  }
}

这段示例代码还展示了使用像素迭代器的另一种方式 - 可以不使用 operator[], 而改用递增与解引用.

使用定位器

遗憾的是, 这种对缓存友好的版本需要额外维护源视图中的两个独立迭代器, 颇为麻烦. 对每个像素, 我们想访问其上下邻居. 这类相对访问可以用 GIL 定位器完成:

void y_gradient(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  gray8c_view_t::xy_locator src_loc = src.xy_at(0,1);
  for (int y = 1; y < src.height() - 1; ++y)
  {
      gray8s_view_t::x_iterator dst_it = dst.row_begin(y);

      for (int x = 0; x < src.width(); ++x)
      {
          *dst_it = (src_loc(0,-1) - src_loc(0,1)) / 2;
          ++dst_it;
          ++src_loc.x(); // each dimension can be advanced separately
      }
      src_loc += point_t(-src.width(), 1); // carriage return
  }
}

第一行创建一个定位器, 指向源视图第二行的第一个像素. GIL 像素定位器与迭代器非常相似, 区别在于它既可以水平移动也可以垂直移动. src_loc.x() 和 src_loc.y() 分别返回水平迭代器和垂直迭代器的引用, 如上所示, 可以用它们沿所需维度移动定位器. 此外, 还可以用定位器的 operator+= 和 operator-= 同时在两个维度上前进. 与图像视图类似, 定位器提供二元 operator(), 它返回一个像素的引用, 该像素相对当前定位器位置有给定的偏移. 例如, src_loc(0,1) 返回当前像素下方邻居的引用. 定位器是非常轻量的对象 - 它由一个指向当前像素的原始指针和一个 int 组成, 后者指示从一行到下一行的字节数 (即垂直移动时的步长). 调用 ++src_loc.x() 对应一次 C 指针递增. 然而, 上例执行的计算多于必要. 代码 src_loc(0,1) 必须在两个维度上计算像素的偏移, 这很慢. 但请注意, 无论像素位于何处, 两个邻居的偏移都是相同的. 为提升性能, GIL 可以缓存并复用这一偏移:

void y_gradient(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  gray8c_view_t::xy_locator src_loc = src.xy_at(0,1);
  gray8c_view_t::xy_locator::cached_location_t above = src_loc.cache_location(0,-1);
  gray8c_view_t::xy_locator::cached_location_t below = src_loc.cache_location(0, 1);

  for (int y = 1; y < src.height() - 1; ++y)
  {
      gray8s_view_t::x_iterator dst_it = dst.row_begin(y);

      for (int x = 0; x < src.width(); ++x)
      {
          *dst_it = (src_loc[above] - src_loc[below]) / 2;
          ++dst_it;
          ++src_loc.x();
      }
      src_loc += point_t(-src.width(), 1);
  }
}

在本例中, src_loc[above] 对应快速的指针下标操作, 代码是高效的.

创建 GIL 算法的泛型版本

让我们把 x_gradient 变得更泛化. 它应当适用于任何图像视图, 只要二者具有相同的通道数. 梯度运算要对每个通道独立计算.

新接口如下所示:

template <typename SrcView, typename DstView>
void x_gradient(SrcView const& src, DstView const& dst)
{
  gil_function_requires<ImageViewConcept<SrcView>>();
  gil_function_requires<MutableImageViewConcept<DstView>>();
  gil_function_requires
  <
    ColorSpacesCompatibleConcept
    <
      typename color_space_type<SrcView>::type,
      typename color_space_type<DstView>::type
    >
  >();

  ... // compute the gradient
}

新算法现在以输入和输出图像视图的类型作为模板参数. 这使得既可以使用内建的 GIL 图像视图, 也可以使用任何用户自定义的图像视图类. 前三行是可选的; 它们使用 boost::concept_check 来确保两个实参都是有效的 GIL 图像视图, 第二个是可变的, 且二者的色彩空间兼容 (即具有相同的通道集合).

GIL 不要求使用其内建的构造. 你可以自由使用自己的通道、色彩空间、迭代器、定位器、视图和图像. 但是, 要与 GIL 的其余部分协作, 它们必须满足一组要求; 换言之, 它们必须符合相应的 GIL 概念. GIL 的概念定义在用户指南中.

在 C++ 中使用模板和泛型编程的最大缺点之一是编译错误可能非常难以理解. 这是缺少早期类型检查的副作用 - 泛型实参可能不满足某个函数的要求, 但不兼容可能深藏在嵌套调用的代码中触发, 那段代码既陌生又与问题几乎无关. GIL 使用 boost::concept_check 来缓解这一问题. 上面三行代码检查模板参数是否为其对应概念的有效模型. 如果模型不正确, 编译错误将出现在 gil_function_requires 内部, 离问题更近, 也更容易追踪. 此外, 这类检查会被编译器去除, 没有任何性能开销. 使用概念检查的缺点是有时会严重拖慢编译时间. 因此 GIL 仅在调试模式下执行概念检查, 且仅当 BOOST_GIL_USE_CONCEPT_CHECK 被定义时才启用 (默认关闭).

泛型函数的主体与具体版本非常相似. 最大的区别是我们需要循环遍历像素的各个通道, 并为每个通道计算梯度:

template <typename SrcView, typename DstView>
void x_gradient(SrcView const& src, DstView const& dst)
{
  for (int y = 0; y < src.height(); ++y)
  {
      typename SrcView::x_iterator src_it = src.row_begin(y);
      typename DstView::x_iterator dst_it = dst.row_begin(y);

      for (int x = 1; x < src.width() - 1; ++x)
          for (std::size_t c = 0; c < num_channels<SrcView>::value; ++c)
              dst_it[x][c] = (src_it[x-1][c]- src_it[x+1][c]) / 2;
  }
}

为每个通道写一个显式循环可能带来性能问题. GIL 允许我们把这类逐通道操作抽象出来:

template <typename Out>
struct halfdiff_cast_channels
{
  template <typename T>
  auto operator()(T const& in1, T const& in2) const -> Out
  {
      return Out((in1 - in2) / 2);
  }
};

template <typename SrcView, typename DstView>
void x_gradient(SrcView const& src, DstView const& dst)
{
  using dst_channel_t = typename channel_type<DstView>::type;

  for (int y = 0; y < src.height(); ++y)
  {
      typename SrcView::x_iterator src_it = src.row_begin(y);
      typename DstView::x_iterator dst_it = dst.row_begin(y);

      for (int x = 1; x < src.width() - 1; ++x)
      {
          static_transform(src_it[x-1], src_it[x+1], dst_it[x],
              halfdiff_cast_channels<dst_channel_t>());
      }
  }
}

static_transform 是通道级 GIL 算法的一个示例. 其他此类算法还有 static_generate, static_fill 和 static_for_each. 它们分别是 STL generate, transform, fill 和 for_each 在通道级的对应物. GIL 通道算法使用静态递归来展开循环; 它们从不在通道上显式循环.

注意, 现代编译器有时已会自行展开诸如上述的通道级循环. 然而, 使用 GIL 通道级算法的另一个优点是它们按语义配对通道, 而不是按通道在内存中的顺序. 例如, 上面的示例能正确地把 RGB 源与 BGR 目标相匹配.

我们可以这样将泛型版本用于不同类型的图像:

// Calling with 16-bit grayscale data
void XGradientGray16_Gray32(
    unsigned short const* src_pixels, std::ptrdiff_t src_row_bytes,
    int w, int h,
    signed int* dst_pixels, std::ptrdiff_t dst_row_bytes)
{
  gray16c_view_t src = interleaved_view(w, h, reinterpret_cast<gray16_pixel_t const*>(src_pixels), src_row_bytes);
  gray32s_view_t dst = interleaved_view(w, h, reinterpret_cast<gray32s_pixel_t*>(dst_pixels), dst_row_bytes);
  x_gradient(src,dst);
}

// Calling with 8-bit RGB data into 16-bit BGR
void XGradientRGB8_BGR16(
    unsigned char const* src_pixels, std::ptrdiff_t src_row_bytes,
    int w, int h,
    signed short* dst_pixels, std::ptrdiff_t dst_row_bytes)
{
  rgb8c_view_t  src = interleaved_view(w, h, reinterpret_cast<rgb8_pixel_t const*>(src_pixels), src_row_bytes);
  bgr16s_view_t dst = interleaved_view(w, h, reinterpret_cast<bgr16s_pixel_t*>(dst_pixels), dst_row_bytes);
  x_gradient(src, dst);
}

// Either or both the source and the destination could be planar - the gradient code does not change
void XGradientPlanarRGB8_RGB32(
    unsigned short const* src_r, unsigned short const* src_g, unsigned short const* src_b,
    std::ptrdiff_t src_row_bytes, int w, int h,
    signed int* dst_pixels, std::ptrdiff_t dst_row_bytes)
{
  rgb16c_planar_view_t src = planar_rgb_view (w, h, src_r, src_g, src_b,        src_row_bytes);
  rgb32s_view_t        dst = interleaved_view(w, h, reinterpret_cast<rgb32s_pixel_t*>(dst_pixels), dst_row_bytes);
  x_gradient(src,dst);
}

如这些示例所示, 源和目标都可以是交织式或平面式的, 通道深度任意 (假定目标通道可从源赋值), 色彩空间任意兼容.

GIL 2.1 还能原生表示通道不按字节对齐的图像, 例如 6 位 RGB222 图像或 1 位 Gray1 图像. GIL 算法可原生作用于这些图像. 关于使用此类图像的更多信息, 参见设计指南或示例文件.

Image View Transformations

计算 y 梯度的一种方法是把图像旋转 90 度, 计算 x 梯度, 再把结果旋转回来. 在 GIL 中做法如下:

template <typename SrcView, typename DstView>
void y_gradient(SrcView const& src, DstView const& dst)
{
  x_gradient(rotated90ccw_view(src), rotated90ccw_view(dst));
}

rotated90ccw_view 接受一个图像视图, 返回一个表示其输入逆时针旋转 90 度的图像视图. 它是 GIL 视图变换函数的一个示例. GIL 提供了多种变换函数, 可执行任意轴对齐旋转、转置视图、垂直或水平翻转视图、提取矩形子图、执行颜色转换、对视图子采样等. 视图变换函数快速而浅层 - 它们不复制像素, 只是改变访问像素的“坐标系”. 例如 rotated90cw_view 返回一个视图, 其水平迭代器是原视图的垂直迭代器. 上述计算 y_gradient 的代码因内存访问模式而较慢; 使用 rotated90cw_view 并不会使其更慢.

另一个例子: 假设我们要计算彩色图像第 N 个通道的梯度. 做法如下:

template <typename SrcView, typename DstView>
void nth_channel_x_gradient(SrcView const& src, int n, DstView const& dst)
{
  x_gradient(nth_channel_view(src, n), dst);
}

nth_channel_view 是一个视图变换函数, 它接受任意视图并返回其第 N 个通道的单通道 (灰度) 视图. 例如对交织式 RGB 视图, 返回的视图是步进视图 - 其水平迭代器每递增一次就跳过两个通道. 若作用于平面式 RGB 视图, 返回的类型是简单的灰度视图, 其水平迭代器是 C 指针. 图像视图变换函数可以串接使用. 例如, 要计算视图中偶数像素第二个通道的 y 梯度, 使用:

y_gradient(subsampled_view(nth_channel_view(src, 1), 2, 2), dst);

GIL 有时可以化简串接后的视图. 例如, 两个嵌套的子采样视图 (在 X 和 Y 方向跳过像素的视图) 可以表示为一个子采样视图, 其步长是两个视图步长的乘积.

一维像素迭代器

让我们再回到 x_gradient. 许多图像视图算法对每个像素施加同一操作, GIL 提供了一个抽象来处理它们. 然而, 我们的算法有一种不寻常的访问模式, 因为它跳过第一列和最后一列. 看看如何把它改写成规范形式, 是有益且有启发性的. 在 GIL 中的做法是: 写一个对每个像素都适用的版本, 但只把它应用于排除第一列和最后一列的子图:

void x_gradient_unguarded(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  for (int y = 0; y < src.height(); ++y)
  {
      gray8c_view_t::x_iterator src_it = src.row_begin(y);
      gray8s_view_t::x_iterator dst_it = dst.row_begin(y);

      for (int x = 0; x < src.width(); ++x)
          dst_it[x] = (src_it[x-1] - src_it[x+1]) / 2;
  }
}

void x_gradient(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  assert(src.width() >= 2);
  x_gradient_unguarded(subimage_view(src, 1, 0, src.width()-2, src.height()),
                       subimage_view(dst, 1, 0, src.width()-2, src.height()));
}

subimage_view 是 GIL 视图变换函数的另一个示例. 它接受一个源视图和一个矩形区域 (本例中定义为 x_min,y_min,width,height), 返回一个作用于源视图该区域的视图. 上述实现与作用于原始视图的版本相比, 没有可测量的性能下降.

既然 x_gradient_unguarded 对每个像素都适用, 我们可以把它重写得更紧凑:

void x_gradient_unguarded(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  gray8c_view_t::iterator src_it = src.begin();
  for (gray8s_view_t::iterator dst_it = dst.begin(); dst_it != dst.end(); ++dst_it, ++src_it)
      *dst_it = (src_it.x()[-1] - src_it.x()[1]) / 2;
}

GIL 图像视图提供 begin() 和 end() 方法, 它们返回一维像素迭代器, 按从左到右、从上到下的顺序遍历视图中的每个像素. 它们会正确地“回车” - 跳过行末所有未使用的字节. 因此它们略有欠缺, 因为需要相对于行末跟踪自己的当前位置. 其递增运算符要多做一次检查 (是否已到行末?), 若改用两个嵌套循环即可避免该检查. 这些迭代器有一个方法 x(), 返回我们之前使用的更轻量的水平迭代器. 水平迭代器没有行末的概念. 在本例中, 水平迭代器是原始 C 指针. 在我们的示例中, 必须使用水平迭代器才能正确访问两个邻居, 因为它们可能位于图像视图之外.

STL 等价算法

GIL 为许多算法提供了 STL 等价物. 例如, std::transform 是一个 STL 算法, 它把一个泛型函数作用于源范围的对应元素, 并将结果赋给目标范围中的每个元素. 在本例中, 我们想把对应源像素水平邻居的半差值赋给每个目标像素. 如果把该操作抽象成一个函数对象, 就可以用 GIL 的 transform_pixel_positions 来完成:

struct half_x_difference
{
  auto operator()(gray8c_loc_t const& src_loc) const -> int
  {
      return (src_loc.x()[-1] - src_loc.x()[1]) / 2;
  }
};

void x_gradient_unguarded(gray8c_view_t const& src, gray8s_view_t const& dst)
{
  transform_pixel_positions(src, dst, half_x_difference());
}

GIL 提供算法 for_each_pixel 和 transform_pixels, 它们是 STL std::for_each 和 std::transform 在图像视图上的对应物. 它还提供 for_each_pixel_position 和 transform_pixel_positions, 后者不向泛型函数传递像素引用, 而是传递像素定位器. 这使得函数更加强大, 可以通过传入的定位器使用像素的邻居. GIL 算法使用效率更高的两个嵌套循环遍历像素 (而不是使用一维迭代器的单循环).

颜色转换

比起计算图像每个颜色平面的梯度, 我们常常想计算亮度的梯度. 换言之, 我们想把彩色图像转换为灰度, 再计算结果的梯度. 下面演示如何计算 32 位浮点 RGB 图像的亮度梯度:

void x_gradient_rgb_luminosity(rgb32fc_view_t const& src, gray8s_view_t const& dst)
{
  x_gradient(color_converted_view<gray8_pixel_t>(src), dst);
}

color_converted_view 是一个 GIL 视图变换函数, 它接受任意图像视图, 并返回处于目标色彩空间与通道深度的视图 (以模板参数指定). 在本例中, 它在 32 位浮点 RGB 像素之上构造一个 8 位整数灰度视图. 与所有其他视图变换函数一样, color_converted_view 非常快速且浅层. 它不复制数据, 也不执行任何颜色转换, 而是返回一个视图, 该视图在每次访问像素时执行颜色转换.

在本算法的泛型版本中, 我们可能希望把色彩空间转换为灰度, 但保持通道深度不变. 做法是: 构造一个 GIL 灰度像素的类型, 其通道与源相同, 然后把颜色转换到该像素类型:

template <typename SrcView, typename DstView>
void x_luminosity_gradient(SrcView const& src, DstView const& dst)
{
  using gray_pixel_t = pixel<typename channel_type<SrcView>::type, gray_layout_t>;
  x_gradient(color_converted_view<gray_pixel_t>(src), dst);
}

当目标色彩空间与通道类型恰好与源相同时, 无需颜色转换. GIL 会检测这种情况并完全避免调用颜色转换代码 - 即 color_converted_view 原样返回源视图.

图像

上面的例子存在性能问题 - x_gradient 对大多数源像素解引用两次, 这会使上述代码执行两次颜色转换. 有时, 把颜色转换后的图像复制到临时缓冲区并用它计算梯度可能更高效 - 这样每个像素只调用一次颜色转换. 使用我们的非泛型版本可以这样实现:

void x_luminosity_gradient(rgb32fc_view_t const& src, gray8s_view_t const& dst)
{
  gray8_image_t ccv_image(src.dimensions());
  copy_pixels(color_converted_view<gray8_pixel_t>(src), view(ccv_image));

  x_gradient(const_view(ccv_image), dst);
}

首先构造一个与源具有相同尺寸的 8 位灰度图像. 然后把源的颜色转换视图复制到临时图像中. 最后在 x_gradient algorithm 中使用临时图像的只读视图. 如示例所示, GIL 提供全局函数 view 和 const_view, 它们接受一个图像并返回其像素的可变视图或不可变视图.

把上述代码做成泛型版本要更费些周折:

template <typename SrcView, typename DstView>
void x_luminosity_gradient(SrcView const& src, DstView const& dst)
{
  using d_channel_t = typename channel_type<DstView>::type;
  using channel_t = typename detail::channel_convert_to_unsigned<d_channel_t>::type;
  using gray_pixel_t = pixel<channel_t, gray_layout_t>;
  using gray_image_t = image<gray_pixel_t, false>;

  gray_image_t ccv_image(src.dimensions());
  copy_pixels(color_converted_view<gray_pixel_t>(src), view(ccv_image));
  x_gradient(const_view(ccv_image), dst);
}

首先使用 channel_type 元函数获取目标视图的通道类型. 元函数是作用于类型的函数. 在 GIL 中, 元函数是类模板 (用 struct 类型说明符声明), 它们以模板参数的形式接受参数, 并在一个名为 type 的嵌套 typedef 中返回结果. 本例中的 channel_type 是一个一元元函数, 在此示例中以图像视图的类型调用, 返回与该图像视图关联的通道的类型.

具有关联像素类型的 GIL 构造, 如像素、像素迭代器、定位器、视图和图像, 都符合 PixelBasedConcept, 这意味着它们提供一组元函数来查询像素属性, 如 channel_type, color_space_type, channel_mapping_type 和 num_channels.

得到目标视图的通道类型之后, 我们用另一个元函数去除其符号性 (若其为有符号整数类型), 然后用它生成灰度像素的类型. 由像素类型创建图像类型. GIL 的 image 类以像素类型和一个布尔值 (指示图像应为平面式还是交织式) 特化. GIL 中的单通道 (灰度) 图像必须始终是交织式的. 在 GIL 中构造类型有多种方式. 我们本可以直接使用类型工厂元函数, 而不必直接实例化类. 以下代码与之等价:

template <typename SrcView, typename DstView>
void x_luminosity_gradient(SrcView const& src, DstView const& dst)
{
  using d_channel_t = typename channel_type<DstView>::type;
  using channel_t = typename detail::channel_convert_to_unsigned<d_channel_t>::type;
  using gray_image_t = typename image_type<channel_t, gray_layout_t>::type;

  gray_image_t ccv_image(src.dimensions());
  copy_and_convert_pixels(src, view(ccv_image));
  x_gradient(const_view(ccv_image), dst);
}

GIL 提供一组生成 GIL 类型的元函数 - image_type 即是这样一种元函数, 它由给定的通道类型、颜色布局以及平面式/交织式选项 (默认为交织式) 构造图像的类型. 还有类似的元函数可构造像素引用、迭代器、定位器和图像视图的类型. GIL 还有元函数 derived_pixel_reference_type, derived_iterator_type, derived_view_type 和 derived_image_type, 它们从给定的源构造构造出新的 GIL 构造类型, 只改变该类型的一个或多个属性而保持其余不变.

从图像类型出发, 我们可以使用嵌套 typedef value_type 来获得像素的类型. GIL 图像、图像视图和定位器都有嵌套 typedef value_type 和 reference, 用于获得像素的类型和像素的引用的类型. 如果你拿到的是一个像素迭代器, 可以从其 iterator_traits 获得这些类型. 另请注意算法 copy_and_convert_pixels, 它是 copy_pixels 的简写版本, 带有颜色转换后的源视图.

虚拟图像视图

迄今为止, 我们处理的是像素存储在内存中的图像. GIL 允许你为任意图像创建图像视图, 包括合成函数. 为演示这一点, 我们来创建 Mandelbrot 集的视图. 首先, 需要创建一个函数对象, 计算图像中给定位置 (x,y) 处 Mandelbrot 集的值:

// models PixelDereferenceAdaptorConcept
template <typename Pixel>   // Models PixelValueConcept
struct mandelbrot_fn
{
  using point_t = point<ptrdiff_t>;
  using const_t = mandelbrot_fn;
  using value_type = Pixel;
  using reference = value_type;
  using const_reference = value_type;
  using argument_type = point_t;
  using result_type = reference;
  static bool constexpr is_mutable = false;

  mandelbrot_fn() = default;
  mandelbrot_fn(point_t const& sz, value_type const& in_color, value_type const& out_color)
      : _in_color(in_color), _out_color(out_color), _img_size(sz) {}

  auto operator()(point_t const& p) const -> result_type
  {
      // normalize the coords to (-2..1, -1.5..1.5)
      // (actually make y -1.0..2 so it is asymmetric, so we can verify some view factory methods)
      double t = get_num_iter(point<double>(p.x/(double)_img_size.x*3-2, p.y/(double)_img_size.y*3-1.0f));//1.5f));
      t = pow(t,0.2);

      result_type ret;
      for (std::size_t k = 0; k<num_channels<Pixel>::value; ++k)
          ret[k] = typename channel_type<Pixel>::type(_in_color[k]*t + _out_color[k]*(1-t));
      return ret;
  }

private:
  value_type _in_color,_out_color;
  point_t _img_size;
  static constexpr int MAX_ITER = 100;

  auto get_num_iter(point<double> const& p) const -> double
  {
      point<double> Z(0,0);
      for (int i = 0; i < MAX_ITER; ++i)
      {
          Z = point<double>(Z.x*Z.x - Z.y*Z.y + p.x, 2*Z.x*Z.y + p.y);
          if (Z.x*Z.x + Z.y*Z.y > 4)
              return i/static_cast<double>(MAX_ITER);
      }
      return 0;
  }
};

现在我们可以使用 GIL 的 virtual_2d_locator 配合这个函数对象, 构造一个大小为 200x200 像素的 rgb8 Mandelbrot 视图:

using deref_t = mandelbrot_fn<rgb8_pixel_t>;
using point_t = deref_t::point_t;
using locator_t = virtual_2d_locator<deref_t, false>;
using my_virt_view_t = image_view<locator_t>;

point_t dims(200,200);

// Construct a Mandelbrot view with a locator, taking top-left corner (0,0) and step (1,1)
my_virt_view_t mandel(dims, locator_t(
    point_t(0,0), point_t(1,1),
    deref_t(dims, rgb8_pixel_t(255, 0, 255), rgb8_pixel_t(0, 255, 0))));

我们可以像对待真实视图一样对待这个合成视图. 例如, 调用我们的 x_luminosity_gradient 算法计算 Mandelbrot 集旋转 90 度后视图的亮度梯度, 并保存原图与结果:

#include <boost/gil/extension/io/jpeg.hpp>

gray8s_image_t img(dims);
x_luminosity_gradient(rotated90cw_view(mandel), view(img));

// Save the Mandelbrot set and its 90-degree rotated gradient
// (jpeg cannot save signed char; must convert to unsigned char)
write_view("mandel.jpg", mandel, jpeg_tag{});
write_view("mandel_grad.jpg", color_converted_view<gray8_pixel_t>(const_view(img)), jpeg_tag{});

运行期指定的图像与图像视图

至此, 我们创建了一个泛型函数, 它计算图像视图模板特化的图像梯度. 但有时, 图像视图的属性 (如色彩空间和通道深度) 可能在编译期不可用. GIL 的 dynamic_image 扩展支持处理在运行期指定的 GIL 构造, 也称为 变体. GIL 提供了运行期实例化图像 any_image 和运行期实例化图像视图 any_image_view 的模型. 也已具备创建其他变体的机制, 如 any_pixel, any_pixel_iterator 等. GIL 的大多数算法和全部视图变换函数同样可用于运行期实例化的图像视图, 且二元算法 (如 copy_pixels) 的任一或全部实参都可以是变体.

让我们让 x_luminosity_gradient 算法接受变体图像视图. 为简单起见, 假定只有源视图可以是变体. 使用多个变体的示例, 参见 GIL 接受多个变体的图像视图算法重载.

首先, 我们需要创建一个函数对象, 它包含模板化的目标视图, 并有一个以模板化源视图为参数的应用运算符:

#include <boost/gil/extension/dynamic_image/dynamic_image_all.hpp>

template <typename DstView>
struct x_gradient_obj
{
  using result_type = void;        // required typedef

  DstView const& _dst;
  x_gradient_obj(DstView const& dst) : _dst(dst) {}

  template <typename SrcView>
  auto operator()(SrcView const& src) const -> result_type
  {
    x_luminosity_gradient(src, _dst);
  }
};

第二步是为 x_luminosity_gradient 提供一个重载, 它接受图像视图变体并调用 variant2::visit, 将函数对象传入:

template <typename ...SrcViews, typename DstView>
void x_luminosity_gradient(any_image_view<SrcViews...> const& src, DstView const& dst)
{
  variant2::visit(x_gradient_obj<DstView>(dst), src);
}

any_image_view<SrcViews...> 是图像视图变体. 它以 SrcViews... 为模板参数, 后者枚举了该变体可能采取的所有视图类型. src 内部包含当前实例化类型的索引, 以及包含实例的一块内存. variant2::visit 对该索引执行 switch 语句, 其每个 case 把内存转换为正确的视图类型, 并用它调用函数对象. 对变体调用算法只有一次 switch 语句的开销. 对图像视图中的每个像素执行操作的算法在与变体一起使用时几乎没有性能下降.

我们可以这样构造变体并调用算法:

#include <boost/gil/extension/io/jpeg.hpp>

using my_img = any_image<gray8_image_t, gray16_image_t, rgb8_image_t, rgb16_image_t>;
my_img runtime_image;
read_image("input.jpg", runtime_image, jpeg_tag{});

gray8s_image_t gradient(runtime_image.dimensions());
x_luminosity_gradient(const_view(runtime_image), view(gradient));
write_view(
    "x_gradient.jpg",
    color_converted_view<gray8_pixel_t>(const_view(gradient)),
    jpeg_tag{});

在本例中, 我们创建一个图像变体, 它可以是 8 位或 16 位的 RGB 或灰度图像. 然后使用 GIL 的 I/O 扩展从文件加载图像, 保持其原生色彩空间和通道深度. 若所有允许的图像类型都无法匹配磁盘上的图像, 将抛出异常. 接着构造一个 8 位有符号 (即 char) 图像来存储梯度, 并对其调用 x_luminosity_gradient. 最后把结果保存到另一个文件. 我们保存的是转换为 8 位无符号的视图, 因为 JPEG I/O 不支持有符号 char.

注意 read_image, dimensions, view 和 const_view 这类自由函数和方法既可用于模板化类型, 也可用于变体类型. 对模板化图像, view(img) 返回模板化视图; 而对图像变体, 它返回视图变体. 例如, view(runtime_image) 的返回类型是 any_image_view<Views>, 其中 Views 枚举了与四种图像类型对应的四个视图. const_view(runtime_image) 返回四个只读视图类型的 any_image_view, 等等.

关于使用变体的一个警告: 用变体实例化算法, 实际上会以该变体可能采取的每种类型实例化它. 对二元算法, 算法会以两种输入类型的每种可能组合实例化! 这会同时拖累编译时间和可执行文件的大小.

结论

本教程简要展示了在 GIL 中编写泛型且高效的图像处理算法所面临的挑战. 我们选取一个简单的算法, 展示了如何使其适用于位深度、色彩空间、通道顺序和平面式/交织式结构各异的图像表示. 我们证明了该算法可以处理完全抽象的虚拟图像, 甚至类型在运行期才确定的图像. 相关视频演示还表明, 即使对于复杂场景, 生成的汇编代码也可与针对特定图像类型手写的该算法 C 版本相媲美.

然而, 即使对于这样一个简单的算法, 我们距离完全泛化且优化的代码还很远. 特别是, 呈现的算法作用于同质图像, 即像素的通道全部为同一类型的图像. 也存在包含不同类型通道的图像示例, 例如打包的 565 RGB 格式. 尽管 GIL 提供了作用于异质像素的概念和算法, 但我们把扩展 x_gradient 的任务留作读者的练习. 其次, 在计算出梯度值之后, 我们只是简单地把它转换为目标通道类型. 这并不总是所需的操作. 例如, 若源通道是范围为 [0..1] 的 float, 而目标是 unsigned char, 把半差转换为 unsigned char 的结果只会是 0 或 1. 相反, 我们可能想做的是把结果缩放到目标通道的范围内. GIL 的通道级算法在这类情况下可能有用. 例如, channel_convert 通过把源通道值线性缩放到目标通道的范围来在通道间转换.

在改进性能方面还有很多工作可做. 通道级操作 (如半差) 可以抽象为原子级的通道级算法, 并可为具体通道类型提供性能重载. 可以使用处理器专有的操作, 例如同时对整行像素执行操作, 或者预取数据. 所有这些优化都可以实现为泛型算法的性能特化. 最后, 编译器虽然在不断改进, 但在某些情况下仍无法充分优化泛型代码, 例如无法内联某些函数或把某些变量放入寄存器. 如果性能是问题所在, 值得用不同的编译器尝试你的代码.
