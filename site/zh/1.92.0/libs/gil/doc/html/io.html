IO 扩展

概述

这个 boost::gil 扩展提供了一个易于使用的接口, 用于读写各种图像格式. 它还包含一个用于添加新格式的框架.

所有受支持的图像格式请参见 3.3 节. 基础教程见 [link gil.io.tutorial Tutorial] 一节. 此外, 该扩展要求 Boost 1.42 及以上版本, 并且用到了 GIL 扩展 Toolbox.

添加新图像格式请参见 [link gil.io.using_io.extending_gil__io_with_new_formats Extending GIL::IO with new Formats] 一节.

支持的平台

所有受 Boost 支持且拥有良好 C++ 编译器的平台. 根据图像格式的不同, 可能需要以下图像库中的一个或多个:

  • libtiff

  • libjpeg

  • libpng

  • libraw

  • zlib

本库被设计为支持用户所需的任意多种格式. 例如, 如果用户只需要 bmp 支持, 则不需要上述任何依赖.

本文档中有关于图像格式依赖的更多细节. 请参见 [link gil.io.using_io.supported_image_formats Supported Image Formats] 一节.

教程

得益于现代 C++ 编程技术, 本库的接口相当小巧且易于使用. 在本教程中, 我将简要介绍如何使用这个 boost::gil 扩展. 更多细节请参见第 3 节.

每种受支持的 IO 格式都提供一个单独的顶层头文件. 例如, 包含 boost/gil/extension/io/tiff.hpp 即可读取或写入 TIFF 文件.

读取图像

最常见的读取 tiff 图像的情形大概可以这样完成:

std::string filename( "image.tif" );
rgb8_image_t img;
read_image( filename, img, tiff_tag() );

这段代码对所有其他图像格式都是一样的. 唯一需要改变的是 read_image 调用中的标记类型 ( tiff_tag ). read_image() 要求所提供的图像类型与文件中存储的图像兼容. 如果用户不知道图像是什么格式, 可以使用 read_and_convert_image(). 另一个重要事实是, read_image() 会为读取操作分配所需的适当内存. 如果内存已经分配, 也有 read_view 或 read_and_convert_view 对应版本.

有时用户只想读取图像的一部分, 此时上面的调用如下所示:

read_image( filename
          , img
          , image_read_settings< tiff_tag >( point_t( 0, 0 ), point_t( 50, 50 ) )
          );

image_read_settings 类为用户提供与图像格式无关的读取设置, 同时也可以作为格式相关设置的载体. 更多细节请参见具体的图像格式章节 [link gil.io.using_io.supported_image_formats Supported Image Formats].

写入图像

除了读取信息之外, 写入是此 Boost.GIL 扩展的第二部分. 写入比读取简单得多, 因为现有的图像视图已包含全部信息.

例如, 写入图像可以这样完成:

std::string filename( "image.tif" );
rgb8_image_t img( 640, 480 );

// write data into image

write_view( filename
          , view( img )
          , tiff_tag()
          );

该接口与读取图像类似. 要添加图像格式特定的参数, 用户可以使用 image_write_info 类. 例如, 用户可以在写入时这样指定 JPEG 质量:

std::string filename( "image.jpg" );
rgb8_image_t img( 640, 480 );

// write data into image

write_view( filename
          , view( img )
          , image_write_info< jpeg_tag >( 95 )
          );

上面的示例将写入一幅 jpeg 质量设为 95% 的图像.

读写内存缓冲区

同样支持对内存缓冲区的读写. 如下所示:

// 1. Read an image.
ifstream in( "test.tif", ios::binary );

rgb8_image_t img;
read_image( in, img, tiff_tag() );

// 2. Write image to in-memory buffer.
stringstream out_buffer( ios_base::out | ios_base::binary );

rgb8_image_t src;
write_view( out_buffer, view( src ), tiff_tag() );

// 3. Copy in-memory buffer to another.
stringstream in_buffer( ios_base::in | ios_base::binary );
in_buffer << out_buffer.rdbuf();

// 4. Read in-memory buffer to gil image
rgb8_image_t dst;
read_image( in_buffer, dst, tag_t() );

// 5. Write out image.
string filename( "out.tif" );
ofstream out( filename.c_str(), ios_base::binary );
write_view( out, view( dst ), tiff_tag() );

如果用户使用自己的流类, 必须确保它具有 read、write、seek、close 等通用接口.

使用 IO

总体概述

教程指出了以各种图像格式读写图像的一些用例. 本节将提供更全面的概述.

接下来的几节将介绍读取和写入接口. 但值得指出的是, 通过使用一些高级元编程技术, 该接口相当小巧, 希望也易于理解.

除通用接口外, 用户还可以直接与底层图像格式交互. 为此, 每个读取器或写入器都提供对所谓后端的访问.

例如:

typedef bmp_tag tag_t;

typedef get_reader_backend< const std::string
                          , tag_t
                          >::type backend_t;

backend_t backend = read_image_info( bmp_filename
                                   , tag_t()
                                   );

BOOST_CHECK_EQUAL( backend._info._width , 127 );
BOOST_CHECK_EQUAL( backend._info._height, 64 );

当然, 使用 C++11 的 auto 特性时可以省去该 typedef.

读取接口

如教程所示, 有几种读取图像的方法. 下面列举所有读取函数并附简短说明:

  • read_image - 不做转换读入 gil 图像. 会分配内存.

  • read_view - 不做转换读入 gil 视图.

  • read_and_convert_image - 读取并转换到 gil 图像. 会分配内存.

  • read_and_convert_view - 读取并转换到 gil 视图.

  • read_image_info - 读取图像头.

如果源 (文件) 与目标 (gil 图像类型) 的色彩空间不兼容, 则此处需要进行转换. 在这种情况下, 用户必须使用 xxx_and_convert_xxx 变体.

所有函数都以文件名或设备作为第一个参数. 文件名可以是 C 字符串、std::string、std::wstring, 直到 std::filesystem 和 boost::filesystem 路径. std::filesystem 的可用性会被自动检测, 除非定义了 BOOST_GIL_IO_USE_BOOST_FILESYSTEM 宏强制优先使用 Boost.Filesystem. 对 TIFF 图像而言, 设备可以是 FILE*、std::ifstream 和 TIFF*.

第二个参数是图像类型或视图类型, 取决于 read_xxx 函数. 第三个也是最后一个参数是 image_read_settings<FormatTag> 的实例, 或者只是 FormatTag. 设置可以多种多样, 取决于所读取的格式. 但它们都共享读取部分图像区域的设置. 第一个点描述图像左上角坐标, 第二个是 x 和 y 方向上的尺寸.

下面是设置部分读取的示例:

read_image( filename
          , img
          , image_read_settings< tiff_tag >( point_t( 0, 0 ), point_t( 50, 50 ) )
          );

每种格式都支持仅读取头信息, 使用 read_image_info. 请参阅 3.3 节下特定格式的章节. 下面是一个基本示例:

image_read_info< tiff_t > info = read_image_info( filename
                                                , tiff_t()
                                                );

GIL 还带有动态图像扩展. 在 GIL.IO 的语境下, 用户可以基于若干图像类型定义一个 any_image 类型. 然后 IO 扩展会为当前图像文件选择匹配的图像类型. 以下示例展示了该特性:

any_image< gray8_image_t
         , gray16_image_t
         , rgb8_image_t
         , rgba8_image_t
         > runtime_image;

read_image( filename
          , runtime_image
          , tiff_tag()
          );

在评审期间, 人们明确需要逐扫描行读取大图像. 为支持这种用例, 所有受支持的图像格式都实现了 scanline_reader. 然后 scanline_read_iterators 将允许遍历整幅图像. 以下代码示例展示了其用法:

typedef tiff_tag tag_t;

typedef scanline_reader< typename get_read_device< const char*
                                                 , tag_t
                                                 >::type
                        , tag_t
                        > reader_t;

reader_t reader = make_scanline_reader( "C:/boost/libs/gil/test/extension/io/images/tiff/test.tif", tag_t() );

typedef rgba8_image_t image_t;

image_t dst( reader._info._width, reader._info._height );
fill_pixels( view(dst), image_t::value_type() );

typedef reader_t::iterator_t iterator_t;

iterator_t it  = reader.begin();
iterator_t end = reader.end();

for( int row = 0; it != end; ++it, ++row )
{
    copy_pixels( interleaved_view( reader._info._width
                                    , 1
                                    , ( image_t::view_t::x_iterator ) *it
                                    , reader._scanline_length
                                    )
                , subimage_view( view( dst )
                                , 0
                                , row
                                , reader._info._width
                                , 1
                                )
                );
}

遍历图像有很多方式, 但目前仅支持按扫描行遍历.

写入接口

写出图像只有一个函数, 即 write_view. 与读取类似, 第一个参数是文件名或设备. 文件名可以是 C 字符串、std::string、std::wstring, 直到 std::filesystem 和 boost::filesystem 路径. std::filesystem 的可用性会被自动检测, 除非定义了 BOOST_GIL_IO_USE_BOOST_FILESYSTEM 宏强制优先使用 Boost.Filesystem. 对 TIFF 图像而言, 设备可以是 FILE*、std::ifstream 和 TIFF*.

第二个参数是指向被写图像的视图对象. 第三个也是最后一个参数是一个标记, 或者是一个包含更多设置的 image_write_info<FormatTag> 对象. 例如 JPEG 质量就是一个例子. 所有可用设置的列表请参阅 3.3 节下特定格式的章节.

支持写入 any_image<…>. 参见以下示例:

any_image< gray8_image_t
         , gray16_image_t
         , rgb8_image_t
         , rgba8_image_t
         > runtime_image;

// fill any_image

write_view( filename
          , view( runtime_image )
          , tiff_tag()
          );

支持的图像格式

BMP

BMP 图像文件格式的总体介绍参见以下 BMP_Wiki.

请注意, 该代码未在 BMP 格式的 X Windows System 变体 (通常称为 XBM 和 XPM 格式) 上测试过.

这里只涉及 MS Windows 和 OS/2 格式.

目前该代码能够读写以下图像类型:

读取:

gray1_image_t、gray4_image_t、gray8_image_t、rgb8_image_t 和 rgba8_image_t

写入:

rgb8_image_t 和 rgba8_image_t

由于 gil 缺少索引图像类型, 当前接口只能写出非索引图像. 这一点很快会有所改变.

JPEG

JPEG 图像文件格式的总体介绍参见以下 JPEG_Wiki.

这个 jpeg 扩展基于 libjpeg 库, 库的地址见 JPEG_Lib.

支持自 8x 起的所有版本.

用户必须确保正确安装了该库. 我强烈建议用户自行构建该库, 这可能为你省去很多麻烦.

目前该代码能够读写以下图像类型:

读取:

gray8_image_t, rgb8_image_t, cmyk8_image_t

写入:

gray8_image_t, rgb8_image_t, cmyk8_image_t

可以读取 YCbCr 或 YCCK 图像, 但由于 gil 尚未提供这两种色彩空间, 结果可能不准确. 目前这些色彩空间被当作 rgb 图像读取. 这一点很快会有所改变.

PNG

PNG 图像文件格式的总体介绍参见以下 PNG_Wiki.

这个 png 扩展基于 libpng, 库的地址见 PNG_Lib.

支持自 1.5.x 起的所有版本.

用户必须确保正确安装了该库. 我强烈建议用户自行构建该库, 这可能为你省去很多麻烦.

目前该代码能够读写以下图像类型:

读取:

gray1, gray2, gray4, gray8, gray16, gray_alpha_8, gray_alpha_16, rgb8, rgb16, rgba8, rgba16

写入:

gray1, gray2, gray4, gray8, gray16, gray_alpha_8, gray_alpha_16, rgb8, rgb16, rgba8, rgba16

要读取 gray_alpha 图像, 用户必须在定义了 BOOST_GIL_IO_ENABLE_GRAY_ALPHA 宏的情况下编译应用程序. 该色彩空间在 toolbox 中用 gray_alpha.hpp 定义.

PNM

PNM 图像文件格式的总体介绍参见以下 PNM_Wiki. pnm 格式不需要外部库.

该扩展可以读取两种形式的格式 (ASCII 和二进制), 即 P1 到 P6 类型; 但只能写入二进制格式.

目前该代码能够读写以下图像类型:

读取:

gray1, gray8, rgb8

写入:

gray1, gray8, rgb8

读取单色文本图像时, 数据被读作 gray8 图像.

RAW

总体介绍参见 RAW_Wiki.

目前该扩展只能读取 rgb8 图像.

TARGA

BMP 图像文件格式的总体介绍参见以下 TARGA_Wiki.

目前该代码能够读写以下图像类型:

读取:

rgb8_image_t and rgba8_image_t

写入:

rgb8_image_t and rgba8_image_t

由于 gil 缺少索引图像类型, 当前接口只能写出非索引图像. 这一点很快会有所改变.

TIFF

TIFF 图像文件格式的总体介绍参见以下 TIFF_Wiki.

这个 tiff 扩展基于 libtiff, 库的地址见 TIFF_Lib.

支持自 3.9.x 起的所有版本.

用户必须确保正确安装了该库. 我强烈建议用户自行构建该库, 这可能为你省去很多麻烦.

TIFF 图像几乎可以编码表示各种色彩空间的所有通道尺寸, 甚至可以有平面式图像. 例如 rbg323 或 gray7. 通道还可以具有特定格式, 如整数值或浮点值.

完整的选项集请查阅以下网站:

  • TIFF_Base_Tags

  • TIFF_Extension_Tags

本扩展的作者并不声称支持所有 tiff 格式. 该扩展很可能持续演进, 每个新里程碑都会添加新特性. 以下是一个不完整的列表:

  • 多页 TIFF - 只读

  • 条带 (strip) TIFF - 支持读写

  • 平铺 (tiled) TIFF - 支持读写, 可使用用户定义的平铺尺寸

  • 位图像 TIFF - 完全支持, 例如 gray1_image_t (minisblack)

  • 平面式 TIFF - 完全支持

  • 浮点 TIFF - 完全支持

  • 调色板 TIFF - 受支持, 但目前尚无索引图像类型可用

这个 gil 扩展使用两个不同的测试图像套件来测试读写能力. 见 test_image 文件夹. 建议使用 ImageMagick 测试查看器显示图像.

用新格式扩展 GIL::IO

用新格式扩展 gil::io 应当简单直接. 在添加之前, 我建议先看看现有实现, 然后尝试遵循以下几条准则:

  • 为你的新 xxx 格式创建以下文件

    • xxx_read.hpp - 只包含读取代码

    • xxx_write.hpp - 只包含写入代码

    • xxx_all.hpp - 包含 xxx_read.hpp 和 xxx_write.hpp

  • 把代码加入 boost::gil::detail 命名空间

  • 为新格式创建一个标记类型. 如下所示:

    struct xxx_tag : format_tag {};

  • 为新格式创建 image_read_info. 它包含读取图像所需的全部信息. 它应当由读取器类的 get_info 成员填充并返回. 见下文:

    template<> struct image_read_info< xxx_tag > {};

  • 为新格式创建 image_write_info. 它包含写入图像所需的全部信息:

    template<> struct image_write_info< xxx_tag > {};

  • 以下面的读取器骨架作为起点:

    template< typename Device
        , typename ConversionPolicy
        >
class reader< Device
            , xxx_tag
            , ConversionPolicy
            >
            : public reader_base< xxx_tag
                                , ConversionPolicy
                                >
{
private:

    typedef typename ConversionPolicy::color_converter_type cc_t;

public:

    reader( Device& device )
    : _io_dev( device )
    {}

    reader( Device&     device
          , const cc_t& cc
          )
    : _io_dev( device )
    , reader_base< xxx_tag
                 , ConversionPolicy
                 >( cc )
    {}

    image_read_info< xxx_tag > get_info()
    {
        // your implementation here
    }

    template< typename View >
    void apply( const View& dst_view )
    {
        // your implementation here
    }
};

  • 写入器骨架:

    template< typename Device >
class writer< Device
            , xxx_tag
            >
{
public:

    writer( Device & file )
    : out(file)
    {}

    template<typename View>
    void apply( const View& view )
    {
        // your implementation here
    }

    template<typename View>
    void apply( const View&                        view
              , const image_write_info< xxx_tag >& info )
    {
        // your implementation here
    }
};
