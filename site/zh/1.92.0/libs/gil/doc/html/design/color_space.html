色彩空间与布局

  • 概述

  • 模型

概述

色彩空间刻画了构成像素的通道的集合及其解释. 在 Boost.GIL 中, 色彩空间被定义为一个 MPL 随机访问序列, 其中包含该色彩空间中所有元素的类型.

如果两个色彩空间相等 (即以相同顺序拥有相同的颜色集合), 则认为它们是兼容的.

参见

  • ColorSpaceConcept<ColorSpace>

  • ColorSpacesCompatibleConcept<ColorSpace1,ColorSpace2>

  • ChannelMappingConcept<Mapping>

模型

GIL 目前提供以下色彩空间:

  • gray_t

  • rgb_t

  • rgba_t

  • cmyk_t

它还提供二到五通道的未命名 N 通道色彩空间:

  • devicen_t<2>

  • devicen_t<3>

  • devicen_t<4>

  • devicen_t<5>

除标准布局之外, 它还提供:

  • bgr_layout_t

  • bgra_layout_t

  • abgr_layout_t

  • argb_layout_t

作为示例, 下面是 GIL 定义 RGBA 色彩空间的方式:

struct red_t {};
struct green_t {};
struct blue_t {};
struct alpha_t {};
rgba_t = using mp11::mp_list<red_t, green_t, blue_t, alpha_t>;

色彩空间定义中通道的顺序规定了它们的语义顺序. 例如, red_t 是 rgba_t 的第一个语义通道. 虽然一个色彩空间中通道的语义顺序是唯一的, 但通道在内存中的物理顺序可以不同.

通道的映射由 ChannelMappingConcept 指定, 它是一个由整数类型组成的 MPL 随机访问序列. 色彩空间与其关联的映射通常一起使用.

因此它们在 GIL 的布局中被组合在一起:

template
<
    typename ColorSpace,
    typename ChannelMapping = mp11::make_integer_sequence<int, mp11::mp_size<ColorSpace>::value>
>
struct layout
{
  using color_space_t = ColorSpace;
  using channel_mapping_t = ChannelMapping;
};

下面展示如何为 RGBA 色彩空间创建布局:

using rgba_layout_t = layout<rgba_t>; // default ordering is 0,1,2,3...
using bgra_layout_t = layout<rgba_t, mp11::mp_list_c<int,2,1,0,3>>;
using argb_layout_t = layout<rgba_t, mp11::mp_list_c<int,1,2,3,0>>;
using abgr_layout_t = layout<rgba_t, mp11::mp_list_c<int,3,2,1,0>>;
