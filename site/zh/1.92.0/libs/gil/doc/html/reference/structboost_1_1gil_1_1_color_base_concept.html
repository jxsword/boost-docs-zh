template<typename ColorBase>
struct boost::gil::ColorBaseConcept< ColorBase >

颜色基是颜色元素 (如通道、通道引用或通道指针) 的容器.

颜色基最常见的用途是在像素的实现中, 此时颜色元素就是通道值. 不过, 颜色基概念也可用于其他场景. 例如, 平面式像素的通道在内存中不连续, 其引用是一个代理类, 它使用元素为通道引用的颜色基; 其迭代器使用元素为通道迭代器的颜色基.

颜色基必须有一个关联的布局 (由色彩空间以及通道的排序组成). 索引颜色基元素的方式有两种: 物理索引对应于元素在内存中的排列方式, 而语义索引对应于元素在其色彩空间中的排列方式. 例如, 在 RGB 色彩空间中, 元素的排列顺序为 {red_t, green_t, blue_t}. 对于具有 BGR 布局的颜色基, 物理排序中的第一个元素是蓝色元素, 而第一个语义元素是红色元素. ColorBaseConcept 的模型必须提供 at_c<K>(ColorBase) 函数, 它允许按物理顺序访问元素. GIL 提供了 semantic_at_c<K>(ColorBase) 函数 (稍后描述), 它可作用于 ColorBaseConcept 的任何模型, 并返回对应的语义元素.

concept ColorBaseConcept<typename T> : CopyConstructible<T>, EqualityComparable<T>
{
// a GIL layout (the color space and element permutation)
typename layout_t;
// 第 K 个元素的类型
template <int K>
struct kth_element_type;
where Metafunction<kth_element_type>;
// at_c 的结果
template <int K>
struct kth_element_const_reference_type;
where Metafunction<kth_element_const_reference_type>;
template <int K>
kth_element_const_reference_type<T,K>::type at_c(T);
// 可拷贝构造, 并可与其他兼容的颜色基进行相等比较
template <ColorBaseConcept T2> where { ColorBasesCompatibleConcept<T,T2> }
T::T(T2);
template <ColorBaseConcept T2> where { ColorBasesCompatibleConcept<T,T2> }
bool operator==(const T&, const T2&);
template <ColorBaseConcept T2> where { ColorBasesCompatibleConcept<T,T2> }
bool operator!=(const T&, const T2&);
};
