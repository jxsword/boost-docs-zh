添加新的 io 后端

后端要求列表

要添加对新 IO 后端的支持, 需要满足以下要求:

  • 一个格式标记, 用于标识图像格式, 派生自 boost::gil::format_tag
  • 必须为新格式标记实现布尔元函数 is_supported<PixelType,FormatTag>
  • 必须提供 image_read_info<FormatTag> 的显式特化, 其中包含读取图像之前/读取时即可获得的运行期信息
  • 必须提供 image_write_info<FormatTag> 的显式特化, 其中包含写入图像的运行期编码参数
  • 图像读取器必须被特化:
    template<typename IODevice, typename ConversionPolicy>

ConversionPolicy 的接口

读取图像时使用两种不同的转换策略: read_and_convert<ColorConverter> 与 read_and_no_convert. ColorConverter 可以是用户自定义的颜色转换器.

struct ConversionPolicy
{
template<typename InputIterator,typename OutputIterator>
void read( InputIterator in_begin, InputIterator in_end,
OutputIterator out_end );
};

read_view 与 read_image 之类的方法应当抛出异常而中止, 而不是转换图像

IO 设备的概念

Device 只是一个用于从流读取和向流写入数据的对象. 将 IODevice 作为模板参数加入, 是为了能够替换按 file_name 访问的功能. 这只是临时方案, 一旦 boost 提供了完善的 IO 库, 即可采用该库提供的接口/约束.

concept IODevice
{
void IODevice::read( unsigned char* data, int count );
void IODevice::write( unsigned char* data, int count );
void IODevice::seek(long count, int whence);
void IODevice::flush();
};

namespace boost{namespace gil{namespace detail{
