Boost.Coroutine 提供两种实现 - 非对称协程与对称协程.

对称协程通常出现在并发编程的语境中, 用于表示独立的执行单元. 产生值序列的实现一般使用非对称协程. [5]

有栈

协程的每个实例都有自己的栈.

与无栈协程不同, 有栈协程允许在任意子栈帧中调用挂起操作, 从而支持逃逸后重入的递归操作.

仅可移动

协程仅可移动.

如果协程可以复制, 其栈及其上分配的所有对象也会被复制. 若其中某些对象是 RAII 类 (通过 RAII 模式管理资源), 这将导致未定义行为. 当第一个协程副本终止 (展开其栈) 时, RAII 类的析构函数会释放所管理的资源; 当第二个副本终止时, 相同的析构函数将试图重复释放同一批资源, 从而导致未定义行为.

清理

销毁协程时将展开关联的栈.

协程的构造函数允许传入自定义的 栈分配器. 栈分配器 可以释放栈, 也可以将其缓存供以后使用 (供稍后创建的协程使用).

分段栈

symmetric_coroutine<>::call_type, asymmetric_coroutine<>::push_type 与 asymmetric_coroutine<>::pull_type 支持分段栈 (按需增长).

所需栈的大小并不总能准确估计 - 大多数情况下会分配过多内存 (浪费虚拟地址空间).

构造时协程以默认 (最小) 栈大小启动. 该最小栈大小取页面大小与信号栈规范大小 (POSIX 上的宏 SIGSTKSZ) 中的较大者.

截至撰写时, 已知仅 GCC (4.7) [6] 支持分段栈. 自 1.54 版起, Boost.Coroutine 提供对分段栈的支持.

析构函数释放关联的栈. 实现者可以释放栈, 也可以将其缓存供以后使用.

上下文切换

每次上下文切换时, 协程都会依照底层 ABI 保存并恢复寄存器 (使用 Boost.Context).

某些应用程序不使用浮点寄存器, 出于性能考虑可以禁用 FPU 寄存器的保存.

注释

依照调用约定, 默认会保存 FPU 寄存器.

在 POSIX 系统上, 出于性能考虑, 协程的上下文切换不保存信号掩码.

上下文切换通过 symmetric_coroutine<>::call_type::operator(), asymmetric_coroutine<>::push_type::operator() 与 asymmetric_coroutine<>::pull_type::operator() 完成.

警告

调用 symmetric_coroutine<>::call_type::operator(), asymmetric_coroutine<>::push_type::operator() 与 asymmetric_coroutine<>::pull_type::operator() 时, 若是在 同一 协程内部进行, 会导致未定义行为.

例如, 下面的代码将导致未定义行为:

boost::coroutines::symmetric_coroutine<void>::call_type coro(
    [&](boost::coroutines::symmetric_coroutine<void>::yield_type& yield){
        yield(coro); // yield to same symmetric_coroutine
});
coro();
