对称协程

类 symmetric_coroutine<>::call_type
类 symmetric_coroutine<>::yield_type

非对称协程中调用方与被调方的关系是固定的; 与之不同, 对称协程能够把执行控制权转移给任何其他 (对称) 协程. 例如, 对称协程不要求返回其直接调用方.

symmetric_coroutine<>::call_type

symmetric_coroutine<>::call_type 启动一个对称协程, 并把其参数传输给 协程函数. 模板参数定义所传输参数的类型. symmetric_coroutine<>::call_type 的构造函数接受一个函数 (协程函数) 作为参数, 该函数接受对 symmetric_coroutine<>::yield_type 的引用. 实例化 symmetric_coroutine<>::call_type 不会将执行控制权交给 协程函数 - 而是在第一次调用 symmetric_coroutine<>::call_type::operator() 时合成一个 symmetric_coroutine<>::yield_type, 并以引用形式传给 协程函数.

symmetric_coroutine<>::call_type 的接口不含 get() 函数: 这类协程对象无法从另一个执行上下文取回值.

symmetric_coroutine<>::yield_type

symmetric_coroutine<>::yield_type::operator() 用于以另一个 symmetric_coroutine<>::call_type 作为第一个参数调用 symmetric_coroutine<>::yield_type::operator(), 从而把数据和执行控制权转移给另一个上下文. 或者, 也可以不带 symmetric_coroutine<>::call_type 参数调用 symmetric_coroutine<>::yield_type::operator(), 把控制权交回调用 symmetric_coroutine<>::call_type::operator() 的代码.

该类只有一个定义所传输参数类型的模板参数. 传输给协程的数据通过 symmetric_coroutine<>::yield_type::get() 访问.

重要

symmetric_coroutine<>::yield_type 只能由框架创建.

std::vector<int> merge(const std::vector<int>& a,const std::vector<int>& b)
{
    std::vector<int> c;
    std::size_t idx_a=0,idx_b=0;
    boost::coroutines::symmetric_coroutine<void>::call_type* other_a=0,* other_b=0;

    boost::coroutines::symmetric_coroutine<void>::call_type coro_a(
        [&](boost::coroutines::symmetric_coroutine<void>::yield_type& yield) {
            while(idx_a<a.size())
            {
                if(b[idx_b]<a[idx_a])    // test if element in array b is less than in array a
                    yield(*other_b);     // yield to coroutine coro_b
                c.push_back(a[idx_a++]); // add element to final array
            }
            // add remaining elements of array b
            while ( idx_b < b.size())
                c.push_back( b[idx_b++]);
        });

    boost::coroutines::symmetric_coroutine<void>::call_type coro_b(
        [&](boost::coroutines::symmetric_coroutine<void>::yield_type& yield) {
            while(idx_b<b.size())
            {
                if (a[idx_a]<b[idx_b])   // test if element in array a is less than in array b
                    yield(*other_a);     // yield to coroutine coro_a
                c.push_back(b[idx_b++]); // add element to final array
            }
            // add remaining elements of array a
            while ( idx_a < a.size())
                c.push_back( a[idx_a++]);
        });


    other_a = & coro_a;
    other_b = & coro_b;

    coro_a(); // enter coroutine-fn of coro_a

    return c;
}

std::vector< int > a = {1,5,6,10};
std::vector< int > b = {2,4,7,8,9,13};
std::vector< int > c = merge(a,b);
print(a);
print(b);
print(c);

output:
    a : 1 5 6 10
    b : 2 4 7 8 9 13
    c : 1 2 4 5 6 7 8 9 10 13

本例在主执行上下文中创建了两个 symmetric_coroutine<>::call_type, 接受一个 lambda 函数 (即 协程函数), 该函数把两个有序数组的元素合并到第三个数组中. coro_a() 进入该 协程函数 (即 coro_a 的协程函数), 循环遍历数组并测试另一数组中的当前元素是否小于本地数组中的对应元素. 若是, 该协程就让出控制权给另一个协程 coro_b, 所用的方式是 yield(*other_b). 若本地数组的当前元素小于另一数组的元素, 则将其放入第三个数组. 由于协程会跳回 coro_a() (在离开 协程函数 后从此方法返回), 因此当本地数组的全部元素处理完毕后, 另一个数组的元素将被追加到第三个数组的末尾.

协程函数

协程函数 返回 void, 并以 symmetric_coroutine<>::yield_type 作为参数, 在 协程函数 内部提供协程功能. 使用该实例是传输数据和执行控制权的唯一途径. symmetric_coroutine<>::call_type 不在 symmetric_coroutine<>::call_type 构造时进入 协程函数, 而是在第一次调用 symmetric_coroutine<>::call_type::operator() 时进入.

只要模板参数不是 void, 协程函数 (属于某个 symmetric_coroutine<>::call_type) 都可以假定: (a) 首次进入时以及 (b) 每次 symmetric_coroutine<>::yield_type::operator() 调用之后, 其 symmetric_coroutine<>::yield_type::get() 都有新值可用.

但是, 若模板参数是仅可移动类型, 则在下一次 symmetric_coroutine<>::yield_type::operator() 调用之前, symmetric_coroutine<>::yield_type::get() 只能调用一次.

从主上下文向对称协程传递数据

为了把数据从主上下文传给 symmetric_coroutine<>::call_type, 框架会合成一个与该 symmetric_coroutine<>::call_type 实例相关联的 symmetric_coroutine<>::yield_type. 合成的 symmetric_coroutine<>::yield_type 作为参数传给 协程函数. 主上下文必须调用 symmetric_coroutine<>::call_type::operator() 才能把每个数据值传入 协程函数. 访问传输来的数据值通过 symmetric_coroutine<>::yield_type::get() 完成.

boost::coroutines::symmetric_coroutine<int>::call_type coro( // constructor does NOT enter coroutine-function
    [&](boost::coroutines::symmetric_coroutine<int>::yield_type& yield){
        for (;;) {
            std::cout << yield.get() <<  " ";
            yield(); // jump back to starting context
         }
    });

coro(1); // transfer {1} to coroutine-function
coro(2); // transfer {2} to coroutine-function
coro(3); // transfer {3} to coroutine-function
coro(4); // transfer {4} to coroutine-function
coro(5); // transfer {5} to coroutine-function
异常

symmetric_coroutine<>::call_type 的 协程函数 内部未被捕获的异常会调用 std::terminate().

重要

协程执行的代码不得阻止 detail::forced_unwind 异常的传播. 吞掉该异常会导致栈展开失败. 因此, 任何捕获所有异常的代码都必须重新抛出任何待处理的 detail::forced_unwind 异常.

try {
    // code that might throw
} catch(const boost::coroutines::detail::forced_unwind&) {
    throw;
} catch(...) {
    // possibly not re-throw pending exception
}
重要

不要从 catch 块内部跳转, 然后在另一个执行上下文中重新抛出该异常.

栈展开

有时需要展开未完成协程的栈, 以销毁局部栈变量, 使其能够释放已分配的资源 (RAII 模式). 协程构造函数的 attributes 参数指示析构函数是否应展开栈 (默认展开栈).

栈展开假定以下前置条件:

  • 协程不是 not-a-coroutine
  • 协程未完成
  • 协程未在运行
  • 协程拥有一个栈

展开之后, coroutine 即为完成状态.

struct X {
    X(){
        std::cout<<"X()"<<std::endl;
    }

    ~X(){
        std::cout<<"~X()"<<std::endl;
    }
};

boost::coroutines::symmetric_coroutine<int>::call_type other_coro(...);

{
    boost::coroutines::symmetric_coroutine<void>::call_type coro(
        [&](boost::coroutines::symmetric_coroutine<void>::yield_type& yield){
            X x;
            std::cout<<"fn()"<<std::endl;
            // transfer execution control to other coroutine
            yield( other_coro, 7);
        });

    coro();

    std::cout<<"coro is complete: "<<std::boolalpha<<!coro<<"\n";
}

output:
    X()
    fn()
    coro is complete: false
    ~X()
退出 协程函数

协程函数 通过一个简单的 return 语句退出. 这会跳回对称协程链起始处的 symmetric_coroutine<>::call_type::operator(). 也就是说, 对称协程不像非对称协程那样与调用方有强而固定的关系. symmetric_coroutine<>::call_type 即成为完成状态, 例如 symmetric_coroutine<>::call_type::operator bool 将返回 false.

重要

从 协程函数 返回后, coroutine 即为完成状态 (不能再以 symmetric_coroutine<>::call_type::operator() 恢复执行).
