在 Boost Preprocessor 库的正常使用中, 数据以离散单元的形式作为参数传给宏, 使每个参数对应单一的数据类型. 一个典型的宏可能是:

#define AMACRO(anumber,atuple,anidentifier) someoutput

其中形式为 ( data1, data2, data3 ) 的 'atuple' 本身可以包含不同数据类型的元素.

这是标准的宏设计, 在内部也是来回传递宏数据最简单的方式. Boost PP 库拥有一整套丰富的功能来处理其所有高级数据类型, 而变参数据以其自身较简单的功能, 也提供了表示数据的另一种选择.

宏的设计者 (尤其是为特定库中其他程序员的使用而设计时) 有时会表达这样的需求: 希望某个宏参数允许更接近 C/C++ 的语法, 让单个参数可以模仿 C++ 函数调用, 或 C 风格的类型修饰语法, 或其他更复杂的构造. 大致类似于:

areturn afunction ( aparameter1, aparameter2, aparameter3 )

或者

( type ) data

等等, 诸如此类.

换句话说, 从语法层面设计可能的宏输入时, 是否可以让参数数据在库中使用宏时看起来更像 C/C++, 同时仍能用这种混合记号输入进行一定程度的预处理元编程?

VMD 的功能允许不止一种类型的预处理记号 ( 'empty' 记号除外, 它始终指代某个完整输入) 成为单个输入数据参数的一部分. 这些作为单个参数的预处理记号在语法上是一段连续的数据, 可以以空格分隔并作为一个参数. 当连续的记号是 VMD 标识符时, 需要用空格分隔预处理数据. 这段连续数据的限制是: 该数据的每个顶级部分都必须是某种 VMD 数据类型. 此外, 如果你使用通用宏解析序列, 那么任何作为标识符的顶级 VMD 类型都必须是特定标识符, 意思是它必须是已经注册过的标识符.

VMD 序列功能的含义是: 如果某个输入由一系列数据类型组成, 就可以提取该系列中每种数据类型的数据.

实际上这意味着, 给定上面的示例, 如果 'areturn', 'afunction' 和 'data' 是特定标识符, 就可以解析上面两个输入中的任何一个, 从而识别其中涉及的不同数据类型, 并基于这些结果进行预处理元编程.

序列的定义

我将把这种由一系列顶级数据类型组成的输入数据称为"序列" (sequence). 序列中每个独立的数据类型称为一个"元素" (element). 按照这种"序列"定义, 我们可以拥有 0 个或多个元素, 因此序列是任何 VMD 输入的总称. 因此, 序列是 VMD 能解析的任何输入, 无论它是空, 单个元素, 还是系列中的多个元素. 因此, 当我们说 VMD 宏以通用方式解析输入数据时, 实际上说的就是 VMD 宏解析一个序列. 因此, 序列也可以是 Boost PP 复合数据类型或变参数据的一部分, 只要要求, VMD 仍然可以解析这种嵌入的序列.

由 0 个元素组成的序列是空序列, 我们已经看到空可以用特定宏 BOOST_VMD_IS_EMPTY 来测试. 由单个元素组成的序列可以使用各种测试"特定" VMD 数据类型的识别宏来测试. 但无论序列由 0 个元素, 一个元素还是多于一个元素组成, 我们还可以使用"通用"宏 (将在下文进一步说明) 来解析序列.

序列的解析

解析序列意味着 VMD 可以按顺序逐个遍历序列的每个元素, 确定每个元素的类型和数据, 然后移动到下一个元素. 解析是顺序进行的, 只能向前进行, 但可以进行任意次数. 用 C++ 迭代器的术语来说, 序列的解析模拟了一个前向迭代器.

处理序列等价于以"通用"方式使用 VMD 宏, 而此前我们文档说明的是使用测试各类 VMD 数据的识别宏来"特定地"使用 VMD 宏.

在我解释如何使用 VMD 通用功能处理序列之前, 我想说明两点:

  • 处理包含多种数据类型的序列的可能性很容易被滥用. 一般来说, 就计算机语言的语法层面而言, 保持简单通常比把事情搞得过于复杂更好. 宏参数的语法可能性必须易于理解才能被使用.
  • 使用 VMD 解析序列中的各个数据类型, 比使用 Boost PP 数据类型提供的功能花费更多预处理时间, 因为它基于对序列各顶级类型的前向访问.

序列的约束是: 顶级必须由 VMD 数据类型 (即 VMD 能理解的预处理记号) 组成, 并且在以通用方式解析序列时, 所有顶级 VMD 标识符都必须是特定标识符. 顶级的意思是, 一个 Boost PP 复合数据可以含有 VMD 无法解析的元素, 但只要输入由复合数据类型组成, 而不是内部的不可解析元素, VMD 就可以解析该输入. 因此, 如果预处理数据是上面的示例之一, 你就能成功使用 VMD. 然而, 如果你的预处理数据形如:

&name identifier ( param )

或者

identifier "string literal"

或者

identifier + number

或者

identifier += 4.3

等等, 诸如此类.

你将无法使用 VMD 解析该数据, 因为 '&', "string literal", '+', '+=', 和 "4.3" 是不属于 VMD 顶级数据类型的预处理记号, 因此 VMD 无法在解析层面处理它们. 当然, 你仍然可以把这样的数据作为预处理输入传给宏, 但不能用 VMD 识别这种数据的各个部分.

这类似于如下事实: 如果预处理数据的整体类型不是 VMD 能处理的类型, VMD 无法使用前面讨论过的任何识别宏告诉你该预处理数据的类型.

另一方面, 如果你把 Boost PP 数据类型用作顶级数据类型, 仍然可以使用 VMD 解析输入中的这类记号. 例如:

( &name ) identifier ( param )

或者

identifier ( "string literal" )

或者

identifier ( + ) number

或者

identifier ( += ) 4 ( . ) 3

后续主题将解释 VMD 解析序列中每个 VMD 数据类型的功能.

序列的类型

VMD 序列可以被视为三种一般类型之一:

  1. 空序列
  2. 单元素序列
  3. 多元素序列

空序列就是为空的输入, 即 VMD 所称的"空". 使用前面解释过的识别宏 BOOST_VMD_IS_EMPTY 来测试序列是否为空序列.

#include <boost/vmd/is_empty.hpp>

#define AN_EMPTY_SEQUENCE
#define A_NON_EMPTY_SEQUENCE 23 ( some_identifier )

BOOST_VMD_IS_EMPTY(AN_EMPTY_SEQUENCE) will return 1
BOOST_VMD_IS_EMPTY(A_NON_EMPTY_SEQUENCE) will return 0

空序列的类型是 BOOST_VMD_TYPE_EMPTY. 当顶级标识符不是特定标识符时, 你也可以测试序列是否为空序列, 宏会正确返回 0. 这是因为前面已经说明过的 BOOST_VMD_IS_EMPTY 实际上是一个识别宏, 它也可以用来解析任何序列并判断是否为空.

单元素序列是单个 VMD 数据类型. 这就是本文档中我们一直在讨论的、VMD 可以用识别宏解析的数据. 你可以使用通用宏 BOOST_VMD_IS_UNARY 来测试序列是否是单元素序列.

#include <boost/vmd/is_unary.hpp>

#define AN_EMPTY_SEQUENCE
#define A_SINGLE_ELEMENT_SEQUENCE (1,2)
#define NOT_A_SINGLE_ELEMENT_SEQUENCE (1,2) (45)(name)

BOOST_VMD_IS_UNARY(A_SINGLE_ELEMENT_SEQUENCE) will return 1
BOOST_VMD_IS_UNARY(AN_EMPTY_SEQUENCE) will return 0
BOOST_VMD_IS_UNARY(NOT_A_SINGLE_ELEMENT_SEQUENCE) will return 0

单元素序列的类型就是该独立数据类型的类型. 在上面的示例中, A_SINGLE_ELEMENT_SEQUENCE 的类型是 BOOST_VMD_TYPE_TUPLE.

多元素序列由多于一个数据类型组成. 这是 VMD 可以解析的"新"类型. 你可以使用 BOOST_VMD_IS_MULTI 宏来测试多元素序列.

#define AN_EMPTY_SEQUENCE
#define A_SINGLE_ELEMENT_SEQUENCE (1,2)
#define A_MULTI_ELEMENT_SEQUENCE (1,2) (1)(2) 45

A_MULTI_ELEMENT_SEQUENCE 由一个元组后跟一个 seq 再后跟一个数组成.

#include <boost/vmd/is_multi.hpp>

BOOST_VMD_IS_MULTI(A_MULTI_ELEMENT_SEQUENCE) will return 1
BOOST_VMD_IS_MULTI(AN_EMPTY_SEQUENCE) will return 0
BOOST_VMD_IS_MULTI(A_SINGLE_ELEMENT_SEQUENCE) will return 0

多元素序列的类型总是 BOOST_VMD_TYPE_SEQUENCE.

任何序列的类型都可以用 BOOST_VMD_GET_TYPE 宏获得. 我们将在文档中进一步说明这一点.

序列的大小

任何序列的大小都可以使用 BOOST_VMD_SIZE 宏访问. 空序列的大小总是 0. 单元素序列的大小总是 1. 多元素序列的大小是序列中独立顶级数据类型的数量.

#include <boost/vmd/size.hpp>

#define AN_EMPTY_SEQUENCE
#define A_SINGLE_ELEMENT_SEQUENCE (1,2)
#define A_MULTI_ELEMENT_SEQUENCE (1,2) (1)(2) 45

BOOST_VMD_SIZE(AN_EMPTY_SEQUENCE) will return 0
BOOST_VMD_SIZE(A_SINGLE_ELEMENT_SEQUENCE) will return 1
BOOST_VMD_SIZE(A_MULTI_ELEMENT_SEQUENCE) will return 3
区分序列中连续的 seq 和元组

前面已经提到, 单元素元组同时也是单元素 seq, 因此解析含有 seq 和元组的序列时, 识别序列的每个元素可能是个问题. 在多元素序列中, 如果数据由连续混合的 seq 和元组组成, 我们需要区分 VMD 如何解析这些数据. 规则是: VMD 总是把单元素元组解析为元组, 除非它后面跟着一个或多个单元素元组, 此时它是一个 seq. 下面是一些展示该规则如何应用的示例.

#define ST_DATA (somedata)(element1,element2)

VMD 把上面的数据解析为 2 个连续的元组. 第一个元组是单元素元组 '(somedata)', 第二个元组是多元素元组 '(element1,element2)'.

#define ST_DATA (element1,element2)(somedata)

VMD 把上面的数据解析为 2 个连续的元组. 第一个元组是多元素元组 '(element1,element2)', 第二个元组是单元素元组 '(somedata)'.

#define ST_DATA (somedata)(some_other_data)(element1,element2)

VMD 把上面的数据解析为一个 seq 后跟一个元组. 该 seq 是 '(somedata) (some_other_data)', 该元组是 '(element1,element2)'.

使用 VMD 解析序列输入

对于 VMD 序列, VMD 库提供了两种解析成独立数据类型的方式:

  1. 可以把序列转换为任何 Boost PP 数据类型, 或转换为变参数据, 此时序列中的每个独立数据类型成为所选特定复合数据类型的独立元素. 转换为特定 Boost PP 数据类型或变参数据较慢, 因为它基于对序列各顶级类型的前向访问, 但之后的任何独立元素访问, 其速度与访问 Boost PP 数据类型或变参数据中的任何元素一样快.
  2. 可以通过序列的独立元素直接访问序列. 这比访问 Boost PP 数据类型或变参数据的元素要慢, 但提供了把原始序列当作一系列元素来访问的概念方式.

这两种技术将在后续主题中讨论.

转换序列

处理序列最简单的方式是把它转换为 Boost PP 数据类型. 同样, 你也可以把序列转换为变参数据, 尽管 Boost PP 数据类型在 Boost PP 中拥有的功能远多于变参数据.

要把序列转换为 Boost PP 数据类型或变参数据, 使用的宏是:

  • BOOST_VMD_TO_ARRAY(sequence), 把序列转换为数组
  • BOOST_VMD_TO_LIST(sequence), 把序列转换为列表
  • BOOST_VMD_TO_SEQ(sequence), 把序列转换为 seq
  • BOOST_VMD_TO_TUPLE(sequence), 把序列转换为元组
  • BOOST_VMD_ENUM(sequence), 把序列转换为变参数据

转换之后, 序列的元素成为对应复合数据类型的元素.

一旦序列的元素被转换为复合数据类型的元素, 就可以使用该复合数据类型的全部能力来处理每个元素. 此外, 程序员可以使用 VMD 发现单个元素的类型以做进一步处理.

对于单元素序列, 结果总是单元素的复合数据类型. 对于多元素序列, 结果总是多于一个元素的复合数据类型.

对于空序列, 转换为 seq, 元组或变参数据时结果为空; 转换为数组或列表时, 结果分别为空数组或空列表.

#include <boost/vmd/enum.hpp>
#include <boost/vmd/to_array.hpp>
#include <boost/vmd/to_list.hpp>
#include <boost/vmd/to_seq.hpp>
#include <boost/vmd/to_tuple.hpp>

#define BOOST_VMD_REGISTER_ANID (ANID)

#define SEQUENCE_EMPTY
#define SEQUENCE_SINGLE 35
#define SEQUENCE_SINGLE_2 ANID
#define SEQUENCE_MULTI (0,1) (2)(3)(4)
#define SEQUENCE_MULTI_2 BOOST_VMD_TYPE_SEQ (2,(5,6))

BOOST_VMD_TO_ARRAY(SEQUENCE_EMPTY) will return an empty array '(0,())'
BOOST_VMD_TO_LIST(SEQUENCE_SINGLE) will return a one-element list '(35,BOOST_PP_NIL)'
BOOST_VMD_TO_SEQ(SEQUENCE_SINGLE_2) will return a one-element seq '(ANID)'
BOOST_VMD_TO_TUPLE(SEQUENCE_MULTI) will return a multi-element tuple '((0,1),(2)(3)(4))'
BOOST_VMD_ENUM(SEQUENCE_MULTI_2) will return multi-element variadic data 'BOOST_VMD_TYPE_SEQ,(2,(5,6))'
用法

你可以使用通用头文件:

#include <boost/vmd/vmd.hpp>

或者你也可以为这些宏使用各自的独立头文件. 这些独立头文件是:

#include <boost/vmd/to_array.hpp> //  for the BOOST_VMD_TO_ARRAY macro
#include <boost/vmd/to_list.hpp> //  for the BOOST_VMD_TO_LIST macro
#include <boost/vmd/to_seq.hpp> //  for the BOOST_VMD_TO_SEQ macro
#include <boost/vmd/to_tuple.hpp> // for the BOOST_VMD_TO_TUPLE macro.
#include <boost/vmd/enum.hpp> // for the BOOST_VMD_ENUM macro.
访问序列元素

可以访问序列的单个元素. 实现这一目的的宏名为 BOOST_VMD_ELEM. 该宏接受两个必需参数: 要访问的元素编号和序列, 按此顺序. 元素编号是从 0 开始的编号, 其最大值应当比序列的大小小 1.

BOOST_VMD_ELEM 宏返回实际的序列元素. 如果第一个必需参数大于或等于序列的大小, 宏返回空. 因此, 对空序列 (其大小为 0) 使用 BOOST_VMD_ELEM 总是返回空.

#include <boost/vmd/elem.hpp>

#define BOOST_VMD_REGISTER_ANAME (ANAME)
#define A_SEQUENCE (1,2,3) 46 (list_data1,(list_data2,BOOST_PP_NIL)) BOOST_VMD_TYPE_SEQ ANAME
#define AN_EMPTY_SEQUENCE

BOOST_VMD_ELEM(0,A_SEQUENCE) will return (1,2,3)
BOOST_VMD_ELEM(1,A_SEQUENCE) will return 46
BOOST_VMD_ELEM(2,A_SEQUENCE) will return (list_data1,(list_data2,BOOST_PP_NIL))
BOOST_VMD_ELEM(3,A_SEQUENCE) will return BOOST_VMD_TYPE_SEQ
BOOST_VMD_ELEM(4,A_SEQUENCE) will return ANAME

BOOST_VMD_ELEM(5,A_SEQUENCE) will return emptiness
BOOST_VMD_ELEM(0,AN_EMPTY_SEQUENCE) will return emptiness

直接访问序列的元素比访问 Boost PP 数据类型甚至变参数据的元素要慢, 因为每次访问都必须直接遍历序列的每个元素才能到达被访问的那个. 每次都要重新顺序解析每个元素的过程, 比访问 Boost PP 数据类型元素要慢.

用法

你可以使用通用头文件:

#include <boost/vmd/vmd.hpp>

或者你也可以使用独立头文件:

#include <boost/vmd/elem.hpp>
