用于"空" seq 和元组的功能

Boost PP 的数组和列表可以为空, 但 seq 和元组不能. 空数组的形式是 '(0,())', 空列表的形式是 'BOOST_PP_NIL'. 但 '()' 的形式并不表示空 seq 或空元组. 对于 seq, 它表示一个数据为空的单元素 seq; 对于元组, 它表示一个大小为 1 且单个元素为空的元组.

没有表示空 seq 或空元组的方法, 对 Boost PP 用户来说是一个小问题. 尤其对元组而言, 在支持变参宏时, 无法为"空"是最终用户可能更愿意使用数组而不是元组作为 Boost PP 预处理数据的唯一原因. 否则, 在使用变参宏时, 使用元组比使用数组更容易标注和后续使用, 因为不需要费力指定元组的元素数量.

正如我们看到的, VMD 通过其 BOOST_VMD_IS_EMPTY 宏能够判断预处理数据何时为"空". 因此, 当空应用于 seq 或元组时, 可以把它分别视为空 seq 或空元组, 从而让 seq 和元组可以为空, 就像数组和列表那样.

然而, 把空视为空 seq 或空元组存在一个大问题: Boost PP 中针对 seq 或元组的功能对此一无所知. 换句话说, 如果你把空传递给一个期望 seq 或元组的 Boost PP 宏, 例如:

BOOST_PP_SEQ_SIZE()

或者

BOOST_PP_TUPLE_PUSH_BACK(,1)

你会得到 UB (未定义行为).

为了使用可以为空的 seq 和元组, VMD 定义了许多模仿 Boost PP 中宏的宏, 但它们以 BOOST_VMD_ 开头而不是 BOOST_PP_. VMD 宏处理我将称之为 'VMD seq' 或 'VMD tuple' 的东西, 而 Boost PP 的等效宏处理传统的 seq 或元组. VMD seq 是可以为空的 seq, VMD 元组是可以为空的元组. 因此 VMD seq 是普通 seq 的超集, VMD 元组是普通元组的超集. 因此 VMD 功能可以接受 VMD seq 或元组, 也可以接受普通 seq 或元组, 而 Boost PP 的等效功能只接受普通 seq 或元组. 更准确地说, 只要 VMD seq 或 VMD 元组不为空, Boost PP 功能也可以接受它们. 换句话说, 非空 VMD seq 与 Boost PP seq 之间, 或非空 VMD 元组与 Boost PP 元组之间没有区别.

VMD 提供的、支持 VMD seq 和 VMD 元组的特定宏, 分为数组, 列表, seq 和元组功能. 这些宏的实际头文件位于 VMD 目录的子目录中, 分别以 'array', 'list', 'seq' 和 'tuple' 开头. 这些头文件也都包含在通用头文件 boost/vmd/vmd.hpp 中.

seq 与元组功能

处理 VMD seq 和 VMD 元组的 seq 与元组功能宏集合, 在很大程度上只是 Boost PP 中 seq 与元组功能的一个子集. 这反映出这样一个事实: Boost PP 中许多处理 seq 或元组的宏, 在扩展为处理可能为空的 seq 或空元组时没有意义. 例如, 向 BOOST_PP_SEQ_FIRST_N 传递空 seq 时它不可能有任何含义, 向 BOOST_PP_TUPLE_REM_CTOR 传递空元组时它也不可能有任何含义. 没有获得 VMD 等效形式的其他 Boost PP seq 和元组宏也是如此.

VMD 中处理可能为空的 seq 或空元组的功能集合, 使得在 seq 或元组可能一开始或最终为空的情况下添加或移除元素成为可能, 可以在 seq 或元组为空时获取其大小, 可以在数组, 列表, seq 或元组之间进行可能为空的相互转换, 还可以测试 VMD seq 或 VMD 元组. 这些功能应当让宏程序员能够在处理空 seq 和元组的同时, 继续使用其他 Boost PP seq 和元组功能来处理非空 seq 和元组. 做到这一点最简单的方式是: 在 VMD 与 Boost PP 之间选择时使用 VMD seq 和 VMD 元组的等效函数, 其他情况则使用 Boost PP 的 seq 和元组功能. 只需记住, Boost PP 的 seq 和元组功能永远不能处理空 seq 或空元组.
