生成空与原样

使用 BOOST_PP_EMPTY 和 BOOST_PP_IDENTITY

Boost PP 有一个名为 BOOST_PP_EMPTY() 的宏, 它展开为空.

通常这看起来没什么用, 但在想要返回特定值、同时需要一个不接受参数的进一步宏调用语法的情况下, 该宏可以派上用场. 这种用处出现在 Boost PP 中根据 BOOST_PP_IF 或 BOOST_PP_IIF 逻辑的结果需要选择两条路径的时候. 下面是一个人为构造的示例:

#include <boost/preprocessor/control/iif.hpp>
#include <boost/preprocessor/facilities/empty.hpp>

#define MACRO_CHOICE(parameter) \
    BOOST_PP_IIF(parameter) \
        ( \
        MACRO_CALL_IF_PARAMETER_1, \
        SOME_FIXED_VALUE BOOST_PP_EMPTY \
        ) \
    ()

#define MACRO_CALL_IF_PARAMETER_1() some_processing

上面的总体逻辑是: 如果参数为 1 则调用另一个宏, 而如果参数为 0 则返回某个固定值. 这么做有用的原因在于, 人们可能不想把 MACRO_CHOICE 宏写成这样:

#include <boost/preprocessor/control/iif.hpp>

#define MACRO_CHOICE(parameter) \
    BOOST_PP_IIF(parameter) \
        ( \
        MACRO_CALL_IF_PARAMETER_1(), \
        SOME_FIXED_VALUE \
        )

#define MACRO_CALL_IF_PARAMETER_1() some_processing

因为那样做效率低下. 即使 'parameter' 为 0, MACRO_CALL_IF_PARAMETER_1 的调用仍会被生成.

这种借助 BOOST_PP_EMPTY 返回固定值的惯用法非常有用, 以至于 Boost PP 为 BOOST_PP_EMPTY 配备了一个配套宏. 该配套宏是 BOOST_PP_IDENTITY(value)(). 本质上, BOOST_PP_IDENTITY 在被调用时返回其值. 同样, 与 BOOST_PP_EMPTY 一样, 最后一次调用必须不带值.

我们上面最初使用 BOOST_PP_EMPTY 返回固定值的示例, 现在变成:

#include <boost/preprocessor/control/iif.hpp>
#include <boost/preprocessor/facilities/identity.hpp>

#define MACRO_CHOICE(parameter) \
    BOOST_PP_IIF(parameter) \
        ( \
        MACRO_CALL_IF_PARAMETER_1, \
        BOOST_PP_IDENTITY(SOME_FIXED_VALUE) \
        ) \
    ()

#define MACRO_CALL_IF_PARAMETER_1() some_processing

宏 BOOST_PP_IDENTITY 实际上只是:

#define BOOST_PP_IDENTITY(value) value BOOST_PP_EMPTY

因此可以看到, 它本质上是开头所示常见情形 (借助 BOOST_PP_EMPTY 返回值) 的一种简写.

使用 BOOST_VMD_EMPTY 和 BOOST_VMD_IDENTITY

使用 BOOST_PP_EMPTY 和 BOOST_PP_IDENTITY 的一个问题在于, 最后一次调用必须不带参数. 这是很大的限制. 如果最后一次调用必须带一个或多个参数, 就不能使用 BOOST_PP_EMPTY 或 BOOST_PP_IDENTITY. 换句话说, 对我们两个示例中的任何一个做如下改动:

#include <boost/preprocessor/control/iif.hpp>
#include <boost/preprocessor/facilities/empty.hpp>

#define MACRO_CHOICE(parameter1,parameter2) \
    BOOST_PP_IIF(parameter1) \
        ( \
        MACRO_CALL_IF_PARAMETER_1, \
        SOME_FIXED_VALUE BOOST_PP_EMPTY \
        ) \
    (parameter2)

#define MACRO_CALL_IF_PARAMETER_1(parameter2) some_processing_using_a_parameter

或者

#include <boost/preprocessor/control/iif.hpp>
#include <boost/preprocessor/facilities/identity.hpp>

#define MACRO_CHOICE(parameter1,parameter2) \
    BOOST_PP_IIF(parameter1) \
        ( \
        MACRO_CALL_IF_PARAMETER_1, \
        BOOST_PP_IDENTITY(SOME_FIXED_VALUE) \
        ) \
    (parameter2)

#define MACRO_CALL_IF_PARAMETER_1(parameter2) some_processing_using_a_parameter

都会产生预处理错误, 因为对 BOOST_PP_EMPTY 或 BOOST_PP_IDENTITY 的最后一次调用不能带 1 个或多个参数.

如果最后一次调用可以带任意数量的参数, 那就有用得多了. 这正是使用变参宏解决问题的地方. BOOST_VMD_EMPTY 和 BOOST_VMD_IDENTITY 宏与它们在 Boost PP 中的对应宏具有完全相同的功能, 但最后一次调用可以带任意数量的参数, 并且当选择的是 BOOST_VMD_EMPTY 或 BOOST_VMD_IDENTITY 时, 这些参数会被直接忽略.

现在对于我们的两个示例, 我们可以有:

#include <boost/preprocessor/control/iif.hpp>
#include <boost/vmd/empty.hpp>

#define MACRO_CHOICE(parameter1,parameter2) \
    BOOST_PP_IIF(parameter1) \
        ( \
        MACRO_CALL_IF_PARAMETER_1, \
        SOME_FIXED_VALUE BOOST_VMD_EMPTY \
        ) \
    (parameter2)

#define MACRO_CALL_IF_PARAMETER_1(parameter2) some_processing_using_parameters

或者

#include <boost/preprocessor/control/iif.hpp>
#include <boost/vmd/identity.hpp>

#define MACRO_CHOICE(parameter1,parameter2) \
    BOOST_PP_IIF(parameter1) \
        ( \
        MACRO_CALL_IF_PARAMETER_1, \
        BOOST_VMD_IDENTITY(SOME_FIXED_VALUE) \
        ) \
    (parameter2)

#define MACRO_CALL_IF_PARAMETER_1(parameter2) some_processing_using_parameters

我们的宏将顺利编译, 没有预处理错误, 并按预期工作. BOOST_VMD_EMPTY 和 BOOST_VMD_IDENTITY 在调用时都接受任意数量的参数, 这使它们无论传递什么都可以作为最后一次调用使用.

BOOST_VMD_EMPTY 和 BOOST_VMD_IDENTITY 的用法

要使用 BOOST_VMD_EMPTY 宏, 要么包含通用头文件:

#include <boost/vmd/vmd.hpp>

要么包含特定头文件:

#include <boost/vmd/empty.hpp>

要使用 BOOST_VMD_IDENTITY 宏, 要么包含通用头文件:

#include <boost/vmd/vmd.hpp>

要么包含特定头文件:

#include <boost/vmd/identity.hpp>
在 VC++ 中使用 BOOST_VMD_EMPTY 和 BOOST_VMD_IDENTITY

不幸的是, Visual C++ 默认预处理器在"一个宏展开为某些内容后跟一个展开为空的变参宏"的情况下有问题. 在某些非空展开之后使用 BOOST_VMD_EMPTY, 或者等效地使用 BOOST_VMD_IDENTITY, 就是这种情况. 听起来很奇怪, 这个 VC++ 默认预处理器问题通常的解决办法是使用 BOOST_PP_CAT 把结果与一个空值拼接. 不过话说回来, VC++ 带默认预处理器时的许多非标准行为都难以理解, 甚至难以追踪.

为了让这种技术在符合 C++ 标准的预处理器和 VC++ 非标准默认预处理器下都能透明使用, 你可以使用 BOOST_VMD_IDENTITY_RESULT 宏, 向它传递单个参数, 即由使用 BOOST_VMD_IDENTITY 的宏 (或其等效的 'value BOOST_VMD_EMPTY' 用法) 返回的结果.

给定上面的 MACRO_CHOICE 示例, 如果你有另一个调用 MACRO_CHOICE 的宏, 只需把该调用放入 BOOST_VMD_IDENTITY_RESULT 中. 如下面这个非常简单的例子:

#include <boost/vmd/identity.hpp>

#define CALLING_MACRO_CHOICE(parameter1,parameter2) \
    BOOST_VMD_IDENTITY_RESULT(MACRO_CHOICE(parameter1,parameter2))

或者, 你可以修改 MACRO_CHOICE, 使其实现和用法变为:

#include <boost/preprocessor/control/iif.hpp>
#include <boost/vmd/identity.hpp>

#define MACRO_CHOICE(parameter1,parameter2) \
    BOOST_VMD_IDENTITY_RESULT \
        ( \
        BOOST_PP_IIF(parameter1) \
            ( \
            MACRO_CALL_IF_PARAMETER_1, \
            BOOST_VMD_IDENTITY(SOME_FIXED_VALUE) \
            ) \
        (parameter2) \
        )

#define CALLING_MACRO_CHOICE(parameter1,parameter2) \
    MACRO_CHOICE(parameter1,parameter2)

以这种方式使用 BOOST_VMD_EMPTY 和 BOOST_VMD_IDENTITY, 可以确保它们无论在带默认预处理器的 VC++ 还是在任何符合 C++ 标准的预处理器下使用时都不会出现预处理问题.

BOOST_VMD_IDENTITY_RESULT 的用法

宏 BOOST_VMD_IDENTITY_RESULT 与 BOOST_VMD_IDENTITY 位于同一个头文件中, 因此要使用 BOOST_VMD_IDENTITY_RESULT 宏, 要么包含通用头文件:

#include <boost/vmd/vmd.hpp>

要么包含特定头文件:

#include <boost/vmd/identity.hpp>
