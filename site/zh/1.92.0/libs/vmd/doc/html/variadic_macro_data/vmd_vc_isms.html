VMD 中的 Visual C++ 陷阱

在整篇文档中, 我已经讨论了在使用带默认预处理器的微软 Visual C++ 编译器时需要考虑的 VMD 相关领域. VMD 库支持 VC++ 8 到最新的 14.2 各版本. 它们对应于 Visual Studio 2005 到当前的 Visual Studio 2019.

我在这里将比较简略地给出使用 VMD 时应当考虑的 VC++ 怪癖. 这些怪癖的存在是因为 VC++ 编译器的默认预处理器并不是符合 C++ 标准的预处理器. 更具体地说, VC++ 编译器在调用宏时没有正确遵循展开宏的全部规则. 以下是在 VC++ 及其默认预处理器下使用 VMD 时需要考虑的事项清单:

  • 如果输入解析为一个类函数宏的名字, 且该宏在以空参数调用时会展开为一个元组, BOOST_VMD_IS_EMPTY 宏会错误地展开为 1.
  • BOOST_VMD_ASSERT 宏以及针对各种数据类型的相应 VMD ASSERT 宏不会立即引起编译器错误, 而是在断言发生时生成无效的 C++.
  • 当 BOOST_VMD_ASSERT 宏或某个针对各种数据类型的相应 VMD ASSERT 宏没有产生错误, 而使用它的宏确实会产生一些输出时, 需要使用 BOOST_PP_CAT 把 VMD ASSERT 宏的空结果与正常生成的输出拼接起来, 以正确生成发生 VMD ASSERT 的宏的最终展开.
  • 在某些非空展开之后使用 BOOST_VMD_EMPTY, 或者使用 BOOST_VMD_IDENTITY 时, 需要使用 BOOST_PP_CAT 把返回的值与一个空值拼接. 你可以使用 BOOST_VMD_IDENTITY_RESULT 透明地完成这一点.
  • 如果 VC++8 可能被用作编译器, 请避免使用空括号来传递作为元组或 seq 的空数据.

使用 VC++ 新的符合标准的预处理器时 (截至目前它还不是 Visual Studio 2019 的默认预处理器), 这些问题都不会出现.
