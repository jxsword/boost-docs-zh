Boost PP 之外有用的变参宏

断言与数据类型
生成空与原样
用于"空" seq 和元组的功能

本文档前面的章节已经解释了如何使用 VMD 解析 VMD 数据类型, 以及识别空.

VMD 的另一个功能领域涉及有用的变参宏, 它们基于前面的功能, 扩展了 Boost PP 中已有的类似宏. 这些变参宏可以按以下展示这些行为领域的章节划分:

  1. 扩展的断言宏
  2. 扩展的原样 (identity) 功能
  3. 针对"空" seq 和元组的扩展 seq 与元组功能

文档接下来将给出上述各项的小节.

断言与数据类型

当宏逻辑可以根据传递给宏参数的数据类型选择不同路径时, 用于识别数据类型的 VMD 宏效果最好. 但偶尔预处理元程序员只想验证宏参数数据属于正确的数据类型, 否则应当产生预处理错误, 通知调用该宏的程序员所传递的数据类型不正确.

使用 BOOST_VMD_ASSERT

Boost PP 库有一个宏, 当传给它的条件为 0 时会产生预处理错误. 该宏名为 BOOST_PP_ASSERT. 该宏通过强制调用一个参数数量错误的内部宏来产生预处理错误. 根据 C++ 标准, 对于符合标准的编译器, 这应当总是立即产生预处理错误.

不幸的是, 带默认预处理器的 VC++ 在向宏传递错误数量的参数时只会产生警告. 因此, 使用带默认预处理器的 VC++, BOOST_PP_ASSERT 宏不会产生预处理错误. 令人惊讶的是, 似乎没有其他办法可以通过调用宏迫使带默认预处理器的 VC++ 发出预处理错误 (如果你找到了, 请告诉我). 不过, 可以让宏调用产生无效的 C++ 作为输出, 当 VC++ 编译器稍后遇到该构造时, 会使 VC++ 产生编译器错误.

这正是 BOOST_VMD_ASSERT 宏所做的事情. 它接受与 BOOST_PP_ASSERT 相同的条件参数, 在没有与带默认预处理器的 VC++ 一起使用时它会调用 BOOST_PP_ASSERT; 否则, 当与带默认预处理器的 VC++ 一起使用且条件为 0 时, 它通过生成无效的 C++ 来产生编译器错误. 该编译器错误通过生成如下形式的无效 C++ 产生:

typedef char BOOST_VMD_ASSERT_ERROR[-1];

通过向 BOOST_VMD_ASSERT 传递第二个可选参数 (其形式是一个预处理标识符), 如果第一个参数为 0, 可以为带默认预处理器的 VC++ 生成如下形式的无效 C++:

typedef char optional_argument[-1];

以此代替. 如果需要, 这可以让所产生的 C++ 错误更清晰一些.

如果第一个条件参数不为 0, BOOST_VMD_ASSERT 不产生任何输出.

BOOST_VMD_ASSERT 用法

要使用 BOOST_VMD_ASSERT 宏, 要么包含通用头文件:

#include <boost/vmd/vmd.hpp>

要么包含特定头文件:

#include <boost/vmd/assert.hpp>
针对数据类型的断言

各种数据类型都有自己的断言宏. 它们大多只是把识别宏的结果传给 BOOST_VMD_ASSERT 的快捷方式. 这些断言宏是:

  • 空, BOOST_VMD_ASSERT_IS_EMPTY
  • 标识符, BOOST_VMD_ASSERT_IS_IDENTIFIER
  • 数, BOOST_VMD_ASSERT_IS_NUMBER
  • 数组, BOOST_VMD_ASSERT_IS_ARRAY
  • 列表, BOOST_VMD_ASSERT_IS_LIST
  • seq, BOOST_VMD_ASSERT_IS_SEQ
  • 元组, BOOST_VMD_ASSERT_IS_TUPLE
  • 类型, BOOST_VMD_ASSERT_IS_TYPE

这些宏各自接受的参数与其对应识别宏的参数完全相同. 但它们不是返回非 0 或 0, 而是在输入类型不正确时产生编译器错误.

这些宏只有在宏 BOOST_VMD_ASSERT_DATA 被设为 1 时才检查其断言. 默认情况下 BOOST_VMD_ASSERT_DATA 只在编译器调试模式下被设为 1. 程序员如果愿意, 可以在使用数据类型断言宏之前手动将 BOOST_VMD_ASSERT_DATA 设为 1.

BOOST_VMD_ASSERT_... 用法

要使用各个 BOOST_VMD_ASSERT_... 宏, 要么包含通用头文件:

#include <boost/vmd/vmd.hpp>

要么包含特定头文件:

#include <boost/vmd/assert_is_empty.hpp> // BOOST_VMD_ASSERT_IS_EMPTY
#include <boost/vmd/assert_is_identifier.hpp> // BOOST_VMD_ASSERT_IS_IDENTIFIER
#include <boost/vmd/assert_is_number.hpp> // BOOST_VMD_ASSERT_IS_NUMBER
#include <boost/vmd/assert_is_array.hpp> // BOOST_VMD_ASSERT_IS_ARRAY
#include <boost/vmd/assert_is_list.hpp> // BOOST_VMD_ASSERT_IS_LIST
#include <boost/vmd/assert_is_seq.hpp> // BOOST_VMD_ASSERT_IS_SEQ
#include <boost/vmd/assert_is_tuple.hpp> // BOOST_VMD_ASSERT_IS_TUPLE
#include <boost/vmd/assert_is_type.hpp> // BOOST_VMD_ASSERT_IS_TYPE
断言与 VC++

带默认预处理器的 VC++ 编译器在处理 BOOST_VMD_ASSERT 和数据类型断言宏时有一个怪癖. 如果你在另一个通常会生成输出预处理记号的宏中调用某个断言宏, 那么使用带默认预处理器的 VC++ 时, 必须把断言宏的结果拼接 (concatenate) 到正在生成的其他预处理数据上, 即使断言宏没有产生错误.

举个简单的例子, 假设我们有一个期望元组的宏, 如果元组拥有多于 2 个元素则生成 1, 否则生成 0. 通常我们可以写成:

#include <boost/preprocessor/comparison/greater.hpp>
#include <boost/preprocessor/control/iif.hpp>
#include <boost/preprocessor/tuple/size.hpp>
#include <boost/vmd/assert_is_tuple.hpp>

#define AMACRO(atuple) \
    BOOST_VMD_ASSERT_IS_TUPLE(atuple) \
    BOOST_PP_IIF(BOOST_PP_GREATER(BOOST_PP_TUPLE_SIZE(atuple), 2),1,0)

但对于带默认预处理器的 VC++, 我们必须写成

#include <boost/preprocessor/cat.hpp>
#include <boost/preprocessor/comparison/greater.hpp>
#include <boost/preprocessor/control/iif.hpp>
#include <boost/preprocessor/tuple/size.hpp>
#include <boost/vmd/assert_is_tuple.hpp>

#define AMACRO(atuple) \
    BOOST_PP_CAT \
       ( \
       BOOST_VMD_ASSERT_IS_TUPLE(atuple), \
       BOOST_PP_IIF(BOOST_PP_GREATER(BOOST_PP_TUPLE_SIZE(atuple), 2),1,0) \
       )

带默认预处理器的 VC++ 在第一种写法下不能正确工作, 就编译器输出而言会错误地发生混乱. 但通过在第二种写法中使用 BOOST_PP_CAT, 带默认预处理器的 VC++ 可以正确地与 VMD 断言配合工作.
