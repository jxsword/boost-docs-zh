执行器

每个异步操作都有一个关联执行器, 决定完成处理器如何排队和运行. 异步操作使用关联执行器来跟踪异步任务的工作是否存在、调度完成处理器执行, 并防止完成处理器被重入执行, 以避免递归和潜在的栈溢出问题.

mqtt_client 中的每个异步操作都被定义为组合操作 (composed operation). 这意味着每个 async_xxx 操作都是一个序列, 由发起函数、一系列中间异步操作和最终完成处理器组成.

创建 mqtt_client 实例时, 必须提供一个执行器或一个 ExecutionContext. 指定的执行器 (或 ExecutionContext 的执行器) 将成为与 mqtt_client 关联的默认执行器, 用于执行所有未绑定执行器的异步操作的各个中间操作及最终完成处理器. 若某个异步操作绑定了执行器, 则改用该执行器执行其最终完成处理器.

以下示例将演示前文所述的交互方式.

示例: 将构造函数的执行器用作默认关联执行器

在此代码片段中, mqtt_client 以 strand 构造. 因此, mqtt_client 采用该 strand 作为其新的默认执行器, 用于执行 mqtt_client::async_publish 操作.

int main() {
    boost::asio::io_context ioc;

    // Construct the Client with a strand.
    auto strand = boost::asio::make_strand(ioc.get_executor());
    boost::mqtt5::mqtt_client<boost::asio::ip::tcp::socket> client(strand);

    client.brokers("<your-mqtt-broker>", 1883)
        .async_run(boost::asio::detached);

    // This asynchronous operation will use the default associated executor,
    // which is the strand with which the Client is constructed.
    client.async_publish<boost::mqtt5::qos_e::at_most_once>(
        "<topic>", "Hello world!",
        boost::mqtt5::retain_e::no, boost::mqtt5::publish_props {},
        [&client, &strand](boost::mqtt5::error_code /* ec */) {
            assert(strand.running_in_this_thread());
            client.cancel();
        }
    );

    ioc.run();
}
