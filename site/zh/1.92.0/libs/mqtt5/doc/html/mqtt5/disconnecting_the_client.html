断开客户端连接

mqtt_client 会一直保持活动, 直到它被销毁或被显式停止. 在空闲模式下, mqtt_client 会周期性地向代理服务器发送 PINGREQ 以维持稳定连接.

停止 mqtt_client 的正确方式是调用 mqtt_client::cancel 或 mqtt_client::async_disconnect. 调用 mqtt_client::cancel 会使 mqtt_client 关闭与代理服务器的连接并取消所有未完成的异步操作. 另一方面, mqtt_client::async_disconnect 会首先尝试向代理服务器发送 DISCONNECT 报文 [4] 以告知断开原因, 然后关闭连接并取消所有未完成的异步操作 (效果与 mqtt_client::cancel 相同).

重要

无论使用哪种方法停止 mqtt_client, 都建议确保之前所有异步操作已经完成. 否则, 它们 将被取消.

调用 mqtt_client::cancel 或 mqtt_client::async_disconnect 将带来干净且优雅的关闭过程. 这确保所有资源被正确释放, 所有异步操作被完成 [5]. 因此, 执行上下文 (boost::asio::io_context) 将因缺乏工作而停止.

注释

mqtt_client 的析构函数也会调用 mqtt_client::cancel.

以下代码片段将展示断开 mqtt_client 连接的场景及其与其他异步操作的交互.

示例: 立即断开及其对未完成异步操作的影响

以下代码片段示例展示了以 QoS 0 向代理服务器发布 “Hello World!” 消息, 随后请求断开 mqtt_client 的过程.

int main() {
    boost::asio::io_context ioc;

    boost::mqtt5::mqtt_client<boost::asio::ip::tcp::socket> client(ioc);
    client.brokers("<your-mqtt-broker>", 1883)
        .async_run(boost::asio::detached);

    client.async_publish<boost::mqtt5::qos_e::at_most_once>(
        "<topic>", "Hello world!",
        boost::mqtt5::retain_e::no, boost::mqtt5::publish_props {},
        [](boost::mqtt5::error_code ec) {
            std::cout << ec.message() << std::endl;
        }
    );

    client.async_disconnect(boost::asio::detached);

    ioc.run();
}

假设代理服务器可用且 mqtt_client 能够成功连接到它, 则将发生如下事件顺序:

  1. 客户端将成功建立与代理服务器的连接.
  2. 客户端将发送 DISCONNECT 报文, Reason Code 为 0x00 (Normal Disconnection).

值得注意的是, 包含 “Hello World!” 消息的 PUBLISH 报文将不会被传输. 正如 Packet Ordering (见 优化通信 一节) 中所述, mqtt_client::async_publish 与 mqtt_client::async_disconnect 会将其对应的报文放入队列. 但 DISCONNECT 报文优先级更高, 会独占地先于其他排队报文发送. 因此, 连接将立即终止.

若 mqtt_client 无法建立与代理服务器的连接, 它将在 5 seconds 后停止, 这正是它在退出前尝试向代理服务器发送 DISCONNECT 报文所花费的时间. 这一超时机制确保 mqtt_client 不会无限期等待断开, 从而节约资源并保持高效运行.

在这种情况下, 正确的断开方式是调用 mqtt_client::async_disconnect, 且应在 mqtt_client::async_publish 完成之后进行.

client.async_publish<boost::mqtt5::qos_e::at_most_once>(
    "<topic>", "Hello world!",
    boost::mqtt5::retain_e::no, boost::mqtt5::publish_props {},
    [&client](boost::mqtt5::error_code ec) {
        std::cout << ec.message() << std::endl;
        client.async_disconnect(boost::asio::detached);
    }
);

断开后重启客户端

mqtt_client 成功停止后, 重新激活它非常简单, 只需调用 mqtt_client::async_run. 该方法可以在发起 mqtt_client::async_disconnect 之后立即调用, 无需等待其完成.

在停止与重启之间的间隔期内, mqtt_client 可以重新配置. 更多信息请参见 配置 MQTT 连接.

int main() {
    boost::asio::io_context ioc;

    boost::mqtt5::mqtt_client<boost::asio::ip::tcp::socket> client(ioc);
    client.brokers("<your-mqtt-broker>", 1883)
        .async_run(boost::asio::detached);

    client.async_disconnect(boost::asio::detached);

    // The Client can be reconfigured again.
    client.connect_property(boost::mqtt5::prop::session_expiry_interval, 120)
        .keep_alive(30)
        .async_run(boost::asio::detached); // Restart the Client again.

    // Use the Client...

    ioc.run();
}

[4] mqtt_client 将尝试发送 DISCONNECT 报文, 持续 5 seconds. 无论结果如何, 连接都会被关闭.

[5] 所有未完成的操作将以错误码 boost::asio::error::operation_aborted 完成.
