boost::mqtt5::mqtt_client::async_disconnect (2 of 2 overloads)

通过发送 Reason Code 为 reason_codes.normal_disconnection 的 DISCONNECT 报文断开客户端. 此函数具有终结效果.

概要 
template<
    typename CompletionToken = typename asio::default_completion_token<boost::mqtt5::mqtt_client::executor_type>::type>
decltype(auto)
async_disconnect(
    CompletionToken&& token = {});
说明

客户端将尝试向代理服务器发送 DISCONNECT 报文, 其 Reason Code 描述断开连接的原因. 若 DISCONNECT 报文成功传输, 或经过 5 seconds 仍未成功发送, 客户端将终止连接.

注意

此函数具有终结效果, 将关闭客户端. 参见 mqtt_client::cancel.

参数

名称

说明

token

将用于生成完成处理器的完成标记. 操作完成时将调用该处理器.
处理器签名

此操作的处理器签名:

void (
    boost::mqtt5::error_code // Result of operation.
)
完成条件

当以下条件之一为真时, 异步操作将完成:

  • 客户端已尝试发送 DISCONNECT 报文, 无论发送是否成功.
  • 发生错误. 由处理器中的关联 boost::mqtt5::error_code 指示.
错误码

此操作可能以其结束的所有错误码列表:

  • boost::system::errc::errc_t::success
  • boost::asio::error::operation_aborted[footnote 若客户端未能向服务器发送 DISCONNECT 报文, 可能出现此错误码. 无论如何, 与服务器的连接都会被终止, 客户端会被取消. ]
  • boost::mqtt5::client::error::malformed_packet

请参阅关于 Error handling 的一节, 以了解每个错误码的根本原因.

逐操作取消

此异步操作支持对以下 boost::asio::cancellation_type 值进行取消:

  • cancellation_type::terminal - 调用 mqtt_client::cancel
