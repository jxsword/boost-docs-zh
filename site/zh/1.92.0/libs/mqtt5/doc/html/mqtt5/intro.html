引言

Boost.MQTT5 是一个构建于 Boost.Asio 之上的 C++17 客户端. 该客户端设计用于从兼容 MQTT 5.0 的代理服务器发布或接收消息. Boost.MQTT5 是对 MQTT 5.0 协议标准的完整实现, 完全支持以 QoS 0、1、2 发布或接收消息.

动机

MQTT 协议在各种现实场景中被广泛用于通信, 主要充当与 IoT 设备间数据传输的可靠通信协议. MQTT 协议本身相对简单, 但将其集成到应用中可能相当复杂, 主要原因在于断连/重连之后消息重传的实现颇具挑战. 为了解决这些难题并一劳永逸地简化 MQTT 集成, Boost.MQTT5 的设计秉持以下核心目标:

表 1.1. 核心目标

目标

说明

“即插即用”式接口, 将 MQTT 协议内部细节、底层网络事件、消息重传及其他复杂性抽象化

让开发者仅用一行代码即可发布或接收消息, 大幅降低学习曲线和开发时间. 入门只需基本的 MQTT 知识, 各技能水平的开发者都能轻松使用该库.

高度可靠且健壮的客户端, 可应对网络中断、不可靠的数据传输、网络延迟及其他不可预测的事件

客户端不暴露连接函数 (也没有异步连接函数); 网络连通性、MQTT 握手与消息重传都在客户端内部自动处理, 并严格遵守 MQTT 规范. 这种自动化使开发者无需编写冗长且易错的代码来处理这些场景, 从而可以专注于应用的核心功能.

完全遵循 Boost.Asio 的通用异步模型

接口与实现策略均构建在 Boost.Asio 的基础之上. 这种兼容性使其能够与 Boost.Asio 生态系统中的任何其他库无缝集成.

适用场景

如果以下陈述中任何一条成立, Boost.MQTT5 可能适合你:

  • 你的应用使用 Boost.Asio 并且需要集成 MQTT 客户端.
  • 你需要对 MQTT 代理服务器的异步访问.
  • 你正在开发需要连接 MQTT 代理服务器的更高层组件.
  • 你需要一个可靠且富有韧性的 MQTT 客户端来自动处理所有与网络相关的问题.

以下情况可能不适合你:

  • 你只需要对 MQTT 代理服务器的同步访问.
  • 你连接的 MQTT 代理服务器不支持 MQTT 5 版本.

特性

Boost.MQTT5 的设计核心信念是: 用户应只专注于自己的应用逻辑, 而非网络的复杂性.
该库力图通过一系列旨在提升开发体验的关键特性来体现这一信念:

表 1.2. 特性

特性

说明

完整的 TCP、TLS/SSL 与 WebSocket 支持

MQTT 协议要求底层网络协议提供有序、无损、双向的连接 (流). 用户可以通过模板参数自定义该流. Boost.MQTT5 库已在最常用的传输协议上通过测试: 使用 boost::asio::ip::tcp::socket 的 TCP/IP, 使用 boost::asio::ssl::stream 的 TLS/SSL, 以及使用 boost::beast::websocket::stream 的 WebSocket/TCP 与 WebSocket/TLS.

自动重连与重试机制

自动处理连接丢失、退避、重连与消息传输. 将这些流程自动化, 用户便可完全专注于应用功能本身. 参见 内置自动重连与重试机制.

效率优先

尽可能高效地利用网络与内存资源.

极小的内存占用

在 IoT 设备典型的资源受限环境中确保最佳性能.

完成标记

所有异步函数均采用 Boost.Asio 的通用异步模型实现, 并支持 CompletionToken. 这使其可以灵活地配合回调、协程和 future 使用.

自定义分配器

对自定义分配器的支持为内存资源提供了额外的灵活性与控制力. Boost.MQTT5 会使用与异步函数处理器关联的分配器来创建库实现所需对象的实例.

逐操作取消

所有异步操作都支持按 Asio 逐操作取消 的个体化定向取消. 这使得所有异步函数都可用于 并行操作, 对执行需要超时机制的操作尤为有益.

完整实现 MQTT 5.0 规范

确保与 MQTT 5.0 标准 完全兼容. 这一最新版本引入了增强系统健壮性的重要特性, 包括高级错误处理机制、会话与消息过期, 以及其他为支持现代 IoT 用例而设计的改进.

支持 QoS 0、QoS 1 与 QoS 2

完整实现 MQTT 协议定义的全部服务质量等级, 以匹配消息投递中不同的可靠性需求.

自定义认证

为你的自定义认证器定义接口以执行 Enhanced Authentication. 除用户名/密码认证外, 该自定义点还支持实现 SASL 协议支持的任何认证机制, 为高级安全需求提供灵活性.

高可用性

支持列出同一集群中客户端可连接的多个代理服务器. 当与某个代理服务器的连接失败时, 客户端会切换到列表中的下一个.

离线缓冲

自动缓冲离线期间发出的所有请求, 确保连接重新建立后发送它们. 这使用户可以自由调用任何异步函数, 无需考虑当前连接状态.

入门

Boost.MQTT5 是一个仅头文件库. 使用 Boost.MQTT5 需要满足以下条件:

  • 支持 C++17 的编译器
  • Boost 1.82 或更高版本. 除 Asio 外, 我们还使用其他仅头文件库.
  • OpenSSL. 如果你需要通过 boost::asio::ssl::stream 使用 SSL 连接.

Boost.MQTT5 已在以下编译器上通过测试:

  • clang 12.0 - 18.0 (Linux)
  • GCC 9 - 14 (Linux)
  • Apple clang 17.0.0 (macOS 15, arm64)
  • MSVC 14.37 - Visual Studio 2022 (Windows)

使用本库

  1. 下载 Boost, 并将其加入你的包含路径.
  2. 如果使用 SSL, 请下载 OpenSSL, 链接该库并将其加入包含路径.
  3. 将 Boost.MQTT5 的 include 文件夹加入你的包含路径.

在 Linux 上可以使用以下命令行编译下面的示例:

clang++ -std=c++17 <source-cpp-file> -o example -I<path-to-boost> -Iinclude -pthread

示例

以下示例演示了配置客户端并以 QoS 0 发布 “Hello World!” 应用消息的场景.

#include <boost/mqtt5/mqtt_client.hpp>
#include <boost/mqtt5/types.hpp>

#include <boost/asio/io_context.hpp>
#include <boost/asio/detached.hpp>
#include <boost/asio/ip/tcp.hpp>

#include <iostream>

int main() {
    boost::asio::io_context ioc;

    boost::mqtt5::mqtt_client<boost::asio::ip::tcp::socket> c(ioc);

    c.brokers("<your-mqtt-broker>", 1883)
        .credentials("<your-client-id>", "<client-username>", "<client-pwd>")
        .async_run(boost::asio::detached);

    c.async_publish<boost::mqtt5::qos_e::at_most_once>(
        "<topic>", "Hello world!",
        boost::mqtt5::retain_e::no, boost::mqtt5::publish_props {},
        [&c](boost::mqtt5::error_code ec) {
            std::cout << ec.message() << std::endl;
            c.async_disconnect(boost::asio::detached); // disconnect and close the Client
        }
    );

    ioc.run();
}
