入门

本节将引导你完成正确配置 mqtt_client 以建立与你所选 MQTT 代理服务器连接的步骤.

mqtt_client 不 提供连接函数 (也没有异步连接函数). 相反, 它提供一个用于启动客户端的函数 (参见 mqtt_client::async_run). mqtt_client 的所有配置必须在调用 mqtt_client::async_run 之前完成. 调用该函数后, mqtt_client 将进行首次连接尝试.

选择合适的传输协议

第一步是为你的 MQTT 连接选择合适的传输协议.

MQTT 协议依赖底层传输协议来保证客户端与服务器之间双向字节流的有序可靠传输. 满足这些要求的常见传输协议包括 TCP/IP、用于安全传输的 TLS/SSL, 以及运行在 TCP/IP 与 TLS/SSL 之上的 WebSocket.

MQTT 代理服务器有多种实现, 支持不同的传输协议. 因此, 熟悉你所选代理服务器支持的协议非常重要. 此外, 还要收集可能需要的任何必要信息, 例如证书颁发机构、客户端证书或私钥, 这些可能是建立安全连接所需的.

在本示例中, 我们选择 TCP/IP 作为底层协议来初始化 mqtt_client.

// Initialize the execution context required to run I/O operations.
boost::asio::io_context ioc;

// Construct the Client with boost::asio::ip::tcp::socket as the underlying stream.
boost::mqtt5::mqtt_client<boost::asio::ip::tcp::socket> client(ioc);

配置 MQTT 连接

mqtt_client 提供多种用于配置 MQTT 连接设置的函数. 这些功能包括:

  • 指定代理服务器列表: 你 必须 使用此函数为 mqtt_client 指定要尝试连接的代理服务器列表 (参见 mqtt_client::brokers). mqtt_client 允许为连接指定多个代理服务器. 务必确保 此列表中只包含属于同一集群的代理服务器. 列出不同集群的代理服务器可能导致 MQTT 会话之间不一致.
  • 设置连接凭据: 设置认证详情 (客户端标识符、用户名、密码) (参见 mqtt_client::credentials).
  • 配置保持连接间隔: 设置客户端两次连续传输之间允许的最大间隔 (参见 mqtt_client::keep_alive).
  • 指定自定义的用户实现认证器: 自定义认证将用于 Enhanced Authentication (mqtt_client::authenticator).
  • 定义 CONNECT 报文属性: 指定将在连接发起时随 CONNECT 报文一同发送的属性 (参见 mqtt_client::connect_property 与 mqtt_client::connect_properties).
注释

若用户未设置 maximum_packet_size CONNECT 属性, 它默认为 64KB. 这是唯一有默认值的 CONNECT 属性.

首先, 我们将使用 mqtt_client::brokers 函数指定要连接的代理服务器. 可以是 HiveMQ 在 broker.hivemq.com:1883 提供的公共代理服务器. 此外, 我们可以使用 mqtt_client::credentials 函数设置客户端标识符. 这并非强制, 因为有些代理服务器允许匿名连接.

配置 mqtt_client 之后, 我们调用 mqtt_client::async_run 函数. 这将启动与代理服务器建立连接的过程.

client.brokers(cfg.brokers, cfg.port) // Set the Broker to connect to.
    .credentials(cfg.client_id) // Set the Client Identifier. (optional)
    .connect_property(boost::mqtt5::prop::session_expiry_interval, 60) // optional
    .async_run(boost::asio::detached); // Start the Client.

值得注意的是, 这些配置适用于 mqtt_client::brokers 中列出的每个代理服务器. 要修改任何配置参数, 必须先停止 mqtt_client (使用 mqtt_client::cancel 或 mqtt_client::async_disconnect). 之后可以重新应用配置, 并用 mqtt_client 配合 mqtt_client::async_run 重启.

建立连接

mqtt_client 会发起与 mqtt_client::brokers 所指定代理服务器列表中第一个代理服务器的连接. 单次连接尝试包括以下几个步骤:

  1. 解析代理服务器的主机名.
  2. 创建 TCP 连接.
  3. 执行 TLS/SSL 握手 (如适用).
  4. 执行 WebSocket 握手 (如适用).
  5. 执行 MQTT 握手. 这包括向代理服务器发送 CONNECT 报文, (如适用) 交换 AUTH 报文 (参见 Enhanced Authentication), 并持续进行直到代理服务器发送 CONNACK 报文.

一旦 mqtt_client 收到 CONNACK 报文, 且其 Reason Code 为 0x00 (Success), 连接即成功建立. 若发生以下任一情况, 尝试将失败:

  • 从第 1 步到第 5 步中的任何一步发生失败.
  • mqtt_client 未在 5 seconds 内收到主机名解析的结果.
  • mqtt_client 未能在 5 seconds 内完成第 2 步至第 5 步.

若此次连接尝试不成功, 将按顺序转至下一个代理服务器, 持续此过程直到建立连接或用尽所有选项仍未成功. 若遍历完整列表仍未能成功连接, mqtt_client 将进入一段退避期, 然后对整个列表重新发起一轮尝试. 退避期的时长 (毫秒) 由以下公式决定:

2^(min(retry_count, 4)) * 1000 + jitter

在该公式中, retry_count 表示未成功连接情况下遍历完整列表的完整轮数, jitter 是在 -500ms 到 500ms 之间随机选取的值, 旨在防止多个客户端场景下的同步重连尝试.

使用客户端

调用 mqtt_client::async_run 之后, 就可以根据应用需要使用客户端了. 在本示例中, 我们会向 boost-mqtt5/test 主题发布一条 “Hello World!” 消息, 服务质量 (QoS) 为 0 (至多一次), 所用的函数是 mqtt_client::async_publish.

client.async_publish<boost::mqtt5::qos_e::at_most_once>(
    "boost-mqtt5/test", "Hello world!",
    boost::mqtt5::retain_e::yes, boost::mqtt5::publish_props {},
    [&client](boost::mqtt5::error_code ec) {
        std::cout << ec.message() << std::endl;

        // Disconnnect the Client.
        client.async_disconnect(boost::asio::detached);
    }
);

调试客户端

如果遇到配置或连接问题, 可以使用我们的日志机制来调试问题. mqtt_client 引入 LoggerType 作为其第三个模板参数, 用于指定在 mqtt_client 中记录事件所用的类型.

Boost.MQTT5 库提供了一个内置的 logger 实现, 将操作结果输出到 stderr. 该日志器输出连接过程每个步骤的详细信息, 包括 DNS 解析、TCP 连接、TLS 握手、WebSocket 握手与 MQTT 握手. 要启用此功能, 请用该日志器类的实例构造 mqtt_client:

// Construct the Client with boost::asio::ip::tcp::socket as the underlying stream and enabled logging.
// Since we are not establishing a secure connection, set the TlsContext template parameter to std::monostate.
boost::mqtt5::mqtt_client<
    boost::asio::ip::tcp::socket, std::monostate /* TlsContext */, boost::mqtt5::logger
> client(ioc, {} /* tls_context */, boost::mqtt5::logger(boost::mqtt5::log_level::info));
