LoggerType 概念

LoggerType 表示将由 mqtt_client 用来记录事件的对象类型.

若类型定义了 LoggerType 概念下列函数中的 任意数量 (包括零), 则其满足该概念:

函数签名

实参

说明

void at_resolve(error_code ec, std::string_view host, std::string_view port, const asio::ip::tcp::resolver::results_type& eps);

ec 是解析 (resolve) 操作返回的 error_code.

host 是解析中使用的主机名.

port 是解析中使用的端口.

eps 是解析操作返回的端点列表.

在解析操作完成时调用.

void at_tcp_connect(error_code ec, asio::ip::tcp::endpoint ep);

ec 是 TCP 连接操作返回的 error_code.

ep 是用于建立 TCP 连接的 TCP 端点.

在 TCP 连接操作完成时调用.

void at_tls_handshake(error_code ec, asio::ip::tcp::endpoint ep);

ec 是 TLS 握手操作返回的 error_code.

ep 是用于建立 TLS 握手的 TCP 端点.

在 TLS 握手操作完成时调用.

void at_ws_handshake(error_code ec, asio::ip::tcp::endpoint ep);

ec 是 WebSocket 握手操作返回的 error_code.

ep 是用于建立 WebSocket 握手的 TCP 端点.

在 WebSocket 握手操作完成时调用.

void at_connack(reason_code rc, bool session_present, const connack_props& ca_props);

rc 是 reason_code, 在 CONNACK 报文中收到, 指示 MQTT 握手的结果.

session_present 标志, 指示代理服务器是否已拥有与此连接关联的会话.

ca_props 是 boost::mqtt5::connack_props, 在 CONNACK 报文中收到.

在收到 CONNACK 报文时调用, 标志 MQTT 握手完成.

void at_disconnect(reason_code rc, const disconnect_props& dc_props);

rc 是 reason_code, 在 DISCONNECT 报文中收到, 说明断开连接的原因.

dc_props 是 boost::mqtt5::disconnect_props, 在 DISCONNECT 报文中收到.

在收到 DISCONNECT 报文时调用, 表示代理服务器想要关闭此连接.

void at_transport_error(error_code ec);

ec 是 error_code, 由对底层流执行 async_read_some 或 async_write_some 操作返回 (底层流类型为 StreamType).

在底层 StreamType 流上的读或写操作失败时调用, 触发到代理服务器的重连.

例如, 类型 T 若定义了 at_connack 与 at_disconnect 函数及其相应参数, 即被视为有效的 LoggerType. 这允许你创建自己的 LoggerType 类, 只包含感兴趣的函数.

所有已定义的函数都在 mqtt_client 内部使用其默认执行器直接调用. 若 mqtt_client 以显式或隐式 strand 初始化, 则任何函数都不会被并发调用.

警告

已定义的函数不应阻塞并阻止 mqtt_client 执行工作.

满足此概念的一个类是 logger.
