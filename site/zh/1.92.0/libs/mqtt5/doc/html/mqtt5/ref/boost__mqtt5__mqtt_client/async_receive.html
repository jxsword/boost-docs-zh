boost::mqtt5::mqtt_client::async_receive

异步接收应用消息.

概要 
template<
    typename CompletionToken = typename asio::default_completion_token<boost::mqtt5::mqtt_client::executor_type>::type>
decltype(auto)
async_receive(
    CompletionToken&& token = {});
说明

在客户端的整个生命周期内, 它将接收从代理服务器收到的所有 PUBLISH 报文并完成其投递. 客户端会按投递顺序在内部存储它们. 调用此函数将尝试从内部存储接收一条应用消息.

备注

仅当你已使用 async_subscribe 函数成功建立对某主题的订阅时, 才建议调用此函数.

参数

名称

说明

token

将用于生成完成处理器的完成标记. 操作完成时将调用该处理器. 若立即完成, 处理器的调用将以等效于使用 boost::asio::post 的方式进行.
处理器签名

此操作的处理器签名:

void (
    boost::mqtt5::error_code, // Result of operation.
    std::string,    // Topic, the origin of the Application Message.
    std::string,    // Payload, the content of the Application Message.
    boost::mqtt5::publish_props, // Properties received in the PUBLISH packet.
)
完成条件

当以下条件之一为真时, 异步操作将完成:

  • 客户端的内部存储中有一条待接收的应用消息.
  • 发生错误. 由处理器中的关联 boost::mqtt5::error_code 指示.
错误码

此操作可能以其结束的所有错误码列表:

  • boost::system::errc::errc_t::success
  • boost::asio::error::operation_aborted
  • boost::mqtt5::client::error::session_expired

请参阅关于 Error handling 的一节, 以了解每个错误码的根本原因.

逐操作取消

此异步操作支持对以下 boost::asio::cancellation_type 值进行取消:

  • cancellation_type::terminal
  • cancellation_type::partial
  • cancellation_type::total
