boost::mqtt5::mqtt_client::async_unsubscribe (2 of 2 overloads)

向代理服务器发送 UNSUBSCRIBE 报文, 取消对一个主题的订阅.

概要 
template<
    typename CompletionToken = typename asio::default_completion_token<boost::mqtt5::mqtt_client::executor_type>::type>
decltype(auto)
async_unsubscribe(
    const std::string& topic,
    const unsubscribe_props& props,
    CompletionToken&& token = {});
备注

客户端仍可能通过 mqtt_client::async_receive 函数从刚取消订阅的主题接收残留的应用消息.

参数

名称

说明

topic

要取消订阅的主题.

props

一个 boost::mqtt5::unsubscribe_props 实例.

token

将用于生成完成处理器的完成标记. 操作完成时将调用该处理器. 若立即完成, 处理器的调用将以等效于使用 boost::asio::async_immediate 的方式进行.
处理器签名

此操作的处理器签名:

void (
    boost::mqtt5::error_code, // Result of operation.
    std::vector<boost::mqtt5::reason_code>,  // Vector of Reason Codes containing
                                   // the result of unsubscribe operation
                                   // for the Topic in the UNSUBSCRIBE packet.
    boost::mqtt5::unsuback_props, // Properties received in the UNSUBACK packet.
)
完成条件

当以下条件之一为真时, 异步操作将完成:

  • 客户端已成功发送 UNSUBSCRIBE 报文, 并从代理服务器收到 UNSUBACK 响应.
  • 发生错误. 由处理器中的关联 boost::mqtt5::error_code 指示.
错误码

此操作可能以其结束的所有错误码列表:

  • boost::system::errc::errc_t::success
  • boost::asio::error::no_recovery
  • boost::asio::error::operation_aborted
  • boost::mqtt5::client::error::malformed_packet
  • boost::mqtt5::client::error::packet_too_large
  • boost::mqtt5::client::error::pid_overrun
  • boost::mqtt5::client::error::invalid_topic

请参阅关于 Error handling 的一节, 以了解每个错误码的根本原因.

逐操作取消

此异步操作支持对以下 boost::asio::cancellation_type 值进行取消:

  • cancellation_type::terminal - 调用 mqtt_client::cancel
  • cancellation_type::partial 与 cancellation_type::total - 防止 UNSUBSCRIBE 报文可能的重发
