Qi Confix 解析器指令

说明

Spirit.Qi 的 confix 指令是一个一元解析器组件, 允许把一个解析器(主体)嵌入到一个开头(前缀)与一个结尾(后缀)之内:

confix(prefix, suffix)[subject]

这将产生一个等价于以下序列的解析器

omit[prefix] >> subject >> omit[suffix]

一个简单的例子是非嵌套注释的解析器, 现在可以写为:

confix("/*", "*/")[*(char_ - "*/")]  // C style comment
confix("//", eol)[*(char_ - eol)]    // C++ style comment

使用 confix 指令而非显式序列的优点是, 能够把前缀与后缀封装到一个独立的构造中. 下面的代码片段说明了这一思路:

namespace spirit = boost::spirit;
namespace repo = boost::spirit::repository;

// Define a metafunction allowing to compute the type
// of the confix() construct
template <typename Prefix, typename Suffix = Prefix>
struct confix_spec
{
    typedef typename spirit::result_of::terminal<
        repo::tag::confix(Prefix, Suffix)
    >::type type;
};

confix_spec<std::string>::type const c_comment = repo::confix("/*", "*/");
confix_spec<std::string>::type const cpp_comment = repo::confix("//", "\n");

现在, 注释解析器可以写为

c_comment[*(char_ - "*/")]    // C style comment
cpp_comment[*(char_ - eol)]   // C++ style comment
注释

虽然 confix_p(prefix, subject, suffix) Spirit.Classic 中的解析器曾等价于序列 prefix >> *(subject - suffix) >> suffix, the Spirit.Qi confix` 指令将不再执行这种重构. 这简化了代码, 并使事情更加显式.

头文件 
// forwards to <boost/spirit/repository/home/qi/directive/confix.hpp>
#include <boost/spirit/repository/include/qi_confix.hpp>
概要 
confix(prefix, suffix)[subject]
参数

参数

说明

prefix

开头(前缀)部分的解析器.

suffix

结尾(后缀)部分的解析器.

subject

prefix 与 suffix 部分之间输入序列的解析器.

这三个参数本身都可以是任意复杂的解析器.

属性

confix 指令把其主体的属性类型暴露为自己的属性类型. 若 subject 不暴露任何属性(类型为 unused_type), 则 confix 也不暴露任何属性.

a: A, p: P, s: S: --> confix(p, s)[a]: A
注释

这种记法贯穿 Spirit 文档, 读作: 给定 a, p 和 s 为解析器, A, P 和 S 为它们的属性类型, 那么 confix(p, s)[a] 暴露的属性类型将是 A.

示例

下面的示例展示了 confix 指令的一些简单用例. 我们将通过为不同注释风格和某些简单的带标签数据生成解析器来说明其用法(完整示例代码见 confix.cpp)

前置条件

除了包含 Spirit.Qi 中实现的核心组件所需的主头文件外, 我们还要添加新的 confix 指令所需的头文件.

#include <boost/spirit/include/qi.hpp>
#include <boost/spirit/repository/include/qi_confix.hpp>

为了使下面的示例更易读, 我们把若干元素导入当前命名空间:

using boost::spirit::eol;
using boost::spirit::lexeme;
using boost::spirit::ascii::alnum;
using boost::spirit::ascii::char_;
using boost::spirit::ascii::space;
using boost::spirit::qi::parse;
using boost::spirit::qi::phrase_parse;
using boost::spirit::repository::confix;

解析不同的注释风格

我们将展示如何解析不同的注释风格. 首先解析一个 C++ 注释:

template <typename Iterator>
bool parse_cpp_comment(Iterator first, Iterator last, std::string& attr)
{
    bool r = parse(first, last,
        confix("//", eol)[*(char_ - eol)],  // grammar
        attr);                              // attribute

    if (!r || first != last) // fail if we did not get a full match
        return false;
    return r;
}

这个函数显然会解析诸如 "// This is a comment \n " 这样的输入. 类似地, 解析 'C' 风格的注释也证明非常直接:

template <typename Iterator>
bool parse_c_comment(Iterator first, Iterator last, std::string& attr)
{
    bool r = parse(first, last,
        confix("/*", "*/")[*(char_ - "*/")],    // grammar
        attr);                                  // attribute

    if (!r || first != last) // fail if we did not get a full match
        return false;
    return r;
}

它同样能够解析例如 "/* This is a comment */ ".

解析带标签数据

生成一个从 HTML 片段 "<b>The Body</b>" 中提取正文的解析器也不难:

template <typename Iterator>
bool parse_tagged(Iterator first, Iterator last, std::string& attr)
{
    bool r = phrase_parse(first, last,
        confix("<b>", "</b>")[lexeme[*(char_ - '<')]],  // grammar
        space,                                          // skip
        attr);                                          // attribute

    if (!r || first != last) // fail if we did not get a full match
        return false;
    return r;
}
