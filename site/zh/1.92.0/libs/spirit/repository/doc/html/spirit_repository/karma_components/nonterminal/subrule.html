Karma 子规则

说明

Spirit.Karma 的 subrule 是一个允许创建具名生成器并按名称引用它的组件 —— 很像规则与文法. 它实际上是规则的完全静态版本.

子规则的优势在于性能. 用子规则替换一些规则可以让生成器略快一些(测量数据见下文 性能). 原因是子规则允许 C++ 编译器进行激进内联, 而规则的实现基于虚函数调用, 视编译器而定可能带来一些运行期开销并阻止内联.

子规则的弱点是:

  • 子规则只能在同一个生成器表达式内定义和使用. 子规则不能在一个位置定义, 然后在另一个位置使用.
  • 子规则会给 C++ 编译器带来巨大压力. 它们增加编译时间与编译期间的内存使用, 也增加了触及编译器限制和/或缺陷的风险.

entry %= (
    ast_node %= int_ | binary_node | unary_node

  , binary_node %= '(' << ast_node << char_ << ast_node << ')'

  , unary_node %= '(' << char_ << ast_node << ')'
);

上面的示例可在此处找到: ../../example/karma/calc2_ast_dump_sr.cpp

如这个代码片段(calc2_ast_dump_sr 示例的节选)所示, 子规则可以与规则和文法自由混用. 这里, 一组 3 个子规则(ast_node, binary_node, unary_node)被赋给一条规则(名为 entry). 这意味着生成器的某些部分可以使用子规则(通常是最内层, 对性能最关键的部分), 而其余部分可以使用规则和文法.

头文件 
// forwards to <boost/spirit/repository/home/karma/nonterminal/subrule.hpp>
#include <boost/spirit/repository/include/karma_subrule.hpp>
概要(声明) 
subrule<ID, A1, A2> sr(name);
参数(声明)

参数

说明

ID

必需的数值实参. 给子规则一个唯一的"标识标签".

A1, A2

可选类型, 可以以任意顺序指定. 可以是 1. 签名, 2. locals 之一(有关这些参数的更多信息见规则参考).

注意, 与文法和规则不同, 分隔符类型无需在参数中指定. 子规则会自动使用它们被调用时生效的分隔符类型.

name

可选字符串. 给子规则一个名字, 对调试与错误处理很有用.
概要(用法)

子规则在组内定义和使用, 通常(按照惯例)包围在圆括号内.

// Group containing N subrules
(
    sr1 = expr1
  , sr2 = expr2
  , ... // Any number of subrules
}

同一组内定义的所有子规则的 ID 必须互不相同. 在同一组中定义多个具有相同 ID 的子规则(或多次定义同一个子规则)是错误的.

// Auto-subrules and inherited attributes
(
    srA %= exprA << srB << srC(c1, c2, ...) // Arguments to subrule srC
  , srB %= exprB
  , srC  = exprC
  , ...
)(a1, a2, ...)         // Arguments to group, i.e. to start subrule srA
参数(用法)

参数

说明

sr1, sr2

具有不同 ID 的子规则.

expr1, expr2

生成器表达式. 可以包括 sr1 和 sr2, 以及任何其他有效的生成器表达式.

srA

带有综合属性和继承属性的子规则.

srB

带有综合属性的子规则.

srC

带有继承属性的子规则.

exprA, exprB, exprC

生成器表达式.

a1, a2

传给子规则组的实参. 它们作为继承属性传递给该组的开始子规则 srA.

c1, c2

作为继承属性传给子规则 srC 的实参.
组

子规则组(一组子规则定义)是一个生成器, 可以在生成器表达式中的任何地方使用(在赋给规则的语句中, 以及直接在诸如 generate 之类的函数实参中). 在组内, 生成从开始子规则进行, 即该组中定义的第一个(最顶层)子规则. 在上面概要的两个组中, sr1 与 srA 分别是开始子规则 —— 例如, 当第一个子规则组被调用时, sr1 子规则被调用.

子规则只能在定义它的组中使用. 组可以看作作用域: 子规则的定义仅限于其外围组.

rule<outiter_type> r1, r2, r3;
subrule<1> sr1;
subrule<2> sr2;

r1 =
        ( sr1 = 'a' << space )      // First group in r1.
    <<  ( sr2 = +sr1 )              // Second group in r1.
    //           ^^^
    // DOES NOT COMPILE: sr1 is not defined in this
    // second group, it cannot be used here (its
    // previous definition is out of scope).
;

r2 =
        ( sr1 = 'a' << space )      // Only group in r2.
    <<  sr1
    //  ^^^
    // DOES NOT COMPILE: not in a subrule group,
    // sr1 cannot be used here (here too, its
    // previous definition is out of scope).
;

r3 =
        ( sr1 = space << 'x' )      // Another group. The same subrule `sr1`
                                    // can have another, independent
                                    // definition in this group.
;
属性

子规则在属性方面的行为与规则相同. 具体而言:

  • 其综合属性的类型是子规则签名中指定的类型(若有). 否则是 unused_type.
  • 其继承属性的类型是子规则签名中指定的类型(若有). 否则子规则没有继承属性.
  • 自动子规则(auto-subrule)可以通过 %= 语法赋值来定义. 这种情况下, 子规则的综合属性会自动传播到 RHS 生成器的属性.
  • Phoenix 占位符 _val, _r1, _r2, ... 可用于引用子规则的综合属性与继承属性(若存在).
局部变量

子规则在局部变量(locals)方面的行为与规则相同. 具体而言, Phoenix 占位符 _a, _b, ... 可用于引用子规则的局部变量(若存在).

示例

一些包含:

#include <boost/spirit/include/karma.hpp>
#include <boost/spirit/repository/include/karma_subrule.hpp>
#include <boost/phoenix/core.hpp>
#include <boost/phoenix/operator.hpp>
#include <boost/phoenix/fusion.hpp>

一些 using 声明:

using namespace boost::spirit;
using namespace boost::spirit::ascii;
namespace repo = boost::spirit::repository;

一个只含一条规则的文法, 该规则由一组 2 个子规则定义:

template <typename OutputIterator>
struct mini_xml_generator
  : karma::grammar<OutputIterator, mini_xml()>
{
    mini_xml_generator() : mini_xml_generator::base_type(entry)
    {
        entry %= (
            xml =
                    '<'  << string[_1 = at_c<0>(_val)] << '>'
                <<         (*node)[_1 = at_c<1>(_val)]
                <<  "</" << string[_1 = at_c<0>(_val)] << '>'

          , node %= string | xml
        );
    }

    karma::rule<OutputIterator, mini_xml()> entry;

    repo::karma::subrule<0, mini_xml()> xml;
    repo::karma::subrule<1, mini_xml_node()> node;
};

mini_xml 与 mini_xml_node 数据结构的定义在此不展示. 上面的完整示例可在此处找到: ../../example/karma/mini_xml_karma_sr.cpp

性能

要比较使用子规则时的运行期与编译期性能, 请参见 性能一节, 它位于 Spirit.Qi 子规则(Spirit.Karma 与 Spirit.Qi 子规则的实现非常相似, 因此性能也非常相似).

注释

子规则会把 C++ 编译器逼得很紧. 一组子规则是单个 C++ 表达式. 当前 C++ 编译器无法很好地处理非常复杂的表达式. 一个限制因素是典型编译器对模板递归深度的限制. 一些(但非全部)编译器允许配置这一限制.

g++ 的最大值可以通过编译器旗标设置: -ftemplate-depth. 若你使用相对复杂的子规则, 请适当设置它.
