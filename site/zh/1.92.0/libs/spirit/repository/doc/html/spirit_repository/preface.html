前言

Spirit 仓库

Spirit 仓库是一项社区协作成果, 收集了用于 Spirit.Qi 解析器和 Spirit.Karma 生成器的各种可复用组件(原语, 指令, 文法等). 仓库中的所有组件都经过同行评审和/或在 Spirit General List 上讨论过. 其目标是在能够保持 Spirit 库在代码质量, 灵活性与可维护性方面的高标准的同时, 拓宽其覆盖范围. 与此同时, 它鼓励人们贡献哪怕很小的组件, 因为这降低了成为 Boost 与 Spirit 作者的门槛.

代码的可维护性与作者在较长时期内的投入对 Spirit's 的成功至关重要(对整个 Boost 项目亦然). 这使仓库在作为有意向作者的试验场方面扮演了额外角色. 从仓库移除代码要比从 Spirit 核心库移除容易得多. 因此, 若作者因任何原因无法再维护其贡献, 我们能够更容易地把那些部分从仓库中移除.

仓库是让事物演进的绝佳途径. Spirit 核心已开发多年, 因此我们对它设计得当并暴露了经过验证的 API 有一定信心. 另一方面, 新想法往往需要一些时间才能"渐入佳境". 更改 API 是这一行当的一部分. 同时, 更改 API 总是意味着对用户的干扰, 我们希望把这种干扰降到最低. 再说一次, 在仓库中做改动应当比在核心库中容易得多.

贡献的质量是成功的另一个关键. 这不仅包括代码本身, 还要考虑文档, 测试, 示例等因素. 作者在邮件列表上的活跃程度也与之相关, 这是一个重要方面. 只有得到良好支持的东西才会随时间演化为可用的高质量组件. Spirit General List 上强制性的讨论与对贡献的评审确保了所期望的高质量标准.

基于用户反馈和事物的普遍可用性, 随着时间推移, 可以把仓库组件/文法移入 Spirit 核心库.

支持

请把所有问题提交到 Spirit 的邮件列表. 你可以订阅 Spirit General List. 该邮件列表有可搜索的存档. Spirit 的主页提供了指向该存档的搜索链接. 你也可以通过 Spirit General NNTP news portal (感谢 Gmane) 阅读邮件列表并向其发送消息. 该新闻组镜像了邮件列表. 存档链接如下: http://news.gmane.org/gmane.comp.parsers.spirit.general.
