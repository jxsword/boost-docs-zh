快速入门

你为什么会想用 Spirit?

Spirit 被设计为一个实用的解析工具. 至少, 从内联于 C++ 的正式 EBNF 规范生成一个完整可用的解析器, 这一能力显著缩短了开发时间. 虽然当我们想开发诸如 C 或 Pascal 这样的计算机语言时, 使用 YACC 或 ANTLR 这样成熟的独立解析器或许是务实的, 但当我们想编写极小的微型解析器时, 搬出这些重型武器显然是杀鸡用牛刀. 在这一端的场景里, 程序员通常不是把手头的工作当作正式的解析任务, 而是用 scanf 这类原始工具临时拼凑. 没错, 有诸如正则表达式库(如 boost regex)或扫描器(如 boost tokenizer)这样的工具, 但当我们需要编写更精致的解析器时, 这些工具的扩展性并不好. 即使用这些工具编写一个中等复杂度的解析器, 也会导致代码难以理解和维护.

一个首要目标是让这个工具易于使用. 一提到解析器生成器, 人们的第一反应往往是 "它一定又大又复杂, 学习曲线陡峭". 并非如此. Spirit 被设计为完全可扩展的. 框架按层组织. 这使得可以在只学习最小核心与基本概念之后, 按需学习.

为了开发简单和部署方便, 整个框架只由头文件组成, 没有需要链接或构建的库. 只要把 Spirit 发行包放入你的 include 路径, 编译并运行即可. 代码体积? —— 非常紧凑. 在稍后呈现的快速入门示例中, 代码体积主要由 std::vector 与 std::iostream 的实例化构成.

琐碎示例 #1

创建一个解析浮点数的解析器.

    real_p

(你不得不承认, 这真是琐碎!)上面的代码实际生成了一个 Spirit real_parser(内置解析器), 用于解析浮点数. 注意, 供用户直接使用的解析器, 其名称以 "_p" 结尾, 这是 Spirit 的约定. Spirit 有许多预定义解析器, 一致的命名约定有助于你保持理智!

琐碎示例 #2

创建一个接受由两个浮点数组成的输入行的解析器.

    real_p >> real_p

这里你看到了熟悉的浮点数解析器 real_p 被使用了两次, 每个数字一次. 那个 >> 运算符在其中做什么? 嗯, 它们之间总得用点什么隔开, 而这被选作 "后跟" 的顺序运算符. 上面的程序从两个更简单的解析器创建一个解析器, 用顺序运算符把它们粘合在一起. 结果是一个由更小解析器组成的解析器. 数字之间的空白是否被隐式消耗, 取决于解析器被调用的方式(见下文).

注意: 当我们组合解析器时, 我们得到一个"更大"的解析器, 但它仍然是一个解析器. 解析器可以越来越大, 嵌套越来越多, 但每当你把两个解析器粘合在一起, 你最终得到的仍是一个更大的解析器. 这是一个重要的概念.

琐碎示例 #3

创建一个接受任意数量浮点数的解析器.(任意意味着从零到无穷大之间的任何数量)

    *real_p

这就像正则表达式的 Kleene 星, 尽管对于不习惯看到 * 运算符被这样重载的 C++ 程序员来说, 语法可能看起来有点怪. 实际上, 即使你熟悉正则表达式, 它可能也显得奇怪, 因为星号位于它所修饰的表达式之前. 生活就是这样. 只能怪我们必须遵守 C++ 的语法规则.

任何求值为解析器的表达式都可以与 Kleene 星一起使用. 但请记住, 由于 C++ 运算符优先级规则, 对于复杂表达式, 你可能需要把表达式放进括号中. Kleene 星也被称为 Kleene 闭包, 但我们在大多数地方称它为星(Star).

示例 #4 [ 一个稍微不那么琐碎的示例 ]

本示例将创建一个接受以逗号分隔的数字列表的解析器, 并把数字放入一个 vector.

步骤 1. 创建解析器

    real_p >> *(ch_p(',') >> real_p)

注意 ch_p(','). 它是一个字面量字符解析器, 能够识别逗号 ','. 在这里, Kleene 星修饰的是一个更复杂的解析器, 即由以下表达式生成的解析器:

    (ch_p(',') >> real_p)

注意这是括号必要的情况. Kleene 星号作用于上面完整的表达式.

步骤 2. 使用解析器(既然已经创建)

既然我们已经创建了解析器, 该如何使用它? 与任何 C++ 临时对象的结果一样, 我们可以把它存入变量, 或直接在它上面调用函数.

我们将略过一些低层 C++ 细节, 直接进入正题.

若 r 是一条规则(现在先不用担心规则究竟是什么, 这会在稍后讨论. 只需知道规则是一个可以持有解析器的占位变量即可), 那么我们把解析器存储为规则, 如下:

    r = real_p >> *(ch_p(',') >> real_p);

并不怎么令人兴奋, 只是一个赋值, 与你多年来用过的任何其他 C++ 表达式一样. 把解析器存储在规则中的妙处在于: 规则就是解析器, 而现在你可以按名称引用它.(在这个例子里, 名称是 r). 注意, 现在这是一个完整的赋值表达式, 因此我们用分号 ";" 终结它.

就是这样. 我们完成了解析器的定义. 那么下一步就是调用这个解析器来完成它的工作. 有几种方式可以做到这一点. 眼下, 我们将使用接受 char const* 的自由 parse 函数. 该函数接受三个实参:

以空字符结尾的 const char* 输入
解析器对象
另一个被称为 跳过解析器的解析器

在我们的例子里, 我们希望跳过空格和制表符. Spirit 的预定义解析器库中包含另一个名为 space_p 的解析器. 它是一个非常简单的解析器, 只是识别空白. 我们将使用 space_p 作为跳过解析器. 跳过解析器负责跳过解析器元素之间的字符, 例如 real_p 与 ch_p 之间的字符.

好, 现在开始解析!

    r = real_p >> *(ch_p(',') >> real_p);
    parse(str, r, space_p) // Not a full statement yet, patience...

parse 函数返回一个对象(称为 parse_info), 其中除其他外还保存着解析的结果. 在本例中, 我们需要知道:

解析器是否成功识别了输入 str?
解析器是否 完全解析并消耗了输入直至其末尾?

为了完整呈现我们目前所做的一切, 让我们再把这个解析器包裹在一个函数里:

    bool
    parse_numbers(char const* str)
    {
        return parse(str, real_p >> *(',' >> real_p), space_p).full;
    }

注意在本例中我们舍弃了具名规则, 把解析器直接内联到对 parse 的调用中. 调用 parse 时, 表达式求值为一个临时的未命名解析器, 被传入 parse() 函数, 使用之后即被销毁.

char 与 wchar_t 操作数

细心的读者可能注意到, 解析器表达式使用的是 ',' 而不是如前例那样的 ch_p(','). 由于 C++ 的转换语法规则, 这是可以的. 有些 >> 运算符被重载为在其左侧或右侧(但不可同时两侧)接受 char 或 wchar_t 实参. 只要运算符的至少一个参数是用户自定义类型, 它就可以被重载. 在本例中, real_p 是 operator>> 的第二个实参, 因此使用了 >> 的相应重载, 把 ',' 转换为字符字面量解析器.

省略 ch_p 调用的问题应当是显而易见的: 'a' >> 'b' 不是 spirit 解析器, 它是一个数值表达式, 把 'a' 的 ASCII(或其他编码)值右移 'b' 的 ASCII 值. 然而, ch_p('a') >> 'b' 与 'a' >> ch_p('b') 都是字母 'a' 后跟 'b' 的 Spirit 顺序解析器. 迟早你会习惯的.

注意, parse 函数返回的对象有一个名为 full 的成员, 若上述两个要求都满足(即解析器完整解析了输入), 它返回 true.

步骤 3. 语义动作

我们上面的解析器实际上只是一个识别器. 它回答 "输入是否匹配我们的文法?"这个问题, 但它不记住任何数据, 也不执行任何副作用. 记住: 我们想把解析出的数字放入一个 vector. 这通过挂接到特定解析器的 动作来完成. 例如, 每当我们解析一个实数时, 我们希望在成功匹配后保存解析出的数字. 现在我们希望从解析器中提取信息. 语义动作正是做这个的. 语义动作可以挂接到文法规范中的任何位置. 这些动作是 C++ 函数或函数对象, 每当解析器的某一部分成功识别输入的一部分时就会被调用. 假设你有一个解析器 P 和一个 C++ 函数 F, 你可以通过挂接 F 让解析器在匹配输入时调用 F:

    P[&F]

或者, 若 F 是一个函数对象(函数对象):

    P[F]

函数/函数对象的签名取决于它所挂接的解析器的类型. 解析器 real_p 传递单个实参: 解析出的数字. 因此, 若我们要把函数 F 挂接到 real_p, 我们需要把 F 声明为:

    void F(double n);

不过对于我们的示例, 我们同样可以利用一些预定义的语义函数对象与函数对象生成器( 函数对象生成器是返回函数对象的函数). 为达目的, Spirit 提供了函数对象生成器 push_back_a(c). 简言之, 这个语义动作被调用时, 会把它从所挂接解析器那里收到的解析值追加到容器 c 中.

最后, 这是我们完整的以逗号分隔的列表解析器:

    bool
    parse_numbers(char const* str, vector<double>& v)
    {
        return parse(str,

            //  Begin grammar
            (
                real_p[push_back_a(v)] >> *(',' >> real_p[push_back_a(v)])
            )
            ,
            //  End grammar

            space_p).full;
    }

这与上面的解析器相同. 这一次在战略要点挂接了相应的语义动作, 用于提取解析出的数字并把它们塞进 vector v. parse_numbers 函数成功时返回 true.
