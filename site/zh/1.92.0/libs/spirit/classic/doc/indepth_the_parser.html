深入: 解析器

是什么让 Spirit 运转起来? 现在来看看一些细节... parser 类是框架中最基本的实体. 解析器接受一个由 first-last 迭代器对组成的扫描器, 并返回一个匹配对象作为结果. 迭代器界定当前正在被解析的数据. 若解析成功, 匹配对象求值为 true, 此时输入相应地向前推进. 每个解析器可以表示一个特定的模式或算法, 也可以是由其他解析器组合而成的更复杂的解析器.

所有解析器都继承自基模板类 parser:

template <typename DerivedT>
struct parser
{
    /*...*/

    DerivedT& derived();
    DerivedT const& derived() const;
};

该类是所有解析器的协议基类. parser 类本身并不真正知道如何解析任何东西, 而是依靠模板参数 DerivedT 来执行实际解析. 这一技术在模板元编程圈子里被称为 "Curiously Recurring Template Pattern". 这种继承策略赋予我们多态的力量, 却没有虚函数的开销. 本质上, 这是实现 编译期多态的一种方式.

parser_category_t

每个派生解析器都有一个 typedef parser_category_t 来定义其类别. 默认情况下, 若未指定, 它将继承自基解析器类, 后者将其 parser_category_t typedef 为 plain_parser_category. 框架提供了一些模板类来区分不同类型的解析器. 以下类别是最通用的. 更具体的类型可以继承自它们.

解析器类别
plain_parser_category 普通的原生解析器
binary_parser_category 拥有主体 a 和 b 的解析器(如 alternative)
unary_parser_category 拥有单一主体的解析器(如 kleene 星)
action_parser_category 挂接了语义动作的解析器 
    struct plain_parser_category {};
    struct binary_parser_category       : plain_parser_category {};
    struct unary_parser_category        : plain_parser_category {};
    struct action_parser_category       : unary_parser_category {};

embed_t

每个解析器都有一个 typedef embed_t. 该 typedef 指定解析器如何被嵌入组合器中. 默认情况下, 若未指定, 解析器将按值嵌入. 也就是说, 解析器的一份拷贝被放置为组合器的成员变量. 大多数解析器按值嵌入. 但在某些情况下, 这不合意或不可行. 一个典型的例子是 rule. rule 与其他解析器不同, 是按引用嵌入的.

匹配

匹配(match)持有解析器的结果. 当找到成功匹配时, 匹配对象求值为 true, 否则为 false. 匹配的长度是成功匹配的字符(或记号)数. 这可以通过其 length() 成员函数查询. 负值表示匹配不成功.

每个解析器可以有一个关联的属性. 解析成功时, 该属性也会通过匹配对象返回给使用者. 我们可以通过匹配的 value() 成员函数获取该属性. 不过要当心, 匹配的属性可能是无效的, 此时获取属性将导致异常. 可以查询成员函数 has_valid_attribute() 来获知获取匹配属性是否安全. 属性可以随时通过成员函数 value(v)设置, 其中 v 是新的属性值.

匹配属性在以下情况下有效:

  • 成功的匹配
  • 当其值通过 value(val) 成员函数被设置时
  • 当它从一个具有有效属性的兼容匹配对象(如 match<double> 得自 match<int>)时. 匹配对象 A 与另一个匹配对象 B 兼容, 当且仅当 A 的属性类型可以从 B 的属性类型赋值(即 a = b; 必须能通过编译).

匹配属性在以下情况下未定义:

  • 不成功的匹配
  • 当尝试从具有不兼容属性类型的另一个匹配对象拷贝或赋值时(如从 match<int> 得到 match<std::string>).

match 类:

    template <typename T>
    class match
    {
    public:

        /*...*/

        typedef T attr_t;

                    operator safe_bool() const; // convertible to a bool
        int         length() const;
        bool        has_valid_attribute() const;
        void        value(T const&) const;
        T const&    value();
    };

match_result

前文已反复提到, 解析器返回一个匹配对象作为其结果. 这是一种简化. 实际上, 出于泛型性的考虑, 解析器并非硬编码为返回匹配对象. 更准确地说, 解析器返回一个遵循某概念接口的对象, match 只是其中一个例子. 不过, 无论解析器的结果类型实际上是 match 类, 其派生类, 还是毫不相关的类型, 我们都将称其为匹配对象.

元函数

什么是元函数? 我们都知道函数长什么样. 简单地说, 函数接受一些实参并返回一个结果. 这是我们都钟爱的函数:

int identity_func(int arg)
{ return arg; } // return the argument arg

元函数本质上是同样的东西. 这些家伙同样接受实参并返回结果. 然而, 函数在运行期对值进行操作, 而元函数在编译期对类型进行操作(或常量, 但我们只讨论类型). 元函数是一个模板类(或结构体). 模板参数是元函数的实参, 类内的一个 typedef 则是元函数的返回类型. 下面是对应的元函数:

template <typename ArgT>
struct identity_meta_func
{ typedef ArgT type; } // return the argument ArgT

上面的元函数按如下方式调用:

typename identity_meta_func<ArgT>::type

按照惯例, 元函数通过 typedef type 返回结果. 注意, typename 只在模板内部才需要.

解析器实际使用的匹配类型取决于两个类型: 解析器的属性类型和扫描器类型. match_result 是这样一个元函数: 在给定属性类型和扫描器类型时, 返回所需的匹配类型.

用法:

    typename match_result<ScannerT, T>::type

该元函数基本上回答了这样一个问题: "给定扫描器类型 ScannerT 和属性类型 T, 所需的匹配类型是什么?"[ typename 只在模板内部才需要 ].

parse 成员函数

继承自 parser 的具体子类必须拥有一个与概念接口兼容的对应成员函数 parse(...):

    template <typename ScannerT>
    RT
    parse(ScannerT const& scan) const;

其中 RT 是解析器所需的返回类型.

解析器结果

在大多数情况下, 继承自 parser 的具体子类需要拥有一个嵌套元函数 result, 在给定扫描器类型时, 返回解析器 parse 成员函数的结果 type. 该元函数的形式为:

    template <typename ScannerT>
    struct result
    {
        typedef RT type;
    };

其中 RT 是解析器所需的返回类型. 它通常(但并非总是)依赖于模板参数 ScannerT. 例如, 给定属性类型 int, 我们可以使用 match_result 元函数:

    template <typename ScannerT>
    struct result
    {
        typedef typename match_result<ScannerT, int>::type type;
    };

若解析器未提供 result 元函数, 基解析器类会提供一个默认版本. 默认版本声明为:

    template <typename ScannerT>
    struct result
    {
        typedef typename match_result<ScannerT, nil_t>::type type;
    };

若没有 result 元函数, 请注意解析器的默认属性是 nil_t(即该解析器没有属性).

parser_result

给定扫描器类型 ScannerT 和解析器类型 ParserT, 解析器的实际结果会是什么? parser_result 元函数为此问题提供答案.

用法:

    typename parser_result<ParserT, ScannerT>::type

一般而言, 该元函数只是把调用转发给解析器的 result 元函数:

    template <typename ParserT, typename ScannerT>
    struct parser_result
    {
        typedef typename ParserT::template result<ScannerT>::type type;
    };

这类似于全局函数调用成员函数. 大多数时候, 上面的用法等价于:

    typename ParserT::template result<ScannerT>::type

然而, 不应指望这一点永远成立, 因为 parser_result 元函数可能会针对特定解析器和/或扫描器类型进行特化.

parser_result 元函数使所需的 parse 成员函数的签名几乎成为规范形式:

    template <typename ScannerT>
    typename parser_result<self_t, ScannerT>::type
    parse(ScannerT const& scan) const;

其中 self_t 是指向该解析器的 typedef.

parser 类声明

    template <typename DerivedT>
    struct parser
    {
        typedef DerivedT                embed_t;
        typedef DerivedT                derived_t;
        typedef plain_parser_category   parser_category_t;

        template <typename ScannerT>
        struct result
        {
            typedef typename match_result<ScannerT, nil_t>::type type;
        };

        DerivedT& derived();
        DerivedT const& derived() const;

        template <typename ActionT>
        action<DerivedT, ActionT>
        operator[](ActionT const& actor) const;
    };
