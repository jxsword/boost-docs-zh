参数化解析器

我们已经瞥见了 Spirit 框架的动态本性. 这种能力是 Spirit 的根本. 动态解析是一个非常强大的概念. 我们将通过运行期参数化解析器把这一概念再向前推进. 我们能够处理任何 EBNF 语法都无法单独完成的解析任务.

一个小秘密

潜伏在 boost 发行包中一个叫做 boost::ref 的小家伙, 在与 Spirit 的原语解析器配合使用时是相当强大的猛兽. 我们习惯于看到用字符串或字符字面量创建的 Spirit 原语解析器, 例如:

    ch_p('A')
    range_p('A', 'Z')
    str_p("Hello World")

str_p 有第二种形式, 接受字符串上的两个迭代器:

    char const* first = "My oh my";
    char const* last = first + std::strlen(first);

    str_p(first, last)

不那么显眼的是, 我们同样可以使用 boost::ref:

    char ch = 'A';
    char from = 'A';
    char to = 'Z';

    ch_p(boost::ref(ch))
    range_p(boost::ref(from), boost::ref(to))

使用 boost::ref 时, 传给 ch_p 和 range_p 的实际参数以引用方式持有. 这意味着我们可以随时改变 ch, from 和 to 的值, 而对应的 ch_p 和 range_p 解析器会跟随它们的动态值. 当然, 由于它们以引用方式持有, 你必须确保在解析期间被引用的对象不被销毁.

那 str_p 呢?

str_p 的第一种形式(单实参形式)保留给以空字符结尾的字符串常量, 而第二种形式(双实参 first/last 迭代器形式)则可用于:

    char const* first = "My oh my";
    char const* last = first + std::strlen(first);

    str_p(boost::ref(first), boost::ref(last))
嘿, 别忘了 chseq_p. 所有这些同样适用于这个鲜少使用的原语.

函数式参数化原语

    #include <boost/spirit/attribute/parametric.hpp>

再进一步, Spirit 包含了原语的函数式版本. 它们不是接受字符, 字符串或对字符与字符串的引用(通过 boost::ref), 而是接受函数或函数对象.

f_chlit 与 f_ch_p

chlit 的函数式版本. 该解析器接受一个函数或函数对象(函数对象). 期望该函数具有与以下接口兼容的接口:

    CharT func()

其中 CharT 是字符类型(如 char, int, wchar_t).

期望该函数对象具有与以下接口兼容的接口:

    struct functor
    {
        CharT operator()() const;
    };

其中 CharT 是字符类型(如 char, int, wchar_t).

下面是一个人为编造的例子:

    struct X
    {
        char operator()() const
        {
            return 'X'; 
        }
    };

现在我们可以用 X 来创建 f_chlit 解析器:

    f_ch_p(X())

f_range 与 f_range_p

range 的函数式版本. 该解析器接受与上述接口兼容的函数或函数对象. 区别在于 f_range(和 f_range_p)期望两个函数对象, 一个用于范围的起点, 一个用于终点.

f_chseq 与 f_chseq_p

chseq 的函数式版本. 该解析器接受两个函数或函数对象, 一个用于 begin 迭代器, 一个用于 end 迭代器. 期望该函数具有与以下接口兼容的接口:

    IteratorT func()

其中 IteratorT 是迭代器类型(如 char const*, wchar_t const*).

期望该函数对象具有与以下接口兼容的接口:

    struct functor
    {
        IteratorT operator()() const;
    };

其中 IteratorT 是迭代器类型(如 char const*, wchar_t const*).

f_strlit 与 f_str_p

strlit 的函数式版本. 该解析器接受与 f_chseq 所期望接口兼容的两个函数或函数对象.
