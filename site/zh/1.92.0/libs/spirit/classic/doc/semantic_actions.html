语义动作

语义动作的形式为: expression[action]

归根结底, 在定义了文法并生成了相应解析器之后, 我们还需要产生一些输出并做一些除语法分析之外的工作; 当然, 除非我们想要的仅仅是检查输入是否符合我们的文法, 而这种情况很少见. 语义动作可以挂接到解析器层次内任何层级的任何表达式上. 动作是一个 C/C++ 函数或函数对象, 当在它所挂接的特定上下文中找到匹配时会被调用. 动作函数充当挂进解析器的钩子, 例如可用于:

从解析器生成输出(例如 AST)
报告警告或错误
管理符号表

泛型语义动作(转导接口)

泛型语义动作可以是任何与以下接口兼容的自由函数或函数对象:

    void f(IteratorT first, IteratorT last);

其中 IteratorT 是所用的迭代器类型, first 指向当前输入, last 指向输入末尾之后一个位置(与 STL 迭代器范围相同). 函数对象(functor)应有一个与上述签名相同的成员 operator():

    struct my_functor
    {
        void operator()(IteratorT first, IteratorT last) const;
    };

指向输入中匹配部分的迭代器被传入函数/函数对象.

一般来说, 语义动作接受 first-last 迭代器对. 这是转导(transduction)接口. 动作函数或函数对象直接从输入接收代表匹配产生式的未加工数据. 在许多情况下这就够了. 例如源到源的翻译, 预处理等.

示例:

    void
    my_action(char const* first, char const* last)
    {
        std::string str(first, last);
        std::cout << str << std::endl;
    }

    rule<> myrule = (a | b | *(c >> d))[&my_action];

每当表达式 (a | b | *(c >> d) 在解析时匹配输入流的一部分, 函数 my_action 就会被调用. 两个迭代器 first 和 last 被传入函数. 它们分别指向发现匹配的输入流部分的起点和终点.

常量性:

对于函数对象, 注意 operator() 应当是 const. 这意味着函数对象是不可变的. 有人可能希望拥有一些在动作被调用时被修改的成员变量. 这不是好主意. 首先, 函数对象最好保持轻量. 函数对象被频繁传递, 若负载过重会产生大量开销. 其次, 函数对象按值传递. 因此, 最终挂接到解析器上的实际函数对象肯定不会是使用者提供的原始实例. 这意味着对函数对象状态的修改不会影响使用者传入的原始函数对象, 因为它们是不同的拷贝. 若函数对象需要更新一些状态变量(这很常见), 最好使用对外部数据的引用. 下面的示例展示了如何做到这一点:

    struct my_functor
    {
        my_functor(std::string& str_)
        : str(str_) {}

        void
        operator()(IteratorT first, IteratorT last) const
        {
            str.assign(first, last);
        }

        std::string& str;
    };

完整示例:

现在是我们用语义动作增强后的计算器:

    namespace
    {
        void    do_int(char const* str, char const* end)
        {
            string  s(str, end);
            cout << "PUSH(" << s << ')' << endl;
        }

        void    do_add(char const*, char const*)    { cout << "ADD\n"; }
        void    do_subt(char const*, char const*)   { cout << "SUBTRACT\n"; }
        void    do_mult(char const*, char const*)   { cout << "MULTIPLY\n"; }
        void    do_div(char const*, char const*)    { cout << "DIVIDE\n"; }
        void    do_neg(char const*, char const*)    { cout << "NEGATE\n"; }
    }

我们用语义动作增强文法:

    struct calculator : public grammar<calculator>
    {
        template <typename ScannerT>
        struct definition
        {
            definition(calculator const& self)
            {
                expression
                    =   term
                        >> *(   ('+' >> term)[&do_add]
                            |   ('-' >> term)[&do_subt]
                            )
                    ;

                term =
                    factor
                        >> *(   ('*' >> factor)[&do_mult]
                            |   ('/' >> factor)[&do_div]
                            )
                        ;

                factor
                    =   lexeme_d[(+digit_p)[&do_int]]
                    |   '(' >> expression >> ')'
                    |   ('-' >> factor)[&do_neg]
                    |   ('+' >> factor)
                    ;
            }

            rule<ScannerT> expression, term, factor;

            rule<ScannerT> const&
            start() const { return expression; }
        };
    };

例如, 把表达式 (-1 + 2) * (3 + -4) 喂给规则 expression, 将产生预期的输出:

-1
2
ADD
3
-4
ADD
MULT

顺便说一句, 这正是给定表达式的逆波兰表示法(RPN), 让人想起某些原始计算器和 Forth 语言.

特化动作

一般来说, 语义动作接受 first-last 迭代器对. 不过, 有些情况下我们可能希望以加工后的形式传递数据. 一个具体的例子是数值解析器. 把未加工的数据传给挂接在数值解析器上的语义动作, 只是白白丢掉解析器已解析出的内容, 是不明智的. 我们想传递实际解析出的数字.

语义动作的函数与函数对象签名随其挂接的解析器而变化. 下表列出了接受独特签名的解析器.

除非特定解析器类型的文档中明确说明, 否则未列入上表的解析器默认期望如上所述的泛型签名.

数值动作

适用于:

uint_p
int_p
ureal_p
real_p

函数的签名:

    void func(NumT val);

函数对象的签名: 

    struct ftor
    {
        void operator()(NumT val) const;
    };

其中 NumT 是任何原始数值类型, 如 int, long, float, double 等, 或用户自定义的数值类型, 如 big_int. NumT 与用作 uint_p, int_p, ureal_p 或 real_p 模板参数的类型相同. 解析出的数字被传入函数/函数对象.

字符动作

适用于:

chlit, ch_p
range, range_p
anychar
alnum, alpha
cntrl, digit
graph, lower
print, punct
space, upper
xdigit

函数的签名:

    void func(CharT ch);

函数对象的签名:

    struct ftor
    {
        void operator()(CharT ch) const;
    };

其中 CharT 是解析所用迭代器的 value_type. 例如 char const* 迭代器的 value_type 是 char. 匹配的字符被传入函数/函数对象.

级联动作

动作可以级联. 级联的动作也继承原始动作的函数/函数对象接口. 例如:

    uint_p[fa][fb][fc]

这里, 函数对象 fa, fb 和 fc 都期望签名 void operator()(unsigned n) const.

指令与动作

指令继承它所包围主体的函数/函数对象接口. 示例:

    as_lower_d[ch_p('x')][f]

这里, 假设所用迭代器是 char const*, 则函数对象 f 期望签名 void operator()(char ch) const.
