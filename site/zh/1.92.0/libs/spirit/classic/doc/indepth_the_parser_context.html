深入: 解析器上下文

概述

解析器的 上下文(context)是又一个概念. 一个 context 类的实例(对象)在非终结符开始解析之前创建, 在解析结束之后销毁. 非终结符是 rule, subrule 或 grammar. 非终结符拥有 ContextT 模板参数. 下面的伪代码描绘了非终结符被调用时发生的事情:

    return_type
    a_non_terminal::parse(ScannerT const& scan)
    {
        context_t ctx(/**/);
        ctx.pre_parse(/**/);

        //  main parse code of the non-terminal here...

        return ctx.post_parse(/**/);
    }

提供上下文是为了可扩展性. 其主要目的是暴露非终结符 parse 成员函数的开始与结束, 以容纳外部挂钩. 通过编写专门的上下文类, 我们可以以多种方式扩展非终结符, 而无需修改类本身. 例如, 我们可以编写一个上下文类, 在解析遍历中非终结符被调用的每个节点打印扫描器的当前状态, 从而让非终结符输出调试诊断信息.

一个打印调试信息的解析器上下文示例:

    pre_parse:      non-terminal XXX is entered. The current state of the input
                    is "hello world, this is a test"

    post_parse:     non-terminal XXX has concluded, the non-terminal matched "hello world".
                    The current state of the input is ", this is a test"

大多数时候, 上下文在用户视野中是不可见的. 一般而言, 框架的使用者无需直接处理上下文, 甚至无需知道上下文的存在. 不过, 高级用户可能会发现上下文的某些用途. 因此, 这是公开 API 的一部分. 框架中位于核心之上其他层的其他部分, 也利用上下文来扩展非终结符.

类声明

parser_context 类是非终结符使用的默认上下文类.

    template <typename AttrT = nil_t>
    struct parser_context
    {
        typedef AttrT attr_t;
        typedef implementation_defined base_t;
        typedef parser_context_linker<parser_context<AttrT> > context_linker_t;

        template <typename ParserT>
        parser_context(ParserT const& p) {}

        template <typename ParserT, typename ScannerT>
        void
        pre_parse(ParserT const& p, ScannerT const& scan) {}

        template <typename ResultT, typename ParserT, typename ScannerT>
        ResultT&
        post_parse(ResultT& hit, ParserT const& p, ScannerT const& scan)
        { return hit; }
    };

非终结符的 ContextT 模板参数是一个概念. 上面的 parser_context 类是该概念最简单的模型. 默认 parser_context 的 pre_parse 与 post_parse 成员函数只是空操作. 你可以把非终结符的 ContextT 模板参数看作支配非终结符在解析之前和之后如何表现的策略. 使用者可以通过向特定非终结符传递用户自定义的上下文模板参数, 来提供自己的上下文策略.

解析器上下文策略
attr_t typedef: 非终结符的属性类型. 见 match.
base_t typedef: 非终结符的基类. 非终结符继承自该类.
context_linker_t typedef: 该类类型为 Spirit 提供了把额外功能插入非终结符 parse 函数, 甚至绕过给定上下文的可能. 它应简单地 typedef 为 parser_context_linker<T>, 其中 T 是用户自定义上下文类的类型.
constructor 构造上下文. 非终结符作为实参传递给构造函数.
pre_parse 在解析之前做些事情. 非终结符和当前扫描器作为实参传入.
post_parse 在解析之后做些事情. 无论解析结果如何都会调用它. 传入一个对解析器结果的引用. 上下文有权修改它. 非终结符和当前扫描器也作为实参传入.

base_t 值得进一步解释. 来吧... 上下文严格来说是一个基于栈的类. 它在解析之前创建, 在非终结符的 parse 成员函数退出之后销毁. 有时, 我们需要在非终结符宿主的完整生存期内存在的辅助数据. 由于非终结符继承自上下文的 base_t, 上下文自身在创建时, 于构造期间(当非终结符作为实参传给构造函数时)就能获得对 this 的访问. pre_parse 与 post_parse 亦然.

非终结符继承自上下文的 base_t typedef. 唯一的要求是它是一个可默认构造的类. 拷贝构造与赋值的要求取决于宿主. 若宿主需要, 上下文的 base_t 也同样需要. 一般来说, 提供这些基本要求并无害处.

非默认属性类型

开箱即用, parser_context 类可以 nil_t 以外的类型参数化. 以下代码演示了 parser_context 模板带显式实参的用法, 用于声明匹配结果不同于 nil_t 的规则:

    rule<parser_context<int> > int_rule = int_p;

    parse(
        "123",
        // Using a returned value in the semantic action
        int_rule[cout << arg1 << endl] 
    );

在这个例子中, int_rule 以 int 属性类型声明. 因此, int_rule 变量可以持有任何返回 int 值的解析器(例如 int_p 或 bin_p). 需要注意的重要一点是, 我们可以在绑定到 int_rule 的语义动作中使用该返回值.

示例见 examples 中的 parser_context.cpp. 它是 Spirit 发行包的一部分.

一个示例

作为示例, 让我们看看 Spirit 解析器上下文, 它向解析过程插入一些调试输出:

    template<typename ContextT>
    struct parser_context_linker : public ContextT
    {
        typedef ContextT base_t;

        template <typename ParserT>
        parser_context_linker(ParserT const& p)
        : ContextT(p) {}
        
    // This is called just before parsing of this non-terminal
        template <typename ParserT, typename ScannerT>
        void pre_parse(ParserT const& p, ScannerT &scan)
        {
        // call the pre_parse function of the base class
            this->base_t::pre_parse(p, scan);

#if BOOST_SPIRIT_DEBUG_FLAGS & BOOST_SPIRIT_DEBUG_FLAGS_NODES
            if (trace_parser(p.derived())) {
            // print out pre parse info
                impl::print_node_info(
                false, scan.get_level(), false,
                parser_name(p.derived()),
                scan.first, scan.last);
            }
            scan.get_level()++;  // increase nesting level
#endif 
        }
    // This is called just after parsing of the current non-terminal
        template <typename ResultT, typename ParserT, typename ScannerT>
        ResultT& post_parse(
            ResultT& hit, ParserT const& p, ScannerT& scan)
        {

#if BOOST_SPIRIT_DEBUG_FLAGS & BOOST_SPIRIT_DEBUG_FLAGS_NODES
            --scan.get_level();  // decrease nesting level
            if (trace_parser(p.derived())) {
                impl::print_node_info(
                    hit, scan.get_level(), true,
                    parser_name(p.derived()),
                    scan.first, scan.last);
            }
#endif
        // call the post_parse function of the base class
            return this->base_t::post_parse(hit, p, scan);
        }
    };

在调试期间(定义了 BOOST_SPIRIT_DEBUG), 这个解析器上下文会被注入当前 parser_context 的派生层次中 —— 它原本被指定用于某个具体解析器 —— 因此模板参数 ContextT 代表原始的 parser_context. 出于这个原因, pre_parse 与 post_parse 函数会调用基类中对应的函数. 此外, 这些函数还会调用一个特殊的 print_node_info 函数, 由它实际输出当前非终结符的解析器状态信息. 有关打印信息的更多信息, 你可能想看看 Debugging 主题.
