数值解析

与 chlit, strlit 等类似, 数值解析器也是原语. 数值解析器被单独放在一节中, 以便更好地聚焦这个重要的构件. 框架包含几个预定义对象, 用于解析有符号与无符号整数以及实数. 这些解析器是完全参数化的. 数值解析的大多数重要方面都可以精细调整以适应需要. 这包括基数(radix base), 允许的最小与最大位数, 指数, 小数部分等. 策略控制实数解析器的行为. 框架提供了一些覆盖最常见实数格式的预定义策略, 但用户可以在需要时提供自己的策略.

uint_parser

该类是数值包成员中最简单的一个. uint_parser 可以解析任意长度和大小的无符号整数. uint_parser 解析器可用于解析普通的原始 C/C++ 整数, 甚至用户自定义标量, 如 bigint(无限精度整数). 与 Spirit 中的大多数类一样, uint_parser 是一个模板类. 模板参数可对其行为进行微调. uint_parser 非常灵活, 以至于其他数值解析器都以它为主干来实现.

    template <
        typename T = unsigned,
        int Radix = 10,
        unsigned MinDigits = 1,
        int MaxDigits = -1>
    struct uint_parser { /*...*/ };
uint_parser 模板参数
T 数值解析器的数值基类型. 默认为 unsigned
Radix 基数. 可以是 2: 二进制, 8: 八进制, 10: 十进制和 16: 十六进制. 默认为 10; 十进制
MinDigits 允许的最小位数
MaxDigits 允许的最大位数. 若为 -1, 则上限变为无界

预定义 uint_parsers
bin_p uint_parser<unsigned, 2, 1, -1> const
oct_p uint_parser<unsigned, 8, 1, -1> const
uint_p uint_parser<unsigned, 10, 1, -1> const
hex_p uint_parser<unsigned, 16, 1, -1> const

以下示例展示了如何使用 uint_parser 解析以千位分隔符分隔的数字. 该示例可以正确解析诸如 1,234,567,890 这样的数字.

    uint_parser<unsigned, 10, 1, 3> uint3_p;        //  1..3 digits
    uint_parser<unsigned, 10, 3, 3> uint3_3_p;      //  exactly 3 digits
    ts_num_p = (uint3_p >> *(',' >> uint3_3_p));    //  our thousand separated number parser

bin_p, oct_p, uint_p 和 hex_p 是设计为在表达式中使用的解析器生成器对象. 下面是一个解析以逗号分隔的数字列表的规则示例(我们在 此前见过它):

    list_of_numbers = real_p >> *(',' >> real_p);

稍后, 我们将看到如何提取数值解析器实际解析出的数字. 我们将在 specialized actions 一节中处理这个问题.

int_parser

int_parser 可以解析任意长度和大小的有符号整数. 它与 uint_parser 几乎相同. 唯一的区别是额外的任务: 解析数字前面的 '+' 或 '-' 符号. 类接口与 uint_parser 相同.

预定义 int_parser
int_p int_parser<int, 10, 1, -1> const

real_parser

real_parser 可以解析任意长度和大小(受其参数化类型 T 限制)的实数. real_parser 是一个有 2 个模板参数的模板类. 下面是 real_parser 的模板接口:

    template<
        typename T = double,
        typename RealPoliciesT = ureal_parser_policies<T> >
    struct real_parser;

第一个模板参数是它的数值基类型 T. 其默认值为 double.

解析特殊数值类型

注意, 数值基类型 T 可以由用户指定. 这意味着我们可以用数值解析器解析用户自定义的数值类型, 如 fixed_point(定点实数)和 bigint(无限精度整数).

第二个模板参数是一个汇集所有策略的类, 默认为 ureal_parser_policies<T>. 策略控制实数解析器的行为. 所提供的默认策略被设计为解析 nnn.fff.Eeee 形式的 C/C++ 风格实数, 其中 nnn 是整数部分, fff 是小数部分, E 是 'e' 或 'E', 而 eee 是指数, 可选地以 '-' 或 '+' 为前导. 这对应于以下文法, 区别在于默认情况下也接受不带小数点的普通整数.

    floatingliteral
        =   fractionalconstant >> !exponentpart
        |  +digit_p >> exponentpart
        ;

    fractionalconstant
        =  *digit_p >> '.' >> +digit_p
        |  +digit_p >> '.'
        ;

    exponentpart
        =   ('e' | 'E') >> !('+' | '-') >> +digit_p
        ;

提供默认策略是为了照顾最常见的情况(实数的表示方式有很多种, 因而解析方式也有很多种). 在大多数情况下, real_parser 的默认设置已经足够, 可以开箱即用. 实际上, 框架预定义了四个可直接使用的 real_parser:

预定义 real_parsers
ureal_p real_parser<double, ureal_parser_policies<double> > const
real_p real_parser<double, real_parser_policies<double> > const
strict_ureal_p real_parser<double, strict_ureal_parser_policies<double> > const
strict_real_p real_parser<double, strict_real_parser_policies<double> > const

我们之前已见过 real_p. ureal_p 是它的无符号变体.

严格实数

整数被视为实数的子集, 因此 real_p 与 ureal_p 把整数(不带点)识别为实数. strict_real_p 与 strict_ureal_p 是等价的解析器, 它们 要求必须存在小数点, 一个数才被视为成功的匹配.

进阶: real_parser 策略

解析器策略把实数解析分解为 6 个步骤:

1 parse_sign 解析前导符号
2 parse_n 解析小数点左边的整数
3 parse_dot 解析小数点
4 parse_frac_n 解析小数点之后的小数部分
5 parse_exp 解析指数前缀(如 'e')
6 parse_exp_n 解析实际的指数

而这些子解析任务的交互进一步由以下 3 个策略控制:

1 allow_leading_dot 允许出现前导点(".1" 变为等价于 "0.1")
2 allow_trailing_dot 允许出现尾随点("1." 变为等价于 "1.0")
3 expect_dot 要求必须出现小数点(不允许 "1" 等价于 "1.0")

sign_parser 与 sign_p

在继续之前, 这里包含一个小的实用解析器, 用于简化 '-' 或 '+' 符号的解析. 虽然很容易自己写一个:

    sign_p = (ch_p('+') | '-');

但若不借助语义动作, 就无法提取实际的符号(正或负). sign_p 解析器有一个 bool 属性, 通过匹配对象返回给调用者, 解析之后, 若解析出的符号为负, 该属性被设为 true. 该属性检测是否解析出了负号. 示例:

    bool is_negative;
    r = sign_p[assign_a(is_negative)];

或者更简单地...

    // directly extract the result from the match result's value
    bool is_negative = sign_p.parse(scan).value();

sign_p 解析器期望所挂接的语义动作具有与以下签名兼容的签名(更多细节见 Specialized Actions):

函数的签名:

    void func(bool is_negative);

函数对象的签名: 

    struct ftor
    {
        void operator()(bool is_negative) const;
    };

ureal_parser_policies

    template <typename T>
    struct ureal_parser_policies
    {
        typedef uint_parser<T, 10, 1, -1>   uint_parser_t;
        typedef int_parser<T, 10, 1, -1>    int_parser_t;

        static const bool allow_leading_dot  = true;
        static const bool allow_trailing_dot = true;
        static const bool expect_dot         = false;

        template <typename ScannerT>
        static typename match_result<ScannerT, nil_t>::type
        parse_sign(ScannerT& scan)
        { return scan.no_match(); }

        template <typename ScannerT>
        static typename parser_result<uint_parser_t, ScannerT>::type
        parse_n(ScannerT& scan)
        { return uint_parser_t().parse(scan); }

        template <typename ScannerT>
        static typename parser_result<chlit<>, ScannerT>::type
        parse_dot(ScannerT& scan)
        { return ch_p('.').parse(scan); }

        template <typename ScannerT>
        static typename parser_result<uint_parser_t, ScannerT>::type
        parse_frac_n(ScannerT& scan)
        { return uint_parser_t().parse(scan); }

        template <typename ScannerT>
        static typename parser_result<chlit<>, ScannerT>::type
        parse_exp(ScannerT& scan)
        { return as_lower_d['e'].parse(scan); }

        template <typename ScannerT>
        static typename parser_result<int_parser_t, ScannerT>::type
        parse_exp_n(ScannerT& scan)
        { return int_parser_t().parse(scan); }
    };

默认的 ureal_parser_policies 使用低层整数数值解析器来完成其工作.

real_parser_policies

    template <typename T>
    struct real_parser_policies : public ureal_parser_policies<T>
    {
        template <typename ScannerT>
        static typename parser_result<sign_parser, ScannerT>::type
        parse_sign(ScannerT& scan)
        { return sign_p.parse(scan); }
    };

注意 real_parser_policies 如何替换了 parse_sign —— 该策略继承自 ureal_parser_policies. 默认的 real_parser_policies 在 parse_sign 步骤中简单地使用 sign_p 而非 scan.no_match().

strict_ureal_parser_policies 与 strict_real_parser_policies

    template <typename T>
    struct strict_ureal_parser_policies : public ureal_parser_policies<T>
    {
        static const bool expect_dot = true;
    };

    template <typename T>
    struct strict_real_parser_policies : public real_parser_policies<T>
    {
        static const bool expect_dot = true;
    };

同样, 这些策略只替换了它们希望不同于其父类的那些策略.

特化的实数解析器策略可以在替换部分策略的同时复用一些默认策略. 例如, 以下是一个解析带千位分隔符, 最多两位小数且无指数的数字的实数解析器策略.

完整源代码可在 此处查看.

    template <typename T>
    struct ts_real_parser_policies : public ureal_parser_policies<T>
    {
        //  These policies can be used to parse thousand separated
        //  numbers with at most 2 decimal digits after the decimal
        //  point. e.g. 123,456,789.01

        typedef uint_parser<int, 10, 1, 2>  uint2_t;
        typedef uint_parser<T, 10, 1, -1>   uint_parser_t;
        typedef int_parser<int, 10, 1, -1>  int_parser_t;

        //////////////////////////////////  2 decimal places Max
        template <typename ScannerT>
        static typename parser_result<uint2_t, ScannerT>::type
        parse_frac_n(ScannerT& scan)
        { return uint2_t().parse(scan); }

        //////////////////////////////////  No exponent
        template <typename ScannerT>
        static typename parser_result<chlit<>, ScannerT>::type
        parse_exp(ScannerT& scan)
        { return scan.no_match(); }

        //////////////////////////////////  No exponent
        template <typename ScannerT>
        static typename parser_result<int_parser_t, ScannerT>::type
        parse_exp_n(ScannerT& scan)
        { return scan.no_match(); }

        //////////////////////////////////  Thousands separated numbers
        template <typename ScannerT>
        static typename parser_result<uint_parser_t, ScannerT>::type
        parse_n(ScannerT& scan)
        {
            typedef typename parser_result<uint_parser_t, ScannerT>::type RT;
            static uint_parser<unsigned, 10, 1, 3> uint3_p;
            static uint_parser<unsigned, 10, 3, 3> uint3_3_p;

            if (RT hit = uint3_p.parse(scan))
            {
                T n;
                typedef typename ScannerT::iterator_t iterator_t;
                iterator_t save = scan.first;
                while (match<> next = (',' >> uint3_3_p[assign_a(n)]).parse(scan))
                {
                    hit.value() *= 1000;
                    hit.value() += n;
                    scan.concat_match(hit, next);
                    save = scan.first;
                }
                scan.first = save;
                return hit;

                // Note: On erroneous input such as "123,45", the result should
                // be a partial match "123". 'save' is used to makes sure that
                // the scanner position is placed at the last *valid* parse
                // position.
            }
            return scan.no_match();
        }
    };
