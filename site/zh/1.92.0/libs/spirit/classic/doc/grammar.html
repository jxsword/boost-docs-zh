文法

文法(grammar)封装了一组规则. grammar 类是一个协议基类, 本质上是一份接口契约. grammar 是一个模板类, 由其派生类 DerivedT 和其上下文 ContextT 参数化. 模板参数 ContextT 默认为 parser_context, 一个预定义的上下文.

除非你想要调整文法的底层行为, 否则完全无需关心 ContextT 模板参数. 有关 ContextT 模板参数的详细信息在 其他地方提供. grammar 依赖模板参数 DerivedT —— 一个文法子类 —— 来定义实际规则.

下面给出公开 API. 在 ContextT 之后实际上可能还有更多模板参数. ContextT 参数之后的一切都不属于使用者需要关心的事项, 仅供内部使用.

    template<
        typename DerivedT,
        typename ContextT = parser_context<> >
    struct grammar;

文法定义

继承自 grammar 的具体子类应当拥有一个名为 definition 的嵌套模板类(或结构体):

它是一个带有 typename ScannerT 参数的嵌套模板类.
其构造函数定义文法规则.
其构造函数被传入对实际文法 self 的引用.
它拥有一个名为 start 的成员函数, 该函数返回对开始 rule 的引用.

文法骨架

    struct my_grammar : public grammar<my_grammar>
    {
        template <typename ScannerT>
        struct definition
        {
            rule<ScannerT>  r;
            definition(my_grammar const& self)  { r = /*..define here..*/; }
            rule<ScannerT> const& start() const { return r; }
        };
    };

将扫描器类型与构成文法的规则解耦, 使得文法可以在不同上下文中使用, 可能使用不同的扫描器. 我们并不关心面对的是什么扫描器. 用户自定义的 my_grammar 可以与 任何类型的扫描器一起使用. 与 rule 不同, 文法不与特定扫描器类型绑定. 关于为什么这很重要, 以及进一步理解这一扫描器-规则耦合问题, 请见 "Scanner Business".

实例化并使用 my_grammar

我们上面的文法可以被实例化并投入使用:

    my_grammar g;

    if (parse(first, last, g, space_p).full)
        cout << "parsing succeeded\n";
    else
        cout << "parsing failed\n";

my_grammar IS-A 解析器, 可以在任何期望解析器的地方使用, 甚至可以被另一条规则引用:

    rule<>  r = g >> str_p("cool huh?");
引用文法

与 rule 一样, 文法被置于 EBNF 表达式的右侧时也是以引用方式持有的. 使用者有责任确保被引用的文法保持在作用域内, 在其被引用期间不被销毁.

完整文法示例

回顾我们最初的计算器示例, 现在用文法重写如下:

    struct calculator : public grammar<calculator>
    {
        template <typename ScannerT>
        struct definition
        {
            definition(calculator const& self)
            {
                group       = '(' >> expression >> ')';
                factor      = integer | group;
                term        = factor >> *(('*' >> factor) | ('/' >> factor));
                expression  = term >> *(('+' >> term) | ('-' >> term));
            }

            rule<ScannerT> expression, term, factor, group;

            rule<ScannerT> const&
            start() const { return expression; }
        };
    };

带有 语义动作的完整可运行示例可 在此查看. 它是 Spirit 发行包的一部分.

self

你可能注意到, 文法的 definition 有一个接受外层文法 const 引用的构造函数. 在上面的示例中, 注意 calculator::definition 接收一个 calculator const& self. 虽然在上例中它未被使用, 但在许多情况下这非常有用. self 实参是 definition 通向外部世界的窗口. 例如, calculator 类可能持有对某些状态信息的引用, definition 可以在解析进行时通过 语义动作更新这些信息.

文法胶囊

当文法变得复杂时, 把各部分归组为逻辑模块是个好主意. 例如, 在编写一门语言时, 把表达式和语句放入单独的文法胶囊中可能是明智的. 文法充分利用了 C++ 类的封装特性. 类的声明式本质使其非常适合文法的定义. 由于文法不过是一个类声明, 我们可以方便地把它发布到头文件中. 这样做的理念是: 一旦编写完成并经过充分测试, 文法便可在多种上下文中重用. 我们由此有了文法库的概念.

可重入性与多线程

文法的一个实例可以在不同位置多次使用而没有任何问题. 实现经过了调校, 以一些开销为代价允许这一点. 然而, 若能确定某个文法只会有单一实例, 我们就可以节省相当多的周期与字节. 若希望如此, 只需在包含任何 spirit 头文件之前定义 BOOST_SPIRIT_SINGLE_GRAMMAR_INSTANCE.

    #define BOOST_SPIRIT_SINGLE_GRAMMAR_INSTANCE

另一方面, 若文法打算用于多线程代码, 我们则应在包含任何 spirit 头文件之前定义 BOOST_SPIRIT_THREADSAFE. 这种情况下还需要链接 Boost.Threads

    #define BOOST_SPIRIT_THREADSAFE

使用多个文法开始规则

有时希望一个文法拥有不止一个可见入口点(除了开始规则之外). 为了允许额外的起始点, Spirit 提供了辅助模板 grammar_def, 可用作你的 grammar 的 definition 子类的基类. 下面是一个例子:

    // this header has to be explicitly included
    #include <boost/spirit/utility/grammar_def.hpp> 

    struct calculator2 : public grammar<calculator2>
    {
        enum 
        {
            expression = 0,
            term = 1,
            factor = 2,
        };

        template <typename ScannerT>
        struct definition
        : public grammar_def<rule<ScannerT>, same, same>
        {
            definition(calculator2 const& self)
            {
                group       = '(' >> expression >> ')';
                factor      = integer | group;
                term        = factor >> *(('*' >> factor) | ('/' >> factor));
                expression  = term >> *(('+' >> term) | ('-' >> term));

                this->start_parsers(expression, term, factor); 
            }

            rule<ScannerT> expression, term, factor, group;
        };
    };

grammar_def 模板必须以你希望从 grammar 外部可见的所有规则的类型来实例化:

    grammar_def<rule<ScannerT>, same, same>

简写记法 same 用于指示使用与前一个模板参数所指定的相同类型(如 rule<ScannerT>). 显然, same 不能用作第一个模板参数.

grammar_def 开始类型

或许并不显眼, 但值得注意的是, 除 rule<> 之外, 任何解析器类型都可以被指定(如 chlit<>, strlit<>, int_parser<> 等).

使用 grammar_def 类之后, 不再需要提供 start()成员函数. 作为替代, 你必须插入一次对 this->start_parsers()(它是 grammar_def 模板的成员函数)的调用, 为你的 grammar 定义开始符号. 注意, 作为 start_parsers() 函数实参使用的规则, 其数量与顺序应与 grammar_def 模板中指定的类型相匹配:

    this->start_parsers(expression, term, factor);

文法入口点可以使用以下语法指定:

    g.use_parser<N>() // Where g is your grammar and N is the Nth entry.

这个示例展示如何使用上面 calculator2 文法中的 term 规则:

    calculator2 g;

    if (parse(
            first, last, 
            g.use_parser<calculator2::term>(),
            space_p
        ).full)
    {
        cout << "parsing succeeded\n";
    }
    else {
        cout << "parsing failed\n";
    }

use_parser<> 模板类型的模板参数应当是 start_parsers() 函数调用中所指定规则列表的从零开始的索引.

use_parser<0>

注意, 使用 0(零)作为 use_parser 的模板参数, 等价于使用通过常规手段经 start() 函数导出的开始规则, 如上面第一个 calculator 示例所示. 因此, 即使是仅通过其 start() 函数导出一条规则的文法, 也可以使用这种记法. 另一方面, 不带 use_parser 记法调用 grammar, 将执行被指定为 start_parsers() 函数第一个参数的规则.

可用开始规则的最大数量受以下预处理器常量限制:

    BOOST_SPIRIT_GRAMMAR_STARTRULE_TYPE_LIMIT // defaults to 3
