Phoenix

前一章介绍了 Phoenix 作为实现语义动作的手段. 我们将更深入地考察这个重要的库, 重点关注如何将它与 Spirit 便捷地配合使用. 本章绝不是对该库的详尽论述. 有关 Phoenix 的更多信息, 请抽时间阅读 Phoenix User's Guide. 如果你只想快速上手, 本章大概就够了. 我们不打算把你带进该库的理论与细节, 而是力图为你提供带有注解的范例. 希望这能让你迅速进入高速档.

Spirit 中的语义动作几乎可以是任何函数或函数对象(functor), 只要它能满足所需的签名. 例如, uint_p 要求 void F(T) 形式的签名, 其中 T 是整数的类型(通常为 unsigned int). 原生动作则是 void F(IterT, IterT) 一类的. 你可以用纯 C++ 编写动作. 对 C++ 函数或函数对象的调用因此形如 P[&F] 或 P[F()] 等(见 Semantic Actions). 而 Phoenix 则尝试模仿 C++, 使你能够把函数体内联在代码中定义.

用 C++ 模仿 C++?

Spirit 在 C++ 中尝试模仿 EBNF, 同样地, Phoenix 在 C++ 中尝试模仿 C++!!!

var

还记得 boost::ref 吗? 我们在 Parametric Parsers 一章讨论过它. Phoenix 有一个类似但更灵活的对应物. 它叫做 var. 其用法与 boost::ref 相似, 可以直接替换使用. 然而, 与 boost::ref 不同, 你可以用它构成更复杂的表达式. 这里有一些示例:

    var(x) += 3
    var(x) = var(y) + var(z)
    var(x) = var(y) + (3 * var(z))
    var(x) = var(y)[var(i)] // assuming y is indexable and i is an index

让我们从一个简单的例子开始. 我们想解析一个以逗号分隔的数字列表, 并报告所有数字的总和. 使用 phoenix 的 var, 我们不必编写外部语义动作, 只需把代码内联在语义动作槽位中. 下面是带有 phoenix 动作的完整文法(见 examples 中的 sum.cpp):

    real_p[var(n) = arg1] >> *(',' >> real_p[var(n) += arg1])

完整源代码可 在此查看. 它是 Spirit 发行包的一部分.

argN

注意表达式: var(n) = arg1 . arg1 是什么, 它在那里做什么? arg1 是实参占位符. 记得 real_p(见 Numerics)会把解析出的数字报告给它所挂接的语义动作. arg1 是解析器传给语义动作的第一个实参的占位符. 若传入的实参多于一个, 可以用 arg1..argN 来引用这些实参. 例如, 泛型语义动作(转导接口; 见 Semantic Actions)会被传入 2 个实参: 指向输入流中匹配部分的迭代器(first/last). 你可以分别通过 arg1 和 arg2 引用 first 与 last.

与 var 一样, argN 也是可组合的. 这里有一些示例:

    var(x) += arg1
    var(x) = arg1 + var(z)
    var(x) = arg1 + (3 * arg2)
    var(x) = arg1[arg2] // assuming arg1 is indexable and arg2 is an index

val

注意表达式: 3 * arg2. 该表达式实际上是 val(3) * arg2 的简写等价形式. 稍后我们将看到, 在某些情况下为何需要把常量与字面量显式地包裹在 val 中. 同样, 与 var 和 argN 一样, val 也是可组合的.

函数

还记得我们最初的那个例子吗? 在 Quick Start 一章中, 我们给出了一个解析以逗号分隔的列表并把解析出的数字塞进 vector 的解析器(见 number_list.cpp). 为简单起见, 我们使用了 Spirit 的预定义 actor(见 Predefined Actors). 在该示例中, 我们使用了 push_back_a:

    real_p[push_back_a(v)] >> *(',' >> real_p[push_back_a(v)])

Phoenix 使你能够轻松编写更强大的多态函数, 与 push_back_a 类似. 见 stuff_vector.cpp. 该示例在功能上与 number_list.cpp 相似, 但这一次使用 phoenix 函数实际实现 push_back 函数:

    struct push_back_impl
    {
        template <typename Container, typename Item>
        struct result
        {
            typedef void type;
        };

        template <typename Container, typename Item>
        void operator()(Container& c, Item const& item) const
        {
            c.push_back(item);
        }
    };

    function<push_back_impl> const push_back = push_back_impl();

完整源代码可 在此查看. 它是 Spirit 发行包的一部分.

预定义 Phoenix 函数

Phoenix 的未来版本将包含一套广泛的预定义函数, 覆盖整个 STL 容器, 迭代器与算法. push_back 将是该套件的一部分.

push_back_impl 是 STL 容器的 push_back 成员函数之上的简单封装. 额外的脚手架用于向 phoenix 提供否则无法直接推导的附加信息. result 在给定实参类型(Container 和 Item)时, 向 phoenix 转达函数对象(operator())的返回类型. 在本例中, 返回类型始终就是 void.

push_back 是一个 phoenix 函数对象. 这才是我们实际要用的函数对象. phoenix 函数对象的美妙之处在于: 其实际使用与普通 C++ 函数调用惊人地相似. 下面是用我们的 phoenix 函数对象重写的数字列表解析器:

    real_p[push_back(var(v), arg1)] >> *(',' >> real_p[push_back(var(v), arg1)])

而且, 与预定义 actor 不同, 它们可以被组合. 看出规律了吗? 这里有一些示例:

    push_back(var(v), arg1 + 2)
    push_back(var(v), var(x) + arg1)
    push_back(var(v)[arg1], arg2) // assuming v is a vector of vectors and arg1 is an index

push_back 没有返回类型. 举例来说, 假设我们编写了另一个 phoenix 函数 sin, 我们同样可以在表达式中使用它:

    push_back(var(v), sin(arg1) * 2)

构造

有时, 我们希望构造一个对象. 例如, 我们可能想根据 first/last 迭代器创建一个 std::string. 又比如, 假设我们想解析的是标识符列表. 去掉动作后, 我们的文法是:

    (+alpha_p) >> *(',' >> (+alpha_p))

construct_ 是一个预定义的 phoenix 函数, 你猜对了 —— 它根据传入的实参构造一个对象. 用法为:

    construct_<T>(arg1, arg2,... argN)

其中 T 是所需的类型, arg1..argN 是构造函数实参. 例如, 我们可以这样从 first/last 迭代器对构造一个 std::string:

    construct_<std::string>(arg1, arg2)

现在, 我们把动作挂接到文法上:

    (+alpha_p)
    [
        push_back(var(v), construct_<std::string>(arg1, arg2))
    ]
    >>
    *(',' >>
        (+alpha_p)
        [
            push_back(var(v), construct_<std::string>(arg1, arg2))
        ]
    )

完整源代码可 在此查看. 它是 Spirit 发行包的一部分.

Lambda 表达式

上面看到的所有这些 phoenix 表达式都是 lambda 表达式. 需要注意的重要一点是: 这些表达式不会立即求值. 在文法构造时, 当动作被挂接到产生式上时, lambda 表达式实际上会生成一个未命名的函数对象, 它将在稍后解析时才被求值. 换句话说, lambda 表达式是 惰性求值的.

Lambda 表达式?

lambda 表达式实际上是未命名的部分应用函数, 其中占位符(如 arg1, arg2)被放在某些实参的位置上. 之所以称为 lambda 表达式, 是因为传统上这类占位符用希腊字母 lambda 书写.

Phoenix 使用与 Spirit 所用手法相仿的技巧来模仿 C++, 使你能够在代码中内联定义函数体. 这很怪异, 但如前所述, Phoenix 实际上是在用表达式模板在 C++ 中模仿 C++. 当然, 存在限制...

Phoenix 表达式中的所有成分都必须是一个 actor(phoenix 术语), 就像 Spirit 中的成分应当是 parser 一样. 在 Spirit 中, 你可以写:

    r = ch_p('x') >> 'y';

但不可以写:

    r = 'x' >> 'y';

本质上, parser >> char 是一个解析器, 而 char >> char 是一个 char(char 右移另一个 char).

同样的限制也适用于 Phoenix. 例如:

    int x = 1;
    cout << var(x) << "pizza"

是一个良构的, 惰性求值的 Phoenix 表达式. 但是:

    cout << x << "pizza"

则不是. 这类表达式会被立即执行. C++ 语法规定, 操作数中至少 一个必须是 Phoenix actor 类型. 这同样适用于复合表达式. 例如:

    cout << var(x) << "pizza" << "man"

它被求值为:

    (((cout << var(x)) << "pizza") << "man")

由于 (cout << var(x)) 是一个 actor, 即操作数中至少 一个是 phoenix actor, ((cout << var(x)) << "pizza") 同样是一个 Phoenix actor, 因此整个表达式也是一个 actor.

有时, 写成这样是安全的:

    cout << var(x) << val("pizza") << val("man")

只是为了让所处理的对象显式明了, 尤其是在复杂表达式中, 就像我们在 Spirit 中把字面量字符串显式包裹在 str_p("lit") 中一样.

Phoenix(和 Spirit)还要处理一元运算符. 在这种情况下, 我们别无选择: 操作数必须是 Phoenix actor(或 Spirit 解析器). 例如:

Spirit:

    *ch_p('z')  // good
    *('z') // bad

Phoenix:

    *var(x) // good (lazy)
    *x // bad (immediate)

此外, 在 Phoenix 中, 要让赋值与索引惰性求值, 被操作的对象应当是 Phoenix actor. 例如:

    var(x) = 123 // good (lazy)
    x = 123 // bad (immediate)
    var(x)[0] // good (lazy)
    x[0] // bad, immediate
    var(x)[var(i)] // good (lazy)
    x[var(i)] // bad and illegal (x is not an actor)
    var(x[var(i)]) // bad and illegal (x is not an actor)
