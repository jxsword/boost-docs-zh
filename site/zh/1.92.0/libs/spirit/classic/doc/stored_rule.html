可存储规则

规则是一个怪异的 C++ 公民, 不同于任何其他 C++ 对象. 它不具备正确的拷贝与赋值语义, 不能按值存储与传递. 你不能把规则存入 STL 容器(vector, stack 等)以备后用, 也不能按值向函数传入或从函数返回规则.

EBNF 主要是声明式的. 与函数式编程一样, EBNF 文法是一份静态的配方, 没有"先做这个再做那个"的概念. 然而, 在 Spirit 中, 我们设法哄骗命令式的 C++ 接受声明式的 EBNF. 哈! 有趣!... 我们的做法是伪装 C++ 赋值运算符来模仿 EBNF 的 ::=. 为此, 我们赋予了规则类的赋值运算符与拷贝构造函数不同的含义与语义. 坏处是这样做使规则不同于任何其他 C++ 对象. 你不能拷贝它. 你不能赋值它.

我们想让 C++ 的动态本性为我们所用. 我们已经在这里或那里见过动态 Spirit 的实际运用. 用 Spirit 构建的动态解析器确实有一些有趣的应用. 然而, 除非我们拥有一条行为与任何其他良好 C++ 对象一样的规则, 否则我们将无法充分利用动态解析的力量. 有了这样的猛兽, 我们就能编写在运行期(而非编译期)定义的完整解析器.

我们现在有了动态规则: stored_rules. 基本上, 它们是具有完美 C++ 赋值/拷贝构造语义的规则. 这意味着 stored_rules 可以存储在容器中, 并且/或者可以在运行期动态创建.

    template<
        typename ScannerT = scanner<>,
        typename ContextT = parser_context<>,
        typename TagT = parser_address_tag>
    class stored_rule;

该接口与 rule 类完全相同(有关 API 的更多信息见 规则一节). 唯一的区别在拷贝与赋值语义. 现在, 有了 stored_rule, 我们可以动态地, 以算法方式定义我们的规则. 这里是一些示例...

假设我想为如下内容动态创建一条规则:

    start = *(a | b | c);

我可以分步动态地编写它:

    stored_rule<>  start;

    start = a;
    start = start.copy() | b;
    start = start.copy() | c;
    start = *(start.copy());

后来, 我改变了主意, 想把它(再次动态地)重定义为:

    start = (a | b) >> (start | b);

我这样写:

    start = b;
    start = a | start.copy();
    start = start.copy() >> (start | b);

注意这条语句:

    start = start.copy() | b;

为什么需要 start.copy()? 嗯, 因为与规则一样, stored rule 在 RHS 中被找到时仍然按引用嵌入(原因之一是避免循环共享指针). 如果我们写:

    start = start | b;

我们就有了 左递归! 拷贝 start 的副本可以避免自引用. 我们所做的, 是复制一份 start, 与 b 求或, 然后把结果破坏性地赋回 start.
