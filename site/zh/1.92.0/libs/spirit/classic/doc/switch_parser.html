switch 解析器

switch 解析器可用于简化某些候选构造. 看下面的代码:

    rule<> rule_overall =
            ch_p('a') >> parser_a
        |   ch_p('b') >> parser_b
            // ...
        |   ch_p('n') >> parser_n
        ;

各候选分支以顺序方式正常求值. 这往往效率低下, 尤其是候选分支数量很大时. 为避免这种低效, 并使这类构造能以更可读的形式书写, Spirit 提供了 switch_p 解析器家族. switch_p 解析器使我们能把前面的构造重写为:

    rule<> rule_overall =
            switch_p
            [
                case_p<'a'>(parser_a),
                case_p<'b'>(parser_b),
                // ...
                case_p<'n'>(parser_n)
            ]
        ;

这个 switch_p 解析器从输入流中取下一个字符(或记号), 并尝试把它与作为 case_p 解析器模板参数提供的整型编译期常量进行匹配. 若该字符匹配某个 case_p 分支, 则执行关联的解析器(即: 若匹配 'a', 则执行 parser_a; 若匹配 'b', 则执行 parser_b, 依此类推). 若没有 case_p 分支匹配下一个输入字符, 则整个构造完全不匹配.

Nabialek 技巧

"Nabialek trick" (以其发明者 Sam Nabialek 的名字命名)同样能把规则分派从线性非确定性改进为确定性. 它类似于 switch_p 解析器, 但能处理在产生式之前出现的是关键字(运算符等)而非单个字符或记号的文法.

有时, 希望增加对默认情况(没有任何 case_p 分支匹配)的处理. 这可以借助 default_p 分支来实现:

    rule<> rule_overall =
            switch_p
            [
                case_p<'a'>(parser_a),
                case_p<'b'>(parser_b),
                // ...
                case_p<'n'>(parser_n),
                default_p(parser_default)
            ]
        ;

这种形式在没有任何 case 分支匹配输入流的下一个字符时选择 parser_default 解析器. 请注意, 显然, switch_p 解析器构造中只能加入一个 default_p 分支.

此外, default_p 构造可以省略圆括号和主体, 此时不会执行任何附加解析器, 整个 switch_p 构造对任何不匹配任何 case_p 分支的输入流字符直接返回一次匹配:

    rule<> rule_overall =
            switch_p
            [
                case_p<'a'>(parser_a),
                case_p<'b'>(parser_b),
                // ...
                case_p<'n'>(parser_n),
                default_p
            ]
        ;

switch_p 构造还有另一种形式. 这种形式允许我们显式指定用于与 case_p 分支匹配的值:

    rule<> rule_overall =
            switch_p(cond)
            [
                case_p<'a'>(parser_a),
                case_p<'b'>(parser_b),
                // ...
                case_p<'n'>(parser_n)
            ]
        ;

其中 cond 是一个解析器, 或一个零参函数或函数对象(functor). 若它是解析器, 则会尝试它, 并用其返回值与 case_p 分支匹配. 若它是零参函数或函数对象, 则使用其返回值.

请注意, 在编译期间, switch_p 构造会被变换为真正的 C++ switch 语句. 这使运行期执行非常高效.

BOOST_SPIRIT_SWITCH_CASE_LIMIT

可能的 case_p/default_p 分支数量受 Spirit 编译期常量 BOOST_SPIRIT_SWITCH_CASE_LIMIT 限制, 其默认值为 3. 该常量没有理论上限, 但大多数编译器不允许你指定非常大的数字.

示例:

// Define these before including switch.hpp
#define BOOST_SPIRIT_SWITCH_CASE_LIMIT 10
