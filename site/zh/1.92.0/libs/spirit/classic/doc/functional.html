函数式

如果仔细观察, 你会注意到 Spirit 的全部内容就是 解析器函数的组合. 解析器只是一个接受扫描器并返回匹配的函数. 解析器函数被组合起来, 形成越来越复杂的 高阶形式. 还要注意, 解析器虽然是一个对象, 却是不可变且恒定的. 所有原语与组合解析器对象都是 const 的. parse 成员函数甚至被声明为 const:

    template <typename ScannerT>
    typename parser_result<self_t, ScannerT>::type
    parse(ScannerT const& scan) const;

从各方面来看, 这看起来和感觉上都很像 函数式编程. 而它确实如此. Spirit 无疑是函数式编程在命令式 C++ 领域的一次应用. 例如在 Haskell 中, 有所谓的 解析器组合子, 与 Spirit 采用的方法惊人地相似 —— 解析器函数通过各种运算符组合, 形成建模自顶向下递归下降解析器的高阶解析器函数. 那些聪明的 Haskell 人士早就走在 Spirit 之前这样做了.

函数式风格编程(或称 FP)库正在 C++ 社区中蓄势. 可以肯定, 现在和将来我们会在 Spirit 中看到更多 FP. 实际上, 若仔细观察, 连 C++ 标准库都有 FP 风味. 在标准 C++ 库核心的掩护之下, 深入观察 STL 就能一窥已然就位的真正 FP 范式. 显然, STL 的作者深谙并践行 FP.

FP 视角下的语义动作

STL 风格的 FP

STL 风格 FP 在 Spirit 中更明显的应用是语义动作. 什么是 STL 风格的 FP? 它主要是使用可组合成高阶函数对象的函数对象(functor).

函数对象

函数对象(Function Object), 或称 Functor, 就是任何可以像函数一样被调用的对象. 普通函数是函数对象, 函数指针也是; 更一般地, 定义了 operator() 的类的对象也是.

如今这种 STL 风格的 FP 随处可见. 下例取自 SGI 的标准模板库程序员指南:

    //  Computes sin(x)/(x + DBL_MIN) for each element of a range.

    transform(first, last, first,
              compose2(divides<double>(),
                       ptr_fun(sin),
                       bind2nd(plus<double>(), DBL_MIN)));

说真的, 这不过是 FP 术语中的 柯里化(currying).

柯里化

什么是 "柯里化", 它从何而来?

柯里化源于对函数的数学研究. Frege 在 1893 年观察到, 只需把注意力限制在单实参函数上就足够了. 例如, 对任何双参数函数 f(x,y), 存在一个单参数函数 f', 使得 f'(x) 是一个可应用于 y 的函数, 给出 (f'(x))(y) = f (x,y). 这对应于众所周知的事实: 集合 (AxB -> C) 与 (A -> (B -> C)) 同构, 其中 "x" 是笛卡尔积, "->" 是函数空间. 在函数式编程中, 函数应用以并置表示, 并假定向左结合, 因而上式变为 f' x y = f(x,y).

在 Spirit 的语境下, 同样的 FP 风格函数对象组合也可应用于语义动作. full_calc.cpp 是一个很好的例子. 以下是该示例的一个片段:

    expression =
        term
        >> *(   ('+' >> term)[make_op(plus<long>(), self.eval)]
            |   ('-' >> term)[make_op(minus<long>(), self.eval)]
            )
            ;

完整源代码可 在此查看. 它是 Spirit 发行包的一部分.

Boost 风格的 FP

Boost 把 FP 范式又向前推进了一步. boost 中有一些库专门关注函数对象与高阶编程.

Boost FP 库
bind 和 mem_fn 用于函数/对象/指针与成员函数的通用绑定器, 来自 Peter Dimov
function 用于延迟调用或回调的函数对象包装器, 来自 Doug Gregor
functional 增强的函数对象适配器, 来自 Mark Rodgers
lambda 在实际调用点定义小型无名函数对象等等, 来自 Jaakko Järvi 和 Gary Powell
ref 用于向泛型函数传递引用的实用库, 来自 Jaako Järvi, Peter Dimov, Doug Gregor 和 Dave Abrahams

下面这个例子使用 boost Bind 将一个成员函数用作 Spirit 语义动作. 你可以在文件 bind.cpp 中看到完整示例.

    class list_parser
    {
    public:

        typedef list_parser self_t;

        bool
        parse(char const* str)
        {
            return spirit::parse(str,

                //  Begin grammar
                (
                    real_p
                    [
                        bind(&self_t::add, this, _1)
                    ]

                    >> *(   ','
                            >>  real_p
                                [
                                    bind(&self_t::add, this, _1)
                                ]
                        )
                )
                ,
                //  End grammar

                space_p).full;
        }

        void
        add(double n)
        {
            v.push_back(n);
        }

        vector<double> v;
    };

完整源代码可 在此查看. 它是 Spirit 发行包的一部分.

该解析器解析一个以逗号分隔的实数列表, 并把它们存入 vector<double>. Boost.bind 从 list_parser 的成员函数 add 创建了一个符合 Spirit 规范的语义动作.

Lambda 与 Phoenix

有一个由在下本人编写的库, 名为 Phoenix. 虽然它并非 Spirit 发行包的正式组成部分, 这个库已被广泛用于在 C++ 中试验高级 FP 技术. 该库深受 FC++ 与 boost Lambda(BLL)的影响.

BLL

Phoenix 既受 boost Lambda(BLL)影响, 它的诸如局部变量, 局部函数和可适配闭包等创新, 反过来又影响了 BLL. 目前, BLL 与 Phoenix 已非常相似. 最重要的是, BLL 吸纳了 Phoenix 的可适配闭包. 未来 Spirit 将完全支持 BLL.

Phoenix 允许通过 lambda(匿名函数)表达式在 C++ 中内联编写语义动作. 以下是 phoenix_calc.cpp 示例中的一个片段:

    expression
        =   term[expression.val = arg1]
            >> *(   ('+' >> term[expression.val += arg1])
                |   ('-' >> term[expression.val -= arg1])
                )
        ;

    term
        =   factor[term.val = arg1]
            >> *(   ('*' >> factor[term.val *= arg1])
                |   ('/' >> factor[term.val /= arg1])
                )
        ;

    factor
        =   ureal_p[factor.val = arg1]
        |   '(' >> expression[factor.val = arg1] >> ')'
        |   ('-' >> factor[factor.val = -arg1])
        |   ('+' >> factor[factor.val = arg1])
        ;

完整源代码可 在此查看. 它是 Spirit 发行包的一部分.

你暂时不必担心细节. 这里有太多需要解释的东西. 后续章节会给出启发.

注意诸如这样的 lambda 表达式的用法:

    expression.val += arg1
Lambda 表达式?

lambda 表达式实际上是未命名的部分应用函数, 其中占位符(如 arg1, arg2)被放在某些实参的位置上. 之所以称为 lambda 表达式, 是因为传统上这类占位符用希腊字母 lambda 书写.

其中 expression.val 是 expression 规则的闭包变量(见 Closures). arg1 是语义动作将接收的第一个实参的占位符(见 Phoenix Place-holders). 在 Boost.Lambda(BLL)中, 它对应于 _1.
