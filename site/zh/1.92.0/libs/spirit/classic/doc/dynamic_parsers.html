动态解析器

在 Spirit 中到处可见动态解析. 一组特殊的解析器, 恰如其分地被命名为动态解析器(dynamic parsers), 构成了动态解析最基本的构件. 本章聚焦于这些小家伙. 你会注意到这些解析器与 C++ 控制结构的相似性. 这种相似并非巧合. 这些解析器赋予解析一种命令式的风味, 而且, 由于命令式结构并非声明式 EBNF 的原生成分, 模仿宿主语言 C++ 应当能让它们的使用立刻变得熟悉.

动态解析器根据条件修改解析行为. 构造动态解析器需要一个条件实参和一个主体解析器实参. 某些解析器还需要额外的实参.

条件变量

返回值可转换为 bool 的函数或函数对象可以用作条件. 当函数/函数对象的求值结果为 true 时, 即视为满足条件.

解析器同样可以用作条件. 当解析器匹配时, 条件即满足. 用作条件的解析器以全有或全无的方式工作: 当它们不匹配时, 扫描器不会前进.

条件不满足不会导致解析错误.

if_p

if_p 可以带或不带 else 部分使用. 语法为:

    if_p(condition)[then-parser]

或

    if_p(condition)[then-parser].else_p[else-parser]

当条件满足时, then 解析器将在解析过程中接着被使用. 当条件不满足且存在 else 解析器时, 接着使用 else 解析器. 当条件不满足且不存在 else 解析器时, 整个解析器匹配空序列.( 注释: 较旧版本的 if_p 在条件不满足且无 else 解析器时报告失败.)

示例:

    if_p("0x")[hex_p].else_p[uint_p]

while_p, do_p

while_p/do_p 的语法为:

    while_p(condition)[body-parser]
    do_p[body-parser].while_p(condition)

只要条件满足, 由 while_p 构造的动态解析器就会尝试匹配主体解析器. do_p 返回一个解析器, 它先尝试匹配主体解析器, 然后行为与 while_p 返回的解析器完全一样. 主体解析器匹配失败将导致 while/do 解析器报告失败.

示例:

    uint_p[assign_a(sum)] >> while_p('+')[uint_p[add(sum)]]
    '"' >> while_p(~eps_p('"'))[c_escape_ch_p[push_back_a(result)]] >> '"'

假设 add 是用户自定义的函数对象.

for_p

for_p 需要四个实参. 语法为:

    for_p(init, condition, step)[body-parser]

init 与 step 必须是零参函数/函数对象. for_p 返回一个解析器, 它将:

  1. 调用 init
  2. 检查条件, 若条件不满足则返回一个匹配. 该匹配将覆盖到目前为止已成功匹配的全部内容.
  3. 尝试匹配主体解析器. 主体解析器匹配失败将导致 for 解析器报告失败
  4. 调用 step
  5. 跳转到 2.
