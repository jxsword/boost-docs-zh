风格指南

到某个时候, 尤其当各个位置挂接了大量语义动作时, 文法往往会变得相当难读. 为了让 Spirit 代码保持易读, 一致且美观的外观, 建议采用以下编码风格指南.

这种编码风格改编并扩展自 ANTLR/PCCTS 风格(Terrence Parr)和 Boost 编码指南(David Abrahams 与 Nathan Myers), 是 Joel de Guzman, Chris Uzdavinis 与 Hartmut Kaiser 的共同成果.

  • rule 名称使用标准 C++ (Boost) 约定. rule 名称可以很长.
  • '=' 整齐地缩进到下面 4 个空格处. 与 Boost 一样, 使用空格而非制表符.
  • 把操作数拆分到单独的行, 可以让语义动作整齐地靠右放置.
  • 最后一行的分号终止该 rule.
  • 序列的相邻部分应相应缩进, 使属于同一层级的所有内容都处在同一缩进层级.
    program
        =   program_heading [heading_action]
            >> block [block_action]
            >> '.'
        |   another_sequence
            >> etc
        ;
  • 在文法中优先使用字面量而非标识符. 例如用 "program" 而非 PROGRAM, 用 '>=' 而非 GTE, 用 '.' 而非 DOT. 这使代码更易读. 若无法做到(例如所用记号必须通过整数来标识的场合), 则应改用大写标识符.
  • 对短表达式, 可能无需拆分操作数. 例如 *(',' >> file_identifier), 只要该行不超过 80 个字符.
  • 如果序列能放在一行内, 则在括号内放入空格, 以便与 rule 清晰区分.
    program_heading
        =   as_lower_d["program"]
            >> identifier
            >> '('
            >> file_identifier
            >> *( ',' >> file_identifier )
            >> ')'
            >> ';'
        ;
  • 嵌套指令: 若一条规则无法放进一行(80 个字符), 应当换到下一行, 缩进一级.
  • 指令, 语义表达式(使用 Phoenix 或 LL lambda 表达式)或解析器的方括号应按如下方式放置.
    identifier
        =   nocase
            [
                lexeme
                [
                    alpha >> *(alnum | '_') [id_action]
                ]
            ]
        ;
  • 嵌套一元运算符(如 Kleene 星)
  • 若一条规则带有规则体或其后跟有一个放不进一行的序列, 则一元规则运算符(Kleene 星, '!', '+' 等)应向外移出一个空格, 到相应缩进层级之前. 这使格式更一致, 并把规则"体"放到与规则本身相同的缩进层级, 突出一元运算符.
    block
        =  *(   label_declaration_part
            |   constant_definition_part
            |   type_definition_part
            |   variable_declaration_part
            |   procedure_and_function_declaration_part
            )
            >> statement_part
        ;
