符号表

symbols 类实现了一个符号表. 符号表保存一个符号字典, 其中每个符号是一个 CharT 序列(char, wchar_t, int, 枚举等). 该模板类以字符类型(CharT)为参数, 可以高效处理 8, 16, 32 乃至 64 位字符. 每个符号关联有类型为 T 的可变数据.

传统上, 符号表管理是在 BNF 文法之外, 通过语义动作单独维护的. 与标准做法相反, Spirit 的符号表类 symbols is-a 解析器. 其实例可以在 EBNF 文法规范中的任何地方使用. 它是动态解析器的一个例子. 动态解析器的特征是能够在运行期修改自身行为. 起初, 空的 symbols 对象不匹配任何内容. 任何时刻都可以添加符号, 从而动态地改变其行为.

符号表中的每个条目都有一个关联的可变数据槽. 就此而言, 可以把符号表看作键为字符串的键值对关联容器 (或映射).

symbols 类期望两个模板参数(实际上还有第三个, 见详情框). 第一个参数 T 指定与每个符号关联的数据类型(默认为 int), 第二个参数 CharT 指定符号的字符类型(默认为 char).

    template
    <
        typename T = int,
        typename CharT = char,
        typename SetT = impl::tst<T, CharT>
    >
    class symbols;
三态状态树

实际的集合实现由 SetT 模板参数(symbols 类的第三个模板参数)提供. 默认情况下, 它使用 tst 类, 即三叉搜索树(Ternary Search Tree)的一种实现.

对许多典型的搜索问题, 三叉搜索树比哈希更快, 尤其当搜索接口基于迭代器时. 在含 n 个字符串的三叉搜索树中搜索长度为 k 的字符串, 至多需要 O(log n+k) 次字符比较. 对于不成功的搜索, TST 比哈希表快许多倍, 因为不匹配只需检查少量几个字符就能更早发现. 哈希表在搜索时总是检查整个键.

详情见 http://www.cs.princeton.edu/~rs/strings/.

下面是一些声明示例:

    symbols<> sym;
    symbols<short, wchar_t> sym2;

    struct my_info
    {
        int     id;
        double  value;
    };

    symbols<my_info> sym3;

声明好符号表之后, 可以使用以下构造静态地添加符号:

    sym = a, b, c, d ...;

其中 sym 是符号表, a..d 等是字符串. 注意, 逗号运算符在通过赋值向符号表添加条目时起到分隔作用. 由于运算符重载, 这是可行且正确的(尽管可能需要一点时间来适应), 并且是用大量符号初始化符号表的简洁方式. 此外, 对符号表进行多次赋值, 在不同时刻迭代地添加符号(或符号组), 也是完全合法的.

简单示例:

    sym = "pineapple", "orange", "banana", "apple", "mango";

注意, 把同一个符号多次添加到符号表是无效的, 不过你可以任意多次修改与某个符号关联的值.

现在, 我们可以在文法中使用 sym. 示例:

    fruits = sym >> *(',' >> sym);

或者, 符号可以通过成员函数对象 add 动态添加(见下文的 symbol_inserter). 成员函数对象 add 可以作为语义动作挂接到解析器上, 接收一个 begin/end 对:

    p[sym.add]

其中 p 是一个解析器(而 sym 是一个符号表). 成功时, 输入中被匹配的部分会被添加到符号表中.

add 也可用于直接初始化数据. 示例:

    sym.add("hello", 1)("crazy", 2)("world", 3);

当然, 前提是与 sym 关联的数据槽位是整数.

与每个符号关联的数据可以随时修改. 最显而易见的方式当然是通过 语义动作. 与往常一样, 函数或函数对象可以挂接到符号表. 符号表期望与以下签名兼容的函数或函数对象:

函数的签名:

    void func(T& data);

函数对象的签名:

    struct ftor
    {
        void operator()(T& data) const;
    };

其中 T 是符号表的数据类型(其模板参数列表中的 T). 当符号表成功匹配输入中的内容时, 与符号表中匹配条目关联的数据会被报告给语义动作.

符号表实用工具

有时, 你可能希望直接操作符号表. 这里提供了一些符号表实用工具.

add

    template <typename T, typename CharT, typename SetT>
    T*  add(symbols<T, CharT, SetT>& table, CharT const* sym, T const& data = T());

把符号 sym(C 字符串)添加到符号表 table, 外加可选的与该符号关联的数据 data. 返回指向与该符号关联的数据的指针, 若添加失败(例如该符号先前已被添加)则返回 NULL.

find

    template <typename T, typename CharT, typename SetT>
    T*  find(symbols<T, CharT, SetT> const& table, CharT const* sym);

从符号表 table 中查找符号 sym(C 字符串). 返回指向与该符号关联的数据的指针, 若未找到则返回 NULL

symbol_inserter

symbols 类持有一个名为 add 的此类的实例. 它可以像成员函数一样直接调用, 传入一个 first/last 迭代器和可选数据:

    sym.add(first, last, data);

或者, 传入一个 C 字符串和可选数据:

    sym.add(c_string, data);

其中 sym 是一个符号表. data 实参是可选的. 这一方案的妙处在于它可以级联. 我们在上面已经见过它的运用. 以下是罗马数字解析器的一个片段

    //  Parse roman numerals (1..9) using the symbol table.

    struct ones : symbols<unsigned>
    {
    	ones()
    	{
            add
                ("I"    , 1)
                ("II"   , 2)
                ("III"  , 3)
                ("IV"   , 4)
                ("V"    , 5)
                ("VI"   , 6)
                ("VII"  , 7)
                ("VIII" , 8)
                ("IX"   , 9)
    		;
    	}

    } ones_p;

注意, 用户自定义结构体 ones 派生自 symbols. 然后在构造时, 我们使用 add symbol_inserter 添加了所有符号.

完整源代码可 在此查看. 它是 Spirit 发行包的一部分.

同样, add 也可以用作语义动作, 因为它符合动作接口(见语义动作):

    p[sym.add]

其中 p 当然是一个解析器.
