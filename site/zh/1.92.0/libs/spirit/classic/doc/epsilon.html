Epsilon

Epsilon(epsilon_p 和 eps_p)是一个多用途解析器, 它返回零长度匹配.

简单形式

在其最简形式下, epsilon_p 匹配空串, 并且总是返回零长度匹配:

    epsilon_p // always returns a zero-length match

这种形式通常用于无条件触发 语义动作. 例如, 在一组候选分支失败时触发错误消息会很有用:

    r = A | B | C | eps_p[error]; // error if A, B, or C fails to match

语义谓词

语义谓词允许你在文法的任意位置挂接函数. 在这种角色下, epsilon 接受一个零参(nullary)函数/函数对象. 运行期函数/函数对象通常是一个测试, 用于消解文法中的歧义. 当函数/函数对象的结果求值为 false 时, 将报告解析失败. 否则将报告一个空匹配. 一般形式为:

    eps_p(f) >> rest;

零参函数 f 被调用来执行语义测试(比如说, 检查某个符号是否在 符号表中). 若测试返回 true, 则求值 rest. 否则, 该产生式将提前返回不匹配, 而根本不会触碰 rest.

句法谓词

与语义谓词类似, 句法谓词在求值另一个产生式之前, 断言某种条件语法得到满足. 这一次, epsilon_p 接受一个(条件)解析器. 一般形式为:

    eps_p(p) >> rest;

若 p 在输入流上匹配成功, 则尝试识别 rest. 解析器 p 被调用来执行语法检查. 无论 p 成功与否, eps_p(p) 总是返回零长度匹配(即不消耗输入). 若测试返回 true, 则求值 rest. 否则, 该产生式将提前返回不匹配, 而根本不会触碰 rest.

示例:

    eps_p('0') >> oct_p // note that '0' is actually a ch_p('0')

这里的 epsilon 被用作句法谓词. oct_p(见 numerics)仅在我们看到前导 '0' 时才被解析. 把前导 '0' 包裹在 epsilon 中, 可使解析器不从输入中消耗任何内容. 若看到 '0', epsilon_p 报告零长度的成功匹配.

原语实参

Epsilon 允许 char, int, wchar_t, char const*, wchar_t const* 等原语类型实参. 示例:

eps_p("hello") // same as eps_p(str_p("hello"))
eps_p('x') // same as eps_p(ch_p('x'))

抑制语义动作

在句法谓词 eps_p(p) 中, 直接或间接挂接到条件解析器 p 上的任何语义动作都不会被调用. 然而, 挂接到 epsilon 自身的语义动作总是会被调用. 以下代码片段说明了这一行为:

    eps_p(c[f])  // f not called
    eps_p(c)[f]  // f is called
    eps_p[f]     // f is called

实际上, 条件解析器 p 被隐式地包裹在 no_actions_d 指令中:

    no_actions_d[p]

条件解析器必须没有副作用(语义动作). 条件解析器的目的是通过在输入流中向前查看某个特定模式来消解歧义. 歧义与语义动作相处得并不好. 在有歧义的文法上会发生回溯. 而一旦发生回溯, 我们无法撤销已被触发的语义动作的效果.

取负

运算符 ~ 为 epsilon_p/eps_p 构造的解析器而定义. 它通过对报告的结果取补来执行取反. ~~eps_p(x) 与 eps_p(x) 完全相同.
