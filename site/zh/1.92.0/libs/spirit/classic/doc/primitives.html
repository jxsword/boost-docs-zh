原语

框架预定义了一些解析器原语. 这些是使用者用来构建更复杂解析器的最基本构件. 这些原语解析器都是模板类, 因此非常灵活.

这些原语解析器可以直接实例化, 也可以通过模板化的辅助函数实例化. 一般而言, 辅助函数处理起来要简单得多, 因为它少打很多字.

我们之前通过生成器函数 ch_p 见过字符字面量解析器, 它其实并不是解析器, 而是解析器生成器. 类 chlit<CharT> 是字符字面量解析器背后的实际模板类. 要实例化一个 chlit 对象, 你必须显式地提供字符类型 CharT 作为模板参数, 它决定了字符的类型. 该类型通常对应于输入类型, 一般是 char 或 wchar_t. 下面的表达式创建一个临时解析器对象, 它将识别单个字母 'X'.

    chlit<char>('X');

使用 chlit 的生成器函数 ch_p 简化了 chlit<> 类的使用(大多数 Spirit 解析器类都是如此, 因为它们大多有对应的生成器函数). 调用该函数很方便, 因为编译器会通过实参推导为我们推断模板类型. 上面的例子用 ch_p 辅助函数表达可以不那么啰嗦.

    ch_p('X')  // equivalent to chlit<char>('X') object
解析器生成器

每当你看到解析器生成器函数的调用, 它都等价于解析器本身. 因此, 我们常常把 ch_p 称为字符解析器, 即便严格来说它是一个生成字符解析器的函数.

以下文法片段展示了这些形式的实际运用:

    // a rule can "store" a parser object.  They're covered
    // later, but for now just consider a rule as an opaque type
    rule<> r1, r2, r3;

    chlit<char> x('X');     // declare a parser named x

    r1 = chlit<char>('X');  //  explicit declaration
    r2 = x;                 //  using x
    r3 = ch_p('X')          //  using the generator

chlit 与 ch_p

匹配单个字符字面量. chlit 有一个模板类型参数, 默认为 char(即 chlit<> 等价于 chlit<char>). 该类型参数是 chlit 解析时将识别的字符类型. 函数生成器版本从实际函数实参推导模板类型参数. chlit 类构造函数接受单个参数: 它用来与输入匹配的字符. 示例:

    r1 = chlit<>('X');
    r2 = chlit<wchar_t>(L'X');
    r3 = ch_p('X');

回到我们最初的例子:

    group = '(' >> expr >> ')';
    expr1 = integer | group;
    expr2 = expr1 >> *(('*' >> expr1) | ('/' >> expr1));
    expr  = expr2 >> *(('+' >> expr2) | ('-' >> expr2));

文法声明中的字符字面量 '(', ')', '+', '-', '*' 和 '/' 是在幕后隐式创建的 chlit 对象.

char 操作数

之所以能这样, 是由于 operator>> 的两个特殊模板化重载, 它们接受 (char, ParserT) 或 (ParserT, char). 这些函数把字符转换为 chlit 对象.

你也可以更喜欢显式地声明为:

    chlit<> plus('+');
    chlit<> minus('-');
    chlit<> times('*');
    chlit<> divide('/');
    chlit<> oppar('(');
    chlit<> clpar(')');

range 与 range_p

字符的 range(范围)由一个低/高字符对创建. 这样的解析器匹配 range 内的单个字符, 包括两个端点. 与 chlit 一样, range 有一个模板类型参数, 默认为 char. range 类构造函数接受两个参数: 它用来与输入匹配的字符范围(from 与 to, 含端点). 函数生成器版本是 range_p. 示例:

    range<>('A','Z')    // matches 'A'..'Z'
    range_p('a','z')    // matches 'a'..'z'

注意, 依据底层字符编码, 第一个字符必须"先于"第二个字符. 与 chlit 一样, range 是单字符解析器.

字符映射

字符映射本质上是平台相关的. 标准中并不保证例如 'A' < 'Z', 不过在许多场合, 我们很清楚自己使用的字符集, 如 ASCII, ISO-8859-1 或 Unicode. 但在移植到另一个平台时要当心.

strlit 与 str_p

该解析器匹配一个字符串字面量. strlit 有一个模板类型参数: 迭代器类型. 在内部, strlit 持有一个指向字符串或字符容器的 begin/end 迭代器对. strlit 尝试用该字符串匹配当前输入流. 模板类型参数默认为 char const*. strlit 有两个构造函数. 第一个接受以空字符结尾的字符指针. 该构造函数可用于从带引号的字符串字面量构建 strlits. 第二个构造函数接受一个 first/last 迭代器对. 函数生成器版本是 str_p. 示例:

    strlit<>("Hello World")
    str_p("Hello World")

    std::string msg("Hello World");
    strlit<std::string::const_iterator>(msg.begin(), msg.end());
字符层面与短语层面的解析

典型的解析器把字符(构成单词或词素的符号)与短语(构成句子的单词)的处理视为两个不同的领域. 诸如保留字, 运算符, 字面量字符串, 数值常量等构成文法终结符的实体, 通常先在单独的词法分析阶段提取出来.

到这里, 从我们目前的示例中可以明显看出, 值得注意的是: 与标准做法相反, Spirit 框架同时处理字符层面与短语层面的解析任务. 可以认为一个词法分析器被无缝地集成到了 Spirit 框架之中.

虽然 Spirit 解析器库不需要单独的词法分析器, 但没有理由不这样做. 人们总是可以按需拥有任意多层解析器. 理论上, 可以用同一个框架创建预处理器, 词法分析器和真正的解析器.

chseq 与 chseq_p

匹配一个字符序列. chseq 与 strlit 具有相同的模板类型参数和构造函数参数. 函数生成器版本是 chseq_p. 示例:

    chseq<>("ABCDEFG")
    chseq_p("ABCDEFG")

strlit 是一个隐式词法元素(lexeme). 也就是说, 它只在字符层面工作. 而 chseq —— strlit 的孪生兄弟 —— 则既可以在字符层面也可以在短语层面工作. 这只是意味着它可以忽略字符串字符之间的空白. 例如:

    chseq<>("ABCDEFG")

可以解析:

    ABCDEFG
    A B C D E F G
    AB CD EFG

更多字符解析器

框架还预定义了整套单字符解析器:

单字符解析器
anychar_p 匹配任何单个字符(包括空终止符: '\0')
alnum_p 匹配字母数字字符
alpha_p 匹配字母字符
blank_p 匹配空格或制表符
cntrl_p 匹配控制字符
digit_p 匹配数字
graph_p 匹配非空格的可打印字符
lower_p 匹配小写字母
print_p 匹配可打印字符
punct_p 匹配标点符号
space_p 匹配空格、制表符、回车和换行
upper_p 匹配大写字母
xdigit_p 匹配十六进制数字

取反 ~

chlit, range, anychar_p, alnum_p 等单字符解析器可以被取反. 例如:

    ~ch_p('x')

匹配除 'x' 之外的任何字符. 字符解析器的双重取反会抵消取反. ~~alpha_p 等价于 alpha_p.

eol_p

匹配行尾(CR/LF 及其组合).

nothing_p

永远不匹配任何东西, 总是失败.

end_p

匹配输入的结尾(当输入耗尽时返回 0 长度的成功匹配)

eps_p

Epsilon(epsilon_p 与 eps_p)是一个多用途解析器, 返回零长度匹配. 详情见 Epsilon.
