选择解析器

选择解析器可用于从给定的解析器列表中标识出成功识别当前输入序列的那个解析器. 示例:

    rule<> rule_select =
        select_p
        (
            parser_a
          , parser_b
            /* ... */
          , parser_n
        );

各解析器(parser_a, parser_b 等)从左到右依次尝试, 直到某个解析器匹配当前输入序列. 若找到了匹配的解析器, select_p 解析器返回该解析器的位置(从零开始的索引). 例如, 在上面的示例中, 若 parser_b 匹配则返回 1.

select 解析器家族有两个预定义解析器: select_p 与 select_fail_p. 这两个解析器的区别在于处理不匹配情况的方式(当没有任何解析器匹配当前输入序列时). select_p 解析器在找不到匹配解析器时返回 -1, 而 select_fail_p 解析器则完全不匹配.

下面的示例展示如何把选择解析器与 switch 解析器非常方便地配合使用:

    int choice = -1;
    rule<> rule_select =
            select_fail_p('a', 'b', 'c', 'd')[assign_a(choice)]
        >>  switch_p(var(choice)) 
            [
                case_p<0>(int_p),
                case_p<1>(ch_p(',')),
                case_p<2>(str_p("bcd")),
                default_p
            ]
        ;

本示例展示了一条规则, 它匹配:

  • 'a' 后跟一个整数
  • 'b' 后跟一个 ','
  • 'c'后跟 "bcd"
  • 单个 'd'.

对于其他输入序列, 给出的规则完全不匹配.

BOOST_SPIRIT_SELECT_LIMIT

select_p 解析器内部可能的条目数受 Spirit 编译期常量 BOOST_SPIRIT_SELECT_LIMIT 限制, 其默认值为 3. 该值不应大于 PHOENIX_LIMIT 给出的编译期常量(见 phoenix). 示例:

// Define these before including anything else
#define PHOENIX_LIMIT 10
#define BOOST_SPIRIT_SELECT_LIMIT 10
