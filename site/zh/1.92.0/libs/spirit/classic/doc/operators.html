运算符

运算符是对象组合与嵌入的手段. 通过运算符重载, 简单的解析器可以组合成组合器, 这些运算符经过精心设计, 以逼近某种扩展巴科斯-诺尔范式(EBNF)变体的语法. 如下表达式:

    a | b

实际产生一个新的解析器类型, 它是其操作数 a 和 b 的组合器. 进一步看这个例子, 若 a 和 b 的类型为 chlit<>, 则结果将具有组合类型:

    alternative<chlit<>, chlit<> >

一般来说, 对任何二元运算符, 它取其两个实参 parser1 和 parser2, 并创建一个形如下式的新组合解析器

    op<parser1, parser2>

其中 parser1 和 parser2 本身可以是任意复杂的解析器, 唯一的限制是你的编译器所强加的限制.

集合运算符

集合运算符
a | b 联合体 匹配 a 或 b. 也称为候选(alternative)
a & b Intersection 匹配 a 且 b
a - b 差 匹配 a 但不匹配 b. 若两者都匹配且 b 匹配的文本比 a 匹配的文本短, 则做出一次成功匹配
a ^ b XOR 匹配 a 或 b, 但不同时匹配两者

短路求值

候选操作数按先来先服务的方式, 从最左边的操作数开始逐一尝试. 在找到成功匹配的候选之后, 解析器即结束搜索, 实质上是对其他潜在可行候选的搜索进行了短路. 这种短路隐式地给予最左边的候选最高优先级.

短路的方式与 C 或 C++ 的逻辑表达式相同; 例如 if (x < 3 || y < 2), 其中若 x 求值小于 3, 则 y < 2 测试根本不会执行. 除了为候选提供必要的隐式优先级规则之外(考虑到 Spirit 解析器编译器的非确定性本质, 这是必要的), 短路还改善了执行时间. 若候选分支的顺序在逻辑上无关紧要, 请力求把(预期)最常见的选择放在最前面以获得最大效率.

交集

一些研究者断言, 交集(如 a & b)让我们能够定义上下文相关语言("XBNF" [引自 Leu-Weiner, 1973]). "把一门语言定义为有限个上下文无关语言之交的理论由 Leu 与 Weiner 于 1973 年发展".

~ 运算符

补运算符 ~ 最初曾被纳入考虑. 对其价值与含义的进一步理解使我们举棋不定. 基本问题源于这样一个事实: ~a 将产生 U-a, 其中 U 是所有字符串的全集. 不过, 在有意义之处, 某些解析器是可以取补的(例子见 原语字符解析器).

顺序运算符

顺序运算符
a >> b 序列 按顺序匹配 a 和 b
a && b 顺序与(Sequential-and) 顺序与. 同上, 按顺序匹配 a 和 b
a || b 顺序或(Sequential-or) 按顺序匹配 a 或 b

顺序运算符 >> 也可以被视为顺序与运算符. 表达式 a && b 读作: 按顺序匹配 a 和 b. 沿着这一逻辑, 我们还可以有顺序或运算符, 表达式 a || b 读作: 按顺序匹配 a 或 b. 即, 若 a 和 b 都匹配, 则必须是按顺序的; 这等价于 a >> !b | b.

可选与循环

可选与循环
*a Kleene 星 把 a 匹配零(0)次或多次
+a 正闭包 把 a 匹配一(1)次或多次
!a 可选 把 a 匹配零(0)次或一(1)次
a % b 列表 匹配由 a 的一次或多次重复组成, 并以 b 的出现分隔的列表. 这与 a >> *(b >> a) 相同. 注意 a 不得同时匹配 b

若更仔细地观察, 请注意我们把形如 !a 的可选表达式与循环归为同一类别. 这是合乎逻辑的, 考虑到可选是把跟在其后的表达式匹配零(0)次或一(1)次.

原语类型操作数

对二元运算符而言, 两个操作数中可以有一个(但不可同时两个)是 char, wchar_t, char const* 或 wchar_t const*. 设 P 是解析器对象, 这里是一些示例:

    P | 'x'
    P - L"Hello World"
    'x' >> P
    "bebop" >> P

需要强调的是, C++ 规定只有当至少一个实参是用户自定义类型时, 运算符才可以被重载. 通常, 在涉及多个运算符的表达式中, 显式地把最左边的操作数声明为解析器类型, 就足以使传播至其右侧所有其余操作数都被视为解析器. 示例:

    r = 'a' | 'b' | 'c' | 'd';          // ill formed
    r = ch_p('a')  | 'b' | 'c' | 'd';   // OK

第二种情况按如下方式解析:

    r  (((chlit<char> | char) | char) | char)

    a  (chlit<char> | char)
    r  (((a) | char) | char)

    b  (a | char)
    r  (((b)) | char)

    c  (b | char)
    r  (((c)))

运算符优先级与分组

由于我们在 C++ 中定义元语言, 我们遵循 C/C++ 的运算符优先级规则. 括号内的分组表达式可以覆盖这一点(例如, *(a | b) 读作: 把 a 或 b 匹配零(0)次或多次).
