获取指向容器属性结尾的迭代器
end_container

模板 end_container 是用作属性定制点的类型. Karma 的重复生成器(例如 List (%), Kleene (unary *), Plus (unary +) 和 Repeat)会调用它, 以获取指向存放待输出属性的容器的结尾的迭代器.

模块头文件 
#include <boost/spirit/home/support/container.hpp>

另请参见 包含结构.

注释

用户程序不需要直接包含此头文件, 因为它通常由依赖其内容的其它 Spirit 头文件包含.

命名空间

名称

boost::spirit::traits

概要 
template <typename Container, typename Enable>
struct end_container
{
    static typename container_iterator<Container>::type
    call(Container& c);
};
模板参数

参数

说明

默认值

Container

类型 Container, 需要为其返回指向第一个元素的迭代器

none

Enable

辅助模板参数, 可利用 SFINAE 有选择地启用或禁用 end_container 的某些特化(即 boost::enable_if 或 boost::disable_if).

void

记法约定

C

需要为其返回 end 迭代器的容器类型.

c

一个容器 C 的实例.

表达式语义

表达式

语义

end_container<C>::call(c)

返回可用于与其他迭代器比较以检测另一迭代器是否到达给定容器 c 结尾的迭代器. 返回的迭代器的类型应当与定制点 traits::container_iterator 返回的类型相同.
预定义特化

Spirit 为若干类型预定义了此定制点的特化. 下表列出了这些类型以及内嵌 typedef type 所返回的类型:

模板参数

语义

C

返回 c.end().

C const

返回 c.end().

unused_type

返回 &unused.
何时实现

每当某个类型要用作替代 STL 容器的属性时, 就需要为该类型实现定制点 end_container. 它仅适用于生成器(Spirit.Karma). 根据经验: 每当某个类型要作为属性传递给通常暴露 STL 容器的生成器 C, 且该类型不暴露 STL 容器的接口(即 is_container<C>::type 通常会返回 mpl::false_)时, 就必须实现它.

相关的属性定制点

如果实现了此定制点, 以下其他定制点可能也需要实现.

名称

何时实现

Karma: List (%), Kleene (unary *), Plus (unary +), Repeat.

traits::next_iterator
