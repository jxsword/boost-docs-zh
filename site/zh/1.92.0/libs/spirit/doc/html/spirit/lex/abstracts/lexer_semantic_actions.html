词法分析器语义动作

词法分析器的主要任务通常是识别输入中的记号. 传统上, 这一任务还辅以如下能力: 每当检测到某个特定记号时执行任意代码. Spirit.Lex 的设计也支持这种运行模式. 我们借用了用于解析器 (Spirit.Qi) 和生成器 (Spirit.Karma) 的语义动作概念. 词法分析器语义动作可以附加到任何记号定义上. 它们是一些 C++ 函数或函数对象, 每当某个记号定义成功识别输入的一部分时就会被调用. 假设你有一个记号定义 D 和一个 C++ 函数 f, 你可以让词法分析器每当匹配到输入时就调用 f, 做法是附加 f:

D[f]

上面的表达式把 f 链接到记号定义 D 上. f 所需的原型是:

void f (Iterator& start, Iterator& end, pass_flag& matched, Idtype& id, Context& ctx);

其中:

Iterator& start

这是指向底层输入序列中匹配范围起点的迭代器. 该迭代器的类型与定义 lexertl::actor_lexer<...> 的类型时所指定的类型相同 (其第一个模板参数). 语义动作可以修改此迭代器的值, 从而影响匹配到的输入序列.

Iterator& end

这是指向底层输入序列中匹配范围终点的迭代器. 该迭代器的类型与定义 lexertl::actor_lexer<...> 的类型时所指定的类型相同 (其第一个模板参数). 语义动作可以修改此迭代器的值, 从而影响匹配到的输入序列.

pass_flag& matched

这个值被预先初始化为 pass_normal. 如果语义动作把它设置为 pass_fail, 其行为就如同这个记号一开始就没有被匹配一样. 如果语义动作把它设置为 pass_ignore, 词法分析器将忽略当前记号, 并尝试从输入中匹配下一个记号.

Idtype& id

这是被匹配记号的 Idtype 类型的 token id (大多数情况下这将是一个 std::size_t). 语义动作可以修改这个 token id 的值, 从而影响所创建记号的 id.

Context& ctx

这是一个对词法分析器特有的未指定类型的引用, 为当前词法分析器状态提供上下文. 它可用于访问不同的内部数据项, 并且是从语义动作内部控制词法分析器状态所必需的.

当使用 C++ 函数作为语义动作时, 也允许以下原型:

void f (Iterator& start, Iterator& end, pass_flag& matched, Idtype& id);
void f (Iterator& start, Iterator& end, pass_flag& matched);
void f (Iterator& start, Iterator& end);
void f ();
重要

为了使用词法分析器语义动作, 你需要使用类型 lexertl::actor_lexer<> 作为你的词法分析器类 (而不是像前面的例子中所描述的那样使用类型 lexertl::lexer<>).

词法分析器语义动作的上下文

传给任何词法分析器语义动作的最后一个参数是对一个未指定类型的引用 (见上表中的 Context 类型). 这个类型之所以未指定, 是因为它取决于词法分析器返回的记号类型. 它实现在词法分析器所暴露的迭代器类型的内部. 尽管如此, 任何上下文类型都应暴露若干函数, 以允许影响词法分析器的行为. 下表概述了可用功能并给出了简短说明.

表 8. 传递给词法分析器语义动作的任何上下文所暴露的函数

名称

说明

Iterator const& get_eoi() const

函数 get_eoi() 可用于访问词法分析器初始化时所用的输入流的末尾迭代器

void more()

函数 more() 告诉词法分析器, 下一次匹配到规则时, 相应的记号应当被追加到当前记号值上, 而不是替换它.

Iterator const& less(Iterator const& it, int n)

函数 less() 返回一个迭代器, 定位在当前记号起始迭代器之后第 n 个输入字符处 (即把返回值传递给参数 end, 就可以把当前记号除前 n 个字符之外的所有字符退还给输入流.

bool lookahead(std::size_t id)

函数 lookahead() 可用于为不支持类似 flex 的 a/b 构造 (匹配 a, 但仅当后面跟着 b 时) 的词法分析器引擎实现前瞻. 它会在当前记号之后的输入上调用词法分析器, 而不实际向前移动输入流. 该函数返回词法分析器是否能够用给定的 token id id 匹配到一个记号.

std::size_t get_state() const 和 void set_state(std::size_t state)

函数 get_state() 和 set_state() 可用于查看和修改当前的词法分析器状态.

token_value_type get_value() const 和 void set_value(Value const&)

函数 get_value() 和 set_value() 可用于查看和修改当前的记号值.

使用 Phoenix 的词法分析器语义动作

即使可以自己编写函数对象实现 (即使用 Boost.Lambda 或 Boost.Bind), 定义词法分析器语义动作的首选方式仍是使用 Boost.Phoenix. 在这种情况下, 你可以使用预定义的 Spirit 占位符来访问上述参数:

表 9. 用于词法分析器语义动作的预定义 Phoenix 占位符

占位符

说明

_start

指向匹配到的输入序列起点的迭代器. 对该迭代器值的任何修改都会反映在生成的记号中.

_end

指向匹配到的输入序列终点之后的迭代器. 对该迭代器值的任何修改都会反映在生成的记号中.

_pass

引用表示语义动作结果的值. 它被预先初始化为 lex::pass_flags::pass_normal. 如果把它设置为 lex::pass_flags::pass_fail, 词法分析器的行为就如同没有匹配到任何记号; 如果设置为 lex::pass_flags::pass_ignore, 词法分析器将忽略当前匹配, 并继续尝试从输入中匹配记号.

_tokenid

指向将被生成的记号的 token id. 对该值的任何修改都会反映在生成的记号中.

_val

指向下一个记号将据以初始化的值. 对该值的任何修改都会反映在生成的记号中.

_state

指向输入被匹配时所处的词法分析器状态. 对该值的任何修改都会反映在词法分析器本身 (下一次匹配将在新状态下开始). 当前正在生成的记号不受对该变量修改的影响.

_eoi

指向整个词法分析器输入的末尾迭代器. 该值不可修改.

作为最后一个参数传递给任何词法分析器语义动作的上下文对象, 在使用 Boost.Phoenix 表达式时无法直接访问. 我们改为提供预定义的 Phoenix 函数, 允许调用上文提到的不同支撑函数. 下表列出了可用的支撑函数并描述了它们的功能:

表 10. 词法分析器语义动作内可从 Phoenix 表达式使用的支撑函数

普通函数

Phoenix 函数

说明

ctx.more()

more()

函数 more() 告诉词法分析器, 下一次匹配到规则时, 相应的记号应当被追加到当前记号值上, 而不是替换它.

ctx.less()

less(n)

函数 less() 接受一个整数参数 n, 返回一个定位在当前记号起始迭代器之后第 n 个输入字符处的迭代器 (即把返回值赋给占位符 _end, 就可以把当前记号除前 n 个字符之外的所有字符退还给输入流.

ctx.lookahead()

lookahead(std::size_t) 或 lookahead(token_def)

函数 lookahead() 接受单个参数, 指定要在输入中匹配的记号. 例如, 该函数可用于为不支持类似 flex 的 a/b 构造 (匹配 a, 但仅当后面跟着 b 时) 的词法分析器引擎实现前瞻. 它会在当前记号之后的输入上调用词法分析器, 而不实际向前移动输入流. 该函数返回词法分析器是否能够匹配到指定的记号.
