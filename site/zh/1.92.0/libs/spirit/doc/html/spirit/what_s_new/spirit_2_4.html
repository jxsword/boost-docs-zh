Spirit V2.4

从 V2.3 (Boost V1.43.0) 到 V2.4 (Boost V1.44.0) 的变化: Spirit.Qi 和 Spirit.Karma
新特性
  • 定制点 traits::transform_attribute 现在接受一个附加模板参数 Domain, 允许针对 qi::domain 或 karma::domain 更好地特化该定制点.
重要

这是一个破坏接口的变更, 需要修改现有代码. 如果你的代码中有此定制点的特化, 你需要为新模板参数添加特化, 即 qi::domain 或 karma::domain.

  • Spirit.Qi 中的语义动作现在按需隐式调用函数 pre (属于定制点 traits::transform_attribute), 把给定属性转换为暴露的属性类型. 此组件不调用该定制点的函数 post 和 fail (因为那样毫无意义).
  • Spirit.Karma 中的语义动作现在按需隐式调用函数 pre (属于定制点 traits::transform_attribute), 把给定属性转换为消耗的属性类型.
  • 添加了 Spirit.Karma 的 skip 指令, 它在语义上等价于 Spirit.Karma 的 omit 指令, 只是不会执行内嵌生成器.
  • 为 Spirit.Karma rule 添加了调试支持.
  • 为 Spirit.Karma 添加了严格模式, 当前行为 (不变) 作为宽松模式保留. 添加了 Spirit.Karma 编译期指令 strict[] 和 relaxed[], 允许在两者之间切换.
  • 添加了 Spirit.Karma 的 duplicate 指令, 把给定属性复制到内嵌生成器序列的所有元素.
缺陷修复
  • Spirit.Qi 和 Spirit.Karma 中的组件现在接受单元素 Fusion 序列作为其属性, 只要 Fusion 序列中的元素与组件的属性类型兼容.
  • 字符范围解析器和生成器组件现在还可以写作 char_("a", "z") 而不是 char_('a', 'z'), 使其与 char_('a') 组件的语法一致 (后者也可写作 char_("a")). 请注意, 混合语法形式, 即 char_('a', "z") 和 char_("a", 'z'), 不受支持.
  • 修复了 Spirit.Karma 序列中的属性处理: 当该序列的所有元素消耗相同属性类型或该属性类型的容器, 且传入的属性也是该属性类型的容器时, 此前只有当重复容器是序列的最后一个元素时才支持使用. 现在 repeat(num)[a] 生成器可以位于任意位置 (嗯, 实际上现在任何重复容器都可以位于任意位置, 但这并不总是有意义, 因为它通常会吃掉所有给定的属性值).
  • 修复了 variant 元素为 STL 序列时 variant 的调试输出.
  • 修复了 multi_pass 中的一个缺陷, 避免在切换迭代器时在输入末尾丢失一个字符.
从 V2.3 (Boost V1.43.0) 到 V2.4 (Boost V1.44.0) 的变化: Spirit.Lex
新词法分析器特性
  • 词法分析器现在与 Qi 的 simple_trace 实用程序生成的调试输出良好集成. 记号打印为: '<' 匹配序列 '>'.
词法分析器缺陷修复
  • 修复了在词法分析器语义表达式中把 lex::_val 用作右值的问题.
  • 记号值现在也可在词法分析器语义表达式中用于内省 (作为 iterator_range).
