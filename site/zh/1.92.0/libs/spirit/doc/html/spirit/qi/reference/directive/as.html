强制原子赋值的解析器指令 (as<T>, as_string[], as_wstring[])
说明

as<T> 类强制对其主体的合成属性进行原子赋值. 通常, 重复解析器 (例如 Kleene 等) 或暴露 vector<A> 的序列, 会通过反复调用 traits::push_back_container 把元素赋给作为其合成属性提供的容器. 在某些情况下, 这可能不合需要. as<T> 类创建一个指令, 该指令会向其主体传递一个 T 类型的临时对象. 如果主体解析器通过, 该临时对象将通过一次调用 traits::assign_to 赋给指令的给定属性. 如果主体解析器失败, 指令的属性不会被改动.

注释

T 必须是容器类型. 如果 traits::is_container 对 T 不返回 true, 将发生编译期错误.

注释

as<T> 隐式地引发与 hold 指令在本质上类似的提交/回滚语义.

注意

根据所涉及的类型, traits::assign_to 定制点默认可能会使用 traits::push_back_container 把临时对象赋给给定属性. 请使用 属性处理的定制 一节中描述的接口来操控此赋值操作的语义.

表达式

语义

as<T>()[a]

创建 t 的一个 T 类型的临时对象, 并调用主体解析器 a, 提供 t 作为属性. 如果主体解析器通过, 则把 t 赋给 attr.

as_string[a]

等价于 as<std::string>()[a]

as_wstring[a]

等价于 as<std::wstring>()[a]

属性

参见 复合属性记法.

表达式

属性

as<T>()[a]

a: A --> as<T>()[a]: T

复杂度

复杂度由主体解析器 a 的复杂度, 以及把容器 t 赋给给定属性 attr 的赋值复杂度决定.

注释

下面示例的测试框架在 基础示例 一节中给出.

一些 using 声明:

using boost::spirit::utree;
using boost::spirit::utree_type;
using boost::spirit::utf8_symbol_type;
using boost::spirit::qi::as;
using boost::spirit::qi::as_string;
using boost::spirit::qi::char_;

as<T>, as_string 和 as_wstring 的简单用法:

为了用 utree 正确处理字符串拼接, 我们使用 as_string[]. 我们还使用 as<T> 显式创建一个 utree 符号节点.

utree ut;

typedef as<utf8_symbol_type> as_symbol_type;
as_symbol_type const as_symbol = as_symbol_type();

test_parser_attr("foo", as_string[*char_], ut);
std::cout << ut << std::endl; // will output >"foo"<
BOOST_ASSERT(ut.which() == utree_type::string_type);
ut.clear();

test_parser_attr("foo", as<std::string>()[*char_], ut);
std::cout << ut << std::endl; // will output >"foo"<
BOOST_ASSERT(ut.which() == utree_type::string_type);
ut.clear();

test_parser_attr("foo", as_symbol[*char_], ut);
std::cout << ut << std::endl; // will output >foo<
BOOST_ASSERT(ut.which() == utree_type::symbol_type);
ut.clear();

test_parser_attr("foo", as<utf8_symbol_type>()[*char_], ut);
std::cout << ut << std::endl; // will output >foo<
BOOST_ASSERT(ut.which() == utree_type::symbol_type);
