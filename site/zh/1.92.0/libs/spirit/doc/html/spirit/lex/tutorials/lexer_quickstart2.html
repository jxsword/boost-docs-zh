快速上手 2 - 更佳单词计数器: 使用 Spirit.Lex

熟悉 Flex 的人可能会抱怨 Lex 快速上手 1 - 单词计数器: 使用 Spirit.Lex 一节中的示例过于复杂, 没有利用该工具所提供的种种可能. 特别是前一个示例没有直接使用词法分析器动作来统计行数、单词数和字符数. 因此, 本教程这一步给出的示例将展示如何在 Spirit.Lex 中使用语义动作. 尽管该示例统计的仍是文本元素, 其目的在于沿途引入新的概念和配置选项 (完整示例代码见此处: word_count_lexer.cpp).

前置条件

除了唯一必需的 #include (特定于 Spirit.Lex) 之外, 本示例还需要包含 Boost.Phoenix 库中的几个头文件. 该示例展示了如何把仿函数附加到记号定义上; 这可以通过任何产生可调用对象的 C++ 技术来完成. 使用 Boost.Phoenix 完成此任务可以简化工作, 并避免向其他库添加依赖 (反正 Spirit 已经在使用 Boost.Phoenix).

#include <boost/spirit/include/lex_lexertl.hpp>
#include <boost/phoenix/operator.hpp>
#include <boost/phoenix/statement.hpp>
#include <boost/phoenix/stl/algorithm.hpp>
#include <boost/phoenix/core.hpp>

为了让下面的代码更易读, 我们引入以下命名空间.

namespace lex = boost::spirit::lex;

为了让读者预览本示例的内容, 下面给出了作为起点使用的 flex 程序. 有用的代码直接包含在与每个记号定义关联的动作内部.

%{
    int c = 0, w = 0, l = 0;
%}
%%
[^ \t\n]+  { ++w; c += yyleng; }
\n         { ++c; ++l; }
.          { ++c; }
%%
main()
{
    yylex();
    printf("%d %d %d\n", l, w, c);
}

语义动作: Spirit.Lex

Spirit.Lex 使用一种非常相似的方式把动作与记号定义关联起来 (对任何熟悉 Spirit 的人来说这也应当似曾相识): 在一对 [] 括号内指定要执行的操作. 为了能够把语义动作附加到记号定义上, 为每个记号定义了一个 token_def<> 的实例.

template <typename Lexer>
struct word_count_tokens : lex::lexer<Lexer>
{
    word_count_tokens()
      : c(0), w(0), l(0)
      , word("[^ \t\n]+")     // define tokens
      , eol("\n")
      , any(".")
    {
        using boost::spirit::lex::_start;
        using boost::spirit::lex::_end;
        using boost::phoenix::ref;

        // associate tokens with the lexer
        this->self
            =   word  [++ref(w), ref(c) += distance(_start, _end)]
            |   eol   [++ref(c), ++ref(l)]
            |   any   [++ref(c)]
            ;
    }

    std::size_t c, w, l;
    lex::token_def<> word, eol, any;
};

所示代码的语义如下. 每当词法分析器匹配到相应的记号时, [] 括号内的代码就会被执行. 这与 Flex 非常相似: 其中与记号定义关联的动作代码会在识别出匹配的输入序列之后被执行. 上面的代码使用了用 Boost.Phoenix 构造的函数对象, 但只要暴露正确的接口, 也可以插入任何 C++ 函数或函数对象. 更多细节请参阅 词法分析器语义动作 一节.

把记号定义与词法分析器相关联

如果就记号定义与词法分析器相关联的方式而言, 把这段代码与 Lex 快速上手 1 - 单词计数器: 使用 Spirit.Lex 中的代码进行比较, 你会注意到这里使用了不同的语法. 在前一个示例中, 我们使用的是 self.add() 风格的 API, 而这里我们直接把记号定义赋给 self, 并使用 | 运算符组合不同的记号定义. 下面再次给出该代码片段:

this->self
    =   word  [++ref(w), ref(c) += distance(_1)]
    |   eol   [++ref(c), ++ref(l)]
    |   any   [++ref(c)]
    ;

这样, 我们就有了一种非常强大且自然的构建词法分析器的方式. 若翻译成英语, 它可以读作: 词法分析器将识别 ('=') 由 ('|') 记号定义 word、eol 和 any 中任何一个所定义的记号.

与前一个示例的第二个区别是, 我们没有为各个记号显式指定要使用的记号 id. 使用语义动作来触发一些有用的工作, 使我们免于定义它们. 为了确保每个记号都被分配一个 id, Spirit.Lex 库在内部为记号定义分配唯一的编号, 从 boost::spirit::lex::min_token_id 定义的常量开始.

整合所有内容

为了执行上面定义的代码, 我们仍需实例化词法分析器类型, 用某个输入序列馈入它, 并创建一对迭代器以便遍历词法分析器创建的记号序列. 这段代码展示了如何完成这些步骤:

int main(int argc, char* argv[])
{

  typedef
        lex::lexertl::token<char const*, lex::omit, boost::mpl::false_>
     token_type;

  typedef lex::lexertl::actor_lexer<token_type> lexer_type;

  word_count_tokens<lexer_type> word_count_lexer;

  std::string str (read_from_file(1 == argc ? "word_count.input" : argv[1]));
    char const* first = str.c_str();
    char const* last = &first[str.size()];

  lexer_type::iterator_type iter = word_count_lexer.begin(first, last);
    lexer_type::iterator_type end = word_count_lexer.end();

  while (iter != end && token_is_valid(*iter))
        ++iter;

    if (iter == end) {
        std::cout << "lines: " << word_count_lexer.l
                  << ", words: " << word_count_lexer.w
                  << ", characters: " << word_count_lexer.c
                  << "\n";
    }
    else {
        std::string rest(first, last);
        std::cout << "Lexical analysis failed\n" << "stopped at: \""
                  << rest << "\"\n";
    }
    return 0;
}

把 omit 指定为记号属性类型会生成一个完全不保存任何记号属性的记号类 (甚至不保存被匹配输入序列的迭代器范围), 从而尽可能优化记号、词法分析器以及可能的解析器实现. 把 mpl::false_ 指定为第 3 个模板参数会生成一个记号类型和一个迭代器, 二者都不保存词法分析器状态, 从而允许更加激进的优化. 这样, 记号实例仅包含记号 id 作为唯一的数据成员.
