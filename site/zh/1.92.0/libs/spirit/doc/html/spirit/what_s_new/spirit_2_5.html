Spirit V2.5

从 V2.4.2 (Boost V1.46.0) 到 V2.5 (Boost V1.47.0) 的变化: Spirit.Qi 和 Spirit.Karma

此版本的 Spirit 现在支持 Boost.Phoenix 新版本 (V3), 该版本已作为 Boost V1.47 的一部分发布. 请注意, 此支持纯属初步性质, 不应视为生产质量. 我们现在发布它的原因是, 让想在代码中使用 Boost.Phoenix 新版本的人能够这样做, 而不会与使用 Spirit 的现有代码发生任何冲突. 一般来说, 无需更改任何 Spirit 代码. 要为 Spirit 启用 Boost.Phoenix V3, 你需要在构建中定义以下预处理器常量 (在包含任何 Spirit include 文件之前):

#define BOOST_SPIRIT_USE_PHOENIX_V3 1
Qi 或 Karma 的新特性
  • 添加了 utree, 一个可表示抽象语法树的泛型、层次化、动态数据结构. 它与 Spirit.Qi 和 Spirit.Karma 集成良好. 解析时它可以作为属性传给几乎任何文法. 同时, 它可以用作生成输出的属性.
  • 添加了新宏 BOOST_SPIRIT_TERMINAL_NAME, 它接受两个参数 (终结符名称及其类型). 此前只有一个参数 (终结符名称), 类型假定为终结符名称附加 _type. 这对诸如 int_ 之类的终结符会产生无效的 C++ 标识符, 导致生成的类型 int__type 带有虚假的双下划线, 而 C++ 中双下划线是保留给系统使用的.
  • 数值解析器现在允许 2..10 和 16 中的任意基数
  • 占位符 _val 现在可以在 rule 右侧之外的顶层语义动作中使用. 下面是一个示例: 
    int i = 0
BOOST_TEST(test_attr("456", int_[_val = _1], i) && i == 456);
    此时 _val 指传入 parse() 或 phrase_parse() 函数的属性值. 类似构造现在在 Spirit.Karma 中也可用: 
    int i = 123;
BOOST_TEST(test("123", int_[_1 = _val], i));
    此变更统一了 _val 占位符的处理, 允许在任何地方使用它, 而不仅是附加到 rule 右侧的语义动作中.
  • 添加了对 Spirit.Karma 无符号数值生成器 的支持, 基数可以是 2 .. 36 (含) 范围内的任意值.
Qi 或 Karma 中的缺陷修复
  • Spirit.Qi 整数字面量 (例如 int_(10)) 在失败时不再消耗输入.
  • 修复了 TRAC#5246: mmap_file_iterator 无法正确初始化.
  • 修复了 TRAC#5246: mmap_file_iterator 无法正确初始化.
  • 修复了 karma::real_policies<> 中一个 const 正确性问题, 该问题阻碍了在生成器中使用 const 浮点类型. 感谢 Jeroen Habraken (又名 VeXocide) 报告该问题并提交补丁和测试.
  • 修复了 Spirit.Qi 的 attr(attrib) 解析器、Spirit.Qi 的 symbols<> 解析器, 以及 Spirit.Karma 的 symbols<> 生成器, 使其正确处理容器属性. 这些组件在 Boost V1.46.1 中损坏 (感谢 Aaron Graham 和 Joerg Becker 报告这些问题).
  • 修复了 stream 解析器, 使其在流解析器组件成功时正确调整底层输入流的迭代器. 感谢 Brian O'Kennedy 在 Stackoverflow 上报告此问题.
  • 修复了与适配的 ADT 一起使用时失败的 Karma 数值生成器 (感谢 Colin Rundel 报告该问题).
破坏性变更
  • Spirit.Qi 指令 repeat 错误地为其属性实现了提交/回滚语义, 在指令失败时保持属性不动. 此行为已被移除, 因为它与类似组件不一致. 依赖此功能的现有代码将会损坏. 请参阅 Spirit.Qi 指令 hold 了解如何修复你的代码.
  • 添加了预处理器定义 BOOST_SPIRIT_NO_PREDEFINED_TERMINALS, 用于阻止预定义终结符对象的实例化 -- 这会大大拖慢编译时间. 定义 BOOST_SPIRIT_NO_PREDEFINED_TERMINALS 后, 由用户实例化所需的终结符. 因此, 不再写 using qi::uint_, 而是写: qi::uint_type uint_.
Lex 的新特性
  • 添加了在使用 lex::char_ 和 lex::string 创建记号定义时指定记号 id 的能力. 这两个基础组件现在都接受第二个参数, 它将被解释为从此定义生成的任何记号所请求的记号 id.
  • 添加了新记号类型 lex::lexertl::position_token<>, 它在本质上与现有的 lex::lexertl::token<> 类即插即用兼容. 但它额外以 iterator_range 的形式保存指向底层被匹配输入序列的一对迭代器.
Lex 中的缺陷修复
  • 修复了在为记号定义附加动作时把它们与所有状态关联 (使用 "*" 作为状态名) 的问题.
让一切运转起来
  • 添加了 Spirit.Karma 定制点 traits::extract_from_container, 当属性是容器时将调用它而不是较旧的定制点 traits::extract_from (此时 traits::is_container 对该属性返回 true).
  • 类型 hold_any 现在接受一个模板参数: basic_hold_any<Char>, 其中 Char 是流运算符使用的字符类型 (operator>>() 和 operator<<()). hold_any 仍作为 typedef basic_hold_any<char> hold_any 可用;
  • 语义动作现在支持属性兼容性. 这是一个破坏性变更, 但必须定义 #define BOOST_SPIRIT_ACTIONS_ALLOW_ATTR_COMPAT 新行为才会生效. 默认情况下, 旧行为仍然保留.
  • 备选现在支持属性兼容性.
  • 序列和容器组件 (list、Kleene、Plus 和 repeat) 的容器属性处理已被完全重写. 它现在支持更多用例, 行为也比旧版本可预测得多. 感谢 Thomas Taylor、Richard Crossley、Semen、Adalberto Castelo 以及其他许多人报告缺陷并帮助使新代码按预期工作.
