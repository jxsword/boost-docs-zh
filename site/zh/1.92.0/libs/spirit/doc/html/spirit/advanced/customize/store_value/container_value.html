确定要存入容器的类型(Qi)
container_value

模板 container_value 是用作属性定制点的模板元函数. Qi 的重复解析器(Kleene, Plus, List 和 Repeat)会调用它, 以确定要存入容器中的类型.

模块头文件 
#include <boost/spirit/home/support/container.hpp>

另请参见 包含结构.

注释

用户程序不需要直接包含此头文件, 因为它通常由依赖其内容的其它 Spirit 头文件包含.

命名空间

名称

boost::spirit::traits

概要 
template <typename Container, typename Enable>
struct container_value
{
    typedef <unspecified> type;
};
模板参数

参数

说明

默认值

Container

类型 Container 是需要推断其元素类型的类型.

none

Enable

辅助模板参数, 可利用 SFINAE 有选择地启用或禁用 container_value 的某些特化(即 boost::enable_if 或 boost::disable_if).

void

C

要测试的类型, 测试它是否需要被视为容器.

T1, T2, ...

任意类型

表达式语义

表达式

语义

container_value<C>::type

元函数, 求值为要存入给定容器类型 C 的类型.
预定义特化

Spirit 为若干类型预定义了此定制点的特化. 下表列出了这些类型及其暴露的类型和相应的语义:

模板参数

语义

C

非 const 的 value_type, 属于给定容器类型 C.

boost::optional<C>

返回 container_value<C>::type

boost::variant<T1, T2, ...>

返回 container_value<TN>::value, 针对的是第一个 TN (取自 T1, T2, ...) 中使 is_container<TN>::type 求值为 mpl::true_ 的那个. 否则将返回 unused_type.

unused_type

返回 unused_type.
何时实现

每当某个类型要用作替代 STL 容器的属性时, 就需要为该类型实现定制点 is_container. 它仅适用于解析器(Spirit.Qi). 根据经验: 每当某个类型要作为属性传递给通常暴露 STL 容器的解析器, 且该类型不暴露 STL 容器的接口(即没有用于 value_type 的内嵌 typedef)时, 就必须实现它. 这些组件具有如下形式的属性传播规则:

a: A --> Op(a): vector<A>

其中 Op(a) 表示对组件 a 的任何有意义的操作.

相关的属性定制点

如果实现了此定制点, 以下其他定制点可能也需要实现.

名称

何时实现

traits::clear_value

Qi: List, Kleene, Plus, Repeat.

示例

下面的示例展示了库所提供的 traits::container_value 定制点的默认实现:

template <typename Container, typename Enable/* = void*/>
struct container_value
  : detail::remove_value_const<typename Container::value_type>
{};

库会在适当的位置实例化此模板, 并把所提供的容器类型用作模板实参. 在解析要存入该容器的元素时, 内嵌的 type 被用作属性类型.

下面的示例展示了 unused_type 的预定义特化:

template <>
struct container_value<unused_type>
{
    typedef unused_type type;
};

它把内嵌的 type 同样定义为 unused_type, 以这种方式将"无关"属性状态传播给内嵌解析器.
