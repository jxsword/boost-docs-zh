Complex - 变得更简单

在上一节中, 我们展示了如何格式化复数 (即一对 double). 在本节中, 我们将在此示例的基础上构建, 目标是避免在格式规范中使用语义动作. 让我们先看结果代码, 之后再尝试理解它 (本示例的完整源文件可在此处找到: complex_number_easier.cpp):

template <typename OutputIterator>
bool generate_complex(OutputIterator sink, std::complex<double> const& c)
{
    using boost::spirit::karma::double_;
    using boost::spirit::karma::omit;
    using boost::spirit::karma::generate;

    return generate(sink,

        //  Begin grammar
        (
           !double_(0.0) << '(' << double_ << ", " << double_ << ')'
        |   omit[double_] << double_ << omit[double_]
        ),
        //  End grammar

        c.imag(), c.real(), c.imag()     //  Data to output
    );
}

让我们先介绍一些基本的库特性.

让数值生成器失败

所有 数值生成器 (例如 double_ 等)都从附加的属性获取要输出的值.

double d = 1.5;
generate(out, double_, d);       // will emit '1.5' (without the quotes)

或者, 它们可以用字面量值初始化. 例如, 要输出常量 1.5, 可以这样写:

generate(out, double_(1.5));     // will emit '1.5' as well (without the quotes)

与简单的 1.5 或 lit(1.5) 的区别在于, double_(1.5) 会在属性可用时消耗一个属性. 此外, 它会把其立即值与所提供属性的值进行比较, 如果两者不相等则失败.

double d = 1.5;
generate(out, double_(1.5), d);  // will emit '1.5' as long as d == 1.5

这一特性 -- 即仅当属性匹配立即值时才成功生成 -- 使数值生成器能够用于动态控制输出的生成方式.

注释

相当多的生成器在其立即值与所提供属性不相等时会失败. 其中包括所有 字符生成器 和所有 字符串生成器. 一般来说, 所有拥有由 lit() 变体创建的兄弟生成器的生成器都属于这一类.

谓词 - 输出生成器的条件判断

除了前面提到的 eps 生成器之外, Spirit.Karma 还提供了两个支持动态流控制的特殊运算符: And 谓词 (一元 &) 和 Not 谓词 (一元 !). 这两个谓词的主要特性是丢弃其附属生成器发出的所有输出. 这与解析时所用谓词的行为等价: 在解析中, 谓词不消耗任何输入, 从而允许在输入流中向前查看. 在 Karma 中, 只要其关联的生成器成功, And 谓词就会成功; 而 Not 谓词仅在其关联的生成器失败时才成功.

注释

Spirit.Karma 中的生成器谓词会消耗一个属性 (如果可用). 这使得它们的行为不同于 Spirit.Qi 中的谓词, 后者不暴露任何属性. 这是因为谓词允许基于仅在运行期才可获得的数据做出决策. 在 Spirit.Qi 中, 解析时决策是基于再向前查看若干输入记号做出的; 而在 Spirit.Karma 中, 判定标准必须由用户提供. 实现这一点最简单的方式就是提供一个属性.

作为示例, 下面的生成器会成功生成

double d = 1.0;
BOOST_ASSERT(generate(out, &double_(1.0), d));    // succeeds as d == 1.0

而下面这个则会失败:

double d = 1.0;
BOOST_ASSERT(!generate(out, !double_(1.0), d));   // fails as d == 1.0

这两个都不会发出任何输出. 谓词会丢弃应用了它们的生成器所发出的一切内容.

忽略所提供的属性

有时, 我们希望 '跳过' (即忽略) 所提供的属性. 例如, 在备选生成器中就会出现这种情况: 其中某些备选项只需提取传递给备选生成器的整体属性的一部分. Spirit.Karma 为此提供了一个特殊的伪生成器: 指令 omit[]. 该指令会消耗一个由其内嵌生成器所定义的类型的属性, 但不发出任何输出.

注释

Spirit.Karma 中的 omit 指令, 其作用与 Spirit.Qi 中同名指令正好 '相反'. 而 omit 在 Spirit.Qi 中消耗输入但不暴露任何属性, Spirit.Karma 中的对应指令则消耗属性而不发出任何输出.

将所有内容整合起来

与我们前面的第一个例子非常相似, 我们使用两个备选项, 以便根据复数的虚部是否为零来支持两种不同的输出格式. 若虚部不为零则执行第一个备选项, 否则执行第二个备选项. 这次我们使用 Not 谓词 (一元 !) 并结合许多 Karma 原始生成器在特定条件下 失败 的特性. 下面再次给出第一个备选项, 供参考:

!double_(0.0) << '(' << double_ << ", " << double_ << ')'

生成器 !double_(0.0) 会做几件事情. 首先, 由于 Not 谓词 (一元 !), 只有当 double_(0.0) 生成器 失败 时它才会成功, 否则整个第一个备选项都会失败. 其次, double_(0.0) 生成器只有在其属性值等于其直接参数时才会成功 (即在本例中为 0.0). 第三, Not 谓词不发出任何输出 (无论成功还是失败), 并丢弃 double_(0.0) 可能已发出的任何输出.

由于我们将复数的虚部作为 !double_(0.0) 的属性值传入, 因此只有当它不等于零时才会选择整个第一个备选项 (!double_(0.0) 不会失败). 这正是我们所需要的!

现在, 第二个备选项必须只发出复数的实部. 为了简化整个文法, 我们力求统一所有备选项的属性类型. 由于第一个备选项暴露的属性类型是 tuple<double, double, double>, 我们需要跳过属性的第一个和最后一个元素 (记住, 我们将实部作为属性的第二个元素传入). 我们通过使用 omit[] 指令来实现这一点:

omit[double_] << double_ << omit[double_]

该表达式的整体属性是 tuple<double, double, double>, 但 omit[] 会 '吃掉' 第一个和最后一个元素. 该表达式发出的输出由单个生成的 double 组成, 它表示元组的第二个元素, 也就是我们复数的实部.

重要

一般而言, 最好使用不需要语义动作的生成器构造. 原因在于语义动作经常使用类似这样的构造: double_[_1 = c.real()]. 但这里的赋值是实实在在的一次赋值! 数据实际上会被 复制 到附加到该动作的生成器的属性值中. 另一方面, 不含任何语义动作的文法通常不必复制属性, 因此效率更高.
