消耗属性的生成器指令(omit[] 和 skip[])
说明

指令 omit[] 和 skip[] 消耗内嵌生成器的属性类型而不生成任何输出. omit[] 指令仍会执行内嵌生成器, 之后丢弃生成的输出. skip[] 指令不会执行内嵌生成器, 而只用它来提取暴露的属性类型.

头文件 
// forwards to <boost/spirit/home/karma/directive/omit.hpp>
#include <boost/spirit/include/karma_omit.hpp>

另请参见 包含结构.

名称

boost::spirit::omit // alias: boost::spirit::karma::omit

boost::spirit::skip // alias: boost::spirit::karma::skip

所属模型

UnaryGenerator

记法约定

a

一个生成器对象

A

生成器 a 的属性类型

表达式语义

仅当表达式的语义与 UnaryGenerator 不同或在其中未定义时, 才给出其语义.

表达式

语义

omit[a]

omit 指令消耗内嵌生成器 A 的属性类型而不生成任何输出. 它总是成功. 内嵌生成器会被执行, 任何生成的输出都会被丢弃.

skip[a]

skip 指令消耗内嵌生成器 A 的属性类型而不生成任何输出. 它总是成功. 内嵌生成器不会被执行.
属性

参见 复合属性记法.

表达式

属性

omit[a] 

a: A --> omit[a]: A
a: Unused --> omit[a]: Unused

skip[a] 

a: A --> skip[a]: A
a: Unused --> skip[a]: Unused
复杂度

omit[] 指令的总体复杂度取决于内嵌生成器的复杂度. skip[] 生成器指令的总体复杂度是 O(1), 因为它不生成任何输出.

示例
注释

下面示例的测试框架在 基础示例 一节中给出.

一些包含:

#include <boost/spirit/include/karma.hpp>
#include <boost/spirit/include/support_utree.hpp>
#include <boost/phoenix/core.hpp>
#include <boost/phoenix/operator.hpp>
#include <boost/fusion/include/std_pair.hpp>
#include <boost/proto/deep_copy.hpp>
#include <iostream>
#include <string>

一些 using 声明:

using boost::spirit::karma::double_;
using boost::spirit::karma::omit;

omit 生成器指令的基本用法. 它展示了该指令如何消耗所提供属性的第一个元素而不生成任何内容, 把属性的第二个元素留给未包装的 double_ 生成器.

std::pair<double, double> p (1.0, 2.0);
test_generator_attr("2.0", omit[double_] << double_, p);

一般来说, 当属性类型包含的信息 (元素) 多于生成所需输出所需要的信息时, 该指令很有用. 通常在这种情况下, 我们会求助于语义动作来显式地把整体属性的正确部分传递给生成器. omit 指令无需使用语义动作即可实现相同目的.

考虑属性类型:

typedef fusion::vector<int, double, std::string> attribute_type;

其中我们只需要从第一个和最后一个元素生成输出:

typedef std::back_insert:iterator<std::string> iterator_type;

karma::rule<iterator_type, attribute_type()> r;
r = int_[_1 = phoenix::at_c<0>(_val)] << string[_1 = phoenix::at_c<2>(_val)];

std::string str;
iterator_type sink(str);
generate(sink, r, attribute_type(1, 2.0, "example"));  // will generate: '1example'

这容易出错且可读性不佳. 使用 omit 指令可以达到同样的效果:

r = int_ << omit[double_] << string;

这样同时更具可读性, 也更高效, 因为我们不必使用语义动作.

使用 skip[] 指令的语义与 omit[] 指令相同, 区别在于它并不实际执行内嵌生成器. 因此, 通常更倾向于使用 skip[] 指令而不是 omit[] 指令. 另一方面, 每当内嵌生成器产生副作用 (具有需要执行的语义动作)时, omit[] 指令非常有用.
