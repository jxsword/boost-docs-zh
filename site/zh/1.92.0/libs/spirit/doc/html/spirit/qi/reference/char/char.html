字符解析器 (char_、lit)
说明

char_ 解析器匹配单个字符. char_ 解析器有一个关联的 字符编码命名空间. 在执行禁止区分大小写和处理字符范围等基本操作时需要用到它.

char_ 有多种形式.

char_

char_ 的无参形式匹配关联的 字符编码命名空间 中的任意字符.

char_               // matches any character
char_(ch)

char_ 的单参数形式 (带一个字符参数) 匹配给定的字符.

char_('x')          // matches 'x'
char_(L'x')         // matches L'x'
char_(x)            // matches x (a char)
char_(first, last)

带两个参数的 char_ 匹配一个字符范围.

char_('a','z')      // alphabetic characters
char_(L'0',L'9')    // digits

字符范围由一个低-高字符对创建. 这样的解析器匹配处于该范围内的单个字符, 包括两个端点. 注意, 第一个字符必须 先于 第二个字符, 这依据底层的 字符编码命名空间.

字符映射本质上是平台相关的. 例如, 标准并不保证 'A' < 'Z', 这就是为什么在 Spirit2 中, 我们特意把一个特定的 字符编码命名空间 (例如 ASCII、ISO-8859-1) 附加到 char_ 解析器上, 以消除这种歧义.

注释

稀疏位向量

为了容纳 16/32 和 64 位字符, 当字符类型不大于 8 位时, 字符集从 std::bitset 实现静态切换为使用不相交范围的有序向量的稀疏位/布尔集(range_run). 该集合由范围构造, 相邻或重叠的范围会被合并.

range_runs 在存在大量范围和少量单个不相交值的情况下非常节省空间. 查找复杂度为 O(log n), 其中 n 是范围的数量.

char_(def)

最后, 当给定一个字符串 (普通 C 字符串, std::basic_string 等)时, 该字符串会被视为字符集定义字符串, 其语法类似于 posix 风格的正则表达式字符集 (不同之处在于用双引号而不是方括号界定集合元素, 且没有特殊的取反 ^ 字符). 示例:

char_("a-zA-Z")     // alphabetic characters
char_("0-9a-fA-F")  // hexadecimal characters
char_("actgACTG")   // DNA identifiers
char_("\x7f\x7e")   // Hexadecimal 0x7F and 0x7E
lit(ch)

当传入单个字符时, lit 的行为类似于单参数的 char_, 只是 lit 不合成属性. 单纯的 char 或 wchar_t 等价于一个 lit.

注释

lit 同时被 字符串解析器 和字符解析器复用. 一般而言, 传入字符时创建字符解析器, 传入字符串时创建字符串解析器. 例外是传入单元素字面量字符串的情况, 例如 lit("x"). 此时我们对此进行优化, 创建字符解析器而不是字符串解析器.

示例:

'x'
lit('x')
lit(L'x')
lit(c) // c is a char
头文件 
// forwards to <boost/spirit/home/qi/char/char.hpp>
#include <boost/spirit/include/qi_char_.hpp>

命名空间

名称

boost::spirit::lit // alias: boost::spirit::qi::lit

ns::char_

在上表中, ns 表示一个 字符编码命名空间.

所属模型

PrimitiveParser

记法约定

c, f, l

一个字面量字符, 例如 'x'、L'x', 或任何可转换为 char 或 wchar_t 的东西; 或一个 惰性参数, 求值为任何可转换为 char 或 wchar_t 的东西.

ns

一个 字符编码命名空间.

cs

一个 String, 或求值为 String 的 惰性参数, 该字符串按照一种类似于 POSIX 风格正则表达式字符集的语法 (不含方括号和取反 ^ 字符) 指定字符集定义字符串.

cp

一个字符解析器、字符范围解析器或字符集解析器.

表达式语义

仅当表达式的语义与 PrimitiveParser 不同或在其中未定义时, 才给出其语义.

表达式

语义

c

从字符 c 创建字符解析器.

lit(c)

从字符 c 创建一个字符解析器.

ns::char_

创建一个匹配 ns 编码中任意字符的字符解析器.

ns::char_(c)

以 ns 编码从字符 c 创建一个字符解析器.

ns::char_(f, l)

创建一个字符范围解析器, 匹配范围 (f 到 l, 含端点) 内的字符, 使用 ns 编码.

ns::char_(cs)

以 ns 编码从字符集定义字符串 cs 创建一个字符集解析器.

~cp

对 cp 取反. 结果是一个取反的字符解析器, 匹配 ns 编码中除 cp 所匹配字符之外的任意字符.

复杂度

O(N), 但对于含 16 位 (或更多) 字符的字符集 (例如 wchar_t) 除外. 这些字符集具有 O(log N) 复杂度, 其中 N 是集合中不同字符范围的数量.

示例
注释

下面示例的测试框架在 基础示例 一节中给出.

一些 using 声明:

using boost::spirit::qi::lit;
using boost::spirit::ascii::char_;

基本字面量:

test_parser("x", 'x');                      // plain literal
test_parser("x", lit('x'));                 // explicit literal
test_parser("x", char_('x'));               // ascii::char_

范围:

char ch;
test_parser_attr("5", char_('0','9'), ch);  // ascii::char_ range
std::cout << ch << std::endl;               // prints '5'

字符集:

test_parser_attr("5", char_("0-9"), ch);    // ascii::char_ set
std::cout << ch << std::endl;               // prints '5'

使用 Boost.Phoenix 的惰性 char_

namespace phx = boost::phoenix;
test_parser("x", phx::val('x'));            // direct
test_parser("5",
    char_(phx::val('0'),phx::val('9')));    // ascii::char_ range
