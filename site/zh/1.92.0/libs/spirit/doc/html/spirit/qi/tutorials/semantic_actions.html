解析器语义动作

上一节的示例非常简单. 它只识别数据, 但对数据不做任何处理. 它回答的问题是: "输入匹配了吗?". 现在, 我们要从解析的内容中提取信息. 例如, 我们希望在成功匹配后存储解析出的数字. 为此, 你需要 语义动作.

语义动作可以附加到文法规范中的任何位置. 这些动作是 C++ 函数或函数对象, 每当解析器的某一部分成功识别输入的一部分时就会被调用. 假设你有一个解析器 P 和一个 C++ 函数 F. 你可以通过附加 F, 让解析器在匹配到输入时调用 F:

P[F]

上面的表达式把 F 链接到解析器 P.

函数/函数对象的签名取决于它所附加到的解析器的类型. 解析器 double_ 传入解析出的数字. 因此, 如果我们要把函数 F 附加到 double_, 我们需要把 F 声明为:

void F(double n);

实际上还会传入另外 2 个参数 (解析器上下文和对布尔 'hit' 参数的引用). 目前我们不需要它们, 稍后我们会更多地了解这些其他参数. Spirit.Qi 允许我们像上面那样绑定单参数函数. 其他参数被简单地忽略.

语义动作示例

下面展示附加语义动作的各种方式:

  • 使用普通函数指针
  • 使用简单函数对象
  • 将 Boost.Bind 与普通函数配合使用
  • 将 Boost.Bind 与成员函数配合使用
  • 使用 Boost.Lambda

给定:

namespace client
{
    namespace qi = boost::spirit::qi;

    // A plain function
    void print(int const& i)
    {
        std::cout << i << std::endl;
    }

    // A member function
    struct writer
    {
        void print(int const& i) const
        {
            std::cout << i << std::endl;
        }
    };

    // A function object
    struct print_action
    {
        void operator()(int const& i, qi::unused_type, qi::unused_type) const
        {
            std::cout << i << std::endl;
        }
    };
}

注意, 使用函数对象时, 我们需要有一个带 3 个参数的 operator(). 由于我们不关心另外两个, 可以为它们使用 unused_type. 稍后我们会在其他地方看到更多 unused_type 的身影. unused_type 是 Spirit 提供的支持类.

所有示例都解析如下形式的输入:

"{integer}"

花括号中的一个整数.

第一个示例展示如何附加一个普通函数:

parse(first, last, '{' >> int_[&print] >> '}');

有什么新东西? 嗯, int_ 是 double_ 的兄弟. 我确信你能猜到这个解析器做什么.

下一个示例展示如何附加一个简单的函数对象:

parse(first, last, '{' >> int_[print_action()] >> '}');

我们可以使用 Boost.Bind 来“绑定”成员函数:

writer w;
parse(first, last, '{' >> int_[boost::bind(&writer::print, &w, _1)] >> '}');

同样地, 我们也可以使用 Boost.Bind 来“绑定”普通函数:

parse(first, last, '{' >> int_[boost::bind(&print, _1)] >> '}');

是的, 我们也可以使用 Boost.Lambda:

parse(first, last, '{' >> int_[std::cout << _1 << '\n'] >> '}');

绑定语义动作函数还有更多方式, 但上面的示例是最常见的. 附加语义动作是开始用 Spirit 解析时必须攻克的第一道关卡. 请熟悉这项任务, 并深入了解其背后的工具, 例如 Boost.Bind 和 Boost.Lambda.

上面的示例可在此处找到: ../../example/qi/actions.cpp

Phoenix

Boost.Phoenix 是 Spirit 附带的伴随库, 特别适合绑定语义动作. 它就像强化版的 Boost.Lambda, 带有特殊的定制特性, 使语义动作与 Spirit 的集成变得容易. 如果你的需求超出简单到中等程度的解析, 建议使用这个库. 本教程接下来的所有示例都将使用 Boost.Phoenix 来编写语义动作.

重要

为 Spirit.Qi 编写语义动作有多种方式: 使用普通函数、Boost.Bind、Boost.Lambda 或 Boost.Phoenix. 后三者允许你使用特殊的占位符来控制参数位置 (_1、_2 等). 这些库各自有自己的占位符实现, 分别位于不同的命名空间. 你必须确保不把占位符与其不属于的库混用, 并且在编写一个语义动作时不混用不同的库.

一般来说, 对于 Boost.Bind, 请使用 ::_1, ::_2 等 (是的, 这些占位符定义在全局命名空间中).

对于 Boost.Lambda, 请使用命名空间 boost::lambda 中定义的占位符.

对于使用 Boost.Phoenix 编写的语义动作, 请使用命名空间 boost::spirit 中定义的占位符. 请注意, 为方便起见, 所有现有的占位符也可以从命名空间 boost::spirit::qi 中使用.
