抑制跳过的解析器指令 (lexeme[])
说明

lexeme 指令使其主体成为基础组件 (primitive). 从逻辑角度看, 词素 (lexeme) (和基础组件) 是最小的原子单元 (例如单词、数字、标识符等). 这些通常是你放进词法分析器的东西 (这也是 "lexeme" 一词的由来), 但在没有词法分析器的世界里, 你把它们放进 lexeme. 把主体视为基础组件, lexeme 指令会执行初始预跳过 (如同所有基础组件一样) 并关闭空白字符跳过.

在短语层级, 解析器会忽略空白字符, 可能还包括注释. 当你想在字符层级而非短语层级工作时, 请使用 lexeme. 把相关部分包进 lexeme 指令中, 可以让解析器在字符层级工作. 例如, 下面是一个解析整数的 rule:

integer = lexeme[ -(lit('+') | '-') >> +digit ];

lexeme 指令指示其主体解析器在字符层级工作. 如果没有它, integer rule 将允许诸如 "1 2 345" 这样的输入中存在错误的内嵌空白字符, 该输入将被解析为 "12345".

注释

请记住 lexeme[] 会预跳过空格. 如果不希望如此, 请改用 no_skip 指令.

// forwards to <boost/spirit/home/qi/directive/lexeme.hpp>
#include <boost/spirit/include/qi_lexeme.hpp>

名称

boost::spirit::lexeme // alias: boost::spirit::qi::lexeme

所属模型

UnaryParser

记法约定

a

表达式语义

仅当表达式的语义与 UnaryParser 不同或在其中未定义时, 才给出其语义.

表达式

语义

lexeme[a]

对主体解析器 a (及其所有子解析器) 进行预跳过并关闭空白字符跳过.
属性

参见 复合属性记法.

表达式

属性

lexeme[a] 

a: A --> lexeme[a]: A
a: Unused --> lexeme[a]: Unused
复杂度

复杂度由主体解析器 a 的复杂度决定

lexeme[] 的简单用法:

这里使用 lexeme 将防止在数字与符号之间跳过, 使 "1 2 345" 这样的输入变为错误.
