Spirit V2.1

从 V2.0 (Boost V1.37.0) 到 V2.1 (Boost V1.41.0) 的变化: Spirit.Qi 和 Spirit.Karma
  • Spirit 现在基于最新版本的 Boost.Proto
  • qi::phrase_parse 和 qi::phrase_format 现在默认执行后置跳过.
  • karma::generate_delimited 和 karma::format_delimited 现在默认不执行前置分隔.
  • 更改了 qi::phrase_parse、qi::phrase_match、karma::generate_delimited 和 match_delimited 的参数顺序. 属性现在始终是最后一个参数.
  • 为这些函数添加了新的重载, 允许显式指定后置跳过和前置分隔行为.
  • 添加了多属性 API 函数
  • 移除了 grammar_def<>
  • 移除了函数 make_parser() 和 make_generator()
  • 移除了 qi::none 和 karma::none
  • 序列和列表现在接受标准容器作为其属性
  • 字符串占位符终结符现在可以接受其他字符串作为其参数 (例如 std::string)
  • 所有接受字面量的终结符现在也接受 (惰性) 函数对象
  • 终结符和指令的所有占位符 (例如 int_、double_、verbatim 等) 此前仅在命名空间 boost::spirit 中定义. 现在它们还被额外导入命名空间 spirit::qi、spirit::karma 和 spirit::lex (如果相应子库支持).
  • 终结符占位符 char_ 和 string 不再在命名空间 boost::spirit 中定义, 因为它们已被移到字符集命名空间, 从而允许基于所用命名空间 (例如 spirit::ascii 等) 进行正确的字符集处理
  • 终结符占位符 uint、ushort、ulong 和 byte 已更名为 uint_、ushort_、ulong_ 和 byte_.
  • qi::skip[] 现在如果在 lexeme[] 内部使用, 会重新启用外层跳过器
  • 添加了 karma::maxwidth[] 指令 (参见 maxwidth)
  • 添加了 karma::omit[], 允许消耗主体生成器的属性而不产生任何输出 (参见 omit).
  • 添加了 karma::buffer[], 允许避免在生成器于序列中途失败时产生不需要的输出 (参见 buffer).
  • karma::delimit[] 现在如果在 verbatim[] 内部使用, 会重新启用外层分隔符
  • Karma: 添加了与谓词 (operator&()) 和非谓词 (operator!()). 两者现在总是消耗一个属性.
  • Karma: 更改了 char_()、string()、int_() 等以及 double_() 等的语义: 所有这些生成器现在总是暴露一个属性. 如果它们没有关联的属性, 就生成其直接字面量. 如果有关联的属性, 生成器会先测试属性值是否等于直接字面量; 若不相等则失败且不生成任何内容; 否则生成其直接字面量. 更多信息例如参见 int_.
  • karma::lit() 现在可用于生成整数和浮点数
  • qi::rule 和 karma::rule 现在可以使用其拷贝构造函数直接初始化. 也就是说, 现在可以这样: qi::rule<...> r = ...some parser...;.
  • 添加了 qi::attr(), 把其直接参数暴露为其属性.
  • 添加了布尔解析器和生成器 (bool_、true_、false_).
  • 添加了 attr_cast<>, 支持在 Qi 和 Karma 文法中进行就地属性类型转换.
  • 几乎所有 Karma 生成器现在都接受 optional<> 属性, 若其未初始化则生成失败.
  • Qi 和 Karma rule 现在自动检测是否应用自动 rule 语义 (不再需要使用 operator%=(), 即使它仍然存在). 如果右侧没有任何元素附加语义动作, 就会应用自动 rule 语义. 这适用于 rule 初始化和赋值.
  • Qi 和 Karma rule 现在基于属性定制点 traits::transform_attribute 进行内在属性转换.
  • 所有 char_ 解析器现在总是暴露一个属性. 早先 char_(...) 不暴露属性, 而 char_ 暴露. 如果你需要不暴露任何属性的字面量解析器, 请改用 lit(...).
  • qi::int_spec、qi::real_spec、karma::int_spec 和 karma real_spec 类型已不存在. 它们已被 qi::int_parser、qi::real_parser、karma::int_generator 和 karma::real_generator 取代.
从 V2.0 (Boost V1.37.0) 到 V2.1 (Boost V1.41.0) 的变化: Spirit.Lex

以下是 Spirit.Lex 自 2.0 版以来的变化列表. Spirit.Lex 2.1 是对随 Boost V1.37 发布的 Spirit.Lex 的完全重写. 与 Spirit 库的所有代码部分一样, Spirit.Lex 可作为独立部分使用. Spirit.Lex 现在使用 Spirit 2.1 版提供的基础设施.

  • lex::lexer_def 类已更名为 lex::lexer, 而原来的 lex::lexer 类已不存在. 这简化了词法分析器的创建.
  • lex::lexer 类不再有函数 def(Self& self), 记号定义可以在任何时候添加到词法分析器, 通常在用户定义的词法分析器类的构造函数中: 
    template <typename Lexer>
struct example_tokens : lex::lexer<Lexer>
{
      example_tokens()
      {
          // your token definitions here
          this->self = ...
      }
};
  • 新的词法分析器类现在可以直接使用. 函数 make_lexer() 已被移除.
  • lex::tokenize_and_parse() 和 lex::tokenize_and_phrase_parse() 函数已更改, 以匹配 qi::parse() 和 qi::phrase_parse() 函数所实现的参数顺序. 二者都把任意数量的属性参数作为最后的参数. 此参数列表受宏 SPIRIT_ARGUMENTS_LIMIT 限制.
  • lex::lexertl_lexer 和 lex::lexertl_token 类已移入 lex::lexertl 命名空间, 名称已更改为 lex::lexertl::lexer 和 lex::lexertl::token. 这也适用于 lex::lexert_actor_lexer 以及 static_lexertl_* 类型族.
  • 类 lex::lexertl_token_set 已被移除. 此功能现在可从词法分析器类获得.
  • Spirit.Lex 库已更新为使用 Ben Hanson 的 Lexertl 词法分析器构建库的最新版本 (Boost 评审待定).
  • lex::lexer<Lexer> 模板构造函数现在接受一个可选参数, 指定用于表生成的 match_flags. 目前有以下标志可用: 
    match_flags::match_default,          // no flags
match_flags::match_not_dot_newline,  // the regex '.' doesn't match newlines
match_flags::match_icase             // all matching operations are case insensitive
    如果未向构造函数传递参数, 则使用 match_flags::match_default, 即 . 匹配换行符且匹配区分大小写.
  • 占位符 char_() 和 string() 现在可用于记号定义, 并且与 token_def 同义.
  • 词法分析器语义动作现在必须符合已更改的接口 (详情参见 词法分析器语义动作).
  • 添加了在使用 Phoenix 时可从词法分析器语义动作内部使用的占位符符号: lex::_start、lex::_end、lex::_eoi、lex::_state、lex::_val 和 lex::_pass (更多细节参见 词法分析器语义动作).
  • 添加了在使用 Phoenix 时可从词法分析器语义动作内部使用的 (惰性) 支持函数: lex::more()、lex::less() 和 lex::lookahead() (更多细节参见 词法分析器语义动作).
  • 移除了 lex::omitted, 改用 lex::omit 以统一整体接口.
