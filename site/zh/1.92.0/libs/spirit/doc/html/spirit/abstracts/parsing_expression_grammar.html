解析表达式文法(PEG)

解析表达式文法(PEG)[6] 是扩展巴科斯-诺尔范式(EBNF)[7] 的一种派生, 但解释不同, 其设计目的是表示递归下降解析器. PEG 可以直接表示为递归下降解析器.

与 EBNF 一样, PEG 是一种形式文法, 通过一组用于识别该语言字符串的规则来描述一种形式语言. 与 EBNF 不同的是, PEG 具有精确的解释. 每个 PEG 文法只有一棵有效的分析树(参见抽象语法树).

序列

与 EBNF 中一样, 序列用并列表示:

a b

上面的 PEG 表达式表明, 若要成功, b 必须跟在 a 之后. 下面是语法图:

下面是一个简单的例子:

'x' digit

它表示字符 x 后面必须跟一个数字.

注释

在 Spirit.Qi 中, 由于 C++ 不允许并列, 我们使用 >> 表示序列; 而在 Spirit.Karma 中则使用 <<.

备选

在 PEG 中, 备选用斜杠表示:

a / b
注释

在 Spirit.Qi 和 Spirit.Karma 中, 与 EBNF 一样, 我们使用 | 表示备选.

备选允许多种选择. 上面的表达式读作: 尝试匹配 a. 如果 a 成功, 则成功; 否则尝试匹配 b. 这与通常的 EBNF 解释略有不同, 在后者中你只需匹配 a 或 b. 下面是语法图:

PEG 允许备选存在歧义. 在上面的表达式中, a 和 b 都可以匹配某个输入字符串. 然而, 只有第一个匹配的备选是有效的. 如前所述, 只能有一棵有效的分析树.

循环

同样, 与 EBNF 一样, PEG 使用正则表达式的 Kleene star 和加号循环:

a*
a+
注释

Spirit.Qi 和 Spirit.Karma 使用前缀星号和加号, 因为 C++ 中没有后缀星号或加号.

下面是相应的语法图:

第一个称为 Kleene star, 匹配其主体 a 零次或多次. 第二个是加号, 匹配其主体 a 一次或多次.

与 EBNF 不同, PEG 的循环是贪婪的. 它会尽可能多地匹配, 直到其主体匹配失败, 而不管后面的内容是什么. 下面是一个经典的例子: 一个相当常见的 EBNF/regex 表达式在 PEG 中匹配失败:

alnum* digit

在 PEG 中, alnum 会尽可能多地吞掉字母数字字符, 不留下任何剩余内容. 因此, 末尾的数字将什么也得不到. 循环在递归下降代码中以 for/while 循环的形式简单实现, 因而极其高效. 这无疑是一个优势. 另一方面, 熟悉 EBNF 和 regex 行为的人可能会觉得这种行为是个大坑. PEG 提供了另外几种机制来规避这个问题. 稍后我们将看到更多这样的机制.

差集

在某些情况下, 你可能希望限制某个表达式. 你可以把 PEG 表达式看作对一个潜在无限字符串集合的匹配. 差集运算符允许你限制这个集合:

a - b

该表达式读作: 匹配 a 但不匹配 b.

注释

Spirit.Karma 中没有差集运算符, 因为这个概念在输出生成的上下文中没有意义.
