迷你 XML - 错误处理

没有错误处理的解析器是不完整的. Spirit2 提供了一些设施, 使为文法适配错误处理变得容易. 我们将用迷你 xml 解析器的另一个版本来结束 Qi 教程, 这次带错误处理.

此示例的完整 cpp 文件可在此处找到: ../../example/qi/mini_xml3.cpp

文法如下:

template <typename Iterator>
struct mini_xml_grammar
  : qi::grammar<Iterator, mini_xml(), qi::locals<std::string>, ascii::space_type>
{
    mini_xml_grammar()
      : mini_xml_grammar::base_type(xml, "xml")
    {
        using qi::lit;
        using qi::lexeme;
        using qi::on_error;
        using qi::fail;
        using ascii::char_;
        using ascii::string;
        using namespace qi::labels;

        using phoenix::construct;
        using phoenix::val;

        text %= lexeme[+(char_ - '<')];
        node %= xml | text;

        start_tag %=
                '<'
            >>  !lit('/')
            >   lexeme[+(char_ - '>')]
            >   '>'
        ;

        end_tag =
                "</"
            >   lit(_r1)
            >   '>'
        ;

        xml %=
                start_tag[_a = _1]
            >   *node
            >   end_tag(_a)
        ;

        xml.name("xml");
        node.name("node");
        text.name("text");
        start_tag.name("start_tag");
        end_tag.name("end_tag");

        on_error<fail>
        (
            xml
          , std::cout
                << val("Error! Expecting ")
                << _4                               // what failed?
                << val(" here: \"")
                << construct<std::string>(_3, _2)   // iterators to error-pos, end
                << val("\"")
                << std::endl
        );
    }

    qi::rule<Iterator, mini_xml(), qi::locals<std::string>, ascii::space_type> xml;
    qi::rule<Iterator, mini_xml_node(), ascii::space_type> node;
    qi::rule<Iterator, std::string(), ascii::space_type> text;
    qi::rule<Iterator, std::string(), ascii::space_type> start_tag;
    qi::rule<Iterator, void(std::string), ascii::space_type> end_tag;
};

有什么新东西?

可读的名称

首先, 调用基类时, 我们为文法起一个名字:

: mini_xml_grammar::base_type(xml, "xml")

然后, 我们为所有 rule 命名:

xml.name("xml");
node.name("node");
text.name("text");
start_tag.name("start_tag");
end_tag.name("end_tag");
成功时

on_success 声明一个处理器, 在 rule 成功匹配时应用.

on_success(rule, handler)

这指定了在 rule 成功匹配时会调用该处理器. 处理器具有如下签名:

void handler(
	fusion::vector<
		Iterator& first,
		Iterator const& last,
		Iterator const& i> args,
	Context& context)

first 指向输入序列中 rule 被匹配之前的位置. last 指向输入序列的最后位置. i 指向输入序列中 rule 所消耗的最后一个字符之后的位置.

成功处理器可用于为文法中每个匹配的 rule 附加关于匹配该 rule 的输入部分的附加信息. 在编译器应用中, 这可以是来自输入流的文件、行号和列号的组合, 用于报告诊断或其他消息.

出错时

on_error 声明我们的错误处理器:

on_error<Action>(rule, handler)

这将指定我们遇到错误时要做什么. 我们将用 phoenix 打印错误消息:

on_error<fail>
(
    xml
  , std::cout
        << val("Error! Expecting ")
        << _4                               // what failed?
        << val(" here: \"")
        << construct<std::string>(_3, _2)   // iterators to error-pos, end
        << val("\"")
        << std::endl
);

在我们的示例中, 我们选择 fail, 针对 Action: 退出并失败. 返回 no_match (false). 它可以是以下之一:

Action

说明

fail

退出并失败. 返回 no_match.

retry

尝试错误恢复, 可能移动迭代器位置.

accept

强制成功, 恰当地移动迭代器位置.

rethrow

重新抛出该错误.

rule 是处理器所附加到的 rule. 在我们的例子中, 我们附加到 xml rule.

handler 是实际的错误处理函数. 它接受 4 个参数:

参数

说明

first

进入带处理器的 rule 时迭代器的位置.

last

输入的末尾.

error-pos

错误发生时迭代器的实际位置.

what

失败的内容: 描述失败的字符串.
期望点

你可能没有注意到, 我们的一些表达式从使用 >> 变成了 >. 例如:

end_tag =
        "</"
    >   lit(_r1)
    >   '>'
;

这是什么? 这是 期望 运算符. 文法中会有一些 "确定性点". 这些是回溯 不能 发生的地方. 对于上面的示例, 当你得到一个 "</" 时, 接下来必定要看到一个有效的结束标签. 它应当是开始标签给你的那个. 之后, 接下来必定要有一个 '>'. 否则, 无论其他分支在哪里, 继续下去并尝试它们都没有意义. 输入肯定是错误的. 发生这种情况时, 会抛出 expectation_failure 异常. 在外层某处, 错误处理器会捕获该异常.

试着构建解析器: ../../example/qi/mini_xml3.cpp. 你可以在 ../../example/qi/mini_xml_samples 中找到一些示例供测试之用. "4.toyxml" 中有一个错误:

<foo><bar></foo></bar>

用它运行该示例会得到:

Error! Expecting "bar" here: "foo></bar>"
Error! Expecting end_tag here: "<bar></foo></bar>"
-------------------------
Parsing failed
