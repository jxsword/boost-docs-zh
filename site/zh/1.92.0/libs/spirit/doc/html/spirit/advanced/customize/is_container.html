判断一个类型是否应被视为容器(Qi 与 Karma)

is_container

模板 is_container 是用作属性定制点的模板元函数. Qi 的 Sequence (>>) 运算符和 Karma 的 Sequence(<<) 运算符会调用它, 以确定所提供的属性是否可能被视为容器.

头文件 
#include <boost/spirit/home/support/container.hpp>

另请参见 包含结构.

注释

用户程序不需要直接包含此头文件, 因为它通常由依赖其内容的其它 Spirit 头文件包含.

命名空间

名称

boost::spirit::traits

概要 
template <typename Container, typename Enable>
struct is_container
{
    <unspecified>;
};
模板参数

参数

说明

none

任意类型

表达式语义

表达式

语义

is_container<C>::type

元函数的结果: 求值为 mpl::true_ (当给定类型 C 要被视为容器时), 否则为 mpl::false_. 通常, is_container 的任何实现都需要表现得如同一个 MPL Boolean Constant.
预定义特化

Spirit 为若干类型预定义了此定制点的特化. 下表列出了这些类型, 以及相应特化求值为 mpl::true_ 的条件(参见 MPL Boolean Constant):

模板参数

语义

T

返回 mpl::true_, 如果 T 定义了以下内嵌类型: value_type, iterator, size_type 和reference. 否则返回 mpl::false_.

boost::optional<T>

返回 is_container<T>::type

boost::variant<T1, T2, ...>

返回 mpl::true_, 如果 is_container<TN>::type 中至少有一个返回 mpl::true_ (其中 TN 为 T1, T2, ...). 否则返回 mpl::false_.

unused_type

返回 mpl::false_.
何时实现

每当某个类型要用作替代 STL 容器的属性时, 就需要为该类型实现定制点 is_container. 它适用于解析器(Spirit.Qi)和生成器(Spirit.Karma). 根据经验: 每当某个类型要作为属性传递给通常暴露 STL 容器的解析器或生成器 C, 且该类型不暴露 STL 容器的接口(即 is_container<C>::type 通常会返回 mpl::false_)时, 就必须实现它. 这些组件具有如下形式的属性传播规则:

a: A --> Op(a): vector<A>

其中 Op(a) 表示对组件 a 的任何有意义的操作.
