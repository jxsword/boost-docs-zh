Spirit V2.2

从 V2.1 (Boost V1.41.0) 到 V2.2 (Boost V1.42.0) 的变化: Spirit.Qi 和 Spirit.Karma
新特性
  • 添加了 auto_ 组件 (位于 Spirit.Qi 和 Spirit.Karma 中), 添加了 API 函数 qi::create_parser 和 karma::create_generator.
  • 为所有不接受属性的 API 函数添加了基于 auto_ 的重载 (参见 Qi API 和 Karma API).
  • 添加了 karma::columns 指令.
  • 添加了 karma::symbols<Attr, T> 生成器.
  • Spirit.Qi 定制点 traits::push_back_container 现在返回 bool 以报告条目是否已添加到容器.
  • 为 karma::maxwidth 指令添加了一个重载, 允许指定一个附加参数 (任何兼容的输出迭代器) 来接收 "溢出" 输出 (不适合 maxwidth 限制的输出).
  • 现在可以把 Phoenix 表达式用作 Spirit.Karma 属性.
  • 添加了 basic_istream_iterator<Char, Traits>, 可用作 std::istream_iterator 的等价物, 区别在于它是一个 ForwardIterator, 允许直接从任何 std::basic_istream 解析.
  • 添加了 qi::matches 指令.
缺陷修复
  • 修复了 karma::alternatives 使其能与 hold_any 的内嵌容器配合工作 (即 *stream | "empty" 这样的构造) (这也修复了 Karma 示例 basic_facilities.cpp).
  • 修复了针对字符类型的数值 Spirit.Karma 生成器.
  • 为未使用的属性修复了 qi::repeat[].
  • 修复了 karma::repeat[] 中一个罕见的编译问题.
  • 修复了 Spirit.Qi 和 Spirit.Karma 中的序列, 使其在属性为 (STL) 容器的 (STL) 容器时能正确编译.
  • 修复了 lex::token_def::what 中的一个缺陷.
  • 修复了 Spirit.Qi symbols, 使其不再匹配子字符串. 添加了 qi::symbols::prefix_find 以允许匹配 (前缀) 子字符串.
  • rule 的继承参数通常必须包装在函数对象中 (即 phoenix::val), 对整数值则无此必要. 现在所有字符串类型也可以不经包装直接传入 (即 std::string、char const* 等).
  • 为所有相关的 Spirit.Qi API 函数添加了概念检查, 强制迭代器至少为 std::forward_iterator_tag 类型.
  • 修复了 qi::match 和 qi::phrase_match 这组 API 函数, 使其不再在内部使用 std::stream_iterator, 因为此迭代器仅为 std::input_iterator_tag 类型, 对 Spirit.Qi 来说是不够的.
