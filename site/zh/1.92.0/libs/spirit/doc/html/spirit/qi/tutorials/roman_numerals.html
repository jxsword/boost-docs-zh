罗马数字

本示例演示:

  • 符号表
  • rule
  • 文法
符号表

符号表保存符号字典, 其中每个符号是一个字符序列 (char、wchar_t、int、枚举等). 该模板类以字符类型为参数, 可以高效处理 8、16、32 甚至 64 位字符. 每个符号关联一个类型为 T 的可变数据.

传统上, 符号表管理是在 BNF 文法之外通过语义动作单独维护的. 与标准做法相反, Spirit 的符号表类 symbols 是一个解析器. 其实例可以在 EBNF 文法规范的任何地方使用. 它是动态解析器的一个例子. 动态解析器的特点在于能够在运行期修改自身行为. 最初, 空的 symbols 对象不匹配任何内容. 任何时候都可以添加或删除符号, 从而动态改变其行为.

符号表中的每个条目都有一个关联的可变数据槽. 就此而言, 可以把符号表看作键为字符串的键值对关联容器 (或映射).

symbols 类需要两个模板参数. 第一个参数指定符号的字符类型. 第二个参数指定与每个符号关联的数据类型: 即其属性.

下面是使用符号表解析罗马数字百位 (100..900) 的解析器. 记住, 与每个槽关联的数据是解析器的属性 (会传给附加的语义动作).

struct hundreds_ : qi::symbols<char, unsigned>
{
    hundreds_()
    {
        add
            ("C"    , 100)
            ("CC"   , 200)
            ("CCC"  , 300)
            ("CD"   , 400)
            ("D"    , 500)
            ("DC"   , 600)
            ("DCC"  , 700)
            ("DCCC" , 800)
            ("CM"   , 900)
        ;
    }

} hundreds;

下面是解析罗马数字十位 (10..90) 的解析器:

struct tens_ : qi::symbols<char, unsigned>
{
    tens_()
    {
        add
            ("X"    , 10)
            ("XX"   , 20)
            ("XXX"  , 30)
            ("XL"   , 40)
            ("L"    , 50)
            ("LX"   , 60)
            ("LXX"  , 70)
            ("LXXX" , 80)
            ("XC"   , 90)
        ;
    }

} tens;

最后, 个位 (1..9) 的解析器:

struct ones_ : qi::symbols<char, unsigned>
{
    ones_()
    {
        add
            ("I"    , 1)
            ("II"   , 2)
            ("III"  , 3)
            ("IV"   , 4)
            ("V"    , 5)
            ("VI"   , 6)
            ("VII"  , 7)
            ("VIII" , 8)
            ("IX"   , 9)
        ;
    }

} ones;

现在我们可以在解析器表达式的任何地方使用 hundreds、tens 和 ones. 它们都是解析器.

规则

到目前为止, 我们一直把解析器表达式内联, 直接传给 phrase_parse 函数. 表达式求值为一个临时的、匿名的解析器, 它被传入 phrase_parse 函数, 使用后随即销毁. 这对小解析器没问题. 当表达式变复杂时, 你会希望把表达式拆成更小、更易理解的部分, 给它们命名, 并在其他解析器表达式中按名称引用.

解析器表达式可以赋给所谓的 "rule". 声明 rule 有多种方式. 最简单的形式是:

rule<Iterator> r;

至少, rule 需要知道它要处理的迭代器类型. 这个 rule 不能与 phrase_parse 一起使用. 它只能与 parse 函数 -- 一个不做空白字符跳过的版本 (没有跳过器参数) -- 一起使用. 如果你想让它跳过空白字符, 你需要传入跳过解析器的类型, 如下一种形式:

rule<Iterator, Skipper> r;

示例:

rule<std::string::iterator, space_type> r;

这种类型的 rule 既可用于 phrase_parse 也可用于 parse.

对于下一个示例, 还有一种你应该了解的 rule 形式:

rule<Iterator, Signature> r;

或者

rule<Iterator, Signature, Skipper> r;
提示

Iterator 之后的 rule 模板参数可以以任意顺序提供.

Signature 指定 rule 的属性. 你已经看到我们的解析器可以有属性. 回想一下, double_ 解析器有一个 double 属性. 准确地说, 这些是 合成 属性. 解析器 "合成" 属性值. 把它们想象成函数返回值.

还有另一种属性, 称为 "继承" 属性. 目前我们不需要它们, 但你应该知道这类属性的存在. 你可以把它们想象成函数参数. 相应地, rule 签名就是一个形如下面的函数签名:

result(argN, argN,..., argN)

声明 rule 之后, 现在可以把任何解析器表达式赋给它. 示例:

r = double_ >> *(',' >> double_);
文法

文法封装一个或多个 rule. 它与 rule 具有相同的模板参数. 声明文法的方法是:

  1. 从 grammar 类模板派生一个 struct (或 class)
  2. 声明一个或多个 rule 作为成员变量
  3. 通过给出起始 rule 来初始化基文法类 (它是文法开始解析时第一个被调用的 rule)
  4. 在你的构造函数中初始化你的 rule

罗马数字文法是一个非常好的文法简单示例:

template <typename Iterator>
struct roman : qi::grammar<Iterator, unsigned()>
{
    roman() : roman::base_type(start)
    {
        using qi::eps;
        using qi::lit;
        using qi::_val;
        using qi::_1;
        using ascii::char_;

        start = eps             [_val = 0] >>
            (
                +lit('M')       [_val += 1000]
                ||  hundreds    [_val += _1]
                ||  tens        [_val += _1]
                ||  ones        [_val += _1]
            )
        ;
    }

    qi::rule<Iterator, unsigned()> start;
};

需要注意的事项:

  • 文法和起始 rule 的签名是 unsigned(). 它有一个类型为 unsigned 的合成属性 (返回值), 没有继承属性 (参数).
  • 我们没有指定跳过解析器. 我们不想在数字之间跳过.
  • roman::base_type 是 grammar<Iterator, unsigned()> 的 typedef. 如果 roman 不是模板, 你可以简单地写: base_type(start)
  • 最好把你的文法做成模板, 使它们可以针对不同的迭代器类型复用.
  • _val 是另一个 Boost.Phoenix 占位符, 表示 rule 的合成属性.
  • eps 是一个特殊的 Spirit 解析器, 不消耗任何输入且总是成功. 我们用它把 rule 的合成属性 _val 在其他任何操作之前初始化为零. 真正的解析器从 +lit('M') 开始, 解析罗马数字千位. 以这种方式使用 eps 有利于做前置和后置初始化.
  • 表达式 a || b 读作: 按顺序匹配 a 或 b. 也就是说, 如果 a 和 b 都匹配, 则必须按顺序匹配; 这等价于 a >> -b | b, 但更高效.
开始解析! 

bool r = parse(iter, end, roman_parser, result);

if (r && iter == end)
{
    std::cout << "-------------------------\n";
    std::cout << "Parsing succeeded\n";
    std::cout << "result = " << result << std::endl;
    std::cout << "-------------------------\n";
}
else
{
    std::string rest(iter, end);
    std::cout << "-------------------------\n";
    std::cout << "Parsing failed\n";
    std::cout << "stopped at: \": " << rest << "\"\n";
    std::cout << "-------------------------\n";
}

roman_parser 是一个类型为 roman 的对象, 即我们的罗马数字解析器. 这次我们使用不带跳过的 parse 函数版本. 我们不想跳过任何空格! 我们还传入一个属性 unsigned result, 它将接收解析出的值.
