Spirit V2.3

从 V2.2 (Boost V1.42.0) 到 V2.3 (Boost V1.43.0) 的变化: Spirit.Qi 和 Spirit.Karma
新特性
  • 定制点 transform_attribute 现在必须实现第三个函数: void fail(Exposed&), 它通常什么都不做. 每当 rule 的右侧 (或 attr_cast 的内嵌解析器) 解析失败时, 都会调用此函数. 此变更只影响 Qi. 更多细节参见 traits::transform_attribute 的描述.
  • 添加了对用 BOOST_FUSION_ADAPT_CLASS 和 BOOST_FUSION_ADAPT_CLASS_NAMED 创建的属性序列的支持. 此支持需要包含新的头文件: #include <boost/spirit/include/support_adapt_class_attributes.hpp>.
  • 添加了 karma::ostream_iterator 作为 qi::istream_iterator 的对应物 (参见新头文件: #include <boost/spirit/home/support/iterators/ostream_iterator.hpp>).
  • 添加了 qi::hold, 允许确保内嵌解析器在解析失败时不会触碰传入的属性.
  • 添加了 qi::no_skip 指令, 它等价于 qi::lexeme, 只是不做预跳过.
  • 添加了 karma::no_delimit 指令, 它等价于 karma::verbatim, 只是不执行后置分隔步骤.
  • 为 multi_pass 迭代器框架添加了新的 input_iterator 策略 (名为 buffering_input_iterator), 允许包装不保存从输入读取的最后一个字符的底层输入迭代器 (例如 std::istream_iterator). 现在它被用作默认输入策略.
缺陷修复
  • 序列 (Qi 和 Karma 中) 现在可以让一个没有属性的组件作为其最后一个元素.
  • 序列 (Qi 和 Karma 中) 现在可以把单元素属性序列作为其属性.
  • karma::buffer[karma::buffer[...]] 这样的构造不再导致执行双重缓冲. 如果备选项被包装进 karma::buffer[] 指令, 情况也是如此 (例如: buffer[a] | b).
  • Spirit.Karma 输出迭代器 (内部使用, 在使用基于流的 API 时也会暴露) 现在可以正确复制 (感谢 Jonas Persson 报告此问题).
  • 默认 multi_pass 迭代器现在可用于不保存从输入读取的最后一个字符的底层输入迭代器 (例如 std::istream_iterator). 感谢 Larry Evans 和 Peter Schueller 独立报告此问题.
  • 指令 karma::omit[] 现在不再接受任意属性类型.
  • Spirit.Karma 谓词 (与谓词和非谓词) 以及指令 karma::omit[] 现在完全禁用输出, 而不是像以前那样把输出拦截到一个随后被丢弃的缓冲区中.
  • 修复了 karma::rule 以正确处理可选属性.
从 V2.2 (Boost V1.42.0) 到 V2.3 (Boost V1.43.0) 的变化: Spirit.Lex
新词法分析器特性
  • 该库默认不再为动态词法分析器最小化生成的词法分析器表. 现在只为静态词法分析器最小化生成的表.
  • 函数 lexer<>::init_dfa() 现在接受单个布尔参数 (默认为 false), 允许强制最小化生成的词法分析器表.
