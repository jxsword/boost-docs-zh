生成器语义动作

在上一节中我们提到了解析器与生成器之间一个非常重要的区别. 解析器可以在不“生成”任何数据的情况下使用, 而生成器总是需要有数据才能生成输出. 我们提到过一种向生成器传递数据的方式: 将其作为主 API 函数之一的参数提供 (例如 generate() 或 generate_delimited()). 但有时这样做不可行, 或者并不理想.

与 Spirit.Qi 非常相似, Spirit.Karma 中同样有语义动作. 语义动作可以附加到文法规格中的任何位置. 这些动作是一些 C++ 函数或函数对象, 每当生成器的某个部分即将被调用时就会被调用. 假设你有一个生成器 G 和一个 C++ 函数 F, 你可以让生成器在即将被调用之前调用 F, 做法是附加 F:

G[F]

上面的表达式把 F 链接到生成器 G 上.

Spirit.Qi 中的语义动作是在解析器成功匹配其输入之后被调用的, 匹配到的值会被传入该语义动作. 在 Spirit.Karma 中情况正好相反: 语义动作在其关联的生成器被调用之前被调用, 它们可以提供生成器所需的数据.

函数/函数对象的签名取决于它所附加到的生成器的类型. 生成器 double_ 需要一个要生成的数字. 因此, 如果我们要把函数 F 附加到 double_ 上, 就需要把 F 声明为:

void F(double& n);

其中要求该函数使用要生成的值来初始化参数 n.

重要

一般而言, 更正式地说, 语义动作 F 附加到生成器 G 上时, 需要将对生成器属性类型的引用作为其第一个参数. 关于生成器属性的更多信息, 请参见“生成器属性”一节.

在上面的例子中, 函数 F 以 double& 作为其第一个参数, 因为生成器 double_ 的属性恰好是 double.

实际上还会传入另外 2 个参数 (生成器上下文, 以及对一个布尔型 'pass' 参数的引用). 目前我们不需要它们, 但稍后我们会进一步讨论这些其他参数. Spirit.Karma 允许我们像上面那样绑定单参数函数, 其余参数会被直接忽略.

总而言之, 语义动作可能的签名有:

void f(Attrib&);
void f(Attrib&, Context&);
void f(Attrib&, Context&, bool&);
语义动作示例

在下面的例子中, 我们展示附加语义动作的多种方式:

  • 使用普通函数指针
  • 使用简单函数对象
  • 将 Boost.Bind 与普通函数配合使用
  • 将 Boost.Bind 与成员函数配合使用
  • 使用 Boost.Lambda

假设我们有:

namespace client
{
    namespace karma = boost::spirit::karma;

    // A plain function
    void read_function(int& i)
    {
        i = 42;
    }

    // A member function
    struct reader
    {
        void print(int& i) const
        {
            i = 42;
        }
    };

    // A function object
    struct read_action
    {
        void operator()(int& i, unused_type, unused_type) const
        {
            i = 42;
        }
    };
}

注意, 对于函数对象, 我们需要一个带有 3 个参数的 operator(). 由于我们不关心另外两个参数, 可以对它们使用 unused_type. 我们会在别处更多地见到 unused_type, 要习惯使用它. unused_type 是 Spirit 提供的一个支撑类, 大多数时候它表示“我不在乎, 就用合适的默认值”.

以下所有示例生成的输出形式如下:

"{integer}"

花括号中的一个整数.

第一个示例展示如何附加一个普通函数:

generate(outiter, '{' << int_[&read_function] << '}');

有什么新东西? 嗯, int_ 是 double_ 的兄弟. 相信你能猜到这个生成器做什么, 以及它期望什么类型的属性.

下一个示例展示如何附加一个简单的函数对象:

generate(outiter, '{' << int_[read_action()] << '}');

我们可以使用 Boost.Bind 来“绑定”成员函数:

reader r;
generate(outiter, '{' << int_[boost::bind(&reader::print, &r, _1)] << '}');

同样地, 我们也可以使用 Boost.Bind 来“绑定”普通函数:

generate(outiter, '{' << int_[boost::bind(&read_function, _1)] << '}');

最后同样重要的是, 我们还可以使用 Boost.Lambda:

std::stringstream strm("42");
generate(outiter, '{' << int_[strm >> lambda::_1] << '}');

绑定语义动作函数还有更多方式, 但上面的例子是最常见的. 附加语义动作是开始用 Spirit 进行生成时要闯的第一道关. 如果你还没有这样做, 熟悉一下其背后的工具 (如 Boost.Bind 和 Boost.Lambda) 或许是个好主意.

Phoenix

Boost.Phoenix 是随 Spirit 一起提供的一个配套库, 特别适合用于绑定语义动作. 它就像是强化版的 Boost.Lambda, 带有一些特别的定制特性, 使得语义动作与 Spirit 的集成变得容易. 如果你的需求超出了简单到中等程度的生成, 我建议你使用这个库. 从现在起给出的示例将只使用 Phoenix 库.

重要

为 Spirit.Karma 编写语义动作有多种方式: 使用普通函数, Boost.Bind, Boost.Lambda 或 Boost.Phoenix. 后三者允许你使用特殊的占位符来控制参数的位置 (_1, _2 等). 这些库各自有自己的占位符实现, 分别位于不同的命名空间中. 你必须确保不要把占位符与不属于它们的库混用, 也不要在编写一个语义动作时混用不同的库.

一般来说, 对于 Boost.Bind, 请使用 ::_1, ::_2 等 (是的, 这些占位符定义在全局命名空间中).

对于 Boost.Lambda, 请使用命名空间 boost::lambda 中定义的占位符.

对于使用 Boost.Phoenix 编写的语义动作, 请使用命名空间 boost::spirit 中定义的占位符. 请注意, 为方便起见, 所有现有的占位符也可以从命名空间 boost::spirit::karma 中使用.
