快速上手 1 - 单词计数器: 使用 Spirit.Lex

Spirit.Lex 是高度模块化的, 这遵循了 Spirit 库的总体构建原则. 你永远不会为用不到的特性付出代价. 它与其他 Spirit 部分紧密集成, 但也可以单独使用来构建独立的词法分析器. 第一个快速上手示例描述了一个独立应用: 统计文件中的字符数、单词数和行数, 与著名的 Unix 命令 wc 所做的非常相似 (完整示例代码见此处: word_count_functor.cpp).

前置条件

唯一需要的 #include (特定于 Spirit.Lex) 如下. 它是为了以独立方式使用 Spirit.Lex、并构建于 Lexertl 库之上所需的全部必要定义的一个封装. 此外, 我们 #include 了两个 Boost 头文件, 以定义 boost::bind() 和 boost::ref().

#include <boost/spirit/include/lex_lexertl.hpp>
#include <boost/bind/bind.hpp>
#include <boost/ref.hpp>

为了让下面的代码更易读, 我们引入以下命名空间.

namespace lex = boost::spirit::lex;

定义记号

使用 Spirit.Lex 创建词法分析器时最重要的一步, 是定义要在输入序列中识别的记号. 这通常通过定义描述匹配字符序列的正则表达式 (以及可选的相应记号 id) 来完成. 此外, 定义的记号需要与库提供的词法分析器对象的实例相关联. 下面的代码片段展示了如何用 Spirit.Lex 完成这一步.

模板 word_count_tokens 定义了三个不同的记号: ID_WORD、ID_EOL 和 ID_CHAR, 分别表示一个单词 (除空白字符或换行符以外的任何内容)、一个换行符以及任何其他字符 (ID_WORD、ID_EOL 和 ID_CHAR 是表示记号 id 的枚举值, 但也可以是任何其他可转换为整数的值). 任何记号定义类的直接基类都必须是模板 lex::lexer<>, 其对应的模板参数 (此处为: lex::lexertl::lexer<BaseIterator>) 定义了必须使用哪种底层词法分析引擎来提供所需的状态机功能. 在本例中, 我们使用基于 Lexertl 的词法分析引擎作为底层词法分析器类型.

template <typename Lexer>
struct word_count_tokens : lex::lexer<Lexer>
{
    word_count_tokens()
    {
        // define tokens (the regular expression to match and the corresponding
        // token id) and add them to the lexer 
        this->self.add
            ("[^ \t\n]+", ID_WORD) // words (anything except ' ', '\t' or '\n')
            ("\n", ID_EOL)         // newline characters
            (".", ID_CHAR)         // anything else is a plain character
        ;
    }
};

完成有用的工作

我们将采用这样一种设置: 希望 Spirit.Lex 库在识别出任何生成的记号之后调用一个给定函数. 为此, 我们需要实现一个仿函数, 它至少接受生成的记号作为参数, 并返回一个布尔值, 用于允许停止记号化过程. 本例使用的默认记号类型携带一个类型为 boost::iterator_range<BaseIterator> 的记号值, 指向底层输入序列中被匹配的范围.

在本例中, 结构体 'counter' 被用作仿函数, 通过识别由 Spirit.Lex 库传入的已匹配记号, 来统计被分析输入序列中的字符数、单词数和行数.

struct counter
{
    // the function operator gets called for each of the matched tokens
    // c, l, w are references to the counters used to keep track of the numbers
    template <typename Token>
    bool operator()(Token const& t, std::size_t& c, std::size_t& w, std::size_t& l) const
    {
        switch (t.id()) {
        case ID_WORD:       // matched a word
        // since we're using a default token type in this example, every 
        // token instance contains a `iterator_range<BaseIterator>` as its token
        // attribute pointing to the matched character sequence in the input 
            ++w; c += t.value().size();
            break;
        case ID_EOL:        // matched a newline character
            ++l; ++c;
            break;
        case ID_CHAR:       // matched something else
            ++c;
            break;
        }
        return true;        // always continue to tokenize
    }
};

剩下的就是编写一些样板代码, 把目前描述的各个部分联系起来. 为了简化本示例, 我们调用 lex::tokenize() 函数 (该函数在 Spirit.Lex 中实现; 关于此函数的更详细描述见此处: FIXME), 尽管我们也可以编写一个循环来遍历词法分析器迭代器 [first, last).

整合所有内容

主函数只是把给定文件加载到内存中 (作为一个 std::string), 使用正确的迭代器类型实例化记号定义模板的一个实例 (word_count_tokens<char const*>), 最后调用 lex::tokenize 并传入该计数函数对象的一个实例. 如果整个输入序列已被成功记号化, 则 lex::tokenize() 的返回值将为 true, 否则为 false.

int main(int argc, char* argv[])
{
    // these variables are used to count characters, words and lines
    std::size_t c = 0, w = 0, l = 0;

    // read input from the given file
    std::string str (read_from_file(1 == argc ? "word_count.input" : argv[1]));

    // create the token definition instance needed to invoke the lexical analyzer
    word_count_tokens<lex::lexertl::lexer<> > word_count_functor;

    // tokenize the given string, the bound functor gets invoked for each of 
    // the matched tokens
    using boost::placeholders::_1;
    char const* first = str.c_str();
    char const* last = &first[str.size()];
    bool r = lex::tokenize(first, last, word_count_functor,
        boost::bind(counter(), _1, boost::ref(c), boost::ref(w), boost::ref(l)));

    // print results
    if (r) {
        std::cout << "lines: " << l << ", words: " << w
                  << ", characters: " << c << "\n";
    }
    else {
        std::string rest(first, last);
        std::cout << "Lexical analysis failed\n" << "stopped at: \""
                  << rest << "\"\n";
    }
    return 0;
}

将 Spirit.Lex 与 Flex 比较

刻意选择本示例, 使其尽可能类似于等价的 Flex 程序 (见下文), 后者与使用 Spirit.Lex 时需要编写的内容没有太大不同.

注释

有趣的是, 用 Spirit.Lex 编写的词法分析器与 Flex 生成的等价程序的性能比较表明, 两者的执行速度相当! 总的来说, 多亏了高度优化的 Lexertl 库以及与 Spirit 的精心设计集成, 使用 Spirit.Lex 所需付出的抽象代价可以忽略不计.

本教程剩余的示例将使用 Spirit.Lex 更复杂的特性, 主要是为了进一步简化要编写的代码, 同时保持与 Flex 相应特性的相似性. Spirit.Lex 的设计目标是尽可能与 Flex 相似. 这就是为什么在本文档中, 对应的 Flex 代码几乎处处伴随着所展示的 Spirit.Lex 示例. 因此, 下面就是与上文所示示例对应的 Flex 代码.

%{
    #define ID_WORD 1000
    #define ID_EOL  1001
    #define ID_CHAR 1002
    int c = 0, w = 0, l = 0;
%}
%%
[^ \t\n]+  { return ID_WORD; }
\n         { return ID_EOL; }
.          { return ID_CHAR; }
%%
bool count(int tok)
{
    switch (tok) {
    case ID_WORD: ++w; c += yyleng; break;
    case ID_EOL:  ++l; ++c; break;
    case ID_CHAR: ++c; break;
    default:
        return false;
    }
    return true;
}
void main()
{
    int tok = EOF;
    do {
        tok = yylex();
        if (!count(tok))
            break;
    } while (EOF != tok);
    printf("%d %d %d\n", l, w, c);
}
