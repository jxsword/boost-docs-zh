关于记号与记号值

如前所述, 词法扫描是分析输入字符流并将其切分为被称为记号 (token) 的字符串的过程, 这些字符串大多数时候由空白分隔. 词法分析器所识别的不同记号类型通常会被赋予唯一的整数记号标识符 (token id). 这些 token id 通常被解析器用来识别当前记号, 而无需再次查看匹配到的字符串. Spirit.Lex 库在这一点上并无不同, 它使用 token id 作为标识为特定词法分析器定义的不同记号类型的主要手段. 不过, 它与常用的词法分析器有所不同: 它向用户返回 (用户定义的) 记号类的实例 (或其引用). 这个记号类的唯一限制是, 它必须至少携带其所表示记号的 token id. 关于用户定义记号类型必须暴露的接口的更多信息, 请查阅 Token Class 参考部分. 本库提供了一个基于 Lexertl 库的默认记号类型, 在大多数情况下应该足够使用: 即 lex::lexertl::token<> 类型. 本节着重描述记号类可以实现的一般特性, 以及它与 Spirit.Lex 库其他部分的集成方式.

记号的剖析

理解记号定义 (由模板 lex::token_def<> 表示) 与记号本身 (例如由模板 lex::lexertl::token<> 表示) 之间的区别非常重要.

记号定义用于描述特定记号类型的主要特性, 尤其是:

  • 使用在匹配该记号类型时应用的正则表达式模式来简化记号类型的定义,
  • 将一个记号类型与特定的词法分析器状态相关联,
  • 可选地为记号类型指定一个 token id,
  • 可选地关联一段代码, 每当匹配到该记号类型的实例时就执行它,
  • 以及可选地指定记号值的属性类型.

记号本身是由词法分析器迭代器返回的数据结构. 解引用一个词法分析器迭代器会返回对最后匹配的记号实例的引用. 它封装了底层输入序列中由定义该记号类型时所用的正则表达式匹配到的部分. 递增词法分析器迭代器会推进底层输入流, 并调用词法分析器去匹配下一个记号. 记号数据结构至少包含被匹配记号类型的 token id, 从而可以识别匹配到的字符序列. 可选地, 记号实例还可以包含一个记号值和/或该记号实例被匹配时所处的词法分析器状态. 下面的图展示了一个记号的示意结构.

出于优化的考虑, 记号值以及记号被识别时所处词法分析器状态可以省略, 从而避免记号携带多于实际所需的数据. 这一配置可以在定义记号类型时, 通过为 lex::lexertl::token<> 模板提供适当的模板参数来实现.

词法分析器迭代器对每个被匹配的不同记号定义都返回同一种记号类型. 为了容纳各种记号类型 (记号定义) 可能暴露的不同记号值类型, 记号值的一般类型是一个 Boost.Variant. 至少 (对于默认配置) 这个记号值 variant 会被配置为始终持有一个 boost::iterator_range, 其中包含指向该记号实例匹配到的输入序列的迭代器对.

注释

如果该词法分析器与 Spirit.Qi 解析器配合使用, 存储的 boost::iterator_range 记号值将恰好被转换为所请求的记号类型 (解析器属性) 一次. 这发生在第一次访问需要相应类型转换的记号值时. 转换后的记号值将存储在 Boost.Variant 中, 替换最初存储的迭代器范围. 这避免了把输入序列不止一次地转换为记号值, 从而优化了词法分析器与 Spirit.Qi 的集成, 即使在解析器回溯期间也是如此.

下面是 lex::lexertl::token<> 模板的原型:

template <
    typename Iterator = char const*,
    typename AttributeTypes = mpl::vector0<>,
    typename HasState = mpl::true_
>
struct lexertl_token;

其中:

Iterator

这是用于访问底层输入流的迭代器的类型. 其默认值为普通 char const*.

AttributeTypes

它或者是一个 mpl 序列, 包含记号定义所用的所有属性类型, 或者是类型 omit. 如果 mpl 序列为空 (这是默认情况), 所有记号实例将存储一个 boost::iterator_range<Iterator>, 指向输入流中匹配区段的起始和结束位置. 如果类型是 omit, 生成的记号将完全不包含记号值 (属性).

HasState

它或者是 mpl::true_, 或者是 mpl::false_, 用于控制生成的记号实例是否包含它们生成时所处的词法分析器状态. 默认值为 mpl::true_, 因此所有记号实例都将包含词法分析器状态.

通常, 在构造期间, 记号实例总是持有一个 boost::iterator_range 作为其记号值, 除非它被定义为使用 omit 记号值类型. 当第一次被请求时, 这个迭代器范围会被就地转换为所请求的记号值类型 (属性).

记号定义的外貌

记号定义 (由 lex::token_def<> 模板表示) 通常作为词法分析器定义的一部分使用. 同时, 记号定义实例也可以在 Spirit.Qi 中用作解析器组件.

这个类的模板原型如下所示:

template<
    typename Attribute = unused_type,
    typename Char = char
>
class token_def;

其中:

Attribute

这是表示该记号类型的记号实例所支持的记号值 (属性) 的类型. 每当这个记号定义被用作解析器组件时, 该属性类型就会暴露给 Spirit.Qi 库. 默认属性类型是 unused_type, 这意味着记号实例持有一个 boost::iterator_range, 指向输入流中匹配区段的起始和结束位置. 如果属性是 omit, 记号实例将完全不暴露任何记号类型. 任何其他类型都将直接用作记号值类型.

Char

这是底层输入序列的迭代器的值类型. 其默认值为 char.

记号类型与记号定义类型的模板参数的语义非常相似且相互关联. 根据经验, 你可以把记号定义类型看作是指定与某个特定记号类型相关的一切的手段 (例如 identifier 或 integer). 另一方面, 记号类型用于定义 Spirit.Lex 库生成的所有记号实例的一般特性.

重要

如果你在记号类型定义声明中没有列出任何记号值类型 (这将使用默认的 boost::iterator_range 记号类型), 一切都会正常编译和工作, 只是效率稍低. 这是因为每次请求记号值时, 都会从匹配到的输入序列重新转换得到.

但是, 一旦你在定义记号类型时指定了至少一个记号值类型, 你就必须在记号定义类中列出 lex::token_def<> 声明所用的所有值类型, 否则将发生编译错误.

使用 lex::lexertl::token<> 的示例

让我们从一些例子开始. 我们参考 Spirit.Lex 的一个示例 (该示例的完整源代码请参见 example4.cpp).

第一段代码片段展示了记号定义类的一个摘录, 即几个记号类型的定义. 其中一些记号类型不暴露特殊的记号值 (if_, else_ 和 while_). 它们的记号值将始终持有匹配到的输入序列的迭代器范围. identifier 和整数 constant 的记号定义被特化, 分别暴露一个显式的记号类型: std::string 和 unsigned int.

// these tokens expose the iterator_range of the matched input sequence
lex::token_def<> if_, else_, while_;

// The following two tokens have an associated attribute type, 'identifier'
// carries a string (the identifier name) and 'constant' carries the 
// matched integer value.
//
// Note: any token attribute type explicitly specified in a token_def<>
//       declaration needs to be listed during token type definition as 
//       well (see the typedef for the token_type below).
//
// The conversion of the matched input to an instance of this type occurs
// once (on first access), which makes token attributes as efficient as 
// possible. Moreover, token instances are constructed once by the lexer
// library. From this point on tokens are passed by reference only, 
// avoiding them being copied around.
lex::token_def<std::string> identifier;
lex::token_def<unsigned int> constant;

由于 Spirit.Qi 生成的解析器是全属性的, 任何 Spirit.Qi 解析器组件都需要暴露某个类型作为其解析器属性. 自然地, lex::token_def<> 将记号值类型暴露为其解析器属性, 从而实现与 Spirit.Qi 的平滑集成.

下一段代码片段演示了在定义要使用的记号类型时如何指定所需的记号值类型. 至少被一个记号定义用到的所有记号值类型, 也必须为该记号定义重新逐一列出.

// This is the lexer token type to use. The second template parameter lists 
// all attribute types used for token_def's during token definition (see 
// calculator_tokens<> above). Here we use the predefined lexertl token 
// type, but any compatible token type may be used instead.
//
// If you don't list any token attribute types in the following declaration 
// (or just use the default token type: lexertl_token<base_iterator_type>)  
// it will compile and work just fine, just a bit less efficient. This is  
// because the token attribute will be generated from the matched input  
// sequence every time it is requested. But as soon as you specify at 
// least one token attribute type you'll have to list all attribute types 
// used for token_def<> declarations in the token definition class above, 
// otherwise compilation errors will occur.
typedef lex::lexertl::token<
    base_iterator_type, boost::mpl::vector<unsigned int, std::string>
> token_type;

要完全避免记号拥有记号值, 可以使用特殊标签 omit: token_def<omit> 和 lexertl_token<base_iterator_type, omit>.
