符号生成器(symbols)
说明

类 symbols 实现了一个"反向"符号表: 键值对的关联容器 (或映射), 其值 (大多数时候)是字符串. 它把要生成的值 (键)映射到任何其他值, 后者将替代原始键被输出.

Karma 符号表类 symbols 是一个生成器 (is-a), 其实例可以在文法规范的任何位置使用. 它是动态生成器的一个例子. 动态生成器的特点在于能够在运行期修改其行为. 最初, 空的 symbols 对象不会输出任何内容. 任何时候都可以添加符号, 从而动态地改变其行为.

symbols 生成器把所提供的属性用作要在内部关联容器中查找的键. 如果键存在, 生成器输出关联的值并成功 (除非底层输出流报告错误). 如果符号生成器中存储的值类型是 unused_type, 它将改为输出键. 如果键不存在, 生成器失败且不输出任何内容.

属性

symbol<Attrib, T> 的属性是 Attrib.

如果所提供的属性是 Boost.Fusion 序列, 则符号表生成器将使用该 Boost.Fusion 序列的第一个元素作为查找用的键. 该第一个元素的类型需要可转换为 Attrib. 在这种情况下, 调用从符号表中为找到的条目存储的值派生的生成器时, 会把该 Boost.Fusion 序列的第二个元素用作属性.

如果所提供的属性是容器类型 (traits::is_container 解析为 mpl::true_), 则符号表生成器将使用该容器中存储的第一个元素作为查找用的键. value_type (由 traits::container_value 返回)必须可转换为 Attrib. 在这种情况下, 调用从符号表中为找到的条目存储的值派生的生成器时, 会把该容器中存储的第二个元素用作属性.

如果所提供的属性既不是 Boost.Fusion 序列也不是容器类型, 则所提供的属性直接用作条目查找的键. 调用从符号表中为找到的条目存储的值派生的生成器时, 会把该属性用作属性.

无论如何, 由于所提供的键 (即 Boost.Fusion 序列的第一个元素, 容器的第一个元素, 或其他情况下的属性)会作为属性传递给从符号表中为找到的条目存储的值派生的生成器, 符号表可以存储生成器, 这些生成器将基于该值产生输出. 例如:

// The symbol table maps a single character key to a rule<>
// The rule<> exposes an attribute of char as well
rule<output_iterator_type, char()> r1 = char_;

symbols<char, rule<output_iterator_type, char()> > sym;
sym.add
    ('j', r1.alias())
    ('h', r1.alias())
    ('t', r1.alias())
    ('k', r1.alias())
;

// Supplying a fusion vector as the attribute will use the first element
// (the 'j') as the key to be looked up, while the second element (the 'J') 
// is passed on as the attribute to the rule<> stored in the symbol table. 
// Consequently, the example generates a single 'J'.
BOOST_ASSERT(test("J", sym, make_vector('j', 'J')));
复杂度

默认实现使用 std::map<> 或 std::set<>, 复杂度为:

O(log n)

其中 n 是存储的符号数量.
