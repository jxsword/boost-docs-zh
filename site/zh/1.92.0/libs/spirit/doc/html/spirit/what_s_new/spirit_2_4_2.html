Spirit V2.4.2

从 V2.4.1 (Boost V1.45.0) 到 V2.4.2 (Boost V1.46.0) 的变化: Spirit.Qi 和 Spirit.Karma
Qi 或 Karma 的新特性
  • 为 Spirit.Qi 和 Spirit.Karma 在文档中添加了关键词索引.
  • 引入了新的定制点 traits::assign_to_container_from_value, 每当需要把属性值添加到容器属性时都会调用它.
  • 把 proto::lit (它曾用于实现 spirit::lit) 替换为一个单独的版本, 允许区分 'lit(foo)' 与 'foo'. 这不应改变任何语义, 也不应破坏现有代码.
  • 添加了 Spirit.Qi 指令 as<T>[] (及其字符串特化 as_string[] 和 as_wstring[]), 支持把容器属性类型作为整体赋值.
  • 添加了 Spirit.Karma 指令 as<T>[] (及其字符串特化 as_string[] 和 as_wstring[]), 支持在输出生成期间把容器属性类型作为整体处理.
  • 在 Spirit.Qi 中, lit() 现在也可用于数值字面量.
  • symbols<> 解析器组件现在有一个显式名称, 用于错误处理和调试, 可以使用新的成员函数 sym.name(...) 设置. 感谢 teajay 贡献补丁.
  • symbols<Attrib, T> 生成器组件现在有一个显式名称, 用于错误处理和调试, 可以使用新的成员函数 sym.name(...) 设置.
Qi 或 Karma 中的缺陷修复
  • 修复了 Spirit.Qi 序列中处理容器属性的一个缺陷, 该缺陷导致前面元素正确解析出的属性被序列后面的元素覆盖.
  • 修复了 Spirit.Karma 生成器 string(s). 此前即使 s 只匹配其属性的前缀, 它也会成功.
从 V2.4.1 (Boost V1.45.0) 到 V2.4.2 (Boost V1.46.0) 的变化: Spirit.Lex
Lex 的新特性
  • 添加了 qi::tokenid() 基础解析器, 允许基于给定记号 id 匹配任意词法分析器记号. 与 qi::token() 的区别在于, 它把匹配记号的记号 id 作为其属性暴露 (而不是像 qi::token() 那样暴露匹配输入的 iterator_range).
  • 为默认 lexertl::token<> 定义添加了一个附加模板参数: 记号 id 的类型. 此类型默认为 std::size_t. 任何用作 id 类型的类型都必须可以 (显式) 从 std::size_t 转换而来.
  • 现在可以把词法分析器语义动作附加到基于 lex::char() 和 lex::string() 的记号定义上.
  • 现在可以指定词法分析器在匹配某些记号后应自动切换到的词法分析器状态. 为此, 记号定义语法已扩展: 
    template <typename Lexer>
struct lexer : lex::lexer<Lexer>
{
    lexer()
    {
        int_ = "[1-9][0-9]*";
        this->self("INITIAL", "TARGETSTATE") = int_;
    }
    lex::token_def<int> int_;
};
    此示例词法分析器将匹配 int_ 记号, 然后把词法分析器切换到状态 "TARGETSTATE". 如果未指定第二个参数, 词法分析器保持先前状态 (与之前一样).
  • 解析器基础组件 qi::token 和 qi::tokenid 现在可以不带任何参数使用. 在这种情况下, 它们将匹配任意记号.
  • lex::lit() 已被移除.
Lex 中的缺陷修复
  • 修复了词法分析器中把记号一次性分配给所有词法分析器状态时出问题的缺陷. 现在只需使用 "*" 作为状态名即可做到. 例如, 这将把记号 int_ 添加到所有词法分析器状态: 
    template <typename Lexer>
struct lexer : lex::lexer<Lexer>
{
    lexer()
    {
        int_ = "[1-9][0-9]*";
        this->self("*") = int_;
    }
    lex::token_def<int> int_;
};
    注意: self("*") = ... 必须在所有词法分析器状态被引入词法分析器对象之后执行.
  • 修复了词法分析器前瞻. 前瞻操作现在使用与其参数 token_def 实例关联的词法分析器状态来求值.
  • 修复了 multi_pass 迭代器中一个导致向用户返回错误记号的缺陷. 这可能在配合一个执行词法分析器状态切换并在语义动作中使用 pass_fail 使记号匹配失败的词法分析器时发生.
已知问题
  • Spirit.Qi 整数字面量 (例如 int_(10)) 在失败时会消耗输入, 这可能导致备选运算符出现问题.
