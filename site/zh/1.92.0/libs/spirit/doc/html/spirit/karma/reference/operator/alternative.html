Alternative 生成器(a | b)
说明

生成器备选用于把不同的, 更原始的生成器组合成备选项. 备选中的所有生成器从左到右依次调用, 直到其中一个成功.

头文件 
// forwards to <boost/spirit/home/karma/operator/alternative.hpp>
#include <boost/spirit/include/karma_alternative.hpp>

另请参见 包含结构.

所属模型

NaryGenerator

表达式语义

仅当表达式的语义与 NaryGenerator 不同或在其中未定义时, 才给出其语义.

表达式

语义

a | b

生成器 a 和 b 从左到右依次执行, 直到其中一个成功. 失败的生成器会迫使备选生成器尝试下一个. 只有当备选的所有元素都失败时, 备选才整体失败. 备选的每个元素都会被传入备选的整个属性.

备选会拦截并缓冲当前执行的元素的输出. 这可以避免失败元素产生部分输出, 因为缓冲的内容只会在某个元素成功后才被转发到实际输出.

属性

参见 复合属性记法.

表达式

属性

a | b (备选)

 

a: A, b: B --> (a | b): variant<A, B>
a: A, b: Unused --> (a | b): A
a: Unused, b: B --> (a | b): B
a: Unused, b: Unused --> (a | b): Unused
a: A, b: A --> (a | b): A
重要

上表仅把 variant<A, B> 用作占位符. 记法 variant<A, B> 表示类型 boost::variant<A, B>.

备选的属性处理很特殊, 因为其行为在编译期并未完全确定. 首先, 被选中的备选元素取决于提供给备选生成器的属性的实际类型 (即 variant 中存储的内容). 在运行期提供的属性类型把考虑中的备选集合缩小到属性兼容的那些. 其余备选依次尝试, 直到第一个成功. 此行为的示例见下文.

复杂度

备选生成器的总体复杂度由其元素复杂度之和决定. 备选本身的复杂度是 O(N), 其中 N 是备选中的元素数量.

注释

下面示例的测试框架在 基础示例 一节中给出.

一些包含:

#include <boost/spirit/include/karma.hpp>
#include <boost/spirit/include/support_utree.hpp>
#include <boost/phoenix/core.hpp>
#include <boost/phoenix/operator.hpp>
#include <boost/fusion/include/std_pair.hpp>
#include <boost/proto/deep_copy.hpp>
#include <iostream>
#include <string>

一些 using 声明:

using boost::spirit::karma::double_;
using boost::spirit::karma::ascii::string;

备选的基本用法. 尽管 double_ 生成器只是第二个备选, 它却被选中用于输出格式化, 因为所提供的属性类型与 string 备选的属性类型不兼容 (即不可转换).

boost::variant<std::string, double> v1(1.0);
test_generator_attr("1.0", string | double_, v1);
test_generator_attr("2.0", string | double_, 2.0);

同样的格式化规则可用于输出字符串. 这次我们提供字符串 "example", 结果是第一个备选被选中用于生成输出.

boost::variant<std::string, double> v2("example");
test_generator_attr("example", string | double_, v2);
test_generator_attr("example", string | double_, "example");
