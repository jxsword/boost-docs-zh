判断组件是否处理容器属性(Qi 与 Karma)

handles_container

模板 handles_container 是用作属性定制点的模板元函数. Qi 的 Sequence (>>) 运算符和 Karma 的 Sequence(<<) 运算符会调用它, 以确定序列元素(组件)是否直接处理容器属性. 仅对容器属性调用此定制点, 且仅在序列与所提供的容器属性兼容时调用.

如果作为序列一部分的组件能够直接处理容器属性, 序列会将属性直接传递给该组件, 无需任何额外操作. 在 Spirit.Qi 中, 组件使用该属性直接存储所有匹配到的属性. 在 Spirit.Karma 中, 生成器组件直接从该属性提取生成输出所需的属性.

如果作为序列一部分的组件不能处理容器属性, 在 Spirit.Qi 中, 序列会向解析器组件传递容器属性的 value_type 的新实例, 并代表解析器组件把结果插入属性. 在 Spirit.Karma 中, 序列会代表生成器组件提取下一个容器元素, 并把提取到的值传递给它.

头文件 
#include <boost/spirit/home/support/handles_container.hpp>

另请参见 包含结构.

注释

用户程序不需要直接包含此头文件, 因为它通常由依赖其内容的其它 Spirit 头文件包含.

命名空间

名称

boost::spirit::traits

概要 
template <
    typename Component, typename Attribute, typename Context,
    typename Iterator, typename Enable>
struct handles_container
{
    <unspecified>;
};

表达式语义

表达式

语义

handles_container<Component, Attribute>::type

元函数的结果: 求值为 mpl::true_ (当给定组件类型 Component 直接处理容器属性时), 否则为 mpl::false_. 通常, handles_container 的任何实现都需要表现得如同一个 MPL Boolean Constant.
预定义特化

Spirit 为若干类型预定义了此定制点的特化. 下表列出了这些类型, 以及相应特化求值为 mpl::true_ 的条件(参见 MPL Boolean Constant):

模板参数

语义

Component, Attribute

总是返回 mpl::false_ (默认).

rule<Iterator, T1, T2, T3, T4>, Attribute

返回 is_container<A>, 其中 A 是 rule 暴露的属性(Spirit.Qi 和 Spirit.Karma).

grammar<Iterator, T1, T2, T3, T4>, Attribute

返回 is_container<A>, 其中 A 是 grammar 暴露的属性(Spirit.Qi 和 Spirit.Karma).
何时实现

每当某个类型直接处理容器属性时, 就需要为该类型实现定制点 handles_container. 它适用于解析器(Spirit.Qi)和生成器(Spirit.Karma). 仅在少数情况下才需要实现它.
