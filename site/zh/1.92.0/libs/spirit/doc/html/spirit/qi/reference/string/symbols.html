符号解析器 (symbols)
说明

类 symbols 实现了一个符号表: 键为字符串的键值对关联容器 (或映射). symbols 类可以高效处理 8、16、32 甚至 64 位字符.

传统上, 符号表管理是在文法之外通过语义动作单独维护的. 与标准做法相反, Spirit 的符号表类 symbols 是一个解析器 (is-a parser), 其实例可以在文法规范的任何地方使用. 它是动态解析器的一个例子. 动态解析器的特点在于能够在运行期修改自身行为. 最初, 空的 symbols 对象不匹配任何内容. 任何时候都可以添加符号, 从而动态改变其行为.

表达式语义

仅当表达式的语义与 PrimitiveParser 不同或在其中未定义时, 才给出其语义.

表达式

语义

Sym()

构造一个空的符号表, 名称为 "symbols".

Sym(name)

构造一个名为 name 的空符号表.

Sym(sym2)

从 sym2 (另一个 symbols 对象)复制构造一个 symbols.

Sym(sseq)

从 sseq (一个 STL 字符串容器) 构造符号表, 名称为 "symbols".

Sym(sseq, name)

从 sseq (一个 STL 字符串容器) 构造符号表, 名称为 name.

Sym(sseq, dseq)

从 sseq 和 dseq (一个 STL 字符串容器和一个 STL 数据容器 (带 value_type T)) 构造符号表, 名称为 "symbols".

Sym(sseq, dseq, name)

从 sseq 和 dseq (一个 STL 字符串容器和一个 STL 数据容器 (带 value_type T)) 构造符号表, 名称为 name.

sym = sym2

把 sym2 赋给 sym.

sym = s1, s2, ..., sN

把一个或多个符号 (s1...sN) 赋给 sym.

sym += s1, s2, ..., sN

添加一个或多个符号 (s1...sN) 到 sym.

sym.add(s1)(s2)...(sN)

添加一个或多个符号 (s1...sN) 到 sym.

sym.add(s1, d1)(s2, d2)...(sN, dN)

添加一个或多个符号 (s1...sN) 及关联数据 (d1...dN) 到 sym.

sym -= s1, s2, ..., sN

移除一个或多个符号 (s1...sN), 自 sym.

sym.remove(s1)(s2)...(sN)

移除一个或多个符号 (s1...sN), 自 sym.

sym.clear()

擦除 sym 中的所有符号.

sym.at(s)

返回与符号 s 关联的对象的引用. 如果 sym 尚未包含这样的对象, at 会插入默认对象 T().

sym.find(s)

返回与符号 s 关联的对象的指针. 如果 sym 尚未包含这样的对象, find 返回空指针.

sym.prefix_find(f, l)

返回指向与范围 [f, l) 开头匹配的最长符号所关联对象的指针, 并更新 f 使其指向该匹配末尾之后. 如果没有符号匹配, 则返回空指针, 且 f 保持不变.

sym.for_each(f)

对于 sym 中的每个符号 s, 即一个 std::basic_string<Char>, 其关联数据为 d (类型为 T 的对象), 调用 f(s, d)

sym.name()

获取 symbols 对象的当前名称.

sym.name(name)

把 symbols 对象的当前名称设置为 name.
属性

symbol<Char, T> 的属性是 T.

复杂度

默认实现使用三向搜索树 (TST), 复杂度为:

O(log n+k)

其中 k 是在含 n 个字符串的 TST 中要搜索的字符串长度.

对于许多典型的搜索问题, TST 比散列更快, 尤其当搜索接口基于迭代器时. 对于不成功的搜索, TST 比散列表快许多倍, 因为不匹配只需检查少量字符就能更早发现. 散列表在搜索时总是要检查整个键.

另一种实现使用混合散列表前端 (针对第一个字符) 加 TST: tst_map. 这带来的复杂度为

O(1 + log n+k-1)

这被发现显著快于普通 TST, 尽管内存使用要求略高 (散列表中的每个槽位是一个 TST 节点). 如果你需要搜索大量符号, 请使用 tst_map 实现. 这可以通过把 tst_map 用作 symbols 类的第三个模板参数来完成:

symbols<Char, T, tst_map<Char, T> > sym;
示例
注释

下面示例的测试框架在 基础示例 一节中给出.

一些 using 声明:

using boost::spirit::qi::symbols;

带数据的符号表:

symbols<char, int> sym;

sym.add
    ("Apple", 1)
    ("Banana", 2)
    ("Orange", 3)
;

int i;
test_parser_attr("Banana", sym, i);
std::cout << i << std::endl;

当 symbols 用于不区分大小写的解析时 (在 no_case 指令中), 添加的符号字符串应为小写. 当 symbols 用于 no_case 指令中时, 含有一个或多个大写字符的符号字符串将不匹配任何输入.

symbols<char, int> sym;

sym.add
    ("apple", 1)    // symbol strings are added in lowercase...
    ("banana", 2)
    ("orange", 3)
;

int i;
// ...because sym is used for case-insensitive parsing
test_parser_attr("Apple", no_case[ sym ], i);
std::cout << i << std::endl;
test_parser_attr("ORANGE", no_case[ sym ], i);
std::cout << i << std::endl;
