风格指南

到了某个阶段, 特别是当大量语义动作附加到各个位置时, 文法往往会变得相当难以理解. 为了保持 Spirit 代码易读、一致且美观的外观, 建议遵循以下编码风格指南.

这种编码风格改编并扩展自 ANTLR/PCCTS 风格和 Boost Library Requirements and Guidelines, 是 Joel de Guzman、Chris Uzdavinis 和 Hartmut Kaiser 的共同成果.

  • rule 名称使用标准 C++ (Boost) 约定. rule 名称可以很长.
  • '=' 整齐地缩进到下面 4 个空格处. 与 Boost 中一样, 使用空格而不是制表符.
  • 把操作数拆分到单独的行, 可以让语义动作整齐地靠右放置.
  • 最后一行的分号终止该 rule.
  • 序列的相邻部分应相应缩进, 使属于同一层级的所有内容都处在同一缩进层级.
program
    =   program_heading [heading_action]
        >> block [block_action]
        >> '.'
    |   another_sequence
        >> etc
    ;
  • 在文法中优先使用字面量而不是标识符. 例如用 "program" 而不是 PROGRAM, 用 '>=' 而不是 GTE, 用 '.' 而不是 DOT. 这会使代码更易读. 如果做不到 (例如所用记号必须通过整数标识), 则应改用大写标识符.
  • 对于短表达式, 可能无需拆分操作数. 例如 *(',' >> file_identifier), 只要该行不超过 80 个字符.
  • 如果序列能放在一行内, 则在括号内放入空格, 以便与 rule 清晰区分.
program_heading
    =   no_case["program"]
        >> identifier
        >> '('
        >> file_identifier
        >> *( ',' >> file_identifier )
        >> ')'
        >> ';'
    ;
  • 嵌套指令: 如果某个 rule 一行放不下 (80 个字符), 应在下一行缩进一级继续. 指令、语义表达式 (使用 Phoenix 或 LL lambda 表达式) 或解析器的括号应按如下方式放置.
identifier
    =   no_case
        [
            lexeme
            [
                alpha >> *(alnum | '_') [id_action]
            ]
        ]
   ;
  • 嵌套一元运算符 (例如 Kleene 星号): 如果某个 rule 带有主体或其后跟有放不下一行的序列, 一元 rule 运算符 (Kleene 星号、'!'、'+' 等) 应比相应缩进层级向外移出一个空格. 这使格式更一致, 并把 rule 的 '主体' 放在与 rule 本身相同的缩进层级, 突出显示一元运算符.
block
   =  *(   label_declaration_part
       |   constant_definition_part
       |   type_definition_part
       |   variable_declaration_part
       |   procedure_and_function_declaration_part
       )
       >> statement_part
   ;
