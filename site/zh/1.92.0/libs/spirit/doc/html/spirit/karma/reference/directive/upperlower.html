控制大小写敏感的生成器指令(upper[], lower[])
说明

生成器指令 ns::lower[] 和 ns::upper[] 强制其内嵌生成器只输出小写或大写字符, 其依据是在由 ns 定义的字符集中对生成字符的解释 (参见 字符编码命名空间).

头文件 
// forwards to <boost/spirit/home/karma/directive/upper_lower_case.hpp>
#include <boost/spirit/include/karma_upper_lower_case.hpp>

另请参见 包含结构.

命名空间

名称

ns::lower

ns::upper

在上表中, ns 表示一个 字符编码命名空间.

所属模型

lower[] 和 upper[] 的模型是其主体生成器的模型.

记法约定

a

一个生成器对象

A

生成器 a 的属性类型

ns

一个 字符编码命名空间.

表达式语义

lower[] 和 upper[] 指令没有特殊的生成器语义. 它们是纯粹的修饰指令. 它们间接影响所有主体生成器的工作方式. 它们添加信息 (tag::upper 或 tag::lower) 到 Modifier 模板参数, 该参数在把 proto::expr 变换为相应生成器表达式时使用. 这通过以下特化实现:

namespace boost { namespace spirit
{
    template <typename CharEncoding>
    struct is_modifier_directive<
            karma::domain
          , tag::char_code<tag::lower, CharEncoding> >
      : mpl::true_
    {};

    template <typename CharEncoding>
    struct is_modifier_directive<
            karma::domain
          , tag::char_code<tag::upper, CharEncoding> >
      : mpl::true_
}}

(更多细节参见描述把 Boost.Proto 表达式编译为相应生成器表达式过程的章节).

表达式

语义

ns::lower[a]

以小写形式生成 a, 按由 ns 定义的字符集解释. 只要内嵌生成器成功, 该指令就成功 (除非底层输出流报告错误).

ns::upper[a]

以大写形式生成 a, 按由 ns 定义的字符集解释. 只要内嵌生成器成功, 该指令就成功 (除非底层输出流报告错误).
注释

如果两个指令对于某个生成器都是"激活"的, 则最内层的指令优先. 例如:

generate(sink, ascii::lower['A' << ascii::upper['b']])

将生成 "aB" (不含引号).

此外, 这些指令对输出在由 ns 定义的字符集中没有大写或小写对应形式的字符的生成器没有影响.

属性

参见 复合属性记法.

表达式

属性

ns:lower[a] 

a: A --> ns:lower[a]: A
a: Unused --> ns:lower[a]: Unused

ns:upper[a] 

a: A --> ns:upper[a]: A
a: Unused --> ns:upper[a]: Unused
复杂度

生成器指令 ns::lower[] 和 ns::upper[] 的总体复杂度由其内嵌生成器的复杂度决定. 这些指令本身是仅编译期指令, 对运行期性能没有影响.

示例
注释

下面示例的测试框架在 基础示例 一节中给出.

一些包含:

#include <boost/spirit/include/karma.hpp>
#include <iostream>
#include <string>

一些 using 声明:

using boost::spirit::karma::double_;
using boost::spirit::ascii::upper;
using boost::spirit::ascii::lower;

upper 和 lower 生成器指令的基本用法:

test_generator_attr("abc:2.0e-06", lower["ABC:" << double_], 2e-6);
test_generator_attr("ABC:2.0E-06", upper["abc:" << double_], 2e-6);
