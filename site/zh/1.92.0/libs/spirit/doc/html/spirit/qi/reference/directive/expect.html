期望指令 (expect[])
说明

有些场合要求输入必须匹配某个特定解析器, 否则输入无效. 这种情况通常出现在匹配了文法的一部分之后, 此时上下文已完全明确. 在这种情况下, 匹配失败应当导致异常. 例如, 在解析电子邮件地址时, 必须匹配一个名称、一个 "@" 和一个域名, 否则该地址无效.

expect 指令要求参数解析器匹配输入, 否则发出异常. 使用 on_error(), 可以通过调用处理器来处理该异常, 并可报告解析失败所处的上下文.

expect 指令解析一个操作数解析器表达式, 它可以是单个解析器, 也可以是像序列这样的复杂解析器表达式.

单个解析器:

expect[a]

解析器表达式:

expect[a >> b >> ...]

在后一种情况下, 普通 序列 在某个元素失败时只是返回不匹配 (返回 false), 而 expect 指令会在任何解析器 (甚至是序列的第一个解析器) 匹配失败时抛出 expectation_failure<Iter>.

注释

Spirit 提供了两种通过抛出期望异常来处理期望失败的方式. 如果你不需要在序列的第一个解析器失败时抛出异常, 请使用 期望运算符.

头文件 
// forwards to <boost/spirit/home/qi/directive/expect.hpp>
#include <boost/spirit/include/qi_expect.hpp>

另请参见 包含结构.

所属模型

UnaryParser

记法约定

a

一个 Parser

Iter

一个 ForwardIterator 类型

期望失败

当操作数解析器匹配失败时, 会抛出一个 expectation_failure<Iter>:

template <typename Iter>
struct expectation_failure : std::runtime_error
{
    Iter first;           // [first, last) iterator pointing
    Iter last;            // to the error position in the input.
    info what_;       // Information about the nature of the error.
};
表达式语义

仅当表达式的语义与 UnaryParser 不同或在其中未定义时, 才给出其语义.

表达式

语义

expect[a]

匹配 a. 如果 a 失败, 则抛出 expectation_failure<Iter>

属性

参见 复合属性记法.

表达式

属性

expect[a] 

a: A --> expect[a]: A
a: Unused --> expect[a] : Unused
复杂度

期望解析器的总体复杂度由其参数解析器的复杂度决定. expect 指令本身的复杂度为 O(1).

示例
注释

下面示例的测试框架在 基础示例 一节中给出.

一些 using 声明:

using boost::spirit::ascii::char_;
using boost::spirit::qi::expect;
using boost::spirit::qi::expectation_failure;

下面的代码使用期望运算符抛出一个 expectation_failure: 当期望 "o" 而输入中发现的是 "x" 时, 发生刻意的解析错误. catch 块打印与错误相关的信息. 注意: 这是演示 bare-metal (裸机层面) 的底层代码. 通常, 你会使用错误处理器来处理错误.

try
{
    test_parser("xi", expect[char_('o')]); // should throw an exception
}
catch (expectation_failure<char const*> const& x)
{
    std::cout << "expected: "; print_info(x.what_);
    std::cout << "got: \"" << std::string(x.first, x.last) << '"' << std::endl;
}

上面的代码将打印:

expected: tag: literal-char, value: o
got: "x"
