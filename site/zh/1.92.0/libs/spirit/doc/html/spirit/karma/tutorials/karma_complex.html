Complex - 第一个更复杂的生成器

在本节中, 我们将开发一个复数生成器, 允许把 std::complex 表示为 (real, imag) (其中 real 和 imag 是复数的实部和虚部), 或者当虚部恰好为零时表示为简单的 real. 本示例将展示 Spirit.Karma 的强大之处: 把格式化规则的编译期定义与运行期基于规则应用的决策结合起来. 同样, 这次我们使用 Boost.Phoenix 来执行语义动作.

我们的目标是允许根据复数的虚部是否为零应用两种不同的输出格式. 让我们把两者写成一组备选:

    '(' << double_ << ", " << double_ << ')'
|   double_

其中第一个备选应用于虚部非零的数, 而第二个用于实数. 一般来说, 备选按其定义的顺序依次尝试, 直到其中一个表达式 (以 '|' 界定)成功. 如果没有生成器表达式成功, 整个备选就失败.

如果我们保持这个格式化文法不变, 我们的生成器将总是选择第一个备选. 我们需要添加一些附加规则, 使第一个备选能够失败. 这样, 如果第一个备选失败, 将改为选择第二个备选. 关于是否选择第一个备选的决策必须在运行期做出, 因为只有那时我们才真正知道复数虚部的值. Spirit.Karma 为我们提供了一个原语生成器 eps(), 它可用作语义谓词. 它的特性是仅当其实参为 true 时才"成功"生成 (而它自己从不生成任何输出).

double imag = ...;     // imaginary part

    eps(imag != 0) << '(' << double_ << ", " << double_ << ')'
|   double_

如果序列的一个生成器元素失败, 整个序列就会失败. 这正是我们需要的, 它迫使对虚部为零的复数选择第二个备选.

现在来看完整的示例, 这次带有正确的语义动作 (本示例的完整 cpp 文件可在此处找到: complex_number.cpp).

在本示例及后续所有相关示例中, 我们将使用 std::complex 类型. 在这里你可以看到生成器的完整代码, 它允许把复数输出为一对数 (如果虚部非零)或单个数 (如果该复数是实数):

template <typename OutputIterator>
bool generate_complex(OutputIterator sink, std::complex<double> const& c)
{
    using boost::spirit::karma::eps;
    using boost::spirit::karma::double_;
    using boost::spirit::karma::_1;
    using boost::spirit::karma::generate;

    return generate(sink,
        //  Begin grammar
        (
            eps(c.imag() != 0) <<
            '(' << double_[_1 = c.real()] << ", " << double_[_1 = c.imag()] << ')'
        |   double_[_1 = c.real()]
        )
        //  End grammar
    );
}

double_ 生成器附加了这个语义动作:

_1 = n

它把 n 传递给生成器所附加语义动作的第一个元素. 记住, Spirit.Karma 中的语义动作在相应生成器被调用之前调用, 并且预期它们为生成器提供要使用的数据. 上面的语义动作把要生成的值 (n)赋给生成器 (实际上是 double_ 的属性). _1 是一个 Phoenix 占位符, 引用语义动作所附加生成器的属性. 如果你需要关于语义动作的更多信息, 可以在本节阅读: 语义动作.

这些语义动作易于理解, 但有一个意想不到的副作用: 效率略低于可能达到的水平. 此外, 它们往往使格式化文法的可读性下降. 我们将在后面某一节看到如何使用 Spirit.Karma 的其他内置特性来完全摆脱语义动作. 在 Spirit 中编写文法时, 应始终尽量避免语义动作, 这通常是可行的. 语义动作确实是非常强大的工具, 但没有它们, 文法往往更高效, 也更易读.
