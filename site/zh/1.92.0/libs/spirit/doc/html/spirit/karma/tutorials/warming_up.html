热身

学习如何使用 Spirit.Karma 非常简单. 我们将从简单的例子开始, 逐步深入.

简单示例 #1 生成一个数字

让我们创建一个将输出浮点数的生成器:

double_

很简单吧? 上面的代码实际上实例化了一个 Spirit 浮点数生成器 (内置生成器). Spirit 有许多预定义的生成器, 一致的命名约定会帮助你在迷宫中找到方向. 特别需要注意的是, 与相同实体相关的事物 (如此例中的浮点数) 在 Spirit.Karma 和 Spirit.Qi 中的命名是相同的. 事实上, 两个库都在使用完全相同的变量实例来指代浮点数生成器或解析器: double_.

简单示例 #2 生成两个数字

现在, 让我们创建一个生成器, 它将输出由两个浮点数组成的一行.

double_ << double_

这里你看到了熟悉的浮点数生成器 double_, 它被使用了两次, 每个数字一次. 如果你习惯于看到 '>>' 运算符在 Spirit.Qi 中被用于连接两个解析器, 你可能会好奇, 那个 '<<' 运算符在这里是做什么的? 我们决定像 std::stream 库那样区分序列的生成与解析: 我们使用运算符 '>>' 表示输入 (解析), 用运算符 '<<' 表示输出 (生成). 除此之外没有显著差别. 上面的程序用两个更简单的生成器创建出一个生成器, 用序列运算符把它们粘合在一起. 结果就是一个由更小的生成器组合而成的生成器. 数字之间的空白可以根据生成器的调用方式隐式插入 (见下文).

注释

当我们组合生成器时, 最终得到的是一个“更大”的生成器, 但它仍然是一个生成器. 生成器可以变得越来越大, 嵌套得越来越多, 但每当你把两个生成器粘合在一起时, 最终得到的都是一个更大一些的生成器. 这是一个重要的概念.

简单示例 #3 生成一个或多个数字

现在, 为两个数字生成输出已经不太有趣了. 让我们创建一个生成器, 它将连续输出零个或多个浮点数.

*double_

这就像正则表达式的 Kleene 星号. 我们把 * 移到前面, 原因与我们在 Spirit.Qi 中所做的相同: 我们必须遵守 C++ 的语法规则. 但如果你熟悉正则表达式 (而且你肯定记得那些 C++ 语法规则), 用不了多久它看起来就会非常眼熟了.

任何求值结果为生成器的表达式都可以与 Kleene 星号一起使用. 但请记住, 由于 C++ 运算符优先级规则, 对于复杂的表达式, 你可能需要将其放入括号中. 与上面一样, 如果需要, 可以在生成的数字之间隐式插入空白.

简单示例 #4 生成逗号分隔的数字列表

我们沿用 Spirit.Qi“热身”一节的做法, 将创建一个生成逗号分隔数字列表的生成器.

double_ << *(lit(',') << double_)

注意 lit(','). 它是一个字面字符生成器, 只是简单地生成逗号 ','. 在这里, Kleene 星号修饰的是一个更复杂的生成器, 即由以下表达式生成的那个生成器:

(lit(',') << double_)

注意, 这是括号必不可少的情况之一. Kleene 星号括住了上面完整的表达式, 在生成的输出中将整个模式重复零次或多次.

让我们开始生成!

生成器的定义已经完成. 剩下的就是调用生成器来完成它的工作. 目前, 我们将使用 generate_delimited 函数. 该函数的一个重载接受四个参数:

  1. 接受生成字符的输出迭代器
  2. 生成器表达式
  3. 另一个生成器, 称为定界生成器
  4. 要格式化并输出的数据

将这个最小示例与等价的解析器示例比较时, 我们注意到一个显著的区别. 解析器可以 (而且实际上也很有意义) 在不为已解析输入创建任何内部表示的情况下使用 (即不从已解析输入“生成”任何数据). 以这种方式使用解析器, 会将提供的输入与给定的解析器表达式进行核对, 从而可以验证输入是否可解析. 对于生成器而言, 这种模式没有任何意义. 不生成任何输出的输出生成是什么? 因此我们总是必须提供要从中生成输出的数据. 在我们的示例中, 我们提供一个 double 数字列表, 作为函数 generate_delimited 的最后一个参数 (见下面的代码).

在这个例子中, 我们希望用空格来分隔生成的数字. Spirit 的预定义生成器库中还包括另一个名为 space 的生成器. 它是一个非常简单的生成器, 只是产生空格. 它等价于写 lit(' '), 或简单地写 ' '. 之所以实现它, 是为了与对应的预定义 space 解析器保持相似性. 我们将使用 space 作为定界符. 定界符负责在生成器元素之间插入字符, 例如在 double_ 和 lit 之间.

好, 现在让我们开始生成 (本示例的完整源代码请参见 num_list1.cpp).

template <typename OutputIterator>
bool generate_numbers(OutputIterator& sink, std::list<double> const& v)
{
    using karma::double_;
    using karma::generate_delimited;
    using ascii::space;

    bool r = generate_delimited(
        sink,                           // destination: output iterator
        double_ << *(',' << double_),   // the generator
        space,                          // the delimiter-generator
        v                               // the data to output 
    );
    return r;
}

注释

你可能想知道, 一个实际上只是单一数据结构的 vector<double> 如何能用作一串生成器的参数 (我们称之为属性). 这看起来违反直觉, 也与你使用 printf 的经验不符, 在那里每个格式化占位符都必须与一个对应的参数相匹配. 我们将在本教程后面更详细地解释这一行为. 现在只需把它当作一个特例, 它是为允许对 STL 容器进行更灵活的输出格式化而特意实现的: 如果序列中的所有元素都接受与此容器所存元素兼容的属性, 那么该序列就接受单一的容器属性.

generate 函数根据输出生成的结果返回 true 或 false. 正如本文档多处概述的那样, 生成器可能因不同原因而失败. 可能的原因之一是底层输出迭代器出错 (内存耗尽或磁盘满等). 另一个原因可能是数据不满足某个特定生成器的要求.

注释

char 和 wchar_t 操作数

细心的读者可能会注意到, 生成器表达式使用的是 ',', 而不像前面的例子那样使用 lit(','). 根据 C++ 的转换语法规则, 这样做是没有问题的. Spirit 提供的 << 运算符被重载为可在其左侧或右侧接受 char 或 wchar_t 参数 (但不能两者同时). 只要运算符的参数中至少有一个是用户定义类型, 该运算符就可以被重载. 在这里, double_ 是 operator<< 的第 2 个参数, 因此使用了 << 的相应重载, 把 ',' 转换为一个字符字面量生成器.

省略 lit 的问题应当是显而易见的: 'a' << 'b' 不是 spirit 生成器, 它是一个数值表达式, 把 'a' 的 ASCII (或其他编码) 值左移 'b' 的 ASCII 值位. 然而, lit('a') << 'b' 和 'a' << lit('b') 都是用于字母 'a' 后跟 'b' 的 Spirit 序列生成器. 迟早你会习惯的.

注意, 我们把生成器直接内联在了对 generate_delimited 的调用中. 调用该函数时, 表达式求值为一个临时的、未命名的生成器, 它被传入 generate_delimited 函数, 被使用, 然后被销毁.

这里, 我们选择通过把 generate 函数做成模板来使其通用, 以输出迭代器类型为模板参数. 这样, 它就可以把生成的数据放入任何符合 STL 规范的输出迭代器中.
