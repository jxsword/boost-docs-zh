迷你 XML - AST!

停下来想一想... 在上一个示例中, 我们已经非常接近生成 AST (抽象语法树) 了. 我们解析了一个结构体, 并以 struct 的形式生成了它的内存表示: struct employee. 如果我们把实现改为解析一个或多个 employee, 结果将是一个 std::vector<employee>. 我们可以继续增加更多层次: 团队、部门、公司. 那时我们就有了这一切的 AST 表示.

在本示例 (实际上是两个示例) 中, 我们将探索如何创建 AST. 我们将解析一个极简的类 XML 语言, 并把结果编译成树形的数据结构.

在此过程中, 我们将看到新特性:

  • 继承属性
  • Variant 属性
  • 局部变量
  • 非谓词
  • 惰性 lit

这些示例的完整 cpp 文件可在此处找到: ../../example/qi/mini_xml1.cpp 以及此处: ../../example/qi/mini_xml2.cpp

mini_xml_samples 子目录中有几个示例 toy-xml 文件: ../../example/qi/mini_xml_samples/1.toyxml、../../example/qi/mini_xml_samples/2.toyxml 和 ../../example/qi/mini_xml_samples/3.toyxml, 供测试之用. 示例 ../../example/qi/mini_xml_samples/4.toyxml 中有一个错误.

初试

闲话少说, 下面是 XML 文法的第一个版本:

template <typename Iterator>
struct mini_xml_grammar : qi::grammar<Iterator, mini_xml(), ascii::space_type>
{
    mini_xml_grammar() : mini_xml_grammar::base_type(xml)
    {
        using qi::lit;
        using qi::lexeme;
        using ascii::char_;
        using ascii::string;
        using namespace qi::labels;

        using phoenix::at_c;
        using phoenix::push_back;

        text = lexeme[+(char_ - '<')        [_val += _1]];
        node = (xml | text)                 [_val = _1];

        start_tag =
                '<'
            >>  !lit('/')
            >>  lexeme[+(char_ - '>')       [_val += _1]]
            >>  '>'
        ;

        end_tag =
                "</"
            >>  lit(_r1)
            >>  '>'
        ;

        xml =
                start_tag                   [at_c<0>(_val) = _1]
            >>  *node                       [push_back(at_c<1>(_val), _1)]
            >>  end_tag(at_c<0>(_val))
        ;
    }

    qi::rule<Iterator, mini_xml(), ascii::space_type> xml;
    qi::rule<Iterator, mini_xml_node(), ascii::space_type> node;
    qi::rule<Iterator, std::string(), ascii::space_type> text;
    qi::rule<Iterator, std::string(), ascii::space_type> start_tag;
    qi::rule<Iterator, void(std::string), ascii::space_type> end_tag;
};

自底向上, 让我们考察 text rule:

rule<Iterator, std::string(), space_type> text;

及其定义:

text = lexeme[+(char_ - '<')        [_val += _1]];

语义动作收集字符, 并通过 += 把它们追加到 rule 的 std::string 属性 (由占位符 _val 表示).

备选 
rule<Iterator, mini_xml_node(), space_type> node;

及其定义:

node = (xml | text)                 [_val = _1];

稍后我们会看到一个 mini_xml_node 结构. 观察该 rule 定义, 可以看到这里有一些备选. 一个 xml node 要么是 xml, 要么是 text. 嗯... 先记住这个想法...

rule<Iterator, std::string(), space_type> start_tag;

同样, 它有一个 std::string 属性. 然后是它的定义:

start_tag =
        '<'
    >>  !char_('/')
    >>  lexeme[+(char_ - '>')       [_val += _1]]
    >>  '>'
;
非谓词

start_tag 与 text rule 相似, 只是增加了 '<' 和 '>'. 但等等, 为了确保 start_tag 也不会解析 end_tag, 我们加上: !char_('/'). 这是一个 "非谓词":

!p

它会尝试解析器 p. 如果成功, 则失败; 否则通过. 换句话说, 它对 p 的结果取反. 不过与 eps 一样, 它不消耗任何输入. 它总是会把迭代器位置回退到进入时的位置. 因此, 表达式:

!char_('/')

基本上是说: 此时不应当出现 '/'.

继承属性

end_tag:

rule<Iterator, void(std::string), space_type> end_tag;

哦! 现在我们看到了一个继承属性: std::string. end_tag 没有合成属性. 让我们看看它的定义:

end_tag =
        "</"
    >>  lit(_r1)
    >>  '>'
;

_r1 是另一个表示第一个继承属性的 Boost.Phoenix 占位符 (我们只有一个; 如果有更多, 使用 _r2、_r3 等).

惰性 lit

看看我们这里如何使用 lit: 这次不是用字面量字符串, 而是用第一个继承属性的值, 它在我们的 rule 声明中被指定为 std::string.

最后是我们的 xml rule:

rule<Iterator, mini_xml(), space_type> xml;

mini_xml 是我们这里的属性. 稍后我们会看到它是什么. 让我们看看它的定义:

xml =
        start_tag                   [at_c<0>(_val) = _1]
    >>  *node                       [push_back(at_c<1>(_val), _1)]
    >>  end_tag(at_c<0>(_val))
;

了解 Boost.Fusion 的人现在会注意到 at_c<0> 和 at_c<1>. 这提示我们 mini_xml 是一种 tuple -- 一个 fusion 序列. 这里的 at_c<N> 是 Boost.Phoenix 提供的 tuple 访问器的惰性版本.

这一切如何工作

那么, 发生了什么?

  1. 解析 start_tag 时, 解析出的开始标签字符串被放入 at_c<0>(_val).
  2. 然后我们解析零个或多个 node. 在每一步, 我们把结果 push_back 到 at_c<1>(_val) 中.
  3. 最后, 我们解析 end_tag, 并给它传入一个继承属性: at_c<0>(_val). 这是我们从 start_tag 获得的字符串. 考察上面的 end_tag. 如果它得到的内容与从 start_tag 得到的不同, 解析就会失败. 这确保我们的标签是配对的.

为了进一步说明最后一项, 发生的事情是这样的:

end_tag(at_c<0>(_val))

调用:

end_tag =
        "</"
    >>  lit(_r1)
    >>  '>'
;

传入 at_c<0>(_val), 即来自开始标签的字符串. 它在 end_tag 主体中被称为 _r1.

结构体

让我们看看我们的结构体. 它必定是层次化的: xml 是层次化的. 它也是递归的: xml 是递归的.

struct mini_xml;

typedef
    boost::variant<
        boost::recursive_wrapper<mini_xml>
      , std::string
    >
mini_xml_node;

struct mini_xml
{
    std::string name;                           // tag name
    std::vector<mini_xml_node> children;        // children
};

关于备选与 Variant

这就是 mini_xml_node 的样子. 我们已有提示: 它要么是 string, 要么是 mini_xml. 为此我们使用 Boost.Variant. boost::recursive_wrapper 包装了 mini_xml, 使其成为递归数据结构.

没错, 你猜对了: 备选的属性:

a | b

是一个

boost::variant<A, B>

其中 A 是 a 的属性, B 是 b 的属性.

再次适配 struct

mini_xml 无需多想. 它就是一个普通的 struct. 但正如我们在 employee 示例中看到的, 我们可以把它适配为 Boost.Fusion 序列:

BOOST_FUSION_ADAPT_STRUCT(
    client::mini_xml,
    (std::string, name)
    (std::vector<client::mini_xml_node>, children)
)

再来一次

下面是另一个版本. AST 结构保持不变, 但这次你会看到我们使用自动 rule, 使文法完全不用语义动作. 如下:

template <typename Iterator>
struct mini_xml_grammar
  : qi::grammar<Iterator, mini_xml(), qi::locals<std::string>, ascii::space_type>
{
    mini_xml_grammar()
      : mini_xml_grammar::base_type(xml)
    {
        using qi::lit;
        using qi::lexeme;
        using ascii::char_;
        using ascii::string;
        using namespace qi::labels;

        text %= lexeme[+(char_ - '<')];
        node %= xml | text;

        start_tag %=
                '<'
            >>  !lit('/')
            >>  lexeme[+(char_ - '>')]
            >>  '>'
        ;

        end_tag =
                "</"
            >>  lit(_r1)
            >>  '>'
        ;

        xml %=
                start_tag[_a = _1]
            >>  *node
            >>  end_tag(_a)
        ;
    }

    qi::rule<Iterator, mini_xml(), qi::locals<std::string>, ascii::space_type> xml;
    qi::rule<Iterator, mini_xml_node(), ascii::space_type> node;
    qi::rule<Iterator, std::string(), ascii::space_type> text;
    qi::rule<Iterator, std::string(), ascii::space_type> start_tag;
    qi::rule<Iterator, void(std::string), ascii::space_type> end_tag;
};

在看过第一个 xml 解析器示例之后, 这个版本理解起来不应当更难. rule 几乎相同, 只是我们去掉了语义动作, 改用自动 rule (如果你错过了, 请参见 employee 示例). 不过有一些新东西. 全在 xml rule 里:

局部变量 
rule<Iterator, mini_xml(), locals<std::string>, space_type> xml;

哇, 现在我们有四个模板参数了. 那个 locals 家伙在那里干什么? 嗯, 它声明 rule xml 将拥有一个局部变量: 一个 string. 让我们看看它在实践中如何使用:

xml %=
        start_tag[_a = _1]
    >>  *node
    >>  end_tag(_a)
;
  1. 解析 start_tag 时, 解析出的开始标签字符串被放入由 (又一个) Boost.Phoenix 占位符指定的局部变量: _a. 我们只有一个局部变量. 如果更多, 则由 _b.._z 指定.
  2. 然后我们解析零个或多个 node.
  3. 最后, 我们解析 end_tag, 并给它传入一个继承属性: _a, 即我们的局部变量.

把数据填充到 xml 属性的过程中没有涉及任何动作. 多亏了自动 rule, 这一切都自动搞定了.
