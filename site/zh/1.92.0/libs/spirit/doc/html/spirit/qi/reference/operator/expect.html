期望运算符 (a > b)
说明

有些场合要求输入必须匹配某个特定解析器, 否则输入无效. 这种情况通常出现在匹配了文法的一部分之后, 此时上下文已完全明确. 在这种情况下, 匹配失败应当导致异常. 例如, 在解析电子邮件地址时, 匹配完名称和 "@" 之后必须有域名, 否则该地址无效.

期望运算符 (>) 要求其后的解析器匹配输入, 否则发出异常. 使用 on_error(), 可以通过调用处理器来处理该异常, 并可报告解析失败所处的上下文.

相比之下, 后随运算符 (>>) 不要求其后的解析器匹配输入, 这允许回溯, 或简单地从 parse() 函数返回 false 而不抛出异常.

与 序列 类似, 期望运算符 a > b 按顺序解析两个或更多操作数 (a、b 等):

a > b > ...

然而, 普通 序列 在某个元素失败时只是返回不匹配 (返回 false), 而期望运算符 > 会在第二个或后续操作数 (除第一个之外的所有操作数) 匹配失败时抛出 expectation_failure<Iter>.

期望失败

当除第一个之外的任何操作数匹配失败时, 会抛出一个 expectation_failure<Iter>:

template <typename Iter>
struct expectation_failure : std::runtime_error
{
    Iter first;           // [first, last) iterator pointing
    Iter last;            // to the error position in the input.
    info what_;       // Information about the nature of the error.
};
表达式语义

仅当表达式的语义与 NaryParser 不同或在其中未定义时, 才给出其语义.

表达式

语义

a > b

匹配 a, 随后是 b. 如果 a 失败, 则不匹配. 如果 b 失败, 则抛出 expectation_failure<Iter>

注释

如果需要在 a 失败时抛出异常, 请使用 expect 指令而不是期望运算符.

属性

参见 复合属性记法.

复杂度

期望解析器的总体复杂度由其各元素复杂度之和决定. 期望运算符本身的复杂度为 O(N), 其中 N 是序列中元素的数量.

一些 using 声明:

using boost::spirit::ascii::char_;
using boost::spirit::qi::expectation_failure;

下面的代码使用期望运算符抛出一个 expectation_failure: 当期望 "o" 而输入中发现的是 "i" 时, 发生刻意的解析错误. catch 块打印与错误相关的信息. 注意: 这是演示 bare-metal (裸机层面) 的底层代码. 通常, 你会使用错误处理器来处理错误.

try
{
    test_parser("xi", char_('x') > char_('o')); // should throw an exception
}
catch (expectation_failure<char const*> const& x)
{
    std::cout << "expected: "; print_info(x.what_);
    std::cout << "got: \"" << std::string(x.first, x.last) << '"' << std::endl;
}

上面的代码将打印:

expected: tag: literal-char, value: o
got: "i"
