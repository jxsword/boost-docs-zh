复合组件属性的更多内容

在解析输入或生成输出时, 常常希望将一些常量元素与可变部分组合起来. 例如, 让我们看一看解析或格式化复数的例子: 复数写作 (real, imag), 其中 real 和 imag 是表示复数实部与虚部的变量. 这可以按如下方式实现:

库

序列表达式

Qi

'(' >> double_ >> ", " >> double_ >> ')'

Karma

'(' << double_ << ", " << double_ << ')'

幸运的是, 字面量(例如 '(' 和 ", ")不 暴露任何属性(实际上它们确实暴露特殊类型 unused_type, 但在此上下文中 unused_type 被解释为仿佛该组件根本不暴露任何属性). 理解这一点非常重要: 字面量不会消耗传递给该组件序列的 fusion 序列的任何元素. 如前所述, 它们只是不暴露任何属性, 也不产生(消耗)任何数据. 下面的示例展示了这一点:

// the following parses "(1.0, 2.0)" into a pair of double
std::string input("(1.0, 2.0)");
std::string::iterator strbegin = input.begin();
std::pair<double, double> p;
qi::parse(strbegin, input.end(),
    '(' >> qi::double_ >> ", " >> qi::double_ >> ')', // parser grammar 
    p);                                               // attribute to fill while parsing

下面是等价的 Spirit.Karma 代码片段:

// the following generates: (1.0, 2.0)
std::string str;
std::back_insert_iterator<std::string> out(str);
generate(out,
    '(' << karma::double_ << ", " << karma::double_ << ')', // generator grammar (format description)
    p);                                                     // data to use as the attribute

其中, 作为要生成的数据传入的 pair 的第一个元素仍然与第一个 double_ 关联, 第二个元素与第二个 double_ 生成器关联.

这一行为应当是熟悉的, 因为它符合其他输入/输出格式化库(如 scanf, printf 或 boost::format)处理其可变部分的方式. 在此上下文中, 可以把 Spirit.Qi 和 Spirit.Karma 的原语组件(例如上面的 double_)看作属性值的类型安全占位符.

提示

与上面给出的提示类似, 本示例可以用 Spirit 的多属性 API 函数改写:

double d1 = 0.0, d2 = 0.0;
qi::parse(begin, end, '(' >> qi::double_ >> ", " >> qi::double_ >> ')', d1, d2);
karma::generate(out, '(' << karma::double_ << ", " << karma::double_ << ')', d1, d2);

它提供了清晰而舒适的语法, 更接近 printf 或 boost::format 所暴露的基于占位符的语法.

让我们从更正式的角度来看待这一点. 当涉及以 unused_type 作为属性的生成器时, 序列属性传播规则定义了一种特殊行为(参见 生成器复合属性规则):

库

序列属性传播规则

Qi

a: A, b: Unused --> (a >> b): A

Karma

a: A, b: Unused --> (a << b): A

其含义为:

设 a 与 b 为解析器(生成器), 且 A 为 a 的属性类型, unused_type 为 b 的属性类型, 则 a >> b(a << b) 的属性类型同样将为 A. 无论暴露 unused_type 的元素处于什么位置, 该规则都适用.

一旦涉及字面量, 这条规则就是理解序列中属性处理的关键. 就仿佛带有 unused_type 属性的元素在属性传播过程中"消失"了一样. 值得注意的是, 这不仅适用于序列, 也适用于任何复合组件. 例如, 对于备选组件, 相应的规则是:

a: A, b: Unused --> (a | b): A

这同样可以简化表达式的整体属性类型.
