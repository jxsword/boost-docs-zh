不抛出异常的期望

默认情况下, 当期望失败发生时, X3 会抛出 expectation_failure. C++ 异常虽然直接明了, 但带有可观的开销, 可能显著影响应用程序的处理速度, 尤其当你的解析器在性能关键的循环中被调用时.

简而言之, 即使是像下面这样最简单的文法, 如果以不匹配的输入调用 100,000 次, 也会抛出异常 100,000 次.

x3::lit('a') > 'b'

你可以改变这一行为, 把错误存储到用户提供的变量中, 而不是抛出异常.

取决于文法的复杂程度, 不抛出模式可比传统模式快1-90 倍.

提示

性能提升的上限受 C++ 异常的开销约束, 也就是说, 解析时间的缩短幅度受异常本会引入的开销所限制.

迁移指南

要切换到不抛出模式, 请在包含 X3 头文件之前把宏 BOOST_SPIRIT_X3_THROW_EXPECTATION_FAILURE 定义为 0, 然后对解析器的入口点做几处修改.

下面是一个处于默认(抛出)模式的解析器示例:

#include <boost/spirit/home/x3.hpp>

void do_parse()
{
    // ... setup your variables here...

    try
    {
        bool const ok = x3::parse(first, last, parser);
        if (!ok)
        {
            // error handling
        }
    }
    catch (x3::expectation_failure<Iterator> const& failure)
    {
        // error handling
    }
}

接下来, 按如下方式调整代码以切换到不抛出模式:

#define BOOST_SPIRIT_X3_THROW_EXPECTATION_FAILURE 0
#include <boost/spirit/home/x3.hpp>

void do_parse()
{
    // ... setup your variables here...

    // convenient helper, defaults to `boost::optional<x3::expectation_failure<Iterator>>`
    x3::expectation_failure_optional<Iterator> failure;

    bool const ok = x3::parse(
        first, last, x3::with<x3::expectation_failure_tag>(failure)[parser]);

    if (!ok)
    {
        if (failure.has_value())
        {
            // error handling
        }
    }
}
提示

你也可以在 on_error 处理器 中检查该变量.

就是这些! 所有 X3 解析器在语义上都与之前相同, 唯一的区别是: 期望失败将被存储到变量中, 而不是作为 C++ 异常抛出.

上下文值支持以下类型:

  • bool
  • std::optional<x3::expectation_failure<Iterator>>
  • boost::optional<x3::expectation_failure<Iterator>>
  • optional 类型的 std::reference_wrapper
