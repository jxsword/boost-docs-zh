复合组件属性的更多内容

在解析输入时, 常常希望把一些常量元素与可变部分组合起来. 例如, 让我们看看解析或格式化复数的示例, 复数写作 (real, imag), 其中 real 和 imag 是表示复数实部和虚部的变量. 这可以通过编写以下代码实现:

'(' >> double_ >> ", " >> double_ >> ')'

字面量 (例如 '(' 和 ", ") 不 暴露任何属性 (实际上, 它们确实暴露特殊类型 unused_type, 但在此上下文中 unused_type 被解释为该组件完全不暴露任何属性). 非常重要的一点是: 字面量不消耗传给该组件序列的 fusion 序列的任何元素. 如前所述, 它们只是不暴露任何属性, 也不产生 (消耗) 任何数据. 以下示例展示了这一点:

// the following parses "(1.0, 2.0)" into a pair of double
std::string input("(1.0, 2.0)");
std::string::iterator strbegin = input.begin();
std::pair<double, double> p;
x3::parse(strbegin, input.end(),
    '(' >> x3::double_ >> ", " >> x3::double_ >> ')', // parser grammar
    p);                                               // attribute to fill while parsing

其中作为待生成数据传入的 pair 的第一个元素仍与第一个 double_ 关联, 第二个元素与第二个 double_ 解析器关联.

这种行为应当是熟悉的, 因为它符合其他输入和输出格式化库 (例如 scanf、printf 或 boost::format) 处理可变部分的方式. 在此上下文中, 你可以把 Spirit.X3 的基础组件 (例如上面的 double_) 看作属性值的类型安全占位符.

提示

仅适用于序列: 为保持简单, 与 __Spirit.qi__ 不同, Spirit.X3 在 parse 和 phrase_parse 函数中不再支持多于一个属性. 此时只需使用 std:tuple'. Be sure to include boost/fusion/adapted/std_tuple.hpp'.

让我们从更正式的角度来看待这一点:

a: A, b: Unused --> (a >> b): A

其含义为:

设 a 与 b 为解析器, A 为 a 的属性类型, unused_type 为 b 的属性类型, 则 a >> b (a << b) 的属性类型同样是 A. 无论暴露 unused_type 的元素处于何种位置, 此规则均适用.

一旦涉及字面量, 这条规则就是理解序列中属性处理的关键. 就仿佛带有 unused_type 属性的元素在属性传播过程中"消失"了一样. 值得注意的是, 这不仅适用于序列, 也适用于任何复合组件. 例如, 对于备选组件, 相应的规则是:

a: A, b: Unused --> (a | b): A

这同样可以简化表达式的整体属性类型.
