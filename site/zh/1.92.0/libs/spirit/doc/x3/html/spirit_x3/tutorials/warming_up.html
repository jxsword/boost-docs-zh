热身

我们将从展示解析器表达式的示例开始, 让你体会如何从最简单的解析器构建解析器, 并随着讲解逐步深入. 把 EBNF 与 Spirit 比较, 表达式起初可能显得有些别扭. Spirit 大量使用运算符重载来实现其魔法.

简单示例 #1 解析一个数字

创建一个解析浮点数的解析器.

double_

(你不得不承认, 这很简单!) 上面的代码实际上生成了一个 Spirit 浮点解析器 (一个内建解析器). Spirit 有许多预定义解析器, 一致的命名约定帮你保持清醒不至抓狂!

简单示例 #2 解析两个数字

创建一个接受由两个浮点数组成的输入行的解析器.

double_ >> double_

这里你看到熟悉的浮点数值解析器 double_ 被使用了两次, 每个数字一次. 那个 >> 运算符在那里做什么? 嗯, 它们之间必须用某个东西分隔, 而它被选作 "后随" 序列运算符. 上面的程序从两个更简单的解析器创建出一个解析器, 用序列运算符把它们粘合在一起. 结果是一个由更小解析器组合而成的解析器. 数字之间的空白是否被隐式消耗取决于解析器的调用方式 (见下文).

注释

当我们组合解析器时, 我们得到一个 "更大" 的解析器, 但它仍然是一个解析器. 解析器可以越来越大, 嵌套越来越深, 但每当你把两个解析器粘合在一起, 你就得到一个更大的解析器. 这是一个重要概念.

简单示例 #3 解析零个或多个数字

创建一个接受零个或多个浮点数的解析器.

*double_

这类似于正则表达式的 Kleene 星号, 尽管对于不习惯看到 * 运算符被这样重载的 C++ 程序员来说, 语法可能看起来有点怪. 实际上, 如果你熟悉正则表达式, 它可能也显得怪异, 因为星号位于它所修饰的表达式之前. 世事如此. 只能怪我们必须遵循 C++ 的语法规则.

任何求值为解析器的表达式都可以与 Kleene 星号一起使用. 记住, 对于复杂表达式, C++ 运算符优先级规则可能要求你把表达式放进括号. Kleene 星号也被称为 Kleene 闭包, 但我们在大多数地方称它为星号 (Star).

简单示例 #4 解析以逗号分隔的数字列表

本示例将创建一个接受以逗号分隔的数字列表的解析器.

double_ >> *(char_(',') >> double_)

注意 char_(','). 它是一个字面量字符解析器, 能够识别逗号 ','. 在这里, Kleene 星号修饰的是一个更复杂的解析器, 即由以下表达式生成的解析器:

(char_(',') >> double_)

注意这是括号必要的情况. Kleene 星号作用于上面完整的表达式.

开始解析!

解析器的定义完成了. 下一步是调用这个解析器来做它的工作. 有几种方法可以做到. 现在, 我们将使用 phrase_parse 函数. 该函数的一个重载接受四个参数:

  1. 指向输入开头的迭代器
  2. 指向输入末尾之后一位的迭代器
  3. 解析器对象
  4. 另一个解析器, 称为跳过解析器

在我们的示例中, 我们希望跳过空格和制表符. Spirit 的预定义解析器库中包含另一个名为 space 的解析器. 它是一个非常简单的解析器, 只识别空白字符. 我们将使用 space 作为我们的跳过解析器. 跳过解析器负责跳过解析器元素之间的字符, 例如 double_ 和 char_ 之间.

好, 现在开始解析!

template <typename Iterator>
bool parse_numbers(Iterator first, Iterator last)
{
    using x3::double_;
    using x3::phrase_parse;
    using ascii::space;

    bool r = phrase_parse(
        first,                          //  Start Iterator
        last,                           //  End Iterator
        double_ >> *(',' >> double_),   //  The Parser
        space                           //  The Skip-Parser
    );
    if (first != last) // fail if we did not get a full match
        return false;
    return r;
}

parse 函数根据解析结果返回 true 或 false. 第一个迭代器按引用传入. 解析成功时, 该迭代器被重新定位到解析器消耗的最右位置. 如果它等于 last, 则是完全匹配; 否则是部分匹配. 部分匹配发生在解析器只能解析输入的一部分时.

注意我们把解析器直接内联在 parse 调用中. 调用 parse 时, 表达式求值为一个临时的、匿名的解析器, 它被传入 parse() 函数, 使用后随即销毁.

这里, 我们选择通过把解析器做成模板来使其泛型化, 以迭代器类型为参数. 这样一来, 只要迭代器符合前向迭代器要求, 它就可以接受来自任何符合 STL 的序列的数据.

你可以在这里找到完整的 cpp 文件: num_list1.cpp

注释

char 和 wchar_t 操作数

细心的读者可能注意到, 解析器表达式用的是 ',' 而不是像前面示例那样的 char_(','). 由于 C++ 的转换语法规则, 这样做是可以的. 有一些 >> 运算符被重载为可以在其左侧或右侧 (但不能同时) 接受 char 或 wchar_t 参数. 只要运算符至少有一个参数是用户定义类型, 它就可以被重载. 在这个例子中, double_ 是 operator>> 的第二个参数, 因此使用了 >> 的相应重载, 把 ',' 转换为字符字面量解析器.

省略 char_ 的问题应当很明显: 'a' >> 'b' 不是 Spirit 解析器, 它是一个数值表达式, 把 'a' 的 ASCII (或其他编码) 值右移 'b' 的 ASCII 值位. 然而, char_('a') >> 'b' 和 'a' >> char_('b') 都是 Spirit 序列解析器, 匹配字母 'a' 后随 'b'. 你迟早会习惯的.

最后, 注意我们通过检查解析后第一个迭代器是否等于结尾迭代器来测试完全匹配 (即解析器完整解析了输入). 如果要允许部分匹配, 可以删掉这部分.
