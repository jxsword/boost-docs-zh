复合组件的属性

Spirit.X3 为所有复合解析器 (例如序列、备选、Kleene 星号等) 实现了良定义的属性类型传播规则. 例如, 序列的主要属性传播规则是:

a: A, b: B --> (a >> b): tuple<A, B>

其含义为:

给定 a 和 b 是解析器, A 是 a 的属性类型, B 是 b 的属性类型, 则 a >> b (a << b) 的属性类型将是 tuple<A, B>.

注释

记法 tuple<A, B> 用作持有类型 A 和 B 的任意 fusion 序列的占位表达式, 例如 boost::fusion::tuple<A, B> 或 std::pair<A, B> (更多信息参见 Boost.Fusion).

如上所见, 要使一个类型与复合表达式的属性类型兼容, 它必须

  • 要么可转换为该属性类型,
  • 要么暴露某些功能, 即它需要符合与该组件兼容的概念.

每个复合组件实现自己的属性传播规则集. 有关不同复合解析器如何消耗属性的完整列表, 请参阅解析器复合属性规则一节.

序列解析器的属性

序列要求属性类型暴露 fusion 序列概念, 且该 fusion 序列的所有元素都必须与组件序列的对应元素兼容. 例如, 表达式:

double_ >> double_

与任何持有两个类型的 fusion 序列兼容, 且这两个类型都必须与 double 兼容. fusion 序列的第一个元素必须与第一个 double_ 的属性兼容, 而 fusion 序列的第二个元素必须与第二个 double_ 的属性兼容. 假设我们拥有一个 std::pair<double, double> 的实例, 就可以直接用上面的表达式完成两件事: 解析输入以填充属性:

// the following parses "1.0 2.0" into a pair of double
std::string input("1.0 2.0");
std::string::iterator strbegin = input.begin();
std::pair<double, double> p;
x3::phrase_parse(strbegin, input.end(),
    x3::double_ >> x3::double_,       // parser grammar
    x3::space,                        // delimiter grammar
    p);                               // attribute to fill while parsing
提示

仅适用于序列: 为保持简单, 与 __Spirit.qi__ 不同, Spirit.X3 在 parse 和 phrase_parse 函数中不再支持多于一个属性. 此时只需使用 std:tuple'. Be sure to include boost/fusion/adapted/std_tuple.hpp'.

备选解析器的属性

备选解析器顾名思义就是关于备选的. 为了保存来自不同备选项的可能不同的结果 (属性) 类型, 我们使用 Boost.Variant 数据类型. 这些组件的主要属性传播规则是:

a: A, b: B --> (a | b): variant<A, B>

备选还有第二条非常重要的属性传播规则:

a: A, b: A --> (a | b): A

这常常能显著简化问题. 如果备选的所有子表达式暴露相同的属性类型, 整个备选也将暴露完全相同的属性类型.
