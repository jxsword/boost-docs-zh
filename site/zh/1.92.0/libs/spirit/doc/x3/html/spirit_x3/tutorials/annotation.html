注解 - 装饰 AST

作为理解本教程的先决条件, 请先回顾前面的 employee 示例. 本示例正是在该示例的基础上构建的.

停下来想一想... 实际上, 在前面的示例中我们已经在生成 AST(抽象语法树)了. 我们解析了一个单一结构, 并以 struct 的形式生成了它的内存表示: struct employee. 如果我们修改实现以解析一个或多个 employee, 结果将是一个 std::vector<employee>. 我们还可以继续添加更多层次: 团队、部门、公司等等. 我们可以为这一切建立 AST 表示.

本示例展示如何用迭代器位置为 AST 添加注解, 以便在使用客户端提供的 on_success 处理器进行后处理时访问源代码. 该示例将展示如何获取输入源流中与 AST 中给定元素相对应的位置.

此外, 本示例还展示了如何使用 “with” 指令“注入”客户端数据, 使 on_success 处理器在解析遍历期间被调用时能够通过解析器的上下文访问这些数据.

本示例完整的 cpp 文件可在这里找到: annotation.cpp

AST

首先, 我们更新之前的 employee struct, 这次把 person 拆分到它自己的 struct 中. 现在我们有两个 struct: person 和 employee. 另外还请注意, 我们继承了 person 与 employee, 它们来自 x3::position_tagged, 后者提供位置信息, 使我们随时都能得知 AST 在输入流中的位置.

namespace client { namespace ast
{
    struct person : x3::position_tagged
    {
        person(
            std::string const& first_name = ""
          , std::string const& last_name = ""
        )
        : first_name(first_name)
        , last_name(last_name)
        {}

        std::string first_name, last_name;
    };

    struct employee : x3::position_tagged
    {
        int age;
        person who;
        double salary;
    };
}}

与之前一样, 我们需要把我们的 struct 告知 Boost.Fusion, 使它们成为文法可以利用的一等 fusion 公民:

BOOST_FUSION_ADAPT_STRUCT(client::ast::person,
    first_name, last_name
)

BOOST_FUSION_ADAPT_STRUCT(client::ast::employee,
    age, who, salary
)
x3::position_cache

在继续之前, 让我介绍一个名为 position_cache 的辅助类. 它是一个简单的类, 收集指向 AST 中各元素在输入流中所在位置的迭代器范围. 给定一个 AST, 你可以查询 position_cache 以获得 AST 的位置. 例如:

auto pos = positions.position_of(my_ast);

其中 my_ast 是 AST, positions 是 position_cache; position_of 返回一个迭代器范围, 指向 AST 被解析时的起点和终点位置 (pos.begin() 和 pos.end()). positions.begin() 与 positions.end() 则指向整个输入流的起点和终点.

on_success

on_success 为你提供了语义动作所能提供的一切, 而又没有视觉上的杂乱. 声明式代码可以而且应当摆脱命令式代码. on_success 作为一种概念和机制, 是对 Spirit 上一版本 Qi 处理方式的一次重要突破.

正如前面的 employee 示例 所演示的, 从输入源提取数据的首选方式是让解析器在遍历输入流的过程中替我们把数据收集到 C++ struct 中. 理想情况下, Spirit X3 文法是完全带属性的, 并且以这样的方式声明: 你不必添加任何命令式代码, 也完全不需要语义动作. 解析器只是按声明的方式工作, 你随之得到自己的数据.

然而, 在某些情况下, 不可避免地要引入命令式代码. 但语义动作会打乱我们整洁的声明式文法. 如果我们希望保持代码整洁, on_success 处理器就是另一种回调钩子: 它们由解析器在成功解析后执行, 调用客户端代码, 而不污染文法. 与语义动作一样, on_success 处理器可以访问 AST、迭代器和上下文. 但与语义动作不同, on_success 处理器与实际的文法干净地分离.

注释: on_success 处理器收到的是已预跳过的迭代器, 即便规则定义已通过 no_skip 指令禁用了预跳过.

注解处理器

如前所述, 我们用 on_success 处理器为 AST 添加其在输入流中的位置注解:

// tag used to get the position cache from the context
struct position_cache_tag;

struct annotate_position
{
    template <typename T, typename Iterator, typename Context>
    inline void on_success(Iterator const& first, Iterator const& last
    , T& ast, Context const& context)
    {
        auto& position_cache = x3::get<position_cache_tag>(context).get();
        position_cache.annotate(ast, first, last);
    }
};

position_cache_tag 是一个特殊标签, 我们将用它获取对实际 position_cache 的引用; 后者是客户端数据, 我们将在最初调用 parse 时注入它. 稍后会详细说明.

我们的 on_success 处理器获取对实际 position_cache 的引用, 并调用其 annotate 成员函数, 传入 AST 和迭代器. position_cache.annotate(ast, first, last) 用 x3::position_tagged 所需的信息为 AST 添加注解.

解析器

现在我们为 employee 编写一个解析器. 为简单起见, 输入将采用如下形式:

{ age, "forename", "surname", salary }

开始:

namespace parser
{
    using x3::int_;
    using x3::double_;
    using x3::lexeme;
    using ascii::char_;

    struct quoted_string_class;
    struct person_class;
    struct employee_class;

    x3::rule<quoted_string_class, std::string> const quoted_string = "quoted_string";
    x3::rule<person_class, ast::person> const person = "person";
    x3::rule<employee_class, ast::employee> const employee = "employee";

    auto const quoted_string_def = lexeme['"' >> +(char_ - '"') >> '"'];
    auto const person_def = quoted_string >> ',' >> quoted_string;

    auto const employee_def =
            '{'
        >>  int_ >> ','
        >>  person >> ','
        >>  double_
        >>  '}'
        ;

    auto const employees = employee >> *(',' >> employee);

    BOOST_SPIRIT_DEFINE(quoted_string, person, employee);
}
规则声明 
struct quoted_string_class;
struct person_class;
struct employee_class;

x3::rule<quoted_string_class, std::string> const quoted_string = "quoted_string";
x3::rule<person_class, ast::person> const person = "person";
x3::rule<employee_class, ast::employee> const employee = "employee";

回头再看一看最初的 employee 解析器. 有什么变化?

  • 我们把单一的 employee 规则拆分为三个更小的规则: quoted_string、person 和 employee.
  • 我们使用了前向声明的规则类: quoted_string_class、person_class 和 employee_class.
规则类

与之前一样, 在本示例中, 规则类 quoted_string_class、person_class 和 employee_class 为规则提供 X3 执行其任务所需的静态已知 ID. 除此之外, 规则类还可以扩展出一些用户定义的定制钩子, 它们会在以下时机被调用:

  • 成功时: 在规则成功解析输入之后.
  • 出错时: 在规则解析失败之后.

让规则类继承自客户端提供的处理器, 例如上文我们的 annotate_position 处理器:

struct person_class : annotate_position {};
struct employee_class : annotate_position {};

上面的代码告诉 X3 检查规则类是否拥有 on_success 或 on_error 成员函数, 并在相应事件发生时恰当地调用它们.

with 指令

对于任何解析器 p, 都可以注入补充数据, 供语义动作和处理器在被调用时访问. 一般语法为:

with<tag>(data)[p]

在我们这个具体示例中, 我们注入 position_cache 到解析过程中, 供我们的 annotate_position on_success 处理器访问:

auto const parser =
    // we pass our position_cache to the parser so we can access
    // it later in our on_sucess handlers
    with<position_cache_tag>(std::ref(positions))
    [
        employees
    ];

通常, 这在调用 x3::parse 或 x3::phrase_parse 之前完成. with 是一种非常轻量的操作. 你可以注入任意多的数据, 甚至可以叠加多个 with 指令:

with<tag1>(data1)
[
    with<tag2>(data2)[p]
]

多个 with 指令可以(这一点或许并不明显)从被调用函数的外部注入. 概要如下:

template <typename Parser>
void bar(Parser const& p)
{
    // Inject data2
    auto const parser = with<tag2>(data2)[p];
    x3::parse(first, last, parser);
}

void foo()
{
    // Inject data1
    auto const parser = with<tag1>(data1)[my_parser];
    bar(p);
}
开始解析

现在我们有了支持注解的完整解析机制:

using iterator_type = std::string::const_iterator;
using position_cache = boost::spirit::x3::position_cache<std::vector<iterator_type>>;

std::vector<client::ast::employee>
parse(std::string const& input, position_cache& positions)
{
    using boost::spirit::x3::ascii::space;

    std::vector<client::ast::employee> ast;
    iterator_type iter = input.begin();
    iterator_type const end = input.end();

    using boost::spirit::x3::with;

    // Our parser
    using client::parser::employees;
    using client::parser::position_cache_tag;

    auto const parser =
        // we pass our position_cache to the parser so we can access
        // it later in our on_sucess handlers
        with<position_cache_tag>(std::ref(positions))
        [
            employees
        ];

    bool r = phrase_parse(iter, end, parser, space, ast);

    // ... Some error checking here

    return ast;
}

我们来走读一下这段代码.

首先, 我们定义了一些 typedef: 1) 解析器所用的迭代器类型 iterator_type; 2) position_cache 类型. 后者是一个模板, 接受它将容纳的容器的类型. 在这里是一个 std::vector<iterator_type>.

主 parse 函数接受一个输入(一个 std::string)和对 position_cache 的引用, 并返回一个 AST: std::vector<client::ast::employee>.

在 parse 函数内部, 我们首先创建一个 AST, 解析得到的数据将存放在其中:

std::vector<client::ast::employee> ast;

最后, 我们创建解析器, 注入对 position_cache 的引用, 然后调用 phrase_parse:

using client::parser::employees;
using client::parser::position_cache_tag;

auto const parser =
    // we pass our position_cache to the parser so we can access
    // it later in our on_sucess handlers
    with<position_cache_tag>(std::ref(positions))
    [
        employees
    ];

bool r = phrase_parse(iter, end, parser, space, ast);

解析成功后, AST(ast)将包含实际解析得到的数据.

获取源位置

既然已经有了主 parse 函数, 我们来准备一个示例源文件用于解析, 并展示如何在成功解析返回后获取某个 AST 元素的位置.

给定如下输入:

std::string input = R"(
{
    23,
    "Amanda",
    "Stefanski",
    1000.99
},
{
    35,
    "Angie",
    "Chilcote",
    2000.99
},
{
    43,
    "Dannie",
    "Dillinger",
    3000.99
},
{
    22,
    "Dorene",
    "Dole",
    2500.99
},
{
    38,
    "Rossana",
    "Rafferty",
    5000.99
}
)";

在实例化一个将保存源流位置的 position_cache 对象之后, 我们调用 parse 函数:

position_cache positions{input.begin(), input.end()};
auto ast = parse(input, positions);

现在我们有了一个包含解析结果的 AST(ast). 我们来获取第 2 个 employee 的源位置:

auto pos = positions.position_of(ast[1]); // zero based of course!

pos 是一个迭代器范围, 其中包含指向输入流中 ast[1] 的起点和终点的迭代器.
