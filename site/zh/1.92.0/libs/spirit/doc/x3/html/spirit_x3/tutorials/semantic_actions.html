解析器语义动作

上一节的示例非常简单. 它只识别数据, 但对数据不做任何处理. 它回答的问题是: "输入匹配了吗?". 现在, 我们要从解析的内容中提取信息. 例如, 我们希望在成功匹配后存储解析出的数字. 为此, 你需要 语义动作.

语义动作可以附着到文法规范中的任何位置. 这些动作是多态函数对象, 每当解析器的某个部分成功识别出输入的一段时就会被调用. 假设你有一个解析器 p 和一个多态的 C++ 函数对象 f. 你可以让解析器在匹配到输入时调用 f, 做法是附着 f:

p[f]

上面的表达式把 f 链接到解析器 p. f 应当是一个具有如下签名的多态函数对象:

template <typename Context>
void operator()(Context const& ctx) const;

我们也可以使用如下形式的 C++14 泛型 lambda:

[](auto& ctx) { /*...*/ }

从上下文中, 我们可以提取相关信息:

表 2. 解析上下文访问函数

函数

说明

示例

_val

对直接或间接调用解析器 p 的最内层规则的属性的引用

_val(ctx) = "Gotya!"

_where

指向输入流的迭代器范围

_where(ctx).begin()

_attr

对解析器 p 的属性的引用

_val(ctx) += _attr(ctx)

_pass

对一个 bool 标志的引用, 该标志可用于强制 p 失败

_pass(ctx) = false


语义动作示例

给定:

struct print_action
{
    template <typename Context>
    void operator()(Context const& ctx) const
    {
        std::cout << _attr(ctx) << std::endl;
    }
};

请注意, 对于函数对象, 我们需要一个带有 Context 参数的 operator(). 如果我们不关心上下文, 可以使用 unused_type. 我们将在其他地方更多地见到 unused_type. unused_type 是 Spirit 提供的一个支撑类.

所有示例都解析如下形式的输入:

"{NNN}"

其中 NNN 是花括号内的一个整数(例如 {44}).

第一个示例展示如何附着函数对象:

parse(first, last, '{' >> int_[print_action()] >> '}');

有什么新东西? 嗯, int_ 是 double_ 的兄弟. 我确信你能猜到这个解析器做什么.

下一个示例展示如何使用 C++14 lambda:

auto f = [](auto& ctx){ std::cout << _attr(ctx) << std::endl; };
parse(first, last, '{' >> int_[f] >> '}');

附着语义动作是开始用 Spirit 进行解析时要跨过的第一道坎. 请熟悉这一任务.
