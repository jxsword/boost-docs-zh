错误处理

不谈错误处理, 本教程就不算完整. 作为理解本教程的先决条件, 请回顾前面的 employee 与 annotations 示例. 本示例正是建立在这些先前示例的基础之上.

本示例完整的 cpp 文件可在这里找到: error_handling.cpp

请回顾前面的 annotations 示例. 其中的内容对理解错误处理非常有帮助.

AST

我们的 AST 与之前 annotations 中的完全相同:

namespace client { namespace ast
{
    struct person : x3::position_tagged
    {
        person(
            std::string const& first_name = ""
          , std::string const& last_name = ""
        )
        : first_name(first_name)
        , last_name(last_name)
        {}

        std::string first_name, last_name;
    };

    struct employee : x3::position_tagged
    {
        int age;
        person who;
        double salary;
    };
}}

我们有两个 struct: person 和 employee. 每一个都继承自 x3::position_tagged, 后者提供位置信息, 使我们随时都能得知 AST 在输入流中的位置. 错误处理与报告将需要这些信息.

与之前一样, 我们需要把我们的 struct 告知 Boost.Fusion, 使它们成为文法可以利用的一等 fusion 公民:

BOOST_FUSION_ADAPT_STRUCT(client::ast::person,
    first_name, last_name
)

BOOST_FUSION_ADAPT_STRUCT(client::ast::employee,
    age, who, salary
)
期望

有些场合要求输入必须匹配某个特定解析器, 否则输入无效. 这种情况通常出现在匹配了文法的一部分之后, 此时上下文已完全明确. 在这种情况下, 匹配失败应当导致异常. 例如, 在解析电子邮件地址时, 必须匹配一个名称、一个 "@" 和一个域名, 否则该地址无效.

X3 有两种机制可辅助实现解析器期望:

  1. 期望运算符(Expectation operator)
  2. expect 指令 (expect[p])

期望运算符(Expectation operator)要求随后的解析器 (b) 匹配输入, 否则就会抛出一个 expectation_failure. 使用客户端提供的 on_error 处理器, 该异常可得到处理: 以解析失败处的源迭代器和上下文调用该处理器, 即可报告相应位置.

相比之下, 序列运算符(Sequence)不要求随后的解析器匹配输入, 因而允许回溯, 或者直接从 parse 函数返回 false 而不抛出异常.

expect 指令 (expect[p]) 要求其参数解析器匹配输入, 否则就会抛出异常. 借助 on_error(), 该异常可得到处理: 以解析失败处的上下文调用处理器, 即可报告相应位置.

提示

关于如何在不使用 C++ 异常的情况下切换到更高效的错误处理, 请参阅 不抛出异常的期望教程.

on_error

on_error 是 on_success 的对应物, 如 annotations 示例 中所讨论的. on_success 处理器是在成功解析之后由解析器执行的客户端代码回调钩子, 而 on_error 处理器则是在通过 expect 运算符或指令抛出 expectation_failure 时由解析器执行的客户端代码回调钩子. on_error 处理器可以访问迭代器、上下文以及被抛出的异常.

错误处理

在继续之前, 让我介绍一个辅助类: x3::error_handler. 它是一个实用类, 提供 Clang 风格的错误报告, 会给出如下美观的报告:

In line 16:
Error! Expecting: person here:
    'I am not a person!'    <--- this should be a person
____^_

稍后我们将看到, 这条错误消息正是本示例所输出的内容.

下面是我们的 on_error 处理器:

struct error_handler
{
    template <typename Iterator, typename Exception, typename Context>
    x3::error_handler_result on_error(
        Iterator& first, Iterator const& last
      , Exception const& x, Context const& context)
    {
        auto& error_handler = x3::get<x3::error_handler_tag>(context).get();
        std::string message = "Error! Expecting: " + x3::which(x) + " here:";
        error_handler(x3::where(x), message);
        return x3::error_handler_result::fail;
    }
};

x3::error_handler_tag 是一个特殊标签, 我们将用它获取对实际 x3::error_handler 的引用; 后者将在最初调用 parse 时注入. 我们在这里取得 x3::error_handler:

auto& error_handler = x3::get<error_handler_tag>(context).get();

x3::error_handler 处理所有琐碎的细节, 例如确定行号和实际列位置, 以及格式化要打印的错误消息. 我们所要做的只是提供实际的错误字符串, 它从 expectation_failure 异常中提取:

std::string message = "Error! Expecting: " + x3::which(x) + " here:";

然后, 我们返回 x3::error_handler_result::fail, 告诉 X3: 捕获到这类事件时, 我们希望使解析失败. 你可以返回以下之一:

Action

说明

fail

退出并失败. 返回 no_match.

retry

尝试错误恢复, 可能移动迭代器位置.

accept

强制成功, 恰当地移动迭代器位置.

rethrow

重新抛出该错误.
解析器

现在我们重写 employee 解析器, 把错误处理考虑在内. 与 annotations 示例一样, 输入将采用如下形式:

{ age, "forename", "surname", salary }

下面开始:

namespace parser
{
    using x3::int_;
    using x3::double_;
    using x3::lexeme;
    using ascii::char_;

    struct quoted_string_class;
    struct person_class;
    struct employee_class;

    x3::rule<quoted_string_class, std::string> const quoted_string = "quoted_string";
    x3::rule<person_class, ast::person> const person = "person";
    x3::rule<employee_class, ast::employee> const employee = "employee";

    auto const quoted_string_def = lexeme['"' >> +(char_ - '"') >> '"'];
    auto const person_def = quoted_string > ',' > quoted_string;

    auto const employee_def =
            '{'
        >   int_ > ','
        >   person > ','
        >   double_
        >   '}'
        ;

    auto const employees = employee >> *(',' >> employee);

    BOOST_SPIRIT_DEFINE(quoted_string, person, employee);

    struct quoted_string_class {};
    struct person_class : x3::annotate_on_success {};
    struct employee_class : error_handler, x3::annotate_on_success {};
}

回头再看一看 带注解的 employee 解析器. 有什么变化? 它几乎完全相同, 除了:

在适当之处, 我们用期望运算符(Expectation operator)取代序列运算符(Sequence):

auto const person_def = quoted_string > ',' > quoted_string;

auto const employee_def =
        '{'
    >   int_ > ','
    >   person > ','
    >   double_
    >   '}'
    ;

文法中会有一些“确定性点”. 它们是回溯不能发生的地方. 对于上面的示例, 当你得到一个 '{' 时, 接下来肯定必须看到一个 int_. 之后, 肯定必须有一个 ',', 然后是一个 person, 以此类推, 直到最后一个 '}'. 否则, 无论其他分支在哪里, 继续下去并尝试它们都毫无意义. 输入肯定是错误的. 此时, 会抛出一个 expectation_failure 异常. 在外层的某个地方, 错误处理器会捕获该异常. 在我们的例子中, 它在我们的 on_error 处理器中被捕获.

另请注意, 我们让 employee_class 继承自我们的 error_handler. 这样做是在告诉 X3: 我们的 error_handler 应当被调用, 无论异常是在 employee 规则内部抛出, 还是在它所调用的任何内容(即 person 和 quoted_string 规则)内部抛出.

开始解析

现在我们有了带错误处理的完整解析机制:

void parse(std::string const& input)
{
    using boost::spirit::x3::ascii::space;
    typedef std::string::const_iterator iterator_type;

    std::vector<client::ast::employee> ast;
    iterator_type iter = input.begin();
    iterator_type const end = input.end();

    using boost::spirit::x3::with;
    using boost::spirit::x3::error_handler_tag;
    using error_handler_type = boost::spirit::x3::error_handler<iterator_type>;

    // Our error handler
    error_handler_type error_handler(iter, end, std::cerr);

    // Our parser
    using client::parser::employees;
    auto const parser =
        // we pass our error handler to the parser so we can access
        // it later in our on_error and on_sucess handlers
        with<error_handler_tag>(std::ref(error_handler))
        [
            employees
        ];

    bool r = phrase_parse(iter, end, parser, space, ast);

    // ... Some final reports here
}

在调用 phrase_parse 之前, 我们首先创建一个 AST, 解析得到的数据将存放在其中:

std::vector<client::ast::employee> ast;

我们还创建了实际的错误处理器, 把消息发送到 std::cerr:

error_handler_type error_handler(iter, end, std::cerr);

然后, 我们注入对 error_handler 的引用, 所用的 with 指令与我们在 annotations 示例 中的做法类似:

auto const parser =
    // we pass our error handler to the parser so we can access
    // it later in our on_error and on_sucess handlers
    with<error_handler_tag>(std::ref(error_handler))
    [
        employees
    ];
