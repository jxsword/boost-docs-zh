罗马数字

本示例演示:

  • 符号表
  • 非终结符规则
符号表

符号表保存一个符号字典, 其中每个符号是一个字符序列. 该模板类可以高效地处理 8、16、32 甚至 64 位字符. 每个符号都关联着类型为 T 的可变数据.

传统上, 符号表管理是在 BNF 文法之外通过语义动作单独维护的. 与标准做法相反, Spirit 的符号表类 symbols 是一个解析器. 其实例可以在 EBNF 文法规范的任何地方使用. 它是动态解析器的一个例子. 动态解析器的特点在于能够在运行期修改自身行为. 最初, 空的 symbols 对象不匹配任何内容. 任何时候都可以添加或删除符号, 从而动态改变其行为.

符号表中的每个条目都可以有一个关联的可变数据槽. 从这个角度看, 可以把符号表视为键值对的关联容器(或映射), 其键为字符串.

symbols 类需要一个模板参数来指定与每个符号关联的数据类型: 即其属性. X3 中有几个命名空间, 你可以在其中找到用于处理不同字符编码的 symbols 类的各种版本, 包括 ascii、standard、standard_wide、iso8859_1 和 unicode. 主 x3 命名空间中默认的符号解析器类型是 standard.

下面是使用符号表解析罗马数字百位 (100..900) 的解析器. 记住, 与每个槽关联的数据是解析器的属性 (会传给附加的语义动作).

struct hundreds_ : x3::symbols<unsigned>
{
    hundreds_()
    {
        add
            ("C"    , 100)
            ("CC"   , 200)
            ("CCC"  , 300)
            ("CD"   , 400)
            ("D"    , 500)
            ("DC"   , 600)
            ("DCC"  , 700)
            ("DCCC" , 800)
            ("CM"   , 900)
        ;
    }

} hundreds;

下面是解析罗马数字十位 (10..90) 的解析器:

struct tens_ : x3::symbols<unsigned>
{
    tens_()
    {
        add
            ("X"    , 10)
            ("XX"   , 20)
            ("XXX"  , 30)
            ("XL"   , 40)
            ("L"    , 50)
            ("LX"   , 60)
            ("LXX"  , 70)
            ("LXXX" , 80)
            ("XC"   , 90)
        ;
    }

} tens;

最后, 个位 (1..9) 的解析器:

struct ones_ : x3::symbols<unsigned>
{
    ones_()
    {
        add
            ("I"    , 1)
            ("II"   , 2)
            ("III"  , 3)
            ("IV"   , 4)
            ("V"    , 5)
            ("VI"   , 6)
            ("VII"  , 7)
            ("VIII" , 8)
            ("IX"   , 9)
        ;
    }

} ones;

现在我们可以在解析器表达式的任何地方使用 hundreds、tens 和 ones. 它们都是解析器.

规则

到目前为止, 我们一直把解析器表达式内联, 直接传给 phrase_parse 函数. 表达式求值为一个临时的、匿名的解析器, 它被传入 phrase_parse 函数, 使用后随即销毁. 这对小解析器没问题. 当表达式变复杂时, 你会希望把表达式拆成更小、更易理解的部分, 给它们命名, 并在其他解析器表达式中按名称引用.

解析器表达式可以赋给所谓的 "rule". 声明 rule 有多种方式. 最简单的形式是:

rule<ID> const r = "some-name";
规则 ID

至少, 规则需要一个标识标签. 这个 ID 可以是任何 struct 或 class 类型, 无需定义, 前向声明即可. 在后续教程中, 我们将看到规则 ID 还可以具有用于错误处理和注解的额外功能.

规则名称

名称是可选的, 但对调试和错误处理很有用, 稍后我们会看到. 注意规则 r 被声明为 const. 规则是不可变的, 最好声明为 const. 规则是轻量的, 可以按值传递. 它唯一的成员变量是一个 std::string: 即其名称.

注释

与 Qi (Spirit V2)不同, X3 规则可以同时与 phrase_parse 和 parse 一起使用, 而无需指定 skip 解析器

规则属性

对于下一个示例, 还有一种你应该了解的 rule 形式:

rule<ID, Attribute> const r = "some-name";

Attribute 参数指定规则的属性类型. 你已经看到, 我们的解析器可以拥有属性. 回想一下, double_ 解析器拥有 double 类型的属性. 确切地说, 这些是合成属性: 解析器“合成”属性值. 如果把解析器看作函数, 可以把它们想象成函数返回值.

规则定义

声明规则之后, 你需要为该规则提供一个定义. 例如:

auto const r_def = double_ >> *(',' >> double_);

按照惯例, 规则定义带有 _def 后缀. 与规则一样, 规则定义也是不可变的, 最好声明为 const.

BOOST_SPIRIT_DEFINE

既然我们有了规则及其定义, 就使用 BOOST_SPIRIT_DEFINE 宏把规则与规则定义绑定起来:

BOOST_SPIRIT_DEFINE(r);

在幕后, 实际发生的事情是: 我们在客户端命名空间中定义了一个 parse_rule 函数, 它告诉 X3 如何调用规则. 因此, 对于使用 BOOST_SPIRIT_DEFINE 定义的每条规则, 都有一个重载的 parse_rule 函数. 在解析时, Spirit X3 会递归调用相应的 parse_rule 函数.

注释

BOOST_SPIRIT_DEFINE 是可变参数的, 可用于一条或多条规则. 示例: BOOST_SPIRIT_DEFINE(r1, r2, r3);

文法

与 Qi (Spirit V2)不同, X3 摒弃了把文法作为封装规则的具体实体的观念. 在 X3 中, 文法只是一组协同工作的规则的逻辑组合, 通常有一个单一的顶层起始规则作为主入口. X3 文法用命名空间来组织. 罗马数字文法是一个非常好的简单文法示例:

namespace parser
{
    using x3::eps;
    using x3::lit;
    using x3::_val;
    using x3::_attr;
    using ascii::char_;

    auto set_zero = [](auto& ctx){ _val(ctx) = 0; };
    auto add1000 = [](auto& ctx){ _val(ctx) += 1000; };
    auto add = [](auto& ctx){ _val(ctx) += _attr(ctx); };

    x3::rule<class roman, unsigned> const roman = "roman";

    auto const roman_def =
        eps                 [set_zero]
        >>
        (
            -(+lit('M')     [add1000])
            >>  -hundreds   [add]
            >>  -tens       [add]
            >>  -ones       [add]
        )
    ;

    BOOST_SPIRIT_DEFINE(roman);
}

需要注意的事项:

  • 起始规则的属性是 unsigned.
  • _val(ctx) 获取对规则合成属性的引用.
  • _attr(ctx) 获取对解析器合成属性的引用.
  • eps 是一个特殊的 spirit 解析器, 不消耗任何输入, 但总是成功. 我们用它把规则的合成属性初始化为零, 先于其他一切. 实际的解析从 +lit('M') 开始, 解析罗马数字的千位. 以这种方式使用 eps, 适合做前置和后置初始化.
  • 规则 roman 和定义 roman_def 都是 const 对象.
  • 规则的 ID 是 class roman. 如示例所示, C++ 允许你在实际的模板声明中直接声明该类:
x3::rule<class roman, unsigned> const roman = "roman";
开始解析! 
bool r = parse(iter, end, roman, result);

if (r && iter == end)
{
    std::cout << "-------------------------\n";
    std::cout << "Parsing succeeded\n";
    std::cout << "result = " << result << std::endl;
    std::cout << "-------------------------\n";
}
else
{
    std::string rest(iter, end);
    std::cout << "-------------------------\n";
    std::cout << "Parsing failed\n";
    std::cout << "stopped at: \": " << rest << "\"\n";
    std::cout << "-------------------------\n";
}

roman 就是我们的罗马数字解析器. 这一次我们使用的是 parse 函数的不跳过版本: 我们不想跳过任何空格! 我们还传入了一个属性 unsigned result, 它将接收解析得到的值.
