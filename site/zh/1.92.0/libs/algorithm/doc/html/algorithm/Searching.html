Boyer-Moore Search

概述

头文件 'boyer_moore.hpp' 包含用于搜索值序列的 Boyer-Moore 算法的一个实现.

Boyer–Moore 字符串搜索算法是一种特别高效的字符串搜索算法, 一直是实用字符串搜索文献中的标准基准. Boyer-Moore 算法由 Bob Boyer 和 J. Strother Moore 发明, 发表于 1977 年 10 月的 Communications of the ACM, 该文章的副本可在 http://www.cs.utexas.edu/~moore/publications/fstrpos.pdf 获取.

Boyer-Moore 算法使用两张预计算的表来获得比朴素搜索更好的性能. 这些表依赖于被搜索的模式, 使 Boyer-Moore 算法比更简单的算法占用更多内存并有更高的启动开销, 但这些开销会在搜索过程中很快得到补偿, 尤其是当模式长度超过几个元素时.

但是, Boyer-Moore 算法不能与 std::search 之类的比较谓词一起使用.

术语说明: 我把被搜索的序列称为"模式" (pattern) , 把在其中搜索的序列称为"语料" (corpus) .

接口

为了灵活性, Boyer-Moore 算法有两个接口: 基于对象的接口和过程式接口. 基于对象的接口在构造函数中构建表, 并使用 operator () 执行搜索. 过程式接口一步完成建表和搜索. 如果你要在多个语料中搜索同一模式, 应当使用对象接口, 只构建一次表.

以下是对象接口:

template <typename patIter>
class boyer_moore {
public:
    boyer_moore ( patIter first, patIter last );
    ~boyer_moore ();

    template <typename corpusIter>
    pair<corpusIter, corpusIter> operator () ( corpusIter corpus_first, corpusIter corpus_last );
    };

以下是对应的过程式接口:

template <typename patIter, typename corpusIter>
pair<corpusIter, corpusIter> boyer_moore_search (
        corpusIter corpus_first, corpusIter corpus_last,
        patIter pat_first, patIter pat_last );

每个函数都接受两对迭代器. 前两个定义语料, 后两个定义模式. 注意, 这两对迭代器不必是同一类型, 但它们必须"指向"同一类型. 换句话说, patIter::value_type 与 curpusIter::value_type 必须是同一类型.

函数的返回值是一对迭代器, 指向模式在语料中的位置. 如果模式为空, 它返回语料开头的一个空范围 (corpus_first, corpus_first) . 如果未找到模式, 它返回语料末尾的一个空范围 (corpus_last, corpus_last) .

兼容性说明

此搜索器的早期版本只返回单个迭代器. 如 https://cplusplusmusings.wordpress.com/2016/02/01/sometimes-you-get-things-wrong/ 所解释, 这是一个欠佳的接口选择, 并已从 1.62.0 发布版起更改. 期望返回单个迭代器的旧代码可以通过把搜索器的 operator () 返回值替换为该 pair 的 .first 字段来更新.

原来:

iterator foo = searcher(a, b);

现在改为:

iterator foo = searcher(a, b).first;

性能

Boyer-Moore 算法的执行时间虽然仍与被搜索字符串的大小成线性关系, 但其常数因子可以显著低于许多其他搜索算法: 它不需要检查被搜索字符串的每个字符, 而是跳过其中一些. 通常, 被搜索的模式越长, 算法越快. 它的效率源于: 每次在搜索字符串与文本之间寻找匹配失败时, 它都会利用该次尝试获得的信息, 尽可能多地排除文本中字符串不可能匹配的位置.

内存使用

该算法分配两张内部表. 第一张的大小与模式长度成正比; 第二张对模式中"字母表"的每个成员有一个条目. 对于 (8 位的) 字符类型, 该表包含 256 个条目.

复杂度

在语料中查找模式的最坏情况性能是 O(N) (线性) 时间; 即与被搜索语料的长度成正比. 一般而言, 搜索是亚线性的; 并非语料中的每个条目都需要检查.

异常安全

Boyer-Moore 算法的面向对象版本和过程式版本都按值接受参数, 且不使用传入信息以外的任何信息. 因此, 两个接口都提供强异常保证.

注释
  • 使用基于对象的接口时, 模式在搜索期间必须保持不变; 即从对象构造之时起, 直到对 operator () 的最后一次调用返回.
  • Boyer-Moore 算法要求模式和语料都使用随机访问迭代器.
定制点

Boyer-Moore 对象接受一个 traits 模板参数, 使调用者能够定制其中一张预计算表的存储方式. 该表称为跳转表 (skip table) , (在逻辑上) 对模式可能包含的每个可能值有一个条目. 搜索 8 位字符数据时, 该表包含 256 个元素. traits 类定义要使用的表.

默认 traits 类对小"字母表"使用 boost::array, 对较大的字母表使用 tr1::unordered_map. 基于数组的跳转表性能极佳, 但当被搜索元素的"字母表"增大时可能会大得离谱. 基于 unordered_map 的版本只随模式中唯一元素的数量增长, 但会进行多得多的堆分配, 且查找性能较慢.

要使用不同的跳转表, 你应当定义自己的跳转表对象和自己的 traits 类, 并用它们实例化 Boyer-Moore 对象. 这些对象的接口有待描述 (TBD) .
