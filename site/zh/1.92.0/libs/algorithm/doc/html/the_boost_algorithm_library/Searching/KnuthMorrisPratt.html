Knuth-Morris-Pratt Search

概述

头文件 'knuth_morris_pratt.hpp' 包含用于搜索值序列的 Knuth-Morris-Pratt 算法的一个实现.

Knuth-Morris-Pratt 算法的基本前提是: 当发生失配时, 被搜索的模式中包含的信息可以用来确定下一次匹配可能从哪里开始, 从而跳过语料中已经检查过的一些元素.

它通过根据被搜索的模式构建一张表来做到这一点, 表中模式的每个元素有一个条目.

该算法由 Donald Knuth 和 Vaughan Pratt 于 1974 年构想, James H. Morris 也独立提出. 三人于 1977 年在 SIAM Journal on Computing 上联合发表 http://citeseer.ist.psu.edu/context/23820/0

但是, Knuth-Morris-Pratt 算法不能与 std::search 之类的比较谓词一起使用.

接口

术语说明: 我把被搜索的序列称为"模式" (pattern) , 把在其中搜索的序列称为"语料" (corpus) .

为了灵活性, Knuth-Morris-Pratt 算法有两个接口: 基于对象的接口和过程式接口. 基于对象的接口在构造函数中构建表, 并使用 operator () 执行搜索. 过程式接口一步完成建表和搜索. 如果你要在多个语料中搜索同一模式, 应当使用对象接口, 只构建一次表.

以下是对象接口:

template <typename patIter>
class knuth_morris_pratt {
public:
    knuth_morris_pratt ( patIter first, patIter last );
    ~knuth_morris_pratt ();

    template <typename corpusIter>
    pair<corpusIter, corpusIter> operator () ( corpusIter corpus_first, corpusIter corpus_last );
    };

以下是对应的过程式接口:

template <typename patIter, typename corpusIter>
pair<corpusIter, corpusIter> knuth_morris_pratt_search (
        corpusIter corpus_first, corpusIter corpus_last,
        patIter pat_first, patIter pat_last );

每个函数都接受两对迭代器. 前两个定义语料, 后两个定义模式. 注意, 这两对迭代器不必是同一类型, 但它们必须"指向"同一类型. 换句话说, patIter::value_type 与 curpusIter::value_type 必须是同一类型.

函数的返回值是一对迭代器, 指向模式在语料中的位置. 如果模式为空, 它返回语料开头的一个空范围 (corpus_first, corpus_first) . 如果未找到模式, 它返回语料末尾的一个空范围 (corpus_last, corpus_last) .

兼容性说明

此搜索器的早期版本只返回单个迭代器. 如 https://cplusplusmusings.wordpress.com/2016/02/01/sometimes-you-get-things-wrong/ 所解释, 这是一个欠佳的接口选择, 并已从 1.62.0 发布版起更改. 期望返回单个迭代器的旧代码可以通过把搜索器的 operator () 返回值替换为该 pair 的 .first 字段来更新.

原来:

iterator foo = searcher(a, b);

现在改为:

iterator foo = searcher(a, b).first;

性能

Knuth-Morris-Pratt 算法的执行时间与被搜索字符串的大小成线性关系. 通常, 被搜索的模式越长, 算法越快. 它的效率源于: 每次在搜索字符串与文本之间寻找匹配失败时, 它都会利用该次尝试获得的信息, 尽可能多地排除文本中字符串不可能匹配的位置.

内存使用

该算法有一张表, 对模式的每个元素有一个条目, 外加一个额外条目. 因此, 搜索一个 1026 字节的字符串时, 该表将有 1027 个条目.

复杂度

最坏情况性能是 O(2n) , 其中 n 是语料的长度. 平均时间为 O(n) . 最好情况性能是亚线性的.

异常安全

Knuth-Morris-Pratt 算法的面向对象版本和过程式版本都按值接受参数, 且不使用传入信息以外的任何信息. 因此, 两个接口都提供强异常保证.

注释
  • 使用基于对象的接口时, 模式在搜索期间必须保持不变; 即从对象构造之时起, 直到对 operator () 的最后一次调用返回.
  • Knuth-Morris-Pratt 算法要求模式和语料都使用随机访问迭代器. 应当可以改写为使用双向迭代器 (甚至可能前向迭代器) , 但本实现没有这样做.
