NDEBUG

务必定义 NDEBUG uBLAS 判断你想要 release 配置的唯一方式是检查你是否定义了 NDEBUG. 如果没有定义, 它会假定你想要 debug 配置, 并加入大量非常有用的运行期检查. 但是这些检查非常慢!

BOOST_UBLAS_MOVE_SEMANTICS

该补丁及说明由 Nasos Iliopoulos 提供.

该选项的一个直接效果是: 当向同类型赋值时, 类型 vector<T> 和 matrix<T> 不再需要 noalias. 该选项对 bounded 和 c 类型没有影响. 尽管罕见, 但并非所有编译器都支持拷贝消除 (它使移动语义成为可能), 因此必须进行测试, 以确保启用它确实有收益. 一个小型演示和测试见 test_move_semantics.cpp

在 测试示例中定义了两个测试, 一个针对向量, 一个针对矩阵. 该示例的目的是打印每个容器存储的指针, 即在向临时对象赋值之前和之后各打印一次. 启用移动语义后, vector<T> 和 matrix<T> 的存储会从临时对象移动过来, 而不执行拷贝.

如果你的编译器支持移动语义, 你会得到类似下面的输出:

matrix<double> --------------------------------------------------------------------
Temporary pointer r: 0x94790c0
Pointer (must be equal to temp. pointer if move semantics are enabled) : 0x94790c0

注释:

  • 看到矩阵和向量按值 (VALUE) 传递应该不令人意外, 编译器会处理好: 要么移动 (如果底层代码不修改对象), 要么拷贝 (如果底层代码修改对象).
  • 可能还有一些改进空间 (例如在交换前清空数据)
  • 移动语义并不消除临时对象. 它们只是移动临时对象的存储, 从而不执行拷贝.
  • MSVC 在 debug 模式下不实现命名返回值优化 (NRVO). 因此如果你用该编译器构建 debug 版本, 你可能会得到 与 release 构建不同的行为.
  • 启用移动语义的方式是 #define BOOST_UBLAS_MOVE_SEMANTICS.
  • 等 C++0x 标准发布后, 利用右值引用还有很大的优化空间. (我有一个用它实现的很棒的 vector).
  • 如果你启用了移动语义而你的编译器不支持, 操作只会像按 const 引用传递一样.

BOOST_UBLAS_CHECK_ENABLE

当定义了 BOOST_UBLAS_CHECK_ENABLE 时, 所有索引和参数检查都会启用. 它在 debug 模式下启用, 在 release 模式下禁用.

BOOST_UBLAS_TYPE_CHECK

当启用 BOOST_UBLAS_TYPE_CHECK 时, 所有可能开销很大的结构检查都会启用. 如果不希望这样, 可以在包含任何 uBLAS 头文件之前使用 #define BOOST_UBLAS_TYPE_CHECK 0. 宏 BOOST_UBLAS_TYPE_CHECK_EPSILON 可用于控制可接受的容差, 该检查的实现细节见 detail/matrix_assign.hpp.

BOOST_UBLAS_USE_LONG_DOUBLE

启用涉及 'long double' 容器的 uBLAS 表达式

BOOST_UBLAS_USE_INTERVAL

启用涉及 'boost::numeric::interval' 类型容器的 uBLAS 表达式

用宏配置 uBLAS

ublas/config.hpp 及其他地方出现了许多宏. 希望将来其中一些会消失! 它们分为 4 组:

  • 由 'boost/numeric/ublas/config.hpp' 根据 NDEBUG 自动设置. 用于区分 debug (安全) 与 release (快速) 模式. 类似于 STLport
    • Release 模式 (定义了 NDEBUG)
      • BOOST_UBLAS_INLINE 依赖于编译器的定义, 用于控制函数内联.
      • BOOST_UBLAS_USE_FAST_SAME
    • Debug 模式
      • BOOST_UBLAS_CHECK_ENABLE 启用索引、迭代器和参数检查. 防止越界访问等.
      • BOOST_UBLAS_TYPE_CHECK 对使用非稠密类型的表达式结果启用额外检查. 捕捉诸如把数值上非对称的矩阵赋给 symmertic_matrix 之类的运行期错误. 使用 #define BOOST_UBLAS_TYPE_CHECK 0 可禁用开销很大的数值类型检查. (注释: "结构检查" 会是一个更好的名字.)
      • BOOST_UBLAS_TYPE_CHECK_EPSILON 默认: sqrt(epsilon), 控制期望结果与计算结果之间允许的差值大小. 如果你要使用接近奇异的或严重病态缩放的矩阵, 请增大此值. 这些类型检查的实现请参见 detail/matrix_assign.hpp.
  • 由 'boost/numeric/ublas/config.hpp' 根据编译器以及 boost/config.hpp 的宏自动设置. 补充 boost/config.hpp 已提供的编译器缺陷变通手段
    • BOOST_UBLAS_NO_NESTED_CLASS_RELATION VC7.1 的一个特别棘手的问题. 要求 uBLAS 和用户使用 begin(it) 而不是 it.begin()
    • BOOST_UBLAS_NO_SMART_PROXIES 禁用向代理自动传播 '常量性'. 智能代理会自动判断它们引用的底层容器是否为常量, 并相应调整其迭代器和容器访问的定义以反映该常量性.
  • 供 uBLAS 作者用于测试实现方法. 在 config.hpp 中预置
    • BOOST_UBLAS_USE_INVARIANT_HOISTING
    • BOOST_UBLAS_USE_INDEXING
    • BOOST_UBLAS_USE_INDEXED_ITERATOR
    • BOOST_UBLAS_NON_CONFORMANT_PROXIES 带间隙 (gappy) 的容器可能是不一致的, 即在不同索引处包含元素. 在这些容器的代理 (例如向量 range) 之间赋值很困难, 因为左值可能需要插入新元素. 这很慢.
    • BOOST_UBLAS_USE_DUFF_DEVICE 在所有平台上几乎无用 (参见 GCC 的 -funroll-loops)
  • 用户选项. 可以在包含任何 uBLAS 头文件之前由用户预定义. 为了绕过编译期缺陷, 某些编译器也可能自动定义它们.
    • BOOST_UBLAS_USE_LONG_DOUBLE 启用涉及 'long double' 容器的 uBLAS 表达式
    • BOOST_UBLAS_USE_INTERVAL 启用涉及 'boost::numeric::interval' 类型容器的 uBLAS 表达式
    • BOOST_UBLAS_SIMPLE_ET_DEBUG 为了简化调试, 可以简化表达式模板, 使其限制为单一运算
    • BOOST_UBLAS_ENABLE_PROXY_SHORTCUTS 启用从代理类到矩阵表达式的自动转换
    • BOOST_UBLAS_NO_ELEMENT_PROXIES 对带间隙的类型禁用元素代理.
    • 带间隙的类型 (sparse、coordinate、compressed) 把非零元素存储在自己的容器中. 当赋予新的非零元素时, 它们必须重排这些容器. 这会使指向这些元素的引用、迭代器或指针失效. 这可能发生在一些令人意外的时候, 例如表达式 "a [1] = a [0] = 1;". 元素代理保证所有这类表达式都能按预期工作. 但是它们也带来自己的限制和效率问题. 例如, 从 Boost 1.30.0 起, 它们会阻止在不同类型之间进行元素赋值.
    • BOOST_UBLAS_REFERENCE_CONST_MEMBER 启用后允许返回对三角矩阵或带状矩阵固定 (零或一) 元素的引用
    • BOOST_UBLAS_NO_EXCEPTIONS 禁用 uBLAS 内部检查和错误条件抛出的异常. BOOST_NO_EXCEPTIONS 有同样效果.
    • BOOST_UBLAS_SINGULAR_CHECK 在三角 solve() 函数中检查奇异性
