基础线性代数库

uBLAS 是一个 C++ 模板类库, 为稠密、紧凑与稀疏矩阵提供 BLAS 1、2、3 级功能. 其设计与实现通过运算符重载统一数学记法, 并通过表达式模板生成高效代码.

功能

uBLAS 为稠密、单位与稀疏向量, 以及稠密、单位、三角、带状、对称、厄米特与稀疏矩阵提供模板化 C++ 类. 可以通过范围 (range)、切片 (slice)、适配器类与间接数组构造向量和矩阵的视图. 本库涵盖向量和矩阵上常见的基础线性代数运算: 各种范数等归约运算、向量和矩阵的加减法及与标量的乘法、向量的内积与外积、矩阵-向量与矩阵-矩阵乘积以及三角求解器. 容器、视图与表达式模板运算之间的粘合剂是一个基本符合 STL 的迭代器接口.

常见问题

问: 新项目应该使用 uBLAS 吗?
答: 撰写本文时 (2012 年 9 月) 已有许多优秀的矩阵库可用, 例如 MTL4、armadillo、eigen. uBLAS 提供一套稳定且经过充分测试的向量与矩阵类、线性代数的典型运算以及三角方程组的求解器. uBLAS 提供稠密、结构化与稀疏矩阵 - 全部使用相似的接口. 最后, uBLAS 的性能良好 (但并非出众). 另一方面, uBLAS 上一次重大改进是在 2008 年, 且自 2009 年以来没有提交过重大变更. 因此应当自问几个问题来辅助决策: 是否容易获得? uBLAS 是 boost 的一部分, 因而在许多环境中都可用. 是否易用? 对于简单的事情 uBLAS 易于使用, 但一旦偏离常规路径就需要扎实的 C++ 知识. 性能? 存在更快的替代品. 是否前沿? uBLAS 已有 10 多年历史, 错过了 C++11 的所有新特性.

问: 我在运行 uBLAS 稠密向量与矩阵基准测试. 为什么会看到原生 C 实现与库实现之间有显著的性能差异?
答: uBLAS 区分调试模式 (启用大小与类型一致性检查, 禁用表达式模板) 与发布模式 (禁用大小与类型一致性检查, 启用表达式模板). 请检查预处理器符号 NDEBUG (属于 cassert) 是否已定义. NDEBUG 启用发布模式, 发布模式转而使用表达式模板. 你可以选择定义 BOOST_UBLAS_NDEBUG 来禁用 uBLAS 的所有边界、结构及类似检查.

问: 我编写了一些 uBLAS 测试, 尝试错误地把不同矩阵类型相互赋值或越界访问向量与矩阵维度. 为什么我没有得到编译期或运行期诊断?
答: uBLAS 区分调试模式 (启用大小与类型一致性检查, 禁用表达式模板) 与发布模式 (禁用大小与类型一致性检查, 启用表达式模板). 请检查预处理器符号 NDEBUG (属于 cassert) 是否已定义. NDEBUG 禁用调试模式, 而大小与类型一致性检查需要调试模式.

问: 我编写了一些 uBLAS 基准测试来衡量矩阵链乘法 (如 prod (A, prod (B, C)) ) 的性能, 发现由于使用表达式模板而导致显著的性能损失. 如何禁用表达式模板?
答: 你不需要禁用表达式模板. 请尝试用 prod (A, matrix_type (prod (B, C))) 或 prod (A, prod<matrix_type > (B, C)) 重新引入临时对象.
