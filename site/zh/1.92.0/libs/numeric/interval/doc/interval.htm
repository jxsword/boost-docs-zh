引言与概述

顾名思义, 本库旨在帮助操纵数学区间. 它由单个头文件 <boost/numeric/interval.hpp> 以及主要是一个可用作 interval<T> 的类型组成. 实际上, 该区间模板被声明为 interval<T,Policies>, 其中 Policies 是控制区间类各种行为的策略类; interval<T> 只是为类型 T 选取默认策略而已.

警告! 并非所有处理器、操作系统和编译器的组合都支持原生浮点格式的保证区间算术. 下面是在配合基本算术运算符使用 interval<float> 和 interval<double> 时已知能正确工作的系统列表.

  • 对于 x86 类硬件, 只要浮点计算使用传统的 x87 浮点单元 (不支持 -mfpmath=sse2), 本库即可在 GCC、Visual C++ ≥ 7.1、Intel 编译器 (Windows 上 ≥ 8)、CodeWarrior (≥ 9) 下使用.
    • clang (至 v9) 没有正确的 舍入支持.
    • clang (10+) 需要指定 -frounding-math.
    • gcc 需要指定 -frounding-math.
    • msvc 需要指定 /fp:strict, 这意味着 MSVC 10.0 及更早版本无法正常工作.
  • Sparc 硬件在 GCC 和 Sun 编译器下受支持.
  • PowerPC 硬件在 GCC 和 CodeWarrior 下受支持, 条件是浮点计算不使用 Altivec 单元.
  • Alpha 硬件在 GCC 下受支持, 但平方根可能除外. 必须使用选项 -mfp-rounding-mode=d -mieee.

上面的列表并不详尽. 而且, 即使某个系统不能为硬件浮点类型提供保证的计算, 区间库仍然可用于用户定义类型以及进行盒 (box) 算术.

区间算术

区间是一对数字, 表示这两个数字之间的所有数字. (区间被视为闭区间, 因此边界包含在内.) 本库的目的是把通常的算术函数扩展到区间. 这些区间将写作 [a,b], 表示 a 与 b 之间 (含) 的所有数字. a 和 b 可以是无穷 (但不能是同一个无穷), 且 a ≤ b.

区间算术的基本性质是 包含性质:

``若 f 是定义在数字集合上的函数, 则 f 可以扩展为定义在区间上的新函数. 该新函数 f 接受一个区间实参并返回区间结果, 满足: ∀ x ∈ [a,b], f(x) ∈ f([a,b]).''

这种性质并不限于只有一个实参的函数. 只要可能, 区间结果应当是能满足该性质的最小区间 (如果新函数总是回答 [-∞,+∞], 那就没有什么用处).

用户想使用本库至少有两个原因. 最明显的是用户需要用区间进行计算. 例如, 输入数据带有某种固有的不精确性: 输入变量可以不传数字而传一个区间. 另一个示例应用是求解方程, 通过不断二分区间直到区间宽度足够小. 第三个示例应用是在计算机图形学中, 盒、线段或射线的计算可以通过区间化为点的计算.

使用区间算术的另一个常见原因是计算机不能产生精确的结果: 通过使用区间, 可以量化舍入误差的传播. 这种方法在数值计算中经常使用. 例如, 假设计算机以十位十进制有效数字存储数字. 对于问题 1 + 1E-100 - 1, 计算机会回答 0, 尽管正确的答案应该是 1E-100. 借助区间算术, 计算机会回答 [0,1E-9]. 对于这么小的结果来说这个区间相当大, 但现在精度是已知的, 无需再计算误差传播.

数字、舍入与异常行为

底层数字类型 是保存区间边界的类型. 为了成功使用区间算术, 底层数字类型必须具备一些 特性. 首先, 根据区间的定义, 底层数字必须是全序的, 例如 complex<T> 不能用作区间的底层数字类型. 底层数字类型的数学函数还应与全序兼容 (例如若 x>y 且 z>t, 则也应成立 x+z > y+t), 因此取模类型也不可用.

其次, 如果想保证包含性质, 计算必须精确, 或者提供某些舍入方法 (例如向负无穷或正无穷舍入). 注意, 我们也可以显式指定不进行舍入, 例如当底层数字类型是精确的, 即数学运算的结果总是在计算和表示时不损失精度. 如果数字类型不精确, 我们仍可以显式指定不进行舍入, 但显而易见的后果是不再保证包含性质.

最后, 由于严重的精度损失总是可能发生, 必须有某些数字表示无穷大, 否则必须定义异常行为. 对于 NaN (Not a Number) 也会出现同样的情况.

考虑到以上各点, 你可能想把类模板 interval 的模板实参 T 限定为 IEEE-754 标准定义的浮点类型 float、double 和 long double. 确实, 如果区间算术意在取代处理器浮点单元提供的算术, 这些类型是最佳选择. 然而与 std::complex 不同, 我们不想把 T 限定为这些类型. 这就是我们允许通过两个策略 (rounding 和 checking) 给定舍入和异常行为的原因. 尽管如此, 我们仍为上述浮点类型提供了高度优化的舍入和检查类特化.

运算与函数

在包含性质的指引下, 在区间上定义初等算术运算非常直接. 例如, 若 [a,b] 和 [c,d] 是区间, 则 [a,b]+[c,d] 可以通过取包含所有 x+y 的最小区间来计算, 其中 x 取自 [a,b], y 取自 [c,d]; 此时, 只需把 a+c 向下舍入、把 b+d 向上舍入即可. 其他运算符和函数也以类似方式定义 (定义见下文).

比较

也可以定义一些比较运算符. 给定两个区间, 结果是一个三态布尔类型 {false,true,indeterminate}. 答案 false 和 true 很容易处理, 因为它们可以直接映射到布尔值 true 和 false. 但答案 indeterminate 却不然, 因为比较运算符本应是布尔函数. 那么, 要如何得到布尔答案呢?

一种解决方案是决定采用某种异常行为, 例如断言失败或抛出异常. 此时, 当结果为 indeterminate 时就会触发该异常行为.

另一种解决方案是把 indeterminate 总是映射为 false, 或总是映射为 true. 若选择 false, 该比较将被称为 "certain"; 实际上, [a,b] < [c,d] 的结果为 true 当且仅当: ∀ x ∈ [a,b] ∀ y ∈ [c,d], x < y. 若选择 true, 该比较将被称为 "possible"; 实际上, [a,b] < [c,d] 的结果为 true 当且仅当: ∃ x ∈ [a,b] ∃ y ∈ [c,d], x < y.

由于这两种方案都有明确定义的语义, 我们是否应该强制采用其中之一并不明确. 出于这个原因, 默认行为是在 indeterminate 情况下抛出异常, 以模仿真实的比较. 其他行为可以通过使用特定的比较命名空间来选择. 还有一批显式命名的比较函数. 更多细节见 比较 页面.

库概览与用法

本库提供两个截然不同的使用层次. 其一是不指定策略而直接使用基本类模板 interval<T>. 这只要求了解并理解上文阐述的概念以及命名空间 boost 的内容. 除了类 interval<T> 之外, 这个层次还提供算术运算符 (+, -, *, /), 代数函数与分段代数函数 (abs, square, sqrt, pow), 超越函数与三角函数 (exp, log, sin, cos, tan, asin, acos, atan, sinh, cosh, tanh, asinh, acosh, atanh), 标准比较运算符 (<, <=, >, >=, ==, !=), 以及若干区间专有函数 (min, max, 它们与 std::min 和 std::max 的含义不同; lower, upper, width, median, empty, singleton, equal, in, zero_in, subset, proper_subset, overlap, intersect, hull, bisect).

对于某些接受多个 interval<T> 类型参数的函数, 会考虑实参类型 T 和 interval<T> 的所有至少含有一个 interval<T> 的组合, 以避免把 T 类型的实参转换为 interval<T> 类型的单元素区间. 这样做是出于效率考虑 (实参是单元素区间有时可以使某些检查变得不必要).

本库稍微进阶的用法是手工挑选策略 Rounding 和 Checking, 并把它们传给 interval<T, Policies>, 途径是使用 Policies := boost::numeric::interval_lib::policies<Rounding,Checking>. 可以使用命名空间 boost::numeric::interval_lib 中提供的各种类来构造合适的策略, 详见 区间支持库 一节. 也可以通过命名空间重载运算符来选择比较方案.

模板类 interval

模板类 interval 本身的公有接口保持得最为精简: 
template <class T, class Policies = typename interval_lib::default_policies<T>::type>
class interval
{
  public:
  typedef T base_type;
  typedef Policies traits_type;

  interval();
  interval(T const &v);
  template<class T1> interval(T1 const &v);
  interval(T const &l, T const &u);
  template<class T1, class T2> interval(T1 const &l, T2 const &u);
  interval(interval<T, Policies> const &r);
  template<class Policies1> interval(interval<T, Policies1> const &r);
  template<class T1, class Policies1> interval(interval<T1, Policies1> const &r);

  interval &operator=(T const &v);
  template<class T1> interval &operator=(T1 const &v);
  interval &operator=(interval<T, Policies> const &r);
  template<class Policies1> interval &operator=(interval<T, Policies1> const &r);
  template<class T1, class Policies1> interval &operator=(interval<T1, Policies1> const &r);

  void assign(T const &l, T const &u);

  T const &lower() const;
  T const &upper() const;

  static interval empty();
  static interval whole();
  static interval hull(T const &x, T const &y);

  interval& operator+= (T const &r);
  interval& operator-= (T const &r);
  interval& operator*= (T const &r);
  interval& operator/= (T const &r);
  interval& operator+= (interval const &r);
  interval& operator-= (interval const &r);
  interval& operator*= (interval const &r);
  interval& operator/= (interval const &r);
};

这些构造函数创建包围其实参的区间. 如果有两个实参, 第一个被假定为左边界, 第二个为右边界. 因此实参必须是有序的. 如果不满足性质 !(l <= u), 将使用检查策略创建空区间. 如果不给实参, 创建的区间是单元素区间零.

如果实参的类型与底层数字类型相同, 这些值将直接用作边界. 如果类型不同, 库将使用舍入策略来转换实参 (conv_down 和 conv_up) 并创建包围区间. 当实参是使用不同策略的区间时, 会检查输入区间以正确传播其空性 (如果为空).

赋值运算符的行为类似, 只不过显然它们只接受一个实参. 还有一个 assign 函数, 可以直接改变区间的边界. 当边界无序时, 其行为与双实参构造函数一样. 没有直接接受区间或单个数字作为参数的 assign 函数; 在这种情况下直接使用赋值运算符即可.

边界的类型和区间类型的策略定义了区间所包含的值集合. 例如, 使用默认策略时, 区间是实数集合的子集. 静态函数 empty 和 whole 产生的区间/子集分别是空子集和全集. 它们是静态成员函数而不是全局函数, 因为它们无法推断自己的返回类型. hull 也是如此. empty 和 whole 需要使用检查策略来获得所得区间的边界.

运算与函数

下面的某些函数要求底层数字类型定义了 min 和 max. 这些是对 interval 类仅有的要求 (但策略可能有其他要求).

运算符 + - * / += -= *= /=

基本运算是一元负号和二元 + - * /. 一元负号接受一个区间并返回一个区间. 二元运算接受两个区间, 或一个区间和一个数字, 并返回一个区间. 如果实参是数字而不是区间, 可以预期结果与先把该数字转换为区间时相同. 该性质对下面所有的函数和运算符都成立.

还有一些赋值运算符 += -= *= /=. 没什么可说的: x op= y 等价于 x = x op y. 如果计算期间抛出异常, 左值不会被修改 (但如果基类型在赋值期间抛出异常, 它可能已被破坏).

运算符 / 和 /= 会在分母恰好为零时尝试产生一个空区间. 如果分母包含零 (但不只有零), 结果将是包含所有除法结果的最小区间; 因此它的一个边界会是无穷, 但未必是整个区间.

lower upper median width norm

lower、upper、median 分别计算区间的下边界、上边界和中位数 ((lower+upper)/2 舍入到最近). width 计算区间的宽度 (upper-lower 向正无穷舍入). norm 计算区间绝对值的一个上界; 它是一个数学范数 (名字由此而来), 类似于实数的绝对值.

min max abs square pow nth_root division_part? multiplicative_inverse

函数 min、max 和 abs 也有定义. 请不要把它们与标准库中定义的函数 (即 a<b?a:b、a>b?a:b、a<0?-a:a) 混淆. 这些函数与区间算术的基本性质兼容. 例如, max([a,b], [c,d]) = {max(x,y) 其中 x ∈ [a,b] 且 y ∈ [c,d]}. 它们不是定义在 std 命名空间中, 而是定义在 boost 命名空间中, 以避免与其他定义冲突.

square 函数相当特殊. 从它的名字可以预期, 它计算其参数的平方. 提供这个函数的原因是: square(x) 并不是 x*x, 当 x 包含零时它只是后者的一个子集. 例如, [-2,2]*[-2,2] = [-4,4] 但 [-2,2]² = [0,4]; 结果是一个更小的区间. 因此, 应该用 square(x) 代替 x*x, 因为它精度更好且有少量性能提升.

与 square 类似, pow 提供了一种高效且更精确的计算区间整数幂的方法. 请注意: 当幂为 0 且区间非空时, 结果是 1, 即使输入区间包含 0. nth_root 计算区间的整数次方根 (nth_root(pow(x,k),k) 包围 x 或 abs(x), 取决于 k 是奇数还是偶数). 如果整数参数不为正, nth_root 的行为未定义. multiplicative_inverse 计算 1/x.

函数 division_part1 和 division_part2 在用户期望除法在必要时返回不相交区间时很有用. 例如, 包含 [2,3] / [-2,1] 的最窄闭集不是 ]-∞,∞[ 而是 ]-∞,-1] 和 [2,∞[ 的并集. 当除法结果可以只用一个区间表示时, division_part1 返回该区间并把布尔引用设置为 false. 但是, 如果结果需要两个区间, division_part1 返回负的部分并把布尔引用设置为 true; 现在需要调用 division_part2 来获取正的部分. 第二个函数可以把第一个函数返回的布尔值作为最后一个参数. 如果不给这个布尔值, 则假定其为 true, 此时如果除法没有产生第二个区间, 函数的行为是不确定的.

intersect hull overlap in zero_in subset proper_subset empty singleton equal

intersect 计算两个闭集的交集, hull 计算包含两个参数的最小区间; 这些参数可以是数字或区间. 如果其中一个参数是无效数字或空区间, 函数将只使用另一个参数来计算结果区间 (如果检查策略允许).

没有并集函数, 因为如果两个区间不重叠, 它们的并集就不是区间. 如果重叠, hull 函数计算并集.

函数 overlap 测试两个区间是否有公共子集. in 测试一个数字是否在区间内; zero_in 是测试零是否在区间内的变体. subset 测试第一个区间是否是第二个区间的子集; proper_subset 测试是否是真子集. empty 和 singleton 测试一个区间是否为空或是否为单元素区间. 最后, equal 测试两个区间是否相等.

sqrt log exp sin cos tan asin acos atan sinh cosh tanh asinh acosh atanh fmod

函数 sqrt、log、exp、sin、cos、tan、asin、acos、atan、sinh、cosh、tanh、asinh、acosh、atanh 也有定义. 没什么可说的; 这些函数把传统函数扩展到区间, 并遵守区间算术的基本性质. 当输入区间严格位于函数定义域之外时, 它们使用 checking 策略产生空区间.

函数 fmod(interval x, interval y) 要求 y 的下边界严格为正, 并返回一个区间 z, 满足 0 <= z.lower() < y.upper() 且 z 是 x-n*y 的超集 (其中 n 是整数). 因此, 如果两个参数都是正的单元素区间, 该函数 fmod(interval, interval) 的行为将类似于传统函数 fmod(double, double).

请注意 fmod 不遵守算术区间的包含性质. 例如, fmod([13,17],[7,8]) 的结果应该是 [0,8] (因为它必须包含 [0,3] 和 [5,8]). 但当目的是限制一个区间以计算周期函数时, 这个答案并没有什么用处. 这就是 fmod 会回答 [5,10] 的原因.

add sub mul div

这四个函数接受两个数字并返回这些运算的包围区间. 它避免了在运算前把数字转换为区间, 在优化器较差时可以获得更好的代码.

常量

一些常量隐藏在 boost::numeric::interval_lib 命名空间中. 它们需要用区间类型显式模板化. 函数是 pi<I>()、pi_half<I>() 和 pi_twice<I>(), 它们返回区间类型 I 的对象. 它们各自的值是 π、π/2 和 2π.

异常抛出

区间类和围绕该类定义的所有函数本身从不抛出任何异常. 但是, 这并不意味着操作永远不会抛出异常. 例如, 考虑拷贝构造函数. 如前所述, 它是编译器生成的默认拷贝构造函数. 因此, 如果基类型的拷贝构造函数不抛出异常, 它就不会抛出异常.

同样的情况适用于所有函数: 只有当基类型或两个策略之一抛出异常时, 才会抛出异常.

区间支持库

区间支持库由一组类组成, 可以使用和组合这些类来构造几乎各种常用的区间策略. 与配合 interval<T> 使用的基本类和函数 (在该类型中默认策略作为隐式的第二个模板参数) 不同——那些组件只属于命名空间 boost——这些组件属于命名空间 boost::numeric::interval_lib.

这里只给出概要, 每一节的内容都推迟到单独的网页, 因为它只面向高级用户. 这样可以在不过度拉长本文档篇幅的情况下, 用示例对每个主题加以展开.

常见陷阱与危险

比较

最大的问题之一可能是比较函数和运算符的正确使用. 首先, 函数和运算符不会去判断两个区间是否是同一个数学对象. 因此, 如果使用的比较是 "certain", 那么 x != x 总是为真, 除非 x 是单元素区间; cereq 和 cerne 也有同样的问题.

对比较的另一个误导性解读是: 你不能总是期望 [a,b] < [c,d] 等价于 !([a,b] >= [c,d]), 因为比较不一定是全序. 相等比较和小于比较应被视为两个不同的关系运算符. 不过, 默认的比较运算符确实遵守这个性质, 因为只要 [a,b] 和 [c,d] 重叠, 它们就会抛出异常.

区间值与区间引用

这个问题是上一个关于 x != x 的问题的推论. 库的所有函数只考虑区间的值, 而不是区间的引用. 特别地, 不应期望 (除非 x 是单元素区间) 以下各对值相等: x/x 和 1, x*x 和 square(x), x-x 和 0, 等等. 因此, 区间变宽的主要原因是区间算术不识别同一变量的不同出现. 所以, 只要可能, 用户必须重写公式以消除同一变量的多次出现. 例如, square(x)-2*x 的精度远低于 square(x-1)-1.

未受保护的舍入

如 本节所述, 当基类型是基本浮点类型时, 加速计算的一个好方法是在算法的热点处解除对区间的保护. 这种方法是安全的, 并且确实能改进区间计算. 但请记住, 在解除保护块内执行的任何基本浮点运算都可能有未定义行为 (但仅对当前线程). 并且不要忘记按照 示例 中的说明创建舍入对象.

设计理由

本库的目的是通过使用模板化的类 boost::numeric::interval, 提供一种高效且通用的处理区间算术的方法. 我们为其提供设计理由的最大争议点是这个类模板的格式.

提供一个基类型为 double 的 interval 类本来会更容易. 或者遵循 std::complex 而只允许对 float、double 和 long double 进行特化. 我们决定不这样做, 以便允许在自定义类型上使用区间, 例如定点大浮点库类型 (MPFR 等)、有理数等等.

策略设计. 虽然把它做成只有一个模板参数的类模板很有吸引力, 但区间算术用途的多样性实际上迫使我们使用策略. 该类的行为可以由两个策略确定. 这些策略被打包成单个策略类, 而不是让 interval 带三个模板参数. 这既是为了易用性 (策略类可以被默认选取), 也是为了可读性.

第一个策略提供在底层数字类型上定义区间类型函数所需的全部数学函数. 第二个策略设定计算中遇到的异常情况的处理方式.

我们可以预见到这些策略的任意组合都适用的情况. 此外, 我们希望让库的用户能够复用 interval 类模板, 同时又能选择自己的行为. 一些示例见这个 页面.

舍入策略. 库为基本类型 float 和 double 提供了舍入策略的特化实现. 为了让这些实现既正确又快速, 库需要大量使用舍入模式. 一些处理器被直接处理, 并且提供了一些机制来加速计算. 仅仅为了节省几个计算周期而做如此繁重且冒险的优化似乎不值; 但实际上, 加速倍数很容易超过 2 或 3, 视计算机而定. 而且, 这些优化并不会以任何重大方式影响接口 (按照我们选择的设计, 一切都可以通过特化或传递不同的模板参数来添加).

Pred/succ. 在前一个版本中, 提供了两个函数 pred 和 succ, 以及各种推论函数如 widen. 其意图是把区间扩大一个 ulp (尽可能小), 例如为了保证包含性质. 自从把 interval 改为 T 的模板之后, 我们无法为任意的参数定义 ulp. 反过来, 舍入策略让我们能够在使区间更紧的同时完全消除 ulp 的使用 (如果结果是一个可表示的单元素区间, 那么扩大区间毫无用处). 我们决定去掉这些函数.

std::less 的特化. 由于运算符 < 依赖于用户局部选择的比较命名空间, 不可能正确地特化 std::less. 因此, 对于可能需要该类的算法和模板 (例如 std::map), 你必须显式地提供这样一个类.

输入/输出. 区间库不包含 I/O 运算符. 打印区间值允许大量的定制: 有些人可能想输出边界, 有些人可能想显示区间的中位数和宽度, 等等. 示例文件 io.cpp 展示了一些可能性, 可以作为用户定义自己运算符的基础.

与整数的混合运算. 在使用和复用模板代码时, 常见会有像 2*x 这样的运算. 但是, 库默认不提供它们, 因为从 int 到底层数字类型的转换并不总是正确的 (想想从 32 位整数到单精度浮点数的转换). 因此这些函数被放在一个单独的头文件中, 用户如果想使用这些混合运算符, 就需要显式包含它. 另一点是, 由于技术上的定义方式, 没有混合比较运算符.

区间感知函数. 库定义的所有函数显然都知道自己在操纵区间, 并按照一般的区间算术原则行事. 因此, 它们的行为可能与常见的非区间感知函数不同. 例如, max 由规范集扩展 (canonical set extension) 定义, 其结果并不总是两个参数之一 (如果两个区间不重叠, 结果就是两个区间之一).

该行为与 std::max 不同, 后者返回其某个参数的引用. 因此, 如果用户期望返回一个引用, 她应该使用 std::max, 因为这正是该函数所做的. 请注意, 当两个区间重叠时 std::max 会抛出异常. 该行为并不违背 C++ 标准所描述的行为, 因为两个参数并不 "等价", 并且它使得 a <= b 与 &b == &std::max(a,b) 之间可以等价 (某些特殊情况可能是实现定义的). 但它与 SGI 所描述的行为不同, 因为即使 "两者互不大于对方", 它也不返回第一个参数.
