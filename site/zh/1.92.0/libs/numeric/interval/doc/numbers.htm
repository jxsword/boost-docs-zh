数值类型要求

这里所说的 "数 (number)" 是指 interval 类的基础类型. 为了遵守包含性质, 区间库对这个基础类型有许多性质要求. 所有这些性质已在本文档的其他章节详细说明; 这里我们将试着对它们做个总结.

序关系

数值类型必须提供一种序. 这种序通过运算符 < <= => > == != 表达. 它必须是全序 (自反性、反对称性、传递性, 且每一对数都可比较). 因此 complex<T> 不适合作为基础类型; 若你需要区间的包含性质, 应当用 complex< interval<T> > 代替 interval< complex<T> > (但遗憾的是, complex 只提供特化).

请注意: 无效数不受序关系的约束; 若与这些无效数的比较总是返回 false (!= 除外), 甚至在概念上更好. 若你的检查策略使用 interval_lib::checking_base 且你的基础类型包含无效数, 则需要这一性质: nan!=nan (此处 nan 是一个无效数). 若该性质不成立, 则不应直接使用 checking_base.

区间算术涉及大量与零的比较. 默认情况下, 这些比较通过把数与 static_cast<T>(0) 比较来完成. 然而, 若数值类型的格式在处理零时允许更快的比较, 可以特化 interval_lib::user 命名空间中的模板函数:

namespace user {
template<class T> inline bool is_zero(T const &v) { return v == static_cast<T>(0); }
template<class T> inline bool is_neg (T const &v) { return v <  static_cast<T>(0); }
template<class T> inline bool is_pos (T const &v) { return v >  static_cast<T>(0); }
}

数值极限

关于检查策略的另一条说明. 它通常足以处理基础类型可能引发的异常行为; 特别是无穷数和无效数 (得益于四个函数 pos_inf, neg_inf, nan 和 is_nan). 然而, 若你使用 interval_lib::checking_base (默认检查策略正是如此), 你的基础类型应有一个正确特化的 std::numeric_limits<T>. 特别地, 值 has_infinity 和 has_quiet_NaN, 以及函数 infinity 和 quiet_NaN 应相应地定义.

概括地说, 若你不依赖默认策略且不使用 interval_lib::checking_base, 则基础类型没有必要有数值极限特化.

数学性质

确保数被正确排序还不够. 基本运算符还应遵守一些依赖于序的性质. 如下所示:

  • 0 ≤ x ⇒ -x ≤ 0
  • x ≤ y ⇒ -y ≤ -x
  • x ≤ y ⇒ x+z ≤ y+z
  • x ≤ y 且 z ≥ 0 ⇒ x×z ≤ y×z
  • 0 < x ≤ y ⇒ 0 < 1/y ≤ 1/x

前述性质也用于 (并且足以用于) abs, square 和 pow. 对于所有超越函数 (包括 sqrt), 还需要其他性质. 这些函数应当具有与对应实函数相同的性质. 例如, cos 的期望性质为:

  • cos 对所有有效数都有定义;
  • 它是 2π 周期的;
  • cos(2π-x) 等于 cos(x);
  • cos 是 [0,2π] 上的减函数.

舍入

若你使用的基础类型从不计算出不精确的结果, 可以跳过本段其余内容. 若你对包含性质不感兴趣 (近似结果已足够), 也可以跳过. 若你仍在阅读, 多半是因为你想了解舍入策略应满足的基本性质.

无论考虑哪种运算或函数, 都应遵守如下性质: f_down(x,y) <= f(x,y) <= f_up(x,y). 其中 f 表示所计算的无限精确函数, f_down 和 f_up 是返回可能不精确但类型正确 (即基础类型) 的值的函数. 若可能, 它们应尽量返回最近的可表示值, 但这并不总是容易做到.

常量

为了让三角函数正确工作, 库需要知道 π 常量的值 (还有 π/2 和 2π). 由于这些常量在基础类型中可能不可表示, 库不必知道其精确值: 一个下界和一个上界就足够了. 若用户未提供这些值, 将使用默认值: 它们是整数值 (因此 π 被限制在 3 和 4 之间).

运算符与转换

如开头所述, 比较运算符应为基础类型定义. 舍入策略定义了区间库使用的大量函数. 因此算术运算符不需要为基础类型定义 (除非某个预定义类有此要求). 然而有一个例外: 一元负号需要定义. 而且, 该运算符只应提供精确结果; 这正是舍入策略不提供取负函数的原因.

从 int 到基础类型的转换需要定义 (只需要少数几个值可用: -1, 0, 1, 2). 反方向的转换由舍入策略提供 (int_down 和 int_up 成员); 除此之外没有其他严格必需的转换. 不过, 在舍入策略中尽可能多地提供转换 (conv_down 和 conv_up 成员) 可能是有价值的, 以便利用区间转换.
