适配你自己的运算

在 odeint 中, 步进器算法的实现与底层的基本数学运算相互独立. 这是通过让用户完全掌控状态类型以及针对该状态类型的数学运算来实现的. 在技术上, 这是通过引入三个概念完成的: StateType、Algebra、Operations. odeint 中的大多数步进器都将满足这三个概念的三个类类型作为模板参数. 注意, 这些概念并非彼此完全独立, 而是必须提供有效的组合才能使步进器正常工作. 下文将给出一些合理的 state_type-algebra-operations 组合示例. 对于最常见的状态类型, 如 vector<double> 或 array<double,N>, 默认值 range_algebra 和 default_operations 完全够用, odeint 可以直接使用, 完全无需操心代数/运算.

重要

state_type、algebra 和 operations 并不相互独立, 必须提供有效的组合才能使 odeint 正常工作

此外, 由于 odeint 自行处理中间临时对象所需的内存, 它还需要知道如何创建 state_type 对象, 或许还需要知道如何分配内存 (调整大小). 总而言之, 将 odeint 与非标准状态类型配合使用时, 需要处理好以下事项:

  • 构造/析构
  • 调整大小 (如果可能/需要)
  • 代数运算

再次说明, odeint 已经为大多数常见状态类型提供了基本接口. 因此, 如果你使用 std::vector 或 std::array 作为状态类型, 无需任何额外工作, 开箱即用.

构造/调整大小

我们区分两类基本状态类型: 固定大小与动态大小. 对于固定大小的状态类型, 默认构造函数 state_type() 已经分配了所需的内存, 典型示例是 std:array<T,N>. 动态大小的类型必须调整大小以确保分配了足够的内存, 标准构造函数不负责调整大小. 这方面的示例是 vector<double> 之类的 STL 容器.

让你自己的状态类型配合 odeint 工作的最简单方式是使用固定大小的状态, 基于范围代数 (range_algebra) 进行计算, 并提供以下功能:

警告

如果你的状态类型默认构造时不分配内存, 你 必须将其定义为可调整大小 并提供 resize 功能 (见下文). 否则会发生段错误.

因此 Boost.Range 支持的固定大小数组可以立即配合 odeint 使用. 对于动态大小的数组, 还必须额外提供 resize 功能. 首先, 必须通过特化结构体 is_resizeable 将状态标记为可调整大小, 该结构体由一个 typedef 和一个 bool 值组成:

使用容器接口

作为第一个示例, 我们取最简单的情况, 实现自己的向量 my_vector, 它将提供容器接口. 这使 Boost.Range 开箱即用. 我们为向量添加了一点功能, 使它在构造时分配一些默认容量. 这在使用调整大小时很有帮助, 因为这样可以确保调整大小不需要新的分配.

template< size_t MAX_N >
class my_vector
{
    typedef std::vector< double > vector;

public:
    typedef vector::iterator iterator;
    typedef vector::const_iterator const_iterator;

public:
    my_vector( const size_t N )
        : m_v( N )
    {
        m_v.reserve( MAX_N );
    }

    my_vector()
        : m_v()
    {
        m_v.reserve( MAX_N );
    }

// ... [ implement container interface ]

因此, 除定义之外, 唯一要做的事就是将 my_vector 声明为可调整大小:

// define my_vector as resizeable

namespace boost { namespace numeric { namespace odeint {

template<size_t N>
struct is_resizeable< my_vector<N> >
{
    typedef std::true_type type;
    static const bool value = type::value;
};

} } }

如果我们不特化 is_resizeable 模板, 代码仍能编译, 但 odeint 不会调整 my_vector 内部临时实例的大小, 从而尝试填充零长度的向量, 导致段错误! 完整示例见 my_vector.cpp

std::list

如果你的状态类型可以配合 Boost.Range 工作, 但处理调整大小的方式不同, 你需要特化 odeint 用来检查状态大小和调整状态大小的两个实现:

作为示例, 我们将在 odeint 中使用 std::list 作为状态类型. 由于 std::list 不受 boost::size 支持, 我们必须替换 same_size 和 resize 实现, 才能让 list 配合 odeint 工作. 以下代码展示了所需的模板特化:

typedef std::list< double > state_type;

namespace boost { namespace numeric { namespace odeint {

template< >
struct is_resizeable< state_type >
{ // declare resizeability
    typedef std::true_type type;
    const static bool value = type::value;
};

template< >
struct same_size_impl< state_type , state_type >
{ // define how to check size
    static bool same_size( const state_type &v1 ,
                           const state_type &v2 )
    {
        return v1.size() == v2.size();
    }
};

template< >
struct resize_impl< state_type , state_type >
{ // define how to resize
    static void resize( state_type &v1 ,
                        const state_type &v2 )
    {
        v1.resize( v2.size() );
    }
};

} } }

有了这些定义, odeint 就知道如何调整 std::list 的大小, 因此它们可以用作状态类型. 完整示例见 list_lattice.cpp.

代数与运算

为提供最大灵活性, odeint 以高度模块化的方式实现. 这意味着可以在不改动积分算法的情况下更换底层数学运算. 基本数学运算就是向量空间的运算, 即 state_types 的加法以及 state_type 与标量的乘法 (time_type). 在 odeint 中, 这通过两个概念实现: Algebra 和 Operations. 标准的实现方式是范围代数 (range algebra), 它基于 Boost.Range 库, 提供将特定运算施加到容器各个元素上的函数. 如果你的状态类型不受 Boost.Range 支持, 有多种方式可以告诉 odeint 如何执行代数运算:

  • 为你的状态类型实现 boost::begin 和 boost::end, 使其能配合 Boost.Range 工作.
  • 实现向量-向量加法运算符 + 和标量-向量乘法运算符 *, 并使用非标准的 vector_space_algebra.
  • 实现你自己的、提供所需函数的代数.
GSL 向量

在下面的示例中, 我们将尝试使用 gsl_vector 类型 (来自 GSL, 即 GNU Scientific Library) 作为 odeint 中的状态类型. 我们通过在 gsl_vector 外实现一个负责构造/析构的包装器来实现这一点. 同时, 还对 Boost.Range 进行扩展, 使其也能配合 gsl_vector 工作, 这还需要实现新的 gsl_iterator.

注释

odeint 已经包含了这里展示的全部代码, 见 gsl_wrapper.hpp, 因此 gsl_vector 可以直接开箱使用. 以下描述仅用于教学目的.

GSL 是一个 C 库, 因此 gsl_vector 既没有构造函数, 也没有析构函数或任何 begin 或 end 函数, 更没有任何迭代器. 要让它配合 odeint 工作, 需要实现很多东西. 注意, 这里展示的所有工作都已包含在 odeint 中, 因此在 odeint 中使用 gsl_vector 不需要任何进一步调整. 我们在此仅将其作为教学示例呈现. 我们先从定义合适的构造函数和析构函数开始. 这是通过特化 state_wrapper (针对 gsl_vector) 完成的. 状态包装器 (state wrapper) 被步进器在内部用于创建和管理状态类型的临时实例:

template<>
struct state_wrapper< gsl_vector* >
{
    typedef double value_type;
    typedef gsl_vector* state_type;
    typedef state_wrapper< gsl_vector* > state_wrapper_type;

    state_type m_v;

    state_wrapper( )
    {
        m_v = gsl_vector_alloc( 1 );
    }

    state_wrapper( const state_wrapper_type &x )
    {
        resize( m_v , x.m_v );
        gsl_vector_memcpy( m_v , x.m_v );
    }


    ~state_wrapper()
    {
        gsl_vector_free( m_v );
    }

};

这个 state_wrapper 特化告诉 odeint gsl_vector 如何被创建、复制和销毁. 接下来需要调整大小, 这是必需的, 因为 gsl_vector 是动态大小的对象:

template<>
struct is_resizeable< gsl_vector* >
{
    typedef std::true_type type;
    const static bool value = type::value;
};

template <>
struct same_size_impl< gsl_vector* , gsl_vector* >
{
    static bool same_size( const gsl_vector* x , const gsl_vector* y )
    {
        return x->size == y->size;
    }
};

template <>
struct resize_impl< gsl_vector* , gsl_vector* >
{
    static void resize( gsl_vector* x , const gsl_vector* y )
    {
        gsl_vector_free( x );
        x = gsl_vector_alloc( y->size );
    }
};

到目前为止, 我们定义了创建/析构和调整大小, 但 gsl_vector 也不支持迭代器, 所以我们先实现一个 gsl 迭代器:

/*
 * defines an iterator for gsl_vector
 */
class gsl_vector_iterator
      : public boost::iterator_facade< gsl_vector_iterator , double ,
                                       boost::random_access_traversal_tag >
{
public :

    gsl_vector_iterator( void ): m_p(0) , m_stride( 0 ) { }
    explicit gsl_vector_iterator( gsl_vector *p ) : m_p( p->data ) , m_stride( p->stride ) { }
    friend gsl_vector_iterator end_iterator( gsl_vector * );

private :

    friend class boost::iterator_core_access;
    friend class const_gsl_vector_iterator;

    void increment( void ) { m_p += m_stride; }
    void decrement( void ) { m_p -= m_stride; }
    void advance( ptrdiff_t n ) { m_p += n*m_stride; }
    bool equal( const gsl_vector_iterator &other ) const { return this->m_p == other.m_p; }
    bool equal( const const_gsl_vector_iterator &other ) const;
    double& dereference( void ) const { return *m_p; }

    double *m_p;
    size_t m_stride;
};

迭代器的 const 版本存在类似的类. 然后我们有一个返回尾迭代器的函数 (const 同样如此):

gsl_vector_iterator end_iterator( gsl_vector *x )
{
    gsl_vector_iterator iter( x );
    iter.m_p += iter.m_stride * x->size;
    return iter;
}

最后, 添加 Boost.Range 的绑定:

// template<>
inline gsl_vector_iterator range_begin( gsl_vector *x )
{
    return gsl_vector_iterator( x );
}

// template<>
inline gsl_vector_iterator range_end( gsl_vector *x )
{
    return end_iterator( x );
}

const 版本也有类似的定义. 这最终使 odeint 能够以 gsl 向量作为状态类型工作. 这些绑定的完整代码见 gsl_wrapper.hpp. 它看起来可能相当复杂, 但请记住 gsl 是一个预编译的 C 库.

向量空间代数

如上所述, 在 odeint 中对类容器状态类型执行代数运算的标准方式是遍历容器的元素, 并在底层值类型上逐元素执行运算. 这是通过 range_algebra 实现的, 它使用 Boost.Range 来获取状态类型的迭代器. 不过, 还有其他方式可以在容器上实现代数运算, 其中之一是直接为容器定义加法/乘法运算符, 然后使用 vector_space_algebra. 如果你使用这种代数, 必须为 state_type 定义以下运算符:

点类型

这里我们展示如何在状态类型上实现所需的运算符. 作为示例, 我们定义一个新类 point3D, 表示具有 x,y,z 分量的三维向量, 并为它定义加法和标量乘法运算符. 我们使用 Boost.Operators 来减少需要编写的代码量. 点类型的类如下所示:

class point3D :
    boost::additive1< point3D ,
    boost::additive2< point3D , double ,
    boost::multiplicative2< point3D , double > > >
{
public:

    double x , y , z;

    point3D()
        : x( 0.0 ) , y( 0.0 ) , z( 0.0 )
    { }

    point3D( const double val )
        : x( val ) , y( val ) , z( val )
    { }

    point3D( const double _x , const double _y , const double _z  )
        : x( _x ) , y( _y ) , z( _z )
    { }

    point3D& operator+=( const point3D &p )
    {
        x += p.x; y += p.y; z += p.z;
        return *this;
    }

    point3D& operator*=( const double a )
    {
        x *= a; y *= a; z *= a;
        return *this;
    }

};

通过从 Boost.Operators 的类派生, 我们不必定义 operator+( point3D , point3D ) 之类的外部类运算符, 因为 operators 库已经处理好了. 注意, 对于简单的 Runge-Kutta 格式 (如 runge_kutta4), 只需要 + 和 * 运算符. 但如果使用受控步进器, 还需要指定除法运算符 /, 因为误差项的计算涉及状态类型的逐元素除法. 此外, 受控步进器还需要一个 abs 函数来计算状态类型的逐元素绝对值:

// only required for steppers with error control
point3D operator/( const point3D &p1 , const point3D &p2 )
{
    return point3D( p1.x/p2.x , p1.y/p2.y , p1.z/p2.z );
}

point3D abs( const point3D &p )
{
    return point3D( std::abs(p.x) , std::abs(p.y) , std::abs(p.z) );
}

最后, 我们必须提供一个特化, 用于计算状态的无穷范数:

// also only for steppers with error control
namespace boost { namespace numeric { namespace odeint {
template<>
struct vector_space_norm_inf< point3D >
{
    typedef double result_type;
    double operator()( const point3D &p ) const
    {
        using std::max;
        using std::abs;
        return max( max( abs( p.x ) , abs( p.y ) ) , abs( p.z ) );
    }
};
} } }

同样注意, 只有在你想使用受控步进器时才需要最后两步. 对于简单步进器, 只需定义简单的 += 和 *= 运算符即可. 定义了这样的点类型之后, 我们就可以在步进器的模板参数列表中显式配置 vector_space_algebra, 轻松对 Lorenz 系统执行积分:

const double sigma = 10.0;
const double R = 28.0;
const double b = 8.0 / 3.0;

void lorenz( const point3D &x , point3D &dxdt , const double t )
{
    dxdt.x = sigma * ( x.y - x.x );
    dxdt.y = R * x.x - x.y - x.x * x.z;
    dxdt.z = -b * x.z + x.x * x.y;
}

using namespace boost::numeric::odeint;

int main()
{

    point3D x( 10.0 , 5.0 , 5.0 );
    // point type defines it's own operators -> use vector_space_algebra !
    typedef runge_kutta_dopri5< point3D , double , point3D ,
                                double , vector_space_algebra > stepper;
    int steps = integrate_adaptive( make_controlled<stepper>( 1E-10 , 1E-10 ) , lorenz , x ,
                                    0.0 , 10.0 , 0.1 );
    std::cout << x << std::endl;
    std::cout << "steps: " << steps << std::endl;
}

完整示例见 lorenz_point.cpp

注释

对于大多数 state_types, odeint 能够自动确定正确的代数和运算. 但如果你想使用自己的 state_type, 如本例中配合 point3D 的情形, 就必须手动配置正确的代数/运算, 除非你的 state_type 可以配合 range_algebra 和 default_operations 的默认选择工作.
