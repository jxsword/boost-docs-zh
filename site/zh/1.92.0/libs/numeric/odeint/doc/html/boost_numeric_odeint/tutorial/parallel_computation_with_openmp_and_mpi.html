OpenMP 与 MPI 并行计算

OpenMP
MPI
概念

由于如今多核 (甚至在笔记本电脑上) 非常普及, 并行化是现代数值库的一项关键特性. odeint 目前支持 OpenMP 和 MPI 并行化, 将在以下小节中介绍. 不过, 首先应当明确: 在多核/多机上高效分配 ODE 积分的难点在于系统函数的并行化, 这仍然是用户的职责. 仅仅使用并行的 odeint 后端而不对系统函数做并行化, 几乎不会带来任何性能提升.

OpenMP

odeint 的 OpenMP 支持以外部后端的形式实现, 需要手动包含. 视编译器而定, 可能需要一些额外的编译标志, 例如 GCC 的 -fopenmp.

#include <omp.h>
#include <boost/numeric/odeint.hpp>
#include <boost/numeric/odeint/external/openmp/openmp.hpp>

在最简单的 OpenMP 并行化方案中, 我们使用标准的 vector 作为状态类型:

typedef std::vector< double > state_type;

我们用一些随机数据初始化状态:

size_t N = 131101;
state_type x( N );
boost::random::uniform_real_distribution<double> distribution( 0.0 , 2.0*pi );
boost::random::mt19937 engine( 0 );
generate( x.begin() , x.end() , boost::bind( distribution , engine ) );

现在必须配置步进器以使用 OpenMP 后端. 具体做法是显式提供 openmp_range_algebra 作为步进器的模板参数. 该代数要求状态类型是 Random Access Range 的模型, 并会被多个线程使用.

typedef runge_kutta4<
                  state_type , double ,
                  state_type , double ,
                  openmp_range_algebra
                > stepper_type;

除了为步进器提供 OpenMP 并行化之外, 我们还需要一个并行化的系统函数来利用可用内核. 这里以一个最近邻耦合的简单一维相位振子链为例展示:

struct phase_chain
{
    phase_chain( double gamma = 0.5 )
    : m_gamma( gamma ) { }

    void operator()( const state_type &x , state_type &dxdt , double /* t */ ) const
    {
        const size_t N = x.size();
        #pragma omp parallel for schedule(runtime)
        for(size_t i = 1 ; i < N - 1 ; ++i)
        {
            dxdt[i] = coupling_func( x[i+1] - x[i] ) +
                      coupling_func( x[i-1] - x[i] );
        }
        dxdt[0  ] = coupling_func( x[1  ] - x[0  ] );
        dxdt[N-1] = coupling_func( x[N-2] - x[N-1] );
    }

    double coupling_func( double x ) const
    {
        return sin( x ) - m_gamma * ( 1.0 - cos( x ) );
    }

    double m_gamma;
};

注释

在 OpenMP 后端中, 系统函数总是由启动积分的线程顺序调用.

最后, 我们使用 odeint 的某个 integrate 函数执行积分. 可以看到, 并行化完全隐藏在步进器和系统函数之中. OpenMP 会负责在线程间分配工作并自动汇合.

integrate_n_steps( stepper_type() , phase_chain( 1.2 ) ,
                   x , 0.0 , 0.01 , 100 );

积分完成后, 数据可以立即访问并做进一步处理. 注意, 你可以在程序开头调用 omp_set_schedule 来指定 OpenMP 调度方式:

int chunk_size = N/omp_get_max_threads();
omp_set_schedule( omp_sched_static , chunk_size );

完整示例见 openmp/phase_chain.cpp.

拆分状态

对于高级场景, odeint 提供了另一种使用 OpenMP 的方式, 可以更精确地控制并行化. 例如, 对于奇数大小的数据, OpenMP 的线程边界与缓存行不匹配会损害性能, 此时建议把数据从连续的 vector<T> 复制到单独的、各自对齐的向量中. 为此, odeint 提供了 openmp_state<T> 类型, 它本质上是 vector<vector<T>> 的别名.

这里, 初始化用一个 vector<double> 完成, 然后我们使用 odeint 的 split 函数填充一个 openmp_state. 拆分方式使各子区域的大小至多相差 1, 以使计算尽可能均匀.

const size_t N = 131101;
vector<double> x( N );
boost::random::uniform_real_distribution<double> distribution( 0.0 , 2.0*pi );
boost::random::mt19937 engine( 0 );
generate( x.begin() , x.end() , boost::bind( distribution , engine ) );
const size_t blocks = omp_get_max_threads();
state_type x_split( blocks );
split( x , x_split );

当然, 系统函数必须改为处理 openmp_state. 注意, 状态的每个子区域在单个任务中计算, 但在边界处需要对相邻区域的读访问.

struct phase_chain_omp_state
{
    phase_chain_omp_state( double gamma = 0.5 )
    : m_gamma( gamma ) { }

    void operator()( const state_type &x , state_type &dxdt , double /* t */ ) const
    {
        const size_t N = x.size();
        #pragma omp parallel for schedule(runtime)
        for(size_t n = 0 ; n < N ; ++n)
        {
            const size_t M = x[n].size();
            for(size_t m = 1 ; m < M-1 ; ++m)
            {
                dxdt[n][m] = coupling_func( x[n][m+1] - x[n][m] ) +
                             coupling_func( x[n][m-1] - x[n][m] );
            }
            dxdt[n][0] = coupling_func( x[n][1] - x[n][0] );
            if( n > 0 )
            {
                dxdt[n][0] += coupling_func( x[n-1].back() - x[n].front() );
            }
            dxdt[n][M-1] = coupling_func( x[n][M-2] - x[n][M-1] );
            if( n < N-1 )
            {
                dxdt[n][M-1] += coupling_func( x[n+1].front() - x[n].back() );
            }
        }
    }

    double coupling_func( double x ) const
    {
        return sin( x ) - m_gamma * ( 1.0 - cos( x ) );
    }

    double m_gamma;
};

使用 openmp_state<T> 状态类型会自动选择 openmp_algebra, 它在并行区域上执行 odeint 的内部计算. 因此无需手动配置步进器. 积分结束时, 我们使用 unsplit 把各子区域重新拼接成单个向量.

integrate_n_steps( runge_kutta4<state_type>() , phase_chain_omp_state( 1.2 ) ,
                   x_split , 0.0 , 0.01 , 100 );
unsplit( x_split , x );

注释

对于高级用例, 你其实不需要使用 openmp_state<T>, openmp_algebra 只是 openmp_nested_algebra<range_algebra> 的别名, 它支持任何 Random Access Range 模型作为外层并行状态类型, 并对元素使用给定的代数.

完整示例见 openmp/phase_chain_omp_state.cpp.

MPI

要将并行计算扩展到多台机器, 可以使用 MPI.

系统函数的实现与拆分数据的 OpenMP 变体类似, 主要区别在于: OpenMP 使用 spawn/join 模型, 所有未显式并行化的部分只在主线程中执行; 而 MPI 的模型中每个节点独立进入 main() 方法, 依据其 rank 分道执行, 并通过消息传递和显式屏障同步.

odeint 的 MPI 支持同样以外部后端的形式实现. 视 MPI 实现而定, 代码可能需要用例如 mpic++ 编译.

#include <boost/numeric/odeint.hpp>
#include <boost/numeric/odeint/external/mpi/mpi.hpp>

我们不是读取其他线程的数据, 而是异步地向相邻节点发送和接收相关数据, 并在此期间执行一些计算以隐藏延迟.

struct phase_chain_mpi_state
{
    phase_chain_mpi_state( double gamma = 0.5 )
    : m_gamma( gamma ) { }

    void operator()( const state_type &x , state_type &dxdt , double /* t */ ) const
    {
        const size_t M = x().size();
        const bool have_left = x.world.rank() > 0,
                   have_right = x.world.rank() < x.world.size()-1;
        double x_left, x_right;
        boost::mpi::request r_left, r_right;
        if( have_left )
        {
            x.world.isend( x.world.rank()-1 , 0 , x().front() ); // send to x_right
            r_left = x.world.irecv( x.world.rank()-1 , 0 , x_left ); // receive from x().back()
        }
        if( have_right )
        {
            x.world.isend( x.world.rank()+1 , 0 , x().back() ); // send to x_left
            r_right = x.world.irecv( x.world.rank()+1 , 0 , x_right ); // receive from x().front()
        }
        for(size_t m = 1 ; m < M-1 ; ++m)
        {
            dxdt()[m] = coupling_func( x()[m+1] - x()[m] ) +
                        coupling_func( x()[m-1] - x()[m] );
        }
        dxdt()[0] = coupling_func( x()[1] - x()[0] );
        if( have_left )
        {
            r_left.wait();
            dxdt()[0] += coupling_func( x_left - x().front() );
        }
        dxdt()[M-1] = coupling_func( x()[M-2] - x()[M-1] );
        if( have_right )
        {
            r_right.wait();
            dxdt()[M-1] += coupling_func( x_right - x().back() );
        }
    }

    double coupling_func( double x ) const
    {
        return sin( x ) - m_gamma * ( 1.0 - cos( x ) );
    }

    double m_gamma;
};

与 openmp_state<T> 类似, 我们使用 mpi_state< InnerState<T> >, 它自动选择 mpi_nested_algebra 以及合适的 MPI 无关内层代数 (由于我们的内层状态是 vector, 内层代数将与 OpenMP 示例中一样是 range_algebra).

typedef mpi_state< vector<double> > state_type;

在主程序中, 我们构造一个 communicator, 它告诉我们集群的 size 以及当前节点在其内的 rank. 我们只在主节点上生成输入数据, 避免在其他节点上做不必要的工作. split 在这里充当 MPI 集合函数, 而不是简单地复制数据块, 它把区域从主节点发送/接收到每个从节点. 该输入参数在从节点上被忽略, 但主节点会在其输出中接收一个区域并参与计算.

boost::mpi::environment env( argc , argv );
boost::mpi::communicator world;

const size_t N = 131101;
vector<double> x;
if( world.rank() == 0 )
{
    x.resize( N );
    boost::random::uniform_real_distribution<double> distribution( 0.0 , 2.0*pi );
    boost::random::mt19937 engine( 0 );
    generate( x.begin() , x.end() , boost::bind( distribution , engine ) );
}

state_type x_split( world );
split( x , x_split );

现在 x_split 包含 (仅) 每个节点的本地数据块, 我们开始积分.

为了在主节点上打印结果, 我们使用 unsplit 把处理后的数据发回.

integrate_n_steps( runge_kutta4<state_type>() , phase_chain_mpi_state( 1.2 ) ,
                   x_split , 0.0 , 0.01 , 100 );
unsplit( x_split , x );

注释

mpi_nested_algebra::for_eachN 不使用任何 MPI 构造, 它只是对本地数据块调用内层代数, 系统函数也不受任何屏障保护, 因此如果你不手动放置屏障 (例如在参数研究中各元素完全独立的情形), 你可能会看到各节点分道执行, 在不同时刻从这个调用返回.

完整示例见 mpi/phase_chain.cpp.

    static void split( const Container1 &from , Container2 &to );

    static void unsplit( const Container2 &from , Container1 &to );
