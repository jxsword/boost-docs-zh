概述

欢迎使用 Boost.Statechart, 一个用于有限状态机的 C++ 库. 特性包括:

  • UML 状态图与可执行 C++ 代码之间的直接转换. 目前两个方向都需要手工完成, 但将这些任务自动化应该不难
  • 全面的 UML 语义支持:
    • 层次化 (复合、嵌套) 状态
    • 正交 (并发) 状态
    • 进入、退出与转换动作
    • 守卫 (guard)
    • 浅历史/深历史
    • 事件延迟
  • 错误处理支持
  • 最大程度的类型安全
  • 编译期状态图校验
  • 支持异步状态机与多线程
  • 状态局部存储
  • 泛型设计, 允许定制内存管理、错误处理和线程机制

支持的平台

Boost.Statechart 能否在您的平台上工作以及如何工作, 最好在 状态页上确认. 如果您所用编译器那一列的单元格全为绿色, 库应能如宣传的那样工作. 其他颜色的单元格表示可能存在问题, 详情请点击链接. 在启用本库之前, 我还建议在您的特定平台上、以后续开发中会用到的所有模式 (debug、release 等) 下运行测试 (见 入门) (状态页只显示 debug 模式的结果). 测试所用编译器开关与后续开发中使用的越接近, 以后遇到意外的可能性就越小. 这类意外的一个例子是 Intel 9.0 配 MSVC 7.1 基础工具集: DllTestNormal 和 DllTestNative 在 debug 模式下通过, 在 release 模式下却失败.

Getting started

  1. 按照 Boost 入门页面所述的步骤 1-4 操作. 由于 Boost.Statechart 是仅头文件库, 完成后您应该已经掌握足够信息, 可以在自己喜欢的环境中编译教程中的示例 (PingPong 除外, 它需要 Boost.Thread 二进制文件)
  2. 可选: 如果要编译 PingPong 示例或在项目中使用 fifo_scheduler<>, 需要取得 Boost.Thread 二进制文件并与之链接, 见 Boost 入门页面的步骤 5-6
  3. 可选: 如果要运行测试, 需要按 Boost 入门页面步骤 5.2 所述取得 bjam 可执行文件. 完成后, bjam 应已安装在您的 PATH 中. 打开命令提示符, 将当前目录切换到 boost_1_38_0/libs/statechart/test. 输入 
    bjam --toolset=your-toolset

    (其中 your-toolset 是 Boost 入门页面步骤 5.2.2 所述的名称之一) 并按回车. 测试运行结束后, 失败项 (如有) 会在输出末尾以 "...failed updating X targets..." 消息的形式标出. 某些平台预期会有某些失败项, 见 支持的平台.

读者

整个 Boost.Statechart 文档都假定读者熟悉状态机概念、UML 状态图以及大部分 UML 状态机术语. 如果不熟悉, 以下链接可能有用:

  • http://www.objectmentor.com/resources/articles/umlfsm.pdf 介绍状态机与 UML 状态图
  • http://www.sts.tu-harburg.de/teaching/ws-99.00/OOA+D/StateDiagrams.pdf 讲解了大部分 UML 状态图元素与术语
  • 状态图的发明者 David Harel 在其原始论文中给出了透彻而依然易读的论述: http://www.wisdom.weizmann.ac.il/~dharel/SCANNED.PAPERS/Statecharts.pdf
  • UML 规范 (正式版) 见 http://www.omg.org/cgi-bin/doc?formal/03-03-01 (参见第 2.12 和 3.74 章)

部分所用术语在 UML 规范中找不到, 更多信息请参见 术语定义.
