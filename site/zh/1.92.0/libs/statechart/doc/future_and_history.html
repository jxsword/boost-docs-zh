待办清单

本库已基本完成, 但还有一些工作待做 (红色 = 正式评审后新增的条目):

  1. 实现一个类似选择点 (choice point) 的类, 讨论见 此帖
  2. 优化状态进入与状态退出, 提升速度并减小代码体积
  3. 重新实现 fifo_scheduler<>::processor_handle, 使 fifo_scheduler<>::create_processor<>() 和 fifo_scheduler<>::destroy_processor() 不再 (间接) 调用全局的 operator new() 和 operator delete()
  4. 确保所有内容都可在关闭 C++ RTTI 支持的情况下编译 (这需要 Boost.Config 目前尚缺的支持, 并且可能需要给 shared_ptr 打补丁)
  5. 当 C++ RTTI 被关闭而 BOOST_STATECHART_USE_NATIVE_RTTI 又被定义时报错
  6. 目前要求传入一个 mpl::list<> 来指定内层初始状态和反应, 这过于严格. 请检查对序列的要求并相应地写入文档 (David Abrahams)
  7. 用 mpl::vector 和 mpl::deque 代替 mpl::list 进行编译性能测量, 找出最快的一个. 把推荐的最快容器写入文档, 并相应修改所有示例 (David Abrahams)
  8. 研究状态机如何序列化. 对序列化 (serialization) 库的初步考察表明, 目前 (1.33) 还不支持重载了 operator new 的类型 (相应的代码已在序列化库中存在, 但由于与某些编译器不兼容而暂时被注释掉). 这种支持对 Boost.Statechart 的序列化至关重要
  9. 实现一个类似 switch 的反应 (Simon Gittins, Darryl Green)
  10. 在教程中, 把不完整的代码片段链接到可用的完整示例代码
  11. 在适当之处, 将参考文档链接到示例
  12. 增加实现描述, 更好地解释性能权衡 (Jonathan Turkanis)
  13. 增加指向其他实现描述的链接, 并讨论性能权衡 (Jonathan Turkanis)
  14. 增加使用 Boost.Statechart 的应用列表 (Paul A. Bristow)
  15. 重构 state_machine 类模板, 以减小包含许多不同状态机的应用程序的代码体积
  16. 增加一幅有助于理解何为不稳定状态机的图
  17. 为大量使用 MPL 的代码添加注释
  18. 增加常见错误的示例
  19. 实现 priority_scheduler<>
  20. 利用 Pavel Vozenilek 提交的 PP 代码消除 fifo_scheduler 中的代码重复
  21. 为文档中的所有图添加编号和标签
  22. 为所有头文件添加 #pragma once (可加快 MS 兼容编译器的编译速度)
  23. 研究 fifo_worker<> 是否应该以及如何接受一个定义锁定与等待方式的策略参数

  • 修复了一个与分配器有关的缺陷, 该缺陷在 GCC >= 4.0 上导致许多测试出现编译错误
  • 修复了在 Intel 9.0 和 Code Warrior 上导致编译失败的若干问题

  • 新增关于 UML2.0 符合性的常见问题条目
  • 使 unconsumed_event 的文档更显眼
  • 为 GCC 声明了 state_base::~state_base virtual. 这使状态退出略微变慢, 但消除了大量 has virtual functions but non-virtual destructor 警告

  • 整理了所有 html 文件, 校验工具为 http://validator.w3.org/
  • 修复了失效链接

  • 修正了关于状态与事件分配的文档

17 December, 2005

  • 在性能文档中加入了详细的性能数据
  • 新增 Performance 示例及其配套的 Performance.xls, 二者用于进行更详细的测量并绘制相应图表, 这些图表现已收录在性能文档中
  • 简化了 BitMachine 示例 (不再需要性能测量函数)
  • 移除了由 David Abrahams, Jonathan Turkanis, Rob Steward 和 Dave Gomboc 建议的待办事项 (研究如何为非正交状态机实现常数时间分派). 更详细的性能测量表明, 与花在状态进入和状态退出上的时间相比, 花在事件分派上的时间几乎总是很小. 更多信息见性能文档中的 速度与可扩展性权衡
  • 修复了一个声明顺序缺陷, 该缺陷导致在 HP-UX 上用 GCC3.4.2 编译时 event_base.hpp 出现编译期错误 (该错误在 MinGW 上的 GCC3.4.2 和 MSVC7.1 上均未出现)
  • 用 boost 发行包 1.33.1 版进行了测试

14 August, 2005

  • 本发布只能与 boost 发行包 1.33.0 版配合使用
  • 破坏性变更: 将 simple_state<>::operator new 和 simple_state<>::operator delete 的转发添加给传给 state_machine 的分配器 (Peter Petrov). 这大大简化了内存管理的定制. 现在用户只需把自己的分配器传给 state_machine<>, 不再需要为状态类单独重载 operator new/delete. 未定制内存管理的既有状态类将自动使用传给 state_machine<> 的分配器. 以 operator new/delete 被 直接重载的既有状态类将继续照常工作. 既有代码拒绝编译的唯一情形是: 状态类继承自一个重载了 operator new/delete 的附加基类 (会导致调用歧义错误). 需要为此类状态类添加转发函数 (示例见 BitMachine)
  • 破坏性变更: 为 event 类模板增加了 Allocator 参数, 并新增了 event<>::operator new/delete. 这使内存管理定制更容易, 但也可能破坏既有代码 (见前一条)
  • 新增了 Jamfile.v2 文件
  • 为所有反应添加了 event_base 特化, 并相应更新了参考文档. 这使得可以实现由任意类型事件触发的反应
  • 新增一项设施, 可对未触发反应的事件进行特殊处理. 更多信息参见 process_event() 效果说明的第 10 点. 相应更新了测试与文档
  • 新增常见问题条目, 解释如何排查编译期错误 (John Spalding)
  • 新增常见问题条目, 给出不用状态局部存储的 StopWatch 变体代码, 并解释了该做法的缺点 (Jeff Garland, Rob Steward)
  • 新增常见问题条目, 解释动态链接状态机的陷阱. 还添加了相关测试, 以探明 FSM 能否放入 DLL 以及如何放入
  • 移除了 Jonathan Turkanis 建议的待办事项 (消除把单个模板化内层初始状态包进 mpl::list<> 的必要性), 因为目前我看不到不借助大型丑陋变通方案而实现它的办法. 问题描述见: http://thread.gmane.org/gmane.comp.lib.boost.devel/128741
  • 把关于代码的所有说明作为注释放入代码内 (Pavel Vozenilek, Augustus Saunders)
  • 在合适的平台上, 本库现在应能在关闭异常支持的情况下编译 (由于没有此类平台的访问条件, 未经测试)
  • 为有缺陷的标准库添加了分配器支持. 感谢 Joaquín M López Muñoz 将其分配器变通方案加入 boost/detail

  • 修复了一个缺陷: 在不稳定状态机中, exception_thrown 事件可能被发送到一个 并非最外层不稳定状态的状态 (按参考文档的规定). 此前, 事件被发送到其直接内层状态的进入动作抛出异常的那个状态, 这只对没有正交区域的状态机才是正确的. 还更新了教程中的 异常处理一节, 现在详细解释了这一行为
  • 修复了一个缺陷: 在极少数情况下, 会阻止对内存不足情况的正确处理

  • 更改了 state_machine::terminate() 的实现, 使正交区域现在严格按照编号从高到低退出, 而不像以前那样任意退出. 相应更新了文档
