Scheduler 概念

一个 Scheduler 类型定义以下内容:

  • 传给 event_processor<> 子类型构造函数的是什么, 以及这些对象的生存期如何管理
  • 多个 event_processor<> 子类型对象能否共享同一个队列和调度器线程
  • 事件如何加入调度器的队列
  • 当调度器队列清空时, 是否等待以及如何等待新事件
  • 是否加锁以及用何种类型的锁来确保线程安全
  • 能否为已不存在的 event_processor<> 子类型对象排队事件, 以及处理这类事件时会发生什么
  • 当被服务的一个 event_processor<> 子类型对象传播异常时会发生什么

对于一个 Scheduler 类型 S 和一个对象 cpc (其类型为 const S::processor_context), 下列表达式必须良构并具有所指结果:

表达式 类型 结果
cpc.my_scheduler() S & 对调度器的引用
cpc.my_handle() S::processor_handle 标识 event_processor<> 子类型对象的句柄

为防止滥用, S::processor_context 的所有成员都应声明为 private. 因此, event_processor<> 必须是 S::processor_context 的友元.

FifoWorker 概念

一个 FifoWorker 类型定义以下内容:

  • 当内部工作队列清空时, 是否等待以及如何等待新工作项
  • 是否加锁以及用何种类型的锁来确保线程安全

对于 FifoWorker 类型 F、该类型的一个对象 f、该类型的一个 const 对象 cf、任意类型的无参函数对象 w 以及一个 unsigned long 值 n, 下列表达式/语句必须良构并具有所指结果:

表达式/语句 类型 效果/结果
F::work_item boost::function0< void >  
F() or F( false ) F 构造 FifoWorker 类型的 非阻塞 (见下) 对象. 在单线程构建中, 第二个表达式不是良构的
F( true ) F 构造 FifoWorker 类型的 阻塞 (见下) 对象. 在单线程构建中不是良构的
f.queue_work_item( w );   构造一个 F::work_item 类型的对象并加入队列, 以 w 作为唯一实参
f.terminate();   创建一个 F::work_item 类型的对象并加入队列, 该对象稍后在 operator()() 中执行时, 会修改内部状态, 使得 terminated() 从此返回 true
cf.terminated(); bool true 若已调用 terminate() 且相应工作项已在 operator()() 中执行; 否则返回 false

唯一允许的调用线程是同时也调用 operator()()
f( n ); unsigned long 进入一个循环, 每轮从队列中出队最旧的工作项并对其调用 operator()().

若满足以下一个或多个条件, 则退出循环并返回已执行的工作项数:

  • f.terminated() == true
  • 应用程序是单线程的, 且内部队列为空
  • 应用程序是多线程的, 内部队列为空, 且 worker 创建为非阻塞
  • n != 0 且自调用 operator()() 以来已处理的工作项数等于 n

若队列为空且上述条件都不满足, 则调用 operator()() 的线程进入等待状态, 直到另一个线程调用 f.queue_work_item().

只能恰好从一个线程调用
f(); unsigned long 与 f( n ); 带 n == 0 时 (见上) 的语义完全相同

ExceptionTranslator 概念

一个 ExceptionTranslator 类型定义状态机运行期间发生的 C++ 异常如何转换为异常事件.

对于一个 ExceptionTranslator 对象 et、一个任意类型的无参函数对象 a (返回 result), 以及一个任意类型的函数对象 eh (接受 const event_base & 参数, 返回 result), 下列表达式必须良构并具有所指结果:

表达式 类型 效果/结果
et( a, eh ); result
  1. 尝试执行 return a();
  2. 若 a() 传播异常, 则捕获该异常
  3. 在 catch 块内调用 eh, 传入一个合适的、栈上分配的 Event 概念模型
  4. 返回值来自 eh

StateBase 概念

一个 StateBase 类型是给定状态机类型所有状态的公共基类. state_machine<>::state_base_type 是 StateBase 概念的一个模型.

对于一个 StateBase 类型 S 和该类型的一个 const 对象 cs, 下列表达式必须良构并具有所指结果:

表达式 类型 结果
cs.outer_state_ptr() const S * 0, 若 cs 是 最外层状态; 否则为指向 cs 直接外层状态的指针
cs.dynamic_type() S::id_type 一个无歧义标识 cs 最派生类型的值. S::id_type 值可与 operator==() 和 operator!=() 比较. 可以用 std::less< S::id_type > 建立一种未指定的排序次序. 与 typeid( cs ) 不同, 即使在不支持 C++ RTTI (或被配置为不支持) 的平台上, 该函数仍然可用
cs.custom_dynamic_type_ptr<
  Type >()		 const Type * 指向自定义类型标识符的指针, 或 0. 若 != 0, 则 Type 必须与先前设置的指针类型匹配. 该函数仅在未定义 BOOST_STATECHART_USE_NATIVE_RTTI 时可用

一个 SimpleState 类型定义特定状态机的一个状态.

对于一个 SimpleState 类型 S 和一个指针 pS (指向 S 类型对象, 该对象以 new 分配), 下列表达式/语句必须良构并具有所指效果/结果:

表达式/语句 类型 效果/结果/注释
state< S, C, I, h > *
  pB = pS;		   state< S, C, I, h > 必须是 S 的无歧义公有基类. 参见 state<> 文档了解以下各项的要求与语义: C、I 与 h
new S( mc ) S * 进入状态 S. 对可从 S::S() 中调用的函数没有任何限制 (与 SimpleState 概念模型的构造函数不同). mc 必须转发给 state< S, C, I, h >::state()

表达式/语句 类型 效果/结果/注释
const event< E > * pCB = pCE;   event< E > 必须无歧义地公有派生自 E
new E( *pCE ) E * 复制 pE

类模板 state_machine 概要

namespace boost
{
namespace statechart
{
  template<
    class MostDerived,
    class InitialState,
    class Allocator = std::allocator< void >,
    class ExceptionTranslator = null_exception_translator >
  class state_machine : noncopyable
  {
    public:
      typedef MostDerived outermost_context_type;

      void initiate();
      void terminate();
      bool terminated() const;

      void process_event( const event_base & );

      template< class Target >
      Target state_cast() const;
      template< class Target >
      Target state_downcast() const;

      // a model of the StateBase concept
      typedef implementation-defined state_base_type;
      // a model of the standard Forward Iterator concept
      typedef implementation-defined state_iterator;

      state_iterator state_begin() const;
      state_iterator state_end() const;

      void unconsumed_event( const event_base & ) {}

    protected:
      state_machine();
      ~state_machine();

      void post_event(
        const intrusive_ptr< const event_base > & );
      void post_event( const event_base & );

      const event_base * triggering_event() const;
  };
}
}

类模板 state_machine 构造函数与析构函数

state_machine();

效果: 构造一个未运行的状态机

~state_machine();

效果: 析构当前活动的外层状态及其所有直接和间接内层状态. 最内层状态最先析构. 其余状态在其所有直接和间接内层状态都析构后立即析构. 每个状态的内层状态按其正交区域编号析构: 编号最高的正交区域中的状态总是最先析构, 其次是编号次高的区域中的状态, 依此类推
注释: 不会尝试调用任何 exit 成员函数

类模板 state_machine 修改函数

void initiate();

效果:

  1. 调用 terminate()
  2. 构造一个函数对象 action, 其无参 operator()() 返回 result, 该函数对象
    1. 进入 (构造) 以 InitialState 模板参数指定的状态
    2. 按深度优先进入由 InitialState 的直接与间接内层初始状态构成的树. 每个状态的内层状态按其正交区域编号进入: 总是先进入 0 号正交区域中的状态, 然后是 1 号区域中的状态, 依此类推
  3. 构造一个函数对象 exceptionEventHandler, 其 operator()() 返回 result 并接受一个异常事件参数, 用于处理传入的异常事件, 与普通事件的处理有如下差异:
    • 从异常抛出之时起, 直到异常事件反应执行完毕之后, 需要退出的状态只会被析构, 而不会调用任何 exit 成员函数
    • 反应搜索的起点总是最外层的 不稳定状态
    • 与普通事件一样, 当前状态无法处理事件时, 反应搜索向外移动. 然而, 如果没有外层状态 (已到达 最外层状态), 反应搜索即视为失败. 也就是说, 异常事件绝不会分派给引起该异常事件的正交区域之外的其他正交区域
    • 若在异常事件反应搜索或反应执行期间抛出异常, 该异常会传播出 exceptionEventHandler 函数对象 (即 ExceptionTranslator 不用于转换处理异常事件时抛出的异常)
    • 若找不到针对异常事件的反应, 或处理异常事件后状态机不稳定, 则重新抛出原始异常. 否则, 返回一个 result 对象, 其值即 simple_state<>::discard_event()
  4. 把 action 和 exceptionEventHandler 传给 ExceptionTranslator::operator()(). 若 ExceptionTranslator::operator()() 抛出异常, 该异常传播给调用者. 若调用者捕获该异常, 则析构当前活动的外层状态及其所有直接和间接内层状态. 最内层状态最先析构. 其余状态在其所有直接和间接内层状态都析构后立即析构. 每个状态的内层状态按其正交区域编号析构: 编号最高的正交区域中的状态总是最先析构, 其次是编号次高的区域中的状态, 依此类推. 否则继续第 5 步 (返回值被丢弃)
  5. 处理所有已投递的事件 (见 process_event()). 若没有更多已投递事件, 则返回调用者

抛出: 从 ExceptionTranslator::operator()() 传播出的任何异常. 异常从不源于库本身, 只源于通过模板参数提供的代码:

  • Allocator::rebind<>::other::allocate()
  • 状态构造函数
  • react 成员函数
  • exit 成员函数
  • 转换动作

void process_event( const event_base & );

效果:

  1. 把传入的事件选为当前事件 (下文称 currentEvent)
  2. 开始一次新的 反应搜索
  3. 从所有当前活动的 最内层状态中任选一个本次反应搜索尚未访问过的状态. 若不存在这样的状态, 则继续第 10 步
  4. 构造一个函数对象 action, 其无参 operator()() 返回 result, 该函数对象执行以下操作:
    1. 从当前最内层状态开始向外搜索适合 currentEvent 的反应, 直到找到一个为该事件定义了反应的状态. 若未找到反应, 返回 simple_state<>::forward_event()
    2. 执行找到的反应. 若反应结果等于 simple_state<>::forward_event() 的返回值, 则恢复反应搜索 (步骤 a). 否则返回反应结果
  5. 构造一个函数对象 exceptionEventHandler, 它返回 result 并接受一个异常事件参数, 用于处理传入的异常事件, 与普通事件的处理有如下差异:
    • 从异常抛出之时起, 直到异常事件反应执行完毕之后, 需要退出的状态只会被析构, 而不会调用任何 exit 成员函数
    • 若处理异常事件时状态机是稳定的, 则异常事件反应搜索从上一次普通事件反应搜索中最后访问的最内层状态开始 (异常事件正是这次普通反应搜索产生的结果)
    • 若处理异常事件时状态机 不稳定, 则异常事件反应搜索的起点是最外层的 不稳定状态
    • 与普通事件一样, 当前状态无法处理事件时, 反应搜索向外移动. 然而, 如果没有外层状态 (已到达 最外层状态), 反应搜索即视为失败. 也就是说, 异常事件绝不会分派给引起该异常事件的正交区域之外的其他正交区域
    • 若在异常事件反应搜索或反应执行期间抛出异常, 该异常会传播出 exceptionEventHandler 函数对象 (即 ExceptionTranslator 不用于转换处理异常事件时抛出的异常)
    • 若找不到针对异常事件的反应, 或处理异常事件后状态机不稳定, 则重新抛出原始异常. 否则, 返回一个 result 对象, 其值即 simple_state<>::discard_event()
  6. 把 action 和 exceptionEventHandler 传给 ExceptionTranslator::operator()(). 若 ExceptionTranslator::operator()() 抛出异常, 该异常传播给调用者. 若调用者捕获该异常, 则析构当前活动的外层状态及其所有直接和间接内层状态. 最内层状态最先析构. 其余状态在其所有直接和间接内层状态都析构后立即析构. 每个状态的内层状态按其正交区域编号析构: 编号最高的正交区域中的状态总是最先析构, 其次是编号次高的区域中的状态, 依此类推. 否则继续第 7 步
  7. 若 ExceptionTranslator::operator()() 的返回值等于 simple_state<>::forward_event() 的返回值, 则继续第 3 步
  8. 若 ExceptionTranslator::operator()() 的返回值等于 simple_state<>::defer_event() 的返回值, 则把 currentEvent.intrusive_from_this() 的返回值存入被延迟事件队列. 继续第 11 步
  9. 若 ExceptionTranslator::operator()() 的返回值等于 simple_state<>::discard_event() 的返回值, 则继续第 11 步

类 result

定义在用户提供的 react 成员函数 (当执行 custom_reaction 时调用) 中所采取反应的性质. 此类型的对象总是通过调用某个反应函数获得, 并且必须由 react 成员函数立即返回.

namespace boost
{
namespace statechart
{
  class result
  {
    public:
      result( const result & other );
      ~result();

    private:
      // Result objects are not assignable
      result & operator=( const result & other );
  };
}
}

类 result 构造函数与析构函数

result( const result & other );

要求: other 未被消费
效果: 拷贝构造一个新的 result 对象, 并把 other 标记为已消费. 也就是说, result 具有破坏性拷贝语义
