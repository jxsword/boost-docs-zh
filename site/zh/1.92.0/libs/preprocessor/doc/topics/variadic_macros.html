变参宏

几乎所有编译器都支持变参宏. 变参宏是形如下式的宏:
#define SOME_MACRO(ZeroOrMoreParameters,...) macro expansion possible specifying __VA_ARGS__
参数列表中的 '...' 表示调用宏时的变参数据, 展开中的 __VA_ARGS__ 表示宏展开中的变参数据. 变参数据的形式是以逗号分隔的一个或多个预处理器记号.

'...' 必须是宏定义中的最后一个参数, 它前面可以有 0 个或多个非变参参数.

在宏的展开中, __VA_ARGS__ 可以出现 0 次或多次, 用来表示变参数据. 展开中的变参数据是一个以逗号分隔的预处理器记号列表, 代表宏的调用者作为宏的最后几个实参输入的变参数据.

示例 - 创建并调用一个变参宏.

#define INITIALIZE_INT_ARRAY(array_name,...) \ 
 static int array_name[] = { __VA_ARGS__ }; \ 
 /**/

 INITIALIZE_INT_ARRAY(myname,45,789,33510,9346,2)
Preprocessor 库支持
使用本库的所有编译器都要求支持变参宏. 这通常意味着 C 级编译为 C99 或更高, C++ 级编译为 C++11 或更高. 许多 C++ 编译器在 C++98/C++03 级别上也支持变参宏, 只要这些编译器在该级别上没有开启严格合规. 特别是 gcc 和 clang 两个编译器, 只要在该级别上没有开启严格的 ANSI 合规, 就会在 C++98/C++03 级别上支持变参宏. 对这些编译器而言, 这在很大程度上意味着在 C++98/C++03 编译级别上不使用 -pedantic 或 -pedantic-errors 选项. Boost C++ 正在弃用在 C++98/C++03 级别上编译 Boost 库的做法, 所以如果你必须在该级别上继续使用本库, 请注意上述告诫.

Visual C++ 的默认预处理器在变参宏方面有一些怪癖, 要求最终用户以略微不同的方式编写代码. 使用 Visual C++ 的默认预处理器时 BOOST_PP_VARIADICS_MSVC 为 1, 否则为 0. 这样, 最终用户就可以检测 Visual C++ 默认预处理器的存在并相应地编写代码.

对变参数据处理的支持主要集中于把变参数据转换为其他库数据类型的能力, 因为处理那些 Boost 预处理库数据类型的功能远比直接处理变参数据的功能丰富.

利用变参宏的扩展功能

库中的一些宏通过使用变参宏提供扩展功能.

变参宏版本之所以能提供扩展功能, 是因为变参参数能够涵盖数量可变的实参. 库具有能知道调用变参宏时传入的变参实参数量的功能. 这使同一个变参宏可以处理不同数量的参数, 因而为同一个宏名提供了不止一种语法等价形式.

库中提供这种增强功能的宏全部围绕 元组操作. 有了变参宏, 可以在不必知道元组大小的情况下操作元组. 因此, 虽然调用者在使用元组宏功能时仍可指定大小, 但每个元组宏都有无需指定大小的语法版本.

对变参数据的扩展支持

库为处理变参数据提供了扩展支持, 超出了 C++ 规范为变参宏提供的功能. 它通过预处理器编程以及使用库自身的一些其他功能来做到这一点.

库所提供的功能形式围绕两个直接处理变参数据的宏, 以及一组在变参数据与其他库数据类型之间进行转换的宏.

这两个宏是 BOOST_PP_VARIADIC_ELEM 和 BOOST_PP_VARIADIC_SIZE, 它们分别返回变参数据的特定记号和变参数据的记号数量.

用于把变参数据转换为库数据类型的宏是 BOOST_PP_VARIADIC_TO_ARRAY、BOOST_PP_VARIADIC_TO_LIST、BOOST_PP_VARIADIC_TO_SEQ 和 BOOST_PP_VARIADIC_TO_TUPLE.

其余四个宏把库数据类型转换为以逗号分隔的预处理器记号 (即变参数据的形式), 它们不使用变参宏. 这些函数是 BOOST_PP_ARRAY_ENUM、BOOST_PP_LIST_ENUM、BOOST_PP_SEQ_ENUM 和 BOOST_PP_TUPLE_ENUM. 你可以借助变参宏支持, 可靠地把这些变参数据用作其他宏的实参.

C++20 对变参宏的支持

C++20 规范中有一个可用于变参宏展开的新构造, 名为 __VA_OPT__. 该构造用于变参宏的展开中时, 后面跟着一个开圆括号 '('、预处理数据和一个闭圆括号 ')'. 当调用变参宏所传递的变参数据为空时, 这个新构造展开为空. 当调用变参宏所传递的变参数据不为空时, 这个新构造展开为其开闭圆括号之间的预处理数据.

本库对这一 C++20 新构造的支持方式是: 在使用本库时自动检测编译器的预处理器是否支持这个新构造. 检测 __VA_OPT__ 构造支持情况的库宏名为 BOOST_PP_VARIADIC_HAS_OPT. 它是一个无参的类函数宏, 若编译器工作在 C++20 模式且支持 __VA_OPT__ 构造则返回 1, 否则返回 0.

当 __VA_OPT__ 构造在 C++20 模式下受支持时, 传给各变参宏和 BOOST_PP_OVERLOAD 的变参数据可以为空; 否则, 在非此模式下, 传给变参宏的变参数据绝不应为空. 在此 C++20 模式下, 用空数据调用 BOOST_PP_VARIADIC_SIZE 展开为 0, 用空数据调用 BOOST_PP_VARIADIC_TO_ARRAY 展开为空数组 '(0,())', 用空数据调用 BOOST_PP_VARIADIC_TO_LIST 展开为空列表 'BOOST_PP_NIL', 用空数据调用 BOOST_PP_OVERLOAD 则会创建一个追加了 0 的重载名. 同样在此 C++20 模式下, 把空数组 '(0,())' 传给 BOOST_PP_ARRAY_ENUM 展开为空的变参数据, 把空列表 'BOOST_PP_NIL' 传给 BOOST_PP_LIST_ENUM 也展开为空的变参数据. seq 和元组都不能为空, 因此把空的变参数据传给 BOOST_PP_VARIADIC_TO_SEQ 或 BOOST_PP_VARIADIC_TO_TUPLE 都是错误的. 同样, 把空数据传给 BOOST_PP_VARIADIC_ELEM 总是错误的, 因为没有可访问的变参数据记号.
用元组代替数组
数组作为一种预处理器数据类型, 是一个二元素元组, 其中第一个元素是数组大小, 第二个元素是构成数组数据的元组. 由于编译器支持变参宏, 元组知道自己的大小, 因此没有理由使用数组预处理器数据类型而非元组预处理器数据类型; 元组数据类型现在拥有数组数据类型的全部功能, 且语法上更易使用. 对于现代 C++ 编译器而言, 预处理器数组数据类型实质上已经过时.
使用变参数据
变参数据以逗号分隔的预处理器记号的形式存在. 无论变参数据来自变参宏的 __VA_ARGS__, 来自库数据类型向变参数据的转换, 还是来自编写宏的程序员手工构造的逗号分隔预处理记号, 情况都是如此.

在内部处理变参数据最简单的方法是把它转换为库数据类型. 库数据类型——无论是 数组、列表、序列还是 元组——都拥有丰富的数据操作功能, 而库中的变参数据功能只允许把变参数据作为一个整体访问, 或一次访问变参数据的一个记号.

库的用户仍然可以选择把变参数据传回内部宏, 而不是把它转换为其他库数据类型. 把变参数据整体作为宏的最后一个参数传给变参宏没有任何问题. 但是:

试图把变参数据整体直接传入非变参宏不保证可行, 可能失败.

这是由一些编译器的预处理器缺陷造成的, 目前最突出的是 Visual C++ 的默认预处理器. 即使把变参数据作为实参传给非变参宏, 当它不是以 __VA_ARGS__ 的形式表示时, 在某些编译器上也可能失败.

下面是非常简单的示例, 展示如何把变参数据传给非变参宏.

首先是一个不应这样做的示例.

示例 - 把变参数据整体传给非变参宏. 切勿这样做.

#define MACRO_ARG_2(x,y) BOOST_PP_ADD(x,y)
#define VAR_MACRO(...) __VA_ARGS__

/* The following should not be done and is not guaranteed to work with compilers. */

int xx = MACRO_ARG_2(VAR_MACRO(2,3));
有两种方法可以把变参数据传给非变参宏. 第一种方法是使用库中的 BOOST_PP_VARIADIC_ELEM 宏, 把变参数据的各个记号分别传给非变参宏.

示例 - 把变参数据的各个记号传给非变参宏.

#define MACRO_ARG_2(x,y) BOOST_PP_ADD(x,y)
#define VAR_MACRO(...) __VA_ARGS__

/* The following will work correctly */

int xx = MACRO_ARG_2
 (
 BOOST_PP_VARIADIC_ELEM(0,VAR_MACRO(2,3)),
 BOOST_PP_VARIADIC_ELEM(1,VAR_MACRO(2,3))
 );
第二种方法是使用库中一个名为 BOOST_PP_OVERLOAD 的宏. 该宏允许用一个公共前缀把一个变参宏“重载”到具有不同参数数量的非变参宏上.

示例 - 把变参数据整体传给 BOOST_PP_OVERLOAD, 再传给非变参宏.

#define MACRO_ARG_2(x,y) BOOST_PP_ADD(x,y)
#define VAR_MACRO(...) __VA_ARGS__

/* The following will work correctly */

int xx = BOOST_PP_OVERLOAD(MACRO_ARG_,VAR_MACRO(2,3))(VAR_MACRO(2,3));

/* For Visual C++'s default preprocessor it is necessary to do this */

int xx = 
BOOST_PP_CAT(BOOST_PP_OVERLOAD(MACRO_ARG_,VAR_MACRO(2,3))(VAR_MACRO(2,3)),BOOST_PP_EMPTY());
虽然这些技术在把变参数据传给非变参宏时是可行的, 但更好的做法是在内部使用现有的库数据类型, 只在需要一个接受数量可变参数的宏时, 才把变参宏用作面向最终用户的接口, 这样问题会少得多.
