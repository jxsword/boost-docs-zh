Preprocessor 库的限制

Boost 预处理库一直存在某些特定的限制, 本文档的其他部分对它们有专门说明, 并且它们在头文件 config/limits.hpp 中以对象式宏的形式实现. 这些限制主要规定了库中某些特性的最大数量. 选择这些最大值, 是为了兼顾本库所支持的大量编译器及其预处理器, 提供一个最低公共的限制集合, 使这些编译器中的绝大多数都能成功工作. 这反映了如下情况: C/C++ 标准很少为编译器规定预处理器限制, 而是允许每个编译器自行选择其预处理器中它认为必要的任何限制. 虽然这使各个编译器可以在很大程度上自行选择其认为必要的预处理器限制, 但它使像本库这样的预处理器库更难在多个操作系统平台上与大量预处理器协同工作. 这种局面的困难程度意味着这个 Boost 预处理库选择了相当保守的限制.

事实上, 这些限制宏虽然确实存在, 但以前从未在预处理库代码内部使用过. 换言之, 尽管限制宏确实存在, 库内部使用的却是与这些宏所代表的值等价的固定数字. 这种历史状况最可能反映了如下事实: 库不希望最终用户通过重新定义 config/limits.hpp 中的宏来改变这些限制, 进而改变库的工作方式, 从而导致使用库时出问题.

这一状况现已改变: 当预处理器符合 C++ 标准时, config/limits.hpp 中规定的一部分限制宏如今已在库代码内部使用. 因此, 本主题讨论最终用户如何更改库的限制.

限制的类型

Boost 预处理库中的限制可以分为:

  • 数值
  • 大小
  • 循环
  • 迭代
库支持数 (number). 它支持基本的算术、比较和逻辑运算. 这一支持由宏 BOOST_PP_LIMIT_MAG 说明, 其中 'MAG' 是 "MAGNITUDE" 的缩写. 当前的固定最大值为 256. 这意味着库支持 0 到 256 范围内的数值运算.

库支持高级类型的最大大小. 这些类型是数组、列表、seq、元组和变参数据. 这些高级构造的“大小”指的是一个高级构造最多可由多少个元素构成. 对数组和元组而言, 该值由宏 BOOST_PP_LIMIT_TUPLE 说明; 对变参数据而言, 该值由宏 BOOST_PP_LIMIT_VARIADIC 说明. 在这两种情况下, 当前的固定最大值为 64. 对 seq 而言, 该值由宏 BOOST_PP_LIMIT_SEQ 说明, 其当前固定值为 256. 对列表而言, 从来没有过限制宏, 但实际上列表元素数量的上限由上面给出的 BOOST_PP_LIMIT_MAG 的最大值决定. 因此, 列表与 seq 一样, 默认最多 256 个元素. 数组、元组和变参数据的最大元素数量是 64, 而 seq 和列表则是不大得多的 256, 原因在于: 前一类构造的实现常常要把同样数量的值作为参数传给内部宏, 而一些编译器对宏可拥有的参数数量施加了限制; 因此选择了安全得多的 64, 以便能够与这些编译器协同工作.

循环构造由控制结构 BOOST_PP_WHILE 和重复构造 BOOST_PP_FOR、BOOST_PP_REPEAT 组成. 每个都有一个限制宏, 当前都设为 256. 这意味着循环最多可运行 256 次. 对应的限制宏是 BOOST_PP_LIMIT_WHILE、BOOST_PP_LIMIT_FOR 和 BOOST_PP_LIMIT_REPEAT.

迭代构造由局部迭代和文件迭代构造组成. 具体细节在它们各自的主题中有更充分的讨论. 对应的宏是 BOOST_PP_LIMIT_ITERATION, 其值为 256.

限制之间的依赖关系

其中一些限制实际上依赖于其他限制. 它们是:
  • BOOST_PP_LIMIT_MAG 依赖于 BOOST_PP_LIMIT_WHILE. 除 BOOST_PP_INC 和 BOOST_PP_DEC 之外的所有算术宏都依赖于使用 BOOST_PP_WHILE 的循环. 同样, 除 BOOST_PP_EQUAL 和 BOOST_PP_NOT_EQUAL 之外的所有比较宏都依赖于 BOOST_PP_WHILE. 因此, BOOST_PP_LIMIT_MAG 的值同时也是 BOOST_PP_LIMIT_WHILE 的值.
  • BOOST_PP_LIMIT_TUPLE 依赖于 BOOST_PP_LIMIT_VARIADIC, 因为数组/元组功能最终常常会调用变参数据功能. 因此, BOOST_PP_LIMIT_TUPLE 可以小于 BOOST_PP_LIMIT_VARIADIC, 但绝不能大于它.
  • BOOST_PP_LIMIT_SEQ 依赖于 BOOST_PP_LIMIT_MAG, 因为 seq 的总大小至多必须是最大数. 因此, BOOST_PP_LIMIT_SEQ 可以小于 BOOST_PP_LIMIT_MAG, 但绝不能大于它.
  • BOOST_PP_LIMIT_FOR、BOOST_PP_LIMIT_REPEAT 和 BOOST_PP_LIMIT_ITERATION 都依赖于 BOOST_PP_LIMIT_MAG. 这些值中的任何一个都可以小于 BOOST_PP_LIMIT_MAG, 但都不能大于它.

更改限制

最终用户可以通过在包含预处理库头文件之前定义限制宏来更改限制. 这既可以在源文件中进行, 也可以作为编译器命令行的一部分进行.

在说明哪些限制可以更改之前, 需要强调几点:

  • 可更改的限制只适用于符合 C++ 标准的预处理器. 你可以使用宏 BOOST_PP_IS_STANDARD (以 BOOST_PP_IS_STANDARD() 形式调用) 来判断你的编译器是否拥有符合 C++ 标准的预处理器. 几乎所有主流编译器 (包括 gcc 和 clang) 都拥有符合 C++ 标准的预处理器. 最值得注意的是, Visual C++ 的默认预处理器不符合 C++ 标准, 但 Visual C++ 的新预处理器 (Visual Studio 2019 及以上版本可用) 是符合 C++ 标准的预处理器. 如果你为不符合 C++ 标准的预处理器更改某个限制, 该更改会被直接忽略, 也不会发生预处理器错误. 这是因为任何不符合标准的预处理器实际上都不会包含或使用 config/limits.hpp 文件中的宏.
  • 警告 ! 警告 ! 警告 ! 提高限制可能意味着预处理器会失败, 因为编译器本身无法应对限制的提高. 其原因可能是编译器对可传给宏的参数数量、嵌套宏调用的数量, 乃至预处理器展开宏所需的内存量有内部限制.
  • 除了可能先包含预处理器头文件 boost/preprocessor/config/config.hpp 之外, 更改任何限制都必须在 TU (翻译单元) 中包含 Boost 预处理头文件之前进行, 才能正常工作. 在包含 Boost 预处理头文件之后试图更改限制, 最坏会导致预处理器错误, 最好也会导致 UB (未定义行为).
  • 限制只能更改为下文给出的特定值. 试图把限制更改为特定值以外的值, 会导致更改被忽略; 如果在包含 Boost 预处理头文件之后错误地进行更改, 则会导致预处理器错误.
所有默认值为 256 的限制都可以改为 512 或 1024, 但 BOOST_PP_LIMIT_WHILE 除外, 它不能被更改.
两个默认值为 64 的限制可以改为 128 或 256.

各个限制的具体情况:
  • BOOST_PP_LIMIT_MAG : 更改此限制时, BOOST_PP_LIMIT_WHILE 的值也会随之改变, 使之等于 BOOST_PP_LIMIT_MAG. 这是因为数值计算依赖于 BOOST_PP_WHILE 循环, 因此 BOOST_PP_LIMIT_WHILE 本身不能被更改. 此外, 更改 BOOST_PP_LIMIT_MAG 限制时, BOOST_PP_LIMIT_SEQ 的值 (如果它没有被同时改为小于 BOOST_PP_LIMIT_MAG) 也会被改为 BOOST_PP_LIMIT_MAG 的值. 这样, 除非你另有决定并自行更改 BOOST_PP_LIMIT_SEQ, 否则 seq 将与列表一样, 通常具有由 BOOST_PP_LIMIT_MAG 定义的相同的最大元素数量.
  • BOOST_PP_LIMIT_TUPLE: 更改此限制时, 如果 BOOST_PP_LIMIT_VARIADIC 的值没有被同时改为大于 BOOST_PP_LIMIT_TUPLE, 那么 BOOST_PP_LIMIT_VARIADIC 的值也会随之改变, 使之至少等于 BOOST_PP_LIMIT_TUPLE. 这是因为元组/数组依赖于变参功能.
  • BOOST_PP_LIMIT_SEQ、BOOST_PP_LIMIT_FOR、BOOST_PP_LIMIT_REPEAT、BOOST_PP_LIMIT_ITERATION: 如果你试图把这些值中的任何一个设置为大于 BOOST_PP_LIMIT_MAG 的值, 该限制将被设置为等于 BOOST_PP_LIMIT_MAG 的值. 这是因为所有这些限制都依赖于数值范围.

其他注意事项

如果你对某个限制的默认值感到满意, 就没有必要更改任何限制. 然而, 如果你决定提高某个限制, 应当意识到这样做会影响预处理器使用的内存量以及完成预处理的速度. 在前一种情况下, 已知有些预处理器会在限制值被提高时耗尽内存, 尽管在现代计算机系统中这实在不应该发生. 在后一种情况下, 预处理可能变得如此缓慢, 以至于在使用某个提高了的限制的同时还想让预处理在合理的时间内完成变得不可能. 后一种情况可能发生在你使用列表或 seq, 并在遍历大量元素的同时还对每个元素值执行耗时的操作 (这会生成进一步的宏循环) 之时. 几乎所有算术和比较运算都会引发进一步的宏循环.

对列表和 seq 而言, 有些功能会使用 BOOST_PP_FOR 宏. 如果通过 BOOST_PP_LIMIT_MAG 宏提高了列表和 seq 的最大大小, 你可能还需要定义 BOOST_PP_LIMIT_FOR 来提高 'for' 循环的最大数量, 以便使用这些功能遍历所有列表或 seq.

BOOST_PP_WHILE 构造在内部被几乎所有算术宏和比较宏用作循环, 也被库中许多其他遍历元素的宏在内部使用. 虽然该构造可以在一个已经在运行的 BOOST_PP_WHILE 循环之内被调用, 但发生这种情况时有可能耗尽 BOOST_PP_WHILE 循环. 为解决这个问题, 你可以指定一个大于你通常使用的最大数的 BOOST_PP_LIMIT_MAG. 这会给你两倍数量的 BOOST_PP_WHILE 循环, 使你在遍历列表和 seq 的同时必须进行算术计算、且所遍历的列表和/或 seq 的数量接近你原本的最大值时, 不至于耗尽循环.

测试限制

使用 Boost Build 的 b2 命令在 preprocessor 测试目录中进行的默认测试只测试默认限制. 如果你想在测试目录中测试任何可设置的非默认限制, 可以用以下任一显式目标调用 b2 命令:

  • preprocessor_128 : 多达 128 个元素的数组、元组和变参数据
  • preprocessor_256 : 多达 256 个元素的数组、元组和变参数据
  • preprocessor_512 : 最大值为 512 的数、列表、seq、循环和迭代构造
  • preprocessor_1024 : 最大值为 1024 的数、列表、seq、循环和迭代构造
  • preprocessor_tup : 此列表中的第一和第二项
  • preprocessor_num : 此列表中的第三和第四项
  • preprocessor_limits : 所有预处理库限制
如果你用最后一个 preprocessor_limits 目标调用 b2, 对你的编译器来说测试可能要花一段时间. 当你选择上述目标之一时 (如 'b2 preprocessor_limits'), 默认测试不会运行. 如果你希望默认测试与诸如 preprocessor_limits 之类的目标一起运行, 命令应为 'b2 . preprocessor_limits', 其中 '.' 记法表示所有非显式 (即默认) 目标.
