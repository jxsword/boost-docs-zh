动机

C++ 的函数参数列表和模板参数列表是特殊的语法构造, 无法用 C++ 构造直接操纵或生成它们. 这导致不必要的代码重复.
看看 Boost 中 is_function<> 元函数的实现. 该实现使用了一个重载的 is_function_tester() 函数, 用于测试一个类型是否可转换为函数指针. 由于参数列表受到特殊对待, 无法直接匹配具有任意参数列表的函数. 相反, 必须为要支持的每种不同参数数量重载 is_function_tester(). 例如:
template<class R>
yes_type is_function_tester(R (*)());

template<class R, class A0>
yes_type is_function_tester(R (*)(A0));

template<class R, class A0, class A1>
yes_type is_function_tester(R (*)(A0, A1));

template<class R, class A0, class A1, class A2>
yes_type is_function_tester(R (*)(A0, A1, A2));

// ...
在实现泛型组件或元编程设施时, 对这类重复的需求出现得特别频繁, 但在许多简单得多的情形中也会出现这种需求.

典型解决方案

通常, 这种重复是手工完成的. 手工重复代码效率极低, 但在未经训练的眼睛看来有时反而更易读.
另一种解决方案是编写一个外部程序来生成重复代码, 或者使用某些其他额外的语言手段, 如智能编辑器. 遗憾的是, 使用外部代码生成器有许多缺点:
  • 编写生成器需要时间. (使用标准生成器可以缓解这一点.)
  • 直接操纵 C++ 代码不再有效率.
  • 调用生成器可能很困难.
  • 在某些环境中, 自动化生成器的调用可能很困难. (对活动库 (active libraries) 而言, 自动调用是理想状态.)
  • 移植和分发生成器可能很困难, 或者干脆要耗费宝贵的时间.

预处理器怎么样?

由于 C++ 自带预处理器, 人们会以为它能直接支持这类需求. 在这种情况下使用预处理器是非常理想的, 因为:
  • 预处理器具有高度可移植性.
  • 预处理器作为编译过程的一部分被自动调用.
  • 预处理器元代码可以直接嵌入 C++ 源代码.
  • 编译器通常允许查看或输出预处理后的代码, 这可用于调试, 或用于复制粘贴生成的代码.
最不幸的是, 这个预处理器是一个非常低级的预处理器, 它特意不支持重复和递归宏. 需要库的支持!
有关预处理器能力与限制的详细信息, 请参阅 C++ 标准 [Std].

重访动机示例

使用预处理库的原语, is_function_tester() 可以这样实现:
#include <boost/preprocessor/arithmetic/inc.hpp>
#include <boost/preprocessor/punctuation/comma_if.hpp>
#include <boost/preprocessor/repetition.hpp>

#ifndef MAX_IS_FUNCTION_TESTER_PARAMS
#define MAX_IS_FUNCTION_TESTER_PARAMS 15
#endif

#define IS_FUNCTION_TESTER(Z, N, _) \
   template<class R BOOST_PP_COMMA_IF(N) BOOST_PP_ENUM_PARAMS(N, class A)> \
   yes_type is_function_tester(R (*)(BOOST_PP_ENUM_PARAMS(N, A))); \
   /**/

BOOST_PP_REPEAT(BOOST_PP_INC(MAX_IS_FUNCTION_TESTER_PARAMS), IS_FUNCTION_TESTER, _)

#undef IS_FUNCTION_TESTER
要更改所支持的函数参数的最大数量, 现在只需修改 MAX_IS_FUNCTION_TESTER_PARAMS 的定义并重新编译.
