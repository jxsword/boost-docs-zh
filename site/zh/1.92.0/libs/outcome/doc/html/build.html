构建与安装

作为单一头文件使用

Outcome v2 以单一头文件形式提供, 并在每次提交时重新生成. 在 Linux 上获取:

wget https://github.com/ned14/outcome/raw/master/single-header/outcome.hpp

在 BSD 上:

fetch https://github.com/ned14/outcome/raw/master/single-header/outcome.hpp

如果你安装了 curl:

curl -O -J -L https://github.com/ned14/outcome/raw/master/single-header/outcome.hpp

否则, 只需从上方下载原始文件, 放到你认为合适的位置. 如果你可能使用 Microsoft Visual Studio 进行调试, 你会发现 https://github.com/ned14/outcome/raw/master/include/outcome/outcome.natvis 处的调试器可视化文件值得加入你的构建.

从 vcpkg 包管理器使用

这种方式特别简单, 适用于 Mac OS、Linux 与 Microsoft Windows:

vcpkg install outcome

Outcome 出现在 <boost/outcome/outcome.hpp>. 这是 Outcome 的完整副本, 因此 Experimental Outcome 与所有常用头文件都在你期望的位置.

从 Conan 包管理器使用

(感谢 Théo Delrieu 贡献此支持)

在命令行中, 将 Outcome 的 bintray 仓库添加到 conan:

conan remote add outcome https://api.bintray.com/conan/ned14/Outcome

现在只需把以下内容加入你的 Conan 构建:

[requires]
Outcome/master@ned14/stable

Conan 会在 <outcome.hpp> 提供 Outcome.

从 cmake hunter 包管理器使用

Outcome 尚未提交到 cmake hunter 包管理器主仓库. 不过你可以将其添加为 git 子模块:

cd yourthirdpartyrepodir
git submodule add https://github.com/ned14/quickcpplib
git submodule add https://github.com/ned14/outcome
cd ..
git submodule update --init --recursive

现在, 通过在你项目的 cmake/Hunter/config.cmake 中添加内容, 告诉 cmake hunter 存在一个以 git 子模块形式提供的 cmake hunter 包:

hunter_config(quickcpplib GIT_SUBMODULE "yourthirdpartyrepodir/quickcpplib")
hunter_config(outcome GIT_SUBMODULE "yourthirdpartyrepodir/outcome")

……最后在你的 CMakeLists.txt 中, 现在像普通 cmake hunter 包一样添加 outcome:

hunter_add_package(quickcpplib)
find_package(quickcpplib CONFIG REQUIRED)
hunter_add_package(outcome)
find_package(outcome CONFIG REQUIRED)

接下来照常告诉 cmake 链接 outcome (cmake 目标见下文):

target_link_libraries(mytarget outcome::hl)

作为 git 子模块使用

如果你非常希望跟踪最新版的 Outcome, 可以把它作为 git 子模块加入项目, 以便及时获得缺陷修复. 方法如下:

git submodule add https://github.com/ned14/outcome
cd outcome
git checkout master
git submodule update --init --recursive

此后你就可以用以下方式在代码中使用 Outcome:

#include "outcome/single-header/outcome.hpp"

大功告成, 可以开始了. 你可能不时希望更新到最新版:

cd outcome
git pull
git submodule update

作为稳定源码压缩包使用

如果你更想要一个来自 stable 与 develop 分支的单一源码压缩包——其所有单元测试已在所有平台上通过, 并包含全部文档、测试与源码——可以随时从这里获取:

https://github.com/ned14/outcome/releases

该压缩包在 Outcome 完整编译并通过 CI 所测试的全部平台上的所有单元测试时自动生成. 目前包括:

  • Linux: GCC 7.5, clang 9, clang 11
  • MacOS: XCode 12
  • Windows: VS2019.7

所有单元测试都在 Address 与 Undefined Behaviour sanitizer 下运行.

需要强调的是, 更新的编译器并未经过测试, 因此存在较小的可能性: 该压缩包在更新的编译器上可能无法工作.

运行单元测试套件

要运行单元测试套件, 你需要安装 cmake 3.3 或更高版本.

mkdir build
cd build
cmake ..
cmake --build .
ctest

在某些 cmake 生成器 (Visual Studio、Xcode) 上, 你可能需要告诉 cmake build 使用 Release 或 Debug 之类的配置. 同样地, ctest 也需要被告知相同信息, 例如:

mkdir build
cd build
cmake ..
cmake --build . --config Release
ctest -C Release

每次提交时, 测试由 Travis 运行并上传到这里的 CDash 看板.

CMake find_package() 导入目标支持

Outcome 完全符合 cmake install 规范, 因此安装 Outcome 后, cmake 的 find_package() 就能找到它.

mkdir build
cd build
cmake ..
cmake --build .
sudo cmake --build . --target install

Modular CMake 构建支持

如果你在 CMake 项目中使用 Outcome, Outcome 是一个全程只使用现代 cmake 3 的 “modular cmake” 项目. 这让你可以把 Outcome 目录作为 cmake 子目录加入, 而不会对其余 cmake 产生意外影响. 你需要使用 cmake 3.3 或更高版本.

add_subdirectory(
  "${CMAKE_CURRENT_SOURCE_DIR}/outcome"  # path to outcome source
  "${CMAKE_CURRENT_BINARY_DIR}/outcome"  # your choice of where to put binaries
  EXCLUDE_FROM_ALL                       # please only lazy build outcome on demand
)

Outcome 的 cmake 提供以下有用的产物:

  • outcome::hl (target): Outcome 仅头文件库. 把它加到你 cmake 中的任何 target_link_libraries() 里, 即可以仅头文件库的形式引入 Outcome. 这还会通过 PUBLIC 向你的链接添加任何调试器可视化支持文件与系统库依赖, 并强制所有消费方可执行文件至少以 C++ 14 配置, 因为 Outcome 最低要求该标准.
  • outcome_TEST_TARGETS (list): 生成 Outcome 测试套件的目标列表. 如果你希望在自己运行测试套件的同时也运行 Outcome 的测试套件, 可以把它附加到你自己的测试套件中.
