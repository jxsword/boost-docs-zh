错误处理框架评审

Outcome 始于 2014 年, 2018 年以 Boost.Outcome 之名进入 Boost, 因此是最早一批替代 C++ 标准异常抛出的主要错误处理框架之一. 从那以后, 有时正是作为对 Outcome 设计选择的回应, 其他替代框架陆续出现. 本页试图对这些替代方案给出一个相当持平的总结, 并给出在作者看来它们与 Outcome 相比的表现.

以下按其在 C++ 生态中大致的可用时间排序, 即按出现顺序排列.

  1. std 异常抛出

    C++ 异常抛出的优缺点

  2. std 错误码

    优缺点: std::error_code

  3. std expected

    优缺点: std::expected<T, E>

  4. Outcome (提案中的 std result)

    优缺点: Outcome 及其提案中的 std::result<T>

  5. LEAF

    Lightweight Error Augmentation Framework 的优缺点
