value_or_error Concept

到目前为止还没有真正提到的一点是: Outcome 如何与提案中的 P0323 std::expected<T, E> 互操作——其设计落在 unchecked<T, E = varies> 与 checked<T, E = varies> 之间 (两者都是硬编码无值策略的类型别名, 如本教程前文所述).

Expected 与 Outcome 在设计意图上彼此同构, 但得益于提案的 ValueOrError concept 框架 (Outcome 实现了它的一个子集), 使用 Expected 与 Outcome 的代码之间的互操作应当是无缝的.

explicit basic_result(concepts::value_or_error<T, E> &&) 与 explicit basic_outcome(concepts::value_or_error<T, E> &&) 构造函数会从任何匹配 concepts::value_or_error<T, E> concept 的类型显式构造——该范围包括 std::expected<A, B>——前提是 A 可构造为 X, 且 B 可构造为 Y. value_or_error concept 为真, 当且仅当输入类型具有:

  1. 一个 .has_value() 观察器, 返回 bool.
  2. .value() 与 .error() 观察器.

实现

Outcome 实现 concepts::value_or_error 转换的机制可由用户扩展: 通过把 value_or_error<T, U> 类型的特化注入 BOOST_OUTCOME_V2_NAMESPACE::convert 命名空间.

Outcome 的默认 convert::value_or_error<T, U> 实现在默认机制中显式排除了 Outcome 的 result 与 outcome 类型, 因为有一个大坑: value_or_error 匹配类型的 .value() 在 constexpr 中常常不可调用 (因为它可能抛异常), 这使得该转换机制对 constexpr 代码几乎无用. 此外, outcome 针对把 result 作为输入提供了具备 constexpr 能力的转换构造函数重载.

注意, 如果你确实启用 outcome 输入, result 会匹配输入的 outcome, 但会静默丢弃任何异常状态. 这很可能不是你想要的.
