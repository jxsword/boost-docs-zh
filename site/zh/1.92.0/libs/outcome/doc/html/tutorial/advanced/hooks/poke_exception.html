自定义 exception ptr

如果你只想让 result 在不调用内存分配器的情况下捕获栈回溯, 并保留对优化很重要的任何拷贝平凡性, 你已经拥有所需的一切.

但让我们继续: 拦截本地化 outcome 从本地化 result 构造的任何情形, 取出任何已存储的回溯, 并用它合成一个带消息文本 (包含回溯) 的 exception ptr. 首先看看合成 exception ptr 的函数:

namespace error_code_extended
{
  // Synthesise a custom exception_ptr from the TLS slot and write it into the outcome
  template <class R> inline void poke_exception(outcome<R> *o)
  {
    if(o->has_error())
    {
      extended_error_info *eei = mythreadlocaldata().get(BOOST_OUTCOME_V2_NAMESPACE::hooks::spare_storage(o));
      if(eei != nullptr)
      {
        // Make a custom string for the exception
        std::string str(o->error().message());
        str.append(" [");
        struct unsymbols  // RAII cleaner for symbols
        {
          char **_{nullptr};
          ~unsymbols() { ::free(_); }
        } symbols{::backtrace_symbols(eei->backtrace.data(), eei->items)};
        if(symbols._ != nullptr)
        {
          for(size_t n = 0; n < eei->items; n++)
          {
            if(n > 0)
            {
              str.append("; ");
            }
            str.append(symbols._[n]);
          }
        }
        str.append("]");

        // Override the payload/exception member in the outcome with our synthesised exception ptr
        BOOST_OUTCOME_V2_NAMESPACE::hooks::override_outcome_exception(o, std::make_exception_ptr(std::runtime_error(str)));
      }
    }
  }
}

如果被构造的本地化 outcome 处于出错状态, 尝试按其备用存储中唯一的 16 位值获取 TLS 槽位. 如果有效, 把栈回溯符号化成字符串, 并用它构造一个带运行期错误的 exception ptr. 最后, 用新的 exception ptr 覆盖刚拷贝构造的本地化 outcome 中的负载/异常成员.

正如 void override_outcome_exception(basic_outcome<T, EC, EP, NoValuePolicy> *, U &&) noexcept 的参考文档指出的: 如果有任何其他替代方案, 你几乎肯定不想使用该函数. 值得解释一下这句话的含义.

在本节中, 我们总是在从基于 result 的 API 过渡到基于 outcome 的 API 的确切转换点, 从已存储状态与错误码合成 exception ptr. 这之所以可以接受, 只是因为我们知道我们的代码强制执行这一纪律.

如果是在设计一个库设施, 就不能假设库用户具备这种纪律. 更明智的做法可能是让 exception ptr 的合成惰性化——经由一个自定义无值策略, 只在需要时 (例如 .exception() 观察, 或无值可用的 .value() 观察) 才生成包含栈回溯的错误消息.

不过, 这样的设计比本节呈现的设计更不确定, 因为其不确定性比本设计更难预测. 最终采用哪种策略, 取决于绝对确定性对你的 Outcome 应用有多重要.
