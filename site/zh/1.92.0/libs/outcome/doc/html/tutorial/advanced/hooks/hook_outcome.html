挂钩 outcome

最后一步是针对非常特定的情况添加事件钩子: 当我们的本地化 outcome 从本地化 result 拷贝或移动构造时.

你必须非常小心, 使这些 noexcept 性与 noexcept——即 outcome 中类型的 性相匹配. 你可能注意到 poke_exception() 会创建一个 std::string 并向其追加. 这可能抛出异常. 如果 T、EC 与 EP 的拷贝和/或移动构造函数是 noexcept, 那么 outcome 的拷贝和/或移动构造函数也将如此. 因此如果 poke_exception() 抛出异常, 程序会立即终止, 这很糟.

我们在本例中通过把 poke_exception() 包进一个 try...catch 来避免该问题——后者会丢弃任何被抛出的异常. 对 v2.2 之前的 Outcome, 这些特别命名的自由函数必须放入一个被 ADL 搜索的命名空间:

namespace error_code_extended
{
  // Specialise the outcome copy and move conversion hook for when our localised result
  // is used as the source for copy construction our localised outcome
  template <class T, class U> inline void hook_outcome_copy_construction(outcome<T> *res, const result<U> & /*unused*/) noexcept
  {
    try
    {
      // when copy constructing from a result<T>, poke in an exception
      poke_exception(res);
    }
    catch(...)
    {
      // Do nothing
    }
  }
  template <class T, class U> inline void hook_outcome_move_construction(outcome<T> *res, result<U> && /*unused*/) noexcept
  {
    try
    {
      // when move constructing from a result<T>, poke in an exception
      poke_exception(res);
    }
    catch(...)
    {
      // Do nothing
    }
  }
}

对 Outcome v2.2 及以后, 这些函数必须放入一个自定义无值策略, 名称分别为 on_outcome_copy_construction() 与 on_outcome_move_construction(). 与之前一样, 函数的实现完全相同, 只是名称与位置变了.
