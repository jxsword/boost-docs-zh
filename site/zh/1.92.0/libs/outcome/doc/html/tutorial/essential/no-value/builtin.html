内建策略

这些是 Outcome 内建的预定义策略:

 

all_narrow

如果对不存在的值/错误/异常进行观察, 程序会进入硬性未定义行为状态. 编译器确实不为无效观察编译任何代码——CPU 会 “跑向” 未知之处.

尽管听起来很糟, 它生成最优的代码, 而且这种硬性未定义行为对检测工具非常友好, 例如未定义行为 sanitizer、valgrind memcheck 等.

如果你正在考虑选择该策略, 务必先读 static void _ub(Impl &&).

注意, unchecked<T, E = varies> 是 basic_result 的别名, 带有无值策略 all_narrow.

 

terminate

对缺失值/错误/异常的观察会导致一次对 std::terminate() 的调用.

注意, 配置 EC = void 或 EP = void 会使 default_policy 选择 terminate 作为无值策略.

 

error_code_throw_as_system_error<T, EC, EP>

该策略假定 EC 具有 std::error_code 的接口, 且 EP 具有 std::exception_ptr 的接口. 在缺失值观察时:

  • 如果经类型 EP 的指针存储了异常, 则重抛它;
  • 否则, 如果存储了 EC 类型的错误, 则把它转换为 error_code, 然后作为 system_error 抛出.

在缺失错误观察时抛出:

  • bad_result_access("no error"), 来自 basic_result<> 的实例.
  • bad_outcome_access("no error"), 来自 basic_outcome<> 的实例.

在缺失异常观察时抛出 bad_outcome_access("no exception").

为 boost::system::error_code 与 boost::exception_ptr 提供了重载.

注意, 如果 is_error_code_available<T> 对 EC 为真, 且 (若 basic_outcome) is_exception_ptr_available<T> 对 EP 为真, default_policy 会选择 error_code_throw_as_system_error<T, EC, EP> 作为无值策略.

 

exception_ptr_rethrow<T, EC, EP>

该策略假定 EC 或 EP (除非 void) 具有 std::exception_ptr 的接口. 在缺失值观察时:

  • 在 basic_result<> 的实例中, 重抛 EC 所指向的异常;
  • 在 basic_outcome<> 的实例中, 若存在异常 EP 则重抛它, 否则重抛 EC.

在缺失错误观察时:

  • 在 basic_result<> 的实例中, 抛出 bad_result_access("no error");
  • 在 basic_outcome<> 的实例中, 抛出 bad_outcome_access("no error").

在缺失异常观察时抛出 bad_outcome_access("no exception").

为 boost::exception_ptr 提供了重载.

注意, 如果 is_exception_ptr_available<T> 对 EC 为真, 或 (若 basic_outcome) is_exception_ptr_available<T> 对 EP 为真, default_policy 会选择 exception_ptr_rethrow<T, EC, EP> 作为无值策略.

 

throw_bad_result_access<EC>

在缺失值观察时抛出 bad_result_access_with<EC>(ec), 其中 ec 是所存错误的值. 若未存储错误, 则行为未定义.

在缺失错误观察时抛出 bad_result_access("no error").

该策略可与 basic_outcome<> 实例一起使用, 此时它对所有无值/错误/异常观察都抛出 bad_outcome_access.

注意, checked<T, E = varies> 是 basic_result 的别名, 带有无值策略 throw_bad_result_access<EC>.
