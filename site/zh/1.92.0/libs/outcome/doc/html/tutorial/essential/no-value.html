无值策略

在上一节我们看到: 如果对类型 .value() 的、不含值的对象调用成员函数 outcome<T> 时, 能依据某种用户定义策略抛出异常, 将会很有用.

先考虑 result<T>. 它是 basic_result<T, E, NoValuePolicy> 的别名, 其中 E 是存储错误信息的类型, 默认为 std::error_code/boost::system::error_code; NoValuePolicy 是一个无值策略, 默认为 default_policy<T, EC, EP>.

basic_result::value() 的语义是:

  1. 调用 NoValuePolicy::wide_value_check(*this).
  2. 返回对所含值的引用. 如果实际没有存储值, 你的程序就进入了未定义行为.

因此, 函数 .value() 的语义取决于无值策略. 默认策略 (policy::default_policy<T, EC, void>) 针对 EC (类型为 std::error_code1) 做以下事情:

  • 如果 r.has_value() == false 抛出异常 std::system_error{r.error()},
  • 否则无效.
注释

类模板 basic_result<T, E, NoValuePolicy> 与 basic_outcome<T, EC, EP, NoValuePolicy>

从不使用异常. 所有与异常相关的逻辑完全经由无值策略提供.

在使用模板 basic_result<> 或 basic_outcome<> 设计你自己的成功或失败类型时, 你必须决定想用哪种无值策略. 要么自己写一个, 要么使用预定义策略之一.

你还可以为 basic_result<> 使用另外两个预定义别名之一:

  • unchecked<T, E = varies>: 它使用策略 all_narrow, 对缺失值或错误的任何观察都是未定义行为;
  • checked<T, E = varies>: 它使用策略 throw_bad_result_access<EC>, 对缺失值或错误的任何观察会分别抛出 bad_result_access_with<EC> 或 bad_result_access.
  1. 存在抛出 boost::system::system_error 的类似重载——当 EC 为 boost::system::error_code 时. [return]
