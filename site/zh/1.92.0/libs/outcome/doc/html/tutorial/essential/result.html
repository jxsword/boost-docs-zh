result<>

我们将定义一个把 std::string 转换为 int 的函数. 该函数可能因多种原因失败; 如果失败, 我们想要传达失败原因.

outcome::result<int> convert(const std::string& str) noexcept;

模板别名 result<T, E = varies, NoValuePolicy = policy::default_policy<T, E, void>> 有三个模板参数, 但后两个有默认值. 第一个 (T) 表示函数成功时返回对象的类型. 第二个 (EC) 是函数失败时容纳失败原因信息的对象类型. result 对象在任一时刻要么存储 T 要么存储 EC, 因此概念上类似于 variant<T, EC>. 在独立版 Outcome 中 EC 默认为 std::error_code, 在 Boost.Outcome 中默认为 boost::system::error_code 1. 第三个参数 (NoValuePolicy) 称为无值策略, 我们稍后介绍.

如果 T 与 EC 都是可平凡复制的, result<T, EC, NVP> 也可平凡复制. 每个操作 (构造、拷贝构造、赋值、析构等) 的平凡性、复杂度与 constexpr 性总是 T 与 EC 中对应操作的交集, 例如若 T 与 EC 都是字面类型, result<T, EC, NVP> 也会是. 此外, 若 T 与 EC 都有标准布局, result<T, EC, NVP> 有标准布局; 因此若 T 与 EC 是 C 兼容的, result<T, EC, NVP> 也会是 C 兼容的.

{
  Success     = 0, // 0 should not represent an error
  EmptyString = 1, // (for rationale, see tutorial on error codes)
  IllegalChar = 2,
  TooLong     = 3,

假定我们已把它接入 std::error_code 框架, 如本节所述.

这种接入的一个显著效果是: ConversionErrc 现在可转换为 std::error_code. 现在我们可以这样实现函数 convert:

outcome::result<int> convert(const std::string& str) noexcept
{
  if (str.empty())
    return ConversionErrc::EmptyString;

  if (!std::all_of(str.begin(), str.end(), ::isdigit))
    return ConversionErrc::IllegalChar;

  if (str.length() > 9)
    return ConversionErrc::TooLong;

  return atoi(str.c_str());
}

result<T, EC> 可从任何 T2 (可转换为 T) 构造, 也可从任何 EC2 (可转换为 EC) 构造——前提是 T 与 EC 之间任一方向都不可能构造. 如果可能, 所有隐式转换都被禁用, 你将需要使用带标签构造函数之一:

outcome::result<int> r {outcome::in_place_type<std::error_code>, ConversionErrc::EmptyString};
outcome::result<int> s {outcome::in_place_type<int>, 1};
