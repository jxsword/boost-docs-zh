挂钩 result

现在我们告诉 Outcome: 对本地化 result<T> 的每个实例, 仅在失败构造时, 运行自定义代码——递增 TLS 存储中的当前槽位, 并把当前栈回溯写入其中.

对 v2.2 之前的 Outcome, 我们必须通过向一个被 ADL 搜索的命名空间插入一个特别命名的自由函数来做到:

namespace error_code_extended
{
  // Specialise the result construction hook for our localised result
  // We hook any non-copy, non-move, non-inplace construction, capturing a stack backtrace
  // if the result is errored.
  template <class T, class U> inline void hook_result_construction(result<T> *res, U && /*unused*/) noexcept
  {
    if(res->has_error())
    {
      // Grab the next extended info slot in the TLS
      extended_error_info &eei = mythreadlocaldata().next();

      // Write the index just grabbed into the spare uint16_t
      BOOST_OUTCOME_V2_NAMESPACE::hooks::set_spare_storage(res, mythreadlocaldata().current - 1);

      // Capture a backtrace into my claimed extended info slot in the TLS
      eei.items = ::backtrace(eei.backtrace.data(), eei.backtrace.size());
    }
  }
}

对 Outcome v2.2 及以后, 我们必须使用一个自定义无值策略, 其中包含名为 on_result_construction() 的函数. 两种机制下函数实现完全相同, 只是函数声明的名称与位置不同.

上面唯一不明显的部分是对 void set_spare_storage(basic_result|basic_outcome *, uint16_t) noexcept 的调用.

result 与 outcome 都把其内部状态元数据保存在一个 uint32_t 中, 其中一半未被 Outcome 使用. 由于给任何特定的 result 或 outcome 实例附加一个小小的唯一编号非常有用, 我们允许用户代码把这 16 位设置成任何他们想要的值. 取回这 16 位的对应函数是 uint16_t spare_storage(const basic_result|basic_outcome *) noexcept.

比较操作会忽略这 16 位备用存储的状态.

以下操作期间这 16 位备用存储会传播:

  1. result 之间的拷贝与移动构造.
  2. outcome 之间的拷贝与移动构造.
  3. 从 result 到 outcome 的拷贝与移动构造.
  4. 上述所有的转换拷贝与移动构造.
  5. 上述所有的赋值.

它们在以下操作中不传播:

  1. 任何经过 failure_type 或 success_type 的转换或翻译.
  2. 任何经过 ValueOrError concept 匹配的转换或翻译.
  3. 任何对值/错误/异常的拆包或重打包, 例如把 outcome 手动重打包成 result.
