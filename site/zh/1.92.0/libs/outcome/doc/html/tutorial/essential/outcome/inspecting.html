检查 outcome

继续前面的例子, 在 Layer3 中我们有函数 z, 它再次经由异常报告失败. 它将调用来自 h 的函数 Layer2_old, 后者返回 outcome<int> (其中可能存储 int 或 std::error_code 或 std::exception_ptr). 目标是把它拆包为成功的返回值 int, 或抛出恰当的异常: 如果我们存储的是 std::exception_ptr, 直接重抛它. 如果我们存储的是 std::error_code, 把它作为 std::system_error 抛出——后者设计用于存储 std::error_code:

auto z() -> int // throws on failure
{
  if (outcome::outcome<int> o = old::h())
    return o.value();
  else if (o.has_exception())
    std::rethrow_exception(o.exception());
  else
    throw std::system_error{o.error()};
}
在 Github 上查看此代码

函数 has_exception() 检查存储的是否为 EP (std::exception_ptr), 函数 exception() 访问它. 类似地, 函数 error() 在存储了 EC (std::error_code) 时访问它. outcome<> 还有函数 has_failure() 用于检查存储的是 EC 还是 EP.

看起来上述 “拆包” outcome<> 的模式如此常见, 以至于应当把它实现在函数 .value() 内部, 这样函数 z 就可以写成:

return old::h().value();

而这正是前述无值策略模板参数的用途, 将在下一节描述.
