开始之前

Outcome v2 命名空间

建议你经由以下命名空间别名来引用本 Outcome v2 的实体:

namespace outcome = BOOST_OUTCOME_V2_NAMESPACE;
在 Github 上查看此代码

仅限独立版 Outcome: 随着对本库应用补丁与修改, 命名空间会被置换, 以免造成二进制不兼容. 某个时刻会定义命名空间 outcome_v2, 那将是首选命名空间. 在此之前, BOOST_OUTCOME_V2_NAMESPACE 表示最近更新的版本, 并逐步接近 outcome_v2.

仅限 Boost.Outcome: 由于 Boost 不跨发布版提供二进制兼容, BOOST_OUTCOME_V2_NAMESPACE 总是展开为 boost::outcome_v2.

在线编译器

如果你从未用过它们, 你会发现 Godbolt 与 Wandbox 非常宝贵. 它们让你在网页浏览器里玩 C++.

Outcome 的大多数源码片段在其右上角有一个指向 github 上原始源码的链接. 你可以把这些源码复制粘贴进 Godbolt (如果你想研究生成的汇编) 或 Wandbox (如果你想运行程序).

Godbolt

Godbolt 对于在线查看一段 C++ 在所有主流编译器与 CPU 架构下生成的汇编非常宝贵.

独立版 Outcome 已内建于 Godbolt! 在右侧窗格的工具栏中, 点击库下拉框 (目前是右起第三个, 图标像一本书), 找到 Outcome 并选择你想要的版本.

选定之后, 你可以对 Outcome 的这些版本执行 #include:

<outcome-basic.hpp>
包含 basic_outcome.hpp + try.hpp, 它尽可能少地包含系统头文件, 以给出对编译时间影响绝对最小的 Outcome 版本. 参见 https://github.com/ned14/stl-header-heft.
<outcome-experimental.hpp>
包含 experimental/status_outcome.hpp + try.hpp, 它把基础版的低编译时间影响与来自提案 status_code 参考实现 (位于 https://ned14.github.io/status-code/) 的部分结合. 如果你在嵌入式系统上、必须绝对避免二进制膨胀, 并且不介意可能不稳定的 status_code, 这绝对是为你准备的版本.
<outcome.hpp>
包含 outcome.hpp, 它引入 std STL 类型的全部特化, 加上 iostream 支持. 如果你不知道该用哪个版本, 就用这个, 它应当 “直接可用”.

这是第一个教程主题的源码载入 Godbolt 的样子: https://godbolt.org/z/4of3c8

Wandbox

Wandbox 允许你把第三方头文件放进单独的标签页. 它还附带较新的 Boost 库. 两种技术都可用于探索 Outcome.

这是第一个教程主题的源码载入 Wandbox 的样子: https://wandbox.org/permlink/sJoeKHXSyCU5Avft
