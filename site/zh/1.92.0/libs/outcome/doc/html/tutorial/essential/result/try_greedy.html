TRY 是贪婪的

BOOST_OUTCOME_TRYV(expr)/BOOST_OUTCOME_TRY(expr) 的隐式转换语义比 basic_result<T, E, NoValuePolicy> 更 “贪婪”. 例如, 这段代码无法编译:

outcome::result<int, std::error_code> test(outcome::result<int, std::errc> r)
{
    return r;  // you need to use explicit construction here
    // i.e. return outcome::result<int>(r);
}

之所以这样选择, 是因为 std::errc 与 std::error_code 之间存在非平凡转换, 所以即使该转换对 std::error_code 是隐式的, Outcome 也不在此处暴露这种隐式性, 以控制隐式构造函数的数量 (隐式构造函数会显著增加构建时间).

TRY 操作则更贪婪:

outcome::result<int, std::error_code> test(outcome::result<int, std::errc> r)
{
    BOOST_OUTCOME_TRY(r);    // no explicit conversion needed
    return r.value();
}

这是因为 result<int, std::error_code> 会从 int 或 std::error_code 能隐式构造的任何东西隐式构造. 然而 result<int, std::error_code> 不会从 result<int, std::errc> 隐式构造.

因此使用时请牢记: 在隐式转换方面, TRY 比 Outcome 类型本身更贪婪.
