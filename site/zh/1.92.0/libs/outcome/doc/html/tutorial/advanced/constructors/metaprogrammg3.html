替代方案

毫无疑问, 许多人会不喜欢两阶段调用模式, 即

make<file_handle>{"hello"}();

那么让我们来考察最显而易见的替代方案: 模板化自由函数 make<T>.

由于 C++ 无法对模板函数做部分特化, 你需要使用带标签重载, 例如:

template<class... Args>
inline outcome::result<file_handle> make(std::in_place_type_t<file_handle>, Args&& ... args)
{
  return file_handle::file(std::forward<Args>(args)...);
}
...
// Now you must always write this:
make(std::in_place_type<file_handle>, "hello");

带标签重载对较小的项目没问题, 但对更大的代码库:

  1. 键入 make(std::in_place_type<file_handle>, "hello") 比 make<file_handle>{"hello"}() 花时间更长, 写起来可能也没那么直观.
  2. 如果你把允许的构造重载编码进 make<file_handle> 类型, 而不是让变参自由函数无法解析出恰当的重载, 编译器错误消息会清晰得多.
  3. 解析变参自由函数重载对编译器而言不是常量时间, 而解析 make<file_handle> 的类型特化是常量时间. 换言之, 自由函数对构建时间而言是昂贵的, 而完全特化的类型则不然.
  4. 事实证明, 在编写泛型代码时, 传递各种其调用运算符不带参数的对象构造工厂对象会相当有用. 这实际上成了一种惰性构造机制.
