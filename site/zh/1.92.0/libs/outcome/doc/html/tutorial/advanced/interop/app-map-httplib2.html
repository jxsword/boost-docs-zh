把 HTTP 库映射进应用程序 2/2

如果你记得教程中关于 value_or_error Concept 的一节, 这里就是如何在 Outcome 中实现自定义 value_or_error Concept 转换器的示例:

// Inject custom ValueOrError conversion
BOOST_OUTCOME_V2_NAMESPACE_BEGIN
namespace convert
{
  // Provide custom ValueOrError conversion from
  // httplib::result<U> into any app::outcome<T>
  template <class T, class U>  //
  struct value_or_error<app::outcome<T>, httplib::result<U>>
  {
    // False to indicate that this converter wants `result`/`outcome`
    // to NOT reject all other `result`
    static constexpr bool enable_result_inputs = true;
    // False to indicate that this converter wants `outcome` to NOT
    // reject all other `outcome`
    static constexpr bool enable_outcome_inputs = true;

    template <class X,                                                                              //
              typename = std::enable_if_t<std::is_same<httplib::result<U>, std::decay_t<X>>::value  //
                                          && std::is_constructible<T, U>::value>>                   //
    constexpr app::outcome<T> operator()(X &&src)
    {
      // Forward any successful value, else synthesise an exception ptr
      return src.has_value() ?                              //
             app::outcome<T>{std::forward<X>(src).value()}  //
             :
             app::outcome<T>{app::make_httplib_exception(std::forward<X>(src))};
    }
  };
}  // namespace convert
BOOST_OUTCOME_V2_NAMESPACE_END
在 Github 上查看此代码

首先应当注意: 这些自定义转换器必须直接注入 BOOST_OUTCOME_V2_NAMESPACE::convert 命名空间, 并且必须部分或完全特化 value_or_error<T, U>. 这里我们把转换器特化为 value_or_error 转换——从 httplib::result<U> 到 app::outcome<T>, 即从第三方 HTTP 库的错误类型到我们应用的 outcome 类型 (它对我们应用是唯一的, 因为我们硬编码了一个 app 局部错误类型).

其次要注意: 你需要恰当设置 enable_result_inputs 与 enable_outcome_inputs, 否则 result 与 outcome 输入将不会被该转换器匹配1. 在这个转换器中, 我们确实希望转换其他 result 与 outcome 输入, 所以把这些布尔量标记为 true.

第三要注意的是对 operator() 的要求. 若要求不满足, value_or_error 在 basic_result 与 basic_outcome 中的转换构造函数将被禁用. 注意要求: 衰变后的 operator() 输入 X 匹配 httplib::result<U>, 且 T 可从 U 构造. 这意味着 explicit basic_result(concepts::value_or_error<T, E> &&) 与 explicit basic_outcome(concepts::value_or_error<T, E> &&) 构造函数当且仅当输入类型是 httplib::result<U>、且 result 的值类型可从输入的值类型构造时才可用.

如果 operator() 可用, 它自然会把 httplib::result<U> 转换成 app::outcome<T>——要么原样转发任何成功, 要么调用 app::make_httplib_exception() 把 httplib::failure 类型擦除成 app::httplib_error.

  1. 这里引用的 result 与 outcome 是本特定 Outcome 库所定义的. 如果看到来自另一 Outcome 实现的 result 或 outcome, 它们总是必须经由 ValueOrError 匹配转换框架解析. [return]
