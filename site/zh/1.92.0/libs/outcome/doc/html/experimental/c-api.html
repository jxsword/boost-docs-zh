从 C 代码使用 Outcome

C 代码 (如今更常见的是许多能讲 C ABI 却不能讲 C++ ABI 的其他编程语言) 的一个长期难题是: 如何解释 C++ 异常抛出. 答案当然是它们无法解释, 因此需要在 C++ 一侧编写如下形式的 C 垫片 (shim) 代码:

// The API we wish to expose to C
const char *get_value(double v);

// The C shim function for the C++ get_value() function.
extern "C" int c_get_value(const char **ret, double v)
{
  try
  {
    *ret = get_value(v);
    return 0;  // success
  }
  catch(const std::range_error &)
  {
    return ERANGE;
  }
  // More catch clauses may go in here ...
  catch(...)
  {
    return EAGAIN;
  }
}

这件事足够痛苦, 以致大多数人会求助于 SWIG 之类的绑定生成工具来自动完成这类乏味的样板代码生成. 这对较大的项目还行, 但对较小的项目, 搭建与配置 SWIG 的成本同样不低.

真正理想的情况是: 涉及 result<T>、返回 noexcept 的 C++ 函数能被 C 直接使用. Experimental Outcome 确实提供了这种设施, 本节接下来将予以介绍.
