主要差异

<system_error> 与提案中的 <system_error2> 之间的主要设计差异如下:

  1. experimental::status_code<DomainType> 既能表示失败码, 也能表示警告与成功形态码. experimental::errored_status_code<DomainType> 更类似于 std::error_code, 它只能表示失败 (这由 C++ 20 契约或运行期断言检查强制执行).

  2. 错误码的域实现定义由 experimental::status_code<DomainType> 传递的负载类型, 而非像 int 在 std::error_code 中那样被硬编码. 负载类型可以是任何你喜欢的类型, 包括不可平凡复制、仅可移动、复杂等类型.

    该设施极其有用. 例如, 可以返回栈回溯等额外失败元数据. 你也完全可以根据 NDEBUG 或 _DEBUG 是否被定义而改变负载.

  3. 如果你的域定义的负载类型是可平凡复制或移动重定位1 的, 它会获得到仅可移动 experimental::status_code<erased<T>> (其中 T 是另一个可平凡复制或移动重定位类型) 的隐式可转换性. 这允许全局头文件使用单一的、通用的、类型擦除的状态码类型, 这对任何复杂程度的代码库都极为可取. 然而, 与 std::error_code (它在 <system_error> 代码中承担完全相同的角色) 不同, 被类型擦除的负载可以大于 int 在 std::error_code 中的硬编码大小.

    该设施同样极其有用: 额外失败元数据可被类型擦除, 穿过对它们一无所知的代码传递, 并在处理点还原出携带失败元数据的原始类型. 事实上, P1095 提案的 std::error 就是 experimental::status_code<erased<intptr_t>> 的类型别名, 它能传输被擦除的 std::exception_ptr 实例、POSIX 错误码以及更多其他内容.

  4. 域不相同的状态码之间的相等比较总是语义上的, 即询问它们是否语义等价, 而非完全相等. 这类似于你把 std::error_code 与 std::error_condition 相比较的情形, 但由于 <system_error2> 中没有后者的对应物, 这意味着当你看到代码:

    if(code1 == code2) ...

    ……你可以高度确信这是一个非精确的、语义上的匹配操作. 同样的代码在 <system_error> 下则高度含混: 究竟执行的是精确还是非精确比较并不明确 (毕竟那里只有 “code1 == code2”, 它取决于 code1 与 code2 的类型, 而这通常并不显然).

    这种含混性, 以及审计 <system_error> 代码正确性时的高认知负担, 在过去十年间给生产 C++ 带来了许多令人惊讶、始料未及的失败处理缺陷.

  5. <system_error2> 作为全新设计, 具有全 constexpr 的构造与析构, 从而避免了 <system_error> 所需的静态全局变量. 每个静态全局变量都需要一个原子栅栏, 以防其尚未初始化, 因此每次检索错误类别都会使代码膨胀并抑制优化, 还使得在仅头文件库中使用自定义错误码类别变得不可靠. Boost.System 已复制了 <system_error2> 的全 constexpr 构造与析构, 因此在这方面现在具有类似特性.

  6. 最后, 这是一个虽小却重要的差异. 在 <system_error> 下, 这个极其常见的使用场景是含混的:

    if(ec) ...

    这段代码的意思是 '发生了错误?', '错误码被设置?', 还是 '错误码非零?'. 按标准的正确答案是最后一种, 但快速考察 github 上的开源 <system_error> 代码就会立刻发现, 关于正确用法存在广泛的混淆.

    <system_error2> 通过完全移除布尔测试解决了这一问题. 现在人们写 if(sc.success()) ...、if(sc.failure()) ...、if(sc.empty()) ... 等, 从而消除含混.

  1. 移动重定位不在标准之中, 目前处于 WG21 演进工作组孵化器. 它定义为这样一种类型: 其移动构造函数把逐位从源 memcpy() 到目标, 接着把一个默认构造实例的逐位 memcpy() 到源, 并带有程序员给出的保证: 对默认构造实例调用析构函数时没有任何可观察副作用. 出乎意料的是, 相当多的标准库类型能满足这一定义, 包括 std::vector<T>、std::shared_ptr<T> 与 std::exception_ptr. [return]
