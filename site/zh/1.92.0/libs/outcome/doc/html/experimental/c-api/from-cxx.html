从 C 调用 C++

C++ 与 C ABI 具有出色的双向兼容性, 但要编写 C 代码能够直接调用 (无需在 ABI 边界进行编排转换) 的 C++ 代码, 你必须遵守一些限制:

  1. 若要可从 C 安全调用, C++ 函数不得抛出异常, 因此应始终标记为 noexcept.

  2. C++ 函数应当用 extern "C" 注解, 以防止其符号被修饰, 从而赋予它 C 而非 C++ 的 ABI.

  3. 不能在 extern "C" 函数中使用重载.

  4. 在 C++ 函数声明中, 你只能使用同时满足以下两个特征的类型:

    • std::is_standard_layout_v<T>
    • std::is_trivially_copyable_v<T>

    (注意, std::is_trivially_copyable_v<T> 要求平凡析构, 但不要求平凡构造. 这意味着 C++ 可以对原本平凡的类型进行非平凡构造)

以上是标准对良定义的 C 与 C++ 互操作所作的官方要求. 然而, MSVC、GCC 与 clang 三大编译器都宽松得多. 在这三大编译器中, “准标准布局 (almost-standard-layout)” 的 C++ 类型在 C 中工作良好.

“准标准布局” 的 C++ 类型有以下要求:

  1. 没有虚函数或虚基类, 即 std::is_polymorphic_v<T> 必须为 false. 这是因为 vptr 会以 C 无法知晓的方式使数据布局的正确起始位置发生偏移.
  2. 引用类型的非静态数据成员在 C 看来是指针. 你绝不能从 C 向 C++ 传递一个会被 C++ 视为引用的非空指针.
  3. C++ 继承在 C 数据布局中看来, 就像最派生类在顶部按继承顺序嵌套了所继承类型的变量.
  4. 带非平凡析构函数的类型工作良好, 只要其移动构造与赋值至少像 memcpy() 那样等同于逐位拷贝. 你只需确保该类型的实例返回到 C++, 而不会在 C 中沦为孤儿. 本节前面页面把这类类型称为 “移动重定位 (move relocating)” 类型.

Experimental Outcome 对从 C 使用的支持不满足当前的严格要求, 因此依赖刚才描述的 (非常常见的) 实现定义行为 (希望未来的 C++ 标准能把要求放宽到刚才描述的程度).

具体而言, 提案中的 status_code 是准标准布局类型, 因此虽然不能从 extern "C" 函数返回它 (编译器会报错), 但在三大编译器上, 从 C++ 函数把它返回给 C 代码是完全安全的——只要 T 是 “准标准布局” 的 C++ 类型, 它就是 “准标准布局” 的 C++ 类型.
