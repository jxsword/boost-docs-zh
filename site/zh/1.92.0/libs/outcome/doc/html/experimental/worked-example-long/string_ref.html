字符串引用

<system_error2> 不使用 std::string 来返回可能静态或动态分配的字符串, 从而避免拖入大量影响构建时间的标准库.

取而代之, 状态码域有一个 string_ref, 它具有多态实现, 可能使用原子引用计数器管理动态内存分配, 也可能不. 由于这种多态性, 当你传递 string_ref 实例时, 无需担心底层实际使用的是哪种实现.

string_ref 提供与 span<const char> 相同的成员函数, 因此可以正常参与 STL 算法与容器. 特别地, 如果你需要对它做字符串搜索或切片, 可以轻松在其上构造一个 string_view.

  // Return the name of our custom code domain
  virtual int _do_name(_vtable_name_args &args) const noexcept override final
  {
    args.ret = string_ref("file i/o error domain");
    return 0;  // errno value if failed
  }

现在你理解了 string_ref 的作用, 返回状态码域的名称便不言自明. 注意我们使用 string_ref 的非托管构造函数, 因为字符串 "file i/o error domain" 是静态存储的.
