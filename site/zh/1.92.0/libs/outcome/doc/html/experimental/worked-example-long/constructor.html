构造函数

错误码域的构造与析构 100% 是 constexpr 的, 状态码也是如此. 这使编译器能够 100% 只在其“脑中”实例化两者, 不生成任何代码, 因而无任何开销.

遗憾的是, 这也意味着每个域必须能够被无限次实例化, 而由于 100% 处于 constexpr 中, 任何实例在内存中也不会有唯一地址. 因此我们无法像 std::error_category 那样, 用它们在内存中的地址来比较域的等价性.

我们的解决办法是使用取自硬随机数源的非常随机的 64 位数字. 强烈建议使用网站 https://www.random.org/cgi-bin/randbyte?nbytes=8&format=h 作为该数字的来源.

(如果你好奇 64 位整数的碰撞概率, SG14 估计: 若随机数源足够随机, 单个进程中大约需要存在 190,000 个不同的域, 才会有 0.00000001% 的碰撞概率)

  // unique id must be from a hard random number source
  // Use https://www.random.org/cgi-bin/randbyte?nbytes=8&format=h to get a hard random 64 bit id.
  // Do NOT make up your own value. Do NOT use zero.
  constexpr explicit _file_io_error_domain(typename _base::unique_id_type id = 0x230f170194fcc6c7) noexcept
      : _base(id)
  {
  }
  static inline constexpr const _file_io_error_domain &get();
在 Github 上查看此代码

这种方法的一个不错的副作用是: 仅头文件库中的自定义错误域是安全的, 不像自定义 <system_error> 错误类别那样. Boost.System 的错误类别现在也可选择加入这一相同的安全机制, 以便在仅头文件库用例中同样安全.
