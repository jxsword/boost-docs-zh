errno

失败时返回一个特殊值, 并把错误码 (一个 int) 存入全局 (或线程局部) 对象 errno, 这一惯用法继承自 C, 并用于其标准库:

int readValue(const char * filename)
{  
  FILE* f = fopen(filename, "r");
  if (f == NULL)
    return 0; // special value indicating failure
              // keep errno value set by fopen()

  int i;
  int r = fscanf(f, "%d", &i);
  if (r == 0 || r == EOF) { // special values: i not read
    errno = ENODATA;        // choose error value to return
    return 0;

  fclose(f);
  errno = 0;  // clear error info (success)
  return i;
}

这种技术的一个优点 (对某些人是优点, 对另一些人是缺点) 是: 它使用熟悉的控制语句 (if 与 return) 来标示所有处理失败的执行路径. 当我们阅读这段代码时, 我们知道它在何时、何种条件下可能不产出预期结果而退出.

缺点

因为无论失败还是成功, 我们都要写入一个全局 (或线程局部) 对象, 我们的函数不是纯函数: 它们有副作用. 这意味着许多有用的编译器优化 (如公共子表达式消除) 无法应用. 这表明并非只有 C++ 在为报告失败选择次优方案.

无论返回什么类型, 我们总需要一个留作特殊用途的值, 这有时很麻烦. 在上例中, 如果成功读到的 i 值是 0, 而我们返回它, 调用者会认为这是一次失败, 尽管它并不是.

使用 if 语句与提前 return 传播错误是手工的. 我们很容易忘记检查失败, 错误地让后续操作执行, 可能对程序状态造成损害.

在几乎每一层函数调用上, 我们可能都不得不改变错误码的值, 使其反映适合当前层的错误状况. 如果这样做, 原始错误码就丢了.
