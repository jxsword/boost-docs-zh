错误码

错误码是一种合理的错误处理技术, 在 C 中同样可行. 这种情况下, 信息同样以 int 存储, 但按值返回, 这使函数可以成为纯函数 (无副作用且引用透明).

int readInt(const char * filename, int& val)
{
  FILE* fd;
  int r = openFile(filename, /*out*/ fd);
  if (r != 0)
    return r; // return whatever error openFile() returned

  r = readInt(fd, /*out*/ val);
  if (r != 0)
    return READERRC_NOINT; // my error code

  return 0;   // success
}

由于错误信息的类型 (int) 是静态已知的, 无需内存分配或类型擦除. 这种技术非常高效.

缺点

手工编写的所有失败路径既可以视为优点, 也可以视为缺点. 忘记放置失败处理的 if 会导致缺陷.

如果我需要把低层函数返回的错误码替换为本层更合适的错误码, 关于原始失败的信息就丢了.

此外, 不同第三方库中不同程序员发明的所有可能错误码, 都必须装进同一个 int 且不与任何其他错误码值重叠. 这几乎不可能, 且扩展性差.

由于错误经由返回值传递, 我们不能再用函数的返回类型返回计算出的值. 计算值被写入函数的输出参数, 这要求在我们有值可放入之前先创建对象. 这要求许多处于非预期状态的对象存在. 写输出参数往往需要一次间接, 并可能带来一些运行期开销.
