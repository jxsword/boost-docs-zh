lazy<T, Executor = void>/atomic_lazy<T, Executor = void>

这与 eager<T, Executor = void> 非常相似, 区别在于返回 lazy<T> 的函数立即挂起. 因此返回 lazy<T> 的函数适用于需要立即实例化、但其执行将发生在别处 (例如单独的内核线程) 的任务. 由于用工作线程执行惰性执行协程的函数体是很常见的用例, 大多数人会想用 atomic_lazy<T> 而非 lazy<T>.

atomic_lazy<T> 类似于 lazy<T>, 区别在于设置协程结果时执行原子释放 (release), 而检查协程是否已完成则是原子获取 (acquire).

lazy<T> 的语义类似于正在被标准化的 std::lazy<T>. 参见 https://wg21.link/P1056 Add lazy coroutine (coroutine task) type.

Executor 模板参数纯粹是为了与 ASIO 等第三方软件兼容, 该 awaitable 可直接被 ASIO 使用.

使用示例 (必须从协程化的函数内调用):

lazy<int> func(int x)
{
  co_return x + 1;
}
...
// Always suspends perhaps causing other coroutines to execute, then resumes.
int r = co_await func(5);

lazy<T> 具有特殊语义: 如果 T 是能够从 exception_ptr 或 error_code 构造的类型, 函数体内抛出的任何异常都会经由 T 发送, 若 error_from_exception( ) 成功匹配被抛异常, 则优先走错误码路径. 这意味着 basic_result<T, E, NoValuePolicy> 或 basic_outcome<T, EC, EP, NoValuePolicy> (其类型之一兼容时) 的 .error() 或 .exception() 会被设置.

注意, lazy<T> 在其他方面不传输异常抛出, 并会把协程体内抛出的任何异常经由协程机制重抛. 这在当前 C++ 编译器中不会产生可靠后果. 因此你应当把协程体包在 try...catch 中, 如果 T 不能自行传输异常.

要求: 你的编译器需支持 C++ 协程.

命名空间: BOOST_OUTCOME_V2_NAMESPACE::awaitables

头文件: <boost/outcome/coroutine_support.hpp>
