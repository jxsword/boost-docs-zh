failure_type<EC, EP = void>

用于构造不成功 result 或 outcome 的类型糖. 一般不直接构造, 而是经由自由函数 failure(T &&, ...). 可用 is_failure_type<T> 检测.

这是一个常规包装类型: 默认构造、拷贝与移动构造函数为默认, 赋值为默认, 析构函数为默认.

成员类型别名 error_type 与 exception_type 分别指示 EC 与 E.

存在一个显式初始化构造函数, 接受任意类型 U 与 V, 将分别转发构造所含的 error_type 与 exception_type. 如果你希望指定备用存储值, 它还有一个可选参数 spare_storage.

存在两个带标签的初始化构造函数, 接受 in_place_type_t<error_type> 或 in_place_type_t<exception_type> 与一个 U, 将分别转发构造所含的 error_type 与 exception_type. 如果你希望指定备用存储值, 两者同样有一个可选参数 spare_storage.

存在 .error() 与 .exception() 引用观察器, 带有惯常的 constexpr 左值、const 左值、右值与 const 右值重载. 可以使用惯常的 .has_error() 与 .has_exception() 观察器来发现其中哪个或两者有效.

存在一个 .spare_storage() 观察器, 返回构造该失败类型糖时所用的备用存储值.

存在特化 failure_type<EC, void> 与 failure_type<void, E>, 它们对被 void 的类型不存储任何东西, 且不提供其观察器函数.

要求: 无.

命名空间: BOOST_OUTCOME_V2_NAMESPACE

头文件: <boost/outcome/success_failure.hpp>
