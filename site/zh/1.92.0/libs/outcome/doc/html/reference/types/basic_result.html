一种和类型, 携带 T 或 E 之一; NoValuePolicy 规定在试图读取不存在的状态时该怎么办, 并支持注入钩子以在生命周期事件发生时捕获. T 与 E 之一或两者可为 void, 以表示该状态没有值. 注意, E = void 会把 basic result 实质上变成一个 optional<T>, 但带有 NoValuePolicy 可配置的行为. 可用 is_basic_result<T> 检测.

要求: C++ 20 下为 concept 要求, 否则为静态断言:

  • trait type_can_be_used_in_basic_result<R> 对 T 与 E 皆为真.
  • 要么 E 为 void, 要么为 DefaultConstructible (仅限 Outcome v2.1 及更早版本).

命名空间: BOOST_OUTCOME_V2_NAMESPACE

头文件: <boost/outcome/basic_result.hpp>

包含: 最轻量的 C 与 C++ 头文件:

  1. <cstdint>
  2. <initializer_list>
  3. <iosfwd>
  4. <new>
  5. <type_traits>
  6. 若 BOOST_OUTCOME_USE_STD_IN_PLACE_TYPE 为 1, 则为 <utility> (仅 C++ 17 或更高时默认为 1)
  7. 仅当 C++ 异常被禁用且 BOOST_OUTCOME_DISABLE_EXECINFO 未定义时 (用于在 “异常抛出” 时打印栈回溯):
    1. <sal.h> (仅 Windows)
    2. <stddef.h> (仅 Windows)
    3. <string.h> (仅 Windows)
    4. <execinfo.h> (仅 POSIX)
  8. <cstdio>
  9. <cstdlib>
  10. <cassert>

这套非常轻量的包含依赖, 使 basic result 适合用于超大型 C++ 代码库的全局头文件.

设计理由

basic result 类型是 Outcome 库的主力类型, 提供一个带可选值的简单和类型, 表示成功或失望. 与 P0323 std::expected<T, E> 不同, Outcome 的 result 类型专为在超大型代码库中实现失败处理的便利而设计, 并为此做了多处 API 差异化.

第一个主要设计差异是: basic result 的构造函数设计以 std::variant<...> 为范本——而 std::optional<T> 的构造函数设计则是 std::expected<T, E> 所效仿的对象. 这意味着只要无歧义, basic result 会隐式构造 T 或 E, 与 variant 的行为相同. 当隐式构造有歧义时, 隐式构造函数被禁用, 一个 T 或 E 可以经由 in_place_type_t<T> 指定, 或经由 success_type<T> 或 failure_type<T>. 我们实现了 variant 构造函数的一个子集以降低编译期影响, 因此隐式与显式构造函数设计被划分为固定子集以减少 SFINAE 执行.

第二个主要设计差异是: 仅当 T 与 E 都是可平凡复制或 void 时才使用 union 存储, 否则使用 struct 存储. 这通常不是问题, 因为假定 sizeof(E) 在失败处理场景中会很小. 只为可平凡复制类型使用 union 存储的选择极大降低了编译器负担, 并在超大型 C++ 14 代码库中大幅缩短编译时间, 因为拷贝与移动无需为了实现基于 union 存储的实现所要求的 never-empty 保证而经历复杂仪式 (C++ 17 起拷贝与移动构造函数实例化少得多, 但积少成多——避免的工作总是最快的).

公有成员类型别名

  • value_type 为 T.
  • error_type 为 E.
  • no_value_policy_type 为 NoValuePolicy.
  • value_type_if_enabled 为 T——当可从 T 构造时; 否则它是一个命名有用的不可用内部类型.
  • error_type_if_enabled 为 E——当可从 E 构造时; 否则它是一个命名有用的不可用内部类型.
  • rebind<A, B = E, C = NoValuePolicy> 为 basic_result<A, B, C>.

受保护成员谓词布尔量

  • predicate::constructors_enabled 为 constexpr 布尔真, 如果衰变后的 value_type 与衰变后的 error_type 不是同一类型.

  • predicate::implicit_constructors_enabled 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. trait is_error_type<E> 不同时对衰变后的 value_type 与衰变后的 error_type 为真.
    3. value_type 不能从 error_type 隐式构造, 且 error_type 不能从 value_type 隐式构造.
      OR
      trait is_error_type<E> 对衰变后的 error_type 为真, 且 error_type 不能从 value_type 隐式构造, 且 value_type 是整型.

  • predicate::enable_value_converting_constructor<A> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. 衰变后的 A 不是此 basic_result 类型.
    3. predicate::implicit_constructors_enabled 为真.
    4. 衰变后的 A 不是 in_place_type_t.
    5. trait is_error_type_enum<E, Enum> 对 error_type 与衰变后的 A 为假.
    6. value_type 可从 A 隐式构造, 且 error_type 不能从 A 隐式构造.
      OR
      value_type 与衰变后的 A 是完全相同的类型, 且 value_type 可从 A 隐式构造.

  • predicate::enable_error_converting_constructor<A> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. 衰变后的 A 不是此 basic_result 类型.
    3. predicate::implicit_constructors_enabled 为真.
    4. 衰变后的 A 不是 in_place_type_t.
    5. trait is_error_type_enum<E, Enum> 对 error_type 与衰变后的 A 为假.
    6. value_type 不能从 A 隐式构造, 且 error_type 可从 A 隐式构造.
      OR
      error_type 与衰变后的 A 是完全相同的类型, 且 error_type 可从 A 隐式构造.

  • predicate::enable_error_condition_converting_constructor<ErrorCondEnum> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. 衰变后的 ErrorCondEnum 不是此 basic_result 类型.
    3. 衰变后的 ErrorCondEnum 不是 in_place_type_t.
    4. trait is_error_type_enum<E, Enum> 对 error_type 与衰变后的 ErrorCondEnum 为真.

  • predicate::enable_compatible_conversion<A, B, C> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. basic_result<A, B, C> 不是此 basic_result 类型.
    3. A 为 void, 或 value_type 可从 A 显式构造.
    4. B 为 void, 或 error_type 可从 B 显式构造.

  • predicate::enable_make_error_code_compatible_conversion<A, B, C> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. basic_result<A, B, C> 不是此 basic_result 类型.
    3. trait is_error_code_available<T> 对衰变后的 error_type 为真.
    4. predicate::enable_compatible_conversion<A, B, C> 不为真.
    5. A 为 void, 或 value_type 可从 A 显式构造.
    6. error_type 可从 make_error_code(B) 显式构造.

  • predicate::enable_make_exception_ptr_compatible_conversion<A, B, C> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. basic_result<A, B, C> 不是此 basic_result 类型.
    3. trait is_exception_ptr_available<T> 对衰变后的 error_type 为真.
    4. predicate::enable_compatible_conversion<A, B, C> 不为真.
    5. A 为 void, 或 value_type 可从 A 显式构造.
    6. error_type 可从 make_exception_ptr(B) 显式构造.

  • predicate::enable_inplace_value_constructor<Args...> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. value_type 为 void, 或 value_type 可从 Args... 显式构造.

  • predicate::enable_inplace_error_constructor<Args...> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. error_type 为 void, 或 error_type 可从 Args... 显式构造.

  • predicate::enable_inplace_value_error_constructor<Args...> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. predicate::implicit_constructors_enabled 为真.
    3. value_type 可从 Args... 显式构造, 或 error_type 可从 Args... 显式构造——两者中恰好一个成立 (不可同时).

所提供的 标准要求摘要

  • DefaultConstructible, 总是删除, 以迫使用户为每个实例化的 result 选择有值或出错.
  • MoveConstructible, 如果 value_type 与 error_type 都实现移动构造函数.
  • CopyConstructible, 如果 value_type 与 error_type 都实现拷贝构造函数.
  • MoveAssignable, 如果 value_type 与 error_type 都实现移动构造函数与移动赋值.
  • CopyAssignable, 如果 value_type 与 error_type 都实现拷贝构造函数与拷贝赋值.
  • Destructible.
  • Swappable, 带强保证而非弱保证. 更多信息参见 void swap(basic_result &).
  • TriviallyCopyable, 如果 value_type 与 error_type 都是可平凡复制的.
  • TrivialType, 如果 value_type 与 error_type 都是平凡类型.
  • LiteralType, 如果 value_type 与 error_type 都是字面类型.

  • StandardLayoutType, 如果 value_type 与 error_type 都是标准布局类型. 若是, basic_result 在 C 中的布局保证为以下之一:

    struct trivially_copyable_result_layout {
  union {
    value_type value;
    error_type error;
  };
  unsigned int flags;
};

    ……如果 value_type 与 error_type 都是 TriviallyCopyable; 否则:

    struct non_trivially_copyable_result_layout {
  value_type value;
  unsigned int flags;
  error_type error;
};

    显然, 所有 C 兼容的 C++ 类型都是 TriviallyCopyable, 所以如果你把不可平凡复制的类型从 C++ 传给 C, 你就是在做未定义行为.

  • EqualityComparable, 如果 value_type 与 error_type 彼此之间实现相等比较.

  • LessThanComparable, 未实现, 因为存在来自 value_type 与 error_type 的隐式转换, 这会造成重大意外 (即难以诊断的缺陷), 所以我们完全不实现它们.

  • Hash, 未实现, 因为对不相等的非值项实现通用唯一哈希需要依赖启用 RTTI.

因此 basic_result 满足 Regular concept——如果 value_type 与 error_type 都是 Regular (除缺少默认构造函数外). 在需要默认构造函数的场合, 把 basic_result 包装进 std::optional<T> 通常就足够了.

公有成员函数

禁用构造函数

  1. basic_result(Args...) = delete

    禁用型全捕获构造函数, 用于在 predicate::constructors_enabled 为假时尝试使用非原位构造函数时给出有用的诊断错误.

  2. basic_result(X &&) = delete

    禁用型隐式构造函数, 用于在 predicate::implicit_constructors_enabled 为假时尝试使用隐式构造函数时给出有用的诊断错误.

拷贝与移动构造函数和赋值, 以及析构函数

  1. basic_result() = delete

    默认构造函数 (已禁用).

  2. basic_result(basic_result &&)

    移动构造函数. constexpr、平凡性与 noexcept 传播.

  3. basic_result(const basic_result &)

    拷贝构造函数. constexpr、平凡性与 noexcept 传播.

  4. basic_result &operator=(basic_result &&)

    移动赋值. constexpr、平凡性与 noexcept 传播.

  5. basic_result &operator=(const basic_result &)

    拷贝赋值. constexpr、平凡性与 noexcept 传播.

  6. ~basic_result()

    析构函数. constexpr、平凡性与 noexcept 传播.

比较

LessThanComparable 为何未实现, 见上文.

  1. bool operator==(const basic_result<A, B, C> &) const

    若此 result 与另一个 result 比较相等则返回 true. constexpr 且 noexcept 传播.

  2. bool operator==(const success_type<A> &) const
