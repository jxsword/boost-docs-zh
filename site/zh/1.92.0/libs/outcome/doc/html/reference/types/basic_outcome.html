一种类型, 携带以下之一: (i) 成功的 T (ii) 失望 EC (iii) 失败 EP (iv) 失望 EC 与失败 EP 并存; NoValuePolicy 规定在试图读取不存在的状态时该怎么办, 并支持注入钩子以在生命周期事件发生时捕获. T、EC 与 EP 中的任意一个、两个或全部可为 void, 以表示该状态没有值. 可用 is_basic_outcome<T> 检测.

要求: C++ 20 下为 concept 要求, 否则为静态断言:

  • trait type_can_be_used_in_basic_result<R> 对 T、EC 与 EP 为真.
  • 要么 EC 为 void, 要么为 DefaultConstructible (仅限 Outcome v2.1 及更早版本).
  • 要么 EP 为 void, 要么为 DefaultConstructible.

命名空间: BOOST_OUTCOME_V2_NAMESPACE

头文件: <boost/outcome/basic_outcome.hpp>

包含: 最轻量的 C 与 C++ 头文件:

  1. <cstdint>
  2. <initializer_list>
  3. <iosfwd>
  4. <new>
  5. <type_traits>
  6. 若 BOOST_OUTCOME_USE_STD_IN_PLACE_TYPE 为 1, 则为 <utility> (仅 C++ 17 或更高时默认为 1)
  7. 仅当 C++ 异常被禁用且 BOOST_OUTCOME_DISABLE_EXECINFO 未定义时 (用于在 “异常抛出” 时打印栈回溯):
    1. <sal.h> (仅 Windows)
    2. <stddef.h> (仅 Windows)
    3. <string.h> (仅 Windows)
    4. <execinfo.h> (仅 POSIX)
  8. <cstdio>
  9. <cstdlib>
  10. <cassert>

这套非常轻量的包含依赖, 使 basic outcome 适合用于超大型 C++ 代码库的全局头文件.

设计理由

basic_outcome 在 basic_result<T, E, NoValuePolicy> 的基础上扩展了第三个可传递的状态, 惯常 (但不必然) 是某种 “中止” 或 “异常” 状态, 函数可返回它以表明操作不仅失败了, 而且是灾难性地失败, 即请放弃任何重试该操作的尝试.

一个完美的替代方案是为中止代码路径抛出 C++ 异常, 而且大多数程序确实应当那样做, 而不是使用 basic_outcome. 然而, 有许多使用场景中选择 basic_outcome 会大放异彩:

  1. 适用于 C++ 异常或 RTTI 不可用, 但重要的是拥有不终止程序的灾难性失败能力的场合.
  2. 适用于即使在灾难性失败情形下也要求确定性行为的场合.
  3. 在使用 Outcome 的代码的单元测试套件中, 把测试失败积累进一个 basic_outcome 以便日后报告极其方便. 类似便利也适用于 RPC 场景: 需要把 C++ 异常抛出积累起来, 以便回报给发起端点.
  4. 适用于函数为 “双重用途确定性” 的场合: 它既可以确定性地使用——此时基于 .error() 切换控制流; 也可以非确定性地使用——通过抛出一个可能携带自定义负载的异常.

公有成员类型别名

  • value_type 为 T.
  • error_type 为 EC.
  • exception_type 为 EP.
  • no_value_policy_type 为 NoValuePolicy.
  • value_type_if_enabled 为 T——当可从 T 构造时; 否则它是一个命名有用的不可用内部类型.
  • error_type_if_enabled 为 EC——当可从 EC 构造时; 否则它是一个命名有用的不可用内部类型.
  • exception_type_if_enabled 为 EP——当可从 EP 构造时; 否则它是一个命名有用的不可用内部类型.
  • rebind<A, B = EC, C = EP, D = NoValuePolicy> 为 basic_outcome<A, B, C, D>.

受保护成员谓词布尔量

  • predicate::constructors_enabled 为 constexpr 布尔真, 如果:

    1. 衰变后的 value_type 与衰变后的 error_type 不是同一类型, 或两者都是 void.
    2. 衰变后的 value_type 与衰变后的 exception_type 不是同一类型, 或两者都是 void.
    3. 衰变后的 error_type 与衰变后的 exception_type 不是同一类型, 或两者都是 void.

  • predicate::implicit_constructors_enabled 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. trait is_error_type<E> 不同时对衰变后的 value_type 与衰变后的 error_type 为真.
    3. value_type 不能从 error_type 隐式构造, 且 error_type 不能从 value_type 隐式构造.
      OR
      trait is_error_type<E> 对衰变后的 error_type 为真, 且 error_type 不能从 value_type 隐式构造, 且 value_type 是整型.
    4. value_type 不能从 exception_type 隐式构造.
    5. error_type 不能从 exception_type 隐式构造.
    6. exception_type 不能从 value_type 隐式构造.
    7. exception_type 不能从 error_type 隐式构造.

  • predicate::enable_value_converting_constructor<A> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. 衰变后的 A 不是此 basic_outcome 类型.
    3. predicate::implicit_constructors_enabled 为真.
    4. 衰变后的 A 不是 in_place_type_t.
    5. trait is_error_type_enum<E, Enum> 对 error_type 与衰变后的 A 为假.
    6. value_type 可从 A 隐式构造, 且 error_type 不能从 A 隐式构造.
      OR
      value_type 与衰变后的 A 是完全相同的类型, 且 value_type 可从 A 隐式构造.
    7. exception_type 不能从 A 隐式构造.

  • predicate::enable_error_converting_constructor<A> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. 衰变后的 A 不是此 basic_outcome 类型.
    3. predicate::implicit_constructors_enabled 为真.
    4. 衰变后的 A 不是 in_place_type_t.
    5. trait is_error_type_enum<E, Enum> 对 error_type 与衰变后的 A 为假.
    6. value_type 不能从 A 隐式构造, 且 error_type 可从 A 隐式构造.
      OR
      error_type 与衰变后的 A 是完全相同的类型, 且 error_type 可从 A 隐式构造.
    7. exception_type 不能从 A 隐式构造.

  • predicate::enable_error_condition_converting_constructor<ErrorCondEnum> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. 衰变后的 ErrorCondEnum 不是此 basic_outcome 类型.
    3. 衰变后的 ErrorCondEnum 不是 in_place_type_t.
    4. trait is_error_type_enum<E, Enum> 对 error_type 与衰变后的 ErrorCondEnum 为真.
    5. exception_type 不能从 ErrorCondEnum 隐式构造.

  • predicate::enable_exception_converting_constructor<A> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. 衰变后的 A 不是此 basic_outcome 类型.
    3. predicate::implicit_constructors_enabled 为真.
    4. 衰变后的 A 不是 in_place_type_t.
    5. value_type 不能从 A 隐式构造.
    6. error_type 不能从 A 隐式构造.
    7. exception_type 可从 A 隐式构造.

  • predicate::enable_error_exception_converting_constructor<A, B> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. 衰变后的 A 不是此 basic_outcome 类型.
    3. predicate::implicit_constructors_enabled 为真.
    4. 衰变后的 A 不是 in_place_type_t.
    5. value_type 不能从 A 隐式构造.
    6. error_type 可从 A 隐式构造.
    7. value_type 不能从 B 隐式构造.
    8. exception_type 可从 B 隐式构造.

  • predicate::enable_compatible_conversion<A, B, C, D> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. basic_outcome<A, B, C, D> 不是此 basic_outcome 类型.
    3. A 为 void, 或 value_type 可从 A 显式构造.
    4. B 为 void, 或 error_type 可从 B 显式构造.
    5. C 为 void, 或 exception_type 可从 C 显式构造.

  • predicate::enable_make_error_code_compatible_conversion<A, B, C, D> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. basic_outcome<A, B, C, D> 不是此 basic_outcome 类型.
    3. trait is_error_code_available<T> 对衰变后的 error_type 为真.
    4. predicate::enable_compatible_conversion<A, B, C, D> 不为真.
    5. A 为 void, 或 value_type 可从 A 显式构造.
    6. error_type 可从 make_error_code(B) 显式构造.
    7. C 为 void, 或 exception_type 可从 C 显式构造.

  • predicate::enable_inplace_value_constructor<Args...> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. value_type 为 void, 或 value_type 可从 Args... 显式构造.

  • predicate::enable_inplace_error_constructor<Args...> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. error_type 为 void, 或 error_type 可从 Args... 显式构造.

  • predicate::enable_inplace_exception_constructor<Args...> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. exception_type 为 void, 或 exception_type 可从 Args... 显式构造.

  • predicate::enable_inplace_value_error_exception_constructor<Args...> 为 constexpr 布尔真, 如果:

    1. predicate::constructors_enabled 为真.
    2. predicate::implicit_constructors_enabled 为真.
    3. value_type 可从 Args... 显式构造, 或 error_type 可从 Args... 显式构造, 或 exception_type 可从 Args... 显式构造——三者中恰好一个成立.

所提供的 标准要求摘要

  • DefaultConstructible, 总是删除, 以迫使用户为每个实例化的 outcome 选择有值、出错或例外.
  • MoveConstructible, 如果 value_type、error_type 与 exception_type 全部实现移动构造函数.
  • CopyConstructible, 如果 value_type、error_type 与 exception_type 全部实现拷贝构造函数.
  • MoveAssignable, 如果 value_type、error_type 与 exception_type 全部实现移动构造函数与移动赋值.
  • CopyAssignable, 如果 value_type、error_type 与 exception_type 全部实现拷贝构造函数与拷贝赋值.
  • Destructible.
  • Swappable, 带强保证而非弱保证. 更多信息参见 void swap(basic_outcome &).
  • TriviallyCopyable, 如果 value_type、error_type 与 exception_type 都是可平凡复制的.
  • TrivialType, 如果 value_type、error_type 与 exception_type 都是平凡类型.
  • LiteralType, 如果 value_type、error_type 与 exception_type 都是字面类型.

  • StandardLayoutType. basic_outcome 能否被 C 使用是实现定义的. 不过 MSVC、GCC 与 clang 三大编译器对 basic_outcome 的 C 布局实现如下:

    struct outcome_layout {
  struct trivially_copyable_result_layout {
    union {
      value_type value;
      error_type error;
    };
    unsigned int flags;
  };
  exception_type exception;
};

    ……如果 value_type 与 error_type 都是 TriviallyCopyable; 否则:

    struct outcome_layout {
  struct non_trivially_copyable_result_layout {
    value_type value;
    unsigned int flags;
    error_type error;
  };
  exception_type exception;
};

    如果你选择标准布局的 value_type、error_type 与 exception_type, basic_outcome 在 MSVC、GCC 与 clang 上可从 C 正常使用.

  • EqualityComparable, 如果 value_type、error_type 与 exception_type 彼此之间实现相等比较.

  • LessThanComparable, 未实现, 因为存在来自 value_type、error_type 与 exception_type 的隐式转换, 这会造成重大意外 (即难以诊断的缺陷), 所以我们完全不实现它们.

  • Hash, 未实现, 因为对不相等的非值项实现通用唯一哈希需要依赖启用 RTTI.

因此 basic_outcome 满足 Regular concept——如果 value_type、error_type 与 exception_type 都是 Regular (除缺少默认构造函数外). 在需要默认构造函数的场合, 把 basic_outcome 包装进 std::optional<T> 通常就足够了.

公有成员函数

禁用构造函数

  1. basic_outcome(Args...) = delete

    禁用型全捕获构造函数, 用于在 predicate::constructors_enabled 为假时尝试使用非原位构造函数时给出有用的诊断错误.

  2. basic_outcome(X &&) = delete

    禁用型隐式构造函数, 用于在 predicate::implicit_constructors_enabled 为假时尝试使用隐式构造函数时给出有用的诊断错误.

拷贝与移动构造函数和赋值, 以及析构函数

  1. basic_outcome() = delete

    默认构造函数 (已禁用).

  2. basic_outcome(basic_outcome &&)

    移动构造函数. constexpr、平凡性与 noexcept 传播.

  3. basic_outcome(const basic_outcome &)

    拷贝构造函数. constexpr、平凡性与 noexcept 传播.

  4. basic_outcome &operator=(basic_outcome &&)

    移动赋值. constexpr、平凡性与 noexcept 传播.

  5. basic_outcome &operator=(const basic_outcome &)

    拷贝赋值. constexpr、平凡性与 noexcept 传播.

  6. ~basic_outcome()

    析构函数. constexpr、平凡性与 noexcept 传播.

观察器

  1. explicit operator bool() const noexcept

    若存在值则返回 true. constexpr, 永不抛出.

  2. bool has_value() const noexcept

    若存在值则返回 true. constexpr, 永不抛出.

  3. bool has_error() const noexcept

    若存在错误则返回 true. constexpr, 永不抛出.

  4. bool has_exception() const noexcept

    若存在异常则返回 true. constexpr, 永不抛出.

  5. bool has_failure() const noexcept
