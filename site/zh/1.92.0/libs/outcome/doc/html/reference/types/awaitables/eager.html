eager<T, Executor = void>/atomic_eager<T, Executor = void>

这与 lazy<T, Executor = void> 非常相似, 区别在于返回 eager<T> 的函数立即开始执行, 而且如果该函数在执行过程中从不挂起, 就不会发生挂起-恢复循环. 因此返回 eager<T> 的函数适用于可能需要挂起、但通常会立即完成的任务.

atomic_eager<T> 类似于 eager<T>, 区别在于设置协程结果时执行原子释放 (release), 而检查协程是否已完成则是原子获取 (acquire).

Executor 模板参数纯粹是为了与 ASIO 等第三方软件兼容, 该 awaitable 可直接被 ASIO 使用.

使用示例 (必须从协程化的函数内调用):

eager<int> func(int x)
{
  co_return x + 1;
}
...
// Executes like a non-coroutine function i.e. r is immediately set to 6.
int r = co_await func(5);

eager<T> 具有特殊语义: 如果 T 是能够从 exception_ptr 或 error_code 构造的类型, 函数体内抛出的任何异常都会经由 T 发送, 若 error_from_exception( ) 成功匹配被抛异常, 则优先走错误码路径. 这意味着 basic_result<T, E, NoValuePolicy> 或 basic_outcome<T, EC, EP, NoValuePolicy> (其类型之一兼容时) 的 .error() 或 .exception() 会被设置.

注意, eager<T> 在其他方面不传输异常抛出, 并会把协程体内抛出的任何异常经由协程机制重抛. 这在当前 C++ 编译器中不会产生可靠后果. 因此你应当把协程体包在 try...catch 中, 如果 T 不能自行传输异常.

要求: 你的编译器需支持 C++ 协程.

命名空间: BOOST_OUTCOME_V2_NAMESPACE::awaitables

头文件: <boost/outcome/coroutine_support.hpp>
