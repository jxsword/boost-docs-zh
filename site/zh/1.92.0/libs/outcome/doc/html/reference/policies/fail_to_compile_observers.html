fail_to_compile_observers

在尝试编译宽观察器策略函数时, 会发生以下静态断言, 使构建失败:

在为一个 result/outcome 尝试宽观察 value、error 或 exception 时, 其 EC 或 E 类型不是 void, 且 trait::has_error_code_v、trait::has_exception_ptr_v 与 trait::has_exception_ptr_v 全为 false. 请指定一个 NoValuePolicy 告诉 result/outcome 该怎么办, 或者使用更具体的便捷类型别名, 例如 unchecked 表示你希望宽观察器为窄观察, 或 checked 表示你总是想要异常抛出等.

这一编译失败是在 Outcome v2.0 的 Boost 同行评审之后引入的, 依据的反馈是: 在类型无法识别时, 用户经常对默认选择 all_narrow 策略感到意外. 人们认为这在默认配置中引入了过多危险, 因此为确保基于 Outcome 的既有代码在升级后大声地破坏, 实现了上述非常冗长的静态断言.

要求: 无.

命名空间: BOOST_OUTCOME_V2_NAMESPACE::policy

头文件: <boost/outcome/policy/fail_to_compile_observers.hpp>
