Experimental

在 <boost/outcome/experimental> 中, 附带了一个基于 Outcome 的模拟, 其模拟对象是 P1095 Zero overhead deterministic failure 所指 P0709 Zero overhead exceptions: Throwing values 的具体实现. 这个纯库实现让你今天就能在 Outcome 支持的任何 C++ 14 编译器 上, 使用对潜在未来 C++ 轻量异常的高度近似摹本.

这个 Experimental Outcome 实现已投入生产使用多年. 它至少已在十亿台设备上出货, 是一套在 Microsoft Windows、Apple iOS 与 Google Android 设备上非常流行的游戏套件的组成部分. 它同样支撑着大型企业应用: 确实, 美国包括期货在内的所有交易, 都由一个基于 Experimental Outcome 的代码库实时捕获进 SEC (美国证券交易委员会) 的数据库. 最后, Experimental Outcome 还被用于部分驾驶辅助汽车的固件, 在那里, 它特别丰富灵活的失败附加信息, 加上与全局禁用 C++ 异常的兼容性, 被证明是一大优势.

未来 C++ 中失败处理的根基可能是 std::error——出自 P1028 status_code. 该提案目前正在 WG21 的库演进工作组 (LEWG) 中打磨, 预期它将被标准化为 std::error_code 的大型增强与向后兼容超集, 同时还能传输任何仅可移动类型, 例如 std::exception_ptr. 与 std::error_code 一样, 提案中的 std::error 恰好占据两个 CPU 寄存器的布局, 因而极为轻量. 它可以包装任意第三方错误处理系统, 并能从 std::error_code 与 std::exception_ptr 自动构造, 完全 (无论其如何定制) 原样传播底层原始实现 (例如 boost::exception_ptr). 与 <system_error> 不同, std::error 不依赖昂贵标准库头文件, 因此将其纳入全局构建对构建时间影响极低. std::error 懂得如何把自己作为常规 C++ 异常抛出, 也懂得如何无损地消化任意 C++ 异常抛出. 最后, std::error 是 ABI 稳定的, 并且是 P1029 move bitcopying 类型, 被移动源对象无需析构.

Experimental Outcome 使用了相同的提案 std::error 对象, 即 P1095 将为其 E 类型所用者, 做法是在内部捆绑 https://ned14.github.io/status-code/ (提案 std::error 的参考实现库) 的一份副本. 对于通过特征 is_move_bitcopying<T> 自声明为移动位拷贝的类型, Outcome 会模拟移动位拷贝语义, status code 也加入其中. 这极大改善了代码生成, 使其不逊于使用 std::error_code (一种可平凡复制类型) 的情况, 正如 https://godbolt.org/z/GEdEGc 所展示的, 尽管提案中的 std::error 是带有非平凡析构函数的仅可移动类型.

Outcome 通过以下头文件把 status_code 绑定进 basic_result 与 basic_outcome 定制:

  • <boost/outcome/experimental/status_result.hpp>
  • <boost/outcome/experimental/status_outcome.hpp>

这些头文件把 BOOST_OUTCOME_SYSTEM_ERROR2_NAMESPACE 命名空间的全部内容导入 BOOST_OUTCOME_V2_NAMESPACE::experimental 命名空间. 因此 BOOST_OUTCOME_SYSTEM_ERROR2_NAMESPACE 中的一切都可以经由 BOOST_OUTCOME_V2_NAMESPACE::experimental 访问.

由于 P1095 还为轻量 C++ 异常提议了 C 语言支持, experimental Outcome 也提供一个基于宏的 C 接口, 使 C 代码能够使用 status_result<T, E> 的 C 兼容子集:

  • <boost/outcome/experimental/result.h>

对于某些嵌入式系统等非 Windows 非 POSIX 平台, 独立版 Experimental Outcome 可以在定义 BOOST_OUTCOME_SYSTEM_ERROR2_NOT_POSIX 宏的情况下使用. 这不会包含 POSIX 头文件, 并在这类平台上提供一个高保真、完全确定的 C++ 异常替代品.

最后, Experimental Outcome 还有一个单头文件版本, 位于 https://github.com/ned14/outcome/blob/develop/single-header/outcome-experimental.hpp. 你可以通过 #include <outcome-experimental.hpp> 在 godbolt 上试用它.

警告

必须以最强硬的措辞强调: <boost/outcome/experimental> 内的任何条目都可能根据 WG21 标准委员会的反馈发生未预告的破坏性变更. 尽管如此, 这些破坏性变更中的大多数很可能只是命名调整而非根本语义变化, 因此你只需少量查找替换即可完成升级.
