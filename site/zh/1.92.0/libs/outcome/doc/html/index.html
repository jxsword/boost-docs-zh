注释

2021 年 12 月底, 独立版 Outcome 实现永久 ABI 稳定. 从 v2.2.3 起, 你将获得跨 Outcome 发布版的 ABI 兼容性保证.

Outcome 是一套工具, 用于在直接使用 C++ 异常处理并不合适的场景中报告与处理函数失败. 这类场景包括:

  • 存在以禁用异常方式编译的程序或其部分;

  • 程序中存在大量依赖失败类型的分支, 使用 if 语句比 try-catch 块更整洁;

  • 存在硬性要求: 失败执行路径的代价不得高于成功执行路径;

  • 存在像 filesystem 库那样的情形: 失败应当远程处理 (使用 C++ 异常抛出) 还是本地处理, 无法在函数内部决定, 需要由调用者决定; 而在后一种情况下, 出于前述原因抛出 C++ 异常并不可取;

  • 程序/框架中有些部分自身实现异常处理, 不希望用异常跨线程、任务、纤程等传播失败报告;

  • 需要让异常穿过未实现异常抛出安全的层进行传播;

  • 存在外部要求 (例如公司级政策): 失败处理路径必须在代码中显式标示.

  • 在需要与 C 代码互操作、而又不想借助 C++ 异常包装垫片很重要的场合.

  • 在你的以 C 为主的代码库需要类似异常的错误处理, 且 Outcome 在 C 中可用的功能子集足以满足需求时.

Outcome 通过让函数返回一个特殊类型来处理失败, 该类型既能存储成功计算出的值 (或 void), 也能存储关于失败的信息. Outcome 还附带一组处理此类类型的惯用法.

我们特别注意确保 Outcome 对构建时间的影响尽可能小, 从而使其适合在超大型代码库的全局头文件中使用. 存储布局有保证, 且对 result<T, E>1 是 C 兼容的, 从而使基于 Outcome 的代码长期 ABI 稳定.

Outcome 中完全确定性的全 noexcept C++ 协程支持尤其强大, 我们还提供针对 Outcome 优化的 eager<T, Executor = void>/atomic_eager<T, Executor = void>、lazy<T, Executor = void>/atomic_lazy<T, Executor = void> 与 generator<T, Executor = void> awaitable, 适用于任何用户类型.

示例用法 (C++)

Outcome 库中的主力是 result<T>: 它要么表示一个类型为 T 的成功计算值, 要么表示一个代表失败原因的 std::error_code/boost::system::error_code2. 你把它用于函数的返回类型:

outcome::result<string> data_from_file(string_view path) noexcept;
在 Github 上查看此代码

可以手动检查状态:

if (outcome::result<string> rslt = data_from_file("config.cfg"))
  use_string(rslt.value());                   // returns string
else
  throw LibError{rslt.error(), "config.cfg"}; // returns error_code
在 Github 上查看此代码

或者, 如果该函数被另一个同样返回 result<T> 的函数调用, 你可以使用一个专用控制语句:

outcome::result<int> process(const string& content) noexcept;

outcome::result<int> int_from_file(string_view path) noexcept
{
  BOOST_OUTCOME_TRY(auto str, data_from_file(path));
  // if control gets here data_from_file() has succeeded
  return process(str);  // decltype(str) == string
}
在 Github 上查看此代码

BOOST_OUTCOME_TRY 是一个控制语句. 如果返回的 result<T> 对象包含错误信息, 外围函数立即返回, 其 result<U> 携带同样的失败信息; 否则, 作用域内会有一个 T 类型的自动对象可用.

示例用法 (C)

与 C++ API 等价: BOOST_OUTCOME_C_DECLARE_RESULT_SYSTEM(ident, T) 声明该 C 类型, 此后 BOOST_OUTCOME_C_RESULT_SYSTEM(ident) 引用它. 你把它用于函数的返回类型:

BOOST_OUTCOME_C_DECLARE_RESULT_SYSTEM(result_string, const char *)

BOOST_OUTCOME_C_RESULT_SYSTEM(result_string) data_from_file(const char *path);
在 Github 上查看此代码

可以手动检查状态:

  BOOST_OUTCOME_C_RESULT_SYSTEM(result_string) rslt = data_from_file("config.cfg");
  if(BOOST_OUTCOME_C_RESULT_HAS_VALUE(rslt))
    use_string(rslt.value);  // returns string
  else
    fprintf(stderr, "%s\n", outcome_status_code_message(&rslt.error));
在 Github 上查看此代码

或者, 如果该函数被另一个同样返回 BOOST_OUTCOME_C_RESULT_SYSTEM(ident) 的函数调用, 你可以使用一个专用控制语句:

BOOST_OUTCOME_C_DECLARE_RESULT_SYSTEM(result_int, int)

BOOST_OUTCOME_C_RESULT_SYSTEM(result_int) process(const char *content);

BOOST_OUTCOME_C_RESULT_SYSTEM(result_int) int_from_file(const char *path)
{
  BOOST_OUTCOME_C_RESULT_SYSTEM_TRY(const char *str, result_int, /* cleanup on fail */, data_from_file(path));
  // if control gets here data_from_file() has succeeded
  return process(str);  // decltype(str) == string
}
在 Github 上查看此代码

C Result 保证与其 C++ 对应物布局完全相同. 有便捷转换函数可用, 但你也可以用 reinterpret cast.

注释

本库在 1.70 发布版 (2019 年春) 加入 Boost C++ 库集合. 如有需要, 它可以被嫁接进老得多的 Boost 发布版.

  1. 如果你选择了 C 兼容的 T 与 E 类型. [return]
  2. result<T> 在独立版 Outcome 中默认为 std::error_code, 在 Boost.Outcome 中默认为 boost::system::error_code. 你可以用 std_result<T> 或 boost_result<T> 强制做出选择. [return]
