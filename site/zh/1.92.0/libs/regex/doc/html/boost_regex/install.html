构建与安装库

从 zip 文件解压该库时, 必须保留其内部目录结构 (例如解压时使用 -d 选项). 如果解压时没有这样做, 那你最好停止阅读本文, 删除刚解压的文件, 然后重试!

本库使用前无需配置; 大多数流行的编译器 / 标准库 / 平台已"开箱即用"地得到支持. 如果你确实遇到配置问题, 或只是想用你的编译器测试配置, 那么流程与 boost 全体相同; 见 config 库文档.

该库将所有代码封装在命名空间 boost 内.

这是一个仅头文件库, 对 C++03 编译器的所有支持现已移除.

仍需要构建外部库 libboost_regex 的, 只有那些使用已弃用的 POSIX C API 的人

此外, 本库现在可以以"独立"模式使用, 无需 Boost C++ 库的其余部分; 为此你必须满足以下条件之一:

  • 拥有支持 __has_include 的 C++17 编译器; 此时如果 <boost/config.hpp> 不存在, 则库会自动进入独立模式. 或者:
  • 构建时定义 BOOST_REGEX_STANDALONE.

如果你将本库与 ICU 一起使用, 请注意: 由于它现在是仅头文件库, 除非你使用附带的 CMake 脚本, 否则当你使用 <boost/regex/icu.hpp> 时, 需要自行链接 ICU 库.

与 CMake 一起使用

该库自带一个非常基本的 CMakeLists.txt, 允许从其他 CMake 脚本使用本库.

CMakeLists.txt 定义了两个目标:

  • Boost::regex 这是用于普通仅头文件构建的目标.
  • Boost::regex_icu 这是当你在代码中使用 <boost/regex/icu.hpp> 并希望自动处理 ICU 依赖时使用的目标.

还有一个配置选项:

  • BOOST_REGEX_STANDALONE: 设置后不会将其他 Boost 库作为依赖目标, 并且 Boost.Regex 进入独立模式. 使用 -DBOOST_REGEX_STANDALONE=on 调用 CMake 以启用独立模式.
