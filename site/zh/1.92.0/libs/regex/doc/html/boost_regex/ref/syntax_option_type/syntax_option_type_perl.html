Perl 正则表达式的选项

对于 perl 正则表达式, 必须总是设置以下选项之一:

元素

标准化

设置后的效果

ECMAScript

是

指定正则表达式引擎识别的文法使用其正常语义: 即与 ECMA-262 (ECMAScript 语言规范, 第 15 章第 10 部分, RegExp (正则表达式) 对象) 中给出的语义相同 (FWD.1).

这在功能上与 Perl 正则表达式语法 相同.

在此模式下, Boost.Regex 还识别所有 perl 兼容的 (?...) 扩展.

perl

否

同上.

normal

同上.

使用 perl 风格正则表达式时还可以设置以下选项:

元素

标准化

设置后的效果

icase

是

指定正则表达式与字符容器序列的匹配应不区分大小写.

nosubs

是

指定当正则表达式与字符容器序列匹配时, 不在提供的 match_results 结构中存储任何子表达式匹配.

optimize

是

指定正则表达式引擎应更加关注匹配正则表达式的速度, 而较少关注构造正则表达式对象的速度. 否则对程序输出没有可察觉的影响. 对 Boost.Regex 而言目前该选项无任何效果.

collate

是

指定形如 [a-b] 的字符范围应区分区域设置.

newline_alt

否

指定 \n 字符与分支运算符 | 效果相同, 允许将以换行符分隔的列表用作分支列表.

no_except

否

防止 basic_regex 在遇到无效表达式时抛出异常.

no_mod_m

否

通常 Boost.Regex 的行为如同 Perl 的 m 修饰符已开启: 断言 ^ 和 $ 分别在内嵌换行符之后和之前匹配; 设置此标志等价于在表达式前加 (?-m) 前缀.

no_mod_s

否

通常情况下, Boost.Regex 是否用 "." 匹配换行符由匹配标志 match_dot_not_newline 决定. 指定此标志等价于在表达式前加 (?-s) 前缀, 因而使 "." 不匹配换行符, 无论匹配标志中是否设置了 match_not_dot_newline.

mod_s

否

通常情况下, Boost.Regex 是否用 "." 匹配换行符由匹配标志 match_dot_not_newline 决定. 指定此标志等价于在表达式前加 (?s) 前缀, 因而使 "." 匹配换行符, 无论匹配标志中是否设置了 match_not_dot_newline.

mod_x

否

开启 perl 的 x 修饰符: 使表达式中未转义的空白被忽略.

no_empty_expressions

否

设置后禁止空表达式 / 空分支.

save_subexpression_location

否

设置后, 各子表达式在原始正则表达式字符串中的位置可以通过 subexpression() (basic_regex 的成员函数) 访问.
