标准符合性

C++

Boost.Regex 旨在符合 C++ 库扩展技术报告.

ECMAScript / JavaScript

支持所有 ECMAScript 正则表达式语法特性, 但以下情况除外:

转义序列 \u 匹配任何大写字符 (与 [[:upper:]] 相同), 而不是 Unicode 转义序列; Unicode 转义序列请使用 \x{DDDD}.

Perl

几乎所有 Perl 特性都已支持, 但以下除外:

(?{code}) 在编译型强类型语言中无法实现.

(??{code}) 在编译型强类型语言中无法实现.

(*VERB) 目前不识别也不实现 回溯控制动词.

此外, 下列特性与 Perl 的行为略有不同:

^ $ \Z 这些会识别任何行结束序列, 而不仅仅是 \n: 参见下文的 Unicode 要求.

POSIX

所有 POSIX 基本和扩展正则表达式特性均已支持, 但以下情况除外:

除 POSIX 标准为 C 区域设置指定的名称外, 不识别任何字符排序名称, 除非它们已通过 traits 类显式注册.

字符等价类 ( [[=a=]] 等) 在 Win32 之外可能存在问题. 实现该特性需要了解系统生成的字符串排序键的格式; 如果你需要此特性, 而默认实现在你的平台上不可用, 则需要提供自定义 traits 类.

Unicode

以下注释针对 Unicode 技术标准 #18: Unicode Regular Expressions version 11.

项目

特性

支持

1.1

十六进制记法

是: 使用 \x{DDDD} 表示码点 UDDDD.

1.2

字符属性

支持 General Category Property 下列出的所有名称. 目前不支持 Script names 和 Other Names.

1.3

差集与交集

通过前向预查间接支持:

(?=[[:X:]])[[:Y:]]

给出字符属性 X 与 Y 的交集.

(?![[:X:]])[[:Y:]]

给出 Y 中不在 X 内的所有内容 (差集).

1.4

简单单词边界

符合: 非间隔标记 (non-spacing marks) 包含在单词字符集合中.

1.5

忽略大小写匹配

支持, 注意在此级别下, 大小写转换是 1:1 的, 不支持多对多的大小写折叠操作 (例如 "ß" 到 "SS").

1.6

行边界

支持, 但 "." 只匹配 "\r\n" 中的一个字符. 除此之外单词边界能正确匹配; 包括不在 "\r\n" 序列中间匹配.

1.7

码点

支持: 只要使用 u32* 算法, UTF-8、UTF-16 和 UTF-32 都会被视为 32 位码点序列.

2.1

规范等价 (Canonical Equivalence)

不支持: 由库的使用者负责将所有文本转换为与正则表达式相同的规范形式.

2.2

默认字素簇 (Grapheme Clusters)

不支持.

2.3默认单词边界

不支持.

  

2.4

默认宽松匹配

不支持.

2.5

命名属性

支持: 表达式 "[[:name:]]" 或 \N{name} 匹配命名字符 "name".

2.6

通配属性

不支持.

3.1

定制标点.

不支持.

3.2

定制字素簇

不支持.

3.3

定制单词边界.

不支持.

3.4

定制宽松匹配

部分支持: [[=c=]] 匹配与 "c" 属于同一主等价类的字符.

3.5

定制范围

支持: 当以 collate 标志构造表达式时, [a-b] 匹配排序在 a 到 b 范围内的任何字符.

3.6

上下文匹配

不支持.

3.7

增量匹配

支持: 向正则表达式算法传递标志 match_partial.

3.8

Unicode 集共享

不支持.

3.9

可能匹配集

不支持, 不过该信息会在内部用于优化正则表达式的匹配, 并在不可能匹配时快速返回.

3.10

折叠匹配

部分支持: 可以通过自定义正则表达式 traits 类达到类似效果.

3.11

自定义子匹配求值

不支持.
