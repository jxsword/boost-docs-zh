本地化

Boost.Regex 为运行期本地化提供了广泛支持, 所使用的本地化模型可分为两部分: 前端和后端.

前端本地化处理用户能看到的一切 - 错误消息以及正则表达式语法本身. 例如, 一个法语应用可以把 [[:word:]] 改为 [[:mot:]], 把 \w 改为 \m. 修改前端区域设置需要开发者主动支持, 即为库提供一个包含本地化字符串的消息目录供其加载. 前端区域设置只受 LC_MESSAGES 类别影响.

后端本地化处理表达式被解析之后发生的一切 - 换句话说, 就是用户看不到也不能直接交互的一切. 它处理大小写转换、排序和字符类成员关系. 后端区域设置不需要开发者做任何干预 - 库会从底层操作系统 / 运行库获取当前区域设置所需的全部信息. 这意味着, 如果程序用户不直接与正则表达式交互 - 例如表达式嵌入在你的 C++ 代码中 - 则无需显式本地化, 库会为你处理好一切. 例如, 在代码中嵌入表达式 [[:word:]]+ 将总是匹配整个单词; 如果程序运行在例如希腊语区域设置的机器上, 它仍会匹配整个单词, 只是使用希腊字符而非拉丁字符. 后端区域设置受 LC_TYPE 和 LC_COLLATE 类别影响.

Boost.Regex 支持三种独立的本地化机制:

Win32 本地化模型.

这是在 Win32 下编译库时的默认模型, 由 traits 类 w32_regex_traits 封装. 当该模型生效时, 每个 basic_regex 对象都有自己的 LCID; 默认情况下它是 GetUserDefaultLCID 返回的用户默认设置, 但如果你愿意, 可以对 basic_regex 对象调用 imbue 将其区域设置设为其他 LCID. Boost.Regex 使用的所有设置都直接从操作系统获取, 绕过 C 运行库. 前端本地化需要一个资源 dll, 其中包含带有用户自定义字符串的字符串表. 该 traits 类导出函数:

static std::string set_message_catalogue(const std::string& s);

在代码编译任何正则表达式之前, 需要用一个标识资源 dll 名称的字符串来调用它 (但不必在构造任何 basic_regex 实例之前):

boost::w32_regex_traits<char>::set_message_catalogue("mydll.dll");

该库在 NT 下提供完整的 Unicode 支持; 在 Windows 9x 下库会优雅降级 - 支持 0 到 255 的字符, 其余字符被视为"未知"图形字符.

C 本地化模型.

对于所有支持 C++ locale 的非 Windows 编译器, 该模型已被弃用, 改用 C++ locale. 此区域设置由 traits 类 c_regex_traits 封装; Win32 用户可以通过定义预处理器符号 BOOST_REGEX_USE_C_LOCALE 强制该模型生效. 当该模型生效时, 存在一个由 setlocale 设置的全局区域设置. 所有设置都从运行库获取, 因此 Unicode 支持取决于运行库的实现.

不支持前端本地化.

注意, 调用 setlocale 会使所有已编译的正则表达式失效; 调用 setlocale(LC_ALL, "C") 会使本库的行为等同于大多数传统的正则表达式库, 包括本库的 1.x 版本.

C++ 本地化模型.

该模型是非 Windows 编译器的默认模型.

当该模型生效时, basic_regex 的每个实例都拥有自己的 std::locale 实例; 类 basic_regex 也有成员函数 imbue, 可以按实例为单位设置表达式的区域设置. 前端本地化需要一个 POSIX 消息目录, 它将通过表达式区域设置的 std::messages facet 加载; traits 类导出符号:

static std::string set_message_catalogue(const std::string& s);

在代码编译任何正则表达式之前, 需要用一个标识消息目录名称的字符串来调用它 (但不必在构造任何 basic_regex 实例之前):

boost::cpp_regex_traits<char>::set_message_catalogue("mycatalogue");

注意, 调用 basic_regex<>::imbue 会使 basic_regex 该实例中当前已编译的任何表达式失效.

最后注意, 如果你以非默认的本地化模型构建库, 那么在构建支持库时以及在代码中包含 <boost/regex.hpp> 或 <boost/cregex.hpp> 时, 都必须定义相应的预处理器符号 (BOOST_REGEX_USE_C_LOCALE 或 BOOST_REGEX_USE_CPP_LOCALE). 确保这一点的最佳方式是把 #define 加入 <boost/regex/user.hpp>.

最后, 自定义排序元素名称从消息 id 400 开始加载, 并在其后第一次加载失败时终止. 每条消息形如: "tagname string", 其中 tagname 是 [[.tagname.]] 内使用的名称, string 是排序元素的实际文本. 注意, 排序元素 [[.zero.]] 的值用于字符串到数字的转换 - 如果你用其他值替换它, 那么该值将用于字符串解析 - 例如, 如果想在正则表达式中使用 Unicode 阿拉伯-印度数字代替拉丁数字, 可以将 [[.zero.]] 的值设为 Unicode 字符 0x0660.

注意, POSIX 定义的字符类名称和排序元素名称始终可用 - 即使定义了自定义名称也是如此; 相反, 自定义错误消息和自定义语法消息则会替换默认消息.
