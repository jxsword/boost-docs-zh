引言与概述

正则表达式是文本处理中常用的一种模式匹配形式; 许多用户都熟悉 Unix 工具 grep、sed 和 awk 以及编程语言 Perl, 它们都大量使用正则表达式. 传统上, C++ 用户只能使用 POSIX C API 来操作正则表达式; Boost.Regex 虽然提供了这些 API, 但它们并不是使用本库的最佳方式. 例如, Boost.Regex 可以处理宽字符字符串, 或执行搜索替换操作 (方式类似于 sed 或 Perl), 这是传统 C 库无法做到的.

类 basic_regex 是本库的核心类; 它表示一个"机器可读"的正则表达式, 其建模非常接近 std::basic_string, 可以把它想象成一个字符串加上正则表达式算法所需的实际状态机. 与 std::basic_string 一样, 几乎总是通过两个 typedef 来引用该类:

namespace boost{

template <class charT,
         class traits = regex_traits<charT> >
class basic_regex;

typedef basic_regex<char> regex;
typedef basic_regex<wchar_t> wregex;

}

为了说明本库的用法, 假设我们正在编写一个信用卡处理程序. 信用卡号码通常是 16 位数字的字符串, 分为 4 位一组, 组间以空格或连字符分隔. 在把信用卡号码存入数据库之前 (这未必是客户会喜欢的事!), 我们可能想验证号码格式是否正确. 要匹配任意数字可以使用正则表达式 [0-9], 但这样的字符范围实际上是依赖区域设置的. 因此应该使用 POSIX 标准形式 [[:digit:]], 或 Boost.Regex 与 Perl 的简写 \d (注意, 许多较老的库往往硬编码为 C 区域设置, 因此对它们而言这不是问题). 这样, 用于验证信用卡号码格式的正则表达式如下:

(\d{4}[- ]){3}\d{4}

这里, 圆括号起到分组 (并标记以便将来引用) 子表达式的作用, 而 {4} 表示"恰好重复 4 次". 这是 Perl、awk 和 egrep 所用扩展正则表达式语法的一个例子. Boost.Regex 也支持 sed 和 grep 所用的较老的"基本"语法, 但它通常不太有用, 除非你已有一些需要复用的基本正则表达式.

现在把这个表达式放进一些 C++ 代码中, 以验证信用卡号码的格式:

bool validate_card_format(const std::string& s)
{
   static const boost::regex e("(\\d{4}[- ]){3}\\d{4}");
   return regex_match(s, e);
}

注意我们必须在表达式中添加一些额外的转义: 记住转义会被 C++ 编译器先看到一次, 然后才被正则表达式引擎看到, 因此在 C/C++ 代码中嵌入正则表达式时, 转义必须加倍书写. 另外注意, 所有示例都假定你的编译器支持实参相依查找 (argument-dependent lookup); 如果你的编译器不支持 (例如 VC6), 则必须给示例中的部分函数调用加上 boost:: 前缀.

熟悉信用卡处理的人会意识到, 虽然上面使用的格式适合人类可读的卡号, 但它不是在线信用卡系统要求的格式; 后者要求号码为 16 位 (或可能 15 位) 数字的字符串, 中间没有任何空格. 我们需要一种在两种格式之间轻松转换的方法, 这正是搜索与替换的用武之地. 熟悉 sed 和 Perl 工具的人在这里已经领先一步; 我们需要两个字符串 - 一个是正则表达式 - 另一个是"格式字符串", 它描述用于替换匹配内容的文本. 在 Boost.Regex 中, 这一搜索替换操作通过算法 regex_replace 执行; 对于信用卡示例, 我们可以编写如下两个算法来提供格式转换:

// match any format with the regular expression:
const boost::regex e("\\A(\\d{3,4})[- ]?(\\d{4})[- ]?(\\d{4})[- ]?(\\d{4})\\z");
const std::string machine_format("\\1\\2\\3\\4");
const std::string human_format("\\1-\\2-\\3-\\4");

std::string machine_readable_card_number(const std::string s)
{
   return regex_replace(s, e, machine_format, boost::match_default | boost::format_sed);
}

std::string human_readable_card_number(const std::string s)
{
   return regex_replace(s, e, human_format, boost::match_default | boost::format_sed);
}

这里我们在正则表达式中使用标记子表达式, 把卡号的四个部分拆分为独立字段; 然后格式字符串使用类似 sed 的语法, 用重新格式化的版本替换匹配的文本.

在上面的示例中, 我们没有直接操作正则表达式匹配的结果; 但一般而言, 匹配结果除了整体匹配外还包含若干子表达式匹配. 当库需要报告正则表达式匹配时, 它使用类 match_results 的实例来完成; 与之前一样, 最常见的情况也有对应的 typedef:

namespace boost{

typedef match_results<const char*>                  cmatch;
typedef match_results<const wchar_t*>               wcmatch;
typedef match_results<std::string::const_iterator>  smatch;
typedef match_results<std::wstring::const_iterator> wsmatch;

}

算法 regex_search 和 regex_match 使用 match_results 来报告匹配内容; 这两个算法的区别在于: regex_match 只会找到消耗全部输入文本的匹配, 而 regex_search 会在被匹配文本的任意位置搜索匹配.

注意, 这些算法并不限于搜索普通的 C 字符串, 任何双向迭代器类型都可以被搜索, 从而几乎可以无缝搜索任何类型的数据.

对于搜索替换操作, 除了我们已见过的算法 regex_replace 之外, match_results 类还有一个 format 成员, 它接受匹配结果和格式字符串, 并通过合并二者生成新字符串.

要遍历文本中某个表达式的所有出现, 有两种迭代器类型: regex_iterator 枚举找到的 match_results 对象, 而 regex_token_iterator 枚举一系列字符串 (类似于 perl 风格的 split 操作).

对于不喜欢模板的人, 有一个高层封装类 [RegEx], 它是底层模板代码的封装 - 为不需要库全部能力的人提供简化接口, 且只支持窄字符和"扩展"正则表达式语法. 该类现已弃用, 因为它不属于正则表达式 C++ 标准库提案.

POSIX API 函数: regcomp、regexec、regfree 和 [regerr] 同时提供窄字符版本和 Unicode 版本, 为需要与这些 API 兼容的人而提供.

最后注意, 本库现已支持 运行期本地化, 并识别完整的 POSIX 正则表达式语法 - 包括多字符排序元素和等价类等高级特性 - 同时提供与其他正则表达式库的兼容性, 包括 GNU 和 BSD4 regex 包、PCRE 和 Perl 5.
