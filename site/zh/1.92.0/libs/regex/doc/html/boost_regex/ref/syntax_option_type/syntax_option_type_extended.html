POSIX 扩展正则表达式的选项

对于 POSIX 扩展正则表达式, 必须总是设置以下选项中的恰好一个:

元素

标准化

设置后的效果

extended

是

指定正则表达式引擎识别的文法与 IEEE Std 1003.1-2001 (可移植操作系统接口 (POSIX), 基本定义与头文件, 第 9 节, 正则表达式) 中 POSIX 扩展正则表达式所用的文法相同 (FWD.1).

更多信息见 POSIX 扩展正则表达式指南.

此外, 还支持一些 perl 风格的转义序列 (POSIX 标准规定只能转义"特殊"字符, 其他所有转义序列都导致未定义行为).

egrep

是

指定正则表达式引擎识别的文法与 IEEE Std 1003.1-2001 (可移植操作系统接口 (POSIX), Shell 与工具, 第 4 节, Utilities, grep) 中 POSIX 实用工具 grep 在给定 -E 选项时所用的文法相同 (FWD.1).

即与 POSIX 扩展语法 相同, 但除 "|" 之外换行符也充当分支字符.

awk

是

指定正则表达式引擎识别的文法与 IEEE Std 1003.1-2001 (可移植操作系统接口 (POSIX), Shell 与工具, 第 4 节, awk) 中 POSIX 实用工具 awk 所用的文法相同 (FWD.1).

即与 POSIX 扩展语法 相同, 但允许在字符类中使用转义序列.

此外, 还支持一些 perl 风格的转义序列 (实际上, awk 语法只要求识别   和 ; 按 POSIX 标准, 所有其他 Perl 风格转义序列属于未定义行为, 但实际上被 Boost.Regex 识别).

使用 POSIX 扩展正则表达式时还可以设置以下选项:

元素

标准化

设置后的效果

icase

是

指定正则表达式与字符容器序列的匹配应不区分大小写.

nosubs

是

指定当正则表达式与字符容器序列匹配时, 不在提供的 match_results 结构中存储任何子表达式匹配.

optimize

是

指定正则表达式引擎应更加关注匹配正则表达式的速度, 而较少关注构造正则表达式对象的速度. 否则对程序输出没有可察觉的影响. 对 Boost.Regex 而言目前该选项无任何效果.

collate

是

指定形如 [a-b] 的字符范围应区分区域设置. 对 POSIX 扩展正则表达式而言, 该位默认为开, 但可以关闭它以强制仅按码点比较范围.

newline_alt

否

指定 \n 字符与分支运算符 | 效果相同, 允许将以换行符分隔的列表用作分支列表.

no_escape_in_lists

否

设置后转义字符在列表内成为普通字符, 因此 [\b] 会匹配 '\' 或 'b'. 对 POSIX 扩展正则表达式而言, 该位默认为开, 但可以关闭它以强制在列表内识别转义.

no_bk_refs

否

设置后后向引用被禁用. 对 POSIX 扩展正则表达式而言, 该位默认为开, 但可以关闭它以启用后向引用支持.

no_except

否

防止 basic_regex 在遇到无效表达式时抛出异常.

save_subexpression_location

否

设置后, 各子表达式在原始正则表达式字符串中的位置可以通过 subexpression() (basic_regex 的成员函数) 访问.
