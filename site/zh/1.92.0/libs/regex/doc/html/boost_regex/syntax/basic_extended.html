POSIX 扩展正则表达式语法

概要

POSIX 扩展正则表达式语法由 POSIX C 正则表达式 API 支持, 实用工具 egrep 和 awk 使用其变体. 在 Boost.Regex 中, 向 regex 构造函数传递标志 extended 即可构造 POSIX 扩展正则表达式, 例如:

// e1 is a case sensitive POSIX-Extended expression:
boost::regex e1(my_expression, boost::regex::extended);
// e2 a case insensitive POSIX-Extended expression:
boost::regex e2(my_expression, boost::regex::extended|boost::regex::icase);

POSIX 扩展语法

在 POSIX 扩展正则表达式中, 除以下特殊字符外, 所有字符都匹配自身:

.[{}()\*+?|^$
通配符:

在字符集合之外使用时, 单字符 '.' 会匹配任何单个字符, 但以下除外:

  • 当向匹配算法传递标志 match_no_dot_null 时的 NULL 字符.
  • 当向匹配算法传递标志 match_not_dot_newline 时的换行字符.
锚点:

'^' 字符在用作表达式的首字符, 或子表达式的首字符时, 匹配行首.

'$' 字符在用作表达式的末字符, 或子表达式的末字符时, 匹配行尾.

标记子表达式:

以 ( 开始、以 ) 结束的部分充当标记子表达式. 与该子表达式匹配的内容会被匹配算法拆分到单独的字段中. 标记子表达式还可以被重复, 或通过后向引用引用.

重复:

任何原子 (单个字符、标记子表达式或字符类) 都可以用 *、+、? 和 {} 运算符重复.

* 运算符会把前面的原子匹配零次或多次, 例如表达式 a*b 会匹配以下任意一项:

b
ab
aaaaaaaab

+ 运算符会把前面的原子匹配一次或多次, 例如表达式 a+b 会匹配以下任意一项:

ab
aaaaaaaab

但不会匹配:

b

? 运算符会把前面的原子匹配零次或一次, 例如表达式 ca?b 会匹配以下任意一项:

cb
cab

但不会匹配:

caab

原子还可以用有界重复来重复:

a{n} 匹配重复恰好 n 次的 'a'.

a{n,} 匹配重复n 次或更多次的 'a'.

a{n, m} 匹配重复介于 n 和 m 次之间 (含)的 'a'.

例如:

^a{2,3}$

会匹配以下之一:

aa
aaa

但不会匹配以下任何一项:

a
aaaa

如果前面的构造不可重复, 则使用重复运算符是错误的, 例如:

a(*)

会引发错误, 因为没有任何内容可供 * 运算符作用.

后向引用:

转义字符后跟一个数字 n (其中 n 在 1-9 范围内) 会匹配与子表达式 n 所匹配相同的字符串. 例如表达式:

^(a*)[^a]*\1$

会匹配字符串:

aaabbaaa

但不匹配字符串:

aaabba
注意

POSIX 标准不支持"扩展"正则表达式的后向引用; 这是对该标准的兼容性扩展.

分支

| 运算符会匹配其两个参数之一, 例如: abc|def 会匹配 "abc" 或 "def".

括号可用于对分支进行分组, 例如: ab(d|ef) 会匹配 "abd" 或 "abef" 之一.

字符集合:

字符集合是以 [ 开始、以 ] 结束的括号表达式; 它定义一个字符集合, 并匹配该集合的任意单个成员字符.

括号表达式可以包含以下内容的任意组合:

单个字符:

例如 [abc] 会匹配字符 'a'、'b' 或 'c' 中的任意一个.

字符范围:

例如 [a-c] 会匹配 'a' 到 'c' 范围内的任意单字符. 对 POSIX 扩展正则表达式而言, 默认情况下, 字符 x处于 y 到 z 的范围内, 当且仅当它在该范围内排序时; 这会产生区域相关的行为. 取消设置 collate 选项标志 可以关闭该行为 - 此时字符是否处于某范围内仅由比较字符的码点决定.

取反:

如果括号表达式以 ^ 字符开头, 则它匹配其所含字符的补集, 例如 [^a-c] 匹配任何不在范围 a-c 内的字符.

字符类:

形如 [[:name:]] 的表达式匹配名为 "name" 的命名字符类, 例如 [[:lower:]] 匹配任意小写字符. 参见 字符类名称.

排序元素:

形如 [[.col.] 的表达式匹配排序元素 col. 排序元素是任何单个字符, 或任何作为单个单元排序的字符序列. 排序元素还可用作范围的端点, 例如: 假设在当前区域设置中 "ae" 被视为单个排序元素, 则 [[.ae.]-c] 匹配字符序列 "ae", 加上 "ae"-c 范围内的任意单字符.

排序元素可以代替转义 (字符集合内通常不允许转义), 例如 [[.^.]abc] 会匹配字符 'abc^' 中的任意一个.

作为扩展, 排序元素还可以通过其 符号名称 指定, 例如:

[[.NUL.]]

匹配一个 NUL 字符.

等价类:

形如 [[=col=]] 的表达式匹配任何主排序键与排序元素 col 相同的字符或排序元素; 与排序元素一样, 名称 col 可以是 符号名称. 主排序键是忽略大小写、重音符号或区域特定定制的排序键; 例如 [[=a=]] 匹配以下字符之一: a, À, Á, Â, Ã, Ä, Å, A, à, á, â, ã, ä 和 å. 遗憾的是, 该特性的实现依赖于平台的排序与本地化支持; 不能指望该特性在所有平台之间, 甚至在同一平台的所有区域设置之间, 以可移植的方式正常工作.

组合:

以上所有内容都可以在一个字符集合声明中组合, 例如: [[:digit:]a-c[.NUL.]].

转义

POSIX 标准未为 POSIX 扩展正则表达式定义任何转义序列, 除了以下情况:

  • 任何特殊字符前加转义字符后匹配它自身.
  • 普通字符前加转义字符的效果未定义.
  • 字符类声明内的转义应匹配它自身: 换句话说, 转义字符在字符类声明内不是"特殊"的; 因此 [\^] 会匹配字面 '\' 或 '^'.

不过这样限制太多, 所以 Boost.Regex 还支持以下与标准兼容的扩展:

运算符优先级

运算符的优先级顺序如下:

  1. 排序相关括号符号 [==] [::] [..]
  2. 转义字符 \
  3. 字符集合 (括号表达式) []
  4. 分组 ()
  5. 单字符 ERE 重复 * + ? {m,n}
  6. 连接
  7. 锚点 ^$
  8. 分支 |
匹配到什么

当一个正则表达式有多种匹配方式时, 使用 最左最长规则 获得"最佳"可能的匹配.

变体

Egrep

当表达式在设置 标志 egrep 的情况下编译时, 表达式被视为以换行符分隔的 POSIX 扩展表达式 列表; 列表中任意表达式匹配即找到匹配, 例如:

boost::regex e("abc\ndef", boost::regex::egrep);

会匹配 POSIX 基本表达式 "abc" 或 "def" 之一.

顾名思义, 该行为与 Unix 实用工具 egrep 一致, 也与带 -E 选项的 grep 一致.

awk

除 POSIX 扩展特性 外, 转义字符在字符类声明内也是特殊的.

此外, 还要求支持某些不属于 POSIX 扩展规范定义的转义序列 - 不过 Boost.Regex 无论如何都默认支持这些序列.

选项

构造正则表达式时, 多种标志 可以与 extended 和 egrep 选项组合; 尤其请注意, newline_alt 选项会改变语法, 而 collate、nosubs 和 icase 选项 则修改大小写和区域设置敏感性的应用方式.
