match_results

概要 
#include <boost/regex.hpp>

正则表达式与许多简单的模式匹配算法不同: 它不仅能找到整体匹配, 还能产生子表达式匹配; 每个子表达式在模式中用一对括号 (...) 界定. 必须有某种方法把子表达式匹配报告给用户: 这通过定义一个 match_results 类来实现, 该类充当子表达式匹配的索引集合, 每个子表达式匹配包含在一个 sub_match 类型的对象中.

模板类 match_results 表示一个由字符序列组成的集合, 代表正则表达式匹配的结果. match_results 类型的对象会被传给算法 regex_match 和 regex_search, 并由迭代器 regex_iterator 返回. 集合的存储由类 match_results 的成员函数按需分配和释放.

模板类 match_results 符合 (lib.sequence.reqmts) 中规定的序列 (Sequence) 要求, 但仅支持为 const 限定序列定义的操作.

类模板 match_results 最常见的用法是作为以下 typedef 之一: cmatch、wcmatch、smatch 或 wsmatch:

template <class BidirectionalIterator,
         class Allocator = std::allocator<sub_match<BidirectionalIterator> >
class match_results;

typedef match_results<const char*>              cmatch;
typedef match_results<const wchar_t*>           wcmatch;
typedef match_results<string::const_iterator>   smatch;
typedef match_results<wstring::const_iterator>  wsmatch;

   template <class charT, class Traits, class A>

   difference_type position(unsigned int sub = 0) const;
   difference_type position(const char_type* sub) const;
   template <class charT>
   difference_type position(const charT* sub) const;
   template <class charT, class Traits, class A>
   difference_type position(const std::basic_string<charT, Traits, A>& sub) const;
   string_type str(int sub = 0) const;
   string_type str(const char_type* sub)const;
   template <class Traits, class A>
   string_type str(const std::basic_string<char_type, Traits, A>& sub)const;
   template <class charT>
   string_type str(const charT* sub)const;
   template <class charT, class Traits, class A>
   string_type str(const std::basic_string<charT, Traits, A>& sub)const;
   const_reference operator[](int n) const;
   const_reference operator[](const char_type* n) const;
   template <class Traits, class A>
   const_reference operator[](const std::basic_string<char_type, Traits, A>& n) const;
   template <class charT>
   const_reference operator[](const charT* n) const;
   template <class charT, class Traits, class A>
   const_reference operator[](const std::basic_string<charT, Traits, A>& n) const;

   const_reference prefix() const;

   const_reference suffix() const;
   const_iterator begin() const;
   const_iterator end() const;
   // format:
   template <class OutputIterator, class Formatter>
   OutputIterator format(OutputIterator out,
                        Formatter fmt,
                        match_flag_type flags = format_default) const;
   template <class Formatter>
   string_type format(Formatter fmt,
                     match_flag_type flags = format_default) const;

   allocator_type get_allocator() const;
   void swap(match_results& that);

#ifdef BOOST_REGEX_MATCH_EXTRA
   typedef typename value_type::capture_sequence_type capture_sequence_type;
   const capture_sequence_type& captures(std::size_t i)const;
#endif

};

template <class OutputIterator, class Formatter>
OutputIterator format(OutputIterator out,
                      Formatter fmt,
                      match_flag_type flags = format_default);

要求: 类型 OutputIterator 符合输出迭代器要求 (C++ 标准 24.1.2).

类型 Formatter 必须是以下之一: 指向 char_type[] 类型以空字符结尾字符串的指针; 或一个 char_type 的容器 (例如 std::basic_string<char_type>); 或一个一元、二元或三元函子, 通过函数调用计算替换字符串: 要么是 fmt(*this) (它必须返回一个 char_type 的容器用作替换文本), 要么是 fmt(*this, out) 或 fmt(*this, out, flags) (二者都把替换文本写入 *out, 然后返回新的 OutputIterator 位置). 注意, 如果格式化器是函子, 则它是按值传递的: 想传递带内部状态的函数对象的用户可能想使用 Boost.Ref 包装该对象, 使其按引用传递.

要求: match_results 对象必须已因成功调用 regex_search 或 regex_match 而初始化, 或由 regex_iterator 返回, 且底层迭代器此后未被使无效. 如果 match_results 对象未初始化, 则会引发 std::logic_error.

效果: 如果 fmt 是以空字符结尾的字符串或 char_type 的容器, 则把字符序列 [fmt.begin(), fmt.end()) 拷贝到 OutputIterator out. 对于 fmt 中的每个格式说明符或转义序列, 用它所代表的字符或它所引用的 *this 内的字符序列替换该序列. flags 中指定的位掩码决定识别哪些格式说明符或转义序列; 默认为 ECMA-262 (ECMAScript 语言规范, 第 15 章第 5.4.11 节 String.prototype.replace) 所用的格式.

如果 fmt 是函数对象, 则根据该函数对象接受的参数个数, 它要么:

  • 调用 fmt(*this), 并把返回的字符串拷贝到 OutputIterator out.
  • 调用 fmt(*this, out).
  • 调用 fmt(*this, out, flags).

在所有情况下, 都返回 OutputIterator 的新位置.

更多信息见 格式语法指南.

返回: out.

template <class Formatter>
string_type format(Formatter fmt,
                   match_flag_type flags = format_default);

要求 类型 Formatter 必须是以下之一: 指向 char_type[] 类型以空字符结尾字符串的指针; 或一个 char_type 的容器 (例如 std::basic_string<char_type>); 或一个一元、二元或三元函子, 通过函数调用计算替换字符串: 要么是 fmt(*this) (它必须返回一个 char_type 的容器用作替换文本), 要么是 fmt(*this, out) 或 fmt(*this, out, flags) (二者都把替换文本写入 *out, 然后返回新的 OutputIterator 位置).

要求: match_results 对象必须已因成功调用 regex_search 或 regex_match 而初始化, 或由 regex_iterator 返回, 且底层迭代器此后未被使无效. 如果 match_results 对象未初始化, 则会引发 std::logic_error.

效果: 如果 fmt 是以空字符结尾的字符串或 char_type 的容器, 则拷贝字符串 fmt: 对于 fmt 中的每个格式说明符或转义序列, 用它所代表的字符或它所引用的 *this 内的字符序列替换该序列. flags 中指定的位掩码决定识别哪些格式说明符或转义序列; 默认为 ECMA-262 (ECMAScript 语言规范, 第 15 章第 5.4.11 节 String.prototype.replace) 所用的格式.

如果 fmt 是函数对象, 则根据该函数对象接受的参数个数, 它要么:

  • 调用 fmt(*this) 并返回结果.
  • 调用 fmt(*this, unspecified-output-iterator), 其中 unspecified-output-iterator 是一种未指定的 OutputIterator 类型, 用于把输出拷贝到字符串结果中.
  • 调用 fmt(*this, unspecified-output-iterator, flags), 其中 unspecified-output-iterator 是一种未指定的 OutputIterator 类型, 用于把输出拷贝到字符串结果中.

效果: 交换两个序列的内容.

typedef typename value_type::capture_sequence_type capture_sequence_type;

定义一个实现特定的类型, 它满足标准库序列 (Sequence) 的要求 (21.1.1, 包括可选的表 68 操作), 其 value_type 为 sub_match<BidirectionalIterator>. 该类型恰好是 std::vector<sub_match<BidirectionalIterator> >, 但你不应当真的依赖这一点.

const capture_sequence_type& captures(std::size_t i)const;

要求: match_results 对象必须已因成功调用 regex_search 或 regex_match 而初始化, 或由 regex_iterator 返回, 且底层迭代器此后未被使无效. 如果 match_results 对象未初始化, 则会引发 std::logic_error.

效果: 返回一个序列, 包含为子表达式 i 获得的所有捕获.

返回: (*this)[i].captures();

前置条件: 库必须在定义了 BOOST_REGEX_MATCH_EXTRA 的情况下构建和使用, 并且必须向正则表达式匹配函数 ( regex_match、regex_search、regex_iterator 或 regex_token_iterator ) 传递 match_extra 标志, 此成员函数才会被定义并返回有用的信息.

设计理由: 启用该特性会带来以下影响:

  • sub_match 占用更多内存, 导致复杂表达式在匹配期间更快地耗尽内存或栈空间.
  • 匹配算法在处理某些特性 (例如独立子表达式) 时效率更低, 即使未使用 match_extra.
  • 使用 match_extra 时, 匹配算法的效率会大幅降低 (即更慢). 这主要是由于必须进行的额外内存分配.
