历史
致谢

了解程序执行所需的时间在测试和生产环境中都很有用. 如果这类计时信息还能细分为挂钟时间、用户占用的 CPU 时间以及操作系统为响应用户请求而占用的 CPU 时间, 那就更有帮助了.

类 cpu_timer 测量挂钟时间、用户 CPU 进程时间和系统 CPU 进程时间. 类 auto_cpu_timer 是 cpu_timer 的改进版本, 它会在 auto_cpu_timer 对象被销毁时自动报告已流逝的时间.

安装

Boost.Timer 实现为需要单独编译的库, 因此你必须把二进制文件安装到链接器能找到的位置. 如果你按照 Boost 入门 的说明操作, 这一步已经替你完成了.

使用计时器

使用 auto_cpu_timer

最简单也最常见的用法是把下面高亮的两行添加到你想计时的作用域中. 源代码参见 auto_cpu_timer_example.cpp.

#include <boost/timer/timer.hpp>
#include <cmath>

int main()
{
  boost::timer::auto_cpu_timer t;

  for (long i = 0; i < 100000000; ++i)
    std::sqrt(123.456L); // burn some time

  return 0;
}

auto_cpu_timer 对象被创建时即开始计时. 当作用域结束、对象被销毁时, 其析构函数会停止计时器并在默认输出流 std::cout 上显示计时信息.

该程序的输出大致如下:

    5.713010s wall, 5.709637s user + 0.000000s system = 5.709637s CPU (99.9%)

换句话说, 按照墙上时钟的度量, 该程序运行了 5.713010 秒; 操作系统为其计入了 5.709637 秒的用户 CPU 时间和 0 秒的系统 CPU 时间, 两者合计为 5.709637, 占挂钟时间的 99.9%.

输出流、报告的小数位数以及报告格式都可以通过 auto_cpu_timer 的构造函数实参控制. 下面是上述程序在几组不同构造函数实参下的输出样子:

构造 输出
t 5.713010s wall, 5.709637s user + 0.000000s system = 5.709637s CPU (99.9%)
t(std::cerr, 2) 5.71s wall, 5.70s user + 0.00s system = 5.70s CPU (99.9%)
t(1) 5.7s wall, 5.7s user + 0.0s system = 5.7s CPU (99.9%)
t(3, "%w seconds\n") 5.713 seconds
 
t("%t sec CPU, %w sec real") 5.709637 sec CPU, 5.713010 sec real

格式字符串的处理在 此处 描述.

使用 cpu_timer

以下代码每 20 个 CPU 秒创建一个检查点:

using boost::timer::cpu_timer;
using boost::timer::cpu_times;
using boost::timer::nanosecond_type;
...
nanosecond_type const twenty_seconds(20 * 1000000000LL);
nanosecond_type last(0);
cpu_timer timer;
while (more_transactions)
{
  process_a_transaction();
  cpu_times const elapsed_times(timer.elapsed());
  nanosecond_type const elapsed(elapsed_times.system
    + elapsed_times.user);
  if (elapsed >= twenty_seconds)
  {
    ... create a checkpoint ...
    last = elapsed;
  }
}

其他注意事项

挂钟计时会受到许多外部因素的影响, 例如其他进程的影响.

cpu_timer 和 auto_cpu_timer 从 Boost.Chrono 的 high_resolution_clock 获取挂钟计时. 在运行 Windows、Linux 和 Mac OS X 的 Intel 兼容 CPU 上, 这是一个 "稳定时钟 (steady clock)" [C++11 20.11.3], 但在其他平台上可能并非稳定. cpu_timer_info.cpp 会报告 high_resolution_clock 在特定平台上是否稳定.

稳定时钟 由 C++11 标准定义为: 其值随物理时间前进永不减小、且其值以相对于真实时间的稳定速率前进的时钟. 也就是说, 该时钟不可被调整. 稳定时钟永远不会倒退, 即使操作系统的时钟被重置回退 (例如在夏令时切换期间) 也一样.

调试构建的计时结果通常比发布构建慢好几倍, 因为编译器优化被关闭, 而且库通常会在调试构建中提供代价高昂的错误检查.

基准测试代码可能被优化掉, 尤其是在定义了 NDEBUG 的情况下. 可能需要检查生成的代码以确认没有发生这种情况.

建议

想一想对你的应用什么最重要. 对于生产过程, 挂钟时间可能是最重要的. 而要研究代码效率, 总 CPU 时间 (用户 + 系统) 往往是更好的度量.

一个有用的建议是: 永远不要轻信计时结果, 除非它们 (1) 至少是 CPU 时间分辨率的 100 倍, (2) 运行多次, 并且 (3) 在发布构建上运行. 而且对于好得难以置信的结果, 应以怀疑的态度进行调查.

第一次调用计时器或其他函数时, 共享库 (DLL 与 .so) 可能带来额外的时间延迟, 包括昂贵的磁盘访问. 如果这会造成误导, 应考虑静态链接.

参考

规范按 C++ 标准库的风格给出 (C++11, 17.5.1.4 [structure.specifications]). 可以提供附加的 概述 元素以帮助理解. 概述 元素仅具说明性 -- 实际语义由其他详细规范元素给出.

未指定为 noexcept 的函数在发生内存分配错误时会抛出 std::bad_alloc 异常. 其他错误通过 -1 的时间值报告. [注释: 现代硬件和操作系统拥有健壮的时钟子系统, 因此这类错误即使可能出现也很罕见. -- 注释结束]

Timer 库满足与 C++11 标准库相同的数据竞争规避要求 (17.6.5.9 [res.on.data.races]). 除非用户提供加锁机制, 否则 Timer 库类型的共享对象会有未定义行为的风险. 参见 C++11, 17.6.4.10 [res.on.objects], Shared objects and the library.

<boost/timer/timer.hpp> 概要

namespace boost
{
  namespace timer
  {
    class cpu_timer;       // wall clock, user, and system timer
    class auto_cpu_timer;  // automatic report() on destruction 

    typedef boost::int_least64_t nanosecond_type;

    struct cpu_times
    {
      nanosecond_type wall;
      nanosecond_type user;
      nanosecond_type system;

      void clear();
    };
      
    const int           default_places = 6;

    std::string format(const cpu_times& times, short places, const std::string& format); 
    std::string format(const cpu_times& times, short places = default_places); 

  } // namespace timer
} // namespace boost

默认格式

默认格式为 " %ws wall, %us user + %ss system = %ts CPU (%p%)\n".

Typedef nanosecond_type

typedef nanosecond_type 提供一个能够表示纳秒的由实现定义的类型. 对于 POSIX 和 Windows 系统, nanoseconds_type 为 boost::int_least64_t.

底层类型不基于 Boost Date-Time 或 Chrono 库, 以避免对大型库的依赖. 这一设计选择将来可能改变.

虽然 nanosecond_type 能够表示一 纳秒, 但常见操作系统计时器的实际分辨率可能低得多. 对于 2010 年前后桌面系统的挂钟时间, 分辨率通常不会优于一 微秒. 对于用户和系统时间, Windows 上的典型分辨率为 15 毫秒, POSIX 上为 10 毫秒.

结构体 cpu_times

结构体 cpu_times 打包了已流逝的挂钟时间、用户进程 CPU 时间和系统进程 CPU 时间. 这些流逝时间的来源定义参见 当前时间值.

void clear();

效果: wall = user = system = 0LL.

命名空间作用域函数

std::string format(const cpu_times& times, short places, const std::string& format);
std::string format(const cpu_times& times, short places = default_places);

概述: 把 times 的值转换为表示秒数、保留 places 位小数的字符串, 并按 format 的控制把它们插入返回字符串.

备注: 对于不带 format 实参的重载, 使用 默认格式 作为 format.

返回: 一个字符串, 它是 format 的副本, 但下所示序列的任何实例都会被相应的值替换. 时间以秒为单位报告, 显示 std::max(0, std::min(default_places, 9)) 位小数. 百分比报告到一位小数. [注释: 由于操作系统度量各种时间的方式不同, 百分比可能超过 100%. --注释结束]

格式替换序列

序列 替换值
%w times.wall
%u times.user
%s times.system
%t times.user + times.system
%p times.wall 的百分比, 由 times.user + times.system

类 cpu_timer

cpu_timer 对象测量挂钟已流逝时间以及计入用户和系统的进程已流逝时间.

当前时间值 是由操作系统提供的当前挂钟时间、用户进程时间和系统进程时间:

  • 挂钟时间是普通手表或挂钟所度量的时间.
  • 用户进程时间是 "为执行调用进程的用户指令而计入的 CPU 时间". 参见 POSIX.
  • 系统进程时间是 "系统代表调用进程执行而计入的 CPU 时间". 参见 POSIX.

cpu_timer 概要

    
    class cpu_timer
    {
    public:

      //  constructor
      cpu_timer() noexcept;
 
      //  compiler generated; shown for exposition only
     ~cpu_timer() noexcept = default; 
      cpu_timer(const cpu_timer&) noexcept = default;
      cpu_timer& operator=(const cpu_timer&) noexcept = default;      

      //  observers
      bool         is_stopped() const noexcept;
      cpu_times    elapsed() const noexcept;
      std::string  format(int places, const std::string& format) const;
      std::string  format(int places = default_places) const;

      //  actions
      void         start() noexcept;
      void         stop() noexcept;
      void         resume() noexcept;
    };

cpu_timer 构造函数

cpu_timer() noexcept;

效果: 构造一个 cpu_timer 类型的对象. 调用 start().

cpu_timer 观测器

bool is_stopped() const noexcept;

返回: true, 如果 stop() 是最近调用的 action 函数; 否则为 false.

cpu_times elapsed() const noexcept;

返回: 如果 is_stopped(), 则为截至上一次 stop() 的累计已流逝时间. 否则, 为从最近一次调用 start() 或 resume() 到 当前时间值 之间累计的已流逝时间.

std::string       format(int places, const std::string& format) const;
std::string       format(int places = default_places) const;

概述: 返回一个字符串, 表示当前已流逝时间, 由 format 非成员函数 格式化.

返回: boost::timer::format(elapsed(), places[, format]).

cpu_timer 操作

void start() noexcept;

效果: 从 当前时间值 开始累计已流逝时间.

后置条件: !is_stopped().

void stop() noexcept;

效果: 如果 !is_stopped(), 则从 当前时间值 起停止累计已流逝时间.

[注释: 这可以通过 elapsed() 观察到. -- 注释结束]

后置条件: is_stopped().

void resume() noexcept;

概述: 重新启动计时器, 继续累计额外的已流逝时间.

效果: 如果 is_stopped(), 则从 当前时间值 起恢复累计额外的已流逝时间. 否则, 无效果.

类 auto_cpu_timer

类 auto_cpu_timer 增加了一个 report() 函数到 class cpu_timer, 并在销毁时自动调用 report().

auto_cpu_timer 概要

    
    class auto_cpu_timer : public cpu_timer
    {
    public:
      explicit auto_cpu_timer(short places = default_places);
               auto_cpu_timer(short places, const std::string& format);
      explicit auto_cpu_timer(const std::string& format);
               auto_cpu_timer(std::ostream& os, short places, const std::string& format);
      explicit auto_cpu_timer(std::ostream& os, short places = default_places);
               auto_cpu_timer(std::ostream& os, const std::string& format);

     ~auto_cpu_timer() noexcept;

      // compiler generated; shown for exposition only
      auto_cpu_timer(const auto_cpu_timer&) = default;
      auto_cpu_timer& operator=(const auto_cpu_timer&) = default;

      // observers
      std::ostream&      ostream() const noexcept;
      short              places() const noexcept;
      const std::string& format_string() const noexcept;

      // actions
      void               report();
    };

[注释: 不带 std::ostream& 实参的构造函数隐含 std::cout. 避免使用默认实参, 因为即使不使用标准流, 它也需要包含代价高昂的 <iostream>. --注释结束]

auto_cpu_timer 构造函数

explicit auto_cpu_timer(short places = default_places);
         auto_cpu_timer(short places, const std::string& format);
explicit auto_cpu_timer(const std::string& format);               
         auto_cpu_timer(std::ostream& os, short places, const std::string& format);
explicit auto_cpu_timer(std::ostream& os, short places = default_places);
         auto_cpu_timer(std::ostream& os, const std::string& format);

效果: 构造一个 auto_cpu_timer 类型的对象, 并存储建立后置条件所需的 ostream、小数位数和格式字符串数据.

后置条件:

  • 对于带有 os 实参的重载, ostream() == os. 否则 ostream() == std::cout.
  • places() == places.
  • 对于带有 format 实参的重载, format_string() == format. 否则 format_string() == std::cout

auto_cpu_timer 析构函数

~auto_cpu_timer() noexcept;

效果: 如果 !is_stopped(), 则 stop(), report().

[注释: 由于该函数是 noexcept, 实现必须确保没有任何异常逸出. --注释结束]

auto_cpu_timer 观测器

这些观测器允许测试构造函数的后置条件并规定其他功能, 而无需求助于 "仅为说明 (for exposition only)" 的私有成员.

std::ostream& ostream() const noexcept;

返回: 构造时或后续拷贝赋值所存储的 ostream.

short places() const noexcept;

返回: 构造时或后续拷贝赋值所存储的小数位数 (places).

const std::string& format_string() const noexcept;

返回: 构造时或后续拷贝赋值所存储的格式字符串.

auto_cpu_timer 操作

void report();

效果: 如同执行以下操作:

ostream() << timer::format(elapsed(), places(), format_string());

[注释: 先调用 stop() 再调用 report() 可能是可取的, 因为在计时器运行期间进行 I/O 可能产生误导性的结果. 之后可以调用 resume() 继续计时. --注释结束]
