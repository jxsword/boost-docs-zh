说明

Orderable 概念表示全序数据类型.

直观地说, Orderable 对象必须定义一个名为 less 的二元谓词, 返回第一个实参是否应被视为小于第二个实参. "total" (全) 一词意味着不同的对象必须总是可比的; 若 a 与 b 不相等, 则 less(a, b) 与 less(b, a) 中恰有一个为真. 这与允许某些对象不可比 (既不小于也不大于) 的更弱的序形成对照. 另请注意, 通过设置

a <= b = !(b < a)
a < b = !(b <= a)

定律描述采用非严格版本, 是因为它更易于人类阅读, 但同样可以用严格序等价地表述.

最小完整定义

less

当 less 有定义时, 其他方法用它按下方定律所规定的同一定义推导.

Laws

严格地说, 全序 <= 是集合 S 上的一个二元谓词 \( <= \; : S \times S \to bool \ ), 使得对所有的 a, b, c (属于 S),

if a <= b 且 b <= a then a == b // 反对称性
if a <= b 且 b <= c then a <= c // 传递性
either a <= b or b <= a // 完全性

a >= b 当 且仅 当 !(a < b)

<tt>LessThanComparable</tt> 数据类型的自由模型

两个数据类型 T 与 U 若建模通常 LessThanComparable C++ 概念的跨类型版本, 则通过如下设置自动成为 Orderable 的模型:

less(x, y) = (x < y)

LessThanComparable 概念的跨类型版本类似于 N3351 中给出的 EqualityComparable 概念的跨类型版本, 后者与通常的单类型定义兼容. 但请注意, LessThanComparable 概念只要求 < 是严格弱序, 这比全序弱. 因此, 若 less 与未定义全序的 LessThanComparable 数据类型的对象一起使用, 某些算法可能出现意外行为. 本库作者认为把 operator< 定义为非全序是个坏主意, 但这有争议, 因此为 LessThanComparable 数据类型提供模型的设计选择也有争议. 等待用户的反馈.

保序函数

设 A 与 B 为两个 Orderable 数据类型. 函数 \( f : A \to B\) 若保持 Orderable 概念的结构, 则称为保序的 (也称单调). 严格地说, 对所有对象 x, y (数据类型为 A),

if less(x, y) then less(f(x), f(y))

另一个重要性质是保序反映 (order-reflecting), 可表述为

if less(f(x), f(y)) then less(x, y)

我们称既保序又保序反映的函数为序嵌入 (order-embedding), 即

less(x, y) if and only if less(f(x), f(y))

方法的跨类型版本

比较方法 (less, less_equal, greater 和 greater_equal) 被"重载"以处理具有某些性质的不同数据类型. 具体而言, 对满足下列条件的不同数据类型 A 与 B 定义:

  1. A 与 B 共享一个公共数据类型 C, 由 common 元函数判定
  2. A, B 和 C 单独来看都是 Orderable
  3. \( \mathrm{to<C>} : A \to C \) 与 \( \mathrm{to<C>} : B \to C \) 都是序嵌入, 由 is_embedding 元函数判定.

对满足上述性质的数据类型, 方法定义为

less(x, y) = less(to<C>(x), to<C>(y))
less_equal(x, y) = less_equal(to<C>(x), to<C>(y))
greater_equal(x, y) = greater_equal(to<C>(x), to<C>(y))
greater(x, y) = greater(to<C>(x), to<C>(y))

方法的部分应用

less, greater, less_equal 和 greater_equal 方法可以以两种不同方式调用. 首先, 可以像普通函数一样调用:

less(x, y)
greater(x, y)
less_equal(x, y)
greater_equal(x, y)

不过它们也可以按如下方式对实参做部分应用:

less.than(x)(y) == less(y, x)
greater.than(x)(y) == greater(y, x)
less_equal.than(x)(y) == less_equal(y, x)
greater_equal.than(x)(y) == greater_equal(y, x)

请务必注意实参顺序是颠倒的, 例如 less.than(x)(y) 等价于 less(y, x) 而非 less(x, y). 这是因为这些变体旨在与高阶算法配合使用, 在那里所选取的应用顺序才有意义.

返回先对两个实参应用变换、再执行 less 的函数.

ordering 基于把函数应用到若干对象的结果创建一个全序, 这与接受必须表示全序的自定义谓词的算法配合使用时特别有用.

具体而言, ordering 满足

ordering(f) == less ^on^ f
