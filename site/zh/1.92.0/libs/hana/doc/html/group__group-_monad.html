说明

Monad 概念表示具有展平嵌套结构层级能力的 Applicative.

历史上, Monad 是来自范畴论 (数学的一个抽象分支) 的构造. 函数式编程社群最终发现 Monad 可用于形式化副作用等若干有用的东西, 这使得 Monad 在该社群得到广泛采用. 然而, 即使在 C++ 这样的多范式语言中, 也有若干构造结果是 Monad, 例如 std::optional, std::vector 等.

每个人都试图用不同的类比来介绍 Monad, 而大多数人都会失败. 这被称为 [Monad tutorial fallacy][1]. 我们将避免这个陷阱: 不提供任何特定的直觉, 而是直接从数学上说明什么是单子. 至于具体的直觉, 我们让初学者去阅读网上众多优秀教程之一. 理解 Monad 一开始可能需要时间, 但一旦想通, 许多模式都会显露出 Monad 的本色; 这份顿悟就是你努力的回报.

定义 Monad 的方式有多种; Haskell 使用一个叫 bind 的函数 (>>=) 和另一个叫 return 的函数 (与 C++ 的 return 语句毫无关系), 然后引入一个类型要成为 Monad 必须用这些函数满足的关系. 数学家有时使用一个叫 join 的函数和另一个叫 unit 的函数, 或有时使用其他范畴论构造, 如函子伴随和 Kleisli 范畴.

本库采用组合式方法. 首先, 我们用 flatten 函数 (等价于 join) 连同 lift 函数 (来自 Applicative, 等价于 unit) 引入单子函数组合的概念. 然后, 我们用这个单子组合运算符写出 Monad 必须满足的性质, 因为我们觉得这比其他方式更清楚地展示了 Monad 与 Monoid 之间的联系.

粗略地说, 我们把 Monad 称为一个 Applicative, 它还定义了一种组合返回单子结果的函数的方式, 而非只能组合返回普通结果的函数. 与普通函数组合一样, 我们要求这种组合满足结合律并具有单位元. 对普通组合而言, 单位元是恒等函数 id. 对单子组合而言, 单位元是 lift 函数 (由 Applicative 定义). 这一构造在下方定律中更为清晰.

注释
Monad 众所周知难以消化. 然而, 为该概念提供完整详尽的解释超出了本文档的范围. [Typeclassopedia][2] 是一个不错的 Haskell 导向资料, 其中可以找到关于 Monad 的更多信息.

最小完整定义

首先, Monad 必须既是 Functor 又是 Applicative. 同时, 必须提供满足下述单子组合定律的 flatten 或 chain 实现.

注释
ap 方法 (对 Applicatives 而言) 可以从 Monad 与 Functor 的最小完整定义推导; 更多信息见下文.

Laws

为简化定律的书写, 我们使用函数之间的比较. 对两个函数 f 与 g, 我们定义

f == g 当 且仅 当 f(x) == g(x) 对 任意 x

对于通常的函数组合, 我们给定两个函数 \( f : A \to B \ ) 与 \( g : B \to C \ ), 并产生新函数 \( compose(g, f) : A \to C \ ). 这种函数组合满足结合律, 即

compose(h, compose(g, f)) == compose(compose(h, g), f)

此外, 这种组合具有单位元, 即恒等函数. 这只是意味着

compose(f, id) == compose(id, f) == f

如果你正在读 Monad 定律, 这可能不算新知识. 现在, 我们可以观察到, 上述内容等价于说: 带有组合运算符的函数构成一个 Monoid, 其单位元是恒等函数.

给定 Applicative F, 如果我们想组合两个函数 \( f : A \to F(B) \ ) 和 \( g : B \to F(C) \ ) 会怎样? 当 Applicative F 同时也是 Monad 时, 这类接受普通值但返回单子值的函数被称为单子函数. 要组合它们, 显然不能使用普通函数组合, 因为 f 与 g 的定义域和陪域无法正确匹配. 我们需要一个新运算符 — 不妨称之为 monadic_compose:

◆ tap

template<typename M >
constexpr auto boost::hana::tap
constexpr

#include <boost/hana/fwd/tap.hpp>

初始值:
= [](auto&& f) {
return tag-dispatched;
}

在单子链内执行 tap.

给定函数 f, tap<M> 返回一个新函数: 先对实参执行 f, 然后返回提升到 M Monad 中的实参. 结合 chain(m, lift<M>) == m 这一性质, 这提供了一种在单子链内执行动作而不影响整体结果的方式. 例如插入调试语句, 或执行那些不属于链本身但需要在链内执行的动作.

注释
由于 C++ 不是纯语言, 可以在 f 函数内执行副作用. 实际上, 副作用正是想用 tap 的唯一理由. 但不应依赖副作用以任何特定顺序执行.
模板参数
M被 tap 的单子链中各单子的标签 (一个 Monad).
参数
f要在单子链中执行的函数. 它将以 f(x) 形式被调用, 其中 x 是链中前一个单子内的值. f 的结果总是被丢弃.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)
#include <boost/hana/assert.hpp>
#include <boost/hana/chain.hpp>
#include <boost/hana/equal.hpp>
#include <boost/hana/tap.hpp>
#include <boost/hana/tuple.hpp>
#include <set>
namespace hana = boost::hana;
int main() {
// 我们使用有序容器, 因为函数的调用顺序
// 未被指定.
std::set<int> before, after;
auto xs = hana::make_tuple(1, 2, 3)
| hana::tap<hana::tuple_tag>([&](int x) { before.insert(x); })
| [](auto x) { return hana::make_tuple(x, -x); }
| hana::tap<hana::tuple_tag>([&](int x) { after.insert(x); });
BOOST_HANA_RUNTIME_CHECK(before == std::set<int>{1, 2, 3});
BOOST_HANA_RUNTIME_CHECK(after == std::set<int>{1, -1, 2, -2, 3, -3});
BOOST_HANA_RUNTIME_CHECK(xs == hana::make_tuple(1, -1, 2, -2, 3, -3));
}
