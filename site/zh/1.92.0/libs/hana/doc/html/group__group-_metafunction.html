说明

Metafunction 是一个函数, 以 hana::type 为输入并返回 hana::type 作为输出.

Metafunction 是满足 FunctionObject 概念的对象, 但还带有额外要求. 首先, 必须能把 Metafunction 应用到标签为 type_tag 的实参上, 且这种应用的结果必须是标签同样为 type_tag 的对象. 注意 hana::type 和 hana::basic_type 是仅有的这类类型.

其次, Metafunction 必须提供嵌套的 ::apply 模板, 允许执行与调用运算符相同的类型级计算. 用 Boost.MPL 的说法, Metafunction F 因此是一个 MetafunctionClass, 并且还是一个 FunctionObject. 严格地说, 对任何对象 f (类型为 F, 且是一个 Metafunction) 以及任意类型 T..., 以下必须成立:

f(hana::type_c<T>...) == hana::type_c<F::apply<T...>::type>
boost::hana::apply
constexpr auto apply
以给定实参调用 Callable.
定义: apply.hpp:40

第三, 为了便于值与类型的互操作, Metafunction 还必须允许以非 hana::type 的实参调用. 此时结果等价于对该实参的类型调用元函数. 严格地说, 这意味着对任意对象 x...,

f(x...) == f(hana::type_c<decltype(x)>...)

最小完整定义

Metafunction 概念没有基于标签分派方法的最小完整定义. 取而代之, 应满足上文记载的语法要求, 并在 Hana 的命名空间中显式特化 Metafunction 结构.

具体模型

hana::metafunction, hana::metafunction_class, hana::template_

设计理由: 为什么不让 <tt>Metafunction</tt> 建模 <tt>Comparable</tt>?

看到 hana::template_ 时, 一个自然的问题是 Metafunction 是否应当做成 Comparable. 的确, 比较两个模板 F 与 G (用 template_<F> == template_<G>) 似乎合理. 然而, 当 F 和/或 G 是别名模板时, 有两种比较可谈. 第一种是浅比较, 它判定两个别名模板相等当且仅当它们是同一个别名模板. 第二种是深比较, 它判定两个模板别名相等当且仅当对任意模板实参它们都别名到同一类型. 例如, 给定 F 与 G 定义为

template <typename T>
using F = void;
template <typename T>
using G = void;

浅比较会判定 F 与 G 不同, 因为它们是两个不同的模板别名; 而深比较会判定 F 与 G 相等, 因为它们总是展开为同一类型 void. 遗憾的是, 深比较无法实现, 因为需要对所有可能的类型检查 F 与 G. 另一方面, 浅比较也不能令人满意, 因为 Metafunction 无非是作用在 type 上的函数, 而两个函数的相等通常以深比较定义. 因此, 我们采取保守立场, 不为 Metafunction 提供比较.

把模板提升为 Metafunction.

给定模板类或模板别名 f, template_<f> 是满足下式的 Metafunction:

template_<f>(type_c<x>...) == type_c<f<x...>>
decltype(template_<f>)::apply<x...>::type == f<x...>
注释
在 SFINAE 上下文中, 表达式 template_<f>(type_c<x>...) 在表达式 f<x...> 合法时总是合法.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)
#include <boost/hana/assert.hpp>
#include <boost/hana/equal.hpp>
#include <boost/hana/type.hpp>
#include <type_traits>
namespace hana = boost::hana;
template <typename ...> struct f;
struct x;
struct y;
BOOST_HANA_CONSTANT_CHECK(hana::template_<f>() == hana::type_c<f<>>);
BOOST_HANA_CONSTANT_CHECK(hana::template_<f>(hana::type_c<x>) == hana::type_c<f<x>>);
BOOST_HANA_CONSTANT_CHECK(hana::template_<f>(hana::type_c<x>, hana::type_c<y>) == hana::type_c<f<x, y>>);
static_assert(std::is_same<
decltype(hana::template_<f>)::apply<x, y>::type,
f<x, y>
>::value, "");
int main() { }

把 Metafunction 变换成接受 type 并返回默认构造对象的函数.

给定 Metafunction f, integral 返回一个新的 Metafunction, 它对 f 返回的类型进行默认构造. 更具体地说, 下式成立:

integral(f)(t...) == decltype(f(t...))::type{}
boost::hana::integral
constexpr auto integral
把 Metafunction 变换成接受类型并返回默认构造对象的函数.
定义: type.hpp:513

integral 的主要用例是把返回某类型的 Metafunction 变换成函数, 前者返回的类型继承自 std::integral_constant 这类有意义基类, 后者返回例如 hana::integral_constant.

注释
  • 这不是 Metafunction, 因为它不返回 type. 因此, 把 decltype(integral(f)) 做成像通常 Metafunction 那样的 MPL 元函数类并无意义.
  • 把 integral 与返回 std::integral_constant 的元函数一起使用时, 别忘了包含 boost/hana/ext/std/integral_constant.hpp 头文件, 确保 Hana 能与结果互操作.
  • 在 SFINAE 上下文中, 表达式 integral(f)(t...) 在表达式 decltype(f(t...))::type 合法时总是合法.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)
#include <boost/hana/assert.hpp>
#include <boost/hana/ext/std/integral_constant.hpp>
#include <boost/hana/not.hpp>
#include <boost/hana/type.hpp>
#include <type_traits>
namespace hana = boost::hana;
constexpr auto is_void = hana::integral(hana::metafunction<std::is_void>);
BOOST_HANA_CONSTANT_CHECK(is_void(hana::type_c<void>));
BOOST_HANA_CONSTANT_CHECK(hana::not_(is_void(hana::type_c<int>)));
int main() { }
