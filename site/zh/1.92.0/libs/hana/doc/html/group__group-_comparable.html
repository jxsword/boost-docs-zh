说明

Comparable 概念定义相等与不等.

直观地说, Comparable 对象必须定义一个名为 equal 的二元谓词, 返回两个对象是否表示同一抽象值. 换言之, equal 必须检查深层相等. 由于"表示同一抽象值"难以形式化表述, 相等的确切含义部分地交由程序员按以下准则自行解释:

  1. 相等应与拷贝构造兼容; 拷贝构造一个值应得到一个 equal 值.
  2. 相等应与表示方式无关; 以 4/8 表示分数的对象应当 equal 以 2/4 表示分数的对象, 因为它们表示的是同一个数学对象 1/2.

此外, equal 还必须表现出使其能直观用于判定对象等价的性质, 这由 Comparable 的定律形式化.

最小完整定义

  1. equal
    当 equal 有定义时, not_equal 默认实现为其补运算. 对所有对象 x, y (标签为 Comparable),
    not_equal(x, y) == not_(equal(x, y))

Laws

equal 必须定义一个等价关系, 而 not_equal 必须是其补. 换言之, 对所有对象 a, b, c (标签为 Comparable), 下述必须成立:

equal(a, a) // 自反性
if equal(a, b) then equal(b, a) // 对称性
if equal(a, b) && equal(b, c) then equal(a, c) // 传递性
not_equal(a, b) 等价于 not_(equal(a, b))

<tt>EqualityComparable</tt> 数据类型的自由模型

两个数据类型 T 与 U 若建模 N3351 中提出的跨类型 EqualityComparable 概念, 则通过设置下式, 自动建模 Comparable 概念:

equal(x, y) = (x == y)

注意, 这同样使通常意义下的 EqualityComparable 类型以相同方式成为 Comparable 的模型.

保持相等性的函数

设 A 与 B 为两个 Comparable 标签. 函数 \(f : A \to B\) 若保持 Comparable 概念的结构, 则称为保持相等性的. 严格地说, 对所有对象 x, y (标签为 A),

if equal(x, y) then equal(f(x), f(y))

等价地, 我们只要求 f 是通常数学意义上的函数. 另一个性质是单射性 (injectivity), 可视为一种"无损耗"映射. 该性质可表述为

if equal(f(x), f(y)) then equal(x, y)

这等价于说 f 把不同元素映射到不同元素, 因此有"无损耗"的类比. 换言之, f 不会把定义域中不同的元素坍缩到其像中的单个元素而丢失信息.

这些函数非常重要, 尤其是保持相等性的那些, 因为它们使我们能简单地对程序进行推理. 另请注意, 保持相等性这一性质在数学中被视为理所当然, 因为它是函数定义的一部分. 我们认为在这里做区分很重要, 因为编程的演进路径不同, 程序员已经习惯了使用不保持相等性的函数.

方法的跨类型版本

equal 与 not_equal 方法被"重载"以处理具有某些性质的不同标签. 具体而言, 对满足下列条件的不同标签 A 与 B 定义:

  1. A 与 B 共享一个公共标签 C, 由 common 元函数判定
  2. A, B 和 C 单独来看都是 Comparable
  3. \( \mathtt{to<C>} : A \to C \ ) 与 \( \mathtt{to<C>} : B \to C \ ) 都是保持相等性且单射的 (即它们是嵌入), 由 is_embedding 元函数判定.

对满足上述性质的标签, 方法定义为

equal(x, y) = equal(to<C>(x), to<C>(y))
not_equal(x, y) = not_equal(to<C>(x), to<C>(y))

重要说明: <tt>equal</tt> 的特殊行为

在异构值编程的语境中, 让不相关对象比较出 false 而不是触发错误是有用的. 为此, equal 对不满足上述跨类型重载要求的、标签为 T 与 U 的不相关对象采用特殊行为. 具体而言, 当 T 与 U 不相关 (即 T 无法转换为 U, 反之亦然) 时, 比较这些标签的对象会得到编译期 false 值. 其效果是: 像 float 和 std::string 这样的不相关对象比较结果为 false, 而比较相关但无法安全嵌入同一超结构的相关对象 (如 long long 与 float, 因精度损失) 会触发编译期断言. 另请注意, 对任何标签 T, 若未提供 Comparable 的最小完整定义, 也会触发编译期断言, 因为 T 与 T 平凡地共享公共标签 T, 这是预期行为. 这一设计选择旨在为对象比较提供更多灵活性, 同时仍拒绝最可能是编程错误的使用模式.

返回一个 Logical, 表示 x 是否等于 y.

equal 函数可以以两种不同方式调用. 首先, 可以像普通函数一样调用:

equal(x, y)

不过它也可以用 equal.to 对某个实参做部分应用:

equal.to(x)(y) == equal(x, y)

换言之, equal.to(x) 是一个等价于 partial(equal, x) 的函数对象. 这是为了增强某些构造的可读性, 尤其在使用高阶算法时.

Signature

给定 Logical Bool 与共享公共嵌入的两个 Comparable A 和 B, 签名为 \( \mathtt{equal} : A \times B \to Bool \ ).

参数
