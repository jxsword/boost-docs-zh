返回对象的标签是否与给定标签匹配.

给定一个 tag Tag 和一个 C++ 类型 T, is_a<Tag, T> 是一个编译期 Logical, 表示 T 的 tag 是否恰好为 Tag. 换言之, 它等价于

std::is_same<Tag, tag_of<T>::type>

为方便起见, 为使用 is_a 提供了另一种语法. 具体来说, is_a<Tag> 是一个函数对象, 返回传给它的实参是否具有给定的 tag. 换言之,

is_a<Tag>(x) == is_a<Tag, decltype(x)>

用给定实参创建一个具有给定 tag 的对象.

这个函数的作用与通常 C++ 中的构造函数相同. 不过, 它创建的不是特定 C++ 类型的对象, 而是特定 tag 的对象, 无论该对象的 C++ 类型是什么.

这个函数实际上是一个变量模板, 因此 make<T> 可以作为一个函数对象传递, 用于创建 tag 为 T 的对象. 此外, 它使用 tag 分派, 所以这就是为用户自定义 tag 对它进行定制的方式.

最后, make 的默认实现等价于用相应实参调用给定 tag 的构造函数. 换言之, 默认情况下,

make<T>(args...) == T(args...)

注意, 实参被完美转发, 且使用的构造形式与文档所述完全一致, 即 T(args...). 但是, 如果 T(args...) 不是有效的表达式, 将触发编译错误. 这个默认行为很有用, 因为它使没有 tag 概念的外来 C++ 类型可以开箱即用地用 make 构造, 因为它们的 tag 就是它们自身.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)
#include <boost/hana/assert.hpp>
#include <boost/hana/core/make.hpp>
#include <boost/hana/equal.hpp>
#include <boost/hana/tuple.hpp>
#include <string>
namespace hana = boost::hana;
int main() {
hana::tuple<int, char, double, std::string> ts{1, '2', 3.3, "abcd"};
BOOST_HANA_RUNTIME_CHECK(ts == hana::make_tuple(1, '2', 3.3, std::string{"abcd"}));
// std::string 没有 tag 的概念, 但它仍可与 make<> 一起使用
std::string foo{"foo"};
BOOST_HANA_RUNTIME_CHECK(hana::make<std::string>("foo") == foo);
}

把对象从一种数据类型转换为另一种数据类型.

to 是把 static_cast 语言构造扩展到数据类型上的产物. 给定目标数据类型 To 和对象 x, to 会创建一个数据类型为 To 的新对象 (源自 x) . 但请注意, 并不要求 to 真正创建新对象, 它可以返回对原对象的引用 (例如当试图把对象转换到它自己的数据类型时) .

作为 static_cast 的自然扩展, to 提供默认行为. 为便于下文叙述, 设 To 为目标数据类型, From 为 x 的数据类型, 即源数据类型. 那么 to 有如下默认行为:

  1. 如果 To 与 From 数据类型相同, 则对象原样转发.
  2. 否则, 如果 From 可转换为 To (使用 static_cast) , 则 x 被转换为 From (使用 static_cast) .
  3. 否则, 调用 to<From>(x) 会触发静态断言.

不过, to 是一个通过 tag 分派的函数, 这意味着可以特化 to_impl (在 boost::hana 命名空间中) , 以针对任意数据类型定制其行为. 另请注意, to 同时使用 To 和 From 数据类型进行 tag 分派, 这意味着 to_impl 以 to_impl<To, From>::apply(x) 的形式调用. 另请注意, 有些概念提供从其模型出发或到达其模型的转换. 例如, 任何 Foldable 都可以转换为 Sequence. 这是通过特化 to_impl<To, From> 实现的 (当 To 是 Sequence 且 From 是 Foldable 时) . 当提供了这类转换时, 它们会在源概念 (此处即 Foldable) 的文档中说明.

Hana 可转换性

当对象 x (数据类型为 From) 可以转换为数据类型 To (使用 to) 时, 我们说 x 可以 Hana 转换到数据类型 To. 我们也说存在一个从 From 到 To 的 Hana 转换. 这点术语有助于避免混淆 C++ 提供的各种转换.

Embeddings

正如你可能已经注意到的, Hana 到处都在使用代数与范畴论结构, 以帮助严格地规定概念. 这些结构总是带有与之关联的运算, 这正是它们有用的原因. 嵌入这一概念刻画了把较小结构注入较大结构、同时保持结构运算的想法. 换言之, 嵌入是既单射又保持结构的映射. 结构的运算被保持究竟意味着什么, 留给每个结构的文档去解释. 例如, 当我们谈到从 Monoid A 到 Monoid B 的 Monoid 嵌入时, 我们的意思只是一个保持单位元和结合运算的单射变换, 如 Monoid 的文档所述.

但这与 to 函数有什么关系呢? 很简单, to 函数是两个数据类型之间的映射, 这些数据类型有时会是某种结构, 而知道这种映射是否良态 (即无损且保持结构) 有时是有用的. 这种转换良态的判据恰恰就是成为嵌入. 要指明某个转换是嵌入, 只需把 embedding 类型用作相应 to_impl 特化的基类. 显然, 你应当确保该转换确实是嵌入, 除非你想搬起石头砸自己的脚.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)
#include <boost/hana/assert.hpp>
#include <boost/hana/config.hpp>
#include <boost/hana/core/to.hpp>
#include <boost/hana/equal.hpp>
#include <boost/hana/tuple.hpp>
namespace hana = boost::hana;
template <typename X, typename Y, typename Z>
struct Triple {
X first;
Y second;
Z third;
};
BOOST_HANA_CONSTEXPR_LAMBDA auto triple = [](auto x, auto y, auto z) {
return Triple<decltype(x), decltype(y), decltype(z)>{x, y, z};
};
namespace boost { namespace hana {
template <typename X, typename Y, typename Z>
struct to_impl<tuple_tag, Triple<X, Y, Z>> {
static constexpr auto apply(Triple<X, Y, Z> xs) {
return make_tuple(xs.first, xs.second, xs.third);
}
};
}}
int main() {
BOOST_HANA_CONSTEXPR_CHECK(
hana::to<hana::tuple_tag>(triple(1, '2', 3.3)) == hana::make_tuple(1, '2', 3.3)
);
}
