说明

Searchable 概念表示可搜索的结构.

直观地说, Searchable 是任何 (有限或无限) 包含可用谓词搜索的元素的结构. 有时, Searchable 会把键关联到值; 可以用谓词搜索键, 并返回关联的值. 这就产生了类 map 的数据结构. 另一些时候, 被搜索的结构元素 (即谓词作用的对象) 与被返回的元素相同, 这就产生了类 set 的数据结构. 一般地, 我们把键称为 Searchable 结构中用于搜索的那些元素, 把值称为 Searchable 中搜索成功时返回的那些元素. 如前所述, 两个概念并不要求不同, 且让键与值重合往往很有用 (想想 std::set).

any_of, all_of 和 none_of 等方法允许对结构的键做简单查询, 而 find 和 find_if 等方法则能找到与键关联的值. 若在意性能, 应始终使用最专门的方法, 因为越专门的方法通常越能做重量级优化. 例如, 以哈希表实现关联式数据结构时, 用 find 访问远比 find_if 快, 因为后者要对所有条目做线性搜索. 类似地, 使用 contains 大概率比用等价谓词的 any_of 快得多.

洞见
在惰性求值上下文中, 任何 Foldable 也可以成为 Searchable 的模型, 因为我们可以用 fold_right 在结构中惰性地搜索. 然而, 在 C++ 的语境中, 有些 Searchable 无法折叠; 例如想想无限集合.

最小完整定义

find_if and any_of

当提供了 find_if 与 any_of 时, 其余函数按下文解释的定律实现.

注释
我们本可以把 any_of(xs, pred) 实现为: 检查 find_if(xs, pred) 是否为空 optional, 从而把最小完整定义归约为 find_if. 但没有这样做, 因为该实现要求 any_of 的谓词返回编译期 Logical, 比现状更受限.

Laws

为使各方法的语义保持一致, Searchable 概念的任何模型都必须满足一些性质. 严格地说, 对任意 Searchable (xs 与 ys) 和任意谓词 p, 应满足以下定律:

any_of(xs, p) <=> !all_of(xs, negated p)
<=> !none_of(xs, p)
contains(xs, x) <=> any_of(xs, equal.to(x))
find(xs, x) == find_if(xs, equal.to(x))
find_if(xs, always(false_)) == nothing
is_subset(xs, ys) <=> all_of(xs, [](auto x) { return contains(ys, x); })
is_disjoint(xs, ys) <=> none_of(xs, [](auto x) { return contains(ys, x); })

具体模型

hana::map, hana::optional, hana::range, hana::set, hana::string, hana::tuple

内建数组的自由模型

大小已知的内建数组可以像同质元组一样进行查找. 然而, 由于数组只能保存单一类型的对象, 且传给 find_if 的谓词必须返回编译期 Logical, find_if 方法基本没有用处. 出于同样的原因, find 方法也基本没有用处. 提供这个模型主要是因为 any_of 方法及其同类方法, 它们既实用又在编译期高效.

保持结构的函数

给定两个 Searchables S1 和 S2, 称函数 \( f : S_1(X) o S_2(X) \) 保持 Searchable 结构, 如果对所有 xs (数据类型为 S1(X)) 以及谓词 \( \mathtt{pred} : X o Bool \) (针对一个 Logical Bool) ,

any_of(xs, pred) 当且仅当 any_of(f(xs), pred)
find_if(xs, pred) == find_if(f(xs), pred)

这实际上只是下面这组更直观要求的推广. 对于所有 xs (数据类型为 S1(X)) 以及 x (数据类型为 X) ,

x ^in^ xs 当且仅当 x ^in^ f(xs)
find(xs, x) == find(f(xs), x)

返回结构中与给定键相关联的值, 否则失败.

给定一个 key 和一个 Searchable 结构, at_key 返回第一个键等于给定 key 的值; 如果不存在这样的键, 则在编译期失败. 这要求 key 为编译期 Comparable, 正如 find 一样. at_key 满足以下条件:

at_key(xs, key) == find(xs, key).value()

◆ is_subset

constexpr auto boost::hana::is_subset
constexpr

#include <boost/hana/fwd/is_subset.hpp>

初值:
= [](auto&& xs, auto&& ys) {
return tag-dispatched;
}

返回一个结构是否包含另一个结构键的子集.

给定两个 Searchable xs 和 ys, is_subset 返回一个 Logical, 表示 xs 是否为 ys 的子集. 换言之, 它返回 xs 的所有键是否也存在于 ys 中. 此方法并不返回 xs 是否为严格意义下 ys 的子集; 如果 xs 和 ys 相等, 则 xs 的所有键也都存在于 ys 中, is_subset 返回真.

注释
为方便起见, is_subset 也可以用中缀表示法应用.

方法的跨类型版本

此方法使用两个实参的 tag 进行分派. 它可以对任意两个 Searchable 调用 (前提是它们共享公共的 Searchable 嵌入) , 如 Searchable 概念主文档中所定义. 当具有两个不同 tag 但共享公共嵌入的 Searchable 被传给 is_subset 时, 它们会先被转换到这个公共 Searchable, 然后使用该公共嵌入的 is_subset 方法. 当然, 对于自定义 Searchable, 也可以出于效率考虑重写此方法.

注释
虽然 is_subset 支持跨类型分派, 但库目前并未使用它, 因为不存在共享公共嵌入的 Searchable 模型.
参数
xs要检查是否为 ys 的子集的结构.
ys要检查是否为 xs 的超集的结构.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)

#include <boost/hana/tuple.hpp>
namespace hana = boost::hana;
static_assert(
hana::is_subset(hana::make_tuple(1, '2', 3.3), hana::make_tuple(3.3, 1, '2', nullptr))
, "");
// is_subset 可以用中缀表示法应用
static_assert(
hana::make_tuple(1, '2', 3.3) ^hana::is_subset^ hana::make_tuple(3.3, 1, '2', nullptr)
, "");
int main() { }
