Functor
Concepts

Functor 概念表示可映射的类型.

直观地说, Functor 是某种能容纳泛型数据的盒子, 可以对盒中的数据映射一个函数, 从而创建一个新的、变换后的盒子. 因为我们只关心在黑盒内容上映射函数, 成为函子的真正要求只是提供一个能做映射的函数, 外加映射行为良好的若干保证. 这些要求在下述定律中精确化. Functor 所刻画的模式非常通用, 因此用途广泛. 许多对象都能以某种方式成为 Functor, 最明显的例子是序列, 即把函数常规地映射到每个元素. 本文档不再深入函子的本质; Typeclassopedia 是一个不错的 Haskell 导向资料, 可供参考.

Functor 是参数化的数据类型, 以其包含对象的数据类型为参数. 与 Hana 中其他地方一样, 这种参数化只停留在文档层面, 并不被强制执行.

在本库中, 映射函数命名为 transform, 取自 std::transform 算法; 其他编程语言给它起了不同的名字 (通常是 map).

注释
functor 一词来自函数式编程, 该概念在那里已使用多年, 尤其是在 Haskell 语言中. Haskell 人从范畴论借用了这个术语; 泛泛地说, 范畴论是数学中处理抽象结构及其间变换的领域.

Laws

设 xs 为标签为 F(A) 的 Functor, \( f : A \to B \ ) 与 \( g : B \to C \ ). 必须满足以下定律:

transform(xs, id) == xs
transform(xs, compose(g, f)) == transform(transform(xs, f), g)
boost::hana::compose
constexpr auto compose
返回两个或更多函数的组合.
定义: compose.hpp:52

第一行说明映射恒等函数不应有任何作用, 这排除了函子在幕后做恶劣勾当的可能. 第二行说明映射两个函数的组合等同于先映射第一个函数、再对结果映射第二个函数. 通常的函子定律一般仅限于以上内容, 但本库还包含其他便捷方法, 它们应满足以下等式. 设 xs 为标签为 F(A) 的 Functor, \( f : A \to A \ ), \( \mathrm{pred} : A \to \mathrm{Bool} \ ) (其中 Logical 为某个 Bool), 以及 oldval, newval, value 为标签 A 的对象. 那么,

adjust(xs, value, f) == adjust_if(xs, equal.to(value), f)
adjust_if(xs, pred, f) == transform(xs, [](x){
if pred(x) then f(x) else x
})
replace_if(xs, pred, value) == adjust_if(xs, pred, always(value))
replace(xs, oldval, newval) == replace_if(xs, equal.to(oldval), newval)
fill(xs, value) == replace_if(xs, always(true), value)

Functor 的保持结构的函数

两个函子之间也保持函子定律的映射称为自然变换 (该术语来自范畴论). 自然变换是一个函数 f, 从函子 F 映到函子 G, 使得对每个具有合适签名的其他函数 g 以及每个对象 xs (标签为 F(X)),

f(transform(xs, g)) == transform(f(xs), g)

这类变换有几个例子, 例如把 to<tuple_tag> 应用到 optional 值. 的确, 对任何函数 g 和 hana::optional opt,

to<tuple_tag>(transform(opt, g)) == transform(to<tuple_tag>(opt), g)

当然, 自然变换并不限于 to<...> 函数. 但请注意, Functor 之间的任何转换函数若要使转换行为直观, 就应当是自然的.
