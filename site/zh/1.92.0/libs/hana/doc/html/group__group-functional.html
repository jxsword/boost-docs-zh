template<std::size_t n>
constexpr auto boost::hana::arg
constexpr

#include <boost/hana/functional/arg.hpp>

初值:
= [](auto&& x1, ..., auto&& xm) -> decltype(auto) {
return forwarded(xn);
}

返回所传参数中的第 n 个.

具体来说, arg<n>(x1, ..., xn, ..., xm) 等价于 xn. 注意下标从 1 开始, 因此 arg<1> 返回第 1 个参数, arg<2> 返回第 2 个, 依此类推. 使用 arg<0> 是错误的. 把少于 n 个的参数传给 arg<n> 同样是错误的.

模板参数
n一个无符号整数, 表示要返回的参数. n 必须为正 (即非零) .
参数
x1,...,xm一个可变参数包, 返回其中第 n 个参数.

我们本可以选择让 arg 像 arg(n)(x...) 那样使用, 而不是像 arg<n>(x...) 那样. 如果所有参数类型相同, 那么 n 就可以只在运行时才知. 然而, 那样我们将失去静态断言 n 边界内有效性的能力.

关于 <tt>n</tt> 为非类型模板参数的设计理由

我认为唯一有趣的用例是使用编译期 n, 这意味着用法将变成 arg(int_<n>)(x...), 它比 arg<n>(x...) 更难书写. 这一点尚可讨论.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)

// hana::arg<0>(1, '2', 3.3); // 静态断言 (与参数个数无关)

创建捕获给定变量的函数.

给定 0 个或多个变量, capture 创建一个可用于部分应用函数的闭包. 这与 partial 非常相似, 只是 capture 允许稍后再指定要部分应用的函数. 具体来说, capture(vars...) 是一个函数对象, 它接受一个函数 f, 并返回 f 部分应用到 vars... 后的结果. 换言之,

capture(vars...)(f)(args...) == f(vars..., args...)
注释
f 的元数必须与传给它的参数总数匹配, 即 sizeof...(vars) + sizeof...(args).

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)
#include <boost/hana/assert.hpp>
#include <boost/hana/config.hpp>
#include <boost/hana/functional/capture.hpp>
namespace hana = boost::hana;
int main() {
BOOST_HANA_CONSTEXPR_LAMBDA auto sum = [](auto x, auto y, auto z) {
return x + y + z;
};
BOOST_HANA_CONSTEXPR_CHECK(hana::capture(1, 2, 3)(sum)() == 6);
BOOST_HANA_CONSTEXPR_CHECK(hana::capture(1, 2)(sum)(3) == 6);
}

把函数柯里化到给定的实参个数.

柯里化 是这样一种技术: 我们考虑一个接受多个参数的函数 (或等价地, 接受一个参数元组的函数) , 并把它变成一个接受单个参数、返回用于处理其余参数的函数的函数. 为了便于直观理解, 把函数 f (其接受 X1, ..., Xn 类型的参数并返回一个 R) 的类型记为

(X1, ..., Xn) -> R

然后, 柯里化就是把 f 变成一个等价函数 (记作 g) 的过程, 该函数的类型为

X1 -> (X2 -> (... -> (Xn -> R)))

这给出下面的等价关系, 其中 x1、...、xn 分别是类型 X1、...、Xn 的对象:

f(x1, ..., xn) == g(x1)...(xn)

柯里化在若干情况下很有用, 尤其是在使用高阶函数时.

这个 curry 工具是柯里化在 C++ 中的一种实现. 具体来说, curry<n>(f) 是一个满足下式的函数

curry<n>(f)(x1)...(xn) == f(x1, ..., xn)

注意必须显式指定 n, 因为 C++ 中存在带可变参数的函数, 使得无法知道柯里化应当在何时停止.

与通常的柯里化不同, 这个实现还允许一次用多个参数调用柯里化后的函数. 因此, 下面的等式总是成立

curry<n>(f)(x1, ..., xk) == curry<n - k>(f)(x1)...(xk)

当然, 这要求 k 小于或等于 n; 不满足这一点会触发静态断言. 之所以支持这种语法, 是因为它使柯里化后的函数可以用在期望普通函数的场合.

另一个"扩展"是支持 curry<0>(f): curry<0>(f) 是一个无参函数; 而柯里化的经典定义似乎未定义这种情况, 因为无参函数在纯函数式语言中意义不大.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)
#include <boost/hana/assert.hpp>
#include <boost/hana/config.hpp>
#include <boost/hana/functional/curry.hpp>
namespace hana = boost::hana;
int main() {
BOOST_HANA_CONSTEXPR_LAMBDA auto add = [](auto x, auto y, auto z) {
return x + y + z;
};
BOOST_HANA_CONSTEXPR_CHECK(hana::curry<3>(add)(1)(2)(3) == 1 + 2 + 3);
BOOST_HANA_CONSTEXPR_CHECK(hana::curry<3>(add)(1)(2, 3) == hana::curry<3>(add)(1)(2)(3));
BOOST_HANA_CONSTEXPR_CHECK(hana::curry<3>(add)(1, 2, 3) == hana::curry<3>(add)(1)(2)(3));
// 用无参函数进行 curry
BOOST_HANA_CONSTEXPR_LAMBDA auto two = []() {
return 2;
};
BOOST_HANA_CONSTEXPR_CHECK(hana::curry<0>(two)() == two());
}

demux(f)(g...)(x...) == f(g(x...)...)

注释
当只与两个函数一起使用时, demux 是结合的. 换言之 (并记 demux(f, g) = demux(f)(g) 以简化记号) , demux(demux(f, g), h) == demux(f, demux(g, h)) 成立.

返回一个计算函数不动点的函数.

fix 是 Y 组合子 (也称不动点组合子) 的一种实现. 它编码了递归的思想, 实际上任何递归函数都可以用它写出来.

具体来说, fix(f) 是一个满足下式的函数

fix(f)(x...) == f(fix(f), x...)

这个定义允许 f 把它的第一个参数用作递归调用自身的延续. 实际上, 如果 f 以 y... 调用其第一个参数, 根据上式这等价于调用 f(fix(f), y...).

多数情况下, 不使用不动点组合子来定义递归函数更方便、更高效. 不过, 在某些情况下, fix 或者提供了更多灵活性 (例如可以在 f 内部更改回调) , 或者使得能够写出否则无法递归定义的函数.

参数
f以 f(self, x...) 形式调用的函数, 其中 x... 是 fix(f)(x...) 表达式中的参数, 而 self 是 fix(f).

因此, 返回的函数仍可以用通常的函数调用语法应用, 但它也获得了用中缀表示法应用的能力. 中缀语法具有很强的表现力, 尤其是与某些高阶算法结合使用时. 由于 operator^ 是左结合的, x ^infix(f)^ y 实际上会被解析为 (x ^infix(f))^ y. 不过, 为了灵活性, 两个参数在中缀表示法中的应用顺序无关紧要. 因此, 下式总是成立

(x ^ infix(f)) ^ y == x ^ (infix(f) ^ y)

不过, 请注意在中缀表示法中把多于一个参数应用到运算符的同一侧会导致编译期断言:

(infix(f) ^ x) ^ y; // 编译期断言
y ^ (x ^ infix(f)); // 编译期断言

此外, 用 infix 创建的函数可以用中缀表示法部分应用. 具体来说,

(x ^ infix(f))(y1, ..., yn) == f(x, y1, ..., yn)
(infix(f) ^ y)(x1, ..., xn) == f(x1, ..., xn, y)
  1. 选择 ^ 运算符是因为它是左结合的, 且优先级足够低, 使得大多数表达式都会呈现预期的行为.
  2. 这个运算符不能定制, 因为那需要在实现上做更多复杂化; 我想让它尽可能简单. 为中缀应用提供统一语法也有好处.

◆ _

constexpr unspecified boost::hana::_ {}
constexpr

#include <boost/hana/functional/placeholder.hpp>

内联地创建表示 C++ 运算符的简单函数.

具体来说, _ 是一个用作占位符的对象, 用于构建表示对 C++ 运算符调用的函数对象. 它的工作方式是重载 _ 与任意对象之间的运算符, 使其返回一个函数对象, 该函数对象实际对其参数调用相应的运算符. 因此, 对任何受支持的运算符 @:

(_ @ _)(x, y) == x @ y
boost::hana::_
constexpr unspecified _
内联地创建表示 C++ 运算符的简单函数.
定义: placeholder.hpp:70

运算符也可对单个参数进行内联部分应用：

(x @ _)(y) == x @ y
(_ @ y)(x) == x @ y

当以多于所需数量的参数调用时, 用 _ 创建的函数会丢弃多余参数, 而不是触发错误:

(_ @ _)(x, y, z...) == x @ y

这使得用 _ 创建的函数更容易在高阶算法中使用, 因为这类算法有时会向其回调提供多于必要的信息.

受支持的运算符

  • 算术: 二元 +、二元 -、/、*、%、一元 +、一元 -
  • 位运算: ~、&、|、^、<<、>>
  • 比较: ==、!=、<、<=、>、>=
  • 逻辑: ||、&&、!
  • 成员访问: * (解引用) 、[] (数组下标)
  • 其他: () (函数调用)

不支持更复杂的功能, 比如把占位符内联组合成更大函数对象的能力. 这是有意为之; 如果你需要更强大的工具, 应当使用 C++14 泛型 lambda 或 Boost.Phoenix 这样的库. 这里的目标只是在简单情况下为你省下几个字符.

Example

// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)

static_assert(plus(1, 2) == 1 + 2, "");

static_assert(increment(1) == 2, "");
