说明

Monoid 概念表示具有带单位元的结合二元运算的数据类型.

具体而言, Monoid 是数学中常用来构造更复杂代数结构 (如 Group, Ring 等) 的基础代数结构. 它们在多种场景有用, 尤其是以细粒度方式定义数的性质. 就其核心而言, Monoid 是一个对象集合 S 连同一个二元运算 (设为 +), 该运算满足结合律且在 S 中有单位元. Monoid 的例子很多:

  • 字符串, 以拼接为运算, 空字符串为单位元
  • 整数, 以加法为运算, 0 为单位元
  • 整数, 以乘法为运算, 1 为单位元
  • 以及其他许多...

从整数的例子可以看到, 有些集合可以根据二元运算和单位元的不同选取, 以不止一种方式看作单子. 此处使用的方法名指的是加法意义下的整数单子; plus 是其二元运算, zero 是该运算的单位元.

Laws

对所有对象 x, y 和 z (属于 Monoid M), 必须满足以下定律:

plus(zero<M>(), x) == x // 左零元
plus(x, zero<M>()) == x // 右零元
plus(x, plus(y, z)) == plus(plus(x, y), z) // 结合律

非布尔算术数据类型的自由模型

数据类型 T 在 std::is_arithmetic<T>::value 为真时即为算术类型. 对于非布尔算术数据类型 T, 其 Monoid 模型通过如下设置自动定义:

plus(x, y) = (x + y)
zero<T>() = static_cast<T>(0)

#### 不默认将 bool 设为 Monoid 的设计理由 首先, 定义一个加法 Monoid 于 bool 类型之上毫无意义. 其次, 用逻辑与或逻辑或来定义 Monoid 似乎也说得通. 然而, C++ 允许 bool 之间相加, 而本概念的方法名也确实暗示加法运算. 本着最小惊讶原则, 默认不提供模型.

保持结构的函数

设 A 与 B 为两个 Monoid. 函数 f : A -> B 被称为Monoid 态射, 若它保持 A 与 B 之间的单子结构. 严格地说, 对所有对象 x, y (数据类型为 A),

f(plus(x, y)) == plus(f(x), f(y))
f(zero<A>()) == zero<B>()

具有这些性质的函数与 Monoid 交互良好, 因此得到了如此特殊的对待.

方法的跨类型版本

plus 方法被"重载"以处理具有某些性质的不同数据类型. 具体而言, plus 对满足下列条件的不同数据类型 A 与 B 定义:

  1. A 与 B 共享一个公共数据类型 C, 由 common 元函数判定
  2. A, B 和 C 单独来看都是 Monoid
  3. to<C> : A -> B 与 to<C> : B -> C 都是 Monoid 嵌入 (由 is_embedding 元函数判定).

对满足上述性质的数据类型, plus 的定义通过设置

plus(x, y) = plus(to<C>(x), to<C>(y))
