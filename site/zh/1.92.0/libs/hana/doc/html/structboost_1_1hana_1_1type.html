说明

template<typename T>
struct boost::hana::type< T >

以值层表示的 C++ 类型.

type 是一种特殊的对象, 表示诸如 int、void、std::vector<float> 或任何你能想到的东西之类的 C++ 类型.

本页解释 type 在底层是如何工作的. 为了建立对 Hana 中类型层元编程的直觉, 你应该阅读关于类型层计算的教程小节.

注释
由于一些微妙的原因, hana::type 的实际表示是实现定义的. 特别地, hana::type 可能是一个依赖类型, 因此不应尝试对它进行模式匹配. 但是, 可以假定 hana::type 继承自 hana::basic_type, 这在声明重载函数时可能有用:
template <typename T>
void f(hana::basic_type<T>) {
// do something with T
}
完整的情况是 ADL 会导致模板实参被实例化. 因此, 如果 hana::type 被天真地定义, 那么诸如 hana::type<T>{} == hana::type<U>{} 这样的表达式会同时导致 T 和 U 被实例化. 这通常不是问题, 除非 T 或 U 不应该被实例化. 为了避免这些实例化, hana::type 使用了一些技巧来实现, 这就是表示是实现定义的原因. 当不需要该行为时, hana::basic_type 可以用来代替.

左值与右值

当把 type 存储在异构容器中时, 某些算法会返回对这些对象的引用. 由于我们主要感兴趣的是访问它们的嵌套 ::type, 收到一个引用是不可取的; 我们最终会尝试在引用类型内部获取嵌套的 ::type, 这会导致编译错误:

auto ts = make_tuple(type_c<int>, type_c<char>);
using T = decltype(ts[0_c])::type; // error: 'ts[0_c]' is a reference!

出于这个原因, type 提供了一元 + 运算符的一个重载, 它可以用来把左值变成右值. 因此, 当使用一个可能是对 type 对象的引用的结果时, 可以使用 + 来确保在获取其嵌套的 ::type 之前得到一个右值:

auto ts = make_tuple(type_c<int>, type_c<char>);
using T = decltype(+ts[0_c])::type; // ok: '+ts[0_c]' is an rvalue

已弃用:
decltype_ 的语义可能令人困惑, 应优先使用 hana::typeid_. decltype_ 可能会在库的下一个主要版本中被移除.

decltype_ 在某种程度上等价于 decltype, 因为它返回一个对象的类型; 不同之处在于它把类型作为一个 hana::type 返回 — 它是 Hana 的一等公民, 而不是原始 C++ 类型. 具体而言, 给定一个对象 x, decltype_ 满足

decltype_(x) == type_c<decltype(x) with references stripped>

正如你所见, decltype_ 会从对象的实际类型中去除任何引用. 这样做的原因在下面解释. 但是, 任何 cv 限定符都会被保留. 另外, 当给定一个 hana::type 时, decltype_ 就是恒等函数. 因此, 对于任何 C++ 类型 T,

decltype_(type_c<T>) == type_c<T>

与 metafunction 等的指定方式相结合, 这种行为使得同时与类型和值交互变得更容易. 然而, 它确实使得无法创建一个 type, 使其包含另一个 type (使用 decltype_). 换言之, 无法用此工具创建一个 type_c<decltype(type_c<T>)>, 因为 decltype_(type_c<T>) 将只是 type_c<T> 而不是 type_c<decltype(type_c<T>)>. 这个用例被认为是罕见的, 如果需要, 可以使用手工编写的函数.

去除引用的设计理由

模板实参推导的规则决定了: 一个总是与 decltype 匹配的完美方案是不可能的. 因此, 我们必须选定一个对我们的需求而言足够好且足够一致的方案. 无法匹配 decltype 行为的一个情形是: 实参是一个普通的、未加括号的变量或函数形参. 在这种情况下, decltype_ 的实参会被推导为对该变量的引用, 但 decltype 本会给我们该变量的实际类型 (不带引用). 另外, 鉴于 metafunction 等的当前定义, 如果 decltype_ 能返回引用, 那它几乎没什么用, 因为 F 在其最简单的用例中不太可能期望一个引用:

int i = 0;
auto result = metafunction<F>(i);

因此, 总是丢弃引用似乎是最不痛苦的做法.

正如你所见, typeid_ 会从对象的实际类型中去除任何引用和 cv 限定符. 这样做的原因是它忠实地建模了语言的 typeid 在引用和 cv 限定符方面的行为, 而且事实证明这在大多数情况下也是人们期望的行为. 另外, 当给定一个 hana::type 时, typeid_ 就是恒等函数. 因此, 对于任何 C++ 类型 T,

sizeof 关键字, 提升到 Hana.

sizeof_ 在某种程度上等价于 sizeof, 因为它返回表达式或类型的大小; 但它接受任意表达式或一个 hana::type, 并以一个 integral_constant 的形式返回其大小. 具体而言, 给定一个表达式 expr, sizeof_ 满足

sizeof_(expr) == size_t<sizeof(decltype(expr) with references stripped)>
boost::hana::type::sizeof_
constexpr auto sizeof_

然而, 给定一个 type, sizeof_ 将只是获取该对象所表示的 C++ 类型的大小. 换言之,

sizeof_(type_c<T>) == size_t<sizeof(T)>

sizeof_ 的行为与 decltype_ 的行为一致. 特别地, 参见 decltype_ 的文档以理解为什么 sizeof_ 总是去除引用.

给定一个 SFINAE 友好的函数, is_valid 返回该函数调用以给定实参进行时是否有效. 具体而言, 给定一个函数 f 和实参 args...,

is_valid(f, args...) == whether f(args...) is valid

constexpr auto is_valid
检查一个 SFINAE 友好的表达式是否有效.
定义: type.hpp:369

结果以编译期 Logical 的形式返回. 此外, is_valid 可以按柯里化形式使用, 如下:

is_valid(f)(args...)

这种语法使得创建检查泛型表达式在任意给定实参上是否有效的函数变得容易.

警告
要检查调用无参函数 f 是否有效, 应使用 is_valid(f)() 语法. 实际上, is_valid(f /* no args *‍/) 会被解释为把 is_valid 柯里化为 f, 而不是把 is_valid 应用到 f 且不带实参.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)
#include <boost/hana/assert.hpp>
#include <boost/hana/not.hpp>
#include <boost/hana/type.hpp>
#include <string>
#include <vector>
namespace hana = boost::hana;
int main() {
// Checking for a member
struct Person { std::string name; };
auto has_name = hana::is_valid([](auto&& p) -> decltype((void)p.name) { });
Person joe{"Joe"};
static_assert(has_name(joe), "");
static_assert(!has_name(1), "");
// Checking for a nested type
auto has_value_type = hana::is_valid([](auto t) -> hana::type<
typename decltype(t)::type::value_type
> { });
static_assert(has_value_type(hana::type_c<std::vector<int>>), "");
static_assert(!has_value_type(hana::type_c<Person>), "");
}
