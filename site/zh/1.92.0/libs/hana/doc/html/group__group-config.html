宏定义文档

◆ BOOST_HANA_CONFIG_DISABLE_ASSERTIONS

#define BOOST_HANA_CONFIG_DISABLE_ASSERTIONS

#include <boost/hana/config.hpp>

禁用 BOOST_HANA_*_ASSERT 宏及其同类宏.

定义此宏时, BOOST_HANA_*_ASSERT 宏及其同类宏被禁用, 即它们展开为空.

当 NDEBUG 被定义时, 此宏会自动定义. 用户也可以在包含此头文件之前定义它, 或在命令行上定义.

◆ BOOST_HANA_CONFIG_DISABLE_CONCEPT_CHECKS

#define BOOST_HANA_CONFIG_DISABLE_CONCEPT_CHECKS

#include <boost/hana/config.hpp>

禁用接口方法中的概念检查.

当此宏未定义 (默认) 时, 通过 tag 分派的方法会确保传给它们的实参是相应概念的模型. 这对捕获编程错误非常有帮助, 但也会稍微降低编译期效率. 你可能应该始终让检查保持启用 (因而永远不要定义此宏) , 除非是在那些编译非常频繁、而其中使用 Hana 的代码极少修改的翻译单元中.

◆ BOOST_HANA_CONFIG_ENABLE_STRING_UDL

#define BOOST_HANA_CONFIG_ENABLE_STRING_UDL

#include <boost/hana/config.hpp>

启用"字符串字面量运算符模板"GNU 扩展的使用.

该运算符尚未成为语言的一部分, 但 Clang 和 GCC 都支持它. 这个运算符使 Hana 能够提供用于创建编译期字符串的漂亮 _s 用户定义字面量.

此宏未定义时, Hana 不会使用该 GNU 扩展. 由于这是一个非标准扩展, 默认情况下不定义此宏.

◆ BOOST_HANA_CONFIG_ENABLE_DEBUG_MODE

#define BOOST_HANA_CONFIG_ENABLE_DEBUG_MODE

#include <boost/hana/config.hpp>

启用由 Hana 执行的额外断言和健全性检查.

定义此宏时 (默认不定义) , Hana 可能执行额外的健全性检查. 这些检查的执行代价可能很高, 无论体现在编译时间还是执行时间上. 这些检查有助于在应用程序的初始开发阶段进行调试, 但不应作为正常配置的一部分启用.

展开为库完整版本号 (十六进制表示) 的宏.

具体来说, BOOST_HANA_VERSION 展开为一个形如 0xVVRRPPPP 的十六进制数, 其中 VV 是库的主版本号, RR 是次版本号, PPPP 是补丁级别. 这使得库的版本可以被比较:

#include <boost/hana/version.hpp>
#if BOOST_HANA_VERSION < 0x01020003
// Hana 的版本 < 1.2.3
#else
// Hana 的版本 >= 1.2.3
#endif
version.hpp
定义用于跟踪库版本的宏.
注释
库的主版本号、次版本号和补丁级别也可以通过 BOOST_HANA_{MAJOR,MINOR,PATCH}_VERSION 宏单独获得.
