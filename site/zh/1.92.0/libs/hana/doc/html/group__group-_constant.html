说明

Constant 概念表示可在编译期操纵的数据.

就其核心而言, Constant 只是把 std::integral_constant 背后的原则推广到所有可在编译期构造的类型, 即所有具有 constexpr 构造函数的类型 (也称为 Literal types). 更具体地说, Constant 是一个对象, 从中可以取得 constexpr 值 (通过 value 方法), 而不论对象本身的 constexpr 性.

所有 Constant 都必须在下述意义上彼此大致等价. 设 C(T) 和 D(U) 分别表示 Constant (它们分别持有 T 类型对象和 U 类型对象) 的标签. 那么, 标签为 D(U) 的对象必须可转换为标签为 C(T) 的对象, 只要 U 可转换为 T (由 is_convertible 判定). 这里的解释是: Constant 只是一个持有某种类型对象的盒子, 只要盒子内的对象可以互换, 就应该可以在盒子之间互换.

由于这最后一项要求, 有人可能会以为 std::integral_constant 这类特化的"盒子"无法成为 Constant, 因为它们不能持有任意类型 T 的对象 (std::integral_constant 只能持有整型). 这是误解; 该要求应理解为: 只要 C(T) 是有意义的 (例如对 T 为整型的 std::integral_constant 而言)且存在从 U 到 T 的转换, 那么从 D(U) 到 C(T) 的转换也应当存在. 作为 Constant 的确切要求体现在以下定律中.

最小完整定义

value 与 to, 满足下述定律.

Laws

设 c 为标签为 C 的对象, 它表示一个 Constant, 其中持有标签为 T 的对象. 第一个定律通过要求下式良构造, 保证被包裹对象的值总是常量表达式:

constexpr auto x = hana::value<decltype(c)>();

这意味着 value 函数必须返回一个可在编译期构造的对象. 值得注意的是 value 只接收对象的类型而非对象本身. 这正是 Constant 概念的核心: 实现 value 所需的唯一信息必须存于其实参的类型中, 从而可静态获得.

必须满足的第二个定律确保 Constant 基本上是"傻盒子", 这使得无需用户费力就能为许多概念提供模型. 该定律只要求以下表达式有效:

to<C>(i)

其中 i 是一个任意的 Constant, 其内部值的标签可转换为 T (由 hana::is_convertible 元函数判定). 换言之, 只要 U 可转换为 T, 一个 Constant (持有 U) 就可转换为 Constant (持有 T), 前提是能创建这样一个 Constant.

最后, 标签 C 必须提供嵌套的 value_type 别名, 指向 T, 使我们能够查询标签为 C 的对象所存内部值的标签. 换言之, 对任何对象 c (标签为 C), 下式必须成立:

std::is_same<
C::value_type,
tag_of<decltype(hana::value(c))>::type
>::value

精化概念

在某些情况下, Constant 可以自动成为另一个概念的模型. 特别是, 若 Constant C 持有标签为 T 的对象, 且 T 建模概念 X, 那么 C 在大多数情况下也可以建模 X, 做法是对其底层值执行所需的运算, 然后把结果重新包进一个 C.

更具体地说, 若 Constant C 的底层值 (C::value_type) 是 Comparable, Orderable, Logical 或 Monoid (最高到 EuclideanRing) 的模型, 那么 C 也必须是这些概念的模型. 换言之, 当 C::value_type 建模所列概念之一时, C 本身也必须建模该概念. 不过请注意, 上述概念都提供了自由模型, 因此无需做任何额外工作.

理论上也可以为 Foldable 等概念提供模型, 但实践中只有少数概念作为 Constant 有用. 为上述概念提供自由模型是有用的, 因为它让各种整型常量 (std::integral_constant, mpl::integral_c 等) 只需定义 Constant 概念就能轻松获得它们的模型.

备注
一个有趣的事实是: Constant 其实是把 constexpr 范畴 (即本库涵盖的所有内容) 的子范畴规范嵌入到 Hana 范畴的嵌入. 因此, 在该子范畴中成立的结论, 通过这个函子在这里同样成立. 这就是为什么只需通过该嵌入传递, 就能为 Constant 提供任何适用于 constexpr 的概念的模型.

具体模型

hana::integral_constant

提供到底层值标签的转换

任何 Constant c (其底层值的标签为 T) 都可转换为任何标签 U, 只要 T 可转换为 U. 具体而言, 该转换等价于

to<U>(c) == to<U>(value<decltype(c)>())

另外, 只要底层类型的转换是嵌入 (embedding), 这些转换也都会被标记为嵌入. 这是为了让 Constant 能方便地与 constexpr 对象互操作:

plus(int_c<1>, 1) == 2

constexpr auto plus
Monoid 上的结合二元运算.

严格说来, 这有时是对嵌入定义的违反. 的确, 虽然从任何 Constant 到 constexpr 对象存在嵌入 (因为 Constant 只是规范包含), 但从 Constant 到运行期对象不存在嵌入, 因为我们将失去定义 value 方法的能力 (对象的 constexpr 性将会丢失). 由于无法基于类型区分 constexpr 与非 constexpr 对象, Hana 无法知道转换是否到 constexpr 对象. 换言之, to 方法无法区分

constexpr int i = hana::to<int>(int_c<1>);

这是一个嵌入, 而

int i = hana::to<int>(int_c<1>);

则不是. 为稳妥起见, 我们本可以把该转换标记为非嵌入. 然而, 例如若 integral_constant_tag<int> 到 int 的转换未被标记为嵌入, 我们就必须写 plus(to<int>(int_c<1>), 1) 而不是只写 plus(int_c<1>, 1), 相当繁琐. 因此, 该转换被标记为嵌入, 但这也意味着如下代码

int i = 1;
plus(int_c<1>, i);

将被视为合法, 这隐式地丢失了 int_c<1> 是 Constant 这一事实, 因而不遵循 Hana 中跨类型运算的通常规则.

提供的公共数据类型

由于要求 Constant 在内容兼容时可互换, 两个 Constant (A 与 B) 只要 A::value_type 与 B::value_type 有公共数据类型, 就会有公共数据类型. 它们的公共数据类型是一个未指明的 Constant C, 使得 C::value_type 恰好就是 common_t<A::value_type, B::value_type>. 为体现这一点, 还提供了 common 元函数的一个特化, 供 Constant 使用.

同理, 也提供从任意常量 A 到类型 T 的公共数据类型, 其中 A::value_type 与 T 共享公共类型. A 与 T 的公共类型显然就是 A::value_type 与 T 的公共类型. 如前文转换一节所述, 这有时是对公共数据类型定义的违反, 因为必须存在到公共类型的嵌入, 而这并非总是如此. 出于前文同样的原因, 该公共数据类型仍然提供.

返回与常量关联的编译期值.

此函数返回与 Constant 关联的值. 该值总是常量表达式. 常规用法是把 value 用在对象 c 上:

constexpr auto result = hana::value<decltype(c)>();

不过为方便起见, 也提供了 value 的一个重载, 使它可以按如下方式调用:

constexpr auto result = hana::value(c);

此重载的做法是对实参取 const&, 然后转发给 value 的第一个版本. 由于它不使用实参, 即使实参不是常量表达式, 结果仍可以是常量表达式.

注释
value<T>() 以 value_impl<C>::apply<T>() 做标签分派, 其中 C 是 T 的标签.
hana::value 是重载函数, 不是函数对象. 因此它无法传给高阶算法. 若需要等价的函数对象, 请改用 hana::value_of.

Example

// Copyright Louis Dionne 2013-2017
// Distributed under the Boost Software License, Version 1.0.
// (See accompanying file LICENSE.md or copy at http://boost.org/LICENSE_1_0.txt)
#include <boost/hana/integral_constant.hpp>
#include <boost/hana/value.hpp>
namespace hana = boost::hana;
int main() {
auto i = hana::integral_c<int, 3>; // 注意没有 constexpr
static_assert(hana::value<decltype(i)>() == 3, "");
static_assert(hana::value(i) == 3, "value(i) is always a constant expression!");
}

此函数对象等价于 value, 但由于它是函数对象, 可以传给高阶算法. value 无法传给高阶算法, 因为它实现为重载函数.
