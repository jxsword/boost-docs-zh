其他 API

setjmp()/longjmp()

C99 定义了 setjmp() / longjmp() 以提供非本地跳转, 但它并不要求 longjmp() 保存当前栈帧. 因此, 跳入一个已通过调用 longjmp() 退出的函数是未定义行为 [2] .

ucontext_t

自 POSIX.1-2004 起 ucontext_t 已被弃用, 并在 POSIX.1-2008 中被移除! makecontext() 的函数签名是:

void makecontext(ucontext_t *ucp, void (*func)(), int argc, ...);

makecontext() 的第三个实参指定其后整数实参的个数; 若 func 要接受这些实参, 则需要进行函数指针转换, 这在 C99 中是未定义行为 [3] .

var-arg 列表中的实参要求是整数; 在 var-arg 列表中传递指针并不保证可行, 特别是在指针大于整数的体系结构上会失败.

ucontext_t 在上下文切换之间保存信号掩码, 这涉及消耗大量 CPU 周期的系统调用 (ucontext_t 较慢; 一次上下文切换比 fcontext_t 多耗费 两个数量级的 CPU 周期 ).

Windows 纤程

Windows Fiber API 的一个缺点是 CreateFiber() 不接受指向用户分配栈空间的指针, 从而无法将栈复用于其他上下文实例. 因为若对尚未转换为纤程的线程调用 ConvertThreadToFiber() , 则 Windows Fiber API 要求先调用 SwitchFiber() . 出于同样的原因, 若线程此前被强制转换为纤程, 则在 ConvertFiberToThread() 返回之后必须调用 SwitchFiber() (这效率不高).

if ( ! is_a_fiber() )
{
    ConvertThreadToFiber( 0);
    SwitchToFiber( ctx);
    ConvertFiberToThread();
}

若满足条件 _WIN32_WINNT >= _WIN32_WINNT_VISTA , 则提供函数 IsThreadAFiber() 用于检测当前线程是否已被转换. 遗憾的是, Windows XP + SP 2/3 定义了 _WIN32_WINNT >= _WIN32_WINNT_VISTA 却未提供 IsThreadAFiber() .
