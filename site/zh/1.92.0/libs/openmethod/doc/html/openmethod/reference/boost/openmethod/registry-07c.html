boost::openmethod::registry

方法、类和策略.

概要

声明于 <boost/openmethod/preamble.hpp>

template<class... Policy>
class registry;

说明

方法存在于注册表的上下文中. 任何用作方法或覆写器参数、或用作方法调用实参的类, 都必须向同一个注册表注册.

在调用方法之前, 必须用 initialize 函数初始化其注册表. 这通常在 main 的开头完成.

多个注册表可以在同一个程序中共存. 它们必须分别初始化. 不同注册表中的方法所引用的类必须向每个注册表注册.

注册表还包含一组 policies, 用于控制某些操作的执行方式. 例如, rtti 策略提供类型信息、实现动态转换等. 可以替换它以对接自定义 RTTI 系统 (如 LLVM 的).

策略实现为 Boost.MP11 引用型元函数. 一个策略类必须包含一个 fn<Registry> 模板, 该模板提供一组特定于该策略职责的静态成员. 注册表通过把自身传递给嵌套的 fn 类模板来实例化策略.

这样设计有两个原因.

一些策略是 "有状态的": 它们包含静态数据成员. 由于多个注册表可以在同一个程序中共存, 每个有状态的策略都需要自己独立的一组静态数据成员. 例如, vptr_vector 是一个 "vptr" 策略, 包含一个静态的 vptr vector, 它不能与其他注册表共享.

此外, 一些策略需要访问同一注册表中的其他策略. 它们可以通过 Registry 模板参数访问. 例如, vptr_vector 在把 type_id 用作索引之前对其进行哈希, 条件是 Registry 包含一个 type_hash 策略. 若 Registry 包含 runtime_checks 策略, 它会执行越界检查. 若检测到错误, 则调用 error_handler 策略 (若存在).

要求

  • Policy 必须包含一个指向其根基类的 category 别名. 注册表每个类别最多只能包含一个策略.

  • Policy 必须包含一个 fn<Registry> 元函数.
