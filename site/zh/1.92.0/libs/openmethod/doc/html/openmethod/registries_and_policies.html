方法作用于一个注册表的范围之内. 方法只能引用同一注册表中的类. 如果一个类在多个使用不同注册表的方法中用作虚参数, 它必须分别向每个注册表注册.

类模板 use_classes, method, virtual_ptr, 以及宏 BOOST_OPENMETHOD 和 BOOST_OPENMETHOD_CLASSES, 都接受一个额外的实参, 一个 registry 类, 其默认值为 default_registry. 默认注册表可以通过定义宏处理器符号 BOOST_OPENMETHOD_DEFAULT_REGISTRY 来覆盖 (必须在包含 <boost/openmethod/core.hpp> 之前定义). 该符号的值用作 use_classes, method, virtual_ptr 等的默认模板参数. 一旦包含了 core 头文件, 更改 BOOST_OPENMETHOD_DEFAULT_REGISTRY 就不会产生任何效果.

注册表拥有一组策略. 每个策略属于一个策略类别. 注册表每个类别最多只能包含一个策略. 策略控制如何获取类型信息、如何获得 vptr、如何处理和报告错误等. 虽然 initialize 的行为可以通过选项定制, 但策略主要参与方法分发.

策略被放在 boost::openmethod::policies 命名空间中.

default_registry 包含以下策略:

策略类别 策略 职责

rtti

std_rtti

为类和对象提供类型信息

vptr

vptr_vector

把 vptr 存储在一个带索引的集合中

type_hash

fast_perfect_hash

把类型 id 哈希为 vector 中的索引

error_handler

default_error_handler

调用一个可覆写的处理器函数

output

stderr_output

把诊断信息打印到 stderr

若定义了 BOOST_OPENMETHOD_ENABLE_RUNTIME_CHECKS, 则 default_registry 还包含 runtime_checks 策略. 这会在方法分发期间启用额外的验证, 能够检测出 initialize 无法捕获的类缺失注册.

该库提供另一个预定义注册表: indirect_registry. 当在运行期动态加载共享库, 并且跨越程序与共享库边界添加方法和覆写器时, 它非常有用. 参见关于共享库的章节.

注册表可以从零开始创建, 使用 registry 模板. 下面是 default_registry 的定义, 从 <boost/openmethod/registry.hpp> 复制而来:

struct default_registry
    : registry<
          policies::std_rtti,
          policies::vptr_vector, policies::fast_perfect_hash,
          policies::default_error_handler,
          policies::stderr_output
#ifdef BOOST_OPENMETHOD_ENABLE_RUNTIME_CHECKS
          ,
          policies::runtime_checks
#endif
          > {
};

在定义新注册表时, 建议定义一个派生自 registry<…​> 的新类, 而不是通过 typedef, 因为后者会产生过长的符号名并使调试更困难.

也可以通过复制现有注册表的策略来创建注册表, 使用 with 和 without 嵌套模板. 例如, indirect_registry 是对 default_registry 的微调:

struct indirect_registry : default_registry::with<policies::indirect_vptr> {};

策略实现为一元 Boost.MP11 引用型元函数. 策略是一个普通类, 包含一个嵌套类模板 fn, 注册表会实例化该模板, 并把自身作为唯一的模板实参传入. 这一机制的原因是允许策略拥有静态数据成员, 而每个注册表必须拥有自己的一组. 例如, vptr_vector 把 v-table 指针存储在一个 std::vector 中. 如果它用在两个不同的注册表中, 就需要使用两个不同的 vector, 每个注册表一个.
