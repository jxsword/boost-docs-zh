考虑一个表示并求值算术表达式的类层次结构:

#include <iostream>

struct Node {
    virtual ~Node() {}
    virtual int value() const = 0;
};

struct Variable : Node {
    Variable(int value) : v(value) {}
    int value() const override { return v; }
    int v;
};

struct Plus : Node {
    Plus(const Node& left, const Node& right) : left(left), right(right) {}
    int value() const override { return left.value() + right.value(); }
    const Node& left; const Node& right;
};

struct Times : Node {
    Times(const Node& left, const Node& right) : left(left), right(right) {}
    int value() const override { return left.value() * right.value(); }
    const Node& left; const Node& right;
};

int main() {
    Variable a{2}, b{3}, c{4};
    Plus d{a, b}; Times e{d, c};
    std::cout << e.value() << "\n"; // 20
}

我们想添加一个以后缀记法打印表达式的新操作. 该怎么做?

简单的办法是: 添加一个新的虚函数. 如下所示:

#include <iostream>

struct Node {
    // as before
    virtual void postfix(std::ostream& os) const = 0;
};

struct Variable : Node {
    // as before
    virtual void postfix(std::ostream& os) const override { os << v; }
};

struct Plus : Node {
    // as before
    void postfix(std::ostream& os) const override {
        left.postfix(os); os << ' '; right.postfix(os); os << " +";
    }
};

struct Times : Node {
    // as before
    void postfix(std::ostream& os) const override {
        left.postfix(os); os << ' '; right.postfix(os); os << " *";
    }
};

int main() {
    Variable a{2}, b{3}, c{4};
    Plus d{a, b}; Times e{d, c};
    e.postfix(std::cout); // 2 3 + 4 *
    std::cout << " = " << e.value() << "\n"; // = 20
}

如果这些类是一个小型的自包含程序的一部分, 这可能是一个合理的解决方案. 否则, 这种方法存在严重的问题.

  • 我们需要修改层次结构中的所有类, 而在一个真实的程序中, 这些类可能数量众多并分布在多个文件中. 这还假定我们能够访问它们的源代码.

  • 我们需要重新编译所有使用 Node 类的文件, 因为它们的虚函数表 (v-table) 的布局已经改变.

  • 使用 Node 类的程序都会得到 postfix 的覆写器, 即使那些在任何地方都不调用 postfix 的程序也不例外.

  • 它们还会引入 postfix 的传递依赖, 在此例中即 std::ostream、locale、刻面 (facet)、异常等. 注意, 现在我们需要先包含 <iostream>, 然后再定义这些类.

在 C++ 中, 这个问题通常用访问者 (Visitor) 设计模式来 "解决". 如果 Node 尚不支持 Visitor, 我们可能仍需要修改 Node 以使其具备 Visitor 支持. 但一旦完成, 我们就可以添加所需的全部操作, 尽管方式较为笨拙.

遗憾的是, 现在添加新的Node类变得困难了, 因为我们必须修改 Visitor 的接口及其所有实现, 并重新编译所有使用 Visitor 的文件. 我们是用一个问题换来了另一个问题.

Paul Graham 曾说, 设计模式本质上是在表达能力较弱的语言中为缺失的语言特性提供的变通方案. 确实, 在某些语言中, 我们的问题根本不存在. C# 有扩展类. Lisp、Clojure、Dylan、Julia、Cecil、TADS 等语言则拥有多方法.

但是等等! 多方法与我们的问题有什么关系? 这里并没有多重分发! 问题是, "多方法" 这个名字并不太好. 即使在支持多方法的语言中, 许多 "多方法" 也只有一个虚参数, 它们其实是单方法 (uni-method)[1]! 出于这个原因, 我们更倾向于使用 "开放方法" (open-methods) 这一术语, 以强调其重要特性: 开放性. 多重分发只是一个附赠好处.

开放方法类似于虚函数, 但它作为一个独立函数存在于类之外. 我们可以创建所需的全部开放方法, 而无需修改现有的类.

本库为 C++17 及以上版本实现了开放方法. 接下来我们将看到如何在 Node 示例中使用它们.

1. Multiple dispatch in practice, Radu Muschevici, 2008.
