通常, BOOST_OPENMETHOD 用于头文件, 而 BOOST_OPENMETHOD_CLASSES 和 BOOST_OPENMETHOD_OVERRIDE 用于实现文件.

让我们以一个工资管理 (payroll) 应用为例. 我们有两个角色: Employee 和 Salesman, 以及一个计算员工月薪的 pay 方法. 我们希望从多个翻译单元覆写并调用 pay, 因此把它放在一个头文件中:

// roles.hpp

#ifndef ROLES_HPP
#define ROLES_HPP

#include <boost/openmethod.hpp>

struct Employee { virtual ~Employee() = default; };

struct Salesman : Employee {
    double sales = 0.0;
};

BOOST_OPENMETHOD(pay, (boost::openmethod::virtual_ptr<const Employee>), double);

#endif // ROLES_HPP

BOOST_OPENMETHOD 会定义一个内联函数. 因此, 在同一个翻译单元中, 它不能以相同的实参被调用多次. 包含保护符 (include guard) 保证了这一点.

让我们为 "普通" 员工编写覆写, 他们领取固定工资. BOOST_OPENMETHOD_OVERRIDE 会向该方法添加一个覆写器. 我们不希望多次添加同一个覆写器, 那会造成歧义. 因此它被放在一个实现文件中:

// employee.cpp

#include "roles.hpp"
#include <boost/openmethod.hpp>

BOOST_OPENMETHOD_OVERRIDE(
    pay, (boost::openmethod::virtual_ptr<const Employee>), double) {
    return 5000.0;
}

BOOST_OPENMETHOD_CLASSES(Employee);

销售人员像员工一样领取工资, 外加按其销售额计算的佣金. next 函数仅在覆写器函数体内可用, 它调用下一个最特化的覆写器. 它类似于其他语言中的 super, 区别在于它代表的不是对象, 而是一个覆写器.

// salesman.cpp

#include "roles.hpp"
#include <boost/openmethod.hpp>

BOOST_OPENMETHOD_OVERRIDE(
    pay, (boost::openmethod::virtual_ptr<const Salesman> emp), double) {
    return next(emp) + emp->sales * 0.05; // base + commission
}

BOOST_OPENMETHOD_CLASSES(Employee, Salesman);

发薪时间到了!

// main.cpp

#include "roles.hpp"
#include <iostream>

#include <boost/openmethod/initialize.hpp>

int main() {
    boost::openmethod::initialize();

    Employee bill;
    Salesman bob; bob.sales = 100'000.0;

    std::cout << "pay bill: $" << pay(bill) << "\n"; // pay bill: $5000
    std::cout << "pay bob: $" << pay(bob) << "\n"; // pay bob: $10000
}

在前一个示例中, 我们使用 next 调用上一级覆写器 (super-overrider). 我们也可以直接调用一个覆写器. 为此, 我们可以在头文件中声明该覆写器, 并在一个实现文件中定义它:

// roles.hpp

#ifndef ROLES_HPP
#define ROLES_HPP

#include <boost/openmethod.hpp>

struct Employee { virtual ~Employee() = default; };

struct Salesman : Employee {
    double sales = 0.0;
};

BOOST_OPENMETHOD(pay, (boost::openmethod::virtual_ptr<const Employee>), double);

BOOST_OPENMETHOD_DECLARE_OVERRIDER(
    pay, (boost::openmethod::virtual_ptr<const Employee>), double);

#endif // ROLES_HPP

与函数声明不同, BOOST_OPENMETHOD_DECLARE_OVERRIDER 不能在同一个翻译单元中以相同实参出现多次. 此外, 它要求在使用该宏之前先定义方法本身.

覆写器被放置在覆写器 容器中. 覆写器容器是一个以该方法命名的类模板, 声明在当前命名空间中. 它针对每个覆写器签名进行特化. 宏 BOOST_OPENMETHOD_OVERRIDER 接受与 BOOST_OPENMETHOD_OVERRIDE 相同的实参, 并展开为覆写器容器的对应特化. 容器有一个静态成员函数 fn, 其中包含由用户提供的覆写器函数体. 我们可以像这样调用 Employee 的覆写器:

BOOST_OPENMETHOD_OVERRIDE(
    pay, (boost::openmethod::virtual_ptr<const Salesman> emp), double) {
    return BOOST_OPENMETHOD_OVERRIDER(
               pay, (boost::openmethod::virtual_ptr<const Employee> emp),
               double)::fn(emp) +
        emp->sales * 0.05; // base + commission
}

这类似于虚函数调用基类覆写器. 虚函数没有相当于 Smalltalk 或 Python 的 super 的东西, 但 OpenMethod 有, 它就是 next. 它几乎总是正确的选择.

例外情况是: 当性能至关重要时, 我们可能希望内联对基类覆写器的调用. BOOST_OPENMETHOD_INLINE_OVERRIDE 将覆写器定义为一个内联函数, 它可以放在头文件中:

// roles.hpp

#ifndef ROLES_HPP
#define ROLES_HPP

#include <boost/openmethod.hpp>

struct Employee { virtual ~Employee() = default; };

struct Salesman : Employee {
    double sales = 0.0;
};

BOOST_OPENMETHOD(pay, (boost::openmethod::virtual_ptr<const Employee>), double);

BOOST_OPENMETHOD_INLINE_OVERRIDE(
    pay, (boost::openmethod::virtual_ptr<const Employee>), double) {
    return 5000.0;
}

#endif // ROLES_HPP

经过内联, Salesman 的覆写器会编译为 (clang-20, x64-linux):

movsd	xmm0, qword ptr [rsi + 8]
mulsd	xmm0, qword ptr [rip + .LCPI1_0]
addsd	xmm0, qword ptr [rip + .LCPI1_1]
ret
