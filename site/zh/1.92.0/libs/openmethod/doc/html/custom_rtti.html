策略机制的最初动机是使 OpenMethod 能够与自定义 RTTI 系统对接.

内置注册表使用 std_rtti 所实现的 rtti. 下面是它的完整源代码:

struct std_rtti : rtti {
    template<class Registry>
    struct fn {
        template<class Class>
        static constexpr bool is_polymorphic = std::is_polymorphic_v<Class>;

        template<class Class>
        static auto static_type() -> type_id {
            return &typeid(Class);
        }

        template<class Class>
        static auto dynamic_type(const Class& obj) -> type_id {
            return &typeid(obj);
        }

        template<typename Stream>
        static auto type_name(type_id type, Stream& stream) -> void {
            stream << boost::core::demangle(
                reinterpret_cast<const std::type_info*>(type)->name());
        }

        static auto type_index(type_id type) -> std::type_index {
            return std::type_index(
                *reinterpret_cast<const std::type_info*>(type));
        }

        template<typename D, typename B>
        static auto dynamic_cast_ref(B&& obj) -> D {
            return dynamic_cast<D>(obj);
        }
    };
};

  • is_polymorphic 用于检查一个类是否为多态类. 该模板是必需的.

  • static_type 在类注册期间被 virtual_ptr 的 "final" 构造调用. 它也被调用以设置 bad_call::method. 该函数是必需的.

  • dynamic_type 用于读取虚实参的动态类型. 如果只使用 virtual_ptr 的 "final" 构造, 或者注册表中的所有类都提供了 boost_openmethod_vptr, 则此函数可以省略.

  • type_name 将一个类型的表示写入 LightweightOutputStream. 它用于格式化错误消息和跟踪消息. 该函数是可选的; 若未提供, type 将被呈现为 "type_id(type)".

  • type_index 返回一个唯一标识某个类的对象. 某些形式的 RTTI (最典型的是 C++ 的 typeid 运算符) 并不保证一个类的类型信息对象在同一程序内是唯一的. 该函数是可选的; 若未提供, 则假定 type 是唯一的, 并按原样使用.

  • dynamic_cast_ref 将一个对象转换为某个类. 它接受一个引用, 并返回一个与 B 具有相同类别 (以及适用的 cv 限定符) 的引用. 仅在存在虚继承时才需要此函数.

让我们用自定义 RTTI 的几种变体来重写 Node 示例.

在第一个示例中, 我们使用一种 "静态" 方案, 其中类型 id 是编译期常量:

struct Node {
    virtual ~Node() {}
    virtual int value() const = 0;
    // our custom RTTI:
    Node(unsigned type) : type(type) {}
    unsigned type;
    static constexpr unsigned static_type = 1;
};

struct Variable : Node {
    static constexpr unsigned static_type = 2;
    Variable(int value) : Node(static_type), v(value) {}
    int value() const override { return v; }
    int v;
};

struct Plus : Node {
    static constexpr unsigned static_type = 3;
    Plus(const Node& left, const Node& right)
        : Node(static_type), left(left), right(right) {}
    int value() const override { return left.value() + right.value(); }
    const Node& left; const Node& right;
};

struct Times : Node {
    static constexpr unsigned static_type = 4;
    Times(const Node& left, const Node& right)
        : Node(static_type), left(left), right(right) {}
    int value() const override { return left.value() * right.value(); }
    const Node& left; const Node& right;
};

让我们为该方案定义一个 rtti 策略. 我们将全局替换默认注册表, 因此不包含 <boost/openmethod/core.hpp> 或 <boost/openmethod.hpp>, 只包含实现该策略所需的内容:

#include <boost/openmethod/preamble.hpp>
#include <boost/openmethod/policies/vptr_vector.hpp>

struct custom_rtti : boost::openmethod::policies::rtti {
    template<class Registry>
    struct fn : defaults {
        template<class T>
        static constexpr bool is_polymorphic = std::is_base_of_v<Node, T>;

        using type_id = boost::openmethod::type_id; // for brevity

        template<typename T>
        static auto static_type() {
            if constexpr (is_polymorphic<T>) {
                return reinterpret_cast<type_id>(T::static_type);
            } else {
                return reinterpret_cast<type_id>(0);
            }
        }

        template<typename T>
        static auto dynamic_type(const T& obj) {
            if constexpr (is_polymorphic<T>) {
                return reinterpret_cast<type_id>(obj.type);
            } else {
                return reinterpret_cast<type_id>(0);
            }
        }
    };
};

该策略对 "多态" 的定义与 C++ 的不同. 在这里, 若一个类派生自 Node, 它就是 "多态" 的, 这意味着 dynamic_type 能够提取虚实参的运行期类型. 实际上, 该策略并不要求 Node 在 C++ 意义上是多态的. 如果我们移除虚析构函数, 并把 value 也实现为一个开放方法, 程序仍然可以工作.

该策略相当精简. 它不支持虚继承, 因为它没有提供 dynamic_cast_ref 函数. 它不会产生良好的错误或跟踪消息, 因为它没有提供 type_name 函数. 作为替代, 它依赖于 type_name, 后者继承自 rtti::defaults. 它将类型呈现为带修饰的整数, 例如 "type_id(2)". 所有非 "多态" 类型都会以同样的方式呈现为 "type_id(0)".

rtti::defaults 还为 type_index 提供了一个默认实现, 它只是简单地返回其实参.

现在我们需要一个策略来从对象获取 v-table 指针. 我们的 RTTI 系统有一个有趣的特性: 它的类型 id 在一个小的密集范围内单调分配. 这意味着我们可以把它们用作 vector 的索引. vptr_vector 正好适合这一用途. 下面就是我们的注册表:

struct custom_registry : boost::openmethod::registry<
        custom_rtti, boost::openmethod::policies::vptr_vector> {};

#define BOOST_OPENMETHOD_DEFAULT_REGISTRY custom_registry

定义宏 BOOST_OPENMETHOD_DEFAULT_REGISTRY 将设置所有需要注册表的库组件所使用的默认注册表.

接下来, 我们包含主头文件. 由于已定义 BOOST_OPENMETHOD_DEFAULT_REGISTRY, 其值将用作默认注册表.

示例的其余部分保持不变.

延迟 RTTI

在前一个示例中, RTTI 系统静态地分配类型 id. 另一种常见做法是使用一个由静态构造函数操作的全局计数器来分配类型 id. 如下所示:

struct Node {
    Node(unsigned type) : type(type) {}
    unsigned type;
    static unsigned last_type;
    static unsigned static_type;
};

struct Variable : Node {
    static unsigned static_type;
    Variable(int value) : Node(static_type), v(value) {}
    int v;
};

struct Plus : Node {
    static unsigned static_type;
    Plus(const Node& left, const Node& right)
        : Node(static_type), left(left), right(right) {}
    const Node& left; const Node& right;
};

struct Times : Node {
    static unsigned static_type;
    Times(const Node& left, const Node& right)
        : Node(static_type), left(left), right(right) {}
    const Node& left; const Node& right;
};

类型 id 在另一个翻译单元中分配:

unsigned Node::last_type = 0;
unsigned Node::static_type = ++Node::last_type;
unsigned Variable::static_type = ++Node::last_type;
unsigned Plus::static_type = ++Node::last_type;
unsigned Times::static_type = ++Node::last_type;

这是一个问题, 因为 static_type 由 BOOST_OPENMETHOD_CLASSES 调用, 同样也是在静态构造期间. 对于跨多个翻译单元的静态构造函数的执行顺序, 并没有任何保证. BOOST_OPENMETHOD_CLASSES 有可能在类型 id被分配之前就读取它们.

解决办法是让 rtti 策略派生自 deferred_static_rtti. 这样做会把读取类型 id 的时机推迟到 initialize 被调用时:

#include <boost/openmethod/preamble.hpp>
#include <boost/openmethod/policies/vptr_vector.hpp>

//                                          note: vvvvvvvvvvvvvvvv
struct custom_rtti : boost::openmethod::policies::deferred_static_rtti {
    template<class Registry>
    struct fn : defaults {
        template<class T>
        static constexpr bool is_polymorphic = std::is_base_of_v<Node, T>;

        using type_id = boost::openmethod::type_id; // for brevity

        template<typename T>
        static auto static_type() {
            if constexpr (is_polymorphic<T>) {
                return reinterpret_cast<type_id>(T::static_type);
            } else {
                return reinterpret_cast<type_id>(0);
            }
        }

        template<typename T>
        static auto dynamic_type(const T& obj) {
            if constexpr (is_polymorphic<T>) {
                return reinterpret_cast<type_id>(obj.type);
            } else {
                return reinterpret_cast<type_id>(0);
            }
        }
    };
};
