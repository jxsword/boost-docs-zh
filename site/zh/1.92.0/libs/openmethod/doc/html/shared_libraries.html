本节讨论 OpenMethod 如何与 Linux、其他类 POSIX 平台以及 Windows 上的共享库互操作.

静态链接

在所有平台上, 与共享库的静态链接行为与链接静态库相同. 来自程序和共享库的对象都可以向默认注册表或任何注册表提供类、方法和覆写器.

动态链接

所谓 "动态链接", 是指程序在启动之后加载共享库并访问其内容. 动态链接的一个常见应用是实现插件架构.

OpenMethod 使用全局数据来跟踪方法、覆写器和类, 它们全部由静态构造函数和析构函数管理. initialize 使用这些信息来建立分发表. 这些变量必须是真正的全局且唯一的, 库才能正确运作.

在此条件下, 共享库可以动态地向现有注册表添加类、方法和覆写器. 在加载或卸载共享库之后, 必须调用 initialize 来重建分发表.

在 Linux 和类 POSIX 平台上, 动态链接几乎不需要程序员做什么就能满足唯一性要求. 在 Linux 上, 只需加入 -rdynamic; 若使用 ENABLE_EXPORTS ON, 则是给库的目标属性添加 cmake 即可.

如果库只使用自己的注册表 (例如把开放方法作为实现细节使用), 它拥有自己的全局数据, 无需调用 initialize.

我们来看一个示例. 以下头文件被程序和共享库同时包含:

// animals.hpp

#include <string>
#include <boost/openmethod.hpp>

struct Animal { virtual ~Animal() {} };
struct Herbivore : Animal {};
struct Carnivore : Animal {};

BOOST_OPENMETHOD(
    meet, (
        boost::openmethod::virtual_ptr<Animal>,
        boost::openmethod::virtual_ptr<Animal>),
    std::string);

共享库包含一个添加两个覆写器的对象、一个新类 Tiger, 以及一个工厂函数:

// extensions.cpp
#include "animals.hpp"

using namespace boost::openmethod::aliases;

BOOST_OPENMETHOD_OVERRIDE(
    meet, (virtual_ptr<Herbivore>, virtual_ptr<Carnivore>), std::string) {
    return "run";
}

BOOST_OPENMETHOD_OVERRIDE(
    meet, (virtual_ptr<Carnivore>, virtual_ptr<Herbivore>), std::string) {
    return "hunt";
}

struct Tiger : Carnivore {};

BOOST_OPENMETHOD_CLASSES(Tiger, Carnivore);

extern "C" {
#ifdef _WIN32
__declspec(dllexport)
#endif
auto make_tiger() -> Animal* {
    return new Tiger;
}
}

主程序添加几个类, 然后调用 meet 方法. 此时, 我们只有兜底覆写器:

// dynamic_main.cpp

#include "animals.hpp"

#include <boost/openmethod.hpp>
#include <boost/openmethod/initialize.hpp>
#include <boost/dll/shared_library.hpp>
#include <boost/dll/runtime_symbol_info.hpp>
#include <iostream>
#include <memory>

using namespace boost::openmethod::aliases;

struct Cow : Herbivore {};
struct Wolf : Carnivore {};

BOOST_OPENMETHOD_CLASSES(Animal, Herbivore, Cow, Wolf, Carnivore);

BOOST_OPENMETHOD_OVERRIDE(
    meet, (virtual_ptr<Animal>, virtual_ptr<Animal>), std::string) {
    return "greet";
}

int main() {
    std::cout << "Before loading the shared library.\n";

    boost::openmethod::initialize();

    std::cout << "cow meets wolf -> "
              << meet(*std::make_unique<Cow>(), *std::make_unique<Wolf>())
              << "\n"; // greet
    std::cout << "wolf meets cow -> "
              << meet(*std::make_unique<Wolf>(), *std::make_unique<Cow>())
              << "\n"; // greet

    // to be continued...

    return 0;
}

我们使用 Boost.DLL 加载共享库. 调用 initialize 之后, 新的覆写器被安装. 主程序还可以使用 Tiger 对象, 即使它在编译期对该类一无所知.

int main() {
    // ...

    std::cout << "\nAfter loading the shared library.\n";

    boost::dll::shared_library lib(
        boost::dll::program_location().parent_path() / LIBRARY_NAME,
        boost::dll::load_mode::rtld_now);
    boost::openmethod::initialize();

    std::cout << "cow meets wolf -> "
              << meet(*std::make_unique<Cow>(), *std::make_unique<Wolf>())
              << "\n"; // run
    std::cout << "wolf meets cow -> "
              << meet(*std::make_unique<Wolf>(), *std::make_unique<Cow>())
              << "\n"; // hunt

    auto make_tiger = lib.get<Animal*()>("make_tiger");
    std::cout << "cow meets tiger -> "
              << meet(
                     *std::make_unique<Cow>(),
                     *std::unique_ptr<Animal>(make_tiger()))
              << "\n"; // hunt

    return 0;
}

最后, 我们卸载共享库并再次调用 initialize. 共享库提供的覆写器会从方法中移除.

    // ...

    std::cout << "\nAfter unloading the shared library.\n";

    lib.unload();
    boost::openmethod::initialize();

    std::cout << "cow meets wolf -> "
              << meet(*std::make_unique<Cow>(), *std::make_unique<Wolf>())
              << "\n"; // greet
    std::cout << "wolf meets cow -> "
              << meet(*std::make_unique<Wolf>(), *std::make_unique<Cow>())
              << "\n"; // greet

    return 0;
}

Windows

如果我们在 Windows 上尝试这个示例, 结果令人失望:

Before loading the shared library.
cow meets wolf -> greet
wolf meets cow -> greet

After loading the shared library.
cow meets wolf -> greet
wolf meets cow -> greet
cow meets tiger -> unknown class struct Tiger

这里发生的事情是, 程序和 DLL 各自拥有 "全局" 变量自己的副本. 当 DLL 被加载时, 其静态构造函数运行, 它们把覆写器添加到它们自己的方法副本中 (即针对给定名称和签名的 method::fn 静态变量). 当主程序调用 initialize 时, 它们被忽略.

同样, DLL 中的 BOOST_OPENMETHOD_CLASSES(Tiger, Carnivore) 把 Tiger 添加到 DLL 的注册表副本中. 从程序注册表的角度看, 这个类并不存在.

理论上, 这可以通过在需要的地方添加 declspec(dllimport) 和 declspec(dllexport) 属性来修复. 然而, 这并不可行, 因为程序和 DLL 都可能导入和导出注册表和方法. 底层对象从模板实例化而来, 这使问题更加复杂. 相关研究正在进行中. 不过, 截至目前, 只有当动态加载不尝试跨模块共享注册表时, Windows 才支持它.

间接 vptr

initialize 会重建注册表中的 v-table. 这会使所有 virtual_ptr 失效, 也会使由 inplace_vptr_base 存储在对象中、与该注册表相关的 v-table 指针失效. 这很少成为问题, 因为大多数动态加载共享库的程序都在其执行的最开始处进行加载.

否则, 必须使用间接 v-table 指针. 这可以通过使用包含 indirect_vptr 策略的注册表来实现. <boost/openmethod/default_registry.hpp> 提供一个 indirect_registry, 它拥有与 default_registry 相同的策略, 外加 indirect_vptr. 我们可以用它来覆盖默认注册表, 例如使用编译器命令行开关 (-DBOOST_OPENMETHOD_DEFAULT_REGISTRY=indirect_registry).

下面是一个携带 virtual_ptr 跨越 initialize 调用的程序示例:

// indirect_main.cpp

#include "animals.hpp"

#include <boost/openmethod.hpp>
#include <boost/openmethod/initialize.hpp>
#include <boost/openmethod/interop/std_unique_ptr.hpp>
#include <boost/dll/shared_library.hpp>
#include <boost/dll/runtime_symbol_info.hpp>
#include <iostream>

using namespace boost::openmethod::aliases;

struct Cow : Herbivore {};
struct Wolf : Carnivore {};

BOOST_OPENMETHOD_CLASSES(Animal, Herbivore, Cow, Wolf, Carnivore);

BOOST_OPENMETHOD_OVERRIDE(
    meet, (virtual_ptr<Animal>, virtual_ptr<Animal>), std::string) {
    return "greet";
}

auto main() -> int {
    using namespace boost::openmethod::aliases;

    std::cout << "Before loading the shared library.\n";
    boost::openmethod::initialize();

    auto gracie = make_unique_virtual<Cow>();
    auto willy = make_unique_virtual<Wolf>();

    std::cout << "cow meets wolf -> " << meet(*gracie, *willy) << "\n"; // greet
    std::cout << "wolf meets cow -> " << meet(*willy, *gracie) << "\n"; // greet
    std::cout << "cow.vptr() = " << gracie.vptr() << "\n"; // 0x5d3121d22be8
    std::cout << "wolf.vptr() = " << willy.vptr() << "\n"; // 0x5d3121d22bd8

    std::cout << "\nAfter loading the shared library.\n";

    boost::dll::shared_library lib(
        boost::dll::program_location().parent_path() / LIBRARY_NAME,
        boost::dll::load_mode::rtld_now);

    boost::openmethod::initialize();

    std::cout << "cow meets wolf -> " << meet(*gracie, *willy) << "\n"; // run
    std::cout << "wolf meets cow -> " << meet(*willy, *gracie) << "\n"; // hunt
    std::cout << "cow.vptr() = " << gracie.vptr() << "\n"; // 0x5d3121d21998
    std::cout << "wolf.vptr() = " << willy.vptr() << "\n"; // 0x5d3121d21988

    return 0;
}

该程序加载一个自身以 -DBOOST_OPENMETHOD_DEFAULT_REGISTRY=indirect_registry 编译的共享库.
