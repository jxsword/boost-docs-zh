1 准备工作

本节涵盖理解本参考所需的一些基本信息.

1.1 命名空间

本文档中, 除非另有说明, 所有无限定标识符都应假定定义于命名空间 boost::parameter.

1.2 异常

除非另有说明, 本文档描述的操作都不抛出异常.

1.3 线程安全

本库的所有组件都可以在多个线程中安全使用, 无需同步.1

1.4 排版约定

以无衬线字体书写的名称表示concept.

在代码块中, 斜体表示未具体指明的文本, 其满足代码块之后详细说明中给出的要求.

在宏所生成记号的规范中, 粗体用于突出显示被展开宏实参在结果中的位置.

特殊字符 β 表示 BOOST_PARAMETER_MAX_ARITY 的值.

2 术语

关键字
函数形参的名称.
关键字标签类型
用于唯一标识函数形参的类型. 其名称通常与该形参相同.
位置实参
不带显式关键字传递的实参. 其形参按通常的 C++ 方式确定: 相对于形参列表的位置.
标签类型
"关键字标签类型"的简称.
关键字对象
keyword<T> (其中 标签类型 T) 的一个实例.
带标签引用

类型与某个关键字标签类型 (该对象的关键字) 相关联、且持有引用 (指向该对象的值) 的对象.

作为简称, "对 x 的带标签引用"指值为 x 的带标签引用.

带标签默认值
一个带标签引用, 其值表示默认实参的值.
带标签惰性默认值
一个带标签引用, 其值在无参调用时计算出一个默认实参值.
预期实参类型
预期实参类型, 对单元素 ArgumentPack 而言, 是其元素值的类型. 任何其他类型 X 的预期实参类型就是 X 本身.

注释

在本参考中, 我们将根据上下文用 concept 名称 (及其他名称) 描述类型和对象. 例如, "一个 ArgumentPack"既可以指满足 ArgumentPack 的类型, 也可以指该类型的对象.

3 概念

本节描述 Parameter 库使用的泛型类型 concept.

3.1   ArgumentPack

ArgumentPack 是指向传递给函数的实际实参的带标签引用的集合. 每个 ArgumentPack 同时也是一个有效的 MPL Forward Sequence 和 MPL Associative Sequence, 由其带标签引用中的关键字标签类型组成. 若定义了 BOOST_PARAMETER_CAN_USE_MP11, 则每个 ArgumentPack 同时也是一个有效的 Boost.MP11 映射 (map), 其键为关键字标签类型. singular.cpp、compose.cpp 和 mpl.cpp 测试程序演示了此功能.

要求

在下表中,

  • A 满足 ArgumentPack
  • A 的一个实例: x
  • u 是 关键字对象, 其类型为 K
  • v 是一个带标签默认值, 其标签类型为 L, 值类型为 D
  • w 是一个带标签惰性默认值, 其标签类型为 M, 值类型为 E const
  • z 是一个包含单个元素的 ArgumentPack (由 keyword<…>::operator= 创建)

调用 w 的值时抛出的任何异常都会传播给调用者.

ArgumentPack 要求
表达式 类型 要求 语义/说明
x[u] binding<A, K>::type x 包含一个元素 b, 其关键字为 K 返回 b 的值 (按引用).
x[u] binding<A, L, D>::type 无 若 x 包含一个元素 b, 其关键字与 u 的相同, 则返回 b 的值 (按引用); 否则返回 u 的值.
x[w] lazy_binding<A, M, E>::type 无 若 x 包含一个元素 b, 其关键字与 w 的相同, 则返回 b 的值 (按引用); 否则调用 w 的值并返回其结果.
x, z 模型: ArgumentPack 无 返回一个 ArgumentPack, 包含 x 与 z 的全部元素.

3.2   ParameterSpec

一个 ParameterSpec 描述与给定关键字对应的实参的类型要求, 并指出该实参是可选还是必需. 下表详细列出允许的形式, 并描述实际实参类型满足各形式的条件. 在每一行中,

  • K 是该 ParameterSpec 的关键字标签类型
  • A 是一个预期实参类型, 与 K 相关联 (如有)
  • P 满足 ArgumentPack 且包含 A
  • F 是一个 MPL 二元元函数类
ParameterSpec 允许的形式及满足条件
类型 A 是否必需 A 必须满足的条件
K 否 不适用
optional<K,F> 否 mpl::apply2<F,A,P>::type::value 为 true.
required<K,F> 是 mpl::apply2<F,A,P>::type::value 为 true.

ParameterSpec 中的信息用于限制 转发函数将匹配的实参.

operator=

概要: 
template <typename T>
constexpr ArgumentPack operator=(T const& value) const;

template <typename T>
constexpr ArgumentPack operator=(T& value) const;

template <typename T>
constexpr ArgumentPack operator=(T const&& value) const;

template <typename T>
constexpr ArgumentPack operator=(T&& value) const;
要求:以下之一:
  • Tag 的嵌套 qualifier 类型必须是 forward_reference.
  • 要使用 const 左值引用重载, T 必须是标量, 或 Tag 的嵌套 qualifier 类型必须是 in_reference.
  • 要使用可变左值引用重载, Tag 的嵌套 qualifier 类型必须是 out_reference 或 in_out_reference, 且 T 不得带 const 限定.
  • 要对非标量 T 使用 const 右值引用重载, Tag 的嵌套 qualifier 类型必须是 in_reference.
  • 要对非标量 T 使用可变右值引用重载, Tag 的嵌套 qualifier 类型必须是 consume_reference 或 move_from_reference.
返回:一个 ArgumentPack, 包含单个带标签引用: 指向 value, 关键字为 Tag

4.3   parameters

提供一个接口, 用于把转发函数的实际实参组装成 ArgumentPack, 其中任何位置实参将按照 parameters 的相应模板实参打上标签.

定义于:boost/parameter/parameters.hpp 
template <typename ...PSpec>
struct parameters
{
    template <typename ...Args>
    struct match
    {
        typedef … type;
    };

    template <typename ...Args>
    ArgumentPack operator()(Args&&... args) const;
};
要求: PSpec 参数包中的每个元素都必须是 ParameterSpec 的模型.

注释

在本节中, 对任何实参类型 A ## i, R ## i 与 K ## i 定义如下:

令 D0 为集合 [d0, …, d ## j], 即所有推导的
parameter spec (位于 PSpec 参数包中) 的集合
R ## i 是预期实参类型, 对应 A ## i

若 A ## i 是如下运算符的结果类型: keyword<T>:: operator=
then
K ## i 为 T
否则
若某个 A ## j (j ≤ i) 是
keyword<T>:: operator=
或者 某个 P ## j (其中 j ≤ i) 是推导的
then
若某个parameter spec d ## j 存在于 D ## i
匹配 A ## i
then
K ## i 是关键字标签类型, 属于 d ## j.
Di+1 为 D ## i - [ d ## j]
否则
K ## i 是关键字标签类型, 属于 P ## i.
match
用于把转发函数从重载决议中移除的元函数.
返回:若 Params... 中的所有元素都被满足 (见下文), 则为 parameters<Params...>; 否则 match<Args...>::type 未定义.

P 是 Params... 中的元素, 若以下任一条件成立则被满足:

  • P 是未指明的默认值
  • 或者, P 是一个关键字标签类型
  • 或者, P 是 optional <X,F>, 且
    • X 不是任何 K ## i (对任何 i),
    • 或者 X 是某个 K ## i, 且 mpl::apply<F,R ## i
      >::type::value 为 true
  • 或者, P 是 required <X,F>, 且
    • X 是某个 K ## i, 且
    • mpl::apply<F,R ## i >::type::value 为 true

operator()

概要: 
template <typename ...Args>
ArgumentPack operator()(Args&&... args) const;
返回:

一个 ArgumentPack, 对每个 a ## i 包含:

  • 若 a ## i 是单元素 ArgumentPack, 则为其元素
  • 否则, 为一个带标签引用, 其关键字为 K ## i, 其值
    a ## i

5 元函数

元函数在概念上是一个操作 C++ 类型并返回 C++ 类型的函数.

5.1   binding

返回用关键字标签类型或带标签默认值对实参包进行索引的结果类型.

定义于:boost/parameter/binding.hpp 
template <typename A, typename K, typename D = void_>
struct binding
{
    typedef … type;
};
要求:A 必须是 ArgumentPack 的模型.

BOOST_PARAMETER_FUNCTION((bool), evaluate, kw,
    (deduced
        (required
            (lrc, (std::bitset<1>))
            (lr, (std::bitset<2>))
        )
        (optional
            (rrc, (std::bitset<3>), rvalue_const_bitset<2>())
            (rr, (std::bitset<4>), rvalue_bitset<3>())
        )
    )
)
{
    BOOST_TEST_EQ(
        passed_by_lvalue_reference_to_const
      , U::evaluate_category<0>(lrc)
    );
    BOOST_TEST_EQ(
        passed_by_lvalue_reference
      , U::evaluate_category<1>(lr)
    );
    BOOST_TEST_EQ(
        passed_by_rvalue_reference_to_const
      , U::evaluate_category<2>(std::forward<rrc0_type>(rrc0))
    );
    BOOST_TEST_EQ(
        passed_by_rvalue_reference
      , U::evaluate_category<3>(args[_rr0])
    );

    return true;
}

宏参数:

  • name 是函数的基本名称; 它决定生成的转发函数的名称.

实参说明符语法:

argument-specifiers ::= specifier-group0 {specifier-group0}

specifier-group0 ::= specifier-group1 |
    (
        '(' 'deduced'
            specifier-group1 {specifier-group1}
        ')'
    )

specifier-group1 ::=
    (
        '(' 'optional'
            optional-specifier {optional-specifier}
        ')'
    ) | (
        '(' 'required'
            required-specifier {required-specifier}
        ')'
    )

optional-specifier ::=
    '('
        argument-name ',' restriction ',' default-value
    ')'

required-specifier ::=
    '(' argument-name ',' restriction ')'

restriction ::=
    ( '*' '(' mfc ')' ) |
    ( '(' type-name ')' ) |
    '*'
  • argument-name 是任何有效的 C++ 标识符.
  • default-value 是任何有效的 C++ 表达式; 如有必要, 用户代码可以依据 previous-name ## _type 计算它, 其中 previous-name 是前一个 specifier-group0 或 specifier-group1 中的 argument-name. 此表达式将恰好被调用一次.
  • mfc 是一个 MPL 二元元函数类: 其第一个实参将是相应 argument-name 的类型, 第二个实参将是整个 ArgumentPack, 返回类型是一个布尔整型常量; 但是, 用户代码不能用 mfc 依据 previous-name ## _type 计算得出.
  • type-name 要么是一个目标类型的名称, 要么是一个 MPL 二元元函数类: 其第一个实参将是相应 argument-name 的类型, 第二个实参将是整个 ArgumentPack, 返回类型是目标类型. 若 restriction 使用此形式, 则生成的名称 argument-name ## _type 的类型将依据目标类型计算, 并且生成的引用 argument-name (但不含其在 args 中的对应项) 将被转换成该类型.

    char const* key;

        (deduced
            (required
                (y, (int))
                (z, (char const*))
            )

        this->key = z;

class char_reader
{
    int index;
    char const* key;

 public:
    explicit char_reader(char const* k) : index(0), key(k)
    {
    }

    BOOST_PARAMETER_BASIC_FUNCTION_CALL_OPERATOR((void), tag,
        (deduced
            (required
                (y, (int))
                (z, (char const*))
            )
        )
    )
    {
        this->index = args[_y];
        this->key = args[_z];
    }

    BOOST_PARAMETER_BASIC_CONST_FUNCTION_CALL_OPERATOR((char), tag,
        (deduced
            (required
                (y, (bool))
                (z, (std::map<char const*, std::string>))
            )
        )
    )
    {
        return args[_y] ? (
            (args[_z].find(this->key)->second)[this->index]
        ) : this->key[this->index];
    }
};

            >
        >
    >
>((_x = 0, _y = 1), 0, 1);

// Use mp_bind_q on tag::x to access the value type of _x.
check<
    parameters<
        tag::x
      , optional<
            deduced<tag::y>
          , boost::mp11::mp_bind<
                std::is_convertible // boost::is_convertible, standard version.
              , boost::mp11::_1 // will be bound to the argument type of _y.
              , boost::mp11::mp_bind_q<
                    tag::x
                  , boost::mp11::_2 // will be bound to the argument pack type.
                >
            >
        >
    >
>((_x = 0U, _y = 1U), 0U, 1U);

8.4   BOOST_PARAMETER_DISABLE_MP11_USAGE

对无法支持 Boost.MP11 的编译器, 可能需要禁用对其的使用. 用户可以在项目设置中或在包含任何库头文件之前 #define 此宏. 这样做会使 BOOST_PARAMETER_CAN_USE_MP11 保持未定义.

8.5   BOOST_PARAMETER_VARIADIC_MPL_SEQUENCE

若 BOOST_PARAMETER_HAS_PERFECT_FORWARDING 已被 #define, 则确定 MPL 变参序列, 即 parameters 的嵌套 parameter_spec 类型所依据的序列. 若用户未手动 #define 此宏, 则本库会把它 #define 为 boost::mp11::mp_list (若 BOOST_PARAMETER_CAN_USE_MP11 已定义), boost::fusion::list (若 BOOST_FUSION_HAS_VARIADIC_LIST 已由 Boost.Fusion 定义), boost::fusion::deque (若 BOOST_FUSION_HAS_VARIADIC_DEQUE 已由 Boost.Fusion 定义), 否则 boost::mpl::vector.

示例: 
#define BOOST_PARAMETER_VARIADIC_MPL_SEQUENCE boost::fusion::vector
定义于:boost/parameter/parameters.hpp

8.6   BOOST_PARAMETER_MAX_ARITY

若 BOOST_PARAMETER_HAS_PERFECT_FORWARDING 已被 #define, 则:

  • 若 MPL 变参序列 (parameters 的嵌套 parameter_spec 类型所依据的) 没有大小限制 — boost::mp11::mp_list、boost::fusion::list 和 boost::fusion::deque 即是如此, 而 boost::mpl::vector 则不然 — 则可以安全地忽略此宏. 手动定义 BOOST_PARAMETER_VARIADIC_MPL_SEQUENCE 的用户代码, 若该序列有大小限制, 也应手动把此宏定义为该大小限制.

若 BOOST_PARAMETER_HAS_PERFECT_FORWARDING 未被 #define, 则:

  • 若把可变引用按位置传给支持 Boost.Parameter 且元数大于或等于阈值的函数, 则必须用 boost::ref 或 std::ref 包裹; 该阈值即 BOOST_PARAMETER_EXPONENTIAL_OVERLOAD_THRESHOLD_ARITY.
定义于:boost/parameter/config.hpp
默认值:BOOST_MPL_LIMIT_VECTOR_SIZE (由 Boost.MPL 定义), 若支持完美转发; 否则为 8.
最小值:2
最大值:BOOST_PARAMETER_COMPOSE_MAX_ARITY

8.7   BOOST_PARAMETER_COMPOSE_MAX_ARITY

若 BOOST_PARAMETER_HAS_PERFECT_FORWARDING 未被 #define, 则确定 compose 函数以及 BOOST_PARAMETER_NO_SPEC_FUNCTION、BOOST_PARAMETER_NO_SPEC_MEMBER_FUNCTION、BOOST_PARAMETER_NO_SPEC_CONST_MEMBER_FUNCTION、BOOST_PARAMETER_NO_SPEC_FUNCTION_CALL_OPERATOR、BOOST_PARAMETER_NO_SPEC_CONST_FUNCTION_CALL_OPERATOR、BOOST_PARAMETER_NO_SPEC_CONSTRUCTOR 和 BOOST_PARAMETER_NO_SPEC_NO_BASE_CONSTRUCTOR 代码生成宏所支持的实参个数上限.

定义于:boost/parameter/config.hpp
默认值:20 (少数较老的编译器), 否则 64
最小值:2

8.8   BOOST_PARAMETER_EXPONENTIAL_OVERLOAD_THRESHOLD_ARITY

若本库不支持完美转发, 则确定一个实参个数阈值: 在低于该阈值时 parameters 会生成指数数量的函数调用运算符重载, 在大于等于该阈值时 parameters 则不会. 本库只会在以下情况下把它 #defined: 它尚未被 #defined, 且 BOOST_PARAMETER_HAS_PERFECT_FORWARDING 未被 #defined.

定义于:boost/parameter/config.hpp
默认值:0
最小值:0
