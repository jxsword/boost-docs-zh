Boost.Parameter 库

摘要:使用本库编写可以按名称接受实参的函数和类模板: 
new_window(
    "alert"
  , _width=10
  , _titlebar=false
);

smart_ptr<
    Foo
  , deleter<Deallocate<Foo> >
  , copy_policy<DeepCopy>
> p(new Foo);

由于命名实参可以按任意顺序传递, 当函数或模板有多个带有有用默认值的形参时, 它们尤其有用. 本库还支持 推导参数: 即可以从其类型推导出其身份的参数.

1 动机

在 C++ 中, 实参通常按其相对于形参列表的位置获得含义: 传递的第一个实参映射到函数定义中的第一个形参, 依此类推. 当最多只有一个带默认值的形参时, 这种协议没有问题; 但只要存在几个有用的默认值, 位置式接口就会变得繁重:

  • 由于实参的含义由其位置决定, 我们必须为带默认值的形参选择一个 (往往是任意的) 顺序, 这使得某些默认值组合无法使用:

    window* new_window(
    char const* name
  , int border_width = default_border_width
  , bool movable = true
  , bool initially_visible = true
);

bool const movability = false;
window* w = new_window("alert box", movability);

    在上面的示例中, 我们想要创建一个不可移动、border_width 取默认值的窗口, 结果却得到一个可移动且 border_width 为零的窗口. 要获得期望的效果, 需要这样写:

    window* w = new_window(
    "alert box", default_border_width, movability
);

  • 读者可能很难理解调用点处实参的含义:

    window* w = new_window("alert", 1, true, false);

    这个窗口是可移动且初始不可见, 还是不可移动且初始可见? 读者需要记住实参的顺序才能确定.

  • 调用的作者可能也记不住实参的顺序, 从而导致难以发现的缺陷.

1.1 命名函数参数

本库通过把每个形参名与一个关键字对象关联来解决上述问题. 现在, 用户可以按名称而非位置来标识实参:

window* w = new_window(
    "alert box"
  , movable_=false
); // OK!

1.2 推导函数参数

推导参数可以在不提供显式形参名的情况下以任意位置传递. 函数拥有可根据所传实参类型唯一标识的形参, 这种情况并不少见. new_window 的 name 形参就是这样一个例子: 其他实参 (若有效) 都不能合理地转换为 char const*. 有了推导参数接口, 我们就可以在任何实参位置传递窗口名而不会引起歧义:

window* w = new_window(
    movable_=false
  , "alert box"
); // OK!
window* w = new_window(
    "alert box"
  , movable_=false
); // OK!

恰当地使用推导参数接口, 可以让用户甚至不必记住形式参数名.

1.3 类模板参数支持

我们为命名参数接口和推导参数接口给出的理由, 同样适用于类模板, 正如适用于函数一样. 使用 Parameter 库, 我们可以创建允许显式命名模板实参 (此处为 shared 和 Client) 的接口, 如下:

smart_ptr<
    ownership<shared>
  , value_type<Client>
> p;

传递命名模板实参的语法不如函数实参的语法自然 (理想情况下, 我们希望能写 smart_ptr<ownership = shared, …>). 这一小小的语法缺陷使得推导参数与类模板搭配使用时收益尤其大:

// p and q could be equivalent, given a deduced
// parameter interface.
smart_ptr<shared, Client> p;
smart_ptr<Client, shared> q;

2 教程

本教程展示了所有基础知识 (如何为函数模板和类模板构建命名参数接口与推导参数接口), 以及若干更高级的惯用法.

2.1 支持命名参数的函数

本节将展示如何使用 Parameter 库为 Boost Graph 库 的 depth_first_search 算法构建富有表现力的接口.1

2.1.1 头文件与命名空间

Parameter 库的大多数组件都在以其命名的头文件中声明. 例如,

#include <boost/parameter/keyword.hpp>

将确保编译器知道 boost::parameter::keyword. 还有一个合并头文件 boost/parameter.hpp, 它包含本库的大多数组件. 在本教程的其余部分, 除非另有说明, 你都可以用上述规则确定访问库中任一组件应 #include 哪个头文件.

此外, 下面的示例也将按照已经声明了命名空间别名

namespace parameter = boost::parameter;

的方式来编写: 我们将写 parameter::xxx 而非 boost::parameter::xxx.

2.1.2 抽象接口: depth_first_search

Graph 库的 depth_first_search 算法是一个泛型函数, 按引用接受一到四个实参. 若所有实参都是必需的, 其签名可能如下:

template <
    typename Graph
  , typename DFSVisitor
  , typename Index
  , typename ColorMap
>
void
    depth_first_search(
        Graph const& graph
      , DFSVisitor visitor
      , typename graph_traits<g>::vertex_descriptor root_vertex
      , IndexMap index_map
      , ColorMap& color
    );

但是, 大多数形参都有有用的默认值, 如下表所示.

depth_first_search 的形参
形参名称 数据流向 类型 默认值 (如有)
graph in 模型: Incidence Graph、Vertex List Graph 无: 此实参是必需的.
visitor in 模型: DFS Visitor boost::dfs_visitor<>()
root_vertex in graph 的顶点描述符类型. *vertices(graph).first
index_map in Readable Property Map 的模型, 键类型为 graph 的顶点描述符, 值类型为整数类型. get(boost::vertex_index,graph)
color_map 输入/输出 Read/Write Property Map 的模型, 键类型为 graph 的顶点描述符类型. 一个 boost::iterator_property_map, 由 std::vector 创建, 元素类型为 default_color_type, 大小为 num_vertices(graph), 并使用 index_map 作为索引映射.

不必被上面第二列和第三列的信息吓到. 就本练习而言, 你不需要详细理解它们.

2.1.3 定义关键字

本练习的目的是让 depth_first_search 可以用命名实参调用, 并省略任何默认值合适的实参:

graphs::depth_first_search(g, color_map_=my_color_map);

要使该语法合法, 需要存在一个名为 "color_map_" 的对象, 其赋值运算符可以接受 my_color_map 实参. 在这一步, 我们将为每个形参创建一个这样的关键字对象. 每个关键字对象将由一个唯一的关键字标签类型标识.

我们将在命名空间 graphs 中定义接口. 本库为定义关键字对象提供了一个便捷宏:

#include <boost/parameter/name.hpp>

namespace graphs {

    BOOST_PARAMETER_NAME(graph)    // Note: no semicolon
    BOOST_PARAMETER_NAME(visitor)
    BOOST_PARAMETER_NAME(root_vertex)
    BOOST_PARAMETER_NAME(index_map)
    BOOST_PARAMETER_NAME(color_map)
}

你在这里看到的 graph 关键字的声明等效于:

namespace graphs {
    namespace tag {

        // keyword tag type
        struct graph
        {
            typedef boost::parameter::forward_reference qualifier;
        };
    }

    namespace // unnamed
    {
        // A reference to the keyword object
        boost::parameter::keyword<tag::graph> const& _graph
            = boost::parameter::keyword<tag::graph>::instance;
    }
}

它定义了一个 关键字标签类型 (名为 tag::graph) 和一个 关键字对象引用 (名为 _graph).

这些涉及无名命名空间和引用的"花哨操作"全都是为了: 在使用命名参数接口的函数模板被多个翻译单元实例化时, 避免违反一次定义规则 (ODR)2 (MSVC6.x 用户见此说明).

2.1.4 编写函数

定义好关键字之后, 函数模板定义遵循使用 BOOST_PARAMETER_FUNCTION 宏的简单模式:

#include <boost/parameter/preprocessor.hpp>

namespace graphs {

    BOOST_PARAMETER_FUNCTION(
        (void),                 // 1. parenthesized return type
        depth_first_search,     // 2. name of the function template
        tag,                    // 3. namespace of tag types
        (required (graph, *) )  // 4. one required parameter, and
        (optional               //    four optional parameters,
                                //    with defaults
            (visitor,     *, boost::dfs_visitor<>())
            (root_vertex, *, *vertices(graph).first)
            (index_map,   *, get(boost::vertex_index,graph))
            (color_map,   *,
                default_color_map(num_vertices(graph), index_map)
            )
        )
    )
    {
        // ... body of function goes here...
        // use graph, visitor, index_map, and color_map
    }
}

BOOST_PARAMETER_FUNCTION 的实参包括:

  1. 生成的函数模板的返回类型. 返回类型两侧的圆括号可防止其可能包含的逗号干扰预处理器, 并且总是必需的.
  2. 生成的函数模板的名称.
  3. 一个命名空间的名称, 在其中可以找到名称与函数形参名匹配的标签类型.
  4. 函数签名.

2.1.5 函数签名

函数签名描述为一个或两个相邻的带括号项 (Boost.Preprocessor 序列), 按形参若按位置传递时的期望顺序描述函数的各个形参. 任何必需的形参必须放在最前面; 但当所有形参都是可选时, (required … ) 子句可以省略.

2.1.5.1 必需形参

必需形参放在最前面, 嵌套在 (required … ) 子句中, 写成一系列二元组, 描述每个形参名以及对实参类型的任何要求. 此处只有一个必需形参, 因此只有一个二元组:

(required (graph, *) )

由于 depth_first_search 不要求其 graph 形参具有特定类型, 我们用星号表示允许任何类型. 必需形参必须始终位于签名中任何可选形参之前; 但若没有必需形参, (required … ) 子句可以完全省略.

2.1.5.2 可选形参

可选形参嵌套在 (optional … ) 子句中, 写成一系列相邻的三元素组, 描述形参名、对实参类型的任何要求, 以及表示形参默认值的表达式:

(optional
    (visitor,     *, boost::dfs_visitor<>())
    (root_vertex, *, *vertices(graph).first)
    (index_map,   *, get(boost::vertex_index,graph))
    (color_map,   *,
        default_color_map(num_vertices(graph), index_map)
    )
)

2.1.5.3 处理"输入"、"输出"、"消耗/移入"与"转发"形参

默认情况下, Boost.Parameter 把所有形参当作 转发 形参, 即函数会以右值引用接受它们, 并且只会用 std::forward 或 boost::forward 把它们转发给其他函数. 此类形参可以是 const 左值、可变左值、const 右值或可变右值. 因此, 默认配置给予用户代码最大的灵活性. 然而:

  • 用户可以把一个或多个形参配置为 输入 形参: 它们可以与 转发 形参属于相同的类别, 但现在按 const 左值引用传递, 因而只能读取. 接着上一个示例, 为表明 root_vertex 和 index_map 是只读的, 我们把它们的名称包裹在 in(…) 中.
  • 用户可以把一个或多个形参配置为 输出 形参 (函数只写) 或 输入-输出 形参 (函数既读又写). 此类形参只能是可变左值. 在示例中, 为表明 color_map 是可读写的, 我们把它的名称包裹在 in_out(…) 中. 注意, Boost.Parameter 认为 out(…) 与 in_out(…) 没有功能差异, 因此你可以选择更能自文档化的那一种.
  • 用户可以把一个或多个形参配置为 消耗或 移入 形参: 函数会以可变右值引用接受它们, 并以 std::move 或 boost::move 作为最后一步访问. 此类形参只能是可变右值. Boost.Parameter 支持把相应名称包裹在 consume(…) 或 move_from(…) 中.
BOOST_PARAMETER_NAME(graph)
BOOST_PARAMETER_NAME(visitor)
BOOST_PARAMETER_NAME(in(root_vertex))
BOOST_PARAMETER_NAME(in(index_map))
BOOST_PARAMETER_NAME(in_out(color_map))

要查看形参绑定到违反其类别约束的实参时会发生什么, 可以尝试编译 compose.cpp 测试程序, 并以 #define 定义 LIBS_PARAMETER_TEST_COMPILE_FAILURE_0 宏或 LIBS_PARAMETER_TEST_COMPILE_FAILURE_1 宏. 你应当会遇到由特定约束违规导致的编译错误.

2.1.5.4 位置实参

当实参按位置传递 (不使用关键字) 时, 它们将按签名中形参给出的顺序映射到形参上. 例如在此调用中

graphs::depth_first_search(x, y);

x 将始终被解释为图, 而 y 将始终被解释为访问器.

2.1.5.5 默认表达式求值

注意, 在我们的示例中, graph 形参的值被用于 root_vertex、index_map 和 color_map 的默认表达式中.

(required (graph, *) )
(optional
    (visitor,     *, boost::dfs_visitor<>())
    (root_vertex, *, *vertices(graph).first)
    (index_map,   *, get(boost::vertex_index, graph))
    (color_map,   *,
        default_color_map(num_vertices(graph), index_map)
    )
)

若某个形参传入了实际实参, 则其默认表达式永远不会被求值, 甚至不会被实例化. 我们可以用目前的代码实际演示这一点: 把 depth_first_search 的函数体替换为打印实参的内容:

#include <boost/graph/depth_first_search.hpp>  // for dfs_visitor

BOOST_PARAMETER_FUNCTION(
    (bool), depth_first_search, tag
    …signature goes here…
)
{
    std::cout << "graph=" << graph;
    std::cout << std::endl;
    std::cout << "visitor=" << visitor;
    std::cout << std::endl;
    std::cout << "root_vertex=" << root_vertex;
    std::cout << std::endl;
    std::cout << "index_map=" << index_map;
    std::cout << std::endl;
    std::cout << "color_map=" << color_map;
    std::cout << std::endl;
    return true;
}

#include <boost/core/lightweight_test.hpp>

int main()
{
    char const* g = "1";
    depth_first_search(1, 2, 3, 4, 5);
    depth_first_search(
        g, '2', _color_map = '5',
        _index_map = "4", _root_vertex = "3"
    );
    return boost::report_errors();
}

尽管 vertices(graph).first 之类的默认表达式对给定的 graph 实参是病态的, 两个调用都会编译通过, 并且每个调用打印的内容完全相同.

2.1.5.6 签名匹配与重载

实际上, 该函数签名非常宽泛: 只要为必需的 graph 形参传递了某个值, 对 depth_first_search 的任何少于五个实参的调用都会匹配我们的函数. 乍看之下这似乎不是问题; 毕竟, 若实参不符合 depth_first_search 实现所施加的要求, 稍后在其函数体被实例化时会产生编译错误.

非常宽泛的函数签名至少有三个问题.

  1. 当我们的 depth_first_search 被实例化时, 它已被选为最佳匹配重载. 本来可能有其他 depth_first_search 重载若被选中反而可以工作. 等我们看到编译错误时, 已经没有机会改变这一决定.
  2. 即使没有重载, 在实例化时产生的错误消息通常会把令人困惑的实现细节暴露给用户. 例如, 用户可能看到 BOOST_PARAMETER_FUNCTION 生成的名称, 如 graphs::detail::depth_first_search_with_named_params (更糟的是, 想想你在 STL 实现中犯错时会得到什么样的错误).4
  3. 暴露这种过于宽松的函数模板签名所带来的问题一直是讨论的焦点, 在存在无限定调用时尤其如此. 若我们只是想避免无意的实参依赖查找 (ADL), 可以把 depth_first_search 隔离在一个不含任何类型的命名空间中6; 但假如我们就是希望它能通过 ADL 找到呢?

当传入的实参类型不合适时, 阻止函数参与重载决议通常是个好主意. 当未提供必需的 graph 形参时, 本库已经会这样做; 但我们不太可能遇到不接收图作为操作对象的深度优先搜索. 假设我们找到了另一个深度优先搜索算法, 它可以作用于不满足 Incidence Graph 的图呢? 若只是简单地添加一个重载, 就会产生歧义:

// new overload
BOOST_PARAMETER_FUNCTION((void), depth_first_search, (tag),
    (required (graph,*))( … )
)
{
    // new algorithm implementation
}

…

// ambiguous!
depth_first_search(boost::adjacency_list<>(), 2, "hello");
2.1.5.6.1 谓词要求

我们确实不希望编译器考虑原版的 depth_first_search, 因为 root_vertex 实参 "hello" 不满足这一要求: 与 graph 形参的顶点描述符类型相匹配. 相反, 这个调用应当只调用我们的新重载. 为了让原 depth_first_search 重载退出竞争, 我们首先按如下方式编码这一要求:

struct vertex_descriptor_predicate
{
    template <typename T, typename Args>
    struct apply
      : boost::mpl::if_<
            boost::is_convertible<
                T
              , typename boost::graph_traits<
                    typename boost::parameter::value_type<
                        Args
                      , graphs::graph
                    >::type
                >::vertex_descriptor
            >
          , boost::mpl::true_
          , boost::mpl::false_
        >
    {
    };
};

这种编码是一个 MPL 二元元函数类: 一种带有嵌套 apply 元函数的类型, 该元函数接受两个模板实参. 对于第一个模板实参, Boost.Parameter 会传入我们对其施加要求的类型; 对于第二个模板实参, Boost.Parameter 会传入整个实参包, 从而可以提取 depth_first_search 其他形参的类型 (借助 value_type 元函数及相应关键字标签类型). apply 元函数的结果 type 将等效于 boost::mpl::true_, 若 T 满足 boost::is_convertible 语句所施加的要求; 否则结果等效于 boost::mpl::false_.

至此, 我们可以把元函数类的名称加圆括号后追加到函数签名中相应的 * 元素上.

(root_vertex
  , *(vertex_descriptor_predicate)
  , *vertices(graph).first
)

现在, 只有当 root_vertex 实参可以转换为图的顶点描述符类型时, 原版 depth_first_search 才会被调用; 而我们那个原本有歧义的示例将顺利调用新重载.

我们可以用同样的概念对其他实参的求编码要求; 只需为每个实参调整嵌套 apply 元函数的实现. 这里没有篇幅完整描述 graph 库的细节, 但只需展示接下来的几个元函数类提供了必要的检查即可.

struct graph_predicate
{
    template <typename T, typename Args>
    struct apply
      : boost::mpl::eval_if<
            boost::is_convertible<
                typename boost::graph_traits<T>::traversal_category
              , boost::incidence_graph_tag
            >
          , boost::mpl::if_<
                boost::is_convertible<
                    typename boost::graph_traits<T>::traversal_category
                  , boost::vertex_list_graph_tag
                >
              , boost::mpl::true_
              , boost::mpl::false_
            >
        >
    {
    };
};

struct index_map_predicate
{
    template <typename T, typename Args>
    struct apply
      : boost::mpl::eval_if<
            boost::is_integral<
                typename boost::property_traits<T>::value_type
            >
          , boost::mpl::if_<
                boost::is_same<
                    typename boost::property_traits<T>::key_type
                  , typename boost::graph_traits<
                        typename boost::parameter::value_type<
                            Args
                          , graphs::graph
                        >::type
                    >::vertex_descriptor
                >
              , boost::mpl::true_
              , boost::mpl::false_
            >
        >
    {
    };
};

struct color_map_predicate
{
    template <typename T, typename Args>
    struct apply
      : boost::mpl::if_<
            boost::is_same<
                typename boost::property_traits<T>::key_type
              , typename boost::graph_traits<
                    typename boost::parameter::value_type<
                        Args
                      , graphs::graph
                    >::type
                >::vertex_descriptor
            >
          , boost::mpl::true_
          , boost::mpl::false_
        >
    {
    };
};

同样, 计算 color_map 形参的默认值也非小事, 因此最好把该计算提取到单独的函数模板中.

template <typename Size, typename IndexMap>
boost::iterator_property_map<
    std::vector<boost::default_color_type>::iterator
  , IndexMap
  , boost::default_color_type
  , boost::default_color_type&
>&
    default_color_map(Size num_vertices, IndexMap const& index_map)
{
    static std::vector<boost::default_color_type> colors(num_vertices);
    static boost::iterator_property_map<
        std::vector<boost::default_color_type>::iterator
      , IndexMap
      , boost::default_color_type
      , boost::default_color_type&
    > m(colors.begin(), index_map);
    return m;
}

签名把每个谓词元函数括在圆括号中, 并以星号作为前缀, 如下:

BOOST_PARAMETER_FUNCTION((void), depth_first_search, graphs,
(required
    (graph, *(graph_predicate))
)
(optional
    (visitor
      , *  // not easily checkable
      , boost::dfs_visitor<>()
    )
    (root_vertex
      , (vertex_descriptor_predicate)
      , *vertices(graph).first
    )
    (index_map
      , *(index_map_predicate)
      , get(boost::vertex_index, graph)
    )
    (color_map
      , *(color_map_predicate)
      , default_color_map(num_vertices(graph), index_map)
    )
)
)

对泛型函数的实参如此完整地编码类型要求通常并非必要. 但这样做是值得的: 你的代码将更具自文档性, 并且往往能提供更好的用户体验. 借助 对约束和 concept 的语言支持, 你也将更平稳地过渡到 C++20 标准.

2.1.5.6.2 关于类型要求的更多内容

为函数形参编码类型要求, 对于让函数拥有推导参数接口至关重要. 我们再回来看一下 new_window 示例:

window* w = new_window(
    movable_=false
  , "alert box"
);
window* w = new_window(
    "alert box"
  , movable_=false
);

这一次的目标是能够在不指定关键字的情况下调用 new_window 函数. 对于每个具有要求类型的形参, 我们可以把该类型括在圆括号中, 然后替换形参签名中的 * 元素:

BOOST_PARAMETER_NAME((name_, keywords) name)
BOOST_PARAMETER_NAME((movable_, keywords) movable)

BOOST_PARAMETER_FUNCTION((window*), new_window, keywords,
    (deduced
        (required
            (name, (char const*))
            (movable, (bool))
        )
    )
)
{
    // ...
}

现在以下语句可以工作, 它们彼此等效, 也与之前的语句等效:

window* w = new_window(false, "alert box");
window* w = new_window("alert box", false);

2.1.5.7 推导参数

为进一步说明推导参数支持, 考虑 def 函数 (来自 Boost.Python) 的示例. 其签名大致如下:

template <
    typename Function
  , typename KeywordExpression
  , typename CallPolicies
>
void def(
    // Required parameters
    char const* name, Function func

    // Optional, deduced parameters
  , char const* docstring = ""
  , KeywordExpression keywords = no_keywords()
  , CallPolicies policies = default_call_policies()
);

请不要被本示例中"关键字"一词的使用分心: 虽然它在 Boost.Python 中的含义与在 Parameter 库中类似, 但就本练习而言, 你可以把它当作完全不同的东西.

调用 def 时只需要两个实参. 其余实参与其形参之间的关联可以由实际传递的实参类型确定, 因此调用者既不必记住实参位置, 也不必为这些实参显式指定形参名. 要用 BOOST_PARAMETER_FUNCTION 生成此接口, 只需把推导参数括入 (deduced …) 子句, 如下:

char const*& blank_char_ptr()
{
    static char const* larr = "";
    return larr;
}

BOOST_PARAMETER_FUNCTION(
    (bool), def, tag,

    (required (name, (char const*)) (func,*) )  // nondeduced

    (deduced
        (optional
            (docstring, (char const*), "")

            (keywords
                // see5
              , *(is_keyword_expression<boost::mpl::_>)
              , no_keywords()
            )

            (policies
              , *(
                    boost::mpl::eval_if<
                        boost::is_convertible<boost::mpl::_,char const*>
                      , boost::mpl::false_
                      , boost::mpl::if_<
                            // see5
                            is_keyword_expression<boost::mpl::_>
                          , boost::mpl::false_
                          , boost::mpl::true_
                        >
                    >
                )
              , default_call_policies()
            )
        )
    )
)
{
    …
}

语法说明

(deduced …) 子句总是包含 (required …) 和/或 (optional …) 子子句, 并且必须位于外层指示非推导形参的任何 (required …) 或 (optional …) 子句之后.

有了上述声明, 以下两个调用等效:

char const* f_name = "f";
def(
    f_name
  , &f
  , some_policies
  , "Documentation for f"
);
def(
    f_name
  , &f
  , "Documentation for f"
  , some_policies
);

若用户想传递一个出于某种原因也可转换为 char const* 的 policies 实参, 她始终可以按如下方式显式指定形参名:

def(
    f_name
  , &f
  , _policies = some_policies
  , "Documentation for f"
);

deduced.cpp 和 deduced_dependent_predicate.cpp 测试程序演示了推导参数支持的更多用法.

2.1.5.8 依赖形参的返回类型

对某些算法而言, 返回类型至少取决于一个实参类型. 但是, 在使用 BOOST_PARAMETER_FUNCTION 或其他代码生成宏编码该返回类型时, 有一个陷阱要避免. 例如, 给定以下定义:

BOOST_PARAMETER_NAME(x)
BOOST_PARAMETER_NAME(y)
BOOST_PARAMETER_NAME(z)

让我们的算法简单地返回其某个实参. 若我们天真地用 parameter::value_type 来实现其返回类型:

BOOST_PARAMETER_FUNCTION(
    (typename parameter::value_type<Args,tag::y>::type), return_y, tag,
    (deduced
        (required
            (x, (std::map<char const*,std::string>))
            (y, (char const*))
        )
        (optional
            (z, (int), 4)
        )
    )
)
{
    return y;
}

那么以位置实参以外的任何方式使用 return_y 都将导致编译错误:

std::map<char const*,std::string> k2s;
assert("foo" == return_y(2, k2s, "foo"));  // error!

问题在于, 尽管 y 是必需形参, BOOST_PARAMETER_FUNCTION 会生成某些重载, 其实参包类型 Args 并不实际包含关键字标签类型 tag::y. 解决办法是使用 SFINAE 阻止生成那些重载. 由于 parameter::value_type 是元函数, 我们用于此工作的工具是 lazy_enable_if:

BOOST_PARAMETER_FUNCTION(
    (
        // Whenever using 'enable_if', 'disable_if', and so on,
        // do not add the 'typename' keyword in front.
        boost::lazy_enable_if<
            typename mpl::has_key<Args,tag::y>::type
          , parameter::value_type<Args,tag::y>
        >
        // Whenever using 'enable_if', 'disable_if', and so on,
        // do not add '::type' here.
    ), return_y, tag,
    (deduced
        (required
            (x, (std::map<char const*,std::string>))
            (y, (char const*))
        )
        (optional
            (z, (int), 4)
        )
    )
)
{
    return y;
}

可运行的演示见 preprocessor_deduced.cpp.

2.2 支持命名参数的成员函数

BOOST_PARAMETER_MEMBER_FUNCTION 和 BOOST_PARAMETER_CONST_MEMBER_FUNCTION 宏接受与 BOOST_PARAMETER_FUNCTION 完全相同的实参, 但设计用于在类体内使用:

BOOST_PARAMETER_NAME(arg1)
BOOST_PARAMETER_NAME(arg2)

struct callable2
{
    BOOST_PARAMETER_CONST_MEMBER_FUNCTION(
        (void), call, tag, (required (arg1,(int))(arg2,(int)))
    )
    {
        std::cout << arg1 << ", " << arg2;
        std::cout << std::endl;
    }
};

#include <boost/core/lightweight_test.hpp>

int main()
{
    callable2 c2;
    callable2 const& c2_const = c2;
    c2_const.call(1, 2);
    return boost::report_errors();
}

这些宏并不直接允许把函数接口与其实现分离, 但你总是可以把实参转发给单独的实现函数:

struct callable2
{
    BOOST_PARAMETER_CONST_MEMBER_FUNCTION(
        (void), call, tag, (required (arg1,(int))(arg2,(int)))
    )
    {
        call_impl(arg1, arg2);
    }

 private:
    void call_impl(int, int);  // implemented elsewhere.
};

2.2.1 静态成员函数

要暴露静态成员函数, 只需在函数名前插入关键字 "static":

BOOST_PARAMETER_NAME(arg1)

struct somebody
{
    BOOST_PARAMETER_MEMBER_FUNCTION(
        (void), static f, tag, (optional (arg1,(int),0))
    )
    {
        std::cout << arg1 << std::endl;
    }
};

#include <boost/core/lightweight_test.hpp>

int main()
{
    somebody::f();
    somebody::f(4);
    return boost::report_errors();
}

2.3 支持命名参数的函数调用运算符

BOOST_PARAMETER_FUNCTION_CALL_OPERATOR 和 BOOST_PARAMETER_CONST_FUNCTION_CALL_OPERATOR 宏接受与 BOOST_PARAMETER_MEMBER_FUNCTION 和 BOOST_PARAMETER_CONST_MEMBER_FUNCTION 宏相同的实参 (函数名除外), 因为这些宏允许把外围类的实例当作函数对象:

BOOST_PARAMETER_NAME(first_arg)
BOOST_PARAMETER_NAME(second_arg)

struct callable2
{
    BOOST_PARAMETER_CONST_FUNCTION_CALL_OPERATOR(
        (void), tag, (required (first_arg,(int))(second_arg,(int)))
    )
    {
        std::cout << first_arg << ", ";
        std::cout << second_arg << std::endl;
    }
};

#include <boost/core/lightweight_test.hpp>

int main()
{
    callable2 c2;
    callable2 const& c2_const = c2;
    c2_const(1, 2);
    return boost::report_errors();
}

2.4 支持命名参数的构造函数

C++ 中缺少"委托构造函数"特性 (http://www.open-std.org/jtc1/sc22/wg21/docs/papers/2006/n1986.pdf) 在一定程度上限制了本库为定义支持命名参数的构造函数所能提供的接口质量. 通常针对缺少构造函数委托的变通方法适用: 必须把公共逻辑提取到一个或多个基类中.

我们来构建一个只是打印其实参的支持命名参数的构造函数. 第一步是编写一个基类, 其构造函数接受一个称为 ArgumentPack 的单一实参: 一组带有其关键字标签的、指向实际实参的引用打包. 实际实参的值从 ArgumentPack 中提取, 方法是用关键字对象对其进行索引:

BOOST_PARAMETER_NAME(name)
BOOST_PARAMETER_NAME(index)

struct myclass_impl
{
    template <typename ArgumentPack>
    myclass_impl(ArgumentPack const& args)
    {
        std::cout << "name = " << args[_name];
        std::cout << "; index = " << args[_index | 42];
        std::cout << std::endl;
    }
};

注意, 按位或运算符 ("|") 作用于传给 ArgumentPack 的索引运算符的关键字对象时有特殊含义: 用于指示默认值. 此处若没有 index 形参存在于该 ArgumentPack 中, 将改用 42.

现在我们可以编写支持命名参数的构造函数接口了:

struct myclass : myclass_impl
{
    BOOST_PARAMETER_CONSTRUCTOR(
        myclass, (myclass_impl), tag
      , (required (name,*)) (optional (index,*))
    ) // no semicolon
};

由于我们为 index 提供了默认值, 而没有为 name 提供, 因此只有 name 是必需的. 我们可以如下测试新接口:

myclass x("bob", 3);                      // positional
myclass y(_index = 12, _name = "sally");  // named
myclass z("june");                        // positional/defaulted

关于 ArgumentPack 操纵的更多内容, 见进阶主题章节.

2.5 支持命名参数的类模板

本节我们将使用 Boost.Parameter 构建 Boost.Python 的 class_ 模板, 其"签名"为:

template <
    ValueType, BaseList = bases<>
  , HeldType = ValueType, Copyable = void
>
class class_;

只有第一个实参 ValueType 是必需的.

2.5.1 命名模板参数

首先, 我们构建一个允许用户按位置或按名称传递实参的接口:

struct B
{
    virtual ~B() = 0;
};

struct D : B
{
    ~D();
};

class_<
    class_type<B>
  , copyable<boost::noncopyable>
> …;

class_<
    D
  , held_type<std::auto_ptr<D> >
  , base_list<bases<B> >
> …;

2.5.1.1 模板关键字

第一步是为每个模板形参定义关键字:

namespace boost { namespace python {

    BOOST_PARAMETER_TEMPLATE_KEYWORD(class_type)
    BOOST_PARAMETER_TEMPLATE_KEYWORD(base_list)
    BOOST_PARAMETER_TEMPLATE_KEYWORD(held_type)
    BOOST_PARAMETER_TEMPLATE_KEYWORD(copyable)
}}

你在这里看到的 class_type 关键字的声明等效于:

namespace boost { namespace python {
    namespace tag {

        struct class_type;  // keyword tag type
    }

    template <typename T>
    struct class_type
      : parameter::template_keyword<tag::class_type,T>
    {
    };
}}

它定义了一个名为 tag::class_type 的关键字标签类型, 以及一个 参数传递模板 (名为 class_type).

2.5.1.2 类模板骨架

下一步是定义类模板的骨架, 它有三个可选形参. 由于用户可能按任意顺序传递实参, 我们并不知道这些形参的实际身份, 因此为它们使用描述性名称或写出实际默认值都为时过早. 我们将给它们起通用名称, 并使用特殊类型 boost::parameter::void_ 作为默认值:

namespace boost { namespace python {

    template <
        typename A0
      , typename A1 = boost::parameter::void_
      , typename A2 = boost::parameter::void_
      , typename A3 = boost::parameter::void_
    >
    struct class_
    {
        …
    };
}}

2.5.1.3 类模板签名

接下来, 我们需要构建一个类型 (称为 ParameterSpec), 用于描述 boost::python::class_ 的"签名". 一个 ParameterSpec 按位置顺序列出必需和可选形参, 以及任何类型要求 (注意它并不指定默认值, 默认值将单独处理):

namespace boost { namespace python {

    using boost::mpl::_;

    typedef parameter::parameters<
        required<tag::class_type, boost::is_class<_> >
      , parameter::optional<tag::base_list, mpl::is_sequence<_> >
      , parameter::optional<tag::held_type>
      , parameter::optional<tag::copyable>
    > class_signature;
}}

2.5.1.4 实参包与形参提取

接着, 在 class_ 的函数体内, 我们使用 ParameterSpec 的嵌套 ::bind< … > 模板把实际实参打包成 ArgumentPack 类型, 然后使用本库的 value_type< … > 元函数提取"逻辑形参". value_type< … > 与 binding< … > 非常相似, 但不会向实际实参类型添加引用. 注意, 默认值通过向其传递可选的第三个实参来指定:

namespace boost { namespace python {

    template <
        typename A0
      , typename A1 = boost::parameter::void_
      , typename A2 = boost::parameter::void_
      , typename A3 = boost::parameter::void_
    >
    struct class_
    {
        // Create ArgumentPack
        typedef typename class_signature::template bind<
            A0, A1, A2, A3
        >::type args;

        // Extract first logical parameter.
        typedef typename parameter::value_type<
            args, tag::class_type
        >::type class_type;

        typedef typename parameter::value_type<
            args, tag::base_list, bases<>
        >::type base_list;

        typedef typename parameter::value_type<
            args, tag::held_type, class_type
        >::type held_type;

        typedef typename parameter::value_type<
            args, tag::copyable, void
        >::type copyable;
    };
}}

2.5.2 测试目前的代码

回顾我们最初的示例,

typedef boost::python::class_<
    class_type<B>, copyable<boost::noncopyable>
> c1;

typedef boost::python::class_<
    D
  , held_type<std::auto_ptr<D> >
  , base_list<bases<B> >
> c2;

现在我们可以检查预期的形参:

BOOST_MPL_ASSERT((boost::is_same<c1::class_type, B>));
BOOST_MPL_ASSERT((boost::is_same<c1::base_list, bases<> >));
BOOST_MPL_ASSERT((boost::is_same<c1::held_type, B>));
BOOST_MPL_ASSERT((
    boost::is_same<c1::copyable, boost::noncopyable>
));

BOOST_MPL_ASSERT((boost::is_same<c2::class_type, D>));
BOOST_MPL_ASSERT((boost::is_same<c2::base_list, bases<B> >));
BOOST_MPL_ASSERT((
    boost::is_same<c2::held_type, std::auto_ptr<D> >
));
BOOST_MPL_ASSERT((boost::is_same<c2::copyable, void>));

2.5.3 推导模板参数

要在此处应用推导参数接口, 只需把类型要求收紧一些, 使 held_type 和 copyable 形参能与其他形参清晰区分. Boost.Python 的做法是: 要求 base_list 是其 bases< … > 模板的特化 (而非任意的 MPL 序列), 并要求 copyable (若显式提供) 为 boost::noncopyable. 标识 bases< … > 特化的一个简单方法是把它们全部派生自同一个类, 作为实现细节:

namespace boost { namespace python {
    namespace detail {

        struct bases_base
        {
        };
    }

    template <
        typename A0 = void, typename A1 = void, typename A2 = void …
    >
    struct bases : detail::bases_base
    {
    };
}}

现在我们可以重写签名, 使三个可选形参都可推导:

typedef parameter::parameters<
    required<tag::class_type, is_class<_> >

  , parameter::optional<
        deduced<tag::base_list>
      , is_base_and_derived<detail::bases_base,_>
    >

  , parameter::optional<
        deduced<tag::held_type>
      , mpl::not_<
            mpl::or_<
                is_base_and_derived<detail::bases_base,_>
              , is_same<noncopyable,_>
            >
        >
    >

  , parameter::optional<
        deduced<tag::copyable>
      , is_same<noncopyable,_>
    >

> class_signature;

看起来我们增加了大量复杂度, 但带给用户的好处更多. 我们最初的示例现在可以不带显式形参名编写:

typedef boost::python::class_<B, boost::noncopyable> c1;

typedef boost::python::class_<
    D, std::auto_ptr<D>, bases<B>
> c2;

3 进阶主题

至此, 你应当已经很好地掌握了基础知识. 本节我们将介绍本库一些更深层的用法.

3.1 细粒度名称控制

如果你不喜欢用于引用关键字对象的前导下划线命名约定, 或者你需要把 tag 这个名字用作关键字类型命名空间之外的其他用途, 还有另一种使用 BOOST_PARAMETER_NAME 的方式:

BOOST_PARAMETER_NAME(
    (
        object-name
      , tag-namespace
    ) parameter-name
)

下面是一个用法示例:

BOOST_PARAMETER_NAME(
    (
        pass_foo, keywords
    ) foo
)

BOOST_PARAMETER_FUNCTION(
    (int), f,
    keywords, (required (foo, *))
)
{
    return foo + 1;
}

int x = f(pass_foo = 41);

但在使用这种更冗长的形式之前, 请先阅读关于关键字对象命名最佳实践的章节.

3.2 更多 ArgumentPack

在考察 ArgumentPack 时 (见支持命名参数的构造函数和类模板两节), 我们已经见过它. 你可能已经猜到, ArgumentPack 实际上是本库所做一切事情的核心; 本节我们将研究更有效地构建和操纵它们的方法.

3.2.1 构建 ArgumentPack

最简单的 ArgumentPack 是向关键字对象赋值的结果:

BOOST_PARAMETER_NAME(index)

template <typename ArgumentPack>
int print_index(ArgumentPack const& args)
{
    std::cout << "index = " << args[_index];
    std::cout << std::endl;
    return 0;
}

int x = print_index(_index = 3);  // prints "index = 3"

此外, ArgumentPack 可以用逗号运算符组合. 下面额外的圆括号用于防止编译器把 print_name_and_index 看作接受两个独立实参:

BOOST_PARAMETER_NAME(name)

template <typename ArgumentPack>
int print_name_and_index(ArgumentPack const& args)
{
    std::cout << "name = " << args[_name];
    std::cout << "; ";
    return print_index(args);
}

int y = print_name_and_index((_index = 3, _name = "jones"));

compose.cpp 测试程序展示了此特性的更多示例.

要构建带位置实参的 ArgumentPack, 可以使用 ParameterSpec. 如类模板签名一节所述, 一个 ParameterSpec 描述形参的位置顺序及任何相关类型要求. 正如我们可以构建 ArgumentPack 类型 (用其嵌套的 ::bind< … > 模板), 我们也可以调用其函数调用运算符来构建 ArgumentPack 对象:

parameter::parameters<
    required<tag::name, is_convertible<_,char const*> >
  , optional<tag::index, is_convertible<_,int> >
> spec;

char const sam[] = "sam";
int twelve = 12;

int z0 = print_name_and_index(
    spec( sam, twelve )
);

int z1 = print_name_and_index(
    spec( _index=12, _name="sam" )
);

3.2.2 提取形参类型

若想知道传给 print_name_and_index 的实参类型, 有几个选择. 最简单且最不易出错的方法是把它们转发给一个函数模板, 让它来做类型推导:

BOOST_PARAMETER_NAME(name)
BOOST_PARAMETER_NAME(index)

template <typename Name, typename Index>
int deduce_arg_types_impl(Name&& name, Index&& index)
{
    // we know the types
    Name&& n2 = boost::forward<Name>(name);
    Index&& i2 = boost::forward<Index>(index);
    return index;
}

template <typename ArgumentPack>
int deduce_arg_types(ArgumentPack const& args)
{
    return deduce_arg_types_impl(args[_name], args[_index | 42]);
}

有时需要在不额外增加一层函数调用的情况下推导实参类型. 例如, 假设我们想返回 index 形参值的两倍? 此时可以使用 value_type< … > 元函数 (前文已介绍):

BOOST_PARAMETER_NAME(index)

template <typename ArgumentPack>
typename boost::parameter::value_type<ArgumentPack,tag::index,int>::type
    twice_index(ArgumentPack const& args)
{
    return 2 * args[_index | 42];
}

注意, 如果我们使用的是 binding< … > 而非 value_type< … >, 最终将返回对 2 * … 表达式中创建的临时对象的引用.

3.2.3 惰性默认值计算

当默认值计算代价高昂时, 最好在确定绝对必要之前避免计算. BOOST_PARAMETER_FUNCTION 会为我们处理这个问题; 但在显式使用 ArgumentPack 时, 我们需要 operator| 之外的工具:

BOOST_PARAMETER_NAME(s1)
BOOST_PARAMETER_NAME(s2)
BOOST_PARAMETER_NAME(s3)

template <typename ArgumentPack>
std::string f(ArgumentPack const& args)
{
    std::string const& s1 = args[_s1];
    std::string const& s2 = args[_s2];
    typename parameter::binding<
        ArgumentPack,tag::s3,std::string
    >::type s3 = args[_s3 | (s1 + s2)];  // always constructs s1 + s2
    return s3;
}

std::string x = f((
    _s1="hello,", _s2=" world", _s3="hi world"
));

在上面的示例中, 尽管用户已经为 s3 传了值, 字符串 "hello, world" 仍被构造. 为解决此问题, 可以惰性计算默认值 (即只在需要时才计算): 使用 boost::bind() 创建函数对象.

typename parameter::binding<
    ArgumentPack,tag::s3,std::string
>::type s3 = args[
    _s3 || boost::bind(
        std::plus<std::string>(), boost::ref(s1), boost::ref(s2)
    )
];

记忆法

要记住 | 和 || 的区别, 回想一下 || 通常使用短路求值: 只有当其第一个实参为 false 时才求值第二个实参. 类似地, 在 color_map[param || f] 中, 只有当没有提供 color_map 实参时才会调用 f.

表达式 bind(std::plus<std::string>(), ref(s1), ref(s2)) 产生一个函数对象, 调用它会把两个字符串相加. 只有当调用者没有提供 s3 实参时, 该函数才会被调用.

4 最佳实践

至此, 你应当对如何使用 Parameter 库有了相当好的认识. 本节指出几个更边缘的问题, 帮助你更有效地使用本库.

4.1 关键字命名

BOOST_PARAMETER_NAME 会给所有关键字对象的名称加上前导下划线, 以避免下面这种通常悄无声息的缺陷:

namespace people
{
    namespace tag
    {
        struct name
        {
            typedef boost::parameter::forward_reference qualifier;
        };

        struct age
        {
            typedef boost::parameter::forward_reference qualifier;
        };
    }

    namespace // unnamed
    {
        boost::parameter::keyword<tag::name>& name
            = boost::parameter::keyword<tag::name>::instance;
        boost::parameter::keyword<tag::age>& age
            = boost::parameter::keyword<tag::age>::instance;
    }

    BOOST_PARAMETER_FUNCTION(
        (void), g, tag, (optional (name, *, "bob")(age, *, 42))
    )
    {
        std::cout << name << ":" << age;
    }

    void f(int age)
    {
        :vellipsis:`        .
        .
        .
        `
        g(age = 3);  // whoops!
    }
}

虽然在上述情况中, 用户试图把值 3 作为 age 形参传给 g, 实际发生的却是 f 的 age 实参被重新赋值为 3, 然后作为位置实参传给了 g. 由于 g 的第一个位置形参是 name, 于是使用了 age 的默认值, g 打印出 3:42. 我们的前导下划线命名约定使这个问题不太可能发生.

在这个特定案例中, 若把 f 的 age 形参声明为 const, 本可以检测到该问题, 而只要有可能, 这样做总是好的. 最后, 我们建议你把所有代码都放进一个外围命名空间, 对带前导下划线的名称尤其如此. 如果我们省略上面的 people 命名空间, 全局命名空间中以前导下划线开头 (这些名称为你的 C++ 编译器保留) 的名称, 可能会与我们无名命名空间中的名称产生无法解决的歧义.

4.2 命名空间

在我们的示例中, 关键字对象总是在 (无名命名空间内的) 与使用这些关键字的 Boost.Parameter 支持函数相同的命名空间中声明:

namespace lib {

    BOOST_PARAMETER_NAME(name)
    BOOST_PARAMETER_NAME(index)

    BOOST_PARAMETER_FUNCTION(
        (int), f, tag,
        (optional (name,*,"bob")(index,(int),1))
    )
    {
        std::cout << name << ":" << index;
        std::cout << std::endl;
        return index;
    }
}

这些函数的用户有几种选择:

  1. 完全限定:

    int x = lib::f(
    lib::_name = "jill"
  , lib::_index = 1
);

    这种方式比许多用户所期望的更冗长.

  1. 通过 using 声明使关键字对象可用:

    using lib::_name;
using lib::_index;

int x = lib::f(_name = "jill", _index = 1);

    这一版本在实际调用点要好得多, 但 using 声明本身可能冗长且难以管理.

  1. 用 using 指示引入整个命名空间:

    using namespace lib;
int x = f(_name = "jill", _index = 3);

    这个选项很方便, 但它会不加区分地使 全部 lib 内容无需限定即可用.

不过, 如果我们在关键字声明外面再加一层命名空间, 就可以给用户更多控制:

namespace lib {
    namespace keywords {

        BOOST_PARAMETER_NAME(name)
        BOOST_PARAMETER_NAME(index)
    }

    BOOST_PARAMETER_FUNCTION(
        (int), f, keywords::tag,
        (optional (name,*,"bob")(index,(int),1))
    )
    {
        std::cout << name << ":" << index;
        std::cout << std::endl;
        return index;
    }
}

现在用户只需一个 using 指示就能引入与 lib 关联的所有关键字名称:

using namespace lib::keywords;
int y = lib::f(_name = "bob", _index = 2);

5 可移植性注意事项

使用 Parameter 库最新 Boost 发布版本的回归测试结果, 查看它在你会用的编译器上的表现. 此外, 你可能需要了解以下针对特定编译器的问题与变通办法.

5.1 完美转发支持

如果你的编译器支持完美转发, 则 Parameter 库会 #define 宏 BOOST_PARAMETER_HAS_PERFECT_FORWARDING, 除非你手动禁用它. 如果你的编译器不提供此支持, 则 parameter::parameters::operator() 会把右值引用当作左值 const 引用来绕过转发问题, 因此在某些情况下, 你必须用 boost::ref 或 std::ref 包裹任何将绑定到输出形参的实参. evaluate_category.cpp 和 preprocessor_eval_category.cpp 测试程序演示了此支持.

5.2 Boost.MP11 支持

如果你的编译器足够符合 C++11 标准, 则 Parameter 库会 #define 宏 BOOST_PARAMETER_CAN_USE_MP11, 除非你手动禁用它. singular.cpp、compose.cpp、optional_deduced_sfinae.cpp 和 deduced_dependent_predicate.cpp 测试程序演示了对 Boost.MP11 的支持.

5.3 不支持 SFINAE

一些较老的编译器不支持 SFINAE. 若你的编译器属于这种情况, Boost 头文件会 #define 预处理器符号 BOOST_NO_SFINAE, 此时支持命名参数的函数不会基于其签名从重载集中移除. sfinae.cpp 和 optional_deduced_sfinae.cpp 测试程序演示了 SFINAE 支持.

5.4 不支持 result_of

惰性默认值计算 依赖 result_of 类模板, 根据构造默认实参的函数对象的类型来计算默认实参的类型. 在不支持 result_of 的编译器上, BOOST_NO_RESULT_OF 会被 #define, 编译器将期望函数对象包含嵌套类型名 result_type, 以表明其无参调用时的返回类型. 要在这些编译器上把普通函数用作默认值生成器, 需要把它包装在一个类中: 该类以 typedef 提供 result_type, 并通过其 operator() 调用该函数.

5.5 编译器在无名命名空间中看不到引用

如果你使用 Microsoft Visual C++ 6.x, 可能会发现编译器难以找到你的关键字对象. 已观察到此问题, 但仅在这一种编译器上出现, 且随着测试代码演进而消失, 因此我们建议你只把它作为最后手段, 而非预防措施. 解决办法是添加 using 声明, 强制这些名称在外围命名空间中无需限定即可用:

namespace graphs {

    using graphs::graph;
    using graphs::visitor;
    using graphs::root_vertex;
    using graphs::index_map;
    using graphs::color_map;
}

8 术语表

8.1 实参 (或"实际参数")

实际传递给函数或类模板的值.

8.2 形参 (或"形式参数")

在函数或类模板中用于指代实参的名称. 例如, f 的形参 x 的值由实参 3 给出:

int f(int x) { return x + 1; }
int y = f(3);
